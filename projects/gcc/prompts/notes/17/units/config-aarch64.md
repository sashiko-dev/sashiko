# config-aarch64

The `config-aarch64` unit implements the GCC backend for the AArch64 architecture, including target option parsing, CPU/ISA feature tables, C-family preprocessor macros and pragmas, AAPCS64/MS/SME calling conventions, ACLE/AdvSIMD/SVE/SME built-in registration, GIMPLE folding, RTL instruction patterns, vector/RTX costing, and native CPU detection.

## Architecture & Data Flow

- Machine-specific AArch64 `.cc` units must `#define IN_TARGET_CODE 1` before `config.h`, `system.h`, and `coretypes.h`, and C++ standard library headers must be requested via `INCLUDE_*` macros before `#include "system.h"` so `safe-ctype.h` does not poison ctype macros. [F7, F10, F94, F152]
- In `aarch64_init_simd_builtin_functions`, backward operand iteration must track `op_num` (for `insn_data[d->code].operand`) separately from `arg_num` (for `d->qualifiers`, initialized to `op_num + 1` for void patterns and `op_num` otherwise). In `aarch64_simd_expand_builtin`, for `k` in `[1, n_operands + is_void)`, `d->qualifiers` and `args` use `k`, `insn_data[icode].operand` uses `k - is_void`, and `CALL_EXPR_ARG` uses `k - 1`, passing `&args[1]` to `aarch64_simd_expand_args`. [F1, F2]
- AdvSIMD tuple tables `aarch64_simd_tuple_modes` and `aarch64_simd_tuple_types` are indexed by `[type_index][num_vectors - 2]` for `num_vectors` in `[2, 4]`, whereas SVE/ACLE table `acle_vector_types` is indexed by `[num_vectors - 1][type]` for `num_vectors` in `[1, MAX_TUPLE_SIZE]` with single vectors at index 0. [F5]
- In `function_instance::call_properties`, `reads_global_state_p`, and `aarch64_call_properties`, `!flag_trapping_math` clears `CP_RAISE_FP_EXCEPTIONS`/`FLAG_RAISE_FP_EXCEPTIONS`, but `CP_READ_FPCR`/`FLAG_READ_FPCR` is never cleared by `-fno-rounding-math` so FP intrinsics are at most `pure`, not `const`. In `modifies_global_state_p`, `CP_PREFETCH_MEMORY` and `FLAG_PREFETCH_MEMORY` must be treated as modifying global state without trapping. [F36, F53]
- In `function_expander::add_input_operand`, a `VOIDmode` operand in `insn_data[icode]` is only valid when its predicate is `aarch64_any_register_operand` or `pmode_register_operand`, and `MODE_VECTOR_BOOL` inputs must have mode `VNx16BImode`. In `function_expander::expand`, `base->expand` must return `const0_rtx` for void functions, a `CONST_SCALAR_INT_P` or `MODE_INT` rtx for `MODE_INT`, and an rtx with exact mode `result_mode ()` otherwise; for `fpm_mode == FPM_set` (or `FLAG_USES_FPMR` in `aarch64_expand_pragma_builtin`), the final `fpm_t` argument must be moved into `gen_rtx_REG (DImode, FPM_REGNUM)` before expanding the instruction. [F37, F38, F50]
- In `aarch64-simd.md`, `mov<mode>` (`VALL_F16_SUB64`) must expand `CONST_VECTOR`s rejected by `cannot_force_const_mem` via `aarch64_expand_vector_init` (and non-trivial `>=64`-bit `CONST_VECTOR`s early via `gen_vec_duplicate` or `force_const_mem`). `*aarch64_simd_mov<mode>` (`VSUB64`) must index `CONST_VECTOR_ELT` with `BYTES_BIG_ENDIAN ? i : n_elts - 1 - i` and provide a `(?w, r)` alternative splitting after reload via `aarch64_simd_emit_reg_reg_move (operands, <VSC>mode, 1)`. [F62, F67, F69]
- In `aarch64-simd.md`, `vec_cmp<mode><v_int_equiv>` must mask both operands of `UNGE`, `UNGT`, `UNLE`, and `UNLT` with `gen_aarch64_cmeq<mode>` self-comparison masks before `gen_aarch64_cmge<mode>`/`cmgt<mode>` so NaNs do not raise FP exceptions; `cmul<conj_op><mode>3` requires `!HONOR_SIGNED_ZEROS (<MODE>mode)`; and `extendbfsf2` must convert `V8BFmode` to `SFmode` via an intermediate `V4SFmode` `force_lowpart_subreg`. [F66, F70, F73]
- `pure_scalable_type_info::analyze_array` must check `count > MAX_PIECES` on `tree_to_uhwi (nelts_minus_one)` before incrementing `count` and checking `count * element_info.pieces.length () > MAX_PIECES`. `pure_scalable_type_info::analyze_record` must verify `wide_bytepos.to_uhwi (&bytepos)` and `pieces.length () + field_info.pieces.length () <= MAX_PIECES` before calling `add_piece` (`pieces.quick_push`). [F91, F92]
- In `aarch64_hard_regno_call_part_clobbered`, any `aarch64_sve_mode_p (mode)` must set `per_register_size` to `BYTES_PER_SVE_VECTOR` rather than `GET_MODE_SIZE (mode)`. In `aarch64_hard_regno_mode_ok`, `GP_REGNUM_P` registers holding a `>8`-byte mode must be even-numbered, and `V8DImode` requires an even register in `[R0_REGNUM, R23_REGNUM]`. `aarch64_modes_compatible_p` must reject mode changes between partial SVE modes with different container bit widths or unit sizes, and between a partial SVE mode and any non-partial mode larger than the partial SVE mode's unit size. [F121, F122, F123]
- When `aarch64_emit_load_store_through_mode` loads a scalar (`!VECTOR_MODE_P (new_mode)`) from memory into an SVE register, it must zero-initialize `CONST0_RTX (full_mode)` and insert via `emit_insr` rather than a paradoxical subreg. In `aarch64_classify_address`, writeback addressing modes are rejected for `VEC_SVE_DATA | VEC_SVE_PRED`, while `aarch64_simd_general_operand` and `aarch64_simd_nonimmediate_operand` restrict `MEM` addresses to bare `REG` or `POST_INC`. [F125, F126, F163]
- In `aarch64_simd_valid_imm`, when a 128-bit AdvSIMD constant has non-repeating low 64 bits and zero high 64 bits (`output_width == 64`), if FP and AdvSIMD immediate checks fail it must return `false` before `aarch64_sve_valid_immediate`. In `aarch64_fp_cc_mode`, `LT`, `LE`, `GT`, `GE`, and `LTGT` must return `CCFPEmode` when `HONOR_NANS (mode) && flag_trapping_math`, while unordered/equality comparisons return `CCFPmode`. [F132, F136]
- `aarch64_general_reg` must test `GP_REGNUM_P (REGNO (op))` directly rather than `REGNO_REG_CLASS (REGNO (op)) == GENERAL_REGS` (which rejects `x8`-`x15`). In `constraints.md`, `CONST_INT` constraints must hardcode `SImode` or `DImode` rather than reading `GET_MODE (op)`. Under `aarch64_harden_sls_blr_p ()`, indirect-call constraint `Ucr` must restrict targets to `STUB_REGS` (excluding `x16`, `x17`, `x30`). In `cmpbr_imm_constraint`, every comparison code in `INT_CMP` and its inverse must map to the same immediate constraint (`Uc0` or `Uc1`). [F161, F164, F165, F176]
- In `atomics.md`, `aarch64_atomic_<atomic_ldoptab><mode>_lse` must emit `ld<atomic_ldop>` with a scratch register rather than `st<atomic_ldop>` or `XZR` even for relaxed/release models so `DMB LD` acquire fences block them. `aarch64_plushi_immediate` (constraint `Uih`) must only accept `HImode` constants where `(val & 0xfff) == val` or `sext_hwi (val & 0xf000, 16) == val`. [F166, F167]

## Object Lifetimes

- Local or non-GTY class-member vectors in `aarch64.cc` and `aarch64_fold_lo_call_to_hi` must use `auto_vec` rather than raw `vec`, and function-local `sbitmap`s must use `auto_sbitmap`. Callers of `function_builder::get_name` must pass the first string allocated in the call's scope to `obstack_free (&m_string_obstack, name)`. [F11, F12, F98, F99]
- In `cortex-a57-fma-steering.cc`, `func_fma_steering::dfs` must queue nodes in `to_free` rather than deleting `fma_node` or `fma_forest` while draining `to_process`; any code deleting an `fma_node *` must check `node->root_p ()` and `static_cast<fma_root_node *> (node)` because `~fma_node` is non-virtual; and `fma_forest::merge_forest` must remove `other_forest` via `m_globals->remove_forest`, update root `m_forest` pointers, and splice `*other_roots` before `delete other_forest`. [F153, F154, F155]

## API Contracts

- Callers of `function_expander::get_fallback_value` (such as `use_cond_insn` and `use_vcond_mask_insn`) must pass their `args` cursor `opno` initialized to 0 before reading the governing predicate from `args[opno++]`, because `get_fallback_value` advances `opno` past argument 0 only when `merge_argno` resolves to 0. [F4]
- `require_const_argument` in `aarch64-builtins.cc` treats `maxval` as an exclusive upper bound `[minval, maxval)` by decrementing `maxval` before comparison, so callers must pass `max_inclusive + 1` for inclusive upper bounds or `ARRAY_SIZE - 1` to exclude a trailing entry. [F6]
- When `function_builder::add_function` registers a placeholder entry (`placeholder_p || m_function_nulls`), it must store `integer_zero_node` (never `NULL_TREE` or `error_mark_node`) in `rfn.decl` to preserve function-code numbering across C, C++, and LTO. [F19]
- When `gimple_folder::fold_pfalse` folds a `PRED_implicit` call with a `pfalse` governing predicate, it must not fold `CP_READ_MEMORY` calls with an `AGGREGATE_TYPE_P (TREE_TYPE (lhs))` result to `build_zero_cst`, and must use `fold_to_stmt_vops` when replacing `CP_WRITE_MEMORY` or `CP_PREFETCH_MEMORY` calls with a nop. In `gimple_folder::fold_to_pfalse`, folding a `TYPE_count` (`svcount_t`) operation must build a zero constant of `abi_vector_types[VECTOR_TYPE_svbool_t]` and convert it via `fold_call_to`. [F29, F30]
- When canonicalizing SME state attributes with `aarch64_merge_string_arguments`, `handle_arm_shared` must pass `can_merge_in_place = false` because function types are shared, whereas `handle_arm_new` passes `true`. In `aarch64_merge_decl_attributes`, if `newdecl` has `arm::new` and `DECL_INITIAL (olddecl) != NULL_TREE`, it must emit an error and not merge; when both decls have `target_version` or `target_clones`, the new attribute's `TREE_VALUE` must be replaced with the old one. [F110, F112]
- Every vector permutation helper called by `aarch64_expand_vec_perm_const_1` (such as `aarch64_evpc_rev64_ext`) must check `if (d->testing_p) return true;` before emitting RTL or querying `currently_expanding_gimple_stmt`, and when `aarch64_expand_vec_perm_const_1` rotates inputs and swaps `d->op0` with `d->op1`, it must also swap `d->zero_op0_p` with `d->zero_op1_p`. RTL expanders that invoke `gen_highpart` directly on an operand must constrain it with `pure_register_operand` rather than `register_operand`. [F85, F116, F160]

## Error Handling

- `register_vector_type`, `handle_arm_new`, `pure_scalable_type_info::analyze`, `aarch64_takes_arguments_in_sve_regs_p`, and `aarch64_init_cumulative_args` must check for `error_mark_node` on function/argument types before inspecting ABI or type properties. [F18, F106, F107, F108]
- In `function_checker::require_immediate_enum`, each `TYPE_VALUES (type)` entry's `TREE_VALUE` must be unwrapped with `DECL_INITIAL` when `TREE_CODE (value) == CONST_DECL` before comparing with `wi::to_widest`. In `function_resolver::infer_integer_scalar_type`, integral arguments with `TYPE_PRECISION (actual) < 32` must resolve to `TYPE_SUFFIX_s32` regardless of `TYPE_UNSIGNED (actual)`. [F20, F22]

## External Contracts

- In `handle_arm_sve_vector_bits_attribute` and `mangle_builtin_type`, fixed-length SVE types created via `arm_sve_vector_bits` must be given a dedicated `TYPE_DECL` (`TYPE_NAME (new_type)`) whose type carries the updated `"SVE type"` attribute with `9__SVE_VLSI...` mangling, and `mangle_builtin_type` must redirect `type` to `TREE_TYPE (TYPE_NAME (type))` when `TYPE_NAME (type)` is a `TYPE_DECL` before calling `lookup_sve_type_attribute`. [F24, F45]
- In `gcc/common/config/aarch64/cpuinfo.h`, enumerator values in `enum CPUFeatures` must match LLVM's `compiler-rt`, with `FEAT_EXT = 62` and `FEAT_INIT` reserved at the top of the 64-bit bitmask. When two FMV declarations have equal explicit priority, `aarch64_compare_version_priority` and `compare_feature_masks` must order `mask1` and `mask2` solely by the highest-index differing bit in `mask1 ^ mask2` across `aarch64_fmv_feature_data`, never by bit popcount. [F44, F138]
- In `aarch64-sme.md`, `aarch64_smstart_sm` and `aarch64_smstop_sm` must have an empty target condition (`""`), `(use (reg:DI VG_REGNUM))`, clobbers of `V0`..`V28` and `P0`..`P15`, and emit literal `.inst` encodings when `!TARGET_SME`; `aarch64_smstart_za` and `aarch64_smstop_za` must both read `TPIDR2_SETUP_REGNUM` and `ZA_FREE_REGNUM`; and every instruction emitting a `bl` to an SME ABI runtime helper must set `(set_attr "is_call" "yes")`. [F79, F80, F81]

## Known Pitfalls

- Before calling `SET_TYPE_MODE` on a canonical type built from user-accessible types (such as `build_array_type_nelts` in `aarch64_init_ls64_builtins_types`), `build_distinct_type_copy` must be called first; `Poly8_t`'s element type in `aarch64_init_simd_builtin_types` must also use `build_distinct_type_copy (unsigned_intQI_type_node)` with `TYPE_STRING_FLAG` cleared; and `register_type_decl` must reset `DECL_ORIGINAL_TYPE (decl) = NULL_TREE` after `pushdecl` to avoid a `dwarf2out` circularity. [F15, F16, F17]
- Both `gimple_folder::fold` and `aarch64_general_gimple_fold_builtin` must ensure any replacement `gassign` has a non-null LHS, and `gimple_folder::fold` must return `NULL` when `!TARGET_SIMD && !TARGET_SVE`. `aarch64_fold_lo_call_to_hi` must wait until `cfun->curr_properties & PROP_last_full_fold`; `aarch64_fold_load` and `aarch64_fold_store` must only fold `vld1`/`vst1` to `MEM_REF` when `!BYTES_BIG_ENDIAN` (and `cfun->after_inlining` for `vld1`); and `aarch64_general_gimple_fold_builtin` must only fold `fmulx` with one `REAL_CST` to `MULT_EXPR` when the constant is neither zero nor infinity (folding `0 * inf` to `+/-2.0`). [F33, F34, F41, F54]
- For SVE floating-point operations under `-ftrapping-math`, `function_expander::use_pred_x_insn` must pass `SVE_STRICT_GP` when `pred != CONST1_RTX (GET_MODE (pred))`, `aarch64_sve_fp_pred` and `aarch64_sve_emit_masked_fp_pred` must restrict partial modes (`vec_flags & VEC_PARTIAL`) via `aarch64_sve_packed_pred` with `SVE_STRICT_GP`, and unpredicated `SVE_FP_UNARY`/`SVE_FP_BINARY` iterators must only contain non-trapping estimation unspecs. [F52, F135, F169]
- In `aarch64_expand_tbl_tbx`, when `aarch64_pack_into_v128s` zero-pads an odd number of 64-bit table registers (`vtbx1`/`vtbx3`) for `UNSPEC_TBX`, expansion must emit `UNSPEC_TBL` and mask indices against `table_nelts` with `GTU` and `vcond_mask` rather than emitting `UNSPEC_TBX` directly. In `aarch64-simd.md`, `aarch64_abs<mode>` must use `UNSPEC_ABS` rather than RTL `abs`, and `aarch64_<su>abd<mode>` must use `(minus (USMAX op1 op2) (<max_opp> op1 op2))` rather than `(abs (minus op1 op2))`. [F40, F71]
- In `.def` files (`aarch64-simd-pragma-builtins.def`, `aarch64-neon-builtins.def`, `aarch64-sve-builtins.def`, `aarch64-sve-builtins-sme.def`), `REQUIRED_EXTENSIONS` in `constexpr` tables must use static `AARCH64_FL_*` flags rather than dynamic `TARGET_*` macros. In `function_expander::get_contiguous_base`, when `mode_suffix_id == MODE_vnum`, `(vl_isa_mode & AARCH64_FL_SM_ON)`, `!TARGET_STREAMING`, and `!size.is_constant ()`, the multiplier must use `aarch64_sme_vq_immediate` rather than `BYTES_PER_SVE_VECTOR`. [F47, F49]
- In `aarch64_gen_ccmp_next`, `TYPE_MODE (TREE_TYPE (treeop0))` must be validated against supported scalar modes before calling `expand_operands` to avoid quadratic `O(n^2)` TER re-expansion. In `aarch64_possible_by_lane_insn_p`, `FOR_EACH_IMM_USE_FAST` must skip `is_gimple_debug` statements before `m_vinfo->lookup_stmt`. When `aarch64_try_widen_mult_by_pow2` replaces a widening conversion of a single-use narrow multiply, it must immediately remove the dead multiply with `gsi_remove` and `release_defs`. [F90, F114, F117]
- In `aarch64_maybe_expand_sve_subreg_move` on big-endian targets, subregs marked with `LRA_SUBREG_P` must not be unwrapped to `SUBREG_REG`. In `func_fma_steering::analyze_fma_fmul_insn`, a use must not be added to `node->add_child` if `get_fma_node (chain->insn)` is already non-null (avoiding cyclic FMA trees). RTL `SET` patterns whose source is a comparison (or `neg`/`zero_extend` of one, like `cstorecc4` and `aarch64_cstore<mode>`) must use `aarch64_comparison_operator_mode` rather than `aarch64_comparison_operator`. [F124, F173, F177]
