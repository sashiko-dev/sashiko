# tree-optimization

Implements GCC's GIMPLE SSA analysis and optimization framework, including the Ranger value-range engine and `range-op` algebra, scalar evolution (SCEV) and loop-iteration (`niter`) analysis, the tree alias oracle, out-of-SSA coalescing, jump threading, scalar passes (CCP, copyprop, DCE, DOM, DSE, forwprop, ifcombine, phiopt, math-opts, tailcall, VRP), loop passes (ch, lim, ivcanon, ivopts, prefetch, split, unswitch), and middle-end diagnostic passes.

## Architecture & Data Flow

- In `ptr_deref_may_alias_global_p`, `ptr_deref_may_alias_auto_p`, `ptr_deref_may_alias_decl_p`, and `ptr_derefs_may_alias_p`, `SSA_NAME_PTR_INFO` must only be read after verifying `POINTER_TYPE_P (TREE_TYPE (ptr))` because non-pointer `SSA_NAME`s store range info in the same union slot; similarly, `ccp_finalize` must dispatch lattice masks by `POINTER_TYPE_P` (`get_ptr_info` / `set_ptr_info_alignment`) vs `INTEGRAL_TYPE_P` (`set_bitmask`). [F117, F118]
- When moving/hoisting statements or relaxing guards to make execution unconditional (`ifcombine_replace_cond`, `move_computations_worker`, `create_new_iv`, `split_loop`, `move_stmt`, `maybe_optimize_guarding_check`), passes must reset flow-sensitive info (`reset_flow_sensitive_info` / `reset_flow_sensitive_info_in_bb`) and rewrite `gimple_needing_rewrite_undefined` statements via `rewrite_to_defined_unconditional` (or `ifcombine_rewrite_to_defined_overflow`); `match_simplify_replacement` must wrap `gimple_simplify_phiopt` in `auto_flow_sensitive`. [F247, F299, F314, F363, F418, F419, F428]
- Duplicating `SSA_NAME_PTR_INFO` onto a new or offset pointer SSA name requires calling `reset_flow_sensitive_info (new_ptr_base)` in `copy_ref_info`, and calling `mark_ptr_info_alignment_unknown` in `rewrite_use_nonlinear_expr` and `issue_prefetch_ref`. [F129, F318, F372]
- After modifying statements or the CFG, `fini_copy_prop` and `perform_tree_ssa_dce` must call `free_numbers_of_iterations_estimates (cfun)` and (if `scev_initialized_p ()`) `scev_reset ()`; `replace_phi_edge_with_variable` must reset niter estimates and upper bounds when `loop_exits_from_bb_p` holds; `tree_unroll_loops_completely` must run `update_ssa (TODO_update_ssa)` (never `TODO_update_ssa_no_phi`), `do_rpo_vn`, `scev_reset`, and `free_numbers_of_iterations_estimates` after `unloop_loops`; and `execute_ranger_vrp` must call `scev_reset ()` before `remove_and_update_globals ()`. [F196, F310, F412, F478]
- In `ranger_cache::apply_inferred_ranges`, `register_inferred_value` for a `stmt_ends_bb_p (s)` statement must be skipped if any outgoing edge of `gimple_bb (s)` has `EDGE_ABNORMAL` or `EDGE_EH`; `infer_oracle ().maybe_adjust_range` in `edge_range`, `range_from_dom`, and `range_on_edge` requires `(e->flags & (EDGE_EH | EDGE_ABNORMAL)) == 0`; and when `register_inferred_value` narrows `m_on_entry` and `!gori ().has_edge_range_p (name)`, it must call `gori_ssa ()->set_range_invariant (name, false)`. [F33, F34, F35]
- When `last_basic_block_for_fn (cfun) > param_vrp_sparse_threshold`, `block_range_cache::set_bb_range` must allocate `sbr_sparse_bitmap` (where 4-bit quad values are 1-based: `0` is empty, `1..SBR_NUM` index `m_range[value - 1]`, and `SBR_UNDEF` is `SBR_NUM + 1` with no `m_range` entry), and `ranger_cache::fill_block_cache` must store `block_result` and return immediately after `range_from_dom` without running `FOR_EACH_PARTIAL_AND_FULL_EQUIV`. [F5, F9, F12]
- In `path_range_query`, `m_path` is in reverse execution order (`entry_bb ()` at `m_path.length () - 1`, `exit_bb ()` at `0`), so `prev_bb ()` (`m_path[m_pos + 1]`) requires `!at_entry ()` and `next_bb ()` (`m_path[m_pos - 1]`) requires `!at_exit ()`; crossing a backedge (`relations_may_be_invalidated (e)`) must call `reset_path ()` and suppress `maybe_register_phi_relation`; any new def must call `killing_def`; and `ssa_range_in_phi` / `maybe_register_phi_relation` must not read `m_cache` or record `VREL_EQ` if `ssa_defined_in_bb (arg, bb)`. [F6, F40, F41]
- In `fold_using_range::range_of_address` and `pointer_plus_operator::fold_range`, inferring `r.set_nonzero` from a non-zero offset or base requires `!TYPE_OVERFLOW_WRAPS` and (`flag_delete_null_pointer_checks` or non-negative offset `known_gt (off, 0)` / `!wi::sign_mask (rh_ub)`); `operator_addr_expr::op1_range` requires `TYPE_OVERFLOW_UNDEFINED (type)` to set non-zero from `!lhs.contains_zero_p ()`; and `pointer_plus_operator::lhs_op1_relation` and `builtin_memref::extend_offset_range` must interpret `sizetype` offsets as `SIGNED`. [F49, F85, F86, F87]
- When `relation_equiv_p (rel)` holds and both operands are equal, `range_operator::fold_range` (for `irange` and `frange`) must pair each sub-range `i` with itself rather than taking the `(i, j)` cross product, capping `wi_fold_in_parts_equiv` `limit` at 8 (0 once `r.num_pairs () > 32`) with inclusive loop bound `x <= lh_range` and stopping if `r.varying_p ()`; for non-equivalent `irange`s with `lh.num_pairs () * rh.num_pairs () > 12`, it must call `wi_fold_in_parts` once on the overall bounds. [F55, F56, F60, F61]
- For `MODE_COMPOSITE_P (mode)` floating-point modes, `frange_nextafter`, `frange_arithmetic`, and `operator_cast::fold_range` must step zero/denormal bounds in `DFmode` via `real_convert` and `real_nextafter`; `frange_arithmetic` must widen toward `inf` by 1 extra ULP (`PLUS_EXPR`/`MINUS_EXPR`), 2 ULPs (`MULT_EXPR`), or 3 ULPs (`RDIV_EXPR`), while `build_lt`/`build_gt` keep closed bounds; `frange::internal_singleton_p` must return `false` if the bound is infinite or `DFmode`-exact; and `frange::canonicalize_zeros` must enforce `+0.0` when `!MODE_HAS_SIGNED_ZEROS` and `[-0.0, +0.0]` when `!HONOR_SIGNED_ZEROS`. [F94, F95, F501, F502]
- Non-default `gswitch` case labels are 1-indexed (`1 .. gimple_switch_num_labels (sw) - 1`, with slot 0 reserved for the default label) in `gimple_outgoing_range::switch_edge_range` / `calc_switch_ranges`, `simplify_gimple_switch_label_vec` (which must call `gimple_switch_set_num_labels (stmt, len + 1)`), and `clean_up_after_unswitching` (which must only call `remove_edge (e)` when `e != default_e` and then call `free_dominance_info (CDI_DOMINATORS)`). [F8, F215, F333, F370]
- In `interpret_rhs_expr`, `PLUS_EXPR`, `MINUS_EXPR`, `NEGATE_EXPR`, or `MULT_EXPR` on non-wrapping integral types where `at_stmt` does not dominate `loop->latch` must be evaluated in `unsigned_type_for (type)` and converted back; similarly, `scev_var_range_cant_overflow` and `infer_loop_bounds_from_undefined` (`infer_loop_bounds_from_signedness` / `infer_loop_bounds_from_pointer_arith`) may only use statements/defs whose basic block dominates `loop->latch`. [F134, F371]
- In `dse_optimize_stmt` and `do_simple_agr_dse`, clearing the LHS of a `gimple_call_return_slot_opt_p` call is forbidden if the return type is `TREE_ADDRESSABLE` or its `TYPE_SIZE` is not `poly_int_tree_p`; `dse_optimize_redundant_stores` must verify `alias_set_subset_of` on both `ao_ref_alias_set` and `ao_ref_base_alias_set` (and DOM's `optimize_stmt` must check `refs_same_for_tbaa_p` and `!DECL_HARD_REGISTER`); and `dse_optimize_call` may ignore `integer_zerop (arg)` only when `!targetm.addr_space.zero_address_valid`. [F180, F198, F212, F213, F244]
- In `record_edge_info`, `record_equality`, `associate_equivalences_with_edges`, and `value_replacement`, floating-point equality (`EQ_EXPR`/`NE_EXPR`) must not record an equivalence or substitute operands when `HONOR_SIGNED_ZEROS` holds and the operand may be zero (or is not a non-zero `REAL_CST` in uncprop), or when `DECIMAL_FLOAT_MODE_P` holds in DOM. [F214, F443, F500]
- In `tree_niter_desc`, `niter` and `max` count loop latch executions (one less than header/exit executions), so `determine_exit_conditions`, `tree_transform_and_unroll_loop`, and `split_loop` must add 1 before dividing/scaling and subtract 1 when storing back; in `tree_transform_and_unroll_loop`, `new_loop->nb_iterations_upper_bound = factor - 1` and `scale_loop_profile` require `desc->cmp != NE_EXPR || desc->control.no_overflow`; and `can_unroll_loop_p`, `niter_for_exit`, `find_bivs`, `find_givs_in_stmt_scev`, and `expand_simple_operations` must reject `contains_abnormal_ssa_name_p` / `SSA_NAME_OCCURS_IN_ABNORMAL_PHI`. [F295, F329, F360, F365, F366]

## Object Lifetimes

- Every `enable_ranger (fun)` call must be paired with `disable_ranger (fun)`; in `pass_wrestrict::execute`, `m_ptr_qry.flush_cache ()` must be called and `m_ptr_qry.rvals` reset to `NULL` when `disable_ranger (fun)` deletes the ranger, and any on-demand `calculate_dominance_info (CDI_DOMINATORS)` must be paired with `free_dominance_info (fun, CDI_DOMINATORS)`; in `ch_base::copy_headers`, the `gimple_ranger` must be deleted before `gimple_duplicate_seme_region` mutates the CFG. [F19, F66, F90, F252]
- Classes/structs owning raw `vec<>`, `bitmap_obstack`, `obstack`, or `vrange_allocator *` members (`block_range_cache`, `infer_range_manager`, `range_def_chain`, `phi_analyzer`, `gimple_ranger`, `edge_info` via `free_dom_edge_info`, `ssa_conflicts` via `ssa_conflicts_delete`, `_var_map` via `delete_var_map`, `lim_aux_data` via `free_lim_aux_data`, `im_mem_ref` via `memref_free` before `obstack_free`, and `instantiate_cache_type`) must explicitly release/free their inner buffers before freeing the outer struct or obstack; in `ssa_lazy_cache::~ssa_lazy_cache`, `bitmap_obstack_release (&m_bitmaps)` is called if `m_ob == &m_bitmaps`, else `BITMAP_FREE (active_p)`. [F20, F27, F109, F167, F169, F232, F285, F288]
- In `jt_path_registry`, every `vec<jump_thread_edge *> *` from `allocate_thread_path` has a heap buffer that must be freed via `path->release ()` or `cancel_thread (path)` (and cleared from `e->aux` in `fwd_jt_path_registry`), and single-arg `remove_path (pathno)` must be called *before* `path->release ()` (or `remove_path (pathno, first)` after); in `fwd_jt_path_registry::thread_block_1`, `ssa_redirect_edges` must free all `rd->incoming_edges` nodes before `delete m_redirection_data`. [F458, F459, F460, F461]
- Individual `use_optype_d` nodes are suballocated from `ssa_operand_memory_d` and must never be passed to `ggc_free`—`finalize_ssa_uses` and `free_stmt_operands` must unlink them with `delink_imm_use` and prepend to `gimple_ssa_operands (fn)->free_uses`; when `finalize_ssa_defs` clears an `SSA_NAME` `gimple_vdef (stmt)`, it must call `unlink_stmt_vdef (stmt)` (propagating `SSA_NAME_OCCURS_IN_ABNORMAL_PHI` to `vuse`) and `release_ssa_name_fn`. [F399, F404]

## API Contracts

- `path_range_query::active_query_compatible_p` returns `false`, so `fold_using_range::fold_stmt` must switch queries via `set_range_query (cfun, src.query ())` and restore `saved_query` on every exit path; `gimple_range_ssa_names` compacts `gimple_range_ssa_p` operands into `vec[count++]` and requires a caller buffer of `vec_size >= 2` (`>= 3` for `COND_EXPR` assignments). [F4, F36]
- Every `range_operator::op1_op2_relation_effect` override must return `false` without intersecting `rel_range` into `lhs_range` whenever `rel` is unhandled or preconditions fail, because a default-constructed `int_range<2> rel_range` is `UNDEFINED`; callers of `find_range` in `range-op-float.cc` must place `-INF`-rounded endpoints in `cp[0..3]` and `+INF`-rounded endpoints in `cp[4..7]`. [F59, F78]
- `vrange_storage` subclasses cannot grow in place, so callers overwriting storage via `set_vrange`/`set_irange`/`set_prange`/`set_frange` must check `fits_p (r)` first; `irange_storage::set_irange` must set `m_precision` and `m_num_ranges` before `write_lengths_address` (matching `irange_storage::size`'s `num_pairs * 2 + 2` `wide_int` layout); and `prange_storage::set_prange` must switch on `m_kind` and return early for `PR_UNDEFINED`/`PR_VARYING`/`PR_ZERO` before reading `r.get_bitmask ()` or `r.m_points_to_p`. [F452, F453, F493]
- Tree expressions substituted into GIMPLE or passed to `create_iv` / `force_gimple_operand` / `gimple_build_debug_bind` must be cloned with `unshare_expr` (in `ccp_folder::fold_stmt`, `create_mem_ref`, `remove_dead_stmt`, `dom_opt_dom_walker::record_equivalences_from_stmt`, `forward_propagate_addr_expr_1`—which also copies `TREE_THIS_VOLATILE`, `TREE_SIDE_EFFECTS`, and `TREE_THIS_NOTRAP`—`execute_sm*`, `create_new_iv`, and `simplify_replace_tree`, and via `unshare_expr_without_location` in `prange_storage::alloc` when `!shared_p`). [F100, F122, F182, F243, F296, F356, F357, F494]

## Known Pitfalls

- To support multi-bit boolean types (e.g. Ada) and 1-bit signed types (`[-1, 0]`, where `+1` overflows), `gori_compute::logical_combine` (`range_is_either_true_or_false`), `get_bool_state`, and boolean `op1_range`/`op1_op2_relation` must test truth by checking whether zero is excluded (`!lhs.contains_zero_p ()` or `lhs.singleton_p ()`) rather than comparing to `[1, 1]`; `factor_out_conditional_operation` must reject multi-bit `BOOLEAN_TYPE` for same-precision `INTEGER_CST` casts and reject 1-bit signed types in `uaddc_cast`/`match_uaddc_usubc`; and `build_lt`, `build_gt`, `irange::set` (`VR_ANTI_RANGE`), `subtract_one`, and `add_one` must step signed bounds by adding/subtracting `-1` rather than `+1`. [F47, F81, F82, F416, F429, F495]
- When removing elements while iterating over a vector or PHI argument list, loop indices must be adjusted: in `gimple-ssa-isolate-paths.cc`, isolating an incoming edge shifts PHI arguments down so `next_i` must be reset to `i`; in `dse_classify_store` (`defs.unordered_remove (i)`—which must also clear `first_phi_def`/`last_phi_def` if equal to the removed PHI), `split_address_groups` (`ordered_remove (j)`), and `jt_path_registry` (`remove_path (i)` / `adjust_one_path`), the loop index `i`/`j` must not be incremented on the removal iteration. [F7, F158, F274, F449]
- In `dom_opt_dom_walker`, calling `gimple_build_assign (rhs, lhs)` with an `SSA_NAME` `rhs` to form a reversed-operand lookup key overwrites `SSA_NAME_DEF_STMT (rhs)`, so the caller must save and restore `SSA_NAME_DEF_STMT (rhs)`; in `split_loop`, `loop_version` may reallocate header PHIs, so `phi` must be re-fetched via `SSA_NAME_DEF_STMT (phi_result)` before reading latch arguments; and in `stmt_semi_invariant_p_1`, recursive calls may reallocate `stmt_stat`, so `stmt_stat.put (stmt, true)` must be used instead of a saved `bool &` reference. [F176, F335, F337]
- Header inclusion order is load-bearing: every `.cc` file must include `"config.h"` before `"system.h"` and before `#if CHECKING_P` (`gimple-range-tests.cc` omits `"config.h"` and must only be `#include`d after `"config.h"` and `"gimple-range.h"`); in `tree-ssa-ifcombine.cc`, `#include "rtl.h"` must precede `#include "tm_p.h"` (for ARM `RTX_CODE` guards) and `#include "backend.h"` must precede `#ifndef LOGICAL_OP_NON_SHORT_CIRCUIT`; and in `tree-ssa-loop-prefetch.cc` and `tree-ssa-math-opts.cc`, `#ifndef` fallbacks for `FENCE_FOLLOWING_MOVNT`, `READ_CAN_USE_WRITE_PREFETCH`, and `POWI_MAX_MULTS` must follow `tm.h` (`backend.h` / `target.h`). [F18, F63, F229, F230, F344, F396]
