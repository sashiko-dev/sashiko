# config-arm

Implements the Arm M-profile Vector Extension (MVE) ACLE built-in type and intrinsic infrastructure (registration, semantic checking, overload resolution, GIMPLE folding, and RTL expansion) alongside the core Arm RTL machine description (`arm.md`), command-line target options (`arm.opt`), backend headers, and pipeline scheduling automata for ARM926EJ-S, ARM1020E, ARM1026EJ-S, and ARM1136J(F)-S cores.

## Architecture & Data Flow

- The first dimension of `acle_vector_types[MAX_TUPLE_SIZE][NUM_VECTOR_TYPES + 1]` is indexed by `num_vectors >> 1` (mapping 1, 2, and 4 vectors to 0, 1, and 2), never by `num_vectors` or `num_vectors - 1`. [F1]
- In `register_builtin_types`, `register_vector_type`, `register_builtin_tuple_types`, and `arm_mve_type_for_scalar_type`, `mve_pred16_t` uses ABI type `UINT16_TYPE` (2 bytes) while data vector types require 16-byte `VECTOR_MODE_P` modes; tuple types are created only for non-boolean types with 2 or 4 vectors (with `VECTOR_MODE_P` `TYPE_MODE == TYPE_MODE_RAW` and 64-bit `TYPE_ALIGN` on both field `val` and record), and floating-point vector/tuple types must be registered unconditionally even when `!TARGET_HAVE_MVE_FLOAT` (never substituted with `void_type_node`). [F20, F40, F41]
- `types_none` must contain two `{ NUM_TYPE_SUFFIXES, NUM_TYPE_SUFFIXES }` entries so `ti == 0` supplies the suffixless `type_suffix_pair` and `types_none[1]` acts as the terminating sentinel. [F2]
- `function_instance::has_inactive_argument ()` must return `false` for every `PRED_m` intrinsic that does not prepend an implicit `inactive` merge argument at index 0, keeping `apply_predication`, `check_gp_argument`, and `m_base_arg` synchronized. Broken by: adding a `PRED_m` intrinsic whose first operand is already an accumulator or destination without adding its `functions::*` base to `has_inactive_argument ()`. [F4]
- When an MVE intrinsic's overloaded and non-overloaded forms have different parameter lists, `function_builder::add_unique_function` must only register the overloaded alias when `OVERLOADED_FORM` is set and only register/hash the non-overloaded decl when `NONOVERLOADED_FORM` is set; inherent overloads with a dummy type-inference argument must pop it via `function_resolver::pop_and_resolve_to`. [F55]
- In `function_instance::reads_global_state_p`, `modifies_global_state_p`, `could_trap_p`, and `function_builder::get_attributes`, any MVE intrinsic whose `call_properties` include `CP_READ_MEMORY` or `CP_READ_FPCR` must be marked `"pure"` (not `"const"`) when `!modifies_global_state_p ()`, and `"nothrow"` must be omitted when `flag_non_call_exceptions && could_trap_p ()`. [F44]
- In `function_expander::use_cond_insn`, `get_fallback_value (mode, merge_argno, opno)` consumes `args[0]` and increments `opno` from 0 to 1 when `merge_argno == DEFAULT_MERGE_ARGNO` (0), after which the `nops` (`insn_data[icode].n_operands - 3`) inputs are read from `args[opno + i]` and the predicate from `args[nops + 1]`. [F6]
- In `function_expander::add_input_operand`, `VOIDmode` in `insn_data[icode].operand[opno].mode` is permitted only when `operand.predicate` is `arm_any_register_operand` (taking the mode from `GET_MODE (x)`); for `VALID_MVE_PRED_MODE` operand modes, non-`CONST_INT` operands must be coerced with `force_lowpart_subreg` while `V8BImode`/`V4BImode` `CONST_INT` operands must have each non-zero 2-bit or 4-bit lane mask canonicalized to all-ones in `HImode` before `gen_lowpart`. [F37, F38]
- In `gcc/config/arm/arm-mve-builtins.cc`, `#define IN_TARGET_CODE 1` must precede `config.h`, `system.h`, and `coretypes.h` (enabling `POLY_INT_CONVERSION`), `#include "gt-arm-mve-builtins.h"` must appear at the end of the file after closing `namespace arm_mve`, `using namespace arm_mve;`, and all `GTY(())` and `gt_ggc_mx`/`gt_pch_nx` declarations, and `function_instance` must not contain GGC-managed `tree` or heap pointers while `registered_function::instance` is marked `GTY ((skip))` with empty `gt_ggc_mx`/`gt_pch_nx` hooks. [F7, F10, F15]
- In `gcc/config/arm/arm.md`, the `"enabled"` attribute must never depend on `"opt_enabled"` or per-function predicates (`optimize_function_for_speed_p`/`optimize_function_for_size_p`); `"predicable_short_it"` must be `"yes"` only on 16-bit Thumb-2 alternatives of `"predicable"` instructions while alternatives emitting non-short IT blocks must set `"enabled_for_short_it"` to `"no"` (for `arm_restrict_it`); and `"mve_safe_imp_xlane_pred"` must be `"yes"` only on across-lane MVE instructions whose unmasked lanes cannot affect active lanes when inputs are VCTP-predicated. [F60, F61, F63]
- In `gcc/config/arm/arm.opt`, CPU-quirk-defaulted erratum flags (`mfix-cortex-m3-ldrd`, `mfix-cmse-cve-2021-35465`, `mfix-cortex-a57-aes-1742098`) must use `Init(2)` so `arm_option_override` can detect unset options (`== 2`), and in `arm.md` the `arch` and `arch_enabled` attributes must include `fix_vlldm` so `lazy_load_multiple_insn` in `vfp.md` selects its `vscclrm\t{vpr}\;vlldm\t%0` alternative before the unmitigated `vlldm` alternative. [F87, F88]
- In `gcc/config/arm/arm.md`, element 0 of `operands[2]` in `*push_multi` holds the `UNSPEC_PUSH_MULT` `SET` (whose first register is `operands[1]`) and `XVECEXP (operands[0], 0, 0)` in `*vfp_pop_multiple_with_writeback` holds the base-register writeback `SET`, so both patterns must start their register loops at index 1, and `*vfp_pop_multiple_with_writeback` must emit `-` only when `(num_regs - 1) > 1`. [F57, F58]
- In `gcc/config/arm/arm.md`, `*load_multiple` for >4 registers requires `reload_completed` in its insn condition (since operands use `load_multiple_operation` without register constraints); in `untyped_call` and `untyped_return`, after handling `R0_REGNUM` via `arm_gen_store_multiple`/`arm_gen_load_multiple` (which uses write-back on `TARGET_THUMB`), `size` must be set to `TARGET_ARM ? 16 : 0` so `addr` is not advanced twice. [F59, F85]
- In `gcc/config/arm/arm.md`, `movdi` on a core hard register (`REGNO <= LAST_ARM_REGNUM`) failing `targetm.hard_regno_mode_ok (REGNO (op), DImode)` must split into `SImode` `gen_lowpart` and `gen_highpart` moves (staging volatile `MEM`s through a `DImode` pseudo), and the post-reload `ANY64_BF` register-to-register `define_split` must check `rtx_equal_p (operands[0], operands[3])` and swap low/high `SImode` move order when destination low overlaps source high. [F77, F79]
- In `gcc/config/arm/arm.md`, when `insv` expands into a `SUBREG` destination in ARM state, it must compute into a fresh `SImode` `subtarget` pseudo, unwrap `target` to `SUBREG_REG (target)` only when the inner mode is narrower than `SImode`, and emit a direct move to `target` (never `gen_lowpart`) when `target` remains a `SUBREG`. [F78]
- In `gcc/config/arm/arm.md`, conditional-compare patterns `*cmp_ite0`, `*cmp_ite1`, `*cmp_and`, and `*cmp_ior` must verify `GET_MODE (operands[6]) != CCmode` and `GET_MODE (operands[6]) == arm_select_dominance_cc_mode (operands[4], operands[5], DOM_CC_...)`; `movsfcc` and `movdfcc` must `FAIL` when `TARGET_THUMB2 && arm_restrict_it && !TARGET_VFP5`; and `truncdfhf2` must be gated on `(TARGET_EITHER && flag_unsafe_math_optimizations) || (TARGET_32BIT && TARGET_FP16_TO_DOUBLE)` to avoid double rounding via `SFmode`. [F69, F71, F76]
- In `gcc/config/arm/arm.md`, `arm_<mcrr>` and `arm_<mrrc>` must validate their 4-bit `opc1` operand (`operands[1]` in `mcrr`, `operands[2]` in `mrrc`) with `arm_const_bounds (op, 0, 16)` (unlike 3-bit `arm_<mcr>`/`arm_<mrc>` which use `(op, 0, 8)`), and `nonsecure_call_internal`/`nonsecure_call_value_internal` must keep the call target as a direct `memory_operand` inside `(call ...)` with `UNSPEC_NONSECURE_MEM` as a separate parallel element. [F74, F75]
- In `gcc/config/arm/arm.md`, stack-protector canary patterns (`*stack_protect_set_insn`, `arm_stack_protect_test_insn`, `stack_protect_set_tls`, `stack_protect_test_tls`) must remain unsplit `define_insn`s that clear the scratch canary register to 0 before finishing, and `*stack_protect_combined_set_insn`/`*stack_protect_combined_test_insn` must check `!general_operand (mem, SImode)` on `force_const_mem (SImode, operands[1])` and materialize `XEXP (mem, 0)` into the scratch register via `replace_equiv_address` before `emit_move_insn`. [F91, F92]
- In `arm1020e.md`, `arm1026ejs.md`, and `arm1136jfs.md`, every `define_bypass` to a store reservation (`1020store1_op`, `store1_op`, `11_store1`) requires `"arm_no_early_store_addr_dep"`; in `arm1136jfs.md`, bypasses into `11_alu_shift_op`, `11_alu_shift_reg_op`, and `11_mult1..11_mult7` require `"arm_no_early_alu_shift_value_dep"`, `"arm_no_early_alu_shift_dep"`, and `"arm_no_early_mul_dep"` respectively; in `arm1020e.md`, every VFP reservation must reserve `"1020a_e"` in cycle 1 and keep `"v10_fmstat"` in an `exclusion_set` with `"v10_fmac,v10_ds"`. [F66, F67, F68]

## Object Lifetimes

- Strings from `function_builder::get_name` are allocated on `m_string_obstack`: temporary names (e.g. in `add_unique_function`) must be freed via `obstack_free (&m_string_obstack, name)` before returning, while strings inserted into `m_overload_names` in `add_overloaded_function` must remain allocated until `~function_builder` without any earlier obstack pointer being passed to `obstack_free` after their allocation. [F11, F12]
- Every `registered_function` allocated with `ggc_alloc<registered_function> ()` and inserted into the non-GGC `function_table` must also be pushed to the `GTY(())` vector `registered_functions` via `function_builder::add_function`, and `function_expander` must keep its per-call vectors in `auto_vec` (`auto_vec<rtx, 16> args`, `auto_vec<expand_operand, 8> m_ops`) rather than raw `vec<T>` so heap storage is freed on scope exit. [F13, F14]

## API Contracts

- In `function_checker`, `require_immediate_enum`, `require_immediate_one_of`, `require_immediate_range`, and `require_immediate_range_multiple` take a `rel_argno` relative to `m_base_arg`, whereas `argument_exists_p`, `require_immediate`, and `require_signed_immediate` take an absolute `argno` index into `m_args`. [F3]
- `function_resolver::check_gp_argument (nops, i, nargs)` sets `nargs` to the total argument count (including any leading `inactive` argument and trailing `mve_pred16_t` predicate) and sets `i` to the 0-based index of the last non-predicate argument (`nops - 1` when unpredicated, `nargs - 2` when predicated); never call it with `nops == 0` when `pred == PRED_none`. [F5]
- `function_builder::get_name` must check `instance.shape->mode_after_pred ()` to place `pred_suffixes[instance.pred]` before the mode suffix when true (e.g. `_m_n`) and after when false (e.g. `_offset_p`); `function_expander::add_mem_operand` requires a `VECTOR_MODE_P` mode, sets `MEM` alignment to the element alignment `GET_MODE_ALIGNMENT (GET_MODE_INNER (mode))` (not full vector alignment), and registers it via `add_fixed_operand`. [F39, F56]
- In `gcc/config/arm/arm-protos.h`, declarations using `rtl.h` macros or types (`RTX_CODE`, `tune_params`) must stay inside `#ifdef RTX_CODE` (and callers must include `rtl.h` before `tm_p.h`/`arm-protos.h`), while D-frontend target hooks (`arm_d_target_versions`, `arm_d_register_target_info`) belong in `gcc/config/arm/arm-d.h` so `tm_d.h` users do not need `tm.h` or `tm_p.h`. [F8, F9]
- `arm_configure_build_target` must take only `(struct arm_build_target *, struct cl_target_option *, bool)` and inspect `cl_target_option` fields directly (never `global_options_set` or a `gcc_options *opts_set` parameter), and scalar built-ins must not be mapped to Neon/MVE ACLE intrinsic built-ins via `TARGET_VECTORIZE_BUILTIN_VECTORIZED_FUNCTION` (use standard RTL optabs instead). [F47, F48]
- In `gcc/config/arm/arm.md`, any predicable `define_insn` or `define_insn_and_split` emitting multiple machine instructions must set `"ce_count"` to that instruction count; overflow-checking expanders (`addv<mode>4`, `uaddv<mode>4`, `subv<mode>4`, `usubv<mode>4`) must emit dynamic overflow branches via `arm_gen_unlikely_cbranch`; conditional move expanders (`movsicc`, `movhfcc`, `movsfcc`, `movdfcc`) must use `expandable_comparison_operator` for operand 1 and canonicalize via `arm_validize_comparison`; and `ashldi3`/`ashrdi3` expanding via `gen_mve_lsll`/`gen_mve_asrl` must convert `operands[2]` from `SImode` to `QImode` via `convert_modes (QImode, SImode, operands[2], 0)`. [F62, F64, F72, F73]
- In `gcc/config/arm/arm.md`, `storehi`, `storehi_bigend`, and `storeinthi` must force `XEXP (mem, 0)` into an `SImode` register via `replace_equiv_address` before `adjust_address` whenever the address is a `MINUS` or non-`CONST_INT_P` `PLUS`; `reload_outdf` must delegate `POST_INC`/`PRE_DEC` on `operands[0]` to `gen_movdi` via byte-offset-0 `DImode` `SUBREG`s while decomposing `PRE_INC`/`POST_DEC` into explicit `gen_addsi3` of `+/-8` around a base-register store; and `load_multiple`/`store_multiple` must `FAIL` unless `operands[2]` is a `CONST_INT_P` in `[2, MAX_LDM_STM_OPS]` and `regno <= LAST_ARM_REGNUM - 1` with `regno + INTVAL (operands[2]) <= LAST_ARM_REGNUM`. [F82, F83, F84]

## Error Handling

- `arm_mve::register_vector_type` must verify that `lang_hooks.decls.pushdecl` returned a `TYPE_DECL` whose `TREE_TYPE` is not `error_mark_node` and satisfies `TYPE_MAIN_VARIANT (TREE_TYPE (decl)) == abi_vector_types[type]` before storing `TREE_TYPE (decl)` in `acle_vector_types[0][type]` (falling back to `abi_vector_types[type]` otherwise), and `handle_arm_mve_h` must verify `handle_arm_mve_types_p` is true before allocating `function_table` or registering functions. [F17, F22]
- In `function_resolver`, `get_argument_type` and `matches_type_p` must check argument and candidate trees against `error_mark_node` before inspecting `TREE_TYPE` or `TYPE_MAIN_VARIANT`, and `require_derived_vector_type` must verify `resolve_to (mode_suffix_id, first_type) != error_mark_node` before emitting a cross-argument diagnostic referencing `first_type`. [F27, F28]
- `gimple_folder::fold` must not fold MVE built-in calls when `!TARGET_HAVE_MVE` or when `lhs` is null on a non-void call, and `report_missing_float` (via `check_requires_float` in `check_builtin_call` and `expand_builtin`) must gate `"requires ISA extension mve.fp"` diagnostics on `reported_missing_float_p`. [F29]

## External Contracts

- In `register_builtin_tuple_types`, each MVE tuple struct type must be built via `lang_hooks.types.simulate_record_decl` with a single `FIELD_DECL` named `"val"`, and `function_builder::add_function` must encode MVE built-in codes as `(index << ARM_BUILTIN_SHIFT) | ARM_BUILTIN_MVE` and push a placeholder entry with `decl = integer_zero_node` (never `NULL_TREE` or `error_mark_node`) into `registered_functions` whenever an overload or unprefixed alias is omitted. [F21, F46]
- In `gcc/config/arm/arm.opt`, `march=`, `mcpu=`, and `mtune=` must each specify both `Save` and self-naming `Negative(march=)`/`Negative(mcpu=)`/`Negative(mtune=)`, and `mlibarch=` must remain `Target RejectNegative JoinedOrMissing NoDWARFRecord DriverOnly Undocumented` for `MULTILIB_ARCH_CANONICAL_SPECS`. [F89, F90]

## Known Pitfalls

- In `function_checker::require_immediate_enum`, `TREE_VALUE (entry)` from `TYPE_VALUES (type)` must be unwrapped via `DECL_INITIAL (value)` when `TREE_CODE (value) == CONST_DECL` before calling `wi::to_widest`; in `function_resolver`, distinguish single MVE vectors from tuples using `VECTOR_TYPE_P (type)` rather than `VECTOR_MODE_P (TYPE_MODE (type))` (tuple `RECORD_TYPE`s also have `VECTOR_MODE_P` modes); and in `function_builder::add_unique_function`, call `get_attributes (instance)` freshly for each `add_function` call rather than sharing the attribute `TREE_LIST`. [F18, F19, F24]
- In `gcc/config/arm/arm.md`, internal flag-setting patterns like `sub_cmpVsi3` and `usub_cmpVsi3_borrow` that only set `CC_REGNUM` in `CC_Vmode` or `CC_Bmode` without trapping or branching must never be given standard trapping-arithmetic optab names (`subv<mode>3`, `usubv<mode>3`, `addv<mode>3`, `uaddv<mode>3`). [F70]
