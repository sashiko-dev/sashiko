# libcpp

This unit implements the GCC C/C++ preprocessor library (`libcpp`), handling preprocessor directives (`#include`, `#define`, `#if`, `#pragma`, `#embed`), constant expression evaluation, source file caching and inclusion lookup, precompiled header (PCH) validation, identifier hash tables, diagnostic emission, and source location/range encoding (`line_maps` and `rich_location`).

## Architecture & Data Flow

- Discriminated unions require checking their tag before access: in `cpp_hashnode`, `type` selects `value` (`NT_VOID` -> `answers`, `NT_USER_MACRO` -> `macro`, `NT_BUILTIN_MACRO` -> `builtin`, `NT_MACRO_ARG` -> `arg_index`) and `is_directive` selects whether `directive_index` is a `dtable` index or `NODE_OPERATOR` token type; in `cpp_macro`, `kind` selects `parm.next` (`cmk_assert`) vs `parm.params` and `exp.text` (`cmk_traditional`) vs `exp.tokens`; in `cpp_file_hash_entry`, `start_dir != NULL` selects `u.file` (`_cpp_file *`) vs `u.dir` (`cpp_dir *`). [F87, F88, F89]
- A `line_map *` points to `line_map_ordinary` iff `MAP_ORDINARY_P (map)` (`map->start_location < LINE_MAP_MAX_LOCATION`) is true, and `line_map_macro` otherwise; downcasts must use `linemap_check_ordinary` or `linemap_check_macro`. Any code decrementing `line_table->info_ordinary.used` or `line_table->info_macro.used` (such as `read_original_filename`) must reset or clamp the corresponding `m_cache` index so `linemap_lookup` does not read out of bounds. [F55, F90]
- In `libcpp/files.cc`, `_cpp_file::fd` uses `-1` as the closed sentinel (since `0` is valid, including for `stdin`); every open check must test `file->fd != -1` and every `close (file->fd)` on a cached `_cpp_file` must reset `file->fd = -1`. In `_cpp_stack_file`, `deps_add_dep (pfile->deps, file->path)` must be called on first inclusion even when `file->path` is `""` (`stdin`) so `mkdeps` adjusts its `-MP` phony target start index. [F41, F99]
- In `_cpp_find_file`, `search_cache` must match both `head->start_dir == start_dir` and `head->u.file->embed == is_embed`, and newly found files whose search traversed `bracket_include`, `quote_include`, or `embed_include` must also be cached under those chain heads. Files resolved via `search_path_exhausted` (`pfile->cb.missing_header`) must be linked into `pfile->all_files` but never cached in `pfile->file_hash`; if `*hash_slot == NULL`, store a non-NULL dummy pointer before calling `htab_clear_slot`. [F19, F53, F97]
- In `read_file_guts`, regular files with `file->st.st_size > INTTYPE_MAXIMUM (ssize_t)` must be rejected before allocation, and both initial and resized allocations of `buf` must include `CPP_BUFFER_PADDING` extra bytes beyond `size`. [F56]
- Multiple-include guard tracking (`pfile->mi_valid` and `ifs->mi_cmacro`) must be invalidated on `#else`, `#elif`, `#elifdef`, `#elifndef`, non-`!defined(X)` `#if` expressions, or in `_cpp_pop_file_buffer`. `do_else` and `do_elif` must update the top `pfile->buffer->if_stack` entry in place (without pushing/popping) and clear `ifs->mi_cmacro = 0`, while `_cpp_pop_buffer` must reset `pfile->state.skipping = 0` when unwinding `buffer->if_stack`. [F48, F98]
- Macro definedness tests in `#ifdef`, `#ifndef`, `#elifdef`, `#elifndef`, and `parse_defined` must call `_cpp_defined_macro_p (node)` (which returns false for `NODE_CONDITIONAL` macros) followed by `_cpp_maybe_notify_macro_use` rather than `cpp_macro_p (node)`. [F84]
- In `do_undef`, `NODE_WARN` identifiers must be diagnosed even when `!cpp_macro_p (node)` unless `suppress_builtin_macro_warnings` is set, `cpp_keyword_p (node)` is true, or `-Wkeyword-macro` already handled the node (`diagnosed`). [F80]
- In `_cpp_handle_directive`, when a directive is encountered while `pfile->state.parsing_args` is non-zero (`was_parsing_args`), `parsing_args` and `prevent_expansion` are zeroed after emitting a pedwarn and restored to `parsing_args = 2` and `prevent_expansion = 1` after `end_directive` only if `!pfile->state.in_deferred_pragma`. [F86]
- When `destringize_and_run` pushes a temporary `cpp_buffer` for `_Pragma`, it must initialize `pfile->buffer->file` and `pfile->buffer->sysp` from `pfile->buffer->prev` before `do_pragma` and propagate `pfile->buffer->sysp` back to `pfile->buffer->prev->sysp` before `_cpp_pop_buffer`. In `cpp_diagnostic_at` and `cpp_diagnostic_with_line`, `pfile->diagnostic_override_loc` must only override the location (and suppress `column` override) when `level != CPP_DL_NOTE`. [F103, F106]
- In `libcpp/directives.cc`, `#pragma push_macro` and `#pragma pop_macro` (`lex_identifier_from_string`) must lex the destringized macro name by pushing a temporary `cpp_buffer` and calling `_cpp_clean_line` and `_cpp_lex_direct` under `cpp_auto_suppress_diagnostics`, requiring a single `CPP_NAME` token reaching `rlimit`. [F85, F104]
- In `libcpp/init.cc`, `_Pragma` and `__STDC__` must remain the last two entries of `builtin_array` in that order unless `cpp_init_special_builtins` is updated in tandem (`n -= 2` for `traditional` or `n--` for normal `__STDC__`). In `libcpp/expr.cc`, `optab` is indexed directly by `enum cpp_ttype` through `CPP_LAST_CPP_OP` (`CPP_LESS_EQ`), so any change to `TTYPE_TABLE` in `libcpp/include/cpplib.h` at or before `CPP_LESS_EQ` must update `optab` in the exact same order. [F42, F45]
- During `_cpp_parse_expr` and `reduce`, `pfile->state.skip_eval` is positive inside unevaluated operands of `||`, `&&`, and `?:`; evaluation diagnostics in `eval_token` (`CPP_W_UNDEF`), `reduce` (overflow), `num_unary_op` (unary `+`), and `num_div_op` (division by zero) must check `!pfile->state.skip_eval`. `_cpp_parse_expr` must increment `pfile->state.comma_ok` on `CPP_OPEN_PAREN`/`CPP_QUERY` and decrement it on `CPP_CLOSE_PAREN`/`CPP_COLON` so `num_binary_op` pedwarns on `CPP_COMMA` in C++ only when `!pfile->state.comma_ok` (and in C when `!CPP_OPTION (pfile, c99) || !pfile->state.skip_eval`). [F81, F82]
- In `cpp_interpret_integer`, once `result.low` reaches the single-word threshold `max`, `max` must be set to `0` and tested with strict inequality (`result.low < max`) so all subsequent digits route through `append_digit` even if `result.low` wraps to `0`. In `cpp_classify_number`, floating-point imaginary constants (`CPP_N_IMAGINARY` with `CPP_N_FLOATING`) in C must only pedwarn when `!CPP_OPTION (pfile, imaginary_constants) && CPP_PEDANTIC (pfile)` and otherwise warn under `CPP_W_C23_C2Y_COMPAT`, whereas C++ and integer imaginary constants always pedwarn. [F50, F83]
- In `EMBED_PARAMS` (`libcpp/directives.cc`), standard `#embed` parameters must precede `NUM_EMBED_STD_PARAMS` (`EMBED_PARAM_OFFSET + 1`) and `gnu::` parameters must follow it, because `_cpp_parse_embed_params` searches `[0, NUM_EMBED_STD_PARAMS)` for unprefixed names and `[NUM_EMBED_STD_PARAMS, NUM_EMBED_PARAMS)` for `gnu::` names. In `finish_embed`, when `CPP_OPTION (pfile, lang) != CLK_ASM && limit >= 64`, middle bytes `[1 .. limit - 2]` must be emitted as `CPP_EMBED` tokens of at most `INT_MAX` and at least 32 bytes (rebalancing 64 bytes from `tok[-2]` if the final chunk is `< 32`). [F46, F57]
- In `pch_open_file`, a `.gch` PCH may only be opened when `file->name[0] != '\0'`, `pfile->cb.valid_pch` is set, `!file->embed` holds, and every entry preceding `pfile->main_file` on `pfile->all_files` has `implicit_preinclude` set. In `is_known_idempotent_file`, `#import` must call `_cpp_mark_file_once_only` before checking `file->cmacro`, and `file->cmacro && cpp_macro_p (file->cmacro)` must precede `file->pchname` handling (which calls `pfile->cb.read_pch`, clears `file->fd = -1` and `file->pchname`, and returns `true` without stacking). [F91, F93]
- Because `_cpp_save_file_entries` sorts `pchf->entries` with `memcmp` via `pchf_save_compare`, `size` must remain the first field of `struct pchf_entry` and `pchf_compare` must compare `size` using `memcmp (&d->size, &e->size, sizeof (off_t))` before lazily computing `md5_buffer`. Because loading a PCH replaces the identifier hash table, `_cpp_save_pragma_names` (`save_registered_pragmas`) and `_cpp_restore_pragma_names` (`restore_registered_pragmas`) must traverse `pfile->pragmas` in identical tree order. [F54, F95]
- In `libcpp` implementation files, `"config.h"` and `"system.h"` must be included before `"cpplib.h"`, `"line-map.h"`, and `"internal.h"` so macros like `CHECKING_P`, `SIZEOF_INO_T`, `SIZEOF_DEV_T`, `GCC_VERSION`, `O_BINARY`, `HAVE_DOS_BASED_FILE_SYSTEM`, and `HAVE_DESIGNATED_INITIALIZERS` are defined before header conditionals and `ENABLE_CANONICAL_SYSTEM_HEADERS`. In `libcpp/include/line-map.h`, the `!CHECKING_P` definition of `linemap_assert(EXPR)` must keep `EXPR` in `((void)(0 && (EXPR)))`. [F12, F49, F59, F60, F61, F62]

## Object Lifetimes

- When lexing a multi-token construct or trailing directive tokens (`get__Pragma_string`, `check_eol`, `skip_rest_of_line`, `_cpp_lex_direct`) while holding a pointer to an earlier `cpp_token` or its `val.str`, `pfile->keep_tokens` must be incremented beforehand and decremented afterward so newline handling and `end_directive` do not reset `pfile->cur_run` and overwrite the token. [F68]
- Because `_cpp_convert_input` may advance `_cpp_file::buffer` past a UTF-8 BOM while storing the allocation base in `_cpp_file::buffer_start`, freeing a file buffer must always pass `buffer_start` (not `buffer`) to `free`, and `_cpp_pop_file_buffer` must null both `buffer_start` and `buffer`. [F69]
- When freeing a `tokenrun` chain in `cpp_destroy` or `_cpp_free_embed_params_tokens`, `run->base` is freed for every initialized run, but the `tokenrun` struct itself must only be freed when `run != &pfile->base_run` (or `t != &save->base_run`) because `base_run` is embedded directly in the enclosing struct. [F65]
- `pfile->buffer_ob` is a strict LIFO obstack shared by `cpp_buffer` (`cpp_push_buffer`/`_cpp_pop_buffer`) and `struct if_stack` (`push_conditional`/`do_endif`); allocations on `buffer_ob` must never outlive the enclosing `cpp_buffer`. `parse_answer` constructs a candidate `cpp_macro` in uncommitted space at the front of `pfile->a_buff` via `_cpp_reserve_room`; callers that only inspect it (`_cpp_test_assertion`, `do_unassert`, duplicate `do_assert`) must not call `_cpp_commit_buff` or `free` on it. [F66, F67]
- `semi_embedded_vec<T, NUM_EMBEDDED>` only frees its `m_extra` array in `~semi_embedded_vec` and does not destroy pointed-to elements; `rich_location` directly owns and must `delete` the `fixit_hint *` elements in `m_fixit_hints`. `label_text` must be constructed via `label_text::take` when wrapping a heap-allocated `char *` to be freed by `~label_text`, or `label_text::borrow` for non-owned buffers. [F72, F73]

## API Contracts

- Any translation unit requiring GCC `gengtype` annotations on `libcpp` structures (`ht_identifier`, `cpp_token`, `line_maps`) must define `GTY` before including `"symtab.h"`, `"line-map.h"`, or `"cpplib.h"`, which otherwise define a no-op `#define GTY(x)` fallback. [F63]
- `destringize_and_run` must save and set `pfile->diagnostic_override_loc` to `expansion_loc` while lexing and running a `_Pragma` buffer, and pragma callbacks invoked during `_Pragma` must query `cpp_get_diagnostic_override_loc` when `pfile->directive_line` lacks a valid token location. `cpp_define`, `_cpp_define_builtin`, and `cpp_undef` must set `CPP_OPTION (pfile, suppress_builtin_macro_warnings) = 1` around `run_directive` and restore it to `0` afterward. [F77, F79]
- In `search_path_head` (`libcpp/files.cc`), an empty filename (`*fname == '\0'`, representing `stdin`) must return `&pfile->no_search_path`, because `_cpp_find_file` and `open_file` only recognize `""` as `stdin` when no directory prefix is prepended. [F100]
- When evaluating `#embed` or `__has_embed` parameters (`pfile->state.in_directive == 3`), `_cpp_parse_expr` must reject negative values and values with nonzero `top->value.high`, and `_cpp_parse_embed_params` must further reject `offset` values exceeding `INTTYPE_MAXIMUM (off_t)`. [F52]
- In `num_lshift` (`libcpp/expr.cc`), when `n < precision` and `!num.unsignedp`, `num.overflow` must be `false` in C++20+ (`CLK_GNUCXX20`), and in C++11–C++17 (`CLK_GNUCXX11`) with non-negative `orig` it must be set only when logical `orig >> (precision - 1 - n) > 1`. For `0o`/`0O` octal tokens, `cpp_classify_number` must record `zero_o_prefix` to reject `float_flag != NOT_FLOAT` with `CPP_N_INVALID`, and `cpp_interpret_integer` must advance `p` past `'o'`/`'O'` for `CPP_N_OCTAL`. [F101, F102]
- `validate_pch` must temporarily set `file->path = pchname` while opening and validating a candidate `.gch` file, close `file->fd` and set `file->fd = -1` when `pfile->cb.valid_pch` rejects it, and always restore `file->path` before returning. Front ends supporting PCH must set `line_maps::cmdline_location` and call `cpp_set_line_map` after reading a PCH file so `pfile->line_table` and restored command-line macro locations reference the newly loaded `line_maps`. [F92, F96]

## Error Handling

- In `_cpp_find_file`, when `make_cpp_file` is not chained into `pfile->all_files` (because `kind == _cpp_FFK_PRE_INCLUDE` fails or a secondary `search_cache` lookup hits), both `file->name` and `file` must be explicitly freed with `free` before returning or replacing `file`. [F70]
- `parse_include` returns a heap-allocated filename string (and optionally a heap-allocated `const cpp_token **` comment array in `*buf` via `check_eol_return_comments`); callers (`do_include_common`, `do_embed`, `do_pragma_dependency`) must free the returned filename and `*buf` on all normal and early-exit paths. [F71]
- In `_cpp_stack_embed`, when reading a non-regular file with a non-zero `params->offset` allocates a separate scratch buffer `buf2` (`size2 = 32 * 1024`), any read error or completion of the offset-skipping loop must free `buf2` when `buf2 != buf` in addition to freeing `buf` and jumping to `fail:` to close `file->fd`. [F74]

## Known Pitfalls

- In `finish_embed`, the first generated token must be written into `pfile->directive_result` and only the remaining `count` tokens into `toks` (`tok_buff->base`), skipping `prefix->base_run.base[0]` (`t++; cnt--;`) when copying `prefix` runs or switching `tok` from `&pfile->directive_result` to `toks` after byte 0 when `prefix->count == 0`. When `params->has_embed` is true (`__has_embed`), `_cpp_stack_embed` and `finish_base64_embed` must determine emptiness and validity without allocating or reading the full payload into a heap buffer. [F43, F58]
- `cpp_diagnostic_get_current_location` must not read `pfile->cur_token[-1].src_loc` when `pfile->cur_token == pfile->cur_run->base`, and `_cpp_stack_include` must zero `pfile->cur_token[-1].src_loc` when `type == IT_CMDLINE` and `pfile->cur_token != pfile->cur_run->base`. [F78]
- In `interpret_float_suffix`, the loop parsing `_FloatN` and `_FloatNx` bit-width digits must stop accumulating into `fn_bits` as soon as `fn_bits >= CPP_FLOATN_MAX`, leaving any remaining digits to be rejected by the outer suffix loop rather than overflowing `fn_bits`. [F51]
