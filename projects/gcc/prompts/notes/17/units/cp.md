# cp

Implements C++ overload resolution, implicit conversion sequence construction, and method/function call building in the GCC C++ front end. It evaluates candidate functions and templates (via z_candidate and tourney/joust), ranks conversion sequences, and generates AST nodes for function, operator, constructor, and destructor invocations.
Implements C++20 concepts and constraints (constraint.cc), C++26 contracts (contracts.cc, contracts.h), and C++20 coroutines (coroutines.cc, coroutines.h). These files handle constraint normalization and satisfaction checking, pre/postcondition and assertion AST tracking and lowering, and coroutine ramp/actor/destroyer state machine transformation.
Defines the central C++ front-end AST data structures, macros, and declarations (cp-tree.h), UndefinedBehaviorSanitizer C++ instrumentation (cp-ubsan.cc), and language-level expression type conversions (cvt.cc). cp-tree.h is the foundational header included across the entire C++ front end.
Processes declarations, declarators, and type definitions (classes, enums, arrays, functions, and variables) in the C++ front end. It handles declaration merging, scope management, variable initialization, local static guard generation, and destructor/cleanup registration.
Handles secondary declaration processing and translation-unit finalization (decl.h, decl2.cc), C++ AST dumping (dump.cc), C++ diagnostic formatting and pretty-printing (error.cc), exception handling semantics (except.cc), and C++ constant/expression expansion helpers (expr.cc). decl2.cc notably drives c_parse_final_cleanups, static initialization/destruction generation, linkage/visibility determination, and deferred instantiation emission.
Covers friend declaration management (friend.cc), the g++ driver specification and command-line option handling (g++spec.cc, lang-specs.h), object/member/new/delete initialization (init.cc), lambda expression semantics and closure construction (lambda.cc), C++ lexical analyzer and pragma/trait initialization (lex.cc), and constraint subsumption logic (logic.cc).
Implements Itanium C++ ABI name mangling (mangle.cc), C++20 module mapper client communication and resolution (mapper-client.cc, mapper-client.h, mapper-resolver.cc), C++26 reflection metafunction lookup tables (metafns.h), and special member function (defaulted/deleted constructors, destructors, assignment, comparison operators) and thunk synthesis (method.cc).
Implements C++20 modules and header units, including serialization and lazy deserialization of AST declarations, types, templates, and preprocessor macros to and from Compiled Module Interface (CMI) files. It encapsulates module records inside a custom 32-bit ELF container format (ELROND) using Tarjan strongly connected components (SCCs) and mmap/file I/O.
Implements C++ lexical and qualified name lookup, argument-dependent lookup (ADL), namespace and binding management (name-lookup.cc, name-lookup.h), C++ operator metadata definitions (operators.def), and constructor/destructor body cloning and inlining preparation (optimize.cc).
Implements the recursive-descent C++ parser and token stream lexer buffer for GCC. It consumes tokens from libcpp, manages tentative parsing and backtracking contexts, handles deferred parsing of class members and default arguments, and invokes semantic routines across the C++ front end (including OpenMP/OpenACC directives) to construct the AST.
Implements C++ templates, including template parameter processing, template argument deduction and unification, partial ordering, explicit and partial specializations, SFINAE substitution (tsubst*), pack expansion, and deferred template instantiation.
Provides C++ AST node construction, lvalue/rvalue classification, cv-qualification and array type canonicalization, tree walking, and C++-specific attribute handling (tree.cc), along with type-traversal utilities (type-utils.h) and a gperf-generated standard library header lookup table for diagnostics (std-name-hint.h).
Implements C++ expression construction and type checking, including unary, binary, conditional, cast, member access, pointer-to-member, assignment, and return expressions. It also provides type compatibility predicates (same_type_p, compypes) and type completion helpers (complete_type, require_complete_type).

## Architecture & Data Flow

- In add_function_candidate, when DECL_CONSTRUCTOR_P (fn) is true and artificial parameters are skipped, each conversion slot convs[i] (for 0 <= i < len) must read its source argument from first_arg when i == 0 && first_arg != NULL_TREE and from (*args)[i + skip - (first_arg != NULL_TREE ? 1 : 0)] otherwise. [F1]
- In add_function_candidate, add_candidate at label out must be passed orig_first_arg rather than first_arg because constructor handling clears first_arg when consuming an artificial parameter while rejection helpers (arity_rejection, arg_conversion_rejection, bad_arg_conversion_rejection) rely on the post-skip first_arg. [F2]
- In add_template_candidate_real, when building args_without_in_chrg for fn_type_unification, destination index ia (starting at 0) and source index ix (starting at skip_without_in_chrg) must be tracked separately so that ia equals nargs_without_in_chrg after copying. [F3]
- In build_over_call, argarray_size, arg_index, conv_index, and param_index must be advanced independently: constructor artificial arguments ('this' and VTT) advance argarray_size and arg_index (via consume_object_arg) without advancing conv_index or param_index, whereas DECL_IOBJ_MEMBER_FUNCTION_P advances conv_index++ without param_index++. [F4]
- In joust, when cand1->num_convs != cand2->num_convs because one candidate is a static member function and the other is non-static, off1 and off2 must offset cand1->convs[i + off1] and cand2->convs[i + off2] in every per-argument loop, and len (initialized from cand1->num_convs) must be decremented when static_2 holds. [F5]
- In add_candidates, when a non-static member function is encountered with first_arg == NULL_TREE, (*args)[0] is extracted into first_arg and (*args)[1..] into non_static_args, but each candidate must be passed fn_first_arg and fn_args so static or non-member functions in the same lkp_range (fns) loop still receive NULL_TREE and args. [F6]
- In build_new_method_call, orig_instance, orig_fns, and orig_args (copied before resolve_args and baselink dismantling) must be used when constructing the non-dependent COMPONENT_REF and call via build_min_non_dep_call_vec when processing_template_decl is true. [F7]
- When build_conditional_expr invokes add_builtin_candidates for COND_EXPR, it pushes args in the order (arg2, arg3, arg1) so add_builtin_candidates only iterates over the first two elements (if (len == 3) len = 2), and build_builtin_candidate shifts convs[0..1] to convs[1..2] and places arg1's boolean conversion at convs[0]. [F8]
- When devirtualizing or converting `this` for an implicit-object member function in `build_over_call`, if `BINFO_TYPE (cand->conversion_path)` differs from `DECL_CONTEXT (fn)` (such as when `fn` was introduced via a `using`-declaration), `base_binfo` must first be resolved to `DECL_CONTEXT (fn)` via `lookup_base`. [F17]
- After `lookup_vfn_in_binfo` finds a final overrider `ov` on a fixed-type object in `build_over_call`, `base_binfo` must be unwound along `BINFO_INHERITANCE_CHAIN` until `SAME_BINFO_TYPE_P (BINFO_TYPE (obinfo), DECL_CONTEXT (ov))` holds, falling back to a virtual call if not found (diamond inheritance). [F18]
- In `extend_ref_init_temps_1`, recursive lifetime extension of temporaries in `TARGET_EXPR_INITIAL (expr)` must be performed after creating `var` and before calling `maybe_constant_init (expr, var, /*manifestly_const_eval=*/true)`, because extending inner temporaries can change the constant evaluation result. [F21]
- In `is_std_init_list`, `type` must be stripped of typedefs via `type = TYPE_MAIN_VARIANT (type)` before checking `CP_TYPE_CONTEXT (type) == std_node` and `DECL_NAME (TYPE_NAME (type)) == init_list_identifier`, because a typedef to `std::initializer_list<T>` has the typedef's own `TYPE_NAME` and context. [F23]
- In `struct conversion`, `u.next` is the active union member only when `has_next (code)` is true (i.e., `kind` is not `ck_identity`, `ck_ambig`, `ck_list`, `ck_aggr`, or `ck_deferred_bad`), `u.expr` is active only for `ck_identity`, `ck_aggr`, or `ck_ambig`, `u.list` is active only for `ck_list`, and `cand` is used only for `ck_user`. [F25]
- In `build_op_delete_call_1`, when selecting a placement deallocation function (`placement != NULL_TREE`), any `TEMPLATE_DECL` candidate must undergo template argument deduction via `fn_type_unification` with `addr` and `placement_args` before checking `constraints_satisfied_p` and `compparms`. [F30]
- Both `add_function_candidate` and `add_template_candidate_real` (when `!obj`) must verify parameter arity against the argument count before computing argument conversions or calling `fn_type_unification`, and `add_function_candidate` must also check `constraints_satisfied_p (fn)` before computing conversions. [F31]
- In `set_flags_from_callee`, `cp_function_chain->can_throw` and `current_function_returns_abnormally` must only be updated when `!cp_unevaluated_operand`. [F33]
- When comparing or hashing placeholder `ATOMIC_CONSTR`s, `equivalent_placeholder_constraints` and `iterative_hash_placeholder_constraint` must skip index 0 of the concept-check argument `TREE_VEC` (`TREE_OPERAND (c, 1)`), starting at index 1 or stopping before 0. [F37]
- In `get_mapped_args`, the `level` returned by `template_parm_level_and_index` is 1-based while `index` is 0-based, so `lists` is indexed at `level - 1`, grown with `safe_grow_cleared (index + 1, false)` to accommodate sparse mappings, and written back via `SET_TMPL_ARGS_LEVEL (args, i + 1, level)`. [F38]
- In `remap_contract`, after remapping the first parameter (`*this`), any remaining artificial parameters (`_in_charge`, `__vtt_parm`) must be skipped independently on `sp` and `dp` using `src_num_artificial_args` and `dst_num_artificial_args`, and a trailing unmatched `dp` on a `POSTCONDITION_STMT` maps `POSTCONDITION_IDENTIFIER`. [F39]
- When filtering contract specifiers by `contract_match_kind`, `copy_contracts_list` and `copy_and_remap_contracts` must accumulate matching elements into a separate `copies` vector and return `NULL_TREE` if `copies.is_empty ()`, never an empty `TREE_VEC` or a `TREE_VEC` sized to the unfiltered input. [F40]
- Coroutine suspend point indices in `build_actor_fn` reserve `0` for initial entry and `1` for `coro.delete.promise`, while the `body_count` (`await_count`) await points use even resume indices starting at `2` (`data.index = 2`, stepped by `+ 2` in `expand_one_await_expression`) and odd destroy indices `lab_num = 3` (`+ 2`). [F41]
- In `register_local_var_uses`, variables in the outermost `BIND_EXPR` (`lvd->nest_depth == 0`) with a non-null `DECL_NAME` must receive their exact unmangled `DECL_NAME` as `local_var.field_id`, whereas nested scopes (`nest_depth > 0`) append `_%u_%u` (`nest_depth`, `bind_indx`). [F43]
- In gcc/cp/coroutines.cc, code that tests target assembler label macros NO_DOT_IN_LABEL or NO_DOLLAR_IN_LABEL with #ifndef (such as get_fn_local_identifier) must appear after tm.h is included (via target.h or cp-tree.h) so that target definitions of those macros are visible before preprocessor evaluation. [F45]
- In await_statement_walker (gcc/cp/coroutines.cc), pushing a BIND_EXPR and its BIND_EXPR_BLOCK onto awpts->bind_stack and awpts->block_stack must be paired with popping both stacks immediately after walking BIND_EXPR_BODY (*stmt). [F48]
- tsubst_constraint_variables must clear cp_unevaluated_operand and cp_unevaluated_typeid_cutoff to 0 across the call to tsubst on the parameter list and restore them immediately afterward. [F56]
- tsubst_requires_expr, tsubst_constraint, and satisfy_normalized_constraints must establish a cp_unevaluated sentinel in scope before substituting or satisfying constraint expressions. [F57]
- In build_contract_violation_ctor, TREE_CONSTANT (ctor) may only be set to true when every field initializer (assertion_kind, eval_semantic, comment, and std_src_loc_impl_ptr after convert_from_reference) satisfies really_constant_p (or is synthesized as an integer constant or source location pointer). [F58]
- In `evaluate_concept_check`, `constraint_satisfaction_value` must be evaluated after `push_to_top_level ()` (with `push_access_scope` preserving any class or `FUNCTION_DECL` scope) so declarations instantiated during concept evaluation do not enter the current scope's binding table. [F64]
- In both overloads of `satisfy_declaration_constraints`, when `regenerated_lambda_fn_p (t)` is true, the single-level `args` must be augmented with the lambda's outer regenerating template arguments via `add_to_template_args` before checking dependence or normalizing constraints. [F65]
- In `satisfy_declaration_constraints`, if `vec_safe_length (failed_type_completions)` changes during `satisfy_normalized_constraints`, the result must not be stored in `decl_satisfied_cache` so `satisfy_atom` can detect satisfaction instability on later evaluations. [F66]
- When `remap_contract` and `copy_contracts_list` walk `CONTRACT_CONDITION` with `copy_tree_body_r`, `copy_body_data` must have `do_not_unshare = true`, `do_not_fold = true`, and `regimplify = false` so front-end tree sharing and unfolded condition trees are preserved. [F68]
- In template argument vectors, level numbers passed to TMPL_ARGS_LEVEL, SET_TMPL_ARGS_LEVEL, and TMPL_ARG are 1-based (outermost level is 1, mapped to (LEVEL) - 1), whereas parameter indices IDX within a level in TMPL_ARG are 0-based. [F77]
- DECL_PARM_INDEX numbers user-declared parameters starting at 1 and assigns 0 to all artificial parameters, while FUNCTION_FIRST_USER_PARM and FUNCTION_FIRST_USER_PARMTYPE skip leading artificial parameters via skip_artificial_parms_for. [F80]
- When cp_ubsan_check_member_access_r iterates over the operands of a handled_component_p expression while ucmd->is_addr is true, ucmd->is_addr must remain true only for operand 0 (if itself a handled_component_p), be set to false for operands i >= 1, and be restored to true after the loop. [F82]
- In gcc/cp/cp-tree.h, #define GCC_DIAG_STYLE __gcc_cxxdiag__ must precede #include "c-family/c-common.h" and #include "diagnostic.h" so that c-common.h and diagnostic-core.h do not default GCC_DIAG_STYLE to __gcc_cdiag__ or __gcc_tdiag__ when declaring ATTRIBUTE_GCC_DIAG. [F83]
- Any scope or RAII guard that saves, resets, or restores `cp_unevaluated_operand` (including `cp_unevaluated`, `cp_evaluated`, and `saved_scope`) must also save, reset (when clearing `cp_unevaluated_operand`), and restore `cp_unevaluated_typeid_cutoff`. [F99]
- `REFLECTION_TYPE_P(TYPE)` must verify `TYPE_P (TYPE)` and compare `TYPE_MAIN_VARIANT (TYPE)` against `meta_info_type_node` because `std::meta::info` is represented as a `LANG_TYPE` node rather than a dedicated tree code and may carry cv-qualifiers. [F100]
- On a `CONSTRUCTOR` node, `CONSTRUCTOR_OMITTED_NOT_WITHIN_LIFETIME_P` (`base.deprecated_flag` / `TREE_DEPRECATED`) marks that the object represented by the `CONSTRUCTOR` is within its lifetime while any omitted subobjects or fields are outside their lifetime. [F102]
- `lang_type::key_method` is multiplexed by `TYPE_POLYMORPHIC_P`: it stores `CLASSTYPE_KEY_METHOD` when `TYPE_POLYMORPHIC_P` is true and `CLASSTYPE_LAMBDA_EXPR` when `TYPE_POLYMORPHIC_P` is false. [F103]
- `lang_type::typeinfo_var` multiplexes `CLASSTYPE_TYPEINFO_VAR` (`VAR_DECL`), `ANON_AGGR_TYPE_FIELD` (`FIELD_DECL`), or a `TREE_LIST` holding both, so it must only be read or written via `CLASSTYPE_TYPEINFO_VAR`, `SET_CLASSTYPE_TYPEINFO_VAR`, `ANON_AGGR_TYPE_FIELD`, and `SET_ANON_AGGR_TYPE_FIELD`. [F104]
- In `lang_decl_min` and `lang_decl_fn`, when `DECL_THUNK_P` holds on a `FUNCTION_DECL`, `min.template_info` stores `THUNK_ALIAS` (not `DECL_TEMPLATE_INFO`), `min.access` stores `THUNK_VIRTUAL_OFFSET`, `fn.befriending_classes` stores `THUNK_TARGET`, and `fn.u5` stores `THUNK_FIXED_OFFSET` (not `DECL_CLONED_FUNCTION`). [F105]
