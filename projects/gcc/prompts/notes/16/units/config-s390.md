# config-s390

This unit defines the core target architecture configuration, command-line options, RTL instruction patterns, and user-facing C intrinsic headers for the IBM S/390 and z/Architecture (s390/s390x) backend, including z/TPF OS subtarget support. It specifies hardware facility flags (z900 through z17, VX/VXE, DFP, HTM, NNPA), register classes, ABI and stack frame layout in `s390.h`/`tpf.h`, and the primary RTL expanders, insns, splitters, and peepholes in `s390.md`, `subst.md`, and `tpf.md`.

## Architecture & Data Flow

- In `s390.h`, `REGNO_OK_FOR_INDEX_P(REGNO)` must check `(REGNO) < FIRST_PSEUDO_REGISTER` before evaluating `REGNO_REG_CLASS(REGNO)`, because `REGNO_REG_CLASS` directly indexes `regclass_map[FIRST_PSEUDO_REGISTER]` without bounds checking. [F3]
- In `s390.md`, `@split_stack_call<mode>` and `@split_stack_cond_call<mode>` must keep the jump `(set (pc) ... (label_ref (match_operand 2)))` and the `.rodata` parameter block emitted by `s390_output_split_stack_data` in the same insn sharing `match_operand 2`, so CFG edge redirection updates both the jump target and the parameter block return label. [F19]
- In `UNSPEC_EXECUTE_JUMP` patterns (`indirect_jump_via_inlinethunk<mode>*` and `casesi_jump_via_inlinethunk<mode>*`), the execute-target `larl_operand` (`label_ref`) must be wrapped in `(if_then_else (match_operand:P ...) (const_int 0) (const_int 0))` to hide it from `mark_jump_label` and prevent it from becoming the sole CFG jump target. [F20]
- In `s390.md`, post-reload `define_split` patterns for `*cpymem_short`, `*clrmem_short`, and `*cmpmem_short` must match the scratch clobber with `(clobber (match_scratch N))` rather than `(clobber (scratch))` because late passes like `late_combine` can propagate a `CONST_INT` into the length operand after RA allocated a register. [F23]
- Single-instruction SS-format block patterns (`*mvc`, `*clc`, `*xc`, `*xc_zero`) require a `const_int_operand` byte length in `1..256`; post-reload constant-length splitters for `*cpymem_short`, `*clrmem_short`, and `*cmpmem_short` must convert their `(length - 1)` operand via `GEN_INT ((INTVAL (op) & 0xff) + 1)`. [F27]
- In `*load_multiple_di`, `*load_multiple_si`, `*store_multiple_di`, and `*store_multiple_si` in `s390.md`, the end-register operand `operands[0]` must be computed as `REGNO(first_reg) + XVECLEN(operands[0], 0) - 1` because `lm`/`lmg`/`lmy` and `stm`/`stmg`/`stmy` take an inclusive last register number. Broken by: omitting `- 1` or reading `XVECLEN(operands[0], 0)` after overwriting `operands[0]` with `gen_rtx_REG`. [F4]
- `load_multiple` and `store_multiple` in `s390.md` are enabled only when `reload_completed` is true and must `FAIL` unless `operands[2]` is a `CONST_INT` in `2..16`, the register operand is a GPR (`REGNO < 16`) in `SImode` (or `DImode` when `TARGET_ZARCH`), and (when `!can_create_pseudo_p ()`) the memory address is `REG` or `(plus REG CONST_INT)`. [F28]
- In `s390.md`, when `!TARGET_64BIT && TARGET_ZARCH`, register-pair string instructions (`*cpymem_long_31z`, `*setmem_long_31z`, `*setmem_long_and_31z`, `*cmpmem_long_31z`) and `SImode` branch-on-index (`*brx_64bit`) must reference the `SImode` subregs of a `TImode` register pair at byte offsets 4 and 12 rather than 0 and 8. [F35]
- Memory operands of RSY-b format conditional-mask instructions (`*cmp_and_trap_unsigned_int<mode>` emitting `clt`/`clgt` and `*mov<mode>cc` emitting `loc`/`locg`/`stoc`/`stocg`) must use the indexless `S` constraint (or `loc_operand`) rather than `T` because the RSY-b encoding uses the index-register field for the M3 mask. [F33]
- Single-register FP sign-bit patterns (`*neg<mode>2_nocc`, `*abs<mode>2_nocc`, `*negabs<mode>2_nocc`, and `copysign<mode>3<tf_fpr>`) must constrain operand 1 with `<fT0>` (`"0"` for `TF`/`FPRX2`, `"f"` for `DF`/`SF`) so register-pair `TF`/`FPRX2` values share the destination register. [F32]
- In `s390.md`, `movstrictqi`, `movstricthi`, and `movstrictsi` must use `subreg_register_operand` (not `register_operand`) for operand 0 inside `strict_low_part`, and `movstricthi` must include `(clobber (reg:CC CC_REGNUM))` while `movstrictqi` and `movstrictsi` must not. [F25]
- Expanders and splitters in `s390.md` that implement `HImode` or `QImode` operations using `SImode` instructions (such as `popcounthi2_z196`, `bswaphi2`, and `mov<HQI:mode>cc`) must convert register operands to `SImode` via `subreg`/`simplify_gen_subreg` rather than mixing `HImode`/`QImode` and `SImode` operands in `SImode` RTXs. [F26]
- `popcountsi2` and `popcounthi2` on `TARGET_Z15` must `zero_extend` the `SImode` or `HImode` input operand to `DImode` before emitting `(popcount:DI ...)` and extract the low subreg (offset 4 for `SI`, 6 for `HI`), because the z15 `popcnt` instruction with M3=8 counts bits across all 64 bits of the register. [F34]
- Peepholes in `s390.md` that fold constant-pool memory loads must verify `GET_CODE (operands[1]) == SYMBOL_REF` and `CONSTANT_POOL_ADDRESS_P (operands[1])` before calling `get_pool_mode (operands[1])` or `get_pool_constant (operands[1])`. [F18]
- The `movdi` constant-pool `define_peephole2` in `s390.md` that splits a 64-bit constant pool load into a high-32-bit move and `ior:DI` must emit a single `emit_move_insn` and `DONE` when either 32-bit half (`operands[2]` or `operands[3]`) is `const0_rtx`, because the `ior:DI` instruction predicate rejects zero immediates. [F24]
- Floating-point load-and-test instructions (`lt<xde><bt>r` in `*cmp<mode>_ccz_0` and `*cmp<mode>_ccs_0_fastmath`) must only be used when `!flag_trapping_math && !flag_signaling_nans` or for `CCZmode` equality comparisons against zero where the input FP register is dead afterwards and clobbered. [F21]
- In `s390.h`, `TARGET_NONSIGNALING_VECTOR_COMPARE_OK` must be true when `TARGET_VX && !TARGET_VXE && (flag_finite_math_only || !flag_trapping_math)`, requiring either `-ffinite-math-only` or `-fno-trapping-math` (not both) to allow non-signaling z13 vector FP comparisons. [F36]
- In `s390.md`, `<FPINT:fpint_name><BFP:mode>2<BFP:tf_fpr>` and `<FPINT:fpint_name><DFP:mode>2` (for `floor`, `btrunc`, `round`, `ceil`, `nearbyint`) must pass M4=4 to `fi<xde>bra`/`fi<xde>tr` to suppress IEEE inexact exceptions, whereas `rint<BFP:mode>2<BFP:tf_fpr>` and `rint<DFP:mode>2` must not suppress inexact exceptions. [F40]
- `fixuns_truncdddi2_emu` in `s390.md` must extend its `DDmode` input to `TDmode` via `gen_extendddtd2` before comparing against $2^{63}$ and subtracting $2^{64}$, because $2^{63}$ cannot be represented with full precision in 64-bit `DDmode`. [F38]
- `trunctdsd2` in `s390.md` must truncate `TDmode` to `DDmode` using rounding mode `DFP_RND_PREP_FOR_SHORT_PREC` before truncating `DDmode` to `SDmode` to avoid double-rounding errors when narrowing from 128-bit to 32-bit decimal floating point. Broken by: using `DFP_RND_CURRENT` or calling `gen_trunctddd2`. [F39]
- The `cpu` attribute list in `s390.md` must exactly match the `processor_type` enumeration order, and `s390_tune_attr` in `s390.h` must clamp `s390_tune` to the last processor in that list (`PROCESSOR_9175_Z17`). [F5]
- In `tm_file`, `s390/s390x.h` must precede `s390/s390.h` on 64-bit configurations so `DEFAULT_TARGET_64BIT` is defined before `s390.h` evaluates `#ifdef DEFAULT_TARGET_64BIT` for `TARGET_DEFAULT` and `S390_TARGET_BITS_STRING`; on z/TPF targets, `s390/tpf.h` must follow `s390/s390.h` so it can `#undef` and override `TARGET_TPF`, `STACK_POINTER_OFFSET`, `TARGET_DEFAULT`, and `ASM_PREFERRED_EH_DATA_FORMAT`. [F6, F8]
- In `s390.h`, fallback definitions for subtarget-only option macros such as `TARGET_TPF_PROFILING` must be guarded with `#ifndef` so they do not overwrite the macro generated in `options.h` when `s390/tpf.opt` is active. [F7]
- Host-only data structures in `s390.h` (`struct s390_frame_layout` and `struct machine_function`) must remain inside `#ifndef USED_FOR_TARGET` because they reference compiler-internal types (`HOST_WIDE_INT`, `rtx`, `enum indirect_branch`) unavailable when building target libraries. [F10]
- In `s390.h`, `HAVE_TF(icode)` must expand to `TARGET_HARD_FLOAT` when `GENERATOR_FILE` is defined because `gencondmd.cc` is compiled before `insn-flags.h` generates `HAVE_*_fpr` and `HAVE_*_vr` macros. [F11]
- In `s390.h`, the `"tune"` spec (`%{!mtune=*:%{!march=*:-mtune=%(VALUE)}}`) in `OPTION_DEFAULT_SPECS` must precede the `"arch"` spec (`%{!march=*:-march=%(VALUE)}`) so `--with-arch=` does not inject `-march=` first and suppress `--with-tune=`; in `DRIVER_SELF_SPECS`, `MARCH_MTUNE_NATIVE_SPECS` must precede `"%{!mesa:%{!mzarch:%{m31:-mesa}%{m64:-mzarch}}}"` and `"%{!march=*:-march=z900}"` because it tests `%{mesa|mzarch:mesa_mzarch}` and strips `-march=native` before default mode and arch options are injected. [F42, F43]

## API Contracts

- `EXPAND_TF(icode, nops)` in `s390.h` initializes `ops[0]` as the output operand from `operands[0]` and iterates `for (size_t i = 1; i < __nops; i++)` to populate input operands `ops[i]` from `operands[i]`, so callers must pass the total operand count (output plus inputs) as `nops`. Broken by: passing `1` for a unary or `2` for a binary TFmode operation. [F1]
- In `vecintrin.h`, `vec_step(x)` must pass `* (__typeof__ (x) *) 0` to `__builtin_s390_vec_step` rather than aliasing `__builtin_s390_vec_step` directly so that `vec_step` accepts both vector type names and vector expressions without evaluating `x`. [F15]
- `VECTOR_STORE_FLAG_VALUE(MODE)` in `s390.h` must evaluate to `CONSTM1_RTX (GET_MODE_INNER (MODE))` because S/390 vector comparison instructions always produce `-1` (all bits set) for true vector elements. [F22]
- In `s390.md`, `fixuns_trunc<FP:mode><GPR:mode>2<FP:tf_fpr>` must `FAIL` when `!TARGET_Z196`, `GET_MODE_CLASS (<FP:MODE>mode) == MODE_DECIMAL_FLOAT`, and `<GPR:MODE>mode == SImode` (and `fixuns_trunc<DFP:mode>si2_emu` must unconditionally `FAIL`) so pre-z196 `TDmode`/`DDmode` to unsigned `SImode` conversions fall back to runtime libcalls. [F31]

## Error Handling

- In the `tabort` expander in `s390.md`, `operands[0]` must be checked with `CONST_INT_P` before reading `INTVAL (operands[0])`, and reserved abort codes 0 through 255 must be rejected by calling `error` with a single `%wd` format string literal followed by `FAIL`. Broken by: omitting `CONST_INT_P`, omitting `FAIL` after `error`, or splitting the format string with `HOST_WIDE_INT_PRINT_DEC`. [F14]

## External Contracts

- In `s390.h`, ABI-relevant pointer and slot calculations must use `UNITS_PER_LONG` (`TARGET_64BIT ? 8 : 4`, matching `Pmode`) rather than `UNITS_PER_WORD` (`TARGET_ZARCH ? 8 : 4`), and when `IN_LIBGCC2` is defined `UNITS_PER_WORD` must be defined from `__s390x__` (8 vs 4) so `libgcc` exports match the 31-bit or 64-bit ABI even under `-m31 -mzarch`. [F29]
- In `s390.h`, `DWARF_FRAME_REGISTERS` must remain `34` even when `FIRST_PSEUDO_REGISTER` changes as fake or hardware registers (such as access registers 36–37 or vector registers 38–53) are added or removed. [F30]
- In `vecintrin.h`, type-overloaded vector intrinsics such as `vec_madd` and `vec_msub` must map to overloaded `__builtin_s390_vec_*` built-ins rather than single-mode instruction built-ins like `__builtin_s390_vfmadb` or `__builtin_s390_vfmsdb`, and single-mode vector FP conversion macros `vec_doublee` and `vec_floate` must expand to `__builtin_s390_vflls((X))` and `__builtin_s390_vflrd((X), 0, 0)` rather than non-existent un-suffixed `__builtin_s390_vfll` or `__builtin_s390_vflr` builtins. [F16, F41]

## Known Pitfalls

- Statement-expression macros in `vecintrin.h` that declare an internal condition-code local (such as `int __cc;` in `vec_all_nan` and `vec_all_numeric`) must use that exact identifier (`__cc`) in both the `&__cc` out-parameter to `__builtin_s390_vec_fp_test_data_class` and the trailing comparison. Broken by: referencing unprefixed `&cc` or `cc`. [F2]
- D front-end target hook macros (`TARGET_D_CPU_VERSIONS` and `TARGET_D_REGISTER_CPU_TARGET_INFO`) must be defined in `gcc/config/s390/s390-d.h` (included via `tm_d.h`) rather than `gcc/config/s390/s390.h` so D target files do not need to include `tm.h`. [F9]
