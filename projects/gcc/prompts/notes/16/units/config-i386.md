# config-i386

Implements RTL instruction expansion and operand preparation routines for the x86/x86_64 backend. It lowers scalar, vector, string/memory, atomic, conditional, and target built-in operations into x86-specific RTL sequences, and synthesizes constant vector permutations and broadcasts.
Provides x86 target-specific RTL optimization passes, option and attribute handling, function multiversioning dispatchers, ISA/mode/pass definitions, and shared backend header declarations. It includes the Scalar-To-Vector (STV) pass, vzeroupper insertion, CET endbr insertion, partial AVX dependency removal, APX NF conversion, and target pragma/attribute validation.
Core implementation of the x86/x86_64 backend target hooks (targetm). It handles SysV and MS calling convention ABI classification, stack frame layout and prologue/epilogue generation, address decomposition and legitimization, instruction scheduling and vectorization cost models, and assembly operand formatting.
Machine description file defining RTL instruction patterns, expanders, splitters, peepholes, and mode/int iterators for x86 SIMD instruction sets. It covers SSE, SSE2, SSE3, SSSE3, SSE4.1, SSE4.2, SSE4A, AVX, AVX2, FMA, FMA4, XOP, AVX-512, VNNI, BF16, FP16, and AVX10.1/AVX10.2 vector operations.

## Architecture & Data Flow

- In ix86_expand_special_args_builtin, when klass == store, CALL_EXPR_ARG (exp, 0) is consumed as target and arg_adjust is set to 1 so the loop over i < nargs reads CALL_EXPR_ARG (exp, i + arg_adjust) while storing into xops[i] and reading insn_p->operand[i + 1]. [F1]
- In ix86_expand_multi_arg_builtin, when comparison_p is true, operand[1] of insn_data[icode] is reserved for the synthesized comparison RTX cmp_op, so the argument loop must offset insn_data[icode].operand lookups by adjust = 1 while indexing CALL_EXPR_ARG and xops by i. [F2]
- In expand_vec_perm_shufps_shufps (count == 2) and expand_vec_perm_vpermq_perm_1, filtered elements from source lanes are packed intoperm1 and dremap.perm using separate destination counters (j/k and cnt) rather than the loop induction variable. [F3]
- In `ix86_expand_call`, `SYMBOL_REF_DECL (XEXP (fnaddr, 0))` on a direct `SYMBOL_REF` call and `MEM_EXPR (fnaddr)` on an indirect `MEM` call can be null (and `MEM_EXPR` may not be a `MEM_REF`), so non-null and `TREE_CODE (mem_expr) == MEM_REF` checks must guard `TYPE_ATTRIBUTES (TREE_TYPE (...))` lookups. [F15]
- In `ix86_expand_builtin` (`gather_gen`), inspecting the `SSA_NAME` definition of mask argument `arg3` to replace an all-ones mask with `pc_rtx` requires verifying `is_gimple_call (def_stmt)`, `fndecl != NULL_TREE`, and `fndecl_built_in_p (fndecl, BUILT_IN_MD)` before reading `DECL_MD_FUNCTION_CODE (fndecl)`. [F16]
- In ix86_expand_int_movcc, when reversing a scalar floating-point comparison (diff < 0 or cf == 0) with HONOR_NANS (cmp_mode) && flag_trapping_math, comparison reversal must be rejected unless code is EQ, NE, ORDERED, or UNORDERED. [F17]
- When ix86_expand_special_args_builtin constructs a fresh MEM rtx from a pointer argument via gen_rtx_MEM, it must update MEM_ALIGN from get_pointer_alignment (arg) (and at least GET_MODE_ALIGNMENT when aligned_mem is true). [F20]
- In expand_set_or_cpymem_constant_prologue, after advancing dst and src by align_bytes, MEM_SIZE must be reduced by align_bytes on dst and src whenever MEM_SIZE_KNOWN_P holds on the original MEM. [F21]
- When ix86_vectorize_vec_perm_const is called with target == NULL_RTX (d.testing_p) and cannot return early from ISA mode checks, it must synthesize dummy raw registers past LAST_VIRTUAL_REGISTER and run ix86_expand_vec_perm_const_1 inside a discarded start_sequence () / end_sequence () block. [F24]
- In ix86_expand_builtin, replacing a gather built-in's destination merge operand op0 with pc_rtx when arg3 is a VECTOR_CST requires checking that every lane has its sign bit set (negative == TYPE_VECTOR_SUBPARTS (TREE_TYPE (arg3))). [F25]
- In ix86_expand_clear, replacing a destination register smaller than 4 bytes with gen_rtx_REG (SImode, REGNO (dest)) is only valid after reload (asserted via reload_completed) because raw register-width reinterpretation on pseudos before reload is invalid. [F26]
- When ix86_broadcast_from_constant or ix86_extract_perm_from_pool_constant inspects a constant-pool MEM whose pool constant has a different mode than the MEM, it must reinterpret the constant via simplify_subreg to the MEM's mode and verify the result is still a CONST_VECTOR before reading XVECEXP lanes. [F27]
- In ix86_prepare_fp_compare_args, BFmode comparisons must be zero-extended and shifted by 16 bits into SFmode whenever !TARGET_AVX10_2 or flag_trapping_math is enabled, and in ix86_expand_fp_compare, BFmode under IX86_FPCMP_COMI must never wrap the COMPARE in UNSPEC_OPTCOMX or UNSPEC_NOTRAP because only vcomisbf16 exists. [F30]
- When ix86_expand_int_compare optimizes a TImode comparison of a 16-byte vector SUBREG against const0_rtx into UNSPEC_PTEST, it must convert V8HFmode or V8BFmode inner registers to V8HImode via gen_lowpart because no ptest pattern exists for 16-bit float vector modes. [F31]
- In ix86_split_to_parts and ix86_split_long_move, non-offsettable MEM operands are forbidden except for stack pushes (push_operand), and splitting a multi-word REG into hard-register parts (REGNO (operand) + i) requires reload_completed. [F34]
- In ix86_split_long_move, pushing a multi-part value in 64-bit mode when the upper part has SImode (such as 12-byte XFmode or a retyped TFmode half) must widen a MEM or REG upper part to DImode before emitting the push, because 64-bit mode has no 32-bit push instruction. [F35]
- In expand_set_or_cpymem_prologue_epilogue_by_misaligned_moves, skipping the runtime small-block branch (when CONST_INT_P (*count) || *min_size >= size) requires that *min_size >= size or UINTVAL (*count) >= size so that the unconditional prologue and tail moves of size bytes do not access past the bounds of the block. [F36]
- In ix86_expand_set_or_cpymem, when a small-block jump to label is used and size_needed < epilogue_size_needed, count_exp must be masked with GEN_INT (size_needed - 1) before emitting label so the epilogue copies only the post-loop remainder. [F37]
- In ix86_expand_builtin for IX86_BUILTIN_PREFETCH with data prefetch (INTVAL (op3) != 1), gen_prefetch must be emitted whenever TARGET_3DNOW, TARGET_PREFETCH_SSE, TARGET_PRFCHW, or TARGET_MOVRS is enabled, and when none are enabled a side-effecting op0 must only be emitted if !MEM_P (op0) so volatile memory is not dereferenced. [F42]
- In ix86_vector_duplicate_value, recog_data must be saved before emitting and recognizing the vec_duplicate insn and restored before returning, because ix86_vector_duplicate_value can be invoked from insn splitters where force_reg would otherwise clobber the active recog_data. [F43]
- In ix86_expand_vector_set, before constructing a VEC_DUPLICATE inside a VEC_MERGE RTX on the do_vec_merge path, the scalar element val must be checked with nonimmediate_operand (val, inner_mode) and forced into a register via force_reg if it is an immediate such as a SYMBOL_REF. [F44]
- In ix86_expand_vector_set_var, 512-bit byte and word vector modes (V32HImode, V32HFmode, V32BFmode, V64QImode) must be split into two 256-bit halves via gen_vec_extract_lo_* and gen_vec_extract_hi_* whenever !TARGET_AVX512BW, because 512-bit byte/word broadcast and comparison require AVX512BW. [F45]
- In expand_vec_perm_pshufb, when emulating a 4-byte or 8-byte vector permutation (nelt < 16) with 16-byte V16QImode instructions in the two-operand case (!d->one_operand_p), byte indices selecting from the second operand (ival >= nelt) must be offset by 16 - nelt to skip the inactive upper bytes of the first 128-bit register. [F46]
- In `ix86_expand_call`, the `TARGET_X32` GOT-slot check and the fallback `call_insn_operand`/`sibcall_insn_operand` register-forcing branch must remain chained with `else if` after the `CM_LARGE_PIC` `construct_plt_address` branch so that a newly constructed PLT address is not re-evaluated by the fallback indirect-call logic. [F47]
- In xlogue_layout::xlogue_layout, when iterating REG_ORDER[0..MAX_REGS-1] with i and skipping BP_REG when hfp is true, destination entries in m_regs must be indexed by a separate counter j that is only incremented for non-skipped registers so that j == m_nregs (17 when hfp, 18 otherwise) upon loop completion. [F48]
- In xlogue_layout::is_stub_managed_reg, because count from count_stub_managed_regs excludes BP_REG when frame_pointer_needed or stack_realign_fp (hfp) is true, the loop over REG_ORDER[i] for i < count must increment count when encountering BP_REG under hfp so all count stub-managed registers in REG_ORDER are inspected. [F49]
- In dispatch_function_versions, fndecls iteration starts at ix = 1 (skipping (*fndecls)[0], which is default_decl) and skips versions with predicate_chain == NULL_TREE, so function_version_info must be populated and subsequently sorted and iterated using the separate actual_versions counter rather than ix or num_versions - 1. [F50]
- In ix86_apx_nf_convert, when filtering FLAGS_REG CLOBBERs out of a PARALLEL pattern pat of length len, retained elements must be written to new_elems[n++] using a separate counter n and wrapped via new_elems[0] when n == 1 or gen_rtvec_v (n, new_elems) otherwise. [F51]
- The entries of processor_cost_table in gcc/config/i386/i386-options.cc must be ordered identically to enum processor_type in i386.h, and the last entry of processor_alias_table (at pta_size - 1) must be "generic". [F55]
- In ix86_handle_interrupt_attribute, parameter and return types must be validated via TYPE_ARG_TYPES (*node) and TREE_TYPE (*node) on the function type rather than DECL_ARGUMENTS or DECL_RESULT, which do not exist yet when type attributes are processed. [F72]
- In `scalar_chain::analyze_register_chain` and `scalar_chain::build`, if `--max_visits` reaches zero or a non-memory DF reference hits an instruction in `disallowed`, chain discovery must abort and union the partially collected `insns` bitmap into `disallowed` so later searches reaching that component also abort. [F76]
- `timode_scalar_chain::compute_convert_gain` must return a negative gain (`-1`) whenever `n_sse_to_integer` or `n_integer_to_sse` is non-zero, and `timode_remove_non_convertible_regs` must iteratively prune any candidate instruction referencing a `TImode` pseudo register that has a non-convertible def or non-debug use. [F77]
- In `dispatch_function_versions` and `ix86_generate_version_dispatcher_body`, the multiversion IFUNC resolver body must emit a call to `IX86_BUILTIN_CPU_INIT` (`__builtin_cpu_init`) before any version predicate checks and call `cgraph_edge::rebuild_edges ()` while `DECL_STRUCT_FUNCTION (resolver_decl)` is the active `cfun`. [F83]
- In `rest_of_handle_insert_vzeroupper`, after running `execute_pass_mode_switching ()`, all `REG_DEAD` and `REG_UNUSED` notes must be stripped from every non-debug instruction and `df_remove_problem (df_note)` followed by `df_analyze ()` must be executed. [F84]
- When `general_scalar_chain::convert_insn` rewrites `SET_DEST` of `insn` from a scalar `REG` into a `vmode` `SUBREG` (or `timode_scalar_chain::convert_insn` rewrites `SET_DEST` to `V1TImode`), any `REG_EQUAL` or `REG_EQUIV` note on `insn` must be removed via `remove_note`. [F86]
- In `ix86_set_current_function`, after restoring target globals for `fndecl`, `reinit_regs ()` must be called if in 64-bit mode `call_used_or_fixed_reg_p (SI_REG)` equals `(cfun->machine->call_abi == MS_ABI)` or if `cfun->machine->call_saved_registers` differs from `prev_call_saved_registers`. [F88]
- In xlogue_layout::xlogue_layout, every SSE register entry in REG_ORDER must be placed at a 16-byte-aligned stack offset ((stack_align_off_in + offset) & 15 == 0), and BP_REG must be skipped when hfp is true. [F90]
- Because timode_scalar_chain::convert_insn mutates REG modes in-place from TImode to V1TImode via PUT_MODE, timode_scalar_chain::fix_debug_reg_uses and convert_scalars_to_vector must wrap any mutated V1TImode REG in DEBUG_INSNs, DECL_RTL, and DECL_INCOMING_RTL of TImode parameters back in a TImode SUBREG. [F96]
- In general_scalar_chain::convert_insn and timode_scalar_chain::convert_insn, non-move vector operations (and immediate stores in V1TImode) cannot write directly to a MEM_P destination and must instead write to a temporary vector register followed by a move. [F97]
- pseudo_reg_set must reject any instruction that defines or uses a hard register—except for a push_operand destination of a pseudo-register source, hard registers inside memory addresses (DF_REF_REG_MEM_P), DF_REF_MUST_CLOBBER defs, and FLAGS_REG defs. [F98]
- In general_scalar_to_vector_candidate_p, a VEC_SELECT source is only a valid STV candidate when SET_DEST is a REG_P (excluding MEM_P destinations so STV does not interfere with vpextr[dq] stores), and scalar_chain::add_insn must not add VEC_SELECT source operands to the chain. [F99]

[F101]
- In ix86_apx_nf_convert, if an instruction between a cstore flag consumer and the next explicit flag setter clobbers FLAGS_REG but lacks get_attr_has_nf (insn), all candidate instructions recorded in current_convert_list for that sequence must be removed from converting_map. [F104]
- In i386-modes.def, vector modes must be defined up to twice the maximum hardware vector byte size (128-byte INT and 256-byte FLOAT vectors), and consecutive register-pair modes P2QI and P2HI must be defined with PARTIAL_INT_MODE rather than INT_MODE. [F106]
- When AVX10.1-256 is enabled without explicit EVEX512, explicitly enabling an AVX512 feature in a target attribute (ix86_valid_target_attribute_tree) must set OPTION_MASK_ISA2_EVEX512, whereas enabling -mevex512 without any explicit AVX512 feature under AVX10.1-256 (ix86_option_override_internal) must clear OPTION_MASK_ISA2_EVEX512. [F107]
- In ix86_parse_stringop_strategy_string, the comma-separated size ranges must have strictly increasing max bounds with the final range having max == -1, must not exceed MAX_STRINGOP_ALGS entries, and must reject rep_prefix_8_byte when !TARGET_64BIT. [F108]
- In ix86_set_current_function, if flag_unsafe_math_optimizations or flag_excess_precision differs from the function's TREE_TARGET_OPTION (x_ix86_unsafe_math_optimizations or x_ix86_excess_precision), the target options must be restored, rebuilt with the current FP flags, and target globals restored or saved.
