# c-family

This unit implements the C front end (`gcc/c/`) and shared C-family infrastructure (`gcc/c-family/`), including declaration and type checking, `C_MAYBE_CONST_EXPR` constant-expression tracking, attribute handlers, built-in and atomic overload resolution, `#pragma` and option processing, UBSan instrumentation, the `-fdump-ada-spec` generator, and the `__GIMPLE` parser.

## Architecture & Data Flow

- In `build_attr_access_from_parms`, `arg2pos` must be populated with the 0-based `argpos` of all named integral parameters in a full first pass over `parms` before resetting `argpos = 0` and inspecting `"arg spec"` VLA bounds in a second pass, so forward-declared size parameters are resolved. In `append_access_attr`, merging and serializing access specs must iterate over `TYPE_ARG_TYPES (node[0])` in ascending `argpos` order (not over `rdwr_map`) and skip entries where `(unsigned)argpos != newa->ptrarg`. [F1, F2]
- Two-pass count/store collectors in `c-ada-spec.cc` must keep identical filter predicates across both passes: `collect_ada_nodes` must initialize destination index `i` to the prior `to_dump_count` before resizing `to_dump`, and `dump_ada_macros` must reset `max_ada_macros` and `store_ada_macro_index` to 0 before `count_ada_macro` and `store_ada_macro` run so the `alloca`-allocated `macros` array is not overflowed. [F3, F4]
- In `c-ada-spec.cc`, `dump_ada_array_type`, `dump_nested_type`, and `handle_nonstring_attribute` (`c-attribs.cc`), plus `finish_struct` and `diagnose_uninitialized_cst_member` (`c-decl.cc`), must strip all array dimensions with `strip_array_types` rather than a single `TREE_TYPE` dereference when inspecting element types or qualifiers. [F22, F36, F86]
- When `handle_hardbool_attribute` turns `*node` into an `ENUMERAL_TYPE` with `ENUM_UNDERLYING_TYPE (*node) = orig`, it must set `TYPE_CANONICAL (*node) = TYPE_CANONICAL (orig)` and leave `TYPE_MIN_VALUE`, `TYPE_MAX_VALUE`, and `TYPE_PRECISION` as copied from `orig`. `c_hardbool_type_attr` must check `TREE_CODE (type) == ENUMERAL_TYPE && !TYPE_LANG_SPECIFIC (type)` before calling `c_hardbool_type_attr_1`, and `c_convert` must check `c_hardbool_type_attr` before switching on `TREE_CODE (type)`. [F25, F26, F115, F251]
- When modifying a type without `ATTR_FLAG_TYPE_IN_PLACE`, `handle_scalar_storage_order_attribute` (with `reverse` true) and `handle_transparent_union_attribute` must call `build_duplicate_type (type)` (not `build_variant_type_copy`); `common_handle_aligned_attribute` on a `TYPE_DECL` with null `DECL_ORIGINAL_TYPE` must copy `*type` via `build_variant_type_copy`, save the old type in `DECL_ORIGINAL_TYPE`, and rebind `TREE_TYPE`; `handle_mode_attribute` on an `ENUMERAL_TYPE` must build a subrange type via `make_unsigned_type`/`make_signed_type` so `TYPE_MAIN_VARIANT` keeps the same mode. [F27, F29, F63]
- In `c_parser_gimple_statement` and `c_parser_parse_gimple_body`, `__PHI` statements are parsed as `IFN_PHI` calls whose arguments alternate basic-block index (`i`) and incoming value (`i + 1`, stride `i += 2`), and in `cdil_gimple_ssa` mode they must be converted to `gphi` nodes via `create_phi_node`/`add_phi_arg` only after all CFG and `gswitch` edges are created, followed by `calculate_dominance_info (CDI_DOMINATORS)` before `fix_loop_structure (NULL)`. [F6, F51, F53]
- In `c_parser_parse_gimple_body`, local non-external, non-`TREE_STATIC` `VAR_P` decls lowered in `cdil_gimple_cfg`/`cdil_gimple_ssa` mode must have `DECL_SEEN_IN_BIND_EXPR_P (var) = 1` set; in `cdil_gimple_ssa` mode, unused SSA version indices below `num_ssa_names` must be allocated with `make_ssa_name_fn` and freed with `release_ssa_name_fn` before `update_ssa (TODO_update_ssa_only_virtuals)`, and `flush_ssaname_freelist` called afterward. [F50, F52]
- In `finish_struct`, `TYPE_LANG_SPECIFIC (t)` and its sorted `field_array` must only be attached when no field in `fieldlist` has `DECL_NAME (x) == NULL`. `field_decl_cmp` and `resort_field_decl_cmp` (used during PCH relocation) must order `FIELD_DECL` entries identically by `DECL_NAME` pointer address and `TYPE_DECL` tie-breaker. In `detect_field_duplicates`, any unnamed `RECORD_OR_UNION_TYPE_P` field must force `timeout = 0` so `detect_field_duplicates_hash` recursively traverses anonymous members using the same `htab`. [F70, F73, F74, F87]
- In `finish_struct`, a bit-field's declared `TREE_TYPE` must be kept until `layout_type (t)` finishes, then narrowed to the width in `DECL_INITIAL (field)` (using `build_bitint_type` for `BITINT_TYPE` only when `width >= (TYPE_UNSIGNED (type) ? 1 : 2)`, else `c_build_bitfield_integer_type`), copying any `c_hardbool_type_attr`, updating `DECL_MODE (field)`, and clearing `DECL_INITIAL (field) = NULL_TREE`. Completed struct/union/enum fields and flags must be propagated across all variants from `TYPE_MAIN_VARIANT (t)` via `TYPE_NEXT_VARIANT`. [F96, F111, F116, F124]
- When `merge_decls` copies `tree_decl_common` and node-specific fields from `newdecl` into `olddecl` via `memcpy`, it must save and restore `DECL_UID (olddecl)`, `DECL_CONTEXT (olddecl)`, `DECL_ARGUMENTS (olddecl)` (for `FUNCTION_DECL`), and `olddecl->decl_with_vis.symtab_node` (for `VAR_DECL` and `FUNCTION_DECL`). [F104]
- In `gcc/c/c-tree.h`, `C_DECL_VARIABLE_SIZE` and `C_ARRAY_PARAMETER` share `DECL_LANG_FLAG_0`, and `C_TYPEDEF_EXPLICITLY_SIGNED` and `C_FUNCTION_IMPLICIT_INT` share `DECL_LANG_FLAG_1` without `TREE_CHECK` guards, so callers must check `TREE_CODE` first. To test variably modified or `[*]` types when `t` might be `error_mark_node`, callers must use `c_type_variably_modified_p` or `c_type_unspecified_p` rather than `C_TYPE_VARIABLY_MODIFIED` or `C_TYPE_VARIABLE_SIZE`. [F142, F143]
- In `c-typeck.cc` initializer handling, `start_init` and `finish_init` must save and restore `require_constant_value`, `require_constant_elements`, and `require_constexpr_value` on `initializer_stack`. Whenever `constructor_fields` or `constructor_unfilled_fields` is initialized or advanced along `DECL_CHAIN` for a `RECORD_TYPE`, `DECL_UNNAMED_BIT_FIELD` nodes must be skipped; for zero-length arrays (`TYPE_MAX_VALUE == NULL_TREE` with non-null `TYPE_SIZE`) or VLAs, `constructor_max_index` must be set to `integer_minus_one_node`. [F151, F153, F173]
- When `convert_for_assignment` or `c_finish_return` calls `convert` or `convert_and_check` for boolean, complex, or `SANITIZE_FLOAT_CAST` float-to-int conversions, it must temporarily set `in_late_binary_op = true` so `build_binary_op` and `note_integer_operands` do not emit `C_MAYBE_CONST_EXPR`. When `build_unary_op` (for increment, decrement, or `ADDR_EXPR`) or `build_modify_expr` receives a `C_MAYBE_CONST_EXPR` lvalue, it must recurse on `C_MAYBE_CONST_EXPR_EXPR` and rebuild the outer `C_MAYBE_CONST_EXPR` preserving `C_MAYBE_CONST_EXPR_PRE` and setting `C_MAYBE_CONST_EXPR_NON_CONST` (and for `ADDR_EXPR`, unwrap `is_access_with_size_p` to the inner `COMPONENT_REF` first). [F176, F177, F187]
- `c_inhibit_evaluation_warnings` is a nesting counter that must be incremented and decremented, never assigned `1`/`0`. In `build_conditional_expr` and `build_binary_op`, operand folding via `c_fully_fold` for `-Wsign-compare` must run whenever `c_inhibit_evaluation_warnings == 0` even if `warn_sign_compare` is off, re-wrapping non-`INTEGER_CST` results with `c_wrap_maybe_const`. In `check_function_arguments`, `check_function_restrict` must run even when `warn_restrict` is off because it sets `DECL_READ_P`. [F183, F240, F241]

## Object Lifetimes

- Default-obstack bitmaps in `dump_ada_specs`, `c_parser_parse_gimple_body`, and `c_finish_omp_clauses` must be bracketed by `bitmap_obstack_initialize (NULL)` and `bitmap_obstack_release (NULL)` on all return paths. Likewise, `verify_sequence_points` must reset `warned_ids` and `save_expr_cache` to `nullptr` before walking `expr` and call `obstack_free (&tlist_obstack, tlist_firstobj)` before returning. [F15, F161, F229]
- Local heap-backed vectors in `gimple-parser.cc`, `c-decl.cc` (`c_struct_parse_info`), `c-typeck.cc`, `c-pragma.cc`, `c-pretty-print.cc`, and `c-warn.cc` must be declared as `auto_vec<T>` rather than raw `vec<T>`. Conversely, structures allocated on `parser_obstack` (`c_declspecs`, `c_declarator`, `c_arg_info`, `c_type_name`, `c_parm`) are bulk-freed via `obstack_free` after each external declaration and must never contain `auto_vec` or other members with non-trivial destructors. [F14, F80, F130, F163, F294]
- In `c_pop_function_context`, the inner function's `loop_names.release ()` and `delete loop_names_hash` must be called before restoring `p->loop_names` and `p->loop_names_hash` from `cfun->language`. In `duplicate_decls`, before calling `ggc_free (newdecl)` after `merge_decls`, `DECL_STRUCT_FUNCTION (newdecl)` must be cleared to `NULL` if `newdecl` is a `FUNCTION_DECL` and any `symtab_node` for `newdecl` must be removed via `snode->remove ()`. [F78, F83]
- `finish_init` must drain and `XDELETE` every remaining `constructor_stack` node of the current initializer, `XDELETE (spelling_base)`, and `XDELETE` the popped `initializer_stack` node before restoring outer initializer state. When `PUSH_SPELLING` resizes `spelling_base` via `XRESIZEVEC`, it must save `SPELLING_DEPTH ()` beforehand and call `RESTORE_SPELLING_DEPTH (depth)` afterward because `spelling` is a raw pointer into `spelling_base`. [F162, F164]
- `tagged_types_tu_compatible_p` links stack-allocated `tagged_tu_seen_cache` entries into `data->cache` before recursing into `comptypes_internal` and must restore `data->cache` to the saved pointer before returning or continuing the field loop. [F166]

## API Contracts

- `c_release_loop_names (num_names)` must only be called when `num_names > 0`, because calling it with `num_names == 0` when `loop_names_hash` is non-NULL (`len > 16`) causes `FOR_EACH_VEC_ELT_REVERSE` to never match `i == len` and erases every entry in `loop_names_hash`. [F68, F84]
- In `verify_counted_by_attribute`, the `TREE_LIST` returned by `lookup_field (struct_type, fieldname)` must be walked via `TREE_CHAIN` to its last node before reading `TREE_VALUE` for the `INTEGRAL_TYPE_P` check; if lookup or type validation fails, `remove_attribute ("counted_by", DECL_ATTRIBUTES (field_decl))` must strip the invalid attribute. [F85, F121]
- `c_convert` must invoke `targetm.invalid_conversion` and `targetm.convert_to_type` on the original `expr` before `STRIP_TYPE_NOPS` or type-code dispatch, and at `maybe_fold` must use `fold_init (ret)` when `init_const` is true (`convert_init` / `convert_and_check` with `init_const`), `fold (ret)` when `init_const` is false, and skip folding altogether when `TREE_CODE (ret) == C_MAYBE_CONST_EXPR`. [F90, F126, F267]
- `c_update_type_canonical` requires `TYPE_MAIN_VARIANT (t) == t && !TYPE_QUALS (t)`. `initialize_elementwise_p` requires `TYPE_MAIN_VARIANT (type) == type`. `user_facing_original_type_p` requires `typedef_variant_p (type)`. `composite_type_internal` requires `t1` and `t2` to already satisfy `comptypes` with matching qualifiers (and `COMPLETE_TYPE_P` on non-identical C23 structs/unions). [F95, F171, F172, F239]
- When leaving a `sizeof` or `typeof` operand, `in_sizeof` or `in_typeof` must be decremented before calling `pop_maybe_used`, because `pop_maybe_used` only processes `maybe_used_decls` entries whose `level > in_sizeof + in_typeof` (queued by `build_external_ref` for undefined static functions and committed only if the operand is `C_TYPE_VARIABLE_SIZE`). [F139, F181]
- `c_wrap_maybe_const` must never be called when `c_dialect_cxx ()` is true (it hits `gcc_unreachable ()`), and must call `STRIP_TYPE_NOPS (expr)` before building `C_MAYBE_CONST_EXPR`. Before passing operands to `make_range` in `warn_logical_operator`, they must be unshared via `unshare_expr` and stripped of `C_MAYBE_CONST_EXPR` via `walk_tree_without_duplicates` with `unwrap_c_maybe_const`. [F231, F302]
- For an `ENUMERAL_TYPE` that is neither `ENUM_IS_SCOPED` nor `ENUM_FIXED_UNDERLYING_TYPE_P`, `ENUM_UNDERLYING_TYPE` is null until `finish_enum` completes the type; `C_BOOLEAN_TYPE_P(TYPE)` must check `ENUM_UNDERLYING_TYPE (TYPE) != NULL_TREE` before testing `TREE_CODE (ENUM_UNDERLYING_TYPE (TYPE)) == BOOLEAN_TYPE`. [F149, F235]

## Error Handling

- At the end of `c_parser_parse_gimple_body`, if `verify_gimple_in_cfg` or `verify_gimple_in_seq` returns non-zero, the body must be cleared via `init_empty_tree_cfg ()` or `gimple_set_body (current_function_decl, NULL)` so middle-end passes do not run on invalid GIMPLE. In `c_parser_gimple_compound_statement`, stray `CPP_CLOSE_PAREN` and `CPP_CLOSE_SQUARE` tokens must be explicitly diagnosed and consumed because `c_parser_skip_until_found` stops at closing delimiters without consuming them. [F44, F54]
- In `start_decl`, `finish_decl`, and `decl_constant_value_1`, `DECL_INITIAL` must never be read or written on a `PARM_DECL` because `DECL_INITIAL` on a `PARM_DECL` aliases `DECL_ARG_TYPE`. In `duplicate_decls`, `TREE_TYPE` must not be poisoned with `error_mark_node` when `TREE_CODE` of the decl is `FUNCTION_DECL`. [F103, F106, F184]
- Callers of `push_init_level` that initialize a local `braced_init_obstack` must call both `pop_init_level` and `obstack_free (&braced_init_obstack, NULL)` on every return path, including parse-error recovery. [F133]

## Known Pitfalls

- In `handle_malloc_attribute`, `DECL_IS_MALLOC (*node) = 1` must only be set for the zero-argument `malloc` attribute; the `malloc (dealloc, ...)` form must attach `*dealloc` and `noinline` without setting `DECL_IS_MALLOC`. In `handle_copy_attribute`, `*no_add_attrs = true` must be set, linkage/inlining/visibility/leaf attributes filtered from `DECL_ATTRIBUTES`, and `ATTR_FLAG_INTERNAL` passed when copying `TYPE_ATTRIBUTES`. [F40, F60]
- `c_declarator::id_loc` is only initialized for `cdk_id` and `cdk_array` declarators. `c_expr::set_error` does not initialize `original_code` or `original_type`, and `c_typespec::expr_const_operands` must be explicitly initialized whenever `spec.expr` is non-null before calling `declspecs_add_type`. [F136, F140, F141]
- When inspecting `FIELD_DECL` nodes in `tagged_types_tu_compatible_p` or `composite_type_internal`, `DECL_BIT_FIELD_TYPE (field)` must be used instead of `TREE_TYPE (field)` whenever `DECL_C_BIT_FIELD (field)` is set. Because `TYPE_MAIN_VARIANT` on an `ARRAY_TYPE` drops element-type qualifiers, callers stripping top-level qualifiers (`common_pointer_type`, `comp_target_types`, `type_lists_compatible_p`, `grokdeclarator`, `fix_string_type`) must guard against `ARRAY_TYPE` or build the unqualified array type before applying `c_build_qualified_type`. [F97, F168, F169, F238]
- In `speculation_safe_value_resolve_call`, `sync_resolve_size`, and `get_atomic_generic_size`, `ARRAY_TYPE` arguments in `params` must undergo `default_conversion` when `c_dialect_cxx ()` is true before checking `POINTER_TYPE_P`. In `sizeof_pointer_memaccess_warning` and `warn_for_sign_compare`, `error_operand_p` must be checked rather than `== error_mark_node`, and `warn_for_omitted_condop` must check `TREE_TYPE (cond) != NULL_TREE` for C++ dependent expressions. [F246, F315, F316]
- In `ubsan_instrument_bounds`, `bound` has `1 + ignore_off_by_one` added to convert an inclusive max index to an exclusive bound, so element-count sources like `get_bound_from_access_with_size` (which requires `class_of_size == 1` and clamps negative signed sizes to 0) must subtract 1 first. In `ubsan_instrument_division` and `ubsan_instrument_shift`, `op0` and `op1` must be unshared with `unshare_expr` at each reuse and evaluated via leading `COMPOUND_EXPR`s before the `COND_EXPR` condition (clamping `BITINT_TYPE` shift counts wider than `MAX_FIXED_MODE_SIZE` before `ubsan_type_descriptor`/`ubsan_encode_value`, and skipping `SANITIZE_SHIFT_BASE` when `GET_MODE_BITSIZE (TYPE_MODE (type0)) != TYPE_PRECISION (type0)`). [F279, F308, F326, F328, F336]
- In `warn_for_restrict`, `arg_positions` stores 1-based indices (`i + 1`), so `argarray` must be indexed with `pos - 1`. In `c-warn.cc`, `warn_parm_ptrarray_mismatch` tracks `parmpos` as 1-based, whereas `warn_parm_array_mismatch` tracks `parmpos` as 0-based for `rdwr_map` lookup and must pass `parmpos + 1` to diagnostics. [F280, F281]
