# match-fold

This unit defines GCC's declarative pattern-matching and expression-simplification framework (`gcc/match.pd`) along with the runtime headers, preambles, and exported helper functions for GENERIC (`generic-match*`) and GIMPLE (`gimple-match*`) folding, tree constant folding declarations (`fold-const.h`), and polynomial integer size helpers (`poly-int-types.h`).

## Architecture & Data Flow

- In `gimple_resimplify1`..`gimple_resimplify4`, recursive calls to `gimple_simplify` must be guarded by checking that `static unsigned depth` is at most 10, incrementing `depth` before the call and decrementing it on both return paths so cyclic valueized expressions do not recurse unboundedly. Broken by: calling `gimple_simplify` without the `depth > 10` return or adding an early return between `++depth` and `--depth`. [F6]
- In `convert_conditional_op` and `try_conditional_simplification` (`gcc/gimple-match-exports.cc`), `IFN_COND_*` calls store `cond` at `ops[0]`, shift the `num_ops` unconditional operands by `+ 1` into `ops[1 .. num_ops]`, and place `else_value` (plus `len` and `bias` when `cond.len` is set) at `ops[num_ops + 1 .. num_ops + 3]`. [F2]
- In `maybe_resimplify_conditional_op`, when `res_op->cond.else_value` is non-null and `res_op` simplifies to a gimple value (`gimple_simplified_result_is_gimple_val`), rebuild `res_op` as `VEC_COND_EXPR`/`IFN_VCOND_MASK_LEN` for vectors or `COND_EXPR` for scalars before `gimple_resimplify3`; when `else_value` is null, `res_op->cond.cond` may be dropped only if `gimple_simplified_result_is_gimple_val (res_op)` is true or the op cannot trap per `generic_expr_could_trap_p` (for `COND_EXPR`) or `operation_could_trap_p`. [F30, F43]
- In `gimple_extract` (`gcc/gimple-match-exports.cc`), extracting a `GIMPLE_SINGLE_RHS` with `REALPART_EXPR`, `IMAGPART_EXPR`, `VIEW_CONVERT_EXPR`, or `BIT_FIELD_REF` requires `TREE_CODE (op0) == SSA_NAME || is_gimple_min_invariant (op0)`, and extracting a non-internal `GIMPLE_CALL` requires its valueized callee to be an `ADDR_EXPR` of a `FUNCTION_DECL` with `DECL_BUILT_IN_CLASS (decl) == BUILT_IN_NORMAL` and `gimple_builtin_call_types_compatible_p (stmt, decl)`. [F24, F25]
- In `maybe_push_res_to_seq` (`gcc/gimple-match-exports.cc`), before emitting a statement to `seq`, every operand in `res_op->ops[0 .. num_ops - 1]` must be checked not to be an `SSA_NAME` with `SSA_NAME_OCCURS_IN_ABNORMAL_PHI` (returning `NULL_TREE` otherwise), and if `res_op->code` is a function (`combined_fn`), `ECF_CONST` must be set in `internal_fn_flags (ifn)` or `flags_from_decl_or_type (decl)` of `builtin_decl_implicit`. [F26, F27]
- In `build_call_internal`, a `direct_internal_fn_p` call failing `direct_internal_fn_supported_p` is only permitted for `IFN_CLZ`, `IFN_CTZ`, `IFN_CLRSB`, `IFN_FFS`, `IFN_POPCOUNT`, and `IFN_PARITY` when `ops[0]` is a `BITINT_TYPE` with precision `> MAX_FIXED_MODE_SIZE` and `(cfun->curr_properties & PROP_gimple_lbitint) == 0`. [F32]
- In `match.pd`, when narrowing `CTZ`, `POPCOUNT`, `PARITY`, or `FFS` on `(convert@1 @0)` to a `BITINT_TYPE` operand `@0` with `TYPE_PRECISION (type0) <= MAX_FIXED_MODE_SIZE`, `type0` must be converted via `build_nonstandard_integer_type` before checking `direct_internal_fn_supported_p`. [F40]
- In `match.pd`, patterns simplifying binary operations (`bit_and`, `bit_ior`, `bit_xor`, `eq`, `ne`) on `(op:c (convert? @0) (convert? (maybe_bit_not @1)))` must check both `types_match (TREE_TYPE (@0), TREE_TYPE (@1))` and `bitwise_inverted_equal_p (@0, @1, wascmp)`, and when simplifying to a non-constant expression or `build_all_ones_cst` (`-1`) rather than a boolean constant, must also require `(!wascmp || element_precision (type) == 1)` (or `TYPE_PRECISION (type) == 1`). [F61, F62]
- In `match.pd`, in the `(vec_perm @0 @1 VECTOR_CST@2)` simplification, all constant-folding (`cop0`, `cop1`), single-element insertion (`bit_insert`), and fallback permutation (`vec_perm`) paths after input canonicalization (`sel.rotate_inputs (1)`, `std::swap (op0, op1)`, or selector canonicalization) must use the local variables `op0`, `op1`, and `op2` rather than `@0`, `@1`, and `@2`. [F4]
- In `match.pd`, rewriting a single-element `vec_perm` from a constant or constructor into `bit_insert` is only valid when `op_mode != BLKmode`. [F48]
- In `match.pd`, when simplifying `(BIT_FIELD_REF (vec_perm@0 @1 @2 VECTOR_CST@3) @rsize @rpos)`, permutation selector indices must be clamped modulo `2 * nelts`, and multi-element extractions must verify that all extracted indices lie in the same input vector (`(start < nelts) == (end < nelts)`), are contiguous, and have `start % nelts_op == 0`. [F57]
- In `match.pd`, when simplifying `(BIT_FIELD_REF CONSTRUCTOR@0 @1 @2)` into a multi-element vector constructor, the loop populating `vals` via `CONSTRUCTOR_APPEND_ELT` must index `CONSTRUCTOR_ELT` at `elt + i` while bounding both `i < count` and `elt + i < CONSTRUCTOR_NELTS (ctor)`. [F3]
- In `match.pd`, vector permutations and reductions that index or iterate over vector elements as a compile-time count (`to_constant ()` on `TYPE_VECTOR_SUBPARTS (type)` or `VECTOR_CST_NELTS`) must first guard with `.is_constant ()`. [F53]
- In `match.pd`, folding a floating-point vector operation across a single-input permutation `(op (vec_perm @0 @0 VECTOR_CST@2) (vec_perm @1 @1 VECTOR_CST@2))` into `(vec_perm (op @0 @1) ...)` requires verifying that the permutation indices cover all `nelts` elements of the input vector. [F54]
- In `match.pd`, folding a vector alternating add/subtract `vec_perm` into a wider-element negate and add/subtract requires `!FLOAT_WORDS_BIG_ENDIAN`, matching IEEE sign-bit positions across `FLOAT_MODE_FORMAT`, and `targetm.can_change_mode_class (TYPE_MODE (ntype), TYPE_MODE (type), ALL_REGS)`. [F45]
- In `match.pd`, transformations introducing target-unsupported vector operations must be gated on `optimize_vectors_before_lowering_p ()` (`(cfun->curr_properties & PROP_gimple_lvec) == 0`), while scalar `COND_EXPR` or FMA canonicalizations that impede vectorization must require `canonicalize_math_after_vectorization_p ()`. [F39]
- In `match.pd`, reducing a low-part `BIT_FIELD_REF` on an integral value to `(convert @0)` requires `(!GIMPLE || is_gimple_reg (@0))`, `BYTES_BIG_ENDIAN == WORDS_BIG_ENDIAN`, `canonicalize_math_after_vectorization_p ()`, and byte-multiple precisions on both `@0` and `type`. [F46]
- In `match.pd`, integer division and modulo simplifications that fold `0 / X`, `X / X`, `1 / X`, `0 % X`, or `X % X` to a constant or comparison must guard the divisor with `!integer_zerop` to preserve division/modulo by zero for diagnostics and C++ `constexpr`. [F17]
- In `match.pd`, canonicalizing `(div @0 integer_pow2p@1)` into `(rshift @0 { build_int_cst (integer_type_node, wi::exact_log2 (wi::to_wide (@1))); })` must be guarded by `#if GIMPLE` and `INTEGRAL_TYPE_P (type) && (TYPE_UNSIGNED (type) || tree_expr_nonnegative_p (@0))`. [F59]
- In `match.pd`, folding `(rshift integer_onep @2)` into `(convert (eq:boolean_type_node @2 { build_zero_cst (TREE_TYPE (@2)); }))` must be guarded by `INTEGRAL_TYPE_P (type)` so vector shifts are not folded into scalar `boolean_type_node` comparisons. [F63]
- In `match.pd`, simplifying `pointer_diff` of a `pointer_plus` (e.g. `(pointer_diff (pointer_plus @@0 @1) @0)`) must reinterpret the `sizetype` offset `@1` as signed via `(convert (view_convert:stype @1))` with `stype = signed_type_for (TREE_TYPE (@1))` rather than `(convert @1)` or `(convert:stype @1)`. [F38]
- In `match.pd`, narrowing or widening comparison/equality simplifications on converted operands `(cmp (convert @00) (convert? @10))` must be disabled when `targetm.have_canonicalize_funcptr_for_compare ()` is true and either inner operand is a pointer to a function or method type (`FUNC_OR_METHOD_TYPE_P`). [F51]
- In `match.pd`, sinking a comparison `(cmp (cond @0 @1 @2) @3)` into `(cond @0 (cmp! @1 @3) (cmp! @2 @3))` must be guarded by `!FLOAT_TYPE_P (TREE_TYPE (@3)) || !operation_could_trap_p (cmp, true, false, @3)`. [F44]
- In `match.pd`, simplifying an outer negation of `FMA`, `IFN_FMS`, `IFN_FNMA`, or `IFN_FNMS` into `IFN_FNMS`, `IFN_FNMA`, `IFN_FMS`, or `IFN_FMA` must be guarded by `!HONOR_SIGN_DEPENDENT_ROUNDING (type)`. [F41]
- In `match.pd`, narrowing a floating-point binary operation `(convert (op (convert @1) (convert @2)))` to `newtype` without `flag_unsafe_math_optimizations` requires `element_precision (newtype) == element_precision (type)`, `real_can_shorten_arithmetic (element_mode (itype), element_mode (type))`, and `!excess_precision_type (newtype)`. [F42]
- In `match.pd`, `double_value_p`, `float_value_p`, and `float16_value_p` must compare `TYPE_MAIN_VARIANT (TREE_TYPE (@0))` rather than raw `TREE_TYPE (@0)` against `double_type_node`, `float_type_node`, or `float16_type_node`. [F14]

## Object Lifetimes

- In `gcc/match.pd`, any heap-backed container declared in a `(with { ... } <subexpr>)` block and used across `<subexpr>` must use an RAII wrapper (such as `vec_perm_builder`, `vec_perm_indices`, or `auto_sbitmap`) because `dt_simplify::gen_1` emits direct `return` and `goto` statements inside `<subexpr>` that bypass manual cleanup. [F12]

## API Contracts

- In GENERIC pattern matching (`gcc/generic-match-head.cc`), `types_match` compares `TYPE_MAIN_VARIANT (t1) == TYPE_MAIN_VARIANT (t2)` after extracting `TREE_TYPE` for non-type arguments, whereas in GIMPLE (`gcc/gimple-match-head.cc`) `types_match` delegates to `types_compatible_p (t1, t2)`. [F13]
- `folding_initializer` and `folding_cxx_constexpr` (`gcc/fold-const.h`) are distinct: `folding_initializer` enables static-initializer constant folding via `fold_init` and `fold_*_initializer_loc`, whereas `folding_cxx_constexpr` indicates C++ manifestly-constant-evaluated context and disables optimizations that hide unspecified or undefined behavior. [F16]
- In `gcc/match.pd`, simplifying `(cmp (op@3 @0 INTEGER_CST@1) INTEGER_CST@2)` for `lt`/`le`/`gt`/`ge` under `TYPE_OVERFLOW_UNDEFINED` must call `fold_overflow_warning` with `WARN_STRICT_OVERFLOW_CONDITIONAL` when folding to a constant or `WARN_STRICT_OVERFLOW_COMPARISON` when rewriting to `(cmp @0 res)`. [F23]
- To encode a `wide_int` constant into a byte buffer in target byte order without allocating a tree node, callers must use `native_encode_wide_int` (`gcc/fold-const.h`) rather than `memcpy` or host-endian byte extraction. [F55]

## Known Pitfalls

- In `gcc/match.pd` `(with { ... })` blocks, `#if GIMPLE` and `#if GENERIC` directives must not split the `{` and `}` or `else` branch of an enclosing `if (...) { ... } else ...` statement, because `genmatch` preprocesses `match.pd` separately per mode and counts brace pairs in each mode. [F5]
- In `gcc/match.pd`, `tree_nop_conversion_p` or equal `TYPE_PRECISION` and `TYPE_SIGN` does not imply `types_match` (e.g. signed vs unsigned or `_BitInt(32)` vs `int`), so replacement expressions must wrap such operands in `(convert ...)`. [F33]
- In `gcc/match.pd`, `TYPE_UNSIGNED` is true for pointer types (`POINTER_TYPE_P`) as well as unsigned integral types, so any pattern guarded by `TYPE_UNSIGNED` that emits bitwise operations (`bit_and`, `bit_ior`, `bit_xor`) must either require `INTEGRAL_TYPE_P` or convert operands to `unsigned_type_for (TREE_TYPE (@0))`. [F34]
- In `gcc/match.pd`, patterns with multiple independent optional nop conversions must use distinct numbered operators (`nop_convert1?`, `nop_convert2?`) and perform replacement arithmetic in the inner operand's type (or `unsigned_type_for (type)`) before converting to `type` to avoid signed overflow UB. [F37]
- In `gcc/match.pd`, simplifications that call `build_nonstandard_integer_type` on a computed bit width or a `BITINT_TYPE` operand's `TYPE_PRECISION` must first verify that the precision is `<= MAX_FIXED_MODE_SIZE`. [F9]
- In `gcc/match.pd`, because a multi-bit `BOOLEAN_TYPE` only allows `0` and `-1` or `1`, negating a boolean value to produce `-1` when `TREE_CODE (type) == BOOLEAN_TYPE` and `TYPE_PRECISION (type) > 1` must convert through `build_nonstandard_integer_type (TYPE_PRECISION (type), TYPE_UNSIGNED (type))`. [F35]
- In `gcc/match.pd`, the `zero_one_valued_p` matchers for `bit_and` and `convert` must not recursively match `zero_one_valued_p` on `@1` (use `wi::leu_p (tree_nonzero_bits (@1), 1)` instead), and the GENERIC `bit_and` and `bit_ior` arms of `with_possible_nonzero_bits` and `with_known_nonzero_bits` must match the non-recursive base predicates `with_possible_nonzero_bits_1` and `with_known_nonzero_bits_1` to avoid infinite recursion. [F7, F8]
- In `gcc/match.pd`, patterns that sink an unconditionally evaluated operand into a conditionally evaluated `cond` branch must require `(GIMPLE || !TREE_SIDE_EFFECTS (...))` on that operand, while patterns that replace a `cond` with one of its branch expressions `@2` must guard any operand of `@2` not already evaluated in the condition with `expr_no_side_effects_p`. [F19, F20]
- In `gcc/match.pd`, paired inverse math comparison rules such as `(cmp:c (logs:s @0) REAL_CST@1) -> (cmp @0 (exps! @1))` and `(cmp:c (exps:s @0) REAL_CST@1) -> (cmp @0 (logs! @1))` must use the `!` modifier on the inverse call so unfolded calls do not cycle endlessly between the two rules. [F60]
- In `gcc/match.pd`, in `(BIT_FIELD_REF (vec_perm@0 @1 @2 VECTOR_CST@3) @rsize @rpos)`, single-element extracts (`known_eq (size, elem_size)`) must be handled before `for (unsigned HOST_WIDE_INT i = 1; i != nelts_op; i++)` because `known_eq` short-circuits `constant_multiple_p`, leaving `nelts_op` at `0`. [F1]
- When constructing `vec_perm_indices` in `gcc/match.pd` to query `can_vec_perm_const_p` for whether an existing `VEC_PERM_EXPR` is supported by the target, `ninputs` must be `2` even when both vector operands of the `VEC_PERM_EXPR` are identical. [F56]
- In `gcc/match.pd`, canonicalizing a narrowing unsigned intermediate conversion `(ocvt (icvt@1 @0))` to `(convert (bit_and @0 mask))` must be restricted to `GIMPLE` (to preserve front-end `-Wconversion` in `GENERIC`), and folding `(cmp (convert @0) INTEGER_CST@1)` to `(cmp @0 (convert @1))` for `eq`/`ne` must be disabled when `GENERIC && TREE_CODE (TREE_TYPE (@0)) == REFERENCE_TYPE && (flag_sanitize & (SANITIZE_NULL | SANITIZE_ALIGNMENT))`. [F21, F22]
- In `gcc/fold-const.h`, `fold_vec_perm` is guarded by `#if GCC_VEC_PERN_INDICES_H` (requiring `"vec-perm-indices.h"` before `"fold-const.h"`), and in `gcc/gimple-match.h`, `directly_supported_p` is guarded by `#ifdef GCC_OPTABS_TREE_H` (requiring `"optabs-tree.h"` before `"gimple-match.h"`). [F10, F11]
