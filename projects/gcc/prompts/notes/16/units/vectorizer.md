# vectorizer

The vectorizer unit (`gcc/tree-vect-loop.cc`, `gcc/tree-vect-data-refs.cc`, `gcc/tree-vect-generic.cc`, and `gcc/tree-predcom.cc`) implements GIMPLE loop vectorization analysis and transformation, data-reference dependence/alignment/interleaving analysis for loop and basic-block SLP vectorization, lowering of unsupported vector operations to narrower vector or scalar code, and loop predictive commoning.

## Architecture & Data Flow

- Whenever `DR_PTR_INFO (dr)` is duplicated onto a derived vector address or IV `SSA_NAME` (`vect_duplicate_ssa_name_ptr_info`, `bump_vector_ptr`), `mark_ptr_info_alignment_unknown` must be called on the new `SSA_NAME_PTR_INFO`, and in `vect_create_addr_base_for_vector_ref`, `DR_PTR_INFO` may only be duplicated onto `addr_base` when `TREE_CODE (addr_base) == SSA_NAME && SSA_NAME_VAR (addr_base) == dest`. [F24, F38]
- In `vect_analyze_data_ref_accesses`, sorting must operate on `datarefs_copy` rather than `vinfo->shared->datarefs`, all interleaving-chain and `vect_analyze_data_ref_access` loops must index `datarefs_copy` while sharing loop counter `i`, any comparison criterion added to `dr_group_sort_cmp` before `DR_INIT` must also be checked as a group-splitting break condition in the inner loop, and `DR_INIT` ties must be broken by `gimple_uid (DR_STMT (dra)) < gimple_uid (DR_STMT (drb))`. [F5, F11]
- In `vect_analyze_data_ref_accesses`, `STMT_VINFO_SLP_VECT_ONLY` on a group's first element (`stmtinfo_a`) must be sticky once set (`if (!STMT_VINFO_SLP_VECT_ONLY (stmtinfo_a))`) and copied to `newgroup` when duplicate accesses split the group; when `vect_dissolve_slp_only_groups` dissolves a non-SLP `STMT_VINFO_SLP_VECT_ONLY` group, each non-leader element must copy `target_alignment` from `first_element` and recompute `misalignment` relative to `DR_INIT (dr_info->dr)`. [F28, F78]
- For grouped data references, alignment is analyzed and stored only on `DR_GROUP_FIRST_ELEMENT`, and `vect_slp_analyze_node_alignment` must preserve a known misalignment and smaller `target_alignment` if re-analyzing for a larger alignment yields `DR_MISALIGNMENT_UNKNOWN`; in `dr_misalignment`, `known_eq (misalignment, 0)` must be checked before `dr_info->target_alignment.is_constant (&target_alignment_c)`, returning `DR_MISALIGNMENT_UNKNOWN` when non-constant rather than calling `to_constant ()`. [F29, F45]
- In `vect_enhance_data_refs_alignment`, after advancing `i0` past initial DRs with null `DR_BASE_ADDRESS`, the subgroup loop `for (i = i0 + 1; i <= datarefs.length (); ++i)` must iterate to `datarefs.length ()` inclusive and guard `i == datarefs.length ()` before indexing `datarefs[i]`; loop versioning for alignment is disabled unless `GET_MODE_SIZE (TYPE_MODE (vectype)).is_constant (&size)` holds. [F6, F52]
- In `vector_alignment_reachable_p`, peeling for alignment must be rejected unless `multiple_p (elem_size * group_size * vf, dr_target_alignment (dr_info))` holds, and in `vect_compute_data_ref_alignment`, if the main loop peeled for alignment (`orig_loop_vinfo && LOOP_VINFO_PEELING_FOR_ALIGNMENT (orig_loop_vinfo) != 0`), epilogue loop alignment analysis must return early leaving misalignment as `DR_MISALIGNMENT_UNKNOWN`. [F39, F44]
- In `vect_analyze_early_break_dependences`, `dest_bb` must have a single predecessor (`single_pred (dest_bb)`), every statement looked up in `loop_vinfo` must be canonicalized via `vect_stmt_to_vectorize`, and any load before `dest_bb` must have `dr_set_safe_speculative_read_required (stmt_vinfo, true)` and `DR_SCALAR_KNOWN_BOUNDS` recorded. [F32, F33]
- In `vect_verify_loop_lens`, `VECTOR_MODE_P (loop_vinfo->vector_mode)` must be checked before calling `get_len_load_store_mode` (as patterns can set scalar modes like `DImode`), and when `internal_len_load_store_bias` returns `-1` for `IFN_LEN_LOAD`, loops with `LOOP_VINFO_LENS (loop_vinfo).length () > 1` must be rejected; in `vect_verify_full_masking_avx512`, any mask group whose `mask_type` is not `MODE_INT` with 1-bit element precision must be rejected. [F91, F92, F93]
- When `vect_get_loop_mask` and `vect_get_loop_len` allocate placeholder `SSA_NAME` controls before loop-header PHIs exist, they must initialize `SSA_NAME_DEF_STMT` on each new `SSA_NAME` (`mask`, `len`, `adjusted_len`) to `gimple_build_nop ()`; at the end of `vect_transform_loop`, any surviving scalar internal call to `IFN_MASK_LOAD` or a `conditional_internal_fn_code` function whose LHS is not `VECTOR_TYPE_P` must be replaced in-place with zero or the call's final `else_arg` operand before `vect_set_loop_condition`. [F72, F74]
- Both `vectorizable_lane_reducing` and `vectorizable_reduction` must reject scalar result types failing `type_has_mode_precision_p`; in `vectorizable_reduction`, when `slp_node` is non-NULL, `ncopies` must be initialized from `SLP_TREE_NUMBER_OF_VEC_STMTS (slp_node)` rather than 1, and when `slp_for_stmt_info` is non-NULL while walking the reduction chain, `STMT_VINFO_REDUC_DEF (vect_orig_stmt (s))` must be set to `phi_info` for every live scalar statement `s` in `SLP_TREE_SCALAR_STMTS (slp_for_stmt_info)`. [F75, F76, F89]
- In `vect_transform_reduction`, `vect_get_loop_mask` must be indexed using a separate `mask_index` counter incremented only on effective reduction copies (`vop[0] && vop[1]`) rather than the `vec_oprnds` index `i`, and when emitting a conditional internal call (`cond_fn_p`), the fallback (`else`) argument passed to `gimple_build_call_internal` must be `vop[reduc_index]` rather than `vop[1]`. [F55, F82]
- `needs_fold_left_reduction_p` must require `FOLD_LEFT_REDUCTION` for non-min/max floating-point ops when `!flag_associative_math` and for integral ops when `!operation_no_trapping_overflow (type, tree_code (code))`; for floating-point `FOLD_LEFT_REDUCTION` with `internal_fn_mask_index (reduc_fn) == -1`, `vect_reduction_update_partial_vector_usage` must disable partial vectors if `HONOR_SIGN_DEPENDENT_ROUNDING (vectype_in)` holds; in `vect_expand_fold_left`, each inserted `BIT_FIELD_REF` extraction statement must be passed to `fold_stmt` (and `update_stmt` if folded). [F84, F98, F99]
- `vect_is_simple_iv_evolution` must reject floating-point steps unless `flag_associative_math` is enabled; in `vect_create_nonlinear_iv_step` for `vect_step_op_mul`, `begin` starts at `wi::to_wide (step_expr)`, so the loop must iterate `vf.to_constant () - 1` times; in `vectorizable_induction`, SLP IV updates must be placed via `standard_iv_increment_position` and `insert_iv_increment`, while for non-SLP `ncopies > 1`, `induction_phi` is copy 0 and the loop runs `1 <= i < ncopies + 1` (pushing statements for `i < ncopies` and attaching `i == ncopies` to `induction_phi` on the latch edge). [F58, F59, F80, F100]
- When `LOOP_VINFO_MASK_SKIP_NITERS` and `LOOP_VINFO_EARLY_BREAKS` are both active, `vectorizable_induction` must create a scalar header PHI (`LOOP_VINFO_MASK_NITERS_PFA_OFFSET`) taking `skip_niters` on the preheader edge and 0 on the latch edge, and `vectorizable_live_operation` must add `step_expr * break_lhs_phi` to early-exit lane-0 extractions; in `vectorizable_live_operation`, immediate-use checks and post-LC-SSA assertions must skip `is_gimple_debug (use_stmt)` and propagate `SSA_NAME_OCCURS_IN_ABNORMAL_PHI (lhs)` onto any replacement `SSA_NAME`. [F73, F81, F85]
- In `get_compute_type` and `type_for_widest_vector_mode`, selecting a narrower vector mode requires `GET_MODE_INNER (mode) == inner_mode`, `known_le (GET_MODE_NUNITS (mode), TYPE_VECTOR_SUBPARTS (original_vector_type))`, `maybe_ne (TYPE_VECTOR_SUBPARTS (vector_compute_type), 1U)`, and `can_implement_p (op, mode)`; piecewise lowering via `nunits_for_known_piecewise_op` requires constant `TYPE_VECTOR_SUBPARTS`, and in `expand_vector_piecewise`, `delta` must be computed from `inner_type` (`VECTOR_TYPE_P (inner_type) ? nunits_for_known_piecewise_op (inner_type) : 1`) rather than dividing `part_width` by `vector_element_bits (type)`. [F40, F49, F50]
- In `expand_vector_conversion`, `gcc_assert (!converts.is_empty ())` must precede the `i < converts.length () - 1` loop to avoid unsigned underflow, and lowering `IFN_VEC_CONVERT` via `VEC_PACK_*` or `VEC_UNPACK_*` optabs must verify `insn_data[icode1].operand[0].mode` is a `VECTOR_MODE_P` matching `TYPE_MODE (cretd_type)` (and `insn_data[icode2].operand[0].mode` when widening); in `do_compare` and `expand_vector_condition`, multi-bit vector booleans use `build_all_ones_cst (stype)` for true and `build_zero_cst (stype)` for false, whereas `SCALAR_INT_MODE_P` bitmasks pack 1 bit per lane. [F1, F41, F47]
- In `pcom_worker::prepare_initializers_chain`, the loop upper bound `n` must be adjusted from `chain->length` (0) to `1` when `chain->type == CT_INVARIANT` (and in `initialize_root_vars`, `!reuse_first` / `chain->has_max_use_after` must hold whenever `chain->length == 0`), and any initializer from `ref_at_iteration` must be rejected (discarding `stmts`) when `!chain->all_always_accessed && tree_could_trap_p (init)`; in `ref_at_iteration`, when `integer_zerop (off)`, `coff` may be placed into the `MEM_REF` offset operand only if `TREE_CODE (DR_BASE_ADDRESS (dr)) != POINTER_PLUS_EXPR`. [F2, F34, F42]

## Object Lifetimes

- Non-RAII `vec` locals allocated with `.create` must be explicitly `.release ()`d on all paths: `datarefs_copy` before every return in `vect_analyze_data_ref_accesses`, every `stmt_vector_for_cost` before scope exit or re-creation in `vect_peeling_hash_get_lowest_cost` and `vect_enhance_data_refs_alignment`, and `result_chain` in `vect_transform_grouped_load` after `vect_record_grouped_load_vectors` returns; in `vect_enhance_data_refs_alignment`, `LOOP_VINFO_DATAREFS (loop_vinfo).copy ()` must be held in `auto_vec<data_reference_p>` and `peeling_htab` in `hash_table<peel_info_hasher>` with `free_ptr_hash <_vect_peel_info>`. [F14, F15, F16, F17]
- Releasing a `vec<rgroup_controls>` (`masks.rgc_vec` or `lens`) must use `release_vec_loop_controls` so each element's `rgc->controls` (`vec<tree>`) is released; `_loop_vec_info::~_loop_vec_info` must only clear `loop->aux` when `loop->aux == this`; `vect_transform_loop` must free every `slp_instance` in `LOOP_VINFO_SLP_INSTANCES (loop_vinfo)` via `vect_free_slp_instance` and `.release ()` the vector; `basic_block *bbs` arrays from `get_loop_body` (`vect_analyze_loop_form`, `optimize_mask_stores`, `update_epilogue_loop_vinfo`) must be freed with `free (bbs)`. [F63, F64, F66, F68]
- In `gcc/tree-predcom.cc`, `release_components` only deletes each `struct component`, so any component discarded in `filter_suitable_components` or skipped as trivial (`comp->refs.length () == 1` in `determine_roots_comp`) must explicitly `free` its `dref` elements; every unretained `chain_p` must be destroyed via `pcom_worker::release_chain` (and unattached `gimple_seq` on failed `prepare_initializers_chain` paths freed via `gimple_seq_discard`), and `insert_init_seqs` must null out `chains[i]->init_seq` after inserting it onto the preheader edge so `release_chain` does not discard live CFG statements. [F18, F19, F20]

## API Contracts

- `vect_analyze_data_ref_dependences` must only allocate and populate `LOOP_VINFO_DDRS (loop_vinfo)` when `!LOOP_VINFO_DDRS (loop_vinfo).exists ()` and must pass `false` for `compute_self_and_rr` to `compute_all_dependences`; before constructing `dr_with_seg_len` in `vect_prune_runtime_alias_test_list`, `align_a` and `align_b` must be clamped with `std::min (align, least_bit_hwi (access_size))`. [F9, F43]
- In `vect_analyze_loop`, when `loop_form_info.assumptions` is not `integer_onep`, `scev_reset_htab ()` and `free_numbers_of_iterations_estimates (loop)` must be called before setting `LOOP_C_FINITE`, and otherwise `free_numbers_of_iterations_estimates (loop)` must still be called; in `expand_vector_conversion`, `optab_for_tree_code` for `VEC_PACK_FIX_TRUNC_EXPR` and `VEC_UNPACK_FIX_TRUNC_LO/HI_EXPR` must pass `ret_type` (whereas `FLOAT_EXPR` and `CASE_CONVERT` pass `arg_type`). [F48, F88]

## Error Handling

- When `vect_analyze_data_refs` or `vect_analyze_data_ref_accesses` encounters an unvectorizable data reference in basic-block SLP (`is_a <bb_vec_info> (vinfo)`), it must set `STMT_VINFO_VECTORIZABLE` to `false` and continue rather than aborting analysis; if `vect_analyze_group_access_1` returns `false`, `vect_analyze_group_access` must dissolve the entire group chain starting at `DR_GROUP_FIRST_ELEMENT` by clearing `DR_GROUP_FIRST_ELEMENT` and `DR_GROUP_NEXT_ELEMENT` on every member. [F30, F31]
- When `vect_analyze_loop_2` rolls back `loop_vinfo` at `again:` before `goto start_over`, it must release `SLP_INSTANCES`, `COMP_ALIAS_DDRS`, and `CHECK_UNEQUAL_ADDRS`, delete and null `vector_costs`, empty `masks.mask_set` and `scan_map`, call `release_vec_loop_controls` on `masks.rgc_vec` and `lens`, reset `STMT_SLP_TYPE` to `loop_vect` on all loop PHIs, scalar statements, and pattern statements, disable `STMT_VINFO_IN_PATTERN_P` for `STMT_VINFO_SLP_VECT_ONLY_PATTERN` patterns, and restore `STMT_VINFO_DEF_TYPE` on reduction definitions from their PHIs. [F65, F77]

## Known Pitfalls

- Shared tree expressions must be passed through `unshare_expr` before gimplification or building new expressions: `cse_and_gimplify_to_preheader` when passing `expr` to `force_gimple_operand`, `vect_create_addr_base_for_vector_ref` for `!loop_vinfo` (passing `DR_REF (dr)` through `strip_zero_offset_components` and `unshare_expr` before building `ADDR_EXPR`), `addr` in `ref_at_iteration`, non-`SSA_NAME`/non-`INTEGER_CST` `niters` in `pcom_worker::prepare_finalizers_chain`, `val` in `replace_ref_with`, and `cond` in `do_cond`. [F22, F27, F71]
- In `vect_create_epilog_for_reduction`, after `scalar_results` is populated, the `INTEGER_INDUC_COND_REDUCTION` (`EQ_EXPR` and `COND_EXPR`) and `adjustment_def` blocks must read and update `scalar_results[0]` rather than `new_temp`; in `check_reduction_path`, every SSA operand step (both descending into `def` and advancing `curr` on backtracking) must be gated on `bitmap_set_bit (visited, SSA_NAME_VERSION (USE_FROM_PTR (curr)))`; when predictive commoning inspects or propagates a store `GIMPLE_ASSIGN` RHS (`is_inv_store_elimination_chain`, `replace_ref_with`, `initialize_root_vars_store_elim_2`), it must check `TREE_CLOBBER_P (val)`. [F25, F56, F61]
