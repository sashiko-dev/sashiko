# MELLANOX ETHERNET DRIVER (mlx5e)

The `mlx5e` driver implements the Mellanox ConnectX-4+ Ethernet netdevice lifecycle, E-Switch vport and uplink representors, flow steering (VLAN, L2, TTC, aRFS, ethtool RXNFC), hardware TC flower/matchall offloads for NIC and switchdev FDB domains, and the NAPI TX/RX/XDP/AF_XDP datapaths.

## Architecture & Data Flow
- `struct mlx5_flow_attr` ends with a flexible-array union (`esw_attr` vs `nic_attr`) excluded from `sizeof(*attr)`. Allocate with `mlx5_alloc_flow_attr(ns)` and copy with `ns_to_attr_sz(ns)`. Shared helpers must check `mlx5e_is_eswitch_flow(flow)` / `ns_type == MLX5_FLOW_NAMESPACE_FDB` before accessing `esw_attr` or `nic_attr`, check `is_mdev_switchdev_mode(priv->mdev)` before accessing `esw->offloads`, and check representor mode or `priv->ppriv != NULL` before dereferencing `rpriv` (`get_tc_ht`, `mlx5e_is_uplink_rep`). [F47, F48, F128, F139]
- In `parse_tc_actions`, splitting a flow into a new post-action `mlx5_flow_attr` at index `i` must call `mlx5e_tc_act_post_parse` for `[i_split, i]`, clone `flow->attr`, set `i_split = i + 1`, and reset `parse_state->if_count = 0` before `list_add`. Because `flow->attr` stays at the tail of `flow->attrs`, `alloc_flow_post_acts`, `mlx5e_tc_offload_flow_post_acts`, `mlx5e_tc_unoffload_flow_post_acts`, and `free_flow_post_acts` must stop at `list_is_last(&attr->list, &flow->attrs)`. [F87, F109]
- In `post_process_attr`, `mlx5e_tc_tun_encap_dests_set` must only run when `mlx5e_is_eswitch_flow(flow) && has_encap_dests(attr)`. Both `extra_split_attr_dests_needed` and `post_process_attr` must check static `MLX5_ESW_DEST_ENCAP` and continue initializing `extra_split_attr`, modify-header handles, and counters even if `mlx5e_tc_tun_encap_dests_set` marks the flow `SLOW`. [F35, F105]
- In `offload_pedit_fields`, `mask_field_get`, and `mask_field_clear`, `struct pedit_headers` masks/values are network byte order and must use width-matched conversions (`32`/`16`/`8`-bit) based on `f->field_bsize`, clearing every consumed or skipped field mask via `mask_field_clear` so `verify_offload_pedit_fields` succeeds. In `actions_prepare_mod_hdr_actions`, if `mod_hdr_acts.num_actions == 0`, clear `MLX5_FLOW_CONTEXT_ACTION_MOD_HDR`, call `mlx5e_mod_hdr_dealloc`, and for FDB flows without VLAN pop/push, reset `esw_attr->split_count = 0`. [F84, F85, F90]
- `mlx5e_tc_match_to_reg_match` must read-modify-write `spec->match_criteria` and `match_value` (masking `max_mask << moffset`, ORing shifted `mask`/`val` bounded by `GENMASK(mlen - 1, 0)`, and setting `MLX5_MATCH_MISC_PARAMETERS_2`). Every `mlx5e_tc_attr_to_reg_mappings` entry must obey `1 <= mlen <= 32` and `moffset + mlen <= 32`, and types omitting `.soffset` (`MAPPED_OBJ_TO_REG`, `VPORT_TO_REG`) must never be passed to `mlx5e_tc_match_to_reg_match` or `mlx5e_tc_match_to_reg_get_match`. [F82, F122, F136]
- In `mlx5e_post_rx_mpwqes`, completed UMRs (`rq->mpwqe.umr_completed`) must be posted via `mlx5e_post_rx_mpwqe`, subtracted from `umr_in_progress`, and reset to 0 before computing `missing`. When posting UMRs on `rq->icosq` (`mlx5e_build_shampo_hd_umr`, `mlx5e_alloc_rx_mpwqe`), set `sq->doorbell_cseg = &umr_wqe->hdr.ctrl`, and in `mlx5e_post_rx_mpwqes` ring via `mlx5e_notify_hw` and reset `sq->doorbell_cseg = NULL`. In `mlx5e_post_rx_wqes`, reduce `wqe_bulk` by `(head + wqe_bulk) & rq->wqe.info.wqe_index_mask` so new WQEs never share a page with uncompleted WQEs. [F66, F92, F158]
- Whenever `rq->hw_gro_data->skb` is handed to `napi_gro_receive` or dropped (`mlx5e_shampo_flush_skb`, `mlx5e_handle_rx_cqe_mpwrq_shampo`, `mlx5e_shampo_complete_rx_cqe`), immediately reset `rq->hw_gro_data->skb = NULL`. At the end of `mlx5e_poll_rx_cq`, if `work_done > 0`, flush any remaining `rq->hw_gro_data->skb` via `mlx5e_shampo_flush_skb(rq, NULL, false)` and call `mlx5e_xdp_rx_poll_complete(rq)` if `rq->xdp_prog` is active before updating the CQ doorbell. [F67, F177]
- In `mlx5e_skb_from_cqe_linear` and `mlx5e_skb_from_cqe_mpwrq_linear`, if `mlx5e_xdp_handle` returns `false` (`XDP_PASS`), recompute `rx_headroom`, `metasize`, and `cqe_bcnt` from `mxbuf->xdp` before `mlx5e_build_linear_skb`. `priv->channels.ptp` (even when `priv->tx_ptp_opened` is set), `sq->ptpsq` (even when `SKBTX_HW_TSTAMP` is set on `skb`), `priv->txq2sq[qid]` in `mlx5e_xmit` (for uncreated/failed HTB queues), and `fs->vlan` (on profiles without `FS_VLAN`) can be `NULL` and must be checked before dereferencing. [F51, F71, F237, F416, F417]
- Both `mlx5e_poll_tx_cq` and `mlx5e_free_txqsq_descs` must unmap WQE DMA via `mlx5e_tx_wi_dma_unmap` before consuming/freeing SKBs, and must handle all `mlx5e_tx_wqe_info` fields (`wi->skb`, `wi->num_fifo_pkts`, `wi->num_bytes`, `wi->resync_dump_frag_page`) in lockstep to pass `npkts` and `nbytes` to `netdev_tx_completed_queue`. Because neither clears `sq->db.wqe_info[ci]`, every WQE producer (`mlx5e_txwqe_complete`, `mlx5e_tx_mpwqe_session_complete`, `mlx5e_tx_flush`) must overwrite `sq->db.wqe_info[pi]` with a full compound literal. [F396, F414, F431, F479]
- On MPWQE-capable SQs, call `mlx5e_tx_mpwqe_ensure_complete(sq)` before `mlx5e_txqsq_get_next_pi` or `mlx5e_post_nop`. In `mlx5e_sq_xmit_mpwqe`, map `txd.dma_addr` and check `dma_mapping_error` before `mlx5e_tx_mpwqe_session_start(sq, eseg)` so `mlx5e_tx_flush` on `err_unmap` never sees an empty active session. Because `mlx5e_tx_mpwqe_session_start` and `mlx5e_tx_mpwqe_same_eseg` only compare `MLX5E_ACCEL_ESEG_LEN` (6 bytes, up to `mss`), `mlx5e_tx_skb_supports_mpwqe` must reject packets needing `eseg` fields at or after `mss`. [F392, F440, F468]

## Synchronization
- Lock order across netdevice paths is `rtnl_lock()` -> `netdev_lock(netdev)` -> `mutex_lock(&priv->state_lock)`. `mlx5e_uplink_rep_enable` and `mlx5e_uplink_rep_disable` must acquire `rtnl_lock()` then `netdev_lock(netdev)`. Callers holding `priv->state_lock` (`mlx5e_change_mtu`, `mlx5e_set_priv_flags`) must unlock it before calling `netdev_update_features(netdev)`, and `dcbnl_rtnl_ops` paths calling `mlx5e_safe_switch_params` (`mlx5e_set_trust_state`) must acquire `netdev_lock(priv->netdev)` outside `priv->state_lock`. [F160, F226, F367]
- In `mlx5e_hairpin_flow_add`, initialize `flows_lock`, `flows`, `dead_peer_wait_list`, `refcnt` (to 1), and `res_ready` before inserting `hpe` into `tc->hairpin_tbl`, and call `complete_all(&hpe->res_ready)` after assigning `hpe->hp` (even when storing an `ERR_PTR` on failure). Lookups and `mlx5e_tc_hairpin_update_dead_peer` must pin entries with `refcount_inc_not_zero` under `hairpin_tbl_lock` and only call `wait_for_completion(&hpe->res_ready)` (then checking `!IS_ERR_OR_NULL(hpe->hp)`) and `mlx5e_hairpin_put` after unlocking. `mlx5e_hairpin_put` must use `refcount_dec_and_mutex_lock(&hpe->refcnt, &tc->hairpin_tbl_lock)`. [F16, F23, F33, F53]
- Lookups in `tc_ht` (`mlx5e_configure_flower`, `mlx5e_delete_flower`, `mlx5e_stats_flower`) must run under `rcu_read_lock()` and pin `flow` via `mlx5e_flow_get` before `rcu_read_unlock()` (which returns `ERR_PTR(-EINVAL)` if `flow` is `NULL` or `refcnt == 0`, so check `IS_ERR(flow)`), and `mlx5e_flow_put` must free via `kfree_rcu`. In `__mlx5e_add_fdb_flow`, always signal `complete_all(&flow->init_done)` after `mlx5e_tc_add_fdb_flow`, and in `mlx5e_tc_del_fdb_flow`, signal `complete_all(&flow->del_hw_done)` after unoffloading rules. [F24, F42, F165]
- When deactivating/closing queues (`mlx5e_deactivate_rq`, `mlx5e_deactivate_txqsq`, `mlx5e_deactivate_icosq`, `mlx5e_close_xdpsq`), clear `MLX5E_RQ_STATE_ENABLED` or `MLX5E_SQ_STATE_ENABLED` and call `synchronize_net()` before stopping TX queues or freeing descriptors/hardware objects, and `cancel_work_sync` all queue works (`dim->work`, `recover_work`, `rx_timeout_work`) before destroying queues. Async recovery works (`mlx5e_tx_timeout_work`, `mlx5e_rq_timeout_work`, `mlx5e_tx_err_cqe_work`) must poll `netdev_trylock` and abort if the active/enabled state bit is cleared. [F219, F220, F221]
- In `mlx5e_post_rx_mpwqe` and `mlx5e_post_rx_wqes`, execute `dma_wmb()` before updating the RQ doorbell record; in `mlx5e_poll_rx_cq` and `mlx5e_poll_tx_cq`, execute `wmb()` after `mlx5_cqwq_update_db_record`, and in `mlx5e_poll_tx_cq` update `sq->cc` and `sq->dma_fifo_cc` only after that `wmb()` to prevent CQ overrun. In `mlx5e_txwqe_complete` with `sq->ptpsq`, execute `wmb()` after `mlx5e_ptp_metadata_map_put` and before `mlx5e_ptpsq_track_metadata`. [F156, F401, F464]
- `mlx5e_napi_poll` must hold `rcu_read_lock()` until `out:`, dereference `c->qos_sqs` and `qos_sqs[i]` with `rcu_dereference()`, and read `c->qos_sqs_size` with `READ_ONCE()` after `smp_rmb()`. In `mlx5e_poll_tx_cq` (`MLX5_CQE_REQ_ERR`), set `MLX5E_SQ_STATE_RECOVERING` via `test_and_set_bit` and queue `sq->recover_work`; `mlx5e_txqsq_wake` and `mlx5e_poll_tx_cq` must only wake `sq->txq` when `MLX5E_SQ_STATE_ENABLED` is set, `MLX5E_SQ_STATE_RECOVERING` is clear, `mlx5e_wqc_has_room_for` is true, and `!mlx5e_ptpsq_metadata_freelist_empty(sq->ptpsq)`. [F408, F473, F477]

## Object Lifetimes
- In `mlx5e_init_rep_tx` / `mlx5e_cleanup_rep_tx`, `mlx5e_rep_neigh_init` must run before `mlx5e_init_uplink_rep_tx` and `mlx5e_tc_ht_init`, and `mlx5e_rep_neigh_cleanup` must run after `mlx5e_tc_ht_cleanup` and `mlx5e_cleanup_uplink_rep_tx`. `mlx5e_destroy_rep_root_ft` must only call `mlx5_destroy_flow_table(rpriv->root_ft)` when `rep->vport == MLX5_VPORT_UPLINK`, and `rep_vport_rx_rule_destroy` must reset `rpriv->vport_rx_rule = NULL`. [F9, F11, F12]
- In `mlx5e_configure_flower`, `mlx5_esw_hold` is a transient barrier always released before return via `mlx5_esw_release`, whereas `mlx5e_tc_block_ipsec_offload` and `mlx5_esw_get` are persistent per-flow holds that must be undone on all error/duplicate exits and in `mlx5e_delete_flower`. Every `mlx5_chains_get_table` call in `mlx5e_add_offloaded_nic_rule` must have a matching `mlx5_chains_put_table` on error and in `mlx5e_del_offloaded_nic_rule`. Whenever `mlx5e_tc_tun_parse` runs on a `mlx5_flow_spec`, call `mlx5_geneve_tlv_option_del` before freeing it if `mlx5_flow_has_geneve_opt(spec)` is true. [F17, F20, F21]
- Because `mlx5e_mod_hdr_alloc` may `krealloc` `mod_hdr_acts->actions` and returns the slot at `mod_hdr_acts->num_actions * MLX5_MH_ACT_SZ`, callers (`mlx5e_tc_match_to_reg_set_and_get_id`, `offload_pedit_fields`) must never cache pointers into `mod_hdr_acts->actions` across calls and must increment `mod_hdr_acts->num_actions` after each allocation. [F137]
- When `mlx5e_xdp_handle` consumes a packet and `MLX5E_RQ_FLAG_XDP_XMIT` is set on `rq->flags`, the RX path must `__test_and_clear_bit(MLX5E_RQ_FLAG_XDP_XMIT, rq->flags)` and increment `frag_page->frags` on all backing pages. Each open RQ (`c->rq`, `c->xskrq`) holds its own `bpf_prog` ref on `rq->xdp_prog`; when `mlx5e_xdp_set` swaps programs with `reset == false`, it must increment `prog` for every active RQ/XSKRQ and put each `old_prog` via `mlx5e_rq_replace_xdp_prog`. [F176, F203]
- `mlx5e_tx_mpwqe_session_complete` must clear `sq->mpwqe.wqe = NULL` after recording `wqe_info` and advancing `sq->pc`. For PTP TX timestamps (`sq->ptpsq && (skb_shinfo(skb)->tx_flags & SKBTX_HW_TSTAMP)`), `mlx5e_cqe_ts_id_eseg` only peeks `metadata_freelist`, whereas `mlx5e_txwqe_complete` pops the freelist, inserts `skb` into `metadata_map`, and calls `skb_get(skb)` after DMA mapping succeeds. [F393, F394]

## API Contracts
- When `mlx5e_tc_update_skb` restores a tunnel or internal port on `skb->dev`, it transfers a netdev reference in `tc_priv->fwd_dev` (even when `tc_priv->skb_done` is set for `MLX5_MAPPED_OBJ_SAMPLE`) that the caller must release via `dev_put(tc_priv->fwd_dev)`. `mlx5i_complete_rx_cqe` signals a dropped IPoIB packet by setting `skb->dev = NULL`, which `mlx5i_handle_rx_cqe` must check and free with `dev_kfree_skb_any()`. When `mlx5e_accel_tx_begin` returns `false`, it has already freed `skb`, so `mlx5e_xmit` must return `NETDEV_TX_OK` without freeing `skb` again. [F22, F46, F412]
- Return value conventions: `mlx5e_tc_table_alloc` returns `ERR_PTR` when `CONFIG_MLX5_CLS_ACT=y` and `NULL` when disabled (check `IS_ERR()`, whereas `mlx5e_fs_init` and `mlx5e_create_netdev` return `NULL` on failure); `mlx5e_mqprio_rl_create` returns `NULL` when no TC has `max_rate`, a valid pointer, or `ERR_PTR` (check `IS_ERR(rl)` for error and `if (rl)` for cleanup); `mlx5e_tc_match_to_reg_set_and_get_id` and `mlx5e_txwqe_build_dsegs` return `>= 0` on success or negative errno on failure (store in signed `int` and check `< 0`). [F41, F43, F233, F234, F409]
- RX/DMA/NAPI contracts: `mlx5e_copy_skb_header` aligns `headlen` up to `sizeof(long)`, so callers must allocate `ALIGN(headlen, sizeof(long))` linear bytes while advancing `skb->tail`/`skb->len` by `headlen`; all `dma_sync_single*_for_cpu` calls on RX `page_pool` buffers must use `rq->buff.map_dir`; when `mlx5e_napi_poll` runs with `budget == 0`, only poll TX CQs and jump to `out:`; TX error/teardown paths must free SKBs via `dev_kfree_skb_any()`, while `mlx5e_poll_tx_cq` must pass `napi_budget` to `napi_consume_skb()` and must only be called on `mlx5e_txqsq` CQs. [F131, F167, F463, F475, F476]

## Error Handling
- Several fields store `ERR_PTR` directly on failure instead of `NULL`: `tc->post_act` and `uplink_priv->post_act` (check `IS_ERR(post_act)` after `get_post_action()`), and `tc->t` and `flow->rule[0]` in NIC TC flows (check `!IS_ERR_OR_NULL()`). By contrast, when an `ERR_PTR`-returning constructor is assigned to a field whose teardown checks `if (obj->field)`, the error path must extract `PTR_ERR` and reset the field to `NULL`. `mlx5_uplink_netdev_get()` can return `NULL` when unbound, so check `netdev` before `netdev_priv(netdev)`. [F49, F50, F54, F241]
- When `mlx5e_alloc_rx_wqes` fails mid-chunk inside `mlx5e_refill_rx_wqes` (`refill_alloc != refill`), `err_free` must free the `total_alloc + refill_alloc` newly allocated WQEs and set `BIT(MLX5E_WQE_FRAG_SKIP_RELEASE)` on all `total_alloc + refill` WQEs whose old pages were already released by `mlx5e_free_rx_wqes`. When `mlx5e_sq_xmit_wqe`, `mlx5e_sq_xmit_mpwqe`, or `mlx5i_sq_xmit` drops `skb` on a DMA mapping error, it must free `skb` via `dev_kfree_skb_any(skb)` and call `mlx5e_tx_flush(sq)`. [F119, F391]

## Known Pitfalls
- Flexible-array, UMR, and WQE hazards: `struct mlx5e_mpw_info` ends with variable-length `alloc_units`, so use `mlx5e_get_mpw_info(rq, i)` instead of `rq->mpwqe.info[i]`; `rq->mpwqe.umr_wqe` is a header-only `struct mlx5e_umr_wqe_hdr`, so `mlx5e_build_umr_wqe` must only access `wqe->hdr`; `sizeof(union mlx5e_alloc_units) == 0`, so `mlx5e_init_wqe_alloc_info` must size elements with `sizeof(*aus->xsk_buffs)` or `sizeof(*aus->frag_pages)` and allocate `wq_sz << rq->wqe.info.log_num_frags` entries; in `mlx5e_tx_mpwqe_add_dseg`, cast `session->wqe` (`struct mlx5e_tx_wqe *`, 32B) to `struct mlx5_wqe_data_seg *` (16B) before adding `session->ds_count`; in `mlx5e_sq_xmit_wqe`, update `eseg->inline_hdr.sz |= cpu_to_be16(ihs)` via bitwise OR after zeroing the WQE so `eseg->trailer` bits are preserved. [F321, F322, F323, F324, F439, F461]
- Wrapping 16-bit WQEBB counters: `sq->pc`, `sq->cc`, `sqcc` (in `mlx5e_poll_tx_cq`, `mlx5e_free_icosq_descs`, `mlx5e_poll_ico_cq`), and `be16_to_cpu(cqe->wqe_counter)` are `u16` cyclic WQEBB counters advanced by `wi->num_wqebbs`. Compare them for equality (`==` / `!=`) or via `mlx5e_wqc_has_room_for` rather than `<` / `<=`, pack `sq->pc` into `cseg->opmod_idx_opcode` before incrementing `sq->pc`, and convert via `mlx5_wq_cyc_ctr2ix` before indexing `sq->db.wqe_info`. In `mlx5e_txwqe_complete` and `mlx5e_sq_xmit_mpwqe`, advance `sq->pc` and run queue-stop checks before `__netdev_tx_sent_queue` so stopping `sq->txq` forces a doorbell ring even with `xmit_more`. [F127, F320, F442, F454, F467]
