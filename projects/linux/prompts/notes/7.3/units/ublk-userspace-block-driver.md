# UBLK USERSPACE BLOCK DRIVER

The ublk driver implements a userspace block device framework that exposes a standard blk-mq block device (`/dev/ublkbN`) whose I/O requests are forwarded to a userspace daemon via `io_uring` passthrough commands (`uring_cmd`) on a companion character device (`/dev/ublkcN`). Device lifecycle management, parameter configuration, and user recovery are controlled through `uring_cmd` operations on `/dev/ublk-control`, while data transfer supports user buffer mapping, pread/pwrite user copy, and `io_uring` registered bvec zero-copy (manual and automatic).

## Architecture & Data Flow

- In `struct ublk_io`, `io->cmd` and `io->req` share an anonymous union discriminated by `UBLK_IO_FLAG_ACTIVE` and `UBLK_IO_FLAG_OWNED_BY_SRV`; callers must sample the old member before overwriting the union and flipping those flags in `__ublk_prep_compl_io_cmd()` or `ublk_fill_io_cmd()`. [F53]
- Because on-daemon buffer registrations increment `io->task_registered_buffers` (capped below `UBLK_REFCOUNT_INIT` in `ublk_daemon_register_io_buf()`) instead of `io->ref`, `ublk_sub_req_ref()` must subtract `UBLK_REFCOUNT_INIT - io->task_registered_buffers` and zero `io->task_registered_buffers`, while `ublk_io_release()` decrements it only when `current == io->task`. [F66]
- In `ublk_ch_uring_cmd_local()`, once `READ_ONCE(io->task) == current` and `UBLK_IO_FLAG_OWNED_BY_SRV` are verified, `(!!(io->flags & UBLK_IO_FLAG_NEED_GET_DATA)) ^ (_IOC_NR(cmd_op) == UBLK_IO_NEED_GET_DATA)` must be enforced before the command switch so `UBLK_IO_NEED_GET_DATA` is accepted if and only if `UBLK_IO_FLAG_NEED_GET_DATA` is set. [F90]
- In `ublk_queue_rqs()`, when `ublk_prep_req(this_q, req, true)` fails, `req` must be moved to `requeue_list` and skipped via `continue` without updating the batch cursor `io` or flushing `submit_list`, and `*rqlist` must be overwritten with `requeue_list` after flushing any remaining `submit_list`. [F93]
- On character device release in `ublk_ch_release_work_fn()`, `ublk_reset_ch_dev(ub)` must reset per-session fields (`ub->mm = NULL`, `ub->nr_io_ready = 0`, `ub->unprivileged_daemons = false`, `ub->ublksrv_tgid = -1`) and reinitialize all queues before `clear_bit(UB_STATE_OPEN, &ub->state)` allows a new open or `UBLK_CMD_START_USER_RECOVERY`. [F60]
- Each `ublk_queue->fail_io` shadows `ub->dev_info.state == UBLK_S_DEV_FAIL_IO`: it must be set on all `ub->dev_info.nr_hw_queues` queues when transitioning to `UBLK_S_DEV_FAIL_IO` in `ublk_ch_release_work_fn()` and cleared on all queues in `ublk_reset_io_flags()` before recovery completes. [F50]
- `ublk_validate_params()` must require `UBLK_PARAM_TYPE_BASIC` and reject `p->chunk_sectors == 0` when `ublk_dev_is_zoned(ub)` is true before `ublk_dev_param_zoned_validate()` runs, guaranteeing `chunk_sectors` is non-zero before `ilog2(chunk_sectors)` is used as a shift exponent in `ublk_get_nr_zones()` and `ublk_report_zones()`. [F101]
- In `struct ublk_io`, `io->task` can be `NULL` for unstarted or quiesced slots (such as in `ublk_queue_reinit()` and `ublk_deinit_queue()`), and `ub->ub_disk` can be `NULL` before `ublk_ctrl_start_dev()` or after `ublk_detach_disk()`, so both pointers must be checked for `NULL` before dereferencing or releasing. [F38]
- `ublk_ctrl_add_dev()` must reject `info.queue_depth == 0`, `info.queue_depth > UBLK_MAX_QUEUE_DEPTH`, `info.nr_hw_queues == 0`, or `info.nr_hw_queues > UBLK_MAX_NR_QUEUES` before allocating queues or tag sets. [F71]

## Synchronization

- Neither `ublk_uring_cmd_cancel_fn()` nor `ublk_ch_release_work_fn()` may acquire `ub->mutex` until `ublk_set_canceling(ub, true)` has been set under `ub->cancel_mutex` and all inflight requests have been aborted via `ublk_abort_queue()`. Broken by: acquiring `ub->mutex` inside `ublk_uring_cmd_cancel_fn()`, `ublk_start_cancel()`, or in `ublk_ch_release_work_fn()` prior to the `ublk_abort_queue()` loop. [F132]
- When handling `UBLK_IO_COMMIT_AND_FETCH_REQ` in `ublk_ch_uring_cmd_local()`, `io->res`, `ublk_fill_io_cmd(io, cmd)`, and `ublk_config_io_buf()` must all update `struct ublk_io` before `ublk_need_complete_req()`, `io_buffer_unregister_bvec()`, or `__ublk_complete_rq()` drops the request reference or ends `req`. Broken by: writing `io->cmd`, `io->flags`, `io->addr`, or `io->buf`, or reading `io->req` after those calls. [F18]
- In `ublk_dispatch_req()`, when `ublk_need_req_ref(ubq)` is true and `UBLK_IO_FLAG_NEED_GET_DATA` is not taken, `ublk_prep_auto_buf_reg()` must initialize `io->ref` to `UBLK_REFCOUNT_INIT` (via `ublk_init_req_ref()`) and any auto-registered buffer state before `ublk_complete_io_cmd()` sets `UBLK_IO_FLAG_OWNED_BY_SRV`, assigns `io->req`, and completes `io->cmd`. [F17]
- In `ublk_get_disk()`, reading `ub->ub_disk` and pinning the gendisk via `get_device(disk_to_dev(disk))` must be done under `ub->lock` to synchronize with `ublk_detach_disk()`, which must atomically set `ub->dev_info.state = UBLK_S_DEV_DEAD`, `ub->dev_info.ublksrv_pid = -1`, and `ub->ub_disk = NULL` under `ub->lock` before `put_disk(disk)`; `ublk_ch_release_work_fn()` must also recheck `ub->ub_disk` after acquiring `ub->mutex`. [F26, F52]
- Lookups in `ublk_index_idr` via `ublk_get_device_from_id()` must hold `ublk_idr_lock` across both `idr_find()` and `ublk_get_device()` (`kobject_get_unless_zero(&ub->cdev_dev.kobj)`), and `ublk_ctl_mutex` must be held when modifying `unprivileged_ublks_added` or testing and setting `UB_STATE_DELETED` in `ublk_ctrl_del_dev()`. [F29]
- When batching requests in `ublk_queue_rqs()`, `ublk_belong_to_same_batch()` must require both `io_uring_cmd_ctx_handle(io->cmd)` and `io->task` to match across all requests placed in the same `submit_list` for `ublk_queue_cmd_list()`. [F64]
- In `ublk_timeout()` (timer/softirq context), resolving `ubq->dev->ublksrv_tgid` via `find_vpid()` and `pid_task()` and delivering `SIGKILL` via `send_sig()` must be enclosed within `rcu_read_lock()` and `rcu_read_unlock()`. [F139]

## Object Lifetimes

- In `ublk_ctrl_start_dev()`, `ublk_get_device(ub)` must be called before `ublk_revalidate_disk_zones()` and `add_disk(disk)`, and on failure of either call the error path must unwind via `ublk_detach_disk(ub)`, `ublk_put_device(ub)`, and `put_disk(disk)`, because once `add_disk()` succeeds `ublk_free_disk()` owns that device reference and `UB_STATE_USED`. [F119]
- `ublk_ctrl_del_dev()` must drop the caller's device reference via `ublk_put_device(ub)` and null out `*p_ub` before waiting on `ublk_idr_wq` for `ublk_idr_freed(idx)`, while leaving `*p_ub` intact if `mutex_lock_killable(&ublk_ctl_mutex)` fails so `ublk_ctrl_uring_cmd()` releases it at `put_dev`. [F2]
- `ublk_remove()` must read `ub->dev_info.flags & UBLK_F_UNPRIVILEGED_DEV` before calling `ublk_put_device(ub)` when decrementing `unprivileged_ublks_added`, and `unprivileged_ublks_added` must only be incremented in `ublk_add_chdev()` after `cdev_device_add()` succeeds. [F5]
- In `ublk_remove()` and `ublk_exit()`, `ublk_stop_dev(ub)` must stop and detach the block device before `cdev_device_del(&ub->cdev, &ub->cdev_dev)` deletes the character device and `ublk_put_device(ub)` drops the initial device reference, and `ublk_exit()` must remove all `ublk_index_idr` devices before unregistering `ublk_chr_class` and `ublk_misc`. [F123]

## API Contracts

- All paths completing an `io_uring_cmd` via `io_uring_cmd_done()` (`ublk_complete_io_cmd()`, `ublk_cancel_cmd()`, and `ublk_ch_uring_cmd_cb()`) must forward the caller's `issue_flags`, and `ublk_cancel_queue()` (invoked from process context outside `io_uring`) must pass `IO_URING_F_UNLOCKED`. [F129]

## Error Handling

- Once `ublk_add_chdev(ub)` calls `device_initialize(&ub->cdev_dev)` with `dev->release = ublk_cdev_rel`, its failure path calls `put_device(dev)` which frees the tag set, queues, device number, mutexes, and `ub`, so `ublk_ctrl_add_dev()` must jump to `out_unlock` rather than any manual teardown label when `ublk_add_chdev()` fails. [F39]
- `ublk_alloc_dev_number()` returns the allocated non-negative device ID (including `0`) on success and a negative errno on failure, so callers must test `ret < 0` rather than `if (ret)`. [F34]

## External Contracts

- When `ublk_dev_need_map_io(ub)` is false (`UBLK_F_USER_COPY`, `UBLK_F_SUPPORT_ZERO_COPY`, or `UBLK_F_AUTO_BUF_REG`), `ublk_check_fetch_buf()` and `ublk_check_commit_and_fetch()` must reject non-zero `ublksrv_io_cmd.addr` except on `UBLK_IO_COMMIT_AND_FETCH_REQ` for `REQ_OP_ZONE_APPEND` (where `addr` is unioned with `zone_append_lba`); when `ublk_dev_need_map_io(ub)` is true, they must allow `buf_addr == 0` if `ublk_dev_need_get_data(ub)` is enabled, except when `req_op(io->req) == REQ_OP_READ` in `ublk_check_commit_and_fetch()`, which always requires a non-zero `buf_addr`. [F81, F87]
- For control commands on an unprivileged device (or `UBLK_CMD_GET_DEV_INFO2`), `ublk_ctrl_uring_cmd_permission()` must verify via `ublk_char_dev_permission()` that the path at `header->addr` is a char device with `stat.rdev == ub->cdev_dev.devt` and `inode_permission()` before advancing `header->addr` and reducing `header->len` by `dev_path_len`. Broken by: adding a per-device control command in `ublk_ctrl_uring_cmd()` without adding its opcode and access mask to `ublk_ctrl_uring_cmd_permission()`. [F146]
- When opening a block device with `UBLK_F_UNPRIVILEGED_DEV` set, `ublk_open()` must reject callers lacking `CAP_SYS_ADMIN` with `-EPERM` unless their `init_user_ns` UID and GID from `ublk_store_owner_uid_gid()` match `ub->dev_info.owner_uid` and `ub->dev_info.owner_gid`. [F145]
- In `ublk_ctrl_add_dev()`, `UBLK_F_UNPRIVILEGED_DEV` must clear `UBLK_F_USER_RECOVERY` and `UBLK_F_USER_RECOVERY_REISSUE` and reject `UBLK_F_USER_COPY`, `UBLK_F_SUPPORT_ZERO_COPY`, and `UBLK_F_AUTO_BUF_REG` with `-EINVAL`, while `ublk_dev_is_zoned(ub)` requires `CONFIG_BLK_DEV_ZONED` and `UBLK_F_USER_COPY` or `UBLK_F_SUPPORT_ZERO_COPY`. [F125]
- UAPI command and parameter validation paths in `ublk_check_cmd_op()`, `ublk_ctrl_uring_cmd()`, `ublk_ctrl_quiesce_dev()`, `ublk_ctrl_start_dev()`, and `ublk_dev_param_zoned_validate()` must return `-EOPNOTSUPP` rather than `-ENOTSUPP`; in `ublk_check_cmd_op()`, `_IOC_TYPE(cmd_op) != 'u'` must be rejected with `-EOPNOTSUPP` when `!IS_ENABLED(CONFIG_BLKDEV_UBLK_LEGACY_OPCODES)`, and when legacy opcodes are enabled, any `_IOC_TYPE(cmd_op)` other than `'u'` or `0` must be rejected. [F32, F86]
- In `ublk_validate_params()` and `ublk_ctrl_start_dev()`, `logical_bs_shift`, `physical_bs_shift`, `io_min_shift`, and `io_opt_shift` are base-2 shifts (`1 << shift` bytes), `max_sectors` is in 512-byte sectors (`max_io_buf_bytes >> 9`), and `dma.alignment` and `seg.seg_boundary_mask` are bitmasks (`is_power_of_2(val + 1)`). [F46]
- `ublk_ctrl_get_params()` and `ublk_ctrl_set_params()` must validate `header->len > sizeof(struct ublk_params_header)` and `0 < ph.len <= header->len`, then clamp `ph.len` to `sizeof(struct ublk_params)` before copying `ub->params` to or from userspace. [F75]
- `ublk_ctrl_get_queue_affinity()` must require `header->len * BITS_PER_BYTE >= nr_cpu_ids`, `header->len` aligned to `sizeof(unsigned long)`, and `header->data[0] < ub->dev_info.nr_hw_queues`, then copy `min(header->len, cpumask_size())` bytes and zero-fill any remaining `header->len - retlen` user bytes via `clear_user()`. [F83]
- In `ublk_ctrl_add_dev()` and `ublk_alloc_dev_number()`, `header->dev_id` must match `info.dev_id` and either equal `U32_MAX` (which casts to `-1` in `int idx` to allocate the lowest free ID in `[0, UBLK_MAX_UBLKS)`) or be strictly less than `UBLK_MAX_UBLKS` to request that specific ID. [F72]
- In `ublk_report_zones()`, `nr_zones` must be clamped to `ub->ub_disk->nr_zones - first_zone`, and the loop over the returned `struct blk_zone` array must stop at the first entry with `zone->len == 0` as a sentinel terminator for a short zone report. [F82]

## Known Pitfalls

- In `ublk_ctrl_uring_cmd()`, `ublk_ctrl_uring_cmd_permission()`, and `ublk_ch_uring_cmd_local()`, any `switch (_IOC_NR(cmd_op))` or `_IOC_NR(cmd_op)` comparison must match against raw command numbers (`_IOC_NR(UBLK_U_...)` or `UBLK_CMD_*` / `UBLK_IO_*`) rather than full 32-bit `_IOR`/`_IOWR`-encoded `UBLK_U_*` constants. [F44]
- `ublk_auto_buf_reg_to_sqe_addr()` must cast `buf->flags` (`__u8`), `buf->reserved0` (`__u8`), and `buf->reserved1` (`__u32`) to `__u64` before left-shifting by 16, 24, and 32 bits so that shifting `reserved0` into bit 31 does not sign-extend via default `int` promotion and shifting `reserved1` by 32 bits is defined. [F100]
