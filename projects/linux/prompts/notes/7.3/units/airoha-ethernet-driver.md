# AIROHA ETHERNET DRIVER

This unit implements the Ethernet and hardware packet offload drivers for Airoha EN7581 SoCs, covering the Frame Engine (FE), QDMA scatter-gather and QoS controllers, Packet Processing Engine (PPE), and RISC-V Network Processor Unit (NPU). It manages up to four GDM MAC ports (LAN DSA switches and WAN ports), hardware QoS scheduling and policing (ETS, HTB, matchall), and L2/L3/L4 flow table offloading via TC flower and NPU firmware communication.

## Architecture & Data Flow

- In `struct airoha_foe_entry`, `airoha_foe_bridge`, `airoha_foe_ipv4`, `airoha_foe_ipv4_dslite`, and `airoha_foe_ipv6` must keep `data` at offset 36 because `airoha_ppe_foe_commit_subflow_entry()` and `airoha_ppe_foe_entry_prepare()` alias it across packet types. However, `ipv6` places `ib2` at offset 44 and uses a 16-byte `struct airoha_foe_mac_info_common l2` (without `src_mac_lo` or `pppoe_id`), whereas `bridge`, `ipv4`, and `dslite` place `ib2` at 16 (12 in the union) and a 24-byte `l2` at 40; callers must check `AIROHA_FOE_IB1_BIND_PACKET_TYPE >= PPE_PKT_TYPE_IPV6_ROUTE_3T` before accessing `ib2` or `l2`. [F33, F61]
- `struct airoha_foe_entry data` must remain the last member of `struct airoha_flow_table_entry` because `struct airoha_foe_entry` ends in the flexible array member `DECLARE_FLEX_ARRAY(u32, d)`. [F71]
- `struct airoha_foe_bridge` must keep `dest_mac_hi`, `src_mac_hi`, `dest_mac_lo`, and `src_mac_lo` as its first 12 bytes, and lookups in `ppe->l2_flows` using `airoha_l2_flow_table_params` must build the key via `airoha_ppe_foe_set_bridge_addrs()` because `src_mac_hi` and `dest_mac_lo` are interleaved in the second 32-bit word. [F60]
- In `struct airoha_flow_table_entry`, `e->hash == 0xffff` indicates the software flow entry is not bound to a hardware FOE slot; callers must check `e->hash != 0xffff` before passing `e->hash` to `airoha_ppe_foe_get_entry_locked()`, `airoha_ppe_foe_commit_entry()`, or `airoha_ppe_foe_entry_get_stats()`, and set `e->hash = 0xffff` before removing an already-evicted flow. [F37]
- When `airoha_ppe_foe_flow_stats_update()` redirects a non-WLAN FOE entry (`pse_port != FE_PSE_PORT_CDM4`) to PSE port 6 for NPU accounting, it must mutate `hwe` in `ppe->foe` (not `e->data`), save original `ib2` and `data` bits into `AIROHA_FOE_TUNNEL_MTU` and `AIROHA_FOE_ACTDP` before overwriting `*ib2`, and call `airoha_ppe_foe_flow_stat_entry_reset()`. [F52]
- When `airoha_ppe_foe_commit_subflow_entry()` binds a bridged subflow: for IPv4 HNAPT (`type == PPE_PKT_TYPE_IPV4_HNAPT`), it must copy `hwe.ipv4.orig_tuple` into `hwe.ipv4.new_tuple` so packets keep their original IPv4 addresses/ports; for IPv6 (`type >= PPE_PKT_TYPE_IPV6_ROUTE_3T`), after copying `e->data.bridge.l2` into `hwe.ipv6.l2`, it must overwrite `hwe.ipv6.l2.src_mac_hi` with `FIELD_PREP(AIROHA_FOE_MAC_SMAC_ID, 0xf)` so hardware preserves the packet's original source MAC. [F47, F48]
- In `airoha_ppe_flow_offload_replace()`, Ethernet header mangling (`FLOW_ACT_MANGLE_HDR_TYPE_ETH`) must run in the first action loop before `airoha_ppe_foe_entry_prepare()`, whereas IPv4/L4 port mangling must run in the second loop between `airoha_ppe_foe_entry_set_ipv4_tuple(..., false)` and `airoha_ppe_foe_entry_set_ipv4_tuple(..., true)`. [F90]
- Whenever a GDM port's MAC address is written to FE registers in `airoha_set_macaddr()`, `airoha_ppe_init_upd_mem()` must be called in lockstep so the PPE `REG_UPDMEM_DATA` source-MAC table entry indexed by `port->id` matches `port->dev->dev_addr` for routed IPv6 FOE entries using `AIROHA_FOE_MAC_SMAC_ID`. [F46]
- Each QDMA TX completion ring (`irq_q->q`) must be initialized to `0xff` via `memset()` in `airoha_qdma_tx_irq_init()` because `0x0` is a valid completion entry and `0xff` is the empty sentinel. In `airoha_qdma_tx_napi_poll()`, every non-`0xff` entry at `irq_q->q[head]` must be reset to `0xff` and have `head`, `irq_queued`, and `done` updated before any `continue` or `goto unlock`, and `done` must be cleared in `REG_IRQ_CLEAR_LEN(id)` in chunks of at most `0x80`. [F42, F91]
- In `airoha_qdma_init_hfwd_queues()`, when a `"qdma%d-buf"` reserved-memory region is present, `num_desc` must be computed from `rmem->size` and `buf_size` (`AIROHA_MAX_PACKET_SIZE` for QDMA0, `AIROHA_MAX_PACKET_SIZE / 2` for QDMA1) and used both to allocate `struct airoha_qdma_fwd_desc` and to program `HW_FWD_DESC_NUM_MASK` in `REG_LMGR_INIT_CFG`. [F107]
- Cumulative counter readers (`airoha_qdma_get_tx_ets_stats()` and `airoha_ppe_flow_offload_stats()`) must report the delta between the current counter and stored snapshot (`port->cpu_tx_packets`/`fwd_tx_packets` or `e->stats`) and update the snapshot, whereas `airoha_update_hw_stats()` adds raw register values and clears `REG_FE_GDM_MIB_CLEAR`. [F106]

## Synchronization

- `ppe_lock` in `airoha_ppe.c` is shared between RX softirq/NAPI (`airoha_ppe_check_skb()` -> `airoha_ppe_foe_insert_entry()`) and process context (`airoha_ppe_setup_tc_block_cb()`, `airoha_ppe_foe_get_entry()`), so it must always be acquired via `spin_lock_bh(&ppe_lock)`, nesting inside `flow_offload_mutex` and outside `airoha_npu_core.lock`. All mutations and traversals of `ppe->foe_flow` and `e->l2_flows` (including `airoha_ppe_foe_remove_flow()`, `airoha_ppe_foe_remove_l2_flow()`, and `airoha_ppe_foe_flow_l2_entry_update()`) must hold `spin_lock_bh(&ppe_lock)`. [F18, F142]
- All TC flower offload operations in `airoha_ppe_setup_tc_block_cb()`, including lazy NPU setup via `airoha_ppe_offload_setup()`, `airoha_ppe_flow_offload_cmd()`, and accesses to `eth->flow_table`, must be serialized under `flow_offload_mutex`. [F29]
- In `airoha_ppe_foe_commit_entry()`, copying the flow descriptor payload into `hwe->d` in the coherent DMA table `ppe->foe` must be ordered by `wmb()` before writing `hwe->ib1` with the updated `AIROHA_FOE_IB1_BIND_STATE` and `AIROHA_FOE_IB1_BIND_TIMESTAMP`. [F21]
- `airoha_irq_bank.irq_lock` is shared between hardirq (`airoha_irq_handler()`), NAPI poll (`airoha_qdma_rx_napi_poll()`, `airoha_qdma_tx_napi_poll()`), and process context (`airoha_qdma_hw_init()`), so `irqmask` and `REG_INT_ENABLE` updates in `airoha_qdma_set_irqmask()` must use `spin_lock_irqsave()` and read back `REG_INT_ENABLE` before unlocking. [F139]
- `DEV_STATE_INITIALIZED` in `eth->state` must only be set at the end of `airoha_hw_init()` after FE, QDMA, and PPE initialization complete, and `airoha_irq_handler()` must check `test_bit(DEV_STATE_INITIALIZED, &qdma->eth->state)` before disabling IRQs or scheduling NAPI. [F24]
- The NPU watchdog hardirq handler `airoha_npu_wdt_handler()` must defer `vzalloc()` and `dev_coredumpv(..., GFP_KERNEL)` to process context via `schedule_work(&core->wdt_work)` (`airoha_npu_wdt_work()`), and `airoha_npu_remove()` must call `cancel_work_sync()` on every core's `wdt_work`. [F150]

## Object Lifetimes

- `FLOW_TYPE_L2_SUBFLOW` entries allocated by `airoha_ppe_foe_commit_subflow_entry()` are not in `eth->flow_table` and are freed directly via `kfree(e)` inside `airoha_ppe_foe_remove_flow()` under `ppe_lock`, whereas `FLOW_TYPE_L4` and `FLOW_TYPE_L2` entries are freed by `airoha_ppe_flow_offload_destroy()` after removal from `eth->flow_table` (with `airoha_ppe_foe_remove_l2_flow()` calling `airoha_ppe_foe_remove_flow()` on each `e->l2_flows` child). [F13]
- In `airoha_npu_wdt_work()`, ownership of the `vzalloc`-allocated dump buffer is transferred to `dev_coredumpv(npu->dev, dump, NPU_DUMP_SIZE, GFP_KERNEL)`, so the caller must not call `vfree(dump)` afterwards. [F16]
- In `airoha_npu_get()` and `airoha_ppe_get_dev()`, `of_node_put(np)` must not be called on the `of_parse_phandle()` node until after the `!pdev` error path finishes logging `np->name`. [F1]

## API Contracts

- `airoha_npu_get()` and `airoha_ppe_get_dev()` acquire a `platform_device` reference (`of_find_device_by_node()`) and a module reference (`try_module_get()`) that must be unwound in reverse order on failure or released via `airoha_npu_put()` / `airoha_ppe_put_dev()`. When `CONFIG_NET_AIROHA` or `CONFIG_NET_AIROHA_NPU` are enabled they return `ERR_PTR(-errno)` on failure, whereas their `#else` stubs in `airoha_offload.h` return `NULL`, so callers that can build without those symbols must check `IS_ERR_OR_NULL()`. [F2, F162]
- `port->id` is 1-based (`1..4`) for GDM register macros (`GDM_BASE`, `REG_GDM_*`, `REG_FE_GDM_*`), whereas `eth->ports[]` is 0-based (`port->id - 1`) with nullable entries. When encoding a GDM port into a hardware PSE port field (`AIROHA_FOE_IB2_PSE_PORT` or `QDMA_ETH_TXMSG_FPORT_MASK`), `port->id == 4` must be mapped to `FE_PSE_PORT_GDM4` (`9`) rather than using `4` (`FE_PSE_PORT_PPE1`). [F40, F65]
- `airoha_npu.stats` is an `__iomem` mapping (`devm_ioremap()`), whereas `airoha_ppe.foe_stats` is coherent DMA memory, so `airoha_ppe_foe_flow_stat_entry_reset()` and `airoha_ppe_foe_entry_get_stats()` must access `npu->stats` via `memset_io()` and `memcpy_fromio()`. Callers of `airoha_ppe_foe_entry_get_stats()` must zero-initialize `*stats` because it is left unmodified when `index >= PPE_STATS_NUM_ENTRIES` or `!eth->npu`. [F38, F151]
- `dev->dsa_ptr` is a nullable pointer that must be checked with `netdev_uses_dsa(dev)` (never `IS_ERR()`), whereas `dsa_port_from_netdev()` in `airoha_get_dsa_port()` returns `ERR_PTR()` and must be checked with `IS_ERR()`. [F32]
- Before modifying Ethernet or TCP headers in-place on transmit, `airoha_get_dsa_tag()` and the GSO path in `airoha_dev_xmit()` must call `skb_cow_head(skb, 0)` to unshare cloned SKB headers. [F153]
- QDMA RX done interrupts for queues `16..31` occupy bits `0..15` (`RX_DONE_HIGH_INT_MASK`) of `QDMA_INT_REG_IDX2`, so converting between a 32-bit RX queue bitmap and `QDMA_INT_REG_IDX2` requires shifting by `RX_DONE_HIGH_OFFSET` (`16`) or taking `qid % RX_DONE_HIGH_OFFSET`. [F41]
- `airoha_qdma_rx_napi_poll()` and `airoha_qdma_tx_napi_poll()` must only re-enable QDMA hardware interrupts via `airoha_qdma_irq_enable()` when `done < budget` and `napi_complete(napi)` returns `true`. [F157]
- Callers of `airoha_qdma_set_chan_tx_sched()` and users of `CHAN_QOS_MODE_MASK(_n)` must pass a channel index `< 8` (bounded modulo `AIROHA_NUM_QOS_CHANNELS`) because `CHAN_QOS_MODE_MASK(_n)` shifts by `(_n) << 2` without masking. [F102]

## Error Handling

- `airoha_ppe_foe_get_entry()` and `airoha_ppe_foe_get_entry_locked()` return `NULL` when polling `REG_PPE_RAM_CTRL` for `PPE_SRAM_CTRL_ACK_MASK` times out on SRAM entries, so every caller must NULL-check the returned pointer before dereferencing it. [F31]
- In `airoha_npu_send_msg()`, `regmap_read_poll_timeout_atomic()` returning `0` only means `MBOX_MSG_DONE` is set; the caller must also verify `FIELD_GET(MBOX_MSG_STATUS, val) == NPU_MBOX_SUCCESS` and return `-EINVAL` otherwise. [F44]
- In `airoha_npu.c`, `devm_ioremap_resource()`, `devm_platform_ioremap_resource()`, and `devm_regmap_init_mmio()` return `ERR_PTR()` (`IS_ERR()`), whereas `devm_ioremap()` in `airoha_npu_ppe_stats_setup()` returns `NULL` on failure. [F30]
- In `airoha_qdma_tx_napi_poll()`, each `irq_q->q[head]` entry must be checked against `0xff` and have `IRQ_RING_IDX_MASK` (`qid < ARRAY_SIZE(qdma->q_tx)` and `q->ndesc`) and `IRQ_DESC_IDX_MASK` (`index < q->ndesc`) validated before indexing `q->desc[]` and `q->entry[]`. [F77]
- In `airoha_ppe_flow_offload_replace()`, `airoha_ppe_flow_mangle_eth()` must reject `act->mangle.offset > 8` so writes stay within the 12-byte MAC header, and `FLOW_ACTION_VLAN_PUSH` / `FLOW_ACTION_PPPOE_PUSH` must enforce `data.vlan.num < 2` and `data.pppoe.num < 1`. [F82]

## External Contracts

- Mailbox structures DMA-mapped to the NPU in `airoha_npu_send_msg()` (`struct ppe_mbox_data`, `struct wlan_mbox_data`) must use fixed-width types (`u32`, `u8`) and explicit reserved padding arrays (`rsv`) matching NPU firmware layout. [F69]
- For 3-tuple routing flows (`PPE_PKT_TYPE_IPV4_ROUTE` and `PPE_PKT_TYPE_IPV6_ROUTE_3T`), `airoha_ppe_foe_entry_prepare()` must set `orig_tuple.ports` or `ipv6.ports` to `0xa5a5a500 | (l4proto & 0xff)`, matching the `_pad` pattern required by `airoha_ppe_foe_get_entry_hash()`. [F81]

## Known Pitfalls

- Callers of `airoha_ppe_foe_commit_entry()` must copy the result of `airoha_ppe_foe_get_entry_locked(ppe, hash)` into a local `struct airoha_foe_entry` rather than passing the `ppe->foe` pointer directly as `e`, because `airoha_ppe_foe_commit_entry()` runs `memcpy(&hwe->d, &e->d, ...)`. Moreover, because `d` starts at offset 4 after `u32 ib1`, `memcpy()` in `airoha_ppe_foe_commit_entry()` and `memcmp()` in `airoha_ppe_foe_compare_entry()` on `&hwe->d` or `&e->data.d` must subtract `sizeof(hwe->ib1)` from `sizeof(*hwe)` or `offsetof(struct airoha_foe_entry, ...)`. [F54, F109]
- Unlike `__le32` QDMA descriptors, all IP addresses, L4 ports, and MAC parts in `struct airoha_foe_entry` are stored in CPU byte order (`be32_to_cpu()`, `be16_to_cpu()`, `ipv6_addr_be32_to_cpu()`, `get_unaligned_be32/16()`). Consequently, `airoha_debugfs_ppe_print_tuple()` must format FOE IPv4 addresses with `%pI4h` and convert IPv6 words via `ipv6_addr_cpu_to_be32()` before `%pI6`. [F74, F118]
- In `airoha_ppe_foe_remove_l2_flow()`, all accesses to the parent `FLOW_TYPE_L2` entry `e` (caching `&e->l2_flows` into `head` and removing `e->l2_node` from `ppe->l2_flows`) must happen before `hlist_for_each_entry_safe(e, n, head, l2_subflow_node)` overwrites `e`. Similarly, `airoha_ppe_foe_flow_l2_entry_update()` must use a separate cursor `iter` to iterate `e->l2_flows` while updating `e->data.ib1` and freeing unbound `iter` subflows. [F87, F88]
- In `airoha_ppe_get_entry_idle_time()`, when the FOE entry state is not `AIROHA_FOE_STATE_BIND`, the 15-bit hardware timestamp `now` must be masked to `AIROHA_FOE_IB1_UNBIND_TIMESTAMP` (8 bits) before subtracting `ts`. [F104]
- In `airoha_ppe_foe_entry_get_stats()`, the `u32` upper counters in `ppe->foe_stats[index]` must be widened to `u64` before shifting left by 32 and ORing with the `u32` lower counters from `npu->stats[index]`. [F100]
- Because netdev TX queue indices can reach `AIROHA_NUM_NETDEV_TX_RINGS - 1` (`35`) with HTB QoS channels, `airoha_dev_xmit()` must reduce `skb_get_queue_mapping(skb)` modulo `ARRAY_SIZE(qdma->q_tx)` (`32`) before indexing `qdma->q_tx[]`. [F67]
- In `airoha_get_dsa_tag()`, stripping the 4-byte `MTK_HDR_LEN` tag shifts the 12-byte MAC header (`2 * ETH_ALEN`) into an overlapping range, so `memmove(skb->data + MTK_HDR_LEN, skb->data, 2 * ETH_ALEN)` must be used (not `memcpy()`) before `__skb_pull()`. [F111]
- In `airoha_qdma_set_rl_token_bucket()` and `airoha_qdma_set_trtcm_token_bucket()`, both `tick` and `unit` must be verified non-zero before dividing or taking modulo; furthermore, 64-bit divisions on TC rates (`opt->rate`, `act->police.rate_bytes_ps`) and reserved-memory size (`rmem->size` in `airoha_qdma_init_hfwd_queues()`) must use `div_u64()` rather than `/`. [F101, F103]
