# MEN CHAMELEON BUS (mcb)

The MEN Chameleon Bus (MCB) subsystem implements a Linux bus driver and device model for discovering and managing IP cores (cells) inside MEN Mikroelektronik FPGAs. It provides an MMIO configuration table parser (`mcb-parse.c`) that instantiates `mcb_device` objects from the on-FPGA Chameleon v2 table, core bus/device/driver registration and resource helpers (`mcb-core.c`), and carrier bus glue drivers for PCI (`mcb-pci.c`) and LPC/DMI (`mcb-lpc.c`) attachments.

## Architecture & Data Flow

- `mcb_alloc_bus()` and `mcb_device_register()` must keep `bus->dev.parent` and `dev->dev.parent` pointing to the carrier `struct device` (matching `bus->carrier` and `dev->dma_dev`), and that carrier device must remain bound to a `struct device_driver` whenever child `mcb_device`s are probed or removed because `mcb_probe()` and `mcb_remove()` unconditionally dereference `mdev->dev.parent->driver->owner`. Broken by: setting `dev->dev.parent = &bus->dev`, passing a driverless carrier to `mcb_alloc_bus()`, or unbinding the carrier before `mcb_release_bus()`. [F33, F73]
- In `mcb_pci_probe()`, `priv->bus->get_irq` must be set to `mcb_pci_get_irq` before calling `chameleon_parse_cells()`, because `chameleon_parse_cells()` calls `mcb_device_register()` (`device_add()`), which can synchronously probe an already-registered `mcb_driver` that calls `mcb_get_irq()`. [F63]
- Before `mcb_device_register()` publishes a cell via `device_add(&dev->dev)`, the caller must populate `dev->id`, `dev->inst`, `dev->group`, `dev->var`, `dev->irq`, and `dev->mem`, and `mcb_device_register()` must take `mcb_bus_get(bus)` and set `dev->dev.release = mcb_release_dev` and `dev->dma_dev = bus->carrier`. [F12]
- In `mcb_pci_probe()` and `mcb_lpc_probe()`, shrinking the carrier MMIO reservation and remapping `priv->base` to `table_size` when `table_size < CHAM_HEADER_SIZE` must occur after `chameleon_parse_cells()` and before `mcb_bus_add_devices()`, releasing both `priv->base` and the `CHAM_HEADER_SIZE` region (`devm_release_mem_region()`) before re-requesting `table_size`. Any change to `chameleon_parse_cells()` invocation or `CHAM_HEADER_SIZE` resizing must be applied in lockstep to both `mcb_pci_probe()` and `mcb_lpc_probe()`. [F34, F38]
- Memory `struct resource` definitions (`sc24_fpga_resource`, `sc31_fpga_resource`) and parser assignments (`mdev->mem` in `chameleon_parse_gdd()`) must use inclusive `.end` bounds (`start + size - 1` or `DEFINE_RES_MEM(start, size)`), with `mdev->mem.start` set to `cb[mdev->bar].addr + offset` so `resource_size(&dev->mem)` matches `size`. Broken by: setting `.end = start + size` or assigning `offset` to `mdev->mem.start` without adding `cb[bar].addr`. [F39, F51]
- `mcb_pci_probe()` must check `pci_resource_flags(pdev, 0) & IORESOURCE_IO` and fail with `-ENOTSUPP` before calling `devm_request_mem_region()`, and `chameleon_parse_gdd()` must skip cells whose `cb[mdev->bar].addr` has bit 0 set (`dev_mapbase & 0x01`), because MCB does not support I/O-mapped BARs. [F64]
- `chameleon_parse_cells()` must verify `le16_to_cpu(header->magic) == CHAMELEONV2_MAGIC` (`0xabce`) after `memcpy_fromio()` before calling `chameleon_get_bar()` or iterating cell descriptors with `for_each_chameleon_cell()`. [F65]
- `struct chameleon_fpga_header` is copied from MMIO space with `memcpy_fromio()`, which preserves little-endian byte order without conversion, so multi-byte fields in `header` (such as `header->magic`) must be converted with `le16_to_cpu()` before use, whereas descriptor words read via `readl()` are already CPU-endian. [F43]
- Because `chameleon_fpga_header.filename` is a `CHAMELEON_FILENAME_LEN`-byte field without a NUL terminator, `chameleon_parse_cells()` must bound copies from `header->filename` to `CHAMELEON_FILENAME_LEN` bytes and NUL-terminate `bus->name` (`CHAMELEON_FILENAME_LEN + 1` bytes) before `name_show()` formats `bus->name` with `%s`. [F53]
- When a `CHAMELEON_DTYPE_BAR` descriptor is present, `chameleon_get_bar()` must reject `bar_count <= 0 || bar_count > CHAMELEON_BAR_MAX` with `-ENODEV` before allocating the `chameleon_bar` array and advancing `*base` by `BAR_DESC_SIZE(bar_count)` (`bar_count * sizeof(struct chameleon_bar) + sizeof(__le32)`). [F40]
- Descriptor parser functions (`chameleon_parse_gdd()`, and any future `chameleon_parse_bdd()` implementation) must validate that the 3-bit 0-based `GDD_BAR` / `bar` index (`0..7`) does not exceed `bar_count - 1` (`bar_count` in `1..6`) before indexing the `cb` (`struct chameleon_bar`) array. [F41]
- When adding or modifying descriptor handling in `chameleon_get_bar()` or the `for_each_chameleon_cell()` loop in `chameleon_parse_cells()`, the MMIO cursor `p` must advance by the exact byte size of each parsed descriptor so that `table_size = p - base` equals the total Chameleon table size. [F36]
- The sysfs attributes in `mcb_carrier_groups` (`revision_show`, `model_show`, `minor_show`, `name_show`) unconditionally cast `struct device *` to `struct mcb_bus *` via `to_mcb_bus(dev)`, so they must only be attached to `mcb_carrier_device_type.groups` on `bus->dev` and never to `mcb_bus_type.dev_groups`. [F76]

## Object Lifetimes

- An `mcb_device` allocated by `mcb_alloc_dev()` must be freed with `mcb_free_dev()` if discarded before `mcb_device_register()` is called, whereas `mcb_device_register()` calls `device_initialize(&dev->dev)` and `mcb_bus_get(bus)` and must release `dev` via `put_device(&dev->dev)` on `device_add()` failure without the caller freeing it again. [F58]
- `mcb_probe()` must acquire both a module reference on the carrier driver (`try_module_get(mdev->dev.parent->driver->owner)`) and a device reference (`get_device(dev)`) before invoking `mdrv->probe()`, and release both if `mdrv->probe()` fails and in `mcb_remove()` after `mdrv->remove()`. [F61]
- `mcb_pci_probe()` enables the PCI device with non-devres `pci_enable_device(pdev)`, so every error path after `pci_enable_device()` succeeds and `mcb_pci_remove()` must call `pci_disable_device(pdev)` after `mcb_release_bus(priv->bus)`. [F8]
- `chameleon_parse_cells()` and `chameleon_parse_gdd()` must not store any virtual pointers derived from `void __iomem *base` into `struct mcb_bus` or `struct mcb_device`, because `mcb_pci_probe()` and `mcb_lpc_probe()` unmap `priv->base` via `devm_iounmap()` whenever `table_size < CHAM_HEADER_SIZE`. [F35]
- `mcb_init()` must be registered with `fs_initcall()` (between `subsys_initcall` and `device_initcall`) so that `bus_register(&mcb_bus_type)` completes after PCI initialization and before built-in MCB carrier and client drivers register at `device_initcall` time. [F17]

## API Contracts

- `mcb_alloc_bus()` and `mcb_request_mem()` return an error-encoded pointer (`ERR_PTR()`) on failure and never `NULL` (callers must check with `IS_ERR()`), whereas `mcb_alloc_dev()` and `mcb_get_resource()` return `NULL` on failure and never an `ERR_PTR()` (callers must check for `NULL`). [F18, F19]
- `mcb_get_resource()` returns a borrowed pointer to `&dev->mem` or `&dev->irq` embedded in `struct mcb_device`, whereas `mcb_request_mem()` allocates a `struct resource` via `request_mem_region()` (returning `ERR_PTR(-EBUSY)` on failure) that must be paired with `mcb_release_mem()`, and dereferences `dev->dev.driver->name` when its `name` parameter is `NULL`. Broken by: passing `mcb_get_resource()`'s return value to `mcb_release_mem()`, or calling `mcb_request_mem(dev, NULL)` on an unbound `mcb_device`. [F9, F78]
- Because `struct mcb_device` is a virtual device on `mcb_bus_type`, `mcb_device_register()` assigns `dev->dma_dev = bus->carrier`, so MCB client drivers must pass `mdev->dma_dev` rather than `&mdev->dev` to DMA-API functions (`dma_set_mask_and_coherent()`, `dma_alloc_coherent()`, `dma_map_*()`). [F68]
- `chameleon_parse_cells()` requires `base` to be an `ioremap`-ed virtual `__iomem` pointer for reading the Chameleon MMIO table (`memcpy_fromio()`, `readl()`) and `mapbase` to be the physical base address used by `chameleon_get_bar()` and `chameleon_parse_gdd()` to populate `mdev->mem.start`. [F69]
- `__mcb_register_driver()` rejects any `struct mcb_driver` whose `.probe` or `.remove` callback is `NULL` with `-EINVAL`, and `mcb_remove()` unconditionally invokes `mdrv->remove(mdev)` without a null check, whereas `mdrv->shutdown` is optional and guarded in `mcb_shutdown()`. [F23]
- `mcb_get_irq()` dispatches to `bus->get_irq(dev)` only when the carrier driver has populated `bus->get_irq` (as `mcb_pci_probe()` does with `mcb_pci_get_irq`) and otherwise falls back to `__mcb_get_irq(dev)` to return `dev->irq.start`. Broken by: calling `dev->bus->get_irq(dev)` directly, which crashes on LPC carriers where `bus->get_irq` is `NULL`. [F24]
- `__mcb_bus_add_devices()` and `__mcb_devices_unregister()` must return `0` on non-error paths (in particular translating a positive `1` return from `device_attach()` to `0` in `__mcb_bus_add_devices()`) so that `bus_for_each_dev()` does not short-circuit before visiting all devices on `mcb_bus_type`. [F49]
- `mcb_match_id()` scans `mdrv->id_table` with `while (ids->device)`, so every `struct mcb_device_id` array registered via `struct mcb_driver.id_table` must be terminated by a sentinel element with `.device == 0`. [F45]

## Error Handling

- `chameleon_parse_cells()` does not unregister `mcb_device` instances that were already registered via `mcb_device_register()` before a later cell descriptor fails or `num_cells == 0`, so callers (`mcb_pci_probe()` and `mcb_lpc_probe()`) must call `mcb_release_bus(priv->bus)` on any error after `mcb_alloc_bus()` succeeds. [F6]
- `chameleon_parse_cells()` returns a negative errno on failure and the positive byte `table_size` on success; in `mcb_pci_probe()` and `mcb_lpc_probe()`, any failure after storing `ret = chameleon_parse_cells(...)` must reassign `ret` to a negative errno before jumping to `out_mcb_bus`. [F20]
- `chameleon_get_bar()` returns a negative errno without allocating `*cb` on failure and a positive `bar_count` with a heap-allocated `*cb` on success, so `chameleon_parse_cells()` must jump to `free_header` (not `free_bar`) when `bar_count < 0` and to `free_bar` on all subsequent errors. [F26]
- In `chameleon_parse_gdd()`, a cell whose BAR index exceeds `bar_count - 1`, whose `cb[mdev->bar].addr` is zero, or whose BAR address has bit 0 set (`dev_mapbase & 0x01`) is skipped by freeing `mdev` (`goto err;` -> `mcb_free_dev(mdev)`) and returning `0`, whereas negative return values are reserved for fatal errors that abort `chameleon_parse_cells()`. [F27]

## External Contracts

- `mcb_uevent()` must format the uevent modalias as `MODALIAS=mcb:16z%03d` using the 3-digit zero-padded decimal `mdev->id`, and `mcb_alloc_bus()` / `mcb_device_register()` must name bus and cell devices `mcb:%d` and `mcb%d-16z%03d-%d:%d:%d` respectively. [F46]
- All functions exported by `mcb-core.c` and `mcb-parse.c` use `EXPORT_SYMBOL_NS_GPL(..., "MCB")`, so any new exported MCB symbol must use the `"MCB"` GPL namespace and any module calling MCB APIs must declare `MODULE_IMPORT_NS("MCB")` and a GPL-compatible `MODULE_LICENSE`. [F74]

## Known Pitfalls

- Because `mcb_alloc_bus()` and `mcb_device_register()` both attach `dev.bus = &mcb_bus_type`, `bus_for_each_dev()` callbacks on `mcb_bus_type` (`__mcb_bus_add_devices()` and `__mcb_devices_unregister()`) visit both `struct mcb_bus` and `struct mcb_device` nodes and must check `dev->type == &mcb_carrier_device_type` before downcasting `dev` with `to_mcb_device()` or `to_mcb_bus()`. [F52]
- In `mcb_probe()`, `mcb_remove()`, and `mcb_shutdown()`, the bound `struct mcb_driver` must be retrieved via `to_mcb_driver(dev->driver)` rather than `mdev->driver`, because `struct mcb_device.driver` is never populated when binding a device to a driver. [F32]
