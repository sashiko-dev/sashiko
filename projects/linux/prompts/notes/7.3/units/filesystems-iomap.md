# FILESYSTEMS [IOMAP]

The iomap subsystem provides a generic extent-based file I/O framework for Linux filesystems, replacing legacy `buffer_head`-based block mapping. Filesystems supply extent mapping callbacks (`struct iomap_ops`) and iomap handles buffered reads/readahead, buffered writes, sub-folio block state tracking, writeback with bio chaining/ioend merging, direct I/O (sync and async), page faults (`page_mkwrite`), FIEMAP, lseek `SEEK_HOLE`/`SEEK_DATA`, and swapfile activation.

## Architecture & Data Flow
- In `struct iomap_folio_state`, `ifs->state` packs two `nr_blocks = i_blocks_per_folio(inode, folio)` bitmaps into one flexible array—uptodate bits at `[0, nr_blocks)` and dirty bits at `[nr_blocks, 2 * nr_blocks)`—sized in `ifs_alloc()` via `struct_size(ifs, state, BITS_TO_LONGS(2 * nr_blocks))`. Dirty-bit helpers must offset block indices by `nr_blocks`, while `ifs_is_fully_uptodate()` tests only `[0, nr_blocks)`. [F80, F129]
- In `struct iomap_ioend`, `struct bio io_bio` must remain the last member because `iomap_ioend_init()` initializes `iomap_ioend_bioset` with `front_pad = offsetof(struct iomap_ioend, io_bio)` and `BIOSET_NEED_BVECS`, placing the bio's inline `bio_vec` array immediately after `io_bio`. [F127]
- `dio->flags` stores both public `dops->end_io` flags (`IOMAP_DIO_UNWRITTEN`, `IOMAP_DIO_COW` in low bits) and private `IOMAP_DIO_*` flags (bits 25..31 in `fs/iomap/direct-io.c`), whereas `dio_flags` passed to `iomap_dio_rw()` uses a separate bit namespace (`IOMAP_DIO_FORCE_WAIT`, `IOMAP_DIO_OVERWRITE_ONLY`, `IOMAP_DIO_PARTIAL` in bits 0..2). Never overlap private flags with public ones or test `dio_flags` constants against `dio->flags`. [F54]
- In `iomap_dio_bio_iter()`, whenever `REQ_FUA` is not set on `bio_opf` for a write extent (`IOMAP_F_NEW`, not `IOMAP_MAPPED`, or cannot use `REQ_FUA`), `IOMAP_DIO_WRITE_THROUGH` must be cleared from `dio->flags` so `__iomap_dio_rw()` preserves `IOMAP_DIO_NEED_SYNC` for post-completion `generic_write_sync()`. [F71]
- `IOCB_HIPRI` must be cleared from `dio->iocb->ki_flags` whenever neither `IOMAP_DIO_INLINE_COMP` nor `IOMAP_DIO_CALLER_COMP` is set on `dio->flags`, whenever an extent requires a second bio (`nr_pages` remains non-zero in `iomap_dio_bio_iter()`), and after each `iomap_dio_iter()` call in `__iomap_dio_rw()`. [F73]
- In `__iomap_dio_rw()` and `iomap_dio_complete()`, direct I/O reads extending past `dio->i_size` must revert the `iov_iter` by `iomi.pos - dio->i_size` after submission and clamp the completed byte count `ret` to `dio->i_size - offset`. [F97]
- `iomap_alloc_ioend()` must reset `wpc->nr_folios = 0` so `wpc->nr_folios >= IOEND_BATCH_SIZE` in `iomap_can_add_to_ioend()` bounds only the current ioend. In `iomap_add_to_ioend()`, after adding `map_len` to `ioend->io_size`, clamp `ioend->io_size` so `ioend->io_offset + ioend->io_size <= end_pos` to keep EOF updates byte-accurate and stop chaining blocks onto an EOF-straddling ioend. [F75, F78]
- `iomap_ioend_can_merge()` must check physical sector contiguity via `ioend->io_sector + (ioend->io_size >> SECTOR_SHIFT) == next->io_sector` (not `io_bio.bi_iter.bi_sector`), and `iomap_ioend_try_merge()` must add `next->io_size` to `ioend->io_size`. `IOMAP_IOEND_BOUNDARY` is set only at `pos == wpc->iomap.offset` of an `IOMAP_F_BOUNDARY` mapping and must be tested only on the second/incoming ioend (never added to `IOMAP_IOEND_NOMERGE_FLAGS`). [F76, F110]
- In `iomap_zero_range()`, when the source mapping is `IOMAP_HOLE` or `IOMAP_UNWRITTEN` and `range_dirty` is true, `iomap_zero_iter_flush_and_stale()` must flush `[iter.pos, iter.pos + iter.len - 1]` and set `IOMAP_F_STALE` on `iter.iomap.flags` rather than advancing past the extent with `iomap_iter_advance_full()`. [F63]
- In `iomap_write_delalloc_release()`, the pagecache data scan upper bound `scan_end_byte` must be clamped to `min(i_size_read(inode), end_byte)` while the final punch still extends to `end_byte`, so dirty cached folios beyond EOF do not prevent punching out post-EOF delalloc blocks. In `iomap_last_written_block()`, a zero `written` count must use `round_down(pos, i_blocksize(inode))` instead of `round_up(pos + written, ...)`. [F86, F125]
- `iomap_file_unshare()`, `iomap_seek_hole()`, and `iomap_seek_data()` must reject start offsets where `pos < 0 || pos >= i_size_read(inode)` and clamp `iter.len` so `pos + iter.len` never exceeds `i_size_read(inode)`. [F85]

## Synchronization
- Modifications to the per-block dirty bitmap in `ifs->state` (`ifs_set_range_dirty()` and `ifs_clear_range_dirty()`) must hold `spin_lock_irqsave(&ifs->state_lock, flags)` because `ifs->state` packs uptodate and dirty bits into the same `unsigned long` bitmap array modified from IRQ bio completions. [F19]
- When a short copy occurs (`copied < len`) on a folio that is not already uptodate (`!folio_test_uptodate(folio)`), `__iomap_write_end()` must return `false` without calling `iomap_set_range_uptodate()` or `iomap_set_range_dirty()`. [F27]
- `iomap_page_mkwrite()` locks `folio = page_folio(vmf->page)`, must revalidate against truncation via `folio_mkwrite_check_truncate()` under `folio_lock()` before running `iomap_iter()`, and must return `VM_FAULT_LOCKED` with `folio` still locked after `folio_wait_stable(folio)` on success, or call `folio_unlock(folio)` on every error path. [F17, F36]
- `iomap_write_delalloc_release()` requires `inode->i_mapping->invalidate_lock` to be held in write mode by the caller, and its `iomap_punch_t` callback (`punch`) must never lock folios because `iomap_write_delalloc_scan()` invokes `punch` while holding `folio_lock()` on a folio that may not cover the punched range. [F138]
- For synchronous direct I/O (`dio->wait_for_completion`), `dio->submit.waiter` must be initialized to `current` before bio submission, cleared via `WRITE_ONCE(dio->submit.waiter, NULL)` in `iomap_dio_done()` before `blk_wake_io_task()`, and checked via `!READ_ONCE(dio->submit.waiter)` in a loop after `set_current_state(TASK_UNINTERRUPTIBLE)`. [F31]
- `iomap_finish_ioend_direct()` must never allow `iomap_dio_complete()` to run `kiocb_invalidate_post_direct_write()` inline on the ioend completion workqueue thread: it only sets `IOMAP_DIO_INLINE_COMP` together with `IOMAP_DIO_NO_INVALIDATE` when `!dio->iocb->ki_filp->f_mapping->nrpages`, and otherwise punts to `s_dio_done_wq`. [F143]
- `iomap_writepages()` rejects direct memory reclaim (`(current->flags & (PF_MEMALLOC | PF_KSWAPD)) == PF_MEMALLOC`) with `WARN_ON_ONCE` and `-EIO`, while permitting `kswapd` (`PF_KSWAPD`) and `PF_MEMALLOC_NOFS` contexts. Writeback ioend allocations in `iomap_alloc_ioend()` and splits in `iomap_split_ioend()` must use `GFP_NOFS` with `iomap_ioend_bioset`. [F139, F142]

## Object Lifetimes
- Callers of `iomap_iter()` must continue invoking `iomap_iter()` until it returns 0 or a negative error code rather than breaking or returning directly from the loop body, because `iomap_iter()` invokes `ops->iomap_end()` on the subsequent call when `iter->iomap.length` is non-zero. [F1]
- `ifs_free()` may only detach and free a `struct iomap_folio_state` when the folio is clean (or its dirty state has been cancelled via `folio_cancel_dirty()`), `ifs->read_bytes_pending` is 0, `ifs->write_bytes_pending` is 0, and `ifs_is_fully_uptodate()` matches `folio_test_uptodate()`. Broken by: calling `ifs_free()` on a dirty folio in `iomap_release_folio()`, on a partial-folio invalidation in `iomap_invalidate_folio()`, or while read/write bytes are pending. [F6]
- Because `struct iomap_ioend` is embedded in front of `io_bio` from `iomap_ioend_bioset`, `bio_put(&ioend->io_bio)` frees `ioend`; all `ioend` fields (including `ioend->io_list` in `iomap_finish_ioends()`) must be read or detached first. When `iomap_split_ioend()` splits a child `split_ioend` (`split_ioend->io_parent = ioend`, incrementing `ioend->io_remaining`), `iomap_finish_ioend()` must free the child via `bio_put()` and only complete the parent when `atomic_dec_and_test(&ioend->io_remaining)` is true. [F10, F11]
- When `wpc->wb_ctx` is non-NULL in `iomap_writepages()`, `wpc->ops->writeback_submit(wpc, error)` must always be called even when `error` is non-zero, and `iomap_ioend_writeback_submit()` must complete a failed `ioend` via `bio_endio(&ioend->io_bio)` (not `bio_put()`) so writeback state on attached folios is ended. [F9]
- `__iomap_dio_rw()` sets `dio->ref = 1`, increments `dio->ref` in `iomap_dio_submit_bio()` before each bio submission, and must finish setting `dio->wait_for_completion`, `dio->flags`, and `dio->error` before `atomic_dec_and_test(&dio->ref)`, never dereferencing `dio` afterward when `!wait_for_completion`. `iomap_dio_bio_end_io()` and `iomap_finish_ioend_direct()` must also cache `dio->flags & IOMAP_DIO_DIRTY` and call `iomap_dio_set_error()` before `atomic_dec_and_test(&dio->ref)`. [F30, F33]
- In `struct iomap_dio`, `submit` (`iter` and `waiter`) and `aio` (`work`) share an anonymous union, so `dio->aio.work` must only be initialized or accessed in `iomap_dio_done()` after `atomic_dec_and_test(&dio->ref)` drops the last reference and when `!dio->wait_for_completion`. [F132]
- In `iomap_dio_complete()`, `dops->end_io()` must be invoked before `kiocb_invalidate_post_direct_write()`, and `inode_dio_end()` and `kfree(dio)` must be executed on every completion path. [F14]

## API Contracts
- Whenever `iomap_write_ops->get_folio` (or `iomap_get_folio()` via `__iomap_get_folio()`) succeeds, `__iomap_put_folio()` must be called on every exit path, and custom `iomap_write_ops->put_folio` implementations must both `folio_unlock(folio)` and `folio_put(folio)`. [F2]
- `iomap_write_delalloc_release()` and its helpers (`iomap_write_delalloc_scan()`, `iomap_write_delalloc_punch()`, `iomap_write_delalloc_ifs_punch()`) take half-open byte intervals `[start_byte, end_byte)`, whereas `iomap_punch_t` takes `(inode, offset, length, iomap)` and VFS range helpers (`filemap_write_and_wait_range()`, `filemap_range_needs_writeback()`, `truncate_pagecache_range()`) take inclusive end offsets (`start + len - 1`). [F56]
- In `struct iomap`, `addr`, `offset`, and `length` are in bytes, and `iomap_sector()` converts `pos` to a sector unless `IOMAP_F_ANON_WRITE` is set. Every `ops->iomap_begin()` mapping must satisfy `iomap.offset <= iter->pos`, `iomap.length > 0`, and `iomap.offset + iomap.length > iter->pos`; when `iter->srcmap.type != IOMAP_HOLE`, `iomap_length_trim()` clamps to the earlier end of `iomap` and `srcmap`. [F89, F149]
- `__iomap_dio_rw()` returns `NULL` when no I/O was performed (`!iomi.len` or a read at/beyond `i_size`), `ERR_PTR(-EIOCBQUEUED)` when async I/O is in flight, `ERR_PTR(ret)` on setup failure, or a valid `struct iomap_dio *` that the caller must pass to `iomap_dio_complete()`. Broken by: checking only `IS_ERR(dio)` and passing `NULL` to `iomap_dio_complete()`. [F40]
- `iomap_init_ioend()` and `iomap_ioend_from_bio()` downcast `struct bio *` via `container_of(bio, struct iomap_ioend, io_bio)`, so any caller (including `iomap_dio_ops::submit_io`) must allocate the bio from `iomap_ioend_bioset` (`.bio_set = &iomap_ioend_bioset`). If `submit_io` overrides `bio->bi_end_io`, its handler must finish via `iomap_dio_bio_end_io(bio)` (or `iomap_finish_ioend_direct()`), never `bio_put()`. [F128, F152]
- `iomap_finish_ioends()` may only be called from sleepable task context (never from a bio `bi_end_io` or atomic context), because it calls `might_sleep()` and `cond_resched()` after every `IOEND_BATCH_SIZE * 8` completions. [F141]
- Range tracepoints defined with `DEFINE_RANGE_EVENT` (`trace_iomap_writeback_folio`, `trace_iomap_release_folio`, `trace_iomap_invalidate_folio`, `trace_iomap_dio_invalidate_fail`, `trace_iomap_dio_rw_queued`, `trace_iomap_zero_iter`) require a file byte offset (`folio_pos(folio) + offset`), not a folio-relative byte offset. [F53]
- Writeback bios in `iomap_alloc_ioend()` must call `wbc_init_bio(wpc->wbc, bio)` and each folio range in `iomap_add_to_ioend()` must call `wbc_account_cgroup_owner(wpc->wbc, folio, map_len)`, while direct writes in `iomap_dio_bio_iter()` must call `task_io_account_write(n)`. `iomap_bmap()` must return `0` (never a negative errno) on failure or non-`IOMAP_MAPPED` extents. [F42, F171]

## Error Handling
- Recording an error into `dio->error` (via `iomap_dio_set_error()`) or `ioend->io_error` (in `iomap_finish_ioend()`) must use `cmpxchg(..., 0, error)` so concurrent completions or subsequent errors do not overwrite the first non-zero error code. [F49]
- In `__iomap_dio_rw()`, `-ENOTBLK` (and `-EFAULT` when `dio->size > 0` and `dio_flags & IOMAP_DIO_PARTIAL`) must be cleared to `0` before `iomap_dio_set_error(dio, ret)` and must force `wait_for_completion = true` (unless `IOCB_NOWAIT` on `-EFAULT`) so already-submitted bios complete cleanly without failing the partial transfer. [F51]
- Runtime I/O failures in `iomap_finish_ioend_buffered()` and user-triggerable DIO/mmap collisions on `IOMAP_DELALLOC` in `iomap_dio_iter()` must log with ratelimited printk (`pr_err_ratelimited` / `pr_warn_ratelimited`) and never `WARN_ON*`, whereas kernel contract violations (such as `IOMAP_HOLE` on a DIO write) use `WARN_ON_ONCE`. [F172]

## External Contracts
- `iomap_swapfile_activate()` and `iomap_swapfile_add_extent()` must sync via `vfs_fsync(swap_file, 1)`, require `IOMAP_MAPPED` or `IOMAP_UNWRITTEN` extents on `sis->bdev` without `IOMAP_F_DIRTY` or `IOMAP_F_SHARED`, align physical start up and end down to `PAGE_SIZE` (skipping `first_ppage >= next_ppage`), and cap `nr_pages` to `isi->sis->max - isi->nr_pages` before `add_swap_extent()`. Page 0 (swap header) is passed to `add_swap_extent()` and counted in `sis->max = isi.nr_pages`, but excluded from `isi->lowest_ppage` and `sis->pages = isi.nr_pages - 1`. [F98, F99, F169]
- In `iomap_fiemap()` and `iomap_to_fiemap()`, each non-hole extent is held in `prev` so the final extent is reported with `FIEMAP_EXTENT_LAST` after the `iomap_iter()` loop ends, `IOMAP_NULL_ADDR` is translated to physical offset 0 for `fiemap_fill_next_extent()`, and `-ENOENT` from `iomap_iter()` is converted to 0. [F170]

## Known Pitfalls
- When `write_ops->iomap_valid()` returns false in `iomap_write_begin()`, `iomap_write_begin()` releases the folio via `__iomap_put_folio()`, sets `IOMAP_F_STALE` on `iter->iomap.flags`, and returns 0 without initializing `*foliop`, so callers must check `iter->iomap.flags & IOMAP_F_STALE` before using `folio` or calling `__iomap_put_folio()`. [F3]
- `iomap_want_unshare_iter()` must check `(iter->iomap.flags & IOMAP_F_SHARED) && iter->srcmap.type == IOMAP_MAPPED` using `iter->srcmap` directly rather than `iomap_iter_srcmap(iter)`, because `iomap_iter_srcmap()` falls back to `&iter->iomap` when `iter->srcmap.type == IOMAP_HOLE`. [F117]
- In `iomap_write_iter()`, `bytes = iov_iter_count(i)` must be initialized before the `retry:` label so that when a short copy (`written == 0` with `copied > 0`) sets `bytes = copied` and jumps to `retry:`, the narrowed `bytes` limit is preserved rather than reset to `iov_iter_count(i)`. [F102]
- Clamping 64-bit extent or file lengths against folio-sized quantities must use 64-bit comparisons before narrowing: `iomap_add_to_ioend()` must clamp `dirty_len` to `wpc->iomap.offset + wpc->iomap.length - pos` via `min_t(u64, ...)` before narrowing to `unsigned int map_len`, and `iomap_adjust_read_range()` must clamp `folio_size(folio) - poff` against `loff_t length` via `min_t(loff_t, ...)` before assigning to `size_t plen`. [F121, F122]
