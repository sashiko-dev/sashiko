# MULTIMEDIA CARD (MMC), SECURE DIGITAL (SD) AND SDIO SUBSYSTEM

`drivers/mmc/host` contains MMC/SD/SDIO host controller drivers (Alcor AU6601/AU6621, Broadcom BCM2835 SDHost, TI DaVinci, STM32 SDMMC MMCI variant, MOXA ART, Freescale i.MX2/3/MPC512x and MXS, Marvell PXA, Realtek PCIe/USB card readers, and Renesas SuperH MMCIF) and the MMC Host Software Queue (HSQ) implementation, bridging `struct mmc_host_ops` and `struct mmc_cqe_ops` to SoC MMIO controllers, DMA engines, PCI/USB bridges, clocks, regulators, and GPIOs.

## Architecture & Data Flow

- In `moxart-mmc.c`, `mxcmmc.c`, `mxs-mmc.c`, and `pxamci.c`, device drvdata stores `struct mmc_host *` (requiring `mmc_priv()` to get the driver host struct), whereas `alcor.c`, `bcm2835.c`, `davinci_mmc.c`, `rtsx_pci_sdmmc.c`, `rtsx_usb_sdmmc.c`, and `sh_mmcif.c` store the driver's private host struct directly. [F130]
- In `mmci_stm32_sdmmc.c`, `sdmmc_idma_validate_data()` sets `idma->use_bounce_buffer` when any scatterlist entry has unaligned offset or (for non-final entries) unaligned length (`for_each_sg(data->sg, sg, data->sg_len - 1, i)` checks the cursor `sg`, and the post-loop check must inspect `sg->offset` on the advanced cursor `sg`, not `data->sg`). `_sdmmc_idma_prep_data()`, `sdmmc_idma_unprep_data()`, and `sdmmc_idma_error()` must only call `dma_map_sg()` or `dma_unmap_sg()` when `!idma->use_bounce_buffer`. [F53, F97]
- In `mmci_stm32_sdmmc.c`, when `sdmmc_busy_complete()` enables `host->variant->busy_detect_mask` in `MMCIMASK0` because `MCI_STM32_BUSYD0` is active, it must record `host->busy_status`, later clear both `host->variant->busy_detect_mask` in `MMCIMASK0` and `host->busy_status = 0` on completion or error, and write `host->variant->busy_detect_mask` to `MMCICLEAR` unconditionally at `complete:` even when `host->busy_status` is `0`. [F64, F148]
- In `bcm2835.c`, all modifications to `SDHCFG` and `SDCDIV` must be mirrored in `host->hcfg` and `host->cdiv`, because `bcm2835_reset_internal()` zeroes both registers, resets `host->clock = 0`, and restores `SDHCFG` and `SDCDIV` from `host->hcfg` and `host->cdiv`. [F59]
- In `davinci_mmc.c`, EDMA in `mmc_davinci_start_dma_transfer()` may only be used when both `host->bytes_left` and every `sg_dma_len(data->sg + i)` are multiples of `rw_threshold` (otherwise unmapping and falling back to PIO), and starting DMA in `mmc_davinci_prepare_data()` must set both `host->do_dma = 1` and `host->bytes_left = 0` so `mmc_davinci_irq()` skips the PIO loop. [F68, F89]
- In `mxcmmc.c`, `host->do_dma` is reset to `1` per request in `mxcmci_request()` when `host->dma` is non-NULL and cleared to `0` in `mxcmci_setup_data()` if any SG segment has `sg->offset & 3`, `sg->length & 3`, or `sg->length < 512` (permanently disabling DMA in `mxcmci_set_ios()` requires setting both `host->do_dma = 0` and `host->dma = NULL`). `mxcmci_irq()` must mask out `STATUS_SDIO_INT_ACTIVE | STATUS_DATA_TRANS_DONE | STATUS_WRITE_OP_DONE` on its initial write to `MMC_REG_STATUS`, and only clear `STATUS_WRITE_OP_DONE` when `mxcmci_use_dma(host)` is true so PIO writes in `mxcmci_transfer_data()` can poll it. [F69, F93, F112]
- In `rtsx_pci_sdmmc.c`, `sd_pre_dma_transfer()` pairs pre-mapped scatterlists via `data->host_cookie` and `host->cookie`; `sd_request()` must call `sdmmc_post_req()` itself only when `!host->using_cookie`, and `rtsx_pci_sdmmc_card_event()` must reset `host->cookie = -1`. [F77]
- In `mmc_hsq`, `hsq->slot` and `hsq->tag_slot` have `HSQ_NUM_SLOTS` (64) elements, and `HSQ_INVALID_TAG` (`HSQ_NUM_SLOTS`) must be checked before indexing with `next_tag` or `tail_tag`. While `hsq->recovery_halt` is set between `mmc_hsq_recovery_start()` and `mmc_hsq_recovery_finish()`, `mmc_hsq_request()` must return `-EBUSY`, `mmc_hsq_pump_requests()` and `mmc_hsq_post_request()` must not dispatch slots, and `mmc_hsq_queue_is_idle()` must return `true` with `*ret = -EBUSY`. [F84, F175]

## Synchronization

- In `mmc_hsq.c`, `mmc_hsq_pump_requests()`, `mmc_hsq_post_request()`, `mmc_hsq_finalize_request()`, and `mmc_hsq_recovery_start()` must use `spin_lock_irqsave(&hsq->lock, flags)`. `mmc_hsq_finalize_request()` must clear `hsq->slot[hsq->next_tag].mrq` under `hsq->lock` and drop `hsq->lock` before calling `mmc_cqe_request_done()`, leaving `hsq->mrq` and `hsq->next_tag` unchanged until `mmc_hsq_post_request()`. `mmc_hsq_pump_requests()` must drop `hsq->lock` before calling `mmc->ops->request_atomic()` or `mmc->ops->request()`, deferring `-EBUSY` retries to `hsq->retry_work`. [F24, F159, F160]
- In `mmci_stm32_sdmmc.c`, `sdmmc_post_sig_volt_switch()` must hold `host->lock` via `spin_lock_irqsave()` when reading `host->pwr_reg` or calling `mmci_write_pwrreg()`, and drop `host->lock` around `readl_relaxed_poll_timeout()` on `MCI_STM32_VSWEND`. Writes to coherent DMA memory (`idma->bounce_buf` in `_sdmmc_idma_prep_data()` and `struct sdmmc_lli_desc` in `sdmmc_idma_start()`) must be followed by `dma_wmb()` before starting IDMA via `writel_relaxed()`. [F25, F26]
- In `alcor.c`, callers of `alcor_request_complete()` holding `host->cmd_mutex` must use asynchronous `cancel_delayed_work(&host->timeout_work)` (never `cancel_delayed_work_sync()`), and `alcor_request_complete()` and `alcor_timeout_timer()` must check `host->mrq` under `host->cmd_mutex`. Similarly, in `bcm2835.c`, `bcm2835_finish_request()` must use asynchronous `cancel_delayed_work(&host->timeout_work)` because `bcm2835_timeout()` calls it from within `timeout_work`. [F29, F157]
- In `bcm2835.c`, `host->irq_block`, `host->irq_busy`, and `host->irq_data` are protected by `host->lock` between `bcm2835_irq()` and `bcm2835_threaded_irq()`, and `bcm2835_threaded_irq()` must release `host->lock` before acquiring `host->mutex`. `bcm2835_dma_complete()` must defer completion to `host->dma_work` (`bcm2835_dma_complete_work()`), which acquires `host->mutex` and maps `host->drain_page`. [F30, F162]
- Because `mmc_signal_sdio_irq()` synchronously calls `host->ops->enable_sdio_irq(host, 0)` which acquires `host->lock`, callers in `mxcmci_irq()`, `mxs_mmc_irq_handler()`, and `mxs_mmc_enable_sdio_irq()` must release `host->lock` before calling `mmc_signal_sdio_irq()`. In `mxcmmc.c`, every rewrite of `MMC_REG_INT_CNTR` must hold `host->lock` and preserve `INT_SDIO_IRQ_EN` when `host->use_sdio` is set (plus `host->default_irq_mask` in `mxcmci_finish_request()`). [F71, F178]
- `sg_miter_start()` must include `SG_MITER_ATOMIC` in `alcor_prepare_sg_miter()`, `bcm2835_prepare_data()`, and `mmc_davinci_prepare_data()` because `sg_miter_next()` runs in hard IRQ context, whereas `sh_mmcif_single_read()`, `sh_mmcif_multi_read()`, `sh_mmcif_single_write()`, and `sh_mmcif_multi_write()` must omit `SG_MITER_ATOMIC` because iteration runs in threaded IRQ `sh_mmcif_irqt()`. [F155, F156]
- To avoid sleeping or deadlocking in atomic/I/O contexts: in `mxcmmc.c`, `mxcmci_cmd_done()` must defer PIO transfers to `host->datawork` (`mxcmci_datawork()`); in `rtsx_usb_sdmmc.c`, `rtsx_usb_led_control()` must defer USB/mutex work to `host->led_work` (`rtsx_usb_update_led()`); and in `rtsx_pci_sdmmc.c` and `rtsx_usb_sdmmc.c`, `sd_normal_rw()` must allocate its bounce buffer with `GFP_NOIO`. [F163, F168, F169]

## Object Lifetimes

- Across `drivers/mmc/host`, `spin_lock_init(&host->lock)` must execute before registering the IRQ handler with `devm_request_irq()` or `request_irq()`, and platform `.remove` callbacks (such as `davinci_mmcsd_remove`) must not be marked `__exit` or wrapped with `__exit_p()`. [F27, F132]
- In `mmci_stm32_sdmmc.c`, when a transfer error occurs while `dma_inprogress(host)` is true, `sdmmc_idma_error()` must disable `MMCI_STM32_IDMACTRLR`, clear `host->dma_in_progress = false` and `data->host_cookie = 0`, and call `dma_unmap_sg()` if `!idma->use_bounce_buffer`. `sdmmc_idma_finalize()` must only call `sdmmc_idma_unprep_data()` when `!data->host_cookie`, leaving pre-mapped requests (`data->host_cookie != 0`) to `.unprep_data`. [F1, F2]
- In `bcm2835.c`, `bcm2835_prepare_dma()` must unmap `data->sg` if `dmaengine_prep_slave_sg()` fails and only set `host->dma_chan` on success, while `bcm2835_dma_complete_work()`, `bcm2835_finish_request()`, and `bcm2835_reset()` must clear `host->dma_chan = NULL` when unmapping or terminating DMA. In `mxs-mmc.c`, when `host->data` is non-NULL, `mxs_mmc_prep_dma()` must call `dma_unmap_sg()` on `dmaengine_prep_slave_sg()` failure, and `mxs_mmc_request_done()` must call `dma_unmap_sg()` and clear `host->data = NULL` before starting `data->stop` or completing `host->mrq`. [F6, F13]
- In `davinci_mmc.c` and `sh_mmcif.c`, any started `host->sg_miter` must be stopped with `sg_miter_stop(&host->sg_miter)` on all paths: in `mmc_davinci_irq()` on both `MMCST0_DATDNE` and error abort (`davinci_abort_data()`), and in every `sh_mmcif` PIO setup/block handler on `host->sd_error`, `!sg_miter_next()`, or block completion. [F9, F22]
- In `sh_mmcif.c` and `moxart-mmc.c`, TX and RX DMA channels are all-or-nothing pairs: if requesting, configuring, or preparing either channel fails (except `-EPROBE_DEFER` in `moxart_probe()`), both channels must be released and set to `NULL` (and `BUF_ACC_DMAREN | BUF_ACC_DMAWEN` cleared in `sh_mmcif`). [F10, F72]
- In `sh_mmcif.c`, `sh_mmcif_probe()` drops its initial `pm_runtime_get_sync()` and `clk_prepare_enable()` references after `mmc_add_host()`, so `sh_mmcif_set_ios()` must gate clock, runtime PM, and DMA acquisition on `!host->power` (`MMC_POWER_UP`) and release on `host->power` (`MMC_POWER_OFF`), and `sh_mmcif_remove()` must set `host->dying = true` and re-acquire `host->clk` and runtime PM before `mmc_remove_host()`, writing `MMCIF_CE_INT_MASK`, and cancelling `timeout_work`. [F21, F134]
- In `rtsx_pci_sdmmc.c` and `rtsx_usb_sdmmc.c`, if `mmc_add_host()` fails in probe, `rtsx_pci_sdmmc_drv_probe()` must call `pm_runtime_dont_use_autosuspend()` and `pm_runtime_disable()`, while `rtsx_usb_sdmmc_drv_probe()` must unregister `host->led` and disable runtime PM. In `rtsx_usb_sdmmc.c`, `sd_set_power_mode()` must return early when `power_mode == host->power_mode` to keep runtime PM balanced, `rtsx_usb_update_led()` must pair `pm_runtime_get_noresume()` with `pm_runtime_put_sync_suspend()` on all paths, and `rtsx_usb_sdmmc_drv_remove()` must set `host->host_removal = true` and `cancel_work_sync(&host->led_work)` before `led_classdev_unregister(&host->led)`. [F17, F18, F19]

## API Contracts

- Across `drivers/mmc/host` (`bcm2835`, `davinci_mmc`, `moxart-mmc`, `pxamci`, `sh_mmcif`), `dma_unmap_sg()` must be passed the original scatterlist entry count `data->sg_len`, never the coalesced segment count returned by `dma_map_sg()`. [F39]
- Because `sg_miter_next()` initializes `sgm->consumed` to `sgm->length`, PIO transfer functions (`alcor_trf_block_pio()`, `bcm2835_transfer_block_pio()`, `davinci_fifo_data_trans()`, `sh_mmcif_mread_block()`, `sh_mmcif_mwrite_block()`) must clamp the byte count to `sgm->length` and overwrite `sgm->consumed` with the transferred count rather than adding to it with `+=`. In `sh_mmcif_multi_read()` and `sh_mmcif_multi_write()`, `sg_miter_next()` must be called once before enabling buffer IRQs and then right after each block transfer in `sh_mmcif_mread_block()` / `sh_mmcif_mwrite_block()`. [F82, F99, F100]
- When `vmmc` is acquired via `mmc_regulator_get_supply()` (`pxamci`, `mxcmmc`, `sh_mmcif`), `mmc->supply.vmmc` holds `ERR_PTR(-ENODEV)` when absent, so callers must check `!IS_ERR(mmc->supply.vmmc)` (not `if (mmc->supply.vmmc)`). Because `ios->vdd` is a 0-based bit number while `ocr_mask` is a bitmask, `mmc_regulator_set_ocr()` takes `vdd` (or `0` on power-off), whereas testing `pdata->ocr_mask` in `pxamci_set_power()` requires `1 << vdd`. [F47, F180]
- In `mmc_hsq.c`, `mmc_hsq_init()` stores `struct mmc_hsq *` in `mmc->cqe_private` (not `mmc_priv(mmc)`). `mmc_hsq_finalize_request()` returns `true` and calls `mmc_cqe_request_done()` only when `hsq->enabled` is true and `mrq == hsq->mrq`; when it returns `false`, the caller must complete `mrq` via its non-HSQ path. [F51, F131]
- In `alcor_init_mmc()`, `mmc->max_blk_count` must be set in blocks (and `mmc->max_req_size` to `mmc->max_blk_count * mmc->max_blk_size`) rather than `mmc->max_segs`, and `alcor_pre_req()` may only set `COOKIE_MAPPED` when every SG entry has `sg->length == AU6601_MAX_DMA_BLOCK_SIZE` and `sg->offset == 0`. [F87, F176]

## Error Handling

- In probe functions: `platform_get_irq(pdev, 0)` errors (`< 0`) must be propagated directly without overwriting the errno, optional secondary IRQs must use `platform_get_irq_optional(pdev, 1)`, and `moxart_probe()` using `irq_of_parse_and_map()` must check `irq <= 0`. For `dma_request_chan()` (`bcm2835`, `davinci_mmc`, `moxart`, `mxcmmc`), `-EPROBE_DEFER` must abort probe and be propagated, while other errors fall back to PIO. For `mmc_gpiod_request_cd()` and `mmc_gpiod_request_ro()` (`pxamci`, `davinci_mmc`), `-ENOENT` means the optional GPIO is absent (not a fatal error, and `host->use_ro_gpio` must stay false), while other negative errnos abort probe. [F41, F57, F186, F187]
- Stack-allocated `struct dma_slave_config` instances passed to `dmaengine_slave_config()` (`moxart_probe()`, `pxamci_setup_data()`, `sh_mmcif_dma_slave_config()`) must be zero-initialized before setting fields. In resume callbacks (`davinci_mmcsd_resume()`, `mxcmci_resume()`, `bcm2835_resume()`, `mxs_mmc_resume()`), `clk_enable()` / `clk_prepare_enable()` return values must be checked before accessing MMIO registers, with `mxcmci_resume()` disabling `clk_per` if `clk_ipg` fails. [F43, F44]
- In `mmci_stm32_sdmmc.c`, `host->variant_priv` (`struct sdmmc_dlyb *`) is NULL when the delay block DT region is absent, and `dlyb->ops->set_input_ck` is NULL on `st,stm32mp25-sdmmc2`, so both pointers must be checked before calling `dlyb->ops->set_input_ck(dlyb)` in `mmci_sdmmc_set_pwrreg()` and `sdmmc_dlyb_phase_tuning()`. [F52]
- Hardware CRC status bits must not be reported as `-EILSEQ` when the response has no valid CRC (`MMC_SEND_OP_COND` in `bcm2835_finish_command()`, commands without `MMC_RSP_CRC` in `mxcmci_read_response()` and `pxamci_cmd_done()`, and 136-bit responses with MSB set on PXA27x in `pxamci_cmd_done()`). On write CRC errors (`MMCST0_CRCWR` in `mmc_davinci_irq()` or `STATUS_CRC_WRITE_ERR` in `mxcmci_finish_data()`), the hardware CRC status (`DAVINCI_MMCDRSP == 0x9f` or `((stat >> 9) & 0x3) == 2`) must be checked to report write timeouts as `-ETIMEDOUT` instead of `-EILSEQ`. [F188, F189]

## Known Pitfalls

- In `bcm2835_prepare_dma()`, multi-block reads (`data->blocks > 1 && dir_data == DMA_FROM_DEVICE`) must trim `min((u32)(FIFO_READ_THRESHOLD - 1) * 4, (u32)data->blocks * data->blksz)` bytes from the final SG entry before `dma_map_sg()`, and `bcm2835_dma_complete_work()` must normalize `host->drain_page` by `host->drain_offset >> PAGE_SHIFT` and mask `host->drain_offset` with `~PAGE_MASK` before `kmap_local_page()` to drain those words from `SDDATA`. [F88, F145]
- In `mmci_stm32_sdmmc.c`, `sdmmc_dlyb_phase_tuning()` must call `dlyb->ops->set_input_ck(dlyb)` after the `mmc_send_tuning()` loop and before the final `dlyb->ops->set_cfg()` so `DLYB_CR` is cleared to `0` first. [F147]
- In `alcor.c`, `alcor_prepare_data()` must clear `AU6601_DATA_XFER_CTRL` to `0`, and `alcor_trigger_data_transfer()` must only be called after `AU6601_INT_CMD_END` (and after `AU6601_INT_DATA_END` for subsequent PIO blocks), never before command completion. In `sh_mmcif.c`, `MMCIF_CE_INT` is write-0-to-clear, so `sh_mmcif_intr()` must write `~(state & mask)` when `host->ccs_enable` is true or `INT_CCS | ~(state & mask)` when false. [F144, F152]
- In `mxcmmc.c`, all register accesses must use `mxcmci_readl()`, `mxcmci_writel()`, `mxcmci_readw()`, and `mxcmci_writew()` (for `CONFIG_PPC_MPC512x` 32-bit big-endian I/O). In `moxart-mmc.c`, `moxart_transfer_pio()` must read `REG_DATA_WINDOW` with native-endian `ioread32()` for all commands (never `ioread32be()`). In `mxs-mmc.c`, `BM_SSP_CMD0_APPEND_8CYC` for `MMC_STOP_TRANSMISSION` must be applied in `mxs_mmc_ac()` rather than `mxs_mmc_adtc()`. [F83, F103, F150]
