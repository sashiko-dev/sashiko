# ASUS NOTEBOOKS AND EEEPC ACPI/WMI EXTRAS DRIVERS

This component provides x86 platform drivers for ASUS notebooks, gaming laptops (ROG/TUF), handhelds (ROG Ally), and Eee PCs using legacy ACPI (`asus-laptop.c`, `eeepc-laptop.c`) and ACPI-WMI (`asus-wmi.c`, `asus-nb-wmi.c`, `eeepc-wmi.c`) interfaces to manage hotkeys, backlights, LEDs, rfkill/PCI hotplug, hwmon fan controls/curves, platform profiles, battery thresholds, and ROG tunables.

## Architecture & Data Flow
- `asus->custom_fan_curves[3]` is indexed by `FAN_CURVE_DEV_CPU` (0x00), `FAN_CURVE_DEV_GPU` (0x01), and `FAN_CURVE_DEV_MID` (0x02), which `fan_curve_attr_2_select()` must extract with `nr & ~FAN_CURVE_PWM_MASK` (not `nr & FAN_CURVE_DEV_GPU` or raw `nr`). Because `asus_fan_curve_attr` mixes `sensor_device_attribute` and `sensor_device_attribute_2`, `asus_fan_curve_is_visible()` must not downcast `attr` and instead checks `attr->name[3]` (`'1'`..`'3'`). [F62, F96]
- Updating fan curve points (`fan_curve_store()`), fan mode (`pwm1_enable_store()`), or thermal policy (`throttle_thermal_policy_write()`) must set `custom_fan_curves[...].enabled = false`, and disabling a curve in `fan_curve_enable_store()` must reset fans via `throttle_thermal_policy_write()` or `asus_fan_set_auto()`. [F123]
- For `FAN_TYPE_AGFN` fans, `pwm1_store()` sets `asus->fan_pwm_mode = ASUS_FAN_CTRL_MANUAL` and `asus_agfn_fan_speed_write()` caches `asus->agfn_pwm`; while `fan_pwm_mode == ASUS_FAN_CTRL_MANUAL`, `fan1_input_show()` must return `-ENXIO` without calling `asus_agfn_fan_speed_read()`. [F60]
- `kbd_led_set()` must return without calling `do_kbd_led_set()` when `led_cdev->flags & LED_UNREGISTERING` is set, and `kbd_led_update()` must preserve `asus->kbd_led_wk` (ORed with `0x80`) for `asus_hotk_resume()` / `asus_hotk_restore()`. When `asus->oobe_state_available` is true, both `asus_wmi_led_init()` and `asus_hotk_restore()` must call `asus_wmi_set_devstate(ASUS_WMI_DEVID_OOBE, 1, NULL)`. [F52, F53]
- `kbd_rgb_mode_groups` is a 3-element array (`{ NULL, NULL, NULL }`) populated via `num_rgb_groups++` in `asus_wmi_led_init()`, so at most two groups can be added without resizing it to preserve the `NULL` sentinel. [F65]
- In `asus_i8042_filter()` (`asus-nb-wmi.c`), packets with `str & I8042_STR_AUXDATA` must return `false` immediately before touching `extended_e0`/`extended_e1`, and any byte after `0xe0`/`0xe1` must reset the flag; `0xe0`-prefixed volume scancodes (`0x20`, `0x2e`, `0x30`) set `atkbd_reports_vol_keys = true`, making `asus_nb_wmi_key_filter()` ignore WMI volume codes `0x30`–`0x32` (`ASUS_WMI_KEY_IGNORE`), while wireless console codes `0x5D`, `0x5E`, and `0x5F` must all fall through to `quirks->key_wlan_event`. [F59, F75, F88]
- In `eeepc-laptop.c`, `set_acpi()`, `get_acpi()`, and `acpi_setter_handle()` index `cm_setv[cm]` / `cm_getv[cm]` and test `eeepc->cm_supported & (0x1 << cm)` unchecked, so `CM_ASL_*` must be in `0..31` in both arrays; `get_cpufv()` must reject `c->num == 0 || c->num > 12`, and `cpufv_store()` must reject `value < 0 || value >= c.num`. [F69, F70]

## Synchronization
- Non-blocking `.brightness_set` LED callbacks (`tpd_led_set`, `wlan_led_set`, `lightbar_led_set` in `asus-wmi.c`; `asus_led_cdev_set`, `asus_kled_cdev_set` in `asus-laptop.c`; `tpd_led_set` in `eeepc-laptop.c`) must only record target state and queue work on `led_workqueue` rather than evaluating WMI/ACPI methods synchronously. [F128, F129]
- `asus_rfkill_notify` (`asus-wmi.c`) must defer `asus_rfkill_hotplug()` to `asus->hotplug_workqueue` via `asus->hotplug_work`, and both `asus_rfkill_wlan_set()` and `asus_rfkill_hotplug()` must serialize WMI devstate evaluations under `asus->wmi_lock`. [F130]
- `asus_i8042_filter` (`asus-nb-wmi.c`) runs in `i8042` serio interrupt context, so it must not sleep, take mutexes, or invoke ACPI/WMI methods. [F134]

## Object Lifetimes
- Every `wmi_evaluate_method()` call in `asus-wmi.c` that passes `struct acpi_buffer output = { ACPI_ALLOCATE_BUFFER, NULL }` takes ownership of `output.pointer` on success and must free it with `kfree()` before returning. [F1]
- In `asus_wmi_add()`, `asus_wmi_platform_init()` must run after `wdrv->detect_quirks()` and before any `asus_wmi_get_devstate()`/`asus_wmi_dev_is_present()` call (to set `asus->dsts_id`); `asus->throttle_thermal_policy_dev`, `platform_profile_setup()`, and `asus_wmi_fan_init()` must precede `asus_wmi_custom_fan_curve_init()`; and quirks, input, LED, backlight, thermal/fan state, and `fnlock_locked` must be initialized before `wmi_install_notify_handler()` and `i8042_install_filter()`. [F21, F103, F104]
- `asus_wmi_remove()` must remove `asus->driver->i8042_filter` and `wmi_remove_notify_handler(asus->driver->event_guid)` before tearing down backlight, input, or LEDs or freeing `asus`, and must call `throttle_thermal_policy_set_default()` (also called by `platform_profile_setup()` before `devm_platform_profile_register()`) and `asus_fan_set_auto()`. [F22, F105]
- `asus_wmi_rfkill_init()` must initialize `hotplug_lock`, `wmi_lock`, `hotplug_workqueue`, and `hotplug_work` (via `asus_setup_pci_hotplug()`) before `asus_register_rfkill_notifier()`. In `asus_wmi_rfkill_exit()`, rfkill notifiers must be unregistered and `asus->wlan.rfkill` unregistered, destroyed, and set to `NULL` before `asus_rfkill_hotplug(asus)` runs, and `asus_rfkill_hotplug(asus)` and `pci_hp_deregister()` must precede `destroy_workqueue(asus->hotplug_workqueue)`. [F6, F17]
- In `asus_setup_pci_hotplug()` and `eeepc_setup_pci_hotplug()`, callers must clear `-EBUSY` from `pci_hp_register()` to `0`, and on any `pci_hp_register()` failure `hotplug_slot.ops` must be reset to `NULL` (and `asus->hotplug_workqueue` destroyed) because hotplug and exit paths check `hotplug_slot.ops` before acting or calling `pci_hp_deregister()`. In `asus_new_rfkill()`, `asus_rfkill_setup()`, and `eeepc_new_rfkill()`, if `rfkill_register()` fails, `rfkill_destroy()` must be called and the `struct rfkill *` pointer reset to `NULL`. [F5, F109, F149]
- In `asus_rfkill_hotplug()`, `eeepc_rfkill_hotplug()`, and `asus_wmi_set_xusb2pr()`, PCI references from `pci_get_slot()`, `acpi_get_pci_dev()`, or `pci_get_device()` must be released with `pci_dev_put()` on every exit path, whereas devices from `pci_scan_single_device()` must not be passed to `pci_dev_put()`. [F2]
- In `asus_wmi_led_init()`/`exit()`, `asus_led_init()`/`exit()`, and `eeepc_led_init()`/`exit()`, `led_workqueue` and `INIT_WORK()` must be set up before `led_classdev_register()`, and all LEDs must be unregistered before `destroy_workqueue(led_workqueue)`. [F106]
- `asus_wmi_register_driver()` and `asus_wmi_unregister_driver()` must guard `used` with `register_mutex`, and `asus_s2idle_check_register()` in `asus_wmi_probe()` must be paired with `asus_s2idle_check_unregister()` both on `asus_wmi_add()` failure and in `asus_wmi_unregister_driver()`. [F12]
- In `asus-laptop.c`, `pega_accel_init()` must set `asus->pega_accel_poll` only after `input_register_device()` succeeds, and `asus_acpi_remove()` must call `pega_accel_exit()` before `asus_platform_exit()`. In `asus_platform_init()`/`exit()` and `eeepc_platform_init()`/`exit()`, `platform_device` must be cleaned up with `platform_device_put()` if `platform_device_add()` fails, `platform_device_del()` + `put()` if `sysfs_create_group()` fails, and `sysfs_remove_group()` before `platform_device_unregister()`. [F23, F111]

## API Contracts
- Payloads passed to `asus_wmi_evaluate_method_agfn()` (such as `struct agfn_fan_args`) must be `__packed` with `agfn.len = sizeof(...)`; `asus_wmi_evaluate_method_agfn()` must copy `args.pointer` into a `GFP_DMA | GFP_KERNEL` buffer via `kmemdup()`, pass `virt_to_phys(input.pointer)` to `ASUS_WMI_METHODID_AGFN`, and copy the buffer back on success. [F37, F66]
- Because `asus->kbd_led` is an embedded `struct led_classdev` only registered on supported models, callers outside LED callbacks (`asus_hotk_resume()`, `asus_hotk_restore()`) must check `!IS_ERR_OR_NULL(asus->kbd_led.dev)` before calling `kbd_led_update(asus)` or `led_classdev_notify_brightness_hw_changed()`. [F35]
- In all `rfkill` callbacks across `asus-wmi.c`, `asus-laptop.c`, and `eeepc-laptop.c`, `blocked` is inverted relative to the ASUS ACPI/WMI state (`1` = enabled/unblocked, `0` = disabled/blocked). In `asus_rfkill_hotplug()` and `eeepc_rfkill_hotplug()`, before scanning or removing PCI slot 0, the driver must read `PCI_VENDOR_ID` (`absent = (l == 0xffffffff)`) and abort if `blocked != absent`. [F55, F147]
- Sysfs `.store` callbacks across `asus-wmi.c`, `asus-laptop.c`, and `eeepc-laptop.c` must return `count` on success and a negative errno on failure (never `0`), while `attribute_group.is_visible` callbacks return unsigned `umode_t` and must return `0` on ACPI/WMI failure rather than a negative errno. [F136, F137]
- `eeepc_set_fan_ctrl()` must read `EEEPC_EC_FAN_CTRL` via `ec_read()` and modify only `EEEPC_EC_FAN_CTRL_BIT` (`0x02`) before `ec_write()`. `set_ally_mcu_hack()` and `set_ally_mcu_powersave()` are exported in `"ASUS_WMI"` and guarded in `asus-wmi.h` with `#if IS_REACHABLE(CONFIG_ASUS_WMI)` fallback stubs. [F57, F150]

## Error Handling
- `asus_wmi_evaluate_method_buf()` must convert an `ACPI_TYPE_INTEGER` value of `0` to `-ENODATA`, and in `ACPI_TYPE_BUFFER` must check `obj->buffer.length > size` and `obj->buffer.length == 0` and `break` before `memcpy()`; because it can return positive integers (`ASUS_WMI_DSTS_UNKNOWN_BIT`), callers must test `if (err)` rather than `if (err < 0)`, and `fan_curve_check_present()` must treat any `fan_curve_get_factory_default()` error as feature absence (`*available = false; return 0;`). [F26, F61, F84, F112]
- `asus_wmi_get_devstate_simple()` and `asus_wmi_get_devstate_bits()` return a negative errno on failure/absence and `>= 0` when present; callers must store the result in a signed `int` and test `< 0` rather than `!result`. [F25]
- In `asus-wmi.c` tunable, GPU, battery, and PWM `.store` handlers (`nv_temp_target_store()`, `ppt_*_store()`, `gpu_mux_mode_store()`, `pwm*_enable_store()`), after `asus_wmi_set_devstate(..., &result)` returns `0`, the handler must also check `result` (`result > 1` or `result != 1`) and return `-EIO` before updating state; conversely, `throttle_thermal_policy_write()` must pass `NULL` for `retval` because some firmwares return the active mode rather than `1`. [F27, F153]
- When `backlight_device_register()` returns `IS_ERR(bd)` in `asus_wmi_backlight_init()`, `asus_screenpad_init()`, `asus_backlight_init()`, or `eeepc_backlight_init()`, the error pointer must not be stored in the `backlight_device` field because notify and exit paths check it for `NULL`. [F32]
- `write_acpi_int()` / `write_acpi_int_ret()` (`asus-laptop.c`) and `write_acpi_int()` / `read_acpi_int()` (`eeepc-laptop.c`) return `-1` on failure, which callers must translate to `-EIO` or `-ENODEV`. In `pega_acc_axis()`, `val` must be initialized to `(unsigned long long)curr` before the `PEGA_ACC_RETRIES` loop so `clamp_val((short)val, ...)` falls back to `curr` on failure. [F28, F40]

## External Contracts
- `throttle_thermal_policy` and `platform_profile` share `asus->throttle_thermal_policy_mode` (`0` = default, `1` = overboost, `2` = silent); `throttle_thermal_policy_store()` must call `platform_profile_notify(asus->ppdev)`, and both `throttle_thermal_policy_write()` (on Vivo) and `fan_curve_get_factory_default()` must swap modes `1` and `2` for WMI. [F144]
- `fan_curve_copy_from_buf()` reads 8 temperatures from `buf[0..7]` and 8 percentages from `buf[8..15]` (scaling `0..100` to `0..255`), while `fan_curve_write()` packs `temps[0..7]` and rescaled `100 * percents[0..7] / 255` into 8-bit shifts of `arg1`..`arg4`. On `ASUS_WMI_DEVID_MINI_LED_MODE2`, `mini_led_mode_show()`/`store()` must bound `mode <= ASUS_MINI_LED_STRONG_MODE` (2) and remap between sysfs (`0`=off, `1`=on, `2`=strong) and 2024 WMI (`0`=weak, `1`=strong, `2`=off). [F64, F68]
- `dgpu_disable_store()` and `egpu_enable_store()` must return `-ENODEV` when `asus->gpu_mux_dev` state is `0` (dGPU mode), and `gpu_mux_mode_store()` must return `-ENODEV` when switching to `0` while `ASUS_WMI_DEVID_DGPU` or `ASUS_WMI_DEVID_EGPU` state is `1`. [F124]
- `asus_wmi_add()` must only probe `use_ally_mcu_hack` when it equals `ASUS_WMI_ALLY_MCU_HACK_INIT` (preserving prior `hid-asus` calls), and every `ASUS_USB0_PWR_EC0_CSEE` call must be followed by `msleep(ASUS_USB0_PWR_EC0_CSEE_WAIT)`. In `asus_hotk_thaw()` and `eeepc_hotk_thaw()`, when WLAN rfkill is present, `.thaw` must read and write back the firmware WLAN state (`ASUS_WMI_DEVID_WLAN` / `CM_ASL_WLAN`). [F125, F127]

## Known Pitfalls
- Sysfs callbacks must match their registered device: `kbd_rgb_mode_groups` callbacks (on `asus->kbd_led`) get `struct led_classdev *` from `dev_get_drvdata(dev)` and must use `container_of(..., struct asus_wmi, kbd_led)`; `charge_control_end_threshold_show()`/`store()` (on `&battery->dev`) must not cast `dev_get_drvdata(dev)` to `struct asus_wmi *`; and `eeepc-laptop.c` `hwmon_attrs` have `NULL` `drvdata`. [F95, F97, F98]
- In `fan1_input_show()`, `fan2_input_show()`, `fan3_input_show()`, and `asus_hwmon_temp1()`, the 32-bit DSTS value from `asus_wmi_get_devstate()` must be masked with `0xffff` to strip upper status flags before converting 100-RPM units (`* 100`) or deci-Kelvin (`deci_kelvin_to_millicelsius()`). [F92, F139]
- In `asus_wmi_add()`, detecting `wlan_ctrl_by_user` requires `(result & (ASUS_WMI_DSTS_PRESENCE_BIT | ASUS_WMI_DSTS_USER_BIT)) == (ASUS_WMI_DSTS_PRESENCE_BIT | ASUS_WMI_DSTS_USER_BIT)`; when true, `asus_rfkill_set()` writes `ASUS_WMI_DEVID_WLAN_LED`, and if `ashs_present()` is also true, WMI rfkill init/exit must be skipped. [F73, F148]
- In `update_bl_status()`, when `store_backlight_power` is set, power changes must update `asus->driver->panel_power`, and if `scalar_panel_brightness` is also set, it must return immediately after changing `ASUS_WMI_DEVID_BACKLIGHT` without writing `ASUS_WMI_DEVID_BRIGHTNESS`; in `asus_wmi_add()`, setting `ASUS_WMI_DEVID_BACKLIGHT` to `2` when `acpi_video_get_backlight_type() != acpi_backlight_vendor` must be gated on `quirks->wmi_backlight_set_devstate`. [F49, F114]
- In `asus_wmi_input_init()`, `SW_TABLET_MODE` must only be configured when `quirks->tablet_switch_mode != asus_wmi_no_tablet_switch`, and when `tablet_switch_mode == asus_wmi_kbd_dock_devid`, `tablet_switch_inverted = true` must be set before `asus_wmi_tablet_sw_init()` so `asus_wmi_tablet_sw_report()` negates `value`. Static `struct quirk_entry` definitions in `asus-nb-wmi.c` and `eeepc-wmi.c` must not be `const` because `*_quirks()` mutates them in place. [F74, F113, F116]
- In `infos_show()` (`asus-laptop.c`), non-NUL-terminated `acpi_table_header` fields (`oem_id` [6], `oem_table_id` [8], `asl_compiler_id` [4]) must be bounded with `snprintf()` limits (`7`, `9`, `5`). In `eeepc_dmi_check()`, model checks for `"701"` and `"702"` must use exact `strcmp()` on `dmi_get_system_info(DMI_PRODUCT_NAME)` rather than substring-matching `dmi_match()`. [F71, F115]
