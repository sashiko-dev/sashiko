# MAXIM MAX7360 KEYPAD LED MFD DRIVER

Core I2C Multi-Function Device (MFD) driver and five child platform drivers (GPIO/GPO, matrix keypad, rotary encoder, pinctrl/pinmux, and PWM) for the Maxim MAX7360 I2C key-switch and LED/GPIO controller. The core MFD driver initializes a shared 8-bit I2C regmap with maple-tree caching, resets the chip, masks initial interrupts, and registers the child platform devices that access hardware registers through the parent's regmap.

## Architecture & Data Flow

- In `max7360_reset()`, writing `MAX7360_GPIO_CFG_GPIO_RST` to `MAX7360_REG_GPIOCFG` resets hardware registers `MAX7360_REG_GPIOCFG` through `MAX7360_REG_GPIO_LAST`, so `regcache_drop_region()` must immediately invalidate that range in the `REGCACHE_MAPLE` cache. [F28]
- `MAX7360_REG_KEYFIFO` and the range `MAX7360_REG_I2C_TIMEOUT` through `MAX7360_REG_RTR_CNT` (including `MAX7360_REG_GPIOIN`) must remain in `max7360_volatile_ranges` so FIFO reads, rotary counter reads, and pending-IRQ acknowledgement reads bypass `REGCACHE_MAPLE`. [F29]
- For the `MAX7360_GPIO_COL` bank, `gpio_config.ngpio` is `MAX7360_MAX_KEY_COLS` (8); `max7360_gpo_init_valid_mask()` and `max7360_set_gpos_count()` must both derive `available_gpios` from `max7360_get_available_gpos()`, clearing bits `[0, MAX7360_MAX_KEY_COLS - available_gpios)` in `valid_mask` so keypad columns occupy lower lines and up to `MAX7360_MAX_GPO` (6) GPOs occupy the highest lines of `MAX7360_REG_PORTS` matching `MAX7360_PORTS`. [F32, F39]
- In `max7360_set_mux()`, any group with `max7360_groups[group].pins[0] >= 6` (covering `PORT6`, `PORT7`, and `ROTARY`) must update `MAX7360_GPIO_CFG_RTR_EN` in `MAX7360_REG_GPIOCFG`, setting it when `selector == MAX7360_PINCTRL_FN_ROTARY` and clearing it for GPIO or PWM functions. Broken by: only writing `MAX7360_GPIO_CFG_RTR_EN` when `group` is `ROTARY` without clearing it when `PORT6` or `PORT7` is muxed to GPIO or PWM. [F48]
- In `max7360_keypad_irq()`, the `val == MAX7360_FIFO_OVERFLOW` (`0x7F`) check and `regmap_read_poll_timeout()` loop must precede and fall through into the `val == MAX7360_FIFO_EMPTY` (`0x3F`) check before decoding `MAX7360_FIFO_ROW` and `MAX7360_FIFO_COL`, as both sentinels have bits `[5:0]` set and polling updates `val` to `MAX7360_FIFO_EMPTY` or a key event. Broken by: returning early after polling or checking `MAX7360_FIFO_EMPTY` before `MAX7360_FIFO_OVERFLOW`. [F42]
- `max7360_keypad_parse_fw()` must reject `cols == 0` or `> MAX7360_MAX_KEY_COLS` and `rows == 0` or `> MAX7360_MAX_KEY_ROWS`, and `struct max7360_keypad.keycodes` must remain a device-managed array of `MAX7360_MAX_KEY_ROWS * MAX7360_MAX_KEY_COLS` (64) entries, because `matrix_keypad_build_keymap()` and `max7360_keypad_irq()` index it via `MATRIX_SCAN_CODE(row, col, get_count_order(cols))`. Broken by: shrinking `keycodes` to `rows * cols` when `cols` is not a power of two, or allowing `cols == 0` (`get_count_order(0)` returns `-EINVAL`). [F21, F54, F57]
- In `max7360_rotary_report_event()`, `max7360_rotary->pos` and `max7360_rotary->steps` must be held in signed `int` locals (`pos` and `maxval`) and `steps` reduced via `steps % maxval` before adding to `pos`, ensuring signed remainder semantics and keeping `pos + maxval >= 0` before `(pos + maxval) % maxval`. Broken by: computing `steps % max7360_rotary->steps` directly with the `u32` field or adding `steps` before modulo reduction. [F53]
- `max7360_pwm_probe()` calls `devm_pwmchip_alloc()` with `sizeof_priv = 0` and overwrites the chip drvdata pointer via `pwmchip_set_drvdata(chip, regmap)`, so `max7360_pwm_request()`, `max7360_pwm_write_waveform()`, and `max7360_pwm_read_waveform()` must treat `pwmchip_get_drvdata(chip)` as a `struct regmap *` directly. [F60]

## Synchronization

- In `max7360_probe()`, `max7360_reset()`, setting `MAX7360_GPIO_CFG_GPIO_EN`, and `max7360_mask_irqs()` (masking `MAX7360_PORT_CFG_INTERRUPT_MASK` in `MAX7360_REG_PWMCFG(i)` and reading `MAX7360_REG_GPIOIN`) must complete before `devm_mfd_add_devices()` publishes child devices, because unmasked GPIO IRQs on the shared `"inti"` line cause spurious IRQs in `max7360-rotary`. [F10]
- Updates to shared registers across sibling drivers—`MAX7360_REG_GPIOCFG` (`max7360_set_mux()`), `MAX7360_REG_GPIOCTRL` (`max7360_pwm_write_waveform()`), `MAX7360_REG_PWMCFG(x)` (`max7360_pwm_request()`, `max7360_handle_mask_sync()`, `max7360_gpio_probe()`), and `MAX7360_REG_DEBOUNCE` (`max7360_set_gpos_count()` for `MAX7360_PORTS` and `max7360_keypad_hw_init()` for `MAX7360_DEBOUNCE`)—must use `regmap_write_bits()` or `regmap_assign_bits()` rather than `regmap_write()` so concurrent sub-drivers do not clobber each other's bits. [F12, F30]
- Both `max7360_gpio_probe()` (via `gpio_config.regmap_irq_flags`) and `max7360_rotary_probe()` (via `devm_request_threaded_irq()`) must request the parent's `"inti"` IRQ with `IRQF_ONESHOT | IRQF_SHARED`, and `max7360_rotary_irq()` must return `IRQ_NONE` when `MAX7360_REG_RTR_CNT` is 0 so shared GPIO interrupts are properly handled. [F13]
- The shared `regmap` created by `devm_regmap_init_i2c()` in `max7360_probe()` performs sleeping I2C transfers under a regmap mutex, so all `regmap_*` accesses across `max7360` and its child drivers (`max7360_keypad_irq()`, `max7360_rotary_irq()`, `max7360_handle_mask_sync()`, and subsystem ops) must execute in sleepable process or threaded-IRQ context. [F74]
- In `max7360_keypad_probe()`, `max7360_keypad->regmap`, `cols`, `input`, `keycodes` (via `max7360_keypad_build_keymap()`), and `input_set_drvdata(input, max7360_keypad)` must be initialized before `devm_request_threaded_irq()` and `input_register_device()` publish `max7360_keypad` to `max7360_keypad_irq()`, `max7360_keypad_open()`, and `max7360_keypad_close()`. [F14]
- In `max7360_rotary_probe()`, `max7360_rotary->regmap`, `input`, `axis`, `steps`, `rollover`, `relative_axis`, and input axis capabilities must all be initialized before `devm_request_threaded_irq()`, because the shared `"inti"` line can invoke `max7360_rotary_irq()` as soon as the handler is registered. [F15]

## Object Lifetimes

- In `max7360_pinctrl_probe()`, `pinctrl_desc` must be stored in the `devm_kzalloc`-allocated `struct max7360_pinctrl` (`chip->pinctrl_desc`) rather than on the stack because `devm_pinctrl_register()` retains the `pinctrl_desc` pointer for the lifetime of `chip->pctldev`. [F5]
- In `max7360_keypad_build_keymap()`, the temporary `keys` buffer is declared with `__free(kfree)`, so it is automatically freed on every exit path after `matrix_keypad_build_keymap()` populates `max7360_keypad->keycodes` and must not be freed manually or retained past return. [F1]
- In `max7360_keypad_probe()` and `max7360_rotary_probe()`, `input` is allocated via `devm_input_allocate_device(dev)`, so `input_register_device(input)` is automatically managed by devres and must not be paired with `input_unregister_device()` or `input_free_device()`. [F8]
- In `max7360_pwm_probe()`, `chip->ops` and `pwmchip_set_drvdata(chip, regmap)` must be set before `devm_pwmchip_add(dev, chip)` publishes the PWM controller to consumers. [F16]

## API Contracts

- In `max7360_pinctrl_probe()` and `max7360_pwm_probe()`, `device_set_of_node_from_dev(dev, dev->parent)` must be called before `devm_pinctrl_register()` or `devm_pwmchip_add()` because their `mfd_cell` entries in `max7360_cells` omit `of_compatible` and client DT phandles reference the parent MFD node. [F76]
- For `MAX7360_GPIO_PORT`, `max7360_gpio_reg_mask_xlate()` must translate `base == MAX7360_REG_PWMBASE` to register `base + offset` with full 8-bit mask `GENMASK(7, 0)`, while other bases (`MAX7360_REG_GPIOIN`, `MAX7360_REG_GPIOCTRL`) map to `base` with single-bit mask `BIT(offset)`. [F70]
- When validating `max7360_keypad->debounce_ms` with `in_range()` in `max7360_keypad_parse_fw()`, the third argument must be the inclusive interval length (`MAX7360_DEBOUNCE_MAX - MAX7360_DEBOUNCE_MIN + 1`), and `max7360_keypad_hw_init()` must subtract `MAX7360_DEBOUNCE_MIN` before encoding `MAX7360_DEBOUNCE`. [F20]
- In `max7360_keypad_build_keymap()`, the `size` returned by `device_property_count_u32()` is a `u32` element count (not a byte length) and must be scaled by `sizeof(*keys)` in `kmalloc_array()` while being passed unscaled to `device_property_read_u32_array()` and `keymap_data.keymap_size`. [F56]
- In `max7360_pwm_round_waveform_fromhw()`, converting `wfhw->duty_steps` below `MAX7360_PWM_MAX` to `wf->duty_length_ns` must use `DIV_ROUND_UP(wfhw->duty_steps * MAX7360_PWM_PERIOD_NS, MAX7360_PWM_STEPS)` so that truncating division in `max7360_pwm_round_waveform_tohw()` rounds the resulting `duty_length_ns` back to the same `duty_steps`. [F51]
- All four waveform callbacks in `max7360_pwm_ops` (`max7360_pwm_round_waveform_tohw()`, `max7360_pwm_round_waveform_fromhw()`, `max7360_pwm_write_waveform()`, and `max7360_pwm_read_waveform()`) cast their `void *_wfhw` argument to `struct max7360_pwm_waveform *`, whose size must never exceed `PWM_WFHWSIZE` (20 bytes). [F61]

## Error Handling

- `max7360_pwm_read_waveform()` and `max7360_pwm_round_waveform_fromhw()` must explicitly zero `wfhw->duty_steps` and `wf->duty_length_ns` (as well as `wf->duty_offset_ns`) when the channel is disabled, because the PWM core passes an uninitialized stack buffer `char wfhw[PWM_WFHWSIZE]`. [F27]
- In `max7360_gpio_probe()`, the stack-allocated `struct gpio_regmap_config gpio_config` must be zero-initialized before conditional population because `MAX7360_GPIO_PORT` and `MAX7360_GPIO_COL` leave mutually exclusive base-address, IRQ, and callback fields unset. [F25]
- `max7360_keypad_build_keymap()` must store the return value of `device_property_count_u32()` in a signed `int` and reject both negative error codes and `0` (converting `0` to `-EINVAL`) before passing the count to `kmalloc_array()` and `device_property_read_u32_array()`. [F18]
- In `max7360_keypad_parse_fw()`, `max7360_keypad->debounce_ms` must be initialized to `MAX7360_DEBOUNCE_MIN` before calling `device_property_read_u32()` for `"keypad-debounce-delay-ms"`, and only `-EINVAL` (missing property) may be ignored while other negative errors must abort probe. [F19]

## External Contracts

- MFD-level firmware properties (`keypad,num-columns`, `linux,keymap`, `keypad-debounce-delay-ms`, `autorepeat`, `linux,axis`, `rotary-encoder,*`, `rotary-debounce-delay-ms`) and named interrupts (`inti`, `intk`) reside on the parent MFD device and must be queried from `dev->parent` (or `input_dev->dev.parent->parent`), not the child platform `dev`. [F67]

## Known Pitfalls

- In `max7360_keypad_open()` and `max7360_keypad_close()`, `MAX7360_CFG_SLEEP` (`BIT(7)` in `MAX7360_REG_CONFIG`) has active-low sleep polarity: setting `MAX7360_CFG_SLEEP` wakes the device out of sleep on open, whereas clearing it to 0 puts the device to sleep on close. [F44]
- In `max7360_keypad_irq()`, the hardware FIFO bit `MAX7360_FIFO_RELEASE` (`BIT(6)`) is 1 on key release and 0 on key press, so the extracted `release` flag must be logically negated (`!release`) when passed to `input_report_key()`. [F43]
- In `max7360_rotary_irq()`, the 8-bit register value read from `MAX7360_REG_RTR_CNT` into `unsigned int val` must be sign-extended from bit 7 via `sign_extend32(val, 7)` before calling `max7360_rotary_report_event()`. Broken by: passing `val` or `(int)val` directly, treating negative 8-bit step counts as `128..255`. [F52]
- In `max7360_pwm_round_waveform_tohw()`, `wf->duty_length_ns` must be checked against `MAX7360_PWM_PERIOD_NS` before casting `wf->duty_length_ns` to `u32` and multiplying by `MAX7360_PWM_STEPS`, so the 32-bit product stays below `2000000 * 256` without truncating high bits or overflowing `u32`. [F49]
