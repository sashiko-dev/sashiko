# HUGETLB SUBSYSTEM

The HugeTLB subsystem manages persistent and surplus huge page pools (`hstate`), huge page reservations (`resv_map`), page table operations (including PMD page table sharing), fault handling, migration, and hardware poison recovery. It includes the in-memory `hugetlbfs` filesystem for file-backed, anonymous (`MAP_HUGETLB`), and System V shared memory (`SHM_HUGETLB`) mappings, alongside HugeTLB vmemmap optimization (HVO), CMA-backed gigantic page allocation, and cgroup v1/v2 resource accounting.

## Architecture & Data Flow

- In hugetlb VMAs, `vma->vm_private_data` holds a `struct hugetlb_vma_lock *` when `VM_MAYSHARE` is set, or a `struct resv_map *` tagged with `HPAGE_RESV_MASK` (`HPAGE_RESV_OWNER | HPAGE_RESV_UNMAPPED`) when clear (requiring `vma_resv_map()` to mask `~HPAGE_RESV_MASK`). In `hugetlb_dup_vma_private()` and `hugetlb_vm_op_open()`, clear `vma->vm_private_data = NULL` only if `vma_lock->vma != vma` before calling `hugetlb_vma_lock_alloc(vma)`. [F79, F142]
- Every successful `region_chg(resv, f, t, &out_regions_needed)` increments `resv->adds_in_progress` by `*out_regions_needed` (>= 1) and must be paired with `region_add()` or `region_abort()` (via `vma_commit_reservation()` or `vma_end_reservation()`) to decrement it by the same amount. [F72]
- `struct file_region` entries in `resv_map->regions` represent `[from, to)`, except `region_del()` must check `rg->to <= f && (rg->to != rg->from || rg->to != f)` before skipping preceding entries so zero-length placeholder entries with `from == to == f` are deleted. [F102]
- Access a hugetlbfs inode's `struct resv_map` via `inode_resv_map(inode)` (`(&inode->i_data)->i_private_data`, never `inode->i_mapping->i_private_data`) and null-check the result when non-regular/non-symlink inodes can be reached. [F50]
- In `free_huge_folio()`, call `hugepage_subpool_put_pages(spool, 1)` only when `folio_test_hugetlb_restore_reserve(folio)` is false; if it returns `0`, set `restore_reserve = true` so `h->resv_huge_pages` is incremented under `hugetlb_lock`. [F15]
- In `enqueue_hugetlb_folio()`, `dequeue_hugetlb_folio_node_exact()`, and `remove_hugetlb_folio()`, moving a folio onto or off `h->hugepage_freelists[nid]` must update `h->free_huge_pages`, `h->free_huge_pages_node[nid]`, and `HPG_freed` (`folio_set_hugetlb_freed()` / `folio_clear_hugetlb_freed()`) in lockstep under `hugetlb_lock`. [F65]
- In `dissolve_free_hugetlb_folio()`, pass `adjust_surplus = true` to `remove_hugetlb_folio()` (and to `add_hugetlb_folio()` if `hugetlb_vmemmap_restore_folio()` fails) whenever `h->surplus_huge_pages_node[folio_nid(folio)]` is non-zero, alongside adjusting `h->max_huge_pages`. In `set_max_huge_pages()`, compute `min_count` using `persistent_huge_pages(h)` and `persistent_free_count` (discounting free surplus pages) rather than `h->nr_huge_pages` and raw `h->free_huge_pages`. [F66, F67]
- `NR_RESET_STRUCT_PAGE` in `mm/hugetlb_vmemmap.c` must be at least `1 + __NR_USED_SUBPAGE` (4 `struct page` entries up to `__page_3`) so `reset_struct_pages()` clears all hugetlb metadata when `vmemmap_restore_pte()` copies `walk->reuse_addr`. The `!CONFIG_HUGETLB_PAGE_OPTIMIZE_VMEMMAP` stub of `hugetlb_vmemmap_restore_folios()` must call `list_splice_init(folio_list, non_hvo_folios)` and return `0`. [F87, F89]
- `hugetlb_add_to_page_cache()` must call `folio_mark_dirty(folio)` to prevent pagecache eviction, and `hugetlb_delete_from_page_cache()` must clear dirty and uptodate flags before `filemap_remove_folio(folio)`. [F174]

## Synchronization

- Always acquire the hugetlb VMA lock (`vma_lock->rw_sema` or `resv_map->rw_sema`) before `mapping->i_mmap_rwsem`. In `__hugetlb_zap_begin()` / `__hugetlb_zap_end()`, lock `hugetlb_vma_lock_write(vma)` before `i_mmap_lock_write()`, and on `ZAP_FLAG_UNMAP` call `__hugetlb_vma_unlock_write_free(vma)` before `i_mmap_unlock_write()`. Callers holding `i_mmap_rwsem` (like `hugetlb_unmap_file_folio()`) may only use `hugetlb_vma_trylock_write(vma)`. [F12, F29]
- For `VM_MAYSHARE` mappings, callers of `hugetlb_walk()` or `huge_pte_offset()` must hold `vma_lock->rw_sema` or `i_mmap_rwsem` (read or write) to prevent concurrent `huge_pmd_unshare()` and `munmap()` from freeing the PMD page table page. In `hugetlb_split()`, call `hugetlb_unshare_pmds(vma, floor, ceil, false)` only while both the VMA and `i_mmap_rwsem` are write-locked. [F33, F36]
- `hugetlb_lock` and `spool->lock` are taken in `free_huge_folio()` via `spin_lock_irqsave()`, so all process-context callers must disable IRQs (`spin_lock_irq()` / `spin_lock_irqsave()`). In `__unmap_hugepage_range()`, unlock `ptl` before taking `hugetlb_lock` to read `h->surplus_huge_pages`, and reset `adjust_reservation` on each iteration. [F152, F153]
- In `hugetlb_fault()`, `hugetlb_no_page()`, and `hugetlb_wp()`, use `__vmf_anon_prepare()` (never `vmf_anon_prepare()`), and on `VM_FAULT_RETRY` call `vma_end_read(vma)` only after `hugetlb_vma_unlock_read(vma)`. [F2]
- `hugetlb_wp()` is entered with `vmf->ptl` held and drops it before `alloc_hugetlb_folio()`, so every subsequent exit path in `hugetlb_wp()` must re-acquire `spin_lock(vmf->ptl)`. [F4]
- `hugetlb_wp()` must detect `MAP_PRIVATE` owner CoW via `folio_test_anon(old_folio)` rather than locking the pagecache folio across `hugetlb_fault_mutex_table`, and `hugetlb_fault()` must use `folio_trylock(folio)` on anonymous folios under `hugetlb_fault_mutex_table`, dropping all locks before `folio_wait_locked(folio)` or `unmap_ref_private()`. Before calling `handle_userfault()` via `hugetlb_handle_userfault()`, release `vmf.ptl`, `hugetlb_vma_lock`, and `hugetlb_fault_mutex_table[hash]`. [F158, F160]
- When `update_and_free_hugetlb_folio()` is called with `atomic == true` on an HVO folio, it links `(struct llist_node *)&folio->mapping` onto `hpage_freelist` and schedules `free_hpage_work`; `free_hpage_workfn()` must clear `folio->mapping = NULL` and use `size_to_hstate(folio_size(folio))` instead of `folio_hstate(folio)`. Callers awaiting buddy release (including `set_max_huge_pages()`) must call `flush_free_hpage_work(h)` or `wait_for_freed_hugetlb_folios()` without holding `hugetlb_lock`. [F26, F27, F86]
- Because `allocate_file_region_entries()` drops `resv->lock` to allocate, it must loop on `while (resv->region_cache_count < (resv->adds_in_progress + regions_needed))` after relocking, and `region_add()` must jump to `retry:` to recompute `actual_regions_needed` via `add_reservation_in_range()`. [F77]
- While holding `folio_lock(folio)`, `hugetlb_folio_mapping_lock_write()` must use `i_mmap_trylock_write(mapping)` rather than blocking `i_mmap_lock_write(mapping)`. In `demote_free_hugetlb_folios()`, acquire the larger-order `src->resize_lock` before `dst->resize_lock`, and drop `hugetlb_lock` before taking `dst->resize_lock` or restoring/optimizing vmemmap. [F39, F40]
- Mark new hugetlb folios uptodate via `__folio_mark_uptodate(folio)` before `set_huge_pte_at()` or `hugetlb_add_to_page_cache()`, and call `folio_set_hugetlb_migratable(folio)` only after page-cache or page-table insertion. [F44]
- Update a folio's `hugetlb_cgroup` pointers and `h_cg->nodeinfo[nid]->usage[idx]` under `hugetlb_lock` using `WRITE_ONCE()` for `usage[idx]`. In `__hugetlb_cgroup_charge_cgroup()`, perform `hugetlb_cgroup_from_task(current)` and the `css_tryget(&h_cg->css)` retry loop inside `rcu_read_lock()`. [F45, F165]
- `huge_pte_lockptr()` must return `pud_lockptr()` when `size >= PUD_SIZE`, `pmd_lockptr()` when `size >= PMD_SIZE || IS_ENABLED(CONFIG_HIGHPTE)`, and `ptep_lockptr()` only when `size < PMD_SIZE && !IS_ENABLED(CONFIG_HIGHPTE)`. [F168]

## Object Lifetimes

- If a folio from `alloc_hugetlb_folio()` is discarded before `hugetlb_add_to_page_cache()` succeeds (or before PTE installation for private mappings), call `restore_reserve_on_error()` before `folio_put(folio)`; after `hugetlb_add_to_page_cache()` succeeds, do not call `restore_reserve_on_error()`. In `hugetlb_no_page()`, call `__vmf_anon_prepare(vmf)` for private mappings before `alloc_hugetlb_folio()`. [F3, F6]
- `remove_hugetlb_folio()` must keep `PG_hugetlb` set when `folio_test_hugetlb_vmemmap_optimized(folio)` is true until `hugetlb_vmemmap_restore_folio()` (or `hugetlb_vmemmap_restore_folios()`) succeeds; on restoration failure, return the folio to the pool via `add_hugetlb_folio()` under `hugetlb_lock` instead of calling `hugetlb_free_folio()`. [F16]
- When `hugetlb_unmap_file_folio()` fails `hugetlb_vma_trylock_write(vma)`, pin `kref_get(&vma_lock->refs)` before dropping `i_mmap_rwsem`, acquire `down_write(&vma_lock->rw_sema)` then `i_mmap_lock_write(mapping)`, and revalidate `vma_lock->vma != NULL` and `hugetlb_vma_maps_pfn()` before unmapping. [F30]
- Because `record_hugetlb_cgroup_uncharge_info()` takes a separate `css_get(&h_cg->css)` per `file_region`, `hugetlb_reserve_pages()` must release the initial `css` reference from `hugetlb_cgroup_charge_cgroup_rsvd()` via `hugetlb_cgroup_put_rsvd_cgroup(h_cg)` or `hugetlb_cgroup_uncharge_cgroup_rsvd()`, and `hugetlb_cgroup_uncharge_file_region()` must only call `css_put(rg->css)` when `region_del` is true. [F9]
- In `region_del()`, when splitting a region drops `resv->lock` to `kmalloc()` `nrg` and jumps to `retry:`, preserve `nrg` across `retry:`, set `nrg = NULL` only when linked into `resv->regions`, and call `kfree(nrg)` after the loop. [F126]

## API Contracts

- When `CONFIG_HUGETLB_PAGE` is enabled, `alloc_hugetlb_folio()` and `filemap_lock_hugetlb_folio()` return `ERR_PTR` on failure (test with `IS_ERR()`), whereas `alloc_hugetlb_folio_nodemask()`, `alloc_hugetlb_folio_reserve()`, and `alloc_hugetlb_folio_vma()` return `NULL`. [F47]
- In `hugetlb_mfill_atomic_pte()`, when `*foliop` is non-NULL on entry, consume ownership by calling `folio_put(*foliop)` and setting `*foliop = NULL` across all return paths, only setting `*foliop` to a newly allocated folio when returning `-ENOENT`. [F7]
- `hugetlb_cgroup_charge_cgroup*()`, `hugetlb_cgroup_commit_charge*()`, `hugetlb_cgroup_uncharge_folio*()`, and `hugetlb_cgroup_uncharge_cgroup*()` take `nr_pages` in `PAGE_SIZE` base pages, whereas `hugetlb_cgroup_uncharge_counter()` and `hugetlb_cgroup_uncharge_file_region()` take huge-page counts and multiply by `resv->pages_per_hpage`. [F60]
- In `__vma_reservation_common()`, private mappings (`!(vma->vm_flags & VM_MAYSHARE)`) must invert non-negative return values from `region_chg()`, `region_add()`, and `region_del()` (`ret > 0` to `0`, `ret == 0` to `1`) for all modes except `VMA_DEL_RESV`. [F117]
- `make_huge_pte()` must check both `try_mkwrite` and `(vma->vm_flags & VM_WRITE)` before marking a PTE writable and dirty, as `hugetlb_install_folio()` passes `try_mkwrite = true` on read-only VMAs during fork CoW. [F181]
- `remove_inode_hugepages()` distinguishes truncation from hole punch strictly by `lend == LLONG_MAX` and passes `end == LONG_MAX` to `hugetlb_unreserve_pages()` / `region_del()` so no `file_region` is split. `hugetlb_vmdelete_list()` takes an exclusive `pgoff_t end` where `0` means the entire range, passing `end ? end - 1 : ULONG_MAX` to `vma_interval_tree_foreach()`. [F103, F106]
- Hugetlb paths (`hugetlbfs_read_iter()`, `hugetlb_no_page()`, `hugetlb_mfill_atomic_pte()`) must test `folio_test_hwpoison(folio)` rather than `folio_test_has_hwpoisoned(folio)`, and `adjust_range_hwpoison()` must check subpages via `is_raw_hwpoison_page_in_hugepage()`. [F176]

## Error Handling

- When rolling back after `hugepage_subpool_get_pages(spool, chg)` returns `gbl_reserve`, pass only `chg - gbl_reserve` to `hugepage_subpool_put_pages()` and unreserve its return value via `hugetlb_acct_memory(h, -gbl_resv)`. [F1]
- Store the return value of `vma_needs_reservation()` in a signed type and check `< 0` (`-ENOMEM`) before treating it as a positive reservation requirement or calling `vma_add_reservation()`, `vma_commit_reservation()`, or `vma_end_reservation()`. [F46]
- In `update_and_free_pages_bulk()`, when `hugetlb_vmemmap_restore_folios()` fails, `bulk_vmemmap_restore_error()` must ensure forward progress across `goto retry` by freeing `non_hvo_folios` if non-empty, or else unlinking folios from `folio_list` one by one until one restores and frees or all become surplus pages. [F128]
- In `alloc_vmemmap_page_list()`, call `memmap_pages_add(nr_pages)` only after the allocation loop succeeds because rollback frees partial allocations via `__free_page(page)`. In `demote_free_hugetlb_folios()`, initialize each split `new_folio` with `new_folio->mapping = NULL`, `init_new_hugetlb_folio(new_folio)`, and propagate `folio_test_hugetlb_cma(folio)` via `folio_set_hugetlb_cma(new_folio)`. [F18, F57]
- `alloc_hugetlb_folio_reserve()` must check `if (!h->resv_huge_pages)` under `hugetlb_lock` and return `NULL` (not `VM_BUG_ON`). In `hugetlb_no_page()`, faulting on a `MAP_PRIVATE` VMA with `HPAGE_RESV_UNMAPPED` must log with `pr_warn_ratelimited()` and return `VM_FAULT_SIGBUS` without `WARN`/`BUG`. [F180, F189]

## Known Pitfalls

- `hugetlb_vma_trylock_write(vma)` acquires `resv_map->rw_sema` on private VMAs and returns `1`, so callers operating only on shareable-locked VMAs (like `hugetlb_vmdelete_list()`) must check `__vma_shareable_lock(vma)` after trylocking and still call `hugetlb_vma_unlock_write(vma)` when skipping. [F31]
- Because `hugetlbfs_file_mmap()` sets `VM_HUGETLB` before validating alignment and reservations, `__hugetlb_zap_begin()` and `__hugetlb_zap_end()` can be called during `do_mmap()` error teardown with `vma->vm_file == NULL` and must guard against `!vma->vm_file`. [F52]
- Page-cache XArray operations (`__filemap_add_folio()`, `filemap_get_folio()`, `filemap_lock_folio()`, `folio->index`) use `PAGE_SIZE` indices (`idx << huge_page_order(h)`), whereas `filemap_lock_hugetlb_folio()`, `hugetlb_add_to_page_cache()`, `hugetlb_fault_mutex_hash()`, and `resv_map` use huge-page indices. [F101]
- In `hugetlb_mfill_atomic_pte()`, when `is_continue` (`MFILL_ATOMIC_CONTINUE`) is true, the folio is already in the pagecache (`folio_in_pagecache = true`) and must skip `__folio_mark_uptodate()`, `hugetlb_add_to_page_cache()`, `folio_set_hugetlb_migratable()`, and `restore_reserve_on_error()`, while still unlocking `folio` on exit. [F119]
- In `__unmap_hugepage_range()`, capture `const bool folio_provided = !!folio` before the loop because the `!folio_provided` branch overwrites `folio` on each present PTE. In `coalesce_file_region()`, reassign `rg = prg` after `kfree(rg)` before calling `list_next_entry(rg, link)`. [F120, F123]
