# DRM DRIVERS AND MISC GPU PATCHES

This unit provides core DRM infrastructure for framebuffers, GEM buffer objects and backing-store helpers (shmem, DMA, TTM, VRAM, shadow planes), GPUSVM/HMM and `drm_pagemap` migration, PRIME/DMA-BUF sharing, `drm_mm` range allocation, KMS objects/properties/planes/modes and wound/wait locking, resource leasing, `drmm_*` managed resources, IOCTL dispatch, output polling, panic rendering, privacy screens, and MIPI DBI/DSI helpers.

## Architecture & Data Flow
- In `drm_gem_shmem_mmap()`, `vma->vm_pgoff` must retain the fake VMA offset from `obj->vma_node` so `drm_vma_node_unmap()` in `drm_gem_shmem_purge_locked()` can unmap active VMAs; `drm_gem_shmem_fault()` must compute `page_offset` from `(vmf->address - vma->vm_start) >> PAGE_SHIFT` rather than `vmf->pgoff`. [F65]
- In `drm_gpusvm`, interval tree nodes (`notifier->itree`, `range->itree`) store inclusive end addresses (`ALIGN(fault_addr + 1, size) - 1`) while API functions use exclusive end addresses (`end - 1` / `itree.last + 1`), and `drm_gpusvm_notifier_insert()`/`_remove()` and `drm_gpusvm_range_insert()`/`__drm_gpusvm_range_remove()` must keep the interval tree and companion `notifier_list`/`range_list` synchronized in ascending order via `rb_prev()`. [F70, F104]
- In `drm_gpusvm_get_pages()` and `__drm_gpusvm_unmap_pages()`, mapping/unmapping loops must advance PFN index `i` by `1 << order` (where `drm_gpusvm_hmm_pfn_to_order()` clamps `hmm_pfn_to_map_order()` by PFN offset and excess beyond `npages`) while incrementing `dma_addr` index `j` by 1; `err_unmap` must pass `num_dma_mapped` (tracking `i`, not `j`). [F105, F119]
- `_drm_lease_revoke()` empties `master->leases` via `idr_remove()` without unlinking `master->lessee_list` or freeing `master` (preserving list links for the tree walk), so `drm_mode_list_lessees_ioctl()` must filter with `!idr_is_empty(&lessee->leases)` under `dev->mode_config.idr_mutex`. [F80, F128]
- In `drm_mm`, `drm_mm_reserve_node()` and `drm_mm_insert_node_in_range()` must reject `size == 0` or `start + size <= start` with `-ENOSPC` so inclusive `LAST(node)` (`start + size - 1`) never underflows, and `node->node_list` and `rm_hole()` must be updated before calling `add_hole()`. [F280, F308]

## Synchronization
- The global lock hierarchy orders `crtc_ww_class` (`drm_modeset_lock`) outer to `mmap_lock`, and `mmap_lock` outer to `reservation_ww_class` (`dma_resv_lock`). When `drm_modeset_lock()` returns `-EDEADLK`, callers must call `drm_modeset_backoff(ctx)` before further locking or `drm_modeset_drop_locks()`; `modeset_lock()` must convert `-EALREADY` to `0` without re-adding `lock->head` to `ctx->locked`; and `drm_modeset_lock_all_ctx()` does not take `dev->mode_config.mutex`. [F228, F229, F322, F384]
- When `drm_gem_lock_reservations()` fails at index `i`, it must unlock `objs[0..i-1]` plus `objs[contended]` (if `contended != -1 && contended >= i`), call `ww_acquire_fini(acquire_ctx)` (never `ww_acquire_done()`) on error return, and on `-EDEADLK` slow-lock `objs[contended]` and skip `i == contended` on retry. [F12, F116]
- `drm_gem_object` and `drm_framebuffer` structs must be fully initialized before `drm_gem_handle_create*()` or `drm_framebuffer_init()` publishes them (`drm_framebuffer` fields are invariant afterward). `drm_gem_handle_create_tail()` requires `dev->object_name_lock` held on entry, always unlocks it before returning, reserves `file_priv->object_idr` with `NULL` using `GFP_NOWAIT` under `file_priv->table_lock` (never nesting `file_priv->prime.lock` inside `table_lock`), and only replaces with `obj` after `drm_vma_node_allow()` and `obj->funcs->open()` succeed. [F4, F23, F24, F25, F188]
- `dev->object_name_lock` protects `obj->handle_count`, `obj->name`, and `dev->object_name_idr`: `drm_gem_flink_ioctl()` and `export_and_register_object()` (plus `drm_prime_add_buf_handle()` in `drm_gem_prime_handle_to_dmabuf()`) must check `obj->handle_count != 0` under `object_name_lock`; in `drm_gem_prime_fd_to_handle()`, if `drm_prime_add_buf_handle()` fails after `drm_gem_handle_create_tail()`, `file_priv->prime.lock` must be unlocked before calling `drm_gem_handle_delete()`. [F28, F223, F247]
- `drm_gem_vmap()`, `drm_gem_vunmap()`, `drm_gem_map_attach()`, and `drm_gem_map_detach()` hold `obj->resv` across `obj->funcs->vmap`, `.vunmap`, `.pin`, and `.unpin`, so those callbacks must not re-lock `obj->resv`. For non-imported `drm_gem_shmem_object`, `shmem->base.resv` protects `pages`, `sgt`, `vaddr`, `madv`, and their refcounts, and `drm_gem_shmem_pin_locked()`/`unpin_locked()` must re-check `refcount_inc_not_zero()`/`refcount_dec_and_test()` on `pages_pin_count` after taking `resv`. [F29, F30, F42, F393]
- `gpusvm->notifier_lock` protects `notifier->root`, `notifier->range_list`, and `svm_pages` state (write-locked in `drm_gpusvm_notifier_invalidate()`, `drm_gpusvm_range_set_unmapped()`, and `drm_gpusvm_unmap_pages()` when `ctx->in_notifier`; read-locked otherwise). `drm_gpusvm_notifier_invalidate()` must check `mmu_notifier_range_blockable()` before locking `notifier_lock`; callers must drop `notifier_lock` before `GFP_KERNEL` allocations; and `drm_gpusvm_range_find_or_insert()`/`_remove()` require the driver SVM lock. [F31, F32, F178, F179]
- `dev->mode_config.idr_mutex` protects both lease trees (`master->leases`, `lessees`, `lessee_list`, `lessee_idr`) and `dev->mode_config.object_idr` (`__drm_mode_object_add()`, `drm_mode_object_register()`, `drm_mode_object_unregister()`, and `kref_get_unless_zero(&obj->refcount)` in `__drm_mode_object_find()`). `dev->mode_config.connector_list_lock` requires `spin_lock_irq` / `spin_lock_irqsave`. [F33, F240, F386]
- `drm_kms_helper_hotplug_event()` and `drm_kms_helper_connector_hotplug_event()` must be called with no modeset locks held; `drm_helper_probe_single_connector_modes()`, `drm_mode_probed_add()`, and `drm_connector_list_update()` require `dev->mode_config.mutex`, while `output_poll_execute()` must use `mutex_trylock(&dev->mode_config.mutex)` and unlock before sending hotplug events. During suspend/teardown, if `poll_enabled` is true, `drm_kms_helper_disable_hpd()` must precede `cancel_delayed_work_sync(&output_poll_work)`. [F252, F254, F255, F391]
- `drm_pagemap_migrate_to_devmem()` requires `mmap_assert_locked(mm)`, whereas `drm_pagemap_evict_to_ram()` pins `devmem_allocation->mm` via `mmget_not_zero()` / `mmput_async()`. `drm_pagemap_zdd_destroy()` must call `complete_all(&devmem->detached)` before `devmem->ops->devmem_release(devmem)`, which runs in `put_page()` (potentially atomic/IRQ) context and must not sleep; likewise, `drm_mm` insertion/reservation paths (`save_stack()`) may run under spinlocks and must use `GFP_NOWAIT`. [F256, F257, F397, F399]
- In `draw_panic_plane()`, `get_scanout_buffer`, `panic_flush`, and `set_pixel` run under `raw_spinlock_t` `dev->mode_config.panic_lock` with IRQs disabled (must not sleep or allocate), and `drm_panic_set_description()` must be paired with `drm_panic_clear_description()` before `drm_panic_unlock()`. [F296, F381]

## Object Lifetimes
- In `drm_framebuffer_init()`, each `fb->obj[i]` with a GEM handle gets a handle ref via `drm_gem_object_handle_get_if_exists_unlocked()`, recorded in `fb->internal_flags` with `DRM_FRAMEBUFFER_HAS_HANDLE_REF(i)`, which must be released via `drm_gem_object_handle_put_unlocked()` on init error and in `drm_framebuffer_cleanup()`. In `drm_gem_object_handle_put_unlocked()`, when `--obj->handle_count == 0`, `drm_gem_object_handle_free()` and `drm_gem_object_exported_dma_buf_free()` must run while `dev->object_name_lock` is held and before `drm_gem_object_put(obj)`. [F1, F5]
- `drm_gem_fb_init_with_funcs()` transfers `drm_gem_object_lookup()` references to `fb->obj[]` on success (dropped by `drm_gem_fb_destroy()`) and puts `objs[0..i-1]` on failure; callers failing after `drm_gem_fb_init_with_funcs()` succeeds (e.g. `drm_gem_fb_afbc_init()`) must drop `fb->obj[]` references. In `drm_mode_getfb2_ioctl()`, handle creation failure on any plane must delete all handles created earlier in that call via `drm_gem_handle_delete()` after zeroing duplicate `r->handles[]` entries. [F3, F14]
- `drm_gem_shmem_vm_open()` must lock `shmem->base.resv` uninterruptibly via `dma_resv_lock()` and unconditionally increment `shmem->pages_use_count` alongside `drm_gem_vm_open(vma)`. For non-imported shmem BOs, `drm_gem_shmem_vunmap_locked()` must only `vunmap()`, clear `shmem->vaddr = NULL`, and call `drm_gem_shmem_unpin_locked()` inside `refcount_dec_and_test(&shmem->vmap_use_count)`, and `drm_gem_shmem_put_pages_locked()` must call `set_pages_array_wb()` (on x86 when `shmem->map_wc`) before `drm_gem_put_pages()`. [F8, F9, F11]
- Because `drm_gem_mmap_obj()` gets `obj` and presets `vma->vm_private_data = obj` and `vma->vm_ops` before calling `obj->funcs->mmap()`, callbacks delegating VMA ownership (`drm_gem_shmem_mmap()` via `dma_buf_mmap()` on imported BOs, or `drm_gem_ttm_mmap()` via `ttm_bo_mmap_obj()`) must call `drm_gem_object_put(obj)` on success, and `drm_gem_shmem_mmap()` must clear `vma->vm_private_data` and `vma->vm_ops` before `dma_buf_mmap()`. [F66, F153]
- In `drm_gem_vram_create()`, once `ttm_bo_init_validate()` is called with `ttm_buffer_object_destroy`, failure of `ttm_bo_init_validate()` invokes `ttm_buffer_object_destroy()` (freeing `gbo`), so the error path must not `kfree(gbo)`. `drm_gem_vram_vunmap()` keeps `gbo->map` mapped, so `drm_gem_vram_bo_driver_move_notify()` must call both `ttm_bo_vunmap()` and `iosys_map_clear(&gbo->map)`. [F15, F16]
- `drm_gem_dmabuf_export()` takes references on both `drm_device` and `drm_gem_object`, requiring `dma_buf_ops.release` to call `drm_gem_dmabuf_release()`. `drm_gem_prime_import_dev()` self-imports (`drm_gem_is_prime_exported_dma_buf()`) by incrementing `obj` refcount directly without `get_dma_buf()`/`dma_buf_attach()`, while foreign imports require `drm_prime_gem_destroy()` in `obj->funcs->free`. [F221, F222, F404]
- In `drm_gpusvm_fini()`, each notifier must be unregistered with `mmu_interval_notifier_remove()` and marked `notifier->flags.removed = true` before calling `drm_gpusvm_range_remove()` (iterating with `drm_gpusvm_for_each_notifier_safe()` / `drm_gpusvm_for_each_range_safe()`), and `mmdrop(gpusvm->mm)` must run last. [F18, F121]
- In `drm_mode_create_lease_ioctl()`, `drm_lease_create()` takes ownership of `&leases` into `lessee->leases` only on success (if it fails, call `idr_destroy(&leases)`; if `file_clone_open()` fails later, call `drm_master_put(&lessee)` without `idr_destroy(&leases)`), and after `file_clone_open()` succeeds, `drm_master_put(&lessee_priv->master)` must precede assigning `lessee_priv->master = lessee`. [F21, F79]
- In `drm_plane_force_disable()`, `__setplane_internal()`, and `drm_mode_page_flip_ioctl()`, `plane->old_fb` is set to `plane->fb` before the driver callback and must be reset to `NULL` on failure so cleanup does not put the still-bound `plane->fb`; in `drm_mode_page_flip_ioctl()`, `out:` must also put and reset `fb = NULL` before `-EDEADLK` retry, cancel `e` with `drm_event_cancel_free()`, and drop `drm_crtc_vblank_put(crtc)` only after the retry loop exits. [F231, F232]
- Every `drm_for_each_connector_iter()` loop must call `drm_connector_list_iter_end()` on all exit paths; `drm_mode_config_cleanup()` must call `flush_work(&dev->mode_config.connector_free_work)` after `drm_connector_list_iter_end()` before destroying other KMS objects or `object_idr`; and `drm_modeset_register_all()` / `drm_modeset_unregister_all()` must register in order (planes, CRTCs, encoders, connectors) and unregister in reverse (LIFO) order. [F237, F239, F325]

## API Contracts
- `drm_gem_object_lookup()`, `drm_framebuffer_lookup()`, and `drm_mode_object_find()` return `NULL` on miss (`drm_mode_object::free_cb` is NULL on static-lifetime KMS objects, making `drm_mode_object_get/put()` no-ops), whereas `drm_gem_get_pages()`, `drm_gem_shmem_get_pages_sgt()`, `drm_gem_dma_get_sg_table()`, `drm_gem_fb_create_with_funcs()`, `drm_privacy_screen_get()`, and `drm_get_panel_backlight_quirk()` return `ERR_PTR` and never `NULL`. [F47, F261, F273, F278]
- Imported `drm_gem_shmem_object` BOs (`drm_gem_is_imported(&shmem->base)`) do not use `shmem->pages` and must never be passed to `drm_gem_shmem_pin()`, `drm_gem_shmem_pin_locked()`, `drm_gem_shmem_unpin()`, or `drm_gem_shmem_get_sg_table()`. [F51]
- Shadow-plane virtual mappings (`drm_gem_fb_vmap()` / `drm_gem_fb_vunmap()`, passing base `map`, not offset-advanced `data`, to `vunmap`) must be established in `begin_fb_access` / `end_fb_access`, never in `atomic_update`; CPU access to FB GEM BOs must be bracketed with `drm_gem_fb_begin_cpu_access()` and `drm_gem_fb_end_cpu_access()`. [F151, F191, F192]
- Callers of `drm_mm_insert_node_in_range()` and `drm_mm_reserve_node()` must zero-initialize `struct drm_mm_node` first; `__drm_mm_interval_first(mm, start, last)` takes an inclusive `last` and returns `&mm->head_node` (never `NULL`) on miss; and `drm_mm_scan_add_block()` nodes must be passed to `drm_mm_scan_remove_block()` in exact reverse order before calling `drm_mm_remove_node()`. [F259, F260, F281]
- On atomic KMS drivers, `drm_object_property_set_value()` is restricted to `DRM_MODE_PROP_IMMUTABLE` properties and `drm_object_property_get_value()` is forbidden (use `drm_object_property_get_default_value()`); `drm_object_attach_property()` must only be called before object registration; and downcasting via `obj_to_connector/crtc/plane()` requires checking `obj->type` first. [F262, F358, F369]

## Error Handling
-In `bo_driver_move()`, `bo->resource` can be `NULL` during initial validation and must be handled (via `ttm_bo_move_null()` for `TTM_PL_SYSTEM` or `-EMULTIHOP`) before calling `drm_gem_vram_bo_driver_move()`; in `drm_gem_shmem_get_pages_locked()` and `drm_gem_shmem_get_pages_sgt_locked()`, `shmem->pages` and `shmem->sgt` must only be assigned after `IS_ERR()` and `dma_map_sgtable()` succeed; and `drm_gem_vmap_locked()` must convert `iosys_map_is_null(map)` into `-ENOMEM`. [F50, F53, F54]

## External Contracts
- `__drm_mode_object_find()` enforces `_drm_lease_held()` on CRTCs, connectors, and planes, while legacy ioctls accessing `crtc->primary` or `crtc->cursor` must explicitly check `drm_lease_held()`; `drm_mode_getresources()`, `drm_mode_getplane_res()`, and `drm_mode_object_get_properties()` must filter by client capability flags and leases on both count and fill passes, guarding `put_user()` with `count < user_capacity` while continuing to count all eligible items. [F326, F408, F410]

## Known Pitfalls
- In `drm_gem_put_pages()`, the `for (i = 0; i < npages; i++)` loop must advance `i += folio_nr_pages(folio) - 1` at the end of the body so multi-page folios are put once. In `drmm_release_action()` and `drmm_kfree()`, the lookup loop must save a match into a separate `dr_match` pointer rather than testing the `list_for_each_entry` cursor after the loop; similarly, `drm_mm_scan_color_evict()` must check `&hole->hole_stack == &mm->hole_stack` after `list_for_each_entry()`. [F117, F127, F319]
