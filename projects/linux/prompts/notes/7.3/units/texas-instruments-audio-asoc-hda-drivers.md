# TEXAS INSTRUMENTS AUDIO (ASoC/HDA) DRIVERS

This unit comprises Texas Instruments audio codec and smart amplifier drivers across the HDA side-codec (`tas2781_hda_i2c`) and ASoC frameworks (PCM1681/1789/179x/186x/3008/3060/3168a/5102a/512x, TAS2552/2562/2764/2770/2780/2781/2783, and TLV320 series codecs/ADCs), along with the shared TAS2781 common and DSP/RCA/calibration firmware libraries (`tas2781-comlib*`, `tas2781-fmwlib`).

## Architecture & Data Flow
- `tasdevice_regmap` in `tas2781-comlib-i2c.c` must use `REGCACHE_NONE` because one `regmap` is shared across multiple I2C addresses (`tasdev->dev_addr`) and `TASDEVICE_BOOKCTL_REG` is outside `tasdevice_ranges`. Whenever `tasdevice_change_chn_book()` or `tasdev_chn_switch()` changes `client->addr`, it must immediately write `0` to `TASDEVICE_PAGE_SELECT`, and `tasdev->cur_book` must only be updated after `regmap_write(map, TASDEVICE_BOOKCTL_REG, book)` succeeds. [F51, F52, F53]
- `tasdevice_init()` and `tas2781_system_resume()` must reset each channel's `cur_book`, `cur_prog`, and `cur_conf` in `tas_priv->tasdevice[i]` to `-1` before reset or program load; marking `tasdevice[i]` with `is_loading = true` in `tasdevice_select_tuningprm_cfg()` or `tasdevice_prmg_load()` must also reset `cur_conf = -1`. In `tasdevice_select_tuningprm_cfg()`, `tasdev_load_calibrated_data()` must run after `tasdevice_load_data(tas_priv, &(conf->dev_data))` so config defaults do not overwrite calibration. [F39, F206, F283]
- In `tas2781_hda_i2c.c`, both `tasdevice_dspfw_init()` and `tas2781_system_resume()` must check `tas_priv->rcabin.init_profile_id >= 0` after `tasdevice_prmg_load()` and apply `TASDEVICE_BIN_BLK_PRE_POWER_UP` via `tasdevice_select_cfg_blk()`. In `tasdevice_fw_ready()`, `fw_state` is set to `TASDEVICE_RCA_FW_OK` after `tasdevice_rca_parser()` and promoted to `TASDEVICE_DSP_FW_ALL_OK` only after `tasdevice_dsp_parser()` and `tasdevice_dsp_create_ctrls()` succeed; `tasdevice_tuning_switch()` and `tasdevice_startup()` must permit playback in either state. [F55, F209, F285]
- In `tas2781-fmwlib.c`, `tasdev_blk_data::dev_idx` and `tasdev_blk::dev_idx & 0x3F` use `0` as a broadcast sentinel for all `ndev` channels and `1..ndev` as 1-based indices that must be decremented by 1 before indexing `tasdevice[]` or shifting `active_dev`, while `dev_idx & 0xC0` in `tasdevice_process_block()` / `map_dev_idx()` tags RCA (`0x00`), DSP program (`0x80`), and coeff/pre (`0xC0`) blocks. Signed profile/program/config indices can be `-1` and must be checked for `>= 0` as well as upper bounds (`rca->ncfgs` and `real_nblocks`, not `nconfig`/`nblocks`). [F220, F221, F222, F248]
- In `tas2764.c`, `tas2770.c`, and `tas2562.c`, `PWR_CTRL` encodes both `dac_powered` and `unmuted`, so power/mute transitions must update those flags via `*_update_pwr_ctrl()`. `tas2764_mute()` must step through `TAS2764_PWR_CTRL_MUTE` (setting `dac_powered = true` and updating before `unmuted = !mute`, and on mute updating with `unmuted = false` and sleeping 6-7 ms before `dac_powered = false`). In `tas2770.c`, `sense_event()` must place `TAS2770_PWR_CTRL_MASK` into `SHUTDOWN` on `PRE_REG` and restore via `tas2770_update_pwr_ctrl()` on `POST_REG`. [F60, F61, F100]
- In `tas2764` and `tas2770`, deasserting `sdz_gpio`/`reset_gpio` or writing `TAS2764_RST`/`TAS2770_RST` requires a >= 1 ms delay before register access, and software reset in `tas2764_codec_probe()`/`tas2770_codec_probe()` must be immediately followed by `regmap_reinit_cache()`. During `tas2764_codec_suspend()`/`tas2770_codec_suspend()`, writing `SHUTDOWN` to `PWR_CTRL` must not clear `dac_powered` or `unmuted`, and resume must call `*_update_pwr_ctrl()` before `regcache_sync()`. [F59, F62, F122]
- `pcm512x_probe()` only fails on `-EPROBE_DEFER` from `devm_clk_get()`, so `pcm512x->sclk` can hold an `ERR_PTR` at runtime; every path accessing `sclk` must guard `clk_*` calls with `!IS_ERR(pcm512x->sclk)`, and `pcm512x_dai_startup_master()` must reject master mode when `IS_ERR(pcm512x->sclk)`. `pcm512x_i2c_probe()` must copy `pcm512x_regmap` to a local struct before setting `read_flag_mask`/`write_flag_mask = 0x80` so SPI is unaffected. [F32, F69]
- In `tlv320aic31xx.c`, DAC-only variants (`codec_type & DAC31XX_BIT`) must skip ADC controls, widgets, routes, and capture DAI registration. When `sysclk_id == AIC31XX_PLL_CLKIN_BCLK`, `aic31xx_hw_params()` must set `sysclk = rate * width * channels` and `p_div = 1` before `aic31xx_setup_pll()`, which must verify `sysclk` and `p_div` are non-zero and only assign `rate_div_line = match` when `match != -1`. `aic31xx_power_on()` must call `aic31xx_set_jack()` after `regcache_sync()` to restore volatile `AIC31XX_HSDETECT`. [F216, F217, F237, F264, F295]

## Synchronization
- All post-probe paths in `tas2781_hda_i2c.c` and `tas2781-i2c.c` that access amplifier registers or invoke `tas2781-fmwlib.c` helpers (`tasdevice_rca_parser`, `tasdevice_dsp_parser`, `tas2781_load_calibration`, `tasdevice_prmg_load`, `tasdevice_select_cfg_blk`, `tasdevice_tuning_switch`, `tasdevice_amp_getvol`/`putvol`, `tasdevice_dev_*`) must hold `tas_priv->codec_lock`, because `tasdevice_change_chn_book()` mutates the shared `i2c_client->addr`, `TASDEVICE_PAGE_SELECT`, and `tasdev->cur_book` without internal locking in fmwlib. [F19, F177]
- In `tascodec_init()` (`tas2781_hda_i2c.c`), `tas_priv->codec` must be assigned before `request_firmware_nowait()` is invoked because `tasdev_fw_ready()` reads `tas_priv->codec` before acquiring `tas_priv->codec_lock`. In `tasdevice_dspfw_init()`, `tasdevice_dsp_prog_ctrl` and `tasdevice_dsp_conf_ctrl` must only be registered via `tasdev_add_kcontrols()` after `tasdevice_dsp_parser()` succeeds and populates `tas_priv->fmw`. In `tasdevice_i2c_probe()`, `tasdevice_parse_dt()`, `tasdevice_init()`, and `tasdevice_reset()` must complete before `devm_snd_soc_register_component()`. [F17, F21, F181]
- In `tas2783-sdw.c`, `tas_io_init()` and `tas_update_status()` must not hold `tas_dev->pde_lock` or `tas_dev->calib_lock` while waiting on `tas_dev->fw_wait`, because `tas2783_fw_ready()` acquires `pde_lock` and `calib_lock` (via `tas2783_update_calibdata()`) before setting `fw_dl_task_done` and calling `wake_up(&tas_dev->fw_wait)`. [F301]
- `tas2764_irq()` and `aic31xx_irq()` perform sleeping I2C register accesses and must be registered as threaded interrupt handlers (`IRQF_ONESHOT` with a `NULL` hardirq handler). In `tas2764_codec_probe()`, `tas2764->component` assignment, `tas2764_reset()`, `regmap_reinit_cache()`, and `TAS2764_INT_MASK0..4` configuration (`0` = unmasked, `1` = masked) must complete before `devm_request_threaded_irq()`. In `tlv320aic31xx.c`, `aic31xx_irq()` must check `if (aic31xx->jack)` before calling `snd_soc_jack_report()`. [F26, F123, F143, F186, F306]
- In `pcm1789.c`, `pcm1789_common_init()` must initialize `pcm1789->regmap`, `pcm1789->dev`, and `INIT_WORK(&pcm1789->work, pcm1789_work_queue)` before `devm_snd_soc_register_component()`. `pcm1789_trigger()` runs in atomic trigger context and must defer the sleeping `regmap_update_bits()` soft-reset write via `schedule_work(&priv->work)`, while `pcm1789_common_exit()` must call `flush_work(&priv->work)` on removal. [F25, F142]

## Object Lifetimes
- In `tas2781_hda_i2c_probe()`, `tasdevice_init()` must be called after `tas2781_read_acpi()` sets `tas_priv->ndev` and before `pm_runtime_enable()` and `component_add()`, and any subsequent failure in probe must jump to `err:` so `tas2781_hda_remove()` calls `tasdevice_remove()` (after `component_del()` and `pm_runtime_disable()`) to destroy `codec_lock`. [F7, F22]
- In `tas2781_hda_unbind()`, `comp->playback_hook` (along with `comp->dev` and `comp->name`) must be cleared, `tas_hda->priv->fw_state` reset to `TASDEVICE_DSP_FW_PENDING`, and `tas2781_hda_remove_controls()` called before `tasdevice_config_info_remove()` and `tasdevice_dsp_remove()` free `tas_priv->fmw` and RCA config state. `tasdevice_dsp_remove()` must always set `tas_dev->fmw = NULL` and must also be called before reloading firmware in `tasdevice_dspfw_init()`. [F20, F58, F120]
- `tasdevice_fw_ready()` and `tas2781_load_calibration()` must jump to `out:` on every exit path to call `release_firmware()` (and unlock `tas_priv->codec_lock` in `tasdevice_fw_ready()`), leaving `tasdev->cali_data_fmw` attached on calibration parse failure so `tasdevice_calbin_remove()` frees it and sets `cali_data_fmw = NULL`. In `tas2781-fmwlib.c`, `tasdevice_rca::cfg_info` and `tasdevice_config_info::blk_data` are pointer arrays whose elements must be individually `kfree`d in `tasdevice_config_info_remove()`, whereas `programs`, `configs`, `calibrations`, and `dev_blks` are contiguous `kcalloc` struct arrays where only `block->data` and the array base pointer are freed. [F161, F166, F268, F269]
- In `tas2781-i2c.c`, `tasdev[i].cali_data_backup` is allocated with non-devm `kmemdup()` in `tasdevice_create_cali_ctrls()` and must be freed with `kfree()` in `tasdevice_deinit()`, whereas dynamically created `snd_kcontrol_new` arrays, control names, `soc_bytes_ext` structs, and `cali_data->data` use `devm_*` and must not be manually freed. [F167]
- Non-devres clocks, regulators, and runtime PM must be unwound in reverse order on probe/resume failure and removal: in `pcm3168a_probe()` and `pcm3168a_rt_resume()`, `clk_prepare_enable(scki)` precedes `regulator_bulk_enable(supplies)`, so rollback and `pcm3168a_disable()` must disable supplies before unpreparing `scki`; in `pcm512x_probe()`, `regulator_bulk_enable()`, `clk_prepare_enable(sclk)`, and `pm_runtime_enable()` must unwind via `err_pm`, `err_clk`, and `err`; in `tlv320aic32x4.c`, `aic32x4_setup_regulators()` must guard optional `ERR_PTR`-valued `supply_ldo`, `supply_dv`, and `supply_av` with `!IS_ERR(...)` and unwind in reverse order. [F10, F130, F170, F171]

## API Contracts
- Because `tas2781-comlib*` and `tas2781-fmwlib.c` are shared between ASoC (`drvdata` is `struct tasdevice_priv *`, `tas_priv->codec` is `struct snd_soc_component *`) and HDA (`drvdata` is `struct tas2781_hda *`, `tas_priv->codec` is `struct hda_codec *`), shared helpers must never call `dev_set_drvdata()`/`dev_get_drvdata()` on `tas_priv->dev` or downcast `tas_priv->codec`. In `tas2781_hda_i2c.c`, callers of `tasdevice_*` firmware helpers must pass `tas_hda->priv` (never `tas_hda` or `tas_hda->hda_priv`, which is `struct tas2781_hda_i2c_priv *`), and HDA kcontrol callbacks must use `snd_kcontrol_chip(kcontrol)` as `struct tasdevice_priv *`. [F54, F109, F110, F111, F112, F151, F275]
- `tasdevice_dev_read()`, `tasdevice_dev_bulk_read()`, `tasdevice_dev_write()`, `tasdevice_dev_bulk_write()`, and `tasdevice_dev_update_bits()` must validate `chn < tas_priv->ndev`, select `TASDEVICE_BOOK_ID(reg)` via `change_chn_book()`, and pass `TASDEVICE_PGRG(reg)` (never the composite `reg`) to `regmap`. Unlike those helpers, `tasdev_chn_switch()` does not bounds-check `chn < tas_priv->ndev` and must return `1` when changing `client->addr`, `0` when unchanged, or a negative errno on `regmap_write` failure. All `tas2781-fmwlib.c` exports must use `EXPORT_SYMBOL_NS_GPL(..., "SND_SOC_TAS2781_FMWLIB")`. [F27, F77, F78, F321]
- In TDM slot callbacks (`tas2764`, `tas2770`, `tas2780`, `tas2562`, `tas2552`, `pcm186x`), `tx_mask` must be verified non-zero before calling `__ffs(tx_mask)` or `__fls(tx_mask)`: `tas2764`, `tas2770`, and `tas2780` must accept 1 or 2 set bits and clear each consumed bit in `tx_mask` before the trailing validation check; `tas2552` requires two adjacent bits (`(__ffs(tx_mask) + 1) == __fls(tx_mask)`); `pcm186x` requires contiguous bits and `__ffs(tx_mask) * slot_width <= 255`; and `tas2562`, `tas2770`, and `pcm3168a` must accept `slot_width == 0`. [F83, F86, F87, F91, F107, F146]

## Error Handling
- `tasdevice_add_config()` never clears `*status` on success and returns a non-NULL partially populated `struct tasdevice_config_info *` on error (which `tasdevice_rca_parser()` stores in `rca->cfg_info[i]` after incrementing `rca->ncfgs`), so callers must initialize `status = 0`, check `status` rather than testing the pointer for `NULL`, and call `tasdevice_config_info_remove()` if `tasdevice_rca_parser()` fails. [F163, F189]
- In `pcm186x_power_on()` and `aic31xx_power_on()`, if `regcache_sync()` fails after `regulator_bulk_enable()` and `regcache_cache_only(..., false)`, the error path must restore `regcache_cache_only(..., true)` and call `regulator_bulk_disable()`. In `tas2770_codec_suspend()`, if `snd_soc_component_update_bits()` fails while in cache-only mode, it must restore `regcache_cache_only(regmap, false)` and `regcache_sync()`, and on success must return `0` (not the positive bit-change return). In `tas2552_probe()`, failure after `pm_runtime_put_sync_autosuspend()` must call `pm_runtime_get_noresume()`. [F14, F36, F37, F173]

## External Contracts
- In `tas2563_save_calibration()`, `efi_rt_services_supported(EFI_RT_SUPPORTED_GET_VARIABLE)` must be checked before `efi.get_variable()`. On every inner loop iteration, `efi_name` must be zeroed (`memset(efi_name, 0, sizeof(efi_name))`) before copying up to `sizeof(var8)` (`TAS2563_CAL_VAR_NAME_MAX`) ASCII chars from `var8` (formatted with 1-based index `i + 1`). `cd->data` must contain `p->ndev` records of `cd->cali_dat_sz_per_dev + 1` bytes: a 1-byte 0-based index `i` followed by `TASDEV_CALIB_N` big-endian `__be32` values. [F31, F41, F44, F114]

## Known Pitfalls
- In `tas2781-i2c.c`, `tas2781_cali_start_reg[]` must keep the four 4-byte calibration registers at the end for `sngl_calib_start()`, mark protected test registers (`TAS2781_PRM_TEST_57_REG`, `TAS2781_PRM_TEST_62_REG`) with `is_locked = true` via `X2781_CL_STT_VAL`, and read current hardware values into `cali_data_backup` (where `bulk_reg_val::val` must remain >= 4 bytes because `tasdevice_dev_read` casts `&p[j].val[0]` to `int *`) before writing start values; `cali_reg_update()` and `partial_cali_data_update()` must switch on the immutable `tas2781_cali_start_reg[j].reg` template rather than `p[j].reg`. [F210, F211, F229, F272, F282]
- In `tas2781`, `tas_priv->cali_data.cali_reg_array.r0_reg` is an encoded `unsigned int` register (`tasdev_r0_data_get()`), whereas `tas_priv->fmw->fct_par_addr.r0_reg` is a 3-byte `[book, page, reg]` array (`tasdev_re_data_get()`). In `tas2781-fmwlib.c`, `fw_parse_variable_hdr*()` must reject `fw_hdr->device >= TASDEVICE_DSP_TAS_MAX_DEVICE` or `== 6`; `tasdev_multibytes_chksum()` must reject `(reg + len - 1) > 127`; and `tasdevice_config::name` / `tasdevice_data::name` (`char[64]`) are not NUL-terminated. [F224, F228, F255, F279]
