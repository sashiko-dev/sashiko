# DRM DRIVERS

This unit defines core DRM/KMS subsystem headers (`include/drm/*.h`), display protocol and bridge helpers (`include/drm/display/*.h`, `include/drm/bridge/*.h`), standard and driver UAPI headers (`include/uapi/drm/*.h`), AMD ASIC definitions, and the safe Rust DRM kernel abstractions (`kernel::drm`).

## Architecture & Data Flow

- `drm_atomic_state.connectors` is dynamically sized to `state->num_connector` with `NULL` holes at unplugged indices: direct lookups by `drm_connector_index()` must check `index < state->num_connector` first, and sparse-array iterators (`for_each_oldnew_*_in_state`, `for_each_old_*_in_state`, `for_each_new_*_in_state` for connectors, CRTCs, and planes) must only assign cursor variables inside `for_each_if` after checking `(__state)->...[__i].ptr != NULL`. [F79, F96]
- In `struct drm_plane_state`, `crtc` and `fb` must be coupled so both are non-NULL when enabled and both are NULL when disabled (`WARN_ON` in `drm_atomic_plane_enabling()` / `drm_atomic_plane_disabling()`). [F67]
- `drm_connector.registration_state` is a tristate (`DRM_CONNECTOR_INITIALIZING`, `DRM_CONNECTOR_REGISTERED`, `DRM_CONNECTOR_UNREGISTERED`); `drm_connector_is_unregistered()` is true only for `DRM_CONNECTOR_UNREGISTERED`, permitting modesets during initialization while blocking userspace modesets on removed connectors. [F126]
- In `struct drm_dp_mst_branch`, `port_parent` is `NULL` and `rad[8]` is all zeros (`lct == 1`) for the root primary branch `mgr->mst_primary`; `rad` nibbles are only valid for link counts `2 .. mstb->lct`. [F52]
- `drm_writeback_connector::encoder` is only initialized by `drm_writeback_connector_init`; when initialized via `drm_writeback_connector_init_with_encoder` or `drmm_writeback_connector_init`, the external `struct drm_encoder *enc` is attached and `wb_connector->encoder` is invalid. [F202]
- Per-device feature overrides must modify `drm_device.driver_features` rather than the shared `drm_driver.driver_features`, checked via `drm_core_check_feature()` or `drm_core_check_all_features()`; `DRIVER_COMPUTE_ACCEL` must never be combined with `DRIVER_RENDER` or `DRIVER_MODESET`. [F64, F124]
- In `impl drm::Driver for T`, `<T::File as DriverFile>::Driver` must equal `T`, because `Device<T>::VTABLE` wires `File::<T::File>::open_callback` which casts `raw_dev` (`Device<T>`) to `&Device<<T::File as DriverFile>::Driver>`. [F261]
- `struct drm_rect` (`x1, y1` inclusive; `x2, y2` exclusive) must keep the exact field order and 32-bit signed layout of UAPI `struct drm_mode_rect` for direct casting in `drm_atomic_helper_damage_iter_init()`; `drm_rect_fp_to_int()` must compute `dst->x2` and `dst->y2` from `(src->x1 >> 16) + (drm_rect_width(src) >> 16)`, not `src->x2 >> 16`. [F218, F249]

## Synchronization

- `drm_device.vbl_lock` is the outer spinlock wrapping inner `vblank_time_lock`; `drm_crtc_funcs` callbacks `enable_vblank`, `disable_vblank`, `get_vblank_counter`, and `get_vblank_timestamp` run with both held and IRQs disabled and must never sleep. `drm_vblank_crtc.last` requires `vbl_lock`, `hwmode` is only valid while `enabled` is true, and `count` must be read via `drm_crtc_vblank_count()` or `drm_crtc_vblank_count_and_time()`. [F134, F179, F213]
- `drm_syncobj.fence` must not be dereferenced directly: lockless readers must hold a `drm_syncobj` reference and call `drm_syncobj_fence_get()` (`dma_fence_get_rcu_safe`), while updates to `fence`, `cb_list`, and `ev_fd_list` must hold `drm_syncobj.lock`. [F177]
- Between `drm_vma_offset_lock_lookup(mgr)` and `drm_vma_offset_unlock_lookup(mgr)`, callers run in atomic context, must only call `drm_vma_offset_lookup_locked` or `drm_vma_offset_exact_lookup_locked`, and must pin any returned object's reference before unlocking. `drm_vma_node_unmap()` accesses `node->vm_node` unlocked and requires external serialization against `drm_vma_offset_remove()`. [F180, F181]
- In `struct drm_dp_mst_topology_mgr`, `payload_count` and `next_start_slot` must only be accessed in atomic commit context (never `atomic_check`); `drm_dp_mst_atomic_payload.vc_start_slot` is undefined during `atomic_check` and may only be read in commit after `drm_dp_mst_atomic_wait_for_dependencies()` (and after `drm_dp_add_payload_part1()` / `drm_dp_remove_payload_part2()` for updated slots) or under the MST modeset lock after `drm_crtc_commit_wait()` on `commit_deps`. [F24, F25]
- In `struct drm_dp_mst_topology_mgr`: `port->mstb` and `mstb->ports` are modified only by `mgr->work` and `mgr->up_req_work` under both `mgr->probe_lock` and `mgr->lock` (other readers need `mgr->lock`); `up_req_recv` and `down_rep_recv` are read unlocked so removal must set `mgr->reset_rx_state = true` under `mgr->lock` instead of clearing them directly; `qlock`, `delayed_destroy_lock`, and `up_req_lock` protect `tx_msg_downq`, `destroy_*_list`, and `up_req_list`. [F22, F27, F138]
- When a `struct drm_private_obj` shares state across multiple CRTCs, drivers must store a `struct drm_crtc_commit` reference in the private state during `atomic_commit_setup` and wait for it at the start of `atomic_commit_tail` to prevent out-of-order non-blocking commits from freeing the state. [F29]
- In `struct drm_connector`: `registration_state` updates require `connector->mutex` and unlocked reads must use `drm_connector_is_unregistered()`; `mode_config.connection_mutex` protects `state`; `mode_config.mutex` protects `modes`, `status`, `probed_modes`, `display_info`, and `edid_blob_ptr`; `eld_mutex`, `edid_override_mutex`, `hdmi.infoframes.lock`, and `hdmi_audio.lock` protect `eld`, `edid_override`, `audio`, and `plugged_cb`. [F34, F40]
- `drm_dev_is_unplugged()` drops its critical section immediately and races with `drm_dev_unplug()`; drivers must wrap hardware accesses in `if (drm_dev_enter(dev, &idx)) { ... drm_dev_exit(idx); }`, noting that calling `drm_dev_unplug()` before `drm_atomic_helper_shutdown()` causes `drm_dev_enter()`-guarded disable callbacks to be skipped. [F35, F120]
- `spsc_queue_push` must set `node->next = NULL` before `atomic_long_xchg(&queue->tail, (long)&node->next)` and keep preemption disabled across `atomic_long_xchg` and `WRITE_ONCE(*tail, node)`; in `spsc_queue_pop`, if `READ_ONCE(node->next)` is NULL and `atomic_long_cmpxchg` fails, the consumer must spin with `smp_rmb()` until `node->next` is non-NULL and store it into `queue->head`. [F175, F176]
- A successful `drm_client_buffer_vmap_local()` leaves `buffer->gem` locked and mapped and must pair with `drm_client_buffer_vunmap_local()` on all exit paths; `drm_client_dev` must be initialized before `drm_client_register()` publishes `client->list` under `clientlist_mutex`, and `drm_client_for_each_modeset()` requires `client->modeset_mutex`. [F15, F31]

## Object Lifetimes

- Drivers and atomic helpers must call `drm_plane_helper_funcs.end_fb_access` and finish all reads of `new_crtc_state` and `new_plane_state` before `drm_atomic_helper_commit_hw_done()`, because signaling `hw_done` allows the next commit to swap and free those states. [F3]
- When `drm_atomic_helper_setup_commit()` takes an extra reference on `struct drm_crtc_commit` for `new_crtc_state->event->base.completion`, it sets `commit->abort_completion = true` so `__drm_atomic_helper_crtc_destroy_state()` drops that reference if the commit aborts while `state->event` is non-NULL. [F5]
- `drm_connector_state.crtc` must only be modified via `drm_atomic_set_crtc_for_connector()` to keep connector refcounts and `crtc_state->connector_mask` symmetric. [F20]
- `struct drm_private_obj` instances must be initialized with `drm_atomic_private_obj_init()` before `drm_dev_register()` and cleaned up with `drm_atomic_private_obj_fini()` only after `drm_dev_unregister()`, and once `drm_client_register()` is called on a `drm_client_dev`, callers must not call `drm_client_release()` outside `drm_client_funcs.unregister`. [F1, F14]
- A `struct drm_connector *` from `drm_connector_list_iter_next()` or `drm_for_each_connector_iter()` is only valid until the next step or `drm_connector_list_iter_end()` unless pinned with `drm_connector_get()`, and every `drm_connector_list_iter_begin()` must pair with `drm_connector_list_iter_end()` on all exit paths. [F11]
- Drivers retaining a `struct drm_dp_mst_port *` must acquire a malloc reference via `drm_dp_mst_get_port_malloc()` inside `drm_dp_mst_topology_cbs.add_connector` and release it with `drm_dp_mst_put_port_malloc()`, never touching `topology_kref`. [F17]
- In Rust `kernel::drm`: `Device::release` must only call `core::ptr::drop_in_place` without freeing the backing pointer (freed by C DRM core); `AlwaysRefCounted::dec_ref` for `drm::Device<T>` and `IntoGEMObject` must drop any `&Self` reference before calling `drm_dev_put` or `drm_gem_object_put`; and `File<T>::inner` must never be called before `open_callback` sets `driver_priv` or after `postclose_callback` runs. [F164, F264, F265]
- Reference rules: assigning `drm_connector.fwnode` transfers a caller-held `fwnode_handle` reference released by `drm_connector_cleanup()`; `drm_dev_set_dma_dev()` / `drm_dev_dma_dev()` must be used instead of direct `dev->dma_dev` access; `drm_file_get_master()` must pair with `drm_master_put(&master)`; and `drm_dp_tunnel_get()` / `drm_dp_tunnel_ref_get()` must pair with `drm_dp_tunnel_put()` / `drm_dp_tunnel_ref_put()`. [F12, F16, F18, F123]

## API Contracts

- Atomic KMS drivers (`drm_drv_uses_atomic_modeset()`) must implement both `atomic_duplicate_state` (returning `NULL` on failure, never `ERR_PTR`, and incrementing refcounts of all copied refcounted objects) and `atomic_destroy_state` (releasing those references) on `drm_crtc_funcs` and `drm_connector_funcs`, while `atomic_set_property` must only update the passed-in `state` without mutating hardware/persistent state or cross-checking properties. [F7, F45, F147, F151]
- For DRM-managed init helpers (`drmm_crtc_init_with_planes()`, `drmm_crtc_alloc_with_planes()`, `drmm_connector_init()`, `drmm_connector_hdmi_init()`), `funcs->destroy` must be `NULL`; for unmanaged init helpers (`drm_crtc_init_with_planes()`, `drm_connector_init*()`), `funcs->destroy` must be non-NULL. [F53]
- The DRM core calls `drm_crtc_vblank_get()` before `drm_crtc_funcs.page_flip_target` and calls `drm_crtc_vblank_put()` itself on non-zero error return; on a `0` return, the driver owns the vblank reference and must call `drm_crtc_vblank_put()` when the flip completes. [F8]
- KMS drivers must call `drm_crtc_vblank_off` when disabling a CRTC and `drm_crtc_vblank_on` when enabling it; `drm_crtc_set_max_vblank_count` requires `dev->max_vblank_count == 0`, `vblank->inmodeset` non-zero (before `drm_crtc_vblank_on`), and `get_vblank_counter` implemented; any non-zero `max_vblank_count` must be a low-bit mask `(1 << N) - 1`. [F110, F201, F270]
- Drivers must never modify `drm_atomic_state.allow_modeset`, must use `drm_atomic_crtc_needs_modeset()` instead of `allow_modeset` in commit paths, must check `allow_modeset` before adding unrelated CRTCs via `drm_atomic_get_crtc_state()`, and must check `state->duplicated` in atomic check paths to permit or fix up states cloned by `drm_atomic_helper_duplicate_state()`. [F65, F76]
- `drm_vma_offset_manager_init`, `drm_vma_offset_lookup_locked`, `drm_vma_offset_add`, `drm_vma_node_start`, and `drm_vma_node_size` use page units whereas `drm_vma_node_offset_addr` returns a byte offset (`<< PAGE_SHIFT`); `drm_vma_offset_exact_lookup_locked()` must be used when an exact base-offset match (`node->vm_node.start == start`) is required; and `drm_vma_node_reset` must never be called on a node still in a manager. [F191, F211, F243]
- `drm_dp_calc_pbn_mode()`, `drm_dp_bw_overhead()`, `drm_dp_link_symbol_cycles()`, and `drm_dsc_config.bits_per_pixel` all use `.4` binary fixed-point bits-per-pixel (`bpp << 4`, in 1/16-bpp units; extract integer bpp via `>> 4` or `drm_dsc_get_bpp_int()`). [F55, F109]
- Any signature change to `#if` / `#ifdef` guarded functions in `include/drm/bridge/aux-bridge.h`, `include/drm/drm_debugfs.h`, `include/drm/drm_drv.h`, or `include/drm/display/drm_dp_tunnel.h` must be updated in lockstep with their `#else` inline stubs. [F60, F61, F77]

## Error Handling

- `drm_syncobj_find` and `drm_syncobj_fence_get` return `NULL` (never `ERR_PTR`) when absent, whereas `drm_syncobj_find_fence` returns `0` or negative errno; `drm_get_panel_backlight_quirk` returns `ERR_PTR` (never `NULL`) when unmatched; and `devm_drm_dp_hpd_bridge_alloc()` / `drm_dp_hpd_bridge_register()` return `ERR_PTR` when `CONFIG_DRM_AUX_HPD_BRIDGE` is enabled but `NULL` when disabled. [F46, F196, F204]
- `drm_vblank_work_schedule` returns `1` when scheduled/rescheduled, `0` when already scheduled at `count`, cancelling, or in modeset, and `< 0` on `drm_vblank_get` failure; `drm_dp_tunnel_update_state()` and `drm_dp_tunnel_handle_irq()` return `1` when state changed, `0` when unchanged, or `< 0` on error, while `drm_dp_tunnel_get_allocated_bw()` and `drm_dp_tunnel_available_bw()` return `-1` when undetermined or disabled. [F48, F200]

## External Contracts

- In `struct drm_crtc_state`, `enable` governs shared resource reservation while `active` governs hardware DPMS state (with `self_refresh_active` set when in self-refresh, checked via `drm_atomic_crtc_effectively_active()`); drivers must not free shared resources when `active` becomes `false` while `enable` is `true` or fail `atomic_check` when flipping `active`, and atomic drivers must populate `drm_connector_state.best_encoder`. [F69, F70, F103]
- Framebuffer & GEM UAPI: GEM handles on a `drm_file` are not refcounted and `DRM_IOCTL_PRIME_FD_TO_HANDLE` deduplicates handles (unlike `DRM_IOCTL_MODE_GETFB2`), so `DRM_IOCTL_GEM_CLOSE` must be called once per unique handle; in `struct drm_mode_fb_cmd2`, `modifier[4]` is only valid when `DRM_MODE_FB_MODIFIERS` is set (identical across used planes), unused plane slots must be zero, and `GETFB2` zeroes `handles` unless master or `CAP_SYS_ADMIN`. [F174, F207, F225]

## Known Pitfalls

- Despite their `ssize_t` return type, `drm_scdc_read()`, `drm_scdc_write()`, `drm_dp_dual_mode_read()`, and `drm_dp_dual_mode_write()` return `0` on success and negative errno on failure, never the byte count. [F42]
- Before state swap in `atomic_check`, callers must iterate planes on a CRTC using `drm_atomic_crtc_state_for_each_plane()` or `drm_atomic_crtc_state_for_each_plane_state()` on the incoming `crtc_state`, not `drm_atomic_crtc_for_each_plane()` (which walks `crtc->state->plane_mask`). [F100]
- In `enum drm_dp_phy`, `DP_PHY_DPRX` is `0` while LTTPRs are 1-based (`DP_PHY_LTTPR1 = 1 .. 8`); `DP_LTTPR_BASE`/`DP_LTTPR_REG` and `DP_FEC_BASE`/`DP_FEC_REG` subtract `DP_PHY_LTTPR1` and must only be called with `DP_PHY_LTTPR(i)`, never `DP_PHY_DPRX` or an unshifted 0-based index. [F84]
- Multi-bit fields and masks: DPCD subfields like `DP_DSC_MAX_BITS_PER_PIXEL_HI` and `DP_DSC_BITS_PER_PIXEL_INC` must be masked with `(val & MASK)` parenthesized before shifting or comparing; `DRM_MODE_PROP_OBJECT` and `DRM_MODE_PROP_SIGNED_RANGE` must be tested with `(flags & DRM_MODE_PROP_EXTENDED_TYPE) == type`; `OMAP_BO_TILED_*` and `OMAP_BO_CACHE_*` must be masked with `OMAP_BO_TILED_MASK` / `OMAP_BO_CACHE_MASK` and compared for equality; and HDMI YCbCr 4:4:4 deep color checks must use `edid_hdmi_ycbcr444_dc_modes`, not `edid_hdmi_rgb444_dc_modes`. [F98, F125, F206, F241, F242]
