# DAMON

DAMON (Data Access Monitor) is a Linux kernel memory management subsystem that monitors memory access patterns using adaptive region splitting/merging and sampling, and applies DAMOS (DAMON-based Operation Schemes) actions such as page reclamation, LRU sorting, madvise, and NUMA page migration. It provides a core monitoring framework with pluggable address-space operation sets for virtual (`vaddr`, `fvaddr`) and physical (`paddr`) memory, a hierarchical sysfs control interface (`/sys/kernel/mm/damon/admin`), and standalone kernel module policies (`damon_reclaim`, `damon_lru_sort`, and `damon_stat`).

## Architecture & Data Flow
- `damos_commit*()` helpers must copy all user-configurable fields and active union members from `src` to `dst` while preserving `dst`'s runtime accounting (`last_psi_total`, `quota`, `stat`). `damos_new_filter()` does not zero `damos_filter`'s union: `damos_commit_filter()` and `damos_commit_quota_goal()` must assign `dst->type` / `dst->metric` before calling `damos_commit_filter_arg()` / `damos_commit_quota_goal_union()`, which switch on the discriminator to copy only the active member (`current_value` for `DAMOS_QUOTA_USER_INPUT`, `nid` for `DAMOS_QUOTA_NODE_MEM_USED_BP` / `FREE_BP`). [F41, F42, F70, F81]
- In `damos_set_filters_default_reject()`, if `s->ops_filters` is non-empty, `s->core_filters_default_reject` must be forced to `false` so regions unmatched by core filters reach the ops filter stage. When `damos_filter_out()` matches a core filter with `filter->allow` set, it sets `s->core_filters_allowed = true`; `damos_va_filter_out()` and `damos_pa_filter_out()` must return `false` when `scheme->core_filters_allowed` is true before iterating `scheme->ops_filters`. [F77, F78]
- Adding an `enum damos_filter_type` value requires updating `damos_filter_for_ops()` (routing `damos_add_filter()` between `s->filters` and `s->ops_filters`), the core or ops filter matcher, `damos_commit_filter_arg()`, `damos_sysfs_filter_type_names[]`, and `damon_sysfs_add_scheme_filters()`. [F76]
- Because `damon_attrs->sample_interval` can be `0`, interval-to-sample-count divisions in `damon_set_attrs()`, `damos_set_next_apply_sis()`, `kdamond_apply_schemes()`, `kdamond_merge_regions()`, `kdamond_init_ctx()`, and `kdamond_fn()` must substitute `1` when `sample_interval == 0`. Whenever `damos->apply_interval_us == 0`, interval calculations in `damos_set_next_apply_sis()`, `kdamond_apply_schemes()`, and `kdamond_init_ctx()` must substitute `ctx->attrs.aggr_interval` (not `sample_interval` or `0`). [F80, F102]
- In `struct damos`, `migrate_dests.nr_dests` discriminates between weighted multi-node and single-node migration: `damos_va_migrate()` and `damos_va_migrate_dests_add()` must check `dests->nr_dests == 0` and use `s->target_nid` instead of dereferencing `dests->node_id_arr` or `dests->weight_arr`. [F43]
- Functions mapping running `damon_ctx` schemes to `sysfs_schemes->schemes_arr` by positional index (`damos_sysfs_set_quota_scores()`, `damos_sysfs_update_effective_quotas()`, `damon_sysfs_schemes_update_stats()`, `damos_sysfs_populate_region_dir()`) must verify the index is `< sysfs_schemes->nr`. [F153]
- Every `damos_quota_goal` added to `quota->goals` must have a non-zero `target_value` (enforced by skipping `!sysfs_goal->target_value` in `damos_sysfs_add_quota_score()`) because `damos_quota_score()` divides by `goal->target_value` without a zero check. [F108]
- `damos_walk_call_walk()` must return early when `s->walk_completed` is true, and `damos_walk_complete()` must only clear `s->walk_completed` across all schemes and complete `control->completion` once every scheme in `ctx` has set `walk_completed = true`. [F86]
- `struct damon_operations` callbacks (`init`, `update`, `get_scheme_score`, `apply_scheme`, `target_valid`, `cleanup_target`, `cleanup`) are optional and left `NULL` by backends like `DAMON_OPS_PADDR` and `DAMON_OPS_FVADDR`; callers in `mm/damon/core.c` must check each pointer for non-NULL before calling it. [F39]
- `damon_sysfs_cmd_strs[]` is indexed directly by `enum damon_sysfs_cmd` in `state_show()` and `state_store()` (up to `NR_DAMON_SYSFS_CMDS`), so `enum damon_sysfs_cmd`, `damon_sysfs_cmd_strs[]`, and `damon_sysfs_handle_cmd()` must be updated in lockstep. [F75]

## Synchronization
- `ctx->kdamond_lock` only protects `ctx->kdamond`; while a `damon_ctx` is running, any external read or update of its internal fields (`attrs`, `adaptive_targets`, `schemes`, `regions`, or quota goals) must execute on the kdamond thread via `damon_call()` or `damos_walk()`. [F24]
- In `kdamond_call()`, a non-repeating `damon_call_control` must be removed from `ctx->call_controls` under `ctx->call_controls_lock` before calling `complete(&control->completion)`, because `damon_call()` allocates non-repeating control structs on the stack. [F22]
- Sysfs handlers and callbacks dereferencing `kdamond->damon_ctx` (`state_show()`, `pid_show()`, `state_store()`) must hold `damon_sysfs_lock`. Because `state_store()` holds `damon_sysfs_lock` while waiting on `damon_call()` or `damos_walk()`, repeating kdamond callbacks (`damon_sysfs_repeat_call_fn()`) must use `mutex_trylock(&damon_sysfs_lock)` and synchronous callbacks from `damon_sysfs_handle_cmd()` must not acquire `damon_sysfs_lock`. [F25, F124]
- `damon_sysfs_kdamonds_add_dirs()` must verify no existing kdamond is running via `damon_sysfs_kdamonds_busy()` before calling `damon_sysfs_kdamonds_rm_dirs()`, because `kdamond_fn()` and `damon_sysfs_repeat_call_fn()` hold uncounted pointers to `damon_ctx` and `damon_sysfs_kdamond`. [F28]
- `__damon_start()` must reinitialize `ctx->kdamond_started` before `kthread_run()` and wait on `wait_for_completion(&ctx->kdamond_started)` while holding `ctx->kdamond_lock` so `kdamond_fn()` is guaranteed to run its teardown if `damon_stop()` is called immediately. `damon_start()` and `kdamond_fn()` must also maintain `nr_running_ctxs` and `running_exclusive_ctxs` in lockstep under `damon_lock`, clearing `running_exclusive_ctxs = false` when `nr_running_ctxs` reaches zero. [F19, F67]
- `kdamond_apply_schemes()` holds `c->walk_control_lock` across `damon_do_apply_schemes()` and `damos_walk_complete()`, so `damos_walk_control->walk_fn` and `damon_operations->apply_scheme` callbacks must not call `damos_walk()` or `damos_walk_cancel()` on the same `damon_ctx`. [F123]
- `damos_va_filter_out()` must handle `DAMOS_FILTER_TYPE_YOUNG` via `damos_va_filter_young_match()` using the caller's already-locked `ptep` or `pmdp` rather than calling `damos_folio_filter_match()`, which performs an `rmap_walk()` that takes sleeping `anon_vma`/folio locks and re-locks page table spinlocks. [F128]
- `__damon_va_three_regions()` must enclose its `for_each_vma(vmi, vma)` traversal in `rcu_read_lock()` / `rcu_read_unlock()`. Likewise, `damos_folio_filter_match()` must call `folio_memcg_check(folio)` and `mem_cgroup_id(memcg)` inside `rcu_read_lock()` / `rcu_read_unlock()` for `DAMOS_FILTER_TYPE_MEMCG`. [F125, F126]

## Object Lifetimes
- `damon_destroy_target(t, ctx)` invokes `ctx->ops.cleanup_target(t)` (calling `put_pid(t->pid)` for `DAMON_OPS_VADDR` and `DAMON_OPS_FVADDR`) before freeing `t`; `damon_free_target(t)` and `damon_destroy_target(t, NULL)` skip `cleanup_target` and must only be used when `t` holds no `ops`-managed reference. When `damon_commit_targets()` destroys a `dst_target`, it must clear `s->quota.charge_target_from = NULL` and `s->quota.charge_addr_from = 0` on every scheme `s` in `dst` where `charge_target_from == dst_target`. [F2, F3]
- When a folio is isolated via `folio_isolate_lru(folio)` in `damon_pa_pageout()`, `damon_pa_migrate()`, or `damos_va_migrate_dests_add()`, the caller must still drop its `damon_get_folio()` reference via `folio_put(folio)`. Any isolated folio not consumed by `reclaim_pages()` or `migrate_pages()`—including unevictable folios checked via `folio_test_unevictable(folio)` in `damon_pa_pageout()`, and folios in `damon_migrate_folio_list()` on `ret_folios` or remaining on `migrate_folios`—must be returned via `folio_putback_lru()`. [F15, F139, F140]
- Once `damos_walk()` installs a stack-allocated `struct damos_walk_control` into `ctx->walk_control`, both `damos_walk_complete()` and `damos_walk_cancel()` must signal `complete(&control->completion)` and reset `ctx->walk_control = NULL`. [F9]
- When `damon_pa_pageout()` attaches a temporary `DAMOS_FILTER_TYPE_YOUNG` filter to `s` via `damos_new_filter()` and `damos_add_filter(s, filter)` (`install_young_filter`), it must unlink and free it with `damos_destroy_filter(filter)` after the region scan loop. [F17]
- In DAMON sysfs teardown helpers (`damon_sysfs_*_rm_dirs()`), a child directory's `*_rm_dirs()` helper must be called before `kobject_put()` on that child's `kobj`. In `mm/damon/sysfs-schemes.c`, both `memcg_path_store()` (before overwriting) and `damon_sysfs_scheme_filter_release()` must `kfree(filter->memcg_path)`. [F10, F11]

## API Contracts
- `damon_get_folio(pfn)` resolves tail pages to their containing `struct folio` with an incremented refcount that callers must release via `folio_put()`, except when `damon_pa_invalid_damos_folio(folio, s)` returns `true` for `folio == s->last_applied`, in which case it calls `folio_put(folio)` itself. Physical-address loops in `mm/damon/paddr.c` must advance `addr` by `folio_size(folio)` when a folio is processed and by `PAGE_SIZE` only when `damon_pa_invalid_damos_folio()` rejects the PFN. [F14, F134]
- `damon_get_task_struct(t)` returns a `struct task_struct *` that the caller must release with `put_task_struct()`; `damon_get_mm(t)` drops that task reference internally while returning an `mm_struct *` that the caller must release with `mmput()` if non-NULL. [F13]
- `damon_ctx->addr_unit` must always be non-zero (`addr_unit_store()`, `damon_reclaim_addr_unit_store()`, and `damon_lru_sort_addr_unit_store()` must reject `0` with `-EINVAL`), `damon_reclaim_apply_parameters()` must reset `addr_unit = 1` when default System RAM is used, and `damon_ctx->min_sz_region` must be clamped to `max(DAMON_MIN_REGION / addr_unit, 1)`. [F51, F104]
- In `DAMON_OPS_PADDR`, region addresses, `*sz_filter_passed`, and the return value of `damon_pa_apply_scheme()` are in core address units (`phys_addr / ctx->addr_unit`), so page counts from `reclaim_pages()` or `damon_migrate_pages()` must be multiplied by `PAGE_SIZE` and scaled via `damon_pa_core_addr()`. Because `apply_scheme` handlers accumulate into `*sz_filter_passed` with `+=`, callers like `damos_apply_scheme()` must initialize `sz_ops_filter_passed = 0`. [F38, F142]
- `damon_migrate_pages()` must validate `target_nid` is in `[0, MAX_NUMNODES)` with `node_state(target_nid, N_MEMORY)`, enter a `memalloc_noreclaim_save()` scope, and partition `folio_list` into per-source-node batches before calling `damon_migrate_folio_list()`; `__damon_migrate_folio_list()` must allocate targets with `~__GFP_RECLAIM | __GFP_NOMEMALLOC | GFP_NOWAIT` and `MIGRATE_ASYNC`. [F130, F141]
- Because `damon_set_attrs()` only computes `attrs->aggr_samples = attrs->aggr_interval / sample_interval` when `attrs->aggr_samples == 0`, external callers must zero `attrs->aggr_samples` when setting new intervals. [F49]
- `damon_feed_loop_next_input()` assumes a target `goal` of `10000` and clamps its return value to `>= 10000`, so callers (`damon_get_intervals_adaptation_bp()`, `damos_set_effective_quota()`) must normalize `score` so `10000` is 100% of goal and scale `last_input` in basis points. Every `damon_operations.get_scheme_score` implementation must return an integer in `[0, DAMOS_MAX_SCORE]` (`0..99`) because `damos_adjust_quota()` indexes `c->regions_score_histogram` unchecked. [F53, F154]
- Module parameter `.set` handlers that start DAMON (`damon_reclaim_enabled_store()`, `damon_lru_sort_enabled_store()`, `damon_stat_enabled_store()`) must check `damon_initialized()` first and defer starting DAMON to `module_init` during early boot. [F146]

## Error Handling
- In `damon_commit_targets()` and `damon_commit_schemes()`, if committing into a newly allocated `new_target` or `new_scheme` fails, it must be destroyed via `damon_destroy_target(new_target, NULL)` or `damon_destroy_scheme(new_scheme)` before returning the error, and linked into `dst` only on success. [F4]
- Because `damon_call()` only returns delivery status (`0`, `-EINVAL`, `-ECANCELED`) and stores the callback's return status in `control->return_code`, synchronous (`!control->repeat`) callers like `damon_sysfs_damon_call()` must check both `damon_call()`'s return value and `control->return_code`. [F34]
- In `__damon_start()`, if `kthread_run()` returns an `ERR_PTR`, `ctx->kdamond` must be reset to `NULL` after extracting `PTR_ERR(ctx->kdamond)` before releasing `ctx->kdamond_lock`, because `damon_is_running()` and `__damon_stop()` treat any non-NULL `ctx->kdamond` as a running task. [F35]
- `damon_sysfs_build_ctx()` always returns an `ERR_PTR` on failure and never `NULL`, so callers (`damon_sysfs_commit_input()`, `damon_sysfs_turn_damon_on()`) must check `IS_ERR()`. `damos_get_wmark_metric_value()` returns a signed `int` status (`0` or `-EINVAL`) and writes the metric into `*metric_value`, so callers like `damos_wmark_wait_us()` must check its return status before reading `metric`. [F36, F37]

## Known Pitfalls
- `damon_new_scheme()` mutates `@quota` in place via `damos_quota_init(quota)` and initializes `scheme->quota.goals` to an empty list, so callers deriving multiple schemes from a shared template (`damon_lru_sort_new_scheme()`) must pass a local copy and populate `scheme->quota.goals` separately. [F68]
- In `mm/damon/vaddr.c`, PMD walk callbacks (`damon_mkold_pmd_entry()`, `damon_young_pmd_entry()`, `damos_va_stat_pmd_entry()`) must return `0` when `pte_offset_map_lock()` fails and never set `walk->action = ACTION_AGAIN`. In `damos_va_stat_pmd_entry()`, the PTE loop (`for (; addr < next; pte += nr, addr += nr * PAGE_SIZE)`) must set `nr = 1` at the start of every iteration before any `continue`, and pass the initial `start_pte` (not `pte`) to `pte_unmap_unlock(start_pte, ptl)`. [F90, F93, F117]
- On 32-bit architectures with 64-bit `phys_addr_t` or `u64`: `damon_pa_phys_addr()` must cast `addr` to `phys_addr_t` before multiplying by `addr_unit`; `damon_pa_core_addr()` must use `div_u64(pa, addr_unit)` when `sizeof(pa) == 8 && sizeof(addr_unit) == 4`; and `damos_get_some_mem_psi_total()` must use `div_u64(..., NSEC_PER_USEC)`. [F97, F99, F133]
- `damon_feed_loop_next_input()` must guard against `unsigned long` overflow/underflow by checking `last_input < ULONG_MAX / score_goal_diff` before multiplying, clamping subtraction at `min_input`, and saturating addition at `ULONG_MAX`. In `damon_stat_set_idletime_percentiles()`, `c->attrs.aggr_interval` must be cast to `long` before multiplying by signed `damon_stat_idletime(region)`. [F106, F113]
- Every `kobject_init_and_add()` call in `mm/damon/sysfs*.c` using a non-literal string variable must pass an explicit `"%s"` format literal. In `memcg_path_store()`, `filter->memcg_path` must be allocated with `size_add(count, 1)` bytes and populated via `strscpy(path, buf, count + 1)`. [F118, F119]
