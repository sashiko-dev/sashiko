# MEMORY MANAGEMENT - KSM (Kernel Samepage Merging)

Kernel Samepage Merging (KSM) dynamically scans anonymous memory areas marked as `VM_MERGEABLE` across processes and deduplicates identical pages into shared copy-on-write (COW) pages or the special zero page. It tracks candidate virtual addresses with `ksm_rmap_item` structures organized into per-process `ksm_mm_slot` lists, uses an unstable red-black tree to detect unchanged pages within a scan pass, and promotes matched pages into a write-protected stable red-black tree (`ksm_stable_node`) while providing reverse-mapping, swap-in copy, page migration, and memory failure hooks.

## Architecture & Data Flow
- `struct ksm_rmap_item::address` packs `STABLE_FLAG`, `UNSTABLE_FLAG`, and `ksm_scan.seqnr & SEQNR_MASK` (`0x0ff`, bits `0..7`) into its low bits while linked in a tree, so address comparisons (`get_next_rmap_item`, `rmap_walk_ksm`, `collect_procs_ksm`), tree detachments, and `unstable_tree_search_insert()` must mask `address` with `PAGE_MASK`. Because `scan_get_next_rmap_item()` resets `root_unstable_tree[nid] = RB_ROOT` and increments `ksm_scan.seqnr`, `remove_rmap_item_from_tree()` computes `age = (unsigned char)(ksm_scan.seqnr - rmap_item->address)` (`BUG_ON(age > 1)`) and must only call `rb_erase()` on `UNSTABLE_FLAG` items when `age == 0`, while always decrementing `ksm_pages_unshared`. [F46, F60, F87]
- In `struct ksm_stable_node`, `head` overlays `node.__rb_parent_color` to discriminate the union: `head == &migrate_nodes` means `list` is on `migrate_nodes`, `head == STABLE_NODE_DUP_HEAD` (`(struct list_head *)&migrate_nodes.prev`) means `hlist_dup` is in a chain, and any other value means `node` is in `root_stable_tree`. `rmap_hlist_len` uses `STABLE_NODE_CHAIN` (`-1024`, not `-1`) to tag chain nodes (`is_stable_node_chain()`), while non-chain paths (`remove_node_from_stable_tree()`, `__is_page_sharing_candidate()`, `stable_tree_append()`) assert `rmap_hlist_len >= 0`. [F62, F85]
- `root_stable_tree` and `root_unstable_tree` point to 1-element arrays (`one_stable_tree`, `one_unstable_tree`) until `merge_across_nodes_store()` allocates `nr_node_ids` roots. PFN-based lookups must index via `get_kpfn_nid()`, full-tree loops must bound `nid` by `ksm_nr_node_ids` (not `nr_node_ids`), and `rb_erase()` in `stable_node_dup_del()` or `remove_rmap_item_from_tree()` must use the node's recorded `NUMA(dup->nid)` or `NUMA(rmap_item->nid)` rather than recomputing the page's NUMA node. [F57, F58]
- In `write_protect_page()`, `ptep_clear_flush()` must run before checking `folio_mapcount(folio) + 1 + swapped != folio_ref_count(folio)` or calling `folio_try_share_anon_rmap_pte()` (restoring the PTE via `set_pte_at()` on failure). After `write_protect_page()` drops the PTE lock, `replace_page()` must reacquire `pte_offset_map_lock()` inside `mmu_notifier_invalidate_range_start()`/`end()` and verify `pte_same(ptep_get(ptep), orig_pte)`, whereas an in-place upgrade (`kpage == NULL`) in `try_to_merge_one_page()` must call `folio_mark_dirty(folio)` so reclaim swaps the KSM folio out instead of freeing it as clean. [F24, F53, F113]
- When `replace_page()` replaces an anonymous `page` with the KSM zero page (`is_zero_pfn(page_to_pfn(kpage))`), it must mark the PTE dirty (`pte_mkdirty`, checked by `is_ksm_zero_pte()` on unmap), call `ksm_map_zero_page(mm)`, and call `dec_mm_counter(mm, MM_ANONPAGES)` instead of taking a folio reference or adding an anon rmap entry. [F10]
- When `ksm_fork()` duplicates a mergeable `mm_struct`, it must reset `mm->ksm_merging_pages` and `mm->ksm_rmap_items` to 0 because `ksm_rmap_item`s are not cloned on fork, while adding the inherited `mm->ksm_zero_pages` count to global `ksm_zero_pages`. [F43]
- Every addition or removal of a `ksm_rmap_item` on `stable_node->hlist` (`stable_tree_append`, `remove_rmap_item_from_tree`, `remove_node_from_stable_tree`) must update `stable_node->rmap_hlist_len`, `rmap_item->mm->ksm_merging_pages`, and `ksm_pages_shared` (for the sole entry) or `ksm_pages_sharing` (when another entry exists) in lockstep. [F44]
- When `stable_node_dup()` collapses a singular `ksm_stable_node` chain via `rb_replace_node(&stable_node->node, &found->node, root)`, it must free the chain node, decrement both `ksm_stable_node_chains` and `ksm_stable_node_dups`, and set `*_stable_node = found`; callers of `__stable_node_chain()` (`chain()` and `chain_prune()`) must verify the returned `folio` is non-NULL before dereferencing `*_stable_node` or `*_stable_node_dup` and treat `*_stable_node == *_stable_node_dup` as a regular non-chain rbtree node. [F48, F71]
- In `ksm_check_stable_tree()`, whenever `stable_node_chain_remove_range()` returns `true` (a regular `ksm_stable_node` or emptied chain was erased from `root_stable_tree + nid`), the rbtree cursor `node` must be reset via `rb_first(root_stable_tree + nid)` rather than advanced with `rb_next(node)`. [F49]
- When an `mm_struct` has `MMF_VM_MERGE_ANY` set across `execve()`, `ksm_execve()` must call `__ksm_enter(mm)` to register a `ksm_mm_slot`, and every path freeing a `ksm_mm_slot` (`__ksm_exit`, `scan_get_next_rmap_item`, `unmerge_and_remove_all_rmap_items`) must clear both `MMF_VM_MERGEABLE` and `MMF_VM_MERGE_ANY` before `mmdrop(mm)`. [F51]
- Because `alloc_stable_node()` uses `kmem_cache_alloc()` rather than `kmem_cache_zalloc()`, `stable_tree_insert()` and `alloc_stable_node_chain()` must explicitly initialize `hlist`, `rmap_hlist_len`, `kpfn` or `chain_prune_time`, `nid`, and the tree/chain link fields before inserting the node. [F41]

## Synchronization
- `ksm_mmlist_lock` is a spinlock that nests inside `mmap_read_lock(mm)`, so `mm_slot_alloc()` (`GFP_KERNEL`), `mm_slot_free()`, `mmdrop()`, and `mmap_read_lock()` / `mmap_write_lock()` in `__ksm_enter()`, `__ksm_exit()`, `scan_get_next_rmap_item()`, and `unmerge_and_remove_all_rmap_items()` must execute outside `ksm_mmlist_lock`. [F93]
- `ksm_process_mergeable()` requires `mmap_assert_locked(mm)`, and after acquiring `mmap_read_lock(mm)` on an `mm_struct` from a `ksm_mm_slot` or `ksm_rmap_item`, `scan_get_next_rmap_item()`, `unmerge_and_remove_all_rmap_items()`, and `find_mergeable_vma()` must check `ksm_test_exit(mm)` before looking up or iterating VMAs. [F17, F28]
- Every `ksm_thread_mutex` holder that accesses the stable or unstable trees (`ksm_scan_thread()`, `run_store()`, `merge_across_nodes_store()`, `max_page_sharing_store()`) must call `wait_while_offlining()` after acquiring `ksm_thread_mutex`, and `wait_while_offlining()` must drop `ksm_thread_mutex` while waiting on `KSM_RUN_OFFLINE`. [F94]
- Modifying a KSM folio's `folio->mapping` (`folio_set_stable_node()`) or its `ksm_stable_node->hlist` (`stable_tree_insert()`, `stable_tree_append()`, and `hlist_del()` in `remove_rmap_item_from_tree()`) requires holding `folio_lock()`, which `rmap_walk_ksm()` and `folio_migrate_ksm()` also require their callers to hold. [F95]
- In `stable_tree_insert()`, `folio_set_stable_node(kfolio, stable_node_dup)` must only be called after `stable_node_dup` is initialized and linked into `root_stable_tree` or a `ksm_stable_node` chain (including fallible `alloc_stable_node_chain()`), so `kfolio->mapping` never points to a freed or unlinked node. [F13]
- In `folio_migrate_ksm()`, `stable_node->kpfn = folio_pfn(newfolio)` and `smp_wmb()` must execute before `folio_set_stable_node(folio, NULL)`, and `ksm_get_folio()` must execute the matching `smp_rmb()` and recheck `READ_ONCE(stable_node->kpfn) != kpfn` before calling `remove_node_from_stable_tree(stable_node)`. [F55]
- In `ksm_get_folio()`, when `folio_try_get(folio)` fails on a folio whose `folio->mapping` matched `expected_mapping`, it must spin with `cpu_relax()` while `folio_test_swapcache(folio)` is set, and after `folio_try_get()` (and optional `folio_lock()`/`folio_trylock()`) succeeds it must re-verify `READ_ONCE(folio->mapping) == expected_mapping`. [F97]
- In `stable_tree_search()`, after matching a candidate `stable_node_dup` with `KSM_GET_FOLIO_NOLOCK`, the candidate folio must be re-fetched via `ksm_get_folio(stable_node_dup, KSM_GET_FOLIO_TRYLOCK)` and unlocked before returning so concurrent page migration observes the elevated folio refcount. [F25]
- Global `ksm_zero_pages` and per-mm `mm->ksm_zero_pages` are modified concurrently by `ksmd` (`replace_page()`) and page table unmapping paths (`ksm_might_unmap_zero_page()`) without a shared KSM lock, so all reads and updates must use `atomic_long_t` operations (`ksm_map_zero_page()`, `ksm_might_unmap_zero_page()`, `mm_ksm_zero_pages()`). [F26]
- In `rmap_walk_ksm()`, when `anon_vma_trylock_read(anon_vma)` fails and `rwc->try_lock` is true, it must set `rwc->contended = true` and return immediately rather than blocking on `anon_vma_lock_read(anon_vma)`. [F101]

## Object Lifetimes
- When `ksm_get_folio()` returns `NULL` (and when `chain()` or `chain_prune()` returns `NULL`), it has already called `remove_node_from_stable_tree(stable_node)` and freed `stable_node`; callers (`stable_tree_search()`, `stable_tree_insert()`) must not dereference `stable_node` or `stable_node_dup` and must restart the rbtree walk (`goto again`). When `ksm_get_folio(stable_node, KSM_GET_FOLIO_TRYLOCK)` returns `ERR_PTR(-EBUSY)`, it has dropped the folio reference without freeing `stable_node`, and callers must check for both `NULL` and `ERR_PTR(-EBUSY)`. [F1, F31, F47]
- Walks over a `ksm_stable_node` chain's `hlist` that call `ksm_get_folio()`, `remove_stable_node()`, or `stable_node_dup_remove_range()` (`stable_node_dup()`, `remove_stable_node_chain()`, `stable_node_chain_remove_range()`) must use `hlist_for_each_entry_safe()` and must not dereference `dup` after those calls return `NULL` or remove the node. [F70]
- When `remove_rmap_item_from_tree()` detaches an `rmap_item` with `STABLE_FLAG` set from its `ksm_stable_node`, it must drop the `anon_vma` reference via `put_anon_vma(rmap_item->anon_vma)` and clear both `rmap_item->head = NULL` and the low flag bits of `rmap_item->address`. [F2]
- `scan_get_next_rmap_item()` only transfers the `folio_get(folio)` reference via `*page` when returning a non-NULL `rmap_item` (released with `put_page(page)` in `ksm_do_scan()`), and must call `folio_put(folio)` whenever `get_next_rmap_item()` returns `NULL` or `should_skip_rmap_item()` returns `true` (after advancing `ksm_scan.rmap_list = &rmap_item->rmap_list` before jumping to `next_page`). [F8, F72]
- `unstable_tree_search_insert()` must call `put_page(tree_page)` on every comparison step where `tree_page` is not returned (including self-match `page == tree_page`, `<` or `>` branches, and cross-node mismatch), and only transfers ownership of `tree_page` via `*tree_pagep` when returning a non-NULL `tree_rmap_item` (released with `put_page(tree_page)` in `cmp_and_merge_page()`). [F9]
- In `mm/ksm.c`, `mm_slot_cache` is sized for `struct ksm_mm_slot` (`KMEM_CACHE(ksm_mm_slot, 0)`), so `struct mm_slot *` pointers from `mm_slot_lookup()` or `mm_node` list walks must be converted with `mm_slot_entry(slot, struct ksm_mm_slot, slot)` and freed as `struct ksm_mm_slot *`. [F90]

## API Contracts
- When `ksm_might_need_to_copy()` allocates a replacement `new_folio`, it must charge `new_folio` to `vma->vm_mm` via `mem_cgroup_charge()` and call `folio_put(new_folio)` if charging or `copy_mc_user_highpage()` fails; on success it returns `new_folio` locked, uptodate, dirty, and refcounted without unlocking or putting the input swapcache `folio`. [F7]
- `folio_set_stable_node(folio, NULL)` sets `folio->mapping` to `(void *)FOLIO_MAPPING_KSM`, so `folio_test_ksm(folio)` can be true while `folio_stable_node(folio)` returns `NULL`; callers of `folio_stable_node()` must null-check its return value before dereferencing. [F88]
- `write_protect_page()` only operates on order-0 folios (`WARN_ON_ONCE(folio_test_large(folio))`), so `try_to_merge_one_page()` must split any large folio with `split_huge_page(page)` under `folio_trylock(folio)` and refresh `folio = page_folio(page)` before calling `write_protect_page()`. [F110]
- When `get_mergeable_page()` or `scan_get_next_rmap_item()` obtains a candidate anonymous page via `folio_walk_start()`, it must call `flush_anon_page(vma, page, addr)` and `flush_dcache_page(page)` before `mmap_read_unlock(mm)`, and `calc_checksum()` must map the page with `kmap_local_page()` / `kunmap_local()`. [F104]

## Error Handling
- When `try_to_merge_with_ksm_page()` succeeds for an `rmap_item` in `try_to_merge_two_pages()`, a subsequent failure of the second merge in `try_to_merge_two_pages()` or of `stable_tree_insert()` in `cmp_and_merge_page()` must call `break_cow()` on each already-merged `rmap_item` to drop its `anon_vma` reference and unshare the KSM page. [F4]
- `__ksm_del_vma()` and `ksm_madvise(..., MADV_UNMERGEABLE, ...)` must not clear `VM_MERGEABLE` if `unmerge_ksm_pages()` returns an error, and `ksm_disable_merge_any()` must call `ksm_add_vmas(mm)` and leave `MMF_VM_MERGE_ANY` set if `ksm_del_vmas(mm)` fails. [F11]
- In `try_to_merge_one_page()`, `err` is pre-initialized to `-EFAULT` and must only be set to `0` or the result of `replace_page()` after `write_protect_page()` succeeds, without intermediate calls like `split_huge_page()` overwriting `err` with `0`. [F33]
- Callers of `find_mergeable_vma()` (`break_cow()`, `get_mergeable_page()`, `try_to_merge_with_zero_page()`, `try_to_merge_with_ksm_page()`) must check that the returned `struct vm_area_struct *` is non-`NULL` before passing it to `try_to_merge_one_page()`, `break_ksm()`, or `folio_walk_start()`, and `write_protect_page()` / `replace_page()` must check that `page_address_in_vma()` is not `(unsigned long)-EFAULT`. [F34, F40]
- In `remove_stable_node()`, finding `folio_mapped(folio)` true is a valid runtime race with `__mmput()` running between `ksm_exit()` and `exit_mmap()`, and must return `-EBUSY` without triggering a `WARN_ON` or `BUG_ON`. [F107]

## External Contracts
- `run_store()` must reject user-supplied `flags > KSM_RUN_UNMERGE` (`2`) with `-EINVAL` so userspace cannot set `KSM_RUN_OFFLINE` (`4`). When `KSM_RUN_UNMERGE` is requested, `unmerge_and_remove_all_rmap_items()` must be bracketed with `set_current_oom_origin()` and `clear_current_oom_origin()`, and on error `ksm_run` must be reset to `KSM_RUN_STOP`. [F64, F115]
- `merge_across_nodes_store()` and `max_page_sharing_store()` must hold `ksm_thread_mutex`, call `wait_while_offlining()`, and reject changes with `-EBUSY` unless `ksm_pages_shared == 0` and `remove_all_stable_nodes() == 0`; `max_page_sharing_store()` must also reject values `< 2` with `-EINVAL`. [F117]
- `ksm_compatible()` rejects VMAs with `VM_SHARED | VM_MAYSHARE | VM_SPECIAL | VM_HUGETLB | VM_DROPPABLE`, `VM_SAO`, `VM_SPARC_ADI`, or DAX files (`file_is_dax(file)`), and `ksm_madvise(..., MADV_MERGEABLE, ...)` must silently ignore incompatible VMAs and return `0`. [F119]

## Known Pitfalls
- When pruning offlined PFN ranges in `stable_node_dup_remove_range()` during `MEM_OFFLINE`, nodes with `kpfn` in `[start_pfn, end_pfn)` must be removed directly via `remove_node_from_stable_tree(stable_node)` without calling `ksm_get_folio()` or `pfn_folio(stable_node->kpfn)`. [F105]
- `ksm_run` must be an `unsigned long` and callers of `wait_on_bit()` and `wake_up_bit()` on `&ksm_run` (`wait_while_offlining()` and `ksm_memory_callback()`) must pass the bit index `ilog2(KSM_RUN_OFFLINE)` rather than the bitmask `KSM_RUN_OFFLINE`. [F89]
