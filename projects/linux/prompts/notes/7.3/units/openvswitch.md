# OPENVSWITCH

`net/openvswitch` implements Open vSwitch (OVS) virtual ports (vports), datapath traffic meters, and kernel tracepoints. It provides the core vport abstraction and registry (`vport.c`), vport backends for netdevs, internal bridge devices, and lightweight tunnels (VXLAN, Geneve, GRE), and Generic Netlink configuration and token-bucket execution for OpenFlow meters (`meter.c`).

## Architecture & Data Flow

- Before downcasting a `struct net_device *` to OVS vport state, `ovs_internal_dev_get_vport()` must verify `ovs_is_internal_dev(netdev)` (`netdev->netdev_ops == &internal_dev_netdev_ops`) and `ovs_netdev_get_vport()` must verify `netif_is_ovs_port(dev)` (`dev->priv_flags & IFF_OVS_DATAPATH`). [F33]
- In `ovs_vport_locate()`, each `hlist_for_each_entry_rcu()` iteration over `hash_bucket(net, name)` must match both `!strcmp(name, ovs_vport_name(vport))` and `net_eq(ovs_dp_get_net(vport->dp), net)`. [F75]
- When `ovs_vport_receive()` handles a packet where `dev_net(skb->dev) != ovs_dp_get_net(vport->dp)`, it must save and restore `skb->mark` across `skb_scrub_packet(skb, true)` and clear `tun_info = NULL` before calling `ovs_flow_key_extract()`. [F54]
- In `internal_dev_recv()`, before calling `netif_rx(skb)`, code must drop routing dst (`skb_dst_drop(skb)`), reset conntrack (`nf_reset_ct(skb)`), pull the Ethernet header via `eth_type_trans()`, and update `skb->csum` via `skb_postpull_rcsum(skb, eth_hdr(skb), ETH_HLEN)`. [F117]
- In `internal_dev_create()`, when creating the datapath local port (`vport->port_no == OVSP_LOCAL`), `vport->dev->netns_immutable = true` must be set before `register_netdevice()` so it cannot be moved out of the datapath's netns. [F118]
- In `do_setup()` for OVS internal devices, `netdev->max_mtu = ETH_MAX_MTU` must be set after calling `ether_setup(netdev)` so `ether_setup()`'s `ETH_DATA_LEN` default does not restrict internal port MTU. [F109]
- `struct vport_portids` stores an element count in `n_ids` (`nla_len(ids) / sizeof(u32)`). `ovs_vport_set_upcall_portids()` must reject `@ids` with `-EINVAL` if `nla_len(ids)` is 0 or not a multiple of `sizeof(u32)` (ensuring `n_ids >= 1` and `rn_ids` is initialized via `reciprocal_value()`), and callers allocating, copying, or serializing `ids[]` must convert between `n_ids` and byte sizes via `sizeof(u32)`. [F61, F86]
- `struct dp_meter_instance.dp_meters` is a direct-mapped `__counted_by(n_meters)` array indexed by `meter_hash(ti, id)` (`id % ti->n_meters`) without collision chains: `dp_meter_instance_alloc()` must set `ti->n_meters` to the exact count passed to `struct_size(ti, dp_meters, size)` before indexing `dp_meters[]`, `lookup_meter()` must verify `meter->id == meter_id`, and `attach_meter()` must reject an occupied `ti->dp_meters[hash]` slot with `-EBUSY`. [F58, F85]
- In `detach_meter()`, shrinking `tbl->ti` to `half_size` is only permitted if every slot in `[half_size, ti->n_meters)` of `ti->dp_meters` is `NULL`; if any upper-half slot is occupied, `detach_meter()` must jump to `out` and return `0` without calling `dp_meter_instance_realloc()` or rolling back detachment. [F70]
- In `dp_meter_create()`, nested band attributes in `a[OVS_METER_ATTR_BANDS]` must be counted and capped at `DP_MAX_BANDS` before allocating `struct dp_meter` with `GFP_KERNEL_ACCOUNT` and `struct_size(meter, bands, n_bands)` and setting the `__counted_by` field `meter->n_bands`; `attach_meter()` bounds total meters by `tbl->max_meters_allowed`. [F56, F124]
- In `dp_meter_create()` and `ovs_meter_execute()`, `band->bucket` and `max_bucket_size` are in bits (`meter->kbps == 1`, `cost = skb->len * 8`) or 1/1000th of a packet (`meter->kbps == 0`, `cost = 1000`); full bucket capacity must be computed strictly as `band->burst_size * 1000ULL` (or `1000LL`) without adding `band->rate`, and `dp_meter_create()` must set `meter->max_delta_t` to the maximum of `div_u64(band->bucket, band->rate)` across all bands. [F40, F45, F78, F110]
- `ovs_meter_execute()` must iterate through all `meter->n_bands` bands to refill every `band->bucket` and deduct cost from bands with sufficient tokens while tracking the highest-rate exceeded band in `band_exceeded_max`, applying band stats and drop actions only after the loop completes. [F69]

## Synchronization

- All mutations to `vport_ops_list`, `dev_table`, `vport->upcall_portids`, and `dp_meter_table` (`tbl->ti`, `tbl->count`, `ti->dp_meters[]`) must be serialized under `ovs_lock()` (`ovs_mutex`), while readers of `dev_table`, `vport->upcall_portids`, and `dp_meter_table` must hold `ovs_mutex` or `rcu_read_lock()`. [F18]
- Functions reading RCU-protected vport or meter pointers under either `ovs_mutex` or `rcu_read_lock()` (`lookup_meter`, `ovs_vport_locate`, `ovs_vport_get_upcall_portids`) must use `rcu_dereference_ovsl()` or `hlist_for_each_entry_rcu(..., lockdep_ovsl_is_held())`, and `ovs_netdev_get_vport()` must use `rcu_dereference_rtnl(dev->rx_handler_data)`. [F106]
- `ovs_vport_receive()` and `ovs_vport_find_upcall_portid()` must be called within an `rcu_read_lock()` critical section in non-sleeping context; `internal_dev_xmit()` explicitly takes `rcu_read_lock()` around `ovs_vport_receive()`, and `netdev_port_receive()` uses `GFP_ATOMIC`. Broken by: relying only on `rcu_read_lock_bh()` in `.ndo_start_xmit` or sleeping in receive paths. [F102]
- `ovs_vport_alloc()` must allocate per-CPU `vport->upcall_stats` and initialize RCU `vport->upcall_portids` via `ovs_vport_set_upcall_portids()` before returning `vport` to its `vport_ops->create` caller, because registering the backing netdevice immediately exposes `vport` to datapath packet reception. [F12]
- In `internal_dev_create()`, `internal_dev_priv(vport->dev)->vport = vport` must be assigned before acquiring `rtnl_lock()` and calling `register_netdevice(vport->dev)`, because `internal_dev_xmit()` and `ovs_internal_dev_get_vport()` dereference it once registered. [F13]
- In `ovs_netdev_link()`, `vport->dev->priv_flags |= IFF_OVS_DATAPATH` must be set under `rtnl_lock()` only after `netdev_rx_handler_register()` succeeds, and `ovs_netdev_detach_dev()` must clear `IFF_OVS_DATAPATH` under `rtnl_lock()` before `netdev_rx_handler_unregister()`. [F93]
- In `ovs_vport_set_upcall_portids()`, `vport_portids->n_ids`, `vport_portids->rn_ids`, and `vport_portids->ids` must all be populated before `rcu_assign_pointer(vport->upcall_portids, vport_portids)` publishes the struct, and the replaced `old` struct must be freed via `kfree_rcu(old, rcu)`. [F26]
- `dp_meter_create()` must initialize `meter->lock` (`spin_lock_init()`), `meter->used`, `meter->max_delta_t`, and all `meter->bands` before `attach_meter()` publishes `meter` into `ti->dp_meters[hash]` with `rcu_assign_pointer()`, as `ovs_meter_execute()` immediately locks and reads them under RCU. [F14]
- Mutable fields of a published `struct dp_meter` (`used`, `stats`, `bands[]`) must be protected by `meter->lock`, using `spin_lock(&meter->lock)` in softirq `ovs_meter_execute()` and `spin_lock_bh(&meter->lock)` in process-context `ovs_meter_cmd_set`, `ovs_meter_cmd_get`, and `ovs_meter_cmd_del`. [F19]
- In `ovs_meter_execute()`, because `now_ms` is sampled before `spin_lock(&meter->lock)`, `long_delta_ms = now_ms - meter->used` must be checked for `< 0` and clamped to `0` under `meter->lock` before clamping to `meter->max_delta_t` and casting to `u32 delta_ms`. [F24]
- In `ovs_meter_cmd_set()` and `ovs_meter_cmd_del()`, `lookup_meter()` and `detach_meter()` (plus `attach_meter()` in `ovs_meter_cmd_set()`) must execute within a single continuous `ovs_lock()` critical section so concurrent commands cannot detach or free the same `old_meter` twice. [F20]

## Object Lifetimes

- In `ovs_vport_del()`, `hlist_del_rcu(&vport->hash_node)` and `module_put(vport->ops->owner)` must execute before `vport->ops->destroy(vport)`, and every `vport_ops.destroy` implementation must wait for an RCU grace period before calling `ovs_vport_free(vport)`. Broken by: dereferencing `vport` after `ops->destroy(vport)` or freeing `vport` synchronously in `destroy`. [F5]
- In `internal_dev_create()`, `vport->dev->priv_destructor = internal_dev_destructor` must be set only after `register_netdevice(vport->dev)` succeeds so the `error_unlock` path can call `free_netdev(dev)` and `ovs_vport_free(vport)` without double-freeing `vport`; once registered (`needs_free_netdev = true`), `internal_dev_destroy()` must only call `unregister_netdevice(vport->dev)` and never call `free_netdev()` or `ovs_vport_free()` directly. [F4, F92]
- In `ovs_netdev_tunnel_destroy()`, under `rtnl_lock()`, `rtnl_delete_link()` (called only if `reg_state == NETREG_REGISTERED`) and `netdev_put()` must be followed by `vport->dev = NULL`, because the RCU callback `vport_netdev_free()` also calls `netdev_put(vport->dev, &vport->dev_tracker)`. [F17]
- Published `dp_meter`, `dp_meter_instance`, and `vport_portids` objects unlinked or replaced on an active datapath must be freed via RCU (`kfree_rcu` in `ovs_meter_free()` and `ovs_vport_set_upcall_portids()`, and `call_rcu(&ti->rcu, dp_meter_instance_free_rcu)` in `dp_meter_instance_realloc()`). [F104]

## API Contracts

- `ovs_vport_receive()` and `ovs_vport_send()` consume `@skb` on every path; callers must not dereference or free `skb` afterwards (e.g., reading `skb->len` after `ovs_vport_receive()` in `internal_dev_xmit()`). Conversely, `ovs_meter_execute()` never frees `@skb`: it returns `true` only when an `OVS_METER_BAND_TYPE_DROP` band triggers and `false` when the packet passes or `lookup_meter()` finds no meter, leaving the caller to drop `@skb`. [F10, F31]
- Before calling `ovs_vport_receive()`, `netdev_port_receive()` must unshare the packet with `skb_share_check(skb, GFP_ATOMIC)`, restore the Ethernet header on `ARPHRD_ETHER` devices via `skb_push_rcsum(skb, ETH_HLEN)`, and pass `skb_tunnel_info(skb)` as `tun_info`. [F112]
- `ovs_vport_get_stats()` must retrieve netdev statistics via `dev_get_stats(vport->dev, &temp)` rather than reading `vport->dev->tstats` directly, because external netdevs may not allocate per-CPU `tstats`. [F34]
- `ovs_vport_alloc()` places private data at `ALIGN(sizeof(struct vport), VPORT_ALIGN)` only when `priv_size > 0`, and `vport_from_priv()` subtracts that exact offset; `vport_priv()` must only be used on vports allocated with `priv_size > 0`, and `vport_from_priv()` requires a pointer to the start of the private area. [F63]

## Error Handling

- In `ovs_meter_cmd_set()`, once `detach_meter(meter_tbl, old_meter)` succeeds, `old_meter` is unlinked and must be freed via `ovs_meter_free(old_meter)` both on normal completion and on the `exit_free_old_meter` error path if `attach_meter(meter_tbl, meter)` fails; an unattached newly created `meter` is freed with `kfree(meter)`. [F8]
- `ovs_meter_cmd_reply_start()` returns `ERR_PTR(-ENOMEM)` or `ERR_PTR(-EMSGSIZE)` on failure, so callers must check `IS_ERR(reply)` and `PTR_ERR(reply)` rather than `!reply`; inside `ovs_meter_cmd_reply_start()`, after `*ovs_reply_header = genlmsg_put(...)`, the check must test `!*ovs_reply_header` rather than `!ovs_reply_header`. [F28, F68]
- `ovs_meter_cmd_set()` must verify `a[OVS_METER_ATTR_ID]` is non-null before calling `dp_meter_create(a)`, and `dp_meter_create()` must initialize `meter->id` from it because `dp_meter_create()` unconditionally dereferences `a[OVS_METER_ATTR_ID]` and `attach_meter()`/`lookup_meter()` key by `meter->id`. [F32]
- In `dp_meter_create()`, each nested band attribute must be validated with `band_policy` to have non-NULL `OVS_BAND_ATTR_TYPE`, `OVS_BAND_ATTR_RATE`, and `OVS_BAND_ATTR_BURST` attributes, and `band->rate == 0` must be rejected with `-EINVAL` before computing `div_u64(band->bucket, band->rate)`. [F57]

## External Contracts

- In `ovs_vport_get_upcall_portids()`, `OVS_VPORT_ATTR_UPCALL_PID` must be serialized as a single `u32` (`ids->ids[0]`) when `OVS_DP_F_VPORT_PIDS` is not set in `vport->dp->user_features`, and as the full `ids->n_ids * sizeof(u32)` array only when `OVS_DP_F_VPORT_PIDS` is enabled. [F62]
- 64-bit Netlink attributes in meter and vport replies (`OVS_METER_ATTR_USED` in `ovs_meter_cmd_reply_stats()`, `OVS_VPORT_UPCALL_ATTR_SUCCESS` and `OVS_VPORT_UPCALL_ATTR_FAIL` in `ovs_vport_get_upcall_stats()`) must be serialized with `nla_put_u64_64bit()` using `OVS_METER_ATTR_PAD` or `OVS_VPORT_ATTR_PAD`. [F120]
- In `dp_meter_genl_ops`, state-modifying commands (`OVS_METER_CMD_SET`, `OVS_METER_CMD_DEL`) must set `.flags = GENL_UNS_ADMIN_PERM`, and all `ovs_meter_cmd_*` handlers must resolve the datapath in `sock_net(skb->sk)` via `get_dp(sock_net(skb->sk), ovs_header->dp_ifindex)`. [F123]

## Known Pitfalls

- Because `dp_meter_instance_realloc()` replaces `tbl->ti` with a new `struct dp_meter_instance` and frees the old one via `call_rcu()`, callers (`attach_meter()`, `detach_meter()`) must not mutate or dereference a cached `ti` pointer after `dp_meter_instance_realloc()` succeeds. [F88]
- Dividing 64-bit quantities such as `band->bucket` (`u64`) or `ktime_get_ns()` (`u64`) by a 32-bit divisor in `meter.c` must use `div_u64()` rather than `/` to avoid `__udivdi3` link failures on 32-bit architectures. [F80]
- When checking whether a `struct sw_flow_key` has a valid MAC protocol in `openvswitch_trace.h`, code must test `!(key->mac_proto & SW_FLOW_KEY_INVALID)` rather than comparing against `MAC_PROTO_NONE` (0), because validity is encoded in bit `0x80` (`SW_FLOW_KEY_INVALID`). [F77]
