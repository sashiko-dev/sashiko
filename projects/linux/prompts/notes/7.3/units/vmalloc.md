# VMALLOC

The VMALLOC subsystem (`mm/vmalloc.c`, `include/linux/vmalloc.h`, `lib/test_vmalloc.c`) manages kernel virtual address (KVA) space allocations, page table mappings, and lazy TLB flushing, backed by a global augmented red-black tree KVA allocator, partitioned per-node busy/lazy trees with size-segregated pools, and a per-CPU `vmap_block` sub-allocator for short-lived small RAM mappings.

## Architecture & Data Flow

- In `struct vmap_area`, `subtree_max_size` and `vm` share a union: `subtree_max_size` is valid only in `free_vmap_area_root`, and `vm` only in `vn->busy.root`. Even in `vn->busy`, `va->vm` is `NULL` for `vm_map_ram()` and `new_vmap_block()` allocations (`VMAP_RAM`), so busy-tree readers must null-check `va->vm` and lookups including `vm_map_ram()` ranges must use `find_vmap_area()` rather than `find_vm_area()`. [F39, F40]
- Whenever a `vmap_area` in `free_vmap_area_root` is inserted, shrunk in `va_clip()`, or expanded in `__merge_or_add_vmap_area()`, `augment_tree_propagate_from(va)` must be called; on insertion (`__link_va()` with `augment == true`), `va->subtree_max_size` must be set to `0` after `rb_insert_augmented()` before calling `augment_tree_propagate_from(va)`. [F47, F56]
- Because `struct vm_struct::size` includes an unmapped trailing `PAGE_SIZE` guard page whenever `!(area->flags & VM_NO_GUARD)`, bounds checks and page-mapping operations (`remap_vmalloc_range_partial()`, `vread_iter()`, `check_sparse_vm_area()`, `ioremap_page_range()`) must use `get_vm_area_size(area)` rather than `area->size`. [F73]
- `vm_area_alloc_pages()` must populate every `PAGE_SIZE` entry of `area->pages[0 .. nr_pages - 1]` exclusively with pages of the `order` recorded via `set_vm_area_page_order()` (splitting with `split_page(page, order)`). Callers operating on high-order units (`__vmap_pages_range_noflush()`, `vm_reset_perms()`, `show_numa_info()`) must index `area->pages[]` with stride `1U << page_order`, while per-page callers (`vfree()`) step by 1. [F63, F82]
- Because a busy `vmap_area` is inserted into `addr_to_node(va->va_start)` but can span multiple `vmap_zone_size` zones, `find_vmap_area()` and `find_unlink_vmap_area()` must scan backwards circularly across `vmap_nodes` via `i = (i + nr_vmap_nodes - 1) % nr_vmap_nodes` starting from `addr_to_node_id(addr)`. [F80]
- Because `vb_alloc()` removes a `vmap_block` from `vbq->free` when `vb->free == 0` while leaving it in `vbq->vmap_blocks`, `_vm_unmap_aliases()` must iterate `vbq->vmap_blocks` via `xa_for_each()` (not `vbq->free`) to find all dirty unmapped ranges and reset `vb->dirty_min = VMAP_BBMAP_BITS` and `vb->dirty_max = 0`. [F64]
- `vmap_lazy_nr` must strictly equal the total pages of `vmap_area`s queued across all `vn->lazy` and `vn->purge_list` lists (`free_vmap_area_noflush()` adds `va_size(va) >> PAGE_SHIFT` and `purge_vmap_node()` subtracts `nr_purged_pages`), or `drain_vmap_work` can see `vmap_lazy_nr > lazy_max_pages()` with nothing to purge. [F59]
- In `is_within_this_va()`, after aligning `max(va->va_start, vstart)` to `align`, `nva_start_addr + size < nva_start_addr` and `nva_start_addr < vstart` must be rejected before testing `nva_start_addr + size <= va->va_end`. In `__alloc_vmap_area()`, `adjust_search_size = false` must be passed to `find_vmap_lowest_match()` when `align <= PAGE_SIZE` or `(vend - vstart) == size`, and parent rollback must advance `vstart` to `va->va_start + 1`. [F75, F76]
- In `pcpu_get_vm_areas()`, subtracting `end` from `pvm_determine_end_from_reverse()` can underflow `base`, so the reverse scan loop must guard with `base + last_end < vmalloc_start + last_end` (not `base < vmalloc_start`), step `area` via `(area + nr_vms - 1) % nr_vms`, and check `base + end > va->va_end` (recomputing `base` within `va`) before checking `base + start < va->va_start` (which steps `va` to `rb_prev(&va->rb_node)`). [F81, F90]

## Synchronization

- After releasing `vn->busy.lock`, callers (`find_vm_area()`, `find_vmap_area_exceed_addr_lock()`, `vread_iter()`, `vmalloc_dump_obj()`) must never dereference a previously looked-up `vmap_area *` or `vm_struct *`; they must copy needed scalar fields under `vn->busy.lock`, re-lookup by address after re-locking, and externally serialize `find_vm_area()` / `vrealloc_node_align_noprof()` against concurrent `vfree()`, `vunmap()`, or `vrealloc()`. [F31, F66]
- `find_vmap_area_exceed_addr_lock()` must release each node's `vn->busy.lock` before locking the next node, and after relocking `addr_to_node(va_start_lowest)->busy.lock` must re-verify `__find_vmap_area()` and retry if removed. It returns a non-NULL `vn` with `vn->busy.lock` held, so `vread_iter()` must unlock `vn->busy.lock` before advancing at `next_va` and on both `finished_zero` and `finished` exit paths when `vn` is non-NULL. [F13, F21]
- `__vmalloc_node_range_noprof()` must keep `VM_UNINITIALIZED` set in `area->flags` until `area->pages` and `area->nr_pages` are populated and mapped, clearing it via `clear_vm_uninitialized_flag()` with `smp_wmb()` paired with `smp_rmb()` in `vread_iter()` and `vmalloc_info_show()`. It must also skip `kmemleak_vmalloc()` when `VM_DEFER_KMEMLEAK` is set in `vm_flags`. [F22, F23]
- Callers of `__purge_vmap_area_lazy()` must hold `vmap_purge_lock`, which serializes the static `purge_nodes` cpumask (requiring `nr_vmap_nodes <= num_possible_cpus()`) and each `vmap_node`'s `purge_list`, `purge_work`, `nr_purged`, and `skip_populate` until `flush_work()` drains all `purge_work`. When `nr_purge_helpers == 0` and `purge_vmap_node()` runs synchronously, `vn->purge_work.func` must be set to `NULL` so `flush_work()` is skipped and `vn->nr_purged` is not double-counted. [F12, F24, F126]
- `__purge_vmap_area_lazy()` must detach each node's `vn->lazy` list into `vn->purge_list` and clear `WRITE_ONCE(vn->lazy.root.rb_node, NULL)` in lockstep under `vn->lazy.lock`, and execute `flush_tlb_kernel_range(start, end)` before running `purge_vmap_node()` to return ranges to node pools or `free_vmap_area_root`. [F25, F60]
- `new_vmap_block()` must initialize all `vb` fields (`lock`, `va`, `used_map`, `free`, `dirty`, `dirty_min`, `dirty_max`, `free_list`, `cpu`) before `xa_insert()`, and enqueue `vb->free_list` onto `per_cpu_ptr(&vmap_block_queue, vb->cpu)` (under `vbq->lock`) rather than `this_cpu_ptr()`, matching `per_cpu(vmap_block_queue, vb->cpu).lock` used when `purge_fragmented_block()` unlinks `vb->free_list`. [F18, F19, F135]
- `vb_alloc()` and `purge_fragmented_blocks()` must hold `rcu_read_lock()` while iterating `vbq->free` with `list_for_each_entry_rcu()`, and after `READ_ONCE()` of `vb->free`/`vb->dirty` must lock `vb->lock` and re-verify capacity or purge conditions. When both locks are held, `vb->lock` must precede `vbq->lock`: `purge_fragmented_block()` must zero `vb->free`, set `vb->dirty = VMAP_BBMAP_BITS`, unlink `vb->free_list` with `list_del_rcu()` under `vbq->lock`, and stage `vb` on a local `purge_list` via `vb->purge`, calling `free_purged_blocks()` only after releasing `vb->lock` and `rcu_read_unlock()`. [F26, F65, F95, F136]
- `vb_free()` must clear `vb->used_map` under `vb->lock` and complete `vunmap_range_noflush()` before re-acquiring `vb->lock` to expand `vb->dirty_min`/`vb->dirty_max` and increment `vb->dirty` via `WRITE_ONCE()`. A `vmap_block` may be purged or freed only when `vb->free + vb->dirty == VMAP_BBMAP_BITS`, and `free_vmap_block()` must use `kfree_rcu(vb, rcu_head)`. [F9, F27]
- `preload_this_cpu_lock()` must allocate the preload node with `gfp_mask` before acquiring `free_vmap_area_lock` and install it via `__this_cpu_try_cmpxchg()`, while `va_clip()` under `free_vmap_area_lock` must only fallback-allocate with `GFP_NOWAIT` when `__this_cpu_xchg(ne_fit_preload_node, NULL)` is NULL. [F30]
- `pcpu_get_vm_areas()` must hold `free_vmap_area_lock` across the scan for `base` and `va_clip()` of all `nr_vms` areas, drop it before `kasan_populate_vmalloc()`, `vn->busy.lock`, or `reclaim_and_purge_vmap_areas()`, and reallocate any `vas[area]` nulled by `recovery` before retrying. [F29]
- Accesses to `vn->pool[i].head` in `node_pool_add_va()`, `node_pool_del_va()`, and `decay_va_pool_node()` must hold `vn->pool_lock`, `node_pool_del_va()` must recheck `!list_empty(&vp->head)` under `vn->pool_lock`, and every addition/removal must update `vn->pool[i].len` in lockstep using `WRITE_ONCE()` to pair with `READ_ONCE()` in `vmap_node_shrink_count()`. [F33, F58]

## Object Lifetimes

- In `vmap()`, when `VM_MAP_PUT_PAGES` is set, ownership of `pages` (`kmalloc`/`vmalloc` memory) and one reference per page is transferred to `area` only after `vmap_pages_range()` succeeds, and the mapping must be freed with `vfree()` rather than `vunmap()`. If `vmap_pages_range()` fails, `vmap()` must call `vunmap(area->addr)` before assigning `area->pages`. [F1, F52]
- `__vmalloc_area_node()` consumes and frees `area` on every failure path (`free_vm_area(area)` or `vfree(area->addr)`), so callers such as `__vmalloc_node_range_noprof()` must not free `area` when `__vmalloc_area_node()` returns `NULL`. [F3]
- `__merge_or_add_vmap_area()` consumes its `va` argument (either freeing `va` via `kmem_cache_free()` when coalesced or linking it into `root` and `head`), so callers (`merge_or_add_vmap_area*()`, `pcpu_get_vm_areas()`) must save `va->va_start`/`va->va_end` into locals beforehand and never dereference or free `va` afterward. [F5, F67]
- In `vfree()`, when `vm->flags & VM_FLUSH_RESET_PERMS` is set, `vm_reset_perms(vm)` must run after `remove_vm_area(addr)` unmaps the KVA range and before `__free_page()` frees `vm->pages`. [F10]
- `__unlink_va()` must detach `va->list` using `list_del_init(&va->list)` rather than `list_del()`, because `free_vmap_area_noflush()` checks `WARN_ON_ONCE(!list_empty(&va->list))` and aborts without inserting `va` into `vn->lazy` if `va->list` is not reinitialized. [F11]

## API Contracts

- When `__GFP_NOFAIL` is set, `vm_area_alloc_pages()` must not abort on `fatal_signal_pending(current)`, and `__vmalloc_node_range_noprof()` and `__vmalloc_area_node()` must retry `__get_vm_area_node()` and `vmap_pages_range()` until they succeed; however, `__vmalloc_area_node()` must strip `__GFP_NOFAIL` when `page_order > 0` so failed high-order allocations fall back to `PAGE_SHIFT` in `__vmalloc_node_range_noprof()`, which must reset both `shift = PAGE_SHIFT` and `align = original_align` before `again:`. [F38, F101, F149]
- `vm_map_ram()`, `vm_unmap_ram(mem, count)`, and `vmap_ram_vread_iter()` must stay synchronized on `count <= VMAP_MAX_ALLOC` and `VMAP_RAM | VMAP_BLOCK`: `vm_unmap_ram()` requires `count` to be the exact page count passed to `vm_map_ram()` because `count <= VMAP_MAX_ALLOC` dispatches to `vb_free()` (`VMAP_RAM | VMAP_BLOCK`) while `count > VMAP_MAX_ALLOC` unlinks a whole `vmap_area` (`VMAP_RAM`). [F53, F71]
- `remap_vmalloc_range_partial()` must call `find_vm_area(kaddr)` on the base `kaddr` before applying `pgoff`, check `pgoff << PAGE_SHIFT` and `PAGE_ALIGN(size) + off` with `check_shl_overflow()` and `check_add_overflow()`, and verify `end_index <= get_vm_area_size(area)` and `VM_USERMAP | VM_DMA_COHERENT`. [F72]
- `vread_iter()` must clamp `count` to `-(unsigned long)addr` when `(unsigned long)addr + count < count`, locate the first area via `find_vmap_area_exceed_addr_lock()` rather than `__find_vmap_area()`, copy via `copy_page_to_iter_nofault()` while holding `vn->busy.lock`/`vb->lock`, and treat `VM_IOREMAP`, `VM_SPARSE`, unmapped gaps, and unset bits in `vb->used_map` of `VMAP_BLOCK` areas as zero-filled holes via `zero_iter()`. [F74, F133, F157]
- Functions installing new kernel mappings (`vmap_page_range()`, `vmap_pages_range()`, `vmap_pfn()`, and callers of `vmap_pages_range_noflush()`) must call `flush_cache_vmap(addr, end)` after populating page tables. Callers of `vunmap_range_noflush()` (`vunmap_range()`, `free_unmap_vmap_area()`, `vb_free()`) must call `flush_cache_vunmap()` before clearing PTEs, check `debug_pagealloc_enabled_static()` for immediate `flush_tlb_kernel_range()`, and flush TLBs before KVA reuse. [F142, F143, F161]
- PTE installation in `vmap_pte_range()`, `vmap_pages_pte_range()`, and `vmap_pfn_apply()` must use `set_pte_at(&init_mm, ...)` or `set_huge_pte_at()`. In `vmap_pte_range()`, when `size != PAGE_SIZE`, `arch_make_huge_pte()` takes `ilog2(size)` while `set_huge_pte_at()` takes `size`, and the huge-PTE branch must advance `pfn += PFN_DOWN(size)` before `continue` while the loop condition advances `pte += PFN_DOWN(size)` and `addr += size`; in `vunmap_pte_range()`, `PTR_ALIGN_DOWN()` on `pte` must multiply the page count by `sizeof(*pte)`. [F50, F103, F121, F140]

## Error Handling

- In `alloc_vmap_area()`, if `kasan_populate_vmalloc()` fails after `va` is inserted into `vn->busy.root`, rollback must call `free_vmap_area(va)` to unlink `va` from `vn->busy` and return its KVA range to `free_vmap_area_root`, whereas `overflow:` before insertion frees `va` with `kmem_cache_free()`. [F7]
- In `vmap_range_noflush()`, `__vunmap_range_noflush()`, and `vmap_small_pages_range_noflush()`, if `vmap_p4d_range()` or `vmap_pages_p4d_range()` fails, the loop must `break` rather than returning early so `arch_sync_kernel_mappings(start, end)` still runs when `mask & ARCH_PAGE_TABLE_SYNC_MASK` is non-zero; `vmap_small_pages_range_noflush()` must also pass a single `int nr = 0` (`&nr`) across `vmap_pages_p4d/pud/pmd/pte_range()`. [F15, F99, F144]
- `alloc_vmap_area()`, `new_vmap_block()`, and `vb_alloc()` return `ERR_PTR(-errno)` on failure rather than `NULL`, whereas high-level APIs (`vm_map_ram()`, `__get_vm_area_node()`) must check `IS_ERR()` and convert failures to `NULL`. `vmap_pages_range_noflush()` and `vmap_page_range()` must check and propagate errors from `kmsan_vmap_pages_range_noflush()` and `kmsan_ioremap_page_range()`. [F36, F37]

## Known Pitfalls

- When `__merge_or_add_vmap_area()` coalesces a freed `vmap_area` with both its `next` and `prev` neighbors, it must unlink the already-merged `next` sibling via `__unlink_va(va, root, augment)` before updating the `prev` sibling's `va_end`, or tree rotations during unlinking can corrupt augmented `subtree_max_size` state. [F57]
- In `struct vmap_area`, `va_start` and `va_end` must precede `rb_node` and pointer fields must reside at or after `rb_node`. `alloc_vmap_area()` must call `kmemleak_scan_area(&va->rb_node, SIZE_MAX, gfp_mask)` only when allocating from `vmap_area_cachep` (not on a pooled `va` from `node_alloc()` or inside `retry:`), and on `overflow:` must set `purged = 1` after `reclaim_and_purge_vmap_areas()`, reset `freed = 0` before `blocking_notifier_call_chain(&vmap_notify_list, 0, &freed)`, and reset `purged = 0` when `freed > 0`. [F69, F100, F123, F160]
- `size_to_va_pool()` indexes `vn->pool[MAX_VA_SIZE_PAGES]` using `(size - 1) / PAGE_SIZE`, so callers (`node_alloc()`, `node_pool_add_va()`) must never pass `size == 0`. In `alloc_vmap_area()`, `node` is the NUMA node ID (`int`) for slab/preload allocations, whereas `vn` and `vn_id` identify the KVA partition in `vmap_nodes[]`. [F79, F106]
- In `kasan_release_vmalloc_node()`, KASAN shadow pages across `vn->purge_list` must be released with `KASAN_VMALLOC_PAGE_RANGE` in the per-`vmap_area` loop first, followed by a single `kasan_release_vmalloc(start, end, start, end, KASAN_VMALLOC_TLB_FLUSH)` after the loop. [F93]
- `reclaim_list_global()`, `decay_va_pool_node()`, and `purge_vmap_node()` must iterate with `list_for_each_entry_safe()`. `vfree_atomic()` writes a `struct llist_node` into `*addr` (requiring mapped, writable memory `>= sizeof(struct llist_node)`), must call `kmemleak_free(addr)` before `llist_add()`, and `delayed_vfree_work()` must traverse `llist_del_all(&p->list)` with `llist_for_each_safe()`. [F94, F96, F125]
- `__vmap_pages_range_noflush()` must use `page_to_phys(pages[i])` rather than `__pa(page_address(pages[i]))`, and `set_area_direct_map()` / `vm_reset_perms()` must guard `page_address(area->pages[i])` against `NULL`, because `vmalloc` allocates with `__GFP_HIGHMEM`. `addr_to_vb_xa()` must advance `index = cpumask_next(index, cpu_possible_mask)` when `!cpu_possible(index)`. [F141, F146]
