# VFIO DRIVER

`drivers/vfio` exposes direct device access to userspace with IOMMU isolation via VFIO containers, IOMMU groups, device cdevs, and iommufd bindings, alongside the core VFIO PCI meta-driver and the VirtIO VFIO PCI driver.

## Architecture & Data Flow
- On `struct vfio_group`, `group->opened_file` (group fd) and `group->cdev_device_open_cnt` (cdev bind) are mutually exclusive under `group->group_lock` (`vfio_device_block_group()`, `vfio_group_fops_open()`). Every opened device `struct file` must set `filep->f_mapping = device->inode->i_mapping` so `vfio_pci_zap_bars()` unmaps BAR VMAs across all fds. In `vfio_pci_core_register_device()`, SR-IOV VFs (`pdev->is_virtfn`) and root-bus devices must get a dedicated per-device `vfio_device_set` keyed on `vdev`. [F63, F79, F179]
- Because 0 is BAR0/INTx, `vdev->msix_bar` is `0xFF` when MSI-X is absent and `vdev->irq_type` is `VFIO_PCI_NUM_IRQS` when no IRQ is active. For `vdev->nointx`, re-assert DisINTx via `pci_intx(pdev, 0)` after `pci_free_irq_vectors()` in `vfio_msi_disable()` and `PCI_COMMAND_INTX_DISABLE` in `vfio_bar_restore()`. `vfio_pci_core_runtime_suspend()` records `vfio_pci_intx_mask(vdev)` in `vdev->pm_intx_masked`, and `vfio_pci_core_runtime_resume()` only calls `vfio_pci_intx_unmask(vdev)` if `pm_intx_masked` is true. [F50, F71, F138]
- `vfio_pci_ioctl_get_region_info()`, `vfio_pci_rw()`, and `vfio_pci_core_mmap()` must verify `index < VFIO_PCI_NUM_REGIONS + vdev->num_regions` and subtract `VFIO_PCI_NUM_REGIONS` before indexing `vdev->region[]`. `vfio_pci_core_mmap()` and `vfio_pci_ioeventfd()` must reject `index >= VFIO_PCI_ROM_REGION_INDEX` (`> VFIO_PCI_BAR5_REGION_INDEX`) before indexing `bar_mmap_supported[]` or `barmap[]`, and `vfio_pci_core_do_io_rw()` / `vfio_pci_ioeventfd()` must exclude `[vdev->msix_offset, vdev->msix_offset + vdev->msix_size)` on `vdev->msix_bar`. [F82, F83, F84]
- In `vfio_pci_config.c`, `vdev->vconfig` and `perm->virt`/`perm->write` (`p_setw()`/`p_setd()`) store little-endian values; `alloc_perm_bits()` must `round_up(size, 4)`, and `vfio_config_do_rw()` clamps accesses via `vfio_pci_cap_remaining_dword()` to 1, 2, or 4 bytes and bounds `cap_id <= PCI_EXT_CAP_ID_MAX` before indexing `ecap_perms[]` (else `direct_ro_perms`). Virtual BAR writes in `vfio_basic_config_write()` set `vdev->bardirty = true`, and reads in `vfio_basic_config_read()` call `vfio_bar_fixup(vdev)` (which uses a `u64` size mask and increments `vbar++` and `i++` twice for 64-bit BARs). [F69, F81, F85, F86, F109, F118]
- Check `pdev->no_command_memory` (not `pdev->is_virtfn`) in `__vfio_pci_memory_enabled()` and `vfio_pci_config.c` for devices without writable `PCI_COMMAND_MEMORY`. In `vfio_pci_rdwr.c`, `vfio_pci_core_ioread*`/`iowrite*` must use `ioread*be`/`iowrite*be` on big-endian hosts under `down_read(&vdev->memory_lock)` while checking `__vfio_pci_memory_enabled(vdev)` when `test_mem` is true. [F142, F147]
- Because `virtvdev->state_mutex` and `reset_lock` are only initialized when `virtvdev->migrate_cap` is set, migration open/close/reset hooks must check `if (!virtvdev->migrate_cap) return;` first, and `migf->has_obj_id` (not `migf->obj_id`, which can be 0) gates using/freeing `migf->obj_id`. In `migrate.c`, when `vhca_buf->include_header_object` is set, `sizeof(struct virtio_admin_cmd_resource_obj_cmd_hdr)` is reserved at SG offset 0 while `vhca_buf->length` counts payload bytes, and any interior `sg_mark_end()` / `last_offset_sg->length` change must be restored via `sg_unmark_end()` immediately after the admin command. [F49, F51, F90, F166]

## Synchronization
- Lock order: `vfio.group_lock` -> `group->group_lock` -> `container->group_lock` -> `vfio.iommu_drivers_lock`, and `device->group->group_lock` before `device->dev_set->lock` (including `vfio_device_block_group()` before `dev_set->lock` in `vfio_df_ioctl_bind_iommufd()`). `vfio_group_set_kvm()` (called under `kvm->lock`) must never take `group_lock` or `dev_set->lock` and instead uses `group->kvm_ref_lock` with `vfio_device_group_get_kvm_safe()`. [F23, F26, F155]
- All helpers in `drivers/vfio/iommufd.c` require `vdev->dev_set->lock` held. In `vfio_df_ioctl_bind_iommufd()` and `vfio_df_group_open()`, `df->access_granted` must be set to `true` via `smp_store_release()` under `device->dev_set->lock` only after `vfio_df_open()` and IOAS attach/`out_devid` copy succeed, pairing with `smp_load_acquire()` in `vfio_device_fops`. [F22, F27]
- `vdev->igate` nests outside `vdev->memory_lock`: MSI/MSI-X helpers in `vfio_pci_intrs.c` and `pci_map_rom()` in `vfio_pci_ioctl_get_region_info()` must wrap calls in `vfio_pci_memory_lock_and_enable()` / `vfio_pci_memory_unlock_and_restore()`, while holders of `vdev->memory_lock` (`vfio_basic_config_write()`, runtime PM) must drop it before calling `vfio_pci_intx_mask()` or `vfio_pci_intx_unmask()`. [F144, F156]
- Never hold `vdev->memory_lock` across `copy_to_user()` or `copy_from_user()` (BAR mmap faults take `down_read(&vdev->memory_lock)` in `vfio_pci_mmap_huge_fault()`). In `vfio_pci_dev_set_hot_reset()`, each device's `vdev->memory_lock` in `dev_set->device_list` must be acquired via `down_write_trylock()` under `dev_set->lock`; early break must occur before `down_write_trylock()` (`list_prev_entry()`), normal completion sets `vdev = list_last_entry()`, and `err_undo` uses `list_for_each_entry_from_reverse()`. [F32, F34, F105]
- INTx mask/unmask must hold `vdev->igate` across `is_intx(vdev)` and `spin_lock_irqsave(&vdev->irqlock, flags)` around `ctx->masked` and hardware state. `vfio_intx_enable()` must set `ctx->masked` and `vdev->irq_type` before `request_irq()` (with `IRQ_DISABLE_UNLAZY` and `IRQF_NO_AUTOEN` when `!vdev->pci_2_3` and masked). `vfio_intx_set_signal()` must update `ctx->trigger` via `WRITE_ONCE()` (paired with `READ_ONCE()` in `vfio_send_intx_eventfd()`) and call `synchronize_irq(pdev->irq)` and `vfio_virqfd_flush_thread(&ctx->unmask)` before `eventfd_ctx_put(old)`. [F29, F30, F136]
- In atomic `virqfd_wakeup()` context: `vfio_pci_ioeventfd_handler()` must use `down_read_trylock(&vdev->memory_lock)` when `ioeventfd->test_mem` is true (returning `1` on contention for `vfio_pci_ioeventfd_thread()`) and pass `test_mem = false` to `vfio_pci_ioeventfd_do_write()`; `vfio_pci_intx_unmask_handler()` must return `> 0` when an interrupt is pending instead of calling `vfio_send_intx_eventfd()` directly. [F152, F153]
- `vfio_pci_core_sriov_configure()` must add `vdev->sriov_pfs_item` to `vfio_pci_sriov_pfs` and unlock `vfio_pci_sriov_pfs_mutex` before `pci_enable_sriov()`. Because `vfio_device_get_from_name()` holds `group->device_lock` during `vfio_pci_core_match()`, `vfio_pci_core_match_token_uuid()` must resolve the PF via `vdev->sriov_pf_core_dev` rather than locking `group->device_lock`. [F38, F160]
- In `migrate.c`, lock order is `virtvdev->state_mutex` -> `migf->lock` -> `migf->list_lock` (`virtiovf_free_data_buffer()` runs outside `list_lock`). `virtiovf_migration_reset_done()` must use `mutex_trylock(&virtvdev->state_mutex)` under `virtvdev->reset_lock` (setting `deferred_reset = true` on contention), and `virtvdev->state_mutex` must always be unlocked via `virtiovf_state_mutex_unlock()`. [F39, F40]

## Object Lifetimes
- `vfio_df_group_open()` must call `vfio_df_open()` even for noiommu devices (`vfio_df_iommufd_bind/unbind()` return early) to balance `vfio_df_close()`. In `vfio_df_ioctl_bind_iommufd()`, failure after `vfio_device_block_group()` must unwind `vfio_df_open()`, `vfio_df_get_kvm_safe()`, and `iommufd_ctx_from_fd()`, reset `df->iommufd = NULL`, and call `vfio_device_unblock_group()`, while `vfio_df_unbind_iommufd()` only runs if `df->access_granted` is true. [F1, F5, F52]
- `vfio_iommufd_physical_unbind()` (under `vdev->dev_set->lock`) must detach/free all PASIDs in `vdev->pasids`, detach `IOMMU_NO_PASID` and clear `vdev->iommufd_attached`, then call `iommufd_device_unbind()` and clear `vdev->iommufd_device = NULL`. Detaching the last group in `vfio_group_detach_container()` when `container->iommu_driver` is set must call `driver->ops->release()`, drop the module ref, and clear `iommu_driver` and `iommu_data` under `container->group_lock`. [F4, F6, F80]
- `vfio_pci_core_init_dev()` must initialize `dummy_resources_list`, `ioeventfds_list`, `sriov_pfs_item`, and `ctx` at allocation, and any custom `vfio_device_ops::init` must call it. `vfio_pci_core_finish_enable()` must be called only after `vfio_pci_core_enable()` and all fallible driver open steps succeed, because its VF token increment and `eeh_dev_open()` are undone by `vfio_pci_core_close_device()`, not `vfio_pci_core_disable()`. [F9, F57]
- `vfio_pci_set_power_state()` must `kfree(vdev->pm_save)` before overwriting it via `pci_store_saved_state()` on D3hot, and `vfio_pci_core_release_dev()` frees any remaining `pm_save`. `__vfio_pci_runtime_pm_exit()` must gate `pm_runtime_get_noresume()` and `eventfd_ctx_put(vdev->pm_wake_eventfd_ctx)` on `vdev->pm_runtime_engaged` under `vdev->memory_lock`. In `vfio_msi_disable()`, `vfio_virqfd_disable()` on `ctx->unmask` and `ctx->mask` must precede `vfio_msi_set_vector_signal(vdev, i, -1, msix)` because the latter frees `ctx`. [F8, F15, F107]
- After `anon_inode_getfile()` succeeds in `virtiovf_pci_save_device_data()` or `virtiovf_pci_resume_device_data()`, error paths must call `virtiovf_clean_migf_resources(migf)` and `fput(migf->filp)` (never `kfree(migf)`). Storing `saving_migf` or `resuming_migf` requires `get_file(migf->filp)`, released by `virtiovf_disable_fds()`. In `virtiovf_pci_get_data_size()`, a temporary `obj_id` (`!obj_id_exists`) must be freed via `virtiovf_pci_free_obj_id()`, whereas an existing `saving_migf->obj_id` must not. [F17, F18, F21]

## API Contracts
- `vfio_check_feature()` returns `1` to proceed with GET/SET, `0` on `VFIO_DEVICE_FEATURE_PROBE`, or `-errno`; callers must check `if (ret != 1) return ret;`. `vfio_iommufd_get_dev_id()` returns `> 0` when bound to `ictx` and `-ENOENT` when unbound but group-owned by `ictx`; ownership checks must treat both as owned. `vfio_iommu_driver_ops::open` can return `NULL` on success (`vfio_noiommu_open()`), so `vfio_ioctl_set_iommu()` must check `IS_ERR(data)` and container code must check `container->iommu_driver` (not `iommu_data`). [F41, F42, F48]
- `vfio_pci_core_register_dev_region()` and `vfio_intx_enable()`/`vfio_intx_set_signal()` take ownership of `data` / `trigger` only on success; callers free/put on error. Region `rw` callbacks (`vfio_pci_regops::rw`, `vfio_pci_core_do_io_rw()`) must use signed `ssize_t` and advance `*ppos` only when `>= 0`. `vfio_pci_core_range_intersect_range()` takes `*ppos & VFIO_PCI_OFFSET_MASK` as `buf_start`, indexing `buf` by `*buf_offset` and the register by `*register_offset`. In `struct perm_bits` callbacks, `pos` is config-space offset while `offset` is capability-relative (`perm->virt`/`write`). [F11, F13, F46, F59, F60]
- Before PCI reset or runtime suspend (`vfio_pci_core_runtime_suspend()`, `vfio_pci_core_disable()`, `vfio_pci_ioctl_reset()`, `vfio_pci_dev_set_hot_reset()`), call `vfio_pci_set_power_state(vdev, PCI_D0)`. In `vfio_pci_core_mmap()`, BAR VMAs must set `pgprot_noncached()`, `pgprot_decrypted()`, and `VM_ALLOW_ANY_UNCACHED | VM_IO | VM_PFNMAP | VM_DONTEXPAND | VM_DONTDUMP` during `.mmap()`. [F148, F165]

## Error Handling
- Convert non-zero `copy_to/from_user()` returns to `-EFAULT` and `pci_read_config_*()` returns in `vfio_pci_config.c` via `pcibios_err_to_errno()`; when `len < 0` in `vfio_cap_init()`/`vfio_ecap_init()`, return `len` (not `ret`). Optional helpers (`vfio_pci_igd_init()`, `vfio_pci_info_zdev_add_caps()`, `vfio_pci_info_atomic_cap()`) return `-ENODEV` when absent; callers fail only on `ret && ret != -ENODEV`. [F44, F47, F55, F99]
- During disable/teardown (`vfio_pci_core_disable()`, `vfio_config_free()`, `vfio_config_init()`), reset freed `vdev` pointers (`region`, `vconfig`, `pci_config_map`, `msi_perm`, `barmap[bar]`) and `num_regions` to `NULL`/`0`. Never leave an `ERR_PTR` in `migf->buf` or `migf->buf_header`, and refresh local `vhca_buf_header` when reallocating `migf->buf_header` in `virtiovf_resume_write()`. Unwinding inside `list_for_each_entry()` in `__vfio_container_attach_groups()` and `vfio_pci_dev_set_pm_runtime_get()` must use `list_for_each_entry_continue_reverse()`. [F53, F54, F75, F106]

## External Contracts
- Opening/attaching `VFIO_NO_IOMMU` requires `capable(CAP_SYS_RAWIO)` and rejects mixing with non-noiommu groups or iommufd compat IOAS. `VFIO_DEVICE_BIND_IOMMUFD` must reject if `df->group` is set and validate `match_token_uuid` via `vfio_df_check_token()` under `dev_set->lock`; `VFIO_DEVICE_FEATURE_PCI_VF_TOKEN` must only support `SET` (never `GET`). In `vfio_pci_ioctl_pci_hot_reset()`, reject `!!hdr.count == vfio_device_cdev_opened(&vdev->vdev)` with `-EINVAL`. [F94, F174, F175, F182]

## Known Pitfalls
- Because `vfio_df_close()` calls `vfio_df_device_last_close()` before decrementing `device->open_count` from 1 to 0, close/disable paths checking if sibling devices in `dev_set` are open (`vfio_pci_dev_set_needs_reset()`) must check `vfio_device_set_open_count(dev_set) > 1`. On SR-IOV VFs (`pdev->is_virtfn`), VF token logic must dereference `vdev->sriov_pf_core_dev->vf_token`, not `vdev->vf_token`. [F7, F114]
- In `vfio_pci_fill_devs()` with `VFIO_PCI_HOT_RESET_FLAG_DEV_ID`, call `vfio_iommufd_device_ictx()` on `fill->vdev` and `vfio_iommufd_get_dev_id()` on the walked `vdev`; initialize `count = 0` before `vfio_pci_for_each_slot_or_bus(..., vfio_pci_count_devs, &count, ...)`. Cast multi-byte variable addresses to `(u8 *)` or `(void *)` before adding byte offsets in `vfio_pci_igd_rw()` and `virtiovf_pci_read/write_config()`, and divide `offset - cur_offset` by `PAGE_SIZE` before adding to `sg_page(sg)` in `virtiovf_get_migration_page()`. [F56, F115, F121, F122]
