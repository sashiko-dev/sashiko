# Hyper-V/Azure CORE AND DRIVERS

This unit implements core Hyper-V guest and root-partition (`mshv`) infrastructure—including hypervisor detection, hypercalls, synthetic timers, and VMBus channel/ring-buffer management—alongside paravirtualized drivers and userspace daemons for networking (`hv_netvsc`), virtual PCIe (`pci-hyperv`), SCSI/FC storage (`storvsc`), dynamic memory ballooning/hot-add (`hv_balloon`), AF_VSOCK (`hyperv_transport`), UIO (`uio_hv_generic`), HID (`hid-hyperv`), and integration utilities (`hv_util`, `hv_kvp`, `hv_snapshot`, `tools/hv/*`).

## Architecture & Data Flow
- Every path through `vmbus_onoffer()` and `vmbus_process_offer()` must decrement `vmbus_connection.offer_in_progress` exactly once (under `channel_mutex` when linking into `chn_list`, `sc_list`, or `channels[]`), and queue `vmbus_add_channel_work()` onto `handle_primary_chan_wq` (primary) or `handle_sub_chan_wq` (sub-channels). [F8, F185]
- Across hibernation, `vmbus_bus_suspend()` unmaps channels via `vmbus_channel_unmap_relid()` and sets `offermsg.child_relid = INVALID_RELID` (`hv_process_channel_removal()` must skip unmapping and `vmbus_release_relid()` when `INVALID_RELID`); on resume (`oldchannel != NULL`), `vmbus_onoffer()` must update `child_relid`, call `vmbus_setup_channel_state()` if `offer` changed, and call `vmbus_channel_map_relid()` under `channel_mutex`. [F67, F68]
- `vmbus_devs[]` must match `enum vmbus_device_type` indices, and `channel_message_table[]` must match `enum vmbus_channel_message_type` indices with `min_payload_len >= sizeof` the handler's struct. When `hv_is_isolation_supported()`, `vmbus_connect()` must reject versions `< VERSION_WIN10_V5_2` and `vmbus_is_valid_offer()` must reject non-hvsock offers without `.allowed_in_isolated = true`. [F87, F88, F89, F166]
- Under `dm_device.ha_lock` (dropped before `hv_mem_hot_add()`), `pfn_covered()` must record non-contiguous `[has->covered_end_pfn, start_pfn)` gaps in `has->gap_list`; `hv_mem_hot_add()` must advance `ha_end_pfn` and `covered_end_pfn` under `ha_lock` before `add_memory()` and roll both back on error; and `hv_page_online_one()` must mark unbacked PFNs (`!has_pfn_is_backed()`) with `__SetPageOffline()`. [F42, F73, F74, F564]
- On `struct vmbus_channel`, `primary_channel` is `NULL` on primary channels and non-NULL on subchannels (where `device_obj` is `NULL`), so shared callbacks must resolve `hv_device` via `chan->primary_channel ? chan->primary_channel->device_obj : chan->device_obj`. [F429]
- In `netvsc_switch_datapath()`, `data_path_is_vf` must be cleared before sending `NVSP_MSG4_TYPE_SWITCH_DATA_PATH` when `!vf` and set to `true` only after `wait_for_completion(&nv_dev->channel_init_wait)` succeeds when `vf` is true; `netvsc_resume()` must reset `data_path_is_vf = false` before `netvsc_attach()`, and `netvsc_unregister_vf()` must call `reinit_completion(&net_device_ctx->vf_add)`. [F251, F265]
- `netvsc_register_vf()` and `netvsc_netdev_event()` (`NETDEV_REGISTER` on `netvsc`, deferred to `ndev_ctx->vfns_work`) must keep `vf_netdev` in `dev_net(ndev)` via `dev_change_net_namespace()`; `netvsc_register_vf()` must raise `ndev->needed_headroom` to `vf_netdev->needed_headroom`, sync `vf_netdev->wanted_features`, and propagate XDP via `netvsc_vf_setxdp()`, while `netvsc_unregister_vf()` resets `needed_headroom` to `RNDIS_AND_PPI_SIZE`. [F253, F361, F371]
- `netvsc_poll()` persists `nvchan->desc` across NAPI polls (calling `hv_pkt_iter_first()` only when `!nvchan->desc`), must not advance `mrc->first` when `send_recv_completions()` fails, and because a transfer-page descriptor can carry multiple RNDIS packets, must only call `napi_complete_done(napi, work_done)` when `work_done < budget` and return `min(work_done, budget)`. [F304, F377]
- In `hv_compose_msi_msg()`, an existing `data->chip_data` (`struct tran_int_desc`) must only be reused when `multi_msi` (`!msi_desc->pci.msi_attrib.is_msix && msi_desc->nvec_used > 1`, where secondary IRQs keep `int_desc->vector_count == 0` so `hv_int_desc_free()` skips `PCI_DELETE_INTERRUPT_MESSAGE` and dummy vCPUs use `hv_compose_multi_msi_req_get_cpu()`); single-MSI and MSI-X must free any existing `chip_data` via `hv_int_desc_free()` first. [F264, F305, F347]

## Synchronization
- Callers using per-CPU hypercall pages (`hyperv_pcpu_input_arg`, `hyperv_pcpu_output_arg`, or `post_msg_page` on TDX with paravisor in `hv_post_message()`)—including `hv_pci_read_mmio()` (which must place `out` at `*this_cpu_ptr(hyperv_pcpu_input_arg) + sizeof(*in)`), `hv_pci_write_mmio()`, and `hv_irq_retarget_interrupt()`—must disable local IRQs with `local_irq_save()` across buffer setup, hypercall, and output reads. [F81, F178, F263]
- All accesses to `vmbus_connection.chn_msg_list` must hold `vmbus_connection.channelmsg_lock` via `spin_lock_irqsave()`; in `__vmbus_establish_gpadl()`, `__vmbus_open()`, and `vmbus_teardown_gpadl()`, `msginfo` must be added to `chn_msg_list` before `vmbus_post_msg()` and `channel->rescind` must be checked under `channelmsg_lock` after insertion before `wait_for_completion(&msginfo->waitevent)`. [F21, F197]
- `vmbus_add_channel_work()` must set `newchannel->probe_done = true` on all paths, and `vmbus_onoffer_rescind()` must wait until `READ_ONCE(channel->probe_done)` is true after `vmbus_rescind_cleanup()` before unregistering or removing the channel, evaluating `clean_up_chan_for_suspend` before `vmbus_device_unregister()` or `hv_process_channel_removal()` frees `channel`. [F28, F119]
- `hv_get_bytes_to_read()` and `hv_get_bytes_to_write()` must use `READ_ONCE()` on `write_index`/`read_index`; `hv_begin_read()` and `hv_end_read()` must issue `virt_mb()` after writing `interrupt_mask` (with `hv_end_read()` re-checking `hv_get_bytes_to_read()` after the barrier); and in `vmbus_on_event()`, if `HV_CALL_BATCHED` sees `hv_end_read() != 0`, it must call `hv_begin_read()` and `tasklet_schedule(&channel->callback_event)` rather than looping. [F113, F423, F424]
- In `netvsc_probe()`, `rtnl_lock()` must be held from before `rndis_filter_device_add()` through scheduling `nvdev->subchan_work`, `register_netdevice()`, and adding to `netvsc_dev_list`; workqueue handlers (`netvsc_subchan_work`, `netvsc_vf_setup`, `netvsc_vfns_work`, `netvsc_link_change`) must use `rtnl_trylock()`, reschedule on contention, and re-validate pointers after locking. [F216, F220]
- In `netvsc_device_add()` and `netvsc_sc_open()`, `nvchan->channel` and `napi_enable()` / `netif_queue_set_napi()` must be set before `vmbus_open()`, and `rcu_assign_pointer(net_device_ctx->nvdev, net_device)` must happen only after `netvsc_connect_vsp()`; in `netvsc_device_remove()`, `napi_disable()` and `netif_queue_set_napi(..., NULL)` must only be called for `i < ndev->real_num_rx_queues`, whereas `netif_napi_del()` runs for all `i < net_device->num_chn`. [F200, F219]
- In `pci-hyperv`, `hbus->state_lock` must be held across `hv_pci_enter_d0()`, resource allocation, BAR prepopulation, and `create_root_hv_pci_bus()` in `hv_pci_probe()`/`hv_pci_resume()`, and throughout `pci_devices_present_work()` and `hv_eject_device_work()`; in `hv_pci_remove()` and `hv_pci_suspend()`, `tasklet_disable(&hdev->channel->callback_event)` must wrap transitioning to `hv_pcibus_removing`, and `hbus->wq` must be flushed/destroyed before `hv_pci_bus_exit()`. [F226, F228]
- Because `hv_compose_msi_msg()` runs with IRQ locks held, it must use `GFP_ATOMIC`, `tasklet_disable_in_atomic(&channel->callback_event)`, and poll `try_wait_for_completion()` while calling `hv_pci_onchannelcallback(hbus)` under `spin_lock_irqsave(&channel->sched_lock, flags)` when `onchannel_callback != NULL`; if a stack-allocated `pci_packet` request times out or aborts, it must remove `trans_id` via `vmbus_request_addr_match()` before returning, and `hv_pci_onchannelcallback()` must call `completion_func()` under `lock_requestor()`. [F30, F365, F366]
- In `storvsc`, before `vmbus_open()`, `channel->max_pkt_size` and `next_request_id_callback` must be set (and `vmbus_set_sc_create_callback()` must precede `VSTOR_OPERATION_CREATE_SUB_CHANNELS`), publishing sub-channels to `stor_chns[]` and `alloced_cpus` only after `vmbus_open()` succeeds; runtime updates to `stor_chns[]` and `alloced_cpus` in `storvsc_change_target_cpu()` and `get_og_chn()` require `spin_lock_irqsave(&stor_device->lock, flags)` paired with `READ_ONCE()`/`WRITE_ONCE()`, and `storvsc_dev_remove()`/`storvsc_suspend()` must set `destroy = true` (`wmb()`) and call `storvsc_wait_to_drain()` before closing or freeing channels. [F408, F410, F413, F414, F487, F531, F533]
- In `hvs_open_connection()`, `lock_sock(sk)` must be held after `vsock_find_bound_socket()` while checking `sk->sk_state` and opening `chan` (with `set_per_channel_state()` and `sock_hold()` on `conn_from_host ? new : sk` before `vmbus_set_chn_rescind_callback()`, resetting `chan = NULL` and calling `sock_put(new)` if `vmbus_open()` fails, and calling `sock_put(sk)` before `release_sock(sk)` at `out:`); `hvs_do_close_lock_held()` holds `lock_sock(sk)` and must use `cancel_delayed_work(&vsk->close_work)` (never `_sync`). [F401, F420, F421, F422, F489, F549]

## Object Lifetimes
- `vmbus_device_register()` consumes ownership of `newchannel->device_obj` and frees it on failure, so `vmbus_add_channel_work()` must not `kfree(newchannel->device_obj)`; conversely, before `newchannel->kobj` is initialized in `vmbus_add_channel_work()`, early error paths in `vmbus_process_offer()` or `vmbus_onoffer()` must call `kfree(newchannel)` instead of `free_channel()`. [F1, F2]
- `vmbus_disconnect_ring()` must first close and remove all sub-channels on `channel->sc_list` using `list_for_each_entry_safe()` (waiting on `rescind_event` if `rescind` is set and calling `hv_process_channel_removal()` under `channel_mutex`); `vmbus_close_internal()` must first call `vmbus_reset_channel_cb()` (disabling `callback_event` and clearing `onchannel_callback` under `sched_lock`) and only call `vmbus_free_requestor()` and allow `vmbus_free_ring()` when both `CHANNELMSG_CLOSECHANNEL` and `vmbus_teardown_gpadl()` succeed. [F5, F6, F116, F186]
- Pages decrypted with `set_memory_decrypted()` must be `memset()`-zeroed after decryption; `__vmbus_establish_gpadl()` must set `gpadl->decrypted = true` before `set_memory_decrypted()` (`PFN_UP(size)` pages) and only clear `decrypted` if `set_memory_encrypted()` succeeds; if `set_memory_decrypted()` or `set_memory_encrypted()` fails in SynIC, VMBus, GPADL, or `hv_uio` paths, the pages must be leaked rather than freed (`vmbus_free_ring()` and `hv_uio_cleanup()` must check `!gpadl.decrypted`). [F52, F69, F132, F181, F557]
- `new_pcichild_device()` must initialize `hpdev->desc` and take two initial references (`refcount_set(&hpdev->refs, 1)` plus `get_pcichild(hpdev)`) before adding `hpdev` to `hbus->children` under `hbus->device_list_lock`, so removing a child from `hbus->children` in `pci_devices_present_work()`, `hv_pci_bus_exit()`, or `hv_eject_device_work()` requires two `put_pcichild(hpdev)` calls (and `get_pcichild_wslot()` must increment `refs` under `device_list_lock`). [F232, F350]
- In `storvsc_queuecommand()`, once `scsi_dma_map(scmnd)` succeeds, `scsi_dma_unmap(scmnd)` must be called if `storvsc_do_io()` returns non-zero; in `storvsc_command_completion()`, `cmd_request->payload` and `payload_sz` must be saved to locals before `scsi_done(scmnd)`, and `kfree(payload)` called only when `payload_sz > sizeof(struct vmbus_channel_packet_multipage_buffer)`. [F392, F393]

## API Contracts
- `hyperv_pcpu_input_arg` and `hyperv_pcpu_output_arg` are `void * __percpu *` variables allocated once per CPU (never freed in `hv_common_cpu_die()`, and kept `NULL` in `hv_common_cpu_init()` until `set_memory_decrypted()` and `memset()` finish); callers must dereference `*this_cpu_ptr(...)` (checking non-NULL and `hv_output_page_exists()` for output, and zeroing reused headers/reserved fields) and pass only directly mapped, 8-byte-aligned memory (`virt_to_phys()`-compatible, never stack or `vmalloc`) to `hv_do_hypercall()`. [F10, F46, F47, F48, F60, F168]
- `hv_call_deposit_pages()` must reject `num_pages > HV_DEPOSIT_MAX`, splits each high-order allocation with `split_page(pages[i], order)`, and transfers ownership to the hypervisor on `HVCALL_DEPOSIT_MEMORY` success; on allocation or hypercall failure, it must set `num_allocations = i` and free individual order-0 pages (`__free_page(pfn_to_page(base_pfn + j))`), while `hv_balloon` must release pages from `alloc_balloon_pages()` via `free_balloon_pages()`. [F16, F18, F105, F123]
- `netvsc_send()` consumes previously batched `msdp->skb` packets (freeing `msd_skb` and its `send_buf_index` slot via `netvsc_free_send_slot()` on `netvsc_send_pkt()` failure), but leaves the current `skb` unfreed when returning an error to `netvsc_xmit()`; `netvsc_dma_unmap()` must be called on `vmbus_sendpacket_mpb_desc()` failure, in `netvsc_send_tx_complete()` for data SKBs, and in `rndis_filter_receive_response()` for control requests (`skb == NULL`). [F201, F202]
- `netvsc_xdp_set()` adds `nvdev->num_chn - 1` references to `prog` (consuming the caller's reference for channel 0) and drops `nvdev->num_chn` references from `old_prog`, so callers reusing `dev_info->bprog` (`netvsc_attach()`) must call `bpf_prog_inc(prog)` before `netvsc_xdp_set()` and `bpf_prog_put(prog)` on failure; in `netvsc_run_xdp()` and `netvsc_alloc_recv_skb()`, the `xdp_buff` page must be freed unless `act` is `XDP_PASS`, `XDP_TX`, or a successful `XDP_REDIRECT` (or if `build_skb()` fails). [F204, F379]

## Error Handling
- Hypercall helpers (`hv_do_hypercall`, `hv_do_rep_hypercall`, `hv_ghcb_hypercall`, `hv_tdx_hypercall`) return a 64-bit status where low 16 bits (`hv_result`) hold the status and bits [43:32] (`hv_repcomp`) hold completed reps, so callers must check `hv_result_success(status)` and convert via `hv_result_to_errno(status)`; `hv_post_message()` returns `-EMSGSIZE` or a positive 16-bit `HV_STATUS_*` code, so callers needing negative errno and retry backoff must use `vmbus_post_msg()`. [F44, F45]

## External Contracts
- For `HV_GPADL_RING` GPADLs, guest ring headers occupy `PAGE_SIZE` each while Hyper-V uses `HV_HYP_PAGE_SIZE`, so `hv_gpadl_size()`, `hv_ring_gpadl_send_hvpgoffset()`, and `hv_gpadl_hvpfn()` must subtract multiples of `PAGE_SIZE - HV_HYP_PAGE_SIZE` before shifting by `HV_HYP_PAGE_SHIFT` (`virt_to_hvpfn()` must handle `is_vmalloc_addr()`); in `netvsc_build_mpb_array()` and `storvsc_queuecommand()`, every `hv_page_buffer` / SGL segment must use `offset_in_hvpage()` (`< HV_HYP_PAGE_SIZE`) and round PFN counts up via `HVPFN_UP(offset + len)`. [F131, F312, F488, F508, F559, F579]
- Because incoming `data` in `rndis_filter_receive()` is in the host-shared GPADL buffer `net_device->recv_buf`, `netvsc_receive()` must verify `buflen <= net_device->recv_section_size` and copy RNDIS headers, `rndis_packet`, and PPIs into `nvchan->recv_buf` before validating or reading them; in `storvsc_on_io_completion()` and `storvsc_command_completion()`, `sense_info_length` must be clamped to `STORVSC_SENSE_BUFFER_SIZE` and `data_transfer_length` zeroed on non-overrun errors and clamped to `payload->range.len`. [F269, F277, F466]

## Known Pitfalls
- `struct rndis_device::link_state` has inverted polarity (`false` = link up, `true` = link down); `struct nvsc_rsc` fields (`vlan`, `csum_info`, `hash_info`) retain stale values across packets and must only be read when their bit in `nvchan->rsc.ppi_flags` is set (and `nvchan->rsc.cnt` must be reset to `0` whenever a packet is dropped or finished); `netvsc_send_pkt()` must initialize `packet->dma_range = NULL` before checking `packet->page_buf_cnt`; and `netvsc_free_send_slot()` uses `sync_change_bit()`, so it must only be called once per valid slot (`index != NETVSC_INVALID_INDEX`). [F225, F242, F244, F291, F301, F334]
