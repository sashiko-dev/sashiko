# NETWORKING DRIVERS

This unit covers core Linux network device headers (`include/linux/netdevice.h` and protocol/offload headers), virtual and tunnel drivers (`tun`, `veth`, `macvlan`/`macvtap`, `ipvlan`/`ipvtap`, `geneve`, `ifb`, `loopback`, `pfcp`, `pptp`, `bsd_comp`, `slip`/`slhc`, `plip`, `rionet`, `mhi_net`, `fjes`), physical Ethernet drivers (`gve`, `octeon_ep`/`octeon_ep_vf`, `cassini`, `k1_emac`, `epic100`, `smc9194`, `smc91c92_cs`), PHY/MDIO helpers, s390 `ctcm`, and the PTP clock subsystem (`drivers/ptp/*`).

## Architecture & Data Flow

- In `gve`, `priv->rx` and `priv->tx` are NULL when closed, so callbacks reachable while down (XSK, stats, `netdev_queue_mgmt_ops`) must check `priv->rx`/`priv->tx`, `netif_running()`, or `gve_get_napi_enabled()`. In DQO RX, `rx->dqo.page_pool` is non-NULL only in RDA mode (`cfg->raw_addressing`) and discriminates `page_info.netmem` vs `page_info.page`. In `gve_tx_ring`, `tx->netdev_txq` is NULL for XDP TX queues, so `gve_tx_stop_ring_dqo()` and `gve_clean_tx_done_dqo()` must guard `netdev_tx_*` calls on `if (tx->netdev_txq)`. [F37, F39, F45, F170]
- In `gve`, when `priv->xdp_prog != NULL`, `priv->tx_cfg.num_xdp_queues` (and `tx_alloc_cfg.num_xdp_rings`) must equal `priv->rx_cfg.num_queues` (0 when NULL). Because `gve_xsk_tx_poll*()` runs in the `block->rx` branch of `gve_napi_poll*()`, `gve_xsk_wakeup()` must schedule the RX NAPI via `gve_rx_idx_to_ntfy()` for both RX and TX wakeups. `gve_reg_xsk_pool()`/`gve_unreg_xsk_pool()` must update `priv->rx[qid].xsk_pool`, `priv->tx[gve_xdp_tx_queue_id(priv, qid)].xsk_pool`, and `priv->xsk_pools` in lockstep. [F54, F55, F60, F156]
- In `octeon_ep` PF, `oct->iq[]`/`oct->oq[]` use 0-based `q_no`, but per-queue SDP CSRs must add `CFG_GET_PORTS_PF_SRN(oct->conf)`; `oct->ioq_vector[j]` binds to `oct->msix_entries[j + CFG_GET_NON_IOQ_MSIX(oct->conf)]`; and VF `vf`'s mailbox in `oct->mbox[]`, `SDP_MBOX_*_DATA`, and `SDP_EPF_MBOX_RINT` are indexed by `vf * rings_per_vf` (checking `< 64` vs `- 64` on CN93), whereas `oct->vf_info[vf]` is indexed by `vf`. [F229, F230, F259, F293]
- In `tun` (`tfile->tx_ring`) and `veth` (`rq->xdp_ring`), `sk_buff *` and `xdp_frame *` are multiplexed in the same `ptr_ring` by tagging bit 0 on `xdp_frame *` (`tun_xdp_to_ptr()`, `veth_xdp_to_ptr()`); all consumers must test `tun_is_xdp_frame()`/`veth_is_xdp_frame()` and strip bit 0 before dereferencing. In `veth`, `rq->napi` is non-NULL only when `xdp_ring` is active, so `veth_xdp_xmit()` and `veth_xmit()` must check `rcu_access_pointer(rq->napi)` before producing to `rq->xdp_ring`. [F729, F773]
- Structural layout invariants: `struct sock sk` must be the first member of `struct tun_file` and `struct pppox_sock`; `struct netdev_notifier_info info` must be first in all `netdev_notifier_*_info` structs; `struct ipvl_dev vlan` and `struct macvlan_dev vlan` must be first in `struct ipvtap_dev` and `struct macvtap_dev` (with notifier events checking `dev->rtnl_link_ops == &ipvtap_link_ops` / `&macvtap_link_ops`, not `netif_is_ipvlan()`/`netif_is_macvlan()`); and `struct ip_tunnel_info info` must be last in `struct geneve_config` (which is last in `struct geneve_dev`). [F624, F634, F635, F810, F1166, F1225]

## Synchronization

- In `gve`, internal entry points calling `gve_reset()`, `gve_close()`, or `gve_reset_recovery()` outside NDO callbacks (`gve_handle_reset()`, `gve_shutdown()`, `gve_suspend()`, `gve_resume()`) must acquire `rtnl_lock()` then `netdev_lock(dev)`. In `gve_turndown()`, `gve_turnup()`, `gve_add_napi()`, and `gve_remove_napi()`, NAPI and XDP redirect helpers must use `_locked` variants (`napi_enable_locked()`, `napi_disable_locked()`, `netif_napi_add_locked()`, `netif_napi_del_locked()`, `xdp_features_*_redirect_target_locked()`). [F24, F25]
- In `gve_turndown()`, the driver must disable all NAPIs, call `netif_tx_disable()`, clear the XDP redirect target, call `gve_clear_napi_enabled(priv)`, and run `synchronize_net()` before `gve_queues_stop()`/`gve_close()` destroy rings and free `priv->tx`/`priv->rx`. All callers of `gve_adminq_issue_cmd()` and `gve_adminq_kick_and_wait()` must run in process context (since `gve_adminq_wait_for_cmd()` sleeps) and hold `priv->adminq_lock`, zeroing any stack `union gve_adminq_command` with `memset()` first. [F20, F26, F48]
- In `octeon_ep`, `octep_get_stats64()` and `octep_vf_get_stats64()` run under RCU and must only read in-memory `oct->stats_iq`/`oct->stats_oq` without calling sleeping mailbox functions (`octep_ctrl_net_get_if_stats()`, `octep_vf_get_if_stats()`). PF-VF mailbox work (`oct->mbox[q]->wk.work`) must be scheduled on `system_wq` via `schedule_work()` (never on single-threaded `octep_wq`, where `ctrl_mbox_task` runs), and `cancel_work_sync(&oct->tx_timeout_task)` / `cancel_delayed_work_sync(&oct->hb_task)` must be called outside `rtnl_lock()`. [F295, F296, F299, F300]
- In `tun`, `tfile->tun` and `tun->tfiles[]` require `rcu_read_lock()` or `rtnl_lock()` (using `tun_get()`/`tun_put()` across blocking calls), and `tun_attach()`/`tun_set_iff()` must publish them via `rcu_assign_pointer()` only after queue/netdev registration succeeds. When `tun_napi_frags_enabled(tfile)` is true, `tun_get_user()` must hold `tfile->napi_mutex` from `tun_napi_alloc_frags()` through `napi_gro_frags()`, cleaning up `tfile->napi.skb` on error; when `tfile->napi_enabled` is true without frags, `tfile->detached` must be checked under `tfile->sk.sk_write_queue.lock`. [F704, F707, F708, F832]
- Per-CPU `u64_stats_t` structs (`pcpu_sw_netstats`, `pcpu_dstats`, `pcpu_lstats`, `vlan_pcpu_stats`, `veth_rq_stats`) must initialize `syncp` via `u64_stats_init()`, bracket updates with `u64_stats_update_begin()`/`end()` with preemption/BH disabled (`dev_sw_netstats_*()`, `dev_lstats_add()`, and `dev_dstats_*()` require the caller to disable preemption/BH, e.g. in `tun.c`), and read via `u64_stats_fetch_begin()`/`retry()`. [F488, F837, F844, F1071, F1195]
- In `drivers/ptp`, `ptp_clock_unregister()` must never be called while holding a driver mutex taken by `.enable` or `.do_aux_work` (`idtcm->lock`, `idt82p33->lock`, `idtfc3->lock`). `ptp_clock_event()` takes `ptp->tsevqs_lock` then `queue->lock` in hardirq context, so process-context callers must disable IRQs and never take `tsevqs_lock` inside `queue->lock`. `ptp_set_pinfunc()` requires `ptp->pincfg_mux`, and `.enable`/`.verify` callbacks must call `ptp_find_pin()` (not `ptp_find_pin_unlocked()`). [F875, F890, F1008, F1012]

## Object Lifetimes

- In `gve`, `gve_rx_queue_start()` (on error) and `gve_rx_queue_stop()` must zero `priv->rx[idx]` because the caller frees `*per_q_mem` via `gve_rx_queue_mem_free()`. `gve_queues_start()` takes ownership of `tx_alloc_cfg->tx` and `rx_alloc_cfg->rx` and frees them on error, so callers must never call `gve_queues_mem_free()` after `gve_queues_start()`. [F2, F40]
- In `gve` QPL mode, `rx->data.page_info[i].page` (GQI) and `rx->dqo.qpl->pages[idx]` (DQO) are borrowed from the QPL, so unfill/free paths (`gve_rx_unfill_pages()`, `gve_free_qpl_page_dqo()`) must only subtract `pagecnt_bias - 1` without `put_page()` (and set `buf_state->page_info.page = NULL` in DQO), whereas `rx->qpl_copy_pool[i].page` requires both `page_ref_sub()` and `put_page()`. [F3, F4]
- In `gve` DQO RDA mode (`rx->dqo.page_pool != NULL`), `gve_reuse_buffer()` transfers ownership by clearing `buf_state->page_info.netmem = 0`, while `gve_free_buffer()` returns `netmem` via `gve_free_to_page_pool()` using `page_pool_put_full_netmem()` (`allow_direct = true` in NAPI, `false` in reset/free). In `gve_rx_stop_ring_dqo()`/`gve_rx_free_ring_dqo()`, `page_pool_disable_direct_recycling()` must precede `gve_remove_napi()`, all `buf_states` must release `netmem` before `page_pool_destroy()`, and `xsk_buff_free(bs->xsk_buff)` requires `gve_buf_state_is_allocated(rx, bs)`. [F5, F6, F10, F148, F149, F168]
- In `octeon_ep` PF and VF, `octep_setup_iqs`/`oqs` must precede `octep_setup_irqs` on open, and on stop `octep_clean_irqs` must precede `octep_free_oqs` (which decrements `oct->num_oqs`) and `octep_clean_iqs` must precede `octep_free_iqs` (to unmap/free in-flight SKBs). Consumed RX pages in `oq->buff_info[read_idx].page` and freed `oq`/`ioq_vector`/`mbox` slots must be set to NULL. [F172, F173, F174, F175, F207]
- In `tun`, a non-NULL `msg_control`/`ptr` passed to `tun_recvmsg()`/`tun_do_read()` must be freed via `tun_ptr_free()` on every exit path. In `veth_napi_del_range()`, `rq->napi` must be cleared, NAPI disabled/deleted, and `synchronize_net()` called before `ptr_ring_cleanup()` and `page_pool_destroy()`. In `ipvtap_dellink()`/`macvtap_dellink()`, `netdev_rx_handler_unregister(dev)` must precede `tap_del_queues()`. [F526, F684, F840]
- In `include/linux/netdevice.h` and `inetdevice.h`, `__netif_napi_del()`/`__netif_napi_del_locked()` do not wait for RCU, so callers must observe an RCU grace period (`synchronize_net()`) before freeing `@napi`; `napi_free_frags()` and `gve_rx_free_skb()` must clear `napi->skb = NULL` when freeing `napi->skb`; `in_dev_get()` and `ip_dev_find()` return refcounted pointers requiring `in_dev_put()` and `dev_put()`, unlike `__in_dev_get_rcu()`/`_rtnl()`; and `netdev_tracker_alloc()` upgrades an existing untracked reference without calling `__dev_hold()`. [F12, F1042, F1043, F1046, F1049, F1050]

## API Contracts

- `ndo_start_xmit` return codes `< NET_XMIT_MASK` (`dev_xmit_complete(rc)`, including `NETDEV_TX_OK` and negative errnos) mean `@skb` was consumed, whereas `NETDEV_TX_BUSY` leaves `@skb` unconsumed (e.g., `epic100`, `smc9194`, `cassini` must return `NETDEV_TX_OK` when `skb_padto()` fails, and `octep_start_xmit()` must free `skb` and return `NETDEV_TX_OK` on DMA map error). `kfree_skb()`/`consume_skb()` must not be called in hardirq/irqs-disabled context (use `dev_kfree_skb_irq()`/`_any()`). Callers of `dev_queue_xmit()` must use `net_xmit_eval()`/`net_xmit_errno()` so `NET_XMIT_CN` is not treated as a drop. [F176, F486, F1039, F1052, F1079]
- In BQL, `@bytes` passed to `netdev_tx_completed_queue()` must match the exact sum passed to `netdev_tx_sent_queue()`/`__netdev_tx_sent_queue()`, and `netdev_tx_reset_queue()` must both clear `__QUEUE_STATE_STACK_XOFF` and call `dql_reset()`. When `netdev_xmit_more()` defers the TX doorbell, drivers (`gve_tx*()`, `octep_start_xmit()`, `__netdev_tx_sent_queue() == true`) must ring the doorbell whenever stopping the queue, returning `NETDEV_TX_BUSY`, or dropping a packet. [F169, F246, F312, F1097, F1116, F1182]
- `napi_complete_done()` must only be called when `work_done < budget` (e.g., in `octep_napi_poll()` when `!tx_pending && rx_done < budget`, and in `gve_napi_poll_dqo()` when migrating off a non-home CPU by decrementing `work_done`), and hardware interrupts must only be re-armed if `napi_complete_done()` returns `true`. `napi_synchronize()` only waits for `NAPI_STATE_SCHED` to clear and does not prevent future `napi_schedule()` calls. [F161, F309, F1059, F1087]
- In `ndo_bpf` (`XDP_SETUP_PROG*`, e.g., `gve_set_xdp()`, `veth_xdp_set()`), the driver must not call `bpf_prog_put()` on the new `prog` or leave `priv->xdp_prog` overwritten on error, and on success must call `bpf_prog_put(old_prog)`. In `ndo_xdp_xmit`, the driver must free dropped frames via `xdp_return_frame()` when returning a non-negative count `< n`, but must not free any frames when returning a negative errno. [F11, F696, F1081, F1082]
- Primary MAC address changes must use `dev_addr_mod()`/`eth_hw_addr_set()` (never `memcpy()` into `dev->dev_addr`), noting `eth_hw_addr_set()` does not set `addr_assign_type = NET_ADDR_RANDOM`. `ether_addr_equal_64bits()`, `is_multicast_ether_addr_64bits()`, `is_etherdev_addr()`, and `macvlan_hash_lookup*()`/`macvlan_eth_hash()` require 2-byte aligned buffers with 2 trailing padding bytes (8 readable bytes total); `ether_addr_equal()`/`ether_addr_copy()` require `u16` alignment (use `ether_addr_equal_unaligned()` otherwise). [F588, F1101, F1102, F1123, F1204]
- In `drivers/ptp`, `ptp_clock_register()` mutates `ptp_clock_info` and `pin_config[]` in place, so drivers must pass per-instance copies rather than shared static templates; `adjphase` requires `getmaxphase`, `n_pins > 0` requires `pin_config` and `verify`, and `ptp_schedule_worker()` requires `do_aux_work` (which returns `>= 0` jiffies to reschedule or `< 0` to stop). [F903, F919, F1021, F1023]

## Error Handling

- Non-standard return conventions: `gve_alloc_pending_packet()` returns NULL when pools are `-1`; `gve_rx_create_page_pool()`, `slhc_init()` (under `CONFIG_INET`), and `tap_get_socket()`/`tap_get_ptr_ring()`/`tun_get_socket()`/`tun_get_tx_ring()` return `ERR_PTR()` (check `IS_ERR()`, not NULL); `tun_build_skb()` returns `ERR_PTR()` on error, NULL when XDP consumes the frame, or `skb`; `octep_ctrl_net_get_link_status()`/`get_mtu()`, `idtfc3_read_subcounter()`, `get_output_base_addr()`, and `ptp_find_pin()` return `< 0` on error and `>= 0` values on success; `__octep_vf_mbox_send_cmd()`, `fjes_hw_issue_request_command()`, and `pch_set_station_address()` return positive status codes on failure; `mdio_read()` in `epic100.c` returns `0xffff` on timeout; and `IP_ECN_decapsulate()`/`IP6_ECN_decapsulate()` in `geneve_rx()` only indicate framing errors when `> 1`. [F36, F38, F200, F201, F356, F549, F560, F719, F733, F904, F909, F910, F911, F1086]
- `ndo_uninit` is not called if `ndo_init` fails or if `register_netdevice()` fails before `ndo_init` runs (e.g., `pfcp_newlink()` must call `pfcp_del_sock()` if `register_netdevice()` fails); conversely, in `macvlan_common_newlink()`, a failed `register_netdevice()` already ran `macvlan_uninit()`, so `destroy_macvlan_port` must check `create && macvlan_port_get_rtnl(lowerdev)` before destroying `port`. In `ipvlan_route_v6_outbound()`, `ip6_route_output()` always returns a non-NULL `dst_entry`, so `dst_release(dst)` must be called when `dst->error` is non-zero. [F505, F552, F700, F1044]

## Known Pitfalls

- Bit index vs bitmask confusion: `NETIF_F_*_BIT`, `NAPI_STATE_*`, and `__QUEUE_STATE_*` are bit indices (for `test_bit()`/`set_bit()` or `for_each_netdev_feature()`, which requires a signed `int bit`), whereas `NETIF_F_*`, `NAPIF_STATE_*`, and `QUEUE_STATE_*` are shifted bitmasks for `&`/`|`. `enum netdev_priv_flags` is full at 32 bits (`BIT_ULL(30/31)`), so new private flags must be 1-bit bitfields on `struct net_device`. Legacy `__be16` `TUNNEL_*` flags are also full; new tunnel flags must use `IP_TUNNEL_*_BIT`. [F1095, F1096, F1133, F1138, F1151]
- In `ndo_start_xmit` (`geneve_xmit_skb()`, `ipvlan_xmit_mode_l2()`, `macvlan_queue_xmit()`), `skb_mac_header` may not be set, so use `skb_eth_hdr(skb)` or call `skb_reset_mac_header(skb)` before `eth_hdr(skb)`; `macvlan_handle_frame()` must return `RX_HANDLER_PASS` on `PACKET_LOOPBACK`. Whenever `pskb_may_pull()`, `pskb_inet_may_pull()`, `skb_share_check()`, `ip_check_defrag()`, or `skb_realloc_headroom()` is called (e.g., in `geneve_rx()`, `macvlan_handle_frame()`, `ipvlan_rcv_frame()`, `ipvlan_get_L3_hdr()`, `pptp_xmit()`), cached header pointers and `*pskb` must be refreshed afterward. [F590, F638, F667, F668, F677, F851]
- In `gve`, BAR0 registers, AdminQ structs, and GQI descriptors/doorbells are big-endian (`__be*`, `iowrite32be`), whereas DQO descriptors and BAR2 doorbells are little-endian (`__le*`, `iowrite32`) at a big-endian `db_index` (`be32_to_cpu`); control-plane paths checking whether queues are allocated must test `netif_running(dev)` rather than `netif_carrier_ok(dev)`; and in DQO RX with header split (`PP_FLAG_ALLOW_UNREADABLE_NETMEM`), `gve_rx_dqo()` must check `!netmem_is_net_iov(buf_state->page_info.netmem)` before calling `netmem_to_page()` or reading `page_address`. [F57, F86, F150]
