# IMGTEC POWERVR DRM DRIVER

This unit implements the DRM driver for Imagination Technologies PowerVR (Rogue Series 6 and later) GPUs, including device initialization, META/MIPS/RISC-V firmware management, GEM/VM memory management, free list and HWRT dataset tracking, execution contexts, KCCB/FWCCB/CCCB ring communication, job scheduling, and UAPI ioctls.

## Architecture & Data Flow
- `pvr_ccb` (`kccb`, `fwccb`) uses command slot indices for `ctrl->write_offset`, `ctrl->read_offset`, and `ctrl->wrap_mask`, and `pvr_kccb_capacity()` reserves one slot (`slot_count - 1`); `pvr_cccb` uses byte offsets where `size` is a power of two (`1 << size_log2` for `get_ccb_space()`), each command sequence must fit `size / 2` with `PADDING_COMMAND_SIZE` left at the end, and `pvr_cccb_write_command_with_header()` wraps with `ROGUE_FWIF_CCB_CMD_TYPE_PADDING`. [F85, F86, F127, F134]
- Free list page counts (`initial_num_pages`, `max_num_pages`, `grow_num_pages`, `ready_pages`) are in 4 KB PM pages (`ROGUE_BIF_PM_PHYSICAL_PAGE_SIZE`) aligned to `FREE_LIST_ALIGNMENT` (4 pages); entries grow downward (`start_page = max_pages - current_pages - num_pages`), `free_list_fw_init()` and `pvr_free_list_reconstruct()` subtract `ready_pages` before setting `current_stack_top = current_pages - 1`, and `pvr_free_list_process_grow_req()` must fold `ready_pages` into `current_pages` and zero it before `pvr_free_list_grow()`. [F55, F61, F83, F84]
- In `pvr_device_info_set_common()` and `pvr_device_info_set_features()`, `const u64 *` bitmasks and sizes are in `u64` words (indexed via `bitmask[i >> 6] & BIT_ULL(i & 63)` up to `min(bitmask_size * 64, mapping_max)`, guarding `~0ull << (mapping_max & 63)` when `(mapping_max & 63) != 0`); `feature_params` is indexed by a separate `param_idx` incremented only when a set feature has non-zero `value_offset` (`param_idx < feature_param_size`), and every `struct pvr_device_features` value field must be `u64`. [F89, F109, F122, F128, F129]
- In `struct pvr_fw_mem`, `core_code_obj`, `core_data_obj`, `core_code`, and `core_data` are optional and remain NULL when absent from the firmware image; because `pvr_fw_object_*` helpers unconditionally dereference `fw_obj->gem`, callers must check `core_code_obj` and `core_data_obj` for non-NULL first, and `fw_mem->code_obj` must be mapped at offset 0 of the FW heap so offset 0 is invalid for all other FW objects. [F49, F87]
- `union pvr_context::queues` is discriminated by `ctx->type` (`geometry`/`fragment` for `RENDER`, `compute` for `COMPUTE`, `transfer` for `TRANSFER_FRAG`), and `job->hwrt` is non-NULL only for geometry and fragment jobs, so arbitrary context/job paths must check `ctx->type` (or use `pvr_context_get_queue_for_job()`) and guard `job->hwrt` for NULL; in `pvr_jobs_link_geom_frag()`, after pairing `job_data[i].job` with `job_data[i + 1].job`, the loop body must increment `i++` to skip the paired fragment job. [F46, F50, F107]

## Synchronization
- Lookups in `pvr_dev->ctx_ids` (`pvr_context_lookup_id()`) and `pvr_dev->free_list_ids` (`pvr_free_list_lookup_id()`) must hold `xa_lock` and use `kref_get_unless_zero()` because entries are erased inside `pvr_context_release()` and `pvr_free_list_release()` after `ref_count` hits zero; lookups in per-file handle XArrays (`pvr_context_lookup()`, `pvr_free_list_lookup()`, `pvr_hwrt_dataset_lookup()`) must hold `xa_lock` across both `xa_load()` and `kref_get()`. [F20, F21]
- In `pvr_destroy_contexts_for_file()`, `pvr_dev->ctx_list_lock` protects `pvr_file->contexts`, and each entry must be unlinked with `list_del_init(&ctx->file_link)` and pinned via `pvr_context_get_if_referenced(ctx)` before dropping `ctx_list_lock` to call `pvr_vm_unmap_all()` and `pvr_context_put()`. [F23]
- `pvr_dev->kccb.ccb.lock` protects `kccb.ccb.ctrl`, `kccb.ccb.ccb`, `kccb.reserved_count`, and `kccb.waiters`; `pvr_kccb_wake_up_waiters()` must iterate `kccb.waiters` with `list_for_each_entry_safe()` and stop when `available_count` reaches zero, and `pvr_kccb_reserve_slot_sync()` must poll while `time_before(jiffies, start_timestamp + RESERVE_SLOT_TIMEOUT) || retries < RESERVE_SLOT_MIN_RETRIES` (saturating `retries` at `U32_MAX`). [F25, F104, F114]
- Before calling `pvr_kccb_send_cmd_reserved_powered()` in `pvr_cccb_send_kccb_kick()` or `pvr_cccb_send_kccb_combined_kick()`, callers must have reserved a KCCB slot and ordered prior CCCB writes with `wmb()`; inside `pvr_kccb_send_cmd_reserved_powered()`, filling `kccb[old_write_offset]` and clearing `kccb.rtn[old_write_offset]` must be ordered before `WRITE_ONCE(ctrl->write_offset, new_write_offset)` by `mb()`, and `pvr_fw_mts_schedule()` must bracket `ROGUE_CR_MTS_SCHEDULE` with `wmb()` and `mb()`. [F26, F27]
- Code outside the IRQ handler, scheduler workqueue, or reset path that submits KCCB commands (`pvr_fw_structure_cleanup()`, `update_logtype()`) must acquire `down_read(&pvr_dev->reset_sem)` and then check `drm_dev_enter()`, returning `-EIO` if lost or unplugged; `pvr_dev->queues.lock` protects `queues.active` and `queues.idle` and must be held across `pvr_device_process_active_queues()`. [F38, F164]
- `pvr_fwccb_process()` must copy `fwccb[read_offset]` by value into a local `struct rogue_fwif_fwccb_cmd` and advance `ctrl->read_offset` before dropping `pvr_dev->fwccb.lock` to call `process_fwccb_command()`; in `pvr_free_list_release()`, if `pvr_fw_structure_cleanup()` returns `-EBUSY`, `pvr_fwccb_process()` must be called to drain pending HWR/freelist reconstruction requests before retrying. [F33, F67]
- `pvr_dev->fw_dev.fw_objs.lock` protects `fw_objs.list`: `pvr_fw_object_create_and_map_common()` must only insert `fw_obj->node` after mapping its GEM object and running `fw_obj->init()`, and `fw_obj->init` callbacks must never create/destroy firmware objects or acquire `fw_objs.lock` because `pvr_fw_hard_reset()` invokes `fw_obj->init()` while holding `fw_objs.lock`. [F31, F166]
- `free_list->lock` protects `current_pages`, `ready_pages`, `mem_block_list`, `hwrt_list`, and the `*_locked()` helpers; `pvr_free_list_insert_pages_locked()` must verify each shifted DMA PFN fits in 32 bits and execute `wmb()` before `pvr_gem_object_vunmap()`. [F167, F168]
- `pvr_gem_object_vmap()` and `pvr_gem_object_vunmap()` must hold `dma_resv_lock(obj->resv, NULL)` and synchronize `shmem_obj->sgt` via `dma_sync_sgtable_for_cpu()`/`device()` when `PVR_BO_CPU_CACHED` is set; in `pvr_gem_object_create()`, `shmem_obj->map_wc`, `pvr_obj->flags`, and `drm_gem_shmem_get_pages_sgt(shmem_obj)` must be initialized before `pvr_gem_object_zero()`, which runs `wmb()` before `pvr_gem_object_vunmap()`. [F36, F169]
- In `pvr_submit_jobs()`, `pvr_mmu_flush_exec()` and `prepare_job_syncs_for_each()` must run before `prepare_job_resvs_for_each()` acquires the `drm_exec` reservation locks on each `job->ctx->fw_obj->gem` and `job->hwrt->fw_obj->gem`, and those locks must remain held across `pvr_jobs_link_geom_frag()`, `update_job_resvs_for_each()`, and `push_jobs()`. [F170]

## Object Lifetimes
- `pvr_kccb_reserve_slot()` always consumes its uninitialized `@f` argument (from `pvr_kccb_fence_alloc()`, with `base` at offset 0 of `struct pvr_kccb_fence`), either freeing it via `pvr_kccb_fence_put(f)` and returning NULL when a slot is available or returning a new `dma_fence_get()` reference when queued on `kccb.waiters`; every reserved KCCB slot increments `kccb.reserved_count` and must be balanced by `pvr_kccb_send_cmd_reserved_powered()` or `pvr_kccb_release_slot()`. [F2, F4, F132]
- In `pvr_jobs_link_geom_frag()`, `get_last_queued_job_scheduled_fence()` returns a `dma_fence_get()` reference that `drm_sched_job_add_dependency(&geom_job->base, f)` consumes on both success and failure; when pairing `geom_job` and `frag_job` via `paired_job`, `frag_job->kccb_fence` must be freed with `pvr_kccb_fence_put()` and nulled, and `pvr_job_get(geom_job)` must be taken to match `pvr_job_put(job->paired_job)` in `pvr_queue_free_job()`. [F11, F13]
- `pvr_gem_object_into_handle()` consumes the caller's `pvr_obj` reference and writes `*handle` only on success (leaving ownership with the caller on failure); in `pvr_ioctl_vm_map()`, `pvr_gem_object_from_handle()` and `pvr_vm_context_lookup()` each acquire a reference that the handler must drop via `pvr_gem_object_put()` and `pvr_vm_context_put()` on both success and failure because `pvr_vm_map()` takes its own reference. [F1, F18]
- In `pvr_hwrt_dataset_create()` and `pvr_hwrt_dataset_release()`, `hwrt_data_fini_fw_structure()` must unlink each `hwrt_data` from `hwrt->free_lists[0]` before `hwrt_fini_kernel_structure()` drops the free list references, and must destroy `raa_obj` and `srtc_obj` only when `hwrt->max_rts > 1`; `hwrt->data[i].hwrt_dataset` must be initialized before exposing the dataset in `pvr_file->hwrt_handles` because `pvr_hwrt_data_lookup()`/`get()`/`put()` delegate refcounting to `hwrt_dataset->ref_count`. [F14, F15]
- Because `pvr_fw_hard_reset()` zeroes every `struct pvr_fw_object` in `fw_objs.list` without `PVR_BO_FW_NO_CLEAR_ON_RESET` and re-invokes `fw_obj->init(cpu_ptr, fw_obj->init_priv)`, `init_priv` (`ctx->data`, `hwrt->common`, `hwrt_data->data`) must stay valid for the lifetime of `fw_obj`; in `pvr_fw_process()` and `pvr_fw_cleanup()`, both host shadow buffers (`fw_mem->code`, `data`, `core_code`, `core_data`) and firmware objects (`code_obj`, `data_obj`, `core_code_obj`, `core_data_obj`) must be freed even after their CPU mappings are unmapped. [F9, F70]
- On teardown in `pvr_device_fini()`, `pvr_device_irq_fini()` must precede `pvr_device_gpu_fini()`, which must run `pvr_fw_fini()` before dropping `kernel_vm_ctx` (created only when `processor_type != PVR_FW_PROCESSOR_TYPE_MIPS`), and in `pvr_fw_init()`, `fw_dev->defs->init(pvr_dev)` must precede `drm_mm_init(&fw_dev->fw_mm, ...)`. [F16, F141, F143]

## API Contracts
- Object creation and vmap functions (`pvr_gem_object_create()`, `pvr_gem_object_vmap()`, `pvr_fw_object_create_and_map()`, `pvr_free_list_create()`, `pvr_hwrt_dataset_create()`) return `ERR_PTR` on failure, whereas handle/ID lookup functions (`pvr_gem_object_from_handle()`, `pvr_context_lookup()`, `pvr_hwrt_data_lookup()`) and `pvr_build_firmware_filename()` (via `kasprintf()`) return NULL. [F40, F43]
- `pvr_fw_object_create_and_map_offset()` takes `@dev_offset` as a 32-bit byte offset relative to `pvr_dev->fw_dev.fw_mm_base` (where 0 maps at the start of the FW heap), whereas `pvr_fw_object_fw_map()` takes `@dev_addr` as a 64-bit GPU virtual address in `fw_mm` where 0 means dynamic allocation from the main FW heap. [F56]
- `pvr_ccb_init()` takes `@num_cmds_log2` (log2 of command count) and `@cmd_size` in bytes, whereas `pvr_cccb_init()` takes `@size_log2` (log2 of total buffer bytes); `pvr_cccb_write_command_with_header()` has no internal lock (callers must serialize and check `pvr_cccb_cmdseq_fits()` first) and requires `@cmd_size` to be 8-byte aligned, and `pvr_cccb_send_kccb_combined_kick()` must pass NULL instead of `@hwrt` to `fill_cmd_kick_data()` for the fragment kick when `@frag_is_pr` is true. [F28, F58, F60]
- Userspace BO creation ioctls (`pvr_ioctl_create_bo()`) must reject flags outside `DRM_PVR_BO_FLAGS_MASK` because `pvr_gem_object_flags_validate()` allows `PVR_BO_KERNEL_FLAGS_MASK`; in `pvr_gem_object_flags_validate()`, each entry in `invalid_combinations` (`DRM_PVR_BO_PM_FW_PROTECT | DRM_PVR_BO_ALLOW_CPU_USERSPACE_ACCESS`) must be tested with `(flags & combo) == combo`, and `pvr_gem_mmap()` must reject mmap unless `DRM_PVR_BO_ALLOW_CPU_USERSPACE_ACCESS` is set. [F81, F97, F176]
- `pvr_get_uobj_array()` returns 0 without modifying `*out` when `in->count == 0` (so callers must reject `count == 0` or zero-initialize `*out` before `kvfree()`), and both `pvr_get_uobj_array()` and `pvr_set_uobj_array()` must widen `obj_size` to `unsigned long` before multiplying by `count` and allocate with `kvmalloc_array()`. [F45, F119]
- `get_fw_obj_size()` in `pvr_context.c` returns a positive byte size or `-EINVAL` (so callers must check `< 0` in a signed `int` before assigning to unsigned `ctx->data_size`), and multi-bit status polls via `pvr_cr_poll_reg32()`/`64()` (`pvr_meta_cr_read32()`, `pvr_fw_stop()`) must pass the full mask as both `reg_value` and `reg_mask`. [F44, F98]

## Error Handling
- In `pvr_submit_jobs()`, if `pvr_job_data_init()`, `prepare_job_syncs_for_each()`, or `pvr_jobs_link_geom_frag()` fails at job index `i`, it must set `*job_count` (`args->jobs.count`) to `i` for userspace (in `pvr_job_data_init()`, if `PVR_UOBJ_GET_ARRAY()` fails after `create_job()`, set `*job_count = i` before incrementing `i++` for `pvr_job_data_fini(job_data_out, i)`), and `pvr_submit_jobs()` must pass `jobs_alloced` rather than the overwritten `args->jobs.count` to `pvr_job_data_fini()`. [F12, F95, F106]
- When an `ERR_PTR`-returning call is assigned into a struct field whose teardown path checks for non-NULL (`ctx->queues.*`, `fw_obj->gem`, `trace_buffer->buf`, `job_data_out[i].job`), the field must be reset to NULL before jumping to cleanup, and sequential `IS_ERR(ptr)` checks must pass that same `ptr` to `PTR_ERR(ptr)`. [F51, F115]

## Known Pitfalls
- PowerVR register clear-masks (`ROGUE_CR_*_CLRMSK`) have 0s in the target field and 1s elsewhere, so extracting or masking a field value requires bitwise negation (`~ROGUE_CR_*_CLRMSK`), and `rogue_slc_init()` must update `ROGUE_CR_SLC_CTRL_MISC` with 32-bit `pvr_cr_read32()`/`pvr_cr_write32()` while preserving `ROGUE_CR_SLC_CTRL_MISC_ENABLE_PSG_HAZARD_CHECK_EN` so the upper 32 scramble bits keep their hardware default. [F57, F73]
- `fill_cmd_kick_data()` in `pvr_cccb.c` appends to `k->cleanup_ctl_fw_addr[k->num_cleanup_ctl++]` without initializing `k->num_cleanup_ctl`, so callers (`pvr_cccb_send_kccb_kick()` and `pvr_cccb_send_kccb_combined_kick()`) must zero-initialize `struct rogue_fwif_kccb_cmd` before calling it. [F54]
- In `pvr_fw_mips.h` and `pvr_mips_fw_process()`, `PVR_MIPS_PT_PAGE_COUNT` must use `DIV_ROUND_UP(ROGUE_MIPSFW_MAX_NUM_PAGETABLE_PAGES * ROGUE_MIPSFW_PAGE_SIZE_4K, PAGE_SIZE)` rather than `>> PAGE_SHIFT`, and `boot_data->pt_phys_addr[page_nr]` must translate each 4 KB firmware page (`page_nr * ROGUE_MIPSFW_PAGE_SIZE_4K`) into a host page index (`>> PAGE_SHIFT`) and sub-page offset (`& ~PAGE_MASK`) on `mips_data->pt_dma_addr`. [F93, F123]
- In `pvr_meta_fw_process()`, `ROGUE_FW_BOOTLDR_CONF_OFFSET` (`0x80`) is in 32-bit dwords, so `fw_code_ptr` (`u8 *`) must be cast to `u32 *` before adding `ROGUE_FW_BOOTLDR_CONF_OFFSET`; in `process_ldr_command_stream()`, skipping an L1 block (`ROGUE_META_LDR_BLK_IS_COMMENT(l1_data->cmd)`) must `goto next_block` rather than `continue` so `l1_data` advances to `fw + l1_data->next`. [F112, F136]
- In `get_cr_isp_mtile_size_val()` and `get_cr_te_aa_val()`, the `samples >= 2`, `samples >= 4`, and `samples >= 8` checks within each `samples_per_pixel` branch must remain sequential independent `if` statements rather than `else if` chains because higher sample counts accumulate bits and shifts across thresholds; in `fw_trace_seq_show()`, the 48-bit timestamp places `read_fw_trace(trace_seq_data, 1) << 32` above `read_fw_trace(trace_seq_data, 2)`. [F77, F100]
