# MARVELL PRESTERA ETHERNET SWITCH DRIVER

This unit implements the core Linux Ethernet switch driver for Marvell Prestera DX / AC3X / AC5X ASICs over PCI, managing firmware loading, command/event mailbox IPC, SDMA packet RX/TX with Marvell DSA tagging, and port netdevices. It integrates with devlink, phylink/ethtool, TC flower/matchall ACL and SPAN mirroring offloads, hardware counter polling, and L3 router/FIB/neighbour hardware offloading.

## Architecture & Data Flow
- `prestera_fix_tb_id()` maps `RT_TABLE_LOCAL` and `RT_TABLE_MAIN` to one hardware table: `prestera_kern_fib_cache_key.kern_tb_id` must store the unmapped kernel table ID to resolve overlap, while `prestera_fib_node_find()`, `prestera_fib_node_create()`, and `prestera_rif_entry_create()` require `prestera_fix_tb_id()`. In `prestera_k_arb_fib_evt()`, an overlapped `bfib_cache` must be demoted (`reachable = false`) before applying a new `RT_TABLE_LOCAL` entry and re-promoted when `RT_TABLE_LOCAL` is deleted. [F68, F169]
- In `struct prestera_fib_info`, `nh_grp` is only populated when `type == PRESTERA_FIB_TYPE_UC_NH` (`NULL` for `TRAP`/`DROP`), so `__prestera_fib_node_destruct()`, `prestera_fib_node_create()`, and `prestera_fib_node_util_is_neighbour()` must check `type == PRESTERA_FIB_TYPE_UC_NH` before accessing `nh_grp`. Direct `/32` unicast FIB routes are programmed as `PRESTERA_FIB_TYPE_UC_NH` in `__prestera_pr_k_arb_fc_lpm_info_calc()`, and `__prestera_k_arb_n_lpm_set()` must not delete that `/32` `prestera_fib_node` while its `prestera_kern_fib_cache` is reachable. [F47, F170]
- `router->nhgrp_hw_state_cache` is a `u8` buffer of `sw->size_tbl_router_nexthop / 8 + 1` bytes indexed by `gid / 8` and `BIT(gid % 8)` (never `unsigned long *` bitops). `__prestera_nexthop_group_create()` must clear the new `grp_id` bit, `prestera_hw_nhgrp_blk_get()` must pass `req.offset` in bits (`buf_offset * 8`) and clamp `memcpy()` to `buf_size - buf_offset`, and `nhgrp_hw_cache_kick` expiration in `prestera_nexthop_group_util_hw_state()` must use `time_before`/`time_after`. [F70, F93, F113, F125]
- `block->ruleset_zero` and per-port vTCAM bindings in `block->binding_list` must stay synchronized: chain 0 binds/unbinds all bound ports when `ruleset->rule_count` transitions between 0 and 1, `prestera_flow_block_bind()`/`unbind()` must bind/unbind `block->ruleset_zero` when `prestera_flow_block_is_bound(block)` is true, and `block->ruleset_zero` must be cleared to `NULL` on rollback or when `rule_count` reaches 0. [F63]
- `prestera_flower_prio_check()` and `prestera_mall_prio_check()` enforce opposite priority orderings: on ingress (`block->ingress`), flower rule priorities must be strictly greater than `mall.prio_max`; on egress (`!block->ingress`), flower rule priorities must be strictly less than `mall.prio_min`. When a matchall rule is removed in `prestera_mall_destroy()`, `block->mall.prio_min` must be reset to `UINT_MAX`, `prio_max` to `0`, and `bound` to `false`. [F59, F102]
- In `prestera_acl_rule_del()`, `list_del(&rule->list)` must execute before `prestera_acl_ruleset_prio_refresh(sw->acl, ruleset)` because `prestera_acl_ruleset_prio_refresh()` scans `acl->rules` to recompute `ruleset->prio.min` and `ruleset->prio.max`. Per-chain template teardown in `prestera_flower_tmplt_destroy()` must filter by `template->chain_index == f->common.chain_index`, whereas `prestera_flower_template_cleanup()` frees all templates on the block. [F61, F62]
- Because `prestera_hw_counters_get()` adds deltas into `block->stats[i]` using `+=`, both `prestera_counter_stats_get()` and `prestera_counter_put()` must zero `block->stats[counter_id - block->offset]` via `prestera_counter_stats_clear()` under `prestera_counter_block_lock(block)`. In `prestera_counter_stats_work()`, if `counter->is_fetching` is true when `block` is missing or `prestera_hw_counters_get()` fails, or if `prestera_hw_counter_trigger()` fails, control must jump to `abort` to call `prestera_hw_counter_abort(counter->sw)`. [F65, F104]
- In `prestera_sdma_rx_poll()`, once `PRESTERA_SDMA_RX_DESC_IS_RCVD(desc)` is true, `buf->skb` must be trimmed to `PRESTERA_SDMA_RX_DESC_PKT_LEN(desc)` before `prestera_sdma_rx_skb_get()`, `prestera_sdma_rx_skb_get()` must sample `buf->buf_dma`, `buf->skb`, and `skb->len` before `prestera_sdma_rx_skb_alloc()` and always call `prestera_sdma_rx_desc_init()` afterward, and every path in that iteration must reach `rx_next_buf` to advance `ring->next_rx` via `% PRESTERA_SDMA_RX_DESC_PER_Q` (1000, not bitwise AND). [F74, F89, F99]
- Firmware IPC message structs (`struct prestera_msg_*`) in `prestera_hw.c` must avoid C bitfields, include explicit trailing `u8` padding arrays after 8/16-bit fields to match `prestera_hw_build_tests()`, and mark 12-byte union members containing `__le64` (`prestera_msg_event_port_param.phy`, `prestera_msg_policer_req.sr_tcm`) as `__packed`. [F79, F80]

## Synchronization
- `__prestera_cmd_ret()` and all `prestera_hw_*` firmware command wrappers lock `fw->cmd_queue[qid].cmd_mtx` and sleep in `prestera_fw_wait_reg32()`, so they must only be called from sleepable process context—never from hardirq, NAPI softirq, `.ndo_start_xmit`, `.ndo_get_stats64`, or under a spinlock, rwlock, or RCU read lock. [F145]
- Asynchronous router work callbacks (`__prestera_router_fib_event_work`, `prestera_router_neigh_event_work`, `prestera_router_update_neighs_work`) and all callers of `prestera_hw_nhgrp_blk_get()` / `prestera_nexthop_group_util_hw_state()` (which uses a function-local `static struct prestera_msg_nh_chunk_resp resp` after `cmd_mtx` is released) must hold `rtnl_lock()`. [F71, F141]
- When walking `sw->router->kern_neigh_cache_ht` in `prestera_k_arb_hw_evt()` and `__prestera_k_arb_fib_evt2nc()`, continue on `IS_ERR(n_cache)` and bracket per-entry work with `rhashtable_walk_stop(&iter)` and `rhashtable_walk_start(&iter)` before sleeping on firmware IPC or `GFP_KERNEL` allocations. `__prestera_k_arb_nc_kern_n_fetch()` must hold `read_lock_bh(&n->lock)` while reading `n->nud_state`, `n->dead`, and `n->ha`, unlocking before `neigh_release(n)` or sleeping. [F98, F143]
- In `prestera_sdma_xmit()` and `prestera_sdma_rx_desc_init()`, `wmb()` must execute after writing `desc->buff` and `desc->word2` before setting the DMA ownership bit in `desc->word1`. `prestera_sdma_xmit()` must hold `spin_lock(&sdma->tx_lock)`, call `dma_sync_single_for_device()`, call `prestera_sdma_tx_desc_xmit(buf->desc)` before setting `buf->is_used = true`, and busy-wait via `udelay(1)` in `prestera_sdma_tx_wait()`; `prestera_sdma_tx_recycle_work_fn()` must unmap and free `buf->skb` followed by `wmb()` before clearing `buf->is_used = false`. [F32, F136, F151]
- In `prestera_port_create()`, `port->id`, `port->dev_id`, `port->hw_id`, `port->dev`, `port->dl_port`, `port->state_mac_lock`, and `port->cached_hw_stats.caching_dw` must be initialized before `prestera_port_list_add(port)`. `prestera_port_list_add()`/`del()` must hold `write_lock(&sw->port_list_lock)`, `prestera_port_find_by_hwid()` and `prestera_find_port()` must hold `read_lock(&sw->port_list_lock)`, and `port->state_mac` accesses must use `port->state_mac_lock` via `prestera_port_mac_state_cache_read()`/`write()`. [F27, F28, F29]

## Object Lifetimes
- In `prestera_port_create()`, `prestera_devlink_port_register()` and `SET_NETDEV_DEVLINK_PORT()` must precede `register_netdev(dev)`, and any post-`register_netdev()` failure (such as `prestera_port_sfp_bind()`) must call `unregister_netdev()` before `prestera_port_list_del()`, `prestera_devlink_port_unregister()`, and `free_netdev()`. In `prestera_port_destroy()`, `cancel_delayed_work_sync(&port->cached_hw_stats.caching_dw)`, `unregister_netdev(dev)`, `prestera_port_list_del(port)`, and `prestera_devlink_port_unregister(port)` must complete in order before `free_netdev(dev)`. [F1, F30, F162]
- In `prestera_router_fini()`, all four router notifiers (`fib_nb`, `netevent_nb`, `inetaddr_nb`, `inetaddr_valid_nb`) must be unregistered before `prestera_neigh_work_fini()` and `prestera_queue_drain()` drain workqueues without holding `rtnl_lock()`, and both must finish before `prestera_k_arb_abort()`. In `prestera_k_arb_abort()`, `kern_fib_cache_ht` must be destroyed with `__prestera_k_arb_abort_fib_ht_cb` before `kern_neigh_cache_ht` with `__prestera_k_arb_abort_neigh_ht_cb`, and neither callback may touch hardware LPM entries. [F20, F39]
- Because `prestera_nh_neigh_put()` destroys `struct prestera_nh_neigh` if and only if `list_empty(&neigh->nexthop_group_list)` is true, `__prestera_nexthop_group_create()` rollback and `__prestera_nexthop_group_destroy()` must `list_del(&nh_grp->nh_neigh_head[nh_cnt].head)` before calling `prestera_nh_neigh_put()`. [F18]
- Because `prestera_acl_rule_create()` increments `ruleset->refcount` on top of the reference returned by `prestera_acl_ruleset_get()`, `prestera_flower_replace()` must call `prestera_acl_ruleset_put(ruleset)` on both success and error paths. In `prestera_acl_vtcam_id_put()`, if `refcount_dec_and_test(&vtcam->refcount)` reaches zero and `prestera_hw_vtcam_destroy()` fails with an error other than `-ENODEV`, `vtcam->refcount` must be restored to 1 via `refcount_set(&vtcam->refcount, 1)` without unlinking or freeing `vtcam`. [F13, F14]
- In `prestera_span_rule_del()`, `binding->span_id == PRESTERA_SPAN_INVALID_ID` must be checked first (returning `-ENOENT`), and after `prestera_hw_span_unbind()` and `prestera_span_put()` succeed, `binding->span_id` must be reset to `PRESTERA_SPAN_INVALID_ID`. [F16, F44]

## API Contracts
- Across notifier, TC offload, and routing paths, `netdev_priv(dev)` must only be cast to `struct prestera_port *` after `prestera_netdev_check(dev)` verifies `dev->netdev_ops == &prestera_netdev_ops`. In `prestera_netdev_port_event()`, `ptr` may only be cast to `struct netdev_notifier_changeupper_info` on `NETDEV_PRECHANGEUPPER`/`NETDEV_CHANGEUPPER` and to `struct netdev_notifier_changelowerstate_info` on `NETDEV_CHANGELOWERSTATE`. In `__prestera_router_fib_event()`, `struct fib_notifier_info *info` may only be downcast to `struct fib_entry_notifier_info` after verifying `info->family == AF_INET` and `FIB_EVENT_ENTRY_REPLACE`/`DEL`. [F116, F117, F119]
- Stack-allocated rhashtable keys (`prestera_acl_ruleset_ht_key`, `prestera_kern_fib_cache_key`, `prestera_kern_neigh_cache_key`, `prestera_nh_neigh_key`, `prestera_nexthop_group_key`, `prestera_fib_key`) and `struct prestera_acl_rule` passed to `prestera_flower_parse()`/`prestera_flower_parse_actions()` must be zero-initialized (`memset`/`kzalloc`). `prestera_rif_entry_create()` must normalize `e->key` with `__prestera_rif_entry_key_copy()`, and callers of `prestera_rif_entry_find()` must zero-initialize `k` before `memcmp()`. [F50, F51, F52]
- `prestera_hw_port_info_get()` and `prestera_find_port()` take the software index `port->id`, whereas all other port firmware commands in `prestera_hw.c`, `prestera_dsa_build()`, and `prestera_port_find_by_hwid()` require `(port->dev_id, port->hw_id)`. In `struct prestera_counter_block`, indexing `block->stats` or `block->counter_flag` must subtract `block->offset` (`counter_id - block->offset`), whereas `idr_remove()` and `prestera_hw_counter_clear()` take raw `counter_id`. [F53, F54]
- Before moving Ethernet MAC headers (`2 * ETH_ALEN` bytes, not `ETH_HLEN`) for the 16-byte DSA tag (`PRESTERA_DSA_HLEN`), `prestera_rxtx_xmit()` must call `skb_cow_head(skb, PRESTERA_DSA_HLEN)`, and `prestera_rxtx_process_skb()` must check `pskb_may_pull(skb, PRESTERA_DSA_HLEN)`, pass `skb->data - ETH_TLEN` to `prestera_dsa_parse()` after `skb_pull(skb, ETH_HLEN)`, and pull with `skb_pull_rcsum()`. [F75, F122]
- When inspecting IPv4 nexthops on a `struct fib_info` in `prestera_router.c`, helpers must call `fib_info_nhc()` rather than `fib_info_nh()` to support nexthop ID (`nhid`) routes. [F155]

## Error Handling
- In `prestera_acl.c`, `prestera_acl_ruleset_lookup()`, `prestera_acl_ruleset_get()`, and `prestera_acl_rule_create()` return `ERR_PTR`, whereas `prestera_acl_rule_lookup()`, `prestera_acl_rule_entry_find()`, and `prestera_acl_rule_entry_create()` return `NULL`. In `prestera_router_hw.c`, `prestera_vr_get()` and `prestera_nexthop_group_get()` return `ERR_PTR`, whereas `prestera_rif_entry_create()`, `prestera_nh_neigh_get()`, `__prestera_nexthop_group_create()`, `prestera_fib_node_create()`, and all `*_find()` helpers return `NULL`. [F42, F43]
- In `prestera_fw_cmd_send()`, once `PRESTERA_CMD_F_REQ_SENT` has been written to `PRESTERA_CMDQ_REQ_CTL_REG(qid)`, every subsequent exit path (including timeout and `ret_size > out_size` returning `-EMSGSIZE`) must jump to `cmd_exit` to write `PRESTERA_CMD_F_REPL_RCVD` before `cmd_mtx` is unlocked. [F6]
- In `prestera_acl_ruleset_block_bind()` and `prestera_mall_replace()`, partial port-bind failures must unwind using `list_for_each_entry_continue_reverse()` to unbind only previously bound ports (and `prestera_acl_ruleset_block_bind()` must reset `block->ruleset_zero = NULL`); if `prestera_span_rule_add()` in `prestera_mall_replace()` returns `-EEXIST`, it must return `-EEXIST` immediately without jumping to `rollback`. [F15, F58]
- In `prestera_flower_parse_goto_action()`, `rule->jump_ruleset` must only be assigned after verifying `!IS_ERR(ruleset)` from `prestera_acl_ruleset_get()`. In `__prestera_acl_rule_entry_act_construct()`, `e->police.valid` must only be set after both `prestera_hw_policer_create()` and `prestera_hw_policer_sr_tcm_set()` succeed. [F48, F49]

## External Contracts
- All DMA addresses programmed into SDMA descriptors (`desc->buff`, `desc->next`) or queue registers must be within `DMA_BIT_MASK(30)` and translated via `prestera_sdma_map(sdma, pa)` (`sdma->map_addr + pa`); RX SKBs in `prestera_sdma_rx_skb_alloc()` must use `GFP_DMA | GFP_ATOMIC` and descriptors in `prestera_sdma_buf_init()` must use `GFP_DMA | GFP_KERNEL`. [F135, F149]
- Unlike other firmware IPC fields which are little-endian, IP addresses in `struct prestera_msg_ip_addr` (`u.ipv4`, `u.ipv6`) in `prestera_hw_lpm_add()` and `prestera_hw_lpm_del()` must remain in network (`__be32`) byte order. In `prestera_dsa_parse()` and `prestera_dsa_build()`, the four big-endian 32-bit DSA words encode `port_num` across `W0[23:19]`, `W1[11:10]`, and `W2[20]` for `TO_CPU` (RX) frames, but in `W3[23:7]` (`PRESTERA_DSA_W3_DST_EPORT`) for `FROM_CPU` (TX) frames. [F81, F87]

## Known Pitfalls
- In `prestera_hw_vtcam_rule_add()` and `prestera_hw_flood_domain_ports_set()`, the `__counted_by_le` count field (`req->n_act` or `req->ports_num`) must be assigned via `__cpu_to_le32()` before indexing `req->actions_msg[]` or `req->ports[]`. [F82]
- When populating `struct prestera_acl_match` (`__be32` arrays) via `rule_match_set()` or `rule_match_set_n()`, multi-byte values must be converted to big-endian (`__be16` or `__be32`) of their exact field width before `memcpy()`. In `prestera_router.c`, `fib_entry_notifier_info::dst` is host-endian `u32` (format with `%pI4h`, convert via `cpu_to_be32()` for `prestera_ip_addr`), whereas `prestera_ip_addr::u.ipv4` is `__be32` (format with `%pI4n`). [F90, F124]
- List lookup functions (`prestera_port_find_by_hwid()`, `prestera_find_port()`) must iterate `list_for_each_entry` with a separate cursor variable (`tmp`) and only assign the return pointer (`port`) upon a match. [F96]
