# GPIO SUBSYSTEM

The Linux GPIO subsystem (`gpiolib.c`, `gpiolib-*.c`, `include/linux/gpio/*.h`) manages the lifecycle of `struct gpio_device` and `struct gpio_desc`, mediates between consumers and `struct gpio_chip` providers using SRCU so hot-unplugged controllers fail safely, and integrates `gpio_irq_chip` domains, `pinctrl` ranges, Device Tree, software nodes, devres, and sysfs. It also includes the generic MMIO library (`gpio-mmio.c`), test drivers (`gpio-sim.c`, `gpio-virtuser.c`), and controller drivers for SoC MMIO blocks, I2C/SPI/PMIC expanders, Super I/O, and USB bridges.

## Architecture & Data Flow
- `gpio_chip_hwgpio()` and `desc_to_gpio()` compute a descriptor's hardware offset via `desc - &desc->gdev->descs[0]`; every `struct gpio_desc *` passed to gpiolib must reside inside its parent `gdev->descs` contiguous array, never standalone or copied. [F441]
- `gpiod_get_array()` must place `struct gpio_array` (`array_info`) in the same `krealloc()` block right after `descs->desc[count]`, set `array_info->desc = descs->desc` after reallocation, and size `invert_mask`/`get_mask`/`set_mask` to `BITS_TO_LONGS(max(gdev->ngpio, count))`. [F435, F438]
- In `gpio_chip_get_multiple()` and `gpiochip_set_multiple()`, when `gc->get_multiple` or `gc->set_multiple` is non-NULL, the function must return its status directly (mapping `> 0` to `-EBADE`) without falling through to the `for_each_set_bit()` loop. [F417]
- In `gpiod_direction_output_nonotify()`, when open-drain/open-source emulation branches to `set_output_flag` and calls `gpiod_direction_input_nonotify(desc)` (clearing `GPIOD_FLAG_IS_OUT`), it must set `GPIOD_FLAG_IS_OUT` afterward so `gpiod_set_raw_value_commit()` does not fail with `-EPERM`. [F423]
- In `gpiod_configure_flags()`, the early return on `!(dflags & GPIOD_FLAGS_BIT_DIR_SET)` must precede `if (dflags & GPIOD_FLAGS_BIT_DIR_OUT)` so `GPIOD_ASIS` (`0`) leaves hardware direction unchanged instead of calling `gpiod_direction_input_nonotify()`. [F422]
- `gpiochip_allocate_mask()` initializes valid masks with `bitmap_fill(p, gc->ngpio)` so all lines start valid before `gpiochip_apply_reserved_ranges()` or `init_valid_mask` clears unavailable lines; in `gpiochip_apply_reserved_ranges()`, both `ranges[--size]` decrements must precede the bounds-check `continue`. [F386, F430]
- When `gc->irq.chip->flags & IRQCHIP_IMMUTABLE` is set, `gpiochip_set_irq_hooks()` and `gpiochip_irqchip_remove()` do not mutate `gc->irq.chip`; an immutable `irq_chip` must include `GPIOCHIP_IRQ_RESOURCE_HELPERS` and call `gpiochip_enable_irq()` / `gpiochip_disable_irq()` in its callbacks. [F455]
- `gpiochip_set_names()` must return early when `"gpio-line-names"` count is `<= chip->offset`, and otherwise clamp `count - chip->offset` to `chip->ngpio` before indexing `names[chip->offset + i]`. [F407]
- In `drivers/gpio/gpio-mmio.c`, `bgpio_line2mask()`, `chip->sdata`, and `chip->sdir` must use `unsigned long` and `BIT()` (supporting 64-bit chips), `chip->sdir` (`1` = out, `0` = in) must be written as `chip->sdir` to `reg_dir_out` and `~chip->sdir` to `reg_dir_in`, and `bgpio_setup_io()` must always populate `gc->set` (using `bgpio_set_none` for `GPIO_GENERIC_NO_OUTPUT`) since `bgpio_*_dir_out*()` and `gpio_generic_chip_set()` call `gc->set()` directly. [F49, F51, F100]
- In `drivers/gpio/gpio-pca953x.c`, `NBANK(chip)` must use `DIV_ROUND_UP(ngpio, BANK_SZ)` (`ngpio <= MAX_LINE`, 40), `pca953x_bank_shift()` must compute `fls((ngpio - 1) / BANK_SZ)` after `ngpio` is set, and `pca953x_irq_pending()` must detect edges by comparing `regs->input & reg_direction` against `chip->irq_stat` under `chip->i2c_lock`. [F103, F104, F109, F124]
- In `drivers/gpio/gpio-sim.c`, `gpio_sim_free()` must restore `chip->value_map` from `chip->pull_map` when clearing `chip->request_map`; `gpio_sim_apply_pull()` must only update `value_map` when the line is unrequested or input; bitmaps must be allocated via `devm_bitmap_alloc`/`zalloc(num_lines)` for `bitmap_replace()`; and line-name/hog helpers must skip `line->offset >= bank->num_lines`. [F234, F254, F270, F298]

## Synchronization
- Runtime accesses to `gdev->chip` and internal `gpiochip_*` wrappers (`gpiochip_get_direction`, `gpiochip_direction_input`, `gpiochip_direction_output`, `gpiochip_get`, `gpio_chip_get_multiple`, `gpiochip_set`, `gpiochip_set_multiple`) must hold `gdev->srcu` (via `gpio_chip_guard`) and check `gc != NULL`; before chip registration in `gpiochip_add_data_with_key()`, call `gc->get_direction()` directly; and when comparing another descriptor's `gdev->chip` against `guard.gc`, use `gpio_device_chip_cmp(gdev, gc)`. [F359, F362, F369]
- `gpiod_find_and_request()` must hold `gpio_devices_srcu` continuously across lookup (`gpiod_fwnode_lookup()` / `gpiod_find()`) and `gpiod_request()`. Modifications to `gpio_devices` must hold `gpio_devices_lock` using RCU list primitives, and removing a `gpio_device` must be followed by `synchronize_srcu(&gpio_devices_srcu)` after dropping `gpio_devices_lock` before freeing or numbing `gdev`. [F367, F476]
- `desc_set_label()` must replace `desc->label` with `rcu_replace_pointer()` and free the old label via `call_srcu(&desc->gdev->desc_srcu, &old->rh, desc_free_label)` (with `synchronize_srcu(&gdev->desc_srcu)` in `gpiodev_release()` before `cleanup_srcu_struct()`). Callers of `gpiod_get_label(desc)` must hold `desc->gdev->desc_srcu` for the entire duration the returned pointer is used and check it for `NULL`. [F382, F469, F470]
- `gpiod_line_state_notify()` must hold `read_lock_irqsave(&desc->gdev->line_state_lock)` around `raw_notifier_call_chain(&desc->gdev->line_state_notifier, ...)`, and `gpiochip_irqchip_add_allocated_domain()` must execute `barrier()` after assigning `gc->irq.domain` before setting `gc->irq.initialized = true`. [F360, F366]
- In `drivers/gpio/gpio-mmio.c`, `chip->lock` (`raw_spin_lock_irqsave`) must protect every `chip->sdata` or `chip->sdir` update together with its `chip->write_reg()` call; in `gpio-sifive.c` (`.disable_locking = true`), post-probe `chip->regs` accesses must hold `chip->gen_gc.lock`, which `sifive_gpio_irq_enable()` must drop before calling `gc->direction_input()` or `sifive_gpio_set_ie()`. [F16, F159]
- In `drivers/gpio/gpio-pca953x.c` (`.disable_locking = true`), `chip->irq_lock` nests outside `chip->i2c_lock` (`lockdep_set_subclass(&chip->i2c_lock, i2c_adapter_depth(client->adapter))`); post-probe regmap accesses and `disable_irq`/`enable_irq` + `regcache_cache_only` toggles in `pca953x_save_context()`/`restore_context()` must hold `chip->i2c_lock`; `pca953x_irq_handler()` must drop `chip->i2c_lock` before `handle_nested_irq()`; and `pca953x_irq_mask`/`unmask`/`set_type`/`shutdown` must only update bitmaps and defer I2C I/O to `pca953x_irq_bus_sync_unlock()`. [F18, F21, F54, F149, F151]
- In `gpio-pcf857x.c`, `gpio-stmpe.c`, `gpio-tc3589x.c`, and `gpio-pmic-eic-sprd.c`, atomic `irq_chip` callbacks must only update cached registers (`regs[][]` or `reg[]`) and defer bus I/O to `*_bus_sync_unlock()` under the IRQ bus lock, and `pcf857x_irq()` must drop `gpio->lock` before `handle_nested_irq()`. [F29, F161, F241]
- In `drivers/gpio/gpio-sim.c` and `gpio-virtuser.c`, `chip->lock` must protect all accesses to `request_map`, `direction_map`, `value_map`, and `pull_map`; `data->consumer_lock` must be initialized before debugfs creation and held across `data->consumer` accesses; and `IRQ_WORK_INIT_HARD` callbacks (`gpio_virtuser_*_atomic`) run in hardirq context and must not sleep, allocate with `GFP_KERNEL`, copy user memory, or call `_cansleep` helpers. [F200, F207, F323]

## Object Lifetimes
- `gpiod_request()` pins `desc->gdev->owner` and `desc->gdev` and must be paired with `gpiod_free()`/`gpiod_put()`, whereas `gpiochip_request_own_desc()` takes neither reference and must be paired with `gpiochip_free_own_desc()`. Similarly, `gpiochip_reqres_irq()` must call `try_module_get(gc->gpiodev->owner)` before `gpiochip_lock_as_irq()` (rolling back with `module_put()` on failure) to match `gpiochip_relres_irq()`. [F344, F358]
- `gpio_device_find*()` functions return a refcounted `struct gpio_device *` that callers must release with `gpio_device_put()`, whereas `gpio_device_get_desc()` and `gpiod_to_gpio_device()` do not increment the refcount. [F453]
- `devm_gpiod_put*()` must call `devm_release_action()` (not `devm_remove_action()`), whereas `devm_gpiod_unhinge()` must call `devm_remove_action_nowarn()` (ignoring `-ENOENT`). When `GPIOD_FLAGS_BIT_NONEXCLUSIVE` is set, `devm_gpiod_get_index()` must check `devm_is_action_added(dev, devm_gpiod_release, desc)` before registering devres. [F349, F451]
- `gdev->label` is allocated with `kstrdup_const()` and must be freed with `kfree_const()` (never `kfree()`). `gpiochip_set_names()` and `gpiodev_release()` must never free individual `desc->name` string pointers (owned by firmware or `gc->names`). `gpiochip_free_mask()` must set `*p = NULL` after `bitmap_free(*p)` to prevent double-free on `gpiochip_add_data_with_key()` rollback. [F348, F356, F445]
- Firmware node references from `of_parse_phandle_with_args_map()` in `of_get_named_gpiod_flags()` and `swnode_gpio_get_reference()` in `swnode_find_gpio()`/`swnode_gpio_count()` must be released with `of_node_put()` or `fwnode_handle_put()` on all return paths. [F353, F355]

## API Contracts
- `GPIOD_FLAG_*` constants (`drivers/gpio/gpiolib.h`) are bit numbers (`0`..`19`) used with `test_bit`/`set_bit`/`clear_bit`/`assign_bit` on `desc->flags`, whereas `enum gpiod_flags`, `enum gpio_lookup_flags`, and `enum of_gpio_flags` are pre-shifted bitmasks used with `|` and `&`. [F493]
- Non-optional acquisition helpers (`gpiod_get_index`, `gpiod_get_array`, `devm_gpiod_get_*`) return `ERR_PTR(-ENOENT)` when no GPIO is assigned, while `_optional` variants convert only `-ENOENT` (`gpiod_not_found()`) to `NULL` and propagate other `ERR_PTR`s; `gpio_to_desc()` takes a global GPIO number and returns `NULL` on failure, whereas `gpiochip_get_desc()` and `gpio_device_get_desc()` take a chip-relative offset, clamp with `array_index_nospec()`, and return `ERR_PTR(-EINVAL)` when `hwnum >= gdev->ngpio`. [F374, F375, F486]
- `gpiod_direction_output()`, `gpiod_get_value*()`, and `gpiod_set_value*()` operate on logical values (applying `GPIOD_FLAG_ACTIVE_LOW` and open-drain/open-source emulation), whereas `*_raw*()` variants operate on physical levels; non-`_cansleep` value accessors must not be called when `gdev->can_sleep` or `gc->can_sleep` is true. [F388, F472]
- `struct gpio_chip` callbacks `.request`, `.direction_input` (requires `.get`), `.direction_output` (at least one of `.direction_output` or `.set` required for output), `.set`, `.set_multiple`, `.get_multiple`, and `.set_config` must return `0` or negative errno, while `.get` and `.get_direction` must return `0`, `1`, or negative errno (`> 1` becomes `-EBADE`). In `.get_multiple`, `*bits` must be masked with `~*mask` before ORing in read values. [F50, F379, F490]
- `gpiod_set_config()` and `gpio_do_set_config()` require `pinconf_to_config_packed(param, arg)` (whereas `gpiod_set_debounce()` takes unpacked microseconds). Implementations of `gc->set_config` must return `-ENOTSUPP` (not `-EINVAL` or `-EOPNOTSUPP`) for unsupported parameters and convert `PIN_CONFIG_INPUT_DEBOUNCE` arguments from microseconds. [F171, F172, F389]
- For `gpiolib`-managed IRQ domains, `irq_data_get_irq_chip_data()` is `struct gpio_chip *gc`, and chained `irq_desc_get_handler_data()` is `gc` unless `girq->parent_handler_data` or `parent_handler_data_array` (when `per_parent_data` is true) is set. A chip with `gc->can_sleep` cannot set `gc->irq.parent_handler` (`-EINVAL`); shared parent IRQs (`IRQF_SHARED`) must leave `parent_handler = NULL`/`num_parents = 0` and use `devm_request_irq()`; non-nested `handle_edge_irq` chips must define `.irq_ack`; and hierarchical domains require `child_to_parent_hwirq` and `fwnode`. [F177, F178, F384, F444, F474, F491, F492]
- In `drivers/gpio/gpio-mmio.c` (`struct gpio_generic_chip`), callbacks must recover the chip via `to_gpio_generic_chip(gc)` (never `gpiochip_get_data(gc)`), drivers must use `gpio_generic_read_reg()`/`gpio_generic_write_reg()` rather than `gc->read_reg`/`write_reg`, and `cfg->sz` must be a power-of-2 byte width (`cfg->sz * 8 <= BITS_PER_LONG`, `gc.ngpio <= chip->bits`). [F114, F115, F173, F245]

## Error Handling
- Public `gpiod_*` entry points must validate `desc` with `VALIDATE_DESC()` / `VALIDATE_DESC_VOID()` before calling internal `*_nonotify()`, `*_commit()`, `gpiod_line_state_notify()`, or `gpio_chip_guard` helpers, except `gpiod_get_direction()` and `gpiod_to_irq()`, which must check `validate_desc(desc, __func__) <= 0` and return `-EINVAL` because `0` is a valid return value. [F376, F377]
- In `gpiod_direction_input_nonotify()` and `gpiod_direction_output_raw_commit()`, the return value of `gpiochip_get_direction()` (`1` for input) must not remain in `ret` on success, because callers pass non-zero `ret` to `ERR_PTR(ret)`. [F378]
- Functions callable before `gpiochip_add_data_with_key()` sets `gc->gpiodev` (`gpiochip_line_is_valid()`, `gpiochip_get_ngpios()`) must not dereference `gc->gpiodev` unconditionally or call `chip_err()`/`chip_warn()`. In `gpiod_get_array()`, `descs->ndescs` must only be incremented after `gpiod_get_index()` succeeds, and in `gpiod_get/set_array_value_complex()`, `mask` must be zeroed with `bitmap_zero(mask, guard.gc->ngpio)` (using `can_sleep ? GFP_KERNEL : GFP_ATOMIC` if heap-allocated). [F381, F385, F387, F473]

## External Contracts
- In `drivers/gpio/gpiolib-sysfs.c`, `/sys/class/gpio/export` and `unexport` resolve global GPIO numbers via `gpio_to_desc()`, whereas per-chip `chipN/export` and `unexport` (`do_chip_export_store()`) resolve 0-based hardware offsets via `gpio_device_get_desc()`. `unexport_gpio_desc()` and `gpiochip_sysfs_unregister()` must check `GPIOD_FLAG_SYSFS` (not just `GPIOD_FLAG_EXPORT`) before unexporting and freeing, and `gpiod_request_user()` must translate `-EPROBE_DEFER` to `-ENODEV`. [F413, F487, F488]

## Known Pitfalls
- In `gpiod_set_array_value_complex()`, the slowpath loop must skip active-low inversion when `array_info && test_bit(i, array_info->invert_mask)` because the fastpath `bitmap_xor()` already inverted `value_bitmap` in place for all `invert_mask` pins (including open-drain/open-source pins); callers must pass a writable `value_bitmap`. [F418, F440]
- In `gpiodev_add_to_list_unlocked()`, `list_for_each_entry_safe(prev, next, &gpio_devices, list)` must check `if (&next->list == &gpio_devices) break;` before reading `next->base`; in `gpiochip_get_ngpios()`, `if (gc->ngpio == 0)` must test the `u16` field `gc->ngpio` after assignment because a `u32` multiple of 65536 truncates to `0`. [F424, F434]
- `for_each_gpio_property_name(propname, con_id)` uses `sizeof(propname)`, so `propname` must be a fixed-size `char` array in scope (not `char *`). `for_each_hwgpio_in_range()` and its wrappers pass `&_label` and `&_i` to `_gpiochip_for_each_data` (`const char **label, int *i`) and call `kfree(_label)` on each step and scope exit, so `_i` must be `int`/`unsigned int` and `_label` must not be reassigned or manually freed. [F437, F446]
