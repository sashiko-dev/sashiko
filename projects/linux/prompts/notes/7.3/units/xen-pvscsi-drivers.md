# XEN PVSCSI DRIVERS

This unit implements the Xen paravirtualized SCSI (pvSCSI) frontend (`xen-scsifront`) and backend (`xen-scsiback`) drivers along with their shared ring protocol header (`vscsiif.h`). The frontend driver exposes a virtual `Scsi_Host` inside a Xen guest domain and forwards SCSI CDBs, task aborts, and device resets over a shared Xen ring buffer and grant table references. The backend driver runs in the host/backend domain, maps guest grant pages, translates virtual H:C:T:L addresses to Linux Target Core (TCM/LIO) LUNs, and submits commands and task management requests as a TCM fabric module (`xen-pvscsi`).

## Architecture & Data Flow

- `struct vscsifrnt_shadow` is embedded in `scsi_cmd_priv(sc)` for `VSCSIIF_ACT_SCSI_CDB` and heap-allocated via `kzalloc` in `scsifront_action_handler` for `VSCSIIF_ACT_SCSI_ABORT` and `VSCSIIF_ACT_SCSI_RESET`; only `scsifront_sync_cmd_done` and `scsifront_action_handler` may `kfree(shadow)`. Broken by: calling `kfree(shadow)` on a CDB shadow or passing `scsi_cmd_priv(sc)` to `scsifront_do_request` for abort/reset. [F31]
- In `struct vscsifrnt_info`, `shadow_free_bitmap` uses 1-bits for free IDs and 0-bits for allocated IDs in `[0, VSCSIIF_MAX_REQS)`. `scsifront_do_request` must check `id >= VSCSIIF_MAX_REQS` after `scsifront_get_rqid` and set `info->shadow[id] = shadow`, `shadow->rqid = id`, and `shadow->inflight = true`; `scsifront_do_response` must reject `ring_rsp->rqid >= VSCSIIF_MAX_REQS`; and `_scsifront_put_rqid` must both set bit `id` in `shadow_free_bitmap` and clear `info->shadow[id] = NULL`. [F43, F64]
- Because `nr_segments` in `struct vscsiif_request` and `struct vscsifrnt_shadow` stores the `VSCSIIF_SG_GRANT` flag (`0x80`) in bit 7, code indexing `seg[VSCSIIF_SG_TABLESIZE]` must mask it off (`nr_segments & ~VSCSIIF_SG_GRANT`), and `scsiback_gnttab_data_map` must verify the masked count is at most `VSCSIIF_SG_TABLESIZE`. [F58]
- In `scsiback_gnttab_data_map`, each indirect segment's `ring_req->seg[i].length` must be checked to be an exact multiple of `sizeof(struct scsiif_request_segment)` before advancing `seg` against `end_seg = base + ring_req->seg[i_seg].length`, and every direct or indirect data `scsiif_request_segment` populated into `pending_req->sgl` must satisfy `sg->offset < PAGE_SIZE`, `sg->length <= PAGE_SIZE`, and `sg->offset + sg->length <= PAGE_SIZE` (widening 16-bit `offset` and `length` to 32-bit `unsigned int` before adding) prior to `scsiback_cmd_exec`. [F60, F83, F86]
- `prepare_pending_reqs` must reject `ring_req->cmd_len > VSCSIIF_MAX_COMMAND_SIZE` before copying `ring_req->cmnd`, and `scsifront_cdb_cmd_done` and `scsiback_send_response` must clamp sense length to `VSCSIIF_SENSE_BUFFERSIZE` before copying `sense_buffer`. [F66]
- When recycling a `struct vscsibk_pend` slot from `se_sess->sess_cmd_map` in `scsiback_get_pend_req`, the entry must be zeroed with `memset`, `req->se_cmd.map_tag` and `req->se_cmd.map_cpu` restored to the allocated tag and CPU, and all `req->grant_handles[]` initialized to `SCSIBACK_INVALID_HANDLE` (`~0`). [F48]
- In `map_data_for_request`, per-scatterlist grant counting must use `PFN_UP(sg->offset + sg->length)` because the first page is capped at `PAGE_SIZE - sg->offset` bytes. `ref_cnt` is a single monotonic index into `shadow->gref[]` across both the indirect segment-page grant loop and the `scsi_for_each_sg` data grant loop (ending as `shadow->nr_grants`), whereas `seg` starts at `shadow->sg ? : shadow->seg` and advances only in the data grant loop. [F70, F84]
- In `scsifront_backend_changed`, the `XenbusStateConnected` branch must check `if (info->pause)` and return after running `VSCSIFRONT_OP_READD_LUN` before checking `XenbusStateInitialised`, because `scsifront_resume` transitions the frontend back to `XenbusStateInitialised` while existing SCSI devices remain attached. [F74]
- `scsifront_do_lun_hotplug` must set `info->curr = current` and populate `info->dev_state_path` before invoking `scsi_add_device` or `scsi_remove_device` and reset `info->curr = NULL` before returning, and `scsifront_sdev_configure` and `scsifront_sdev_destroy` must only write `info->dev_state_path` when `current == info->curr`. [F35]
- `scsiback_init_sring` must check `bind_interdomain_evtchn_to_irq_lateeoi` for `< 0` before assigning `info->irq = err`, and both the `free_irq` error path in `scsiback_init_sring` and `scsiback_disconnect` must reset `info->irq = 0` after calling `unbind_from_irqhandler(info->irq, info)`. [F36]
- In `scsifront_irq_fn` and `scsiback_irq_fn`, `eoiflag` / `eoi_flags` must be initialized to `XEN_EOI_FLAG_SPURIOUS` once before the outer `while` loop and only cleared via `&= ~XEN_EOI_FLAG_SPURIOUS` when a ring item is consumed, never reset on each call to `scsifront_ring_drain` or `scsiback_do_cmd_fn`. [F78]

## Synchronization

- `scsifront_ring_drain` and `scsiback_do_cmd_fn` increment 32-bit unsigned `RING_IDX` indices without modulo reduction and must compare them with `!=` and modular overflow macros (`RING_RESPONSE_PROD_OVERFLOW`, `RING_REQUEST_PROD_OVERFLOW`, `RING_REQUEST_CONS_OVERFLOW`), never `<` or `>`. `scsifront_ring_drain` must read `info->ring.sring->rsp_prod` with `READ_ONCE()` followed by `virt_rmb()` before checking overflow and copying via `RING_COPY_RESPONSE`; `scsiback_do_cmd_fn` must order `ring->sring->req_prod` with `rmb()` before checking overflow and copying via `RING_COPY_REQUEST`, while all response writes to `info->ring` in `scsiback_send_response` must be serialized by `info->ring_lock`. [F20, F21, F65, F87]
- Every successful `scsifront_enter(info)` call (returning 0 under `host->host_lock`) increments `info->callers` and must be paired with `scsifront_return(info)` under `host->host_lock`, including before sleeping on `info->wq_sync` in `scsifront_action_handler`. `scsifront_suspend` must set `info->pause = 1` under `host->host_lock` and wait on `info->wq_pause` (waking `info->wq_sync` each iteration) until `info->callers == 0`, and `info->pause` must remain set across `scsifront_resume` until `scsifront_backend_changed` processes `XenbusStateConnected`. [F4, F100]
- `scsiback_release_translation_entry` must splice `info->v2p_entry_lists` into a local list under `info->v2p_lock` and iterate it with `list_for_each_entry_safe` after dropping `info->v2p_lock`, because `kref_put` calls `scsiback_free_translation_entry` which acquires `tpg->tv_tpg_mutex` and `kfree`s each `v2p_entry`. [F80]
- `scsiback_device_action` must initialize `pending_req->tmr_done` via `init_completion` before calling `target_submit_tmr`, and on all synchronous completion or error paths `scsiback_do_resp_with_sense` must be called before `transport_generic_free_cmd(&pending_req->se_cmd, 0)`. [F23]
- `map_data_for_request` is called by `scsifront_queuecommand` while holding `shost->host_lock` with interrupts disabled (`spin_lock_irqsave`), so any dynamic allocation inside `map_data_for_request` (such as `shadow->sg`) must use `GFP_ATOMIC` and never sleep. [F106]
- `scsiback_irq_fn` must run as a threaded interrupt handler (`request_threaded_irq` with `handler = NULL` and `IRQF_ONESHOT`) because `scsiback_do_cmd_fn` performs `GFP_KERNEL` allocations, waits on `pending_req->tmr_done` in `scsiback_device_action`, and calls `cond_resched()`. [F113]

## Object Lifetimes

- `scsiback_cmd_exec` must call `scsiback_get(pending_req->info)` before `target_submit_prep` and return immediately without freeing resources if `target_submit_prep` returns non-zero (which already completes and frees `se_cmd` via `scsiback_queue_status` and `scsiback_check_stop_free`). On normal completion, `scsiback_cmd_done` must finish `scsiback_fast_flush_area` and `scsiback_do_resp_with_sense` before calling `scsiback_put(info)` and `target_put_sess_cmd(&pending_req->se_cmd)`. Because `scsiback_cmd_exec` and `scsiback_device_action` pass `TARGET_SCF_ACK_KREF`, both `scsiback_check_stop_free` and the completion path (`target_put_sess_cmd` or `transport_generic_free_cmd`) must drop a `cmd_kref` reference so `scsiback_release_cmd` frees the tag. [F22, F39, F124]
- In `scsiback_gnttab_data_map_list`, `gnttab_page_cache_get` failures must return unmapped `mapcount` pages via `gnttab_page_cache_put`, whereas once `scsiback_gnttab_data_map_batch` runs, it must process all `cnt` entries even when a mapping fails (storing `SCSIBACK_INVALID_HANDLE` on failure and calling `get_page` on success) and `scsiback_gnttab_data_map_list` must add `mapcount` to `pending_req->n_grants` before returning `err` so `scsiback_fast_flush_area` owns unmapping handles, putting page refs, returning cached pages, and freeing `req->sgl`. [F9, F75]
- `scsiback_disconnect` must wait on `info->waiting_to_free` until `atomic_read(&info->nr_unreplied_reqs) == 0` before unbinding `info->irq`, setting `info->irq = 0`, and unmapping `info->ring.sring`, and `scsiback_remove` must run `scsiback_disconnect` before `scsiback_release_translation_entry` and `gnttab_page_cache_shrink(&info->free_pages, 0)`. [F12]
- Both `scsifront_remove` and `scsifront_disconnect` must serialize `scsi_remove_host(info->host)` under `scsifront_mutex` by checking `info->host_active != STATE_INACTIVE` and setting `info->host_active = STATE_INACTIVE`, before `scsifront_remove` calls `scsifront_free_ring` and `scsi_host_put`. [F6]
- In `scsifront_sync_cmd_done`, the `RSLT_RESET_ERR` branch of `switch (shadow->rslt_reset)` must return immediately after freeing `shadow` rather than breaking out of the `switch`, because the post-`switch` path calls `wake_up(&shadow->wq_reset)`. [F72]
- `scsiback_make_tpg` must initialize `tpg->tv_tpg_mutex` and register `tpg->se_tpg` via `core_tpg_register` before adding `tpg->tv_tpg_list` to `scsiback_list` under `scsiback_mutex`, and `scsiback_drop_tpg` must remove `tpg->tv_tpg_list` under `scsiback_mutex` before calling `scsiback_drop_nexus` and `core_tpg_deregister`. `scsiback_drop_nexus` must hold `tpg->tv_tpg_mutex` and verify both `tpg->tv_tpg_port_count == 0` and `tpg->tv_tpg_fe_count == 0` (held across each `v2p_entry` `kref` lifetime until `scsiback_free_translation_entry`) before calling `target_remove_session` and freeing `tpg->tpg_nexus`. [F27, F104]

## API Contracts

- `scsiback_do_translation` acquires `info->v2p_lock` and calls `kref_get(&entry->kref)`, transferring a reference that must be released with `kref_put(&v2p->kref, scsiback_free_translation_entry)`, whereas `scsiback_chk_translation_entry` returns an unreferenced pointer under caller-held `info->v2p_lock`. [F7]
- `scsifront_eh_abort_handler` and `scsifront_dev_reset_handler` (via `scsifront_action_handler` and `scsifront_sync_cmd_done`) must initialize `shadow->rslt_reset` to `RSLT_RESET_WAITING` (`0`), forward the action to the backend, wait for the response, and return SCSI midlayer status codes `SUCCESS` or `FAILED` (never negative errnos); if `wait_event_interruptible` on `shadow->wq_reset` returns non-zero, `scsifront_action_handler` must set `shadow->rslt_reset = RSLT_RESET_ERR` under `info->shadow_lock` so `scsifront_sync_cmd_done` frees `shadow` and `rqid`. [F30, F118]
- In `scsifront_queuecommand`, transient failures (`-ENOMEM` from `map_data_for_request` or `-EBUSY` from `scsifront_do_request`) must return `SCSI_MLQUEUE_HOST_BUSY` without calling `scsi_done(sc)`, whereas non-`-ENOMEM` mapping errors (`-E2BIG`) must set `sc->result = DID_ERROR << 16`, call `scsi_done(sc)`, and return `0`. [F117]
- `scsiback_do_cmd_fn` returns `< 0` on ring overflow, `> 0` when more ring work may remain, and `0` when the ring is drained, so `scsiback_irq_fn` must loop while `rc > 0` (not `rc != 0`) and call `xen_irq_lateeoi` only when `!rc` to keep the event channel masked on ring errors. [F77]
- In `scsiback_add_translation_entry`, `strrchr(phy, ':')` locates the `:lun` suffix and overwrites the `':'` separator in `phy` with `'\0'` in-place, so callers (`scsiback_do_add_lun` and `scsiback_do_1lun_hotplug`) must pass a writable buffer containing `:lun` and cannot reuse `phy` across calls. [F94]

## Error Handling

- In `scsifront_queuecommand`, once `map_data_for_request` succeeds, a subsequent failure of `scsifront_do_request` must call `scsifront_gnttab_done(info, shadow)` before returning `SCSI_MLQUEUE_HOST_BUSY` to revoke granted pages and free any indirect `shadow->sg` allocation. [F3]
- In `scsifront_gnttab_done`, if `gnttab_try_end_foreign_access` returns `0` for any grant, it must call `scsifront_set_error` (setting `info->host_active = STATE_ERROR`) and return without `kfree(shadow->sg)`, and `scsifront_cdb_cmd_done` must check `info->host_active == STATE_ERROR` and return before `scsifront_put_rqid` or `scsi_done`. [F32]
- In `scsifront_init_ring`, `xenbus_printf` errors must jump to `fail` to abort `xbt` via `xenbus_transaction_end(xbt, 1)` without overwriting `err`, whereas `xenbus_transaction_end(xbt, 0)` errors other than `-EAGAIN` must jump directly to `free_sring`. [F34]

## External Contracts

- Callers of `scsiback_send_response`, `scsiback_do_resp_with_sense`, and `scsiback_result` must pass Linux `DID_*` host status codes shifted left by 16 bits (`DID_* << 16`) in `result`; `scsiback_result` (via `XEN_VSCSIIF_RSLT_HOST(result)`) and `scsifront_host_byte` must translate between `DID_*` and wire `XEN_VSCSIIF_RSLT_HOST_*` values in bits 16..23 of `vscsiif_response.rslt` in lockstep, preserving `result & 0x00ffff`. [F40, F53]
- In `include/xen/interface/io/vscsiif.h`, action code `4` (`VSCSIIF_ACT_SCSI_SG_PRESET`) must remain reserved and `VSCSIIF_SG_TABLESIZE` (26), `VSCSIIF_MAX_COMMAND_SIZE` (16), `VSCSIIF_SENSE_BUFFERSIZE` (96), and `VSCSIIF_PAGE_SIZE` (4096) must not change without multi-protocol ring support because they fix the 252-byte ring ABI. [F55]
- `scsifront_read_backend_params` must clamp the backend `feature-sg-grant` value to `[VSCSIIF_SG_TABLESIZE, min(SG_ALL, VSCSIIF_SG_TABLESIZE * PAGE_SIZE / sizeof(struct scsiif_request_segment))]` before setting `host->sg_tablesize`, and both `scsifront_probe` and `scsifront_read_backend_params` must set `host->max_sectors` to `(host->sg_tablesize - 1) * PAGE_SIZE / 512` so page-unaligned transfers never exceed `host->sg_tablesize` page grants. [F101, F119]

## Known Pitfalls

- When `nr_sgl > 0` in `scsiback_gnttab_data_map`, indirect `scsiif_request_segment` arrays span discontiguous grant pages; whenever `(unsigned long)seg >= end_seg`, `i_seg` must increment and `seg` and `end_seg` must be re-derived from `vaddr(pending_req, i_seg) + ring_req->seg[i_seg].offset` and `ring_req->seg[i_seg].length`. [F50]
- `scsiback_gnttab_data_map_list` and `scsiback_fast_flush_area` allocate `VSCSI_GRANT_BATCH`-element grant operation and `struct page *` arrays on the kernel stack and must flush each batch via `scsiback_gnttab_data_map_batch` or `gnttab_unmap_refs` whenever the batch index reaches `VSCSI_GRANT_BATCH`. [F61]
- When splitting scatterlist entries into page grants in `map_data_for_request`, each chunk size `bytes` must be clamped to both `min_t(unsigned int, len, PAGE_SIZE - off)` and `min(bytes, data_len)` and the loop must stop when `data_len == 0`. [F63]
- In `scsiback_add_translation_entry`, the `list_for_each_entry` cursor `tpg_entry` remains non-NULL when the loop breaks or finishes without finding a valid LUN and nexus, so the matched TPG must be stored in a separate `tpg` pointer initialized to `NULL` rather than testing `tpg_entry` after the loop. [F79]
- In `scsiback_tpg_param_alias_store`, the `strlen(page) >= VSCSI_NAMELEN` check must precede `len = snprintf(tpg->param_alias, VSCSI_NAMELEN, "%s", page)` because `snprintf` returns the untruncated source length used to index `tpg->param_alias[len - 1]`. [F95]
