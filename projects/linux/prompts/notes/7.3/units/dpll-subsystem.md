# DPLL SUBSYSTEM

The DPLL (Digital Phase Locked Loop) subsystem provides a generic kernel framework and Generic Netlink UAPI (`dpll` family) for registering, querying, configuring, and monitoring hardware DPLL devices and their associated input, output, and MUX pins. Device drivers register `dpll_device` and `dpll_pin` instances with callback tables (`dpll_device_ops`, `dpll_pin_ops`), while the subsystem manages shared object lifetimes, multi-driver registrations, netdev pin associations, and multicast change notifications to user space.

## Architecture & Data Flow

- `dpll_device.pin_refs` and `dpll_pin.parent_refs` are indexed by the driver-assigned `pin->pin_idx`, whereas `dpll_pin_xa` and `dpll_pin.ref_sync_pins` are indexed by the subsystem-assigned `pin->id` (and `dpll_device_xa` and `dpll_pin.dpll_refs` by `dpll->id`). Broken by: passing `pin->id` (or `DPLL_A_PIN_ID` / `DPLL_A_PIN_PARENT_ID`) to `xa_load()` on `pin_refs` or `parent_refs`, or `pin->pin_idx` on `dpll_pin_xa` or `ref_sync_pins`. [F27]
- In `struct dpll_pin_ref`, the untagged union holds `struct dpll_pin *` (`ref->pin`) when stored in `dpll_device.pin_refs` or `dpll_pin.parent_refs` via `dpll_xa_ref_pin_add()`, and `struct dpll_device *` (`ref->dpll`) when stored in `dpll_pin.dpll_refs` via `dpll_xa_ref_dpll_add()`. Broken by: dereferencing `ref->dpll` on entries from `pin_refs`/`parent_refs`, or `ref->pin` on entries from `dpll_refs`. [F26]
- Because `dpll_pin_on_pin_register()` populates both `pin->parent_refs` and `pin->dpll_refs` on a MUX child pin, `dpll_cmd_pin_get_one()` must test `xa_empty(&pin->parent_refs)` to choose between `dpll_msg_add_pin_dplls()` and `dpll_msg_add_pin_parents()`. Broken by: branching on `!xa_empty(&pin->dpll_refs)` before checking `pin->parent_refs`. [F60]
- Before exposing or operating on a `struct dpll_pin` in netlink handlers or notifications (`dpll_pin_pre_doit()`, `dpll_nl_pin_id_get_doit()`, `dpll_nl_pin_get_dumpit()`, `dpll_pin_event_send()`, `dpll_msg_add_pin_ref_sync()`, `dpll_pin_ref_sync_state_set()`), `dpll_pin_available(pin)` must be verified rather than only checking `xa_get_mark(&dpll_pin_xa, pin->id, DPLL_REGISTERED)` or `xa_load()`. [F36]
- In `dpll_nl_ops`, `.doit` callbacks that cast `info->user_ptr[0]` to `struct dpll_device *` must use `dpll_pre_doit` as `.pre_doit`, and those that cast `info->user_ptr[0]` to `struct dpll_pin *` must use `dpll_pin_pre_doit`. Broken by: reading `info->user_ptr[0]` while using `dpll_lock_doit` or the opposite `pre_doit` hook. [F75]
- Before invoking driver setter callbacks, `dpll_pin_freq_set()`, `dpll_pin_esync_set()`, and `dpll_pin_phase_adj_set()` must validate the requested value against the pin's inclusive `[min, max]` ranges (`pin->prop.freq_supported`, `esync.range`, and `pin->prop.phase_range`). [F56]

## Synchronization

- Code executing while holding `dpll_lock` (including all Generic Netlink doit/dumpit paths and all `dpll_device_ops` and `dpll_pin_ops` callbacks) must never call the exported `dpll_device_change_ntf()` or `dpll_pin_change_ntf()`; internal paths holding `dpll_lock` must use `__dpll_device_change_ntf()` or `__dpll_pin_change_ntf()`. [F15]
- Because `dpll_nl_family.parallel_ops` is `true`, every `.doit` entry in `dpll_nl_ops` must pair `.pre_doit` (`dpll_lock_doit`, `dpll_pre_doit`, `dpll_pin_pre_doit`) with `.post_doit` (`dpll_unlock_doit`, `dpll_post_doit`, `dpll_pin_post_doit`) to hold `dpll_lock` across `.doit`; `.pre_doit` must unlock `dpll_lock` on any error return, and `.doit` must never unlock it. [F18, F92]
- Generic Netlink dump operations in `dpll_nl_ops` (`dpll_nl_device_get_dumpit` and `dpll_nl_pin_get_dumpit`) must acquire and release `dpll_lock` within `.dumpit` rather than holding it across `.start` and `.done`, preserving the `nlk_cb_mutex` -> `dpll_lock` lock order. [F17]
- `dpll_netdev_pin_set()` and `dpll_netdev_pin_clear()` unconditionally acquire `rtnl_lock()` inside `dpll_netdev_pin_assign()`, so callers must invoke them from sleepable process context without already holding `rtnl_lock`. [F89]

## Object Lifetimes

- Because `dpll_pin_put()` synchronously destroys `pin->dpll_refs`, `pin->parent_refs`, `pin->ref_sync_pins`, and `pin->prop` via `dpll_pin_prop_free()` before `kfree_rcu(pin, rcu)`, RCU readers of `dpll_netdev_pin()` that do not hold `dpll_lock` may only read fields embedded in `struct dpll_pin` (such as `pin->id` in `dpll_msg_add_pin_handle()`). Broken by: dereferencing `pin->prop.board_label` or `pin->dpll_refs` without `dpll_lock`. [F91]
- `dpll_netdev_pin_set()` publishes `dev->dpll_pin` under `rtnl_lock()` via `rcu_assign_pointer()` without taking a reference on `struct dpll_pin`, so the driver must call `dpll_netdev_pin_clear(dev)` to reset `dev->dpll_pin` to `NULL` before dropping the pin's final reference with `dpll_pin_put()`. [F10]
- `dpll_xa_ref_pin_del()` and `dpll_xa_ref_dpll_del()` must unlink and `kfree()` the matching `struct dpll_pin_registration` on every call, but must erase and `kfree()` the enclosing `struct dpll_pin_ref` only when `refcount_dec_and_test(&ref->refcount)` reaches zero. [F4]
- `dpll_device_unregister()`, `dpll_pin_unregister()`, and `dpll_pin_on_pin_unregister()` only remove the `(ops, priv)` registration entry and do not release the reference acquired by `dpll_device_get()` or `dpll_pin_get()`; drivers must still call `dpll_device_put()` and `dpll_pin_put()` to free the objects. [F79]
- Neither `dpll_pin_register()` nor `dpll_pin_on_pin_register()` may require the target `dpll_device` or parent `dpll_pin` to already carry the `DPLL_REGISTERED` mark, because multi-instance drivers can register pins before the instance owning the parent device or MUX pin registers it. [F77]
- `dpll_pre_doit()` and `dpll_pin_pre_doit()` store a borrowed pointer to `struct dpll_device` or `struct dpll_pin` in `info->user_ptr[0]` without incrementing its refcount, so `.doit` handlers must not drop `dpll_lock` or retain `info->user_ptr[0]` beyond `.post_doit` without taking a reference. [F16]
- `dpll_pin_alloc()` deep-copies all dynamically sized fields of `struct dpll_pin_properties` into `pin->prop` via `dpll_pin_prop_dup()` (rolling back partial allocations in reverse order on failure), and `dpll_pin_put()` releases them via `dpll_pin_prop_free()` before freeing the pin with `kfree_rcu()`. [F3]

## API Contracts

- `drivers/dpll/dpll_nl.c`, `drivers/dpll/dpll_nl.h`, and `include/uapi/linux/dpll.h` are YNL-generated files and must not be edited directly; any changes to DPLL Generic Netlink operations, attribute policies, or UAPI enums/constants must be made in `Documentation/netlink/specs/dpll.yaml` and regenerated. [F93]
- `dpll_device_get()`, `dpll_pin_get()`, `dpll_device_find_from_nlattr()`, and `dpll_pin_find_from_nlattr()` return `ERR_PTR(-errno)` on failure and never `NULL`, whereas `dpll_device_get_by_id()`, `dpll_pin_on_dpll_priv()`, and `dpll_pin_on_pin_priv()` return `NULL` when not found. Broken by: checking `!ptr` instead of `IS_ERR(ptr)` or passing an `ERR_PTR` to `dpll_device_put()`/`dpll_pin_put()`. [F25]
- `dpll_pin_on_pin_priv(parent, pin)` takes `parent` first and child `pin` second, whereas `dpll_pin_ops.state_on_pin_get()` and `state_on_pin_set()` take `(pin, pin_priv, parent_pin, parent_pin_priv, ...)` where `pin_priv` comes from `dpll_pin_on_pin_priv(parent, pin)` and `parent_pin_priv` comes from `dpll_pin_on_dpll_priv(dpll, parent)`. [F28]
- `dpll_pin_registration_find()` matches `(ops, priv, cookie)`, requiring `cookie` to be `NULL` for direct DPLL pin registrations (`dpll_pin_register` / `dpll_pin_unregister`), `pin` for `pin->parent_refs`, and `parent` for `__dpll_pin_register()` / `__dpll_pin_unregister()` in `dpll_pin_on_pin_register()` / `dpll_pin_on_pin_unregister()`. [F29]
- `dpll_device_register()` only guarantees `ops->mode_get` and `ops->lock_status_get` are non-NULL, and `dpll_pin_register()` / `dpll_pin_on_pin_register()` only guarantee `ops->direction_get` and either `ops->state_on_dpll_get` or `ops->state_on_pin_get` are non-NULL; all other `dpll_device_ops` and `dpll_pin_ops` callbacks are optional and must be NULL-checked on each target device or `dpll_pin_ref` before invocation. [F30, F31]
- To support `DPLL_A_PHASE_OFFSET_MONITOR` on a device or `DPLL_A_PIN_FREQUENCY`, `DPLL_A_PIN_ESYNC_FREQUENCY`, `DPLL_A_PIN_REFERENCE_SYNC`, or `DPLL_A_PIN_PHASE_ADJUST` setters on a pin, drivers must provide both the `*_get` and `*_set` callbacks in `dpll_device_ops` or `dpll_pin_ops` on all registered DPLL references, as setters query the current value first for no-op detection and rollback. [F97]
- `dpll_pin_register()` requires `dpll` and `pin` to have identical `module` and `clock_id` fields and non-NULL `ops`, `ops->state_on_dpll_get`, and `ops->direction_get`, whereas `dpll_pin_on_pin_register()` requires `parent->prop.type == DPLL_PIN_TYPE_MUX` and non-NULL `ops`, `ops->state_on_pin_get`, and `ops->direction_get`. [F95]
- Any pin passed as the base pin to `dpll_pin_ref_sync_pair_add()` must implement `ref_sync_get` in the `dpll_pin_ops` of its first DPLL reference, because `dpll_pin_ref_sync_pair_add()` immediately triggers `__dpll_pin_change_ntf()` and `dpll_msg_add_pin_ref_sync()` triggers `WARN_ON(!ops->ref_sync_get)` when `ref_sync_pin` is available. [F96]
- `dpll_device_event_send()` and `dpll_pin_event_send()` invoke `dpll_device_get_one()` and `dpll_cmd_pin_get_one()` with `extack = NULL`, so all `dpll_msg_add_*()` helpers and driver `.get` callbacks in `dpll_device_ops` and `dpll_pin_ops` must accept a `NULL` `extack` pointer. [F33]
- Before calling `ops->lock_status_get()` in `dpll_msg_add_lock_status()`, `status_error` must be initialized to `0`. Before calling `ops->clock_quality_level_get()` in `dpll_msg_add_clock_quality_level()`, the `qls` bitmap of size `DPLL_CLOCK_QUALITY_LEVEL_MAX + 1` must be zero-initialized, and implementations must set 1-based `enum dpll_clock_quality_level` bit indices in `1..DPLL_CLOCK_QUALITY_LEVEL_MAX` (unlike `dpll_pin_properties.capabilities`, which stores a pre-shifted u32 bitmask of `enum dpll_pin_capabilities` values). [F34, F49, F76, F99]
- In `dpll_nl_device_get_dumpit()` and `dpll_nl_pin_get_dumpit()`, `dpll_lock` is released between iterations, so only the XArray index `ctx->idx` (never a `dpll_device` or `dpll_pin` pointer) may be stored in `cb->ctx`; on serialization failure the handler must call `genlmsg_cancel(skb, hdr)`, and on `-EMSGSIZE` save `i` to `dpll_dump_context(cb)->idx` and return `skb->len`. [F46, F102]
- `dpll_pin_get()` deep-copies `const struct dpll_pin_properties *prop` via `dpll_pin_prop_dup()` only when first allocating the `struct dpll_pin` for a `(clock_id, pin_idx, module)` tuple and ignores `prop` on subsequent lookups; if `prop->freq_supported` is non-NULL, `prop->freq_supported_num` must be non-zero and point to at least that many `struct dpll_pin_frequency` elements. [F55, F86]
- Implementations of `dpll_pin_ops.esync_get` must either set `esync->range_num` to `0` or point `esync->range` to an array of at least `esync->range_num` `struct dpll_pin_frequency` elements that remains valid after `esync_get` returns without caller deallocation. [F73]
- `dpll_device_register()` requires `type` in the 1-based inclusive range `[DPLL_TYPE_PPS, DPLL_TYPE_MAX]`, and `dpll_pin_alloc()` requires `prop->type` in `[DPLL_PIN_TYPE_MUX, DPLL_PIN_TYPE_MAX]`, rejecting 0 or out-of-range values with `WARN_ON` and `-EINVAL`. [F54]

## Error Handling

- In Generic Netlink `.doit` handlers and notification senders that allocate an `sk_buff` with `genlmsg_new()` (`dpll_nl_pin_id_get_doit`, `dpll_nl_pin_get_doit`, `dpll_nl_device_id_get_doit`, `dpll_nl_device_get_doit`, `dpll_device_event_send`, `dpll_pin_event_send`), every error path before `genlmsg_reply()` or `genlmsg_multicast()` (including when `genlmsg_put_reply()` or `genlmsg_put()` returns `NULL`) must call `nlmsg_free(msg)`. [F11]
- In `dpll_device_alloc()` and `dpll_pin_alloc()`, the return value of `xa_alloc_cyclic()` must be tested with `ret < 0` rather than `if (ret)` because `xa_alloc_cyclic()` returns `1` on wraparound and a negative errno only on failure. [F24]
- In nested attribute handlers `dpll_pin_ref_sync_set()`, `dpll_pin_parent_device_set()`, and `dpll_pin_parent_pin_set()`, each entry in `tb[]` populated by `nla_parse_nested()` can be `NULL` and must be checked for non-NULL before calling `nla_get_u32()`. [F37]
- When building pin netlink messages, `dpll_msg_add_ffo()` treats `-ENODATA` from `ops->ffo_get()` and `dpll_msg_add_pin_esync()` treats `-EOPNOTSUPP` from `ops->esync_get()` as non-fatal (omitting the attributes and returning `0`), whereas any other non-zero return aborts `dpll_cmd_pin_get_one()`. [F32]
- In `dpll_msg_add_lock_status()`, `DPLL_A_LOCK_STATUS_ERROR` is only added to the Netlink message when `status_error` is non-zero and `status` is either `DPLL_LOCK_STATUS_UNLOCKED` or `DPLL_LOCK_STATUS_HOLDOVER`. [F108]
- User-induced Netlink validation and runtime failures in `drivers/dpll/dpll_netlink.c` must report diagnostics via `NL_SET_ERR_MSG*` on `extack` and return a negative errno without triggering `WARN_ON`, which is reserved for internal invariant or driver registration contract violations. [F109]

## External Contracts

- In `dpll_device_ops` and `dpll_pin_ops`, `temp_get` and `phase_offset_get` report values scaled by `DPLL_TEMP_DIVIDER` and `DPLL_PHASE_OFFSET_DIVIDER` (1000), whereas `phase_adjust_get`, `phase_adjust_set`, and `dpll_pin_phase_adjust_range` use unscaled `s32` picoseconds and `ffo_get` uses `s64` PPM. [F100]
- 64-bit Netlink attributes in the `dpll` attribute set (`enum dpll_a`, such as `DPLL_A_CLOCK_ID`) must be serialized with `nla_put_64bit()` using pad attribute `DPLL_A_PAD`, whereas 64-bit attributes in the `pin` attribute set (`enum dpll_a_pin`, such as `DPLL_A_PIN_CLOCK_ID`, `DPLL_A_PIN_FREQUENCY`, and `DPLL_A_PIN_PHASE_OFFSET`) must use `DPLL_A_PIN_PAD`. [F104]
- `dpll_pin_set_from_nlattr()`, `dpll_set_from_nlattr()`, `dpll_pin_find_from_nlattr()`, and `dpll_device_find_from_nlattr()` must iterate the raw Netlink payload via `nla_for_each_attr()` rather than reading `info->attrs[]`, so repeated multi-attr nests in SET requests are all processed and duplicate filter attributes in ID_GET requests are rejected with `-EINVAL`. [F105]
- Every operation in `dpll_nl_ops` (including read-only GET and ID_GET `.doit` and `.dumpit` commands as well as SET commands) must specify `GENL_ADMIN_PERM` in `.flags` (via `flags: [admin-perm]` in `Documentation/netlink/specs/dpll.yaml`). [F106]

## Known Pitfalls

- In `dpll_pin_prop_dup()`, because `memcpy(dst, src, sizeof(*dst))` shallow-copies `src`'s pointers into `dst` first, each `kmemdup()`/`kstrdup()` call must check `!dst->...` rather than `!src->...` and error unwind labels must only `kfree()` `dst` fields already overwritten prior to the failing allocation. [F59]
- `dpll_pin_set_from_nlattr()` and `dpll_set_from_nlattr()` iterate over the raw Genl message header with `nla_for_each_attr()` and must silently ignore unhandled attribute types in their `switch (nla_type(a))` blocks so target identifier attributes (`DPLL_A_PIN_ID`, `DPLL_A_ID`) do not fail the request. [F61]
