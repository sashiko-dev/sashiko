# RXRPC SOCKETS (AF_RXRPC)

`net/rxrpc` implements `AF_RXRPC` sockets, including RPC call data framing for userspace and in-kernel services (`rxperf`), transmission/reception, peer and RTT management, congestion control, path MTU discovery, and security classes (RxKAD and YFS RxGK) over UDP/IPv4 and UDP/IPv6.

## Architecture & Data Flow
- When `rxrpc_queue_packet()` queues a `txb` with `RXRPC_LAST_PACKET`, it must set `RXRPC_CALL_TX_NO_MORE` on `call->flags`, call `rxrpc_notify_end_tx()`, and clear `call->send_queue = NULL` immediately after advancing `call->send_top`. Broken by: deferring `RXRPC_CALL_TX_NO_MORE` to the I/O thread. [F61]
- In `rxrpc_prepare_data_packet()` and `rxrpc_prepare_data_subpacket()`, `txb->flags` must clear `RXRPC_REQUEST_ACK` and mask with `RXRPC_TXBUF_WIRE_FLAGS`. Set `RXRPC_JUMBO_PACKET` on non-terminal subpackets (`subpkt < req->n - 1`), and set `RXRPC_REQUEST_ACK` or `tq->rtt_samples` only on the terminal subpacket (`subpkt == req->n - 1`), never setting `RXRPC_REQUEST_ACK` when `last && rxrpc_sending_to_client(txb)`. Also test `RXRPC_CALL_BEGAN_RX_TIMER` for `start_tlp` before `test_and_set_bit()` arms `call->expect_rx_by`. [F68, F70, F96]
- In `rxrpc_prepare_data_packet()`, clearing `ix` in `tq->segment_lost` must decrement `call->tx_nr_lost`, and each subpacket must either set `ix` in `tq->segment_retransmitted` (and `tq->ever_retransmitted`) while incrementing `call->tx_nr_resent` (`req->retrans`), or increment `call->tx_nr_sent` (`!req->retrans`). In `rxrpc_send_data_packet()`, when `seq == call->tx_transmitted + 1`, the Don't Fragment check against `call->peer->max_data` must run before advancing `call->tx_transmitted = seq + req->n - 1`. [F67, F69]
- `rxrpc_set_rto()` clamps `call->rto_us` via `rxrpc_bound_rto()` to `[200000, RXRPC_RTO_MAX]`. `rxrpc_get_rto_backoff()` must only take `retrans = true` when actually retransmitting (incrementing `call->backoff` only if `timo_us * 2 <= RXRPC_RTO_MAX`), and `rxrpc_ack_update_rtt()` resets `call->backoff = 0` only on a non-negative RTT sample. `rxrpc_call_add_rtt()` must write `call->srtt_us / 8` to `call->peer->recent_srtt_us` alongside `call->rto_us` to `recent_rto_us` (`call->srtt_us` is shifted left by 3). [F65, F66, F111]
- When `rxrpc_adjust_mtu()` reduces `peer->max_data`, it must clamp `peer->pmtud_good` to `<= max_data` and `peer->pmtud_bad` to `<= max_data + 1`. When `rxrpc_input_probe_for_pmtud()` finishes a probe, it must update `peer->pmtud_jumbo`, clear `conn->pmtud_probe = 0`, and reset `peer->pmtud_lost = false`. [F71]
- `rxrpc_init_client_call_security()` must initialize both `call->security` and `call->security_ix` on all success paths, defaulting to `rxrpc_no_security` when `call->key` is NULL. Connection-wide security failures in `rxrpc_get_incoming_security()` must reject via `rxrpc_direct_conn_abort()` (`RXRPC_SKB_MARK_REJECT_CONN_ABORT`), and `rxrpc_reject_packet()` must set `whdr.callNumber = 0` for `RXRPC_SKB_MARK_REJECT_CONN_ABORT` before falling through. [F63, F64]
- In `rxgk_do_verify_authenticator()` and `rxkad_verify_response()`, advancing `conn->channels[i].call_counter` to a larger wire `call_id` requires verifying `call_id <= INT_MAX` and `conn->channels[i].call == NULL` first, and rejecting any `call_id < conn->channels[i].call_counter` with a connection abort. [F78]
- In `rxgk_get_key()` and `rxgk_rekey()`, compare 16-bit wire `*specific_key_number` against `(u16)current_key`, `(u16)(current_key - 1)`, and `(u16)(current_key + 1)` while reconstructing the full 32-bit `key_number` from `current_key` and rejecting rekey at `current_key == UINT_MAX`. [F121]
- `rxrpc_get_next_serial()` and `rxrpc_get_next_serials()` must check for 0 or 32-bit wrap-around across the `n`-serial range (`serial + n <= n`) and reset `serial` to 1 so no packet or jumbo subpacket gets serial 0. [F118]
- `call->error` and `conn->error` store negative errnos, and `rxrpc_recvmsg_term()` negates `call->error` to positive for `RXRPC_NET_ERROR` and `RXRPC_LOCAL_ERROR` cmsgs. [F55]
- `rxrpc_send_response()` must verify `nr_sg <= ARRAY_SIZE(conn->local->bvec)` from `skb_to_sgvec()` before populating `conn->local->bvec` (sized in `struct rxrpc_local` to `3 + 16` `bio_vec`s / `max(1 + RXRPC_MAX_NR_JUMBO, 3 + 16)` `kvec`s). In `rxrpc_fill_out_ack()`, copying `ack->nAcks` from circular `call->ackr_sack_table` at `sack = call->ackr_sack_base % RXRPC_SACK_SIZE` must split `memcpy` when `sack + ack->nAcks > RXRPC_SACK_SIZE`. [F80, F85, F133]
- `rxrpc_max_backlog` (and `max_backlog` sysctl) must not exceed `RXRPC_BACKLOG_MAX - 1` (circular rings need one dead slot). `struct rxrpc_txqueue` sizes segment bitmasks to `RXRPC_NR_TXQUEUE` (`BITS_PER_LONG`) indexed by `seq & RXRPC_TXQ_MASK`. [F81, F127]

## Synchronization
- `rxrpc_new_client_call_for_sendmsg()` and `rxrpc_do_sendmsg()` must always call `release_sock(&rx->sk)` before returning or running `rxrpc_send_data()`/`rxrpc_recvmsg_data()`. `call->user_mutex` is acquired under `lock_sock(&rx->sk)`, and a non-error `call` from `rxrpc_new_client_call_for_sendmsg()` returns with `call->user_mutex` locked and a reference the caller must unlock and put via `rxrpc_put_call()`. [F1, F144]
- In `rxrpc_send_data()`, `txb` must be detached from `call->tx_pending` at `reload:` before any jump to `maybe_error` or `out:` (which writes `txb` back to `call->tx_pending`). After `wait_for_space` drops and re-acquires `call->user_mutex`, it must jump to `reload:` to detach any new `call->tx_pending` and re-validate `sk->sk_shutdown`, `rxrpc_call_state(call)`, and `call->tx_total_len`. [F44, F72]
- Lockless ordering with `local->io_thread`: readers of `call->error` or `call->completion` must first observe `rxrpc_call_is_complete(call)` (`smp_load_acquire(&call->_state)`), pairing with `smp_store_release()` in `rxrpc_set_call_state()`; `rxrpc_queue_packet()` must set `sq->bufs[ix] = txb` and `send_queue->next` before `smp_store_release(&call->send_top, seq)`; `rxrpc_propose_abort()` must write `send_abort_why`/`err`/`seq` before `smp_store_release(&call->send_abort, abort_code)`; and `rxrpc_begin_rtt_probe()` must order `rtt_serial`/`rtt_sent_at` writes with `smp_wmb()` before setting the pending bit in `call->rtt_avail`. [F24, F25, F26, F29]
- Acquire `rxnet->peer_hash_lock` with `spin_lock_bh()` when hard IRQs are enabled (`rxrpc_lookup_peer()`, `__rxrpc_put_peer()`, `rxrpc_peer_keepalive_worker()`), but with plain `spin_lock()` in `rxrpc_new_incoming_peer()` (hard IRQs disabled). `rxrpc_peer_keepalive_dispatch()` must drop `peer_hash_lock` before `rxrpc_send_keepalive()`, `rxrpc_unuse_local()`, or `rxrpc_put_peer()`. In `rxrpc_lookup_peer()`, fully initialize `candidate` before taking `peer_hash_lock` and re-check `__rxrpc_lookup_peer_rcu()` + `rxrpc_get_peer_maybe()` under it before `hash_add_rcu()`. [F30, F135, F136, F137]
- `rxrpc_assess_MTU_size()` must only be called with hard interrupts enabled because `ip_route_output_ports()` and `ip6_route_output()` can call `local_bh_enable()`. Broken by: calling it in `rxrpc_init_peer()`, `rxrpc_new_incoming_peer()`, or under `local->services_lock`. [F134]
- `rx->recvmsg_lock`, `call->notify_lock`, `peer->lock`, and `conn->state_lock` are shared with `local->io_thread` and require `spin_lock_irq()` when IRQs are enabled. In `rxrpc_notify_socket()`, `call->notify_rx` runs under `rcu_read_lock()` and `spin_lock_irq(&call->notify_lock)`, so callbacks like `rxperf_notify_rx()` must defer blocking work (e.g., `rxrpc_kernel_recv_data()`) to a workqueue. [F142, F143]
- In `rxrpc_init_client_conn_security()`, `conn->security->init_connection_security()` runs under `conn->security_lock`, and setting `conn->state = RXRPC_CONN_CLIENT` must recheck `conn->state == RXRPC_CONN_CLIENT_UNSECURED` under nested `spin_lock_irq(&conn->state_lock)`. In `rxrpc_look_up_server_security()`, reading `conn->local->service` and `rx->securities` must hold `read_lock(&conn->local->services_lock)`. [F34, F35]
- `rxgk_get_key()` holds `read_lock(&conn->security_use_lock)` while incrementing `gk->usage`. When it drops the lock for `rxgk_rekey()`, `rxgk_rekey()` must hold `conn->security_lock`, re-read `conn->rxgk.key_number` and re-check `keys[key_number & mask]`, then nest `write_lock(&conn->security_use_lock)` to update `key_number`/`keys[]` and detach `keys[(current_key - 2) & mask]` into `dead`, calling `rxgk_put(dead)` only after dropping both locks. [F5, F36, F77]
- In `rxgk_extract_token()`, bracket reading `server_key->payload.data[2]` and `rxgk_set_up_token_cipher()` with `down_read(&server_key->sem)` / `up_read(&server_key->sem)`. In `net/rxrpc/proc.c`, `.show` callbacks run under `rcu_read_lock()` or `read_lock(&rxnet->conn_lock)` and must not sleep. In `rxperf_close_socket()` / `rxperf_exit()`, shut down `rxperf_socket` before `flush_workqueue()`, `sock_release()`, `destroy_workqueue()`, and `rcu_barrier()`. [F39, F40, F139]

## Object Lifetimes
- In `rxrpc_send_data()`, a detached or allocated `struct rxrpc_txbuf *txb` must either be queued by `rxrpc_queue_packet()` (`txb = NULL`), freed via `rxrpc_put_txbuf()` at `call_terminated:`, or saved to `call->tx_pending` at `out:`. [F3]
- Every `struct rxgk_context *` from `rxgk_get_key()` in `rxgk_alloc_txbuf()`, `rxgk_secure_packet()`, `rxgk_verify_packet()`, and `rxgk_construct_response()` must be released with `rxgk_put()` across all error paths, helper callees, and `RXRPC_SECURITY_PLAIN`/`default` switch arms. [F4]
- In `rxgk_set_up_ciphers()`, validate transforms from `crypto_krb5_prepare_encryption()` / `crypto_krb5_prepare_checksum()` with `IS_ERR()` in local variables before assigning to `gk`, so `rxgk_generate_transport_key()` can clean up on error via `rxgk_put(gk)` -> `rxgk_free(gk)`. [F17, F46]
- In `rxgk_construct_response()` and `rxkad_respond_to_challenge()`, set `response = NULL` immediately after `rxrpc_post_response(conn, response)` transfers ownership to `conn->tx_response`. [F6]
- Before dropping a reference on `rxrpc_call`, `rxrpc_peer`, or `rxrpc_txbuf` (and in `rxrpc_recvmsg()` before unlocking `call->user_mutex` and calling `rxrpc_put_call()`), cache fields needed for subsequent tracepoints (`debug_id`, `call_debug_id`, `seq`) in local variables. [F8]
- In `output.c`, `rxrpc_send_ACK()` must always call `rxrpc_free_ack(call)` after `rxrpc_alloc_ack()` without overwriting `call->local->kvec[0..1].iov_base`, and `rxrpc_send_data_packet()` passes `whdr` ownership to `rxrpc_prepare_data_packet()` (`page_frag_free(whdr)`). In `rxperf_deliver_to_call()`, `call_complete:` must call `rxrpc_kernel_shutdown_call()`, `rxrpc_kernel_put_call()`, and `cancel_work(&call->work)` before `kfree(call)`. [F14, F15, F20]

## API Contracts
- `rxrpc_alloc_data_txbuf()` and `rxrpc_security::alloc_txbuf` return `NULL` on failure, whereas `rxgk_get_key()` / `rxgk_rekey()` return `ERR_PTR(-ESTALE)` (never `NULL`; callers must translate `-ESTALE` to `-EKEYREJECTED` or `RXGK_BADKEYNO`), and `rxrpc_look_up_server_security()` always returns an `ERR_PTR` on failure (never `NULL`). [F41, F47, F48]
- `rxrpc_recvmsg_data()` and `rxrpc_kernel_recv_data()` return `0` when buffer is filled and data remains, `1` on end of DATA stream, `-EAGAIN` when waiting, and negative errnos on failure. In `rxrpc_kernel_recv_data()`, return `-EMSGSIZE` if `!want_more && ret == 0`, `-EBADMSG` if `ret == 1 && iov_iter_count(iter) > 0`, and `0` (not `1`) if `want_more && ret == 1`. Callers must initialize `*_abort = 0` beforehand and may pass `NULL` `_service` (and `msg` is `NULL` in `rxrpc_recvmsg_data()`). `rxrpc_kernel_send_data()` requires `msg_name == NULL` and `msg_control == NULL`. [F49, F51, F104, F162, F163]
- `rxrpc_kernel_get_call_peer()` returns a new ref via `rxrpc_get_peer()`, whereas `rxrpc_kernel_remote_srx()` and `rxrpc_kernel_remote_addr()` return borrowed pointers and tolerate `peer == NULL` by returning `&rxrpc_null_addr`. [F12, F58]
- In `struct rxrpc_security`, `challenge_to_recvmsg` and `*server_key` callbacks are optional and must be NULL-checked (`RXRPC_SOCK_MANAGE_RESPONSE` requires both `challenge_to_recvmsg` and `sendmsg_respond_to_challenge`). For `key_type_rxrpc_s`, `payload.data[1]` is reserved for `const struct rxrpc_security *`, with cipher/enctype in `data[0]` and inline key material at `&data[2]`. [F56, F126, F158]
- In `rxrpc_do_sendmsg()`, calls in `RXRPC_CALL_CLIENT_AWAIT_CONN` or `RXRPC_CALL_SERVER_RECV_REQUEST` must allow `RXRPC_CMD_SEND_ABORT` instead of returning `-EBUSY`. In `do_udp_sendmsg()`, when `sa_family == AF_INET6`, check `socket->sk->sk_family == AF_INET6` (`-ENOPROTOOPT`) before `udpv6_sendmsg()`. [F106, F151]

## Error Handling
- When `rxrpc_security_types[i]->init()` fails in `rxrpc_init_security()`, decrement `i` before the rollback loop. In `rxrpc_recvmsg()`, an idle non-listening socket must return `-EAGAIN` (not `-ENODATA`). In `rxrpc_send_data()`, test `sk->sk_shutdown & SEND_SHUTDOWN` (not `sk->sk_err`) for `-EPIPE`. [F108, F152, F153]

## External Contracts
- Set `ack->bufferSpace = htons(0)` in `rxrpc_fill_out_ack()`. Never transmit in `rxrpc_reject_packet()` if `sp->hdr.type == RXRPC_PACKET_TYPE_ABORT`. In `rxrpc_input_error()`, IPv4 `ICMP_FRAG_NEEDED` and IPv6 `ICMPV6_PKT_TOOBIG` must call `rxrpc_adjust_mtu()` and jump to `out` without `rxrpc_store_error()`. [F82, F98, F100]
- `RXRPC_USER_CALL_ID` cmsgs use `u32` under `MSG_CMSG_COMPAT` and `unsigned long` otherwise. `RXRPC_SET_CALL_TIMEOUT` requires `!(len & 3) && len >= 4 && len <= 12`, with `hard` in seconds (`<= INT_MAX / HZ`) and `idle`/`normal` in ms (`<= 60 * 60 * 1000`). In `rxkad_decrypt_ticket()`, bit 0 (`*p & 1`) selects `le32_to_cpu()` vs `be32_to_cpu()` for the issue timestamp, and strings must be bounded with `memchr()` and `end - p >= 18` after `REALM`. [F89, F90, F91, F92, F160]

## Known Pitfalls
- `rxrpc_alloc_data_txbuf()` reserves space before `txb->data` only for `rxrpc_jumbo_header` (wire headers use `kvec[0]` in `rxrpc_send_data_packet()`). Security `alloc_txbuf` callbacks must advance `txb->offset` (not `txb->data`), `rxkad_secure_packet_*()` relies on `txb->offset == shdr + txb->len` for padding, and all txbuf/response encoders must zero unused tail/padding bytes. In `rxkad_verify_response()`, save and zero `response->encrypted.checksum` before in-place `rxkad_calc_response_checksum()`. [F62, F76, F123, F124, F161]
- In `rxrpc_prepare_data_packet()`, check `if (i >= req->n) break;` before `!(seq & RXRPC_TXQ_MASK)` advances `tq = tq->next`. In `rxrpc_recvmsg_data()`, evaluate `skb_peek_next()` before `rxrpc_rotate_rx_window(call)`. In `rxrpc_send_response()`, call `rxrpc_local_dont_fragment(conn->local, false)`. [F97, F99, F102]
- Widen `call->rto_us` to `u64` before `<< backoff` and `* NSEC_PER_USEC`; in `rxgk_generate_transport_key()`, only shift `1LL << key->bytelife` for `1 ... 62` and clamp `key->lifetime` with `min_t(u64, ..., INT_MAX / HZ)` before `* HZ`; cast `(u32)check << 16` in `rxkad`; use `do_div(conn->rxgk.start_time, 100)`; and apply `xdr_round_up()` before `/ 4` when advancing `__be32 *`. Compare `rxrpc_seq_t`/`rxrpc_serial_t` via `before()`/`after()` helpers and 8-bit keepalive cursors via `(s8)(cursor - stop) < 0`. Error-queue SKBs in `peer_event.c` use `SKB_EXT_ERR(skb)`, never `rxrpc_skb(skb)`. [F110, F112, F113, F114, F115, F117, F119, F120, F128]
