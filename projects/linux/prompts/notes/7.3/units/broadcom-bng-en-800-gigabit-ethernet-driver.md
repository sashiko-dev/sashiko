# BROADCOM BNG_EN 800 GIGABIT ETHERNET DRIVER

`drivers/net/ethernet/broadcom/bnge` is the PCIe network driver for Broadcom BCM57708 800Gb Ethernet controllers, managing device probe/teardown, HWRM firmware command transport, context backing-store and ring DMA memory, MSI-X interrupts, devlink info, and `net_device` lifecycle (with ring, VNIC, RSS, L2 filter, and `page_pool` initialization).

## Architecture & Data Flow

- When `bnge_is_agg_reqd(bd)` is true, firmware RX ring counts (`bd->hw_resc.resv_rx_rings`, `bd->hw_resc.max_rx_rings`, `hwr.rx`) count total hardware RX rings (`2 * bd->rx_nr_rings`), whereas `bd->rx_nr_rings` and `hwr.grp` count RX ring pairs and must be shifted by 1 (`<< 1` or `>> 1`) when converting between them. [F43]
- Hardware descriptor rings (`rx_desc_ring`, `rx_agg_desc_ring`, `tx_desc_ring`) are two-level page pointer arrays indexed via `[RX_RING(bn, idx)][RX_IDX(idx)]` (or `RX_AGG_RING`/`TX_RING` and `TX_IDX`), whereas software buffer rings (`rx_buf_ring`, `rx_agg_buf_ring`, `tx_buf_ring`) are flat `vzalloc` arrays; `rx_agg_buf_ring` is indexed by `sw_prod` from `rxr->rx_agg_bmap`, not `RING_RX_AGG(bn, prod)`. [F72]
- Occupancy of `rxr->rx_agg_buf_ring[i].netmem` and bit `i` in `rxr->rx_agg_bmap` must be updated in lockstep when allocating (`bnge_alloc_rx_netmem`) or freeing (`bnge_free_one_agg_ring_bufs`) RX aggregation buffers. `bnge_alloc_rx_agg_bmap` stores `bn->rx_agg_ring_mask + 1` (`bn->rx_agg_nr_pages * RX_DESC_CNT`) in `u16 rxr->rx_agg_bmap_size` and allocates `rx_agg_bmap_size / 8` bytes, requiring `MAX_RX_AGG_PAGES * RX_DESC_CNT < 65536` and a multiple of `BITS_PER_LONG`. [F56, F102]
- `BNGE_RX_PAGE_SHIFT` must remain capped at 15 (`BNGE_RX_PAGE_SIZE` < 64 KiB) even when `PAGE_SHIFT >= 16`, because the RX buffer descriptor length (`RX_BD_LEN`) and HWRM `rx_buf_size` (`hwrm_ring_alloc_send_msg`) are 16-bit values that truncate 64 KiB to 0. [F61]
- In `struct bnge_napi`, `bnapi->rx_ring` is only populated for `i < bd->rx_nr_rings` (and is `NULL` on TX-only channels when `BNGE_EN_SHARED_CHNL` is not set), and `bnapi->tx_ring` must be traversed with `bnge_for_each_napi_tx` or NULL-checked per slot. [F39]
- In `struct bnge_ring_mem_info`, `rmem->vmem` (`void **`) is only non-NULL when `rmem->vmem_size > 0` (RX, RX_AGG, and TX software BD rings; `NULL` for NQ, completion, and context-memory rings), so `rmem->vmem` must only be dereferenced when `rmem->vmem_size != 0`. In `bnge_alloc_ring` and `bnge_free_ring`, the coherent DMA size of `rmem->pg_tbl` is computed from `rmem->nr_pages`, `rmem->page_size`, and `rmem->flags & BNGE_RMEM_USE_FULL_PAGE_FLAG`, so these fields must not be modified between allocation and free. [F40, F80]
- When `bd->tx_nr_rings` or `bd->rx_nr_rings` is adjusted (e.g. in `bnge_alloc_irqs` or `bnge_net_init_dflt_rings`), `bd->nq_nr_rings` and `bd->tx_nr_rings_per_tc` must be updated in lockstep. Whenever `bd->hw_resc.resv_rx_rings` or `bd->rx_nr_rings` changes during `bnge_reserve_rings`, `bnge_set_dflt_rss_indir_tbl` must be called to refresh `bd->rss_indir_tbl`. [F49, F50]
- `bd->rss_indir_tbl` stores `bnge_get_rxfh_indir_size(bd)` logical RX ring indices (`0 .. bd->rx_nr_rings - 1`), which `bnge_fill_hw_rss_tbl` translates into pairs of `__le16` firmware IDs (`rx_fw_ring_id`, `cp_fw_ring_id`) in `vnic->rss_table`, chunked into `BNGE_RSS_TABLE_SIZE` (256-byte) blocks per RSS context in `bnge_hwrm_vnic_set_rss`. Whenever `bn->rss_hash_key` is updated (`bn->rss_hash_key_updated`), `bnge_init_vnics` must copy it into `vnic0->rss_hash_key`, recompute `bn->toeplitz_prefix` from its first 8 bytes, and propagate it to all other VNICs. [F59, F74]
- Unlike `fw_vnic_id` and `fw_ring_id` (stored in host byte order), `struct bnge_filter_base::filter_id` is stored in little-endian (`__le64`) directly from `resp->l2_filter_id` in `bnge_hwrm_l2_filter_alloc` and copied without byte-swapping to `req->l2_filter_id` in `bnge_hwrm_l2_filter_free`. `struct bnge_filter_base base` must remain the first member of `struct bnge_l2_filter`. [F60, F78]
- When `ctxm->instance_bmap` is non-zero, `ctxm->pg_info` has `hweight32(ctxm->instance_bmap)` dense entries, so `bnge_hwrm_func_backing_store` must advance a separate dense index `j` into `ctxm->pg_info[j]` only for set bit positions `i` while passing `i` as `req->instance`. `ctxm->split_entry_cnt` must never exceed `BNGE_MAX_SPLIT_ENTRY` (4) because `bnge_hwrm_func_backing_store_qcaps` and `bnge_hwrm_func_backing_store` step a `__le32 *p` pointer across `split_entry_cnt` fields starting at `split_entry_0` and index `ctxm->split[i]`. [F67, F114]
- `bnge_setup_ctxm_pg_tbls` must reject `ctxm->entry_size == 0` and guard `roundup(entries, ctxm->entry_multiple)` with `if (ctxm->entry_multiple)` before calling `bnge_alloc_ctx_pg_tbls` (ensuring `bnge_init_ctx_mem`'s `i += ctxm->entry_size` loop advances), and `bnge_alloc_ctx_pg_tbls` must reject `ctx_pg->nr_pages > MAX_CTX_TOTAL_PAGES` (`MAX_CTX_PAGES * MAX_CTX_PAGES`). [F66, F97]
- `bd->max_tc` must be clamped to `BNGE_MAX_QUEUE` (8) before the `qptr = &resp->queue_id0` loop in `bnge_hwrm_queue_qportcfg()`, because `qptr` walks `2 * bd->max_tc` bytes across consecutive `(queue_id, service_profile)` fields and indexes `BNGE_MAX_QUEUE`-sized arrays on `struct bnge_dev`. [F115]

## Synchronization

- `bnge_hwrm_create_token` returns a non-NULL `bnge_hwrm_wait_token` with `bd->hwrm_cmd_lock` held and must be paired with `bnge_hwrm_destroy_token` to unlink/free the token and unlock `bd->hwrm_cmd_lock`, setting `token = NULL` if destroyed before `exit:` in `__hwrm_send_ctx`. [F2]
- In `__hwrm_send_ctx`, `wmb()` must execute after populating `ctx->req` (including `ctx->req->seq_id`) and any DMA slice buffers and before `__iowrite32_copy` to `bd->bar0` and the doorbell `writel(1, ...)` at `BNGE_GRCPF_REG_CHIMP_COMM_TRIGGER`. When polling a DMA response without a completion ring, the driver must verify `READ_ONCE(ctx->resp->resp_len)` and `READ_ONCE(ctx->resp->seq_id) == ctx->req->seq_id`, execute `dma_rmb()` before testing the trailing `*valid` byte, and zero `*valid = 0` before reading `ctx->resp->error_code` or response data. [F17, F18]
- All 64-bit MMIO doorbell writes must go through `bnge_writeq` (via `bnge_db_write`, `bnge_db_nq`, or `bnge_db_cq`) so `bd->db_lock` serializes the two 32-bit halves of `lo_hi_writeq` on `BITS_PER_LONG == 32` builds. [F19]
- When `bnge_is_agg_reqd(bd)` is true, `bnge_hwrm_ring_alloc` must not write `rxr->rx_db` during `bnge_hwrm_rx_ring_alloc`; it must allocate the RX completion and aggregation rings first and write `rxr->rx_agg_db` before `rxr->rx_db` in `bnge_hwrm_rx_agg_ring_alloc`. [F21]
- Because `bnge_netdev_alloc` sets `netdev->request_ops_lock = true`, `bnge_init_napi`, `bnge_request_irq`, and `bnge_del_napi` must use `_locked` NAPI helpers (`netif_napi_add_config_locked`, `netif_napi_set_irq_locked`, `__netif_napi_del_locked`) with `bn->netdev->lock` held, and `bnge_del_napi` must clear RX/TX queue NAPI pointers and call `synchronize_net()` before `bn->bnapi` is freed. [F14, F135]

## Object Lifetimes

- `bnge_hwrm_req_send` and `bnge_hwrm_req_send_silent` free the request context via `__hwrm_ctx_invalidate` on both success and failure unless the caller first called `bnge_hwrm_req_hold`, in which case the caller must release it with `bnge_hwrm_req_drop`. Broken by: reading `req`/`resp` or calling `bnge_hwrm_req_drop` after send without `bnge_hwrm_req_hold`, or omitting `bnge_hwrm_req_drop` after `bnge_hwrm_req_hold`. [F1]
- In `bnge_probe_one`, `bnge_map_db_bar(bd)` and `bnge_devlink_register(bd)` must only run after `bnge_init_hwrm_resources(bd)` and `bnge_fw_register_dev(bd)` (which populates `bd->db_size` via `bnge_hwrm_func_qcfg` and version fields). During teardown/rollback, `bnge_devlink_unregister` and `bnge_netdev_free` must precede `bnge_fw_unregister_dev` (which must call `bnge_hwrm_func_drv_unrgtr` before `bnge_free_ctx_mem`), which must precede `bnge_cleanup_hwrm_resources` and `bnge_unmap_bars`, with `bnge_devlink_free(bd)` last. [F4, F15, F26, F120]
- Before `bnge_init_chip` allocates firmware resources, all ring/group/VNIC/RSS IDs must be initialized to `INVALID_HW_RING_ID` (and `hw_stats_ctx_id` to `INVALID_STATS_CTX_ID`). Allocation must run `bnge_hwrm_stat_ctx_alloc` before `bnge_hwrm_ring_alloc` (NQ rings, then completion rings, TX completion before TX rings, and RX before AGG rings); `bnge_hwrm_resource_free` must free in reverse order (VNICs/filters, TX/RX/AGG rings, CMPL/NQ rings, stat contexts) and reset each ID to invalid. [F13, F124]
- During `bnge_close_core`, `bnge_free_all_rings_bufs` must recycle all RX buffers (`page_pool_free_va`) and aggregation netmems (`page_pool_recycle_direct_netmem`) before `bnge_free_core` destroys `rxr->page_pool` and `rxr->head_pool` in `bnge_free_rx_rings`. In `bnge_free_core`, `bnge_free_ring` must be called on `ring_struct.ring_mem` (via `bnge_free_nq_tree`) before `bnge_free_nq_desc_arr` (via `bnge_free_nq_arrays`) or `bnge_free_cp_desc_arr` frees `desc_ring` and clears `ring_mem.pg_arr`. [F6, F10]
- `bnge_alloc_core` allocates `bn->bnapi` and all `struct bnge_napi` elements in one contiguous `kzalloc` block (`bnge_free_core` must only `kfree(bn->bnapi)`, never `bn->bnapi[i]`). Similarly, `bnge_alloc_vnic_attributes` places `vnic->rss_hash_key` inside the `vnic->rss_table` coherent DMA buffer (`bnge_free_vnic_attributes` must only `dma_free_coherent` `vnic->rss_table` and set `vnic->rss_hash_key = NULL`). [F7, F8]
- `bnge_alloc_l2_filter` returns an `ERR_PTR` on failure or a hashed `bnge_l2_filter` with incremented `refcnt` (`bnge_lookup_l2_filter` must hold `rcu_read_lock()` across `__bnge_lookup_l2_filter` and `refcount_inc(&fltr->refcnt)`). Callers must release it via `bnge_del_l2_filter` (after `bnge_hwrm_l2_filter_free` if firmware-allocated), which only unlinks (`hlist_del_rcu`) and frees (`kfree_rcu(fltr, base.rcu)`) when `refcount_dec_and_test(&fltr->refcnt)` succeeds. [F11, F27]

## API Contracts

- `bnge_hwrm_req_create` (and `bnge_hwrm_req_init`) and `bnge_hwrm_req_send` (and `bnge_hwrm_req_send_silent`) may only be called from sleeping process context without `bd->hwrm_cmd_lock` or any spinlock held (`GFP_KERNEL`, `bd->hwrm_cmd_lock`, `usleep_range`). `bnge_hwrm_req_create` takes `void **req` and computes `ctx->sentinel` from `req_type`, whereas all other `bnge_hwrm_req_*` functions take `void *req` directly and validate `ctx->sentinel` against `le16_to_cpu(req->req_type)` in `__hwrm_ctx_get`, so `req->req_type` must not be modified after creation. [F33, F136]
- `bnge_hwrm_req_create` places `req` at offset 0 and `struct bnge_hwrm_ctx` at `BNGE_HWRM_CTX_OFFSET`, while `bnge_hwrm_req_dma_slice` carves inline slices downward toward `ctx->req_len` and permits at most one fallback `dma_alloc_coherent` (`ctx->slice_addr`, freed by `__hwrm_ctx_invalidate`); `req_len` must cover the full request and not exceed `BNGE_HWRM_CTX_OFFSET`. [F3, F62]
- `bnge_hwrm_ver_get()` must be the first HWRM command sent in `bnge_fw_register_dev()` because it initializes `bd->hwrm_max_req_len`, `bd->hwrm_max_ext_req_len`, `bd->hwrm_cmd_timeout`, and `bd->hwrm_cmd_max_timeout` used by `__hwrm_send_ctx()`. `bnge_hwrm_func_qcaps()` must run before `bnge_hwrm_queue_qportcfg()`, `bnge_aux_init_dflt_config()`, and `bnge_net_init_dflt_config()` because they check `bnge_is_roce_en(bd)`. [F119, F121]
- `hwrm_ring_alloc_send_msg`, `bnge_set_db`, and `bnge_set_db_mask` require `HWRM_RING_ALLOC_*` bitmasks, whereas `hwrm_ring_free_send_msg` requires firmware `RING_FREE_REQ_RING_TYPE_*` constants. In `hwrm_ring_alloc_send_msg`, `map_index` (`req->logical_id`) must be `ring->grp_idx + bd->rx_nr_rings` for `HWRM_RING_ALLOC_AGG` and `bnapi->index` for `HWRM_RING_ALLOC_CMPL`; for `HWRM_RING_ALLOC_TX`, `ring` must be `&txr->tx_ring_struct` of a `struct bnge_tx_ring_info` with `txr->tx_cpr` already initialized (`container_of` + `bnge_cp_ring_for_tx`). [F34, F36, F109]
- `bnge_db_write`, `bnge_db_cq`, and `bnge_db_nq` require unmasked wrapping producer/consumer indices (`rx_prod`, `rx_agg_prod`, `cp_raw_cons`, `nq_raw_cons`), not ring-masked indices (`RING_RX`, `RING_RX_AGG`), because `DB_RING_IDX(db, idx)` extracts the doorbell epoch bit from `idx & db->db_epoch_mask` (`db_ring_mask + 1`). [F37]

## Error Handling

- In `bnge_alloc_rx_page_pool`, `IS_ERR(pool)` must be checked on a local variable before assigning `rxr->page_pool` or `rxr->head_pool`, `rxr->page_pool` must be destroyed and NULLed if `head_pool` creation fails, and when `!bnge_separate_head_pool(rxr)`, `rxr->head_pool = rxr->page_pool` must be paired with `page_pool_get(pool)` because `bnge_free_rx_rings` unconditionally calls `page_pool_destroy` on both `rxr->page_pool` and `rxr->head_pool`. [F9, F29]
- In `struct bnge_vnic_info`, `l2_filters[0]` is reserved for `netdev->dev_addr` while secondary unicast MACs from `netdev->uc` are stored at 0-based offsets in `uc_list` (sized `(BNGE_MAX_UC_ADDRS - 1) * ETH_ALEN`) and at `l2_filters[1 .. uc_filter_count - 1]`; if `bnge_hwrm_set_vnic_filter` fails at index `i >= 1` in `bnge_cfg_def_vnic`, `vnic->uc_filter_count` must be truncated to `i` so teardown only frees `l2_filters[0 .. i-1]`. [F12, F70]
- `bnge_alloc_one_rx_ring_bufs` succeeds (returning `0` and advancing `rxr->rx_prod`) whenever at least one buffer (`i > 0`) is allocated, whereas `bnge_alloc_one_agg_ring_bufs` requires at least `MAX_SKB_FRAGS` buffers (`i >= MAX_SKB_FRAGS`) and frees partial allocations via `bnge_free_one_agg_ring_bufs` before returning `-ENOMEM`. [F30]

## External Contracts

- `__hwrm_send_ctx` must clear the valid byte at the end of the firmware response (`((u8 *)ctx->resp) + len - 1`) to 0 after completion and zero `ctx->resp` (`memset(ctx->resp, 0, PAGE_SIZE)`) when re-sending a held context (`BNGE_HWRM_INTERNAL_RESP_DIRTY`), so newly added HWRM spec fields read as 0 on older firmware and stale response bytes are not reused. [F64]
- `bnge_backing_store_cfg()` must set `ctx->ctx_arr[last_type].last = 1` on the final enabled context type (`BNGE_CTX_MAX - 1` when `FUNC_BACKING_STORE_CFG_REQ_ENABLES_TIM` is set, else `BNGE_CTX_L2_MAX - 1`) so `bnge_hwrm_func_backing_store()` sets `BNGE_BS_CFG_ALL_DONE` on the last request. [F129]

## Known Pitfalls

- In `struct bnge_ring_struct`, the union member `map_idx` is used on NQ rings (`nqr->ring_struct`) to store `ulp_msix + i` (indexing `bd->irq_tbl`), whereas `grp_idx` is used on RX, RX_AGG, and TX rings to store `0 .. bd->nq_nr_rings - 1` (indexing `bn->grp_info`); do not index `bn->grp_info` by `map_idx` or `bd->irq_tbl` by NQ index `i`. [F35]
- `sizeof(struct bnge_l2_key)` must remain an exact multiple of 4 bytes without padding, and callers of `bnge_alloc_l2_filter()` must initialize both `dst_mac_addr` and `vlan` because `bnge_alloc_l2_filter()` hashes `BNGE_L2_KEY_SIZE` (`sizeof(struct bnge_l2_key) / 4`) `u32` words starting at `&key->filter_key`. [F110]
- In `bnge_set_db`, the hardware ring ID `xid` (`u32`) must be cast to `u64` before shifting left by `DBR_XID_SFT` (32) into `db->db_key64`, and in `BNGE_FW_VER_CODE(maj, min, bld, rsv)`, the 16-bit components `maj`, `min`, and `bld` must be cast to `u64` before shifting left by 48, 32, and 16. [F93, F94]
- In `bnge_hwrm_req_dma_slice`, `offset = max_offset - size` relies on unsigned 32-bit (`u32`) wraparound when `size > max_offset` so `addr < req_addr + max_offset` evaluates to false; do not change `offset` or `size` to a signed or 64-bit type without an explicit `size <= max_offset` check. [F99]
