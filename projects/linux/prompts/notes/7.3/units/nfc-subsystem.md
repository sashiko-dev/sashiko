# NFC SUBSYSTEM

This component encompasses the core NFC subsystem device management (`net/nfc/core.c`), socket family registration (`net/nfc/af_nfc.c`), the NFC Digital protocol stack core (`net/nfc/digital_core.c`), public/internal NFC/NCI/HCI/Digital headers, and four hardware driver families (`s3fwrn5`, `st-nci`, `st21nfca`, and `st95hf`). It manages NFC adapter lifecycles, RF polling, target activation, data exchange, secure element (SE) discovery/I/O, firmware updates, and physical bus transports over I2C, SPI, and UART (serdev).
This component implements core protocol stacks and controller interfaces for the Linux NFC subsystem: the Logical Link Control Protocol (LLCP) and its AF_NFC socket layer, the NFC Digital Protocol stack (NFC-DEP and RF technology polling/anti-collision), the Host Controller Interface (HCI) with SHDLC/NOP link layers, and the NFC Controller Interface (NCI) with its SPI and UART (tty line discipline) transport helpers. It sits between low-level NFC hardware drivers and upper-layer NFC core/socket APIs, handling framing, state machines, flow control, fragmentation/reassembly, and command/response serialization.

## Architecture & Data Flow

- When `dev->ops->check_presence` is implemented on `struct nfc_dev`, `dev->check_pres_timer` must be stopped with `timer_delete_sync` before `nfc_deactivate_target` deactivates the target and before `nfc_data_exchange` calls `im_transceive`, and only re-armed via `mod_timer` when `!dev->shutting_down`. [F70]
- `nfc_devlist_generation` must be initialized to `1` in `nfc_init` and incremented under `nfc_devlist_mutex` in lockstep with `device_add(&dev->dev)` in `nfc_register_device` and `device_del(&dev->dev)` in `nfc_unregister_device`. [F71]
- In `digital_target_found`, `ddev->curr_rf_tech`, `ddev->skb_add_crc`, and `ddev->skb_check_crc` must be updated for the discovered protocol and `ddev->poll_tech_count` must be zeroed before calling `nfc_targets_found`, restoring `ddev->poll_tech_count` if `nfc_targets_found` fails. [F72]
- `st21nfca_hci_load_session` and `st_nci_hci_load_session` must operate on the per-device `init_data.gates` copy (initialized from `st21nfca_gates` or `st_nci_gates`) and update `init_data.gates[j].pipe`, `gate2pipe[gate]`, and `pipes[pipe]` in lockstep when loading open dynamic pipes. [F73]
- `ndlc_open` must call `ndlc->ops->enable(ndlc->phy_id)` before setting `ndlc->powered = 1`, because `st_nci_i2c_enable` and `st_nci_spi_enable` only call `enable_irq` and set `phy->irq_active = true` when both `phy->ndlc->powered == 0` and `phy->irq_active == 0`. [F74]
- In `struct llt_ndlc`, `t1_active` and `t2_active` must be set to `true` whenever `t1_timer` or `t2_timer` is armed with `mod_timer` and cleared to `false` whenever the corresponding timer expires or is stopped with `timer_delete_sync`. [F75]
- When `llt_ndlc_requeue_data_pending` moves unacknowledged packets from `ndlc->ack_pending_q` back to `ndlc->send_q`, it must dequeue from the tail (`skb_dequeue_tail`), set the retransmit bit in `skb->data[0]`, and enqueue at the head (`skb_queue_head`) to preserve packet ordering. [F76]
- In `st21nfca_hci_i2c_read` and `st21nfca_hci_irq_thread_fn`, `phy->current_read_len` must be reset to `0` whenever a frame ends with `ST21NFCA_SOF_EOF`, an I2C read fails, a mid-frame read restarts with `IS_START_OF_FRAME(buf)` (with `skb_trim(skb, 0)`), or a `-EBADMSG` CRC retry occurs. [F79]
- In `st21nfca` and `st-nci` SE control (`st21nfca_hci_control_se`, `st_nci_control_se`), `count_pipes`, `expected_pipes`, `req_completion`, `se_active_timer`, and `se_active = true` must be armed together, and `EVT_HOT_PLUG` / `ANY_OPEN_PIPE` handlers must delete `se_active_timer` and set `se_active = false` before completing `req_completion`. [F80]
- `s3fwrn5_fw_init` must reset `fw_info->parity = 0x00` when initializing a firmware session, and `s3fwrn5_fw_prep_msg` must OR `fw_info->parity` into `hdr.type` and toggle `fw_info->parity ^= 0x80` on every prepared firmware message. [F81]
- Under `phy->common.mutex`, `s3fwrn5_i2c_set_mode` must set `phy->irq_skip = true` whenever `s3fwrn5_phy_power_ctrl` changes `phy->common.mode`, and `s3fwrn5_i2c_write` must clear `phy->irq_skip = false` before sending, so `s3fwrn5_i2c_irq_thread_fn` ignores mode-switch IRQ glitches before the first write. [F82]
- `st95hf_send_recv_cmd` must copy `cmd_array[cmd].cmd_params` into a local stack buffer (`spi_cmd_buffer`) before applying `struct param_list` overrides at `spi_cmd_buffer[3 + list_array[i].param_offset]`, keeping `cmd_array` immutable for restoring default FDT parameters in `st95hf_handle_wtx`. [F83]
- In `st95hf_irq_thread_handler`, when a tag sends `WTX_REQ_FROM_TAG`, `st95hf_handle_wtx(stcontext, true, ...)` temporarily extends the hardware FDT and sets `wtx = true`, which must be cleared along with restoring default FDT via `st95hf_handle_wtx(stcontext, false, 0)` on the next response (and `wtx` and `cb_arg->rats` must be reset on error). [F84]
- For `NFC_DIGITAL_RF_TECH_106A`, `st95hf_in_configure_hw` must store the framing mode in `stcontext->sendrcv_trflag` so `st95hf_in_send_cmd` appends it to the TX frame and `st95hf_error_handling` and `st95hf_response_handler` check and strip the 2-byte CRC (`skb_len - 5` vs `skb_len - 3`) only when `sendrcv_trflag == TRFLAG_NFCA_STD_FRAME_CRC`. [F85]
- `struct nci_hci_dev::pipes` and `struct nfc_hci_dev::pipes` must be sized to `NCI_HCI_MAX_PIPES` and `NFC_HCI_MAX_PIPES` (128) to cover all 7-bit HCI pipe identifiers (`0` through `127`), whereas `gate2pipe` must be sized to `NCI_HCI_MAX_GATES` and `NFC_HCI_MAX_GATES` (256) to allow direct indexing by `u8` gate ID. [F87]
- In `st95hf_spi_recv_response`, bits `6:5` of `receivebuff[0]` (`0x60`) must be combined with `receivebuff[1]` as the upper 2 bits of a 10-bit length on long frames before reading `len - 2` payload bytes into `&receivebuff[2]`, and asynchronous callers must allocate `MAX_RESPONSE_BUFFER_SIZE` (280) bytes. [F95]
- `dev->targets_generation` in `nfc_allocate_device` and `nfc_devlist_generation` in `nfc_init` must be initialized to `1` (non-zero) because Netlink dump callbacks assign them to `cb->seq`. [F97]
- `st_nci_hci_load_session` and `st21nfca_hci_load_session` must verify that `pipe_state` has both created and open bits set in its low nibble via `ST_NCI_DM_IS_PIPE_OPEN` or `ST21NFCA_DM_IS_PIPE_OPEN` (`(p & 0x0f) == (0x02 | 0x04)`) and that `j < ARRAY_SIZE(..._gates)` before recording a dynamic pipe in `init_data.gates`, `gate2pipe`, and `pipes`. [F100]
- In `nfc_target_lost`, if the scan of `dev->targets` reaches `i == dev->n_targets` it must unlock `dev->dev` and return `-EINVAL` without modifying state; otherwise it must clear `dev->active_target = NULL`, decrement `dev->n_targets`, and either compact trailing entries with `memcpy` or free `dev->targets` when `dev->n_targets` becomes `0`. [F105]
- `st21nfca_hci_i2c_write` must byte-stuff only the interior bytes `skb->data[1 .. skb->len - 2]` so the leading and trailing `ST21NFCA_SOF_EOF` delimiters remain unescaped, and `st21nfca_hci_i2c_repack` must track cumulative escape bytes in `j` and trim the unstuffed `skb` to `i - j` before checking the CRC. [F107]
- In `st21nfca_hci_i2c_read`, if a subsequent chunk (`phy->current_read_len > 0`) begins with `IS_START_OF_FRAME(buf)`, the function must reset `skb_trim(skb, 0)` and `phy->current_read_len = 0` before appending `buf` so that a retransmitted frame replaces the interrupted partial frame. [F108]
- When scanning `info->se_info.atr` in `st_nci_se_get_bwi` and `st21nfca_se_get_bwi`, each iteration must advance `i` past `TA` when `ST_NCI_ATR_TA_PRESENT(td)` / `ST21NFCA_ATR_TA_PRESENT(td)` is set before advancing `i` again to read `TB` when `ST_NCI_ATR_TB_PRESENT(td)` / `ST21NFCA_ATR_TB_PRESENT(td)` is set. [F109]
- `digital_target_found()` must validate `protocol` against the supported `NFC_PROTO_*` switch cases (1..7) and return `-EINVAL` on unknown values before computing `target->supported_protocols = (1 << protocol)`. [F115]
- When updating `info->dep_info.curr_nfc_dep_pni` in `st21nfca_im_recv_dep_res_cb()`, the incremented NFC-DEP packet number must be masked with `ST21NFCA_NFC_DEP_PFB_PNI()` (`& 0x03`) so that the 2-bit sequence counter wraps modulo 4. [F118]
- When initializing `struct nci_hci_init_data` or `struct nfc_hci_init_data` (as in `st_nci_hci_network_init()` and `st21nfca_hci_probe()`), `gate_count` must be the element count (`ARRAY_SIZE(...)`) no greater than `NCI_HCI_MAX_CUSTOM_GATES` / `NFC_HCI_MAX_CUSTOM_GATES`, while `memcpy()` into `gates` must use the byte size (`sizeof(...)`). [F123]
- In `digital_target_found()`, `ddev->skb_add_crc` and `ddev->skb_check_crc` must always be set to non-NULL functions—using `digital_skb_add_crc_none` and `digital_skb_check_crc_none` when `DIGITAL_DRV_CAPS_IN_CRC(ddev)` holds—because `digital_in_send()` and `digital_in_send_complete()` call them unconditionally. [F126]
- In `drivers/nfc/st95hf/core.c`, `dev_set_drvdata(&nfc_spi_dev->dev, ...)` stores `&st95context->spicontext` whereas `nfc_digital_set_drvdata()` and IRQ `dev_id` store `st95context`, so SPI device callbacks like `st95hf_remove()` must recover `st95context` via `container_of(spictx, struct st95hf_context, spicontext)`. [F128]
- `struct phy_common common` must remain the first member (at offset 0) of both `struct s3fwrn5_i2c_phy` and `struct s3fwrn82_uart_phy`, because `s3fwrn5_phy_set_wake()`, `s3fwrn5_phy_set_mode()`, and `s3fwrn5_phy_get_mode()` cast `void *phy_id` directly to `struct phy_common *` while bus callbacks cast the same `phy_id` to the outer phy struct. [F129]
- `to_nfc_dev(d)` (`container_of(d, struct nfc_dev, dev)`) must only be applied to a `struct device *` belonging to `nfc_class` (as in `nfc_release()` and `match_idx()`), never to a parent bus `struct device *` (`nfc_dev->dev.parent`). [F130]
- `init_data.session_id` in `struct nci_hci_init_data` and `struct nfc_hci_init_data` (`char session_id[9]`) must be NUL-terminated and at most 8 characters long (as in `st_nci_hci_network_init()` and `st21nfca_hci_probe()`), because HCI session initialization passes `strlen(session_id)` to `nci_hci_set_param()` and `nfc_hci_set_param()`. [F131]
- In `s3fwrn5_fw_request_firmware()`, the 12-byte date field at offset `0x00..0x0B` of the firmware image header has no NUL terminator in the binary image, so copying it into `fw->date` (`char date[13]`) must be bounded to 12 bytes and followed by `fw->date[12] = '\0'`. [F132]
- In `st_nci_hci_network_init()` and `st21nfca_hci_probe()`, the return value `dev_num` of `find_first_zero_bit(dev_mask, *_NUM_DEVICES)` must be checked against `ST_NCI_NUM_DEVICES` / `ST21NFCA_NUM_DEVICES` (256) before calling `set_bit(dev_num, dev_mask)` or formatting `dev_num` into the 2-hex-digit `session_id`. [F134]
- `hdev->quirks` in `struct nfc_hci_dev` (`unsigned long quirks`) is shared between generic HCI quirk bits (`NFC_HCI_QUIRK_SHORT_CLEAR = 0`) and `st21nfca` driver bitflags (`ST21NFCA_FACTORY_MODE = 2`), so any new HCI quirk or `st21nfca` flag bit in `hdev->quirks` must use a distinct bit number `< BITS_PER_LONG`. [F135]
- `nfc_llcp_sock_alloc` initializes `llcp_sock->reserved_ssap` to `LLCP_SAP_MAX`, and `nfc_llcp_recv_connect` only sets `new_sock->reserved_ssap = sock->ssap` for SDP SAPs (`LLCP_WKS_NUM_SAP <= sock->ssap < LLCP_LOCAL_NUM_SAP`), so `llcp_sock_release` must check `llcp_sock->reserved_ssap < LLCP_SAP_MAX` before calling `nfc_llcp_put_ssap`. [F241]
- In struct llc_shdlc, arming or stopping t1_timer or t2_timer must update t1_active or t2_active in lockstep, and each sent I-frame queued on ack_pending_q must store its jiffies timestamp in skb->cb because llc_shdlc_sm_work detects timer expiration via t1_active/t2_active && !timer_pending() and llc_shdlc_reset_t2 re-arms t2_timer from skb->cb. [F246]
- When moving unacknowledged frames from shdlc->ack_pending_q back to shdlc->send_q for retransmission, llc_shdlc_requeue_ack_pending must dequeue from the tail of ack_pending_q, strip the 1-byte SHDLC control header pushed by llc_shdlc_handle_send_queue, queue at the head of send_q, and reset shdlc->ns to shdlc->dnr. [F247]
- In struct nfc_hci_dev, setting hdev->cmd_pending_msg must be accompanied by arming hdev->cmd_timer under hdev->msg_tx_mutex, and __nfc_hci_cmd_completion must stop cmd_timer, free and clear cmd_pending_msg, and schedule msg_tx_work because nfc_hci_msg_tx_work treats cmd_pending_msg != NULL with !timer_pending(&hdev->cmd_timer) as a command timeout. [F248]
- Both standalone HCI (struct nfc_hci_dev) and HCI-over-NCI (struct nci_hci_dev) maintain bidirectional gate-to-pipe mappings in gate2pipe[] and pipes[], which must be updated together when connecting, creating, or resetting pipes (nfc_hci_connect_gate, nfc_hci_cmd_received, nfc_hci_reset_pipes, and their nci_hci_* counterparts). [F249]
- Adding a child socket to a listener's accept_queue in nfc_llcp_accept_enqueue must call sock_hold(sk), set llcp_sock->parent, and call sk_acceptq_added(parent), while removing it in nfc_llcp_accept_dequeue or nfc_llcp_accept_unlink must unlink accept_queue, call sk_acceptq_removed(parent), and call sock_put(sk). [F252]
- Dynamic SDP SAPs (LLCP_WKS_NUM_SAP <= ssap < LLCP_LOCAL_NUM_SAP) are refcounted across a listener and its accepted sockets in local->local_sdp_cnt[ssap - LLCP_WKS_NUM_SAP], and nfc_llcp_put_ssap only clears local->local_sdp and resets the listener's ssap to LLCP_SDP_UNBOUND when atomic_dec_and_test(client_cnt) is true. [F253]
- When the LLCP MAC link goes down, nfc_llcp_mac_is_down must reset local->remote_miu to LLCP_DEFAULT_MIU and local->remote_lto to LLCP_DEFAULT_LTO and call nfc_llcp_socket_release(local, true, 0) so that active connection/bound sockets are closed while local->raw_sockets remain open across link cycles. [F255]
- In net/nfc/llcp_commands.c, llcp_tlv_length[LLCP_TLV_MAX] is indexed by LLCP_TLV_* constants (0 for variable-length TLVs and non-zero for fixed lengths checked by nfc_llcp_build_tlv, llcp_tlv8, and llcp_tlv16), so adding or reordering LLCP_TLV_* constants requires updating llcp_tlv_length in lockstep. [F256]
- NCI command serialization requires ndev->cmd_cnt to be decremented in nci_cmd_work when transmitting a command from ndev->cmd_q and cmd_timer to be armed, while nci_rsp_packet (after stopping cmd_timer) or nci_cmd_timer must reset ndev->cmd_cnt to 1 and queue cmd_work to allow the next command to be sent. [F257]
- Because NCI_OP_CORE_CONN_CREATE_RSP and NCI_OP_CORE_CONN_CLOSE_RSP do not echo the destination or connection parameters, nci_core_conn_create must cache ndev->cur_dest_type and ndev->cur_params before sending the command, and nci_core_conn_close must cache ndev->cur_conn_id and clear ndev->rf_conn_info if the closed conn_info matches it. [F258]
- On NCI RF deactivation in nci_rf_deactivate_ntf_packet, ndev->tx_q must be purged, ndev->rx_data_reassembly freed and nulled, any active NCI_DATA_EXCHANGE completed with -EIO, and nci_clear_target_list(ndev) called only for IDLE_MODE or DISCOVERY deactivation (preserving ndev->targets[] in SLEEP_MODE/SLEEP_AF_MODE). [F259]
- In nci_push_data_hdr and nci_spi_send, the payload length must be sampled from skb->len before calling skb_push to prepend the protocol header, and in nci_spi_send the CCITT CRC must be computed after skb_push so that the header length fields record only the payload size while the SPI CRC covers both header and payload. [F261]
- nci_uart_register stores the caller's struct nci_uart as a shared template in nci_uart_drivers[nu->driver] that nci_uart_set_driver clones via memcpy into a per-TTY allocation stored in tty->disc_data, so runtime callbacks and state mutations must operate on the per-TTY struct nci_uart instance rather than the registered template. [F262]
- In struct nfc_digital_dev, changing the active RF technology (in digital_target_found, digital_in_recv_psl_res, or digital_tg_set_rf_tech) must update ddev->curr_rf_tech and ddev->skb_add_crc/ddev->skb_check_crc (gated by DIGITAL_DRV_CAPS_IN_CRC or DIGITAL_DRV_CAPS_TG_CRC) in lockstep with hardware configuration. [F263]
