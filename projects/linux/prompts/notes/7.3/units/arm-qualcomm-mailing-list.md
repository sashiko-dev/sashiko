# ARM/QUALCOMM MAILING LIST

This unit comprises core Qualcomm SoC platform infrastructure, peripheral drivers, and public headers, including the Secure Channel Manager (`qcom_scm`), hardware CPU frequency scaling (`qcom-cpufreq-hw`), ADM DMA, GENI/QUP I2C and UART controllers, UFS (`ufs-qcom`), DWC3 USB glue (`dwc3-qcom`), USB/PCIe/SGMII PHYs, PMIC battery/charger/backlight drivers (`qcom_battmgr`, `qcom_smbb`, `qcom-wled`), QMI/APR/GPR protocols, and DT binding headers.

## Architecture & Data Flow

- In `i2c-qup.c`, `qup_i2c_determine_mode_v2()` must keep `qup->use_dma = false` if any `msgs[idx].buf` satisfies `is_vmalloc_addr()`. When `qup->use_dma` is true, `qup_i2c_interrupt()` must not write `QUP_RESET_STATE` to `QUP_STATE` on error, `qup_i2c_xfer_v2()` must reset `qup->use_dma = false` after `qup_i2c_bam_xfer()`, and `qup_i2c_bam_clear_tag_buffers()` must reset `sg_cnt` and `tag_buf_pos` to 0 whenever `sg_cnt` exceeds `qup->max_xfer_sg_len` (flushing via `qup_i2c_bam_schedule_desc()`). [F74, F99, F104, F180]
- In `qcom_adm.c`, `adm_prep_slave_sg()` must snapshot `achan->mux`, `achan->crci`, and `blk_size` into `async_desc` so `adm_start_dma()` programs `ADM_CRCI_CTL` from `async_desc` rather than `achan`. `cple` and `desc` must be 8-byte aligned (`ADM_DESC_ALIGN`) with `2 * ADM_DESC_ALIGN` slack in `async_desc->dma_len`, their DMA addresses shifted right by 3 (`>> 3`), `wmb()` issued before writing `ADM_CH_CMD_PTR`, and `adm_dma_free_desc()` must free the unaligned `async_desc->cpl`. [F77, F131, F154]
- In `qcom-cpufreq-hw.c`, `qcom_cpufreq_hw_read_lut()` allocates `LUT_MAX_ENTRIES + 1` entries for `policy->freq_table` (clamping `reg_perf_state` to `LUT_MAX_ENTRIES - 1` in `qcom_cpufreq_get_freq()`); when `dev_pm_opp_of_add_table()` succeeds, it sets `icc_scaling_enabled = true`, disables all DT OPPs via `for (rate = 0; ; rate++)`, and re-enables only LUT matches. When `data->per_core_dcvs` is true, frequency updates must write `index` to `soc_data->reg_perf_state + i * 4` for all sibling cores `i`. [F63, F64, F92, F108]
- In `ufs-qcom.c`, on `POST_CHANGE` in `ufs_qcom_pwr_change_notify()`, `dev_req_params` must be copied to `host->dev_req_params` before `ufs_qcom_icc_update_bw()` indexes `ufs_qcom_bw_table` (clamping gear/lane to `QCOM_UFS_MAX_GEAR`/`QCOM_UFS_MAX_LANE` and keeping `[MODE_MAX][0][0]` at the table maximum). In `ufs_qcom_op_runtime_config()`, `opr->base` must be computed as `hba->mcq_base + (opr->offset - UFS_QCOM_MCQ_CONFIG_OFFSET)`. [F370, F374, F387, F426]
- In `qcom_geni_serial.c`, helpers reachable from earlycon (`qcom_geni_serial_poll_bitfield()`, `qcom_geni_serial_get_char()`, `qcom_geni_serial_wr_char()`, `__qcom_geni_serial_console_write()`) must only call `to_dev_port(uport)` when `((struct qcom_geni_private_data *)uport->private_data)->drv` is non-NULL, and FIFO word counts (`tx_fifo_depth`, `TX_FIFO_WC`, `RX_FIFO_WC_MSK`) must be scaled by `BYTES_PER_FIFO_WORD` (4) when compared with byte counts. [F421, F424]

## Synchronization

- In `__scm_smc_do()`, `qcom_scm_lock` must be acquired and released around each `__scm_smc_do_quirk_handle_waitq()` call inside the retry loop so it is not held across `msleep()` on `QCOM_SCM_V2_EBUSY`; because `qcom_scm_lock` is held while waiting on `__scm->waitq_comp`, `qcom_scm_irq_handler()` and `scm_get_wq_ctx()` must call `__scm_smc_do_quirk()` directly with `ARM_SMCCC_FAST_CALL` without taking `qcom_scm_lock`. `__qcom_scm_qseecom_call()` requires `qcom_scm_qseecom_call_lock` held outside `qcom_scm_lock`. [F9, F28, F160, F167]
- In `qcom-cpufreq-hw.c`, `data->throttle_irq` is requested with `IRQF_NO_AUTOEN` and enabled only in `qcom_cpufreq_ready()`. In `qcom_cpufreq_hw_cpu_offline()`, `data->cancel_throttle = true` must be set under `data->throttle_lock` and unlocked before `cancel_delayed_work_sync(&data->throttle_work)`, while `qcom_lmh_dcvs_notify()` must check `data->cancel_throttle` under `data->throttle_lock` before re-arming `throttle_work` or `throttle_irq`. `policy->fast_switch_possible` requires `!icc_scaling_enabled`. [F32, F33, F171]
- Callers of `devm_pmic_glink_client_alloc()` (like `qcom_battmgr_probe()`) must initialize all locks, work items, completions, power supplies, and the client pointer in `priv` before `pmic_glink_client_register()`. Both `cb` and `pdr` callbacks run under `spin_lock_irqsave(&pg->client_lock, flags)` (while a requester holds `battmgr->lock` waiting on `battmgr->ack`), so neither may sleep, acquire `battmgr->lock`, or call `pmic_glink_send()`/`qcom_battmgr_request()` synchronously; all request paths in `qcom_battmgr.c` must hold `battmgr->lock` and reset `battmgr->ack` and `battmgr->error = 0` before `pmic_glink_send()`. [F207, F208, F232, F298, F299, F494, F495]
- In `qcom_geni_serial.c`, `uport->irq` is marked `IRQ_NOAUTOEN` in probe; `qcom_geni_serial_startup()` must call `qcom_geni_serial_start_rx()` under `uart_port_lock_irq(uport)` before `enable_irq(uport->irq)`. In `qcom_geni_serial_shutdown()`, `disable_irq(uport->irq)` must precede `uart_port_lock_irq(uport)`, which serializes `stop_tx()`, `stop_rx()`, and `cancel_tx_cmd()`. In `msm_serial.c`, `msm_set_baud_rate()` must unlock `port->lock` around `msm_find_best_baud()` and `dev_pm_opp_set_rate()`, and `msm_complete_rx/tx_dma()` must recheck `!dma->rx.count` and `!sg_dma_len(&dma->tx_sg)` after locking `port->lock`. [F328, F329, F330, F333, F334]
- In `__msm_console_write()` and `qcom_geni_serial_console_write()`, when `oops_in_progress` is set, use `uart_port_trylock_irqsave()` and only unlock if `locked` is true; in `qcom_geni_serial_console_write()`, when `qcom_geni_serial_main_active(uport)` is true and `!locked` or `port->tx_remaining == 0`, call `qcom_geni_serial_poll_tx_done()` instead of `qcom_geni_serial_drain_fifo()`. In RX ISR/DMA paths of both serial drivers, call `uart_prepare_sysrq_char()` under `uport->lock` and unlock via `uart_unlock_and_check_sysrq*()`. [F331, F456, F473]
- In `dwc3-qcom.c`, port wakeup IRQs must be requested with `IRQF_NO_AUTOEN`, enabled after DWC3 core suspend (sampling `port->usb2_speed` first), and disabled via `disable_irq_nosync()` using the saved `port->usb2_speed` before DWC3 core resume; `dwc3_qcom_is_host(qcom)` and `qcom->dwc.xhci` must only be accessed where role switching cannot race. In `qmi.h`, `qmi->txn_lock` nests outside `txn->lock`, and a `QMI_RESPONSE` `qmi_msg_handler.fn` runs under `txn->lock` and must not call `qmi_txn_init/wait/cancel()` or `qmi_send_indication()`. [F339, F376, F462, F463, F569]

## Object Lifetimes

- In `qcom_scm.c` ICE key functions (`qcom_scm_ice_set_key()`, `qcom_scm_derive_sw_secret()`, `qcom_scm_generate_ice_key()`, `qcom_scm_prepare_ice_key()`, `qcom_scm_import_ice_key()`), every TZMem buffer holding key or secret material must be wiped with `memzero_explicit()` on all return paths before `__free(qcom_tzmem)` releases it to `__scm->mempool`. [F7]
- Every `struct dev_pm_opp *` from `dev_pm_opp_find_freq_*()` in `qcom-cpufreq-hw.c` and `ufs_qcom_opp_freq_to_clk_freq()` must be released with `dev_pm_opp_put(opp)` on all paths. In `i2c-qup.c`, `i2c-qcom-geni.c`, and `msm_serial.c`, DMA channels from non-devm `dma_request_chan()` must be freed via `dma_release_channel()` on error and remove, resetting `chan = NULL` on `ERR_PTR` or release; in `qup_i2c_bam_schedule_desc()`, if RX `dmaengine_prep_slave_sg()` fails after `dma_async_issue_pending(qup->btx.dma)`, call `dmaengine_terminate_sync(qup->btx.dma)` before `dma_unmap_sg()`. [F16, F23, F60, F143, F312, F320]
- In `ufs-qcom.c`, once `phy_init(phy)` succeeds in `ufs_qcom_power_up_sequence()`, any failure must call `phy_exit(phy)`; `ufs_qcom_exit()` must disable lane clocks and call `phy_power_off()` before `phy_exit()`, and non-devm MSI IRQs in `ufs_qcom_config_esi()` must be freed via `platform_device_msi_free_irqs_all(hba->dev)` on error and in `ufs_qcom_remove()` when `host->esi_enabled` is set. In `dwc3-qcom.c`, `of_icc_get()` paths must be released with `icc_put()`, and once `reset_control_deassert(qcom->resets)` runs, neither probe error paths nor `dwc3_qcom_remove()` may call `reset_control_assert(qcom->resets)`. [F314, F317, F435, F449]
- Callers must `kfree()` buffers returned by `nvmem_cell_read()` (in `qusb2_phy_set_tune2_param()`, even when `val[0] == 0`), `qmi_encode_message()`, and `qcom_mdt_read_metadata()`, and balance `qmp_get()` with `qmp_put()` and `qcom_smem_state_get/register()` with `qcom_smem_state_put/unregister()` (which reject `NULL`/`ERR_PTR`). Conversely, pointers from `qmi_ops.new_server`/`del_server`, `pdr_add_lookup()`, `get_pbs_client_device()`, `geni_se_clk_tbl_get()`, `qcom_smem_get()`, `qcom_ubwc_config_get_data()`, and QMI/APR/GPR rx callbacks (`decoded`, `txn`, `resp`, `payload`) are borrowed and must not be freed or retained asynchronously. [F196, F479, F481, F483, F485, F488, F489, F490, F492, F493, F550, F553]

## API Contracts

- `qcom_scm_call()` requires preemptible process context; atomic/idle/IRQ callers must use `qcom_scm_call_atomic()` (which on legacy platforms takes `<= 5` args and returns `smc_res.a0` without `qcom_scm_remap_error()`). Before `qcom_scm_probe()` publishes `__scm`, `__scm` is NULL, so early-reachable functions must check `__scm != NULL` (and `qcom_scm_shm_bridge_enable()` must use its `scm_dev` arg). `qcom_scm_qseecom_app_send()` requires `qcom_tzmem_alloc()` buffers; `qcom_scm_assign_mem()` takes `*srcvm` as a `BIT(vmid)` mask updated only on success while `src[]` and `newvm[].vmid` use indices `0..63`; `qcom_scm_ice_set_key()` takes `data_unit_size` in 512-byte sectors. [F42, F45, F47, F48, F49, F112, F138, F161, F164]
- Unit and argument conventions: `qcom-cpufreq-hw.c` cpufreq tables/getters use kHz while `dev_pm_opp_*`, `qcom_cpufreq_hw_recalc_rate()`, and `qcom_lmh_get_throttle_freq()` use Hz. In `ufs-qcom.c`, when `hba->use_pm_opp` is set and `freq != ULONG_MAX`, timer/clock/gear helpers must translate `freq` via `ufs_qcom_opp_freq_to_clk_freq()`, and `ufs_qcom_set_clk_40ns_cycles()` takes `ceil(clk_freq, HZ_PER_MHZ)` in MHz mapped via its `switch` table (403 MHz -> 16). In `qcom_battmgr.c`, `sc8280xp` firmware mWh/mAh/mW/mV values are multiplied by 1000 for `power_supply`, while `status.percent` must use unscaled `100 * capacity` divided by `last_full_capacity / 1000` (guarded for `!= 0`). [F126, F270, F271, F305, F346, F347, F414]
- In `dwc3-qcom.c`, platform `drvdata` is owned by `dwc3_core_probe()` and points to `&qcom->dwc` (`struct dwc3 *`), so `dwc3_qcom_probe()` must not call `platform_set_drvdata()`, all callbacks must downcast via `to_dwc3_qcom()`, and `dwc3_qcom_probe()` must set `probe_data.ignore_clocks_and_resets = true` and cap `probe_data.res->end` at `res.start + SDM845_QSCRATCH_BASE_OFFSET`. In `msm_serial.c`, `struct uart_port uart` must remain the first member of `struct msm_port`. In `ufs-qcom.c`, `ufs_qcom_ice_keyslot_program/evict()` must bracket ICE calls with `ufshcd_hold/release(hba)`, and `ufs_qcom_config_esi()` must allocate `hba->nr_hw_queues - hba->nr_queues[HCTX_TYPE_POLL]` MSIs. [F422, F423, F468, F470, F475]

## Error Handling

- Non-standard returns: `qcom_hwspinlock_trylock()` returns `1` on lock acquisition, `0` when contended, and `< 0` on error; `btqcomsmd_send()` must call `kfree_skb(skb)` only when `ret == 0`; `qcom_scm_shm_bridge_enable()` must map `SHMBRIDGE_RESULT_NOTSUPP` to `-EOPNOTSUPP`; `apr_send_pkt()`, `gpr_send_*_pkt()`, `geni_se_clk_tbl_get()`, and `qcom_mdt_get_size()` (`ssize_t`) return positive sizes/counts on success and `< 0` on error; `qcom_register_ssr_notifier()`, `qcom_glink_smem_register()`, and `qcom_smd_register_edge()` return `ERR_PTR` when enabled but `NULL` when disabled. [F44, F51, F62, F491, F503, F506, F515]
- In `qcom-cpufreq-hw.c`, `data->throttle_irq` is `-ENXIO` when absent, so online/offline/exit paths must check `throttle_irq > 0` (`>= 0` in `__qcom_cpufreq_hw_get()`), and `reg_current_vote`/`reg_intr_clr` must be checked non-zero before MMIO access. In `ufs-qcom.c`, `ufs_qcom_setup_clocks()` must NULL-check `ufshcd_get_variant(hba)`, `ufs_qcom_init()` must clear `ufshcd_set_variant(hba, NULL)` on failure, and `ufs_qcom_clk_scale_notify()` must call `ufshcd_uic_hibern8_exit()` on error after entering Hibern8. [F54, F56, F144, F316, F343, F344]
- In `qcom_battmgr.c`, all `power_supply` property callbacks must return `-EAGAIN` when `!battmgr->service_up`; in `qcom_battmgr_sm8350_callback()`, integer property responses must check `resp->intval.result` and jump to `out_complete` (to signal `battmgr->ack`) before decoding `resp->intval.value`, whereas string properties (`BATT_MODEL_NAME`) must check `payload_len == sizeof(resp->strval)` and skip `resp->intval.result`. Once `qmi_txn_init()` succeeds (`ret >= 0`), the caller must call either `qmi_txn_wait()` or `qmi_txn_cancel()`, never both, and also check `resp.result != QMI_RESULT_SUCCESS_V01`. [F222, F245, F261, F509, F510]

## Known Pitfalls

- `qcom_scm_hdcp_req()` unconditionally dereferences `req[0..4]` before checking `req_cnt`, so callers must pass an array of at least `QCOM_SCM_HDCP_MAX_REQ_CNT` (5) elements. In `i2c-qup.c`, `qup_i2c_set_tags()` and `qup_i2c_write_rx_tags_v1()` encode a length of `QUP_READ_LIMIT` (256) as `0` in the u8 tag byte while QUP v2 RX caps `blk_xfer_limit` to `RECV_MAX_DATA_LEN` (254); SMBus block reads (`qup_i2c_check_msg_len()`) must check `msg->buf[0] <= I2C_SMBUS_BLOCK_MAX` (`-EPROTO`) and restore `qup->is_smbus_read = false` and `msg->len += 1` after the recursive read. [F76, F88, F97, F192]
- In `qcom_battmgr_probe()`, `QCOM_BATTMGR_SC8280XP` has enum value `0` (`NULL` match data) while unmatched parents default to `QCOM_BATTMGR_SM8350` (`1`), so variant lookup must use `of_match_device(qcom_battmgr_of_variants, dev->parent)` rather than `of_device_get_match_data()`. Every property in `sm8350/sm8550_*_props` must have a matching entry in `sm8350_*_prop_map` and a case in `qcom_battmgr_sm8350_callback()` because unmapped slots zero-initialize to `0` (`BATT_STATUS`, `USB_ONLINE`, `WLS_ONLINE`). [F221, F231]
- In `qmi_encdec.c`, a `struct qmi_elem_info` entry with `QMI_DATA_LEN` writes a 4-byte `u32` during `qmi_decode_message()` regardless of wire `elem_size` (`u8`/`u16`), so the target C struct field must be `u32`; for `QMI_STRING`, `elem_len` must be `max_wire_chars + 1`, and all `qmi_elem_info` and `qmi_msg_handler` arrays must end with `QMI_EOTI` and `.fn = NULL` sentinels. In `apr.h`, `svc_to_apr_device()` must never be called on a dynamic `gpr_port_t` (nor `to_apr_device()` on `svc->dev`), and `apr_driver.gpr_callback` receives `gpr_device_t *` as `void *data` whereas `gpr_port_cb` receives `priv`. [F512, F548, F549, F551, F552]
