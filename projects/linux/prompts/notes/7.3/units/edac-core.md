# EDAC-CORE

EDAC-CORE (`include/linux/edac.h` and `drivers/edac/`) provides the core Error Detection and Correction framework for memory controllers (`edac_mc`), generic non-memory ECC devices (`edac_device`), PCI parity checking (`edac_pci`), polling workqueues, debugfs error injection, and RAS sysfs features (`ecs`, `mem_repair`, `scrub`), along with hardware EDAC drivers.

## Architecture & Data Flow

- In `edac_dev_register()`, the first-pass `attr_gcnt` sum across `ras_features[]` must equal the exact number of `attribute_group` pointers populated in the second pass (`1` for scrub/mem_repair, `ecs_info.num_media_frus` for ECS), and `ras_attr_groups` must be allocated with `attr_gcnt + 1` entries for the trailing `NULL` sentinel. [F76]
- Keep `enum edac_mem_repair_attributes`, `enum edac_ecs_attributes`, and `enum edac_scrub_attributes` in 1-to-1 positional correspondence with their `dev_attr[]` tables and `*_attr_visible()` switches. `mem_repair_create_desc()`, `ecs_create_desc()`, and `scrub_create_desc()` must copy template attributes into heap-allocated per-instance/per-FRU `dev_attr[]` arrays (with `instance` or `fru_id` set, and `scrub_attrs` sized to `SCRUB_MAX_ATTRS + 1` for `NULL` termination) so `TO_MR_DEV_ATTR`, `TO_ECS_DEV_ATTR`, and `TO_SCRUB_DEV_ATTR` downcasts never see stack or shared static structs. [F58, F59, F219, F257, F258]
- In `struct edac_dev_sysfs_attribute`, `struct edac_dev_sysfs_block_attribute`, and `struct edac_pci_dev_attribute`, `struct attribute attr` must remain the first member at offset 0 because sysfs handlers cast directly between `struct attribute *` and the outer struct pointer without `container_of()`. [F78]
- `edac_mc_alloc_dimms()` and `edac_get_dimm()` must use the same row-major flattening order across `mci->layers[0..n_layers-1]` and keep `mci->dimms[idx]->idx == idx`, because `edac_get_dimm()` validates `mci->dimms[index]->idx != index` and `mci_for_each_dimm()` advances via `(dimm)->idx + 1`. [F61]
- In `edac_mc_handle_error()`, `row` and `chan` must start at `-1`, transition to `dimm->csrow`/`dimm->cschannel` on the first matching populated DIMM, and transition to `-2` (remaining `-2` thereafter) if another matching populated DIMM has a different csrow or channel. In `edac_raw_mc_handle_error()`, `e->grain` must be clamped to `1` when zero before evaluating `fls_long(e->grain - 1)`. [F101, F107]
- `edac_device_handle_ce_count()` and `edac_device_handle_ue_count()` must propagate error counts in lockstep across `block->counters` (when `instance->nr_blocks > 0`), `instance->counters`, and `edac_dev->counters`. [F63]

## Synchronization

- Callers of `__find_mci_by_dev()` / `add_mc_to_global_list()`, `find_edac_device_by_dev()` / `add_edac_dev_to_global_list()`, and `find_edac_pci_by_dev()` / `add_edac_pci_to_global_list()` must hold `mem_ctls_mutex`, `device_ctls_mutex`, or `edac_pci_ctls_mutex` respectively. Before calling `add_*_to_global_list()`, the device pointer (`mci->pdev`, `edac_dev->dev`, `pci->dev`) and unique index (`mc_idx`, `dev_idx`, `pci_idx`) must be initialized, and the functions must keep `mc_devices`, `edac_device_list`, and `edac_pci_list` sorted in strictly ascending index order. `del_*_from_global_list()` must use `list_del_rcu()` followed by `synchronize_rcu()` before `INIT_LIST_HEAD()` so concurrent NMI readers finish traversing the node. [F20, F24, F100, F154]
- In `edac_mc_add_mc_with_groups()`, `edac_device_add_device()`, and `edac_pci_add_device()`, delayed polling work must only be initialized and queued when `edac_check` is non-NULL, after sysfs creation succeeds and `op_state` is set to `OP_RUNNING_POLL` under the subsystem mutex. `edac_mc_reset_delay_period()` must hold `mem_ctls_mutex` while iterating `mc_devices` and check `mci->op_state == OP_RUNNING_POLL` before calling `edac_mod_work()`. [F25, F26]
- `edac_mc_del_mc()`, `edac_device_del_device()`, and `edac_pci_del_device()` must set `op_state = OP_OFFLINE` and remove the controller from its global list under `mem_ctls_mutex`, `device_ctls_mutex`, or `edac_pci_ctls_mutex`, then unlock that mutex before synchronously draining polling work via `edac_stop_work()` (or `edac_device_workq_teardown()`), and must finish draining work before removing sysfs (`edac_remove_sysfs_mci_device()` / `edac_device_remove_sysfs()`). [F10, F23]
- `edac_mc_handle_error()` overwrites the single per-controller `mci->error_desc` buffer and increments non-atomic counters without internal locking; drivers must not invoke it concurrently on the same `struct mem_ctl_info` (e.g., from both a poller workqueue and an IRQ handler). [F156]
- In `edac_pci_sysfs.c`, setup and teardown of the shared `edac_pci_top_main_kobj` and its `THIS_MODULE` reference in `edac_pci_main_kobj_setup()` and `edac_pci_main_kobj_teardown()` must be gated by `atomic_inc_return(&edac_pci_sysfs_refcount) == 1` and `atomic_dec_return(&edac_pci_sysfs_refcount) == 0`. [F27]
- Work items on the `'edac-poller'` workqueue (including `edac_check` callbacks) run with `WQ_MEM_RECLAIM` and must not allocate memory with `GFP_KERNEL` or flush non-`WQ_MEM_RECLAIM` workqueues. In `mpc85xx_edac.c`, `mpc85xx_pci_check()`, `mpc85xx_pcie_check()`, and `mpc85xx_l2_check()` also run directly from hardirq handlers in `EDAC_OPSTATE_INT` mode and must never sleep or take blocking locks. [F272, F273]

## Object Lifetimes

- `csrow_release()` and `dimm_release()` must remain no-ops because `struct csrow_info` and `struct dimm_info` are owned by `struct mem_ctl_info` and freed in `mci_release()`; moreover, `mci_for_each_dimm()` dereferences `(dimm)->idx` in its loop step expression after each iteration body, so loop bodies must never free `dimm` elements. [F3, F91]
- Once `edac_device_register_sysfs_main_kobj()` succeeds inside `edac_device_alloc_ctl_info()`, the `struct edac_device_ctl_info` must be freed via `edac_device_free_ctl_info()` (which unregisters the main kobject), never via `__edac_device_free_ctl_info()` or `kfree()`. Because `dev_ctl->blocks` is a single contiguous allocation into which `dev_inst[i].blocks` points, `__edac_device_free_ctl_info()` must only `kfree(ci->blocks)` and never `kfree(inst->blocks)`. [F6, F116]
- Under `mem_ctls_mutex`, `edac_mc_add_mc_with_groups()` must only set `edac_mc_owner = mci->mod_name` after `add_mc_to_global_list(mci)` and `edac_create_sysfs_mci_device(mci, groups)` succeed, and `edac_mc_del_mc()` must reset `edac_mc_owner = NULL` when `del_mc_from_global_list(mci)` returns true (`list_empty(&mc_devices)`). [F11]
- `edac_stop_work()` must call `cancel_delayed_work_sync(work)` followed by `flush_workqueue(wq)` before an EDAC control structure is freed, and `edac_workqueue_teardown()` must reset `wq = NULL` after `destroy_workqueue(wq)`. [F189]

## API Contracts

- `find_mci_by_dev()` and `edac_mc_find()` return borrowed `struct mem_ctl_info *` pointers without taking a reference, whereas `edac_mc_del_mc()`, `edac_device_del_device()`, and `edac_pci_del_device()` return detached controllers that the caller must free with `edac_mc_free()`, `edac_device_free_ctl_info()`, or `edac_pci_free_ctl_info()` / `edac_pci_release_generic_ctl()`. [F12]
- Before calling `edac_mc_add_mc_with_groups()` (or `edac_mc_add_mc()`), drivers must populate `dimm->nr_pages` (in pages) for all present DIMMs, set raw enums in `dimm->dtype`/`mtype`/`edac_mode` and `BIT()` masks (`*_FLAG_*`) in `mci->mtype_cap`/`edac_ctl_cap`/`edac_cap`/`scrub_cap`, and initialize `mci->pdev`, `mci->mod_name`, `mci->ctl_name`, and `mci->dev_name`. Drivers must set `edac_check` before registration and never change its nullness before removal. [F44, F47, F284]
- In `edac_mc_handle_error()` and `edac_raw_mc_handle_error()`, `page_frame_number` is a PFN, `offset_in_page` is a byte offset, and `dimm->grain` / `e->grain` is a non-zero error granularity in bytes. Direct callers of `edac_raw_mc_handle_error(e)` must pass the `&mci->error_desc` embedded in a valid `struct mem_ctl_info` with non-NULL `e->msg` and `e->other_detail`. In `edac_ce_error()` and `edac_mc_scrub_block()`, software scrubbing must translate `e->page_frame_number` via `mci->ctl_page_to_phys()` when present, verify `pfn_valid(page)` before `pfn_to_page()`, map with `kmap_atomic()`/`kunmap_atomic()`, and bracket `PageHighMem(pg)` mappings with `local_irq_save()`/`local_irq_restore()`. [F45, F155, F168]
- `edac_mc_find_csrow_by_page()` tests the inclusive PFN range `[csrow->first_page, csrow->last_page]` (where `last_page = first_page + nr_pages - 1`) and returns `-1` when no populated csrow matches. `edac_get_dimm(mci, layer0, layer1, layer2)` returns `NULL` when any active coordinate is negative or out of bounds. Callers must check `row >= 0` or `dimm != NULL` before dereferencing. [F39, F83, F213]
- `edac_queue_work()`, `edac_mod_work()`, and `round_jiffies_relative()` take delays in jiffies, whereas `edac_device_workq_setup()` and `edac_device_reset_delay_period()` take milliseconds, must convert them via `msecs_to_jiffies()`, and must update `edac_dev->poll_msec` and `edac_dev->delay` in lockstep; `edac_device_add_device()` must preserve any non-zero driver-supplied `edac_dev->poll_msec` before falling back to `DEFAULT_POLL_INTERVAL`. [F49, F64]
- In `struct edac_device_ctl_info`, `sysfs_attributes` must point to a `NULL`-terminated array (`attr.name == NULL`), whereas `edac_device_block::block_attributes` is bounded by `block->nr_attribs` without a `NULL` sentinel. The `off_val` parameter to `edac_device_alloc_ctl_info()` only offsets the formatted sysfs block name; callers of `edac_device_handle_ce*()` and `edac_device_handle_ue*()` must always pass 0-based `inst_nr` and `block_nr` indices. [F77, F79]
- `edac_pci_do_parity_check()`, `edac_pci_handle_pe()`, and `edac_pci_handle_npe()` must only be called from sleepable context with interrupts enabled because `edac_pci_dev_parity_iterator()` calls `for_each_pci_dev()` (`pci_get_device()`); local IRQs may only be disabled inside `edac_pci_dev_parity_test()` around per-device config reads. [F157]
- In `edac_dev_register()`, `RAS_FEAT_SCRUB` and `RAS_FEAT_MEM_REPAIR` entries in `ras_features` must have non-NULL ops and 0-based sequential `instance` numbers per feature type, while `RAS_FEAT_ECS` entries must have non-NULL `ecs_ops` and non-zero `ecs_info.num_media_frus`. Heap-allocated `struct attribute` instances in `ecs_create_desc()`, `mem_repair_create_desc()`, and `scrub_create_desc()` must be initialized with `sysfs_attr_init()`. In `ecs.c`, `mem_repair.c`, and `scrub.c`, `*_attr_visible()` must only expose read or write permission when the corresponding getter or setter callback in `ops` is non-NULL, and every read-write attribute is gated on its getter (`read_*`/`get_*`) being non-NULL. [F46, F163, F164, F165]

## Error Handling

- For child `dimm_info` and `csrow_info` devices in `edac_mc_sysfs.c`, `edac_create_dimm_object()` and `edac_create_csrow_object()` must call `put_device()` when `device_add()` fails, while post-registration teardown in `edac_create_csrow_objects()`, `edac_delete_csrow_objects()`, and `edac_remove_sysfs_mci_device()` must call `device_unregister()`. [F2]
- When `device_register()` fails on `mci_pdev` in `edac_mc_sysfs_init()` or on `&ctx->dev` in `edac_dev_register()`, the error path must call `put_device()` and return without jumping to manual `kfree()` labels (`data_mem_free`), because `mc_attr_release()` and `edac_dev_release()` free the device and its attached allocations. Any failure in `edac_dev_register()` before `device_register(&ctx->dev)` must jump to `data_mem_free`, while feature descriptors from `ecs_create_desc()`, `mem_repair_create_desc()`, and `scrub_create_desc()` (`attr_groups[0]`) are devm-managed on `parent` and must never be `kfree()`d by callers. [F4, F5, F42, F188]
- `edac_device_create_instance()`, `edac_device_create_block()`, and `edac_pci_create_instance_kobj()` must take a `kobject_get()` reference on the parent controller's main kobject before `kobject_init_and_add()` (because the child `.release` callback calls `kobject_put()` on it) and unwind created instances/blocks on loop error. [F8]
- Return value conventions: `edac_device_add_device()` and `edac_pci_add_device()` return `0` on success and positive `1` on failure (callers must check non-zero and return a negative errno from probe); `edac_mc_add_mc_with_groups()` / `edac_mc_add_mc()` returns `0` or a negative errno; `edac_mc_alloc()`, `edac_device_alloc_ctl_info()`, and `edac_pci_alloc_ctl_info()` return `NULL` on failure (whereas `platform_device_register_simple()` returns an `ERR_PTR`); `skx_get_all_bus_mappings()` returns `< 0` on error and `0` when no sockets are found (both are failures); `_apl_rd_reg()` returns `< 0` on timeout/busy and `1..3` on P2SB status errors (so `apl_rd_reg()` must initialize `ret = 0` before `ret |= _apl_rd_reg(...)` and callers must test `ret != 0`); and platform drivers must propagate negative error codes from `platform_get_irq()` directly. [F35, F36, F37, F200, F202, F212]
- In `fsl_mc_err_probe()`, `altr_sdram_probe()`, `mpc85xx_pci_err_probe()`, and `mpc85xx_l2_err_probe()`, a devres group is opened via `devres_open_group()`: on success the group must be closed/removed (`devres_remove_group()`), and on error any registered EDAC controller must be deleted (`edac_mc_del_mc()`, `edac_device_del_device()`, `edac_pci_del_device()`), any mapped IRQ disposed (`irq_dispose_mapping()`), and `devres_release_group()` called before `edac_mc_free()` / `edac_device_free_ctl_info()` so devm-managed IRQs referencing `mci`/`dci` cannot fire after free. [F13, F43, F184]

## External Contracts

- In `dimmdev_label_store()` and `channel_dimm_label_store()`, userspace input must be non-empty after stripping a single trailing `'\0'` or `'\n'`, strictly shorter than `sizeof(dimm->label)` (`EDAC_MC_LABEL_LEN + 1` = 32 bytes), and explicitly NUL-terminated before returning. [F81]
- In `struct edac_scrub_ops` and `EDAC_SCRUB_ATTR_SHOW`, `get_min_cycle`, `get_max_cycle`, `get_cycle_duration`, and `set_cycle_duration` use scrub cycle durations in seconds (`"%u\n"`), whereas `read_addr`, `write_addr`, `read_size`, and `write_size` use 64-bit values formatted in hexadecimal (`"0x%llx\n"`). [F283]

## Known Pitfalls

- `edac_mc_handle_error()` reuses `mci->error_desc` across calls and must zero it with `memset()` and normalize `e->msg` and `e->other_detail` to `""` before use; when more than `EDAC_MAX_LABELS` DIMMs match, the label cursor `p` must be reset to `e->label` and `*p = '\0'` so the fallback string replaces the overlong list; and when `edac_get_dimm()` returns `NULL`, `edac_inc_ue_error()` must increment `mci->ue_noinfo_count` while `edac_inc_ce_error()` increments `mci->ce_noinfo_count`. [F66, F67, F94]
- String formatting and naming: iterative buffer appends in `edac_dimm_info_location()`, `edac_mc_alloc_dimms()`, and `edac_mc_handle_error()` must use `scnprintf()` rather than `snprintf()`, while `skx_adxl_decode()` and `skx_show_retry_rd_err_log()` must check `MSG_SIZE - len <= 0` or `len - n > 0` between `snprintf()` calls; `dev_set_name()` and `kobject_init_and_add()` with runtime strings must use a literal `"%s"` format; and `edac_pci_alloc_ctl_info()` callers must pass `edac_pci_name` of at most `EDAC_DEVICE_NAME_LEN` (31) bytes. [F85, F114, F128, F236]
- `edac_mc_add_mc_with_groups()` checks `edac_mc_owner != mci->mod_name` by pointer equality, so a driver registering multiple `struct mem_ctl_info` instances must pass the exact same `mod_name` pointer for all of them. When searching `mc_devices` with `list_for_each()`, `edac_mc_find()` must reset the loop variable to `NULL` if the loop ends without a match. [F92, F166]
- Pointer/context multiplexing: in `ecs.c` and `mem_repair.c`, `dev_get_drvdata()` must be called on `ras_feat_dev` (`&ctx->dev`), whereas `ops->cb()` must be passed `ras_feat_dev->parent` and `ctx->ecs.private` or `ctx->mem_repair[inst].private`; debugfs handlers using `to_mci(file->private_data)` (`edac_fake_inject_write`, `inject_enable_write`) require `&mci->dev` as file data whereas `altr_sdr_mc_err_inject_write()` requires `mci`; and in `altera_edac.c`, `altr_edac_device_handler()` expects `dev_id` to be `struct edac_device_ctl_info *` whereas `prv->ecc_irq_handler` expects `struct altr_edac_device_dev *`. [F97, F125, F126]
