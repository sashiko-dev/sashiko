# RUST [PIN-INIT]

Provides the `pin-init` crate, its procedural macro crate (`pin-init-internal`), and kernel integration (`rust/kernel/init.rs`) for safe, fallible in-place and pinned initialization of Rust structs. It enables constructing self-referential C-backed types (such as kernel mutexes and wait lists) and large heap-allocated structures directly in target memory slots (`Box`, `Arc`, `KBox`, or stack) without moving them or overflowing the stack, while providing compile-time structural pinning projections (`#[pin_data]`), pinned destruction (`#[pinned_drop]`), and safe zero-initialization traits (`Zeroable`, `ZeroableOption`).

## Architecture & Data Flow

- When re-initializing an already-initialized `StackInit<T>`, `StackInit::init` must set `this.is_init = false` before calling `this.value.assume_init_drop()` and `init.__init(...)`, and only set `this.is_init = true` after `init.__init` returns `Ok(())`. Broken by: leaving `this.is_init` as `true` during `assume_init_drop()` or `init.__init()`, causing `StackInit::drop` to double-drop `this.value` on error or panic. [F3]
- In `ArrayInit::__init`, `guard.num_init` must be set to `i` before invoking `(self.0)(i)` and `init.__init(&raw mut (*slot)[i])?`, and `core::mem::forget(guard)` must be called only after the `0..N` loop finishes, so `ArrayInitGuard::drop` drops `ptr[..i]` without dropping the failed element `i`. Broken by: incrementing `guard.num_init` before `init.__init` succeeds. [F6]
- `Zeroable` must never be implemented for uninhabited types (such as `!` or `core::convert::Infallible`) or for wide pointers with vtable metadata (`*mut T` / `*const T` with `T: ?Sized` for trait objects), because `zeroed()` and `init_zeroed()` produce all-zero bit patterns. Broken by: adding `unsafe impl Zeroable` for `Infallible`, `!`, or unsized raw pointers without restricting metadata to slice or `str` pointers. [F23]
- The `ZeroableOption` implementation for `Box<T>` in `rust/pin-init/src/alloc.rs` must restrict `T` to `Sized` (`unsafe impl<T> ZeroableOption for Box<T>`), because Rust's option layout optimization guaranteeing that all-zero bytes represent `None` only applies to `Box<T>` when `T: Sized`. Broken by: relaxing the impl to `T: ?Sized`. [F58]
- `zeroable::derive` and `zeroable::maybe_derive` must check or bound every struct or union field type `#field_type` on `::pin_init::Zeroable` (via `assert_zeroable::<#field_type>()` or `where #ty: for<'__dummy> ::pin_init::Zeroable`), not just the type's generic parameters. [F59]
- In `#[pin_data]`, `generate_projections` and `generate_the_pin_data` must only project `&mut Field` or `Slot<Unpinned, Field>` for fields without `#[pin]`, and must project `Pin<&mut Field>` and `Slot<Pinned, Field>` (requiring `PinInit`) for `#[pin]` fields, while `generate_unpin_impl` must bound `Unpin` on every `#[pin]` field. [F68]
- The initializer closure generated by `init::expand` must have return type `Result<InitOk, #error>` (enforced via `__make_closure`) and only construct `InitOk` via `unsafe { InitOk::new() }` at the end of the closure after all fields and `#field_check` have run. Broken by: using `()` or a safe constructor as the `Ok` type, allowing early `return Ok(...)` to skip fields. [F65]
- `make_field_check` in `rust/pin-init/internal/src/init.rs` must emit both `&(*slot).#field_name` and the struct literal `#path { #(#field_name: loop {},)* #zeroing_trailer }` inside the unreachable closure so the compiler rejects unaligned packed fields (E0793), duplicate fields, and missing fields. Broken by: removing either check or adding `..::core::mem::zeroed()` when `init_kind` is `InitKind::Normal`. [F21]
- `expand` and `init_fields` in `rust/pin-init/internal/src/init.rs` must construct internal `__data` and `__{ident}_guard` identifiers with `Span::mixed_site()` while binding `let #ident = #guard.let_binding();` with the field identifier's span. Broken by: using `Span::call_site()` or field spans for internal identifiers, or `Span::mixed_site()` for `let #ident`. [F45]
- `pin_data` in `rust/pin-init/internal/src/pin_data.rs` resolves `#[cfg]` attributes on struct fields one field per expansion pass by stripping all `cfg` attributes from the matched field and returning two mutually exclusive `#[::pin_init::pin_data(#args)]` branches (`cfg(all(...))` and `cfg(not(all(...)))`) before collecting `FieldInfo`. [F43]
- `WaitEntry` must be `#[repr(C)]` with `wait_list: ListHead` as its first field, and only `WaitEntry` nodes may be linked into `CMutex::wait_list`, because `CMutexGuard::drop` downcasts `self.mtx.wait_list.next()` directly via `list_field.as_ptr().cast::<WaitEntry>()` without offset adjustment. [F52]
-In `<ListHead as PinnedDrop>::drop`, when `self` is linked to another node (`!ptr::eq(self.next.as_ptr(), &*self)`), both `next.prev` and `prev.next` must be updated in lockstep to `self.prev` and `self.next` so neighbor `Link` pointers do not dangle to the dropped `ListHead`. [F29]

## Synchronization

- In `<Arc<T> as InPlaceInit<T>>::try_pin_init` and `try_init`, `this` must remain the sole uncloned `Arc<MaybeUninit<T>>` until `Arc::get_mut(&mut this)` obtains the mutable slot and `init.__init(slot)` completes before `this.assume_init()` publishes the `Arc<T>`. Broken by: creating another strong or weak reference before `Arc::get_mut` or exposing the `Arc` before `init.__init` returns `Ok(())`. [F15]
- In `StaticInit::deref`, the slow path under `self.lock.acquire()` must recheck `self.present.get()` before calling `self.init.take()`, and must set `self.present.set(true)` only after `pin_init::raw_init(ptr, f)` completes, because `self.init` is `None` (`unreachable_unchecked()`) once taken and `self.present` gates `assume_init_ref()`. [F36]
- `SpinLock::acquire` must acquire `self.inner` with `Ordering::Acquire` in `compare_exchange` and `SpinLockGuard::drop` must store `false` with `Ordering::Release`. Broken by: weakening either ordering to `Ordering::Relaxed`. [F13]
- In `CMutex::lock` and `CMutexGuard::drop`, `self.spin_lock` must be held whenever reading or mutating `self.locked` or inserting, inspecting, or dropping `_wait_entry` in `self.wait_list` (including when `_wait_entry` goes out of scope after the `thread::park()` loop), because `locked` and `wait_list` use non-atomic `Cell`s. Broken by: dropping `sguard` before `_wait_entry` is dropped at the end of `if self.locked.get()`. [F30]
- When `CMutex::lock` drops `sguard` (`self.spin_lock`) across `thread::park()`, it must reacquire `self.spin_lock` and recheck `self.locked.get()` in a `while` loop before setting `self.locked.set(true)`. Broken by: replacing `while self.locked.get()` with `if` or setting `self.locked.set(true)` without rechecking under `self.spin_lock`. [F11]

## Object Lifetimes

- `init_fields` in `rust/pin-init/internal/src/init.rs` must bind each initialized field accessor via `let #ident = #guard.let_binding();` on the field's `DropGuard` rather than dereferencing `*slot` directly (`&mut (*slot).#ident`), so the reference lifetime cannot outlive the initializer closure. [F64]
- `generate_drop_impl` in `pin_data.rs` must generate a `Drop` impl delegating to `PinnedDrop::drop` with `OnlyCallFromDrop::new()` when `PinnedDrop` is passed to `#[pin_data(PinnedDrop)]`, and otherwise emit `MustNotImplDrop` and `UselessPinnedDropImpl_you_need_to_specify_PinnedDrop` conflict impls. [F7]

## API Contracts

- Implementations of `PinInit::__init` and closures passed to `pin_init_from_closure` or `init_from_closure` must initialize every field of `slot` on `Ok(())`, and on `Err(err)` must drop any partially initialized state in `slot` before returning because callers only deallocate `slot` without dropping it. [F16]
- An `Init<T, E>` implementation or closure passed to `init_from_closure` must not rely on `slot` remaining at a fixed address after `__init` returns, because `Init<T, E>` cancels the pinning requirement of its supertrait `PinInit<T, E>` and allows the caller to move the initialized `T`. [F61]
- `impl_fn_zeroable_option!` implements `ZeroableOption` only for `extern "Rust"`, `unsafe extern "Rust"`, `extern "C"`, and `unsafe extern "C"` function pointers with up to 20 parameters, relying on Rust's `Option` niche layout guarantee that all-zero bytes represent `None`. Broken by: implementing `ZeroableOption` for a wrapper or pointer type without that layout guarantee. [F71]
- In `rust/pin-init/internal/src/init.rs`, `expand` resolves the initializer error type by checking the trailing `? <type>` syntax first, then folding `#[default_error(<type>)]` attributes so the last attribute wins, and only falling back to the `default_error` argument when neither is present. [F44]

## Error Handling

- In `init_fields`, each struct field initialized via `Slot::write` or `Slot::init` must be bound to a local `DropGuard` in field-declaration order and forgotten with `core::mem::forget` under the field's exact `#[cfg]` attributes only after all field initializers and `_: { ... }` blocks succeed. Broken by: forgetting a `DropGuard` early or writing `InitializerKind::Value` fields without a `DropGuard`. [F4]
- `ChainPinInit::__init` and `ChainInit::__init` must hold the initialized `slot` inside a `DropGuard` while invoking the chained closure `self.1` and only call `core::mem::forget(guard)` after `self.1` returns `Ok(())`, so `T` is dropped in place if `self.1` fails or panics. [F5]
- In `pin_init!` and `init!` macro expansion (`init::expand`), when `..Zeroable::init_zeroed()` (`InitKind::Zeroing`) is used, `::core::ptr::write_bytes(slot, 0, 1)` must execute before `#init_fields` so omitted fields and padding are zeroed without clobbering explicitly initialized fields. [F20]
- In `PThreadMutex::new`, `init_raw` must check each `libc::pthread_mutex*` call for a non-zero errno return, destroy initialized `attr` via `libc::pthread_mutexattr_destroy` on both the `pthread_mutexattr_settype` error path and after `pthread_mutex_init`, and preserve `ret` for `from_raw_os_error(ret)`. [F24]

## Known Pitfalls

- `stack_pin_init!` and `stack_try_pin_init!` in `rust/pin-init/src/lib.rs` must bind `let val = $val;` before binding `let mut $var = ::core::pin::pin!(StackInit::uninit());` and then immediately shadow `$var` with the result of `StackInit::init($var, val)`. Broken by: declaring `$var` before evaluating `$val` or passing `$val` inline into `StackInit::init($var, $val)`. [F47]
- Wrapper initializer macros `try_init!` and `try_pin_init!` in `rust/kernel/init.rs` must forward `$($args:tt)*` with `#[default_error($crate::error::Error)]` to `::pin_init::init!` and `::pin_init::pin_init!` rather than matching the struct path, generics, or fields in `macro_rules!`. [F72]
- `SelfReplacer` in `rust/pin-init/internal/src/pin_data.rs` must keep `visit_item_mut` as a no-op so that replacing `Self` with the struct identifier in `struct_.generics` and `struct_.fields` does not descend into nested `syn::Item` definitions where `Self` refers to a different type. [F42]
- In `ListHead::insert_next` and `ListHead::insert_prev`, the neighbor's back-link (`list.next.prev()` or `list.prev.next()`) must be replaced with `this` before `list.next` or `list.prev` is replaced with `this`, so the second field initializer does not dereference uninitialized `this`. [F28]
- Because `ListHead` in `rust/pin-init/examples/linked_list.rs` is a circular doubly-linked list, `ListHead::next` must check `ptr::eq(self.next.as_ptr(), self)` and return `None` for a single-element empty sentinel (required by `CMutexGuard::drop`), while loops traversing multi-element lists via `next()` must explicitly check `ptr::eq` against the starting node to terminate. [F25, F49]
