# ATMEL MACB ETHERNET DRIVER

The Atmel/Cadence MACB/GEM Ethernet driver supports Cadence MACB (10/100 EMAC), AT91RM9200 EMAC, and Cadence GEM (Gigabit/10G Ethernet MAC) controllers across platform and PCI buses. It manages multi-queue DMA descriptor rings, NAPI RX/TX polling, phylink/PCS/MDIO link management, IEEE 1588 PTP hardware timestamping and clock adjustment, ethtool n-tuple RX flow steering, and IEEE 802.1Qbv (TAPRIO/ENST) scheduled traffic offload.

## Architecture & Data Flow

- Because GEM shares RX descriptor bits 22:23 between `GEM_RX_TYPEID_MATCH` and `GEM_RX_CSUM` and cannot offload RX checksums in promiscuous mode, `GEM_BIT(RXCOEN)` in `NCFGR` must be enabled if and only if `(dev->features & NETIF_F_RXCSUM) && !(dev->flags & IFF_PROMISC)` across `macb_init_hw()`, `macb_set_rx_mode()`, and `macb_set_rxcsum_feature()`. [F59]
- Because hardware sets `MACB_BIT(TX_USED)` only on the first descriptor of a transmitted frame and `tx_skb->skb` is set only on its last descriptor, `macb_tx_complete()` and `macb_tx_error_task()` must test `TX_USED` on the first descriptor and then advance `tail` until `tx_skb->skb` is non-NULL. [F91]
- In `macb_start_xmit()`, `desc_cnt` must count TX descriptors using `DIV_ROUND_UP(..., bp->max_tx_length)` for the linear payload and each fragment (plus 1 when `is_lso && skb_headlen(skb) > hdrlen`) so the `CIRC_SPACE` check matches the descriptors consumed by `macb_tx_map()`. [F111]
- `bp->max_tx_length` (including `MACB_MAX_TX_LEN`, `GEM_MAX_TX_LEN`, and any `macb_config.max_tx_length`) must be a multiple of `MACB_TX_LEN_ALIGN` (8 bytes). In `macb_features_check()`, when a nonlinear UDP packet uses UFO, every payload buffer before the final fragment (`skb_headlen(skb) - hdrlen` and `frags[0 .. nr_frags - 2]`) must be aligned to `MACB_TX_LEN_ALIGN`, and `skb_is_nonlinear(skb)` must be checked before decrementing `nr_frags`. [F79, F112]
- PTP one-step sync packets (`ptp_one_step_sync(skb) == true`) must be excluded from software FCS generation in `macb_pad_and_fcs()`, from `MACB_BIT(TX_NOCRC)` in `macb_tx_map()`, and from `gem_ptp_do_txstamp()` in `macb_tx_complete()`. [F162]
- `macb_probe()` sets `driver_data` on `&pdev->dev` to `struct net_device *dev` and registers wakeup capability there, while `macb_mii_init()` sets `driver_data` on `&bp->dev->dev` to `bp->mii_bus`; therefore `dev_get_drvdata()` for `struct net_device *` and `device_may_wakeup()` in `macb_runtime_suspend()`/`macb_runtime_resume()` must use `&pdev->dev` (`dev`), never `&bp->dev->dev`. [F101, F126]
- `bp->hw_stats` is a union of `struct macb_stats` (`macb`) and `struct gem_stats` (`gem`), so shared code (`macb_interrupt()`, `macb_get_stats()`) must check `macb_is_gem(bp)` before selecting a member. `macb_update_stats()` and `gem_update_stats()` iterate `macb_stats`, `gem_stats`, and `queue_stats` via pointer arithmetic, so their fields must match `MACB_PFR..MACB_TPF`, `gem_statistics[]`, and `QUEUE_STATS_LEN` `unsigned long` entries in `queue_statistics[]`. [F46, F83]
- `macb_taprio_setup_replace()` must validate that link `speed` is positive and `entry->gate_mask` is a single bit within `bp->queue_mask` (`is_power_of_2(entry->gate_mask)` and `!(entry->gate_mask & ~bp->queue_mask)`) before calling `enst_max_hw_interval(speed)` or `order_base_2(entry->gate_mask)`. [F108]
- Any code that reads or writes `USRIO` (`macb_or_gem_readl(bp, USRIO)` or `macb_or_gem_writel(bp, USRIO, ...)`) must be guarded by `!(bp->caps & MACB_CAPS_USRIO_DISABLED)`. [F139]

## Synchronization

- When both `queue->tx_ptr_lock` and `bp->lock` are needed, `queue->tx_ptr_lock` must be acquired first with `spin_lock_irqsave()` before acquiring `bp->lock` (as in `macb_start_xmit()` and `macb_tx_restart()`), and `bp->lock` must never be held when acquiring `queue->tx_ptr_lock`. [F144]
- In `macb_start_xmit()`, `macb_tx_complete()`, `macb_tx_restart()`, and `macb_tx_complete_pending()`, `queue->tx_ptr_lock` must be held with `spin_lock_irqsave()` across all `CIRC_SPACE()`/`CIRC_CNT()` checks, updates to `queue->tx_head` and `queue->tx_tail`, BQL reporting, and subqueue stop/wake calls. [F20]
- `napi_disable(&queue->napi_tx)` and `napi_disable(&queue->napi_rx)` must be called outside `bp->lock` and `queue->tx_ptr_lock` (because `napi_disable()` sleeps waiting for `macb_tx_poll()`, which takes `bp->lock`), and before resetting hardware or freeing rings in `macb_close()` and `macb_suspend()`. In `macb_open()` and `macb_resume()`, `napi_enable()` must be called on all queues before initializing hardware and starting phylink. [F22, F148]
- All reads and updates of `bp->hw_stats` and `bp->ethtool_stats`—including calls to `macb_update_stats()` and `gem_update_stats()`—must be serialized under `bp->stats_lock` with local interrupts disabled (`spin_lock_irq()` in process context or `spin_lock()` inside `macb_interrupt()` under `bp->lock`). [F19]
- When reading DMA descriptors in `gem_rx()`, `macb_rx()`, and `gem_ptp_txstamp()`, the CPU must check the ownership/validity bit (`MACB_BIT(RX_USED)` in `desc->addr` or `MACB_BIT(TX_USED)`/`DMA_TXVALID` in `desc->ctrl`) after `rmb()`, and then issue `dma_rmb()` before reading `desc->ctrl` or `desc_ptp->ts_1`/`desc_ptp->ts_2`. [F26]
- In `gem_tsu_get_time()`, `gem_tsu_set_time()`, and `gem_tsu_incr_set()`, all acquisitions of `bp->tsu_clk_lock` must use `spin_lock_irqsave()` / `spin_unlock_irqrestore()` because `gem_tsu_get_time()` is called via `gem_ptp_txstamp()` inside `macb_tx_complete()` while `queue->tx_ptr_lock` is held with IRQs disabled. [F146]
- In `gem_add_flow_filter()` and `gem_del_flow_filter()`, `bp->rx_fs_lock` must be held via `spin_lock_irqsave()` across searching and mutating `bp->rx_fs_list.list` (kept sorted in ascending `fs.location` order with `bp->rx_fs_list.count` updated in lockstep) and programming `gem_prog_cmp_regs()`, `gem_enable_flow_filters()`, and `SCRT2`. [F31, F69]

## Object Lifetimes

- In `macb_free_consistent()`, `bp->macbgem_ops.mog_free_rx_buffers(bp)` must be called before freeing `bp->queues[0].rx_ring` and clearing `queue->rx_ring`, because `gem_free_rx_buffers()` reads each RX descriptor's DMA address from `queue->rx_ring` to unmap live `queue->rx_skbuff` entries. [F5]
- In `macb_remove()`, `macb_clks_disable()` must not be called manually because clearing wakeup via `device_set_wakeup_enable(&bp->pdev->dev, 0)` before `pm_runtime_disable(&pdev->dev)` causes `macb_runtime_suspend()` to disable all device clocks. [F130]

## API Contracts

- Indexing `queue->tx_ring` or `queue->rx_ring` requires wrapping the logical ring index with `macb_tx_ring_wrap()` or `macb_rx_ring_wrap()` before scaling it with `macb_adj_dma_desc_idx()` (as in `macb_tx_desc()`, `macb_rx_desc()`, and `macb_tx_restart()`), whereas `queue->tx_skb` and `queue->rx_skbuff` are indexed by the unscaled wrapped index. [F49]
- In `macb_tx_map()` and `macb_tx_unmap()`, linear SKB buffers mapped with `dma_map_single()` must set `tx_skb->mapped_as_page = false` and use `dma_unmap_single()`, whereas paged fragments mapped with `skb_frag_dma_map()` must set `tx_skb->mapped_as_page = true` and use `dma_unmap_page()`. Callers of `macb_tx_unmap()` outside NAPI poll context (`macb_tx_error_task()` and `macb_tx_map()` rollback) must pass `budget = 0`. [F150, F154]
- Before writing `TBQP` in `macb_tx_error_task()`, transmission must be halted via `macb_halt_tx(bp)` using delay-based atomic polling (`read_poll_timeout_atomic` on `MACB_TSR` for `MACB_BIT(TGO)` to clear, or clearing `MACB_BIT(TE)` in `MACB_NCR` on timeout) because `bp->lock` is held with interrupts disabled. [F133]
- In `macb_clear_csum()`, when `skb->ip_summed == CHECKSUM_PARTIAL`, `skb_cow_head(skb, 0)` must succeed before zeroing the 16-bit checksum field at `skb_checksum_start(skb) + skb->csum_offset` so cloned headers are unshared and Zynq hardware computes valid UDP checksums. [F167]
- In `macb_configure_dma()`, the receive buffer size written to `GEM_DMACFG` (`RXBS` for queue 0) and `queue->RBQS` (for `q >= 1`) must be in units of `RX_BUFFER_MULTIPLE` (64 bytes), and `macb_init_rx_buffer_size()` must round `bp->rx_buffer_size` up to a multiple of `RX_BUFFER_MULTIPLE` on GEM. [F50]
- When clearing interrupt status bits in `ISR`, the driver must check `bp->caps & MACB_CAPS_ISR_CLEAR_ON_WRITE` and write 1s to `queue_writel(queue, ISR, ...)` when set, because reading `ISR` alone does not clear interrupts on those GEM implementations. [F140]
- Each ethtool RX flow rule at `index = fs->location` consumes `SCRT2[index]` and compare slots `GEM_IP4SRC_CMP(index)`, `GEM_IP4DST_CMP(index)`, and `GEM_PORT_CMP(index)`, so `fs->location < bp->max_tuples` (`min(SCR2CMP / 3, T2SCR)`) and `fs->ring_cookie < bp->num_queues` must be validated. When accessing `T2CMPW0`/`T2CMPW1` via `gem_writel_n()` or `gem_readl_n()`, the compare index must be wrapped in `T2CMP_OFST()` (`cmp * 2`), whereas `SCRT2` fields `CMPA`/`CMPB`/`CMPC` take the unscaled compare index. [F48, F84]
- When `netif_running(netdev)` is true across `macb_suspend()` and `macb_resume()`, `bp->pm_data.usrio` and `bp->pm_data.scrt2` must be saved before hardware reset and restored on resume alongside `macb_init_hw()`, `macb_set_rx_mode()`, and `macb_restore_features()`. [F70]

## Error Handling

- `macb_rx_frame()` has a tri-state signed `int` return contract: `0` when a frame is delivered to NAPI, `1` when SKB allocation fails and descriptors are recycled without resetting the ring, and `-1` when descriptor chain lengths are inconsistent (such as `offset + frag_len > len` when `frag != last_frag`, where it must free the skb and return `-1` so `macb_rx()` resets the RX queue). [F39, F80]
- In `macb_set_wol()`, `phylink_ethtool_set_wol()` must be called first and any non-zero return other than `-EOPNOTSUPP` must be returned immediately without updating `bp->wolopts`, `bp->wol`, or wakeup state. In `macb_get_wol()`, `phylink_ethtool_get_wol()` must be called before OR-ing `(WAKE_MAGIC | WAKE_ARP)` into `wol->supported` and `bp->wolopts` into `wol->wolopts`. [F33, F34]
- In `gem_ptp_init()`, `ptp_clock_register()` can return either an `ERR_PTR` or `NULL`; when `IS_ERR(bp->ptp_clock)` is true, `gem_ptp_init()` must reset `bp->ptp_clock = NULL` before returning because `gem_ptp_remove()` and `gem_get_ts_info()` only test `bp->ptp_clock` for non-NULL. [F37]
- In `macb_clk_init()`, `*pclk` and `*hclk` must be validated with `IS_ERR_OR_NULL()` (converting `NULL` to `-ENODEV`), while `*tx_clk`, `*rx_clk`, and `*tsu_clk` come from `devm_clk_get_optional()` and must be validated with `IS_ERR()` so `NULL` remains valid. [F42]
- In `init_reset_optional()`, `zynqmp_pm_is_function_supported(PM_IOCTL, IOCTL_SET_GEM_CONFIG)` returns `0` when supported and a negative errno when unsupported, so the ZynqMP GEM configuration block must only execute when the return value is `0`. [F43]

## External Contracts

- Both `macb_phylink_usx_pcs_ops` and `macb_phylink_pcs_ops` must define a non-NULL `.pcs_config` callback, and `macb_mac_select_pcs()` must return `&bp->phylink_usx_pcs` only for `PHY_INTERFACE_MODE_10GBASER`, `&bp->phylink_sgmii_pcs` only for `PHY_INTERFACE_MODE_SGMII`, and `NULL` otherwise. [F164]
- `macb_mii_probe()` must set `bp->phylink_config.mac_managed_pm = true`, and `macb_suspend()` must stop the link via `phylink_stop(bp->phylink)` under `rtnl_lock()` without calling `netif_carrier_off(netdev)`. [F165]
- `macb_set_ringparam()` must reject non-zero `ring->rx_mini_pending` or `ring->rx_jumbo_pending` with `-EINVAL` and round both `bp->rx_ring_size` and `bp->tx_ring_size` to a power of two via `roundup_pow_of_two()`. [F172]
- In `gem_prog_cmp_regs()` and `gem_enable_flow_filters()`, Type 2 screener compare fields for `ip4src`, `ip4dst`, `psrc`, and `pdst` are only programmed and enabled when their corresponding mask in `fs->m_u.tcp_ip4_spec` is all-ones (`0xFFFFFFFF` for IPv4 addresses, `0xFFFF` for ports). [F85]

## Known Pitfalls

- `bp->queue_mask` is a potentially sparse bitmask of hardware queues (`hw_q` in `0..MACB_MAX_QUEUES-1`) whereas `bp->queues[0..bp->num_queues-1]` is densely packed; `GEM_ISR`/`IER`/`IDR`/`IMR`/`TBQP`/`RBQP`/`RBQS` take `(hw_q - 1)` for `hw_q > 0` (with `hw_q == 0` using `MACB_*` registers), while `GEM_ENST_*` macros take `hw_q` and `platform_get_irq()` takes the dense index `q`. [F77]
- When extracting a buffer's DMA address from an RX descriptor (`struct macb_dma_desc`), callers (`gem_rx()` and `gem_free_rx_buffers()`) must use `macb_get_addr()`, which masks `desc->addr` with `MACB_BF(RX_WADDR, ...)` (stripping `RX_USED` and `RX_WRAP`) and clears `GEM_BIT(DMA_RXVALID)` when `bp->hw_dma_cap & HW_DMA_CAP_PTP` is set. [F153]
- Because GEM 1588 timer registers (`TN`, `TSL`, `TSH`) do not latch atomically, under `bp->tsu_clk_lock` `gem_tsu_get_time()` must read `TN` before and after `TSL`/`TSH` and re-read all three if `first > second`, and `gem_tsu_set_time()` must write `0` to `TN` before writing `TSH`, `TSL`, and `TN`. In `gem_tsu_incr_set()`, `GEM_TISUBN` must be written before `GEM_TI` (with `sub_ns[7:0]` in `SUBNSINCRL` bits `[31:24]` and `sub_ns[23:8]` in `SUBNSINCRH` bits `[15:0]`) because writing `GEM_TI` latches `GEM_TISUBN`. [F30, F51, F113]
- When `gem_hw_timestamp()` combines the 6-bit descriptor timestamp seconds (`DMA_SECH`, `DMA_SECL`) with the upper bits of `tsu.tv_sec` (`~GEM_DMA_SEC_MASK & tsu.tv_sec`), it must subtract `GEM_DMA_SEC_TOP` if the MSB (`GEM_DMA_SEC_TOP >> 1`) is set in `ts->tv_sec` and clear in `tsu.tv_sec`. [F114]
- Because `MACB_BIT`/`MACB_BF*`/`GEM_BIT`/`GEM_BF*` shift a 32-bit signed `int` literal `1`, they must never be used with 32-bit-wide fields (`GEM_TSL_SIZE == 32`) or 64-bit values (`TSU_SEC_MAX_VAL`). Upper 32-bit words (`desc_64->addrh`, `sech`, `GEM_OCTTXH`/`GEM_OCTRXH`) must be cast to `u64` before `<< 32`, and in `gem_ptp_adjfine()`/`gem_ptp_init_timer()` 24-bit `GEM_SUBNSINCR_SIZE` shifts and `scaled_ppm * word` products must use `u64` and `div_u64`/`div_u64_rem`. [F102, F103, F105]
- `macb_set_tx_clk()` must return early when `bp->caps & MACB_CAPS_CLK_HW_CHG` is non-zero (or `!bp->tx_clk`), because `MACB_CAPS_CLK_HW_CHG` indicates hardware adjusts the TX clock automatically. [F89]
- `struct gem_statistic::stat_string` is a 32-byte (`ETH_GSTRING_LEN`) `__nonstring` array where `gem_statistics[]` entries can fill all 32 bytes without a NUL terminator, whereas `gem_get_ethtool_strings()` passes `queue_statistics[i].stat_string` to `snprintf("q%d_%s", ...)`, requiring `queue_statistics[]` strings to stay NUL-terminated. [F123]
