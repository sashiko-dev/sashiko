# CRYPTO API

The CRYPTO API implements the core Linux kernel cryptographic framework (algorithm lookup, larval probing, template instantiation, spawn graphs, transform lifecycles, `cryptd`, `crypto_engine`, `crypto_user` netlink, and `AF_ALG` sockets), frontends for `acomp`, `aead`, `ahash`, and `akcipher`, and software cipher, hash, AEAD, KDF, MAC, compression, and key-agreement implementations.

## Architecture & Data Flow
- Variable-length sub-requests must remain the final member of `adiantum_request_ctx` (`u`), `adiantum_setkey()`'s `data` (`req`), `essiv_aead_request_ctx` (`aead_req`), and `hctr2_request_ctx` (`u`). In `authenc.c`/`authencesn.c`, `reqoff` must be `>= 2 * digestsize` with `sizeof(*areq_ctx) + reqoff` added to the max sub-request size. In `cryptd_*_init_tfm()`, parent `reqsize` must include both `cryptd_*_request_ctx` and the child's `reqsize`/`descsize` (never stack sub-requests). [F120, F121, F274, F301]
- In `acomp_do_req_chain()`, `acomp_save_req()` must run unconditionally before `acomp_do_one_req()`, and `acomp_virt_to_sg()` must save `req->base.flags`, `req->svirt`, and `req->dvirt` into `req->chain` before `acomp_request_set_{src,dst}_sg()` overwrites the union pointers and clears the VIRT flags; `acomp_reqchain_finish()` restores them and `req->base.{complete,data}` only when `err != -EINPROGRESS`. [F34, F35, F56]
- For `CRYPTO_AHASH_ALG_BLOCK_ONLY` transforms, `ahash_prepare_alg()` appends `cra_blocksize + 1` bytes to `cra_reqsize` and `halg.statesize` (partial-block length at `ahash_request_ctx(req) + crypto_ahash_reqsize(tfm) - 1`, buffer at `blenp - bs`). When `crypto_ahash_{update,finup}()` prepends `req->sg_head` to `req->src`, `ahash_{update,finup}_finish()` must restore `req->src`, `req->nbytes`, and `req->base.{complete,data}`. [F61, F118]
- In `crypto_hash_walk_done()`, for scatterlist walks (`!(walk->flags & CRYPTO_AHASH_REQ_VIRT)`), `walk->data` must be decremented by `walk->offset` before `kunmap_local(walk->data)`, and when `walk->entrylen` is non-zero, `walk->offset` must be reset to `0` and `walk->pg` incremented before `hash_walk_next(walk)`. [F102]
- `af_alg_alloc_tsgl()` allocates `MAX_SGL_ENTS + 1` entries and `struct af_alg_sgl` embeds `sgl[ALG_MAX_PAGES + 1]` to reserve the trailing slot for `sg_chain()`. `af_alg_sendmsg()` must cap additions to `MAX_SGL_ENTS - sgl->cur`, and `af_alg_get_rsgl()` / `hash_sendmsg()` must populate at most `ALG_MAX_PAGES` entries so `af_alg_link_sg()` has a spare chaining entry. [F74, F75]
- In `af_alg_sendmsg()` and `af_alg_pull_tsgl()`, `ctx->merge` must only be used when `!(msg->msg_flags & MSG_SPLICE_PAGES)` and must be cleared to 0 whenever `MSG_SPLICE_PAGES` is used or when `af_alg_pull_tsgl()` drains `ctx->used` to 0 (`ctx->init = ctx->more`). [F65]
- In `{hash,aead,skcipher}_check_key()`, once `tfm = pask->private` no longer has `CRYPTO_TFM_NEED_KEY` set, the parent socket's `pask->nokey_refcnt` must be decremented with `atomic_dec()` while the child socket's `ask->nokey_refcnt` is cleared to `0` with `atomic_set()`. [F105]
- When `crypto_create_tfm_node()` or `__crypto_alloc_tfmgfp()` fails in `frontend->init_tfm(tfm)` or `alg->cra_init(tfm)` with `-EAGAIN`, it must call `crypto_shoot_alg(alg)` to set `CRYPTO_ALG_DYING` so the retry loop in `crypto_alloc_tfm_node()` or `crypto_alloc_base()` does not re-select the same algorithm. [F103]

## Synchronization
- In `crypto_start_tests()`, `set_crypto_boot_test_finished()` must run before taking `crypto_alg_sem` (at `late_initcall` in `crypto_algapi_init()`), and each loop iteration must take `crypto_alg_sem`, mark `l->test_started = true` on one larval, drop `crypto_alg_sem` before `crypto_schedule_test(larval)`, and restart from the head of `crypto_alg_list`. Similarly, `crypto_start_test()` must recheck and set `larval->test_started = true` under `down_write(&crypto_alg_sem)` and unlock before `crypto_schedule_test()`. [F17, F18, F98, F134]
- In `crypto_larval_lookup()`, a new larval is allocated via `crypto_larval_add()` only when `!(mask & CRYPTO_ALG_TESTED)`, whereas an existing larval must be waited on via `crypto_larval_wait()` regardless. When `crypto_larval_wait()` wakes and sees `!alg` or `PTR_ERR(alg) == -EEXIST` from `larval->adult`, it must re-run `crypto_alg_lookup(alg->cra_name, type, mask)` and loop if another larval is returned. [F19, F20]
- `crypto_alg_sem` rules: `crypto_grab_spawn()` must take `down_write(&crypto_alg_sem)` and verify `!crypto_is_moribund(alg)` before linking `spawn->list` into `alg->cra_users` (else `crypto_mod_put(alg)`). In `crypto_spawn_alg()`, if `crypto_mod_get(alg)` fails under `down_read(&crypto_alg_sem)`, pin `alg` with `crypto_alg_get(alg)` before `up_read(&crypto_alg_sem)` to call `crypto_shoot_alg()` and `crypto_alg_put()` outside the read lock. [F22, F23]
- Instance/template teardown locking: `crypto_destroy_instance_workfn()` must traverse `tmpl->dead` under `down_write(&crypto_alg_sem)` and only unlink/free instances with `refcount_read(&inst->alg.cra_refcnt) == -1`. `crypto_unregister_template()` and `crypto_update_alg()` must call `up_write(&crypto_alg_sem)` before invoking `crypto_free_instance()`, `crypto_remove_final()`, or `flush_work(&tmpl->free_work)`. [F24, F25, F252]
- `AF_ALG` socket locking: when locking both child `sk` and parent `psk = ask->parent` (as in `{aead,hash,skcipher}_check_key()`), lock `sk` first and then `lock_sock_nested(psk, SINGLE_DEPTH_NESTING)`. Under `lock_sock(sk)`: `alg_bind()` must reject rebinding with `-EBUSY` when `atomic_read(&ask->refcnt) != 0`; `alg_setsockopt()` must reject changes with `-EBUSY` when `atomic_read(&ask->refcnt) != atomic_read(&ask->nokey_refcnt)`; `af_alg_sendmsg()` must check/set `ctx->write = true` across `af_alg_wait_for_wmem()` and clear it before `release_sock(sk)`; `af_alg_alloc_areq()` must reject when `ctx->inflight` is true until `af_alg_free_resources()` finishes; `hash_{sendmsg,recvmsg}()` must only access `ctx->more` and `ctx->result` under `lock_sock(sk)`. [F28, F29, F30, F31, F33]
- Async completion callbacks (`ahash_op_done()`, `async_done_continue()` in `chacha20poly1305.c`, `hmac_finup_done()`, `crypto_ccm_decrypt_done()`, `gcm_*_done()`) must clear `CRYPTO_TFM_REQ_MAY_SLEEP` from the request flags before invoking follow-up operations or continuation subrequests. Callers of `acomp_walk_virt()` in atomic context (e.g., under `crypto_acomp_lock_stream_bh()`) must pass `atomic = true`. [F135, F139, F248]
- In `crypto/cryptd.c`, `struct cryptd_{skcipher,hash,aead}_ctx` must keep `refcount_t refcnt` as their first member; `cryptd_enqueue_request()` and `cryptd_queue_worker()` must disable BH (`local_bh_disable()`) and hold `cpu_queue->bh_lock` across all `cpu_queue->queue` operations and `refcnt` increments, releasing `bh_lock` and re-enabling BH before `crypto_request_complete()`. Worker completions in `cryptd_{skcipher,hash}_complete()` and `cryptd_aead_crypt()` must wrap `*_request_complete()` in `local_bh_disable()`/`local_bh_enable()`. [F192, F193, F321]
- In `crypto/crypto_engine.c`, `engine->queue_lock` must be taken with `spin_lock_irqsave()`/`spin_unlock_irqrestore()` when accessing `engine->{queue,running,busy,cur_req}` and dropped before `op->do_one_request()`, `crypto_request_complete()`, or `msleep()`. In `crypto_pump_requests()`, `queue_lock` must be re-acquired before jumping to `start_request` or `out`, and `-EINPROGRESS` backlog completion must be skipped when requeuing on `-ENOSPC`. [F281, F323]
- In `crypto/crypto_engine.c`, when `!engine->retry_support`, `engine->cur_req` blocks further dequeues until `crypto_finalize_request()` (which requires BH-disabled softirq context) clears `engine->cur_req = NULL` under `queue_lock`. `engine->busy` is cleared only when `in_kthread` and the queue is empty or `!engine->running`; `crypto_engine_stop()` must re-verify under `queue_lock` after its polling loop that both `crypto_queue_len(&engine->queue)` and `engine->busy` are zero before clearing `engine->running`, and `crypto_engine_exit()` must not destroy `engine->kworker` if stop fails. [F232, F233, F282, F322]

## Object Lifetimes
- In `crypto_mod_put()`, `alg->cra_module` must be saved into a local variable before calling `crypto_alg_put(alg)` because `crypto_alg_put()` may free `alg` via `crypto_destroy_alg(alg)`. [F2]
- `crypto_register_instance()` and `{aead,ahash,akcipher}_register_instance()` require `inst->free` to be set beforehand and take ownership of `inst` only on success; on error, the caller must invoke its teardown helper to call `crypto_drop_spawn()` and free `inst`. `crypto_drop_spawn()` must return if `!spawn->alg` and only call `crypto_mod_put(spawn->alg)` when `!spawn->registered`. [F5, F45, F159]
- When `frontend->init_tfm(tfm)` fails in `crypto_create_tfm_node()`, `crypto_exit_ops(tfm)` is skipped, so `init_tfm` callbacks (`crypto_acomp_init_tfm()`, `crypto_ahash_init_tfm()`, `crypto_{ccm,gcm}_init_tfm()`, `hctr2_init_tfm()`, `essiv{,_skcipher,_aead}_init_tfm()`) must roll back any fallback/child transforms or `alg->init_tfm` state before returning non-zero. [F6, F188]
- In `af_alg.c`: once `af_alg_accept()` calls `sock_init_data(newsock, sk2)`, `newsock` owns `sk2` and error paths must never call `sock_put(sk2)`. In `alg_bind()`, `(ask->type, ask->private)` must be swapped with `(type, private)` under `lock_sock(sk)` when `ask->refcnt == 0` and released via `alg_do_release(type, private)` after `release_sock(sk)`. [F8, F16]
- `AF_ALG` scatterlist and socket memory: `sock_kmalloc()` allocations must be freed with `sock_kfree_s()`/`sock_kzfree_s()` using exact sizes (`struct_size(sgl, sg, MAX_SGL_ENTS + 1)`, `areq->tsgl_entries * sizeof(*tsgl)`, `areq->areqlen`), skipping `sock_kfree_s()` when `rsgl == &areq->first_rsgl` and `kvfree()` when `sgl->sgt.sgl == sgl->sgl`. Before `extract_iter_to_sg()` populates an `af_alg_sgl`, `sgl.need_unpin = iov_iter_extract_will_pin(&msg->msg_iter)` must be set; in `af_alg_get_rsgl()`, `rsgl->sgl.{need_unpin,sgt}` and `rsgl->sg_num_bytes = 0` (on error) must be initialized whenever `rsgl` is on `areq->rsgl_list`; in `hash_sendmsg()`, errors before `ctx->sgl` is initialized in the loop must jump to `unlock_free_result`, not `unlock_free`. [F11, F14, F124, F125, F167]
- `crypto_acomp_{compress,decompress}()` and `crypto_ahash_{init,update,finup,digest}()` reject `CRYPTO_TFM_REQ_ON_STACK` requests when the transform is async unless cloned via `crypto_request_clone()`, and `ahash_request_free()` must not `kfree()` on-stack requests. `acomp_request_clone()` must rebase `nreq->src` and `nreq->dst` to `&nreq->chain.{ssg,dsg}` when they pointed to `req->chain.{ssg,dsg}`. [F116, F117]
- In `cryptd`, `ctx->refcnt` is only incremented/decremented when non-zero, must be read before `*_request_complete()` (which may free a zero-refcnt `tfm`), and must not be decremented when `err == -EINPROGRESS`. `cryptd_{skcipher,ahash,aead}_child()` returns a borrowed pointer owned by the parent `cryptd` transform. In `cryptd_exit()`, `destroy_workqueue(cryptd_wq)` must run before `cryptd_fini_queue(&queue)`. [F176, F177, F195]

## API Contracts
- Residual byte returns: for `CRYPTO_AHASH_ALG_BLOCK_ONLY` algorithms (`cbcmac`, `cmac`, `ghash`, and block-only `ahash` drivers), `.update` returns the non-negative unconsumed residual byte count (`< bs`) on success (which `ahash_update_finish()` buffers) or negative errno. In `crypto/cbc.c` and `crypto/ecb.c`, lskcipher `encrypt`/`decrypt` return the residual byte count `rem` when `!(flags & CRYPTO_LSKCIPHER_FLAG_FINAL)` and `-EINVAL` when `CRYPTO_LSKCIPHER_FLAG_FINAL` is set. `crypto_hash_walk_{first,done}()` return a positive byte count, 0, or negative errno (must be stored in a signed `int` and passed to `crypto_hash_walk_done()` on error to unmap). `crypto_akcipher_sync_decrypt()` returns the positive decrypted length `data.dlen`, unlike `crypto_akcipher_sync_encrypt()` which returns 0. [F39, F40, F52, F225, F226]
- Template contracts: `crypto_attr_alg_name()` returns an `ERR_PTR` on invalid input (accepted directly by `crypto_grab_spawn()`). Templates using `crypto_alg_mod_lookup()` for an auxiliary algorithm (like `essiv_create()`) must pass `crypto_algt_inherited_mask(algt)` and OR `alg->cra_flags & CRYPTO_ALG_INHERITED_FLAGS` into the instance. Templates built with `lskcipher_alloc_instance_simple()` passing `NULL` state to `crypto_lskcipher_{encrypt,decrypt}()` must reject non-zero `inst->alg.co.statesize`. Template `.setkey` callbacks must sync `CRYPTO_TFM_REQ_MASK` from parent to child transforms, and import callbacks in `hmac.c` and `cryptd.c` must bind `desc->tfm` or `ahash_request_set_tfm()` before calling child import. [F44, F243, F333, F335, F338]

## Error Handling
- In `ahash_do_req_chain()`, before invoking the synchronous fallback transform on a virtual-address request, it must verify `crypto_ahash_statesize(tfm) <= HASH_MAX_STATESIZE`, `crypto_ahash_need_fallback(tfm)`, and `!crypto_hash_no_export_core(tfm)`, and must restore `ahash_request_set_tfm(req, tfm)` before returning. In `hmac_{update,finup}_ahash()`, `ahash_request_isvirt(preq)` must be checked to call `ahash_request_set_virt(..., preq->svirt)` vs `ahash_request_set_crypt(..., preq->src)`. [F37, F228]
- In `essiv_aead_crypt()`, `rctx->assoc` must be initialized to `NULL` before branching, and freed synchronously only when `err != -EINPROGRESS && err != -EBUSY` (or in `essiv_aead_done()` when `err != -EINPROGRESS`). Similarly, in async continuation callbacks that preserve `CRYPTO_TFM_REQ_MAY_BACKLOG` (`hmac_finup_done()`, `crypto_cts_{encrypt,decrypt}_done()`, `async_done_continue()`), the parent request must not be completed when the continuation returns either `-EINPROGRESS` or `-EBUSY`. [F224, F284]

## Known Pitfalls
- In `hash_walk_new_entry()` and the `CONFIG_HIGHMEM` path of `shash_ahash_digest()`, `sg->offset` must be normalized with `offset_in_page()` (after advancing `page` by `offset >> PAGE_SHIFT`) before computing `PAGE_SIZE - offset`. In `_aead_recvmsg()`, `aead_sufficient_data()` must be checked before subtracting `as` or `ctx->aead_assoclen` from `used`, and `used >= outlen - usedpages` must be checked when `usedpages < outlen`. [F73, F81]
- Request/context offsets and sizing: `crypto_akcipher_sync_prep()` must size its bounce buffer to `mlen = max(data->slen, data->dlen)`, check `sizeof(*req) + reqsize + mlen < mlen` for overflow, and offset `data->buf` by `(u8 *)(req + 1) + reqsize`. In `crypto_rfc{4106,4543,4309}_crypt()` and `crypto_cts_reqctx_space()`, the scratch space past `subreq` must be offset by the child's `reqsize`, never the parent's. In `crypto_{ccm,gcm}_req_priv_ctx` and `hctr2_request_ctx`, hash and skcipher subrequests share union `u` and must be strictly serialized. In `hmac_setkey_ahash()`, `HASH_REQUEST_ON_STACK(req, fb)` must bind to `fb = crypto_ahash_fb(tctx->hash)`, not the async `tctx->hash`. [F85, F122, F229, F287, F292]
- State and IV preservation across in-place operations: in `crypto_arc4_crypt()`, `crypto_lskcipher_ctx(tfm)` must not be mutated directly (copy to per-request `siv` when `!(flags & CRYPTO_LSKCIPHER_FLAG_CONT)`). In `crypto_cts_decrypt()` (`nbytes > bsize`), the IV for the final two blocks must be copied into `crypto_cts_reqctx_space(req)` before `crypto_skcipher_decrypt(subreq)`. In `echainiv_encrypt()`, `nseqno` at `info + ivsize - 8` (`info = req->iv`) must be read before zeroing `info`, copying to `req->dst`, and overwriting `info`. In `crypto_ccm_decrypt()`, `req->iv` (counter zeroed) must be copied into `pctx->idata` for CTR decryption so `req->iv` is preserved for `crypto_ccm_auth()`. [F71, F245, F246, F247]
