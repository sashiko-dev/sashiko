# FIRMWARE LOADER (request_firmware)

The firmware loader subsystem (`drivers/base/firmware_loader/`, `include/linux/firmware.h`, and `rust/kernel/firmware.rs`) provides synchronous and asynchronous APIs to load device firmware from built-in kernel sections, direct VFS paths (with optional XZ and ZSTD decompression), EFI platform firmware, or a userspace sysfs fallback. It also manages device-bound firmware caching across suspend/resume cycles, provides a sysfs-driven firmware upload framework (`firmware_upload_register`), and exposes safe Rust bindings (`Firmware` and `ModInfoBuilder`).

## Architecture & Data Flow
- On failure (`ret < 0`), `_request_firmware()` must set `*firmware_p = NULL`, and `assign_fw()` must reject `fw_priv->size == 0` with `-ENOENT`, because C and Rust callers (`request_firmware_work_func()`, `Firmware::request_internal()`, `Firmware::data()`) rely on `*firmware_p` being non-NULL with a non-zero `size` and non-NULL `data` if and only if the request returns `0`. [F44, F71]
- Rust's `FwFunc` must only wrap C functions matching the contract of `request_firmware*` (returning `0` only when initializing an owning, non-null `bindings::firmware` pointer), and `Firmware` must maintain exclusive, immutable ownership of its `data` buffer until `Drop` calls `bindings::release_firmware`. [F96, F97]
- In `alloc_lookup_fw_priv()`, requests with `FW_OPT_NOCACHE` or `FW_OPT_PARTIAL` must not look up existing `fw_priv` instances via `__lookup_fw_priv()`, and `FW_OPT_NOCACHE` requests must not add `tmp->list` to `fwc->head` (while still calling `INIT_LIST_HEAD(&tmp->list)` so `list_del()` in `__free_fw_priv()` is a no-op). [F48]
- For paged buffers (`fw_priv->is_paged_buf`), `fw_priv->data` must remain `NULL` during writes and only be mapped via `fw_map_paged_buf()` at load completion, because `firmware_data_read()` and `firmware_data_write()` test `fw_priv->data` to distinguish pre-allocated buffers from paged buffers. [F52]
- In `struct fw_priv`, `page_array_size` and `nr_pages` count `struct page *` elements whereas `size` and `allocated_size` count bytes: `fw_grow_paged_buf()` must scale `kvmalloc_array()`, `memcpy()`, and the tail `memset()` at `&new_pages[fw_priv->page_array_size]` by `sizeof(void *)`, and only increment `fw_priv->nr_pages` after each `alloc_page()` succeeds. [F51, F89]
- `fw_free_paged_buf()` must unmap `fw_priv->data`, free `fw_priv->pages[0..nr_pages - 1]` and `fw_priv->pages`, and reset `pages`, `page_array_size`, `nr_pages`, `data`, and `size` to `NULL`/`0` because the same `fw_priv` is reused across decompression retries, `loading = 1` restarts, or subsequent uploads. [F50]
- `struct fw_sysfs` is shared between sysfs fallback (`fw_upload_priv == NULL`) and firmware upload (`fw_upload_priv != NULL`, `fw == NULL`), so `fw_dev_release()`, `firmware_loading_store()`, `fw_upload_is_visible()`, and `fw_upload_start()` must check `fw_sysfs->fw_upload_priv`; because upload reuses a persistent `fw_sysfs->fw_priv`, every upload end or abort path (`firmware_loading_store()` case `-1`/default, `fw_upload_start()` when `!fw_priv->size`, and `fw_upload_main()` exit) must free paged buffers and call `fw_state_init(fw_sysfs->fw_priv)` under `fw_lock`. [F37, F56]
- `fw_upload_set_error()` must record `fwlp->err_progress = fwlp->progress` alongside `fwlp->err_code` under `fwlp->lock`, and `fw_upload_main()` must leave `err_code`, `err_progress`, and `remaining_size` intact when setting `progress = FW_UPLOAD_PROG_IDLE`, resetting them only in `fw_upload_start()` when the next upload begins. [F57]
- In `fw_load_sysfs_fallback()`, `dev_set_uevent_suppress(f_dev, true)` must be set before `device_add(f_dev)` and only cleared before `kobject_uevent(&fw_sysfs->dev.kobj, KOBJ_ADD)` after `fw_priv->pending_list` is linked onto `pending_fw_head` under `fw_lock` and `FW_OPT_UEVENT` is verified. [F100]
- In `fw_run_sysfs_fallback()` and `fw_force_sysfs_fallback()`, `fw_fallback_config.ignore_sysfs_fallback` and `FW_OPT_NOFALLBACK_SYSFS` must be checked before `fw_fallback_config.force_sysfs_fallback` and `FW_OPT_USERHELPER` so disabling sysfs fallback takes precedence. [F77]
- `device_cache_fw_images()` must pair `fw_fallback_set_cache_timeout()` with `fw_fallback_set_default_timeout()`, and `fw_cache.state` must be reset to `FW_LOADER_NO_CACHE` in both `fw_suspend()` and the `PM_POST_*` cases of `fw_pm_notify()` in case suspend aborts before syscore. [F59]

## Synchronization
- `free_fw_priv()` must acquire `fw_priv->fwc->lock` before calling `kref_put(&fw_priv->ref, __free_fw_priv)`, `__free_fw_priv()` must unlink `fw_priv->list` while holding `fwc->lock` and then release `fwc->lock` before freeing buffers, and `free_fw_priv()` must unlock `fwc->lock` only when `kref_put()` returns 0. [F3]
- `__allocate_fw_priv()` must initialize `fw_priv->pending_list` with `INIT_LIST_HEAD()`, and any transition to `FW_STATUS_DONE` or `FW_STATUS_ABORTED` must go through `__fw_state_set()` (`fw_state_done()`, `fw_state_aborted()`, `__fw_load_abort()`) while holding `fw_lock` whenever `fw_priv` may be on `pending_fw_head`, so `list_del_init(&fw_priv->pending_list)` and `complete_all()` run safely in lockstep. [F15, F43, F49]
- In `fw_load_sysfs_fallback()`, after `device_add()` and acquiring `fw_lock`, `fw_load_abort_all` and `fw_state_is_aborted(fw_priv)` must be checked before `list_add(&fw_priv->pending_list, &pending_fw_head)` so an already-aborted `fw_priv` is never linked onto `pending_fw_head`. [F16]
- All firmware load paths (`fw_get_filesystem_firmware()`, `firmware_fallback_platform()`, and `firmware_loading_store()`) must finish populating `fw_priv->data` (including `fw_map_paged_buf()`) and `fw_priv->size` before calling `fw_state_done()`, which wakes batched waiters in `_request_firmware_prepare()`. [F19]
- `fw_upload_start()` must be called with `fw_lock` held and acquires `fwlp->lock` inside `fw_lock` (fixing the lock order `fw_lock` -> `fwlp->lock`); under both locks it must verify `fwlp->progress == FW_UPLOAD_PROG_IDLE`, set `FW_UPLOAD_PROG_RECEIVING`, populate `fwlp->data` and `fwlp->remaining_size`, and call `get_device(fw_dev->parent)` before calling `queue_work(system_long_wq, &fwlp->work)`. [F27, F114]
- `fw_upload_main()` must not hold `fwlp->lock` across `fwlp->ops->prepare()`, `write()`, `poll_complete()`, or `cleanup()`, because `cancel_store()` and `firmware_upload_unregister()` acquire `fwlp->lock` on another thread to call `fwlp->ops->cancel()`. [F22]
- Every `fw_cache_entry` on `fw_cache.fw_names` must hold one reference on its `fw_priv`: `fw_cache_piggyback_on_request()` must call `kref_get(&fw_priv->ref)` before releasing `fwc->name_lock`, `cache_firmware()` must call `kfree(fw)` rather than `release_firmware(fw)` to retain the reference, and `__async_dev_cache_fw_image()` must unlink and free the entry if `cache_firmware()` fails. [F17, F58]
- `alloc_fw_cache_entry()` and `dev_create_fw_entry()` run under `fwc->name_lock` or `dev->devres_lock` and must use `GFP_ATOMIC`; in `__device_uncache_fw_images()`, `fwc->fw_names` must be drained with a `while (!list_empty(&fwc->fw_names))` loop that unlinks one `fw_cache_entry` and drops `fwc->name_lock` before calling `uncache_firmware()`, which may sleep in `vunmap()`/`vfree()`. [F83, F110, F112]
- `device_cache_fw_images()` must call `cancel_delayed_work_sync(&fwc->work)` before starting firmware caching and must release `fw_lock` before calling `async_synchronize_full_domain(&fw_cache_domain)`. [F23]
- In `fw_load_sysfs_fallback()` and `firmware_upload_register()`, `fw_sysfs->fw_priv` and `fw_sysfs->fw_upload_priv` must be initialized before `device_add(&fw_sysfs->dev)`, and `fw_sysfs_wait_timeout()` and `device_del(f_dev)` must be called without holding `fw_lock` because sysfs attribute handlers acquire `fw_lock`. [F24, F117]

## Object Lifetimes
- `release_firmware()` must check `!firmware_is_builtin(fw)` before calling `firmware_free_data(fw)` (which calls `vfree(fw->data)` whenever `!fw->priv`), and callers of `firmware_request_builtin()` must never pass their caller-owned `struct firmware` to `release_firmware()` because it unconditionally calls `kfree(fw)`. [F1, F55]
- When `fw_priv->data` is pre-allocated by the caller (`fw_priv->allocated_size != 0`), loading helpers (`firmware_fallback_platform()`, `fw_decompress_zstd()`, `fw_decompress_xz()`, and `fw_get_filesystem_firmware()`) must write into `fw_priv->data` within `fw_priv->allocated_size` without replacing `fw_priv->data` or freeing it on error. [F5]
- In `fw_load_sysfs_fallback()`, if `device_add(f_dev)` fails after `device_initialize(f_dev)`, cleanup must jump directly to `put_device(f_dev)` without calling `device_del(f_dev)` or `kfree(fw_sysfs)`, whereas after `device_add(f_dev)` succeeds, both `device_del(f_dev)` and `put_device(f_dev)` must be called; when `fw_sysfs->fw_upload_priv` is non-NULL, `fw_dev_release()` must call `fw_upload_free()` to release `fw_priv`, `fw_upload`, and `fw_upload_priv` before `kfree(fw_sysfs)`. [F10, F11]
- `fw_upload_main()` must release the parent device reference taken by `fw_upload_start()` via `put_device(fw_dev->parent)`, call `fw_free_paged_buf()`, clear `fwlp->data = NULL`, and call `fw_upload_prog_complete()` on every exit path, while invoking `fwlp->ops->cleanup()` only if `fwlp->ops->prepare()` succeeded. [F14]
- `firmware_upload_unregister()` must check `fw_upload_priv->progress` under `fw_upload_priv->lock`, invoke `fw_upload_priv->ops->cancel(fw_upload)` if non-idle, and call `flush_work(&fw_upload_priv->work)` after unlocking before calling `device_unregister(&fw_sysfs->dev)` and `module_put(module)`. [F102]
- In `dev_cache_fw_image()`, `todo` must be iterated with `list_for_each_entry_safe()`, and when `__fw_entry_found(fce->name)` is true, `fce` must be set to `NULL` after `free_fw_cache_entry(fce)` so `async_schedule_domain()` is not called on a freed entry. [F82]

## API Contracts
- `alloc_lookup_fw_priv()` and `_request_firmware_prepare()` use tri-state returns: `alloc_lookup_fw_priv()` returns `1` when batching onto an existing `fw_priv`, `0` when allocating a new one, and `< 0` on error; `_request_firmware_prepare()` returns `0` when firmware is already assigned, `1` when the caller must load it, and `< 0` on error. [F28, F29]
- All callers of `fw_add_devm_name()` (`assign_fw()` and `firmware_request_cache()`) must hold `fw_lock`, and `fw_add_devm_name()` must return `0` if `fw_cache_is_setup(dev, name)` is already true; `assign_fw()` must only call it when `FW_OPT_UEVENT` is set and `FW_OPT_NOCACHE` is clear (releasing `fw_lock` on error), and `request_firmware_into_buf()`, `request_partial_firmware_into_buf()`, and `_request_firmware_nowait()` with `!uevent` must return `-EOPNOTSUPP` if `fw_cache_is_setup()` is true. [F26, F31, F60]
- `__allocate_fw_priv()` requires a non-NULL `dbuf` when `FW_OPT_PARTIAL` is set and forbids a non-zero `offset` without `FW_OPT_PARTIAL`; when loading into a preallocated buffer, `fw_get_filesystem_firmware()` bounds `msize` to `fw_priv->allocated_size` (passing `file_size_ptr` only when `FW_OPT_PARTIAL` is set), and `fw_copy_to_prealloc_buf()` and `firmware_fallback_platform()` must verify buffer capacity before `memcpy()`. [F46, F64, F66]
- In `struct fw_upload_ops`, `prepare`, `write`, `poll_complete`, and `cancel` are validated non-NULL in `firmware_upload_register()` while `cleanup` is optional (`if (fwlp->ops->cleanup)`); in `fw_upload_main()`, `ops->write()` receives the unshifted base pointer `fwlp->data`, cumulative `offset`, and `fwlp->remaining_size`, and on returning `FW_UPLOAD_ERR_NONE` must set `*written` in `1..=size` while `fw_upload_main()` advances `offset` and decrements `fwlp->remaining_size` without advancing `fwlp->data`. [F38, F73, F90]

## Error Handling
- In `_request_firmware()`, secondary lookups (`fw_decompress_zstd`, `fw_decompress_xz`, `firmware_fallback_platform()`) and `firmware_fallback_sysfs()` must be gated on `!(opt_flags & FW_OPT_PARTIAL)`; each secondary lookup must only run when the preceding lookup returned `-ENOENT`, whereas `firmware_fallback_sysfs()` runs on any non-zero `ret` and must return `ret` unchanged when sysfs fallback is disabled or skipped. [F39, F78, F79]
- `fw_run_sysfs_fallback()` returns `bool` and must explicitly check `if (ret < 0) return false;` on `int`-returning hooks like `security_kernel_load_data()` instead of returning `ret` directly (which converts negative errnos to `true`). [F30]
- `fw_decompress_zstd()` must check the `size_t` return value of `zstd_decompress_dctx()` with `zstd_is_error(len)` before assigning `len` to `fw_priv->size`; when `fw_priv->allocated_size == 0`, it must validate the frame header with `zstd_get_frame_header()` and reject `ZSTD_CONTENTSIZE_UNKNOWN` with `-EINVAL` before calling `vzalloc(out_size)`. [F34, F67]

## External Contracts
- Non-VFS firmware loading paths (`firmware_fallback_platform()`, `fw_run_sysfs_fallback()`, and `firmware_loading_store()`) must validate loads with `security_kernel_load_data(LOADING_FIRMWARE, true)` before loading and `security_kernel_post_load_data(..., LOADING_FIRMWARE, ...)` before marking `fw_priv` done. [F129]
- In sysfs binary attribute handlers, `firmware_data_read()` must return `0` when `offset > fw_priv->size` before subtracting `offset` from `fw_priv->size`, and `firmware_data_write()` must require `capable(CAP_SYS_RAWIO)` (returning `-EPERM` otherwise) and reject `offset + count > fw_priv->allocated_size` with `-ENOMEM` when writing to a preallocated buffer (`fw_priv->data != NULL`). [F131, F134]

## Known Pitfalls
- In `fw_get_filesystem_firmware()`, `fw_path[0]` (`fw_path_para`) must be formatted with `%.*s` bounded at `'\n'` into the `PATH_MAX` buffer (returning `-ENAMETOOLONG` if `len >= PATH_MAX`); when `decompress` is non-NULL, the loop over `fw_path` must reset `buffer = NULL` after `vfree(buffer)` and call `fw_free_paged_buf(fw_priv)` if `decompress()` fails before continuing to the next path. [F53, F94]
- In `firmware_loading_store()`, writing `0` when `fw_state_is_loading(fw_priv)` is false must fall through to the `default`/`-1` cases to call `fw_load_abort(fw_sysfs)`, and `kill_pending_fw_fallback_reqs()` must iterate `pending_fw_head` with `list_for_each_entry_safe()` because `__fw_load_abort()` unlinks `fw_priv->pending_list`. [F80, F81]
- Because `fw_grow_paged_buf()` allocates `fw_priv->pages[]` with `__GFP_HIGHMEM`, unmapped page accesses must use highmem-safe helpers (`kmap_local_page()`/`kunmap_local()` or `memcpy_from_page()`/`memcpy_to_page()`), and `fw_map_paged_buf()` maps `fw_priv->data` read-only (`PAGE_KERNEL_RO`); `fw_realloc_pages()` must round `min_size` up with `PAGE_ALIGN(min_size) >> PAGE_SHIFT`, and `firmware_rw()` must clamp per-page bytes via `min_t(size_t, PAGE_SIZE - page_ofs, count)` before narrowing to `int`. [F86, F87, F120]
