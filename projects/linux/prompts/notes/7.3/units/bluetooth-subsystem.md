# BLUETOOTH SUBSYSTEM

This subsystem implements Bluetooth HCI event packet processing (`hci_event.c`), the `PF_BLUETOOTH`/`BTPROTO_HCI` socket layer (`hci_sock.c`), the Bluetooth Management (`mgmt`) protocol interface (`mgmt.c`, `mgmt_util.c`, `mgmt_config.c`), and the Microsoft vendor-specific HCI extension (`msft.c`). It processes controller events and command responses, updates `hci_dev` and `hci_conn` state, exposes raw, user, monitor, control, and logging socket channels, dispatches userspace management commands and asynchronous events, and manages controller-offloaded LE advertisement monitoring.

## Architecture & Data Flow
- Before accessing `conn->iso_qos.ucast` (which shares a union with `conn->iso_qos.bcast` in `struct bt_iso_qos`), event handlers looking up or iterating connections by handle (`hci_unbound_cis_failed`, `hci_le_cis_established_evt`) must verify `conn->type == CIS_LINK` rather than inferring unicast ISO from `conn->dst`. [F42]
- In `hci_le_big_sync_established_evt` (when `!ev->status`), each BIS `hci_conn` must have `bis->state = BT_CONNECTED`, `HCI_CONN_BIG_SYNC` set in `bis->flags`, and `hci_debugfs_create_conn(bis)` and `hci_conn_add_sysfs(bis)` called before `hci_iso_setup_path(bis)`. In `hci_le_big_info_adv_report_evt`, update `pa_sync->iso_qos.bcast.encryption` from `ev->encryption` before `hci_connect_cfm(pa_sync, 0)`. [F47, F52]
- In `hci_cc_read_buffer_size` and `hci_cc_le_read_buffer_size*`, return `HCI_ERROR_INVALID_PARAMETERS` if `!hdev->acl_mtu || !hdev->acl_pkts` or `hdev->le_mtu && hdev->le_mtu < HCI_MIN_LE_MTU`, and initialize `*_cnt` credits whenever `*_pkts` are set. In `hci_num_comp_pkts_evt` and `hci_cc_delete_stored_link_key`, clamp `conn->sent` and `hdev->stored_num_keys` to 0 on underflow, and clamp `hdev->*_cnt` to `hdev->*_pkts`. [F54, F70, F103]
- In `hci_cc_read_local_ext_features` and `hci_remote_ext_features_evt`, check `page < HCI_MAX_PAGES` before indexing `features[page]`, and do not update `hdev->max_page` when `HCI_QUIRK_BROKEN_LOCAL_EXT_FEATURES_PAGE_2` is set. [F71, F116]
- In `le_set_scan_enable_complete`, `LE_SCAN_ENABLE` must only call `clear_pending_adv_report(hdev)` and `hci_discovery_set_state(hdev, DISCOVERY_FINDING)` when `hdev->le_scan_type == LE_SCAN_ACTIVE`, and `LE_SCAN_DISABLE` must cancel `hdev->le_scan_disable` and flush any pending report via `mgmt_device_found`. [F53]
- When disabling a single extended advertising set (`hci_cc_le_set_ext_adv_enable` with `cp->num_of_sets != 0`, `hci_le_ext_adv_term_evt`), do not clear `HCI_LE_ADV` if any `adv_info` in `hdev->adv_instances` has `adv->enabled`. Check `list_empty(&hdev->adv_instances)` before calling `hci_disable_advertising_sync` in `mesh_send_done_sync` or `remove_advertising_sync`, and call `cancel_adv_timeout(hdev)` whenever `hdev->cur_adv_instance` is modified or expired. [F59, F186, F200]
- In `hci_mgmt_cmd` and `hci_logging_frame`, verify `skb->len >= sizeof(*hdr)` (or `+ 3`) before unsigned subtraction. For `HCI_MGMT_VAR_LEN` handlers in `mgmt.c`, `hci_mgmt_cmd` only checks `len >= handler->data_len`, so handlers must validate exact payload sizes: array commands must bound count by `(U16_MAX - sizeof(*cp)) / sizeof(elem)` and check `struct_size == len`, while `add_advertising` and `add_ext_adv_data` must verify `data_len == sizeof(*cp) + cp->adv_data_len + cp->scan_rsp_len` and `tlv_data_is_valid`. [F76, F77, F102, F203, F208, F268]
- In `mgmt_connect_failed`, if `test_and_clear_bit(HCI_CONN_MGMT_CONNECTED, &conn->flags)` succeeds, call `mgmt_device_disconnected` instead of emitting `MGMT_EV_CONNECT_FAILED`. Because `read_ext_controller_info` and `read_ext_index_list` replace legacy CoD/name/index event flags on `sk`, every path updating CoD, local name, or `hdev->appearance` must call `ext_info_changed`, and `mgmt_index_added`/`removed` must emit both legacy and extended index events (skipping `HCI_QUIRK_RAW_DEVICE`). [F185, F194, F195, F252, F272]
- `mgmt_mesh_foreach`, `mgmt_mesh_next`, and `mgmt_mesh_find` must iterate `&hdev->mesh_pending` (never `&hdev->mgmt_pending`), and `mesh_send_complete` must call `mgmt_mesh_remove(mesh_tx)` on every non-NULL `mesh_tx`. In `mgmt_adv_monitor_device_found`, `hdev->advmon_pend_notify` is cleared before iterating `hdev->monitored_devices` and must be set back to `true` if any entry has `!dev->notified` (do not `break` early on a `bdaddr` match). [F201, F220, F225, F229]

## Synchronization
- Lock hierarchy: `lock_sock(sk)` -> `{mgmt_chan_list_lock, hdev->lock, hci_dev_list_lock, hci_sk_list.lock}`; `hdev->req_lock` (`hci_req_sync_lock`) -> `hdev->lock` (`hci_dev_lock`) -> `{msft->filter_lock, hdev->mgmt_pending_lock}`. `hci_sock_ioctl` must drop `lock_sock(sk)` before calling unbound device ioctls (`hci_dev_open/close/reset/cmd`, `hci_inquiry`), and neither `hdev->lock` nor `msft->filter_lock` may be held across blocking `__hci_cmd_sync` calls. [F127, F168, F259]
- All allocations under `read_lock(&hci_sk_list.lock)` or `read_lock(&hci_dev_list_lock)` in `hci_sock.c` and `mgmt.c` must use `GFP_ATOMIC`, and `mgmt_cmd_complete` (which uses `GFP_KERNEL`) must only be called after `read_unlock(&hci_dev_list_lock)`. [F126, F257]
- Callbacks in `hci_ev_table`, `hci_le_ev_table`, `hci_cc_table`, and `hci_cs_table` enter unlocked and must release any `hci_dev_lock(hdev)` they acquire. `check_pending_le_conn`, `process_adv_report`, and `hci_unbound_cis_failed` require `hci_dev_lock(hdev)`, and because `hci_conn_hash_lookup_*` drops `rcu_read_unlock()` before returning an unreferenced `hci_conn *`, event handlers like `hci_num_comp_pkts_evt` must hold `hci_dev_lock(hdev)` across lookup and `hci_conn_tx_dequeue`. [F12, F22, F23]
- Loops over `hdev->conn_hash.list` or `hdev->adv_instances` that delete entries must use `list_for_each_entry_safe` under `hdev->lock`. When iterating BIS `hci_conn` entries in `hci_le_create_big_complete_evt` or `hci_le_big_sync_lost_evt` to call functions that sleep or mutate `conn_hash.list` (`hci_debugfs_create_conn`, `hci_conn_del`), hold `hci_dev_lock(hdev)` and loop on `hci_conn_hash_lookup_big_state` instead of `list_for_each_entry_rcu`. [F93, F121]
- In `hci_sock_bind`, initialize `hci_pi(sk)->channel`, `hdev`, flags, and `mtu` under `lock_sock(sk)` before setting `sk->sk_state = BT_BOUND`. Serialize all `mgmt_chan_list` accesses and `hci_mgmt_cmd(chan, sk, skb)` execution under `mgmt_chan_list_lock`. [F15, F128]
- In `mgmt.c`, `hci_cmd_sync` work callbacks for `hdev->mgmt_pending` commands must verify `__mgmt_pending_listed` under `hdev->mgmt_pending_lock` and copy needed `cmd->param`/`user_data` before unlocking (returning `-ECANCELED` if unlinked), while completion callbacks must return immediately before `hci_dev_lock(hdev)` or accessing `cmd` if `err == -ECANCELED` or `!mgmt_pending_valid(hdev, cmd)`, and then call `mgmt_pending_free(cmd)`. [F160, F161]
- Asynchronous `hci_cmd_sync` workers must read parameters from `cmd->param` (e.g., `set_name_sync`) rather than `hdev` fields modified after `hci_cmd_sync_queue`, and must re-lookup `hci_conn_params` or `hci_conn` by address (`add_device_complete`, `disconnect_sync`, `unpair_device_sync`, `get_conn_info_sync`, `get_clock_info_sync`) rather than caching pointers or flags across the lock drop. [F163, F188]
- `mgmt_pending_foreach` callbacks run under `hdev->mgmt_pending_lock` and must not call `mgmt_pending_find/add/remove/listed/valid` or `hci_dev_lock` on `hdev`. In `set_powered`, powering off (`cp->val == 0x00`) must call `hci_cmd_sync_cancel_sync(hdev, -EHOSTDOWN)` before queueing `set_powered_sync`. [F261, F262]
- Before sending `HCI_OP_READ_ENC_KEY_SIZE` in `hci_read_enc_key_size`, pre-populate `conn->enc_key_size`, and in `hci_cc_read_enc_key_size` reject smaller key sizes by clearing `HCI_CONN_ENCRYPT` and `HCI_CONN_AES_CCM` and setting `status = HCI_ERROR_AUTH_FAILURE`. In `hci_conn_complete_evt` and `le_conn_complete_evt`, verify `conn->state == BT_CONNECT` on any looked-up `HCI_ROLE_MASTER` connection. [F16, F17, F55]

## Object Lifetimes
- When `check_pending_le_conn` starts an implicit auto-connection (`!params->explicit_connect`), it stores `hci_conn_get(conn)` in `params->conn` which `le_conn_complete_evt` must release via `hci_conn_drop`, `hci_conn_put`, and `params->conn = NULL`. In `pair_device`, call `hci_conn_drop(conn)` on error before `cmd->user_data = hci_conn_get(conn)`, after which `pairing_complete` must clear `connect/security/disconn_cfm_cb` and call both `hci_conn_drop` and `hci_conn_put`. [F2, F150]
- In `hci_sock_bind`, if `hci_pi(sk)->hdev` has `HCI_UNREGISTER` set, clear `hci_pi(sk)->hdev = NULL`, reset `sk->sk_state = BT_OPEN`, and call `hci_dev_put(hdev)` before checking `BT_BOUND`. On `HCI_CHANNEL_USER` bind failure after `hci_dev_open` (`!= -EALREADY`), clear `HCI_USER_CHANNEL`, call `mgmt_index_added(hdev)`, and `hci_dev_put(hdev)`. In `hci_sock_release` for `HCI_CHANNEL_USER`, only call `hci_dev_do_close`, clear `HCI_USER_CHANNEL`, and call `mgmt_index_added` if `!hci_dev_test_flag(hdev, HCI_UNREGISTER)`, while always decrementing `hdev->promisc` and calling `hci_dev_put(hdev)`. [F4, F5, F119]
- `hci_event_packet` owns `skb` and frees it at `done:`, so event and CC callbacks must never call `kfree_skb(skb)`. In `hci_sock.c`, `hci_send_to_sock` and `hci_send_to_monitor` must unshare and reserve headroom with `__pskb_copy_fclone` before `skb_push`, and `sock_queue_rcv_skb` callers must call `kfree_skb(skb)` on non-zero return. [F14, F135, F137]
- `mgmt_alloc_skb` reserves `sizeof(struct mgmt_hdr)` headroom and sets `bt_cb(skb)->mgmt`; `mgmt_send_event_skb` (and `mgmt_event_skb`) requires this headroom and unconditionally consumes `skb` via `kfree_skb(skb)`, whereas `mgmt_send_adv_monitor_device_found` borrows `skb` and must run before `mgmt_event_skb` pushes `struct mgmt_hdr`. [F145, F235, F265]
- `mgmt_pending_new` allocates an unlinked `mgmt_pending_cmd` freed with `mgmt_pending_free`, whereas `mgmt_pending_add` links it onto `hdev->mgmt_pending` so it must be unlinked via `mgmt_pending_remove` or `mgmt_pending_valid` before `mgmt_pending_free`. When `mgmt_pending_foreach` has `remove = true`, it unlinks and frees `cmd` itself, so its callback and `cmd->cmd_complete` must never call `mgmt_pending_remove` or `mgmt_pending_free`. [F146, F148]
- `settings_rsp` and `sk_lookup` call `sock_hold(match->sk)` when `match->sk == NULL`, so callers must initialize `match.sk = NULL` and call `sock_put(match.sk)` if non-NULL. In `mgmt_cleanup`, iterate `hci_dev_list` under `read_lock(&hci_dev_list_lock)` and pass `silent = true` to `mesh_send_complete` so `mgmt_mesh_remove` unlinks `mesh_tx` and drops `mesh_tx->sk` without allocating under the rwlock. [F149, F158]
- `__add_adv_patterns_monitor` and `msft_le_monitor_advertisement_cb` must call `hci_free_adv_monitor(hdev, monitor)` on error, whereas `msft_le_cancel_monitor_advertisement_cb` must call `hci_free_adv_monitor` and `msft_monitor_device_del` only when `!msft->suspending`. Because `msft_do_close` frees all `msft->address_filters` locally when `HCI_UP` is cleared, `msft_add/cancel_address_filter_sync` must check `hdev->msft_data` and `test_bit(HCI_UP, &hdev->flags)` before dereferencing `address_filter`, and `msft_remove_addr_filters_sync` must set an `AF_STATE_ADDING` filter to `AF_STATE_REMOVING` without freeing it. [F151, F155, F156, F170, F171, F246]

## API Contracts
- `hci_hdev_from_sock(sk)` returns a borrowed `hci_dev *`, `ERR_PTR(-EBADFD)`, or `ERR_PTR(-EPIPE)` (never NULL); callers must hold `lock_sock(sk)`, check `IS_ERR(hdev)`, and never call `hci_dev_put(hdev)`. In `hci_sock_sendmsg`, `hci_logging_frame` and `hci_mgmt_cmd` borrow `skb` and must jump to `drop:`, whereas `HCI_CHANNEL_RAW` and `HCI_CHANNEL_USER` queue `skb` on success; in `hci_mgmt_cmd`, `hdev` from `hci_dev_get` is optional (`if (hdev && chan->hdev_init)`) and owned by `hci_mgmt_cmd` (jump to `done:` for `if (hdev) hci_dev_put(hdev)`). [F6, F7, F8, F20, F30, F33]
- `hci_event_func`, `hci_le_meta_evt`, and `hci_cc_func` only pull `min_len` (`sizeof(*ev)`) bytes, so variable-length handlers must pull trailing bytes via `hci_ev_skb_pull`, `hci_cc_skb_pull`, or `hci_le_ev_skb_pull` (using `flex_array_size` rather than `struct_size`, and in `hci_le_adv_report_evt` / `hci_le_ext_adv_report_evt` pulling `sizeof(*info)` then `info->length + 1` or `info->length` per entry) and check for NULL. `hci_sent_cmd_data` also returns NULL on mismatch. [F37, F39, F66, F105, F106]
- `hci_cc_table` callbacks and `hci_conn_set_handle()` return a `u8` HCI status (`0x00` or `HCI_ERROR_*`, never a negative errno), and connection-complete handlers must abort `hci_debugfs_create_conn` and `hci_conn_add_sysfs` if `!HCI_CONN_HANDLE_UNSET(conn->handle)` or `hci_conn_set_handle()` is non-zero. [F38, F43]
- `hci_conn_add`, `hci_conn_add_unset`, `hci_connect_le`, `hci_connect_acl`, `hci_connect_le_scan`, and `hci_add_adv_instance` return `ERR_PTR` (check `IS_ERR()`, and convert to NULL in `check_pending_le_conn`), whereas `hci_conn_hash_lookup_*`, `hci_conn_params_add`, and `mgmt_alloc_skb` return NULL on failure. [F40, F41, F176, F177]
- Management handlers that can run when `hdev` is powered off (`set_powered` with `cp->val == 1`, `add_uuid`, `remove_uuid`, `set_dev_class`, `remove_adv_monitor`) must use `hci_cmd_sync_submit` rather than `hci_cmd_sync_queue`. Access quirks and `dev_flags` via `hci_test_quirk` and `hci_dev_*_flag` rather than `test_bit` on `&hdev->flags`. [F164, F244]

## Error Handling
- `mgmt_status(int err)` maps `err < 0` as kernel errnos and `err >= 0` as HCI status codes, so keep negative errnos in a signed `int`/`long` rather than `u8`. In `set_default_phy_complete` and `read_local_oob_*_data_complete`, `cmd->skb` can be `NULL` or `ERR_PTR`, so check both `!skb` and `IS_ERR(skb)` before reading `skb->data` or calling `kfree_skb(skb)`, and in `msft_add_address_filter_sync`, reset `skb = NULL` on `IS_ERR(skb)` before jumping to `done:`. [F173, F174, F175]

## External Contracts
- `link_to_bdaddr` maps `CIS_LINK`, `BIS_LINK`, `PA_LINK`, and `LE_LINK` to LE address types, whereas `mgmt_device_disconnected` only emits `MGMT_EV_DEVICE_DISCONNECTED` for `ACL_LINK`, `LE_LINK`, and `BIS_LINK`. BR/EDR link key paths must use `BDADDR_BREDR`, while SMP LE key paths (`load_long_term_keys`, `load_irks`, `mgmt_new_ltk/irk/csrk`) must use LE address types. [F179, F270]

## Known Pitfalls
- In `ext_evt_type_to_legacy`, mask out `LE_EXT_ADV_DATA_STATUS_MASK` before testing `!evt_type`, and test `LE_EXT_ADV_DIRECT_IND` before returning `LE_ADV_IND` under `LE_EXT_ADV_CONN_IND`. In `process_adv_report`, only validate `direct_addr` RPA/IRK when `!hci_dev_test_flag(hdev, HCI_MESH) && direct_addr && hci_dev_test_flag(hdev, HCI_PRIVACY)`, and keep `!ext_adv` on the inner `store_pending_adv_report` check rather than `!has_pending_adv_report(hdev)`. [F82, F83, F84]
- In `hci_num_comp_pkts_evt`, `switch (conn->type)` must cover `SCO_LINK`/`ESCO_LINK` for `sco_cnt`, `CIS_LINK`/`BIS_LINK`/`PA_LINK` for `iso_cnt`, and fall back to `acl_cnt` for `LE_LINK` when `!hdev->le_pkts`. In `hci_conn_complete_evt` and `hci_sync_conn_complete_evt`, fall back to `ESCO_LINK` lookup when `ev->link_type == SCO_LINK` is not found. In `hci_disconn_complete_evt`, guard `hci_conn_params_lookup` and `hci_update_passive_scan` with `if (conn->type == LE_LINK)`. [F88, F90, F92]
- Wire and `hdev` name arrays (`ev->name` in `hci_remote_name_evt`, `hdev->dev_name` [248], `hdev->short_name` [10]) need not be NUL-terminated when full and are 1 byte shorter than `MGMT_MAX_*_LENGTH`, so bound copies by `sizeof(hdev->*)` and lengths with `strnlen`. In `hci_le_ltk_request_evt`, zero trailing `sizeof(cp.ltk) - ltk->enc_size` bytes with `memset()`. In `load_conn_param`, initialize `bool update = false` inside the `for` loop body. [F45, F111, F180, F233]
