# REALTEK AUDIO CODECS

This unit implements ALSA SoC (ASoC) I2C audio codec drivers for Realtek RT5631/ALC5631, RT5640/RT5639/RT5642, and RT5645/RT5650/ALC3270 codecs, managing direct and indexed private register maps, DAPM routing and widgets, DAI clock/PLL/ASRC/TDM configurations, hardware EQ controls, and interrupt- or polling-driven jack and headset button detection.

## Architecture & Data Flow
- In `struct rt5640_priv`, `ovcd_th` and `ovcd_sf` are stored as pre-shifted register field values (`RT5640_MIC1_OVTH_*` shifted by `RT5640_MIC1_OVTH_SFT` and scale factor shifted by `RT5640_MIC_OVCD_SF_SFT`), whereas `jd_src` is stored unshifted and shifted by `RT5640_JD_SFT` when written to `RT5640_JD_CTRL`. In `rt5640_probe()`, `"realtek,jack-detect-source"` and `"realtek,over-current-scale-factor"` must be bounds-checked against `RT5640_JD_SRC_HDA_HEADER` and `RT5640_OVCD_SF_1P5` before storing or shifting. [F35, F58]
- Enabling or bypassing `RT5640_IRQ_MB1_OC_MASK` in `RT5640_IRQ_CTRL2` must go through `rt5640_enable_micbias1_ovcd_irq()` and `rt5640_disable_micbias1_ovcd_irq()` to update `rt5640->ovcd_irq_enabled` in lockstep, so `rt5640_jack_work()` ignores the falling-edge interrupt triggered when disabling the OVCD IRQ. [F39]
- In non-HDA jack detection mode, `rt5640_jack_work()` keeps OVCD micbias1 power and the OVCD IRQ enabled after headset detection if and only if `SND_JACK_MICROPHONE` is reported in `rt5640->jack->status`, which `rt5640_jack_work()` and `rt5640_disable_jack_detect()` check to balance `rt5640_disable_micbias1_for_ovcd()` and `rt5640_disable_micbias1_ovcd_irq()`. Broken by: clearing `SND_JACK_MICROPHONE` in `rt5640->jack->status` before `rt5640_disable_jack_detect()` or leaving micbias1 enabled for `SND_JACK_HEADPHONE`. [F40]
- Because `rt5640_set_ovcd_params()` enables sticky over-current detection (`RT5640_MB1_OC_STKY_EN`), every OVCD polling cycle in `rt5640_detect_headset()`, `rt5640_start_button_press_work()`, and `rt5640_button_press_work()` must clear `RT5640_MB1_OC_STATUS` via `rt5640_clear_micbias1_ovcd()` before sleeping or rescheduling; `rt5640_start_button_press_work()` must also reset `poll_count`, `press_count`, `release_count`, `pressed`, and `press_reported` before scheduling `rt5640->bp_work`. [F41, F60]
- In `rt5640_button_press_work()`, button press reporting must be deferred until `rt5640->poll_count >= (JACK_UNPLUG_TIME / BP_POLL_TIME)` while latching `rt5640->pressed = true` once `press_count >= BP_THRESHOLD`, and `rt5640->pressed && !rt5640->press_reported` must be checked before `rt5640->release_count >= BP_THRESHOLD` (which returns early). [F61]
- When `rt5640_sel_asrc_clk_src()` updates `RT5640_ASRC_2`, it must update `rt5640->asrc_en` and bits `0x3` of `RT5640_JD_CTRL` in lockstep based on whether any filter in `RT5640_ASRC_2` remains non-zero. [F43]
- `rt5645_sys_resume()` must reset `rt5645->jack_type = 0` before calling `rt5645_jack_detect_work()`, because when `pdata.jd_mode != 0` and a jack is present (`!val`), `rt5645_jack_detect_work()` only runs jack-in detection when `rt5645->jack_type == 0` and treats `jack_type == SND_JACK_HEADPHONE` as jack-out. [F67]
- In `rt5645_probe()`, `rt5645->eq_param` must be zero-allocated (`devm_kcalloc()`) for `RT5645_HWEQ_NUM` entries because `rt5645_hweq_get()` copies all `RT5645_HWEQ_NUM` entries to userspace, and `rt5645_enable_hweq()` must validate each `rt5645->eq_param[i].reg` with `rt5645_validate_hweq()` (`0x1a4..0x1cd`, `0x1e5..0x1f8`, or `RT5645_EQ_CTRL2`) before `regmap_write()`, breaking on the first non-matching entry (including `reg == 0` or invalid entries written by `rt5645_hweq_put()` before its validation loops). [F33, F53]
- In `rt5645.c`, `rt5645_hp_event()` and `rt5645_lout_event()` share the headphone amplifier power stage through `hp_amp_power()`, so each must call `hp_amp_power(component, 1)` on `SND_SOC_DAPM_POST_PMU` and `hp_amp_power(component, 0)` on `SND_SOC_DAPM_PRE_PMD` to keep `hp_amp_power_count` balanced. [F50]
- In `rt5645.c`, any DAPM route using `is_using_asrc()` as its connection check must have a source supply widget whose `shift` field (bit in `RT5645_ASRC_1`) is handled in `is_using_asrc()`'s `switch (source->shift)` (bits 0, 1, 3, 8, 9, or 10) to check the matching clock-select nibble in `RT5645_ASRC_2` or `RT5645_ASRC_3`. [F105]
- Every `snd_soc_dai_driver` using `rt5640_aif_dai_ops` or `rt5645_aif_dai_ops` must have a 0-based `.id` in `[0, RT5640_AIFS)` or `[0, RT5645_AIFS)`, because `hw_params()` and `set_dai_fmt()` index `lrck[dai->id]`, `bclk[dai->id]`, and `master[dai->id]` before validating `dai->id`. [F57]
- In `rt5645_set_dai_pll()` and `rt5640_set_dai_pll()`, cached PLL state (`pll_in`, `pll_out`, `pll_src`) must be updated only after `rl6231_pll_calc()` succeeds and `PLL_CTRL1`/`PLL_CTRL2` are written, and `pll_in` and `pll_out` must be zeroed when disabling the PLL (`!freq_in || !freq_out`). [F49]
- In `rt5631.c`, headphone depop stage helpers (`onebit_depop_power_stage`, `onebit_depop_mute_stage`, `depop_seq_power_stage`, `depop_seq_mute_stage`) must sample `RT5631_SOFT_VOL_CTRL` and `RT5631_INT_ST_IRQ_CTRL_2` before disabling soft volume and HP zero-crossing (mask `0xf7ff`), and restore both after the depop sequence. [F46]
- In `rt5645_get_pdata()`, precedence is: `dmi_first_match(dmi_platform_data)` first (every non-sentinel `dmi_platform_data` entry must set `.driver_data` to a non-`NULL` `struct rt5645_platform_data *` as it is unconditionally dereferenced), then device properties if `rt5645_check_dp()` is true, then `jd_mode3_platform_data`, and finally the `quirk` module parameter (`quirk != -1`). [F76, F83]

## Synchronization
- Because `rt5645_i2c_probe()` requests the threaded interrupt `rt5645_irq` before `devm_snd_soc_register_component()` invokes `rt5645_probe()` to set `rt5645->component`, `rt5645_jack_detect_work()` must check that `rt5645->component` is non-`NULL` before dereferencing it. [F13]
- `rt5645_btn_check_callback()` runs in timer softirq atomic context; it must not acquire `rt5645->jd_mutex` or perform I2C regmap I/O, and instead schedules `rt5645->jack_detect_work` on `system_power_efficient_wq`. [F95]
- In `rt5640_jack_work()`, when a headset with `SND_JACK_MICROPHONE` is unplugged, `cancel_delayed_work_sync(&rt5640->bp_work)` must be called before `rt5640_disable_micbias1_ovcd_irq()` and `rt5640_disable_micbias1_for_ovcd()`. [F16]

## Object Lifetimes
- In `rt5640`, `rt5640->irq` and `rt5640->jd_gpio_irq` must be acquired with `request_irq()` (never `devm_request_*_irq()`) in lockstep with setting `rt5640->irq_requested` and `rt5640->jd_gpio_irq_requested` to `true`, and `rt5640_disable_irq_and_cancel_work()` must `free_irq()` and clear those flags to `false` before calling `cancel_delayed_work_sync()` on `rt5640->jack_work` and then `rt5640->bp_work`. [F4, F38, F78]
- In `rt5640_i2c_probe()`, `rt5640->bp_work` and `rt5640->jack_work` must be initialized and `rt5640_disable_irq_and_cancel_work()` registered via `devm_add_action_or_reset()` before `devm_snd_soc_register_component()`. [F11]
- `rt5640_disable_jack_detect()` must return immediately when `rt5640->jack` is `NULL`, and after tearing down IRQs, work, and active microphone OVCD state, it must set both `rt5640->jd_gpio` and `rt5640->jack` to `NULL` (including on failed `rt5640_enable_jack_detect()`). [F5]
- In `rt5645_i2c_remove()` and `rt5645_sys_suspend()`, `timer_delete_sync(&rt5645->btn_check_timer)` must be called before `cancel_delayed_work_sync(&rt5645->jack_detect_work)` because `rt5645_btn_check_callback()` queues `rt5645->jack_detect_work`. [F2]
- In `rt5645_jack_detect()`, the `"LDO2"` DAPM pin must only be disabled on jack removal when `rt5645->pdata.jd_mode == 0`, because `rt5645_probe()` force-enables `"JD Power"` and `"LDO2"` for the component's lifetime whenever `rt5645->pdata.jd_mode != 0`. [F9]

## API Contracts
- In `rt5640`, device properties (`realtek,in*-differential`, `realtek,lout-differential`, `realtek,dmic*-data-pin`, `realtek,jack-detect-*`, and `realtek,over-current-*`) must be parsed in `rt5640_probe()` rather than `rt5640_i2c_probe()` so machine drivers can attach software properties before `snd_soc_register_card()`. [F81]
- `rt5640_dmic_enable()` unconditionally switches GPIO2 to `RT5640_GP2_PIN_DMIC1_SCL` and uses boolean `dmic1_data_pin` and `dmic2_data_pin` only to select GPIO3/GPIO4 (`true`) vs IN1P/IN1N (`false`), so `rt5640_probe()` must subtract 1 from non-zero DT pin values and only call `rt5640_dmic_enable()` when `dmic_en` is true. [F64]
- `rt5640_detect_headset()` must return a non-negative `SND_JACK_*` mask (`0` if unplugged, `SND_JACK_HEADSET`, or `SND_JACK_HEADPHONE` on short or timeout after `JACK_DETECT_MAXCOUNT` iterations) and never a negative errno. [F24]
- `rt5640_sel_asrc_clk_src()` and `rt5645_sel_asrc_clk_src()` require `filter_mask` to be a bitwise OR of `RT5640_*_FILTER` / `RT5645_*_FILTER` flags (and non-zero for `rt5640`) and `clk_src` to be an unshifted `RT5640_CLK_SEL_*` / `RT5645_CLK_SEL_*` selector. [F36]
- `rt5631_codec_set_dai_pll()`, `rt5640_set_dai_pll()`, and `rt5645_set_dai_pll()` treat `freq_in == 0` or `freq_out == 0` as a request to disable the PLL and switch sysclk back to MCLK, returning `0` before validating `source` or calling `rl6231_pll_calc()`. [F37]
- On `rt5631`, `rt5631_hifi_codec_set_dai_fmt()` must be invoked before `rt5631_codec_set_dai_pll()` and `rt5631_hifi_pcm_params()`, because `set_fmt` sets `rt5631->master` and performs a full write to `RT5631_SDP_CTRL` that overwrites `RT5631_SDP_I2S_DL_MASK` set by `hw_params`. [F106]
- In `snd_soc_component_set_jack()`, when `jack` is non-`NULL`: `rt5645_component_set_jack()` dereferences `data` as `*(int *)data` (the `SND_JACK_*` mask, which must not be dereferenced when `hs_jack` is `NULL`); on `rt5640` with `jd_src != RT5640_JD_SRC_HDA_HEADER`, `rt5640_set_jack()` forwards `data` as `struct rt5640_set_jack_data *` (or `NULL`). [F74, F75]

## Error Handling
- In `rt5645_i2c_probe()`, once `regulator_bulk_enable()` succeeds on `rt5645->supplies`, every subsequent error path must jump to `err_irq` or `err_enable` to call `regulator_bulk_disable()`, and `rt5645_i2c_remove()` must call `regulator_bulk_disable()` after stopping IRQ/timer/work. [F3]
- Callers of `rt5645_get_pdata()` (`rt5645_components()`, `rt5645_i2c_probe()`) must zero-initialize the target `struct rt5645_platform_data` before calling it. [F32]
- Clock/divider helpers (`snd_soc_params_to_bclk()` and `get_coeff()` in `rt5631_hifi_pcm_params()`, `rl6231_calc_dmic_clk()` in `set_dmic_clk()`, and `rl6231_get_clk_info()` in `rt5640_hw_params()`/`rt5645_hw_params()`) must have their return values stored in signed `int`s and checked for `< 0` before dividing, indexing `coeff_div`, or bit-shifting into `DMIC` or `ADDA_CLK1` registers. [F25, F69, F70]

## External Contracts
- In `rt5645.c`, the `"Speaker HWEQ"` `SNDRV_CTL_ELEM_TYPE_BYTES` control (`rt5645_hweq_info`, `rt5645_hweq_get`, `rt5645_hweq_put`) exchanges a 57-entry (`RT5645_HWEQ_NUM`) array of big-endian 16-bit `(reg, val)` pairs (`struct rt5645_eq_param_s_be16`) in `ucontrol->value.bytes.data`, converted via `cpu_to_be16()`/`be16_to_cpu()` to/from `rt5645->eq_param`. [F52]
- Callers of exported `rt5640_detect_headset()` must first configure OVCD via `rt5640_set_ovcd_params()` and force-enable `"LDO2"` and `"MICBIAS1"` via `rt5640_enable_micbias1_for_ovcd()` (balanced with `rt5640_disable_micbias1_for_ovcd()`); if `rt5640_set_jack_data.use_platform_clock` is `true`, the card must also define a `"Platform Clock"` DAPM widget. [F102, F103]
- `rt5645_components()` returns a function-local `static char buf[32]`, so callers must not `kfree()` the returned pointer or assume previous return pointers remain unchanged across calls. [F107]

## Known Pitfalls
- Private register macros in `rt5640.h` (`RT5640_BIAS_CUR4..RT5640_EQ_PST_VOL`) and `rt5645.h` (`RT5645_DIG_VOL..RT5645_EQ_PST_VOL`) are raw 8-bit offsets that must have `RT5640_PR_BASE` / `RT5645_PR_BASE` (`0x100`) added so regmap routes them through `rt5640_ranges` / `rt5645_ranges`. By contrast, `rt5631_regmap_config` has no `regmap_range_cfg`, so `rt5631.h` 2nd-layer private registers (`RT5631_EQ_BW_LOP..RT5631_SPK_INTL_CTRL`) must be accessed via `rt5631_read_index()` and `rt5631_write_index()`. [F54, F55]
- In `rt5640.c`, `get_sdp_info()` must be stored in a signed `int` and checked for `< 0` first, and `rt5640_hw_params()` / `rt5640_set_dai_fmt()` must test `RT5640_U_IF1` and `RT5640_U_IF2` with two separate `if` statements (not `else if`) because `RT5640_IF_113` and `RT5640_IF_223` set both flags. [F23, F59]
- Because `RT5640_GCTL2` is volatile and not restored by `regcache_sync()`, `rt5640_resume()` must reprogram its jack-detect enable and polarity bits when `rt5640->jack` is active; in both `rt5640_enable_jack_detect()` and `rt5640_resume()`, JD polarity must be inverted (`RT5640_JD_P_INV` or `RT5640_JD2_P_INV` when `!rt5640->jd_inverted`) so the OR-ed codec IRQ line is 0 while a jack is inserted and does not mask OVCD button-press edges. [F42, F85]
- In `rt5640.c`, external input 2 (`realtek,in2-differential`, `IN2 Boost`, `BST2`) maps to `RT5640_IN3_IN4` and BST4 bits (`RT5640_PWR_BST4_BIT`, `RT5640_M_BST4_*`), whereas input 3 (`realtek,in3-differential`, `IN3 Boost`, `BST3`) maps to `RT5640_IN1_IN2` and BST2 bits (`RT5640_PWR_BST2_BIT`, `RT5640_M_BST2_*`). [F63]
- Despite the swapped enum grouping in `rt5645.h`, `dmic1_data_pin` in `rt5645_i2c_probe()` only accepts `RT5645_DMIC_DATA_IN2N`, `GPIO5`, and `GPIO11`, while `dmic2_data_pin` only accepts `RT5645_DMIC_DATA_IN2P`, `GPIO6`, `GPIO10`, and `GPIO12`. [F66]
- In `rt5645_hw_params()`, `rt5645_set_dai_fmt()`, and `rt5645_set_tdm_slot()`, updates to data length, BCLK polarity, and TDM slots in `RT5645_I2S1_SDP`, `RT5645_I2S2_SDP`, and `RT5645_TDM_CTRL_1` must branch on `rt5645->codec_type` because bit positions differ between `CODEC_TYPE_RT5645` and `CODEC_TYPE_RT5650`. [F68]
- In `rt5645_spk_put_volsw()`, writing `RT5645_SPK_VOL` requires enabling the 25 MHz RC clock (`RT5645_PWR_CLK25M_PU` in `RT5645_MICBIAS`) before `snd_soc_put_volsw()` and scheduling `rt5645->rcclock_work` to power it down (`RT5645_PWR_CLK25M_PD`) after 200 ms. [F86]
