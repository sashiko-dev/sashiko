# DRM DRIVERS FOR MEDIATEK

This component implements the DRM KMS and GEM drivers for MediaTek SoC display subsystems (MMSYS/VDOSYS). It binds modular Display Data Path (DDP) hardware blocks—such as OVL, OVL adaptor, RDMA, ETHDR, MERGE, color/gamma/AAL processors, DSI, DPI, DisplayPort/eDP bridges, and HDMI CEC—into unified DRM CRTC, plane, encoder, and bridge pipelines using the Linux component framework and MediaTek CMDQ mailbox hardware.

## Architecture & Data Flow

- Because `DDP_COMPONENT_DRM_OVL_ADAPTOR` is `DDP_COMPONENT_ID_MAX + 1` with no DT node (`comp_node` entry is `NULL`), component tables must be sized `DDP_COMPONENT_DRM_ID_MAX`, `mtk_drm_of_ddp_path_build_one()` must bound `idx` by `DDP_COMPONENT_DRM_ID_MAX` and deduplicate it via `ovl_adaptor_comp_added`, `mtk_ddp_path_available()` and `mtk_crtc_create()` must exempt it from `comp_node` null checks, and `mtk_find_possible_crtcs()` must only increment CRTC index `i` when `mtk_ddp_path_available()` is true. [F67, F82, F98]
- In `mtk_drm_get_all_drm_priv()`, each `mtk_drm_private` instance must be placed in `all_drm_priv` at the fixed index (`CRTC_MAIN`, `CRTC_EXT`, or `CRTC_THIRD`) matching its non-empty path because `mtk_crtc_update_output()` indexes `all_drm_private` by `drm_crtc_index(crtc)`. In `mtk_drm_kms_init()`, `drm->dev_private` must be updated to `private->all_drm_private[i]` before each `component_bind_all()` call, and `dma_dev` must be populated on all `mmsys_dev_num` instances. [F64, F83]
- When `conn_routes` is non-NULL, `mtk_crtc_create()` allocates `path_len + 1` entries in `mtk_crtc->ddp_comp` and leaves `ddp_comp[ddp_comp_nr - 1]` as `NULL` until `mtk_crtc_update_output()` runs, so `mtk_ddp_comp_mode_valid()` must check `comp != NULL`. Uninitialized `conn_routes` components must have `comp->encoder_index = -1`, and `mtk_crtc_update_output()` must check `comp->encoder_index >= 0` before shifting `BIT(comp->encoder_index)`. [F87, F109]
- All `drm_plane` instances for a CRTC must be allocated in a single contiguous `mtk_crtc->planes` array in the same component order (`comp_idx` 0 then 1) that `mtk_ddp_comp_for_plane()` walks using `mtk_ddp_comp_layer_nr()`, because `mtk_ddp_comp_for_plane()` computes `local_index = plane - mtk_crtc->planes` via pointer subtraction. `mtk_crtc_update_config()` sets per-plane `pending.config`/`async_config` and CRTC `pending_planes`/`pending_async_planes`, which must be cleared in `mtk_crtc_ddp_config()` (when `!cmdq_handle`) or `ddp_cmdq_cb()`. [F58, F88]
- In `mtk_disp_ovl.c` and `mtk_crtc.c`, AFBC registers (`DISP_REG_OVL_PITCH_MSB`, `DISP_REG_OVL_HDR_ADDR`, `DISP_REG_OVL_HDR_PITCH`) and `OVL_LAYER_AFBC_EN` must be gated on `ovl->data->supports_afbc` (`mtk_ddp_comp_is_afbc_supported(comp)`). `DISP_REG_OVL_PITCH(idx)` takes `pending->pitch & GENMASK(15, 0)` (with `OVL_CONST_BLEND` set whenever `blend_mode == DRM_MODE_BLEND_PIXEL_NONE` or `!state->base.fb->format->has_alpha`), while `DISP_REG_OVL_PITCH_MSB(idx)` takes `pending->pitch >> 16` (ORed with `OVL_PITCH_MSB_2ND_SUBBUF` for AFBC). [F95, F102, F147]
- In `struct mtk_disp_ovl_data`, any non-zero `blend_modes` must include `BIT(DRM_MODE_BLEND_PREMULTI)`, `mtk_ovl_fmt_convert()` must only read `state->base.pixel_blend_mode` when that bit is set, and `gmc_bits` must be `<= GMC_THRESHOLD_BITS` (16) to avoid unsigned shift underflow in `mtk_ovl_layer_on()`. [F56, F121]
- In `mtk_ovl_adaptor_layer_config()`, `MTK_OVL_ADAPTOR_LAYER_NUM` (4) is bounded by `OVL_ADAPTOR_MDP_RDMA0..7` and `OVL_ADAPTOR_MERGE0..3`. When `!use_dual_pipe`, `rdma_r` must be stopped via `mtk_mdp_rdma_stop()`; on layer disable, `mtk_ethdr_layer_config()` must still be called after stopping `merge`, `rdma_l`, and `rdma_r`. In `mtk_merge_advance_config()`, `if (r_w)` must follow `if (priv->fifo_en)`. In `mtk_ethdr_layer_config()`, `MIX_L_SRC_*` and `MIX_SRC_CON` use 0-based `idx`, whereas `mtk_mmsys_mixer_in_config()` takes `idx + 1`. [F68, F85, F86, F112]
- In `mtk_gamma_set()` and `mtk_aal_gamma_set()`, enabling the LUT in `DISP_GAMMA_CFG` or `DISP_AAL_CFG` requires clearing `GAMMA_RELAY_MODE` or `AAL_RELAY_MODE`. In `mtk_gamma_set()`, 12-bit LUTs (`lut_bits == 12`) write R/G to `DISP_GAMMA_LUT + i * 4` and B to `DISP_GAMMA_LUT1 + i * 4` after selecting `cur_bank` in `DISP_GAMMA_BANK`. [F78, F94]
- In `mtk_dp.c`, `mtk_dp->drm_dev` is `NULL` until `mtk_dp_bridge_attach()` completes and after `mtk_dp_bridge_detach()`, so `mtk_dp_wait_hpd_asserted()`, `mtk_dp_parse_capabilities()`, and `mtk_dp_aux_transfer()` must log with `mtk_dp->dev`. In `mtk_dp_bridge_atomic_enable()` and `mtk_dp_bridge_atomic_disable()`, `mtk_dp->enabled` and `mtk_dp->audio_enable` must be updated before calling `mtk_dp_update_plugged_status()`. [F39, F74]
- In `mtk_dp_training()`, when `mtk_dp_train_cr()` fails at `DP_LINK_BW_1_62`, `lane_count` is halved and `link_rate` must be reset to `max_link_rate`; `train_info.link_rate` and `lane_count` are updated only after CR and EQ succeed, and `mtk_dp_train_cr()` resets `voltage_retries = 0` whenever `prev_lane_adjust != link_status[4]`. `mtk_dp_bulk_16bit_write()` packs 2 bytes per 32-bit register at 4-byte stride (`offset + i * 2`), guarding `i + 1 < length` when `length` is odd. [F72, F90, F113]
- In `mtk_dsi.c`, SoC-dependent offsets and feature flags must be read from `dsi->driver_data`. In `mtk_dsi_poweron()`, `mtk_dsi_phy_timconfig()` must run before `mtk_dsi_config_vdo_timing()`. `MIPI_DSI_MODE_NO_EOT_PACKET` sets `DIS_EOT` in `DSI_TXRX_CTRL` and omits the 2-byte EOT timing delta. In `mtk_dsi_host_transfer()`, short RX payloads (`recv_cnt <= 2`) start at `&read_data[1]` and long payloads at `&read_data[4]`, clamping `recv_cnt` to `10` and `msg->rx_len`. In `mtk_dsi_cmdq()`, short TX packets (`tx_len <= 2`) pack payload at `cmdq_off = 2`, whereas long packets use `cmdq_off = 4`. [F76, F92, F93, F103, F149]
- In `mtk_dpi.c`, every `struct mtk_dpi_conf` must set a non-zero `pixels_per_iter`, and if `!clocked_by_hdmi`, provide non-zero `.factor` entries (`num_dpi_factor > 0`). When `dpi->conf->clocked_by_hdmi` is true, `mtk_dpi_start()`/`mtk_dpi_stop()` must not call `mtk_dpi_power_on()`/`mtk_dpi_power_off()`, and `mtk_dpi_set_display_mode()` must not call `mtk_dpi_set_pixel_clk()`. In `mtk_cec_hpd_high()`, hotplug requires both `HDMI_PORD` and `HDMI_HTPLG` to be set simultaneously in `RX_EVENT`. [F115, F123, F159]

## Synchronization

- `mtk_crtc->config_lock` and `crtc->dev->event_lock` in `mtk_crtc.c` must always be acquired with `spin_lock_irqsave()`; `config_lock` nests inside `mtk_crtc->hw_lock` and outside `event_lock`. `ddp_cmdq_cb()` and `mtk_drm_finish_page_flip()` must check `mtk_crtc->config_updating` under `config_lock`, and `ddp_cmdq_cb()` must not clear pending flags when `config_updating` is true. In `mtk_crtc_update_config()`, `dma_sync_single_for_device()`, `cmdq_vblank_cnt = 3`, and clearing `config_updating` under `config_lock` must happen BEFORE `mbox_send_message()`. [F27, F157, F161, F162]
- When `mtk_crtc->cmdq_client.chan` is non-NULL, `mtk_drm_finish_page_flip()` must return after `drm_crtc_handle_vblank()`, deferring `mtk_crtc_finish_page_flip()` to `ddp_cmdq_cb()`. When disabling planes in `mtk_crtc_plane_disable()` or `mtk_crtc_atomic_disable()` with an active `cmdq_client.chan`, the driver must call `mtk_crtc_update_config()` and wait on `mtk_crtc->cb_blocking_queue` until `mtk_crtc->cmdq_vblank_cnt == 0`. [F28, F29]
- In `mtk_crtc_mode_set_nofb()`, writes to `pending_width`, `pending_height`, and `pending_vrefresh` must be ordered before `state->pending_config = true` by `wmb()`. In `mtk_dsi_switch_to_cmd_mode()` and `mtk_dsi_host_send_cmd()`, the target interrupt bit in `dsi->irq_data` must be cleared via `mtk_dsi_irq_data_clear()` before starting the hardware operation and waiting in `mtk_dsi_wait_for_irq_done()`. [F31, F33]
- In `mtk_dp.c`, `mtk_dp->irq_thread_handle` is protected by `mtk_dp->irq_thread_lock` (set in `mtk_dp_hpd_event()`, atomically snapshotted and zeroed in `mtk_dp_hpd_event_thread()`). `mtk_dp->plugged_cb` and `mtk_dp->codec_dev` are protected by `mtk_dp->update_plugged_status_lock`, which `mtk_dp_audio_hook_plugged_cb()` must unlock before calling `mtk_dp_update_plugged_status()`. In `mtk_cec.c`, `cec->hpd_event` and `cec->hdmi_dev` must be snapshotted under `cec->lock` and invoked after unlocking. [F34, F35, F36]

## Object Lifetimes

- In `mtk_drm_drv.c`, `of_node_put()` must be called on early `break`, `goto`, or `return` inside `for_each_child_of_node()` or `for_each_endpoint_of_node()` (never before `continue`), `mtk_drm_get_all_drm_priv()` must release `pdev` and `drm_dev` with `put_device()`, and `mtk_drm_probe()` must release `private->mutex_node` and `private->comp_node[comp_id]` on failure and in `mtk_drm_remove()`. Callers of `mtk_drm_of_get_ddp_ep_cid()` must call `of_node_put(next)` even on negative error returns, and `mtk_drm_data` and `temp_path` must be duplicated with `devm_kmemdup()`. [F1, F5, F6, F134, F151]
- In `mtk_drm_bind()`, if initialization fails after assigning `private->all_drm_private[i]->drm = drm`, every `all_drm_private[i]->drm` entry across all `mmsys_dev_num` instances must be cleared to `NULL` alongside `drm_dev_put(drm)`. In multi-MMSYS setups, only the `private->drm_master` instance may unregister/free `private->drm` in `mtk_drm_unbind()` (calling `drm_dev_unregister()`, `drm_kms_helper_poll_fini()`, and `drm_atomic_helper_shutdown()` before `component_unbind_all()`) or suspend/resume KMS. [F3, F38, F143]
- In `mtk_crtc.c`, when `mbox_request_channel()` fails or subsequent initialization fails after `mbox_free_channel()`, `mtk_crtc->cmdq_client.chan` must be set to `NULL`. In `mtk_crtc_atomic_begin()`, moving `mtk_crtc_state->base.event` to `mtk_crtc->event` requires `drm_crtc_vblank_get(crtc)` and clearing `mtk_crtc_state->base.event`, balanced in `mtk_crtc_finish_page_flip()` by `drm_crtc_send_vblank_event()`, `drm_crtc_vblank_put(crtc)`, and `mtk_crtc->event = NULL`. [F7, F8]
- In `mtk_dp_bridge_attach()`, `drm_dp_aux_register()`, `mtk_dp_poweron()`, `drm_bridge_attach()`, and `enable_irq()`/`mtk_dp_hwirq_enable()` must be unwound in reverse order on error and in `mtk_dp_bridge_detach()` (which clears `mtk_dp->drm_dev = NULL`). `mtk_dp->phy_dev` (`platform_device_register_data()`) must be unregistered if `devm_phy_get()` fails and in `mtk_dp_remove()` (with `mtk_dp->audio_pdev`). [F17, F19]
- In `mtk_dp_edid_read()` and `mtk_dp_bdg_detect()`, when `!mtk_dp->enabled`, temporary `drm_atomic_bridge_chain_pre_enable()` and `mtk_dp_aux_panel_poweron(mtk_dp, true)` state must be symmetrically disabled before returning. In `mtk_dp_get_calibration_data()`, `nvmem_cell_get()` requires `nvmem_cell_put()`, and `buf` from `nvmem_cell_read()` must be freed with `kfree(buf)` on all paths. `mtk_dsi_poweron()`/`mtk_dsi_poweroff()` and `mtk_dpi_power_on()`/`mtk_dpi_power_off()` must balance `refcount` across DDP and bridge callers and unwind on error. [F15, F16, F20, F21]

## API Contracts

- All direct calls to `cmdq_dev_get_client_reg()` and `cmdq_pkt_*()` in `mediatek-drm` must be guarded by `#if IS_REACHABLE(CONFIG_MTK_CMDQ)` with CPU MMIO fallbacks. `mtk_disp_ovl_adaptor_master_bind()` passes `struct device *mmsys_dev` as `void *data` to `component_bind_all()`, whereas `mtk_drm_kms_init()` passes `struct drm_device *drm`, so `.bind` callbacks for `ovl_adaptor` sub-drivers (`mtk_ethdr_bind()`, `mtk_disp_merge_bind()`) must not cast `data` to `struct drm_device *`. [F130, F182]
- `mtk_find_possible_crtcs()` returns a positive bitmask or negative errno, so callers must check `< 0` in a signed `int` before assigning to `encoder.possible_crtcs`. Callers of `mtk_dither_set_common()` must clamp `bpc` to `MTK_MAX_BPC` (`bpc == 0` or `MTK_MIN_BPC <= bpc <= MTK_MAX_BPC`). `mtk_gem_prime_import_sg_table()` must verify `drm_prime_get_contiguous_size(sg) >= attach->dmabuf->size`, and `mtk_drm_mode_fb_create()` must reject `info->num_planes != 1`. [F51, F124, F181]
- Both `mtk_ovl_adaptor_layer_config()` and `mtk_ethdr_layer_config()` must check `!pending->enable || !pending->width || !pending->height` and disable the layer before computing `align_width / 2 - 1`. `mtk_ddp_comp_supported_rotations()` and `mtk_ovl_supported_rotations()` must include `DRM_MODE_ROTATE_0`, and `mtk_ovl_layer_check()` must test `state->rotation & ~DRM_MODE_ROTATE_0` when rejecting rotated YUV buffers. [F84, F174]
- `mtk_dp_set_color_format()` must translate `enum dp_pixelformat` via a `switch` into both `DP_COLOR_FORMAT_*` (`MTK_DP_ENC0_P0_3034`) and `PIXEL_ENCODE_FORMAT_DP_ENC0_P0_*` (`MTK_DP_ENC0_P0_303C`). `mtk_dp_aux_transfer()` must chunk transfers to `DP_AUX_MAX_PAYLOAD_BYTES` (16), encoding non-zero `length` as `(length - 1) << 12` and `0` via `AUX_NO_LENGTH_AUX_TX_P0`. In `mtk_dp_get_calibration_data()`, byte length `len` must be divided by `sizeof(u32)` before checking `fmt->idx >= len`, and any out-of-bounds entry must reset all `MTK_DP_CAL_MAX` entries to `default_val`. [F45, F89, F91]
- In `struct mtk_dpi_conf`, `dimension_mask` and `hvsize_mask` must be unshifted bitmasks (`HPW_MASK`, `HSIZE_MASK`), `output_fmts` must place RGB formats before BGR and YUV, and `mtk_dpi_bridge_atomic_get_output_bus_fmts()` must scale `num_output_fmts` by `sizeof(*output_fmts)`. [F55, F135, F176]

## Error Handling

- When `mtk_drm_kms_init()` binds sub-components across `mmsys_dev_num` devices in `private->all_drm_private[i]->dev`, any failure during `component_bind_all()` must unwind only previously bound indices in reverse (`while (--i >= 0)`). In `mtk_drm_of_ddp_path_build_one()`, `next` must be initialized to `NULL` before `mtk_drm_of_get_ddp_ep_cid()`, and `-ENODEV` must be returned before final-component validation (`-EINVAL`) so `mtk_drm_of_ddp_path_build()` can ignore `-ENODEV` and skip disabled CRTC paths. [F2, F40, F53]
- In `mtk_dpi_probe()`, optional pinctrl handles (`dpi->pinctrl`, `dpi->pins_gpio`, `dpi->pins_dpi`) must be reset from `IS_ERR()` to `NULL` on lookup failure because `mtk_dpi_bridge_enable()` and `mtk_dpi_bridge_disable()` only test them for non-NULL. In `mtk_dsi_host_transfer()`, `recv_cnt` must be signed `ssize_t` rather than `u32` so negative `int ret` error codes in `return ret < 0 ? ret : recv_cnt;` are sign-extended. [F48, F118]

## External Contracts

- In `mtk_dp_aux_transfer()`, when `mtk_dp->bridge.type != DRM_MODE_CONNECTOR_eDP` and `!mtk_dp->train_info.cable_plugged_in`, set `msg->reply` to NACK and return `-EIO` (not `-EAGAIN`). `mtk_dp_video_mute()` must follow the MMIO mute update with `arm_smccc_smc(MTK_DP_SIP_CONTROL_AARCH32, mtk_dp->data->smc_cmd, enable, ...)`. In `mtk_dpi_bridge_attach()` and `mtk_dsi_host_attach()`, if `devm_drm_of_get_bridge()` on port 1 fails with an error other than `-EPROBE_DEFER`, fall back to port 0, endpoint 0. [F43, F97, F173]

## Known Pitfalls

- Register bit-update helpers have opposite parameter orders: `mtk_dsi_mask()` and `rdma_update_bits()` take `(..., offset, mask, val)`, whereas `mtk_dp_update_bits()`, `mtk_dpi_mask()`, and `mtk_ddp_write_mask()` take `val` before `mask`. In `mtk_ovl_layer_config()`, `DRM_MODE_ROTATE_180` must be translated by XORing `rotation` with `DRM_MODE_REFLECT_X | DRM_MODE_REFLECT_Y` before checking reflection bits. In `mtk_ethdr_layer_config()`, disabling a layer must write `0` to `MIX_L_SRC_SIZE(idx)` rather than clearing `BIT(idx)` in `MIX_SRC_CON`. [F47, F100, F111]
- In `mtk_dsi_config_vdo_timing()`, `mtk_dsi_ps_control()` must be called with `config_vact = false` so `DSI_HSTX_CKL_WC` is not overwritten after `mtk_dsi_config_vdo_timing_per_frame_lp()`. In `mtk_dsi_poweron()`, `mipi_dsi_pixel_format_to_bpp()` must be checked for `< 0` in signed `int` before assigning to `u32`, and `dsi->data_rate` and `data_rate_mhz` must use `DIV_ROUND_UP_ULL()` and `DIV_ROUND_UP()`. `mtk_dp_aux_transfer()` must use a `do { ... } while (accessed_bytes < msg->size)` loop so zero-length (`msg->size == 0`) AUX transactions still execute `mtk_dp_aux_do_transfer()`. [F104, F114, F120]
