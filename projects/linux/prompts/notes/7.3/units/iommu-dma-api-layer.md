# IOMMU DMA-API LAYER

This unit provides the I/O Virtual Address (IOVA) allocator (`drivers/iommu/iova.c`) and the glue layer (`drivers/iommu/dma-iommu.c`) connecting the generic Linux DMA mapping API to the IOMMU subsystem. It manages red-black tree IOVA address spaces with per-CPU magazine range caches (`iova_rcache`), deferred IOTLB flush queues (`iova_fq`), SWIOTLB bounce buffering for untrusted or unaligned DMA, scatterlist coalescing, and MSI doorbell page remapping.

## Architecture & Data Flow

- Functions operating on both managed DMA and unmanaged MSI-only domains (`iommu_dma_alloc_iova()`, `iommu_dma_free_iova()`, `cookie_msi_granule()`, `cookie_msi_pages()`) must check `domain->cookie_type` (`IOMMU_COOKIE_DMA_IOVA` vs `IOMMU_COOKIE_DMA_MSI`) before accessing `domain->iova_cookie->iovad` or `domain->msi_cookie`. In `cookie_msi_granule()` and `cookie_msi_pages()`, `default:` must end with `BUG()`, not `unreachable()`. [F32, F77]
- `iovad->anchor` is an embedded sentinel in `iovad->rbroot` with `pfn_lo` and `pfn_hi` set to `IOVA_ANCHOR` (`~0UL`). `alloc_iova_mem()` must zero-initialize `struct iova` via `kmem_cache_zalloc()`, and `free_iova_mem()` must check `iova->pfn_lo != IOVA_ANCHOR` before `kmem_cache_free()` so error paths and `put_iova_domain()` never free the anchor or misidentify an uninitialized node. [F39, F74]
- `remove_iova()` must call `__cached_rbnode_delete_update(iovad, iova)` before `rb_erase(&iova->node, &iovad->rbroot)` so `rb_next()` can advance `cached32_node` and `cached_node` while linked. `__cached_rbnode_delete_update()` must check `free == cached_iova` in addition to `free->pfn_hi < iovad->dma_32bit_pfn` because prior `rb_next()` updates or anchor state can leave `cached32_node` at `pfn_hi >= iovad->dma_32bit_pfn`. [F47, F48]
- In `__alloc_and_insert_iova_range()`, `iovad->max32_alloc_size = size` must only be set after an rbtree search (including `retry`) fails, never on the early `size >= iovad->max32_alloc_size` fast-fail path. The `retry` branch must reset `high_pfn = limit_pfn`, `low_pfn = retry_pfn + 1`, and `curr = iova_find_limit(iovad, limit_pfn)`, and insertion must pass `prev` (not `curr`, which can be `NULL`) to `iova_insert_rbtree()`. [F49, F83]
- `struct iova` bounds `pfn_lo`/`pfn_hi` are inclusive (`new->pfn_hi = new->pfn_lo + size - 1`). `alloc_iova()` and `alloc_iova_fast()` convert their inclusive `limit_pfn` to exclusive (`limit_pfn + 1`) for `__alloc_and_insert_iova_range()` and `iova_rcache_get()`. `reserve_iova()` rejects `(pfn_hi | pfn_lo) > (ULLONG_MAX >> iova_shift(iovad))`, and byte-region callers (`iova_reserve_iommu_regions()`) must pass `iova_pfn(iovad, start + length - 1)` as `pfn_hi`. [F63, F73]
- `alloc_iova_fast()` must round `size` up to a power of two when `size < (1 << (IOVA_RANGE_CACHE_MAX_SIZE - 1))`, because `iova_rcache_insert()`/`iova_rcache_get()` index `rcaches` by `order_base_2(size)`. On `alloc_iova()` failure with `flush_rcache` true, it must set `flush_rcache = false` before draining per-CPU/global rcaches and jumping to `retry`. In `iova_magazine_pop()`, the reverse scan requires `!iova_magazine_empty(mag)` on entry and must check `if (i == 0) return 0;` in the loop body before `i--`. [F65, F85, F86]
- In `iommu_dma_init_domain()`, `base_pfn` starts at `1` and is clamped to at least `domain->geometry.aperture_start >> order` so `iovad->start_pfn` is never `0`. If `iovad->start_pfn` is already non-zero, it must verify `1UL << order == iovad->granule` and `base_pfn == iovad->start_pfn` (returning `-EFAULT` on mismatch) and return `0` without re-running `init_iova_domain()` or `iova_domain_init_rcaches()`. [F61, F118]
- In `struct iommu_dma_cookie`, `single_fq` (`vmalloc`) and `percpu_fq` (`__alloc_percpu`) share a union discriminated by `cookie->options.qt == IOMMU_DMA_OPTS_SINGLE_QUEUE`. `struct iova_fq` ends with flexible array `entries[]` of power-of-two length `options.fq_size` (`fq->mod_mask = fq_size - 1`), and must be allocated with `struct_size(queue, entries, fq_size)`. In `queue_iova()`, if `fq_full(fq)` remains true after `fq_ring_free_locked()`, `fq_flush_iotlb()` must be followed by a second `fq_ring_free_locked()` before `fq_ring_add()`. [F68, F87, F106, F107]
- In `iommu_dma_map_phys()`, `iommu_dma_map_sg()`, and `iommu_dma_iova_bounce_and_link()`, SWIOTLB bounce mapping must precede `arch_sync_dma_for_device()` / `iommu_dma_sync_sg_for_device()`, which must precede `__iommu_dma_map()` / `iommu_map_nosync()`. When `iommu_dma_map_sg_swiotlb()` is used, `sg_dma_mark_swiotlb(sg)` marks the list so `iommu_dma_unmap_sg()`, `iommu_dma_sync_sg_for_cpu()`, and `iommu_dma_sync_sg_for_device()` check `sg_dma_is_swiotlb()` and process each segment individually. [F54, F137]
- `iommu_dma_map_sg()` must call `iommu_dma_sync_sg_for_device()` before mutating `s->offset`/`s->length`, and `__finalise_sg()`/`__invalidate_sg()` must restore `s->offset += sg_dma_address(s)`. `PCI_P2PDMA_MAP_BUS_ADDR` segments must be marked with `sg_dma_mark_bus_address(s)` and `continue` without mutating `s->offset`, `s->length`, `iova_len`, or `prev`, and `__finalise_sg()`/`__invalidate_sg()` must unmark them without adding `sg_dma_address(s)` to `s->offset`. [F52, F89]
- In `__finalise_sg()`, each iteration must read stashed fields from `s` and reset `sg_dma_address(s) = DMA_MAPPING_ERROR` and `sg_dma_len(s) = 0` before writing to `cur` (avoiding clobbering `cur` when `cur == s`), advance `dma_addr` by `s_iova_len`, and reset `cur_len = 0` whenever `s_length + s_iova_off < s_iova_len`. In `iommu_dma_unmap_sg()`, after the first loop locates `start` and breaks, `nents` must be decremented (`nents -= i`) and the second loop `for_each_sg(tmp, tmp, nents, i)` must start at `tmp` (not `sg_next(tmp)`) before calling `__iommu_dma_unmap()` only if `end` is non-zero. [F90, F91]

## Synchronization

- `iovad->iova_rbtree_lock`, `cpu_rcache->lock`, `rcache->lock`, and `fq->lock` are acquired in both process/timer/workqueue and interrupt DMA paths, so top-level acquisitions must use `spin_lock_irqsave()`. All accesses to `iovad->rbroot`, `cached_node`, `cached32_node`, and `max32_alloc_size` must hold `iova_rbtree_lock`, and all runtime accesses to `fq->head`, `fq->tail`, and `fq->entries` in `fq_full()`, `fq_ring_add()`, and `fq_ring_free_locked()` must hold `fq->lock`. [F21, F23, F131]
- In `__iova_rcache_insert()`, `__iova_rcache_get()`, and `queue_iova()`, the per-CPU pointer (`rcache->cpu_rcaches` or `cookie->percpu_fq`) is resolved before `spin_lock_irqsave()`, so `raw_cpu_ptr()` must be used instead of `this_cpu_ptr()`. Because DMA map/rcache paths run in atomic contexts or under `spin_lock_irqsave()`, `alloc_iova_mem()`, `iova_magazine_alloc()`, and `iommu_map*()` must use `GFP_ATOMIC`. [F128, F132]
- `iova_depot_work_func()` must check `rcache->depot_size > num_online_cpus()` and call `iova_depot_pop(rcache)` under `rcache->lock`, then release `rcache->lock` before calling `iova_magazine_free_pfns()`, `iova_magazine_free()`, and `schedule_delayed_work()`. [F25]
- In `iommu_dma_init_fq()`, `fq_flush_start_cnt`, `fq_flush_finish_cnt`, `single_fq`/`percpu_fq`, `fq_timer`, and `fq_timer_on` must be initialized and ordered by `smp_wmb()` before publishing `WRITE_ONCE(cookie->fq_domain, domain)`. Unmap paths (`__iommu_dma_unmap()`, `__iommu_dma_iova_unlink()`) must snapshot `READ_ONCE(cookie->fq_domain)` into `iotlb_gather.queued`, and `queue_iova()` must execute `smp_mb()` before reading `options.qt`, `single_fq`/`percpu_fq`, and before reading `fq_flush_start_cnt`. [F16, F17]
- `fq_flush_iotlb()` must increment `fq_flush_start_cnt` before `flush_iotlb_all()` and `fq_flush_finish_cnt` after it returns, and `fq_ring_free_locked()` must stop at the first entry where `entry.counter >= atomic64_read(&cookie->fq_flush_finish_cnt)`. `queue_iova()` must test `!atomic_read(&cookie->fq_timer_on)` before `!atomic_xchg(&cookie->fq_timer_on, 1)` to arm `fq_timer`, and `fq_flush_timeout()` must clear `fq_timer_on` to `0` before calling `fq_flush_iotlb()`. [F18, F19]
- `iommu_dma_sw_msi()` and `iommu_dma_get_msi_page()` mutate and traverse `cookie->msi_page_list` without an internal cookie lock and require the caller to hold the device's `iommu_group` mutex (`iommu_group_mutex_assert(dev)`). [F22]

## Object Lifetimes

- In `fq_ring_free_locked()`, `fq->entries[idx].freelist` must be re-initialized with `IOMMU_PAGES_LIST_INIT()` immediately after `iommu_put_pages_list()` because `iommu_put_pages_list()` frees pages without unlinking their list nodes. [F1]
- `iommu_put_dma_cookie()` must check `cookie->iovad.granule` is non-zero before calling `iommu_dma_free_fq()` and `put_iova_domain(&cookie->iovad)`. `iommu_dma_free_fq()` must call `timer_delete_sync(&cookie->fq_timer)` before freeing `single_fq`/`percpu_fq`, and must complete before `put_iova_domain(&cookie->iovad)`. [F2, F20]
- Every `struct iommu_dma_msi_page` on `cookie->msi_page_list` (`cookie_init_hw_msi_region()`, `iommu_dma_get_msi_page()`) must be individually heap-allocated because `iommu_put_dma_cookie()` and `iommu_put_msi_cookie()` call `kfree()` on each entry. In `iova_reserve_iommu_regions()`, `resv_regions` from `iommu_get_resv_regions()` must be released with `iommu_put_resv_regions()` on all return paths. [F4, F120]
- When `free_iova_fast()` caches a PFN range via `iova_rcache_insert()`, the `struct iova` node remains allocated and linked in `iovad->rbroot` until drained via `iova_magazine_free_pfns()` or freed during domain teardown by `put_iova_domain()`. [F13]
- `iova_domain_init_rcaches()` must initialize all `rcaches`, `rcache->work`, and per-CPU magazines before registering `iovad->cpuhp_dead` on `CPUHP_IOMMU_IOVA_DEAD`, and `put_iova_domain()` must remove `cpuhp_dead` and `cancel_delayed_work_sync(&rcache->work)` before freeing depot magazines and `iovad->rbroot`. Similarly, `iova_cache_get()`/`iova_cache_put()` must hold `iova_cache_mutex` across `iova_cache_users` transitions and tear down `CPUHP_IOMMU_IOVA_DEAD` before destroying `iova_cache` and `iova_magazine_cache`. [F26, F27]

## API Contracts

- `init_iova_domain()` requires `granule` to be a power-of-two byte size `<= PAGE_SIZE`, whereas `start_pfn`, `size`, `pfn`, and `limit_pfn` passed to `alloc_iova*()`, `free_iova*()`, `find_iova()`, and `reserve_iova()` are in `iovad->granule` PFNs. Before `iommu_dma_alloc_iova()` or `iommu_dma_free_iova()` shifts a byte `size` by `iova_shift(iovad)`, callers must add `iova_offset(iovad, addr)` and round up with `iova_align(iovad, size + iova_off)`. [F62, F102, F142]
- `dma_iova_try_alloc()` must zero `*state` before any early return, check `use_dma_iommu(dev)` before dereferencing `iommu_get_dma_domain(dev)->iova_cookie`, and reject `size` with bit 63 (`DMA_IOVA_USE_SWIOTLB`) set; callers must read size via `dma_iova_size(state)` rather than `state->__size`. `dma_iova_free()` only frees the IOVA range without unmapping page tables or SWIOTLB buffers, so active `dma_iova_link()` mappings must be unlinked via `dma_iova_unlink()` first (or `dma_iova_destroy()` used). [F10, F35, F44]
- When `iommu_deferred_attach_enabled` is active, DMA mapping/allocation entry points (`__iommu_dma_map()`, `__iommu_dma_alloc_noncontiguous()`, `iommu_dma_map_sg()`, `dma_iova_try_alloc()`) must call `iommu_deferred_attach()` and abort only on non-zero return. [F31, F124]
- When `attrs & DMA_ATTR_MMIO` is set in `iommu_dma_map_phys()`, `iommu_dma_unmap_phys()`, or `dma_iova_link()`, CPU cache sync and SWIOTLB bouncing must be skipped, and unaligned buffers requiring SWIOTLB bouncing must be rejected. [F127]

## Error Handling

- In `__iommu_dma_alloc_noncontiguous()`, resources acquired in order `__iommu_dma_alloc_pages()`, `iommu_dma_alloc_iova()`, `sg_alloc_table_from_pages()`, and `iommu_map_sg()` must unwind in reverse order (`sg_free_table()`, `iommu_dma_free_iova()`, `__iommu_dma_free_pages()`). [F6]
- Because `iommu_dma_map_sg()` mutates scatterlist entries in place during its setup loop, any error after the loop begins must branch to `out_restore_sg` (or `out_free_iova`) to call `__invalidate_sg(sg, nents)`. In `iommu_dma_map_sg_swiotlb()`, if `iommu_dma_map_phys()` fails on segment `i`, `out_unmap:` must pass `i` (not `nents`) and `attrs | DMA_ATTR_SKIP_CPU_SYNC` to `iommu_dma_unmap_sg_swiotlb()`. [F9, F92]
- Callers of `iommu_map_sg()` (`__iommu_dma_alloc_noncontiguous()`, `iommu_dma_map_sg()`) must store the result in a signed `ssize_t` and check `ret < 0` before comparing against unsigned `size` or `iova_len`. `iommu_dma_alloc_iova()` returns `0` on failure (check `!iova`), whereas `iommu_dma_map_swiotlb()` returns `(phys_addr_t)DMA_MAPPING_ERROR` (check `phys == (phys_addr_t)DMA_MAPPING_ERROR`, not `!phys`). [F28, F29, F30]
- In `iova_reserve_pci_windows()`, the `bridge->dma_ranges` loop must reserve `[start, end]` when `end > start`, fail with `-EINVAL` only on `else if (end < start)` (allowing `end == start`), and set `end = ~(phys_addr_t)0` before `goto resv_iova` on the final entry. [F78]

## External Contracts

- In `iommu_dma_mmap()` and `iommu_dma_mmap_noncontiguous()`, user VMA bounds must be validated with `(vma->vm_pgoff >= count || vma_pages(vma) > count - vma->vm_pgoff)` against `PAGE_ALIGN(size) >> PAGE_SHIFT` before `vm_map_pages()` or `remap_pfn_range()`, returning `-ENXIO` on failure. [F69]
- In `include/linux/iova.h`, external declarations and inline stubs must be guarded by `#if IS_REACHABLE(CONFIG_IOMMU_IOVA)`. `iommu_dma_max_mapping_size()` must return `swiotlb_max_mapping_size(dev)` whenever `dev_is_untrusted(dev)` is true. PCI host bridge window reservations (`iova_reserve_pci_windows()`) belong in `iova_reserve_iommu_regions()` and not in `iommu_dma_get_resv_regions()` (also used by VFIO). [F141, F144, F145]

## Known Pitfalls

- In `__alloc_and_insert_iova_range()`, the backward walk computes `new_pfn = (high_pfn - size) & align_mask` and must check `high_pfn < size` after the loop for unsigned underflow; `retry_pfn + 1` must only be evaluated after `retry_pfn < limit_pfn` (since `retry_pfn` is `IOVA_ANCHOR` `~0UL` at `&iovad->anchor.node`); and `align_mask` must use `fls_long(size - 1)` rather than `__fls(size - 1)` (undefined at `size == 1`). [F64, F98, F101]
- In `iova_insert_rbtree()`, because `new` starts at `&start` (stack parameter address) when `start` is non-NULL, a non-NULL `start` must only be passed when `start` is a valid ancestor of the insertion slot with `iova->pfn_lo != to_iova(start)->pfn_lo` so `while (*new)` advances `new` into `start`'s child pointers before `rb_link_node()`. [F84]
- CPU cache sync guards must use `!(attrs & DMA_ATTR_SKIP_CPU_SYNC)` without combining `!` and `== 0` (`!(attrs & DMA_ATTR_SKIP_CPU_SYNC) == 0` inverts the test). CPU page counts across `dma-iommu.c` alloc, free, vmap, mmap, and sgtable helpers must be computed as `PAGE_ALIGN(size) >> PAGE_SHIFT` rather than `size >> PAGE_SHIFT`. [F75, F103]
- Avoid 32-bit truncation and overflow: cast `unsigned long` PFNs to `dma_addr_t` before left-shifting by `iova_shift(iovad)` in `iova_dma_addr()` and `iommu_dma_alloc_iova()`; cast `(size - 1)` to `phys_addr_t` before `~` (`~(phys_addr_t)(size - 1)`) in `iommu_dma_get_msi_page()`; cast `~0` and `DMA_MAPPING_ERROR` to `phys_addr_t` when comparing/assigning `phys_addr_t`; use `max_len - cur_len >= s_length` in `__finalise_sg()`; and print `phys_addr_t` with `%pa` by address. [F94, F95, F96, F97, F112]
