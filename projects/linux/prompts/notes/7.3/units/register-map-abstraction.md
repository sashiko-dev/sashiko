# REGISTER MAP ABSTRACTION

`include/linux/regmap.h` defines the public interface, configuration structures, inline helpers, polling macros, and `!CONFIG_REGMAP` build stubs for the Linux kernel Register Map (`regmap`) abstraction layer, providing unified register access across buses, register caching (`REGCACHE_FLAT`, `REGCACHE_RBTREE`, `REGCACHE_MAPLE`), bitfield helpers (`regmap_field`), and register-backed interrupt controllers (`regmap_irq_chip`).

## Architecture & Data Flow

- In `struct regmap_irq_chip`, each `irqs[i].reg_offset` and `sub_reg_offsets[b].offset[j]` must be a multiple of `map->reg_stride` with `reg_offset / map->reg_stride < chip->num_regs`. `REGMAP_IRQ_REG_LINE(_id, _reg_bits)` sets `.mask = BIT((_id) % (_reg_bits))` (`unsigned int`) and `.reg_offset = (_id) / (_reg_bits)`, requiring stride 1 and `0 < _reg_bits <= BITS_PER_TYPE(unsigned int)`. Broken by: using `REGMAP_IRQ_REG_LINE` when `reg_stride > 1` or `_reg_bits > 32`. [F48, F59]
- Each `struct regmap_range_cfg` in `regmap_config.ranges` (`num_ranges` entries) must satisfy `range_min <= range_max <= max_register`, `selector_reg <= max_register`, `window_len > 0`, and no `selector_reg` or `[window_start, window_start + window_len - 1]` from any other entry `j != i` may overlap `[range_min, range_max]`. Broken by: leaving `window_len == 0`, `range_max > config->max_register` (e.g., `max_register = 0`), or placing `selector_reg` inside another virtual range. [F47]

## Synchronization

- `regmap_reinit_cache` and `regmap_register_patch` are not fully serialized by `map->lock` (`regmap_reinit_cache` takes no lock and `regmap_register_patch` reallocates `map->patch` before locking), so callers must prevent concurrent regmap accesses during `regmap_reinit_cache` and concurrent `regmap_register_patch` or `regcache_sync` calls. [F14]
- `regmap_read_poll_timeout` and `regmap_field_read_poll_timeout` must not be called from atomic context when `sleep_us` or `timeout_us` is non-zero; `regmap_read_poll_timeout_atomic` is safe in atomic context only if `map` is configured for atomic access (`fast_io` or non-sleeping lock, and `REGCACHE_FLAT` or `REGCACHE_NONE`). Broken by: calling non-atomic poll macros in IRQ/spinlock context, or `_atomic` on a mutex or `REGCACHE_MAPLE`/`REGCACHE_RBTREE` regmap. [F13]
- A `struct regmap_bus` providing `async_write` must serialize asynchronous writes against non-async bus I/O, and callers of `regmap_raw_write_async` must keep the `val` buffer valid until `regmap_async_complete` returns. Broken by: passing a stack-allocated or immediately freed `val` buffer to `regmap_raw_write_async` without waiting for `regmap_async_complete`. [F12]
- When `use_relaxed_mmio` is set in `struct regmap_config` for a little-endian or 8-bit MMIO regmap (`!io_port`), regmap uses `read*_relaxed`/`write*_relaxed` accessors without memory barriers, requiring the driver to issue explicit barriers where ordering against DMA or other memory accesses is needed. [F15]
- Every `regmap_init_*` and `devm_regmap_init_*` macro must invoke `__regmap_init_*` / `__devm_regmap_init_*` through `__regmap_lockdep_wrapper`, which allocates one `static struct lock_class_key` per expansion site. Broken by: calling `__regmap_init*` directly without the wrapper, or wrapping `regmap_init_*` in a shared helper for both parent and nested regmaps without forwarding per-caller `lock_key` and `lock_name`. [F9, F31]

## Object Lifetimes

- In `struct regmap_bus`, setting `free_on_exit` transfers ownership of `bus` to `__regmap_init()`, which calls `kfree(bus)` both on `__regmap_init()` failure and in `regmap_exit()`, whereas `bus->free_context(bus_context)` is called only in `regmap_exit()` and never on `__regmap_init()` failure. Broken by: relying on `__regmap_init()` failure to call `free_context`, or manually calling `kfree(bus)` on failure when `free_on_exit` is set. [F1]
- `__regmap_init()` stores `wr_table`, `rd_table`, `volatile_table`, `precious_table`, `wr_noinc_table`, and `rd_noinc_table` from `struct regmap_config` without copying, and `regmap_add_irq_chip_fwnode()` stores `chip` directly in `d->chip`, so these structures and their nested arrays (`irqs`, `config_base`, `sub_reg_offsets`) must outlive the regmap and IRQ chip. Broken by: stack-allocating or freeing them before `regmap_exit()` / `regmap_del_irq_chip()`. [F4]
- `regmap_field_bulk_alloc` and `devm_regmap_field_bulk_alloc` write element pointers from a single `kcalloc` block into a caller-allocated `rm_field` array of `num_fields` pointers, so `regmap_field_bulk_free` and `devm_regmap_field_bulk_free` must be called once with `rm_field[0]`. Broken by: passing an unallocated `struct regmap_field **` array to `*_bulk_alloc`, or calling `*_bulk_free(rm_field[i])` in a loop. [F28]
- Non-devm regmap resources (`regmap_init*`, `regmap_field_alloc`, `regmap_field_bulk_alloc`, `regmap_add_irq_chip*`) require matching manual teardown (`regmap_exit`, `regmap_field_free`, `regmap_field_bulk_free`, `regmap_del_irq_chip`), while `devm_*` counterparts must not be passed to non-devm teardown functions. [F78]

## API Contracts

- `regmap_update_bits_base()` and its wrappers (`regmap_update_bits`, `regmap_write_bits`, `regmap_set_bits`, `regmap_clear_bits`, `regmap_assign_bits`, `regmap_test_bits`) take pre-shifted full-register bitmasks and values, whereas `regmap_field_*` and `regmap_fields_*` APIs take unshifted field-relative masks and values that regmap shifts by `field->shift`. Broken by: passing unshifted values to `regmap_update_bits`, bit indices instead of `BIT(n)` to `regmap_set_bits`, or pre-shifted masks to `regmap_field_update_bits`. [F93]
- `regmap_bulk_read`, `regmap_bulk_write`, `regmap_multi_reg_read`, and `regmap_bus.reg_noinc_read`/`reg_noinc_write` take `val_count` in register elements and index `val` as an array of `BITS_TO_BYTES(config->val_bits)`-sized (`u8`/`u16`/`u32`) elements, whereas `regmap_raw_*` and `regmap_noinc_read`/`regmap_noinc_write` take `val_len` in bytes. Broken by: passing `sizeof(buf)` as `val_count` to `regmap_bulk_*`, passing a `u32` buffer when `val_bits` is 8 or 16, or treating `val_count` as bytes in `reg_noinc_*` bus callbacks. [F62, F63]
- `regmap_read_poll_timeout*` and `regmap_field_read_poll_timeout` take `val` by lvalue name (passing `&(val)`) and only populate `val` when returning `0` or `-ETIMEDOUT` (leaving `val` uninitialized on read error); passing `timeout_us = 0` disables timeout (polls forever), and `_atomic` widens `timeout_us` to `u64` and re-reads once on timeout before checking `cond`. Broken by: passing `&val`, reading `val` on errors other than `-ETIMEDOUT`, or passing `timeout_us = 0` on bounded hardware waits. [F19, F58, F70]
- In `struct regmap_config`, custom `lock` and `unlock` callbacks override `fast_io` and `use_hwlock` (unless `disable_locking` is true), receive `lock_arg` as their sole parameter, and require `can_sleep` to be set explicitly if the custom lock or bus I/O can sleep. Broken by: providing sleeping `lock`/`unlock` callbacks without `.can_sleep = true`, or setting `lock_arg` expecting default mutex/spinlock callbacks to use it. [F11]
- In `struct regmap_config`, when `cache_type != REGCACHE_NONE`, `reg_defaults` and `num_reg_defaults` must either both be non-zero or both be zero (`regcache_init` duplicates `reg_defaults`), and `num_reg_defaults_raw` must be the number of register elements in `reg_defaults_raw` (not its byte size). Broken by: setting `reg_defaults` with `num_reg_defaults == 0`, or setting `num_reg_defaults_raw = sizeof(defaults_array)` when `val_bits > 8`. [F34, F64]
- Registers with read side effects (such as clear-on-read interrupt status or FIFO-pop registers) must be designated via `regmap_config.precious_reg` or `regmap_config.precious_table` so that regmap never reads them outside explicit driver calls. [F72]
- In `struct regmap_config`, positive values of `reg_shift` downshift (`>>`) and negative values upshift (`<<`) register addresses (after adding `reg_base`), so callers must use `REGMAP_UPSHIFT(s)` (which negates `s`) for a left shift and `REGMAP_DOWNSHIFT(s)` for a right shift. [F57]
- In `struct reg_field` (and `REG_FIELD` / `REG_FIELD_ID`), `msb` must be `>= lsb` and `< BITS_PER_TYPE(unsigned int)`, because `regmap_field_init` computes the `unsigned int` field mask as `GENMASK(reg_field.msb, reg_field.lsb)` and shifts values by `reg_field.lsb`. Broken by: reversing `_lsb` and `_msb` (`_lsb > _msb`) or setting `_msb >= 32`. [F61]
- `regmap_parse_val` reads `BITS_TO_BYTES(config->val_bits)` bytes from `const void *buf` without a buffer-length argument, so callers must ensure `buf` points to at least `regmap_get_val_bytes(map)` bytes. [F68]
- In `struct regmap_irq_chip` passed to `regmap_add_irq_chip*` or `devm_regmap_add_irq_chip*`, setting both `mask_base` and `unmask_base` requires `mask_unmask_non_inverted = true`, and setting `clear_on_unmask` forbids `ack_base` and `use_ack`, or registration fails with `-EINVAL`. [F27]
- When `struct regmap_irq_chip.set_type_config` is set (such as to `regmap_irq_set_type_config_simple`), both `num_config_bases` and `num_config_regs` must be non-zero and `type.type_reg_offset / map->reg_stride` must be less than `num_config_regs`, or `d->config_buf` will be `NULL` or indexed out of bounds. [F67]
- `regmap_del_irq_chip(irq, data)` and `devm_regmap_del_irq_chip(dev, irq, data)` require the exact primary `irq` number passed to `regmap_add_irq_chip*()` (with `devm_regmap_del_irq_chip()` asserting `WARN_ON(irq != data->irq)` and requiring `data` to be non-NULL). Broken by: passing a mapped child virq or `0` instead of the primary `irq`, or `NULL` `data`. [F7]
- When multiple `regmap_irq_chip` controllers are registered for the same device, or when the IRQ domain belongs to a child/alternate firmware node rather than `dev_fwnode(map->dev)`, drivers must set `regmap_irq_chip.domain_suffix` or use `regmap_add_irq_chip_fwnode` / `devm_regmap_add_irq_chip_fwnode`. [F80]
- Setting `regmap_irq_chip.runtime_pm` causes the regmap IRQ controller to hold a runtime PM reference (`pm_runtime_get_sync` / `pm_runtime_put`) on `map->dev` only during IRQ bus `sync_unlock` and threaded IRQ handling; initial register setup in `regmap_add_irq_chip*` and suspend/resume register restoration remain the caller's responsibility. Broken by: calling `regmap_add_irq_chip*` while the device is runtime-suspended. [F81]
- `regmap_init_mdio` and `devm_regmap_init_mdio` require `val_bits == 16` and `reg_bits` of `5` (Clause 22) or `21` (Clause 45, packing the 5-bit device address at `REGMAP_MDIO_C45_DEVAD_SHIFT` under `REGMAP_MDIO_C45_DEVAD_MASK` and 16-bit register under `REGMAP_MDIO_C45_REGNUM_MASK`), returning `ERR_PTR(-EOPNOTSUPP)` otherwise. [F29]
- When `CONFIG_REGMAP` is disabled, `dev_get_regmap()` returns `NULL` silently without calling `WARN_ONCE(1, "regmap API is disabled")`, whereas all operational inline stubs in `include/linux/regmap.h` emit `WARN_ONCE` and fail, and initialization macros (`regmap_init_*`, `devm_regmap_init_*`) are not defined at all. Broken by: adding `WARN_ONCE` to `dev_get_regmap()`, or calling regmap APIs from a driver without `select REGMAP*` or `IS_ENABLED(CONFIG_REGMAP)` guards. [F39, F95]

## Error Handling

- `regmap_test_bits` and `regmap_field_test_bits` return a negative errno if the register read fails, `0` if any tested bit is clear, and `1` if all tested bits are set, so callers must store the result in a signed `int` and check `< 0` before treating non-zero as true. Broken by: `if (regmap_test_bits(...))` or assigning directly to `bool`. [F17]
- `regmap_get_val_bytes` and `regmap_get_max_register` return a signed `int` that is `-EINVAL` on error (when `format_write` is used or `max_register` is unset), so callers must store the return value in a signed variable and check `< 0` before using it as an unsigned byte size or register bound. [F18]
- `regmap_init*`, `devm_regmap_init*`, `regmap_field_alloc`, and `devm_regmap_field_alloc` return an `ERR_PTR()` on failure and never `NULL`, whereas `dev_get_regmap`, `regmap_get_device`, and `regmap_irq_get_domain` return `NULL` (not `ERR_PTR`) and return borrowed pointers without taking a reference. Broken by: mixing up `IS_ERR()` and `!ptr` checks, or calling `regmap_exit()` / `put_device()` on `dev_get_regmap()` / `regmap_get_device()`. [F6, F16]
- A `struct regmap_bus` `gather_write` callback must return `-ENOTSUPP` (specifically `-ENOTSUPP`, not `-EOPNOTSUPP`) when split register/value writes are unsupported on a device so that the regmap core falls back to linearizing the write into a single buffer for `bus->write`. [F24]
- In `regmap_read_poll_timeout` and `regmap_field_read_poll_timeout`, the `read_poll_timeout` break condition must short-circuit on `__ret || (cond)` and the macro must return `__ret ?: __tmp` so that a read failure aborts polling before evaluating `cond` and propagates `__ret` instead of `-ETIMEDOUT` or `0`. [F51]

## External Contracts

- When `regmap_config.reg_format_endian` or `val_format_endian` is `REGMAP_ENDIAN_DEFAULT` (`0`), regmap resolves register endianness from `bus->reg_format_endian_default` and value endianness from device firmware properties (`big-endian`, `little-endian`, `native-endian`) before `bus->val_format_endian_default`, defaulting to `REGMAP_ENDIAN_BIG`. Broken by: hardcoding a non-default `val_format_endian` for a device whose DT/ACPI binding specifies endianness properties. [F46]

## Known Pitfalls

- `regmap_update_bits`, `regmap_set_bits`, `regmap_clear_bits`, `regmap_field_write`, and `regmap_field_update_bits` pass `force = false` to `regmap_update_bits_base` / `regmap_field_update_bits_base`, skipping the bus write when the target bits match the current value; write-1-to-clear or trigger bits require `regmap_write_bits` or `regmap_field_force_write`. [F75]
- In `struct regmap_config`, setting `use_raw_spinlock` only selects a `raw_spinlock_t` when `fast_io` is also set on either `struct regmap_config` or `struct regmap_bus` (and `disable_locking`, custom `lock`/`unlock`, and `use_hwlock` are unset); otherwise `__regmap_init` falls back to a sleeping `struct mutex`. Broken by: setting `.use_raw_spinlock = true` on a non-`fast_io` bus without `.fast_io = true`. [F10]
- In `struct regmap_config`, zero in `max_register` or in both `read_flag_mask` and `write_flag_mask` is treated as unspecified unless the disambiguating boolean `max_register_is_0` or `zero_flag_mask` is explicitly set to `true`. Broken by: configuring a single-register regmap with `max_register = 0` without `max_register_is_0 = true`, or zeroing flag masks to override `regmap_bus.read_flag_mask` without `zero_flag_mask = true`. [F54]
- `REGMAP_IRQ_MAIN_REG_OFFSET(arr)` uses `ARRAY_SIZE((arr))` to populate `struct regmap_irq_sub_irq_map.num_regs`, so `arr` must be a fixed-size `unsigned int` array rather than a pointer, and manual initialization of `num_regs` must use `ARRAY_SIZE(arr)` rather than `sizeof(arr)`. [F66]
