# KERNEL VIRTUAL MACHINE FOR RISC-V (KVM/riscv)

`arch/riscv/kvm` implements the RISC-V KVM backend using the Hypervisor ('H') extension, providing G-stage page tables, VMIDs, HFENCE/TLB flushing, trap/MMIO/CSR emulation, SBI extensions, SBI Nested Acceleration (NACL), per-vCPU timers (SSTC/hrtimer), PMU counters (`perf_events`), FP/Vector context switching, and AIA (APLIC and IMSIC).

## Architecture & Data Flow
- In `kvm_arch_vcpu_load()`, `kvm_arch_vcpu_put()`, `kvm_riscv_vcpu_aia_load()`, and `kvm_riscv_vcpu_aia_put()`, every CSR accessed on the direct `csr_write()`/`csr_read()` path must also be updated in the parallel `nacl_csr_write()`/`nacl_csr_read()` branch; `kvm_arch_vcpu_put()` must never clear `CSR_HGATP`. [F81, F174]
- The `unsigned long` field order of `kvm_cpu_context` (up to `t6`), `kvm_vcpu_csr`, `kvm_vcpu_aia_csr`, and `kvm_vcpu_smstateen_csr` must match UAPI `kvm_riscv_core`, `kvm_riscv_csr`, `kvm_riscv_aia_csr`, and `kvm_riscv_smstateen_csr`, which ONE_REG handlers index as `unsigned long` arrays. [F80]
- Every `KVM_GET_ONE_REG`/`KVM_SET_ONE_REG` handler must validate `KVM_REG_SIZE(reg->id)` before `copy_from_user()`/`copy_to_user()`; in `kvm_riscv_vcpu_vreg_addr()`, `reg_num < KVM_REG_RISCV_VECTOR_REG(0)` must reject `KVM_REG_RISCV_VECTOR_CSR_REG(datap)` with `-ENOENT`, and vector registers must use `cntx->vector.datap` at `(reg_num - KVM_REG_RISCV_VECTOR_REG(0)) * vlenb` with `reg_size == vlenb`. [F85, F133]
- When updating single-letter extensions in `vcpu->arch.isa[0]` in `kvm_riscv_vcpu_set_reg_config()`, preserve `vcpu->arch.isa[0] & ~KVM_RISCV_BASE_ISA_MASK` (`GENMASK(25, 0)`) because multi-letter extension bits live at `>= RISCV_ISA_EXT_BASE` (26). [F140]
- `vcpu->arch.aia_context.imsic_state` is only allocated when `aia_init()` sets `kvm->arch.aia.initialized = true`, and `kvm->arch.aia.aplic_state` remains `NULL` when `nr_sources == 0`; check `kvm_riscv_aia_initialized(kvm)` before IMSIC operations and `aplic_state != NULL` before APLIC operations. [F50]
- `aplic->irqs` (`nr_irqs = nr_sources + 1`) and `imsic->nr_msis` (`nr_ids + 1`) use 1-based IDs with ID 0 reserved: word counts must use `DIV_ROUND_UP(aplic->nr_irqs, 32)` and `BITS_TO_U64(imsic->nr_msis)`, APLIC accessors and `kvm_riscv_aia_aplic_inject()` must reject `!irq || irq >= aplic->nr_irqs`, and IMSIC must keep bit 0 of `EIP0`/`EIE0` zero in `imsic_mrif_rmw()`, skip it in `imsic_mrif_topei()`, and reject `!iid || iid >= imsic->nr_msis` in `kvm_riscv_vcpu_aia_imsic_inject()`. [F94, F95, F127]
- Host guest external interrupt (`hgei`) indices in `aia_hgei_control` and `imsic->vsfile_hgei` are 1-based in `[1, kvm_riscv_aia_nr_hgei]` (bit 0 cleared in `free_bitmap`, `<= 0` unassigned), and `lc->msi_va`/`lc->msi_pa` offsets use `ret * IMSIC_MMIO_PAGE_SZ` since page 0 is the host supervisor file. [F97]
- Accessing a hardware IMSIC VS-file's indirect CSRs (`CSR_VSISELECT`/`CSR_VSIREG`) in `imsic_vsfile_local_*()` must run on `vsfile_cpu`, set `HSTATUS_VGEIN` in `CSR_HSTATUS` to `hgei`, and restore `CSR_HSTATUS` and `CSR_VSISELECT`; on 64-bit (`#ifndef CONFIG_32BIT`), odd `isel` values for `ISELECT_IPRIO0`..`15`, `IMSIC_EIP0`..`63`, and `IMSIC_EIE0`..`63` must be rejected; in APLIC, check enabled+pending via `(irqd->state & APLIC_IRQ_STATE_ENPEND) == APLIC_IRQ_STATE_ENPEND`. [F96, F119, F152]
- In `kvm_riscv_mmu_ioremap()` and `kvm_riscv_gstage_map_page()`, G-stage leaf PTEs must use user-accessible `PAGE_*` protections and `pte_mkdirty()` (never `PAGE_KERNEL_IO`), and `gstage_pte_page_vaddr()` must extract PFNs via `__page_val_to_pfn(pte_val(pte))`; when dirty logging is active on a writable memslot, `kvm_riscv_mmu_map()` must force `vma_pagesize = PAGE_SIZE`, force `writable = false` on `!is_write`, and call `mark_page_dirty_in_slot()` on writes. [F170, F171, F193]
- The per-vCPU `hfence_queue` in `tlb.c` tracks occupancy in-band via `hfence_queue[idx].type != 0` (`KVM_RISCV_HFENCE_UNKNOWN`); `vcpu_hfence_dequeue()` must clear `.type = 0` and `vcpu_hfence_enqueue()` must only write into slots where `.type == 0`. [F102]
- On every VM exit, `kvm_riscv_vcpu_sync_interrupts()` must call `kvm_riscv_vcpu_timer_sync()` to copy `CSR_VSTIMECMP` (`CSR_VSTIMECMPH` on RV32) into `vcpu->arch.timer.next_cycles` when `sstc_enabled` is true; in `kvm_riscv_vcpu_update_hrtimer()` and `kvm_riscv_vcpu_timer_blocking()`, `hrtimer_start()` and `t->next_set = true` must run even when `delta_ns == 0`, with `kvm_riscv_delta_cycles2ns()` clamping `cycles_delta` to `0` when `cycles_now >= cycles`. [F65, F109, F128]
- In `kvm_riscv_vcpu_trap_redirect()`, set `SR_SPP` in `guest_context.sstatus` alongside updating `CSR_VS*` and `guest_context.sepc`; CSR, MMIO, and SBI exit setup must clear `return_handled = 0`, and their `*_return()` handlers must check and set `return_handled = 1` before writing registers and advancing `sepc`. [F69, F83]
- Guest shared-memory GPAs `pmu_context.snapshot_addr` and `sta.shmem` use `INVALID_GPA` (not `0`) when unconfigured and must reset to `INVALID_GPA` on vCPU reset or `SBI_SHMEM_DISABLE` (`-1UL`); `kvm_sbi_sta_steal_time_set_shmem()` must enforce 64-byte alignment (`SZ_64 - 1`) on `shmem_phys_lo`. [F53, F91]

## Synchronization
- In `kvm_arch_vcpu_ioctl_run()`, blocking helpers called while `vcpu->kvm->srcu` is held (`kvm_riscv_check_vcpu_requests()` on `KVM_REQ_SLEEP` and `kvm_riscv_vcpu_wfi()`) must drop and re-acquire `srcu`, and aborting guest entry after `IN_GUEST_MODE` and `kvm_vcpu_srcu_read_unlock()` requires restoring `OUTSIDE_GUEST_MODE`, `local_irq_enable()`, `preempt_enable()`, and `kvm_vcpu_srcu_read_lock(vcpu)`. [F7, F8]
- The guest switch around `__kvm_riscv_switch_to()`/`__kvm_riscv_nacl_switch_to()` must stay in `noinstr` `kvm_riscv_vcpu_enter_exit()` bracketed by `guest_state_enter_irqoff()`/`guest_state_exit_irqoff()` with IRQs disabled, saving `CSR_HTVAL`, `CSR_HTINST`, `CSR_SCAUSE`, `CSR_STVAL`, and `gcntx->sepc` before `local_irq_enable()`, and transiently enabling/disabling IRQs after `kvm_riscv_vcpu_sync_interrupts()` before `guest_timing_exit_irqoff()`. [F157, F158, F159]
- `kvm_riscv_reset_vcpu()` must disable preemption via `get_cpu()`/`put_cpu()` across `kvm_arch_vcpu_put()`, resetting state, and `kvm_arch_vcpu_load()`; in `kvm_sbi_hsm_vcpu_start()`, `target_vcpu->arch.mp_state_lock` must be held across `kvm_riscv_vcpu_stopped()` (checked before `blocking` in `kvm_sbi_hsm_vcpu_get_status()`), `kvm_riscv_vcpu_sbi_request_reset()`, and `__kvm_riscv_vcpu_power_on()`. [F6, F29, F105]
- In `kvm_riscv_vcpu_aia_imsic_update()`, clear the new HGEI's `CSR_HGEIE` bit, zero its VS-file via `imsic_vsfile_local_clear()`, and map G-stage MMIO via `kvm_riscv_mmu_ioremap()` before publishing `vsfile_*` under `write_lock_irqsave(&imsic->vsfile_lock)`. [F21]
- Per-vCPU `CSR_HGEIP`/`CSR_HGEIE` accesses in `kvm_riscv_vcpu_aia_imsic_has_interrupt()`/`kvm_riscv_vcpu_aia_imsic_put()` and MSI injection in `kvm_riscv_vcpu_aia_imsic_inject()` must hold `read_lock_irqsave(&imsic->vsfile_lock, flags)`; when blocking, `imsic_put()` sets `BIT(imsic->vsfile_hgei)` in `CSR_HGEIE`, and `hgei_interrupt()`/`kvm_riscv_aia_disable()` must clear it and call `kvm_vcpu_kick()`. [F27, F156]
- Callers of `imsic_vsfile_read()` and `imsic_vsfile_rw()` must release `imsic->vsfile_lock` and restore IRQs first, and those helpers must pass `wait = 1` to `on_each_cpu_mask()` because their IPI callbacks access caller-stack buffers; `imsic_swfile_extirq_update()` must hold `raw_spin_lock_irqsave(&imsic->swfile_extirq_lock, flags)` across `imsic_mrif_topei()` and `IRQ_VS_EXT` updates, and active `imsic->swfile` accesses while `vsfile_cpu < 0` must use `imsic_mrif_atomic_*`/atomic bitops. [F28, F32, F41, F137]
- In `kvm_riscv_gstage_vmid_update()`, recheck `kvm_riscv_gstage_vmid_ver_changed(vmid)` after acquiring `vmid_lock`; in `kvm_riscv_vcpu_pmu_ctr_cfg_match()`, set `perf_event_attr.disabled = true` before `kvm_pmu_create_perf_event()` so counting starts only on `SBI_PMU_CFG_FLAG_AUTO_START` or `kvm_riscv_vcpu_pmu_ctr_start()`. [F20, F36]

## Object Lifetimes
- In `riscv_kvm_exit()`, call `kvm_exit()` before `kvm_riscv_teardown()` so per-CPU teardown disables AIA and NACL before `kvm_riscv_aia_exit()`/`kvm_riscv_nacl_exit()` free resources; in `kvm_riscv_vcpu_context_reset()`, save and restore `cntx->vector.datap` around zeroing `guest_context`. [F1, F5]
- In `kvm_arch_vcpu_create()`, `kvm_riscv_vcpu_sbi_init()` must run after ISA, PMU, and AIA init and before `kvm_riscv_reset_vcpu()`, and `kvm_riscv_vcpu_sbi_deinit()` must invoke `ext->deinit(vcpu)` whenever `ext_status[idx] != KVM_RISCV_SBI_EXT_STATUS_UNAVAILABLE` (including `DISABLED`). [F3, F4]
- Error paths in `kvm_riscv_aia_aplic_init()` and `kvm_riscv_vcpu_aia_imsic_init()` must reset `aplic_state = NULL` and `imsic_state = NULL` before freeing, and `aia_init()` failure at `idx` must clean up IMSICs `idx - 1`..`0` and APLIC without setting `aia.initialized`. [F13, F55]
- In `kvm_riscv_vcpu_aia_imsic_release()`, reset `vsfile_cpu` and `vsfile_hgei` to `-1` under `vsfile_lock` and call `kvm_riscv_mmu_iounmap()` before reading/clearing the old VS-file and calling `kvm_riscv_aia_free_hgei()`; in `imsic_update()`, if `kvm_riscv_mmu_ioremap()` fails, free `new_vsfile_hgei` without modifying `imsic->vsfile_hgei`. [F14, F15]
- `kvm_pmu_create_perf_event()` must call `kvm_pmu_release_perf_event(pmc)` (setting `pmc->perf_event = NULL`) before creating a new event, and `kvm_pmu_clear_snapshot_area()` must only free `kvpmu->sdata` and reset `snapshot_addr = INVALID_GPA` without writing to guest memory. [F17, F18]

## API Contracts
- `KVM_RUN` loop handlers (`kvm_riscv_vcpu_exit`, `kvm_riscv_vcpu_aia_update`, `kvm_riscv_check_vcpu_requests`, and callees) return `> 0` to resume guest, `0` after setting `run->exit_reason` for userspace exit, or `< 0` on error; `kvm_vcpu_sbi_extension::handler` callbacks must explicitly set `retdata->err_val` on unsupported calls and return `0` for guest SBI errors/traps/userspace exits, returning negative errno only to abort `KVM_RUN`. [F42, F43, F104]
- `sbi_context.ext_status[]` and `riscv_vcpu_get_sbi_ext()` use `enum KVM_RISCV_SBI_EXT_ID` (`< KVM_RISCV_SBI_EXT_MAX`), whereas `kvm_vcpu_sbi_find_ext()` takes `SBI_EXT_*`; in `struct kvm_sbi_fwft_feature`, `.set`/`.get` return `SBI_SUCCESS`/`SBI_ERR_*` and `.set` touches hardware CSRs only when `!one_reg_access`; in-kernel `csr_funcs[]` handlers must return `KVM_INSN_CONTINUE_NEXT_SEPC` without advancing `sepc` or writing `RD` (unmatched CSRs default to `KVM_INSN_ILLEGAL_TRAP`). [F61, F107, F182, F183]
- Static vCPU config writes must return `-EBUSY` once `ran_atleast_once` is true (in `kvm_riscv_vcpu_set_reg_config()`, validate `reg_val` per `reg_num` and break early if unchanged first), AIA config/init writes must return `-EBUSY` once `kvm_riscv_aia_initialized(kvm)` is true, and `kvm_riscv_vcpu_copy_reg_indices()` helpers must accept `uindices == NULL` and return the element count. [F82, F110, F134]
- Guest PMU requires host `SSCOFPMF`, reserves counter index `1` (`CSR_TIME`), requires `kvm_pmu_validate_counter_mask()` before `__ffs`/`__fls` or `pmc[]` indexing, sets `.count = 32` in `KVM_RISCV_VCPU_HPMCOUNTER_CSR_FUNCS`, and sets `exclude_host`, `exclude_hv`, and `RISCV_PMU_CONFIG1_GUEST_EVENTS`; atomic callers of `kvm_riscv_mmu_ioremap()` must pass `in_atomic = true` and top up `pcache` before `kvm->mmu_lock`. [F64, F101, F126, F162, F195]

## Error Handling
- Callers of `kvm_riscv_vcpu_unpriv_read()` must zero-init `struct kvm_cpu_trap` (running with `local_irq_save()`, `a0`/`a1` bindings, `__kvm_riscv_unpriv_trap`, and `.option norvc`) and check `trap->scause != 0` afterward; in `kvm_riscv_mmu_map()`, `KVM_PFN_ERR_HWPOISON` must call `send_sig_mceerr(BUS_MCEERR_AR, ...)` and return `0`; in `kvm_pmu_create_perf_event()`, `perf_event_create_kernel_counter()` failure must log with `pr_debug()` and return `0` with `SBI_ERR_NOT_SUPPORTED`. [F47, F175, F180, F192]

## External Contracts
- Truncate 32-bit SBI inputs via `lower_32_bits()`/`u32`; treat `(cp->a2 == 0 && cp->a3 == 0)` and `cp->a3 == -1UL` as full flushes in `kvm_sbi_ext_rfence_handler()`; use `__le32`/`__le64 __user *` conversions for `struct sbi_sta_struct` in `kvm_riscv_vcpu_record_steal_time()`; require 4-byte aligned `len == 4` MMIO in APLIC/IMSIC with `__swab32()` on `APLIC_SETIPNUM_BE`/`IMSIC_MMIO_SETIPNUM_BE`; and `memset()` `run->system_event` in `kvm_riscv_vcpu_sbi_system_reset()`. [F62, F92, F123, F154, F189]

## Known Pitfalls
- In cross-vCPU handlers, access locks, state, and interrupts on the target cursor (`tmp`/`target_vcpu`), not `vcpu`; in `kvm_sbi_ext_ipi_handler()` when `hbase != -1UL`, check `tmp->vcpu_id >= hbase` and `hart_bit < __riscv_xlen` before `1UL << hart_bit`, and set `SBI_ERR_INVALID_PARAM` if `hmask ^ sentmask` is non-zero. [F106, F121]
- `KVM_DEV_RISCV_AIA_GRP_ADDR` looks up vCPUs via `kvm_get_vcpu(kvm, idx)`, whereas `KVM_DEV_RISCV_AIA_GRP_IMSIC` uses `kvm_get_vcpu_by_id(kvm, vcpu_id)`; guard `GENMASK_ULL` in `aia_imsic_ppn()`/`aia_imsic_hart_index()` against zero `nr_hart_bits`/`nr_group_bits`, and in `kvm_pmu_get_sample_period()` fall back to `GENMASK(pmc->cinfo.width, 0)` when `pmc->counter_val == 0`. [F98, F122, F129]
- For RV32 compatibility: widen shift/mask operands to 64-bit (`1ULL`, `phys_addr_t`, `gpa_t`) when computing GPAs/PAs (`kvm_riscv_gstage_gpa_size`, `kvm_arch_prepare_memory_region`, `kvm_riscv_aia_inject_msi`); size `struct imsic_mrif_eix` bitmaps as `unsigned long [BITS_PER_TYPE(u64) / BITS_PER_LONG]`; and guard `irqs_pending[1]`/`irqs_pending_mask[1]` with `#ifdef CONFIG_32BIT`. [F124, F138, F139]
