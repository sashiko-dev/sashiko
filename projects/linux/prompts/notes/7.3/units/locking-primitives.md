# LOCKING PRIMITIVES

This component provides the core Linux kernel locking primitives—spinlocks, rwlocks, mutexes, rwsems, and seqlocks—alongside the runtime locking correctness validator (`lockdep`) and per-CPU locking event counters (`kernel/locking/lockdep.c` and `kernel/locking/lock_events.c`).

## Architecture & Data Flow

- Helpers (`debug_class_ops_*`, `lock_stats()`, `clear_lock_stats()`, `get_lock_stats()`, `zap_class()`) derive indices into `lock_classes_in_use` and per-CPU stats via `class - lock_classes`. `held_lock::class_idx` and `chain_hlock_class_idx()` are 0-based indices into `lock_classes[MAX_LOCKDEP_KEYS]` and `lock_classes_in_use`, so `hlock_class()`, `lock_chain_get_class()`, and `print_chain_keys_chain()` must index `lock_classes + class_idx` without subtracting 1. [F63, F105]
- Every `struct lock_class` in `lock_classes[]` resides on `all_lock_classes`, `free_lock_classes`, or `delayed_free.pf[].zapped`, and allocating or zapping a class in `register_lock_class()` or `zap_class()` must update `lock_classes_in_use`, `classhash_table`, `nr_lock_classes`, `max_lock_class_idx`, and `nr_unused_locks` in lockstep under the graph lock: `register_lock_class()` increments `nr_unused_locks`, `mark_lock()` decrements it when `usage_mask` transitions from `0` to non-zero, and `zap_class()` decrements it if `usage_mask == 0` while unlinking all `list_entries` where `entry->class == class` or `entry->links_to == class`. [F5, F47, F48]
- In `struct lock_class`, `hash_entry`, `lock_entry`, `locks_after`, and `locks_before` must precede `key` and the struct must remain `__no_randomize_layout`, because `reinit_class()` calls `memset_startat(class, 0, key)` to zero `key` and subsequent fields while preserving those list heads. [F70]
- Every `struct lock_list` entry in `list_entries[]` has its bit set in `list_entries_in_use` iff it is linked into `locks_after` or `locks_before`, and `check_prev_add()` must add or update both `prev->locks_after` (via `calc_dep`) and `next->locks_before` (via `calc_depb`) in lockstep. [F49]
- When `remove_class_from_lock_chain()` zaps a `struct lock_chain`, it must call `free_chain_hlocks()`, reset `chain->chain_key` to `INITIAL_CHAIN_KEY`, call `dec_chains(chain->irq_context)`, unlink `chain->entry`, and defer clearing `lock_chains_in_use` via `pf->lock_chains_being_freed` until `__free_zapped_classes()`. Because `task_irq_context()` sets both `LOCK_CHAIN_HARDIRQ_CONTEXT` and `LOCK_CHAIN_SOFTIRQ_CONTEXT` when a hardirq interrupts a softirq, `inc_chains()` and `dec_chains()` must test `LOCK_CHAIN_HARDIRQ_CONTEXT` before `LOCK_CHAIN_SOFTIRQ_CONTEXT`. [F50, F84]
- When a held lock at index `i` in `curr->held_locks` is modified or released before the top of the stack (`__lock_set_class()`, `__lock_downgrade()`, or `i < depth - 1` in `__lock_release()`), lockdep must rewind `curr->lockdep_depth = i` and `curr->curr_chain_key = hlock->prev_chain_key` and replay subsequent locks via `reacquire_held_locks()`. [F51]
- Reverse scans of `curr->held_locks` in `find_held_lock()`, `check_prevs_add()`, and `get_first_held_lock()` must stop when `irq_context` changes between adjacent entries (`prev_hlock->irq_context != hlock->irq_context`), and `find_held_lock()` and `check_prevs_add()` require `depth > 0` before indexing `curr->held_locks + depth - 1`. [F72]
- `struct lockdep_map::class_cache` only has `NR_LOCKDEP_CACHING_CLASSES` (2) slots whereas `subclass` can reach `MAX_LOCKDEP_SUBCLASSES - 1` (7), so `register_lock_class()` and `__lock_acquire()` must check `subclass < NR_LOCKDEP_CACHING_CLASSES` before indexing `lock->class_cache[subclass]`. Also, `sizeof(struct lock_class_key)` must not exceed `sizeof(struct lockdep_map)` or `sizeof(raw_spinlock_t)` because static locks use their own address as `lock->key` and index `lock->key->subkeys + subclass`. [F69, F98]

## Synchronization

- `lockdep_lock()` and `lockdep_unlock()` must be called with local interrupts disabled: `lockdep_lock()` increments per-CPU `lockdep_recursion` before acquiring `__lock` and setting `__owner = current`, and `lockdep_unlock()` clears `__owner = NULL` and releases `__lock` before decrementing `lockdep_recursion`. Key and class teardown paths (`lockdep_unregister_key()`, `lockdep_free_key_range_reg()`, `lockdep_free_key_range_imm()`, `free_zapped_rcu()`) must acquire `lockdep_lock()` directly rather than `graph_lock()` so matching `lock_class` entries are zapped even when `debug_locks == 0`. [F2, F9]
- Outside selftests (`!inside_selftest()`), `zap_class()` and `remove_class_from_lock_chain()` must unlink entries with RCU primitives, clear `chain->chain_key`, `class->key`, and `class->name` via `WRITE_ONCE()`, stage unlinked classes and chains in `delayed_free.pf[delayed_free.index]` under `lockdep_lock()`, queue `call_rcu(&delayed_free.rcu_head, free_zapped_rcu)` after `lockdep_unlock()`, and defer `__free_zapped_classes()` / `reinit_class()` and `lock_chains_in_use` clearing until `free_zapped_rcu()`. [F23, F121]
- `register_lock_class()`, `lookup_chain_cache_add()`, and `mark_lock()` perform an optimistic lockless check before acquiring `graph_lock()`, and must re-verify that the class, chain, or `usage_mask` bit was not concurrently added after acquiring `graph_lock()`. [F21]
- Lockdep helpers called under `graph_lock`—`save_trace()`, `alloc_list_entry()`, `add_chain_cache()`, `valid_state()`, `mark_lock_irq()`, `check_deadlock()`, and `check_prevs_add()`—drop `graph_lock` before returning failure (`NULL` or `0`), so callers must return immediately on failure without calling `graph_unlock()`. Conversely, `print_usage_bug()` calls `debug_locks_off()` without releasing `graph_lock`, so callers holding `graph_lock` (like `valid_state()`) must call `graph_unlock()` before `print_usage_bug()`. [F7, F37]
- `check_wait_context()` must initialize `curr_inner = task_wait_context(curr)` and test `next_outer > curr_inner` even when `curr->lockdep_depth == 0`, enforcing for any non-trylock acquisition (`!next->trylock`) of a lock with non-zero `wait_type_inner` that `wait_type_outer ?: wait_type_inner` does not exceed `curr_inner` narrowed via `min(curr_inner, prev_inner)` across held locks in the active `irq_context` (unless `LD_LOCK_WAIT_OVERRIDE` resets `curr_inner = prev_inner`). [F79, F119]
- `lock_is_held_type()` and its callees (`lockdep_enabled()`, `check_flags()`, `lockdep_recursion_inc()`, `lockdep_recursion_finish()`, `__lock_is_held()`, `match_held_lock()`, `look_up_lock_class()`) must be `noinstr` or `__always_inline` and use `hlist_for_each_entry_rcu_notrace()`. Diagnostic slow paths inside `noinstr` helpers (`warn_bogus_irq_restore()`, `look_up_lock_class()`, `check_flags()`) must bracket calls to `WARN_ONCE()`, `debug_locks_off()`, `printk()`, `print_irqtrace_events()`, and `dump_stack()` with `instrumentation_begin()` and `instrumentation_end()`. [F113, F114]
- `__lockdep_enabled`, `lockdep_enabled()`, and `lockdep_assert_*()` in `include/linux/lockdep.h` must read per-CPU `lockdep_recursion`, `hardirqs_enabled`, and `hardirq_context` via `this_cpu_read()` because they run in preemptible contexts. In `kernel/locking/lockdep.c`, `lockdep_hardirqs_on_prepare()` and `lockdep_hardirqs_on()` must use `this_cpu_read(lockdep_recursion)` and `__debug_atomic_inc()` before verifying `irqs_disabled()`, whereas after `irqs_disabled()` is confirmed in `lockdep_hardirqs_on()` and `lockdep_hardirqs_off()`, `hardirqs_enabled` writes must use `__this_cpu_write()`. [F115, F116]
- In `spinlock_api_smp.h` and `rwlock_api_smp.h`, blocking lock acquisitions must invoke `spin_acquire()` or `rwlock_acquire*()` before acquiring the arch lock, whereas trylock primitives (`__raw_spin_trylock*`, `raw_spin_trylock_irq*`, `__raw_read_trylock`, `__raw_write_trylock`, `write_trylock_irqsave`) must invoke `spin_acquire()` / `rwlock_acquire*()` only after `do_raw_*_trylock()` succeeds and restore any disabled preemption, BH, or local IRQs on contention. [F16, F30]
- `do_raw_spin_unlock()` must invoke `mmiowb_spin_unlock()` before `arch_spin_unlock(&lock->raw_lock)`, `do_raw_spin_trylock()` must invoke `mmiowb_spin_lock()` only when `arch_spin_trylock()` succeeds, and arch unlock paths emitting `mmiowb()` (`queued_spin_unlock()` on MIPS, `arch_spin_unlock()` on SuperH LL/SC) must execute `mmiowb()` before the lock-release store. `spin_needbreak()` and `rwlock_needbreak()` must check `preempt_model_preemptible()` at runtime before checking lock contention. [F108, F109, F111]
- `write_seqlock*()` and `write_seqcount_begin*()` / `raw_write_seqcount_begin()` must lock `sl->lock` or disable preemption before incrementing `sequence`, `do_write_seqcount_begin_nested()` must call `seqcount_acquire()` before `do_raw_write_seqcount_begin(s)`, and `write_sequnlock*()` / `write_seqcount_end*()` must increment `sequence` before unlocking or re-enabling preemption. Plain `seqcount_t` write-begin helpers require the caller to already have preemption disabled (`lockdep_assert_preemption_disabled()`), whereas `seqcount_mutex_t` on `!PREEMPT_RT` automatically disables/re-enables preemption. [F14, F26, F125]
- On `CONFIG_PREEMPT_RT`, when `__seqprop_##lockname##_sequence()` observes `seq & 1` on a `seqcount_LOCKNAME_t` with a preemptible associated lock (`seqcount_spinlock_t`, `seqcount_rwlock_t`, `seqcount_mutex_t`), it must lock and unlock `s->lock` before re-reading `s->seqcount.sequence` with `smp_load_acquire()`, so readers (`read_seqcount_begin()`, `raw_read_seqcount_begin()`, `raw_read_seqcount()`) cannot run in atomic contexts where taking `s->lock` is invalid. [F28, F126]
- `seqcount_t` and `seqcount_latch_t` read-begin helpers (`__read_seqcount_begin()`, `raw_read_seqcount()`, `read_seqcount_latch()`) must use bounded `kcsan_atomic_next(KCSAN_SEQLOCK_REGION_MAX)` rather than a persistent KCSAN atomic region because callers may exit without `read_seqcount_retry()`, while non-raw `seqcount_latch_t` helpers (`read_seqcount_latch()`, `read_seqcount_latch_retry()`, `write_seqcount_latch_begin()`, `write_seqcount_latch_end()`) must bracket accesses with `kcsan_atomic_next()` and `kcsan_nestable_atomic_begin()`/`end()`. [F13, F27]

## Object Lifetimes

- Dynamically allocated `struct lock_class_key` objects (`!static_obj(key)`) must be registered with `lockdep_register_key()` before being passed to `lockdep_init_map_type()` or used by a lock, and unregistered with `lockdep_unregister_key()` in sleepable process context (`might_sleep()`) before freeing; `lockdep_unregister_key()` must unlink `key->hash_entry` under `lockdep_lock()` even when `!debug_locks` and call `synchronize_rcu_expedited()` before returning. Static keys (`static_obj(key)`) must never be passed to `lockdep_register_key()` or `lockdep_unregister_key()`. [F1, F45, F122, F129]

## API Contracts

- `lock_is_held_type()` returns `LOCK_STATE_UNKNOWN` (-1) when lockdep is disabled or recursing, `LOCK_STATE_NOT_HELD` (0) when not held, and `LOCK_STATE_HELD` (1) when held, so callers must compare against `LOCK_STATE_NOT_HELD` or `LOCK_STATE_HELD` rather than testing boolean truthiness. Unlike `lock_acquire()` (which takes `read` == 0, 1, or 2), `__lock_is_held()` and `lock_is_held_type()` compare `!!hlock->read == read` and only accept `read` == -1 (any), 0 (write), or 1 (any read). [F32, F33]
- `lockdep_init_map_type()` and `STATIC_LOCKDEP_MAP_INIT()` require a non-NULL `name` and a valid static or registered dynamic `key`. `lockdep_init_map_waits()` must forward its outer wait-type parameter to `lockdep_init_map_type()`, and lock reclassification helpers (`lockdep_set_class*()`, `lockdep_set_subclass()`, `__lock_set_class()`) must pass the lock's existing `wait_type_inner`, `wait_type_outer`, and `lock_type` to `lockdep_init_map_type()`. [F43]
- When `CONFIG_DEBUG_LOCK_ALLOC` is disabled, `_nested` and `_nest_lock` macros in `mutex.h`, `rwsem.h`, and `spinlock*.h` must map to the non-nested primitive with the exact same wait, signal, and IO semantics (e.g., `mutex_lock_io_nested` -> `mutex_lock_io`). [F58]

## Error Handling

- Lockdep BFS helpers (`__bfs*`, `check_path`, `find_usage_*`) return `enum bfs_result` where negative values indicate errors (`bfs_error(res)`), `BFS_RMATCH` (0) indicates a match stored in `*target_entry`, and `BFS_RNOMATCH` (1) leaves `*target_entry` unchanged. `alloc_chain_hlocks()` returns a non-negative index into `chain_hlocks[]` on success (0 is valid) and `-1` on failure, so callers must store the result in a signed `int` and check `< 0`. `hlock_class()` returns `NULL` when `hlock->class_idx` is not set in `lock_classes_in_use`, so lockless diagnostic paths (`print_lock()`) must check for `NULL`. [F34, F35, F39]

## External Contracts

- In `kernel/locking/lock_events.c`, every debugfs file using `fops_lockevent` under `lock_event_counts` stores its `enum lock_events` ID cast to `(void *)(long)` in `dentry->d_inode->i_private`, with `LOCKEVENT_reset_cnts` (`== lockevent_num`) valid in `lockevent_names[lockevent_num + 1]` but out of bounds for `lockevents[lockevent_num]`, so `lockevent_read()` must reject `id >= lockevent_num` before indexing `per_cpu(lockevents[id], cpu)`. [F68, F136]

## Known Pitfalls

- Bitwise operations on `struct lock_class::usage_mask` must use shifted `LOCKF_*` constants or `lock_flag(bit)`, whereas `usage_traces[]` indexing and functions taking `enum lock_usage_bit` (`mark_lock`, `valid_state`, `print_usage_bug`) require unshifted `LOCK_*` bit numbers. Furthermore, `class->usage_traces` has `LOCK_TRACE_STATES` entries whereas `usage_str` has an extra entry at `LOCK_USAGE_STATES` (for `verify_lock_unused()`), so `usage_traces[]` indexing must be bounded by `< LOCK_TRACE_STATES`. [F44, F66]
- Because `held_lock::read` stores `1` for normal readers and `2` for recursive readers (`0` for writers), functions distinguishing read-held from write-held locks (`__lock_is_held()`, `__lock_contended()`, `__lock_acquired()`) must normalize `hlock->read` with `!!hlock->read` before comparing or indexing `stats->bounces[]`. [F77]
- Runtime lock initializer wrappers that allocate a per-callsite `static struct lock_class_key __key` (`mutex_init`, `init_rwsem`, `raw_spin_lock_init`, `spin_lock_init`, `rwlock_init`, `seqcount_init`, `seqcount_LOCKNAME_init`, `seqcount_latch_init`, `seqlock_init`) must be macros rather than `static inline` functions. When updating a lock's subclass via `lockdep_set_subclass()` or `lock_set_subclass()`, the existing `(lock)->dep_map.name` pointer must be preserved rather than replaced with `#lock`. `lockdep_copy_map()` must clear every entry of `to->class_cache[]` to `NULL` after `*to = *from`. [F54, F55, F76]
- In `save_trace()`, remaining capacity `MAX_STACK_TRACE_ENTRIES - nr_stack_trace_entries - LOCK_TRACE_SIZE_IN_LONGS` must be stored in a signed `int max_entries` and checked for `<= 0` before calling `stack_trace_save()`, and `stack_trace[]` indexing / `nr_stack_trace_entries` updates are scaled in `unsigned long` units (`LOCK_TRACE_SIZE_IN_LONGS`), whereas `traces_identical()` and `jhash()` scale `trace->nr_entries` by `sizeof(trace->entries[0])` bytes. [F67, F99]
- `size_to_bucket()` maps `size` in `1..MAX_CHAIN_BUCKETS` to `size - 1`, so `alloc_chain_hlocks()` must only pass a split remainder to `add_chain_block(curr + req, size - req)` when `size > req` to avoid indexing `chain_block_buckets[-1]`. `lock_point()` returns `LOCKSTAT_POINTS` when `points[]` is full, so `__lock_contended()` must check `< LOCKSTAT_POINTS` before indexing `stats->contention_point[]` or `stats->contending_point[]`. [F64, F71]
