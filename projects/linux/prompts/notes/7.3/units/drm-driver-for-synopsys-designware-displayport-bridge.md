# DRM DRIVER FOR SYNOPSYS DESIGNWARE DISPLAYPORT BRIDGE

This component implements a DRM bridge driver for the Synopsys DesignWare Cores DisplayPort Transmitter Controller (`dw-dp`). It provides DisplayPort link training (full and fast), AUX channel transactions, EDID reading, Hot-Plug Detect (HPD) handling, Secondary Data Packet (SDP) transmission, and video stream timing/format configuration, exposing `dw_dp_bind()` for SoC display drivers to attach the bridge to a `drm_encoder`.

## Architecture & Data Flow
- `dw_dp_bridge_atomic_duplicate_state()` only duplicates `state->base` via `__drm_atomic_helper_bridge_duplicate_state()`, leaving `struct dw_dp_bridge_state` subclass fields zeroed; therefore, `dw_dp_bridge_atomic_check()` must unconditionally populate `state->video_mapping`, `state->color_format`, `state->bpc`, and `state->bpp` from `dw_dp_get_output_format(bridge_state->output_bus_cfg.format)`, copy the aligned `crtc_state->adjusted_mode` into `state->mode`, and populate any other field read during `dw_dp_bridge_atomic_enable()`. [F37, F83]
- `dp->link.lanes` must never exceed 4 (clamped in `dw_dp_link_parse()` via `min_t(u8, phy_get_bus_width(dp->phy), drm_dp_max_lane_count(link->dpcd))`), because `dw_dp_link_train_update_vs_emph()` and `dw_dp_link_get_adjustments()` use `dp->link.lanes` to index 4-element arrays (`struct dw_dp_link_train_set`, `phy_cfg.dp`, and `u8 buf[4]`). [F40]
- `dp->link.train.adjust.voltage_swing[i]` and `pre_emphasis[i]` store unshifted levels (`0..3`) for `phy_cfg.dp.voltage[i]` and `phy_cfg.dp.pre[i]`, so `dw_dp_link_get_adjustments()` must right-shift values from `drm_dp_get_adjust_request_*()` and `dw_dp_link_train_update_vs_emph()` must left-shift them into `DP_TRAINING_LANE0_SET`. [F24]
- In `dw_dp_link_train_set_pattern()`, changing the training pattern must update `SCRAMBLE_DIS` in `DW_DP_CCTL`, `TPS_SEL` in `DW_DP_PHYIF_CTRL` (via `dw_dp_phy_set_pattern()`), and `DP_TRAINING_PATTERN_SET` in sink DPCD (with `DP_LINK_SCRAMBLING_DISABLE` set iff `pattern` is non-zero and not `DP_TRAINING_PATTERN_4`) in lockstep. [F28]
- In `dw_dp_link_configure()`, `ENHANCE_FRAMING_EN` in `DW_DP_CCTL` and `DP_LANE_COUNT_ENHANCED_FRAME_EN` in the sink `DP_LINK_BW_SET` / `DP_LANE_COUNT_SET` DPCD write must be enabled or disabled together according to `dp->link.caps.enhanced_framing`. [F31]
- In `dw_dp_link_channel_equalization()` and `dw_dp_link_train_fast()`, `link->caps.tps4_supported` must be checked before `link->caps.tps3_supported` when selecting `pattern` so sinks supporting both use `DP_TRAINING_PATTERN_4`. [F46]
- In `dw_dp_link_train_full()`, the `retry:` label must precede `dw_dp_link_train_init(&link->train)` so that every link-rate downgrade via `dw_dp_link_downgrade()` resets `link->train.adjust`, `clock_recovered`, and `channel_equalized` before re-running `dw_dp_link_configure()` and `dw_dp_link_clock_recovery()`. [F49]
- In `dw_dp_link_clock_recovery()`, the `for (;;)` loop must reset `tries = 0` whenever `dw_dp_link_get_adjustments(link, status)` returns `true` and increment `tries` up to 5 only when `!adj_changed`. [F50]
- `dw_dp_link_disable()` must reset `link->train.clock_recovered` and `link->train.channel_equalized` to `false` when powering down the link so `dw_dp_link_train_valid(&link->train)` returns `false` while the link is disabled. [F5]
- In `dw_dp_aux_transfer()`, `msg->request` must be masked with `~DP_AUX_I2C_MOT` in the `switch` dispatch so middle-of-transaction I2C requests match `DP_AUX_I2C_WRITE`, `DP_AUX_I2C_WRITE_STATUS_UPDATE`, and `DP_AUX_I2C_READ`, while the unmasked `msg->request` is written to `AUX_CMD_TYPE` in `DW_DP_AUX_CMD`. [F45]
- `dw_dp_aux_transfer()` must reject `msg->size > 16` before calling `dw_dp_aux_write_data()` or `dw_dp_aux_read_data()`, because the hardware AUX data buffer consists of only four 32-bit registers (`DW_DP_AUX_DATA0`..`DW_DP_AUX_DATA3`) and `dw_dp_readable_ranges` forbids reading past `DW_DP_AUX_DATA3`. [F38]
- In `dw_dp_handle_hpd_event()`, `HPD_IRQ`, `HPD_HOT_PLUG`, and `HPD_HOT_UNPLUG` in `DW_DP_HPD_STATUS` must be tested with separate `if` statements rather than `else if`, with `HPD_HOT_PLUG` and `HPD_HOT_UNPLUG` evaluated after `HPD_IRQ` so every pending status bit is cleared and a concurrent plug/unplug overrides `dp->hotplug.long_hpd` to `true`. [F47]
- Each SDP bank index `nr` allocated from `dp->sdp_reg_bank` (`0 <= nr < SDP_REG_BANK_SIZE`) maps to a 9-register (36-byte) stride at `DW_DP_SDP_REGISTER_BANK + nr * 9 * 4` and enable bit `BIT(2) << nr` (`EN_VERTICAL_SDP << nr` / `EN_HORIZONTAL_SDP << nr`); bit 0 must be pre-reserved via `set_bit(0, dp->sdp_reg_bank)` in `dw_dp_bridge_atomic_enable()` before `dw_dp_video_enable()` calls `dw_dp_send_sdp()`, and `dp->sdp_reg_bank` must be cleared via `bitmap_zero()` in `dw_dp_bridge_atomic_disable()`. [F42, F72]
- When `dw_dp_video_need_vsc_sdp(dp)` is true, `dw_dp_video_set_msa()` must set `DP_MSA_MISC_COLOR_VSC_SDP` in `DW_DP_VIDEO_MSA2` (`MISC0`) and `dw_dp_video_enable()` must send the corresponding VSC SDP packet via `dw_dp_send_vsc_sdp(dp)`. [F36]

## Synchronization
- `dw_dp_aux_transfer()` (and DPCD/DDC helpers using `dp->aux`) must never be called from `dw_dp_irq()`, while `dp->irq` is disabled in `dw_dp_reset()`, or while holding `dp->irq_lock`, because `dw_dp_aux_transfer()` waits on `dp->complete` which is signaled in `dw_dp_irq()` after `dw_dp_handle_hpd_event()` takes `dp->irq_lock`. [F74]
- `dw_dp_hpd_work()` must release `dp->irq_lock` before calling `dw_dp_link_retrain()`, `drm_helper_hpd_irq_event()`, or any call that acquires DRM modeset locks. [F10]
- Updates and reads of `dp->hotplug.long_hpd` together with clearing the HPD interrupt status bits in `DW_DP_HPD_STATUS` across `dw_dp_handle_hpd_event()` and `dw_dp_hpd_work()` must be serialized under `dp->irq_lock`. [F9]
- `dw_dp_irq()` must be registered as a threaded interrupt handler (`devm_request_threaded_irq()` with `IRQF_ONESHOT` and a `NULL` hardirq handler) because `dw_dp_handle_hpd_event()` acquires the sleeping mutex `dp->irq_lock`. [F73]
- When retraining the link asynchronously (`dw_dp_link_retrain()` from `dw_dp_hpd_work()`), after `drm_modeset_acquire_init(&ctx, 0)`, `dev->mode_config.connection_mutex` must be locked via `drm_modeset_lock()` before calling `dw_dp_link_train()`, handling `-EDEADLK` via `drm_modeset_backoff(&ctx)` before retrying, and every exit path must call `drm_modeset_drop_locks(&ctx)` followed by `drm_modeset_acquire_fini(&ctx)`. [F6, F76]

## Object Lifetimes
- `struct dw_dp_bridge_state` must keep `struct drm_bridge_state base` as its first member at offset 0 and must not own dynamically allocated sub-resources, because `dw_dp_bridge_funcs.atomic_destroy_state` is bound directly to `drm_atomic_helper_bridge_destroy_state`, which frees the state via `kfree(state)`. [F1]
- In `dw_dp_bind()`, `dp->irq_lock`, `dp->hpd_work`, `dp->complete`, `dp->regmap`, `dp->bridge` attachment, and `dw_dp_init_hw()` must be initialized before `devm_request_threaded_irq()` registers `dw_dp_irq()`. [F13]
- In `dw_dp_bind()`, `phy_init(dp->phy)` must be immediately paired with `devm_add_action_or_reset(dev, dw_dp_phy_exit, dp)` before any subsequent fallible initialization steps so `phy_exit(dp->phy)` runs automatically on probe failure or device teardown. [F8]
- Before performing AUX transactions in `dw_dp_hpd_detect_link()`, `dw_dp_bridge_edid_read()`, or `dw_dp_link_enable()`, `dp->phy` must be powered on with `phy_power_on(dp->phy)` and balanced with `phy_power_off(dp->phy)` when detection/EDID read completes or in `dw_dp_link_disable()`. [F81]
- `dw_dp_bind()` must copy the contents of `plat_data` by value into `dp->plat_data` rather than storing the `const struct dw_dp_plat_data *plat_data` pointer. [F61]

## API Contracts
- `dw_dp_link_clock_recovery()` and `dw_dp_link_channel_equalization()` return a negative errno only on PHY or DPCD communication failure and return `0` even when training fails after retries, recording logical completion in `dp->link.train.clock_recovered` and `dp->link.train.channel_equalized`. Broken by: assuming a `0` return means training succeeded without checking `clock_recovered` or `channel_equalized`. [F15]
- Callers of `dw_dp_send_sdp()` (such as `dw_dp_send_vsc_sdp()`) must zero-initialize `struct dw_dp_sdp` before populating it because `dw_dp_send_sdp()` unconditionally writes all 32 bytes of `sdp->base.db` across eight 32-bit registers regardless of the length in `sdp->base.sdp_header.HB3`. [F20]
- When calling `phy_configure(dp->phy, &phy_cfg)` with a stack-allocated `union phy_configure_opts`, `dw_dp_link_train_update_vs_emph()` and `dw_dp_phy_configure()` must explicitly initialize all three `phy_cfg.dp` action flags (`set_lanes`, `set_rate`, and `set_voltages`). [F78]
- Link rates in `dw_dp_plat_data.max_link_rate` and `dw_dp_link.rate` are stored in kHz (matching `drm_dp_max_link_rate()` and `drm_dp_link_rate_to_bw_code()`), so `dw_dp_link_parse()` must multiply `dp->phy->attrs.max_link_rate` by 100 and `dw_dp_phy_configure()` must divide `rate` by 100 to convert to/from the Generic PHY Mb/s unit. [F77]
- `dw_dp_get_bridge_state()` and `dw_dp_get_output_format()` return borrowed pointers (to `dp->bridge.base.state` and `dw_dp_output_formats` respectively), whereas `dw_dp_bridge_edid_read()` and `dw_dp_bridge_atomic_get_output_bus_fmts()` transfer ownership of their heap-allocated return values to the DRM caller. [F2]
- Callers of `dw_dp_bind()` must pass an already-initialized `struct drm_encoder` with `encoder->dev` populated and must create the connector separately (e.g. via `drm_bridge_connector_init()`), because `dw_dp_bind()` sets `dp->aux.drm_dev = encoder->dev` and calls `drm_bridge_attach()` with `DRM_BRIDGE_ATTACH_NO_CONNECTOR`. [F62]

## Error Handling
- In `dw_dp_link_train_update_vs_emph()`, `dw_dp_link_configure()`, and `dw_dp_link_train_set_pattern()`, calls to `drm_dp_dpcd_write()` and `drm_dp_dpcd_writeb()` return positive byte counts on success and negative errnos on failure, so `ret < 0` must be checked and the return value normalized to `0` on success. [F14]
- In `dw_dp_link_train_full()` and `dw_dp_link_train_fast()`, every exit path after `dw_dp_link_configure()` succeeds must jump to `out:` to execute `dw_dp_link_train_set_pattern(dp, DP_TRAINING_PATTERN_DISABLE)` so training patterns are cleared and scrambling is restored, without overwriting `ret` from the preceding training or downgrade step. [F7, F16]
- In `dw_dp_aux_transfer()`, `ssize_t ret` must be initialized to `0` prior to dispatching on `msg->request` so that 0-byte (`I2C_ADDR_ONLY`) transfers and non-`DP_AUX_NATIVE_REPLY_ACK` read replies return `0` after populating `msg->reply`. [F22]
- In `dw_dp_aux_transfer()`, `WARN_ON` is reserved for the caller contract violation `msg->size > 16` (returning `-E2BIG`), while sink/link timeouts and short reads return `-ETIMEDOUT` or `-EBUSY` without `WARN_ON` so that `drm_dp_aux` helpers can retry or propagate transient AUX failures cleanly. [F80]

## External Contracts
- `dw_dp_bridge_atomic_get_output_bus_fmts()` must allocate `output_fmts` as a heap array of `u32` elements and write the populated element count `j` (not the byte size) to `*num_output_fmts`. [F58]

## Known Pitfalls
- Interrupt event bits in `DW_DP_GENERAL_INTERRUPT` (`AUX_REPLY_EVENT`) and `DW_DP_HPD_STATUS` (`HPD_IRQ`, `HPD_HOT_PLUG`, `HPD_HOT_UNPLUG`) are write-1-to-clear and must be cleared with `regmap_write()` of only the specific bit mask being acknowledged, never `regmap_update_bits()`. [F66]
- `DW_DP_PHYIF_CTRL` uses two different lane encodings and requires P3 powerdown during rate/lane reconfiguration: in `dw_dp_phy_configure()`, the controller must set `PHY_POWERDOWN = 0x3` (P3) before calling `phy_configure()` and programming `PHY_LANES` as `lanes / 2` (encoding 1, 2, 4 as 0, 1, 2), and return `PHY_POWERDOWN` to `0x0` (P0) before calling `dw_dp_phy_xmit_enable()`; in `dw_dp_phy_xmit_enable()`, `XMIT_ENABLE` takes `GENMASK(lanes - 1, 0)` only when `lanes` is `1`, `2`, or `4`, while `0` and other values must assign `xmit_enable = 0` to avoid unsigned underflow of `lanes - 1`. [F41, F52, F69]
- In `dw_dp_send_sdp()`, `sdp->base.sdp_header` and the eight 4-byte chunks of `sdp->base.db` (`u8 db[32]` in `__packed struct dp_sdp`) must be read using `get_unaligned_le32()`, and `payload` must remain a `const u8 *` pointer because the loop advances `payload += 4` over 8 iterations (`i = 1..8`) to cover 32 bytes. Broken by: casting directly to `const u32 *` or changing `payload` to `const u32 *` while keeping `payload += 4`. [F43, F57]
- `dw_dp_aux_write_data()` and `dw_dp_aux_read_data()` must iterate `DIV_ROUND_UP(size, 4)` times over the 32-bit `DW_DP_AUX_DATA0` registers and clamp each word's byte count with `min_t(size_t, size - i * 4, 4)` so trailing partial words are not dropped and the byte shift `j * 8` stays within `0..24`. [F54]
