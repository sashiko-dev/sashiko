# ETHERNET PHY LIBRARY

Provides MDIO bus controllers, MDIO bus multiplexers, OpenFirmware/ACPI/fwnode MDIO registration helpers, XPCS platform glue, and vendor Ethernet PHY drivers/libraries (including Aquantia, Broadcom, Airoha EN8811H, ADIN1100, and AX88796B). It bridges hardware MDIO/I2C/GPIO/MMIO interfaces and firmware descriptions to the kernel phylib, hwmon, LED, clock, and PTP timestamping subsystems.
Contains Ethernet PHY device drivers for Broadcom (BCM54140, BCM63xx, BCM7xxx, BCM84881, BCM87xx), Texas Instruments DP83xxx series (including DP83640 with PTP hardware clock), Marvell automotive/transceiver PHYs (88Q2xxx, 88X2222), Intel XWAY, ICPlus, LXT, Cicada, Cortina, Davicom, ET1011C, plus the fixed-PHY emulation bus (`fixed_phy.c`) and linkmode pause negotiation helpers (`linkmode.c`).
Implements the core MDIO bus and device subsystem (`mdio_bus.c`, `mdio_bus_provider.c`, `mdio_device.c`, `mdio_devres.c`) along with major Ethernet PHY drivers for Marvell (`marvell.c`), Micrel/Microchip (`micrel.c`, `microchip.c`), Meson GXL (`meson-gxl.c`), and the Microchip RDS PTP timestamping library (`microchip_rds_ptp.c`). It manages `mii_bus` lifecycle, Clause 22/45 bus transfers and locking, MDIO device discovery and reset control, sysfs statistics, and complex multi-port PHY features including PTP, hwmon, SFP, and cable diagnostics.
Contains the Small Form-factor Pluggable (SFP) cage state machine and bus infrastructure (`sfp.c`, `sfp-bus.c`, `sfp.h`), Realtek (`realtek/`), SMSC (`smsc.c`), Vitesse (`vitesse.c`), STE10Xp, Teranetics, uPD60620, and Xilinx GMII2RGMII PHY drivers, software PHY register emulation (`swphy.c`), OpenFirmware network helpers (`net/core/of_net.c`), and the core public/UAPI headers for phylib, MDIO, and MII (`include/linux/phy.h`, `include/linux/mdio.h`, `include/linux/mii.h`, `include/uapi/linux/mdio.h`, `include/uapi/linux/mii.h`).

## Architecture & Data Flow

- In `of_phy_register_fixed_link()`, `struct fixed_phy_status status` must be zero-initialized (`= {}`) at declaration because the `"in-band-status"` branch jumps directly to `register_phy:` without assigning any fields, relying on `status.link` and all other members being zero. [F47]
- In drivers/net/phy/air_en8811h.c, manual LED updates in air_hw_led_on_set() (when !on), air_led_blink_set(), and air_led_brightness_set() must clear priv->led[index].rules to 0, while air_led_hw_control_set() must clear AIR_PHY_LED_STATE_FORCE_ON and AIR_PHY_LED_STATE_FORCE_BLINK in priv->led[index].state. [F57]
- In drivers/net/mdio/mdio-mux-multiplexer.c, mdio_mux_multiplexer_switch_fn() and mdio_mux_multiplexer_remove() must only call mux_control_deselect(s->muxc) when s->do_deselect is true, and mdio_mux_multiplexer_switch_fn() must update s->do_deselect to true only when mux_control_select() succeeds and false when it fails. [F59]
- In drivers/net/phy/bcm-phy-ptp.c, any operation under priv->mutex that triggers a CPU framesync on NSE_CTRL must first clear NSE_FRAMESYNC_MASK | NSE_CAPTURE_EN via bcm_ptp_framesync_disable(), call bcm_ptp_framesync(), and restore priv->nse_ctrl via bcm_ptp_framesync_restore(). [F63]
- In drivers/net/phy/bcm-phy-ptp.c, bcm_ptp_settime_locked() must pass NSE_INIT to bcm_ptp_framesync() so SHADOW_LOAD (TIME_CODE_LOAD | NCO_TIME_LOAD) takes effect and auto-clears, whereas bcm_ptp_adjfine() triggers bcm_ptp_framesync() without NSE_INIT and must explicitly write 0 to SHADOW_LOAD after loading FREQ_LOAD. [F64]
- In drivers/net/phy/bcm-phy-ptp.c, reading captured timestamps in bcm_ptp_get_framesync_ts() and bcm_ptp_get_tstamp() must begin by writing HB_READ_START to HB_STAT_CTRL (or TS_READ_START to TS_READ_CTRL) and finish by writing HB_READ_END followed by 0 to HB_STAT_CTRL (or TS_READ_END followed by 0 to TS_READ_CTRL). [F65]
- In drivers/net/phy/aquantia/, aqr_phy_led_polarity_set() must record active-low and active-high LED indices in priv->leds_active_low and priv->leds_active_high, and aqr_gen1_config_init() must iterate over both bitmasks after reset to restore LED polarity via aqr_phy_led_active_low_set(). [F67]
- In drivers/net/phy/air_en8811h.c, en8811h_probe() initializes priv->mcu_needs_restart to false after en8811h_load_firmware(), and en8811h_config_init() must set priv->mcu_needs_restart to true on its first execution and call en8811h_restart_mcu(phydev) on subsequent executions before writing AIR_PHY_MCU_CMD_1..4. [F68]
- In drivers/net/phy/bcm-cygnus.c, bcm_omega_config_init() and bcm_omega_set_tunable() (for ETHTOOL_PHY_DOWNSHIFT) must keep EEE state coupled with downshift by calling bcm_phy_set_eee(phydev, count == DOWNSHIFT_DEV_DISABLE), and bcm_omega_set_tunable() must then call genphy_restart_aneg(phydev). [F69]
- In drivers/net/mdio/mdio-cavium.c, every Clause 22 or Clause 45 bus operation must call cavium_mdiobus_set_mode(p, C22) or cavium_mdiobus_set_mode(p, C45) before issuing SMI_CMD, keeping p->mode synchronized with the mode bit in SMI_CLK. [F71]
- In drivers/net/phy/bcm-phy-lib.h, any change to the signatures of bcm_ptp_probe(), bcm_ptp_config_init(), or bcm_ptp_stop() in drivers/net/phy/bcm-phy-ptp.c must update both the IS_ENABLED(CONFIG_BCM_NET_PHYPTP) declarations and the #else static inline stubs in drivers/net/phy/bcm-phy-lib.h. [F73]
- In drivers/net/phy/aquantia/aquantia.h, any change to the signature of aqr_hwmon_probe() in drivers/net/phy/aquantia/aquantia_hwmon.c must update both the IS_REACHABLE(CONFIG_HWMON) declaration and the #else static inline stub in drivers/net/phy/aquantia/aquantia.h. [F74]
- In aqr_fw_boot(), iram_offset and dram_offset read from struct aqr_fw_header must have primary_offset added to them, and both sections must be validated with aqr_fw_validate_get() and checked for sizeof(u32) size alignment before calling aqr_fw_load_memory(). [F75]
- LED callbacks in air_en8811h.c must reject index >= EN8811H_LED_COUNT with -EINVAL before indexing priv->led[index] or computing register addresses with AIR_PHY_LED_ON(index) and AIR_PHY_LED_BLINK(index), and en8811h_led_hw_is_supported() must reject rules & ~en8811h_led_trig with -EOPNOTSUPP. [F78]
- Aquantia LED callbacks in aquantia_leds.c must reject index >= AQR_MAX_LEDS with -EINVAL before accessing AQR_LED_PROV(index), AQR_LED_DRIVE(index), or setting BIT(index) in priv->leds_active_low and priv->leds_active_high, and aqr_phy_led_hw_is_supported() must reject rules & ~supported_triggers with -EOPNOTSUPP. [F79]
- In bcm_phy_led_brightness_set(), index must be validated to be < 4 before mapping indices 0..1 to BCM54XX_SHD_LEDS1 and 2..3 to BCM54XX_SHD_LEDS2 with 4-bit shift BCM54XX_SHD_LEDS_SHIFT(index % 2). [F88]
- In mdio_mux_mmioreg_probe(), s->iosize must be validated to be 1, 2, or 4 bytes, the 'mux-mask' property must fit within s->iosize * 8 bits, and every child node's 'reg' value must have no bits set outside s->mask because mdio_mux_mmioreg_switch_fn() ORs desired_child directly into (x & ~s->mask). [F93]
- In pcs-xpcs-plat.c, xpcs_plat_init_res() must validate that pxpcs->reg_width is 2 or 4 and that resource_size(res) is at least pxpcs->reg_width * SZ_256 for indirect mode or pxpcs->reg_width * SZ_2M for direct mode, and all xpcs_mmio_read/write callbacks must reject addr != 0 with -ENODEV. [F95]
- Lookup tables passed to sentinel-terminated kernel APIs, specifically whitelist_phys[] in of_mdio.c (passed to of_match_node()) and aqr_hwmon_info[] in aquantia_hwmon.c (passed via aqr_hwmon_chip_info to devm_hwmon_device_register_with_info()), must retain their trailing {} or NULL sentinel entry. [F96]
- In `bcm_ptp_txtstamp`, `HWTSTAMP_TX_ONESTEP_P2P` and `HWTSTAMP_TX_ONESTEP_SYNC` must fall through into `HWTSTAMP_TX_ON` so one-step packets (`PTP_MSGTYPE_PDELAY_RESP` and `PTP_MSGTYPE_SYNC`) are queued on `priv->tx_queue` with `BCM_SKB_CB(skb)->discard = true` to drain their hardware TX timestamps. [F104]
- In `bcm_phy_get_wol`, when `ctl & BCM54XX_WOL_DIR_PKT_EN` is set, `is_broadcast_ether_addr(da)` must be checked before `is_multicast_ether_addr(da)` because the broadcast MAC address `FF:FF:FF:FF:FF:FF` has the least-significant bit of its first octet set and would otherwise match `is_multicast_ether_addr(da)`. [F108]
- In `bcm_phy_handle_interrupt`, the Interrupt Mask Register value read from `MII_BCM54XX_IMR` has active-low enable polarity (where a set bit means masked), so `irq_mask` must be bitwise-inverted (`irq_mask = ~irq_mask`) before testing `!(irq_status & irq_mask)`. [F109]
- In `mdio_i2c_alloc`, `smbus_byte_mii_read_default_c22` and `smbus_byte_mii_write_default_c22` must only be selected when `i2c_check_functionality(i2c, I2C_FUNC_SMBUS_BYTE_DATA)` is true and `!i2c_check_functionality(i2c, I2C_FUNC_I2C)` is true. [F110]
- In `of_mdiobus_child_is_phy`, a child node with a `compatible` property that does not match `of_get_phy_id`, `ethernet-phy-ieee802.3-c45`, `ethernet-phy-ieee802.3-c22`, or `whitelist_phys` must return `false` so `__of_mdiobus_parse_phys` registers it via `of_mdiobus_register_device`. [F111]
- In `aqr_hwmon_probe`, the in-place compaction loop `for (i = j = 0; hwmon_name[i]; i++)` must only advance destination index `j` when `isalnum(hwmon_name[i])` is true and must write the NUL terminator at `hwmon_name[j] = '\0'` after the loop. [F112]
- Both `ipq4019_mdio_select_mdc_rate` and `ipq4019_mdio_set_div` must compute MDC frequency using `DIV_ROUND_UP(ahb_rate, div)` (or `div + 1` when reading `MDIO_MODE_DIV_MASK`) so the default rate does not exceed 2.5 MHz and matches the exact equality check `priv->mdc_rate == DIV_ROUND_UP(ahb_rate, div)`. [F120]
- `mscc_miim_clk_set` must return early when `miim->bus_freq` is zero, compute the prescaler with ceiling division `DIV_ROUND_UP(rate, 2 * miim->bus_freq) - 1`, and reject `div == 0` or `div & ~MSCC_MIIM_CFG_PRESCALE_MASK` before writing `MSCC_MIIM_REG_CFG`. [F121]
- Because `g12a_ephy_pll_recalc_rate` divides `parent_rate * m` directly by `n = FIELD_GET(PLL_CTL0_N, val)` without a zero check, `ETH_PLL_CTL0` must always be initialized with a non-zero `PLL_CTL0_N` field in `g12a_ephy_pll_init` before rate recalculation. [F122]
- In drivers/net/pcs/pcs-xpcs-plat.c, because dw_xpcs_plat::reg_base is a byte-addressed void __iomem * pointer, every MMIO register offset (DW_VR_CSR_VIEWPORT, ofs, or csr) must be explicitly scaled by pxpcs->reg_width (<< 2 for 4-byte width or << 1 for 2-byte width). [F129]
