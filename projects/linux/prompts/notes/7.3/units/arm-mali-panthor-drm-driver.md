# ARM MALI PANTHOR DRM DRIVER

The Panthor DRM driver (`drivers/gpu/drm/panthor`) manages ARM Mali Valhall (Gen 10+) GPUs with a Command Stream Frontend (CSF) microcontroller, providing GEM shmem buffer management, `io-pgtable` and `drm_gpuvm` virtual memory (sync/async `VM_BIND`), firmware loading and host-MCU interfaces, timeslice-based command stream group (CSG) scheduling via `drm_gpu_scheduler`, tiler heap management, and devfreq/runtime PM.

## Architecture & Data Flow

- Hardware MMU AS slot 0 is reserved for the MCU VM (`vm->for_mcu`): user VMs allocate from bit 1 (`ffz(ptdev->mmu->as.alloc_mask | BIT(0))`), and `sched->as_slot_count` masks out bit 0 (`as_present & GENMASK(31, 1)`). `alloc_mask` must remain `unsigned long` for bitops. Under `slots_lock`, `panthor_vm_release_as_locked()` must clear `slots[vm->as.id].vm`, clear `vm->as.id` in `alloc_mask`, reset `active_cnt = 0`, remove `lru_node`, and set `vm->as.id = -1`. [F71, F101, F154]
- CSG slot IDs (`csg_id`) are 0-based in `[0, MAX_CSGS - 1]` (`MAX_CSGS` is 31 as bit 31 of `JOB_INT_*` is `JOB_INT_GLOBAL_IF`), whereas queue doorbell IDs in `group_bind_locked()` are 1-based (`csg_id + 1`) because doorbell 0 is `CSF_GLB_DOORBELL_ID`. In `process_fw_events_work()`, `JOB_INT_GLOBAL_IF` (`BIT(31)`) must be cleared from `events` before the `while (events)` loop extracts `csg_id = ffs(events) - 1`. [F100, F121]
- When `csg_slot_sync_state_locked()` transitions a `panthor_group` out of `PANTHOR_CS_GROUP_ACTIVE`, it must call `cs_slot_reset_locked()` on every queue to set `CS_STATE_STOP` and suspend the queue timeout unless the queue is in `group->blocked_queues`. In `cs_slot_sync_queue_state_locked()`, `CS_STATUS_BLOCKED_REASON_SYNC_WAIT` only sets `BIT(cs_id)` in `group->blocked_queues` when `cs_iface->output->status_scoreboards == 0`. In `group_schedule_locked()`, wakeup is skipped only if `(queue_mask & group->blocked_queues) == queue_mask`. [F74, F75, F128]
- When `CSG_STATE_SUSPEND` times out in `panthor_sched_suspend()`, each affected `csg_slot->group` must be marked `timedout = true` (and `innocent = true` if `group_can_run()` held) before escalating to `CSG_STATE_TERMINATE`. In `tick_ctx_apply()`, both loops over `ctx->groups[prio]` must initialize `new_csg_prio = MAX_CSG_PRIO` and decrement `new_csg_prio` on every iteration (including `continue` branches). [F76, F120]
- `queue_run_job()` must update `queue->fence_ctx.last_fence` with a reference to `job->done_fence` on every non-empty job, and for sync-only jobs (`!job->call_info.size`) assign and return a reference to `queue->fence_ctx.last_fence`. Before calling `drm_sched_start(&queue->scheduler, 0)`, `queue_start()` must restore `job->base.s_fence->parent = dma_fence_get(job->done_fence)` for every job in `pending_list`. [F78, F86]
- `prepare_job_instrs()` must zero-pad `instrs->buffer` up to `ALIGN(instrs->count, NUM_INSTRS_PER_CACHE_LINE)` before updating `instrs->count`. Because ringbuffer pointers `insert` and `extract` are monotonically increasing 64-bit byte offsets, `copy_instrs_to_ringbuf()` must mask `job->ringbuf.start` with `ringbuf_size - 1` (requiring power-of-two `ringbuf_size` in `group_create_queue()`) and split wrapping writes. [F61, F102]
- Every chunk addition or removal in `panthor_alloc_heap_chunk()`, `panthor_free_heap_chunk()`, and `panthor_heap_return_chunk()` must update `heap->chunks` and `heap->chunk_count` under `heap->lock` in lockstep with `atomic_add()`/`atomic_sub()` of `heap->chunk_size` on `pool->size`. Heap contexts in `pool->gpu_contexts` are spaced by `panthor_heap_ctx_stride(ptdev)` (L2-aligned `HEAP_CONTEXT_SIZE`), not `HEAP_CONTEXT_SIZE`. [F91, F149]
- `panthor_heap_pool::xa` uses 0-based `XA_FLAGS_ALLOC` (`XA_LIMIT(0, MAX_HEAPS_PER_POOL - 1)`) in `panthor_heap_create()` because `panthor_get_heap_ctx_offset()` indexes `pool->gpu_contexts` directly by ID. `panthor_vm_pool::xa` and `panthor_group_pool::xa` use 1-based `XA_FLAGS_ALLOC1` (`XA_LIMIT(1, ...)`) so handle 0 means "no handle". Callers of all three must check `ret < 0` and reset `ret = 0` after extracting the ID. [F50, F95, F96]
- `panthor_vm_prepare_map_op_ctx()` must compute `pt_count` by aligning `va + size` up and `va` down to each level boundary (`1ull << 39`, `1ull << 30`, `1ull << 21`), and `panthor_vm_prepare_unmap_op_ctx()` must reserve up to 2 L3 tables for unaligned `SZ_2M` boundaries. In `panthor_vm_cleanup_op_ctx()`, unconsumed page tables must be bulk-freed as `count - ptr` entries at `pages + ptr` before `kfree(pages)`. [F140, F147]
- In `panthor_submit_ctx_add_deps_and_arm_jobs()`, each job `i` must have wait deps added, be armed, and update signal fences in a single pass before job `i + 1`. In `panthor_ioctl_vm_bind_async()`, the inner loop inside `drm_exec_until_all_locked(&ctx.exec)` must call `drm_exec_retry_on_contention(&ctx.exec)` immediately after `panthor_vm_bind_job_prepare_resvs()` before checking `if (ret)`. [F122, F123]
- `panthor_ioctl_dev_query()` has two parallel `switch (args->type)` blocks—one when `!args->pointer` setting `args->size = sizeof(...)` and one when `args->pointer` is non-NULL copying via `PANTHOR_UOBJ_SET()`; any query type added or modified must update both switches with matching struct sizes. [F90]

## Synchronization

- Lookup in `panthor_vm_pool_get_vm()` and `group_from_handle()` must hold `xa_lock(&pool->xa)` across `xa_load()` and `panthor_vm_get()` / `group_get()`. Iterating over a file's `panthor_group_pool` or `panthor_vm_pool` XArray (`panthor_fdinfo_gather_group_samples()`, `panthor_fdinfo_gather_group_mem_info()`, `panthor_vm_heaps_sizes()`) must hold `xa_lock()` across `xa_for_each()` and must not take sleeping locks (`vm->heaps.lock`, `pool->lock`), using atomic `panthor_heap_pool_size()` instead. [F26, F27, F174]
- `panthor_scheduler::reset.lock` must be acquired before `sched->lock`. In `panthor_sched_pre_reset()`, `sched->reset.in_progress` must be set to `true` before `cancel_work_sync(&sched->sync_upd_work)` and `cancel_delayed_work_sync(&sched->tick_work)`. [F43]
- `panthor_job_irq_handler()` must not take `sched->lock` and must defer to `sched->fw_events_work`, as `tick_work` waits on `ptdev->fw->req_waitqueue` via `panthor_fw_csg_wait_acks()` under `sched->lock`. Because `sched->wq` uses `WQ_MEM_RECLAIM` in the dma-fence signaling path, `tiler_oom_work` (blocking allocations in `panthor_heap_grow()`) must run on `sched->heap_alloc_wq`, and `group_release()` must defer teardown to `release_work` on `panthor_cleanup_wq`. [F178, F179, F180]
- `panthor_vm_bind_run_job()` runs `panthor_vm_exec_op()` inside `dma_fence_begin_signalling()`, so `panthor_vm_prepare_map_op_ctx()` and `panthor_vm_prepare_unmap_op_ctx()` must pre-allocate all `panthor_vma` structs, `sg_table` pages, `drm_gpuvm_bo`, and `rsvd_page_tables` pages upfront so `alloc_pt()` never allocates during page-table updates. [F176]
- In `panthor_ioctl_group_submit()` and `panthor_ioctl_vm_bind_async()`, VM and BO reservation locks must be held via `ctx.exec` from before `panthor_submit_ctx_add_deps_and_arm_jobs()` until `panthor_submit_ctx_push_jobs()` finishes. [F33]
- Under `ptdev->mmu->vm.lock`, `panthor_vm_create()` must call `panthor_vm_stop(vm)` if `ptdev->mmu->vm.reset_in_progress` is true when adding to `mmu->vm.list`, and `panthor_vm_free()` must call `panthor_vm_start(vm)` if `reset_in_progress` is true before `drm_sched_entity_destroy()` and `drm_sched_fini()`. [F44]
- In `panthor_vm_active()`, if lockless `refcount_inc_not_zero(&vm->as.active_cnt)` fails, the caller must take `ptdev->mmu->as.slots_lock` and recheck `refcount_inc_not_zero(&vm->as.active_cnt)` before assigning an AS slot, pairing with `refcount_dec_and_mutex_lock()` in `panthor_vm_idle()`. [F46]
- Transitions of `ptdev->pm.state` into `SUSPENDING` or `ACTIVE` and the paired `unmap_mapping_range()` in `panthor_device_suspend()`/`panthor_device_resume()` must hold `ptdev->pm.mmio_lock`, matching `panthor_mmio_vm_fault()`. `pfile->user_mmio.offset` must be written with `WRITE_ONCE()` and read once with `READ_ONCE()` in `panthor_mmap()`, and never read after `vma->vm_pgoff` is adjusted to `DRM_PANTHOR_USER_MMIO_OFFSET`. [F35, F36]
- In `sched_process_csg_irq_locked()`, after reading `cs_irq_req` and `cs_irq_ack`, the host must write `csg_iface->input->cs_irq_ack = cs_irq_req` before calling `cs_slot_process_irq_locked()` on any slot in `cs_irq_req ^ cs_irq_ack`. When `panthor_device_reset_work()` aborts because `pm.state != ACTIVE`, it must leave `ptdev->reset.pending` set so `panthor_device_resume()` forces a slow reset (`reset.fast = false`). [F88, F170]

## Object Lifetimes

- In `panthor_submit_ctx_push_jobs()`, `drm_sched_entity_push_job()` takes ownership of `ctx->jobs[i].job`, so it must be set to `NULL` immediately. In `panthor_submit_ctx_push_fences()`, `drm_syncobj_add_point()` takes ownership of `sig_sync->chain`, so it must be set to `NULL`. In `panthor_submit_ctx_update_job_sync_signal_fences()`, replacing `sig_sync->fence` must save `old_fence`, assign `dma_fence_get(done_fence)`, and then call `dma_fence_put(old_fence)`. [F4, F5, F6]
- `panthor_heap_pool` holds a weak pointer `pool->vm` that `panthor_heap_pool_destroy()` clears to `NULL` under `down_write(&pool->lock)`, so `panthor_heap_create()` must grab `panthor_vm_get(pool->vm)` under `down_read(&pool->lock)` and reverify `pool->vm` under `down_write(&pool->lock)`. [F15]
- Queuing a `panthor_group` work item (`group_queue_work()` or `cs_slot_process_tiler_oom_event_locked()`) must take `group_get(group)` before `queue_work()`, drop it with `group_put(group)` if `queue_work()` returns `false`, and drop it at the end of the work handler. [F20]
- `panthor_group_destroy()` must not destroy `queue->entity` or `queue->scheduler`; teardown is deferred until `group_release_work()` calls `group_free_queue()`. `group_free_queue()` must check `queue->scheduler.ops` before `drm_sched_fini()`, and `job_release()` / `panthor_vm_bind_job_release()` must check `job->base.s_fence` before `drm_sched_job_cleanup()`. [F29, F57]
- Under `sched->lock`, the scheduler's runtime PM reference on `ptdev->base.dev` is gated by `sched->pm.has_ref` (`tick_work()`, `queue_run_job()`, `panthor_sched_unplug()`). In `panthor_device_suspend()`, `panthor_gpu_suspend()` must run last after `sched`/`fw`/`mmu`, and in `panthor_device_resume_hw_components()`, `panthor_gpu_resume()` must run first. [F24, F157]
- Because `panthor_device`, `panthor_mmu`, and `panthor_vm` can outlive `panthor_remove()` and `ptdev->iomem`, paths that may run after `panthor_device_unplug()` (`panthor_vm_free()`, `panthor_vm_flush_range()`, `panthor_vm_active()`) must guard MMIO accesses with `drm_dev_enter()`/`drm_dev_exit()`. Every path freeing `panthor_gem_object::label.str` must use `kfree_const()`. [F153, F161]

## API Contracts

- `panthor_vm_get_heap_pool()` returns an `ERR_PTR()` and never `NULL`, whereas `panthor_heap_pool_put()` only checks for `NULL` and must not be passed an `ERR_PTR()`. `panthor_vm_pool_get_vm()` and `group_from_handle()` return `NULL` when a handle is absent, whereas `panthor_vm_get_bo_for_va()` returns `ERR_PTR(-ENOENT)`. [F48, F49]
- Indirect UAPI objects/arrays must use `PANTHOR_UOBJ_SET()` and `PANTHOR_UOBJ_GET_ARRAY()`, and extensible structs in `PANTHOR_UOBJ_MIN_SIZE()` must keep their original `_last_mandatory_field` in `PANTHOR_UOBJ_DECL()`. In `panthor_get_uobj_array()`, `!in->count` must return `NULL` (setting `_dest_array = NULL` and returning `0`) before checking `in->stride < min_stride`, while errors leave `_dest_array` untouched; when `obj_size != in->stride`, the copy loop advances `out_ptr` by `obj_size` and `in_ptr` by `in->stride`. [F52, F114, F115, F145, F196]
- `panthor_vm_root_gem(vm)` (`exclusive_vm_root_gem`) is a base `struct drm_gem_object` and must never be downcast with `to_panthor_bo()`. `struct panthor_submit_ctx` holds `struct drm_sched_job *` pointers for either `panthor_job` or `panthor_vm_bind_job` and must use `job_put`/`upd_resvs` callbacks instead of downcasting. [F150, F151]
- In `panthor_vm_map_pages()` and `panthor_vm_unmap_pages()`, `io_pgtable_ops` calls must be split at `SZ_2M`/`SZ_1G` boundaries via `get_pgsize()` and followed by `panthor_vm_flush_range()`. Both `panthor_job_update_resvs()` and `panthor_vm_bind_job_update_resvs()` must use `DMA_RESV_USAGE_BOOKKEEP` for private and external objects. `panthor_job_create()` must verify `group_can_run(job->group)`. [F68, F190, F194]
- `panthor_<name>_irq_suspend()` / `_resume()` must not call `drm_dev_enter()`, and unplug callers (`panthor_*_unplug()`) must check `!IS_ENABLED(CONFIG_PM) || pm_runtime_active(ptdev->base.dev)`. Runtime GPU resume callers (`panthor_query_timestamp_info()`, `tick_work()`, `queue_run_job()`) must call `panthor_device_resume_and_get(ptdev)` instead of `pm_runtime_resume_and_get()`. [F159, F173]

## Error Handling

- `panthor_fw_wait_acks()` and `panthor_fw_csg_wait_acks()` populate `*acked` even when returning `-ETIMEDOUT` (with `panthor_fw_csg_wait_acks()` clearing `CSG_STATE_MASK` in `*acked` unless all state bits matched), and `csgs_upd_ctx_apply_locked()` must sync state for those acknowledged bits before checking for timeout. [F58, F119]
- `panthor_heap_grow()` returns `-ENOMEM` when a heap hits `target_in_flight` or `max_chunks` or allocation fails, and `group_process_tiler_oom()` must treat `-ENOMEM` as non-fatal by acknowledging `CS_TILER_OOM` with `new_chunk_va = 0`. [F51]
- Store integer return values in a variable before passing to boolean `drm_WARN_ON()`. Unlike `panthor_kernel_bo_destroy()` and `group_free_queue()`, `panthor_vm_put()` and `panthor_devfreq` callbacks only check for `NULL`, so `ERR_PTR` values in `fw->vm` or `pdevfreq->devfreq` must be reset to `NULL` on init failure. [F54, F55]

## External Contracts

- UAPI tiler heap handles pack `(args->vm_id << 16) | heap_id`, whereas `panthor_heap_destroy()` takes `args->handle & GENMASK(15, 0)`. Because `heap->chunk_size >> 12` is encoded in bits 11:0 of chunk GPU VAs, `panthor_heap_create()` must enforce `chunk_size <= SZ_8M` and `panthor_heap_return_chunk()` must mask `chunk_gpu_va` with `GENMASK_ULL(63, 12)`. [F66, F138]
- In `panthor_vm_bind_prepare_op_ctx()`, `op->va | op->size | op->bo_offset` must be page-aligned, `UNMAP` must reject non-zero `bo_handle`/`bo_offset`, and `SYNC_ONLY` must reject non-zero `bo_handle`/`bo_offset`/`va`/`size` or zero `syncs.count`. In `panthor_ioctl_vm_bind_sync()`, if op `i` fails, `args->ops.count` must be set to `i`. Group priorities above `MEDIUM` require `group_priority_permit()`. [F106, F107, F195]

## Known Pitfalls

- `panthor_fw_ring_csg_doorbells()` takes a 32-bit CSG bitmask (e.g. `BIT(csg_id)`) despite its parameter name `csg_slot`, whereas `panthor_fw_get_csg_iface()`, `panthor_fw_get_cs_iface()`, and `panthor_fw_csg_wait_acks()` take a 0-based slot index (`< MAX_CSGS` / `< MAX_CS_PER_CSG`). [F63, F99]
- Avoid 32-bit shift/cast truncation: cast `vma->vm_pgoff` to `u64` before `<< PAGE_SHIFT` in mmap/fault paths; cast `out_attr` to `u64` before `<< (8 * i)` in `mair_to_memattr()`; cast `status_wait_sync_value_hi` to `u64` before `<< 32` in `cs_slot_sync_queue_state_locked()`; keep `panthor_job_cs_params` register fields shifted by `>= 32` as `u64`; and check `offset > U32_MAX` before `(u32)offset / panthor_heap_ctx_stride()` in `panthor_heap.c`. [F129, F132, F133, F134, F137]
- In `panthor_vm_map_pages()`, reset `offset = 0` at the end of the `for_each_sgtable_dma_sg()` loop body after the first mapped segment. In `tick_ctx_cleanup()`, never dereference the `list_for_each_entry_safe()` cursor `group` outside the loop body (use `sched->ptdev`). `panthor_kernel_bo::kmap` is `void *` (byte-indexed), whereas `u64 instrs->buffer[]` is `u64`-indexed. [F116, F118, F148]
