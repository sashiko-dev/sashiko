# FUSE FILESYSTEM [PASSTHROUGH]

Implements FUSE passthrough I/O to underlying backing files and enforces mutual exclusion between page-cached I/O, parallel direct I/O, and uncached/passthrough I/O modes on FUSE inodes. It manages connection-scoped backing file registrations mapped by IDR IDs (`backing.c`), coordinates inode I/O mode transitions and reference counts (`iomode.c`), and delegates read, write, splice, and mmap file operations directly to VFS backing-file helpers (`passthrough.c`).

## Architecture & Data Flow

- Because `fi->iocachectr` and `fi->direct_io_waitq` share an anonymous union in `struct fuse_inode` with the directory-only `fi->rdc` structure, `fuse_file_io_release()` (called from `fuse_file_put()` for both files and directories) must not access `fi->iocachectr` or `fi->direct_io_waitq` when `ff->iomode == IOM_NONE`. Broken by: reading or modifying `fi->iocachectr` or `fi->direct_io_waitq` unconditionally in `fuse_file_io_release()`, or entering `IOM_CACHED` / `IOM_UNCACHED` on a non-regular-file inode. [F57]
- `fuse_file_cached_io_open()` must only transition `ff->iomode` to `IOM_CACHED`, set `FUSE_I_CACHE_IO_MODE`, and increment `fi->iocachectr` when `ff->iomode == IOM_NONE`, because `fuse_file_mmap()` can invoke it multiple times on the same `FOPEN_DIRECT_IO` file while `fuse_file_io_release()` decrements `fi->iocachectr` only once. [F32]
- Because `fuse_file_io_open()` still sets `ff->passthrough` when both `FOPEN_PASSTHROUGH` and `FOPEN_DIRECT_IO` are set, `read_iter`, `write_iter`, `splice_read`, and `splice_write` in `fs/fuse/file.c` must let `FOPEN_DIRECT_IO` override `fuse_file_passthrough(ff)`, whereas `fuse_file_mmap()` must dispatch `fuse_file_passthrough(ff)` first. Broken by: dispatching read, write, or splice on `fuse_file_passthrough(ff)` without checking `!(ff->open_flags & FOPEN_DIRECT_IO)`. [F39]
- In `fuse_is_io_cache_wait()`, the wait predicate must require both `READ_ONCE(fi->iocachectr) < 0` and `!fuse_inode_backing(fi)` so that `fuse_file_cached_io_open()` only waits on `fi->direct_io_waitq` for in-progress parallel direct I/O writes and exits immediately if a passthrough backing file is attached. Broken by: checking only `READ_ONCE(fi->iocachectr) < 0`, causing `fuse_file_cached_io_open()` to sleep until all passthrough files close instead of returning `-ETXTBSY`. [F45]
- Backing file IDs in `fc->backing_files_map` are 1-based positive integers allocated via `idr_alloc_cyclic(..., 1, 0, ...)` in `fuse_backing_id_alloc()`, and both `fuse_backing_close()` and `fuse_passthrough_open()` must reject `backing_id <= 0` with `-EINVAL` before querying the IDR. [F41]
- `fuse_backing_open()` must reject any backing file whose superblock stacking depth `file_inode(file)->i_sb->s_stack_depth` is greater than or equal to `fc->max_stack_depth` with `-ELOOP`. [F43]

## Synchronization

- On a live `struct fuse_inode`, all modifications to `fi->iocachectr`, `fi->fb`, `FUSE_I_CACHE_IO_MODE` in `fi->state`, and transitions of `ff->iomode` to or from `IOM_CACHED` must be serialized under `spin_lock(&fi->lock)`. Lockless reads of `fi->iocachectr` and `fi->fb` outside `fi->lock` (in `fuse_is_io_cache_wait()`, `fuse_file_io_open()`, and `fuse_file_mmap()`) must use `READ_ONCE(fi->iocachectr)` and `fuse_inode_backing(fi)` (`READ_ONCE(fi->fb)`), and must only test the pointer without dereferencing it or calling `fuse_backing_get()` unless `fi->lock` or an `IOM_UNCACHED` reference is held. [F13, F19]
- In `fuse_file_cached_io_open()`, `FUSE_I_CACHE_IO_MODE` must be set on `fi->state` on every iteration of `while (fuse_is_io_cache_wait(fi))` before dropping `fi->lock` for `wait_event()`, and cleared if `fuse_inode_backing(fi)` is non-NULL after the loop, so new parallel direct I/O writes take an exclusive lock instead of starving the waiter. Broken by: setting `FUSE_I_CACHE_IO_MODE` only after the loop, or failing to clear it on the `-ETXTBSY` return path. [F46]
- `fuse_passthrough_write_iter()` and `fuse_passthrough_splice_write()` must hold `inode_lock(inode)` on the FUSE inode across `backing_file_write_iter()` and `backing_file_splice_write()`, while `spin_lock(&fi->lock)` (acquired in `.end_write` callback `fuse_passthrough_end_write()` via `fuse_write_update_attr()`) nests inside `inode_lock(inode)`. Broken by: calling `backing_file_write_iter()` / `backing_file_splice_write()` without `inode_lock(inode)`, or holding `fi->lock` while calling them or acquiring `inode_lock(inode)`. [F18]
- `fuse_backing_lookup()` must perform `idr_find(&fc->backing_files_map, backing_id)` and `fuse_backing_get(fb)` (`refcount_inc_not_zero(&fb->count)`) within the same `rcu_read_lock()` critical section, paired with `spin_lock(&fc->lock)` around `idr_alloc_cyclic()`/`idr_remove()` and `kfree_rcu(fb, rcu)` in `fuse_backing_free()`. Broken by: freeing `struct fuse_backing` with `kfree()`, calling `fuse_backing_get()` after `rcu_read_unlock()`, or mutating `fc->backing_files_map` on a live connection without `fc->lock`. [F12]
- Because `fuse_inode_uncached_io_start()` calls `fuse_backing_put(fb)` while holding `spin_lock(&fi->lock)`, `fuse_backing_put()` and `fuse_backing_free()` must be safe to execute in spinlock atomic context and must not call sleeping functions (such as `synchronize_rcu()` or a mutex lock). [F62]
- `fuse_backing_id_alloc()` must bracket `spin_lock(&fc->lock)` and `spin_unlock(&fc->lock)` with `idr_preload(GFP_KERNEL)` and `idr_preload_end()`, using `GFP_ATOMIC` for `idr_alloc_cyclic()` while `fc->lock` is held. [F9]
- `fuse_passthrough_write_iter()` and `fuse_passthrough_read_iter()` must check `if (!iov_iter_count(iter)) return 0;` before delegating to `backing_file_write_iter()` or `backing_file_read_iter()`, which in `fuse_passthrough_write_iter()` avoids acquiring `inode_lock(inode)` on zero-length I/O. [F52]

## Object Lifetimes

- `fuse_inode_uncached_io_start()` consumes the caller's `struct fuse_backing` reference (`fb`) on success, but leaves `fb` unconsumed on error (`-EBUSY` or `-ETXTBSY`) so the caller must call `fuse_backing_put(fb)`. Its conflict check `if (fb && oldfb && oldfb != fb)` must allow `fb == NULL` when `oldfb != NULL` and `fb == oldfb`, storing `fb` via `fuse_inode_backing_set()` only when `fb && !oldfb` and calling `fuse_backing_put(fb)` in the `else` branch. Broken by: dropping `fb` before returning an error, rejecting `fb == NULL && oldfb != NULL` or `fb == oldfb`, or a caller like `fuse_file_passthrough_open()` putting `fb` on success or leaking it on error. [F1, F50]
- `fuse_passthrough_open()` acquires a `struct fuse_backing` reference via `fuse_backing_lookup()`, `ff->passthrough` via `backing_file_open()`, and `ff->cred` via `get_cred(fb->cred)`, whereas `fuse_passthrough_release()` releases only `ff->passthrough` (`fput()`) and `ff->cred` (`put_cred()`), not `fb`. Broken by: expecting `fuse_passthrough_release(ff, fb)` to drop the `fb` reference returned by `fuse_passthrough_open()`, or omitting `fuse_backing_put(fb)` when `backing_file_open()` fails. [F2]
- `fuse_passthrough_release()` must clear `ff->passthrough = NULL` and `ff->cred = NULL` after calling `fput()` and `put_cred()` because a failure in `fuse_file_passthrough_open()` calls `fuse_passthrough_release()` before `fuse_open()` invokes `fuse_sync_release()` -> `fuse_prepare_release()`, which re-tests `fuse_file_passthrough(ff)`. [F3]
- `fuse_inode_uncached_io_end()` must clear `fi->fb` via `fuse_inode_backing_set(fi, NULL)` and wake `fi->direct_io_waitq` under `fi->lock` only when `fi->iocachectr` increments to `0`, and must release the detached `oldfb` via `fuse_backing_put(oldfb)` after `spin_unlock(&fi->lock)`. [F8]
- In `fuse_backing_open()`, `fb->file`, `fb->cred`, and `fb->count` must be initialized before `fuse_backing_id_alloc()` publishes `fb` in `fc->backing_files_map`, and failure of `fuse_backing_id_alloc()` must clean up via `fuse_backing_free(fb)` rather than jumping to `out_fput`. [F4]
- `fuse_file_passthrough_open()` reads `ff->args->open_outarg.backing_id` from `union fuse_file_args` and therefore must only be called during file open (`fuse_file_io_open()`) before `fuse_prepare_release()` zeroes `ff->args` and repurposes the union for `ff->args->release_args`. [F58]
- In `fuse_backing_files_free()`, the `idr_for_each()` callback `fuse_backing_id_free()` must return `0` after freeing each `struct fuse_backing` so that `idr_for_each()` visits and frees every remaining entry in `fc->backing_files_map` before `idr_destroy()` is called. [F51]

## API Contracts

- `ff->iomode` (`IOM_NONE`, `IOM_CACHED`, `IOM_UNCACHED`) must only be mutated by file open and release helpers in `fs/fuse/iomode.c`, whereas transient per-I/O uncached references on `fi->iocachectr` must use `fuse_inode_uncached_io_start()` and `fuse_inode_uncached_io_end()` without touching `ff->iomode`. Broken by: setting `ff->iomode = IOM_UNCACHED` or calling `fuse_file_uncached_io_open()` for a per-request direct I/O operation whose `fi->iocachectr` reference is dropped before `fuse_file_io_release()`. [F33]
- In `fuse_passthrough_splice_read()` and `fuse_passthrough_splice_write()`, the stack `struct kiocb iocb` must be initialized via `init_sync_kiocb()` with the outer FUSE `struct file *` (`in` or `out`) rather than `backing_file`—because `fuse_file_accessed()` and `fuse_passthrough_end_write()` downcast `file_inode(iocb->ki_filp)` as a FUSE inode—and `iocb.ki_pos` must be synchronized with `*ppos` before and after calling `backing_file_splice_read()` or `backing_file_splice_write()`. [F56, F70]
- `fuse_passthrough_read_iter()`, `fuse_passthrough_splice_read()`, and `fuse_passthrough_mmap()` must set `ctx.accessed = fuse_file_accessed`, and `fuse_passthrough_write_iter()` and `fuse_passthrough_splice_write()` must set `ctx.end_write = fuse_passthrough_end_write` in `struct backing_file_ctx` when calling `backing_file_*` helpers. Broken by: omitting `accessed` or `end_write`, leaving FUSE inode cached attributes or `i_size` stale after backing-file I/O. [F69]
- `fuse_backing_open()` must capture the registering task's credentials via `get_current_cred()` in `fb->cred`, `fuse_passthrough_open()` must pass `fb->cred` to `backing_file_open()` and save a reference in `ff->cred`, and all `fuse_passthrough_*` I/O and mmap operations must pass `ff->cred` in `ctx.cred`. Broken by: using `current_cred()` of the VFS reader/writer/mmapper task instead of `fb->cred` / `ff->cred`. [F77]
- `fuse_passthrough_open()` returns an `ERR_PTR(err)` on failure and never `NULL`, whereas `fuse_backing_lookup()` and `fuse_backing_get()` return `NULL` on failure and never an `ERR_PTR`; callers must check `IS_ERR()` for `fuse_passthrough_open()` and `!fb` for `fuse_backing_lookup()` and `fuse_backing_get()`. [F20]
- `fuse_file_passthrough_open()` must guard calls to `fuse_passthrough_open()` and `fuse_passthrough_release()` with `IS_ENABLED(CONFIG_FUSE_PASSTHROUGH)` because `iomode.c` is compiled unconditionally while `passthrough.c` is only built when `CONFIG_FUSE_PASSTHROUGH` is enabled without header stubs for those functions. [F68]
- `fuse_backing_open()` must reject any `map->fd` whose dentry is not a regular file (`!d_is_reg(file->f_path.dentry)`), returning `-EISDIR` for directories and `-EINVAL` for other non-regular files before allocating a `struct fuse_backing`. [F42]

## Error Handling

- `fuse_file_io_open()` must translate any error from `fuse_file_passthrough_open()`, `fuse_file_cached_io_open()`, or conflicting `FOPEN_PASSTHROUGH` flags into `-EIO` and log it only via `pr_debug()` without triggering kernel warnings. Broken by: propagating raw internal error codes (such as `-ETXTBSY`, `-EBUSY`, `-ENOENT`, or `-EINVAL`) to the VFS `open()` caller or using `WARN_ON()` on server-supplied `open_flags` / `backing_id` errors. [F78]

## External Contracts

- Both `fuse_backing_open()` and `fuse_backing_close()` must verify `fc->passthrough` and `capable(CAP_SYS_ADMIN)` and return `-EPERM` if either check fails before accessing `fc->backing_files_map`. Broken by: omitting `fc->passthrough && capable(CAP_SYS_ADMIN)`, or using `ns_capable()` instead of `capable(CAP_SYS_ADMIN)` while backing files remain hidden from `lsof`. [F76]
- `fuse_file_passthrough_open()` must reject any `ff->open_flags` bit outside `FOPEN_PASSTHROUGH_MASK` (`FOPEN_PASSTHROUGH | FOPEN_DIRECT_IO | FOPEN_PARALLEL_DIRECT_WRITES | FOPEN_NOFLUSH`) with `-EINVAL`, and `fuse_file_io_open()` must clear `FOPEN_PARALLEL_DIRECT_WRITES` whenever `FOPEN_DIRECT_IO` is not set. [F49]
- In `fuse_backing_open()`, both `map->flags` and `map->padding` in the userspace-supplied `struct fuse_backing_map` must be verified to be zero before looking up `map->fd`, returning `-EINVAL` if either field is non-zero. [F40]

## Known Pitfalls

- In `fuse_passthrough_open()`, `backing_file_open()` must be passed the FUSE `file` and `file->f_flags` as `user_file` and `flags`, paired with `&fb->file->f_path` and `fb->cred` from the looked-up `struct fuse_backing` as `real_path` and `cred`. Broken by: passing `&file->f_path` instead of `&fb->file->f_path` or `fb->file->f_flags` instead of `file->f_flags`. [F54]
