# SERIAL LOW-POWER INTER-CHIP MEDIA BUS (SLIMbus)

The SLIMbus subsystem provides the core Linux bus framework for the MIPI Serial Low-power Inter-chip Media Bus, managing controller and client device registration, Device Tree enumeration, and logical address allocation. It implements synchronous and asynchronous value/information element messaging using transaction IDs (TIDs), bus clock-pause reconfiguration scheduling, and audio data stream lifecycle management (allocate, prepare, enable, disable, unprepare, and free) integrated with ASoC.

## Architecture & Data Flow

- Every child `struct device` registered under `slim_controller.dev` must be embedded in a `struct slim_device`, because `slim_ctrl_remove_device()`, `slim_match_dev()`, and `of_find_slim_device()` unconditionally downcast `ctrl->dev` children via `to_slim_device()` without checking `dev->bus`. Broken by: registering a non-`slim_device` child (such as `slim_framer.dev`) with `parent = ctrl->dev`. [F67]
- Stack-allocated `struct slim_val_inf` instances passed to `slim_xfer_msg()` for synchronous TID transactions must have `msg->comp` initialized to `NULL` (as `slim_fill_msg()` does), because `slim_do_transfer()` treats a non-NULL `txn->msg->comp` as an asynchronous caller-supplied completion and skips waiting on its on-stack `done` completion. [F28]
- In `slim_device_alloc_laddr()`, the `ctrl->get_laddr` check must precede the `report_present` branch so `slim_get_logical_addr()` (`report_present = false`) still obtains an address when `ctrl->get_laddr` is set; when `ctrl->get_laddr` is NULL and `report_present` is true, `ida_alloc_max(&ctrl->laddr_ida, SLIM_LA_MANAGER - 1, ...)` must be used so client addresses span `0x00..0xFE` while reserving `SLIM_LA_MANAGER` (`0xFF`). [F43, F53]
- When adding or modifying `SLIM_MSG_MC_*` codes, update `slim_val_inf_sanity()`, `slim_xfer_msg()`, `slim_tid_txn()`, and `slim_ec_txn()` in lockstep: `txn->rl` starts at 6, adds `msg->num_bytes` only for write-bearing codes (`CHANGE_VALUE`, `REQUEST_CHANGE_VALUE`, `CLEAR_INFORMATION`, `REQUEST_CLEAR_INFORMATION`), and adds 1 when `slim_tid_txn(txn->mt, txn->mc)` is true. [F40, F58]
- Message codes and flags stored in or tested against `struct slim_msg_txn.mc` (or passed as `u8 mc` to `slim_xfer_msg()`, `slim_tid_txn()`, and `slim_ec_txn()`) must fit within the 8-bit `u8` type and 7-bit wire mask `SLIM_MSG_MC_MASK`, never using bit shifts `>= 8`. [F59]
- Before entering clock pause (`wakeup == false`), `slim_ctrl_clk_pause()` must reject `restart > SLIM_CLK_UNSPECIFIED` with `-EINVAL`, verify under `ctrl->txn_lock` that no entry in `ctrl->tid_idr` (`0 <= i < SLIM_MAX_TIDS`) is pending (returning `-EBUSY`), set `ctrl->sched.clk_state = SLIM_CLK_ENTERING_PAUSE` before sending broadcast messages, and transition to `SLIM_CLK_PAUSED` (calling `complete(&sched->pause_comp)`) on success or `SLIM_CLK_ACTIVE` on failure. [F35, F50]
- In `slim_stream_enable()`, when `ctrl->enable_stream` is NULL, the loop calling `slim_define_channel()` and `slim_define_channel_content()` must complete across all `stream->num_ports` ports before the `slim_activate_channel()` loop begins; whether `ctrl->enable_stream` is used or not, `slim_stream_enable()` must transition every `stream->ports[i].ch.state` to `SLIM_CH_STATE_ACTIVE` on success. [F39, F55]
- `slim_define_channel()` must add 1 extra slot to the truncated slot count (`stream->bps / SLIM_SLOT_LEN_BITS + 1`) when `stream->prot != SLIM_PROTO_ISO` (PUSH/PULL protocols), whereas `slim_define_channel_content()` always encodes the unadjusted sample slot count `stream->bps / SLIM_SLOT_LEN_BITS` in `wbuf[3]`. [F65]
- Each entry in `slim_presence_rate_table` (`drivers/slimbus/stream.c`) must store the exact SLIMbus 2.0 Table 66 natural frequency in Hz at the array index matching its presence rate code so `slim_get_prate_code()` resolves `cfg->rate` to the specification code. [F77]

## Synchronization

- Every access to `ctrl->tid_idr` (`slim_msg_response()`, `slim_alloc_txn_tid()`, `slim_free_txn_tid()`, and `slim_ctrl_clk_pause()`) must hold `ctrl->txn_lock` via `spin_lock_irqsave()`, and `idr_alloc_cyclic()` in `slim_alloc_txn_tid()` must use `GFP_ATOMIC`. `slim_msg_response()` must release `ctrl->txn_lock` before calling `slim_free_txn_tid(ctrl, txn)`, which unconditionally acquires `ctrl->txn_lock`. [F86, F87]
- `slim_device_alloc_laddr()` and `slim_report_absent()` must update `sbdev->is_laddr_valid` under `ctrl->lock`, release `ctrl->lock`, and then call `slim_device_update_status()` to update `sbdev->status` and invoke `sbdrv->device_status`. Controller `get_laddr`/`set_laddr` callbacks run under `ctrl->lock` and must not call `slim_get_logical_addr()`, `slim_device_report_present()`, or `slim_report_absent()` on the same `ctrl`. [F34, F89]
- In `slim_ctrl_clk_pause()`, `ctrl->sched.m_reconf` must be held across the entire clock-pause entry or wakeup sequence, and when nesting locks, `ctrl->sched.m_reconf` must be acquired before `ctrl->txn_lock`. [F18]
- In `slim_do_transfer()`, core reconfiguration messages (`txn->mt == SLIM_MSG_MT_CORE` with `txn->mc` in `SLIM_MSG_MC_BEGIN_RECONFIGURATION..SLIM_MSG_MC_RECONFIGURE_NOW`) sent while `ctrl->sched.clk_state == SLIM_CLK_ENTERING_PAUSE` must bypass `pm_runtime_get_sync()`, the `SLIM_CLK_ACTIVE` check, and `pm_runtime_put_autosuspend()`. [F90]
- Insertions and removals on `dev->stream_list` in `slim_stream_allocate()` and `slim_stream_free()` must hold `dev->stream_list_lock`, with `rt->name` and `rt->dev` initialized before `list_add_tail()` and `kfree(stream)` called after `list_del()`. [F20]

## Object Lifetimes

- In `slim_msg_response()`, `slim_free_txn_tid(ctrl, txn)` and `memcpy(msg->rbuf, reply, len)` must execute before `complete(txn->comp)`, because `txn`, `txn->msg`, `msg->rbuf`, and `txn->comp` (`done`) are allocated on the waiting thread's stack in `slim_do_transfer()`, `slim_xfer_msg()`, and `slim_read()`. [F68]
- In `slim_do_transfer()`, if `ctrl->xfer_msg()` returns `-ETIMEDOUT` or `wait_for_completion_timeout()` on `txn->comp` expires, `slim_free_txn_tid(ctrl, txn)` must be called before returning so delayed interrupts in `slim_msg_response()` cannot dereference the stack-allocated `slim_msg_txn` via `ctrl->tid_idr`. [F1]
- `slim_alloc_txn_tid()` allocates TIDs in `[1, SLIM_MAX_TIDS)` via `idr_alloc_cyclic()`, reserving `txn->tid == 0` as the unallocated sentinel. `slim_do_transfer()` must initialize `txn->tid = 0` before calling `slim_tid_txn()` or `ctrl->xfer_msg()`, and release the non-`clk_pause_msg` runtime-PM reference on exit only when `txn->tid == 0 || ret == -ETIMEDOUT` (since `slim_msg_response()` drops it for any non-zero `tid`, including TIDs allocated inside `ctrl->xfer_msg()`). [F26, F73]
- `slim_stream_unprepare()` must `kfree(stream->ports)` and reset `stream->ports = NULL` and `stream->num_ports = 0`, because `slim_stream_prepare()` rejects non-NULL `rt->ports` and `slim_stream_free()` frees only `stream->name` and `stream`. [F7]
- `slim_register_controller()` must allocate `ctrl->id` from `ctrl_ida` and initialize `ctrl->laddr_ida`, `ctrl->tid_idr`, `ctrl->lock`, `ctrl->sched.m_reconf`, `ctrl->sched.pause_comp`, and `ctrl->txn_lock` before calling `of_register_slim_devices(ctrl)`. [F78]
- `slim_unregister_controller()` must unregister all child `slim_device` instances via `slim_remove_device()`—which balances `of_node_get()` in `slim_add_device()` with `of_node_put(sbdev->dev.of_node)` and calls `device_unregister(&sbdev->dev)`—before freeing `ctrl->id` in `ctrl_ida`, and must not invoke `slim_ctrl_clk_pause()` during teardown. [F9, F76]

## API Contracts

- `txn->msg` in `struct slim_msg_txn` can be `NULL` for broadcast control transactions such as `SLIM_MSG_MC_BEGIN_RECONFIGURATION` and `SLIM_MSG_MC_RECONFIGURE_NOW`, so `slim_do_transfer()` and `ctrl->xfer_msg` implementations must not dereference `txn->msg` without checking `slim_tid_txn()`, message code, or `txn->msg != NULL`. [F27]
- For any transaction registered in `ctrl->tid_idr`, `txn->msg->rbuf` must be non-NULL and large enough to hold the `len` bytes passed to `slim_msg_response(ctrl, reply, tid, len)`, because `slim_msg_response()` executes `memcpy(msg->rbuf, reply, len)` without checking `msg->num_bytes`. [F71]
- In `slim_xfer_msg()`, `slim_val_inf_sanity()` must validate that `msg != NULL`, `msg->num_bytes <= 16`, `msg->start_offset + msg->num_bytes <= 0xC00`, and required `msg->rbuf`/`msg->wbuf` pointers are non-NULL for `mc` before `slim_slicesize()` and `txn->ec`/`txn->rl` arithmetic execute. [F45]
- `slim_readb()` must read into an unsigned `u8` buffer so bytes `0x80..0xFF` zero-extend to `128..255` in the returned `int` rather than sign-extending to negative values, and callers must store the return value in a signed `int` and check `< 0` before truncating to `u8`. [F23, F62]
- In `struct slim_controller`, `get_laddr`, `set_laddr`, `wakeup`, `enable_stream`, and `disable_stream` are optional and must be NULL-checked before invocation; when `ctrl->get_laddr` is non-NULL, logical addresses are provided by the controller, so `slim_report_absent()` must only call `ida_free(&ctrl->laddr_ida, sbdev->laddr)` when `!ctrl->get_laddr`. [F29, F33]
- Every `struct slim_driver` registered via `__slim_driver_register()` must provide `drv->probe` and a non-NULL `drv->id_table` terminated by a `{}` zero sentinel (`manf_id == 0`, `prod_code == 0`), because `slim_device_match()` unconditionally dereferences `sbdrv->id_table` in `slim_match()` whenever `of_driver_match_device()` returns 0; `remove` and `device_status` are optional and must be NULL-checked after checking `dev->driver`. [F30, F94]
- In `slim_device_probe()`, `sbdrv->probe(sbdev)` runs before `slim_get_logical_addr(sbdev)` and `slim_device_update_status(sbdev, SLIM_DEVICE_STATUS_UP)`, so a driver cannot perform SLIMbus transfers in `probe()` unless it calls `slim_get_logical_addr()` first or defers transfers to `device_status()`. [F95]
- `slim_register_controller()` synchronously enumerates DT children via `of_register_slim_devices()` and registers child `slim_device` instances, so controller drivers must initialize `ctrl->dev` and callbacks (`get_laddr`, `set_laddr`, `xfer_msg`) before calling `slim_register_controller()`. [F96]
- When stopping an active stream, callers must invoke `slim_stream_disable(stream)` before `slim_stream_unprepare(stream)`, because `slim_stream_disable()` requires `stream->ports` and `stream->num_ports` to be non-zero to deactivate and remove each port's channel. [F8]
- In `slim_stream_enable()`, `ctrl->enable_stream` replaces the core channel-definition and `SLIM_MSG_MC_RECONFIGURE_NOW` transfers, whereas in `slim_stream_disable()`, `ctrl->disable_stream` is called before the core still sends `SLIM_MSG_MC_BEGIN_RECONFIGURATION`, `slim_deactivate_remove_channel()`, and `SLIM_MSG_MC_RECONFIGURE_NOW`. [F102]

## Error Handling

- In the wakeup path of `slim_ctrl_clk_pause()`, `ret` must be reset to `0` after `wait_for_completion_timeout(&sched->pause_comp, ...)` succeeds (which returns positive remaining jiffies) before conditionally calling `ctrl->wakeup(ctrl)` and returning `ret`. [F25]

## External Contracts

- `struct slim_eaddr` must remain a 6-byte `__packed` structure ordered as `instance` (`u8`), `dev_index` (`u8`), `prod_code` (`u16`), and `manf_id` (`u16`), whereas DT child nodes under `ctrl->dev->of_node` parsed by `of_register_slim_devices()` must have `compatible` matching `"slim%x,%x"` (`manf_id`, `prod_code`) and a 2-cell `u32` `reg` (`reg[0] = dev_index`, `reg[1] = instance`), formatted by `slim_add_device()` and `slim_device_uevent()` as `MODALIAS=slim:%x:%x:%x:%x`. [F48, F104]

## Known Pitfalls

- `slim_fill_msg()` narrows `u32 addr` to `u16 msg->start_offset` and `size_t count` to `u8 msg->num_bytes` before `slim_xfer_msg()` runs `slim_val_inf_sanity()`, so callers of `slim_read()` and `slim_write()` must not rely on `slim_val_inf_sanity()` to catch `addr >= 0x10000` or `count >= 256` that wrap modulo `2^16` or `2^8` into range. [F66]
- `slim_stream_prepare()` allocates `rt->ports` with `hweight32(cfg->port_mask)` elements while scanning `for_each_set_bit(..., &cfg->port_mask, SLIM_DEVICE_MAX_PORTS)` (32 bits): callers must supply at least `hweight32(cfg->port_mask)` elements in `cfg->chs`, and `rt->ports[i]` and `cfg->chs[i]` must be indexed by the dense counter `i` (`0 .. rt->num_ports - 1`) rather than the sparse bit position stored in `port->id`. [F46, F70]
- When reusing a `struct slim_msg_txn` across multiple `slim_do_transfer()` calls (as in `slim_ctrl_clk_pause()`), callers must explicitly reinitialize `txn.mc`, `txn.rl`, and `msg` fields (`num_bytes`, `wbuf`) before each call because `ctrl->xfer_msg` implementations may mutate `txn->rl` or `txn->msg` in place. [F41]
- In `of_register_slim_devices()`, per-child validation failures inside `for_each_child_of_node(ctrl->dev->of_node, node)` must use `continue` rather than `return` or `break` without `of_node_put(node)`, so that remaining child DT nodes are still registered and node references are not leaked. [F57]
- In `slim_slicesize()`, the bounded value returned by `clamp(code, 1, (int)ARRAY_SIZE(sizetocode))` must be assigned back to `code` before indexing `sizetocode[code - 1]`. [F24]
