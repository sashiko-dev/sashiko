# LED SUBSYSTEM

The Linux LED subsystem (`drivers/leds/`) implements the core LED class, trigger framework, flash and multicolor class extensions, V4L2 flash subdevice integration, and hardware controller drivers.

## Architecture & Data Flow

- In `led-core.c`, `LED_BLINK_SW` in `led_cdev->work_flags` is set only when `led_set_software_blink()` arms `blink_timer` and cleared when software blinking stops in `led_blink_set()`, `led_stop_software_blink()`, or `led_timer_function()`. On the final state of a `LED_BLINK_ONESHOT` cycle (`brightness` if `LED_BLINK_INVERT`, else `!brightness`), `led_timer_function()` must set `LED_BLINK_ONESHOT_STOP` and still call `mod_timer()`, clearing `LED_BLINK_SW` on the next tick. [F59, F96]
- In `led_classdev_suspend()`, `LED_SUSPENDED` must be set in `led_cdev->flags` before `led_set_brightness_nopm(led_cdev, 0)` and `flush_work(&led_cdev->set_brightness_work)`, and in `led_classdev_resume()`, cleared only after `led_set_brightness_nopm()` and `led_cdev->flash_resume()` complete. While set, `LED_SUSPENDED` gates hardware callbacks in `led_set_brightness_nosleep()`, `led_set_brightness_sync()`, and `led_set_flash_*()` without overwriting `led_cdev->brightness`. [F61, F143]
- `led_mc_set_brightness()` and `led_mc_trigger_event()` must check `led_cdev->flags & LED_MULTI_COLOR` before `lcdev_to_mccdev(led_cdev)`, and `led_mc_set_brightness()` must verify `num_colors == mcled_cdev->num_colors` before indexing `subled_info`. `led_mc_calc_color_components()` must scale with `DIV_ROUND_CLOSEST(brightness * mcled_cdev->subled_info[i].intensity, led_cdev->max_brightness)` so low non-zero values do not truncate to 0. [F106, F116]
- `LED_FLASH_SYSFS_GROUPS_SIZE` (5) in `struct led_classdev_flash::sysfs_groups` must be at least one element larger than the maximum groups appended by `led_flash_init_sysfs_groups()` (4) to stay NULL-terminated. In `flash_fault_show()`, `ARRAY_SIZE(led_flash_fault_names)` must equal `LED_NUM_FLASH_FAULTS`. [F86, F122]
- In `leds-qcom-flash.c`, static `struct reg_field` templates (`mvflash_3ch_regs`, `mvflash_3ch_pmi8998_regs`, `mvflash_4ch_regs`) must remain `const` and be duplicated with `devm_kmemdup()` before adding `reg_base`, and `REG_THERM_THRSH3` must only be accessed when `flash_data->hw_type == QCOM_MVFLASH_3CH`. In `update_allowed_flash_current()`, existing `led->current_in_use_ma` must be subtracted from `flash_data->total_ma` and zeroed under `flash_data->lock` before adding new current, and `REG_THERM_THRSH1..3` must be saved into `thrsh[]`, tested in descending order (`OTST3..1`), and restored on all paths once modified. [F46, F66, F67, F100, F128]
- In `leds-max77693.c`, `sub_leds[fled_id].fled_id` must be set to `FLED1`/`FLED2` before `sub_led_to_led()` uses it in `container_of()`, and `max77693_led_iout_to_reg()` must clamp `ua >= FLASH_IOUT_MIN`. In drivers with a `__counted_by` flexible array (`mt6360_priv::leds`, `mt6370_priv::leds`, `sy7802::leds`, `aw200xx::leds`), `leds_count` / `num_leds` must be set to `count` before indexing `leds[]`. In `struct mt6360_led`, `isnk`, `mc`, and `flash` share a union and must only be used when matching `led->led_no`. [F113, F114, F117, F118]

## Synchronization

- Driver callbacks invoked from `set_brightness_delayed()` (`brightness_set`, `brightness_set_blocking`, `blink_set`) must never acquire `led_cdev->led_access` or `led_cdev->trigger_lock`, as `led_trigger_set()` and `led_classdev_unregister()` call `flush_work()` / `cancel_work_sync(&led_cdev->set_brightness_work)` while holding those locks. [F25]
- In the trigger lock hierarchy, `triggers_list_lock` and `leds_list_lock` nest outside `led_cdev->trigger_lock`, callers of `led_trigger_set()` must hold `down_write(&led_cdev->trigger_lock)`, and `trig->leddev_list_lock` nests inside `led_cdev->trigger_lock`. `led_trigger_read()` must lock `triggers_list_lock` then `led_cdev->trigger_lock`, hold both across the sizing and formatting calls to `led_trigger_format()` (where `led_trigger_snprintf()` must take signed `ssize_t size` so negative `size - len` selects `vsnprintf(NULL, 0, ...)`), unlock in reverse order, and free `data` with `kvfree()`. [F11, F121, F152]
- Traversals of `trig->led_cdevs` (`led_trigger_event()`, `led_mc_trigger_event()`, `led_trigger_blink_setup()`) must use `list_for_each_entry_rcu()` under `rcu_read_lock()`, and mutations must hold `trig->leddev_list_lock` with RCU list ops. In `led_trigger_set()`, attach must call `list_add_tail_rcu()`, `synchronize_rcu()`, and `flush_work(&led_cdev->set_brightness_work)` before `activate()`; detach and `err_add_groups` / `err_activate` rollback must call `list_del_rcu()` under `trig->leddev_list_lock`, `synchronize_rcu()`, `cancel_work_sync()`, and `led_stop_software_blink()` before removing groups, calling `deactivate()`, clearing `trigger` / `trigger_data`, or `kfree(event)`. [F8, F9, F28, F97]
- `led_blink_setup()` and `led_blink_set_oneshot()` run under `rcu_read_lock()` from `led_trigger_blink_setup()` and must never call `flush_work()` or sleep. When `LED_BLINK_SW` is set and `brightness == LED_OFF`, `led_set_brightness()` must set `LED_BLINK_DISABLE` and queue `set_brightness_work` rather than calling `led_stop_software_blink()` (`timer_delete_sync()`) directly from atomic context. [F148, F149]
- In `led_set_brightness_nopm()`, a deferred `LED_OFF` (`value == 0`) clears `LED_SET_BRIGHTNESS` and `LED_SET_BLINK` while setting `LED_SET_BRIGHTNESS_OFF` after writing `delayed_set_value`; `set_brightness_delayed()` processes `LED_SET_BRIGHTNESS_OFF` before `LED_SET_BRIGHTNESS` and re-arms `LED_SET_BRIGHTNESS` if `delayed_set_value != LED_OFF`. [F60]
- `led_classdev_register_ext()` holds `led_cdev->led_access` across `led_trigger_set_default()` and must not auto-promote `hw_control_trigger` to `default_trigger` (deadlocks with `rtnl_mutex`). `led_sysfs_disable()` / `led_sysfs_enable()` callers must hold `led_cdev->led_access`, and sysfs store handlers must check `led_sysfs_is_disabled(led_cdev)` under `led_cdev->led_access` and return `-EBUSY` when disabled. [F153, F168]
- In `aw2013_probe()`, `aw200xx_probe()`, and `sy7802_probe()`, `chip->mutex` must be initialized via `devm_mutex_init()` before locking, held across DT registration and hardware init, and unlocked on all error paths before devres destroys it. Because `aw200xx_regmap_config` sets `.disable_locking = true`, all `chip->regmap` accesses (`dim_store()`, `aw200xx_brightness_set()`, `aw200xx_probe()`) must hold `chip->mutex`. [F15, F136, F159]
- In `leds-mt6360.c`, `leds-mt6370-flash.c`, and `leds-sy7802.c`, the controller mutex (`priv->lock` / `chip->mutex`) must be held across checking that the opposite mode's bitmask (`fled_strobe_used` vs `fled_torch_used`) is zero (returning `-EBUSY` if non-zero), programming shared enable registers (keeping the shared enable bit set while any sibling bit remains set), and updating the active bitmask. In `leds-qcom-flash.c`, `flash_data->lock` must be held in `set_flash_module_en()` when updating `flash_data->chan_en_bits` and writing `!!flash_data->chan_en_bits` to `REG_MODULE_EN`. [F30, F32, F68, F72]

## Object Lifetimes

- During `led_classdev_unregister()`, `led_trigger_set(led_cdev, NULL)`, `led_stop_software_blink()`, and `flush_work(&led_cdev->set_brightness_work)` must complete before `device_unregister(led_cdev->dev)`, `list_del(&led_cdev->node)` under `leds_list_lock`, and `mutex_destroy(&led_cdev->led_access)`. Drivers using `devm_led_classdev_register_ext()` or `devm_led_classdev_flash_register_ext()` must not call `mutex_destroy()` in `.remove()` on any mutex acquired by `brightness_set_blocking`, because devres unregisters the LED and flushes `set_brightness_work` after `.remove()`. [F6, F126]
- `led_trigger_unregister()` must unlink `trig->next_trig` with `list_del_init()` under `triggers_list_lock` so `list_empty_careful(&trig->next_trig)` sees it as unregistered, and detach all matching LEDs on `leds_list` via `led_trigger_set(led_cdev, NULL)` before `led_trigger_unregister_simple()` frees `trig`. [F10]
- A `struct led_classdev` from `led_get()` must be released via `led_put()`, and `led_add_lookup()` entries removed with `led_remove_lookup()` before freeing. `led_classdev_next_name()` must call `put_device(dev)` on every non-NULL device from `class_find_device_by_name()`. `led_add_brightness_hw_changed()` must call `device_remove_file()` if `sysfs_get_dirent()` fails, and `led_remove_brightness_hw_changed()` must call `sysfs_put(led_cdev->brightness_hw_changed_kn)` before `device_remove_file()`. [F3, F5, F179]
- Flash drivers using `v4l2_flash_init()` must register `led_classdev_flash` first, check `v4l2_flash_init()` with `IS_ERR()` (its `!CONFIG_V4L2_FLASH_LED_CLASS` stub returns `NULL`, and `qcom_flash_v4l2_init()` must check `IS_ERR(v4l2_flash)` before storing into `flash_data->v4l2_flash[]`), and call `v4l2_flash_release()` before unregistering `led_classdev_flash`. Unscoped `fwnode_for_each_child_node()` loops must call `fwnode_handle_put(child)` on every early exit, and child pointers stored from `_scoped` loops must be pinned with `fwnode_handle_get()` / `of_node_get()` and released on error. [F99, F131, F132, F176]

## API Contracts

- `led_set_brightness_nopm()` invokes `led_cdev->brightness_set` synchronously whenever non-NULL (including from timer and hardirq/RCU contexts), so sleeping drivers must leave `brightness_set` NULL and use `brightness_set_blocking`. `led_blink_set_nosleep()` defers `blink_set` to `set_brightness_work` only when both `blink_set` and `brightness_set_blocking` are non-NULL, so `blink_set` must not sleep unless `brightness_set_blocking` is also set. [F146, F147]
- In `led_blink_setup()`, `led_set_software_blink()`, and driver `blink_set` callbacks, `!*delay_on && !*delay_off` (substituting default ms timings into both pointers) must be checked before individual `!*delay_on` or `!*delay_off` checks; `blink_set` must return 0 on hardware blink activation or non-zero for software fallback, and hardware blinking must stop on `LED_OFF`. [F105, F165]
- `led_get()`, `devm_led_get()`, and `devm_of_led_get()` return `ERR_PTR()` on failure and never `NULL`, whereas `devm_of_led_get_optional()` translates `ERR_PTR(-ENOENT)` into `NULL` while returning `ERR_PTR()` for other errors. `__devm_led_get()` consumes the `led` reference, calling `led_put(led)` immediately if `devres_alloc()` fails. [F2, F35]
- `led_get_default_pattern()` stores `fwnode_property_count_u32()` in a signed `int`, allocates with `kcalloc(count, sizeof(*pattern), GFP_KERNEL)`, passes element `count` to `fwnode_property_read_u32_array()`, frees `pattern` and returns `NULL` (not `ERR_PTR`) without modifying `*size` on failure, and writes `count` to `*size` on success. [F7, F40, F115]
- `led_classdev_flash_register_ext()` validates and installs `fled_cdev->ops`, `ops->strobe_set`, `led_cdev->brightness_set_blocking`, `flash_resume`, and `fled_cdev->sysfs_groups` only when `led_cdev->flags & LED_DEV_CAP_FLASH` is set; post-registration code like `qcom_flash_v4l2_init()` must check `LED_DEV_CAP_FLASH` first. Flash `brightness` is in uA, `timeout`/`duration` in us, `fault_get` outputs `LED_FAULT_*` bits, and any `struct led_flash_setting` used with `led_set_flash_*()` must have non-zero `step` and `min <= max`. [F44, F107, F160, F163]
- `led_classdev_multicolor_register_ext()` requires `1 <= mcled_cdev->num_colors <= LED_COLOR_ID_MAX` and `subled_info[i].color_index < LED_COLOR_ID_MAX`, and overwrites `led_cdev.groups`. `led_classdev_notify_brightness_hw_changed()` requires `LED_BRIGHT_HW_CHANGED` in `led_cdev->flags`. `led_trigger_register()` returns `-EEXIST` if a registered trigger shares `name` and either shares `trigger_type` or has `trigger_type == NULL`. [F166, F175, F178]

## Error Handling

- If `led_add_brightness_hw_changed()` fails in `led_classdev_register_ext()`, rollback must call `device_unregister(led_cdev->dev)` and set `led_cdev->dev = NULL` before unlocking `led_cdev->led_access` so `led_classdev_unregister()` exits at `IS_ERR_OR_NULL(led_cdev->dev)`. Non-devm multi-LED `probe()` loops must unwind already-registered LEDs in reverse order on failure, and DT parsers reusing `ret` (`__sso_led_dt_parse()`, `aw200xx_probe_fw()`) must set `ret = -EINVAL` on failed bounds checks before jumping to cleanup. [F4, F16, F49]
- `__led_set_brightness()` and `__led_set_brightness_blocking()` return `-ENOTSUPP` when the callback is NULL; `set_brightness_delayed_set_brightness()` relies on `-ENOTSUPP` to fall back from non-blocking to blocking and must silently ignore `-ENOTSUPP` as well as `-ENODEV` when both `LED_UNREGISTERING` and `LED_HW_PLUGGABLE` are set. [F38, F173]

## External Contracts

- In `led_classdev_register_ext()`, colliding names are resolved into `final_name` (`"%s_%u"`) for `led_cdev->dev->kobj.name` without modifying `led_cdev->name`, unless `LED_REJECT_NAME_CONFLICT` is set (returning `-EEXIST`). When `init_data` is non-NULL, `led_cdev->name` is not populated and may be NULL, so post-registration code must use `proposed_name`, `final_name`, or `dev_name(led_cdev->dev)`. Writing `0` (`LED_OFF`) to `brightness` (`brightness_store()`) must call `led_trigger_remove(led_cdev)` before `led_set_brightness()`, and core `led_class_attrs` must not add generic names like `color` that collide with `led_cdev->groups`. [F42, F98, F169, F180]

## Known Pitfalls

- On `struct led_classdev`, `flags` stores shifted `BIT()` masks (`LED_SUSPENDED`, `LED_UNREGISTERING`, etc.) manipulated with bitwise operators, whereas `work_flags` stores unshifted bit indices (`LED_BLINK_SW` = 0 .. `LED_SET_BLINK` = 8) manipulated with atomic bitops (`set_bit`, `clear_bit`, `test_bit`, `test_and_clear_bit`). [F55]
- In `led_compose_name()`, `struct led_properties props` must be zero-initialized before `led_parse_fwnode_props()`, and `props.color` / `props.func_enum` used only when `color_present` / `func_enum_present` are true. Calling `led_mc_calc_color_components()` before `led_classdev_register_ext()` defaults `max_brightness` to `LED_FULL` requires initializing `led_cdev.max_brightness` to non-zero first. [F53, F167]
- `led_flash_init_sysfs_groups()` only exposes `flash_brightness`, `flash_timeout`, and `flash_fault` groups when `ops->flash_brightness_set`, `ops->timeout_set`, and `ops->fault_get` are non-NULL, and overwrites `led_cdev->groups`. In flash drivers with 0-based torch current registers (`mt6360`, `mt6370`, `rt4505`, `sy7802`, `lm3601x`), subtracting 1 from `brightness`/`level` must occur only after checking it is non-zero, and `leds-mt6370-flash.c` / `leds-sy7802.c` callbacks must check for `MT6370_LED_JOINT` / `SY7802_LED_JOINT` (2) before single-channel macros. [F57, F91, F161]
- In `leds-aw200xx.c`, `AW200XX_LED2REG(x, columns)` must map `x` across the 12-column stride, `dim_store()` must write `AW200XX_REG_DIM_PAGE1` on page 1 (while `aw200xx_brightness_set()` writes paired `DIM`/`FADE` on page 4), and `aw200xx_imax_from_global()` must use `do_div()` on `u64 led_imax_uA`. [F93, F108, F135]
