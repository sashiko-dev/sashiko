# PWM SUBSYSTEM

The PWM subsystem (`drivers/pwm/` and `drivers/gpio/gpio-mvebu.c`) manages PWM chip registration, channel lookup (via DT, ACPI, or lookup tables), state and waveform rounding/application, and sysfs, character device (`/dev/pwmchip*`), GPIO (`CONFIG_PWM_PROVIDE_GPIO`), and debugfs interfaces, alongside controller drivers.

## Architecture & Data Flow

- In `__pwm_apply()`, assign `pwm->state = *state` only after `ops->apply()` or `__pwm_write_waveform()` succeeds and before `pwm_apply_debug()`, because `.apply()` inspects `pwm->state` for the previous state while `.get_state()` in `pwm_apply_debug()` depends on the updated `pwm->state`. In `pwm_apply_debug()`, skip rounding/polarity checks when `!s1.enabled`, and gate the `state->period < s2.period` warning on `s2.duty_cycle != 0`. [F52, F93]
- `pwm_state_valid()` treats any disabled `struct pwm_state` (`!state->enabled`) as valid regardless of `period`/`duty_cycle` (when enabled, `period > 0 && duty_cycle <= period`); driver `.apply()` callbacks must check `state->enabled` before dividing by `state->period` or subtracting `state->period - state->duty_cycle`. `pwm_wf_valid()` requires `period_length_ns <= S64_MAX`, `duty_length_ns <= period_length_ns`, and `duty_offset_ns == 0 || duty_offset_ns < period_length_ns` before `pwm_wf2state()` or `round_waveform_tohw()`. [F73, F74]
- In `pwmchip_alloc()` and `pwmchip_priv()`, compute size with `struct_size(chip, pwms, npwm)`, `ALIGN(..., PWMCHIP_ALIGN)`, and `size_add(..., sizeof_priv)`. `chip->npwm` is set in `pwmchip_alloc()` before `pwmchip_priv()` and must never increase (`pwms` is `__counted_by(npwm)`). `chip->atomic` discriminates the `nonatomic_lock`/`atomic_lock` union and must be set before `__pwmchip_add()` and never changed afterwards. [F37, F117, F119]
- In `drivers/pwm/core.c`, call `pwmchip_from_dev()` only on a controller device (`&chip->dev`), and call `pwmexport_from_dev()` and `pwm_from_dev()` only on an exported channel child device (`&export->pwm_dev`). [F121]
- In `pwm_get()`, scanning `pwm_lookup_list` must reset `match = 0` each iteration, weight `dev_id` by 2 and `con_id` by 1 (`dev+con > dev only > con only`), and record the winner in `chosen` rather than dereferencing the `list_for_each_entry` cursor `p` after the loop. [F96]
- `dwc_pwm_probe()` registers `ddata->info->nr` `struct pwm_chip` instances per PCI device: store per-chip `struct dwc_pwm` via `pwmchip_get_drvdata(chip)` and `struct dwc_pwm_drvdata` (with `ddata->chips[]`) via `dev_set_drvdata()` so `dwc_pwm_suspend()`/`dwc_pwm_resume()` iterate over all chips. [F55]
- Shared-period/pin guards: `pwm_imx_tpm_apply_hw()` must return `-EBUSY` on changing `tpm->real_period` if `tpm->user_count > 1` or `cmod && cur_prescale != p->prescale`, and `pwm_imx_tpm_suspend()` must reset `tpm->real_period = 0` when `tpm->enable_count == 0`. `fsl_pwm_apply_config()` must return `-EBUSY` if `fsl_pwm_is_other_pwm_enabled()` when changing `fpc->period`, and swap `fpc->clk[newclk]`/`fpc->clk[oldclk]` on `clk_select` change. `lpc18xx_pwm_config()` must return `-EBUSY` on changing non-zero `period_ns` when `bitmap_weight(&lpc18xx_pwm->event_map, LPC18XX_PWM_EVENT_MAX) > 2`. [F56, F57, F60, F61]
- `pwm_mediatek_clk_enable()` and `lpc18xx_pwm_probe()` must reject `clk_rate == 0 || clk_rate > NSEC_PER_SEC` (`lpc18xx_pwm` also stores `max_period_ns` as `u64` and `min_period_ns = DIV_ROUND_UP(NSEC_PER_SEC, clk_rate)`). `bcm2835_pwm_apply()` must check `state->period > max_period` (computed with `(u64)U32_MAX`) before multiplying `state->period * pc->rate`. [F108, F111, F112]

## Synchronization

- Lock hierarchy in `drivers/pwm/core.c`: `pwmchip_lock(chip)` nests inside both `pwm_lock` and `struct pwm_export::lock`; never acquire `pwm_lock` or `export->lock` (e.g., via `pwm_get()`/`pwm_put()`) while holding `pwmchip_lock(chip)`. `chip->operational` is modified only under both `pwm_lock` (outer) and `scoped_guard(pwmchip, chip)` (inner), so holding either lock suffices to read it. Paths already holding `pwm_lock` (e.g., `pwm_cdev_free()`, `pwm_cdev_ioctl()`, `pwm_seq_show()`) must call `__pwm_put()`, not `pwm_put()`. [F17, F20, F147]
- In `pwmchip_remove()`, call `gpiochip_remove(&chip->gpio)` and `pwmchip_sysfs_unexport(chip)` before acquiring `pwm_lock`, because `pwm_gpio_free()` and `pwm_unexport_child()` both call `pwm_put()`, which acquires `pwm_lock`. [F19]
- `pwm_device_request()`, `__pwm_put()`, and `pwmchip_remove()` call `ops->request` and `ops->free` under `pwm_lock` without `pwmchip_lock(chip)`, whereas `ops->apply`, `ops->get_state`, and waveform callbacks run under `pwmchip_lock(chip)` without `pwm_lock`; multi-channel drivers sharing state across `.request`/`.free` and `.apply`/`.get_state` need their own lock (e.g., `tpm->lock` in `pwm-imx-tpm.c`, `tcbpwmc->lock` across the full check-and-update in `atmel_tcb_pwm_apply()` and `atmel_tcb_pwm_request()`). [F18, F23, F28]
- When `chip->atomic` is true, `pwmchip_lock()` acquires `spin_lock(&chip->atomic_lock)` (and `pwm_apply_might_sleep()`/`pwm_set_waveform_might_sleep()` call `non_block_start()` under `CONFIG_PWM_DEBUG`), so `ops->apply`, `ops->get_state`, `ops->capture`, and waveform callbacks must not sleep. [F142]
- `pwm_class_get_state()` drops the `device_find_child()` reference on `pwm_dev` and returns a non-NULL `struct pwm_export *` with `export->lock` held; `pwm_class_suspend()` and `pwm_class_resume_npwm()` must release `export->lock` on every path via `pwm_class_apply_state()` or `mutex_unlock(&export->lock)`. [F7]
- In `drivers/pwm/pwm-meson.c`, `meson->lock` is shared with `channel->mux.lock`, `channel->div.lock`, and `channel->gate.lock` for `REG_MISC_AB` accesses: `spin_lock_init(&meson->lock)` must precede `meson->data->channels_init(chip)`, and `clk_set_rate()` in `meson_pwm_enable()` must be called outside `meson->lock`. [F26]
- In `drivers/pwm/pwm-gpio.c`, `pwm_gpio_probe()` must initialize `gpwm->lock` and `gpwm->gpio_timer`, register `pwm_gpio_disable_hrtimer` via `devm_add_action_or_reset()` before `pwmchip_add()`, and reject `gpiod_cansleep(gpwm->gpio)`. `pwm_gpio_apply()` and `pwm_gpio_get_state()` must use `guard(spinlock_irqsave)(&gpwm->lock)` and call `hrtimer_cancel(&gpwm->gpio_timer)` outside `gpwm->lock`. When `gpwm->running && state->enabled`, `pwm_gpio_apply()` stages `gpwm->next_state` with `gpwm->changing = true`, which `pwm_gpio_get_state()` must return. [F65, F129, F151, F152]

## Object Lifetimes

- Every `struct pwm_chip` passed to `__pwmchip_add()` must be allocated via `pwmchip_alloc()` or `devm_pwmchip_alloc()` (setting `chip->uses_pwmchip_alloc`) and released via `pwmchip_put()` (`put_device(&chip->dev)`), never `kzalloc()`, `devm_kzalloc()`, or embedded in a driver struct. [F1]
- `pwm_device_request()` acquires `try_module_get(chip->owner)` then `get_device(&chip->dev)` before `ops->request()`, and must roll them back in reverse order on failure. When `pwmchip_remove()` sets `chip->operational = false`, it clears `PWMF_REQUESTED` and calls `ops->free()` on requested channels; `__pwm_put()` must gate its `PWMF_REQUESTED` check and `ops->free()` call on `chip->operational`, while always calling `put_device(&chip->dev)` and `module_put(chip->owner)`. [F2, F3]
- Reference and allocation cleanup in core: `export_store()` must call `pwm_put(pwm)` if `pwm_export_child()` fails after `pwm_request_from_chip()`, and `pwm_unexport_child()` must call `put_device(pwm_dev)` and `pwm_put(pwm)`. `of_pwm_get()` and `pwm_get()` must call `pwm_put(pwm)` if `pwm_device_link_add()` returns an `ERR_PTR`. `of_pwm_get()` must call `of_node_put(args.np)` after `of_parse_phandle_with_args_map()`, and `of_pwmchip_add()` (`of_node_get()`) must be balanced by `of_pwmchip_remove()`. In `pwm_cdev_free()`/`pwm_cdev_release()`, save `pwm->label` before `__pwm_put()`/`pwm_put()` zeroes it, then `kfree(label)`, and set `cdata->pwm[hwpwm] = NULL` in `pwm_cdev_free()`. [F6, F9, F10, F130]
- Callers of `devm_add_action_or_reset()` (e.g., `devm_pwmchip_alloc()`, `__devm_pwmchip_add()`, `devm_pwm_get()`, `devm_fwnode_pwm_get()`, `devm_clk_rate_exclusive_get()`) must not invoke the cleanup callback on error, and `devm_add_action_or_reset()` callbacks must be dedicated `void (*)(void *)` wrappers (e.g., `devm_pwmchip_put`), never function-pointer casts. [F11, F123]
- Driver probe/remove/PM lifetimes: enable peripheral clocks before any MMIO `readl()`/`writel()` in `.probe()` (e.g., `pwm-imx-tpm`, `pwm-imx27`, `pwm-bcm-kona`, `pwm-bcm-iproc`, `pwm-hibvt`, `pwm-intel-lgm`). Drivers whose `.suspend()`, `.resume()`, or `.remove()` call `dev_get_drvdata()`/`platform_get_drvdata()` must set matching drvdata in `.probe()`. In explicit `.remove()` callbacks (`atmel_hlcdc_pwm_remove()`, `atmel_tcb_pwm_remove()`, `hibvt_pwm_remove()`, `lpc18xx_pwm_remove()`, `pwm_clk_remove()`), call `pwmchip_remove(chip)` before stopping hardware or disabling clocks. [F126, F127, F128]
- Driver resource tracking: `mvebu_pwm_request()` rejects requests with `-EBUSY` when `mvpwm->gpiod` is non-NULL under `mvpwm->lock`, so `mvebu_pwm_free()` must clear `mvpwm->gpiod = NULL` under `mvpwm->lock`. `atmel_hlcdc_pwm_apply()` must set `atmel->cur_clk = NULL` after `clk_disable_unprepare(atmel->cur_clk)` when `!state->enabled`, and `atmel_hlcdc_pwm_suspend()`/`resume()` must both check `if (!pwm->state.enabled)`. `pwm_mediatek_clk_enable()`/`disable()`, `pwm_mediatek_config()`, `pwm_mediatek_get_state()`, and `pwm_mediatek_init_used_clks()` must balance/roll back `clk_top`, `clk_main`, and `clk_pwms[hwpwm].clk`. [F13, F14, F15, F139, F140]

## API Contracts

- Waveform callbacks: `ops->sizeof_wfhw` must be `<= PWM_WFHWSIZE` (20 bytes) and callbacks must only access `ops->sizeof_wfhw` bytes of `wfhw`. `round_waveform_fromhw`, `read_waveform`, and `write_waveform` must return `0` or a negative errno (never `> 0`, unlike `round_waveform_tohw`). In `struct pwm_waveform`, a disabled channel has `period_length_ns == 0` (not `duty_length_ns == 0`). Only chips with `chip->ops->write_waveform != NULL` get a cdev `devt` (`/dev/pwmchip*`) and `CONFIG_PWM_PROVIDE_GPIO` `gpio_chip` in `__pwmchip_add()`/`pwmchip_remove()`. [F30, F41, F120, F167]
- Legacy state callbacks: `pwm_get_state_hw()` does not zero-initialize `*state`, so `.get_state()` must explicitly set `state->polarity` and `state->enabled` (plus `period` and `duty_cycle` when enabled). `.apply()` must reject unsupported `state->polarity` with `-EINVAL` rather than ignoring it. Under `pwm_apply_debug()`, `.apply()` must round `period` (when `duty_cycle != 0`) and `duty_cycle` down to hardware ticks, while `.get_state()` must round tick-to-ns divisions up (e.g., `DIV_ROUND_UP_ULL`) for idempotency. [F38, F105, F158]
- `pwmchip_alloc()` and `devm_pwmchip_alloc()` return `ERR_PTR()` on failure (never `NULL`; check with `IS_ERR()`) and store `pwmchip_priv(chip)` via `pwmchip_set_drvdata()`; drivers passing non-zero `sizeof_priv` must not overwrite `chip->dev` drvdata via `pwmchip_set_drvdata()` or `dev_set_drvdata()`. [F34, F118]
- All entry points indexing `chip->pwms[hwpwm]` or `cdata->pwm[hwpwm]` (`pwm_request_from_chip()`, `export_store()`, `unexport_store()`, `pwm_cdev_request()`, `pwm_cdev_free()`, `pwm_cdev_get_requested_pwm()`) must check `hwpwm < chip->npwm`. `of_pwm_single_xlate()` uses `args[0]` = period, `args[1]` = flags for channel 0 when `args_count < 3`, and delegates to `of_pwm_xlate_with_flags()` (`args[0]` = channel, `args[1]` = period, `args[2]` = flags) when `args_count >= 3`. `acpi_pwm_get()` must check `args.nargs >= 2` (returning `-EPROTO` otherwise) and `args.nargs > 2` for `args[2]`. `pwm_adjust_config()` must scale `state.duty_cycle` on period change and invert it (`period - duty_cycle`) on polarity change. [F51, F53, F75, F77]

## Error Handling

- Waveform error handling in `drivers/pwm/core.c`: core paths must check `pwmchip_supports_waveform(chip)` before waveform callbacks, and paths reading hardware waveforms (`pwm_get_waveform_might_sleep()`, `pwm_get_state_hw()`, `__pwm_set_waveform()`) must also check `ops->read_waveform != NULL` (for write-only drivers like `argon_fan_hat_pwm_ops`). In `__pwm_apply()`, convert `err > 0` from `__pwm_round_waveform_tohw()` to `-EINVAL`. In `pwm_set_waveform_might_sleep()`, remap `err == -EDOM` to `-EINVAL` before mapping `err == 1` to `-EDOM` (if `exact`) or `0` (if `!exact`). [F32, F33, F91]
- `pwm_device_link_add()` returns `NULL` when consumer `dev` is `NULL` (non-error) and `ERR_PTR(-EINVAL)` on failure; callers must test `IS_ERR(dl)`, not `!dl` or `IS_ERR_OR_NULL(dl)`. `pwm_put()` accepts `NULL` and must check `if (!pwm) return;` before dereferencing `pwm->chip`. In `pwm_class_suspend()`, save `export->suspend = state` before disabling each channel, and if `pwm_class_apply_state()` fails at index `i`, call `pwm_class_resume_npwm(pwmchip_dev, i)` to re-enable only channels `0 .. i - 1`. [F35, F36, F54]
- Driver error checks: `meson_pwm_calc()` must store `clk_round_rate()` in signed `long fin_freq` (`<= 0` check), and `meson_pwm_cnt_to_ns()` must guard `fin_freq == 0` and cast `cnt` to `u64`. `lp3943_pwm_parse_dt()` must store `of_property_count_u32_elems()` in signed `int num_outputs`. `mvebu_pwm_probe()` must return `0` when `"marvell,pwm-offset"` or `"pwm"` mem resource is absent. `fsl_pwm_ticks_to_ns()` and `fsl_pwm_calculate_duty()` must guard `do_div()` divisors against `0` and widen `duty_ns` to `unsigned long long`. [F42, F43, F49, F107, F110]

## External Contracts

- In `__pwm_apply()`, if `!pwm_state_valid(state)` and the current `!pwm_state_valid(&pwm->state)` (e.g., `enabled && !period`), it must assign `pwm->state = *state` and return `0` without calling driver callbacks so sysfs users can configure attributes incrementally. [F163]

## Known Pitfalls

- Clamping and overflow: in `lp3943_pwm_config()`, clamp `duty_ns = min(duty_ns, period_ns)` after clamping `period_ns` so `duty_ns * LP3943_MAX_DUTY / period_ns` fits in `u8`. In `mc33xs2410_pwm_apply()`, recompute `period = mc33xs2410_pwm_get_period(wr_val[0])` and clamp `min(period, state->duty_cycle)` before `rel_dc`. In `meson_pwm_calc()`, keep `duty`, `period`, `freq` as `u64` and use `mul_u64_u64_div_u64()`. In `__dwc_pwm_configure_timer()`, check `tmp < 1 || tmp > (1ULL << 32)` (not `1UL << 32`). In `gpio-mvebu.c`, map blink register `0` to/from `UINT_MAX + 1ULL` in 64-bit math and clamp sub-1-tick durations to `1`. When period/duty is `reg + 1` ticks (`pwm-mediatek`, `pwm-imx-tpm`), guard against `0` ticks before subtracting `1`. [F58, F68, F83, F109, F113, F115]
- In `pwm_round_waveform_might_sleep()`, check and log `ret_tohw` and `ret_fromhw` separately for `__pwm_round_waveform_tohw()` and `__pwm_round_waveform_fromhw()`, pass `(&wf_req, wf)` to `pwm_check_rounding()`, and return `ret_tohw`. [F90]
