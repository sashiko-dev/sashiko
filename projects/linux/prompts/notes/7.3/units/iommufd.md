# IOMMUFD

IOMMUFD (`drivers/iommu/iommufd`) provides the `/dev/iommu` userspace character device (and optional `/dev/vfio/vfio` compatibility) and in-kernel APIs for managing IOMMU objects, I/O Address Spaces (IOAS), paging and nested hardware page tables (HWPT), vIOMMUs, vDevices, hardware queues, and I/O page fault/event queues across tiered page pinning (`iopt_pages`), interval trees (`iopt_area`), `iommu_domain`s, and `iommufd_access` accessors.

## Architecture & Data Flow

- Interval tree nodes in `io_pagetable` (`area_itree`, `allowed_itree`, `reserved_itree`) use closed inclusive byte IOVAs `[start, last]`, whereas `iopt_pages` trees (`access_itree`, `domains_itree`), `iopt_area::pages_node`, and `last_*` variables use inclusive 0-based `PAGE_SIZE` page indices `[start, last]`; `pfn_reader::batch_end_index`, `pfn_reader_user::upages_end`, and `pfn_batch::end` use half-open exclusive bounds `[start, end)`. [F57, F84]
- Because an `iopt_area` can start at a non-zero sub-page `area->page_offset` within its first page (`iopt_area_index(area)`), `iopt_area_index_to_iova()`, `batch_from_domain()`, `raw_pages_from_domain()`, and `batch_to_domain()` must apply `area->page_offset` only on the first page index and reset `page_offset` to `0` thereafter. [F87]
- In `interval_tree_double_span_iter_update()`, `itrees[0]` (`access_itree`) is evaluated before `itrees[1]` (`domains_itree`) and `iter->last_used` is clamped to `min(iter->spans[i].last_used, last_hole)` so `itrees[0]` takes priority. In `pfn_reader_next()`, `interval_tree_double_span_iter_next(&pfns->span)` must only be called when `pfns->batch_end_index == pfns->span.last_used + 1` so mid-span stops resume within the same span. [F102, F103]
- When `iopt_area_split()` replaces `area` with `lhs` and `rhs` in `iopt->area_itree`, if `area->storage_domain` is non-NULL it must also remove `area->pages_node` from `pages->domains_itree`, insert `lhs->pages_node` and `rhs->pages_node`, copy `area->storage_domain` to both new areas, and increment `rhs->pages->kref`. [F61]
- `iopt_table_remove_domain()` must compact `iopt->domains` into a dense `[0, iopt->next_domain_id)` array before calling `iopt_unfill_domain()`, which relies on `iopt->next_domain_id != 0` and `xa_load(&iopt->domains, 0)` to reassign `area->storage_domain` or remove `area->pages_node` from `pages->domains_itree`. [F62]
- Any mutation to `iopt->domains`, `iopt->access_list`, or `iopt->disable_large_pages` must recalculate `iopt->iova_alignment` under write-locked `domains_rwsem` and `iova_rwsem`, and `iopt_disable_large_pages()` must revert `iopt->disable_large_pages` to `false` if `iopt_calculate_iova_alignment()` fails. [F63]
- Every device bound via `iommufd_device_bind()` must support `IOMMU_CAP_CACHE_COHERENCY`, every IOAS mapping protection mask built by `conv_iommu_prot()` or `iommufd_vfio_map_dma()` must include `IOMMU_CACHE`, and in `iommufd_hwpt_paging_alloc()`, `iommufd_hwpt_paging_enforce_cc()` and optional `immediate_attach` (`iommufd_hw_pagetable_attach()`) must execute before `iopt_table_add_domain(&ioas->iopt, hwpt->domain)` maps any PTEs. [F141, F166]
- `struct iommufd_hw_pagetable` is embedded in `iommufd_hwpt_paging` or `iommufd_hwpt_nested`; code must check `hwpt->obj.type` or use `find_hwpt_paging()` before downcasting with `to_hwpt_paging()` or `to_hwpt_nested()`. `iommufd_viommu_alloc_hwpt_nested()` must set both `hwpt_nested->viommu = viommu` and `hwpt_nested->parent = viommu->hwpt` so `find_hwpt_paging()` resolves the parent while `iommufd_hwpt_nested_destroy()` decrements only `viommu->obj.users`. [F51, F111]
- Internal `struct iommufd_access` objects created by `iommufd_access_create_internal()` leave `access->ictx` and `access->ops` as `NULL` (`iommufd_access_is_internal(access)`), so shared paths must check `!iommufd_access_is_internal(access)` before dereferencing `access->ops` or calling `iommufd_ctx_put()`. `iommufd_access_change_ioas()` must reject `access->ioas != access->ioas_unpin` with `-EBUSY`, clear `access->ioas = NULL` while keeping `access->ioas_unpin = cur_ioas` before dropping `access->ioas_lock` for `access->ops->unmap()`, and update both to `new_ioas` afterward. [F53, F70]

## Synchronization

- Operations on `struct io_pagetable` and `struct iopt_pages` must acquire locks strictly in the order `iopt->domains_rwsem` -> `iopt->iova_rwsem` -> `pages->mutex` -> `pages->source_mm->mmap_lock`. In `update_mm_locked_vm()`, if `user && user->locked` is non-zero, `mmap_read_lock(pages->source_mm)` must be released and `user->locked` set to `0` before acquiring `mmap_write_lock(pages->source_mm)`. [F27, F157]
- `iommufd_lock_obj()` must increment `obj->users` before `obj->wait_cnt` (under `xa_lock(&ictx->objects)` unless `obj->users` is already held), and `iommufd_put_object()` must decrement `obj->users` before `obj->wait_cnt` so `iommufd_object_remove()` with `REMOVE_WAIT` never sees `wait_cnt == 0` with elevated `users`. [F24]
- Callers of `iommufd_hwpt_paging_alloc()` must hold `ioas->mutex` until after `iommufd_object_finalize()` or `iommufd_object_abort_and_destroy()` is called on the returned `hwpt_paging`, and `iommufd_hwpt_paging_abort()` must call `list_del_init(&hwpt_paging->hwpt_item)` while `ioas->mutex` is held before `iommufd_hwpt_paging_destroy()`. [F6]
- `iommufd_hw_pagetable_put()` must only be called after releasing `ioas->mutex` and `igroup->lock` (as in `iommufd_hw_pagetable_detach()` and `iommufd_device_change_pt()`), because dropping the last reference to an `auto_domain` invokes `iommufd_hwpt_paging_destroy()`, which acquires `ioas->mutex`, `domains_rwsem`, and `iova_rwsem`. [F26]
- Writers of `area->num_accesses` (`iopt_area_add_access()` and `iopt_area_remove_access()`) must hold both `iopt->iova_rwsem` and `area->pages->mutex`. Before invoking `access->ops->unmap()`, callers must set `area->prevent_access = true` (in `iopt_unmap_iova_range()`) and release `access->ioas_lock`, `iopt->iova_rwsem`, `iopt->domains_rwsem`, and `xa_lock(&ioas->iopt.access_list)`. [F29, F152]
- `area->storage_domain` and `area->pages_node` in `pages->domains_itree` are protected by `area->pages->mutex`, and `iopt_unfill_domain()` must update or clear `area->storage_domain` under `pages->mutex` before `iopt_area_unmap_domain()` or `iopt_area_unfill_domain()` unmaps the domain. [F31]
- `idev->igroup->lock` protects `idev->vdev` and `idev->destroying`; `iommufd_vdevice_alloc_ioctl()` must check `!idev->destroying && !idev->vdev` under `idev->igroup->lock`, and `iommufd_device_remove_vdev()` must set `idev->destroying = true` and drop `idev->igroup->lock` before calling `iommufd_object_tombstone_user(idev->ictx, &vdev->obj)`. [F34]
- `iommufd_hwpt_detach_device()` and `iommufd_hwpt_replace_device()` must detach or replace the IOMMU attach handle before calling `iommufd_auto_response_faults()` and freeing the old handle. `fault->common.lock` (nested inside `fault->mutex` when both are taken) synchronizes `fault->common.deliver` and must be released before `copy_to_user()`, `xa_alloc(..., GFP_KERNEL)`, or `iopf_group_response()`. [F36, F149]
- Readers of `ictx->mt_mmap` in `iommufd_fops_mmap()` must hold `mtree_lock(&ictx->mt_mmap)` while looking up `struct iommufd_mmap` and incrementing `immap->owner->users` via `refcount_inc_not_zero()` before unlocking and dereferencing `immap`, and must drop that reference if subsequent mmap validation or `io_remap_pfn_range()` fails. [F25]

## Object Lifetimes

- `iommufd_device_do_replace()` must verify that `idev` itself is in `attach->device_array` via `iommufd_device_is_attached(idev, pasid)`, return `NULL` when `hwpt == old_hwpt`, and on a real replacement add `num_devices` (`iommufd_group_device_num(igroup, pasid)`) to `hwpt->obj.users`, subtract `num_devices - 1` from `old_hwpt->obj.users`, and return `old_hwpt` with one retained reference for the caller to release via `iommufd_hw_pagetable_put()`. [F9, F67]
- `iommufd_vdevice_alloc_ioctl()` transfers the `iommufd_get_device()` reference (both `users` and `wait_cnt` on `idev->obj`) to `vdev->idev` on success, and `iommufd_vdevice_destroy()` must release it with `iommufd_put_object()` after `iommufd_vdevice_abort()` clears `idev->vdev = NULL` under `idev->igroup->lock`. [F11]
- `iommufd_hw_queue_alloc_ioctl()` must pin the guest queue IOVA range via `iommufd_hw_queue_alloc_phys()` and verify contiguous PFNs before `viommu->ops->hw_queue_init_phys()`. `iommufd_hw_queue_alloc_phys()` must free its `kvcalloc()`-allocated `pages` array with `kvfree()` on all paths and undo `iommufd_access_pin_pages()`, `iommufd_access_detach_internal()`, and `iommufd_access_destroy_internal()` in reverse order on error; `iommufd_hw_queue_destroy()` must invoke `hw_queue->destroy` before unpinning `hw_queue->access`. [F13, F146]
- On error paths in `iopt_area_fill_domain()` and `iopt_area_fill_domains()`, `pfn_reader_release_pins(&pfns)` must be called before `iopt_area_unfill_partial_domain()` and `pfn_reader_destroy(&pfns)` so that newly pinned pages buffered in `pfns` are unpinned before `update_unpinned()` reconciles `pages->npinned` with `pages->last_npinned`. [F16]
- Because `iopt_pages_fill_xarray()` points `user.upages` into the caller-supplied `out_pages` array via `iopt_pages_fill()`, it must reset `user.upages = NULL` before calling `pfn_reader_user_destroy(&user, pages)` on every exit path so `pfn_reader_user_destroy()` does not `kfree()` the caller's buffer. [F17]
- An `iommufd_object` type associated with a `struct file` holding a `users` reference must declare `IOMMUFD_FILE_OFFSET` in `iommufd_object_ops` and defer `fd_install()` until all fallible steps succeed, so `iommufd_object_abort_and_destroy()` can synchronously close the file via `__fput_sync()` before freeing the object. [F22]

## API Contracts

- Every object allocated by `_iommufd_object_alloc()` or `_iommufd_object_alloc_ucmd()` must place its `struct iommufd_object` member at offset 0 so `kfree(obj)` frees the base address and `iommufd_get_object()` / `iommufd_get_*()` `container_of()` wrappers preserve `ERR_PTR(-ENOENT)` (never `NULL`, so callers must check `IS_ERR()`). `_iommufd_object_alloc_ucmd()` can be called at most once per `iommufd_ucmd` and only when `iommufd_object_ops[type].abort` is `NULL`; callers must not manually finalize or abort it. [F39, F56, F123]
- When `to_destroy` is non-NULL, `iommufd_object_remove()` always consumes the caller's `to_destroy->users` reference even on failure, and if `refcount_dec_if_one(&obj->users)` fails after `REMOVE_WAIT` zeroed `obj->wait_cnt`, it must restore `obj->wait_cnt` to 1 under `ictx->objects` `xa_lock`. [F4]
- Because `iopt_for_each_contig_area()` terminates with `area == NULL` both when `[iova, last_iova]` is fully traversed and when a gap or unpopulated area (`!area->pages`) is hit, `iopt_area_contig_init()` and `iopt_area_contig_next()` must set `iter->area = NULL` on failure while keeping `iter->area` non-NULL upon normal completion (`iter->last_iova <= last_iova`), and callers must check `iopt_area_contig_done(&iter)` after the loop. [F43, F98]
- `iommufd_access_pin_pages()` requires every `iopt_area` slice in `[iova, last_iova]` to be `PAGE_SIZE`-aligned in its backing `iopt_pages` (`iopt_area_contig_is_aligned()`), and `iommufd_access_unpin_pages()` / `iopt_area_remove_access()` require the exact same `(iova, length)` / `[start_index, last_index]` slice and `unlock_area` boolean passed when pinning because `iopt_pages_get_exact_access()` matches nodes by exact `start` and `last`. [F58, F88]

## Error Handling

- When domain allocation fails with an `ERR_PTR` in `iommufd_hwpt_paging_alloc()`, `iommufd_hwpt_nested_alloc()`, or `iommufd_viommu_alloc_hwpt_nested()`, `hwpt->domain` must be cleared to `NULL` before jumping to `out_abort` so `__iommufd_hwpt_destroy()` does not pass an error pointer to `iommu_domain_free()`. [F8]
- `iommufd_hw_pagetable_detach()` returns `NULL` when `xa_load(&igroup->pasid_attach, pasid)` finds no attachment, and callers such as `iommufd_device_detach()` must check the returned `hwpt` for `NULL` before decrementing `idev->obj.users` or dereferencing `hwpt`. [F42]
- In `iommufd_hw_pagetable_attach()`, `xa_store(&igroup->pasid_attach, pasid, attach, GFP_KERNEL)` must only be called after `iommufd_hwpt_attach_device()` succeeds so that `igroup->pasid_attach` retains `XA_ZERO_ENTRY` and `iommufd_group_first_attach(igroup, pasid)` remains true for `err_free_attach` and `err_release_pasid` on failure. [F110]
- In `iommufd_device_do_replace()`, the `err_unresv` rollback path must pass the newly prepared `hwpt_paging` rather than `old_hwpt_paging` to `iommufd_group_remove_reserved_iova()`, whereas the success path removes reserved IOVAs from `old_hwpt_paging` when its `ioas` differs from the new HWPT. [F95]
- In `iommufd_access_pin_pages()`, `iopt_area_add_access()` must be the last fallible operation in the `iopt_for_each_contig_area()` loop body because the `err_remove` rollback unpins `[iova, iter.cur_iova - 1]` and relies on `iopt_area_contig_next()` advancing `iter.cur_iova` before inspecting the next area. In `iommufd_access_rw()`, `rc` must be initialized to `-EINVAL` before the `iopt_for_each_contig_area()` loop so an empty iteration never returns uninitialized stack data. [F44, F99]
- `iopt_add_access()` must allocate the `iopt->access_list` XArray ID into a temporary local variable and only assign `access->iopt_access_list_id` after `iopt_calculate_iova_alignment()` succeeds. [F64]

##Known Pitfalls

- When `batch_clear_carry()` carries `keep_pfns` from `batch->end - 1` into slot 0, it must compute `batch->pfns[0]` using `batch->npfns[batch->end - 1]` before overwriting `batch->npfns[0] = keep_pfns` (in case `batch->end == 1`), and must set `batch->end = 1` and `batch->total_pfns = keep_pfns`. In `iopt_area_unpin_domain()`, when reading PFNs starting from `start = max(start_index, *unmapped_end_index)`, `batch_last_index` must be computed as `start_index + batch->total_pfns - 1` (not `start + batch->total_pfns - 1`) because `batch->total_pfns` already includes carried PFNs covering `[start_index, *unmapped_end_index)`. [F65, F85]
- In `struct iova_bitmap`, `bitmap->bitmap` must use `u8 __user *` byte granularity and `iova_bitmap_get()` must add `!!offset_in_page(addr)` to `npages` before clamping to `PAGE_SIZE / sizeof(struct page *)`. In `iova_bitmap_set()`, `page_idx` (`cur_bit / BITS_PER_PAGE`) must be checked against `last_page_idx` (`mapped->npages - 1`) on every loop iteration (calling `iova_bitmap_advance_to()` when `page_idx > last_page_idx`), and `bitmap_set()` must be called on the page-aligned `kaddr` from `kmap_local_page(mapped->pages[page_idx])` with `mapped->pgoff * BITS_PER_BYTE` added to bit offsets rather than `kaddr + mapped->pgoff`. [F83, F133, F134]
- In `__alloc_iova_check_range()`, aligning candidate IOVA start boundaries up to `iova_alignment` must use `check_add_overflow(*start, iova_alignment - 1, &aligned_start)` rather than `ALIGN()`, and must verify `aligned_start < last` before subtracting `last - aligned_start`. In `iommufd_hw_queue_alloc_phys()`, rounding `offset + cmd->length` up to `PAGE_SIZE` to compute `max_npages` and `length` must use chained `check_add_overflow()` calls into `size_t length` rather than `DIV_ROUND_UP()` or `PAGE_ALIGN()`. [F112, F116]
- When computing a page size or alignment mask by left-shifting by a bit index from `__ffs()`, `__ffs64()`, or `iova_bitmap_map::pgshift` (such as in `iova_bitmap_offset_to_index()`, `iopt_alloc_iova()`, and `iopt_table_add_domain()`), the shifted constant must be `1UL` rather than the 32-bit `int` literal `1`. [F113]
- In `__iopt_remove_reserved_iova()`, the next node must be prefetched via `next = iopt_reserved_iter_next(reserved, 0, ULONG_MAX)` before calling `interval_tree_remove(&reserved->node, &iopt->reserved_itree)` and `kfree(reserved)`. [F108]
