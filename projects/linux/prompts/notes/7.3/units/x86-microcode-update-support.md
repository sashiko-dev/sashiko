# X86 MICROCODE UPDATE SUPPORT

This unit implements early-boot (initrd/built-in firmware) and late-runtime (sysfs/firmware loader) CPU microcode update support for x86 Intel and AMD processors. `core.c` provides the vendor-agnostic framework, including command-line parsing, sysfs interfaces, CPU hotplug and syscore resume hooks, and stop_machine/NMI rendezvous synchronization across SMT siblings and offline CPUs during late loading. `intel.c` and `amd.c` implement vendor-specific binary blob parsing, header/checksum/SHA-256 verification, patch caching, and MSR-based microcode application.

## Architecture & Data Flow

- Before calling `find_patch(cpu)`, `ucode_cpu_info[cpu].cpu_sig.sig` must be populated with `CPUID(1).EAX` (as in `load_ucode_amd_bsp()`, `load_ucode_amd_ap()`, and `collect_cpu_info_amd()`), and `mc_cpu_online()` must zero `ucode_cpu_info[cpu]` before `collect_cpu_info()`. Whenever a CPU's revision is collected or updated in `mc_cpu_online()`, `apply_microcode_late()`, or `apply_microcode_amd()`, `ucode_cpu_info[cpu].cpu_sig.rev`, `cpu_data(cpu).microcode`, and (on CPU 0) `boot_cpu_data.microcode` must be updated in lockstep. [F32, F37]
- In `load_late_locked()`, `setup_cpus()` must validate online/offline CPU state before `microcode_ops->request_microcode_fw()` is invoked; in `load_late_stop_cpus()`, `store_cpu_caps(&prev_info)` must be called before `stop_machine_cpuslocked()` so `microcode_check(&prev_info)` compares against pre-update hardware CPUID capabilities rather than `boot_cpu_data`. [F38, F39]
- In `load_ucode_intel_bsp()` and `load_ucode_amd_bsp()`, `ed->old_rev` must be sampled before applying the patch and `ed->new_rev` must be set only if applying the patch succeeds, because `microcode_init()` tests `early_data.new_rev` to report whether an early update occurred. [F40]
- In `load_microcode_amd()`, after `_load_microcode_amd()` populates `microcode_cache`, `find_patch(cpu)` must be checked against `cpu_data(cpu).microcode` using `cpumask_first(cpumask_of_node(nid))` across `for_each_node_with_cpus(nid)` rather than `for_each_node()` or only CPU 0, so mixed-stepping multi-node systems return `UCODE_NEW` when any populated node needs an update without indexing an empty node cpumask. [F47, F61]
- On AMD Zen and newer (`x86_family(bsp_cpuid_1_eax) >= 0x17`), `equiv_table` is bypassed by `find_equiv_id()`, `verify_equivalence_table()`, `install_equiv_cpu_table()`, and `free_equiv_cpu_table()`, and patches are matched by decoding family/model/stepping from `patch_id` via `ucode_rev_to_cpuid()`. `cpuid_to_ucode_rev()` and `ucode_rev_to_cpuid()` must zero-initialize `union zen_patch_rev` and `union cpuid_1_eax` (`p = {}`, `c.full = 0`) before writing bitfields because callers compare the full 32-bit `ucode_rev` or `full` word. [F33, F106]
- In `verify_and_add_patch()`, `patch` must be allocated with `sizeof(*patch)` while `patch->data` is allocated with `kmemdup(fw + SECTION_HDR_SIZE, *patch_size, GFP_KERNEL)` and `patch->size` is set to `*patch_size`, because `__apply_microcode_amd()` passes `p->size` to `verify_sha256_digest()` to hash the exact patch payload. Broken by: passing `*patch_size` to `kzalloc()` for `struct ucode_patch`, or computing `p->size` from `ksize(p->data)` or including `SECTION_HDR_SIZE`. [F85]
- In AMD containers, `struct equiv_cpu_entry` and `struct microcode_header_amd` must remain `__packed`. The equivalence table byte length `hdr[2]` excludes `CONTAINER_HDR_SZ` (12 bytes)—entries start at `buf + CONTAINER_HDR_SZ`, `num_entries` is `hdr[2] / sizeof(struct equiv_cpu_entry)`, and advancing to the first section adds `hdr[2] + CONTAINER_HDR_SZ`—and each section's `u32` patch size at offset 4 (`sh_psize`) excludes the 8-byte `SECTION_HDR_SIZE`, so header/patch pointers must be offset by `SECTION_HDR_SIZE` and buffers advanced by `patch_size + SECTION_HDR_SIZE`. [F62, F86, F87]
- In `intel_microcode_sanity_check()` and `intel_find_matching_signature()`, `ext_header` is at byte offset `MC_HEADER_SIZE + intel_microcode_get_datasize(mc_hdr)` from `mc` (adding `EXT_HEADER_SIZE` and `EXT_SIGNATURE_SIZE * i` to `(void *)ext_header`). `data_size + MC_HEADER_SIZE > total_size` and `ext_table_size < EXT_HEADER_SIZE` must be rejected before unsigned subtractions, and the `u32 *` checksum loops must divide `ext_table_size` and `MC_HEADER_SIZE + data_size` by `sizeof(u32)`. [F79, F89, F90]

## Synchronization

- Secondary and soft-offlined SMT threads in `load_secondary()`, `load_secondary_wait()`, `wait_for_cpus()`, `wait_for_ctrl()`, and `microcode_offline_nmi_handler()` must remain `noinstr` and use `raw_cpu_*`/`raw_atomic_*` accessors until `wait_for_ctrl()` returns, because instrumentation exceptions (`#INT3`, `#DB`, `#PF`) reenable NMIs via `IRET`; inside the spin loops of `wait_for_cpus()` and `wait_for_ctrl()`, `instrumentation_begin()` and `touch_nmi_watchdog()` must only be called when `!microcode_ops->use_nmi`. [F116, F117]
- In `__load_primary()`, the primary thread must write its own `ucode_ctrl.result` before setting `per_cpu(ucode_ctrl.ctrl, sibling)` to `SCTRL_APPLY` or `SCTRL_DONE`, and must always update `ucode_ctrl.ctrl` for every sibling after `wait_for_cpus(&late_cpus_in)` succeeds. [F17]
- In `load_primary()` on CPU 0 (`!cpu && nr_offl`), if `kick_offline_cpus(nr_offl)` times out waiting for `offline_in_nmi == nr_offl`, `__load_primary(cpu)` must be skipped, and `release_offline_cpus()` must still be called unconditionally to set `ucode_ctrl.ctrl = SCTRL_DONE` on all CPUs in `cpu_offline_mask`. [F114]
- When `wait_for_cpus()` times out waiting for `cnt` to reach zero, it must execute `raw_atomic_inc(cnt)` before returning `false` so late-arriving CPUs cannot decrement `cnt` to zero and proceed after other CPUs have already timed out. [F74]
- Before sending `NMI_VECTOR` to an online or soft-offlined CPU for microcode rendezvous, the sender must set that CPU's `ucode_ctrl.nmi_enabled` to `true`, and `microcode_nmi_handler()` and `microcode_offline_nmi_handler()` must clear `ucode_ctrl.nmi_enabled` to `false` upon entry. [F14]
- `load_late_locked()` and `load_late_stop_cpus()` require `cpus_read_lock()` (held by `reload_store()`). In `setup_cpus()`, every CPU in `cpus_booted_once_mask` that is a primary SMT thread (`topology_is_primary_thread(cpu)`) must be online, and offline secondary threads are permitted only if `microcode_ops->nmi_safe || (microcode_ops->use_nmi && apic->nmi_to_offline_cpu)`. Before `stop_machine_cpuslocked(load_cpus_stopped, ...)`, `load_late_stop_cpus()` must initialize `late_cpus_in`, `offline_in_nmi`, `loops_per_usec`, and `microcode_nmi_handler_enable`. [F13, F113, F120]

## Object Lifetimes

- In `intel.c`, `load_ucode_intel_bsp()` sets `ucode_patch_va` to the sentinel `UCODE_BSP_LOADED` (`0x1UL`) rather than storing the initrd/built-in pointer from `get_microcode_blob()`, and `save_builtin_microcode()` must clear `ucode_patch_va` to `NULL` via `xchg()` before copying the patch to heap with `save_microcode_patch()`. [F1]
- In `parse_microcode_blobs()` (`intel.c`), `mc` is a reusable scratch buffer across loop iterations; when promoting `mc` to `new_mc`, the code must `kvfree(new_mc)` any prior candidate and reset `mc = NULL` so subsequent iterations do not overwrite `new_mc` and the exit paths (`kvfree(mc)` and `fail:`) do not double-free it. [F2]
- When Intel's `request_microcode_fw()` returns `UCODE_NEW` or `UCODE_NEW_SAFE`, `ucode_patch_late` holds a heap allocation; in `load_late_stop_cpus()`, `microcode_ops->finalize_late_load(!updated)` receives `0` on success and `1` on failure, where Intel's `finalize_late_load()` must transfer `ucode_patch_late` to `ucode_patch_va` via `update_ucode_pointer()` (which `kvfree()`s the prior `ucode_patch_va`) on `0` or `kvfree(ucode_patch_late)` on non-zero and reset `ucode_patch_late = NULL`, and AMD's `finalize_late_load_amd()` must call `cleanup()` on non-zero. [F3, F100]
- `microcode_bsp_resume()` tests `ucode_cpu_info[cpu].mc` to dispatch `microcode_ops->apply_microcode(cpu)` vs `reload_early_microcode(cpu)`, so Intel must keep `ucode_cpu_info[cpu].mc` `NULL` (since `apply_microcode_late()` uses `ucode_patch_late`), while AMD sets it to `p->data` and clears it to `NULL` in `microcode_fini_cpu_amd()`, which `mc_cpu_down_prep()` must invoke via `microcode_fini_cpu(cpu)` along with `sysfs_remove_group(&dev->kobj, &mc_attr_group)`. [F6, F98]
- In `amd.c`, `free_equiv_cpu_table()` must zero `equiv_table` after `vfree(equiv_table.entry)`, and `_load_microcode_amd()` must call `free_equiv_cpu_table()` before `install_equiv_cpu_table()` and call `cleanup()` (freeing both `equiv_table` and `microcode_cache`) whenever `__load_microcode_amd()` fails. [F5]
- In `request_microcode_fw()` (`intel.c`) and `request_microcode_amd()` (`amd.c`), the `const struct firmware *` obtained from `request_firmware_direct()` must be released with `release_firmware()` before returning on every path after successful acquisition, and any retained patches must be heap-copied before `release_firmware()`. [F7]

## API Contracts

- In `amd.c`, `update_cache()` unconditionally consumes ownership of `new_patch` and `new_patch->data`, either linking `new_patch` into `microcode_cache` (and freeing any replaced entry `p` and `p->data`) or freeing `new_patch->data` and `new_patch` when an equal or newer patch is already cached; `patch_newer(p, new_patch)` is a signed tri-state where `< 0` (different stepping on Family >= 0x17) continues scanning `microcode_cache`, `0` frees `new_patch` and returns, and `> 0` replaces `p` with `new_patch` and immediately returns (whereas `free_cache()` must use `list_for_each_entry_safe()`). [F4, F67, F76]
- `MSR_IA32_UCODE_WRITE` in `__apply_microcode()` must be passed the address of the Intel payload `mc->bits` (past the 48-byte `struct microcode_header_intel`), whereas in `__apply_microcode_amd()`, `MSR_AMD64_PATCH_LOADER` must be written with `(unsigned long)&mc->hdr.data_code` (past `SECTION_HDR_SIZE`) after `verify_sha256_digest()` succeeds, and on Family `0x17` (`x86_family(bsp_cpuid_1_eax) == 0x17`), `invlpg()` must be executed on `p_addr` and on `p_addr_end` (`p_addr + psize - 1`) if it crosses a page boundary. [F34, F104]
- Callers of `intel_microcode_sanity_check(void *mc, bool print_err, int hdr_type)` must ensure the buffer at `mc` holds at least `sizeof(struct microcode_header_intel)` and `get_totalsize(mc)` bytes before calling it, must check for any negative (or non-zero) return value rather than testing exclusively for `-EINVAL` (as an extended signature table size mismatch returns `-EFAULT`), and must pass `mc` through `intel_microcode_sanity_check()` before calling `intel_find_matching_signature(mc, sig)` so `ext_hdr->count` is validated against `ext_table_size`. [F35, F55, F129]
- Despite their `unsigned int family` parameter name in `internal.h`, `load_ucode_amd_bsp()` and `load_ucode_amd_ap()` require the raw `CPUID(1).EAX` signature value (`cpuid_1_eax`) rather than `x86_family(cpuid_1_eax)`, because they store it in `bsp_cpuid_1_eax` and `ucode_cpu_info[cpu].cpu_sig.sig`. [F24]
- `verify_patch()` and `verify_and_add_patch()` return `< 0` on error, `0` on a matching-family patch, and `1` on a non-matching-family patch, and must populate `*patch_size` before returning `1`. `parse_container()` returns `0` both when `verify_equivalence_table()` fails and when a match is found (`desc->mc` is non-NULL), and `orig_size - size` when no match was found; `scan_containers()` callers must zero-initialize `struct cont_desc` and check `size >= s` before `ucode += s; size -= s;`. [F26, F27, F81]
- `load_ucode_intel_bsp()` and `load_ucode_amd_bsp()` run before memory allocators are usable and must apply patches in-place from initrd/built-in memory, deferring heap copies (`save_microcode_patch()`, `_load_microcode_amd()`) to `early_initcall` (`save_builtin_microcode()`, `save_microcode_in_initrd()`); `save_microcode_in_initrd()` must call `_load_microcode_amd()` rather than `load_microcode_amd()`, because `for_each_node_with_cpus(nid)` and `cpumask_of_node(nid)` are not initialized at `early_initcall` time. [F110, F122]

## Error Handling

- In `load_secondary_wait()`, if `wait_for_cpus(&late_cpus_in)` times out at the initial rendezvous, the secondary CPU records `UCODE_TIMEOUT` and returns `false` without panicking, whereas if `wait_for_ctrl()` times out waiting for its primary thread to complete the update, it must call `panic()`. [F132]
- The kernel must be tainted with `TAINT_CPU_OUT_OF_SPEC` (`LOCKDEP_STILL_OK`) when `load_late_stop_cpus()` updates at least one CPU (`updated > 0`) while `!is_safe || failed || timedout`, or when `microcode.amd_sha_check=off` disables AMD patch SHA-256 verification in `load_ucode_amd_bsp()`. [F133]
- In `load_late_locked()`, the `switch` on `microcode_ops->request_microcode_fw()` must explicitly handle `UCODE_OK` by returning `0` without calling `load_late_stop_cpus()`. In `scan_microcode()`, the function must return `size ? NULL : patch` after its loop so any early `break` on a truncated record rejects the entire blob. [F64, F71]

## Known Pitfalls

- Unlike Intel, AMD early BSP loading in `load_ucode_amd_bsp()` and AP/late loading in `apply_microcode_amd()` must apply a patch even when the current revision equals `mc->hdr.patch_id` (skipping only when `rev > mc->hdr.patch_id`), whereas `reload_ucode_amd()` and `load_microcode_amd()` only trigger when `rev < patch_id`. [F105]
- In `get_totalsize()` and `intel_microcode_get_datasize()`, a zero `hdr->datasize` in `struct microcode_header_intel` indicates a legacy Intel microcode format where `hdr->totalsize` is ignored and sizes default to `DEFAULT_UCODE_DATASIZE` (2000) and `DEFAULT_UCODE_TOTALSIZE` (2048). Broken by: reading `hdr->totalsize` or `hdr->datasize` directly instead of calling `get_totalsize()` and `intel_microcode_get_datasize()`. [F56]
- `load_ucode_ap()` and its vendor callees (`load_ucode_intel_ap()`, `load_ucode_amd_ap()`) run during AP bringup both at boot and during post-init CPU hotplug with interrupts disabled, so they must not be marked `__init`, call `__init` functions like `microcode_loader_disabled()` or `find_microcode_in_initrd()`, or sleep; furthermore, `microcode_loader_disabled()`, `amd_check_current_patch_level()`, `load_ucode_bsp()`, and `load_ucode_ap()` must query CPU vendor and family via `x86_cpuid_vendor()` and `native_cpuid_eax(1)` instead of `boot_cpu_data`. [F119, F125]
