# S390 VFIO-AP DRIVER

The S390 VFIO AP driver (`vfio_ap`) implements VFIO mediated device (mdev) passthrough of s390 Adjunct Processor (AP) cryptographic adapters, usage domains, and control domains to KVM guests. It registers a virtual `matrix` bus and root device (`matrix_dev`), an AP bus driver (`vfio_ap_drv`) for CEX4+ crypto queues, and an mdev driver (`vfio_ap_matrix_driver`) exposing sysfs matrix assignment attributes and `vfio_ap_matrix_dev_ops`. It manages guest APCB shadow masks (`shadow_apcb`), intercepts guest `PQAP(AQIC)` via a KVM `pqap_hook` (`handle_pqap`) to pin NIB pages and register GISA interrupts, resets AP queues via `system_long_wq` workers, and handles dynamic host AP configuration changes.

## Architecture & Data Flow

- Bit-level tests, mutations, and iterations on `ap_matrix`, `ap_config_info`, and `ap_matrix_mdev` masks (`apm`, `aqm`, `adm`, `apm_add`, `aqm_add`, `adm_add`) must use s390 big-endian inverted bitops (`test_bit_inv`, `set_bit_inv`, `clear_bit_inv`, `find_first_bit_inv`, `for_each_set_bit_inv`). Word-level `bitmap_*` calls (`bitmap_and`, `bitmap_andnot`, `bitmap_equal`, `bitmap_intersects`, `bitmap_empty`, `bitmap_clear`) on these inverted masks must always pass full-long bit counts (`AP_DEVICES` or `AP_DOMAINS`, 256) rather than `*_max + 1`. [F55, F80]
- `ap_matrix.apm_max`, `aqm_max`, and `adm_max` hold inclusive 0-based maximum IDs (`info->na`/`info->nd` if `info->apxa`, else 63/15). Sysfs store handlers and `ap_matrix_overflow_check()` must reject `bit > *_max` with `-ENODEV`, while `vfio_ap_mdev_matrix_show()` and `control_domains_show()` must pass `*_max + 1` as bit-search limits (`vfio_ap_mdev_matrix_show()` must also check `(apid1 < napm_bits) && (apqi1 < naqm_bits)` before the single-mask `else if` branches). `ap_matrix_copy()` copies only the bitmaps, so `matrix_mdev->matrix` and `shadow_apcb` max bounds must be initialized via `vfio_ap_matrix_init()`. [F39, F56, F62, F90]
- In `ap_config_store()`, `matrix_mdev->matrix` must hold `m_new` during `vfio_ap_mdev_validate_masks()` and `ap_matrix_overflow_check()`, be restored to `m_old` before `vfio_ap_mdev_hot_unplug_adapters()` and `vfio_ap_mdev_hot_unplug_domains()`, and be copied from `m_new` again before `vfio_ap_mdev_link_adapter()` and `vfio_ap_mdev_link_domain()`. [F68]
- In `vfio_ap_mdev_hot_unplug_adapters()` and `vfio_ap_mdev_hot_unplug_domains()`, `vfio_ap_mdev_unlink_adapter()` or `vfio_ap_mdev_unlink_domain()` must be called before clearing the bit in `matrix_mdev->shadow_apcb`, and `qlist` cleanup must use `list_for_each_entry_safe` to call `list_del(&q->reset_qnode)`. [F67]
- In `vfio_ap_mdev_filter_matrix()`, after intersecting `matrix_mdev->matrix` with `matrix_dev->info` into `shadow_apcb`, `_queue_passable()` checks must iterate over `shadow_apcb.apm` and `shadow_apcb.aqm` (not `matrix_mdev->matrix`) so host-unconfigured queues do not filter out assigned adapters. Any APID cleared from `shadow_apcb.apm` that was set in `prev_shadow_apm` must be recorded in `apm_filtered` and reset by the caller via `reset_queues_for_apids()`. [F43, F44]
- In `vfio_ap_mdev_remove_queue()`, if the removed queue's APID and APQI are set in `shadow_apcb`, the driver must clear the APID from `shadow_apcb.apm`, call `vfio_ap_mdev_update_guest_apcb()`, and call `reset_queues_for_apid()` before unlinking `q` via `vfio_ap_unlink_queue_fr_mdev()`. If not reset via `reset_queues_for_apid()`, it must verify both `AP_QID_CARD(q->apqn)` and `AP_QID_QUEUE(q->apqn)` are set in `matrix_dev->info.apm` and `info.aqm` before calling `vfio_ap_mdev_reset_queue(q)`. [F47, F85]
- In `vfio_ap_mdev_probe_queue()`, `vfio_ap_mdev_link_queue(matrix_mdev, q)` must execute before checking whether `matrix_mdev->apm_add` or `aqm_add` is non-empty, and `vfio_ap_on_scan_complete()` must clear `apm_add`, `aqm_add`, and `adm_add` after `vfio_ap_mdev_hot_plug_cfg(matrix_mdev)`. [F70]
- After `ap_get_qdev(apqn)` returns a non-NULL `struct ap_queue *`, `vfio_ap_find_queue()` must verify `queue->ap_dev.device.driver == &matrix_dev->vfio_ap_drv->driver` before reading `dev_get_drvdata(&queue->ap_dev.device)` as a `struct vfio_ap_queue *`, and must always call `put_device(&queue->ap_dev.device)`. [F32]
- Because `matrix_mdev->kvm` and `q->matrix_mdev` are NULL when no guest or mdev is attached, `get_update_locks_for_mdev()`, `release_update_locks_for_mdev()`, `get_update_locks_for_queue()`, and `vfio_ap_mdev_update_guest_apcb()` must null-check `matrix_mdev`, `q->matrix_mdev`, and `matrix_mdev->kvm` before dereferencing `kvm`. [F33]

## Synchronization

- When updating a guest's APCB or modifying `matrix_mdev->kvm`, locks must be acquired in the order `matrix_dev->guests_lock`, then `kvm->lock` (if attached), then `matrix_dev->mdevs_lock`, and released in reverse order via `get_update_locks_for_*` and `release_update_locks_for_*`. `get_update_locks_by_apqn()` always locks `guests_lock` and `mdevs_lock`, so callers must call `release_update_locks_for_mdev(matrix_mdev)` even when it returns `NULL`. [F7, F18]
- `matrix_mdev->kvm` must not be modified between `get_update_locks_for_mdev()` (or `get_update_locks_by_apqn()` / `get_update_locks_for_queue()`) and `release_update_locks_for_mdev()`; `vfio_ap_mdev_set_kvm()` and `vfio_ap_mdev_unset_kvm()` must use `get_update_locks_for_kvm(kvm)` and `release_update_locks_for_kvm(kvm)` with a local `kvm` pointer. [F20]
- `kvm->arch.crypto.pqap_hook_rwsem` must never be acquired for write while holding `matrix_dev->mdevs_lock`, `guests_lock`, or `kvm->lock`, because KVM vCPU intercept holds `pqap_hook_rwsem` for read when calling `handle_pqap()`, which locks `mdevs_lock`. Under `mdevs_lock`, `handle_pqap()` must verify both `vcpu->kvm->arch.crypto.pqap_hook` and `matrix_mdev->kvm` are non-NULL before accessing `matrix_mdev->qtable` or calling `vfio_ap_irq_enable()` / `vfio_ap_irq_disable()`. [F22, F101]
- Callers of `vfio_ap_mdev_validate_masks()` must lock `ap_perms_mutex` before `get_update_locks_for_mdev()` because `ap_apqn_in_matrix_owned_by_def_drv()` requires `ap_perms_mutex`, whereas `vfio_ap_mdev_resource_in_use()` is called by the AP bus with `ap_perms_mutex` already held and must not lock it. [F112]
- Every call to `vfio_ap_mdev_reset_queue()` must be made under `matrix_dev->mdevs_lock` and paired with `flush_work(&q->reset_work)` before releasing `mdevs_lock`, and `apq_reset_check()` must never acquire `mdevs_lock`, `guests_lock`, or `kvm->lock`. Both `vfio_ap_mdev_reset_queues()` and `vfio_ap_mdev_reset_qlist()` must complete two full passes—queuing reset on all entries, then flushing all entries without breaking early when `q->reset_status.response_code` is non-zero. [F23, F66]
- When unplugging or filtering queues from a guest (`vfio_ap_mdev_hot_unplug_adapters()`, `vfio_ap_mdev_hot_unplug_domains()`, `vfio_ap_mdev_remove_queue()`, `vfio_ap_mdev_unset_kvm()`, or `vfio_ap_mdev_filter_matrix()` callers), the guest's APCB must be updated or cleared before resetting the removed queues. [F25]

## Object Lifetimes

- During queue removal (`vfio_ap_mdev_remove_queue()`), unassignment, mdev removal, or KVM detachment, `q->reset_work` must be flushed (`vfio_ap_mdev_reset_qlist()`, `vfio_ap_mdev_reset_queues()`, or `flush_work()`) before `q->matrix_mdev` or `matrix_mdev->kvm` is cleared (`vfio_ap_unlink_mdev_fr_queue()`, `vfio_ap_mdev_unlink_fr_queues()`), `kvm_put_kvm()` is called, or `kfree(q)` is called. `vfio_ap_mdev_remove_queue()` must save `q->matrix_mdev` before freeing `q` and pass the saved pointer to `release_update_locks_for_mdev()`. [F9, F24]
- When guest memory is unmapped via `vfio_ap_mdev_dma_unmap()`, `unmap_iova()` must hold `matrix_dev->mdevs_lock` and call `vfio_ap_irq_disable(q)` for every queue in `matrix_mdev->qtable.queues` whose `q->saved_iova` falls within `[iova, iova + length)`. [F98]
- In `vfio_ap_set_request_irq()` and `vfio_ap_set_cfg_change_irq()`, an existing `req_trigger` or `cfg_chg_trigger` must be released with `eventfd_ctx_put()` only after `eventfd_ctx_fdget(fd)` succeeds (when `fd >= 0`), and cleared to `NULL` after `eventfd_ctx_put()` when `fd == -1`. [F15]
- In `vfio_ap_matrix_dev_create()`, if `device_register(&matrix_dev->device)` fails, error recovery must call `put_device(&matrix_dev->device)` so `vfio_ap_matrix_dev_release()` frees `matrix_dev` (recovering it via `container_of(dev, struct ap_matrix_dev, device)`, never `dev_get_drvdata(dev)`), whereas failures after `device_register()` succeeds must call `device_del()` before `put_device()`. [F1, F77]

## API Contracts

- `vfio_ap_irq_enable()` and `vfio_ap_free_aqic_resources()` must pass page count `1` to `vfio_pin_pages()` and `vfio_unpin_pages()`. `vfio_ap_irq_enable()` must treat only a `vfio_pin_pages()` return value of `1` as success (mapping any other return to `AP_RESPONSE_INVALID_ADDRESS`), restore the byte offset via `h_nib = page_to_phys(h_page) | (nib & ~PAGE_MASK)` for `ap_aqic()`, and zero-initialize `aqic_gisa` (`gisc = isc`, `isc = nisc`, `gisa = virt_to_phys(gisa) >> 4`). [F29, F42, F109]
- In `vfio_ap_validate_nib()`, a zero guest NIB address (`!*nib`) must be explicitly rejected with `-EINVAL` in addition to `kvm_s390_is_gpa_in_memslot()`, because GPA 0 is a valid s390 memslot while a zero NIB is architecturally invalid and `q->saved_iova == 0` is the unpinned sentinel in `vfio_ap_free_aqic_resources()`. [F53]
- In `vfio_ap_irq_disable()`, when `ap_aqic()` returns `AP_RESPONSE_NORMAL` or `AP_RESPONSE_OTHERWISE_CHANGED`, it must call `vfio_ap_wait_for_irqclear(q->apqn)` (where `AP_RESPONSE_NORMAL` and `AP_RESPONSE_RESET_IN_PROGRESS` return only when `!status.irq_enabled` and otherwise `fallthrough` to `AP_RESPONSE_BUSY`) before calling `vfio_ap_free_aqic_resources(q)`. [F64, F93]
- Queue reset paths (`vfio_ap_mdev_reset_queue()` and `apq_reset_check()`) must use `ap_zapq()` and call `vfio_ap_free_aqic_resources(q)` directly rather than `vfio_ap_irq_disable(q)`. In `apq_reset_check()`, when `ap_tapq()` stops returning `-EBUSY`, if the prior `q->reset_status.response_code` was `AP_RESPONSE_RESET_IN_PROGRESS`, `AP_RESPONSE_BUSY`, or `AP_RESPONSE_STATE_CHANGE_IN_PROGRESS`, or if `apq_status_check()` returned `-EAGAIN`, it must re-issue `ap_zapq(q->apqn, 0)` and continue polling before freeing AQIC resources. [F86, F94]
- When host AP configuration additions are recorded in `vfio_ap_mdev_cfg_add()`, `vfio_ap_filter_apid_by_qtype()` must query added queues via `ap_test_queue(..., 1, &info)` and clear any APID from `apm_add` whose adapter type `info.at` is below `AP_DEVICE_TYPE_CEX4` or whose response code does not populate `info`. [F91]
- Because `vfio_ap` uses `vfio_pin_pages()`, `vfio_ap_mdev_probe()` must register `matrix_mdev->vdev` via `vfio_register_emulated_iommu_dev()`, and `vfio_ap_matrix_dev_ops` must provide `.dma_unmap` (`vfio_ap_mdev_dma_unmap`) and `vfio_iommufd_emulated_*` callbacks. [F108]

## Error Handling

- In `vfio_ap_irq_enable()`, once `vfio_pin_pages()` returns `1`: if `kvm_s390_pv_cpu_is_protected(vcpu)` is true, `ensure_nib_shared(h_nib & PAGE_MASK)` must succeed, and `kvm_s390_gisc_register(kvm, isc)` must be stored in a signed `int` (`nisc`) and checked for `nisc < 0` before assigning to `aqic_gisa.isc`; if either fails, `vfio_unpin_pages(&q->matrix_mdev->vdev, nib, 1)` must be called (never `gmap_convert_to_secure()`) before returning `AP_RESPONSE_INVALID_ADDRESS`. After `ap_aqic()`, `AP_RESPONSE_NORMAL` must call `vfio_ap_free_aqic_resources(q)` before saving `nib` and `isc` into `q`, `AP_RESPONSE_OTHERWISE_CHANGED` must unpin `nib` and unregister `isc` locally, and `default` must call `vfio_ap_irq_disable(q)`. [F10, F12, F30, F63, F110]
- Because `vfio_ap_mdev_validate_masks()` and `ap_matrix_overflow_check()` validate `matrix_mdev->matrix` in place, sysfs store handlers and `vfio_ap_mdev_link_queue()` must check if the bit/queue is already in the target state before mutating, and `assign_adapter_store()`, `assign_domain_store()`, and `ap_config_store()` must revert `matrix_mdev->matrix` (`clear_bit_inv()` or `ap_matrix_copy(&matrix_mdev->matrix, &m_old)`) when validation fails. [F16, F37, F49]

## External Contracts

- `handle_pqap()` must return `-EOPNOTSUPP` only when `ECA_AIV` is clear in `vcpu->arch.sie_block->eca`, and on all other paths must return `0` after copying the 32-bit `struct ap_queue_status` (`qstatus`, initialized to `AP_RESPONSE_Q_NOT_AVAIL`) into `vcpu->run->s.regs.gprs[1]` and right-shifting `gprs[1]` by 32 bits. [F31]
- In `vfio_ap_mdev_request()`, `kvm_arch_crypto_clear_masks()` and `signal_guest_ap_cfg_changed()` must be invoked under `get_update_locks_for_mdev(matrix_mdev)` before signaling `matrix_mdev->req_trigger`, rather than calling `signal_guest_ap_cfg_changed()` in `vfio_ap_mdev_unset_kvm()`. [F26]
- In `vfio_ap_mdev_get_device_info()`, `vfio_ap_get_irq_info()`, and `vfio_ap_irq_set_init()`, only `minsz` (`offsetofend` of `num_irqs` or `count`) may be copied from/to userspace, any non-zero return from `copy_from_user()`/`copy_to_user()` must be converted to `-EFAULT`, and `argsz >= minsz` and `index < VFIO_AP_NUM_IRQS` must be checked. `vfio_ap_set_irqs()` must validate via `vfio_ap_irq_set_init()` and require `VFIO_IRQ_SET_DATA_EVENTFD` before reading the `s32` fd at `arg + minsz`. [F28, F59, F115]

## Known Pitfalls

- In `ap_config_store()`, `vfio_ap_mdev_hot_unplug_cfg()`, `vfio_ap_mdev_cfg_remove()`, `vfio_ap_mdev_on_cfg_remove()`, `vfio_ap_mdev_on_cfg_add()`, and `vfio_ap_mdev_hot_plug_cfg()`, dirty flags across adapter, domain, and control-domain filtering (`vfio_ap_mdev_filter_matrix()`, `vfio_ap_mdev_filter_cdoms()`, `bitmap_andnot()`) must be combined with bitwise `|=` rather than logical `||` so no bitmap update is short-circuited. [F61]
- In `vfio_ap_mdev_verify_no_sharing()`, `assigned_to` must be skipped when `assignee == assigned_to`, both `bitmap_and()` checks on `apm` and `aqm` must be non-zero to report `-EADDRINUSE`, and when `assignee` is NULL the `else` branch must pass `assigned_to` (not `assignee`) to `vfio_ap_mdev_log_in_use_err()`. [F69]
- `VFIO_AP_DBF_*` calls must not pass `%s` pointers to non-persistent memory (e.g., mdev device names) and must stay within `DBF_MAX_SPRINTF_ARGS` (10 total arguments including format string). `vfio_ap_le_guid_to_be_uuid()` converts `guid->b[0..7]` with `le32_to_cpup()` / `le16_to_cpup()` and reads `guid->b[8..15]` through unsigned `__u16` and `__u32` casts into `unsigned long uuid[6]` to log UUIDs by value. [F60, F76]
