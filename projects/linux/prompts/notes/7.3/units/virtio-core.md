# VIRTIO CORE

This unit implements the Virtio bus core, virtqueue ring layouts (split, packed, in-order, and vringh), Virtio transports (PCI modern/legacy/admin, MMIO, vDPA), the vDPA bus core and backends (VDUSE, vdpa_sim, vp_vdpa, eni_vdpa), Virtio RTC/PTP, Virtio crypto, and userspace test tools under `tools/virtio/`.

## Architecture & Data Flow
- Any change to `struct virtqueue_ops` must update all four tables (`split_ops`, `packed_ops`, `split_in_order_ops`, `packed_in_order_ops`). Generic code outside `VIRTQUEUE_CALL` must use `virtqueue_is_packed(vq)` or `virtqueue_is_in_order(vq)` rather than comparing `vq->layout` to single enum values. [F260, F295]
- Split virtqueues require `is_power_of_2(num)` and mask indices with `& (vring.num - 1)`, whereas packed virtqueues allow non-power-of-2 sizes and wrap by comparing `>= vring.num` and subtracting `vring.num`. Packed `vq->last_used_idx` embeds the wrap counter at bit 15 (`VRING_PACKED_EVENT_F_WRAP_CTR`), so indexing `vring.desc[]` or `desc_state[]` must use `packed_last_used()`. [F277, F278]
- On packed virtqueue init/reset, available and used wrap counters start at 1 (`avail_used_flags = 1 << VRING_PACKED_DESC_F_AVAIL`) with zeroed descriptor flags. In `virtqueue_add_packed`, ring slots are indexed by `i` while `desc_extra` is indexed by `curr` (free-list); `unmap_release` must advance both in parallel. [F301, F320]
- `desc_state[head].indir_desc` stores either the indirect descriptor table (`vq->indirect`) or `ctx` (`!vq->indirect`), so `vq->indirect` must be disabled when `context` is true. Indirect tables allocate `total_sg` descriptors and trailing `vring_desc_extra` entries in one buffer; `desc_extra[head/id].len` must store only `total_sg * sizeof(*desc)` so `detach_indirect_split` and `detach_buf_packed_in_order` compute `num = len / sizeof(*desc)`. [F246, F322]
- In `vp_find_vqs_*`, `vm_find_vqs`, and `virtio_vdpa_find_vqs`, a NULL `vqs_info[i].name` must set `vqs[i] = NULL` and continue without incrementing `queue_idx`; `vp_dev->vqs` is indexed by `queue_idx` (`vq->index`), not `i`. Because `vp_dev->admin_vq.vq_index` can exceed `nvqs` and `vp_modern_get_num_queues(mdev)`, `setup_vq()` must exempt `vp_is_avq()` from the `num_queues` check and `vp_del_vqs()` must fetch its info from `vp_dev->admin_vq.info`. [F272, F299]
- Accessing `struct vdpa_vq_state` or `struct vduse_vq_info` union members requires checking `VIRTIO_F_RING_PACKED` in `driver_features`, and `get_driver_features(vdev)` may only be called after verifying `get_status(vdev) & VIRTIO_CONFIG_S_FEATURES_OK`. [F52, F145]
- VDUSE ioctls indexing `dev->vqs[]` must reject `index >= dev->vq_num` and clamp with `array_index_nospec`. `VDUSE_VQ_SETUP` must reject `config.group != 0` on API v0 and `config.group >= dev->ngroups` on API >= v1. `VDUSE_DEV_SET_CONFIG` and `vduse_vdpa_get_config` must check `offset <= dev->config_size` before `length > dev->config_size - offset`. [F79, F80, F82]

## Synchronization
- In `virtqueue_add_split`, descriptors and `avail->ring[avail]` must be written before `virtio_wmb(vq->weak_barriers)` and updating `avail->idx`. In `virtqueue_add_packed*`, `desc[head].flags` must be written only after all other descriptor fields/chains and `virtio_wmb`. In `virtqueue_get_buf_ctx_*`, `virtio_rmb` must follow polling `used->idx` or `desc[idx].flags` before reading `id` and `len`. When `VIRTIO_F_ORDER_PLATFORM` is negotiated, `vq->weak_barriers` must be forced to `false`. [F206, F207, F210, F377]
- `virtqueue_kick_prepare_{split,packed}` must execute `virtio_mb(vq->weak_barriers)` after exposing descriptors/indices and before reading event suppression fields. Conversely, `virtqueue_poll` and `virtqueue_enable_cb_delayed_{split,packed}` must execute `virtio_mb` or `virtio_store_mb` after writing the event suppression structure before polling for used buffers; in packed rings with `vq->event`, `driver->off_wrap` must be ordered with `virtio_wmb` before `driver->flags`. [F209, F211, F212]
- Modifications and iterations of `virtio_device.vqs` must hold `dev->vqs_list_lock` and use `READ_ONCE`/`WRITE_ONCE` for `vq->broken`. In `virtio_reset_device` (under `CONFIG_VIRTIO_HARDEN_NOTIFICATION`) and `virtio_device_shutdown`, `virtio_break_device(dev)` and `virtio_synchronize_cbs(dev)` must precede `dev->config->reset(dev)`. [F214, F217]
- `dev->config_core_enabled`, `dev->config_driver_disabled`, `dev->config_change_pending`, and `drv->config_changed(dev)` are serialized under `dev->config_lock` with IRQs disabled. `virtio_config_core_enable` and `virtio_config_driver_enable` must flush `config_change_pending` via `__virtio_config_changed(dev)` under `config_lock`. `virtio_config_core_disable` must precede `remove`/`freeze`/`reset_prepare` and be re-enabled if `freeze` or `reset_prepare` fails. [F192, F215, F216, F261]
- In `virtio_pci`, `vp_dev->virtqueues` and `slow_virtqueues` are protected by `vp_dev->lock` (`spin_lock_irqsave`). `vp_modern_disable_vq_and_reset` removes `info->node` under `vp_dev->lock`, sets `vq->reset = true`, marks `__virtqueue_break(vq)`, and calls `synchronize_irq` on its MSI-X vector; `vp_del_vq` only unlinks `info->node` if `!vq->reset`, and in `vp_del_vqs` with `per_vq_vectors`, `free_irq(irq, vq)` must precede `vp_del_vq`. [F218, F219, F220, F265]
- In `vp_reset` (`virtio_pci_modern.c`), after writing 0 to `device_status`, the driver must poll `vp_modern_get_status(mdev)` until it reads 0 before calling `vp_modern_avq_cleanup` (which detaches unused buffers and completes `cmd->completion` with `-EIO`) and `vp_synchronize_vectors`. Admin VQ operations in `virtqueue_exec_admin_cmd` and `vp_modern_avq_done` must hold `spin_lock_irqsave(&admin_vq->lock, flags)` and initialize `cmd->completion` before `virtqueue_add_sgs`. [F198, F221, F222]
- In `vdpa.c`, `vdpa_mgmtdev_ops.dev_add` and `dev_del` run with `vdpa_dev_lock` held for write, so they must set `vdev->mdev` and call `_vdpa_register_device` / `_vdpa_unregister_device`. Lock order is `vdpa_dev_lock` -> `vdev->cf_lock` -> backend locks. `vdev->cf_lock` protects config access, `features_valid`, and `vdpa_set_features_unlocked` / `vdpa_reset`. [F3, F32, F403]
- In `vduse_dev_open`, `vduse_lock` must remain held across `idr_find(&vduse_idr, ...)` until `dev->lock` is acquired and `dev->connected = true` is set. In `vduse_dev_read_iter`, before dropping `dev->msg_lock` for `copy_to_iter`, `msg->req` must be copied to the stack and `msg` moved to `dev->recv_list`; rollback on failure must re-lookup `msg` via `vduse_find_msg(&dev->recv_list, req.request_id)`. [F20, F21]
- `vduse_vdpa_kick_vq` must check `eventfd_signal_allowed()` and defer to `schedule_work(&vq->kick)` if false. `vduse_vq_kick` must never take `dev->rwsem`; it checks `READ_ONCE(vq->dev->suspended)` under `vq->kick_lock`, and `vduse_vdpa_suspend` must cycle every `vq->kick_lock` after setting `dev->suspended`. `vduse_dev_reset` and `vduse_vdpa_suspend` must release `dev->rwsem` before `flush_work`/`cancel_work_sync` on `dev->inject` and `vq->inject`. [F22, F161, F162]
- VDUSE per-VQ spinlock nesting requires `vq->ready_lock` inside `vq->kick_lock` or `vq->irq_lock` with BH or IRQs disabled. In VDUSE umem registration/deregistration, lock order is `dev->domain_lock` -> `dev->as[asid].mem_lock` -> `mmap_read_lock(current->mm)` -> `write_lock(&domain->bounce_lock)`. On-demand allocation in `vduse_domain_map_bounce_page` (under `read_lock(&domain->bounce_lock)`) must use `GFP_ATOMIC` and `cmpxchg(&head_map->bounce_page, NULL, tmp_page)`. [F24, F165, F168]

## Object Lifetimes
- Once `__vdpa_alloc_device` / `vdpa_alloc_device` or `register_virtio_device` initializes `dev->dev`, any error path must release the device via `put_device(&dev->dev)` rather than `kfree()`. In `unregister_virtio_device`, all accesses to `dev` must precede `device_unregister(&dev->dev)`. Every `bus_find_device(&vdpa_bus, ...)` lookup in `vdpa.c` must be paired with `put_device(dev)`. [F1, F4, F190, F191]
- Before calling `_vdpa_register_device` or `vdpa_register_device`, a vDPA backend must complete all device-specific initialization (domains, buffers, vrings, `u64_stats_init`). Conversely, `vdpa_mgmtdev_unregister()` must be called before tearing down parent hardware or freeing structures used by `dev_del` or `vdpa_release_dev`. [F33, F143]
- Because `vduse_domain_init_bounce_map` and `vduse_domain_alloc_coherent` insert IOTLB entries holding `get_file(domain->file)` self-references, `vduse_dev_reset` and `vduse_domain_free_coherent` must remove them before `vduse_domain_destroy` calls `fput(domain->file)`. Once `kobject_init` and `kobject_add` succeed in `vduse_dev_init_vqs`, `vduse_virtqueue` must be freed via `kobject_put` (never `kfree`), and `dev->vqs` reset to `NULL` on error. [F10, F13]
- In `vp_find_one_vq_msix`, if `request_irq` fails after `vp_setup_vq` succeeds, `vp_del_vq(vq, *p_info)` must be called before returning. Because `vp_find_vqs` retries across vector policies, `vp_del_vqs` must reset `per_vq_vectors`, `intx_enabled`, `msix_enabled`, `msix_vectors`, and `msix_used_vectors` to 0/false and clear `msix_names`, `msix_affinity_masks`, and `vqs` to `NULL`. Transport `del_vqs` functions must iterate `&vdev->vqs` with `list_for_each_entry_safe`. [F193, F194, F297]
- In `virtqueue_add_*`, when `premapped` is true, `extra[...].addr` is set to `DMA_MAPPING_ERROR` so `vring_need_unmap_buffer` skips caller-owned mappings, whereas indirect descriptor tables (`VRING_DESC_F_INDIRECT`) are mapped by the ring and must be unmapped whenever `vq->use_map_api` is true. `vring_free_queue` must receive the exact byte size passed to `vring_alloc_queue`, and `vring_del_virtqueue` only frees rings when `vq->we_own_ring` is true. [F200, F326, F390]

## API Contracts
- Callers must externally serialize all mutating virtqueue operations on a given virtqueue (`virtqueue_add_*`, `virtqueue_kick`, `virtqueue_kick_prepare`, `virtqueue_get_buf*`, `virtqueue_enable_cb*`, `virtqueue_detach_unused_buf`, `virtqueue_resize`, `virtqueue_reset`); when calling `disable_vq_and_reset`, no virtqueue function other than the callback may run concurrently. [F213, F397]
- `virtio_add_status`, `virtio_features_ok`, `virtio_synchronize_cbs`, `virtio_config_ops` callbacks (`reset`, `get`, `set`, `get_status`, `set_status`, `get_features`, `finalize_features`), and `virtio_cread*`/`virtio_cwrite*` may sleep and must never be called from atomic context, spinlocks, virtqueue callbacks, or `config_changed` handlers. [F361, F396, F398, F503]
- `vp_set_status` and `vm_set_status` call `BUG_ON(status == 0)`; callers must use `virtio_reset_device` or `config->reset` to reset a device. A `virtio_driver->remove` callback must reset the device (`status == 0`) before returning. If `drv->shutdown` is defined, `virtio_dev_shutdown` must call only `drv->shutdown(dev)` without calling `virtio_device_shutdown(dev)`. Drivers using virtqueues inside `.probe` must call `virtio_device_ready(dev)` first (and only once). [F240, F337, F338, F481]
- `virtio_has_feature` and `virtio_check_driver_offered_feature` take a bit index (`0..VIRTIO_FEATURES_BITS - 1`), not a mask, and call `BUG()` if a device feature (`< VIRTIO_TRANSPORT_F_START`) is missing from `drv->feature_table`. Feature array helpers (`virtio_features_*`, `virtio_get_features`) unconditionally access `VIRTIO_FEATURES_U64S` (2) `u64` words. [F230, F464, F473]
- `vring_create_virtqueue*` and `vring_new_virtqueue` return `NULL` on failure, whereas transport `setup_vq` helpers and `virtio_find_single_vq` return `ERR_PTR(-errno)` (check with `IS_ERR()`). `virtio_pci_vf_get_pf_dev` converts `ERR_PTR` to `NULL` (check with `!dev`). When `vdev->map` (`struct virtio_map_ops`) is set, all nine callbacks must be non-NULL, and `sync_single_for_{cpu,device}` receive `addr + offset` pre-added as `map_handle`. [F232, F238, F252, F381, F411]
- `vduse_domain_alloc_iova` returns `0` on failure, whereas `vduse_domain_map_page` and `vduse_domain_alloc_coherent` return `DMA_MAPPING_ERROR`. `vhost_iotlb_*`, `vduse_iotlb_*`, `vduse_domain_alloc_iova`, and `struct vringh_range::end_incl` take inclusive end addresses (`start + size - 1`). `vringh_init_iotlb*` does not set `vrh->iotlb` or `vrh->iotlb_lock`; callers must call `vringh_set_iotlb` before any `*_iotlb()` operation. [F50, F51, F423, F448]

## Error Handling
- On DMA mapping failure (`unmap_release`) in `virtqueue_add_packed` and `virtqueue_add_packed_in_order`, cleanup must restore `avail_used_flags` and `avail_wrap_counter`, and overwrite `desc[i].flags` for all written non-head descriptors (`i != head`) with the opposite wrap counter's `AVAIL | USED` bits (`unpub_flags`). [F248]
- In `virtqueue_get_buf_ctx_split` and `virtqueue_get_buf_ctx_packed`, the device-supplied descriptor `id` must be verified (`id < vring.num` and `desc_state[id].data != NULL`) before detaching, calling `BAD_RING` and returning `NULL` otherwise. [F276]
- Callers of `vringh_iov_pull_iotlb` and `vringh_iov_push_iotlb` (`vdpasim_net_work`, `vdpasim_blk_handle_req`) must store the return value in a signed `ssize_t` and check for `< 0`/`<= 0` before using it. `vringh_need_notify_{user,kern,iotlb}` return `< 0` on error, `0` for no notify, and `1` for notify; callers must check `< 0`. [F42, F422]

## Known Pitfalls
- `virtqueue_poll()` and `virtqueue_enable_cb*()` have opposite return polarities: `virtqueue_poll()` returns `true` when used buffers are pending (`false` when `vq->broken`), whereas `virtqueue_enable_cb*()` returns `false` when used buffers are pending and `true` when empty or `vq->broken`. [F250]
- `VIRTIO_F_ACCESS_PLATFORM` has inverted quirk polarity: `virtio_has_dma_quirk(vdev)` returns `true` when `VIRTIO_F_ACCESS_PLATFORM` is NOT negotiated. Unlike split-ring descriptor flags (`1`, `2`, `4`), `VRING_PACKED_DESC_F_AVAIL` (`7`), `VRING_PACKED_DESC_F_USED` (`15`), and `VRING_PACKED_EVENT_F_WRAP_CTR` (`15`) are bit shifts that must be shifted (`1 << ...`). [F425, F484]
- In `vp_finalize_features`, `vdev->features` must be saved before `vring_transport_features(vdev)` and passed to `vp_transport_features(vdev, features)` afterward, because `vring_transport_features` clears transport feature bits not handled by `virtio_ring`. In `vp_modern_get_{driver_}extended_features`, the `u32` return of `vp_ioread32` must be widened to `u64` before shifting by `32 * (i & 1)`. [F296, F307]
- In `virtqueue_enable_cb_delayed_split`, `avail_idx_shadow - last_used_idx` and `vring_read_split_used_idx(vq) - last_used_idx` must be cast to `u16`. In `virtqueue_kick_prepare_packed`, `event_idx` must be decremented by `vq->packed.vring.num` when `wrap_counter != vq->packed.avail_wrap_counter` before calling `vring_need_event(event_idx, new, old)`. The split ring's trailing `avail_event_idx` at `used->ring[num]` is only 2 bytes and must be accessed via `(__virtio16 *)`, never as an 8-byte `struct vring_used_elem`. [F317, F319, F324, F426]
- `vduse_vdpa_get_config` must `memset(buf, 0, len)` before checking `offset > dev->config_size` or clamping `len`. When removing entries from `domain->iotlb` in `vduse_iotlb_del_range`, each iteration must re-query `vhost_iotlb_itree_first` rather than advancing with `vhost_iotlb_itree_next`. [F54, F106]
- When `drivers/virtio/virtio_ring.c`, `drivers/vhost/vringh.c`, or `include/linux/virtio*.h` introduces a use of a kernel macro, type, or helper, a matching userspace stub must be added under `tools/virtio/linux/` in lockstep, and `tools/virtio/` tests must initialize virtqueues and `vringh` with `weak_barriers = true`. [F438, F508]
