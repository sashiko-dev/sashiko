# BITOPS API

The BITOPS API provides generic and architecture-specific bit manipulation primitives, including atomic, non-atomic, and bit-lock operations (`set_bit`, `clear_bit`, `change_bit`, `test_and_*_bit`, `test_bit`, `test_and_set_bit_lock`, `clear_bit_unlock`) on `unsigned long` memory bitmaps, along with word-level bit search, counting, rotation, and order helpers (`ffs`, `__ffs`, `fls`, `__fls`, `fls64`, `ffz`, `fns`, `rol*`/`ror*`, `get_count_order*`) and `lib/test_bitops.c`.

## Architecture & Data Flow

- In `include/linux/bitops.h`, `bitop(op, nr, addr)` must check `__builtin_constant_p((uintptr_t)(addr) != (uintptr_t)NULL) && (uintptr_t)(addr) != (uintptr_t)NULL` before `__builtin_constant_p(*(const unsigned long *)(addr))` to guard NULL dereferences and avoid `-Waddress` warnings; every `bitop()`-wrapped primitive must have matching `generic_<name>`, `const_<name>`, `arch_<name>`, and `_<name>` (or `___<name>`) definitions plus a `__check_bitop_pr(<name>)` assertion. [F32, F55]
- On s390 (`arch/s390/include/asm/bitops.h`), standard bitops use `unsigned long` LSB0 numbering (`|63..0|127..64|`), so byte-addressed `arch_test_bit` must XOR `nr` with `BITS_PER_LONG - BITS_PER_BYTE` for the byte offset, while MSB0 helpers (`set_bit_inv`, `clear_bit_inv`, `test_and_clear_bit_inv`, `__set_bit_inv`, `__clear_bit_inv`, `test_bit_inv`) XOR `nr` with `BITS_PER_LONG - 1` before calling LSB0 bitops and must not be mixed with un-XORed LSB0 bitops; in `for_each_set_bit_inv`, the loop increment must pass `(bit) + 1` to `find_next_bit_inv`. [F31, F45, F64]
- In `arch/m68k/include/asm/bitops.h`, bitops on big-endian 32-bit `unsigned long` bitmaps must swizzle bit indices with `nr ^ 31` for byte offsets (`(char *)vaddr + (nr ^ 31) / 8` in `bset`/`bclr`/`bchg`), bitfield offsets (`bfset`/`bfclr`/`bfchg`), and `bfffo` MSB0 outputs (`res ^ 31` in `ffz` and `find_*_bit`); `xor_unlock_is_negative_byte` on `!CONFIG_COLDFIRE` must target `(char *)p + 3` with `eor.b` (bits 0..7); and `find_first_zero_bit`/`find_first_bit` post-increment `*p++` with `res = 32`, so `out:` must compute `res += ((long)p - (long)vaddr - 4) * 8`. [F47, F49, F78]
- In `arch/alpha/include/asm/bitops.h`, `set_bit`, `clear_bit`, `change_bit`, `test_and_*_bit`, and `arch___*_bit` index bitmaps as 32-bit `int *` arrays (`((int *)addr) + (nr >> 5)`) with 32-bit `ldl_l`/`stl_c` and `1UL << (nr & 31)` masks (never `1 << (nr & 31)`), and `arch/mips/lib/bitops.c` fallbacks (`__mips_*_bit*`) must likewise shift `1UL << bit` rather than `1 << bit`. [F71, F72, F80]
- In `arch/mips/include/asm/bitops.h`, every atomic bitop (`set_bit`, `clear_bit`, `change_bit`, `test_and_set_bit_lock`, `test_and_clear_bit`, `test_and_change_bit`, `xor_unlock_is_negative_byte`) must check `!kernel_uses_llsc` before executing `LONG_LL`/`LONG_SC` loops and keep its inline path synchronized with its `__mips_*` fallback in `arch/mips/lib/bitops.c`; `__fls` and `fls` must only emit `clz` when `__builtin_constant_p(cpu_has_clo_clz) && cpu_has_clo_clz` is true (and `dclz` in 64-bit `__fls` when `__builtin_constant_p(cpu_has_mips64) && cpu_has_mips64` is true). [F38, F82, F83]
- `fls` and `fls64` implementations that fold constants with `__builtin_clz`, `__builtin_clzl`, or `__builtin_clzll` (`arch/powerpc/include/asm/bitops.h`, `arch/x86/include/asm/bitops.h`, `arch/riscv/include/asm/bitops.h`) must guard the builtin call with a non-zero check (`x ? ... : 0`) even inside `if (__builtin_constant_p(x))`. [F68]
- On 32-bit architectures (`BITS_PER_LONG == 32`), `__ffs64(u64 word)` in `include/linux/bitops.h` must check whether `(u32)word` is zero first and, if so, return `__ffs((u32)(word >> 32)) + 32` before calling `__ffs((unsigned long)word)`. [F69]
- Rotation helpers (`rol64`, `ror64`, `rol32`, `ror32`, `rol16`, `ror16`, `rol8`, `ror8`) in `include/linux/bitops.h` must mask both `shift` and `-shift` with `width - 1` (`63`, `31`, `15`, or `7`) rather than computing `width - shift` so multiple-of-width shifts do not shift by `width`. [F65]
- In `arch/xtensa/include/asm/bitops.h` (`BIT_OPS`) and `arch/riscv/include/asm/bitops.h` (`arch_change_bit`, `arch_test_and_change_bit`), XOR-based toggle operations must pass the uninverted single-bit mask (`inv` empty or `__NOP`), reserving mask inversion (`~` or `__NOT`) for AND-based clear operations; in `DEFINE_CLROP` and `test_and_clear_bits` (`arch/powerpc/include/asm/bitops.h`), the `CONFIG_PPC32` constant-mask branch must pass `~mask` to `is_rlwinm_mask_valid` and `rlwinm`, whereas the general branch passes uninverted `mask` to `andc`. [F57, F63]

## Synchronization

- In `arch/hexagon/include/asm/bitops.h`, the non-atomic `arch___*_bit` and `arch___test_and_*_bit` functions must delegate to the atomic `test_and_*_bit` `memw_locked` loops rather than plain memory stores, because normal writes on Hexagon do not invalidate LL/SC reservations on the same word. [F34]
- `generic_test_bit` (`include/asm-generic/bitops/generic-non-atomic.h`) must preserve `volatile` on `addr`, whereas `const_test_bit` discards `volatile` and must only be selected by `bitop()` when `nr`, non-NULL `addr`, and `*(const unsigned long *)(addr)` are compile-time constants; on x86 (`arch/x86/include/asm/bitops.h`), `arch_test_bit_acquire` must use `constant_test_bit_acquire` (`asm volatile("testb ..." ::: "memory")`) rather than `constant_test_bit` when `nr` is constant. [F13, F41]
- In `arch/mips/include/asm/bitops.h`, `__bit_op` and `__test_bit_op` must emit `__SYNC(full, loongson3_war)` immediately before the `1:` LL/SC loop label; `test_and_set_bit`, `test_and_clear_bit`, `test_and_change_bit`, `xor_unlock_is_negative_byte`, and `clear_bit_unlock` must call `smp_mb__before_atomic()` beforehand and `smp_llsc_mb()` after value-returning/unlock operations; and `__clear_bit_unlock` must wrap `__clear_bit(nr, addr)` with `smp_mb__before_llsc()` and `nudge_writes()`. [F6, F7, F9]
- In `arch/riscv/include/asm/bitops.h`, `arch_test_and_set_bit`, `arch_test_and_clear_bit`, and `arch_test_and_change_bit` must use `.aqrl` AMO instructions (`__test_and_op_bit`), `arch_test_and_set_bit_lock` must use `.aq`, and `arch_clear_bit_unlock`, `arch___clear_bit_unlock`, and `arch_xor_unlock_is_negative_byte` must use `.rl`. [F15]
- In `arch/powerpc/include/asm/bitops.h`, `test_and_*_bits` must bracket their LL/SC loop with `PPC_ATOMIC_ENTRY_BARRIER` and `PPC_ATOMIC_EXIT_BARRIER`, `test_and_set_bits_lock` must follow it with `PPC_ACQUIRE_BARRIER`, and `*_unlock*` helpers must precede the store with `PPC_RELEASE_BARRIER` (including inside `CONFIG_PPC32` `rlwinm` paths). [F16]
- In `arch/alpha/include/asm/bitops.h`, `test_and_set_bit` and `test_and_set_bit_lock` must branch past `xor %0,%3,%0` and `stl_c` when the bit is already set (`bne %2,2f`), and `test_and_clear_bit` when the bit is already clear (`beq %2,2f`), placing label `2:` before the trailing `mb` instruction (`#ifdef CONFIG_SMP` for `test_and_*_bit`, unconditional for `test_and_set_bit_lock`). [F17, F62]
- In `arch/mips/lib/bitops.c` (`__mips_*_bit*`, `__mips_xor_is_negative_byte`) and `arch/arm/include/asm/bitops.h` (`____atomic_*_bit`), IRQ-disabling atomic bitop fallbacks must wrap the word update in `raw_local_irq_save(flags)` and `raw_local_irq_restore(flags)`, and ARM's `ATOMIC_BITOP` must only select `____atomic_*_bit` when `!defined(CONFIG_SMP)`. [F2, F18]
- In `arch/parisc/include/asm/bitops.h`, `set_bit`, `clear_bit`, `change_bit`, and `test_and_*_bit` must advance `addr += BIT_WORD(nr)` before calling `_atomic_spin_lock_irqsave(addr, flags)` and `_atomic_spin_unlock_irqrestore(addr, flags)` so they hash the target word into `__atomic_hash` identically to `<asm-generic/bitops/lock.h>`, and in `arch/parisc/lib/bitops.c`, `__xchg64`, `__xchg32`, `__xchg8`, and `CMPXCHG`-generated `__cmpxchg_u*` helpers must be marked `notrace` and serialize via `_atomic_spin_lock_irqsave`/`_atomic_spin_unlock_irqrestore`. [F35, F85]
- `set_mask_bits` and `bit_clear_unless` in `include/linux/bitops.h` must sample `*ptr` via `READ_ONCE(*(ptr))` into `old__` and recompute `new__` from the updated `old__` on every `try_cmpxchg(ptr, &old__, new__)` retry (with `bit_clear_unless` breaking if `old__ & test__`), preserving concurrent changes to unmasked bits. [F36]

## Object Lifetimes

- In `test_fns` (`lib/test_bitops.c`), `buf` is declared with `__free(kfree)` and initialized to `NULL`, so it must not be passed to an explicit `kfree(buf)` call; in `test_bitops_startup`, every bit set in `g_bitmap` via `set_bit` must be cleared via `clear_bit` before `find_first_bit(g_bitmap, BITOPS_LAST)` is called. [F4, F5]

## API Contracts

- Bitmaps passed to `<linux/bitops.h>` bitops (`set_bit`, `clear_bit`, `change_bit`, `test_and_*_bit`, `test_bit`, and `__*` variants) and little-endian bitops (`*_bit_le`, `ext2_*_bit_atomic`, which XOR `nr` with `BITOP_LE_SWIZZLE`) must be `unsigned long`-aligned objects of at least `BITS_TO_LONGS(nr + 1)` words—never narrower integers (`u8`, `u16`, `u32`) cast to `unsigned long *`—and `*_bit_le` must not be mixed with native bitops; `BITS_TO_LONGS`/`BITS_TO_U64`/`BITS_TO_U32`/`BITS_TO_BYTES` use ceiling division, and `BITS_TO_LONGS(nr)` returns a word count, so byte-sized calls (`kmalloc`, `memset`, `memcpy`) must multiply by `sizeof(unsigned long)` or use `BITS_TO_BYTES(nr)`. [F73, F74, F75, F107]
- `ffs`, `fls`, `fls64`, and `fls_long` return 1-based bit positions (`1..32` or `1..64`) and `0` when the input is `0`, whereas `__ffs`, `__ffs64`, `__fls`, and `ffz` return 0-based bit indices (`0..BITS_PER_LONG-1` or `0..63`) and are undefined when no matching bit exists (`0` for `__ffs*`/`__fls`, or `~0UL` for `ffz`). [F21, F42]
- `fns(word, n)` in `include/linux/bitops.h` takes a 0-based set-bit rank `n` and returns the 0-based bit index of the `n`-th set bit in `word` or `BITS_PER_LONG` when fewer than `n + 1` bits are set; its loop `while (word && n--)` must check `word` before decrementing `n` and guard `__ffs(word)` with `word ? __ffs(word) : BITS_PER_LONG`. [F43, F56]
- `get_count_order` and `get_count_order_long` return `-1` when the input is `0` and the rounded-up power-of-two order (`fls(--count)` or `(int)fls_long(--l)`) otherwise, whereas `get_bitmask_order(0)` returns `0`. Broken by: storing `get_count_order*` into an unsigned integer when input can be `0`. [F22]
- In `include/linux/bitops.h`, `set_mask_bits(ptr, mask, bits)` returns the previous value of `*ptr` before the atomic update, whereas `bit_clear_unless(ptr, clear, test)` returns a boolean (`!(old__ & test__)`) indicating whether `clear` was cleared; `xor_unlock_is_negative_byte(mask, addr)` takes a bitmask `mask` restricted to bits 0–6 (not a bit number `nr`), atomically XORs `*addr` with release semantics, and returns whether `BIT(7)` was set. [F25, F101]
- In `arch/powerpc/include/asm/bitops.h`, `set_bits`, `clear_bits`, `clear_bits_unlock`, `change_bits`, and `test_and_*_bits` take a shifted `mask` (`BIT_MASK(nr)`) and word pointer (`addr + BIT_WORD(nr)`), and `test_and_*_bits` return the unshifted `unsigned long` `(old & mask)` (converted to `int` via `!= 0` in `arch_test_and_*_bit`); `PPC_BIT*` and `PPC_BITEXTRACT` take MSB0 bit numbers (`width - 1 - be`), and `PPC_BITMASK*(bs, be)` require `bs <= be`. [F30, F50]
- In `arch/s390/include/asm/bitops.h`, `__flogr(word)` returns a 0-based MSB0 bit index (`0` for MSB `0x8000000000000000UL`, `63` for LSB, and `64` when `word == 0`), so the `!CONFIG_CC_HAS_BUILTIN_FFS` fallback `ffs(int word)` must cast `word` to `unsigned int val` before computing `BITS_PER_LONG - __flogr(-val & val)`. [F46, F70]

## Error Handling

- In `arch/m68k/include/asm/bitops.h`, `find_first_zero_bit` and `find_first_bit` must return `0` when `!size` before computing `words = (size + 31) >> 5` and clamping the result to `size`, and `find_next_zero_bit` and `find_next_bit` must guard `offset >= size` before subtracting `size - offset`. [F48]

## External Contracts

- On x86 (`arch/x86/include/asm/bitops.h`), `arch___test_and_clear_bit` must execute as a single `btr` instruction that is atomic with respect to the local CPU because `kvm_guest_apic_eoi_write` in `arch/x86/kernel/kvm.c` relies on it to clear `KVM_PV_EOI_BIT` shared with a hypervisor on the same CPU. [F102]

## Known Pitfalls

- In `include/linux/bitops.h`, statement-expression macros `set_mask_bits` and `bit_clear_unless` must parenthesize all macro parameters and suffix internal local variables with double underscores (`mask__`, `bits__`, `clear__`, `test__`, `old__`, `new__`) so caller identifiers in argument expressions are not shadowed. [F53]
- In `arch/x86/include/asm/bitops.h`, the constant-`nr` byte-mask branches of `arch_set_bit`, `arch_clear_bit`, and `arch_change_bit` using `"iq"` with `int`-typed `CONST_MASK(nr)` must format the source operand with `%b1` (`orb %b1,%0`, `andb %b1,%0`, `xorb %b1,%0`); in `variable_ffs`, `fls`, and `fls64`, `CONFIG_X86_64` pre-initializes the output register to `-1` before `bsfl`/`bsrl`/`bsrq`, whereas 32-bit x86 (`!CONFIG_X86_64`) must explicitly set `-1` on `ZF=1` via `cmovzl` (with `"=&r"`) or `jnz`. [F88, F89]
- In `arch/s390/include/asm/bitops.h`, the `tm` inline assembly path in `arch_test_bit` must be guarded by `!IS_ENABLED(CONFIG_PROFILE_ALL_BRANCHES) && __builtin_constant_p(nr)` and use the `"Q"` memory constraint for `*addr` and `"I"` for `mask`; in `__flogr`, the inline assembly branch must pass an even/odd `union register_pair` with `"+d"` to `flogr`, clobber `"cc"`, and bound `rp.even` with `__assume(bit <= 64)` and `bit & 127`. [F90, F91]
- Inline assembly LL/SC and bitop loops require strict register constraints: on Alpha (`arch/alpha/include/asm/bitops.h`), `stl_c` failure retries must jump to `.subsection 2` and mark `temp`/`oldbit` `"=&r"`; on MIPS (`arch/mips/include/asm/bitops.h`), `__bit_op`/`__test_bit_op` must mark `__temp`/`__orig` `"=&r"` with `__LLSC_CLOBBER` and pass `"%1"` as `ll_dst` in `test_and_clear_bit`'s `LONG_EXT`/`LONG_INS` path; on PowerPC (`arch/powerpc/include/asm/bitops.h`), `PPC_LLARX`/`PPC_STLCX` loops must mark `old`/`t` `"=&r"`, clobber `"cc", "memory"`, and pass `eh = IS_ENABLED(CONFIG_PPC64)` in `test_and_set_bits_lock`; on Xtensa (`TEST_AND_BIT_OP`), `XCHAL_HAVE_EXCLUSIVE` must return `value & mask` (not `tmp & mask`, which `getex` overwrites); and on SuperH (`arch/sh/include/asm/bitops.h`), `ffz`/`__ffs` must initialize `result` (`%0`) to `~0L` because `add #1, %0` runs in the `bt/s`/`bf/s` delay slot. [F58, F61, F93, F94, F96]
