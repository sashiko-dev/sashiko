# NETWORKING [ETHTOOL]

`net/ethtool` implements the Generic Netlink (`ethtool` family) infrastructure, the legacy `SIOCETHTOOL` ioctl dispatcher (`dev_ethtool`), bitset and string serialization, and CMIS CDB transceiver firmware flashing, translating userspace requests into `ethtool_ops` and `ethtool_phy_ops` callbacks while managing netdevice locking and notifications.

## Architecture & Data Flow
- In `ethnl_request_ops->prepare_data`, read the target device from `reply_base->dev` rather than `req_base->dev` (except in per-PHY handlers where `ethnl_perphy_dump_all_dev()` and `ethnl_perphy_dumpit()` bind `req_info->dev`), because `ethnl_default_start()` clears `req_info->dev = NULL` for dumps. Because `reply_data` is allocated with `kmalloc()` and reused across dump iterations, `ethnl_init_reply_data()` must zero `ops->reply_data_size` bytes and set `reply_data->dev` before each `ops->prepare_data()` call. [F45, F69]
- Command-specific request/reply structs for `ethnl_request_ops` must embed `ethnl_req_info` or `ethnl_reply_data` at offset 0 with `req_info_size`/`reply_data_size` set to the full container sizes, and `orig_req_info` passed to `ethnl_notify()` must be an instance of that command's request struct. When `.parse_request` is shared between GET and SET, both GET and SET `nla_policy` arrays must be sized to at least the highest attribute index read by `.parse_request` (marking SET-unsupported attributes `NLA_REJECT` or `NLA_UNSPEC`). [F82, F136]
- `ethnl_reply_header_size()` must reserve `IFNAMSIZ` rather than `strlen(dev->name)` so a concurrent rename after `ethnl_default_doit()` drops `rtnl_lock()` cannot overflow the SKB in `ethnl_fill_reply_header()`. Every `ethnl_request_ops->fill_reply` callback and `ethnl_fill_reply_header()` must never write more bytes than `reply_size` and `ethnl_reply_header_size()` estimated. [F21, F80]
- Custom RSS contexts in `dev->ethtool->rss_ctx` use 1-based IDs in `XA_LIMIT(1, (ops->rxfh_max_num_contexts ?: U32_MAX) - 1)`; context 0 is never stored in `rss_ctx` and must bypass `xa_load()`. After `ops->create_rxfh_context()` or `ops->modify_rxfh_context()` succeeds, the `ethtool_rxfh_context` entry in `rss_ctx` must be updated in lockstep (`rss_set_ctx_update()`) with any changed `indir`, `key`, `hfunc`, `input_xfrm`, and `*_configured` flags. [F63, F91]
- For non-default RSS contexts, `__rss_prepare_ctx()` must set `data->no_key_fields = !dev->ethtool_ops->rxfh_per_ctx_key` and `ethtool_get_rxfh()` must zero `rxfh_dev.key_size` when `!ops->rxfh_per_ctx_key`. In `rss_fill_reply()`, optional attributes (`CONTEXT`, `INDIR`, `HFUNC`, `INPUT_XFRM`, `HKEY`, `FLOW_HASH`) must only be emitted when their value/size or `has_flow_hash` is non-zero, and `HFUNC`/`INPUT_XFRM`/`HKEY` must be omitted when `data->no_key_fields` is true. [F64, F105]
- When adding a configurable field to `struct ethtool_rxfh`, `ethtool_get_rxfh()` must explicitly `copy_to_user()` it from `rxfh_dev` to `useraddr`, and `ethtool_set_rxfh()` must include its `*_NO_CHANGE` sentinel in the no-op rejection check, which must be gated on `!create` (`rxfh.rss_context != ETH_RXFH_CONTEXT_ALLOC`). [F78, F111]
- `ethtool_ringparam_get_cfg()` must overwrite `kparam->tcp_data_split` and `kparam->hds_thresh` with `dev->cfg->hds_config` and `dev->cfg->hds_thresh` after `ops->get_ringparam()`, and `ethtool_set_ringparam()` and `ethnl_set_rings()` must use `ethtool_ringparam_get_cfg()` when reading ring config. [F60]
- In `ethtool_rxnfc_copy_from_user()` and `ethtool_rxnfc_copy_to_user()`, copying `struct ethtool_rxnfc` and computing the `rule_locs` offset must branch on `compat_need_64bit_alignment_fixup()` to translate `struct compat_ethtool_rxnfc` (which omits the 4-byte alignment holes before `fs.ring_cookie` and after `fs`). [F99]

## Synchronization
- In `ethnl_request_ops`, `parse_request` and `set_validate` run unlocked with only a netdev reference held, `prepare_data` and `set` run under `rtnl_lock()` and `netdev_lock_ops(dev)`, and `reply_size`, `fill_reply`, and `cleanup_data` in `ethnl_default_doit()` and `ethnl_default_dump_one()` run after both locks are released. Because callers already hold `rtnl_lock()` and `netdev_lock_ops(dev)`, `ethtool_op_get_link()` must call `__linkwatch_sync_dev(dev)` rather than `linkwatch_sync_dev(dev)`. [F28, F157]
- Callers of `ethtool_rss_notify()` with `ETHTOOL_MSG_RSS_NTF` or `ETHTOOL_MSG_RSS_CREATE_NTF` must release `dev->ethtool->rss_lock` first because `ethnl_notify()` dispatches to `rss_prepare_data()`, which acquires `rss_lock`. Conversely, callers of `ethtool_rxfh_context_lost()` must hold either `rtnl_lock()` or `dev->ethtool->rss_lock` to serialize erasing and freeing the context from `dev->ethtool->rss_ctx`. [F33, F34]
- In `dev_ethtool()`, when `ETHTOOL_FLASHDEV` or `ETHTOOL_GDRVINFO` falls back to devlink, `__dev_ethtool()` must pin `state->devlink` via `netdev_to_devlink_get(dev)` under `rtnl_lock()`, and `devlink_compat_flash_update()`, `devlink_compat_running_version()`, and `devlink_put()` must run after `rtnl_unlock()`. [F29]
- `dev->irq_moder->rx_profile` and `tx_profile` must be updated under `rtnl_lock()` in `ethnl_update_profile()` by copying via `rtnl_dereference()`, publishing with `rcu_assign_pointer()`, and retiring `old_profile` via `kfree_rcu()`, and read in `coalesce_fill_reply()` under `rcu_read_lock()` via `rcu_dereference()`. In `__ethtool_get_ts_info()`, `rcu_read_lock()` must be held across `rcu_dereference(dev->hwprov)` and the entire `ethtool_get_ts_info_by_phc(dev, info, &hwprov->desc)` call. [F35, F36]
- While `dev->ethtool->module_fw_flash_in_progress` is set, `ethnl_netdev_event()` must reject `NETDEV_PRE_UP` with `NOTIFY_BAD` and module/reset entry points (`module_get_power_mode()`, `ethnl_set_module_validate()`, `get_module_eeprom_by_page()`, `ethtool_get_module_info_call()`, `ethtool_get_module_eeprom_call()`, `ethtool_reset()`) must return `-EBUSY`. Accesses to `module_fw_flash_work_list` must be serialized by `module_fw_flash_work_list_lock` without sleeping. [F40, F167]
- In `linkstate_get_sqi()`, `linkstate_get_sqi_max()`, `get_phy_tunable()`, and `set_phy_tunable()`, `mutex_lock(&phydev->lock)` must be held while checking `phydev->link` and invoking `phydev->drv` callbacks (`get_sqi`, `get_sqi_max`, `get_tunable`, `set_tunable`). [F41]

## Object Lifetimes
- Every `net_device` reference from `ethnl_parse_header_dev_get()` is tracked in `req_info->dev_tracker` and must be released via `ethnl_parse_header_dev_put(req_info)` (or `netdev_put(req_info->dev, &req_info->dev_tracker)`), never raw `dev_put()`. Netlink dump `.start()` callbacks (`ethnl_default_start()`, `ethnl_perphy_start()`, `ethnl_rss_dump_start()`) must drop `req_info->dev` and set it to `NULL`, saving at most `dev->ifindex`. [F1, F27]
- In `ethnl_default_dumpit()` and `ethnl_perphy_dump_all_dev()`, `for_each_netdev_dump()` under `rcu_read_lock()` must pin `dev` via `netdev_hold(dev, &dev_tracker, GFP_ATOMIC)` before calling `rcu_read_unlock()` to invoke the sleeping dump helper, and must re-acquire `rcu_read_lock()` before calling `netdev_put()`. [F26]
- In `ethnl_default_set_doit()`, `dev->cfg_pending` is allocated with `kmemdup(dev->cfg, ...)` before `ops->set()`, swapped with `dev->cfg` only if `ops->set()` returns `>= 0`, and on every exit path after allocation `dev->cfg_pending` must be freed and reset to `dev->cfg` before `netdev_unlock_ops(dev)`. [F7]
- In `ethnl_rss_create_doit()` and `ethtool_set_rxfh()`, `ctx` is inserted into `dev->ethtool->rss_ctx` under `dev->ethtool->rss_lock` before `ops->create_rxfh_context()`; on failure, it must be erased with `xa_erase()` and freed with `kfree(ctx)` under `rss_lock`. When deleting an RSS context in `ethnl_rss_delete_doit()` or `ethtool_set_rxfh()`, `ethtool_check_rss_ctx_busy()` and `ops->remove_rxfh_context()` must succeed under `rss_lock` before `xa_erase()` and `kfree(ctx)`. [F9, F11]

## API Contracts
- `ethtool_rx_flow_rule_create()` (which allocates both `ethtool_rx_flow_rule` and `flow->rule`) and `ethtool_cmis_cdb_init()` always return `ERR_PTR(-errno)` on failure (never `NULL`) after cleaning up partial allocations; callers must check `IS_ERR()`, must not pass error pointers to `ethtool_rx_flow_rule_destroy()` or `ethtool_cmis_cdb_fini()`, and must free valid flow rules via `ethtool_rx_flow_rule_destroy()` rather than `kfree()`. [F18, F57]
- In `ethnl_request_ops`, `.set_validate` and `.set` return negative errno on failure, `0` for no-op (skipping `.set` or suppressing `ethnl_notify()`), and `1` when valid/modified. In `ethnl_update_*()` helpers, `*mod` is only ever set to `true` on a change and never cleared, so callers must initialize `mod = false`. [F42, F116]
- `ethnl_req_get_phydev()` returns a `struct phy_device *`, `NULL` when no device/PHY is attached, or `ERR_PTR(-ENODEV)` on invalid `req_info->phy_index`; callers must check `IS_ERR()` and pass `tb` (`info->attrs`) and `header` separately without indexing `tb[header]` beforehand because `tb` is `NULL` during `ethnl_default_notify()`. [F43]
- `ethnl_bitset_size()`, `ethnl_put_bitset()`, and `ethnl_update_bitset()` require `unsigned long *` bitmaps, whereas `ethnl_bitset32_size()`, `ethnl_put_bitset32()`, and `ethnl_update_bitset32()` require `u32 *` bitmaps (all taking `nbits` in bits). On 64-bit big-endian, `unsigned long` bitmaps differ in word layout from `u32` arrays and must convert via `bitmap_to_arr32()`/`bitmap_from_arr32()`; `ethnl_update_bitset()` must pass a local `u32_mod = false` to `ethnl_update_bitset32()` and only convert back and set `*mod = true` if `u32_mod` is true. [F53, F66, F98]
- Driver statistics structs (`ethtool_link_ext_stats`, `ethtool_fec_stats`, `ethtool_fec_hist::values`, `ethtool_pause_stats`) use `ETHTOOL_STAT_NOT_SET` (`~0ULL`) for unpopulated `u64` fields; callers must initialize them via `ethtool_stats_init((u64 *)s, sizeof(*s) / 8)` before driver callbacks and check `!= ETHTOOL_STAT_NOT_SET` before emitting. [F51]
- Buffer allocations before driver callbacks must use driver-reported sizes, not clamped or user-supplied sizes: `ethnl_get_priv_flags_info()` must allocate `nflags * ETH_GSTRING_LEN` from `ops->get_sset_count(dev, ETH_SS_PRIV_FLAGS)` before clamping `nflags` to 32; `ethtool_get_dump_data()` must `vzalloc(tmp.len)` from `ops->get_dump_flag()` while capping `dump.len` to `min(tmp.len, dump.len)`; `ethtool_get_regs()` must allocate `ops->get_regs_len(dev)` bytes and copy only `min(regs.len, reglen)` to user. [F83, F84, F85]
- `ethtool_sprintf()` and `ethtool_puts()` write at most `ETH_GSTRING_LEN` bytes (with NUL) into `*data` and advance `*data += ETH_GSTRING_LEN`. Because entries in `ethnl_string_array_t` (`const char [][ETH_GSTRING_LEN]`) may lack a NUL terminator, `ethnl_strz_size()`, `ethnl_put_strz()`, and `ethnl_name_to_idx()` must bound scans to `ETH_GSTRING_LEN` via `strnlen()`/`strncmp()`. [F135, F137]

## Error Handling
- In `ethnl_default_doit()`, `ethnl_default_dump_one()`, and `ethnl_default_notify()`, `ops->cleanup_data(reply_data)` is only called when `ops->prepare_data()` returns `>= 0`, so any `prepare_data` implementation that allocates memory must free it before returning a negative error. [F6]
- In `ethnl_default_dumpit()` and `ethnl_perphy_dump_all_dev()`, `ret` must be reset to `0` at the end of each `for_each_netdev_dump()` iteration after ignoring `-EOPNOTSUPP`, and any other negative error must return `skb->len` when `skb->len > 0` so already-dumped messages are not discarded. [F109]
- In `ethtool_get_ts_info_by_phc()`, both `-ENODEV` and `-EOPNOTSUPP` from `ethtool_net_get_ts_info_by_phc()` must fall back to `ethtool_phy_get_ts_info_by_phc()`, whose returned `struct phy_device *` is an `ERR_PTR` on failure (never `NULL`) and must be checked with `IS_ERR()`. [F46]
- In `ethtool_set_rxfh_fields()`, cross-feature validation of symmetric-xor RSS input transformation via `ops->get_rxfh` must only run when `ops->get_rxfh` is non-NULL, because drivers implementing `ops->set_rxfh_fields` are not required to implement `ops->get_rxfh`. [F48]
- `linkstate_get_sqi()` and `linkstate_get_sqi_max()` return `-EOPNOTSUPP` when unsupported and `-ENETDOWN` when `!phydev->link`; `linkstate_prepare_data()` must ignore both via `linkstate_sqi_critical_error()` and store them in `data->sqi`/`data->sqi_max`, which `linkstate_reply_size()` and `linkstate_fill_reply()` gate with `linkstate_sqi_valid()`. [F50]

## External Contracts
- In `__dev_ethtool()`, `ns_capable(net->user_ns, CAP_NET_ADMIN)` is required for every `SIOCETHTOOL` command (evaluating `sub_cmd` at `useraddr + sizeof(ethcmd)` for `ETHTOOL_PERQUEUE`) except whitelisted unprivileged `ETHTOOL_G*` queries. In `ethtool_genl_ops`, all `*_SET` and `*_ACT` ops plus `ETHTOOL_MSG_WOL_GET` and `ETHTOOL_MSG_MODULE_EEPROM_GET` must set `.flags = GENL_UNS_ADMIN_PERM`, and lookups/notifications must be scoped to the socket/device netns (`genl_info_net()`, `sock_net()`, `ethnl_multicast()`). [F177, F178]
- Both `ethnl_set_features()` and `ethtool_set_features()` must reject with `-EINVAL` any request mask with bits outside `NETIF_F_ETHTOOL_BITS` (`~NETIF_F_ETHTOOL_BITS`), and must restrict changes to `dev->wanted_features` to bits set in `dev->hw_features`. [F186]

## Known Pitfalls
- `ethtool_rxnfc_copy_struct()` populates an uninitialized `struct ethtool_rxnfc` from userspace, initially copying only `offsetof(struct ethtool_rxnfc, data) + sizeof(info->data)` bytes for `ETHTOOL_GRXFH`/`ETHTOOL_SRXFH` and only copying the full struct if `info->flow_type & FLOW_RSS` is set (re-verifying `info->flow_type & FLOW_RSS` after the second copy). Consequently, `ethtool_set_rxnfc()` must gate accesses to insertion-only fields (`info.fs.flow_type`, `info.fs.ring_cookie`) on `cmd == ETHTOOL_SRXCLSRLINS`, and flow classification rules (`ETHTOOL_SRXCLSRLINS`/`ETHTOOL_GRXCLSRULE`) must read `FLOW_RSS` from `info.fs.flow_type` whereas RXFH commands use top-level `info.flow_type`. Also, `ethtool_rxnfc_copy_to_user()` must pass the `rxnfc` pointer directly to `copy_to_user()`, never `&rxnfc`. [F47, F100, F107, F129]
- In `ethtool_check_xfrm_rxfh()`, `ethtool_check_flow_types()`, and `ethtool_set_rxfh()`, any bitmask or capability test on `input_xfrm` must first guard against `input_xfrm == RXH_XFRM_NO_CHANGE` (`0xff`), which has all `RXH_XFRM_*` bits set. In `ethtool_set_rxfh()`, the userspace byte offset of the RSS hash key within `rss_config[]` is `rss_cfg_offset + user_indir_len`, where `user_indir_len` is `indir_bytes` only when `rxfh.indir_size != 0 && rxfh.indir_size != ETH_RXFH_INDIR_NO_CHANGE`, and `0` otherwise. [F89, F106]
- In `ethnl_update_bitset32_verbose()`, an `ETHTOOL_A_BITSET_NOMASK` request must snapshot `bitmap` into `saved_bitmap` before clearing `bitmap`, skip setting `*mod` inside the per-bit loop, and set `*mod = true` afterward only if `!ethnl_bitmap32_equal(saved_bitmap, bitmap, nbits)`. In `net/ethtool/bitset.c`, `ethnl_lower_bits(n)` (`~(u32)0 >> (32 - n % 32)`) is undefined when `n % 32 == 0` and must always be guarded by `if (n % 32)` or `if (nbits < 32)`. [F65, F96]
- In `net/ethtool/cmis_cdb.c`, `ethtool_cmis_cdb_compose_args()` must populate the `u8` `args->read_write_len_ext` exclusively via `ethtool_cmis_get_max_lpl_size()` (clamped to at most 128) and never with an unclamped EPL payload size. When initializing a `struct ethtool_module_eeprom` request via `ethtool_cmis_page_init()` for an output pointer parameter such as `struct cmis_wait_for_cond_rpl *rpl` in `ethtool_cmis_module_poll()`, pass `sizeof(*rpl)` rather than `sizeof(rpl)`. [F119, F128]
