# RADEON and AMDGPU DRM DRIVERS

The AMDGPU DRM driver (`drivers/gpu/drm/amd`) manages AMD GPUs from Southern Islands (GCN 1.0) through RDNA4 (GFX12) and CDNA/MI-series accelerators, covering IP discovery and lifecycle, TTM/GEM/VRAM/GART and multi-level GPU VM page tables, command rings, DRM scheduler jobs, MES/KIQ/userqueue execution, SR-IOV virtualization, XGMI hives, XCP partitioning, RAS recovery, PSP firmware loading, multimedia/display engines, and the KGD-to-KFD ROCm compute interface.

## Architecture & Data Flow
- Struct layout invariants: `struct dev_pagemap pgmap` must remain last in `struct amdgpu_kfd_dev` and `kfd` last in `struct amdgpu_device` (flexible array); `struct dma_fence base` at offset 0 of `struct amdgpu_amdkfd_fence` (`kfree_rcu(f, rcu)`); `struct amdgpu_ring ring` at offset 0 of `struct amdgpu_umsch_mm`; `struct ttm_tt ttm` at offset 0 of `struct amdgpu_ttm_tt`; and `present_flag_0` at offset 0 of `amdgpu_fw_shared` / `vcn4` / `vcn5` [F108, F109, F859, F860, F1168].
- In `amdgpu_ring`, `ring_size` is in bytes (power of 2) while `wptr`, `rptr`, `max_dw`, `count_dw`, and `buf_mask` (`(ring_size / 4) - 1`) are in DWords (`extra_bytes` is excluded from `ring_size`/`buf_mask`). Indexing `ring->ring[]` or `ring_obj` offsets in `amdgpu_ring_write*`, `insert_nop`, `init_cond_exec`, and `emit_gfx_shadow` must mask `wptr` with `ring->buf_mask`, whereas advancing `wptr` masks with `ring->ptr_mask` [F968, F1103, F1119, F1120].
- Ring `.emit_frame_size` and `.emit_ib_size` in `gfx_v8_0`–`v12_0` and `sdma_v5_2`–`v7_0`, plus `*_size` fields in `gfx_v9_0`–`v12_0_kiq_pm4_funcs` and `gfx_v*_get_csb_size`, must match the exact DWords emitted by their callbacks in lockstep [F946, F947, F948, F1450, F1451, F1460, F1575, F1590, F1787, F1996].
- `gfx_v*_init_gds_vmid` (GFX8–GFX11) must start at `vmid = 1` and preserve VMID 0 for HWS/GDS sizing (`gfx_v11_0`/`v12_0_constants_init` also only program `regSH_MEM_BASES` for `i != 0`). Compute EOP interrupt (`get_cpc_int_cntl`, `set_compute_eop_interrupt_state`) and wave-limit helpers in GFX8–GFX12 must only touch MEC1 (`me == 1`), leaving other MECs to KFD [F952, F953, F1439, F1456, F1573, F1574, F1697, F1699].
- In `amdgpu_vm_ptes_update` and `amdgpu_vm_pt_free_list`, when `params->unlocked` is true, updates must only modify leaf entries (descending until `amdgpu_vm_pt_descendant` is false; `amdgpu_bo_vm::entries` has 0 elements at `AMDGPU_VM_PTB`) and never queue child PTs onto `params->tlb_flush_waitlist`. When locked updates overwrite a parent entry covering child PTs, `params->needs_flush` must be set and children moved to `tlb_flush_waitlist` [F1279, F1280, F1300].

## Synchronization
- Every SRBM/GRBM queue selection (`acquire_queue`/`lock_srbm` in `amdgpu_amdkfd_gfx_v7`–`v12`, `vi_srbm_select` in GFX8/SDMA v2.4/v3.0, `soc15_grbm_select` in GFX9, `nv_grbm_select` in GFX10, `soc21`/`soc24_grbm_select` and `select_me_pipe_q` in GFX11/v12) must hold `adev->srbm_mutex` and reset selection to `(0, 0, 0, 0)` before unlocking on all paths, including timeouts [F8, F922, F1405, F1538, F1665, F1800, F2068].
- Every SE/SH/instance selection (`kgd_wave_control_execute`, `wave_control_execute_v10_3`–`v12`, `gfx_v8_0`–`v12_0_select_se_sh`, and `si`/`vi_get_register_value`) must hold `adev->grbm_idx_mutex` and restore broadcast mode (`0xffffffff, 0xffffffff, 0xffffffff`) before unlocking on all paths [F26, F921, F1404, F1537, F1664, F1946, F2063].
- Lock ordering and atomic contexts: `amdgpu_gfx_rlc_enter_safe_mode` and `amdgpu_gfx_off_ctrl` must be called outside `srbm_mutex` and `gpu_clock_mutex`; `kiq->ring_lock` (`spin_lock_irqsave`) nests inside `srbm_mutex` across `amdgpu_ring_alloc`/packet writes/`amdgpu_ring_commit` (or `amdgpu_ring_undo` on error) and must be released before `amdgpu_fence_wait_polling`/`msleep`; IRQ `.set` (under `adev->irq.lock`) and `.process` callbacks must never sleep, lock `srbm_mutex`/`grbm_idx_mutex`, or use KIQ register accessors [F31, F586, F917, F1024, F1102, F1406, F1412, F1519, F1671, F2137, F2142].
- `amdgpu_mes_lock`/`unlock` (on `mes->mutex_hidden`) and `amdgpu_vm_eviction_lock`/`trylock`/`unlock` (on `vm->eviction_lock`) must always be used instead of raw `mutex_lock` so `memalloc_noreclaim_save()` and `memalloc_noreclaim_restore()` bracket the critical section; callers holding `amdgpu_mes_lock` must not acquire BO reservation locks [F568, F767].
- `amdgpu_device_lock_reset_domain` must set `reset_domain->in_gpu_reset = 1` before `down_write(&reset_domain->sem)`, and `unlock_reset_domain` must clear it to `0` before `up_write`. In `set_barrier_auto_waitcnt` (under `grbm_idx_mutex`), `reset_domain->sem` must use `down_read_trylock`, and once `amdgpu_amdkfd_suspend(adev, true)` runs, all exit paths must restart the compute scheduler, call `amdgpu_amdkfd_resume(adev, true)`, and `up_read` [F12, F27, F1061].
- In `amdgpu_ih_ring_write`, IV dwords must be written before checking `wptr != READ_ONCE(ih->rptr)`, with `wmb()` before `WRITE_ONCE(*ih->wptr_cpu, cpu_to_le32(wptr))`. IH readers (`amdgpu_ih_process`, `amdgpu_ih_wait_on_checkpoint_process_ts`, `amdgpu_gmc_filter_faults_remove`) must execute `rmb()` after `amdgpu_ih_get_wptr` before reading `ih->ring`. In `amdgpu_gart_invalidate_tlb` and `amdgpu_device_aper_access`, `mb()` and `amdgpu_device_flush_hdp`/`invalidate_hdp` must separate PTE/BAR accesses and GPU TLB flushes [F206, F516, F576, F577].
- In GFX9 and SDMA v3.0–v7.0 `*_ring_set_wptr`, when `ring->use_doorbell` is true, `*ring->wptr_cpu_addr` must be updated via `WRITE_ONCE` or `atomic64_set` before ringing `WDOORBELL32`/`WDOORBELL64`. During SDMA v4.0–v7.0 and VPE v6.1 ring resume/start, writing a smaller WPTR must be bracketed by setting `MINOR_PTR_UPDATE = 1` beforehand and `0` afterward, before setting `RB_ENABLE = 1` [F1675, F1817, F1818, F1952, F1973, F2071].

## Object Lifetimes
- `amdgpu_bo_create_reserved` unreferences `*bo_ptr` and returns `0` when `size == 0`, allocates a new BO only when `*bo_ptr == NULL` (`free = true`), and on `error_free` must only call `amdgpu_bo_unref(bo_ptr)` when `free` is true. Callers allocating new kernel BOs (e.g., RLC SR/CPT, MEC HPD/fw, CP PFP/ME/MEC fw, SDMA v7.0 fw) must initialize `*bo_ptr = NULL` beforehand and call `amdgpu_bo_kunmap` and `amdgpu_bo_unreserve` once CPU population is done [F599, F685, F909, F1056, F1402, F1536, F1658, F1940].
- Interior/borrowed pointers that must never be freed directly: `adev->reg_offset[hw_ip][inst]` points inside `adev->mman.discovery_bin` (must stay allocated until `amdgpu_discovery_fini`); `adev->gfx.rlc.register_restore` points inside `register_list_format`; `xcc_info->numa_info` is owned by `numa_info_xa`; and shared firmware pointers (`adev->vcn.inst[i].fw` when `!per_inst_fw`, and `adev->sdma.instance[i].fw` when `duplicate == true`) must only be released once via `inst[0]` [F19, F237, F744, F1051, F1163, F1533, F1796, F1939].
- In `amdgpu_job_submit`, `&job->base.s_fence->finished` must be pinned with `dma_fence_get` and `amdgpu_job_free_resources(job)` called after `drm_sched_job_arm` and before `drm_sched_entity_push_job`. `amdgpu_job_submit_direct` frees `job` only when `amdgpu_ib_schedule` succeeds (callers must call `amdgpu_job_free` on error). `amdgpu_job_set_gang_leader` must not ref `scheduled` when `job == leader`, and `amdgpu_job_free` must only put `job->gang_submit` when `!= &job->base.s_fence->scheduled` [F558, F559, F584].
- In `amdgpu_vm_update_range`, `amdgpu_vm_tlb_flush` takes ownership of `tlb_cb` (freed in `amdgpu_vm_tlb_seq_cb`), so `tlb_cb` must be set to `NULL` before `error_free: kfree(tlb_cb)`. In `amdgpu_vm_tlb_fence_create`, `f->dependency` consumes the caller's `*fence` reference without `dma_fence_get`, and `dma_fence_get(&f->base)` must be called before `schedule_work(&f->work)` [F752, F1218].
- Callers of `amdgpu_gfx_off_ctrl` and `amdgpu_gfx_off_ctrl_immediate` must pair every disable (`false`, incrementing `gfx_off_req_count`) with an enable (`true`, decrementing it) and never pass `true` when `gfx_off_req_count == 0`. When `gfx_v9_0`/`v10_0`/`v11_0_set_powergating_state` toggles powergating, `amdgpu_gfx_off_ctrl*(adev, false)` must precede ungating (`!enable`), and `amdgpu_gfx_off_ctrl*(adev, true)` must follow gating (`enable`) [F390, F918, F1411, F1771].

## API Contracts
- Non-standard return conventions: `amdgpu_fence_wait_polling` returns remaining timeout (>0) on success and `0` on timeout (check `r < 1`, not `r < 0`); `amdgpu_ih_ts_after(t1, t2)` returns true when `t2` is after `t1` (pass earlier timestamp as `t1`, and always use `amdgpu_ih_ts_after*` for 48-bit IH timestamps); `__verify_ras_table_checksum` returns `0` on valid, positive `1..255` on mismatch, and `< 0` on error; `amdgpu_vram_mgr_query_page_status` returns `0` (reserved), `-EBUSY` (pending), or `-ENOENT` (only reserve on `-ENOENT`) [F414, F665, F666, F1081, F1263].
- `amdgpu_vmid_grab` returns `0` both when a VMID is assigned (`job->vmid != 0`) and when all VMIDs are busy (`job->vmid == 0`, `*fence` set to wait on). `amdgpu_ctx_get_fence` returns `ERR_PTR(-EINVAL)` if `seq >= centity->sequence`, `NULL` if expired (`seq + amdgpu_sched_jobs < centity->sequence`), or a new `dma_fence_get` reference; `amdgpu_ctx_add_fence` takes its own `dma_fence_get` reference and requires a `struct drm_sched_fence` on a `struct amdgpu_ctx_entity` [F165, F166, F250, F299, F301, F591].
- VM and TTM unit conversions: `amdgpu_vm_bo_lookup_mapping`, `amdgpu_vm_update_range`, and `amdgpu_vm_ptes_update` (`start`, `end`) take 4KB GPU PFNs (`addr >> AMDGPU_GPU_PAGE_SHIFT`; `mapping->start`/`last` are inclusive PFNs), whereas `amdgpu_vm_bo_map`/`replace_map`/`unmap`/`clear_mappings` and `dst` in `amdgpu_vm_ptes_update` take byte addresses, and `vm->update_funcs->update` takes `pe` as a byte offset (`entry_idx * 8`). `amdgpu_mem_partition_info.range.lpfn` is inclusive, so `amdgpu_bo_placement_from_domain` must set `places[c].lpfn = range.lpfn + 1` [F606, F787, F810, F1258, F1344].
- Partition (`xcp_id`), doorbell, and wb indexing: `amdgpu_gem_object_create`, `amdgpu_vm_pt_create`, and `amdgpu_bo_create` (`bp->xcp_id_plus1`) take a 1-based index (`0` = any partition -> `bo->xcp_id = -1`; pass `xcp_id + 1`). `KFD_XCP_MEM_ID(adev, xcp_id)` can return `-1` and must be checked `>= 0`. Doorbells are indexed in 32-bit dwords, so 64-bit QWORD assignments in `adev->doorbell_index` must be shifted `<< 1`. `amdgpu_device_wb_get` offsets index `adev->wb.wb[offs]` directly (cast to 64-bit when `support_64bit_ptrs` is true) but multiply by 4 when added to `adev->wb.gpu_addr` [F77, F423, F425, F637, F1162, F1259, F1485, F1891, F1892, F2117].

## Error Handling
- In `amdgpu_sched_ops`, `amdgpu_job_prepare_job` must never return an `ERR_PTR` (it sets `dma_fence_set_error` on `finished` and returns `NULL`, keeping `job->vm` non-NULL), whereas `amdgpu_job_run` skips `amdgpu_ib_schedule` when `finished->error < 0` (or marks `finished` `-ECANCELED` on VRAM-lost generation mismatch or gang job resubmission while still calling `amdgpu_job_free_resources`) and returns `ERR_PTR(r)` if `amdgpu_ib_schedule` fails [F560, F592, F619].
- In `amdgpu_device_ip_early_init`, an IP block's `early_init` returning `-ENOENT` marks `status.valid = false` without failing device init, whereas any other non-zero return fails init with `-ENODEV`. Because `kcalloc` failure for IP dump buffers (`adev->gfx.ip_dump_*` and `adev->sdma.ip_dump`) is non-fatal in `sw_init`, all `dump_ip_state` and `print_ip_state` callbacks (and `amdgpu_coredump` for nullable `job`/`coredump->ring`) must null-check pointers before dereferencing [F215, F222, F935, F1424, F1682, F1827].
- In `amdgpu_gem_fault`, `ttm_bo_vm_reserve` locks `bo->base.resv` on return `0`; every exit path must unlock `bo->base.resv` except when `ttm_bo_vm_fault_reserved` or `ttm_bo_vm_dummy_page` returns `VM_FAULT_RETRY` with `!(vmf->flags & FAULT_FLAG_RETRY_NOWAIT)`. `amdgpu_bo_fault_reserve_notify` must return a `vm_fault_t` bitmask (`0`, `VM_FAULT_NOPAGE`, or `VM_FAULT_SIGBUS`), never a negative errno [F385, F607].

## External Contracts
- Union ioctl arguments (`union drm_amdgpu_ctx` and `union drm_amdgpu_gem_*`) overlay `in` and `out` in the same buffer; handlers must read `in` first and zero `out` before populating outputs. In `amdgpu_info_ioctl`, every `copy_to_user` must clamp size to `min(size, sizeof(kernel_obj))`, and in `amdgpu_gem_op_ioctl`/`amdgpu_gem_list_handles_ioctl` non-zero `copy_to_user` returns must be converted to `-EFAULT` [F209, F413, F422, F630].
- Hardware register encodings: 256-byte-aligned GPU base addresses (`CP_HQD_PQ_BASE*`, `CP_HQD_EOP_BASE_ADDR*`, `CP_GFX_HQD_BASE`, `CP_RB0/1_BASE*`, `SQ_SHADER_TBA/TMA*`, `COMPUTE_PGM_LO/HI`, `SDMA*_RB_BASE*`, `IH_RB_BASE*`, `VPEC_QUEUE0_RB_BASE*`) must be shifted `addr >> 8` in 64-bit arithmetic before splitting `lower_32_bits`/`upper_32_bits` (PSP `C2PMSG_36` LFB addresses shift `>> 20`). In SDMA v2.4–v7.0 and VPE, software `wptr` is in DWords while hardware `RB_RPTR`/`RB_WPTR`, writeback slots, and doorbells use byte offsets (`wptr << 2` in 64-bit before splitting, `>> 2` on read) [F54, F945, F1261, F1431, F1604, F1736, F1833, F1861, F1879, F1884, F1990, F1991, F2115].

## Known Pitfalls
- 32-bit shift and multiplication overflows: cast 32-bit operands to `u64`/`uint64_t` before shifting or multiplying into 64-bit results, including `RREG32(mmRCC_CONFIG_MEMSIZE) << 20`, `si.totalram * si.mem_unit`, `amdgpu_vram_limit << 20`, `ttm->num_pages`/`bo_mem->start` `<< PAGE_SHIFT`, `(mask + 1) << shift` in `amdgpu_vm_ptes_update`, `vm_size << 18`, `nps << UMC_NPS_SHIFT` (40), `1ULL << id` in `fw_autoload_mask`/`queue_mask`, `1ULL << bit_width` in `amdgpu_gfx_create_bitmask`, and upper 32-bit register reads shifted `<< 32` [F289, F292, F486, F487, F669, F844, F992, F1144, F1147, F1333, F1477, F1605, F2012, F2112].
- Unit, pointer, and loop pitfalls: in `gfx_firmware_header_v1_0` and `sdma_firmware_header_v1_0`, `ucode_size_bytes` is bytes while `jt_offset`/`jt_size` are DWords (`* 4` for bytes, unscaled on `__le32 *`). `amdgpu_ring_write_multiple` takes DWords (`sizeof(payload) >> 2`). `pci_get_drvdata(pdev)` returns `struct drm_device *` and requires `drm_to_adev()`. In `gfx_v8_0`–`v12_0` `sw_init`, queue loops nest `j` (`queue`) outside `k` (`pipe`), so `(me, pipe, queue)` callees take `(i, k, j)`; `ring->me` and `lock_srbm` are 1-based (`mec + 1`), while `PACKET3_MAP_QUEUES_ME` is 0-based (`ring->me - 1`) [F53, F310, F943, F986, F1002, F1007, F1126, F1427, F1465, F1481, F1482, F1591, F1712, F1724].
