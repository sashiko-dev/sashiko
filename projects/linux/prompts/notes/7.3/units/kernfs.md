# KERNFS

kernfs provides an in-memory pseudo-filesystem framework (underlying sysfs, cgroupfs, etc.) that decouples subsystem hierarchy management and active-reference lifetimes from VFS inode and dentry locking. It manages directory, regular attribute file, and symlink nodes (`struct kernfs_node`) organized in per-root red-black trees and IDRs, supporting optional namespace tags, buffered/`seq_file` I/O, mmap, poll/fsnotify notifications, exportfs file handles, and extended attributes.

## Architecture & Data Flow

- Under `kernfs_open_file_mutex_ptr(kn)`, `on->nr_to_release` is incremented in `kernfs_get_open_node()` (if `KERNFS_HAS_RELEASE`) and decremented in `kernfs_release_file()` (setting `of->released = true`) or `kernfs_unlink_open_file()` on `open_failed`; `kernfs_drain_open_files()` clears `of->mmapped = false` when decrementing `on->nr_mmapped`, and `kernfs_unlink_open_file()` clears `kn->attr.open` before `kfree_rcu()`. `kernfs_release_file()` must synchronize via `kernfs_open_file_mutex_ptr(kn)` (not `of->mutex`) and call `kn->attr.ops->release(of)` directly. [F9, F65, F118]
- Because `dir.root` is in the `struct kernfs_node` union (`dir`, `symlink`, `attr`) and `kernfs_root(kn)` reads `kn->__parent->dir.root` when `kn->__parent` is non-NULL, every `KERNFS_DIR` node must set `kn->dir.root` and every non-root node must set `kn->__parent` before `kernfs_root(kn)` is called. Before calling `kernfs_add_one(kn)`, creators must initialize `kn->__parent`, `kn->ns`, `kn->priv`, type-specific union fields, and cached `KERNFS_HAS_*` or `KERNFS_LOCKDEP` flags. [F17, F46]
- `__kernfs_new_node()` allocates 1-based 32-bit cyclic IDs from `root->ino_idr` and increments `root->id_highbits` on wrap below `root->last_id_lowbits`; `kernfs_create_root()` initializes `id_highbits` to `1` when `sizeof(ino_t) < sizeof(u64)` and `0` otherwise because `gen == 0` is a wildcard on 32-bit `ino_t`. In `kernfs_find_and_get_node_by_id()`, RCU lookup in `root->ino_idr` must verify `kernfs_ino(kn) == ino`, `!gen || kernfs_gen(kn) == gen`, `__kernfs_active(kn)`, and `atomic_inc_not_zero(&kn->count)`. [F37, F80, F96]
- In `kernfs_fop_open()` (when `ops->prealloc` is set) and `kernfs_fop_write_iter()`, write buffers must be allocated with `len + 1` bytes and `len` must be bounded by `of->atomic_write_len` (rejecting larger writes with `-E2BIG`) or clamped to `PAGE_SIZE`, because `kernfs_fop_write_iter()` unconditionally sets `buf[len] = '\0'`. [F76]
- `kernfs_show(kn, true)` must clear `KERNFS_HIDDEN` and call `kernfs_activate_one(kn)` only if `KERNFS_ACTIVATED` is set, and `kernfs_activate_one(kn)` must record `KERNFS_ACTIVATED` before checking `KERNFS_HIDDEN | KERNFS_REMOVING` to decide whether to subtract `KN_DEACTIVATED_BIAS` from `kn->active`. [F75]
- In `kernfs_rename_ns()`, `kn` must be unlinked via `kernfs_unlink_sibling()` before mutating `kn->__parent`, `kn->ns`, `kn->name`, or `kn->hash`, and re-linked via `kernfs_link_sibling()` only after recomputing `kn->hash` via `kernfs_name_hash()`. `kernfs_unlink_sibling()` must call `RB_CLEAR_NODE(&kn->rb)` after `rb_erase()` so `RB_EMPTY_NODE(&kn->rb)` indicates whether `kn` is unlinked. [F62, F63]
- `kn->iattr` is lazily allocated via `kernfs_iattrs(kn)`; read-only paths (`kernfs_refresh_inode()`, `kernfs_xattr_get()`) use `kernfs_iattrs_noalloc(kn)` and handle `NULL`, whereas `kernfs_iop_listxattr()`, `__kernfs_setattr()`, and `kernfs_vfs_user_xattr_set()` must call `kernfs_iattrs(kn)` and return `-ENOMEM` if `NULL`. Broken by: returning `-ENODATA` from `kernfs_iop_listxattr()` when `kn->iattr` is `NULL`. [F45]
- `kernfs_fop_open()` must always call `seq_open()` (with `&kernfs_seq_ops` if `ops->seq_show` is set or `NULL` otherwise), set `of->seq_file->private = of`, and restore `FMODE_PWRITE` if `FMODE_WRITE` is set, because `kernfs_of(file)` dereferences `((struct seq_file *)file->private_data)->private`. [F48]
- In `kernfs_iop_lookup()`, `kernfs_set_rev(parent, dentry)` must be called for all non-error lookups (`!IS_ERR(inode)`), including positive dentries, because a positive dentry can later become negative via `dentry_unlink_inode()` and be checked by `kernfs_dop_revalidate()`. [F50]
- Every file read path (`kernfs_seq_show()` and `kernfs_file_read_iter()`) must snapshot `atomic_read(&of_on(of)->event)` into `of->event` while holding an active reference on `of->kn` before invoking the read callback. [F59]

## Synchronization

- In `struct kernfs_root`, `root->kernfs_supers_rwsem` nests outside `root->kernfs_rwsem`, and `root->kernfs_rwsem` nests outside `root->kernfs_iattr_rwsem`, `root->kernfs_rename_lock`, and `kernfs_pr_cont_lock` (`spin_lock_irq()`). Updates to `kn_parent->dir.subdirs`, `kn_parent->dir.rev` (`kernfs_inc_rev()`), `kn->mode`, and `kn->iattr` timestamps/UID/GID must hold `root->kernfs_iattr_rwsem` for write. [F26, F114]
- Accessing `kn->name` requires RCU read lock or `kernfs_root(kn)->kernfs_rwsem` (`kernfs_rcu_name()`). Because `kn->name` is allocated via `kstrdup_const()`, freeing it must use `kfree_const()` (`kernfs_free_rcu()`, `__kernfs_new_node()`), while `kernfs_rename_ns()` must publish the new name with `rcu_assign_pointer()`, free `old_name` via `kfree_rcu_mightsleep()` if `!is_kernel_rodata((unsigned long)old_name)`, and call `kernfs_get(new_parent)` before updating `kn->__parent` under `kernfs_rename_lock` and `kernfs_put(old_parent)` after. [F16, F28, F105]
- Accessing `kn->__parent` via `kernfs_parent(kn)` requires `rcu_read_lock()`, `root->kernfs_rwsem`, or `root->kernfs_rename_lock` (unless `kn->count == 0`); pinning parent without `kernfs_rwsem` or walking multi-step ancestors (`kernfs_path_from_node()`) requires `read_lock_irqsave(&root->kernfs_rename_lock, flags)` unless `KERNFS_ROOT_INVARIANT_PARENT` is set, and `kernfs_rename_ns()` must use `write_lock_irq(&root->kernfs_rename_lock)`. [F29, F30, F112]
- When `KERNFS_ROOT_INVARIANT_PARENT` is set, `kernfs_rename_ns()` rejects `old_parent != new_parent` with `WARN_ON_ONCE` and `-EINVAL`. In `kernfs_node_dentry()`, `root->flags & KERNFS_ROOT_INVARIANT_PARENT` must be verified before walking ancestors (failing with `WARN_ON_ONCE` and `ERR_PTR(-EINVAL)` otherwise), and each step must copy `kernfs_rcu_name(kntmp)` via `kstrdup()` while holding `root->kernfs_rwsem` for read before dropping `root->kernfs_rwsem` to call `lookup_noperm_positive_unlocked()`. [F35, F143]
- In `kernfs_get_open_node()`, a new `struct kernfs_open_node` must have `on->event`, `on->poll`, and `on->files` initialized under `kernfs_open_file_mutex_ptr(kn)` before `rcu_assign_pointer(kn->attr.open, on)` publishes it, and `on` must be freed with `kfree_rcu()`. Readers not holding `kernfs_open_file_mutex_ptr(kn)` or a linked `kernfs_open_file` (`!list_empty(&of->list)`) must dereference `kn->attr.open` under `rcu_read_lock()`. [F19, F123]
- On regular file I/O, seek, and mmap paths (`kernfs_seq_start`, `kernfs_file_read_iter`, `kernfs_fop_write_iter`, `kernfs_fop_mmap`, `kernfs_fop_llseek`), `of->mutex` must be acquired before `kernfs_get_active_of(of)`. In `kernfs_file_read_iter()` and `kernfs_fop_write_iter()`, when `of->prealloc_buf` is non-NULL, `of->prealloc_mutex` must be locked outside `of->mutex` and unlocked on exit instead of calling `kfree(buf)`, whereas dynamic buffers are freed with `kfree(buf)` after `kernfs_put_active_of(of)` and `mutex_unlock(&of->mutex)`. [F10, F33]
- Every `kernfs_break_active_protection(kn)` inside an active-referenced `kernfs_ops` callback must be matched by `kernfs_unbreak_active_protection(kn)` before returning, and in `kernfs_remove_self(kn)` that `kernfs_unbreak_active_protection(kn)` must occur before `up_write(&root->kernfs_rwsem)`. [F6]
- `kernfs_notify()` may be called from any context: it must only wake `on->poll` under `rcu_read_lock()` and enqueue `kn` (taking `kernfs_get(kn)`) onto `kernfs_notify_list` (terminated with `KERNFS_NOTIFY_EOL`, not `NULL`) under `spin_lock_irqsave(&kernfs_notify_lock, flags)`. `kernfs_notify_workfn()` resets `kn->attr.notify_next = NULL` under `kernfs_notify_lock`, runs sleeping `kernfs_supers_rwsem`, `kernfs_rwsem`, and `fsnotify()` calls, and calls `kernfs_put(kn)`. [F74, F113]
- Every `idr_alloc_cyclic()` or `idr_remove()` on `root->ino_idr` must hold `root->kernfs_idr_lock`. `kernfs_active(kn)` asserts `kernfs_root(kn)->kernfs_rwsem` is held; callers without `kernfs_rwsem` must use `__kernfs_active(kn)`. [F25, F27]
- `pr_cont()` must never be called while holding `root->kernfs_rename_lock`; `pr_cont_kernfs_name()` and `pr_cont_kernfs_path()` must format into `kernfs_pr_cont_buf` under `spin_lock_irqsave(&kernfs_pr_cont_lock, flags)` first. [F111]
- `kernfs_fop_open()` must initialize `of->mutex` at three separate `mutex_init()` call sites for `has_mmap`, `file->f_mode & FMODE_WRITE`, and read-only files for distinct lockdep classes, and `kernfs_fop_mmap()` must check `KERNFS_HAS_MMAP` before locking `of->mutex`. [F119]

## Object Lifetimes

- File and VMA operations on `struct kernfs_open_file` must acquire active references via `kernfs_get_active_of()` / `kernfs_put_active_of()` rather than `kernfs_get_active(of->kn)`, so operations abort once `of->released` is set by `kernfs_release_file()`. [F1]
- `kernfs_destroy_root()` must bracket `kernfs_remove(root->kn)` with `kernfs_get(root->kn)` and `kernfs_put(root->kn)`, because `kernfs_put()` frees `struct kernfs_root` when the root node's `count` reaches zero while `kernfs_remove()` still holds `root->kernfs_rwsem`. [F2]
- `kernfs_new_node()` sets `kn->count` to 1 and pins `parent` (and `kernfs_create_link()` pins `target`), and `kernfs_add_one()` consumes that `kn->count` reference only on success; creators must call `kernfs_put(kn)` on `kernfs_add_one()` failure (without a separate `kernfs_put(target)` in `kernfs_create_link()`). [F3]
- `kernfs_seq_start()` locks `of->mutex` (unlocked in `kernfs_seq_stop()`) and gets `kernfs_get_active_of(of)`; because `kernfs_seq_stop()` skips `kernfs_seq_stop_active()` on `ERR_PTR(-ENODEV)`, `kernfs_seq_start()` and `kernfs_seq_next()` must call `kernfs_seq_stop_active()` when `ops->seq_start` or `ops->seq_next` returns `ERR_PTR(-ENODEV)`. [F7]
- `kernfs_fop_open()` holds `kernfs_get_active(kn)` only during open setup, and on failure after `of` allocation, `prealloc_buf` allocation, `seq_open()`, and `kernfs_get_open_node()` it must unwind in reverse order: `kernfs_unlink_open_file(kn, of, true)`, `seq_release()`, `kfree(of->prealloc_buf)`, `kfree(of)`, and `kernfs_put_active(kn)`. [F8]
- `kernfs_get_inode()` takes its own `kernfs_get(kn)` in `kernfs_init_inode()` when `iget_locked()` returns `I_NEW` (released in `kernfs_evict_inode()`), so callers holding a refcounted `kn` (e.g. `__kernfs_fh_to_dentry()`) must still call `kernfs_put(kn)` afterward. [F14]
- In `kernfs_fop_readdir()`, saving `pos` in `file->private_data` before `dir_emit()` must be paired with `kernfs_get(pos)` (and cleared to `NULL` at EOF), and `kernfs_dir_pos()` must consume that reference via `kernfs_put(pos)` and fall back to an rbtree search by `ctx->pos` hash if `pos` is no longer active, under `parent`, or matching `hash`. [F70]

## API Contracts

- `kernfs_find_ns()`, `kernfs_walk_ns()`, `kernfs_dentry_node()`, `kernfs_node_from_dentry()`, and `kernfs_root_to_node()` return borrowed pointers, whereas `kernfs_find_and_get_ns()`, `kernfs_walk_and_get_ns()`, `kernfs_get_parent()`, and `kernfs_find_and_get_node_by_id()` increment `kn->count` and require `kernfs_put()`. `kernfs_node_from_dentry()` and `kernfs_root_from_sb()` must verify `s_op == &kernfs_sops` before calling `kernfs_dentry_node()` or `kernfs_info()`. [F4, F107]
- `kernfs_ops(kn)` asserts `lockdep_assert_held(kn)` when `KERNFS_LOCKDEP` is set and requires an active reference on `kn`; paths without an active reference must check cached `KERNFS_HAS_*` flags or `of->atomic_write_len` instead. [F47]
- `kernfs_fop_mmap()` must verify `vma->vm_file == file`, `!(of->mmapped && of->vm_ops != vma->vm_ops)`, and `!(vma->vm_ops && vma->vm_ops->close)` after `ops->mmap(of, vma)` succeeds before saving `vma->vm_ops` into `of->vm_ops` and setting `vma->vm_ops = &kernfs_vm_ops`. [F67]
- RCU path-walk VFS callbacks (`kernfs_dop_revalidate()` with `LOOKUP_RCU`, `kernfs_iop_permission()` with `MAY_NOT_BLOCK`, `kernfs_iop_get_link()` when `!dentry`) must return `-ECHILD` or `ERR_PTR(-ECHILD)` before acquiring `kernfs_rwsem`, `kernfs_iattr_rwsem`, or sleeping allocations. [F110]
- In `kernfs_notify_workfn()`, `FS_MODIFY` events must look up target and parent VFS inodes via `ilookup()` and `kernfs_get_parent()` (not dcache aliases); `fsnotify()` with `FS_EVENT_ON_CHILD` and `&name` requires a non-NULL `p_inode`, falling back to `fsnotify_inode(inode, FS_MODIFY)` otherwise. [F53, F133]
- Once `kernfs_enable_ns()` sets `KERNFS_NS` on an empty directory, every child in `kernfs_add_one()` or `kernfs_find_ns()` under it must have `(bool)ns == kernfs_ns_enabled(parent)`. In `kernfs_fop_open()`, setting both `ops->prealloc` and `ops->seq_show` fails with `-EINVAL`. [F125, F142]

## Error Handling

- `kernfs_get_inode()` returns `NULL` (not `ERR_PTR`) on failure; callers must test `!inode` and convert `NULL` to `ERR_PTR(-ENOMEM)` before passing it to `d_splice_alias()`. [F39]
- In `kernfs_file_read_iter()` and `kernfs_fop_write_iter()`, `len` receiving `ops->read()` or `ops->write()` must be `ssize_t` (not `size_t`). Functions accepting nullable `kn` (`kernfs_remove()`, `__kernfs_remove()`, `kernfs_get()`, `kernfs_put()`, `kernfs_get_active()`, `kernfs_put_active()`, `kernfs_name()`, `kernfs_path_from_node()`) must check `!kn` before calling `kernfs_root(kn)` (including in `lockdep_assert_held*()`). [F41, F44]
- Deactivation/draining helpers (`kernfs_should_drain_open_files()`) must not `WARN_ON(atomic_read(&kn->active) != KN_DEACTIVATED_BIAS)`, as concurrent callers between `kernfs_unbreak_active_protection()` and `kernfs_put_active()` can transiently increment `kn->active`. [F134]

## External Contracts

- Public functions under `#ifdef CONFIG_KERNFS` in `include/linux/kernfs.h` must have matching `static inline` stubs in `#else`. `kernfs_file_fops` must wire `copy_splice_read` and `iter_file_splice_write`, and `kernfs_sops` must leave `.freeze_fs`/`.unfreeze_fs`/`.freeze_super`/`.thaw_super` as `NULL` so suspend/hibernate writes to `/sys/power/` do not deadlock. [F60, F131, F135]
- `kernfs_encode_fh()` and `__kernfs_fh_to_dentry()` require `*max_len >= 2` / `fh_len >= 2`, encoding `kn->id` as 64-bit for `FILEID_KERNFS` and reconstructing `((u64)fid->i32.gen << 32) | fid->i32.ino` for `FILEID_INO32_GEN` / `FILEID_INO32_GEN_PARENT`. [F78]
- With `KERNFS_ROOT_EXTRA_OPEN_PERM_CHECK`, `kernfs_fop_open()` must fail with `-EACCES` (even with `CAP_DAC_OVERRIDE`) if `FMODE_WRITE` lacks `S_IWUGO` and `ops->write || ops->mmap`, or `FMODE_READ` lacks `S_IRUGO` and read/mmap ops. `kernfs_iop_mkdir()`, `kernfs_iop_rmdir()`, and `kernfs_iop_rename()` must hold `kernfs_get_active()` on all `kernfs_node` arguments across `root->syscall_ops`, and `kernfs_iop_mkdir()` returns `ERR_PTR(ret)`. [F137, F144]

## Known Pitfalls

- In `kernfs_path_from_node(to, from, buf, buflen)` and `kernfs_path_from_node_locked(kn_to, kn_from, buf, buflen)`, the first parameter is `to` and the second is `from`, opposite to their kernel-doc comments and the `!CONFIG_KERNFS` stub. `kernfs_path_from_node_locked()` must check for negative `strscpy()` returns before adding to `len` and use a signed loop counter `i` for the `depth_to - 1` down-to-`0` loop. [F51, F83]
- `KN_DEACTIVATED_BIAS` must remain `INT_MIN + 1` (not `INT_MIN`) so negating it in `atomic_sub(KN_DEACTIVATED_BIAS, &kn->active)` in `kernfs_activate_one()` does not overflow `int`. [F98]
