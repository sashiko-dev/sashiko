# DRM DRIVER FOR VMWARE VIRTUAL GPU

This unit implements the VMware SVGA virtual GPU DRM driver (`drivers/gpu/drm/vmwgfx`), covering KMS display units (Legacy Display Unit, Screen Object Unit, and Screen Target Display Unit), video overlays, Guest Memory Object (MOB) page tables, resource lifecycle and eviction, 3D resources (shaders, views, state objects, streamoutputs, simple resources), page-dirty tracking for coherent buffer objects, DMA-BUF PRIME handle conversion, and host RPC/mksGuestStats hypercall messaging.

## Architecture & Data Flow

- A `struct vmw_user_object` must never have both `surface` and `buffer` non-NULL: when `vmw_user_object_lookup` resolves a non-dumb BO handle to a surface via `vmw_lookup_surface_for_buffer`, it must release and clear `uo->buffer` via `vmw_user_bo_unref(&uo->buffer)`. [F8]
- Tearing down a defined STDU in `vmw_stdu_crtc_mode_set_nofb` or `vmw_stdu_crtc_atomic_disable` requires `vmw_stdu_bind_st(dev_priv, stdu, NULL)` and `vmw_stdu_update_st` before `vmw_stdu_destroy_st`, and both `vmw_stdu_destroy_st` and `vmw_sou_fifo_destroy` must wait via `vmw_fallback_wait(..., 3*HZ)`. When `stdu->defined` and `new_crtc_state->enable && !new_crtc_state->active && !new_crtc_state->mode_changed`, `vmw_stdu_crtc_atomic_disable` must only unbind and update to blank, not destroy. [F40, F72, F140]
- In `vmwgfx_so.c`, an active `struct vmw_view` must be linked into both `srf->view_list` (`view->srf_head`) and `view->cotable` (`view->cotable_head`) with `res->id = view->view_id`, and unlinked from both with `list_del_init` and `res->id = -1` when destroyed or uncommitted. In `vmw_dx_shader_cotable_list_scrub` and `vmw_dx_streamoutput_cotable_list_scrub`, `entry->committed` must be preserved when `readback` is true and cleared to `false` only when `!readback`. [F66, F68]
- `vmw_otables_setup` must `kmemdup` `dx_tables` or `pre_dx_tables` per device, and `vmw_otable_batch_setup` must `PFN_ALIGN` each enabled `otables[i].size` before `vmw_setup_otable_base` shifts by `PAGE_SHIFT`. In `vmw_setup_otable_base` and `vmw_mob_bind`, `mob->pt_level` from `vmw_mob_pt_setup` must be offset by `VMW_MOBFMT_PTDEPTH_1 - SVGA3D_MOBFMT_PT_1` once when `mob->pt_bo` is populated, and `vmw_mob_calculate_pt_pages`/`vmw_mob_build_pt` must use ceiling division (`DIV_ROUND_UP`/`PFN_ALIGN`). [F69, F93, F119, F120]
- `vmw_resource_mob_attach` and `vmw_resource_mob_detach` must update `gbo->res_tree` and `gbo->res_prios` in lockstep using the priority cached in `res->used_prio` at attach time (not recomputing from `res->res_dirty`) and clear `res->mob_node` with `RB_CLEAR_NODE` on detach. [F62]
- In `struct vmw_bo_dirty`, `start` and `end` form a half-open page range `[start, end)` within `bitmap`; when no pages are dirty, `start` must be set to `bitmap_size` (or `>= end`) and `end` to `0` so `min`/`max` updates in `vmw_bo_vm_mkwrite` establish valid bounds. [F92]
- `vmw_kms_sou_init_display` requires `dev_priv->has_gmr` and `SVGA_CAP_SCREEN_OBJECT_2`; `vmw_kms_stdu_init_display` requires `dev_priv->has_mob` and `SVGA_CAP_GBOBJECTS`. `vmw_stdu_connector_mode_valid` must align `hdisplay`/`vdisplay` to `GPU_TILE_SIZE` (64) and page-align byte size before checking `max_primary_mem`, `max_mob_pages * PAGE_SIZE`, and `max_mob_size`. In `vmw_stdu_connector_atomic_check`, if `gui_x`/`gui_y` differ from `set_gui_x`/`set_gui_y`, `new_crtc_state->mode_changed` must be set to `true`. [F71, F145, F147]

## Synchronization

- Unpinning a TTM BO (`ttm_bo_unpin` or `vmw_bo_pin_reserved(bo, false)`), attaching/detaching/unbinding MOB resources (`vmw_resource_mob_attach`, `vmw_resource_mob_detach`, `vmw_resource_unbind_list`), or attaching a dirty tracker (`vmw_bo_dirty_add` and surface `dirty_alloc` in `vmw_kms_fb_create`) requires holding the BO's reservation lock (`ttm_bo_reserve`/`ttm_bo_unreserve` or `vmw_bo_unpin_unlocked`). [F21, F33, F163]
- `dev_priv->resource_lock` protects `dev_priv->res_idr[]` (`res->id`) and `dev_priv->res_lru[]` (`res->lru_head`). In `vmw_resource_alloc_id`, `idr_alloc` under `resource_lock` must use `GFP_NOWAIT` bracketed by `idr_preload(GFP_KERNEL)` and `idr_preload_end()`. When evicting in `vmw_resource_validate` or `vmw_resource_evict_type`, callers must take `vmw_resource_reference` and `list_del_init(&evict_res->lru_head)` before dropping `resource_lock` for `vmw_resource_do_evict`. [F22, F23, F162]
- `dev_priv->binding_mutex` must be held when calling `vmw_view_destroy`, `vmw_view_cotable_list_destroy`, `vmw_view_surface_list_destroy`, `vmw_dx_shader_cotable_list_scrub`, `vmw_dx_streamoutput_cotable_list_scrub`, or `vmw_query_readback_all` (and when mutating `srf_head`, `cotable_head`, `binding_head`, `committed`, or `dx_query_ctx`), but must be released before `vmw_execbuf_fence_commands` in `vmw_query_move_notify`, `vmw_dx_shader_unbind`, and `vmw_dx_streamoutput_unbind`. [F25, F26]
- In `vmw_bo_vm_mkwrite`, `FAULT_FLAG_ALLOW_RETRY` must be masked off `vmf->flags` before calling `ttm_bo_vm_reserve(bo, vmf)` and restored afterward, and `bo->base.resv` must be unlocked via `dma_resv_unlock` on all return paths after `ttm_bo_vm_reserve` succeeds. [F31]
- Lockless access to `mksstat_user_pages[slot]` and `mksstat_kern_pages[slot]` requires winning `atomic_cmpxchg(..., MKSSTAT_PID_RESERVED)` on `mksstat_user_pids[slot]` or `mksstat_kern_pids[slot]`. When adding a slot, populate pages and call `hypervisor_ppn_add` while `MKSSTAT_PID_RESERVED`, then `atomic_set` the pid/pgid. When removing (`vmw_mksstat_remove_ioctl`, `vmw_mksstat_remove_all`), claim with `MKSSTAT_PID_RESERVED`, call `hypervisor_ppn_remove`/`hypervisor_ppn_reset_all`, unpin/free pages, clear `*_pages[slot] = NULL`, and only then `atomic_set` the pid to `0`. [F14, F34, F35, F172, F191]
- Reading or updating `du->gui_x`, `du->gui_y`, `du->pref_width`, `du->pref_height`, or `du->pref_active` in `vmw_du_update_layout` and `vmw_kms_check_topology` requires holding `crtc->mutex` (acquired inside `dev->mode_config.mutex` in `vmw_du_update_layout`). `vmw_kms_close` must call `drm_mode_config_cleanup` without holding `dev->mode_config.mutex` and before `vmw_kms_ldu_close_display`. [F37, F139]

## Object Lifetimes

- Once `vmw_simple_resource_init` or `vmw_gb_shader_init` initializes an embedded `struct vmw_resource`, `res_free` owns the enclosing allocation and runs on init failure, so callers (`vmw_simple_resource_create_ioctl`, `vmw_user_shader_alloc`, `vmw_shader_alloc`) must never call `kfree` directly. `vmw_simple_resource_create_ioctl` and `vmw_user_shader_alloc` must take a second `vmw_resource_reference` (`tmp`) before `ttm_base_object_init`, unreference `tmp` if `ttm_base_object_init` fails, and always unreference `res`. [F1, F2, F144]
- In command-buffer resource creation (`vmw_dx_shader_add`, `vmw_view_add`, `vmw_dx_streamoutput_add`), references to `cotable` and `srf` must be acquired via `vmw_resource_reference` before `vmw_resource_init`, and the local `res` reference must be dropped via `vmw_resource_unreference(&res)` on both success and failure. [F3]
- User-space handle lookups in `vmw_user_resource_lookup_handle` and `vmw_simple_resource_lookup` must acquire a reference on `struct ttm_base_object` via `ttm_base_object_lookup` and increment the embedded resource's refcount via `vmw_resource_reference` before calling `ttm_base_object_unref`. [F166]
- When `switch_guest_memory` is true in `vmw_resource_unreserve`, `res->guest_memory_bo` must be detached, dirty-released (if `res->coherent`), and unreferenced via `vmw_user_bo_unref` when switching to a different BO, and must still call `vmw_bo_dirty_release` when `new_guest_memory_bo == res->guest_memory_bo` and `res->coherent` is true. [F6]
- `vmw_resource_pin` and `vmw_resource_unpin` must hold `dev_priv->cmdbuf_mutex` and bracket their operation with `vmw_resource_reserve` and `vmw_resource_unreserve` (including on `vmw_resource_pin` error), pinning `res->guest_memory_bo` via `vmw_bo_pin_reserved(vbo, true)` only when `res->pin_count` transitions `0 -> 1` and unpinning when `--res->pin_count` reaches `0`. [F7]
- Because `mob->pt_bo` and `batch->otable_bo` are created pinned via `vmw_bo_create_and_populate`, every teardown/rollback path (`vmw_mob_destroy`, `vmw_mob_bind`, `vmw_otable_batch_setup`, `vmw_otable_batch_takedown`) must unpin the BO before `vmw_bo_unreference`. In `vmw_takedown_otable_base` and `vmw_mob_unbind`, `mob->pt_bo->tbo` must be reserved and fenced via `vmw_bo_fence_single(bo, NULL)` after emitting the takedown/destroy command, and `vmw_otable_batch_takedown` must deactivate all enabled OTables before fencing/unpinning `batch->otable_bo`. [F12, F141, F170]
- `vmw_du_plane_duplicate_state` must reset `vps->pinned = 0`, `vps->cpp = 0`, and `vps->cursor.mob = NULL`, and call `vmw_user_object_ref(&vps->uo)`. In `vmw_stdu_primary_plane_prepare_fb`, if `vmw_resource_pin` on `vps->uo`'s surface succeeds, `vps->pinned` must be incremented; if it fails, `vmw_user_object_unref(&vps->uo)` must be called. Framebuffers from `vmw_kms_fb_create` must release `vmw_bo_dirty_add` via `vmw_bo_dirty_release` (and `dirty_free` when `!bo->dirty && surf && surf->res.dirty`) in `vmw_framebuffer_surface_destroy`/`vmw_framebuffer_bo_destroy` before unreferencing the backing object. [F9, F10, F19]
- Under `overlay->mutex`, `vmw_overlay_stop` with `pause == true` must unpin `stream->buf` and set `stream->paused = true` while retaining `stream->buf` and `stream->saved`, whereas `pause == false` unreferences `stream->buf` and sets `stream->paused = false`. In `vmw_overlay_update_stream`, if `vmw_overlay_send_put` fails after `vmw_overlay_move_buffer` pinned `buf`, `buf` must be unpinned with `inter = false`, and on success `stream->buf = vmw_bo_reference(buf)` must only be called when `stream->buf != buf`. [F17, F77, F176]

## API Contracts

- A `struct vmw_framebuffer *vfb` must only be downcast with `vmw_framebuffer_to_vfbd` (or passed to `vmw_kms_readback`, `vmw_kms_sou_readback`, `vmw_kms_stdu_readback`, or `vmw_kms_sou_do_bo_dirty`) when `vfb->bo` is true, and with `vmw_framebuffer_to_vfbs` when `vfb->bo` is false. [F133]
- Callers of `vmw_kms_helper_validation_finish` must pass `file_priv` and `user_fence_rep` as either both NULL or both non-NULL, and `fence`, `handle`, and `ret` must be zero/NULL-initialized before `vmw_execbuf_fence_commands`. [F45, F189]
- `vmw_view_add` and `vmw_view_remove` must validate `(user_key, view_type)` with `vmw_view_id_ok` before `vmw_view_key` or indexing `vmw_view_cotables`; callers of `vmw_shader_key` must validate with `vmw_shader_id_ok` first; and `vmw_shader_define` must cast `size` and `offset` to `u64` before adding (`(u64)buffer->tbo.base.size < (u64)size + (u64)offset`). [F88, F90, F116]
- `vmw_resource_dirty_update`, `vmw_bo_dirty_unmap`, and `vmw_resources_clean` take `start` and `end` as page indices (`pgoff_t`), whereas `vmw_res_func::dirty_range_add` receives byte offsets. In `vmw_prime_handle_to_fd`, handles `> VMWGFX_NUM_MOB` or non-dumb BOs (`!vbo->is_dumb`) with a surface handle from `vmw_lookup_surface_handle_for_buffer` must use `ttm_prime_handle_to_fd`. [F126, F188]

## Error Handling

- In KMS helpers using `struct vmw_validation_context` (`vmw_du_helper_plane_update`, `vmw_kms_sou_do_bo_dirty`, `vmw_kms_sou_readback`), failure of `vmw_validation_prepare` requires `vmw_validation_unref_lists(&val_ctx)`, whereas failure after `vmw_validation_prepare` succeeds requires `vmw_validation_revert(&val_ctx)`. [F11]
- When `VMW_CMD_RESERVE` fails in `vmw_mob_bind`, the error path must decrement `vmw_fifo_resource_dec(dev_priv)` and only unpin/unreference `mob->pt_bo` if `pt_set_up` is true. In `vmw_kms_fb_create`, every branch jumping to `err_out` must set `ret` to a negative errno before jumping. [F13, F42]
- In `vmw_mksstat_add_ioctl`, `nr_pinned_stat`, `nr_pinned_info`, and `nr_pinned_strs` from `pin_user_pages_fast(..., FOLL_LONGTERM, ...)` must be stored in signed `long` variables; on any partial pin or negative error, all positive `nr_pinned_*` slices must be unpinned in reverse order via `unpin_user_pages`, `mksstat_user_pids[slot]` reset to `0`, and `page` and `pages_stat` freed (never `kfree(pages_info)` or `kfree(pages_strs)`). [F15, F61, F130]
- Return conventions: `vmw_user_object_buffer` can return `NULL` on surface-backed objects (`guest_memory_bo == NULL`); `vmw_query_move_notify` can receive `old_mem == NULL`; `vmw_crtc_state_and_lock` can return both `ERR_PTR` and `NULL`; `drm_atomic_get_connector_state` and `vmw_shader_lookup`/`vmw_view_lookup`/`vmw_dx_streamoutput_lookup`/`vmw_simple_resource_lookup` return `ERR_PTR` (check `IS_ERR`); `vmw_recv_msg` frees/nulls `reply` on error/retry and can return `0` with `*msg == NULL`; and `vmw_mksstat_get_kern_slot` returns negative errno on failure (check `slot >= 0`). [F16, F41, F43, F44, F52, F56, F58, F59]

## Known Pitfalls

- When enabling `VMW_BO_DIRTY_MKWRITE` in `vmw_bo_dirty_scan_pagetable` or `vmw_bo_dirty_add`, or before unmapping PTEs in `vmw_bo_dirty_pre_unmap`, `wp_shared_mapping_range` must be called before `clean_record_shared_mapping_range` so hardware dirty bits set prior to write-protection are harvested into `dirty->bitmap`. [F64]
- In `vmw_stdu_primary_plane_prepare_fb`, when `new_content_type != SAME_AS_DISPLAY`, `metadata.base_size` must be assigned after `metadata = vmw_user_object_surface(&new_vfbs->uo)->metadata` so the struct copy does not clobber CRTC dimensions; when `vps->uo.buffer->is_dumb`, `!res->res_dirty`, and `drm_atomic_helper_damage_merged` reports damage, `vmw_resource_dirty_update` must be called explicitly. In `vmw_stdu_bo_cpu_commit`, `src_offset` uses display coordinates and `src_pitch` while `dst_offset` uses `fb_top`/`fb_left` and `dst_pitch`. [F73, F102, F187]
- `struct vmw_shader` and `struct vmw_dx_shader` both have `res_type == vmw_res_shader`, so `vmw_res_to_shader` and `vmw_res_to_dx_shader` must only be used on `vmw_gb_shader_func` and `vmw_dx_shader_func` resources respectively. `vmw_dx_shader_add` must pass `shader_type = 0` to `vmw_shader_key` after `vmw_shader_id_ok`. `vmw_view_cmd_to_type` must check non-contiguous command IDs before computing unsigned `u32 tmp = (id - SVGA_3D_CMD_DX_DEFINE_SHADERRESOURCE_VIEW) / 2`. [F89, F103, F118, F134]
- In `vmw_ldu_commit_list`, do not dereference the `list_for_each_entry` cursor `entry` after the loop exits without breaking (use the saved `crtc` pointer); COTable/surface scrub functions must use `list_for_each_entry_safe`; and in `vmw_resources_clean`, the initial RB-tree lookup on `vbo->res_tree` must record `found = cur_res` and continue `cur = cur->rb_left` rather than breaking early. [F101, F104, F105]
- In `vmw_kms_check_display_memory`, cast `drm_rect_width`, `drm_rect_height`, and `bounding_box.x2` to `u64` before multiplying; in `vmw_bo_dirty_unmap`, cast `(end - start)` to `loff_t` before `<< PAGE_SHIFT`; and when converting a resource's end byte offset `res->guest_memory_offset + res->guest_memory_size` to a page index (`vmw_bo_dirty_transfer_to_res`, `vmw_resource_do_validate`), use ceiling division (`DIV_ROUND_UP` or `__KERNEL_DIV_ROUND_UP`). [F110, F112, F121]
