# INTEL PMT DRIVERS

The Intel Platform Monitoring Technology (PMT) drivers provide a unified device class (`intel_pmt`) and auxiliary bus drivers (`intel_vsec.telemetry`, `intel_vsec.crashlog`, and `intel_vsec.discovery`) to discover and access hardware telemetry, crashlog, and feature capability tables exposed via Intel Vendor-Specific Extended Capabilities (VSEC) over PCIe MMIO. They expose data regions to userspace via sysfs binary files (`read` and `mmap`) and control attributes, and provide in-kernel APIs to query PMT features and read telemetry endpoints.

## Architecture & Data Flow
- `struct intel_pmt_entry.ep` is only populated when `ns->pmt_add_endpoint` is non-NULL and `entry->size > 0`. Shared helpers (like `intel_pmt_read()` in `class.c`) must use `entry->pcidev`, `entry->cb`, and `entry->base` rather than dereferencing `entry->ep`, and `pmt_telem_header_decode()` must reject `header->size == 0` with `1` because `pmt_telem_probe()`, `intel_pmt_get_features()`, and `pmt_telem_remove()` unconditionally dereference `entry->ep`. [F21, F63]
- `struct intel_pmt_entry` must remain the first member of `struct crashlog_entry`: `intel_pmt_dev_register()` sets `dev` driver data to `entry`, which crashlog sysfs handlers cast to `struct crashlog_entry *` and class sysfs handlers (`guid_show`, etc.) cast to `struct intel_pmt_entry *`. [F105]
- Every `intel_pmt_class` device must use `&ivdev->auxdev.dev` as its `device_create()` parent, and unless `ivdev->cap_id == ilog2(VSEC_CAP_DISCOVERY)`, its driver data must be a `struct intel_pmt_entry *` (cast unconditionally by `intel_pmt_attr_visible()` and `guid`/`size`/`offset` attributes). In `pmt_features_probe()`, `priv->parent` must separately be `&ivdev->pcidev->dev` for PCI device matching against `&entry->ep->pcidev->dev` in `intel_pmt_get_features()`. [F70, F106]
- In `pmt_features_discovery()`, each `feature_layout[feature->id]` branch must set `feature->attr_group` to the exact `struct attribute_group` in the `default_groups` of the `ktype` passed to `kobject_init_and_add()`, so `pmt_features_remove()` removes the right group via `sysfs_remove_group(&feature->kobj, feature->attr_group)`. [F43]
- Because `struct feature_table` places `command`, `watcher`, and `rmid` in a union at layout-dependent offsets, callers must use `get_watcher()` and `get_command()` and verify `feature_layout[f->id] == LAYOUT_RMID` before reading `rmid.num_rmids`. [F67]
- In `pmt_feature_get_feature_table()`, validate that `sizeof(*header) + FEAT_ATTR_SIZE(header->attr_size) + PMT_GUID_SIZE(header->num_guids)` does not exceed `resource_size(&res)` (`disc_tbl->size * sizeof(u32)`) before reading attributes or allocating `guids`. [F49]
- In `pmt_feature_get_disc_table()`, `priv->mask & BIT(disc_tbl->id)` must reject duplicate active feature IDs with `-EINVAL` before `kobject_init_and_add()` registers `pmt_feature_names[feature->id]`, and `priv->mask |= BIT(disc_tbl->id)` must only be set after all `SKIP_FEATURE` checks pass. [F46]
- In `intel_pmt_populate_entry()`, under `ACCESS_LOCAL` with `intel_pmt_is_early_client_hw(dev)`, reset `entry->base_addr = 0` before the PCI BAR `0..5` loop so `!entry->base_addr` detects when no BAR contains `disc_res->start` rather than keeping `disc_res->end + 1 + header->base_offset`. [F71]

## Synchronization
- `ep_lock` must be held across `intel_pmt_dev_create()` in `pmt_telem_probe()`, across `kref_put()` and `intel_pmt_dev_destroy()` in `pmt_telem_remove()`, and across every lookup or traversal of `telem_array` in `telemetry.c`. `pmt_telem_register_endpoint()` must call `kref_get(&entry->ep->kref)` before unlocking `ep_lock`. [F10, F11]
- Sysfs callbacks on `intel_pmt` devices (`intel_pmt_read`, `intel_pmt_mmap`, `guid_show`, `size_show`, `offset_show`) must never acquire `ep_lock`, because `pmt_telem_remove()` holds `ep_lock` while `intel_pmt_dev_destroy()` removes sysfs files and unregisters the device. [F98]
- In `intel_pmt_get_regions_by_feature()`, both `xa_for_each(&telem_array, ...)` passes (counting and population) must run within the same `ep_lock` critical section using the identical filter predicate (`entry->feature_flags & BIT(id)`). [F66]
- All crashlog control-register updates must go through `pmt_crashlog_rmw()` while holding `crashlog->control_mutex` (along with any preceding `pmt_crashlog_disabled()` / `pmt_crashlog_complete()` checks in `clear_store`, `consumed_store`, `enable_store`, `rearm_store`, and `trigger_store`). All bit fields in `struct crashlog_status` and `struct crashlog_control` (after `offset`) are pre-shifted bitmasks (`BIT()`/`GENMASK()`), and `pmt_crashlog_rmw()` must mask off `control->trigger_mask` from the read value before modifying `@bit` so old trigger bits are not re-issued. [F40, F99, F111]

## Object Lifetimes
- In `pmt_telem_add_endpoint()`, `entry->ep` (`struct telem_endpoint`) must be allocated with `kzalloc()` and freed only via `kref_put(&ep->kref, pmt_telem_ep_release)`—never `devm_kzalloc()` or direct `kfree()` in `pmt_telem_remove()`—because consumers may hold references after device removal. [F2]
- `intel_pmt_dev_register()` sets up `xa_alloc()`, `device_create()`, optional `sysfs_create_group()`, and (when `entry->size > 0`) `devm_ioremap_resource()`, `sysfs_create_bin_file()`, and optional `ns->pmt_add_endpoint()`. Both its `fail_*` labels and `intel_pmt_dev_destroy()` must unwind these in strict reverse order, and `intel_pmt_dev_destroy()` must guard `sysfs_remove_bin_file()` with `if (entry->size)` and `sysfs_remove_group()` with `if (entry->attr_grp)`. [F4, F25]
- `entry->disc_table` is mapped via `devm_ioremap_resource()` on the parent auxiliary device in `intel_pmt_dev_create()`, whereas `entry->base` is mapped on the child `intel_pmt_class` `dev` in `intel_pmt_dev_register()` so it is automatically unmapped when `intel_pmt_dev_destroy()` calls `device_unregister(dev)` (or if registration fails later). [F9]
- All insertions, removals, and traversals of `pmt_feature_list` (`pmt_features_add_feat`, `pmt_features_remove_feat`, `intel_pmt_get_features`) must hold `feature_list_lock`. In `pmt_features_remove()`, each initialized `struct feature` must be unlinked via `pmt_features_remove_feat()`, have `feature->attr_group` removed, and call `kobject_put(&feature->kobj)` before `device_unregister(priv->dev)` frees `devm_kmalloc(priv->dev, ...)` allocations like `feature->table.guids`. [F8, F100]
- `pmt_crashlog_header_decode()` must initialize `crashlog->control_mutex`, `crashlog->info`, and `entry->attr_grp` before `intel_pmt_dev_register()` exposes sysfs attributes, and `pmt_crashlog_remove()` must call `intel_pmt_dev_destroy()` before `mutex_destroy(&crashlog->control_mutex)`. [F86]
- `intel_pmt_get_features(entry)` must only be called after `intel_pmt_dev_create()` returns `0` on a telemetry entry (where `pmt_telem_add_endpoint()` populated `entry->ep`), never when `intel_pmt_dev_create()` returns `1` or on `pmt_crashlog_ns`. [F88]

## API Contracts
- `pmt_telem_register_endpoint()`, `pmt_telem_find_and_register_endpoint()`, and `intel_pmt_get_regions_by_feature()` always return an `ERR_PTR` (never `NULL`) on failure; callers must check `IS_ERR()`. On success, endpoint callers receive a `kref`-incremented `struct telem_endpoint *` that must be released with `pmt_telem_unregister_endpoint()`, including after `pmt_telem_read()` or `pmt_telem_read32()` returns `-ENODEV`. [F1, F20]
- `intel_pmt_get_regions_by_feature()` must initialize `feature_group` (`__free(kfree)`) to `NULL` before any early `ERR_PTR` return, use `guard(mutex)(&ep_lock)`, and transfer ownership of the `kref`-counted `struct pmt_feature_group *` via `no_free_ptr(feature_group)` on success; callers must release it with `intel_pmt_put_feature_group()`. [F3, F27]
- `pmt_telem_read()` and `pmt_telem_read32()` take `id` as a 0-based sample index and `count` in 8-byte qwords (`SAMPLE_ID_OFFSET`, `NUM_BYTES_QWORD`) or 4-byte dwords (`SAMPLE_ID_OFFSET32`, `NUM_BYTES_DWORD`), whereas `ep->header.size` and `pmt_telem_read_mmio()`'s `off` and `count` are in bytes. [F30]
- `PMT_XA_START` must remain `>= 1` so `xa_alloc()` in `intel_pmt_dev_register()` never allocates `devid == 0`. `pmt_telem_get_next_endpoint()` and `pmt_telem_find_and_register_endpoint()` reserve `0` as both the initial cursor (`start = 0` to include `devid == 1`) and the end-of-iteration sentinel. [F31, F45]
- `intel_pmt_is_early_client_hw(struct device *dev)` unconditionally applies `dev_to_ivdev(dev)`, so callers must pass `&ivdev->auxdev.dev`, never `&pcidev->dev` or the `intel_pmt_class` child `dev`. [F91]

## Error Handling
- `pmt_telem_probe()`, `pmt_crashlog_probe()`, and `pmt_features_probe()` must index their entry arrays by `priv->num_entries` (or `priv->count`) rather than loop index `i`, incrementing the counter only after registration succeeds (`ret == 0`), so `.remove` on `abort_probe` only tears down initialized entries. [F26]
- For reserved, zero-size, or unsupported hardware discovery entries, `pmt_crashlog_header_decode()`, `pmt_telem_header_decode()`, and `pmt_feature_get_disc_table()` must return positive `1` (`SKIP_FEATURE`) rather than a negative errno so `.probe` skips the entry without aborting the whole device. [F112]

## External Contracts
- In `crashlog.c`, `clear_store()`, `consumed_store()`, and `rearm_store()` are set-only and must return `-EINVAL` when given `false`, whereas `enable_store()` inverts `enabled` when calling `pmt_crashlog_set_disable()`. In `trigger_store()`, `!trigger` must call `pmt_crashlog_set_clear(crashlog)` and return before the `pmt_crashlog_complete(crashlog)` check (which returns `-EEXIST` when true); conversely, `consumed_store()` requires `pmt_crashlog_complete(crashlog)` to be true (returning `-EEXIST` when false). [F69, F110]
- `intel_pmt_mmap()` must reject `VM_WRITE | VM_MAYWRITE` with `-EROFS`, validate `vsize` against the page-rounded span `(PFN_UP(entry->base_addr + entry->size) - PFN_DOWN(entry->base_addr)) * PAGE_SIZE` (accounting for sub-page `base_addr` offsets), and map with `pgprot_noncached(vma->vm_page_prot)` via `io_remap_pfn_range()`. [F103]

## Known Pitfalls
- Discovery `base_offset` / `offset` fields pack a 3-bit BAR index (`GET_BIR` / `DT_TBIR`, `GENMASK(2, 0)`) in the low bits of an 8-byte-aligned byte offset: `ACCESS_LOCAL` must reject any non-zero BAR index with `-EINVAL`, and `ACCESS_BARID` must mask bits `31:3` in place via `GET_ADDRESS(v)` (`(v) & GENMASK(31, 3)`). Never replace `GET_ADDRESS(v)` with `FIELD_GET(GENMASK(31, 3), v)` or `(v) >> 3`, which divides the byte offset by 8. [F55, F72]
- In `pmt_telem_header_decode()`, `TELEM_SIZE(v)` (`((v) & GENMASK(27, 12)) >> 10`) extracts the DWORD count from bits `27:12` and multiplies by 4 (`>> 12` combined with `<< 2`); replacing it with `FIELD_GET(GENMASK(27, 12), v)` without `* sizeof(u32)` breaks the byte size. [F73]
- In `struct feature_table`, `header`, `caps`, and the union of `command`, `watcher`, and `rmid` must remain contiguous 32-bit hardware-layout fields before `guids`, and `pmt_feature_get_feature_table()` must assign `feat_tbl->guids` only after `memcpy_fromio(tbl_offset, feat_offset, FEAT_ATTR_SIZE(header->attr_size))`. [F44]
- `enum pmt_feature_id` is 1-based and sparse (`FEATURE_INVALID = 0x0` and `FEATURE_RESERVED = 0x9` are unpopulated): always validate `id` with `pmt_feature_id_is_valid(id)` before shifting `BIT(id)` or indexing `pmt_feature_names[]` or `feature_layout[]`. Every valid `pmt_feature_id` must have entries in `pmt_feature_names[]`, `feature_layout[]`, and `caps_show()`, and `pmt_caps_*` arrays must be NULL-terminated with `{}`-terminated inner `struct pmt_cap` arrays. [F50, F113]
