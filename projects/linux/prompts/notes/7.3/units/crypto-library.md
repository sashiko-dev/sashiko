# CRYPTO LIBRARY

Core kernel cryptographic library implementations for message digests and HMACs (MD5, SHA-1, SHA-224/256, SHA-384/512, SM3), the Poly1305 authenticator, Multi-Precision Integer (MPI) arithmetic and coders, constant-time memory utilities (`__crypto_memneq`, `__crypto_xor`), and architecture-specific dispatch headers for MIPS, PowerPC, RISC-V, s390, and SPARC.

## Architecture & Data Flow
- `mpi_size_t` must remain a signed integer type because MPI reverse loops (`MPN_COPY_DECR`, `mpihelp_cmp`, `mpihelp_lshift`, `mpihelp_divrem`, `mpi_powm`) terminate on `< 0` and low-level limb loops (`mpihelp_add_n`, `mpihelp_sub_n`, `mpihelp_mul_1`, `mpihelp_addmul_1`, `mpihelp_submul_1`) index from `j = -size` up to `-1`. [F56]
- In `mpihelp_mul_karatsuba_case`, `ctx->tspace` and `ctx->tp` must each be allocated to `2 * vsize` limbs via `mpi_alloc_limb_space(2 * vsize)` while recording `ctx->tspace_size = vsize` and `ctx->tp_size = vsize`, because recursive `mul_n` and `mpihelp_mul` calls write up to `2 * vsize` limbs into those scratch buffers. [F99]
- In `mpi_read_raw_data` and `mpi_read_raw_from_sgl`, decoding a big-endian byte stream into little-endian `val->d[0 .. nlimbs - 1]` must compute limb counts with `DIV_ROUND_UP(nbytes, BYTES_PER_MPI_LIMB)` (and `DIV_ROUND_UP(nbits, 8)` in `mpi_read_from_buffer`) and pre-offset the initial byte position by `(BYTES_PER_MPI_LIMB - nbytes % BYTES_PER_MPI_LIMB) % BYTES_PER_MPI_LIMB` so the partial high limb `val->d[nlimbs - 1]` is populated first. [F55, F93]
- In `__hmac_*_preparekey` (`md5`, `sha1`, `sha256`, `sha512`), the local `derived_key` union must be zero-initialized (`= { 0 }`) before copying or hashing `raw_key` into `derived_key.b` and cleared with `memzero_explicit` before returning. HMAC context initializers (`hmac_*_init*`) must set the inner hash `bytecount` (or `bytecount_lo` with `bytecount_hi = 0`) to the hash block size, not `0`. [F35, F48]
- `hmac_sha1_final`, `__hmac_sha256_final`, and `__hmac_sha512_final` write only a 32-bit big-endian bit length at `ctx->sha_ctx.buf[BLOCK_SIZE - 4]` and rely on the preceding `memset(&ctx->sha_ctx.buf[digest_size], 0, BLOCK_SIZE - digest_size)` to zero the upper bytes of the 64-bit or 128-bit length field. [F64]
- In `__sha512_update`, `partial = ctx->bytecount_lo % SHA512_BLOCK_SIZE` must be computed before adding `len` to `ctx->bytecount_lo`, and overflow of `ctx->bytecount_lo += len` must increment `ctx->bytecount_hi` via `check_add_overflow`. After appending `0x80` at `ctx->buf[partial++]`, `__md5_final`, `__sha1_final`, and `__sha256_final` must flush and zero-pad an extra block when `partial > BLOCK_SIZE - 8` (and `__sha512_final` when `partial > SHA512_BLOCK_SIZE - 16`). [F49, F63]
- Architecture-specific hash and Poly1305 `*_blocks` functions that fall back to `*_blocks_generic` when `!may_use_simd()` must use the exact same in-memory state layout as the generic path so incremental updates can mix task and interrupt contexts. [F118]
- In `poly1305_core_emit` (`poly1305-donna32.c` and `poly1305-donna64.c`), constant-time selection between `h` and `h + -p` relies on subtracting `1UL << 26` (in `g4`) or `1ULL << 42` (in `g2`) and deriving the mask as `(g >> (width - 1)) - 1` using an unsigned right shift. [F96]
- When `!IS_ENABLED(CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS)`, `__crypto_xor` must compute the shared relative alignment `relalign` of `dst`, `src1`, and `src2`, advance byte-by-byte until `(unsigned long)dst & (relalign - 1)` is zero, and gate direct `u64`/`u32`/`u16` dereferences on `!(relalign & 7)`, `!(relalign & 3)`, and `!(relalign & 1)`. [F70]
- In `mpi_copy`, the immutable and constant flags (`16 | 32`) must be cleared on the new copy's `flags` field (`b->flags &= ~(16|32)`). [F45]

## Synchronization
- In PowerPC (`chacha.h`, `poly1305.h`, `sha1.h`, `sha256.h`) and RISC-V (`chacha.h`, `sha256.h`, `sha512.h`) arch helpers, every vector or SPE assembly call must be bracketed by `vsx_begin`/`vsx_end`, `spe_begin`/`spe_end` (with `preempt_disable()` before `enable_kernel_*()` and `disable_kernel_*()` before `preempt_enable()`, chunking by `SZ_4K` or `MAX_BYTES` in PowerPC ChaCha and SPE SHA), or `kernel_vector_begin`/`kernel_vector_end` (after checking both the extension static key and `crypto_simd_usable()` / `may_use_simd()`). [F15, F122, F123]

## Object Lifetimes
- `mpi_get_buffer` must allocate at least 1 byte (`if (!n) n++;`) when `mpi_get_size(a)` is 0 so `kmalloc` returns a valid pointer with `*nbytes == 0`, transfers ownership of `buf` to the caller on success, and frees `buf` via `kfree` if `mpi_read_buffer` fails. Broken by: error paths not freeing `buf`, or callers omitting `kfree` when `*nbytes == 0`. [F1, F105]
- In `mpi_mul` and `mpi_powm`, the destination limb buffer (`wp` or `rp`) must never alias any input limb buffer (`up`, `vp`, `bp`, `ep`, `mp`): when `w->alloced < wsize` and `w->d` aliases an input, allocate a new destination buffer with `assign_wp = 1`, free it via `mpi_free_limb_space` on failure, or install it afterward via `mpi_assign_limb_space`; otherwise copy the aliased input to temporary limb space. [F3, F39]
- In `mpi_powm`, temporary limb allocations for `mp`, `bp`, `ep`, and `xp` must be recorded in and freed via dedicated marker pointers (`mp_marker`, `bp_marker`, `ep_marker`, `xp_marker`) because `rp` and `xp` are swapped (`swap(rp, xp)`), and after the loop `rp` must be copied or shifted into `res->d` (and `rp` reset to `res->d`) before final normalization. [F4, F81]
- In `mpi_tdiv_qr`, every temporary limb buffer allocated for aliased or normalized operands must be pushed onto `marker[markidx++]` and freed in reverse (LIFO) order at `out_free_marker:` across both normal completion and `-ENOMEM` exits. [F8]
- In `mpi_read_raw_from_sgl`, the `SG_MITER_ATOMIC` iterator must be stopped with `sg_miter_stop(&miter)` on the `nbits > MAX_EXTERN_MPI_BITS` error path and before calling `mpi_alloc(nlimbs)` (which uses `GFP_KERNEL` and may return early on `!val` or `nbytes == 0`). [F7]
- In `lib/crypto/mips/*.h`, `md5_blocks`, `sha1_blocks`, `sha256_blocks`, and `sha512_blocks` must check `octeon_has_crypto()`, enclose all COP2 register accesses between `flags = octeon_crypto_enable(&cop2_state)` and `octeon_crypto_disable(&cop2_state, flags)`, and write initial block dwords (`0..6` or `0..14`) with `write_octeon_64bit_block_*` before writing the final dword (`block[7]` or `block[15]`) with `octeon_*_start()`. [F113, F116]

## API Contracts
- Unlike `mpi_alloc`, `mpi_copy`, `mpi_read_raw_data`, and `mpi_read_raw_from_sgl` which return `NULL` on failure, `mpi_read_from_buffer` returns an `ERR_PTR` (`-EINVAL` or `-ENOMEM`) and never `NULL`. `*ret_nread` is an in-out byte count updated to `nbytes + 2` only on success; `mpi_read_from_buffer` must check `*ret_nread >= 2` before reading `nbits`, and check `nbits <= MAX_EXTERN_MPI_BITS` and `DIV_ROUND_UP(nbits, 8) + 2 <= *ret_nread` before `mpi_read_raw_data`. `mpi_read_raw_data` and `mpi_read_raw_from_sgl` must strip leading zero bytes before checking `MAX_EXTERN_MPI_BITS` and allocating limbs. [F18, F25, F51, F52]
- `mpi_tdiv_qr` accepts a `NULL` `quot` (used by `mpi_tdiv_r`): every `quot` access must be guarded by `if (quot)`, and when `!quot && dsize > 1`, `rem` must be sized to `nsize + 1` limbs for `qp = rp + dsize`. In `mpi_read_buffer`, `mpi_get_buffer`, and `mpi_write_to_sgl`, `sign` is optional and must be guarded by `if (sign)`. [F22, F23]
- Callers of `mpihelp_add`/`mpihelp_sub` must ensure `s1_size >= s2_size`; callers of `mpihelp_mul` and `mpihelp_mul_karatsuba_case` must ensure `usize >= vsize` and `prodp` disjoint from `up`/`vp`; callers of `mpihelp_add_n`, `mpihelp_sub_n`, `mpihelp_mul_1`, `mpihelp_addmul_1`, and `mpihelp_submul_1` must ensure limb count `>= 1`. [F30, F57]
- Callers of `mpihelp_lshift` and `mpihelp_rshift` must ensure `0 < cnt < BITS_PER_MPI_LIMB` and `usize > 0` (`mpi_rshift` must fall back to a copy when `nbits == 0`), with `wp >= up` for in-place `mpihelp_lshift` and `wp <= up` for in-place `mpihelp_rshift`. Callers of `mpihelp_divrem` must ensure `nsize >= dsize >= 1`, MSB of `dp[dsize - 1]` set, and `qp` disjoint or `qp + dsize >= np`; callers of `udiv_qrnnd` must ensure `nh < d`. [F60, F74, F90, F100, F101, F128]
- MPI allocation, resizing, coding, and arithmetic functions (`mpi_alloc`, `mpi_resize`, `mpi_get_buffer`, `mpi_read_raw_*`, `mpi_add*`, `mpi_sub*`, `mpi_mul*`, `mpi_tdiv_qr`, `mpi_powm`, `mpi_set_bit`, `mpi_rshift`) use `GFP_KERNEL` or `cond_resched()` and require sleepable process context. [F119]
- Internal finalizers (`__md5_final`, `__sha1_final`, `__sha256_final`, `__sha512_final`) must finish reading `ctx->buf` before writing to `out` (as `hmac_*_final` passes `ctx->*ctx.buf` as `out`) and must not zeroize `*ctx`, whereas public `*_final` functions must zeroize the entire context before returning. [F50]
- `poly1305_blocks` takes `len` in bytes and `poly1305_emit` takes `(state, digest, nonce)`, whereas `poly1305_core_blocks` takes `nblocks` in 16-byte blocks and `poly1305_core_emit` / `poly1305_emit_64` takes `(state, nonce, dst)`. Both block functions take `padbit`/`hibit` as an unshifted `1` for full blocks in `poly1305_update` and `0` in `poly1305_final` for a `0x01`-padded partial block. [F32, F67, F130]
- Arch ChaCha wrappers must only pass valid block lengths to assembly and update `state->x[12]` or tail bytes: PowerPC `chacha_p10le_8x` requires 256-byte multiples; RISC-V `chacha_zvkb(state, in, out, nblocks, nrounds)` takes `in` before `out` and 64-byte block counts; s390 `chacha20_vx` requires `kernel_fpu_begin(&vxstate, KERNEL_VXR)`/`kernel_fpu_end`, `bytes > CHACHA_BLOCK_SIZE`, `nrounds == 20`, and `cpu_has_vx()`, then adds `round_up(bytes, CHACHA_BLOCK_SIZE) / CHACHA_BLOCK_SIZE` to `state->x[12]`. [F69, F108, F124]
- Arch init functions must check all prerequisites before enabling static keys: SPARC (`HWCAP_SPARC_CRYPTO` before reading `%asr26`, then `CFR_*`); RISC-V (`riscv_vector_vlen() >= 128` and `riscv_isa_extension_available`); s390 (`S390_CPU_FEATURE_MSA` and `cpacf_query_func`). In `lib/crypto/sha256.c`, the arch `"sha256.h"` include and all `sha256_finup_2x*` and `hmac_sha2*` code must remain under `#ifndef __DISABLE_EXPORTS`, and `sha256_finup_2x()` must substitute `&initial_sha256_ctx` when `!ctx` without mutating `*ctx`. [F110, F111, F112, F129, F134]

## Error Handling
- MPI functions that allocate or resize limb space (`mpi_resize`, `RESIZE_IF_NEEDED`, `mpi_copy`, `mpi_alloc_limb_space`, `mpihelp_mul`) must check for failure and propagate `-ENOMEM`; in `mpi_mul`, `err` must be initialized to `0` at declaration because fast paths bypass `mpi_resize` and `mpihelp_mul`. [F19, F20]
- In `mpihelp_mul_karatsuba_case`, reallocating `ctx->tspace` or `ctx->tp` must free the old buffer first, and if allocating `ctx->tp` fails, `ctx->tspace` must be freed and set to `NULL` so `mpihelp_release_karatsuba_ctx` does not double-free it. [F44]
- `mpi_write_to_sgl` and `mpi_read_raw_from_sgl` must check `sg_nents_for_len(sgl, nbytes) < 0` before calling `sg_miter_start`; in `mpi_read_buffer`, when `buf_len < n - lzeros`, it must still write `*nbytes = n - lzeros` (and `*sign = a->sign` if `sign`) before returning `-EOVERFLOW`. [F53, F136]
- In `mpi_powm`, `bsize` must be checked for zero *after* the `if (bsize > msize)` modular reduction (which normalizes `bp`) and before the exponentiation loop so a base that is a multiple of `mod` exits early with `res->nlimbs = 0`. [F75]

## Known Pitfalls
- In `mpi_add` and `mpi_tdiv_qr`, limb pointers (`u->d`, `v->d`, `w->d`, `num->d`, `den->d`, `rem->d`, `quot->d`) must be loaded only *after* all `RESIZE_IF_NEEDED` and `mpi_resize` calls complete, because resizing the destination frees and replaces its `->d` array when an input aliases the destination. [F37]
- In `mpi_mul`, when `w->alloced >= wsize` and `wp == up`, allocating temporary storage `up = tmp_limb = mpi_alloc_limb_space(usize)` must also check `if (wp == vp)` and update `vp = up` before `MPN_COPY(up, wp, usize)` so `mpi_mul(w, w, w)` does not leave `vp` aliasing `wp`. [F84]
- In `mpi_tdiv_qr`, when `qsize <= 0`, copying `num` to `rem` must precede zeroing `quot->nlimbs = 0` and `quot->sign = 0` because `quot` may alias `num`; in multi-limb division, `np` must be copied to temporary limb space when `quot && qp == np`, and `dp` must be copied when `normalization_steps != 0` or `dp == rp || (quot && dp == qp)`. In `mpi_fdiv_r`, `divisor->sign` must be sampled and `divisor` cloned with `mpi_copy` when `rem == divisor` before calling `mpi_tdiv_r`. [F40, F41, F85]
- Unlike `mpi_read_buffer` (which strips `count_lzeros(a)` leading zero bytes), `mpi_write_to_sgl` requires `nbytes >= mpi_get_size(a)` (full `a->nlimbs * BYTES_PER_MPI_LIMB` bytes) or returns `-EOVERFLOW`. In `mpi_read_raw_data` and `mpi_read_buffer`, the intra-limb byte offset (`i` or `lzeros`) must be reset to `0` after the first outer loop iteration, and `mpi_read_raw_data` / `mpi_read_raw_from_sgl` must subtract `(BITS_PER_LONG - 8)` from `count_leading_zeros(...)` on the MSB `u8`. [F54, F80, F94]
- In `mpi_set_bit`, extending `a->nlimbs` to `limbno + 1` must zero already-allocated limbs `a->d[a->nlimbs .. a->alloced - 1]` before calling `mpi_resize(a, limbno + 1)`, and both `mpi_test_bit` and `mpi_set_bit` must shift `A_LIMB_1` (`(mpi_limb_t)1`), not `1` or `1U`. [F89, F103]
- In `mpihelp_add_1` and `mpihelp_sub_1`, `s1_ptr` and `res_ptr` are post-incremented before `--s1_size`, so at `leave:` the uncopied tail is `s1_size - 1` limbs; in `mpihelp_cmp`, differing unsigned limbs must be compared via `(op1_word > op2_word) ? 1 : -1`, not subtraction; in `mpihelp_mod_1` and `mpihelp_divmod_1`, `!(divisor_limb << 1)` must set `divisor_limb_inverted = ~(mpi_limb_t)0` instead of calling `udiv_qrnnd`. [F77, F92, F95]
- In `poly1305-donna32.c`, 32-bit limbs `h0..h4` must be cast to `u64` before multiplying by `r0..r4`/`s1..s4` or adding `nonce[0..3]`; in `poly1305-donna64.c`, `u32 hibit` and `nonce[1]`/`nonce[3]` must be cast to `u64` before shifting (`((u64)hibit) << 40`, `(u64)nonce[1] << 32`) and 44-bit `u64` limbs widened to `u128` before multiplication. [F86, F87]
- In `lib/crypto/memneq.c`, every XOR accumulation into `neq` must be followed by `OPTIMIZER_HIDE_VAR(neq)`. In `lib/crypto/mips/sha1.h`, `state->h[4]` must be transferred via the 64-bit `hash_tail` union rather than `((u64 *)state->h)[2]`; in `lib/crypto/powerpc/curve25519.h`, `fe51_frombytes` must stage input through an 8-byte-aligned buffer (`PTR_ALIGN((void *)sbuf, 8)`) before `x25519_fe51_frombytes`. [F106, F109, F127]
