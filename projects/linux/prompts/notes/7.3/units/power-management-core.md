# POWER MANAGEMENT CORE

This unit comprises the power capping (`powercap`) subsystem core, the CPU idle injection framework (`idle_inject`), the Intel/AMD Running Average Power Limit (`intel_rapl`) common core and its MSR and TPMI hardware interface drivers, and core kernel headers for runtime PM (`pm_runtime.h`), PM QoS (`pm_qos.h`), wakeup sources (`pm_wakeup.h`), wake IRQs (`pm_wakeirq.h`), and PM clocks (`pm_clock.h`).

## Architecture & Data Flow

- In `intel_rapl_common.c`, `rp->lead_cpu` is `-1` when a package is added with `id_is_cpu == false`, so `get_rid()`, `rapl_init_domains()`, `package_power_limit_irq_save()`, and `package_power_limit_irq_restore()` must check `rp->lead_cpu >= 0` first. In `rapl_cpu_down_prep()`, when clearing `cpu` from `rp->cpumask` leaves it empty (`lead_cpu >= nr_cpu_ids`), `rapl_remove_package_cpuslocked(rp)` must be called before invalidating `rp->lead_cpu`; if online CPUs remain and `rp->lead_cpu == cpu`, `rp->lead_cpu` must be updated to `lead_cpu`. [F33, F52]
- `rp->domains` is a dense array of length `rp->nr_domains` for active domains in `rp->domain_map`. In `rapl_pmu_event_init()`, `event->attr.config & RAPL_EVENT_MASK` (`GENMASK(7, 0)`) is validated against `1 <= cfg < PERF_RAPL_MAX` and `event->cpu >= 0` before indexing `event_to_domain[cfg]`, leaving `event->hw.idx == -1` if the package lacks that domain; PMU callbacks (`event_read_counter()`, `rapl_event_update()`) must check `event->hw.idx >= 0` and index `rp->domains` by `event->hw.idx`, not `enum rapl_domain_type` (`event->hw.flags`). [F73, F155]
- In `intel_rapl_common.c`, powercap `constraint_ops` callbacks receive a dense constraint index `cid` (`0` to `find_nr_power_limit(rd) - 1`) and must translate `cid` via `contraint_to_pl(rd, cid)` before indexing `rd->rpl[]` or calling `rapl_read_pl_data()` / `rapl_write_pl_data()`. [F54]
- `rapl_read_data_raw()` and `rapl_write_data_raw()` must map `prim` via `prim_fixups(rd, prim)` before `get_rpi()`, which must reject `prim < 0 || prim >= NR_RAPL_PRIMITIVES` before indexing `rp->priv->rpi`; `write_raw` callbacks (`rapl_msr_update_func`, `tpmi_rapl_write_raw`) must do a masked read-modify-write (`val = (val & ~ra->mask) | ra->value`) to preserve sibling fields in shared registers. [F61, F68]
- `rapl_detect_powerlimit()` must probe power limit presence using `PL_LIMIT` rather than `PL_ENABLE`, and `rpi_msr[]` must not define `PL4_ENABLE` because MSR `RAPL_DOMAIN_REG_PL4` (`MSR_VR_CURRENT_CONFIG`) has no enable bit. [F120]
- `POWER_LIMIT1` through `POWER_LIMIT4` must be contiguous at the start of `enum rapl_primitives` with `NR_POWER_LIMITS == POWER_LIMIT4 + 1` (used by `rd->rpl[NR_POWER_LIMITS]`, `pl_names`, and `is_pl_valid()`). Modifying `enum rapl_domain_type` requires updating `rapl_domain_names[]`, `zone_ops[]`, and `rapl_check_domain()` in lockstep in exact enum order. [F64, F72]
- In `struct rapl_package`, `domain_map` must remain `unsigned long` so `bitmap_weight(&rp->domain_map, RAPL_DOMAIN_MAX)` and `test_bit(domain, &rp->domain_map)` do not read past a narrower integer field. In `rapl_pmu_update()`, skipping `perf_pmu_unregister()` / `perf_pmu_register()` requires `rapl_pmu.registered && !(rp->domain_map & (~rapl_pmu.domain_map))`. [F91, F109]
- In `enum tpmi_rapl_register`, every hardware register (including unused/reserved slots) must be listed in exact architectural order up to `TPMI_RAPL_REG_MAX = 15`, because `parse_one_domain()` uses `reg_index` as both `BIT(reg_index)` in `tpmi_domain_flags` and the MMIO offset (`offset + reg_index * 8`). [F69]
- `parse_one_domain()` must validate `tpmi_domain_size == 1`, require `BIT(TPMI_RAPL_REG_UNIT)` and `BIT(TPMI_RAPL_REG_ENERGY_STATUS)` in `tpmi_domain_flags`, and reject duplicate `domain_type` entries before populating `trp->priv.regs`. For `TPMI_RAPL_DOMAIN_SYSTEM`, it must require `BIT(TPMI_RAPL_REG_DOMAIN_INFO)` in `tpmi_domain_flags` (or fail with `-ENODEV`), and if `TPMI_RAPL_DOMAIN_ROOT` is clear in `TPMI_RAPL_REG_DOMAIN_INFO`, return `0` without registering `RAPL_DOMAIN_PLATFORM`. [F70, F118]
- In `powercap_register_zone()` and `powercap_unregister_zone()`, `control_type->nr_zones` must be incremented and decremented under `control_type->lock` because `powercap_unregister_control_type()` rejects unregistration with `-EINVAL` while `nr_zones` is non-zero. [F46]
- Adding zone or constraint sysfs attributes in `powercap_sys.c` requires updating `POWERCAP_ZONE_MAX_ATTRS`, `POWERCAP_CONSTRAINTS_ATTRS`, `struct powercap_constraint_attr`, `seed_constraint_attributes()`, `free_constraint_attributes()`, and `create_constraints()` in lockstep. [F49]
- In `struct pm_qos_constraints`, `struct pm_qos_flags_request`, and `struct pm_qos_flags`, `target_value`, `flags`, and `effective_flags` must remain 32-bit `s32` types because the lockless PM QoS read path relies on single-instruction atomic 32-bit loads. [F26]
- In `device_init_wakeup(dev, enable)`, `device_set_wakeup_capable(dev, true)` must precede `device_wakeup_enable(dev)` when enabling, and `device_wakeup_disable(dev)` must precede `device_set_wakeup_capable(dev, false)` when disabling. [F67]

## Synchronization

- In `intel_rapl_common.c`, `rapl_event_update()` must update `event->hw.prev_count` via `local64_try_cmpxchg()` and accumulate into `event->count` via `local64_add()` because `rapl_pmu_event_read()` calls `rapl_event_update()` without holding `rapl_package_pmu_data.lock`, racing with `rapl_hrtimer_handle()` and `rapl_pmu_event_stop()`. [F21]
- Under `rapl_package_pmu_data.lock`, `__rapl_pmu_event_start()` and `rapl_pmu_event_stop()` must keep `event->hw.state` (`PERF_HES_STOPPED`), `event->active_entry` in `data->active_list`, `data->n_active`, and `data->hrtimer` (started on `0 -> 1`, canceled on `1 -> 0`) updated in lockstep. [F57]
- All reads and writes to `idle_inject_device.run_duration_us`, `idle_duration_us`, and `latency_us` must use `READ_ONCE()` and `WRITE_ONCE()` because they are accessed locklessly by `idle_inject_timer_fn()` (hardirq) and `idle_inject_fn()` (per-CPU kthreads) while being updated via `idle_inject_set_duration()` or `idle_inject_set_latency()`. [F13]
- `pm_runtime_mark_last_busy()` must read time via `ktime_get_mono_fast_ns()` rather than `ktime_get()` because runtime PM resume can run while the timekeeping seqcount write lock is held during clocksource switching. [F128]
- Iterating over wakeup sources with `for_each_wakeup_source()`, `wakeup_sources_walk_start()`, and `wakeup_sources_walk_next()` requires holding the SRCU read lock via `wakeup_sources_read_lock()` and `wakeup_sources_read_unlock()`. [F133]

## Object Lifetimes

- When a caller passes a pre-allocated `power_zone` or `control_type` to `powercap_register_zone()` or `powercap_register_control_type()`, `ops->release` must be non-NULL (`powercap_release()` only calls `kfree()` when `allocated` is true); in `powercap_release()`, all internal fields (`allocated`, `parent_idr`, `idr`, `lock`, `name`, `zone_dev_attrs`, `constraints`) must be read and destroyed before calling `ops->release()`, which may immediately free the enclosing struct. [F1, F2]
- `RAPL_DOMAIN_PACKAGE` must stay at `rp->domains[0]` (`RAPL_DOMAIN_PACKAGE == 0`) and be unregistered last in `rapl_package_register_powercap()` and `rapl_remove_package_cpuslocked()`, because `release_zone()` frees `rp->domains` via `kfree(rd)` on `RAPL_DOMAIN_PACKAGE` and must set `rp->domains = NULL` so `rapl_add_package_cpuslocked()`'s `err_free_package` path does not double-free it; `kfree(rp)` must not precede `release_zone()`. [F6, F74]
- When removing a PMU-enabled RAPL package, `rapl_package_remove_pmu(rp)` must precede `rapl_remove_package(rp)` (zeroing `rapl_pmu` after `perf_pmu_unregister()` on the last package). In `intel_rapl_tpmi_remove()`, teardown must call `rapl_package_remove_pmu(trp->rp)`, then `rapl_remove_package(trp->rp)`, then `trp_release(trp)` (which unregisters `tpmi_control_type` under `tpmi_rapl_lock` when `tpmi_rapl_packages` becomes empty). [F7, F58, F60]
- In `rapl_msr_remove()`, `cpuhp_remove_state(rapl_msr_priv->pcap_rapl_online)` must be called before `powercap_unregister_control_type(rapl_msr_priv->control_type)` so `rapl_cpu_down_prep()` unregisters all package zones first. [F8]
- `rapl_msr_write_raw()` must call `smp_call_function_single()` with `wait=1` because callers (`rapl_write_data_raw()`) pass a stack-allocated `struct reg_action` accessed by `rapl_msr_update_func()` on the target CPU. [F110]
- `idle_inject_register_full()` must allocate `sizeof(*ii_dev) + cpumask_size()` bytes, and if a CPU in the mask already has a non-NULL `per_cpu(idle_inject_device, cpu)`, `out_rollback` must stop at `cpu == cpu_rb` so it only clears CPUs assigned during the current call. [F9, F81]
- `idle_inject_unregister()` must call `idle_inject_stop(ii_dev)` before clearing `per_cpu(idle_inject_device, cpu)` and freeing `ii_dev`; `idle_inject_stop()` must call `hrtimer_cancel(&ii_dev->timer)` before `cpu_hotplug_disable()`, and under `cpu_hotplug_disable()` iterate over all CPUs in `ii_dev->cpumask` (including offline CPUs via `for_each_cpu()`) to clear `iit->should_run` and call `wait_task_inactive(iit->tsk, TASK_ANY)`. [F10, F12]

## API Contracts

- `__pm_runtime_resume()` and `pm_runtime_get_sync()` return `1` when already active, `0` on synchronous resume, or `< 0` while leaving `dev->power.usage_count` incremented on error; `pm_runtime_resume_and_get()` drops `usage_count` on `< 0` and normalizes `1` to `0`. Broken by: treating `1` from `pm_runtime_get_sync()` as an error, or not dropping the reference on `< 0`. [F43]
- `pm_runtime_suspended(dev)` requires `!dev->power.disable_depth` and `runtime_status == RPM_SUSPENDED`, whereas `pm_runtime_active(dev)` is true when `dev->power.disable_depth` is non-zero or `runtime_status == RPM_ACTIVE`. Along with `pm_runtime_status_suspended()` and `pm_runtime_enabled()`, they read `dev->power` locklessly and are only reliable under `dev->power.lock` or when runtime PM state/enablement cannot change. [F27, F92]
- `pm_runtime_set_active()` and `pm_runtime_set_suspended()` require runtime PM to be disabled on `@dev`, and manual `pm_runtime_use_autosuspend(dev)` (without `devm_pm_runtime_enable()`) must be paired with `pm_runtime_dont_use_autosuspend(dev)` on teardown. `pm_runtime_blocked()` must only be called during system suspend/resume. [F126, F132]
- In atomic or idle-loop contexts where `dev->power.lock` (a sleeping lock on `PREEMPT_RT`) cannot be acquired and `dev->power.qos` cannot be freed concurrently, callers must use `dev_pm_qos_raw_resume_latency()` instead of `dev_pm_qos_read_value()`. When `!CONFIG_PM`, `dev_pm_qos_read_value()` only supports `DEV_PM_QOS_RESUME_LATENCY`, `DEV_PM_QOS_MIN_FREQUENCY`, and `DEV_PM_QOS_MAX_FREQUENCY`, triggering `WARN_ON(1)` on `DEV_PM_QOS_LATENCY_TOLERANCE` or `DEV_PM_QOS_FLAGS`. [F129, F158]
- Powercap sysfs handlers invoke `powercap_zone_ops` and `powercap_zone_constraint_ops` without holding `control_type->lock`, so drivers must synchronize inside callbacks. `create_constraints()` requires non-NULL `const_ops` and `get_power_limit_uw`, `set_power_limit_uw`, `get_time_window_us`, and `set_time_window_us` callbacks even when `nr_constraints == 0`, with `nr_constraints <= MAX_CONSTRAINTS_PER_ZONE` (10). [F17, F145]
- `idle_inject` callers must provide their own lock to serialize `idle_inject_start()`, `idle_inject_stop()`, and `idle_inject_unregister()`. The `update` callback in `idle_inject_register_full()` runs in hardirq context from `idle_inject_timer_fn()` and must not sleep. `idle_inject_register*()` returns `NULL` (never `ERR_PTR()`). `idle_inject_set_duration()` and `idle_inject_set_latency()` take microseconds, and `run_duration_us + idle_duration_us > 0` must be set before `idle_inject_start()`. [F14, F41, F42, F134]

## Error Handling

- In `powercap_register_zone()`, `dev_set_name()` must only be called after all fallible pre-registration steps succeed right before `device_register(&power_zone->dev)`, and if `device_register()` fails cleanup must use `put_device(&power_zone->dev)` rather than the `err_dev_ret` `kfree` labels. [F3]
- In `rapl_config()`, `rp->priv->defaults` and `rp->priv->rpi` must be NULL-checked after assigning interface tables, and optional callbacks like `defaults->set_floor_freq` must be NULL-checked before invocation in `set_domain_enable()`. [F34]
- Because `rapl_write_data_raw()` does not check `ra.reg.val`, MMIO `write_raw` callbacks like `tpmi_rapl_write_raw()` must check `if (!ra->reg.mmio)` and return `-EINVAL` before dereferencing `ra->reg.mmio`. When `rapl_write_pl_data()` rejects a BIOS-locked limit (`rd->rpl[pl].locked`), it must log with `pr_debug()` (not `pr_warn()`/`pr_err()`) and return `-EACCES`. [F36, F151]

## External Contracts

- In `create_power_zone_common_attributes()`, `dev_attr_energy_uj` mode must only grant read/write access to root (`S_IRUSR` or `S_IWUSR | S_IRUSR`) and never `S_IRUGO`. In `define_power_zone_store`, writing `0` to `energy_uj` calls `power_zone->ops->reset_energy_uj(power_zone)`, whereas writing any non-zero unsigned integer must be silently ignored and return `count`. [F78, F148]

## Known Pitfalls

- Pre-allocated `power_zone` or `control_type` structs passed to `powercap_register_zone()` or `powercap_register_control_type()` are zeroed with `memset()`, so fields like `power_zone->private_data` (`powercap_set_zone_data()`) must be set only after registration. [F47]
- In `parse_one_domain()` (`intel_rapl_tpmi.c`), the `while (++reg_index != TPMI_RAPL_REG_MAX)` loop must `continue` (not `break`) on unmapped `enum tpmi_rapl_register` values in `switch (reg_index)` so `trp->priv.regs[domain_type][reg_id].mmio` is only assigned when `reg_id` was set. [F86]
- In `set_domain_enable()`, after writing `PL_ENABLE` for `POWER_LIMIT1`, the driver must read back `PL_ENABLE` via `rapl_read_pl_data()` and verify `mode == val` before calling `defaults->set_floor_freq(rd, mode)`. [F117]
- In `include/linux/pm_qos.h`, converting a 32-bit microsecond QoS limit such as `PM_QOS_LATENCY_ANY` (`S32_MAX`) to nanoseconds by multiplying by `NSEC_PER_USEC` (`1000L`) must cast the operand to `s64` before multiplication. [F94]
