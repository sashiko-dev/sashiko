# PIN CONTROLLER - MEDIATEK

This unit provides the MediaTek v1 (`pinctrl-mtk-common`) and v2 (`pinctrl-mtk-common-v2`) core pin controller and GPIO libraries along with SoC-specific pin/register description drivers (including MT8186, MT8188, MT8189, MT8192, MT8195, MT8196, MT8365, MT8516, and MT2701 headers). The v1 core manages pinmux, pinconf, GPIO chip, and EINT integration via syscon regmaps and fixed port offsets, while the v2 library provides multi-base MMIO register field lookup (`mtk_pin_field_calc`), bias/pull resistance helpers (PU/PD, R1/R0, RSEL), drive strength helpers, and EINT initialization for Paris-based SoC drivers.

## Architecture & Data Flow

- Because `pinctrl-mtk-common.h` and `pinctrl-mtk-common-v2.h` define incompatible `struct mtk_pinctrl` layouts and both `mtk_eint_init()` and `mtk_build_eint()` store their `struct mtk_pinctrl *` in `struct mtk_eint::pctl` (`void *`), shared `mtk-eint` code must never cast `eint->pctl` to `struct mtk_pinctrl *` and may only pass it to `eint->gpio_xlate` callbacks. [F74]
- Every `struct mtk_pin_field_calc` array in `struct mtk_pin_reg_calc` must have entries ordered by ascending pin range (`s_pin <= e_pin < next.s_pin`) and `i_base < soc->nbase_names`, because `mtk_hw_pin_field_lookup()` binary-searches `rc->range` by `desc->number` and rejects `c->i_base > hw->nbase - 1`. [F88]
- Because `mtk_w32()` and `mtk_r32()` add `reg` directly to `pctl->base[i]` (`void __iomem *`, byte-addressed), `s_addr` and `x_addrs` in `struct mtk_pin_field_calc` (and `offset` and `next` in `struct mtk_pin_field`) must be byte offsets and byte strides, whereas `s_bit`, `x_bits`, and `sz_reg` are bit counts. Broken by: setting `x_addrs` to a 32-bit word count instead of a byte stride. [F77]
- When `mtk_hw_pin_field_lookup()` sets `pfd->next` to non-zero because `pfd->bitpos + c->x_bits > c->sz_reg`, `mtk_hw_set_value()` and `mtk_hw_get_value()` must access both `pf.offset` (low `32 - pf.bitpos` bits) and `pf.offset + pf.next` (remaining high bits) via `mtk_hw_write_cross_field()` and `mtk_hw_read_cross_field()`. [F32]
- In v2 SoC `struct mtk_pin_reg_calc` tables (such as `mt8186_reg_cals` and `mt8192_reg_cals`), unsupported hardware register types (like `PINCTRL_PIN_REG_SR` when there is no slew-rate control) must be left unpopulated (`range == NULL`) rather than aliased to another register range. [F87]
- `struct mtk_pin_soc::pins` (v2) and `struct mtk_pinctrl_devdata::pins` (v1) must be dense 0-based arrays where element `i` has pin number `i`, because callers (`mtk_xt_find_eint_num()`, `mtk_xt_get_gpio_n()`, `mtk_pctrl_find_function_by_pin()`) index `pins` directly by `desc[i].number` or `pin->pin.number`. [F48]
- Every non-NULL `functions` array in `struct mtk_desc_pin` and `funcs` array in `struct mtk_pin_desc` must end with a zeroed sentinel element where `.name == NULL` (as appended by `MTK_PIN`), because function lookup loops advance `func++` until `func->name` is `NULL`. [F51]
- In `pinctrl-mtk-common-v2.c`, `mtk_is_virt_gpio()` indexes `desc->funcs[desc->eint.eint_m].name` directly by `desc->eint.eint_m` rather than searching by `muxval`, so for any v2 `struct mtk_pin_desc` with `eint.eint_m != NO_EINT_SUPPORT` and non-NULL `funcs`, `eint.eint_m` must be a valid index into `funcs` whose entry has `.name == NULL` iff the pin is a virtual GPIO. [F79]
- In `pinctrl-mtk-common.c`, `mtk_pmx_find_gpio_mode()` locates a pin's GPIO `muxval` by comparing the first `sizeof(GPIO_MODE_PREFIX) - 1` bytes of `func->name` against `"GPIO"` via `strncmp()`, so in v1 `struct mtk_desc_pin` tables each pin's GPIO function name must start with `"GPIO"` and precede any other `"GPIO"`-prefixed function. [F80]
- In `pinctrl-mtk-common-v2.h`, `EINT_NA` and `NO_EINT_SUPPORT` must be `U16_MAX` (`0xffff`) rather than `-1` because they are compared against `u16` fields `desc->eint.eint_m` and `desc->eint.eint_n` (and `unsigned int *gpio_n`), whereas in `pinctrl-mtk-common.h`, `NO_EINT_SUPPORT` is `255` (`U8_MAX`) to match `unsigned char` `struct mtk_desc_eint.eintnum`, requiring all valid v1 EINT numbers to be strictly less than `255`. [F67, F68]
- When a SoC provides `struct mtk_pin_soc::eint_pin` to `mtk_build_eint()` / `mtk_eint_do_init()`, the array must have at least `eint_hw->ap_num` elements (padded with `EINT_INVALID_BASE` for unused EINT indices) and, for each valid `instance < eint->nbase`, `index` values in `0 .. base_pin_num[instance] - 1`. [F55]
- In `mtk_pinconf_bias_set_combo()` and `mtk_pinconf_bias_get_combo()`, `try_all_type & MTK_PULL_RSEL_TYPE` must be evaluated before `try_all_type & MTK_PULL_PU_PD_TYPE` because `MTK_PULL_PU_PD_RSEL_TYPE` sets both bit flags and relies on trying the RSEL path first before falling back to plain PU/PD. [F57]
- In `mtk_pinconf_bias_set_pu_pd_rsel()`, `mtk_pinconf_bias_set_rsel()` must only be called when `arg != MTK_DISABLE`, whereas `mtk_pinconf_bias_set_pu_pd()` is always called with `enable = (arg == MTK_DISABLE ? MTK_DISABLE : MTK_ENABLE)`. [F39]
- In `pinctrl-mtk-common.c`, `pctl->regmap2` is only populated when a second `"mediatek,pctl-regmap"` phandle exists in DT, so single-regmap SoC `mtk_pinctrl_devdata` tables (such as `mt8365_pinctrl_data` and `mt8516_pinctrl_data`) must set `type1_start >= type1_end` to prevent `mtk_get_regmap()` from returning the `NULL` `pctl->regmap2`. [F21]
- In `pinctrl-mtk-common.c`, single-bit updates write `BIT(bit)` to `SET_ADDR` or `CLR_ADDR` via `regmap_write()` unless `mt8365_set_clr_mode` is set, whereas `mt8365_set_clr_mode` and multi-bit fields (`mtk_pmx_set_mode()`, `mtk_pconf_set_driving()`) must use `regmap_update_bits()` on the base register to avoid overwriting sibling pins. [F37]
- In `pinctrl-mtk-common.c`, `mtk_pconf_parse_conf()` (`PIN_CONFIG_LEVEL`) and `mtk_gpio_direction_output()` must call `mtk_gpio_set()` before setting the pin direction to output, while input/schmitt/EINT setup (`mtk_xt_set_gpio_as_eint()`) sets the direction to input before enabling `mtk_pconf_set_ies_smt()`. [F33]
- In `mtk_pconf_group_set()`, `g->config` in `struct mtk_pinctrl_group` is updated to `configs[i]` only after `mtk_pconf_parse_conf()` returns non-negative, keeping `mtk_pconf_group_get()` synchronized with the last applied config. [F34]
- In `pinctrl-mtk-common.c`, `mtk_pinctrl_devdata.mode_per_reg` must be in `1..10` because `mtk_pmx_set_mode()` divides and takes modulo of `pin` by `mode_per_reg` and shifts the 3-bit (`GPIO_MODE_BITS`) 32-bit `unsigned int` `mask` and `val` left by `GPIO_MODE_BITS * (pin % mode_per_reg)`. [F72]
- In `pinctrl-mtk-common.c`, every `struct mtk_drv_group_desc` and `struct mtk_pin_drv_grp` used by `mtk_pconf_set_driving()` must satisfy `step > 0`, `min_drv >= step`, `high_bit >= low_bit`, and `pin_drv->bit + drv_grp->high_bit < 32`. [F73]
- Every `struct mtk_pin_ies_smt_set` entry defined with `MTK_PIN_IES_SMT_SPEC(start, end, offset, bit)` in `spec_ies` or `spec_smt` must satisfy `start <= end` so `mtk_pconf_spec_set_ies_smt_range()` matches `[start, end]`. [F47]

## Synchronization

- Callers of `mtk_build_eint()` must initialize `hw->soc`, `hw->base`, `hw->nbase`, `hw->dev`, and `hw->lock` beforehand, because `mtk_build_eint()` publishes `hw` via `hw->eint->pctl` and `mtk_eint_xt` to `mtk_eint_do_init()`, enabling EINT callbacks (`mtk_xt_get_gpio_state()`, `mtk_xt_set_gpio_as_eint()`) that invoke `mtk_hw_get_value()` and `mtk_hw_set_value()`. [F8]
- All MMIO read-modify-write updates to pin configuration registers in `pinctrl-mtk-common-v2.c` must go through `mtk_rmw()`, which serializes `mtk_r32()` and `mtk_w32()` under `spin_lock_irqsave(&pctl->lock, flags)` (safe when EINT callbacks like `mtk_xt_set_gpio_as_eint()` invoke `mtk_hw_set_value()` from atomic interrupt context). [F94]

## Object Lifetimes

- In `mtk_build_eint()`, error paths after allocating `hw->eint->base` (`err_free_eint` and `err_free_base`) must manually `iounmap()` any `of_iomap()`-mapped `hw->eint->base[j]` entries, `devm_kfree()` both `hw->eint->base` and `hw->eint`, and clear `hw->eint = NULL`. [F84]
- In `mtk_pctrl_init()`, each `device_node` returned by `of_parse_phandle(np, "mediatek,pctl-regmap", ...)` must be released with `of_node_put(node)` immediately after `syscon_node_to_regmap(node)` and before returning on `IS_ERR(pctl->regmap1)` or `IS_ERR(pctl->regmap2)`. [F5]
- `mtk_pctrl_dt_subnode_to_map()` must free the temporary `configs` array from `pinconf_generic_parse_dt_config()` via `kfree(configs)` on both success and error paths, and `mtk_pctrl_dt_node_to_map()` must call `pinctrl_utils_free_map()` if any child subnode fails. [F86]

## API Contracts

- `mtk_hw_pin_field_lookup()` (`pinctrl-mtk-common-v2.c`) must return `-ENOTSUPP` (not `-EOPNOTSUPP` or `-EINVAL`) when a register field or pin range is absent from `hw->soc->reg_cal`, because `mtk_xt_set_gpio_as_eint()`, `mtk_pinconf_adv_pull_set()`, and `mtk_pinconf_adv_pull_get()` explicitly check `err == -ENOTSUPP` to trigger fallback paths. [F15]
- `mtk_eint_pm_ops` (`mtk_eint_suspend()` and `mtk_eint_resume()` in `pinctrl-mtk-common.c`) casts `dev_get_drvdata(device)` to the v1 `struct mtk_pinctrl` layout to read `pctl->eint` and runs via `NOIRQ_SYSTEM_SLEEP_PM_OPS` with device interrupts disabled; only v1 drivers probing via `mtk_pctrl_init()` or `mtk_pctrl_common_probe()` may bind `mtk_eint_pm_ops`, while v2 Paris drivers must bind `mtk_paris_pinctrl_pm_ops`. [F75, F102]
- `mtk_hw_get_value()` and the getter callbacks in `struct mtk_pin_soc` (`bias_disable_get`, `bias_get`, `bias_get_combo`, `drive_get`, `adv_pull_get`, `adv_drive_get`) write 32-bit `int *` or `u32 *` out-parameters interchangeably under `-Wno-pointer-sign`, so callers and implementations must only pass pointers to 32-bit integers (`int` or `u32`). [F81]
- `mtk_rmw()` (`pinctrl-mtk-common-v2.c`) clears `mask` and bitwise-ORs `set` directly into the 32-bit register without shifting or masking `set`, so callers (`mtk_hw_set_value()` and `mtk_hw_write_cross_field()`) must pre-shift both `mask` and `set` to `pf.bitpos` and mask `value` with `pf.mask` before calling `mtk_rmw()`. [F25]
- Hardware `PINCTRL_PIN_REG_PUPD` (`mtk_pinconf_bias_set_pupd_r1_r0()`, `mtk_pinconf_bias_get_pupd_r1_r0()`, `mtk_pinconf_adv_pull_set()`, `mtk_pinconf_adv_pull_get()`) and `pupd_bit` in `mtk_pctrl_spec_pull_set_samereg()` encode `0` for pull-up and `1` for pull-down, so callers must invert `pullup`/`isup` when reading or writing `PUPD`. [F26]
- `mtk_pinconf_bias_disable_get()`, `mtk_pinconf_bias_get()`, `mtk_pinconf_bias_disable_get_rev1()`, and `mtk_pinconf_bias_get_rev1()` must return `-EINVAL` (and only set `*res = 1` on a match) when the queried bias state is not active, whereas `mtk_pinconf_bias_get_combo()` and its sub-helpers return `0` when bias is disabled and report the disabled state via `*enable = MTK_DISABLE` (or `MTK_PUPD_SET_R1R0_00` for `MTK_PULL_PUPD_R1R0_TYPE`, where `mtk_pinconf_bias_set_pupd_r1_r0()` accepts both `MTK_DISABLE` and `MTK_PUPD_SET_R1R0_00`). [F17, F62, F112]
- In `mtk_pinconf_bias_set_rsel()` and `mtk_pinconf_bias_get_pu_pd_rsel()`, `arg`/`*enable` is a resistance in Ohms mapped via `mtk_hw_pin_rsel_lookup()` / `mtk_rsel_get_si_unit()` when `hw->rsel_si_unit` is true, and a symbolic constant in `[MTK_PULL_SET_RSEL_000, MTK_PULL_SET_RSEL_111]` when false. [F28]
- In `mtk_pconf_set_pull_select()` (`pinctrl-mtk-common.c`), `pctl->devdata->mt8365_set_clr_mode` (`mt8365_set_clr_mode()`) takes an unshifted bit index (`pin & pctl->devdata->mode_mask`) and base offsets (`reg_pullen`, `reg_pullsel`), unlike the standard path which uses `BIT(...)` and `SET_ADDR`/`CLR_ADDR`. [F27]

## Error Handling

- `mtk_hw_get_value()` and `mtk_hw_pin_field_get()` in `pinctrl-mtk-common-v2.c` leave their output parameter (`*value` or `*pfd`) uninitialized when returning a non-zero error code, so every caller must check the returned `int` status before reading the output variable. [F12]
- In `pinctrl-mtk-common-v2.c`, `mtk_xt_find_eint_num()` returns the positive sentinel `EINT_NA` (`U16_MAX`) rather than a negative error code when `eint_n` is not found in `hw->soc->pins`, so `mtk_xt_get_gpio_n()` (and any caller) must compare against `EINT_NA` rather than checking `< 0`. [F16]
- `hw->soc->pull_type` in `struct mtk_pin_soc` is optional and may be `NULL`, so `mtk_pinconf_bias_set_combo()` and `mtk_pinconf_bias_get_combo()` must check `if (hw->soc->pull_type)` before indexing `hw->soc->pull_type[desc->number]` (defaulting to `MTK_PULL_TYPE_MASK`), and when non-NULL, `pull_type` must be sized to cover every pin number passed to combo bias get/set. [F19, F54]
- In `mtk_pinconf_adv_pull_set()`, when writing `PINCTRL_PIN_REG_PUPD` returns `-ENOTSUPP` and `hw->soc->bias_set` is `NULL`, the fallback path must try `mtk_pinconf_bias_set_rev1()` and then `mtk_pinconf_bias_set()` rather than calling `hw->soc->bias_set_combo`. [F60]
- In `mtk_eint_init()` and `mtk_pctrl_init()` (`pinctrl-mtk-common.c`), `devm_kzalloc()` and `devm_kcalloc()` return `NULL` on failure, whereas `devm_platform_ioremap_resource()`, `syscon_node_to_regmap()`, and `devm_pinctrl_register()` return `ERR_PTR` values that must be checked with `IS_ERR()` on the assigned target pointer (e.g. `IS_ERR(pctl->eint->base[0])`, not `IS_ERR(pctl->eint->base)`). [F13]
- In `mtk_pconf_set_pull_select()` (`pinctrl-mtk-common.c`), `pctl->devdata->spec_pull_set` (`mtk_pctrl_spec_pull_set_samereg()`) must be invoked before the `arg != 0 && arg != 1` check, and a non-zero return from `spec_pull_set` must fall through to the generic pull path rather than returning immediately. [F29]
- In `mtk_pconf_set_ies_smt()` (`pinctrl-mtk-common.c`), the local `offset` variable must be assigned from `pctl->devdata->ies_offset` or `pctl->devdata->smt_offset` on all non-early-return branches before `offset` is read to compute `bit` and `reg_addr`. [F14]
- In `mtk_gpio_get_direction()` and `mtk_gpio_get()` (`pinctrl-mtk-common.c`), the local `read_val` passed to `regmap_read()` must be initialized to `0` before the call because `regmap_read()`'s return status is not checked before evaluating `read_val & bit`. [F24]

## External Contracts

- In `mtk_build_eint()`, the Device Tree `"reg-names"` property must list the `hw->soc->nbase_names` pinctrl register bases first followed by at least one EINT register base, because `mtk_build_eint()` computes `hw->eint->nbase = count_reg_names - hw->soc->nbase_names` and maps EINT bases starting at DT index `hw->soc->nbase_names`. [F50]

## Known Pitfalls

- Every `struct mtk_pin_field_calc` entry in `mtk_pin_soc.reg_cal` must have `sz_reg > 0` and `1 <= x_bits <= 30`, and any range where a field can span across registers (`bitpos + x_bits > sz_reg`) must have `sz_reg == 32` and `x_bits >= 2` because `mtk_hw_bits_part()` computes `*l = 32 - pf->bitpos` and `*h = get_count_order(pf->mask) - *l`. [F69]
- In `mtk_hw_pin_rsel_lookup()` and `mtk_rsel_get_si_unit()`, the loop bound `check <= hw->soc->npin_rsel - 1` uses unsigned arithmetic because `npin_rsel` is `unsigned int`, so `hw->soc->pin_rsel` must be non-NULL with `npin_rsel > 0` whenever `hw->rsel_si_unit` can be enabled on a SoC with `MTK_PULL_RSEL_TYPE` pins. [F49]
- `mtk_pinconf_drive_set*` and `mtk_pinconf_drive_get*` index `mtk_drive[desc->drv_n]` (`DRV_GRP0`..`DRV_GRP4`) where `mtk_drive[DRV_FIXED]` is zero-filled (`step == 0, scal == 0`), so `desc->drv_n` must be `<= DRV_GRP4` and any pin with `drv_n == DRV_FIXED` must not have a `DRV`/`E4`/`E8` register entry or be passed `arg == 0`. [F53]
- In `struct mtk_pin_drv_grp` tables (`devdata->pin_drv_grp`), `grp` must be strictly less than `devdata->n_grp_cls` (`0 <= grp < n_grp_cls`), because `mtk_pconf_set_driving()` only rejects `pin_drv->grp > pctl->devdata->n_grp_cls` before indexing `pctl->devdata->grp_desc + pin_drv->grp`. [F52]
- In `mtk_eint_init()` (`pinctrl-mtk-common.c`), `pctl->eint->base` (`void __iomem **`) is allocated with `sizeof(pctl->eint->base)` (a single pointer size, not scaled by `pctl->eint->nbase`), so increasing `pctl->eint->nbase` above 1 requires converting the allocation to `devm_kmalloc_array()` or `devm_kcalloc()` with `sizeof(*pctl->eint->base)`. [F76]
