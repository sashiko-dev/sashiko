# USB TYPEC PORT CONTROLLER DRIVERS

This component implements the USB Type-C Port Manager (TCPM) state machine and USB Power Delivery (PD) protocol stack (`tcpm.c`) along with the standard USB Type-C Port Controller Interface (TCPCI) hardware driver (`tcpci.c`). TCPM manages Type-C connection states, role swaps, PDO/APDO negotiation, PPS, VDMs, alternate modes, and SOP' cable discovery via `struct tcpc_dev`, exporting state to the Type-C, USB role switch, and `power_supply` subsystems.

## Architecture & Data Flow

- When `"pd-disable"` is set (`!port->pd_supported`), `tcpm_fw_get_caps()` returns early without allocating `port->pds` or `port->pd_list` or populating `port->src_pdo`/`port->snk_pdo`; callers must guard `port->pds` (e.g., in `tcpm_register_port()`) and check `port->pd_supported` before reading PDOs in `tcpm_set_charge()` or `tcpm_rp_cc()`. [F27]
- Neither `PORT_RESET` in `run_state_machine()` nor `tcpm_reset_port()` may clear `port->pd_events`, so asynchronous events like `TCPM_VBUS_EVENT` queued during reset are preserved for `tcpm_pd_event_handler()`. In `_tcpm_pd_hard_reset()`, received hard resets must be ignored in `TOGGLING`, `ERROR_RECOVERY`, `PORT_RESET`, and `PORT_RESET_WAIT_OFF`. [F37, F71]
- In `tcpm_typec_disconnect()`, `port->plug_prime` and `port->cable` must be unregistered and set to `NULL` outside `if (port->connected)`, as SOP' discovery in `SRC_VDM_IDENTITY_REQUEST` can register them before `port->connected` is set. In `DR_SWAP_CHANGE_DR`, `tcpm_unregister_altmodes(port)` must run unconditionally before toggling `port->data_role`. [F42, F51]
- SOP (`TCPC_TX_SOP`) and SOP' (`TCPC_TX_SOP_PRIME`) use separate message IDs (`message_id`/`rx_msgid` vs `*_prime`), revisions (`negotiated_rev` vs `negotiated_rev_prime`), and mode tables (`mode_data`/`partner_altmode` vs `mode_data_prime`/`plug_prime_altmode`). Updating/downgrading `port->negotiated_rev` or partner SVDM version on SOP must clamp `port->negotiated_rev_prime` or cable SVDM version down to match. [F46, F47]
- `port->rx_msgid` and `port->rx_msgid_prime` must be initialized to `-1` on port reset, startup, and soft reset, and `tcpm_pd_rx_handler()` must exempt `PD_CTRL_SOFT_RESET` on `TCPC_TX_SOP` from the `msgid == port->rx_msgid` duplicate drop check. [F82]
- Before scheduling SOP `DISCOVER_IDENTITY` under an explicit contract in `SRC_READY` or `SNK_READY`, `run_state_machine()` must call `tcpm_set_initial_svdm_version(port)`. In `vdm_run_state_machine()`, `port->vdo_data[0]` must be cleared to `0` once a VDM is sent in `VDM_STATE_SEND_MESSAGE`, when `CMD_DISCOVER_IDENT` gets `-EAGAIN` from `tcpm_ams_start()`, or before `VDM_STATE_ERR_SEND` queues a fallback SOP `CMD_DISCOVER_SVID`. [F40, F41]
- In `vdm_state_machine_work()`, the `do-while` loop must stop when `port->vdm_state` becomes `VDM_STATE_SEND_MESSAGE` or `VDM_STATE_BUSY` so `VDM_STATE_SEND_MESSAGE` is entered only when `mod_vdm_delayed_work()` runs `vdm_state_machine`. In `tcpm_pd_ctrl_request()`, receiving `PD_CTRL_REJECT`, `PD_CTRL_WAIT`, or `PD_CTRL_NOT_SUPP` in `GET_STATUS_SEND` or in `SRC_READY`/`SNK_READY` when `port->vdm_state > VDM_STATE_READY` must not fall through to the soft-reset path. [F73, F81]
- In `run_state_machine()`, `SNK_WAIT_CAPABILITIES` must pass `upcoming_state` (using `SNK_WAIT_CAPABILITIES_TIMEOUT` only when `!port->self_powered`) to `tcpm_set_state()`, and `hard_reset_state()` must return `SNK_READY` for both states. In `PORT_RESET`, CC must be set to `TYPEC_CC_OPEN` when `port->self_powered` is true, and `TYPEC_CC_RD` or `tcpm_rp_cc(port)` when false. [F72, F106]
- In `run_state_machine()`, `port->potential_contaminant` must be evaluated against `port->enter_state` (`SRC_ATTACH_WAIT` to `SRC_UNATTACHED`, or `SNK_ATTACH_WAIT`/`SNK_DEBOUNCED` to `SNK_UNATTACHED`) before `port->enter_state = port->state` overwrites it. [F74]
- Whenever `port->vbus_present` is set to `true` (`_tcpm_pd_vbus_on()`, `tcpm_init()`), `port->vbus_vsafe0v` must be set to `false`. In `tcpci_set_vbus()`, `!source` (`TCPC_CMD_DISABLE_SRC_VBUS`) and `!sink` (`TCPC_CMD_DISABLE_SINK_VBUS`) writes must execute before `source` (`TCPC_CMD_SRC_VBUS_DEFAULT`) and `sink` (`TCPC_CMD_SINK_VBUS`) enable writes. [F52, F68]
- RDO indices are 1-based while `port->src_pdo` is 0-based: `tcpm_pd_check_request()` must reject `!index || index > port->nr_src_pdo` before indexing `port->src_pdo[index - 1]`, and `tcpm_pd_build_request()`/`tcpm_pd_build_pps_request()` must pass `src_pdo_index + 1` to RDO macros. When `op_mw < port->operating_snk_mw` in `tcpm_pd_build_pps_request()`, `op_ma` and `out_mv` must use ceiling division and round up to `RDO_PROG_CURR_MA_STEP`/`RDO_PROG_VOLT_MV_STEP`, whereas `tcpm_pps_set_op_curr()`/`tcpm_pps_set_out_volt()` round down. [F57, F86]
- Because `tcpm_pd_set()` and `usb_power_delivery_register_capabilities()` scan `pdo[]` up to `PDO_MAX_OBJECTS` until a `0` entry, every `struct usb_power_delivery_capabilities_desc` (`tcpm_register_source_caps()`, `tcpm_register_sink_caps()`, `tcpm_fw_get_caps()`) must have trailing `pdo[]` slots zeroed. [F95]
- In `tcpci_irq()`, `TCPC_RX_BYTE_CNT` (`cnt`) is `1 + sizeof(msg.header) + payload_cnt`, so `payload_cnt` must be `cnt - (1 + sizeof(msg.header))` only when `cnt > 3` (else `0`) and clamped to `sizeof(msg.payload)` before `regmap_raw_read()`. Wire `msg->payload` words are `__le32` and must be converted with `le32_to_cpu()` on RX (`tcpm_pd_data_request()`, `tcpm_handle_vdm_request()`) and `cpu_to_le32()` on TX. [F54, F62]
- In `svdm_consume_svids()`, each VDO in `p[1..cnt-1]` packs two 16-bit SVIDs (upper then lower 16 bits); before storing each into `pmdata->svids[pmdata->nsvids++]`, discovery must stop if `!svid` (`0x0000`) or `pmdata->nsvids >= SVID_DISCOVERY_MAX`. [F60]

## Synchronization

- In role-swap and PPS calls (`tcpm_dr_set`, `tcpm_pr_set`, `tcpm_vconn_set`, `tcpm_pps_set_op_curr`, `tcpm_pps_set_out_volt`, `tcpm_pps_activate`), `port->swap_lock` must be acquired before `port->lock`, and `port->lock` must be dropped while waiting on `port->swap_complete` or `port->pps_complete` with `port->swap_lock` held. [F12]
- In `tcpm_pd_transmit()`, `reinit_completion(&port->tx_complete)` and `port->tcpc->pd_transmit()` must run under `port->lock`, and `port->lock` must be dropped across `wait_for_completion_timeout(&port->tx_complete, ...)` and re-acquired before reading `port->tx_status` or returning. [F13]
- In `tcpm_handle_vdm_request()`, `port->vdm_sm_running` must be set to `true` before dropping `port->lock`, and `port->lock` must be unlocked across `typec_altmode_*` or `typec_cable_altmode_vdm()` calls and re-locked before `tcpm_queue_vdm()` or returning to `tcpm_pd_rx_handler()`. [F15]
- Event notifications (`tcpm_cc_change()`, `tcpm_vbus_change()`, `tcpm_pd_hard_reset()`, etc.) must update `port->pd_events` under `port->pd_event_lock`, and `tcpm_pd_event_handler()` must snapshot and clear `port->pd_events` under `port->pd_event_lock` (inside `port->lock`) and unlock `port->pd_event_lock` before running handlers. [F19]
- In `tcpm_set_state()`, immediate transitions (`delay_ms == 0`) must not call `mod_tcpm_delayed_work(port, 0)` when `port->state_machine_running` is true, relying on the active `tcpm_state_machine_work()` loop under `port->lock`. [F20]
- All accesses, allocations, and frees of `port->logbuffer`, `port->logbuffer_head`, and `port->logbuffer_tail` in `_tcpm_log()`, `tcpm_debug_show()`, and `tcpm_debugfs_exit()` must hold `port->logbuffer_lock` (updating `port->logbuffer_tail = tail` in `tcpm_debug_show()` only after the loop when `!seq_has_overflowed(s)`), and `tcpm_unregister_port()` must call `tcpm_debugfs_exit()` only after `kthread_destroy_worker()` and `tcpm_reset_port()`. [F21, F80]

## Object Lifetimes

- `tcpm_register_port()` borrows `tcpc->fwnode` without taking a reference, so callers like `tcpci_register_port()` that obtain `tcpc.fwnode` via `device_get_named_child_node()` (`tcpci_parse_config()`) must call `fwnode_handle_put(tcpci->tcpc.fwnode)` both on `tcpm_register_port()` failure and after `tcpm_unregister_port()` in `tcpci_unregister_port()`. [F1]
- In `tcpm_fw_get_caps()`, `caps` either aliases the borrowed `fwnode` (when `capabilities` is NULL) or holds a child reference from `fwnode_get_next_child_node(capabilities, caps)`, so every exit from the `port->pd_count` loop must pass through `put_caps:` (which calls `fwnode_handle_put(caps)` only when `caps != fwnode`) and `put_capabilities:`. [F2]
- Whenever `port->partner_source_caps` is unregistered via `usb_power_delivery_unregister_capabilities()` (`tcpm_register_source_caps()`, `tcpm_reset_port()`, `SOFT_RESET`, SOP `SOFT_RESET_SEND`, `PR_SWAP_SNK_SRC_SINK_OFF`), it must immediately be set to `NULL`. Never call `kfree()` on `sink_cap` or `source_cap` after `usb_power_delivery_unregister_capabilities()` (e.g., in `tcpm_port_unregister_pd()`). [F6, F102]
- `tcpci_suspend()` and `tcpci_resume()` must branch identically on `device_may_wakeup(dev)` so `enable_irq_wake(i2c->irq)` pairs with `disable_irq_wake(i2c->irq)` and clearing `TCPC_ALERT_MASK` to `0` pairs with restoring `chip->tcpci->alert_mask`. [F114]

## API Contracts

- `_tcpm_log()` locks `port->logbuffer_lock` and uses `GFP_KERNEL`, so `tcpm_log()`, `tcpm_log_force()`, `tcpm_pd_transmit_complete()`, and `tcpm_tcpc_reset()` (which locks `port->lock`) require sleepable context, whereas `tcpm_pd_receive()` must use `GFP_ATOMIC` and avoid `tcpm_log()`. [F120]
- In `tcpm_pd_transmit()` and `struct tcpc_dev.pd_transmit` callbacks (`tcpci_pd_transmit()`), `msg` is `NULL` for `TCPC_TX_HARD_RESET` and `TCPC_TX_BIST_MODE_2`, so `msg` must be checked for `NULL` before dereferencing. [F28]
- In `tcpm_queue_vdm()` and `tcpm_queue_vdm_unlocked()`, `cnt` is the number of VDOs in `data` excluding `header`, so callers whose count includes the header (`tcpm_altmode_vdm`, `tcpm_cable_altmode_vdm`, `tcpm_handle_vdm_request`) must pass `count - 1` (or `rlen - 1` with `&response[1]`). [F92]
- `tcpci_register_port()` must not set `dev`'s driver data or assume `dev_get_drvdata(dev)` is `struct tcpci_chip *`, as external chip drivers store their own struct in `dev` and recover it from `struct tcpci_data *` via `container_of`. In `tcpci_set_vbus()`, `tcpci->data->set_vbus` returns `< 0` on error, `> 0` to bypass default `TCPC_COMMAND` writes and return `0`, or `0` to run standard commands. [F23, F96]
- `tcpm_port` stores mV, mA, and mW (`tcpm_set_current_limit(port, max_ma, mv)` takes mA first, mV second), whereas `power_supply` properties (`tcpm_psy_get_voltage_now`, `tcpm_psy_get_current_now`) and `"op-sink-microwatt"` use uV, uA, and uW, requiring scaling by 1000. [F34]
- In `tcpci_set_auto_vbus_discharge_threshold()`, `requested_vbus_voltage_mv == 0` must write `0` directly to `TCPC_VBUS_SINK_DISCONNECT_THRESH`. For `TYPEC_PWR_MODE_PD` (non-FRS), threshold must use `apdo_min_voltage_mv * VPPS_SHUTDOWN_MIN_PERCENT / 100 - VSINKPD_MIN_IR_DROP_MV` when `pps_active` is true, and `requested_vbus_voltage_mv` with `VSRC_NEW_MIN_PERCENT`, `VSRC_VALID_MIN_MV`, and `VSINKDISCONNECT_PD_MIN_PERCENT` when false, then divide by `TCPC_VBUS_SINK_DISCONNECT_THRESH_LSB_MV` (25 mV) and clamp to `TCPC_VBUS_SINK_DISCONNECT_THRESH_MAX`. [F35, F83]
- When `tcpm_pd_set()` changes `port->selected_pd`, it must update `port->port_source_caps` and `port->port_sink_caps`, call `typec_port_set_usb_power_delivery(p, NULL)` to unlink the old PD, set `port->selected_pd = pd`, and call `typec_port_set_usb_power_delivery(p, port->selected_pd)`. [F39]
- `tcpci_register_port()` must only wire `is_vbus_vsafe0v`, `enable_auto_vbus_discharge`, `set_auto_vbus_discharge_threshold`, `check_contaminant`, and `set_orientation` on `tcpci->tcpc` when the corresponding `tcpci->data` flag/callback is set. In `tcpm_set_roles()`, a `data` role mismatching `TYPEC_PORT_DFP`/`TYPEC_PORT_UFP` must return `-ENOTSUPP`, and `usb_role` passed to `tcpm_mux_set()` must be `USB_ROLE_NONE` for `TYPEC_SINK` on DFP-only or `TYPEC_SOURCE` on UFP-only ports. [F107, F136]

## Error Handling

- Because `tcpm_typec_connect()` sets `port->connected = true` before `typec_register_partner()` and leaves `port->partner` as `NULL` on error, all paths accessing `port->partner` (`tcpm_pd_svdm()`, `svdm_consume_identity()`, `tcpm_typec_disconnect()`) must check `port->partner` even when `port->connected` is true. [F24]
- In `tcpm_pd_svdm()`, `svdm_version` must be initialized unconditionally on the `TCPC_TX_SOP_PRIME` branch before checking `port->cable`, and incoming `CMDT_INIT` SVDMs with `rx_sop_type == TCPC_TX_SOP_PRIME` must be dropped immediately because SOP-only pointers (`modep`, `pdev`) are uninitialized. [F29]
- Helpers in `tcpci.c` like `tcpci_check_std_output_cap()` and `tcpci_get_vbus()` that return negative errno values from `regmap_read()` alongside `0`/`1` results must return `int`, not `bool`. In `tcpm_fw_get_caps()`, `tcpm_fw_get_snk_vdos()`, and `tcpm_fw_get_pd_revision()`, property counts must be clamped with `min(ret, PDO_MAX_OBJECTS)` or `min(ret, VDO_MAX_OBJECTS)`, and `"pd-revision"` must require an exact `u8` count of 4. [F22, F64]

## External Contracts

- In `tcpci_pd_transmit()`, `cnt = pd_header_cnt(header) * 4` is the payload byte length, `TCPC_TX_BYTE_CNT` is `cnt + 2`, and when `TX_BUF_BYTE_x_hidden` is set, `[cnt + 2, msg->header, msg->payload]` must be written in one `regmap_raw_write()` to `TCPC_TX_BYTE_CNT`. When `port->negotiated_rev < PD_REV30`, `tcpm_pd_send_source_caps()` and `tcpm_pd_send_sink_caps()` must filter PDOs via `tcpm_forge_legacy_pdo()`, clearing PD 3.0 Fixed PDO bits and returning `0` for `PDO_TYPE_APDO` to omit APDOs. [F93, F134]

## Known Pitfalls

- State transitions in `run_state_machine()` after `tcpm_pd_transmit()` or its send wrappers (`tcpm_pd_send_source_caps()`, etc.) must use `tcpm_set_state_cond()` rather than `tcpm_set_state()` whenever an event during the `port->lock` drop could have changed `port->state`. [F14]
- Before passing remaining `port->delayed_runtime` to `mod_tcpm_delayed_work()` or `tcpm_set_state()` (`unsigned int delay_ms`), callers must check `ktime_after(port->delayed_runtime, ktime_get())`, and before `jiffies_to_msecs(port->max_wait - jiffies)`, `run_state_machine()` must check `time_is_after_jiffies(port->max_wait)`. [F90]
- In `tcpm_handle_vdm_request()`, dispatching to `typec_cable_altmode_vdm()` vs `typec_altmode_vdm()`/`typec_altmode_notify()` in `switch (adev_action)` must test `rx_sop_type == TCPC_TX_SOP_PRIME`, not `response_tx_sop_type`. [F69]
- In `tcpm_pd_set()`, `data->source_desc.pdo[i]` must be copied to `port->src_pdo[i]` and `data->sink_desc.pdo[i]` to `port->snk_pdo[i]`, and after the 0-based loop (`for (i = 0; i < PDO_MAX_OBJECTS && desc.pdo[i]; i++)`), `i` must be assigned directly to `port->nr_src_pdo` and `port->nr_snk_pdo` without adding 1. [F58, F70]
- Before writing `TCPC_ROLE_CTRL`, `tcpci_set_cc()` must check `TCPC_POWER_STATUS_VCONN_PRES` and `TCPC_TCPC_CTRL_ORIENTATION`, forcing the VCONN-sourcing CC pin (`CC1` for `TYPEC_POLARITY_CC2`, `CC2` for `TYPEC_POLARITY_CC1`) to `TCPC_ROLE_CTRL_CC_OPEN`. In `tcpci_set_polarity()`, if `TCPC_ROLE_CTRL_DRP` is set, it must read `TCPC_CC_STATUS` via `tcpci_get_cc()`, clear `TCPC_ROLE_CTRL_DRP`, and set the active CC pin from `TCPC_CC_STATUS` and the inactive pin to `TCPC_ROLE_CTRL_CC_OPEN`. [F43, F44]
- In `tcpci_irq()`, `irq_ret` must be latched from `status & tcpci->alert_mask` before `process_status:` rather than recomputed on retry passes, and `TCPC_ALERT_EXTENDED_STATUS` handling must be gated on `tcpci->data->vbus_vsafe0v`. In `tcpci_init()`, after `TCPC_POWER_STATUS_UNINIT` clears, the driver must write `TCPC_FAULT_STATUS_ALL_REG_RST_TO_DEFAULT` to `TCPC_FAULT_STATUS` and `0xffff` to `TCPC_ALERT`. [F67, F108, F109]
