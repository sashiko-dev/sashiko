# KDUMP

The KDUMP component implements primary-kernel crash dump preparation (`crashkernel=` parsing, physical/CMA memory reservation, ELF64 header and per-CPU/vmcoreinfo note generation, CPU/memory hotplug updates, and configfs dm-crypt key staging), panic-time kexec transition, and secondary (kdump) kernel extraction of the previous kernel's ELF headers, notes, device dumps, driver-managed RAM ranges, and dm-crypt keys via `/proc/vmcore` read and mmap operations.

## Architecture & Data Flow
- In `fs/proc/vmcore.c`, `elfcorebuf` must be allocated via `__get_free_pages()` (mapped via `__pa()` and `remap_pfn_range()`), whereas `elfnotes_buf` and `vmcoredd_node->buf` must be allocated via `vmcore_alloc_buf()` (`vmalloc_user()` on `CONFIG_MMU`, mapped via `remap_vmalloc_range_partial()`). `elfcorebuf_sz`, `elfnotes_sz`, and each `vmcoredd_node` size (summed in `vmcoredd_orig_sz`) must be `PAGE_SIZE`-aligned so `mmap_vmcore()` stays page-aligned and `vmcoredd_update_program_headers()` / `vmcore_reset_offsets_elf64()` preserve `PT_LOAD` sub-page offsets. [F43, F113]
- `elfcorebuf_sz_orig` must always match the size whose page order was used to allocate `elfcorebuf` via `__get_free_pages()`, and only be updated when `vmcore_realloc_elfcore_buffer_elf64()` reallocates or resizes within the same order, so `free_elfcorebuf()` passes the matching order to `free_pages()` even after `elfcorebuf_sz` shrinks in `merge_note_headers_elf64()`. [F4]
- Both `__read_vmcore()` and `mmap_vmcore()` place `vmcoredd_list` device dumps at file offsets `[elfcorebuf_sz, elfcorebuf_sz + vmcoredd_orig_sz)` ahead of `elfnotes_buf` at `[elfcorebuf_sz + vmcoredd_orig_sz, elfcorebuf_sz + elfnotes_sz)`, so indexing into `elfnotes_buf` must subtract both `elfcorebuf_sz` and `vmcoredd_orig_sz`. [F42]
- When mutating `/proc/vmcore` layout after `parse_crash_elf_headers()` (in `vmcoredd_update_size()` or `vmcore_add_device_ram_elf64()`), program header offsets in `elfcorebuf`, range offsets in `vmcore_list` via `set_vmcore_list_offsets()`, `vmcore_size` via `get_vmcore_size()`, and `proc_vmcore->size` must all be updated together. In `process_ptload_program_headers_elf64/32()`, `vmcoredd_update_program_headers()`, and `vmcore_reset_offsets_elf64()`, each `vmcore_range` is page-aligned while `phdr->p_offset` must include the sub-page offset `(paddr - start)`. [F44, F64]
- In `merge_note_headers_elf64/32()`, `update_note_header_size_elf64/32()` must run before `get_note_number_and_size_elf64/32()` and `copy_notes_elf64/32()`, and `copy_notes_elf64/32()` must run before `PT_NOTE` program headers in `elfptr` are overwritten and compacted in place via `memmove()` (and the vacated `i` bytes at `elfptr + *elfsz` zeroed). [F46, F93]
- When marking the crash header unusable or consumed in a kdump kernel (in `vmcore_unusable()` or `vmcore_init()`), `elfcorehdr_addr` must be set to `ELFCORE_ADDR_ERR` (`-2ULL`) rather than `ELFCORE_ADDR_MAX` (`-1ULL`) or `0`, so `is_vmcore_usable()` returns `0` while `is_kdump_kernel()` remains `true`. [F25]
- `crashk_res` and `crashk_low_res` store inclusive bounds `[start, end]` when reserved and `{0, 0}` when unreserved, so size queries must use `crash_resource_size()` (`!res->end ? 0 : resource_size(res)`) rather than `resource_size()`. When releasing either resource in `__crash_shrink_memory()` or promoting `crashk_low_res` to `crashk_res` in `crash_shrink_memory()`, `start` and `end` must both be zeroed alongside `release_resource()`. [F50, F54]
- `crash_exclude_mem_range()` requires `mem->ranges` to be sorted in ascending address order so it can `break` when `p_end < start`. Removing or splitting `mem->ranges[i]` requires `memmove()` with byte length `(mem->nr_ranges - (i + 1)) * sizeof(mem->ranges[i])`; on a split (`p_start > start && p_end < end`), `mem->nr_ranges >= mem->max_nr_ranges` must be checked before `memmove()` or mutating `mem->ranges[i]`, and `i` and `mem->nr_ranges` must be updated in lockstep (`i--`/`nr_ranges--` on removal, `i++`/`nr_ranges++` on split). [F49, F69, F88]
- In `reserve_crashkernel_generic()`, any physical memory range reserved for `crashk_res` or `crashk_low_res` must be passed to `kmemleak_ignore_phys()` because the crashkernel region is subsequently removed from the kernel linear map. In `reserve_crashkernel_cma()`, halving `request_size` on failure must use `roundup(request_size / 2, PAGE_SIZE)` after verifying `request_size > PAGE_SIZE`. [F86, F112]
- In `crash_notes_memory_init()`, per-CPU `crash_notes` (`note_buf_t`) must satisfy `sizeof(note_buf_t) <= PAGE_SIZE` and be allocated with alignment `min(roundup_pow_of_two(sizeof(note_buf_t)), PAGE_SIZE)` so each CPU's note buffer stays within one physical page. `crash_save_cpu()` must validate `0 <= cpu < nr_cpu_ids` before indexing `per_cpu_ptr(crash_notes, cpu)` and terminate notes with `final_note(buf)` (`n_namesz == 0` sentinel). [F58, F123]
- In `kernel/crash_dump_dm_crypt.c`, key descriptions, payloads, and counts must be bounded against `KEY_DESC_MAX_LEN`, `KEY_SIZE_MAX`, and `KEY_NUM_MAX` before copying into `struct dm_crypt_key` or allocating `struct keys_header`. Because `struct keys_header::keys` is `__counted_by(total_keys)`, `get_keys_header_size()` must use `struct_size(keys_header, keys, total_keys)` and `build_keys_header()` must set `keys_header->total_keys = key_count` before indexing `keys_header->keys[i]`. [F66, F89]

## Synchronization
- In `fs/proc/vmcore.c`, read-side accesses to `vmcore_cb_list` in `read_from_oldmem()`, `pfn_is_ram()`, and `vmcore_remap_oldmem_pfn()` must be protected by `vmcore_cb_srcu` rather than `vmcore_mutex` or a fair `rw_semaphore`, because `mmap_vmcore()` holds `mm->mmap_lock` while `read_from_oldmem()` may fault on user memory and acquire `mm->mmap_lock`. [F104]
- In `vmcore_add_device_dump()`, the dump buffer must be allocated, initialized with `vmcoredd_write_header()`, and populated by `data->vmcoredd_callback()` before acquiring `vmcore_mutex` to check `vmcore_open` and append `dump->list` to `vmcoredd_list`. Any error path after `dump` or `buf` is allocated—including returning `-EBUSY` when `vmcore_open` is non-zero—must release `vmcore_mutex` and free both `buf` and `dump` with `vfree()`. [F1, F19]
- `__crash_kexec()` may run in NMI or atomic panic context and must only be invoked when `panic_cpu` holds the current CPU (via `panic_try_start()` in `crash_kexec()`), using non-blocking `kexec_trylock()` and busy-wait `mdelay()`. `crash_cma_clear_pending_dma()` must be called after `machine_crash_shutdown()` and before `machine_kexec()` to delay for `CMA_DMA_TIMEOUT_SEC` when `crashk_cma_cnt` is non-zero. [F96, F107]
- `crash_check_hotplug_support()` and `crash_handle_hotplug_event()` must acquire `__crash_hotplug_lock` via `crash_hotplug_lock()` before attempting `kexec_trylock()`, and release `kexec_unlock()` before `crash_hotplug_unlock()`. `crash_shrink_memory()` must hold `kexec_trylock()` continuously across verifying `!kexec_crash_image` and shrinking or swapping `crashk_res` and `crashk_low_res`. [F15, F22]
- In `__read_vmcore()`, the loop iterating over `vmcore_list` must call `cond_resched()` on every iteration (and after reading the ELF note segment) to prevent softlockups and RCU stalls in kdump kernels. [F67]

## Object Lifetimes
- `vmcore_cleanup()` must remove `/proc/vmcore` via `proc_remove(proc_vmcore)` and set `proc_vmcore` to `NULL` before calling `vmcore_free_ranges()`, `free_elfcorebuf()`, and `vmcore_free_device_dumps()`. `free_elfcorebuf()` must reset both `elfcorebuf` and `elfnotes_buf` to `NULL` after freeing them to prevent double-free on subsequent cleanup calls. [F5, F6]
- `unregister_vmcore_cb()` must unlink `cb->next` with `list_del_rcu()` under `vmcore_mutex` and then call `synchronize_srcu(&vmcore_cb_srcu)` after dropping `vmcore_mutex` before returning. [F18]
- `vmcore_process_device_ram()` must call `vmcore_free_ranges(&list)` when `list` overlaps an existing `vmcore_list` entry or `vmcore_add_device_ram_elf64()` fails, and must not free `list` once `vmcore_add_device_ram_elf64()` splices its `struct vmcore_range` nodes into `vmcore_list`. [F2]
- In `mmap_vmcore_fault()`, the page returned by `find_or_create_page()` must be unlocked with `unlock_page(page)` and released with `put_page(page)` if `__read_vmcore()` fails, whereas on success it must be unlocked and have its reference transferred to `vmf->page` without `put_page()`. [F11]
- In `kernel/crash_reserve.c`, `crashk_res` and `crashk_low_res` must be inserted into `iomem_resource` during `reserve_crashkernel_generic()` and `reserve_crashkernel_low()` only when `HAVE_ARCH_ADD_CRASH_RES_TO_IOMEM_EARLY` is defined, and deferred to `early_initcall(insert_crashkernel_resources)` otherwise. [F97]

## API Contracts
- `crash_exclude_mem_range()`, `struct crash_mem::ranges`, `crashk_res`, `crashk_low_res`, and `crashk_cma_ranges` represent physical memory regions with inclusive `[start, end]` bounds (`size = end - start + 1`), whereas `struct vmcore_range` and `vmcore_alloc_add_range()` take `(paddr, size)` with exclusive end `paddr + size`. [F40]
- `copy_oldmem_page()`, `copy_oldmem_page_encrypted()`, `vmcore_remap_oldmem_pfn()`, `remap_oldmem_pfn_checked()`, and `remap_oldmem_pfn_range()` take the target oldmem location as a page frame number (`paddr >> PAGE_SHIFT` or `*ppos / PAGE_SIZE`), while `read_from_oldmem()` (and `elfcorehdr_read()`, `elfcorehdr_read_notes()`, `dm_crypt_keys_read()`) takes `*ppos` as a physical byte address and advances `*ppos` in-place, requiring callers re-reading from `elfcorehdr_addr` or `dm_crypt_keys_addr` to reset their local address variable first. [F39, F41]
- A `struct vmcore_cb` `pfn_is_ram` callback must return `true` when the PFN is RAM or when the callback cannot tell, and return `false` only when the page is known not to be RAM, because `pfn_is_ram()` stops on the first `false` return and substitutes zeroes. [F26]
- A `struct vmcore_cb` `.get_device_ram` callback must only add `PAGE_SIZE`-aligned `paddr` and `size` ranges, and must free any `struct vmcore_range` nodes it allocated before returning a non-zero error code because `vmcore_process_device_ram()` returns immediately without calling `vmcore_free_ranges(&list)`. `vmcore_add_device_ram_elf64()` also requires that `ehdr->e_phnum + count` fits in 16-bit `Elf32_Half` without truncation. [F3, F65]
- Callers of `parse_crashkernel()` that pass a non-NULL `high` pointer must also pass a non-NULL `low_size` pointer (along with non-NULL `crash_size` and `crash_base`), because the `,high` fallback passes `low_size` as `crash_size` to `__parse_crashkernel()`, which executes `BUG_ON(!crash_size || !crash_base)`. [F30]

## Error Handling
- In `read_from_oldmem()`, `nr_bytes` and `tmp` must be signed `ssize_t` so that a negative errno returned by `copy_oldmem_page()` or `copy_oldmem_page_encrypted()` is not promoted to an unsigned value when evaluated in `if (tmp < nr_bytes)`. [F24]
- In `mmap_vmcore()` and `remap_oldmem_pfn_checked()`, if any partial page-range mapping call fails after prior segments have been mapped, all already-mapped bytes (`[vma->vm_start, vma->vm_start + len)` or `[from, from + len)`) must be unmapped with `do_munmap()` before returning `-EAGAIN`. [F34]
- In `reserve_crashkernel_generic()`, `CRASH_ADDR_LOW_MAX` is the inclusive lower bound for high memory; if `crash_base >= CRASH_ADDR_LOW_MAX` requires low memory and `reserve_crashkernel_low(crash_low_size)` fails, `memblock_phys_free(crash_base, crash_size)` must be called and the function must return without populating `crashk_res` or calling `kmemleak_ignore_phys()`. [F33, F53]
- `__parse_crashkernel()` must initialize `*crash_size = 0` and `*crash_base = 0` and return `-ENOENT` when no matching `crashkernel=` option exists versus `-EINVAL` on malformed syntax, because `parse_crashkernel()` branches specifically on `ret == -ENOENT` to fall back to `,high` or apply `DEFAULT_CRASH_KERNEL_LOW_SIZE`. [F27]
- When iterating `config_keys_subsys.su_group.cg_children` in `build_keys_header()`, each `struct config_item` must be checked for `item->ci_type == &config_key_type` before downcasting with `to_config_key(item)` and checked for non-NULL `key->description` before copying with `strscpy()`. [F29]

## External Contracts
- In `merge_note_headers_elf64/32()` and `vmcoredd_update_program_headers()`, the merged `PT_NOTE` header's `p_filesz` and `p_memsz` must equal the unpadded note size (`elfnotes_orig_sz + vmcoredd_orig_sz`), while `PT_LOAD` file offsets begin at the page-aligned `elfcorebuf_sz + elfnotes_sz`. `vmcoredd_write_header()` must populate `name` and `dump_name` with `strscpy_pad()` and set `n_descsz` to `data_size - sizeof(struct vmcoredd_header) + sizeof(vdd_hdr->dump_name)`. [F63, F122]
- `configfs_dmcrypt_keys_init()` must switch `config_keys_subsys.su_group.cg_item.ci_type` from `config_keys_type` to `kdump_config_keys_type` when `is_kdump_kernel()` is true, so the kdump kernel exposes only the `restore` attribute and disables configfs child item creation. [F127]

## Known Pitfalls
- In `update_note_header_size_elf64/32()`, `nhdr_ptr->n_namesz` and `nhdr_ptr->n_descsz` must be widened to `u64` before adding 3 for 4-byte alignment so 32-bit values near `UINT_MAX` do not wrap and bypass `(real_sz + sz) > max_sz`, and advancing `nhdr_ptr` by `sz` requires casting to `char *` first (`(Elf*_Nhdr *)((char *)nhdr_ptr + sz)`). In `mmap_vmcore()` and `mmap_vmcore_fault()`, `vma->vm_pgoff` and `vmf->pgoff` (`pgoff_t`) must be widened to 64-bit (`u64`/`loff_t`) before `<< PAGE_SHIFT`. [F80, F82, F92]
- In `read_from_oldmem()`, `offset` is initialized to `*ppos % PAGE_SIZE` before the `do { ... } while (count)` loop and must be reset to `0` at the end of each iteration. In `remap_oldmem_pfn_checked()`, whenever `!pfn_is_ram(pos)` is hit, any preceding contiguous RAM span (`pos > pos_start`) must be remapped before remapping `zeropage_pfn` and setting `pos_start = pos + 1`, and any trailing RAM span (`pos > pos_start`) must be remapped after the loop. [F71, F73]
- `parse_crashkernel_mem()` rounds `system_ram` up to `SZ_128M` as `total_mem`, matches `[start, end)` (`total_mem >= start && total_mem < end`), and after breaking out of `do { ... } while (*cur++ == ',')` must advance `cur` to `' '` or `'@'` before parsing `@offset`. In `get_last_crashkernel()`, when `!suffix`, any token ending with an entry in `suffix_tbl` (`",high"`, `",low"`, `",cma"`) must be skipped via `goto next` while scanning to the last match. [F56, F74, F75]
- Helper functions in `fs/proc/vmcore.c` reachable from `vmcore_add_device_dump()` or `register_vmcore_cb()` (such as `get_vmcore_size()`, `set_vmcore_list_offsets()`, and `vmcore_alloc_buf()`) must not be marked `__init`. Header declarations in `include/linux/crash_dump.h` and `include/linux/crash_core.h` for overridable hooks (`elfcorehdr_alloc`, `elfcorehdr_free`, `elfcorehdr_read`, `elfcorehdr_read_notes`, `remap_oldmem_pfn_range`, `dm_crypt_keys_read`) must not carry `__weak`. [F98, F115]
