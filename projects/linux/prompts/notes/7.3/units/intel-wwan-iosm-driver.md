# INTEL WWAN IOSM DRIVER

The Intel WWAN IOSM (IPC over Shared Memory) driver provides PCIe host communication for Intel XMM 7360 and 7560 cellular modems, implementing shared-memory descriptor rings, IP multiplexing (MUX Lite and Aggregation), WWAN network interfaces and control ports (AT, MBIM, XMMRPC), devlink firmware flashing and coredump collection, and relayfs/debugfs tracing.

## Architecture & Data Flow

- `ipc_mux->ul_adb.pp_qlt[]` is only allocated when `ipc_mux->protocol != MUX_LITE`, and union accesses in `union mux_type_cmdh`, `union mux_type_header`, and `struct mux_adb` (`adgh` vs `adbh`) must be discriminated by `ipc_mux->protocol == MUX_LITE`. In `struct iosm_mux`, `ipc_mux->session[if_id].wwan != NULL` is the discriminator that session `if_id` is open and must be checked before operating on a session or passing it to `ipc_wwan_receive()` or `ipc_mux_netif_tx_flowctrl()`. [F51, F52]
- Downlink MUX decoders (`ipc_mux_dl_fcth_decode()`, `ipc_mux_dl_adgh_decode()`, `mux_dl_adb_decode()`) must verify `if_id < IPC_MEM_MUX_IP_SESSION_ENTRIES` and clamp `if_id` with `array_index_nospec()` before indexing `ipc_mux->session[if_id]`. In `mux_dl_adb_decode()` and `mux_dl_process_dg()`, `le16_to_cpu(adth->table_length)` must be `>= sizeof(struct mux_adth)`, and each `le32_to_cpu(dg->datagram_index)` must lie within `[sizeof(struct mux_adbh), le32_to_cpu(adbh->block_length))`. [F81, F82]
- Because `ipc_pcie_alloc_skb()` does not zero SKB data and `ipc_mux_ul_encoded_process()` recycles UL ADB SKBs into `ul_adb.free_list` via `skb_trim(skb, 0)` without clearing data, `ipc_mux_acb_alloc()` must zero `MUX_MAX_UL_ACB_BUF_SIZE` bytes at `skb->data`, and `ipc_mux_ul_skb_alloc()` must `memset()` the header (`adbh`, `adgh`, or `qlth_skb->data`) and zero `ul_adb->dg`, `dg_count[]`, and `qlt_updated[]`. Similarly, `ipc_protocol_free_msg_get()` must `memset(msg, 0, sizeof(*msg))` on `p_ap_shm->msg_ring[head]`. [F55, F56, F57]
- In `ipc_protocol_ul_td_send()` and `ipc_protocol_pipe_cleanup()`, the tail index must be read from the host's processed cursor `pipe->old_tail` rather than `p_ap_shm->tail_array[pipe->pipe_nr]`. `ipc_protocol_pipe_cleanup()` must sample `p_ap_shm->head_array[pipe->pipe_nr]` and `pipe->old_tail` before zeroing `head_array` and `tail_array` so all in-flight SKBs in `pipe->skbr_start` between `old_tail` and `head` are freed. [F69, F100]
- In `ipc_imem_dl_skb_process()`, `IPC_CTYPE_CTRL` packets must check `port_id == IPC_MEM_CTRL_CHL_ID_7` and `ipc_is_trace_channel(ipc_imem, port_id)` before the `else` branch that calls `wwan_port_rx(ipc_imem->ipc_port[port_id]->iosm_port, skb)`, because `ipc_imem->ipc_port[]` entries are `NULL` for flash and trace channels. [F92]
- In `ipc_imem_run_state_worker()`, because `ipc_mux_init()` runs before `ipc_imem_wwan_channel_init()` allocates `ipc_imem->wwan`, the worker must set `ipc_imem->mux->wwan = ipc_imem->wwan` after `ipc_imem_wwan_channel_init()` succeeds. When `ipc_imem->mmio->mux_protocol == MUX_AGGREGATION` on `IPC_MEM_IP_CHL_ID_0`, `ipc_imem_wwan_channel_init()` must override `ul_nr_of_entries`, `dl_nr_of_entries`, and `dl_buf_size` in `struct ipc_chnl_cfg` before `ipc_imem_channel_init()`. [F64, F66]
- In `ipc_coredump_get_list()`, `cd_table->list.num_entries` must be bounded to `1..IOSM_NOF_CD_REGION` and each `entry[i].size` must not exceed `devlink->cd_file_info[i].default_size`, because `ipc_coredump_collect()` allocates `default_size` bytes and reads `actual_size` bytes into it. [F78]

## Synchronization

- Every callback queued to `ipc_task_queue_send_task()` runs in `ipc_task_queue_handler()` in softirq tasklet context: callbacks must use `GFP_ATOMIC` and never sleep, and atomic/tasklet code must never call `ipc_protocol_msg_send()` or `ipc_task_queue_send_task(..., true)` (calling tasklet helpers like `ipc_protocol_tq_msg_send()` or `ipc_imem_msg_send_feature_set(..., true)` directly instead). [F34, F129]
- Device and port creation or removal cannot run in softirq tasklet context, so `ipc_imem_handle_irq()` must defer `ipc_devlink_deinit()`, `ipc_mux_init()`, `ipc_imem_wwan_channel_init()`, `ipc_port_init()`, and `ipc_debugfs_init()` to process context via `schedule_work(&ipc_imem->run_state_worker)`. `FULLY_FUNCTIONAL` must be set in `ipc_imem->flag` (with `smp_mb__before_atomic()` / `smp_mb__after_atomic()`) only after all of those initializations succeed. [F24, F132]
- `ipc_task_queue_add_task()` must acquire `ipc_task->q_lock` with `spin_lock_irqsave()` and execute `smp_wmb()` after populating `ipc_task->args[pos]` before updating `ipc_task->q_wpos` for the lockless consumer `ipc_task_queue_handler()`. [F131]
- In `ipc_wwan_init()`, `ipc_wwan->dev` and `ipc_wwan->ipc_imem` must be initialized before `wwan_register_ops()`, which synchronously invokes `ipc_wwan_newlink()` for `IP_MUX_SESSION_DEFAULT`. `ipc_wwan_newlink()` must publish `priv` to `ipc_wwan->sub_netlist[if_id]` with `rcu_assign_pointer()` only after `register_netdevice()` succeeds, and `ipc_wwan_dellink()` must clear `sub_netlist[if_id]` with `RCU_INIT_POINTER(..., NULL)` before `unregister_netdevice_queue()`. [F20, F136]
- Readers of `ipc_wwan->sub_netlist[if_id]` (`ipc_wwan_receive()` and `ipc_wwan_tx_flowctrl()`) must hold `rcu_read_lock()` across `rcu_dereference(ipc_wwan->sub_netlist[if_id])` and all accesses to `priv`, `priv->netdev`, and `netif_rx(skb)`. In `ipc_wwan_receive()`, `skb` must be set to `NULL` after `netif_rx(skb)` so `dev_kfree_skb(skb)` after `rcu_read_unlock()` only frees `skb` when `if_id` is invalid or `priv` is `NULL`. [F19, F137]
- In `ipc_protocol_tq_msg_send()`, `ipc_protocol_msg_prep()` must populate `p_ap_shm->msg_ring[index]` and `ipc_protocol->rsp_ring[index]` must be stored before `ipc_protocol_msg_hp_update()` advances `p_ap_shm->msg_head` and rings the HPDA doorbell. [F39]
- In `ipc_pm_wait_for_device_active()`, bit `CONSUME_STATE` (0) of `ipc_pm->host_sleep_pend` must be set (with `smp_mb__before_atomic()` / `smp_mb__after_atomic()`) before waiting on `ipc_pm->host_sleep_complete` and cleared afterwards, pairing with `test_bit()` in `ipc_pm_on_link_wake()`. When `ipc_pm_signal_hpda_doorbell()` defers a doorbell via `ipc_pm->pending_hpda_update = true`, `ipc_pm_on_link_wake()` must re-invoke `ipc_pm_signal_hpda_doorbell()` once `ipc_pm->host_pm_state == IPC_MEM_HOST_PM_ACTIVE`. [F38, F71]

## Object Lifetimes

- SKBs allocated via `ipc_pcie_alloc_skb()` store their DMA address, direction, and original mapped length in `IPC_CB(skb)`, while `ipc_pcie_alloc_local_skb()` must initialize `IPC_CB(skb)->mapping = 0`. `ipc_pcie_kfree_skb()` (or `ipc_pcie_addr_unmap()` using `IPC_CB(skb)->len`) must only be called on SKBs whose `IPC_CB(skb)` was initialized by `ipc_pcie_alloc_local_skb()`, `ipc_pcie_alloc_skb()`, or `ipc_imem_map_skb_to_dma()`, and DMA-mapped SKBs must never be freed directly with `dev_kfree_skb()`. [F58, F148]
- In `ipc_imem_dl_skb_process()`, downlink SKBs on `IPC_CTYPE_CTRL` channels must be DMA-unmapped with `ipc_pcie_addr_unmap()` before being passed to `ipc_imem_sys_devlink_notify_rx()`, `ipc_trace_port_rx()`, or `wwan_port_rx()`. Conversely, `IPC_CTYPE_WWAN` SKBs remain mapped until `ipc_mux_dl_decode()` calls `ipc_pcie_kfree_skb()`, so `ipc_mux_net_receive()` must pass a `skb_clone(skb, GFP_ATOMIC)` copy (adjusted with `skb_pull(dest_skb, offset)` and `skb_trim(dest_skb, pkt_len)`) to `ipc_wwan_receive()`. [F3, F141, F146]
- SKBs dequeued from `ipc_mux->ul_adb.free_list` in `ipc_mux_ul_skb_alloc()` are tagged with `UL_MUX_OP_ADB` and, once completed on the UL pipe, must be recycled through `ipc_mux_ul_encoded_process()`—which decrements `ipc_mux->ul_data_pend_bytes`, calls `skb_trim(skb, 0)`, and requeues `skb` to `free_list`—rather than freed via `ipc_pcie_kfree_skb()`. [F68]
- `ipc_imem->ipc_devlink` is only allocated on `IPC_MEM_EXEC_STAGE_BOOT` (tracked by `IOSM_DEVLINK_INIT`), while `mux`, `wwan`, `ipc_port[]`, and `trace` are only allocated in `ipc_imem_run_state_worker()` (tracked by `FULLY_FUNCTIONAL`). Both `ipc_imem_run_state_worker()` and `ipc_imem_cleanup()` must guard `ipc_devlink_deinit()` with `test_and_clear_bit(IOSM_DEVLINK_INIT, &ipc_imem->flag)`, and `ipc_imem_cleanup()` must guard `ipc_mux_deinit()`, `ipc_debugfs_deinit()`, `ipc_wwan_deinit()`, and `ipc_port_deinit()` with `test_and_clear_bit(FULLY_FUNCTIONAL, &ipc_imem->flag)`. [F17, F47]
- `ipc_protocol_pipe_cleanup()` must set both `pipe->skbr_start = NULL` and `pipe->tdr_start = NULL` after freeing them because `ipc_imem_pipe_cleanup()` is invoked both when closing individual channels and again across all `ipc_imem->nr_of_channels` channels during `ipc_imem_channel_reset()`. [F8]
- `ipc_protocol_msg_send()` passes stack-allocated `send_args` and `response` (`struct ipc_rsp`) to the tasklet queue and stores `&response` in `ipc_protocol->rsp_ring[index]`, so both `ipc_protocol_tq_msg_send_cb` and the timeout cleanup `ipc_protocol_tq_msg_remove` must be queued with `wait = true`. In `ipc_task_deinit()`, `tasklet_kill()` must stop `ipc_task->ipc_tasklet` before `ipc_task_queue_cleanup()` drains `ipc_task->ipc_queue`. [F28, F111]

## API Contracts

- `ipc_protocol_msg_prep()`, `ipc_protocol_tq_msg_send()`, `ipc_mux_schedule()`, `ipc_mux_open_session()`, `ipc_mux_close_session()`, and `ipc_imem_sys_wwan_open()` return a non-negative 0-based ring index or `channel_id` on success and a negative errno on failure; callers must store the result in a signed `int` and check `< 0` rather than `!= 0`. Conversely, `ipc_mux_ul_adb_allocate()` returns `false` on success and `true` on failure. [F40, F42, F43]
- `ipc_task_queue_send_task()` duplicates `msg` with `kmemdup(msg, size, GFP_ATOMIC)` and frees it after `args->func` returns when `size > 0`, whereas `size == 0` forwards `msg` directly without copying or freeing it; callers passing persistent objects (`&channel->dl_pipe`) or synchronous stack args (`&send_args`) must pass `size = 0`. [F110]
- `ipc_imem_channel_alloc()` returns the compacted slot index `i` in `ipc_imem->channels[i]` (passed to `ipc_imem_channel_open()` and `ipc_imem_channel_close()`), while overwriting `channel->channel_id` with the logical `enum ipc_channel_id` `index` used to index `ipc_imem->ipc_port[]`. [F93]
- `FULLY_FUNCTIONAL` (0), `IOSM_DEVLINK_INIT` (1), and `CONSUME_STATE` (0) are bit numbers for `set_bit()`/`test_bit()`, whereas `IPC_MEM_WWAN_MUX` (`BIT(0)`), `UL_AGGR` (`BIT(8)`), `DL_AGGR` (`BIT(9)`), and `UL_FLOW_CREDIT` (`BIT(21)`) are pre-shifted bitmasks. `ipc_imem_msg_send_feature_set()` takes an unshifted value (`0` or `IPC_MEM_INBAND_CRASH_SIG` = 1) in `reset_enable` because `ipc_protocol_msg_prep_feature_set()` shifts it left by `RESET_BIT` (7). [F59, F60]
- In `ipc_wwan_link_transmit()`, when `ipc_imem_sys_wwan_transmit()` returns 0 the SKB is owned by `session->ul_list`, when it returns `-EBUSY` the SKB must not be freed (`NETDEV_TX_BUSY`), and on any other non-zero return `ipc_wwan_link_transmit()` must free `skb` via `dev_kfree_skb_any()`. In `ipc_imem_sys_cdev_write()`, if `ipc_imem_call_cdev_write()` fails after queuing `skb`, it must `skb_dequeue_tail(&channel->ul_list)` and return a negative errno without freeing `skb`. [F5, F151]
- `ipc_imem_sys_devlink_read()` rejects any SKB with `bytes_to_read < skb->len`, returns 0 for any packet with `skb->len <= bytes_to_read`, and leaves `*bytes_read` unmodified on error; callers expecting a fixed-size message must check both `ret == 0` and `bytes_read == expected_size`. [F45, F79]
- `ipc_coredump_collect()` must allocate `*data` using `vmalloc()` (and free it with `vfree()` on error) because `ipc_devlink_create_region()` sets `vfree` as the `devlink_region_ops.destructor`. Conversely, because `fw->data` is vmalloc memory that cannot be passed to `dma_map_single()`, `ipc_flash_boot_psi()` must copy the PSI payload with `kmemdup(..., GFP_KERNEL)` before `ipc_imem_sys_devlink_write()` maps it via `ipc_pcie_addr_map()`. [F16, F142]

## Error Handling

- When `ipc_mux_ul_adgh_encode()` or `mux_ul_dg_encode()` inspects a packet via `skb_peek(ul_list)`, it must leave `src_skb` on `ul_list` and not call `dev_kfree_skb(src_skb)` if ADB allocation or space checks fail before `src_skb` is copied and dequeued. [F4]
- In `ipc_pcie_probe()`, `pci_enable_device()` and `dma_set_mask(ipc_pcie->dev, DMA_BIT_MASK(64))` must succeed before `ipc_imem_init()` allocates DMA memory. In both `ipc_pcie_probe()` error paths and `ipc_pcie_cleanup()`, `ipc_imem_cleanup()` must run before `ipc_pcie_resources_release()`, followed by `pci_release_regions()` and `pci_disable_device()`. If `request_threaded_irq()` fails at index `i` in `ipc_acquire_irq()`, `ipc_pcie->nvec` must be set to `i` before calling `ipc_release_irq()`. [F11, F85, F116]
- In `ipc_imem_run_state_worker()`, if `ipc_imem_wwan_channel_init()` fails after `ipc_mux_init()` succeeds, `ipc_mux_deinit(ipc_imem->mux)` must be called before returning. In `ipc_mux_init()`, if allocating `pp_qlt[i]` fails, prior `pp_qlt[0 .. i - 1]` and `ipc_mux` must be freed; if a subsequent `ipc_pcie_alloc_skb()` fails, `ipc_mux_deinit(ipc_mux)` must be called. [F12, F13]
- In `ipc_devlink_create_region()`, `devlink_region_create()` returns an `ERR_PTR` (not `NULL`) on failure; when index `i` fails, `ipc_devlink_create_region()` must unwind only indices `i - 1` down to `0` and `ipc_devlink_init()` must jump past `ipc_devlink_destroy_region()`. [F53]

## Known Pitfalls

- Unlike `struct mux_adth` (which ends with `dg[]` so `sizeof(struct mux_adth)` excludes `struct mux_adth_dg` elements and callers must not subtract `sizeof(struct mux_adth_dg)`), `struct mux_qlth` and `struct ipc_mem_lite_gen_tbl` embed a trailing single-element `ql` or `vfl` member, so their total byte sizes must be computed from `offsetof(..., ql)` or `offsetof(..., vfl)` rather than `sizeof(...)`. [F108, F109]
- In `ipc_mux_ul_encode_adth()`, `ul_adb->next_table_index` points into `ul_adb->buf`, so when emitting a `struct mux_qlth` at `p_adb_qlt`, `memcpy(p_adb_qlt, ul_adb->pp_qlt[i], qlt_size)` must occur before any subsequent table writes through `*ul_adb->next_table_index`. In `mux_ul_dg_encode()`, whenever `mux_ul_dg_update_tbl_index()` flushes and allocates a new ADB mid-loop, `nr_of_skb`, `offset`, and `dg` must be reset for the new ADB. [F97, F113]
- In `iosm_ipc_pm.c`, bitfields in `union ipc_pm_cond` (`irq`, `hs`, `link`) use `IPC_PM_ACTIVE` (`1`) and `IPC_PM_SLEEP` (`0`), which is inverted relative to `enum ipc_mem_dev_pm_state` (`IPC_MEM_DEV_PM_ACTIVE == 0`) and `enum ipc_mem_host_pm_state` (`IPC_MEM_HOST_PM_ACTIVE == 0`). [F99]
- In `ipc_imem_channel_alloc()`, `channel` remains pointing to `&ipc_imem->channels[ipc_imem->nr_of_channels - 1]` when no match is found, so `i >= ipc_imem->nr_of_channels` must be checked before inspecting `channel`. In `ipc_mmio_init()`, the retry loop polling `ipc_mmio_get_exec_stage()` must use pre-decrement (`--retries > 0`) because the post-loop timeout check tests `if (!retries)`. [F89, F94]
