# BROADCOM NETXTREME-E ROCE DRIVER

The Broadcom NetXtreme-E RoCE driver (`bnxt_re`, under `drivers/infiniband/hw/bnxt_re`) implements an InfiniBand/RDMA Verbs provider over Broadcom NetXtreme-C/E Ethernet NICs via the auxiliary bus and the `bnxt_en` Upper Layer Protocol (ULP) interface. It manages RDMA hardware resources, Doorbell Pacing, Congestion Control, hardware statistics, and debugfs/restrack diagnostics while translating IB verbs into fast-path work/completion queue operations (`qplib_fp`) and slow-path RDMA Controller Firmware (RCFW) commands (`qplib_rcfw`).

## Architecture & Data Flow
- For user-space QPs, `bnxt_re_init_user_qp()` sets `qplib_qp->qp_handle` to `ureq->qp_handle` rather than `&qp->qplib_qp`, so kernel paths that downcast `qp_handle` or touch kernel CQ flush lists (`bnxt_qplib_add_flush_qp()`, `bnxt_qplib_clean_qp()`) must only run on kernel QPs/CQs (`rdma_is_kernel_res(&qp->ib_qp.res)` / `!qp->sumem` / `!cq->umem`). Also, because `IB_USER_VERBS_CMD_POLL_CQ` is enabled, `bnxt_re_poll_cq()` on user CQs (`cq->umem != NULL`) must return 0 after `bnxt_re_resize_cq_complete()` without polling CQEs or dereferencing `cq->cql`. [F126, F173]
- In `bnxt_re_nq_record`, `BNXT_RE_MAX_MSIX` must equal `BNXT_MAX_ROCE_MSIX`; `msix_entries[0]` (`BNXT_RE_AEQ_IDX`) serves the CREQ while NQs use `msix_entries[1..num_msix-1]` (`BNXT_RE_NQ_IDX`) and map to `rdev->nqr->nq[0..num_msix-2]`. `bnxt_re_start_irq()` must refresh `msix_entries[].vector` from `ent[]` before restarting CREQ and NQ (at `indx - 1`) IRQs. CQ/SRQ lifecycle operations must track load via `nq->load` under `rdev->nqr->load_lock` without modifying `nq->budget`, and `bnxt_re_synchronize_nq()` must restore `nq->budget` after polling. [F8, F52, F61]
- When `bnxt_qplib_service_nq()` processes CQ or SRQ notifications, it must update `cq->toggle`/`srq->toggle`, `dbinfo.toggle`, the userspace shared page (`*uctx_cq_page` or `*uctx_srq_page`), and call `bnxt_qplib_armen_db()` before invoking `nq->cqn_handler` or `nq->srqn_handler`. `uctx_cq_page`/`uctx_srq_page` and `hash_entry` are populated only when `BNXT_QPLIB_CQ_TOGGLE_BIT` or `BNXT_QPLIB_SRQ_TOGGLE_BIT` is set in `rdev->chip_ctx->modes.toggle_bits`, so teardown and NQ paths must guard their use. [F43, F56]
- `rdev->qplib_res.pacing_data` (`rdev->pacing.dbr_page`) and pacing work items (`dbq_fifo_check_work`, `dbq_pacing_work`) are initialized only when `rdev->pacing.dbr_pacing` is true. Because `bnxt_re_pacing_alert()` sets `pacing_data->do_pacing` and `alarm_th` to max on the shared `dbr_page` to suppress duplicate alerts, `bnxt_re_db_fifo_check()` must read `rdev->pacing.do_pacing_save` to compute the next pacing rate and update both `do_pacing_save` and `alarm_th`. [F44, F69]
- In `bnxt_qplib_cq_process_req()`, `do_wa9060()` must be guarded by `!bnxt_qplib_is_chip_gen_p5_p7(qp->cctx)`, clearing `sq->condition` and setting `sq->single` only when a phantom REQ CQE (`wr_id == BNXT_QPLIB_FENCE_WRID`) arrives and keeping `sq->single` true until SWQEs up to `cqe_sq_cons` complete. When a QP moves to error or enters the SQ flush list (`bnxt_qplib_mark_qp_error()`, `__bnxt_qplib_add_flush_qp()`, or `__flush_sq()`), `bnxt_qplib_cancel_phantom_processing()` must clear `sq.condition`, `sq.send_phantom`, and `sq.single`. [F65, F66, F142]
- In `bnxt_qplib_cq_process_req()`, `__flush_sq()`, and `bnxt_qplib_cq_process_terminal()`, any `while (*budget)` path that skips emitting a software CQE (such as `BNXT_QPLIB_FENCE_WRID` or unsignaled WQEs) must still advance `sq->hwq.cons` via `bnxt_qplib_hwq_incr_cons()` and update `sq->swq_last = swq->next_idx`. [F103]
- When polling CQE, NQE, or CREQ rings, `CQE_CMP_VALID`, `NQE_CMP_VALID`, or `CREQ_CMP_VALID` must be checked and followed by `dma_rmb()` before reading descriptor fields, and consumer advancement must use `bnxt_qplib_hwq_incr_cons()` to toggle `BNXT_QPLIB_FLAG_EPOCH_CONS_SHIFT` on wrap. In responder CQE handlers, hardware `wr_id_idx` must be bounds-checked against `srq->hwq.max_elements` or `rq->max_wqe - 1` and `rq->swq_last` before indexing `swq[]`. [F87, F88]
- Because `bnxt_qplib_cqe` stores the `immdata`/`invrkey` union in host endianness (`le32_to_cpu()`), `bnxt_re_poll_cq()` must check `CQ_RES_RC_FLAGS_IMM` to convert `cqe->immdata` with `cpu_to_be32()` for `wc->ex.imm_data` while assigning `cqe->invrkey` directly to `wc->ex.invalidate_rkey`. [F81]
- Before indexing `rcfw->crsqe_tbl[cookie]`, the cookie must be masked with `RCFW_MAX_COOKIE_VALUE` to strip `RCFW_CMD_IS_BLOCKING` (`0x8000`). In `map_qp_id_to_tbl_indx()`, `qid == 1` (QP1) maps to `rcfw->qp_tbl_size - 1`, and other QP IDs map to `qid % (rcfw->qp_tbl_size - 2)` with the subtraction parenthesized. [F84, F91]
- In `bnxt_qplib_post_send()`, when `qp->is_host_msn_tbl` is true, `bnxt_qplib_fill_psn_search()` must only run for wire WQEs (`msn_update == true`), skipping UD/GSI sends, `LOCAL_INV`, `FAST_REG_MR`, and `BIND_MW`. PSNs (`sq->psn`, `qp->send_psn`) must be masked with `BTH_PSN_MASK` on every increment and assignment to `swq->start_psn`/`next_psn`. [F67, F118]
- When transitioning a QP from INIT to RTR in `__modify_flags_from_init_state()`, `CMDQ_MODIFY_QP_MODIFY_MASK_VLAN_ID` must not be cleared from `qp->modify_flags`. On pre-GenP5 adapters where `IB_QPT_GSI` uses `rdev->gsi_ctx.gsi_sqp`, `bnxt_re_modify_qp()` must mirror state, `pkey_index`, `qkey`, and `sq.psn` onto `gsi_sqp` via `bnxt_re_modify_shadow_qp()`, and `bnxt_re_destroy_qp()` must call `bnxt_re_destroy_gsi_sqp()`. [F59, F70]

## Synchronization
- `bnxt_re_lock_cqs()` and `bnxt_qplib_acquire_cq_flush_locks()` must lock `qp->scq` first (`spin_lock_irqsave`) and `qp->rcq` second only when `qp->rcq != qp->scq`, unlocking in reverse under the same check. Callers of `bnxt_qplib_add_flush_qp()` or `bnxt_qplib_clean_qp()` must hold `bnxt_re_lock_cqs()` before acquiring `flush_lock`. `bnxt_qplib_clean_qp()` must scrub matching `qp_handle` entries in `scq`/`rcq` (`__clean_cq()`), reset `sq`/`rq` `hwq.prod` and `hwq.cons` to 0, and remove the QP from `sqf_head`/`rqf_head`. [F11, F23, F64]
- In `bnxt_qplib_create_qp()` and `bnxt_qplib_destroy_qp()`, updates to `rcfw->qp_tbl[]` must use `spin_lock_bh(&rcfw->tbl_lock)`, and `bnxt_qplib_process_qp_event()` must hold `spin_lock(&rcfw->tbl_lock)` across looking up `qp_handle`, calling `bnxt_qplib_mark_qp_error()`, and invoking `rcfw->creq.aeq_handler()`. [F20]
- `rcfw->cmdq.hwq.lock` must be acquired with `spin_lock_bh()` in process context (`__send_message()`, `__bnxt_qplib_rcfw_send_message()`) and `spin_lock_nested(&hwq->lock, SINGLE_DEPTH_NESTING)` in `bnxt_qplib_process_qp_event()` (under `rcfw->creq.hwq.lock`). Under `cmdq.hwq.lock`, `crsqe->is_waiter_alive` and `crsqe->resp` are synchronized, `bnxt_qplib_process_qp_event()` must issue `smp_wmb()` after copying `crsqe->resp` before clearing `crsqe->is_in_used = false`, and `__send_message()`/`__send_message_no_waiter()` (whose callers must hold `cmdq.hwq.lock`) must execute `wmb()` before `writel()` to `cmdq_mbox`. [F26, F27, F151]
- `bnxt_qplib_service_nq()` and `bnxt_qpn_cqn_sched_task()` must hold `spin_lock_bh(&cq->compl_lock)` while accessing `cq->arm_state`, updating `cq->cnq_events`, and calling `nq->cqn_handler()`, with `bnxt_qpn_cqn_sched_task()` rechecking `atomic_read(&cq->arm_state)` under `compl_lock`. In `bnxt_qplib_post_send()`/`post_recv()` (under `sq_lock`/`rq_lock`), `bnxt_qplib_nq_work` must be allocated with `GFP_ATOMIC`. [F30, F159]
- Because `bnxt_re_pacing_alert()` and `bnxt_re_db_fifo_check()` call `cancel_work_sync()` and `cancel_delayed_work_sync()` while holding `rdev->pacing.dbq_lock`, worker functions `bnxt_re_db_fifo_check()` and `bnxt_re_pacing_timer_exp()` must acquire `rdev->pacing.dbq_lock` with `mutex_trylock()` rather than `mutex_lock()`. [F18]

## Object Lifetimes
- All updates to `en_info->rdev` must be serialized with `rtnl_lock()` via `bnxt_re_update_en_info_rdev()`, cleared to `NULL` on `bnxt_re_add_device()` rollback and in `bnxt_re_suspend()`, and checked for `NULL` in `bnxt_re_remove()` and ULP callbacks (`bnxt_re_async_notifier()`, `bnxt_re_stop_irq()`, `bnxt_re_start_irq()`), which must extract `en_info` via `auxiliary_get_drvdata(handle)` rather than casting `handle` to `bnxt_re_dev *`. [F15, F119]
- `bnxt_re_dev_init()` must only call `bnxt_re_register_netdev()` on `BNXT_RE_COMPLETE_INIT`, and `bnxt_re_dev_uninit()` must only call `bnxt_unregister_dev()` on `BNXT_RE_COMPLETE_REMOVE`, preserving ULP state across suspend/resume. During `bnxt_re_suspend()`, if `BNXT_STATE_FW_FATAL_COND` is set, the driver must set `ERR_DEVICE_DETACHED` and `BNXT_RE_FLAG_ERR_DEVICE_DETACHED`, wake `cmdq.waitq`, and call `bnxt_re_dev_stop()`, which must only dispatch `IB_EVENT_QP_FATAL` without calling `bnxt_re_modify_qp()`. [F134, F137]
- In `bnxt_re_dev_uninit()`, `bnxt_re_net_unregister_async_event()` (passing persistent `&rdev->event_bitmap`, never a stack variable) must run before `bnxt_re_uninit_dcb_wq()`, `bnxt_re_deinitialize_dbr_pacing()` must cancel `dbq_fifo_check_work` and `dbq_pacing_work` before freeing `dbr_page`, and `bnxt_re_free_gid_ctx()` must run before `bnxt_re_cleanup_res()`/`bnxt_re_free_res()`. In `bnxt_re_alloc_res()`, `bnxt_qplib_get_dev_attr()` must run before `bnxt_qplib_alloc_res()`. [F5, F17, F130, F131]
- In `bnxt_re_destroy_qp()`, `bnxt_qplib_flush_cqn_wq()` and `bnxt_qplib_destroy_qp()` (which clears `rcfw->qp_tbl[tbl_indx]` under `rcfw->tbl_lock` before `CMDQ_BASE_OPCODE_DESTROY_QP` and restores it on failure) must run before `bnxt_qplib_clean_qp()` and `bnxt_qplib_free_qp_res()`, followed by `bnxt_re_synchronize_nq()` on `scq_nq`/`rcq_nq`. `bnxt_qplib_destroy_cq()` must call `__wait_for_all_nqes()` before freeing `cq->hwq`. [F10, F68, F164]
- During `bnxt_re_resize_cq()`, old `cq->umem` and `cq->qplib_cq.hwq` must stay allocated until `bnxt_re_poll_cq()` calls `bnxt_re_resize_cq_complete()` and `bnxt_qplib_resize_cq_complete()` to free old `cq->hwq`, swap in `resize_hwq`, clear only `BNXT_QPLIB_FLAG_EPOCH_CONS_SHIFT` in `dbinfo.flags`, and promote `resize_umem`/`resize_cqe`; error rollback in `bnxt_re_resize_cq()` must release and NULL `cq->resize_umem` and restore `sg_info`/`dpi`. [F7, F62]
- Once `bnxt_re_mmap_entry_insert()` succeeds, `bnxt_re_user_mmap_entry` must be released via `rdma_user_mmap_entry_remove()`, not `kfree()`. `uctx->dpi` is lazily allocated on the first user PD in `bnxt_re_alloc_pd()` and freed only in `bnxt_re_dealloc_ucontext()`, while `bnxt_re_dealloc_pd()` only removes `pd->pd_db_mmap`. [F2, F73]
- In `bnxt_re_create_fence_mr()`, `fence->dma_addr`, `mr->ib_mr.lkey`/`rkey`, and `fence->mw` must only be set after each step succeeds, and any `ERR_PTR` result (e.g., `cq->resize_umem`, `fence->mw`) must be reset to `NULL` on `IS_ERR()` because teardown paths check non-NULL to unwind. In `bnxt_qplib_free_hwq()`, `__free_pbl()` must pass `is_umem = hwq->is_user` only for the leaf level (`i == hwq->level`) and `false` for non-leaf levels. In `bnxt_re_create_ah()` and `bnxt_re_modify_qp()`, `rdma_read_gid_hw_context()` returns a borrowed reference whose `ctx->refcnt` must not be modified. [F6, F19, F46, F166]

## API Contracts
- Callers of `bnxt_qplib_rcfw_cmd_prep()` and `bnxt_re_init_hwrm_hdr()` must zero-initialize stack request structs first. When passing a DMA side buffer (`msg->sb`), callers must align `sbuf.size` to `BNXT_QPLIB_CMDQE_UNITS` (16 bytes), pre-populate `req.resp_size` with `sbuf.size / BNXT_QPLIB_CMDQE_UNITS`, and verify `!rc` from `bnxt_qplib_rcfw_send_message()` before reading `sbuf.sb`. [F34, F49, F121]
- In `__send_message()`, `bnxt_qplib_get_cmd_slots()` and the free-slot check must run before `bnxt_qplib_set_cmd_slots()` mutates `req->cmd_size` in place using ceiling division `(req->cmd_size + BNXT_QPLIB_CMDQE_UNITS - 1) / BNXT_QPLIB_CMDQE_UNITS`, while `__get_cmdq_base_cmd_size()` for `crsqe->req_size` must run after. Non-sleepable RCFW callers (e.g., `bnxt_re_create_ah()`/`destroy_ah()` without sleepable flags) must set `cmdqmsg.block = true`, and HWRM callers of `bnxt_re_fill_fw_msg()` must pass `BNXT_RE_HWRM_CMD_TIMEOUT(rdev)` (multiplying seconds by 1000). [F55, F57, F115, F153]
- Before creating an SRQ, QP, or CQ, callers must set `sg_info.pgsize = PAGE_SIZE` and `sg_info.pgshft = PAGE_SHIFT` for both kernel and user queues; `bnxt_qplib_alloc_init_hwq()` callers must set `aux_depth = 0` when `aux_stride == 0`; and `bnxt_qplib_create_srq()` must call `bnxt_qplib_armen_db(&srq->dbinfo, DBC_DBC_TYPE_SRQ_ARMENA)` unconditionally. [F47, F111, F144]
- CQE helpers called by `bnxt_qplib_poll_cq()` and `bnxt_qplib_process_flush_list()` must advance `*pcqe` and decrement `*budget` in lockstep for each CQE written. In `bnxt_re_aeq_handler()` and `bnxt_re_handle_affi_async_event()`, `void *obj` is `NULL` for `CREQ_BASE_TYPE_FUNC_EVENT`, `bnxt_qplib_qp *` for QP error events, and `bnxt_qplib_cq *` for CQ error events, so callers must check event types before downcasting. [F124, F127]
- `bnxt_re_copy_wr_payload()` returns `-EINVAL` if inline data exceeds `BNXT_QPLIB_SWQE_MAX_INLINE_LENGTH`, so callers must store the return in a signed `int` and check `< 0`. `bnxt_re_add_gid()` must handle `-EALREADY` from `bnxt_qplib_add_sgid()` by incrementing `sgid_tbl->ctx[tbl_idx]->refcnt` and returning 0. [F37, F38]

## Error Handling
- In `bnxt_re_mmap()`, every path after `rdma_user_mmap_entry_get()` returns a non-NULL `rdma_entry` must call `rdma_user_mmap_entry_put(rdma_entry)` before returning; `BNXT_RE_MMAP_DBR_PAGE` and `BNXT_RE_MMAP_TOGGLE_PAGE` must reject `vma->vm_flags & VM_WRITE` with `-EFAULT` before `vm_insert_page()`, whereas PCI BAR mappings must use `rdma_user_mmap_io()`. `qp->qplib_qp.srq` is `NULL` on QPs without an SRQ, so `bnxt_re_handle_qp_async_event()` must check non-NULL before `container_of()`. [F3, F40, F165]
- In `__bnxt_qplib_rcfw_send_message()`, non-zero `evnt->status` must return `-EIO`. When `ERR_DEVICE_DETACHED` is set on `rcfw->cmdq.flags`, RCFW wait/poll functions must map the return code via `bnxt_qplib_map_rc(opcode)` (0 for destroy opcodes, `-ETIMEDOUT` otherwise), and `bnxt_re_net_ring_free()`/`bnxt_re_net_stats_ctx_free()` must return 0 immediately when `BNXT_RE_FLAG_ERR_DEVICE_DETACHED` is set. [F32, F99, F135]

## Known Pitfalls
- In `bnxt_re_post_send()`, `bnxt_re_post_send_shadow_qp()`, `bnxt_re_post_recv()`, and `bnxt_re_post_recv_shadow_qp()`, the stack `struct bnxt_qplib_swqe wqe` must be zeroed on every loop iteration. In `bnxt_re_build_qp1_send_v2()`, `wqe->sg_list` must be shifted up using a reverse loop (`for (i = wqe->num_sge; i; i--)`) before inserting the header SGE at `sg_list[0]`. [F48, F125]
- In `bnxt_qplib_post_send()`, `case BNXT_QPLIB_SWQE_TYPE_SEND:` must `break` only when `qp->type == CMDQ_CREATE_QP1_TYPE_GSI` and otherwise fall through to `SEND_WITH_IMM`/`INV`; PSN packet count calculation must guard against `qp->mtu == 0` before dividing and clamp `pkt_num` to at least 1 when `data_len == 0`. In `bnxt_re_process_res_rc_wc()`, `IB_WC_RECV_RDMA_WITH_IMM` requires `(cqe->flags & (CQ_RES_RC_FLAGS_RDMA | CQ_RES_RC_FLAGS_IMM)) == (CQ_RES_RC_FLAGS_RDMA | CQ_RES_RC_FLAGS_IMM)`. [F93, F96, F114]
- Cast to `u64` before shifting by >= 24 or 32 bits: `st_idx` and `npsn` in `bnxt_re_update_msn_tbl()`, `cq_handle_high`/`srq_handle_high` in `clean_nq()` and `bnxt_qplib_service_nq()`, and `hwrm_intf_major`/`minor` in `bnxt_re_query_hwrm_intf_version()`. [F107, F108, F109]
