# AMD IOMMU (AMD-VI)

The AMD IOMMU (AMD-Vi) driver implements DMA address translation, device isolation, Shared Virtual Addressing (SVA/PASID), I/O page fault (PPR/IOPF) handling, and interrupt remapping (including Guest Virtual APIC / AVIC) for x86 systems with AMD IOMMU hardware. It parses ACPI IVRS (IVHD/IVMD) tables during boot to discover IOMMU hardware units and device mappings, manages v1 (host) and v2 (guest/x86-64 compatible) IO page tables via the io-pgtable framework, and exposes `iommu_ops`, `irq_domain_ops`, and KVM/perf interfaces.

## Architecture & Data Flow

- Physical addresses written to IOMMU registers, DTEs, IRTEs, GCR3 tables, and IO page tables (including `gcr3` in `update_gcr3()` and `amd_iommu_set_gcr3()`) must include the SME encryption mask via `iommu_virt_to_phys()` or `__sme_set()`, and addresses read back for CPU mapping or `iova_to_phys` must strip it via `iommu_phys_to_virt()` or `__sme_clr()`. In `build_completion_wait()`, use `iommu->cmd_sem_paddr` rather than `iommu_virt_to_phys((void *)iommu->cmd_sem)` because kdump with `FEATURE_SNP` maps `cmd_sem` via `iommu_memremap()`. [F63, F178, F179]
- In `struct amd_iommu`, ring buffer pointers (`cmd_buf`, `evt_buf`, `ppr_log`, `ga_log`) are `u8 *` and head/tail offsets (`MMIO_*_HEAD_OFFSET`, `MMIO_*_TAIL_OFFSET`, `cmd_buf_head`, `cmd_buf_tail`) are byte offsets, so pointer math must add byte offsets or multiply indices by entry byte size before casting. In `__iommu_queue_command_sync()`, `left = (iommu->cmd_buf_head - next_tail) % CMD_BUFFER_SIZE` requires unsigned `u32` operands and a power-of-two `CMD_BUFFER_SIZE` (8192). [F130, F135]
- `amd_iommu_reset_cmd_buffer()` must disable `CONTROL_CMDBUF_EN`, zero both hardware registers (`MMIO_CMD_HEAD_OFFSET`, `MMIO_CMD_TAIL_OFFSET`) and software cursors (`cmd_buf_head`, `cmd_buf_tail`), and re-enable `CONTROL_CMDBUF_EN`. In `iommu_print_event()` and `amd_iommu_poll_ppr_log()`, consumed ring entries must be zeroed in memory when `!amd_iommu_snp_en` (and not written when `amd_iommu_snp_en` is true) so wrap-around polling detects unwritten entries. [F83, F119]
- Because `amd_iommu_resume()` restores hardware state via `early_enable_iommu()` (`iommu_init_flags()`, `iommu_enable_gt()`) and `amd_iommu_enable_interrupts()`, persistent `MMIO_CONTROL_OFFSET` feature bits (`CONTROL_EPH_EN`, `CONTROL_GT_EN`) must be configured in those helpers rather than only during initial PCI probe. In `iommu_init_pci()`, `late_iommu_features_init()` must run before checking `FEATURE_GT` or calling `iommu_enable_gt()`. [F153, F164]
- Every failure path in `state_next()` must transition `init_state` to `IOMMU_NOT_FOUND`, `IOMMU_INIT_ERROR`, or `IOMMU_CMDLINE_DISABLED` so `iommu_go_to_state()` exits its `while (init_state != state)` loop. Any failure or early exit in `amd_iommu_detect()`, `iommu_go_to_state()`, or `iommu_snp_enable()` before `amd_iommu_snp_en` and `snp_rmptable_init()` succeed must clear `CC_ATTR_HOST_SEV_SNP` via `cc_platform_clear()`. [F81, F110]
- When `amd_iommu_set_dirty_tracking()` toggles `pdomain->dirty_tracking` under `pdomain->lock`, it must update `DTE_FLAG_HAD` in `dte->data[0]` under `dev_data->dte_lock` and call `device_flush_dte()` for every device in `pdomain->dev_list`, then call `amd_iommu_domain_flush_all(pdomain)`. [F77]
- `irq_remap_table->table` is typed as `u32 *` but holds 128-bit `struct irte_ga` entries when `AMD_IOMMU_GUEST_IR_GA(amd_iommu_guest_ir)` is true and 32-bit `union irte` entries otherwise; code indexing or sizing `table->table` must branch on `AMD_IOMMU_GUEST_IR_GA(amd_iommu_guest_ir)` or use `iommu->irte_ops`. In `struct amd_ir_data`, `ga_root_ptr` must be `u64` (not 32-bit) to preserve all 40 bits of `(pi_data->vapic_addr >> 12)` in `amd_iommu_activate_guest_mode()`. [F102, F124]
- In `irte_ga_set_affinity()`, host affinity updates (`vector` and `dest_apicid`) must not be written to `irte` or flushed via `modify_irte_ga()` when `irte->lo.fields_remap.guest_mode` is set; host `irq_cfg` is saved in `ir_data->cfg` and restored by `amd_iommu_deactivate_guest_mode()`. [F78]
- Functions taking a generic `struct device *` must check `dev_is_pci(dev)` before dereferencing `to_pci_dev(dev)` because ACPI HID platform devices (`acpihid_map`) are also managed. In `struct amd_iommu_pci_seg`, `last_bdf` is an inclusive maximum BDF (`<= 0xffff`), so per-BDF tables require `last_bdf + 1` elements and `0..last_bdf` loops require a counter wider than `u16`. [F88, F138]
- In ACPI IVRS parsing, `struct ivhd_header` is 40 bytes only for types `0x11`/`0x40` and 24 bytes for type `0x10` (advance by `get_ivhd_header_size(h)` and only read `efr_reg`/`efr_reg2` on `0x11`/`0x40`), and `struct ivhd_entry` has variable size so loops must advance by `ivhd_entry_length(p)` rather than `sizeof`. [F97, F98]

## Synchronization

- Nested lock acquisitions must obey the order `iommu_dev_data.mutex` -> `{ protection_domain.lock, iommu_table_lock }` -> `iommu_dev_data.dte_lock` -> `amd_iommu.lock`. `struct amd_iommu.lock` and `struct irq_remap_table.lock` must remain `raw_spinlock_t` acquired via `raw_spin_lock_irqsave()` because IRQ remapping callbacks (`irq_remapping_activate()`, `irq_remapping_deactivate()`, `amd_ir_set_affinity()`) invoke them while holding raw `irq_desc` locks. [F31, F170]
- `protection_domain.lock` (`spin_lock_irqsave()`) must be held for all mutations and traversals of `domain->dev_list`, all operations on `sva_pdom->dev_data_list` and GCR3 updates in `pasid.c`, and all accesses and `refcnt` updates on `domain->iommu_array` (`pdom_attach_iommu()`, `pdom_detach_iommu()`, `domain_flush_pages_v1()`, `domain_flush_complete()`). Allocations under `protection_domain.lock` (`pdom_attach_iommu()`, `__get_gcr3_pte()`) must use `GFP_ATOMIC`. [F27, F29, F30, F168]
- In `attach_device()` and `detach_device()`, sleeping PCI capability and IOPF queue operations (`pdev_enable_caps()`, `pdev_disable_caps()`, `amd_iommu_iopf_add_device()`, `amd_iommu_iopf_remove_device()`, `iopf_queue_flush_dev()`) must execute under `dev_data->mutex` outside `spin_lock_irqsave(&domain->lock, flags)`. [F167]
- Updates to a device's 256-bit `dev_table_entry` must hold `iommu_dev_data.dte_lock`, and `write_dte_upper128()` must read `ptr->data128[1]` and preserve `DTE_DATA2_INTR_MASK` in `new->data[2]` inside `dte_lock` so DMA DTE updates do not clobber interrupt-remapping fields written by `set_dte_irq_entry()`. [F32]
- All IRTE slot allocations, modifications, and frees in `struct irq_remap_table` (`alloc_irq_index()`, `__modify_irte_ga()`, `modify_irte()`, `free_irte()`, `dump_irte()`) must hold `table->lock` (`raw_spinlock_t`), and 128-bit IRTE updates in `__modify_irte_ga()` must use `try_cmpxchg128()`. [F36]

## Object Lifetimes

- In `detach_device()`, `dev_update_dte()` and `amd_iommu_domain_flush_all()` must execute before `list_del(&dev_data->list)`, `destroy_gcr3_table()`, and `pdom_detach_iommu()`, because domain cache invalidation iterates `domain->dev_list` and `domain->iommu_array`. Also, when `dev_data->ppr` is true, `iopf_queue_flush_dev(dev)` must precede `amd_iommu_iopf_remove_device(iommu, dev_data)`, which must only be called when `dev_data->ppr` is true. [F1, F6]
- In `attach_device()`, if `pdom_is_sva_capable(domain)` holds and `init_gcr3_table(dev_data, domain)` fails after `pdom_attach_iommu(iommu, domain)` succeeded, `pdom_detach_iommu(iommu, domain)` must be called before unlocking `dev_data->mutex`. In `pasid.c`, `iommu_sva_set_dev_pasid()` pairs `amd_iommu_set_gcr3()` with adding `pdom_dev_data` to `sva_pdom->dev_data_list`, and `remove_dev_pasid()` must call `amd_iommu_clear_gcr3()`, `list_del()`, and `kfree()`. [F4, F13]
- `protection_domain_alloc()` allocates both `struct protection_domain` and an IDA ID via `pdom_id_alloc()`, so callers failing after it (`do_iommu_domain_alloc()`, `amd_iommu_domain_alloc_sva()`) must free both `domain->id` via `pdom_id_free()` and `domain` (or call `amd_iommu_domain_free()`). For SVA domains, `iommu_sva_domain_free()` must call `mmu_notifier_unregister(&sva_pdom->mn, domain->mm)` when `sva_pdom->mn.ops` is set before `amd_iommu_domain_free(domain)`. [F3, F14]
- `alloc_dev_data()` keeps each `struct iommu_dev_data` in `pci_seg->dev_data_list` for the segment's lifetime (`amd_iommu_release_device()` retains `dev_data` and asserts `WARN_ON(dev_data->domain)`). In `iommu_init_device()`, `dev_iommu_priv_set(dev, dev_data)` must precede `setup_aliases(iommu, dev)` because `clone_alias()` calls `dev_iommu_priv_get(&pdev->dev)`. [F10, F11]
- `alloc_irq_table()` drops `iommu_table_lock` to allocate `new_table` via `__alloc_irq_table()` and re-acquires `iommu_table_lock` to re-check `pci_seg->irq_lookup_table[devid]` and `[alias]`, clearing `new_table = NULL` if installed and otherwise freeing `new_table->table` and `new_table` after unlocking. [F15]
- `amd_iommu_init_identity_domain()` and `amd_iommu_iopf_init(iommu)` must complete before `iommu_device_register()` in `amd_iommu_init_pci()`/`iommu_init_pci()`, and `free_iommu_one()` must call `free_sysfs(iommu)` before freeing buffers, logs, MMIO, and the IOPF queue. In `state_next()`, if initialization fails after `irq_remapping_enabled` is set, call `free_dma_resources()` and `uninit_device_table_dma()` rather than `disable_iommus()` or `free_iommu_resources()`. [F18, F19, F42]
- In kdump kernels (`is_kdump_kernel()`), `pci_seg->dev_table`, `iommu->cmd_buf`, `iommu->evt_buf`, and (when `check_feature(FEATURE_SNP)` is true) `iommu->cmd_sem` are mapped with `iommu_memremap()` and must be released with `memunmap()` rather than `iommu_free_pages()`. In `early_enable_iommus()`, `reuse_device_table()` must free `pci_seg->dev_table` before overwriting it with `old_dev_tbl_cpy`, or `memunmap(old_dev_tbl_cpy)` on failure. [F20, F150]

## API Contracts

- `blocked_domain` and `release_domain` are standalone `struct iommu_domain` instances not embedded in `struct protection_domain`, so their callbacks (`blocked_domain_attach_device`, `blocked_domain_set_dev_pasid`) must never pass `domain` to `to_pdomain()`. Also, `protection_domain_alloc()` returns `NULL` on failure, whereas `iommu_ops` domain allocation callbacks must return `ERR_PTR(-errno)`. [F46, F137]
- `get_amd_iommu_from_dev()` and `get_amd_iommu_from_dev_data()` must only be called after `amd_iommu_probe_device()` completes; functions running during device probe (`check_device()`, `iommu_init_device()`, `clone_alias()`, `amd_iommu_probe_device()`) must use `rlookup_amd_iommu()`. [F50]
- `amd_iommu_def_domain_type()` must check `dev_is_pci(dev) && to_pci_dev(dev)->untrusted` and return `IOMMU_DOMAIN_DMA` before any `IOMMU_DOMAIN_IDENTITY` heuristics, and must never return `IOMMU_DOMAIN_IDENTITY` when `CC_ATTR_MEM_ENCRYPT` or `amd_iommu_snp_en` is active. [F183]
- `amd_iommu_activate_guest_mode()` and `amd_iommu_deactivate_guest_mode()` must save `valid`, zero `entry->lo.val` and `entry->hi.val`, rebuild all fields for the target mode (even if `guest_mode` is already set), and call `modify_irte_ga()` to flush the IRT. Also, `amd_iommu_register_ga_log_notifier(NULL)` must call `synchronize_rcu()` after clearing `iommu_ga_log_notifier`. [F22, F79]

## Error Handling

- `get_acpihid_device_id()`, `get_device_sbdf_id()`, `get_ioapic_devid()`, `get_hpet_devid()`, and `get_devid()` return a non-negative 32-bit SBDF or a negative errno; callers must store the result in a signed `int` and test `< 0` before applying `PCI_SBDF_TO_DEVID()` or `PCI_SBDF_TO_SEGID()`. [F44]
- `search_dev_data()` returns `NULL` when no `struct iommu_dev_data` exists for `devid` (such as IOAPIC or HPET entries), so interrupt remapping callers (`set_dte_irq_entry()`, `iommu_get_int_tablen()`, `irq_remapping_alloc()`, `amd_ir_set_vcpu_affinity()`) must check `dev_data` for `NULL`. Also, `amd_ir_set_vcpu_affinity()` must return `-EINVAL` (not `0`) when `!AMD_IOMMU_GUEST_IR_VAPIC(amd_iommu_guest_ir)`, `!ir_data->iommu`, or `!dev_data || !dev_data->use_vapic`. [F43, F54]
- `destroy_gcr3_table()` must check `if (gcr3_info->gcr3_tbl == NULL) return;` before calling `free_gcr3_table(gcr3_info)`, because passthrough domains on non-PASID devices skip GCR3 allocation while `free_gcr3_table()` unconditionally frees `gcr3_info->domid`. [F53]
- `iommu_page_make_shared()` must immediately return on error from `snp_lookup_rmpentry()`, when `!assigned` (`-EINVAL`), or when `psmash()` fails, before calling `rmp_make_shared()`. In `amd_iommu_report_page_fault()`, DMA faults on an attached device must suppress logging when `report_iommu_fault()` returns `0`, and all fault logs must be ratelimited. [F56, F194]

## External Contracts

- In `update_dte256()`, `write_dte_upper128()` must precede `write_dte_lower128()` when setting `DTE_FLAG_V` or `DTE_FLAG_GV`, `write_dte_lower128()` must precede `write_dte_upper128()` when clearing either bit, and changing `DTE_GPT_LEVEL_MASK` (`data[2]`) on a valid `DTE_FLAG_GV` DTE requires clearing `data128[0]` via `write_dte_lower128()` and calling `iommu_flush_dte_sync()` first. In `set_dte_gcr3_table()`, `gcr3` must be split across `DTE_GCR3_14_12` (`gcr3 >> 12` in `data[0]`), `DTE_GCR3_30_15` (`gcr3 >> 15` in `data[1]`), and `DTE_GCR3_51_31` (`gcr3 >> 31` in `data[1]`). [F65, F132, F156]
- In `pdev_enable_caps()`, `pdev_enable_cap_pasid()` must precede `pdev_enable_cap_ats()`, which must precede `pdev_enable_cap_pri()`, because PCIe forbids modifying PASID Enable while ATS is enabled and `pdev_enable_cap_pri()` requires `dev_data->ats_enabled`. [F142]
- In `amd_iommu_handle_irq()`, after writing 1s to clear `int_mask | overflow_mask` in `MMIO_STATUS_OFFSET` and running log handlers, re-read `MMIO_STATUS_OFFSET` in a loop until those bits read as 0 (hardware bug ERBT1312). In `enable_iommus_vapic()` and `iommu_ga_log_enable()`, poll `MMIO_STATUS_OFFSET` until `MMIO_STATUS_GALOG_RUN_MASK` clears/sets when disabling/enabling `CONTROL_GALOG_EN`. [F158, F161]

## Known Pitfalls

- `iommu_feature_enable()` and `iommu_feature_disable()` take an unshifted bit index (`CONTROL_*` in `0..63`), whereas `check_feature()` and `check_feature2()` take a pre-shifted 64-bit bitmask (`FEATURE_*`), and `set_dte_bit()` takes a `0..255` bit index (`DEV_ENTRY_*`) rather than a pre-shifted `DTE_FLAG_*` mask. [F62]
- Every IOMMU command builder must zero `struct iommu_cmd` with `memset(cmd, 0, sizeof(*cmd))` before calling `CMD_SET_TYPE()`, which ORs the opcode into `cmd->data[1]`. In `pasid.c`, loops over `pdom->dev_data_list` calling `remove_dev_pasid()` (which unlinks and `kfree`s its argument) must use `for_each_pdom_dev_data_safe()` or `break` immediately. [F57, F112]
- In `struct unity_map_entry`, `devid_start` and `devid_end` are inclusive bounds, whereas `address_end` is an exclusive bound (`address_start + PAGE_ALIGN(m->range_length)`), so range length is `entry->address_end - entry->address_start` without `+ 1`. Also, `amd_iommu_irq_ops` callbacks (`amd_iommu_enable_faulting()`, `amd_iommu_disable()`, `amd_iommu_reenable()`) must not be marked `__init`. [F93, F154]
