# DRM DRIVERS FOR BRIDGE CHIPS

This component provides the core DRM bridge subsystem (`drm_bridge.c`, `drm_bridge.h`), the generic bridge connector helper (`drm_bridge_connector.c`), and drivers for Toshiba (`tc358768`, `tc358775`), Thine (`thc63lvd1024`), Texas Instruments (`ti-sn65dsi83`, `ti-tdp158`, `ti-tfp410`, `ti-tpd12s015`), and Waveshare (`waveshare-dsi`) bridge chips. It manages linear bridge chains attached to DRM encoders, reference-counted lifecycles, bus format negotiation, modeset state propagation, and delegated connector operations (EDID, HPD, modes, HDMI/DP audio, and CEC).

## Architecture & Data Flow

- Reverse bridge chain traversals in `drm_atomic_bridge_chain_disable()`, `drm_atomic_bridge_chain_pre_enable()`, and `drm_atomic_bridge_chain_check()` must stop their `list_for_each_entry_reverse()` loop when `iter == bridge`. In `drm_atomic_bridge_chain_pre_enable()`, when `iter->pre_enable_prev_first` is true, the inner reverse scan must stop at `next == bridge` or `!next->pre_enable_prev_first` and set `iter = limit` after enabling `iter` before checking `if (iter == bridge) break;`. [F11, F81]
- In `drm_atomic_bridge_chain_post_disable()`, the inner forward scan over consecutive `pre_enable_prev_first` bridges must explicitly break when `list_is_last(&next->chain_node, &encoder->bridge_chain)` or `!next->pre_enable_prev_first` (backing up `next = list_prev_entry(next, chain_node)` on the latter), and set `limit = next` so `bridge = limit` skips the reversed sub-chain. [F80]
- In `select_bus_fmt_recursive()` and `drm_atomic_bridge_chain_select_bus_fmts()`, format-selection loops must only continue iterating while `ret == -ENOTSUPP` (`if (ret != -ENOTSUPP) break;`), and `select_bus_fmt_recursive()` must only index `in_bus_fmts[i]` when `!ret`. [F83]
- In `drm_bridge_connector_init()`, if `bridge_connector->bridge_hdmi` is present and any bridge in the chain has `ycbcr_420_allowed` false (clearing `connector->ycbcr_420_allowed`), `BIT(HDMI_COLORSPACE_YUV420)` must be cleared from `supported_formats` before calling `drmm_connector_hdmi_init()`. [F51]
- When `bridge_connector->bridge_hdmi` is non-NULL, `drm_bridge_connector_detect()` updates connector EDID state via `drm_atomic_helper_connector_hdmi_hotplug(connector, status)`, and `drm_bridge_connector_get_modes()` must check `bridge_connector->bridge_hdmi` before `bridge_edid` and `bridge_modes` so it calls `drm_edid_connector_add_modes(connector)` directly without re-running EDID detection. [F58, F85]
- `__devm_drm_bridge_alloc()` registers `drm_bridge_put_void` with the embedded `struct drm_bridge *bridge` pointer (not `container`), so `drm_bridge_put_void()` and `devm_drm_put_bridge()` require the `void *` devres data argument to be the `struct drm_bridge *` address. [F99]
- In `tc358768_calc_pll()`, `tc358768_bridge_mode_valid()` must pass `verify_only = true` so validation returns before mutating `priv` PLL fields (`fbd`, `prd`, `frs`, `dsiclk`, `pclk`), and after searching `frs_limits` for `target_pll >= frs_limits[i]`, both `i == 0` and `i == ARRAY_SIZE(frs_limits)` must be rejected before indexing `frs_limits[i - 1]` and `frs_limits[i]`. [F65, F71]
- In `tc358768_dsi_host_transfer()`, `msg->tx_len` must be rejected with `-ENOTSUPP` when greater than 8 bytes because the long-packet loop writes 16-bit words to `TC358768_DSICMD_WD0 + i` and hardware only provides four 16-bit data registers (`TC358768_DSICMD_WD0`..`TC358768_DSICMD_WD3` at `0x0610`..`0x0616`) before `TC358768_DSI_EVENT` (`0x0620`). [F69]
- `tc358775_parse_dt()` must validate `tc->num_dsi_lanes` to 1..4 via `drm_of_get_data_lanes_count(..., 1, 4)` before `tc_bridge_atomic_enable()` uses `tc->num_dsi_lanes` as a shift exponent in `L0EN << tc->num_dsi_lanes` and as a divisor in `dsiclk`, `t1`, and `t3`. [F95]
- In `sn65dsi83_parse_lvds_endpoint()`, `ti,lvds-termination-ohms` must be validated as 100 or 200 and mapped to `OHM_100` (0) or `OHM_200` (1) in `ctx->lvds_term_conf[channel]` before passing it to `sn65dsi83_select_lvds_vod_swing()` to index `lvds_vod_swing_data_table` and `lvds_vod_swing_clock_table`. [F75]

## Synchronization

- In `drivers/gpu/drm/drm_bridge.c`, the global `bridge_list` is protected by `bridge_lock`, which must be held across every insertion, removal, lookup, and iteration (`drm_bridge_add`, `drm_bridge_remove`, `of_drm_find_bridge`, and `allbridges_show`). [F14]
- In `drm_bridge_connector_handle_hpd`, `dev->mode_config.mutex` must be acquired to update `connector->status` and released before invoking `drm_bridge_connector_hpd_notify` and `drm_kms_helper_connector_hotplug_event`, preserving the lock order `bridge->hpd_mutex` -> `dev->mode_config.mutex` when called via `drm_bridge_connector_hpd_cb`. [F18]
- In `drm_bridge_attach`, `bridge->dev`, `bridge->encoder`, and `bridge->chain_node` insertion into `encoder->bridge_chain` must be completed before invoking `bridge->funcs->attach(bridge, encoder, flags)`. [F20]
- In `sn65dsi83_atomic_disable`, hardware error monitoring must be stopped (`REG_IRQ_EN`/`REG_IRQ_GLOBAL` cleared when `ctx->irq` is set, or `sn65dsi83_monitor_stop` calling `cancel_delayed_work_sync(&ctx->monitor_work)` when polling) before asserting `ctx->enable_gpio` reset and disabling `ctx->vcc`. [F23]
- In `tc358768.c`, `drm_bridge_add(&priv->bridge)` must only be called inside `tc358768_dsi_host_attach` after `priv->output`, `priv->dsi_lanes`, `priv->dsi_bpp`, and `priv->pd_lines` are initialized, and `tc358768_dsi_host_detach` must call `drm_bridge_remove(&priv->bridge)` before `drm_panel_bridge_remove(priv->output.bridge)`. [F27]
- In `tpd12s015_probe`, `tpd->hpd_gpio` must be stored before `devm_request_threaded_irq` registers `tpd12s015_hpd_isr` (which must be a threaded IRQ with a `NULL` primary handler and `IRQF_ONESHOT` because `tpd12s015_detect` and `drm_bridge_hpd_notify` can sleep), and `DRM_BRIDGE_OP_HPD` must be set in `tpd->bridge.ops` before `drm_bridge_add(&tpd->bridge)`. [F26, F132]

## Object Lifetimes

- When a bridge driver registers its `struct drm_bridge` with `drm_bridge_add()` in `.probe` (such as `sn65dsi83_probe()`, `tc_probe()`, `tfp410_init()`, `thc63_probe()`, or `tpd12s015_probe()`), it must call `drm_bridge_remove()` in `.remove` and on post-add `.probe` error paths, never in `drm_bridge_funcs.detach`. I2C-controlled DSI bridges (`tc_probe()`, `sn65dsi83_probe()`) must call `drm_bridge_add()` before `devm_mipi_dsi_attach()` and `drm_bridge_remove()` if host attach fails. [F4, F111]
- Bridges attached to an encoder via `drm_bridge_attach()` are automatically detached during `drm_encoder_cleanup()`, so bridge drivers must not call `drm_bridge_detach()` on their downstream bridge in their `drm_bridge_funcs.detach` or bus `.remove` callbacks. [F103]
- Every `struct device_node *` acquired from OF graph helpers (`of_graph_get_endpoint_by_regs()`, `of_graph_get_remote_port_parent()`, `of_graph_get_remote_endpoint()`, `of_graph_get_remote_node()`, or `of_graph_get_port_by_id()`) in bridge drivers must be released with `of_node_put()` on all normal and error paths. [F6]

## API Contracts

- Every `struct drm_bridge` passed to `drm_bridge_add()` or `devm_drm_bridge_add()` must be allocated via `devm_drm_bridge_alloc()` with a non-NULL `drm_bridge_funcs` pointer (not `devm_kzalloc()`), and because it returns an `ERR_PTR` on failure (never `NULL`), callers must check `IS_ERR()` and propagate `PTR_ERR()`. [F28, F133]
- In `drm_bridge_attach(encoder, bridge, previous, flags)`, `bridge` (second parameter) is the unattached downstream bridge (`bridge->dev == NULL`) and `previous` (third parameter) is the already-attached upstream bridge (`previous->dev != NULL && previous->encoder == encoder`); swapping them returns `-EBUSY` or `-EINVAL`. [F44]
- `drm_bridge_edid_read()` (via `drm_bridge_funcs.edid_read`) transfers ownership of the returned `const struct drm_edid *` to the caller, which must free it with `drm_edid_free()` even when `drm_edid_valid()` returns false. [F8]
- In `struct drm_bridge_funcs`, `.atomic_reset()` returns an `ERR_PTR` on failure (checked with `IS_ERR()` in `drm_bridge_attach()`), whereas `.atomic_duplicate_state()` returns `NULL` on failure (checked for truthiness in `drm_bridge_atomic_duplicate_priv_state()`). [F30]
- In `drm_atomic_bridge_check()`, `.atomic_check()` returns `0` or a negative errno and takes precedence over `.mode_fixup()`, which returns `bool` (`false` mapped to `-EINVAL`) and is never called when `.atomic_check()` is non-NULL. Because `drm_atomic_bridge_propagate_bus_flags()` overwrites `bridge_state->output_bus_cfg.flags` and `input_bus_cfg.flags` right before `drm_atomic_bridge_check()`, a bridge that customizes bus flags must do so in `.atomic_check` and not set `.mode_fixup`. [F45, F137]
- Implementations of `drm_bridge_funcs.atomic_get_input_bus_fmts` and `atomic_get_output_bus_fmts` must return a `kmalloc()`-allocated `u32` array and set `*num_input_fmts` or `*num_output_fmts` to the array length, or set the count to 0 when no formats are supported (returning `NULL` with a non-zero count is treated as `-ENOMEM`). [F136]
- In `drm_atomic_bridge_chain_select_bus_fmts()`, when the last bridge does not implement `atomic_get_output_bus_fmts`, `conn->display_info.bus_formats[0]` may only be accessed after verifying that both `conn->display_info.num_bus_formats` and `conn->display_info.bus_formats` are non-zero/non-NULL, falling back to `MEDIA_BUS_FMT_FIXED` otherwise. [F78]
- Bridge drivers must keep `drm_bridge_funcs` as `static const` in read-only memory and advertise `detect`, `get_modes`, `edid_read`, or HPD via `bridge->ops`, never setting `DRM_BRIDGE_OP_DETECT`, `DRM_BRIDGE_OP_MODES`, or `DRM_BRIDGE_OP_EDID` unless the corresponding callback is implemented. [F138]
- Only one hot-plug callback may be registered on a `struct drm_bridge` at a time via `drm_bridge_hpd_enable()` (calling it again before `drm_bridge_hpd_disable()` triggers `WARN` and is ignored), and bridge drivers must invoke `drm_bridge_hpd_notify()` only from a sleeping context because it acquires `bridge->hpd_mutex`. [F143]

## Error Handling

- `of_drm_find_bridge()` returns `NULL` when no matching bridge is registered, whereas `devm_drm_of_get_bridge()` and `drmm_of_get_bridge()` return an `ERR_PTR`, so callers must check `!bridge` for `of_drm_find_bridge()` and `IS_ERR(bridge)` for the managed helpers. [F29]
- Exported bridge chain traversal helpers in `drm_bridge.c` (such as `drm_atomic_bridge_chain_check()`, `drm_bridge_chain_mode_valid()`, and the chain enable/disable functions) accept a `NULL` `bridge` pointer and must check `!bridge` before dereferencing `bridge->encoder`. [F37]
- `drm_atomic_get_new_bridge_state()` returns `NULL` for bridges without atomic state hooks, so `select_bus_fmt_recursive()` (when `.atomic_get_input_bus_fmts` is NULL) and `drm_atomic_bridge_propagate_bus_flags()` must null-check `cur_state`, `bridge_state`, and `next_bridge_state` before dereferencing them. [F39]
- In `tc358768_bridge_atomic_pre_enable()`, once `tc358768_hw_enable(priv)` enables `priv->refclk`, `priv->supplies`, and `priv->reset_gpio`, any failure in `tc358768_sw_reset()`, `tc358768_setup_pll()`, or format validation must call `tc358768_hw_disable(priv)` to roll back hardware power and `priv->enabled`. [F10]
- In `tc358768.c`, `tc358768_read()` is a no-op when `priv->error` is non-zero and leaves `*val` unmodified if `regmap_bulk_read()` fails on a 32-bit register, so callers such as `tc358768_update_bits()` must check `if (priv->error) return;` after `tc358768_read()` before using the read value. [F32]
- Callers of `drm_of_get_data_lanes_count()` (`tc358775_parse_dt()`, `sn65dsi83_host_attach()`) must store its return value in a signed `int` and check `< 0` before assigning to an unsigned lane-count field; similarly, `tpd12s015_probe()` must store `gpiod_to_irq()` in a signed `int` (`tpd->hpd_irq`) and check `>= 0` (not truthiness or `> 0`). [F35, F36]
- In `sn65dsi83_parse_lvds_endpoint()`, `lvds_vod_swing_data` and `lvds_vod_swing_clk` must be pre-initialized to `{ 0, 1000000 }` and `lvds_term` to `200`, and any `of_property_read_u32_array()` return value other than `0` or `-EINVAL` must abort before `lvds_vod_swing_conf` is used. [F46]

## External Contracts

- For bridges with active-low reset or powerdown GPIOs (`reset_gpio` in `tc358768` and `tc358775`, `stby_gpio` in `tc358775`, `pdwn` in `thc63lvd1024`, `powerdown` in `ti-tfp410`), `gpiod` calls use logical polarity where `GPIOD_OUT_HIGH` / `1` asserts reset or powerdown and `0` deasserts it to enable the chip. [F117]
- In `ti-sn65dsi83`, `bridge.pre_enable_prev_first` must be `true` so the DSI host enters LP-11/HS clock before `sn65dsi83_atomic_pre_enable()` locks `REG_RC_LVDS_PLL` and triggers `REG_RC_RESET_SOFT_RESET` (converting 16-bit timing values written via `regmap_bulk_write()` to `__le16` with `cpu_to_le16()`), while `sn65dsi83_atomic_enable()` clears `REG_IRQ_STAT` (write-1-to-clear) after video starts. [F76, F119]
- After starting a MIPI DSI command transfer by writing `TC358768_DSI_CMDTX_DC_START` to `TC358768_DSICMD_TX`, `tc358768_dsicmd_tx()` must poll `TC358768_DSICMD_TX` with `regmap_read_poll_timeout()` until `TC358768_DSI_CMDTX_DC_START` clears before returning or issuing another command. [F114]
- In `tc358775`, `d2l_read()`/`d2l_write()` encode 16-bit addresses as big-endian (`put_unaligned_be16`) and 32-bit values as little-endian (`put_unaligned_le32`); `tc_bridge_atomic_enable()` must set `EVTMODE` in `VPCTRL` only on `TC358765`, map `LVI_R2`..`R7`/`G2`..`G7`/`B2`..`B7` onto the first three LVDS lane pairs in `LV_MX0003`..`LV_MX2427` for JEIDA-18/24, and write `VFUEN_EN` to `VFUEN` to latch updates. [F122, F123]

## Known Pitfalls

- In `drm_bridge_connector_init()`, after `drm_for_each_bridge_in_chain(encoder, bridge)` finishes, the `bridge` cursor points to the list head rather than a valid bridge, so post-loop setup blocks must reassign `bridge` from `bridge_connector->bridge_*` before dereferencing `bridge`. [F79]
- In `tfp410_parse_timings()`, `pclk_sample`, `bus_width`, and `deskew` must be initialized to their defaults (`0`, `24`, and `0`) before `of_property_read_u32()` because return values of those optional DT reads are ignored; `deskew` (`u32`) must be checked for `deskew <= 7` and cast to `(s32)deskew` before subtracting 4, and `timings->hold_time_ps` must be clamped with `max(0, ...)` before assigning to `u32`. [F48, F77]
- In `tc358768`, `tc358768_write()` and `tc358768_read()` access registers in `0x100 <= reg < 0x600` as 2-word (32-bit) big-endian transfers and registers outside that range as 1-word (16-bit) transfers, so `tc358768_read()` must zero `*val` before 16-bit reads and access tables (`tc358768_writeable_reg()`, `tc358768_readable_reg()`) must cover `reg` through `reg + 2` for 32-bit registers. [F112]
- In `tc358768` clock/timing helpers (`tc358768_pll_to_pclk()`, `tc358768_pclk_to_pll()`, `tc358768_calc_pll()`, `tc358768_dpi_to_ns()`, `tc358768_dpi_to_dsi_bytes()`, `tc358768_dsi_bytes_to_ns()`), `u32` rates/counts and `unsigned long refclk` must be cast to `u64` before multiplying and divided via `div_u64()` (rounding up in `tc358768_dpi_to_dsi_bytes()`), while `tc358768_ns_to_cnt()` must use `DIV_ROUND_UP(ns * 1000, period_ps)` with `ns` small enough not to overflow `u32`. [F89, F90, F91]
