# IOMMU SUBSYSTEM

Core Linux IOMMU subsystem infrastructure and SoC-specific IOMMU hardware drivers (Freescale PAMU, Renesas IPMMU-VMSA, MediaTek M4U v1/v2, TI OMAP IOMMU, and Unisoc SPRD IOMMU). It manages IOMMU device and group lifecycles, domain allocation and attachment (including PASID and Shared Virtual Addressing), IOVA-to-physical mapping/unmapping, IO page table allocation and page fault queues (IOPF), and Device Tree/firmware translation (`of_iommu`).

## Architecture & Data Flow
- In `iommu_setup_default_domain()`, `group->default_domain` must be set to `dom` before calling `__iommu_group_set_domain_internal()` or `__iommu_group_set_domain()`, and both `group->domain` and `group->default_domain` must revert to `old_dom` if post-attach setup fails when `old_dom` is non-NULL. [F56]
- `__iommu_take_dma_ownership()` and `__iommu_release_dma_ownership()` require `xa_empty(&group->pasid_array)` and must switch `group->domain` to `group->blocking_domain` when setting `group->owner` and back to `group->default_domain` when clearing `group->owner` and `group->owner_cnt`. [F61]
- Entries in `group->pasid_array` (created via `iommu_make_pasid_array_entry()`) are tagged XArray pointers (`IOMMU_PASID_ARRAY_DOMAIN` or `IOMMU_PASID_ARRAY_HANDLE`); readers must check `xa_pointer_tag()` and strip the tag with `xa_untag_pointer()` before dereferencing. [F135]
- In `iommu_attach_device_pasid()`, `__iommu_set_group_pasid()`, and `__iommu_remove_group_pasid()`, every loop over `group->devices` must check `device->dev->iommu->max_pasids > 0`, verify `pasid < max_pasids` and `pasid != IOMMU_NO_PASID`, and skip devices with `max_pasids == 0`; global PASIDs are allocated in `[IOMMU_FIRST_GLOBAL_PASID, dev->iommu->max_pasids - 1]` (reserving `0`), and `iommu_alloc_mm_data()` must reject an existing `mm->iommu_mm` when `iommu_mm->pasid >= dev->iommu->max_pasids`. [F80, F81, F102]
- Dynamically allocated `struct iommu_domain` instances must initialize `domain->owner = dev_iommu_ops(dev)` (via `iommu_domain_init()` or `iommu_sva_domain_alloc()`), while callers checking domain compatibility must use `domain_iommu_ops_compatible()` because static `blocked_domain`/`identity_domain` lack `domain->owner`. [F41, F190]
- When `iommu_ops` provides a static `ops->default_domain`, `iommu_get_def_domain_type()` must report `ops->default_domain->type` and `iommu_group_alloc_default_domain()` must require `req_type == ops->default_domain->type`; when `!IS_ENABLED(CONFIG_IOMMU_DMA)`, `iommu_get_default_domain_type()` must reject `IOMMU_DOMAIN_DMA` (`WARN_ON`, return `-1`) and default `0` to `IOMMU_DOMAIN_IDENTITY`. [F62, F191]
- `__iommu_probe_device()` de-duplicates deferred groups onto `group_list` by checking `list_empty(&group->entry)`, so `bus_iommu_probe()` must unlink each group with `list_del_init(&group->entry)` rather than `list_del()`. [F116]
- `struct ioptdesc` overlays `struct page` and is cast to/from `struct folio *` via `folio_ioptdesc()` and `ioptdesc_folio()`, so its field offsets must match `struct page` and `iopt_freelist_elm` must keep bit 0 clear. [F133]
- `of_iommu_get_resv_regions()` must skip DMA regions where `of_translate_dma_region()` returns `length == 0` before calling `iommu_resv_region_get_type()` or `iommu_alloc_resv_region()` (as consumers compute `start + length - 1`), and must OR `IOMMU_CACHE` into `prot` when `of_dma_is_coherent(dev->of_node)` is true. [F82, F155]
- In `mtk_iommu.c`, shared page-table and group state (`share_dom` in `mtk_iommu_domain_finalise()` and `m4u_group[]` in `mtk_iommu_device_group()`) must be accessed on `mtk_iommu_get_frst_data(hw_list)` under its `mutex`—always reusing `share_dom` (`iop`, `cfg`, `pgsize_bitmap`) while updating `dom->domain.geometry` per `region_id`—whereas per-bank hardware state uses the device's own `data`; `mtk_iommu_tlb_flush_range_sync()` must iterate over every `mtk_iommu_data` on `bank->parent_data->hw_list`, and `mtk_iommu_runtime_resume()` must return `0` if `!reg->wr_len_ctrl` and otherwise call `mtk_iommu_tlb_flush_all(data)`. [F70, F71, F112, F162]
- In `mtk_iommu` / `mtk_iommu_v1`, `of_xlate` / `mtk_iommu_v1_create_mapping()` must verify `args->args_count == 1`, and DT/probe paths must verify `larb_nr` in `[1, MTK_LARB_NR_MAX]`, `larbid < MTK_LARB_NR_MAX` (or `MT2701_LARB_NR_MAX`), no duplicate `larb_imu[id].dev`, and consistent `larbid` with non-NULL `larb_imu[larbid].dev` across `fwspec->ids[]`; in `ipmmu-vmsa.c`, `ipmmu_probe()` must clamp `mmu->num_ctx` to `min(IPMMU_CTX_MAX, mmu->features->number_of_contexts)`, `mmu->utlb_ctx[utlb]` and `mmu->domains[context_id]` must update in lockstep with `IMUCTR(utlb)` and `mmu->ctx`, and `ipmmu_ctx_reg()` / `IMUCTR()` / `IMUASID()` require discontinuous offsets for `context_id > 7` and `utlb >= 32`. [F72, F83, F84, F89, F91, F92]
- In `omap-iommu`, `omap_iommu_map()` must mirror entries across `omap_domain->iommus` (rolling back with `iopgtable_clear_entry()` on failure), `IOPGD_SUPER` and `IOPTE_LARGE` entries must be replicated across 16 entries and rewound to `IOSUPER_MASK`/`IOLARGE_MASK` on clear, and `omap_iommu_runtime_suspend()` saves TLBs only when `obj->domain && obj->iopgd`; in `sprd-iommu.c`, `sprd_iommu_attach_device()` must disable hardware (`sprd_iommu_hw_en(sdev, false)`) while programming PPN/VPN registers, and `map`/`unmap` must check `iova >= aperture_start` and `iova + size <= aperture_end + 1`. [F75, F76, F79, F96, F98]

## Synchronization
- `iommu_probe_device_lock` must be held across `dev_iommu_get()`, `__iommu_probe_device()`, `dev_iommu_priv_set()` (when `!CONFIG_FSL_PAMU`), and `of_iommu_configure()`; `iommu_init_device()` enters and exits with `iommu_probe_device_lock` held and must recheck `!dev->iommu || dev->iommu_group` after dropping it for `dev->bus->dma_configure(dev)`, while `ops->probe_finalize(dev)` must be called outside `group->mutex` and `iommu_probe_device_lock`. [F14, F27, F171]
- `iommu_device_register()` and `iommu_device_register_bus()` must set `WRITE_ONCE(iommu->ready, true)` only after `bus_iommu_probe()` succeeds (paired with `!dev->iommu && !READ_ONCE(iommu->ready)` returning `-EPROBE_DEFER` in `iommu_fwspec_init()`), and `iommu_device_use_default_domain()` must check `if (!group->default_domain)` under `group->mutex` and return `-EPROBE_DEFER` before incrementing `group->owner_cnt`. [F17, F29]
- In `io-pgfault.c`, lock order is `queue->lock` -> `dev->iommu->lock` -> `fault_param->lock` (`iopf_queue_flush_dev()` must never be called under `fault_param->lock`); `fault_param->lock` protects `partial`, `faults`, and `group->pending_node` (including `ops->page_response()` and `list_del_init(&group->pending_node)`); and `iopf_get_dev_fault_param()` must use `rcu_read_lock()`, `rcu_dereference()`, and `refcount_inc_not_zero()`, pairing with `kfree_rcu()` in `iopf_put_dev_fault_param()`. [F23, F164, F166]
- `iommu_sva_lock` (nesting outside `group->mutex`) must be held across `iommu_sva_bind_device()` and `iommu_sva_unbind_device()` to serialize `mm->iommu_mm->sva_domains`, `domain->users`, and `handle->users`; in `iommu_sva_handle_mm()`, the worker must pin `mm` via `mmget_not_zero(mm)`, hold `mmap_read_lock(mm)`, and pass `FAULT_FLAG_REMOTE` (`regs = NULL`) to `handle_mm_fault()`. [F31, F168]
- In `mtk_iommu`, TLB flushes must hold `spin_lock_irqsave(&bank->tlb_lock, flags)`, poll and clear (`0`) `REG_MMU_CPE_DONE`, and on timeout release `curbank->tlb_lock` before calling `mtk_iommu_tlb_flush_all()`; in `ipmmu-vmsa.c`, `mmu->lock` requires `spin_lock_irqsave()`; in `omap-iommu.c`, `iopte_alloc()` must re-check `!*iopgd` after re-acquiring `obj->page_table_lock` (freeing raced `iopte`) and every `iopgd`/`iopte` write requires `flush_iopte_range()`; in `fsl_pamu`, `pamu_set_liodn()` must call `pamu_disable_liodn()` under `iommu_lock` before `pamu_config_ppaace()`, `pamu_enable_liodn()` needs `mb()` before/after `PAACE_AF_V`, and `attach_device()` must use `GFP_ATOMIC` and drop `device_domain_lock` before `detach_device()`. [F33, F36, F38, F74, F78, F158, F180, F181]

## Object Lifetimes
- In `iommu_report_device_fault()`, the `iopf_param` ref from `iopf_get_dev_fault_param()` is dropped via `iopf_put_dev_fault_param()` on non-last faults (`!(fault->prm.flags & IOMMU_FAULT_PAGE_REQUEST_LAST_PAGE)` after `report_partial_fault()`), or transferred to `group->fault_param` in `iopf_group_alloc()`; when `domain->iopf_handler(group)` returns `0`, the handler owns `group` (and must call `iopf_group_response()` and `iopf_free_group()`), whereas on error or `abort_group` fallback, `err_abort` must call `iopf_group_response()` and free `group` (`__iopf_free_group()` if `group == &abort_group`, where `__iopf_free_group()` only calls `kfree(iopf)` for entries without `IOMMU_FAULT_PAGE_REQUEST_LAST_PAGE`). [F3, F4, F105, F106, F134, F201]
- In `iopf_queue_remove_device()`, under `fault_param->lock`, all partial faults on `fault_param->partial` must be freed and each pending `iopf_group` on `fault_param->faults` must be responded to, unlinked with `list_del_init(&group->pending_node)`, and freed via `iopf_free_group()` before dropping `param->fault_param`. [F6]
- `iommu_sva_domain_alloc()` takes `mmgrab(mm)` and sets `domain->cookie_type = IOMMU_COOKIE_SVA` and `domain->mm = mm`, which `iommu_domain_free()` releases via `mmdrop(domain->mm)` before calling `domain->ops->free(domain)`; in `iommu_sva_bind_device()` / `iommu_sva_unbind_device()`, the PASID is detached and `handle` freed only when `handle->users` reaches 0 (or on domain alloc failure), and `domain` is freed via `iommu_domain_free()` only when `--domain->users == 0`. [F7, F8]
- `iommu_group_alloc()` drops its initial ref on `group->kobj` after creating `group->devices_kobj`, so `iommu_group_get()`, `iommu_group_ref_get()`, and `iommu_group_put()` must operate on `group->devices_kobj`; in `iommu_deinit_device()`, when `list_empty(&group->devices)` is true, `group->default_domain` and `group->blocking_domain` must be freed via `iommu_domain_free()` and nulled after `ops->release_device(dev)` and before `module_put(ops->owner)`. [F9, F10]
- Callers of `iommu_fwspec_add_ids()` must re-read `dev_iommu_fwspec_get(dev)` afterwards because `fwspec` may be `krealloc()`ed; `iommu_device_register()` must be called only after `platform_set_drvdata()` and driver state init (`data->hw_list`, `data->mutex`); `_omap_iommu_detach_dev()` must detach `omap_domain->iommus` in reverse order (`iommu--`) before `omap_iommu_detach_fini()`; and `sprd_iommu_cleanup()` must not null `dom->sdev` until after `dma_free_coherent()` and `sprd_iommu_hw_en(dom->sdev, false)`. [F15, F16, F132, F144]

## API Contracts
- `iommu_put_pages_list()` and `iommu_pages_list_splice()` leave the source `struct iommu_pages_list` head invalid so callers reusing it must reinitialize with `IOMMU_PAGES_LIST_INIT`, and `iommu_alloc_pages_node_sz()` must reject `__GFP_HIGHMEM` and translate `NUMA_NO_NODE` to `numa_mem_id()`. [F1, F169]
- `struct iommu_iotlb_gather` must be initialized (and reset after `iotlb_sync`) via `iommu_iotlb_gather_init()` (`gather->start = ULONG_MAX`), and because `gather.end` and `domain.geometry.aperture_end` are inclusive (`start + size - 1`), range size calculations must add 1 (`end - start + 1`); paging domains that only translate within `[aperture_start, aperture_end]` must set `geometry.force_aperture = true`. [F49, F50, F193]
- Callers must check `domain->cookie_type` before reading the `struct iommu_domain` cookie union (`handler`, `iova_cookie`, `msi_cookie`, `mm`); `iommu_attach_device_pasid()`, `iommu_replace_device_pasid()`, `iommu_attach_group_handle()`, and `iommu_replace_group_handle()` require a freshly allocated `struct iommu_attach_handle` (`curr != entry`); and PASID-supporting drivers must provide `domain->ops->set_dev_pasid`, `iommu_ops->blocked_domain`, and an infallible `blocked_domain->ops->set_dev_pasid`. [F39, F173, F197]
- `iommu_report_device_fault()` requires sleepable context (`GFP_KERNEL`, `fault_param->lock`); `iopf_queue_add_device()` requires `ops->page_response`; and when removing a device from an IOPF queue, the driver must disable PRI in the IOMMU hardware and flush hardware fault queues first, call `iopf_queue_flush_dev()` (only before `iopf_queue_remove_device()`), call `iopf_queue_remove_device()`, and only then disable endpoint PRI. [F22, F147, F165]
- Every `iommu_ops` must define `.probe_device` and `.device_group` (returning `ERR_PTR`, never `NULL`) and set `.owner = THIS_MODULE` if modular; `alloc_io_pgtable_ops()` must check `fmt < IO_PGTABLE_NUM_FMTS`, require both `cfg->alloc` and `cfg->free` with `IO_PGTABLE_CAP_CUSTOM_ALLOCATOR`, and have hardware page-table walks disabled before `free_io_pgtable_ops()`; domain callbacks invoked before attach (`flush_iotlb_all`, `free`, `map_pages`) must NULL-check `dom->bank`, `domain->mmu`, and `dom->sdev`; `mtk_iommu` range TLB flushes must never receive `size == 0`; and `get_ome_index(&omi_index, dev)` callers must pre-initialize `omi_index = ~(u32)0`. [F44, F54, F87, F90, F183, F185, F186, F200]

## Error Handling
- When `iommu_report_device_fault()` fails before constructing an `iopf_group` (`err_bad_iopf`), it must complete any `IOMMU_FAULT_PAGE_REQ` event via `iopf_error_response()` (`IOMMU_PAGE_RESP_INVALID`) before returning `-EINVAL`; and `ops->domain_alloc_identity`, `ops->domain_alloc_sva`, `iommu_group_alloc_default_domain()`, and `__iommu_group_alloc_default_domain()` must return an `ERR_PTR` (never `NULL`) on failure. [F5, F40, F42]
- In `iommu_map_nosync()` and `__iommu_unmap()`, `pgsize` is in bytes and `count` in pages; `iommu_map_nosync()` must reset `mapped = 0` each iteration and subtract `size -= mapped` before `if (ret) break;`, `.map_pages` must add any partially mapped bytes to `*mapped` on error so `iommu_unmap(domain, orig_iova, orig_size - size)` unrolls partial progress, and `.unmap_pages` must return unmapped bytes. [F115, F194]
- In `__iommu_set_group_pasid()`, `err_revert` must stop before `last_gdev` (`if (device == last_gdev) break;` at loop start) while rolling back PASID-capable devices (`max_pasids > 0`) via `old->ops->set_dev_pasid()` or `iommu_remove_dev_pasid()`, whereas in `__iommu_group_set_domain_internal()`, `err_revert` must re-attach `group->domain` to `last_gdev` before breaking (`if (gdev == last_gdev) break;` at loop end). [F58, F103]
- `iommu_alloc_global_pasid()` must check `dev->iommu->max_pasids > 0` before `max_pasids - 1`, check the signed `int` return of `ida_alloc_range()` for `< 0`, and return `IOMMU_PASID_INVALID` (`-1U`) on failure (callers must test `== IOMMU_PASID_INVALID`, never `< 0`); `dev_iommu_get_max_pasids()` must check `pci_max_pasids() > 0` before casting to `u32`; and `mtk_iommu_mm_dts_parse()` `err_larbdev_put` must scan all `MTK_LARB_NR_MAX` slots (`i--`). [F52, F109, F123, F125]

## Known Pitfalls
- In `iommu_pgsize()`, `addr_merge` (`paddr | iova`) must be checked for non-zero before `__ffs(addr_merge)`, and `check_add_overflow(offset, pgsize_next, &offset_end)` must be used before comparing `offset_end <= size`; in `iommu_map_sg()`, `while (i <= nents)` with `if (++i < nents) sg = sg_next(sg)` must be kept so `i == nents` flushes the final segment; and in `iommu_resv_region_get_type()`, `%pr` takes `phys` while `%pap` takes `&start`/`&end`. [F113, F122, F124, F142]
- 32-bit upper address/PFN values must be widened to 64-bit (`u64` or `phys_addr_t`) before left-shifting (`va34_32`/`pa34_32` in `mtk_iommu_isr()`, `make64()` and `2ULL << ...` in `fsl_pamu.c`, `IMEUAR` under `IS_ENABLED(CONFIG_64BIT)` in `ipmmu_domain_irq()`, and `*(dom->pgt_va + ...)` in `sprd_iommu_iova_to_phys()`); in `mtk_iommu.c`, use `MTK_IOMMU_IS_TYPE()` (not `MTK_IOMMU_HAS_FLAG()`) for `MTK_IOMMU_TYPE_MM` (`0`) and keep `++i` in the `while` condition of bank `do { ... } while (++i < ...)` loops; in `ipmmu_domain_irq()`, read `IMELAR`/`IMEUAR` before writing `0` to `IMSTR`; and in `omap-iommu.c`, use `iopgd_is_section()`/`iopgd_is_super()` and pass byte offsets (`index * sizeof(da)`) to `flush_iopte_range()`. [F110, F111, F118, F127, F128, F130, F131, F140, F157]
