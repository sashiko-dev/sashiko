# PCI ENHANCED ERROR HANDLING (EEH) FOR POWERPC

Implements PowerPC PCI Enhanced Error Handling (EEH) on `pseries` and `powernv` alongside generic PCIe error reporting and containment (`aer`, `dpc`, and `pcie_do_recovery`). EEH detects frozen Partitionable Endpoints (PEs) or fenced PHBs via MMIO all-ones reads or firmware interrupts, collects RTAS/OPAL diagnostics, and drives asynchronous reset, BAR restoration, hotplug re-enumeration, and driver recovery via `eehd`. Generic PCIe port drivers and `err.c` handle hardware/APEI error interrupts, link containment, and recovery broadcasts across PCI hierarchies.

## Architecture & Data Flow
- Isolating a PE via `eeh_pe_mark_isolated()` or clearing `EEH_PE_ISOLATED` via `eeh_pe_state_clear()` must update PE isolation state, `pdev->error_state`, `pe->check_count`, and `EEH_PE_CFG_BLOCKED` (when `EEH_PE_CFG_RESTRICTED` is set) together across the PE subtree, and `eeh_slot_error_detail()` must check `!(pe->state & EEH_PE_CFG_BLOCKED)` before calling `eeh_pe_restore_bars(pe)` and `eeh_dump_pe_log()`. When `edev->pe->state & EEH_PE_CFG_RESTRICTED` is set, `eeh_dev_save_state()` and `eeh_dev_restore_state()` must skip `pci_save_state()`/`pci_restore_state()`, and `eeh_dev_restore_state()` must call `eeh_pe_restore_bars(edev->pe)` only when `list_is_last(&edev->entry, &edev->pe->edevs)`. [F58, F138, F139]
- During `eeh_pe_reset_full()`, `EEH_PE_RESET` is marked on the PE subtree so `pnv_eeh_get_pe_state()` returns active flags before querying OPAL freeze status. In `pnv_eeh_cfg_blocked()`, `if (edev->physfn && (edev->pe->state & EEH_PE_RESET))` must precede `if (edev->pe->state & EEH_PE_CFG_BLOCKED)` so VF FLR config accesses are not blocked while both flags are set. [F66, F91, F105]
- During PE recovery and reset, EEH helpers (`eeh_bridge_check_link()`, `eeh_restore_bridge_bars()`, `eeh_restore_device_bars()`, `pnv_eeh_do_flr()`, `pnv_eeh_do_af_flr()`) must use `eeh_ops->read_config` and `eeh_ops->write_config` (with `pnv_eeh_cfg_blocked()` exempting `edev->physfn` when `EEH_PE_RESET` is set). When restoring `PCI_COMMAND` from `edev->config_space[1]`, `eeh_restore_bridge_bars()` must OR in `PCI_COMMAND_MEMORY | PCI_COMMAND_MASTER`, whereas `eeh_restore_device_bars()` must read `PCI_COMMAND` and update only `PCI_COMMAND_PARITY` and `PCI_COMMAND_SERR`. [F147, F149]
- Because `eeh_remove_device()` and `eeh_rmv_device()` clear `edev->pdev = NULL` while leaving `edev` on `pe->edevs` when `EEH_PE_KEEP` is set, any traversal of `pe->edevs` (`eeh_pe_for_each_dev`, `eeh_pe_dev_traverse`) must check `edev->pdev != NULL` (or `eeh_edev_actionable(edev)`) before dereferencing it. [F47]
- The cached `pe->bus` pointer must only be returned by `eeh_pe_bus_get()` when `EEH_PE_PRI_BUS` is set in `pe->state`, and `EEH_PE_PRI_BUS` must be cleared when a PE's primary bus is permanently torn down or immediately before `pci_hp_add_devices()` re-enumerates it (not before `eeh_pe_reset_full()` finishes in `eeh_reset_device()`). [F60]
- When `eeh_pe_reset_full()` or `eeh_pe_state_clear()` is called with `include_passed == false`, passed-through child PEs (`eeh_pe_passed(pe) == true`) must keep their software state and be re-frozen via `eeh_pe_refreeze_passed()` if parent reset thawed their MMIO. [F64]
- Because `0` is a valid PE address (`PE#0`), `eeh_dev_check_failure()` must test `edev->pe == NULL` rather than `!pe->addr`, and `__eeh_pe_get()` must skip `EEH_PE_PHB` root PEs before matching `pe->addr`. In `eeh_dev_check_failure()`, `pnv_eeh_get_pe()`, and `pnv_eeh_next_error()`, the loop escalating a frozen PE to its ancestor must stop at `EEH_PE_PHB` and walk up to the highest frozen non-PHB ancestor rather than breaking on the first frozen parent. [F77, F106]
- In `eeh_driver.c`, `edev->in_error` is set only when `eeh_report_error()` invokes `error_detected(pci_channel_io_frozen)`, must be checked before invoking `slot_reset()` or `resume()`, and must be cleared on recovery completion or `eeh_remove_device()`. In `eeh_result_priority()`, `PCI_ERS_RESULT_CAN_RECOVER` (4) must rank above `PCI_ERS_RESULT_RECOVERED` (3) and `PCI_ERS_RESULT_NONE` (1), and `eeh_handle_normal_event()` must reset `result = PCI_ERS_RESULT_NONE` before `eeh_pe_report("slot_reset", ...)`. [F68, F93]
- `struct pci_io_addr_range` in `eeh_cache.c` stores inclusive bounds `[addr_lo, addr_hi]`, so `__eeh_addr_cache_get_device()` and `eeh_addr_cache_insert()` must use strict `<` and `>` comparisons, and `__eeh_addr_cache_rmv_dev()` must restart from `rb_first()` after `rb_erase()`/`kfree()`. [F88, F99]
- In `pcie_do_recovery()`, runtime PM and `report_perm_failure_detected` must be broadcast via `pci_walk_bridge(bridge, ...)` across the full hierarchy, and `status` must be preset to `PCI_ERS_RESULT_RECOVERED` before broadcasting `report_mmio_enabled` or `report_slot_reset` because `merge_result()` treats `PCI_ERS_RESULT_NONE` votes as no-ops. [F69, F73]
- `struct pci_dev::aer_info` is `NULL` on devices without AER capability, so `aer_ratelimit()`, `pci_dev_aer_stats_incr()`, `pci_rootport_aer_stats_incr()`, and sysfs `is_visible` callbacks must check `aer_info != NULL`. Loops indexing `dev_cor_errs` (`AER_MAX_TYPEOF_COR_ERRS` = 16) or `dev_fatal_errs`/`dev_nonfatal_errs` must bound iteration by the counter array size rather than `ARRAY_SIZE(strings_array)`, while `aer_correctable_error_string` and `aer_uncorrectable_error_string` must keep 32 elements for `__aer_print_error()`. [F42, F83, F84]
- Functions indexing `e_info->dev[]` and `e_info->ratelimit_print[]` (`add_error_device()`, `aer_get_device_error_info()`, `aer_print_error()`) must enforce `i < AER_MAX_MULTI_ERR_DEVICES` (5), `find_source_device()` must reset `e_info->error_dev_num = 0`, and `aer_process_err_devices()` must log all devices with `aer_print_error()` in a separate loop before calling `handle_error_source()`. [F85, F101]

## Synchronization
- `eeh_handle_normal_event()`, `eeh_handle_special_event()`, `eeh_dev_restore_state()`, and `eeh_pe_bus_get()` must release `pci_lock_rescan_remove()` via `pci_unlock_rescan_remove()` on every early return and completion path, and `eeh_handle_special_event()` must drop it before calling `eeh_handle_normal_event()`. [F6]
- In `__eeh_send_failure_event()`, when `pe` is non-NULL, `pe` must be marked with `EEH_PE_RECOVERING` via `eeh_pe_state_mark()` before `event` is added to `eeh_eventlist` under `eeh_eventlist_lock`, preventing `eeh_pe_tree_remove()` from freeing `pe` while queued. [F19]
- In `eeh_dev_check_failure()` and `eeh_phb_check_failure()`, `confirm_error_lock` (via `eeh_serialize_lock()`) must be held continuously across checking `EEH_PE_ISOLATED`, querying `eeh_ops->get_state()`, and calling `eeh_pe_mark_isolated()`, and released before calling `eeh_send_failure_event()`. [F20]
- In `eeh_pe_report_edev()`, the caller must copy `edev->pdev` to a local `pdev` and pin it with `get_device(&pdev->dev)` before acquiring `device_lock(&pdev->dev)`, holding both `device_lock` and `eeh_pcid_get(pdev)` across the callback and `eeh_pcid_put(pdev)` (which must be called on every path). In `drivers/pci/pcie/err.c` recovery broadcast helpers and `cxl_rch_handle_error_iter()`, `device_lock(&dev->dev)` must be held across reading `dev->driver`, checking `err_handler`, and invoking callbacks. [F8, F21, F34]
- In `eeh_reset_device()`, `EEH_PE_KEEP` must be marked on `pe` before removing devices (`eeh_rmv_device()` or `pci_hp_remove_devices()`) and cleared only after `eeh_pe_restore_bars()` and `eeh_pe_detach_dev()`, so `eeh_remove_device()` marks devices `EEH_DEV_DISCONNECTED` instead of unlinking them from `pe`. [F24]
- In `eeh_handle_normal_event()`, `eeh_slot_error_detail(pe, EEH_LOG_TEMP)` must not be called until after `eeh_set_irq_state(pe, false)` and `eeh_pe_report("error_detected(IO frozen)", ...)` complete, because `eeh_slot_error_detail()` may thaw MMIO on the frozen PE. [F25]
- In `eeh_pe_reset()` and `pcibios_set_pcie_reset_state()`, asserting `EEH_RESET_HOT` or `EEH_RESET_FUNDAMENTAL` via `eeh_ops->reset()` must be preceded by freezing the PE with `eeh_ops->set_option(pe, EEH_OPT_FREEZE_PE)` and marking `EEH_PE_CFG_BLOCKED` (for non-VF PEs), and `EEH_PE_CFG_BLOCKED` must be cleared on `EEH_RESET_DEACTIVATE`. [F26]
- On PowerNV, `pnv_eeh_event()` must mask its own IRQ via `disable_irq_nosync(irq)` before queueing `eeh_send_failure_event(NULL)`, `eeh_handle_special_event()` must loop until `eeh_ops->next_error(&pe)` returns `EEH_NEXT_ERR_NONE` (or `EEH_NEXT_ERR_DEAD_IOC`), and `pnv_eeh_next_error()` must never return `EEH_NEXT_ERR_INF` and only call `enable_irq(eeh_event_irq)` when `ret == EEH_NEXT_ERR_NONE` and `eeh_enabled()` is true. [F28, F103]
- All accesses to `pci_io_addr_cache_root.rb_root` must hold `pci_io_addr_cache_root.piar_lock` with `spin_lock_irqsave()`, and `eeh_addr_cache_insert()` must allocate nodes with `GFP_ATOMIC`. In `eeh_probe_device()`, `edev->pe`, `edev->pdev = dev`, and `dev->dev.archdata.edev = edev` must be set before `eeh_addr_cache_insert_dev(dev)` and `eeh_sysfs_add_device(dev)`. [F29, F30]
- In `dpc_reset_link()`, `PCI_DPC_RECOVERING` must be set in `pdev->priv_flags` before clearing `PCI_EXP_DPC_STATUS_TRIGGER`, and `PCI_DPC_RECOVERED` must be updated before clearing `PCI_DPC_RECOVERING` and waking `dpc_completed_waitqueue`. In `aer_recover_queue()`, writers must use `kfifo_in_spinlocked(..., &aer_recover_ring_lock)`, and `aer_recover_work_func()` must free `entry.regs` via `ghes_estatus_pool_region_free()` after `pci_print_aer()` and call `pci_dev_put(pdev)`. [F33, F36]

## Object Lifetimes
- Callers of `eeh_handle_normal_event(pe)` (`eeh_event_handler()`, `eeh_handle_special_event()`) must not dereference or modify `pe` after it returns, because non-VF recovery failure removes the PE's devices via `pci_hp_remove_devices()` and frees `pe`. [F1]
- In `eeh_pe_tree_remove()`, a PE must never be unlinked or freed while `EEH_PE_KEEP` or `EEH_PE_RECOVERING` is set, or when `EEH_PE_PHB` is set in `pe->type` (even when `edevs` and `child_list` are empty). In `eeh_pe_reset_and_recover()`, every return path after `eeh_pe_state_mark(pe, EEH_PE_RECOVERING)` must call `eeh_pe_state_clear(pe, EEH_PE_RECOVERING, true)`. [F3, F7, F96]
- In `eeh_probe_device()`, if `eeh_ops->probe(dev)` returns an `edev` still bound to a stale `edev->pdev != dev`, `eeh_pe_tree_remove(edev)`, `eeh_addr_cache_rmv_dev(edev->pdev)`, and `eeh_sysfs_remove_device(edev->pdev)` must be called before rebinding `edev->pdev = dev`. In `eeh_remove_device()`, `eeh_sysfs_remove_device(dev)` must be called before clearing `dev->dev.archdata.edev = NULL`. [F18, F130]
- Every `struct pci_dev *` added to `e_info->dev[]` by `find_source_device()` via `add_error_device()` has its refcount incremented with `pci_dev_get()`, and `aer_process_err_devices()` must release that reference via `handle_error_source()`'s call to `pci_dev_put()`. [F13]

## API Contracts
- `eeh_ops->get_state()` and `eeh_wait_state()` return a negative error code or an `EEH_STATE_*` bitmask where `0` is a frozen PE, so callers must check `eeh_state_active()` (requiring both `EEH_STATE_MMIO_ACTIVE` and `EEH_STATE_DMA_ACTIVE`) and `EEH_STATE_NOT_SUPPORT` rather than treating `0` or a bitwise AND as active. In `pseries_eeh_get_state()`, RTAS slot reset state 0 must translate to `EEH_STATE_MMIO_ACTIVE | EEH_STATE_DMA_ACTIVE | EEH_STATE_MMIO_ENABLED | EEH_STATE_DMA_ENABLED`. [F37, F67, F90]
- `eeh_ops->get_state` implementations (`pseries_eeh_get_state`, `pnv_eeh_get_state`) must set `*delay` whenever `delay != NULL` and `EEH_STATE_UNAVAILABLE` is returned (as `eeh_wait_state()` passes an uninitialized `int mwait`), and must never sleep or allocate with `GFP_KERNEL` because `eeh_dev_check_failure()` calls them under raw spinlock `confirm_error_lock`. [F53, F156]
- Optional callbacks in `struct eeh_ops`—`restore_config` (`NULL` on pSeries), `notify_resume` (`NULL` on PowerNV), and `err_inject`—must be checked for `NULL` before invocation. `eeh_pe_configure()` must call `eeh_ops->configure_bridge(pe)` for every non-NULL `pe`, including VFIO passthrough PEs (`eeh_pe_passed(pe)`). [F46, F148]
- In `eeh_handle_normal_event()` and `eeh_handle_special_event()`, `eeh_set_channel_state(pe, pci_channel_io_perm_failure)` must be called only after `eeh_pe_report(..., eeh_report_failure, NULL)`, because `eeh_edev_actionable()` returns `false` once `error_state == pci_channel_io_perm_failure`. [F59]
- `eeh_powernv_init()` must call `eeh_set_pe_aux_size()` before `eeh_init()`, because `eeh_init()` immediately allocates root PHB `struct eeh_pe` instances using `eeh_pe_aux_size` for inline `pe->data` storage. [F74]
- Because `PCI_EXP_TYPE_RC_EC` and `PCI_EXP_TYPE_RC_END` have `subordinate == NULL`, `pci_walk_bridge()` must check `bridge->subordinate` before calling `pci_walk_bus()`, and `find_source_device()` must use `pcie_walk_rcec()` when `pci_pcie_type(parent) == PCI_EXP_TYPE_RC_EC`. [F44]

## Error Handling
- On PowerNV, `opal_pci_reset()` returns a signed `s64` where a positive value is a millisecond delay, so reset helpers (`pnv_eeh_phb_reset`, `pnv_eeh_root_reset`, `pnv_eeh_bridge_reset`) must pass positive returns to `pnv_eeh_poll()` and map any final non-`OPAL_SUCCESS` status to `-EIO`. On pSeries, `pseries_eeh_phb_configure_bridge()` must wait on positive RTAS busy returns from `rtas_call(ibm_configure_pe, ...)` via `rtas_busy_delay_time()` and `rtas_busy_delay()`. [F38, F39]
- Any `reset_subordinates` callback passed to `pcie_do_recovery()` (`aer_root_reset`, `dpc_reset_link`) must check the return value of its reset and link-wait helpers (`pcie_reset_flr`, `pci_bus_error_reset`, `dpc_wait_rp_inactive`, `pci_bridge_wait_for_secondary_bus`) and return `PCI_ERS_RESULT_DISCONNECT` when non-zero. In `aer_root_reset()`, an RCiEP (`PCI_EXP_TYPE_RC_END`) uses `dev->rcec` rather than `pcie_find_root_port(dev)` as `root`, and `root` and `root->aer_cap` must be checked for non-zero. [F40, F43]
- Stack-allocated `struct aer_err_info` instances (`dpc_process_error`, `pci_print_aer`, `aer_isr_one_error`) must be zero-initialized and have `severity` set before calling `aer_get_device_error_info()` or `aer_print_error()`, and `aer_get_device_error_info()` must reset `info->status = 0` and `info->tlp_header_valid = 0` on each call. [F50]

## External Contracts
- Buffers passed by physical address to RTAS calls (`pci_regs_buf` in `eeh_slot_error_detail()` and `slot_errbuf` in `pseries_eeh_get_log()`) must reside in static BSS storage in the RMO region rather than heap or stack memory. `pseries_eeh_get_log()` must hold `slot_errbuf_lock` with `spin_lock_irqsave()` across clearing `slot_errbuf`, `rtas_call(ibm_slot_error_detail, ...)`, and `log_error()`, while `pseries_send_allow_unfreeze()` must hold `rtas_data_buf_lock`. [F31, F161]

## Known Pitfalls
- `eeh_dump_dev_log()` and `eeh_dump_pe_log()` must accumulate buffer offsets into `pci_regs_buf` using `scnprintf()` rather than `snprintf()` so `len - n` never underflows on truncation. In `eeh-powernv.c`, big-endian outputs written by OPAL (`__be64 frozen_pe_no`, `__be16 err_type`, `__be16 severity`, `__be16 pcierr`, and `struct OpalIoP7IOCErrorData` fields) must be converted with `be16_to_cpu()` or `be64_to_cpu()` before use. [F76, F78]
- `EEH_POSSIBLE_ERROR(val, type)` must apply bitwise NOT to a signed `int` (`(type)~0`, not `~0U`) so it sign-extends to `0xffffffffffffffffULL` when `type` is `u64` in `eeh_readq()`/`eeh_readq_be()`, whereas `EEH_IO_ERROR_VALUE(size)` takes `size` in bytes `{1, 2, 4}` and shifts unsigned `~0U`. In `eeh_memcpy_fromio()`, the trailing 4-byte `0xffffffff` check must guard `n >= 4` and offset `void *dest` by `n - 4` before casting to `u32 *`. [F89, F111, F112, F118]
- When iterating over consecutive 32-bit PCI config registers in `eeh_dump_dev_log()`, `eeh_save_bars()`, `eeh_restore_bridge_bars()`, and `eeh_restore_device_bars()`, the byte offset passed to `read_config`/`write_config` must advance by `i * 4`, and single-byte config registers restored from `u32 edev->config_space[16]` must be extracted via `SAVED_BYTE(OFF)` (`BYTE_SWAP(OFF)`). [F102, F119]
