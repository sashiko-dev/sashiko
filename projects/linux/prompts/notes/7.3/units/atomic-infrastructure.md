# ATOMIC INFRASTRUCTURE

This component provides the Linux kernel's core atomic integer operations (`atomic_t` and `atomic64_t`) and saturating reference counters (`refcount_t`) across both C and Rust (`kernel::sync::atomic::Atomic<T>` and `kernel::sync::refcount::Refcount`). It includes architecture-independent headers (`include/linux/atomic.h`, `include/linux/refcount.h`), generic C fallbacks (`include/asm-generic/atomic*.h`), architecture-specific low-level implementations across `arch/*/include/asm/atomic*.h`, and LKMM-compliant Rust abstractions.

## Architecture & Data Flow

- Because `AtomicType` in `rust/kernel/sync/atomic.rs` only requires one-way bit validity from `T` to `T::Repr` (supporting restricted-bit-pattern types like unit-only enums), every mutation of `Atomic<T>` (`self.0`) and every call to `from_repr` must ensure the stored or transmuted `T::Repr` value is a valid bit pattern of `T`. [F77]
- `Atomic<T>`, `AtomicRepr<T>`, and `Refcount` must remain `#[repr(transparent)]` wrappers around `UnsafeCell<T::Repr>` and `Opaque<bindings::refcount_t>`, because `AtomicBasicOps`, `AtomicExchangeOps`, `AtomicArithmeticOps`, and `Refcount::as_atomic` cast raw pointers directly between these Rust types and C `atomic_t`, `atomic64_t`, and `refcount_t`. [F74]
- On 32-bit x86 (`arch/x86/include/asm/atomic64_32.h`) and ARCv2 (`arch/arc/include/asm/atomic64-arcv2.h`), `atomic64_t` must declare its `s64 counter` field with `__aligned(8)` because 32-bit ABIs only guarantee 4-byte alignment for `s64` while hardware 64-bit atomics require 8-byte alignment. Broken by: removing `__aligned(8)` or accessing an only 4-byte-aligned `s64` through `atomic64_t`. [F50]
- In `arch/x86/include/asm/atomic64_32.h`, `__alternative_atomic64` and `alternative_atomic64` patch calls between `atomic64_<f>_386` and `atomic64_<g>_cx8` in a single `asm volatile` block, so both assembly routines must obey identical custom register conventions for inputs, outputs, and clobbers. [F45]
- In `arch/arm/include/asm/atomic.h`, 64-bit inline assembly operations that propagate carry or test sign bits (`ATOMIC64_OP`, `arch_atomic64_dec_if_positive`, `arch_atomic64_fetch_add_unless`) must use `%Q` for the low word and `%R` for the high word, while `ldrexd` and `strexd` use `%0` and `%H0`. [F48]
- In `arch/arm64/include/asm/atomic.h`, every atomic operation dispatched through `__lse_ll_sc_body(op, ...)` must have both a `__lse_<op>` implementation in `arch/arm64/include/asm/atomic_lse.h` and a matching `__ll_sc_<op>` implementation in `arch/arm64/include/asm/atomic_ll_sc.h` with identical parameter and return types. [F82]

## Synchronization

- In `include/linux/refcount.h` and `rust/kernel/sync/refcount.rs`, `refcount_add_not_zero()`, `refcount_inc_not_zero()`, `refcount_add()`, `refcount_inc()`, and `Refcount::inc()` use relaxed atomic RMW operations and provide no memory ordering, requiring callers to stabilize the object via RCU, locking, or an existing reference. [F94]
- For objects in memory subject to type-safe reuse (such as `SLAB_TYPESAFE_BY_RCU`), `refcount_set_release()` must be called only after all fields of the new object are initialized, and RCU readers must use `refcount_inc_not_zero_acquire()` or `refcount_add_not_zero_acquire()` so secondary validation loads are ordered after the refcount increment. Broken by: using relaxed `refcount_set()` or `refcount_inc_not_zero()`, or modifying fields after `refcount_set_release()`. [F11, F12, F93]
- In `__refcount_sub_and_test()`, `atomic_fetch_sub_release()` must be paired with `smp_acquire__after_ctrl_dep()` when the counter transitions to zero (`old > 0 && old == i`) so that prior accesses are ordered before the decrement and subsequent object deallocation is ordered after it. [F13]
- C `arch_atomic_try_cmpxchg()` and `arch_atomic64_try_cmpxchg()` implementations must only write the observed value to `*old` when the compare-and-exchange fails, and never overwrite `*old` on success when the memory backing `old` may have been concurrently published. Broken by: unconditionally assigning `*old = prev` before checking whether `prev == orig_old`. [F20]
- On architectures that serialize atomic RMW operations with spinlocks and interrupt disabling (ARC `!CONFIG_ARC_HAS_LLSC` in `arch/arc/include/asm/atomic-spinlock.h` and PA-RISC in `arch/parisc/include/asm/atomic.h`), `arch_atomic_set()` and `arch_atomic64_set()` must acquire the same lock (`atomic_ops_lock` or `_atomic_spin_lock_irqsave`) rather than performing a plain `WRITE_ONCE()`. [F14]
- In `arch/parisc/include/asm/atomic.h` on `CONFIG_SMP`, `_atomic_spin_lock_irqsave` must disable local interrupts via `local_irq_save(f)` before calling `arch_spin_lock(ATOMIC_HASH(l))`, and `_atomic_spin_unlock_irqrestore` must release `arch_spin_unlock(s)` before restoring interrupts via `local_irq_restore(f)`. [F10]
- On architectures where normal stores do not clear hardware lock reservations or lack single-instruction 64-bit atomicity, atomic stores and loads must use exclusive instructions rather than plain accesses: Hexagon `arch_atomic_set()` (`arch/hexagon/include/asm/atomic.h`) must use a `memw_locked` LL/SC loop rather than `WRITE_ONCE()`, and non-LPAE ARM (`!CONFIG_GENERIC_ATOMIC64 && !CONFIG_ARM_LPAE` in `arch/arm/include/asm/atomic.h`) must use `ldrexd` for `arch_atomic64_read()` and an `ldrexd`/`strexd` loop for `arch_atomic64_set()` rather than `ldrd`/`strd`. [F16, F104, F105]
- On Alpha (`arch/alpha/include/asm/atomic.h`), value-returning `_relaxed` atomic RMW primitives (`ATOMIC_OP_RETURN`, `ATOMIC_FETCH_OP`, `ATOMIC64_OP_RETURN`, `ATOMIC64_FETCH_OP`) must unconditionally emit `smp_mb()` after the LL/SC loop to preserve LKMM address/data dependency ordering, while `__atomic_acquire_fence()` and `__atomic_post_full_fence()` are defined as empty to avoid duplicate barriers. [F22]
- In `arch/mips/include/asm/atomic.h`, `ATOMIC_OP`, `ATOMIC_OP_RETURN`, `ATOMIC_FETCH_OP`, and `ATOMIC_SIP_OP` must gate the `raw_local_irq_save`/`raw_local_irq_restore` fallback versus the `ll`/`sc` assembly loop solely on `if (!kernel_uses_llsc)` without conjoining `R10000_LLSC_WAR`. [F55, F84]
- In MIPS `ATOMIC_SIP_OP` (`arch_atomic_sub_if_positive` and `arch_atomic64_sub_if_positive` in `arch/mips/include/asm/atomic.h`), `__SYNC(full, loongson3_war)` must be placed both immediately before the LL/SC loop and at the label `2:` target of the conditional exit branch `bltz` so speculative or reordered memory accesses cannot break LL/SC cache coherence. [F18]

## Object Lifetimes

- After `Refcount::dec_and_test` returns `false`, the caller must not dereference or otherwise use the `&Refcount` reference (or the enclosing object if its lifetime is tied to the `Refcount`), because another thread may concurrently drop the last reference and free the backing memory. [F7]

## API Contracts

- In `arch/*/include/asm/atomic*.h`, any C function implementing an optional `arch_atomic_*` or `arch_atomic64_*` primitive (other than `read`, `set`, `add`, `sub`, `and`, `or`, `xor`) must also `#define arch_atomic_<op> arch_atomic_<op>` so `include/linux/atomic/atomic-arch-fallback.h` does not silently use the fallback. [F107]
- `arch_atomic_dec_if_positive` and `arch_atomic64_dec_if_positive` must return the signed value `old - 1` (`int` or `s64`/`long`) even when `*v` was non-positive and not decremented, so `0` indicates a successful `1 -> 0` transition while `< 0` indicates failure. Broken by: returning `old` or `0` on failure, or checking `!atomic_dec_if_positive(v)` instead of `< 0`. [F24]
- Architecture implementations of `arch_atomic64_inc_not_zero` (such as in `arch/powerpc/include/asm/atomic.h`) must normalize the 64-bit old counter value to a boolean `int` (`t1 != 0`) rather than returning the 64-bit value directly, which would truncate to `0` when the low 32 bits of a non-zero counter are zero. [F23]
- `refcount_set`, `refcount_set_release`, and `Refcount::set` must not be given a negative `int`/`i32` value because negative values represent the saturated (`bad value`) range; additionally, `refcount_set_release` must only be called after the new object is fully initialized. [F32]
- In `rust/kernel/sync/atomic.rs`, `unsafe trait AtomicType` must only be implemented for types with all bits initialized (no padding bytes or `MaybeUninit`) that are round-trip transmutable to `Self::Repr`, and `unsafe impl AtomicAdd<Rhs> for T` must ensure `T::rhs_into_delta(rhs)` produces a `<T::Repr as AtomicImpl>::Delta` (`i32` or `i64`) whose two's-complement `wrapping_add` with any valid `T::Repr` of `T` yields a valid bit pattern of `T`. [F31, F71]
- In `rust/kernel/sync/atomic.rs`, `Atomic::try_cmpxchg` must write the updated `tmp` representation back to `*old` (`*old = unsafe { from_repr(tmp) }`) before returning, because `Atomic::cmpxchg` passes `&mut old` and returns `Err(old)` on failure to report the current value of `*self`. [F36]
- In `arch/x86/include/asm/atomic64_32.h`, every out-of-line `atomic64_*_cx8` or `atomic64_*_386` helper invoked via `alternative_atomic64` or `__alternative_atomic64` must be declared with `ATOMIC64_DECL` or `ATOMIC64_DECL_ONE` before `#undef ATOMIC64_EXPORT` so `arch/x86/lib/atomic64_32.c` exports it with `EXPORT_SYMBOL`. [F109]

## Error Handling

- In `include/linux/refcount.h` and `rust/kernel/sync/refcount.rs`, whenever a refcount operation detects overflow (`old < 0 || old + i < 0`), addition on zero (`!old` in `__refcount_add`), underflow (`old <= 0 || old - i < 0`), or a `1 -> 0` leak (`old <= 1` in `refcount_dec`, `__refcount_dec`, and `Refcount::dec`), it must call `refcount_warn_saturate()` to clamp `r->refs` to `REFCOUNT_SATURATED`; dropping a potentially final reference must use `refcount_dec_and_test` or `Refcount::dec_and_test`. [F44, F110]

## Known Pitfalls

- In `arch/x86/include/asm/atomic64_32.h`, `arch_atomic64_read_nonatomic()` performs a non-atomic 64-bit read that may tear, so it must only seed unconditional `arch_atomic64_try_cmpxchg()` loops and never conditional loops (such as `atomic64_add_unless` or `atomic64_dec_if_positive`) that can exit early before `arch_atomic64_try_cmpxchg()` validates the value. [F37]
- In `arch/x86/include/asm/atomic64_32.h`, the `CONFIG_X86_CX8` definition of `__alternative_atomic64()` emits an inline `call` instruction and must wrap its output operand list with `ALT_OUTPUT_SP(out)` so the compiler tracks the stack pointer register dependency. [F96]
- In `arch/arm64/include/asm/atomic_ll_sc.h`, `__ll_sc__cmpxchg_case_##name##sz` (`__CMPXCHG_CASE`) takes `unsigned long old` and compares it with 32-bit `eor %w[tmp], %w[oldval], %w[old]`, so for sub-word sizes (`sz < 32`) it must explicitly cast `old = (u##sz)old` before the inline assembly. [F30]
- In `arch/arm64/include/asm/atomic_lse.h`, `__lse_atomic64_dec_if_positive()` reuses `[ret] "+&r" (v)` for the decremented return value while `[v] "+Q" (v->counter)` holds the memory address, so `[ret]` and `[tmp] "=&r" (tmp)` must keep the `&` earlyclobber modifier across the `1:` retry loop. [F66]
- In `arch/arm64/include/asm/atomic_ll_sc.h` and `arch/arm64/include/asm/atomic_lse.h`, the 128-bit compare-and-exchange macro `__CMPXCHG128` must type its `"+Q"` memory constraint operand as `*(u128 *)ptr` so the compiler hazards against all 16 bytes of the target. [F99]
- In `arch/arm64/include/asm/atomic_lse.h`, every inline assembly block emitting ARMv8.1 LSE instructions (`stclr`, `stset`, `steor`, `stadd`, `ldclr`, `ldset`, `ldeor`, `ldadd`, `cas`, `casp`) must begin with `__LSE_PREAMBLE` so the assembler enables the LSE architectural extension. [F81]
- In `arch_atomic_cmpxchg_relaxed()` and `arch_atomic64_cmpxchg_relaxed()` in `arch/arm/include/asm/atomic.h`, each `do { ... } while (res)` iteration must reset `res` (`mov %0, #0`) before `teq` and `strexeq`/`strexdeq`, because `strexeq`/`strexdeq` does not write `res` when `oldval != old`. [F61]
- In `arch/powerpc/include/asm/atomic.h`, `arch_atomic_fetch_add_unless()` and `arch_atomic64_fetch_add_unless()` add `a` in-place to `t` before `stwcx.`/`stdcx.`, so on the store-success path before label `2:` they must subtract `a` back (`sub%I2c`/`subf`) to return the original value. [F39]
- In `arch/powerpc/include/asm/atomic.h`, `arch_atomic_read`, `arch_atomic_set`, `arch_atomic64_read`, and `arch_atomic64_set` must use base-register zero-offset addressing (`"b"(&v->counter)`) when `IS_ENABLED(CONFIG_PPC_KERNEL_PREFIXED)` is true; when false, `arch_atomic64_read()` and `arch_atomic64_set()` emit DS-form instructions (`ld`/`std`) and must constrain `v->counter` with `DS_FORM_CONSTRAINT` rather than `"m<>"`. [F90, F97]
- In `arch/riscv/include/asm/atomic.h` and `arch/loongarch/include/asm/atomic.h`, `ATOMIC_OPS` for `sub` passes a negated operand `I = -i` to the hardware atomic add instruction (`amoadd`/`amadd`), so `c_op` in `ATOMIC_OP_RETURN` must be `+` (`result + (-i)`), not `-`. [F35]
- In `arch/s390/include/asm/atomic.h`, `arch_atomic64_sub`, `arch_atomic64_sub_return`, and `arch_atomic64_fetch_sub` must cast `_i` to `(s64)` before unary negation (`-(s64)(_i)`) so a 32-bit `unsigned int` argument is not negated in 32-bit unsigned arithmetic and zero-extended to a positive `s64`. [F70]
- In `arch/s390/include/asm/atomic_ops.h`, inline assembly memory operands for 64-bit and z196 atomic instructions (`__atomic64_read`, `__atomic64_set`, `__ATOMIC_OP`, `__ATOMIC_CONST_OP`, `__ATOMIC64_OP`, `__ATOMIC_TEST_OP`, `__ATOMIC_CONST_TEST_OP`) must use combined `"RT"` or `"+QS"` constraints rather than standalone `"T"` or `"+S"`. [F101]
- In `arch/mips/include/asm/atomic.h`, `ATOMIC_FETCH_OP` and `ATOMIC_SIP_OP` must exit the `.set MIPS_ISA_LEVEL` section with `.set pop` before emitting any `move` pseudo-instruction so the assembler does not emit a 64-bit `daddu` instruction on 32-bit MIPS builds. [F102]
- In `arch/arc/include/asm/atomic-llsc.h` and `arch/arc/include/asm/atomic64-arcv2.h`, inline assembly blocks (`ATOMIC_OP`, `arch_atomic64_set`, `ATOMIC64_OP`, `__arch_cmpxchg64_relaxed`) that modify `v->counter` through a register pointer input (`"r"(&v->counter)`) without a memory output constraint must clobber `"memory"` (or be surrounded by `smp_mb()`). [F98]
- `ATOMIC_HASH(a)` in `arch/parisc/include/asm/atomic.h` must cast pointer `a` to `unsigned long` before dividing by `L1_CACHE_BYTES` and masking with `ATOMIC_HASH_SIZE - 1`, so both `atomic_t *` and `atomic64_t *` addresses hash by byte cacheline offset into `__atomic_hash`. [F75]
- In `arch/m68k/include/asm/atomic.h`, direct-to-memory arithmetic and logical inline assembly (`ATOMIC_OP`, `arch_atomic_sub_and_test`, `arch_atomic_add_negative`) must constrain the integer operand with `ASM_DI` (`"d"` on `CONFIG_COLDFIRE`, `"di"` otherwise) because ColdFire CPUs cannot execute immediate-to-memory operations. [F86]
- In `arch/xtensa/include/asm/atomic.h`, the `!XCHAL_HAVE_EXCLUSIVE && !XCHAL_HAVE_S32C1I` inline assembly in `ATOMIC_OP`, `ATOMIC_OP_RETURN`, and `ATOMIC_FETCH_OP` must use fixed register `a14` (and clobber `"a14"`) for the `rsil`/`wsr` interrupt-masking sequence to prevent register window overflows. [F103]

## Other

- In `arch/alpha/include/asm/atomic.h`, every LL/SC store-conditional failure branch (`beq`) must branch forward to a retry stub in `.subsection 2` that jumps back (`br 1b`) to the `ldl_l`/`ldq_l` label, rather than branching backward directly in the main path. [F62]
