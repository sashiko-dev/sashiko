# MELLANOX MLX5 core VPI driver

The mlx5 core driver (`drivers/net/ethernet/mellanox/mlx5/core`) manages Mellanox ConnectX/BlueField PCI functions, Subfunctions (SFs), SR-IOV VFs, firmware command/event queues, health recovery, devlink, LAG, PTP clocks, E-Switch/switchdev offloads, flow steering (FS, SWS/mlx5dr, and HWS), Ethernet (`mlx5e`) RX/TX/XDP/XSK datapaths, TC offloads, and IPoIB.

## Architecture & Data Flow

- Multi-WQEBB SQ/ICOSQ WQEs cannot cross page boundaries; `mlx5e_txqsq_get_next_pi()` and `mlx5e_icosq_get_next_pi()` pad page-edge space with up to `wqe_size - 1` NOP WQEBBs (setting `.num_wqebbs = 1` in `sq->db.wqe_info` and refreshing `pi`), so room checks must reserve `MLX5E_STOP_ROOM(wqe_size)` (`2 * wqe_size - 1`) and `mlx5e_get_max_sq_aligned_wqebbs()` must clamp below `MLX5_SEND_WQE_MAX_WQEBBS` (16). [F82, F95, F126]
- `mlx5e_tir_init()` must either link `tir->list` into `res->td.tirs_list` under `res->td.list_lock` (`reg == true`) or call `INIT_LIST_HEAD(&tir->list)` (`reg == false`), because `mlx5e_tir_destroy()` tests `!list_empty(&tir->list)` before locking `list_lock` and calling `list_del(&tir->list)`. [F4]
- When allocating XSK RX descriptors (`mlx5e_xsk_alloc_rx_mpwqe()`, `mlx5e_xsk_alloc_rx_wqes*()`), per-WQE release state (`wi->skip_release_bitmap`/`wi->consumed_strides` or `MLX5E_WQE_FRAG_SKIP_RELEASE`) must be cleared; when `mlx5e_xdp_handle()` returns true on XSK RX, `MLX5E_RQ_FLAG_XDP_XMIT` must be cleared and skip-release marked. On XSK TX (`mlx5e_xsk_tx()`, `mlx5e_xsk_tx_post_err()`), when `xp_tx_metadata_enabled(sq->xsk_pool)` is true, a second `union mlx5e_xdp_info` entry (`.xsk_meta`) must be pushed to `sq->db.xdpi_fifo`. [F9, F79, F80]
- Subfunctions (`mlx5_core_is_sf(dev)`) leave `dev->priv.irq_table` and `eq_table->rmap` NULL, so callers must use `mlx5_irq_table_get(dev)` and `mlx5_eq_table_get_pci_rmap()`, pass `pool->dev->pdev` to `pci_irq_vector()` and `dev` to `mlx5_sf_coredev_to_adev()`, and obtain `mdev` via `container_of(adev, struct mlx5_sf_dev, adev)->mdev` rather than `pci_get_drvdata(mdev->pdev)`. [F86, F454, F565, F660, F661]

## Synchronization

- `devl_lock(priv_to_devlink(dev))` must be acquired before `dev->intf_state_mutex` (`mlx5_load_one_devl_locked()`, `mlx5_unload_one_devl_locked()`, `mlx5_health_try_recover()`) and before `mlx5_devcom_comp_lock()` in `dev.c`, and is required by `mlx5_eswitch_enable*()`/`disable*()`. `esw->state_lock` nests outside `esw_qos_lock(esw)` and must never be held across `mlx5_eswitch_event_handler_unregister()` or `flush_workqueue(esw->work_queue)`. [F495, F539, F898, F1280, F1283, F1288]
- Callers holding `priv->state_lock` (`mlx5e_xsk_disable_locked()`, `mlx5e_open_locked()`) must not synchronously invoke devlink health reporter recovery that acquires `devl_lock` (defer RX timeout to `rq->rx_timeout_work`), and `mlx5e_tx_reporter_recover_from_ctx()`/`err_cqe_recover()` must not acquire `priv->state_lock`. [F38, F1098]
- Polling an EQ (`mlx5_eq_comp_int()`, `mlx5_eq_async_int()`, `mlx5_eq_get_eqe()`) or CQ (`mlx5_cqwq_get_cqe*()`, `poll_timeout()` in `cmd.c`) requires `dma_rmb()`/`rmb()` after checking hardware ownership and before reading payload fields; `eq_update_ci()` must follow `__raw_writel` with `wmb()`. [F40, F732, F889, F1552]
- Posting WQEs (`mlx5e_notify_hw()`, `mlx5_wc_post_nop()`, `mlx5_aso_post_wqe()`) requires `dma_wmb()` before updating `*wq->db = cpu_to_be32(pc)` and `wmb()` before ringing the UAR/BlueFlame doorbell. Polling CQEs (`mlx5_wc_poll_cq()`, `mlx5e_ptp_poll_ts_cq()`, `mlx5_aso_poll_cq()`) requires `mlx5_cqwq_pop()`, `mlx5_cqwq_update_db_record()` (masking `wq->cc & 0xffffff`), and `wmb()` before advancing `cc` or pushing `ptpsq->metadata_freelist`. [F154, F730, F731, F813, F1095, F1484, F1549]
- Callbacks on `mlx5_eq_notifier_register()` (under `mlx5_eq_async::lock`), `mlx5_notifier_register()` (`events->fw_nh`), and async command callbacks (`mlx5_cmd_cbk_t` / `mlx5_async_cbk_t` from `mlx5_cmd_comp_handler()`) run in atomic EQ context and must not sleep; when `callback != NULL`, `cmd_alloc_ent()`/`cmd_exec()` must use `GFP_ATOMIC` and `mlx5_cmd_exec_cb()` must use `down_trylock`, while `mlx5_cmd_stats::lock` requires `spin_lock_irq`/`irqsave`. [F42, F173, F230, F1021, F1022, F1024]
- In `mlx5e_tc_ct_restore_flow()` (RX softirq), `ct_priv->ht_lock` is taken with `spin_lock()`, so all process/workqueue acquisitions of `ct_priv->ht_lock` must use `spin_lock_bh()`, and `mlx5e_tc_ct_restore_flow()` must release `entry` via `__mlx5_tc_ct_entry_put()` to defer `mlx5_tc_ct_entry_del()` to `ct_priv->wq`. [F168, F169]
- `fs_node.lock` must be acquired top-down (`FS_LOCK_GRANDPARENT` on `ft`, `FS_LOCK_PARENT` on `fg`, `FS_LOCK_CHILD` on `fte`) via `nested_down_read/write_ref_node()`. Because `alloc_insert_flow_group()` and `insert_fte()` insert into `fgs_hash`/`ftes_hash` with `node.active = false` before HW creation, lookups (`lookup_fte_locked()`) must check `node.active` under the node's write lock, and `_mlx5_add_flow_rules()`/`try_add_to_existing_fg()` must revalidate `ft->node.version` and `u64` `matched_fgs_get_version()` after dropping read locks. [F235, F241, F242, F249, F327, F356]
- In HWS BWC, `ctx->bwc_send_queue_locks[idx]` protects `bwc_matcher->rules[idx]` and the queue (`mlx5hws_bwc_rule_destroy_simple()` and `hws_bwc_rule_action_update()` must lock `bwc_rule->bwc_queue_idx`). Extending `bwc_matcher->at` or resizing/rehashing `bwc_matcher->matcher` requires unlocking the single `queue_lock`, locking all queues via `hws_bwc_lock_all_queues(ctx)`, revalidating, and re-reading `bwc_matcher->matcher` afterwards since `hws_bwc_matcher_move()` replaces and destroys `old_matcher`. [F556, F557, F558, F597, F658]

## Object Lifetimes

- `mlx5_eq_cq_get()` increments `cq->refcount` under `rcu_read_lock()`, so callers receiving a non-NULL CQ must call `mlx5_cq_put()`. `mlx5_irq_attach_nb()` must call `irq_get(irq)` before registering `nb`, `mlx5_irq_detach_nb()` must unregister `nb` before `mlx5_irq_put(irq)`, and `mlx5_irq_affinity_irq_release()` must read `pool` (via `mlx5_irq_get_pool(irq)`), `cpu`, and index before `mlx5_irq_put(irq)` and call `cpu_put(pool, cpu)` only when `mlx5_irq_put(irq)` returns non-zero. [F1, F379, F453, F546]
- `mlx5e_get_next_matching_encap()` drops the caller's reference on input `e` via `mlx5e_encap_put()` and returns a reference on the next entry, whereas `mlx5e_get_next_nhe()` acquires `next` via `mlx5e_rep_neigh_entry_hold()` under `rcu_read_lock()` before releasing input `nhe` via `mlx5e_rep_neigh_entry_release()` (in non-atomic context); breaking early from either loop requires releasing the current cursor. [F16, F1067, F1166]
- `lookup_fte_locked()` returns an active `fs_fte` with two references (`tree_get_node()` and `nested_down_write_ref_node()`) and `fte->node.lock` held, requiring both `up_write_ref_node(&fte->node, false)` and `tree_put_node(&fte->node, false)`. `tree_remove_node()` decrements `node->refcount` even when returning `-EEXIST` (`refcount > 1`), so `mlx5_destroy_flow_table()`/`mlx5_destroy_flow_group()` must not be retried. [F205, F206, F209]
- Device removal/shutdown (`remove_one()`, `shutdown()`, `mlx5_sf_dev_remove()`, `mlx5_sf_dev_shutdown()`) must set `MLX5_BREAK_FW_WAIT` in `dev->intf_state` before draining `fw_reset` or `health` workqueues. `mlx5_drain_fw_reset()` and `mlx5_drain_health_wq()` must set `MLX5_FW_RESET_FLAGS_DROP_NEW_REQUESTS` / `MLX5_DROP_HEALTH_WORK` before cancelling work, and `mlx5_pci_close()` must call `mlx5_drain_health_wq(dev)` before `iounmap(dev->iseg)`. [F232, F390, F541, F542]
- Notifiers must be unregistered before flushing or destroying their target workqueues (`mlx5e_tc_tun_cleanup()`, `mlx5_events_stop()`, `mlx5_pagealloc_stop()`, `mlx5e_pcie_cong_event_cleanup()`, `mlx5_clock_unload()`, `mlx5_ldev_free()`, `mlx5_lag_mp_cleanup()`, `mlx5e_rep_neigh_cleanup()`, `mlx5e_rep_bridge_cleanup()`), and `ct_priv->wq` must be flushed/destroyed before CT tables/rhashtables in `mlx5_tc_ct_del_ft_cb()`/`mlx5_tc_ct_clean()`. [F14, F32, F223, F404, F544, F907, F1068, F1090, F1557]
- In `cmd_work_handler()`, once `iowrite32be` rings `&dev->iseg->cmd_dbell`, `ent` must not be dereferenced unless `cmd_mode == CMD_MODE_POLLING || poll_cmd` (using local copies). In `mlx5_cmd_comp_handler()`, `cmd_ent_put(ent)` must only be called when `!forced`, `mlx5_cmd_is_down(dev)`, or `!opcode_allowed(cmd, ent->op)` so timed-out command slots stay reserved until firmware completes. In `mlx5_cmd_exec_cb_handler()`, `work` fields must be copied to locals before `work->user_callback(status, work)` and never dereferenced after. [F872, F873, F876]

## API Contracts

- `mlx5e_flow_get()`, `mlx5_eswitch_get_vport()`, `mlx5_devlink_eswitch_get()`, `mlx5_irq_affinity_request()`, `mlx5_get_uars_page()`, `mlx5e_tc_int_port_get()`, `mlx5e_tc_tun_init()`, `mlx5_create_flow_table()`, `mlx5_modify_header_alloc()`, and `mlx5_packet_reformat_alloc()` return `ERR_PTR` (never `NULL`), whereas `mlx5e_encap/decap/route_get()`, `mlx5_eswitch_get_rep()`, `mlx5_vf_get_core_dev()`, `mlx5_get_flow_namespace*()`, `mlx5_tc_ct_init()`, `mlx5e_tc_int_port_init()`, and `mlx5dr_*`/`mlx5_smfs_*`/`mlx5hws_*` allocators return `NULL` on failure. `mlx5_tc_ct_entry_get()` can return `NULL`, `ERR_PTR(-EINVAL)`, or a valid pointer. [F53, F56, F61, F254, F255, F417, F561, F740, F748, F1102, F1103, F1299]
- `create_comp_eq()` (unlike `mlx5_eqn2comp_eq()` which returns `ERR_PTR(-ENOENT)`), `mlx5_cmd_create_match_definer()`, `mlx5_esw_try_lock()`, `mlx5hws_buddy_alloc_mem()`, `MLX5_FLEXIBLE_INLEN()`, `mlx5e_htb_get_txq_by_classid()`, `mlx5e_select_htb_queue()`, and `mlx5_geneve_tlv_option_create()` return a non-negative ID/mode/offset/length on success and a negative errno on failure (store in signed `int` and test `< 0`). `mlx5_irq_get_locked()`/`irq_get()` return `1` on success and `0` on failure; `mlx5_vsc_gw_read_block_fast()` returns bytes read (check `ret != length`, not `ret < 0`). [F66, F250, F253, F559, F562, F563, F1104, F1464, F1465]
- Byte lengths/offsets must be divided by 2 (into 2-byte words) for `mlx5_wqe_eth_seg::swp_*_offset` (`mlx5e_set_eseg_swp()`), HWS `remove_words.num_of_words` (`action.c`, while `insert_header.header_size` is in bytes), and STE v1/v3 header action sizes/offsets (`dr_ste_v1/v3_set_*`, which must also call `dr_ste_v1_set_reparse()`). Geneve option lengths in `geneve_opt_len`/`genevehdr.opt_len` and `struct geneve_opt::length` are in 4-byte words (`len / 4` and `length * 4`). [F50, F63, F580, F857]

## Error Handling

- In `create_async_eqs()` and `destroy_async_eqs()`, once `mlx5_cmd_use_events()` switches command completions to `table->cmd_eq`, any rollback or teardown of `table->cmd_eq` must first call `mlx5_cmd_use_polling(dev)` and `mlx5_cmd_allowed_opcode(dev, CMD_ALLOWED_OPCODE_ALL)` before unregistering `cq_err_nb` and releasing `ctrl_irq`; `table->pages_eq` setup/cleanup must be skipped when `MLX5_CAP_GEN(dev, page_request_disable)` is set. [F3, F149]
- After publishing a shared resource with a completion (`hash_add_rcu()` in `mlx5e_attach_encap()` or `tbl->hlist` in `mlx5e_mod_hdr_attach()`), `complete_all(&res_ready)` must be called on both success and failure; `mlx5e_encap_entry::compl_result` and `mlx5e_mod_hdr_handle::compl_result` use `> 0` (`1`) for success and `< 0` for error (whereas `mlx5e_decap_entry::compl_result` uses `0` for success), and `mlx5e_encap_dealloc()` must also check `e->flags & MLX5_ENCAP_ENTRY_VALID` before freeing `e->pkt_reformat`. [F17, F51, F52, F195, F883]
- When a pointer field is inspected by teardown helpers that only check for non-NULL (`steering->*_root_ns`, `esw->fdb_table.offloads.esw_chains_priv`, `ft->fs_dr_table.dr_table`, `priv->adev[i]`, `res->rss[i]`, vport ACL pointers in `esw/acl/`, or `macsec_fs` fields), init error paths must reset the field to `NULL`, whereas `health->fw_reporter`, `fw_fatal_reporter`, and `vnic_reporter` store `ERR_PTR` and require `!IS_ERR_OR_NULL()` checks. [F220, F260, F407, F717, F913, F914, F1111, F1265, F1470]
- In `hws_bwc_matcher_move()`, once `mlx5hws_matcher_resize_set_target(old_matcher, new_matcher)` succeeds, even if `hws_bwc_matcher_move_all()` fails, `bwc_matcher->matcher` must be updated to `new_matcher` and `old_matcher` destroyed. In `mlx5hws_bwc_rule_create_simple()`, every error path after `hws_bwc_rule_cnt_inc_with_rehash()` must call `hws_bwc_rule_cnt_dec()`, and `-EBUSY`/`-ETIMEDOUT`/`-EAGAIN` from `hws_bwc_rule_create_sync()` must return immediately without rehashing. [F536, F538, F627]

## Known Pitfalls

- Structs used as hash/mapping keys (`struct mlx5_ct_tuple`, `struct mlx5_flow_act::vlan` in `mlx5_eswitch_termtbl_get_create()`, `struct mlx5_flow_spec`, `struct mlx5e_neigh`, `struct mlx5_mapped_obj`) must be zero-initialized (`= {}` or `memset`) so stack padding or union bytes do not corrupt lookups; reused buffers (`set_ctx` in `set_hca_cap()`, `flow_group_in` in `esw/acl/` and `fs_ttc.c`, `mnvda` in `nv_param.c`) must be cleared between calls. [F59, F263, F300, F573, F1113, F1114, F1313, F1472, F1487]
- `struct mlx5_flow_attr` ends with a union of flexible arrays (`esw_attr`/`nic_attr`), so copying it in `add_post_rule()` requires `ns_to_attr_sz(MLX5_FLOW_NAMESPACE_FDB)` rather than `sizeof(*attr)`, and `*old_attr = *attr` in `mlx5_tc_ct_entry_update_rule()` does not save `esw_attr`/`nic_attr`. `rq->mpwqe.info` elements have a trailing flexible array and must be indexed via `mlx5e_get_mpw_info(rq, i)`, never `rq->mpwqe.info[i]`. [F135, F136, F143, F1187]
- `mlx5e_mod_hdr_alloc()` can reallocate `mod_hdr_acts->actions` (when `!is_static` or transitioning from `is_static`), invalidating any previously returned action pointer, and callers must increment `mod_hdr_acts->num_actions` after populating each slot. Iterating `e->flows` (`struct encap_flow_item`) requires `container_of(efi, struct mlx5e_tc_flow, encaps[efi->index])` using the runtime `efi->index`, never `encaps[0]`. [F54, F884, F933, F999]
- 64-bit shifts must use 64-bit types/literals (`1ULL << ent->idx` in `mlx5_cmd_comp_handler()` so `ent->idx == 31` does not sign-extend into bit 32 `MLX5_TRIGGERED_CMD_COMP`; `1ULL << MLX5_EVENT_TYPE_*` in `eq.c`; `(u64)cbs_man` in `MLX5_CALC_CBS()`; `(u64)` casts on STE miss addresses in `dr_ste_v0/v1_get_miss_addr()`, `uar2pfn()` in `alloc_uars_page()`, `block_idx` in `mlx5_dm_sw_icm_alloc()`, and timer words in `poll_trace()`/`clock.c`). [F127, F806, F807, F976, F977, F1177, F1531, F1533]
- EQE CQ numbers (`eqe->data.comp.cqn`, `eqe->data.cq_err.cqn`) must be converted with `be32_to_cpu()` and masked with `0xffffff` before calling `mlx5_eq_cq_get()`. In `nic_vport_context` (`vport.c`) and `set_l2table_entry_cmd()` (`mpfs.c`), 6-byte MAC addresses sit after a 2-byte reserved pad (`+ 2` byte offset from `MLX5_ADDR_OF`). In `fte_match_param`, `MLX5_SET_TO_ONES` on `smac_47_16` or `dmac_47_16` must also set `smac_15_0` or `dmac_15_0` to ones. [F90, F823, F1347, F1507]
- In `mlx5_health_check_fatal_sensors()`, `sensor_pci_not_working(dev)` must be checked before `mlx5_get_nic_state(dev)` and `sensor_fw_synd_rfr(dev)` because offline PCI reads return `0xffffffff`, which aliases `MLX5_INITIAL_SEG_NIC_INTERFACE_SW_RESET` (`0x7`). `mlx5_fw_tracer_cleanup()` must use non-blocking `cancel_work(&tracer->update_db_work)` and `mlx5e_ptp_close_txqsq()` must guard `cancel_work_sync(&ptpsq->report_unhealthy_work)` with `current_work() != &ptpsq->report_unhealthy_work` to avoid self-deadlock. [F459, F879, F1072]
