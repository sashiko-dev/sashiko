# XARRAY

The XArray unit implements an RCU-safe, radix-tree-based resizable array mapping `unsigned long` indices to pointers or tagged value entries, supporting multi-index entries and hierarchical search marks, alongside the IDR and IDA ID allocation APIs.

## Architecture & Data Flow

- `xas->xa_node` encodes special cursor states (`NULL` for root, `XAS_BOUNDS`, `XAS_RESTART`, and `XA_ERROR(errno)` with low bits `10`) alongside `struct xa_node *` pointers; verify `xas_is_node(xas)` or `!xas_not_node(node)` before dereferencing `xas->xa_node` rather than only checking `!= NULL`. Similarly, verify `xa_is_node(entry)` (which checks `xa_is_internal(entry)` and `(unsigned long)entry > 4096`) before calling `xa_to_node(entry)` [F35, F107].
- XArray entries encode their type in the low two bits (`00` for pointers, `10` for internal entries via `xa_mk_internal()`, and `x1` for value entries or tagged pointers); pointers passed to `xa_tag_pointer()` must be 4-byte aligned and tags must be `0`, `1`, or `3` (never `2`) [F71].
- The normal XArray API (`xa_load`, `__xa_erase`, `__xa_store`, `__xa_cmpxchg`) translates `XA_ZERO_ENTRY` to `NULL` via `xa_zero_to_null()`, whereas `__xa_insert()` must use `__xa_cmpxchg_raw()` so an existing `XA_ZERO_ENTRY` (reserved slot) is seen as non-NULL and returns `-EBUSY` [F46].
- Within an `xa_node`, search mark bits in `node->marks` must only be set on canonical entry offsets and never on sibling slots (`xa_is_sibling()`); `xas_squash_marks()` merges sibling range marks onto `xas->xa_offset`, and `node_mark_slots()` during `xas_split()` / `xas_try_split()` strides by `sibs + 1` [F53].
- On `XA_FLAGS_TRACK_FREE` arrays, `xas_store()` sets `XA_FREE_MARK` when storing `NULL`, but callers storing non-`NULL` entries (`__xa_store()`, `__xa_cmpxchg_raw()`, `__xa_alloc()`) must explicitly clear `XA_FREE_MARK`. For `XA_FLAGS_ZERO_BUSY` (`XA_FLAGS_ALLOC1`) arrays, `xas_create()` / `xas_expand()` must materialize an empty index `0` as `XA_ZERO_ENTRY` with slot 0's `XA_FREE_MARK` cleared, and `xas_shrink()` / `xa_destroy()` must convert `XA_ZERO_ENTRY` back to `NULL` in `xa->xa_head` and clear `XA_FREE_MARK` on `xa` [F55, F56].
- Every mutation that changes `node->count` or `node->nr_values`—in `update_node()`, `xas_split()`, `xas_try_split()`, `xas_shrink()`, and `xas_free_nodes()`—must call `xas_update(xas, node)` on each affected node before freeing it or returning [F52].
- In `xas_store()`, storing the identical single-slot entry (`(first == entry) && !xas->xa_sibs`) returns immediately without modifying `count`, `values`, or marks, whereas overwriting an existing child `xa_node` (`xa_is_node(next) && (!node || node->shift)`) must free the replaced subtree via `xas_free_nodes()`. When `node` is `NULL` (`slot == &xas->xa->xa_head`), the store loop must exit at `if (!node) break;` before incrementing `offset` or `slot` [F9, F112].
- In `__xa_alloc()`, `xas.xa_index = limit.min` must be re-initialized inside the `do { ... } while (__xas_nomem(&xas, gfp))` loop before `xas_find_marked()`. In `__xa_alloc_cyclic()`, when `*next = *id + 1` wraps to `0`, `XA_FLAGS_ALLOC_WRAPPED` must be set in `xa->xa_flags` and consumed on the next call to return `1`. In `xa_store_range()`, check `if (xas_error(&xas)) goto unlock;` before advancing `first += xas_size(&xas)` so `-ENOMEM` retries resume at `first` [F64, F87, F95].
- Each slot in `ida->xa` stores either a value entry (`xa_is_value(entry)`) holding `BITS_PER_XA_VALUE` (`BITS_PER_LONG - 1`) bits or a `struct ida_bitmap *`; `ida_alloc_range()`, `ida_find_first_range()`, `ida_free()`, and `ida_destroy()` must check `xa_is_value()` before dereferencing or freeing an entry as a bitmap, and only use value entries for bit offsets `< BITS_PER_XA_VALUE`. Never clear `XA_FREE_MARK` on IDA value entries; clear it only when a `struct ida_bitmap` is full (`bitmap_full()`), and re-set it via `xas_set_mark(&xas, XA_FREE_MARK)` when clearing a bitmap bit [F38, F61, F98].
- All IDR operations (`idr_alloc_u32()`, `idr_remove()`, `idr_find()`, `idr_for_each()`, `idr_get_next_ul()`, `idr_replace()`) bias radix-tree indices by subtracting `idr->idr_base` before tree access and adding `idr->idr_base` back when returning IDs [F66].

## Synchronization

- In `xas_expand()`, `xas_create()`, `xas_split()`, and `xas_try_split()`, all fields, child slots, and mark bitmaps of a new `struct xa_node` must be initialized before `rcu_assign_pointer()` publishes `xa_mk_node(node)`. When `xas_split()` or `xas_try_split()` splits an entry within the same `xa_node`, it must store `entry` into each canonical slot `node->slots[canon]` before writing `xa_mk_sibling(canon)` into higher sibling slots while iterating `offset` downward to `xas->xa_offset` [F14, F15].
- In `xas_store()`, erasing an entry (`!entry`) must call `xas_init_marks(xas)` before `rcu_assign_pointer(*slot, entry)` publishes `NULL`; if an RCU reader in `xas_find_marked()` or `xas_next_marked()` sees a mark on a `NULL` slot (other than `XA_FREE_MARK` on an `xa_track_free` array), it must continue searching [F27].
- When unlinking an `xa_node` in `xas_shrink()` or `xas_free_nodes()`, every non-node present slot in the unlinked node must be overwritten with `XA_RETRY_ENTRY` before `xa_node_free()` is called, and `xas->xa_node` in `xas_shrink()` / `xas_delete_node()` must be set to `XAS_BOUNDS` when the root node is removed [F57].
- In `xas_descend()`, resolving a sibling entry under RCU must loop with `while (xa_is_sibling(entry))` to handle concurrent range stores, and if following a sibling in an internal node (`node->shift > 0`) loads a child node (`xa_is_node(entry)`) due to a concurrent split, it must return `XA_RETRY_ENTRY` [F28].
- Lockless RCU callers of `xas_load()`, `xas_find()`, `xas_find_marked()`, `xas_for_each()`, or `xas_for_each_marked()` must filter returned entries with `xas_retry()`, which calls `xas_reset(xas)` on `XA_RETRY_ENTRY` to restart from `xa_head` while returning `true` without resetting `xas` on `XA_ZERO_ENTRY` [F29].
- In `idr_get_next_ul()` and `idr_get_next()`, lockless RCU iteration must loop with `radix_tree_for_each_slot()`, skip `NULL` slots from concurrent `idr_remove()`, and call `radix_tree_iter_retry(&iter)` only when `entry` is `XA_RETRY_ENTRY` or an internal entry at `&idr->idr_rt.xa_head` [F122].
- While holding `xa->xa_lock`, `xas_alloc()` and `xas_try_split()` must only allocate `struct xa_node` objects using `GFP_NOWAIT` (plus `__GFP_ACCOUNT` if `XA_FLAGS_ACCOUNT` is set), deferring sleepable `gfp_t` allocations to `xas_nomem()`, `__xas_nomem()`, or `xas_split_alloc()` outside `xa->xa_lock`. When `__xas_nomem()` drops and reacquires `xa->xa_lock`, it selects the lock variant from `xa_lock_type(xas->xa)` (`XA_FLAGS_LOCK_IRQ` or `XA_FLAGS_LOCK_BH`), so arrays locked with `_irq` or `_bh` must have the matching flag in `xa_flags` [F18, F22].
- In `__xa_cmpxchg_raw()`, `curr = xas_load(&xas)` and `curr == old` must remain inside the `do { ... } while (__xas_nomem(&xas, gfp))` loop so the slot is reloaded and revalidated if `__xas_nomem()` drops `xa->xa_lock` [F25].
- `xa_head_locked()`, `xa_entry_locked()`, and `xa_parent_locked()` assert `lockdep_is_held(&xa->xa_lock)`, so callers (`xas_create()`, `xas_store()`, `xas_set_mark()`, `xas_clear_mark()`, `xas_find_conflict()`, `xa_delete_node()`) require `xa->xa_lock`. `xa_update_node_t` callbacks invoked from `xas_update()` also run under `xa->xa_lock` with interrupts possibly disabled and must never drop the lock, enable interrupts, or sleep [F21, F125].
- `struct idr` mutation functions (`idr_alloc_u32()`, `idr_alloc()`, `idr_alloc_cyclic()`, `idr_remove()`, `idr_replace()`) require external caller locking, whereas `struct ida` operations must take `xa_lock_irqsave(&ida->xa, flags)` because `ida_bitmap` is freed with `kfree()` without RCU. In `__xa_alloc()` and `idr_alloc_u32()`, write the allocated ID to `*id` / `*nextid` before publishing the entry pointer (and only after `idr_get_free()` succeeds) [F19, F63].

## Object Lifetimes

- Because `xas_start()` trusts a valid `xas->xa_node` (`xas_valid(xas)`) and immediately dereferences it via `xas_reload()`, any code that drops `xa->xa_lock` or `rcu_read_lock()` must reset `xas->xa_node` to `XAS_RESTART` (via `xas_reset()`, `xas_set()`, `xas_pause()`, or `xas_nomem()`) before reusing `xas` [F23].
- When aborting an operation on `struct xa_state` or cleaning up after `xas_split_alloc()` or `xas_try_split()`, callers must call `xas_destroy()` rather than `xas_nomem()` to free `xas->xa_alloc`, because `xas_nomem()` allocates a new node when `xas->xa_node == XA_ERROR(-ENOMEM)` [F1].
- `xas_alloc()` consumes a single preallocated `xa_node` by setting `xas->xa_alloc = NULL`, whereas `xas_split_alloc()` chains multiple pre-initialized nodes via `node->parent` to be popped by `xas_split()` or freed via `xas_destroy()` / `radix_tree_node_rcu_free()` (never raw `kmem_cache_free()`, which requires zeroed `slots` and `tags`) [F6, F106].
- Because `private_list` and `rcu_head` share a union in `struct xa_node`, `list_empty(&node->private_list)` must hold before `xa_node_free()` or `xas_destroy()` frees the node via RCU [F3].
- In `ida_alloc_range()`, a fallback `struct ida_bitmap` allocated into `alloc` after dropping `xa_lock` must be freed via `kfree(alloc)` on both the `nospc` error exit and the `out` exit path whenever `bitmap != alloc` [F2].

## API Contracts

- `xas_reload()` requires `xas_valid(xas)` to be true because it dereferences any non-NULL `xas->xa_node`; after `XA_STATE()`, `xas_reset()`, or `xas_pause()`, call `xas_load()` instead. When `xas_find_marked()` finishes without a match, it must set `xas->xa_node` to `XAS_RESTART` if `xas->xa_index > max`, and `XAS_BOUNDS` only when `xas->xa_index <= max` [F36, F58].
- `__xa_store()`, `__xa_cmpxchg_raw()`, and `__xa_alloc()` reject `xa_is_advanced(entry)` entries (`xa_is_internal(entry) && entry <= XA_RETRY_ENTRY`) with `-EINVAL` while permitting `XA_ZERO_ENTRY`, whereas `xa_store_range()` rejects all `xa_is_internal(entry)` entries (including `XA_ZERO_ENTRY`) with `XA_ERROR(-EINVAL)`. `xa_mk_value(v)` warns if `(long)v < 0`, restricting values to `[0, LONG_MAX]` [F45, F48].
- `__xa_alloc*()` requires `XA_FLAGS_TRACK_FREE` (`XA_FLAGS_ALLOC` or `XA_FLAGS_ALLOC1`), failing with `-EINVAL` if `!xa_track_free(xa)`. `__xa_alloc_cyclic()` returns `1` on wrap-around and `0` otherwise, whereas `xa_alloc_cyclic*()` wrappers normalize non-negative returns to `0` [F34, F47].
- `xa_destroy()` frees only internal `struct xa_node` structures and not user pointers stored in the array, whereas `ida_destroy()` calls `kfree()` on every non-value `struct ida_bitmap`. `xa_find()`, `xa_find_after()`, `idr_get_next()`, and `idr_get_next_ul()` must only update `*indexp` or `*nextid` when a matching entry is found [F10, F44].
- Mutations updating node counts on an XArray that uses `node->private_list` must set `xas->xa_update` via `xas_set_update()` (otherwise `xas_update()` asserts `list_empty(&node->private_list)`). When `XA_FLAGS_ACCOUNT` is set, node allocations must OR `__GFP_ACCOUNT` into `gfp` and pass `xas->xa_lru` to `kmem_cache_alloc_lru()` [F131, F132].
- Before calling `xas_split()` across a node level (`xas->xa_shift < node->shift`), the caller must call `xas_split_alloc()` with the same order and `entry` and abort if `xas_error(xas)`. `xas_split_alloc()` only supports splitting across one `xa_node` level (`xas->xa_shift + 2 * XA_CHUNK_SHIFT > order`), and `xas_try_split()` rejects horizontal splits (`sibs != 0`) or vertical splits below `order - 1` with `-EINVAL`. When `!CONFIG_XARRAY_MULTI`, `xas_set_order()` triggers `BUG_ON(order > 0)` [F82, F133, F138].
- `idr_alloc()` and `idr_alloc_cyclic()` take an exclusive upper bound `end` (`end <= 0` means `INT_MAX + 1`), whereas `idr_alloc_u32()`, `xa_alloc*()`, `ida_alloc_range()`, and `ida_find_first_range()` take inclusive upper bounds. `ida_alloc_range()` and `ida_find_first_range()` clamp `(int)max < 0` to `INT_MAX`, and on `(int)min < 0` return `-ENOSPC` and `-EINVAL` respectively [F49, F50].
- In `idr_for_each_entry_ul()` and `idr_for_each_entry_continue_ul()`, the loop condition must save the prior ID in `tmp` before `++id` and evaluate `((entry) = tmp <= id ? idr_get_next_ul(idr, &(id)) : NULL) != NULL` so `++id` wrapping from `ULONG_MAX` to `0` terminates with `entry == NULL` [F84].

## Error Handling

- `xa_store()`, `__xa_store()`, `xa_cmpxchg()`, `__xa_cmpxchg()`, and `xa_store_range()` return `XA_ERROR` pointers on failure, which callers must check with `xa_is_err()` / `xa_err()` (where `xa_is_err()` compares against `xa_mk_internal(-MAX_ERRNO)` and `xa_err()` uses a signed shift `(long)entry >> 2` rather than `xa_to_internal()`). Conversely, `idr_replace()` returns `ERR_PTR(-ENOENT)` (without `WARN_ON_ONCE` on unallocated or negative IDs) and must be checked with `IS_ERR()` / `PTR_ERR()` [F31, F32, F51, F128].
- `xas_set_err()` requires a negative errno; clear errors via `xas_reset()`, never `xas_set_err(xas, 0)`. `xas_nomem()` and `__xas_nomem()` only allocate a node and reset `xas->xa_node` to `XAS_RESTART` when `xas->xa_node == XA_ERROR(-ENOMEM)`; otherwise they call `xas_destroy(xas)` and return `false` without overwriting `xas->xa_node`. On failure in `xas_split_alloc()` or `xas_try_split()`, call `xas_destroy(xas)` before `xas_set_err()` [F33, F40, F41].
- In `xas_create_range()`, parent traversal must stop if `node->shift >= shift`, and on `xas_error(xas)` it must restore `xas->xa_shift`, `xas->xa_sibs`, and `xas->xa_index` while preserving `xas->xa_node` [F39].
- `idr_for_each()` and `idr_get_next()` must guard against IDs exceeding `INT_MAX` with `WARN_ON_ONCE(id > INT_MAX)` before truncating to `int`. `ida_free()` must silently return when `(int)id < 0`, and on an unallocated non-negative `id` must unlock `xa_lock` before calling `WARN()` (never `BUG_ON()`) [F67, F126, F127].

## Known Pitfalls

- To pause `xas_for_each()` or `xas_for_each_marked()` before dropping `xa_lock` or `rcu_read_lock()`, call `xas_pause(xas)` while still holding the lock; it advances `xas->xa_index` past sibling slots and sets `xas->xa_node` to `XAS_BOUNDS` on wrap to `0`, or `XAS_RESTART` otherwise [F60, F89].
- Widen `unsigned char` slot fields (`xa_offset`, `xa_sibs`, `node->offset`) to `unsigned long` before left-shifting by `node->shift` or `xas->xa_shift` (which can reach 60 on 64-bit). Guard `(index >> order) << order` in `xas_set_order()` with `order < BITS_PER_LONG ? ... : 0`, and guard `__ffs(last + 1)` in `xa_store_range()` with `if (last + 1)` [F96, F99].
- `__xas_prev()` relies on `unsigned char xas->xa_offset` wrapping from `0` to `255` (`while (xas->xa_offset == 255)`) to detect underflow. In `xas_find_marked()`, after `xas_move_index(xas, offset)`, check `(xas->xa_index - 1) >= max` to catch `xa_index` wrapping to `0` at `ULONG_MAX`. In `xas_find_chunk()`, use single-word masking (`*addr & (~0UL << offset)`) only when `XA_CHUNK_SIZE == BITS_PER_LONG` and `offset < XA_CHUNK_SIZE` [F75, F78, F111].
