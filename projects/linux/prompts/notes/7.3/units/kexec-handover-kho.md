# KEXEC HANDOVER (KHO)

Kexec Handover (KHO) preserves physical memory pages, folios, vmalloc regions, and subsystem metadata blobs across a kexec reboot for live update. It tracks preserved physical memory ranges in a page-based radix tree, passes metadata and subsystem subtrees via a Flattened Device Tree (FDT), and reserves movable CMA-backed scratch regions so the incoming kernel can perform early-boot allocations and place kexec segments without overwriting preserved memory.

## Architecture & Data Flow

- Before `kho_preserved_memory_reserve()` writes `union kho_page_info` (`info.magic = KHO_PAGE_MAGIC`) into `page->private`, it must initialize all `1UL << order` struct pages via `kho_get_preserved_page()` (calling `init_deferred_page()` under `CONFIG_DEFERRED_STRUCT_PAGE_INIT`) and call `memblock_reserved_mark_noinit()`. `kho_restore_page()` requires `info.magic == KHO_PAGE_MAGIC` in `page->private` and must clear `page->private = 0` so unpreserved, tail, or already-restored pages return `NULL`. [F31, F41]
- When `kho_restore_page()` reconstructs pages from reserved memory, `kho_init_folio()` must set the head page refcount to 1, clear its codetag via `clear_page_tag_ref()`, and zero tail page refcounts, whereas `kho_init_pages()` must set refcount to 1 and call `clear_page_tag_ref()` on every individual page `page + i`. [F39]
- `struct kho_radix_node`, `struct kho_radix_leaf`, and `struct kho_vmalloc_chunk` pages must be zero-initialized on allocation (`get_zeroed_page()` or `memblock_alloc()`) because `0` is the sentinel for empty `table[]` entries, unset `bitmap` bits, end-of-array in `chunk->phys[]`, and `NULL` in `chunk->hdr.next`. Loops over `chunk->phys` in `kho_vmalloc_unpreserve_chunk()` and `kho_restore_vmalloc()` must check both `i < ARRAY_SIZE(chunk->phys)` and `chunk->phys[i]`. [F34, F57]
- In `kho_radix_get_table_index()` and `__kho_radix_walk_tree()`, level `0` is the `struct kho_radix_leaf` bitmap and intermediate `struct kho_radix_node` tables use 1-based levels `1 .. KHO_TREE_MAX_DEPTH - 1` with shift `((level - 1) * KHO_TABLE_SIZE_LOG2) + KHO_BITMAP_SIZE_LOG2`. Because `kho_radix_walk_leaf()` casts `struct kho_radix_leaf *` to `unsigned long *` across `PAGE_SIZE * BITS_PER_BYTE` bits while `kho_radix_add_key()` and `kho_radix_del_key()` use `leaf->bitmap`, `bitmap` must stay at offset 0 and span `PAGE_SIZE`. [F56, F84]
- `__kho_preserve_pages_order()` must only be called when `start_pfn < end_pfn`, must cap the initial order to `min(count_trailing_zeros(start_pfn), ilog2(end_pfn - start_pfn))`, and must decrement `order` using `1UL << order` until `start_pfn` and `start_pfn + (1UL << order) - 1` reside in the same NUMA node. [F79]
- In `kho_populate()`, every incoming `scratch` area must be registered with `memblock_add()` and marked via `memblock_mark_kho_scratch()`, and the descriptor array reserved with `memblock_reserve(scratch_phys, scratch_len)`, before calling `memblock_set_kho_scratch_only()`. On a KHO boot, `kho_memory_init_early()` must set `kho_scratch = phys_to_virt(kho_in.scratch_phys)` before `free_area_init()` and call `kho_extend_scratch()` only after `efi_init()`/`reserve_regions()`. [F98, F99]
- `kho_extend_scratch()` must register both `.leaf = kho_ext_walk_leaf` and `.node = kho_ext_walk_node` when walking `kho_in.radix_tree` into `busy_blocks`, because radix tree table pages are not recorded as leaves in `kho_in.radix_tree` itself but must not be marked `MEMBLOCK_KHO_SCRATCH` before `kho_mem_retrieve()` parses the tree. [F47]
- In `kho_reserve_scratch()`, both `kho_scratch_cnt` (`nodes_weight(node_states[N_MEMORY]) + 2`) and the per-node allocation loop (`for_each_node_state(nid, N_MEMORY)`) must filter by `N_MEMORY` to skip memoryless NUMA nodes. Scratch sizes in `scratch_size_update()` and `scratch_size_node()` must be rounded up with `round_up(..., SCRATCH_ALIGNMENT_BYTES)` (`PAGE_SIZE * MAX_ORDER_NR_PAGES`) and allocated with `SCRATCH_ALIGNMENT_BYTES` alignment. [F68, F81]
- On cold (non-KHO) boots, `kho_init()` must register each `kho_scratch[i]` region with `kmemleak_ignore_phys()` before releasing its pageblocks to CMA via `init_cma_reserved_pageblock()`. [F122]
- In `kho_preserve_vmalloc()` and `kho_restore_vmalloc()`, `struct kho_vmalloc::total_pages` stores the total count of order-0 base pages (`vm->nr_pages`) and `area->pages` holds `total_pages` base `struct page` pointers, whereas each `struct kho_vmalloc_chunk::phys[i]` entry stores the physical address of a contiguous `(1 << order)`-page block. [F83]
- Serializable pointer unions declared with `DECLARE_KHOSER_PTR` (`preservation->first` in `struct kho_vmalloc` and `chunk->hdr.next` in `struct kho_vmalloc_hdr`) must be written with `KHOSER_STORE_PTR()` and read with `KHOSER_LOAD_PTR()` rather than accessed via `.ptr` directly. [F59]
- `kho_preserve_vmalloc()` and `kho_restore_vmalloc()` only accept vmalloc regions whose flags are a subset of `KHO_VMALLOC_SUPPORTED_FLAGS` (`VM_ALLOC | VM_ALLOW_HUGE_VMAP`), rejecting other flags with `-EOPNOTSUPP` on preserve or `NULL` on restore. `KHO_VMALLOC_SUPPORTED_FLAGS`, `KHO_VMALLOC_*`, `vmalloc_flags_to_kho()`, and `kho_flags_to_vmalloc()` must be updated in lockstep so all supported flags round-trip through `preservation->flags`. [F50, F121]

## Synchronization

- `kho_out.lock` serializes both in-place modifications to `kho_out.fdt` and unlocked `list_add()`/`list_del()` mutations of `kho_out.dbg.fdt_list`. `kho_add_subtree()` and `kho_remove_subtree()` must update the subnodes in `kho_out.fdt` (setting both `KHO_SUB_TREE_PROP_NAME` and `KHO_SUB_TREE_SIZE_PROP_NAME`) and the debugfs blob list (`kho_debugfs_blob_add()` / `kho_debugfs_blob_remove()`) in lockstep under `kho_out.lock`. [F17, F42]
- `struct kho_radix_tree::lock` protects all intermediate node table allocations/lookups and non-atomic `__set_bit()`/`__clear_bit()` leaf bitmap updates in `kho_radix_add_key()`, `kho_radix_del_key()`, and `kho_radix_walk_tree()`. Because `kho_radix_walk_tree()` holds `tree->lock` across all `cb->node` and `cb->leaf` callbacks and `kho_radix_init_tree()` shares one lockdep class, walk callbacks must never call `kho_radix_add_key()`, `kho_radix_del_key()`, or `kho_radix_walk_tree()` on the same tree, and any second tree locked inside a callback needs `lockdep_set_class()`. [F18, F19, F20]
- `struct kho_block_set` and its `kho_block_set_*` and `kho_block_set_it_*` helpers perform no internal locking when mutating `bs->blocks`, `bs->nblocks`, `bs->head_pa`, or `block->ser`, so callers must externally synchronize concurrent operations on the same block set. [F21]

## Object Lifetimes

- Temporary mappings created with `early_memremap()` in `kho_populate()` for `fdt` and `scratch` must be unmapped in reverse acquisition order via `early_memunmap(scratch, scratch_len)` followed by `early_memunmap(fdt, fdt_len)` on both the normal completion path and all error paths. [F1]
- `kho_radix_alloc_node()` and `kho_radix_free_node()` must be annotated with `__ref`, pairing `get_zeroed_page(GFP_KERNEL)` with `free_page()` when `slab_is_available()` is true and `memblock_alloc(PAGE_SIZE, PAGE_SIZE)` with `memblock_free(node, PAGE_SIZE)` when false, and `kho_radix_destroy_tree()` must clear `tree->root = NULL`. A `struct kho_radix_tree` allocated via `memblock_alloc()` or inherited from the previous kernel must not be passed to `kho_radix_destroy_tree()` after `slab_is_available()` becomes true. [F5, F92, F105]
- Memory allocated and preserved by `kho_alloc_preserve()` must be released with `kho_unpreserve_free()` in the pre-kexec kernel (`kho_unpreserve_folio()` then `folio_put()`), whereas in the post-kexec kernel it must be reclaimed and freed with `kho_restore_free()` (`kho_restore_folio(__pa(mem))` then `folio_put()`). [F8]
- Because `new_vmalloc_chunk()` allocates each `struct kho_vmalloc_chunk` with `get_zeroed_page(GFP_KERNEL)` and preserves it via `kho_preserve_pages()`, `kho_preserve_vmalloc()` must set `preservation->first` before the page loop for rollback, `kho_unpreserve_vmalloc()` must free each chunk with `free_page()`, and `kho_restore_vmalloc()` must restore each chunk with `kho_restore_pages()` and free it with `__free_page()`—always loading `KHOSER_LOAD_PTR(chunk->hdr.next)` before freeing `chunk`. [F9, F49]

## API Contracts

- All KHO preservation, unpreservation, subtree registration, and radix-tree modification APIs (`kho_radix_add_key()`, `kho_radix_del_key()`, `kho_preserve_*()`, `kho_unpreserve_*()`, `kho_alloc_preserve()`, `kho_add_subtree()`, `kho_remove_subtree()`, and `kho_restore_vmalloc()`) may sleep and must only be called from process context. [F104]
- Folios preserved via `kho_preserve_folio()` must use `kho_unpreserve_folio()` and `kho_restore_folio()` with the exact folio PFN and order, whereas ranges preserved via `kho_preserve_pages()` must use `kho_unpreserve_pages()` and `kho_restore_pages()` with the identical start address and `nr_pages`. [F35]
- `kho_alloc_preserve()` must reject `size == 0` with `ERR_PTR(-EINVAL)` and `get_order(size) > MAX_PAGE_ORDER` with `ERR_PTR(-E2BIG)` before calling `folio_alloc()`, and always returns an `ERR_PTR()` on failure (never `NULL`), whereas `kho_restore_folio()`, `kho_restore_pages()`, and `kho_restore_vmalloc()` return `NULL` on failure. [F25, F60]
- Memory blobs passed to `kho_add_subtree()` and `kho_remove_subtree()`, as well as pointers passed to `kho_unpreserve_free()` and `kho_restore_free()`, must reside in the kernel linear direct map rather than `vmalloc` address space. `kho_add_subtree()` only records `virt_to_phys(blob)` in the root FDT and registers a borrowed pointer in debugfs, so the caller must separately preserve `blob`'s pages and call `kho_remove_subtree(blob)` before unpreserving and freeing `blob`. [F11, F106]
- `kho_unpreserve_vmalloc()` only unpreserves the vmalloc data pages and frees the internal `struct kho_vmalloc_chunk` metadata pages, leaving ownership of the virtual mapping `@ptr` with the caller to free via `vfree()`. [F10]
- In `kho_restore_vmalloc()`, the `vm_struct` must be allocated with `VM_UNINITIALIZED`, populated and wired to `area->pages` and `area->nr_pages`, unpoisoned via `kasan_unpoison_vmalloc()` (adding `KASAN_VMALLOC_VM_ALLOC` when `VM_ALLOC` is set), and finalized with `clear_vm_uninitialized_flag()`. [F114]
- `kho_encode_radix_key()` and `kho_decode_radix_key()` require `@phys` to be aligned to `1UL << (PAGE_SHIFT + order)` with `PAGE_SHIFT + order < 64`; `kho_decode_radix_key()` must subtract 1 from 1-based `fls64(key)` to get `order_bit` and shift the 64-bit `@key` left by `PAGE_SHIFT + *order` (`64 - order_bit`) to shift out the order bit. `kho_radix_add_key()` and `kho_radix_del_key()` only accept keys with `fls64(key) <= KHO_RADIX_KEY_WIDTH` (`-ERANGE` or early return). [F37, F54, F77]
- `kho_fill_kimage()` and `kho_locate_mem_hole()` must bypass KHO scratch placement when `!kho_enable` or when loading a crash kernel (`image->type == KEXEC_TYPE_CRASH`), with `kho_locate_mem_hole()` returning `1` on bypass, `0` on success, and `-EADDRNOTAVAIL` on failure. [F124]

## Error Handling

- `kho_populate()` must verify that `kho_get_mem_map_phys(fdt)` returns a non-zero physical address before registering incoming `scratch` regions in memblock or setting `kho_in.fdt_phys` and `kho_in.scratch_phys`. If `kho_memory_init_early()` fails `kho_get_mem_map(fdt)` or `kho_radix_init_tree(&kho_in.radix_tree, mem_map)`, it must zero `kho_in.fdt_phys` and `kho_in.scratch_phys`; if `kho_mem_retrieve()` fails `kho_radix_walk_tree()`, it must zero `kho_in.fdt_phys` and `kho_in.radix_tree.root`. [F2, F3]
- When `kho_radix_add_key()` allocates intermediate nodes along a missing branch and a subsequent `kho_radix_alloc_node()` call fails, it must free all newly allocated nodes in `intermediate_nodes[]` via `kho_radix_free_node()` and reset `anchor_node->table[anchor_idx] = 0` while holding `tree->lock`. [F4]
- In `kho_add_subtree()` and `kho_remove_subtree()`, any path after a successful `fdt_open_into(root_fdt, root_fdt, PAGE_SIZE)` must repack `root_fdt` with `fdt_pack(root_fdt)` under `kho_out.lock`. In `kho_add_subtree()`, libfdt return values from `fdt_open_into()`, `fdt_add_subnode()`, and `fdt_setprop()` must be kept in signed variables (`off`, `fdt_err`) and translated to `-EEXIST` or `-ENOMEM`, and any `fdt_setprop()` failure must call `fdt_del_node(root_fdt, off)` before `fdt_pack()`. [F12, F27]
- In `kho_reserve_scratch()`, the index `i` into `kho_scratch` must be a signed `int` so that on any memblock allocation failure, `err_free_scratch_areas` frees all previously allocated `kho_scratch[0..i-1]` areas via `memblock_phys_free()` in reverse (`for (i--; i >= 0; i--)`), frees the `kho_scratch` array via `memblock_free()`, and sets `kho_enable = false`. [F13, F65]
- If `kho_init()` fails during setup, it must unwind in reverse acquisition order by calling `kho_unpreserve_free(kho_out.fdt)` (only when `kho_out.fdt` is not an `ERR_PTR`), destroying `kho_out.radix_tree` with `kho_radix_destroy_tree()`, clearing `kho_out.fdt = NULL`, releasing all `kho_scratch` regions via `free_reserved_area()`, and setting `kho_enable = false`. [F14, F26]
- In `kho_restore_vmalloc()`, before restoring each contiguous block into `pages`, `idx + contig_pages > total_pages` must be rejected, and after walking all chunks, `idx != total_pages` must be rejected before calling `__get_vm_area_node()` and `vmap_pages_range()`. [F58]
- In `lib/test_kho.c`, allocations stored in `struct kho_test_state` (`state->folios`, `state->folios_info`, `state->fdt`) must not be freed on normal return from `kho_test_save()`, and on failure `kho_test_generate_data()` must `folio_put()` all `state->nr_folios` folios and reset `state->nr_folios = 0`. [F16]

## External Contracts

- The KHO root FDT created by `kho_out_fdt_setup()` and validated by `kho_populate()` must have root `"compatible"` set to `KHO_FDT_COMPATIBLE` (`"kho-v4"`) and a 64-bit `KHO_FDT_MEMORY_MAP_PROP_NAME` (`"preserved-memory-map"`) property read in `kho_get_mem_map_phys()` via `get_unaligned((const u64 *)mem_ptr)` after verifying `len == sizeof(u64)`. Subnode properties `KHO_SUB_TREE_PROP_NAME` and `KHO_SUB_TREE_SIZE_PROP_NAME` must also be stored as 64-bit values and checked for `len == sizeof(u64)` before dereferencing (including when `size == NULL` in `kho_retrieve_subtree()`). [F29, F61, F66, F93]
- In `kho_parse_scratch_size()`, a `kho_scratch=` parameter not ending in `'%'` must parse all three `sizes` entries (`scratch_size_lowmem`, `scratch_size_global`, `scratch_size_pernode`) via `memparse()` with a non-zero `total_size`, no trailing characters (`!*p`), and set `scratch_scale = 0` so `scratch_size_update()` and `scratch_size_node()` do not overwrite them; a `'%'`-suffixed value must satisfy `len <= ARRAY_SIZE(s_scale)` before copying `len - 1` bytes into `s_scale`. [F46, F53]

## Known Pitfalls

- Use 64-bit shifts for page orders and radix tree indices: `1UL << (order + PAGE_SHIFT)` in `kho_preserved_memory_reserve()` and `kho_ext_walk_leaf()` and `1UL << order` in `kho_get_preserved_page()` (since orders can reach 2 GiB+), and 64-bit `unsigned long i` in `__kho_radix_walk_tree()` for `key = start | (i << shift)` (where `shift` reaches 51 on 4 KiB-page systems). [F76, F80]
- In `kho_populate()`, physical handover regions (`fdt_phys` and `scratch_phys`) must be accessed via `early_memremap()` / `early_memunmap()` and `kho_get_mem_map_phys()` rather than `phys_to_virt()`, `kho_get_fdt()`, or `kho_get_mem_map()`. [F107]
- In `kho_remove_subtree()` and `kho_debugfs_blob_remove()`, the loop must `break` immediately after `fdt_del_node(root_fdt, off)` or `list_del(&ff->list)`/`kfree(ff)` because neither `fdt_next_subnode()` nor `list_for_each_entry()` is safe to continue after in-place element deletion. [F70]
- In `kho_walk_scratch()`, the `struct resource` passed to the hole-locator callback `func` must set `.end` to the inclusive upper bound `kho_scratch[i].addr + kho_scratch[i].size - 1`. [F63]
