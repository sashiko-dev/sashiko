# EMULEX 10Gbps iSCSI - OneConnect DRIVER

The `be2iscsi` driver implements an open-iSCSI hardware offload initiator for Emulex/Broadcom OneConnect and BladeEngine (BE2, BE3-R, and SkyHawk/BE_GEN4) 10Gbps PCIe adapters. It integrates with the Linux SCSI midlayer, `libiscsi`, and `scsi_transport_iscsi` to offload TCP/IP connection management and iSCSI PDU/SGL data-path processing to adapter firmware via hardware rings (EQ, CQ, MCCQ, WRBQ, and default header/data rings) and MMIO doorbells.

## Architecture & Data Flow
- Error detection paths set bits in `BEISCSI_HBA_IN_ERR` without clearing `BEISCSI_HBA_ONLINE`, so operational guards must use `beiscsi_hba_is_online(phba)` rather than only `test_bit(BEISCSI_HBA_ONLINE, &phba->state)`. [F95]
- `phba->cid_to_cri_map` (`BE_GET_CRI_FROM_CID`) and `pasync_ctx->cid_to_async_cri_map` (`BE_GET_ASYNC_CRI_FROM_CID`) are distinct: index controller tables (`wrb_context`, `ep_array`, `conn_table`) with `BE_GET_CRI_FROM_CID(cid)`, and per-ULP `pasync_ctx->async_entry[].wq` with `BE_GET_ASYNC_CRI_FROM_CID(cid)`. [F58]
- In `struct hwi_wrb_context`, `pwrb_handle_base` is a circular alloc/free ring mutated by `beiscsi_get_wrb_handle()`/`beiscsi_put_wrb_handle()`, whereas `pwrb_handle_basestd` is an unmodified lookup array indexed by `wrb_index` for `hwi_complete_cmd()` and `hwi_complete_drvr_msgs()`. [F59]
- In `struct be_ctrl_info`, `mcc_tag[MAX_MCC_CMD]` is indexed 0-based (`0 .. MAX_MCC_CMD - 1`) via `mcc_alloc_index`/`mcc_free_index`, whereas the tag values inside it are 1-based (`1 .. MAX_MCC_CMD`) and directly index `mcc_wait`, `mcc_tag_status`, and `ptag_state` (sized `MAX_MCC_CMD + 1`). [F79]
- In `struct hwi_context_memory`, `be_eq[MAX_CPUS]` has one more slot than `be_cq[MAX_CPUS - 1]`: indices `0 .. phba->num_cpus - 1` pair `be_eq[i]` with `be_cq[i]` for I/O, while `be_eq[phba->num_cpus]` is the dedicated MCC EQ with no `be_cq` entry. Broken by: indexing `be_cq[i]` or `be_eq[i].iopoll` up to `i <= phba->num_cpus`. [F82]
- Per-ULP resources (`phba->cid_array_info[ulp_num]`, `phwi_context->pasync_ctx[ulp_num]`, and `phba->init_mem`/`phba->mem_req` entries separated by `MEM_DESCR_OFFSET` (8) between `BEISCSI_ULP0` and `BEISCSI_ULP1`) are allocated only when `test_bit(ulp_num, &phba->fw_config.ulp_supported)` is set; always check `ulp_supported` before indexing them or calling `BEISCSI_ULP_AVLBL_CID`. [F49, F68]
- In SGL handle and CID ring pools (`alloc_io_sgl_handle`/`free_io_sgl_handle`, `alloc_mgmt_sgl_handle`/`free_mgmt_sgl_handle`, `beiscsi_get_cid`/`beiscsi_put_cid`), `beiscsi_get_cid` must check `ulp_supported` before indexing `cid_array_info[cid_from_ulp]`, allocation must mark the slot empty (`NULL` or `BE_INVALID_CID`), and release must verify the `free_index`/`cid_free` slot is empty before returning the item. [F13, F61]
- `task->sc != NULL` discriminates SCSI IO tasks (using `alloc_io_sgl_handle`/`free_io_sgl_handle` and `scsi_dma_map`/`scsi_dma_unmap` guarded by `io_task->num_sg`, clearing `io_task->scsi_cmnd` on unmap) from management tasks (`task->sc == NULL`, using `alloc_mgmt_sgl_handle`/`free_mgmt_sgl_handle` and `dma_map_single` only when `task->data_count != 0`, guarded by and clearing `io_task->mtask_addr`). [F45, F164]
- Every WRB submission path (`beiscsi_iotask`, `beiscsi_iotask_v2`, `beiscsi_mtask`, `beiscsi_offload_cxn_v0`, `beiscsi_offload_cxn_v2`) must set the new WRB's `ptr2nextwrb` to its own `wrb_index`, update `pwrb_context->plast_wrb->ptr2nextwrb` to that `wrb_index` if `plast_wrb` is non-NULL, and set `pwrb_context->plast_wrb = pwrb`. [F65]
- `beiscsi_hba_alloc` uses `iscsi_host_alloc`, so `shost->shost_data` is `struct iscsi_cls_host` and `struct beiscsi_hba *` must be retrieved via `iscsi_host_priv(shost)` (never `shost_priv(shost)`). Likewise, `cls_session->dd_data` and `cls_conn->dd_data` point to `iscsi_session` and `iscsi_conn` (whose `dd_data` are `beiscsi_session` and `beiscsi_conn`), whereas `iscsi_endpoint::dd_data` and `iscsi_task::dd_data` point directly to `beiscsi_endpoint` and `beiscsi_io_task`. [F125, F126]

## Synchronization
- Every MCC command submission must hold `ctrl->mbox_lock` while calling `alloc_mcc_wrb()` (which acquires `ctrl->mcc_lock`), populating the WRB, and calling `be_mcc_notify()`, and must drop `ctrl->mbox_lock` before `beiscsi_mccq_compl_wait()`. `ctrl->mcc_lock` nests inside `ctrl->mbox_lock` and protects `mcc_obj.q.head`, `mcc_obj.q.used`, `mcc_tag`, `mcc_alloc_index`, `mcc_free_index`, and `mcc_tag_available`. [F21, F156]
- In `be_mcc_notify()`, `MCC_TAG_STATE_RUNNING` must be set and `wmb()` executed after populating the MCC WRB and before writing `DB_MCCQ_OFFSET`. For async MCC commands, `MCC_TAG_STATE_ASYNC`, `ctrl->ptag_state[tag].cbfn`, and `tag_mem_state` or `phba->boot_struct.tag` must be initialized before `be_mcc_notify()`. [F22, F161]
- When `beiscsi_mccq_compl_wait()` times out (`rc <= 0`), it sets `ptag_state[tag].tag_mem_state`, executes `wmb()` before setting `MCC_TAG_STATE_TIMEOUT`, and returns `-EBUSY` without freeing the tag; callers must not free `nonemb_cmd` on `-EBUSY`. When woken with `BEISCSI_HBA_ONLINE` clear, it clears `MCC_TAG_STATE_RUNNING` (which `be_mcc_queues_destroy()` spins waiting for) and returns `-EIO` without saving `mbx_cmd_mem` into `tag_mem_state`, leaving the caller to free any non-embedded DMA buffer. [F2, F23, F159]
- `session->back_lock` (`spin_lock_bh`) must be held when reading `pwrb_handle->pio_handle` and completing or cleaning up tasks (`hwi_complete_cmd`, `hwi_complete_drvr_msgs`, `beiscsi_hdl_fwd_pdu`, `beiscsi_offload_connection`). In `beiscsi_eh_abort` and `beiscsi_eh_device_reset`, hold `session->back_lock` while checking `task->sc`, pinning via `iscsi_get_task`, setting the WRB `invld` bit, and reading `io_task->psgl_handle->sgl_index`, then drop `session->back_lock` while keeping the task reference across `beiscsi_mgmt_invalidate_icds`. [F25, F26]
- Unsolicited PDU CQE processing (`beiscsi_hdq_process_compl`) must hold `spin_lock_bh(&phba->async_pdu_lock)`, which nests outside `spin_lock_bh(&session->back_lock)` in `beiscsi_hdl_fwd_pdu`. Pool locks `phba->io_sgl_lock`, `phba->mgmt_sgl_lock`, and `pwrb_context->wrb_lock` must use `spin_lock_irqsave` and nest inside `session->frwd_lock` and `session->back_lock`. [F27, F28]
- `beiscsi_alloc_pdu()` is called by `libiscsi` under the session lock, so all allocations on its path (including `dma_pool_alloc()` from `beiscsi_sess->bhs_pool`) must use `GFP_ATOMIC`. Conversely, `iscsi_session_failure()` requires process context, so atomic/timer error paths like `beiscsi_hw_health_check()` must schedule `phba->sess_work` (`beiscsi_sess_work`) instead of calling `beiscsi_session_fail` directly. [F151, F175]
- In `be_iopoll`, when `beiscsi_process_cq` returns `< budget`, call `irq_poll_complete(iop)` before re-arming the EQ interrupt via `hwi_ring_eq_db(..., 1, 1)`. In `beiscsi_flush_cq` (process context), wrap `beiscsi_process_cq` with `irq_poll_disable(&pbe_eq->iopoll)` and `irq_poll_enable(&pbe_eq->iopoll)`. [F35, F37]

## Object Lifetimes
- When `beiscsi_exec_nemb_cmd` is called with a non-NULL `cbfn`, a `0` return transfers ownership of `nonemb_cmd` to `phba->ctrl.ptag_state[tag].tag_mem_state` for `cbfn` to free via `dma_free_coherent`; callers such as `beiscsi_modify_eq_delay` must only call `beiscsi_free_nemb_cmd` when `beiscsi_exec_nemb_cmd` returns non-zero. [F3]
- During login (`ISCSI_OP_LOGIN`), `beiscsi_alloc_pdu` caches `plogin_sgl_handle` and `plogin_wrb_handle` on `beiscsi_conn` and sets `login_in_progress = 1` for reuse; `beiscsi_cleanup_task` must not call `beiscsi_free_mgmt_task_handles` while `login_in_progress` is set. On endpoint teardown (`beiscsi_free_ep`, `beiscsi_ep_disconnect`), return `ep_cid` via `beiscsi_put_cid()`, NULL out `phba->ep_array[cri_index]`, `beiscsi_ep->phba`, `beiscsi_ep->conn`, and `phba->conn_table[cri_index]`, and if `login_in_progress` is set (or in `beiscsi_offload_connection`), free login task handles and clear `login_in_progress`. [F10, F62]
- In `be_complete_io`, `beiscsi_cleanup_task`, and `beiscsi_free_mgmt_task_handles`, every released task resource (`io_task->cmd_bhs`, `task->hdr`, `io_task->pwrb_handle`, `io_task->psgl_handle`, `io_task->scsi_cmnd`, `io_task->mtask_addr`) must be cleared to `NULL` or `0` immediately upon release. [F12]
- Firmware does not generate a completion CQE for `BE_TGT_CTX_UPDT_CMD` (`CONTEXT_UPDATE`), so `beiscsi_offload_connection` must immediately return the `pwrb_handle` from `alloc_wrb_handle` via `beiscsi_put_wrb_handle` after ringing the doorbell without zeroing `pwrb_handle->pwrb`. [F14]
- `be_ctrl_init` allocates `sizeof(struct be_mcc_mailbox) + 16` bytes in `ctrl.mbox_mem_alloced` and stores 16-byte `PTR_ALIGN`-ed pointers in `ctrl.mbox_mem`; BMBX commands must use `ctrl.mbox_mem`, whereas `dma_free_coherent` must always use `ctrl.mbox_mem_alloced`. [F51]
- In `beiscsi_boot_create_kset`, each `iscsi_boot_create_*` call using `beiscsi_boot_kobj_release` must be preceded by `scsi_host_get(phba->shost)`, and on failure must jump to `put_shost` before `iscsi_boot_destroy_kset`. In `beiscsi_conn_bind`, `iscsi_lookup_endpoint(transport_fd)` must be paired with `iscsi_put_endpoint(ep)` on both success and all error paths. [F5, F16]
- `beiscsi_disable_port` must atomically test and clear `BEISCSI_HBA_ONLINE`, disable/free IRQs, disable `irq_poll` on all EQs, and synchronously cancel `eqd_update`, `boot_work`, and (on error recovery) `mcc_work` before calling `hwi_cleanup_port` and `beiscsi_cleanup_port` (keeping `phba->init_mem`, `phba->phwi_ctrlr`, `phba->wq`, and `ctrl->mbox_mem_alloced` intact until `beiscsi_remove`). In `beiscsi_remove`, call `iscsi_host_remove(phba->shost, false)` first, stop `hw_check`, `recover_port`, and `sess_work` before `beiscsi_disable_port`, and destroy `boot_kset`, `phba->wq`, and `shost` only after `beiscsi_disable_port` completes. [F34, F137, F139, F166]

## API Contracts
- `be_mbox_notify` and its BMBX wrappers return `0` on success, negative errno on poll failure, and a positive 16-bit firmware `compl_status` on completion error, so callers must check `status != 0` rather than `status < 0`. [F41]
- Because `be_wrb_hdr_prepare`, `ADAPTER_SET_WRB_TYPE`, and `AMAP_SET_BITS` use bitwise OR/masking without clearing other fields, callers reusing `wrb_from_mbox(&ctrl->mbox_mem)`, SGE arrays, or stack `struct beiscsi_offload_params` must `memset` the target struct to `0` first; similarly, callers of `adapter_get_sol_cqe` must zero-initialize `struct common_sol_cqe`. [F48, F50]
- When allocating a `struct be_dma_mem` buffer for a non-embedded command (`beiscsi_boot_get_sinfo`, `beiscsi_if_get_gw`, `beiscsi_mgmt_invalidate_icds`), `size` and the `dma_alloc_coherent` length must cover the full in-place response struct/union rather than `sizeof(nonemb_cmd->size)` or `sizeof(*req)`. `be_cmd_hdr_prepare` subtracts `sizeof(struct be_cmd_req_hdr)` from `cmd_len`, while `struct be_cmd_resp_hdr` reports `response_length` and `actual_resp_len` excluding the header, so `beiscsi_if_get_info` and `beiscsi_bsg_request` must add the header size when reallocating or copying; on `0` return from `beiscsi_if_get_info`, the caller owns `*if_info` and must `kfree` it. [F4, F116, F119]
- Default PDU ring SGEs (`struct phys_addr`) in `beiscsi_hdq_post_handles` store the lower 32 DMA address bits in `pasync_sge[pi].hi` and the upper 32 bits in `pasync_sge[pi].lo`, and runtime replenishment in `beiscsi_hdq_process_compl` must pass `nbuf` as `8 * consumed`. [F55]
- `beiscsi_alloc_pdu()` overwrites `io_task->cmd_bhs->iscsi_hdr.itt` with `((wrb_index << 16) | sgl_index)` and saves `task->itt` in `io_task->libiscsi_itt`; any path completing a task-backed PDU via `__iscsi_complete_pdu()` must restore `hdr->itt = io_task->libiscsi_itt` under `session->back_lock`. [F171]
- `__beiscsi_log` and `beiscsi_log` pass `__LINE__` before `##arg` to `shost_printk` and index `level[1] <= '3'`, so `level` must be a `KERN_*` string and `fmt` must begin with an integer format specifier (e.g., `"BM_%d : ..."`) to consume `__LINE__`. [F128]

## Error Handling
- `beiscsi_boot_get_shandle` returns `1` when a boot target is configured and a negative errno otherwise, so `beiscsi_dev_probe` must check `ret > 0` before starting boot work and explicitly `return 0;` at the end of probe rather than `return ret;`. [F44]
- In `beiscsi_process_mcc_compl()`, check `MCC_TAG_STATE_TIMEOUT` before writing `ctrl->mcc_tag_status[tag]`, and ensure `MCC_TAG_STATE_TIMEOUT`, `MCC_TAG_STATE_ASYNC`, and `MCC_TAG_STATE_IGNORE` each call `free_mcc_wrb(ctrl, tag)` and return before `wake_up_interruptible(&ctrl->mcc_wait[tag])`. [F96]

## Known Pitfalls
- `be_fill_queue()` zeroes the entire `struct be_queue_info` (including embedded `dma_mem`), so callers (`beiscsi_create_eqs`, `beiscsi_create_cqs`, `beiscsi_create_def_hdr`, `beiscsi_create_def_data`) must assign `mem->dma` after `be_fill_queue()`. `be_cmd_iscsi_post_sgl_pages()` mutates `q_mem->dma` in place (`+= req->num_pages * PAGE_SIZE`), so callers (`beiscsi_post_pages`) must pass a temporary `struct be_dma_mem` copy rather than a persistent descriptor. [F57, F70]
- In pseudo-bitfield `struct amap_*` types, each `u8` represents 1 hardware bit, no field may cross a 32-byte (`u32` dword) boundary, backing byte arrays must use `sizeof(struct amap_*) / 8`, and indexing `u32 dw[]` with `offsetof(struct amap_*, field)` must divide by `32` (`offsetof(...) / 32`). `AMAP_SET_BITS`/`AMAP_GET_BITS` operate on host-endian `u32` dwords: populate outgoing descriptors before `be_dws_cpu_to_le`/`swap_dws` (with a positive multiple-of-4 length), and swap incoming CQEs with `be_dws_le_to_cpu` before `AMAP_GET_BITS` (except `struct pdu_base` in `beiscsi_hdl_gather_pdu`, which is not DWORD-swapped and reconstructs 24-bit big-endian `DataSegmentLength` as `(data_len_hi << 16) | be16_to_cpu(data_len_lo)`). [F86, F87, F114, F124]
- In `beiscsi_process_cq()`, every CQE iteration (unless aborting on `beiscsi_hba_in_error(phba)`) must reach `proc_next_cqe` to clear the `valid` bit on `sol`, advance `cq` via `queue_tail_inc(cq)`, and increment `num_processed` before `hwi_ring_cq_db()`. In `hwi_complete_cmd()`, because `beiscsi_mtask()` uses `INI_RD_CMD` (`HWH_TYPE_IO_RD`, 5) for `ISCSI_OP_NOOP_OUT` and `2` (`INI_TMF_CMD`/`HWH_TYPE_LOGOUT`) for both `ISCSI_OP_SCSI_TMFUNC` and `ISCSI_OP_LOGOUT`, those `wrb_type` cases must check `task->hdr->opcode & ISCSI_OPCODE_MASK`. [F97, F104]
- Iterating `pasync_ctx->async_entry[cri].wq.list` to unlink handles via `beiscsi_hdl_put_handle()` must use `list_for_each_entry_safe()`, and `beiscsi_hdl_fwd_pdu()` must capture `plast_handle = pasync_handle` inside `list_for_each_entry()` rather than dereferencing `pasync_handle` after the loop. [F101]
- In `beiscsi_hba_alloc()`, never assign `pcidev->dma_mask` (64-bit) to `shost->dma_boundary`. [F167]
