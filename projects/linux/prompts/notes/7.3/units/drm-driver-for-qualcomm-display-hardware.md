# DRM DRIVER for Qualcomm display hardware

This unit (`drivers/gpu/drm/msm/disp/dpu1`) implements the Qualcomm Snapdragon DPU display driver across DPU 1.x–12.0, including the SoC hardware catalogs, core clock/bandwidth performance management (`dpu_core_perf`), DRM CRTC (`dpu_crtc`), virtual and physical encoders (video, command, and writeback modes), interrupt controller (`dpu_hw_interrupts`), pixel format layouts, and low-level MMIO hardware block drivers (`dpu_hw_*`).

## Architecture & Data Flow
- Any non-mode state change that alters resource reservation in `dpu_crtc_get_topology()` or `dpu_encoder_update_topology()` (such as writeback YUV format toggling `num_cdm` or clone mode toggling `cwb_enabled`) must be mirrored in `dpu_encoder_needs_modeset()` and `dpu_crtc_check_mode_changed()` to set `new_crtc_state->mode_changed = true`. [F58]
- In `dpu_crtc_atomic_check()`, early returns for inactive/disabled CRTCs (`!crtc_state->enable || !drm_atomic_crtc_effectively_active(crtc_state)`) must zero `cstate->new_perf` (copied by `dpu_crtc_duplicate_state()`). When `mode_changed || connectors_changed` is set, `dpu_crtc_assign_resources()` must populate `cstate->mixers` and `num_mixers` before `_dpu_crtc_check_and_setup_lm_bounds()` computes `cstate->lm_bounds`. [F48, F57]
- In `dpu_crtc_assign_resources()` and `dpu_encoder_virt_atomic_mode_set()`, `num_ctl` for `DPU_HW_BLK_CTL` can be smaller than `num_lm` or `dpu_enc->num_phys_encs` (e.g. one active CTL driving two mixers/encoders), so `hw_ctl` indexing must clamp to `num_ctl - 1` or `hw_ctl[0]` rather than indexing `hw_ctl[i]` directly. [F71]
- When clearing or resetting blend stages (`_dpu_crtc_blend_setup()`, `dpu_encoder_helper_reset_mixers()`, `dpu_hw_ctl_reset_intf_cfg_v1()`), `clear_all_blendstages`, `set_active_fetch_pipes(ctl, NULL)`, `set_active_pipes(ctl, NULL)`, and (on mixer/CTL reset) `set_active_lms(ctl, NULL)` must be called in lockstep. `dpu_hw_ctl_reset_intf_cfg_v1()` must mask off only the `CTL_*_ACTIVE` bits specified in `cfg`, whereas `dpu_hw_ctl_intf_cfg_v1()` must update `CTL_*_ACTIVE` registers via read-modify-write. [F54, F184, F185]
- In `dpu_hw_ctl.c`, every `dpu_hw_ctl_update_pending_flush_*_v1` helper (and `dpu_hw_ctl_update_pending_flush_dspp_sub_blocks`) must set both the sub-block bit in `ctx->pending_*_flush_mask` and the corresponding summary bit (`BIT(*_IDX)`) in `ctx->pending_flush_mask` so `dpu_hw_ctl_trigger_flush_v1` writes the sub-block flush register. [F183]
- `dpu_encoder_helper_phys_cleanup()` must explicitly unbind and disable all optional features configured on shared blocks (`hw_wb`, `hw_intf`, `hw_pp` dither, `hw_cwb`, `merge_3d`, `hw_cdm`, `hw_dsc`) and clear `dpu_enc->dsc = NULL` before flushing and starting `ctl`. Any `dpu_encoder_virt` state cleared during `dpu_encoder_virt_atomic_disable()` or `dpu_encoder_helper_phys_cleanup()` (`connector`, `dsc`, `enabled`) must be re-initialized in `dpu_encoder_virt_atomic_enable()`, not `dpu_encoder_virt_atomic_mode_set()`. [F55, F56]
- In `dpu_crtc_kickoff_clone_mode()`, `rt_encoder` and `wb_encoder` must be initialized to `NULL` before `drm_for_each_encoder_mask()`, `wb_encoder` must be kicked off via `dpu_encoder_kickoff()` before `rt_encoder`, and `dpu_encoder_start_frame_done_timer()` must only be called after `dpu_encoder_kickoff()` (in both clone and normal kickoff) has set `dpu_enc->frame_busy_mask`. [F18, F46, F81]
- In video mode, `dpu_encoder_phys_vid_enable()` must set `enable_state = DPU_ENC_ENABLING` and defer `hw_intf->ops.enable_timing(phys_enc->hw_intf, 1)` and `DPU_ENC_ENABLED` until `dpu_encoder_phys_vid_handle_post_kickoff()` after the CTL flush. On a command-mode or writeback kickoff wait timeout, `_dpu_encoder_phys_cmd_handle_ppdone_timeout()` and `_dpu_encoder_phys_wb_handle_wbdone_timeout()` must decrement `pending_kickoff_cnt`, set `enable_state = DPU_ENC_ERR_NEEDS_HW_RESET`, and increment the timeout counter (reset to `0` on a successful wait). [F189, F190]
- In `dpu_encoder_phys_vid_setup_timing_engine()`, `dpu_encoder_phys_vid_enable()`, `dpu_encoder_phys_wb_setup_ctl()`, and `_dpu_encoder_phys_wb_update_flush()`, `intf_cfg.merge_3d` and `update_pending_flush_merge_3d()` must only be set when both `dpu_encoder_helper_get_3d_blend_mode(phys_enc)` is non-zero and `phys_enc->hw_pp->merge_3d` is non-NULL. [F249]
- DPU `irq_idx` values are 1-based unsigned values (`1`..`DPU_NUM_IRQS` via `DPU_IRQ_IDX`, `0` = no IRQ): `DPU_IRQ_REG`/`DPU_IRQ_BIT` and `dpu_core_irq_get_entry()` subtract 1, `dpu_core_irq()` must pass `bit - 1` from `ffs(irq_status)` to `DPU_IRQ_IDX` and `irq_status &= ~BIT(bit - 1)` on every loop path, `dpu_encoder_helper_wait_for_irq()` must test `irq_idx == 0` (not `< 0`), and unpopulated `intr_*` catalog fields must be left `0` (never `-1`). [F66, F67, F196, F211]
- When `pipe->multirect_index != DPU_SSPP_RECT_SOLO`, `dpu_hw_sspp_setup_multirect()` and `dpu_hw_sspp_setup_sourceaddress()` must read-modify-write `SSPP_MULTIRECT_OPMODE`, `SSPP_SRC_YSTRIDE0`, and `SSPP_SRC_YSTRIDE1` to preserve the sibling rectangle's bits. In `dpu_hw_lm.c`, `dpu_hw_lm_setup_out()` and `dpu_hw_lm_setup_color3()` (on DPU < 12) share `LM_OP_MODE` and must read-modify-write to preserve each other's bits (`BIT(31)` and `BIT(30)`). [F192, F195]
- Catalog invariants (`catalog/dpu_*.h` and `dpu_hw_catalog.c`): block `.name` strings must be `<= 15` chars; `dpu_ctl_cfg` on DPU >= 5.0 must not set `BIT(DPU_CTL_SPLIT_DISPLAY)`; `dpu_perf_cfg` must set non-zero `.max_bw_high` and `.min_prefill_lines`; SmartDMA v2 SoCs must use `*_SDMA` SSPP masks; VIG SSPPs without CSC (`_VIG_SBLK_NOSCALE`) must use `plane_formats` (RGB only); `dpu_dsc_cfg` on DPU >= 7.0 and all `dpu_pingpong_cfg` must set `.sblk` (plus `.intr_rdptr` on DPU < 5.0); `_setup_mdp_ops()` must omit `setup_vsync_source` on DPU >= 8.0. [F104, F107, F108, F109, F110, F111, F256, F258]

## Synchronization
- Lock hierarchy and IRQ context: `phys_enc->vblank_ctl_lock` -> `dpu_kms->hw_intr->irq_lock` -> `phys_enc->enc_spinlock` (and `dpu_enc->enc_spinlock` -> `crtc->dev->event_lock`). `irq_lock`, `phys_enc->enc_spinlock`, and `dpu_enc->enc_spinlock` are acquired in hardirq context (`dpu_core_irq()`, `dpu_encoder_vblank_callback()`), so all process-context acquisitions must use `spin_lock_irqsave()`. Never call `dpu_core_irq_*()`, `phys->ops.control_vblank_irq()` (in `dpu_encoder_toggle_vblank_for_crtc()`), or `ctl->ops.reset`/`wait_reset_status` (sleeps) while holding `enc_spinlock`, and never acquire `enc_spinlock` under `event_lock`. [F130, F131, F160, F265, F266]
- In `dpu_encoder_resource_control()`, `cancel_delayed_work_sync(&dpu_enc->delayed_off_work)` must be called before acquiring `dpu_enc->rc_lock` (because `dpu_encoder_off_work()` acquires `rc_lock`). Process-context events (`KICKOFF`, `PRE_STOP`, `STOP`, `ENTER_IDLE`) must hold `rc_lock` across all `rc_state` checks, transitions, and resource/IRQ calls, whereas `DPU_ENC_RC_EVENT_FRAME_DONE` runs in interrupt context and must not acquire `rc_lock`. Under `ENTER_IDLE`, after locking `rc_lock`, the handler must revalidate both `rc_state == DPU_ENC_RC_STATE_ON` and `frame_busy_mask[0] == 0`. [F29, F30, F127]
- `dpu_enc->crtc` is protected by `dpu_enc->enc_spinlock` in `dpu_encoder_assign_crtc()` and `dpu_encoder_vblank_callback()`. In `_dpu_encoder_kickoff_phys()`, `dpu_enc->enc_spinlock` must be held across setting `set_bit(i, dpu_enc->frame_busy_mask)` (only for `phys->split_role != ENC_ROLE_SLAVE`), calling `_dpu_encoder_trigger_flush()` (which accumulates `pending_flush` onto `cur_master` when `needs_single_flush(phys)` is true and increments `pending_kickoff_cnt`), and calling `_dpu_encoder_trigger_start(dpu_enc->cur_master)`. [F25, F86, F124]
- `dpu_encoder_phys_vid_vblank_irq()` must hold `phys_enc->enc_spinlock` while checking `hw_ctl->ops.get_flush_register(hw_ctl)` against `hw_ctl->ops.get_pending_flush(hw_ctl)` and decrementing `phys_enc->pending_kickoff_cnt`. In `dpu_encoder_phys_vid_disable()`, after clearing `enable_timing(phys_enc->hw_intf, 0)` under `enc_spinlock`, a master encoder must call `dpu_encoder_phys_inc_pending()` and wait in `dpu_encoder_phys_vid_wait_for_tx_complete()` before calling `dpu_encoder_helper_phys_cleanup()`. [F162, F163]
- `dpu_encoder_frame_done_callback()` runs in hardirq context: it must zero `dpu_enc->frame_done_timeout_ms` before calling non-blocking `timer_delete(&dpu_enc->frame_done_timer)` (whereas process-context `dpu_encoder_virt_atomic_disable()` uses `timer_delete_sync()` under `enc_lock`). `dpu_encoder_frame_done_timeout()` must verify `frame_busy_mask[0]`, `dpu_enc->crtc`, and `atomic_xchg(&dpu_enc->frame_done_timeout_ms, 0) != 0` before reporting `DPU_ENCODER_FRAME_EVENT_ERROR`. [F32, F134]
- `dpu_crtc_frame_event_cb()` runs in hardirq/softirq context: it must filter out `DPU_ENCODER_FRAME_EVENT_IDLE` before dequeuing from `dpu_crtc->frame_event_list` under `spin_lock_irqsave(&dpu_crtc->spin_lock, ...)`, and defer `dpu_core_perf_crtc_release_bw()` to `dpu_crtc_frame_event_work()` via `kthread_queue_work()`. Every path in `dpu_crtc_frame_event_work()` must return `fevent` to `frame_event_list` under `dpu_crtc->spin_lock`. [F80, F129]

## Object Lifetimes
- When transferring `crtc->state->event` to `dpu_crtc->event` in `dpu_crtc_atomic_flush()` or sending a vblank event in `_dpu_crtc_complete_flip()` and `dpu_crtc_disable()`, the source pointer must be cleared to `NULL` under `dev->event_lock`. [F2]
- `dpu_encoder_assign_crtc()` requires `dpu_enc->crtc` to be `NULL` before reassignment and `dpu_encoder_toggle_vblank_for_crtc()` drops requests when `dpu_enc->crtc != crtc`. In `dpu_crtc_enable()`, when `!old_crtc_state->self_refresh_active`, call `dpu_encoder_assign_crtc(encoder, crtc)` before `drm_crtc_vblank_on(crtc)` (and skip assignment when `old_crtc_state->self_refresh_active`). In `dpu_crtc_disable()`, call `drm_crtc_vblank_off(crtc)` before `dpu_encoder_assign_crtc(encoder, NULL)`, keep `dpu_enc->crtc` when entering `crtc->state->self_refresh_active`, and clear it when disabling from `old_crtc_state->self_refresh_active`. [F4, F17]
- In `dpu_crtc_disable()`, `_dpu_crtc_wait_for_frame_done(crtc)` must complete before setting `dpu_crtc->enabled = false`, releasing/zeroing lingering `dpu_crtc->frame_pending` references, dropping clock/bandwidth votes via `dpu_core_perf_crtc_update(crtc, 0)`, and calling `pm_runtime_put_sync(crtc->dev->dev)`. `dpu_crtc_atomic_check()` increments `dpu_kms->bandwidth_ref` per active commit (released via `dpu_core_perf_crtc_release_bw()` when `frame_pending` reaches 0 or on disable abort), while `dpu_crtc_enable()`/`dpu_crtc_disable()` hold an extra `bandwidth_ref` for `INTF_MODE_VIDEO`. [F19, F33]
- `_dpu_encoder_resource_enable()` must call `pm_runtime_get_sync()` before `_dpu_encoder_irq_enable()`, and `_dpu_encoder_resource_disable()` must call `_dpu_encoder_irq_disable()` before `pm_runtime_put_sync()`. In `dpu_encoder_resource_control()`, video mode keeps runtime PM active during `DPU_ENC_RC_STATE_IDLE` (`ENTER_IDLE` only disables IRQs), so `KICKOFF` and `PRE_STOP` from `IDLE` in video mode must only call `_dpu_encoder_irq_enable()` and `PRE_STOP` must enter `PRE_OFF` so `STOP` calls `_dpu_encoder_resource_disable()`. Under `enc_lock`, `dpu_encoder_virt_atomic_disable()` must call `dpu_encoder_wait_for_tx_complete()`, send `PRE_STOP`, run `phys->ops.disable`, drain `frame_done_timer` via `timer_delete_sync()`, and then send `STOP`. [F8, F9, F20]
- `dpu_crtc_assign_resources()` and `dpu_crtc_reassign_planes()` must release existing `dpu_global_state` reservations via `dpu_rm_release()` / `dpu_rm_release_all_sspp()` before checking `if (!crtc_state->enable) return 0;`. `dpu_encoder_virt_atomic_mode_set()` must overwrite unused `dpu_enc->hw_pp[i]` (`i >= num_pp`) with `NULL` and set `dpu_enc->cur_master->hw_cdm = NULL` when no `DPU_HW_BLK_CDM` is assigned. [F6, F13]

## API Contracts
- In `dpu_core_perf_crtc_update()`, bus bandwidth updates (`_dpu_core_perf_crtc_update_bus()`, which must return early if `!kms->num_paths`, convert `bw_ctl` from Bps to kBps by dividing by 1000, and divide `avg_bw` by `kms->num_paths`) must execute before core clock updates (`dev_pm_opp_set_rate()`). For enabled CRTCs, votes are only increased when `params_changed != 0` (pre-kickoff) and only decreased when `params_changed == 0` (post-commit). [F34, F91, F140]
- Callers must zero-initialize `struct dpu_core_perf_params perf = { 0 }` before `dpu_core_perf_aggregate()`, `struct msm_display_topology topology = { 0 }` before `dpu_encoder_update_topology()`, and `struct dpu_hw_intf_cfg` before `ctl->ops.setup_intf_cfg()` or `reset_intf_cfg()`. In `struct dpu_hw_intf_cfg`, `intf`, `intf_master`, `wb`, and `merge_3d` take 1-based enum IDs, whereas `cwb` and `dsc` take pre-shifted bitmasks (`BIT(idx - CWB_0)` / `BIT(idx - DSC_0)`); conversely, all `dpu_hw_ctl_update_pending_flush_*_v1` ops take 1-based enum IDs. [F44, F47, F177, F179, F200]
- `dpu_rm_get_assigned_resources()` takes the element count (`ARRAY_SIZE(...)` or `1`, never `sizeof(...)`) as `blks_size`, and callers must downcast returned `struct dpu_hw_blk *` pointers with the `to_dpu_hw_*` macro matching `enum dpu_hw_blk_type`. In `dpu_crtc_atomic_check()` and `dpu_crtc_assign_resources()`, resource reallocation is triggered only by `mode_changed || connectors_changed` (ignoring `active_changed`) and reserved whenever `crtc_state->enable` is true (ignoring `active`). [F96, F100, F136]

## Error Handling
- `dpu_encoder_helper_wait_for_irq()` and `dpu_encoder_wait_for_commit_done()` return signed `int` negative error codes: `-EWOULDBLOCK` when `enable_state == DPU_ENC_DISABLED` and `-ETIMEDOUT` only on an actual hardware timeout. Callers must store the return value in a signed `int` and check `ret == -ETIMEDOUT` before invoking `dpu_encoder_helper_report_irq_timeout()` or `msm_disp_snapshot_state()`. [F36, F166]

## Known Pitfalls
- In `dpu_crtc_disable()`, encoder iteration must use `old_crtc_state->encoder_mask` (not `crtc->state->encoder_mask`), and `dpu_crtc_vblank()` must iterate `crtc->dev->mode_config.encoder_list` because `crtc->state->encoder_mask` is already cleared when disabling a CRTC. [F82]
- Bitwise masking and fixed-point scaling: signed fields in `dpu_hw_scaler3_de_cfg`/`dpu_hw_scaler3_cfg`, `dpu_hw_pixel_ext` (`dpu_hw_sspp_setup_pe_config`, which skips `color == 2` so `lr_pe[2]`/`tb_pe[2]`/`tot_req_pixels[2]` are uninitialized), and `dpu_csc_cfg` (`(data->csc_mv[i] >> 7) & 0x1FFF` in `dpu_hw_csc_setup`) must be masked before shifting/ORing. In `dpu_hw_dsc_config*()`, `dsc->bits_per_component` must be converted/masked (`== 10` or `& 0xf`), and 6.4 fixed-point `dsc->bits_per_pixel` must be converted via `drm_dsc_get_bpp_int(dsc)` in `drm_mode_to_intf_timing_params()`. In `dpu_hw_intf_setup_timing_engine()`, `data_width` is halved (`p->width >> 1`) only when `p->wide_bus_en && !dp_intf`. In `dpu_hw_ctl.c`, 1-based block enums must be checked for non-zero and `fetch_tbl`/`lm_tbl` entries checked against `CTL_INVALID_BIT` before `BIT(...)`. [F176, F222, F223, F224, F227, F228, F230, F257]
