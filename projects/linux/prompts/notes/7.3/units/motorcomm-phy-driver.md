# MOTORCOMM PHY DRIVER

Linux phylib Ethernet PHY driver (`drivers/net/phy/motorcomm.c`) supporting Motorcomm YT8511, YT8521, YT8531, YT8531S, and YT8821 Gigabit and 2.5Gbps PHYs. It manages extended register paging across UTP, Fiber, and Common spaces, RGMII/SGMII/2500Base-X interface and delay configuration, combo UTP/Fiber media arbitration, SyncE clock output, Wake-on-LAN (WoL), and hardware LED trigger offloading.

## Architecture & Data Flow
- In `yt8521_read_status()`, when `priv->reg_page == YT8521_RSSR_TO_BE_ARBITRATED`, `yt8521_read_status_paged(phydev, YT8521_RSSR_FIBER_SPACE)` must only be called if `!link_utp`, because `yt8521_read_status_paged()` unconditionally resets `phydev->lp_advertising`, `duplex`, `speed`, `asym_pause`, and `pause` on entry. [F43]
- In `yt8521_read_status_paged()`, `phydev->lp_advertising`, `duplex`, `speed`, `asym_pause`, and `pause` must be reset before reading page status; when `page == YT8521_RSSR_FIBER_SPACE`, `MII_BMSR` must be read twice to detect a 1000Mbps-to-100Mbps transition where `YTPHY_SPECIFIC_STATUS_REG` still reports link. [F28]
- In `yt8521_read_status()`, when `priv->polling_mode == YT8521_MODE_POLL`, a link-up transition (`phydev->link == 0` to `1`) while `priv->reg_page == YT8521_RSSR_TO_BE_ARBITRATED` must update `priv->reg_page`, `YT8521_REG_SPACE_SELECT_REG`, and `phydev->port` together to the winning medium, and a link-down transition (`1` to `0`) must reset `priv->reg_page = YT8521_RSSR_TO_BE_ARBITRATED` and `phydev->port = PORT_NONE`. [F4, F25]
- On YT8521, YT8531S, and YT8821, `MII_BMCR` is banked separately in `YT8521_RSSR_UTP_SPACE` and `YT8521_RSSR_FIBER_SPACE`; unarbitrated YT8521/YT8531S operations in `yt8521_modify_utp_fiber_bmcr()` and all YT8821 operations in `yt8821_modify_utp_fiber_bmcr()` must apply `MII_BMCR` changes to both pages via `yt8521_modify_bmcr_paged()`. [F29]
- In the fiber branch of `yt8521_adjust_status()`, `!(lpa & YTPHY_FLPA_PAUSE)` (`0x3 << 7`) must be tested before `(lpa & YTPHY_FLPA_ASYM_PAUSE)` (`0x2 << 7`) so the final `else` branch runs only when bit 7 (`0x1 << 7`, symmetric pause without asymmetric pause) is set. [F45]
- `yt8521_suspend()` and `yt8821_suspend()` must skip setting `BMCR_PDOWN` when `YTPHY_WCR_ENABLE` is set in `YTPHY_WOL_CONFIG_REG`, while `yt8521_resume()` and `yt8821_resume()` must disable auto-sleep (`YT8521_ESC1R_SLEEP_SW` in `YT8521_EXTREG_SLEEP_CONTROL1_REG`) before checking `YTPHY_WCR_ENABLE` and clearing `BMCR_PDOWN`. [F67]
- In `yt8821_config_init()` and `yt8821_read_status()`, `YT8821_CHIP_MODE_FORCE_BX2500` sets `RATE_MATCH_PAUSE` with fixed `PHY_INTERFACE_MODE_2500BASEX`, whereas `YT8821_CHIP_MODE_AUTO_BX2500_SGMII` sets `RATE_MATCH_NONE` and calls `yt8821_update_interface()` to switch `phydev->interface` between `2500BASEX` and `SGMII` by link speed. [F68]

## Synchronization
- Every function calling `phy_select_page()` (such as `ytphy_set_wol()`, `yt8511_config_init()`, `yt8521_read_status_paged()`, and `yt8521_modify_bmcr_paged()`) must exit through `phy_restore_page()` on all paths, including when `phy_select_page()` returns a negative errno, to unlock the MDIO bus and restore the page. [F1]
- Code between `phy_select_page()` and `phy_restore_page()`, as well as `.read_page`/`.write_page` callbacks (`yt8511_read_page()`, `yt8511_write_page()`, `yt8521_read_page()`, `yt8521_write_page()`), runs with the MDIO bus mutex held and must only use unlocked accessors (`__phy_*`, `ytphy_*_ext`, `ytphy_rgmii_clk_delay_config()`), never `*_with_lock`, `phy_read()`, `phy_write()`, `phy_modify()`, or nested `phy_select_page()`. [F69, F75]
- Callers of `ytphy_modify_ext()` and `ytphy_rgmii_clk_delay_config()` must already hold the MDIO bus lock (via `phy_lock_mdio_bus()` or `phy_select_page()`), or else use `ytphy_modify_ext_with_lock()` / `ytphy_rgmii_clk_delay_config_with_lock()` to serialize the two-step `YTPHY_PAGE_SELECT` and `YTPHY_PAGE_DATA` access. [F8]
- Because `PHY_ID_YT8531` does not define `.read_page` or `.write_page` in `motorcomm_phy_drvs`, YT8531 callbacks and helpers (`yt8531_probe()`, `yt8531_config_init()`, `yt8531_set_wol()`, `yt8531_link_change_notify()`, `yt8531_set_ds()`) must lock the MDIO bus via `*_with_lock` helpers or `phy_modify()`, never `phy_select_page()` or `ytphy_set_wol()`. [F71]
- Internal UTP/Fiber status and autoneg helpers (`ytphy_utp_read_lpa()`, `yt8521_adjust_status()`, `yt8521_fiber_setup_forced()`, `ytphy_check_and_restart_aneg()`, `yt8521_fiber_config_aneg()`, `ytphy_setup_master_slave()`, `ytphy_utp_config_advert()`, `ytphy_utp_config_aneg()`, `ytphy_utp_read_abilities()`) require `mdio_lock` held and the target page selected via `phy_select_page()`. [F72]
- In `yt8511_config_init()`, after `phy_select_page(phydev, YT8511_EXT_CLK_GATE)` locks the MDIO bus and saves `oldpage`, intermediate switches to `YT8511_EXT_DELAY_DRIVE` and `YT8511_EXT_SLEEP_CTRL` must use `__phy_write(phydev, YT8511_PAGE_SELECT, ...)` and rely on the single final `phy_restore_page(phydev, oldpage, ret)`. [F6]
- `yt8521_modify_bmcr_paged()` and `yt8521_fiber_config_aneg()` call `usleep_range(1000, 1100)` while holding the sleepable MDIO bus mutex (`phydev->mdio.bus->mdio_lock`) inside `phy_select_page()`, so neither function (nor callers like `yt8521_soft_reset()`) may be called from atomic context or drop `mdio_lock` across the sleep. [F73]

## Object Lifetimes
- In `yt8821_utp_init()`, the original value of `YT8821_UTP_EXT_PI_CTRL_REG` must be read and saved via `ytphy_read_ext()` before clearing the `YT8821_UTP_EXT_PI_*_CLK_*_SEL_AFE` bits, and immediately restored via `ytphy_write_ext()` before subsequent UTP register writes. [F7]

## API Contracts
- `yt8521_prepare_fiber_features()` only sets fiber linkmode bits in `dst` without clearing existing bits, so callers initializing a stack linkmode bitmap (`yt8521_config_aneg_paged()`) or replacing `phydev->supported` (`yt8521_get_features_paged()`) must call `linkmode_zero(dst)` first. [F22]
- When `priv->reg_page == YT8521_RSSR_TO_BE_ARBITRATED`, `yt8521_config_aneg()` must save `phydev->advertising` into `priv->combo_advertising` before `yt8521_config_aneg_paged()` masks `phydev->advertising` to page-specific UTP or Fiber capabilities, and restore `phydev->advertising` from `priv->combo_advertising` before returning. [F78]
- LED hardware control callbacks (`yt8521_led_hw_is_supported()`, `yt8521_led_hw_control_set()`, and `yt8521_led_hw_control_get()`) must reject 0-based `index >= YT8521_MAX_LEDS` (`3`) with `-EINVAL` before computing `YT8521_LED0_CFG_REG + index`. [F41]

## Error Handling
- When a paged function stores a non-negative register value from `__phy_read()` into `ret` (as in `yt8521_read_status_paged()`, `yt8521_modify_bmcr_paged()`, and `yt8521_aneg_done_paged()`), success paths must pass `0` or `link` to `phy_restore_page()` rather than falling through to `err_restore_page` with the raw register value in `ret`. [F19]
- In functions that jump to a `phy_restore_page(phydev, old_page, ret)` cleanup label when `phy_select_page()` fails (such as `yt8511_config_init()`, `ytphy_set_wol()`, and `yt8521_config_init()`), `ret` must be initialized to `0` before `phy_select_page()` so an early jump on `old_page < 0` never passes an uninitialized `ret`. [F13]
- `ytphy_setup_master_slave()` and `ytphy_utp_config_advert()` return `< 0` on error, `0` if advertisement registers are unchanged, and `> 0` if modified; callers like `ytphy_utp_config_aneg()` must check `< 0` for errors and treat positive returns as `changed = true`. Broken by: `if (err) return err;`. [F20]
- `yt8521_read_status_paged()` and `yt8521_aneg_done_paged()` return `< 0` on MDIO error, `0` for no link, and `1` for link up; callers (`yt8521_read_status()` and `yt8521_aneg_done()`) must store the result in a signed `int` and check `< 0` before using it in boolean link expressions. [F21]
- `ytphy_get_wol()` returns `void` and exits early if `ytphy_read_ext_with_lock(phydev, YTPHY_WOL_CONFIG_REG)` fails, so it must initialize `wol->supported = WAKE_MAGIC` and `wol->wolopts = 0` before reading `YTPHY_WOL_CONFIG_REG`. [F23]
- In `yt8511_config_init()` and `ytphy_rgmii_clk_delay_config()`, the `switch (phydev->interface)` block must validate that `phydev->interface` is one of the four `PHY_INTERFACE_MODE_RGMII*` modes and abort with `-EOPNOTSUPP` in `default:` before modifying any hardware delay or clock registers. [F46]

## External Contracts
- `ytphy_set_wol()` must select `YT8521_RSSR_UTP_SPACE` before modifying `YTPHY_INTERRUPT_ENABLE_REG` and, when enabling `WAKE_MAGIC`, verify `phydev->attached_dev != NULL` (`-ENODEV`) and `is_valid_ether_addr(mac_addr)` (`-EINVAL`) before programming the MAC address registers. [F80]
- Wake-on-LAN MAC address programming in `ytphy_set_wol()` and `yt8531_set_wol()` must write `dev_addr[0..5]` as three big-endian 16-bit words (`(mac_addr[i * 2] << 8) | mac_addr[i * 2 + 1]`) in descending register order from `YTPHY_WOL_MACADDR2_REG` (`0xA007`, highest bytes) to `YTPHY_WOL_MACADDR0_REG` (`0xA009`, lowest bytes). [F40]

## Known Pitfalls
- Because `YT8521_RSSR_TO_BE_ARBITRATED` (`0xFF`) has `YT8521_RSSR_SPACE_MASK` (`BIT(1)`) set, callers using `struct yt8521_priv` must check `priv->reg_page != YT8521_RSSR_TO_BE_ARBITRATED` before passing `priv->reg_page` to `yt8521_write_page()` or any `yt8521_*_paged()` helper, or `page & YT8521_RSSR_SPACE_MASK` will alias `YT8521_RSSR_FIBER_SPACE`. [F42]
- When decoding link speed from `YTPHY_SPECIFIC_STATUS_REG` in `yt8521_adjust_status()` and `yt8821_adjust_status()`, the register value must be masked with the full non-contiguous `YTPHY_SSR_SPEED_MASK` (`(0x3 << 14) | BIT(9)`) before switching, because `YTPHY_SSR_SPEED_2500M` (`(0x0 << 14) | BIT(9)`) shares bits 15:14 == 0 with `YTPHY_SSR_SPEED_10M`. [F44]
- In `yt8521_fiber_config_aneg()` and `yt8521_fiber_setup_forced()`, modifying `YT8521_LINK_TIMER_CFG2_REG` or `YTPHY_MISC_CONFIG_REG` must be followed by clearing `YT8521_CCR_SW_RST` in `YT8521_CHIP_CONFIG_REG`, and enabling fiber autonegotiation when `!(bmcr & BMCR_ANENABLE)` requires pulsing `BMCR_PDOWN` across `usleep_range(1000, 1100)`. [F66]
- When `yt8521_modify_bmcr_paged()` is called with `set == BMCR_RESET`, it must poll `MII_BMCR` (up to 500 iterations with `usleep_range(1000, 1100)`) until `BMCR_RESET` self-clears before restoring the register page and releasing the MDIO bus lock. [F65]
- `yt8521_probe()` branches explicitly on `phydev->drv->phy_id == PHY_ID_YT8521` and `PHY_ID_YT8531S` to select chip-specific SyncE bitmasks in `YTPHY_SYNCE_CFG_REG`, returning `-EINVAL` for any other `phy_id`; assigning `.probe = yt8521_probe` to another PHY ID requires adding a matching branch. [F60]
- When combining multi-field masks or values into a single register modification—such as `YT8521_RC1R_RX_DELAY_MASK | YT8521_RC1R_GE_TX_DELAY_MASK` in `ytphy_rgmii_clk_delay_config()` or `YT8531_RGMII_RXD_DS_LOW_MASK | YT8531_RGMII_RXD_DS_HI_MASK` in `yt8531_set_ds()`—each operand of `|` must name its distinct GE/FE or HI/LOW field macro. [F50]
