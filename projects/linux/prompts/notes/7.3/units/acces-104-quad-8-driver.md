# ACCES 104-QUAD-8 DRIVER

This driver supports the ACCES 104-QUAD-8 and ACCES 104-QUAD-4 PC/104 quadrature encoder counter boards under the Linux Generic Counter subsystem. It registers an ISA driver that maps I/O ports via an 8-bit MMIO regmap, exposes 8 24-bit LS7267 counter channels and 24 signals (16 quadrature A/B inputs and 8 index inputs) with counter/signal extensions, and handles shared hardware interrupts to push counter events.

## Architecture & Data Flow

- Every `QUAD8_DATA(id)` sequence (`quad8_count_read()`, `quad8_preset_register_set()`, `quad8_filter_clock_prescaler_set()`) must first write `SELECT_RLD | RESET_BP` to `QUAD8_CONTROL(id)` to reset the 3-byte pointer to byte 0; 24-bit transfers must use a `u8 value[3]` buffer with `regmap_noinc_read()`/`regmap_noinc_write()` and `get_unaligned_le24()`/`put_unaligned_le24()` rather than incrementing bulk or 4-byte/big-endian accessors. [F31, F41]
- Per-channel control shadow bytes (`priv->cmr`, `priv->ior`, `priv->idr`) must retain their `REGISTER_SELECTION` prefix (`SELECT_CMR`, `SELECT_IOR`, `SELECT_IDR`) set in `quad8_init_counter()`. Partial updates must use `quad8_control_register_update()` under `priv->lock`, passing an unshifted field value, a compile-time constant mask, and the matching shadow array. [F22, F27]
- When `quad8_function_write()` transitions a channel to `COUNTER_FUNCTION_PULSE_DIRECTION` (`NON_QUADRATURE`) while `INDEX_MODE` in `priv->idr[id]` is `ENABLE_INDEX_MODE`, it must first clear `INDEX_MODE` in `priv->idr[id]` and `QUAD8_CONTROL(id)` via `quad8_control_register_update()` before updating `priv->cmr[id]`. [F30]
- Because `RANGE_LIMIT` and `MODULO_N` modes use the hardware Preset Register as the count ceiling, both `quad8_count_preset_write()` and `quad8_count_ceiling_write()` must update `priv->preset[count->id]` and program the hardware via `quad8_preset_register_set()` in lockstep under `priv->lock`. [F29]
- `LOAD_PIN` in `priv->ior[count->id]` is active-low (`LOAD_CNTR = 0`): `quad8_count_preset_enable_write()` and `quad8_count_preset_enable_read()` must invert `preset_enable` (`!preset_enable` / `!u8_get_bits(...)`), and `quad8_action_read()` must check `u8_get_bits(priv->ior[count->id], LOAD_PIN) == LOAD_CNTR` for index signals. [F35]
- Quadrature signal callbacks (`quad8_signal_ext`) must derive the counter channel index 0..7 as `signal->id / 2` (for `signal->id` in 0..15), whereas index signal callbacks (`quad8_index_ext` and `quad8_signal_read()`) must derive it as `signal->id - 16` (for `signal->id` in 16..23). [F37]
- In `quad8_events_configure()`, `irq_enabled` must be computed from a fresh zero-initialized bitmask on each call by walking `counter->events_list` and unconditionally written to `QUAD8_INDEX_INTERRUPT`; `irq_enabled |= BIT(event_node->channel)` must execute before the `continue` branch that skips unchanged `FLG_PINS` writes. [F32, F46]
- After handling set channel bits from `QUAD8_INTERRUPT_STATUS`, `quad8_irq_handler()` must clear pending hardware interrupts by writing `CLEAR_PENDING_INTERRUPTS` (`ENABLE_COUNTERS | ENABLE_INTERRUPT_FUNCTION`) to `QUAD8_CHANNEL_OPERATION`. [F64]
- Register accesses through `priv->map` are constrained by `quad8_regmap_config` to `quad8_rd_ranges` (0x0..0x12, 0x16..0x18) for reads and `quad8_wr_ranges` (0x0..0xF, 0x11..0x12, 0x17..0x17) for writes; any newly accessed offset must be added to the corresponding range table. [F42]
- Because `quad8_counts`, `quad8_signals`, `quad8_count_synapses`, `quad8_signal_ext`, `quad8_index_ext`, and `quad8_count_ext` are file-scope non-const arrays shared across all bound ISA instances, per-device state must reside in `struct quad8` via `counter_priv(counter)` and never mutate those static descriptors. [F82]

## Synchronization

- `quad8_irq_handler()` must not hold `priv->lock` when calling `counter_push_event()`, because `counter_push_event()` acquires `counter->events_list_lock` and invokes read callbacks that take `priv->lock`, while `counter_enable_events()` and `counter_disable_events()` call `quad8_events_configure()` under `counter->events_list_lock`. [F8]
- All process-context acquisitions of `priv->lock` must use `spin_lock_irqsave()` / `spin_unlock_irqrestore()` because `quad8_irq_handler()` calls `counter_push_event()`, which can invoke component read callbacks (`quad8_count_read()`, `quad8_function_read()`, `quad8_action_read()`) that acquire `priv->lock` in hardirq context. [F7]
- Read callbacks in `quad8_ops`, `quad8_signal_ext`, `quad8_index_ext`, and `quad8_count_ext`, as well as `quad8_events_configure()`, must not sleep or perform blocking allocations because `counter_push_event()` and `counter_enable_events()` invoke them while holding `counter->events_list_lock` with IRQs disabled. [F67]
- `quad8_control_register_update()`, `quad8_preset_register_set()`, `quad8_flag_register_reset()`, and `quad8_filter_clock_prescaler_set()` do not lock `priv->lock` internally and must be called with `priv->lock` held whenever invoked after `quad8_probe()`. [F3]
- `quad8_polarity_write()` delegates to `quad8_index_polarity_set()`, which acquires and releases `priv->lock` internally, so `quad8_polarity_write()` must not hold `priv->lock` across that call. [F2]
- `quad8_direction_read()` must not acquire `priv->lock` because, in addition to being registered as a `COUNTER_COMP_DIRECTION` callback in `quad8_count_ext`, it is called directly by `quad8_action_read()` while `priv->lock` is already held. [F70]
- Multi-step channel Data/RLD sequences using the per-channel Byte Pointer (`RESET_BP` on `QUAD8_CONTROL(id)` followed by `QUAD8_DATA(id)` reads/writes or `LOADS` transfers in `quad8_count_read()`, `quad8_preset_register_set()`, and `quad8_filter_clock_prescaler_set()`) must execute under a single continuous `priv->lock` critical section. [F10]
- `quad8_count_read()` must hold `priv->lock` across writing `SELECT_RLD | RESET_BP | TRANSFER_CNTR_TO_OL` to `QUAD8_CONTROL(count->id)` and reading 3 bytes via `regmap_noinc_read()` from `QUAD8_DATA(count->id)`, without combining instantaneous status flags from `QUAD8_CONTROL`. [F61]
- Because counters can only be loaded via the Preset Register, `quad8_count_write()` must hold `priv->lock` continuously while loading `val` via `quad8_preset_register_set()`, issuing `TRANSFER_PR_TO_CNTR`, calling `quad8_flag_register_reset()`, and restoring `priv->preset[count->id]` via `quad8_preset_register_set()`. [F11]
- In `quad8_action_read()`, for quadrature signals (`synapse->signal->id < 16`), `priv->lock` must be held continuously across both `quad8_function_get()` and `quad8_direction_read()`, and `quad8_function_get()` (not `quad8_function_read()`) must be used inside that critical section. [F12]
- `quad8_count_ceiling_read()` and `quad8_count_ceiling_write()` must hold `priv->lock` continuously across checking `COUNT_MODE` in `priv->cmr[count->id]` and reading or updating `priv->preset[count->id]` (and calling `quad8_preset_register_set()`). [F13]
- `quad8_signal_cable_fault_read()` and `quad8_signal_cable_fault_enable_write()` must hold `priv->lock` continuously across checking or updating `priv->cable_fault_enable` and accessing the shared `QUAD8_CABLE_STATUS` register. [F14]

## Object Lifetimes

- In `quad8_probe()`, `priv->map`, `priv->lock`, all channels via `quad8_init_counter()`, and the hardware interrupt registers (`QUAD8_INDEX_INTERRUPT` and `QUAD8_CHANNEL_OPERATION`) must be initialized before `devm_request_irq()` and `devm_counter_add()` are called. [F5]
- In `quad8_probe()`, `devm_request_irq()` for `quad8_irq_handler()` must be bound to `&counter->dev` rather than the parent `struct device *dev` so the IRQ is freed during `counter_unregister()` before the `counter_device` is torn down. [F57]
- `quad8_probe()` must allocate `struct counter_device` and `struct quad8` via `devm_counter_alloc()` and register the device via `devm_counter_add()` rather than embedding `struct counter_device` inside a `devm_kzalloc()`-allocated `struct quad8`. [F58]
- `quad8_driver` defines no `.remove` callback and relies entirely on devres (`devm_*`) in `quad8_probe()` for cleanup on probe failure and driver unbind, so any resource acquired in `quad8_probe()` must be devres-managed unless `.remove` and error rollback are added. [F6]

## API Contracts

- `QUAD8_CABLE_STATUS` is active-low in hardware: `quad8_signal_cable_fault_enable_write()` must write `~priv->cable_fault_enable` (initialized to `GENMASK(7, 0)` in `quad8_probe()`), and `quad8_signal_cable_fault_read()` must first verify under `priv->lock` that `priv->cable_fault_enable & BIT(channel_id)` is non-zero (returning `-EINVAL` if disabled) before reading `QUAD8_CABLE_STATUS` and inverting the tested bit (`!ret`). [F18, F24]
- `quad8_signal_read()` must reject signals with `signal->id < 16` with `-EINVAL` before computing `BIT(signal->id - 16)` to test `QUAD8_INDEX_INPUT_LEVELS`, because `quad8_ops.signal_read` is invoked for all 24 signals in `quad8_signals` and only index signals (16..23) have readable levels. [F38]
- `quad8_watch_validate()` must reject `watch->channel > QUAD8_NUM_COUNTERS - 1` with `-EINVAL` (protecting `priv->ior`, `QUAD8_CONTROL`, and `BIT(channel)` in `quad8_events_configure()`), and must scan `counter->next_events_list` (not `counter->events_list`) to reject (`-EINVAL`) any watch matching an existing `event_node->channel` with a different `event_node->event`. [F40, F47]
- In `quad8_count_write()`, `quad8_count_preset_write()`, and `quad8_count_ceiling_write()`, the `u64` input must be checked against `LS7267_CNTR_MAX` (`GENMASK(23, 0)`, returning `-ERANGE` if greater) before narrowing to `unsigned int` in `priv->preset` or `unsigned long` in `quad8_preset_register_set()` for 24-bit serialization. [F50]
- All `COUNTER_COMP_BOOL` read callbacks (`quad8_count_enable_read()`, `quad8_count_preset_enable_read()`, `quad8_signal_cable_fault_read()`, `quad8_signal_cable_fault_enable_read()`) must write a normalized `0` or `1` into their `u8` output parameter rather than an unshifted bitmask. [F80]
- In `quad8_probe()`, `devm_request_irq()` must pass the `struct counter_device *counter` pointer (not `struct quad8 *priv`) as the `void *dev_id` argument because `quad8_irq_handler()` casts `private` to `struct counter_device *` to derive `priv` via `counter_priv(counter)` and call `counter_push_event()`. [F55]
- `quad8_regmap_config` must keep `.io_port = true` and a non-sleeping spinlock configuration (via `devm_regmap_init_mmio()`'s `fast_io` bus) because `regs` is an `ioport_map` cookie from `devm_ioport_map()` and `priv->map` is accessed under `spin_lock_irqsave(&priv->lock, irqflags)` and in `quad8_irq_handler()`. [F72]
- Every `counter_synapse.signal` pointer in `quad8_count_synapses` must point to an element within the `quad8_signals` array assigned to `counter->signals`. [F79]

## Error Handling

- In `quad8_signal_read()` and `quad8_signal_cable_fault_read()`, `regmap_test_bits()` returns 0 when the tested bit is clear, 1 when set, or a negative errno on failure, so its result must be stored in a signed `int` and checked with `ret < 0` rather than `if (ret)`. [F16]
- In `quad8_count_ceiling_write()`, updating `priv->preset[count->id]` and programming the hardware preset register via `quad8_preset_register_set()` is valid only when `u8_get_bits(priv->cmr[count->id], COUNT_MODE)` is `RANGE_LIMIT` or `MODULO_N`; all other count modes must return `-EINVAL`. [F45]
- In `quad8_probe()`, `devm_request_region()`, `devm_counter_alloc()`, and `devm_ioport_map()` return `NULL` on failure (converted to `-EBUSY` or `-ENOMEM`), whereas `devm_regmap_init_mmio()` returns an error-encoded pointer that must be checked with `IS_ERR()` and converted via `PTR_ERR()`. [F17]
- User-reachable sysfs and ioctl callbacks in `104-quad-8.c` must return negative errno codes (`-EINVAL`, `-ERANGE`) without kernel warnings when rejecting unsupported signal IDs, out-of-range values, or incompatible hardware modes (such as writing ceiling outside `RANGE_LIMIT`/`MODULO_N` or reading `cable_fault` when disabled). [F84]

## Known Pitfalls

- In `quad8_signals`, index signals for channels 0..7 are at indices 16..23 (1 per channel), whereas `QUAD8_COUNT_SYNAPSES(_id)` initializes `synapse[2].signal` to `quad8_signals + 2 * (_id) + 16`; exposing the 3rd synapse in `QUAD8_COUNT` requires changing that offset to `quad8_signals + (_id) + 16`. [F54]
