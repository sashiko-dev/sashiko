# KEXEC

The KEXEC subsystem implements the `kexec_load` and `kexec_file_load` system calls and core infrastructure for loading and booting into a new normal or crash dump kernel image without passing through firmware. It manages `struct kimage` allocations, non-overlapping destination/source page lists and indirection pages, CMA and reserved crash memory allocation, ELF image parsing, purgatory relocation, SHA-256 segment digest verification, and the final transition sequence in `kernel_kexec()`.

## Architecture & Data Flow
- In `do_kexec_load()` and `SYSCALL_DEFINE5(kexec_file_load)`, a new `struct kimage` must complete `machine_kexec_prepare()`, `kimage_crash_copy_vmcoreinfo()`, segment loading, `kimage_terminate()`, and `machine_kexec_post_load()` (plus `kimage_file_post_load_cleanup()` in file mode) before publication via `xchg(dest_image, image)`. In `kexec_file_load()`, `kexec_calculate_store_digests(image)` must run after all segments (including purgatory) are prepared and before `kimage_load_segment()` copies `image->segment[i].kbuf` into destination pages. [F19, F49]
- `struct kexec_segment` unions userspace pointer `buf` with kernel pointer `kbuf`; `kimage_load_normal_segment()`, `kimage_load_cma_segment()`, and `kimage_load_crash_segment()` must check `image->file_mode` to select `kbuf` with `memcpy()` versus `buf` with `copy_from_user()`. [F31]
- `kexec_add_buffer()` may only be called when `image->file_mode` is set and `list_empty(&kbuf->image->control_pages)`. Before calling `arch_kexec_locate_mem_hole(kbuf)`, it must initialize `kbuf->cma = NULL` (as `kexec_locate_mem_hole()` only sets `cma` on `kexec_alloc_contig()` success, while `kexec_add_buffer()` unconditionally stores it into `image->segment_cma[]`) and clamp `kbuf->buf_align` to at least `PAGE_SIZE` and `ALIGN(kbuf->memsz, PAGE_SIZE)` to avoid undefined shifts in `get_order()`. [F35, F84, F122]
- Both `kexec_load_check()` (before `kimage_alloc_init()`) and `kexec_add_buffer()` must verify the segment count does not exceed `KEXEC_SEGMENT_MAX` before writing `image->segment[]` or `image->segment_cma[]`. [F59]
- `sanity_check_segment_list()` must verify for every segment that `mem` (`mstart`) and `mem + memsz` (`mend`) are `PAGE_MASK`-aligned, do not wrap (`mstart > mend`), are below `KEXEC_DESTINATION_MEMORY_LIMIT`, do not overlap other segments, and satisfy `bufsz <= memsz` before any segment pages are allocated or loaded; the `mstart > mend` and `~PAGE_MASK` checks must precede `PAGE_COUNT(image->segment[i].memsz)` so `((x) + PAGE_SIZE - 1) >> PAGE_SHIFT` cannot wrap to `0`. For `KEXEC_TYPE_CRASH` images, `kimage_alloc_init()` and `sanity_check_segment_list()` must also verify `entry` and every `[mem, mem + memsz - 1]` lie within `[phys_to_boot_phys(crashk_res.start), phys_to_boot_phys(crashk_res.end)]`. [F60, F61, F86]
- In `kimage_alloc_crash_control_pages()`, when `[hole_start, hole_end]` overlaps `image->segment[i]`, the inner loop must advance `hole_start = ALIGN(mend, size)` and `break` to restart the segment scan from `i = 0`, and once `i == image->nr_segments`, advance `image->control_page = hole_end + 1`. [F77]
- When searching non-crash System RAM for segment placement, `locate_mem_hole_callback()` must skip resources with `IORESOURCE_SYSRAM_DRIVER_MANAGED` set and `kexec_walk_memblock()` must pass `MEMBLOCK_NONE` to `for_each_free_mem_range()` / `for_each_free_mem_range_reverse()` so driver-managed memory is never used. [F98]
- `kimage_add_entry()` must reserve the final slot of each indirection page (`image->last_entry = ind_page + (PAGE_SIZE / sizeof(kimage_entry_t)) - 1`) for an `IND_INDIRECTION` link, keep the slot after the latest entry zeroed until `kimage_terminate()` writes `IND_DONE`, and require all addresses ORed with `IND_FLAGS` to be `PAGE_MASK`-aligned. Because `kimage_load_normal_segment()` emits one `IND_DESTINATION` per segment followed by per-page `IND_SOURCE` entries, `for_each_kimage_entry()` walkers (`kimage_dst_used()`, `kimage_map_segment()`) must reset their destination cursor on `IND_DESTINATION` and add `PAGE_SIZE` on `IND_SOURCE`. [F64, F74]
- In `do_kimage_alloc_init()`, `image->elfcorehdr_index` must be initialized to `-1`, and `image->ima_segment_index` must be gated by `image->is_ima_segment_index_set` in `check_ima_segment_index()`, because `0` is a valid index in `image->segment[]`. [F56]
- `elf_read_ehdr()` and `elf_read_phdr()` must byte-swap fields via `elf16_to_cpu()`, `elf32_to_cpu()`, or `elf64_to_cpu()` according to `EI_CLASS`, and `elf_is_ehdr_sane()` / `elf_is_phdr_sane()` must validate header entry sizes and overflow-checked buffer bounds against `buf_len` before reading program headers or segments. [F67]
- `kexec_apply_relocations()` and `kexec_purgatory_find_symbol()` must validate that section indices (`sh_info`, `sh_link`, `st_shndx`) are below `ehdr->e_shnum`, and `kexec_purgatory_get_set_symbol()` must verify `sym->st_size == size` and `sec->sh_type != SHT_NOBITS` before accessing `pi->purgatory_buf`. [F68]

## Synchronization
- `do_kexec_load()`, `SYSCALL_DEFINE5(kexec_file_load)`, and `kernel_kexec()` must acquire `__kexec_lock` via the atomic `cmpxchg` `kexec_trylock()` (never a sleeping mutex, as `__crash_kexec()` acquires it in NMI panic context) before reading or updating `kexec_image`, `kexec_crash_image`, or crash memory, and hold it until installation, protection updates, or reboot finishes. Process-context holders remain sleepable, while NMI or syscall callers must never spin on `kexec_trylock()`. [F16, F100, F101]
- For crash images in `do_kexec_load()` and `SYSCALL_DEFINE5(kexec_file_load)`, under `__kexec_lock`, if `kexec_crash_image` is non-NULL, `arch_kexec_unprotect_crashkres()` must be called and the old image atomically cleared and freed via `kimage_free(xchg(&kexec_crash_image, NULL))` before allocating and loading the new image; `arch_kexec_protect_crashkres()` must be called before `kexec_unlock()` only if `kexec_crash_image` is non-NULL. [F18, F104]
- `kernel_kexec()` is called with `system_transition_mutex` already held by the reboot syscall path and must not call `lock_system_sleep()` or `unlock_system_sleep()`, while always balancing its own `kexec_trylock()` with `kexec_unlock()` on every exit path. [F14]
- In `kernel_kexec()` when `kexec_image->preserve_context` is false, `kexec_in_progress = true` must be set under `__kexec_lock` before `kernel_restart_prepare()`, and `cpu_hotplug_enable()` must be called after `migrate_to_reboot_cpu()` and `syscore_shutdown()` before `machine_shutdown()`. [F23, F97]
- In `kernel_kexec()` when `kexec_image->preserve_context` is set (`CONFIG_KEXEC_JUMP`), suspend must proceed in order: `pm_prepare_console()`, `freeze_processes()`, `console_suspend_all()`, `dpm_suspend_start(PMSG_FREEZE)`, `dpm_suspend_end(PMSG_FREEZE)`, `suspend_disable_secondary_cpus()`, `local_irq_disable()`, `syscore_suspend()`, and unwind in reverse using `PMSG_RESTORE` for `dpm_resume_start()` and `dpm_resume_end()`; an error from `dpm_suspend_start()` or `dpm_suspend_end()` must jump to `Resume_devices` (`dpm_resume_end(PMSG_RESTORE)`), skipping `dpm_resume_start()`. [F24, F94, F95]
- `kexec_limit_handler()` and `kexec_load_permitted()` must hold `limit->mutex` (`load_limit_reboot.mutex` or `load_limit_panic.mutex`) continuously across checking and updating `limit->limit`. `kexec_load_disabled`, `kexec_load_limit_panic`, and `kexec_load_limit_reboot` are one-way ratchets: `kexec_load_disabled` only transitions `0` to `1` (`SYSCTL_ONE`), and `kexec_limit_handler()` rejects negative values or values `>= limit->limit` when `limit->limit != -1`. [F21, F120]

## Object Lifetimes
- Pages allocated via `kimage_alloc_pages()` have `PG_reserved` set, their compound order stored in `page_private`, and `arch_kexec_post_alloc_pages()` applied, so they must be freed only via `kimage_free_pages()` (or `kimage_free_page_list()`) rather than `__free_pages()` or `free_page()`. [F6]
- During `do_kexec_load()` and `kexec_file_load`, `kimage_crash_copy_vmcoreinfo(image)` must be called after `machine_kexec_prepare(image)` (which may modify crash memory on architectures like s390), and in `kimage_free(image)`, `crash_update_vmcoreinfo_safecopy(NULL)` must be called before `vunmap(image->vmcoreinfo_data_copy)`. [F10, F123]
- When freeing indirection pages in `kimage_free()` via `for_each_kimage_entry()`, an `IND_INDIRECTION` entry must be saved in `ind` and only freed upon encountering the next `IND_INDIRECTION` entry or after loop termination, because the loop continues dereferencing `*ptr` inside the current indirection page. [F72]
- In `kimage_file_post_load_cleanup()`, `arch_kimage_file_post_load_cleanup(image)` must be called before `kfree(image->image_loader_data)` because `image->fops->cleanup` reads `image->image_loader_data`. `kexec_load_purgatory()` must free and null `pi->sechdrs` and `pi->purgatory_buf` in reverse order on error, while on success leaving both allocated until `kimage_file_post_load_cleanup()` runs after `kexec_calculate_store_digests()` and `kexec_post_load()`. Whenever file-mode buffers are freed, their pointer fields on `struct kimage` and `struct purgatory_info` must be set to `NULL`. [F2, F12, F32]

## API Contracts
- `kimage_is_destination_range()`, `locate_mem_hole_top_down()`, `locate_mem_hole_bottom_up()`, and `locate_mem_hole_callback()` take an inclusive byte range `[start, end]`, so callers checking size `sz` at `addr` must pass `addr + sz - 1`, and `kexec_walk_memblock()` must convert memblock's exclusive `mend` to `res.end = mend - 1`. [F36, F63]
- `locate_mem_hole_callback()`, `locate_mem_hole_top_down()`, `locate_mem_hole_bottom_up()`, `kexec_walk_resources()`, and `kexec_walk_memblock()` return `1` on success (to stop the walk) and `0` to continue searching, whereas `kho_locate_mem_hole()` returns `0` on success, `< 0` on error (which must abort `kexec_locate_mem_hole()` without falling back to CMA/RAM), and `1` when KHO is inactive or loading a crash image. [F78]
- Pages used for kexec (`kimage_alloc_pages()`, `kimage_alloc_crash_control_pages()`, `kexec_alloc_contig()`, and crash pages in `kimage_load_crash_segment()`) must call `arch_kexec_post_alloc_pages()` before writing data (including before `clear_highpage()`) and `arch_kexec_pre_free_pages()` before freeing (`kimage_free_pages()`, `kimage_free_cma()`) or after writing each crash page; both functions take a page count (`1 << order` or `memsz >> PAGE_SHIFT`), not a byte size. [F89, F110]
- `sanity_check_segment_list()` must call `accept_memory(image->segment[i].mem, image->segment[i].memsz)` for every segment after validating its bounds and before kexec allocates or swaps pages for the segments. [F111]
- `kexec_build_elf_info()` frees `elf_info->proghdrs` via `kexec_free_elf_info(elf_info)` on any failure and transfers ownership of `elf_info->proghdrs` (while borrowing `buf` and `ehdr`, which `kexec_free_elf_info()` must not free) to the caller only when it returns `0`. [F11]

## Error Handling
- In `kimage_file_prepare_segments()`, any `struct kimage` pointer field that may receive an `ERR_PTR` (`image->cmdline_buf`, `image->image_loader_data`) must be validated with `IS_ERR()` before assignment or cleared to `NULL` before jumping to `out` (which calls `kimage_file_post_load_cleanup(image)`). `kexec_image_load_default()` returns `ERR_PTR` on failure and `NULL` when a loader has no private data. [F3, F25]
- In `kimage_file_prepare_segments()`, after `kernel_read_file_from_fd()` succeeds for `initrd_fd` and its positive byte count is saved in `image->initrd_buf_len`, `ret` must be reset to `0`. Similarly, in `kimage_alloc_init()`, `kimage_file_alloc_init()`, and `kexec_calculate_store_digests()`, when `kimage_alloc_control_pages()` or `vzalloc()` fails after an earlier step left `ret == 0`, `ret` must be set to `-ENOMEM` before jumping to cleanup. [F27, F33]

## External Contracts
- Both `kexec_load` (via `kexec_load_check()`) and `kexec_file_load` must call `kexec_load_permitted(image_type)`, which requires global `capable(CAP_SYS_BOOT)` (not `ns_capable()`) and `!kexec_load_disabled`, and atomically decrements `load_limit_panic` or `load_limit_reboot` (when not `-1`) under `limit->mutex`. Under `CONFIG_KEXEC_SIG`, `kimage_validate_signature()` must fail the load if `kexec_image_verify_sig()` fails and either `sig_enforce` is true or `security_locked_down(LOCKDOWN_KEXEC)` is active without `ima_appraise_signature(READING_KEXEC_IMAGE)`. [F119, F121]
- In `kimage_file_prepare_segments()`, a non-zero `cmdline_len` includes the trailing NUL byte (`image->cmdline_buf[cmdline_len - 1] == '\0'`, returning `-EINVAL` otherwise) and is stored in `image->cmdline_buf_len` before calling `ima_kexec_cmdline()` or `image->fops->load()`, while `ima_kexec_cmdline()` must be passed `image->cmdline_buf_len - 1` to exclude the NUL terminator. [F93, F118]
- Every UAPI flag added for `kexec_load` or `kexec_file_load` in `include/uapi/linux/kexec.h` must also be added to `KEXEC_FLAGS` or `KEXEC_FILE_FLAGS` in `include/linux/kexec.h`. `kexec_load_check()` must mask out `KEXEC_ARCH_MASK` when validating `flags` against `KEXEC_FLAGS` (`(flags & KEXEC_FLAGS) != (flags & ~KEXEC_ARCH_MASK)`), and `COMPAT_SYSCALL_DEFINE4(kexec_load)` must reject `KEXEC_ARCH_DEFAULT` whereas native `SYSCALL_DEFINE4(kexec_load)` accepts both `KEXEC_ARCH` and `KEXEC_ARCH_DEFAULT`. [F54, F81]
- `struct kexec_segment` in `include/linux/kexec.h` must maintain an identical binary layout to UAPI `struct kexec_segment` in `include/uapi/linux/kexec.h` because `sys_kexec_load` copies descriptors directly via `memdup_array_user()`. Purgatory symbols accessed via `kexec_purgatory_get_set_symbol()` (`purgatory_sha_regions`, `purgatory_sha256_digest`) must have `STB_GLOBAL` binding in a non-`SHT_NOBITS` section and match the exact byte size passed by `kexec_calculate_store_digests()`. [F55, F58]

## Known Pitfalls
- Callers that reuse a `struct kexec_buf` across multiple `kexec_add_buffer()` calls, such as `kexec_elf_load()`, must reset `kbuf->mem = KEXEC_BUF_MEM_UNKNOWN` before each call unless a fixed physical address is intended, and `kexec_elf_load()` must initialize `lowest_addr` to `ULONG_MAX` (not `UINT_MAX`). [F34, F82]
- In `kexec_purgatory_setup_sechdrs()`, each allocated non-BSS section's `sechdrs[i].sh_addr` and `sechdrs[i].sh_offset` in `pi->sechdrs` must be updated together to `kbuf->mem + offset` and `offset` within `pi->purgatory_buf`; after `kexec_purgatory_setup_sechdrs()`, target `SHF_ALLOC` sections must be looked up in `pi->sechdrs` rather than the un-relocated `(void *)pi->ehdr + pi->ehdr->e_shoff`. [F45, F79]
- In `kimage_alloc_page()` and `kimage_alloc_normal_control_pages()`, pages that exceed memory limits or overlap destination ranges must be queued onto `image->unusable_pages`, `image->dest_pages`, or `extra_pages` during the loop rather than freed immediately, and bounds checks against `KEXEC_CONTROL_MEMORY_LIMIT` and `KEXEC_SOURCE_MEMORY_LIMIT` must compare PFNs against `LIMIT >> PAGE_SHIFT` rather than shifting the PFN left (which overflows 32-bit `unsigned long` on PAE/highmem). [F75, F83]
- When `kimage_alloc_page()` swaps a newly allocated destination `page` with an existing source `old_page` found via `kimage_dst_used()`, it must update `*old` to `page`'s address while preserving `*old & ~PAGE_MASK`, and if `old_page` is rejected for being HighMem when `!(gfp_mask & __GFP_HIGHMEM)`, free `old_page` (not `page`) before `continue`. [F76]
- Because `kexec_core_sysctls` entries for `kexec_load_limit_panic` and `kexec_load_limit_reboot` store a `struct kexec_load_limit *` in `.data` (with `.maxlen` unset), `kexec_limit_handler()` must pass a temporary `struct ctl_table` with `.data = &val` and `.maxlen = sizeof(val)` to `proc_dointvec()` rather than passing `table` directly. [F92]
