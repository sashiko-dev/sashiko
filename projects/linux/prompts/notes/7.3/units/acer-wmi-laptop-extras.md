# ACER WMI LAPTOP EXTRAS

The Acer WMI Laptop Extras driver (`drivers/platform/x86/acer-wmi.c`) provides platform integration for Acer, Gateway, Packard Bell, and legacy OEM laptops via ACPI-WMI (`AMW0`, `WMID`, and `WMID` Gaming interfaces), Embedded Controller (EC) registers, and `i8042` commands. It manages rfkill switches (WiFi, Bluetooth, 3G), LCD backlight brightness, the mail LED, sparse-keymap hotkey and tablet-mode input events, an ACPI BMA150 accelerometer, Predator/Nitro thermal platform profiles, turbo/fan/overclocking controls, and hwmon temperature and fan speed sensors.

## Architecture & Data Flow

- In `acer_wmi_init()`, `interface` must only be assigned to `&AMW0_interface` after `dmi_walk(type_aa_dmi_decode, NULL)` and the `WMID_GUID2` / `has_type_aa` detection block, because that block runs whenever `interface != NULL` and returns `-ENODEV` if neither `WMID_GUID2`, `has_type_aa`, nor `force_caps` is present. [F46]
- In `acer_wmi_init()`, `interface->capability` must be updated in exact order: WMI/DMI probing, `set_quirks()`, clearing `ACER_CAP_BRIGHTNESS` when `acpi_video_get_backlight_type() != acpi_backlight_vendor`, and overriding with `force_caps` before testing `ACER_CAP_SET_FUNCTION_MODE`; at runtime, `update_bl_status()` (`acer_bl_ops.update_status`) must obtain target brightness via `backlight_get_brightness(bd)` rather than reading `bd->props.brightness` directly. [F47, F84]
- `find_quirks()` must fall back to `quirks = &quirk_unknown` when no DMI quirk matches, because subsequent code dereferences `quirks` unconditionally and `acer_wmi_init()` checks `quirks == &quirk_unknown` to reject non-whitelisted `AMW0_GUID1` machines not in `non_acer_quirks`. [F50]
- In `acer_quirks` and `non_acer_quirks`, `struct dmi_system_id.driver_data` must point to a `struct quirk_entry` when paired with `.callback = dmi_matched`, and hold an integer capability bitmask cast to `(void *)` when paired with `.callback = set_force_caps`. Never add new entries to `non_acer_quirks`, and only add Acer, Gateway, or Packard Bell machines to `acer_quirks`. [F58, F86]
- `type_aa_dmi_decode()` must clear `ACER_WMID3_GDS_RFBTN` from the global `commun_func_bitmap` decoded from `struct hotkey_function_type_aa` so `wmid3_set_device_status()` never includes the RF button bit in `get_params.devices` or `set_params.devices`. [F33]
- `wmid3_set_device_status()` must first query the current `commun_func_bitmap` state via `WMID_GUID3` method 2, verify both `return_value.error_code == 0` and `return_value.ec_return_value == 0`, and modify only the target `device` bit in `set_params.devices` before invoking method 1. [F32]
- `last_non_turbo_profile` stores a valid `enum acer_predator_v4_thermal_profile` (never `PLATFORM_PROFILE_*` or `INT_MIN`), initialized in `acer_predator_v4_platform_profile_probe()` and updated in `acer_predator_v4_platform_profile_set()` and `acer_thermal_profile_change()` only when the profile is not `ACER_PREDATOR_V4_THERMAL_PROFILE_TURBO`. [F23]
- `acer_predator_v4_platform_profile_probe()`, `acer_predator_v4_platform_profile_get()`, and `acer_predator_v4_platform_profile_set()` must support the exact same set of `enum platform_profile_option` values mapped to `enum acer_predator_v4_thermal_profile`. `acer_predator_v4_platform_profile_probe()` must unconditionally advertise the fixed profile set rather than querying `ACER_WMID_MISC_SETTING_SUPPORTED_PROFILES`, as firmware on some models returns invalid bitmaps. [F37, F67]
- `enum acer_wmi_predator_v4_sensor_id` values are 1-based firmware IDs (1..16): `acer_wmi_hwmon_is_visible()` tests the 16-bit `supported_sensors` mask (`ACER_PREDATOR_V4_SUPPORTED_SENSORS_BIT_MASK`) via `BIT(sensor_id - 1)`, whereas `acer_wmi_hwmon_read()` packs `sensor_id` directly into `ACER_PREDATOR_V4_SENSOR_INDEX_BIT_MASK`. [F39]
- Across `acer_suspend()` and `acer_resume()`, `ACER_CAP_MAILLED` and `ACER_CAP_BRIGHTNESS` states are saved in `interface->data` (`ACER_CAP_MAILLED` is turned off in `acer_suspend()` and `acer_platform_shutdown()`), and `acer_resume()` must call `acer_gsensor_init()` whenever `acer_wmi_accel_dev != NULL`. [F74]
- Sentinel terminators must be preserved: `{ "", 0 }` for `norfkill_ids`, `{KE_END, 0}` for `acer_wmi_keymap`, `NULL` for `acer_wmi_hwmon_info`, and `{}` for DMI tables (`acer_blacklist`, `amw0_whitelist`, `acer_quirks`, `non_acer_quirks`). [F42]

## Synchronization

- In `acer_rfkill_init()`, `rfkill_inited` must be set to `true` only after all `acer_rfkill_register()` calls finish, because `acer_rfkill_register()` calls `rfkill_register()` before `rfkill_set_sw_state()` and relies on `acer_rfkill_set()` skipping `set_u32()` while `!rfkill_inited`. [F10]
- In `acer_rfkill_init()`, `wireless_rfkill`, `bluetooth_rfkill`, and `threeg_rfkill` must all be registered for every enabled capability before `schedule_delayed_work(&acer_rfkill_work, ...)`, because `acer_rfkill_update()` passes them to `rfkill_set_hw_state()` / `rfkill_set_sw_state()` based on `has_cap()`. In `acer_rfkill_exit()`, `cancel_delayed_work_sync(&acer_rfkill_work)` must run under the same condition (`(ec_raw_mode || !wmi_has_guid(ACERWMID_EVENT_GUID)) && has_cap(ACER_CAP_WIRELESS | ACER_CAP_BLUETOOTH | ACER_CAP_THREEG)`) before unregistering and destroying those devices. [F9, F77]
- In `acer_wmi_input_setup()`, `acer_wmi_input_dev` must be allocated and configured via `sparse_keymap_setup()` (plus `SW_TABLET_MODE` capability when `ACER_CAP_KBD_DOCK` is set) before `wmi_install_notify_handler(ACERWMID_EVENT_GUID, acer_wmi_notify, NULL)` is called. [F12]
- In `acer_wmi_accel_setup()`, `gsensor_handle` must be populated before `acer_wmi_accel_dev` is allocated and registered, because `acer_gsensor_event()` and `acer_resume()` only check `if (acer_wmi_accel_dev)` before evaluating ACPI methods on `gsensor_handle`. [F14]
- In `acer_wmi_hwmon_init()`, the global `u64 supported_sensors` must be populated before calling `devm_hwmon_device_register_with_info()`, which immediately invokes `acer_wmi_hwmon_is_visible()` with `&supported_sensors` cast from `const void *` to `const u64 *`. [F15, F59]
- In `WMID_set_u32()`, setting `ACER_CAP_MAILLED` when `quirks->mailled == 1` must bracket `i8042_command(&param, 0x1059)` with `i8042_lock_chip()` and `i8042_unlock_chip()`. [F75]
- `get_u32()`, `set_u32()`, `WMI_gaming_execute_u64()`, `WMI_gaming_execute_u32_u64()`, `acer_gsensor_init()`, and `acer_gsensor_event()` perform sleeping ACPI/WMI evaluations, EC I/O, or `i8042_lock_chip()` and must only be called from sleepable context. [F76]

## Object Lifetimes

- In `AMW0_set_capabilities()`, `struct acpi_buffer out = {ACPI_ALLOCATE_BUFFER, NULL}` is reused in place for the second `wmab_execute()` call: do not free `out.pointer` if the first `wmab_execute()` fails, do not reset `out.length = ACPI_ALLOCATE_BUFFER` before the second call without freeing `out.pointer`, and always `kfree(out.pointer)` on every path after the first call succeeds. [F1]
- `acer_rfkill_register()` calls `rfkill_destroy()` on `rfkill_dev` and returns an `ERR_PTR` if `rfkill_register()` fails; on success, ownership transfers to `acer_rfkill_init()` rollback and `acer_rfkill_exit()`, which must call both `rfkill_unregister()` and `rfkill_destroy()`. [F2]
- In `acer_wmi_accel_setup()`, the `struct acpi_device *adev` returned by `acpi_dev_get_first_match_dev("BST0001", NULL, -1)` must be released with `acpi_dev_put(adev)` after extracting `gsensor_handle`. [F5]
- In `acer_wmi_init()`, `acer_platform_device` must be assigned by `platform_device_alloc()` before `platform_device_add()` triggers `acer_platform_probe()` (which passes `&acer_platform_device->dev` to `acer_wmi_hwmon_init()`), and if `platform_device_add()` fails it must be freed with `platform_device_put()` rather than `platform_device_unregister()`. [F7]
- During teardown in `acer_wmi_input_destroy()` and `acer_wmi_exit()`, `wmi_remove_notify_handler(ACERWMID_EVENT_GUID)` must be called before unregistering `acer_wmi_input_dev`, `acer_wmi_accel_dev`, or `acer_platform_device`. [F13]
- In `acer_platform_probe()` and `acer_platform_remove()`, `mail_led`, `acer_backlight_device`, and rfkill devices use non-devres APIs requiring manual teardown via `acer_led_exit()`, `acer_backlight_exit()`, and `acer_rfkill_exit()` in both probe error paths and `acer_platform_remove()`, whereas `platform_profile_device` and `hwmon` use `devm_*` APIs and must not be manually unregistered. [F66]

## API Contracts

- `AMW0_get_u32()`, `AMW0_set_u32()`, `WMID_get_u32()`, `WMID_set_u32()`, `wmid_v2_get_u32()`, `wmid_v2_set_u32()`, `get_u32()`, and `set_u32()` take an `ACER_CAP_*` capability flag as `cap`, whereas `wmid3_get_device_status()` and `wmid3_set_device_status()` take an `ACER_WMID3_GDS_*` device bitmask as `device`. [F24]
- On `ACER_AMW0_V2`, `set_u32()` must route `ACER_CAP_MAILLED` to `AMW0_set_u32()`, call `WMID_set_u32()` followed by `AMW0_set_u32()` for `ACER_CAP_WIRELESS` and `ACER_CAP_BLUETOOTH`, and fall through to `WMID_set_u32()` otherwise; `get_u32()` only routes `ACER_CAP_MAILLED` to `AMW0_get_u32()` before falling through to `WMID_get_u32()`. [F48]
- `AMW0_set_u32()` and `WMID_set_u32()` must reject `value > max_brightness` for `ACER_CAP_BRIGHTNESS` and `value > 1` for `ACER_CAP_MAILLED`, `ACER_CAP_WIRELESS`, `ACER_CAP_BLUETOOTH`, and `ACER_CAP_THREEG`, because `acer_commandline_init()` passes unvalidated module parameters (`mailled`, `threeg`, `brightness`) to `set_u32()`. [F41]
- Acer WMI radio states (`get_u32()`, `set_u32()`, and `device_state & ACER_WMID3_GDS_*`) encode enabled as non-zero and disabled as `0`, so `acer_rfkill_set()`, `acer_rfkill_register()`, `acer_rfkill_update()`, and `acer_wmi_notify()` must logically invert (`!state` / `!blocked`) when converting to/from `rfkill_set_sw_state()`, `rfkill_set_hw_state()`, and `set_u32()`. [F27]
- `acer_rfkill_register()` passes `(void *)(unsigned long)cap` as the `rfkill_alloc()` data argument, so `acer_rfkill_set()` must extract `u32 cap = (unsigned long)data` by value and never dereference `data`. [F60]
- In `acer_gsensor_event()`, the 64-bit `integer.value` elements from the `RDVL` ACPI package must be cast to `s16` before `input_report_abs()` so two's-complement readings sign-extend into `[-16384, 16384]`. [F56]
- When `acer_thermal_profile_change()` changes the thermal profile via `WMID_gaming_set_misc_setting()` rather than `platform_profile_cycle()`, it must call `platform_profile_notify(platform_profile_device)`. [F82]

## Error Handling

- Scalar query helpers for `WMID_GUID1`, `WMID_GUID2`, and `WMID_GUID4` (`WMI_execute_u32()`, `WMID_set_capabilities()`, `get_wmid_devices()`, `WMI_gaming_execute_u64()`, and `WMI_gaming_execute_u32_u64()`) must check `obj != NULL` and handle both `ACPI_TYPE_INTEGER` and `ACPI_TYPE_BUFFER` responses; for 32-bit queries (`WMI_execute_u32()`, `WMID_set_capabilities()`, `get_wmid_devices()`), `ACPI_TYPE_BUFFER` must accept both `sizeof(u32)` and `sizeof(u64)` lengths and read the low 32 bits. [F19, F45]
- In `wmid3_get_device_status()`, `wmid3_set_device_status()`, `wmid3_set_function_mode()`, `acer_kbd_dock_get_initial_state()`, and `acer_wmi_notify()`, `obj` must be checked for `obj != NULL`, `obj->type == ACPI_TYPE_BUFFER`, and the exact expected `obj->buffer.length` (4 or 8) before dereferencing `obj->buffer.pointer`. [F20]
- Because `acer_wmi_init()` treats `acer_wmi_accel_setup()` failure (such as `-ENODEV` when `BST0001` is absent) as non-fatal and continues with `acer_wmi_accel_dev == NULL`, `acer_gsensor_event()`, `acer_resume()`, `acer_wmi_init()` cleanup, and `acer_wmi_exit()` must check `acer_wmi_accel_dev != NULL` before using or unregistering it. [F21]
- In `acer_backlight_init()`, the return value of `backlight_device_register()` must be checked with `IS_ERR(bd)` in a local variable, setting `acer_backlight_device = NULL` on error before returning `PTR_ERR(bd)`. [F22]

## External Contracts

- In `acer_wmi_keymap`, scancode `0x61` must remain `{KE_KEY, 0x61, {KEY_UNKNOWN} }` rather than `KE_IGNORE` or `KEY_SWITCHVIDEOMODE` so udev/hwdb rules can remap it on machines where it does not duplicate ACPI Video Bus events. [F43]

## Known Pitfalls

- In `acer_wmi_notify()`, when `sparse_keymap_entry_from_scancode()` maps `return_value.key_num` to `KEY_TOUCHPAD_TOGGLE`, `scancode` must be rewritten to `KEY_TOUCHPAD_ON` or `KEY_TOUCHPAD_OFF` based on `device_state & ACER_WMID3_GDS_TOUCHPAD` before calling `sparse_keymap_report_event()`, which requires matching `KEY_TOUCHPAD_ON` and `KEY_TOUCHPAD_OFF` entries in `acer_wmi_keymap`. [F49]
- `WMID_gaming_get_sys_info()` and `WMI_gaming_execute_u32_u64()` take `u32` inputs (`command` and `in`), so callers like `acer_wmi_hwmon_read()` and `WMID_gaming_get_misc_setting()` that construct `u64` bitfields must not set bits above bit 31. [F55]
- `WMID_get_u32()` truncates the 32-bit `result` from `WMI_execute_u32()` via `*value = (u8)result`, discarding bits [31:8] for any `WMID_GUID1` capability read through it. [F57]
- In `acer_gsensor_event()`, `union acpi_object out_obj[5]` passed to `acpi_evaluate_object(gsensor_handle, "RDVL", NULL, &output)` must have at least 5 elements because `out_obj[0]` holds the `ACPI_TYPE_PACKAGE` header and `out_obj[1..4]` hold its 4 package elements. [F61]
- While DMI match tables (`acer_quirks`, `non_acer_quirks`, `acer_blacklist`, `amw0_whitelist`), `norfkill_ids`, and `acer_wmi_keymap` are `__initconst`, `struct quirk_entry` definitions (`quirk_unknown`, `quirk_*`) assigned to `quirks` are dereferenced at runtime and must never be marked `__initdata` or `__initconst`. [F69]
