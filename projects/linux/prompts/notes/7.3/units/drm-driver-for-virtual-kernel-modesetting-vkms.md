# DRM DRIVER FOR VIRTUAL KERNEL MODESETTING (VKMS)

VKMS is a software-only Virtual Kernel Modesetting DRM driver used for headless display emulation and DRM/KMS API testing without physical display hardware. It emulates planes (primary, overlay, cursor), CRTCs with hrtimer-driven vblanks and gamma LUTs, encoders, virtual and writeback connectors, a dynamic configuration layer (`vkms_config`), and an asynchronous workqueue-based line-by-line pixel composer that blends planes in 16-bit ARGB, computes frame CRCs, and populates writeback framebuffers.

## Architecture & Data Flow

- Every pixel format in `vkms_formats` (`vkms_plane.c`) must have a matching case in `get_pixel_read_line_function()`, and every format in `vkms_wb_formats` (`vkms_writeback.c`) must have a matching case in `get_pixel_write_function()` (`vkms_formats.c`), because `vkms_plane_atomic_update()` and `vkms_wb_atomic_commit()` unconditionally resolve formats through these helpers, which call `BUG()` in their `default:` branches. [F40, F41, F68]
- `struct pixel_argb_u16` stores `a`, `r`, `g`, `b` in CPU endianness with `sizeof(struct pixel_argb_u16) == 8` and no padding, whereas 16-bit DRM formats (`ARGB16161616`, `XRGB16161616`, `ABGR16161616`, `XBGR16161616`, `RGB565`, `BGR565`) must convert between `__le16` framebuffer memory and CPU endianness. `compose_active_planes()` and `blend()` accumulate into `*crc32` via `crc32_le(*crc32, ...)` over raw `output_buffer->pixels` bytes without zeroing it, requiring callers to initialize `crc32 = 0`. [F35, F62]
- `struct line_buffer.n_pixels` stores the element count of `struct pixel_argb_u16` entries, whereas `compose_active_planes()` must scale `line_width` by `sizeof(struct pixel_argb_u16)` both when allocating `stage_buffer.pixels` and `output_buffer.pixels` with `kvmalloc()` and when passing `row_size` in bytes to `blend()` for `crc32_le()`. [F92]
- Every `struct drm_plane_state` on a VKMS plane is embedded inside `struct vkms_plane_state.base.base` (via `struct drm_shadow_plane_state`), so `vkms_plane_reset()` and `vkms_plane_duplicate_state()` must allocate `struct vkms_plane_state` so both `to_vkms_plane_state()` and `to_drm_shadow_plane_state()` downcasts remain valid. Broken by: using generic helpers like `drm_gem_reset_shadow_plane()` or `drm_atomic_helper_plane_reset()`. [F95]
- Before `blend()` runs, `compose_active_planes()` must validate `!iosys_map_is_null(&plane_state[i]->frame_info->map[0])` and `planes[i]->pixel_read_line` across every entry `i` in `crtc_state->active_planes` (`num_active_planes`), plus `active_wb->pixel_write` when `active_wb` is non-NULL. Broken by: checking only the primary or first plane's `frame_info->map[0]`. [F73]
- `vkms_plane_atomic_check()` must call `drm_atomic_helper_check_plane_state()` with `DRM_PLANE_NO_SCALING` for both `min_scale` and `max_scale` because `blend_line()` assumes `src` and `dst` rectangles have identical dimensions modulo rotation. [F64]
- `vkms_wb_atomic_check()` must reject writeback framebuffers where `fb->width != mode->hdisplay` or `fb->height != mode->vdisplay`, and `vkms_writeback_row()` must bound written pixels to `min_t(size_t, drm_rect_width(&frame_info->dst), src_buffer->n_pixels)`. [F63]
- In `Rx_read_line()` for sub-byte formats (`DRM_FORMAT_R1`, `DRM_FORMAT_R2`, `DRM_FORMAT_R4`), pixels within a byte block are extracted MSB-first starting at `bit_offset = (8 - bits_per_pixel) - rem_x * bits_per_pixel`, and `src_pixels` must advance by `step` on horizontal reads only when `bit_offset < 0 || 8 <= bit_offset`. [F60]
- In `READ_LINE_YUV_SEMIPLANAR()` and `planar_yuv_read_line()`, chroma plane pointers must start at `(x_start / hsub, y_start / vsub)` and advance by `step` only when `(i + subsampling_offset + 1) % subsampling == 0`, where `get_subsampling_offset()` returns `-x_start - 1` or `-y_start - 1` for reverse directions. [F61]
- `get_conversion_matrix_to_argb_u16()` must call `swap_uv_columns(matrix)` after copying the base YCbCr matrix whenever `format` is a YVU or CrCb-ordered format (`DRM_FORMAT_YVU420`, `DRM_FORMAT_YVU422`, `DRM_FORMAT_YVU444`, `DRM_FORMAT_NV21`, `DRM_FORMAT_NV61`, `DRM_FORMAT_NV42`). [F66]
- Converting 32.32 fixed-point color channels back to 16-bit integer components in `argb_u16_from_RGB565()`, `argb_u16_from_yuv161616()`, and `lerp_u16()` must round to nearest via `drm_fixp2int_round()` rather than truncating with `drm_fixp2int()`. [F80]
- `vkms_config->dev` is only non-NULL while a `vkms_device` is instantiated (`vkms_create()` sets `config->dev = vkms_device` and `vkms_destroy()` resets `config->dev = NULL`), so `vkms_config` validation helpers must null-check `config->dev` before passing `&config->dev->drm` to `drm_info()`. [F50]
- In `vkms_create()`, `dma_coerce_mask_and_coherent()`, `drm_vblank_init()`, `vkms_modeset_init()`, and `vkms_config_register_debugfs()` must complete before `drm_dev_register()`, and `drm_client_setup()` must be called only after `drm_dev_register()` succeeds. [F104]

## Synchronization

- All accesses to `vkms_crtc_state` fields `crc_pending`, `wb_pending`, `frame_start`, and `frame_end` across `vkms_vblank_simulate()`, `vkms_composer_worker()`, and `vkms_wb_atomic_commit()` must be protected by `vkms_output->composer_lock` (acquired via `spin_lock_irq()` in process and workqueue contexts). [F22]
- In `vkms_vblank_simulate()`, `state->frame_start` must only be updated when `!state->crc_pending` under `output->composer_lock`, and `vkms_composer_worker()` must snapshot `frame_start`, `frame_end`, `crc_pending`, and `wb_pending` and clear `crc_pending` under `out->composer_lock` before dropping the lock to run `compose_active_planes()`. [F23]
- `drm_crtc_vblank_put()` and `drm_crtc_vblank_off()` must never be called while holding `vkms_output->lock` (e.g., in `vkms_set_composer()` and `vkms_crtc_atomic_disable()`), because `vkms_disable_vblank()` calls `hrtimer_cancel(&out->vblank_hrtimer)`, which waits for `vkms_vblank_simulate()` (which acquires `out->lock`). In `vkms_set_composer()`, call `drm_crtc_vblank_get(&out->crtc)` before `spin_lock_irq(&out->lock)` when `enabled` is true, update `out->composer_enabled` under `out->lock`, and call `drm_crtc_vblank_put(&out->crtc)` after unlocking only if `old_enabled` was true. [F24, F109]
- `vkms_output->lock` and `vkms_output->composer_lock` must never nest inside each other (`vkms_vblank_simulate()` releases `output->lock` before acquiring `output->composer_lock`), whereas `crtc->dev->event_lock` nests inside `vkms_output->lock` in `vkms_crtc_atomic_flush()`. Broken by: acquiring `vkms_output->lock` while holding `composer_lock` or `dev->event_lock`. [F110]

## Object Lifetimes

- `vkms_plane_helper_funcs` must map plane framebuffers via `drm_gem_fb_vmap()` in `vkms_prepare_fb()` and unmap them via `drm_gem_fb_vunmap()` in `vkms_cleanup_fb()` so mappings remain valid while `vkms_composer_worker()` runs asynchronously. Broken by: replacing them with `DRM_GEM_SHADOW_PLANE_HELPER_FUNCS` (`begin_fb_access`/`end_fb_access`), which unmaps plane buffers before `vkms_composer_worker()` finishes. [F5]
- `vkms_atomic_commit_tail()` must call `flush_work(&vkms_state->composer_work)` on every old `vkms_crtc_state` after `drm_atomic_helper_wait_for_flip_done()` and before `drm_atomic_helper_cleanup_planes()` so in-flight composition finishes before plane framebuffer vmaps are unmapped and the old CRTC state is destroyed. [F44]
- When `new_state->crtc` and `new_state->fb` are non-NULL, `vkms_plane_atomic_update()` assigns `frame_info->fb = fb` and acquires a reference with `drm_framebuffer_get()`, which `vkms_plane_destroy_state()` must release with `drm_framebuffer_put()` before freeing `vkms_state->frame_info`. [F6]
- Because VKMS modesetting objects (`vkms_plane`, `vkms_output`, `composer_workq`, `drm_encoder`, `vkms_connector`, and `wb_connector`) are initialized with `drmm_*` helpers, error and teardown paths in `vkms_output_init()`, its callees, and `vkms_destroy()` must not call manual `drm_*_cleanup()` or `destroy_workqueue()`. [F99]
- `struct vkms_config` is manually allocated and freed via `vkms_config_create()` and `vkms_config_destroy()`, and must outlive the instantiated `struct vkms_device` (call `vkms_destroy(config)` before `vkms_config_destroy(config)`). `vkms_config_get_device_name()` returns a borrowed pointer to `config->dev_name` (allocated with `kstrdup_const()` and freed with `kfree_const()` in `vkms_config_destroy()`), valid only while `config` lives and never to be passed to `kfree()`. [F15, F103]
- The `plane`, `crtc`, `encoder`, and `connector` fields in `struct vkms_config_plane`, `struct vkms_config_crtc`, `struct vkms_config_encoder`, and `struct vkms_config_connector` are unmanaged temporary pointers used only during `vkms_output_init()` and must never be dereferenced outside `vkms_output_init()` or freed by `vkms_config_destroy_*()`. [F102]

## API Contracts

- In `vkms_frame_info`, `src` is 16.16 fixed-point while `dst` is integer CRTC pixels. In `blend_line()`, `dst_line.x1` and `dst_line.x2` must be clamped to `[0, crtc_x_limit]` (returning early if `dst_line.x2 <= dst_line.x1`) before inverse-transforming `src_line`, converting `src` via `drm_rect_fp_to_int()`, and calling `clamp_line_coordinates()` so `pixel_read_line_t` callbacks receive `x_start` in `[0, fb->width)`, `y_start` in `[0, fb->height)`, `count` within `fb->width`/`fb->height`, and `out_pixel` with capacity for at least `count` elements. [F56, F57, F122]
- Before invoking `current_plane->pixel_read_line()` in `blend_line()`, `src_x_start` must be incremented by `pixel_count - 1` when `direction == READ_RIGHT_TO_LEFT` and `src_y_start` must be incremented by `pixel_count - 1` when `direction == READ_BOTTOM_TO_TOP`, and the output pointer must be offset to `&stage_buffer->pixels[dst_x_start]`. [F36]
- `packed_pixels_addr_1x1()` and the `READ_LINE()` macro can only be used for format planes where `drm_format_info_block_width()` and `drm_format_info_block_height()` are both 1; formats packing multiple pixels per block (such as `DRM_FORMAT_R1`, `DRM_FORMAT_R2`, and `DRM_FORMAT_R4` in `Rx_read_line()`) must call `packed_pixels_addr()` to retrieve `rem_x` and `rem_y`. [F91]
- In `vkms_formats.c`, 8-bit channels and YUV offsets must scale to 16-bit by multiplying by `257` (`argb_u16_from_u8888()`, `argb_u16_from_yuv161616()`, `YUV888_semiplanar_read_line()`, `planar_yuv_read_line()`), and 16-bit channels must scale to 8-bit with `DIV_ROUND_CLOSEST(..., 257)` (`argb_u16_to_ARGB8888()`). `argb_u16_from_yuv161616()` expects 16-bit `y`, `channel_1`, and `channel_2` in `[0, 0xffff]`, so 8-bit YUV callers must multiply each byte channel by `257` before calling it. [F39, F82]
- `vkms_config_create()`, `vkms_config_default_create()`, and all `vkms_config_create_*()` functions return `ERR_PTR(-ENOMEM)` on allocation failure and never `NULL`, whereas `vkms_config_crtc_primary_plane()` and `vkms_config_crtc_cursor_plane()` return `NULL` when no matching plane is attached. [F26]
- `vkms_plane_init()`, `vkms_crtc_init()`, and `vkms_connector_init()` return `ERR_PTR`/`ERR_CAST` on failure rather than `NULL`, whereas `.atomic_duplicate_state` callbacks (`vkms_atomic_crtc_duplicate_state()` and `vkms_plane_duplicate_state()`) return `NULL` on failure. [F27]
- `vkms_config_plane_attach_crtc()`, `vkms_config_encoder_attach_crtc()`, and `vkms_config_connector_attach_encoder()` must reject objects belonging to different `struct vkms_config` instances with `-EINVAL` and reject duplicate attachments in the target XArray (`possible_crtcs` or `possible_encoders`) with `-EEXIST`. [F48]

## External Contracts

- Every `drm_encoder` initialized in `vkms_output_init()` and `vkms_enable_writeback_connector()` must include its own `drm_encoder_mask()` in `possible_clones`, and any non-writeback encoder and writeback encoder (`wb_encoder`) sharing a `possible_crtc` must mutually include each other's `drm_encoder_mask()` in `possible_clones`. [F115]
- `vkms_output_init()` must validate `vkmsdev->config` with `vkms_config_is_valid()`, which enforces that plane, CRTC, encoder, and connector counts are in `[1, 31]`, every plane/encoder has a possible CRTC, every connector has a possible encoder, and every CRTC has a possible encoder, one primary plane, and at most one cursor plane. [F125]

## Known Pitfalls

- Because `vkms_config_for_each_plane`, `vkms_config_for_each_crtc`, `vkms_config_for_each_encoder`, and `vkms_config_for_each_connector` expand to `list_for_each_entry`, any loop that unlinks or frees elements via `vkms_config_destroy_*()` must use `list_for_each_entry_safe()` instead. [F76]
- Fixed-point arithmetic on `s64` values in `vkms_formats.c` and `vkms_composer.c` (`argb_u16_from_RGB565()`, `argb_u16_to_RGB565()`, `argb_u16_from_yuv161616()`, `lerp_u16()`, `get_lut_index()`, `vkms_composer_worker()`) must use `<drm/drm_fixed.h>` helpers (`drm_fixp_div()`, `drm_fixp_mul()`) rather than raw 64-bit `/` or `%` operators. [F79]
- In `argb_u16_from_yuv161616()`, the signed `s64` values `fp_r`, `fp_g`, and `fp_b` returned by `drm_fixp2int_round()` must be clamped to `[0, 0xffff]` with `clamp()` before assigning to `u16 r, g, b`. [F81]
- `get_block_step_bytes()` must cast `fb->pitches[plane_index]` to signed `int` before negating for `READ_BOTTOM_TO_TOP` and return a signed `int` stored in a signed `step` variable in callers (`READ_LINE`, `Rx_read_line`, `READ_LINE_YUV_SEMIPLANAR`, `planar_yuv_read_line`). Broken by: storing `step` in an unsigned variable (`u32` or `size_t`) or negating `fb->pitches[plane_index]` without a signed cast. [F83]
- In `clamp_line_coordinates()`, `current_plane->frame_info->fb->width` and `fb->height` (`unsigned int`) must be cast to signed `int` before subtracting `*src_x_start` or `*src_y_start` inside `max(0, ...)`. [F87]
- When logging FourCC pixel format codes with the `%p4cc` printk specifier in `get_pixel_read_line_function()` and `get_pixel_write_function()`, pass the address of the `u32 format` variable (`&format`) rather than passing `format` by value. [F96]
