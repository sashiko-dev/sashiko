# INTEL TOUCH HOST CONTROLLER (THC) DRIVER

The Intel Touch Host Controller (THC) driver subsystem provides PCI and hardware abstraction layers for touch devices connected over Intel's THC controller using HID-over-I2C (`intel-quicki2c`) and HID-over-SPI (`intel-quickspi`). It consists of a shared hardware/DMA core module (`intel-thc`) managing MMIO regmap access, PIO transfers, scatter-gather PRD table DMA rings, interrupt handling, and Wake-on-Touch (WoT), paired with two PCI client drivers that implement protocol state machines and register `hid_ll_driver` interfaces with the Linux HID subsystem.

## Architecture & Data Flow

- RxDMA/SwDMA ring pointers (`TPCRP`, `TPCWP`) store a wraparound bit in `THC_POINTER_WRAPAROUND` (`0x80`) and the 7-bit index in `THC_POINTER_MASK`. `is_dma_buf_empty()` treats a ring as empty only when masked indices match while wraparound bits differ; therefore, `dma_set_start_bit()` must set `TPCWP` to `0x80` after `thc_reset_dma_settings()` resets `TPCRP` to 0, `thc_dma_read()` must mask `write_ptr` with `THC_POINTER_MASK`, and `update_write_pointer()` must wrap `write_ptr + 1 == 0x10` (`THC_WRAPAROUND_VALUE_ODD`) to `0x80` and `0x90` (`THC_WRAPAROUND_VALUE_EVEN`) to 0. [F51, F90, F91]
- After `read_dma_buffer()` copies a frame in `thc_dma_read()`, `thc_copy_one_sgl_to_prd()` must reinitialize `read_config->prd_tbls[prd_table_index]` before `update_write_pointer()` advances the hardware write pointer. [F50]
- Every populated `struct thc_prd_entry` in `thc_copy_one_sgl_to_prd()` and `write_dma_buffer()` must store `sg_dma_address(sg) >> THC_ADDRESS_SHIFT` in `dest_addr`, set `end_of_prd = 1` on the final entry (0 on preceding entries), and have `len` as a multiple of `SZ_4K` on all non-final entries. `dma_set_max_packet_size()` rounds `max_packet_size` up with `ALIGN(size, SZ_4K)`, `calc_prd_entries_num()` requires `DIV_ROUND_UP(mes_len, THC_MIN_BYTES_PER_SG_LIST_ENTRY) <= PRD_ENTRIES_NUM` (`16`), and `write_dma_buffer()` rewrites `prd_tbls[0].entries` and calls `dma_set_prd_control(dev, i, 0, write_config)`. [F53, F70, F88, F122, F129]
- `dma_set_prd_base_addr()` in `thc_dma_configure()` must program `prd_base_addr_high`/`low` with the DMA address `config->prd_tbls_dma_handle` from `dma_alloc_coherent()`, never `config->prd_tbls` or `virt_to_phys()`. [F130]
- A `struct thc_dma_configuration` channel has `is_enabled == false` and NULL `prd_tbls`/`sgls` unless `thc_dma_set_max_packet_sizes()` set a non-zero packet size before `thc_dma_allocate()`, so all per-channel DMA helpers must check `config->is_enabled` before accessing PRD tables or registers. [F36]
- During SWDMA, `thc_swdma_read_start()` must quiesce device interrupts (`thc_interrupt_quiesce()`), pause `THC_RXDMA1` and `THC_RXDMA2` (`thc_wait_for_dma_pause()`), call `thc_reset_dma_settings()`, and disable I2C Rx max-size and interrupt-delay features while saving their states in `dev->dma_ctx->rx_max_size_en` and `rx_int_delay_en`. `thc_swdma_read_completion()` must then pause `THC_SWDMA`, reset DMA settings, restore the saved I2C features (and clear the temporary flags), restart `THC_RXDMA2`, and unquiesce interrupts. [F4, F52]
- In `quicki2c_device`, `qcdev->ddata` is NULL for Lunar Lake PCI IDs in `quicki2c_pci_tbl`, so any access to `qcdev->ddata` or calls to `quicki2c_dma_adv_enable()` / `quicki2c_dma_adv_disable()` must check `if (qcdev->ddata)`. Also, `qsdev->driver_data` and `qcdev->ddata` point to static structs shared across PCI ports, so per-device ACPI overrides must be stored in `qsdev->spi_packet_size`, `qcdev->i2c_max_frame_size`, and `qcdev->i2c_int_delay` rather than mutating the shared structs. [F33, F59]
- In `quickspi_probe()` and `quickspi_restore()`, `reset_tic()` must run after `thc_interrupt_config()` sets `THC_M_PRT_INTTYP_DATA_VAL` to `THC_BITMASK_INVALID_TYPE_DATA` and before `thc_dma_configure()` sets it to `THC_BITMASK_INTERRUPT_TYPE_DATA`. `qcdev->state` / `qsdev->state` must be set to `QUICKI2C_ENABLED` / `QUICKSPI_ENABLED` only after `*_hid_probe()` sets `hid_dev`, and restored to `QUICKSPI_ENABLED` at the end of `quickspi_restore()` after `reset_tic()` sets `QUICKSPI_RESET`. [F57, F105]
- `quickspi_alloc_report_buf()` must size `qsdev->input_buf` (and `quickspi_dma_init()` must size `THC_RXDMA2`) to at least `max(le16_to_cpu(qsdev->dev_desc.rep_desc_len), le16_to_cpu(qsdev->dev_desc.max_input_len))` because `quickspi_irq_thread_handler()` reads both `REPORT_DESCRIPTOR_RESPONSE` and input reports into `qsdev->input_buf` via `thc_rxdma_read()`. [F102]
- In `handle_input_report()`, `pkt->len` from `struct hidi2c_report_packet` must be checked for zero (and skipped as a reset response) before evaluating `HIDI2C_DATA_LEN(le16_to_cpu(pkt->len))`, which subtracts `HIDI2C_LENGTH_LEN` (`2`). [F74]
- In `thc_interrupt_handler()`, only `THC_NONDMA_INT`, `THC_TXN_ERR_INT`, and `THC_FATAL_ERR_INT` return early; all other interrupt checks (`THC_PIO_DONE_INT`, `THC_RXDMA1_INT`, `THC_RXDMA2_INT`, `THC_SWDMA_INT`, `THC_TXDMA_INT`, `THC_I2CSUBIP_INT`) must fall through and OR their bit into `interrupt_type`. [F81]
- Before starting PIO in `prepare_pio()`, `THC_M_PRT_SW_SEQ_STS_THC_SS_ERR | THC_M_PRT_SW_SEQ_STS_TSSDONE` must be cleared so `pio_wait()` polls until `THC_SS_CIP` is clear and `TSSDONE` is set. [F85]

## Synchronization

- Every synchronous transfer entry point (`thc_tic_pio_read()`, `thc_tic_pio_write()`, `thc_tic_pio_write_and_read()`, `thc_i2c_subip_pio_read()`, `thc_i2c_subip_pio_write()`, `thc_swdma_read()`, and `thc_dma_write()`) must acquire `dev->thc_bus_lock` via `mutex_lock_interruptible()` and unlock it on all return paths. `thc_dma_write()` must hold `dev->thc_bus_lock` from `write_dma_buffer()` until after `wait_event_interruptible_timeout(dev->write_complete_wait, ...)` and `thc_dma_write_completion()` complete, serializing `prd_tbls[0]` and enforcing the post-write `dev->perf_limit` delay. [F5, F15]
- `thc_interrupt_handler()` and the threaded IRQ handlers (`quicki2c_irq_thread_handler()`, `quickspi_irq_thread_handler()`) must not acquire `dev->thc_bus_lock` before waking `dev->swdma_complete_wait` or `dev->write_complete_wait`, because `thc_swdma_read()` and `thc_dma_write()` sleep on those waitqueues while holding `dev->thc_bus_lock`. [F16]
- `thc_regmap_cfg` must keep `.fast_io = true` and `thc_regmap_read()`/`thc_regmap_write()` must remain non-sleeping, because `quicki2c_irq_quick_handler()` and `quickspi_irq_quick_handler()` call `thc_interrupt_enable(thc_hw, false)` in hardirq context before returning `IRQ_WAKE_THREAD` (and the IRQ thread handlers must re-enable interrupts via `thc_interrupt_enable(thc_hw, true)` after `thc_interrupt_handler()` clears status bits). [F123, F126]
- `quicki2c_reset()` must set `qcdev->reset_ack = false` and `qcdev->state = QUICKI2C_RESETING` before `write_cmd_to_txdma(qcdev, HIDI2C_RESET, ...)`. Similarly, `reset_tic()` must set `qsdev->state = QUICKSPI_RESETING` and `qsdev->reset_ack = false` before `thc_interrupt_quiesce(qsdev->thc_hw, false)`, and must transition `qsdev->state` to `QUICKSPI_RESET` before calling `quickspi_get_device_descriptor()`. [F19, F20]

## Object Lifetimes

- Although `struct thc_dma_context` is devm-allocated in `thc_dma_init()`, each enabled channel's coherent PRD tables (`dma_alloc_coherent()`) and scatterlists (`sgl_alloc()`, `dma_map_sg()`) in `setup_dma_buffers()` are unmanaged. During teardown or error rollback, `thc_dma_unconfigure()` must be called before `thc_dma_release()` so hardware DMA engines are stopped and PRD base registers are cleared before scatterlists are unmapped and PRD tables are freed. [F1, F109]
- `thc_i2c_subip_init()` must succeed before `thc_i2c_subip_regs_save()` or `thc_i2c_subip_regs_restore()` is called, because both unconditionally dereference `dev->i2c_subip_regs`, allocated at the end of `thc_i2c_subip_init()`. [F11]
- In `thc_wot_config()`, if `dev_pm_set_dedicated_wake_irq()` fails after `device_init_wakeup(thc_dev->dev, true)`, it must roll back via `device_init_wakeup(thc_dev->dev, false)`, and `thc_wot_unconfig()` must be called in `quicki2c_dev_deinit()` and `quickspi_dev_deinit()`. In `quicki2c_dev_deinit()`, external touch interrupts must also be quiesced via `thc_interrupt_quiesce(qcdev->thc_hw, true)` alongside `thc_interrupt_enable(qcdev->thc_hw, false)`. [F12, F106]
- `quicki2c_acpi_get_dsm_property()` and `thc_acpi_get_property()` must free the `union acpi_object` from `acpi_evaluate_dsm_typed()` with `ACPI_FREE(obj)` after copying into `prop_buf` (never returning a pointer into `obj->buffer.pointer`). [F10]

## API Contracts

- Despite kernel-doc comments claiming NULL on failure, `thc_dev_init()`, `quicki2c_dev_init()`, and `quickspi_dev_init()` return `ERR_PTR`-encoded error codes. Callers must check `IS_ERR()`, and `quicki2c_probe()` / `quickspi_probe()` must jump to `disable_pci_device` before calling `pci_set_drvdata()` or `*_dev_deinit()`. [F27, F29]
- Callers of `quicki2c_acpi_get_dsm_property()` or `thc_acpi_get_property()` with `ACPI_TYPE_INTEGER` must pass the address of a `u32` as `prop_buf` because both write `*(u32 *)prop_buf`. With `ACPI_TYPE_BUFFER` (including `quicki2c_acpi_get_dsd_property()`), `prop_buf` must be at least as large as `obj->buffer.length` because they `memcpy()` the entire ACPI buffer unchecked. [F64, F98]
- Because `THC_PORT_TYPE_SPI` is 0, a new `struct thc_device` defaults to SPI mode; for I2C devices, `thc_port_select(dev, THC_PORT_TYPE_I2C)` must be called before `thc_interrupt_config()`, `thc_tic_pio_read()`, `thc_tic_pio_write()`, or `thc_tic_pio_write_and_read()`. [F46]
- `thc_interrupt_handler()` returns a positive bitmask of `BIT(enum thc_int_type)` flags (setting `BIT(THC_UNKNOWN_INT)` when no status bit matched) rather than `<= 0`, so IRQ thread handlers must test `BIT(THC_FATAL_ERR_INT)`, `BIT(THC_TXN_ERR_INT)`, and `BIT(THC_UNKNOWN_INT)` explicitly. [F32]
- `thc_rxdma_read()` (via `thc_dma_read()`) reads at most one PRD table frame per call and sets `*read_finished` via `is_dma_buf_empty()`, so callers must loop on `while (!read_finished)` and break immediately on error. Because `thc_dma_read()` returns 0 without modifying `*read_len` if `is_dma_buf_empty()` is true on entry, callers inspecting `read_len` (like `quicki2c_get_report()`) must initialize `read_len` to 0 before the call. [F39, F79]
- In `thc_swdma_read()` / `thc_swdma_read_start()`, `prd_tbl_len` may be NULL (when NULL, set `THC_M_PRT_RPRD_CNTRL_SW_THC_SWDMA_I2C_RX_DLEN_EN` without dereferencing it), and `write_len` must be `<= 2 * sizeof(u32)` (8 bytes) so `write_buff` fits in `DATA0`/`DATA1`. In `thc_dma_read()`, `read_finished` is nullable (NULL from `thc_swdma_read()`) and must be guarded with `if (read_finished)`. [F34, F35, F72]
- Although `thc_*_pio_*` helpers take `u32 *buffer`, their size arguments are in bytes (`prepare_pio()` writes the byte count to `THC_SS_BC` and `pio_start()`/`pio_complete()` divide by `sizeof(u32)`). [F100]
- Unit conversions: `thc_i2c_set_rx_int_delay()` takes microseconds and divides by 10, whereas `qcdev->i2c_int_delay` (ACPI `ISUB.INDV`) is in 10-us units and must be multiplied by 10 by callers; `thc_spi_write_config()` takes `perf_limit` in 10-us units; `thc_spi_read_config()` / `thc_spi_write_config()` take `spi_rd_mps` and `spi_wr_mps` in 16-byte units (`qsdev->spi_packet_size`), whereas `thc_dma_set_max_packet_sizes()` takes bytes. [F41, F42, F43]
- In `thc_interrupt_quiesce()`, setting `THC_M_PRT_CONTROL_THC_DEVINT_QUIESCE_EN` when `int_quiesce` is true must precede polling `THC_DEVINT_QUIESCE_HW_STS`, whereas clearing it when `int_quiesce` is false must follow that poll. [F117]

## Error Handling

- `thc_dma_init()` and `devm_kzalloc()` in `thc_i2c_subip_init()` return NULL on failure, so callers must check `!ptr` and return `-ENOMEM` or `ERR_PTR(-ENOMEM)` rather than using `PTR_ERR()` or `IS_ERR()`. [F28]
- In `setup_dma_buffers()`, `config->sgls` and `config->sgls_nent` must be zeroed with `memset()` before the `sgl_alloc()` loop, and `thc_copy_sgls_to_prd()` must zero `config->prd_tbls` before populating entries, so `release_dma_buffers()` skips unallocated scatterlists and unused PRD fields are 0. [F38]
- In `quicki2c_reset()`, if waiting on `qcdev->reset_ack_wq` times out without `qcdev->reset_ack`, the driver must fall back to reading `qcdev->dev_desc.input_reg` via `thc_tic_pio_read()` and treat a 16-bit zero length (`!get_unaligned_le16(qcdev->input_buf)`) as a successful reset. [F121]

## External Contracts

- Hardware PRD control fields `THC_M_PRT_RPRD_CNTRL_PTEC`, `PCD`, and `THC_WRDMA_PTEC` are 0-based, so `thc_dma_configure()` must pass `PRD_ENTRIES_NUM - 1` and `prd_tbl_num - 1` (and `write_dma_buffer()` passes 0-based last entry index `i`) to `dma_set_prd_control()`. [F92]
- Wire report framing: in `quickspi_get_device_descriptor()` and `reset_tic()`, `FIELD_GET(HIDSPI_INPUT_HEADER_REPORT_LEN, int_cause_val)` is in 4-byte dwords and must be multiplied by `sizeof(u32)`. `quickspi_set_report()` must pass `buf + 1` and `buf_len - 1` to `write_cmd_to_txdma()` (`output_hdr.content_id` carries `buf[0]`), whereas `quickspi_handle_input_data()` must add `sizeof(body_hdr->content_id)` to `input_len` and start at `input_body->content - sizeof(body_hdr->content_id)`. In HID-over-I2C, the 16-bit wire `len` includes its own 2-byte size (`HIDI2C_LENGTH_LEN`), so `quicki2c_init_write_buf()` adds `HIDI2C_LENGTH_LEN` and readers subtract it via `HIDI2C_DATA_LEN()`. [F77, F96, F97]
- `struct quicki2c_subip_acpi_parameter` (`__packed`) and `struct quicki2c_subip_acpi_config` must retain their trailing `u8 reserved` padding so their sizes cover the full `ICRS` and `ISUB` ACPI buffers, which `quicki2c_acpi_get_dsd_property()` evaluates via `acpi_evaluate_object()` with a NULL `external_params` pointer. [F63, F115]

## Known Pitfalls

- In `struct quicki2c_device`, `qcdev->report_len` holds the allocated capacity of `qcdev->report_buf` and must not be overwritten with per-transfer lengths, whereas in `struct quickspi_device`, `qsdev->report_len` holds the transient payload length set in `quickspi_handle_input_data()` for `quickspi_get_report()`. [F60]
- In `thc_i2c_subip_regs_save()` and `thc_i2c_subip_regs_restore()`, the file-scope array `i2c_subip_regs[i]` holds register offsets while `dev->i2c_subip_regs[i]` holds saved register values; do not swap them in `thc_i2c_subip_pio_read()` or `thc_i2c_subip_pio_write()`. [F86]
