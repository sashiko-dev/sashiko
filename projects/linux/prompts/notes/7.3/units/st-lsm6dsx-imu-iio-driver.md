# ST LSM6DSx IMU IIO DRIVER

Industrial I/O (IIO) driver for STMicroelectronics LSM6DSx, ISM330, ASM330, and LSM9DS1 6-axis Inertial Measurement Units (accelerometer + gyroscope) over I2C, SPI, and I3C buses. It registers separate IIO devices for accelerometer, gyroscope, and up to three external I2C slave sensors attached to the IMU's embedded sensor hub, supporting direct register reads, motion wakeup threshold events, hardware pattern/tagged FIFO buffering, and software-triggered buffering.

## Architecture & Data Flow

- In `struct st_lsm6dsx_settings`, `channels`, `odr_table`, `samples_to_discard`, and `fs_table` only have 2 elements (`ST_LSM6DSX_ID_GYRO` and `ST_LSM6DSX_ID_ACC`). Code handling `ST_LSM6DSX_ID_EXT0..2` must guard on `sensor->id` or substitute the `ST_LSM6DSX_ID_ACC` reference sensor before indexing them or calling `st_lsm6dsx_check_odr()`. In `st_lsm6dsx_set_odr()`, the dependency loop must skip `i == sensor->id` while subsequent `st_lsm6dsx_check_odr()` and `odr_table[]` accesses use `ref_sensor` (`ST_LSM6DSX_ID_ACC`). [F44, F58]
- When updating or disabling the ODR for `ST_LSM6DSX_ID_ACC` or `ST_LSM6DSX_ID_EXT0..EXT2`, `st_lsm6dsx_set_odr()` must check all other sensors in `ST_LSM6DSX_ID_ACC..ST_LSM6DSX_ID_MAX` via `st_lsm6dsx_check_odr_dependency()` and return without writing the accelerometer ODR register if any other enabled sensor requires a higher ODR. [F6]
- For external sensor-hub devices (`ST_LSM6DSX_ID_EXT0..EXT2`), `sensor->ext_info.slv_odr` stores the slave's own ODR (for slave register writes, oneshot delays, and sysfs reads) while `sensor->odr` stores the accelerometer trigger ODR resolved via `st_lsm6dsx_check_odr()`. [F30]
- Updating `IIO_CHAN_INFO_SAMP_FREQ` in `st_lsm6dsx_write_raw()` and `__st_lsm6dsx_shub_write_raw()` while in direct mode must only validate and cache the resolved hardware frequency returned by `st_lsm6dsx_check_odr()` into `sensor->odr` without calling `st_lsm6dsx_set_odr()` to write hardware ODR registers. [F31]
- When computing delays that depend on the active accelerometer clock (such as in `st_lsm6dsx_shub_wait_complete()`), check `hw->enable_mask & BIT(ST_LSM6DSX_ID_ACC)` before using the accelerometer's `sensor->odr`, falling back to `12500` mHz when `ST_LSM6DSX_ID_ACC` is not enabled. [F34]
- Active hardware FIFO buffering is tracked in `hw->fifo_mask` (committed only after `st_lsm6dsx_update_fifo()` succeeds) separately from `hw->enable_mask` and `hw->suspend_mask`. FIFO flush and resume across reconfiguration and `st_lsm6dsx_suspend()`/`st_lsm6dsx_resume()` must be gated on `hw->fifo_mask`. On resume, `st_lsm6dsx_resume_fifo()` must be called (rather than `st_lsm6dsx_set_fifo_mode()` directly) so `st_lsm6dsx_reset_hw_ts()` resets the timestamp counter before re-entering `ST_LSM6DSX_FIFO_CONT`. [F35, F99]
- Whenever the hardware timestamp counter is reset via `ST_LSM6DSX_REG_TS_RESET_ADDR` (on FIFO resume or when a timestamp rollover threshold is reached during FIFO readout), `st_lsm6dsx_reset_hw_ts()` must refresh `sensor->ts_ref` with `iio_get_time_ns()` for every allocated `hw->iio_devs[i]`. [F38]
- In `st_lsm6dsx_update_fifo()`, `st_lsm6dsx_flush_fifo()` must drain the old pattern before `st_lsm6dsx_device_set_enable()` updates `hw->enable_mask`, which must precede `st_lsm6dsx_update_decimators()` recomputing `sensor->sip`, `sensor->decimator`, `hw->ts_sip`, and `hw->sip` for `st_lsm6dsx_update_watermark()`. [F36]
- `st_lsm6dsx_update_watermark()` must return early when `hw->sip` is 0 before dividing `fifo_watermark` by `hw->sip`. `st_lsm6dsx_read_fifo()` and `st_lsm6dsx_read_tagged_fifo()` must clamp a zero `pattern_len` (when `hw->sip` is 0) to `ST_LSM6DSX_SAMPLE_SIZE` or `ST_LSM6DSX_TAGGED_SAMPLE_SIZE` before dividing `fifo_len` by `pattern_len` or incrementing `read_len` by `pattern_len`. [F67, F68]
- `st_lsm6dsx_update_decimators()` only computes `sensor->sip` and `sensor->decimator` for sensors enabled in `hw->enable_mask` (setting `sensor->sip = 0` otherwise). When parsing untagged FIFO patterns in `st_lsm6dsx_read_fifo()`, each step `sip` must check `*_sip > 0` and `!(sip % sensor->decimator)` before extracting samples, pushing to buffers, or decrementing `*_sip`. [F37, F69]
- Because `st_lsm6dsx_shub_config_channels()` packs enabled external sensors (`ST_LSM6DSX_ID_EXT0..EXT2`) contiguously into `SLV1..SLV3`, `st_lsm6dsx_push_tagged_data()` must map `ST_LSM6DSX_EXT0_TAG..EXT2_TAG` to the 1st, 2nd, and 3rd enabled external sensor in `hw->enable_mask`, not directly to `hw->iio_devs[ST_LSM6DSX_ID_EXT0..2]`. [F39]
- FIFO diff counts and watermarks use different word units: pattern FIFO (`st_lsm6dsx_read_fifo`) scales `fifo_diff` by `ST_LSM6DSX_CHAN_SIZE` (2B) with `th_wl = 3` and must round `fifo_len` down to a multiple of `pattern_len` (`hw->sip * ST_LSM6DSX_SAMPLE_SIZE`), whereas tagged FIFO (`st_lsm6dsx_read_tagged_fifo`) scales `fifo_diff` by `ST_LSM6DSX_TAGGED_SAMPLE_SIZE` (7B) with `th_wl = 1`. [F51, F76]
- In `struct st_lsm6dsx_hw`, `iio_devs[ST_LSM6DSX_ID_EXT0..EXT2]` are only populated for detected external slaves; any loop over `hw->iio_devs` up to `ST_LSM6DSX_ID_MAX` must check `if (!hw->iio_devs[i])` before dereferencing or calling `iio_priv()`. [F46]
- Before accessing optional `struct st_lsm6dsx_reg` descriptors (`event_settings.enable_reg`, `drdy_mask`, `decimator[]`, `batch[]`, `lir`, `clear_on_read`, `aux_sens`, `emb_func`, `wr_once`, `pwr_table.reg`, `fs_table.reg`), check `reg.addr != 0`. Control and IRQ pin accesses (`reset`, `boot`, `bdu`, `irq_config.hla`, `irq_config.od`) must use `hw->settings` descriptors rather than hardcoded addresses/masks. [F86, F88]
- Code that flushes, drains, or configures the hardware FIFO (`st_lsm6dsx_flush_fifo()`, `st_lsm6dsx_handler_thread()`, `st_lsm6dsx_probe()`, `st_lsm6dsx_buffer_preenable()`, `st_lsm6dsx_buffer_postdisable()`) must check that `hw->settings->fifo_ops.read_fifo` or `update_fifo` is non-NULL before invoking it. [F87]
- Fixed-size descriptor arrays have trailing zeroes: bound `fs_avl`/`odr_avl` loops by `fs_len`/`odr_len` (never `ST_LSM6DSX_FS_LIST_SIZE` or `ST_LSM6DSX_ODR_LIST_SIZE`), and check `id[j].name != NULL` or `settings->i2c_addr[i] != 0` when iterating `st_lsm6dsx_sensor_settings[].id[]` or `i2c_addr[]`. `enum st_lsm6dsx_hw_id` values must be in `1 .. ST_LSM6DSX_MAX_ID - 1`. [F28, F43, F45]

## Synchronization

- Mutex acquisition in `struct st_lsm6dsx_hw` must follow `hw->conf_lock -> hw->fifo_lock -> hw->page_lock`. Code holding `hw->fifo_lock` must never acquire `hw->conf_lock`, and code holding `hw->page_lock` must never acquire `hw->fifo_lock`, `hw->conf_lock`, or call `st_lsm6dsx_*_locked()` or `st_lsm6dsx_sensor_set_enable()`. [F12]
- At runtime (after `st_lsm6dsx_init_device()`), all primary-page `hw->regmap` accesses must hold `hw->page_lock`, and secondary-page accesses must hold `hw->page_lock` across the entire `st_lsm6dsx_set_page(hw, true)`, register access, and `st_lsm6dsx_set_page(hw, false)` sequence. [F102]
- Updates to FIFO configuration, watermark registers, and shared sensor/FIFO enable state across `st_lsm6dsx_update_fifo()`, `st_lsm6dsx_set_watermark()`, and `st_lsm6dsx_write_event_config()` must be serialized under `hw->conf_lock`. Broken by: calling `st_lsm6dsx_update_watermark()`, `st_lsm6dsx_update_decimators()`, or `__st_lsm6dsx_sensor_set_enable()` without `hw->conf_lock`. [F13]
- All calls to `hw->settings->fifo_ops.read_fifo` must be serialized under `hw->fifo_lock`. `st_lsm6dsx_flush_fifo()` must hold `hw->fifo_lock` continuously across draining the FIFO and setting `ST_LSM6DSX_FIFO_BYPASS`, and `st_lsm6dsx_handler_thread()` must loop `do { ... } while (len > 0);` under `hw->fifo_lock` until `read_fifo()` returns `<= 0`. [F14, F96]
- In `st_lsm6dsx_read_raw()`, `st_lsm6dsx_shub_read_raw()`, `st_lsm6dsx_write_raw()`, and `st_lsm6dsx_shub_write_raw()`, `IIO_CHAN_INFO_RAW` reads and all `write_raw` updates must claim direct mode with `iio_device_claim_direct(iio_dev)` (or return `-EBUSY`), and every subsequent normal and error path must call `iio_device_release_direct(iio_dev)`. [F1, F107]

## Object Lifetimes

- Whenever `st_lsm6dsx_set_page(hw, true)` succeeds in `st_lsm6dsx_shub_read_output()`, `st_lsm6dsx_shub_write_reg()`, `st_lsm6dsx_shub_write_reg_with_mask()`, `st_lsm6dsx_shub_master_enable()`, or `st_lsm6dsx_init_shub()`, `st_lsm6dsx_set_page(hw, false)` must be called before unlocking `hw->page_lock` or returning, even when the register access fails. [F2]
- In `st_lsm6dsx_probe()`, `st_lsm6dsx_init_regulators()` (including `msleep(50)`) must run before any `hw->regmap` access. `hw->fifo_lock`, `hw->conf_lock`, `hw->page_lock`, `hw->buff`, `hw->settings`, and primary `hw->iio_devs[]` must be initialized before `st_lsm6dsx_init_device()` and `st_lsm6dsx_shub_probe()`, which must precede IRQ, FIFO, software buffer, and IIO device registration. [F4, F18, F81]
- FIFO readers must use the pre-allocated heap buffer `hw->buff` (`ST_LSM6DSX_BUFF_SIZE`) rather than stack buffers. In `st_lsm6dsx_shub_alloc_iiodev()`, stack `magn_channels` must be copied to a `devm_kzalloc()` buffer before assigning `iio_dev->channels`, and all allocations/registrations must use `devm_*` bound to `hw->dev` (bus drivers have no `.remove`). [F74, F78, F85]

## API Contracts

- After `st_lsm6dsx_shub_check_wai()`, `st_lsm6dsx_shub_read()`, or `st_lsm6dsx_shub_write()` uses `SLV0` for a one-shot I2C transaction, it must pair `st_lsm6dsx_shub_master_enable(sensor, true)` with `st_lsm6dsx_shub_master_enable(sensor, false)` and reset the `SLV0` address register to `hub_settings->pause`. [F9]
- `st_lsm6dsx_check_odr()` returns the matched ODR in positive milli-Hz on success or `-EINVAL` on failure (writing the hardware register code to `*val`); callers must store its return value in a signed `int` and test `< 0` rather than non-zero. [F19]
- `st_lsm6dsx_shub_write_with_mask()` shifts `val` by `__ffs(mask)` internally and requires an unshifted field value, whereas `st_lsm6dsx_update_bits_locked()`, `st_lsm6dsx_shub_write_reg_with_mask()`, and `regmap_update_bits()` require `val` to be pre-shifted with `ST_LSM6DSX_SHIFT_VAL(val, mask)` or `FIELD_PREP()`. [F23]
- `st_lsm6dsx_alloc_iiodev()` and `st_lsm6dsx_shub_alloc_iiodev()` return `NULL` (never an `ERR_PTR`) on failure. `st_lsm6dsx_shub_check_wai()` returns `-ENODEV` when a slave is absent (which `st_lsm6dsx_shub_probe()` skips) versus other negative errnos on bus failure. [F29]
- Any buffer passed to `iio_push_to_buffers_with_timestamp()` must be 8-byte aligned and at least `ST_LSM6DSX_IIO_BUFF_SIZE` (16) bytes long (using `hw->scan[id]` or `u8 iio_buff[ST_LSM6DSX_IIO_BUFF_SIZE] __aligned(8)`), never an unaligned offset into `hw->buff`. [F104]
- Internal ODR fields (`sensor->odr`, `sensor->ext_info.slv_odr`, `odr_avl[].milli_hz`) are in milli-Hz and must be converted at the `IIO_CHAN_INFO_SAMP_FREQ` ABI boundary using `*val = odr / 1000` and `*val2 = (odr % 1000) * 1000` (`IIO_VAL_INT_PLUS_MICRO`) on reads and `val = val * 1000 + val2 / 1000` on writes. [F109]
- `st_lsm6dsx_sw_trigger_handler_thread()` must always call `iio_trigger_notify_done(iio_dev->trig)` on every path before returning `IRQ_HANDLED`. [F111]

## Error Handling

- Callers of `st_lsm6dsx_sensor_set_enable()`, `st_lsm6dsx_device_set_enable()`, and `st_lsm6dsx_shub_read_output()` must check for a negative return value (`err < 0`) before proceeding or consuming the output buffer. [F26]

## External Contracts

- Primary IMU sensors (`ST_LSM6DSX_ID_ACC` and `ST_LSM6DSX_ID_GYRO`) report and accept `IIO_CHAN_INFO_SCALE` in nano-units (`IIO_VAL_INT_PLUS_NANO` and `"0.%09u"`), whereas external sensor-hub sensors (`st_lsm6dsx_shub.c`) use micro-units (`IIO_VAL_INT_PLUS_MICRO` and `"0.%06u "`). [F53]
- `st_lsm6dsx_irq_setup()` must map `IRQF_TRIGGER_LOW` and `IRQF_TRIGGER_FALLING` to `irq_active_low = true` in `hw->settings->irq_config.hla` (and `IRQF_TRIGGER_HIGH`/`IRQF_TRIGGER_RISING` to `false`, rejecting other modes with `-EINVAL`), and must OR `IRQF_SHARED` into `irq_type` when open-drain is enabled. [F91]

## Known Pitfalls

- Multi-byte sensor register values are little-endian and must use `le16_to_cpu()`, `le32_to_cpu()`, or `cpu_to_le16()`. In `st_lsm6dsx_read_oneshot()` and `st_lsm6dsx_shub_read_oneshot()`, `le16_to_cpu()` must be cast to `s16` before storing into `int *val`. [F49, F72]
- Pattern FIFO timestamps (`st_lsm6dsx_read_fifo()`) are 24-bit values split across `data[1] << 16 | data[0] << 8 | data[3]`, whereas tagged FIFO timestamps (`st_lsm6dsx_read_tagged_fifo()`) are 32-bit `__le32` integers after the tag byte. Both must compare the unscaled unsigned tick count in `s64 ts` against `0xff0000` or `0xffff0000` to set `reset_ts` before multiplying `ts` by `hw->ts_gain`. [F50, F70]
- In `st_lsm6dsx_read_fifo()`, the inner `while (acc_sip > 0 || gyro_sip > 0 || ext_sip > 0)` loop must only decrement `gyro_sip`, `acc_sip`, and `ext_sip` and increment `sip` in the second phase after the `if (ts_sip-- > 0)` timestamp read, keeping `sip` and `*_sip` unchanged during the initial channel `memcpy` phase. [F56]
- When writing the 3-byte `SLV0` configuration block at `slv0_addr` in `st_lsm6dsx_shub_read()` and `st_lsm6dsx_shub_check_wai()`, if `slv_addr + 2 == aux_sens->addr`, `config[2]` must OR in `ST_LSM6DSX_SHIFT_VAL(3, aux_sens->mask)` both when starting the read and when resetting `SLV0` so `aux_sens` is not overwritten. [F40]
- In `st_lsm6dsx_update_watermark()`, the loop over `hw->iio_devs[]` must use the `watermark` parameter when `cur_sensor == sensor` and `cur_sensor->watermark` otherwise. Updating `fifo_th.addr` must hold `hw->page_lock`, read `fifo_th.addr + 1` to preserve upper bits outside `fifo_th.mask`, and bulk-write the combined value as `__le16` (`cpu_to_le16()`). [F60, F97]
- In `st_lsm6dsx_core.c`, `dev_get_drvdata(dev)` on the bus `struct device` returns `struct st_lsm6dsx_hw *` (used by PM callbacks), whereas IIO sysfs `device_attribute` callbacks receive `&iio_dev->dev` and must use `iio_priv(dev_to_iio_dev(dev))` to obtain `struct st_lsm6dsx_sensor *`. [F77]
- In `st_lsm6dsx_reset_device()`, `st_lsm6dsx_flush_fifo(hw)` must be executed (ignoring `-ENOTSUPP`) before setting `hw->settings->reset` so interrupt line 1 is not asserted during hardware reset, which would switch I3C-capable chips into I3C-only mode. [F84]
- In `st_lsm6dsx_read_oneshot()`, after enabling the sensor, sleep for `usleep_range(3 * delay, 4 * delay)` (`delay = 1000000000 / sensor->odr`) before reading the output register. In `st_lsm6dsx_shub_wait_complete()`, the sleep timeout `2000000U / odr + 1` ms must be clamped to at least 10 ms via `max_t(u32, 2000000U / odr + 1, 10)`. [F94, F95]
