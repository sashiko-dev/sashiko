# INTEL DRM XE DRIVER (Lunar Lake and newer)

The Intel Xe DRM driver (`drivers/gpu/drm/xe`) manages Intel Xe-architecture GPUs (Lunar Lake and newer), implementing TTM buffer objects (`xe_bo`), GPU virtual memory (`xe_vm`, `xe_pt`, `drm_gpusvm`), Graphics Technology (`xe_gt`) and tile management, GuC/HuC/GSC firmware stacks, workload scheduling and LRC submission, SR-IOV PF/VF virtualization, power management, and OA/PMU/EU-stall telemetry.

## Architecture & Data Flow

- When `try_add_system()` builds placements for a BO with both `XE_BO_FLAG_SYSTEM` and `XE_BO_FLAG_VRAM_MASK`, `XE_PL_TT` must set `TTM_PL_FLAG_FALLBACK`; consequently, `xe_bo_validate()` must return 0 when `xe_bo_is_pinned(bo)` is true, and `xe_dma_buf_pin()` must pass `in_place = true` to `xe_bo_pin_external()` so validation does not migrate a pinned TT BO back to VRAM. [F58, F59]
- Device shrinker page counts in `xe->mem.shrinker` must be updated in lockstep via `xe_ttm_tt_account_add()` and `xe_ttm_tt_account_subtract()` under `xe_bo_lock()` whenever a mappable `ttm_tt` is populated, unpopulated, shrunken, pinned/unpinned while populated, or has `xe_tt->purgeable` mutated; in `xe_ttm_tt_populate()`, a backed-up `ttm_tt` is restored via `ttm_tt_restore()` only when `!xe_tt->purgeable`, otherwise `ttm_tt_clear_backed_up(tt)` must be called before allocating pages and `xe_tt->purgeable` reset to `false`. [F61, F68, F965, F995]
- On SR-IOV PF (`IS_SRIOV_PF(xe)`), `VFID = 0` (`PFID`) identifies the PF while VFs use 1-based `VFID(1..totalvfs)` across `xe->sriov.pf.vfs`, `gt->sriov.pf.vfs`, `xe_lmtt` (`lmtt->pd->entries[vfid]`), and GuC capture/SR-IOV ABIs; per-VF GGTT and LMEM allocations live only on `tile->primary_gt`, and provisioning or releasing `config->lmem_obj` on LMTT devices must update and invalidate all tiles' LMTTs via `pf_update_vf_lmtt()` or `pf_reset_vf_lmtt()` before freeing PT BOs. [F255, F256, F274, F468, F486, F863, F1009]
- `gt->sriov` is a union of `pf` and `vf` gated on `IS_SRIOV_PF(xe)` / `IS_SRIOV_VF(xe)` (after `xe_sriov_probe_early()`); on VFs, `xe_gt_mcr_*` accessors assert `!IS_SRIOV_VF`, `xe_guc_init()` skips `log`, `capture`, `ads`, `dbm`, `pc`, and `engine_activity` (leaving their BOs NULL), and PF-only sysfs/debugfs attributes and `skip_guc_pc` paths must be guarded accordingly. [F151, F252, F819, F1106, F1107, F1108, F1242]
- `rw_with_mcr_steering()` must keep `MCR_MULTICAST` set in `steer_reg` during MCR reads and restore `MCR_MULTICAST` after any unicast write so `xe_gt_mcr_multicast_write()` sees `MCR_MULTICAST` set under `mcr_lock(gt)`; in `apply_one_mmio()`, `reg.masked` registers set the upper 16-bit write mask via `entry->clr_bits << 16` without reading hardware, while non-masked `reg.mcr` registers must use `xe_gt_mcr_unicast_read_any()`/`xe_gt_mcr_multicast_write()`. [F347, F891, F911]
- `bind_op_prepare()` must set `BIT(tile->id)` in `vma->tile_staged`, `unbind_op_prepare()` must check `(vma->tile_present | vma->tile_staged) & BIT(tile->id)`, and `bind_op_commit()` must move `BIT(tile->id)` from `tile_staged` to `tile_present`; when zapping PTEs of a VMA or SVM range, `tile_invalidated` must be updated via `WRITE_ONCE`, and `DRM_GPUVA_OP_REMAP` handlers must check `op->remap.prev` and `op->remap.next` with independent `if` statements (never `else if`), inheriting `xe_vma_max_pte_size(old)` on split VMAs. [F837, F933, F1284, F1308, F1311, F1344]
- Under `ct->fast_lock`, `__g2h_reserve_space()`, `__g2h_release_space()`, and `guc_ct_change_state()` must keep `ct->ctbs.g2h.info.space`, `ct->g2h_outstanding`, and a runtime PM reference (`xe_pm_runtime_get_noresume()` when `g2h_outstanding` becomes non-zero, `xe_pm_runtime_put()` when it reaches zero) synchronized; every G2H event whose H2G sender reserved `g2h_len > 0` must release `len` dwords in `parse_g2h_event()` (or `g2h_fast_path()`), while unsolicited G2H events must not. [F1122, F1166]

## Synchronization

- Lock acquisition across VM, BO, and validation paths must follow the order `vm->lock` -> `xe_validation_device.lock` (`val->lock`) -> `drm_exec` (`dma_resv` / `xe_bo_lock`) -> `bo->ttm.bdev->lru_lock` / `vm->svm.gpusvm.notifier_lock` -> `vm->userptr.invalidated_lock`; `xe_gt_sriov_pf_master_mutex(gt)` nests outside `&ggtt->lock` and `dma_resv` locks, and `xe_validation_should_retry()` must call `drm_exec_fini(ctx->exec)` before unlocking/relocking `val->lock` and re-run `drm_exec_init(ctx->exec, ...)` even if relocking fails. [F382, F978, F979, F1258, F1279]
- In BO creation helpers that accept an optional `vm` whose reservation lock is held by the caller (`__xe_bo_create_locked()`, `xe_bo_create_user()`, and `xe_bo_create_pin_map_at_aligned()`), unlocking the BO on exit or error must use `xe_bo_unlock_vm_held(bo)` instead of `xe_bo_unlock(bo)` so the caller's VM `dma_resv` lock is preserved when `bo->vm` is non-NULL. [F4]
- When `xe_bo_init_locked()` creates a `ttm_bo_type_kernel` BO, or when `xe_bo_fault_migrate()` / `xe_bo_cpu_fault()` / `xe_bo_cpu_fault_fastpath()` migrates or populates a BO in the CPU fault path, the caller must wait for (or test in `no_wait_gpu` mode) `DMA_RESV_USAGE_KERNEL` fences on `bo->ttm.base.resv`, and `xe_bo_cpu_fault()` must return `VM_FAULT_RETRY` without calling `__xe_bo_cpu_fault()` whenever `retry_after_wait` is true. [F21, F22, F71]
- Because `xe_guc.submission_state.lock` (`idm_mutex`/`dbm_mutex`), `xe_guc_ct.lock`, `m->job_mutex` (held across arming/pushing jobs and updating `m->fence` on `m->q`), and `preempt_fence_work_func()`'s `dma_fence_begin_signalling()` scope are in the `fs_reclaim` / dma-fence signaling path, code holding them must never perform `GFP_KERNEL` allocations or wait for hardware responses; likewise, `xe_bo_move()`, `xe_bo_shrink()`, and callers holding `dma_resv` locks on D3Cold-capable devices must not call synchronous runtime PM resume (`xe_pm_runtime_get*()`), checking `xe_rpm_reclaim_safe(xe)` instead. [F183, F411, F604, F618, F745, F972, F1222, F1232]
- Spinlocks acquired in hardirq context—`xe_execlist_port.lock`, `gsc->lock`, `xe->irq.lock` (required by `gt_engine_identity()`, `csc_hw_error_handler()`, and `hw_error_source_handler()`), `ct->fast_lock` (required across `has_room()`, `h2g_write()`, and `__g2h_reserve_space()`), and `tlb_inval->pending_lock`—must be acquired with `spin_lock_irq()` or `spin_lock_irqsave()` in process, timer, or workqueue context, and `gtidle->lock` (`raw_spinlock_t`) must use `raw_spin_lock_irqsave()`. [F165, F233, F376, F528, F560, F1085, F1223, F1398]
- `xe_device_wmb(xe)` (which issues `wmb()` plus a root-tile MMIO write to `VF_CAP_REG` on `IS_DGFX(xe)`) must be called after CPU writes to device-visible memory before notifying hardware in `wq_item_append()` (before updating `wq_desc.tail`), `xe_migrate_update_pgtables_cpu()`, `gsccs_send_message()` (before `pxp_pkt_submit()`), and `h2g_write()` (before `desc_write(xe, h2g, tail, ...)`). [F180, F563, F619, F923, F1084]

## Object Lifetimes

- Because an `xe_bo`'s `drm_gem_object` refcount holds a `ttm_buffer_object` refcount dropped only in `xe_gem_object_free()`, TTM callbacks and shrinker/eviction paths must first verify `xe_bo_is_xe_bo(tbo)` and obtain a GEM refcount via `xe_bo_get_unless_zero()` before accessing `struct xe_bo` fields; dropping a BO reference in atomic or spinlock/reclaim-tainted context (such as `client->bos_lock` in `show_meminfo()`) must use `xe_bo_put_deferred()` + `xe_bo_put_commit()` or `xe_bo_put_async()`. [F2, F111, F132, F166]
- Before `xe_pt_commit_prepare_bind()`, `entries[i].pt_entries[j].pt` owns newly allocated child `xe_pt` subtrees and requires `xe_pt_cancel_bind()` on error, whereas `xe_pt_commit_prepare_bind()` moves new subtrees into `pt_dir->staging` and stores displaced live subtrees in `entries[i].pt_entries[j].pt` for `xe_pt_commit()` or reverse-order `xe_pt_abort_bind()`. [F772, F868]
- `xe_tlb_inval_fence_init()` acquires a `xe_pm_runtime_get_noresume()` reference that is only released by `xe_tlb_inval_fence_fini()` when the fence is signaled, so every initialized `xe_tlb_inval_fence` must be signaled on all paths (including backend issue failure or `xe_tlb_inval_reset()`); in `xe_tlb_inval_job_destroy()`, `job->fence` (`ifence`) must be freed with `kfree(ifence)` when `!job->fence_armed` and `dma_fence_put(job->fence)` when `job->fence_armed` is true. [F1251, F1252, F1316]
- When destroying a userptr VMA, `XE_VMA_DESTROYED` must be set under `xe_svm_notifier_lock` and `xe_userptr_destroy()` called under `vm->lock` in `xe_vma_destroy()`, while `xe_userptr_remove()` (`mmu_interval_notifier_remove()`) must wait until `xe_vma_destroy_late()` after the unbind fence signals; because `vma->destroy_cb` and `vma->destroy_work` share a union, `INIT_WORK(&vma->destroy_work, ...)` must not be called until `vma_destroy_cb()` runs. [F1271, F1375]

## API Contracts

- When calling `xe_force_wake_get()` with `XE_FORCEWAKE_ALL` (`BIT(XE_FW_DOMAIN_ID_COUNT)`), callers must verify full wake success via `xe_force_wake_ref_has_domain(fw_ref, XE_FORCEWAKE_ALL)` (not `!fw_ref`) and still pass `fw_ref` to `xe_force_wake_put()` on partial failure; `XE_FORCEWAKE_ALL` must be translated to `fw->initialized_domains` before `for_each_fw_domain_masked()` and must never be passed to `xe_force_wake_ref()` or `xe_force_wake_assert_held()`. [F43, F79, F98, F127]
- G2H event handlers invoked from `process_g2h_msg()` execute while `ct->lock` is already held and cannot reserve G2H CTB space; any H2G message sent from a G2H handler (such as in `deregister_exec_queue()`) must use `xe_guc_ct_send_g2h_handler()` after the triggering path (such as `disable_scheduling_deregister()`) pre-reserves G2H space for all resulting G2H events. [F552, F1086]
- `xe_bb_new()`, `xe_bb_ccs_new()`, `xe_bb_create_job()`, and `xe_bb_create_migration_job()` return `ERR_PTR` on failure (never `NULL`), and job creation does not take ownership of `bb`; callers must check `IS_ERR()` and always release `bb` via `xe_bb_free(bb, fence)`, passing `NULL` when aborting before `xe_sched_job_push()` and the armed job's fence after `xe_sched_job_push()` (while still calling `dma_fence_put(fence)` on their own reference). [F586, F959, F961, F981]
- `xe_pt_walk_range()` and `xe_pt_walk_shared()` take an exclusive upper address `end` (`last + 1`, such as `xe_vma_end(vma)`), whereas `xe_vma_create()`, `xe_range_fence_insert()`, `xe_range_fence_tree_first()`/`next()`, and `xe_vm_pgtable_update_ops` use an inclusive upper address `last` (`start + range - 1`); additionally, `xe_range_fence_insert()` consumes ownership of `@rfence` on every return path. [F777, F864, F1289]
- `xe_guc_ct_send_recv()` returns the response length in dwords when `response_buffer` is non-NULL or non-negative `GUC_HXG_RESPONSE_MSG_0_DATA0` when `response_buffer` is NULL (as in `xe_guc_ct_send_block()`, `xe_guc_mmio_send()`, and `xe_guc_mmio_send_recv()`, which also writes `VF_SW_FLAG_COUNT` dwords into any non-NULL `response_buf`); callers expecting no payload (such as `relay_send_transaction()`) must treat positive returns as `-EPROTO`. [F440, F1098, F1099, F1100]
- `xe_assert()`, `xe_tile_assert()`, and `xe_gt_assert()` compile out to `BUILD_BUG_ON_INVALID(condition)` when `CONFIG_DRM_XE_DEBUG` is disabled, so they must never be used as branch conditions, wrap expressions with side effects, or validate untrusted user ioctl arguments (which must use `XE_IOCTL_DBG()`). [F197, F1014]

## Error Handling

- Because consumers test struct BO and suballocator pointers (`ggtt->scratch`, `xe->psmi.capture_obj[id]`, `ct->bo`, `log->bo`, `ads->bo`, `pc->bo`, `guc->hwconfig.bo`, `cache->sam`, `buffer->metadata_bo`, `buffer->activity_bo`, `vm->pt_root[id]`, and `vm->scratch_pt[id][i]`) for `NULL` rather than `IS_ERR()`, initialization paths must check `IS_ERR()` on a local variable or reset the struct slot to `NULL` on failure. [F246, F590, F645, F1109, F1261]
- In `xe_vm_bind_ioctl()`, if `vm_bind_ioctl_ops_create()` returns `ERR_PTR` for `ops[i]`, `ops[i]` must be reset to `NULL` before `unwind_ops`; when `ops_execute()` returns `ERR_PTR(-ENODATA)` (no PT updates needed), `vm_bind_ioctl_ops_execute()` must still call `vm_bind_ioctl_ops_fini()`, and `xe_vm_bind_ioctl()` must skip `vm_bind_ioctl_ops_unwind()` (which unwinds in reverse order only when `err && err != -ENODATA`) and signal user fences via `vm_bind_ioctl_signal_fences()`. [F1264, F1288]

## External Contracts

- In `xe_query_ioctl()`, `xe_oa_user_extensions()`, `xe_oa_user_ext_set_property()`, `xe_hw_engine_lookup()`, `vm_bind_ioctl_check_args()`, and `xe_vm_madvise_ioctl()`, user-supplied table indices (`query->query`, `ext.name`, `ext.property`, `eci.engine_class`, `pat_index`, `args->type`) must be bounds-checked and wrapped in `array_index_nospec()` before indexing, and every `xe_query_funcs` handler must write the expected size and return 0 when `query->size == 0` or return `-EINVAL` when `query->size != size`. [F484, F766, F858, F940, F1333]

## Known Pitfalls

- Although `xe_bo_is_vram()` returns true for `XE_PL_STOLEN` on DGFX, `XE_PL_STOLEN` is not managed by `xe_ttm_vram_mgr`, so `mem_type_is_vram()` must exclude `XE_PL_STOLEN` and `xe_ttm_io_mem_pfn()` / `vram_region_gpu_offset()` must branch on `XE_PL_STOLEN` before calling `res_to_mem_region()`; also, `XE_PL_TT`'s `man->size` is in pages (requiring `<< PAGE_SHIFT` for bytes), whereas `XE_PL_VRAM*` managers store `man->size` in bytes. [F109, F944, F1379]
- 64-bit shift/division and unit mismatches: `num_pages`/`page_offset`, high dwords in `get_pagefault()` and `make_u64*()`, migration PDE slots, `2ULL << exponent`, and `1ull << walk->shifts[level]` / `va_bits` must cast to `u64` before shifting and use `div_u64()`/`div64_u64()`/`DIV_ROUND_UP_ULL()`/`mul_u64_u32_div()` instead of `/`; `xe_guc_relay_*`, `xe_guc_buf_reserve()`, `guc_ct_buffer_desc` (`head`/`tail`), `CTX_*` macros, `second_idx`, and `uc_css_header` `*_dw` fields are in dwords, whereas `xe_guc_buf_from_data()`, `guc_log_buffer_state`, `wqi_head`/`tail`, `iosys_map`, and `%*ph` widths are in bytes. [F123, F125, F316, F441, F516, F519, F700, F884, F984, F1007, F1012, F1103, F1144, F1174, F1176, F1198, F1362, F1376]
- Structs whose release callbacks or downcasts pass the first member pointer directly to `kfree()` or `container_of()` without offset adjustment—`struct xe_ttm_tt` (`ttm`), `struct xe_gpu_scheduler` (`base`), `struct kobj_eclass`/`kobj_gt`/`kobj_tile` (`base`), `struct xe_tlb_inval_fence` (`base`), and KUnit `xe_test_priv` containers (`base`)—must keep that base member at offset 0 (allocated with `kzalloc()`, never `devm_kzalloc()`, for sysfs kobjects), and 32-bit seqno/timestamp comparisons in `xe_hw_fence_signaled()`, `xe_sched_job_started()`/`completed()`, `gt_engine_identity()`, `xe_hwmon_energy_get()`, and `get_engine_active_ticks()` must use wrap-safe 32-bit modular arithmetic. [F131, F335, F509, F511, F512, F521, F540, F889, F1037, F1177, F1195, F1369, F1371]
