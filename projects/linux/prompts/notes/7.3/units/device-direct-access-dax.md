# DEVICE DIRECT ACCESS (DAX)

The DAX subsystem (`drivers/dax/`) provides direct byte-addressable access to persistent and differentiated memory ranges without using the page cache. It implements the `struct dax_device` pseudo-filesystem and block-device host registry (`super.c`), the `dax` bus and dynamic/static region partitioning framework (`bus.c`), endpoint drivers for `/dev/daxX.Y` character devices (`device.c`) and hotplugged System RAM (`kmem.c`), and provider bridge drivers for NVDIMM PMEM (`pmem.c`), CXL (`cxl.c`), and EFI/ACPI soft-reserved HMEM ranges (`hmem/`).

## Architecture & Data Flow

- In `dax_open()`, the opened character-device inode's `inode->i_mapping` and `filp->f_mapping` must be redirected to `dax_inode(dax_dev)->i_mapping` (with `host = dax_inode(dax_dev)`) so `unmap_mapping_range(inode->i_mapping, 0, 0, 1)` in `kill_dev_dax()` unmaps all active VMAs across all opened `/dev/daxX.Y` descriptors. [F62]
- When `dev_dax->align > PAGE_SIZE`, `dev_dax_probe()` sets `pgmap->vmemmap_shift = order_base_2(dev_dax->align >> PAGE_SHIFT)`, and `dax_set_mapping()` must check `if (dev_dax->pgmap->vmemmap_shift)` to limit `nr_pages` to `1` so `folio->mapping` and `folio->index` are only set on the compound head folio. [F61]
- When removing a full range in `dev_dax_shrink()`, `unregister_dax_mapping()` must run via `devm_release_action()` before `trim_dev_dax_range()` decrements `dev_dax->nr_range` and frees `dev_dax->ranges`, because `unregister_dax_mapping()` indexes `dev_dax->ranges[mapping->range_id]` and sets `mapping->range_id = -1`. [F50]
- Dynamic `dev_dax` range sizes and alignment changes (`size_store()`, `mapping_store()`, `dev_dax_resize()`, `dev_dax_validate_align()`) must satisfy `alloc_is_aligned()` (`max_t(unsigned long, dev_dax->align, memremap_compat_align())`), and `dev_dax->ranges` must stay ordered by increasing `pgoff`. In-place resizing via `adjust_dev_dax_range()` is only permitted on `dev_dax->ranges[dev_dax->nr_range - 1]` (`adjust_ok()`) and must update both the `dax_region->res` child via `adjust_resource()` and `dax_range->range.end` in lockstep. [F51, F151]
- In `dev_dax_resize()`, each `retry:` pass must re-read `first = region_res->child` and reset `rc = -ENOSPC`, and each sibling loop iteration must reset `alloc = 0` before checking inter-resource and tail gaps, breaking out to decrement `to_alloc` and jump to `retry:` after any single `alloc_dev_dax_range()` or `adjust_dev_dax_range()`. [F89]
- `__free_dev_dax_id()` must atomically under `dax_dev_rwsem` free `dev_dax->id` from `dax_region->ida`, drop `dax_region->kref` via `dax_region_put()`, and set `dev_dax->id = -1` so `dax_bus_probe()` rejects the invalidated device and `dev_dax_release()` (`free_dev_dax_id()`) does not double-free what `alloc_dev_dax_id()` acquired. It returns the previous ID (`>= 0`) when invalidating a dynamic ID and `-1` otherwise, so `delete_store()` must test `>= 0` (not `== 0`). [F45, F55]
- In `kill_dax()`, `dax_holder_notify_failure()` must be invoked while `DAXDEV_ALIVE` is still set and `holder_ops` is valid, and `dax_dev->holder_ops` and `dax_dev->holder_data` must only be cleared after `clear_bit(DAXDEV_ALIVE, &dax_dev->flags)` and `synchronize_srcu(&dax_srcu)` complete. [F65]
- On a dynamic `dax_region`, `create_store()` only assigns `dax_region->seed` if `NULL` while updating `dax_region->youngest`, `dax_bus_probe()` clears `seed` only after `dax_drv->probe()` succeeds, and `delete_store()` clears `seed` and `youngest` if they match `victim` before unregistering it. [F54]
- In `delete_store()`, the child returned by `device_find_child_by_name(dax_region->dev, buf)` is unconditionally downcast via `to_dev_dax(victim)`, requiring every direct child `struct device` under a dynamic `dax_region->dev` to be an embedded `dev_dax->dev`. [F107]

## Synchronization

- Whenever both `dax_region_rwsem` and `dax_dev_rwsem` are acquired, `dax_region_rwsem` must be acquired before `dax_dev_rwsem` (as in `size_store()`, `mapping_store()`, `align_store()`, and `unregister_dev_dax()` -> `put_device()` -> `dev_dax_release()` -> `free_dev_dax_id()`). Broken by: calling `get_dax_range()`, `unregister_dev_dax()`, or `dax_region_avail_size()` while holding `dax_dev_rwsem`. [F122]
- Every call to `dax_alive()`—including via `dax_direct_access()`, `dax_zero_page_range()`, `dax_copy_from_iter()`, `dax_copy_to_iter()`, and `check_vma()`—must run inside a `dax_read_lock()` / `dax_read_unlock()` (`dax_srcu`) critical section. Because `dax_mmap()` drops `dax_read_lock()` after `check_vma()`, every fault path (`__dev_dax_pte_fault()`, `__dev_dax_pmd_fault()`, `__dev_dax_pud_fault()`) must re-run `check_vma()` under `dax_read_lock()` before mapping pages. [F15, F19]
- `get_dax_range(dev)` returns a non-NULL `struct dev_dax_range *` with `dax_region_rwsem` held for write and releases the lock itself when returning `NULL`, so callers must call `put_dax_range()` if and only if `get_dax_range()` returned non-NULL. [F6]
- Mutations to `dax_region->res` and `dev_dax->ranges` (`alloc_dev_dax_range()`, `adjust_dev_dax_range()`, `trim_dev_dax_range()`, `devm_register_dax_mapping()`) must hold `dax_region_rwsem` for write, while `dax_region_avail_size()`, `seed_show()`, and `create_show()` must hold `dax_region_rwsem`. Kernel-initiated lifecycle paths (`devm_create_dev_dax()`, `unregister_dev_dax()`) must use uninterruptible `down_write(&dax_region_rwsem)` rather than `down_write_killable()`. [F23, F121]
- Callers of `dev_dax_size()` must hold `dax_dev_rwsem`—in read mode (`down_read_interruptible(&dax_dev_rwsem)`) for read-only inspection (`size_show()`, `dax_bus_probe()`) and in write mode when mutating `dev_dax` state (`size_store()`, `delete_store()`). [F24]
- In `delete_store()`, `device_lock(dev)` and `device_lock(victim)` must be held while checking `victim->driver` and `dev_dax_size(dev_dax)` and invalidating `dev_dax->id` under `dax_dev_rwsem`, and both `dax_dev_rwsem` and `device_lock(victim)` must be released before calling `devm_release_action(dev, unregister_dev_dax, victim)`. [F26]
- Accesses and updates to `dax_drv->ids` (`__dax_match_id()`, `dax_match_id()`, `do_id_store()`, `dax_driver_unregister()`) must hold `dax_bus_lock`, and `dax_bus_lock` must be released before calling `driver_attach()` or `driver_unregister()`. [F28]
- `walk_hmem_resources()` holds `hmem_resource_lock` across the entire loop invoking `walk_hmem_fn` (`hmem_register_device()`), so callbacks run in sleepable process context and must not call `hmem_register_resource()` or `walk_hmem_resources()`. [F136]

## Object Lifetimes

- `kill_dax()` must be called on a `struct dax_device` to clear `DAXDEV_ALIVE` and synchronize `dax_srcu` before the final reference is dropped via `put_dax()` (where `dax_destroy_inode()` asserts `!test_bit(DAXDEV_ALIVE, ...)`). `__devm_create_dev_dax()` must call `kill_dax(dax_dev)` before `device_add(&dev_dax->dev)` so unbound devices start dead, and `dev_dax_probe()` must call `run_dax(dax_dev)` only after `devm_memremap_pages()` and `cdev_add()` succeed, registering `dev_dax_kill` after `dev_dax_cdev_del`. [F5, F111]
- `kill_dev_dax()` must call `kill_dax(dax_dev)` before `unmap_mapping_range(inode->i_mapping, 0, 0, 1)`. On dynamic `dev_dax` devices (`!static_dev_dax(dev_dax)`), `dev_dax->pgmap` is `devm_kzalloc()`-allocated in `dev_dax_probe()` and must be cleared to `NULL` in `kill_dev_dax()`, whereas on static devices `dev_dax->pgmap` is `kmemdup()`-allocated in `__devm_create_dev_dax()` and freed in `dev_dax_release()`. [F21, F113]
- `struct dax_mapping` must reference its entry in `dev_dax->ranges` via the integer index `mapping->range_id` resolved under `dax_region_rwsem` in `get_dax_range()` rather than caching a `struct dev_dax_range *`, because `alloc_dev_dax_range()` reallocates `dev_dax->ranges` with `krealloc()` while `dax_mapping` devices remain registered. [F104]
- In `devm_register_dax_mapping()`, `dev->parent` (`&dev_dax->dev`) must be pinned with `get_device(dev->parent)` before `device_add()`, and `dax_mapping_release()` must drop that reference via `put_device(parent)` only after `ida_free(&dev_dax->ida, mapping->id)`. [F1]
- `unregister_dev_dax()` must call `device_del(dev)` to unbind endpoint drivers before calling `free_dev_dax_ranges(dev_dax)` to release the parent `dax_region` range resources. [F3]
- In `__devm_create_dev_dax()`, `dev_dax->dax_dev` and `dev->type = &dev_dax_type` must be assigned before `device_add(dev)`, and any failure at or after `device_add(dev)` must clean up via `kill_dev_dax(dev_dax)` and `put_device(dev)` (or `unregister_dev_dax`) rather than jumping to pre-registration `err_*` labels. [F14]
- Devres actions that unregister `dev_dax` devices (`unregister_dev_dax`) and `dax_mapping` children (`unregister_dax_mapping`) must be registered on `dax_region->dev` (not `&dev_dax->dev`). `alloc_dev_dax_range()` must skip `devm_register_dax_mapping()` when `!device_is_registered(&dev_dax->dev)`, deferring initial mapping registration in `__devm_create_dev_dax()` until after `device_add(&dev_dax->dev)` and `unregister_dev_dax` devres registration succeed. [F110, F114]
- In `dev_dax_kmem_remove()` and `dax_kmem_exit()`, if `remove_memory()` fails for any range (or `CONFIG_MEMORY_HOTREMOVE` is disabled), `any_hotremove_failed` must be set to `true` and the failed `data->res[i]`, `data->res_name`, `data->mgid`, node `memory_dev_type`, and module-global `kmem_name` must not be freed or unregistered. [F60]
- In `dax_fs_exit()`, `rcu_barrier()` must be called after `kern_unmount(dax_mnt)` and before `kmem_cache_destroy(dax_cache)` so all RCU-deferred `dax_free_inode` callbacks finish returning objects to `dax_cache`. [F13]
- In `__dax_pmem_probe()`, `pgmap` must be zero-initialized and `devm_namespace_enable()` checked before `nvdimm_setup_pfn()`; afterwards, the driver must call `devm_namespace_disable()`, convert little-endian `pfn_sb->dataoff` and `pfn_sb->align`, and reserve `[nsio->res.start, nsio->res.start + offset)` before creating the `dev_dax` device. [F46, F119]

## API Contracts

- `__dev_dax_pmd_fault()`, `__dev_dax_pud_fault()`, and `dax_set_mapping()` must compute page offset via `linear_page_index(vmf->vma, ALIGN_DOWN(vmf->address, fault_size))` (and pass `vmf` to `vmf_insert_folio_pmd()`/`pud()`) rather than `vmf->pgoff`. When `fault_size > dev_dax->align` (or `CONFIG_HAVE_ARCH_TRANSPARENT_HUGEPAGE_PUD` is disabled in `__dev_dax_pud_fault()`), the handler must return `VM_FAULT_FALLBACK`, whereas `fault_size < dev_dax->align` must return `VM_FAULT_SIGBUS`. [F47, F85]
- Public character-device inodes (such as in `dax_open()`) must be converted to `struct dax_device *` via `inode_dax()` (`container_of(inode->i_cdev, struct dax_device, cdev)`), whereas `to_dax_dev()` (`container_of(inode, struct dax_device, inode)`) must only be called on internal `dax_fs_type` inodes (`dax_inode()`). [F105]
- `alloc_dax_region()` returns `NULL` on failure whereas `devm_create_dev_dax()` returns an `ERR_PTR()`. `alloc_dax_region()` requires `dev_get_drvdata(parent)` to be `NULL` on entry and both `range->start` and `range_len(range)` to be aligned to `align`, setting `dev_set_drvdata(parent, dax_region)` before `sysfs_create_groups()` (`dax_region_attribute_groups`); `dax_region_unregister()` must remove those groups before dropping the region reference. [F31, F32, F109]
- In `__devm_create_dev_dax()`, static regions (`IORESOURCE_DAX_STATIC`) require `data->id >= 0` and may supply a pre-populated `data->pgmap`, whereas dynamic regions require `data->id < 0` and `data->pgmap == NULL`. Because `data->pgmap` is duplicated with `kmemdup(data->pgmap, sizeof(struct dev_pagemap), GFP_KERNEL)` (copying only one `struct range`), `dev_dax_probe()` rejects `static_dev_dax()` with `nr_range > 1`. [F102, F148]
- `dax_direct_access()` requires a signed `long` variable for its return value and treats `0` available pages from `dax_dev->ops->direct_access()` as `-ERANGE`, returning either a negative errno or a positive page count capped to `nr_pages`. [F36]
- `dax_copy_from_iter()` must use `_copy_from_iter_flushcache()` when `DAXDEV_NOCACHE` is set, `dax_copy_to_iter()` must use `_copy_mc_to_iter()` when `DAXDEV_NOMC` is set, and `dax_flush()` must call `arch_wb_cache_pmem()` when `dax_write_cache_enabled(dax_dev)` (`DAXDEV_WRITE_CACHE`) is true. Composite/stacked DAX drivers must query underlying devices with `dax_write_cache_enabled()` and propagate it via `dax_write_cache()`. [F64, F133]
- `dax_zero_page_range()` only accepts `nr_pages == 1` (rejecting any other count with `-EIO`) and must wrap `dax_dev->ops->zero_page_range()` in `dax_mem2blk_err()` so `-EHWPOISON` converts to `-EIO`. [F48]
- `alloc_dax()` must reject non-NULL `ops` with `ERR_PTR(-EOPNOTSUPP)` when `cpu_dcache_is_aliasing()` is true and with `ERR_PTR(-EINVAL)` when `!ops->zero_page_range`, while allowing `ops == NULL` for `device-dax` callers. [F117]
- `fs_dax_get_by_bdev()` requires `blk_queue_dax(bdev->bd_disk->queue)` to be true and both the partition's byte start offset and byte size to be `PAGE_SIZE`-aligned, returning `NULL` otherwise. [F139]
- `dax_bus_probe()` must reject `dev_dax` devices where `dev_dax_size(dev_dax) == 0` or `dev_dax->id < 0` with `-ENXIO`, and `delete_store()` must reject deleting static devices, driver-bound devices, non-zero-sized devices, or device ID 0 (`dev_dax->id <= 0`). [F118]
- Because `walk_hmem_resources()` aborts its loop as soon as `fn` returns non-zero, `hmem_register_device()` must return `0` when skipping a resource that is not `REGION_DISJOINT` from `IORES_DESC_CXL` or does not return `REGION_INTERSECTS` for `IORES_DESC_SOFT_RESERVED`. [F86]

## Error Handling

- Callers of `alloc_dax()` must check its return value with `IS_ERR()` before storing it into a device field or passing it to `kill_dax()` or `put_dax()`, because `alloc_dax()` returns an `ERR_PTR()` on failure while `kill_dax()` and `put_dax()` only guard against `NULL`. [F30]
- `dax_pgoff_to_phys()` returns `(phys_addr_t)-1` on failure (when `pgoff` or `size` falls outside any `dev_dax->ranges` entry), so callers must check `phys == -1` before passing `phys` to `PHYS_PFN()`. [F35]
- `dax_alloc_inode()` must NULL-check `alloc_inode_sb()` and initialize `inode->i_rdev = 0`, and `dax_free_inode()` must check `if (inode->i_rdev)` before freeing `iminor(inode)` from `dax_minor_ida`. [F40]

## Known Pitfalls

- In `dev_dax_probe()`, dynamic `dev_pagemap` allocation uses `struct_size(pgmap, ranges, dev_dax->nr_range - 1)` because `struct dev_pagemap` unions `range` with `ranges[]` (requiring `nr_range >= 1`), whereas `dev_dax_kmem_probe()` must pass `dev_dax->nr_range` to `struct_size(data, res, ...)` for `struct dax_kmem_data`. [F75]
- `dev_dax_resize()` and `dev_dax_shrink()` guard against unsigned underflow on `resource_size_t` by checking `size < dev_size` before computing `to_shrink = dev_dax_size(dev_dax) - size`, and clamping each reverse-loop step with `shrink = min_t(u64, to_shrink, range_len(range))` using a signed loop index `int i`. [F74]
- When `dev_dax_resize()` calculates free space in `dax_region->res`, the gap between sibling resources `res` and `next` is `next->start - (res->end + 1)` starting at `res->end + 1`, whereas the gap at the region tail is `region_res->end - res->end` because both `.end` fields are inclusive. [F99]
- In `dev_dax` sysfs store handlers (`size_store()`, `align_store()`), `!dax_region->dev->driver` must be checked under `dax_region_rwsem` (returning `-ENXIO` if the parent region is disabled) whereas `dev->driver` must be checked under `dax_dev_rwsem` (returning `-EBUSY` if the child `dev_dax` is bound); `align_store()` must also save and restore `dev_dax->align` if `dev_dax_validate_align()` fails. [F56, F94]
