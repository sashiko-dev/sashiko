# ROCKER DRIVER

The Rocker driver is a PCI switchdev network device driver for the QEMU-emulated Rocker Ethernet switch. It manages PCI BAR0 MMIO registers, MSI-X interrupts, and descriptor-based DMA rings (command, event, per-port TX, and per-port RX) formatted with 8-byte-aligned TLVs. It implements a pluggable world architecture providing an OF-DPA pipeline (`rocker_ofdpa.c`) that offloads L2 bridging, VLANs, FDB learning/ageing, and IPv4 FIB/ARP routing via netdevice, netevent, FIB, and switchdev notifiers.

## Architecture & Data Flow

- `struct ofdpa_flow_tbl_entry` and `struct ofdpa_fdb_tbl_entry` must be zero-allocated with `kzalloc` because `ofdpa_flow_tbl_add`, `ofdpa_flow_tbl_find`, `ofdpa_port_fdb`, and `ofdpa_fdb_tbl_find` compute `crc32` and `memcmp` over `key_len` or `sizeof(key)`, including padding and unused union tail bytes. For `ROCKER_OF_DPA_TABLE_ID_UNICAST_ROUTING`, `ofdpa_flow_tbl_ucast4_routing` must set `entry->key_len` to `offsetof(struct ofdpa_flow_tbl_key, ucast_routing.group_id)` so the action field `group_id` is excluded from key hashing. [F31, F62]
- In `ofdpa_port_vlan`, `change_bit(ntohs(internal_vlan_id), ofdpa_port->vlan_bitmap)` must run before `ofdpa_port_vlan_l2_groups` and `ofdpa_port_vlan_flood_group`, and be toggled back if `ofdpa_port_ctrl_vlan_add` or those group calls fail. Because the bit is already toggled, `ofdpa_port_vlan_l2_groups` must program the CPU port (`out_pport = 0`) L2 interface group only when `(adding && ref == 1)` or `(!adding && ref == 0)`. [F43, F68]
- In `ofdpa_port_bridge_join` and `ofdpa_port_bridge_leave`, `ofdpa_port_vlan_del(ofdpa_port, OFDPA_UNTAGGED_VID, 0)` must run before updating `ofdpa_port->internal_vlan_id` and `ofdpa_port->bridge_dev`, and `ofdpa_port_vlan_add(ofdpa_port, OFDPA_UNTAGGED_VID, 0)` must run after both fields are updated. [F44]
- A port's per-VLAN L2 interface group (`ROCKER_GROUP_L2_INTERFACE(vlan_id, ofdpa_port->pport)`) and learned FDB entries may exist only while `ofdpa_port->stp_state` is `BR_STATE_LEARNING` or `BR_STATE_FORWARDING`; `ofdpa_port_stp_update` must update `ofdpa_port->stp_state` before calling `ofdpa_port_fdb_flush` and `ofdpa_port_fwding`. [F45]
- When `ofdpa_flow_tbl_add` replaces an existing entry matched by `ofdpa_flow_tbl_find`, the replacement must preserve `found->cookie` and set `cmd` to `ROCKER_TLV_CMD_TYPE_OF_DPA_FLOW_MOD` rather than allocating from `ofdpa->flow_tbl_next_cookie` or sending `FLOW_ADD`. [F46]
- `struct ofdpa_group_tbl_entry` is discriminated by `ROCKER_GROUP_TYPE_GET(entry->group_id)`: only `ROCKER_OF_DPA_GROUP_TYPE_L2_FLOOD` and `ROCKER_OF_DPA_GROUP_TYPE_L2_MCAST` allocate `entry->group_ids` (freed in `ofdpa_group_tbl_entry_free`), while other group types use their union structs. [F33]
- The union in `struct rocker_fib_event_work` is discriminated by `fib_work->event`: `FIB_EVENT_ENTRY_REPLACE` and `FIB_EVENT_ENTRY_DEL` use `fib_work->fen_info` (`fen_info.fi`), whereas `FIB_EVENT_RULE_ADD` and `FIB_EVENT_RULE_DEL` use `fib_work->fr_info` (`fr_info.rule`). [F34]
- Before `rocker_dma_rx_ring_skb_alloc` allocates or maps an RX `sk_buff` (and in `rocker_dma_rx_ring_skb_map` on `tlv_put_failure`), `desc_info->tlv_size` must be set to `0` and the descriptor cookie to `NULL` so hardware skips the descriptor on error and `rocker_dma_rx_ring_skb_free` does not free a stale `sk_buff`. [F29]
- Pointer arithmetic on `struct rocker_tlv *` and descriptor buffers (`rocker_tlv_next`, `rocker_tlv_data`, `rocker_tlv_start`, `rocker_tlv_nest_end`, `rocker_tlv_nest_cancel`, `rocker_tlv_put`) must use `char *` and `ROCKER_TLV_ALIGN` (8-byte) offsets rather than `sizeof(struct rocker_tlv)` (6 bytes). `rocker_tlv_put` must store unpadded `rocker_tlv_attr_size(attrlen)` in `tlv->len` while advancing `desc_info->tlv_size` by `rocker_tlv_total_size(attrlen)` and zeroing `rocker_tlv_padlen(attrlen)` trailing bytes. [F57, F85]

## Synchronization

- Callers of `rocker_cmd_exec` (or OF-DPA helpers checking `ofdpa_flags_nowait`) in hardirq (`ofdpa_port_ev_mac_vlan_seen`), timer (`ofdpa_fdb_cleanup`), atomic neighbour (`ofdpa_port_neigh_update`, `ofdpa_port_neigh_destroy`), or spinlock (`ofdpa_port_fdb_flush`, `ofdpa_fib4_abort`) context must set `OFDPA_OP_FLAG_NOWAIT` (`nowait = true`). When `nowait == true`, `process` is never invoked and the command completes asynchronously after `rocker_cmd_exec` returns. [F87, F103]
- `rocker->cmd_ring_lock` is taken in hardirq handler `rocker_cmd_irq_handler` with `spin_lock`, so all non-hardirq acquisitions must use `spin_lock_irqsave`. In `rocker_cmd_exec`, reserving a descriptor (`rocker_desc_head_get`), initializing `rocker_wait` (`rocker_wait_init`, `wait->nowait`), running `prepare`, and publishing (`rocker_desc_head_set`) all execute under `cmd_ring_lock` with IRQs disabled; `prepare` must not sleep or re-enter `rocker_cmd_exec`, and `wait->nowait` must be set before `rocker_desc_head_set`. [F13, F105]
- `ofdpa->fdb_tbl_lock` and `ofdpa->flow_tbl_lock` must always be acquired with `spin_lock_irqsave`, and when nested (`ofdpa_port_fdb_flush`, `ofdpa_fdb_cleanup`), `fdb_tbl_lock` must be acquired outer to `flow_tbl_lock`. [F19]
- In `ofdpa_port_ipv4_neigh` and `ofdpa_port_ipv4_nh`, any fields needed from an existing `ofdpa_neigh_tbl_entry` (`found->index`, `found->eth_dst`, `found->ttl_check`) after releasing `ofdpa->neigh_tbl_lock` must be copied out while holding `neigh_tbl_lock` before calling `ofdpa_neigh_del(found)` or unlocking. [F22]
- Work items on `rocker->rocker_owq` (`rocker_router_fib_event_work`, `rocker_switchdev_event_work`) acquire `rtnl_lock()`, so `ofdpa_fini`, `rocker_world_fini`, `flush_workqueue(rocker->rocker_owq)`, and `destroy_workqueue(rocker->rocker_owq)` must never be called while holding `rtnl_lock()`. [F109]
- When publishing or returning a reusable descriptor on `tx_ring`, `rx_ring`, or `event_ring`, `rocker_desc_gen_clear` must clear `ROCKER_DMA_DESC_COMP_ERR_GEN` before `rocker_desc_head_set` advances `head`. In consumer loops (`rocker_event_irq_handler`, `rocker_port_poll_rx`), every descriptor from `rocker_desc_tail_get` must have `rocker_desc_gen_clear`, `rocker_desc_head_set`, and `credits++` executed even when `rocker_desc_err` or processing fails. [F14, F75]
- In `ofdpa_port_internal_vlan_id_get` and `ofdpa_port_internal_vlan_id_put`, `ofdpa->internal_vlan_tbl_lock` must be held with `spin_lock_irqsave` across the `internal_vlan_tbl` lookup, `ref_count` update, and bit allocation or clearing in `ofdpa->internal_vlan_bitmap`. [F23]

## Object Lifetimes

- `ofdpa_flow_tbl_do()`, `ofdpa_flow_tbl_add()`, and `ofdpa_flow_tbl_del()` unconditionally consume the caller-allocated `struct ofdpa_flow_tbl_entry *` (inserting it into `ofdpa->flow_tbl` or freeing it with `kfree()`), so callers must never free or dereference `entry` after the call even if `rocker_cmd_exec()` fails. [F1]
- In `rocker_router_fib_event` and `rocker_switchdev_event` (called under `rcu_read_lock`), transient notifier payloads must be copied and referenced objects pinned (`fib_info_hold`, `fib_rule_get`, `dev_hold`, and a `GFP_ATOMIC` copy of `fdb_info->addr`) before queueing work on `rocker_owq`, and released in the worker. [F21]
- In `rocker_port_xmit()`, if `rocker_desc_head_get()` returns `NULL`, return `NETDEV_TX_BUSY` without freeing `skb`. Any failure after acquiring `desc_info` must unmap mapped fragments via `rocker_tx_desc_frags_unmap()`, cancel open TLV nests via `rocker_tlv_nest_cancel()`, call `dev_kfree_skb(skb)`, and return `NETDEV_TX_OK` without advancing `tx_ring` head. [F9, F28]
- In `rocker_probe()`, `rocker_dma_rings_init()`, `request_irq()` for `ROCKER_MSIX_VEC_CMD`, and allocating `rocker->rocker_owq` must precede `rocker_probe_ports()`, which must precede registering `rocker->fib_nb`, `rocker_switchdev_notifier`, and `rocker_switchdev_blocking_notifier`. In `rocker_remove()` and `ofdpa_fini()`, notifiers must be unregistered and `timer_delete_sync(&ofdpa->fdb_cleanup_timer)` plus `rocker_remove_ports()` (which calls `ofdpa_fini()` to flush `rocker_owq`) must complete before `destroy_workqueue(rocker->rocker_owq)`, freeing command/event IRQs, and `rocker_dma_rings_fini()`. [F10, F90, F91, F92]
- In `rocker_probe_port()`, `rocker_world_port_pre_init()` must allocate `rocker_port->wpriv` before `rocker->ports[port_number]` is assigned and before `register_netdev()`, while `rocker_world_port_init()` must run after `register_netdev()` (as `ofdpa_port_init()` needs `dev->ifindex`). On `err_world_port_init`, `rocker->ports[port_number]` must be reset to `NULL` before `unregister_netdev(dev)` and `free_netdev(dev)` so `rocker_remove_ports()` does not double-free `dev`; callers of `ofdpa_port_get` iterating `port_count` must check for `NULL`. [F7, F15, F93]
- In `rocker_port_open()`, `rocker_port_dma_rings_init()`, TX/RX `request_irq()`, `rocker_world_port_open()`, and `napi_enable()` must precede `rocker_port_set_enable(rocker_port, true)` and `netif_start_queue()`, and `rocker_port_stop()` must tear them down in reverse order. Per-port TX/RX DMA rings and IRQs (and `ROCKER_MSIX_VEC_TEST` in `rocker_basic_hw_test()`) are scoped to `ndo_open`/`ndo_stop` or the test frame and must not use `devm_*` or `dmam_*`. [F94, F95]

## API Contracts

- Callers of `rocker_tlv_parse`, `rocker_tlv_parse_nested`, and `rocker_tlv_parse_desc` must pass a `tb` array of at least `maxtype + 1` elements (`attrs[ROCKER_TLV_*_MAX + 1]`) and check `tb[attr]` for non-`NULL` before passing it to `rocker_tlv_get_*`, `rocker_tlv_data`, `rocker_tlv_len`, or `rocker_tlv_parse_nested`. In `ofdpa_cmd_group_tbl_add_group_ids`, nested `ROCKER_TLV_OF_DPA_GROUP_IDS` entries must use 1-based attribute types (`i + 1`) because `rocker_tlv_parse` requires `type > 0`. [F30, F38, F55]
- `rocker_port->port_number` is 0-based (`0 .. rocker->port_count - 1`) for indexing `rocker->ports[]`, `ROCKER_MSIX_VEC_TX`/`RX`, and `ROCKER_DMA_TX`/`RX`, whereas `rocker_port->pport` is 1-based (`port_number + 1`) for hardware TLVs, OF-DPA group/flow ports, and `PORT_PHYS_ENABLE`/`PORT_PHYS_LINK_STATUS` bit shifts. Event handlers decoding a 1-based TLV port (`rocker_event_link_change`, `rocker_event_mac_vlan_seen`) must subtract 1 into an `unsigned int port_number` and verify `port_number < rocker->port_count` before indexing `rocker->ports[port_number]`. [F37, F54]
- `ROCKER_GROUP_L2_INTERFACE`, `ROCKER_GROUP_L2_MCAST`, and `ROCKER_GROUP_L2_FLOOD` call `ntohs(vlan_id)` internally and require a network-byte-order `__be16 vlan_id`, whereas `ROCKER_GROUP_VLAN_SET` requires host byte order. Bit operations on `ofdpa_port->vlan_bitmap` must use host-byte-order `ntohs(vlan_id)` (`0..4095`), whereas `ofdpa->internal_vlan_bitmap` must use the 0-based offset `ntohs(vlan_id) - OFDPA_INTERNAL_VLAN_ID_BASE` (`0..254`). [F39, F89]
- Stack-allocated `struct switchdev_notifier_fdb_info` structures passed to `call_switchdev_notifiers` in `rocker_fdb_offload_notify` and `ofdpa_port_fdb_learn_work` must be zero-initialized (`= {}`) so unpopulated flags like `is_local` are not stack garbage. [F27]
- Notifiers and device-walk callbacks receiving an arbitrary `struct net_device *` must verify `rocker_port_dev_check(dev)` (or `rocker_port_dev_check_under(dev, rocker)`) before downcasting `netdev_priv(dev)` to `struct rocker_port *`. [F86]
- In `ofdpa_fib4_add` and `ofdpa_fib4_del`, host-byte-order `fen_info->dst` must be converted via `htonl(fen_info->dst)` before passing to `ofdpa_port_fib_ipv4`. In `ofdpa_port_attr_bridge_ageing_time_set`, `ageing_time` must be converted via `clock_t_to_jiffies(ageing_time)` before storing into `ofdpa_port->ageing_time` or comparing against `ofdpa->ageing_time`. [F40, F41]

## Error Handling

- In `rocker_switchdev_event` and `rocker_router_fib_event`, because `queue_work()` runs unconditionally after `switch (event)`, any branch inside the switch that rejects or ignores an event must `kfree` the allocated work item and `return` directly rather than using `break`. [F69]
- In `ofdpa_port_ipv4_resolve`, a `neigh_create` failure returns an error pointer that must be checked with `IS_ERR(n)` and converted to a negative errno via `PTR_ERR(n)` rather than returning `IS_ERR(n)`. [F25]
- All ports on a `struct rocker` instance must share the same mode; in `rocker_world_check_init`, when `rocker->wops` is already set and `rocker->wops->mode != mode`, return an explicit `-EINVAL` rather than `err` (which holds `0` from `rocker_cmd_get_port_settings_mode`). [F26, F97]

## External Contracts

- 64-bit MMIO registers (`TEST_REG64`, `TEST_DMA_ADDR`, `DMA_DESC_ADDR`, `PORT_PHYS_LINK_STATUS`, `PORT_PHYS_ENABLE`, `SWITCH_ID`) must use `rocker_read64`/`rocker_write64`, whereas 32-bit registers use `rocker_read32`/`rocker_write32`. In `rocker_port_set_enable` and `rocker_carrier_init`, bitmasks for `PORT_PHYS_ENABLE` and `PORT_PHYS_LINK_STATUS` must shift a 64-bit constant (`1ULL << rocker_port->pport`, up to `ROCKER_FP_PORTS_MAX` = 62), and `rocker_port_set_enable` must read-modify-write `PORT_PHYS_ENABLE` so sibling ports' bits are preserved. [F50, F77, F100]
- In `rocker_switchdev_event_work`, `SWITCHDEV_FDB_ADD_TO_DEVICE` and `SWITCHDEV_FDB_DEL_TO_DEVICE` must ignore entries where `!fdb_info->added_by_user || fdb_info->is_local`, and a successful `rocker_world_port_fdb_add` must call `rocker_fdb_offload_notify` (`SWITCHDEV_FDB_OFFLOADED`) under `rtnl_lock()`. In `ofdpa_port_fdb_learn` and `ofdpa_port_fdb_learn_work`, internal VLAN IDs (`0x0f00..0x0ffe`) must be translated back to VID `0` via `ofdpa_port_vlan_to_vid` and `call_switchdev_notifiers` invoked under `rtnl_lock()`. [F123, F126]

## Known Pitfalls

- `struct fib_info` must be stored and passed by pointer (`fen_info.fi` and `ofdpa_flow_tbl_entry.fi`) rather than copied by value across FIB notifier work items and OF-DPA flow entries so that `fib_info_nh(fi, 0)` can access its trailing `fib_nh[]` flexible array. [F82]
- In `ofdpa_port_ipv4_neigh` and `ofdpa_port_ipv4_nh`, `updating` (`found && adding`) and `removing` (`found && !adding`) must be evaluated before `adding` is overwritten with `!found && adding`, because `if (!adding) kfree(entry)` later relies on the updated `adding` flag to decide whether `entry` was inserted into `ofdpa->neigh_tbl` or must be freed. [F66]
- In `ofdpa_port_fdb`, the post-unlock check `if (!found == removing)` handles both adding an existing entry (`found && !removing`) and removing a missing entry (`!found && removing`) by freeing the unused `fdb` allocation and setting `OFDPA_OP_FLAG_REFRESH` when refreshing an existing entry. [F67]
- In `rocker_port_attr_set`, each `case` in `switch (attr->id)` must end with `break` so pre-validation in `SWITCHDEV_ATTR_ID_PORT_PRE_BRIDGE_FLAGS` does not fall through into `SWITCHDEV_ATTR_ID_PORT_BRIDGE_FLAGS`. [F70]
