# DRM DRIVER FOR FIRMWARE FRAMEBUFFERS

This component provides system framebuffer platform device registration (`sysfb`), aperture ownership management for hand-off between generic boot framebuffer drivers and native GPU drivers (`aperture`), the `nomodeset` kernel parameter helper, and a shared DRM modesetting helper library (`drm_sysfb`) with four firmware/boot framebuffer DRM drivers (`simpledrm`, `efidrm`, `vesadrm`, and `ofdrm`).

## Architecture & Data Flow

- In `efidrm_device_create()`, `vesadrm_device_create()`, `simpledrm_device_create()`, and `ofdrm_device_create()`, `sysfb->fb_format` must be initialized before `drm_mode_config_reset(dev)`, which in turn must be called before `drm_dev_register()`. [F21]
- In `sysfb_create_simplefb()`, `efidrm_device_create()`, and `vesadrm_device_create()`, resource creation, `devm_aperture_acquire_for_platform_device()`, and `devm_request_mem_region()` for `screen_info` framebuffers must use the page-aligned visible scanout size (`PAGE_ALIGN(height * stride)`) after verifying it does not exceed advertised VRAM size, rather than `resource_size(res)` or `si->lfb_size`. [F56]
- In `simpledrm_device_init_clocks()`, `simpledrm_device_init_regulators()`, and `simpledrm_device_create()`, when `dev_get_platdata(&pdev->dev)` is non-NULL, the driver must use `struct simplefb_platform_data` and skip parsing `pdev->dev.of_node` properties, clocks, and regulators. [F105]
- Because `vesadrm_primary_plane_helper_atomic_check()` switches `new_sysfb_crtc_state->format` between `DRM_FORMAT_C8` and `DRM_FORMAT_RGB332` when emulating `DRM_FORMAT_XRGB8888` on a `DRM_FORMAT_C8` framebuffer (and restores `sysfb->fb_format` when switching back), `vesadrm_fill_palette_lut()` and `vesadrm_crtc_helper_atomic_flush()` must handle both formats. [F73]
- In `ofdrm_device_fill_gamma()` and `ofdrm_device_load_gamma()`, format switches must cover both little-endian and big-endian format codes produced by `display_get_validated_format()` (`DRM_FORMAT_RGB565 | DRM_FORMAT_BIG_ENDIAN` and `DRM_FORMAT_BGRX8888` in addition to `DRM_FORMAT_RGB565` and `DRM_FORMAT_XRGB8888`). [F72]
- In `ofdrm.c`, `sysfb->fb_gamma_lut_size` and `drm_crtc_enable_color_mgmt()` must only be enabled when `odev->cmap_base` is non-NULL, and every `struct ofdrm_device_funcs` with `.cmap_ioremap` must also set `.cmap_write` because `ofdrm_set_gamma_lut()` unconditionally invokes `odev->funcs->cmap_write`. [F51]
- In `ofdrm.c`, `get_cmap_address_of()` must verify `(offset + size) < max_size` against the BAR size returned by `of_get_pci_address()` or `of_get_address()` before translating the address and calling `devm_ioremap(dev->dev, address + offset, size)`. [F62]
- In `ofdrm.c`, `ofdrm_rage_m3a_cmap_write()` and `ofdrm_rage_m3b_cmap_write()` share palette registers at `cmap_base + 0xb0`/`0xb4` and must read-modify-write bit `0x20` (`PALETTE_ACCESS_CNTL`) in `DAC_CNTL` (`cmap_base + 0x58`) before writing `addr` and `data` to select Head A or Head B without clobbering other `DAC_CNTL` bits. [F50]
- `drm_sysfb_get_validated_int()` must clamp its `u32 max` bound with `min(max, INT_MAX)` when validating `u64 value` before returning `int`. [F79]

## Synchronization

- In `aperture_detach_devices()`, `ap->dev` must be sampled and set to `NULL` and `ap->lh` removed via `list_del(&ap->lh)` before calling `ap->detach(dev)` under `apertures_lock`, so the synchronous `devm_aperture_acquire_release()` callback sees `!ap->dev` and returns early without deadlocking on `apertures_lock` or double-deleting `ap->lh`. [F45]
- In `devm_aperture_acquire()`, `apertures_lock` must be held continuously across the `overlap()` scan over `apertures` and the `list_add(&ap->lh, &apertures)` insertion, and released before calling `devm_add_action_or_reset()`. [F16]
- In `sysfb.c`, `disable_lock` must be held across checking `disabled` and registering `pd` in `sysfb_init()`, and across `sysfb_unregister()` (which clears `pd = NULL`) and setting `disabled = true` in `sysfb_disable()`; `aperture_remove_conflicting_devices()` and `aperture_remove_conflicting_pci_devices()` must call `sysfb_disable()` unconditionally (never under `CONFIG_FB` or `apertures_lock`) before `aperture_detach_devices()`. [F17, F18, F48]

## Object Lifetimes

- All four `drm_sysfb` platform drivers (`efidrm`, `ofdrm`, `simpledrm`, `vesadrm`) must call `drm_dev_unplug()` (not `drm_dev_unregister()`) in their `.remove` callback, and `drm_sysfb_plane_helper_atomic_update()` and `drm_sysfb_plane_helper_atomic_disable()` must guard `sysfb->fb_addr` accesses with `drm_dev_enter()` and `drm_dev_exit()`. [F98]
- In `efidrm_device_create()` and `vesadrm_device_create()`, `drm_sysfb_get_memory_si()` returns the caller's stack-allocated `resbuf` (which `mem` also aliases when `devm_request_mem_region()` fails), so neither `res` nor `mem` may be stored past `*_device_create()`. [F87]
- In `ofdrm.c`, `display_get_edid_of()` reads the Device Tree `EDID` property into its `u8 buf[EDID_LENGTH]` parameter and returns `buf` directly to be stored in `sysfb->edid`, so callers must pass a device-lifetime buffer (`odev->edid`) rather than a stack buffer. [F88]
- In `ofdrm_device_init_pci()`, the `struct pci_dev *pcidev` from `display_get_pci_dev_of()` must never be managed with `pcim_*` or `devm_*` helpers on `pcidev`; `pci_disable_device(pcidev)` must instead be registered on `&pdev->dev` via `devm_add_action_or_reset(&pdev->dev, ofdrm_pci_release, pcidev)`. [F99]
- In `simpledrm_device_create()`, `devm_drm_dev_alloc()` must precede `simpledrm_device_init_clocks()` and `simpledrm_device_init_regulators()` so their `devm_add_action_or_reset()` release callbacks run before `drmm_kzalloc()` frees `sdev->clks` and `sdev->regulators` on final `drm_device` release. [F108]
- In `simpledrm_device_attach_genpd()` and `simpledrm_device_detach_genpd()`, `sdev->pwr_dom_count <= 1` must be an early-return no-op; for `pwr_dom_count > 1`, `simpledrm_device_detach_genpd()` must call `device_link_del(sdev->pwr_dom_links[i])` before `dev_pm_domain_detach(sdev->pwr_dom_devs[i], true)` in reverse order (`while (i) { --i; ... }`). [F59, F107]
- In `sysfb_parent_dev()`, when `screen_info_pci_dev(si)` returns a non-NULL `struct pci_dev *pdev`, `sysfb_pci_dev_is_enabled(pdev)` must verify that `PCI_COMMAND_MEMORY` is set in `PCI_COMMAND` and, if not, call `pci_dev_put(pdev)` and return `ERR_PTR(-ENODEV)`. [F93]
- `sysfb_init()` must be registered at `device_initcall` level (or later) so it executes after the PCI subsystem is initialized and EFI quirks and `screen_info_pci_dev()` can resolve the parent PCI device. [F92]
- In `drm_sysfb_crtc_reset()` and `drm_sysfb_crtc_atomic_destroy_state()`, `struct drm_sysfb_crtc_state` instances (including prior `crtc->state` in `drm_sysfb_crtc_reset()`) must be torn down via `drm_sysfb_crtc_state_destroy()`, which calls `__drm_atomic_helper_crtc_destroy_state(&sysfb_crtc_state->base)` before `kfree(sysfb_crtc_state)`. [F8]
- In `drm_sysfb_connector_helper_get_modes()`, the `struct drm_edid *` returned by `drm_edid_read_custom()` must be freed with `drm_edid_free(drm_edid)` after `drm_edid_connector_update(connector, drm_edid)`. [F9]
- In `ofdrm.c` and `simpledrm.c`, every Device Tree node reference acquired via `of_get_parent()` (in `display_get_model_of()` and `ofdrm_avivo_cmap_ioremap()`) or `of_parse_phandle()` (for `"panel"` in `simpledrm_device_create()`) must be released with `of_node_put()` before returning. [F103]

## API Contracts

- `drm_sysfb_plane_helper_get_scanout_buffer()` runs from the `drm_panic` handler in atomic/panic context with `dev->mode_config.panic_lock` held; it must only copy pre-computed scanout metadata from `struct drm_sysfb_device` into `struct drm_scanout_buffer` without sleeping, allocating memory, or taking sleeping locks. [F115]
- `drm_sysfb_get_format_si()` (and `efidrm_get_format_si()`, `vesadrm_get_format_si()`) returns `NULL` on failure, whereas `simplefb_get_validated_format()` (`simplefb_get_format_pd()`, `simplefb_get_format_of()`) and `display_get_validated_format()` return an `ERR_PTR` and never `NULL`. [F27]
- `drm_sysfb_get_validated_int()` and `drm_sysfb_get_validated_int0()` (and their `*_si`, `*_pd`, and `*_of` wrappers) return negative errno values on failure; callers must store results in signed `int` variables and check `< 0` before assigning to unsigned fields like `sysfb->fb_pitch`. [F26]
- In `simpledrm.c` and `ofdrm.c`, framebuffer `stride` / `linebytes` must be validated with `drm_sysfb_get_validated_int()` (allowing 0) and defaulted to `drm_format_info_min_pitch(format, 0, width)` when 0, whereas `width`, `height`, and `depth` must be validated with `drm_sysfb_get_validated_int0()`. [F57]
- `drm_sysfb_get_stride_si()` must compute maximum stride with `div64_u64(size, height)` (not `size / height` on `u64 size`), and callers must first validate `height` with `drm_sysfb_get_height_si()` so `height` is strictly positive. [F78]
- `efidrm`, `vesadrm`, and `ofdrm` store `struct drm_device *` (`&sysfb->dev`) in platform drvdata via `platform_set_drvdata(pdev, dev)`, whereas `simpledrm` stores `struct simpledrm_device *` (`sdev`), and each driver's `.remove` callback must cast `platform_get_drvdata(pdev)` to that exact type. [F40]
- In `simpledrm.c`, `devm_add_action_or_reset()` is registered with `sdev` (`struct simpledrm_device *`), so `simpledrm_device_release_clocks`, `simpledrm_device_release_regulators`, and `simpledrm_device_detach_genpd` must cast `void *res` directly to `struct simpledrm_device *` (not `struct drm_device *`). [F80]
- While `vesadrm`'s `vesa->cmap_write` takes 16-bit color values (`u16 red, u16 green, u16 blue`) and shifts them right by 8 internally, `ofdrm`'s `odev->funcs->cmap_write` takes 8-bit values (`unsigned char r, unsigned char g, unsigned char b`) already shifted right by 8 in `ofdrm_set_gamma_lut()`. [F37]
- When `simpledrm_device_create()` probes via `of_node`, it must check `simplefb_get_memory_of()` (`"memory-region"`) before falling back to `platform_get_resource(pdev, IORESOURCE_MEM, 0)`, using `devm_memremap()` with `iosys_map_set_vaddr()` for `"memory-region"` and `devm_ioremap_wc()` with `iosys_map_set_vaddr_iomem()` for `IORESOURCE_MEM`. [F104]
- Drivers using `drm_sysfb_build_fourcc_list()` must size their `formats` array with `DRM_SYSFB_PLANE_NFORMATS(num_native)` (which adds 1 for emulated `DRM_FORMAT_XRGB8888`) and pass the returned count `nformats` (not `ARRAY_SIZE()`) to `drm_universal_plane_init()`. [F55]
- The `drm_sysfb_get_*_si` helpers in `drm_sysfb_screen_info.c` are compiled and declared only when `CONFIG_SCREEN_INFO` is enabled, so any caller must depend on or select `SCREEN_INFO` (or `SYSFB`). [F127]

## Error Handling

- `simplefb_get_memory_of()` has a tri-state return: `NULL` when no `"memory-region"` property is present (requiring fallback to `IORESOURCE_MEM`), `ERR_PTR(-ENOMEM)` on allocation failure (which must abort probe via `IS_ERR(mem)`), or a valid `struct resource *`; `mem` in `simpledrm_device_create()` must be initialized to `NULL` for the `pd` path. [F28]
- In `efidrm_device_create()`, `vesadrm_device_create()`, and `simpledrm_device_create()`, a `NULL` return from `devm_request_mem_region()` must not fail probe and must fall back to `mem = res` so `mem->start` and `resource_size(mem)` remain valid for mapping. [F35]
- In `simpledrm_device_init_clocks()`, `simpledrm_device_init_regulators()`, and `simpledrm_device_attach_genpd()`, only `-EPROBE_DEFER` unwinds (`while (i) { --i; ... }`) and aborts probe; other errors must log a message, release any unenabled handle (`clk_put()`, `regulator_put()`), and continue without storing `ERR_PTR` into `sdev->clks` (leaving `NULL` entries in `0..clk_count-1`, guarded by `if (sdev->clks[i])` on release) or `sdev->regulators` (compacted via `sdev->regulators[i++]` into `sdev->regulator_count`), while `simpledrm_device_detach_genpd()` must guard `dev_pm_domain_detach()` with `!IS_ERR_OR_NULL(sdev->pwr_dom_devs[i])` because `dev_pm_domain_attach_by_id()` stores `ERR_PTR` directly in `sdev->pwr_dom_devs[i]`. [F38, F39, F69, F106]
- All `ofdrm_device_funcs.cmap_ioremap` implementations and `get_cmap_address_of()` return `IOMEM_ERR_PTR(...)` on failure rather than `NULL`, and `ofdrm_device_create()` must check `IS_ERR(cmap_base)` on a local variable before assigning `odev->cmap_base` so `odev->cmap_base` stays `NULL` on failure. [F36]
- In `vesadrm_device_create()`, `__screen_info_vesapm_info_base(si)` must be checked for non-zero before calling `phys_to_virt(pmi_base)` and assigning `vesa->cmap_write = vesadrm_pmi_cmap_write`, and `sysfb->fb_gamma_lut_size` must only be set when `vesa->cmap_write` is non-NULL. [F33]
- In `vesadrm` and `ofdrm` atomic commit paths, internal driver invariants (such as LUT `index != (index & 0xff)` or missing `crtc->state` in `drm_sysfb_crtc_atomic_duplicate_state`) use `drm_WARN_ON_ONCE` / `drm_WARN_ON`, whereas unsupported LUT pixel formats use `drm_warn_once` and invalid UAPI `gamma_lut->length` uses `drm_dbg`. [F133]

## External Contracts

- In `__aperture_remove_legacy_vga_devices()` and `aperture_remove_conflicting_pci_devices()`, conflicting graphics devices and the `VGA_FB_PHYS_BASE` aperture must be detached via `aperture_detach_devices()` before calling `vga_remove_vgacon(pdev)`. [F22]
- Platform devices created for `screen_info` in `sysfb_init()` and `sysfb_create_simplefb()` must be allocated with `platform_device_alloc(..., 0)` so device ID `0` is reserved for `sysfb` while other OF/DT parsers start at offset `1`. [F94]
- In `drm_sysfb_get_edid_block()`, `sysfb->edid` holds only a single `EDID_LENGTH` (128-byte) base block; after verifying `block * EDID_LENGTH + len <= EDID_LENGTH` and copying into `buf`, it must add `buf[126]` to `buf[127]` and zero `buf[126]` to strip unavailable EDID extension blocks while preserving the checksum. [F54]
- In `vesadrm.c`, `vesa->pmi.PrimaryPalette` is computed as `(u8 *)pmi_addr + pmi_addr[2]`, and `vesadrm_pmi_cmap_write()` must pass a 4-byte `{ blue >> 8, green >> 8, red >> 8, 0x00 }` struct in `%edi` and `&vesa->pmi.PrimaryPalette` in `%esi` for `call *(%%esi)`. [F65]

## Known Pitfalls

- `efidrm_get_mem_flags()` must only allow `EFI_MEMORY_WT` or `EFI_MEMORY_WB` caching flags when `efi_enabled(EFI_MEMMAP)` is true, `efi_mem_desc_lookup(start, &md)` succeeds, and `start + len <= md.phys_addr + (md.num_pages << EFI_PAGE_SHIFT)`, defaulting to `EFI_MEMORY_WC | EFI_MEMORY_UC` otherwise. [F102]
- In `simpledrm_device_init_regulators()`, both `for_each_property_of_node()` loops must use the identical filter `p = strstr(prop->name, SUPPLY_SUFFIX)` with `p && p != prop->name`, and `len` passed to `strscpy(name, prop->name, min(sizeof(name), len))` must include `+ 1` (`strlen(prop->name) - strlen(SUPPLY_SUFFIX) + 1`) for the NUL terminator. [F58, F89]
- In `ofdrm.c`, raw Open Firmware properties fetched via `of_get_property()` (`vendor-id`, `device-id` in `display_get_model_of()` and `display_get_pci_dev_of()`) and raw address cells passed to `of_translate_address()` (`io_of_addr` in `ofdrm_qemu_cmap_ioremap()`) are `__be32` and must use `be32_to_cpup()` / `cpu_to_be32()`. [F60]
- In `ofdrm.c`, `odev->cmap_base` is a byte-addressed `void __iomem *`, so while register-offset helpers add byte offsets directly to `odev->cmap_base`, `ofdrm_gxt2000_cmap_write()` must cast `odev->cmap_base` to `unsigned int __iomem *` before adding `index` so each palette index scales by 4 bytes. [F85]
- For SLOF-initialized AVIVO displays (`"vga,Display-"` nodes) in `ofdrm`, the PCI `"vendor-id"`, `"device-id"`, and BAR 0 colormap address properties reside on `of_parent = of_get_parent(of_node)` rather than on `of_node` itself. [F74]
- In `display_get_model_of()`, specific `"ATY,"` node-name prefix checks (`"ATY,Rage128"`, `"ATY,RageM3pA"`, `"ATY,RageM3p12A"`, `"ATY,RageM3pB"`, `"ATY,Rage6"`) must precede the catch-all `of_node_name_prefix(of_node, "ATY,")` check that returns `OFDRM_MODEL_MACH64`. [F109]
