# VM SOCKETS (AF_VSOCK)

Implements the `AF_VSOCK` (`PF_VSOCK`) address family for communication between virtual machines and their host hypervisor or locally via loopback (`SOCK_STREAM`, `SOCK_SEQPACKET`, `SOCK_DGRAM`), including socket lifecycle, hash tables, pluggable transports, BPF sockmap, `SOCK_DIAG`, `vsockmon`, loopback, and VMCI transport.

## Architecture & Data Flow

- `vsock_remove_sock()` must only call `vsock_remove_bound(vsk)` when `SOCK_DEAD` is set on `sk` (set in `__vsock_release()` before `vsk->transport->release(vsk)`), because `transport->release(vsk)` also calls `vsock_remove_sock()` during transport reassignment in `vsock_assign_transport()` where local bindings must be preserved. [F60]
- When `vsock_connect()` or `vsock_connect_timeout()` fails, times out, or is interrupted after `sock->state` is `SS_CONNECTING`, both `sk->sk_state` (`TCP_CLOSE` or `TCP_CLOSING`) and `sk->sk_socket->state` (`SS_UNCONNECTED`) must be updated in lockstep. `vsock_dgram_connect()` must set both `sock->state = SS_CONNECTED` and `sk->sk_state = TCP_ESTABLISHED` so `sock_map_redirect_allowed()` permits connected datagram sockets. [F61, F69]
- In `vmci_transport_recv_listen()`, after `vsock_assign_transport(vpending, vsock_sk(sk))`, it must check `vmci_check_transport(vpending)` and abort with a reset and `sock_put(pending)` if another transport was assigned; `pos = fls(proto_int)` must also be checked for non-zero before `1 << (pos - 1)`. In `vmci_transport_recv_connecting_server()`, `pending->sk_state = TCP_ESTABLISHED` and `vsock_insert_connected(vpending)` must precede `vmci_transport_send_attach(pending, handle)` and be rolled back before `release_sock(pending)` on error. [F66, F70, F112]
- `struct vmci_transport_recv_notify_data` and `struct vmci_transport_send_notify_data` must not exceed the size or alignment of `struct vsock_transport_recv_notify_data` and `struct vsock_transport_send_notify_data`, because VMCI notify wrappers cast stack-allocated `vsock_transport_*_notify_data` pointers directly to the VMCI types. [F118]
- In `vmci_transport_notify.c`, `data->consume_head` and `data->produce_tail` must be sampled in `recv_pre_dequeue` and `send_pre_enqueue` before ring indices change so `recv_post_dequeue` (only when `data_read` is true, not `MSG_PEEK`) and `send_post_enqueue` can detect wrap-around and increment `consume_q_generation` / `produce_q_generation`. [F78]
- After setting `vmci_trans(vsk)->consume_size` in `vmci_transport_recv_listen()` or `vmci_transport_recv_connecting_client_negotiate()`, `notify_ops->process_request()` or `notify_ops->process_negotiate()` must run to update `write_notify_window` to `consume_size` and clamp `write_notify_min_window` to `<= consume_size`. In `vmci_transport_notify_waiting_write`, `PKT_FIELD(vsk, write_notify_window)` must be checked for `< PAGE_SIZE` before subtracting `PAGE_SIZE` and must not exceed `consume_size`. [F77, F115]
- `struct vmci_datagram dg` must be at offset 0 of `struct vmci_transport_packet`, `vmci_transport_recv_stream_cb()` must check `VMCI_DG_SIZE(dg) >= sizeof(*pkt)` before casting, and `vmci_transport_packet_init()` must set `pkt->dg.payload_size = sizeof(*pkt) - sizeof(pkt->dg)`. `vmci_transport_dgram_enqueue()` must reject `len > VMCI_MAX_DG_PAYLOAD_SIZE`, allocate `len + sizeof(*dg)`, and subtract `sizeof(*dg)` from `vmci_datagram_send()`, while `vmci_transport_dgram_dequeue()` must verify `dg->payload_size == skb->len - sizeof(*dg)` and copy from offset `sizeof(*dg)`. [F85, F120, F121]
- `vsock_bind_table` has `VSOCK_HASH_SIZE + 1` buckets (`0..VSOCK_HASH_SIZE - 1` for ports, `VSOCK_HASH_SIZE` for `vsock_unbound_sockets`). In `__vsock_bind_connectible()`, the rolling `u32 port` counter must wrap to `LAST_RESERVED_PORT + 1` whenever `port == VMADDR_PORT_ANY` or `port <= LAST_RESERVED_PORT`. `vsock_for_each_connected_socket()` must filter `vsock_connected_table` by `vsk->transport == transport`. [F65, F81, F82]

## Synchronization

- `lock_sock(sk)` nests outside `vsock_table_lock`, and `vsock_table_lock` is taken in BH callbacks (`vmci_transport_recv_stream_cb`, `vmci_transport_qp_resumed_cb`), so `vsock_table_lock` must always use `spin_lock_bh(&vsock_table_lock)`, `vsock_bind_table` / `vsock_connected_table` must only be accessed under `vsock_table_lock`, and code holding `vsock_table_lock` (`sk_diag_fill`, `vsock_diag_dump`, `vsock_for_each_connected_socket` callbacks) must never call `lock_sock(sk)`. [F23, F140]
- `vmci_transport_peer_detach_cb` acquires `spin_lock_bh(&trans->lock)` before `bh_lock_sock(trans->sk)`, so `trans->lock` must never be acquired under `lock_sock` or `bh_lock_sock`, and `vmci_transport_destruct` must clear `trans->sk = NULL` under `spin_lock_bh(&trans->lock)` before queueing `trans` for cleanup. [F139]
- Callers of `vsk->transport->release(vsk)` (`vsock_assign_transport()`, `__vsock_release()`) must hold `lock_sock` / `lock_sock_nested`, and `.release` callbacks must not acquire the socket lock. Connectible socket callbacks (`vsock_poll`, `vsock_connectible_setsockopt`, `vsock_connectible_sendmsg`, `__vsock_connectible_recvmsg`) must read `vsk->transport` only after `lock_sock(sk)`, and `vsock_shutdown()` must hold `lock_sock(sk)` across checking/updating `sock->state`, `sk->sk_shutdown`, `SOCK_DONE`, and `vsock_send_shutdown()`. [F22, F34, F64]
- When scheduling `vsk->connect_work` via `mod_delayed_work()`, the caller must take `sock_hold(sk)` beforehand and call `sock_put(sk)` if `mod_delayed_work()` returns true; `vsock_connect_timeout()` must recheck `sk->sk_state == TCP_SYN_SENT` and call `vsock_transport_cancel_pkt(vsk)` under `lock_sock(sk)` before dropping that reference. [F30]
- In `vsock_connectible_sendmsg()`, `sk->sk_err`, `sk->sk_shutdown & SEND_SHUTDOWN`, and `vsk->peer_shutdown & RCV_SHUTDOWN` must be rechecked after `wait_woken()` relocks `sk` before `notify_send_pre_enqueue()`, `seqpacket_enqueue()`, or `stream_enqueue()`. In `vsock_connectible_wait_data()`, `prepare_to_wait(sk_sleep(sk), wait, TASK_INTERRUPTIBLE)` must run at the start of every loop iteration before checking `vsock_connectible_has_data(vsk)`, `sk->sk_err`, or shutdown flags and dropping `lock_sock(sk)`. [F32, F33]
- `vmci_transport_recv_dgram_cb` and `vmci_transport_recv_stream_cb` run in BH tasklet context and must use `GFP_ATOMIC` and `vmci_transport_send_control_pkt_bh` (never `vmci_transport_alloc_send_control_pkt` or non-BH send helpers). `vmci_transport_handle_detach` also runs in atomic context and must short-circuit on `vsk->local_addr.svm_cid == VMADDR_CID_HOST` before calling `vsock_stream_has_data(vsk)`, which may block on a host. [F136, F138]
- In `vmci_transport_recv_connecting_server` and `vmci_transport_recv_connecting_client_negotiate`, `vmci_event_subscribe` for `VMCI_EVENT_QP_PEER_DETACH` must precede `vmci_transport_queue_pair_alloc`. In `vmci_transport_notify_qstate.c`, `vmci_transport_notify_pkt_recv_post_dequeue()` and `vmci_transport_notify_pkt_send_post_enqueue()` must execute `smp_mb()` after queue-pair dequeue/enqueue before querying `vmci_qpair_consume_free_space()` or `vmci_qpair_produce_buf_ready()`. [F36, F126]
- `the_vsock_loopback.pkt_queue` accesses must hold `spin_lock_bh(&vsock->pkt_queue.lock)` (including in `vsock_loopback_work()`), and `vsock_loopback_exit()` must call `vsock_core_unregister()` and `flush_work(&vsock->pkt_work)` before purging `pkt_queue` and destroying `vsock->workqueue`. `vsock_bpf_check_needs_rebuild` must copy `struct proto` into `vsock_bpf_prot` under `spin_lock_bh(&vsock_prot_lock)` and publish `vsock_prot_saved` via `smp_store_release` paired with `smp_load_acquire` (never mutating `vsock_proto` in place). [F38, F133]

## Object Lifetimes

- In `__vsock_release()`, `sock_orphan(sk)` must be called after `vsk->transport->release(vsk)` completes because transport `release()` callbacks call `vsock_linger(sk)`, which dereferences `sk_sleep(sk)` (`sk->sk_wq`) that `sock_orphan(sk)` clears to `NULL`. [F2]
- In `vsock_assign_transport()`, if `vsk->transport == new_transport` it must return `0`; if another `vsk->transport` is set, it must call `vsk->transport->release(vsk)`, `vsock_deassign_transport(vsk)`, and reset `SOCK_DONE`, `sk->sk_state`, and `vsk->peer_shutdown`. It must call `try_module_get(new_transport->module)` under `vsock_register_mutex` (balanced by `module_put` in `vsock_deassign_transport` or on error), and direct accesses to `transport_*` pointers without a socket reference must hold `vsock_register_mutex`. [F3, F129]
- When `vsock_create()` fails after `__vsock_create()`, it must clear `sock->sk = NULL` before `sock_put(sk)`. `vsock_sk_destruct()` must call `__skb_queue_purge(&sk->sk_error_queue)`, `vsock_deassign_transport(vsk)`, and `put_cred(vsk->owner)`. In `vsock_connectible_sendmsg()`, every early exit from the inner wait loop after `add_wait_queue(sk_sleep(sk), &wait)` must call `remove_wait_queue(sk_sleep(sk), &wait)` before jumping to `out_err`. [F5, F6, F18]
- On failure in `vmci_transport_recv_connecting_server()`, `destroy:` must call `sock_put(pending)` because `vmci_transport_recv_listen()` calls `vsock_remove_pending(sk, pending)` without setting `vpending->rejected`, causing `vsock_pending_work()` to skip its `sock_put()`. In `vmci_transport_recv_dgram_cb()`, `sock_hold(sk)` must precede `sk_receive_skb(sk, skb, 0)` because `sk_receive_skb()` consumes a reference on `sk` and takes ownership of `skb`. [F12, F16]
- `vsock_tap_all` updates must hold `vsock_tap_lock` with `list_add_rcu()` / `list_del_rcu()`. `vsock_deliver_tap()` must run under `rcu_read_lock()`, clone the SKB with `skb_clone(skb, GFP_ATOMIC)` and pin `tmp->dev` with `dev_hold()` / `dev_put()` around `dev_queue_xmit()` in `__vsock_deliver_tap_skb()`, and free the `build_skb(opaque)` SKB with `consume_skb(skb)`. `vsock_remove_tap()` must call `synchronize_net()` after unlocking `vsock_tap_lock` and only call `module_put(vt->module)` if `vt` was found. [F19, F37, F159]

## API Contracts

- `vsock_enqueue_accept(listener, connected)` calls `sock_hold()` on both `connected` and `listener`, whereas `vsock_dequeue_accept(listener)` drops only `listener`'s reference via `sock_put(listener)` and transfers `connected`'s reference to the caller. [F10]
- In `struct vsock_transport`, `cancel_pkt`, `seqpacket_allow`, `notify_buffer_size`, `notify_set_rcvlowat`, `unsent_bytes`, `read_skb`, and `msgzerocopy_allow` are optional and must be NULL-checked before invocation. Any transport using `virtio_transport_*` callbacks must embed `struct vsock_transport` inside `struct virtio_transport` for `container_of()` in `vsock_core_get_transport(vsk)`. [F40, F123]
- `vsock_stream_has_data()`, `vsock_connectible_has_data()`, and `vsock_stream_has_space()` return a signed `s64` (negative on error), so callers must use a signed type and check `< 0` or `> 0`. `vsock_addr_cast()` must set `*out_addr = (struct sockaddr_vm *)addr` as soon as `len >= sizeof(**out_addr)` before `vsock_addr_validate(*out_addr)`, because `vsock_dgram_connect()` checks `remote_addr->svm_family == AF_UNSPEC` when `vsock_addr_cast()` returns `-EAFNOSUPPORT`. [F44, F46]
- `vsock_proto` must define `.close = vsock_close` and `vsock_release()` must call `sk->sk_prot->close(sk, 0)` before `__vsock_release()` for `sock_map_close()`. `vsock_poll()` must check `sk_is_readable(sk)`. `vsock_bpf_update_proto()` must verify `vsk->transport` (`-ENODEV`) and `vsk->transport->read_skb` (`-EOPNOTSUPP`), and restore `sk->sk_write_space = psock->saved_write_space` on restore. `vsock_connect()` must fail with `-EOPNOTSUPP` if `SOCK_ZEROCOPY` is set and `!vsock_msgzerocopy_allow(transport)`, and both `vsock_connect()` and `vsock_accept()` must set `SOCK_SUPPORT_ZC` when allowed. [F151, F153, F154, F157]

## Error Handling

- On connection-oriented sockets, `vsk->transport` is NULL until `vsock_assign_transport()` succeeds and is cleared by `vsock_deassign_transport()`, so functions reachable on unconnected sockets (`vsock_stream_has_data()`, `vsock_poll()`, `vsock_read_skb()`, `vsock_bpf_recvmsg()`, `vsock_transport_cancel_pkt()`) must NULL-check `vsk->transport`. Similarly, `vmci_transport_destruct()` must NULL-check both `vmci_trans(vsk)` and `vmci_trans(vsk)->notify_ops`. [F39, F41]
- In `vsock_connect()`, when `sock->state == SS_CONNECTING`, a non-blocking call (`flags & O_NONBLOCK`) must jump to `out` with `-EALREADY` without entering the wait loop or rescheduling `vsk->connect_work`, whereas a blocking call must wait until `sk->sk_state` is `TCP_ESTABLISHED` or `TCP_CLOSING` or `sk->sk_err != 0`. After `transport->connect(vsk)` succeeds, `sk->sk_err` must be cleared to `0` and `err` set to `-EINPROGRESS`, and the `O_NONBLOCK` path in the wait loop must jump to `out_wait` to preserve `err`. [F8, F49, F98]
- In `vsock_connectible_sendmsg()`, if an error, timeout, signal, or shutdown occurs after `total_written > 0`, `out_err` must overwrite `err` with `total_written` when `sk->sk_type == SOCK_STREAM` (or `total_written == len` for `SOCK_SEQPACKET`) and pass `err` through `sk_stream_error()` for `SOCK_STREAM`. In `__vsock_stream_recvmsg()`, when the loop breaks with `copied > 0` (except on `notify_recv_post_dequeue()` failure), `err` must be overwritten with `copied` after checking `sk->sk_err` and `RCV_SHUTDOWN`. [F47, F48]
- `sk->sk_err` stores positive errno values and syscall handlers must negate `sk->sk_err` on return. VMCI API calls return VMCI-specific negative codes that must be converted via `vmci_transport_error_to_vsock_error()` (or mapped to `-ENOMEM`). In `vmci_transport_recv_connecting_client_negotiate()`, `detach_sub_id`, `handle`, and `qpair` must only be stored into `vmci_trans(vsk)` after `vmci_transport_send_qp_offer()` succeeds so `destroy` does not double-free them in `vmci_transport_cleanup()`. [F43, F45, F50]

## External Contracts

- In `vsock_shutdown()`, `mode` (`SHUT_RD`/`SHUT_WR`/`SHUT_RDWR`) must be incremented by 1 before checking `(mode & ~SHUTDOWN_MASK) || !mode`, and when `sock->state == SS_UNCONNECTED`, only `sock_type_connectible(sk->sk_type)` sockets exit early while `SOCK_DGRAM` sockets still update `sk->sk_shutdown` and call `sk->sk_state_change(sk)`. In `__vsock_connectible_recvmsg()`, `MSG_ERRQUEUE` must run before `lock_sock(sk)`, `!transport || sk->sk_state != TCP_ESTABLISHED` must return `0` if `SOCK_DONE` is set and `-ENOTCONN` otherwise, and `vsk->peer_shutdown` must not be checked before draining data. [F55, F97, F99]
- `vsock_diag_handler_dump()` must check `nlmsg_len(h) >= sizeof(struct vsock_diag_req)` before `netlink_dump_start()`. In `vsock_diag_dump()`, sockets skipped via `continue` (`!net_eq(sock_net(sk), net)` or `__vsock_in_bound_table(vsk)` in `vsock_connected_table`) must not increment `i`, whereas `i < last_i` and `vdiag_states` mismatches must jump to `next_bind`/`next_connected` to increment `i`, and `last_i` must be reset to `0` when advancing `bucket`. [F94, F103, F166]

## Known Pitfalls

- `vmci_transport_send_reset_bh(dst, src, pkt)`, `vmci_transport_send_invalid_bh(dst, src)`, `vmci_transport_send_wrote_bh(dst, src)`, and `vmci_transport_send_read_bh(dst, src)` take `(dst, src)` in reverse order compared to `vmci_transport_send_control_pkt_bh(src, dst, ...)`, so reply callers must pass `(&dst, &src)`. `vmci_transport_allow_dgram()` must check `peer_cid == VMADDR_CID_HYPERVISOR` (`0`) before `vsock->cached_peer != peer_cid`, because `sk_alloc()` zero-initializes `cached_peer` to `0` and `cached_peer_allow_dgram` to `false`. [F58, F74]
- In `vmci_transport_recv_listen()` and `vmci_transport_recv_connecting_server()`, once a child `pending` socket is found on `pending_links`, state transitions, resets, and `sk_err` updates must target `pending`, while `vsock_remove_pending()`, `vsock_enqueue_accept()`, and `listener->sk_data_ready(listener)` must target `listener`. In `vmci_transport_notify_pkt_poll_out()`, `send_waiting_write(sk, 1)` must only be called when `produce_q_free_space == 0` to avoid an infinite `WAITING_WRITE` / `READ` loop. [F107, F109]
