# RTRS TRANSPORT DRIVERS

The RTRS (RDMA Transport) subsystem implements a reliable, multipath RDMA transport layer (used primarily by RNBD) across `rtrs-core`, `rtrs-client`, and `rtrs-server`. It manages RDMA CM connections, protection domains, fast memory registration and invalidation, heartbeats, multipath routing policies, automatic reconnection and failover, and sysfs interfaces.

## Architecture & Data Flow

- When `RTRS_MSG_NEW_RKEY_F` is negotiated (server `always_invalidate=true`), `map_cont_bufs()` allocates `srv_mr->iu` and the server sends `RTRS_MSG_RKEY_RSP` via `IB_WR_SEND_WITH_IMM` after `IB_WR_REG_MR`, while the client allocates `con->rsp_ius` on `cid > 0` and updates `clt_path->rbufs[buf_id].rkey` in `rtrs_clt_rkey_rsp_done()` before completing IO. Guard all `srv_mr->iu` accesses with `always_invalidate`, and guard client `con->rsp_ius` indexing and `rtrs_clt_recv_done()`/`rtrs_clt_rkey_rsp_done()` calls with `clt_path->flags & RTRS_MSG_NEW_RKEY_F` (using `&`, never `==`/`!=`, on `flags`). [F43, F44, F71, F85]
- In `init_conns()`, connection `cid == 0` (`RTRS_ADMIN_CON`) must be created and established before `cid > 0` because `create_con_cq_qp()` for `cid > 0` relies on `clt_path->s.dev`, `queue_depth`, and `flags` (`RTRS_MSG_NEW_RKEY_F`) populated by `cid == 0`. `rtrs_path::signal_interval` must also be initialized on `cid == 0` via `min_not_zero(queue_depth, SERVICE_CON_QUEUE_DEPTH)` because send helpers modulo-divide by `signal_interval`. [F67, F106]
- `path->con[0]` is reserved for admin/heartbeat traffic (`RTRS_ADMIN_CON`), IRQ IO connections (`RTRS_IO_CON`) use indices `1` to `path->irq_con_num - 1`, and poll queues use `>= path->irq_con_num`. `rtrs_permit_to_clt_con()` and `rtrs_clt_rdma_cq_direct()` must offset 0-based IO queue indices by `+1`, and `alloc_path()` requires `con_num >= 1` (`irq_con_num >= 2`) to avoid modulo-by-zero in `(permit->cpu_id % (clt_path->s.irq_con_num - 1)) + 1`. [F55, F107]
- Selectively signaled send helpers (`rtrs_post_rdma_write_imm_empty()`, `rtrs_post_send_rdma()`, `rtrs_post_rdma_write_sg()`, `rdma_write_sg()`, `send_io_resp_imm()`) must increment `con->wr_cnt` and set `IB_SEND_SIGNALED` every `path->signal_interval` WRs to match the `s->signal_interval` credits added to `con->c.sq_wr_avail` in `rtrs_srv_rdma_done()`. Chained `IB_WR_REG_MR` WRs in client/server IO and `process_info_req()` must set `wr.send_flags = 0`, never `IB_SEND_SIGNALED`. [F64, F138]
- On a server `rdma_cm_id`, `cm_id->context` points to `struct rtrs_srv_ctx` until `create_con()` reassigns `cm_id->context = &con->c` during `RDMA_CM_EVENT_CONNECT_REQUEST`; `rtrs_srv_rdma_cm_handler()` must handle `RDMA_CM_EVENT_CONNECT_REQUEST` before casting `cm_id->context` to `struct rtrs_con`. In `struct rtrs_srv_op`, `id->rd_msg` is assigned only during `process_read()` and is NULL or stale during `process_write()`, so `rtrs_srv_resp_rdma()` and `send_io_resp_imm()` must check `id->dir` before dereferencing `id->rd_msg`. [F45, F46]
- Within each `srv->chunks[buf_id]`, IO data is at offset `0` (`data_len`), the user control message is at `data_len` (`usr_len`), and the RTRS RDMA header is at `off = data_len + usr_len`. On the client, `rtrs_clt_init_req()` copies the user message into the first `req->usr_len` bytes of `req->iu->buf`, and `rtrs_clt_write_req()`/`rtrs_clt_read_req()` must write the RTRS header at `req->iu->buf + req->usr_len`. [F61, F79]
- `rtrs_clt_init_req()` snapshots `clt_path->clt->mp_policy` into `req->mp_policy`; all increments and decrements of `clt_path->stats->inflight` must test `req->mp_policy == MP_POLICY_MIN_INFLIGHT` rather than `clt->mp_policy`. `clt->permits` is a byte-strided allocation with element size `permit_size(clt) = sizeof(struct rtrs_permit) + clt->pdu_sz`; always index it via `get_permit(clt, idx)` and never via `struct rtrs_permit` pointer arithmetic. [F60, F80]
- Session limits `clt->max_io_size` (updated under `clt->paths_mutex` in `rtrs_rdma_conn_established()`) and `clt->max_segments` (in `query_fast_reg_mode()`) must be clamped to the minimum across all paths, and `clt_path->max_pages_per_mr` clamped to `min(RTRS_MAX_SEGMENTS, ib_dev->attrs.max_mr_size / (1ULL << max(12, ffs(ib_dev->attrs.page_size_cap) - 1)), ib_dev->attrs.max_fast_reg_page_list_len)`. [F66, F136]
- Set `clt_path->for_new_clt = 1` on the first path in `rtrs_clt_open()`, on a sysfs-added path when `clt->paths_num == 0`, and on any path once `cid == 0` is established in `rtrs_rdma_conn_established()`, so `msg.first_conn` is set whenever the server may need to create a new `rtrs_srv_sess`. In `rtrs_clt_rdma_done()` and `rtrs_srv_rdma_done()`, any valid peer completion (`IB_WC_RECV_RDMA_WITH_IMM` or client `IB_WC_RECV`) must reset `s.hb_missed_cnt = 0`, and `rtrs_stop_hb()` must reset `path->hb_missed_cnt = 0` while preserving `path->hb_missed_max`. [F63, F69]

## Synchronization

- In `rtrs_clt_stop_and_destroy_conns()`, `clt_path->state` must not be `RTRS_CLT_CONNECTED`, `clt_path->init_mutex` must be cycled, `synchronize_rcu()` and `rtrs_stop_hb()` must run before `stop_cm()`, and `fail_all_outstanding_reqs()` must run after `stop_cm()` drains QPs and before `rtrs_clt_path_down()` and `destroy_con_cq_qp()`. In `rtrs_srv_close()`, `ib_unregister_client(&rtrs_srv_client)` must run before `close_ctx(ctx)` closes paths and flushes `rtrs_wq`, before `free_srv_ctx(ctx)`. [F26, F28]
- All calls to `create_con_cq_qp()` and `destroy_con_cq_qp()` must hold `con->con_mutex`. All transitions of `clt_path->state` must go through `rtrs_clt_change_state()` under `clt_path->state_wq.lock`, and `srv_path->state` through `rtrs_srv_change_state()` under `srv_path->state_lock` using `spin_lock_irqsave()`/`spin_unlock_irqrestore()` (because callers like `close_path()` via `rtrs_srv_resp_rdma()` can run in atomic/softirq context with IRQs disabled). [F30, F31, F140]
- In `rtrs-srv.c`, the lock hierarchy is `ctx->srv_mutex` outer to `srv->paths_mutex` inner (never call `put_srv()` while holding `srv->paths_mutex`). Updates to `paths_up` and `link_ev` callbacks in `rtrs_clt_path_up()`/`down()` and `rtrs_srv_path_up()`/`down()` must be serialized under `clt->paths_ev_mutex` and `srv->paths_ev_mutex`. In `rtrs_rdma_process_wr_wait_list()`, unlock `con->rsp_wr_wait_lock` before calling `rtrs_srv_resp_rdma()` and re-acquire it afterward. [F32, F33, F34]
- Pass `can_wait = false` to `complete_rdma_req()` when called from CQ context (`process_io_rsp()` or `rtrs_clt_inv_rkey_done()`) so MR invalidation completes asynchronously instead of sleeping on `req->inv_comp`. Pass `wait = false` to `rtrs_clt_close_conns()` when called from `rtrs_clt_reconnect_work()` or `rtrs_clt_rdma_cm_handler()` (`RDMA_CM_EVENT_DEVICE_REMOVAL`). [F141, F148]
- In `rtrs_clt_remove_path_from_sysfs()`, loop calling `rtrs_clt_close_conns(clt_path, true)` and `rtrs_clt_change_state_get_old(clt_path, RTRS_CLT_DEAD, &old_state)` until `changed || old_state == RTRS_CLT_DEAD`, and only unlink and free the path when `changed` is true. [F90]
- Sync `rtrs_iu` buffers and `srv_path->dma_addr` chunks with `ib_dma_sync_single_for_device()` after CPU writes before posting a WR (and before reposting a receive `rtrs_iu` in `rtrs_clt_rkey_rsp_done()`), and with `ib_dma_sync_single_for_cpu()` before CPU reads. On the server when `always_invalidate` is true, `rtrs_srv_rdma_done()` must post `IB_WR_LOCAL_INV` via `rtrs_srv_inv_rkey()` on `RTRS_IO_REQ_IMM` and defer `process_io_req()` (and `ib_dma_sync_single_for_cpu()`) until `rtrs_srv_inv_rkey_done()`. [F152, F153]
- In `rtrs_clt_update_wc_stats()`, access `stats->pcpu_stats` via `get_cpu_ptr()`/`put_cpu_ptr()`. Because local `s` is reassigned to `per_cpu_ptr(stats->pcpu_stats, con->cpu)` inside `if (con->cpu != cpu)` (where remote `cpu_migr.from` must use `atomic_inc()`), any current-CPU stat updates through `s` must precede that block. [F98, F149]

## Object Lifetimes

- In `rtrs_cq_qp_destroy()`, call `rdma_destroy_qp(con->cm_id)` and set `con->qp = NULL` before `destroy_cq()`. `create_cq()`/`destroy_cq()` must pair `ib_alloc_cq()` with `ib_free_cq()` when `is_pollqueue(con)` is true (`con->cid >= con->path->irq_con_num`), and `ib_cq_pool_get()` with `ib_cq_pool_put(con->cq, con->nr_cqe)` otherwise. [F3, F127]
- In `destroy_con_cq_qp()`, `rtrs_cq_qp_destroy(&con->c)` and `rtrs_iu_free(con->rsp_ius, ...)` must precede decrementing `clt_path->s.dev_ref` and calling `rtrs_ib_dev_put(clt_path->s.dev)` (setting `clt_path->s.dev = NULL` at 0). If `create_con_cq_qp()` or `rtrs_rdma_addr_resolved()` fails after incrementing `dev_ref` or allocating `rsp_ius`, still invoke `destroy_con_cq_qp(con)` under `con->con_mutex`. In `dev_free()`, call `pool->ops->deinit(dev)` before `ib_dealloc_pd(dev->ib_pd)` and `kfree(dev)`. [F2, F4, F129]
- In `rtrs_clt_remove_path_from_arr()`, `list_del_rcu(&clt_path->s.entry)` and `synchronize_rcu()` must precede decrementing `clt->paths_num` and replacing any per-CPU `clt->pcpu_path` entries pointing to `clt_path`, followed by a second `synchronize_rcu()` if any per-CPU entry was replaced. [F8]
- In `rtrs_clt_open()` and `rtrs_clt_create_path_from_sysfs()`, add a new `rtrs_clt_path` to `clt->paths_list` in `RTRS_CLT_CONNECTING` state before calling `init_path(clt_path)`. If an error occurs after `alloc_path()` before `rtrs_clt_create_path_files()` binds `clt_path` and `clt_path->stats` to their kobjects, explicitly call `free_percpu(clt_path->stats->pcpu_stats)` and `kfree(clt_path->stats)` before `free_path(clt_path)`. [F9, F126]
- Once `device_initialize(&clt->dev)` binds `rtrs_clt_dev_release`, release `clt` and its mutexes in `alloc_clt()` error paths and `free_clt()` exclusively via `put_device(&clt->dev)` or `device_unregister(&clt->dev)`. Call `free_permits(clt)` only in `rtrs_clt_close()` (which waits on `clt->permits_wait`), never inside `free_clt()`. [F10, F120]
- When tearing down a client session or path (`rtrs_clt_close()` or `rtrs_clt_remove_path_from_sysfs()`), `rtrs_clt_close()` must call `rtrs_clt_destroy_sysfs_root(clt)` before iterating `clt->paths_list`, and `rtrs_clt_close_conns(clt_path, true)` plus (for single-path removal) `rtrs_clt_remove_path_from_arr(clt_path)` must complete before `rtrs_clt_destroy_path_files()`. [F25, F122]
- In `rtrs_srv_close_work()`, only call `rtrs_srv_destroy_path_files()`, `rtrs_srv_path_down()`, `unmap_cont_bufs()`, and `rtrs_srv_free_ops_ids()` after disconnecting and draining all QPs, calling `percpu_ref_kill(&srv_path->ids_inflight_ref)`, and waiting on `srv_path->complete_done`. In `rtrs_srv_destroy_path_files()`, when `srv_path->kobj.state_in_sysfs` is true, remove `rtrs_srv_path_attr_group`, call `kobject_put(&srv_path->kobj)` without `kobject_del()`, and call `rtrs_srv_destroy_once_sysfs_root_folders(srv_path)` inside that guard (which registers/unregisters `srv->dev` under `srv->paths_mutex` only when `srv->dev_ref` transitions `0 <-> 1`). [F17, F24, F124]
- Stack-allocated work requests and `struct ib_sge` entries linked into a send WR chain (e.g., `struct ib_sge list` in `send_io_resp_imm()`, `struct ib_reg_wr rwr` in `rtrs_clt_write_req()`) must be declared in a scope encompassing the `ib_post_send()` call. [F112]

## API Contracts

- Every caller of `path_it_init(&it, clt)` (`rtrs_clt_request()`, `rtrs_clt_failover_req()`, `rtrs_clt_rdma_cq_direct()`) must hold `rcu_read_lock()`, initialize its return status to a negative error (`-ECONNABORTED` or `-1`) before the loop in case no path is `RTRS_CLT_CONNECTED`, and call `path_it_deinit(&it)` on all exit paths to unlink per-CPU `clt_path->mp_skip_entry` from `it->skip_list`. [F11, F52]
- Callers of `rtrs_cq_qp_create()` must initialize `con->cid`, `con->path`, and `con->path->irq_con_num` beforehand because `create_cq()` calls `is_pollqueue(con)` before `rtrs_cq_qp_create()` assigns `con->path = path`. [F53]
- After `ib_dma_map_sg()` in `rtrs_clt_write_req()`, `rtrs_clt_read_req()`, and `map_cont_bufs()`, pass the coalesced count returned by `ib_dma_map_sg()` to DMA consumers (`ib_alloc_mr()`, `ib_map_mr_sg()`, `rtrs_map_sg_fr()`, `rtrs_post_rdma_write_sg()`, `for_each_sg()`), but pass original `req->sg_cnt` or `sgt->nents` to `ib_dma_unmap_sg()`. [F151]
- `rtrs_ib_dev_find_or_add()` and `rtrs_iu_alloc()` return `NULL` on failure, whereas `alloc_clt()`, `alloc_path()`, `get_or_create_srv()`, `__alloc_path()`, and `rtrs_srv_cm_init()` return `ERR_PTR`. `rtrs_addr_to_sockaddr()` sets `addr->src = NULL` when no `,` or `@` delimiter is present (so check `path->src` before copying), and passes an un-terminated source prefix of length `d - str` to `rtrs_str_to_sockaddr()`, which must bound all reads to `len` bytes. [F39, F47, F119]

## Error Handling

- In `rtrs-clt.c`, `con->cm_err` is `0` while connecting, `1` on `RDMA_CM_EVENT_ESTABLISHED` (`flag_success_on_conn`), and negative errno on failure (`flag_error_on_conn`). `rtrs_clt_rdma_cm_handler()` must store `rtrs_rdma_conn_established()`'s return value in local `cm_err` so non-zero errors trigger `flag_error_on_conn()`. [F38]
- If `rtrs_clt_read_req()` or `rtrs_clt_write_req()` fails in `rtrs_clt_request()` or `rtrs_clt_failover_req()`, clear `req->in_use = false` before trying the next path; `complete_rdma_req()` must return early without `WARN_ON()` when `!req->in_use`. [F62, F167]
- In `init_conns()`, after `for (cid = 0; cid < clt_path->s.con_num; cid++)` finishes, reset `cid = clt_path->s.con_num - 1` before any step that can `goto destroy` (`for (i = 0; i <= cid; i++)`). In `map_cont_bufs()`, `srv_path->mrs_num` counts completed entries for `unmap_cont_bufs()`, so any error after `sg_alloc_table()` inside the loop must unwind `srv_path->mrs[srv_path->mrs_num]` before calling `unmap_cont_bufs()`. In `rtrs_map_sg_fr()` and `map_cont_bufs()`, check `ib_map_mr_sg()` for `nr != count` and return `nr < 0 ? nr : -EINVAL`. [F42, F84, F95]

## External Contracts

- `rtrs_to_io_rsp_imm()` packs `msg_id` into 19 bits (`0x7ffff`) and `abs(errno)` into 9 bits (`0x1ff << 19`), and `rtrs_from_io_rsp_imm()` negates the extracted 9-bit value as `-(int)((payload >> 19) & 0x1ff)`; status values passed to `rtrs_srv_resp_rdma()` and `send_io_resp_imm()` must be `<= 0` with magnitude `<= 511`. `struct rtrs_msg_conn_req` must keep `u8 __cma_version` and `u8 __ip_version` as its first two bytes and zero-initialize them in `rtrs_rdma_route_resolved()` before `rdma_connect_locked()`. [F104, F155]

## Known Pitfalls

- Any send WR posted with `IB_WR_RDMA_WRITE_WITH_IMM` or `IB_WR_RDMA_WRITE` (`rtrs_iu_post_rdma_write_imm()`, `rtrs_post_rdma_write_imm_empty()`, `send_io_resp_imm()`) must be allocated as `struct ib_rdma_wr`, never bare `struct ib_send_wr`, even when `num_sge == 0`. [F111]
- In `rtrs-clt.c`, `alloc_path_reqs()` allocates `req->sge` with only 2 elements (`max_send_sge = 2`), so `rtrs_post_rdma_write_sg()` must be called with `fr_en = true` whenever mapped SG `count > 1`, and both branches of `if (fr_en)` must leave index `i` at the final SGE slot (`1` for `fr_en`, `count` for `!fr_en`) where `req->iu` is placed. [F97, F114]
- In `rdma_write_sg()` and `send_io_resp_imm()`, `if (need_inval && always_invalidate)` must precede `else if (always_invalidate)` and `else if (need_inval)`. In `rtrs_clt_rdma_done()` under `IB_WC_RECV_RDMA_WITH_IMM`, the `RTRS_HB_MSG_IMM`/`RTRS_HB_ACK_IMM` branches must early-return via `rtrs_clt_recv_done(con, wc)` when `clt_path->flags & RTRS_MSG_NEW_RKEY_F` is set, rather than falling through to `rtrs_post_recv_empty()`. [F87, F88]
- Use 32-bit types (`u32`/`int`, not `u16`) for WR/CQ depth variables (`max_send_wr`, `max_recv_wr`, `cq_num`, `nr_cqe`) in `create_con_cq_qp()`, `create_con()`, and `rtrs_cq_qp_create()` to avoid `U16_MAX` overflow. In `get_next_path_min_latency()`, initialize `ktime_t min_latency` to `KTIME_MAX` (not `INT_MAX`). [F100, F101]
