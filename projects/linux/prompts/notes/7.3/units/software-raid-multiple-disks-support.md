# SOFTWARE RAID (Multiple Disks) SUPPORT

This unit implements the Linux MD RAID-4, RAID-5, and RAID-6 personalities (`drivers/md/raid5.c`, `drivers/md/raid5.h`), parity/syndrome calculation interfaces (`include/linux/raid/pq.h`, `include/linux/raid/xor.h`), autodetect declarations (`include/linux/raid/detect.h`), and UAPI superblock, journal/PPL, and ioctl definitions (`include/uapi/linux/raid/md_p.h`, `include/uapi/linux/raid/md_u.h`).

## Architecture & Data Flow

- `raid5_compute_sector()` sets `sh->qd_idx = -1` for RAID-4/5, and `raid5_compute_blocknr()` sets `dev[].sector = 0` on P/Q disks. Shared code indexing `sh->dev[sh->qd_idx]` must check `sh->qd_idx >= 0` or `conf->level == 6` (or `s.q_failed`), and loops over `sh->dev[]` inspecting data-disk sectors or counting non-overwritten data blocks (`stripe_ahead_of_reshape()`, `add_all_stripe_bios()`, `need_this_block()`, `handle_stripe_dirtying()`) must skip both `sh->pd_idx` and `sh->qd_idx`. [F50, F95]
- `need_this_block()` and `handle_stripe_dirtying()` must use matching conditions when forcing reconstruct-write (RCW) over RMW (`rmw_level == PARITY_DISABLE_RMW` or `sh->sector >= mddev->resync_offset`). In `handle_stripe_dirtying()`, forcing RCW at or beyond `resync_offset` requires `s->failed == 0`; entering the RCW pre-read branch requires resetting `rcw = 0` before recounting; and if `rcw > disks && rmw > disks` without `STRIPE_PREREAD_ACTIVE`, `STRIPE_DELAYED` must be set. [F62, F96, F97]
- `handle_stripe_dirtying()` may call `schedule_reconstruction()` while `STRIPE_COMPUTE_RUN` is set only if `s->req_compute` was set in the same `handle_stripe()` pass; if `STRIPE_COMPUTE_RUN` was started earlier (`!s->req_compute`), it must wait. When `schedule_reconstruction()` runs RCW (`rcw != 0`), it must call `r5c_release_extra_page(sh)` in case `handle_stripe_dirtying()` reserved `orig_page` (`R5C_EXTRA_PAGE_IN_USE`) for an RMW prexor that will not run `ops_complete_prexor()`. [F7, F74]
- On a batch head, `sh->batch_head == sh`, so lone/head checks must test `(!sh->batch_head || sh == sh->batch_head)` and subordinate checks must test `(sh->batch_head && sh != sh->batch_head)`. In `ops_run_io()`, `ops_run_biodrain()`, and `handle_stripe_clean_event()`, per-disk loops traversing `sh->batch_list` via backward `goto` must reset `sh = head_sh` (and `dev = &head_sh->dev[i]`) for each disk `i` and after `unhash:`. [F89, F92]
- When zero-copy write (`R5_SkipCopy`) aliases a bio page into `dev->page` in `ops_run_biodrain()`, clear `R5_UPTODATE` and `R5_OVERWRITE` (keeping them clear in `ops_complete_reconstruct()`), and restore `dev->page = dev->orig_page` when completing or failing `dev->written`. When all discard bios complete in `handle_stripe_clean_event()`, clear `R5_Discard` and `R5_UPTODATE` on data/parity slots and unhash every batched stripe via `remove_hash(sh)` under `conf->hash_locks[hash]`. [F67, F151]
- Whenever `STRIPE_OP_COMPUTE_BLK` is scheduled (`fetch_block()`, `handle_parity_checks5/6()`), initialize both `sh->ops.target` and `sh->ops.target2`, setting any unused slot to `-1`. When initiating an XOR check (`sh->check_state = check_state_run`), clear `R5_UPTODATE` on `sh->dev[sh->pd_idx].flags` and decrement `s->uptodate`, and in `handle_parity_checks6()`, reset `sh->ops.zero_sum_result = 0`. [F51, F73]
- In `analyse_stripe()`, `R5_WriteError` and `R5_MadeGood` apply only to the primary disk and must look up `rdev2 = conf->disks[i].rdev` rather than local `rdev` (which may point to `replacement`, used by `R5_MadeGoodRepl`). In `raid5_end_read_request()`, a read error on a RAID-6 P disk (`sh->qd_idx >= 0 && sh->pd_idx == i`) must set `R5_ReadError` immediately rather than retrying with `R5_ReadNoMerge`. [F58, F106]
- In `handle_stripe()`, transitioning out of `reconstruct_state_drain_result` or `reconstruct_state_prexor_drain_result` must not set `STRIPE_INSYNC` when `prexor != 0` or `s.failed > 1`. In `handle_stripe_fill()`, skipping `fetch_block()` to flush journaled degraded stripes (`s->to_read && s->injournal && s->failed`) must remain gated on `s->to_read`, and the loop must `break` as soon as `fetch_block()` returns `1`. In `delay_towrite()`, delaying for `R5C_LOG_CRITICAL` or `s->log_failed` requires `s->injournal > 0`. [F98, F99, F102]
- Every `md_write_inc(mddev, bi)` paired with `bio_inc_remaining(bi)` in `__add_stripe_bio()` and `make_discard_request()` must be balanced by `md_write_end(conf->mddev)` before `bio_endio()`/`bio_io_error()` in `handle_stripe_clean_event()` and `handle_failed_stripe()`. For aligned reads, `raid5_read_one_chunk()` increments `conf->active_aligned_reads` once; decrement it either on success in `raid5_align_endio()` or, if queued via `add_bio_to_retry()`, upon completion in `retry_aligned_read()`. [F15, F155]
- Before a newly allocated `stripe_head` is first passed to `raid5_release_stripe()`, set `sh->hash_lock_index` and increment `conf->active_stripes`. Whenever `conf->inactive_list + hash` transitions between empty and non-empty (`release_inactive_stripe_list()`, `get_free_stripe()`, `find_get_stripe()`), update `conf->empty_inactive_list_nr` in lockstep. When unlinking a stripe with `sh->group != NULL` in `find_get_stripe()` or `__get_priority_stripe()`, decrement `sh->group->stripes_cnt` and set `sh->group = NULL` under `conf->device_lock`. [F16, F19, F71]
- `check_reshape()` must call `resize_chunks()` and `resize_stripes()` before `raid5_start_reshape()` increases `raid_disks` or `chunk_sectors`, and neither may shrink `scribble_disks`, `scribble_sectors`, or `pool_size`. Size per-CPU `scribble` for the max of old/new `raid_disks` and `chunk_sectors`, update `scribble_disks`/`scribble_sectors` in `resize_chunks()` only after `scribble_alloc()` succeeds on all present CPUs, and use `struct_size_t(struct stripe_head, dev, devs)` for `max(raid_disks, previous_raid_disks)` in `kmem_cache_create()`. [F60, F86, F116]

## Synchronization

- `conf->device_lock` and `conf->hash_locks` are taken in I/O completion IRQ context, so process context must use `_irq`/`_irqsave`. Always acquire `conf->hash_locks[hash]` before `conf->device_lock` (and `0..NR_STRIPE_HASH_LOCKS-1` in ascending order in `lock_all_device_hash_locks_irq()`). All `stripe_hashtbl` and `inactive_list[hash]` mutations (`insert_hash()`, `remove_hash()`, `__find_stripe()`, `get_free_stripe()`) must hold `conf->hash_locks[hash]`. [F24, F30, F135]
- In `find_get_stripe()`, if `atomic_inc_not_zero(&sh->count)` fails on a hashed stripe, acquire `conf->device_lock` while still holding `conf->hash_locks[hash]` and recheck `!atomic_read(&sh->count)` before unlinking `sh->lru` and incrementing `sh->count`. Each `temp_inactive_list` (`conf`, `worker`, `cb`) must only be appended to by its owner under `conf->device_lock` and drained via `release_inactive_stripe_list()` under `conf->hash_locks[hash]` after dropping `conf->device_lock`. [F26, F31]
- `handle_active_stripes()` is entered with `conf->device_lock` held and must re-acquire `spin_lock_irq(&conf->device_lock)` before returning on every exit path after dropping it. In `raid5_remove_disk()`, removing a journal device (`test_bit(Journal, &rdev->flags) && conf->log`) runs in `raid5d` context and must never sleep; immediately return `-EBUSY` if `active_stripes`, `r5c_cached_full_stripes`, or `r5c_cached_partial_stripes` is non-zero. [F13, F146]
- `handle_stripe()` must acquire exclusive ownership via `test_and_set_bit_lock(STRIPE_ACTIVE, &sh->state)` after `clear_batch_ready(sh)` returns 0 (re-setting `STRIPE_HANDLE` and returning if already active). Attaching, detaching, or checking overlap of bios on `sh->dev[i].toread`/`towrite` and updating `sh->overwrite_disks` require `sh->stripe_lock`. `lock_two_stripes()` locks the lower address first, and `head->batch_head->batch_lock` nests inside `stripe_lock` (rechecking `stripe_can_batch(head)` under `batch_lock`). [F20, F28, F29, F137]
- In `raid5_start_reshape()`, update geometry (`previous_raid_disks`, `raid_disks`, `prev_chunk_sectors`, `chunk_sectors`, `prev_algo`, `algorithm`), `conf->generation++`, and `conf->reshape_progress` under `conf->device_lock` and `write_seqcount_begin(&conf->gen_lock)` with `smp_mb()` before `reshape_progress`, then cycle `raid5_quiesce(mddev, true)` and `false`. `use_new_offset()` must execute `smp_rmb()` after reading `reshape_progress` and before reading `generation` or `rdev->data_offset` (paired with `smp_wmb()` in `end_reshape()`). [F22, F40, F63]
- In `get_reshape_loc()`, after lockless `conf->reshape_progress == MaxSector` fails, sample `reshape_progress` and `reshape_safe` together under `conf->device_lock` and recheck `reshape_progress == MaxSector` before `ahead_of_reshape()`. In `init_stripe()` and `make_stripe_request()`, guard reshape geometry reads and stripe lookup with `read_seqcount_begin`/`retry(&conf->gen_lock)`, rechecking `stripe_ahead_of_reshape()` after `raid5_get_active_stripe()` when `previous` is set. [F34, F35]
- `raid5_quiesce(mddev, true)` must set `smp_store_release(&conf->quiesce, 2)`, wait for `active_stripes == 0` and `active_aligned_reads == 0`, then set `conf->quiesce = 1` and wake `wait_for_reshape`; `raid5_read_one_chunk()` must increment `active_aligned_reads` before checking `smp_load_acquire(&conf->quiesce) != 0`. In `release_stripe_list()` and `raid5_unplug()`, `smp_mb()` / `smp_mb__before_atomic()` must precede `clear_bit(STRIPE_ON_RELEASE_LIST / STRIPE_ON_UNPLUG_LIST, &sh->state)` before `__release_stripe()`. [F38, F39, F129]
- Hold `conf->cache_size_mutex` whenever growing, shrinking, or resizing the stripe cache; `raid5_cache_scan()` and `raid5d()` (`R5_ALLOC_MORE`) must use `mutex_trylock()`, and `raid5_set_cache_size()` must drop `cache_size_mutex` around `md_allow_write(mddev)`. Lockless `raid5_cache_count()` must read `max_nr_stripes` and `min_nr_stripes` with `READ_ONCE()` and check `max_stripes < min_stripes` before subtracting. In `resize_stripes()`, update `conf->slab_cache` and `conf->active_name` before calling `raid5_release_stripe()`. [F18, F25, F37, F142]
- In `raid_run_ops()`, hold `local_lock(&conf->percpu->lock)` before `this_cpu_ptr(conf->percpu)` and across all `ops_run_*` helpers using `percpu->scribble` or `spare_page`. Handlers replacing stripe buffers, queue limits, worker groups, or logging state (`raid5_store_stripe_size()`, `raid5_store_skip_copy()`, `raid5_store_group_thread_cnt()`, `raid5_change_consistency_policy()`) must use `mddev_suspend_and_lock(mddev)`, and `raid5_store_skip_copy()` must update `BLK_FEAT_STABLE_WRITES` via `queue_limits_start/commit_update()`. [F138, F149, F159]

## Object Lifetimes

- Before blocking on `wait_for_quiescent`, `wait_for_stripe`, `wait_for_reshape`, or `R5_Overlap` during bio submission (`raid5_get_active_stripe()`, `add_all_stripe_bios()`, `raid5_make_request()`), callers holding `ctx->batch_last` must release it via `raid5_release_stripe()` and set `ctx->batch_last = NULL`. When `ops_run_io()` issues I/O for a batched member (`sh != head_sh`), increment both `sh->count` and `head_sh->count`, and in `raid5_end_write_request()` release `sh->batch_head` before `sh`. [F2, F4]
- Every `rdev->nr_pending` reference acquired in `analyse_stripe()` for `s->blocked_rdev` or `s->handle_bad_blocks` (`R5_WriteError`, `R5_MadeGood`, `R5_MadeGoodRepl`) must be released in `handle_stripe()` before `clear_bit_unlock(STRIPE_ACTIVE, &sh->state)`. In `ops_run_io()`, after incrementing `rdev->nr_pending` for a write, checking `rdev_has_badblock()` must increment `rdev->nr_pending` a second time before `md_wait_for_blocked_rdev()` (`bad < 0`), or call `rdev_dec_pending()` and set `rdev = NULL` when skipping (`bad > 0`). [F5, F8]
- In `raid5_run()`, once `conf->thread` is moved to `mddev->thread` and `mddev->private = conf` is set, any error jumping to `abort:` must call `md_unregister_thread(mddev, &mddev->thread)` before `free_conf(conf)` and reset `mddev->private = NULL`. [F9]

## API Contracts

- When `raid5_read_one_chunk()` returns `0` to fall back to the stripe cache, it must not call `bio_put(raid_bio)` or `md_account_bio(mddev, &raid_bio)` because `raid5_make_request()` retains ownership. Callers of `raid5_get_active_stripe()` passing `R5_GAS_NOBLOCK` must check for a `NULL` return. In `ops_run_io()` and `analyse_stripe()`, store `rdev_has_badblock()` in a signed `int` to distinguish `< 0` (unacknowledged), `> 0` (acknowledged), and `0`. [F1, F44, F46]
- `raid5_compute_sector()` takes an array-relative `r_sector`, returns a per-disk sector (without `rdev->data_offset`), requires a non-NULL `int *dd_idx`, and takes an optional `sh`; because `raid5_compute_blocknr()` and `raid5_bio_lowest_chunk_sector()` pass an uninitialized stack `struct stripe_head` (zero-length `dev[]`), `raid5_compute_sector()` must only write `sh->pd_idx`, `sh->qd_idx`, and `sh->ddf_layout` and never read `sh` or index `sh->dev[]`. [F53, F120]
-When walking an `r5dev` bio chain (`toread`, `read`, `towrite`, `written`), bound iteration with `bi->bi_iter.bi_sector < dev->sector + RAID5_STRIPE_SECTORS(conf)` and advance via `r5_next_bio(conf, bi, dev->sector)` (saving next before `bio_endio()`/`bio_io_error()`), never raw `bi->bi_next`. `raid5_end_read_request()` and `raid5_end_write_request()` match `bi` against `&sh->dev[i].req` or `&sh->dev[i].rreq` across `0 <= i < sh->disks` (calling `BUG()` if not found) and must not be used on cloned bios. [F91, F121]
- Do not conflate stripe allocation return values: `grow_one_stripe()` and `drop_one_stripe()` return `1` on success and `0` on failure, whereas `grow_stripes()` and `grow_buffers()` return `0` on success and non-zero on failure. In `resize_stripes()`, once Step 2 drains `conf->inactive_list` (stalling array I/O), all allocations until Step 4 completes must use `GFP_NOIO`. In `raid5_set_cache_size()`, if `grow_one_stripe()` fails, roll back `conf->min_nr_stripes = conf->max_nr_stripes` under `cache_size_mutex`. [F45, F59, F141]

## Error Handling

- Callers of `setup_conf()` (`raid5_run()`, `raid5_takeover_raid1()`) must check its return value with `IS_ERR(conf)` and `PTR_ERR(conf)`, as it returns `ERR_PTR()` rather than `NULL`. Inside `setup_conf()`, after any helper overwrites `ret` with `0` (such as `bioset_init()` or `raid5_alloc_percpu()`), subsequent failure branches jumping to `abort` must explicitly set `ret` to a negative errno. [F41, F42]

## Known Pitfalls

- When aligning a `sector_t` down with `& ~(align - 1)`, cast the alignment unit (`RAID5_STRIPE_SECTORS(conf)`, `chunk_sectors`, `prev_chunk_sectors`, `reshape_sectors`) to `sector_t` before `- 1` and `~` to avoid 32-bit mask truncation on 32-bit kernels. Use `sector_div()`, `do_div()`, or `DIV_ROUND_UP_SECTOR_T()` instead of `/` or `%` on `sector_t`/`u64`, passing a temporary copy (`tmp_sec`, `stripe2`) when the dividend is still needed. In `reshape_request()`, clamp forward-reshape `readpos`/`safepos` subtractions with `min_t(sector_t, reshape_sectors, ...)` and check `writepos >= reshape_sectors` on backward reshapes. [F83, F107, F112, F113]
- In completion and bad-block paths (`raid5_end_read_request()`, `raid5_end_write_request()`, and `R5_MadeGoodRepl` in `handle_stripe()`), if `conf->disks[i].replacement` has become `NULL`, fall back to `conf->disks[i].rdev`. [F72]
