# IRQ SUBSYSTEM

The Generic IRQ (`genirq`) subsystem manages interrupt descriptors (`struct irq_desc`), hardware interrupt controllers (`struct irq_chip`), flow handlers, and device interrupt actions (`request_threaded_irq` / `free_irq`). It coordinates hardirq and threaded IRQ execution, SMP affinity and CPU hotplug migration, wakeup and suspend/resume power management, spurious interrupt detection, IPI multiplexing, and vector matrix allocation.

## Architecture & Data Flow

- Convert `struct irq_data *` to `struct irq_desc *` via `irq_data_to_desc()` (never `container_of(data, struct irq_desc, irq_data)`), get top-level `irq_data` via `irq_desc_get_irq_data(irq_data_to_desc(data))`, and when `CONFIG_IRQ_DOMAIN_HIERARCHY` may be disabled, walk parents via `irqd_get_parent_data()` rather than `d->parent_data`. [F128, F174]
- An initialized `struct irq_desc` never has a NULL `desc->irq_data.chip`; teardown and initialization install `&no_irq_chip`, so unassigned-chip checks must test `chip == &no_irq_chip`. [F49]
- Updating `desc->status_use_accessors` in `irq_modify_status()`, `__irq_set_trigger()`, or `__setup_irq()` must synchronize `IRQD_NO_BALANCING`, `IRQD_PER_CPU`, `IRQD_LEVEL`, and `IRQD_TRIGGER_MASK` in `desc->irq_data` under `desc->lock`; any new `IRQD_*` flag in `include/linux/irq.h` requires a `BIT_MASK_DESCR(IRQD_*)` entry in `irqdata_states[]`. [F62, F79]
- In `irq_startup()`, normal (non-managed) IRQs must call `irq_setup_affinity(desc)` before `__irq_startup(desc)` when `IRQCHIP_AFFINITY_PRE_STARTUP` is set in `d->chip->flags`, and after `__irq_startup(desc)` otherwise. `irq_shutdown()` on a started IRQ increments `desc->depth` (and aborted managed startup in `irq_startup()` sets `desc->depth = 1` with `IRQD_MANAGED_SHUTDOWN`), while `irq_startup_managed()` clears `IRQD_MANAGED_SHUTDOWN`, decrements `desc->depth`, and only calls `irq_startup()` when `desc->depth == 0`. [F64, F136]
- When `alloc_descs()` initializes an IRQ from `struct irq_affinity_desc` or `irq_set_affinity_deactivated()` stores a mask on an unactivated `IRQD_AFFINITY_ON_ACTIVATE` IRQ, `IRQD_AFFINITY_SET` must be set alongside updating `desc->irq_common_data.affinity` (and `effective_affinity`). In `irq_update_affinity_desc()`, if `irqd_is_activated(&desc->irq_data)` is true, call `irq_domain_deactivate_irq()` before setting `IRQD_AFFINITY_MANAGED | IRQD_MANAGED_SHUTDOWN` and updating `affinity`, and `irq_domain_activate_irq(&desc->irq_data, false)` afterward. [F63, F81]
- In `irq_move_masked_irq()`, `IRQD_SETAFFINITY_PENDING` is cleared before `irq_do_set_affinity(data, desc->pending_mask, false)`; if that returns `-EBUSY`, `IRQD_SETAFFINITY_PENDING` must be re-set and `desc->pending_mask` preserved, whereas all other outcomes must clear `desc->pending_mask`. [F72]
- Adding an `irqaction` to `desc->action` must call `irq_pm_install_action()` and removing one in `__free_irq()` or `__cleanup_nmi()` must call `irq_pm_remove_action()` under `desc->lock` so `nr_actions`, `force_resume_depth`, `no_suspend_depth`, and `cond_suspend_depth` stay balanced. In `__setup_irq()`, when sharing and `old->flags & IRQF_ONESHOT` is set, `IRQF_COND_ONESHOT` in `new->flags` must be promoted to `IRQF_ONESHOT` before checking `(old->flags ^ new->flags) & IRQF_ONESHOT`. [F68, F98]
- In `cond_unmask_eoi_irq()`, when `desc->istate & IRQS_ONESHOT` is set and `!irqd_irq_disabled(&desc->irq_data) && irqd_irq_masked(&desc->irq_data) && !desc->threads_oneshot`, `chip->irq_eoi(&desc->irq_data)` must be called before `unmask_irq(desc)` even on `IRQCHIP_EOI_THREADED` chips. [F110]
- In `irq_sw_resend()`, a nested threaded IRQ (`irq_settings_is_nested_thread(desc)`) must redirect `desc` to `irq_to_desc(desc->parent_irq)`, and adding `desc->resend_node` to `irq_resend_list` under `irq_resend_lock` must be guarded by `hlist_unhashed(&desc->resend_node)` (with `clear_irq_resend()` unlinking it in `irq_shutdown()`). [F71]
- In `suspend_device_irq()`, a non-wakeup IRQ on an `IRQCHIP_MASK_ON_SUSPEND` chip must call `mask_irq(desc)` in addition to `__disable_irq(desc)`; a disabled wakeup IRQ on an `IRQCHIP_ENABLE_WAKEUP_ON_SUSPEND` chip must be enabled with `__enable_irq(desc)` and `IRQD_IRQ_ENABLED_ON_SUSPEND`, then re-disabled by `__disable_irq(desc)` in `resume_irq()`. `irq_set_irq_wake()` must reject NMIs (`irq_is_nmi(desc)`) with `-EINVAL`, and under `scoped_irqdesc_get_and_buslock()` only call `set_irq_wake_real()` and update `IRQD_WAKEUP_STATE` on `wake_depth` 0<->1 transitions, rolling back on error. [F152, F154, F155]
- In `kernel/irq/matrix.c`, mutating `cm->alloc_map` or `cm->managed_map` must update `cm->available`, `cm->allocated`, `cm->managed`, and `cm->managed_allocated` in lockstep, adjusting `m->global_available` and `m->total_allocated` only when `cm->online` is true (and leaving `available`/`global_available` unchanged on managed alloc/free). [F66]

## Synchronization

- Lock ordering is strictly `desc->request_mutex` -> `chip_bus_lock(desc)` -> `desc->lock` -> `irq_resend_lock`. In `__setup_irq()` error cleanup when `!desc->action`, `irq_release_resources(desc)` must run after unlocking `desc->lock` and before `chip_bus_sync_unlock(desc)`. Paths invoking slow-bus `irq_chip` callbacks (`irq_set_wake`, `irq_set_type`, `irq_get_irqchip_state`) must use `scoped_irqdesc_get_and_buslock()` rather than `scoped_irqdesc_get_and_lock()`. `resend_irqs()` must unlink `desc->resend_node` with `hlist_del_init()` and drop `irq_resend_lock` before calling `desc->handle_irq(desc)`. [F4, F23, F35]
- Process-context callers acquiring `desc->lock` (or `gc_lock` / `gc->lock` in early-boot paths like `irq_domain_alloc_generic_chips()` and `irq_map_generic_chip()`) must disable interrupts via `raw_spinlock_irq` or `raw_spinlock_irqsave`. Code inside `scoped_irqdesc_get_and_lock()` or `scoped_irqdesc_get_and_buslock()` must not manually re-lock `desc->lock`. `irq_setup_alt_chip()` must only be called from `chip->irq_set_type()` or while holding `desc->lock`. [F22, F156, F157, F182]
- Any loop waiting for `irqd_irq_inprogress(&desc->irq_data)` to clear must drop `desc->lock` (and `chip_bus_sync_unlock(desc)` in `irq_finalize_oneshot()`) while spinning and recheck state after relocking: `__synchronize_hardirq()` rechecks `irqd_irq_inprogress` under `desc->lock` and, when `sync_chip` is true (`__synchronize_irq()`), queries `__irq_get_irqchip_state(irqd, IRQCHIP_STATE_ACTIVE, &inprogress)`; `irq_finalize_oneshot()` rechecks `IRQTF_RUNTHREAD` before clearing `action->thread_mask` from `desc->threads_oneshot` and calling `unmask_threaded_irq(desc)`; `irq_wait_on_inprogress()` revalidates `!irqd_irq_disabled(&desc->irq_data) && desc->action`. [F27, F28, F34, F108]
- Because `handle_irq_event()` drops and reacquires `desc->lock`, the `IRQS_PENDING` retry loops in `handle_edge_irq()` and `try_one_irq()` must re-verify `desc->action` on every iteration (plus `!irqd_irq_disabled(&desc->irq_data)` in `handle_edge_irq()`). In `suspend_device_irqs()`, `suspend_device_irq(desc)` runs under `desc->lock`, which must be released before calling `synchronize_irq(irq)`—including when `suspend_device_irq()` only sets `IRQD_WAKEUP_ARMED`. [F37, F109]
- `irq_set_thread_affinity()` runs under `desc->lock` and must only set `IRQTF_AFFINITY` and wake the kthreads; `irq_thread_check_affinity()` copies the effective affinity mask under `desc->lock` and calls `set_cpus_allowed_ptr()` after unlocking. Real-time priority (`sched_set_fifo(current)`) must be set inside `irq_thread()` on `current`, not in `setup_irq_thread()`. In `irq_forced_thread_fn()`, force-threaded handlers (`IRQTF_FORCED_THREAD`) must run with `local_bh_disable()` and, on `!CONFIG_PREEMPT_RT` kernels, `local_irq_disable()` across `irq_thread_fn()`. [F29, F159, F160]
- Unserialized flow handlers (`handle_percpu_irq`, `handle_percpu_devid_irq`, `handle_fasteoi_nmi`, `handle_percpu_devid_fasteoi_nmi`) must call `__kstat_incr_irqs_this_cpu(desc)` without touching `desc->tot_count`, and `kstat_irqs_desc()` must sum per-CPU `desc->kstat_irqs->cnt` whenever `_IRQ_PER_CPU`, `_IRQ_PER_CPU_DEVID`, or `IRQS_NMI` is set. [F65]
- In `kernel/irq/ipi-mux.c`, `ipi_mux_send_mask()` must use `atomic_fetch_or_release()` on `icpu->bits` followed by `smp_mb__after_atomic()` before reading `icpu->enable`, pairing with `atomic_or()` on `icpu->enable` and `smp_mb__after_atomic()` before reading `icpu->bits` in `ipi_mux_unmask()`. [F31]

## Object Lifetimes

- Every `__setup_irq()` caller (`request_threaded_irq()`, `request_nmi()`, `setup_percpu_irq()`, `__request_percpu_irq()`, `request_percpu_nmi()`) must call `irq_chip_pm_get(&desc->irq_data)` beforehand and `irq_chip_pm_put()` if `__setup_irq()` fails; on success, `__free_irq()`, `__cleanup_nmi()`, or `__free_percpu_irq()` drops the reference. `__setup_irq()` does not free `new->secondary` allocated by `irq_setup_forced_threading()` on error—`request_threaded_irq()` must `kfree(action->secondary)`. [F1, F2]
- `setup_irq_thread()` takes an extra reference via `get_task_struct(t)`, so `__setup_irq()` (`out_thread`) and `__free_irq()` must stop and release threads with `kthread_stop_put()`. `init_desc()` must initialize `desc->wait_for_threads`, and `__setup_irq()` must call `wake_up_and_wait_for_irq_thread_ready()` for both `new` and `new->secondary`. `irq_thread()` must register `irq_thread_dtor` via `task_work_add()` before its loop and cancel it with `task_work_cancel_func()` on normal exit after `kthread_should_stop()`. [F3, F14, F25]
- `irq_shutdown_and_deactivate()` must call `irq_domain_deactivate_irq(&desc->irq_data)` unconditionally after `irq_shutdown(desc)` even when `irqd_is_started(&desc->irq_data)` is false, because `irq_activate()` can activate an IRQ before startup. During CPU offline in `migrate_one_irq()`, `irq_force_complete_move(desc)` must run before checking `irqd_is_per_cpu(d) || !irqd_is_started(d) || !irq_needs_fixup(d)`. [F9, F11]
- Under `CONFIG_SPARSE_IRQ`, `free_desc()` (under `sparse_irq_lock`) must remove debugfs, procfs, and sysfs entries (`irq_remove_debugfs_entry`, `unregister_irq_proc`, `irq_sysfs_del`) before `delete_irq_desc(irq)`, and free `desc`, its cpumasks, and `kstat_irqs` via `call_rcu(&desc->rcu, delayed_free_desc)`. `irq_sysfs_del()` must only call `kobject_del(&desc->kobj)` when `desc->istate & IRQS_SYSFS` is set. `irq_domain_remove_sim()` must call `irq_work_sync(&work_ctx->work)` before freeing `work_ctx->pending`, `work_ctx`, and calling `irq_domain_remove(domain)`. [F7, F17, F30]

## API Contracts

- Callers registering an affinity notifier (`irq_set_affinity_notifier()`) or hint (`__irq_apply_affinity_hint()`) must clear them (`NULL`) before `free_irq()`. IRQs requested with `devm_request_*_irq()` must be freed with `devm_free_irq()`, not `free_irq()`. Descriptors with `_IRQ_PER_CPU_DEVID` (`irq_settings_is_per_cpu_devid(desc)`) use `action->percpu_dev_id` and `desc->percpu_enabled`: global IRQ APIs must reject them (`IRQ_GET_DESC_CHECK_GLOBAL`), per-CPU devid APIs require them (`IRQ_GET_DESC_CHECK_PERCPU`), and they must pair with `handle_percpu_devid_irq()` or `handle_percpu_devid_fasteoi_nmi()`. [F13, F15, F51, F131]
- Unlike `irq_get_*(irq)`, `irq_data_get_*(struct irq_data *d)` accessors unconditionally dereference `d` (and `d->common`), so callers (`ipi_send_verify()`, `ipi_send_single()`, `ipi_get_hwirq()`) must verify `d != NULL` first. Wildcard Linux IRQ allocation macros (`irq_alloc_desc()`, `devm_irq_alloc_desc()`) must pass `from = 1` (not 0), whereas hardware IRQ numbers treat `0` as valid and use `INVALID_HWIRQ` (`~0UL`) as the invalid sentinel. [F42, F48, F84]
- In `irq_do_set_affinity()`, when `force` is true `mask` is passed directly to `chip->irq_set_affinity()` without intersecting `cpu_online_mask`; when `force` is false `prog_mask` is filtered by `cpu_online_mask` and rejected with `-EINVAL` if empty. `irq_set_affinity_deactivated()` only defers `chip->irq_set_affinity()` when `CONFIG_IRQ_DOMAIN_HIERARCHY` is enabled, `!irqd_is_activated(data)`, and `irqd_affinity_on_activate(data)` is set. [F43, F100]
- In `irq_do_set_affinity()` and `__irq_set_trigger()`, `IRQ_SET_MASK_OK` and `IRQ_SET_MASK_OK_DONE` update core state and fall through to `IRQ_SET_MASK_OK_NOCOPY` (normalizing `ret = 0`). Under `CONFIG_GENERIC_IRQ_EFFECTIVE_AFF_MASK`, `irq_set_affinity` callbacks returning `IRQ_SET_MASK_OK*` must populate a non-empty `effective_affinity` (and update `affinity` themselves for `NOCOPY`). In `__irq_set_trigger()`, `irq_set_type` must return `IRQ_SET_MASK_OK*` (calling `irqd_set_trigger_type()` itself for `NOCOPY`). [F112, F179, F180]
- In `struct irq_chip_generic`, `gc->irq_base` is a domain hwirq base when `gc->domain` is set and a virq base when NULL, so `irq_remove_generic_chip()` and `irq_gc_get_irq_data()` must translate `gc->irq_base + offset` via `irq_find_mapping()` when `gc->domain` is non-NULL. `irq_can_handle*()` helpers return `true` when an IRQ can be serviced; flow handlers must guard early return with `!irq_can_handle*(desc)`. [F41, F97]

## Error Handling

- In `class_irqdesc_lock_constructor()`, the `class_irqdesc_lock_t _t` compound initializer must finish before calling `__irq_get_desc_lock(irq, &_t.flags, ...)` in a separate statement so zero-initialization does not clobber `_t.flags`. Because `scoped_irqdesc_get_and_lock()` and `scoped_irqdesc_get_and_buslock()` skip their body when `__irq_get_desc_lock()` returns `NULL`, any status variable returned after the block must default to an error (e.g., `-EINVAL` or `false`). [F40, F50]
- `request_any_context_irq()` and `devm_request_any_context_irq()` return `IRQC_IS_HARDIRQ` (0) or `IRQC_IS_NESTED` (1) on success and negative errno on failure; wrappers must check `rc < 0` and preserve positive returns. Callers of `*get_irqchip_state()` (such as `__synchronize_hardirq()`) must initialize `*state` beforehand. [F44, F55]
- In `kernel/irq/matrix.c`, `matrix_alloc_area()` returns `>= m->alloc_end` and `matrix_find_best_cpu*()` returns `UINT_MAX` on failure; `irq_matrix_alloc*()` must check `cpumask_empty(msk)` first (returning `-EINVAL`), translate unsigned sentinels to `-ENOSPC`, and only write `*mapped_cpu` on success. In `irq_matrix_reserve_managed()`, `cleanup:` must stop at `failed_cpu` so `irq_matrix_remove_managed()` only runs on CPUs that succeeded in that call. [F59, F60, F101]

## Known Pitfalls

- `try_retrigger()` and `irq_chip_retrigger_hierarchy()` return `0` on failure and non-zero on success, whereas `irq_sw_resend()` and `check_irq_resend()` return `0` on success and negative errno on failure. [F46]
- In `__setup_irq()`, all `goto mismatch;` branches must precede the `do { ... old = *old_ptr; } while (old);` loop because `mismatch:` dereferences `old`, which is `NULL` after the loop; `IRQF_ONESHOT` thread mask allocation must check `thread_mask == ~0UL` before `ffz(thread_mask)` and shift with `1UL << ffz(thread_mask)`. In `note_interrupt()`, inside `if (action_ret & IRQ_WAKE_THREAD)`, use `if (action_ret == IRQ_WAKE_THREAD)` to defer spurious checking (`SPURIOUS_DEFERRED`) only when no primary handler returned `IRQ_HANDLED`, compare `desc->threads_handled_last` using `!=`, and use `time_after()` for `jiffies`. [F99, F111, F115, F123]
- In `irq_chip_shutdown_parent()` and `irq_chip_startup_parent()`, direct `parent->chip->irq_shutdown` / `irq_startup` calls take `parent` (`data->parent_data`), whereas fallback `irq_chip_disable_parent()` / `irq_chip_enable_parent()` calls must take the child `data`. Callers of `for_each_irq_desc_reverse(irq, desc)` must declare `irq` as a signed `int`. [F87, F104]
