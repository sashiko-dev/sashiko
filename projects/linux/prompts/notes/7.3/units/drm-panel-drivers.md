# DRM PANEL DRIVERS

This component contains DRM panel drivers for Samsung, Seiko, Sharp, Sitronix, Sony, Startek, and TDO display panels, along with `panel-simple` for generic DPI, LVDS, and MIPI-DSI panels. Drivers implement `drm_panel_funcs` to sequence regulators, GPIOs, bus transfers, and display modes, alongside optional `backlight_ops` and runtime PM handlers.

## Architecture & Data Flow

- In `panel-simple.c`, `panel_simple_dsi_probe()` downcasts `panel->desc` via `container_of(..., struct panel_desc_dsi, desc)`, so every `dsi_of_match` entry must point to a `struct panel_desc_dsi` whose `desc.connector_type` is not `DRM_MODE_CONNECTOR_LVDS`. In `panel_simple_override_nondefault_lvds_datamapping()`, `panel->desc` must be copied via `devm_kmemdup()` before mutating `bus_format` and `bpc`. [F28, F44]
- In `panel-simple.c`, every `platform_of_match` entry except `panel-dpi` must set `.data` to a non-NULL `struct panel_desc *`, and `panel-dpi` (`.data = NULL`) must remain last before the sentinel so `panel_simple_get_desc()` only falls back to `panel_dpi_probe()` when no specific compatible matches. [F29]
- In `panel-simple.c`, a `struct panel_desc` must specify either `modes` or `timings`, never both (`WARN_ON(panel->desc->num_timings && panel->desc->num_modes)`). `panel_simple_parse_panel_timing_node()` may populate `panel->override_mode` and set `panel->override_mode.type` (checked by `panel_simple_get_non_edid_modes()`) only when `desc->num_modes == 0`, `desc->num_timings != 0`, and a `panel->desc->timings[]` entry matches `ot->flags` and passes `PANEL_SIMPLE_BOUNDS_CHECK()`. [F30, F64, F106]
- In `panel-simple.c`, polarity flags in `display_timing.flags` (e.g., `DISPLAY_FLAGS_DE_HIGH`) must match `panel_desc.bus_flags` (e.g., `DRM_BUS_FLAG_DE_HIGH`). LVDS descriptors must pair `MEDIA_BUS_FMT_RGB666_1X7X3_SPWG` with `.bpc = 6` or `MEDIA_BUS_FMT_RGB888_1X7X4_{SPWG,JEIDA}` with `.bpc = 8` and limit `.bus_flags` to `DRM_BUS_FLAG_DE_{LOW,HIGH}` and `DRM_BUS_FLAG_DATA_{MSB_TO_LSB,LSB_TO_MSB}`; DPI/DSI descriptors must set `.bpc` to `6` or `8`, and DPI descriptors require non-zero `.bus_format` and valid `.bus_flags`. [F42, F124, F125]
- In `panel-samsung-sofef00.c`, `panel-sony-tulip-truly-nt35521.c`, and `panel-startek-kd070fhfid015.c`, `devm_backlight_device_register()` receives `struct mipi_dsi_device *dsi` as `devdata`, so their `backlight_ops` callbacks must cast `bl_get_data(bl)` to `struct mipi_dsi_device *`. In `panel-sony-acx565akm.c`, `acx565akm_cabc_attr_group` is on `&lcd->backlight->dev.kobj`, so its sysfs callbacks rely on `backlight_device_register()` storing `struct acx565akm_panel *lcd` as `dev_get_drvdata(&lcd->backlight->dev)`. [F97, F98]
- In `panel-sony-acx565akm.c`, `acx565akm_set_cabc_mode()` caches `lcd->cabc_mode = mode` unconditionally but only writes to hardware when `lcd->enabled` is true; `acx565akm_power_on()` must set `lcd->enabled = true` before calling `acx565akm_set_cabc_mode(lcd, lcd->cabc_mode)`. Also, `acx565akm_set_sleep_mode()` must wait for any remaining guard time and update `lcd->hw_guard_wait = msecs_to_jiffies(120)` and `lcd->hw_guard_end = jiffies + lcd->hw_guard_wait` after sleep mode commands. [F50, F51]
- In `panel-samsung-s6e63j0x03.c`, `ctx->bl_dev->props.power` must track panel power state across `prepare` (`BACKLIGHT_POWER_REDUCED`), `enable` (`BACKLIGHT_POWER_ON`), `disable` (`BACKLIGHT_POWER_REDUCED`), and `unprepare` (`BACKLIGHT_POWER_OFF`). `s6e63j0x03_update_gamma()` and `s6e63j0x03_enable()` must bracket MTP/gamma writes with `s6e63j0x03_apply_mtp_key(ctx, true)` (`0xf1, 0x5a, 0x5a`) and `s6e63j0x03_apply_mtp_key(ctx, false)` (`0xf1, 0xa5, 0xa5`). [F54, F55]
- In `panel-samsung-s6e8aa5x01-ams561ra01.c`, `s6e8aa5x01_ams561ra01_update_status()` must check `if (!ctx->panel.enabled) return 0;` before sending DSI commands, and bracket gamma/AID writes with `MCS_ACCESSPROT` unlock (`0xf0, 0x5a, 0x5a`), `MCS_GAMMAUPD` (`0xf7, 0x03`), and lock (`0xf0, 0xa5, 0xa5`). `s6e8aa5x01_ams561ra01_probe()` must set `ctx->bl->props.max_brightness` to at most `ARRAY_SIZE(s6e8aa5x01_ams561ra01_cmds) - 1`. [F56, F60]
- In `s6e88a0_ams427ap24_set_brightness()`, `candela_enum` must be validated against `CANDELA_10CD ... CANDELA_300CD`, `s6e88a0_ams427ap24_elvss` indexed at `0` for `candela_enum <= CANDELA_111CD` and `candela_enum - CANDELA_111CD` otherwise, and `s6e88a0_ams427ap24_{aid,elvss,gamma}` (trailing `VAR_LEN_*` bytes) copied at offset `FIX_LEN_*` after the fixed header bytes in `b2`, `b6`, and `ca`. [F61, F94]
- In `s6e63m0_probe()`, `"max-brightness"` must be clamped to `MAX_BRIGHTNESS` (`NUM_GAMMA_LEVELS - 1`) because `s6e63m0_set_brightness()` indexes gamma/ACL/ELVSS tables with `bd->props.brightness`. In `s6e63j0x03_get_brightness_index()`, `index` must be clamped to `NUM_GAMMA_STEPS - 1` when `brightness / (MAX_BRIGHTNESS / NUM_GAMMA_STEPS) >= NUM_GAMMA_STEPS` before `s6e63j0x03_update_gamma()` indexes `gamma_tbl`. [F58, F59]
- In `panel-startek-kd070fhfid015.c`, `dsi_dcs_bl_get_brightness()` and `dsi_dcs_bl_update_status()` clear `MIPI_DSI_MODE_LPM` in `dsi->mode_flags` before the DCS brightness transfer and must restore `dsi->mode_flags |= MIPI_DSI_MODE_LPM` afterward. [F57]
- In `st7789v_read_data()`, any `len` other than 1, 3, or 4 must be rejected with `-EOPNOTSUPP` before setting `xfer[1].len = len * 2` into the 4-element `u16 rxbuf[4]` stack array and unpacking 9-bit SPI words. [F69]

## Synchronization

- In `panel-sony-acx565akm.c`, `lcd->mutex` must be held across all post-probe calls to `acx565akm_transfer()`, `acx565akm_set_cabc_mode()`, `acx565akm_power_on()`, and `acx565akm_power_off()`. Because `acx565akm_bl_update_status()` acquires `lcd->mutex`, paths already holding `lcd->mutex` (such as `acx565akm_power_on()`) must call `acx565akm_bl_update_status_locked()` instead of `acx565akm_bl_update_status()` or `backlight_update_status()`. [F14, F118]
- In `panel-simple.c`, `panel_simple_probe()` must initialize `panel->desc`, `panel->supply`, `panel->enable_gpio`, and `panel->ddc` and call `dev_set_drvdata(dev, panel)` before `pm_runtime_enable(dev)` and `drm_panel_add(&panel->base)`. `panel_simple_remove()` must call `drm_panel_remove(&panel->base)` and `panel_simple_shutdown(dev)` before `pm_runtime_dont_use_autosuspend(dev)`, `pm_runtime_disable(dev)`, and `put_device(&panel->ddc->dev)` (and probe error cleanup must also call `pm_runtime_dont_use_autosuspend(dev)` before `pm_runtime_disable(dev)`). [F17, F18, F100]
- In `panel-simple.c`, `panel_simple_prepare()` must call `pm_runtime_put_autosuspend(panel->dev)` if `pm_runtime_get_sync(panel->dev)` fails. In `panel_simple_get_modes()`, all DDC EDID reads (`p->ddc`) and accesses to `p->drm_edid` must remain bracketed by `pm_runtime_get_sync()` and `pm_runtime_mark_last_busy()` / `pm_runtime_put_autosuspend()` because `panel_simple_suspend()` frees `p->drm_edid` and sets it to `NULL` on runtime suspend (`panel_simple_resume()` must wait `p->desc->delay.unprepare` since `p->unprepared_time` before re-enabling `p->supply`). [F102, F103, F120]
- In `s6e63j0x03_probe()`, `s6e88a0_ams427ap24_probe()`, and `s6e63m0_probe()` / `s6e63m0_spi_probe()`, bus/transport state (`ctx->dsi = dsi`, `dbi->read_commands = s6e63m0_dbi_read_commands`, `ctx->transport_data`, `ctx->dcs_read`, `ctx->dcs_write`) and backlight registration (`ctx->bl_dev` / `s6e88a0_ams427ap24_register_backlight()`) must complete before `drm_panel_add(&ctx->panel)` and `mipi_dsi_attach(dsi)`. On teardown, `s6e63j0x03_remove()` must call `drm_panel_remove()` before `backlight_device_unregister()`, and `s6e63m0_dsi_remove()` must call `mipi_dsi_detach(dsi)` before `s6e63m0_remove(&dsi->dev)`. [F19, F20, F21, F131]

## Object Lifetimes

- In `panel_simple_probe()` and `panel_simple_remove()`, the `ddc-i2c-bus` `device_node` must be released with `of_node_put(ddc)` immediately after `of_find_i2c_adapter_by_node(ddc)`, while `panel->ddc` must be released via `put_device(&panel->ddc->dev)` on probe failure and in `panel_simple_remove()`. [F3]
- In `panel-sony-acx565akm.c`, `acx565akm_probe()` must initialize `lcd->mutex` and run `acx565akm_detect(lcd)` before `acx565akm_backlight_init(lcd)` registers `lcd->backlight` and attaches `acx565akm_cabc_attr_group`. On `sysfs_create_group()` failure or in `acx565akm_remove()` (after `drm_panel_remove()`), `acx565akm_backlight_cleanup()` must remove the sysfs group before calling `backlight_device_unregister(lcd->backlight)`. [F6, F111]
- When a DSI panel driver's `.probe` registers the panel with `drm_panel_add()` (or `s6e63m0_probe()`) before calling `mipi_dsi_attach()` or `devm_mipi_dsi_attach()`, it must call `drm_panel_remove()` (or `s6e63m0_remove()`) if the DSI attach fails. [F11]
- In `panel-sharp-lq101r1sx01.c`, `sharp_panel_probe()` binds to both DSI-LINK1 (`secondary != NULL`) and DSI-LINK2 (`secondary == NULL`), but only allocates `struct sharp_panel` and calls `sharp_panel_add(sharp)` on DSI-LINK1 (initializing `sharp->link1`, `sharp->link2`, and `sharp_panel_add(sharp)` before `mipi_dsi_attach(dsi)`). `sharp_panel_remove()` must call `mipi_dsi_detach(dsi)` before `if (sharp) sharp_panel_del(sharp)`, and the `of_find_mipi_dsi_device_by_node()` reference on `&secondary->dev` must be released via `put_device()` on DSI-LINK1 probe failure (guarded by `if (secondary)`) and in `sharp_panel_del()`. [F22, F76, F109]

## API Contracts

- In `.get_modes` callbacks, each `struct drm_display_mode` allocated via `drm_mode_create()` or `drm_mode_duplicate()` transfers ownership to `connector` via `drm_mode_probed_add(connector, mode)`. In `panel_simple_get_timings()` and `seiko_panel_get_timings()`, `num_timings` must be clamped to `p->desc->num_timings` and `timings` checked for non-NULL before copying, while returning `p->desc->num_timings`. [F13, F63]
- In `s6e63m0`, `dcs_read` and `dcs_write` callbacks must normalize positive byte counts from `mipi_dsi_dcs_read()` / `mipi_dsi_dcs_write()` to `0` on success because `s6e63m0_dcs_read()` / `s6e63m0_dcs_write()` store their return value directly into `ctx->error`. Because `trsp` (`ctx->transport_data`) is `NULL` in `s6e63m0_dsi_probe()` (`dsi_mode == true`) and points to `struct mipi_dbi` only in `s6e63m0_spi_probe()`, DSI callbacks must derive `mipi_dsi_device` from `dev` rather than dereferencing `trsp`. [F23, F26]
- In `panel-samsung-s6e63m0*.c`, buffers passed to `s6e63m0_dcs_write()` must have `len > 0` with the DCS command at `data[0]` and `len - 1` parameter bytes at `data + 1`. `s6e63m0_spi_dcs_write()` must use `mipi_dbi_command_stackbuf()` (not `mipi_dbi_command_buf()`) because callers pass `static const` rodata and stack buffers. `s6e63m0_dsi_dcs_write()` must split payloads (`remain = len - 1`, which must not exceed `U8_MAX` / 255 because `u8 cmdwritten` is compared against `int remain`) into chunks of at most `S6E63M0_DSI_MAX_CHUNK` (15) bytes, prefixing subsequent chunks with an `MCS_GLOBAL_PARAM` (`0xb0`) write of `cmdwritten`. [F67, F87, F92, F93]
- MIPI DCS column, page, and partial-row address commands require inclusive 0-based start and end coordinates (e.g., `hdisplay - 1`, `vdisplay - 1`, `partial_end - 1`), and in `sharp_setup_symmetrical_split()` the left link must cover columns `[0, mode->hdisplay / 2 - 1]` while the right link covers `[mode->hdisplay / 2, mode->hdisplay - 1]`. [F68]
- In `panel-sharp-lq101r1sx01.c` and `panel-sony-acx565akm.c`, multi-byte offsets and status words are big-endian: `sharp_panel_write()` / `sharp_panel_read()` must encode the 16-bit offset in big-endian byte order, and `acx565akm_detect()` must convert the 4-byte `MIPI_DCS_GET_DISPLAY_STATUS` response with `__be32_to_cpu()`. In `panel-sony-acx565akm.c`, 9-bit SPI transfers require 2 bytes per word: `acx565akm_transfer()` must set `x->len = 2` for the command word (and when `rlen > 1 && wlen == 0`, set `bits_per_word = 10` and shift `cmd <<= 1`), while 1-word writes in `acx565akm_set_cabc_mode()` and `acx565akm_set_brightness()` must set bit 8 (`1 << 8`) in a 2-byte buffer. [F70, F71, F82]
- In MIPI-DSI panel drivers, `MIPI_DSI_MODE_NO_EOT_PACKET`, `MIPI_DSI_MODE_VIDEO_NO_HFP`, `MIPI_DSI_MODE_VIDEO_NO_HBP`, and `MIPI_DSI_MODE_VIDEO_NO_HSA` have negative polarity (setting the flag disables the packet/interval) and must only be set when the panel requires disabling them. [F83]
- New DRM panel drivers must not copy `panel_simple_shutdown()`'s calls to `drm_panel_disable()` and `drm_panel_unprepare()` into `.shutdown` or `.remove` callbacks, because modeset drivers handle shutdown via `drm_atomic_helper_shutdown()`. [F128]

## Error Handling

- In `sharp_ls060_prepare()`, `seiko_panel_prepare()`, and `stk_panel_prepare()`, where multiple regulators are enabled in stages, each failure label must disable only the supplies already enabled in reverse (LIFO) order. In `s6e63j0x03_prepare()`, `s6e88a0_ams427ap24_prepare()`, `s6e88a0_ams452ef01_prepare()`, `sharp_panel_prepare()`, `sharp_nt_panel_prepare()`, `sony_td4353_jdi_prepare()`, and `tdo_tl070wsh30_panel_prepare()`, any DSI or init failure after enabling supplies must disable those supplies before returning. [F9, F12]
- In `s6e8aa0` and `s6e63m0`, `ctx->error` short-circuits all subsequent `dcs_read`/`dcs_write` calls when negative and must be consumed and reset to `0` via `s6e8aa0_clear_error()` or `s6e63m0_clear_error()`. In `s6e8aa0_set_sequence()`, `s6e8aa0_read_mtp_id(ctx)` must run before `s6e8aa0_panel_init(ctx)` and set `ctx->error` to a negative errno on a short read, `id[0] == 0x00`, or an unknown `id[1]` variant so `s6e8aa0_brightness_set()` aborts on `ctx->error` before dereferencing `ctx->variant->gamma_tables`, and `s6e8aa0_prepare()` must call `s6e8aa0_unprepare()` if `ctx->error < 0`. [F10, F62, F114]
- In `sharp_nt_panel_add()` (`panel-sharp-ls043t1le01.c`), because probe continues when `devm_gpiod_get()` for `reset` returns an `ERR_PTR`, `sharp_nt->reset_gpio` must be reset to `NULL` on error so `sharp_nt_panel_prepare()` and `sharp_nt_panel_unprepare()` do not pass an `ERR_PTR` to `gpiod_set_value()`. [F31]
- Functions issuing MIPI DSI transfers via `mipi_dsi_*_multi()` helpers (such as `s6e88a0_ams427ap24_on()`, `sofef00_panel_on()`, and `dsi_dcs_bl_update_status()`) must zero-initialize `struct mipi_dsi_multi_context` (e.g., `{ .dsi = dsi }`) so `accum_err` starts at `0`. [F33]
- In `st7789v_check_id()` and `st7789v_prepare()`, SPI display ID verification (`MIPI_DCS_GET_DISPLAY_ID`) must be skipped when `ctx->spi->mode & SPI_NO_RX` is set, and a non-zero return from `st7789v_check_id()` in `st7789v_prepare()` must only log `dev_warn` rather than aborting panel preparation. [F116]

## External Contracts

- In `struct panel_desc`, `struct seiko_panel_desc`, and `struct drm_display_mode` definitions, physical dimensions (`size.width`/`size.height` and `width_mm`/`height_mm`) must specify the active display area in millimeters (not the mechanical outline) and match the aspect orientation (`hdisplay` vs `vdisplay`). [F38]
- When programming `MIPI_DCS_SET_PIXEL_FORMAT` on controllers requiring both RGB/DPI (bits [6:4]) and MCU/DBI (bits [2:0]) fields (`st7789v_prepare()`, `sharp_nt_panel_init()`, `sony_td4353_jdi_on()`, and `stk_panel_init()`), the 3-bit `MIPI_DCS_PIXEL_FMT_*` value must be placed in both nibbles (`(fmt << 4) | fmt`). [F40]
- In `panel-sony-acx565akm.c`, `cabc_mode_store()` must match the userspace input (after stripping an optional trailing newline) against `acx565akm_cabc_modes[]` and return `-EINVAL` if no entry matches or if `!lcd->has_cabc && i != 0`, while `cabc_mode_show()` and `cabc_available_modes_show()` must report `acx565akm_cabc_modes[0]` (`"off"`) when `!lcd->has_cabc`. [F72]

## Known Pitfalls

- Stack-allocated `struct spi_transfer` instances in `st7789v_spi_write()`, `st7789v_read_data()` (`panel-sitronix-st7789v.c`), and `acx565akm_transfer()` (`panel-sony-acx565akm.c`) must be zero-initialized (`= { }` or `memset()`) before populating fields and submitting to `spi_sync()` or `spi_sync_transfer()`. [F35]
