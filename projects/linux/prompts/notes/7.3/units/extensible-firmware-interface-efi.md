# EXTENSIBLE FIRMWARE INTERFACE (EFI)

This subsystem implements the pre-boot EFI Boot Stub (`drivers/firmware/efi/libstub/*`), architecture-specific EFI initialization and virtual runtime memory mappings (ARM, ARM64, LoongArch, RISC-V, x86), and core kernel EFI runtime service wrappers (`drivers/firmware/efi/*`). It also manages UEFI variable services (generic and OP-TEE StandaloneMM), capsule updates, Common Platform Error Record (CPER) parsing, ESRT/BGRT/MOK/RCI2/OVMF tables, TPM event logs, confidential computing unaccepted memory, and Apple device properties.

## Architecture & Data Flow

- On x86_64, `efi_map_region()` and `efi_map_region_fixed()` map each region in `efi_mm.pgd` at both `md->phys_addr` (1:1) and `md->virt_addr`, so `efi_update_mappings()` and `efi_unmap_pages()` must update or unmap both in lockstep, and `efi_map_next_entry()` must traverse `efi.memmap` in reverse via `efi_map_next_entry_reverse()`. [F59, F84]
- On x86, `efi_arch_mem_reserve()` must update `e820_table` to `E820_TYPE_RESERVED` via `e820__range_update()` and `e820__update_table()` whenever it inserts a reserved `EFI_MEMORY_RUNTIME` descriptor into `efi.memmap`. In `efi_reuse_config()`, `EFI_MEMORY_ATTRIBUTES_TABLE_GUID` must be overwritten with `EFI_INVALID_TABLE_ADDR` on kexec boots so `efi_memattr_init()` does not run against a runtime-only kexec memory map. [F52, F62]
- In `should_map_region()` (`arch/x86/platform/efi/efi.c`), the `EFI_MEMORY_RUNTIME` check must precede all exclusions, and the `EFI_CONVENTIONAL_MEMORY` with `EFI_MEMORY_SP` exclusion must precede `efi_is_mixed()`. In `efi_free_boot_services()`, the descriptor filter in the second copy loop must match the `num_entries++` filter in the first loop. [F93, F96]
- In `create_mapping_protection()` (`arch/arm64/kernel/efi.c`) and `efimem_to_pgprot_map()` (`arch/riscv/kernel/efi.c`), `(attr & (EFI_MEMORY_XP | EFI_MEMORY_RO)) == (EFI_MEMORY_XP | EFI_MEMORY_RO)` must be checked before `attr & EFI_MEMORY_RO`, and on arm64 `code_is_misaligned` must remain a `static` boolean latched via `|=`. [F91, F92]
- When iterating, indexing, sizing, or copying entries within an EFI memory map buffer (`efi.memmap` or `struct efi_memory_map`), pointer arithmetic and `memcpy()` lengths must use the runtime stride `desc_size` rather than `sizeof(efi_memory_desc_t)`. `__efi_mem_desc_lookup()` and `efi_memmap_entry_valid()` must bound `md->num_pages` against `0` and `(U64_MAX - md->phys_addr) >> EFI_PAGE_SHIFT` (`EFI_PAGES_MAX`) before shifting. [F106, F107, F115]
- In `drivers/firmware/efi/unaccepted_memory.c`, `struct efi_unaccepted_memory::size` is in bytes while `bitmap[]` is indexed by `unit_size` blocks from `phys_base`: `accept_memory()` and `range_contains_unaccepted_memory()` must extend `end` by `unit_size` when `(start + size - unaccepted->phys_base) % unit_size == 0` and clamp `end` to `unaccepted->size * unit_size * BITS_PER_BYTE`, while `process_unaccepted_memory()` must accept ranges with `end - start < 2 * unit_size` immediately before rounding. [F242, F243, F301]
- In `x86` and shared `libstub` code, UEFI union fields and methods must be accessed via `efi_table_attr()`, `efi_call_proto()`, `efi_bs_call()`, `efi_rt_call()`, `efi_dxe_call()`, or `efi_fn_call()`, and handle/event arrays via `for_each_efi_handle()`, `efi_get_handle_at()`, or `efi_set_event_at()`. [F209]
- In `exit_boot()`, `allocate_e820()` must pre-allocate `e820ext` (with `EFI_MMAP_NR_SLACK_SLOTS` headroom) and `unaccepted_table` before `efi_exit_boot_services()`, and `setup_e820()` populates `unaccepted_table->bitmap` via `process_unaccepted_memory()` from the post-EBS map while converting `EFI_UNACCEPTED_MEMORY` to `E820_TYPE_RAM`. When `install_cfg_tbl` is true in `efi_get_memory_map()`, `install_configuration_table` for `LINUX_EFI_BOOT_MEMMAP_GUID` must run before the final `get_memory_map` call (and be uninstalled with `NULL` on failure). [F234, F235]
- In `efi_decompress_kernel()` on x86, when `CONFIG_RANDOMIZE_BASE` is enabled and `!efi_nokaslr`, `boot_params->hdr.loadflags` must have `KASLR_FLAG` set in lockstep, and `seed[0]` must be zeroed if `cmdline_memmap_override` or AMI UEFI v2.0 or older is detected. Unlike `efi_pe_entry()`, `efi_handover_entry()` must zero `[_bss, _ebss)` before `efi_stub_entry()`, and `efi_allocate_bootparams()` must set `hdr->initrd_addr_max = INT_MAX`. [F216, F230, F239]

## Synchronization

- All `runtime-wrappers.c` callers using global `efi_rts_work` must hold `efi_runtime_lock` across `__efi_queue_work()` until `wait_for_completion(&efi_rts_work.efi_rts_comp)` returns and `efi_rts_work.efi_rts_id` is reset to `EFI_NONE`. On x86_64 mixed mode, every `efi_thunk()` call must hold `efi_runtime_lock` with IRQs disabled, while `*_nonblocking` thunks must use `spin_trylock_irqsave()` and return `EFI_NOT_READY` on contention. [F29, F187]
- Every virtual EFI runtime call in `efi_call_rts()` and `efi_call_virt_pointer()` must bracket the call with `arch_efi_call_virt_setup()` / `efi_call_virt_save_flags()` and `efi_call_virt_check_flags()` / `arch_efi_call_virt_teardown()` (x86_64 syncs low mappings skipping `[EFI_VA_END, EFI_VA_START)`, saves FPU/speculation, and enters `efi_mm`; arm64 loads `efi_mm` with preemption disabled, takes `efi_rt_lock`, and calls `__efi_fpsimd_begin()`; RISC-V disables preemption around switching to `efi_mm`). [F17, F60, F144, F188, F321]
- `efivar_lock()` and `efivar_trylock()` must release `efivars_lock` and return `-ENODEV` if `!__efivars->ops`. Callers of `efivar_get_variable()`, `efivar_get_next_variable()`, and `efivar_set_variable_locked()` must hold `efivars_lock`, and `efivar_ops_nh` notifier callbacks must never call functions that acquire `efivars_lock`. When `nonblocking` is true, `efi_query_variable_store()` must delegate to `query_variable_store_nonblocking()` without `GFP_KERNEL` allocations or blocking `efi.set_variable()` calls. [F33, F180, F196]
- In `drivers/firmware/efi/capsule.c`, `sg_pages` must be populated, cache-flushed via `efi_capsule_flush_cache_range()`, and unmapped before acquiring `capsule_mutex`; `efi_capsule_update_locked()` and `capsule_reboot_notify()` must hold `capsule_mutex` when accessing `stop_capsules`, `efi_reset_type`, or `capsule_pending`. [F25, F150]
- In `efi_mem_reserve_persistent()` and `efi_mem_reserve_iomem()`, allocations must use `GFP_ATOMIC`, slot claims must use `atomic_fetch_add_unless(&rsv->count, 1, rsv->size)`, and linking into `efi_memreserve_root->next` must hold `efi_mem_reserve_persistent_lock`. [F153]

## Object Lifetimes

- When `efi_capsule_update()` returns 0, neither `efi_capsule_update()` nor `efi_capsule_release()` may free `cap_info->pages` or `sg_pages[i]`, because firmware accesses them across reboot; in `capsule-loader.c`, `cap_info->index` must be set to `NO_FURTHER_WRITE_ACTION` (`-1`) both when `efi_free_all_buff_pages()` frees pages on failure and when `efi_capsule_submit_update()` succeeds. [F1, F56]
- `efi_memmap_install()` must only free the previous physical memory map via `__efi_memmap_free()` after `efi_memmap_unmap()` and a successful `__efi_memmap_init(data)`, whereas `__efi_memmap_init()` must never free the old physical map. Before `efi_memmap_init_late()`, the caller must call `efi_memmap_unmap()` to unmap `efi.memmap.map` and clear `EFI_MEMMAP`. [F5, F171]
- On x86, `__efi_enter_virtual_mode()` must call `efi_check_for_embedded_firmwares()` before `efi_free_boot_services()` unmaps `EFI_BOOT_SERVICES_CODE`. In `efi_alloc_page_tables()` (`arch/x86/platform/efi/efi_64.c`), `efi_pgd` must be allocated via `__get_free_pages()` rather than `pgd_alloc()`, and `pud_alloc()` failure must free the 5-level `p4d` page before `efi_pgd`. [F13, F22]
- In `efivar_ssdt_load()`, a successful `acpi_load_table(data, NULL)` transfers ownership of `data` to ACPI, so `kfree(data)` must only be called on failure. In `efi_query_variable_store()`, if the dummy variable write unexpectedly returns `EFI_SUCCESS`, `efi_delete_dummy_variable()` must be called before freeing `dummy`. [F4, F21]
- In `accept_memory()`, the stack-allocated `struct accept_range range` added to `accepting_list` under `unaccepted_memory_lock` must remain on `accepting_list` (with IRQs disabled and half-open `[start, end)` overlap checks using `<=` / `>=`) while `unaccepted_memory_lock` is dropped across `arch_accept_memory()`, and must be removed via `list_del(&range.list)` before returning. [F183, F241]
- In `efi_exit_boot_services()`, operations that modify the UEFI memory map such as `efi_pci_disable_bridge_busmaster()` must run before `efi_get_memory_map()`, and once `exit_boot_services()` has been called once, the retry path must reuse the existing map buffer without calling `allocate_pool` or `free_pool`. [F173]

## API Contracts

- Every function in `drivers/firmware/efi/runtime-wrappers.c` that invokes UEFI Runtime Services via a C indirect call must be annotated with `__nocfi`, and on x86_64 runtime service calls must use `arch_efi_call_virt()` rather than raw `efi_call()` so IBT is saved/disabled and restored. [F143, F289]
- In `efivar_set_variable_locked()`, if `set_variable_nonblocking` is `NULL`, `set_variable` is called even when `nonblocking` is true, so any `efivar_operations` backend with a sleeping `set_variable` (like `tee_stmm_efi.c`) must implement `set_variable_nonblocking`. Because `efivars_register()` allows only one `__efivars` singleton, `tee_stmm_efi_probe()` must call `efivars_generic_ops_unregister()` before registering `tee_efivars` and restore generic ops on removal. [F232, F320]
- In `tee_stmm_efi.c`, buffers registered with `tee_shm_register_kernel_buf()` must be allocated in `setup_mm_hdr(&comm_buf, payload_size, func)` via `alloc_pages_exact(COMM_BUF_SIZE(payload_size), ...)` (not slab), and callers must pass the base `comm_buf` (not the returned `var_hdr->data` pointer) to `mm_communicate()` and `free_pages_exact()`, while `tee_mm_communicate()` must always call `tee_shm_free(shm)`. [F181, F271, F331]
- `efi_get_embedded_fw()` returns a borrowed pointer in `*data` to `fw->data` owned by `efi_embedded_fw_list`, so callers must not `kfree(*data)`. Conversely, `realloc_pages(old_memmap, old_shift)` in `arch/x86/platform/efi/efi.c` always frees `old_memmap`, even when `__get_free_pages()` returns `NULL`. [F14, F15]
- `cper_estatus_check()`, `cper_estatus_check_header()`, and `cper_estatus_print()` (and all `cper_print_*` helpers) run in GHES NMI/hardirq/panic contexts and must not sleep or perform blocking allocations, and `cper_estatus_check()` must validate all header and section sizes before printing. [F78, F154]
- `process_unaccepted_memory(start, end)` and `arch_accept_memory(start, end)` take `[start, end)` physical addresses, whereas `accept_memory(start, size)` and `range_contains_unaccepted_memory(start, size)` take start address and byte length. In `efi_decompress_kernel()` on x86, `efi_random_alloc()` must be passed `LOAD_PHYSICAL_ADDR` as `alloc_min` and clamp `md->phys_addr` to `max(md->phys_addr, alloc_min)`. [F219, F224, F240]

## Error Handling

- In `drivers/firmware/efi/efi.c`, optional physical table addresses in `struct efi` (e.g., `acpi`, `smbios`, `esrt`, `tpm_log`, `mokvar_table`, `coco_secret`, `unaccepted`) are initialized to `EFI_INVALID_TABLE_ADDR` (`~0UL`) rather than `0`, so presence checks must compare against `EFI_INVALID_TABLE_ADDR`. In `efi_mem_reserve_persistent()`, `efi_memreserve_root` must be checked against both `(void *)ULONG_MAX` and `NULL`. [F34, F37]
- In `check_var_size()`, if `__efivars->ops->query_variable_store` is `NULL` or returns `EFI_UNSUPPORTED`, fall back to returning `EFI_SUCCESS` when `size <= SZ_64K` and `EFI_OUT_OF_RESOURCES` otherwise. In `tee_stmm_efi.c`, check both `rc < 0` and `arg.ret != 0` after `tee_client_invoke_func()` / `tee_client_open_session()`, and convert `EFI_NOT_FOUND` in `get_property_int()` to `EFI_SUCCESS` with `var_property` zeroed. [F203, F206, F208]
- In `allocate_new_fdt_and_exit_boot()`, `priv.runtime_map` is only allocated when `!efi_novamap` (so `free_pool` on error must be guarded by `if (!efi_novamap)`), and if `set_virtual_address_map()` fails after `efi_exit_boot_services()` succeeds, the stub must set `virt_addr = U64_MAX` on every `EFI_MEMORY_RUNTIME` descriptor and still return `EFI_SUCCESS`. [F172, F218]
- In functions returning an EFI pool buffer via a double-pointer out-parameter (`efi_handle_cmdline()`, `preserve_pci_rom_image()`, `efi_get_memory_map()`), `__free(efi_pool)` or error cleanup must operate on the local buffer pointer and only transfer it via `no_free_ptr()` on success. In `efi_tpm_eventlog_init()`, unsigned `tbl_size` must not be stored in the signed `int` (`final_tbl_size`) used for `tpm2_calc_event_log_size()`. [F201, F270]

## External Contracts

- In x86 mixed mode (`CONFIG_EFI_MIXED`), 64-bit output pointers/sizes in `efi64_thunk()` must use `efi64_zero_upper()`, 64-bit value arguments must use `__efi64_split()`, 32-bit status returns must use `__efi64_widen_efi_status()`, and every `__efi64_argmap_<func>` macro in `arch/x86/include/asm/efi.h` must match the exact `mixed_mode` method name passed to `efi_fn_call()`. [F53, F87]
- When storing or reading 64-bit addresses/sizes in split 32-bit `boot_params` or `screen_info` fields, use `efi_set_u64_split()` (and set `VIDEO_CAPABILITY_64BIT_BASE` when `ext_lfb_base` is non-zero) and cast upper 32-bit fields (`efi_memmap_hi`, `efi_systab_hi`, `ext_lfb_base`) to `u64` before `<< 32`. In `libstub`, tables persisting across kexec (`unaccepted_table` and RNG `seed`) must use `EFI_ACPI_RECLAIM_MEMORY` rather than `EFI_LOADER_DATA`. [F111, F259, F332]

## Known Pitfalls

- When copying a single descriptor out of `efi.memmap` into a standalone `efi_memory_desc_t` variable (e.g., `out_md` in `__efi_mem_desc_lookup()`), bound `memcpy()` to `sizeof(efi_memory_desc_t)` rather than `efi.memmap.desc_size`. When converting `md->num_pages` to bytes without `memrange_efi_to_native()`, shift by `EFI_PAGE_SHIFT` (12) rather than `PAGE_SHIFT`, and in `memrange_efi_to_native()`, compute `*npages = PFN_UP(*addr + (*npages << EFI_PAGE_SHIFT)) - PFN_DOWN(*addr)` before masking `*addr &= PAGE_MASK`. [F108, F116, F285]
- In `set_permissions()` (ARM, ARM64, RISC-V), sequential adjustments for `EFI_MEMORY_RO` and `EFI_MEMORY_XP` must accumulate into the local `pte`/`val` variable before writing `*ptep`, never re-reading the original PTE. When reserving EFI tables during early boot (`efi_tpm_eventlog_init()`, `efi_memattr_init()`), pass the physical table address to `memblock_reserve()`, never the virtual pointer from `early_memremap()`. [F54, F325]
- Because UEFI `allocate_pool` returns uninitialized memory, partially populated structures allocated via `allocate_pool` must be zeroed with `memset()`. In `drivers/firmware/efi/libstub/vsprintf.c`, format strings only support specifiers `c, s, o, p, x, X, d, i, u` and qualifiers `h, hh, l, ll` (never `%z` or `%t`), and `%.*ls` precision specifies maximum output UTF-8 bytes rather than UTF-16 code units. [F215, F295, F296]
- When removing entries inside `for_each_mem_region(r)` in `reserve_regions()`, decrement `r--` after `memblock_remove()`, and in `update_fdt()`, delete existing FDT memory reservations in reverse index order (`while (num_rsv-- > 0) fdt_del_mem_rsv(fdt, num_rsv);`). In `accept_memory()`, widen `unaccepted->unit_size` (`u32`) to `u64` before multiplying by bitmap sizes/indices and call `touch_softlockup_watchdog()` before `spin_unlock_irqrestore()`. [F98, F273, F281, F316]
