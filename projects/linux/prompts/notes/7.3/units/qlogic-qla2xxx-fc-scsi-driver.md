# QLOGIC QLA2XXX FC-SCSI DRIVER

This unit (`qla_attr.c`, `qla_bsg.c`, `qla_bsg.h`, `qla_dbg.c`, `qla_dbg.h`) implements Scsi_Host sysfs attributes and binary attributes, Fibre Channel transport callbacks including NPIV virtual port (`fc_vport`) lifecycle management, Block SG (BSG) ELS/CT passthrough and vendor commands, hardware register/RAM crash dumps, and structured kernel/tracepoint logging for the QLogic qla2xxx Fibre Channel HBA driver.

## Architecture & Data Flow
- When `bsg_request->msgcode == FC_BSG_RPT_ELS`, `bsg_job->dev` is an `fc_rport` rather than a `Scsi_Host`; `qla24xx_bsg_request()` and `qla2x00_process_els()` must obtain `rport` via `fc_bsg_to_rport(bsg_job)` and check `!rport` before calling `rport_to_shost(rport)` or reading `rport->dd_data`. [F38]
- Adapter-wide callbacks (`qla2x00_get_host_port_state`, `qla2x00_get_fc_host_stats`, `qla2x00_reset_host_stats`, `qla2x00_get_priv_stats`, and `*_fw_dump`) must use `base_vha = pci_get_drvdata(ha->pdev)` rather than a potentially virtual `vha`. [F57]
- In `qla_attr.c`, `ha->isp_ops->write_nvram` and `read_nvram` are NULL on ISP81xx/8044/83xx/27xx/28xx, `mpi_fw_dump` is NULL except on ISP27xx/28xx, and `beacon_on`/`beacon_off` are NULL on ISP2100/2200; callers must check the pointer or chip-type macro before invoking them, and when `qla2x00_sysfs_write_nvram` or `qla2x00_sysfs_write_vpd` writes via `write_nvram`, it must reload `ha->nvram`/`ha->vpd` via `read_nvram` under `ha->optrom_mutex` (plus `get_flash_version` for VPD). [F39, F54]
- `ha->queue_pair_map` is a 0-based sparse array of length `ha->max_qpairs` separate from `ha->base_qpair`; loops in `qla2x00_get_fc_host_stats`, `qla2x00_reset_host_stats`, and `qla24xx_bsg_timeout` must NULL-check `ha->queue_pair_map[i]` and handle `ha->base_qpair` explicitly. [F77]
- In `qla24xx_proc_fcp_prio_cfg_cmd`, `QLFC_FCP_PRIO_GET_CONFIG` and `QLFC_FCP_PRIO_SET_CONFIG` must reject `payload_len` when `!len || len > FCP_PRIO_CFG_SIZE`, update `ha->flags.fcp_prio_enabled` and `FCP_PRIO_ATTR_ENABLE` in `ha->fcp_prio_cfg->attributes` in lockstep followed by `qla24xx_update_all_fcp_prio(vha)`, and free and clear `ha->fcp_prio_cfg = NULL` if `qla24xx_fcp_prio_cfg_valid` fails. [F61, F79]
- `ql_ktrace()` must set `pbuf[0] = 0` before any early `break` (including `!trace_ql_dbg_log_enabled()`) because `ql_dbg*`/`ql_log*` callers test uninitialized stack `if (!pbuf[0])` before calling `ql_dbg_prefix()`; `ql_mask_match(level)` must require `level != 0` and be checked before string formatting or MMIO reads; `ql_log_all` (`3`) must never be passed to `ql_log`/`ql_log_pci`; and no `ql_dbg_*` bitmask may exceed `0x40000000` (signed `int`). [F91, F124, F161, F162]

## Synchronization
- In `qla2x00_process_els`, `qla2x00_process_ct`, `qla24xx_process_bidir_cmd`, and `qlafx00_mgmt_cmd`, all scatterlist DMA mappings, `fcport` fields, and `sp` fields (`type`, `u.bsg_job`, `free`, `done`) must be initialized before `qla2x00_start_sp` or `qla2x00_start_bidir` publishes `sp` to the request queue. [F18]
- `req->outstanding_cmds` is 1-based across `[1, req->num_outstanding_cmds)`; in `qla_bsg_found`, after attaching stack `sp->comp = &comp` and dropping `qpair->qp_lock_ptr` to abort and wait, the timeout/failure path must re-acquire `qpair->qp_lock_ptr`, verify `req->outstanding_cmds[cnt]` still matches `bsg_job` before clearing it to `NULL`, and reset `sp->comp = NULL` before calling `kref_put(&sp->cmd_kref, qla2x00_sp_release)`. [F65, F78]
- In `qla2x00_dev_loss_tmo_callbk` and `qla2x00_terminate_rport_io`, `fcport->scan_state != QLA_FCPORT_FOUND` must be checked before marking `fcport` dead or scheduling session deletion, and `rport->port_state != FC_PORTSTATE_ONLINE` must be checked under `host->host_lock` before clearing `fcport->rport` and `*rport->dd_data`. [F31]
- In `qla24xx_process_bidir_cmd`, `ha->selflogin_lock` must be held across checking `vha->self_login_loop_id == 0`, initializing `vha->bidir_fcport`, calling `qla2x00_fabric_login`, and storing `vha->self_login_loop_id`. [F28]
- All `isp_ops->fw_dump` callbacks in `qla_dbg.c` (`qla2100_fw_dump`, `qla2300_fw_dump`, `qla24xx_fw_dump`, `qla25xx_fw_dump`, `qla81xx_fw_dump`, `qla83xx_fw_dump`) require `ha->hardware_lock` held with IRQs disabled and must use `udelay()` and pre-allocated buffers (`ha->fw_dump`, `ha->gid_list`) without sleeping or allocating. [F141]

## Object Lifetimes
- In `qla2x00_bsg_job_done`, all fields of `sp` (`sp->u.bsg_job`, `sp->comp`, `sp->vha`, `sp->handle`) must be read before `kref_put(&sp->cmd_kref, qla2x00_sp_release)`, which invokes `sp->free(sp)` and frees `sp`. [F1]
- In `qla2x00_bsg_sp_free` and `qlafx00_mgmt_cmd`, `SRB_FXIOCB_BCMD` scatterlists (`request_payload` and `reply_payload`) are mapped and unmapped only when `piocb_rqst->flags` has `SRB_FXDISC_REQ_DMA_VALID` and `SRB_FXDISC_RESP_DMA_VALID` set; in `qla2x00_bsg_sp_free`, `sp->fcport` is freed asynchronously via `ha->wq` (`qla2xxx_free_fcport_work`, never synchronously in IRQ context) and only when `sp->type` is `SRB_CT_CMD`, `SRB_FXIOCB_BCMD`, or `SRB_ELS_CMD_HST` (`SRB_ELS_CMD_RPT` borrows the rport's `fcport` and `SRB_BIDI_CMD` uses embedded `vha->bidir_fcport`). [F5, F128, F140]
- `ha->optrom_mutex` must be held whenever accessing `ha->optrom_state`, `ha->optrom_buffer`, `ha->optrom_region_start`, or `ha->optrom_region_size` across sysfs (`qla2x00_sysfs_read_optrom`, `qla2x00_sysfs_write_optrom`, `qla2x00_sysfs_write_optrom_ctl`) and BSG (`qla2x00_optrom_setup`, `qla2x00_read_optrom`, `qla2x00_update_optrom`); `ha->optrom_buffer` is allocated only when `ha->optrom_state == QLA_SWAITING`, and every path that frees `ha->optrom_buffer` or fails `vzalloc` must set `ha->optrom_buffer = NULL` and `ha->optrom_state = QLA_SWAITING` before unlocking. [F8, F26]
- In `qla2x00_sysfs_read_xgmac_stats` and `qla2x00_sysfs_read_dcbx_tlv`, `vha->hw->optrom_mutex` must be acquired before checking whether `ha->xgmac_data` or `ha->dcbx_tlv` is `NULL`, and held across `dma_alloc_coherent`, `memset`, and the firmware mailbox fetch; these buffers remain owned by `ha` across subsequent reads and must not be freed at the end of the read. [F12, F27]
- In `qla24xx_vport_create`, `scsi_host_set_prot()` and `scsi_host_set_guard()` must run before `scsi_add_host_with_dma()`, while `fc_host_*` initialization (copying `supported_classes` and `supported_speeds` from `base_vha->host`), `qlt_vport_create()`, `qla24xx_vport_disable()`, and `qla2xxx_create_qpair()` must run after it succeeds; `qla2xxx_transport_vport_functions` must match `qla2xxx_transport_functions` except `.vport_create`, `.vport_disable`, and `.vport_delete` must remain NULL. [F59, F126, F151]
- In `qla24xx_vport_delete` (and `qla24xx_vport_create` error cleanup), `vha` resides in `shost_priv(vha->host)`, so `scsi_host_put(vha->host)` must be called last after: setting `VPORT_DELETE` and waiting for `LOOP_RESYNC_ACTIVE` to clear, `qla24xx_disable_vp(vha)`, `qla2x00_wait_for_sess_deletion(vha)`, `qlt_remove_target`, `fc_remove_host(vha->host)` (before `scsi_remove_host`), `scsi_remove_host(vha->host)`, `qla24xx_deallocate_vp_id(vha)`, decrementing `ha->cur_vport_count` and clearing `vha->vp_idx` in `ha->vp_idx_map` under `ha->vport_lock`, `qla2x00_vp_stop_timer(vha)`, `qla2x00_free_fcports(vha)`, freeing `vha->gnl.l`/`vha->scan.l`, and calling `qla2xxx_delete_qpair` only if `vha->qpair->vp_idx == vha->vp_idx`. [F14, F22, F58, F127, F152]
- `qla2x00_alloc_sysfs_attr()` and `qla2x00_free_sysfs_attr()` iterate `bin_file_entries[]` until the required `{ NULL }` sentinel and must apply identical hardware-capability predicates (`IS_FWI2_CAPABLE(ha)` for non-zero `iter->type`, `IS_QLA25XX(ha)` for type 2, `IS_CNA_CAPABLE(ha)` for type 3); because attributes are attached to `&host->shost_gendev.kobj`, their `.read`/`.write` callbacks must resolve `vha` via `dev_to_shost(container_of(kobj, struct device, kobj))` rather than `class_to_shost`. [F76, F129, F156]

## API Contracts
- In `qla2x00_process_els`, non-`ELS_AUTH_ELS` commands must validate that both `bsg_job->request_payload.sg_cnt` and `bsg_job->reply_payload.sg_cnt` are `<= 1` (returning `-ENOBUFS` otherwise) before DMA mapping. [F80]
- Flash Layout Table fields (`ha->flt_region_*`) are in 32-bit dword units and must be multiplied by 4 (`<< 2`) when used as byte offsets in `read_optrom()` or `qla2x00_optrom_setup()`; when determining active flash regions, `qla27xx_get_active_image()` populates `active_regions.global`, and on `IS_QLA28XX(ha)` adapters `qla28xx_get_aux_images()` must also be called before reading `active_regions.aux` fields. [F50, F130]
- `qla24xx_dump_ram()` and `qla27xx_dump_mpi_ram()` take `ram_dwords` in 32-bit dwords (so byte counts like `cram_size` in `qla24xx_dump_memory()` must be divided by 4), whereas `qla2xxx_dump_ram()` takes `ram_words` in 16-bit words; `ha->fw_memory_size` is the inclusive last RAM address, so `qla24xx_dump_memory` and `qla2300_fw_dump` must pass `ha->fw_memory_size - start_addr + 1`; and consecutive `qla24xx_read_window()` calls in `qla24xx`/`25xx`/`81xx`/`83xx_fw_dump` must assign `iter_reg = qla24xx_read_window(...)`. [F49, F85, F119]

## Error Handling
- In `qla2x00_process_els` and `qla2x00_process_ct`, when `qla2x00_start_sp(sp)` fails, the caller must release `sp` with `qla2x00_rel_sp(sp)` (not `sp->free(sp)` or `kref_put`) before jumping to `done_unmap_sg` or `done_free_fcport`; in `qla2x00_process_els`, `done_free_fcport` must call `qla2x00_free_fcport(fcport)` only when `qla_port_allocated` is set (not when borrowed from `rport->dd_data` for `FC_BSG_RPT_ELS`). [F2, F4]
- Unlike `qla2x00_start_sp()` (which returns `0` or a negative errno), `qla2x00_start_bidir()` returns `EXT_STATUS_OK` (`0`) or a positive `EXT_STATUS_*` code; in `qla24xx_process_bidir_cmd()`, `req_data_len` and `rsp_data_len` must be initialized from `payload_len` before comparing `req_data_len != rsp_data_len`, and if any precondition or `qla2x00_start_bidir()` fails, the function must unmap any mapped scatterlists, store the `EXT_STATUS_*` code in `bsg_reply->reply_data.vendor_reply.vendor_rsp[0]`, call `bsg_job_done` with `DID_OK << 16`, and return `0`. [F11, F33, F45]
- In `qla2x00_process_loopback`, `new_config` must be zero-initialized via `memset` before loopback mode setup; on `IS_QLA81XX`/`8031`/`8044`, `qla81xx_get_port_config` must verify `(config[0] & INTERNAL_LOOPBACK_MASK) == 0`, and if `new_config[0]` was set by `qla81xx_set_loopback_mode`, `qla81xx_reset_loopback_mode` must revert it after `qla2x00_loopback_test`; in `qla81xx_set_loopback_mode` and `qla81xx_reset_loopback_mode`, `ha->notify_dcbx_comp`, `ha->notify_lb_portup_comp`, `ha->idc_extend_tmo`, and `ha->flags.idc_compl_status` must be reset to 0 on every exit path (and in the `dcbx_comp` wait loop), and DMA resources must be torn down in reverse acquisition order. [F9, F47, F62, F63, F102]
- In `qla84xx_mgmt_cmd()`, `mn` is allocated from `ha->s_dma_pool` first, and `mgmt_b = NULL` and `dma_direction = DMA_NONE` must be initialized before the command switch so that `done_unmap_sg` frees `mgmt_b` (if non-NULL) and unmaps the scatterlist only when mapped before `exit_mgmt` frees `mn`; in `qla2x00_get_host_stats()` and `qla2x00_get_tgt_stats()`, if `kzalloc` for `data` fails, free `req_data` and return `-ENOMEM` without calling `bsg_job_done()`. [F10, F42, F43]
- `ha->isp_ops->write_optrom()` returns `QLA_SUCCESS` (`0`) or a positive `QLA_*` status code; callers (`qla2x00_sysfs_write_optrom_ctl()` and `qla2x00_update_optrom()`) must translate any non-zero return into a negative errno (`-EIO` or `-EINVAL`). [F35]
- In `qla2x00_terminate_rport_io()` and `qla2x00_dev_loss_tmo_callbk()`, if `pci_channel_offline(fcport->vha->hw->pdev)` is true, call `qla_pci_set_eeh_busy()`, wait via `qla2x00_eh_wait_for_pending_commands()`, and return without attempting session deletion or port logout; in `qla24xx_bsg_timeout()` and `qla_bsg_found()`, if `qla2x00_isp_reg_stat(ha)` is non-zero, call `qla_pci_set_eeh_busy(vha)`, and when `ha->flags.eeh_busy` is set, `qla_bsg_found()` must skip `ha->isp_ops->abort_command(sp)` and wait on `sp->comp`. [F138, F139]

## External Contracts
- Because `fc_bsg_host_dispatch` and `fc_bsg_rport_dispatch` call `bsg_job_done()` and overwrite `bsg_reply->result` whenever `.bsg_request` returns non-zero, `qla24xx_bsg_request` handlers must either call `bsg_job_done()` (or queue async completion) and return `0`, or return non-zero without calling `bsg_job_done()`. [F149]
- Option ROM staging in `qla2x00_sysfs_write_optrom_ctl`, `qla2x00_sysfs_write_optrom`, and `qla2x00_optrom_setup` must verify `start <= ha->optrom_size` and store the clamped byte length (not `start + size`) in `ha->optrom_region_size`; in `qla2x00_sysfs_write_optrom_ctl()`, `val == 2` is only allowed when `(ha->optrom_size == OPTROM_SIZE_2300 && start == 0) || IS_QLA24XX_TYPE(ha) || IS_QLA25XX(ha)` (newer adapters must return `-EINVAL` and use BSG). [F51, F115, F158]

## Known Pitfalls
- `rport->dd_data` points to an inline `fc_port_t *` slot (`dd_fcrport_size = sizeof(struct fc_port *)`) and must be dereferenced as `*(fc_port_t **)rport->dd_data` and checked for `NULL`, whereas `fc_vport->dd_data` stores `scsi_qla_host_t *` directly; iterations over `vha->vp_fcports` (e.g., `qla2x00_get_starget_*`) must NULL-check `fcport->rport`, and search loops over `vha->vp_fcports` (`qla24xx_iidma`) or `req->outstanding_cmds` (`qla_bsg_found`) must use a `found` boolean rather than testing `!fcport` or `!sp` after the loop. [F37, F98, F99]
- In `qla2x00_sysfs_read_nvram` and `qla2x00_sysfs_read_vpd`, `ha->isp_ops->read_optrom` must be skipped when `!IS_NOCACHE_VPD_TYPE(ha)`; in `qla2x00_sysfs_write_reset` (`case 0x2025d`), only `IS_QLA83XX(ha)` may take the `qla83xx_idc_lock` / `QLA83XX_IDC_DEV_STATE` branch while 81xx, 27xx, and 28xx must call `qla81xx_restart_mpi_firmware`; and in `ql_dump_regs`, `IS_P3P_TYPE(ha)` must be tested before `IS_FWI2_CAPABLE(ha)` because P3P adapters also set `DT_FWI2`. [F92, F93, F94]
- When accessing vendor data trailing `struct fc_bsg_request` or `struct fc_bsg_reply`, add byte offsets to `void *` (`bsg_job->request`, `bsg_job->reply`) or `(uint8_t *)` rather than typed pointers (and update `bsg_job->reply_len` accordingly); when calling `sg_copy_from_buffer()` with a heap-allocated response pointer (`data` or `req_data`), pass `data` directly rather than `&data`; and when reading `__le16` elements from `vha->dport_data` in `qla2x00_do_dport_diagnostics_v2`, use `le16_to_cpu()`. [F82, F83, F113, F118]
- In `qla_attr.c`, `ha->link_data_rate` holds sparse `PORT_SPEED_*` constants (up to `0xFFFF`) and must be mapped via `port_speed_str` or `switch` rather than array indexing; `qla2x00_zio_timer_store` and `qla_zio_threshold_store` must reject negative or below-minimum `sscanf(buf, "%d", &val)` inputs with `-ERANGE`; and 16-bit `ha->fw_attributes*` fields shifted by 16/32/48 bits must be cast to `uint64_t` first. [F73, F74, F108]
