# WWAN DRIVERS

The WWAN subsystem core (`wwan_core.c`) manages virtual WWAN devices (`struct wwan_device`), exposes modem control channels (AT, MBIM, QMI, QCDM, FIREHOSE, etc.) as character devices (`struct wwan_port`), and provides an RTNL link interface (`rtnl_link_ops` kind `"wwan"`) for multiplexed WWAN network interfaces. Accompanying drivers include MHI client drivers for control ports (`mhi_wwan_ctrl.c`) and MBIM IP data multiplexing (`mhi_wwan_mbim.c`), plus a software simulator (`wwan_hwsim.c`) with debugfs controls and an AT parser.

## Architecture & Data Flow

- In `mhi_wwan_ctrl.c`, `mhi_wwan_rx_budget_dec()` must evaluate `MHI_WWAN_RX_REFILL` whenever `mhiwwan->rx_budget` was non-zero before decrementing (even when going from `1` to `0`), and `mhi_wwan_ctrl_refill_work()` must call `mhi_wwan_rx_budget_inc()` directly only if `alloc_skb()` fails before `skb->destructor = __mhi_skb_destructor` is set; once set, freeing `skb` on any path restores `rx_budget` via `__mhi_skb_destructor()`. [F9, F47]
- In `mhi_dl_xfer_cb()` and `mhi_mbim_dl_callback()`, `transaction_status == -EOVERFLOW` indicates a split transfer rather than a fatal error: the received `skb` bytes must be finalized with `skb_put()`, and in `mhi_mbim_dl_callback()` appended to `mbim->skbagg_head` via `mhi_net_skb_agg()` without calling `mhi_mbim_rx()`, resetting `mbim->skbagg_head = NULL` once the final (`0`) fragment is aggregated or an incomplete chain is dropped. [F34, F73]
- When chaining a fragment SKB onto `head`'s `frag_list` in `mhi_net_skb_agg()` or `wwan_port_fops_write()`, `head->len`, `head->data_len`, and `head->truesize` must all be incremented by `skb->len`, `skb->len`, and `skb->truesize` alongside updating the tail pointer. [F52]
- Because `wwan_class` and `wwandev->dev` host devices of different types, any `struct device *` must be checked against `wwan_dev_type`, `wwan_port_dev_type`, or `wwan_type` before downcasting with `to_wwan_dev()`, `to_wwan_port()`, or `to_net_dev()`. [F38]
- In `wwan_dev_parent_match()`, matching a `wwan_device` requires checking both `dev->parent == parent` and `dev == parent` so `wwan_dev_get_by_parent()` resolves lookups passed either the hardware parent device or `&wwandev->dev` itself (from `netdev->dev.parent` in `wwan_rtnl_newlink()` and `wwan_rtnl_dellink()`). [F67]
- In `wwan_core.c`, `is_wwan_child()` must return non-zero on a matching port child to short-circuit `device_for_each_child()` in `wwan_remove_dev()`, whereas `wwan_child_dellink()` must always return `0` so `device_for_each_child()` in `wwan_unregister_ops()` queues every child netdev onto `kill_list`. [F71]
- In `struct wwan_netdev_priv`, `drv_priv[]` must remain the final flexible-array member aligned to `sizeof(void *)`, `wwan_rtnl_alloc()` must allocate `sizeof(struct wwan_netdev_priv) + wwandev->ops->priv_size`, and WWAN netdev drivers must access per-link private data via `wwan_netdev_drvpriv(dev)` rather than `netdev_priv(dev)`. [F42, F112]
- When a `wwan_port` is stopped on final close in `wwan_port_op_stop()` or disconnected in `wwan_remove_port()`, `port->rxq` must be purged via `skb_queue_purge()` along with calling `port->ops->stop(port)`. [F54]
- In `mhi_net_rx_refill_work()`, both `alloc_skb()` and `mhi_queue_skb()` must use the per-instance `mbim->mru` field initialized from `mhi_dev->mhi_cntrl->mru` rather than `MHI_DEFAULT_MRU`. [F49]
- In `mhi_mbim_setup()`, `ndev->max_mtu` must not exceed `MHI_MAX_BUF_SZ - sizeof(struct mbim_tx_hdr)` (`0xffff - ndev->needed_headroom`) so `skb->len` after `skb_push(skb, sizeof(struct mbim_tx_hdr))` in `mbim_tx_fixup()` fits in the 16-bit `nth16->wBlockLength` field. [F64]
- `mbim_rx_verify_ndp16()` must reject `le16_to_cpu(ndp16->wLength) < USB_CDC_NCM_NDP16_LENGTH_MIN` before subtracting `sizeof(struct usb_cdc_ncm_ndp16)` and decrementing `ret` for the NULL terminator entry. [F63]
- Every `enum wwan_port_type` value below `__WWAN_PORT_MAX` must have `.name` and `.devsuf` in `wwan_port_types`, `WWAN_PORT_UNKNOWN` must remain above `WWAN_PORT_MAX`, and every `mhi_wwan_ctrl_match_table` entry before `{}` must set `.driver_data` to a valid `enum wwan_port_type` (`<= WWAN_PORT_MAX`). [F68, F97]
- `port->at_data.termios` in `struct wwan_port` must remain typed as `struct ktermios` (not `struct termios`) because `wwan_port_fops_at_ioctl()` copies both `sizeof(struct termios)` and `sizeof(struct termios2)` bytes to and from `&port->at_data.termios`. [F65]

## Synchronization

- `mhiwwan->rx_lock` in `struct mhi_wwan_dev` must always be acquired with `spin_lock_bh()` / `spin_unlock_bh()` because `__mhi_skb_destructor()` can invoke `mhi_wwan_rx_budget_inc()` from softirq/BH context while the MHI controller holds `pm_lock`. [F98]
- In `mhi_wwan_ctrl_tx()` and `mhi_ul_xfer_cb()`, `mhiwwan->tx_lock` must be held with `spin_lock_bh()` across `mhi_queue_skb()`, `mhi_queue_is_full()`, and the corresponding `wwan_port_txoff()` or `wwan_port_txon()` call. [F21]
- In `mhi_mbim_ndo_xmit()`, `mbim->tx_lock` must be held with `spin_lock_irqsave()` across `mbim_tx_fixup()`, `mhi_queue_skb()`, `mhi_queue_is_full()`, and the increment of `mbim->tx_seq`. [F18]
- In `mhi_mbim_newlink()`, all `struct mhi_mbim_link` fields (`mbim`, `session`, `ndev`, `rx_syncp`, `tx_syncp`) must be initialized before `hlist_add_head_rcu()`; in `mhi_mbim_rx()`, `mhi_mbim_get_link_rcu()` and all accesses to `link` and `link->ndev` must stay inside `rcu_read_lock()`, paired with `hlist_del_init_rcu()` and `synchronize_rcu()` before `unregister_netdevice_queue()` in `mhi_mbim_dellink()`. [F15, F102]
- In `mhi_mbim_probe()`, `mbim->tx_lock`, `mbim->rx_refill`, `mbim->mdev`, `mbim->mru`, and driver data must be initialized before calling `mhi_prepare_for_transfer()` and `wwan_register_ops()`. [F14]
- All updates and reads of the 64-bit statistics counters in `struct mhi_mbim_link` must be bracketed by `u64_stats_update_begin()` / `u64_stats_update_end()` and `u64_stats_fetch_begin()` / `u64_stats_fetch_retry()` using `link->rx_syncp` for RX and `link->tx_syncp` for TX. [F80]
- In `wwan_remove_port()`, `port->ops` must be set to `NULL` under `port->ops_lock` before calling `wake_up_interruptible(&port->waitqueue)` so that `is_read_blocked()` and `is_write_blocked()` evaluate to `false` for tasks sleeping in `wwan_wait_rx()` or `wwan_wait_tx()`. [F105]
- In `wwan_create_port()`, `wwan_register_lock` must be held continuously across `__wwan_port_dev_assign_name()` and `device_register(&port->dev)` after initializing all `struct wwan_port` fields and locks (`port->ops_lock`, `port->rxq`, `port->waitqueue`). [F23]
- In `wwan_hwsim.c`, debugfs `destroy` write handlers must defer deletion to `wwan_wq`; deletion paths must unlink `port->list` or `dev->list` with `list_del_init()` under `dev->ports_lock` or `wwan_hwsim_devs_lock` and drop the spinlock before calling `wwan_hwsim_port_del()` or `wwan_hwsim_dev_del()`, which must guard `cancel_work_sync()` with `current_work() != &...->del_work`. [F28, F76]

## Object Lifetimes

- In `mhi_wwan_mbim.c`, `mbim_tx_fixup()` frees `skb` via `dev_kfree_skb_any(skb)` and returns `NULL` when `skb_cow_head()` fails, whereas `mhi_queue_skb()` leaves `skb` unfreed on error for `mhi_mbim_ndo_xmit()` to free after releasing `mbim->tx_lock`. [F2]
- In `mhi_wwan_ctrl_stop()`, `MHI_WWAN_RX_REFILL` must be cleared under `spin_lock_bh(&mhiwwan->rx_lock)` before `cancel_work_sync(&mhiwwan->rx_refill)` and `mhi_unprepare_from_transfer(mhiwwan->mhi_dev)`, because unpreparing MHI and purging `port->rxq` free RX SKBs whose `__mhi_skb_destructor()` would otherwise re-schedule `mhiwwan->rx_refill`. [F10]
- In `mhi_mbim_remove()`, `mhi_unprepare_from_transfer(mhi_dev)` and `cancel_delayed_work_sync(&mbim->rx_refill)` must run before `wwan_unregister_ops()` and `kfree_skb(mbim->skbagg_head)`, because `mhi_mbim_ul_callback()` dereferences `skb->dev` (`ndev`) and `wwan_netdev_drvpriv(ndev)` while MHI flushes in-flight buffers. [F11]
- In `wwan_unregister_ops()`, all child WWAN netdevs must be deleted via `wwan_child_dellink()` and `unregister_netdevice_many()` under `rtnl_lock()` before `wwandev->ops` is set to `NULL`; both `wwandev->ops = NULL` and `device_unregister(&port->dev)` (in `wwan_remove_port()`) must precede `wwan_remove_dev(wwandev)`, which only unregisters `wwandev->dev` when `wwandev->ops` is `NULL` and no `wwan_class` child remains. [F4, F26]
- In `wwan_create_dev()`, `wwan_create_port()`, and `wwan_hwsim_dev_new()`, IDA IDs (`wwan_dev_ids`, `minors`) and struct memory must be freed directly only if failure occurs before `device_register()`; once `device_register()` is called, rollback if `device_register()` itself fails must use `put_device()`, and rollback after `device_register()` succeeds must use `device_unregister()` while preserving `err`. [F6, F39]
- In `wwan_hwsim_exit()` and `err_clean_devs` in `wwan_hwsim_init()`, `debugfs_remove(wwan_hwsim_debugfs_devcreate)` and `wwan_hwsim_free_devs()` must be followed by `flush_workqueue(wwan_wq)` before removing `wwan_hwsim_debugfs_topdir`, unregistering `wwan_hwsim_class`, and destroying `wwan_wq`. [F96]

## API Contracts

- Implementations of `wwan_port_ops.tx` and `wwan_port_ops.tx_blocking` take ownership of `struct sk_buff *skb` only when returning `0`; on any non-zero error return they must leave `skb` unfreed because `wwan_port_fops_write()` frees `head` via `kfree_skb(head)` whenever `wwan_port_op_tx()` returns non-zero. [F1]
- `wwan_port_rx()`, `wwan_port_txon()`, and `wwan_port_txoff()` are called from atomic/BH contexts and while holding driver spinlocks (`mhiwwan->tx_lock`), so they must never sleep or acquire `port->ops_lock` or `port->data_lock`. [F103]
- Every `struct sk_buff` passed to `wwan_port_rx()` must be linear (`skb->data_len == 0`), and MHI `dl_xfer_cb` handlers (`mhi_dl_xfer_cb()` and `mhi_mbim_dl_callback()`) must commit the DMA transfer length via `skb_put(skb, mhi_result->bytes_xferd)` before passing `skb` to `wwan_port_rx()`, `mhi_net_skb_agg()`, or `mhi_mbim_rx()`. [F61, F116]
- When `CONFIG_WWAN_DEBUGFS` is enabled, `wwan_get_debugfs_dir()` acquires a reference on `wwandev->dev` via `wwan_dev_get_by_parent()` that must be released by calling `wwan_put_debugfs_dir()`, which drops both the lookup reference from `wwan_dev_get_by_debugfs()` and the caller's held reference. [F3]
- Any `wwan_ops.setup` callback whose driver relies on `unregister_netdevice_queue()` in `wwan_ops.dellink` (or default `wwan_rtnl_dellink()`) without calling `free_netdev()` must set `ndev->needs_free_netdev = true`, whereas `wwan_create_default_link()` must call `free_netdev(dev)` if `wwan_rtnl_newlink()` fails and `rtnl_configure_link()` if it succeeds. [F8, F109]
- In `struct wwan_port_ops`, `start`, `stop`, and `tx` are mandatory while `tx_blocking` and `tx_poll` are optional, and `port->ops` becomes `NULL` in `wwan_remove_port()`, so core callers must check `port->ops` under `port->ops_lock` and null-check `tx_blocking` and `tx_poll` before calling them. [F36]
- In `struct wwan_ops`, `setup` is mandatory, while `newlink` and `dellink` are optional and `wwandev->ops` is `NULL` when only ports are registered, so RTNL handlers must check `wwandev->ops` and fall back to `register_netdevice()` or `unregister_netdevice_queue()` when `newlink` or `dellink` is `NULL`. [F37]
- MHI WWAN drivers (`mhi_wwan_ctrl_probe()`, `mhi_mbim_probe()`, and `mhi_mbim_remove()`) must pass the shared MHI controller device `&cntrl->mhi_dev->dev`—not the per-channel `&mhi_dev->dev`—as `parent` to `wwan_create_port()`, `wwan_register_ops()`, and `wwan_unregister_ops()`, and must call `mhi_prepare_for_transfer()` before `mhi_get_free_desc_count(..., DMA_FROM_DEVICE)`. [F88, F89]
- When a non-NULL `struct wwan_port_caps *caps` is passed to `wwan_create_port()`, `caps->frag_len` must be non-zero, and in `wwan_port_fops_write()` each allocated `skb` must be linked into `head` before `copy_from_user()` can jump to `freeskb`. [F70]

## Error Handling

- `wwan_create_dev()` and the lookup helpers `wwan_dev_get_by_parent()`, `wwan_dev_get_by_name()`, `wwan_dev_get_by_debugfs()`, and `wwan_port_get_by_minor()` always return an `ERR_PTR` (never `NULL`) on failure, so callers must check `IS_ERR()` rather than testing for `NULL`. [F29]
- `mbim_rx_verify_nth16()` and `mbim_rx_verify_ndp16()` return either a non-negative 16-bit offset/frame count or `-EINVAL` as a signed `int`, so callers in `mhi_mbim_rx()` must store the result in a signed `int` (`ndpoffset`, `nframes`) and check `< 0` before using it. [F33]
- When `mhi_res->transaction_status` is `-ENOTCONN` in `mhi_mbim_dl_callback()` or `mhi_mbim_ul_callback()`, the callback must free the SKB and return immediately without scheduling `mbim->rx_refill`, incrementing `link->tx_errors`, or calling `netif_wake_queue()`. [F93]
- `wwan_port_fops_at_ioctl()` must return `-ENOIOCTLCMD` for unrecognized ioctl commands and may only be called when `port->type == WWAN_PORT_AT`, so that `wwan_port_fops_ioctl()` guards `port->at_data` access and falls through to generic port ioctls such as `TIOCINQ`. [F35]
- `wwan_register_ops()` must not abort or roll back `wwandev->ops` registration if `wwan_create_default_link()` fails, because default link creation is best-effort and user space can still create links via RTNL afterward. [F40]

## External Contracts

- In `mhi_wwan_mbim.c`, `usb_cdc_ncm_ndp16.dwSignature` packs the multiplexed session ID in bits 24–31 via `(session << 24)` and the NDP type signature in bits 0–23 (`MBIM_NDP16_SIGN_MASK`), so `mhi_mbim_rx()` must mask `dwSignature` with `MBIM_NDP16_SIGN_MASK` (`0x00ffffff`) when checking for `USB_CDC_MBIM_NDP16_IPS_SIGN`. [F79]
- In `wwan_port_fops_poll()`, if the port has been removed (`!port->ops` under `port->ops_lock`), the returned poll mask must include `EPOLLHUP | EPOLLERR`. [F110]

## Known Pitfalls

- Flag constants `WWAN_PORT_TX_OFF` and `enum mhi_wwan_flags` (`MHI_WWAN_DL_CAP`, `MHI_WWAN_UL_CAP`, `MHI_WWAN_RX_REFILL`) must be defined as unshifted 0-based bit numbers rather than `BIT()` masks because they are passed directly to `set_bit()`, `clear_bit()`, and `test_bit()`. [F43]
- In `mhi_mbim_rx()`, all reads at variable packet offsets (`ndpoffset`, `dpeoffset`, `dgram_offset`) must use `skb_copy_bits()` rather than indexing `skb->data`, because `mhi_net_skb_agg()` chains multi-transfer MBIM packets across `skb_shinfo(head)->frag_list`. [F62]
- In `mbim_tx_fixup()`, `skb_cow_head(skb, sizeof(struct mbim_tx_hdr))` must run before `skb_push()`, and the original IP datagram length must be sampled from `skb->len` before `skb_push(skb, sizeof(struct mbim_tx_hdr))` mutates `skb->len`, so `dpe16[0].wDatagramLength` records the payload size while `nth16->wBlockLength` records the total NTB size. [F50, F115]
- `mhi_mbim_probe()` must pass `0` as `def_link_id` to `wwan_register_ops()`, while `mhi_mbim_newlink()` must add `mhi_mbim_get_link_mux_id()` to `if_id` when initializing `link->session` so both the default link and user-created links receive the controller's base mux ID offset. [F44]
- The format string `fmt` passed to `__wwan_port_dev_assign_name()` must contain a single `%d` specifier (escaped as `%%d` when formatted into `namefmt` in `wwan_create_port()`) and fit within the 32-byte stack buffers `namefmt` and `buf`, because `fmt` is passed to both `sscanf()` and `snprintf()`. [F85]
