# PCI SUBSYSTEM [RUST]

This unit provides safe Rust abstractions over the Linux kernel's C PCI subsystem (`include/linux/pci.h`) and thin C helper wrappers in `rust/helpers/pci.c` for inline and Kconfig-stubbed APIs (`CONFIG_PCI_IOV`, `CONFIG_PCI_MSI`). It exposes PCI driver registration (`pci::Driver`, `pci::Adapter`, `module_pci_driver!`), device ID matching tables (`DeviceId`, `Vendor`, `Class`, `ClassMask`, `pci_device_table!`), context-typed device handles (`pci::Device<Ctx>`), memory-mapped BAR and configuration space I/O (`Bar`, `DevresBar`, `ConfigSpace`), and PCI interrupt vector management (`IrqVectorRegistration`, `IrqVector`, `IrqTypes`).

## Architecture & Data Flow
- `pci::Device<Ctx>` must remain a `#[repr(transparent)]` wrapper around `Opaque<bindings::pci_dev>` whose layout does not depend on `Ctx`, with `AsBusDevice::OFFSET` set to `offset_of!(bindings::pci_dev, dev)`, because `*mut bindings::pci_dev` and `*const Device<Ctx>` are cast directly between each other in `probe_callback`, `remove_callback`, `impl_device_context_deref!`, and `AlwaysRefCounted::dec_ref`. [F53]
- `Adapter<T>`'s `driver::DriverLayout::DriverData<'bound>` associated type must equal the `T::Data<'bound>` type stored via `set_drvdata` in `Adapter::probe_callback` and borrowed via `drvdata_borrow` in `Adapter::remove_callback`, so `Registration::post_unbind_callback` reconstructs the matching `Pin<KBox<...>>` type. [F56]
- `pci::DeviceId` must remain a `#[repr(transparent)]` wrapper around `bindings::pci_device_id` with `DRIVER_DATA_OFFSET` equal to `offset_of!(bindings::pci_device_id, driver_data)`, so `IdArray` transmutation and pointer-provenance writes at `DRIVER_DATA_OFFSET` are sound. [F59]
- `ClassMask`, `ConfigSpaceSize`, and `IrqType` must be constructed from raw C values through explicit discriminant matching (`ClassMask::try_from`, `Device::cfg_size`, and `IrqType::from_raw`) rather than transmutation, and every variant in `ClassMask` must have a matching raw `u32` arm before `_ => Err(EINVAL)` in `<ClassMask as TryFrom<u32>>::try_from`. [F43, F66]

## Synchronization
- Because `pci::Device<device::Normal>` and `pci::Device<device::Bound>` implement `Sync`, their `&self` methods must be thread-safe for concurrent calls; unsynchronized state-mutating or callback-scoped operations (`enable_device_mem`, `set_master`, `sriov_get_totalvfs`) and `crate::dma::Device` (for `dma_set_mask`, `dma_set_coherent_mask`, `dma_set_mask_and_coherent`, `dma_set_max_seg_size`) must be restricted to `pci::Device<device::Core<'_>>`, which must not implement `Sync`. [F82, F85]
- `pci::Driver::Data<'bound>` must require the `Send` bound because the `Pin<KBox<T::Data<'_>>>` instance initialized in `Adapter::probe_callback` may be accessed in `Adapter::remove_callback` and dropped on a different thread when the PCI device is unbound. [F57]

## Object Lifetimes
- `Adapter::probe_callback` transfers ownership of `T::Data` to the device via `set_drvdata`, whereas `Adapter::remove_callback` must only borrow it via `drvdata_borrow` to run `T::unbind`, leaving ownership in `struct device` until `driver::Registration::post_unbind_callback` drops it. Broken by: calling `drvdata_obtain` or clearing driver data in `remove_callback`. [F3]
- `IrqVectorRegistration::index` must tie the lifetime of the returned `IrqVector<'_>` (and its inner `IrqRequest<'_>`) to the `&self` borrow of `IrqVectorRegistration` rather than the `'a` lifetime of `self.dev`, ensuring all registered IRQ handlers are dropped before `IrqVectorRegistration::drop` calls `pci_free_irq_vectors`. [F9]
- `Bar<'a, SIZE>` must only contain fields that are covariant over `'a` and remain valid for the entire bound lifetime of `self.pdev`, because `CovariantForLt for Bar<'static, SIZE>` transmutes reference lifetimes and `Bar::into_devres` extends `'a` to `'static` inside `DevresLt::new` until device unbind. [F64]
- The BAR resource name passed to `Bar::new`, `Device::iomap_region_sized`, and `Device::iomap_region` must require `'static` lifetime (`&'static CStr`), because `bindings::pci_request_region` stores the raw string pointer directly in `struct resource` where a shorter lifetime would dangle if `Bar` is leaked. [F63]
- `AlwaysRefCounted` must only be implemented for `pci::Device` (`Device<device::Normal>`), never for `Device<device::Bound>` or `Device<device::Core<'_>>`, so `ARef<pci::Device>` handles cannot preserve `Bound` or `Core` context guarantees beyond their valid scopes. It must pair `pci_dev_get` in `inc_ref` with `pci_dev_put` in `dec_ref`, while `Device::as_ref` and `TryFrom<&device::Device<Ctx>> for &Device<Ctx>` must return borrowed references without modifying refcounts. [F5, F83]

## API Contracts
- Resource-acquiring and hardware-access methods requiring a bound driver (`iomap_region_sized`, `iomap_region`, `config_space`, `config_space_extended`, and `alloc_irq_vectors`) must be implemented on `pci::Device<device::Bound>` rather than `pci::Device<device::Normal>`, so an `ARef<pci::Device>` cannot map BARs, access config space, or allocate IRQs after unbind. [F84]
- Before calling C PCI resource functions (`pci_resource_start`, `pci_resource_len`, `pci_request_region`, `pci_iomap`), BAR indices must be validated with `Bar::index_is_valid(bar)` (`bar < bindings::PCI_NUM_RESOURCES`), and `Bar::new` must reject zero-length resources (`len == 0`) with `Err(ENOMEM)` before requesting or mapping the region. [F92]
- `ConfigSpaceBackend` only implements `IoCapable` for `u8`, `u16`, and `u32` (never `u64`) and converts `view.ptr.addr()` to `i32` for `pci_read_config_{byte,word,dword}` and `pci_write_config_{byte,word,dword}`, relying on the `ConfigSpace` bound of at most 4096 bytes so the cast never truncates or changes sign. [F37]
- `bindings::pci_irq_type` must only be exposed through `IrqVectorRegistration::irq_type` and `IrqVector::irq_type` rather than directly on `pci::Device`, because `pci_irq_type` falls back to `PCI_IRQ_INTX` whenever `msix_enabled` and `msi_enabled` are false. [F81]
- `IrqVectorRegistration::index` must convert the `usize` vector index to `u32` via `u32::try_from` rather than `as u32` before calling `bindings::pci_irq_vector`, so 64-bit indices above `u32::MAX` fail with `EINVAL` instead of wrapping. [F46]
- `DeviceId` constructors (`from_id`, `from_class`, `from_class_and_vendor`) must initialize wildcard ID fields (`vendor`, `device`, `subvendor`, `subdevice`) to `DeviceId::PCI_ANY_ID` (`!0`) and unused `class`, `class_mask`, `driver_data`, and `override_only` fields to `0`. [F24]
- `Device::sriov_get_totalvfs` treats a return value of `0` from `bindings::pci_sriov_get_totalvfs` as `None` (SR-IOV unavailable or zero VFs) by wrapping `total_vfs as u16` in `NonZero::new`. [F18]

## Error Handling
- `Bar::new` must reject zero-length BARs (`len == 0`) before calling `pci_request_region`, check `ioptr == 0` (since `bindings::pci_iomap` returns `NULL` rather than an `ERR_PTR`), and validate the region via `MmioRaw::new_region(ioptr, len as usize)` (checking `len >= SIZE` and 4-byte base/size alignment). On failure, it must unwind in reverse order (`pci_release_region` if `pci_iomap` returns 0; `Bar::do_release` calling `pci_iounmap` before `pci_release_region` if `MmioRaw::new_region` fails), matching `Bar::drop`. [F14, F35, F70]
- Downcasting `&device::Device<Ctx>` to `&pci::Device<Ctx>` in `TryFrom::try_from` must verify `bindings::dev_is_pci(dev.as_raw())` before computing `container_of!(dev.as_raw(), bindings::pci_dev, dev)` and casting the pointer. [F62]
- While `Device<Bound>::cfg_size` treats a `(*self.as_raw()).cfg_size` value other than 256 or 4096 as `unreachable!()`, `Device<Bound>::config_space_extended` must check `self.cfg_size() != ConfigSpaceSize::Extended` at runtime and return `Err(EINVAL)` for devices with 256-byte configuration space. [F94]
- `Device::alloc_irq_vectors` must validate the `c_int` return of `bindings::pci_alloc_irq_vectors` with both `to_result(ret)?` (for negative errno codes) and `NonZero::new(ret as usize).ok_or(EINVAL)?` before constructing `IrqVectorRegistration`. [F16]
- In `IrqVectorRegistration::index`, `bindings::pci_irq_vector` returns a signed `c_int` that is negative on error (e.g., `-EINVAL`), so `irq < 0` must be checked before casting `irq as u32` for `IrqRequest::new`. [F17]
- In `impl_config_space_io_capable!`, `ConfigSpaceBackend::io_read` ignores the return status of `bindings::pci_read_config_{byte,word,dword}`, so the out-parameter `val` must be zero-initialized (`let mut val: $ty = 0;`) rather than using `MaybeUninit::uninit()`. [F23]

## External Contracts
- In `rust/helpers/pci.c`, `__rust_helper` wrappers for C PCI APIs that become `static inline` stubs only when a Kconfig option is disabled must be guarded by `#ifndef CONFIG_PCI_IOV` (`rust_helper_pci_sriov_get_totalvfs`) or `#ifndef CONFIG_PCI_MSI` (`rust_helper_pci_alloc_irq_vectors`, `rust_helper_pci_free_irq_vectors`, `rust_helper_pci_irq_vector`), whereas wrappers for always-inline functions like `rust_helper_pci_irq_type` must remain unguarded. [F29]
- `Adapter::register` must initialize `name`, `probe`, `remove`, and `id_table` on the underlying `bindings::pci_driver` before calling `bindings::__pci_register_driver` with `module.as_ptr()` and `name.as_char_ptr()`, and `Adapter::unregister` must pair it with `bindings::pci_unregister_driver`. [F89]

## Known Pitfalls
- `ConfigSpace<'a, T>` encodes the zero-based PCI configuration-space byte offset as the address of `ptr` (starting at `core::ptr::null_mut()`) and the region size as its slice metadata, requiring `ptr` to be aligned and `ptr..ptr + KnownSize::size(ptr)` to lie within `0..pdev.cfg_size().into_raw()`. `ConfigSpaceBackend` (`io_read`, `io_write`) must pass `view.ptr.addr() as i32` to `pci_read_config_*` and `pci_write_config_*` without ever dereferencing `view.ptr`. [F32, F36]
- `Class::to_24bit_class` shifts any input `val <= 0xFFFF` left by 8 bits and leaves `val > 0xFFFF` unchanged, so 16-bit C `PCI_CLASS_*` constants must be normalized via `to_24bit_class`, while already-24-bit class values (such as `pci_dev::class` passed to `Class::from_raw`, which may have base class `0x00`) must not be passed to `to_24bit_class`. [F42]
- `IrqType::from_raw` uses a wildcard `_ => IrqType::Intx` arm when matching raw `u32` flags from `pci_irq_type`, so any new `IrqType` variant added to `IrqType::as_raw` must also be matched explicitly before the wildcard arm in `IrqType::from_raw`. [F44]
