# CTU CAN FD DRIVER

This component implements the Linux SocketCAN network device driver for the open-source CTU CAN FD IP core (`ctucanfd`), supporting both Classical CAN and CAN FD frames. It consists of a bus-independent core (`ctucanfd_base.c`) managing MMIO register access, bit-timing calculation, TX hardware buffer priority rotation, NAPI-based RX FIFO polling, and error/fault state reporting, paired with PCI (`ctucanfd_pci.c`) and Device Tree platform (`ctucanfd_platform.c`) bus glue drivers.

## Architecture & Data Flow

- In `struct ctucan_priv`, `struct can_priv can` must remain the first struct member because SocketCAN helpers (`alloc_candev`, `open_candev`, `can_put_echo_skb`) and `ctucanfd` callbacks cast `netdev_priv(ndev)` directly to their respective private types. [F1]
- `priv->can_clk` in `struct ctucan_priv` is only populated when `ctucan_probe_common()` is called with `can_clk_rate == 0` (from `ctucan_platform_probe()`); when `can_clk_rate != 0` (from `ctucan_pci_probe()`), `priv->can_clk` remains `NULL`. Broken by: passing `priv->can_clk` to a clock API that rejects `NULL` or dereferencing it in shared code without checking `priv->can_clk`. [F20]
- `ntxbufs` passed to `ctucan_probe_common()` (stored in `priv->ntxbufs`) must be in `1..8` so `% priv->ntxbufs` never divides by zero and 32-bit shifts by `(priv->ntxbufs - 1) * 4` (`ctucan_rotate_txb_prio()`), `buf * 4` (`ctucan_get_tx_status()`), and `buf + 8` (`ctucan_give_txtb_cmd()`) stay in bounds. Software 0-based indices `[0, priv->ntxbufs - 1]` map to `(buf + 1) * 0x100` for TXT buffer MMIO offsets in `ctucan_insert_frame()`, `1 << (buf + 8)` in `ctucan_give_txtb_cmd()`, and shift `buf * 4` in `ctucan_get_tx_status()`. [F37, F51]
- `priv->txb_head` and `priv->txb_tail` are monotonically incremented counters mapped to slots via `% priv->ntxbufs` and compared with `(int)(priv->txb_head - priv->txb_tail) > 0` (never wrapped modulo `priv->ntxbufs` on increment). Under `priv->tx_lock` in `ctucan_tx_interrupt()`, each completed slot at `priv->txb_tail % priv->ntxbufs` must consume its echo SKB, increment `priv->txb_tail`, and call `ctucan_rotate_txb_prio()` to rotate the `priv->ntxbufs` 4-bit nibbles of `priv->txb_prio` and write `CTUCANFD_TX_PRIORITY` before `ctucan_give_txtb_cmd()` marks the buffer empty. [F26, F38]
- When starting or restarting the controller in `ctucan_chip_start()`, `priv->txb_head` and `priv->txb_tail` must be reset to `0`, and `priv->txb_prio` must be reset to `0x01234567` and written to `CTUCANFD_TX_PRIORITY` before enabling `REG_MODE_ENA` in `CTUCANFD_MODE`. [F28]
- `ctucan_reset()` must clear `CTUCANFD_FLAG_RX_FFW_BUFFERED` in `priv->drv_flags` whenever `REG_MODE_RST` is written to `CTUCANFD_MODE` so that a stale `priv->rxfrm_first_word` is not consumed by `ctucan_rx()` after the hardware RX FIFO is reset. [F30]
- CAN frame payload 32-bit words in `cf->data` must be converted with `le32_to_cpu()` before `ctucan_write_txt_buf()` in `ctucan_insert_frame()` and with `cpu_to_le32()` after `ctucan_read32(priv, CTUCANFD_RX_DATA)` in `ctucan_read_rx_frame()`, independent of whether `priv->read_reg`/`priv->write_reg` use little- or big-endian MMIO. [F40]
- In `ctucan_set_btr()`, any excess of `bt->phase_seg1` above `max_ph1_len` (`63` for nominal `CTUCANFD_BTR`, `31` for data `CTUCANFD_BTR_FD`) must be added into `prop_seg` and `phase_seg1` clamped to `max_ph1_len` before `FIELD_PREP()`, because `REG_BTR_PH1` and `REG_BTR_FD_PH1_FD` are 6 and 5 bits wide while `REG_BTR_PROP` and `REG_BTR_FD_PROP_FD` are 7 and 6 bits wide. [F50]

## Synchronization

- `priv->tx_lock` is taken in both `ctucan_start_xmit()` and hardirq `ctucan_tx_interrupt()`, so every acquisition must use `spin_lock_irqsave(&priv->tx_lock, flags)` and pair with `spin_unlock_irqrestore(&priv->tx_lock, flags)` on all exit paths, including the early exit in `ctucan_tx_interrupt()` when the first TX buffer is not in a finished state. [F6, F76]
- In `ctucan_start_xmit()`, the frame must be written via `ctucan_insert_frame()` and the echo SKB queued via `can_put_echo_skb()` at `txtb_id` before `ctucan_give_txtb_cmd(priv, TXT_CMD_SET_READY, txtb_id)` is issued and `priv->txb_head` is incremented. [F9]
- In `ctucan_tx_interrupt()`, `REG_INT_STAT_TXBHCI` must only be cleared in `CTUCANFD_INT_STAT` when at least one TX buffer was processed (`some_buffers_processed` is true), and the handler must then loop to re-check `(int)(priv->txb_head - priv->txb_tail) > 0`. [F11]
- When handling `REG_INT_STAT_RBNEI`, `ctucan_interrupt()` must mask `REG_INT_STAT_RBNEI` via `CTUCANFD_INT_MASK_SET` before clearing it in `CTUCANFD_INT_STAT` and calling `napi_schedule()`, and `ctucan_rx_poll()` must clear `REG_INT_STAT_RBNEI` in `CTUCANFD_INT_STAT` before unmasking it via `CTUCANFD_INT_MASK_CLR`. [F69]
- When `alloc_canfd_skb()` or `alloc_can_skb()` fails in `ctucan_rx()` after popping `ffw` from `CTUCANFD_RX_DATA`, `ctucan_rx()` must buffer `ffw` in `priv->rxfrm_first_word` with `CTUCANFD_FLAG_RX_FFW_BUFFERED` set and return `0`, and `ctucan_rx_poll()` must not call `napi_complete_done()` when `res == 0`. [F85]
- `ctucan_reset()` sleeps via `usleep_range(100, 200)` while polling `CTUCANFD_DEVICE_ID`, so `ctucan_reset()` and its callers (`ctucan_probe_common()`, `ctucan_open()`, `ctucan_do_set_mode()`) must only execute in sleepable process context and never in hardirq, softirq, or under `priv->tx_lock`. [F75]
- `ctucan_interrupt()` runs in hardirq context and `ctucan_rx_poll()` runs in NAPI softirq context, so `ctucan_interrupt()`, `ctucan_tx_interrupt()`, `ctucan_err_interrupt()`, `ctucan_rx_poll()`, and `ctucan_rx()` must use only non-blocking calls and atomic SKB allocations. [F78]

## Object Lifetimes

- Every `pm_runtime_get_sync()` call in `ctucan_open()`, `ctucan_get_berr_counter()`, and `ctucan_probe_common()` must release the runtime PM reference with `pm_runtime_put_noidle()` when `pm_runtime_get_sync()` returns a negative error, and with `pm_runtime_put()` on paths after it succeeds. [F2]
- `ctucan_open()` acquires resources in the order `pm_runtime_get_sync()`, `open_candev()`, `request_irq()`, `ctucan_chip_start()`, and `napi_enable()`, and both its error path and `ctucan_close()` must release them in reverse order (`napi_disable()` and `ctucan_chip_stop()` before `free_irq()`, `close_candev()`, and `pm_runtime_put()`). [F3]
- In `ctucan_probe_common()`, `INIT_LIST_HEAD(&priv->peers_on_pdev)` must run before `set_drvdata_fnc(dev, ndev)` and before any `goto err_free` path, because `set_drvdata_fnc()` runs before clock lookup, runtime PM, reset, and `register_candev()`, and `err_free` unconditionally calls `list_del_init(&priv->peers_on_pdev)` before `free_candev(ndev)`; `ctucan_platform_probe()` must also clear `platform_set_drvdata(pdev, NULL)` on negative return. [F4, F21]
- `ctucan_probe_common()` must pass `ntxbufs` as `echo_skb_max` to `alloc_candev()`. `ctucan_start_xmit()` must leave `skb` unfreed on `NETDEV_TX_BUSY`, consume it via `can_dev_dropped_skb()` or `kfree_skb()` on early `NETDEV_TX_OK` drops, or queue it via `can_put_echo_skb()` to be released in `ctucan_tx_interrupt()` at `txtb_id = priv->txb_tail % priv->ntxbufs` via `can_get_echo_skb()` (`TXT_TOK`) or `can_free_echo_skb()` (`TXT_ERR`/`TXT_ABT`). [F5, F82]
- In `ctucan_pci_probe()` and `ctucan_pci_remove()`, the Avalon-MM to PCI Express interrupt enable register (`CYCLONE_IV_CRA_A2P_IE` at `cra_base + 0x0050`) is enabled only after all `ctucan_probe_common()` calls complete and is cleared to `0` before unregistering any `net_device`. [F64]
- In `ctucan_pci_remove()` and `ctucan_platform_remove()`, each registered CAN device must be torn down in the order `unregister_candev(ndev)` (and `pm_runtime_disable(&pdev->dev)` on platform devices), then `netif_napi_del(&priv->napi)` (and `list_del_init(&priv->peers_on_pdev)` on PCI), and finally `free_candev(ndev)`. [F7]

## API Contracts

- In `ctucan_probe_common()`, `priv->write_reg` and `priv->read_reg` must be initialized to `ctucan_write32_le` and `ctucan_read32_le` and verified against `CTUCANFD_ID` (`0xCAFD`) in `CTUCANFD_DEVICE_ID` (falling back to `ctucan_write32_be` and `ctucan_read32_be`) after `pm_runtime_get_sync(dev)` and before `ctucan_reset(ndev)`. [F67]
- In `ctucan_pci_probe()`, `INIT_LIST_HEAD(&bdata->ndev_list_head)` and `pci_set_drvdata(pdev, bdata)` must execute before `ctucan_probe_common()` is called with `ctucan_pci_set_drvdata`, because `ctucan_pci_set_drvdata()` downcasts `dev` to `struct pci_dev` and adds `priv->peers_on_pdev` to `ctucan_pci_get_bdata(pdev)->ndev_list_head`. [F59]
- `ctucan_set_btr()` and `ctucan_set_secondary_sample_point()` must return `-EPERM` if `CTU_CAN_FD_ENABLED(priv)` is true, and `ctucan_chip_start()` must call `ctucan_set_bittiming()`, `ctucan_set_data_bittiming()`, and `ctucan_set_secondary_sample_point()` before setting `REG_MODE_ENA` in `CTUCANFD_MODE`. [F84]
- `ctucan_start_xmit()` must validate outgoing frames with `can_dev_dropped_skb(ndev, skb)` rather than `can_dropped_invalid_skb()` and return `NETDEV_TX_OK` immediately when it returns true, without freeing `skb` again. [F80]
- `ctucan_insert_frame()` must verify both `buf < priv->ntxbufs` and `ctucan_is_txt_buf_writable(priv, buf)` (ensuring the buffer's `CTUCANFD_TX_STATUS` nibble is not `TXT_RDY`, `TXT_TRAN`, or `TXT_ABTP`) before writing frame words to `(buf + 1) * 0x100`. [F32]
- Because `ctucan_start_xmit()` casts `skb->data` to `struct canfd_frame *` for both Classical CAN and CAN FD SKBs, `ctucan_insert_frame()` must only read `cf->flags` when `isfdf` (`can_is_canfd_skb(skb)`) is true; likewise, because `ctucan_rx()` allocates a `struct can_frame` via `alloc_can_skb(ndev, (struct can_frame **)&cf)` when `REG_FRAME_FORMAT_W_FDF` is clear, `ctucan_read_rx_frame()` must only touch `cf->flags` and allow `len > 8` when `REG_FRAME_FORMAT_W_FDF` is set. [F55, F56]
- Before calling `ctucan_read_rx_frame(priv, cf, ffw)`, `ctucan_rx()` must have already read `ffw` from `CTUCANFD_RX_DATA` (or restored it from `priv->rxfrm_first_word`) and verified `FIELD_GET(REG_FRAME_FORMAT_W_RWCNT, ffw)` is non-zero; `ctucan_read_rx_frame()` must then read and consume all `RWCNT` remaining 32-bit words from `CTUCANFD_RX_DATA`: 1 identifier word, 2 timestamp words, and all `wc = RWCNT - 3` data words (discarding trailing words beyond `len`). [F24, F39]

## Error Handling

- In `ctucan_err_interrupt()` and the RX overflow path of `ctucan_rx_poll()`, `alloc_can_err_skb(ndev, &cf)` may return `NULL`: controller state updates (`priv->can.state = state`), `can_bus_off(ndev)` on `CAN_STATE_BUS_OFF`, error counter increments, and clearing data overrun via `REG_COMMAND_CDO` must still execute, while every dereference of `cf` and call to `netif_rx(skb)` must be guarded by `if (skb)`. [F16, F86]
- In `ctucan_probe_common()`, `pm_runtime_enable(dev)` and its corresponding `pm_runtime_disable(dev)` on error must remain guarded by `if (pm_enable_call)` because `ctucan_platform_probe()` passes `pm_enable_call = 1` whereas `ctucan_pci_probe()` passes `pm_enable_call = 0` across multiple cores sharing one `struct device`. [F73]
- In `ctucan_err_interrupt()`, per-interrupt `netdev_info()` logs for error capture (`CTUCANFD_ERR_CAPT`) and arbitration lost (`REG_INT_STAT_ALI`) must be gated by `net_ratelimit()`, and `WARN()` in `ctucan_read_fault_state()` must only trigger when none of `REG_EWL_ERA`, `REG_EWL_ERP`, or `REG_EWL_BOF` is set. [F88]

## External Contracts

- The Device Tree match table `ctucan_of_match` in `ctucanfd_platform.c` and the PCI ID table `ctucan_pci_tbl` in `ctucanfd_pci.c` must remain `static const` arrays terminated by an empty `{}` sentinel entry. [F74]

## Known Pitfalls

- `ctucan_get_tx_status()` masks each 4-bit `CTUCANFD_TX_STATUS` nibble with `0x7`, stripping bit 3 so it never returns `TXT_ETY` (`0x8`) and instead maps empty buffers to `0x0`; callers such as `ctucan_is_txt_buf_writable()` must therefore test for non-writable states (`TXT_RDY`, `TXT_TRAN`, `TXT_ABTP`) rather than equality with `TXT_ETY`. [F41]
- In `ctucan_insert_frame()` and `ctucan_read_rx_frame()`, the loop index `i` used as an offset in `cf->data + i` and `CTUCANFD_DATA_1_4_W + i` must advance by 4 bytes per 32-bit word (`i += 4`), because both `cf->data` (`u8 *`) and `priv->mem_base` (`void __iomem *`) use byte-scaled pointer arithmetic. [F57]
- In `ctucan_pci_probe()`, `bdata->bar0_base` and `bdata->bar1_base` must preserve the base addresses returned by `pci_iomap()` for `pci_iounmap()`, whereas `cra_addr` (`bdata->cra_base`) is offset by `CTUCAN_BAR0_CRA_BASE` (`0x4000`) when `driver_data != CTUCAN_WITHOUT_CTUCAN_ID` and `addr` is incremented by `0x4000` for each additional core. [F48]
