# PER-CPU MEMORY ALLOCATOR

This component defines the header interfaces, architecture-specific accessors, and internal data structures for the Linux kernel per-CPU memory allocator and per-CPU synchronization and accounting primitives (`DEFINE_PER_CPU`, `alloc_percpu`, `this_cpu_*`/`raw_cpu_*`, `mm/percpu-internal.h`, `percpu_ref`, `percpu_rw_semaphore`, and `percpu_counter`).

## Architecture & Data Flow
- In `mm/percpu-internal.h`, all `struct pcpu_block_md` fields (`scan_hint`, `scan_hint_start`, `contig_hint`, `contig_hint_start`, `left_free`, `right_free`, `first_free`, `nr_bits`) are measured in `PCPU_MIN_ALLOC_SIZE` allocation bits, whereas `pcpu_chunk->free_bytes`, `start_offset`, and `end_offset` are in bytes. Broken by: comparing or adding block hints/offsets directly with byte sizes without converting via `PCPU_MIN_ALLOC_SIZE` / `PCPU_MIN_ALLOC_SHIFT`. [F37]
- In `struct pcpu_block_md`, `scan_hint_start > contig_hint_start` must hold iff `scan_hint == contig_hint`, and when `scan_hint` is non-zero and smaller than `contig_hint`, `scan_hint_start` must precede `contig_hint_start`. Broken by: `pcpu_block_update()` or `pcpu_block_refresh_hint()` leaving non-zero `scan_hint < contig_hint` at `scan_hint_start > contig_hint_start`. [F39]
- For a `struct pcpu_chunk` serving `chunk->nr_pages` pages, `chunk->alloc_map` and `chunk->obj_exts` are sized for `pcpu_chunk_map_bits(chunk)` entries, `chunk->bound_map` must be allocated with `pcpu_chunk_map_bits(chunk) + 1` bits for the trailing end-boundary bit, and `chunk->populated[]` is sized for `chunk->nr_pages` bits. Broken by: sizing `bound_map` without `+ 1`, or indexing `obj_exts` by page index instead of `PCPU_MIN_ALLOC_SIZE` bit offset. [F56]
- `PCPU_BITMAP_BLOCK_SIZE` must equal `PAGE_SIZE` so each `struct pcpu_block_md` in `chunk->md_blocks` (sized by `pcpu_chunk_nr_blocks()`) corresponds to one physical page when block hint updates adjust `chunk->nr_empty_pop_pages` and `pcpu_nr_empty_pop_pages`. [F40]
- `pcpu_stats_save_ai()` copies only `sizeof(struct pcpu_alloc_info)` bytes into `pcpu_stats_ai`, omitting the `groups[]` flexible array even though `pcpu_stats_ai.nr_groups` is copied; readers of `pcpu_stats_ai` must never access `pcpu_stats_ai.groups`. [F80]
- `PERCPU_COUNTER_LOCAL_BATCH` (and any `batch` passed to `percpu_counter_add_batch` under `CONFIG_SMP`) is typed as `s32` and bounded by `INT_MAX` so local deltas satisfying `abs(count + amount) < batch` fit without overflow in `s32 __percpu *counters` before folding into `s64 count`. [F78]
- In `arch/x86/include/asm/percpu.h`, `this_percpu_xchg_op()` loops `do { } while (!this_cpu_try_cmpxchg(_var, &pxo_old__, _nval));` without re-reading `_var`, which requires `percpu_try_cmpxchg_op()` to update `*pco_oval__ = pco_old__` whenever `cmpxchg` fails (`!success`). [F70]
- In `arch/x86/include/asm/percpu.h`, `percpu_cmpxchg64_op`, `percpu_try_cmpxchg64_op`, `percpu_cmpxchg128_op`, and `percpu_try_cmpxchg128_op` split 64-bit/128-bit values via an anonymous union `struct { low, high; }` where `low` must precede `high` to match little-endian register pairs (`%eax:%edx`/`%ebx:%ecx` and `%rax:%rdx`/`%rbx:%rcx`). [F61]
- In `arch/s390/include/asm/percpu.h`, `arch_this_cpu_to_op_simple()` must assign `old__ = prev__` at the start of each `do { ... } while (prev__ != old__)` iteration (with `prev__` initialized from `READ_ONCE(*ptr__)` and updated by `cmpxchg(ptr__, old__, new__)`) so each retry recomputes `new__ = old__ op (val)` from the latest witness value. [F71]
- Whenever `CONFIG_AMD_MEM_ENCRYPT` is enabled, `DECLARE_PER_CPU_DECRYPTED` and `DEFINE_PER_CPU_DECRYPTED` must place variables in the `"..decrypted"` section regardless of `CONFIG_VIRTUALIZATION` so decrypted per-CPU variables never share pages with encrypted variables. [F100]

## Synchronization
- Fast-path `percpu_ref` operations (`percpu_ref_get_many()`, `percpu_ref_tryget_many()`, `percpu_ref_tryget_live_rcu()`, and `percpu_ref_put_many()`) must hold an RCU read-side critical section continuously across `__ref_is_percpu()` and the subsequent per-CPU or `ref->data->count` update. [F12]
- `__ref_is_percpu()` must load `ref->percpu_count_ptr` once with `READ_ONCE()`, test that snapshot against `__PERCPU_REF_ATOMIC_DEAD` (both `__PERCPU_REF_ATOMIC` and `__PERCPU_REF_DEAD`), and only when returning `true` assign `*percpu_countp` from the same snapshot; when returning `false`, `*percpu_countp` is uninitialized. Broken by: re-fetching `percpu_count_ptr`, masking only `__PERCPU_REF_ATOMIC`, or dereferencing `percpu_count` without checking the return value. [F27, F44]
- Under `CONFIG_PERCPU_STATS`, `pcpu_stats_area_alloc()` and `pcpu_stats_area_dealloc()` must be called with `pcpu_lock` held (`lockdep_assert_held(&pcpu_lock)`) and update both `pcpu_stats` and `chunk->nr_alloc` (plus `chunk->max_alloc_size` on alloc) in lockstep, whereas `pcpu_stats_chunk_alloc()` and `pcpu_stats_chunk_dealloc()` acquire `pcpu_lock` internally via `spin_lock_irqsave()` and must not be called while holding `pcpu_lock`. [F18, F41]
- In `include/linux/percpu-rwsem.h`, `percpu_down_read_internal()`, `percpu_down_read_trylock()`, and `percpu_up_read()` must wrap the `rcu_sync_is_idle(&sem->rss)` check and `*sem->read_count` update in `preempt_disable()` / `preempt_enable()` and use IRQ-safe `this_cpu_inc()` / `this_cpu_dec()` rather than `__this_cpu_inc()` / `__this_cpu_dec()`. [F105]
- In `this_cpu_*` helpers that resolve a pointer via `raw_cpu_ptr()` before accessing memory (`_pcp_protect`, `_pcp_protect_return`, `this_cpu_cmpxchg128`, `_protect_cmpxchg_local`, `arch_this_cpu_to_op_simple`), both `raw_cpu_ptr()` and the memory operation must stay inside `preempt_disable_notrace()` / `preempt_enable_notrace()`. [F91]
- On x86, `this_percpu_xchg_op` (backing `this_cpu_xchg_{1,2,4,8}`) must use a `this_cpu_read()` and `this_cpu_try_cmpxchg()` loop rather than `raw_percpu_xchg_op`'s non-atomic read-then-write or the hardware `LOCK`-prefixed `xchg` instruction, keeping `this_cpu_xchg()` local-interrupt-safe without `LOCK` overhead. [F22]
- In `__kern_my_cpu_offset()` (arm64) and `__my_cpu_offset()` (arm), the non-volatile `asm` reading `tpidr_el1`/`tpidr_el2` or `TPIDRPRW` must keep `"Q" (*(const unsigned long *)current_stack_pointer)` as an input operand so `barrier()` invalidates cached CPU offsets across preemption. [F24]
- In `arch/arm64/include/asm/percpu.h`, when `__KVM_NVHE_HYPERVISOR__` is defined, `__my_cpu_offset` must resolve to `__hyp_my_cpu_offset()` (`read_sysreg(tpidr_el2)`), and under `CONFIG_DEBUG_PREEMPT`, `this_cpu_ptr`, `__this_cpu_read`, and `__this_cpu_write` must be redefined to their `raw_cpu_*` counterparts. [F96]
- Under `!CONFIG_SMP`, `percpu_counter_add()` and `percpu_counter_limited_add()` must disable local interrupts with `local_irq_save()` / `local_irq_restore()` around the read-modify-write of `fbc->count`. [F20]

## Object Lifetimes
- `get_cpu_var(var)` and `get_cpu_ptr(var)` disable preemption via `preempt_disable()` and must be paired on all exit paths with `put_cpu_var(var)` and `put_cpu_ptr(var)` to call `preempt_enable()`. [F8]
- On x86 with `CONFIG_SMP`, any variable defined with `DEFINE_EARLY_PER_CPU` or `DEFINE_EARLY_PER_CPU_READ_MOSTLY` must have its `_early_map` values copied to `per_cpu(_name, cpu)` and `early_per_cpu_ptr(_name)` set to `NULL` in `setup_per_cpu_areas()` before `__initdata` is freed. [F43]

## API Contracts
- In atomic mode (`__ref_is_percpu()` false), `percpu_ref_tryget_many()` and `percpu_ref_tryget()` increment `ref->data->count` whenever it is non-zero even if `__PERCPU_REF_DEAD` is set, whereas `percpu_ref_tryget_live_rcu()` and `percpu_ref_tryget_live()` return `false` when `ref->percpu_count_ptr & __PERCPU_REF_DEAD` is set. [F6]
- `percpu_ref_put_many()` invokes `ref->data->release(ref)` directly inside `rcu_read_lock()` when `atomic_long_sub_and_test()` reaches zero, and `percpu_ref_kill()` does not imply an RCU grace period before `release`; `release` callbacks must not sleep, and freeing RCU-protected objects requires an explicit `call_rcu()`. [F104]
- A `struct percpu_ref` initialized with `PERCPU_REF_INIT_DEAD` starts with refcount 0 in atomic/dead mode and must be revived with `percpu_ref_reinit()` before use, whereas `PERCPU_REF_INIT_ATOMIC` starts with refcount 1 in sticky atomic mode (`force_atomic`) until `percpu_ref_switch_to_percpu()` is called. [F49]
- `percpu_ref_is_dying()` tests `ref->percpu_count_ptr & __PERCPU_REF_DEAD` without internal locking or RCU protection, so callers must externally synchronize against concurrent `percpu_ref_kill()`, `percpu_ref_reinit()`, or `percpu_ref_resurrect()` calls. [F15]
- While `__ref_is_percpu(ref, &percpu_count)` is true, `percpu_ref_get_many`, `percpu_ref_tryget_many`, and `percpu_ref_put_many` must perform unchecked modular `unsigned long` addition/subtraction on `*percpu_count` rather than testing single-CPU values for zero or underflow. [F79]
- When a `struct percpu_counter` is updated with `percpu_counter_add_local()` or `percpu_counter_sub_local()`, deltas accumulate in `fbc->counters` up to `PERCPU_COUNTER_LOCAL_BATCH` (`INT_MAX`) without updating `fbc->count`, so readers must call `percpu_counter_sum()` (or `percpu_counter_sum_positive()`) rather than `percpu_counter_read()`. [F32]
- On `CONFIG_SMP` builds, `percpu_counter_read()` can return a negative value even for a non-negative counter because positive increments may reside in per-CPU `fbc->counters`; callers requiring a non-negative approximate read must use `percpu_counter_read_positive()`, which reads `fbc->count` once with `READ_ONCE()` and clamps negative values to 0. [F60]
- `percpu_counter_compare()` and `__percpu_counter_compare()` return a signed three-way comparison (`1`, `0`, `-1`), whereas `percpu_counter_limited_add()` and `__percpu_counter_limited_add()` return `bool` (`true` if `amount` was added within `limit`). [F30]
- In `!CONFIG_SMP` `percpu_counter_limited_add()`, `amount == 0` must short-circuit to `true` before the sign-split bound check, and `limit` acts as an upper bound when `amount > 0` (`count <= limit`) but as a lower bound when `amount < 0` (`count >= limit`). [F68]
- `raw_cpu_*()` and `__this_cpu_*()` do not disable preemption or interrupts (`__this_cpu_*()` only calls `__this_cpu_preempt_check()`); callers must only use them when preemption (and interrupts, if an IRQ handler touches the same variable) is already disabled, and otherwise use `this_cpu_*()`. [F25]
- `this_cpu_try_cmpxchg*()`, `__this_cpu_try_cmpxchg*()`, and `raw_cpu_try_cmpxchg*()` take a pointer `ovalp` to the expected value, return `bool`, and overwrite `*ovalp` with the current value on failure; on x86 (`percpu_try_cmpxchg_op`, `percpu_try_cmpxchg64_op`, `percpu_try_cmpxchg128_op`), `_ovalp` is cast directly to `(__pcpu_type_##size *)`, `(u64 *)`, or `(u128 *)`, so `*ovalp`'s width must match the per-CPU variable. [F34, F85]
- On arm64 and s390, `this_cpu_cmpxchg128(pcp, ...)` casts `raw_cpu_ptr(&(pcp))` to `(void *)` before calling `cmpxchg128_local()` or `cmpxchg128()`; callers must ensure `sizeof(pcp) == sizeof(u128)` (16 bytes) and 16-byte alignment. [F86]
- Architecture implementations of `this_cpu_add_return_*` and `raw_cpu_add_return_*` (`percpu_add_return_op` on x86, `__PERCPU_RET_OP_CASE` on arm64, `__percpu_add` on LoongArch, `arch_this_cpu_add_return` on s390) must add `val` to the old value returned by hardware fetch-and-add instructions (`xadd`, `ldadd`, `amadd`, `laa`/`laag`) to return the updated value. [F35]
- On x86, `this_cpu_read_stable()` (`__raw_cpu_read_stable`) omits `volatile` and uses an `"i"` address constraint with no memory input, so it must only be used for per-CPU variables whose value is invariant across CPU migration for the current task (e.g., `current_task`, `cpu_current_top_of_stack`). [F93]
- `pcpu_obj_full_size(size)` scales `size` by `num_possible_cpus()` and adds `size / PCPU_MIN_ALLOC_SIZE * sizeof(struct obj_cgroup *)` when `CONFIG_MEMCG` is enabled and `!mem_cgroup_kmem_disabled()`; callers must pass the `PCPU_MIN_ALLOC_SIZE`-aligned byte size on both charge and uncharge. [F81]
- In `struct pcpu_group_info`, `cpu_map` is an array of `nr_units` entries where unmapped unit slots must be populated with the sentinel value `NR_CPUS`. [F58]
- Under `CONFIG_SMP` on x86, `DEFINE_EARLY_PER_CPU` and `DEFINE_EARLY_PER_CPU_READ_MOSTLY` size `_name##_early_map` to `NR_CPUS`, and `early_per_cpu_map(_name, _idx)` and `early_per_cpu(_name, _cpu)` index it without bounds checks, requiring `_idx` and `_cpu` in `[0, NR_CPUS)`. [F63]
- Per-CPU variables exported to modules must use `EXPORT_PER_CPU_SYMBOL()` or `EXPORT_PER_CPU_SYMBOL_GPL()` instead of `EXPORT_SYMBOL*()`, because `EXPORT_PER_CPU_SYMBOL*` expands to a no-op under `__CHECKER__` to preserve the `__percpu` address-space qualifier in `sparse`. [F111]

## External Contracts
- Every `DECLARE_PER_CPU_SECTION()` declaration and its corresponding `DEFINE_PER_CPU_SECTION()` definition must pass the exact same section suffix `sec` to `__PCPU_ATTRS(sec)` so the compiler generates matching section access code. Broken by: declaring with `DECLARE_PER_CPU()` when defined with `DEFINE_PER_CPU_READ_MOSTLY()`, `DEFINE_PER_CPU_SHARED_ALIGNED()`, or `DEFINE_PER_CPU_PAGE_ALIGNED()`. [F99]
- On x86, `percpu_cmpxchg64_op`, `percpu_try_cmpxchg64_op`, `percpu_cmpxchg128_op`, and `percpu_try_cmpxchg128_op` must pass `&(_var)` in `"S"`, `old__` in `"+a"`/`"+d"`, `new__` in `"b"`/`"c"`, and wrap outputs in `ALT_OUTPUT_SP()` to match the `this_cpu_cmpxchg{8,16}b_emu` assembly ABI. [F98]

## Known Pitfalls
- `percpu_counter_initialized(fbc)` checks `fbc->counters != NULL` under `CONFIG_SMP`, but unconditionally returns `true` under `!CONFIG_SMP` (where `struct percpu_counter` has only `s64 count`). Broken by: relying on `percpu_counter_initialized(fbc)` on `!CONFIG_SMP` to detect uninitialized or destroyed counters. [F9]
- In `include/linux/percpu_counter.h`, `struct percpu_counter` and its API helpers are duplicated across `#ifdef CONFIG_SMP` and `#else /* !CONFIG_SMP */` blocks; any new or modified `percpu_counter_*` interface must be updated in both blocks in lockstep. [F52]
- `this_cpu_sub`, `__this_cpu_sub`, `this_cpu_sub_return`, `__this_cpu_sub_return`, and `raw_cpu_sub_return` must cast `val` to `typeof(pcp)` before unary negation (`-(typeof(pcp))(val)`) so subtracting a narrower unsigned value from a 64-bit per-CPU variable does not wrap at 32 bits and zero-extend. [F73]
- In `percpu_add_op`, the constant `-1` check must compare `(val) == (typeof(val))-1` in `val`'s full width before casting `(int)(val)` into `pao_ID__`, so a 64-bit `val` equal to `UINT_MAX` (`0xffffffffULL`) is not truncated to `-1` and emitted as `dec`. [F74]
- `PERCPU_PTR(__p)` must cast `__p` directly to `(TYPEOF_UNQUAL(*(__p)) __force __kernel *)((__force unsigned long)(__p))` without a statement-expression temporary variable, and `SHIFT_PERCPU_PTR(__p, __offset)` must apply `RELOC_HIDE()` to `PERCPU_PTR(__p)`. [F101]
