# IRQCHIP DRIVERS

This unit implements core irqchip probing, per-CPU IRQ partitioning, and interrupt/MSI controller drivers for ARM GIC (GICv3/v4, ITS, MBI, GICv2m, GIC PM), RISC-V (PLIC, APLIC, IMSIC, ACLINT SSWI), and SoC controllers (Atmel AIC/AIC5, BCM2712/2836, MediaTek CIRQ, PIC32, Qualcomm MPM, Renesas INTC-IRQPIN and RZ/G2L/V2H, Socionext EXIU, Sophgo SG2042/SG2044, STM32MP EXTI, sun4i/sun6i-r, TI Crossbar/PRUSS, and Xilinx INTC).

## Architecture & Data Flow

- Callers of `its_send_mapti()` must update `event_map.col_map[event]` before the call, whereas callers of `its_send_movi()` must update `col_map[event]` only after `its_send_movi()` returns because `its_build_movi_cmd()` reads the old collection via `dev_event_to_col()` for `SYNC`. [F59]
- In `its_vlpi_map()` and `its_vlpi_unmap()`, set `irqd_set_forwarded_to_vcpu(d)` before `lpi_write_config()` on map, and clear `irqd_clr_forwarded_to_vcpu(d)` before `lpi_update_config()` on unmap, because `get_vlpi_map()` checks `irqd_is_forwarded_to_vcpu(d)` to select `vprop_page` vs `prop_table_va`. In `lpi_update_config()`, `direct_lpi_inv(d)` is valid only when `gic_rdists->has_direct_lpi && (is_v4_1(its_dev->its) || !irqd_is_forwarded_to_vcpu(d))`; GICv4.0 forwarded vLPIs must use `its_send_vinv()`. [F61, F105]
- In `irq-gic-v3-its.c`, `event_lpi_map` arrays (`lpi_map`, `col_map`, `vlpi_maps`) are indexed by `its_get_event_id(d)` (`d->hwirq - lpi_base`), whereas LPI property tables (`prop_table_va`, `vprop_page` in `lpi_write_config()`) are indexed by `hwirq - 8192`. Similarly, `mip_middle_domain_free()`, `gicv2m_unalloc_msi()`, `mbi_free_msi()`, and `its_irq_domain_free()` must subtract `mip->msi_offset` (while GIC SPI fwspec uses `hwirq + mip->msi_base`), `v2m->spi_start`, `mbi->spi_start`, or `lpi_base` before freeing bitmap bits. [F85, F94, F128, F133]
- `irq_to_cpuid_lock()` and `irq_to_cpuid_unlock()` must check `d->chip == &its_vpe_irq_chip` before casting `d->chip_data` to `struct its_vpe *`, because non-vPE IRQs store `struct its_device *` in `d->chip_data` and only reach a vPE via `get_vlpi_map(d)`. [F42]
- In `its_vpe_set_affinity()`, whenever `from != cpu`, `its_send_vmovp()` and `its_vpe_db_proxy_move()` must always be called after updating `vpe->col_idx`, even if `from` and `cpu` share a GICv4.1 `vpe_table_mask`. Under `vpe_proxy.lock`, `its_vpe_db_proxy_map_locked()` and `its_vpe_db_proxy_unmap_locked()` must keep `vpe->vpe_proxy_event` (`-1` when unmapped) and `vpe_proxy.vpes[slot]` synchronized, evicting any existing occupant at `vpe_proxy.next_victim` first. [F58, F63]
- In `its_set_affinity()`, `its_dec_lpi_count(d, prev_cpu)` runs before `its_select_cpu()` / `cpumask_pick_least_loaded()`, so every exit path must either call `its_inc_lpi_count(d, cpu)` or branch to `err` to restore `its_inc_lpi_count(d, prev_cpu)`. [F60]
- `its_allocate_entry()` must zero `cmd->raw_cmd[0..3]`, and every ITS command builder must call `its_fixup_cmd(cmd)`. In `its_send_vmovp()`, `struct its_cmd_desc desc = {}` must be zero-initialized because the `!its_list_map` path leaves `seq_num` and `its_list` unset while `its_build_vmovp_cmd()` encodes both. `its_alloc_collections()` must initialize `target_address = ~0ULL` because `valid_col()` rejects entries with low 16 bits set, and when `!GITS_TYPER_PTA`, the CPU number must be left-shifted by 16. [F47, F48, F49, F92]
- When programming `GITS_BASER<n>`, `GITS_CBASER`, `GICR_PROPBASER`, or `GICR_PENDBASER`, if read-back shareability is 0, cacheability must be cleared and set to non-cacheable (`*_nC`). All `GITS_BASER<n>` writes must use `its_write_baser()` to update `baser->val`; in `its_restore_enable()`, writing `GITS_CBASER` resets `GITS_CREADR` to 0, so reset `its->cmd_write = its->cmd_base` and `gits_write_cwriter(0, ...)`. [F67, F68, F71]
- On GICv4.1 redistributors (`GICR_TYPER_RVPEID`), `__gic_update_rdist_properties()` and `allocate_vpe_l1_table()` must clear `GICR_VPENDBASER_Valid` (writing `GICR_VPENDBASER_PendingLast`) before clearing `GICR_VPROPBASER_4_1_VALID` or reprogramming `GICR_VPROPBASER`, and `inherit_vpe_l1_table_from_rd()` must clear `GICR_VPROPBASER_4_1_Z`. On GICv4.0 deschedule (`its_vpe_deschedule()`), `its_clear_vpend_valid()` must poll `GICR_VPENDBASER_Dirty` clear before and after clearing `Valid`, saving `IDAI` and `PendingLast` into `vpe`. [F70, F74, F151]
- In `its_of_probe()` and `its_acpi_probe()`, all ITS nodes must be reset via `its_reset_one()` before any `its_probe_one()` call, and `its_enable_quirks(its)` must run at the start of `its_probe_one()` before `is_v4(its)` or table allocations. In `its_cpu_init_lpis()`, when `RDIST_FLAGS_RD_TABLES_PREALLOCATED` and `GICR_CTLR_ENABLE_LPIS` are set, jumping to `out` skips `GICR_PROPBASER`/`PENDBASER` setup but must still run GICv4 `has_vlpis` and `allocate_vpe_l1_table()`. [F139, F141, F142]
- In `irq-gic-v3.c`, `gic_cpu_sys_reg_enable()` must precede `gic_prio_init()`, `gic_cpu_init()`, and `gic_cpu_sys_reg_init()` on boot, SMP startup, and CPU PM exit. `gic_chip` (EOImode 0) and `gic_eoimode1_chip` (EOImode 1) must be updated together for shared callbacks, flags, and EOI errata. EPPI hwirqs use `__gic_get_rdist_index()` (`hwirq - EPPI_BASE_INTID + 32`) and `__gic_get_ppi_index()` (`+ 16`), whereas ESPIs use `GICD_I*nE` at `hwirq - ESPI_BASE_INTID`. [F82, F96, F135]
- In `irq-riscv-imsic-state.c`, `global->nr_ids` is 1-based inclusive, so `lpriv->dirty_bitmap`, `lpriv->vectors`, and `imsic->matrix` must be sized to `global->nr_ids + 1` with ID 0 reserved in `imsic_matrix_init()` and skipped in `__imsic_local_sync()`. In `irq-sifive-plic.c`, `plic_irq_enable()` must call both `plic_irq_toggle(..., 1)` and `plic_irq_unmask(d)`, and `plic_set_affinity()` must clear the old per-hart enable bit using `irq_data_get_effective_affinity_mask(d)` before `irq_data_update_effective_affinity()` overwrites it, setting the new CPU's enable bit only if `!irqd_irq_disabled(d)`. [F242, F244, F261]

## Synchronization

- `its_irq_set_vcpu_affinity()` runs under `irq_desc` lock with IRQs disabled, so it must acquire `its_dev->event_map.vlpi_lock` via `guard(raw_spinlock)` (never `raw_spinlock_irq`), hold `vlpi_lock` across all GICv4 VLPI calls (`its_vlpi_map()`, `get()`, `unmap()`, `prop_update()`), and use `GFP_ATOMIC` in all helpers called under it. [F1, F18, F166]
- `its->dev_alloc_lock` (mutex) nests outside `its->lock` (raw spinlock protecting `its_device_list` and command queue). In GICv4 `ITSList` operations, locks must nest `vm->vmapp_lock` -> `vpe->vpe_lock` -> `vmovp_lock` -> `its->lock`. In `its_vpe_4_1_deschedule()`, when `info->req_db` is true, `vpe->vpe_lock` must be held with IRQs disabled across `its_clear_vpend_valid()` and updating `vpe->pending_last`. [F29, F163, F164]
- In `its_send_single_command()` and `its_send_single_vcommand()`, `its->lock` must be held through `its_flush_cmd()` and `its_post_commands()`, and dropped before `its_wait_for_range_completion()`. In `its_alloc_table_entry()` and `allocate_vpe_l2_table()`, a zeroed L2 page must be flushed to PoC (if non-shareable) before writing `page_to_phys(page) | GITS_BASER_VALID` to `table[idx]`, followed by flushing `table + idx` and `dsb(sy)`. [F24, F27]
- In `gic_complete_ack()`, an `isb()` is required after `ICC_IAR1_EL1` (and `ICC_EOIR1_EL1` in EOImode 1) before handling the IRQ/NMI; in `__gic_handle_irq_from_irqsoff()`, `gic_pmr_mask_irqs()` + `isb()` must precede `gic_read_iar()`; and in `gic_irq_set_irqchip_state()`, `gic_poke_irq(d, GICD_ISACTIVER)` must be followed by `gic_peek_irq(d, reg)` to flush the posted write. [F149, F169, F174]
- In `irq-riscv-imsic-state.c`, `lpriv->lock` nests outside `imsic->matrix_lock`, so code holding `matrix_lock` must never acquire `lpriv->lock` or call `imsic_vector_alloc()`/`free()`. Updates to `vec->enable`, `move_next`, `move_prev`, `lpriv->dirty_bitmap`, and `lpriv->timer` must hold `per_cpu_ptr(imsic->lpriv, vec->cpu)->lock` with IRQs disabled (`imsic_vector_mask()`/`unmask()` require IRQs already disabled), `imsic_state_offline()` must use `timer_delete_sync_try(&lpriv->timer)` while holding `lpriv->lock`, and `__imsic_local_timer_start()` must use `add_timer_on(&lpriv->timer, cpu)`. [F204, F205, F237, F334, F336]
- `aic_irq_domain_xlate()` and `aic5_irq_domain_xlate()` must use `guard(raw_spinlock_irqsave)` (not `raw_spinlock_irq`), and `aic5_*` callbacks must lock `&bgc->lock` on chip 0 while updating per-bank fields on `gc`. In `irq-qcom-mpm.c`, `priv->lock` must be released before calling `irq_resolve_mapping()`, `irq_set_irqchip_state()`, or parent chip callbacks. In `irq-pruss-intc.c`, `intc->lock` (mutex) must never be acquired in `pruss_irqchip` callbacks or `pruss_intc_irq_handler()`. [F108, F158, F212, F342]

## Object Lifetimes

- `its_alloc_pages_node()` and `its_free_pages()` pass `order` to `alloc_pages_node()`/`free_pages()` but page count `1 << order` to `set_memory_decrypted()`/`encrypted()`, and must leak pages rather than freeing them if decryption/encryption fails. `its_create_device()` must save the exact size passed to `itt_alloc_pool()` in `dev->itt_sz` for `itt_free_pool()`. [F3, F123, F125]
- `its_vlpi_map()` must increment `nr_vlpis` and call `its_map_vm()` only when `!irqd_is_forwarded_to_vcpu(d)`, and `its_vlpi_unmap()` must clear `event_map.vm = NULL` and free `vlpi_maps` when `!--nr_vlpis` reaches 0. `its_msi_teardown()` must hold `its->dev_alloc_lock` and skip unmapping/freeing `its_dev` when `its_dev->shared` is true or `lpi_map` is non-empty. [F6, F7]
- `gicv2m_init_one()` takes ownership of `fwnode` only on success, so callers must free `child`/`fwnode` on error (and on early break from `of_find_matching_node()` in `gicv2m_of_init()`). `gicv2m_get_fwnode()` and `gic_v3_get_gsi_domain_id()` are called at runtime and must not be `__init`. In `gic_runtime_resume()`, return `0` after enabling clocks if `chip_pm->chip_data` is `NULL`. [F13, F16, F99, F134]
- During IMSIC vector migration in `__imsic_local_sync()`, the old CPU frees `vec` after clearing `vec->move_next`, and the new CPU must not clear `vec->move_prev` or its `dirty_bitmap` bit while `READ_ONCE(mvec->move_next)` is non-NULL. [F195]

## API Contracts

- `its_irq_set_vcpu_affinity()` accepts `vcpu_info == NULL` to unmap, so check `!info` before dereferencing it, and `its_vlpi_get()`/`unmap()`/`prop_update()` must check `event_map.vm && irqd_is_forwarded_to_vcpu(d)` before indexing `vlpi_maps`. In `its_vpe_set_affinity()`, when `!atomic_read(&vpe->vmapp_count)`, return `-EINVAL` only if `gic_requires_eager_mapping()` is true. In `its_build_vmapp_cmd()`, unmapping on GICv4.1 (`!valid && is_v4_1(its)`) must return `NULL` to suppress `VSYNC`. `gic_retrigger()`, `its_irq_retrigger()`, and `its_vpe_retrigger()` must negate (`!`) the 0-on-success return of `*_set_irqchip_state()`. [F40, F44, F98, F140]
- Every `msi_prepare` callback over an ITS domain must set `info->scratchpad[0].ul` to the DeviceID and round `nvec` up to a power of two (as must `gicv2m_irq_domain_alloc()`). In `msi_parent_ops` using `msi_lib_init_dev_msi_info()`, fasteoi parents (`mip`, `gic_v3_its`, `gic_v5_its`, `gicv2m`, `gic_v3_mbi`) must set `MSI_CHIP_FLAG_SET_EOI` and never `MSI_CHIP_FLAG_SET_ACK`, whereas edge parents (`sg2042`, `sg2044`, `imsic`) must set `MSI_CHIP_FLAG_SET_ACK`. [F52, F88, F121, F175, F176, F347]
- GIC MSI `.alloc` callbacks must call `iommu_dma_prepare_msi(info->desc, msi_addr)`, and `.irq_compose_msi_msg` callbacks must use `msi_msg_set_addr()` (or physical doorbell addresses in `sg2042`/`sg2044`/`imsic`, never ioremapped VAs). In GICv3 EOImode 1, `gic_eoimode1_mask_irq()` must write `GICD_ICACTIVER` when `irqd_is_forwarded_to_vcpu(d)` is true, and `gic_irq_domain_map()` must call `irqd_set_handle_enforce_irqctx(irqd)`. [F179, F182, F183, F343]
- `imsic_irq_domain_alloc()` and `.irq_set_affinity` callbacks (`imsic`, `aplic_direct`, `plic`) must call `irq_data_update_effective_affinity()`. Non-atomic MSI domains over `imsic_base_domain_ops` (PCI MSI/MSI-X) must set `IRQCHIP_MOVE_DEFERRED` so `imsic_irq_ack()` calls `irq_move_irq(d)`, whereas `aplic_msi_template` must not. In RISC-V APLIC (`irq-riscv-aplic-*.c`), source 0 is reserved (`1..priv->nr_irqs`): `APLIC_SETIENUM`/`CLRIENUM`/`SETIPNUM_LE` take `d->hwirq`, `APLIC_SOURCECFG_BASE`/`TARGET_BASE` use `(d->hwirq - 1) * sizeof(u32)`, domain size is `priv->nr_irqs + 1`, and `aplic_msi_translate()` must get `aplic_priv` from `((struct msi_domain_info *)d->host_data)->data`. [F224, F310, F348, F349]

## Error Handling

- `its_lpi_alloc()` halves `nr_irqs` to fit and returns actual count in `*nr_ids`, so callers requiring `nr_irqs` (like `its_vpe_irq_domain_alloc()`) must check `*nr_ids < nr_irqs` and call `its_lpi_free()`; if the vPE loop in `its_vpe_irq_domain_alloc()` fails after assigning `vm->db_bitmap` and `vm->vprop_page`, rollback must call `its_vpe_irq_domain_free(domain, virq, i)` without also calling `its_lpi_free()` or `its_free_prop_table()` directly. [F2, F37]
- `gic_cpu_pm_notifier()` must restore state on both `CPU_PM_EXIT` and `CPU_PM_ENTER_FAILED`. In `gic_set_type()`, `gic_configure_irq()` failure on a PPI/EPPI must warn and return `0`. Runtime polling timeouts in GICv3/ITS and unmapped-ID logs in RISC-V handlers (`aplic_direct`, `plic`, `imsic`) must use ratelimited printk, never `WARN_ON()`. [F136, F188, F189, F359]
- In `plic_probe()`, set `error = -E...` before jumping to `fail_cleanup_contexts` after `plic_parse_context_parent()` overwrites `error = 0`, and reset `handler->present = false` and clear fields on `plic_handlers` on failure. In `imsic_irqdomain_init()`, check `!imsic || !imsic->fwnode` before dereferencing `imsic`, and in `imsic_vector_alloc()`, store `irq_matrix_alloc()` in a signed `int` and reset `irq`, `enable`, `move_next`, and `move_prev`. Check `d->parent_data` in `qcom_mpm_*` and `d->parent_data->chip` in `stm32mp_exti_*` before calling `irq_chip_*_parent()`. [F199, F216, F218, F221, F222, F226]

## External Contracts

- Before writing `GITS_BASER<n>` or `GITS_CBASER`, `its_force_quiescent()` must clear `GITS_CTLR_ENABLE` and `GITS_CTLR_ImDe` and poll `GITS_CTLR_QUIESCENT`. `gic_mask_irq()` must wait for `RWP` after writing `GICD_ICENABLER`, and `gic_set_affinity()` must mask an enabled IRQ before writing `GICD_IROUTER` and unmask afterward. [F28, F34]

## Known Pitfalls

- In `gic_init_bases()`, `gic_enable_quirks()` must precede reading `GICD_TYPER2`, which must be guarded by `!(gic_data.flags & FLAGS_WORKAROUND_CAVIUM_ERRATUM_38539)`; every `struct gic_quirk` table needs a `.desc = NULL` sentinel. Under `gic_nvidia_t241_erratum`, `gic_peek_irq()` and `gic_set_type()` must use `gic_dist_base_alias(d)` for SPI/ESPI while `gic_poke_irq()` writes `gic_data.dist_base`. When `gic_arm64_erratum_2941627_needed(d)` is true, `gic_eoi_irq()` and `gic_eoimode1_eoi_irq()` must write `GICD_ICACTIVER` via `gic_poke_irq()`. [F97, F145, F147, F148]
- In `its_vpe_*_mask_irq()`/`unmask_irq()`, pass `d->parent_data` to `lpi_write_config()`, but pass `d` and `d->parent_data->hwirq` to `its_vpe_send_inv()` / `__direct_lpi_inv()`. On GICv4.0, `its_vlpi_set_doorbell()` must update a mapped vLPI via `its_send_vmovi()`, never `its_send_vmapti()`. In `its_sgi_set_irqchip_state()`, subtract `SZ_128K` when using `its->sgir_base + GITS_SGIR`. In `its_lpi_init()`, check `numlpis > 2` because `GICD_TYPER_NUM_LPIS(0)` is `2`. [F104, F120, F127, F186]
- In `irq-renesas-rzg2l.c`, `irq-renesas-rzv2h.c`, and `irq-pic32-evic.c`, callbacks must get driver priv from `d->domain->host_data` (`irq_data_to_priv` / `irqd_to_priv`), never `d->chip_data`; in `rzg2l`, shift `TSSR` fields by `TSSEL_SHIFT(tssr_offset)` (`8 * tssr_offset`); in `rzv2h_tint_irq_endisable()`, write `BIT(tint_nr)` to `ICU_TSCLR` after `ICU_TSSR(k)` under `priv->lock`; and in `rzg2l`/`rzv2h`, only clear `ISCR`/`ICU_ISCLR`/`ICU_TSCLR` when edge-triggered. `imsic_early_dt_init()` must call `of_node_clear_flag(node, OF_POPULATED)` so `imsic_platform_driver` can bind, and `aplic_msi_write_msg()` must cast `msg->address_hi` to `u64` before `<< 32`. [F220, F249, F290, F311, F312, F316, F329]
