# MEMORY MAPPING

The MEMORY MAPPING subsystem (`mm/`) manages virtual memory areas (VMAs) and user address space layout on MMU and no-MMU architectures, implementing VMA lifecycle, maple tree and interval tree indexing, merging, splitting, and page table manipulation for `mmap`, `munmap`, `brk`, `mremap`, `mprotect`, `mlock`, `mincore`, `msync`, and `mseal`.

## Architecture & Data Flow

- `vma_merge_existing_range()` and `vma_merge_new_range()` must verify `can_merge_remove_vma()` (`!vma->vm_ops || !vma->vm_ops->close`) on any VMA to be deleted (`middle` or `next`), as `vma_complete()` frees `vp->remove`/`vp->remove2` without `vma_close()`; `special_mapping_vmops` relies on `.close` and `.may_split` to prevent removal or splitting. If `vmg->__remove_next && !can_merge_remove_vma(next)` in `vma_merge_existing_range()`, reduce a 3-way merge to left-only (`merge_right = merge_both = false`) and set `vmg->target = prev` after `if (merge_right) vmg->target = next;`. [F4, F101, F159]
- In `can_vma_merge_right()`, when `can_merge_left` is true after `can_vma_merge_before(vmg)` succeeds, it must also verify `!prev->anon_vma || !next->anon_vma || prev->anon_vma == next->anon_vma`, because an unfaulted middle range can be compatible with both `prev` and `next` when their `anon_vma`s differ. [F100]
- `vms_gather_munmap_vmas()` stores detached VMAs into `mas_detach` at 0-based indices `[0, vms->vma_count - 1]`. `vms_clear_ptes()` must position `mas_detach` at index 1 before passing `vms->vma` (index 0) to `unmap_vmas()` and `free_pgtables()`, whereas full walks in `vms_complete_munmap_vmas()` and `reattach_vmas()` start at index 0. [F88]
- In `move_normal_pmd()` and `move_normal_pud()`, `uffd_supports_page_table_move(pmc)` must check `!vma_has_uffd_without_event_remap()` on both `pmc->old` and `pmc->new` before checking `pmd_none(*new_pmd)`/`pud_none(*new_pud)` so `pmc_revert` recurses symmetrically. In `move_ptes()`, if `vma_has_uffd_without_event_remap(vma)` holds, drop uffd-wp PTE markers via `pte_clear()` and strip uffd-wp bits via `pte_clear_uffd_wp()` and `pte_swp_clear_uffd_wp()`. [F62, F63]
- In `check_prep_vma()`, when `is_vm_hugetlb_page(vma)` is true, `align_hugetlb(vrm)` must run before `vrm_set_delta(vrm)` and `vrm_remap_type(vrm)` to align `old_len` and `new_len` to `huge_page_size(h)`, check `addr`/`new_addr` against `~huge_page_mask(h)`, and reject `new_len > old_len`. [F94]
- In `can_change_shared_pte_writable()`, a PTE in a writable `VM_SHARED` mapping may only be upgraded to writable during `mprotect()` if `pte_dirty(pte)` is already true (besides `maybe_change_pte_writable(vma, pte)`), as clean PTEs may require a write fault for writenotify. [F168]
- In `__mmap_new_vma()`, `khugepaged_enter_vma()` must only be called when `!vma_is_anonymous(vma)`, because private anonymous VMAs register with `khugepaged` on page fault. [F157]
- `munlock_folio()` must leave clearing `PG_mlocked` to `__munlock_folio()`, which decrements `folio->mlock_count` under the lruvec lock, clears `PG_mlocked` via `folio_test_clear_mlocked()` only when `mlock_count` reaches zero, and checks `folio_evictable()` only after `PG_mlocked` is cleared. [F66]

## Synchronization

- When `unlock` is `true`, `do_vmi_munmap()` and `do_vmi_align_munmap()` release `mm->mmap_lock` only when returning `0`; on non-zero error returns, `mm->mmap_lock` remains write-locked and the caller (`__vm_munmap()`, `SYSCALL_DEFINE1(brk)`, `shrink_vma()`) must unlock it. [F13]
- `expand_stack(mm, addr)` (in `mm/mmap.c` and `mm/nommu.c`) must be called with `mm->mmap_lock` held for reading; on non-NULL return `mm->mmap_lock` remains read-locked (via `mmap_write_downgrade()`), whereas on `NULL` return it has already dropped `mm->mmap_lock`. [F14]
- Before inserting a VMA into `mm->mm_mt` via `vma_iter_store_new()` or `vma_iter_store_gfp()` or linking it via `vma_link_file()`, the caller must call `vma_start_write(vma)` so `vma_mark_attached()` and subsequent `i_mmap_lock_write()` observe the VMA write-locked. [F22]
- In `__mmap_prepare()`, `vms_clean_up_area()` must unmap PTEs (`vms_clear_ptes()`) and call `vma_close()` on overlapping VMAs while they are still in `mm->mm_mt`, before `vma_merge_new_range()` or `__mmap_new_vma()` overwrites the maple tree range and before `vms_complete_munmap_vmas()` runs. [F27]
- `mm_take_all_locks(mm)` requires `mm->mmap_lock` write-locked until `mm_drop_all_locks(mm)`, serializes via `mm_all_locks_mutex`, and locks in order: `vma_start_write()`, hugetlb `i_mmap_rwsem`, regular `i_mmap_rwsem`, and `anon_vma->root->rwsem`. `vm_lock_anon_vma()` sets bit 0 of `anon_vma->root->rb_root.rb_root.rb_node`, and `vm_unlock_anon_vma()` must clear bit 0 via `__test_and_clear_bit()` before `anon_vma_unlock_write(anon_vma)`. [F26, F92]
- During `move_page_tables()`, `take_rmap_locks(pmc->old)` (`i_mmap_lock_write` then `anon_vma_lock_write`) must be held when moving `NORMAL_PMD`/`NORMAL_PUD` entries (`should_take_rmap_locks()`) and when `pmc->need_rmap_locks` is true. In `move_normal_pmd()`, after taking `old_ptl` and `new_ptl`, re-read `*old_pmd` and abort if `!pmd_present(pmd) || pmd_leaf(pmd)` before clearing `old_pmd` to guard against THP `retract_page_tables()`. [F36, F37]
- `reusable_anon_vma()` runs under `mmap_read_lock` where a neighbour VMA's `anon_vma` may be concurrently faulted in, so it must load `READ_ONCE(old->anon_vma)` into a local variable once before checking `list_is_singular(&old->anon_vma_chain)` rather than reloading `old->anon_vma`. [F32]
- In `SYSCALL_DEFINE5(remap_file_pages)`, `security_mmap_file()` must be called outside `mm->mmap_lock` after pinning `file = get_file(vma->vm_file)` and dropping `mmap_read_unlock(mm)`; after `mmap_write_lock_killable(mm)`, the VMA must be re-looked up and revalidated (`vma->vm_flags == vm_flags && vma->vm_file == file`). [F154]
- In `mincore_swap()`, when `shmem` is true (lockless shmem lookup), pin the swap device via `get_swap_device(entry)` and `put_swap_device(si)` around `swap_cache_get_folio(entry)`; when `shmem` is false, the caller must hold the PTE spinlock `ptl`. [F41]
- Per-CPU `mlock_fbatch.fbatch` accesses in `mlock_folio()`, `mlock_new_folio()`, `munlock_folio()`, and `mlock_drain_local()` must hold `local_lock(&mlock_fbatch.lock)`, whereas `mlock_drain_remote(cpu)` accesses `per_cpu(mlock_fbatch.fbatch, cpu)` locklessly only when `cpu` is offline. [F135]
- In `mm/nommu.c`, `nommu_region_tree` and `struct vm_region` (`vm_usage`, `vm_start`, `vm_end`, `vm_top`) are protected by `nommu_region_sem`, which nests outside `i_mmap_rwsem`. `__put_nommu_region(region)` requires `nommu_region_sem` held for writing and always drops it via `up_write(&nommu_region_sem)` before freeing resources. [F19, F42]

## Object Lifetimes

- All VMA teardown and rollback paths (`remove_vma()`, `vms_clean_up_area()`, `copy_vma()`, `delete_vma()`) must close the VMA via `vma_close(vma)` rather than calling `vma->vm_ops->close(vma)` directly, because `vma_close()` resets `vma->vm_ops` to `&vma_dummy_vm_ops` to prevent double `.close()`. [F1]
- `vm_area_dup()` shallow-copies `orig->vm_file`, `orig->vm_policy`, and `orig->anon_vma` without incrementing refcounts; callers (`__split_vma()`, `copy_vma()`, `dup_mmap()`) must separately acquire and on error unwind `vma_dup_policy()` (`mpol_put()`), `anon_vma_clone()`/`anon_vma_fork()` (`unlink_anon_vmas()`), and `get_file()` (`fput()`) before `vm_area_free()`. [F10]
- Every successful `vma_iter_prealloc(vmi, ...)` in `__split_vma()`, `__mmap_new_vma()`, `expand_upwards()`, and `expand_downwards()` that does not consume the preallocated maple nodes via `vma_iter_store_new()`, `vma_iter_store_overwrite()`, or `vma_iter_clear()` must release them with `vma_iter_free(vmi)`. [F8]
- Any `mt_on_stack()` maple tree populated via `vms_gather_munmap_vmas()` (`do_vmi_align_munmap()`, `__mmap_prepare()`) must be destroyed on every exit path via `vms_complete_munmap_vmas()`, `reattach_vmas()`, or `vms_abort_munmap_vmas()`. `vms_abort_munmap_vmas()` may call `reattach_vmas()` only while `vms->clear_ptes` is true; once PTEs are cleared, it must store `NULL` with `GFP_KERNEL|__GFP_NOFAIL` and call `vms_complete_munmap_vmas()`. [F6, F132]
- `user_shm_lock()` must charge `UCOUNT_RLIMIT_MEMLOCK` against the passed-in `ucounts` via `inc_rlimit_ucounts()` and pin it with `get_ucounts(ucounts)` under `shmlock_user_lock` (calling `dec_rlimit_ucounts()` on limit failure or if `get_ucounts()` returns `NULL`), paired with `user_shm_unlock()`. [F170]

## API Contracts

- `vma_modify()` and its wrappers (`vma_modify_flags()`, `vma_modify_name()`, `vma_modify_policy()`, `vma_modify_flags_uffd()`) return an `IS_ERR()` pointer on failure and never `NULL`, whereas `vma_merge_new_range()`, `vma_merge_extend()`, and `copy_vma()` return `NULL` on failure or non-merge. [F44]
- `do_mmap()`, `mmap_region()`, `__get_unmapped_area()`, `do_mremap()`, and `mremap_to()` return an `unsigned long` that is either a page-aligned address or a negative errno cast to `unsigned long`; callers must check `IS_ERR_VALUE()` (or `offset_in_page()`) rather than `< 0`, `IS_ERR()`, or `!addr`. [F59]
- `vma_iter_config()`, `vma_iter_area_lowest()`, `vma_iter_area_highest()`, and `find_vma_intersection()` take an exclusive upper address and subtract 1 internally, whereas raw `mas_set_range()` and `__mas_set_range()` require an inclusive upper bound (`vm_end - 1`). [F58]
- When preallocating a maple tree iterator via `vma_iter_prealloc(vmi, vma)` before clearing an entry with `vma_iter_clear(vmi)` (as in `vma_shrink()` and `delete_vma_from_mm()`), the second argument must be `NULL` rather than the VMA pointer. [F48]
- After `__split_vma()` stores the new VMA via `vma_complete()`, it must reposition `vmi` onto the remaining original `vma` by calling `vma_next(vmi)` when `new_below` is non-zero and `vma_prev(vmi)` when `new_below` is zero. [F67]
- In `vms_gather_munmap_vmas()`, after `for_each_vma_range(*(vms->vmi), next, vms->end)` and `vms->next = vma_next(vms->vmi)` advance `vms->vmi` past the unmapped range, `vms->vmi` must be rewound via `while (vma_iter_addr(vms->vmi) > vms->start) vma_iter_prev_range(vms->vmi);` before returning `0`. [F110]
- Any VMA with `vm_ops == &special_mapping_vmops` must have `vm_private_data` pointing to a `struct vm_special_mapping`; when `sm->fault` is `NULL`, `sm->pages` must be NULL-terminated if shorter than `len >> PAGE_SHIFT`, and `special_mapping_fault()` must walk `sm->pages` sequentially stopping at `NULL` rather than indexing `sm->pages[vmf->pgoff]`. [F87, F131]
- In `mlock_folio()`, `mlock_new_folio()`, and `munlock_folio()`, after adding a folio to `mlock_fbatch`, `mlock_folio_batch()` must be called immediately when `!folio_may_be_lru_cached(folio)` (rather than testing `folio_test_large(folio)`). [F155]
- On `!CONFIG_MMU`, `remap_vmalloc_range()` must reject any VMA lacking `VM_USERMAP` with `-EINVAL`, and `vmalloc_user_noprof()` / `vmalloc_32_user_noprof()` must pass `__GFP_ZERO` and set `VM_USERMAP` on the VMA. [F174]

## Error Handling

- File-backed VMA setup in `__mmap_new_file_vma()`, `do_mmap_shared_file()`, and `do_mmap_private()` must invoke `mmap_file()` rather than `vfs_mmap()` directly, so that if `file->f_op->mmap` fails, `vma->vm_ops` is reset to `&vma_dummy_vm_ops` before cleanup runs. [F2]
- When `dup_anon_vma()` clones `src->anon_vma` into `dst` with `dst->anon_vma == NULL` (recording `dst` in `*dup`), any subsequent `commit_merge()` failure in `vma_merge_existing_range()` or `vma_expand()` must call `unlink_anon_vmas(anon_dup)`. In `vma_merge_existing_range()`, if `dup_anon_vma()` or `commit_merge()` fails, also restore `vmg->vmi` to `start` via `vma_iter_set(vmg->vmi, start)` and `vma_iter_load(vmg->vmi)`. [F5, F68]
- `vma_merge_new_range()` and `vma_merge_existing_range()` return `NULL` both on non-merge and on OOM, so callers that cannot ignore OOM (`vma_modify()`, `do_brk_flags()`) must check `vmg_nomem(vmg)` unless `vmg->give_up_on_oom` is set. Because `vma_merge_existing_range()` mutates `vmg->start`, `vmg->end`, and `vmg->pgoff` before `commit_merge()` can fail, `vma_modify()` must snapshot `vmg->start` and `vmg->end` beforehand and return `ERR_PTR(-ENOMEM)` if `vmg_nomem(vmg)` is true. [F43, F69]
- In `expand_vma_in_place()` and `copy_vma_and_data()`, do not overwrite `vrm->vma` with a `NULL` return from `vma_merge_extend()` or `copy_vma()` before `vrm_uncharge(vrm)`. If `move_page_tables(&pmc)` is incomplete or `vm_ops->mremap(new_vma)` fails in `copy_vma_and_data()`, move `moved_len` bytes back to `vma` with `pmc_revert.need_rmap_locks = true` and set `vrm->vma = new_vma`, `vrm->old_len = vrm->new_len`, and `vrm->addr = vrm->new_addr` so `move_vma()` still runs `vrm_stat_account()` and `unmap_source_vma()`. [F11, F46, F56]

## External Contracts

- In `SYSCALL_DEFINE5(mremap)` and `do_mremap()`, `addr` must be untagged via `untagged_addr(addr)` while `new_addr` must remain tagged so `check_mremap_params()` rejects a tagged `new_addr` via `vrm->new_addr > TASK_SIZE - vrm->new_len`. [F83]
- In `do_mmap()`, unrecognized `flags` bits outside `LEGACY_MAP_MASK` must be silently masked off under `MAP_SHARED`, and rejected with `-EOPNOTSUPP` only under `MAP_SHARED_VALIDATE` (where `MAP_SYNC` requires `file->f_op->fop_flags & FOP_MMAP_SYNC`). [F160]
- In `SYSCALL_DEFINE1(brk)`, `check_data_rlimit()` must be evaluated against the unaligned `brk` before comparing `PAGE_ALIGN(brk)` with `PAGE_ALIGN(mm->brk)`, and `mm->brk` must be updated under `mmap_write_lock(mm)` before `do_vmi_align_munmap(..., unlock = true)` drops the lock. [F171]
- In `do_mprotect_pkey()`, `VM_ACCESS_FLAGS | VM_FLAGS_CLEAR` must be masked off from `vma->vm_flags` before ORing in `calc_vm_prot_bits(prot, new_vma_pkey)`, and any access bit lacking its `VM_MAY*` bit (`(newflags & ~(newflags >> 4)) & VM_ACCESS_FLAGS`) must fail with `-EACCES`. [F173]

## Known Pitfalls

- In `copy_vma()`, when `vma->vm_file` is non-NULL, `vmg.skip_vma_uprobe` must be set to `true` before calling `vma_merge_new_range(&vmg)` so `vma_complete()` does not call `uprobe_mmap()` to install a uprobe PTE that `move_page_tables()` will overwrite and orphan. [F9]
- When a PTE loop advances its `pte_t *` pointer to the end of the range (`mincore_pte_range()`, `change_pte_range()`, `move_ptes()`), `pte_unmap()` or `pte_unmap_unlock()` must be passed `pte - 1` (or the initial `start_pte` as in `mlock_pte_range()`) rather than the post-loop pointer. [F127]
- In `mm/mremap.c`, because `try_realign_addr()` rounds `pmc->old_addr` down to `PMD_MASK` without adjusting `pmc->old_end` or `pmc->len_in`, `pmc_progress()` must return `0` when `pmc->old_addr < pmc->old_end - pmc->len_in`. In `get_extent()`, the distance to `next = (addr + size) & mask` must be computed via unsigned modular subtraction (`next - old_addr` and `next - new_addr`) rather than clamping `next` to `old_end` first. [F85, F117]
- In `vma_iter_next_rewind()`, after calling `vma_next(vmi)` followed by `vma_prev(vmi)`, `vma_iter_next_range(vmi)` must only be called when `prev` is non-NULL, because when `!prev`, `vma_prev(vmi)` has already positioned `vmi` at the initial gap. [F111]
- Overflow checks: in `do_mmap()`, `vm_brk_flags()`, and `do_mseal()`, check `PAGE_ALIGN(len)` for wraparound to `0`; in `__do_sys_mincore()`, compute `pages` as `(len >> PAGE_SHIFT) + (offset_in_page(len) != 0)`; in `do_mlock()` and `__do_sys_munlock()`, add `offset_in_page(start)` to `len` before `PAGE_ALIGN(len)` and mask `start &= PAGE_MASK` after; in `count_mm_mlocked_page_nr()`, clamp `end` when `ULONG_MAX - len < start`; in `file_mmap_ok()`, check `len > maxsize` then `pgoff > (maxsize - len) >> PAGE_SHIFT`. [F93, F118, F120, F122, F123]
- In `mm/nommu.c`, `__vmalloc_noprof()` and `vrealloc_node_align_noprof()` must mask off `__GFP_HIGHMEM` (`(gfp_mask | __GFP_COMP) & ~__GFP_HIGHMEM`) before delegating to `kmalloc_noprof()` or `krealloc_noprof()`. [F153]
