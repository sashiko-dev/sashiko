# USB MASS STORAGE DRIVER

This unit (`drivers/usb/storage`) implements the core lifecycle, USB transfer engine, and transport protocols (Bulk-Only, Control/Bulk, and Control/Bulk/Interrupt) for the Linux USB Mass Storage driver, along with device quirk tables, UAS capability detection, and subdrivers for Shuttle USBAT bridges and Sierra Wireless TRU-Install modems.

## Architecture & Data Flow
- `us_unusual_dev_list` in `usb.c` and `usb_storage_usb_ids` in `usual-tables.c` (and `usbat_unusual_dev_list` / `usbat_usb_ids` in `shuttle_usbat.c`) must expand `UNUSUAL_DEV`, `COMPLIANT_DEV`, and `USUAL_DEV` in identical 1-to-1 order so probe routines can index via `(id - *_usb_ids)`. In `unusual_devs.h`, all device-specific entries (including `unusual_uas.h`) must precede class-wide `USUAL_DEV` entries. Every separate subdriver's `unusual_*.h` header must also be included in `ignore_ids[]` in `usual-tables.c` so `usb_usual_ignore_device()` prevents `usb-storage` from binding. [F46, F47, F79]
- When blacklisting UAS via `US_FL_IGNORE_UAS` in `unusual_uas.h` for a device that also matches an earlier `UNUSUAL_DEV` entry in `unusual_devs.h`, `US_FL_IGNORE_UAS` must be added to that `unusual_devs.h` entry as well because `usb_storage_usb_ids` includes `unusual_devs.h` before `unusual_uas.h`. [F45]
- In `uas_use_uas_driver()` and `get_device_info()`, `usb_stor_adjust_quirks()` must be called after initializing flags from `id->driver_info` and applying descriptor-based quirk flags, and before testing `US_FL_IGNORE_UAS` or `US_FL_IGNORE_DEVICE`. Any `US_FL_*` flag added to the switch in `usb_stor_adjust_quirks()` that should be clearable via the `quirks` module parameter must also be included in `mask` so `*fflags = (*fflags & ~mask) | f` clears the static table bit when omitted. [F48, F115]
- In `usb_stor_invoke_transport()`, `scsi_eh_restore_cmnd(srb, &ses)` must be called immediately after `us->transport(us->srb, us)` before any retry jump (`goto Retry_Sense`), error exit, or inspection of `srb` fields because `scsi_eh_prep_cmnd()` overwrites `srb` in place with a `REQUEST_SENSE` command. When disabling `US_FL_SANE_SENSE` after an oversized auto-`REQUEST_SENSE` times out or fails, it must simultaneously set `US_FL_BAD_SENSE` in `us->fflags` so subsequent ATA passthrough commands or sense responses do not re-enable `US_FL_SANE_SENSE`. [F49, F50]
- In `usb_stor_Bulk_transport()`, `bcb` (`struct bulk_cb_wrap *`) and `bcs` (`struct bulk_cs_wrap *`) both alias `us->iobuf`. Before `memcpy(bcb->CDB, srb->cmnd, bcb->Length)`, `bcb->CDB` must be zeroed with `memset(bcb->CDB, 0, sizeof(bcb->CDB))` and `us->iobuf[31]` must be zeroed when `US_FL_BULK32` is set. Receiving the CSW into `bcs` overwrites `bcb`, so status-stage checks must use saved state in `us->tag`, `transfer_length`, and `srb->cmnd` rather than reading `bcb` fields. [F36, F106]
- The USB runtime PM reference acquired by `usb_autopm_get_interface_no_resume()` in `usb_stor_probe2()` is tracked by `US_FLIDX_SCAN_PENDING` after `scsi_add_host()` succeeds: `usb_stor_scan_dwork()` must drop it via `usb_autopm_put_interface()` before clearing `US_FLIDX_SCAN_PENDING`, and `quiesce_and_remove_host()` drops it if `US_FLIDX_SCAN_PENDING` remains set after `cancel_delayed_work_sync()`. [F5]
- `us->max_lun` stores the inclusive maximum 0-based LUN number (bounded by `US_BULK_MAX_LUN_LIMIT = 15` in `usb_stor_Bulk_max_lun()` and checked via `srb->device->lun > us->max_lun`), whereas `Scsi_Host->max_lun` stores the exclusive LUN count and must be set to `us->max_lun + 1`. [F69]
- In `shuttle_usbat.c` (`usbat_info->sectors` from `usbat_flash_get_sector_count()`) and `last_sector_hacks()` (`sdkp->capacity`), capacities store the total sector count, whereas SCSI `READ_CAPACITY` responses and `READ_10`/`WRITE_10` LBAs use 0-based sector numbers (last sector is `capacity - 1`). In `last_sector_hacks()`, `us->last_sector_retries` must remain preserved via early return when `++us->last_sector_retries < 3` on a failed last-sector `READ_10`/`WRITE_10`, and must not be reset at `done:` when `srb->cmnd[0] == TEST_UNIT_READY`. [F76, F82]
- In `get_pipes()`, `usb_find_int_in_endpoint()` is required only when `us->protocol == USB_PR_CBI`; for other protocols `ep_int` can be NULL and must be checked before populating `us->recv_intr_pipe` and `us->ep_bInterval`, and `usb_stor_CB_transport()` must only call `usb_stor_intr_transfer()` when `us->protocol == USB_PR_CBI`. When `usb_stor_clear_halt()` clears `USB_ENDPOINT_HALT`, it must also call `usb_reset_endpoint(us->pusb_dev, endp)` on success. [F28, F60]
- In `usbat_hp8200e_rw_block_test()` and `usbat_multiple_write()`, both the setup command packet and the interleaved register/data payload (`num_registers * 2` bytes) alias the 64-byte `us->iobuf`, so `num_registers` must not exceed `US_IOBUF_SIZE / 2` (32) and `data[]` must only be populated after `usbat_execute_command()` has transmitted `command[]`. In `usbat_hp8200e_rw_block_test()`, only the first iteration (`i == 0`) may set `cmdlen = 16` to send `USBAT_CMD_WRITE_REGS` and bulk-write the register/data pairs; retry iterations (`i > 0`) must set `cmdlen = 8`. [F90, F100]

## Synchronization
- When both locks are held, `us->dev_mutex` must be acquired before `scsi_lock(host)` (`host->host_lock`). In `usb_stor_control_thread()` after processing a command, under `scsi_lock(host)` the thread must clear `us->srb = NULL` and test `US_FLIDX_TIMED_OUT` in `us->dflags` (not `srb->result == DID_ABORT << 16`) to decide whether to signal `us->notify` and clear `US_FLIDX_ABORTING` and `US_FLIDX_TIMED_OUT`; both locks must then be released before calling `scsi_done_direct(srb)` (skipped when `srb->result == DID_ABORT << 16`). [F6, F15, F17]
- In `usb_stor_msg_common()` and `usb_stor_bulk_transfer_sglist()`, `US_FLIDX_URB_ACTIVE` and `US_FLIDX_SG_ACTIVE` must be set only after `usb_submit_urb()` or `usb_sg_init()` succeeds, after which `US_FLIDX_ABORTING` must be rechecked and cancellation guarded by `test_and_clear_bit()` on the active flag (matching `usb_stor_stop_transport()`). [F19]
- In `usb_stor_invoke_transport()`, `Handle_Errors` must hold `scsi_lock(us_to_host(us))` while setting `US_FLIDX_RESETTING` and clearing `US_FLIDX_ABORTING` before releasing `us->dev_mutex`, and must release `us->dev_mutex` before calling `usb_stor_port_reset(us)` and re-acquire it afterward because `usb_stor_pre_reset()` locks `us->dev_mutex` and `usb_stor_post_reset()` reports the bus reset and unlocks it. `usb_stor_suspend()` and `usb_stor_resume()` must also hold `us->dev_mutex` around `us->suspend_resume_hook()`. [F11, F52, F124]
- In `usb_stor_invoke_transport()`, `scsi_lock(us_to_host(us))` must be held around `usb_stor_report_device_reset(us)`, whereas `usb_stor_reset_resume()` and `usb_stor_post_reset()` must not hold `scsi_lock` when calling `usb_stor_report_bus_reset(us)`. After blocking in `usb_lock_device_for_reset()` in `usb_stor_port_reset()` or in `wait_event_interruptible_timeout(us->delay_wait, ...)` in `usb_stor_reset_common()`, `US_FLIDX_DISCONNECTING` in `us->dflags` must be rechecked before issuing `usb_reset_device()` or endpoint clear-halt transfers. [F21, F127]
- In `usb_stor_probe1()`, `us->dev_mutex` (including `us_set_lock_class(&us->dev_mutex, intf)` for multi-interface USB resets), `us->cmnd_ready`, `us->notify`, `us->delay_wait`, and `us->scan_dwork` must be initialized before `associate_dev()` calls `usb_set_intfdata()`, and `usb_stor_acquire_resources()` must allocate `us->current_urb` and run `us->unusual_dev->initFunction` before starting `us->ctl_thread`. In `usb_stor_scan_dwork()`, `usb_stor_Bulk_max_lun(us)` and updating `us->max_lun` / `us_to_host(us)->max_lun` must be serialized under `us->dev_mutex`. [F12, F22, F136]
- URB submissions in `usb_stor_msg_common()`, scatter-gather initializations in `usb_stor_bulk_transfer_sglist()`, and command-path buffer allocations in `shuttle_usbat.c` must use `GFP_NOIO` rather than `GFP_KERNEL` because they execute during block I/O command processing. [F129]

## Object Lifetimes
- During disconnect, `quiesce_and_remove_host()` must cancel `us->scan_dwork`, call `scsi_remove_host()`, and set `US_FLIDX_DISCONNECTING` before `release_everything()` stops `us->ctl_thread`, frees `us->extra`, `us->current_urb`, `us->cr`, and `us->iobuf`, and drops the final `Scsi_Host` reference via `scsi_host_put()`. When `usb_stor_control_thread()` exits its command loop, it must sleep until `kthread_should_stop()` returns true before returning, because `usb_stor_release_resources()` unconditionally calls `kthread_stop(us->ctl_thread)`. [F4, F7]
- In `usb_stor_msg_common()`, `us->current_urb->context` points to the stack-allocated completion `urb_done`, so once `usb_submit_urb()` succeeds, `usb_stor_msg_common()` must wait for completion or call `usb_kill_urb(us->current_urb)` on timeout/signal before returning. `usb_stor_release_resources()` invokes `us->extra_destructor(us->extra)` and then unconditionally calls `kfree(us->extra)`, so `extra_destructor` callbacks must only free subordinate resources inside `us->extra` without calling `kfree(us->extra)` themselves. [F8, F104]

## API Contracts
- `usb_stor_msg_common()` sets `URB_NO_TRANSFER_DMA_MAP` with `transfer_dma = us->iobuf_dma` if and only if `us->current_urb->transfer_buffer == us->iobuf`; callers of URB transfer helpers must pass either `us->iobuf` at offset 0 or a DMA-mappable heap buffer, never `srb->cmnd` or `us->iobuf + offset`. Likewise, in `sierra_ms.c`, `sierra_get_swoc_info()` performs a synchronous `usb_control_msg()` into `swocInfo` and converts `LinuxSKU` and `LinuxVer` via `le16_to_cpu()` in place, so callers must allocate `swocInfo` via `kmalloc()` (never on the stack) and not apply `le16_to_cpu()` a second time. [F42, F64, F133]
- `usb_stor_control_msg()` returns the non-negative transferred byte count on success and a negative `-Exxx` errno on failure, whereas `usb_stor_ctrl_transfer()` translates the URB result via `interpret_urb_result()` into a non-negative `USB_STOR_XFER_*` status (`0..4`). The severity ordering `USB_STOR_XFER_GOOD` (0), `USB_STOR_XFER_SHORT` (1), `USB_STOR_XFER_STALLED` (2), `USB_STOR_XFER_LONG` (3), and `USB_STOR_XFER_ERROR` (4) in `transport.h` must be preserved because `usb_stor_CB_transport()` tests `result > USB_STOR_XFER_STALLED`. [F23, F84]
- `uas_use_uas_driver()` must return `0` (not a negative errno) when UAS is unsupported or `uas_find_endpoints()` returns `-ENODEV`, and `1` only when the UAS driver should bind, because `storage_probe()` treats any non-zero return from `uas_use_uas_driver()` as a match and returns `-ENXIO`. In `sierra_ms_init()`, any path that switches the device to modem mode via `sierra_set_ms_mode()` must return `-EIO` even when `sierra_set_ms_mode()` succeeds, so `usb_stor_probe2()` aborts binding `usb-storage`. [F25, F27]
- `usb_stor_probe2()` must verify that both `us->transport` and `us->proto_handler` are non-NULL (returning `-ENXIO` via `BadDevice` otherwise) before calling `get_pipes()` or `usb_stor_acquire_resources()`. Because `us_to_host()` uses `container_of((void *)us, struct Scsi_Host, hostdata)` and `host_to_us()` casts `host->hostdata`, every `struct us_data` must be allocated via `scsi_host_alloc(sht, sizeof(*us))` in `usb_stor_probe1()` and freed via `scsi_host_put(us_to_host(us))` in `release_everything()`. [F29, F103]

## Error Handling
- `usb_stor_Bulk_max_lun()` must return `0` whenever `usb_stor_control_msg()` returns `<= 0` or `us->iobuf[0]` exceeds `US_BULK_MAX_LUN_LIMIT`, never propagating a negative errno into the `u8` field `us->max_lun`. In `init_usbat()`, non-zero `USB_STOR_XFER_*` or `USB_STOR_TRANSPORT_*` statuses returned by USBAT helpers must be translated into `-EIO` before returning, because `usb_stor_acquire_resources()` propagates a non-zero `initFunction` return value directly from `usb_stor_probe2()`. [F24, F26]
- In `usb_stor_acquire_resources()`, the return value `th` of `kthread_run()` must be checked with `IS_ERR(th)` before assigning `us->ctl_thread = th`, because `usb_stor_release_resources()` passes `us->ctl_thread` to `kthread_stop()` whenever `us->ctl_thread` is non-NULL. [F34]
- In `usb_stor_bulk_transfer_sglist()`, the `usb_stor_xfer_error` failure path must zero `*act_len` when `act_len` is non-NULL because `usb_stor_bulk_srb()` and `usb_stor_bulk_transfer_sg()` unconditionally subtract `partial` from the requested length. `usb_stor_invoke_transport()` must also reset `scsi_set_resid(srb, 0)` before calling `us->transport(srb, us)` and again before calling `us->transport(us->srb, us)` for auto-`REQUEST_SENSE`. [F37, F38]
- Transport callbacks (`us->transport`) must return `USB_STOR_TRANSPORT_FAILED` for device-level command failures that can be diagnosed via `REQUEST_SENSE` and reserve `USB_STOR_TRANSPORT_ERROR` for fatal transport failures, because `usb_stor_invoke_transport()` skips auto-sense and resets the device on `USB_STOR_TRANSPORT_ERROR`. When auto-sense succeeds after a failed non-ATA-passthru command (`result != USB_STOR_TRANSPORT_GOOD`) but normalized sense has `sense_key == 0`, `asc == 0`, `ascq == 0`, and `fm_ili == 0`, `usb_stor_invoke_transport()` must set `srb->result = DID_ERROR << 16` and `HARDWARE_ERROR` in `srb->sense_buffer`. [F149, F150]
- In `usb_stor_reset_common()`, `usb_stor_clear_halt()` must be called on both `us->recv_bulk_pipe` and `us->send_bulk_pipe` using separate variables (`result` and `result2`), overwriting `result` with `result2` only when `result >= 0`. In `usb_stor_Bulk_transport()`, the `if (result == USB_STOR_XFER_STALLED)` CSW retry check must remain a sequential `if` after the `if (result == USB_STOR_XFER_SHORT && cswlen == 0)` retry rather than an `else if`. [F33, F86]

## External Contracts
- In `usb_stor_Bulk_transport()`, `bcb->Signature`, `bcb->DataTransferLength`, and `bcs->Residue` use little-endian conversion (`__le32`), whereas `bcb->Tag` and `bcs->Tag` are written and compared in native host endianness (`us->tag`) and `bcs->Residue` must be clamped to `min(residue, transfer_length)` before updating `scsi_resid`. [F73]

## Known Pitfalls
- In `struct us_data`, `dflags` is an `unsigned long` manipulated with atomic bitops (`set_bit`, `clear_bit`, `test_bit`, `test_and_clear_bit`) using `US_FLIDX_*` indices, whereas `fflags` is a `u64` bitmask of `US_FL_*` flags initialized from `usb_device_id::driver_info` (cast to `kernel_ulong_t` in `usual-tables.c`, which is 32 bits on 32-bit architectures). Broken by: storing a `US_FL_*` flag above bit 31 in `UNUSUAL_DEV()` in `usual-tables.c`, or mixing `US_FLIDX_*` indices and `US_FL_*` bitmasks. [F107]
- In drivers that permit dynamic USB device IDs (such as `usb_storage_driver` where `no_dynamic_id` is not set), probe functions must bounds-check that `id` falls within the static `usb_device_id` table before computing `(id - table) + unusual_dev_list`, falling back to `for_dynamic_ids`. When a USB bridge VID:PID is shared across enclosures where only specific models have broken UAS, `US_FL_IGNORE_UAS` must be set conditionally in `uas_use_uas_driver()` via distinguishing descriptors (with NULL-checked `udev->manufacturer`/`product`) rather than unconditionally in `unusual_uas.h`, and `uas_find_endpoints(alt, eps)` must succeed before dereferencing `eps[1]->ss_ep_comp`. [F66, F91, F114]
- In `usb_stor_invoke_transport()`, the auto-sense call `us->transport(us->srb, us)` must store its return value in `temp_result` rather than overwriting `result` (which is inspected later when handling all-zero sense data). When an initial 18-byte (`US_SENSE_SIZE`) auto-sense returns a valid `0x70..0x73` response with `srb->sense_buffer[7] > US_SENSE_SIZE - 8`, `srb->sense_buffer[7]` must be clamped to `US_SENSE_SIZE - 8` before calling `scsi_normalize_sense()` or `scsi_sense_desc_find()`. [F72, F81]
- In `usb_stor_Bulk_transport()`, when a device skips the data-in phase and returns a 13-byte CSW (`US_BULK_CS_WRAP_LEN`) during the data stage, the CSW must be copied from `srb` into `bcs` via `usb_stor_access_xfer_buf()` and `scsi_set_resid(srb, transfer_length)` must be called before jumping to `skipped_data_phase`. [F85]
