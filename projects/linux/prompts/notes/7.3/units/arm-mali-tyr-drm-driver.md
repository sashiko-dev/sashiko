# ARM MALI TYR DRM DRIVER

The Arm Mali Tyr DRM driver (`drivers/gpu/drm/tyr/`) is a Rust kernel driver for Arm Mali Valhall Command Stream Frontend (CSF) GPUs (such as Mali-G610 on RK3588), providing a drop-in userspace-compatible counterpart to the C `panthor` driver. It manages platform device probing (clocks, regulators, MMIO, soft reset, L2 power-on), hardware address space (AS) slot allocation, ARM64 LPAE Stage 1 page tables via DRM GPUVM and GEM shmem buffer objects, CSF MCU firmware parsing and booting, and the `DRM_IOCTL_PANTHOR_DEV_QUERY` UAPI.

## Architecture & Data Flow
- Every `SlotManager` entry point inspecting a `LockedSeat` (`activate`, `idle`, `evict`) must call `self.check_seat` before using `SeatInfo::slot`, and `Seat::slot` must return `Some(info.slot)` only for `Seat::Active` (`None` for `Idle` or `NoSeat`). `allocate_slot` lazily evicts and reassigns `Idle` slots without updating the previous owner's `Seat`, so `AsSlotManager::start_vm_update`, `end_vm_update`, and `flush_vm` must never target an unvalidated `Idle` slot. [F19, F39]
- `SlotManager::record_active_slot` and `SlotManager::reactivate_slot` must record the same `self.use_seqno` in both `Seat::Active(SeatInfo)` and `Slot::Active(SlotInfo)` and increment `self.use_seqno`; `reactivate_slot` must also preserve the existing `SlotInfo::slot_data` in `self.slots[slot_idx]`. [F40]
- `AddressSpaceManager::new` must reject any `as_present` mask where `as_present.trailing_ones() != as_present.count_ones()` because `SlotManager` indices (`0..slot_count`) are used directly as hardware AS numbers. `SlotManager::new` must cap `slot_count` at both `MAX_SLOTS` and `u8::MAX as usize + 1` (since `SeatInfo::slot` is `u8`), and `allocate_slot` must iterate only over `&self.slots[..self.slot_count]`, returning the first `Slot::Free` or the `Slot::Idle` with minimum `seqno`. [F54, F68, F75]
- `get_pgsize` in `vm.rs` must bound `SZ_4K` runs at the next `SZ_2M` boundary and `SZ_2M` runs at the next `SZ_1G` boundary, and `pt_map` must pass `curr_iova | curr_paddr` to `get_pgsize` so `SZ_2M` block mappings are only used when both IOVA and physical address are 2 MiB-aligned. [F115]
- `FwParser::parse_section_entry` inverts the positive permission bits in `SectionFlags` when building `VmMapFlags` (`!write()` sets `VmFlag::Readonly`, `!exec()` sets `VmFlag::Noexec`, and `cache_mode() != CacheMode::Cached` sets `VmFlag::Uncached`), which `VmMapFlags::to_prot` maps to `iommu::pgtable::prot` flags. [F60]
- `GpuInfo` implements `unsafe impl AsBytes` for direct byte-wise copy to userspace in `TyrDrmFileData::dev_query`, so it must remain `#[repr(transparent)]` over `uapi::drm_panthor_gpu_info` with no implicit padding, no kernel pointers, no interior mutability, and `pad` explicitly initialized to `0` in `GpuInfo::new`. [F82]

## Synchronization
- Lock ordering requires acquiring `Vm::gpuvm_unique` before `Mmu::as_manager` (as in `Vm::map_bo_range` and `Vm::unmap_range` calling `Vm::exec_op` and `PtUpdateContext`); code holding `Mmu::as_manager` (such as `SlotOperations` or `AddressSpaceManager`) must never call back into `Vm` to acquire `Vm::gpuvm_unique`. [F110]
- Every page-table mutation in `Vm::exec_op` (`sm_map` or `sm_unmap`) and every call to `pt_map` (`unsafe { pt.map_pages(...) }`) or `pt_unmap` (`unsafe { pt.unmap_pages(...) }`) on `VmAsData::page_table` must occur while holding `Vm::gpuvm_unique` on IOVA ranges coordinated with `UniqueRefGpuVm`, bracketed by a `PtUpdateContext` so `Mmu::start_vm_update` locks the VA region beforehand and `PtUpdateContext::drop` calls `Mmu::end_vm_update` and `Mmu::flush_vm` before `gpuvm_unique` is released. [F16, F91]
- Reading a live 64-bit counter across split 32-bit `_LO` and `_HI` MMIO registers (such as `CYCLE_COUNT_LO`/`CYCLE_COUNT_HI` or `TIMESTAMP_LO`/`TIMESTAMP_HI`) must use `read_u64_no_tearing` rather than a single pair of `io.read` calls with `join_u64`, so high-word rollover between the two reads is detected and retried. [F102]

## Object Lifetimes
- In `Firmware::drop`, `self.stop()` must execute before `self.vm.kill()` and before `Firmware::sections` are dropped so the MCU is halted before its firmware `KernelBo` mappings and backing memory are unmapped. [F3]
- In `Vm::kill`, `self.deactivate()` must be called to flush and disable the VM's hardware AS slot before `self.unmap_range` unmaps the VM's virtual address range. [F12]
- While a hardware AS slot is programmed with `pt.ttbr()` from `VmAsData::as_config`, `SlotManager` must keep the `Arc<VmAsData>` in `self.slots[slot_idx]` and only remove it after `AddressSpaceManager::evict` (`as_flush` and `as_disable` with `MmuCommand::FlushMem`) succeeds. [F113]
- In `Vm::map_bo_range` and `Vm::unmap_range`, `self.gpuvm.deferred_cleanup()` must be called after releasing `self.gpuvm_unique` on both success and error paths of `self.exec_op()`. Broken by: propagating `self.exec_op()?` before calling `deferred_cleanup()`, or calling `deferred_cleanup()` while holding `gpuvm_unique`. [F8]
- In `TyrPlatformDriver::probe`, clocks and regulators must be enabled and `issue_soft_reset` and `gpu::l2_power_on` must complete before `GpuInfo::new` reads GPU feature registers, and `pdev.dma_set_mask_and_coherent` must be called with `MMU_FEATURES::pa_bits` before constructing `Mmu`, `Vm`, `Firmware`, or `drm::Registration` so no DMA allocations exist while the DMA mask is mutated. [F95, F111]
- `TyrPlatformDriver::probe` passes `TyrDrmRegistrationData<'drm>` (containing `'drm`-scoped `pdev`, `Firmware<'drm>`, and `Arc<IoMem<'drm>>`) to `unsafe { drm::Registration::new(...) }`, so `TyrPlatformDriverData` must own the returned `drm::Registration<'bound, TyrDrmDriver>` and never `mem::forget` it before `'bound` ends. [F89]

## API Contracts
- In `AddressSpaceManager::validate_as_slot`, `as_nr >= MAX_AS` (`16`) must be rejected before evaluating `self.as_present & (1 << as_nr)` on the `u32` mask, and every per-slot MMU method must call `validate_as_slot(as_nr)` before accessing hardware registers. [F78]
- In `AddressSpaceManager`, every `MmuCommand` written to `COMMAND` must be preceded and followed by `as_wait_ready` (polling `!STATUS.active_ext()`), and changes to `TRANSTAB_LO`/`HI`, `TRANSCFG_LO`/`HI`, and `MEMATTR_LO`/`HI` in `as_enable` and `as_disable` must be committed with `as_send_cmd_and_wait(as_nr, MmuCommand::Update)`. [F104]
- `AddressSpaceManager::as_start_update` must reject `region.start >= region.end`, clamp the lock region to at least 32 KiB (`4096 * 8`), align `lockaddr_base` down to `lock_region_size`, encode `LOCKADDR::size` as `lock_region_log2 - 1`, and shift `lockaddr_base` right by 12 before calling `try_with_base`. [F33]
- `VmAsData::as_config` must compute the `TRANSCFG` input address restriction field as `55 - va_bits`, convert it via `InaBits::try_from`, and reject `InaBits::Reset` (`0`) with `Err(EINVAL)`. [F34]
- `Vm::map_bo_range` and partial `Vm::unmap_range` calls must preallocate 3 `GpuVaAlloc` objects in `VmOpResources::preallocated_gpuvas`, and `GpuVmData::sm_step_remap` must return `remap_ret.unused_va` via `PtUpdateContext::return_preallocated_gpuva` so a subsequent `sm_step_map` does not fail with `EINVAL`. [F36]
- Once a GPU fault is reported in `GPU_FAULTSTATUS` / `GPU_FAULTADDRESS_LO` / `GPU_FAULTADDRESS_HI`, `GPU_COMMAND::clear_fault()` must be written to `GPU_COMMAND` because hardware will not report subsequent GPU faults until the previous fault is cleared. [F108]

## Error Handling
- In `KernelBo::new`, `Vm::map_bo_range`, `Vm::unmap_range`, and `GpuVmData::sm_step_map`, `u64`/`usize` size conversions must use `try_from` (returning `EOVERFLOW`), and `map_bo_range`/`unmap_range` must require non-zero, `SZ_4K`-aligned offsets, addresses, and sizes with `checked_add` bounds checks (`EINVAL`) against `bo.size()` and `self.va_range`. [F57, F74]
- To keep `IoPageTable` synchronized with `GpuVm`, `sm_step_unmap`/`sm_step_remap` must complete `pt_unmap` before `op.remove`/`op.remap`, and `sm_step_map` must deduct `skip = u64::min(sgt_entry_length, gem_offset)` from `gem_offset` and `sgt_entry_length` (adding `skip` to `paddr`) per SGT entry, treat both `result.is_err()` and `mapped == 0` (where `IoPageTable::map_pages` takes `pgcount` in pages but returns `mapped` in bytes) as failures in `pt_map` that `pt_unmap` `iova..(iova + segment_mapped)`, and verify `bytes_left_to_map == 0` after the SGT loop—rolling back `start_iova..iova` via `pt_unmap` before returning any error without `op.insert`. [F21, F67, F124]
- Before subtracting `size_of::<EntryHeader>()` or slicing `self.cursor.view`, `FwParser::parse_entry` must verify `entry_size` is 4-byte aligned, `entry_size >= size_of::<EntryHeader>()`, and `entry_start.checked_add(entry_size) <= header_end`. When `EntryHeader::entry_type` returns `Err` for an unknown type, `parse_entry` must ignore the entry if `entry_hdr.optional()` (bit 31) is `true` and return `Err(EINVAL)` only if `false`. [F31, F51]
- For each loadable firmware section, `SectionHeader::new` and `FwParser::parse_section_entry` must validate `va.start <= va.end` (both `SZ_4K`-aligned) and `data.start <= data.end <= firmware_size`, and `Firmware::init_section_mem` must verify `data.len() <= mem.bo().size()` before writing into the `KernelBo`. [F53]

## External Contracts
- `TyrDrmDriver::INFO` must set `drm::DriverInfo::name` to `c"panthor"` so userspace stacks (such as Mesa) recognize Tyr as a compatible `panthor` DRM device. [F119]
- In `TyrDrmFileData::dev_query`, when `devquery.pointer == 0`, each `devquery.type_` arm must set `devquery.size` to the pointee struct's byte size (`core::mem::size_of_val(&reg_data.gpu_info) as u32`); when `devquery.pointer != 0`, it must wrap `devquery.pointer` and `devquery.size as usize` in a `UserSlice` and write via `writer.write`. [F81]
- Firmware binary headers in `fw/parser.rs` must be decoded in little-endian byte order via `Cursor::read_u8`, `read_u16`, and `read_u32`, and `FirmwareHeader::new` together with `FwParser::parse_fw_header` must reject binaries where `_padding1` or `_padding2` is non-zero or `size` exceeds `Cursor::len()`. [F50]
- `FwParser::parse_section_entry` must skip protected-mode (`section_hdr.section_flags.prot()`) and empty-VA (`section_hdr.va.is_empty()`) sections by returning `Ok(None)` rather than `Err`, reject any section starting at `CSF_MCU_SHARED_REGION_START` (`0x04000000`) that lacks `SectionFlags::shared`, map sections with `cache_mode != CacheMode::Cached` using `VmFlag::Uncached`, and `FwParser::parse` must return `Err(EINVAL)` if `parsed_sections.is_empty()` after parsing all entries. [F63, F100]

## Known Pitfalls
- Interrupt bits in `GPU_IRQ_RAWSTAT`, `JOB_IRQ_RAWSTAT`, and `mmu_control::IRQ_RAWSTAT` must be cleared by writing 1s to the write-only `GPU_IRQ_CLEAR`, `JOB_IRQ_CLEAR`, or `mmu_control::IRQ_CLEAR` registers (writing to `*_RAWSTAT` forces interrupts on). In particular, `Firmware::boot` must clear the global job interrupt via `JOB_IRQ_CLEAR::zeroed().with_glb(true)` both before writing `McuControlMode::Auto` to `MCU_CONTROL` and after polling `MCU_STATUS` and `JOB_IRQ_RAWSTAT`. [F47, F103]
- In `AddressSpaceManager::as_enable`, `as_disable`, and `as_start_update`, logical 64-bit MMU registers (`TRANSTAB`, `TRANSCFG`, `MEMATTR`, `LOCKADDR`) must be accessed via their split 32-bit `*_LO` (`val as u32`) and `*_HI` (`(val >> 32) as u32`) register definitions rather than 64-bit MMIO writes. [F76]
- `MEMATTR::is_writeback_cacheable` must verify that both outer (`mair_attr >> 4`) and inner (`mair_attr & ARM_MAIR_INNER_MASK`) nibbles have `ARM_MAIR_WRITE_BACK_BIT` (`0x4`) set and neither equals `ARM_MAIR_NON_CACHEABLE` (`0x4`), because `0b0100` also sets bit 2 for Normal Non-cacheable memory. [F59]
- In `GpuVmData::sm_step_remap`, `pt_unmap` must only unmap the sub-range between `op.prev()` (`prev.addr() + prev.length()`, or `op.va_to_unmap().addr()` if `None`) and `op.next()` (`next.addr()`, or `op.va_to_unmap().addr() + op.va_to_unmap().length()` if `None`), rather than the full `op.va_to_unmap()` range, so retained `prev` and `next` split mappings are preserved. [F71]
- In `pt_map` and `pt_unmap` (`drivers/gpu/drm/tyr/vm.rs`), 64-bit GPU virtual addresses (`curr_iova` and `iova`) must be converted to `usize` via `usize::try_from` (returning `EOVERFLOW` on failure, after unmapping any prior progress in `pt_map`) rather than `as usize` before calling `IoPageTable::map_pages` or `unmap_pages`. [F72]
- In `FwParser::parse_entry`, `EntryHeader::size()` includes the 4-byte `EntryHeader` already consumed by `self.cursor.read_u32()`, so `entry_end` must be `entry_start + entry_size` and the post-entry `self.cursor.advance()` must advance by `entry_size - size_of::<EntryHeader>()`. [F84]
- Register field enums in `fw.rs` and `regs.rs` implementing `From<Bounded<T, N>>` for infallible `=>` accessors (`CacheMode`, `AccessType`, `McuStatus`, `MemoryType`, `MmuAccessType`) use `_ => unreachable!()` and must cover every value in `0..(1 << N)`; enums with sparse encodings in their bit width must use `TryFrom<Bounded<T, N>>` and `?=>`. [F88]
