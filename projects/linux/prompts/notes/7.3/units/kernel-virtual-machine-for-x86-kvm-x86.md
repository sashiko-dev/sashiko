# KERNEL VIRTUAL MACHINE FOR X86 (KVM/x86)

Core x86 implementation of KVM (`kvm.ko`), bridging generic KVM with vendor backends (`kvm-intel`/`kvm-amd`). It manages VM and vCPU lifecycles, the guest entry/exit loop (`vcpu_enter_guest`), instruction emulation (`emulate_ops`), register/MSR/FPU virtualization, interrupt/exception/NMI/SMI injection, paravirtualized time (`kvmclock` and TSC scaling/synchronization), memslot metadata, and x86 ioctl handlers.

## Architecture & Data Flow

- When `vcpu->arch.guest_state_protected` is true, guest GPRs, RIP, CPL, and segments are inaccessible: paths reachable by confidential guests (`vcpu_enter_guest`, `kvm_arch_vcpu_put`, `kvm_can_deliver_async_pf`, `kvm_get_linear_rip`) must check `!vcpu->arch.guest_state_protected`, hypercalls must use `is_64_bit_hypercall(vcpu)` (not `is_64_bit_mode()`), `store_regs()` must be skipped, and `kvm_sync_valid_fields()` must return `0` when `kvm->arch.has_protected_state` is set so `kvm_arch_vcpu_ioctl_run()` rejects non-zero `kvm_valid_regs`/`kvm_dirty_regs` with `-EINVAL`. [F48, F84]
- When `x86_emulate_instruction()` exits to userspace without writeback, it sets `emulate_regs_need_sync_to_vcpu`; `__get_regs()` must flush `ctxt`'s register cache to the vCPU when set, and `__set_regs()` must set `emulate_regs_need_sync_from_vcpu` so `x86_emulate_instruction()` invalidates `ctxt`'s cache on resume. When resuming with `EMULTYPE_NO_DECODE`, `x86_emulate_instruction()` must not re-decode, clear the exception queue, check code breakpoints, or re-check L1 instruction intercepts for L2 guests. [F63, F73]
- In `kvm_unprotect_and_retry_on_failure()`, if `emulation_type & EMULTYPE_WRITE_PF_TO_SP` is set, it must return `false` without calling `__kvm_mmu_unprotect_gfn_and_retry()` so a failed instruction writing to its own translation page table does not enter an infinite page-fault loop. [F116]
- In `kvm_check_and_inject_events()`, the re-injection `if`/`else if` chain must check `kvm_is_exception_pending(vcpu)` before `vcpu->arch.nmi_injected` and `vcpu->arch.interrupt.injected` and do nothing in that branch so a pending exception suppresses NMI and IRQ re-injection. [F107]
- Every transition of a vCPU to `KVM_MP_STATE_RUNNABLE` must use `kvm_set_mp_state()` rather than assigning `vcpu->arch.mp_state` directly, so `vcpu->arch.pv.pv_unhalted` is cleared in lockstep. [F62]
- When `kvm_deliver_exception_payload()` delivers a `DB_VECTOR` payload to `vcpu->arch.dr6`, it must clear `DR_TRAP_BITS`, set `DR6_ACTIVE_LOW`, OR in `ex->payload`, flip active-low bits present in `ex->payload`, clear reserved `BIT(12)`, and reset `ex->has_payload` and `ex->payload`. [F75]
- When guest-visible dynamic XSTATE or MWAIT enablement bits change in `vcpu->arch.xcr0` (bits in `XFEATURE_MASK_EXTEND`), `vcpu->arch.ia32_xss`, or `vcpu->arch.ia32_misc_enable_msr` (`MSR_IA32_MISC_ENABLE_MWAIT`), `vcpu->arch.cpuid_dynamic_bits_dirty` must be set to `true`. [F70]
- In `kvm_guest_time_update()`, `PVCLOCK_GUEST_STOPPED` must be cleared from `hv_clock.flags` immediately after updating `vcpu->pv_time`, and `PVCLOCK_TSC_STABLE_BIT` must only be cleared for `KVM_XEN_HVM_CONFIG_PVCLOCK_TSC_UNSTABLE` after both `vcpu->pv_time` and `kvm_hv_setup_tsc_page()` have consumed `hv_clock`. In `kvm_setup_guest_pvclock()`, transient per-clock updates (`version` and `PVCLOCK_GUEST_STOPPED`) must be applied to a local copy of `ref_hv_clock` rather than mutating `ref_hv_clock` in place. [F58, F105]
- In `kvm_vm_ioctl_set_clock()`, when `ka->use_master_clock` is true, `ka->kvmclock_offset` must be computed by subtracting `ka->master_kernel_ns` (updated via `pvclock_update_vm_gtod_copy()`) rather than `get_kvmclock_ns()`, and `now_real_ns - data.realtime` must only be added to `data.clock` if `now_real_ns > data.realtime`. [F137]
- In `kvm_sev_es_outs()` and `kvm_sev_es_ins()`, each iteration's PIO `count` passed to `emulator_pio_out()` or `emulator_pio_in()` must be clamped to `min_t(unsigned int, PAGE_SIZE / size, vcpu->arch.sev_pio_count)` so `size * count` never overflows the single-page `vcpu->arch.pio_data` buffer. [F103]
- `kvm_caps` fields must never have static default initializers; `kvm_x86_vendor_init()` zeroes `kvm_caps` with `memset()` and recomputes all fields from scratch so reloading a vendor module does not retain stale state. Advertising `KVM_X86_SW_PROTECTED_VM` in `kvm_caps.supported_vm_types` must be gated on `tdp_mmu_enabled` (not `tdp_enabled`). [F147, F150]

## Synchronization

- Modifications to per-VM TSC synchronization tracking fields (`kvm->arch.last_tsc_*`, `cur_tsc_*`, `nr_vcpus_matched_tsc`, `user_set_tsc`) via `__kvm_synchronize_tsc` and masterclock updates via `pvclock_update_vm_gtod_copy` must hold `kvm->arch.tsc_write_lock` with IRQs disabled. Masterclock updates after VM init must bracket writes under `pvclock_sc` and `tsc_write_lock` with `kvm_start_pvclock_update` (`KVM_REQ_MCLOCK_INPROGRESS`) and `kvm_end_pvclock_update` (`KVM_REQ_CLOCK_UPDATE` before clearing `KVM_REQ_MCLOCK_INPROGRESS`). [F18, F19]
- In `kvm_get_wall_clock_epoch()` and `__get_kvmclock()`, reading `get_cpu_tsc_khz()` and the host TSC must execute on the same CPU under `get_cpu()`/`put_cpu()`, and `ka->master_cycle_now` and `ka->master_kernel_ns` must be snapshotted inside the `ka->pvclock_sc` seqcount retry loop. [F170]
- `pvclock_gtod_notify` runs under the timekeeper `tk_core.seq` write lock and must defer work via `irq_work_queue(&pvclock_irq_work)` (never `queue_work()`). `kvmclock_cpufreq_notifier()` / `__kvmclock_cpufreq_notifier()` must process CPU frequency increases on `CPUFREQ_PRECHANGE` (with a post-request synchronous IPI for remote CPUs) and decreases on `CPUFREQ_POSTCHANGE`, updating `cpu_tsc_khz` via synchronous `smp_call_function_single(cpu, tsc_khz_changed, freq, 1)`. [F28, F157]
- When updating shared guest `pvclock_vcpu_time_info` in `kvm_setup_guest_pvclock` or `kvm_steal_time` in `record_steal_time`, KVM must store an odd `version`, issue `smp_wmb()`, write payload fields, and store the incremented even `version`. In `kvm_setup_guest_pvclock()`, `gpc->khva` must only be accessed under `read_lock_irqsave(&gpc->lock, flags)` after `kvm_gpc_check()`, dropping `gpc->lock` before `kvm_gpc_refresh()` and re-validating in a loop. [F22, F174]
- `kvm_arch_vcpu_put()` runs in preemption/sched-out context when `vcpu->preempted` is set: it must acquire `srcu_read_lock(&vcpu->kvm->srcu)` around `kvm_steal_time_set_preempted()` and `kvm_xen_runstate_set_preempted()`, and `kvm_steal_time_set_preempted()` must use `copy_to_user_nofault()` after checking `current->mm == vcpu->kvm->mm`. [F175]
- Callers of `kvm_vcpu_ioctl_x86_set_vcpu_events()` (`KVM_SET_VCPU_EVENTS` and `sync_regs()`) must hold `vcpu->kvm->srcu` via `kvm_vcpu_srcu_read_lock(vcpu)` because toggling SMM state calls `kvm_leave_nested()`, which accesses guest memory. Broken by: calling without `srcu` held or acquiring `srcu` inside `kvm_vcpu_ioctl_x86_set_vcpu_events()` where it nests with `sync_regs()`. [F162]
- Toggling per-VM APICv state in `__kvm_set_or_clear_apicv_inhibit()` requires holding `kvm->arch.apicv_update_lock` for write and issuing `kvm_make_all_cpus_request(kvm, KVM_REQ_APICV_UPDATE)` before writing `kvm->arch.apicv_inhibit_reasons`, while `__kvm_vcpu_update_apicv()` must hold `apicv_update_lock` for read with preemption disabled. [F168]
- Asynchronous NMI injection (`kvm_inject_nmi`) must queue NMIs via `atomic_inc(&vcpu->arch.nmi_queued)` and `kvm_make_request(KVM_REQ_NMI, vcpu)`, drained into `nmi_pending` in `process_nmi`. VM ioctls configuring pre-vCPU state (`KVM_CAP_SPLIT_IRQCHIP`, `KVM_CAP_PMU_CAPABILITY`, `KVM_CREATE_IRQCHIP`, `KVM_SET_BOOT_CPU_ID`, `KVM_SET_TSC_KHZ`) must hold `kvm->lock` across `!kvm->created_vcpus` and the update, whereas `kvm_arch_suspend_notifier` must not acquire `kvm->lock` around `kvm_for_each_vcpu`. [F27, F39, F40]

## Object Lifetimes

- Callers of `emulator_read_write()`, `emulator_read_write_onepage()`, `kvm_sev_es_mmio_read()`, and `kvm_sev_es_mmio_write()` must pass a `val`/`data` buffer that outlives a `KVM_EXIT_MMIO` return to userspace, because unhandled MMIO stores `val`/`data` in `vcpu->mmio_fragments[].data` for completion on a subsequent `KVM_RUN`. Broken by: passing a stack-allocated variable as `val` or `data`. [F140]
- During vendor module teardown in `kvm_x86_vendor_exit`, `pvclock_gtod_unregister_notifier(&pvclock_gtod_notifier)` must be followed by `irq_work_sync(&pvclock_irq_work)` and then `cancel_work_sync(&pvclock_gtod_work)` in that exact order. [F29]

## API Contracts

- In the `KVM_RUN` execution path (`vcpu_run`, `vcpu_enter_guest`, `vcpu_block`, `kvm_x86_vcpu_pre_run`, and `vcpu->arch.complete_userspace_io` callbacks), functions must return `1` to keep running the guest in the kernel, `0` to exit cleanly to userspace with `vcpu->run->exit_reason` set, and `< 0` on a negative errno failure. Broken by: returning `0` on success when intending to resume the guest, causing a spurious `KVM_EXIT_UNKNOWN`. [F43]
- `kvm_get_time_scale()` requires both `scaled_hz` and `base_hz` to be non-zero on entry so its shift loops normalize `scaled64 < tps32` and `tps32 > 0` before `div_frac()` invokes `do_shl32_div32()`. Callers must reject `0` frequencies (`user_tsc_khz == 0` in `kvm_set_tsc_khz()`, `get_cpu_tsc_khz() == 0` in `__get_kvmclock()`/`kvm_guest_time_update()`/`kvm_get_wall_clock_epoch()`), and `kvm_guest_time_update()` must clamp `tgt_tsc_khz` after `kvm_scale_tsc()` to at least `1`. [F124, F125]
- In `pvclock_gtod_data` time readers, `do_monotonic()` (`kvm_get_monotonic_and_clockread()`) must read `gtod->clock` and add `gtod->clock.offset` without `gtod->offs_boot` to compute `CLOCK_MONOTONIC`, whereas `do_kvmclock_base()` (`kvm_get_time_and_clockread()`) reads `gtod->raw_clock` and adds `gtod->offs_boot`. [F56]
- `struct kvm_segment` stores `limit` in bytes whereas `struct desc_struct` stores a 20-bit limit; `emulator_get_segment()` must shift `var.limit >>= 12` when `var.g` is set before `set_desc_limit()`, and `emulator_set_segment()` must set `var.limit = (var.limit << 12) | 0xfff` when `desc->g` is set. [F57]

## Error Handling

- In `kvm_arch_vm_ioctl(KVM_CREATE_IRQCHIP)`, `kvm_pic_init()`, `kvm_ioapic_init()`, and `kvm_setup_default_ioapic_and_pic_routing()` must execute under `kvm->lock` before setting `kvm->arch.irqchip_mode = KVM_IRQCHIP_KERNEL`, and failure of `kvm_ioapic_init()` or routing setup must destroy any already-created IOAPIC (`kvm_ioapic_destroy`) and PIC (`kvm_pic_destroy`) before unlocking. [F15]
- `kvm_read_guest_virt()` must zero `*exception` with `memset()` before calling `kvm_read_guest_virt_helper()`. When preparing userspace exits or guest-visible structures in `prepare_emulation_failure_exit()`, `kvm_msr_user_space()`, `emulator_pio_in_out()`, and `kvm_pv_clock_pairing()`, unpopulated buffers and padding (`u64 info[5]` before `get_exit_info()`, `insn_bytes`, `vcpu->run->msr.pad`, `vcpu->arch.pio_data` on `in`, and `clock_pairing.pad`) must be explicitly zeroed. [F54, F182]

## External Contracts

- Guest- or user-controlled array indices in `kvm_sched_yield()`, `kvm_set_dr()`, `kvm_get_dr()`, `set_msr_mce()`, `get_msr_mce()`, and `kvm_vcpu_ioctl_x86_set_mce()` must be clamped with `array_index_nospec()` after bounds checking before indexing `map->phys_map`, `vcpu->arch.db`, `vcpu->arch.mci_ctl2_banks`, or `vcpu->arch.mce_banks`. [F181]
- `exception_type()` must bound `vector <= 31` before evaluating `1 << vector`, `kvm_vcpu_ioctl_x86_set_vcpu_events()` must reject `events->exception.nr > 31 || events->exception.nr == NMI_VECTOR` with `-EINVAL` when `injected` or `pending` is set, and `kvm_is_vm_type_supported()` must bound `type < 32` before evaluating `kvm_caps.supported_vm_types & BIT(type)`. [F85, F133]
- In `kvm_vcpu_ioctl_x86_get_vcpu_events()`, `events` must be zero-initialized with `memset()`, software exceptions (`kvm_exception_is_soft()`) must not be marked `injected` or `pending`, `events->sipi_vector` must remain zero, and `ex->pending` must be ORed into `events->exception.injected` when `!vcpu->kvm->arch.exception_payload_enabled`. [F185]
- In `kvm_vcpu_ioctl_x86_get_xsave2()`, exported guest XSAVE state must be masked to `vcpu->arch.guest_supported_xcr0 | XFEATURE_MASK_FPSSE` when calling `fpu_copy_guest_fpstate_to_uabi()`, whereas `kvm_vcpu_ioctl_x86_set_xsave()` validates against `kvm_caps.supported_xcr0`. [F87]
- In `kvm_x86_vendor_init()`, when `kvm_caps.has_tsc_control` is true, `kvm_caps.max_guest_tsc_khz` must be capped at `0x7fffffffULL` so any `user_tsc_khz` fits in the signed `int` returned by `KVM_GET_TSC_KHZ`. In `kvm_arch_vcpu_ioctl(KVM_SET_TSC_KHZ)`, reject with `-EINVAL` if `vcpu->arch.guest_tsc_protected` is true, or if `kvm_caps.has_tsc_control` is true and `(u32)arg >= kvm_caps.max_guest_tsc_khz`. [F89, F127]
- In `____kvm_emulate_hypercall()`, `KVM_HC_MAP_GPA_RANGE` must reject guest `gpa` and `npages` with `-KVM_EINVAL` if `!PAGE_ALIGNED(gpa)`, `!npages`, or `gpa_to_gfn(gpa) + npages <= gpa_to_gfn(gpa)` before exiting to userspace; whenever exiting with `KVM_EXIT_HYPERCALL`, `vcpu->run->hypercall.ret` must be set to `0` prior to returning `0`. [F99, F186]
- In `kvm_vm_ioctl_enable_cap()`, `KVM_CAP_X86_DISABLE_EXITS` must validate `cap->args[0]` against `~kvm_get_allowed_disable_exits()` (not a static mask), `KVM_CAP_X86_APIC_BUS_CYCLES_NS` must reject `bus_cycle_ns == 0` or `check_mul_overflow((u64)U32_MAX * 128, bus_cycle_ns, &unused)`, and `KVM_CAP_VM_DISABLE_NX_HUGE_PAGES` must check `capable(CAP_SYS_BOOT)` (not `ns_capable()`). In `kvm_vm_ioctl_check_extension()`, per-VM capabilities (`KVM_CAP_READONLY_MEM`, `KVM_CAP_SYNC_REGS`) must check `kvm` when non-NULL. [F90, F91, F151, F187]

## Known Pitfalls

- In `emulator_read_write()`, when an access crosses a page boundary and `now` bytes are processed on the first page, `addr += now` must be truncated to 32 bits (`addr = (u32)addr`) when `ctxt->mode != X86EMUL_MODE_PROT64` before translating the second page. In `emulator_cmpxchg_emulated()`, `emulator_try_cmpxchg_user()` must fall back to `emulator_write_emulated()` if the GPA range crosses a cache-line boundary when `boot_cpu_has(X86_FEATURE_SPLIT_LOCK_DETECT)` is true (or a page boundary otherwise). [F96, F176]
- In `kvm_inject_exception()`, suppressing the exception error code in Real Mode must clear `vcpu->arch.exception.has_error_code &= is_protmode(vcpu)` (before `trace_kvm_inj_exception()`) rather than modifying `vcpu->arch.exception.error_code`. `kvm_sync_valid_fields()` and `sync_valid_fields` in `kvm_arch_vcpu_ioctl_run()` must be typed as `u64` (not `u32`) so `~sync_valid_fields` masks all 64 bits of `kvm_valid_regs` and `kvm_dirty_regs`. [F120, F126]
- `kvm_calc_nested_tsc_offset()` must cast `l1_offset` to `s64` and use signed `mul_s64_u64_shr()` rather than `kvm_scale_tsc()` / `mul_u64_u64_shr()`, whereas `adjust_tsc_offset_host()` requires `adjustment >= 0` when scaling with `kvm_scale_tsc()`. [F128]
- In `kvm_arch_vcpu_load()`, backwards host TSC movement must be detected by storing `rdtsc() - vcpu->arch.last_host_tsc` (when `last_host_tsc` is non-zero) into a signed `s64 tsc_delta` and checking `tsc_delta < 0`. In `kvm_synchronize_tsc()`, the 1-second window around `tsc_exp` must be checked as `data < tsc_exp + tsc_hz && data + tsc_hz > tsc_exp` rather than subtracting `tsc_hz` from `tsc_exp` (which underflows). [F136, F138]
