# INTERCONNECT API

The Interconnect API subsystem models on-chip Network-on-Chip (NoC) topologies as directed graphs of interconnect nodes and providers, allowing consumer drivers to request average and peak bandwidth along paths between endpoints. It aggregates bandwidth requests across all consumers per node (supporting initial boot floor constraints until `icc_sync_state`) and dispatches hardware configuration to vendor-specific provider drivers (Qualcomm RPM/RPMh/BCM-voter, NXP i.MX NoC/PM-QoS, MediaTek EMI/DVFSRC, and clk-based providers).

## Architecture & Data Flow

- In `aggregate_requests()`, `node->avg_bw` and `node->peak_bw` must be zeroed and `p->pre_aggregate(node)` invoked before iterating `node->req_list`, and disabled requests (`!r->enabled`) must still be passed to `p->aggregate()` with `avg_bw` and `peak_bw` set to 0 rather than skipped. [F44]
- In `icc_node_add()`, after syncing initial hardware bandwidths via `pre_aggregate()`, `aggregate()`, and `set()`, `node->avg_bw` and `node->peak_bw` must be reset to 0 while keeping boot floors in `node->init_avg` and `node->init_peak`; when `icc_sync_state()` transitions `synced_state` to true, each node's `init_avg` and `init_peak` must be cleared to 0 before calling `aggregate_requests(n)` and `p->set(n, n)`. [F46, F47]
- `qcom_icc_pre_aggregate()` must zero `qn->sum_avg[i]` and `qn->max_peak[i]` across all `QCOM_ICC_NUM_BUCKETS` and queue every BCM in `qn->bcms` via `qcom_icc_bcm_voter_add()`, because `qcom_icc_set()` may run without `qcom_icc_aggregate()` when `node->req_list` is empty; in `qcom_icc_aggregate()`, non-zero `node->init_avg` and `node->init_peak` must clamp `sum_avg[i]` and `max_peak[i]` via `max_t(u64, ...)` during aggregation rather than in `qcom_icc_set()`. [F51, F52]
- `qcom_icc_bcm_init()` must return early when `bcm->addr` is already non-zero so static `struct qcom_icc_bcm` descriptors shared across multiple `qcom_icc_desc` providers do not reinitialize active `bcm->list`/`bcm->ws_list` heads or append duplicate entries to `qn->bcms[qn->num_bcms++]`. [F53]
- In `qcom_icc_bcm_voter_add()` and `qcom_icc_bcm_voter_commit()`, membership of a `struct qcom_icc_bcm` on `voter->commit_list` and `voter->ws_list` is tracked via `list_empty(&bcm->list)` and `list_empty(&bcm->ws_list)`, so removals must use `list_del_init()` and `voter->ws_list` entries must persist until `WAKE` votes match `SLEEP` votes. [F54]
- In `bcm_aggregate()`, all bandwidth-to-vote divisions by `node->buswidth * node->channels`, `node->buswidth`, and `bcm->aux_data.unit` must go through `bcm_div()` (which uses `do_div()` and clamps non-zero dividends smaller than `base` to 1); for mask-based BCMs (`bcm->enable_mask != 0`), `bcm_aggregate_mask()` must set `vote_x[bucket] = 0` and `vote_y[bucket] = bcm->enable_mask` on non-zero `sum_avg`/`max_peak`, and if `bcm->keepalive` is set, set both `vote_x` and `vote_y` to `bcm->enable_mask` for `AMC` and `WAKE`. [F55, F87]
- `tcs_cmd_gen()` and `tcs_list_gen()` must `memset` caller-supplied stack buffers (`struct tcs_cmd *cmd` and `int n[MAX_VCD + 1]` sized as `sizeof(int) * (MAX_VCD + 1)`, not `sizeof(n)`), unconditionally set `cmd->wait`, and clamp `vote_x` and `vote_y` to `BCM_TCS_CMD_VOTE_MASK` (`GENMASK(13, 0)`) before `BCM_TCS_CMD()`. `voter->commit_list` must be sorted by `cmp_vcd` before `tcs_list_gen()`, which resets `cur_vcd_size` to 0 on `commit` and shifts `cur_vcd_size` entries from `n[batch]` to `n[batch + 1]` when `n[batch] >= MAX_RPMH_PAYLOAD` with `!commit`. [F35, F74, F79, F103]
- Qualcomm SMD RPM code (`icc-rpm.c`, `icc-rpm.h`) must size and iterate per-state arrays (`sum_avg`, `max_peak`, `bus_clk_rate`) with `QCOM_SMD_RPM_STATE_NUM` (2) and default `tag == 0` to `RPM_ALWAYS_TAG`, whereas RPMh code (`icc-rpmh.c`, `icc-rpmh.h`) must use `QCOM_ICC_NUM_BUCKETS` (3) and `QCOM_ICC_TAG_ALWAYS`. [F70]
- In `drivers/interconnect/qcom/icc-rpm.c`, AP-owned nodes (`qn->qos.ap_owned == true`) have QoS registers programmed directly via `qcom_icc_qos_set()` during `qnoc_probe()` (when `qos_mode != NOC_QOS_MODE_INVALID`) and must be skipped in `qcom_icc_rpm_set()`; for non-AP-owned nodes, `qcom_icc_rpm_set()` must send requests across all `0 <= rpm_ctx < QCOM_SMD_RPM_STATE_NUM`, and `qcom_icc_set()` must update cached `bus_clk_rate[ctx]` on `qp` and `src_qn` only after `qcom_icc_rpm_set_bus_rate()` succeeds. [F56, F110]
- In `struct qcom_icc_node`, `sum_avg` and `max_peak` must be `u64` (not `u32`) to avoid overflow when summing requests or multiplying by `aux_data.width` or 100; in `qcom_icc_calc_rate()`, `div_u64()` must be used for 64-bit divisions, optional divisors `qn->channels` and `qn->ib_coeff` must be checked for non-zero before dividing (dividing the scaled `agg_peak_rate = qn->max_peak[ctx] * 100` by `qn->ib_coeff`), and `qn->buswidth` must be non-zero. [F83, F89, F93]
- `icc_units_to_bps(bw)` in `include/linux/interconnect-provider.h` must multiply `bw` by `1000ULL` (not `1000` or `1000U`) so `u32` kBps bandwidth values are widened to 64-bit arithmetic before multiplication. [F88]
- Because `struct icc_onecell_data`, `struct icc_path`, and `struct icc_clk_provider` annotate their flexible arrays (`nodes[]`, `reqs[]`, `clocks[]`) with `__counted_by(...)`, callers allocating them (`icc_clk_register()`, `imx_icc_register()`, `qnoc_probe()`, `qcom_icc_rpmh_probe()`, `path_init()`) must initialize the counter member (`num_nodes` or `num_clocks`) before indexing the array. [F64, F102]
- In `imx_icc_register()` and `imx_icc_register_nodes()`, `struct icc_onecell_data` and the optional `settings` array are indexed by sparse `node_desc->id` rather than sequential descriptor index `i`, so `data->num_nodes` must be sized to `get_max_node_id(nodes, nodes_count) + 1` and populated at `provider_data->nodes[node->id]`. [F61]
- Unlike `qcom_icc_rpmh_probe()` and `mtk_emi_icc_probe()`, `qnoc_probe()` in `drivers/interconnect/qcom/icc-rpm.c` dereferences `qnodes[i]` unconditionally for every `0 <= i < desc->num_nodes`, so `desc->nodes` passed to `qnoc_probe()` must not contain `NULL` gaps. [F68]
- Every `path_find()` graph traversal must clear `n->is_traversed = false` on all nodes in `visited_list` (including `edge_list` and `traverse_list` spliced into `visited_list` when `dst` is found) before returning or calling `path_init()`. [F48]
- In `icc_clk_set()` and `icc_clk_unregister()`, `qn->enabled` is set to true only after `clk_prepare_enable(qn->clk)` succeeds, and `clk_disable_unprepare(qn->clk)` is called only when `qn->enabled` is true. [F59]

## Synchronization

- The lock hierarchy in `drivers/interconnect/core.c` is strictly `icc_lock` -> `fs_reclaim` -> `icc_bw_lock` -> `voter->lock` (`struct bcm_voter::lock`); `icc_lock` must never be acquired while `icc_bw_lock` is held, `icc_bw_lock` or `icc_lock` must never be acquired while holding `voter->lock` or `bcm_voter_lock`, and code executing under `icc_bw_lock` (`icc_set_bw()`, `aggregate_requests()`, `apply_constraints()`, and provider `pre_aggregate`, `aggregate`, `get_bw`, and `set` callbacks) must not perform `GFP_KERNEL` or direct-reclaim allocations. [F17, F124, F126]
- All mutations of `icc_node::req_list` and `icc_provider::users` in `path_init()` and `icc_put()` must hold both `icc_lock` and `icc_bw_lock`, so readers iterating `req_list` under `icc_bw_lock` in `aggregate_requests()` or under `icc_lock` in `icc_summary_show()` cannot race with list updates. [F18]
- `path_find()` and its call to `path_init()` must execute within a single continuous `icc_lock` critical section because `path_find()` mutates shared per-node traversal fields (`node->search_list`, `node->is_traversed`, `node->reverse`) in place and `path_init()` walks `node->reverse` to populate `path->reqs`. [F21]
- Mutations to per-hop request metadata `path->reqs[i].tag` in `icc_set_tag()` and `path->reqs[i].enabled` in `__icc_enable()` must be serialized by `icc_lock`. [F23]
- `qcom_icc_bcm_voter_probe()` must initialize `voter->lock`, `voter->commit_list`, `voter->ws_list`, `voter->dev`, `voter->np`, and `voter->tcs_wait` before adding `voter->voter_node` to `bcm_voters` under `bcm_voter_lock`, and all accesses to `voter->commit_list`, `voter->ws_list`, and `bcm->vote_x`/`vote_y` must hold `voter->lock`. [F26]
- In `icc_get_set()` (`drivers/interconnect/debugfs-client.c`), `src_node` and `dst_node` must be read via `rcu_dereference()` and copied with `GFP_ATOMIC` inside `rcu_read_lock()` before calling `rcu_read_unlock()` and invoking blocking functions `icc_get()` and `kzalloc(..., GFP_KERNEL)`. [F127]

## Object Lifetimes

- Even when a provider driver allocates `struct icc_provider` with `devm_kzalloc()`, nodes created via `icc_node_create()` or `icc_node_create_dyn()` are unmanaged heap objects in `icc_idr`: any error before `icc_node_add()` links a node onto `provider->nodes` must call `icc_node_destroy(node->id)` directly, and probe failure or driver remove after `icc_node_add()` must call `icc_nodes_remove()` or `imx_icc_unregister_nodes()` (using `list_for_each_entry_safe*`). [F1, F86, F107]
- A provider must initialize `provider->nodes`, set `provider->data` and callbacks, and create, add, and link all its `icc_node`s before publishing via `icc_provider_register()`, and must call `icc_provider_deregister()` before removing nodes via `icc_nodes_remove()` or `imx_icc_unregister_nodes()`. [F19]
- In `icc_put()`, `icc_set_bw(path, 0, 0)` must be called to re-aggregate and apply zero bandwidth across all hops before acquiring `icc_lock` and `icc_bw_lock` to unlink `path->reqs[i].req_node` from `node->req_list`, decrement `node->provider->users`, and free `path`. [F24]
- `of_icc_bulk_get()` and `icc_bulk_put()` must clear failed or released `paths[i].path` entries to `NULL` and unwind acquired paths in reverse index order, while `icc_bulk_enable()` must unwind partially enabled paths on failure via `icc_bulk_disable(i, paths)`. [F8]
- In `qnoc_probe()`, `qp->intf_clks` are enabled with `clk_bulk_prepare_enable()` only across the node setup and `qcom_icc_qos_set()` loop and must be disabled on any loop error or upon loop completion, whereas `qp->bus_clk` stays enabled until `qnoc_remove()` or probe unwind. [F12]
- In `drivers/interconnect/imx/imx.c`, `imx_icc_node_init_qos()` acquires a non-devm device reference via `of_find_device_by_node()` (`node_data->qos_dev`) and registers `node_data->qos_req` via `dev_pm_qos_add_request()`, so `imx_icc_node_destroy()` must call `dev_pm_qos_remove_request()` and `put_device(node_data->qos_dev)` before destroying the node. [F108]

## API Contracts

- Before calling `icc_node_add(node, provider)`, a provider must initialize `provider->nodes`, set `provider->set` and `provider->aggregate` (called without a NULL check in `aggregate_requests()`), assign `node->data`, and initialize all BCMs, clocks, and provider fields accessed by `get_bw()`, `pre_aggregate()`, `aggregate()`, and `set(node, node)` (which `icc_node_add()` invokes synchronously). Before `icc_provider_register()`, it must set `provider->xlate` or `provider->xlate_extended` (with `provider->data` pointing to a valid `struct icc_onecell_data` when using `of_icc_xlate_onecell()` or `qcom_icc_xlate_extended()`). [F20, F37, F96, F130]
- `icc_node_add(node, provider)` must be called on a source node before calling `icc_link_create(node, dst_id)` or `icc_link_nodes(node, dst_node)`, because both require `node->provider` to be non-NULL and return `-EINVAL` otherwise. [F38]
- Static node IDs passed to `icc_node_create()` must be below `ICC_DYN_ID_START` (100000), whereas dynamic nodes (`id >= ICC_DYN_ID_START`, created via `icc_node_create_dyn()` or `icc_link_nodes()`) must have `node->name` set via `icc_node_set_name()` because `icc_node_destroy()` calls `kfree(node->name)` when `node->id >= ICC_DYN_ID_START`. [F39]
- `apply_constraints()` skips calling `next->provider->set(prev, next)` across provider boundaries (`next->provider != prev->provider`) unless `next->provider->inter_set` is true, whereas `icc_node_add()` and `icc_sync_state()` invoke `provider->set(node, node)` with `src == dst`. [F132]
- Because `icc_init()` counts available DT nodes with `#interconnect-cells` (excluding `ignore_list`) into `providers_count` and `icc_sync_state()` waits for `providers_count` invocations before clearing `init_avg`/`init_peak` floors, provider `platform_driver` structs for those DT nodes must set `.driver.sync_state = icc_sync_state`. [F136]
- `of_icc_get()`, `devm_of_icc_get()`, and `of_icc_get_by_index()` return `NULL` when `"interconnects"` is absent in DT or `!CONFIG_INTERCONNECT`, and `icc_set_bw()`, `icc_enable()`, `icc_disable()`, `icc_put()`, `icc_set_tag()`, and `icc_get_name()` must treat a `NULL` `struct icc_path *` as a no-op. [F62]
- `devm_of_icc_bulk_get()` stores the caller's `struct icc_bulk_data *paths` pointer directly in `struct icc_bulk_devres` without copying the array, so `paths` must remain valid until `devm_icc_bulk_release()` runs at device detach. [F9]
- In `drivers/interconnect/qcom/icc-rpm.c`, `qcom_icc_set()` must check whether the provider has neither `qp->bus_clk_desc` nor `qp->bus_clk` before scaling bus clocks, convert kHz rates to Hz (`1000ULL * active_rate` capped at `ULONG_MAX`) for `clk_set_rate(qp->bus_clk, ...)`, and cap kHz rates at `INT_MAX` for `qcom_icc_rpm_set_bus_rate()`. [F40]
- In `qcom_icc_noc_set_qos_priority()`, `NOC_QOS_PRIORITYn_ADDR(qos->qos_port)` must be updated in two separate `regmap_update_bits()` calls with P1 (`NOC_QOS_PRIORITY_P1_MASK`) updated first and P0 (`NOC_QOS_PRIORITY_P0_MASK`) updated last, and `qcom_icc_set_noc_qos()` must skip register access when `qn->qos.qos_port < 0`; in `qcom_icc_set_bimc_qos()` and `qcom_icc_bimc_set_qos_health()`, `M_BKE_HEALTH_CFG_ADDR` and `M_BKE_EN_ADDR = 1` must only be programmed when `mode != NOC_QOS_MODE_BYPASS`, and `M_BKE_HEALTH_CFG_LIMITCMDS_MASK` must not be set when `regnum == 3`. [F41, F42]
- In `imx_icc_node_set()`, when `node_data->setting->mode == IMX_NOC_MODE_FIXED`, `PRIORITY_COMP_MARK` (`BIT(31)`) must be ORed with `(prio << 8) | prio` in `IMX_NOC_PRIO_REG`; `freq` must be divided by `node_data->desc->adj->bw_div` (non-zero) via `do_div()`, and `dev_pm_qos_update_request()` must not be called if `node_data->qos_dev` is `NULL` or if `freq > S32_MAX` (which must return `-ERANGE`). [F43, F91]

## Error Handling

- `of_icc_get_by_index()` and `of_icc_bulk_get()` suppress error logging on `-EPROBE_DEFER`. In `icc_set_bw()`, if `apply_constraints(path)` returns a non-zero error `ret`, the rollback path must log with `pr_debug()`, restore `old_avg` and `old_peak` across all `path->reqs[i]`, re-run `aggregate_requests()` and `apply_constraints()`, and return the original failure status `ret` without overwriting it with the rollback's return value. [F34, F141]

## External Contracts

- In `qcom_icc_bcm_init()`, `cmd_db_read_aux_data(bcm->name, &data_count)` must be checked for both `IS_ERR(data)` and `!data_count` before reading `struct bcm_db`, and `data->unit` (`__le32`) and `data->width` (`__le16`) must be converted via `le32_to_cpu()` and `le16_to_cpu()` when stored into `bcm->aux_data`. [F72]

## Known Pitfalls

- In `apply_constraints()`, the `continue` branch that skips calling `p->set(prev, next)` on the initial node (`!prev`) or across provider boundaries when `!p->inter_set` must still update `prev = next` before continuing. [F77]
- In `tcs_list_gen()`, `list_is_last(&bcm->list, bcm_list)` must short-circuit before `bcm->aux_data.vcd != list_next_entry(bcm, list)->aux_data.vcd` is evaluated. [F78]
- In `devm_of_icc_get()`, the devres slot `struct icc_path **ptr` must be allocated with `devres_alloc(devm_icc_release, sizeof(*ptr), GFP_KERNEL)` (pointer size), because `devm_icc_release()` dereferences `res` as `*(struct icc_path **)res`. [F98]
