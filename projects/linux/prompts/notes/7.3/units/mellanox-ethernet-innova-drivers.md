# MELLANOX ETHERNET INNOVA DRIVERS

This unit (`drivers/net/ethernet/mellanox/mlx5/core/en_accel/` and `fpga/`) implements ConnectX/Innova hardware network acceleration for IPsec (XFRM), kTLS, MACsec, PSP, and Geneve/UDP GSO offloads—covering control-plane callbacks, flow-steering tables, ASO state updates, and TX/RX WQE/CQE processing—alongside Innova FPGA core/SDK management for device initialization, I2C access, event handling, and Sandbox Unit (SBU) QPs/CQs.

## Architecture & Data Flow
- Hardware ASO event arm bits (`esn_event_arm`, `soft_lft_arm`, `hard_lft_arm`, `epn_event_arm`) are cleared by hardware when triggered, so `mlx5e_ipsec_handle_event()`, `mlx5e_ipsec_handle_limits()`, and `macsec_async_event()` must test `!arm`. In `mlx5e_ipsec_update_esn_state()` and `macsec_epn_update()`, increment `esn_msb`/`epn_msb` and set `overlap = 0` only when `mode_param < 0x80000000L` (`*_SCOPE_MID`), else set `overlap = 1`; then modify the FW object and post an ASO WQE setting `BIT_ULL(54)` at `*_ASO_REMOVE_FLOW_PKT_CNT_OFFSET` to re-arm. [F69, F106, F129]
- When `sa_entry->esn_state.esn_msb == 0` (including non-ESN SAs), `mlx5e_xfrm_add_state()` and `mlx5e_ipsec_update_esn_state()` must initialize `sa_entry->esn_state.esn` to at least 1, and `mlx5e_ipsec_packet_setup()` must program it into `ipsec_aso` `mode_parameter` on `XFRM_DEV_OFFLOAD_OUT` even when `!attrs->replay_esn.trigger`. Replay window validation and `MLX5_IPSEC_ASO_REPLAY_PROTECTION` setup apply only when `dir == XFRM_DEV_OFFLOAD_IN`. [F56, F110]
- `sa_entry->work->data` holds a shadow `struct mlx5e_ipsec_sa_entry *` for `XFRM_DEV_OFFLOAD_CRYPTO` (`mlx5e_ipsec_modify_state`), where `mlx5e_xfrm_advance_esn_state()` builds updated ESN attributes and `sa_entry->attrs` is updated only in `mlx5_accel_esp_modify_xfrm()` after `mlx5_modify_ipsec_obj()` succeeds; for `XFRM_DEV_OFFLOAD_PACKET` (`mlx5e_ipsec_handle_netdev_event`), `work->data` is `struct mlx5e_ipsec_netevent_data *`, so `MLX5E_IPSEC_TUNNEL_SA` must only mark packet-offload tunnel SAs. [F75, F136]
- In `mlx5e_ipsec_init_limits()`, decomposing 64-bit packet limits into 32-bit `start_value` and `BIT_ULL(31)` rounds `n` must decrement `n` for multi-round hard limits (`n >= 1`) so `start_value` is in `[2^31, 2^32)`, and increment `n` for interior soft-limit rounds (`n != attrs->lft.numb_rounds_hard`) with `start_value < BIT_ULL(30)`. In `mlx5e_ipsec_handle_limits()`, hitting an interior soft limit with `soft_packet_limit > BIT_ULL(31)` must set a temporary soft limit of `BIT_ULL(31) - BIT_ULL(30)` and `fix_limit = true` before `mlx5e_ipsec_aso_update_hard()`. [F123, F124]
- For NIC RX IPsec SAs (`rx != ipsec->rx_esw`), `rx_add_rule()` writes `sa_entry->ipsec_obj_id | BIT(31)` into `METADATA_REG_B` and `METADATA_REG_C_2` (plus `MLX5_IPSEC_ASO_SW_CRYPTO_OFFLOAD` in `METADATA_REG_C_4` for crypto offload) so `rx->ft.status` matches via `ipsec_rx_rule_add_match_obj()`. `ipsec_obj_id` in `ipsec->sadb` must fit in 24 bits (`MLX5_IPSEC_METADATA_HANDLE`), and `rx->ft.status` pass rules/groups (`ipsec_rx_status_pass_create`, `rx_add_rule_sa_selector`) must match both `ipsec_syndrome == 0` and `metadata_reg_c_4`. [F77, F95, F146]
- In `rx_add_rule()` and `setup_fte_spi()`, UDP-encapsulated SAs (`attrs->encap`) must match `misc_parameters.inner_esp_spi` and omit `setup_fte_esp(spec)`, whereas non-encapsulated SAs match `outer_esp_spi` and call `setup_fte_esp(spec)`. In `tx_add_rule()`, outer IP, SPI, ESP, and `metadata_reg_a` matches apply only to `XFRM_DEV_OFFLOAD_CRYPTO`, while `XFRM_DEV_OFFLOAD_PACKET` matches `attrs->reqid` in `metadata_reg_c_4` via `setup_fte_reg_c4()`. [F108, F145]
- In `ipsec_rx()`, `ipsec_tx()`, and `ipsec_fs_get_ns()`, the E-Switch path (`rx_esw`, `tx_esw`, `MLX5_FLOW_NAMESPACE_FDB`) is used only when both `ipsec->is_uplink_rep` and `type == XFRM_DEV_OFFLOAD_PACKET` hold; when `rx != ipsec->rx_esw`, `ipsec_rx_chains_create_miss()` must create `rx->pol_miss_ft` at `attr->pol_miss_level` (`MLX5E_ACCEL_FS_POL_MISS_FT_LEVEL`), and `ipsec_rx_update_default_dest()` must update both `rx->pol_miss_rule` and `rx->status_checks.crypto_offload_pass_rule` together. [F72, F73, F104]
- In `mlx5e_macsec_init_sa_fs()` and `mlx5e_macsec_upd_secy()`, install a TX flow rule (`is_tx == true`) only when `sa->assoc_num == ctx->secy->tx_sc.encoding_sa`. In `update_macsec_epn()`, populate `sa->ssci` from the standalone `ctx_tx_sa->ssci` or `ctx_rx_sa->ssci` argument (never from `key->salt`), `sa->salt` from `key->salt`, `epn_state->epn_msb` from `next_pn_halves->upper`, and `epn_state->overlap` to `0` if `next_pn_halves->lower < MLX5_MACSEC_EPN_SCOPE_MID` else `1`. [F65, F68]
- Accessing `key`, `salt`, or `rec_seq` in `union mlx5e_crypto_info` or `struct tls_crypto_info *` must switch on `cipher_type` (`TLS_CIPHER_AES_GCM_128` vs `256`) due to differing key sizes and `rec_seq` offsets. In `tx_post_resync_params()`, compare `priv_tx->crypto_info`'s `rec_seq` with `cpu_to_be64(rcd_sn)` before updating it so `mlx5e_ktls_tx_post_param_wqes()` sets `skip_static_post = false` iff `rcd_sn` changed, and keep `mlx5e_ktls_get_stop_room()` sized for all param, dump, and fence WQEs posted by `mlx5e_ktls_handle_tx_skb()`. [F80, F84, F139]

## Synchronization
- All mutations to `ipsec->sadb` (`xa_insert_bh`, `xa_erase_bh`, and `xa_lock_bh`/`xa_unlock_bh` around `__xa_set_mark`) must use BH-disabling xarray locks because `mlx5e_xfrm_del_state()` can run in softirq via `xfrm_timer_handler()`. In `mlx5e_xfrm_add_state()`, do not insert `sa_entry` into `ipsec->sadb` or set `MLX5E_IPSEC_TUNNEL_SA` until `mlx5_ipsec_create_work()`, `mlx5e_ipsec_create_dwork()`, `mlx5_ipsec_create_sa_ctx()`, and `mlx5e_accel_ipsec_fs_add_rule()` have initialized its work items, object ID, and flow rules. [F21, F155]
- In `mlx5e_ipsec_handle_sw_limits()`, under `spin_lock_bh(&x->lock)`, verify `x->km.state == XFRM_STATE_VALID` before calling `xfrm_state_check_expire(x)` and rescheduling `dwork->dwork`. In `mlx5e_ipsec_block_tc_offload()`, when `CONFIG_MLX5_ESWITCH` is enabled and `mdev->priv.eswitch` is non-NULL, hold `mlx5_esw_lock(esw)` around checking `mdev->num_block_ipsec` and incrementing `mdev->num_block_tc`. [F17, F19]
- In `ktls_tx.c`, `mlx5e_tls_tx_pool` operations (`create_work`, `destroy_work`, `pool_push`, `pool_pop`) must hold `pool->lock` while accessing `pool->list` and `pool->size`, but release `pool->lock` across blocking TIS commands (`mlx5e_tls_priv_tx_init`, `mlx5e_tls_priv_tx_list_cleanup`). `mlx5e_bulk_async_cleanup()` (`mlx5_cmd_cleanup_async_ctx()`) must finish in `create_work()` before splicing `local_list` into `pool->list`, and in `mlx5e_tls_priv_tx_list_cleanup()` before returning. [F30, F31]
- In `tx_sync_info_get()`, hold `spin_lock_irqsave(&tx_ctx->lock, flags)` continuously across `tls_get_record()` and copying `record->frags[i]` into `info->frags` while calling `page_ref_inc(skb_frag_page(frag))`. In `mlx5e_ktls_handle_tx_skb()`, read `tls_ctx->netdev` via `rcu_dereference_bh(tls_ctx->netdev)` and allow `NULL` without dropping/warning; in `mlx5e_psp_set_state()`, hold `rcu_read_lock()` across `psp_skb_get_assoc_rcu(skb)` and copying `pas->tx.spi`, `pas->version`, and `*(u32 *)pas->drv_data` into `psp_st`. [F32, F33, F37]
- In `macsec.c`, all mutations and lookups of `macsec_device_list_head`, `tx_sa`, `rx_sc`, and `rx_sa` across `macsec_offload_ops` and `macsec_async_event()` must hold `macsec->lock`; `macsec_aso_query()` and `macsec_aso_set_arm_event()` must serialize `macsec->aso` accesses under `aso->aso_lock` nested inside `macsec->lock`. [F34]

## Object Lifetimes
- In `mlx5e_xfrm_add_state()` (when `!XFRM_DEV_OFFLOAD_FLAG_ACQ`), acquire `mlx5_eswitch_block_ipsec()`, `mlx5_eswitch_block_mode()`, and (for packet-offload tunnel SAs) `mlx5e_ipsec_fs_tunnel_allowed()` in order; release encap and mode blocks before returning 0 or on error, and unblock ipsec in `mlx5e_xfrm_free_state()`. Every `mlx5e_ipsec_block_tc_offload()` in `mlx5e_accel_ipsec_fs_add_rule()` (for `XFRM_DEV_OFFLOAD_PACKET`) and `mlx5e_accel_ipsec_fs_add_pol()` must pair with `mlx5e_ipsec_unblock_tc_offload()` on error and deletion. [F1, F4]
- In `mlx5e_xfrm_free_state()`, check `sa_entry->work` and `sa_entry->dwork` for non-NULL and drain them with `cancel_work_sync(&sa_entry->work->work)` and `cancel_delayed_work_sync(&sa_entry->dwork->dwork)` before calling `mlx5e_accel_ipsec_fs_del_rule()`, `mlx5_ipsec_free_sa_ctx()`, or `kfree()`. In `mlx5e_ipsec_cleanup()` and `mlx5e_accel_ipsec_fs_cleanup()`, check `ipsec->netevent_nb.notifier_call`, `ipsec->aso`, and `ipsec->roce` for non-NULL rather than re-evaluating `mlx5_ipsec_device_caps()`. [F5, F22, F51]
- In `mlx5e_accel_ipsec_fs_modify()`, install replacement rules into a zeroed stack `sa_entry_shadow.ipsec_rule` via `mlx5e_accel_ipsec_fs_add_rule(&sa_entry_shadow)` before calling `mlx5e_accel_ipsec_fs_del_rule(sa_entry)` and copying `sa_entry_shadow` over `*sa_entry`; thus `mlx5e_accel_ipsec_fs_add_rule()` and its callees (`tx_add_rule`, `rx_add_rule`) must never persist `sa_entry` or create self-referential pointers in `*sa_entry`. [F74, F137]
- In `mlx5e_ipsec_offload_handle_rx_skb()`, after `secpath_set(skb)`, any failure before populating `sp->xvec` must call `secpath_reset(skb)`, and success must call `xfrm_state_hold(sa_entry->x)` under `rcu_read_lock()`. [F12]
- In `mlx5e_ktls_add_tx()`, after `pool_pop(pool)` returns a recycled `priv_tx` (retaining `tisn`), reinitialize `crypto_info`, `dek`, `expected_seq`, `tx_ctx`, and `ctx_post_pending = true`; any failure after `pool_pop()` must return `priv_tx` via `pool_push(pool, priv_tx)`, and `mlx5e_ktls_del_tx()` must call `mlx5_ktls_destroy_key()` on `priv_tx->dek` before `pool_push()`. Create and destroy `priv->tls->dek_pool` in `mlx5e_ktls_init_tx()` / `mlx5e_ktls_cleanup_tx()` whenever `mlx5e_is_ktls_device(priv->mdev)` is true. [F7, F79, F141]
- In kTLS TX resync dump handling, fragment page refcounts must use `page_ref_inc()` in `tx_sync_info_get()`, `page_ref_add(skb_frag_page(f), n - 1)` in `mlx5e_ktls_tx_handle_ooo()` when a fragment spans `n` DUMP WQEs, and `page_ref_dec()` in `mlx5e_ktls_tx_handle_resync_dump_comp()`. If `tx_post_resync_dump()` fails on chunk `n` of fragment `i`, add `n - 1` refs for posted WQEs and jump to `err_out` without incrementing `i` so `for (; i < info.nr_frags; i++)` calls `page_ref_dec()` once on `i` and remaining fragments. [F2, F116]
- In `mlx5e_ktls_del_rx()`, set `MLX5E_PRIV_RX_FLAG_DELETING`, clear the socket RX driver context, call `synchronize_net()`, and synchronize with `priv_rx->rule.work` (waiting on `priv_rx->add_ctx` if `cancel_work_sync(&priv_rx->rule.work)` returns false) and `priv_rx->resync.work` before destroying the flow rule, `tir`, and `dek`. Every path after `post_rx_param_wqes()` must complete `add_ctx` if `rule.work` isn't queued or when it finishes, and `resync_queue_get_psv()`'s `mlx5e_ktls_priv_rx_get()` ref must be dropped via `mlx5e_ktls_priv_rx_put()` on cancel, error, or completion. [F9, F27, F144]
- In `mlx5e_macsec_cleanup()`, call `mlx5_notifier_unregister(mdev, &macsec->nb)` and `destroy_workqueue(macsec->wq)` in that order before `mlx5e_macsec_aso_cleanup()`, `mutex_destroy()`, and `kfree(macsec)`. When updating a MACsec TX SA or SecY in `mlx5e_macsec_upd_txsa()`, `mlx5e_macsec_upd_secy()`, or `macsec_upd_secy_hw_address()`, only tear down and recreate flow rules via `mlx5e_macsec_cleanup_sa_fs()` and `mlx5e_macsec_init_sa_fs()`, preserving `sa->macsec_obj_id`. [F36, F64]

## API Contracts
- TX SKB offload handlers called by `mlx5e_accel_tx_begin()` (`mlx5e_ktls_handle_tx_skb`, `mlx5e_psp_handle_tx_skb`, `mlx5e_ipsec_handle_tx_skb`, `mlx5e_macsec_handle_tx_skb`) must consume/free `skb` before returning `false`, and return `true` when `skb` remains valid. Any inline trailer written in `mlx5e_accel_tx_finish()` (`state->ipsec.tailen` or `state->psp_st.tailen`) must match `mlx5e_accel_tx_ids_len()`, and SWP offsets (`eseg->swp_*_offset`) are in 2-byte units (`skb_*_offset(skb) / 2`). [F43, F61, F83]
- In `mlx5e_ipsec_xfrmdev_ops`, `.xdo_dev_state_delete` (`mlx5e_xfrm_del_state`) and `.xdo_dev_policy_free` (`mlx5e_xfrm_free_policy`) must not sleep, flush workqueues, or issue blocking FW/flow-steering commands; blocking cleanup belongs in `mlx5e_xfrm_free_state()` and `mlx5e_xfrm_del_policy()`. [F156]
- Before `MLX5_CMD_OP_MODIFY_GENERAL_OBJECT` in `mlx5_modify_ipsec_obj()` or `mlx5e_macsec_modify_obj()`, query `modify_field_select` via `MLX5_CMD_OP_QUERY_GENERAL_OBJECT` to confirm overlap and MSB are modifiable. Map replay window bit sizes (`32..256`) via a switch statement to `MLX5_IPSEC_ASO_REPLAY_WIN_*BIT` / `MLX5_MACSEC_ASO_REPLAY_WIN_*BIT` enums, and divide `aes_gcm->key_len` by `BITS_PER_BYTE` for `mlx5_create_encryption_key()`. [F59, F60, F149]

## Error Handling
- In `mlx5e_ipsec_remove_trailer()`, check both `skb_copy_bits()` and `pskb_trim()` for negative errors before subtracting `trailer_len` from `ipv4hdr->tot_len` or `ipv6hdr->payload_len`. In `mlx5e_xfrm_add_state()`, use `NL_SET_ERR_MSG_WEAK_MOD` at `err_xfrm:` so specific `extack` messages are preserved, and ensure `mlx5e_xfrm_validate_state()` checks `x->aead` and `alg_key_len` (`128 + 32` or `256 + 32`) before `mlx5e_ipsec_build_accel_xfrm_attrs()` copies into the 32-byte `aes_gcm->aes_key`. [F48, F54, F92]
- In `ktls_tx.c`, when async `MLX5_CMD_OP_CREATE_TIS` fails, `create_tis_callback()` must set `priv_tx->create_err = 1` so `mlx5e_tls_priv_tx_cleanup()` frees `priv_tx` without issuing `MLX5_CMD_OP_DESTROY_TIS`. If the loop `for (i = 0; i < MLX5E_TLS_TX_POOL_BULK; i++)` in `create_work()` breaks early, pass `i` (not `MLX5E_TLS_TX_POOL_BULK`) to the status check loop and `mlx5e_tls_priv_tx_list_cleanup(pool->mdev, &local_list, i)`, and ensure `size` passed to `mlx5e_tls_priv_tx_list_cleanup()` is at least the list length. [F55, F115, F134]

## External Contracts
- In `mlx5e_xfrm_update_stats()`, packet-offload SA lifetime stats (`x->curlft.packets` and `x->curlft.bytes`) must subtract `auth`, `trailer`, and `replay` drop packets/bytes and outer Ethernet + IP header bytes per succeeded packet from `ipsec_rule->fc`. When `x->xso.flags & XFRM_DEV_OFFLOAD_FLAG_ACQ` is set, `mlx5e_xfrm_add_state()` must allocate `sa_entry` with `GFP_ATOMIC` and skip hardware/SADB setup, and `mlx5e_xfrm_del_state()`, `mlx5e_xfrm_free_state()`, and `mlx5e_xfrm_update_stats()` must skip hardware/SADB operations. [F71, F182]

## Known Pitfalls
- Because `ipsec_fs_init_counters()` aliases `ipsec->rx_ipv6->fc = ipsec->rx_ipv4->fc`, `ipsec_fs_destroy_counters()` and `mlx5e_accel_ipsec_fs_read_stats()` must only destroy or query `ipsec->rx_ipv4->fc`. In `tx_add_policy()`, call `setup_modify_header()` only for `XFRM_POLICY_ALLOW` (with non-zero `reqid`), never `XFRM_POLICY_BLOCK`, as hardware rejects `ACTION_DROP` combined with `ACTION_MOD_HDR`. [F76, F147]
- In `mlx5e_macsec_upd_txsa()`, assign `tx_sa->active = ctx_tx_sa->active` before checking `if (tx_sa->assoc_num != tx_sc->encoding_sa) goto out;`. In `macsec_rx_sa_active_update()`, `mlx5e_macsec_upd_txsa()`, and `mlx5e_macsec_upd_rxsc()`, bail out when `current_active == new_active` (reverting `rx_sa->active = false` if `mlx5e_macsec_init_sa()` fails), and in `mlx5e_macsec_create_object()`, copy the 12-byte `attrs->salt` into `macsec_offload_obj` in reversed 4-byte word order (`&attrs->salt.bytes[4 * (2 - i)]` for `i = 0..2`). [F66, F98, F107]
- `mlx5_wqe_ctrl_seg::tis_tir_num` requires `cpu_to_be32(tis_tir_num << 8)`, whereas `mlx5_wqe_tls_progress_params_seg::tis_tir_num` in `fill_progress_params()` takes `cpu_to_be32(tis_tir_num)` unshifted. In `tx_sync_info_get()`, use `before(tcp_seq + datalen - 1, tls_record_start_seq(record))` rather than `<`, and in `destroy_work()` / `mlx5e_tls_tx_pool_list_cleanup()`, only run the `MLX5E_TLS_TX_POOL_BULK` `list_cut_position()` loop when `pool->size >= MLX5E_TLS_TX_POOL_BULK`. [F102, F114, F128]
