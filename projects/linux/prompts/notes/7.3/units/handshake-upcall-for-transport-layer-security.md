# HANDSHAKE UPCALL FOR TRANSPORT LAYER SECURITY

This component provides an in-kernel generic netlink upcall service (`HANDSHAKE` family) that allows kernel socket consumers (such as sunrpc/NFS or NVMe-over-TCP) to delegate transport layer security handshakes (primarily TLS via `tlshd`) to a userspace daemon. It manages the lifecycle of per-socket handshake requests (`struct handshake_req`), tracks pending requests per network namespace, installs the kernel socket into the userspace handler's file descriptor table upon `HANDSHAKE_CMD_ACCEPT`, and invokes the consumer's completion callback upon `HANDSHAKE_CMD_DONE`. It also provides helpers for sending and parsing TLS Alert records and inspecting TLS record content types via control messages.

## Architecture & Data Flow
- Any `struct handshake_proto` whose `hp_accept`, `hp_done`, or `hp_destroy` callback casts `handshake_req_private(req)` (`hr_priv`) to a private struct must set `hp_privsize` to at least `sizeof` that struct, and `handshake_req_alloc()` must size the allocation using `struct_size(req, hr_priv, proto->hp_privsize)` rather than raw addition so an excessive `hp_privsize` saturates to `SIZE_MAX` instead of wrapping on 32-bit `size_t`. [F55, F60]
- New TLS request parameters added to `struct tls_handshake_args` must be copied into `struct tls_handshake_req` in `tls_handshake_req_init()` (or the mode-specific `tls_*_hello_*()` functions) and emitted as `HANDSHAKE_A_ACCEPT_*` netlink attributes in `tls_handshake_accept()`. [F41]
- In `tls_handshake_accept()`, `switch (treq->th_auth_mode)` must allow `HANDSHAKE_AUTH_UNAUTH` (set by `tls_client_hello_anon()`) to pass through without failing, emitting extra attributes only for `HANDSHAKE_AUTH_PSK` and `HANDSHAKE_AUTH_X509`. Broken by: adding a `default:` branch that returns an error. [F52]
- In `handshake_net_init()`, the memory-scaled limit `si.totalram / (25 * si.mem_unit)` must be evaluated and clamped in `unsigned long` (`clamp(tmp, 3UL, 50UL)`) before assigning to the 32-bit signed `int hn->hn_pending_max` to avoid truncation or signed overflow on systems with large RAM. [F56]
- Trace event definitions in `include/trace/events/handshake.h` that populate `saddr` and `daddr` with `TP_STORE_ADDR_PORTS()` and format them with `%pISpc` must size both `__u8` arrays to `sizeof(struct sockaddr_in6)` and zero-initialize them before storing the address. [F63]

## Synchronization
- Spinlock `hn->hn_lock` must be released before calling `handshake_genl_notify()`, `req->hr_proto->hp_accept()`, or `handshake_complete()`, because those paths perform memory allocations, sleepable key lookups (`lookup_user_key()`, `key_link()`), netlink transmissions, and consumer `hp_done` callbacks. [F18]
- In `handshake_req_submit()`, `req->hr_sk` and `req->hr_odestruct` must be assigned before `handshake_req_hash_add()` and `__add_pending_locked()` publish `req`, because `handshake_rhash_params` hashes `hr_sk` and concurrent `handshake_nl_accept_doit()` readers immediately dereference `req->hr_sk`. [F12]
- `hn->hn_lock` must be held across all modifications to `hn->hn_pending` and `hn->hn_requests`, and `__remove_pending_locked()` and `handshake_req_next()` must use `list_del_init(&req->hr_list)` (never `list_del()`) so `remove_pending()` can reliably check `!list_empty(&req->hr_list)` under `hn->hn_lock` to detect whether `req` is still pending. [F14]
- `tls_handshake_done()` must set `HANDSHAKE_F_REQ_SESSION` in `req->hr_flags` on successful completion (`!status`) before invoking `treq->th_consumer_done()`, and `tls_handshake_close()` must use `test_and_clear_bit(HANDSHAKE_F_REQ_SESSION, &req->hr_flags)` (not a non-clearing `test_bit()`) to gate `tls_alert_send()`. [F19]

## Object Lifetimes
- Once `handshake_req_submit()` succeeds, `struct handshake_req` must remain in `handshake_rhashtbl` across `handshake_req_next()`, `handshake_complete()`, and `handshake_req_cancel()` until `handshake_sk_destruct()` calls `handshake_req_destroy()`, so `handshake_nl_done_doit()`, `tls_handshake_close()`, and `handshake_sk_destruct()` can look up `req` by `sk`. [F35]
- In `handshake_sk_destruct()`, `req->hr_odestruct` must be saved to a local variable before calling `handshake_req_destroy(req)` and invoked afterwards, because `handshake_req_destroy()` kfrees `req` before the chained socket destructor runs. [F36]
- `tls_handshake_req_init()` stores `args->ta_peername` as a shallow pointer in `treq->th_peername` for `nla_put_string()` in `tls_handshake_accept()`, so any non-NULL `ta_peername` passed to `tls_client_hello_*()` or `tls_server_hello_*()` must be a NUL-terminated string valid until the handshake completes or is canceled. [F58]
- In `handshake_init()`, `register_pernet_subsys(&handshake_genl_net_ops)` must be called last after `handshake_req_hash_init()` and `genl_register_family()`, and `handshake_exit()` must call `unregister_pernet_subsys()` and zero `handshake_net_id` before destroying the rhashtable. [F10]

## API Contracts
- `handshake_sk_destruct()`, `handshake_req_destroy()`, and any `handshake_proto.hp_destroy` callback execute from `sk->sk_destruct` during final `struct sock` destruction (which may run in softirq/RCU teardown context) and must not sleep, take sleeping locks, or perform `GFP_KERNEL` allocations. [F66]
- `tls_get_record_type()` directly reads `cmsg->cmsg_level`, `cmsg->cmsg_type`, and `*((u8 *)CMSG_DATA(cmsg))` without checking `cmsg` for `NULL` or validating `cmsg->cmsg_len`; callers must supply a valid, initialized `struct cmsghdr` buffer of at least `CMSG_LEN(sizeof(u8))` bytes. [F48]
- `tls_alert_recv()` reads the 2-byte TLS alert directly from `msg->msg_iter.kvec->iov_base` without checking iterator type or offset; callers must pass a `struct msghdr` backed by an `ITER_KVEC` pointing to the alert segment, calling `iov_iter_revert()` first if `sock_recvmsg()` exhausted the `kvec`. [F57]
- `tls_alert_send()` must zero-initialize its `CMSG_SPACE(sizeof(record_type))` control buffer, set `cmsg->cmsg_len = CMSG_LEN(sizeof(record_type))`, set `MSG_DONTWAIT` in `msg.msg_flags` so `tls_handshake_close()` never blocks on send buffer space, and normalize `sock_sendmsg()`'s return value (`ret < 0 ? ret : 0`). [F32, F67]
- The TLS handshake submission entry points (`tls_client_hello_anon()`, `tls_client_hello_x509()`, `tls_client_hello_psk()`, `tls_server_hello_x509()`, `tls_server_hello_psk()`) must propagate their caller-supplied `gfp_t flags` through `handshake_req_alloc()`, `handshake_req_submit()`, and `handshake_genl_notify()` (`genlmsg_new()` and `genlmsg_multicast_netns()`) rather than hardcoding `GFP_KERNEL`. [F64]
- `tls_client_hello_psk()` must validate that `args->ta_num_peerids` is between `1` and `ARRAY_SIZE(treq->th_peerid)` (5) inclusive, returning `-EINVAL` before allocating `req` if out of bounds. [F30]

## Error Handling
- `tls_handshake_private_keyring()` must return `0` when `treq->th_keyring == TLS_NO_KEYRING`, check `lookup_user_key()` results with `IS_ERR()` and extract negative errnos via `PTR_ERR()`, convert valid `key_ref_t` handles with `key_ref_to_ptr()` for `key_link()`, and release them via `key_ref_put()` (including releasing `process_keyring_ref` if the second lookup fails). [F29]
- `struct handshake_proto.hp_destroy` is optional (`tls_handshake_proto` leaves it `NULL`), so `handshake_req_destroy()` must check `if (req->hr_proto->hp_destroy)` before invoking it. [F24]

## External Contracts
- Because `HANDSHAKE_A_DONE_REMOTE_AUTH` is a multi-attribute, `tls_handshake_remote_peerids()` must walk the attribute stream with `nla_for_each_attr()` rather than reading `info->attrs[HANDSHAKE_A_DONE_REMOTE_AUTH]` directly, and must clamp `treq->th_num_peerids` to `ARRAY_SIZE(treq->th_peerid)`. [F79]
- Netlink attributes carrying socket file descriptors (`HANDSHAKE_A_ACCEPT_SOCKFD`, `HANDSHAKE_A_DONE_SOCKFD`) and X.509 key serial numbers (`HANDSHAKE_A_X509_CERT`, `HANDSHAKE_A_X509_PRIVKEY`) are typed as `NLA_S32` and must be accessed with `nla_get_s32()` and `nla_put_s32()` rather than `u32` helpers. [F78]

## Known Pitfalls
- `handshake_rhashtbl` is configured in `handshake_rhash_params` with `key_len = sizeof_field(struct handshake_req, hr_sk)` and `key_offset = offsetof(struct handshake_req, hr_sk)`, so `rhashtable` lookups on `handshake_rhashtbl` must pass the address of a `struct sock *` variable (`&sk`) rather than the `sk` pointer itself. [F59]
- Flag enums `hn_flags_bits`, `hr_flags_bits`, and `hp_flags_bits` define bit indices (such as `HANDSHAKE_F_PROTO_NOTIFY = 0`), so bitops (`test_bit()`, `set_bit()`, `test_and_set_bit()`, `test_and_clear_bit()`) must take the enum constant directly, whereas production `struct handshake_proto.hp_flags` mask initializers must set `BIT(HANDSHAKE_F_PROTO_NOTIFY)` so `handshake_genl_notify()` does not skip `HANDSHAKE_CMD_READY` multicast notifications. [F31, F71]
- `trace_handshake_cmd_accept()` and `trace_handshake_cmd_done()` (defined via `DECLARE_EVENT_CLASS(handshake_fd_class, ...)`) dereference `req->hr_sk` inside `TP_fast_assign`; when `req` may be `NULL`, callers must invoke `trace_handshake_cmd_accept_err()` or `trace_handshake_cmd_done_err()` instead. [F21]
