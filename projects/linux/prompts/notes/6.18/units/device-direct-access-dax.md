# DEVICE DIRECT ACCESS (DAX)

The DAX subsystem (`drivers/dax/`) provides direct byte-addressable access to persistent and differentiated memory ranges without the page cache. It implements the core `struct dax_device` pseudo-filesystem and block-device host registry (`super.c`), the `dax` bus and dynamic/static region allocator (`bus.c`), endpoint drivers exposing `dev_dax` instances as `/dev/daxX.Y` character devices (`device.c`) or hotplugged System RAM (`kmem.c`), and provider drivers for NVDIMM PMEM (`pmem.c`), CXL (`cxl.c`), and EFI/ACPI soft-reserved HMEM (`hmem/`).

## Architecture & Data Flow

- When removing a full range in `dev_dax_shrink()`, `unregister_dax_mapping()` must execute via `devm_release_action()` before `trim_dev_dax_range()` decrements `dev_dax->nr_range` and frees `dev_dax->ranges`, because `unregister_dax_mapping()` indexes `dev_dax->ranges[mapping->range_id]` and sets `mapping->range_id = -1`. [F50]
- Dynamic `dev_dax` range sizes and alignment changes (`size_store()`, `mapping_store()`, `dev_dax_resize()`, `dev_dax_validate_align()`) must satisfy `alloc_is_aligned()`, requiring alignment to `max_t(unsigned long, dev_dax->align, memremap_compat_align())`. `dev_dax->ranges` must stay ordered by increasing `pgoff`: in-place resizing via `adjust_dev_dax_range()` is only permitted on the last entry `dev_dax->ranges[dev_dax->nr_range - 1]` (`adjust_ok()`, `dev_dax_shrink()`) and must update `dax_region->res` via `adjust_resource()` and `dax_range->range.end` in lockstep. [F51, F151]
- In `dev_dax_resize()`, each `retry:` pass must re-read `first = region_res->child` and reset `rc = -ENOSPC`, and each sibling iteration must reset `alloc = 0` before checking inter-resource and tail gaps, breaking out to decrement `to_alloc` and jump to `retry:` after any single range adjustment or allocation. [F89]
- In `dax_open()`, the opened character-device `inode->i_mapping` and `filp->f_mapping` must be redirected to `dax_inode(dax_dev)->i_mapping` (with `host = dax_inode(dax_dev)`) so `unmap_mapping_range(inode->i_mapping, 0, 0, 1)` in `kill_dev_dax()` unmaps all active VMAs across all open `/dev/daxX.Y` descriptors. [F62]
- When `dev_dax->align > PAGE_SIZE`, `dev_dax_probe()` sets `pgmap->vmemmap_shift = order_base_2(dev_dax->align >> PAGE_SHIFT)`, and `dax_set_mapping()` must check `if (dev_dax->pgmap->vmemmap_shift)` to limit `nr_pages` to `1` so `folio->mapping` and `folio->index` are only set on the compound head folio. [F61]
- In `kill_dax()`, `dax_holder_notify_failure()` must be called while `DAXDEV_ALIVE` is still set and `holder_ops` is valid; `dax_dev->holder_ops` and `dax_dev->holder_data` must only be cleared after `clear_bit(DAXDEV_ALIVE, &dax_dev->flags)` and `synchronize_srcu(&dax_srcu)` complete. [F65]
- `__free_dev_dax_id()` must atomically under `dax_dev_rwsem` free `dev_dax->id` from `dax_region->ida`, drop `dax_region->kref` via `dax_region_put()`, and set `dev_dax->id = -1` so `dax_bus_probe()` rejects the invalidated device and `dev_dax_release()` does not double-free the ID or `dax_region`. `delete_store()` must test `__free_dev_dax_id(dev_dax) >= 0` (not `== 0`), as it returns the previous non-negative ID or `-1` if static/already freed. [F45, F55]
- In `align_store()`, `dev_dax->align` may only be updated after verifying `!dev->driver` and `dax_region->dev->driver` under `dax_region_rwsem` and `dax_dev_rwsem`, and the previous `dev_dax->align` must be saved and restored if `dev_dax_validate_align()` fails for any existing range. [F56]
- In `dax_pgoff_to_phys()`, once the loop finds the `dev_dax_range` containing `pgoff` (`dax_range->pgoff <= pgoff <= pgoff_end`), if `phys + size - 1 > range->end` it must immediately `break` and return `-1` rather than continuing to subsequent ranges. [F91]
- In `dev_dax_kmem_probe()` and `dev_dax_kmem_remove()`, `data->res` must be indexed by the `dev_dax->ranges` loop index `i` (not `mapped`), and `dev_dax_kmem_probe()` must only abort on `request_mem_region()` or `add_memory_driver_managed()` failure when `mapped == 0`, continuing the loop if `mapped > 0`. [F90]
- In `dax_kmem_range()`, inward alignment of an inclusive `struct range` to `memory_block_size_bytes()` must round `range->start` up with `ALIGN()` and compute `r->end` as `ALIGN_DOWN(range->end + 1, memory_block_size_bytes()) - 1`, returning `-ENOSPC` if `r->start >= r->end`. [F97]

## Synchronization

- Whenever both `dax_region_rwsem` and `dax_dev_rwsem` are acquired, `dax_region_rwsem` must be acquired before `dax_dev_rwsem` (including via `get_dax_range()`, `dax_region_avail_size()`, or `unregister_dev_dax()` -> `put_device()` -> `dev_dax_release()` -> `free_dev_dax_id()`). [F122]
- Mutations to `dax_region->res` and `dev_dax->ranges` (`alloc_dev_dax_range()`, `adjust_dev_dax_range()`, `trim_dev_dax_range()`, `devm_register_dax_mapping()`) require `dax_region_rwsem` held for write, while `dax_region_avail_size()`, `seed_show()`, and `create_show()` require `dax_region_rwsem`. Kernel-initiated lifecycle paths (`devm_create_dev_dax()`, `unregister_dev_dax()`) must use uninterruptible `down_write(&dax_region_rwsem)`, never `_killable` or `_interruptible`. [F23, F121]
- `get_dax_range(dev)` returns a non-NULL `struct dev_dax_range *` with `dax_region_rwsem` held for write and unlocks `dax_region_rwsem` itself when returning `NULL`; callers must call `put_dax_range()` if and only if `get_dax_range()` returned non-NULL. [F6]
- Callers of `dev_dax_size()` must hold `dax_dev_rwsem`—in read mode (`down_read_interruptible()`) for read-only inspection (`size_show()`, `dax_bus_probe()`) and in write mode when modifying `dev_dax` state (`size_store()`, `delete_store()`). `__free_dev_dax_id()` also requires `dax_dev_rwsem` held for write. [F24]
- In `delete_store()`, `device_lock(dev)` and `device_lock(victim)` must be held while checking `victim->driver` and `dev_dax_size(dev_dax)` and invalidating `dev_dax->id` under `dax_dev_rwsem`, and both `dax_dev_rwsem` and `device_lock(victim)` must be released before calling `devm_release_action(dev, unregister_dev_dax, victim)`. [F26]
- Every call to `dax_alive()`—including via `dax_direct_access()`, `dax_zero_page_range()`, `dax_copy_from_iter()`, `dax_copy_to_iter()`, and `check_vma()`—must run inside `dax_read_lock()` / `dax_read_unlock()` (`dax_srcu`). Because `dax_mmap()` drops `dax_read_lock()` after `check_vma()`, every fault path (`__dev_dax_pte_fault()`, `__dev_dax_pmd_fault()`, `__dev_dax_pud_fault()`) must re-run `check_vma()` under `dax_read_lock()` before mapping pages. [F15, F19]
- In `fs_dax_get_by_bdev()`, looking up `dax_dev` in `dax_hosts`, checking `dax_alive(dax_dev)`, pinning the inode with `igrab(&dax_dev->inode)`, and claiming `dax_dev->holder_data` via `cmpxchg(&dax_dev->holder_data, NULL, holder)` before setting `dax_dev->holder_ops` must all execute inside `dax_read_lock()` / `dax_read_unlock()`. [F130]
- Accesses and updates to `dax_drv->ids` (`__dax_match_id()`, `dax_match_id()`, `do_id_store()`, `dax_driver_unregister()`) must hold `dax_bus_lock` (using `list_for_each_entry_safe()` when unlinking/freeing in `dax_driver_unregister()`), and `dax_bus_lock` must be released before calling `driver_attach()` or `driver_unregister()`. [F28, F88]

## Object Lifetimes

- `kill_dax()` must be called on a `struct dax_device` to clear `DAXDEV_ALIVE` and synchronize `dax_srcu` before the final reference is dropped via `put_dax()`. In `__devm_create_dev_dax()`, `kill_dax(dax_dev)` must be called before `device_add(&dev_dax->dev)` so unbound devices remain dead; `dev_dax_probe()` must call `run_dax(dax_dev)` only after `devm_memremap_pages()` and `cdev_add()` succeed and register `dev_dax_kill` after `dev_dax_cdev_del`. [F5, F111]
- `kill_dev_dax()` must call `kill_dax(dax_dev)` before `unmap_mapping_range(inode->i_mapping, 0, 0, 1)`. Dynamic `dev_dax` devices (`!static_dev_dax(dev_dax)`) require `data->id < 0` and `data->pgmap == NULL` on creation, and `kill_dev_dax()` must reset `dev_dax->pgmap = NULL`. Static devices (`IORESOURCE_DAX_STATIC`) require `data->id >= 0`, duplicate `data->pgmap` via `kmemdup(..., sizeof(struct dev_pagemap), GFP_KERNEL)` (limiting `dev_dax_probe()` to `nr_range <= 1`), and free `dev_dax->pgmap` in `dev_dax_release()`. [F21, F102, F113, F148]
- In `__devm_create_dev_dax()`, `dev_dax->dax_dev` and `dev->type = &dev_dax_type` must be set before `device_add(dev)`, and any failure at or after `device_add(dev)` must clean up via `kill_dev_dax(dev_dax)` and `put_device(dev)` (or `unregister_dev_dax`) rather than jumping to pre-registration `err_*` labels. `alloc_dev_dax_range()` must skip `devm_register_dax_mapping()` when `!device_is_registered(&dev_dax->dev)`, deferring initial mapping registration until after `device_add()` and `devm_add_action_or_reset(dax_region->dev, unregister_dev_dax, dev)` succeed. [F14, F110]
- Devres actions for `unregister_dev_dax` and `unregister_dax_mapping` must be registered on `dax_region->dev` (never `&dev_dax->dev`) and released against `dax_region->dev` in `delete_store()` and `dev_dax_shrink()`. `unregister_dev_dax()` must call `device_del(dev)` to unbind endpoint drivers before calling `free_dev_dax_ranges(dev_dax)`. [F3, F114]
- In `devm_register_dax_mapping()`, `dev->parent` (`&dev_dax->dev`) must be pinned with `get_device(dev->parent)` before `device_add()`, and `dax_mapping_release()` must call `put_device(parent)` only after `ida_free(&dev_dax->ida, mapping->id)`. `struct dax_mapping` must reference its range via integer `mapping->range_id` resolved under `dax_region_rwsem` in `get_dax_range()`, never a cached `struct dev_dax_range *`, because `alloc_dev_dax_range()` reallocates `dev_dax->ranges` with `krealloc()`. [F1, F104]
- In `dev_dax_kmem_probe()` and `dev_dax_kmem_remove()`, each `struct resource` from `request_mem_region()` has `IORESOURCE_BUSY` cleared (`res->flags = IORESOURCE_SYSTEM_RAM` before `add_memory_driver_managed()`) and must be freed via `remove_resource(res)` + `kfree(res)` + `data->res[i] = NULL`, never `release_mem_region()`. If `remove_memory()` fails for any range (or `!CONFIG_MEMORY_HOTREMOVE`), `any_hotremove_failed` must be set to `true` and the failed `data->res[i]`, `data->res_name`, `data->mgid`, node `memory_dev_type`, and `kmem_name` must not be freed or unregistered. [F7, F42, F60]
- In `alloc_dax_region()`, `dev_get_drvdata(parent)` must be `NULL` on entry (and `range->start` and `range_len(range)` aligned to `align`), and `dev_set_drvdata(parent, dax_region)` must be set before `sysfs_create_groups()` registers `dax_region_attribute_groups`; `dax_region_unregister()` must remove those sysfs groups before dropping the `dax_region` reference. [F32, F109]
- In `dax_fs_exit()`, `rcu_barrier()` must be called after `kern_unmount(dax_mnt)` and before `kmem_cache_destroy(dax_cache)` so all RCU-deferred `dax_free_inode()` callbacks finish returning objects to `dax_cache`. [F13]

## API Contracts

- `__dev_dax_pmd_fault()`, `__dev_dax_pud_fault()`, and `dax_set_mapping()` must compute the page offset via `linear_page_index(vmf->vma, ALIGN_DOWN(vmf->address, fault_size))` (and pass `vmf` to `vmf_insert_folio_pmd()`/`pud()`) rather than using `vmf->pgoff`. When `fault_size > dev_dax->align` (or `!CONFIG_HAVE_ARCH_TRANSPARENT_HUGEPAGE_PUD` in `__dev_dax_pud_fault()`), they must return `VM_FAULT_FALLBACK`, whereas `fault_size < dev_dax->align` must return `VM_FAULT_SIGBUS`. [F47, F85]
- `alloc_dax()` returns an `ERR_PTR()` on failure—rejecting non-NULL `ops` with `ERR_PTR(-EOPNOTSUPP)` when `cpu_dcache_is_aliasing()` is true and `ERR_PTR(-EINVAL)` when `!ops->zero_page_range`, while allowing `ops == NULL` for `device-dax`—whereas `kill_dax()` and `put_dax()` only guard against `NULL`; callers must check `IS_ERR()` before storing the result or passing it to `kill_dax()`/`put_dax()`. Similarly, `alloc_dax_region()` returns `NULL` on failure while `devm_create_dev_dax()` returns an `ERR_PTR()`. [F30, F31, F117]
- `dax_direct_access()` requires a signed `long` variable for its return value and converts `0` available pages from `dax_dev->ops->direct_access()` to `-ERANGE`, returning either a negative errno or a positive page count capped to `nr_pages`. [F36]
- `dax_copy_from_iter()` must use `_copy_from_iter_flushcache()` when `DAXDEV_NOCACHE` is set, `dax_copy_to_iter()` must use `_copy_mc_to_iter()` when `DAXDEV_NOMC` is set, and `dax_flush()` must call `arch_wb_cache_pmem()` when `dax_write_cache_enabled(dax_dev)` is true. Composite or stacked DAX drivers must query underlying devices with `dax_write_cache_enabled()` and propagate `DAXDEV_WRITE_CACHE` via `dax_write_cache()`. [F64, F133]
- Public character-device inodes (such as in `dax_open()`) must be converted to `struct dax_device *` via `inode_dax()` (`container_of(inode->i_cdev, struct dax_device, cdev)`), whereas `to_dax_dev()` (`container_of(inode, struct dax_device, inode)`) must only be used on internal `dax_fs_type` inodes. [F105]
- `dax_bus_probe()` must reject `dev_dax` devices where `dev_dax_size(dev_dax) == 0` or `dev_dax->id < 0` with `-ENXIO`, and `delete_store()` must reject deleting static devices, driver-bound devices, non-zero-sized devices, or device ID 0 (`dev_dax->id <= 0`). In `struct dax_device_driver`, `probe` is mandatory (`__dax_driver_register()`), whereas `remove` is optional and must be NULL-checked in `dax_bus_remove()`. [F38, F118]

## Error Handling

- `dax_pgoff_to_phys()` returns `(phys_addr_t)-1` on failure, so callers must check `phys == -1` (never `!phys` or `phys < 0` on the unsigned type) before passing `phys` to `PHYS_PFN()`. [F35]
- `dax_alloc_inode()` must NULL-check `alloc_inode_sb()` and initialize `inode->i_rdev = 0`, and `dax_free_inode()` must check `if (inode->i_rdev)` before freeing `iminor(inode)` from `dax_minor_ida`. [F40]

## Known Pitfalls

- `dev_dax_resize()` and `dev_dax_shrink()` guard against `resource_size_t` unsigned underflow by checking `size < dev_size` before computing `to_shrink = dev_dax_size(dev_dax) - size`, and clamping each reverse-loop step with `shrink = min_t(u64, to_shrink, range_len(range))` using a signed loop index `int i`. [F74]
- When `dev_dax_resize()` calculates free space in `dax_region->res`, the gap between sibling resources `res` and `next` is `next->start - (res->end + 1)` starting at `res->end + 1`, whereas the tail gap at the end of `region_res` is `region_res->end - res->end` because both `.end` fields are inclusive. [F99]
- In `dev_dax_probe()`, dynamic `dev_pagemap` allocation uses `struct_size(pgmap, ranges, dev_dax->nr_range - 1)` because `struct dev_pagemap` unions `range` with `ranges[]` (requiring `nr_range >= 1`), whereas `dev_dax_kmem_probe()` must pass `dev_dax->nr_range` to `struct_size(data, res, ...)`. [F75]
- In `size_store()` and `align_store()`, `!dax_region->dev->driver` must be checked under `dax_region_rwsem` (returning `-ENXIO` if the parent region is disabled), whereas `dev->driver` must be checked under `dax_dev_rwsem` (returning `-EBUSY` if the child `dev_dax` is bound). [F94]
