# TEGRA XUSB PADCTL DRIVER

This component implements the NVIDIA Tegra XUSB Pad Controller (`padctl`) driver for Tegra124, Tegra210, Tegra186, Tegra194, and Tegra234 SoCs. It manages the physical pads, lanes, and ports shared across USB 2.0 (UTMI, ULPI, HSIC), USB 3.0 SuperSpeed, PCIe, and SATA controllers, exposing generic Linux PHY providers, USB role switches, and Tegra-specific power, sleepwalk, and wake control APIs.

## Architecture & Data Flow

- `padctl->ports` is a single list containing all four port subclasses; code iterating it directly must match the port type (e.g., via `tegra_xusb_find_port()` or `port->ops`) before downcasting with `to_usb2_port()`, `to_ulpi_port()`, `to_hsic_port()`, or `to_usb3_port()`. [F84]
- In `tegra_xusb_setup_ports()`, all USB3 ports must be added via `tegra_xusb_add_usb3_port()` before the `padctl->soc->need_fake_usb3_port` loop calls `tegra_xusb_update_usb3_fake_port()` (which searches `padctl->ports` via `tegra_xusb_find_usb3_port()`), and `tegra210_usb2_phy_power_on/off()` must check `port->usb3_port_fake != -1` before passing it to `XUSB_PADCTL_SS_PORT_MAP` or `XUSB_PADCTL_ELPG_PROGRAM1` macros. [F38, F72]
- `padctl->pcie`, `padctl->sata`, `padctl->usb2`, `padctl->ulpi`, and `padctl->hsic` remain `NULL` when their DT pad node is disabled; `tegra210_uphy_init/deinit()` must check `padctl->pcie` and `padctl->sata` before calling `tegra210_pex/sata_uphy_enable/disable()`. [F32]
- On Tegra210 resume (`tegra210_xusb_padctl_resume_noirq()`), `tegra210_xusb_padctl_restore()` must execute before `tegra210_uphy_init()`, because `tegra210_xusb_padctl_save()` snapshots `XUSB_PADCTL_USB3_PAD_MUX` during `tegra210_xusb_padctl_suspend_noirq()` after `tegra210_uphy_deinit()` clears the PCIe and SATA `IDDQ_DISABLE` bits; writes to lane mux registers in `tegra_xusb_lane_program()` and `tegra210_xusb_padctl_restore()` must also be bracketed by `iddq_enable` and `iddq_disable`. [F47, F97]
- Each `struct tegra_xusb_lane_soc` entry at index `i` must be named `"<pad_type>-<i>"` (`"%s-%u"`) for `tegra_xusb_find_lane()`, the order of names in `tegra*_*_functions` must match hardware mux bitfields written by `tegra_xusb_lane_program()`, and every `struct tegra_xusb_lane_map` table must end with `{ 0, NULL, 0 }` (with unique `(type, index)` pairs in `tegra210_usb3_map`). [F51, F53, F64, F85]
- On Tegra210, USB3 SuperSpeed lanes are hosted by both `tegra210_pcie_pad` and `tegra210_sata_pad`; any USB3 lane or PHY callback changes must be updated in lockstep across `tegra210_pcie_lane_ops`/`tegra210_pcie_phy_ops` and `tegra210_sata_lane_ops`/`tegra210_sata_phy_ops`. [F52]
- On SoCs using `xusb-tegra186.c`, the `usb2` pad's `num_lanes` must not exceed `soc->ports.usb2.count` or `TEGRA_UTMI_PAD_MAX` (4), because `lane->index` indexes both `priv->calib.hs_curr_level` and `priv->utmi_pad_enabled`; in `tegra186_utmi_phy_power_on()`, `priv->calib.hs_curr_level[index] + usb2->hs_curr_level_offset` must be computed in a signed `int` and clamped to `[0, 0x3f]`. [F61, F76]
- In `tegra186_utmi_bias_pad_power_on/off()`, clearing `CYA_TRK_CODE_UPDATE_ON_IDLE` is gated on `padctl->soc->trk_update_on_idle` independently of `trk_hw_mode`, and `priv->usb2_trk_clk` must be disabled at the end of `power_on` when `!trk_hw_mode` or in `power_off` when `trk_hw_mode`. [F92]

## Synchronization

- `tegra_xusb_usb_phy_work` (`port->usb_phy_work`) and `tegra_xusb_role_sw_set()` must never acquire `padctl->lock`, and `tegra_xusb_role_sw_set()` must not call `usb_role_switch_get_role()` or `flush_work(&port->usb_phy_work)`. Broken by: locking `padctl->lock` in `tegra_xusb_usb_phy_work` (deadlocks with `cancel_work_sync()` under `padctl->lock` in `tegra_xusb_port_unregister()`) or in `tegra_xusb_role_sw_set()` (lock inversion with `usb_role_switch` lock held by `tegra_xusb_parse_usb_role_default_mode()` under `padctl->lock`). [F106, F107]
- `tegra186_xusb_padctl_vbus_override()`, `tegra210_xusb_padctl_vbus_override()`, and `tegra210_utmi_port_reset()` must not acquire `padctl->lock` or sleep (`usleep_range`, `GFP_KERNEL`), because `*_phy_set_mode()` calls `*_vbus_override()` under `padctl->lock`, `tegra_phy_xusb_utmi_port_reset()` is called under a spinlock, and `port->usb_phy.notifier` callbacks invoked by `tegra_xusb_usb_phy_work()` run in an RCU read-side critical section. [F105, F108]
- In `xusb-tegra186.c`, `tegra186_utmi_pad_power_on()` and `tegra186_utmi_pad_power_down()` must hold `padctl->lock` continuously across checking `priv->utmi_pad_enabled`, calling `tegra186_utmi_bias_pad_power_on/off()` (which tests `bitmap_empty(priv->utmi_pad_enabled)` and requires `padctl->lock` held), and updating the lane's bit (`set_bit()` after `bias_pad_power_on()`, `clear_bit()` before `bias_pad_power_off()`); callers (`tegra186_utmi_phy_power_on/off()`) must not hold `padctl->lock`. [F22, F104]
- In `xusb-tegra210.c`, `tegra210_pex/sata_uphy_enable()`, `tegra210_pex/sata_uphy_disable()`, `tegra210_uphy_init/deinit()`, and `tegra210_usb3_phy_power_on/off()` must be called with `padctl->lock` held and must not acquire it internally; on failure after `clk_prepare_enable()` or `reset_control_deassert()`, `tegra210_pex/sata_uphy_enable()` must roll back via `reset_control_assert()` and `clk_disable_unprepare()` without setting `enable = true`. [F13, F102, F103]

## Object Lifetimes

- `tegra_xusb_padctl_get()` returns a `struct tegra_xusb_padctl *` with an elevated reference on `padctl->dev` from `of_find_device_by_node()` (releasing the phandle `device_node` via `of_node_put()` on all paths) that callers must release via `tegra_xusb_padctl_put()`, `tegra210_xusb_padctl_probe()` must release both `np` and `&pdev->dev` from `"nvidia,pmc"` on all returns, and `tegra_xusb_find_pad/phy/port_node()` must use `of_get_child_by_name()` and `of_node_put()` the container node. [F1, F10, F91]
- `tegra_xusb_padctl_probe()` initializes resources in the order `reset_control_deassert()`, `regulator_bulk_enable()`, `tegra_xusb_setup_pads()`, and `tegra_xusb_setup_ports()`; both its error path and `tegra_xusb_padctl_remove()` must tear them down in reverse order (ports before pads), and `__tegra_xusb_remove_pads()` / `__tegra_xusb_remove_ports()` must iterate with `list_for_each_entry_safe_reverse` because unregistering frees each entry via its device `.release` callback. [F3, F63]
- Once `tegra_xusb_pad_init()` succeeds, ownership of the `kzalloc`-allocated pad subclass is bound to `pad->dev` (freed in `tegra_xusb_pad_release()` via `pad->soc->ops->remove(pad)`), so any subsequent error path in a pad `->probe()` callback must call `device_unregister(&pad->dev)` without calling `kfree()`. [F4]
- In `tegra_xusb_pad_register()`, every enabled lane's `struct phy` must be created, probed, added to `pad->padctl->lanes`, and bound via `phy_set_drvdata()` before `of_phy_provider_register_full()` publishes the pad to `tegra_xusb_pad_of_xlate()`; conversely, `tegra_xusb_pad_unregister()` must call `of_phy_provider_unregister(pad->provider)` before `tegra_xusb_lane_destroy()`, which must run before `device_unregister(&pad->dev)` frees `pad`. [F15, F19]
- In `tegra_xusb_setup_usb_role_switch()`, `INIT_WORK(&port->usb_phy_work, ...)` and `usb_role_switch_set_drvdata()` must run before `usb_add_phy_dev()`, `of_platform_populate()`, or `tegra_xusb_parse_usb_role_default_mode()`; in `tegra_xusb_port_unregister()`, when `!IS_ERR_OR_NULL(port->usb_role_sw)`, teardown must run `of_platform_depopulate()` and `usb_role_switch_unregister()`, then `cancel_work_sync(&port->usb_phy_work)`, then `usb_remove_phy()`, and then `port->usb_phy.dev->driver = NULL` before `device_unregister(&port->dev)`. [F8, F9, F16, F34]
- When an OTG USB2 port transitions to `USB_ROLE_NONE`, `port->supply` is only enabled if the port was in `USB_ROLE_HOST`, so `regulator_disable(port->supply)` must be guarded by `id_override == ID_OVERRIDE_GROUNDED` in `tegra186_xusb_padctl_id_override()` and by `regulator_is_enabled(port->supply)` in `tegra210_usb2_phy_set_mode()`. [F12]

## API Contracts

- `tegra_xusb_find_lane()`, `tegra_xusb_port_find_lane()`, and `tegra_xusb_port_ops.map` return an `ERR_PTR` and never `NULL` (check `IS_ERR()`), whereas `tegra_xusb_find_port()`, `tegra_xusb_find_usb2/3_port()`, and `tegra210_lane_to_usb3_port()` return `NULL` and never an `ERR_PTR` (check `!port`), and `tegra_xusb_pad_create()` returns `NULL` for disabled DT nodes, `ERR_PTR(err)` on failure, or a valid pointer; lookup helpers return borrowed pointers that callers must not `kfree()` or `put_device()`. [F14, F25, F26, F27]
- `tegra_xusb_find_unused_usb3_port()`, `tegra210_usb3_lane_map()`, `tegra_xusb_padctl_get_usb3_companion()`, and `tegra_xusb_padctl_get_port_number()` return a non-negative 0-based index or a negative errno (`-ENODEV` or `-EINVAL`); callers must store the result in a signed `int` and check `< 0` before indexing. [F29]
- `tegra_xusb_find_lane()` and `tegra_xusb_find_port_node()` use `kasprintf(GFP_KERNEL, ...)`, and `tegra_xusb_padctl_enable/disable_phy_sleepwalk()` and `tegra_xusb_padctl_enable/disable_phy_wake()` lock `padctl->lock` and call `usleep_range()`; all of them and their callers (`tegra_xusb_find_port()`, `tegra_xusb_find_usb2/3_port()`, `tegra_xusb_padctl_get_usb3_companion()`, `tegra_xusb_padctl_usb3_save_context()`, `tegra_phy_xusb_utmi_pad_power_on()`) require sleepable process context (and `padctl->lock` not held for sleepwalk/wake). [F109, F110]
- Every `struct tegra_xusb_pad_ops.probe` implementation must call `dev_set_drvdata(&pad->dev, pad)` with the base `struct tegra_xusb_pad *` for `tegra_xusb_pad_of_xlate()`, and `tegra_xusb_pad_register()` binds each `struct phy` via `phy_set_drvdata(pad->lanes[i], lane)` because all `phy_ops` callbacks and exported `struct phy *` APIs require `phy_get_drvdata(phy)` to return a `struct tegra_xusb_lane *`. [F79, F112]
- On Tegra210, PCIe and SATA lanes can be muxed to PCIe, SATA, or `"usb3-ss"`; `tegra210_pcie_phy_power_on/off()` and `tegra210_sata_phy_power_on/off()` must check `tegra_xusb_lane_check(lane, "usb3-ss")` before calling `tegra210_usb3_phy_power_on/off(phy)`. [F35]
- In `struct tegra_xusb_lane_soc`, `mask` is an unshifted bitmask width and `shift` is the bit offset (`~(soc->mask << soc->shift)` in `tegra_xusb_lane_program()`), whereas in `padctl_readl_poll(padctl, offset, val, mask, us)` both `val` and `mask` must be pre-shifted register bitmasks tested as `(regval & mask) == val`. [F39]

## Error Handling

- `pad->lanes` is a sparse array where disabled/absent DT lanes are `NULL`; in `tegra_xusb_pad_register()`, a failed `phy_create()` leaves an `ERR_PTR` in `pad->lanes[i]`, and if `pad->ops->probe(pad, np, i)` fails after `phy_create()` succeeds, `phy_destroy(pad->lanes[i])` must be called before jumping to `remove:`, which only unwinds indices `< i` (`while (i--)` where `phy_set_drvdata()` was set); all `pad->lanes` readers (`tegra_xusb_pad_of_xlate()`, `tegra_xusb_pad_program()`) must check for `NULL`. [F5, F31]
- In `tegra_xusb_port_init()`, once `device_initialize(&port->dev)` has been called, any error before or during `device_add(&port->dev)` must release the device via `put_device(&port->dev)` rather than `device_unregister(&port->dev)`, whereas in `tegra_xusb_add_usb2_port()` and `tegra_xusb_add_ulpi_port()`, any failure in `ops->map()` or `*_port_parse_dt()` after `tegra_xusb_port_init()` succeeds must call `tegra_xusb_port_unregister()` before `of_node_put(np)`. [F6, F7]
- `tegra_xusb_padctl_get()` relies on `platform_get_drvdata(pdev)` being `NULL` to detect an unprobed controller and return `ERR_PTR(-EPROBE_DEFER)` (so `tegra_xusb_padctl_probe()` must reset `platform_set_drvdata(pdev, NULL)` on its `remove:` failure path), and in `struct tegra210_xusb_padctl`, `priv->regmap` is optional (`NULL` when the PMC regmap is absent), so all Tegra210 PMC sleepwalk functions must check `if (!priv->regmap) return -EOPNOTSUPP;` before `padctl_pmc_readl/writel()`. [F28, F33]

## External Contracts

- `tegra_xusb_setup_usb_role_switch()` must set `port->usb_phy.dev` to `&lane->pad->lanes[port->index]->dev` and set `port->dev.driver` and `port->usb_phy.dev->driver` to the dummy `devm`-allocated `struct device_driver` (never `port->padctl->dev->driver`, whose PM callbacks expect `dev_get_drvdata(dev)` to be `struct tegra_xusb_padctl *`); for `PHY_MODE_USB_OTG`, `submode` in `tegra186/210_*_phy_set_mode()` is `enum usb_role`, and `tegra_xusb_usb_phy_work()` must call `usb_phy_set_event(&port->usb_phy, to_usb_phy_event(role))` before `atomic_notifier_call_chain()`. [F78, F113, F115, F116]

## Known Pitfalls

- Although `struct tegra_xusb_usb2_pad` and `struct tegra_xusb_usb3_pad` declare a `struct mutex lock` member in `xusb.h`, only `tegra124_usb2_pad_probe()` calls `mutex_init(&usb2->lock)`; Tegra210 and Tegra186 pad drivers never initialize `pad->lock` and must serialize pad state with `padctl->lock` instead. [F21]
- Every read-modify-write of `XUSB_PADCTL_ELPG_PROGRAM` (on Tegra186/194/234) and `XUSB_PADCTL_ELPG_PROGRAM_0` (on Tegra210) must hold `padctl->lock` and mask out `ALL_WAKE_EVENTS` from the read value before setting or clearing wake interrupt enable or wakeup event bits, to avoid inadvertently clearing pending write-1-to-clear wake events. [F96]
- When grounding `ID_OVERRIDE` in `tegra186_xusb_padctl_id_override()` or `tegra210_xusb_padctl_id_override()` while `VBUS_OVERRIDE` is set in `USB2_VBUS_ID`, `VBUS_OVERRIDE` must be cleared and written first, followed by a 1-2 ms delay and a fresh register read before setting `ID_OVERRIDE_GROUNDED`. [F44]
- On Tegra210, `tegra210_usb3_phy_power_on/off()` and `tegra210_usb3_*_phy_sleepwalk/wake()` run on `pcie` or `sata` lanes and must map `lane` via `tegra210_usb3_lane_map()` or `tegra210_lane_to_usb3_port()` before indexing USB3 port registers, whereas in `tegra124_usb3_save_context()`, `tegra124_usb3_port_enable()`, and `tegra210_usb3_set_lfps_detect()`, per-lane `IOPHY/UPHY_MISC_PAD_PX_CTL*` macros must use `lane->index` when `lane->pad == padctl->pcie` (and `S0` otherwise), never the USB3 port `index`. [F57, F58]
- In `xusb-tegra210.c`, PMC UTMIP sleepwalk register offsets and bit shifts for `port` (0..3) must be computed through the `UTMIP(_port, _offset1, _offset2)` macros rather than linear `port` arithmetic, because ports 0..2 share registers with UHSIC in the 4th slot while port 3 uses separate extension registers and bit positions. [F59]
- `tegra186_usb3_pad_remove()` currently downcasts `pad` with `to_usb2_pad(pad)` even though `tegra186_usb3_pad_probe()` allocates a `struct tegra_xusb_usb3_pad`; it must not dereference `struct tegra_xusb_usb2_pad`-specific fields (such as `clk`) without first changing the downcast to `to_usb3_pad(pad)`. [F82]
