# FREESCALE QUICC ENGINE UCC ETHERNET DRIVER

This component is the Linux Ethernet network device driver for the Freescale QUICC Engine (QE) Universal Communications Controller (UCC) in Gigabit Ethernet mode (`ucc_geth`). It manages QE parameter RAM (MURAM), SNUMs, buffer descriptor (BD) rings, DMA packet buffers, MAC/UCC registers, NAPI polling, phylink integration, and ethtool operations.

## Architecture & Data Flow
- `ugeth->ug_regs`, `ugeth->uccf`, `ugeth->p_tx_fw_statistics_pram`, and `ugeth->p_rx_fw_statistics_pram` are allocated/mapped only in `ucc_geth_init_mac` and nulled in `ucc_geth_memclean`. Callbacks reachable while the interface is down (`ucc_geth_set_mac_addr`, `uec_get_ethtool_stats`) must check `netif_running(dev)` or NULL-check these pointers even when `ug_info->statisticsMode` enables them. [F33, F47]
- `ugeth->p_scheduler` and `ugeth->p_cpucount` are only allocated in `ucc_geth_startup` when `ucc_geth_tx_queues(ug_info) > 1`; callers (`ucc_geth_start_xmit`, `dump_regs`) must check `if (ugeth->p_scheduler)` before accessing `p_scheduler` or `p_cpucount[txQ]`. [F34]
- `ug_info->bdRingLenRx` (>= 8) and `ug_info->bdRingLenTx` (>= 2) must be powers of two and must not be modified while `netif_running(netdev)` is true (enforced in `uec_set_ringparam`), because rings are allocated only in `ucc_geth_startup` and `TX_RING_MOD_MASK`/`RX_RING_MOD_MASK` wrap SKB indices with `& (size - 1)` while hardware wraps `txBd`/`confBd`/`rxBd` via `T_W`/`R_W` at `size - 1`. [F40, F51]
- `ucc_geth_alloc_tx` and `ucc_geth_alloc_rx` mark the end of each BD ring solely by setting `T_W` or `R_W` on descriptor `bdRingLen - 1`; any code rewriting a BD status word (`get_new_skb`, `ucc_geth_start_xmit`) must preserve the existing `T_W` or `R_W` bit. [F52]
- `ucc_geth` accesses `struct qe_bd` status and length as a combined big-endian `u32` at `(u32 __iomem *)bd` using 32-bit status flags in `0xffff0000` and `BD_LENGTH_MASK` (`0x0000ffff`); `ucc_geth_rx` must subtract the 4-byte FCS (`(bd_status & BD_LENGTH_MASK) - 4`) before `skb_put`. [F62]
- In `ucc_geth_tx`, the `(bd_status & T_R) == 0` loop must check `if (!skb) break;` on `ugeth->tx_skbuff[txQ][ugeth->skb_dirtytx[txQ]]` before advancing `skb_dirtytx` and `confBd`, because unused TX BDs also have `T_R` cleared. [F66]
- `ugeth_enable` only issues `QE_RESTART_TX` and `QE_RESTART_RX` when `!uccf->enabled_tx && uccf->stopped_tx` or `!uccf->enabled_rx && uccf->stopped_rx`; any path calling `ucc_fast_enable` after `ugeth_disable` (such as Magic Packet WoL in `ucc_geth_suspend`) must call `ucc_fast_disable` before `ugeth_enable`. [F44]
- In `ucc_geth_startup`, QE MURAM pointer fields (`tqptr`, `sqptr`, `rqptr`, `rbdqptr`) must be written with MURAM offsets from `qe_muram_alloc`, whereas external BD ring fields (`sqqd[i].bd_ring_base`, `last_bd_completed_address`, `externalbdbaseptr`) must be written with `virt_to_phys()`. [F116]
- `fill_init_enet_entries` and `ucc_geth_startup` pack SNUM (`ENET_INIT_PARAM_SNUM_MASK`), MURAM offset (`ENET_INIT_PARAM_PTR_MASK = 0x00ffffc0`), and RISC mask (`ENET_INIT_PARAM_RISC_MASK = 0x0000003f`) into one `u32` via bitwise OR, requiring thread and global PRAM MURAM offsets to be at least 64-byte aligned. [F57]
- In `ucc_geth_startup`, the MURAM allocation for `ugeth->rx_bd_qs_tbl_offset` (`ugeth->p_rx_bd_qs_tbl`) must allocate `sizeof(struct ucc_geth_rx_bd_queues_entry) + sizeof(struct ucc_geth_rx_prefetched_bds)` per RX queue rather than only `sizeof(*ugeth->p_rx_bd_qs_tbl)`. [F83]
- `ucc_geth_alloc_tx` and `ucc_geth_alloc_rx` must round BD ring byte lengths up to hardware alignment (`UCC_GETH_TX_BD_RING_ALIGNMENT` / `UCC_GETH_RX_BD_RING_ALIGNMENT`) and `roundup_pow_of_two` before `kmalloc` (zeroing trailing `alloc - length` bytes in `ucc_geth_alloc_tx`), while `get_new_skb` and `ucc_geth_free_rx` must allocate/unmap RX SKBs with `max_rx_buf_length + UCC_GETH_RX_DATA_BUF_ALIGNMENT` (64-byte aligned via `skb_reserve` before `dma_map_single`). [F114, F115]
- `ucc_struct_init` requires every entry in `ug_info->l2qt` and `ug_info->l3qt` to be `< ucc_geth_rx_queues(ug_info)`, and `ucc_geth_startup` packs them as 4-bit nibbles (`<< (28 - 4 * i)`) into `p_rx_glbl_pram`, encodes queue counts in `temoder`/`remoder` as `num_queues - 1`, and writes `UCC_BMR_BO_BE | UCC_BMR_GBL` into the high byte (`<< 24`) of `p_tx_glbl_pram->tstate` (`out_be32`) and into `p_rx_glbl_pram->rstate` (`out_8`). [F59, F118]

## Synchronization
- All accesses to TX ring state (`txBd`, `confBd`, `tx_skbuff`, `skb_curtx`, `skb_dirtytx`, `cpucount`) and TX queue stop/wake transitions during active operation must be serialized under `ugeth->lock`. Because `ucc_geth_poll` takes `spin_lock(&ugeth->lock)` in NAPI softirq without disabling hardirqs, `ucc_geth_irq_handler` must never acquire `ugeth->lock`, and non-NAPI callers (`ucc_geth_start_xmit`, `ucc_geth_set_mac_addr`) must disable interrupts/BH when taking it. [F16, F25, F108]
- `ugeth_disable`, `ugeth_graceful_stop_tx`, and `ugeth_graceful_stop_rx` call `msleep(10)` while polling for stop completion and must never be called under `ugeth->lock` or in atomic context; callers like `ugeth_mac_link_up` must use `ugeth_quiesce` and `ugeth_activate` instead, and `ucc_geth_timeout` (`ndo_tx_timeout`) must defer controller reset to process context via `ugeth->timeout_work` (`ucc_geth_timeout_work`). [F106, F107]
- `ucc_geth_timeout_work` must never acquire `rtnl_lock()` because `ucc_geth_close` (`ndo_stop`, called under `rtnl_lock()`) synchronously flushes `ugeth->timeout_work` via `cancel_work_sync(&ugeth->timeout_work)`. [F112]
- In `ucc_geth_suspend()` and `ucc_geth_resume()`, all work must be skipped when `!netif_running(ndev)`, and calls to `phylink_suspend()` and `phylink_resume()` must be serialized under `rtnl_lock()`. [F103]
- In `ucc_geth_start_xmit` and `get_new_skb`, the DMA buffer address must be written to `bd->buf` via `out_be32` (and `tx_skbuff` recorded in `ucc_geth_start_xmit`) before writing the BD status word containing `T_R` or `R_E` via `out_be32`. [F117]
- `ucc_netpoll` (`ndo_poll_controller`) must wrap its call to `ucc_geth_irq_handler` with `disable_irq` and `enable_irq` on `ugeth->ug_info->uf_info.irq` so the hardirq handler cannot concurrently access `uccf->p_ucce` and `uccf->p_uccm`. [F109]
- In `ucc_geth_open`, `ucc_geth_init_mac(ugeth)` must complete before `request_irq`, `phylink_start`, `napi_enable`, and `netif_start_queue` are called. [F23]

## Object Lifetimes
- In `ucc_geth_close`, `napi_disable(&ugeth->napi)` and `cancel_work_sync(&ugeth->timeout_work)` must execute before `ucc_geth_stop(ugeth)`, and `phylink_disconnect_phy(ugeth->phylink)` must execute after `ucc_geth_stop(ugeth)`. Inside `ucc_geth_stop`, `phylink_stop(ugeth->phylink)` must precede `ugeth_disable`, and all controller register accesses must complete before `ucc_geth_memclean(ugeth)` frees `ugeth->uccf` and unmaps `ugeth->ug_regs`. [F7, F8]
- `ugeth_quiesce` stops TX queues (`netif_tx_stop_all_queues`), disables the IRQ (`disable_irq`), and disables NAPI (`napi_disable`) in that order, and `ugeth_activate` must reverse those operations in LIFO order (`napi_enable`, `enable_irq`, `netif_tx_wake_all_queues`) after re-enabling the controller in `ugeth_mac_link_up`. [F9]
- Every call to `of_phy_find_device(ug_info->tbi_node)` (in `uec_configure_serdes` and `ugeth_mac_config`) increments the reference count on `tbiphy->mdio.dev`; callers must call `put_device(&tbiphy->mdio.dev)` on every exit path where `tbiphy` is non-NULL, including the early return when `TBISR_LSTATUS` is set. [F11]
- In `ucc_geth_probe()` and `ucc_geth_remove()`, while `ug_info` and `dev` are managed by devres, `ugeth->phylink` and `ug_info->tbi_node` are unmanaged and must be explicitly released via `phylink_destroy()` and `of_node_put()` on probe failure after acquisition and in `ucc_geth_remove()`. [F94]
- `ucc_geth_startup` frees the MURAM parameter block `init_enet_pram_offset` via `qe_muram_free` immediately after issuing `QE_INIT_TX_RX` with `qe_issue_cmd`, so thread SNUMs and MURAM offsets must be populated in `ugeth->p_init_enet_param_shadow` first and retained there until `ucc_geth_memclean` releases them. [F5]
- Before reinitializing via `ucc_geth_init_mac(ugeth)`, `ucc_geth_resume` (when `!qe_alive_during_sleep()`) and `ucc_geth_timeout_work` must free prior allocations via `ucc_geth_memclean` (or `ucc_geth_stop`), and `ucc_geth_timeout_work` must call `phylink_start(ugeth->phylink)` afterward; `ucc_geth_memclean` must never free or reset `ugeth->ug_info` (cloned from `ugeth_primary_info` in probe). [F12, F13, F46]

## API Contracts
- Mutating `ug_regs->maccfg2` or `uf_regs->upsmr` on a live MAC in `ugeth_mac_link_up`, or clearing the hash table in `ugeth_82xx_filtering_clear_all_addr_in_hash`, requires disabling only the active RX/TX directions via `ugeth_disable(ugeth, comm_dir)` first (and calling `ugeth_quiesce` in `ugeth_mac_link_up`) and restoring those exact directions via `ugeth_enable(ugeth, comm_dir)` on exit. [F15, F48]
- In `ucc_geth_startup`, `init_firmware_statistics_gathering_mode` must be called only after `p_tx_glbl_pram`, `p_rx_glbl_pram`, `p_tx_fw_statistics_pram`, and `p_rx_fw_statistics_pram` are allocated and `temoder`/`remoder` are written to PRAM; similarly, `init_max_rx_buff_len` must write `p_rx_glbl_pram->mrblr` before `init_min_frame_len` reads it to check `min_frame_length >= (mrblr_value - 4)`. [F32, F78]
- When populating or freeing `p_init_enet_param_shadow` in `fill_init_enet_entries` and `return_init_enet_entries`, `rxthread` requires `numThreadsRxNumerical + 1` entries (up to `ENET_INIT_PARAM_MAX_ENTRIES_RX = 9`) with `skip_page_for_first_entry = 1` so entry 0 has no MURAM page, whereas `txthread` uses `numThreadsTxNumerical` entries with `skip_page_for_first_entry = 0`. [F56]
- `ugeth_82xx_filtering_clear_addr_in_paddr` writes `ugeth->indAddrRegUsed[paddr_num] = 0` before calling `hw_clear_addr_in_paddr` (which checks `paddr_num >= NUM_OF_PADDRS`), so callers must pass a 0-based `paddr_num` strictly less than `NUM_OF_PADDRS` (4). [F64]
- `ucc_geth_probe` stores `struct net_device *dev` via `dev_set_drvdata(device, dev)` (used by `ucc_geth_remove`, `ucc_geth_suspend`, `ucc_geth_resume` via `platform_get_drvdata` and `netdev_priv`) and sets `ugeth->phylink_config.dev = &dev->dev` (not `&ofdev->dev`), which `ugeth_mac_link_up`, `ugeth_mac_link_down`, and `ugeth_mac_config` downcast via `to_net_dev(config->dev)`. [F87, F88]
- Byte Queue Limits (BQL) accounting via `netdev_sent_queue` in `ucc_geth_start_xmit` must be balanced by `netdev_completed_queue(dev, howmany, bytes_sent)` in `ucc_geth_tx` on normal completion and by `netdev_reset_queue` in `ucc_geth_open`, `ucc_geth_close`, and `ucc_geth_free_tx` whenever TX rings are initialized or flushed. [F122]
- `ucc_geth_poll` must count only received packets returned by `ucc_geth_rx` (excluding TX completions in `ucc_geth_tx`) toward the NAPI `budget`, and must call `napi_complete_done(napi, howmany)` and re-enable `UCCE_RX_EVENTS | UCCE_TX_EVENTS` in `ugeth->uccf->p_uccm` only when `howmany < budget`. [F123]
- `uec_set_wol` must delegate to `phylink_ethtool_set_wol` first and only fall back to MAC `WAKE_MAGIC` (requiring `qe_alive_during_sleep()` and rejecting `wol->wolopts & ~WAKE_MAGIC`) when the PHY returns `-EOPNOTSUPP`, recording `ugeth->phy_wol_en` so `ucc_geth_suspend` only enables MAC magic-packet wake when `!ugeth->phy_wol_en`. [F128]
- In `ucc_geth_probe`, `PHY_INTERFACE_MODE_SGMII`, `PHY_INTERFACE_MODE_TBI`, and `PHY_INTERFACE_MODE_RTBI` must only be added to `ugeth->phylink_config.supported_interfaces` when `ug_info->tbi_node` (`tbi-handle` in Device Tree) is non-NULL. [F127]

## Error Handling
- `ucc_struct_init` and `ucc_geth_startup` do not roll back earlier allocations when a step fails; instead, their caller `ucc_geth_init_mac` invokes `ucc_geth_stop` (`ucc_geth_memclean`) on failure. Every `qe_muram_alloc` return value in `ucc_geth_startup` must be checked for error before passing the offset to `qe_muram_addr` and storing into `ugeth->p_*`, because `qe_muram_addr` returns a non-NULL address on error that `ucc_geth_memclean` would pass to `qe_muram_free_addr`. [F1, F28]
- In `fill_init_enet_entries`, if `qe_muram_alloc` fails, the SNUM just acquired via `qe_get_snum` for that entry must be released immediately with `qe_put_snum`, whereas entries already written into `p_start` with `risc` set are released later by `return_init_enet_entries`, which must zero each `*p_start` entry as it frees it. [F3]
- In `ucc_geth_probe`, `phylink_create` returns an error pointer (`IS_ERR`/`PTR_ERR`) whereas `of_parse_phandle` and `of_phy_find_device` return `NULL` on failure; `of_get_ethdev_address(np, dev)` only aborts probe on `-EPROBE_DEFER` while other negative codes are non-fatal, so `ucc_geth_probe` must end with `return 0` rather than `return err`. [F38, F39]

## External Contracts
- Device Tree `cell-index` and `device-id` properties are 1-based (`1..8`), which `ucc_geth_probe` converts to a 0-based `ug_info->uf_info.ucc_num = *prop - 1` and validates to be in `0..7` (`< UCC_MAX_NUM`) before calling QE and `ucc_fast` helpers. [F58]
- `uec_get_ethtool_stats` casts `&ugeth->ug_regs->tx64`, `p_tx_fw_statistics_pram`, and `p_rx_fw_statistics_pram` to `u32 __iomem *base` and reads `in_be32(&base[i])`, so `hw_stat_gstrings`, `tx_fw_stat_gstrings`, and `rx_fw_stat_gstrings` (including `"reserved"` entries) must match the 32-bit word layout of those structures. [F60]

## Known Pitfalls
- `enum ucc_geth_num_of_threads` uses a non-linear hardware encoding (`UCC_GETH_NUM_OF_THREADS_4 = 0`, `_1 = 1`, `_2 = 2`, `_6 = 3`, `_8 = 4`) written to `rgftgfrxglobal`, so any code needing the numerical thread count for loop bounds or MURAM sizing must call `ucc_geth_thread_count()`. [F55]
- In `struct ucc_geth_scheduler`, `cpucount0..7` are interleaved in pairs with `cecount0..7` rather than laid out contiguously, so `ucc_geth_start_xmit` must write per-queue packet counts through `ugeth->p_cpucount[txQ]` initialized in `ucc_geth_startup` rather than indexing `&p_scheduler->cpucount0`. [F61]
- In `struct ucc_geth_private`, the buffer descriptor pointers (`p_tx_bd_ring`, `p_rx_bd_ring`, `txBd`, `confBd`, `rxBd`) are declared as `u8 __iomem *` rather than `struct qe_bd __iomem *`, so pointer arithmetic advancing or indexing descriptors in a BD ring must explicitly scale by `sizeof(struct qe_bd)`. [F81]
- `ENET_ADDR_CONT_ENTRY` must never be invoked on a potentially NULL `dequeue()` return value unless the list is known to be non-empty, because `node` is at a non-zero offset in `struct enet_addr_container` and `ENET_ADDR_CONT_ENTRY(NULL)` produces a non-NULL wild pointer that `put_enet_addr_container` passes to `kfree`. [F69]
- In `ucc_geth_rx`, `length = (u16) ((bd_status & BD_LENGTH_MASK) - 4)` is computed before checking `bd_status` and must not be used until after `if (!skb || (!(bd_status & (R_F | R_L))) || (bd_status & R_ERRORS_FATAL))` discards short (`R_SH`) or errored frames; furthermore, if refilling via `get_new_skb(ugeth, bd)` returns NULL, the loop must break immediately without advancing `ugeth->skb_currx[rxQ]` or `bd`. [F67, F79]
- In `ugeth_graceful_stop_tx()` and `ugeth_graceful_stop_rx()`, the completion indicators (`UCC_GETH_UCCE_GRA` in `uccf->p_ucce` via write-1-to-clear, and `GRACEFUL_STOP_ACKNOWLEDGE_RX` in `p_rx_glbl_pram->rxgstpack` via clrbits) must be cleared before issuing `QE_GRACEFUL_STOP_TX`/`RX` and polling with a bounded 10-iteration `msleep(10)` loop. [F101]
