# DRM DRIVERS FOR ROCKCHIP

Implements the Rockchip DRM master driver, GEM/DMA/IOMMU memory management, VOP1 and VOP2 CRTC/plane controllers, and display encoder/bridge subdrivers for DisplayPort (Analogix DP, Cadence DP), MIPI DSI (DesignWare DSI v1/v2), HDMI (DesignWare HDMI/QP, Innosilicon HDMI, RK3066 HDMI), LVDS, and parallel RGB.

## Architecture & Data Flow

- Every Rockchip framebuffer GEM object must be a `struct rockchip_gem_object` (allocated with `size` rounded up via `round_up(size, PAGE_SIZE)` before `drm_gem_object_init()`) because VOP and GEM callbacks downcast via `to_rockchip_obj()`. PRIME-imported buffers are discriminated via `obj->import_attach` (and `private->domain` for IOMMU vs DMA unmapping, with `rockchip_gem_dma_map_sg()` requiring `drm_prime_get_contiguous_size(sg) >= attach->dmabuf->size` when `!private->domain`), whereas internal buffers use `rk_obj->pages != NULL`. [F41, F110, F123, F160]
- For DMA-backed `rockchip_gem_object` buffers (`!rk_obj->pages`) allocated with `alloc_kmap == false`, `rk_obj->kvaddr` holds a non-NULL DMA cookie rather than a virtual address, so `rockchip_gem_prime_vmap()` must check `rk_obj->dma_attrs & DMA_ATTR_NO_KERNEL_MAPPING` before using `rk_obj->kvaddr`. [F40]
- `rockchip_drm_dma_init_device()` sets `private->iommu_dev` to `ERR_PTR(-ENODEV)` if any bound VOP lacks IOMMU mapping; `rockchip_drm_init_iommu()` must check `IS_ERR_OR_NULL(private->iommu_dev)` and reset `private->domain = NULL` if `iommu_paging_domain_alloc()` fails because all downstream IOMMU checks test `private->domain` for non-NULL. [F5, F38]
- `vop_plane_atomic_update()` and `vop_win_disable()` must update `vop->win_enabled` in lockstep with the hardware window `enable` bit under `vop->reg_lock`, while `rockchip_drm_set_win_enabled()` must leave `vop->win_enabled` intact (and skip clock/IOMMU teardown) during Panel Self-Refresh transitions so PSR exit restores only previously enabled windows. [F60, F178]
- After `vop_crtc_gamma_set()` sets `update_gamma_lut` to 1 and polls `vop_lut_buffer_index()` until `lut_idx != old_idx` (with `vop->reg_lock` released during sleeping `readx_poll_timeout()`), it must write `VOP_REG_SET(vop, common, update_gamma_lut, 0)` under `vop->reg_lock` to clear the hardware-auto-cleared bit in `vop->regsbak`. [F59, F157]
- In VOP2, video port and window registers in `vop2_nonvolatile_range` are cached in `vop2->map` (`REGCACHE_MAPLE`) until `vop2_cfg_done()` latches them; `vop2_disable()` and `__vop2_regs_dump()` must call `regcache_drop_region(vop2->map, 0, vop2_regmap_config.max_register)`. On `vop2->version <= VOP_VERSION_RK3588`, `vop2_enable()` must initialize `vop2->old_layer_sel` and `vop2->old_port_sel` by reading `RK3568_OVL_LAYER_SEL` and `RK3568_OVL_PORT_SEL`. [F220, F221]
- In `vop2_create_crtcs()`, `possible_crtcs` bit positions must use the sequential index `nvp` of connected video ports (`vp->crtc.port != NULL`) rather than `vp->id`, `vp->nlayers` must only be assigned for connected ports, and RK3566 quirks (`RK3568_OTP_WIN_EN` and skipping mirror windows via `vop2_is_mirror_win()`) must check `vop2->data->soc_id == 3566` rather than `vop2->version`. [F231, F278]
- For VOP2 cluster windows (`vop2_cluster_window(win)`), `vop2_plane_atomic_update()` and `vop2_win_disable()` must update `VOP2_WIN_CLUSTER_ENABLE` alongside `VOP2_WIN_ENABLE`, and clear `VOP2_WIN_AFBC_ENABLE` and `VOP2_WIN_TRANSFORM_OFFSET` to `0` when `!afbc_en`. In `rockchip_vop2_mod_supported()`, SoC/window restrictions (rejecting `DRM_FORMAT_MOD_LINEAR` on RK3568 cluster windows and non-AFBC `XRGB2101010`/`XBGR2101010` on RK3588) must precede the generic `DRM_FORMAT_MOD_LINEAR` acceptance. [F225, F279]
- In `rk3568_vop2_setup_overlay()` and `rk3576_vop2_setup_overlay()`, `vp->win_mask` and each plane's `win->delay` must be updated before calling `vop2_setup_alpha()` and `rk3568_vop2_setup_dly_for_windows()`. In `vop2_setup_alpha()`, the mixer loop must skip `zpos == 0` and compute the register offset as `(mixer_id + zpos - 1) * 0x10`. [F226, F254]
- On `VOP_VERSION_RK3568` (`!vop2_supports_seamless_gamma_lut_update(vop2)`), `vop2_crtc_atomic_check_gamma()` must reject gamma LUT on a second CRTC via `vop2_gamma_lut_in_use()`, and `vop2_crtc_atomic_set_gamma_rk356x()` must disable `DSP_LUT_EN`, call `vop2_cfg_done()`, and poll `vop2_vp_dsp_lut_poll_disabled()` before writing `vop2->lut_regs` (which is `NULL` if `"gamma-lut"` is absent). [F207, F284]
- VOP2 interrupt registers (`RK3568_VP_INT_EN`/`CLR`, `RK3568_SYS0_INT_EN`/`CLR`, `RK3568_SYS1_INT_EN`/`CLR`) and per-VP bits in `RK3568_REG_CFG_DONE` require upper-16-bit write masks (`mask << 16 | val`). In VOP1 `struct vop_reg`, any field with `write_mask = true` must lie within bits `[15:0]` with a 4-byte aligned offset `< vop->len`. [F85, F289]
- Sentinel conventions: `rockchip_dw_dsi_chip_data` unsigned GRF offsets use `0` as unpopulated; `rockchip_hdmi_chip_data.lcdsel_grf_reg` and `cdn_dp_device.active_port` use `-1` (checked via `< 0` and `< dp->ports`); and in `analogix_dp-rockchip.c`, `rockchip_grf_reg_field` must be initialized via `GRF_REG_FIELD()` (`.valid = true`) and checked via `field->valid` because `0x0000` is a valid GRF offset on `rk3588_edp`. [F50, F51, F54]
- In dual-DSI mode (`dsi->slave != NULL`), a slave instance (`!master1`) sets `dsi->is_slave = true` and returns `0` immediately from `bind`/`unbind`, while the master performs runtime PM, GRF config, and VOP mux selection for both `dsi` and `dsi->slave`. When an external PHY (`dsi->phy`) is present, `dw_mipi_dsi_phy_init()` and `dw_mipi_dsi_get_lane_mbps()` must return before accessing internal DPHY registers or `dsi->pllref_clk`. [F56, F68, F97]

## Synchronization

- `vop->reg_lock` is acquired with non-IRQ-saving `spin_lock()` in process context to protect plane registers, `vop->win_enabled`, and `vop_cfg_done()` across plane/CRTC updates and `rockchip_drm_set_win_enabled()`, and must never be acquired in `vop_isr()` or hardirq context. [F19, F151]
- In `vop_crtc_atomic_flush()`, `vop_wait_for_irq_handler()` must be called after releasing `vop->reg_lock` (having set `cfg_done`) and before acquiring `crtc->dev->event_lock` to arm `vop->event`. Before setting `VOP_PENDING_FB_UNREF` in `vop->pending`, callers must acquire both `drm_framebuffer_get()` and `drm_crtc_vblank_get()` and queue the FB via `drm_flip_work_queue(&vop->fb_unref_work, ...)`. [F21, F153]
- In `vop_crtc_atomic_disable()`, `reinit_completion(&vop->dsp_hold_completion)` and `vop_dsp_hold_valid_irq_enable(vop)` must precede setting standby to 1, and `wait_for_completion_timeout(&vop->dsp_hold_completion, ...)` must finish before detaching the IOMMU or disabling VOP clocks; `vop_dsp_hold_valid_irq_disable(vop)` must precede `vop->is_enabled = false`. In `vop_enable()`, runtime PM and VOP clocks must be enabled before `rockchip_drm_dma_attach_device()`, and `vop->is_enabled = true` set before `drm_crtc_vblank_on()`. [F16, F17, F18]
- Both `vop_isr()` and `vop2_isr()`/`rk3576_vp_isr()` run on `IRQF_SHARED` lines in hardirq context and must guard hardware access with non-sleeping `pm_runtime_get_if_in_use()` and `pm_runtime_put()`. `vop_isr()` toggles clocks via `clk_enable()`/`clk_disable()` on `vop->hclk` and `vop->aclk`, which must remain prepared until `vop_unbind()`. [F130, F154, F294]
- In VOP2, `vop2_lock(vop2)` (`vop2->vop2_lock`) must be held across `vop2_crtc_atomic_enable()` and `vop2_crtc_atomic_disable()` (and released on every early return) to serialize `vop2->enable_count`, `vop2_enable()`/`vop2_disable()`, and `vop2_crtc_atomic_try_set_gamma()`. In `vop2_crtc_atomic_disable()`, the driver must set `RK3568_VP_DSP_CTRL__STANDBY` and wait for `vp->dsp_hold_completion` before decrementing `vop2->enable_count` and calling `vop2_disable()` (and restore `vp->dclk` to `vp->dclk_src` if reparented). [F184, F195, F227, F295]
- When `vop2->version <= VOP_VERSION_RK3588`, `rk3568_vop2_setup_layer_mixer()` must hold `vop2->ovl_lock`, swap displaced `old_win` into `old_layer_id` so no window is selected by multiple layers, commit and poll `rk3568_vop2_wait_for_port_mux_done()` when `port_sel != old_port_sel`, and poll `rk3568_vop2_wait_for_layer_cfg_done()` before writing `RK3568_OVL_LAYER_SEL`. [F219, F286]
- `vop2_crtc_atomic_flush()` must call `vop2_cfg_done(vp)` before moving `crtc->state->event` to `vp->event` under `crtc->dev->event_lock`, and `vop2_isr()`/`rk3576_vp_isr()` must only deliver `vp->event` when `BIT(vp->id)` in `RK3568_REG_CFG_DONE` has cleared. Debugfs dump callbacks (`vop2_summary_show()`, `__vop2_regs_dump()`) must hold `drm_modeset_lock_all(drm_dev)`. [F228, F298]
- In `cdn-dp-core.c`, `dp->lock` must be held for all mailbox/hardware/audio operations and `dp->suspended` updates; `cdn_dp_request_firmware()` requires `dp->lock` on entry, drops it around `request_firmware()`, and must re-acquire it before returning; `cdn_dp_pd_event_work()` must unlock `dp->lock` before calling `drm_bridge_hpd_notify()`. [F11, F25, F145, F165]
- `dw_mipi_dsi_rockchip_host_attach()` and `dw_mipi_dsi_dphy_init()` must check `dsi->usage_mode == DW_DSI_USAGE_IDLE` and set the new mode under `dsi->usage_mutex` before `component_add()`, and reset it to `DW_DSI_USAGE_IDLE` under `dsi->usage_mutex` after `component_del()`. In `dw_hdmi_qp-rockchip.c`, hardirq handlers must mask the level-triggered HPD interrupt in `hdmi->regmap` before returning `IRQ_WAKE_THREAD`, and the threaded handler clears it, schedules `hdmi->hpd_work`, and unmasks it. [F31, F166]

## Object Lifetimes

- In `rockchip_gem_prime_vunmap()`, `vunmap(map->vaddr)` must only be called when `rk_obj->pages && map->vaddr != rk_obj->kvaddr`. In `rockchip_fb_create()`, failure of `drm_gem_fb_init_with_funcs()` frees `afbc_fb` via `kfree()`, whereas a subsequent failure of `drm_gem_fb_afbc_init()` must call `drm_framebuffer_put(&afbc_fb->base)`. [F4, F175]
- In `vop_bind()`, locks, `vop_create_crtc()`, `pm_runtime_enable()`, and `vop_initial()` must complete before `devm_request_irq()`. In `vop2_bind()`, per-VP `irq_name` passed to `devm_request_irq()` must be allocated via `devm_kasprintf()` (not a stack buffer). In both `vop_destroy_crtc()` and `vop2_destroy_crtcs()`, all `drm_plane`s must be cleaned up via `drm_plane_cleanup()` before `drm_crtc_cleanup()` (and `of_node_put(crtc->port)` in VOP2). [F23, F177, F271, F274]

## API Contracts

- `rockchip_drm_gem_object_mmap()` borrows the caller's GEM reference (never calling `drm_gem_vm_close()` or `drm_gem_object_put()` on error) and must reset `vma->vm_pgoff = 0` and clear `VM_PFNMAP` before `vm_map_pages()` or `dma_mmap_attrs()`. `rockchip_gem_create_with_handle()` must pass `alloc_kmap = true` for `drm->fb_helper->client.file`; `rockchip_gem_get_pages()` must set `sg_dma_address(s) = sg_phys(s)` before `dma_sync_sgtable_for_device()`; and `rockchip_gem_prime_get_sg_table()` must allocate a new `struct sg_table`. [F2, F3, F159, F172, F173]
- `rockchip_drm_endpoint_is_subdriver()` returns `1` (subdriver), `0` (external bridge), or `-ENODEV`, so callers seeking external bridges must check `== 0`. `rockchip_rgb_init()` returns `NULL` when unused, `ERR_PTR` on error, or a valid pointer (`vop2_bind()` calls `vop2_destroy_crtcs()` on `-EPROBE_DEFER` and clears `vop2->rgb = NULL` on other `IS_ERR` returns; `unbind` guards `rockchip_rgb_fini()` with `if (rgb)`). `dw_mipi_dsi_rockchip_find_second()` returns `NULL`, `ERR_PTR(-EPROBE_DEFER)`, or a device pointer, requiring both `IS_ERR()` and non-NULL checks. [F39, F47, F55, F277]
- `vop_crtc_reset()` and `vop_crtc_duplicate_state()` must allocate `struct rockchip_crtc_state` (never bare `drm_crtc_state`) because VOP and encoder callbacks downcast via `to_rockchip_crtc_state()`. In `vop_reg_set()` and its macros, `reg->mask != 0` checks field existence, and `_mask` and value `v` must be passed unshifted. In VOP2, `vop2_vp_write()`/`read()` take VP-relative offsets, `vop2_writel()`/`readl()` take absolute offsets, and `vop2_win_write()` takes an `enum vop2_win_regs` index. [F48, F121, F216]

## Error Handling

- `rockchip_gem_iommu_map()` must store `iommu_map_sgtable()` in `ssize_t` and compare against `(ssize_t)rk_obj->base.size`; callers of `vop_convert_format()`, `vop2_convert_format()`, and `cdn_dp_mailbox_read()` must store the result in a signed `int` before checking `< 0`. [F37, F42, F53, F204]
- `vop_crtc_duplicate_state()`, `vop2_crtc_duplicate_state()`, and `inno_hdmi_connector_duplicate_state()` must check `WARN_ON(!state)` and return `NULL` before downcasting; `vop_plane_atomic_async_check()` must fall back to `plane->crtc->state` if `drm_atomic_get_existing_crtc_state()` returns `NULL`; and `rockchip_dp_suspend()`/`resume()` must check `IS_ERR(dp->adp)` rather than `!dp->adp`. [F43, F44, F52, F206]

## Known Pitfalls

- Register indexing and pointer scaling: in `rockchip_drm_vop.c`, `vop->regsbak` is `uint32_t *` and must be indexed by `offset >> 2` (whereas `vop->regs` takes byte offsets); in `inno_hdmi.c`, `hdmi_readb`/`writeb` multiply their offset by `4` (taking unscaled indices, unlike byte-offset `rk3066_hdmi.c`); and in `dw_hdmi-rockchip.c`, `dw_hdmi_rockchip_bind()` must copy `plat_data->phy_data` to `hdmi->chip_data` and overwrite `phy_data = hdmi` and `priv_data = hdmi` on a `devm_kmemdup()` copy. [F115, F118, F119]
- In `vop2_plane_atomic_update()`, `afbc_tile_num` and `VOP2_WIN_AFBC_PIC_SIZE` must be computed before the `rotate_90 || rotate_270` block swaps `act_info`/`actual_w`/`actual_h`; `VOP2_WIN_AFBC_HDR_PTR` (and on RK3576+, `VOP2_WIN_AFBC_PLD_OFFSET` with `PLD_OFFSET_EN`) takes the uncropped base `rk_obj->dma_addr + fb->offsets[0]`; and `VOP2_WIN_AFBC_AUTO_GATING_EN` must be written as `0` on `VOP_VERSION_RK3568` and `1` on all other versions. [F224, F287, F288]
- In VOP2, bits-per-pixel must be obtained via `vop2_get_bpp(fb->format)` (never `drm_format_info_bpp()`, which is 0 for `YUV420_8BIT`/`10BIT`), and in `vop2_setup_scale()`, `>= 4 * dst_h` must be checked before `>= 2 * dst_h` and `gt4`/`gt2` reset to `0` before `cbcr_src_h`. [F253, F257]
- In VOP2 tables, unsupported `enum vop2_win_regs` entries in cluster/smart `reg_field` arrays must be `{ .reg = 0xffffffff }` so `vop2_regmap_init()` does not add `win->offset` to `0`; cluster `phys_id` (`ROCKCHIP_VOP2_CLUSTER0..3` = 0, 1, 6, 7) is non-contiguous and must be mapped via `switch`; `pre_scan_max_dly[4]` uses index `3` on RK3568 (`rk3568_vop2_setup_bg_dly()`) but sums indices `0..2` on RK3576 (`rk3576_vop2_setup_bg_dly()`); and `rk3588_calc_cru_cfg()` must assign raw dividers (1, 2, 4) before the final `ilog2()`. [F222, F235, F241, F262]
