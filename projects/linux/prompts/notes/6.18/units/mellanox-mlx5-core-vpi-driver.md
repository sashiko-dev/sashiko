# MELLANOX MLX5 core VPI driver

The mlx5 core VPI driver manages ConnectX PCIe/Subfunction lifecycle, firmware command mailboxes, page allocation, MSI-X/EQ/CQ/WQ transport objects, and device health, while providing Flow Steering (FW/DMFS, SWS `mlx5dr`, HWS `mlx5hws`), E-Switch SR-IOV/switchdev offloads, LAG, PTP/DPLL, IPoIB, and `mlx5e` Ethernet/XSK/TC/CT data and control paths.

## Architecture & Data Flow

- Multi-WQEBB SQ/ICOSQ WQEs cannot cross page boundaries (`mlx5e_txqsq_get_next_pi()` pads edges with `.num_wqebbs = 1` NOPs), so room checks must reserve `MLX5E_STOP_ROOM(wqe_size)` (`2 * wqe_size - 1`) WQEBBs and `mlx5e_get_max_sq_aligned_wqebbs()` must clamp to `<= MLX5_SEND_WQE_MAX_WQEBBS - 1` so `wqebbs * 4` fits the 6-bit DS field. [F82, F95, F126]
- In `struct mlx5_wq_ll`, one slot is reserved as the free-list tail sentinel (`wq->tail_next` at `wq->fbc.sz_m1`), so usable capacity in `mlx5_wq_ll_is_full()` / `mlx5_wq_ll_missing()` is `wq->fbc.sz_m1` while `mlx5_wq_ll_get_size()` returns `wq->fbc.sz_m1 + 1`; `mlx5e_rqwq_reset()` on striding RQs must also reset `rq->mpwqe.actual_wq_head = 0`. [F81, F770, F780]
- For Subfunction (`mlx5_core_is_sf(dev)`) devices, `dev->priv.irq_table` and `eq_table->rmap` are NULL; callers must use `mlx5_irq_table_get(dev)` and `mlx5_eq_table_get_pci_rmap()`, null-check `sf_ctrl_pool`/`sf_comp_pool` (falling back to `pcif_pool`), and pass `pool->dev->pdev` to `pci_irq_vector()` vs `dev` to `mlx5_sf_coredev_to_adev()`. [F86, F454, F565, F566]
- In `fs_core.c`, `struct fs_node` must remain the first member of `struct fs_prio` and `struct mlx5_flow_namespace` (and `ns` first in `struct mlx5_flow_root_namespace`) because `del_sw_*` calls `kfree(node)`; downcasting `mlx5_flow_namespace` to `mlx5_flow_root_namespace` requires `find_root(&ns->node)`. [F333, F334]
- Every `enum mlx5_cap_type` queried via `mlx5_core_get_caps*()` must be listed in `types[]` in `main.c` so `mlx5_hca_caps_alloc()` pre-allocates `dev->caps.hca[cap_type]`. [F588]
- In `alloc.c` and `fs_pool.c`, `mlx5_db_pgdir.bitmap` and `mlx5_fs_bulk.bitmask` use inverted polarity (`1` = free, `0` = allocated), whereas `fw_page.bitmask` sets only `[0, MLX5_NUM_4K_IN_PAGE)` to `1` on init so `fwp_fill_manage_pages_out()` must bound `for_each_clear_bit()` to `MLX5_NUM_4K_IN_PAGE`. [F297, F665, F949]

## Synchronization

- `devl_lock(priv_to_devlink(dev))` must be acquired before `dev->intf_state_mutex` (`mlx5_load/unload_one_devl_locked()`, `mlx5_health_try_recover()`) and before `mlx5_devcom_comp_lock(dev->priv.hca_devcom_comp)` (`mlx5_attach/register_device()`); in LAG, `hca_devcom_comp` must precede `ldev->lock`, and no locks or sleeping calls may be taken under `lag_lock`. [F399, F400, F495, F539, F898]
- `rtnl_lock()` must precede `esw->offloads.encap_tbl_lock` (`mlx5e_tc_fib_event_work()`, `mlx5e_rep_update_flows()`) and `esw_qos_lock(esw)` (`esw_qos_devlink_rate_to_mbps()`); `esw->state_lock` nests outside `esw_qos_lock(esw)` and must never be held across `mlx5_eswitch_event_handler_unregister()` or `flush_workqueue(esw->work_queue)`. [F178, F1232, F1280, F1283, F1286]
- In `fs_core.c`, `fs_node.lock` must be acquired top-down (`ft->node` `FS_LOCK_GRANDPARENT` -> `fg->node` `FS_LOCK_PARENT` -> `fte->node` `FS_LOCK_CHILD`); in `mlx5dr_domain_lock()`, `dmn->info.rx.mutex` precedes `tx.mutex` and serializes non-atomic `mlx5dr_ste` / `mlx5dr_ste_htbl` `refcount` updates; in `mlx5_wc_support_get()`, SF devices must lock only `&parent->wc_state_lock`. [F356, F728, F735, F736]
- Callers holding `priv->state_lock` (e.g., `mlx5e_wait_for_min_rx_wqes()`, `mlx5e_open_locked()`) must not synchronously invoke health recovery that acquires `devl_lock` (defer RX timeout to `rq->rx_timeout_work`), and `mlx5e_tx_reporter_recover_from_ctx()` / `mlx5e_tx_reporter_err_cqe_recover()` must not acquire `priv->state_lock`. [F38, F1098]
- In HWS BWC (`bwc.c`), `ctx->bwc_send_queue_locks[idx]` protects `bwc_matcher->rules[idx]` and send queue `mlx5hws_bwc_get_queue_id(ctx, idx)`; to extend `bwc_matcher->at` or resize/rehash `bwc_matcher->matcher`, a thread holding `queue_lock` must unlock it, call `hws_bwc_lock_all_queues(ctx)`, revalidate, and re-read `bwc_matcher->matcher` afterwards because `hws_bwc_matcher_move()` replaces and destroys `old_matcher`. [F556, F557, F597, F658]
- Because `mlx5e_tc_ct_restore_flow()` takes `ct_priv->ht_lock` with `spin_lock()` in RX softirq context, all process/workqueue acquisitions of `ct_priv->ht_lock` must use `spin_lock_bh()`, and RX restore must release entries via `__mlx5_tc_ct_entry_put()` (deferring `mlx5_tc_ct_entry_del()` to `ct_priv->wq`). [F14, F168, F169]
- Hardware DMA/MMIO barriers: polling EQEs (`mlx5_eq_*_int()`), CQEs (`mlx5_cqwq_get_cqe*()`), or command entries (`poll_timeout()`) requires `dma_rmb()`/`rmb()` after the ownership check; posting WQEs (`mlx5e_notify_hw()`, `mlx5_wc_post_nop()`, `mlx5_aso_post_wqe()`) requires `dma_wmb()` before `*wq->db` and `wmb()` before the UAR write; polling CQEs requires `mlx5_cqwq_update_db_record()` and `wmb()` before advancing `cc` or freeing PTP metadata IDs. [F40, F154, F730, F731, F732, F889, F1095, F1484, F1549]
- Atomic EQ event notifiers (`mlx5_eq_notifier_register()`, `mlx5_notifier_register()`) and async command callbacks (`mlx5_cmd_cbk_t`, `mlx5_async_cbk_t`) run in interrupt context and must not sleep; when `callback != NULL`, `cmd_exec()` and `mlx5_cmd_exec_cb()` must use `GFP_ATOMIC` and `down_trylock()`. [F173, F230, F682, F1021, F1022]
- `mlx5_esw_hold()` returns `true` both when it locks `esw->mode_lock` and when `!mlx5_esw_allowed(esw)`, so callers must call `mlx5_esw_release()` iff `mlx5_esw_hold()` returned `true`; `mlx5_esw_try_lock()`, `mlx5_esw_lock()`, and `mlx5_devcom_for_each_peer_begin()` release their lock on failure/false, so unlock/end must only be called on success. [F1259, F1260, F1425]
- In `mlx5e_attach_decap()`, `mlx5e_attach_encap()`, and `mlx5e_mod_hdr_attach()`, the table lock must be dropped before `wait_for_completion(&res_ready)` or hardware allocation and reacquired to set `compl_result` and `complete_all(&res_ready)` (`mlx5e_encap_entry` and `mlx5e_mod_hdr_handle` set `compl_result = 1` on success, whereas `mlx5e_decap_entry` leaves `compl_result = 0`). [F17, F23, F52, F883]

## Object Lifetimes

- Reference-counted lookups: `mlx5_eq_cq_get()` requires `mlx5_cq_put()`; `mlx5e_get_next_matching/valid/init_encap()` and `mlx5e_get_next_nhe()` drop the input reference and return a reference on `next` (release on early loop break); `mlx5e_route_lookup_ipv4/ipv6_get()` require `mlx5e_route_lookup_ipv4/ipv6_put()`; `mlx5_uplink_netdev_get()` requires `mlx5_uplink_netdev_put()`; and `lookup_fte_locked()` holds two references plus `fte->node.lock`, requiring both `up_write_ref_node()` and `tree_put_node()`. [F1, F16, F19, F176, F209, F1166, F1597]
- `tree_remove_node()` decrements `node->refcount` even when returning `-EEXIST` (`refcount > 1`), so `mlx5_destroy_flow_table()` and `mlx5_destroy_flow_group()` consume the caller's reference and must not be retried; in `uar.c`, `kref_put(&up->ref_count, up_rel_func)` must be called under `reg_head.lock` or `wc_head.lock` (selected by `bfreg->wc`). [F206, F722, F768]
- In `add_adev()` (`dev.c`) and `mlx5_sf_dev_add()` (`sf/dev/dev.c`), once `auxiliary_device_init()` succeeds, the `.release` callback owns freeing the wrapper struct and ID, so subsequent error paths must call `auxiliary_device_uninit()` and must not call `kfree()` directly. [F530, F878]
- `mlx5_fc_local_create()` creates `MLX5_FC_TYPE_LOCAL` counters without `fc_bulk->fcs[]` or `bitmask` that must be released via `mlx5_fc_local_put()` in `del_sw_hw_rule()` (never `mlx5_fc_release()` or `mlx5_fc_destroy()`), whereas `MLX5_FC_TYPE_ACQUIRED` counters from `mlx5_fc_create()` are not freed by `mlx5_del_flow_rules()` and must be freed via `mlx5_fc_destroy()`. [F203, F204, F215, F332]
- In `create/destroy_async_eqs()`, once `mlx5_cmd_use_events()` switches to `table->cmd_eq`, teardown must switch back via `mlx5_cmd_use_polling(dev)` and restore `CMD_ALLOWED_OPCODE_ALL` before unregistering `cq_err_nb`; across all subsystems, event/FIB/netdev/switchdev notifiers must be unregistered before flushing or destroying their target workqueues. [F3, F32, F223, F404, F531, F887, F894, F907, F1068, F1090, F1557]
- `mlx5_fw_tracer_cleanup()` must use non-blocking `cancel_work(&tracer->update_db_work)` because `mlx5_fw_tracer_update_db()` calls `mlx5_fw_tracer_reload()` on the same work item; `mlx5e_ptp_close_txqsq()` must guard `cancel_work_sync(&ptpsq->report_unhealthy_work)` with `current_work() != &ptpsq->report_unhealthy_work`. [F879, F1072]
- TIRs must be destroyed (`mlx5e_tir_destroy()`) before their backing RQTs (`mlx5e_rqt_destroy()`) or trap RQs (`mlx5e_close_trap_rq()`); `mlx5e_rx_res_channels_deactivate()` must redirect active RQTs to `drop_rqn` before closing RQs; and `mlx5_cmd_dr_destroy_flow_table()` must destroy `dr_table` before `miss_action`. [F158, F715, F716, F1198, F1199]
- In `cmd_work_handler()`, once `iowrite32be()` rings `&dev->iseg->cmd_dbell`, `ent` must not be dereferenced unless `cmd_mode == CMD_MODE_POLLING || poll_cmd` (cached before ringing); in `mlx5_cmd_exec_cb_handler()`, `work` fields must be copied to locals before `work->user_callback(status, work)`. [F872, F876]

## API Contracts

- Pointer return conventions: `mlx5e_tir_builder_alloc()`, `mlx5_tc_ct_init()`, `mlx5e_tc_int_port_init()`, `mlx5_get_flow_namespace*()`, `mlx5_get_fdb_sub_ns()`, `mlx5_get_root_namespace()`, `mlx5_eswitch_get_rep()`, `mlx5_vf_get_core_dev()`, and all `mlx5dr_*_create*()`, `mlx5_smfs_*`, and `mlx5hws_*` allocators return `NULL` (never `ERR_PTR`), whereas `mlx5e_flow_get()`, `mlx5_eswitch_get_vport()`, `mlx5_devlink_eswitch_get()`, `mlx5_create_flow_table()`, `mlx5_modify_header_alloc()`, `mlx5_packet_reformat_alloc()`, `mlx5_irq_affinity_request()`, `mlx5_get_uars_page()`, and `mlx5e_tc_int_port_get()` return `ERR_PTR` (never `NULL`). [F46, F53, F61, F254, F255, F417, F561, F740, F748, F1102, F1103, F1299]
- `esw->devcom`, `health->fw_reporter`, `health->fw_fatal_reporter`, `health->vnic_reporter`, and `dev->rsc_dump` may be `NULL` or `ERR_PTR` and require `IS_ERR_OR_NULL()`; `mlx5_tc_ct_entry_get()` returns a pointer, `NULL`, or `ERR_PTR(-EINVAL)` (check both `!entry` and `IS_ERR(entry)`). [F56, F259, F407, F911, F913]
- Functions returning non-negative IDs/indices/modes on success or negative errno on failure (store in signed `int` and check `< 0`): `create_comp_eq()` (while `mlx5_eqn2comp_eq()` returns `ERR_PTR(-ENOENT)`), `cmds->create_match_definer()`, `mlx5_esw_try_lock()`, `mlx5_lag_get_dev_index_by_seq()`, `mlx5hws_buddy_alloc_mem()`, `mlx5_sf_hw_table_sf_alloc()`, `mlx5_flexible_inlen()`, `mlx5e_select_htb_queue()`, and `mlx5_geneve_tlv_option_create()`; `mlx5_vsc_gw_read_block_fast()` returns bytes read so far (check `ret != length`). [F66, F250, F253, F418, F559, F560, F563, F1104, F1464, F1465]
- Units and indices: `mlx5_max_tc(mdev)` returns the highest TC index (`num_tc - 1`, loop with `<= mlx5_max_tc(mdev)`); SR-IOV VF software indices are 0-based whereas firmware `function_id`, host VF `vport_num`, `mlx5_query/modify_hca_vport_*`, `ldev->v2p_map`, and `rl.c` indices are 1-based; `mlx5_eswitch_get_vport_metadata_for_match()` is shifted left by 16 bits whereas `for_set()` is unshifted; and WQE `swp_*_offset`, HWS `remove_words.num_of_words`, and STE v1/v3 header sizes/offsets are in 2-byte words (`bytes / 2`). [F63, F302, F423, F450, F577, F580, F610, F613, F742, F857, F1318, F1320]
- Modifying HCA capabilities (`mlx5_vport_set_other_func_cap()`, `esw_ipsec_vf_set_*`), `MLX5_REG_MTMP`, `MLX5_REG_QPDPM`, `MLX5_REG_PCMR`, `MLX5_REG_SBCM`, or `MLX5_REG_PPTB` requires querying the current register/capability buffer first and modifying it in place; `mlx5_crypto_dek_pool_push()` takes ownership of `dek` on all paths so callers must never `kfree(dek)` afterwards. [F289, F339, F430, F594, F936, F1331, F1422, F1489]

## Error Handling

- In `mlx5_tc_ct_entry_add_rule()`, `zone_rule->attr` is set only after `ct_rule_add()` succeeds, so `err_rule` must pass local `attr`; in `mlx5_tc_ct_entry_update_rule()`, `*old_attr = *attr` copies only `sizeof(struct mlx5_flow_attr)` (not trailing `esw_attr`/`nic_attr`) and must be restored if `ct_rule_update()` fails. [F10, F12, F143]
- In `mlx5e_tc_tun_create/update_header_ipv4/ipv6()`, once `encap_header` is assigned to `e->encap_header`, the local `encap_header` pointer must be nulled so error labels do not `kfree(e->encap_header)`; if the neighbour is not `NUD_VALID`, the functions return `0` without allocating `e->pkt_reformat`, so callers must check `e->flags & MLX5_ENCAP_ENTRY_VALID`. [F20, F51, F195]
- In `fs_core.c` (`init_*_root_ns`), `esw_chains_create()`, `add_adev()`, `esw/acl/*`, and `macsec_fs.c`, if setup fails after assigning a pointer into a struct field, the error path must clean up and reset the field to `NULL` so teardown helpers that only check `if (ptr)` do not double-free or dereference an `ERR_PTR`. [F220, F260, F914, F1265, F1470]
- In `hws_bwc_matcher_move()`, once `mlx5hws_matcher_resize_set_target(old_matcher, new_matcher)` succeeds, even if `hws_bwc_matcher_move_all()` fails, `bwc_matcher->matcher` must be updated to `new_matcher` and `old_matcher` destroyed; in `mlx5hws_bwc_rule_create_simple()`, every error after `hws_bwc_rule_cnt_inc_with_rehash()` must call `hws_bwc_rule_cnt_dec(bwc_rule)` and abort without rehash on `-EBUSY`/`-ETIMEDOUT`/`-EAGAIN`. [F536, F538, F627]
- `mlx5_cmd_do()` returns `-EREMOTEIO` when `outbox.status != MLX5_CMD_STAT_OK`, whereas `mlx5_cmd_exec()` and `mlx5_cmd_check()` translate `-EREMOTEIO` via `cmd_status_to_err()` and emulate status/syndrome on `-ENXIO` via `mlx5_internal_err_ret_value()` (requiring every `MLX5_CMD_OP_*` to be listed in `mlx5_internal_err_ret_value()` and `mlx5_command_str()`). [F908, F960, F961]

## Known Pitfalls

- Fixed-size hash/comparison keys (`struct mlx5_ct_tuple`, `struct mlx5_flow_act.vlan` in `eswitch_offloads_termtbl.c`, `struct mlx5_flow_spec`, `struct mlx5e_neigh`, `struct mlx5_mapped_obj`) are hashed or compared across their full `sizeof` including union padding, so stack instances must be zero-initialized (`= {}` or `memset`). [F59, F263, F300, F1113, F1114]
- Flexible arrays and variable-stride layouts: copying `struct mlx5_flow_attr` requires `ns_to_attr_sz()` rather than `sizeof(*attr)`; `rq->mpwqe.info` elements must be accessed via `mlx5e_get_mpw_info(rq, i)` (sized by `alloc_units.frag_pages`) rather than `rq->mpwqe.info[i]`; `rq->mpwqe.umr_wqe` is only a `struct mlx5e_umr_wqe_hdr` without trailing `inline_mtts/klms/ksms`; `struct mlx5e_tc_flow` must be recovered from `efi` via `container_of(efi, struct mlx5e_tc_flow, encaps[efi->index])`; and `mlx5e_mod_hdr_alloc()` may reallocate `mod_hdr_acts->actions` (invalidating prior pointers) without incrementing `num_actions`. [F54, F135, F136, F140, F884, F933, F999, F1187]
- Bitwise width and endianness: 64-bit bitmasks, timestamps, and ICM/BAR addresses (`MLX5_ASYNC_EVENT_MASK`, `MLX5_U64_4K_PAGE_MASK`, `1ULL << ent->idx` in `mlx5_cmd_comp_handler()`, `MLX5_CALC_CBS(m, e)`, `dr_ste_v0/v1_get_miss_addr()`, `uar2pfn()`, `poll_trace()`, `mlx5_read_time()`, `mlx5_dm_sw_icm_alloc()`) must cast operands to `u64`/`1ULL` before shifting; `be32_to_cpu(eqe->data.*.cqn)` and `wq->cc` in `mlx5_cqwq_update_db_record()` must be masked with `0xffffff`; MAC fields in `nic_vport_context` and `l2table_entry` require a `+ 2` byte offset for `ether_addr_copy()`; and `MLX5_SET_TO_ONES` on MAC match masks must set both `*_47_16` and `*_15_0`. [F90, F127, F641, F806, F807, F813, F823, F976, F977, F1177, F1347, F1507, F1531, F1533]
- In `mlx5_modify_lag()`, the new port mapping must be computed into a separate `ports` array and passed to `_mlx5_modify_lag(ldev, ports)` before updating `ldev->v2p_map`; callbacks registered with `mlx5_eq_notifier_register()` must embed `struct mlx5_nb` and downcast via `mlx5_nb_cof()`, whereas `mlx5_blocking_notifier_register()` uses `container_of()`. [F435, F1002]
