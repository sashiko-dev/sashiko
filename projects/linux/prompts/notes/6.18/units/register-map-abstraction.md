# REGISTER MAP ABSTRACTION

`include/linux/regmap.h` defines the public interface, configuration structures, inline helpers, polling macros, and `!CONFIG_REGMAP` build stubs for the Linux kernel Register Map (`regmap`) abstraction layer. It provides a unified API for accessing hardware registers across diverse buses, managing register caches, manipulating bitfields (`regmap_field`), and registering register-backed interrupt controllers (`regmap_irq_chip`).

## Architecture & Data Flow
- In `struct regmap_irq_chip`, each `irqs[i].reg_offset` and `sub_reg_offsets[b].offset[j]` is an address offset that must be a multiple of `map->reg_stride` with `reg_offset / map->reg_stride < chip->num_regs`. `REGMAP_IRQ_REG_LINE(_id, _reg_bits)` sets `.reg_offset = (_id) / (_reg_bits)` and `.mask = BIT((_id) % (_reg_bits))` (into `unsigned int mask`), requiring stride 1 and `0 < _reg_bits <= BITS_PER_TYPE(unsigned int)`. [F48, F59]
- Each `struct regmap_range_cfg` in `regmap_config.ranges` (`num_ranges` entries) must satisfy `range_min <= range_max <= max_register`, `selector_reg <= max_register`, and `window_len > 0`, and no `selector_reg` or `[window_start, window_start + window_len - 1]` from any other entry `j != i` may overlap `[range_min, range_max]`. [F47]
- `regmap_read_poll_timeout_atomic` widens `timeout_us` to `u64 __timeout_us` before `ktime_add_us(ktime_get(), __timeout_us)`, checks `ktime_compare(ktime_get(), __timeout) > 0` only when `__timeout_us` is non-zero (`0` means never timeout), and performs one final `regmap_read` on timeout before re-evaluating `cond`. [F58]

## Synchronization
- `regmap_reinit_cache` takes no lock and `regmap_register_patch` reallocates `map->patch` before locking `map->lock`, so callers must prevent concurrent regmap accesses during `regmap_reinit_cache` and prevent concurrent `regmap_register_patch` or `regcache_sync` calls. [F14]
- `regmap_read_poll_timeout` and `regmap_field_read_poll_timeout` must not be called in atomic context when `sleep_us` or `timeout_us` is non-zero. `regmap_read_poll_timeout_atomic` is safe in atomic context only when `map` uses `fast_io` (or a non-sleeping lock) and `REGCACHE_FLAT` or `REGCACHE_NONE`, since `REGCACHE_MAPLE` and `REGCACHE_RBTREE` allocate cache nodes at runtime on previously uncached registers. [F13, F85]
- Every `regmap_init_*` and `devm_regmap_init_*` macro must invoke its underlying `__regmap_init_*` or `__devm_regmap_init_*` function via `__regmap_lockdep_wrapper` so each call site gets a distinct `static struct lock_class_key`. Because one key is allocated per macro expansion site, wrapping `regmap_init_*` or `devm_regmap_init_*` in a shared helper causes all instances created through it to share one lockdep class unless per-caller `lock_key` and `lock_name` are forwarded. [F9, F31]
- A `struct regmap_bus` providing `async_write` must serialize asynchronous writes against synchronous bus I/O, and callers of `regmap_raw_write_async` must keep the `val` buffer valid until `regmap_async_complete` returns. [F12]
- When `use_relaxed_mmio` is set in `struct regmap_config` for a little-endian or 8-bit MMIO regmap (`!io_port`), regmap uses `read*_relaxed`/`write*_relaxed` without memory barriers, so drivers must issue explicit barriers where ordering against DMA or other memory accesses is required. [F15]

## Object Lifetimes
- In `struct regmap_bus`, setting `free_on_exit` transfers ownership of `bus` to `__regmap_init()`, which calls `kfree(bus)` both on `__regmap_init()` failure and in `regmap_exit()`. By contrast, `bus->free_context(bus_context)` is called only in `regmap_exit()` and never on `__regmap_init()` failure. [F1]
- `__regmap_init()` stores `wr_table`, `rd_table`, `volatile_table`, `precious_table`, `wr_noinc_table`, and `rd_noinc_table` pointers from `struct regmap_config` without copying, and `regmap_add_irq_chip_fwnode()` stores `chip` directly in `d->chip`. These structures and their nested arrays (`irqs`, `config_base`, `sub_reg_offsets`) must outlive the regmap and IRQ chip. [F4]
- `regmap_field_bulk_alloc` and `devm_regmap_field_bulk_alloc` populate a caller-allocated `rm_field` array of `num_fields` pointers from a single `kcalloc` block; callers must allocate the `struct regmap_field **` pointer array beforehand and pass `rm_field[0]` once (not in a loop) to `regmap_field_bulk_free` or `devm_regmap_field_bulk_free`. [F28]
- Non-devm resources (`regmap_init*`, `regmap_field_alloc`, `regmap_field_bulk_alloc`, `regmap_add_irq_chip*`) require matching manual teardown (`regmap_exit`, `regmap_field_free`, `regmap_field_bulk_free`, `regmap_del_irq_chip`), whereas `devm_*` resources must never be passed to non-devm teardown functions. [F78]

## API Contracts
- `regmap_bulk_read`, `regmap_bulk_write`, and `regmap_multi_reg_read` take `val_count` in register elements and index `void *val` as an array of `u8`, `u16`, or `u32` sized to `BITS_TO_BYTES(config->val_bits)`, whereas `regmap_raw_*` and `regmap_noinc_*` take `val_len` in bytes. However, `struct regmap_bus` callbacks `reg_noinc_read` and `reg_noinc_write` receive `val_count` in register elements (`val_len / map->format.val_bytes`), and `regmap_config.num_reg_defaults_raw` is also an element count (not byte size). [F62, F63, F64]
- `regmap_update_bits_base()` and its wrappers (`regmap_update_bits`, `regmap_write_bits`, `regmap_set_bits`, `regmap_clear_bits`, `regmap_assign_bits`, `regmap_test_bits`) take pre-shifted full-register bitmasks and values, whereas `regmap_field_*` and `regmap_fields_*` APIs take unshifted field-relative masks and values that regmap shifts by `field->shift`. [F93]
- `regmap_read_poll_timeout`, `regmap_read_poll_timeout_atomic`, and `regmap_field_read_poll_timeout` take `val` by `unsigned int` lvalue name (passing `&(val)` to the read helper) and only guarantee `val` is initialized when returning `0` or `-ETIMEDOUT`, leaving `val` uninitialized if the first read fails with a negative errno. [F19]
- In `struct regmap_config`, custom `lock` and `unlock` callbacks override `fast_io` and `use_hwlock` (unless `disable_locking` is true), receive `lock_arg` as their sole parameter (default locks ignore `lock_arg`), and require `.can_sleep = true` if the custom lock or bus I/O can sleep. [F11]
- `regmap_del_irq_chip(irq, data)` and `devm_regmap_del_irq_chip(dev, irq, data)` require the exact primary `irq` passed to `regmap_add_irq_chip*()` (not a child virq or `0`), and `devm_regmap_del_irq_chip()` asserts `WARN_ON(irq != data->irq)` and requires non-NULL `data`. [F7]
- In `struct regmap_irq_chip`, setting both `mask_base` and `unmask_base` requires `mask_unmask_non_inverted = true`, and setting `clear_on_unmask` forbids `ack_base` and `use_ack` (otherwise registration returns `-EINVAL`). When `set_type_config` is set (e.g., `regmap_irq_set_type_config_simple`), both `num_config_bases` and `num_config_regs` must be non-zero with `type.type_reg_offset / map->reg_stride < num_config_regs`. [F27, F67]
- When multiple `regmap_irq_chip` controllers are registered on one device or the domain belongs to a child/alternate fwnode rather than `dev_fwnode(map->dev)`, drivers must set `domain_suffix` or use `regmap_add_irq_chip_fwnode` / `devm_regmap_add_irq_chip_fwnode`. Setting `regmap_irq_chip.runtime_pm` only holds runtime PM during IRQ `sync_unlock` and threaded handling, so callers must still ensure the device is powered during `regmap_add_irq_chip*` and handle suspend/resume restoration. [F80, F81]
- When `regmap_config.cache_type != REGCACHE_NONE`, `reg_defaults` and `num_reg_defaults` must either both be non-zero or both be zero (`regcache_init()` duplicates `reg_defaults` per instance). `regmap_reinit_cache()` resets `cache_bypass` and `cache_only` to `false` and updates `max_register`, `max_register_is_set`, `cache_type`, `name`, and boolean access callbacks, but does not update `wr_table`, `rd_table`, `volatile_table`, `precious_table`, `wr_noinc_table`, or `rd_noinc_table`. [F34, F35]
- Per-register access callbacks (`writeable_reg`, `readable_reg`, `volatile_reg`, `precious_reg`, `writeable_noinc_reg`, `readable_noinc_reg`) override their corresponding `struct regmap_access_table`, and within a table `no_ranges` are checked before `yes_ranges`. Registers with read side effects (e.g., clear-on-read or FIFO pop) must be marked via `precious_reg` or `precious_table`. [F53, F72]
- In `struct regmap_config`, positive `reg_shift` downshifts (`>>`) and negative `reg_shift` upshifts (`<<`) register addresses after adding `reg_base`; use `REGMAP_UPSHIFT(s)` for left shifts and `REGMAP_DOWNSHIFT(s)` for right shifts. In `struct reg_field` (`REG_FIELD` / `REG_FIELD_ID`), `msb` must satisfy `lsb <= msb < BITS_PER_TYPE(unsigned int)`. [F57, F61]
- `regmap_init_mdio` and `devm_regmap_init_mdio` require `val_bits == 16` and `reg_bits` of `5` (Clause 22) or `21` (Clause 45, packing the 5-bit device address at `REGMAP_MDIO_C45_DEVAD_SHIFT` / `REGMAP_MDIO_C45_DEVAD_MASK` and 16-bit register under `REGMAP_MDIO_C45_REGNUM_MASK`), returning `ERR_PTR(-EOPNOTSUPP)` otherwise. [F29]
- `regmap_parse_val` reads `BITS_TO_BYTES(config->val_bits)` bytes from `const void *buf` without a length parameter, so `buf` must be at least `regmap_get_val_bytes(map)` bytes long. [F68]
- When `!CONFIG_REGMAP`, `regmap_init_*` and `devm_regmap_init_*` are undefined and operational inline stubs fail with `WARN_ONCE(1, "regmap API is disabled")`, except `dev_get_regmap()` which must silently return `NULL`. [F39, F95]

## Error Handling
- `regmap_init*`, `devm_regmap_init*`, `regmap_field_alloc`, and `devm_regmap_field_alloc` return `ERR_PTR()` on failure and never `NULL`. By contrast, `dev_get_regmap()`, `regmap_get_device()`, and `regmap_irq_get_domain()` return borrowed pointers (no reference taken; never pass to `regmap_exit()` or `put_device()`) and return `NULL` (not `ERR_PTR()`) when absent. [F6, F16]
- `regmap_test_bits` and `regmap_field_test_bits` return a negative errno on read failure, `0` if any tested bit is clear, and `1` if all tested bits are set; `regmap_get_val_bytes` and `regmap_get_max_register` return `-EINVAL` when `format_write` is used or `max_register` is unset. Callers of all four must store the result in a signed `int` and check `< 0`. [F17, F18]
- A `struct regmap_bus` `gather_write` callback must return `-ENOTSUPP` (specifically `-ENOTSUPP`, not `-EOPNOTSUPP` or `-EINVAL`) when split register/value writes are unsupported so the regmap core falls back to linearizing into a single buffer for `bus->write`. [F24]
- In `regmap_read_poll_timeout` and `regmap_field_read_poll_timeout`, the `read_poll_timeout` break condition must short-circuit on `__ret || (cond)` and the macro must return `__ret ?: __tmp` so read errors abort polling before evaluating `cond` and propagate `__ret`. [F51]

## External Contracts
- When `regmap_config.reg_format_endian` or `val_format_endian` is `REGMAP_ENDIAN_DEFAULT` (`0`), regmap resolves register endianness from `bus->reg_format_endian_default` and value endianness from firmware properties (`big-endian`, `little-endian`, `native-endian`) before `bus->val_format_endian_default`, defaulting to `REGMAP_ENDIAN_BIG`. Broken by: hardcoding non-default `val_format_endian` on devices whose DT/ACPI bindings specify endianness properties. [F46]

## Known Pitfalls
- `regmap_update_bits`, `regmap_set_bits`, `regmap_clear_bits`, `regmap_field_write`, and `regmap_field_update_bits` pass `force = false` and skip the bus write when the target bits already match the current/cached value; write-1-to-clear or hardware trigger bits must use `regmap_write_bits` or `regmap_field_force_write`. [F75]
- In `struct regmap_config`, setting `use_raw_spinlock = true` only selects a `raw_spinlock_t` when `fast_io` is also set on either `regmap_config` or `regmap_bus` (and `disable_locking`, custom `lock`/`unlock`, and `use_hwlock` are unset); otherwise `__regmap_init` falls back to a sleeping `struct mutex`. [F10]
- In `struct regmap_config`, a zero `max_register` or zero `read_flag_mask` and `write_flag_mask` are treated as unspecified unless `max_register_is_0 = true` or `zero_flag_mask = true` is explicitly set. [F54]
- In `regmap_read_poll_timeout`, `regmap_read_poll_timeout_atomic`, and `regmap_field_read_poll_timeout`, passing `timeout_us = 0` disables timeout checking and polls indefinitely until `cond` holds or `regmap_read` fails; bounded hardware waits require a non-zero `timeout_us`. [F70]
- `REGMAP_IRQ_MAIN_REG_OFFSET(arr)` uses `ARRAY_SIZE((arr))` to set `struct regmap_irq_sub_irq_map.num_regs`, so `arr` must be a fixed-size `unsigned int` array rather than a pointer. [F66]
