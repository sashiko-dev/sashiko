# RADEON and AMDGPU DRM DRIVERS

Defines the core amdgpu driver header (`amdgpu.h` and `struct amdgpu_device`) along with Audio Co-Processor (ACP), ACPI integration (ATIF/ATCS/XCC DSM), AMD Error Check Architecture (ACA), Aldebaran reset handling, and the KGD-to-KFD compute interface (`amdgpu_amdkfd*`) across GFX v7 through v12 and MI-series GPUs. It bridges GPU memory management, eviction fences, HQD/MQD management, and hardware error reporting with the ROCm/KFD compute subsystem and platform firmware.
Implements core amdgpu device lifecycle management (`amdgpu_device.c`), hardware IP discovery table parsing and sysfs exposure (`amdgpu_discovery.c`), per-file GPU execution contexts (`amdgpu_ctx.c`), debugfs inspection interfaces (`amdgpu_debugfs.c`), and GPU hang device coredumps (`amdgpu_dev_coredump.c`). It orchestrates IP block probing, early/sw/hw/late initialization, suspend/resume, PCIe/XGMI GPU reset recovery, and low-level MMIO/indexed register access.
Contains the top-level PCI and DRM driver entry points (`amdgpu_drv.c`), GEM buffer object and DMA-BUF PRIME sharing (`amdgpu_gem.c`, `amdgpu_dma_buf.c`), GART and doorbell aperture managers (`amdgpu_gart.c`, `amdgpu_doorbell_mgr.c`), hardware and eviction DMA fences (`amdgpu_fence.c`, `amdgpu_eviction_fence.c`), common GFX IP management (`amdgpu_gfx.c`), legacy/common display helpers (`amdgpu_display.c`, `amdgpu_encoders.c`), and EEPROM/FRU/attestation utilities.
Implements GPU Memory Controller and GTT TTM resource management (`amdgpu_gmc.c`, `amdgpu_gtt_mgr.c`), TTM/GEM buffer object lifecycle (`amdgpu_object.c`), HMM/MMU interval notifiers (`amdgpu_hmm.c`), VMID/PASID allocators (`amdgpu_ids.c`), Indirect Buffer and DRM scheduler job execution (`amdgpu_ib.c`, `amdgpu_job.c`), interrupt ring and IRQ domain dispatch (`amdgpu_ih.c`, `amdgpu_irq.c`), Micro Engine Scheduler (`amdgpu_mes.c`), KMS open/close/info ioctls (`amdgpu_kms.c`), and MCA/JPEG/ISP/I2C/HDP/LSDMA/MMHUB/NBIO helpers.
Implements the GPU Virtual Memory (VM) multi-level page table manager (`amdgpu_vm.c`), usermode queue and usermode fence subsystems (`amdgpu_userq.c`, `amdgpu_userq_fence.c`), SR-IOV GPU virtualization and VF2PF mailbox/telemetry (`amdgpu_virt.c`, `amdgpu_vf_error.c`), multimedia engine managers for UVD, VCE, VCN, and UMSCH (`amdgpu_uvd.c`, `amdgpu_vce.c`, `amdgpu_vcn.c`, `amdgpu_umsch_mm.c`), and Virtual KMS (`amdgpu_vkms.c`).
Implements the hardware-specific Graphics and Compute (GC/GFX) IP block drivers for GFX v11 (`gfx_v11_0.c`, `gfx_v11_0_3.c`, RDNA3) and GFX v12 (`gfx_v12_0.c`, RDNA4). It manages CP (PFP, ME, MEC) and RLC/IMU firmware loading, GFX/compute/KIQ ring packet emission (PM4 packets), MQD initialization, usermode queue MES callbacks, EOP and fault interrupt handling, GFXOFF/clockgating/powergating, cleaner shader execution, and per-queue/pipe reset.
Core AMDGPU infrastructure covering TTM memory management (VRAM/GTT/preempt managers and buffer moves), GPU command rings and software ring multiplexing, fence synchronization (`amdgpu_sync` and `amdgpu_seq64`), GPU reset domains/handlers, firmware microcode parsing (`amdgpu_ucode`), RAS EEPROM bad-page persistence and UMC error retirement, RLC/SDMA common helpers, scheduler priority ioctl handling, and Secure Display debugfs interfaces.
Implements AMDGPU virtual memory page table management (`amdgpu_vm_pt`, CPU/SDMA PT updaters, and asynchronous TLB flush fences), DRM buddy-based VRAM resource allocation (`amdgpu_vram_mgr`), Accelerated Compute Partitioning (`amdgpu_xcp` and `aqua_vanjaram` SOC helpers), multi-GPU XGMI hive topology and RAS management (`amdgpu_xgmi`), Video Processing Engine core (`amdgpu_vpe`), ATHUB clockgating (v1.0-v4.1.0), and legacy AtomBIOS bytecode interpreter and display/encoder/DP helpers.
Hardware IP block driver for GFX v10.0 (Navi1x / RDNA1 and Sienna Cichlid / RDNA2 families, `gc_10_1` and `gc_10_3`), managing graphics and compute rings, MEC/PFP/CE/ME/RLC microcode loading, MQD (Memory Queue Descriptor) initialization, KIQ (Kernel Interface Queue), clockgating/powergating, cleaner shaders, and GFX interrupt handling.
Hardware IP block driver for GFX v8.0 (Volcanic Islands / GCN 1.2 family including Tonga, Carrizo, Stoney, Fiji, Polaris10/11/12), managing GFX and compute rings, CP/RLC microcode loading, MQD setup, KIQ, golden registers, clockgating/powergating, and GFX interrupts.
Hardware IP block driver for GFX v9.0 (Vega10/12/20, Raven, Picasso, Renoir, Arcturus, Aldebaran) along with RAS EDC error querying/injection and golden register/shader initialization for GFX v9.4 (Arcturus) and GFX v9.4.2 (Aldebaran).
Hardware backend implementations for the Platform Security Processor (`psp_v3_1`, `psp_v13_0`, `psp_v13_0_4`, `psp_v14_0`) and System DMA engines (`sdma_v2_4`, `sdma_v3_0`, `sdma_v4_0`, `sdma_v4_4`, `sdma_v4_4_2`, `sdma_v5_0`), covering PSP bootloader/SOS/TA/VBIOS-flash/USB-PD mailbox protocols and SDMA GFX/page/RLC ring emission, VM PTE updates, buffer copies, engine soft-resets, and RAS/ACA error reporting.
Implements System DMA IP block drivers for SDMA v5.2 (RDNA2 / GC 10.3), SDMA v6.0 (RDNA3 / GC 11.0), and SDMA v7.0 (RDNA4 / GC 12.0), the SDMA v6.0 packet header definitions (`sdma_v6_0_0_pkt_open.h`), and the Southern Islands (`si.c`, GCN 1.0 Tahiti/Pitcairn/Verde/Oland/Hainan) SoC family common IP block and ASIC-level initialization.
Combines the Vega20 Interrupt Handler (`vega20_ih.c`), Volcanic Islands SoC family common driver (`vi.c`), Video Processing Engine v6.1 hardware backend (`vpe_v6_1.c`, `vpe_6_1_fw_if.h`), the standalone `amdxcp` platform DRM device allocator module (`amdgpu_xcp_drv.c`), and shared AMD headers for ACPI ATIF/ATCS (`amd_acpi.h`), UEFI CPER error records (`amd_cper.h`), PCIe helpers (`amd_pcie*.h`), sysfs register state dumps (`amdgpu_reg_state.h`), IP blocks (`amd_shared.h`), and Aldebaran/Arcturus IP register base offsets.

## Architecture & Data Flow

- Downcasting a `struct dma_fence *` to `struct amdgpu_amdkfd_fence *` must go through `to_amdgpu_amdkfd_fence`, which returns `NULL` unless `f` is non-NULL and `f->ops == &amdkfd_fence_ops`, and callers must check the returned pointer for `NULL` before accessing `amdgpu_amdkfd_fence` fields. [F43]
- In `struct amdgpu_amdkfd_fence`, `fence->svm_bo` distinguishes SVM BO fences from process BO fences: `amdkfd_fence_check_mm` must return `false` when `fence->svm_bo` is non-NULL, and `amdkfd_fence_enable_signaling` must dispatch on `fence->svm_bo` and invert the `0`-on-success return of the KFD schedule helpers to `bool`. [F44]
- In `kgd_gfx_v9_4_3_set_pasid_vmid_mapping`, `regIH_VMID_LUT_INDEX` must be saved before selecting the XCC index (`aid * 4 + (phy_inst % 2) + 1`) and AID index (`aid * 4`) to write `regIH_VMID_0_LUT` and `regIH_VMID_0_LUT_MM`, and restored to its saved value afterward. [F58]
- In `kgd_gfx_v10_set_wave_launch_trap_override`, `mmSPI_GDBG_WAVE_CNTL` must be sampled into `wave_cntl_prev` before calling `kgd_gfx_v10_set_wave_launch_stall(adev, vmid, true)` and restored by writing `wave_cntl_prev` back to `mmSPI_GDBG_WAVE_CNTL` after updating `mmSPI_GDBG_TRAP_MASK`. [F59]
- In `kgd_gfx_v10_validate_trap_override_request`, because `mmSPI_GDBG_TRAP_MASK` on GFX10 is global across all processes, `*trap_mask_supported` must be restricted to `KFD_DBG_TRAP_MASK_DBG_ADDRESS_WATCH` and `trap_override` must be `KFD_DBG_TRAP_OVERRIDE_OR`. [F60]
- In `kgd_gfx_v10_set_address_watch`, `mmTCP_WATCH0_CNTL` and `mmSQ_WATCH0_CNTL` for `watch_id` must be written with `VALID = 0` before programming the `mmTCP_WATCH0_ADDR_H`/`L` and `mmSQ_WATCH0_ADDR_H`/`L` registers, and only written with `VALID = 1` after both address pairs are programmed. [F61]
- In `kgd_set_pasid_vmid_mapping` (GFX7, GFX8) and `kgd_gfx_v9_4_3_set_pasid_vmid_mapping` (GC 9.4.3), after writing `ATC_VMID0_PASID_MAPPING + vmid`, software must wait for bit `1U << vmid` in `ATC_VMID_PASID_MAPPING_UPDATE_STATUS`, write `1U << vmid` to clear that status bit, and mirror `pasid_mapping` into `IH_VMID_0_LUT + vmid`. [F62]
- In SDMA HQD load and destroy functions (`kgd_arcturus_hqd_sdma_*`, `kgd_gfx_v9_4_3_hqd_sdma_*`, `kgd_hqd_sdma_*`, `hqd_sdma_*_v10_3`/`v11`), `RB_ENABLE` in `RB_CNTL` must be cleared and `CONTEXT_STATUS__IDLE_MASK` polled until set before mutating queue registers, and destroy must save hardware `RB_RPTR` back into the MQD. [F63]
- In `kgd_hqd_destroy` (`amdgpu_amdkfd_gfx_v8.c`, `amdgpu_amdkfd_gfx_v10.c`), `hqd_destroy_v10_3`, and `hqd_destroy_v11`, when `m->cp_hqd_vmid == 0` (indicating the HIQ), `RLC_CP_SCHEDULERS.scheduler1` must be cleared to `0` while holding `acquire_queue` before writing `CP_HQD_DEQUEUE_REQUEST`. [F64]
- In `drivers/gpu/drm/amd/amdgpu/amdgpu_aca.c`, `aca_log_aca_error` must drain `handle->error_cache.errors[type]` under `aerr->lock` via `aca_bank_error_remove` (which decrements `aerr->nr_errors`), and `__aca_get_error_data` must also drain `ACA_ERROR_TYPE_DEFERRED` whenever `type != ACA_ERROR_TYPE_DEFERRED`. [F66]
- In `amdgpu_amdkfd_device_init`, after `bitmap_complement` populates `gpu_resources.cp_queue_bitmap` up to `AMDGPU_MAX_QUEUES`, all bits from `last_valid_bit` (`num_pipe_per_mec * num_queue_per_pipe`) through `AMDGPU_MAX_QUEUES - 1` must be explicitly cleared with `clear_bit`. [F78]
- In `hqd_load` across GFX7 through GFX11, `mqd_hqd = &m->cp_mqd_base_addr_lo` is indexed as a flat `uint32_t` array by `reg - hqd_base` over `[hqd_base, hqd_end]`, requiring the MQD struct fields starting at `cp_mqd_base_addr_lo` to match the hardware HQD register offsets 1-to-1. [F81]
- In every `hqd_dump` and `hqd_sdma_dump` implementation, `HQD_N_REGS` must equal the exact total number of registers emitted by its `DUMP_REG` loops, as `*dump` is allocated for `HQD_N_REGS` elements and checked by `WARN_ON_ONCE(i >= HQD_N_REGS)` and `WARN_ON_ONCE(i != HQD_N_REGS)`. [F82]
- In `hqd_load` on GFX9.4.3, GFX10, GFX10.3, and GFX11, when `wptr` is non-NULL, `guessed_wptr` written to `CP_HQD_PQ_WPTR_LO/HI` must reconstruct the 64-bit RPTR from `cp_hqd_pq_rptr` and `cp_hqd_pq_wptr_lo/hi`, adding `queue_size` when `(cp_hqd_pq_wptr_lo & (queue_size - 1)) < (cp_hqd_pq_rptr & (queue_size - 1))`. [F85]
- In `aca_bank_is_valid`, `ACA_BANK_ERR_IS_DEFFERED(bank)` must be checked before `aca_bank_hwip_is_matched(bank, handle->hwip)` so that all deferred and poison ACA banks are routed exclusively to the `ACA_HWIP_TYPE_UMC` handle regardless of the bank's IPID. [F86]
- In `aca_smu_get_valid_aca_banks`, when `type == ACA_SMU_TYPE_UE` and `ACA_REG__STATUS__POISON` is set on `bank.regs[ACA_REG_IDX_STATUS]`, any bank that does not match `ACA_HWIP_TYPE_UMC` must be skipped via `continue` before calling `aca_smu_bank_dump` and `aca_banks_add_bank`. [F87]
- In `kgd_gfx_v9_4_3_set_wave_launch_trap_override`, `kgd_gfx_v11_set_wave_launch_trap_override`, and `kgd_gfx_v12_set_wave_launch_trap_override`, `kfd_dbg_trap_cntl_prev` must be decoded via `trap_mask_map_hw_to_sw` before applying `trap_mask_request` and re-encoded via `trap_mask_map_sw_to_hw` so `TRAP_ON_START` and `TRAP_ON_END` are preserved. [F100]
- `struct dev_pagemap pgmap` must remain the final member of `struct amdgpu_kfd_dev`, and `struct amdgpu_kfd_dev kfd` must remain the final member of `struct amdgpu_device`, because `struct dev_pagemap` ends in a flexible-array member. [F108]
- `struct dma_fence base` must remain the first member (at offset 0) of `struct amdgpu_amdkfd_fence` because `amdkfd_fence_release` frees the allocation by passing the `struct dma_fence *f` pointer directly to `kfree_rcu(f, rcu)`. [F109]
- In `aldebaran_mode2_restore_ip`, RLC must be resumed via `adev->gfx.rlc.funcs->resume(adev)` after reloading firmware with `psp_load_fw_list` and before calling `amdgpu_dpm_wait_for_event(adev, SMU_EVENT_RESET_COMPLETE, 0)`, because SMU firmware requires RLC to be alive to complete the reset process. [F118]
- In `aldebaran_mode2_prepare_hwcontext`, `aldebaran_mode2_suspend_ip` must only be called when `!amdgpu_sriov_vf(adev)` so that bare-metal IP blocks are suspended only when the driver will actually perform a hardware ASIC reset. [F119]
- When `amd_acp_hw_init` returns `-ENODEV` (Azalia board), `acp_hw_init` powergates ACP via `amdgpu_dpm_set_powergating_by_smu` without allocating `acp_genpd` or `acp_cell`, so `acp_suspend`, `acp_resume`, and `acp_hw_fini` must check `!adev->acp.acp_cell` / `!adev->acp.acp_genpd` to ungate ACP on suspend/fini and re-gate it on resume. [F135]
- In `amdgpu_amdkfd_suspend` and `amdgpu_amdkfd_resume`, when `adev->in_s0ix` is true, the driver must call `kgd2kfd_stop_sched_all_nodes(adev->kfd.dev)` and `kgd2kfd_start_sched_all_nodes(adev->kfd.dev)` rather than `kgd2kfd_suspend` and `kgd2kfd_resume`. [F136]
- `amdgpu_acpi_is_s0ix_active` must return `false` unless `adev` is a `CHIP_RAVEN` or newer APU (`adev->flags & AMD_IS_APU`), `pm_suspend_target_state == PM_SUSPEND_TO_IDLE`, `adev->pm.pp_feature & PP_GFXOFF_MASK` and `acpi_gbl_FADT.flags & ACPI_FADT_LOW_POWER_S0` are both set, and `CONFIG_AMD_PMC` is enabled. [F137]
- When parsing `struct ip_v4` entries in `adev->mman.discovery_bin`, `ip->sub_revision` and `ip->variant` must only be read if `ihdr->version >= 3` (defaulting to `0` otherwise), and `ip->base_address_64` vs `ip->base_address` must be selected by `ihdr->base_addr_64_bit` both when reading addresses and advancing `ip_offset`. [F227]
- `amdgpu_device_resume()` must call `amdgpu_vram_mgr_clear_reset_blocks(adev)` before clearing `adev->in_suspend` because system suspend and VBIOS POST clobber VRAM while the DRM buddy allocator would otherwise still track free VRAM blocks as zero-cleared. [F229]
- When `amdgpu_device_check_vram_lost()` detects lost VRAM during `amdgpu_device_reinit_after_reset()`, the recovery path must both increment `adev->vram_lost_counter` via `amdgpu_inc_vram_lost()` and refresh `adev->reset_magic` from `adev->gart.ptr` via `amdgpu_device_fill_reset_magic()`. [F230]
- `amdgpu_ctx_priority_override()` must update `ctx->override_priority` and propagate the new effective priority to every already-allocated `ctx->entities[i][j]` via `amdgpu_ctx_set_entity_priority()`, which updates both `drm_sched_entity_set_priority()` and (for GFX/COMPUTE) `drm_sched_entity_modify_sched()`. [F235]
- In `amdgpu_discovery_set_ip_blocks()`, `amdgpu_discovery_harvest_ip()` must run after `amdgpu_discovery_reg_base_init()` and before `amdgpu_discovery_get_mall_info()` and `amdgpu_discovery_sysfs_init()`, because `amdgpu_discovery_harvest_ip()` adjusts `adev->gmc.num_umc` and the IP harvest masks consumed by MALL sizing and sysfs harvest attributes. [F239]
- When harvesting `VCN_HWID` in `amdgpu_discovery.c`, `adev->vcn.inst_mask` and `adev->jpeg.inst_mask` must be cleared in lockstep, and when `vcn_harvest_count == adev->vcn.num_vcn_inst`, both `AMD_HARVEST_IP_VCN_MASK` and `AMD_HARVEST_IP_JPEG_MASK` must be set in `adev->harvest_ip_mask`. [F240]
- `amdgpu_device_suspend()` must call `amdgpu_ttm_set_buffer_funcs_status(adev, false)` only after `amdgpu_device_evict_resources()`, and `amdgpu_device_ip_resume()` and `amdgpu_device_reinit_after_reset()` must re-enable it only after `amdgpu_device_ip_resume_phase2()` when `buffer_funcs_ring->sched.ready` is true. [F243]
- During bare-metal GPU reset, `ip_block->version->funcs->dump_ip_state()` must be invoked for each IP block in `amdgpu_device_pre_asic_reset()` before `amdgpu_device_ip_suspend()` and hardware reset, so `amdgpu_coredump()` called after reset in `amdgpu_device_reinit_after_reset()` can format the pre-reset register snapshot via `print_ip_state()`. [F244]
- `mgr->ctx_handles` is initialized with `idr_init_base(&mgr->ctx_handles, 1)` and `amdgpu_ctx_alloc` allocates context IDs in `[1, AMDGPU_VM_MAX_NUM_CTX)`, reserving `*id = 0` for allocation failure. [F251]
- Before indexing `hw_id_names`, `adev->reg_offset`, or `adev->ip_versions` with values from the IP discovery binary, callers must validate `instance < HWIP_MAX_INSTANCE` and `hw_id < HW_ID_MAX` via `amdgpu_discovery_validate_ip` and still advance `ip_offset` by the entry's `struct_size` on failure. [F254]
- `amdgpu_discovery_read_from_harvest_table` iterates at most 32 entries of `harvest_info->list` and stops at the first entry where `le16_to_cpu(harvest_info->list[i].hw_id) == 0`. [F257]
