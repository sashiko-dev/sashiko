# ARM MALI PANTHOR DRM DRIVER

The Panthor DRM driver (`drivers/gpu/drm/panthor`) manages ARM Mali Valhall (Gen 10+) GPUs with a Command Stream Frontend (CSF) microcontroller, providing GEM shmem and `drm_gpuvm` memory management, firmware control, `drm_gpu_scheduler` CSG scheduling, tiler heaps, and runtime PM/devfreq.

## Architecture & Data Flow

- MMU AS slot 0 is reserved for the MCU VM (`vm->for_mcu`); user VMs allocate starting at bit 1 (`ffz(ptdev->mmu->as.alloc_mask | BIT(0))`) and scheduler AS accounting masks out bit 0 (`as_present & GENMASK(31, 1)`). `alloc_mask` must be `unsigned long` for bitops. [F101, F154]
- Under `ptdev->mmu->as.slots_lock`, `panthor_vm_release_as_locked()` must clear `slots[vm->as.id].vm`, clear `vm->as.id` in `alloc_mask`, reset `active_cnt = 0`, remove `lru_node`, and set `vm->as.id = -1`. When `panthor_vm_active()` clears an AS bit in `faulty_mask` and unmasks `MMU_INT_MASK`, it must also set `panthor_mmu_as_fault_mask()` in `ptdev->mmu->irq.mask`. [F70, F71]
- GPU VAs and sizes in `panthor_fw_load_section_entry()`, `panthor_kernel_bo_create()`, `panthor_vm_alloc_va()`, and `panthor_vm_bind_prepare_op_ctx()` must align to `panthor_vm_page_size(vm)` (not CPU `PAGE_SIZE`), and `panthor_kernel_bo_destroy()` must unmap `bo->va_node.size` (not `panthor_kernel_bo_size(bo)`). [F106, F186]
- `panthor_vm_prepare_map_op_ctx()` computes `pt_count` by aligning `va + size` up and `va` down to each level boundary (`1ull << 39`, `30`, `21`), and `unmap` reserves up to 2 L3 tables for unaligned `SZ_2M` bounds. `alloc_pt()` increments `rsvd_page_tables.ptr`, so `panthor_vm_cleanup_op_ctx()` must bulk-free `count - ptr` entries at `pages + ptr` before `kfree(pages)`. [F140, F147]
- CSG slot IDs (`csg_id`) are 0-based in `[0, MAX_CSGS - 1]` (`MAX_CSGS` is 31; bit 31 of `JOB_INT_*` is `JOB_INT_GLOBAL_IF`, which `process_fw_events_work()` must clear before looping on `ffs(events) - 1`), whereas queue doorbell IDs in `group_bind_locked()` are `csg_id + 1` (0 is `CSF_GLB_DOORBELL_ID`). [F100, F121]
- Under `sched->lock`, `group_bind_locked()`/`group_unbind_locked()` must keep `group->csg_id`, `csg_slot->group`, `panthor_vm_active()`/`idle()`, `doorbell_id`, the slot's `group` ref, and `tiler_oom_work` in sync. Transitioning out of `PANTHOR_CS_GROUP_ACTIVE` in `csg_slot_sync_state_locked()` must call `cs_slot_reset_locked()` on every queue (suspending timeout unless in `group->blocked_queues`). [F73, F74]
- In `cs_slot_sync_queue_state_locked()`, `CS_STATUS_BLOCKED_REASON_SYNC_WAIT` only sets `BIT(cs_id)` in `group->blocked_queues` when `status_scoreboards == 0`. In `group_schedule_locked()`, skipping wakeup requires `(queue_mask & group->blocked_queues) == queue_mask`. [F75, F128]
- `queue_run_job()` updates `queue->fence_ctx.last_fence` with a ref to `job->done_fence` on non-empty jobs, and returns a ref to `last_fence` for sync-only jobs (`!job->call_info.size`). Before `drm_sched_start()`, `queue_start()` must restore `job->base.s_fence->parent = dma_fence_get(job->done_fence)` on all `pending_list` jobs. [F78, F86]
- `panthor_vm_pool::xa` and `panthor_group_pool::xa` use 1-based `XA_FLAGS_ALLOC1`, whereas `panthor_heap_pool::xa` uses 0-based `XA_FLAGS_ALLOC` in `[0, MAX_HEAPS_PER_POOL - 1]` to index `pool->gpu_contexts` at stride `panthor_heap_ctx_stride(ptdev)`. Adding/freeing a `panthor_heap_chunk` must update `heap->chunk_count` under `heap->lock` in lockstep with `pool->size`. [F91, F95, F96, F149]

## Synchronization

- `panthor_vm_pool_get_vm()` and `group_from_handle()` must hold `xa_lock(&pool->xa)` across `xa_load()` and ref acquisition. Iterating `panthor_group_pool` or `panthor_vm_pool` XArrays (`panthor_fdinfo_gather_group_samples()`, `panthor_vm_heaps_sizes()`) must hold `xa_lock()` across `xa_for_each()` and never take sleeping locks (`vm->heaps.lock`, `pool->lock`) inside it—`group->fdinfo.lock` is a `spinlock_t` and heap sizes use `panthor_heap_pool_size()`. [F26, F27, F174, F175]
- All GPUVA and page table ops on `panthor_vm` (`panthor_vm_exec_op()`, `panthor_vm_get_bo_for_va()`, `show_vm_gpuvas()`) must hold `vm->op_lock`, and `panthor_vm_exec_op()` must clear `vm->op_ctx = NULL` before unlocking. Because `panthor_vm_bind_run_job()` runs in the dma-signaling path, `panthor_vm_prepare_map_op_ctx()` and `unmap` must pre-allocate all VMAs, `sg_table` pages, `drm_gpuvm_bo`, and `rsvd_page_tables` upfront. [F45, F152, F176]
- `panthor_vma_link()` and `panthor_vma_unlink()` must hold `bo->base.base.gpuva.lock`, and callers of `drm_gpuvm_bo_obtain_prealloc()`, `drm_gpuvm_bo_extobj_add()`, and `panthor_vm_bo_put()` must acquire `panthor_vm_resv(vm)` before `gpuva.lock`, with `panthor_vm_bo_put()` holding extra refs on both the GEM and `drm_gpuvm` across unlock. [F182, F199]
- In `panthor_vm_active()`, if `refcount_inc_not_zero(&vm->as.active_cnt)` fails, the caller must lock `ptdev->mmu->as.slots_lock` and recheck `refcount_inc_not_zero()` before assigning an AS slot, pairing with `refcount_dec_and_mutex_lock()` in `panthor_vm_idle()`. Under `ptdev->mmu->vm.lock`, `panthor_vm_create()` must call `panthor_vm_stop(vm)` if `reset_in_progress` is true, and `panthor_vm_free()` must call `panthor_vm_start(vm)` if `reset_in_progress` is true before tearing down its scheduler. [F44, F46]
- `sched->reset.lock` must be acquired before `sched->lock`, and `panthor_sched_pre_reset()` must set `sched->reset.in_progress = true` before cancelling `sync_upd_work` and `tick_work`. `panthor_job_irq_handler()` must never acquire `sched->lock` (deferring to `fw_events_work`), because `tick_work` waits for firmware ACKs under `sched->lock`. [F43, F179]
- Because `sched->wq` (`WQ_MEM_RECLAIM`) is in the fence signaling path, `tiler_oom_work` must be queued on `sched->heap_alloc_wq`. In `group_process_tiler_oom()`, `sched->lock` must be dropped before `panthor_heap_grow()`, and after relocking `sched->lock`, `group->csg_id >= 0` must be rechecked and any unused chunk returned via `panthor_heap_return_chunk()` if scheduled out. [F41, F178]
- In `panthor_ioctl_group_submit()` and `panthor_ioctl_vm_bind_async()`, VM and BO `dma_resv` locks must be held via `ctx.exec` across `panthor_submit_ctx_add_deps_and_arm_jobs()` (which must add wait deps, arm, and update signal fences for job `i` in a single pass before job `i + 1`) and `panthor_submit_ctx_push_jobs()`. Inside `drm_exec_until_all_locked(&ctx.exec)`, `drm_exec_retry_on_contention(&ctx.exec)` must immediately follow `panthor_vm_bind_job_prepare_resvs()`. [F33, F122, F123]
- In `PANTHOR_IRQ_HANDLER` suspend helpers, `pirq->mask` must be cleared to 0 before masking `_INT_MASK` and calling `synchronize_irq()`, and `pirq->suspended = true` set only after `synchronize_irq()`. `panthor_fw_init()` must request job IRQ with `mask = 0` until `panthor_fw_start()` calls `panthor_job_irq_resume(&ptdev->fw->irq, ~0)` right before `MCU_CONTROL_AUTO`. [F28, F160]
- `panthor_device_unplug()` must serialize `drm_dev_unplug()` under `ptdev->unplug.lock`, unlock before subsystem unplug, and wait on/complete `ptdev->unplug.done`. Updating `ptdev->pm.state` to `SUSPENDING`/`ACTIVE` and `unmap_mapping_range()` must hold `ptdev->pm.mmio_lock`. If `panthor_device_reset_work()` aborts because `pm.state != ACTIVE`, it must leave `ptdev->reset.pending` set so `panthor_device_resume()` forces a slow reset. [F34, F35, F170]

## Object Lifetimes

- In `panthor_device_init()`, MMIO-accessing init functions (`panthor_hw_init()`, `panthor_gpu_init()`, `panthor_gpu_coherency_init()`, `panthor_mmu_init()`, `panthor_fw_init()`) must run only after `pm_runtime_resume_and_get()`, and failures must unwind in reverse order (`panthor_fw_unplug()` before `panthor_mmu_unplug()`). `panthor_gpu_suspend()` runs last in suspend and `panthor_gpu_resume()` runs first in resume. [F2, F14, F155, F157]
- Because `drmm_*` objects and `panthor_vm` instances can outlive `panthor_remove()`, `panthor_vm_free()`, `panthor_vm_flush_range()`, and `panthor_vm_active()` must guard MMIO accesses with `drm_dev_enter()`/`drm_dev_exit()`. [F161]
- Ownership transfers must clear the source pointer to `NULL` to prevent double-free: `ctx->jobs[i].job = NULL` after `drm_sched_entity_push_job()`; `sig_sync->chain = NULL` after `drm_syncobj_add_point()`; `op_ctx->map.vm_bo = NULL` after `panthor_vma_link()` (while `remap` passes `drm_gpuvm_bo_get()`); and `op_ctx->preallocated_vmas[i] = NULL` in `panthor_vm_op_ctx_get_vma()`. Replacing `sig_sync->fence` must take `dma_fence_get(done_fence)` before dropping `old_fence`. [F4, F5, F6, F7, F9]
- Because `drm_gpuva_unlink()` drops `vma->base.vm_bo`'s ref, `panthor_vma_unlink()` must call `drm_gpuvm_bo_get(vma->base.vm_bo)` beforehand, restore `vma->base.vm_bo` afterward, and append `vma` to `returned_vmas` so `panthor_vm_cleanup_op_ctx()` calls `panthor_vm_bo_put()` outside the fence signaling path. [F8]
- In `panthor_vm_prepare_map_op_ctx()` and `panthor_vm_bo_put()`, `drm_gem_shmem_pin()`/`unpin()` must be skipped when `drm_gem_is_imported(&bo->base.base)` is true; if `drm_gpuvm_bo_obtain_prealloc()` reuses an existing `vm_bo` or an earlier step fails on a non-imported BO, `drm_gem_shmem_unpin(&bo->base)` must be called. [F11, F200]
- A `panthor_gem_object` with `exclusive_vm_root_gem` aliases that VM's `resv`, must hold a ref on `exclusive_vm_root_gem` dropped in `panthor_gem_free_object()` only after `drm_gem_shmem_free(&bo->base)`, cannot be PRIME-exported, and only maps into that VM. `panthor_gem_create_with_handle()` must finish initializing all fields and debugfs insertion before `drm_gem_handle_create()`. `bo->label.str` must be freed with `kfree_const()`. [F12, F25, F153, F198]
- `panthor_group_destroy()` must not destroy `queue->entity` or `queue->scheduler`; teardown is deferred to `group_release_work()` on `panthor_cleanup_wq` when the final `group_put()` drops. `group_free_queue()`, `panthor_vm_bind_job_release()`, and `job_release()` must check `queue->scheduler.ops` before `drm_sched_fini()`, `job->base.s_fence` before `drm_sched_job_cleanup()`, and `job->done_fence && job->done_fence->ops` to choose between `dma_fence_put()` and `dma_fence_free()`. [F29, F56, F57, F180]
- Under `sched->lock`, the scheduler's runtime PM ref is tracked by `sched->pm.has_ref`: `tick_work()` and `queue_run_job()` (when `group->csg_id >= 0`, which also calls `panthor_devfreq_record_busy()`) call `panthor_device_resume_and_get()`/`pm_runtime_get()` only when `!sched->pm.has_ref`, and drop it only when `sched->pm.has_ref` is true. [F24, F77, F173]
- `panthor_heap_pool::vm` is a weak pointer cleared to `NULL` in `panthor_heap_pool_destroy()` under `down_write(&pool->lock)`, so `panthor_heap_create()` must take `panthor_vm_get(pool->vm)` under `down_read(&pool->lock)` and reverify `pool->vm` under `down_write(&pool->lock)`. In `panthor_devfreq_init()` and `panthor_devfreq_target()`, OPP refs must be acquired after fallible regulator setup and released with `dev_pm_opp_put()` on all paths. [F3, F15]

## API Contracts

- `panthor_vm_get_heap_pool()` returns an `ERR_PTR()` (never `NULL`), whereas `panthor_heap_pool_put()`, `panthor_vm_put()`, and `panthor_devfreq` callbacks only check for `NULL`; never pass an `ERR_PTR()` to `panthor_heap_pool_put()`, and reset `ERR_PTR()` in `fw->vm` or `pdevfreq->devfreq` to `NULL` on init failure. Conversely, `panthor_vm_pool_get_vm()` and `group_from_handle()` return `NULL` on miss, while `panthor_vm_get_bo_for_va()` returns `ERR_PTR(-ENOENT)`. [F48, F49, F55]
- `panthor_heap_create()` returns 0-based IDs, so callers must check `ret < 0` and reset `ret = 0`. UAPI heap handles pack `(vm_id << 16) | heap_id`, whereas `panthor_heap_destroy()` takes `args->handle & GENMASK(15, 0)`. [F50, F66]
- `panthor_vm_root_gem(vm)` is a base `struct drm_gem_object` and must never be downcast with `to_panthor_bo()`. `panthor_submit_ctx` jobs may be `panthor_job` or `panthor_vm_bind_job` and must use `job_put` and `upd_resvs` callbacks rather than downcasting. [F150, F151]
- `panthor_job_update_resvs()` and `panthor_vm_bind_job_update_resvs()` must use `DMA_RESV_USAGE_BOOKKEEP`. `panthor_job_create()` must verify `group_can_run(job->group)`. `panthor_vm_map_pages()` and `panthor_vm_unmap_pages()` must split ops at `SZ_2M`/`SZ_1G` boundaries via `get_pgsize()` and call `panthor_vm_flush_range()`, and `mmu_hw_do_operation_locked()` must send `AS_COMMAND_UNLOCK` and `wait_ready()` after `panthor_gpu_flush_caches()`. [F68, F189, F190, F194]
- `PANTHOR_IRQ_HANDLER` suspend/resume helpers must not use `drm_dev_enter()`; `panthor_*_unplug()` callers must guard them with `!IS_ENABLED(CONFIG_PM) || pm_runtime_active(ptdev->base.dev)`. [F159]
- Indirect UAPI objects/arrays must use `PANTHOR_UOBJ_SET()` and `PANTHOR_UOBJ_GET_ARRAY()`, and extending a struct in `PANTHOR_UOBJ_MIN_SIZE` must keep its original `_last_mandatory_field` in `PANTHOR_UOBJ_DECL`. `panthor_drm_driver_fops` requires `FOP_UNSIGNED_OFFSET`, and `panthor_device_mmap_io()` must require `VM_SHARED` and call `vm_flags_clear(vma, VM_MAYWRITE)` on read-only mappings. [F52, F145, F191, F193, F196]

## Error Handling

- `panthor_heap_grow()` returns `-ENOMEM` when limits are reached or allocation fails, and `group_process_tiler_oom()` must treat `-ENOMEM` as non-fatal by acknowledging `CS_TILER_OOM` with `new_chunk_va = 0`. [F51]
- `panthor_fw_wait_acks()` and `panthor_fw_csg_wait_acks()` populate `*acked` even on `-ETIMEDOUT` (with `panthor_fw_csg_wait_acks()` clearing `CSG_STATE_MASK` unless all state bits matched), and `csgs_upd_ctx_apply_locked()` must sync state for `*acked` bits before handling `-ETIMEDOUT`. When `CSG_STATE_SUSPEND` times out in `panthor_sched_suspend()`, affected groups must be marked `timedout = true` before `CSG_STATE_TERMINATE`. [F58, F76, F119]
- In `panthor_vm_prepare_map_op_ctx()` and `unmap`, both `!pages` from `kcalloc()` and `ret != pt_count` from `kmem_cache_alloc_bulk()` must set `ret = -ENOMEM` before `goto err_cleanup`. Never assign `ret = drm_WARN_ON(...)` when returning `ret` as an errno. [F53, F54]

## External Contracts

- UAPI output structs with padding (`panthor_query_group_priorities_info()`, `panthor_group_get_state()`) must be zeroed with `memset()`, and `panthor_ioctl_dev_query()` changes must update both the size switch and copy switch. In `panthor_ioctl_vm_bind_sync()`, if op `i` fails, `args->ops.count = i` must be set before returning. [F59, F90, F107]
- Group priorities > `MEDIUM` require `group_priority_permit()`, and `panthor_ioctl_group_create()` must enforce `1 <= args->queues.count <= MAX_CS_PER_CSG`. In `panthor_heap_create()`, `initial_chunk_count` must be in `[1, max_chunks]` and `chunk_size` page-aligned in `[SZ_128K, SZ_8M]`; `panthor_heap_return_chunk()` must mask `chunk_gpu_va` with `GENMASK_ULL(63, 12)` because bits 11:0 encode `chunk_size >> 12`. [F97, F138, F139, F195]

## Known Pitfalls

- `panthor_fw_ring_csg_doorbells()` takes a CSG bitmask (`BIT(csg_id)`), despite its parameter being named `csg_slot`, whereas `panthor_fw_get_csg_iface()` and `panthor_fw_csg_wait_acks()` take a 0-based index (and must reject `>= MAX_CSGS` / `>= MAX_CS_PER_CSG`). [F63, F99]
- Cast to `u64` before shifting >= 32 bits: `vma->vm_pgoff` before `<< PAGE_SHIFT` in mmap/fault paths; the high word in `gpu_read64*()` (and use `gpu_read64_counter()` for live counters like `GPU_TIMESTAMP`); `out_attr` in `mair_to_memattr()`; `status_wait_sync_value_hi` in `cs_slot_sync_queue_state_locked()`; and `panthor_job_cs_params` register fields in `prepare_job_instrs()`. [F129, F130, F132, F133, F134, F166]
- In `panthor_vm_map_pages()`, reset `offset = 0` at the end of each `for_each_sgtable_dma_sg()` iteration and abort if `!ret && !mapped`. In `panthor_get_uobj_array()`, check `!in->count` before `in->stride < min_stride`, and advance `out_ptr` by `obj_size` and `in_ptr` by `in->stride`. In `tick_ctx_cleanup()`, do not dereference the loop cursor `group` outside the loop. In `group_schedule_locked()`, check `sched->resched_target != U64_MAX` before `time_before64()`. [F114, F115, F116, F117, F118, F144]
