# IOMMU SUBSYSTEM

Core Linux IOMMU subsystem infrastructure and SoC-specific IOMMU drivers (`fsl_pamu`, `ipmmu-vmsa`, `mtk_iommu` v1/v2, `omap-iommu`, `sprd-iommu`). It manages IOMMU device and group lifecycles, domain allocation and attachment (including PASID and SVA), IOVA mapping/unmapping, IO page tables and page fault queues (IOPF), and Device Tree translation (`of_iommu`).

## Architecture & Data Flow
- Dynamically allocated `struct iommu_domain`s must set `domain->owner = dev_iommu_ops(dev)` (via `iommu_domain_init()` or `iommu_sva_domain_alloc()`), while compatibility checks must use `domain_iommu_ops_compatible(ops, domain)` rather than `domain->owner == ops` because static `blocked_domain` and `identity_domain` leave `owner` unset. [F41, F190]
- In `iommu_setup_default_domain()`, `group->default_domain` must be set to `dom` before calling `__iommu_group_set_domain_internal()` or `__iommu_group_set_domain()`; if attaching or creating direct mappings fails with non-NULL `old_dom`, both `group->domain` and `group->default_domain` must revert to `old_dom`. [F56]
- `__iommu_take_dma_ownership()` and `__iommu_release_dma_ownership()` require `xa_empty(&group->pasid_array)` and must switch `group->domain` to `group->blocking_domain` when setting `group->owner` and back to `group->default_domain` when clearing `group->owner` and `group->owner_cnt`. [F61]
- `struct iommu_group::pasid_array` stores tagged XArray pointers via `iommu_make_pasid_array_entry()` (`IOMMU_PASID_ARRAY_DOMAIN` or `IOMMU_PASID_ARRAY_HANDLE`); readers must check `xa_pointer_tag()` and call `xa_untag_pointer()` before dereferencing. [F135]
- Global PASIDs are allocated from `iommu_global_pasid_ida` in `[IOMMU_FIRST_GLOBAL_PASID, dev->iommu->max_pasids - 1]` (reserving `0` / `IOMMU_NO_PASID` for RID-level handles), and `iommu_alloc_mm_data()` must reject an existing `mm->iommu_mm` when `iommu_mm->pasid >= dev->iommu->max_pasids`. [F81]
- Because `__iommu_probe_device()` de-duplicates deferred groups onto `group_list` using `if (list_empty(&group->entry))`, `bus_iommu_probe()` must unlink each group with `list_del_init(&group->entry)` rather than `list_del()`. [F116]
- `struct ioptdesc` (`iommu-pages.h`) overlays `struct page` and is cast to/from `struct folio *` via `folio_ioptdesc()`/`ioptdesc_folio()`, so its field offsets must match `struct page` and `iopt_freelist_elm` must keep bit 0 clear. [F133]
- In `mtk_iommu.c`, shared page-table (`share_dom` in `mtk_iommu_domain_finalise()`, always recorded and reused even without `SHARE_PGTABLE`) and group state (`m4u_group[]`) must be accessed on `mtk_iommu_get_frst_data(hw_list)` under its `mutex`, whereas per-bank hardware state uses the device's own `data`. `mtk_iommu_tlb_flush_range_sync()` must iterate over every `mtk_iommu_data` on `bank->parent_data->hw_list` to flush `data->bank[bank->id]`. [F70, F71, F112]

## Synchronization
- `iommu_probe_device_lock` must be held across `dev_iommu_get()`, `__iommu_probe_device()`, `dev_iommu_priv_set()` (when `!CONFIG_FSL_PAMU`), `of_iommu_configure()`, and `iommu_fwspec_init()`. `iommu_init_device()` is entered and exited with `iommu_probe_device_lock` held; when it unlocks to call `dev->bus->dma_configure(dev)`, it must reacquire the lock and recheck `!dev->iommu || dev->iommu_group`. `ops->probe_finalize(dev)` must be called outside both `group->mutex` and `iommu_probe_device_lock`. [F14, F27, F146, F171]
- `iommu_device_register()` and `iommu_device_register_bus()` must set `WRITE_ONCE(iommu->ready, true)` only after `bus_iommu_probe()` succeeds, paired with `iommu_fwspec_init()` returning `-EPROBE_DEFER` when `!dev->iommu && !READ_ONCE(iommu->ready)`. In `iommu_device_use_default_domain()`, after taking `group->mutex`, it must check `if (!group->default_domain)` and return `-EPROBE_DEFER` before incrementing `group->owner_cnt`. [F17, F29]
- `iommu_sva_lock` must be held (nesting outside `group->mutex`) across `iommu_sva_bind_device()` and `iommu_sva_unbind_device()` to serialize `mm->iommu_mm->sva_domains`, `domain->users`, and `handle->users`, and in `iommu_alloc_mm_data()`, which must initialize `iommu_mm->pasid` and `iommu_mm->sva_domains` before `smp_store_release(&mm->iommu_mm, iommu_mm)`. [F18, F31]
- In `io-pgfault.c`, mutex locking must follow `queue->lock` -> `dev->iommu->lock` (`param->lock`) -> `fault_param->lock`, and `iopf_queue_flush_dev()` must never be called under `fault_param->lock`. `fault_param->lock` protects `partial`, `faults`, and `group->pending_node` across `ops->page_response()` and `list_del_init(&group->pending_node)`. [F23, F166]
- `iopf_queue_add_device()` must initialize all `fault_param` fields (`users = 1`, `lock`, lists) before `rcu_assign_pointer(param->fault_param, fault_param)` under `queue->lock` and `param->lock`; `iopf_get_dev_fault_param()` must use `rcu_dereference()` and `refcount_inc_not_zero(&fault_param->users)` under `rcu_read_lock()`, paired with `kfree_rcu(fault_param, rcu)`. [F19, F164]
- `iommu_sva_handle_mm()` runs on an unbound workqueue thread and must pin `mm` via `mmget_not_zero(mm)`, hold `mmap_read_lock(mm)`, and pass `FAULT_FLAG_REMOTE` and `regs = NULL` to `handle_mm_fault()` before `mmap_read_unlock(mm)` and `mmput(mm)`. [F168]
- In `mtk_iommu.c`, TLB invalidations in `mtk_iommu_tlb_flush_all()` and `mtk_iommu_tlb_flush_range_sync()` must hold `spin_lock_irqsave(&bank->tlb_lock, flags)`, and `mtk_iommu_tlb_flush_range_sync()` must drop `curbank->tlb_lock` before calling `mtk_iommu_tlb_flush_all()` on timeout. [F36]
- In `omap-iommu.c`, `iopte_alloc()` drops `obj->page_table_lock` around `kmem_cache_zalloc()`, so after re-acquiring the lock it must re-check `!*iopgd` and call `iopte_free(obj, iopte, false)` if already populated. Every write to `iopgd` or `iopte` must be followed by `flush_iopte_range()`, and `iopte_alloc()` requires `*pt_dma == virt_to_phys(iopte)`. [F74, F181]

## Object Lifetimes
- Pages from `iommu_alloc_pages_node_sz()` / `iommu_alloc_pages_sz()` account `1UL << order` pages to `NR_IOMMU_PAGES` and `NR_SECONDARY_PAGETABLE` and must only be freed via `iommu_free_pages()` or `iommu_put_pages_list()` (`__iommu_free_desc()`). [F2]
- In `iommu_report_device_fault()`, the `iopf_param` reference from `iopf_get_dev_fault_param()` is either dropped via `iopf_put_dev_fault_param()` after `report_partial_fault()` (when `!(fault->prm.flags & IOMMU_FAULT_PAGE_REQUEST_LAST_PAGE)`, returning immediately) or transferred to `group->fault_param` by `iopf_group_alloc()`. `__iopf_free_group()` must only `kfree(iopf)` on non-last faults because `group->last_fault` is embedded in `struct iopf_group`. [F3, F105, F106]
- In `iommu_report_device_fault()`, when `domain->iopf_handler(group)` returns `0`, the handler owns `group` and must call `iopf_group_response()` and `iopf_free_group()`; on handler error or `abort_group` fallback, `err_abort` must call `iopf_group_response()` and free `group` (using `__iopf_free_group()` if `group == &abort_group`). [F4, F134, F201]
- In `iopf_queue_remove_device()`, under `fault_param->lock`, all partial faults on `fault_param->partial` must be freed and each pending `iopf_group` on `fault_param->faults` must be responded to, unlinked with `list_del_init(&group->pending_node)`, and freed via `iopf_free_group()` before dropping `param->fault_param`. [F6]
- Under `iommu_sva_lock`, `iommu_sva_bind_device()` must `kfree(handle)` on failure, and `iommu_sva_unbind_device()` must detach the PASID and free `handle` only when `handle->users` reaches zero and free `domain` only when `--domain->users == 0`. `iommu_sva_domain_alloc()` takes `mmgrab(mm)` (`domain->cookie_type = IOMMU_COOKIE_SVA`), which `iommu_domain_free()` releases via `mmdrop(domain->mm)` before `domain->ops->free(domain)`. [F7, F8]
- `iommu_group_alloc()` drops its initial reference on `group->kobj` after creating child `group->devices_kobj`, so `iommu_group_get()`, `iommu_group_ref_get()`, and `iommu_group_put()` must operate on `group->devices_kobj` rather than `&group->kobj`. [F9]
- In `iommu_deinit_device()`, `ops->release_device(dev)` must stop using any attached `iommu_domain`; when `list_empty(&group->devices)` becomes true, `group->default_domain` and `group->blocking_domain` must be freed via `iommu_domain_free()` and set to `NULL` (with `group->domain`) after `ops->release_device(dev)` and before `module_put(ops->owner)`. [F10, F188]
- After calling `iommu_fwspec_add_ids()`, callers must re-read `dev_iommu_fwspec_get(dev)` because `iommu_fwspec_add_ids()` may `krealloc()` the `iommu_fwspec`. Before calling `iommu_device_register()`, an IOMMU driver's probe must call `platform_set_drvdata()` and initialize all state read by `iommu_ops` callbacks because `iommu_device_register()` synchronously runs `bus_iommu_probe()`. [F132, F144]

## API Contracts
- `iommu_put_pages_list()` and `iommu_pages_list_splice()` leave the source `struct iommu_pages_list` head invalid; callers reusing it must reinitialize it with `IOMMU_PAGES_LIST_INIT`. [F1]
- `struct iommu_iotlb_gather` must be initialized and reset with `iommu_iotlb_gather_init()` (setting `start = ULONG_MAX`), never zero-initialized. Both `gather.end` and `iommu_domain_geometry.aperture_end` are inclusive (`start + size - 1`), so range size calculations must add 1 (`end - start + 1`). Paging domains that only translate within `[aperture_start, aperture_end]` must set `geometry.force_aperture = true`. [F49, F50, F193]
- Before accessing the `struct iommu_domain` cookie union (`handler`, `iova_cookie`, `msi_cookie`, `mm`), callers must verify `domain->cookie_type` matches the active variant. [F39]
- `iommu_report_device_fault()` must only be called from sleepable context (`GFP_KERNEL`, `fault_param->lock` mutex). Before `iopf_queue_flush_dev()` or `iopf_queue_remove_device()`, the driver must disable new fault/PRI generation in the IOMMU and flush hardware fault queues (`iopf_queue_flush_dev()` only before `iopf_queue_remove_device()`), and only disable PRI on the endpoint device after `iopf_queue_remove_device()` responds to outstanding faults. [F22, F147, F165]
- In `iommu_attach_device_pasid()`, `__iommu_set_group_pasid()`, and `__iommu_remove_group_pasid()`, every `group->devices` loop must skip devices with `max_pasids == 0`, reject `pasid == IOMMU_NO_PASID`, and verify `pasid < device->dev->iommu->max_pasids` before inserting into `group->pasid_array` or calling `set_dev_pasid`. [F80, F102]
- Drivers supporting PASID attachment must provide `domain->ops->set_dev_pasid`, `iommu_ops->blocked_domain`, and an infallible `blocked_domain->ops->set_dev_pasid`. Callers of PASID or group handle attach/replace APIs must always pass a freshly allocated `struct iommu_attach_handle`. [F173, F197]
- Before calling `free_io_pgtable_ops()`, the driver must disable hardware page-table walks on the domain. Domain callbacks invoked before device attachment (`flush_iotlb_all`, `free`, `map_pages`) must NULL-check attachment-populated pointers (`dom->bank` in `mtk_iommu`, `domain->mmu` in `ipmmu-vmsa`, `dom->sdev` in `sprd-iommu`). [F44, F183]

## Error Handling
- Unlike `ops->domain_alloc_paging` (where `NULL` becomes `ERR_PTR(-ENOMEM)`), `ops->domain_alloc_identity`, `ops->domain_alloc_sva`, `iommu_group_alloc_default_domain()`, and `__iommu_group_alloc_default_domain()` must return an `ERR_PTR` (never `NULL`) on failure because callers only check `IS_ERR()`. [F40, F42]
- `iommu_map_nosync()` must initialize `mapped = 0` each iteration and subtract `size -= mapped` before `if (ret) break;`, and `ops->map_pages` must add any bytes mapped before an error to `*mapped` so `iommu_unmap()` unrolls partial mappings. While `iommu_map()` returns `int` and `iommu_map_sg()` returns `ssize_t`, `iommu_unmap()`, `iommu_unmap_fast()`, and `ops->unmap_pages` return an unsigned `size_t` byte count (`0` on error). [F47, F115, F194]
- In `__iommu_group_set_domain_internal()`, if `IOMMU_SET_DOMAIN_MUST_SUCCEED` is set, failure in `__iommu_device_set_domain()` must record `result = ret` and `continue` (falling back to `group->blocking_domain`). [F104]
- On revert (`err_revert`), `__iommu_group_set_domain_internal()` leaves `group->domain` unchanged and re-attaches `group->domain` to preceding devices including `last_gdev` (`if (gdev == last_gdev) break;` at loop end), whereas `__iommu_set_group_pasid()` stops before `last_gdev` (`if (device == last_gdev) break;` at loop start) and restores `old->ops->set_dev_pasid()` or calls `iommu_remove_dev_pasid()`. [F57, F58, F103]
- When `iommu_report_device_fault()` fails before constructing an `iopf_group` (`err_bad_iopf`), it must complete any `IOMMU_FAULT_PAGE_REQ` event via `iopf_error_response()` (`IOMMU_PAGE_RESP_INVALID`). [F5]
- `iommu_alloc_global_pasid()` must verify `dev->iommu->max_pasids > 0` before subtracting 1 for `ida_alloc_range()`, check the `int` return for `< 0`, and return `IOMMU_PASID_INVALID` (`-1U`) on failure; callers must test `pasid == IOMMU_PASID_INVALID` rather than `< 0`. In `dev_iommu_get_max_pasids()`, `pci_max_pasids()` must be checked for `ret > 0` before assigning to `u32`. [F52, F123, F125]

## Known Pitfalls
- In `iommu_map_sg()`, keep `while (i <= nents)` paired with `if (++i < nents) sg = sg_next(sg)` so iteration `i == nents` flushes the final segment; in `iommu_create_device_direct_mappings()`, keep `if (addr == end) goto map_end;` before `iommu_iova_to_phys(domain, addr)` in `for (addr = start; addr <= end; addr += pg_size)`. [F113, F114]
- `iommu_pgsize()` must check `addr_merge` (`paddr | iova`) for non-zero before `__ffs(addr_merge)` and use `check_add_overflow(offset, pgsize_next, &offset_end)` before comparing `offset_end <= size` (avoiding 32-bit `size_t` wrap). [F122, F124]
- In `.attach_dev` for static identity/platform domains (`fsl_pamu_platform_attach()`, `ipmmu_iommu_identity_attach()`, `omap_iommu_identity_attach()`), verify the previous `domain` from `iommu_get_domain_for_dev(dev)` is non-NULL and not the static domain before calling `to_fsl_dma_domain()`, `to_vmsa_domain()`, or `to_omap_domain()`. [F137]
- In `mtk_iommu.c`, test hardware type with `MTK_IOMMU_IS_TYPE(pdata, type)` rather than `MTK_IOMMU_HAS_FLAG()` because `MTK_IOMMU_TYPE_MM` is `0`; keep `++i` inside the `while (++i < ...)` condition of bank `do { ... } while` loops so `continue` on disabled banks advances `i`; and never pass `size == 0` to `mtk_iommu_tlb_flush_range_sync()` or `mtk_iommu_v1_tlb_flush_range()` (`iova + size - 1` underflows `REG_MMU_INVLD_END_A`). [F90, F110, F111]
- In `omap-iommu`, `IOPGD_SUPER` (`BIT(18) | IOPGD_SECTION`) includes `IOPGD_SECTION`, so use `iopgd_is_section()` / `iopgd_is_super()` (masking with `(1 << 18 | 3)`); and pass byte offsets (`iopgd_index(da) * sizeof(da)`) to `flush_iopte_range()`, whereas `iopgd_offset()`/`iopte_offset()` use `u32 *` index arithmetic. [F118, F140]
- In `ipmmu_domain_irq()`, read `IMELAR`/`IMEUAR` before writing `0` (not 1s) to `IMSTR` because clearing `IMSTR` resets the fault address registers. [F157]
