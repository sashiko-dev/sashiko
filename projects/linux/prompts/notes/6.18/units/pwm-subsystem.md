# PWM SUBSYSTEM

The PWM subsystem (`drivers/pwm/core.c`, `drivers/pwm/pwm-*.c`, and `drivers/gpio/gpio-mvebu.c`) manages PWM chip registration, channel lookup (DT, ACPI, static tables), state and waveform rounding/application, and sysfs, `/dev/pwmchip*`, GPIO (`CONFIG_PWM_PROVIDE_GPIO`), and debugfs interfaces, while controller drivers translate nanosecond states or waveforms into hardware timer configurations, bus transactions, or hrtimer-driven GPIO toggles.

## Architecture & Data Flow

- `struct pwm_chip` unions `nonatomic_lock` and `atomic_lock` discriminated by `chip->atomic`, which must be set before `__pwmchip_add()` initializes the lock and never changed afterwards. [F37]
- `pwmchip_alloc()` and `pwmchip_priv()` must compute the `struct pwm_chip` and `pwms[]` size with `struct_size(chip, pwms, npwm)`, `ALIGN(..., PWMCHIP_ALIGN)`, and `size_add(..., sizeof_priv)`; `chip->npwm` is set before calling `pwmchip_priv()` and must never be increased after allocation (`pwms` is `__counted_by(npwm)`). [F117, F119]
- `pwmchip_from_dev()` must only be called on a controller device (`&chip->dev`), whereas `pwmexport_from_dev()` and `pwm_from_dev()` must only be called on an exported channel child device (`&export->pwm_dev`). [F121]
- In `__pwm_apply()`, `pwm->state = *state` must be assigned only after `ops->apply()` or `__pwm_write_waveform()` succeeds and before `pwm_apply_debug()` runs; in `pwm_apply_debug()`, rounding/polarity checks must be skipped when `!s1.enabled`, and the `state->period < s2.period` warning must be gated on `s2.duty_cycle != 0`. [F52, F93]
- `pwm_wf_valid()` requires `wf->period_length_ns <= S64_MAX`, `wf->duty_length_ns <= wf->period_length_ns`, and `wf->duty_offset_ns == 0 || wf->duty_offset_ns < wf->period_length_ns` (preventing underflow in `pwm_wf2state()`); in `pwm_state_valid()`, an enabled `struct pwm_state` requires `period > 0` and `duty_cycle <= period`, whereas `!state->enabled` is valid regardless of `period` and `duty_cycle`. Broken by: subtracting `state->period - state->duty_cycle` or dividing by `state->period` in `.apply()` before checking `state->enabled`. [F73, F74]
- `dwc_pwm_probe()` registers `ddata->info->nr` `struct pwm_chip` instances per PCI device; per-chip `struct dwc_pwm` must be in `pwmchip_get_drvdata(chip)` while `dev_set_drvdata()` stores `struct dwc_pwm_drvdata` (`ddata->chips[]`) so `dwc_pwm_suspend()`/`dwc_pwm_resume()` iterate over all chips. [F55]
- In `pwm-imx-tpm.c`, `pwm_imx_tpm_suspend()` must reset `tpm->real_period = 0` when `tpm->enable_count == 0` because suspend resets hardware period registers and `pwm_imx_tpm_apply_hw()` skips reprogramming when `state->period == tpm->real_period`; changing `tpm->real_period` must fail with `-EBUSY` if `tpm->user_count > 1` or if `cmod != 0 && cur_prescale != p->prescale`, and when `!cmod`, `PWM_IMX_TPM_CNT` must be reset to `0` before writing `PWM_IMX_TPM_MOD` and polling `PWM_IMX_TPM_MOD`/`PWM_IMX_TPM_CnV` until latched or `-ETIME`. [F56, F57, F134]
- Shared-period/pin drivers: `fsl_pwm_apply_config()` must return `-EBUSY` if `periodcfg` changes while `fsl_pwm_is_other_pwm_enabled(fpc, pwm)` is true and swap `fpc->clk[newclk]`/`fpc->clk[oldclk]` when `clk_select` changes; `lpc18xx_pwm_config()` must return `-EBUSY` on changing non-zero `period_ns` when `bitmap_weight(&lpc18xx_pwm->event_map, LPC18XX_PWM_EVENT_MAX) > 2`; `lp3943_pwm_request_map()`/`lp3943_pwm_free_map()` must claim and clear `pwm_map->output[]` bits in `lp3943->pin_used`. [F59, F60, F61]
- In `pwm_imx27_apply()`, because `MX3_PWMSAR` cannot be read while disabled, `duty_cycles` must be cached in `imx->duty_cycle` for `pwm_imx27_get_state()` when `!state->enabled`, and updated only after the ERR051198 FIFO workaround compares and writes the previous `imx->duty_cycle` under `local_irq_save()` when `cr & MX3_PWMCR_EN`, decreasing `duty_cycles`, and `period_us < 2` or `MX3_PWMSR_FIFOAV` has under 2 words. [F66, F135]
- Clock rate and 64-bit bounds checks: `pwm_mediatek_clk_enable()` and `lpc18xx_pwm_probe()` must reject `!rate` or `rate > NSEC_PER_SEC` (with `lpc18xx_pwm_probe()` storing `max_period_ns` as `u64` and `min_period_ns = DIV_ROUND_UP(NSEC_PER_SEC, clk_rate)`); `bcm2835_pwm_apply()` must check `state->period` against `max_period = DIV_ROUND_UP_ULL((u64)U32_MAX * NSEC_PER_SEC + NSEC_PER_SEC / 2, pc->rate) - 1` before multiplying `state->period * pc->rate`. [F108, F111, F112]

## Synchronization

- In `drivers/pwm/core.c`, `pwmchip_lock(chip)` nests inside both `pwm_lock` and `export->lock`; neither `pwm_lock` nor `export->lock` may be acquired while holding `pwmchip_lock(chip)`, and `chip->operational` is modified only while holding both `pwm_lock` (outer) and `scoped_guard(pwmchip, chip)` (inner) so holding either lock suffices to read it. [F17, F20]
- `ops->request` and `ops->free` run under `pwm_lock` without `pwmchip_lock(chip)`, whereas `ops->apply`, `ops->get_state`, and waveform callbacks run under `pwmchip_lock(chip)` without `pwm_lock`; multi-channel drivers accessing shared chip state across both groups (such as `tpm->lock` in `pwm_imx_tpm_request()`, `pwm_imx_tpm_free()`, and `pwm_imx_tpm_apply()`) must use a driver-internal lock. [F18, F28]
- When `chip->atomic` is true, `pwmchip_lock()` acquires `spin_lock(&chip->atomic_lock)`, so `apply`, `get_state`, `capture`, and waveform callbacks execute in atomic context and must not sleep. [F142]
- In `pwmchip_remove()`, `gpiochip_remove(&chip->gpio)` and `pwmchip_sysfs_unexport(chip)` must be called before acquiring `pwm_lock`, because `pwm_gpio_free()` and `pwm_unexport_child()` call `pwm_put()`, which acquires `pwm_lock`; paths already holding `pwm_lock` (`pwm_cdev_free()`, `pwm_cdev_ioctl()`, and `pwm_seq_show()`/`pwm_dbg_show()`) must use `__pwm_put()` and never call `pwm_put()`, `pwm_capture()`, or `pwmchip_find_by_name()`. [F19, F147, F148]
- `pwm_class_get_state()` drops the `device_find_child()` reference on `pwm_dev` and returns `export` with `export->lock` held; callers (`pwm_class_suspend()`, `pwm_class_resume_npwm()`) must unlock `export->lock` on every path via `pwm_class_apply_state()` or `mutex_unlock(&export->lock)`. [F7]
- In `pwm-gpio.c`, because `pwm_gpio_timer()` runs in hardirq `HRTIMER_MODE_REL` context and acquires `gpwm->lock`, `pwm_gpio_apply()` and `pwm_gpio_get_state()` must use `guard(spinlock_irqsave)(&gpwm->lock)` and call `hrtimer_cancel(&gpwm->gpio_timer)` outside `gpwm->lock`; reconfiguring when `gpwm->running && state->enabled` must stage `gpwm->next_state` and set `gpwm->changing = true`, and `pwm_gpio_get_state()` must return `gpwm->next_state` when `gpwm->changing` is true. [F65, F152]

## Object Lifetimes

- Every `struct pwm_chip` passed to `__pwmchip_add()` must be allocated via `pwmchip_alloc()` or `devm_pwmchip_alloc()` (setting `chip->uses_pwmchip_alloc`) and released via `pwmchip_put()` (`put_device(&chip->dev)`). [F1]
- `pwm_device_request()` acquires `try_module_get(chip->owner)` then `get_device(&chip->dev)` before `ops->request()` and must roll them back in reverse order on failure; when `pwmchip_remove()` marks `chip->operational = false`, it clears `PWMF_REQUESTED` and calls `ops->free()`, so `__pwm_put()` must gate its `PWMF_REQUESTED` check and `ops->free()` call on `chip->operational` while still calling `put_device(&chip->dev)` and `module_put(chip->owner)`. [F2, F3]
- In `export_store()`, the `pwm_request_from_chip()` reference must be released via `pwm_put(pwm)` if `pwm_export_child()` fails or when `pwm_unexport_child()` unregisters the child device (after `put_device(pwm_dev)`); in `pwm_export_child()`, once `device_register(&export->pwm_dev)` is called, failure must clear `PWMF_EXPORTED` and call `put_device(&export->pwm_dev)` rather than `kfree(export)`. [F5, F6]
- In `of_pwm_get()` and `pwm_get()`, if `pwm_device_link_add()` returns an `ERR_PTR`, `pwm_put(pwm)` must be called; `of_pwm_get()` must always call `of_node_put(args.np)` after `of_parse_phandle_with_args_map()` succeeds, and `of_pwmchip_add()`'s `of_node_get()` must be balanced by `of_pwmchip_remove()` in `pwmchip_remove()` and `__pwmchip_add()` error paths. [F9, F130]
- For channels requested via `pwm_cdev_request()`, `pwm_cdev_free()` and `pwm_cdev_release()` must save `pwm->label` before calling `__pwm_put()`/`pwm_put()` (which zeroes `pwm->label`), then `kfree(label)`, and `pwm_cdev_free()` must clear `cdata->pwm[hwpwm] = NULL`. [F10]
- Callers of `devm_add_action_or_reset()` (or `devm_*` wrappers) must not also invoke the cleanup callback on error, and registered callbacks must be dedicated `void (*)(void *)` wrappers (such as `devm_pwmchip_put`, `devm_pwmchip_remove`, `devm_pwm_release`) rather than cast typed functions. [F11, F123]
- Drivers that access MMIO registers in `.probe()` must enable peripheral clocks first; drivers whose `.suspend()`, `.resume()`, or `.remove()` call `dev_get_drvdata()`/`platform_get_drvdata()` must set matching drvdata in `.probe()`; and explicit `.remove()` callbacks (`atmel_hlcdc_pwm_remove`, `atmel_tcb_pwm_remove`, `hibvt_pwm_remove`, `lpc18xx_pwm_remove`, `pwm_clk_remove`) must call `pwmchip_remove(chip)` before stopping hardware or disabling clocks (and `atmel_tcb_pwm_probe()`/`remove()` must release `slow_clk`, `gclk`, `clk` in LIFO order). [F12, F126, F127, F128]
- In `pwm_gpio_probe()`, `gpwm->lock` and `gpwm->gpio_timer` must be initialized, `pwm_gpio_disable_hrtimer` registered via `devm_add_action_or_reset()`, and `gpiod_cansleep(gpwm->gpio)` rejected before `pwmchip_add(chip)` exposes the chip. [F129, F151]

## API Contracts

- In `pwm_ops_check()`, a chip with `ops->write_waveform` must also provide `round_waveform_tohw` and `round_waveform_fromhw` and have `ops->sizeof_wfhw <= PWM_WFHWSIZE` (20 bytes, which callbacks must not overrun on the `void *wfhw` stack buffer), whereas a chip without `write_waveform` must provide `ops->apply`; only chips with `ops->write_waveform` get a `/dev/pwmchip*` `devt` and `CONFIG_PWM_PROVIDE_GPIO` `gpio_chip`. [F120, F156, F167]
- `round_waveform_fromhw`, `read_waveform`, and `write_waveform` must return `0` on success or a negative errno and never return positive values (unlike `round_waveform_tohw`, which returns `1` when rounding up); in `struct pwm_waveform`, a disabled PWM is represented by `period_length_ns == 0` (not `duty_length_ns == 0`). [F30, F41]
- Because `pwm_get_state_hw()` does not zero-initialize `*state`, `.get_state()` must explicitly initialize `state->polarity` and `state->enabled` (and `period`/`duty_cycle` when enabled); `.apply()` must reject unsupported `state->polarity` with `-EINVAL`, round `period` (when `duty_cycle != 0`) and `duty_cycle` down to hardware ticks, and `.get_state()` must round tick-to-ns divisions up (e.g., `DIV_ROUND_UP_ULL`) so reapplying `.get_state()` is idempotent. [F38, F105, F158]
- `pwmchip_alloc()` and `devm_pwmchip_alloc()` return `ERR_PTR()` on failure (never `NULL`, so callers must check `IS_ERR()`) and store `pwmchip_priv(chip)` in `chip->dev`'s drvdata; drivers passing non-zero `sizeof_priv` must not overwrite `chip->dev`'s drvdata with `pwmchip_set_drvdata()` or `dev_set_drvdata()`. [F34, F118]
- Every lookup or userspace entry point indexing `chip->pwms[hwpwm]` or `cdata->pwm[hwpwm]` must bounds-check `hwpwm < chip->npwm`; `of_pwm_single_xlate()` treats `args->args[0..1]` as `(period, flags)` for channel 0 when `args_count < 3` and delegates to `of_pwm_xlate_with_flags()` `(channel, period, flags)` when `args_count >= 3`; `acpi_pwm_get()` must verify `args.nargs >= 2` (returning `-EPROTO` otherwise) and check `args.nargs > 2` before reading `args.args[2]`. [F51, F75, F77]
- Driver helper conventions: `MC33XS2410_PWM_*` channel macros take 1-based `pwm->hwpwm + 1`, and `mc33xs2410_write_regs()`/`mc33xs2410_read_regs()` take `len` in 16-bit register frames (at most `MC33XS2410_MAX_TRANSFERS - 1` (4) for `read_regs`); `keembay_pwm_update_bits(priv, mask, val, offset)` takes `offset` fourth and passes unshifted `val` to `u32_replace_bits()`; `dwc_pwm_writel()`, `brcmstb_pwm_writel()`, and `berlin_pwm_writel()` take `value` before `offset`. [F45, F47, F48, F122]

## Error Handling

- Before invoking waveform callbacks, core paths must check `pwmchip_supports_waveform(chip)`, and hardware read paths (`pwm_get_waveform_might_sleep()`, `pwm_get_state_hw()`, `__pwm_set_waveform()`) must also verify `ops->read_waveform != NULL` (for write-only drivers like `argon_fan_hat_pwm_ops`). [F33]
- When `__pwm_apply()` adapts `struct pwm_state` to a waveform driver, `err > 0` from `__pwm_round_waveform_tohw()` must be converted to `-EINVAL`; in `pwm_set_waveform_might_sleep()`, `err == -EDOM` from `__pwm_set_waveform()` must be remapped to `-EINVAL` before mapping `err == 1` to `-EDOM` (if `exact`) or `0` (if `!exact`). [F32, F91]
- `pwm_device_link_add()` returns `NULL` when consumer `dev` is `NULL` and `ERR_PTR(-EINVAL)` on failure, so callers must check `IS_ERR(dl)` rather than `!dl` or `IS_ERR_OR_NULL(dl)`; `pwm_put()` accepts a nullable `pwm` and must check `if (!pwm) return;` before dereferencing `pwm->chip`. [F35, F36]
- In `pwm-mediatek.c`, `pwm_mediatek_clk_enable()` prepares/enables `clk_top`, `clk_main`, and `clk_pwms[hwpwm].clk` and must disable them in reverse order on error (and in `pwm_mediatek_clk_disable()`), `pwm_mediatek_config()` and `pwm_mediatek_get_state()` must balance `pwm_mediatek_clk_enable()` with `pwm_mediatek_clk_disable()` on all paths, and `pwm_mediatek_init_used_clks()` must roll back all channels in `handled` on failure. [F15, F139]
- Signed return value and divisor checks: `meson_pwm_calc()` must store `clk_round_rate()` in signed `long fin_freq` and reject `<= 0`, while `meson_pwm_cnt_to_ns()` must check `fin_freq != 0` and cast `cnt` to `u64` before `div64_ul(NSEC_PER_SEC * (u64)cnt, fin_freq)`; `lp3943_pwm_parse_dt()` must store `of_property_count_u32_elems()` in signed `int num_outputs`; `fsl_pwm_ticks_to_ns()` must check `(rate >> fpc->period.clk_ps) != 0` and `fsl_pwm_calculate_duty()` must check `period_ns != 0` and widen `duty_ns` to `unsigned long long` before `do_div()`. [F42, F43, F107, F110]

## External Contracts

- In `__pwm_apply()`, when the requested `state` fails `pwm_state_valid(state)` and the current `pwm->state` is also invalid, `__pwm_apply()` must update `pwm->state = *state` and return `0` without calling driver callbacks so sysfs users can configure attributes incrementally. [F163]
- In `pwm_cdev_ioctl()`, waveform ioctls (`PWM_IOCTL_ROUNDWF`, `PWM_IOCTL_GETWF`, `PWM_IOCTL_SETROUNDEDWF`, `PWM_IOCTL_SETEXACTWF`) must reject `cwf.__pad != 0` with `-EINVAL`, verify `cwf.hwpwm` via `pwm_cdev_get_requested_pwm()`, and zero `cwf.__pad` before `copy_to_user()`. [F164]

## Known Pitfalls

- In `pwm_round_waveform_might_sleep()`, `ret_tohw` and `ret_fromhw` must be checked and logged separately for `__pwm_round_waveform_tohw()` and `__pwm_round_waveform_fromhw()`, while `pwm_check_rounding(&wf_req, wf)` must compare the saved `wf_req` copy against `*wf` and return `ret_tohw`. [F90]
- Duty clamping after period quantization: in `lp3943_pwm_config()`, after clamping `period_ns`, `duty_ns` must be clamped with `min(duty_ns, period_ns)` before computing `duty_ns * LP3943_MAX_DUTY / period_ns` so the `u8` duty value does not wrap; in `mc33xs2410_pwm_apply()`, after `wr_val[0] = mc33xs2410_pwm_get_freq(period)`, `period` must be recomputed via `mc33xs2410_pwm_get_period(wr_val[0])` and `duty_cycle` clamped with `min(period, state->duty_cycle)` before computing `rel_dc`. [F58, F68]
- Counter underflow/overflow: when hardware defines period/duty as `reg + 1` ticks (`pwm_mediatek_config()`, `pwm_imx_tpm_round_state()`), a `0` tick count must be rejected or handled as disabled before subtracting `1`; in `__dwc_pwm_configure_timer()`, 64-bit `tmp` must be checked against `tmp < 1 || tmp > (1ULL << 32)` before `tmp - 1`; in `meson_pwm_calc()`, `duty`/`period`/`freq` must be `u64` and `cnt`/`duty_cnt` computed with `mul_u64_u64_div_u64()`; in `gpio-mvebu.c`, blink register `0` means `2^32` (`UINT_MAX + 1ULL`) and sub-1-tick durations clamp to `1`. [F83, F109, F113, F115]
