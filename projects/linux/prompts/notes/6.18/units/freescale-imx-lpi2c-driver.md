# FREESCALE IMX LPI2C DRIVER

This component is the Linux I2C bus driver for the Freescale/NXP i.MX Low Power I2C (LPI2C) controller (`fsl,imx7ulp-lpi2c`). It registers an `i2c_adapter` supporting both master transfers (via interrupt-driven PIO, polled atomic PIO, and DMA engine channels) and I2C target (slave) mode, while managing peripheral clocks, pinctrl bus recovery, and runtime/system power management.

## Architecture & Data Flow

- In `lpi2c_imx_master_isr`, `LPI2C_MSR` must be masked with `LPI2C_MIER` (`temp &= enabled`), and `MSR_NDF` must be checked before `MSR_RDF` and `MSR_TDF` in the `if`/`else if` chain so a concurrent FIFO-ready bit does not service FIFOs or re-enable interrupts when a NACK (`MSR_NDF`) completes the transfer [F43].
- In `lpi2c_cleanup_dma`, `dmaengine_terminate_sync` must be dispatched using `dma->dma_data_dir` before calling `lpi2c_dma_unmap(dma)`, because `lpi2c_dma_unmap` uses `dma->dma_data_dir` to select the channel and then resets `dma->dma_data_dir` to `DMA_NONE` [F30].
- In RX DMA mode (`I2C_M_RD`), `dma->chan_tx` must be configured (`DMA_SLAVE_BUSWIDTH_2_BYTES` to `LPI2C_MTDR`), mapped, submitted via `lpi2c_dma_rx_cmd_submit`, terminated, and unmapped using `dma->chan_tx->device->dev`, `dma->dma_tx_addr`, `dma->rx_cmd_buf_len`, and `DMA_TO_DEVICE` to feed 16-bit `RECV_DATA` command words, kept separate from the 1-byte RX data buffer on `dma->chan_rx` (`LPI2C_MRDR`, `dma->dma_addr`, `dma->dma_len`) [F51, F64].
- In `lpi2c_imx_dma_burst_num_calculate`, `dma->tx_burst_num` and `dma->rx_burst_num` must be computed via `lpi2c_imx_find_max_burst_num` as exact divisors (`!(len % i)`) of the transfer word count (`cmd_num` for `chan_tx` in `I2C_M_RD` mode, and `dma->dma_len` for `chan_rx` or write-mode `chan_tx`) not exceeding `fifosize / 2`. `lpi2c_imx_find_max_burst_num` relies on `fifosize >= 2` and `i > 0` so `len % i` never divides by zero and returns at least 1, preventing `(dma->rx_burst_num - 1) << 16` from underflowing in `lpi2c_dma_enable` [F42, F55].
- In `lpi2c_imx_dma_xfer` and `lpi2c_dma_submit`, `dma->using_pio_mode` is set to `true` before DMA setup and cleared to `false` once `dmaengine_submit` succeeds, so `lpi2c_imx_xfer_common` only falls back to `lpi2c_imx_pio_xfer` when DMA fails before transfer submission [F29].
- In `lpi2c_imx_read_rxfifo`, `lpi2c_imx->block_data` must be cleared to `0` when issuing the post-length `RECV_DATA` command for an SMBus block read, and multi-chunk `RECV_DATA` commands must only be written when `!(lpi2c_imx->delivered & 0xff)` so new 256-byte (`CHUNK_DATA`) commands are queued only at chunk boundaries [F48].
- In `lpi2c_imx_xfer_common`, `lpi2c_imx->delivered`, `lpi2c_imx->msglen`, `lpi2c_imx->rx_buf`, and `lpi2c_imx->tx_buf` must be reset on every iteration of the `for (i = 0; i < num; i++)` loop, and any failure after `lpi2c_imx_start` succeeds must jump to `stop:` rather than `disable:` so `lpi2c_imx_stop` issues `GEN_STOP` [F47].
- In `lpi2c_imx_write_txfifo` and `lpi2c_imx_read_rxfifo`, calling `lpi2c_imx_intctrl` (writing `LPI2C_MIER`) and `complete(&lpi2c_imx->complete)` must be guarded by `if (!atomic)` so `.xfer_atomic` transfers do not enable hardware interrupts or touch `lpi2c_imx->complete` [F37].
- In `lpi2c_imx_config`, the `for (prescale = 0; prescale <= 7; prescale++)` search loop must be followed by `if (prescale > 7) return -EINVAL;` before packing `prescale` into `LPI2C_MCFGR1`, because exhausting the loop without `clklo < 64` leaves `prescale` at `8` [F46].
- `lpi2c_imx->adapter.bus_recovery_info` is populated by `lpi2c_imx_init_recovery_info` only when `devm_pinctrl_get` succeeds, so every caller (`lpi2c_imx_bus_busy`, `lpi2c_imx_stop`, `lpi2c_imx_txfifo_empty`) must verify `lpi2c_imx->adapter.bus_recovery_info` is non-NULL before calling `i2c_recover_bus` [F22].
- `lpi2c_imx->target` is `NULL` when no I2C slave target is registered, so `lpi2c_imx_isr` and `lpi2c_resume_noirq` must check `lpi2c_imx->target` before invoking `lpi2c_imx_target_isr` or `lpi2c_imx_target_init` (which dereferences `lpi2c_imx->target->addr`). In `lpi2c_resume_noirq`, `lpi2c_imx_target_init` must be called after `pm_runtime_force_resume(dev)` succeeds when `lpi2c_imx->target` is non-NULL [F23, F35].
- In `lpi2c_imx_target_init`, configuring `SCFGR2_FILTSDA`, `SCFGR2_FILTSCL`, and `SCFGR2_CLKHOLD` in `LPI2C_SCFGR2` requires enabling clock stretching (`SCFGR1_RXSTALL | SCFGR1_TXDSTALL` in `LPI2C_SCFGR1`) and asserting `SCR_FILTEN` with `SCR_SEN` in `LPI2C_SCR` [F34].

## Synchronization

- Because `struct lpi2c_imx_struct` has no spinlock, process context and `lpi2c_imx_master_isr` serialize access to PIO transfer fields (`tx_buf`, `rx_buf`, `delivered`, `msglen`, `block_data`) via `LPI2C_MIER`: callers must initialize them before unmasking `LPI2C_MIER`, and `lpi2c_imx_master_isr` masks `LPI2C_MIER` before touching them. Broken by: enabling `MIER_RDIE` or `MIER_TDIE` before initial FIFO writes or buffer setup finish, or modifying `delivered`/`msglen` while `LPI2C_MIER` is non-zero [F9].
- In `lpi2c_imx_pio_xfer` and `lpi2c_dma_submit`, `reinit_completion(&lpi2c_imx->complete)` must be called before unmasking master interrupts in `LPI2C_MIER` via `lpi2c_imx_intctrl` (or `lpi2c_imx_write`) or submitting the DMA descriptor via `dmaengine_submit` and `dma_async_issue_pending` [F8].
- In `lpi2c_imx_dma_xfer` for `I2C_M_RD` messages, `lpi2c_dma_submit` must map `dma->dma_buf`, arm `lpi2c_imx->complete`, and issue `dma->chan_rx` before `lpi2c_dma_rx_cmd_submit` issues `dma->chan_tx` to write `RECV_DATA` command words to `LPI2C_MTDR` [F10].
- `lpi2c_dma_enable` must unmask `MIER_NDIE` via `lpi2c_imx_intctrl` when enabling DMA in `LPI2C_MDER` so that `lpi2c_imx_master_isr` wakes `lpi2c_imx_dma_msg_complete` via `complete(&lpi2c_imx->complete)` if `MSR_NDF` is asserted during a DMA transfer [F13].
- `lpi2c_imx_register_target` must set `lpi2c_imx->target` before `lpi2c_imx_target_init` enables `SCR_SEN` and `SLAVE_INT_FLAG`, and `lpi2c_imx_unregister_target` must reset `LPI2C_SCR` before clearing `lpi2c_imx->target = NULL` and calling `pm_runtime_put_sync` [F14].
- When `atomic` is true, `lpi2c_imx_xfer_common` and its callees (`lpi2c_imx_start`, `lpi2c_imx_bus_busy`, `lpi2c_imx_txfifo_empty`, `lpi2c_imx_stop`) must use `lpi2c_imx_pio_xfer_atomic` and `lpi2c_imx_read_msr_poll_timeout(true, ...)` (`readl_poll_timeout_atomic`) rather than `lpi2c_imx_pio_xfer`, `lpi2c_imx_dma_xfer`, `wait_for_completion_timeout`, or `readl_poll_timeout` [F69].

## Object Lifetimes

- `lpi2c_imx_master_enable` acquires a runtime PM reference on `lpi2c_imx->adapter.dev.parent` before accessing `LPI2C_MCR` (rolling it back via `rpm_put` if `lpi2c_imx_config` fails), and every path in `lpi2c_imx_xfer_common` after `lpi2c_imx_master_enable` succeeds must call `lpi2c_imx_master_disable` to clear `MCR_MEN` and release that reference [F1].
- In `lpi2c_imx_dma_xfer`, `dma->dma_buf` must be acquired via `i2c_get_dma_safe_msg_buf`, mapped and unmapped on `chan->device->dev` via `lpi2c_dma_submit` and `lpi2c_dma_unmap`, and any active DMA on `dma->chan_tx` or `dma->chan_rx` must be terminated via `dmaengine_terminate_sync` (in `lpi2c_cleanup_rx_cmd_dma` and `lpi2c_cleanup_dma`) and unmapped before `kfree(dma->rx_cmd_buf)` and `i2c_put_dma_safe_msg_buf` release the underlying memory buffers. Broken by: jumping to `disable_dma` instead of `disable_cleanup_data_dma` or `disable_cleanup_all_dma` after `lpi2c_dma_submit` [F3, F72].
- `lpi2c_imx_probe` must call `platform_set_drvdata(pdev, lpi2c_imx)` before `pm_runtime_enable` and `lpi2c_dma_init`, and must initialize `base`, `clks`, `rate_per`, `txfifosize`, `rxfifosize`, `dma`, `devm_request_irq`, runtime PM, and `i2c_set_adapdata(&lpi2c_imx->adapter, lpi2c_imx)` before calling `i2c_add_adapter(&lpi2c_imx->adapter)`. `lpi2c_imx_remove` must call `i2c_del_adapter(&lpi2c_imx->adapter)` before `pm_runtime_disable(&pdev->dev)` [F15, F57].
- On any error in `lpi2c_imx_probe` after enabling runtime PM autosuspend, teardown must call `pm_runtime_dont_use_autosuspend`, `pm_runtime_put_sync`, and `pm_runtime_disable` in that order (at `rpm_disable`) so `lpi2c_runtime_suspend` disables the clocks synchronously before runtime PM is disabled [F58].

## API Contracts

- In `lpi2c_imx_dma_xfer`, the buffer obtained from `i2c_get_dma_safe_msg_buf(msg, I2C_DMA_THRESHOLD)` must be released via `i2c_put_dma_safe_msg_buf(dma->dma_buf, msg, xferred)` with `xferred = true` only when the DMA transfer and post-transfer `MSR_NDF` check succeed (`ret == 0`), and `xferred = false` on any error path [F76].
- `lpi2c_imx_write_txfifo` and `lpi2c_imx_read_rxfifo` return `true` only when the entire message (`lpi2c_imx->delivered == lpi2c_imx->msglen`) has been transferred and `false` while bytes remain, which `lpi2c_imx_write_atomic` and `lpi2c_imx_read_chunk_atomic` use as their polling termination condition [F25].
- In `lpi2c_imx_target_isr`, when `SSR_AVF` is set with `SASR_READ_REQ`, the handler must invoke `i2c_slave_event` with `I2C_SLAVE_READ_REQUESTED`, write the first byte to `LPI2C_STDR`, and jump to `ret` without also processing `SSR_TDF` (`I2C_SLAVE_READ_PROCESSED`) in the same IRQ [F79].
- Runtime PM calls in `lpi2c_imx_master_enable`, `lpi2c_imx_master_disable`, `lpi2c_imx_register_target`, and `lpi2c_imx_unregister_target` must pass `lpi2c_imx->adapter.dev.parent` (the platform device `&pdev->dev`) rather than `&lpi2c_imx->adapter.dev` [F50].
- System sleep callbacks in `lpi2c_pm_ops` must pair `pm_runtime_resume_and_get` in `lpi2c_suspend` with `pm_runtime_force_suspend` in `lpi2c_suspend_noirq`, `pm_runtime_force_resume` in `lpi2c_resume_noirq`, and `pm_runtime_put_autosuspend` in `lpi2c_resume` so the controller stays active across late suspend and early/noirq resume [F61].
- I2C 7-bit addresses in `struct i2c_msg.addr` and `struct i2c_client.addr` are unshifted in bits [6:0] and must be shifted left by 1 when programming hardware registers: via `i2c_8bit_addr_from_msg(msgs)` for `LPI2C_MTDR` in `lpi2c_imx_start`, and `(lpi2c_imx->target->addr << 1)` for `LPI2C_SAMR` in `lpi2c_imx_target_init` [F78].

## Error Handling

- In `lpi2c_imx_bus_busy`, `lpi2c_imx_txfifo_empty`, and `lpi2c_imx_write_atomic`, error status bits (`MSR_ALF` or `MSR_NDF`) included in the `lpi2c_imx_read_msr_poll_timeout` condition must be checked on `temp` before treating `err == 0` as success, because those error bits satisfy the poll predicate and return `err == 0` [F44].
- In `lpi2c_dma_submit` and `lpi2c_dma_rx_cmd_submit`, if `dmaengine_prep_slave_single` fails the streaming mapping (`dma->dma_addr` or `dma->dma_tx_addr`) must be unmapped, and if `dmaengine_submit` fails (`dma_submit_error`) both the mapping must be unmapped and the descriptor freed via `dmaengine_desc_free` [F2].
- In `lpi2c_imx_dma_xfer`, failures in `lpi2c_imx_alloc_rx_cmd_buf` or `lpi2c_dma_rx_cmd_submit` must jump to `disable_cleanup_data_dma` rather than `disable_cleanup_all_dma`, because `lpi2c_dma_rx_cmd_submit` unmaps `dma->dma_tx_addr` internally on error and `lpi2c_cleanup_rx_cmd_dma` would unmap an unmapped or already-unmapped `dma_tx_addr` [F19].
- In `lpi2c_dma_init`, if `dma_request_chan` returns an `IS_ERR` pointer for `dma->chan_tx` or `dma->chan_rx`, that field must be cleared to `NULL` before jumping to `dma_exit`, because `dma_exit` passes any non-`NULL` `dma->chan_rx` or `dma->chan_tx` to `dma_release_channel` [F5].
- `lpi2c_imx_xfer_common` must check `MSR_NDF` after `lpi2c_imx_stop` only when `!result` so that a prior transfer failure code in `result` is not overwritten with `-EIO`, and must convert `result == 0` into `num` while returning negative `result` values unchanged [F21].
- In `lpi2c_imx_probe`, non-`-EPROBE_DEFER` errors from `lpi2c_imx_init_recovery_info` and `lpi2c_dma_init` must be ignored (falling back to no bus recovery or PIO mode) and `ret` must be overwritten by `i2c_add_adapter` so that non-fatal optional init errors are not returned from `lpi2c_imx_probe` [F26].
- Routine I2C bus NACKs (`MSR_NDF`) and PIO/bus poll timeouts in `lpi2c_imx_bus_busy`, `lpi2c_imx_stop`, `lpi2c_imx_txfifo_empty`, and `lpi2c_imx_xfer_common` must be logged at `dev_dbg` level rather than `dev_err` or `WARN*` [F81].

## External Contracts

- The RX watermark in `LPI2C_MFCR` bits 16+ must be strictly less than the transfer/burst count (`dma->rx_burst_num - 1` in `lpi2c_dma_enable`, and `0` in `lpi2c_imx_set_rx_watermark` when `remaining <= (lpi2c_imx->rxfifosize >> 1)`), because RX interrupts and DMA requests fire only when the RX FIFO count exceeds the RX watermark [F40].
- When issuing `RECV_DATA` commands to `LPI2C_MTDR` in `lpi2c_imx_read_init`, `lpi2c_imx_read_rxfifo` (for non-block chunks), and `lpi2c_imx_alloc_rx_cmd_buf`, the chunk length (at most `CHUNK_DATA` = 256) must be encoded as `(count - 1)` in bits 0-7 ORed with `RECV_DATA << 8`, because hardware receives `DATA[7:0] + 1` bytes per command [F38].
- When `MSR_ALF` (arbitration lost) is detected in `lpi2c_imx_bus_busy`, the driver must clear `LPI2C_MSR` and return `-EAGAIN` so that `__i2c_transfer` in the I2C core automatically retries the transfer up to `adapter.retries` [F75].

## Known Pitfalls

- In `lpi2c_imx_config`, intermediate timing variables `clk_cycle`, `clkhi`, and `clklo` must use `unsigned int` rather than `u8` so values >= 256 at low `prescale` iterations do not wrap modulo 256 and prematurely satisfy `clklo < 64` [F52].
- Resetting the master (`LPI2C_MCR` in `lpi2c_imx_master_enable`) or target (`LPI2C_SCR` in `lpi2c_imx_target_init` and `lpi2c_imx_unregister_target`) requires writing `MCR_RST` or `SCR_RST` followed explicitly by writing `0`, because the hardware reset bits do not self-clear [F67].
