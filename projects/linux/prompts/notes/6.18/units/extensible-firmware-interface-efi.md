# EXTENSIBLE FIRMWARE INTERFACE (EFI)

This unit implements the pre-boot UEFI Boot Stub (`drivers/firmware/efi/libstub/*`) and the kernel EFI subsystem (`drivers/firmware/efi/*` and architecture-specific EFI bindings across ARM, ARM64, LoongArch, RISC-V, and x86). It manages EFI virtual memory mappings, runtime service wrappers, variable services (generic and OP-TEE StandaloneMM), capsule updates, CPER error parsing, confidential computing unaccepted memory, ESRT/BGRT/MOK/RCI2/TPM tables, and early/system EFI framebuffers.

## Architecture & Data Flow

- When indexing, sizing, or copying entries within an EFI memory map buffer (`efi.memmap`), use the runtime stride `desc_size`, whereas copying a single descriptor into a standalone `efi_memory_desc_t` variable must bound `memcpy()` to `sizeof(efi_memory_desc_t)`. `__efi_mem_desc_lookup()` and `efi_memmap_entry_valid()` must bound `md->num_pages` against `0` and `(U64_MAX - md->phys_addr) >> EFI_PAGE_SHIFT` (`EFI_PAGES_MAX`) before shifting or adding. [F106, F107, F115, F116]
- On x86_64, `efi_map_region()` maps each region in `efi_mm.pgd` at both `md->phys_addr` (1:1) and `md->virt_addr`, so `efi_update_mappings()` and `efi_unmap_pages()` must update or unmap both in lockstep, and `efi_map_next_entry()` must iterate `efi.memmap` in reverse via `efi_map_next_entry_reverse()`. When `efi_arch_mem_reserve()` inserts a reserved `EFI_MEMORY_RUNTIME` entry into `efi.memmap`, it must also update `e820_table` to `E820_TYPE_RESERVED`. [F59, F62, F84]
- On x86, `efi_reserve_boot_services()` must set `EFI_MEMORY_RUNTIME` on pre-reserved or non-freeable regions; `efi_free_boot_services()` must never pass `EFI_MEMORY_RUNTIME` or `< SZ_1M` regions to `memblock_free_late()`, and its second descriptor copy loop must use the exact same filter as its `num_entries++` counting loop. On kexec boots, `efi_reuse_config()` must set `EFI_MEMORY_ATTRIBUTES_TABLE_GUID` to `EFI_INVALID_TABLE_ADDR`. [F52, F96, F160]
- In `create_mapping_protection()` (arm64) and `efimem_to_pgprot_map()` (riscv), `(attr & (EFI_MEMORY_XP | EFI_MEMORY_RO)) == (EFI_MEMORY_XP | EFI_MEMORY_RO)` must be tested before `attr & EFI_MEMORY_RO`; on arm64, `code_is_misaligned` is a `static` bool latched via `|=`. On 32-bit ARM, `efi_create_mapping()` must test `EFI_MEMORY_WB`, `EFI_MEMORY_WT`, `EFI_MEMORY_WC`, then `MT_DEVICE` in an `if`/`else if` chain. [F90, F91, F92]
- In `struct efi_unaccepted_memory`, `size` is in bytes while `bitmap[]` is indexed by `unit_size` blocks from `phys_base` (`unit_size` must be widened to `u64` before multiplying). `accept_memory()` and `range_contains_unaccepted_memory()` must extend `end` by `unit_size` when `(start + size - unaccepted->phys_base) % unit_size == 0` and clamp `end` to `size * unit_size * BITS_PER_BYTE`; `process_unaccepted_memory()` must call `arch_accept_memory(start, end)` first if `end - start < 2 * unit_size`. [F242, F243, F281, F301]
- In x86 and shared libstub code, UEFI union fields/methods must be accessed via `efi_table_attr()`, `efi_call_proto()`, `efi_bs_call()`, `efi_rt_call()`, `efi_dxe_call()`, or `efi_fn_call()`, and handle/event arrays via `for_each_efi_handle()`, `efi_get_handle_at()`, or `efi_set_event_at()`. In `efi_convert_cmdline()`, `efi_measure_tagged_event()` must measure raw `image->load_options` before `efi_apply_loadoptions_quirk()` mutates `options`. [F209, F237]
- In x86 libstub: `efi_handover_entry()` must zero `[_bss, _ebss)` before `efi_stub_entry()`; `efi_allocate_bootparams()` must set `hdr->initrd_addr_max = INT_MAX`; `efi_pe_entry()` must update `screen_info_offset` after `handle_kernel_image()` relocates the kernel; `sev_enable()` must precede `efi_5level_switch()` (which requires `la57_toggle` and `new_cr3 <= U32_MAX`); and `exit_boot()` must pre-allocate `e820ext` and `unaccepted_table` before `efi_exit_boot_services()`. [F216, F229, F234, F239, F329, F330]

## Synchronization

- Virtual EFI runtime calls in `efi_call_rts()` and `efi_call_virt_pointer()` must bracket the call with `arch_efi_call_virt_setup()` and `efi_call_virt_save_flags()` before, and `efi_call_virt_check_flags()` plus `arch_efi_call_virt_teardown()` after. On arm64 (`efi_virtmap_load()`, `efi_rt_lock`, `__efi_fpsimd_begin()`), x86_64 (`efi_sync_low_kernel_mappings()` skipping `[EFI_VA_END, EFI_VA_START)`, `efi_fpu_begin()`, `efi_enter_mm()`), and RISC-V, setup disables preemption and loads `efi_mm` while teardown unwinds in reverse order without sleeping. [F17, F60, F144, F188, F321]
- In `runtime-wrappers.c`, callers using `efi_rts_work` must hold `efi_runtime_lock` across `__efi_queue_work()` until `wait_for_completion()` finishes and `efi_rts_id` is reset to `EFI_NONE`. Non-blocking wrappers (`virt_efi_set_variable_nb`, `virt_efi_query_variable_info_nb`, `virt_efi_reset_system`) must use `down_trylock(&efi_runtime_lock)` and invoke firmware directly. In x86_64 mixed mode, `efi_thunk()` requires holding `efi_runtime_lock` with IRQs disabled, while `efi_thunk_*_nonblocking()` must use `spin_trylock_irqsave()`. [F29, F187, F318]
- `efivar_lock()` and `efivar_trylock()` must release `efivars_lock` and return `-ENODEV` if `!__efivars->ops`. Callers of `efivar_get_variable()`, `efivar_get_next_variable()`, and `efivar_set_variable_locked()` must hold `efivars_lock`, whereas `efivar_ops_nh` notifier callbacks are invoked by `efivars_register()` with `efivars_lock` already held and must not call `efivar_lock()`, `efivar_set_variable()`, or `efivars_register()`/`unregister()`. [F180, F196]
- In `efi_capsule_update()`, all scatter-gather pages in `sg_pages` must be populated, cache-flushed via `efi_capsule_flush_cache_range()`, and unmapped before acquiring `capsule_mutex` and calling `efi_capsule_update_locked()`. `efi_capsule_update_locked()` and `capsule_reboot_notify()` must hold `capsule_mutex` when accessing `stop_capsules`, `efi_reset_type`, or `capsule_pending`. [F25, F150]
- In `efi_mem_reserve_persistent()` and `efi_mem_reserve_iomem()`, allocations must use `GFP_ATOMIC`, slot claims must use `atomic_fetch_add_unless(&rsv->count, 1, rsv->size)`, and linking a new entry into `efi_memreserve_root->next` must hold `efi_mem_reserve_persistent_lock`. [F153]

## Object Lifetimes

- When `efi_capsule_update()` returns 0, the caller must not free or modify the physical data pages `pages` or scatter-gather pages `sg_pages[i]`. In `capsule-loader.c`, `cap_info->pages` and `cap_info->phys` (sized with `sizeof(phys_addr_t)`) must be updated in lockstep, and `cap_info->index` must be set to `NO_FURTHER_WRITE_ACTION` (`-1`) on error cleanup and when `efi_capsule_submit_update()` succeeds so `efi_capsule_release()` does not free submitted pages. [F1, F55, F56, F114]
- `efi_memmap_install()` must only free the previous `efi.memmap` physical memory via `__efi_memmap_free()` after `efi_memmap_unmap()` and a successful `__efi_memmap_init(data)`, whereas `__efi_memmap_init()` must never free the old physical map. Callers of `efi_memmap_init_late()` must first call `efi_memmap_unmap()`. In `efi_init()` (`efi-init.c`), if `uefi_init()` fails, `efi_memmap_unmap()` must be called before returning. [F5, F18, F171]
- In `efi_exit_boot_services()`, operations that modify the memory map such as `efi_pci_disable_bridge_busmaster()` must run before `efi_get_memory_map()`, and once `exit_boot_services()` has been called once, the retry path must reuse the existing map buffer without calling `allocate_pool` or `free_pool`. When `install_cfg_tbl` is true in `efi_get_memory_map()`, `install_configuration_table` for `LINUX_EFI_BOOT_MEMMAP_GUID` must precede the final `get_memory_map` call. [F173, F235]
- In `efivar_ssdt_load()`, `acpi_load_table(data, NULL)` takes ownership of `data` on success, so `kfree(data)` must only run on failure. In `efi_get_device_by_path()` and its node parsers (`parse_acpi_path()`, `parse_pci_path()`), each step returns a refcounted `struct device *` (or `ERR_PTR`); callers like `unmarshal_devices()` must reset `dev = NULL` on `IS_ERR(dev)` before jumping to `put_device(dev)` cleanup. In `efifb_add_links()`, the node from `find_pci_overlap_node()` must be released with `of_node_put()`. [F4, F7, F41, F132, F184]
- In `accept_memory()`, the stack-allocated `struct accept_range range` on `accepting_list` must remain linked while `unaccepted_memory_lock` is dropped (with IRQs kept disabled) across `arch_accept_memory()` (where overlap checks treat `entry->end <= range.start` or `entry->start >= range.end` as non-overlapping), and must be removed via `list_del(&range.list)` and followed by `touch_softlockup_watchdog()` before unlocking. [F183, F241, F316]
- In `tee_stmm_efi.c`, `setup_mm_hdr(&comm_buf, payload_size, func)` allocates `comm_buf` via `alloc_pages_exact(COMM_BUF_SIZE(payload_size), ...)` (never slab) and returns the inner `var_hdr->data` pointer; callers must pass `comm_buf` to `mm_communicate()` and `free_pages_exact()`, and `tee_mm_communicate()` must call `tee_shm_free(shm)`. `tee_stmm_efi_probe()` must call `efivars_generic_ops_unregister()` before registering `tee_efivars`, and `tee_stmm_efi_remove()` must restore generic ops after unregistering. [F181, F182, F232, F271, F331]
- On x86, `__efi_enter_virtual_mode()` must call `efi_check_for_embedded_firmwares()` before `efi_free_boot_services()`. In `map_properties()`, only the `setup_data` payload (`pa_data + sizeof(*data)`) may be freed via `memblock_free_late()` after zeroing `data->len`, keeping the header intact. In libstub, functions returning pool buffers via out-parameters (`efi_handle_cmdline()`, `preserve_pci_rom_image()`, `efi_get_memory_map()`) must only transfer the local `__free(efi_pool)` pointer via `no_free_ptr()` on success. [F8, F13, F270]

## API Contracts

- `efi_get_embedded_fw()` returns a borrowed pointer in `*data` owned by `efi_embedded_fw_list`; callers must copy the data and never `kfree(*data)`. Conversely, `realloc_pages(old_memmap, old_shift)` in `arch/x86/platform/efi/efi.c` always frees `old_memmap` even when returning `NULL`. [F14, F15]
- `efi_query_variable_store()` and `query_variable_store_nonblocking()` must return `efi_status_t` values (never negative errno), and when `nonblocking` is true, must not sleep or allocate with `GFP_KERNEL`. In `efivar_set_variable_locked()`, any `efivar_operations` backend with a sleeping `set_variable` must implement `set_variable_nonblocking`, and `check_var_size()` must be passed `data_size + ucs2_strsize(name, EFI_VAR_NAME_LEN)` (falling back to `size <= SZ_64K ? EFI_SUCCESS : EFI_OUT_OF_RESOURCES` on `EFI_UNSUPPORTED`). [F33, F40, F203, F223, F320]
- `efi_mem_type()` returns a non-negative EFI memory type (`0` is `EFI_RESERVED_TYPE`), `-ENOTSUPP`, or `-EINVAL` (callers must use a signed int and check `< 0`), whereas `efi_mem_attributes()` returns a `u64` bitmask or `0`. `efi_memmap_insert()` requires `EFI_PAGE_SIZE`-aligned range bounds, `buf` sized with `efi_memmap_split_count()`, and mutually exclusive overlap conditions. `efi_set_mapping_permissions()` on ARM/arm64/RISC-V must skip section/block or `region_is_misaligned(md)` mappings. [F39, F85, F97, F151]
- Drivers retaining `EFI_BOOT_SERVICES_DATA` tables across boot (`efi_esrt_init()`, `efi_bgrt_init()`) must call `efi_mem_reserve()`. `efi_mem_reserve_persistent()` must size new `linux_efi_memreserve` entries and reserve `iomem_resource` using `SZ_4K` rather than `PAGE_SIZE`. `reserve_unaccepted()` must page-align `efi.unaccepted` and call `memblock_add(start, size)` before `memblock_reserve(start, size)`. [F131, F167, F168]
- `cper_estatus_check()`, `cper_estatus_check_header()`, and `cper_estatus_print()` run in NMI/hardirq/panic contexts and must never sleep or allocate with `GFP_KERNEL`. `cper_estatus_print_section()` must verify `gdata->error_data_length` is at least the minimum section header size before dereferencing payloads, and `cper_print_fw_err()` must compute trailing data offsets according to `fw_err->revision`. [F78, F79, F81, F154]
- On x86_64, all runtime service calls (including `set_virtual_address_map`) must use `arch_efi_call_virt()` (not raw `efi_call()`) so IBT is saved/restored. In `runtime-wrappers.c`, every function making a direct C indirect call to UEFI Runtime Services must be annotated `__nocfi`, and UEFI 2.0 wrappers (`query_variable_info`, `update_capsule`, `query_capsule_caps`) must return `EFI_UNSUPPORTED` when `efi.runtime_version < EFI_2_00_SYSTEM_TABLE_REVISION`. [F143, F289, F313]
- Variable writers (`generic_ops.set_variable`, `efibc_init()`) must check `efi_rt_services_supported(EFI_RT_SUPPORTED_SET_VARIABLE)`, and `efi_reboot()` / `efi_shutdown_init()` must check `EFI_RT_SUPPORTED_RESET_SYSTEM` (registering `efi_power_off` at `SYS_OFF_PRIO_FIRMWARE + 1`). `process_unaccepted_memory(start, end)` and `arch_accept_memory(start, end)` take `[start, end)` addresses, whereas `accept_memory(start, size)` and `range_contains_unaccepted_memory(start, size)` take start and byte length. [F127, F224, F314, F333]

## Error Handling

- Optional physical table addresses in `struct efi` (`acpi`, `smbios`, `esrt`, `tpm_log`, `mokvar_table`, `coco_secret`, `unaccepted`) are initialized to `EFI_INVALID_TABLE_ADDR` (`~0UL`), so presence checks must compare against `EFI_INVALID_TABLE_ADDR` rather than `0`. In `efi_mem_reserve_persistent()`, `efi_memreserve_root` must be checked against both `(void *)ULONG_MAX` and `NULL`. Optional runtime pointers (`efi.get_next_variable`, `generic_ops.get_variable`) must be checked for non-NULL before use. [F34, F35, F37]
- In `allocate_new_fdt_and_exit_boot()`, `priv.runtime_map` is only allocated when `!efi_novamap`, so `fail:` must guard `free_pool` with `if (!efi_novamap)`; if `set_virtual_address_map()` fails after `efi_exit_boot_services()` succeeds, set `virt_addr = U64_MAX` on all `EFI_MEMORY_RUNTIME` descriptors and still return `EFI_SUCCESS`. In `__efi_queue_work()`, when `!efi_enabled(EFI_RUNTIME_SERVICES)`, set `efi_rts_work.status = EFI_DEVICE_ERROR` before `exit`. [F172, F204, F218]

## External Contracts

- All UEFI function pointers must be declared `__efiapi`, and `efi_guid_t` requires 32-bit alignment. In x86 mixed mode (`CONFIG_EFI_MIXED`), every `efi_fn_call()` method `func` requires an exact-named `__efi64_argmap_<func>` macro in `arch/x86/include/asm/efi.h`, 64-bit pointer/size out-params must use `efi64_zero_upper()`, 64-bit value args must use `__efi64_split()`, and 32-bit `efi_status_t` returns must use `__efi64_widen_efi_status()`. [F53, F87, F324]
- Sysfs attributes under `/sys/firmware/efi/runtime-map/`, `/sys/firmware/efi/esrt/`, `/sys/firmware/efi/systab`, and `/sys/firmware/efi/mok-variables/` must use mode `0400` (and `efi_mokvar_sysfs_read()` must check `capable(CAP_SYS_ADMIN)`). `systab_show()` must not have new fields added and must print `SMBIOS3=` before `SMBIOS=`. Libstub tables persisting across kexec (`unaccepted_table`, RNG `seed`) must be allocated from `EFI_ACPI_RECLAIM_MEMORY` rather than `EFI_LOADER_DATA`. [F165, F166, F332, F341]

## Known Pitfalls

- Shift `efi_memory_desc_t.num_pages` by `EFI_PAGE_SHIFT` (12), never `PAGE_SHIFT`, and in `memrange_efi_to_native()` compute `*npages` before masking `*addr &= PAGE_MASK`. Pass physical table addresses (never virtual pointers from `early_memremap()`) to `memblock_reserve()`. In `set_permissions()` (ARM/arm64/RISC-V), accumulate `EFI_MEMORY_RO` and `EFI_MEMORY_XP` changes into the local `pte`/`val` variable before writing `*ptep`. [F54, F108, F285, F325]
- Decrement `r--` after `memblock_remove()` inside `for_each_mem_region(r)` in `reserve_regions()`; delete FDT reservations in reverse order (`while (num_rsv-- > 0)`) in `update_fdt()`; and compute `next = desc.base_address + desc.length` before `continue` in `efi_adjust_memory_range_protection()`. Zero partially populated `allocate_pool` buffers with `memset()`. In libstub `vsprintf.c`, never use `%z`/`%t`, and `%.*ls` precision counts output UTF-8 bytes rather than UTF-16 units. [F98, F215, F265, F273, F295, F296]
