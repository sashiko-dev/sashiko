# NETWORKING DRIVERS

The Google Virtual Ethernet (gve) driver supports Google Cloud's virtual NIC (gVNIC) PCIe device. It implements an admin queue for control-plane communication with the hypervisor/device and supports both GQI (Google Queue Interface) and DQO (Descriptor Queue Option) datapath queue formats, each operating in either Queue Page List (QPL) or Raw DMA Addressing (RDA) mode, alongside XDP, AF_XDP (XSK), PTP hardware clock, RSS, and flow steering.
This component contains the Marvell Octeon PCIe Endpoint (octeon_ep) Physical Function (PF) and Virtual Function (octeon_ep_vf) Ethernet drivers for CN9K and CN10K (CNXK) SoC families. They enable host-to-Octeon network and control communication over PCIe using hardware Instruction Queues (IQ for TX), Output Queues (OQ for RX), PF-to-firmware control mailboxes, and PF-to-VF mailboxes.
This component comprises five distinct Ethernet hardware drivers: SMSC EPIC/100 PCI Fast Ethernet (epic100), SMC 9194 ISA/platform Ethernet (smc9194), SMC 91c92 PCMCIA Ethernet/Modem (smc91c92_cs), SpacemiT K1 SoC RGMII/RMII EMAC (k1_emac), and Sun Cassini PCI Gigabit Ethernet (cassini). Together they cover legacy PIO/PCMCIA/PCI NICs and a modern Device Tree platform SoC MAC using phylib, syscon regmap, runtime PM, and NAPI.
This component contains a diverse set of core virtual/tunnel network devices, bus-backed network drivers, hamradio drivers, and MDIO helpers: Fujitsu Extended Socket (fjes), GENEVE UDP tunnel (geneve), hamradio AX.25 drivers (bpqether, hdlcdrv, mkiss), Intermediate Functional Block (ifb), IPVLAN/IPVTAP (ipvlan), loopback/blackhole netdev (loopback), MACVLAN/MACVTAP (macvlan), Clause 22/45 MDIO library (mdio), and MHI bus network driver (mhi_net).
This component includes core virtual networking drivers, legacy serial/parallel/PPP framing drivers, and PHY libraries: universal TUN/TAP driver (tun), virtual Ethernet pair driver with XDP/page_pool support (veth), 3GPP PFCP UDP tunnel (pfcp), netlink monitor device (nlmon), RapidIO Ethernet (rionet), Sun GEM PHY library (sungem_phy), generic MII library (mii), parallel port IP (plip), SLIP/CSLIP/VJ compression (slip, slhc), and PPP BSD compression and PPTP tunneling (bsd_comp, pptp).
This component contains two distinct subsystems: the Linux PTP (IEEE 1588 Precision Time Protocol) core framework and hardware clock drivers (drivers/ptp/*: ptp_clock, ptp_chardev, ptp_sysfs, ptp_vclock, Renesas ClockMatrix/FemtoClock3/82P33, Broadcom DTE, ZHAW InES, KVM virtual PTP for x86/ARM, and Intel PCH), and the IBM s390 Channel-to-Channel (CTC/MPC) mainframe network driver (drivers/s390/net/ctcm_*).
This component provides the core kernel headers, UAPI definitions, and Device Tree bindings for Linux network devices, link-layer protocols (Ethernet, 802.1Q VLAN, MACVLAN, HSR, PPPoX, TUN/TAP, FDDI, Fibre Channel, ARP), IPv4 device configuration, and ethtool/netdev netlink interfaces. Centered around include/linux/netdevice.h, it defines the lifecycle, queueing, NAPI polling, feature offload masks, statistics, and driver callback contracts (struct net_device_ops) used across all networking drivers and stack layers.

## Architecture & Data Flow

- In DQO RX rings, rx->dqo.page_pool is only allocated when cfg->raw_addressing is true (GVE_DQO_RDA_FORMAT) and is NULL in QPL mode, so all DQO RX teardown and buffer-management paths must check rx->dqo.page_pool before calling page_pool APIs and use it to discriminate page_info.netmem from page_info.page. [F37]
- Because priv->rx and priv->tx are NULL whenever the device is closed, any callback or helper reachable while the interface is down (such as XSK pool setup/wakeup, stats reporting, and netdev_queue_mgmt_ops) must verify priv->rx/priv->tx, netif_running(dev), or gve_get_napi_enabled(priv) before indexing priv->rx or priv->tx. [F39]
- In struct gve_tx_ring, tx->netdev_txq is only initialized for regular network stack TX queues (idx < priv->tx_cfg.num_queues) in DQO mode and is NULL for XDP TX queues, so functions shared with XDP TX queues such as gve_tx_stop_ring_dqo() and gve_clean_tx_done_dqo() must check tx->netdev_txq for non-NULL before calling netdev_tx_* queue APIs. [F45]
- In struct gve_tx_pending_packet_dqo, the skb/xdpf union is discriminated by pending_packet->type (GVE_TX_PENDING_PACKET_DQO_SKB vs GVE_TX_PENDING_PACKET_DQO_XDP_FRAME vs GVE_TX_PENDING_PACKET_DQO_XSK), while the dma/len vs tx_qpl_buf_ids union is discriminated by whether tx->dqo.qpl is non-NULL. [F46]
- Every stack-allocated union gve_adminq_command must be zeroed with memset(&cmd, 0, sizeof(cmd)) before populating its fields and calling gve_adminq_issue_cmd() or gve_adminq_execute_cmd(), because all 64 bytes are copied to coherent DMA memory and cmd.status must start as GVE_ADMINQ_COMMAND_UNSET (0). [F48]
- GVE_PACKET_STATE_UNALLOCATED must remain 0 in enum gve_packet_state, and gve_free_pending_packet() must reset pending_packet->state to GVE_PACKET_STATE_UNALLOCATED, because tx->dqo.pending_packets is zero-allocated with kvcalloc() without per-element state initialization. [F49]
- Because 0 is a valid array index in DQO buffer and packet pools, empty struct gve_index_list instances and s16 list heads/tails in struct gve_rx_ring and struct gve_tx_ring must be explicitly initialized to -1 rather than relying on zero-initialization. [F50]
- When an XDP program is loaded (`priv->xdp_prog != NULL`), `priv->tx_cfg.num_xdp_queues` (and `tx_alloc_cfg.num_xdp_rings` during queue allocation) must equal `priv->rx_cfg.num_queues`, and must be 0 when `priv->xdp_prog` is NULL, because `gve_xdp_tx_queue_id()` maps each RX queue `i` to TX queue `priv->tx_cfg.num_queues + i`. [F54]
- Because XSK TX polling (`gve_xsk_tx_poll()` and `gve_xsk_tx_poll_dqo()`) executes inside the `block->rx` branch of `gve_napi_poll()` and `gve_napi_poll_dqo()`, `gve_xsk_wakeup()` must schedule the RX NAPI instance via `gve_rx_idx_to_ntfy(priv, queue_id)` for both RX and TX wakeups. [F55]
- When `priv->cache_rss_config` is true, `priv->rss_config.hash_key` and `priv->rss_config.hash_lut` must be kept synchronized with device RSS state across `gve_init_rss_config()` and `gve_set_rxfh()`, because `gve_adminq_configure_rss()` and `gve_get_rxfh()` read omitted or queried RSS fields from `priv->rss_config`. [F59]
- Registering or unregistering an AF_XDP pool for queue `qid` in `gve_reg_xsk_pool()` and `gve_unreg_xsk_pool()` must update both `priv->rx[qid].xsk_pool` and `priv->tx[gve_xdp_tx_queue_id(priv, qid)].xsk_pool` in lockstep with bit `qid` in `priv->xsk_pools`. [F60]
- When `pci_enable_msix_range()` in `gve_alloc_notify_blocks()` enables fewer vectors than requested, `priv->num_ntfy_blks` must be rounded down to an even number `(vecs_enabled - 1) & ~0x1`, `priv->mgmt_msix_idx` set to `priv->num_ntfy_blks`, and `tx_cfg`/`rx_cfg` `max_queues` and `num_queues` clamped to the available per-direction vectors. [F65]
- In DQO RX buffer management (`gve_buffer_mgmt_dqo.c`), `rx->dqo.used_buf_states_cnt` must be incremented in `gve_try_recycle_buf()` and decremented in `gve_get_recycled_buf_state()` when mutating `rx->dqo.used_buf_states`, and `buf_state->next` must equal `buf_state - rx->dqo.buf_states` iff allocated. [F68]
- During reset recovery and PM resume (`gve_reset_recovery()` calling `gve_init_priv(priv, true)`), `skip_describe_device` must be true so user-configured queue counts (`priv->tx_cfg`, `priv->rx_cfg`), ring sizes (`priv->tx_desc_cnt`, `priv->rx_desc_cnt`), coalescing, and `priv->rx_copybreak` are not overwritten by device defaults. [F70]
- `gve_adminq_release()` must clear `GVE_PRIV_FLAGS_DEVICE_RINGS_OK`, `GVE_PRIV_FLAGS_DEVICE_RESOURCES_OK`, and `GVE_PRIV_FLAGS_ADMIN_QUEUE_OK` in `priv->state_flags` so `gve_queues_stop()` and `gve_teardown_device_resources()` skip issuing adminq commands to the already-reset device during `gve_reset_and_teardown()`. [F71]
- Every opcode in `enum gve_adminq_opcodes` and `enum gve_adminq_extended_cmd_opcodes` must have a corresponding case in `gve_adminq_issue_cmd()` in `gve_adminq.c`, and any per-command counter exposed via ethtool must be updated in lockstep in `gve_gstrings_adminq_stats` and `gve_get_ethtool_stats()`. [F73]
- The order and count of entries in `gve_gstrings_main_stats`, `gve_gstrings_rx_stats`, and `gve_gstrings_tx_stats` must match the sequential `data[i++]` writes and the `NUM_GVE_RX_CNTS` / `NUM_GVE_TX_CNTS` strides in `gve_get_ethtool_stats()`, and the `rx_xdp_*` action entries must match the order of `enum xdp_action` up to `GVE_XDP_ACTIONS`. [F74]
- TX and RX descriptor ring sizes (`tx_desc_cnt` and `rx_desc_cnt`) must be powers of two within `[min_tx_desc_cnt, max_tx_desc_cnt]` and `[min_rx_desc_cnt, max_rx_desc_cnt]` so that `ring_size - 1` is a valid bitmask for circular indexing. [F77]
- In GQI RX descriptors (`struct gve_rx_desc`), the 3-bit sequence number extracted by `GVE_SEQNO(desc->flags_seq)` uses 1-based values `[1, 7]` (with 0 indicating an empty slot), so `rx->desc.seqno` must start at 1 and wrap from 7 to 1 via `gve_next_seqno()`. [F78]
- In DQO RX and TX completion rings, `cur_gen_bit` starts at 0 on a zeroed ring and must be XOR-flipped whenever `head` wraps to 0 (`cur_gen_bit ^= (head == 0)`), and descriptor fields must not be read until `compl_desc->generation != cur_gen_bit` followed by `dma_rmb()`. [F79]
- In DQO RX buffer management, `struct gve_rx_buf_state_dqo` lists use `-1` as the end-of-list sentinel and mark an entry as allocated by setting `buf_state->next` to its own index (`buf_state - rx->dqo.buf_states`), which `gve_rx_dqo()` must verify along with `buffer_id < rx->dqo.num_buf_states`. [F80]
- In DQO TX completions, `compl_tag` must have `GVE_ALT_MISS_COMPL_BIT` (`BIT(15)`) stripped when `type == GVE_COMPL_TYPE_DQO_PKT` and must be bounds-checked against `tx->dqo.num_pending_packets` (which is capped at `S16_MAX`) before indexing `tx->dqo.pending_packets`. [F81]
- QPL IDs are partitioned at `tx_cfg.max_queues`—TX queue `q` uses ID `q` and RX queue `q` uses `tx_cfg.max_queues + q`—and `gve_qpl_dma_dir()` relies on `id < gve_rx_start_qpl_id(&priv->tx_cfg)` to choose `DMA_TO_DEVICE` versus `DMA_FROM_DEVICE`. [F83]
- In `gve_adminq_process_flow_rules_query()` and `gve_adminq_process_rss_query()`, the device-returned `be32_to_cpu(descriptor->total_length)` must equal `sizeof(*descriptor)` plus the expected payload byte length before copying data out of `(void *)(descriptor + 1)`. [F90]
- In `priv->stats_report->stats[]`, the starting index of NIC-written RX stats shifts upward by `NIC_RX_STATS_REPORT_NUM * num_stopped_rxqs + NIC_TX_STATS_REPORT_NUM * num_stopped_txqs`, and each NIC stat entry's `queue_id` must be bounds-checked against `priv->rx_cfg.num_queues` (or `num_tx_queues`) before indexing. [F91]
- Because `struct gve_tx_pkt_desc_dqo.buf_size` is a 14-bit field capped at `GVE_TX_MAX_BUF_SIZE_DQO` (`16383`), `gve_tx_fill_pkt_desc_dqo()` must split larger buffers across multiple descriptors and `gve_num_descs_per_buf()` must reserve `DIV_ROUND_UP(size, GVE_TX_MAX_BUF_SIZE_DQO)` descriptors per buffer. [F93]
- In DQO TX, hardware allows at most `GVE_TX_MAX_DATA_DESCS` (10) data descriptors per non-TSO packet or per TSO segment, so non-GSO SKBs in RDA mode with `num_buffer_descs > GVE_TX_MAX_DATA_DESCS` must be linearized via `skb_linearize()` and GSO SKBs failing `gve_can_send_tso()` must clear `NETIF_F_GSO_MASK`. [F94]
- In DQO TX, `report_event` may only be set on the last packet descriptor of a packet (`(desc_idx - 1) & tx->mask`) and only when `((last_desc_idx - tx->dqo_tx.last_re_idx) & tx->mask) >= GVE_TX_MIN_RE_INTERVAL` (32). [F95]
- In GQI RX (`gve_rx()`), the first fragment of a packet includes a 2-byte hardware padding prefix (`GVE_RX_PAD`) counted in `be16_to_cpu(desc->len)`, and `frag_size > rx->packet_buffer_size` must be checked before subtracting `page_info->pad` and syncing/copying the buffer. [F98]
- In `gve_adminq_describe_device`, after `gve_process_device_options` parses all options, `priv->queue_format` and `supported_features_mask` must be selected by testing `dev_op_dqo_rda`, `dev_op_dqo_qpl`, `dev_op_gqi_rda`, `priv->queue_format == GVE_GQI_RDA_FORMAT`, and finally `GVE_GQI_QPL_FORMAT` in that priority order. [F99]
- In `gve_rx_dqo`, after `hsplit` processing and `gve_dma_sync`, `if (rx->ctx.skb_head)` must be checked to append fragments via `gve_rx_append_frags` and return before reaching the `xprog` (XDP) or `rx_copybreak` branches. [F100]
- In `gve_rx`, every error path that drops a fragment or packet (`ctx->drop_pkt = true`) must jump to `finish_frag` rather than returning early, so `ctx->frag_cnt` is incremented and `gve_rx_ctx_clear(ctx)` resets `ctx->drop_pkt` when `is_last_frag` is true. [F105]
- In `gve_rx_poll_dqo`, `complq->head`, `complq->num_free_slots`, `complq->cur_gen_bit`, `bufq->head`, and `rx->cnt` must be updated on every consumed completion descriptor before any `continue` on `!rx->ctx.skb_head` or `!compl_desc->end_of_packet`, whereas `work_done` is incremented only when `compl_desc->end_of_packet` is set. [F107]
- In `gve_get_recycled_buf_state`, when `rx->dqo.recycled_buf_states` is empty and `rx->dqo.used_buf_states.head != -1`, the search over `rx->dqo.used_buf_states` must be bounded to a fixed number of attempts (5), re-enqueuing any `buf_state` with `gve_buf_ref_cnt(buf_state) != 0` back onto `rx->dqo.used_buf_states`. [F108]
- In `gve_handle_report_stats`, the per-queue loops for TX (`0` to `gve_num_tx_queues(priv)`) and RX (`0` to `priv->rx_cfg.num_queues`) must index `priv->tx[idx]` and `priv->rx[idx]` using the loop induction variable `idx` while advancing a single shared `stats_idx` cursor across `priv->stats_report->stats`. [F110]
- In `gve_get_ethtool_stats`, the output cursor `i` must advance by the exact per-queue stat count on every branch—including when `skip_nic_stats || stats_idx < 0` or when `priv->rx` or `priv->tx` is NULL—and `skip_nic_stats` must be reset to `false` before scanning TX NIC stats. [F111]
- In `gve_tx_avail()`, `gve_rx_refill_buffers()`, and `gve_has_free_tx_qpl_bufs()`, the `u32` producer and consumer counters (`req`/`done`, `fill_cnt`/`cnt`, `alloc_tx_qpl_buf_cnt`/`free_tx_qpl_buf_cnt`) are unmasked free-running counters whose occupancy must be computed via unsigned wrapping subtraction (`producer - consumer`). [F115]
- In DQO rings (`num_avail_tx_slots()` and `gve_rx_post_buffers_dqo()`), `head` and `tail` are pre-masked indices in `[0, mask]`, so used slots must be computed as `(tail - head) & mask` and available slots as `mask - num_used` (reserving one slot so full does not alias empty). [F116]
- In `gve_tx_alloc_ring_dqo()`, `tx->dqo.num_pending_packets` must be reduced by `(tx->dqo.complq_mask + 1) / GVE_TX_MIN_RE_INTERVAL`, halved for dual miss/reinjection completions, and clamped to `S16_MAX` so packet indices fit in positive `s16` values without colliding with `-1` or `GVE_ALT_MISS_COMPL_BIT`. [F118]
- `priv->rss_key_size` is a byte count whereas `priv->rss_lut_size` is an element count of 32-bit LUT entries (`u32` or `__be32`), so memory allocations, copies, and `gve_adminq_process_rss_query` byte-length checks must scale `priv->rss_lut_size` by 4 bytes while passing it unscaled to `configure_rss.hash_lut_size` and `rxfh->indir_size`. [F126]
- `priv->stats_report->stats` is a flexible array containing `(GVE_TX_STATS_REPORT_NUM * num_tx_queues + GVE_RX_STATS_REPORT_NUM * priv->rx_cfg.num_queues)` driver-written `struct stats` elements followed by NIC-written elements, and `gve_set_priv_flags` must only zero the driver-written prefix when `report-stats` is disabled. [F127]
- `priv->irq_db_indices` is an array of cacheline-aligned `struct gve_irq_db` elements (`irq_db_stride = sizeof(*priv->irq_db_indices)`), whereas `block->irq_db_index` is a `__be32 *` pointing to `&priv->irq_db_indices[i].index` and must not be indexed as a contiguous `__be32` array. [F128]
- In GQI QPL TX FIFO (`gve_tx_alloc_fifo`), `fifo->head` is always aligned up to `L1_CACHE_ALIGN(fifo->head)` at the end of every allocation, so `gve_skb_fifo_bytes_required` must include both wrap-around padding (`pad_bytes`) and header cacheline alignment padding (`L1_CACHE_ALIGN(hlen) - hlen`). [F152]
