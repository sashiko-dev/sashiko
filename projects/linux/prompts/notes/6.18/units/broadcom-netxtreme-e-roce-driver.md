# BROADCOM NETXTREME-E ROCE DRIVER

The Broadcom NetXtreme-E RoCE driver (`drivers/infiniband/hw/bnxt_re`) implements an InfiniBand/RDMA Verbs provider over Broadcom NetXtreme-C/E Ethernet NICs via the auxiliary bus and the `bnxt_en` Upper Layer Protocol (ULP) interface. It manages RDMA hardware resources, Doorbell Pacing, Congestion Control, hardware statistics, and debugfs/restrack diagnostics while translating IB verbs into fast-path work/completion queue operations (`qplib_fp`) and slow-path RDMA Controller Firmware (RCFW) commands (`qplib_rcfw`).

## Architecture & Data Flow
- For user QPs, `bnxt_re_init_user_qp()` sets `qplib_qp->qp_handle` to `ureq->qp_handle`, and `bnxt_re_register_ib()` enables `IB_USER_VERBS_CMD_POLL_CQ`. Kernel paths that downcast `qp_handle` or touch kernel CQ flush lists (`bnxt_qplib_add_flush_qp()`, `bnxt_qplib_clean_qp()`) must only run on kernel resources (`rdma_is_kernel_res()` / `!qp->sumem` / `!cq->umem`), and `bnxt_re_poll_cq()` on `cq->umem != NULL` must return 0 right after `bnxt_re_resize_cq_complete()` without polling CQEs or touching `cq->cql`. [F126, F173]
- During `bnxt_re_resize_cq()`, old `cq->umem` and `cq->qplib_cq.hwq` must remain allocated until `bnxt_re_poll_cq()` calls `bnxt_re_resize_cq_complete()` and `bnxt_qplib_resize_cq_complete()`, which free old `cq->hwq`, copy `cq->resize_hwq` into `cq->hwq`, clear only `BNXT_QPLIB_FLAG_EPOCH_CONS_SHIFT` in `cq->dbinfo.flags`, promote `cq->resize_umem` and `cq->resize_cqe`, and clear `cq->resize_umem = NULL`. On `bnxt_re_resize_cq()` error, rollback must release and NULL `cq->resize_umem` and restore `sg_info` and `dpi`. [F7, F62]
- In `bnxt_qplib_service_nq()`, `NQ_BASE_TYPE_CQ_NOTIFICATION` and `NQ_BASE_TYPE_SRQ_EVENT` must update `cq->toggle`/`srq->toggle`, `dbinfo.toggle`, `*uctx_cq_page`/`*uctx_srq_page`, and call `bnxt_qplib_armen_db()` before invoking `nq->cqn_handler` or `nq->srqn_handler`. `uctx_cq_page`/`uctx_srq_page` and `hash_entry` are populated only when `BNXT_QPLIB_CQ_TOGGLE_BIT` or `BNXT_QPLIB_SRQ_TOGGLE_BIT` is set in `rdev->chip_ctx->modes.toggle_bits`, so NQ and teardown paths must guard their use. [F43, F56]
- In `bnxt_qplib_poll_cq()`, `CQ_BASE_CQE_TYPE_CUT_OFF` must call `bnxt_qplib_cq_process_cutoff()` and `goto exit`, bypassing `hw_polled++`, `bnxt_qplib_hwq_incr_cons()`, and `bnxt_qplib_ring_db()`. If another CQE handler returns `-EAGAIN`, the loop must `break` before `bnxt_qplib_hwq_incr_cons()`, whereas other negative `rc` values must fall through to increment `hw_polled` and `cq->hwq.cons`. [F97, F98]
- In `bnxt_qplib_cq_process_req()`, `__flush_sq()`, and `bnxt_qplib_cq_process_terminal()`, any `while (*budget)` path skipping software CQE emission (e.g. `BNXT_QPLIB_FENCE_WRID` or unsignaled WQEs) must still advance `sq->hwq.cons` via `bnxt_qplib_hwq_incr_cons()` and update `sq->swq_last = swq->next_idx`. When emitting a software CQE, helpers must advance `*pcqe` and decrement `*budget` in lockstep. [F103, F124]
- In `bnxt_qplib_cq_process_req()`, `do_wa9060()` must be guarded by `!bnxt_qplib_is_chip_gen_p5_p7(qp->cctx)`, where `sq->condition` is cleared and `sq->single` is set only when a `BNXT_QPLIB_FENCE_WRID` CQE arrives, keeping `sq->single` true until SWQEs up to `cqe_sq_cons` complete. When a QP moves to error or is flushed, `bnxt_qplib_cancel_phantom_processing()` must clear `sq.condition`, `sq.send_phantom`, and `sq.single`. [F65, F66, F142]
- For host MSN tables (`qp->is_host_msn_tbl && psn_sz`), `bnxt_qplib_create_qp()` must size `hwq_attr.aux_depth` and `qp->msn_tbl_sz` to `roundup_pow_of_two(bnxt_qplib_set_sq_size(sq, qp->wqe_mode))` in static WQE mode and half that in variable WQE mode; `bnxt_re_init_user_qp()` must also apply `roundup_pow_of_two(psn_nume)` before multiplying by `psn_sz`. In `bnxt_qplib_post_send()`, `bnxt_qplib_fill_psn_search()` must only run for wire WQEs (`msn_update == true`). [F67, F77, F78]
- In `struct bnxt_re_nq_record`, `BNXT_RE_MAX_MSIX` must equal `BNXT_MAX_ROCE_MSIX`, `msix_entries[0]` (`BNXT_RE_AEQ_IDX`) is the CREQ, and `msix_entries[1..num_msix-1]` (`BNXT_RE_NQ_IDX`) map to `rdev->nqr->nq[0..num_msix-2]`. `bnxt_re_start_irq()` must refresh `msix_entries[].vector` before restarting CREQ and NQ (`indx - 1`) IRQs. CQ/SRQ lifecycle paths must update `nq->load` under `load_lock` without touching `nq->budget`, and `bnxt_re_synchronize_nq()` must restore `nq->budget`. [F8, F52, F61]
- `rdev->qplib_res.pacing_data` and pacing work items are initialized only when `rdev->pacing.dbr_pacing` is true. Because `bnxt_re_pacing_alert()` sets `pacing_data->do_pacing` and `alarm_th` to max on the shared `dbr_page` to suppress duplicate alerts, `bnxt_re_db_fifo_check()` must read `rdev->pacing.do_pacing_save` to compute the next pacing rate and update both `do_pacing_save` and `alarm_th`. [F44, F69]
- Ring polling (CQE, NQE, CREQ) must check validity (`CQE_CMP_VALID`, `NQE_CMP_VALID`, `CREQ_CMP_VALID`) followed by `dma_rmb()` before reading fields, and advance `cons` via `bnxt_qplib_hwq_incr_cons()` to toggle the epoch bit on wrap. Responder CQE handlers must bounds-check `wr_id_idx` against `srq->hwq.max_elements` or `rq->max_wqe - 1` before indexing `swq`. In `bnxt_re_poll_cq()`, `CQ_RES_RC_FLAGS_IMM` converts `cqe->immdata` via `cpu_to_be32()`, while `cqe->invrkey` is assigned directly. [F81, F87, F88]

## Synchronization
- When moving a kernel QP to error or cleaning its completions, callers must acquire upper-level CQ locks via `bnxt_re_lock_cqs()` before `bnxt_qplib_add_flush_qp()` or `bnxt_qplib_clean_qp()`, which then acquire lower-level `flush_lock` via `bnxt_qplib_acquire_cq_flush_locks()`. Both helpers must lock `qp->scq` first (`spin_lock_irqsave`) and `qp->rcq` second only if `qp->rcq != qp->scq`, unlocking in reverse. `bnxt_qplib_clean_qp()` must scrub `qp_handle` in `scq`/`rcq`, reset `sq`/`rq` `prod`/`cons` to 0, and remove the QP from flush lists. [F11, F23, F64]
- In `bnxt_qplib_create_qp()` and `bnxt_qplib_destroy_qp()`, `rcfw->qp_tbl[]` updates require `spin_lock_bh(&rcfw->tbl_lock)`. `bnxt_qplib_destroy_qp()` must clear `rcfw->qp_tbl[tbl_indx]` before sending `DESTROY_QP` and restore it under `tbl_lock` on failure. `bnxt_qplib_process_qp_event()` must hold `spin_lock(&rcfw->tbl_lock)` across looking up `qp_handle`, calling `bnxt_qplib_mark_qp_error()`, and invoking `rcfw->creq.aeq_handler()`. [F20, F68]
- `rcfw->cmdq.hwq.lock` requires `spin_lock_bh()` in process context and `spin_lock_nested(&hwq->lock, SINGLE_DEPTH_NESTING)` inside `bnxt_qplib_process_qp_event()` (under `creq.hwq.lock`). Under `cmdq.hwq.lock`, `__bnxt_qplib_rcfw_send_message()` and `bnxt_qplib_process_qp_event()` synchronize `crsqe->is_waiter_alive` and `crsqe->resp` (with `cookie` masked by `RCFW_MAX_COOKIE_VALUE`), and `bnxt_qplib_process_qp_event()` must issue `smp_wmb()` after copying `crsqe->resp` before clearing `crsqe->is_in_used`. [F26, F84, F151]
- Callers of `__send_message_no_waiter()` must hold `rcfw->cmdq.hwq.lock`, and both `__send_message()` and `__send_message_no_waiter()` must execute `wmb()` before `writel()` to `cmdq_mbox.prod` and `db`. Both `bnxt_qplib_service_nq()` and `bnxt_qpn_cqn_sched_task()` must hold `spin_lock_bh(&cq->compl_lock)` around `cq->arm_state`, `cq->cnq_events`, and `nq->cqn_handler()`, with `bnxt_qpn_cqn_sched_task()` rechecking `cq->arm_state` under the lock. [F27, F30]
- Because `bnxt_re_pacing_alert()` and `bnxt_re_db_fifo_check()` call `cancel_work_sync()` and `cancel_delayed_work_sync()` while holding `rdev->pacing.dbq_lock`, workers `bnxt_re_db_fifo_check()` and `bnxt_re_pacing_timer_exp()` must use `mutex_trylock(&rdev->pacing.dbq_lock)`. [F18]
- `bnxt_qplib_rcfw_start_irq()` and `bnxt_qplib_rcfw_stop_irq()` must maintain `rcfw->rcfw_intr_enabled` so `__bnxt_qplib_rcfw_send_message()` polls via `__poll_for_resp()` when CREQ IRQs are stopped. Non-sleepable RCFW callers (`bnxt_re_create_ah()` / `bnxt_re_destroy_ah()` without sleepable flags) must set `cmdqmsg.block = true`. `bnxt_qplib_post_send()`/`post_recv()` (under `sq_lock`/`rq_lock`) and `bnxt_re_async_notifier()` must use `GFP_ATOMIC` and queue work to `cqn_wq` or `rdev->dcb_wq`. [F31, F153, F159, F163]

## Object Lifetimes
- Because `bnxt_re_register_netdev()` registers `rdev->adev` as the ULP `void *handle`, `bnxt_ulp_ops` callbacks and `bnxt_re_remove()` must extract `en_info` via `auxiliary_get_drvdata(handle)` and check `en_info->rdev != NULL`. Updates to `en_info->rdev` must use `bnxt_re_update_en_info_rdev()` (under `rtnl_lock()`), and clear it on `bnxt_re_add_device()` rollback and in `bnxt_re_suspend()`. [F15, F119]
- `bnxt_re_dev_init()` registers netdev only on `BNXT_RE_COMPLETE_INIT`, `bnxt_re_dev_uninit()` unregisters via `bnxt_unregister_dev()` only on `BNXT_RE_COMPLETE_REMOVE`, and `bnxt_re_probe()` must `kfree(en_info)` if `bnxt_re_add_device()` fails. [F16, F137]
- In `bnxt_re_destroy_qp()`, `bnxt_re_debug_rem_qpinfo()` and `bnxt_qplib_flush_cqn_wq()` must precede `bnxt_qplib_destroy_qp()`, followed by `bnxt_qplib_clean_qp()` (under `bnxt_re_lock_cqs()`), `bnxt_qplib_free_qp_res()`, list removal, `ib_umem_release()`, and `bnxt_re_synchronize_nq()`, returning 0 even if firmware destroy fails. On pre-GenP5 GSI QPs, `bnxt_re_destroy_gsi_sqp()` calls `bnxt_qplib_clean_qp()` on `&qp->qplib_qp` but destroys/frees `gsi_sqp`. `bnxt_qplib_destroy_cq()` must call `__wait_for_all_nqes()` before freeing `hwq`. [F10, F106, F132, F164]
- In `bnxt_re_dev_uninit()`, `bnxt_re_net_unregister_async_event()` (passing persistent `&rdev->event_bitmap`) must precede `bnxt_re_uninit_dcb_wq()`; `bnxt_re_deinitialize_dbr_pacing()` must cancel pacing works before freeing `dbr_page`; and `bnxt_re_free_gid_ctx()` must precede `bnxt_re_cleanup_res()` and `bnxt_re_free_res()`. [F5, F17, F130]
- In `bnxt_re_suspend()`, if `BNXT_STATE_FW_FATAL_COND` is set, the driver must set `ERR_DEVICE_DETACHED` and `BNXT_RE_FLAG_ERR_DEVICE_DETACHED`, wake `cmdq.waitq`, and call `bnxt_re_dev_stop()` (which only dispatches `IB_EVENT_QP_FATAL` without `bnxt_re_modify_qp()`). When detached, RCFW send/wait/poll paths must map return codes via `bnxt_qplib_map_rc(opcode)`, and `bnxt_re_net_ring_free()` / `bnxt_re_net_stats_ctx_free()` must return 0 without calling `bnxt_send_msg()`. [F99, F134, F135]
- Once `bnxt_re_mmap_entry_insert()` succeeds, `bnxt_re_user_mmap_entry` must be released via `rdma_user_mmap_entry_remove()`, never `kfree()`. `uctx->dpi` is lazily allocated on the first user PD in `bnxt_re_alloc_pd()` and deallocated only in `bnxt_re_dealloc_ucontext()`. In `bnxt_qplib_create_srq()`/`create_qp()`, `swq` and `bnxt_qplib_init_psn_ptr()` are allocated only for `!hwq.is_user`, and `bnxt_qplib_free_hwq()` must pass `is_umem = hwq->is_user` to `__free_pbl()` only at leaf level (`i == hwq->level`). [F2, F9, F73, F166]
- In `bnxt_re_create_fence_mr()`, `fence->dma_addr`, `lkey`, `rkey`, and `fence->mw` must only be set after each step succeeds (resetting `ERR_PTR` fields like `fence->mw` or `cq->resize_umem` to `NULL` on `IS_ERR()`), as `bnxt_re_destroy_fence_mr()` uses them as unwind guards. In `bnxt_re_create_ah()` and `bnxt_re_modify_qp()`, `rdma_read_gid_hw_context()` returns a borrowed reference whose `ctx->refcnt` must not be modified. [F6, F19, F46]

## API Contracts
- `__bnxt_re_user_reg_mr()` takes ownership of `umem` only on success; on error callers (`bnxt_re_reg_user_mr()`, `bnxt_re_reg_user_mr_dmabuf()`) must call `ib_umem_release(umem)`. [F1]
- In `__send_message()`, `bnxt_qplib_get_cmd_slots()` and the free-slot check must run before `bnxt_qplib_set_cmd_slots()` mutates `req->cmd_size` into 16-byte `BNXT_QPLIB_CMDQE_UNITS` slots (via ceiling division), while `crsqe->req_size` is set after. Callers with a DMA side buffer (`msg->sb`) must align `sbuf.size` to 16 bytes, set `req.resp_size = sbuf.size / BNXT_QPLIB_CMDQE_UNITS`, and check `!rc` before reading `sbuf.sb`. Stack request structs must be zero-initialized before `bnxt_qplib_rcfw_cmd_prep()` or `bnxt_re_init_hwrm_hdr()`. [F34, F49, F57, F115, F121]
- Callers of `bnxt_qplib_create_srq()`, `create_qp()`, or `create_cq()` must set `sg_info.pgsize = PAGE_SIZE` and `pgshft = PAGE_SHIFT` for both kernel and user queues, and set `hwq_attr.aux_depth = 0` when `aux_stride == 0`. `bnxt_qplib_create_srq()` must call `bnxt_qplib_armen_db(&srq->dbinfo, DBC_DBC_TYPE_SRQ_ARMENA)` unconditionally, and `bnxt_re_modify_srq()` must call `bnxt_qplib_srq_arm_db()` directly on `IB_SRQ_LIMIT` while returning `-EINVAL` on `IB_SRQ_MAX_WR` or `default`. [F47, F95, F111, F144, F145]
- On INIT-to-RTR, `__modify_flags_from_init_state()` must not clear `CMDQ_MODIFY_QP_MODIFY_MASK_VLAN_ID`, and `bnxt_re_modify_qp()` must check `qp_attr->path_mtu` against `iboe_get_mtu(rdev->netdev->mtu)`. On RC RTR-to-RTS in `bnxt_set_mandatory_attributes()`, `CMDQ_MODIFY_QP_MODIFY_MASK_MIN_RNR_TIMER` must be set when `_is_min_rnr_in_rtr_rts_mandatory()` is true. [F59, F79, F143]
- `bnxt_re_init_qp_type()` and `bnxt_re_copy_wr_payload()` / `bnxt_re_copy_inline_data()` return negative errnos on failure and must be checked in a signed `int`. `bnxt_re_add_gid()` must handle `-EALREADY` from `bnxt_qplib_add_sgid()` by incrementing `sgid_tbl->ctx[tbl_idx]->refcnt` and returning 0. In `bnxt_re_aeq_handler()` and `bnxt_re_handle_affi_async_event()`, `void *obj` is polymorphic and must be checked via `creqe->type` and `affi_async->event` before downcasting. [F36, F37, F38, F127]

## Error Handling
- In `bnxt_re_mmap()`, every path after `rdma_user_mmap_entry_get()` returns non-NULL must call `rdma_user_mmap_entry_put(rdma_entry)`. `BNXT_RE_MMAP_DBR_PAGE` and `BNXT_RE_MMAP_TOGGLE_PAGE` must reject `VM_WRITE` with `-EFAULT` before `vm_insert_page()`, while BAR mappings must use `rdma_user_mmap_io()`. [F3, F165]
- `__bnxt_qplib_rcfw_send_message()` must return `-EIO` on non-zero `evnt->status`. `qp->qplib_qp.srq` is `NULL` on non-SRQ QPs and must be checked before `container_of()` in `bnxt_re_handle_qp_async_event()`. In `bnxt_re_create_cq()` and `bnxt_re_create_srq()`, if `get_zeroed_page()` fails after `rc == 0`, `rc` must be set to `-ENOMEM`. [F32, F40, F45]

## External Contracts
- `bnxt_re_process_mad()` must return an `IB_MAD_RESULT_*` bitmask (converting non-zero `rc` to `IB_MAD_RESULT_FAILURE`), never a negative errno, and PMA counter helpers must divide byte counts by 4 for `port_rcv_data` and `port_xmit_data`. `struct bnxt_re_pd_resp` must remain `__attribute__((packed, aligned(4)))` with UAPI `resp` reserved fields zeroed. [F39, F168, F172]

## Known Pitfalls
- In `bnxt_re_post_send()` and `bnxt_re_post_recv()` (and shadow QP variants), stack `struct bnxt_qplib_swqe wqe` must be zeroed each loop iteration. In `bnxt_qplib_post_send()`, `BNXT_QPLIB_SWQE_TYPE_SEND` breaks only for `CMDQ_CREATE_QP1_TYPE_GSI` and otherwise falls through; PSN calculation must guard `qp->mtu == 0` and clamp `pkt_num >= 1`; `psn` increments must mask with `BTH_PSN_MASK`; and `avid` must be `u32`. In `bnxt_re_build_qp1_send_v2()`, `wqe->sg_list` must shift up via a reverse loop. [F48, F96, F110, F114, F118, F125]
- 32/16-bit values must be cast to `u64` before shifting by >= 24 bits (`st_idx`/`npsn` in `bnxt_re_update_msn_tbl()`, `..._handle_high << 32` in `clean_nq()` and `bnxt_qplib_service_nq()`, and `hwrm_intf_major`/`minor` in `bnxt_re_query_hwrm_intf_version()`). In `bnxt_re_process_res_rc_wc()`, `IB_WC_RECV_RDMA_WITH_IMM` requires both `CQ_RES_RC_FLAGS_RDMA | CQ_RES_RC_FLAGS_IMM` bits set. In `bnxt_re_cc_config_set()`, `count >= sizeof(buf)` must be rejected before `buf[count] = '\0'`. [F93, F107, F108, F109, F129]
