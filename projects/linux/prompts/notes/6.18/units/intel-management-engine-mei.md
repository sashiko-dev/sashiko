# INTEL MANAGEMENT ENGINE (mei)

The Intel Management Engine Interface (MEI) subsystem provides the core character device interface (`/dev/mei*`), client bus abstraction, hardware transport bindings (PCI ME, PCI TXE, and SPI/platform Visual Sensing Controller), and client drivers (iAMT watchdog, i915 PXP, and late-binding firmware upload). It manages host-to-firmware communication sessions, virtual tags (vtags), flow control credits, power gating transitions, and firmware loading.

## Architecture & Data Flow
- When `mei_ioctl_connect_vtag()` merges an `MEI_FILE_INITIALIZING` file with an existing `struct mei_cl` on `dev->file_list`, it must unlink and free the initial `cl` and update both `file->private_data` and local `cl` to `pos` before adding `cl_vtag` to `cl->vtag_map`. When `mei_release()` closes a file while other `cl->vtag_map` entries remain, it must pass `file` (not `NULL`) to `mei_cl_flush_queues(cl, file)`. [F53, F56]
- In `mei_read()`, `*offset` and completed read callback `cb` must update in lockstep: reset `*offset = 0` when no completed `cb` is queued before `mei_cl_read_start()` and whenever `mei_cl_del_rd_completed(cl, cb)` frees `cb`, while keeping `cb` in `cl->rd_completed` when `*offset < cb->buf_idx`. [F58]
- `mei_me_set_pm_domain()` and `mei_txe_set_pm_domain()` must copy `*pdev->dev.bus->pm` into per-instance `dev->pg_domain.ops` before overriding runtime PM callbacks, and `mei_me_unset_pm_domain()` / `mei_txe_unset_pm_domain()` must reset `dev_pm_domain_set(dev->parent, NULL)` on remove and shutdown. In `mei_me_probe()` and `mei_me_remove()`, gate `pm_runtime_put_noidle(&pdev->dev)` and `pm_runtime_get_noresume(&pdev->dev)` on `if (mei_pg_is_enabled(dev))`. [F60, F129]
- In `drivers/misc/mei/vsc-tp.c`, `struct vsc_tp_packet.buf` must remain a fixed-size array of `VSC_TP_MAX_XFER_SIZE - sizeof(struct vsc_tp_packet_hdr)` bytes rather than a flexible array `__counted_by` `hdr.len`, because `hdr.len` excludes the trailing `VSC_TP_CRC_SIZE` CRC written at `pkt->buf + olen`. [F103]
- In `vsc_tp_xfer_helper()`, zero `pkt` (`tp->tx_buf`) with `memset(pkt, 0, VSC_TP_MAX_XFER_SIZE)` immediately after the first `vsc_tp_dev_xfer()` so subsequent SPI transfers clock out zeroes, and bound payload copying into `ibuf` by `min(ilen, le16_to_cpu(ack.len))` while still consuming and accumulating CRC on remaining bytes up to `sizeof(ack) + le16_to_cpu(ack.len)`. [F51, F80]
- In `platform-vsc.c`, `mei_vsc_read()` must verify `mei_vsc_read_helper()` returned at least `sizeof(u32)` bytes before reading `hw->rx_hdr` with `get_unaligned_le32()`, and `mei_vsc_read_slots()` must verify `len == hdr->length` and `hdr->length + sizeof(*hdr) == hw->rx_len` before copying from `hw->rx_buf + sizeof(*hdr)`. [F81]
- In `vsc_identify_csi_image()` and `vsc_identify_ace_image()`, verify `(u8 *)sign + sizeof(*sign) <= image->data + image->size` before dereferencing each `struct vsc_fw_sign`, and run `vsc_identify_csi_image()` before `vsc_identify_ace_image()` because a zero `img->image_location[i]` in ACE derives `frag->location` from `fw_loader->frags[frag_index - 1]` (`VSC_IMG_CSI_RUNTIME_FRAG`) via `ALIGN(last_frag->location + last_frag->size, SZ_4K)`. [F76, F98]
- In `vsc_download_firmware()`, the `VSC_CMD_DL_SET` loop must iterate `fw_loader->frags[]` from `VSC_IMG_CSI_SEM_FRAG` through `VSC_IMG_CSI_EM7D_FRAG` inclusive (matching `fw_loader->count`), whereas `VSC_CMD_DL_START` iterates to `VSC_IMG_FRAG_MAX` exclusive; when a final fragment chunk has `len < VSC_FW_PKG_SIZE`, zero the trailing `VSC_FW_PKG_SIZE - len` bytes of `fw_loader->tx_buf` before calling `vsc_tp_rom_xfer()`. [F50, F77]
- Because `__mei_wdt_is_registered()` tests `watchdog_get_drvdata(&wdt->wdd)` under `wdt->reg_lock`, `mei_wdt_register()` must reset drvdata to `NULL` if `watchdog_register_device()` fails, and `mei_wdt_unregister()` must clear drvdata to `NULL` and zero `wdt->wdd` after `watchdog_unregister_device()`. [F12]
- In `mei_wdt.c`, `mei_wdt_register()` must cap `wdt->wdd.max_timeout` at `MEI_WDT_MAX_TIMEOUT` (`65535`) so 16-bit timeout fields never overflow, and `wdt->timeout` and `wdd->timeout` must stay synchronized across `mei_wdt_ops_set_timeout()` and `mei_wdt_ops_start()`. Outgoing Management Control requests must set `req.hdr.bytecount` to `sizeof(req) - offsetof(struct mei_mc_hdr, subcommand)`, and `mei_wdt_rx()` must ignore 0-byte responses and reject positive responses smaller than `sizeof(struct mei_mc_hdr)`. [F62, F83, F101]

## Synchronization
- In `mei_read()`, `mei_write()`, `mei_fsync()`, `mei_ioctl_connect_client()`, and `mei_ioctl_connect_vtag()`, unlock `dev->device_lock` before calling `wait_event*()` on `cl->rx_wait`, `cl->tx_wait`, `cl->wait`, or `dev->wait_dev_state` and re-acquire it afterward; in `mei_read()`, recheck `mei_cl_is_connected(cl)` and refetch `mei_cl_read_cb(cl, file)`, returning `0` if `cb` is `NULL`. [F21, F145]
- `cl->rd_completed` in `struct mei_cl` is protected by `spinlock_t rd_completed_lock` because `mei_cl_read_cb()` inspects it inside the `wait_event_interruptible()` condition of `mei_read()` while `dev->device_lock` is dropped and task state is non-running. Broken by: accessing `cl->rd_completed` under `dev->device_lock` alone or taking a sleeping lock in `mei_cl_read_cb()`. [F144]
- Across `vsc-tp.c` and `platform-vsc.c`, locks must nest in the order `tp->event_notify_mutex` -> `mei_dev->device_lock` -> `tp->mutex`. `tp->event_notify_mutex` protects `tp->event_notify` and `tp->event_notify_context` in `vsc_tp_event_work()` and `vsc_tp_register_event_cb()`. [F16, F18]
- In `vsc-tp.c`, `tp->mutex` must be held across `vsc_tp_xfer()` and `vsc_tp_rom_xfer()` to serialize `tp->tx_buf`, `tp->rx_buf`, and `tp->seq` (`vsc_tp_xfer_helper()` requires exact equality `le32_to_cpu(ack.seq) == tp->seq`), and every `vsc_tp_wakeup_request(tp)` in `vsc_tp_xfer()` must be paired under `tp->mutex` with `vsc_tp_wakeup_release(tp)` even on error. [F19, F102, F125]
- In `vsc_tp_probe()`, `vsc_tp_isr` must be registered as an `IRQF_ONESHOT` threaded IRQ handler (`request_threaded_irq(spi->irq, NULL, vsc_tp_isr, ...)`) and defer `tp->event_notify` to `tp->event_work`. In `vsc_tp_wakeup_request()`, `wait_event_timeout()` must only evaluate non-sleeping state (`atomic_read(&tp->assert_cnt)`), polling `gpiod_get_value_cansleep(tp->wakeuphost)` afterward via `read_poll_timeout()`. [F117, F138]
- In `mei_me_pm_runtime_suspend()`, `mei_txe_pm_runtime_suspend()`, and `mei_vsc_suspend()`, hold `dev->device_lock` continuously across `mei_write_is_idle()` and any synchronous power-gating or aliveness transition (`mei_me_pg_enter_sync()`, `mei_txe_aliveness_set_sync()`). [F25]
- In `drivers/watchdog/mei_wdt.c`, hold `wdt->reg_lock` across `__mei_wdt_is_registered()`, `watchdog_register_device()`, and `watchdog_unregister_device()`. In `mei_wdt_ops_ping()`, call `init_completion(&wdt->response)` before `mei_wdt_ping(wdt)` when `wdt->resp_required` is true. In `mei_wdt_rx()`, when `wdt->state == MEI_WDT_RUNNING` and `res.wdstate & MEI_WDT_WDSTATE_NOT_REQUIRED` is set, defer unregistration via `schedule_work(&wdt->unregister)` and jump to `out` to call `complete(&wdt->response)`. [F28, F29, F91]

## Object Lifetimes
- Every `struct mei_device` and trailing `dev->hw[]` must be a single `kfree`-compatible block stored unchanged as `&dev->dev` drvdata (`mei_device_release()` frees `kfree(dev_get_drvdata(dev))`). Because `cdev_del()`/`device_destroy()` can trigger `mei_device_release()`, `mei_register()` and `mei_deregister()` must cache `dev->minor` beforehand and never dereference `dev` afterward, and `mei_deregister()` must run last in `mei_me_remove()`, `mei_txe_remove()`, and `mei_vsc_remove()` after `mei_stop()`, PM/callback teardown, `mei_disable_interrupts()`, and `free_irq()`. [F1, F2, F107]
- On `mei_vsc_probe()` failure and in `mei_vsc_remove()`, clear the event callback via `vsc_tp_register_event_cb(tp, NULL, NULL)` so `vsc_tp_event_work()` cannot invoke `mei_vsc_event_cb()` with a dangling `mei_dev`. In `vsc_tp_remove()` (also wired as `.shutdown`) and `vsc_tp_probe()` error paths, unregister `tp->pdev`, call `free_irq(spi->irq, tp)`, and call `cancel_work_sync(&tp->event_work)` before destroying `tp->event_notify_mutex` and `tp->mutex`. [F3, F116]
- Because `mei_ioctl_connect_vtag()` shares a `struct mei_cl` across tagged opens, `mei_release()` must remove the file's entry from `cl->vtag_map` and only disconnect, unlink, and `kfree(cl)` if `list_empty(&cl->vtag_map)` holds both before and after `mei_cl_disconnect(cl)` (which drops `dev->device_lock`). [F5]
- `mei_me_cl_by_uuid()` returns a refcounted `struct mei_me_client` via `mei_me_cl_get()`, so callers like `mei_ioctl_connect_client()` and `mei_vt_support_check()` must call `mei_me_cl_put()` on every return path and before looping to `retry:`. [F6]
- `vsc_identify_csi_image()`, `vsc_identify_ace_image()`, and `vsc_identify_cfg_image()` populate `fw_loader->frags[]` with pointers into `fw_loader->csi`, `fw_loader->ace`, and `fw_loader->cfg`, so `vsc_tp_init()` must not call `release_firmware()` until `vsc_download_bootloader()` and `vsc_download_firmware()` finish. In `vsc_get_sensor_name()`, call `ACPI_FREE(buffer.pointer)` on every exit path once `acpi_evaluate_object()` sets a non-NULL `buffer.pointer`. [F9, F120]
- In `mei_pxp_probe()` and `mei_pxp_remove()`, store `comp_master` via `mei_cldev_set_drvdata()` before `component_master_add_with_match()`, and complete `component_master_del()` before freeing `comp_master`, clearing drvdata, and calling `mei_cldev_disable()`. [F11]
- In `mei_wdt_remove()`, complete `wdt->response` (if not `completion_done()`) and call `cancel_work_sync(&wdt->unregister)` before calling `mei_wdt_unregister(wdt)`, `mei_cldev_disable(cldev)`, `dbgfs_unregister(wdt)`, and `kfree(wdt)`. [F134]

## API Contracts
- `mei_cl_write()` unconditionally takes ownership of `struct mei_cl_cb *cb` (queuing it or freeing it via `mei_io_cb_free()` on error), so `mei_write()` must only call `mei_io_cb_free(cb)` when failing before `mei_cl_write()`. [F7]
- Callers of `mei_fw_status_str(dev, buf, len)` and `mei_fw_status2str()` must pass a `buf` of at least `MEI_FW_STATUS_STR_SZ` (54) bytes because `mei_fw_status_str()` unconditionally passes `MEI_FW_STATUS_STR_SZ` to `mei_fw_status2str()`. [F47]
- `vsc_tp_probe()` sets `pinfo.data = &tp` (`sizeof(tp)`), so child platform device consumers like `mei_vsc_probe()` must dereference `*(struct vsc_tp **)dev_get_platdata(dev)`. Unlike `vsc_tp_rom_xfer()`, `vsc_tp_xfer()` rejects `obuf == NULL`, `ibuf == NULL`, or `olen > VSC_TP_MAX_MSG_SIZE` with `-EINVAL`. [F37, F106]
- In `mei_vsc_hw_reset(mei_dev, intr_enable)`, return `0` immediately after `vsc_tp_reset(hw->tp)` without `vsc_tp_init()` when `!intr_enable`. In `mei_vsc_hw_start()`, after `vsc_tp_intr_enable(hw->tp)`, poll `mei_vsc_read_helper()` with `sleep_before_read = true`, `MEI_VSC_POLL_DELAY_US` (100 ms), and `MEI_VSC_POLL_TIMEOUT_US` (400 ms) before setting `hw->fw_ready = true`. In `mei_vsc_suspend()`/`mei_vsc_resume()`, do not call `mei_stop()`/`mei_restart()`; `mei_vsc_suspend()` only checks `mei_write_is_idle(mei_dev)` under `device_lock` (`-EAGAIN` if busy). [F115, F123, F126]

## Error Handling
- `mei_cldev_send()`, `mei_cldev_send_timeout()`, and `vsc_tp_xfer()` return non-negative byte counts on success and negative errnos on failure, so callers with a 0-on-success contract (`mei_pxp_send_message()`, `mei_wdt_ping()`, `mei_wdt_stop()`, `mei_vsc_write()`) must normalize non-negative returns to `0`. [F32, F34]
- In `mei_pxp.c`, `mei_pxp_receive_message()` retries `-ENOMEM` at most once (`!retry` -> `retry = true; goto retry`) before falling through to `mei_pxp_reenable()`; `mei_pxp_reenable()` must still call `mei_cldev_enable()` if `mei_cldev_disable()` fails, and callers must preserve the original negative `byte` error when `mei_pxp_reenable()` returns `0`. [F68, F89]
- `mei_cl_fp_by_vtag()`, `mei_cl_vtag_alloc()`, and `mei_cl_alloc_linked()` return `ERR_PTR(-errno)` on failure (and `mei_cl_fp_by_vtag()` returns `NULL` as a valid bus client `fp`), so callers must check `IS_ERR()`. While iterating `dev->file_list`, check `pos->me_cl != NULL` before calling `mei_cl_uuid(pos)` or accessing `pos->me_cl->props`. [F38, F46]
- In `mei_lb_check_response()`, validate `bytes >= sizeof(rsp->header)` and header fields (`group_id`, `command`, `result`) before checking `bytes < sizeof(*rsp)` or reading `rsp.status`, because firmware error replies may contain only the 4-byte `struct mkhi_msg_hdr`. [F40]
- `vsc_tp_rom_xfer()` returns `0` on SPI transfer success regardless of firmware response content, so `vsc_identify_silicon()` and `vsc_download_bootloader()` must validate `ack->token` against `VSC_TOKEN_ERROR` / expected tokens. [F35]
- In `mei_me_pm_runtime_suspend()` and `mei_txe_pm_runtime_suspend()`, guard `schedule_work(&dev->reset_work)` with `if (ret && ret != -EAGAIN)`. In `mei_me_pci_resume()`, if `mei_restart(dev)` fails after requesting the IRQ, call `free_irq(pdev->irq, dev)` before returning. [F95, F130]

## External Contracts
- In `mei_ioctl()`, `IOCTL_MEI_CONNECT_CLIENT` must route vtag-capable clients (`mei_vt_support_check() == 0`) through `mei_ioctl_connect_vtag()` with `vtag = 0`, while `IOCTL_MEI_CONNECT_CLIENT_VTAG` must reject `vtag == 0` with `-EINVAL`. [F57]

## Known Pitfalls
- In `struct mei_connect_client_data` and `struct mei_connect_client_data_vtag`, input (`in_client_uuid` / `connect`) and output (`out_client_properties`) share a union, and `mei_ioctl_connect_client()` / `mei_ioctl_connect_vtag()` only write `max_msg_length` and `protocol_version`: `mei_ioctl()` must copy `in_client_uuid` (and `vtag`) into locals before passing `&conn.out_client_properties` (preserving the `copy_from_user`-initialized union so `reserved[3]` and padding are not leaked uninitialized). [F39, F151]
- When initializing `union acpi_object` with designated initializers (e.g. in `vsc_get_sensor_name()`), initialize both `.integer.type` and `.integer.value` within `.integer` rather than mixing `.type` and `.integer.value` (which overwrites `.integer.type` with 0). [F42]
- In `struct vsc_fw_cmd`, 16-bit `data.dl_start.option` and `data.dl_set.option` sit at unaligned byte offset 5 and must use unaligned helpers like `put_unaligned_le16()`. In `vsc_download_firmware()`, because `cmd` aliases `fw_loader->tx_buf` and the fragment transfer loop overwrites `tx_buf`, re-initialize `cmd->magic` and `cmd->cmd_id` on every outer iteration and before `VSC_CMD_CAM_BOOT`. [F78, F94]
- In `vsc_identify_csi_image()` and `vsc_identify_ace_image()`, locate the first `struct vsc_fw_sign` at `img->image_location + le32_to_cpu(img->image_count)` rather than `img + 1`, because the binary only contains `image_count` location entries instead of `VSC_IMG_CNT_MAX`. [F105]
