# LED SUBSYSTEM

This component implements the Linux LED subsystem core (`led-core.c`, `led-class.c`), trigger framework (`led-triggers.c`), flash (`led-class-flash.c`) and multicolor (`led-class-multicolor.c`) class extensions, and hardware LED/flash controller drivers. It manages LED registration, sysfs attributes, consumer lookup (`led_get` / `of_led_get`), software blinking via timers, deferred brightness updates via workqueues, and V4L2 flash subdevice integration.

## Architecture & Data Flow

- `LED_BLINK_SW` in `led_cdev->work_flags` is set only when `led_set_software_blink()` arms `blink_timer` and cleared when software blinking stops in `led_blink_set()`, `led_stop_software_blink()`, or `led_timer_function()`. In `led_timer_function()`, reaching the final state of a `LED_BLINK_ONESHOT` cycle must set `LED_BLINK_ONESHOT_STOP` and still call `mod_timer()`, clearing `LED_BLINK_SW` only on the next tick. [F59, F96]
- In `led_classdev_suspend()`, `LED_SUSPENDED` must be set in `led_cdev->flags` before calling `led_set_brightness_nopm(led_cdev, 0)` and `flush_work(&led_cdev->set_brightness_work)`; in `led_classdev_resume()`, it is cleared only after `led_set_brightness_nopm()` and `flash_resume()` complete. While set, `LED_SUSPENDED` gates hardware callbacks in `led_set_brightness_nosleep()`, `led_set_brightness_sync()`, and `led_set_flash_brightness/timeout/duration()` while updating software settings. [F61, F143]
- Generic core and trigger paths (`led_mc_set_brightness()`, `led_mc_trigger_event()`) must check `led_cdev->flags & LED_MULTI_COLOR` before calling `lcdev_to_mccdev()`, and `led_mc_set_brightness()` must verify `num_colors == mcled_cdev->num_colors` before indexing `subled_info`. In `led_mc_calc_color_components()`, channel brightness must be scaled with `DIV_ROUND_CLOSEST(brightness * subled_info[i].intensity, max_brightness)` so low non-zero values do not truncate to 0. [F106, F116]
- `LED_FLASH_SYSFS_GROUPS_SIZE` (5) in `struct led_classdev_flash::sysfs_groups` must be at least one larger than the max groups appended by `led_flash_init_sysfs_groups()` (4) to stay NULL-terminated for `device_create_with_groups()`. In `flash_fault_show()`, `ARRAY_SIZE(led_flash_fault_names)` must equal `LED_NUM_FLASH_FAULTS`. [F86, F122]

## Synchronization

- `led_classdev_register_ext()` must initialize and lock `led_cdev->led_access` before `device_create_with_groups()` and hold it through `trigger_lock` init, `leds_list` insertion, `max_brightness`, `wq`, `led_init_core()`, and `led_trigger_set_default()`. It must not auto-promote `hw_control_trigger` to `default_trigger` (which deadlocks with `rtnl_mutex` in `ledtrig-netdev`). Callers of `led_sysfs_disable()` / `led_sysfs_enable()` must hold `led_access`, and sysfs store handlers must check `led_sysfs_is_disabled()` under `led_access` and return `-EBUSY`. [F21, F153, F168]
- Driver callbacks invoked from `set_brightness_delayed()` (`brightness_set`, `brightness_set_blocking`, `blink_set`) must never acquire `led_cdev->led_access` or `led_cdev->trigger_lock`. [F25]
- In the trigger lock hierarchy, `triggers_list_lock` and `leds_list_lock` nest outside `led_cdev->trigger_lock`, and `trig->leddev_list_lock` nests inside `led_cdev->trigger_lock`. Callers of `led_trigger_set()` must hold `down_write(&led_cdev->trigger_lock)`. `led_trigger_read()` must lock `triggers_list_lock` then `led_cdev->trigger_lock`, unlock both in reverse order on `kvmalloc()` failure or before `memory_read_from_buffer()`, and free `data` with `kvfree(data)`. [F11, F152]
- Traversals of `trig->led_cdevs` (`led_trigger_event()`, `led_mc_trigger_event()`, `led_trigger_blink_setup()`) must use `list_for_each_entry_rcu()` under `rcu_read_lock()`. In `led_trigger_set()`, attaching must call `list_add_tail_rcu()` under `trig->leddev_list_lock`, `synchronize_rcu()`, and `flush_work(&led_cdev->set_brightness_work)` before `trig->activate()`; detaching must call `list_del_rcu()` under `leddev_list_lock`, `synchronize_rcu()`, `cancel_work_sync()`, and `led_stop_software_blink()` before removing groups, calling `deactivate()`, and clearing `trigger_data`. [F9, F28, F97]
- `led_blink_setup()` and `led_blink_set_oneshot()` run inside `rcu_read_lock()` from `led_trigger_blink_setup()` (and softirq/timer contexts) and must not call `flush_work()` or sleep. When `LED_BLINK_SW` is set and `brightness == LED_OFF`, `led_set_brightness()` (which may run in hardirq context) must set `LED_BLINK_DISABLE` and queue `set_brightness_work` rather than calling `led_stop_software_blink()` (`timer_delete_sync()`) directly. [F148, F149]
- In `led_set_brightness_nopm()`, a deferred `LED_OFF` (0) update clears `LED_SET_BRIGHTNESS` and `LED_SET_BLINK` and sets `LED_SET_BRIGHTNESS_OFF` after writing `delayed_set_value`; `set_brightness_delayed()` processes `LED_SET_BRIGHTNESS_OFF` before `LED_SET_BRIGHTNESS` and re-sets `LED_SET_BRIGHTNESS` if `delayed_set_value != LED_OFF`. [F60]
- `led_get()` must hold `leds_lookup_lock` while searching `leds_lookup_list` and copy `lookup->provider` with `kstrdup_const()` before unlocking and calling `class_find_device_by_name()`. [F29]

## Object Lifetimes

- `led_module_get()` takes ownership of the `struct device` reference from `class_find_device_by_of_node()` / `class_find_device_by_name()`, calling `put_device(led_cdev->dev)` if `try_module_get()` fails. A `struct led_classdev` from `led_get()` must be released with `led_put()`, which calls `module_put()` before `put_device(led_cdev->dev)`, and `led_add_lookup()` entries must be removed with `led_remove_lookup()` before freeing. [F1, F179]
- When `led_classdev_next_name()` probes for collisions via `class_find_device_by_name()`, every non-NULL `struct device *` returned must be released with `put_device(dev)` inside the loop. [F3]
- `led_add_brightness_hw_changed()` acquires a `kernfs_node` via `sysfs_get_dirent()` after `device_create_file()` and must call `device_remove_file()` if `sysfs_get_dirent()` returns NULL; `led_remove_brightness_hw_changed()` must call `sysfs_put(led_cdev->brightness_hw_changed_kn)` before `device_remove_file()`. [F5]
- During `led_classdev_unregister()`, `led_trigger_set(led_cdev, NULL)`, `led_stop_software_blink()`, and `flush_work(&led_cdev->set_brightness_work)` must complete before `device_unregister(led_cdev->dev)`, `list_del(&led_cdev->node)` under `leds_list_lock`, and `mutex_destroy(&led_cdev->led_access)`. Drivers using `devm_led_classdev_register_ext()` or `devm_led_classdev_flash_register_ext()` must not call `mutex_destroy()` in `.remove()` on a mutex used by `brightness_set_blocking`, since devres unregisters the LED and flushes `set_brightness_work` after `.remove()`. [F6, F126]
- `led_trigger_unregister()` must unlink `trig->next_trig` with `list_del_init()` under `triggers_list_lock` (so `list_empty_careful(&trig->next_trig)` sees it as unregistered) and detach all matching LEDs on `leds_list` via `led_trigger_set(led_cdev, NULL)` before `led_trigger_unregister_simple()` frees `trig`. [F10]
- Flash drivers using `v4l2_flash_init()` must register `struct led_classdev_flash` first, check `v4l2_flash_init()` with `IS_ERR()` (its `!CONFIG_V4L2_FLASH_LED_CLASS` stub returns `NULL`), and call `v4l2_flash_release()` before unregistering `led_classdev_flash`. [F99, F176]
- When iterating firmware child nodes with unscoped `fwnode_for_each_child_node()`, every early return/goto must call `fwnode_handle_put(child)`, and parent nodes from `fwnode_get_named_child_node()` must also be put. When storing child pointers from `_scoped` loops (`device_for_each_child_node_scoped`, `for_each_available_child_of_node_scoped`), pin each with `fwnode_handle_get()` / `of_node_get()` and release unconsumed references on error. [F131, F132]

## API Contracts

- `led_get()`, `devm_led_get()`, and `devm_of_led_get()` return an `ERR_PTR()` on failure and never `NULL`, whereas `devm_of_led_get_optional()` translates `ERR_PTR(-ENOENT)` into `NULL` while preserving other `ERR_PTR()` values. `__devm_led_get()` consumes the `led` reference passed to it, calling `led_put(led)` immediately if `devres_alloc()` fails or via `devm_led_release()` on detach. [F2, F35]
- `led_set_brightness_nopm()` calls `led_cdev->brightness_set` synchronously whenever non-NULL (including from timer softirq and hardirq/RCU trigger contexts), so sleeping drivers must leave `brightness_set` NULL and implement `brightness_set_blocking`. `led_blink_set_nosleep()` only defers `blink_set` to `set_brightness_work` when both `blink_set` and `brightness_set_blocking` are non-NULL, so `blink_set` must not sleep unless `brightness_set_blocking` is also set. [F146, F147]
- In `led_blink_setup()`, `led_set_software_blink()`, and driver `blink_set` callbacks, `!*delay_on && !*delay_off` (which selects default timings and updates both pointers) must be checked before individual `!*delay_on` or `!*delay_off` checks; `blink_set` must return 0 when hardware blink is activated or non-zero for software fallback, and hardware blink must stop when brightness is set to `LED_OFF`. [F105, F165]
- `led_get_default_pattern()` stores `fwnode_property_count_u32()` in a signed `int`, allocates with `kcalloc(count, sizeof(*pattern), GFP_KERNEL)`, passes element `count` (not byte size) to `fwnode_property_read_u32_array()`, frees `pattern` and returns `NULL` (leaving `*size` untouched) on error, and writes element `count` to `*size` on success (caller frees with `kfree()`). [F7, F40, F115]
- `led_trigger_register()` returns `-EEXIST` if a registered trigger has the same `name` and either shares `trigger_type` or either has `trigger_type == NULL`. `led_trigger_register_simple()` frees the trigger and stores `NULL` into `*tp` on failure, so `led_trigger_event()`, `led_mc_trigger_event()`, `led_trigger_blink_setup()`, and `led_trigger_unregister_simple()` must treat a `NULL` trigger pointer as a no-op. [F41, F178]
- `led_classdev_flash_register_ext()` validates and installs `fled_cdev->ops`, `ops->strobe_set`, `led_cdev->brightness_set_blocking` (all required non-NULL), `flash_resume`, and flash sysfs groups only when `LED_DEV_CAP_FLASH` is set, so post-registration code like `qcom_flash_v4l2_init()` must check `LED_DEV_CAP_FLASH` first. [F44, F160]
- `led_flash_setting` structs used with `led_set_flash_timeout/brightness/duration()` require non-zero `step` and `min <= max` for `led_clamp_align()`; flash `brightness` is in uA, `timeout`/`duration` in us, and `fault_get` outputs `LED_FAULT_*` bits matching `V4L2_FLASH_FAULT_*`. [F107, F163]
- `led_classdev_multicolor_register_ext()` requires `1 <= mcled_cdev->num_colors <= LED_COLOR_ID_MAX` and each `subled_info[i].color_index < LED_COLOR_ID_MAX`, sets `LED_MULTI_COLOR`, and overwrites `led_cdev.groups` with `led_multicolor_groups`. `led_compose_name()` requires a buffer >= `LED_MAX_NAME_SIZE` (64), requires `init_data->devicename` when `default_label` or `devname_mandatory` is set, and returns `-E2BIG` if the name reaches `LED_MAX_NAME_SIZE`. `led_classdev_notify_brightness_hw_changed()` requires `LED_BRIGHT_HW_CHANGED` in `led_cdev->flags`. [F166, F171, F175]

## Error Handling

- If `led_add_brightness_hw_changed()` fails in `led_classdev_register_ext()`, rollback must call `device_unregister(led_cdev->dev)` and reset `led_cdev->dev = NULL` before unlocking `led_access` so a later `led_classdev_unregister()` exits at `IS_ERR_OR_NULL(led_cdev->dev)`. [F4]
- In `led_trigger_set()`, error rollback paths (`err_add_groups`, `err_activate`) must unlink `led_cdev->trig_list` under `led_cdev->trigger->leddev_list_lock` and call `synchronize_rcu()` before setting `led_cdev->trigger = NULL`, and must `kfree(event)` before returning. [F8]
- In `led_get()`, fallback to `leds_lookup_list` happens only when `of_led_get()` returns `ERR_PTR(-ENOENT)`; any other error pointer (e.g. `-EPROBE_DEFER`, `-ENODEV`) must be returned immediately. [F36]
- `__led_set_brightness()` and `__led_set_brightness_blocking()` return `-ENOTSUPP` when their callback is NULL; `set_brightness_delayed_set_brightness()` relies on `-ENOTSUPP` to fall back from non-blocking to blocking and to suppress error logs when neither is set, and must also silently ignore `-ENODEV` when both `LED_UNREGISTERING` and `LED_HW_PLUGGABLE` are set. [F38, F173]

## External Contracts

- In `led_classdev_register_ext()`, name collisions are resolved by formatting `"%s_%u"` into `final_name` via `led_classdev_next_name()` for `device_create_with_groups()` without modifying `led_cdev->name`, unless `LED_REJECT_NAME_CONFLICT` is set in `led_cdev->flags` (which returns `-EEXIST`). Core `led_class_attrs` must not add generic attribute names like `color` that collide with driver `led_cdev->groups`. [F98, F169]
- Writing `0` (`LED_OFF`) to sysfs `brightness` (`brightness_store()`) must call `led_trigger_remove(led_cdev)` before `led_set_brightness()`. In `multi_intensity_store()`, all `mcled_cdev->num_colors` values must be parsed into a temporary array and rejected with `-EINVAL` if `offset + 1 < size` before mutating any `subled_info[i].intensity`. [F82, F180]

## Known Pitfalls

- On `struct led_classdev`, `flags` stores shifted `BIT()` masks (`LED_SUSPENDED`, `LED_UNREGISTERING`, etc.) manipulated with bitwise operators, whereas `work_flags` stores unshifted bit indices (`LED_BLINK_SW` = 0 .. `LED_SET_BLINK` = 8) manipulated with atomic bitops (`set_bit`, `clear_bit`, `test_bit`, `test_and_clear_bit`). [F55]
- When `init_data` is passed to `led_classdev_register_ext()` (or its devm/flash/multicolor wrappers), `led_cdev->name` is not populated by the core and may be NULL; use `proposed_name`, `final_name`, or `dev_name(led_cdev->dev)` instead. In `led_compose_name()`, `struct led_properties props` must be zero-initialized and populated by `led_parse_fwnode_props()` before inspection, and `props.color` / `props.func_enum` used only when `color_present` / `func_enum_present` are true. [F42, F53]
- `led_flash_init_sysfs_groups()` only exposes `flash_brightness`, `flash_timeout`, and `flash_fault` sysfs groups when `ops->flash_brightness_set`, `ops->timeout_set`, and `ops->fault_get` are non-NULL, and overwrites `led_cdev->groups` with `fled_cdev->sysfs_groups`. `led_mc_calc_color_components()` divides by `led_cdev.max_brightness`, so drivers calling it before `led_classdev_multicolor_register_ext()` defaults `max_brightness` to `LED_FULL` must initialize `max_brightness` to a non-zero value first. [F161, F167]
- In `led_trigger_snprintf()`, the `size` parameter must be signed `ssize_t` (not `size_t`) so negative `size - len` in `led_trigger_format(NULL, 0, led_cdev)` takes the `size <= 0` (`vsnprintf(NULL, 0, ...)`) branch instead of unsigned underflow in `vscnprintf()`. [F121]
