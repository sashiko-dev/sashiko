# KFENCE

Kernel Electric-Fence (KFENCE) is a low-overhead, sampling-based memory safety error detector for the Linux kernel heap (SLUB/SLAB). It allocates objects from a dedicated page pool surrounded by unmapped guard pages and in-page canary bytes, intercepting page faults and deallocations to detect and report out-of-bounds accesses, use-after-free accesses, memory corruption, and invalid frees.

## Architecture & Data Flow

- Every `struct kfence_metadata` entry must maintain `ALIGN_DOWN(meta->addr, PAGE_SIZE) == metadata_to_pageaddr(meta)`: `kfence_init_pool()` initializes `meta->addr` to the object page base while `KFENCE_OBJECT_UNUSED`, and `kfence_guarded_alloc()` must reset `meta->addr` via `metadata_to_pageaddr(meta)` before applying right-side offsets, or `metadata_to_pageaddr()` triggers `KFENCE_WARN_ON`. [F50]
- Object pages start mapped in `KFENCE_OBJECT_UNUSED` and are protected on transition to `KFENCE_OBJECT_FREED`. `kfence_guarded_alloc()` must unprotect `meta->addr` when reusing a `KFENCE_OBJECT_FREED` object before writing canaries or zeroing, and `kfence_guarded_free()` must unprotect `addr` before `check_canary()` under `CONFIG_KFENCE_STRESS_TEST_FAULTS`. [F51]
- In `kfence_guarded_free()`, if `meta->unprotected_page` is non-zero, the page at `ALIGN_DOWN(meta->unprotected_page, PAGE_SIZE)` must be zeroed with `memzero_explicit()`, re-protected via `kfence_protect()`, and `meta->unprotected_page` reset to 0 before returning the object to `kfence_freelist`. [F43]
- In `kfence_guarded_free()`, `alloc_covered_add(meta->alloc_stack_hash, -1)` runs for both normal and zombie frees, whereas returning `meta->list` to `kfence_freelist`, decrementing `counters[KFENCE_COUNTER_ALLOCATED]`, and incrementing `counters[KFENCE_COUNTER_FREES]` must only occur when `!zombie`. Unlinking `meta->list` in `kfence_guarded_alloc()` must use `list_del_init(&meta->list)` because `kfence_guarded_free()` checks `KFENCE_WARN_ON(!list_empty(&meta->list))`. [F53, F73]
- `kfence_allocation_gate` and `allocation_gate` in `__kfence_alloc()` must use signed `int` comparisons (`> 0` in `kfence_alloc()` and `toggle_allocation_gate()`, and `> 1` in `__kfence_alloc()`) because `toggle_allocation_gate()` sets `kfence_allocation_gate` to `-kfence_burst`. In `__kfence_alloc()`, `stack_trace_save()`, `get_alloc_stack_hash()`, and `alloc_covered_contains()` must run only after `atomic_inc_return(&kfence_allocation_gate)` confirms `allocation_gate <= 1`. [F71, F84]
- Because `KFENCE_CANARY_PATTERN_U64` encodes the 8-byte pattern starting at `(addr & 0x7) == 0` using `le64_to_cpu(0x0706050403020100)` to match `KFENCE_CANARY_PATTERN_U8(addr)` on big-endian machines, `set_canary()` and `check_canary()` must only access `*(u64 *)addr` at `sizeof(u64)`-aligned addresses and check unaligned boundary bytes with `check_canary_byte()`. [F62, F91]
- `get_stack_skipnr()` must clamp its return value to `< num_entries` (falling back to 0), only exit via `goto found` on initial slab entry points (`kfree`, `kmem_cache_free`, `__kmalloc`, `kmem_cache_alloc`) while advancing `fallback = skipnr + 1` on internal helpers (`kfence_`, `__kfence_`, `__kmem_cache_free`, `__slab_free`), and prepend `ARCH_FUNC_PREFIX` to every matched symbol prefix. `kfence_to_kp_stack()` must bound `j < KS_ADDRS_COUNT` and NULL-terminate `kp_stack[j]`. [F66, F79, F121]
- In `objects_sops`, `start_object()` and `next_object()` must return `(void *)((long)*pos + 1)` for `*pos < CONFIG_KFENCE_NUM_OBJECTS` and `show_object()` must index `&kfence_metadata[(long)v - 1]` because `seq_file` treats a NULL (0) cursor as end-of-iteration. [F65]

## Synchronization

- Once the pool is live, all removals and insertions of `meta->list` on `kfence_freelist` must be serialized by `kfence_freelist_lock` via `raw_spin_lock_irqsave()`, and `kfence_freelist_lock` must never be held while acquiring `meta->lock`. Because both are `raw_spinlock_t` locks taken with IRQs disabled, functions that may acquire non-raw `spinlock_t` locks (such as `get_random_u32_below()`) must run outside their critical sections. [F19, F101]
- Callers of `metadata_update_state()`, `kfence_print_object()`, and `kfence_report_error()` (for every `enum kfence_error_type` except `KFENCE_ERROR_INVALID`, where `meta` may be NULL) must hold `meta->lock` via `raw_spin_lock_irqsave()` or `raw_spin_trylock_irqsave()`. While `meta->lock` is held in `kfence_report_error()`, all console printing (`pr_err()`, `stack_trace_print()`, `kfence_print_object()`, `show_regs()`, `dump_stack_print_info()`) must be bracketed by `lockdep_off()` and `lockdep_on()`. [F20, F38, F106]
- In `kfence_guarded_free()`, checking `kfence_obj_allocated(meta) && meta->addr == (unsigned long)addr`, restoring protection on `meta->unprotected_page`, and calling `metadata_update_state(meta, KFENCE_OBJECT_FREED, NULL, 0)` must happen within a single `meta->lock` critical section. [F26]
- When freeing an object from a `SLAB_TYPESAFE_BY_RCU` cache, `__kfence_free()` must set `meta->state` to `KFENCE_OBJECT_RCU_FREEING` via `metadata_update_state()` under `meta->lock` before calling `call_rcu(&meta->rcu_head, rcu_guarded_free)`, and `metadata_update_state()` must preserve `meta->free_track` when transitioning out of `KFENCE_OBJECT_RCU_FREEING`. [F23]
- Stores to `meta->state` in `metadata_update_state()` and `meta->cache` in `kfence_guarded_alloc()` must use `WRITE_ONCE()` to pair with lockless `READ_ONCE()` checks in `kfence_obj_allocated()`, `kfence_shutdown_cache()`, and `kfence_handle_page_fault()`, and `kfence_shutdown_cache()` must revalidate both fields after acquiring `meta->lock`. [F24]
- Architecture implementations of `kfence_protect_page()` must not send cross-CPU IPIs for TLB shootdowns and must disable preemption around local-CPU TLB flushes (`flush_tlb_one_kernel()` / `local_flush_tlb_one()` on x86, LoongArch, and RISC-V), because `kfence_protect_page()` is called with interrupts disabled under `meta->lock` or during page faults. [F27]
- In `__kfence_alloc()`, waking `allocation_wait` when `kfence_allocation_gate` transitions to 1 must be deferred via `irq_work_queue(&wake_up_kfence_timer_work)` instead of calling `wake_up()` directly during slab allocation. `toggle_allocation_gate()` (`kfence_timer`) must be queued on `system_unbound_wq` and wait on `allocation_wait` with `wait_event_idle()`. [F99, F100]
- `kfence_debugfs_init()` must check `READ_ONCE(kfence_enabled)` before registering debugfs files, and `kfence_init_late()` must call `kfence_debugfs_init()` only after `kfence_init_pool()` and `kfence_init_enable()` succeed, preventing `show_object()` from dereferencing NULL `kfence_metadata` or locking uninitialized `meta->lock`. [F18]

## Object Lifetimes

- During `kfence_shutdown_cache(s)`, after converting still-allocated objects of `s` into zombie freed objects via `kfence_guarded_free(..., true)` (with `meta->lock` released beforehand), a second pass must set `meta->cache = NULL` under `meta->lock` for all `KFENCE_OBJECT_FREED` objects referencing `s`. Readers such as `__kfence_free()` and `kfence_print_object()` must NULL-check `meta->cache`. [F25, F37]
- Once `__kfence_pool` is initialized, disabling KFENCE at runtime must not free `__kfence_pool` or `kfence_metadata`, and re-enabling KFENCE in `kfence_enable_late()` when `__kfence_pool` is already non-NULL must skip `kfence_init_late()` and only set `kfence_enabled` and re-queue `kfence_timer`. [F14]
- When `kfence_init_pool()` succeeds in `kfence_init_pool_early()`, it must call `kmemleak_ignore_phys(__pa(__kfence_pool))` (and must not call it in `kfence_init_late()` where pages come from the page allocator) so the memblock-allocated pool does not overlap in kmemleak with individual KFENCE objects. [F7]
- In `kfence_guarded_free()`, the stack-allocated `struct kcsan_scoped_access assert_page_exclusive` registered with `kcsan_begin_scoped_access()` must be unregistered via `kcsan_end_scoped_access(&assert_page_exclusive)` before returning. [F98]

## API Contracts

- `addr_to_metadata()` must compute `index = (addr - (unsigned long)__kfence_pool) / (PAGE_SIZE * 2) - 1` in a signed type and return NULL when `index < 0 || index >= CONFIG_KFENCE_NUM_OBJECTS` (first two guard pages and trailing guard page), so callers (`kfence_handle_page_fault()`, `kfence_ksize()`, `kfence_object_start()`, `__kfence_obj_info()`) cannot assume `is_kfence_address(addr)` implies non-NULL metadata. [F35, F59]
- `__kfence_obj_info()` must return `false` when `addr_to_metadata((unsigned long)object)` is NULL so `kmem_obj_info()` falls back to `__kmem_obj_info()`, and when non-NULL must set `kpp->kp_ptr = object` and return `true` immediately on `WARN_ON(meta->state == KFENCE_OBJECT_UNUSED)` without copying uninitialized `meta->cache` or `meta->alloc_track`. [F119]
- `__kfence_alloc()` must reject allocations with `size > PAGE_SIZE`, `flags & GFP_ZONEMASK`, `(flags & __GFP_THISNODE) && num_online_nodes() > 1`, `s->flags & (SLAB_CACHE_DMA | SLAB_CACHE_DMA32)`, or `s->flags & SLAB_SKIP_KFENCE` before incrementing `kfence_allocation_gate`. [F110]
- `kfence_protect_page(addr, protect)` expects a page-aligned address (aligned via `ALIGN_DOWN(addr, PAGE_SIZE)` in `kfence_protect()` and `kfence_unprotect()`) and returns `true` on success; arch implementations calling `set_memory_valid()` or `__kernel_map_pages()` must invert the boolean as `!protect`. [F45]
- In `kfence_handle_page_fault()` and `kfence_report_error()`, `regs` may be NULL; when `regs` is NULL, `kfence_report_error()` must fall back to `stack_trace_save()` with `get_stack_skipnr()` and `dump_stack_print_info()` instead of `stack_trace_save_regs()` and `show_regs()`. [F39]

## Error Handling

- Metadata allocation and initialization must use `kfence_metadata_init` and only publish it to `kfence_metadata` via `smp_store_release()` after `kfence_init_pool()` succeeds, while `kfence_shutdown_cache()` must check `smp_load_acquire(&kfence_metadata)` for NULL before indexing `kfence_metadata`. [F32]
- On `kfence_init_pool()` failure (returning the non-zero `addr` where protection failed), `kfence_init_pool_early()` and `kfence_init_late()` must only free the unprotected tail `[addr, __kfence_pool + KFENCE_POOL_SIZE)`, free all of `kfence_metadata_init`, and set both `__kfence_pool` and `kfence_metadata_init` to NULL. In `kfence_alloc_pool_and_metadata()`, if `memblock_alloc()` for `kfence_metadata_init` fails, `__kfence_pool` must be freed via `memblock_free(__kfence_pool, KFENCE_POOL_SIZE)` and set to NULL. [F4, F6]
- In `kfence_guarded_alloc()`, if `raw_spin_trylock_irqsave(&meta->lock, flags)` fails after popping `meta` from `kfence_freelist`, it must re-acquire `kfence_freelist_lock` and re-insert `meta->list` onto `kfence_freelist` before returning NULL. [F9]
- Internal KFENCE invariant violations and page-protection failures must use `KFENCE_WARN_ON()`, which sets `kfence_enabled = false` and `disabled_by_warn = true` (causing `param_set_sample_interval()` to reject re-enabling with `-EINVAL`), whereas detected target memory bugs must call `kfence_report_error()` without disabling KFENCE. [F117]

## External Contracts

- Heap allocators must never place KFENCE objects onto regular slab freelists and must abort normal slab deallocation whenever `kfence_free()` returns `true` (`__must_check`). `__kfence_free()` requires `is_kfence_address(addr)` to refer to a valid KFENCE object page because it dereferences `addr_to_metadata((unsigned long)addr)` without a NULL check, whereas callers freeing arbitrary heap pointers must call `kfence_free()`. [F1, F36]
- `kfence_init_pool()` must set `__folio_set_slab(slab_folio(slab))` and, under `CONFIG_MEMCG`, `slab->obj_exts = (unsigned long)&kfence_metadata_init[i / 2 - 1].obj_exts | MEMCG_DATA_OBJEXTS` on every object page (and clear both in `reset_slab` on failure), while `kfence_guarded_alloc()` sets `slab->slab_cache = cache` and `slab->objects = 1`. `__kfence_free()` requires the slab free path to have already cleared `meta->obj_exts.objcg` via `memcg_slab_free_hook()` (`KFENCE_WARN_ON(meta->obj_exts.objcg)`). [F54, F112, F113]
- `kfence_guarded_alloc()` must perform `slab_want_init_on_alloc(gfp, cache)` zeroing of exact `size` bytes and invoke `cache->ctor(addr)` after `set_canary(meta)`, and `kfence_guarded_free()` must perform `slab_want_init_on_free(meta->cache)` zeroing of `meta->size` bytes after `check_canary(meta)` (when `!zombie`), instead of letting SLUB initialize `s->size`. [F115]
- `print_diff_canary()` and `kfence_report_error()` must gate printing raw corrupted byte values (`0x%02x`) and `show_regs(regs)` behind `no_hash_pointers`, and `print_diff_canary()` must clamp `end` to `meta->addr` (left canary) or `PAGE_ALIGN(address)` (right canary) to avoid leaking object data or reading into the next guard page. [F118]
- `probe_console()` must bound console tracepoint buffer searches to `len` with `strnstr()` and copy at most `min(len + 1, sizeof(observed.lines[0]))` bytes via `strscpy()`, and `kfence_report_error()` must preserve the `"BUG: KFENCE: "` and `"at 0x"`/`"of 0x"` prefixes matched by `probe_console()` and `report_matches()`. [F68]

## Known Pitfalls

- `is_kfence_address()` must cast `((char *)addr - __kfence_pool)` to `unsigned long` before comparing `< KFENCE_POOL_SIZE` so addresses below `__kfence_pool` wrap and fail, and must keep `&& __kfence_pool` on the right-hand side to reject addresses below `KFENCE_POOL_SIZE` when `__kfence_pool` is NULL without adding a load to the fast path. [F69, F82]
- `kfence_init_pool()` must read `__kfence_pool` into `addr` and `start_pfn` only after `arch_kfence_init_pool()` returns, and `arch_kfence_init_pool()` implementations that remap `__kfence_pool` (such as LoongArch) must restore the original `__kfence_pool` and free the `vm_struct` on failure. [F8]
- In `kfence_init_pool()`, the page-setup and `reset_slab` loops over `0 .. KFENCE_POOL_SIZE / PAGE_SIZE - 1` must resolve each page via `pfn_to_page(start_pfn + i)` (not pointer-indexing `struct page *`, which breaks under `CONFIG_SPARSEMEM && !CONFIG_SPARSEMEM_VMEMMAP`) and must skip both `i == 0` and odd `i` (`if (!i || (i % 2)) continue;`) because page 0 is an extended guard page and object pages start at index 2. [F74, F88]
- In `kfence_init_late()`, `alloc_contig_pages()` and `free_contig_range()` under `CONFIG_CONTIG_ALLOC` take page counts (`KFENCE_POOL_SIZE / PAGE_SIZE`, `KFENCE_METADATA_SIZE / PAGE_SIZE`, `free_size / PAGE_SIZE`, where `KFENCE_METADATA_SIZE` must remain `PAGE_ALIGN`-ed), whereas `alloc_pages_exact()` and `free_pages_exact()` under `!CONFIG_CONTIG_ALLOC` take byte sizes. [F85, F94]
- In the odd `page_index` (redzone) branch of `kfence_handle_page_fault()`, `meta` is overwritten when probing `addr - PAGE_SIZE` and `addr + PAGE_SIZE`, so subsequent locking, `unprotected_page` assignment, and `kfence_report_error()` must use `to_report` rather than `meta`. [F77]
- In `check_canary()`, when `check_canary_byte()` detects corruption on the left side (`addr < meta->addr`), the loop must `break` rather than `return` so that `check_canary()` still scans and reports corrupted canary bytes to the right of the object (`meta->addr + meta->size` to `pageaddr + PAGE_SIZE`). [F72]
- In `kfence_print_stack()`, all stack track fields (`ts_nsec`, `pid`, `cpu`, `num_stack_entries`, `stack_entries`) must be read through `track` (`show_alloc ? &meta->alloc_track : &meta->free_track`), and 64-bit nanosecond values `track->ts_nsec` and `interval_nsec` must be divided by `NSEC_PER_SEC` using `do_div()`. [F78, F81]
- In `get_alloc_stack_hash()` and `metadata_update_state()`, the decayed `unsigned long *stack_entries` entry count must be multiplied by `sizeof(stack_entries[0])` when passed to byte-sized APIs (`jhash()` and `memcpy()`), whereas `stack_trace_save()` and `filter_irq_stacks()` take entry counts directly. [F90]
- `metadata_update_state()` must remain `noinline` when calling `stack_trace_save(track->stack_entries, KFENCE_STACK_DEPTH, 1)`, and `test_free()` in `mm/kfence/kfence_test.c` must remain `__always_inline`, so recorded and expected stack traces match the caller frame. [F108]
