# CONTROL GROUP - DEVICE MEMORY CONTROLLER (DMEM)

The Device Memory Controller (`dmem`) is a cgroup subsystem that tracks and enforces hierarchical byte-granularity limits (`min`, `low`, `max`, and current usage) for driver-registered memory regions (`dmem_cgroup_region`). Drivers charge and uncharge allocations against the current task's cgroup pool (`dmem_cgroup_pool_state`) and query the controller during memory pressure to check whether evicting from a candidate pool respects effective protection watermarks.

## Architecture & Data Flow

- `dmem_cgroup_pool_state.cnt` stores unscaled byte counts in `struct page_counter` across `dmem_cgroup_try_charge`, `dmem_cgroup_uncharge`, `set_resource_min`, `set_resource_low`, `set_resource_max`, and `dmemcg_parse_limit`, even though `page_counter` APIs name their parameters `nr_pages`. Broken by: replacing `dmemcg_parse_limit` with `page_counter_memparse` or shifting/dividing values by `PAGE_SHIFT` or `PAGE_SIZE`. [F45]
- In `struct dmem_cgroup_pool_state`, `css_node` links the pool into `dmemcg_state.pools` whereas `region_node` links the pool into `dmem_cgroup_region.pools`; any `container_of` or `list_for_each_entry*` on `dmemcg_state.pools` must use `css_node` and any on `dmem_cgroup_region.pools` must use `region_node`. [F49]
- `dmem_cgroup_state_evict_valuable` must call `dmem_cgroup_calculate_protection(limit_pool, test_pool)`—which walks `css_for_each_descendant_pre` from `limit_pool` down to `test_pool` invoking `page_counter_calculate_protection`—before reading `test_pool->cnt.emin` or `test_pool->cnt.elow`. Broken by: reading `emin` or `elow` without calling `dmem_cgroup_calculate_protection`, or traversing ancestors in post-order instead of pre-order. [F26]
- In `dmem_cgroup_state_evict_valuable`, effective protection watermarks `ctest->emin` and `ctest->elow` are inclusive protected bounds: eviction from `test_pool` is disallowed when `used <= min` (or `used <= low` when `!ignore_low`) and allowed only when `used` is strictly greater than the active watermark. Broken by: changing `used <= min` to `used < min` or `used > low` to `used >= low`. [F34]
- In `get_cg_pool_locked()`, the first upward pass (`for (p = dmemcs; p; p = parent_dmemcs(p))`) must return `pool` directly only when `p == dmemcs && pool->inited`, and must `break` to the second pass when `pool->inited` holds on an ancestor (`p != dmemcs`). [F40]
- Per-cgroup limit files (`min`, `low`, `max` in `files[]`) must carry `CFTYPE_NOT_ON_ROOT` and `dmemcs_offline` must reset all pool limits via `reset_all_resource_limits`, because root pools have no parent limit enforcement and offline cgroups must not retain `min`/`low` protection while residual charges drain. [F62]
- The `files[]` `struct cftype` array passed as `legacy_cftypes` and `dfl_cftypes` in `dmem_cgrp_subsys` must end with a zero-initialized sentinel element `{ }`. [F35]

## Synchronization

- Because `get_cg_pool_locked` may drop `dmemcg_lock` on `-ENOMEM` after `alloc_pool_single` links a child `dmem_cgroup_pool_state` into `dmemcs->pools` before its ancestor `cnt.parent` chain is wired, lockless readers in `get_cg_pool_unlocked` must check `READ_ONCE(pool->inited)` and fall back to `get_cg_pool_locked` when false. [F10]
- After acquiring or reacquiring `dmemcg_lock` in `get_cg_pool_unlocked`, `region->unregistered` must be checked before calling `get_cg_pool_locked` so a holder of a `region->ref` kref cannot attach new pools after `dmem_cgroup_unregister_region` has unlinked `region->pools`. Broken by: checking `region->unregistered` outside `dmemcg_lock` or not rechecking it after dropping and reacquiring `dmemcg_lock` in the `allocpool` retry loop. [F11]
- `dmemcg_state.pools` (`pool->css_node`) must be modified under `dmemcg_lock` using RCU list primitives (`list_add_tail_rcu` in `alloc_pool_single`, `list_del_rcu` in `dmem_cgroup_unregister_region`) while the CSS is live and traversed under `rcu_read_lock()` or `dmemcg_lock`; `dmem_cgroup_region.pools` (`pool->region_node`) is protected solely by `dmemcg_lock` and drained locklessly in `dmemcg_free_rcu()` only after `dmem_cgroup_unregister_region()` unlinks every `pool->css_node` and sets `region->unregistered = true` under `dmemcg_lock`. [F7, F56]
- `dmem_cgroup_calculate_protection()` must hold `rcu_read_lock()` across the entire `css_for_each_descendant_pre()` traversal and the inner `list_for_each_entry_rcu()` scan of `dmemcg_iter->pools` through the `page_counter_calculate_protection()` call. [F57]
- `dmemcg_get_region_by_name()` must be called under `rcu_read_lock()` (or `dmemcg_lock`) and must obtain a non-zero reference via `kref_get_unless_zero(&region->ref)` before returning `region`, paired with `call_rcu(&cgregion->rcu, dmemcg_free_rcu)` when the last `kref` is dropped in `dmemcg_free_region()`. [F55]
- In `dmem_cgroup_register_region`, `ret->pools`, `ret->name`, `ret->size`, and `ret->ref` must be initialized before acquiring `dmemcg_lock` and publishing `ret->region_node` to `dmem_cgroup_regions` via `list_add_tail_rcu`. [F9]
- Because `alloc_pool_single()` is invoked via `get_cg_pool_locked()` while `dmemcg_lock` is held, it must use `GFP_NOWAIT` when `*allocpool` is `NULL` and rely on `get_cg_pool_unlocked()` to drop `dmemcg_lock` before allocating `allocpool` with `GFP_KERNEL` upon `-ENOMEM`. [F51]
- `dmemcg_lock` is acquired with non-IRQ-saving `spin_lock()`/`spin_unlock()`, so no function that acquires `dmemcg_lock` (`dmemcs_free()`, `dmem_cgroup_unregister_region()`, `dmem_cgroup_register_region()`, `get_cg_pool_unlocked()`, `dmem_cgroup_try_charge()`) may be invoked from hardirq or softirq context. [F53]

## Object Lifetimes

- `dmem_cgroup_try_charge` acquires a CSS reference via `get_current_dmemcs()` and, on success, transfers both that CSS reference and the `page_counter` byte charge to `*ret_pool`, which the caller must release by calling `dmem_cgroup_uncharge` with the same `pool` and `size` (never `dmem_cgroup_pool_state_put`). [F1]
- When `dmem_cgroup_try_charge` fails with `-EAGAIN` and `ret_limit_pool` is non-NULL, it must take `css_get(&(*ret_limit_pool)->cs->css)` before calling `css_put(&cg->css)` at `err:` (since `cg->css` pins the ancestor hierarchy containing `fail`), and the caller must release `*ret_limit_pool` via `dmem_cgroup_pool_state_put`. [F2, F13]
- When `alloc_pool_single` consumes a pre-allocated pool from `*allocpool`, it must immediately set `*allocpool = NULL` because `get_cg_pool_locked` may invoke `alloc_pool_single` for multiple ancestors in one pass and `get_cg_pool_unlocked` unconditionally calls `kfree(allocpool)` before returning. [F3]
- Each `dmem_cgroup_pool_state` is linked into both `dmemcs->pools` (`css_node`) and `region->pools` (`region_node`): `dmemcs_free` must unlink both nodes under `dmemcg_lock` before `free_cg_pool`, while `dmem_cgroup_unregister_region` must unlink `region->region_node` and each `pool->css_node` with `list_del_rcu` and set `region->unregistered = true` under `dmemcg_lock` before `kref_put(&region->ref, dmemcg_free_region)` schedules `call_rcu(&cgregion->rcu, dmemcg_free_rcu)` to call `free_cg_pool`. [F5, F12]

## API Contracts

- The `!CONFIG_CGROUP_DMEM` stubs in `include/linux/cgroup_dmem.h` and implementations in `kernel/cgroup/dmem.c` must stay synchronized: `dmem_cgroup_try_charge` zeroes `*ret_pool` (and `*ret_limit_pool` if non-NULL) on entry, sets `*ret_pool` only when returning `0` with `CONFIG_CGROUP_DMEM` enabled, and sets `*ret_limit_pool` only when returning `-EAGAIN`; `dmem_cgroup_uncharge`, `dmem_cgroup_pool_state_put`, and `dmem_cgroup_unregister_region` accept `NULL`. [F16, F30]
- `dmem_cgroup_register_region` returns `NULL` when `size` is `0` or `CONFIG_CGROUP_DMEM` is disabled, a valid pointer on success, and an `ERR_PTR` on allocation failure; callers must check `IS_ERR` (and not pass an `ERR_PTR` to `dmem_cgroup_unregister_region`) and must not call `dmem_cgroup_try_charge` with a `NULL` `region` when `CONFIG_CGROUP_DMEM` is enabled because `get_cg_pool_unlocked` unconditionally dereferences `region->unregistered`. [F15, F17]
- `dmem_cgroup_state_evict_valuable()` must check `if (limit_pool == test_pool) return true;` before testing `if (limit_pool)` or dereferencing `test_pool`, both to allow a cgroup pool to evict from itself regardless of `min`/`low` watermarks and to handle `limit_pool == NULL && test_pool == NULL`. [F37]
- In `dmem_cgroup_state_evict_valuable()`, `if (used <= min) return false;` must be evaluated before `if (!ignore_low)`, and `*ret_hit_low` is only ever set to `true` (when `used > min`, `!ignore_low`, and `used <= low`) and never cleared to `false` (including in the `!CONFIG_CGROUP_DMEM` stub), so callers must pass a non-NULL `ret_hit_low` initialized to `false` before each pass. [F18, F39]
- Callers of `dmem_cgroup_uncharge` must pass the exact byte `size` that was charged to `@pool` by `dmem_cgroup_try_charge`. Broken by: rounding, aligning, or recalculating the allocation size differently between `dmem_cgroup_try_charge` and `dmem_cgroup_uncharge`. [F47]
- Every getter callback `fn` passed to `dmemcg_limit_show` (`get_resource_low`, `get_resource_min`, `get_resource_max`, `get_resource_current`) must accept a `NULL` `struct dmem_cgroup_pool_state *` argument and return the default unconfigured value, because `find_cg_pool_locked` returns `NULL` when the cgroup has not allocated a pool for a region. [F48]
- `dmem_cgroup_try_charge()`, `dmem_cgroup_register_region()`, `get_cg_pool_unlocked()`, and `dmemcg_limit_write()` may perform `GFP_KERNEL` allocations and therefore must only be called from sleepable process context. [F52]

## Error Handling

- In `dmemcg_limit_write`, once `dmemcg_get_region_by_name` returns a non-NULL `region`, any subsequent failure from `dmemcg_parse_limit` or `get_cg_pool_unlocked` (`IS_ERR(pool)`) must set negative `err` and jump to `out_put` so `kref_put(&region->ref, dmemcg_free_region)` runs and `err ?: nbytes` returns `err`. [F22]

## External Contracts

- Region names formatted by `dmem_cgroup_register_region` must not contain whitespace (`' '`, `'\t'`, or `'\n'`), because `dmem_cgroup_region_capacity_show` and `dmemcg_limit_show` emit `<region->name> <value>\n` lines and `dmemcg_limit_write` splits each newline-terminated line at the first space or tab via `strsep(&options, " \t")`. [F31]
- `dmemcg_parse_limit` must require `memparse(options, &end)` to consume the entire limit token (`*end == '\0'`) unless `options` is `"max"`, which maps to `PAGE_COUNTER_MAX` (the same sentinel rendered as `" max\n"` by `dmemcg_limit_show`, used by `reset_all_resource_limits`, and returned as the default by `get_resource_max`). [F32]

## Known Pitfalls

- In `dmem_cgroup_calculate_protection()`, `found_pool` must be reset to `NULL` on each `css_for_each_descendant_pre()` iteration and assigned only when `pool->region == limit_pool->region`, rather than using the `list_for_each_entry_rcu()` cursor `pool` after the inner loop terminates. [F36]
- When `limit_pool` is `NULL` in `dmem_cgroup_state_evict_valuable()`, the ancestor walk `for (limit_pool = test_pool; pool_parent(limit_pool); limit_pool = pool_parent(limit_pool))` must stop while `pool_parent(limit_pool)` is non-NULL so `limit_pool` remains pointing to the root pool rather than advancing to `NULL`. [F38]
- In `dmemcg_limit_write()`, `buf` must be advanced past the current line (`buf = strchr(buf, '\n'); if (buf) *buf++ = '\0';`) at the start of the `while (buf && !err)` loop before any `continue` branches on empty `options` or `region_name`. [F44]
