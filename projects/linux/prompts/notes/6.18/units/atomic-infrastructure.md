# ATOMIC INFRASTRUCTURE

This component provides the Linux kernel's core atomic integer operations (`atomic_t` and `atomic64_t`) and saturating reference counters (`refcount_t`) across both C (`include/linux/atomic.h`, `include/linux/refcount.h`, `include/asm-generic/atomic*.h`, `arch/*/include/asm/atomic*.h`) and Rust (`kernel::sync::atomic::Atomic<T>`, `kernel::sync::refcount::Refcount`).

## Architecture & Data Flow

- `Atomic<T>`, `AtomicRepr<T>`, and `Refcount` must remain `#[repr(transparent)]` wrappers around `UnsafeCell<T::Repr>` and `Opaque<bindings::refcount_t>`, because `AtomicBasicOps`, `AtomicExchangeOps`, `AtomicArithmeticOps`, and `Refcount::as_atomic` cast raw pointers directly to C `atomic_t`, `atomic64_t`, and `refcount_t`. [F74]
- In `rust/kernel/sync/atomic.rs`, `unsafe impl AtomicType for T` requires `size_of::<T>() == size_of::<T::Repr>()`, `align_of::<T>() == align_of::<T::Repr>()`, and all bits initialized (no padding or `MaybeUninit`); because bit validity is only one-way from `T` to `T::Repr`, every mutation of `Atomic<T>` (`self.0`), call to `from_repr`, and `unsafe impl AtomicAdd<Rhs> for T` (where two's-complement `wrapping_add` with `T::rhs_into_delta(rhs)` on any valid `T::Repr` must yield a valid `T`) must preserve valid `T` bit patterns. [F31, F71, F72, F77]
- In `include/linux/refcount.h`, `__refcount_add_not_zero`, `__refcount_add_not_zero_limited_acquire`, `__refcount_add`, and `__refcount_sub_and_test` must carry `__signed_wrap` and test `old < 0 || old + i < 0` (or `old <= 0 || old - i < 0`), and any inline refcount operation detecting overflow, addition on zero (`!old` in `__refcount_add`), underflow, or leak (`old <= 1` in `__refcount_dec`) must call `refcount_warn_saturate()` to clamp `r->refs` to `REFCOUNT_SATURATED`. [F44, F68]
- In `__refcount_add_not_zero_limited_acquire` (`include/linux/refcount.h`), the upper-bound check before `atomic_try_cmpxchg_acquire` must be written as `i > limit - old` (not `old + i > limit`) so positive `old` and `i` cannot overflow signed `int` when `limit` is `INT_MAX`. [F54]
- On 32-bit x86 (`arch/x86/include/asm/atomic64_32.h`) and ARCv2 (`arch/arc/include/asm/atomic64-arcv2.h`), `atomic64_t` must declare `s64 counter` with `__aligned(8)` because 32-bit ABIs only guarantee 4-byte alignment for `s64` while hardware 64-bit atomics require 8-byte alignment. [F50]
- In `arch/x86/include/asm/atomic64_32.h`, `__alternative_atomic64` and `alternative_atomic64` patch calls between `atomic64_<f>_386` and `atomic64_<g>_cx8` in a single `asm volatile` block, so both assembly routines must obey identical custom register conventions for inputs, outputs, and clobbers. [F45]
- In `arch/arm64/include/asm/atomic.h`, every atomic operation dispatched via `__lse_ll_sc_body(op, ...)` must have both a `__lse_<op>` in `atomic_lse.h` and a matching `__ll_sc_<op>` in `atomic_ll_sc.h` with identical parameter and return types. [F82]
- In `arch/arm/include/asm/atomic.h`, 64-bit inline assembly operations that propagate carry or test sign bits (`ATOMIC64_OP`, `arch_atomic64_dec_if_positive`, `arch_atomic64_fetch_add_unless`) must use `%Q` for the low word and `%R` for the high word, whereas `ldrexd` and `strexd` use `%0` and `%H0`. [F48]

## Synchronization

- `refcount_dec_and_mutex_lock`, `refcount_dec_and_lock`, and `refcount_dec_and_lock_irqsave` acquire `lock` (and save IRQ flags into `*flags` for `_irqsave`) if and only if they return `true` after decrementing `r` to 0; when they return `false`, `lock` is not held. [F1]
- `refcount_add_not_zero()`, `refcount_inc_not_zero()`, `refcount_add()`, `refcount_inc()`, and `Refcount::inc()` are relaxed and provide no memory ordering. For objects in memory subject to type-safe reuse (`SLAB_TYPESAFE_BY_RCU`), initialization must call `refcount_set_release()` only after all object fields are initialized, and RCU readers must use `refcount_inc_not_zero_acquire()` or `refcount_add_not_zero_acquire()` before revalidating object identity. [F11, F12, F93, F94]
- In `__refcount_sub_and_test()`, `atomic_fetch_sub_release()` must be paired with `smp_acquire__after_ctrl_dep()` when the counter reaches zero (`old > 0 && old == i`) so prior accesses are ordered before the decrement and object deallocation is ordered after it. [F13]
- C `arch_atomic_try_cmpxchg()` and `arch_atomic64_try_cmpxchg()` implementations must only write the observed value to `*old` when the compare-and-exchange fails, and never overwrite `*old` on success when the memory backing `old` may have been concurrently published. [F20]
- On architectures that serialize atomic RMWs with spinlocks and IRQ disabling (ARC `!CONFIG_ARC_HAS_LLSC` and PA-RISC), `arch_atomic_set()` and `arch_atomic64_set()` must acquire the same lock (`atomic_ops_lock` or `_atomic_spin_lock_irqsave`) rather than performing an unlocked write. In `arch/parisc/include/asm/atomic.h` on `CONFIG_SMP`, `_atomic_spin_lock_irqsave` must call `local_irq_save(f)` before `arch_spin_lock(ATOMIC_HASH(l))`, and `_atomic_spin_unlock_irqrestore` must release `arch_spin_unlock(s)` before `local_irq_restore(f)`. [F10, F14]
- On architectures where normal stores do not clear hardware lock reservations or lack single-copy 64-bit atomicity, atomic accesses must use exclusive loops instead of plain loads/stores: Hexagon `arch_atomic_set()` must use a `memw_locked` loop, and non-LPAE ARM (`!CONFIG_GENERIC_ATOMIC64 && !CONFIG_ARM_LPAE`) must use `ldrexd` in `arch_atomic64_read()` and an `ldrexd`/`strexd` loop in `arch_atomic64_set()` rather than `ldrd`/`strd`. [F16, F104, F105]
- In `arch/mips/include/asm/atomic.h`, `ATOMIC_OP`, `ATOMIC_OP_RETURN`, `ATOMIC_FETCH_OP`, and `ATOMIC_SIP_OP` must gate the `raw_local_irq_save`/`raw_local_irq_restore` fallback versus the `ll`/`sc` assembly loop solely on `if (!kernel_uses_llsc)` without conjoining `R10000_LLSC_WAR`. [F55, F84]
- In MIPS `ATOMIC_SIP_OP` (`arch_atomic_sub_if_positive` and `arch_atomic64_sub_if_positive`), `__SYNC(full, loongson3_war)` must be placed both immediately before the LL/SC loop and at the label `2:` target of the `bltz` exit branch so speculative or reordered accesses cannot break LL/SC cache coherence. [F18]
- On Alpha (`arch/alpha/include/asm/atomic.h`), value-returning `_relaxed` RMW primitives (`ATOMIC_OP_RETURN`, `ATOMIC_FETCH_OP`, `ATOMIC64_OP_RETURN`, `ATOMIC64_FETCH_OP`) must unconditionally emit `smp_mb()` after the LL/SC loop to preserve LKMM dependency ordering while `__atomic_acquire_fence()` and `__atomic_post_full_fence()` are defined empty. [F22]

## Object Lifetimes

- After `Refcount::dec_and_test` returns `false`, the caller must not dereference or use the `&Refcount` reference (or the enclosing object if its lifetime is tied to the `Refcount`), because another thread may concurrently drop the last reference and free the backing memory. [F7]

## API Contracts

- In `arch/*/include/asm/atomic*.h`, any C function implementing an optional `arch_atomic_*` or `arch_atomic64_*` primitive (other than `read`, `set`, `add`, `sub`, `and`, `or`, `xor`) must also `#define arch_atomic_<op> arch_atomic_<op>` so `include/linux/atomic/atomic-arch-fallback.h` does not silently substitute the generic fallback. [F107]
- Every internal `__refcount_*` helper in `include/linux/refcount.h` taking `int *oldp` (`__refcount_add_not_zero`, `__refcount_add_not_zero_limited_acquire`, `__refcount_add`, `__refcount_sub_and_test`, `__refcount_dec`) must guard `*oldp = old` with `if (oldp)` on all return paths; when `i > limit - old` or `old == 0`, `__refcount_add_not_zero_limited_acquire` must leave `r->refs` unchanged, write `old` to `*oldp` if non-NULL, and return `false`. [F3, F28]
- `refcount_set`, `refcount_set_release`, and `Refcount::set` must not be passed a negative `int`/`i32` value because negative values represent the saturated (`bad value`) range. [F32]
- `arch_atomic_dec_if_positive` and `arch_atomic64_dec_if_positive` must return the signed value `old - 1` (`int` or `s64`/`long`) even when `*v` was non-positive and not decremented, so `0` indicates a `1 -> 0` transition while `< 0` indicates failure. [F24]
- Architecture implementations of `arch_atomic64_inc_not_zero` (such as in `arch/powerpc/include/asm/atomic.h`) must normalize the 64-bit old counter value to a boolean `int` (`t1 != 0`) rather than returning the 64-bit value cast to `int`, which truncates to `0` when the low 32 bits of a non-zero counter are zero. [F23]
- In `rust/kernel/sync/atomic/internal.rs`, `AtomicBasicOps::set` and `AtomicExchangeOps::xchg` pass `(a.as_ptr().cast(), v)` (pointer first, value second) to `bindings::#call`, whereas `AtomicArithmeticOps` (`add`, `fetch_add`) must pass `(v, a.as_ptr().cast())` (delta first, pointer second). [F33]
- In `rust/kernel/sync/atomic.rs`, `Atomic::try_cmpxchg` must write the updated `tmp` representation back to `*old` (`*old = unsafe { from_repr(tmp) }`) before returning, because `Atomic::cmpxchg` passes `&mut old` and returns `Err(old)` on failure. [F36]
- In `arch/x86/include/asm/atomic64_32.h`, every out-of-line `atomic64_*_cx8` or `atomic64_*_386` helper invoked via `alternative_atomic64` or `__alternative_atomic64` must be declared with `ATOMIC64_DECL` or `ATOMIC64_DECL_ONE` before `#undef ATOMIC64_EXPORT` so `arch/x86/lib/atomic64_32.c` exports it with `EXPORT_SYMBOL`. [F109]

## Error Handling

- `__refcount_sub_and_test` (and thus `refcount_sub_and_test` and `refcount_dec_and_test`) returns `true` only when `old > 0 && old == i`; on underflow or already-saturated values (`old <= 0 || old - i < 0`), it calls `refcount_warn_saturate(r, REFCOUNT_SUB_UAF)` and returns `false`. [F5]
- `refcount_dec`, `__refcount_dec`, and `Refcount::dec` treat a `1 -> 0` transition (`old <= 1`) as a memory-leak bug and call `refcount_warn_saturate(r, REFCOUNT_DEC_LEAK)`, so dropping a potentially final reference must use `refcount_dec_and_test` or `Refcount::dec_and_test`. [F110]
- `__refcount_add`, `refcount_add`, `refcount_inc`, and `Refcount::inc` require a live reference and call `refcount_warn_saturate(r, REFCOUNT_ADD_UAF)` if `!old` (which must be checked before `old < 0 || old + i < 0` in `__refcount_add` so `old == 0` with `old + i < 0` reports `REFCOUNT_ADD_UAF`, not `REFCOUNT_ADD_OVF`), whereas `refcount_inc_not_zero` and `refcount_add_not_zero` treat `old == 0` as a normal race and return `false` without warning. [F57, F111]
- `__refcount_add_not_zero` and `__refcount_add_not_zero_limited_acquire` return `old != 0` even after saturating via `refcount_warn_saturate(r, REFCOUNT_ADD_NOT_ZERO_OVF)` on `old < 0 || old + i < 0`, whereas exceeding `limit` (`i > limit - old`) in `__refcount_add_not_zero_limited_acquire` returns `false` without saturating. [F27]

## Known Pitfalls

- In `arch/arm64/include/asm/atomic_ll_sc.h`, `__ll_sc__cmpxchg_case_##name##sz` takes `unsigned long old` and compares it with 32-bit `eor %w[tmp], %w[oldval], %w[old]`, so for sub-word sizes (`sz < 32`) it must explicitly cast `old = (u##sz)old` before the inline assembly. [F30]
- In `arch/arm64/include/asm/atomic_lse.h`, every inline assembly block emitting ARMv8.1 LSE instructions must begin with `__LSE_PREAMBLE`, and because LSE implements `andnot` via `stclr`/`ldclr`, `__lse_atomic_and`, `__lse_atomic_fetch_and*`, `__lse_atomic64_and`, and `__lse_atomic64_fetch_and*` must pass the inverted mask `~i` to the `andnot` helper. [F34, F81]
- In `arch/arm64/include/asm/atomic_lse.h` and `atomic_ll_sc.h`, `__CMPXCHG128` must type its `"+Q"` memory operand as `*(u128 *)ptr` so the compiler hazards all 16 bytes, and in `__lse_atomic64_dec_if_positive()`, `[ret] "+&r" (v)` and `[tmp] "=&r" (tmp)` must remain earlyclobber (`&`) across the `1:` retry loop so they do not alias the base register of `[v] "+Q" (v->counter)`. [F66, F99]
- In `arch/arm/include/asm/atomic.h`, `arch_atomic_cmpxchg_relaxed()` and `arch_atomic64_cmpxchg_relaxed()` must reset `res` (`mov %0, #0`) inside each `do { ... } while (res)` iteration before `teq` and `strexeq`/`strexdeq`, because `strexeq` does not write `res` when `oldval != old`. [F61]
- In `arch/x86/include/asm/atomic64_32.h`, `arch_atomic64_read_nonatomic()` may tear and must only seed unconditional `arch_atomic64_try_cmpxchg()` loops (never loops that can exit before `try_cmpxchg` validates the value), and the `CONFIG_X86_CX8` definition of `__alternative_atomic64()` must wrap its output operand list with `ALT_OUTPUT_SP(out)` around its inline `call`. [F37, F96]
- In `arch/powerpc/include/asm/atomic.h`, `arch_atomic_fetch_add_unless()` and `arch_atomic64_fetch_add_unless()` add `a` in-place to `t` before `stwcx.`/`stdcx.`, so on the store-success path before label `2:` they must subtract `a` back (`sub%I2c`/`subf`) to return the original value. [F39]
- In `arch/powerpc/include/asm/atomic.h`, `arch_atomic_read`, `arch_atomic_set`, `arch_atomic64_read`, and `arch_atomic64_set` must use `"b"(&v->counter)` when `IS_ENABLED(CONFIG_PPC_KERNEL_PREFIXED)` is true; when false, `arch_atomic64_read` and `arch_atomic64_set` emit DS-form `ld`/`std` and must constrain `v->counter` with `DS_FORM_CONSTRAINT` rather than `"m<>"`. [F90, F97]
- In `arch/riscv/include/asm/atomic.h` and `arch/loongarch/include/asm/atomic.h`, `ATOMIC_OPS` for `sub` passes `I = -i` to hardware atomic add (`amoadd`/`amadd`), so `c_op` in `ATOMIC_OP_RETURN` must be `+` (`result + (-i)`), not `-`. [F35]
- In `arch/s390/include/asm/atomic.h`, `arch_atomic64_sub`, `arch_atomic64_sub_return`, and `arch_atomic64_fetch_sub` must cast `_i` to `(s64)` before unary negation (`-(s64)(_i)`), and in `arch/s390/include/asm/atomic_ops.h`, 64-bit and z196 inline assembly memory operands must use combined `"RT"` or `"+QS"` constraints rather than standalone `"T"` or `"+S"`. [F70, F101]
- In `arch/mips/include/asm/atomic.h`, `ATOMIC_FETCH_OP` and `ATOMIC_SIP_OP` must exit `.set MIPS_ISA_LEVEL` with `.set pop` before any `move` pseudo-instruction so 32-bit builds do not emit 64-bit `daddu`. [F102]
- In `arch/arc/include/asm/atomic-llsc.h` and `atomic64-arcv2.h`, inline assembly modifying `v->counter` via `"r"(&v->counter)` without a memory output constraint or surrounding `smp_mb()` must clobber `"memory"`, and in `arch/parisc/include/asm/atomic.h`, `ATOMIC_HASH(a)` must cast `a` to `unsigned long` before dividing by `L1_CACHE_BYTES` and masking with `ATOMIC_HASH_SIZE - 1`. [F75, F98]
- In `arch/m68k/include/asm/atomic.h`, direct-to-memory assembly (`ATOMIC_OP`, `arch_atomic_sub_and_test`, `arch_atomic_add_negative`) must constrain the integer operand with `ASM_DI` rather than `"di"` for ColdFire compatibility, and in `arch/xtensa/include/asm/atomic.h`, the `!XCHAL_HAVE_EXCLUSIVE && !XCHAL_HAVE_S32C1I` `rsil`/`wsr` sequence in `ATOMIC_OP`, `ATOMIC_OP_RETURN`, and `ATOMIC_FETCH_OP` must use fixed register `a14` (and clobber `"a14"`). [F86, F103]

## Other

- In `arch/alpha/include/asm/atomic.h`, every LL/SC store-conditional failure branch (`beq`) must branch forward to a retry stub in `.subsection 2` that jumps back (`br 1b`) to the `ldl_l`/`ldq_l` label rather than branching backward directly in the main path. [F62]
