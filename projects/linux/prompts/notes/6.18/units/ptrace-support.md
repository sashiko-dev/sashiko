# PTRACE SUPPORT

Implements architecture-specific `ptrace` support across CPU architectures (`alpha`, `arc`, `arm`, `arm64`, `csky`, `hexagon`, `loongarch`, `m68k`, `microblaze`, `mips`, `nios2`, `openrisc`, `parisc`, `powerpc`, `riscv`, `s390`, and `sh`). It defines saved exception register frames (`struct pt_regs`), `user_regset` / `user_regset_view` accessors, `arch_ptrace` and `compat_arch_ptrace` handlers, syscall entry/exit tracing hooks, single/block-step control, and kernel stack/register query helpers.

## Architecture & Data Flow

- On arm64, ZA and ZT0 share `target->thread.sme_state` (`thread_zt_state()` at `ZA_SIG_REGS_SIZE(sme_vq)`), so `sme_alloc()` in `za_set()` and `zt_set()` must flush only when `!thread_za_enabled(&target->thread)`, and `sve_set_common()` must pass `flush = false`. When `system_supports_sme()` is true in `sve_set_common()`, `TIF_SVE` and clearing `SVCR_SM_MASK` must only occur for `ARM64_VEC_SVE`, while `ARM64_VEC_SME` must set `SVCR_SM_MASK` and `TIF_SME` without setting `TIF_SVE`. [F54, F136]
- In `sve_init_header_from_task()` (arm64), `SVE_PT_REGS_SVE` vs `SVE_PT_REGS_FPSIMD` in `header->flags` must be determined from `target->thread.fp_type == FP_STATE_SVE` (when the requested vector type is active), not `TIF_SVE`. Because `SVE_PT_REGS_FPSIMD` is `0`, `header->size` must be set to `sizeof(header)` when the requested `enum vec_type` is inactive, and `sve_get_common()` must return `0` after writing the header when `header.size == sizeof(header)`. [F52, F96]
- In `report_syscall()` on arm64 and arm, the tracee register overwritten with `PTRACE_SYSCALL_ENTER` / `PTRACE_SYSCALL_EXIT` (`x7` on AArch64, `r12`/`ARM_ip` on AArch32/ARM) must be saved beforehand and restored across the stop (and before `ptrace_report_syscall_exit(regs, 1)` when stepping on arm64). On arm64, `syscall_trace_enter()` must only return `NO_SYSCALL` early after `report_syscall()` when `_TIF_SYSCALL_EMU` is set, and otherwise proceed to seccomp, tracepoints, and audit even if `regs->syscallno == NO_SYSCALL`. [F9, F98]
- On s390, FPRs and low vector registers share `target->thread.ufpu.vxrs[0..15]`: `s390_fpregs_set()` must unpack `vxrs` via `convert_vx_to_fp()` before `user_regset_copyin()` and pack back via `convert_fp_to_vx()` on success, and `s390_vxrs_low_set()` must stage and write only `vxrs[i].low`. In `__poke_user()` and `__poke_user_compat()`, writing `regs.gprs[2]` while `test_pt_regs_flag(regs, PIF_SYSCALL)` is true must update `regs->int_code` to `0x20000 | (data & 0xffff)`, and writes to `regs.psw.mask` must be validated with `((data ^ PSW_USER_BITS) & ~mask)` (and the 31-bit equivalent), rejecting `PSW_ASC_HOME` or `PSW_MASK_EA` without `PSW_MASK_BA`. [F64, F65, F103]
- On MIPS (`ptrace_setregs`, `gpr32_set`, `gpr64_set`, and `PTRACE_POKEUSR`), modifying GPR `$2` (or GPR `$4` when `mips_syscall_is_indirect(child, regs)` is true) must call `mips_syscall_update_nr(child, regs)`, and `ptrace_setfcr31()` must preserve hardware-masked bits in `boot_cpu_data.fpu_msk31`. On LoongArch (`fpr_set`, `simd_set`) and MIPS (`ptrace_setfpregs`, `fpr_set`, `msa_set`, and `PTRACE_POKEUSR` on `FPR_BASE`/`FPC_CSR`), `init_fp_ctx(target)` must be called before writing FP/SIMD state. [F62, F63, F145]
- In `ptrace_hbp_get_event()` and `ptrace_hbp_set_event()` on arm64 and LoongArch, slot index `idx` must be bounds-checked against `ARM_MAX_BRP`/`LOONGARCH_MAX_BRP` or `ARM_MAX_WRP`/`LOONGARCH_MAX_WRP` and clamped with `array_index_nospec()`. In `ptrace_hbp_fill_attr_ctrl()` (arm64) and `ptrace_sethbpregs()` (arm), decoded permission bits must be validated with `(type & allowed_mask) != type` to reject any bit outside `HW_BREAKPOINT_X` or `HW_BREAKPOINT_RW` with `-EINVAL`. [F78, F102]
- On PowerPC (`arch/powerpc/include/asm/ptrace.h`), `TRAP(regs)` must mask out `TRAP_FLAGS_MASK` and `set_trap(regs, val)` must preserve `regs->trap & TRAP_FLAGS_MASK`. On LoongArch and MIPS, where `struct pt_regs` ends with zero-length marker `__last`, `MAX_REG_OFFSET` must be `offsetof(struct pt_regs, __last) - sizeof(unsigned long)` because `regs_get_register()` uses the inclusive check `offset > MAX_REG_OFFSET`. [F72, F101]

## Synchronization

- In `user_regset` callbacks across arm64, s390, and riscv, helpers that save/restore live CPU registers (`fpsimd_preserve_current_state()`, `tls_preserve_current_state()`, `gcs_preserve_current_state()`, `save_access_regs()`, `save_user_fpu_regs()`, `riscv_v_vstate_save()`) must only be called when `target == current`. On arm64, getters reading CPU-cached state (`fpr_get`, `fpmr_get`, `sve_get_common`, `za_get`, `compat_vfp_get`, `tls_get`, `gcs_get`) must call `*_preserve_current_state()` when `target == current`, and FP/FPMR/SVE/SME setters must call `fpsimd_flush_task_state(target)`. [F19, F20, F110]
- On arm64, `__fpr_get()` and `__fpr_set()` must call `fpsimd_sync_from_effective_state(target)` before reading or copying into `target->thread.uw.fpsimd_state`, and `fpr_set()` must call `fpsimd_sync_to_effective_state_zeropad(target)` after `__fpr_set()`. On ARM, `vfp_get()` and `vfp_set()` must call `vfp_sync_hwstate(thread)` before reading `thread->vfpstate.hard`, and `vfp_set()` must call `vfp_flush_hwstate(thread)` after writing it. [F21, F22]
- On RISC-V, when `target == current`, `riscv_vr_get()` must bracket `riscv_v_vstate_save()` with `get_cpu_vector_context()` and `put_cpu_vector_context()` before copying `target->thread.vstate`. On LoongArch, `fpr_get()` and `simd_get()` must call `save_fpu_regs(target)` before reading `target->thread.fpu.fpr`. On s390, `s390_gs_cb_set()` must perform `kzalloc(..., GFP_KERNEL)` and `user_regset_copyin()` before `preempt_disable()`, keeping preemption disabled while updating `target->thread.gs_cb` and calling `restore_gs_cb()`. [F16, F18, F24]
- In `arch/arm/kernel/ptrace.c`, `arch/arm64/kernel/ptrace.c`, and `arch/loongarch/kernel/ptrace.c`, `ptrace_hbp_create()` must initialize `attr.disabled = 1` before calling `register_user_hw_breakpoint()`, because breakpoint address and control fields are configured in separate steps via `modify_user_hw_breakpoint()`. On PowerPC, modifying `regs->nip` or `regs->msr` via `regs_set_return_ip()`, `regs_set_return_msr()`, or `instruction_pointer_set()` must call `set_return_regs_changed()` to clear `local_paca->hsrr_valid` and `srr_valid`. [F13, F25]

## Object Lifetimes

- In `flush_ptrace_hw_breakpoint()`, each non-NULL `perf_event` pointer in `tsk->thread.debug` (`hbp_break[]`, `hbp_watch[]`, or `hbp[]`) must be set to `NULL` immediately after `unregister_hw_breakpoint()`. When updating a slot (`ptrace_hbp_get_initialised_bp`, `ptrace_sethbpregs`, `set_single_step`), an existing `perf_event` must be reused via `modify_user_hw_breakpoint()` rather than calling `register_user_hw_breakpoint()` again. When cloning a task on ARM/ARM64, the child's breakpoint slots must be zeroed via `clear_ptrace_hw_breakpoint()` or `ptrace_hw_copy_thread()` without calling `flush_ptrace_hw_breakpoint()`. [F1, F3, F14]

## API Contracts

- In `struct user_regset` `.set` callbacks, sequential `user_regset_copyin()` and `user_regset_copyin_ignore()` calls must use monotonically non-decreasing `start_pos` offsets (or reset `pos = 0` before restarting from 0 as in `riscv_vr_set()`), and any padding or read-only gap between writable segments must be consumed with `user_regset_copyin_ignore()`. In slot-iterating `.set` callbacks (`compat_gpr_set`, `gpr32_set`, `gpr64_set`, `dsp32_set`, `dsp64_set`, and parisc's `fpr_set`/`gpr_set`/`gpr32_set`), byte `pos` and `count` must be divided by slot byte size before checking bounds or indexing. [F107, F125, F167]
- On arm64: any `user_regset` `.set` handler passing a `target->thread` field directly to `user_regset_copyin()` requires that field to lie within `thread.uw` (fields like `por_el0` or `tpidr2_el0` outside `thread.uw` must be staged in a stack local); in `sve_set_common()` and `za_set()`, `header.flags` must be widened to `unsigned long` and shifted left by 16 when passed to `vec_set_vector_length()`, returning `-EIO` without copying register data if `count > 0` and the resulting task VL differs from `header.vl`; and in `sve_set_common()`, writes to `ARM64_VEC_SME` must reject `SVE_PT_REGS_FPSIMD` in `header.flags` with `-EINVAL` before configuring VL or allocating state. [F40, F73, F116, F168]
- In `regs_get_register()` and `regs_get_kernel_stack_nth()`, out-of-bounds register offsets (`offset > MAX_REG_OFFSET` or `>= NUM_GPRS` on s390) and stack addresses failing `regs_within_kernel_stack(regs, addr)` must return `0` without faulting. On arm64 and s390, `regs_get_kernel_stack_nth()` must read via `READ_ONCE_NOCHECK(*(unsigned long *)addr)` to avoid KASAN false positives; on arm64, `regs_within_kernel_stack()` must also accept `on_irq_stack(addr, sizeof(unsigned long))`; and on parisc, `regs_get_kernel_stack_nth(regs, n)` must subtract word index `n` (`addr -= n`) because the stack grows upward. [F45, F122, F149, F150, F186]
- On arm64, `pt_regs_read_reg(regs, r)` and `pt_regs_write_reg(regs, r, val)` take register index `r` (`r == 31` is `XZR`), whereas `regs_get_register(regs, offset)` takes an 8-byte-aligned byte offset into `struct pt_regs`. On s390, `regs_query_register_offset()`, `regs_query_register_name()`, and `regs_get_register()` use a GPR index in `0..NUM_GPRS-1`, unlike arm, arm64, arc, csky, loongarch, mips, openrisc, parisc, powerpc, riscv, and sh where `offset` is a byte offset into `struct pt_regs`. [F43, F44]
- For `regs_return_value(regs)`: on PowerPC, `is_syscall_success()` and `regs_return_value()` must branch on `trap_is_scv(regs)` (`scv` returns negative `-errno` in `regs->gpr[3]`, whereas non-`scv` sets `0x10000000` in `regs->ccr` and stores positive errno in `regs->gpr[3]` to be negated); on MIPS, `regs_return_value(regs)` must check `is_syscall_success(regs) || !user_mode(regs)` and negate `regs->regs[2]` only when a user-mode syscall failed (`regs->regs[7] != 0`); and on arm64, `regs_return_value(regs)` must call `sign_extend64(val, 31)` when `compat_user_mode(regs)` is true. [F30, F31, F32]

## Error Handling

- On arm64, `sve_alloc()` and `sme_alloc()` allocate `target->thread.sve_state` and `sme_state` in-place without returning a status code, so `sve_set_common()`, `za_set()`, and `zt_set()` must verify both pointers are non-NULL (`-ENOMEM`). In `za_set()` and `zt_set()`, both allocations and `user_regset_copyin()` must succeed before setting `TIF_SME` and `SVCR_ZA_MASK`; in `sve_set_common()`, `vec_set_vector_length()`, `sme_alloc()`, and `sve_alloc()` must succeed before modifying `target->thread.svcr` or setting `TIF_SVE`/`TIF_SME`, and `target->thread.fp_type` must be updated before any subsequent error return. [F5, F38, F53]
- On arm64, `za_get()` and `zt_get()` must check `thread_za_enabled(&target->thread)` before reading `sme_state` or `thread_zt_state()`, and `sve_get_common()` must only read `sve_state` when `header.flags & SVE_PT_REGS_MASK` is `SVE_PT_REGS_SVE` and `header.size > sizeof(header)`. `sve_init_header_from_task()` and `za_get()` must `memset()` their headers to zero before populating fields, and `sve_get_common()` and `za_get()` must zero gaps and trailing padding up to `ALIGN(header.size, SVE_VQ_BYTES)` via `membuf_zero()`. [F39, F41]
- On s390, `s390_gs_cb_get()`, `s390_gs_bc_get()`, and `s390_runtime_instr_get()` must check that `target->thread.gs_cb`, `gs_bc_cb`, or `ri_cb` is non-NULL (`-ENODATA`), and `s390_tdb_get()` must check `regs->int_code & 0x200` before reading `trap_tdb`. In `s390_gs_cb_set()` and `s390_runtime_instr_set()`, a newly `kzalloc`'d control block in local `data` must be freed with `kfree(data)` and not assigned to `target->thread` if `user_regset_copyin()` or `is_ri_cb_valid()` fails (and `s390_runtime_instr_set()` must overwrite `ri_cb.key = PAGE_DEFAULT_KEY >> 4`). Across arm, arm64, loongarch, and sh, `register_user_hw_breakpoint()` / `ptrace_hbp_create()` return values must be checked with `IS_ERR(bp)` before storing into the task's breakpoint array. [F7, F35, F37, F95]

## External Contracts

- In `user_regset` `.set` callbacks that stage data in a local struct (`__fpr_set`, `gpr_set`, `tls_set` on arm64; `vfp_set` on arm; `s390_vxrs_low_set`, `s390_gs_cb_set`, `s390_runtime_instr_set` on s390), the local struct must be pre-populated with synchronized target state before `user_regset_copyin()` so partial writes do not clobber uncopied fields (and on arm64/arm, GPR writes must be validated with `valid_user_regs()` before committing to `task_pt_regs(target)`). On RISC-V, `riscv_vr_get()` and `riscv_vr_set()` must exchange `struct __riscv_v_regset_state` followed by `riscv_v_vsize` bytes at `vstate->datap` (never `struct __riscv_v_ext_state` with its kernel pointer), rejecting `ptrace_vstate.vlenb != vstate->vlenb` with `-EINVAL`. [F58, F75, F175]
- On MIPS: `NT_PRFPREG` handlers `fpr_get()` and `fpr_set()` must treat the 64-bit slot after the 32 64-bit FPRs as two 32-bit registers (`fcr31` followed by read-only `boot_cpu_data.fpu_id`), ignoring writes to `fpu_id` via `user_regset_copyin_ignore()` in `fpr_set()`; `fpr_set()` (on MIPS and LoongArch) must reject `pos + count > sizeof(elf_fpregset_t)` with `-EIO` before `init_fp_ctx(target)`; and `gpr32_set()`/`dsp32_set()` must cast `u32` elements to `s32` to sign-extend on 64-bit kernels. [F76, F77, F112]
- On LoongArch (`simd_get`) and MIPS (`msa_get`), when the target task has not used math or only a narrower FP/SIMD context is live, `copy_pad_fprs()` must pad unused upper bytes of each vector register with `0xff` (`~0ull`). On arm64 and LoongArch, `hw_break_get()` must zero 32-bit padding fields via `membuf_zero(&to, sizeof(u32))`, and `hw_break_set()` must skip the header and per-slot padding via `user_regset_copyin_ignore()`. On LoongArch (`ptrace_hbp_set_addr`) and MIPS (`ptrace_set_watch_regs`), watchpoint/breakpoint addresses in kernel space (`>= XKPRANGE` or `__UA_LIMIT`) must be rejected with `-EINVAL`. [F92, F170, F184]

## Known Pitfalls

- In MIPS `PTRACE_PEEKUSR` and `PTRACE_POKEUSR` for `FPR_BASE ... FPR_BASE + 31`, handlers must test `TIF_32BIT_FPREGS` on `child` via `test_tsk_thread_flag(child, TIF_32BIT_FPREGS)` (not on `current`): when set, odd FP addresses access the high 32 bits of the even FP slot via `get_fpr32()`/`set_fpr32(&fregs[(addr & ~1) - FPR_BASE], addr & 1, ...)`; when clear, accesses must use `get_fpr64(..., 0)` and `set_fpr64(..., 0, data)`. In `fpr_set_msa()` (MIPS) and `gfpr_set_simd()` (LoongArch), the loop must continue while `i < NUM_FPU_REGS && *count > 0` so `*pos` and `*count` advance across all FPR slots. [F87, F99, F100, F113]
- On s390, the ascending offset chains in `__peek_user()`, `__poke_user()`, `__peek_user_compat()`, and `__poke_user_compat()` must check `addr == offsetof(..., regs.orig_gpr2)` before `addr < offsetof(..., regs.fp_regs)`, and `addr == offsetof(..., regs.fp_regs.fpc)` before `addr < offsetof(..., regs.fp_regs) + sizeof(s390_fp_regs)`. When indexing `child->thread.ufpu.vxrs` by byte address for `regs.fp_regs.fprs`, `__peek_user()` and `__poke_user()` must multiply the byte offset by 2 because each 64-bit FPR lives in the upper half of a 128-bit `__vector128` slot. In `.regset_get` callbacks across architectures, `membuf_write()` must be passed pointee size `sizeof(*regs)` rather than pointer size `sizeof(regs)`. [F104, F121, F129]
