# MEN CHAMELEON BUS (mcb)

The MEN Chameleon Bus (MCB) subsystem (`drivers/mcb/`) implements a bus driver and device model for discovering and managing IP cores (cells) inside MEN Mikroelektronik FPGAs. It parses the on-FPGA Chameleon v2 configuration table from MMIO space (`mcb-parse.c`) to instantiate `mcb_device` objects, provides core bus/device/driver registration and resource helpers (`mcb-core.c`), and supplies carrier glue drivers for PCI (`mcb-pci.c`) and LPC/DMI (`mcb-lpc.c`) attachments.

## Architecture & Data Flow
- In `mcb_pci_probe()`, `priv->bus->get_irq = mcb_pci_get_irq` must be set before calling `chameleon_parse_cells()`, because `chameleon_parse_cells()` calls `mcb_device_register()` (`device_add()`), which can synchronously probe an already-registered `mcb_driver` that calls `mcb_get_irq()`. [F63]
- `mcb_alloc_bus()` and `mcb_device_register()` must keep `bus->dev.parent` and `dev->dev.parent` pointing to the carrier `struct device` (which must remain bound to its `struct device_driver` while child `mcb_device` instances are probed or removed), because `mcb_probe()` and `mcb_remove()` unconditionally dereference `mdev->dev.parent->driver->owner`. Broken by: setting `dev->dev.parent = &bus->dev`, passing a driverless carrier device, or unbinding the carrier before `mcb_release_bus()`. [F33, F73]
- Before `mcb_device_register()` calls `device_add(&dev->dev)`, the caller must populate `dev->id`, `dev->inst`, `dev->group`, `dev->var`, `dev->irq`, and `dev->mem`, and `mcb_device_register()` must call `mcb_bus_get(bus)` and set `dev->dev.release = mcb_release_dev` and `dev->dma_dev = bus->carrier` (which MCB client drivers must pass instead of `&mdev->dev` to DMA-API functions). [F12, F68]
- In `mcb_pci_probe()` and `mcb_lpc_probe()`, shrinking the carrier MMIO reservation and remapping `priv->base` when `table_size < CHAM_HEADER_SIZE` must happen in lockstep in both drivers after `chameleon_parse_cells()` and before `mcb_bus_add_devices()`, releasing `priv->base` and calling `devm_release_mem_region()` on `CHAM_HEADER_SIZE` before re-requesting `table_size`. [F34, F38]
- MCB memory `struct resource` definitions (`sc24_fpga_resource`, `sc31_fpga_resource`) and descriptor assignments (`chameleon_parse_gdd()`, or any future `chameleon_parse_bdd()`) must add `cb[mdev->bar].addr` to the descriptor `offset` for `mdev->mem.start` and use inclusive `.end` bounds (`start + size - 1` or `DEFINE_RES_MEM(start, size)`), because `resource_size()` computes `end - start + 1`. [F39, F51]
- When a `CHAMELEON_DTYPE_BAR` descriptor is present, `chameleon_get_bar()` must reject `bar_count <= 0 || bar_count > CHAMELEON_BAR_MAX` with `-ENODEV` before allocating the `chameleon_bar` array and advancing `*base` by `BAR_DESC_SIZE(bar_count)` (`bar_count * sizeof(struct chameleon_bar) + sizeof(__le32)`). [F40]
- Descriptor parsers (`chameleon_parse_gdd()`, and any future `chameleon_parse_bdd()`) must validate that the 3-bit 0-based `GDD_BAR` / `bar` index (`0..7`) does not exceed `bar_count - 1` (`bar_count` is `1..6`) before indexing the `cb` (`struct chameleon_bar`) array. [F41]
- In `chameleon_get_bar()` (which takes `void __iomem **base` as an in-out cursor and advances `*base` by `BAR_DESC_SIZE(bar_count)` only when the descriptor is `CHAMELEON_DTYPE_BAR`) and the `for_each_chameleon_cell()` loop in `chameleon_parse_cells()`, the MMIO cursor `p` must advance by the exact byte size of each parsed descriptor so `table_size = p - base` equals the total table size. Broken by: advancing `p` again after `chameleon_get_bar(&p, ...)`, passing a copy of `p`, or adding a descriptor case that does not advance `p`. [F31, F36]
- `struct chameleon_fpga_header` is copied from MMIO with `memcpy_fromio()` without endian conversion, so multi-byte header fields must be converted with `le16_to_cpu()`, and `chameleon_parse_cells()` must verify `le16_to_cpu(header->magic) == CHAMELEONV2_MAGIC` (`0xabce`) before calling `chameleon_get_bar()` or `for_each_chameleon_cell()`; descriptor words read via `readl()` are already CPU-endian and must not be passed to `le32_to_cpu()`. [F43, F65]
- Because `chameleon_fpga_header.filename` is a `CHAMELEON_FILENAME_LEN`-byte field without a NUL terminator, `chameleon_parse_cells()` must bound copies from `header->filename` to `CHAMELEON_FILENAME_LEN` bytes and NUL-terminate `bus->name` (`CHAMELEON_FILENAME_LEN + 1` bytes) before `name_show()` formats `bus->name` with `%s`. [F53]
- The sysfs attributes in `mcb_carrier_groups` (`revision_show`, `model_show`, `minor_show`, `name_show`) unconditionally cast `dev` via `to_mcb_bus(dev)`, so they must only be attached to `mcb_carrier_device_type.groups` on `bus->dev` and never to `mcb_bus_type.dev_groups` or an `mcb_device`. [F76]

## Synchronization
- `mcb_alloc_bus()`, `mcb_alloc_dev()`, `chameleon_parse_cells()`, `mcb_device_register()`, `mcb_bus_add_devices()`, and `mcb_release_bus()` perform `GFP_KERNEL` allocations or call sleeping driver-core APIs (`device_add()`, `device_attach()`, `device_unregister()`) and must only be called in sleepable process context. [F70]

## Object Lifetimes
- `chameleon_parse_cells()` and `chameleon_parse_gdd()` must not store any virtual pointers derived from `void __iomem *base` into `struct mcb_bus` or `struct mcb_device`, because `mcb_pci_probe()` and `mcb_lpc_probe()` unmap `priv->base` via `devm_iounmap()` whenever `table_size < CHAM_HEADER_SIZE`. [F35]
- In `mcb_alloc_bus()`, failures before `get_device(carrier)` and `device_initialize(&bus->dev)` must free `bus` with `kfree(bus)` without calling `put_device(carrier)`, whereas failures after `device_initialize(&bus->dev)` must call `put_device(&bus->dev)` so `mcb_free_bus()` drops the carrier reference and `mcb_ida` ID. [F57]
- An `mcb_device` from `mcb_alloc_dev()` must be freed with `mcb_free_dev()` if discarded before `mcb_device_register()`; once `mcb_device_register()` calls `device_initialize(&dev->dev)` and `mcb_bus_get(bus)`, it must release `dev` via `put_device(&dev->dev)` (`mcb_release_dev()`) on `device_add()` failure without the caller freeing `mdev` again. [F58]
- `mcb_probe()` must acquire both `try_module_get(mdev->dev.parent->driver->owner)` and `get_device(dev)` before invoking `mdrv->probe()`, and release both if `mdrv->probe()` fails and in `mcb_remove()` after `mdrv->remove()`. [F61]
- `mcb_pci_probe()` enables the PCI device with non-devres `pci_enable_device(pdev)`, so every error path after `pci_enable_device()` succeeds and `mcb_pci_remove()` must call `pci_disable_device(pdev)` after `mcb_release_bus(priv->bus)`. [F8]
- `mcb_init()` must remain registered with `fs_initcall()` so `bus_register(&mcb_bus_type)` runs after PCI initialization (`subsys_initcall`) and before built-in MCB carrier and client drivers register at `device_initcall` time. [F17]

## API Contracts
- `mcb_get_resource()` returns a borrowed pointer to `&dev->mem` or `&dev->irq` embedded in `struct mcb_device` (or `NULL` on failure), whereas `mcb_request_mem()` allocates a `struct resource` via `request_mem_region()` that must be paired with `mcb_release_mem()`, returns `ERR_PTR(-EBUSY)` on failure (never `NULL`), and dereferences `dev->dev.driver->name` when its `name` argument is `NULL`. Broken by: passing `mcb_get_resource()`'s result to `mcb_release_mem()`, or calling `mcb_request_mem(dev, NULL)` on an unbound `mcb_device`. [F9, F78]
- `mcb_alloc_bus()` and `mcb_request_mem()` return `ERR_PTR()` on failure and never `NULL` (check with `IS_ERR()`), whereas `mcb_alloc_dev()` and `mcb_get_resource()` return `NULL` on failure and never `ERR_PTR()` (check for `NULL`). [F18, F19]
- `__mcb_bus_add_devices()` and `__mcb_devices_unregister()` must return `0` on non-error paths—specifically translating a positive `1` return from `device_attach()` to `0` in `__mcb_bus_add_devices()`—so `bus_for_each_dev()` does not short-circuit before visiting all devices on `mcb_bus_type`. [F49]
- `mcb_get_irq()` dispatches to `bus->get_irq(dev)` only when `bus->get_irq` is non-NULL (as set on PCI carriers) and otherwise falls back to `__mcb_get_irq(dev)` (`dev->irq.start`). Broken by: calling `dev->bus->get_irq(dev)` directly, which crashes on LPC carriers where `bus->get_irq` is `NULL`. [F24]
- `__mcb_register_driver()` rejects any `struct mcb_driver` whose `.probe` or `.remove` is `NULL` with `-EINVAL`, and `mcb_remove()` calls `mdrv->remove(mdev)` without a null check, whereas `mdrv->shutdown` is optional and guarded in `mcb_shutdown()`. [F23]
- `chameleon_parse_cells()` requires `base` to be an `ioremap`-ed virtual `__iomem` pointer for reading the table and `mapbase` to be the physical base address used by `chameleon_get_bar()` and `chameleon_parse_gdd()` to populate `mdev->mem.start`. [F69]
- `mcb_match_id()` scans `mdrv->id_table` with `while (ids->device)`, so every `struct mcb_device_id` array must end with a `{ .device = 0 }` sentinel entry. [F45]

## Error Handling
- `chameleon_parse_cells()` does not unregister `mcb_device` instances already registered via `mcb_device_register()` if a later cell fails or `num_cells == 0`, and it returns a positive byte `table_size` on success or a negative errno on failure; therefore, in `mcb_pci_probe()` and `mcb_lpc_probe()`, any error path after `mcb_alloc_bus()` must call `mcb_release_bus(priv->bus)` (`out_mcb_bus`), and any failure after `ret = chameleon_parse_cells(...)` succeeds must overwrite `ret` with a negative errno before jumping to `out_mcb_bus`. [F6, F20]
- `chameleon_get_bar()` returns a negative errno without allocating `*cb` on failure and a positive `bar_count` with a heap-allocated `*cb` on success, so `chameleon_parse_cells()` must jump to `free_header` when `bar_count < 0` and to `free_bar` on all subsequent errors. [F26]
- Because MCB does not support I/O-mapped BARs, `mcb_pci_probe()` must check `pci_resource_flags(pdev, 0) & IORESOURCE_IO` and fail with `-ENOTSUPP` before calling `devm_request_mem_region()`, and `chameleon_parse_gdd()` must skip any cell whose BAR index exceeds `bar_count - 1`, whose `cb[mdev->bar].addr` is zero, or whose BAR address has bit 0 set (`dev_mapbase & 0x01`) by jumping to `err:` (`mcb_free_dev(mdev)`) and returning `0`, reserving negative returns for fatal errors that abort `chameleon_parse_cells()`. [F27, F64]

## External Contracts
- `mcb_uevent()` must format the uevent modalias as `MODALIAS=mcb:16z%03d` using the 3-digit zero-padded decimal `mdev->id`, and `mcb_alloc_bus()` / `mcb_device_register()` must name bus and cell devices `mcb:%d` and `mcb%d-16z%03d-%d:%d:%d` respectively. [F46]
- All functions exported by `mcb-core.c` and `mcb-parse.c` use `EXPORT_SYMBOL_NS_GPL(..., "MCB")`, so any new exported MCB symbol must use the `"MCB"` GPL namespace and any module calling MCB APIs must declare `MODULE_IMPORT_NS("MCB")` and a GPL-compatible `MODULE_LICENSE`. [F74]

## Known Pitfalls
- Because both `mcb_alloc_bus()` and `mcb_device_register()` set `dev.bus = &mcb_bus_type`, `bus_for_each_dev()` callbacks on `mcb_bus_type` (`__mcb_bus_add_devices()` and `__mcb_devices_unregister()`) visit both `struct mcb_bus` and `struct mcb_device` nodes and must check `dev->type == &mcb_carrier_device_type` before downcasting `dev` with `to_mcb_device()` or `to_mcb_bus()`. [F52]
- `struct mcb_device.driver` is never populated when binding a device to a driver; `mcb_probe()`, `mcb_remove()`, `mcb_shutdown()`, and client drivers must retrieve the bound `struct mcb_driver` via `to_mcb_driver(dev->driver)` (or `mdev->dev.driver`) rather than `mdev->driver`. [F32]
