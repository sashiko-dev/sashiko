# BCACHE (BLOCK LAYER CACHE)

`drivers/md/bcache` implements the Linux block-layer cache, enabling fast SSDs to act as writethrough, writeback, or writearound caches for backing block devices as well as providing thin-provisioned flash-only volumes.

## Architecture & Data Flow

- `struct btree` nodes are allocated with `kzalloc()` in `mca_bucket_alloc()` (which `bch_btree_keys_init()` relies on for zeroed `b->keys.set[]`) and recycled across `c->btree_cache_freeable` and `c->btree_cache_freed`: `mca_bucket_free()` must zero `b->key.ptr[0]` and unlink `b->hash` (`hlist_del_init_rcu()`), `bch_btree_keys_free()` must reset `t->prev`, `t->tree`, and `t->data` to `NULL`, `mca_data_alloc()`/`mca_data_free()` must maintain `c->btree_cache_used`, and `mca_alloc()` must reset `b->flags`, `b->written`, and `b->keys` (`nsets = 0`, `last_set_unwritten = 0`) [F12, F62, F76, F77].
- `c->root` must be unlinked from `c->btree_cache` via `list_del_init(&b->list)` whenever installed (`run_cache_set()`, `bch_btree_set_root()`) and re-added in `cache_set_flush()` before `bch_btree_cache_free()`, while shrinker callbacks `bch_mca_scan()` and `bch_mca_count()` must bound reclaim by `mca_can_free(c)` to leave `mca_reserve(c)` nodes [F13, F18].
- In `struct btree_keys`, `b->nsets` is the 0-based index of the last active `bset_tree` in `b->set[MAX_BSETS]` (loops must use `i <= b->nsets`, and `bch_bset_init_next()` requires `b->nsets + 1 < MAX_BSETS`); written `bset_tree`s (`bset_written(b, t)` with `t->size >= 2`) use 1-based `t->tree` and `t->prev` arrays in `[1, t->size)`, whereas unwritten trees use a 0-based `t->prev` table in `[0, t->size)` updated by `bch_bset_fix_lookup_table()` in `bch_bset_insert()` [F71, F96, F97].
- In `bch_extent_insert_fixup()`, `old_offset = KEY_START(k)` and `old_size = KEY_SIZE(k)` must be sampled before `k` is cut so `bch_subtract_dirty()` subtracts the exact overwritten dirty sectors; zero-size extents (`!KEY_SIZE(k)`) must not trigger early `break` on `bkey_cmp(&START_KEY(k), insert) >= 0`; cutting `k` in place via `bch_cut_back()`/`__bch_cut_back()` requires `bch_bset_fix_invalidated_key(b, k)`; and splitting a written key must insert the top half into the unwritten bset and cut `k` in place for the bottom half [F67, F68, F70, F119].
- In `bch_btree_insert_node()` and `bch_btree_insert_keys()`, available space must be checked via `insert_u64s_remaining(b)` (reserving `KEY_MAX_U64S` u64s on extent leaf nodes for splitting, clamped to `>= 0L`) rather than `bch_btree_keys_u64s_remaining(&b->keys)`; in `bch_btree_insert()`, `op.op.lock` must be reset to `0` on each `while` iteration; and in `bch_btree_map_nodes_recurse()` and `bch_btree_map_keys_recurse()`, `from` must be set to `NULL` after the first child recursion [F104, F121, F123].
- In `__ptr_invalid()`, every pointer must have `PTR_BUCKET_NR(c, k, i)` in `[ca->sb.first_bucket, ca->sb.nbuckets)` and `KEY_SIZE(k) + bucket_remainder(c, PTR_OFFSET(k, i)) <= c->cache->sb.bucket_size`; all bucket scans (`for_each_bucket`, `invalidate_buckets_*`) must stay within `[ca->sb.first_bucket, ca->sb.nbuckets)`; 8-bit bucket generations (`b->gen`, `b->last_gc`, `PTR_GEN(k, i)`) must be compared via `gen_after(a, b)` and `can_inc_bucket_gen()` (`bucket_gc_gen(b) < BUCKET_GC_GEN_MAX`); and journal bucket indices must wrap modulo `ca->sb.njournal_buckets` [F91, F99, F100, F146].
- `c->devices[i]` (or `s->d` in `cache_lookup()`) can be a standalone `struct bcache_device` (`flash_dev_run()`) or embedded in `struct cached_dev`, so code must check `d && !UUID_FLASH_ONLY(&c->uuids[i])` before `container_of(d, struct cached_dev, disk)`; scans of `c->uuids` for unattached or flash-only entries must bound loops by `c->nr_uuids` rather than `c->devices_max_used` [F50, F98].
- Every non-bypass `op->bio` passed to `bch_data_insert()` (and `cache_lookup_fn()`) must be embedded in `struct bbio` or allocated with `front_pad = offsetof(struct bbio, bio)` because `bio_next_split()` returns the input bio unsplit on the final segment; similarly, `struct bio bio` must remain the final field of `struct dirty_io` with `DIV_ROUND_UP(KEY_SIZE(&w->key), PAGE_SECTORS)` trailing `bio_vec`s allocated in `read_dirty()` [F187, F336].

## Synchronization

- Nested `struct btree` `b->lock` rw_semaphores must be acquired in descending `b->level` order and ascending `bkey_cmp(&a->key, &b->key)` order at the same level; callers of `btree_node_free(b)` must hold `b->lock` for write and call `btree_node_free(b)` before `rw_unlock(true, b)` because `mca_reap()` can immediately trylock nodes on `c->btree_cache_freeable`; and in `btree_gc_coalesce()`, errors after locking `new_nodes[i]->write_lock` must jump to `out_unlock_nocoalesce` before `btree_node_free()` [F8, F9, F38].
- Because `c->root` and hashed btree nodes can change before `b->lock` is acquired, `bcache_btree_root()` must recheck `_b == c->root && _w == insert_lock(op, _b)` after `rw_lock()`, direct `c->root` lockers (`bch_root_usage()`, `bch_sectors_dirty_init()`) must recheck `b == c->root`, `bch_btree_node_get()` must revalidate `PTR_HASH(c, &b->key) == PTR_HASH(c, k)` after `mca_find()` and `rw_lock()`, and `bch_btree_insert_check_key()` must verify `b->key.ptr[0] == btree_ptr && b->seq == seq + 1` when upgrading read to write lock and `downgrade_write(&b->lock)` before returning [F43, F44, F45, F218].
- `c->bucket_lock` must be held when mutating `c->btree_cache*` lists, `c->bucket_hash`, `c->gc_mark_valid`, or bucket freelists/heaps (`ca->free[]`, `ca->free_inc`, `ca->heap`), and in sysfs handlers accessing them; in `bch_mca_scan()`, `mutex_lock(&c->bucket_lock)` is only allowed when `sc->gfp_mask & __GFP_IO` (else `mutex_trylock()`, returning `SHRINK_STOP` if `c->btree_cache_alloc_lock` is held); and `bch_alloc_sectors()` must drop `c->data_bucket_lock` before `bch_bucket_alloc_set()` and call `bkey_put(c, &alloc.key)` if `pick_data_bucket()` did not consume `alloc.key` [F35, F41, F176, F231].
- In `btree_flush_write()`, `BTREE_NODE_journal_flush` must be set under both `c->bucket_lock` and `b->write_lock` while `mca_reap()` and `btree_node_free()` wait under `b->write_lock` for it to clear; in `__bch_btree_node_write()`, clearing `BTREE_NODE_dirty` and toggling `BTREE_NODE_write_idx` must occur under both `b->write_lock` and `b->io_mutex` so `__btree_node_write_done()` completes `btree_prev_write(b)` [F33, F86].
- `bch_register_lock` must be held in sysfs show/store handlers (rejecting stores with `-EBUSY` when `bcache_is_reboot` is true) and in `bcache_device_unlink()` (gated by `!test_and_set_bit(BCACHE_DEV_UNLINK_DONE, &d->flags)`), but callers must never hold `bch_register_lock` while waiting for `bcache_device_stop()` or `bch_cache_set_stop()` because teardown closures acquire `bch_register_lock` [F40, F164, F230].
- `dc->writeback_lock` must be held shared via `down_read_non_owner()` across `cached_dev_write()` until `cached_dev_write_complete()`, held shared in `update_writeback_rate()` (which must `break` rather than `return` on trylock skip so `BCACHE_DEV_RATE_DW_RUNNING` is cleared after rescheduling `dc->writeback_rate_update`, and teardown must use `cancel_writeback_rate_update_dwork()`), and held exclusive (`down_write()`) in `bch_cached_dev_attach()` across writeback start/init/run and in `bch_writeback_thread()` across `refill_dirty(dc)` and state transitions (always restoring `TASK_RUNNING` and calling `up_write()` before sleeping, calling `read_dirty()`, or breaking) [F36, F166, F167, F213, F222, F223, F276, F323].
- Because clean cache reads and moving-GC reads do not pin their bucket, `bch_cache_read_endio()` and `read_moving_endio()` must check `(!KEY_DIRTY(&b->key) && ptr_stale(c, &b->key, 0))` and set `s->iop.status = BLK_STS_IOERR` while passing `bio->bi_status` (0) to `bch_bbio_endio()`; bio `bi_end_io` callbacks (`dirty_endio()`, `read_dirty_endio()`) run in atomic context and must defer blocking work to `dc->writeback_write_wq`, and `bch_time_stats_update()` (`spin_lock(&stats->lock)`) must only be called from process context [F46, F199, F329, F330].

## Object Lifetimes

- `bch_alloc_sectors()` returns `true` with a bucket pin held for each pointer in `k`, which the caller must release via `bch_btree_insert()` or `bkey_put(c, k)`; `bch_btree_insert()` consumes all keys in its `keylist` and drops one bucket pin via `bkey_put()` per key on both success and error while leaving the `keylist` buffer for `bch_keylist_free()` [F2, F3].
- In `bch_btree_leaf_dirty()`, replacing an existing `w->journal` with an older `journal_ref` (`journal_pin_cmp(b->c, w->journal, journal_ref)`) requires `atomic_dec_bug(w->journal)` before overwriting and incrementing the new pin; `btree_complete_write()` must reset `w->prio_blocked = 0` and `w->journal = NULL` after releasing them [F14, F17].
- Any btree traversal using `struct btree_op` that may call `mca_cannibalize_lock()` or `btree_check_reserve()` must call `bch_cannibalize_unlock(c)` and `finish_wait(&c->btree_cache_wait, &op->wait)` before `op` goes out of scope [F21].
- In `register_bcache()`, after reading the superblock via the initial read-only `bdev_file` and allocating `holder`, the device must be reopened with `BLK_OPEN_READ | BLK_OPEN_WRITE` passing `holder` and the initial `bdev_file` closed with `fput()`; in `register_cache()`, `fput(bdev_file)` is called directly if `cache_alloc(ca)` fails, whereas after `cache_alloc(ca)` succeeds, `kobject_put(&ca->kobj)` (`bch_cache_release()`) owns `ca->bdev_file` and `ca`, so all logging/access of `ca` or `bdev_file` must precede `fput()`/`kobject_put()` [F7, F10, F170].
- In `bcache_device_free()`, any access to `d->disk` (such as `disk->first_minor` for `ida_free()` or `disk->disk_name`) must precede `put_disk(disk)`; `bch_cached_dev_detach()` must take `closure_get(&dc->disk.cl)` before `cached_dev_put(dc)`, and `cached_dev_detach_finish()` must save `dc->disk.c` before `bcache_device_detach()` clears `d->c = NULL` and call `closure_put(&dc->disk.cl)` at the end [F6, F20, F73].
- Once `bch_cached_dev_writeback_start()` creates `dc->writeback_thread`, ownership of `dc->writeback_write_wq` and `cached_dev_get(dc)` transfers to `bch_writeback_thread()` (if `kthread_create()` fails, `bch_cached_dev_writeback_start()` must roll back both); kthreads breaking out of their loop on `CACHE_SET_IO_DISABLE` or `dc->io_disable` (`bch_allocator_thread()`, `bch_gc_thread()`, `cached_dev_status_update()`, `bch_writeback_thread()`) must call `wait_for_kthread_stop()` before returning [F23, F206, F313].
- In `read_dirty()`, once `down(&dc->in_flight)` and `closure_call(&io->cl, read_dirty_submit, NULL, &cl)` run, the closure chain must always reach `write_dirty_finish()` (which must increment `PTR_BUCKET(dc->disk.c, &w->key, i)->pin` for each pointer in `w->key` before calling `bch_btree_insert()`, and always call `bch_keybuf_del(&dc->writeback_keys, w)` and `up(&dc->in_flight)`) and `dirty_io_destructor()` (`bio_free_pages(&io->bio)` and `kfree(io)`), and `read_dirty()` must call `closure_sync(&cl)` before returning [F207, F224, F251].

## API Contracts

- When journaling is active, `bch_journal()` returns an `atomic_t *` pin in `c->journal.pin` with refcount incremented by 1, and the caller must call `atomic_dec_bug()` on a non-NULL `journal_ref` after `bch_btree_insert()` finishes [F1].
- `bch_btree_node_get()` and `__bch_btree_node_alloc()` never return `NULL`; they return either an `ERR_PTR` (check `IS_ERR()`, and in `__bch_btree_node_alloc()` reinitialize `b = ERR_PTR(-EAGAIN)` right after `retry:`) or a valid `struct btree *` with `b->lock` held that the caller must release with `rw_unlock()` [F4, F47, F114].
- `mca_alloc()`, `__bch_btree_node_write()`, `bch_btree_insert()`, and `bch_journal_meta()` must never be called when `current->bio_list` is non-NULL; `bch_btree_node_get()` and `bch_btree_insert_node()` return `-EAGAIN` to abort `bcache_btree_root()` and defer to `bcache_wq`, whereas `-EINTR` restarts traversal from `c->root` (and must be returned by `cached_dev_cache_miss()` when `miss != bio` after `bch_btree_insert_check_key()` invalidates the caller's `btree_iter`) [F42, F54, F80].
- `KEY(inode, offset, size)` stores the ending sector in `KEY_OFFSET(k)` and sector length in `KEY_SIZE(k)` (`KEY_START(k) = KEY_OFFSET(k) - KEY_SIZE(k)`), with `size` capped to `USHRT_MAX` (`(1 << KEY_SIZE_BITS) - 1`) so it does not overflow into `KEY_DIRTY`, and `MAKE_PTR(gen, offset, dev)` takes `(gen, offset, dev)` in that order; standalone `struct bkey` buffers that hold pointers or receive `bkey_copy()` must use `BKEY_PADDED()`, and packed `bkey` sequences in a `bset`, `jset`, or `keylist` are sized/indexed in `uint64_t` words via `bkey_u64s()`, `bkey_next()`, `bkey_idx()`, and `set_bytes()` [F64, F108, F133, F149, F152].
- Bios mapped into single-page `bio_vec`s by `bch_bio_map(bio, NULL)` require `DIV_ROUND_UP(sectors, PAGE_SECTORS)` vectors, `bio->bi_iter.bi_size > 0`, and `bio->bi_vcnt == 0` on entry (preserving existing `bv_page` pointers when `base == NULL`); `bch_bio_alloc_pages()` requires `bio->bi_vcnt` set beforehand and frees its own pages on `-ENOMEM` so callers must not call `bio_free_pages()` on error [F144, F209, F334].

## Error Handling

- `c->root`, `new_nodes[i]` in `btree_gc_coalesce()`, `r[i].b` in `btree_gc_recurse()`, and `w->private` in `bch_keybuf_next()` consumers (initialized to `ERR_PTR(-EINTR)`) can hold `NULL`, an `ERR_PTR`, or a valid pointer, so cleanup and inspection paths must check `!IS_ERR_OR_NULL()` [F48, F49, F65].
- On-disk bounds checks: `__bch_extent_invalid()` must reject `KEY_SIZE(k) > KEY_OFFSET(k)`; `journal_read_bucket()` must verify `set_bytes(j)` against `left << 9`, `PAGE_SIZE << JSET_BITS`, and `len << 9` before `csum_set(j)` or copying; `bch_btree_node_read_done()` must verify `b->written + set_blocks(i, block_bytes(b->c->cache)) <= btree_blocks(b)` (where `set_blocks()` uses `DIV_ROUND_UP`) before checksumming or pushing keys; and `read_super()` must byte-swap and validate version-5+ features (`sb->version >= BCACHE_SB_VERSION_CDEV_WITH_FEATURES`) via `bch_has_unknown_*_features()` before `read_super_common()` [F52, F90, F92, F93, F94, F145].
- `dirty_endio()` clears `KEY_DIRTY(&w->key)` on bio error; `write_dirty()` must still advance `dc->writeback_sequence_next` (truncated to `uint16_t` to match `io->sequence`) and wake `dc->writeback_ordering_wait`, and `write_dirty_finish()` must only insert the clean key if `KEY_DIRTY(&w->key)` is still set [F250, F294].

## Known Pitfalls

- When `bch_extent_insert_fixup()` splits an unwritten key (`!bkey_written(b, k)`), it must copy `k` into a temporary `BKEY_PADDED` buffer before `bch_bset_insert(b, k, &temp.key)` because `bch_bset_insert()` `memmove`s `k`; in `do_btree_node_write()`, `memcpy()` into bio pages must use `page_address(bv->bv_page)` rather than `bvec_virt(bv)` because `bch_bio_map()` sets a non-zero `bv_offset`; and in `do_bio_hook()`, `bio_init_clone()` must take `orig_bio->bi_bdev` rather than `bio->bi_bdev` [F69, F115, F151].
- Integer width and saturation: `bch_extent_merge()` must saturate `KEY_SIZE(l) + KEY_SIZE(r)` at `USHRT_MAX`; `__bch_btree_mark_key()` must clamp `GC_SECTORS_USED(g) + KEY_SIZE(k)` to `MAX_GC_SECTORS_USED`; `bkey_cmp()` returns `int64_t` and must not be truncated to `int`; `bucket_to_sector()` must cast `b` to `sector_t` before `<< c->bucket_bits`; and `btree_flush_write()` must store `atomic_read(fifo_front_p)` in signed `int ref_nr` [F59, F134, F135, F136, F137].
