# BONDING DRIVER

The Linux Ethernet Channel Bonding driver (`drivers/net/bonding`, `include/net/bond*.h`) aggregates multiple slave network interfaces into a logical master virtual `net_device` across seven modes, managing slave enslavement/release, MII and ARP/IPv6 NS link monitoring, hardware offloads (VLAN, IPsec/XFRM, TLS, XDP), and configuration via rtnetlink, sysfs, ioctl, procfs, and debugfs.

## Architecture & Data Flow
- `SLAVE_AD_INFO(slave)` is allocated only in `BOND_MODE_8023AD` (`NULL` otherwise); `BOND_ALB_INFO(bond).tx_hashtbl` is allocated only while open (`bond_open` to `bond_close`), so paths reachable while down (e.g. `__tlb_clear_slave`) must check `tx_hashtbl != NULL`. [F56, F58]
- In 256-entry `tx_hashtbl` and `rx_hashtbl`, `0` is a valid index: links must use `TLB_NULL_INDEX`/`RLB_NULL_INDEX` (`0xffffffff`), and traversal deletions (`__tlb_clear_slave`, `rlb_purge_src_ip`, `rlb_clear_vlan`) must save the next index before `tlb_init_table_entry`/`rlb_delete_table_entry`. `rx_hashtbl[i].src_first` heads the `ip_src` list for bucket `i` independently of the client at `i`, so `rlb_delete_table_entry` must only call `rlb_init_table_entry_dst` and `rlb_src_unlink` without resetting `src_first`. [F99, F100, F123]
- In `bond_alb.c`, `rlb_choose_channel` hashes `arp->ip_dst` and matches `(ip_src, ip_dst)` on outbound ARPs, whereas `rlb_update_entry_from_arp` hashes `arp->ip_src` and matches reversed `(arp->ip_dst, arp->ip_src)` on inbound ARP replies. `rlb_arp_xmit` must verify `bond_slave_has_mac_rcu(bond, arp->mac_src)` and reject ARPs if `ip_dev_find` resolves `arp->ip_src` to a bridge master (`netif_is_any_bridge_master`). In `BOND_MODE_TLB` (`!rlb_enabled`), programming `bond->dev->dev_addr` into a slave via `dev_set_mac_address` (`alb_set_mac_address`, `bond_alb_handle_active_change`) must save and restore `slave->dev->dev_addr` via `dev_addr_set`. [F94, F130, F195]
- In `bond_3ad.c`, `__update_selected` and `__record_pdu` compare/copy `lacpdu->actor_*` against `port->partner_oper`, whereas `__choose_matched` and `__update_ntt` compare `lacpdu->partner_*` against `port->actor_*`. Parameter updates (`lacp_active`, `lacp_fast`, `ad_actor_sys_prio`, `ad_actor_system`, `port_priority`) must propagate via `bond_3ad_update_*` under `spin_lock_bh(&bond->mode_lock)`. In `ad_periodic_machine`, LACPDU TX is gated on `LACP_STATE_LACP_ACTIVITY` in `actor_oper_port_state` or `partner_oper.port_state` (never set in `AD_RX_EXPIRED`). [F80, F81, F129]
- `bond->params.arp_targets` and `ns_targets` are dense zero-terminated arrays (`BOND_MAX_NS_TARGETS <= BOND_MAX_ARP_TARGETS`); `bond_get_targets_ip`/`ip6` stop at the first zero entry and return signed `-1` when not found. Mutations to `arp_targets[]` must update each slave's `target_last_arp_rx[]` in lockstep, and `bond_option_arp_ip_target_rem` must compact `slave->target_last_arp_rx` before `arp_targets` because the slave loop tests `targets[i+1]`. [F77, F98, F233, F257]
- In `bond_arp_rcv` and `bond_na_rcv`, when a backup slave validates a probe because `curr_active_slave` received traffic after `last_link_up`, `sip`/`tip` or `saddr`/`daddr` must be passed in reversed order to `bond_validate_arp`/`bond_validate_na`; IPv6 validation must accept both `NDISC_NEIGHBOUR_SOLICITATION` and `NDISC_NEIGHBOUR_ADVERTISEMENT` and allow `daddr` matching `in6addr_linklocal_allnodes` or `bond_has_this_ip6`. [F114, F115]
- In `bond_miimon_inspect`, `ignore_updelay` must be initialized to `false`, evaluated via `!rcu_dereference(bond->curr_active_slave)` in active-backup and `usable_slaves && usable_slaves->count == 0` in other modes, and cleared once the first `BOND_LINK_BACK` slave becomes `BOND_LINK_UP`; `BOND_LINK_UP` must fall through to `BOND_LINK_FAIL` and `BOND_LINK_DOWN` to `BOND_LINK_BACK`. In `bond_miimon_commit` and `bond_ab_arp_commit`, when a slave becomes `BOND_LINK_UP` (including `slave->prio > active->prio`) or `curr_active_slave` goes down, `bond_select_active_slave` must be deferred via `do_failover = true` until `bond_for_each_slave` completes. [F67, F117, F118, F119]
- Because stacked bonds can be both master and slave, `bond_netdev_event` must check `IFF_MASTER` and `IFF_SLAVE` with independent `if` statements, `bond_enslave` must reject non-bond `IFF_MASTER` devices, and slave release/unwind must only clear `IFF_BONDING` if `!netif_is_bond_master(slave_dev)`. `bond_neigh_setup` must guard `parms->neigh_setup = bond_neigh_init` with `if (parms->dev == dev)` so upper VLAN devices do not downcast `netdev_priv(n->dev)` to `struct bonding *`. [F131, F149, F150]

## Synchronization
- `bond_for_each_slave`, `bond_first_slave`, `bond_last_slave`, `bond_slave_has_mac`, and `bond_slave_get_rtnl` require `rtnl_lock()`; RTNL-only paths (`bond_miimon_commit`, `bond_ab_arp_commit`, `bond_change_active_slave`, `bond_select_active_slave`, `bond_slave_netdev_event`) must use `rtnl_dereference` or `bond_slave_get_rtnl`, never `rcu_dereference`. Lockless readers must hold `rcu_read_lock()` across the call and all uses of pointers from `bond_for_each_slave_rcu`, `bond_first_slave_rcu`, `bond_slave_get_rcu`, `bond_slave_has_mac_rcu`, and `__bond_3ad_get_active_agg_info`; dual-context helpers (`bond_should_notify_peers`, `bond_option_active_slave_get_rcu`) must use `rcu_dereference_rtnl` with RCU or RTNL held across all accesses. [F166, F167, F211, F212, F215, F216, F219]
- `bond_update_slave_arr` requires RTNL and must not be called with `bond->mode_lock` held (it allocates with `GFP_KERNEL` via `struct_size(..., arr, bond->slave_cnt)` and acquires `spin_lock_bh(&bond->mode_lock)` in 802.3ad mode); callers holding `mode_lock` without RTNL must defer via `bond_slave_arr_work_rearm`. `bond_set_active_slave`, `bond_set_backup_slave`, and `bond_set_slave_state`/`bond_commit_link_state` with `BOND_SLAVE_NOTIFY_NOW` require RTNL; callers without RTNL must pass `BOND_SLAVE_NOTIFY_LATER` and later call `bond_slave_state_notify`/`bond_slave_link_notify` under RTNL. [F30, F140, F217]
- `bond->mode_lock` serializes all 802.3ad mutations on `struct port` and `struct aggregator` after `bond_3ad_bind_slave`, and all accesses/modifications to `alb_info.tx_hashtbl` and `rx_hashtbl`. ALB functions calling `dev_set_mac_address` or `dev_set_promiscuity` (`alb_swap_mac_addr`, `alb_fasten_mac_swap`, `alb_change_hw_addr_on_detach`, `bond_alb_deinit_slave`, `rlb_teach_disabled_mac_on_primary`) must run under RTNL with `mode_lock` and `rcu_read_lock` not held; in `bond_alb_handle_active_change`, `curr_active_slave` must be updated via `rcu_assign_pointer` and both slaves cleared via `tlb_clear_slave` before swapping/setting MACs. [F37, F38, F39, F40]
- In `bond_ipsec_add_sa_all` and `bond_ipsec_del_sa_all`, both `bond->ipsec_lock` and `spin_lock_bh(&ipsec->xs->lock)` must be held while checking `xs->km.state == XFRM_STATE_DEAD`, updating `xs->xso.real_dev`, and calling `xdo_dev_state_delete`. `bond_ipsec_del_sa` runs in atomic context with `xs->lock` held and must not take `bond->ipsec_lock` or mutate `bond->ipsec_list`; list removal and `kfree(ipsec)` belong in `bond_ipsec_free_sa` under `mutex_lock(&bond->ipsec_lock)`. [F26, F27]
- In `bond_get_stats`, `bond->stats_lock` must be acquired inside `rcu_read_lock()` via `spin_lock_nested(&bond->stats_lock, bond_get_lowest_level_rcu(bond_dev))`. Syncing UC/MC addresses from `bond->dev` to a slave under RTNL (`bond_hw_addr_swap`, `bond_enslave`) requires `netif_addr_lock_bh(bond->dev)` around `dev_uc_sync*`/`dev_mc_sync*`. In `__bond_release_one` with `unregister == true`, restoring `slave_dev`'s MTU must use `__netif_set_mtu` bracketed by `netdev_lock_ops(slave_dev)` / `netdev_unlock_ops(slave_dev)`. [F41, F47, F179]

## Object Lifetimes
- In `bond_newlink`, `register_netdevice` and `bond_work_init_all` must precede `bond_changelink`, unwinding via `bond_work_cancel_all` and `unregister_netdevice` on error. During `bond_enslave`, `bond_alb_init_slave` must run after `new_slave->perm_hwaddr` is copied and before `bond_master_upper_dev_link`; in 802.3ad mode, `bond_3ad_initialize` (after `bond_set_dev_addr` for the first slave) and `bond_3ad_bind_slave` must precede `netdev_rx_handler_register` and `bond_master_upper_dev_link`. [F1, F36, F72, F157]
- During `__bond_release_one` and `bond_enslave` unwind, `netdev_rx_handler_unregister`, `bond_upper_dev_unlink`, `bond_update_slave_arr`, and clearing RCU pointers (`current_arp_slave`, `primary_slave`, `curr_active_slave` via `bond_change_active_slave(bond, NULL)`) must precede `synchronize_rcu()`, which must precede `slave_disable_netpoll`, `dev_close`, and `kobject_put`. `bond_slave_ns_maddrs_add` must precede `bond_select_active_slave` in `bond_enslave`, and in `__bond_release_one`, `bond_slave_ns_maddrs_del` and `bond_alb_deinit_slave` (which resets `alb_info.rx_slave = NULL` before `rlb_clear_slave`) must run after `bond_upper_dev_unlink` and `bond_change_active_slave(bond, NULL)` and before `bond_select_active_slave`. [F7, F8, F87, F177]
- Once `bond_kobj_init` initializes `slave->kobj`, all error and release paths must call `bond_sysfs_slave_del` before `bond_3ad_unbind_slave` and then `kobject_put(&slave->kobj)` (never direct `kfree`), as `slave_kobj_release` calls `cancel_delayed_work_sync(&slave->notify_work)` and frees `SLAVE_AD_INFO(slave)` and `slave`. [F43, F160, F223]
- Slave release and active-slave failover must bracket changes with balanced `block_netpoll_tx()` / `unblock_netpoll_tx()`. When propagating per-slave changes (`bond_change_mtu`, `bond_set_mac_address`, `alb_set_mac_address`, `bond_vlan_rx_add_vid`, `bond_xdp_set`), failure on `slave` must roll back preceding slaves up to `rollback_slave == slave` without overwriting the original error code. Whenever `dev_xdp_propagate` succeeds with a non-NULL `prog`, the caller must call `bpf_prog_inc(prog)`, and when `bond_xdp_set` clears `old_prog`, it must call `bpf_prog_put(old_prog)` and `static_branch_dec(&bpf_master_redirect_enabled_key)`. [F17, F18, F20, F176]
- In `bond_ipsec_add_sa*`, `bond_ipsec_del_sa_all`, and `bond_ipsec_free_sa`, `xs->xso.real_dev` must be set only after `xdo_dev_state_add` succeeds and cleared to `NULL` before `xdo_dev_state_delete`/`free`. Slave `net_device` pointers obtained under `rcu_read_lock()` in `bond_ipsec_add_sa` and `bond_ethtool_get_ts_info` must be pinned with `netdev_hold`/`dev_hold` before `rcu_read_unlock()` and released on all exits; `dev` from `ip_dev_find` in `rlb_arp_xmit` requires `dev_put(dev)`; routes in `bond_arp_send_all`/`bond_ns_send_all` require `ip_rt_put(rt)`/`dst_release(dst)` on every loop path; and `bond_verify_device_path` callers must check `!IS_ERR_OR_NULL(tags)` and `kfree(tags)`. [F12, F13, F14, F15, F16]

## API Contracts
- Changing or clearing `bond->curr_active_slave` in modes using a primary/active slave must go through `bond_change_active_slave` rather than raw RCU pointer assignment. Before calling `bond_slave_get_rtnl` on an arbitrary `net_device *` (e.g. `bond_option_active_slave_set`), verify `netif_is_bond_slave(slave_dev)` and `bond->dev == netdev_master_upper_dev_get(slave_dev)`; all callers of `bond_slave_get_rcu`/`rtnl`, `bond_option_active_slave_get_rcu`, and `bond_first_slave`/`bond_last_slave`/`bond_first_slave_rcu` must handle `NULL` returns. [F59, F73, F148, F232, F272]
- Readers of `bond->usable_slaves` or `bond->all_slaves` selecting a slave by hash (`bond_xmit_3ad_xor_slave_get`, `bond_xdp_xmit_3ad_xor_slave_get`) must verify both `slaves != NULL` and `READ_ONCE(slaves->count) != 0` before `hash % count`. Callers of `tlb_choose_channel` / `__tlb_choose_channel` must mask `hash_index` to 8 bits (`& 0xFF`). `bond_handle_vlan` returns `false` only when `vlan_insert_tag_set_proto` failed and already freed `skb`, so callers must not transmit or free `skb` on `false`. [F52, F101, F107]
- `bond->params.updelay`, `downdelay`, and `peer_notif_delay` are stored in multiples of `bond->params.miimon` ticks: setters (`_bond_option_delay_set`, `bond_check_params`) must verify `miimon != 0` before dividing/modulo by `miimon`, and exporters must multiply by `miimon`. `__bond_opt_init` uses `optval->value = ULLONG_MAX` as the sentinel to parse `optval->string`: callers must pass either `string` or `value` (without sign-extending `-1` to `ULLONG_MAX`), and `bond_opt_slave_initval` must be passed `&slave_dev` (pointer to `struct net_device *`). [F68, F70, F135, F230, F277]
- `bond_option_mode_set` must reject mode changes with `-EOPNOTSUPP` when `bond->xdp_prog` is set and `!bond_xdp_check(bond, newval->value)`. `bond_xdp_set_features` must call `xdp_clear_features_flag` when `!bond_xdp_check` or `!bond_has_slaves`, and otherwise intersect slave `xdp_features` while masking out `NETDEV_XDP_ACT_XSK_ZEROCOPY`; attaching XDP requires every slave to implement `ndo_bpf` and `ndo_xdp_xmit`. Before invoking slave `xfrmdev_ops` (`xdo_dev_state_add`/`delete`), `bond_ipsec_*` must verify `!netif_is_bond_master(real_dev)` and non-NULL `xfrmdev_ops` and callback. [F84, F161, F162]
- In `slave_set_ns_maddrs`, `slave_set_ns_maddr`, and `bond_ns_send`, unicast `ns_targets` must be converted to solicited-node multicast via `addrconf_addr_solict_mult` before `ndisc_mc_map`/`ndisc_send_skb`, and in active-backup with `arp_validate`, those multicast MACs must be kept on backup slaves and removed from the active slave. [F69, F78]

## Known Pitfalls
- Packet helpers that call `pskb_may_pull` or `pskb_network_may_pull` (`bond_pull_data`, `alb_determine_nd`, `bond_xmit_alb_slave_get`, `bond_eth_hash`, `bond_flow_ip`, `bond_vlan_srcmac_hash`) can reallocate `skb->head` and must re-derive `data` and header pointers (`eth_hdr`, `ip_hdr`, `ipv6_hdr`) after every pull. In `bond_handle_frame`, `skb_share_check` must be written back to `*pskb`, and in `BOND_MODE_ALB` on a bridge port, `skb_cow_head` must succeed before mutating `eth_hdr(skb)->h_dest`. [F85, F86, F144]
- On RX (`bond_na_rcv`, `rlb_arp_recv`, `bond_3ad_lacpdu_recv`), `skb->data` is at the network header (`skb_header_pointer` offset `0`); on TX (`bond_should_broadcast_neighbor`), `skb->data` is at the MAC header (`skb_mac_header_len(skb)`). Because `skb->mac_header` is not guaranteed on `ndo_start_xmit` entry, `bond_xmit_hash` passes `mhoff = 0` from `skb->data`, and `bond_xmit_tlb_slave_get`/`bond_xmit_alb_slave_get` must call `skb_reset_mac_header(skb)` before `eth_hdr(skb)`. In `bond_arp_rcv`, `arp->ar_hln == bond->dev->addr_len` and `arp->ar_pln == 4` must be verified before advancing `arp_ptr` and copying `sip`/`tip` with `memcpy`. [F108, F109, F191]
- MAC buffers passed to `bond_slave_has_mac`, `bond_slave_has_mac_rcu`, `MAC_ADDRESS_EQUAL`, or `ether_addr_equal_64bits` must have 2 bytes of readable trailing padding (`ETH_ALEN + 2`, as in `ad_actor_system`), while code copying/exporting `ad_actor_system` must use `ETH_ALEN` (6) rather than `sizeof`. Before mutating `bond_dev` geometry in `bond_setup_by_slave`, `bond_dev` must be closed with `dev_close` and reopened if `IFF_UP`; `bond_ether_setup` must be used instead of raw `ether_setup` to preserve `IFF_MASTER | (flags & (IFF_SLAVE | IFF_UP))` and clear `IFF_TX_SKB_SHARING`. [F92, F147, F163, F281]
- `bond_for_each_slave` sets the cursor to `NULL` when finishing without `break`, so candidate pointers assigned inside the loop (e.g. `new_aggregator` in `bond_3ad_unbind_slave`) must be cleared if `!slave_iter`. In `bond_ns_send_all`, `struct flowi6 fl6` must be zeroed and `fl6.flowi6_oif` left unset; in `bond_neigh_init`, `struct neigh_parms parms` must be zeroed before `ndo_neigh_setup`. [F65, F66, F122]
