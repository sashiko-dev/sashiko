# HP BIOSCFG DRIVER

The HP BIOS Configuration driver (`hp-bioscfg`) is an x86 platform WMI driver that exposes HP BIOS settings, authentication mechanisms (passwords and Secure Platform Management / Sure Admin keys), and Sure Start audit logs to userspace via the Linux `firmware-attributes` sysfs class. During module initialization, it queries ACPI WMI blocks (either as ACPI packages or binary buffers) across multiple GUIDs to populate string, integer, enumeration, ordered-list, and password attribute instances, and uses WMI method evaluation to read statuses and commit updated BIOS settings.

## Architecture & Data Flow

- Each `hp_alloc_*_data()` function must reset `bioscfg_drv.*_instances_count` to 0 if `kcalloc()` fails, and each `hp_exit_*_attributes()` function must reset `*_instances_count` to 0 when freeing `bioscfg_drv.*_data`, because teardown and lookup loops index `bioscfg_drv.*_data` up to `*_instances_count` without NULL-checking the array pointer. [F6]
- In `hp_populate_*_elements_from_package()` across all five attribute types, when a count element (`PREREQUISITES_SIZE`, `ENUM_SIZE`, `ORD_LIST_SIZE`, or `PSWD_SIZE`) is zero, `eloc` must be incremented an extra time so `expected_*_types[eloc]` and `switch (eloc)` skip the omitted array element and stay aligned with `elem`. [F30]
- When parsing WMI binary buffers, firmware-supplied array counts (`prerequisites_size`, `possible_values_size`, `elements_size`, and `encodings_size`) must be clamped to `MAX_PREREQUISITES_SIZE`, `MAX_VALUES_SIZE`, `MAX_ELEMENTS_SIZE`, and `MAX_ENCODINGS_SIZE` respectively before iterating to populate the fixed-size arrays. [F42]
- In `hp_get_integer_from_buffer()`, the buffer pointer must be aligned to `sizeof(int)` via `PTR_ALIGN((int *)*buffer, sizeof(int))` before reading a 32-bit integer because preceding UTF-16 strings parsed by `hp_get_string_from_buffer()` only preserve `sizeof(u16)` alignment. [F49]
- In `hp_get_string_from_buffer()`, the in-place character-escaping loop must check `i == conv_dst_size` and break immediately after writing `'\\'` via `dst[i++] = '\\'` before writing the second escaped byte to `dst[i]`. [F63]
- For non-empty authentication strings in `hp_set_attribute()`, `hp_calculate_security_buffer()` and `hp_populate_security_buffer()` must both check `strstarts(authentication, BEAM_PREFIX)` and account for the prepended `UTF_PREFIX` (`"<utf-16/>"`) whenever `BEAM_PREFIX` is absent. [F41]
- In `hp_wmi_perform_query()`, `args->datasize = insize` must be assigned before accessing or copying into `args->data` because `struct bios_args` annotates `u8 data[]` with `__counted_by(datasize)`. [F65]
- In `hp_encode_outsize_for_pvsz()`, the `outsize` threshold checks (`> 4096`, `> 1024`, `> 128`, `> 4`, `> 0`) must be evaluated in strictly descending order so each size range maps to its smallest sufficient WMI method ID (1 through 5) and sizes above 4096 are rejected with `-EINVAL`. [F50]
- In `hp_enforce_single_line_input()`, the pointer `p` returned by `memchr(buf, '\n', count)` must be tested against `buf + count - 1` before the general non-NULL `else if (p)` check so a trailing newline is stripped to `'\0'` while any earlier newline is rejected with `-EINVAL`. [F51]
- When a BIOS setting or SPM key write succeeds in `ATTRIBUTE_PROPERTY_STORE()`, `sk_store()`, or `kek_store()`, the driver must update its in-memory state (`update_<type>_value()` or `bioscfg_drv.spm_data.mechanism`) and call `hp_set_reboot_and_signal_event()` (when `requires_physical_presence` is set for attributes, or unconditionally for SPM keys). [F35]
- `hp_init()` must create `bioscfg_drv.class_dev`, `bioscfg_drv.main_dir_kset`, and `bioscfg_drv.authentication_dir_kset` before calling `hp_init_bios_attributes()` or `hp_add_other_attributes()`, and in `hp_init_bios_attributes()`, `hp_alloc_attributes_data(attr_type)` must allocate `bioscfg_drv.<type>_data` sized to `hp_get_instance_count(guid)` before `hp_init_bios_package_attribute()` or `hp_init_bios_buffer_attribute()` indexes into `bioscfg_drv.<type>_data[instance_id]`. [F75, F76]

## Synchronization

- `hp_set_attribute()` acquires `bioscfg_drv.mutex` internally across credential lookup (`hp_get_password_instance_for_type()`), UTF-16 buffer construction (`hp_populate_security_buffer()`), and `hp_wmi_set_bios_setting()`, so neither its callers (such as `ATTRIBUTE_PROPERTY_STORE()`) nor its callees may acquire `bioscfg_drv.mutex`. [F17]
- `hp_init_bios_attributes()`, `hp_add_other_attributes()`, and `release_attributes_data()` hold `bioscfg_drv.mutex` while calling `hp_init_bios_package_attribute()`, `hp_init_bios_buffer_attribute()`, `hp_populate_*_data()`, `hp_exit_*_attributes()`, and `hp_wmi_perform_query()` (via `update_spm_state()`), so none of these functions or their callees may acquire `bioscfg_drv.mutex`. [F80, F81]
- `hp_wmi_perform_query()`, `hp_wmi_set_bios_setting()`, and `hp_get_wmiobj_pointer()` perform `GFP_KERNEL` / `ACPI_ALLOCATE_BUFFER` allocations and evaluate ACPI WMI methods (`wmi_evaluate_method()`, `wmi_query_block()`), so they must only be called from sleepable process context. [F83]

## Object Lifetimes

- Every attribute `struct kobject` (`attr_name_kobj`) must be a standalone heap allocation using `attr_name_ktype` (which provides `kobj_sysfs_ops` and `attr_name_release()` calling `kfree(kobj)`), have `attr_name_kobj->kset` assigned to `authentication_dir_kset` or `main_dir_kset` before `kobject_init_and_add()`, be freed with `kfree()` on error paths before `kobject_init_and_add()`, and be released with `kobject_put()` on error paths during or after `kobject_init_and_add()`. [F3, F12, F68, F93]
- In `release_attributes_data()`, all `hp_exit_*_attributes()` functions must run before `destroy_attribute_objs()` and `kset_unregister()` on `authentication_dir_kset` and `main_dir_kset`, and `hp_exit_*_attributes()` must only remove sysfs groups and free `bioscfg_drv.*_data` without calling `kobject_put(attr_name_kobj)` because `destroy_attribute_objs()` drops every kobject reference using `list_for_each_entry_safe()` (required as `kobject_put()` unlinks and frees `pos`). [F5, F54, F72]
- In `hp_exit_{string,integer,enumeration,ordered_list,password}_attributes()` and `hp_exit_secure_platform_attributes()`, each `attr_name_kobj` pointer in `bioscfg_drv.*_data[instance_id]` and `bioscfg_drv.spm_data` can be `NULL` (if an instance was skipped or failed initialization) and must be checked for non-`NULL` to call `sysfs_remove_group()` before zeroing `<type>_instances_count` and calling `kfree(bioscfg_drv.<type>_data)`. [F14, F23]
- When `kset_find_obj()` returns a non-NULL `struct kobject *` while checking `temp_kset` for duplicate attributes in `hp_init_bios_package_attribute()` or `hp_init_bios_buffer_attribute()`, the caller must release that reference with `kobject_put()`. [F4]
- `hp_get_wmiobj_pointer()` allocates a WMI block buffer via `ACPI_ALLOCATE_BUFFER` and transfers ownership of the returned `union acpi_object *` to the caller, which must free it with `kfree()` before exiting or overwriting the pointer variable. [F1]
- Every path that frees `bioscfg_drv.spm_data.auth_token`, `bioscfg_drv.spm_data.signing_key`, or `bioscfg_drv.spm_data.endorsement_key` (in `hp_clear_all_credentials()`, `sk_store()`, `kek_store()`, or `hp_exit_secure_platform_attributes()`) must immediately set that pointer to `NULL`. [F7]
- In `hp_init()` error rollback and `hp_exit()`, teardown must run `release_attributes_data()` before `device_unregister(bioscfg_drv.class_dev)`, and `device_unregister(bioscfg_drv.class_dev)` before `hp_exit_attr_set_interface()`, reversing the setup sequence. [F11]

## API Contracts

- `hp_calculate_string_buffer()`, `hp_calculate_security_buffer()`, and `hp_wmi_set_bios_setting()` size buffers in bytes, and must stay paired with `hp_ascii_to_utf16_unicode()`: empty strings use 4 bytes (`0x0002`, `0x0000` via `utf16_empty_string()`), while non-empty strings use `sizeof(u16) + strlen(str) * sizeof(u16)` bytes with a `u16` byte-length prefix (`len * 2`) and no NUL terminator; `hp_ascii_to_utf16_unicode()` advances its `u16 *p` cursor by character count `len` (not `len * 2`) and returns the `u16 *` cursor or `NULL` on error. [F28, F40, F67]
- Callers of `hp_wmi_perform_query()` must provide a `buffer` of at least `max(insize, outsize)` bytes and an `outsize <= 4096`, because `hp_wmi_perform_query()` reads `insize` bytes from `buffer` into `args->data` and writes `outsize` bytes (zero-padded via `memcpy_and_pad()`) back into `buffer`. [F26]
- `hp_init_bios_package_attribute()` and `hp_init_bios_buffer_attribute()` consume the first BIOS element (`NAME`) to check `temp_kset` for duplicates and create `attr_name_kobj` before calling `hp_populate_*_package_data()` (starting at `elem = 1, eloc = 1`) or `hp_populate_*_buffer_data()` (starting at `VALUE` with the advanced `buffer_ptr`). [F58]
- In binary buffer parsing (`hp_init_bios_buffer_attribute()`, `hp_populate_*_elements_from_buffer()`, and `hp_get_common_data_from_buffer()`), callers must invoke `hp_get_string_from_buffer()` and `hp_get_integer_from_buffer()` in the exact BIOS field sequence because each call advances `*buffer` and decrements `*buffer_size` in place. [F36]
- `hp_populate_password_package_data()` and `hp_populate_password_buffer_data()` must populate `password_data->common.display_name` from `attr_name_kobj->name` via `hp_friendly_user_name_update()`, because `hp_get_password_instance_for_type()` (called by `hp_set_attribute()`) matches `SETUP_PASSWD` against `password_data[instance].common.display_name`. [F60]
- In sysfs `.store` handlers (`ATTRIBUTE_PROPERTY_STORE()` and `store_password_instance()`), `hp_enforce_single_line_input()` must be called on the duplicated buffer before `validate_*_input()` and `hp_set_attribute()` so that a trailing newline at `buf + count - 1` is stripped in-place and embedded newlines are rejected with `-EINVAL`. [F47]
- `bioscfg_drv.class_dev` is registered under `firmware_attributes_class` with `MKDEV(0, 0)` and must be unregistered using `device_unregister(bioscfg_drv.class_dev)` rather than `device_destroy()`, which matches by `dev_t` and may unregister another device sharing `MKDEV(0, 0)`. [F84]

## Error Handling

- In `ATTRIBUTE_PROPERTY_STORE()`, every exit path after `kstrdup()` must call both `hp_clear_all_credentials()` and `kfree(attr_value)` regardless of whether input validation or `hp_set_attribute()` succeeds or fails. [F8]
- Callers of `hp_encode_outsize_for_pvsz()` (such as `hp_wmi_perform_query()`) must store its return value in a signed `int` rather than an unsigned integer type before checking `< 0`, because it returns `-EINVAL` when `outsize > 4096` and positive WMI method IDs (`1`..`5`) otherwise. [F19]
- Callers of `hp_get_string_from_buffer()` and the `hp_populate_*_elements_from_buffer()` helpers that return its result must test `ret < 0` rather than `if (ret)` for failure, because `hp_get_string_from_buffer()` returns the non-negative converted character `size` on success and `-EINVAL` on error. [F20]
- Every `switch (attr_type)` branch in `hp_add_other_attributes()` after `kobject_init_and_add()` must capture the return value of `hp_populate_secure_platform_data()` or `hp_populate_sure_start_data()` in `ret` (and set `ret = -EINVAL` in `default`) before checking `if (ret)` and jumping to `err_other_attr_init`. [F21]
- In `hp_init_bios_attributes()`, a negative return from `hp_init_bios_package_attribute()` or `hp_init_bios_buffer_attribute()` must not abort the `while (obj)` loop or increment `cur_instance_id`; `instance_id` always advances to query the next WMI block while `cur_instance_id` only advances when `ret >= 0`. [F24]
- In `hp_wmi_perform_query()`, `obj->type == ACPI_TYPE_BUFFER` and `obj->buffer.length >= sizeof(*bios_return)` must be verified before dereferencing `struct bios_return` at `obj->buffer.pointer` or subtracting `sizeof(*bios_return)` from `obj->buffer.length` to compute `actual_outsize`. [F39]
- Positive BIOS WMI return codes from `bios_return->return_code` in `hp_wmi_perform_query()` and `obj->integer.value` in `hp_wmi_set_bios_setting()` must be passed through `hp_wmi_error_and_message()`, which maps `enum wmi_error_values` to negative errno codes and logs non-zero errors via `pr_warn_ratelimited()`. [F90]

## External Contracts

- In `audit_log_entry_count_show()` and `audit_log_entries_show()`, `count` must be zero-initialized before querying `HPWMI_SURESTART_GET_LOG_COUNT`; in `audit_log_entries_show()`, after checking `count * LOG_ENTRY_SIZE <= PAGE_SIZE`, each loop iteration `0 <= i < count` must re-initialize `audit_log_buffer[0] = i + 1` (1-based index) before querying `HPWMI_SURESTART_GET_LOG` (which overwrites the 128-byte `audit_log_buffer`), copy only `LOG_ENTRY_SIZE` (16) bytes into `buf`, and `break` on `ret < 0` to return `i * LOG_ENTRY_SIZE`. [F29, F45, F57]
- Ordered-list `current_value` strings must be converted from comma-separated (`COMMA_SEP`) to semicolon-separated (`SEMICOLON_SEP`) via `replace_char_str()` when populated from BIOS, and converted from `SEMICOLON_SEP` back to `COMMA_SEP` in `validate_ordered_list_input()` before calling `hp_set_attribute()`. [F46]

## Known Pitfalls

- `hp_convert_hexstr_to_str()` returns `-EINVAL` before setting `*str = NULL` if `input_len <= 0`, and otherwise overwrites `*str = NULL` without freeing any prior allocation before transferring ownership of a `krealloc()`-allocated string in `*str`; callers in `hp_populate_*_elements_from_package()` must initialize `str_value = NULL`, call `kfree(str_value)` before reusing the variable or returning, and reset `str_value = NULL` after each `kfree(str_value)` in a loop. [F2, F25]
- Because `enumeration_current_val`, `integer_current_val`, `ordered_list_current_val`, and `string_current_val` are static `struct kobj_attribute` structures shared across all instances of their type, `hp_update_attribute_permissions()` must be called with each instance's `common.is_readonly` flag immediately before `sysfs_create_group()`. [F33]
- In `status_show()`, the loop counter `i` iterating over `data.kek_mod[i]` and `data.sk_mod[i]` from `255` down to `0` (`for (i = 255; i >= 0; i--)`) must remain a signed integer type. [F48]
