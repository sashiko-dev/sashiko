# INTEL PMT DRIVERS

The Intel Platform Monitoring Technology (PMT) drivers provide a unified device class (`intel_pmt`) and auxiliary bus drivers (`intel_vsec.telemetry`, `intel_vsec.crashlog`, and `intel_vsec.discovery`) for discovering and accessing hardware telemetry, crashlog, and feature capability tables exposed via Intel Vendor-Specific Extended Capabilities (VSEC) over PCIe MMIO. They expose telemetry and crashlog data regions to userspace via sysfs binary files (`read` and `mmap`) and control attributes, while also providing in-kernel APIs for consumers to query PMT features and read telemetry endpoints.

## Architecture & Data Flow

- `struct intel_pmt_entry.ep` is only populated when `ns->pmt_add_endpoint` is non-NULL and `entry->size` is non-zero, so code shared with crashlog or zero-size entries (such as `intel_pmt_read()` in `class.c`) must use `entry->pcidev`, `entry->cb`, and `entry->base` instead of dereferencing `entry->ep`. [F21]
- `pmt_telem_header_decode()` must reject `header->size == 0` by returning `1`, because `intel_pmt_dev_register()` returns `0` early when `!entry->size` before calling `ns->pmt_add_endpoint()`, which would leave `entry->ep` NULL while `pmt_telem_probe()` (`intel_pmt_get_features()`) and `pmt_telem_remove()` unconditionally dereference `entry->ep`. [F63]
- Every device registered with `intel_pmt_class` must have an `intel_vsec_device`'s `&auxdev->dev` as its parent because `intel_pmt_attr_visible()` casts `dev->parent` with `to_auxiliary_dev()`; in `pmt_features_probe()`, `priv->parent` must instead be `&ivdev->pcidev->dev` for PCI device matching against `&entry->ep->pcidev->dev` in `intel_pmt_get_features()`. If `ivdev->cap_id` is not `ilog2(VSEC_CAP_DISCOVERY)`, driver data must point to a `struct intel_pmt_entry` because `intel_pmt_attr_visible()` and `guid`, `size`, and `offset` attributes cast it unconditionally. [F70, F106]
- `struct intel_pmt_entry` must remain the first member of `struct crashlog_entry` because `intel_pmt_dev_register()` sets `dev` driver data to `entry`, while crashlog sysfs handlers (`clear_show`, etc.) cast `dev_get_drvdata(dev)` directly to `struct crashlog_entry *` and class sysfs handlers (`guid_show`, etc.) cast it to `struct intel_pmt_entry *`. [F105]
- All bit fields in `struct crashlog_status` and `struct crashlog_control` (after `offset`) must be pre-shifted bitmasks (`BIT()` or `GENMASK()`) rather than bit numbers, and `pmt_crashlog_rmw()` must clear `control->trigger_mask` before modifying `@bit` so trigger bits are not re-asserted during control register updates. [F111]
- In `pmt_feature_get_feature_table()`, before reading attributes or allocating `guids`, the total byte size `sizeof(*header) + FEAT_ATTR_SIZE(header->attr_size) + PMT_GUID_SIZE(header->num_guids)` must be validated not to exceed `resource_size(&res)` (`disc_tbl->size * sizeof(u32)`). [F49]
- In `pmt_features_discovery()`, each `feature_layout[feature->id]` branch must set `feature->attr_group` to the same `struct attribute_group` contained in the `default_groups` of the `ktype` (`pmt_feature_command_ktype`, `pmt_feature_guids_ktype`, `pmt_feature_rmid_ktype`, `pmt_feature_watcher_ktype`) passed to `kobject_init_and_add()`, because `pmt_features_remove()` passes `feature->attr_group` to `sysfs_remove_group(&feature->kobj, feature->attr_group)`. [F43]
- In `pmt_feature_get_disc_table()`, `priv->mask |= BIT(disc_tbl->id)` must only be set after all `SKIP_FEATURE` checks succeed, while `priv->mask & BIT(disc_tbl->id)` must reject duplicate active `disc_tbl->id` values with `-EINVAL` before `kobject_init_and_add()` registers `pmt_feature_names[feature->id]`. [F46]
- Because `struct feature_table` places `command`, `watcher`, and `rmid` in a union at different offsets per layout, accessors must resolve `watcher` and `command` via `get_watcher()` and `get_command()` and check `feature_layout[f->id] == LAYOUT_RMID` before reading `rmid.num_rmids`. [F67]
- In `intel_pmt_populate_entry()`, under `ACCESS_LOCAL` with `intel_pmt_is_early_client_hw(dev)`, `entry->base_addr` must be reset to `0` before the PCI BAR search loop (`0..5`) so that `!entry->base_addr` after the loop detects when no BAR contains `disc_res->start` instead of retaining the non-quirk `disc_res->end + 1 + header->base_offset` value. [F71]
- When `guid == GUID_SPR_PUNIT` and `cb->read_telem` is not used, `pmt_telem_read_mmio()` must read MMIO via `pmt_memcpy64_fromio()`, which requires `addr + off` to be 8-byte aligned (returning `-EFAULT` otherwise) and issues only 64-bit `readq()` accesses including for trailing sub-8-byte remainders. [F102]

## Synchronization

- `ep_lock` must be held across `intel_pmt_dev_create()` in `pmt_telem_probe()`, across `kref_put()` and `intel_pmt_dev_destroy()` in `pmt_telem_remove()`, and across every lookup or traversal of `telem_array` in `drivers/platform/x86/intel/pmt/telemetry.c` (`pmt_telem_get_next_endpoint()`, `pmt_telem_register_endpoint()`, `pmt_telem_get_endpoint_info()`, `intel_pmt_get_regions_by_feature()`). [F10]
- Sysfs callbacks on `intel_pmt` devices (`intel_pmt_read`, `intel_pmt_mmap`, `guid_show`, `size_show`, `offset_show`) must never acquire `ep_lock`, because `pmt_telem_remove()` holds `ep_lock` while calling `intel_pmt_dev_destroy()` to remove sysfs files and unregister the device. [F98]
- `pmt_telem_register_endpoint()` must increment `entry->ep->kref` via `kref_get()` before releasing `ep_lock`. [F11]
- In `intel_pmt_get_regions_by_feature()`, both `xa_for_each(&telem_array, ...)` passes must execute within the same `ep_lock` critical section using the identical filter predicate (`entry->feature_flags & BIT(id)`). [F66]
- Every crashlog control-register modification and any preceding status check (`pmt_crashlog_disabled()`, `pmt_crashlog_complete()`) in `clear_store`, `consumed_store`, `enable_store`, `rearm_store`, and `trigger_store` must be serialized under `crashlog->control_mutex` and go through `pmt_crashlog_rmw()`, which masks off `crashlog->info->control.trigger_mask` from the sampled `readl()` value before setting or clearing the requested bit. [F40, F99]

## Object Lifetimes

- In `pmt_telem_add_endpoint()`, `entry->ep` (`struct telem_endpoint`) must be allocated with `kzalloc()` and freed only via `kref_put(&ep->kref, pmt_telem_ep_release)` rather than `devm_*`, because registered consumers may hold references to `entry->ep` after `pmt_telem_remove()` runs. Broken by: converting `entry->ep` to `devm_kzalloc()` or calling `kfree(entry->ep)` in `pmt_telem_remove()`. [F2]
- `intel_pmt_dev_register()` sets up `xa_alloc()`, `device_create()`, optional `sysfs_create_group()`, and (when `entry->size > 0`) `devm_ioremap_resource()`, `sysfs_create_bin_file()`, and optional `ns->pmt_add_endpoint()`, and both its error labels and `intel_pmt_dev_destroy()` must unwind them in strict reverse order. [F4]
- `entry->disc_table` is mapped via `devm_ioremap_resource()` on the parent auxiliary device in `intel_pmt_dev_create()`, whereas `entry->base` is mapped on the child `intel_pmt_class` device (`dev`) in `intel_pmt_dev_register()` and unmapped when `intel_pmt_dev_destroy()` calls `device_unregister(dev)`. Broken by: binding `entry->base` to the parent auxiliary device (leaving the resource claimed if `intel_pmt_dev_register()` fails later) or accessing `entry->base` after `intel_pmt_dev_destroy()`. [F9]
- All insertions, removals, and traversals of `pmt_feature_list` (`pmt_features_add_feat`, `pmt_features_remove_feat`, `intel_pmt_get_features`) must hold `feature_list_lock`, and `pmt_features_remove()` must unlink each initialized `struct feature` via `pmt_features_remove_feat()`, remove `feature->attr_group`, and call `kobject_put(&feature->kobj)` before `device_unregister(priv->dev)` frees `devm_kmalloc(priv->dev, ...)` allocations like `feature->table.guids`. [F8, F100]
- `pmt_crashlog_header_decode()` must initialize `crashlog->control_mutex`, `crashlog->info`, and `entry->attr_grp` before `intel_pmt_dev_register()` exposes sysfs attributes, and `pmt_crashlog_remove()` must call `intel_pmt_dev_destroy()` to remove those attributes before `mutex_destroy(&crashlog->control_mutex)`. [F86]
- `intel_pmt_get_features(entry)` must only be called after `intel_pmt_dev_create()` returns `0` for a telemetry entry with `pmt_telem_add_endpoint()` registered, because `intel_pmt_get_features()` unconditionally dereferences `entry->ep->pcidev`. [F88]

## API Contracts

- Callers of `pmt_telem_register_endpoint()` and `pmt_telem_find_and_register_endpoint()` receive a reference-counted `struct telem_endpoint *` (`ep->kref` incremented) on success and must release it by calling `pmt_telem_unregister_endpoint()`, including when `pmt_telem_read()` or `pmt_telem_read32()` returns `-ENODEV`. [F1]
- `intel_pmt_get_regions_by_feature()` transfers ownership of a `kref`-counted `struct pmt_feature_group *` via `no_free_ptr(feature_group)` on success (which callers must release with `intel_pmt_put_feature_group()`), while relying on `__free(kfree)` (which must be initialized to `NULL` before any early `ERR_PTR` return) and `guard(mutex)(&ep_lock)` to free `feature_group` and unlock `ep_lock` on early error. [F3, F27]
- `pmt_telem_register_endpoint()`, `pmt_telem_find_and_register_endpoint()`, and `intel_pmt_get_regions_by_feature()` always return an `ERR_PTR` value (never `NULL`) on failure, so callers must check `IS_ERR()` before dereferencing the returned pointer or passing it to unregister/put functions. [F20]
- `pmt_telem_read_mmio()` and `struct pmt_callbacks.read_telem` return a negative errno on failure or the positive byte count read on success, whereas `pmt_telem_read()` and `pmt_telem_read32()` return `0` on success or `-ENODEV`, `-EINVAL`, or `-EPIPE` on failure. Broken by: a `read_telem` callback returning `0` on success instead of `count` (causing `intel_pmt_read()` to report EOF). [F19]
- Callers of `pmt_telem_read_mmio()` must pass the base MMIO address in `addr` and the byte offset separately in `off` (rather than `addr + off` with `off = 0`), because `pmt_telem_read_mmio()` forwards `off` to `cb->read_telem()` before adding `off` to `addr` in the direct MMIO path. [F28]
- `pmt_telem_read()` and `pmt_telem_read32()` take `id` as a 0-based sample index and `count` as a number of 8-byte qwords (`SAMPLE_ID_OFFSET`, `NUM_BYTES_QWORD`) or 4-byte dwords (`SAMPLE_ID_OFFSET32`, `NUM_BYTES_DWORD`) respectively, whereas `ep->header.size` and `pmt_telem_read_mmio()`'s `off` and `count` are in bytes. [F30]
- `pmt_telem_read_mmio()` and `pmt_telem_read()` must only be called from process context when `cb->read_telem` may be populated, because `cb->read_telem` implementations (such as `xe_pmt_telem_read`) acquire sleeping mutexes. [F101]
- `PMT_XA_START` must remain `>= 1` (`1`) so `xa_alloc()` in `intel_pmt_dev_register()` never allocates `devid == 0`; `pmt_telem_get_next_endpoint()` and `pmt_telem_find_and_register_endpoint()` reserve `0` as both the initial cursor (`start = 0` to begin iteration, returning the first `devid` strictly greater than `start`) and the end-of-iteration sentinel. Broken by: starting a `pmt_telem_get_next_endpoint()` loop at `1` (which skips `devid == 1`) or setting `PMT_XA_START` to `0`. [F31, F45]
- Callers of `intel_pmt_is_early_client_hw(struct device *dev)` must pass `&ivdev->auxdev.dev` (the `struct intel_vsec_device`'s embedded auxiliary device), never a `struct pci_dev` device or `intel_pmt_class` child device, because `intel_pmt_is_early_client_hw()` unconditionally applies `dev_to_ivdev(dev)`. [F91]

## Error Handling

- When `entry->size` is `0`, `intel_pmt_dev_register()` returns `0` after creating `entry->attr_grp` without mapping `entry->base`, initializing `entry->pmt_bin_attr`, or calling `ns->pmt_add_endpoint`, so `intel_pmt_dev_destroy()` must guard `sysfs_remove_bin_file()` with `if (entry->size)` and `sysfs_remove_group()` with `if (entry->attr_grp)`. [F25]
- `pmt_telem_probe()`, `pmt_crashlog_probe()`, and `pmt_features_probe()` must index their entry arrays by `priv->num_entries` (or `priv->count`) rather than loop index `i` and increment that counter only after registration succeeds (`ret == 0`), so that calling the `.remove` handler (`pmt_telem_remove()`, `pmt_features_remove()`, etc.) at `abort_probe` tears down only fully initialized entries. [F26]
- When encountering reserved, zero-size, or unsupported hardware discovery entries, `pmt_crashlog_header_decode()`, `pmt_telem_header_decode()`, and `pmt_feature_get_disc_table()` must return positive `1` (`SKIP_FEATURE`) rather than a negative errno so the `.probe` loops skip the entry without aborting device probe. [F112]

## External Contracts

- In `crashlog.c`, `clear_store()`, `consumed_store()`, and `rearm_store()` are set-only and must return `-EINVAL` when the parsed boolean is `false`, whereas `enable_store()` inverts `enabled` when calling `pmt_crashlog_set_disable()`. In `trigger_store()`, `!trigger` (`false`) must be handled by calling `pmt_crashlog_set_clear(crashlog)` and returning before the `pmt_crashlog_complete(crashlog)` check, whereas `consumed_store()` requires `pmt_crashlog_complete(crashlog)` to be true (returning `-EEXIST` when `!pmt_crashlog_complete(crashlog)`). [F69, F110]
- `intel_pmt_mmap()` must reject mappings with `VM_WRITE | VM_MAYWRITE` (`-EROFS`), validate `vsize` against the page-rounded span `(PFN_UP(entry->base_addr + entry->size) - PFN_DOWN(entry->base_addr)) * PAGE_SIZE`, and map with `pgprot_noncached(vma->vm_page_prot)` via `io_remap_pfn_range()`. [F103]

## Known Pitfalls

- `pmt_telem_read()` dispatches through `pmt_telem_read_mmio()`—which invokes `ep->cb->read_telem` when present and enforces 64-bit aligned `readq()` access for `GUID_SPR_PUNIT`—whereas `pmt_telem_read32()` calls `memcpy_fromio()` directly on `ep->base` and bypasses both `ep->cb` and the `GUID_SPR_PUNIT` quirk. [F108]
- Because discovery `base_offset` / `offset` fields pack the 3-bit BAR index (`GET_BIR` / `DT_TBIR`, `GENMASK(2, 0)`) in the low bits of an 8-byte-aligned byte offset, `ACCESS_LOCAL` must reject any non-zero BAR index with `-EINVAL` while `ACCESS_BARID` must mask bits `31:3` in place via `GET_ADDRESS(header->base_offset)` (`(v) & GENMASK(31, 3)`) without right-shifting by 3. Broken by: refactoring `GET_ADDRESS(v)` to `FIELD_GET(GENMASK(31, 3), v)` or `(v) >> 3`, or omitting the `if (bir)` / `if (tbir)` check in `ACCESS_LOCAL`. [F55, F72]
- In `pmt_telem_header_decode()`, `TELEM_SIZE(v)` extracts the 16-bit DWORD count from bits `27:12` of the discovery header and converts it to bytes by shifting right by 10 (`((v) & GENMASK(27, 12)) >> 10`, combining `>> 12` with `<< 2`). Broken by: replacing `TELEM_SIZE(v)` with `FIELD_GET(GENMASK(27, 12), v)` without multiplying by `sizeof(u32)`. [F73]
- In `struct feature_table`, `header`, `caps`, and the union of `command`, `watcher`, and `rmid` must remain contiguous 32-bit hardware-layout fields before `guids`, and `pmt_feature_get_feature_table()` must assign `feat_tbl->guids` only after `memcpy_fromio(tbl_offset, feat_offset, FEAT_ATTR_SIZE(header->attr_size))`. [F44]
- Because `enum pmt_feature_id` is 1-based and sparse (`FEATURE_INVALID = 0x0` and `FEATURE_RESERVED = 0x9` are unpopulated), any code indexing `pmt_feature_names[]` or `feature_layout[]` or shifting `BIT(id)` must validate `id` with `pmt_feature_id_is_valid(id)` rather than a simple range check; every valid `pmt_feature_id` must have entries in `pmt_feature_names[]`, `feature_layout[]`, and `caps_show()`, and each `pmt_caps_*` array must be NULL-terminated with inner `struct pmt_cap` arrays terminated by `{}`. [F50, F113]
