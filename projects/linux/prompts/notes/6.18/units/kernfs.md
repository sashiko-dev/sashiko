# KERNFS

kernfs provides an in-memory pseudo-filesystem framework (underlying sysfs, cgroupfs, etc.) that decouples subsystem hierarchy management and active-reference lifetimes from VFS inode and dentry locking. It manages directory, regular attribute file, and symlink nodes (`struct kernfs_node`) organized in per-root red-black trees and IDRs, supporting optional namespace tags, buffered/`seq_file` I/O, mmap, poll/fsnotify notifications, exportfs file handles, and extended attributes.

## Architecture & Data Flow

- Under `kernfs_open_file_mutex_ptr(kn)`, `on->nr_to_release` is incremented in `kernfs_get_open_node()` when `KERNFS_HAS_RELEASE` is set and decremented in `kernfs_release_file()` (setting `of->released = true`) or `kernfs_unlink_open_file()` when `open_failed` is true. `kernfs_drain_open_files()` clears `of->mmapped = false` when decrementing `on->nr_mmapped`, and `kernfs_unlink_open_file()` clears `kn->attr.open` before `kfree_rcu(on, rcu_head)`. [F9, F65]
- `dir.root` is in the `struct kernfs_node` union (`dir`, `symlink`, `attr`), and `kernfs_root(kn)` reads `kn->__parent->dir.root` when `kn->__parent` is non-NULL; every `KERNFS_DIR` node must set `kn->dir.root` and every non-root node must set `kn->__parent` before `kernfs_root(kn)` is called. [F46]
- `kn->iattr` is lazily allocated via `kernfs_iattrs(kn)`; read-only paths (`kernfs_refresh_inode()`, `kernfs_xattr_get()`) use `kernfs_iattrs_noalloc(kn)` and handle `NULL`, whereas `kernfs_iop_listxattr()`, `__kernfs_setattr()`, and `kernfs_vfs_user_xattr_set()` must call `kernfs_iattrs(kn)` and return `-ENOMEM` if `NULL`. [F45]
- `kernfs_fop_open()` must always call `seq_open()` (with `&kernfs_seq_ops` if `ops->seq_show` is set or `NULL` otherwise), set `of->seq_file->private = of`, and restore `FMODE_PWRITE` if `FMODE_WRITE` is set, because `kernfs_of(file)` dereferences `((struct seq_file *)file->private_data)->private`. [F48]
- In `kernfs_fop_open()` (when `ops->prealloc` is set) and `kernfs_fop_write_iter()`, write buffers must be allocated with `len + 1` bytes and `len` must be bounded by `of->atomic_write_len` (rejecting larger writes with `-E2BIG`) or clamped to `PAGE_SIZE`, because `kernfs_fop_write_iter()` unconditionally sets `buf[len] = '\0'`. [F76]
- Every file read path in `fs/kernfs/file.c` (`kernfs_seq_show()` and `kernfs_file_read_iter()`) must snapshot `atomic_read(&of_on(of)->event)` into `of->event` while holding an active reference on `of->kn` before invoking the read callback. [F59]
- In `kernfs_rename_ns()`, `kn` must be unlinked via `kernfs_unlink_sibling()` before mutating `kn->__parent`, `kn->ns`, `kn->name`, or `kn->hash`, and re-linked via `kernfs_link_sibling()` only after recomputing `kn->hash` via `kernfs_name_hash()`. `kernfs_unlink_sibling()` must call `RB_CLEAR_NODE(&kn->rb)` after `rb_erase()`. [F62, F63]

## Synchronization

- In `struct kernfs_root`, `root->kernfs_supers_rwsem` nests outside `root->kernfs_rwsem`, and `root->kernfs_rwsem` nests outside `root->kernfs_iattr_rwsem`, `root->kernfs_rename_lock`, and `kernfs_pr_cont_lock`. Updates to `kn_parent->dir.subdirs` and `kn_parent->dir.rev` (`kernfs_inc_rev()`), `kn->mode`, and `kn->iattr` timestamps/UID/GID must hold `root->kernfs_iattr_rwsem` for write. [F26, F114]
- On regular file I/O, seek, and mmap paths (`kernfs_seq_start()`, `kernfs_file_read_iter()`, `kernfs_fop_write_iter()`, `kernfs_fop_mmap()`, `kernfs_fop_llseek()`), `of->mutex` must be acquired before `kernfs_get_active_of(of)` (and after `of->prealloc_mutex` when `of->prealloc_buf` is used). [F33]
- `kernfs_fop_open()` must initialize `of->mutex` at three separate `mutex_init()` call sites for `has_mmap`, `file->f_mode & FMODE_WRITE`, and read-only files for distinct lockdep class keys, and `kernfs_fop_mmap()` must check `KERNFS_HAS_MMAP` before locking `of->mutex`. [F119]
- `kernfs_drain()` must release `root->kernfs_rwsem` before waiting on `root->deactivate_waitq` for `kn->active == KN_DEACTIVATED_BIAS` and before calling `kernfs_drain_open_files(kn)`, and must reacquire `root->kernfs_rwsem` for write before returning. [F22]
- Every `kernfs_break_active_protection(kn)` call inside an active-referenced `kernfs_ops` callback must be matched by `kernfs_unbreak_active_protection(kn)` before returning, and in `kernfs_remove_self(kn)` that call must occur before `up_write(&root->kernfs_rwsem)`. [F6]
- `kernfs_active(kn)` asserts `kernfs_root(kn)->kernfs_rwsem` is held; callers without `kernfs_rwsem` must call `__kernfs_active(kn)`. In `kernfs_find_and_get_node_by_id()`, lookup in `root->ino_idr` under `rcu_read_lock()` must verify `__kernfs_active(kn)`, `atomic_inc_not_zero(&kn->count)`, and the upper 32 bits of `kn->id` (`kernfs_ino(kn) != ino` on 64-bit `ino_t`, or `gen && kernfs_gen(kn) != gen` on 32-bit `ino_t`, where `root->id_highbits` starts at `1`). [F27, F37, F80, F96]
- Accessing `kn->__parent` via `kernfs_parent(kn)` requires `rcu_read_lock()`, `root->kernfs_rwsem`, or `root->kernfs_rename_lock` (unless `kn->count == 0`), and taking a parent reference without `kernfs_rwsem` must hold `root->kernfs_rename_lock` across `kernfs_parent(kn)` and `kernfs_get(parent)`. Because `kernfs_get_parent()` and `kernfs_path_from_node()` use `read_lock_irqsave()`, `kernfs_rename_ns()` must use `write_lock_irq(&root->kernfs_rename_lock)`, and `pr_cont_kernfs_name()`/`pr_cont_kernfs_path()` must release `kernfs_rename_lock` before calling `pr_cont()`. [F29, F111, F112]
- Multi-step ancestor traversals without `root->kernfs_rwsem` (`kernfs_path_from_node()`) must hold `root->kernfs_rename_lock` unless `KERNFS_ROOT_INVARIANT_PARENT` is set, and `kernfs_rename_ns()` rejects `old_parent != new_parent` when `KERNFS_ROOT_INVARIANT_PARENT` is set. `kernfs_node_dentry()` requires `KERNFS_ROOT_INVARIANT_PARENT` and must copy `kernfs_rcu_name(kntmp)` under `root->kernfs_rwsem` read lock before dropping it to call `lookup_noperm_positive_unlocked()`. [F30, F35, F143]
- `kn->attr.open` must only be modified under `kernfs_open_file_mutex_ptr(kn)` via `rcu_assign_pointer()` (after `kernfs_get_open_node()` initializes `on->event`, `on->poll`, and `on->files`) and freed with `kfree_rcu()`, while readers without that mutex or a linked `kernfs_open_file` (`!list_empty(&of->list)`) must dereference `kn->attr.open` under `rcu_read_lock()`. [F19, F123]
- `kernfs_notify()` may be called from any context, so it must only wake `on->poll` under `rcu_read_lock()` and queue `kn` onto `kernfs_notify_list` (terminated with `KERNFS_NOTIFY_EOL`, taking `kernfs_get(kn)`) under `spin_lock_irqsave(&kernfs_notify_lock, flags)`, while `kernfs_notify_workfn()` resets `kn->attr.notify_next = NULL` under `kernfs_notify_lock`, runs sleeping `fsnotify()` work, and calls `kernfs_put(kn)`. [F74, F113]
- Every allocation or removal on `root->ino_idr` (`idr_alloc_cyclic()` and `idr_remove()`, including error rollback in `__kernfs_new_node()` and teardown in `kernfs_put()`, before `call_rcu(&kn->rcu, kernfs_free_rcu)` and `kfree_rcu(root, rcu)`) must be serialized by `root->kernfs_idr_lock`. [F24, F25]

## Object Lifetimes

- File and VMA operations acting on `struct kernfs_open_file *of` must acquire active references via `kernfs_get_active_of(of)` (and release via `kernfs_put_active_of(of)`) rather than `kernfs_get_active(of->kn)` directly, so operations abort once `of->released` is set by `kernfs_release_file()`. [F1]
- During subtree removal in `__kernfs_remove()`, every descendant must first be marked `KERNFS_REMOVING` and deactivated with `KN_DEACTIVATED_BIAS` on `pos->active` under `root->kernfs_rwsem`, and the drain loop must re-fetch `pos = kernfs_leftmost_descendant(kn)`, pin `pos` with `kernfs_get(pos)` across `kernfs_drain(pos)`, drop the tree reference via `kernfs_put(pos)` only if `!parent || kernfs_unlink_sibling(pos)` succeeds, and then release its local `kernfs_put(pos)`. [F5, F21, F71]
- `kernfs_destroy_root()` must pin `root->kn` with `kernfs_get(root->kn)` before calling `kernfs_remove(root->kn)` and release it with `kernfs_put(root->kn)` afterward, because `kernfs_put()` frees `struct kernfs_root` when the root node's `count` reaches zero while `kernfs_remove()` still holds `root->kernfs_rwsem`. [F2]
- `kernfs_new_node()` initializes `kn->count` to 1 and pins `parent` (and `kernfs_create_link()` pins `target`), and callers must initialize `kn->ns`, `kn->priv`, union fields, and `KERNFS_HAS_*`/`KERNFS_LOCKDEP` flags before `kernfs_add_one(kn)`. `kernfs_add_one()` transfers `kn->count` to the hierarchy on success without consuming `kn` on error, so creators must call `kernfs_put(kn)` only when `kernfs_add_one()` fails. [F3, F17]
- Accessing `kn->name` requires RCU or `kernfs_root(kn)->kernfs_rwsem` (`kernfs_rcu_name()`). Because `kn->name` is allocated via `kstrdup_const()`, freeing it must use `kfree_const()`, or in `kernfs_rename_ns()` publish the new name with `rcu_assign_pointer()` and free `old_name` via `kfree_rcu_mightsleep()` if `!is_kernel_rodata((unsigned long)old_name)` (while calling `kernfs_get(new_parent)` before reassigning `kn->__parent` under `root->kernfs_rename_lock` and `kernfs_put(old_parent)` afterward). [F16, F28, F105]
- `kernfs_seq_start()` locks `of->mutex` (unlocked in `kernfs_seq_stop()`) and gets `kernfs_get_active_of(of)`; because `kernfs_seq_stop()` skips `kernfs_seq_stop_active()` on `ERR_PTR(-ENODEV)`, `kernfs_seq_start()` and `kernfs_seq_next()` must call `kernfs_seq_stop_active()` when `ops->seq_start` or `ops->seq_next` returns `ERR_PTR(-ENODEV)`. [F7]
- In `kernfs_file_read_iter()` and `kernfs_fop_write_iter()`, when `of->prealloc_buf` is non-NULL, `of->prealloc_mutex` must be locked outside `of->mutex` and unlocked on exit instead of calling `kfree(buf)`, whereas dynamically allocated buffers must be freed with `kfree(buf)` after `kernfs_put_active_of(of)` and `mutex_unlock(&of->mutex)`. [F10]
- `kernfs_get_inode()` takes its own `kernfs_get(kn)` reference in `kernfs_init_inode()` when `iget_locked()` returns a new inode (`I_NEW`) and releases it in `kernfs_evict_inode()`, so callers that obtained `kn` via a refcounted helper (`__kernfs_fh_to_dentry()`) must still call `kernfs_put(kn)` after `kernfs_get_inode()`. [F14]
- In `kernfs_fop_readdir()`, saving `pos` in `file->private_data` before `dir_emit()` must be paired with `kernfs_get(pos)` (and cleared to `NULL` at EOF), and `kernfs_dir_pos()` must consume that reference via `kernfs_put(pos)` and fall back to an rbtree search by `ctx->pos` hash if `pos` is no longer active, under `parent`, or matching `hash`. [F70]

## API Contracts

- `kernfs_find_ns()`, `kernfs_walk_ns()`, `kernfs_dentry_node()`, `kernfs_node_from_dentry()`, and `kernfs_root_to_node()` return borrowed `kernfs_node` pointers, whereas `kernfs_find_and_get_ns()`, `kernfs_walk_and_get_ns()`, `kernfs_get_parent()`, and `kernfs_find_and_get_node_by_id()` increment `kn->count` and require `kernfs_put()`. [F4]
- `kernfs_ops(kn)` asserts `lockdep_assert_held(kn)` when `KERNFS_LOCKDEP` is set and requires an active reference on `kn`; paths without an active reference must check cached `KERNFS_HAS_*` flags or `of->atomic_write_len`. `kernfs_release_file()` must synchronize `kernfs_fop_release()` and `kernfs_drain_open_files()` using `kernfs_open_file_mutex_ptr(kn)` (not `of->mutex`) and call `kn->attr.ops->release(of)` directly instead of `kernfs_ops(kn)`. [F47, F118]
- External entry points accepting an arbitrary `struct dentry *` or `struct super_block *` (`kernfs_node_from_dentry()` and `kernfs_root_from_sb()`) must verify `s_op == &kernfs_sops` before reading `d_inode(dentry)->i_private` via `kernfs_dentry_node()` or casting `sb->s_fs_info` via `kernfs_info()`. [F107]
- Once `kernfs_enable_ns()` sets `KERNFS_NS` on an empty directory, every child added via `kernfs_add_one()` or looked up via `kernfs_find_ns()` under that directory must have `(bool)ns == kernfs_ns_enabled(parent)`, or kernfs triggers a `WARN` and fails with `-EINVAL` or `NULL`. [F142]
- `kernfs_xattr_get()` and `kernfs_xattr_set()` require a full extended attribute name (including prefix such as `security.` or `trusted.`), whereas VFS `xattr_handler` callbacks (`kernfs_vfs_xattr_get()`, `kernfs_vfs_xattr_set()`, `kernfs_vfs_user_xattr_set()`) must first convert `suffix` via `xattr_full_name(handler, suffix)`. [F52]
- VFS callbacks invoked during RCU path walk (`kernfs_dop_revalidate()` when `flags & LOOKUP_RCU`, `kernfs_iop_permission()` when `mask & MAY_NOT_BLOCK`, and `kernfs_iop_get_link()` when `!dentry`) must return `-ECHILD` or `ERR_PTR(-ECHILD)` before acquiring `kernfs_rwsem`, `kernfs_iattr_rwsem`, or allocating with `GFP_KERNEL`. [F110]

## Error Handling

- `kernfs_get_inode()` returns `NULL` (never an `ERR_PTR`) on allocation failure, so callers must test `!inode` rather than `IS_ERR(inode)` and convert `NULL` to `ERR_PTR(-ENOMEM)` before passing it to `d_splice_alias()`, which treats a `NULL` inode as a negative dentry rather than an error. [F39]
- Internal node allocators `__kernfs_new_node()` and `kernfs_new_node()` return `NULL` on failure, whereas public creation APIs (`kernfs_create_root()`, `kernfs_create_dir_ns()`, `kernfs_create_empty_dir()`, `__kernfs_create_file()`, `kernfs_create_link()`) convert `!kn` to `ERR_PTR(-ENOMEM)` and return `ERR_PTR(-errno)`. [F40]
- In `kernfs_file_read_iter()` and `kernfs_fop_write_iter()`, the byte count variable `len` that receives the return value of `ops->read()` or `ops->write()` must have signed type `ssize_t` so negative error codes are not misinterpreted as positive byte counts when updating `iocb->ki_pos`. [F41]
- Functions that accept a nullable `struct kernfs_node *kn` (`kernfs_remove()`, `__kernfs_remove()`, `kernfs_get()`, `kernfs_put()`, `kernfs_get_active()`, `kernfs_put_active()`, `kernfs_name()`, `kernfs_path_from_node()`) must check `!kn` before calling `kernfs_root(kn)` (including inside `lockdep_assert_held*()`). [F44]

## External Contracts

- In `kernfs_iop_lookup()`, `kernfs_set_rev(parent, dentry)` must be called for all non-error lookups (`!IS_ERR(inode)`), including positive dentries, and if `kernfs_find_ns()` finds an existing node that is not active (`!kernfs_active(kn)`), it must return `NULL` immediately without calling `d_splice_alias(NULL, dentry)` so a negative dentry is not cached for a deactivated node. [F50, F132]
- In `kernfs_notify_workfn()`, `FS_MODIFY` events must be generated by looking up target and parent VFS inodes via `ilookup()` and `kernfs_get_parent()` (not dcache aliases); `fsnotify()` with `FS_EVENT_ON_CHILD` and `&name` may only be called when `p_inode` is found, otherwise `fsnotify_inode(inode, FS_MODIFY)` (passing `NULL` for parent and name) must be used. [F53, F133]
- Every public function declared under `#ifdef CONFIG_KERNFS` in `include/linux/kernfs.h` that may be called when `CONFIG_KERNFS` is disabled must have a matching `static inline` stub in the `#else /* CONFIG_KERNFS */` block. [F60]

## Known Pitfalls

- In `kernfs_path_from_node(to, from, buf, buflen)` and `kernfs_path_from_node_locked(kn_to, kn_from, buf, buflen)`, the first parameter is the target node `to` and the second is the base node `from` (or `NULL` for root), opposite to the `@from`, `@to` order in their kernel-doc comments and the `(root_kn, kn)` names in the `!CONFIG_KERNFS` stub. [F51]
