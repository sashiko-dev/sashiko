# NETWORKING [DSA]

The Distributed Switch Architecture (DSA) subsystem (`net/dsa`) manages hardware Ethernet switches attached to a host CPU network interface (the conduit) and exposes switch ports as standard Linux user network devices. It coordinates multi-switch tree topologies, phylink/PHY and devlink integration, modular frame tagging/untagging drivers, and hardware offloading of bridging, VLANs, FDB/MDB tables, LAG, HSR, MRP, and TC actions via switchdev notifiers.

## Architecture & Data Flow

- In `struct dsa_port`, `dp->conduit` and `dp->user` share a union discriminated by `dp->type` (`DSA_PORT_TYPE_CPU` vs `DSA_PORT_TYPE_USER`); user and DSA port code must obtain the conduit via `dsa_port_to_conduit(dp)` (which handles `dp->cpu_port_in_lag` and `dp->cpu_dp`) rather than reading `dp->conduit` or `dp->cpu_dp->conduit`. Similarly, `struct dsa_db` unions `dp`, `lag`, and `bridge`, so `dsa_db_equal()` and `dsa_db_print()` must switch on `db->type` first. [F47, F49]
- In tree-wide and broadcast notifier handlers in `net/dsa/switch.c` (`dsa_switch_bridge_{join,leave}`, `dsa_switch_lag_{change,join,leave}`), `ds->ops->port_*` must only be called with `info->dp->index` when `info->dp->ds == ds`, while `info->dp->ds != ds` must invoke `ds->ops->crosschip_*`. In `dsa_user_add_cls_matchall_mirred()`, `dp->ds == to_dp->ds` must be verified before passing `to_dp->index` to `ds->ops->port_mirror_add`. [F73, F74]
- Because `dst->ports` lists every port in the tree rather than unique switches, per-switch operations must either use `dsa_tree_notify()` (via `dst->nh`) or guard execution with `ds->setup` as in `dsa_switch_setup()` and `dsa_switch_teardown()`. [F121]
- When `dsa_switch_change_tag_proto()` changes a switch's tag protocol, it must update `cpu_dp->rcv` and `cpu_dp->tag_ops` via `dsa_port_set_tag_protocol()` on every CPU port of `ds`, and refresh `p->xmit`, headroom/tailroom, features, and conduit MTU via `dsa_user_setup_tagger()` and `dsa_user_change_mtu()` on every user port of `ds`. `dsa_user_setup_tagger()` must clear `NETIF_F_SG | NETIF_F_FRAGLIST` from `user->features` whenever `user->needed_tailroom > 0`. [F61, F179]
- On switches with `ds->vlan_filtering_is_global`, `dsa_port_vlan_filtering()` must update `ds->vlan_filtering` and call `dsa_user_manage_vlan_filtering()` on every registered user port of `ds` (versus only `dp->vlan_filtering` and `dp->user` when false), and `dsa_port_reset_vlan_filtering()` must not disable VLAN filtering on bridge leave if any port on `ds` remains enslaved to any VLAN-aware bridge (`br && br_vlan_enabled(br)`). [F65, F66]
- When `!dp->ds->fdb_isolation`, `dsa_port_fdb_{add,del}()`, `dsa_port_bridge_host_fdb_{add,del}()`, `dsa_port_lag_fdb_{add,del}()`, `dsa_port_mdb_{add,del}()`, and `dsa_port_bridge_host_mdb_{add,del}()` must force `db.bridge.num = 0`. In `dsa_port_do_vlan_add()` on a shared CPU or DSA port, if `vlan->changed` is true it must return 0 without incrementing `v->refcount` on `dp->vlans`. [F69, F77]
- `struct dsa_lag::id` and the `id` argument to `dsa_lag_by_id(dst, id)` are 1-based (`1 .. dst->lags_len`, `0` unmapped) while `dst->lags` is indexed at `id - 1` (0-based hardware trunk IDs in `dsa_rcv_ll()` must pass `trunk_id + 1`). `dsa_bridge_num_get()` also returns 1-based numbers (`1 .. max - 1`, `0` when `!max` or exhausted), so `dsa_tag_8021q_bridge_vid()` passes `bridge_num` directly to `DSA_8021Q_VBID()` and `dsa_xmit_ll()` uses `dst->last_switch + bridge_num`. [F94, F95]
- In `dsa_8021q_rcv()`, a popped VID not matching `vid_is_dsa_8021q(tmp_vid)` must be restored via `__vlan_hwaccel_put_tag()`, and matching tags must only update `*source_port` and `*switch_id` when `tmp_vbid == 0` and their prior value is `-1`. In `dsa_tag_8021q_find_user()`, checking `(source_port != -1 && switch_id != -1)` must precede `vbid >= 1` and `vid` lookups. [F81, F109]
- Every `DSA_TAG_PROTO_*` enumerator in `enum dsa_tag_protocol` must have a matching `#define DSA_TAG_PROTO_*_VALUE` with the same integer value for `MODULE_ALIAS_DSA_TAG_DRIVER()`. [F85]

## Synchronization

- `dsa2_mutex` nests outside `rtnl_lock()` during switch registration, unregistration, and shutdown. In `dsa_tree_change_tag_proto()` (called from sysfs `tagging_store()`), `rtnl_trylock()` returning `restart_syscall()` on contention must be used instead of `rtnl_lock()` because `dsa_conduit_teardown()` removes the sysfs group under `rtnl_lock()`, and all tree user and conduit netdevices must be verified down (`!(flags & IFF_UP)`) under `rtnl_lock` before changing `tag_ops`. [F29, F166]
- Work items on `dsa_owq` (`dsa_user_switchdev_event_work()` and `dsa_user_standalone_event_work()`) and their callees (`dsa_port_bridge_host_fdb_{add,del}()`) must never acquire `rtnl_lock()` or call helpers that assert `RTNL` (such as `dev_uc_add(conduit, addr)` when `!(conduit->priv_flags & IFF_UNICAST_FLT)`). Non-atomic bitfields on `struct dsa_port` and `struct dsa_switch` must only be modified at probe time or under `rtnl_lock()`, never from `dsa_owq` or softirq. [F27, F171]
- On CPU and DSA ports, `dp->addr_lists_lock` protects `dp->fdbs` and `dp->mdbs` across lookup, `ds->ops->port_{fdb,mdb}_{add,del}`, and list updates (and is required by `dsa_{fdb,mdb}_present_in_other_db()`), while `dp->vlans_lock` protects `dp->vlans`. On user ports, `dp->user_vlans` is serialized by `netif_addr_lock_bh(dev)`: in `dsa_user_{sync,unsync}_ha()` and `dsa_user_vlan_rx_{add,kill}_vid()`, work queued under it must use `GFP_ATOMIC`, and `dsa_flush_workqueue()` must follow `netif_addr_unlock_bh(dev)`. [F24, F162, F163]
- `dsa_user_switchdev_event()` runs under `rcu_read_lock()` (requiring `GFP_ATOMIC` in `dsa_user_fdb_event()`), whereas `dsa_user_switchdev_blocking_event()` does not, so `dsa_port_vlan_filtering()` and `dsa_user_vlan_add()` must acquire `rcu_read_lock()` around RCU upper-device walks (`dsa_port_can_apply_vlan_filtering()` and `dsa_user_vlan_check_for_8021q_uppers()`). [F165]
- In `dsa_conduit_setup()`, `cpu_dp->rcv`, `cpu_dp->tag_ops`, and `cpu_dp->dst` must be initialized and ordered by `wmb()` before assigning `dev->dsa_ptr = cpu_dp`, and `dsa_conduit_teardown()` must clear `dev->dsa_ptr = NULL` before `wmb()`. [F17]

## Object Lifetimes

- Because `dsa_user_xmit()` calls `kfree_skb(skb)` whenever `p->xmit(skb, dev)` returns `NULL`, a tagger `.xmit` callback returning `NULL` must never call helpers that free `skb` on failure (use `__skb_put_padto(..., false)` or `__skb_pad(..., false)` instead of `eth_skb_pad()`) and, when deferring TX as in `sja1105_defer_xmit()`, must allocate work with `GFP_ATOMIC` and call `skb_get(skb)` before queuing. [F1, F169]
- Because `dsa_switch_rcv()` calls `kfree_skb(skb)` when `cpu_dp->rcv(skb, dev)` returns `NULL`, a `.rcv` callback that buffers `skb` and returns `NULL` must call `skb_get(skb)` (under `spin_lock(&priv->meta_lock)` for `priv->stampable_skb` in `sja1105_rcv_meta_state_machine()`), and a `.rcv` callback that returns a previously buffered `skb` in place of the incoming meta `skb` must call `kfree_skb(skb)` on the incoming `skb` itself. [F2, F170]
- When a tagger `.disconnect` callback (`sja1105_disconnect()`, `qca_tag_disconnect()`) frees `ds->tagger_data`, it must clear `ds->tagger_data = NULL` (never `ds->priv`), and `dsa_switch_connect_tag_proto()` must call `tag_ops->disconnect(ds)` if `ds->ops->connect_tag_protocol()` fails. In `dsa_tag_8021q_register()`, `ctx` must be freed if `dsa_tag_8021q_setup(ds)` fails, and `dsa_tag_8021q_unregister()` must unlink and free all `ctx->vlans` entries and set `ds->tag_8021q_ctx = NULL` before `kfree(ctx)`. [F5, F11]
- `dsa_tree_setup()` and `dsa_tree_teardown()` must maintain strict LIFO ordering across `routing_table`, `cpu_ports`, `switches`, `ports`, `conduit`, and `lags` (calling `dsa_tree_teardown_routing_table(dst)` on any setup failure after `dsa_tree_setup_routing_table()`). Within `dsa_tree_{setup,teardown}_ports()`, shared ports (`CPU`/`DSA`) must be set up before non-shared ports (`USER`/`UNUSED`), and non-shared ports must be torn down followed by `dsa_flush_workqueue()` before tearing down shared ports. [F7, F149]
- When unoffloading a bridge port in `dsa_port_pre_bridge_leave()` or on `dsa_port_bridge_join()` error rollback, `switchdev_bridge_port_unoffload()` must be followed by `dsa_flush_workqueue()` before destroying `dp->bridge`. In `dsa_port_bridge_leave()` and `dsa_port_lag_leave()`, `struct dsa_bridge` or `struct dsa_lag` must be copied by value into the notifier info struct and destroyed (`dp->bridge = NULL` / `dp->lag = NULL`) before emitting `DSA_NOTIFIER_BRIDGE_LEAVE` or `DSA_NOTIFIER_LAG_LEAVE`. [F13, F14]
- Every `struct device_node *` reference acquired via `of_parse_phandle()`, `of_get_child_by_name()`, `for_each_available_child_of_node()`, or `of_for_each_phandle()` in `dsa_shared_port_validate_of()`, `dsa_port_setup_routing_table()`, and `dsa_switch_parse_ports_of()` must be released with `of_node_put()` on every return path. [F157]

## API Contracts

- Before calling `dsa_user_to_port()` or `netdev_priv()` on a `struct net_device *` outside `dsa_user_netdev_ops` or `dsa_user_ethtool_ops` callbacks, callers must verify `dsa_user_dev_check(dev)` is true. `dsa_port_from_netdev()` returns `ERR_PTR(-ENODEV)` (not `NULL`) when `netdev` fails `dsa_user_dev_check()`, so callers must check `IS_ERR(dp)`. [F39, F134]
- When `dsa_switch_rcv()` calls `cpu_dp->rcv(skb, dev)`, `skb->data` is `ETH_HLEN` bytes past `skb_mac_header(skb)` (`dsa_etype_header_pos_rx(skb)` is `skb->data - 2`), and `cpu_dp->rcv()` must return with `skb->data` right after the inner Ethernet header; after `eth_type_trans()`, `dsa_switch_rcv()` must pass `skb->len + ETH_HLEN` to `dev_sw_netstats_rx_add()`. In `.rcv` callbacks, `pskb_may_pull(skb, len)` must cover the full header beyond `ETH_HLEN`, and trailer taggers must call `skb_linearize(skb)` before reading `skb_tail_pointer(skb)`. [F87, F180, F184]
- In EtherType-header taggers, `dsa_alloc_etype_header(skb, len)` must only be called after `skb_push(skb, len)` on TX, and `dsa_strip_etype_header(skb, len)` must only be called after `skb_pull(skb, len)` or `skb_pull_rcsum(skb, len)` on RX. In bitmask egress taggers (`rtl4a_tag_xmit`, `rtl8_4_write_tag`, `qca_tag_xmit`, `sja1110_xmit`, `trailer_xmit`, `brcm_tag_xmit_ll`), the destination port must be encoded as `BIT(dp->index)` even when `.rcv` decodes a raw port index. [F58, F86]
- `dsa_routing_port(ds, device)` and `dsa_switch_upstream_port(ds)` return `ds->num_ports` when no route or port exists, whereas `dsa_to_port(ds, p)` returns `NULL` for `p >= ds->num_ports`. `dsa_user_change_mtu()` adds `dsa_tag_protocol_overhead(cpu_dp->tag_ops)` to the conduit MTU, but passes the unadjusted L2 payload MTU (`largest_mtu`, or `old_conduit_mtu - overhead` on rollback) to `dsa_port_mtu_change(cpu_dp, ...)` and `ds->ops->port_change_mtu()`. [F97, F132]

## Error Handling

- `dsa_tag_driver_get_by_{name,id}()` return `ERR_PTR(-ENOPROTOOPT)` rather than `NULL` on failure, so callers like `dsa_port_parse_cpu()` must check `IS_ERR(tag_ops)` and reset `tag_ops = NULL` before falling back or storing into `dst->tag_ops`. [F38]
- `dsa_switch_event()` encodes statuses with `notifier_from_errno(err)` and `dsa_tree_notify()` decodes them via `notifier_to_errno(err)`, so callers must compare against `-EOPNOTSUPP` (not positive `EOPNOTSUPP`). Broadcast notifier handlers (`dsa_switch_tag_8021q_vlan_{add,del}()`, cross-chip `dsa_switch_bridge_join()`) must return `0` rather than `-EOPNOTSUPP` when a switch lacks the optional callback/context, and callers like `dsa_port_set_state_now()` and `dsa_user_changeupper()` must treat `-EOPNOTSUPP` as a non-error or software fallback. [F40, F112, F187]
- When a pointer on `struct dsa_port` is set before a fallible call or torn down—`port->user` in `dsa_user_create()` / `dsa_port_teardown()`, or `dp->hsr_dev` in `dsa_port_hsr_join()`—it must be cleared to `NULL` because callers check `dp->user` for `NULL`. Similarly, `dsa_port_to_bridge_port(dp)` returns `NULL` when `!dp->bridge` (callers must check `brport_dev` before switchdev calls), and software LAG joins leave `dp->lag == NULL` (so `dsa_port_lag_{change,leave}()` and `dsa_user_lag_{pre,}changeupper()` must check `if (!dp->lag)`). [F12, F45, F46, F52]
- When allocating a `struct dsa_mac_addr` in `dsa_port_do_{fdb,mdb}_add()` or `dsa_switch_do_lag_fdb_add()`, `a->db = db` must be initialized so `dsa_mac_addr_find()` matches it via `dsa_db_equal(&a->db, &db)`. When deleting a refcounted entry in `dsa_port_do_{fdb,mdb,vlan,tag_8021q_vlan}_del()` or `dsa_switch_do_lag_fdb_del()`, if `refcount_dec_and_test()` hits zero and the driver callback fails, `refcount_set(&entry->refcount, 1)` must restore the refcount without freeing the entry. [F54, F68]

## Known Pitfalls

- `dsa_8021q_xmit()` takes `u16 tpid` in host byte order and applies `htons(tpid)` internally, whereas `dsa_tag_8021q_register()` takes `__be16 proto` in network byte order and `sja1105_pvid_tag_control_pkt()` converts `sja1105_xmit_tpid(dp)` with `htons()` before comparing with `hdr->h_vlan_proto`. [F107]
- Functions that take a target `struct dsa_port *dp` and also iterate over ports (`dsa_port_reset_vlan_filtering()`, `dsa_port_vlan_filtering()`, `dsa_user_change_mtu()`) must use a distinct loop cursor (`other_dp`). In `dsa_switch_host_fdb_{add,del}()`, the LAG CPU check must test `dsa_port_is_cpu(dp)` on the local port `dp`, test `info->dp->cpu_port_in_lag` on the user port `info->dp`, and pass `dp->lag` (not `info->dp->lag`) to `dsa_switch_do_lag_fdb_{add,del}()`. [F122, F123]
