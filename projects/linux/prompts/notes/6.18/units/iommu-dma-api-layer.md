# IOMMU DMA-API LAYER

This unit provides the I/O Virtual Address (IOVA) allocator (`drivers/iommu/iova.c`) and the glue layer (`drivers/iommu/dma-iommu.c`) connecting the generic Linux DMA mapping API to the IOMMU subsystem. It manages red-black tree IOVA address spaces with per-CPU magazine range caches (`iova_rcache`), deferred IOTLB flush queues (`iova_fq`), SWIOTLB bounce buffering for untrusted or unaligned DMA, scatterlist coalescing, and MSI doorbell page remapping.

## Architecture & Data Flow

- `iovad->anchor` is an embedded rbtree sentinel with `pfn_lo = pfn_hi = IOVA_ANCHOR` (`~0UL`). `free_iova_mem()` must check `iova->pfn_lo != IOVA_ANCHOR` so `put_iova_domain()` does not free the anchor to `iova_cache`, and `alloc_iova_mem()` must use `kmem_cache_zalloc()` so error paths before `pfn_lo` assignment do not see `IOVA_ANCHOR` and leak the node. [F39, F74]
- `remove_iova()` must call `__cached_rbnode_delete_update(iovad, iova)` before `rb_erase(&iova->node, &iovad->rbroot)` so `rb_next()` can advance `cached32_node` and `cached_node` while linked. `__cached_rbnode_delete_update()` must check `free == cached_iova` in addition to `free->pfn_hi < iovad->dma_32bit_pfn`, because prior `rb_next()` updates or anchor state can leave `cached32_node` at `pfn_hi >= dma_32bit_pfn`. [F47, F48]
- In `__alloc_and_insert_iova_range()`, `iovad->max32_alloc_size = size` must only be set after a full rbtree search (including `retry`) fails, never on the early `size >= iovad->max32_alloc_size` fast-fail path. On `retry`, it must check `retry_pfn < limit_pfn` before computing `low_pfn = retry_pfn + 1` (as `retry_pfn` is `IOVA_ANCHOR` at `&iovad->anchor.node`), reset `high_pfn = limit_pfn` and `curr = iova_find_limit(iovad, limit_pfn)`, and pass `prev` (not `curr`) to `iova_insert_rbtree()`. [F49, F83, F98]
- `struct iova` bounds `pfn_lo` and `pfn_hi` are inclusive (`new->pfn_hi = new->pfn_lo + size - 1`). `alloc_iova()` and `alloc_iova_fast()` take an inclusive `limit_pfn` and pass `limit_pfn + 1` to `__alloc_and_insert_iova_range()` and `iova_rcache_get()`. `reserve_iova()` rejects `(pfn_hi | pfn_lo) > (ULLONG_MAX >> iova_shift(iovad))`, and byte-region callers like `iova_reserve_iommu_regions()` must pass `iova_pfn(iovad, start + length - 1)` as `pfn_hi`. [F63, F73]
- `alloc_iova_fast()` must round `size` up to a power of two when `size < (1 << (IOVA_RANGE_CACHE_MAX_SIZE - 1))`, because `iova_rcache_insert()` and `iova_rcache_get()` index `iovad->rcaches` by `order_base_2(size)`. If `alloc_iova()` fails and `flush_rcache` is true, `alloc_iova_fast()` must set `flush_rcache = false` before draining per-CPU and global rcaches and jumping to `retry`. [F65, F85]
- `struct iova_magazine` overlays `size` and `next` in an anonymous union and only full magazines enter `rcache->depot`: `iova_depot_pop()` must reset `mag->size = IOVA_MAG_SIZE` after `rcache->depot = mag->next`, and `iova_magazine_free_pfns()` must reset `mag->size = 0`. `iova_magazine_pop()` requires `!iova_magazine_empty(mag)` and must check `if (i == 0) return 0;` in the loop body before `i--` wraps `i` to `-1`. [F50, F86]
- `iommu_dma_map_sg()` must call `iommu_dma_sync_sg_for_device()` before mutating `s->offset` and `s->length`. `PCI_P2PDMA_MAP_BUS_ADDR` segments must be marked via `sg_dma_mark_bus_address(s)` and `continue` without touching `s->offset`, `s->length`, `iova_len`, or `prev`. `__finalise_sg()` and `__invalidate_sg()` must unmark bus-address segments without modifying `s->offset`, and restore normal segments via `s->offset += sg_dma_address(s)` (not `=`). [F52, F89]
- In `__finalise_sg()`, each iteration must read stashed fields from `s` and reset `sg_dma_address(s) = DMA_MAPPING_ERROR` and `sg_dma_len(s) = 0` before writing to `cur` (avoiding clobbering when `cur == s`), advance `dma_addr` by `s_iova_len` (not `s_length`), and reset `cur_len = 0` whenever `s_length + s_iova_off < s_iova_len`. [F90]
- When `iommu_dma_map_sg()` bounces via `iommu_dma_map_sg_swiotlb()`, `sg_dma_mark_swiotlb(sg)` marks the list so `iommu_dma_unmap_sg()`, `iommu_dma_sync_sg_for_cpu()`, and `iommu_dma_sync_sg_for_device()` branch on `sg_dma_is_swiotlb()`. For non-SWIOTLB lists in `iommu_dma_unmap_sg()`, after the first loop finds `start` and breaks, `nents` must be decremented by `i` (`nents -= i`), the second loop must start at `tmp` (not `sg_next(tmp)`), and `__iommu_dma_unmap()` runs only if `end` is non-zero. [F54, F91]
- On map (`iommu_dma_map_phys()`, `iommu_dma_map_sg()`, `iommu_dma_iova_bounce_and_link()`), SWIOTLB bounce mapping must precede `arch_sync_dma_for_device()` / `iommu_dma_sync_sg_for_device()`, which must precede `__iommu_dma_map()` / `iommu_map_nosync()`. On unmap (`iommu_dma_unmap_phys()`, `__iommu_dma_iova_unlink()` via `iommu_dma_iova_unlink_range_slow()`), `iommu_iova_to_phys()` and `arch_sync_dma_for_cpu()` must precede `__iommu_dma_unmap()` / `iommu_unmap_fast()`, and `swiotlb_tbl_unmap_single()` must follow `arch_sync_dma_for_cpu()`. [F137, F139]
- For granule-unaligned buffers (`iova_unaligned(iovad, phys, size)`) on untrusted PCI devices (`dev_is_untrusted(dev)`), `iommu_dma_map_phys()` and `dma_iova_link()` must reject `DMA_ATTR_MMIO` and bounce via `iommu_dma_map_swiotlb()`, which zeroes pre- and post-padding up to `iovad->granule`. In `iommu_dma_iova_unlink_range_slow()`, the first step must cap at `min_t(size_t, end - addr, iovad->granule - iova_start_pad)` and reset `iova_start_pad = 0` after each iteration. [F70, F93]
- Functions handling both managed DMA domains and unmanaged MSI-only domains (`iommu_dma_alloc_iova()`, `iommu_dma_free_iova()`, `cookie_msi_granule()`, `cookie_msi_pages()`) must check `domain->cookie_type` (`IOMMU_COOKIE_DMA_IOVA` vs `IOMMU_COOKIE_DMA_MSI`) before accessing `domain->iova_cookie->iovad` or `domain->msi_cookie`. In `cookie_msi_granule()` and `cookie_msi_pages()`, `default:` must call `BUG()`, not `unreachable()`. [F32, F77]
- In `iommu_dma_init_domain()`, `base_pfn` starts at `1` and is clamped to `>= domain->geometry.aperture_start >> order` so `iovad->start_pfn` is never `0`. If `iovad->start_pfn != 0`, it must verify `1UL << order == iovad->granule` and `base_pfn == iovad->start_pfn` (returning `-EFAULT` on mismatch). If `domain->type == IOMMU_DOMAIN_DMA_FQ` and `!device_iommu_capable(dev, IOMMU_CAP_DEFERRED_FLUSH)` or `iommu_dma_init_fq(domain)` fails, downgrade `domain->type` to `IOMMU_DOMAIN_DMA`; if `iommu_dma_init_domain()` fails in `iommu_setup_dma_ops()`, reset `dev->dma_iommu = false`. [F59, F61, F118]
- `struct iova_fq` ends with flexible array `entries[]` of power-of-two length `cookie->options.fq_size` (`fq->mod_mask = fq_size - 1`), allocated via `struct_size(queue, entries, fq_size)`. `single_fq` (`vmalloc`) and `percpu_fq` (`__alloc_percpu`) share an anonymous union discriminated by `cookie->options.qt == IOMMU_DMA_OPTS_SINGLE_QUEUE`. In `queue_iova()`, if `fq_full(fq)` holds after `fq_ring_free_locked()`, call `fq_flush_iotlb(cookie)` and `fq_ring_free_locked(cookie, fq)` again before `fq_ring_add(fq)`. [F68, F87, F106, F107]

## Synchronization

- In `iommu_dma_init_fq()`, counters, queues, and `fq_timer` must be initialized and ordered by `smp_wmb()` before `WRITE_ONCE(cookie->fq_domain, domain)`. Unmap paths (`__iommu_dma_unmap()`, `__iommu_dma_iova_unlink()`) must snapshot `READ_ONCE(cookie->fq_domain)` into `iotlb_gather.queued`, and `queue_iova()` must execute `smp_mb()` before reading `cookie->options.qt`, `single_fq`/`percpu_fq`, or `fq_flush_start_cnt`. [F16, F17]
- `fq_flush_iotlb()` must increment `fq_flush_start_cnt` before `flush_iotlb_all()` and `fq_flush_finish_cnt` after, while `fq_ring_free_locked()` stops at the first entry with `counter >= atomic64_read(&cookie->fq_flush_finish_cnt)`. `queue_iova()` must check `!atomic_read(&cookie->fq_timer_on)` before `!atomic_xchg(&cookie->fq_timer_on, 1)` to arm `fq_timer`, and `fq_flush_timeout()` must clear `fq_timer_on` to `0` before `fq_flush_iotlb()`. [F18, F19]
- Top-level acquisitions of `iovad->iova_rbtree_lock` (guarding `rbroot`, `cached_node`, `cached32_node`, `max32_alloc_size`), `cpu_rcache->lock`, `rcache->lock`, and `fq->lock` (guarding `fq_full()`, `fq_ring_add()`, `fq_ring_free_locked()`) must use `spin_lock_irqsave()`. Because `__iova_rcache_insert()`, `__iova_rcache_get()`, and `queue_iova()` resolve per-CPU pointers before locking, they must use `raw_cpu_ptr()` instead of `this_cpu_ptr()`. [F21, F23, F131, F132]
- `iova_depot_work_func()` must check `rcache->depot_size > num_online_cpus()` and call `iova_depot_pop(rcache)` under `rcache->lock`, then unlock before `iova_magazine_free_pfns()`, `iova_magazine_free()`, and `schedule_delayed_work()`. Internal allocations in atomic DMA map/rcache paths (`alloc_iova_mem()`, `iova_magazine_alloc()`, `iommu_map*`) must use `GFP_ATOMIC`, and `iommu_dma_sw_msi()` / `iommu_dma_get_msi_page()` require the device's `iommu_group` mutex. [F22, F25, F128]

## Object Lifetimes

- In `fq_ring_free_locked()`, `fq->entries[idx].freelist` must be re-initialized with `IOMMU_PAGES_LIST_INIT()` immediately after `iommu_put_pages_list()`, because `iommu_put_pages_list()` frees pages without unlinking their list nodes. In `__iommu_dma_iova_unlink()`, `iotlb_gather.queued` may only be enabled when `free_iova` is true (`free_iova && READ_ONCE(cookie->fq_domain)`). [F1, F12]
- `iommu_put_dma_cookie()` must check `cookie->iovad.granule` before calling `iommu_dma_free_fq(cookie)` and `put_iova_domain(&cookie->iovad)` (since `cookie` is lazily initialized). `iommu_dma_free_fq()` must call `timer_delete_sync(&cookie->fq_timer)` before freeing `single_fq`/`percpu_fq`, and must finish before `put_iova_domain()`. [F2, F20]
- `iova_domain_init_rcaches()` must initialize all rcaches, `rcache->work`, and per-CPU magazines before registering `iovad->cpuhp_dead`. In `put_iova_domain()`, `free_iova_rcaches()` must remove `cpuhp_dead` and `cancel_delayed_work_sync(&rcache->work)` before freeing magazines and `iovad->rbroot`. Cached `struct iova` nodes remain in `iovad->rbroot` until drained by `iova_magazine_free_pfns()` or freed by `put_iova_domain()`. [F13, F26]
- Every `struct iommu_dma_msi_page` on `cookie->msi_page_list` must be individually heap-allocated because cookie teardown calls `kfree()` on each entry. In `iova_reserve_iommu_regions()`, `resv_regions` must be released via `iommu_put_resv_regions(dev, &resv_regions)` on all return paths. [F4, F120]

## API Contracts

- `iommu_dma_alloc_noncontiguous()` returns `&sh->sgt` embedded in `struct dma_sgt_handle` with `sh->pages` populated so noncontiguous vmap/mmap/free helpers can recover `sh` via `sgt_handle(sgt)`. `iommu_dma_free_noncontiguous()` must unmap `sgt->sgl->dma_address` before `sg_free_table(&sh->sgt)`, free `sh->pages`, and `kfree(sh)`. [F5, F60]
- `dma_iova_try_alloc()` must zero `*state` before any early return, check `use_dma_iommu(dev)` before dereferencing `domain->iova_cookie`, and reject `size == 0` or sizes with bit 63 (`DMA_IOVA_USE_SWIOTLB`) set; callers must read the size via `dma_iova_size(state)`. `dma_iova_free()` only frees the IOVA range, so linked ranges must be unlinked via `dma_iova_unlink()` first (or `dma_iova_destroy()` used). In `dma_iova_link()`, `iova_offset(iovad, phys) != 0` is only valid when `offset == 0`. [F10, F35, F44, F45]
- `init_iova_domain()` requires a power-of-two byte `granule <= PAGE_SIZE`, whereas `start_pfn` and all `size`, `pfn`, and `limit_pfn` arguments to `alloc_iova*()`, `free_iova*()`, `find_iova()`, and `reserve_iova()` are in `iovad->granule` PFNs. Before `iommu_dma_alloc_iova()` or `iommu_dma_free_iova()` shifts a byte `size` by `iova_shift(iovad)`, callers must add `iova_offset(iovad, addr)` and align with `iova_align(iovad, size + iova_off)`. [F62, F102, F142]
- When `attrs & DMA_ATTR_MMIO` is set in `iommu_dma_map_phys()`, `iommu_dma_unmap_phys()`, or `dma_iova_link()`, skip CPU cache sync and SWIOTLB bouncing, and reject unaligned buffers requiring SWIOTLB. `iommu_dma_alloc()` may only call `iommu_dma_alloc_remap()` when `gfpflags_allow_blocking(gfp)`, and when `!gfpflags_allow_blocking(gfp) && !coherent` (with `CONFIG_DMA_DIRECT_REMAP`), it must use `dma_alloc_from_pool()`. [F127, F129]

## Error Handling

- In `__iommu_dma_alloc_noncontiguous()`, errors must unwind `__iommu_dma_alloc_pages()`, `iommu_dma_alloc_iova()`, `sg_alloc_table_from_pages()`, and `iommu_map_sg()` in reverse order. Callers of `iommu_map_sg()` (`__iommu_dma_alloc_noncontiguous()`, `iommu_dma_map_sg()`) must store the return value in a signed `ssize_t` and check `ret < 0` before comparing against unsigned `size` or `iova_len`. [F6, F28]
- In `iommu_dma_map_sg()`, any error after the `for_each_sg` loop begins must jump to `out_restore_sg` (or `out_free_iova`) to call `__invalidate_sg(sg, nents)`. In `iommu_dma_map_sg_swiotlb()`, if `iommu_dma_map_phys()` fails on segment `i`, `out_unmap` must pass `i` (not `nents`) and `attrs | DMA_ATTR_SKIP_CPU_SYNC` to `iommu_dma_unmap_sg_swiotlb()`. [F9, F92]
- In `iommu_dma_iova_link_swiotlb()`, once the leading bounce segment is linked (`mapped += bounce_len`, `state->__size |= DMA_IOVA_USE_SWIOTLB`), any failure in middle or tail mapping steps must jump to `out_unmap` to call `dma_iova_unlink(dev, state, 0, mapped, dir, attrs)`. [F11]
- `iommu_dma_alloc_iova()` returns `0` on failure (check `!iova`), whereas `iommu_dma_map_swiotlb()` returns `(phys_addr_t)DMA_MAPPING_ERROR` (check `phys == (phys_addr_t)DMA_MAPPING_ERROR`, not `!phys`). When `iommu_deferred_attach_enabled` is true, mapping entry points must call `iommu_deferred_attach()` and abort only on non-zero return. [F29, F30, F31, F124]

## External Contracts

- In `iommu_dma_mmap()` and `iommu_dma_mmap_noncontiguous()`, VMA bounds must be validated with `(vma->vm_pgoff >= count || vma_pages(vma) > count - vma->vm_pgoff)` against `count = PAGE_ALIGN(size) >> PAGE_SHIFT` (avoiding addition overflow), returning `-ENXIO` on failure. [F69]
- In `include/linux/iova.h`, declarations and stubs must be guarded by `#if IS_REACHABLE(CONFIG_IOMMU_IOVA)`. `iommu_dma_max_mapping_size()` must return `swiotlb_max_mapping_size(dev)` whenever `dev_is_untrusted(dev)` is true, and `iova_reserve_pci_windows()` must only be called in `iova_reserve_iommu_regions()` (never in `iommu_dma_get_resv_regions()`). [F141, F144, F145]

## Known Pitfalls

- In `__alloc_and_insert_iova_range()`, the backward walk computes `new_pfn = (high_pfn - size) & align_mask` and must check `high_pfn < size` after the loop for unsigned underflow, and `align_mask` must use `fls_long(size - 1)` rather than `__fls(size - 1)` (undefined at `size == 1`). In `iova_insert_rbtree()`, a non-NULL `start` must be a strict ancestor of the insertion slot (`iova->pfn_lo != to_iova(start)->pfn_lo`) because `new` starts at `&start` on the stack. [F64, F84, F101]
- On 32-bit builds with 64-bit `dma_addr_t`/`phys_addr_t`: cast `unsigned long` PFNs to `dma_addr_t` before left-shifting by `iova_shift(iovad)`; cast `(size - 1)` to `phys_addr_t` before `~` in `iommu_dma_get_msi_page()`; cast `~0` and `DMA_MAPPING_ERROR` to `phys_addr_t` when comparing/assigning `phys_addr_t`; and format `phys_addr_t` with `%pa` by pointer (`&start`). [F94, F95, F96, F112]
- Guard CPU cache sync with `!(attrs & DMA_ATTR_SKIP_CPU_SYNC)` without combining `!` and `== 0`. In `__finalise_sg()`, check segment concatenation limits via subtraction (`max_len - cur_len >= s_length`) to avoid overflow. Compute CPU page counts in DMA helpers as `PAGE_ALIGN(size) >> PAGE_SHIFT`, not `size >> PAGE_SHIFT`. [F75, F97, F103]
