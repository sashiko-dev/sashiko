# EMULEX 10Gbps iSCSI - OneConnect DRIVER

The `be2iscsi` driver implements an open-iSCSI hardware offload initiator for Emulex/Broadcom OneConnect and BladeEngine (BE2, BE3-R, and SkyHawk/BE_GEN4) 10Gbps PCIe adapters, integrating with the Linux SCSI midlayer, `libiscsi`, and `scsi_transport_iscsi` to offload TCP/IP connections and iSCSI PDU/SGL processing via hardware rings (EQ, CQ, MCCQ, WRBQ, and default header/data rings) and MMIO doorbells.

## Architecture & Data Flow
- `iscsi_host_alloc` sets `shost->shost_data` to `struct iscsi_cls_host`, so `struct beiscsi_hba *` must be retrieved via `iscsi_host_priv(shost)`, never `shost_priv(shost)`. Similarly, `cls_session->dd_data` and `cls_conn->dd_data` point to `iscsi_session` and `iscsi_conn` (whose `dd_data` holds `beiscsi_session` and `beiscsi_conn`), whereas `iscsi_endpoint::dd_data` and `iscsi_task::dd_data` point directly to `beiscsi_endpoint` and `beiscsi_io_task`. [F125, F126]
- `phba->cid_to_cri_map` (`BE_GET_CRI_FROM_CID`) and `pasync_ctx->cid_to_async_cri_map` (`BE_GET_ASYNC_CRI_FROM_CID`) are distinct: index controller tables (`wrb_context`, `ep_array`, `conn_table`) with `BE_GET_CRI_FROM_CID(cid)`, and per-ULP `pasync_ctx->async_entry[].wq` with `BE_GET_ASYNC_CRI_FROM_CID(cid)`. [F58]
- In `struct hwi_wrb_context`, `pwrb_handle_base` is mutated as a circular alloc/free ring by `beiscsi_get_wrb_handle` and `beiscsi_put_wrb_handle`, whereas `pwrb_handle_basestd` must remain an unmodified lookup array indexed by `wrb_index` for `hwi_complete_cmd` and `hwi_complete_drvr_msgs`. [F59]
- Every WRB submission path (`beiscsi_iotask`, `beiscsi_iotask_v2`, `beiscsi_mtask`, `beiscsi_offload_cxn_v0`, `beiscsi_offload_cxn_v2`) must set the new WRB's `ptr2nextwrb` to its own `wrb_index`, update `pwrb_context->plast_wrb->ptr2nextwrb` to that `wrb_index` if `plast_wrb` is non-NULL, and set `pwrb_context->plast_wrb = pwrb`. [F65]
- Per-ULP entries in `phba->cid_array_info[ulp_num]` and `phwi_context->pasync_ctx[ulp_num]` exist only where `test_bit(ulp_num, &phba->fw_config.ulp_supported)` is set, and per-ULP descriptors in `phba->init_mem` and `phba->mem_req` are separated by `MEM_DESCR_OFFSET` (8) between `BEISCSI_ULP0` and `BEISCSI_ULP1`. Guard all per-ULP accesses (including `BEISCSI_ULP_AVLBL_CID`) with `ulp_supported`. [F49, F68]
- In SGL handle and CID ring pools (`alloc_io_sgl_handle`/`free_io_sgl_handle`, `alloc_mgmt_sgl_handle`/`free_mgmt_sgl_handle`, `beiscsi_get_cid`/`beiscsi_put_cid`), `beiscsi_get_cid` must check `test_bit(cid_from_ulp, &phba->fw_config.ulp_supported)` before indexing `cid_array_info`, allocation must mark the slot empty (`NULL` or `BE_INVALID_CID`), and release must verify the `free_index`/`cid_free` slot is empty before returning the item. After `hba_setup_cid_tbls` populates `cid_array[]` via `cid_alloc++`, it must reset `cid_alloc = 0` and `cid_free = 0`. [F13, F61, F103]
- `task->sc != NULL` discriminates SCSI IO tasks (`alloc_io_sgl_handle`/`free_io_sgl_handle`, `scsi_dma_map`/`scsi_dma_unmap` guarded by `io_task->num_sg` and `io_task->scsi_cmnd`) from management tasks (`task->sc == NULL`, `alloc_mgmt_sgl_handle`/`free_mgmt_sgl_handle`, `dma_map_single` only when `task->data_count != 0` and guarded by `io_task->mtask_addr`). [F45, F164]
- In `struct be_ctrl_info`, `mcc_tag[MAX_MCC_CMD]` is indexed 0-based (`0 .. MAX_MCC_CMD - 1`) via `mcc_alloc_index`/`mcc_free_index`, whereas the stored tag values are 1-based (`1 .. MAX_MCC_CMD`) and directly index `mcc_wait`, `mcc_tag_status`, and `ptag_state` (sized `MAX_MCC_CMD + 1`). [F79]
- In `struct hwi_context_memory`, `be_eq[MAX_CPUS]` has one more slot than `be_cq[MAX_CPUS - 1]`: indices `0 .. phba->num_cpus - 1` pair `be_eq[i]` with `be_cq[i]` for I/O, while `be_eq[phba->num_cpus]` is the dedicated MCC EQ with no `be_cq` entry or `iopoll`. Broken by: looping `be_cq[i]` or `be_eq[i].iopoll` up to `i <= phba->num_cpus`. [F82]
- Error detection sets bits in `BEISCSI_HBA_IN_ERR` without clearing `BEISCSI_HBA_ONLINE`, so operational guards must check `beiscsi_hba_is_online(phba)` rather than only `test_bit(BEISCSI_HBA_ONLINE, &phba->state)`. Also, `phba->state`, `phba->fw_config.ulp_supported`, and `ctrl->ptag_state[tag].tag_state` are passed to bitops (sometimes via `(void *)` casts) and must remain `unsigned long`. [F95, F130]
- Callers of `adapter_get_sol_cqe` (such as `hwi_complete_cmd`) must zero-initialize `struct common_sol_cqe` beforehand because on SkyHawk (`!is_chip_be2_be3r(phba)`), it writes only `i_sts` or `i_resp` depending on `cmd_cmpl` and updates `i_flags` with `|=`. [F48]

## Synchronization
- Every MCC command submission must hold `ctrl->mbox_lock` while calling `alloc_mcc_wrb`, populating the WRB, and calling `be_mcc_notify`, and release `ctrl->mbox_lock` before `beiscsi_mccq_compl_wait`. `ctrl->mcc_lock` nests inside `ctrl->mbox_lock` and must be held in `alloc_mcc_wrb` and `free_mcc_wrb` when accessing `mcc_obj.q.head`, `mcc_obj.q.used`, `mcc_tag`, `mcc_alloc_index`, `mcc_free_index`, or `mcc_tag_available`. [F21, F156]
- In `be_mcc_notify`, `MCC_TAG_STATE_RUNNING` must be set and `wmb()` executed after populating the MCC WRB and before writing `DB_MCCQ_OFFSET`. For async MCC commands, `MCC_TAG_STATE_ASYNC`, `ctrl->ptag_state[tag].cbfn`, and `tag_mem_state` (or `phba->boot_struct.tag`) must be initialized before `be_mcc_notify`. [F22, F161]
- When `beiscsi_mccq_compl_wait` times out (`rc <= 0`), it must set `ptag_state[tag].tag_mem_state`, execute `wmb()` before setting `MCC_TAG_STATE_TIMEOUT`, and return `-EBUSY` without freeing the tag; callers must not free `nonemb_cmd` on `-EBUSY`. When `beiscsi_mccq_compl_wait` wakes while `!test_bit(BEISCSI_HBA_ONLINE, &phba->state)`, it clears `MCC_TAG_STATE_RUNNING` and returns `-EIO` without saving `mbx_cmd_mem` into `tag_mem_state` (leaving the caller to free it), and `be_mcc_queues_destroy` must wait for `MCC_TAG_STATE_RUNNING` to clear after waking `mcc_wait[tag]`. [F2, F23, F159]
- `session->back_lock` must be held via `spin_lock_bh` when reading `pwrb_handle->pio_handle` and completing or cleaning up tasks in `hwi_complete_cmd`, `hwi_complete_drvr_msgs`, `beiscsi_hdl_fwd_pdu`, and `beiscsi_offload_connection`. Unsolicited PDU CQE processing (`beiscsi_hdq_process_compl`) must hold `spin_lock_bh(&phba->async_pdu_lock)`, which nests outside `session->back_lock` in `beiscsi_hdl_fwd_pdu`. [F26, F27]
- Pool spinlocks `phba->io_sgl_lock`, `phba->mgmt_sgl_lock`, and `pwrb_context->wrb_lock` must be acquired with `spin_lock_irqsave` to protect their handle arrays/indices, and nest inside `session->frwd_lock` and `session->back_lock`. `beiscsi_alloc_pdu` (called under session lock) and the `frwd_lock`/`back_lock` sections in `beiscsi_eh_device_reset` and `beiscsi_eh_abort` must use `GFP_ATOMIC` and never call sleeping functions (`beiscsi_mgmt_invalidate_icds`, `iscsi_eh_device_reset`). [F28, F150, F151]
- In `beiscsi_eh_abort` and `beiscsi_eh_device_reset`, `session->back_lock` must be held while checking `task->sc`, pinning the task with `iscsi_get_task`, setting the WRB `invld` bit, and reading `io_task->psgl_handle->sgl_index`; the task reference must be held across `beiscsi_mgmt_invalidate_icds` after dropping `session->back_lock`. [F25]
- Because `iscsi_session_failure` requires process context, atomic/timer error paths such as `beiscsi_hw_health_check` must schedule `phba->sess_work` (`beiscsi_sess_work`) rather than calling `iscsi_host_for_each_session(phba->shost, beiscsi_session_fail)` directly. [F175]
- In `beiscsi_flush_cq`, each EQ's iopoll must be disabled via `irq_poll_disable(&pbe_eq->iopoll)` before calling `beiscsi_process_cq` from process context and re-enabled via `irq_poll_enable` afterward. In `be_iopoll`, when `beiscsi_process_cq` returns fewer than `budget` entries, `irq_poll_complete(iop)` must be called before re-arming the EQ interrupt via `hwi_ring_eq_db(..., 1, 1)`. [F35, F37]

## Object Lifetimes
- When `beiscsi_exec_nemb_cmd` is called with a non-NULL `cbfn`, a `0` return transfers ownership of `nonemb_cmd` to `phba->ctrl.ptag_state[tag].tag_mem_state` for `cbfn` to free via `dma_free_coherent`, so callers (like `beiscsi_modify_eq_delay`) must only call `beiscsi_free_nemb_cmd` when `beiscsi_exec_nemb_cmd` returns non-zero. [F3]
- During `ISCSI_OP_LOGIN`, `beiscsi_alloc_pdu` caches `plogin_sgl_handle` and `plogin_wrb_handle` on `beiscsi_conn` and sets `login_in_progress = 1` for reuse; `beiscsi_cleanup_task` must not call `beiscsi_free_mgmt_task_handles` while `login_in_progress` is set. In `beiscsi_free_ep` and `beiscsi_ep_disconnect`, return `ep_cid` via `beiscsi_put_cid`, NULL out `phba->ep_array[cri_index]`, `beiscsi_ep->phba`, `beiscsi_ep->conn`, and `phba->conn_table[cri_index]`, and if `login_in_progress` is set (as in `beiscsi_offload_connection`), free login handles and clear `login_in_progress`. [F10, F62]
- In `be_complete_io`, `beiscsi_cleanup_task`, and `beiscsi_free_mgmt_task_handles`, every released task resource (`io_task->cmd_bhs`, `task->hdr`, `io_task->pwrb_handle`, `io_task->psgl_handle`, `io_task->scsi_cmnd`, `io_task->mtask_addr`) must be cleared to `NULL` or `0` immediately upon release. [F12]
- Because firmware does not generate a CQE for `BE_TGT_CTX_UPDT_CMD` (`CONTEXT_UPDATE`), `beiscsi_offload_connection` must immediately return the `pwrb_handle` from `alloc_wrb_handle` to `pwrb_context` via `beiscsi_put_wrb_handle` after ringing the doorbell without zeroing `pwrb_handle->pwrb`. [F14]
- `be_ctrl_init` allocates `sizeof(struct be_mcc_mailbox) + 16` bytes in `ctrl.mbox_mem_alloced` and stores 16-byte `PTR_ALIGN`-ed pointers in `ctrl.mbox_mem`; BMBX commands must use `ctrl.mbox_mem` while `dma_free_coherent` must always use `ctrl.mbox_mem_alloced`. [F51]
- In `beiscsi_remove`, call `iscsi_host_remove(shost, false)` and stop `hw_check`, `recover_port`, and `sess_work` before `beiscsi_disable_port`, and call `iscsi_boot_destroy_kset` and `destroy_workqueue(phba->wq)` only after `beiscsi_disable_port`. [F137, F166]
- `beiscsi_disable_port` must atomically test and clear `BEISCSI_HBA_ONLINE`, disable/free IRQs, disable `irq_poll` on all EQs, and cancel `eqd_update`, `boot_work`, and (on recovery) `mcc_work` before `hwi_cleanup_port` and `beiscsi_cleanup_port`, while keeping `phba->init_mem`, `phba->phwi_ctrlr`, `phba->wq`, and `ctrl->mbox_mem_alloced` intact across recovery until `beiscsi_remove`. [F34, F139]

## API Contracts
- `be_mbox_notify` and its BMBX wrappers return `0` on success, negative errno on doorbell poll failure, and positive 16-bit firmware `compl_status` on command failure, so callers must check `status != 0` rather than `status < 0`. [F41]
- Because `be_wrb_hdr_prepare`, `ADAPTER_SET_WRB_TYPE`, and `AMAP_SET_BITS` update bitfields via bitwise OR/masking without clearing other fields, callers reusing `wrb_from_mbox(&ctrl->mbox_mem)`, SGE arrays, or stack `struct beiscsi_offload_params` must `memset` the target structure to `0` first. [F50]
- Non-embedded `struct be_dma_mem` allocations (`beiscsi_boot_get_sinfo`, `beiscsi_if_get_gw`, `beiscsi_mgmt_invalidate_icds`) must size `dma_alloc_coherent` and `nonemb_cmd->size` to cover the full in-place response struct/union rather than `sizeof(nonemb_cmd->size)` or `sizeof(*req)`. [F116]
- `be_cmd_hdr_prepare` subtracts `sizeof(struct be_cmd_req_hdr)` from `cmd_len`, while `be_cmd_resp_hdr` reports `response_length` and `actual_resp_len` excluding the header, so `beiscsi_if_get_info` (which transfers ownership of `kzalloc`-ed `*if_info` to the caller on `0` return) and `beiscsi_bsg_request` must add the header size when reallocating or copying. [F4, F119]
- In `be_cmd_create_default_pdu_queue`, `length` must be the ring byte size (`num_entries * sizeof(struct phys_addr)`) while `entry_size` is the buffer size (`defpdu_hdr_sz` or `defpdu_data_sz`). In `beiscsi_hdq_post_handles`, `pasync_sge[pi].hi` stores the lower 32 DMA address bits and `pasync_sge[pi].lo` stores the upper 32 bits, and `beiscsi_hdq_process_compl` must pass `nbuf` as `8 * consumed`. [F54, F55]
- Because `beiscsi_alloc_pdu` overwrites `io_task->cmd_bhs->iscsi_hdr.itt` with `((wrb_index << 16) | sgl_index)` and saves `task->itt` in `io_task->libiscsi_itt`, any path completing a task-backed PDU via `__iscsi_complete_pdu` must restore `hdr->itt = io_task->libiscsi_itt` under `session->back_lock`. [F171]

## Error Handling
- In `beiscsi_process_mcc_compl`, `MCC_TAG_STATE_TIMEOUT` must be checked before writing `ctrl->mcc_tag_status[tag]`, and `MCC_TAG_STATE_TIMEOUT`, `MCC_TAG_STATE_ASYNC`, and `MCC_TAG_STATE_IGNORE` must each call `free_mcc_wrb(ctrl, tag)` and return before `wake_up_interruptible(&ctrl->mcc_wait[tag])`. [F96]
- `beiscsi_boot_get_shandle` returns `1` when a boot target is configured and negative errno otherwise, so `beiscsi_dev_probe` must check `ret > 0` before starting boot work and explicitly `return 0;` at the end of probe rather than `return ret;`. [F44]

## Known Pitfalls
- In pseudo-bitfield `struct amap_*` definitions, each `u8` is 1 hardware bit, no field may cross a 32-byte (`u32` dword) boundary in `offsetof`, and backing byte arrays must use `sizeof(struct amap_*) / 8`. When indexing `u32 dw[]` directly with `offsetof(struct amap_*, field)` (as in `beiscsi_process_cq` and `beiscsi_offload_cxn_v0`), divide by 32 (`offsetof(...) / 32`). [F86, F124]
- `AMAP_SET_BITS` and `AMAP_GET_BITS` operate on host-endian `u32` dwords, so populate outgoing contexts/WRBs before `be_dws_cpu_to_le`/`swap_dws` (with a positive multiple-of-4 length) and call `be_dws_le_to_cpu` on incoming CQEs before `AMAP_GET_BITS`—except `struct pdu_base` in `beiscsi_hdl_gather_pdu`, which is not DWORD-swapped and reconstructs the 24-bit DataSegmentLength as `(data_len_hi << 16) | be16_to_cpu(data_len_lo)`. [F87, F114]
- `be_fill_queue` zeroes the entire `struct be_queue_info` (including its embedded `dma_mem`), so callers (`beiscsi_create_eqs`, `beiscsi_create_cqs`, `beiscsi_create_def_hdr`, `beiscsi_create_def_data`) must assign `mem->dma` after `be_fill_queue` returns. Conversely, `be_cmd_iscsi_post_sgl_pages` mutates `q_mem->dma` in place across its batching loop, so `beiscsi_post_pages` must pass a temporary `struct be_dma_mem` copy rather than a persistent descriptor. [F57, F70]
- In `beiscsi_process_cq`, every CQE iteration (unless aborting on `beiscsi_hba_in_error(phba)`) must reach `proc_next_cqe` to clear the `valid` bit on `sol`, advance `cq` via `queue_tail_inc(cq)`, and increment `num_processed` before `hwi_ring_cq_db`. Broken by: using `continue` or returning early inside the loop instead of `goto proc_next_cqe`. [F104]
- Because `beiscsi_mtask` sets WRB type `INI_RD_CMD` (`HWH_TYPE_IO_RD`, 5) for `ISCSI_OP_NOOP_OUT` and `2` (`INI_TMF_CMD`/`HWH_TYPE_LOGOUT`) for both `ISCSI_OP_SCSI_TMFUNC` and `ISCSI_OP_LOGOUT`, `hwi_complete_cmd` must check `task->hdr->opcode & ISCSI_OPCODE_MASK` inside those `wrb_type` cases. [F97]
- Iterating `pasync_ctx->async_entry[cri].wq.list` to unlink handles via `beiscsi_hdl_put_handle` must use `list_for_each_entry_safe`, and `beiscsi_hdl_fwd_pdu` must capture `plast_handle = pasync_handle` inside `list_for_each_entry` rather than dereferencing the loop cursor after termination. [F101]
- `beiscsi_hba_alloc` must never set `shost->dma_boundary` to `pcidev->dma_mask` or `DMA_BIT_MASK(64)`. [F167]
