# NETWORKING [MPTCP]

Implements Multipath TCP (MPTCP v1, RFC 8684) for IPv4 and IPv6 in the Linux networking stack, multiplexing a user-facing `struct mptcp_sock` across underlying TCP subflow sockets via TCP Upper Layer Protocol (ULP) hooks. It manages MPTCP option parsing/generation, SHA-256/HMAC-SHA256 handshakes, connection token hashing, SYN-cookie MP_JOIN state, data sequence mapping and retransmission, pluggable packet schedulers, socket option/diag synchronization, and in-kernel and userspace Path Managers (PM).

## Architecture & Data Flow

- Because a closed initial subflow (`msk->first`) stays on `msk->conn_list` until `mptcp_destroy()`, `mptcp_close_ssk()` must guard one-shot close accounting with `subflow->close_event_done`, `mptcp_pm_rm_addr_or_subflow()` must skip subflows in `TCPF_FIN_WAIT1 | TCPF_FIN_WAIT2 | TCPF_CLOSING | TCPF_CLOSE`, and any `msk->conn_list` walk calling `mptcp_close_ssk()` or `__mptcp_close_ssk()` must use `mptcp_for_each_subflow_safe()`. [F8, F98]
- Because `__mark_subflow_endp_available()` and `mptcp_pm_nl_rm_addr()` do not decrement `msk->pm.local_addr_used` or `msk->pm.add_addr_accepted` for ID 0, kernel PM subflow creation must not increment `local_addr_used` when `local.addr.id == msk->mpc_endpoint_id` or `add_addr_accepted` when `remote.id == 0`. In `mptcp_pm_create_subflow_or_signal_addr()` and `fill_local_addresses_vec_c_flag()`, `__clear_bit(local.addr.id, msk->pm.id_avail_bitmap)` must run right after `select_local_address()` before any `continue`. [F9, F106]
- `msk->first_pending` must point to the first unsent `mptcp_data_frag` in `msk->rtx_queue` (or `NULL`). `__mptcp_clean_una()` must advance `msk->first_pending` before `dfrag_clear()` when `dfrag == msk->first_pending` during `msk->recovery`, clamp `dfrag->already_sent` up to `delta` (after checking `delta <= dfrag->data_len`) before subtracting `delta` when `delta > dfrag->already_sent`, and `__mptcp_retransmit_pending_data()` must reset `first_pending` and zero `already_sent`. [F62, F85]
- Every path populating a newly attached `SKB_EXT_MPTCP` (`struct mptcp_ext`) must call `memset(mpext, 0, sizeof(*mpext))` first because `mptcp_ext_matches()` uses `memcmp()` across bitfields and padding. `mptcp_skb_ext_copy()` must set `from_ext->frozen = 1` on TX clone, and `mptcp_sendmsg_frag()` must check `mptcp_skb_can_collapse_to()` (`!mpext->frozen`) and set `TCP_SKB_CB(skb)->eor = 1` when collapsing is disallowed. [F122, F160]
- When `get_mapping_status()` installs a new DSS mapping (`subflow->map_valid = 1`), it must reset `subflow->map_csum_len = 0`, set `subflow->map_data_csum = csum_unfold(mpext->csum)`, and delete `SKB_EXT_MPTCP` via `skb_ext_del(skb, SKB_EXT_MPTCP)` once accepted or merged (including pure `DATA_FIN` with `data_len == 1` when `subflow->map_valid` is already set, which returns `MAPPING_OK`). When `mpext->data_fin == 1` with `data_len > 1`, `subflow->map_data_len` stores `data_len - 1`, so `__mptcp_make_csum()` takes `subflow->map_data_len + subflow->map_data_fin`. [F230, F231, F244, F256]
- When subflow data consumption advances `mptcp_subflow_get_map_offset(subflow) >= subflow->map_data_len` in `mptcp_subflow_data_available()` or `mptcp_subflow_discard_data()`, `subflow->map_valid` must be reset to `0` (and `subflow->data_avail = false`), and `mptcp_subflow_discard_data()` must include the `TCPHDR_FIN` byte (`avail_len + fin`) when advancing `tcp_sk(ssk)->copied_seq`. [F232, F262]
- Because `opts->addr` and `opts->ahmac` alias `opts->ext_copy` in `struct mptcp_out_options`, `mptcp_established_options_add_addr()` must stage the address in a local `struct mptcp_addr_info` and only write `opts->addr` (and zero `opts->ahmac` if `drop_other_suboptions`) after confirming `OPTION_MPTCP_ADD_ADDR` fits. [F57]
- `mptcp_token_accept()` replaces `req->token_node` in `bucket->req_chain` with `msk` in `bucket->msk_chain` without modifying `bucket->chain_len`, transferring the `chain_len` decrement to `mptcp_token_destroy(msk)`. Unlinking from `req_chain` or `msk_chain` must use `hlist_nulls_del_init_rcu()` or `__sk_nulls_del_node_init_rcu()`, and inserting/removing `msk` in `msk_chain` must pair with `sock_prot_inuse_add(sock_net(sk), sk->sk_prot, 1/-1)` and reset `msk->token = 0` on destroy. [F172, F221, F257]
- `sockopt_seq_inc()` must preserve `(u32)sk->sk_state << 24u` via `sockopt_seq_reset()`, and any setter calling it must have a handler in `sync_socket_options()`. Syncing `ssk->sk_sndbuf` under `SOCK_SNDBUF_LOCK` must update `mptcp_subflow_ctx(ssk)->cached_sndbuf`; updating `ssk->sk_mark` must call `sk_dst_reset(ssk)` if changed; `ssk->sk_rcvlowat` must stay `0` and `tcp_sk(ssk)->notsent_lowat` `UINT_MAX`; and `sync_socket_options()` must propagate `msk->ca_name` without re-checking `CAP_NET_ADMIN`. [F222, F223, F224, F226, F265, F313]

## Synchronization

- Under a subflow socket lock (`ssk`) or in BH context, never acquire `lock_sock(sk)` on the parent `msk`; hold `mptcp_data_lock(sk)`, check `!sock_owned_by_user(sk)`, and if owned, defer via `msk->cb_flags` for `mptcp_release_cb()`. `mptcp_release_cb()` must splice `msk->join_list` and clear `flags` from `msk->cb_flags` before dropping `sk->sk_lock.slock` to run callbacks or lock `ssk`, then re-acquire `sk->sk_lock.slock`. `mptcp_diag_fill_info()` must call `unlock_sock_fast(sk, slow)` before `mptcp_data_lock(sk)`. [F27, F107, F199]
- PM helpers entered with `msk->pm.lock` held (`mptcp_pm_send_ack()`, `mptcp_pm_rm_addr_or_subflow()`, `mptcp_pm_create_subflow_or_signal_addr()`, `mptcp_pm_nl_add_addr_received()`) must `spin_unlock_bh(&msk->pm.lock)` before locking a subflow socket or connecting/closing a subflow, and re-acquire `msk->pm.lock` before returning. Callers of `mptcp_pm_addr_send_ack()`, `mptcp_pm_remove_addr()`, `mptcp_pm_remove_anno_addr()`, `mptcp_pm_remove_addr_entry()`, and `mptcp_pm_rm_subflow()` must hold `lock_sock(sk)` on `msk`. [F17, F24]
- All lookups, modifications, and removals on `msk->pm.userspace_pm_local_addr_list` (`mptcp_userspace_pm_lookup_addr()`, `mptcp_userspace_pm_lookup_addr_by_id()`, `mptcp_userspace_pm_delete_local_addr()`) must hold `spin_lock_bh(&msk->pm.lock)` continuously across the lookup and modification/unlink. `__mptcp_finish_join()`, `mptcp_finish_join()`, `__mptcp_retrans()`, `mptcp_pm_mp_fail_received()`, and `__mptcp_try_fallback()` must hold `spin_lock_bh(&msk->fallback_lock)` across checking and updating `msk->allow_subflows`, `msk->allow_infinite_fallback`, and `MPTCP_FALLBACK_DONE`. [F21, F25]
- Callers of `mptcp_sendmsg_frag()` holding a BH spinlock (`mptcp_data_lock(sk)` in `__mptcp_subflow_push_pending()` or `msk->fallback_lock` in `__mptcp_retrans()`) must set `info.data_lock_held = true` so `mptcp_alloc_tx_skb()` uses `GFP_ATOMIC`. When `mptcp_try_fallback()` calls `tcp_shutdown(ssk, SEND_SHUTDOWN)` in BH context, it must temporarily override `ssk->sk_allocation = GFP_ATOMIC`. `subflow_ulp_clone()` must pass its `priority` argument to `subflow_create_ctx(newsk, priority)` rather than `GFP_KERNEL`. [F136, F137, F294]
- In `net/mptcp/token.c`, all mutations to `bucket->req_chain`, `bucket->msk_chain`, and `bucket->chain_len` must hold `spin_lock_bh(&bucket->lock)`, and `msk->token` must be initialized with `WRITE_ONCE()` before `__sk_nulls_add_node_rcu()`. Lockless RCU scans in `mptcp_token_exists()`, `mptcp_token_get_sock()`, and `mptcp_token_iter_next()` must check `get_nulls_value(pos) != (token & token_mask)` to restart on mismatch, acquire `refcount_inc_not_zero(&sk->sk_refcnt)` under `rcu_read_lock()`, and revalidate `sock_net(sk)` and `READ_ONCE(msk->token)`. [F186, F187, F188, F189]
- `mptcp_subflow_queue_clean()` must splice out `queue->rskq_accept_head/tail` under `queue->rskq_lock` and call `release_sock(listener_ssk)` before locking each unaccepted child's `msk` (`sk = subflow->conn`) and calling `mptcp_cancel_work(sk)`, then re-lock `listener_ssk` and restore `rskq_accept_head/tail`. In `net/mptcp/sockopt.c`, setsockopt helpers delegating to `sock_setsockopt(sk->sk_socket, ...)` or `ip_setsockopt(sk, ...)` on `msk` must do so before `lock_sock(sk)`, and `getsockopt` subflow loops using `copy_to_user()` must run under `lock_sock(sk)` and call `release_sock(sk)` on `-EFAULT`. [F184, F296, F298]

## Object Lifetimes

- Every `struct mptcp_sock *` returned by `mptcp_userspace_pm_get_sock()` or `mptcp_token_get_sock()` (including in `subflow_token_join_request()` if `mptcp_pm_get_local_id()` fails) carries an incremented refcount that must be released with `sock_put((struct sock *)msk)`. When `subflow_syn_recv_sock()` attaches a passive MP_JOIN child, it must transfer `subflow_req->msk` to `ctx->conn` and clear `subflow_req->msk = NULL` to prevent double-put. [F1, F173, F175]
- `mptcp_close_ssk()` and `__mptcp_close_ssk()` can free `subflow` and `sock_put(ssk)`, so callers must read any needed `subflow`/`ssk` fields beforehand. Freeing `msk->first` must set `WRITE_ONCE(msk->first, NULL)`. In `subflow_ulp_release()`, if `ctx->conn` is non-NULL, `ctx` is freed via `kfree_rcu(ctx, rcu)` only when `ctx->disposable || list_empty(&ctx->node)`; otherwise `MPTCP_WORK_CLOSE_SUBFLOW` is scheduled on `ctx->conn`. `mptcp_subflow_reset()` must hold `sock_hold(sk)` on `sk = subflow->conn` across `tcp_done(ssk)` and `mptcp_schedule_work(sk)`. [F6, F7, F178, F181, F292]
- In `__mptcp_subflow_connect()`, every failure path must call `mptcp_pm_close_subflow(msk)`, and if `mptcp_subflow_create_socket()` succeeded, set `subflow->disposable = 1` (and unlink `subflow->node` + `sock_put(ssk)` if linked) before `sock_release(sf)`. Once grafted via `mptcp_sock_graft(ssk, sk->sk_socket)`, `sf` must be discarded via `iput(SOCK_INODE(sf))`, not `sock_release(sf)`. [F179, F180]
- `mptcp_schedule_work(sk)` calls `sock_hold(sk)` when `schedule_work(&msk->work)` newly queues work, paired with `sock_put(sk)` in `mptcp_worker()` or `__sock_put(sk)` in `mptcp_cancel_work()` when `cancel_work_sync()` returns `true`. When `mptcp_subflow_delegate()` sets `BIT(MPTCP_DELEGATE_SCHEDULED)`, it links `subflow->delegated_node` and calls `sock_hold(ssk)`; only `mptcp_napi_poll()` may dequeue it via `mptcp_subflow_delegated_next()`, clear `MPTCP_DELEGATE_SCHEDULED`, and call `sock_put(ssk)`. [F11, F12]
- Removing `struct mptcp_pm_add_entry` items from `msk->pm.anno_list` must unlink under `msk->pm.lock`, call `sk_stop_timer_sync(sk, &entry->add_timer)` after dropping `msk->pm.lock`, and then `kfree(entry)`. `msk->pm.userspace_pm_local_addr_list` entries are allocated with `sock_kmemdup()` and must be freed with `sock_kfree_s()`. `pernet->endp_list` must be traversed with `list_for_each_entry_rcu()`, and unlinked entries require `synchronize_rcu()` before `__mptcp_pm_release_addr_entry()` (so `mptcp_pm_nl_get_local_id()` in RCU receive context must pass `replace = false` to `mptcp_pm_nl_append_new_local_addr()`). [F18, F41, F131, F138, F146]

## API Contracts

- `mptcp_sk(sk)` is valid only on `IPPROTO_MPTCP` parent sockets and `tcp_sk(sk)` / `mptcp_subflow_ctx(sk)` only on `IPPROTO_TCP` subflow sockets (use `mptcp_sk(mptcp_subflow_ctx(sk)->conn)` from a subflow). Before treating an arbitrary `struct sock *` as a subflow (e.g., in BPF or `mptcp_set_rcvlowat()`), verify `sk_fullsock(sk)`, `sk->sk_protocol == IPPROTO_TCP`, and `sk_is_mptcp(sk)`. Before dereferencing `mptcp_subflow_rsk(req)` in `subflow_syn_recv_sock()` or `subflow_ulp_clone()`, check `tcp_rsk(req)->is_mptcp`. [F51, F126, F275, F276]
- `mptcp_pm_get_local_id()`, `mptcp_pm_nl_get_local_id()`, `mptcp_userspace_pm_get_local_id()`, `mptcp_pm_nl_append_new_local_addr()`, `mptcp_userspace_pm_append_new_local_addr()`, `mptcp_get_subflow_data()`, and `mptcp_get_full_info()` return non-negative values (including `0`) on success and negative `int` on error; callers must store results in a signed `int` and test `< 0`. Callers of `__mptcp_nmpc_sk(msk)` must hold `lock_sock((struct sock *)msk)`, check `IS_ERR(ssk)`, and not call `sock_put(ssk)`. [F40, F185, F201]
- `mptcp_crypto_hmac_sha()` and `subflow_generate_hmac()` write a full `SHA256_DIGEST_SIZE` (32-byte) digest into their `hmac` output buffer, so callers must pass a 32-byte buffer (never the 20-byte `subflow->hmac`). `subflow_generate_hmac(key1, key2, nonce1, nonce2, hmac)` takes the sender's `(key, nonce)` first and receiver's second, serializes nonces with `put_unaligned_be32()`, and extracts `thmac` with `get_unaligned_be64()`. [F47, F215, F248]

## Error Handling

- After `mptcp_alloc_tx_skb()` entails an empty `skb` onto `ssk` in `mptcp_sendmsg_frag()`, any early exit before payload bytes are attached must call `tcp_remove_empty_skb(ssk)`. In `mptcp_incoming_options()`, zero-length packets (`seq == end_seq`) must process `DATA_FIN` and return before `skb_ext_add(skb, SKB_EXT_MPTCP)`, and if `skb_ext_add()` returns `NULL` on a non-empty packet, `mptcp_incoming_options()` must return `false`. `mptcp_get_ext(skb)` is nullable and `get_mapping_status()` must check `mpext && mpext->use_map`. [F15, F35, F162, F210]
- In `mptcp_connect()`, failure after `mptcp_token_new_connect(ssk)` must call `mptcp_token_destroy(msk)` and `mptcp_set_state(sk, TCP_CLOSE)`. In `mptcp_pm_nl_subflow_create_doit()`, if `__mptcp_subflow_connect()` fails after `mptcp_userspace_pm_append_new_local_addr()`, `mptcp_userspace_pm_delete_local_addr(msk, &entry)` must be called under `msk->pm.lock` without overwriting `err`. In `__mptcp_subflow_connect()`, `kernel_connect()` returning `-EINPROGRESS` is success (return `0`). In `subflow_v4_route_req()` / `subflow_v6_route_req()`, if `subflow_check_req()` fails after `route_req()`, call `dst_release(dst)`. [F19, F50, F177, F203]

## Known Pitfalls

- `struct mptcp_addr_info::port` is `__be16`: `mptcp_pm_parse_pm_addr_attr()` and `mptcp_nl_fill_addr()` must convert `MPTCP_PM_ADDR_ATTR_PORT` (`NLA_U16`) with `htons()`/`ntohs()`, whereas `MPTCP_ATTR_SPORT`/`DPORT` use `nla_put_be16()`. In `mptcp_write_options()`, `ptr` is `__be32 *` (4-byte stride), so pointer arithmetic advances in 32-bit words, unlike `const unsigned char *ptr` in `mptcp_parse_option()`. [F84, F123]
- Sequence and window arithmetic: 32-bit TCP/subflow sequences in `validate_mapping()` and `mptcp_subflow_discard_data()` must use `before()` (and check `tp->copied_seq - TCP_SKB_CB(skb)->seq <= skb->len` before subtracting from `skb->len`), 64-bit DSNs in `subflow_check_data_avail()` and `mptcp_subflow_discard_data()` must use `before64()` and clamp `old_ack - ack_seq` against `avail_len` before narrowing to `u32`, and 64-bit window deltas in `mptcp_set_rwin()` and `mptcp_check_allowed_size()` must be clamped with `min_t(u64, ..., U32_MAX)`. [F115, F246, F271, F272]
