# ST LSM6DSx IMU IIO DRIVER

Industrial I/O (IIO) driver for STMicroelectronics LSM6DSx, ISM330, ASM330, and LSM9DS1 6-axis Inertial Measurement Units (accelerometer + gyroscope) over I2C, SPI, and I3C buses. It registers separate IIO devices for accelerometer, gyroscope, and up to three external I2C slave sensors attached to the IMU's embedded sensor hub (LIS2MDL/LIS3MDL magnetometers), supporting direct register reads, motion wakeup threshold events, hardware pattern/tagged FIFO buffering, and software-triggered buffering.

## Architecture & Data Flow

- In `struct st_lsm6dsx_settings`, `channels`, `odr_table`, `samples_to_discard`, and `fs_table` have only 2 elements (`ST_LSM6DSX_ID_GYRO`, `ST_LSM6DSX_ID_ACC`); code handling `ST_LSM6DSX_ID_EXT0..2` must guard on `sensor->id` or substitute `ST_LSM6DSX_ID_ACC` (`ref_sensor`) before indexing them or calling `st_lsm6dsx_check_odr()`. In `st_lsm6dsx_set_odr()`, `st_lsm6dsx_check_odr_dependency()` across `ST_LSM6DSX_ID_ACC..MAX` must skip `i == sensor->id` (not `ref_sensor->id`) and return if another enabled sensor requires a higher ODR. [F6, F44, F58]
- For `ST_LSM6DSX_ID_EXT0..2`, `sensor->ext_info.slv_odr` stores the slave's own ODR (for slave register writes, oneshot delays, and sysfs reads) while `sensor->odr` stores the accelerometer trigger ODR from `st_lsm6dsx_check_odr()`. Updating `IIO_CHAN_INFO_SAMP_FREQ` in `st_lsm6dsx_write_raw()` and `__st_lsm6dsx_shub_write_raw()` in direct mode must only validate and cache the resolved frequency from `st_lsm6dsx_check_odr()` into `sensor->odr` without calling `st_lsm6dsx_set_odr()`. [F30, F31]
- `st_lsm6dsx_sensor_set_enable(sensor, false)` (including after `st_lsm6dsx_read_oneshot()`) must not power down `ST_LSM6DSX_ID_ACC` while `hw->enable_event` is non-zero, and `st_lsm6dsx_write_event_config()` must not disable the sensor while `enable_event` is non-zero or `hw->fifo_mask & BIT(sensor->id)` is set. Delays depending on the accelerometer clock (as in `st_lsm6dsx_shub_wait_complete()`) must check `hw->enable_mask & BIT(ST_LSM6DSX_ID_ACC)` before using `acc_sensor->odr`, falling back to `12500` mHz otherwise. [F34, F100]
- Active hardware FIFO buffering is tracked in `hw->fifo_mask` (committed only after `st_lsm6dsx_update_fifo()` succeeds) separately from `hw->enable_mask` and `hw->suspend_mask`. When `hw->fifo_mask` is non-zero, `st_lsm6dsx_suspend()` must call `st_lsm6dsx_flush_fifo(hw)` (`ST_LSM6DSX_FIFO_BYPASS`), and `st_lsm6dsx_resume()` must call `st_lsm6dsx_resume_fifo(hw)` so `st_lsm6dsx_reset_hw_ts(hw)` resets `ST_LSM6DSX_REG_TS_RESET_ADDR` and refreshes `sensor->ts_ref` (`iio_get_time_ns()`) across all allocated `hw->iio_devs[i]` before entering `ST_LSM6DSX_FIFO_CONT`. [F35, F38, F99]
- In `st_lsm6dsx_update_fifo()`, `st_lsm6dsx_flush_fifo()` must drain the old pattern before `st_lsm6dsx_device_set_enable()` updates `hw->enable_mask`, which must precede `st_lsm6dsx_update_decimators()` recomputing `sensor->sip`, `sensor->decimator`, `hw->ts_sip`, and `hw->sip` for `st_lsm6dsx_update_watermark()`. `st_lsm6dsx_update_watermark()` must return early when `!hw->sip` before dividing `fifo_watermark / hw->sip`. [F36, F67]
- `st_lsm6dsx_update_decimators()` only calls `st_lsm6dsx_get_sip()` and `st_lsm6dsx_get_decimator_val()` for sensors in `hw->enable_mask` (setting `sensor->sip = 0` otherwise); in both helpers, ODR quotients `> 1` must be rounded down via `round_down(..., 2)`. In `st_lsm6dsx_read_fifo()`, each step `sip` must check `*_sip > 0` and `!(sip % sensor->decimator)` before extracting/pushing a sample or decrementing `*_sip`. [F37, F66, F69]
- Pattern FIFO (`st_lsm6dsx_read_fifo()`) scales `fifo_diff` by `ST_LSM6DSX_CHAN_SIZE` (2B) with `th_wl = 3` and rounds `fifo_len` down to a multiple of `pattern_len` (`hw->sip * ST_LSM6DSX_SAMPLE_SIZE`). Tagged FIFO (`st_lsm6dsx_read_tagged_fifo()`) scales `fifo_diff` by `ST_LSM6DSX_TAGGED_SAMPLE_SIZE` (7B) with `th_wl = 1`. Both readers must clamp a zero `pattern_len` (when `!hw->sip`) to `ST_LSM6DSX_SAMPLE_SIZE` or `ST_LSM6DSX_TAGGED_SAMPLE_SIZE` before dividing `fifo_len` or advancing `read_len`. [F51, F68, F76]
- Because `st_lsm6dsx_shub_config_channels()` packs enabled external sensors (`ST_LSM6DSX_ID_EXT0..2`) contiguously into `SLV1..SLV3`, `st_lsm6dsx_push_tagged_data()` must map `ST_LSM6DSX_EXT0_TAG..EXT2_TAG` to the 1st, 2nd, and 3rd enabled external sensor in `hw->enable_mask`, and discard bootstrap samples where `(s16)le16_to_cpu(*(__le16 *)data) >= ST_LSM6DSX_INVALID_SAMPLE` (`0x7ffd`). [F39, F54]
- Before accessing any optional `struct st_lsm6dsx_reg` (`event_settings.enable_reg`, `drdy_mask`, `decimator[]`, `batch[]`, `lir`, `clear_on_read`, `aux_sens`, `emb_func`, `wr_once`, `pwr_table.reg`, `fs_table.reg`), check `reg.addr != 0`. Control/IRQ pin accesses (`reset`, `boot`, `bdu`, `irq_config.hla`, `irq_config.od`) must use `hw->settings` descriptors rather than hardcoded addresses/masks, and FIFO callers must check `fifo_ops.read_fifo` / `fifo_ops.update_fifo` is non-NULL. [F86, F87, F88]
- `hw->iio_devs[ST_LSM6DSX_ID_EXT0..2]` are only populated for detected slaves, so loops over `hw->iio_devs` up to `ST_LSM6DSX_ID_MAX` must check `if (!hw->iio_devs[i])` before `iio_priv()`. Bound `fs_avl` and `odr_avl` loops by `fs_len` and `odr_len` (not `ST_LSM6DSX_FS_LIST_SIZE` / `ST_LSM6DSX_ODR_LIST_SIZE`), and check `id[j].name != NULL` or `i2c_addr[i] != 0` when scanning `st_lsm6dsx_sensor_settings[].id[]` or `st_lsm6dsx_ext_dev_settings.i2c_addr[]`. `enum st_lsm6dsx_hw_id` values must be in `1 .. ST_LSM6DSX_MAX_ID - 1`. [F28, F43, F45, F46]

## Synchronization

- Lock hierarchy is `hw->conf_lock -> hw->fifo_lock -> hw->page_lock`: never acquire `hw->conf_lock` under `hw->fifo_lock`, and never acquire `hw->fifo_lock`, `hw->conf_lock`, or call `st_lsm6dsx_*_locked()` / `st_lsm6dsx_sensor_set_enable()` under `hw->page_lock`. At runtime (after `st_lsm6dsx_init_device()`), all primary-page `hw->regmap` accesses and the entire `st_lsm6dsx_set_page(hw, true)`, register access, and `st_lsm6dsx_set_page(hw, false)` sequence must hold `hw->page_lock`. [F12, F102]
- Updates to FIFO configuration, watermark registers, and shared sensor/FIFO enable state across `st_lsm6dsx_update_fifo()`, `st_lsm6dsx_set_watermark()`, and `st_lsm6dsx_write_event_config()` (`st_lsm6dsx_update_watermark()`, `st_lsm6dsx_update_decimators()`, `__st_lsm6dsx_sensor_set_enable()`) must hold `hw->conf_lock`. [F13]
- All calls to `hw->settings->fifo_ops.read_fifo` must hold `hw->fifo_lock`. `st_lsm6dsx_flush_fifo()` must hold `hw->fifo_lock` continuously across draining the FIFO and calling `st_lsm6dsx_set_fifo_mode(hw, ST_LSM6DSX_FIFO_BYPASS)`, and `st_lsm6dsx_handler_thread()` must loop `do { ... } while (len > 0);` under `hw->fifo_lock`. Both `st_lsm6dsx_handler_thread()` and `st_lsm6dsx_sw_trigger_handler_thread()` must remain threaded (`IRQF_ONESHOT`, `NULL` top-half) because they take mutexes and do sleeping `regmap` I/O. [F14, F96, F103]
- In `st_lsm6dsx_read_raw()`, `st_lsm6dsx_shub_read_raw()`, `st_lsm6dsx_write_raw()`, and `st_lsm6dsx_shub_write_raw()`, `IIO_CHAN_INFO_RAW` reads and all `write_raw` updates must claim direct mode with `iio_device_claim_direct(iio_dev)` (or return `-EBUSY`), and every subsequent normal and error path must call `iio_device_release_direct(iio_dev)`. [F1, F107]

## Object Lifetimes

- Whenever `st_lsm6dsx_set_page(hw, true)` succeeds in `st_lsm6dsx_shub_read_output()`, `st_lsm6dsx_shub_write_reg()`, `st_lsm6dsx_shub_write_reg_with_mask()`, `st_lsm6dsx_shub_master_enable()`, or `st_lsm6dsx_init_shub()`, `st_lsm6dsx_set_page(hw, false)` must be called before unlocking `hw->page_lock` or returning, even on register access failure. [F2]
- In `st_lsm6dsx_probe()`, `st_lsm6dsx_init_regulators()` must enable `"vdd"`/`"vddio"` and `msleep(50)` before `st_lsm6dsx_check_whoami()` or any `hw->regmap` access. `hw->fifo_lock`, `hw->conf_lock`, `hw->page_lock`, `hw->buff`, `hw->settings`, and `hw->iio_devs[ST_LSM6DSX_ID_GYRO..ACC]` must be initialized before `st_lsm6dsx_init_device()` and `st_lsm6dsx_shub_probe()`, and all `hw->iio_devs[]` before `st_lsm6dsx_irq_setup()`, `st_lsm6dsx_fifo_setup()`, `st_lsm6dsx_sw_buffers_setup()`, and `devm_iio_device_register()`. [F4, F18, F81]
- Because bus drivers define no `.remove` callbacks, all allocations and registrations must use `devm_*` bound to `hw->dev`. In `st_lsm6dsx_shub_alloc_iiodev()`, copy the stack `magn_channels` array into a `devm_kzalloc()` buffer before assigning `iio_dev->channels` and point `iio_dev->name` to `sensor->name`. FIFO readers must use the pre-allocated 512B heap buffer `hw->buff` (`ST_LSM6DSX_BUFF_SIZE`), not the stack. [F74, F78, F85]
- When `device_may_wakeup(dev) && sensor->id == ST_LSM6DSX_ID_ACC && hw->enable_event` holds, `st_lsm6dsx_suspend()` must call `enable_irq_wake(hw->irq)` without disabling the sensor or setting `hw->suspend_mask`, paired with `disable_irq_wake(hw->irq)` in `st_lsm6dsx_resume()`. [F8]

## API Contracts

- `st_lsm6dsx_shub_write_with_mask()` shifts `val` by `__ffs(mask)` internally and requires an unshifted field value, whereas `st_lsm6dsx_update_bits_locked()`, `st_lsm6dsx_shub_write_reg_with_mask()`, and `regmap_update_bits()` require `val` pre-shifted with `ST_LSM6DSX_SHIFT_VAL(val, mask)` or `FIELD_PREP()`. [F23]
- `st_lsm6dsx_check_odr()` returns positive milli-Hz on success or `-EINVAL` on failure (writing the hw code to `*val`); capture its return in a signed `int` and test `< 0`. Internal ODRs (`sensor->odr`, `sensor->ext_info.slv_odr`, `odr_avl[].milli_hz`) are in milli-Hz and convert at `IIO_CHAN_INFO_SAMP_FREQ` via `*val = odr / 1000`, `*val2 = (odr % 1000) * 1000` (`IIO_VAL_INT_PLUS_MICRO`) on reads and `val = val * 1000 + val2 / 1000` on writes. [F19, F109]
- After `st_lsm6dsx_shub_check_wai()`, `st_lsm6dsx_shub_read()`, or `st_lsm6dsx_shub_write()` uses `SLV0` for a one-shot I2C transfer, it must pair `st_lsm6dsx_shub_master_enable(sensor, true)` with `st_lsm6dsx_shub_master_enable(sensor, false)` and reset the `SLV0` address register to `hub_settings->pause`. [F9]
- Any buffer passed to `iio_push_to_buffers_with_timestamp()` must be 8-byte aligned and at least `ST_LSM6DSX_IIO_BUFF_SIZE` (16B) long (`hw->scan[id]` or `u8 iio_buff[ST_LSM6DSX_IIO_BUFF_SIZE] __aligned(8)`). `st_lsm6dsx_sw_trigger_handler_thread()` must always call `iio_trigger_notify_done(iio_dev->trig)` before returning `IRQ_HANDLED`. [F104, F111]
- `st_lsm6dsx_alloc_iiodev()` and `st_lsm6dsx_shub_alloc_iiodev()` return `NULL` (never `ERR_PTR`) on failure, and `st_lsm6dsx_shub_check_wai()` returns `-ENODEV` when a slave is absent (skipped in `st_lsm6dsx_shub_probe()`) versus other negative errnos on bus failure. Symbols exported from `st_lsm6dsx_core.c` use the `IIO_LSM6DSX` namespace (`MODULE_IMPORT_NS("IIO_LSM6DSX")` in bus drivers). [F29, F113]

## Error Handling

- Callers of `st_lsm6dsx_sensor_set_enable()`, `st_lsm6dsx_device_set_enable()`, and `st_lsm6dsx_shub_read_output()` must check for a negative return value before proceeding or consuming the output buffer. [F26]

## External Contracts

- Primary IMU sensors (`ST_LSM6DSX_ID_ACC`, `ST_LSM6DSX_ID_GYRO`) report and accept `IIO_CHAN_INFO_SCALE` in nano-units (`IIO_VAL_INT_PLUS_NANO`, `"0.%09u"` in `st_lsm6dsx_sysfs_scale_avail()`), whereas external sensor-hub sensors (`st_lsm6dsx_shub.c`) use micro-units (`IIO_VAL_INT_PLUS_MICRO`, `"0.%06u "` in `st_lsm6dsx_shub_scale_avail()`). [F53]
- `st_lsm6dsx_irq_setup()` must map `IRQF_TRIGGER_LOW` / `IRQF_TRIGGER_FALLING` to `irq_active_low = true` in `hw->settings->irq_config.hla` (and `HIGH` / `RISING` to `false`, rejecting others with `-EINVAL`), and must OR `IRQF_SHARED` into `irq_type` when `drive-open-drain` or `pdata->open_drain` is enabled. [F91]

## Known Pitfalls

- When writing the 3-byte `SLV0` configuration block at `slv0_addr` in `st_lsm6dsx_shub_read()` and `st_lsm6dsx_shub_check_wai()`, if `slv_addr + 2 == aux_sens->addr`, `config[2]` must OR in `ST_LSM6DSX_SHIFT_VAL(3, aux_sens->mask)` both when starting the read and when resetting `SLV0` so `aux_sens` is not overwritten. [F40]
- Pattern FIFO timestamps (`st_lsm6dsx_read_fifo()`) are 24-bit values split across `data[1] << 16 | data[0] << 8 | data[3]`, whereas tagged FIFO timestamps (`st_lsm6dsx_read_tagged_fifo()`) are 32-bit `__le32` integers in bytes `0..3` after the tag byte. Both readers must compare the unscaled unsigned tick count in `s64 ts` against `0xff0000` or `0xffff0000` to set `reset_ts` before multiplying `ts` by `hw->ts_gain`. [F50, F70]
- In `st_lsm6dsx_read_fifo()`, the inner `while (acc_sip > 0 || gyro_sip > 0 || ext_sip > 0)` loop must only decrement `gyro_sip`, `acc_sip`, and `ext_sip` and increment `sip` in the second phase after the `if (ts_sip-- > 0)` timestamp read, keeping `sip` and `*_sip` unchanged during the initial channel `memcpy` phase. [F56]
- In `st_lsm6dsx_update_watermark()`, select the `watermark` parameter when `cur_sensor == sensor` and `cur_sensor->watermark` otherwise. Updating the 16-bit watermark register at `fifo_th.addr` must hold `hw->page_lock`, read `fifo_th.addr + 1` to preserve upper bits outside `fifo_th.mask`, and bulk-write the combined value as `__le16` (`cpu_to_le16()`). [F60, F97]
- Multi-byte sensor register values are little-endian (`le16_to_cpu()`, `le32_to_cpu()`, `cpu_to_le16()`). In `st_lsm6dsx_read_oneshot()` and `st_lsm6dsx_shub_read_oneshot()`, cast `le16_to_cpu()` to `s16` before storing into `int *val`; in `st_lsm6dsx_init_hw_timer()`, cast the `ts_settings->freq_fine` byte read into `int val` to `s8` before multiplying by `37500` for `hw->ts_gain`. [F49, F71, F72]
- `dev_get_drvdata(dev)` on the bus `struct device` returns `struct st_lsm6dsx_hw *` (used by PM callbacks), whereas IIO sysfs `device_attribute` callbacks receive `&iio_dev->dev` and must use `iio_priv(dev_to_iio_dev(dev))` to obtain `struct st_lsm6dsx_sensor *`. [F77]
- In `st_lsm6dsx_reset_device()`, call `st_lsm6dsx_flush_fifo(hw)` (ignoring `-ENOTSUPP`) before setting `hw->settings->reset` so INT1 is not asserted during reset, which would switch I3C-capable chips into I3C-only mode. [F84]
- In `st_lsm6dsx_read_oneshot()`, after `st_lsm6dsx_sensor_set_enable(sensor, true)`, wait `usleep_range(3 * delay, 4 * delay)` (`delay = 1000000000 / sensor->odr`) before reading the output register. In `st_lsm6dsx_shub_wait_complete()`, clamp `2000000U / odr + 1` ms to at least 10 ms via `max_t(u32, 2000000U / odr + 1, 10)` before `msleep()`. [F94, F95]
