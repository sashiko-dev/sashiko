# REALTEK AUDIO CODECS

This unit implements ALSA SoC (ASoC) I2C audio codec drivers for Realtek RT5631/ALC5631, RT5640/RT5639/RT5642, and RT5645/RT5650/ALC3270 codecs, managing codec register maps (including indexed private registers), DAPM audio routing and widgets, DAI clock/PLL/ASRC/TDM configurations, hardware EQ controls, and interrupt- or polling-driven jack and headset button detection.

## Architecture & Data Flow
- In `struct rt5640_priv`, `ovcd_th` and `ovcd_sf` are stored as pre-shifted register field values (`RT5640_MIC1_OVTH_* << RT5640_MIC1_OVTH_SFT` and scale factor `<< RT5640_MIC_OVCD_SF_SFT`), whereas `jd_src` is stored unshifted and shifted by `RT5640_JD_SFT` when written to `RT5640_JD_CTRL`. In `rt5640_probe()`, `"realtek,jack-detect-source"` and `"realtek,over-current-scale-factor"` must be bounds-checked against `RT5640_JD_SRC_HDA_HEADER` and `RT5640_OVCD_SF_1P5` before storing/shifting. [F35, F58]
- Toggling `RT5640_IRQ_MB1_OC_MASK` in `RT5640_IRQ_CTRL2` via `rt5640_enable_micbias1_ovcd_irq()` and `rt5640_disable_micbias1_ovcd_irq()` must update `rt5640->ovcd_irq_enabled` in lockstep so `rt5640_jack_work()` ignores the falling-edge interrupt triggered when disabling the OVCD IRQ. [F39]
- In non-HDA mode, `rt5640_jack_work()` keeps OVCD micbias1 and the OVCD IRQ enabled after headset detection iff `SND_JACK_MICROPHONE` is in `rt5640->jack->status`, which `rt5640_jack_work()` and `rt5640_disable_jack_detect()` check to balance `rt5640_disable_micbias1_for_ovcd()` and `rt5640_disable_micbias1_ovcd_irq()`. [F40]
- Because `rt5640_set_ovcd_params()` enables sticky OVCD (`RT5640_MB1_OC_STKY_EN`), every OVCD polling cycle in `rt5640_detect_headset()`, `rt5640_start_button_press_work()`, and `rt5640_button_press_work()` must clear `RT5640_MB1_OC_STATUS` via `rt5640_clear_micbias1_ovcd()` before sleeping or rescheduling, and `rt5640_start_button_press_work()` must reset `poll_count`, `press_count`, `release_count`, `pressed`, and `press_reported` before scheduling `rt5640->bp_work`. [F41, F60]
- In `rt5640_button_press_work()`, button press reporting must be deferred until `rt5640->poll_count >= (JACK_UNPLUG_TIME / BP_POLL_TIME)` while latching `rt5640->pressed = true` once `press_count >= BP_THRESHOLD`, and `rt5640->pressed && !rt5640->press_reported` must be checked before `rt5640->release_count >= BP_THRESHOLD` (which returns early). [F61]
- Every `snd_soc_dai_driver` registered with `rt5640_aif_dai_ops` or `rt5645_aif_dai_ops` must have a 0-based `.id` in `[0, RT5640_AIFS)` or `[0, RT5645_AIFS)`, because `hw_params` and `set_dai_fmt` index `lrck[dai->id]`, `bclk[dai->id]`, and `master[dai->id]` before validating `dai->id`. [F57]
- In `rt5645_probe()`, `rt5645->eq_param` must be zero-allocated (`devm_kcalloc`) for `RT5645_HWEQ_NUM` entries because `rt5645_hweq_get()` copies all `RT5645_HWEQ_NUM` entries to userspace and `rt5645_enable_hweq()` must validate each `rt5645->eq_param[i].reg` with `rt5645_validate_hweq()` (`0x1a4..0x1cd`, `0x1e5..0x1f8`, or `RT5645_EQ_CTRL2`) before `regmap_write()`, breaking on the first non-matching entry (since `rt5645_hweq_put()` overwrites `eq_param` before validating). [F33, F53]
- In `rt5645.c`, `rt5645_hp_event()` and `rt5645_lout_event()` share the headphone amplifier power stage via `hp_amp_power()`, so each must call `hp_amp_power(component, 1)` on `SND_SOC_DAPM_POST_PMU` and `hp_amp_power(component, 0)` on `SND_SOC_DAPM_PRE_PMD` to keep `hp_amp_power_count` balanced. [F50]
- `rt5645_sys_resume()` must reset `rt5645->jack_type = 0` before calling `rt5645_jack_detect_work()`, because when `pdata.jd_mode != 0` and a jack is present (`!val`), `rt5645_jack_detect_work()` only runs jack-in detection when `rt5645->jack_type == 0` and treats `jack_type == SND_JACK_HEADPHONE` as jack-out. [F67]
- In `rt5645_get_pdata()`, precedence is: `dmi_first_match(dmi_platform_data)` (where every non-sentinel entry must set `.driver_data` to a non-NULL `struct rt5645_platform_data *` because it is unconditionally dereferenced), then device properties if `rt5645_check_dp()` is true, then `jd_mode3_platform_data`, and finally the `quirk != -1` module parameter override. Broken by: adding a property in `rt5645_parse_dt()` without checking it in `rt5645_check_dp()`, or leaving `dmi_platform_data[].driver_data` NULL. [F76, F83]

## Synchronization
- Because `rt5645_i2c_probe()` requests threaded IRQ `rt5645_irq` before `devm_snd_soc_register_component()` invokes `rt5645_probe()` to set `rt5645->component`, `rt5645_jack_detect_work()` must check `if (!rt5645->component)` before dereferencing it, and every return path after `mutex_lock(&rt5645->jd_mutex)` (including `rt5645->pdata.jd_mode == 0`) must unlock `rt5645->jd_mutex`. [F1, F13]
- `rt5645_jack_detect_work()` must hold `rt5645->jd_mutex` across `rt5645_jack_detect()`, button detection, `rt5645->jack_type` updates, and `mod_timer(&rt5645->btn_check_timer, ...)`; DAPM lock acquisitions (`snd_soc_dapm_force_enable_pin`, `snd_soc_dapm_disable_pin`, `snd_soc_dapm_sync`) nest inside `rt5645->jd_mutex`. Broken by: acquiring `rt5645->jd_mutex` inside a DAPM widget event callback, or calling `rt5645_jack_detect()` without `jd_mutex`. [F20]
- `rt5645_btn_check_callback()` runs in timer softirq atomic context and `rt5640_irq()`/`rt5640_jd_gpio_irq()` are non-threaded hardirq handlers; none may sleep (`mutex_lock`, `cancel_delayed_work_sync`, I2C regmap I/O), and `rt5640_irq()` must use `mod_delayed_work()` to reschedule `rt5640->jack_work`. [F91, F95]
- `rt5640_enable_micbias1_for_ovcd()` and `rt5640_disable_micbias1_for_ovcd()` acquire the DAPM mutex via `snd_soc_dapm_mutex_lock(dapm)` around all `*_pin_unlocked()` and `snd_soc_dapm_sync_unlocked()` calls, so callers must run in sleepable process context without already holding the DAPM mutex. [F19, F92]
- In `rt5640_enable_jack_detect()` and `rt5640_enable_hda_jack_detect()`, `rt5640->jack` must be assigned before `request_irq()` or `queue_delayed_work()` is called for `rt5640->jack_work`. [F12]
- In `rt5640_jack_work()`, when unplugging a headset with `SND_JACK_MICROPHONE`, `cancel_delayed_work_sync(&rt5640->bp_work)` must be called before `rt5640_disable_micbias1_ovcd_irq()` and `rt5640_disable_micbias1_for_ovcd()`. When handling an OVCD interrupt by calling `rt5640_disable_micbias1_ovcd_irq()` and `rt5640_start_button_press_work()`, `rt5640->jack_work` must be immediately requeued via `queue_delayed_work(system_long_wq, &rt5640->jack_work, 0)`. [F16, F21]

## Object Lifetimes
- In `rt5645_i2c_remove()` and `rt5645_sys_suspend()`, `timer_delete_sync(&rt5645->btn_check_timer)` must be called before `cancel_delayed_work_sync(&rt5645->jack_detect_work)` because `rt5645_btn_check_callback()` re-queues `jack_detect_work`. [F2]
- In `rt5645_jack_detect()`, the `"LDO2"` DAPM pin must only be disabled on jack removal when `rt5645->pdata.jd_mode == 0`, because `rt5645_probe()` force-enables `"JD Power"` and `"LDO2"` for the component's lifetime whenever `jd_mode != 0`. [F9]
- In `rt5640_i2c_probe()`, `rt5640->bp_work` and `rt5640->jack_work` must be initialized and `rt5640_disable_irq_and_cancel_work()` registered via `devm_add_action_or_reset()` before `devm_snd_soc_register_component()`. [F11]
- `rt5640->irq` and `rt5640->jd_gpio_irq` must be acquired with `request_irq()` (never `devm_request_*irq()`) in lockstep with setting `rt5640->irq_requested` and `rt5640->jd_gpio_irq_requested`, and `rt5640_disable_irq_and_cancel_work()` must call `free_irq()` and clear those flags before calling `cancel_delayed_work_sync()` on `rt5640->jack_work` and then `rt5640->bp_work`. [F4, F38, F78]
- `rt5640_disable_jack_detect()` must return immediately if `rt5640->jack` is `NULL`, and after tearing down IRQs, work, and active microphone OVCD state, must clear both `rt5640->jd_gpio` and `rt5640->jack` to `NULL` (including on failed `rt5640_enable_jack_detect()` or `rt5640_enable_hda_jack_detect()`); `rt5640_suspend()` and `rt5640_resume()` must gate `disable_irq(rt5640->irq)` and `enable_irq(rt5640->irq)` on `rt5640->jack` being non-NULL rather than `rt5640->irq`. [F5, F87]
- In `rt5640_suspend()`, when `rt5640->jack` is non-NULL, `disable_irq(rt5640->irq)`, `cancel_delayed_work_sync(&rt5640->jack_work)`, and `cancel_delayed_work_sync(&rt5640->bp_work)` must run in that order before resetting the codec, entering regmap cache-only mode, and powering off `ldo1_en`. In `rt5640_resume()`, volatile `RT5640_GCTL2` jack-detect enable/polarity bits must be reprogrammed after `regcache_sync()`, and `enable_irq(rt5640->irq)` called only after both complete. [F17, F42, F88]

## API Contracts
- In `rt5640`, device properties (`realtek,in*-differential`, `realtek,lout-differential`, `realtek,dmic*-data-pin`, `realtek,jack-detect-*`, `realtek,over-current-*`) must be parsed in `rt5640_probe()` rather than `rt5640_i2c_probe()` so machine drivers can attach software properties before `snd_soc_register_card()`. [F81]
- On `snd_soc_component_set_jack()`: for `rt5640` (with non-NULL `jack` and `jd_src != RT5640_JD_SRC_HDA_HEADER`), `data` is passed to `rt5640_enable_jack_detect()` as `struct rt5640_set_jack_data *` and may be `NULL` (guard every `jack_data` access with `if (jack_data)`); for `rt5645` (`rt5645_component_set_jack()`), `data` is dereferenced as `*(int *)data` whenever `hs_jack` is non-NULL (callers must pass a non-NULL `int *` `SND_JACK_*` mask, and `data` must not be dereferenced when `hs_jack` is `NULL`). [F27, F74, F75]
- `rt5640_sel_asrc_clk_src()` and `rt5645_sel_asrc_clk_src()` require `filter_mask` to be a bitwise OR of `RT5640_*_FILTER` / `RT5645_*_FILTER` flags (non-zero for `rt5640_sel_asrc_clk_src()`) and `clk_src` to be an unshifted `RT5640_CLK_SEL_*` / `RT5645_CLK_SEL_*` selector. When `rt5640_sel_asrc_clk_src()` updates `RT5640_ASRC_2`, it must update `rt5640->asrc_en` and the lower two bits (`0x3`) of `RT5640_JD_CTRL` in lockstep. [F36, F43]
- `rt5631_codec_set_dai_pll()`, `rt5640_set_dai_pll()`, and `rt5645_set_dai_pll()` treat `!freq_in || !freq_out` as a request to disable the PLL (zeroing `pll_in` and `pll_out` on `rt5640`/`rt5645`) and switch sysclk to MCLK, returning `0` before validating `source` or calling `rl6231_pll_calc()`; cached `pll_in`, `pll_out`, and `pll_src` must only be updated after `rl6231_pll_calc()` succeeds. [F37, F49]

## Error Handling
- In `rt5645_i2c_probe()`, once `regulator_bulk_enable()` succeeds on `rt5645->supplies`, the driver must wait `TIME_TO_POWER_MS` (400 ms) before reading `RT5645_VENDOR_ID2` via `temp_regmap`, every subsequent error path must jump to `err_irq` or `err_enable` to call `regulator_bulk_disable()`, and `rt5645_i2c_remove()` must call `regulator_bulk_disable()` after stopping IRQ/timer/work. [F3, F82]
- Callers of `rt5645_get_pdata()` (`rt5645_components()` and `rt5645_i2c_probe()`) must zero-initialize the target `struct rt5645_platform_data` before calling `rt5645_get_pdata()`. [F32]
- Callers of `get_sdp_info()` in `rt5640.c`, `rl6231_calc_dmic_clk()` in `set_dmic_clk()`, `rl6231_get_clk_info()` in `rt5640_hw_params()`/`rt5645_hw_params()`, and `snd_soc_params_to_bclk()`/`get_coeff()` in `rt5631_hifi_pcm_params()` must store the return value in a signed `int` and check for `< 0` before bit-testing `RT5640_U_IF*`, shifting into `RT5640_DMIC`/`RT5645_DMIC_CTRL1` or `RT5640_ADDA_CLK1`/`RT5645_ADDA_CLK1`, dividing by `rx_rate`, or indexing `coeff_div[coeff]`. [F23, F25, F69, F70]

## External Contracts
- In `rt5645.c`, the `"Speaker HWEQ"` `SNDRV_CTL_ELEM_TYPE_BYTES` control (`rt5645_hweq_info`, `rt5645_hweq_get`, `rt5645_hweq_put`) exchanges a 57-entry (`RT5645_HWEQ_NUM`) array of big-endian 16-bit `(reg, val)` pairs (`struct rt5645_eq_param_s_be16`) in `ucontrol->value.bytes.data`, converted via `cpu_to_be16`/`be16_to_cpu` to/from `rt5645->eq_param`. [F52]
- Callers of exported `rt5640_detect_headset()` must first configure OVCD via `rt5640_set_ovcd_params()` and force-enable `"LDO2"` and `"MICBIAS1"` via `rt5640_enable_micbias1_for_ovcd()` (and balance with `rt5640_disable_micbias1_for_ovcd()`), because `rt5640_detect_headset()` only polls `RT5640_MB1_OC_STATUS` (returning `0`, `SND_JACK_HEADSET`, or `SND_JACK_HEADPHONE`, never a negative errno). When `rt5640_set_jack_data.use_platform_clock = true`, the card must define a `"Platform Clock"` DAPM widget for those helpers to toggle. [F24, F102, F103]

## Known Pitfalls
- Private register index macros in `rt5640.h` (`RT5640_BIAS_CUR4..RT5640_EQ_PST_VOL`) and `rt5645.h` (`RT5645_DIG_VOL..RT5645_EQ_PST_VOL`) are raw 8-bit offsets that overlap direct register addresses and must have `RT5640_PR_BASE` or `RT5645_PR_BASE` (`0x100`) added so regmap routes them through `rt5640_ranges`/`rt5645_ranges`. Conversely, `rt5631_regmap_config` has `.max_register = 0x7e` and no `regmap_range_cfg`, so `rt5631.h` private registers (`RT5631_EQ_BW_LOP..RT5631_SPK_INTL_CTRL`) must be accessed via `rt5631_read_index()` and `rt5631_write_index()`. [F54, F55]
- In `rt5640_hw_params()` and `rt5640_set_dai_fmt()`, the bitmask from `get_sdp_info()` must be tested with separate `if (dai_sel & RT5640_U_IF1)` and `if (dai_sel & RT5640_U_IF2)` statements (not `else if`), because `RT5640_IF_113` and `RT5640_IF_223` set both bits. [F59]
- In `rt5640.c`, external input 2 (`realtek,in2-differential`, `IN2 Boost`, `BST2`) maps to register `RT5640_IN3_IN4` and BST4 bits (`RT5640_PWR_BST4_BIT`, `RT5640_M_BST4_*`), whereas external input 3 (`realtek,in3-differential`, `IN3 Boost`, `BST3`) maps to `RT5640_IN1_IN2` and BST2 bits (`RT5640_PWR_BST2_BIT`, `RT5640_M_BST2_*`). Do not swap them based on macro names. [F63]
- In `rt5640_enable_jack_detect()` and `rt5640_resume()`, JD IRQ polarity must be inverted (`RT5640_JD_P_INV` or `RT5640_JD2_P_INV` when `!rt5640->jd_inverted`) so the JD IRQ signal is 0 while a jack is inserted; otherwise the shared OR-ed IRQ line stays stuck at 1 and masks OVCD button-press edges. [F85]
- Despite the swapped enum comments in `rt5645.h`, `dmic1_data_pin` in `rt5645_i2c_probe()` only accepts `RT5645_DMIC_DATA_IN2N`, `RT5645_DMIC_DATA_GPIO5`, and `RT5645_DMIC_DATA_GPIO11`, while `dmic2_data_pin` only accepts `RT5645_DMIC_DATA_IN2P`, `RT5645_DMIC_DATA_GPIO6`, `RT5645_DMIC_DATA_GPIO10`, and `RT5645_DMIC_DATA_GPIO12`. [F66]
- In `rt5645_hw_params()`, `rt5645_set_dai_fmt()`, and `rt5645_set_tdm_slot()`, updates to data length, BCLK polarity, and TDM slots in `RT5645_I2S1_SDP`, `RT5645_I2S2_SDP`, and `RT5645_TDM_CTRL_1` must branch on `rt5645->codec_type` because bit positions differ between `CODEC_TYPE_RT5645` and `CODEC_TYPE_RT5650`. [F68]
- In `rt5645_spk_put_volsw()`, writing `RT5645_SPK_VOL` requires enabling the internal 25 MHz RC clock (`RT5645_PWR_CLK25M_PU` in `RT5645_MICBIAS`) before `snd_soc_put_volsw()` and scheduling `rt5645->rcclock_work` to power it down after 200 ms. In `rt5645_jack_detect_work()`, when `rt5645->pdata.jd_mode == 4`, jack-detect status must be read from `RT5645_A_JD_CTRL1` masked with `0x0020` (`0` = inserted), not `0x0002` or `RT5645_INT_IRQ_ST`. [F86, F89]
