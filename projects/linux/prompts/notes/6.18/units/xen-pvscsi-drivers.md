# XEN PVSCSI DRIVERS

This unit implements the Xen paravirtualized SCSI (pvSCSI) frontend (`xen-scsifront`) and backend (`xen-scsiback`) drivers along with their shared ring protocol header (`vscsiif.h`). The frontend driver exposes a virtual `Scsi_Host` inside a Xen guest domain and forwards SCSI CDBs, task aborts, and device resets over a shared Xen ring buffer and grant table references. The backend driver runs in the host/backend domain, maps guest grant pages, translates virtual H:C:T:L addresses to Linux Target Core (TCM/LIO) LUNs, and submits commands and task management requests as a TCM fabric module (`xen-pvscsi`).

## Architecture & Data Flow
- `struct vscsifrnt_shadow` is embedded in `scsi_cmd_priv(sc)` when `shadow->act == VSCSIIF_ACT_SCSI_CDB` and heap-allocated via `kzalloc` in `scsifront_action_handler` when `shadow->act` is `VSCSIIF_ACT_SCSI_ABORT` or `VSCSIIF_ACT_SCSI_RESET`; only `scsifront_sync_cmd_done` and `scsifront_action_handler` may `kfree(shadow)`. Broken by: calling `kfree(shadow)` on a `VSCSIIF_ACT_SCSI_CDB` shadow or passing `scsi_cmd_priv(sc)` to `scsifront_do_request` for an abort or reset. [F31]
- In `struct vscsifrnt_info`, `shadow_free_bitmap` uses 1-bits for free request IDs and 0-bits for allocated IDs in `[0, VSCSIIF_MAX_REQS)`. `scsifront_do_request` must check `id >= VSCSIIF_MAX_REQS` after `scsifront_get_rqid` and set `info->shadow[id] = shadow`, `shadow->rqid = id`, and `shadow->inflight = true`. `scsifront_do_response` must reject `ring_rsp->rqid >= VSCSIIF_MAX_REQS`, and `_scsifront_put_rqid` must set bit `id` in `shadow_free_bitmap` and clear `info->shadow[id] = NULL`. [F43, F64]
- When recycling a `struct vscsibk_pend` slot from `se_sess->sess_cmd_map` in `scsiback_get_pend_req`, the entry must be zeroed with `memset`, `req->se_cmd.map_tag` and `req->se_cmd.map_cpu` restored to the allocated tag and CPU, and all `req->grant_handles[]` initialized to `SCSIBACK_INVALID_HANDLE` (`~0`). [F48]
- Because `nr_segments` in `struct vscsiif_request` and `struct vscsifrnt_shadow` stores `VSCSIIF_SG_GRANT` (`0x80`) in bit 7, code indexing `seg[VSCSIIF_SG_TABLESIZE]` must mask it off (`nr_segments & ~VSCSIIF_SG_GRANT`). When `VSCSIIF_SG_GRANT` is set in `scsiback_gnttab_data_map`, the `nr_sgl` indirect segment pages occupy `pending_req->pages[0 .. nr_sgl - 1]` and `pending_req->grant_handles[0 .. nr_sgl - 1]`, so data grant mapping and `for_each_sg` page assignment must offset `pg` and `grant` by `nr_sgl` and advance them by `n_segs` per indirect page. [F58, F76]
- In `map_data_for_request`, `ref_cnt` is a single monotonic index into `shadow->gref[]` across both the indirect segment-page grant loop and the `scsi_for_each_sg` data grant loop (ending as `shadow->nr_grants`), whereas `seg` starts at `shadow->sg ? : shadow->seg` and advances only in the data grant loop; `shadow->sg` is granted by taking `page = virt_to_page(seg)` once and stepping `page++`, so `shadow->sg` must be allocated in physically contiguous memory (`kcalloc`/`kmalloc`), never via `vmalloc`. [F70, F89]
- In `map_data_for_request`, per-scatterlist grant counting must include `sg->offset` in `PFN_UP(sg->offset + sg->length)` because the first page is capped at `PAGE_SIZE - sg->offset` bytes; likewise, `scsifront_probe` and `scsifront_read_backend_params` must set `host->max_sectors` to `(host->sg_tablesize - 1) * PAGE_SIZE / 512` so a page-unaligned transfer spanning an extra page never exceeds `host->sg_tablesize` grants. [F84, F119]
- `scsifront_do_lun_hotplug` must set `info->curr = current` and populate `info->dev_state_path` before invoking `scsi_add_device` or `scsi_remove_device` and reset `info->curr = NULL` before returning; `scsifront_sdev_configure` and `scsifront_sdev_destroy` must only write `info->dev_state_path` when `current == info->curr`. [F35]
- In `scsifront_irq_fn` and `scsiback_irq_fn`, `eoiflag` / `eoi_flags` must be initialized to `XEN_EOI_FLAG_SPURIOUS` once before the outer `while` loop and only cleared via `&= ~XEN_EOI_FLAG_SPURIOUS` when a ring item is consumed, never reset to `XEN_EOI_FLAG_SPURIOUS` on each call to `scsifront_ring_drain` or `scsiback_do_cmd_fn`. [F78]

## Synchronization
- Every `scsifront_enter(info)` returning 0 under `host->host_lock` increments `info->callers` and must be paired with `scsifront_return(info)` under `host->host_lock` (including before sleeping on `info->wq_sync` in `scsifront_action_handler`). `scsifront_suspend` sets `info->pause = 1` under `host->host_lock` and waits on `info->wq_pause` until `info->callers == 0`; `info->pause` stays set across `scsifront_resume` until `scsifront_backend_changed` handles `XenbusStateConnected` (returning after `VSCSIFRONT_OP_READD_LUN` before `XenbusStateInitialised`). [F4, F74, F100]
- `scsifront_ring_drain` and `scsiback_do_cmd_fn` use unwrapped 32-bit `RING_IDX` indices, so loops and bounds checks must use `!=` and `RING_*_OVERFLOW` rather than `<` or `>`, and must copy slots via `RING_COPY_RESPONSE` or `RING_COPY_REQUEST` before validating fields. `scsifront_ring_drain` must read `sring->rsp_prod` with `READ_ONCE()` then `virt_rmb()`; `scsiback_do_cmd_fn` must follow `sring->req_prod` with `rmb()`, and `scsiback_send_response` must hold `info->ring_lock` when writing responses. [F20, F21, F65, F87]
- In `drivers/xen/xen-scsiback.c`, the mutex ordering is `scsiback_mutex` outside `tpg->tv_tpg_mutex` and `tpg->se_tpg.tpg_lun_mutex`, and the spinlock `info->v2p_lock` must never be held when acquiring any of these mutexes. Consequently, `scsiback_release_translation_entry` must splice `info->v2p_entry_lists` into a local list under `info->v2p_lock` and iterate it with `list_for_each_entry_safe` after dropping `info->v2p_lock` before `kref_put` calls `scsiback_free_translation_entry` (which acquires `tpg->tv_tpg_mutex` and `kfree`s each `v2p_entry`). [F80, F112]
- `scsiback_add_translation_entry` must increment `tpg->tv_tpg_fe_count` under `tpg->tv_tpg_mutex` before releasing `scsiback_mutex`, and must recheck `scsiback_chk_translation_entry(info, v)` after acquiring `info->v2p_lock` before adding `new->l` to `info->v2p_entry_lists`. [F25]
- `scsiback_device_action` must initialize `pending_req->tmr_done` via `init_completion` before calling `target_submit_tmr`, and on all synchronous completion or error paths `scsiback_do_resp_with_sense` must be called before `transport_generic_free_cmd(&pending_req->se_cmd, 0)`. [F23]
- `map_data_for_request` runs under `shost->host_lock` (`spin_lock_irqsave`), so dynamic allocations (`shadow->sg`) must use `GFP_ATOMIC`; `scsifront_action_handler` runs in SCSI EH context and must allocate `struct vscsifrnt_shadow` with `GFP_NOIO` before acquiring `host->host_lock`; `scsiback_irq_fn` must be a threaded IRQ handler (`request_threaded_irq` with `handler = NULL`, `IRQF_ONESHOT`) because `scsiback_do_cmd_fn` uses `GFP_KERNEL`, waits on `pending_req->tmr_done`, and calls `cond_resched()`. [F106, F107, F113]

## Object Lifetimes
- Both `scsifront_remove` and `scsifront_disconnect` must serialize `scsi_remove_host(info->host)` under `scsifront_mutex` by checking `info->host_active != STATE_INACTIVE` and setting `info->host_active = STATE_INACTIVE`, before `scsifront_remove` calls `scsifront_free_ring` and `scsi_host_put`. [F6]
- `scsiback_disconnect` must wait on `info->waiting_to_free` until `atomic_read(&info->nr_unreplied_reqs) == 0` before unbinding `info->irq`, resetting `info->irq = 0` (also required on the `free_irq` error path of `scsiback_init_sring`), and unmapping `info->ring.sring`; `scsiback_remove` must run `scsiback_disconnect` before `scsiback_release_translation_entry` and `gnttab_page_cache_shrink(&info->free_pages, 0)`. [F12, F36]
- `scsiback_cmd_exec` must call `scsiback_get(pending_req->info)` before `target_submit_prep` and return immediately if `target_submit_prep` fails (as it already completes and frees `se_cmd` via `scsiback_queue_status` and `scsiback_check_stop_free`). In `scsiback_cmd_done`, `scsiback_fast_flush_area` and `scsiback_do_resp_with_sense` must finish before `scsiback_put(info)` and `target_put_sess_cmd`; because `TARGET_SCF_ACK_KREF` is used, both `scsiback_check_stop_free` and the completion path must drop a `cmd_kref` reference. [F22, F39, F124]
- In `scsiback_gnttab_data_map_list`, `gnttab_page_cache_get` failures must return unmapped `mapcount` pages via `gnttab_page_cache_put`, whereas once `scsiback_gnttab_data_map_batch` runs, it must process all `cnt` entries (storing `SCSIBACK_INVALID_HANDLE` on failure and calling `get_page` on success) and `scsiback_gnttab_data_map_list` must add `mapcount` to `pending_req->n_grants` before returning `err` so `scsiback_fast_flush_area` owns unmapping handles, putting page refs, returning cached pages, and freeing `req->sgl`. [F9, F75]
- `scsiback_make_tpg` must initialize `tpg->tv_tpg_mutex` and call `core_tpg_register` before adding `tpg->tv_tpg_list` to `scsiback_list` under `scsiback_mutex`, and `scsiback_drop_tpg` must remove `tpg->tv_tpg_list` under `scsiback_mutex` before `scsiback_drop_nexus` and `core_tpg_deregister`. `scsiback_drop_nexus` must hold `tpg->tv_tpg_mutex` and verify `tv_tpg_port_count == 0` and `tv_tpg_fe_count == 0` (held until `scsiback_free_translation_entry`) before removing `tpg->tpg_nexus`. [F27, F104]

## API Contracts
- `scsiback_do_translation` acquires `info->v2p_lock` and calls `kref_get(&entry->kref)`, transferring a reference that must be released with `kref_put(&v2p->kref, scsiback_free_translation_entry)`, whereas `scsiback_chk_translation_entry` returns an unreferenced pointer under caller-held `info->v2p_lock`. [F7]
- `scsifront_eh_abort_handler` and `scsifront_dev_reset_handler` (via `scsifront_action_handler`) must set `shadow->rslt_reset = RSLT_RESET_WAITING` (`0`), wait for the backend response, and return `SUCCESS` or `FAILED` (never negative errnos). If `wait_event_interruptible` on `shadow->wq_reset` is interrupted, `scsifront_action_handler` must set `shadow->rslt_reset = RSLT_RESET_ERR` under `info->shadow_lock` so `scsifront_sync_cmd_done` frees `shadow` and `rqid` and returns before `wake_up(&shadow->wq_reset)`. [F30, F72, F118]
- In `scsifront_queuecommand`, transient failures (`-ENOMEM` from `map_data_for_request` or `-EBUSY` from `scsifront_do_request`) must return `SCSI_MLQUEUE_HOST_BUSY` without calling `scsi_done(sc)` (and after `map_data_for_request` succeeds, `scsifront_do_request` failure must first call `scsifront_gnttab_done(info, shadow)`), whereas non-`-ENOMEM` mapping errors (`-E2BIG`) must set `sc->result = DID_ERROR << 16`, call `scsi_done(sc)`, and return `0`. [F3, F117]
- `scsiback_do_cmd_fn` returns `< 0` on ring overflow, `> 0` when more ring work may remain, and `0` when the ring is drained, so `scsiback_irq_fn` must loop while `rc > 0` (not `rc != 0`) and call `xen_irq_lateeoi` only when `!rc` to keep the event channel masked on ring errors. [F77]
- In `scsiback_add_translation_entry`, `strrchr(phy, ':')` locates the `:lun` suffix and overwrites the `':'` separator in `phy` with `'\0'` in-place, so callers (`scsiback_do_add_lun` and `scsiback_do_1lun_hotplug`) must pass a writable buffer containing `:lun` and cannot reuse `phy` across calls. [F94]

## Error Handling
- In `scsifront_gnttab_done`, if `gnttab_try_end_foreign_access` returns `0` for any grant, it must call `scsifront_set_error` (setting `info->host_active = STATE_ERROR`) and return without `kfree(shadow->sg)`, and `scsifront_cdb_cmd_done` must check `info->host_active == STATE_ERROR` and return before `scsifront_put_rqid` or `scsi_done`. [F32]
- `prepare_pending_reqs` must drop `v2p->kref` if `scsiback_get_pend_req` fails; once `prepare_pending_reqs` succeeds, any pre-submission failure in `scsiback_do_cmd_fn` must call both `scsiback_do_resp_with_sense` (to drop `v2p->kref`) and `transport_generic_free_cmd(&pending_req->se_cmd, 0)` (to free the session tag). [F38]

## External Contracts
- Callers of `scsiback_send_response`, `scsiback_do_resp_with_sense`, and `scsiback_result` must pass Linux `DID_*` host status codes shifted left by 16 bits (`DID_* << 16`) in `result`, and `scsiback_result()` and `scsifront_host_byte()` must translate between `DID_*` and wire `XEN_VSCSIIF_RSLT_HOST_*` values in bits 16..23 of `vscsiif_response.rslt` in lockstep, with `scsiback_result()` preserving `result & 0x00ffff`. [F40, F53]
- In `scsiback_gnttab_data_map`, indirect `VSCSIIF_SG_GRANT` pages must be mapped `GNTMAP_readonly` and validated for `offset + length <= PAGE_SIZE`, `n_segs * sizeof(struct scsiif_request_segment) == ring_req->seg[i].length`, and total `nr_segments <= SG_ALL` before allocating `pending_req->sgl` or mapping data grants; every data `scsiif_request_segment` in `pending_req->sgl` must also satisfy `sg->offset < PAGE_SIZE`, `sg->length <= PAGE_SIZE`, and `sg->offset + sg->length <= PAGE_SIZE` (widened to 32-bit `unsigned int`). [F60, F83, F86, F126]
- `scsifront_read_backend_params` must clamp the backend `feature-sg-grant` value to `[VSCSIIF_SG_TABLESIZE, min(SG_ALL, VSCSIIF_SG_TABLESIZE * PAGE_SIZE / sizeof(struct scsiif_request_segment))]`; `prepare_pending_reqs` must reject `ring_req->cmd_len > VSCSIIF_MAX_COMMAND_SIZE`, and `scsifront_cdb_cmd_done` and `scsiback_send_response` must clamp sense length to `VSCSIIF_SENSE_BUFFERSIZE`. [F66, F101]

## Known Pitfalls
- When `nr_sgl > 0` in `scsiback_gnttab_data_map()`, indirect `scsiif_request_segment` arrays span discontiguous grant pages; whenever `(unsigned long)seg >= end_seg`, `i_seg` must increment and `seg` and `end_seg` must be re-derived from `vaddr(pending_req, i_seg) + ring_req->seg[i_seg].offset` and `ring_req->seg[i_seg].length`. [F50]
- `scsiback_gnttab_data_map_list` and `scsiback_fast_flush_area` allocate `VSCSI_GRANT_BATCH`-element grant operation and `struct page *` arrays on the kernel stack and must flush each batch via `scsiback_gnttab_data_map_batch` or `gnttab_unmap_refs` whenever the batch index reaches `VSCSI_GRANT_BATCH`. [F61]
- When splitting scatterlist entries into page grants in `map_data_for_request`, each chunk size `bytes` must be clamped to both `min_t(unsigned int, len, PAGE_SIZE - off)` and `min(bytes, data_len)` and the loop must stop when `data_len == 0`. [F63]
- In `scsiback_add_translation_entry`, the `list_for_each_entry` cursor `tpg_entry` remains non-NULL when the loop breaks or finishes without finding a valid LUN and nexus, so the matched TPG must be stored in a separate `tpg` pointer initialized to `NULL` rather than testing `tpg_entry` after the loop. [F79]
