# VM SOCKETS (AF_VSOCK)

Implements the `AF_VSOCK` (`PF_VSOCK`) address family for communication between virtual machines and their host hypervisor or locally via loopback (`SOCK_STREAM`, `SOCK_SEQPACKET`, `SOCK_DGRAM`), including socket tables, transport registration, BPF sockmap, `SOCK_DIAG`, `vsockmon`, loopback, and VMCI transport.

## Architecture & Data Flow

- `vsock_remove_sock()` must only call `vsock_remove_bound(vsk)` when `SOCK_DEAD` is set on `sk` (set in `__vsock_release()`), because `transport->release(vsk)` also runs during transport reassignment in `vsock_assign_transport()` where the local binding must be preserved. [F60]
- When `vsock_connect()` or `vsock_connect_timeout()` fails or times out after setting `sock->state = SS_CONNECTING`, both `sk->sk_state` (`TCP_CLOSE`/`TCP_CLOSING`) and `sk->sk_socket->state` (`SS_UNCONNECTED`) must be updated in lockstep; if `vsock_connect()` aborts on a signal after dropping `lock_sock(sk)` for `schedule_timeout()`, it must also call `vsock_remove_connected(vsk)` in case `sk->sk_state` reached `TCP_ESTABLISHED`. [F61, F62]
- For `SOCK_STREAM` and `SOCK_SEQPACKET`, callers of `vsock_assign_transport(vsk, psk)` must set `vsk->remote_addr` (and `vsk->local_addr` when `psk != NULL`) first; `vsock_assign_transport()` must check `vsock_use_local_transport(remote_cid)` first, then pick `transport_g2h` when `remote_cid <= VMADDR_CID_HOST`, `!transport_h2g`, or `remote_flags & VMADDR_FLAG_TO_HOST`, and `transport_h2g` only otherwise. [F56, F95]
- After `vmci_transport_recv_listen()` calls `vsock_assign_transport(vpending, vsock_sk(sk))`, it must check `vmci_check_transport(vpending)` and abort with a reset and `sock_put(pending)` if another transport was assigned; in `vmci_transport_recv_connecting_server()`, `pending->sk_state = TCP_ESTABLISHED` and `vsock_insert_connected(vpending)` must precede `vmci_transport_send_attach()` and be rolled back before `release_sock(pending)` on error. [F66, F70]
- On peer detach in `vmci_transport_handle_detach()` or `VMCI_TRANSPORT_PACKET_TYPE_RST` in `vmci_transport_recv_connected()`, an established guest socket with `vsock_stream_has_data(vsk) > 0` must keep `sk->sk_state == TCP_ESTABLISHED` so `__vsock_connectible_recvmsg()` can drain queued data. [F106]
- `struct vmci_transport_recv_notify_data` and `struct vmci_transport_send_notify_data` must not exceed the size or alignment of `struct vsock_transport_recv_notify_data` and `struct vsock_transport_send_notify_data`, because VMCI notify hooks cast stack-allocated `vsock_transport_*_notify_data` pointers directly. [F118]
- `vsock_bind_table` has `VSOCK_HASH_SIZE + 1` buckets (`0..VSOCK_HASH_SIZE - 1` for bound connectible sockets hashed by `svm_port % VSOCK_HASH_SIZE`, and `VSOCK_HASH_SIZE` / `vsock_unbound_sockets` for unbound and `SOCK_DGRAM` sockets), and `__vsock_bind_connectible()` must wrap its rolling `u32 port` counter to `LAST_RESERVED_PORT + 1` whenever `port == VMADDR_PORT_ANY` or `port <= LAST_RESERVED_PORT`. [F81, F82]

## Synchronization

- `lock_sock(sk)` nests outside `vsock_table_lock`, and `vsock_table_lock` is taken in BH callbacks (`vmci_transport_recv_stream_cb`, `vmci_transport_qp_resumed_cb`): all `vsock_table_lock` acquisitions must use `spin_lock_bh(&vsock_table_lock)`, table membership (`__vsock_in_bound_table`, `__vsock_in_connected_table`) must only be checked under `vsock_table_lock`, and code holding `vsock_table_lock` (`sk_diag_fill()`, `vsock_diag_dump()`, `vsock_for_each_connected_socket()` callbacks) must never call `lock_sock(sk)`. [F23, F140]
- Callers of `vsk->transport->release(vsk)` (`vsock_assign_transport()`, `__vsock_release()`) must hold `lock_sock` or `lock_sock_nested` beforehand, and transport `.release` implementations must not acquire the socket lock. [F22]
- Connectible socket callbacks (`vsock_poll`, `vsock_connectible_setsockopt`, `vsock_connectible_sendmsg`, `__vsock_connectible_recvmsg`) must read `vsk->transport` only after acquiring `lock_sock(sk)`, and `vsock_shutdown()` must hold `lock_sock(sk)` across the entire check and update of `sock->state`, `sk->sk_shutdown`, `SOCK_DONE`, and `vsock_send_shutdown(sk, mode)`. [F34, F64]
- `vmci_transport_peer_detach_cb` takes `spin_lock_bh(&trans->lock)` before `bh_lock_sock(trans->sk)`, so `trans->lock` must never be acquired while holding `lock_sock` or `bh_lock_sock`, and `vmci_transport_destruct()` must clear `trans->sk = NULL` under `spin_lock_bh(&trans->lock)` before queueing `trans` for cleanup. [F139]
- In `vmci_transport_recv_stream_cb()`, fast-path processing under `bh_lock_sock(sk)` is only allowed when `!sock_owned_by_user(sk)` and `sk->sk_state == TCP_ESTABLISHED` (otherwise defer to `vmci_transport_recv_pkt_work` with the `sk` ref in `recv_pkt_info->sk`); BH callbacks must use `GFP_ATOMIC` and `vmci_transport_send_control_pkt_bh`, and `vmci_transport_handle_detach` (atomic context) must short-circuit on `vsk->local_addr.svm_cid == VMADDR_CID_HOST` before calling `vsock_stream_has_data(vsk)`. [F27, F136, F138]
- Before scheduling `vsk->connect_work` with `mod_delayed_work()`, callers must take `sock_hold(sk)` and call `sock_put(sk)` if `mod_delayed_work()` returns true; `vsock_connect_timeout()` must recheck `sk->sk_state == TCP_SYN_SENT` and call `vsock_transport_cancel_pkt(vsk)` under `lock_sock(sk)` before dropping that ref, and `vsock_connect()`'s `timeout == 0` branch after `schedule_timeout()` must verify `sk->sk_state != TCP_ESTABLISHED` under `lock_sock(sk)` before resetting state and cancelling packets. [F30, F31]
- In `vsock_connectible_sendmsg()`, `sk->sk_err`, `sk->sk_shutdown & SEND_SHUTDOWN`, and `vsk->peer_shutdown & RCV_SHUTDOWN` must be rechecked after `wait_woken()` relocks `sk` before enqueueing; in `vsock_connectible_wait_data()`, `prepare_to_wait(sk_sleep(sk), wait, TASK_INTERRUPTIBLE)` must run at the start of every loop iteration before checking `vsock_connectible_has_data(vsk)`, `sk->sk_err`, or shutdown flags. [F32, F33]

## Object Lifetimes

- In `__vsock_release()`, `sock_orphan(sk)` must be called after `vsk->transport->release(vsk)` completes because transport `release()` callbacks invoke `vsock_linger(sk)`, which dereferences `sk_sleep(sk)` (`sk->sk_wq`) that `sock_orphan(sk)` clears to `NULL`. [F2]
- In `vsock_assign_transport()`, if `vsk->transport` is set, return `0` when `vsk->transport == new_transport`, or else call `vsk->transport->release(vsk)`, `vsock_deassign_transport(vsk)`, and reset `SOCK_DONE`, `sk->sk_state`, and `vsk->peer_shutdown`. [F3]
- In `vsock_assign_transport()`, call `try_module_get(new_transport->module)` under `vsock_register_mutex`, set `vsk->transport` only after `seqpacket_allow()` and `init(vsk, psk)` succeed (calling `module_put()` on error or in `vsock_deassign_transport()`), and only access static `transport_*` pointers without a socket ref under `vsock_register_mutex`. [F4, F129]
- `vsock_enqueue_accept(listener, connected)` takes `sock_hold()` on both sockets, while `vsock_dequeue_accept(listener)` drops `listener`'s ref and transfers `connected`'s ref to the caller; if `vsock_accept()` fails after dequeueing (`listener->sk_err != 0`), it must set `vconnected->rejected = true` before `sock_put(connected)` so `vsock_pending_work()` cleans it up, whereas in `vsock_pending_work()` if `!vsock_is_pending(sk)` and `!vsk->rejected`, it must skip `vsock_remove_connected(vsk)`, `sk->sk_state = TCP_CLOSE`, and the cleanup `sock_put(sk)`. [F10, F11, F108]
- On failure in `vmci_transport_recv_connecting_server()`, its `destroy:` path must call `sock_put(pending)` to drop the creation reference because `vmci_transport_recv_listen()` calls `vsock_remove_pending(sk, pending)` without setting `vpending->rejected`, causing `vsock_pending_work()` to skip its cleanup `sock_put()`. [F12]
- In `vsock_bpf_recvmsg()`, once `sk_psock_get(sk)` succeeds and `lock_sock(sk)` is acquired, every exit path—including fallback paths to `__vsock_recvmsg(sk, msg, len, flags)`—must call `release_sock(sk)` and `sk_psock_put(sk, psock)` before returning; in `vsock_connectible_sendmsg()`, every early exit from the inner space-wait loop after `add_wait_queue(sk_sleep(sk), &wait)` must call `remove_wait_queue(sk_sleep(sk), &wait)` before jumping to `out_err`. [F17, F18]
- In `vsock_loopback_work()`, `virtio_transport_consume_skb_sent(skb, false)` must pass `false` so `skb` is not freed before `virtio_transport_deliver_tap_pkt(skb)` and `virtio_transport_recv_pkt(&loopback_transport, skb)`; in `vmci_transport_recv_dgram_cb()`, `sock_hold(sk)` must precede `sk_receive_skb(sk, skb, 0)` because `sk_receive_skb()` consumes a ref on `sk`. [F16, F160]

## API Contracts

- `vsock_find_bound_socket()` and `vsock_find_connected_socket()` take `sock_hold(sk)` under `vsock_table_lock` (unlike `__vsock_find_bound_socket()` and `__vsock_find_connected_socket()`), so callers must release the returned socket with `sock_put(sk)`. [F9]
- In `struct vsock_transport`, `cancel_pkt`, `seqpacket_allow`, `notify_buffer_size`, `notify_set_rcvlowat`, `unsent_bytes`, `read_skb`, and `msgzerocopy_allow` are optional and must be NULL-checked before invocation; any transport using `virtio_transport_*` callbacks (such as `loopback_transport`) must embed `struct vsock_transport` inside `struct virtio_transport` because callbacks downcast `vsock_core_get_transport(vsk)` via `container_of()`. [F40, F123]
- `vsock_stream_has_data()`, `vsock_connectible_has_data()`, and `vsock_stream_has_space()` return a signed `s64` that is negative on transport error, so callers (`vsock_connectible_wait_data()`, `vsock_has_data()`, `vsock_do_ioctl()`) must store the result in a signed variable and test `< 0` or `> 0` rather than non-zero. [F44]
- For BPF sockmap: `vsock_release()` must invoke `sk->sk_prot->close(sk, 0)` (`vsock_close`) before `__vsock_release()`; `vsock_connectible_recvmsg()` and `vsock_dgram_recvmsg()` must dispatch to `prot->recvmsg()` when `READ_ONCE(sk->sk_prot) != &vsock_proto`; `vsock_poll()` must check `sk_is_readable(sk)` for `EPOLLIN | EPOLLRDNORM`; and `vsock_bpf_update_proto()` must verify `vsk->transport` (`-ENODEV`) and `vsk->transport->read_skb` (`-EOPNOTSUPP`), and restore `sk->sk_write_space = psock->saved_write_space` on restore. [F151, F152, F153, F154]

## Error Handling

- On connectible sockets, `vsk->transport` is NULL until `vsock_assign_transport()` succeeds and after `vsock_deassign_transport()`, so functions reachable on unconnected sockets (`vsock_stream_has_data()`, `vsock_poll()`, `vsock_read_skb()`, `vsock_bpf_recvmsg()`, `vsock_transport_cancel_pkt()`) must check `vsk->transport != NULL`; similarly, in `vmci_transport_destruct()`, both `vmci_trans(vsk)` and `vmci_trans(vsk)->notify_ops` (which is NULL until `vmci_transport_proto_to_notify_struct()`) must be checked for non-NULL. [F39, F41]
- `sk->sk_err` stores positive errno values (negated on return by `vsock_connect()`, `vsock_accept()`, `vsock_connectible_sendmsg()`, `__vsock_stream_recvmsg()`); VMCI API calls (`vmci_datagram_send()`, `vmci_qpair_alloc()`, `vmci_event_subscribe()`, `vmci_qpair_enquev()`, `vmci_qpair_dequev()`) return VMCI-specific negative error codes that must be translated via `vmci_transport_error_to_vsock_error()` or mapped to `-ENOMEM`. [F43, F45, F167]
- In `vsock_connectible_sendmsg()`, if an error, timeout, signal, or shutdown occurs after `total_written > 0`, `out_err` must overwrite `err` with `total_written` for `SOCK_STREAM` (or when `total_written == len` for `SOCK_SEQPACKET`) and pass `err` through `sk_stream_error()` for `SOCK_STREAM`; in `__vsock_stream_recvmsg()`, when breaking out of the receive loop with `copied > 0` (unless `notify_recv_post_dequeue()` failed), `err` must be overwritten with `copied` after checking `sk->sk_err` and `RCV_SHUTDOWN`. [F47, F48]
- In `vsock_connect()`, when `sock->state == SS_CONNECTING`: if `flags & O_NONBLOCK` is set, jump to `out` with `-EALREADY` without entering the wait loop or rescheduling `vsk->connect_work`; if blocking, break into the wait loop, which terminates on `sk->sk_state == TCP_ESTABLISHED || sk->sk_state == TCP_CLOSING || sk->sk_err != 0`; when initiating a connection via `transport->connect(vsk)`, reset `sk->sk_err = 0` and set `err = -EINPROGRESS`, and jump to `out_wait` when `flags & O_NONBLOCK` to preserve `err`. [F8, F49, F98]

## External Contracts

- `vsock_addr_cast()` must assign `*out_addr = (struct sockaddr_vm *)addr` as soon as `len >= sizeof(**out_addr)` before calling `vsock_addr_validate(*out_addr)`, because `vsock_dgram_connect()` checks `remote_addr->svm_family == AF_UNSPEC` when `vsock_addr_cast()` returns `-EAFNOSUPPORT` to reset `vsk->remote_addr` to `VMADDR_CID_ANY`/`VMADDR_PORT_ANY`, set `sock->state = SS_UNCONNECTED`, and return `0`, whereas on a valid address `vsock_dgram_connect()` must set both `sock->state = SS_CONNECTED` and `sk->sk_state = TCP_ESTABLISHED` for BPF sockmap. [F46, F69, F100]
- In `vsock_shutdown()`, userspace `SHUT_RD`/`SHUT_WR`/`SHUT_RDWR` (`0..2`) must be incremented by 1 into the `RCV_SHUTDOWN | SEND_SHUTDOWN` bitmask before rejecting `(mode & ~SHUTDOWN_MASK) || !mode`, and when `sock->state == SS_UNCONNECTED`, only connectible sockets (`sock_type_connectible(sk->sk_type)`) jump to `out` while `SOCK_DGRAM` sockets still update `sk->sk_shutdown` and call `sk->sk_state_change(sk)`. [F55, F97]
- In `__vsock_connectible_recvmsg()`, `MSG_ERRQUEUE` must be handled via `sock_recv_errqueue()` before acquiring `lock_sock(sk)`, `!transport || sk->sk_state != TCP_ESTABLISHED` must return `0` if `sock_flag(sk, SOCK_DONE)` is set and `-ENOTCONN` otherwise, and `vsk->peer_shutdown` must not be checked before draining queued data. [F99]
- `vsock_diag_handler_dump()` must verify `nlmsg_len(h) >= sizeof(struct vsock_diag_req)` before starting the dump; in `vsock_diag_dump()`, sockets skipped via `continue` (`!net_eq(sock_net(sk), net)` or `__vsock_in_bound_table(vsk)` in `vsock_connected_table` to avoid duplicates) must not increment `i`, whereas `i < last_i` and `vdiag_states` mismatches must jump to `next_bind`/`next_connected` to increment `i`, and `last_i` must be reset to `0` when advancing `bucket`. [F94, F103, F166]

## Known Pitfalls

- When `vsock_bpf_recvmsg()` falls back to the native receive path via `__vsock_recvmsg()`, it must call `__vsock_connectible_recvmsg()` or `__vsock_dgram_recvmsg()` rather than `vsock_connectible_recvmsg()` or `vsock_dgram_recvmsg()` to avoid infinite recursion through `sk->sk_prot->recvmsg`. [F102]
- `vmci_transport_send_reset_bh(dst, src, pkt)`, `vmci_transport_send_invalid_bh(dst, src)`, `vmci_transport_send_wrote_bh(dst, src)`, and `vmci_transport_send_read_bh(dst, src)` swap their arguments when calling `vmci_transport_send_control_pkt_bh(src, dst, ...)`, so reply callers must pass `(&dst, &src)`. [F58]
- `vmci_transport_allow_dgram()` must check `peer_cid == VMADDR_CID_HYPERVISOR` (`0`) before comparing `vsock->cached_peer != peer_cid`, because `sk_alloc()` zero-initializes `vsock->cached_peer` to `0` (`VMADDR_CID_HYPERVISOR`) and `vsock->cached_peer_allow_dgram` to `false`. [F74]
- In `vmci_transport_recv_listen()` and `vmci_transport_recv_connecting_server()`, once a child `pending` socket is found on `pending_links`, state transitions, resets, and `sk_err` updates must target `pending`, while `vsock_remove_pending()`, `vsock_enqueue_accept()`, and `listener->sk_data_ready(listener)` must target the listener. [F107]
- In `vmci_transport_notify_pkt_poll_out()`, `send_waiting_write(sk, 1)` must only be called when `produce_q_free_space == 0`, because sending a `WAITING_WRITE` packet when the produce queue is not full causes an infinite `WAITING_WRITE` and `READ` packet loop with the peer. [F109]
