# MEDIATEK ETHERNET PCS DRIVER

`pcs-mtk-lynxi` implements a phylink PCS driver library for MediaTek LynxI SGMII, 1000BASE-X, and 2500BASE-X Ethernet Physical Coding Sublayer blocks used by MediaTek Ethernet MACs (`mtk_eth_soc`) and MT7531 DSA switches (`mt7530-mdio`). It provides lifecycle helpers (`mtk_pcs_lynxi_create` and `mtk_pcs_lynxi_destroy`) that probe hardware device ID and version via `regmap` and expose `mtk_pcs_lynxi_ops` callbacks for link state polling, mode configuration, autonegotiation restart, link-up speed/duplex forcing, and disablement.

## Architecture & Data Flow

- `SGMSYS_PCS_CONTROL_1` and `SGMSYS_PCS_ADVERTISE` each pack two 16-bit Clause 22 MII registers into one 32-bit `regmap` word (`SGMII_BMCR`/`SGMII_ADVERTISE` in bits 15:0; `SGMII_BMSR`/`SGMII_LPA` in bits 31:16). Reads of `BMSR` or `LPA` in `mtk_pcs_lynxi_get_state()` must shift via `FIELD_GET()`, and writes to `BMCR` or `ADVERTISE` must mask to bits 15:0 rather than using unmasked `regmap_write()`. [F22]
- `mtk_pcs_lynxi_config()` and `mtk_pcs_lynxi_link_up()` update disjoint bitmasks of `SGMSYS_SGMII_MODE` via `regmap_update_bits()` (`SGMII_REMOTE_FAULT_DIS | SGMII_SPEED_DUPLEX_AN | SGMII_IF_MODE_SGMII` in `mtk_pcs_lynxi_config()` vs. `SGMII_DUPLEX_HALF | SGMII_SPEED_MASK` in `mtk_pcs_lynxi_link_up()`). Within `mtk_pcs_lynxi_config()`, `SGMII_IF_MODE_SGMII` and `SGMII_SPEED_DUPLEX_AN` must only be set for `PHY_INTERFACE_MODE_SGMII` and cleared via the mask when switching to 1000BASE-X or 2500BASE-X. Broken by: using `regmap_write()` on `SGMSYS_SGMII_MODE` or omitting the mask bits. [F25, F38]
- `mpcs->interface` must be initialized to `PHY_INTERFACE_MODE_NA` in `mtk_pcs_lynxi_create()` and reset to `PHY_INTERFACE_MODE_NA` in `mtk_pcs_lynxi_disable()`, because `mtk_pcs_lynxi_config()` only executes the PHYA power-down, `SGMII_SW_RESET`, `ana_rgc3` speed, and `SGMSYS_PCS_LINK_TIMER` setup when `mpcs->interface != interface`. [F16]
- When `mpcs->interface != interface` in `mtk_pcs_lynxi_config()`, `SGMII_PHYA_PWD` in `SGMSYS_QPHY_PWR_STATE_CTRL` and `SGMII_SW_RESET` in `SGMSYS_RESERVED_0` must be asserted before programming `MTK_SGMII_FLAG_PN_SWAP` in `SGMSYS_QPHY_WRAP_CTRL`, the line rate in `mpcs->ana_rgc3`, and `SGMSYS_PCS_LINK_TIMER`. Broken by: programming those registers before asserting power-down and reset, or only applying `MTK_SGMII_FLAG_PN_SWAP` once in `mtk_pcs_lynxi_create()`. [F34]
- The `phy_interface_t` modes populated in `mpcs->pcs.supported_interfaces` by `mtk_pcs_lynxi_create()` (`PHY_INTERFACE_MODE_SGMII`, `PHY_INTERFACE_MODE_1000BASEX`, `PHY_INTERFACE_MODE_2500BASEX`) must be handled in lockstep by `mtk_pcs_lynxi_inband_caps()` and the `sgm_mode`/`rgc3` selection branches in `mtk_pcs_lynxi_config()`. [F21]

## Synchronization

- `struct mtk_pcs_lynxi` has no internal lock protecting `mpcs->interface` or multi-register sequences across `mtk_pcs_lynxi_ops` callbacks; callers must serialize `pcs_config` and `pcs_disable` externally (as `phylink` does) while individual register accesses rely on `mpcs->regmap` locking. [F6]
- `mtk_pcs_lynxi_get_state()`, `mtk_pcs_lynxi_config()`, `mtk_pcs_lynxi_restart_an()`, and `mtk_pcs_lynxi_link_up()` access `mpcs->regmap` (backed by the sleeping `mt7530_mdio_regmap_lock` mutex on MT7531 DSA switches), and `mtk_pcs_lynxi_config()` unconditionally calls `usleep_range(50, 100)`. None of these callbacks may be invoked from atomic context or wrap `regmap` calls or `usleep_range()` in a `spin_lock`, `rcu_read_lock`, or preemption-disabled section. [F39, F41]

## Object Lifetimes

- `mtk_pcs_lynxi_create()` allocates `struct mtk_pcs_lynxi` with non-devres `kzalloc()` (using `dev` only for logging) and stores a borrowed `struct regmap *regmap` without acquiring a reference. Callers must keep `regmap` valid across all `mtk_pcs_lynxi_ops` callbacks until the PCS is inactive and explicitly call `mtk_pcs_lynxi_destroy()` on teardown or probe failure. Broken by: unmapping `regmap` while phylink is active, omitting `mtk_pcs_lynxi_destroy()` assuming devres cleanup, or freeing `mpcs` with `devm_kfree()`. [F2, F36]
- `mtk_pcs_lynxi_destroy()` immediately frees `struct mtk_pcs_lynxi` via `kfree()` without stopping phylink polling or synchronizing with in-flight `mtk_pcs_lynxi_ops` callbacks, so callers must ensure no active `phylink` instance can invoke callbacks on `pcs` before calling `mtk_pcs_lynxi_destroy()`. [F8]

## API Contracts

- In `mtk_pcs_lynxi_config()` and `mtk_pcs_lynxi_link_up()`, `neg_mode` is a `PHYLINK_PCS_NEG_*` constant (not `MLO_AN_*`). `PHYLINK_PCS_NEG_INBAND_ENABLED` (`PHYLINK_PCS_NEG_INBAND | PHYLINK_PCS_NEG_ENABLED`) is a multi-bit value that must be tested with `==` or `!=` rather than bitwise `&` (whereas `neg_mode & PHYLINK_PCS_NEG_INBAND` tests for any in-band mode), and `mtk_pcs_lynxi_link_up()` must force speed and duplex whenever `neg_mode != PHYLINK_PCS_NEG_INBAND_ENABLED` (including `PHYLINK_PCS_NEG_INBAND_DISABLED`). [F23, F47]
- In `mtk_pcs_lynxi_inband_caps()`, `PHY_INTERFACE_MODE_2500BASEX` must be handled in a separate `switch` case returning only `LINK_INBAND_DISABLE`, while `PHY_INTERFACE_MODE_1000BASEX` and `PHY_INTERFACE_MODE_SGMII` return `LINK_INBAND_DISABLE | LINK_INBAND_ENABLE` and all other modes return `0`. [F24]
- `mtk_pcs_lynxi_config()` must return a positive non-zero value (`changed || mode_changed`) whenever `SGMSYS_PCS_ADVERTISE` (via `regmap_update_bits_check()`) or `mpcs->interface` changes, `0` when neither changes, and a negative errno on failure. [F46]
- `mtk_pcs_lynxi_create()` allocates with `GFP_KERNEL` and calls `regmap_read()` (which may acquire a sleeping mutex such as `mdio_lock` in `mt7531_create_sgmii()`), so callers must invoke it only from sleepable process context without holding `regmap`'s lock. It must verify that `SGMSYS_PCS_DEVICE_ID` equals `SGMII_LYNXI_DEV_ID` (`0x4d544950`) and `FIELD_GET(SGMII_DEV_VERSION, ver)` in `SGMSYS_PCS_SCRATCH` equals `0x1`, returning `NULL` before allocating `struct mtk_pcs_lynxi` if either check fails. [F35, F40]
- `mtk_pcs_lynxi_destroy()` only checks for a `NULL` `pcs` pointer before downcasting via `pcs_to_mtk_pcs_lynxi()` (`container_of`) and calling `kfree()`, so any non-NULL `pcs` passed to it must be an embedded `&mpcs->pcs` returned by `mtk_pcs_lynxi_create()` (never an `ERR_PTR` or another driver's `phylink_pcs`). [F29]
- `mtk_pcs_lynxi_ops` must always populate `.pcs_config`, `.pcs_get_state`, and `.pcs_an_restart` because `phylink_pcs_config()`, `phylink_mac_pcs_get_state()`, and `phylink_pcs_an_restart()` invoke them without NULL checks. [F43]

## Error Handling

- `mtk_pcs_lynxi_config()` must validate both `phylink_mii_c22_pcs_encode_advertisement()` and (when `mpcs->interface != interface`) `phylink_get_link_timer_ns()` for negative error codes before powering down PHYA (`SGMSYS_QPHY_PWR_STATE_CTRL`), resetting the PCS, or updating `mpcs->interface`. Broken by: moving `phylink_get_link_timer_ns()` or `mpcs->interface = interface` after `regmap_set_bits(..., SGMII_PHYA_PWD)` with an early error return before `SGMSYS_QPHY_PWR_STATE_CTRL` is cleared. [F20]

## Known Pitfalls

- When `mtk_pcs_lynxi_config()` releases PHYA power-down after configuring the PCS, it must sleep (`usleep_range(50, 100)`) and write `0` to the entire `SGMSYS_QPHY_PWR_STATE_CTRL` register via `regmap_write()` rather than only clearing `SGMII_PHYA_PWD` with `regmap_clear_bits()`. [F17]
- In `mtk_pcs_lynxi_link_up()`, the forced-speed conditional chain (`SPEED_10`, `SPEED_100`, `else SGMII_SPEED_1000`) must default all speeds other than 10 and 100 (including `SPEED_1000` and `SPEED_2500`) to `SGMII_SPEED_1000` when `neg_mode != PHYLINK_PCS_NEG_INBAND_ENABLED`. Broken by: replacing the `else` branch with an explicit `SPEED_1000` check that skips `SPEED_2500`. [F26]
- `mtk_pcs_lynxi_config()` must convert the nanosecond link timer duration from `phylink_get_link_timer_ns()` into 16 ns (`2 * 8ns`) hardware units via `SGMII_LINK_TIMER_VAL(ns)` before writing `SGMSYS_PCS_LINK_TIMER`, and any runtime `ns` passed to `SGMII_LINK_TIMER_VAL(ns)` must be verified non-negative and `< 16777216` (`(SGMII_LINK_TIMER_MASK + 1) * 2 * 8`) because `FIELD_PREP(SGMII_LINK_TIMER_MASK, (ns) / 2 / 8)` masks with `GENMASK(19, 0)` without sign or overflow checking. [F28, F50]
