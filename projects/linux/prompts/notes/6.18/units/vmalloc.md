# VMALLOC

The VMALLOC subsystem manages kernel virtual address (KVA) space allocations, page table mappings, and lazy TLB flushing in `mm/vmalloc.c` and `include/linux/vmalloc.h`, along with a stress/benchmark test module in `lib/test_vmalloc.c`. It provides `vmalloc`, `vzalloc`, `vrealloc`, `vfree`, `vmap`, `vunmap`, `vm_map_ram`, and `remap_vmalloc_range` backed by a global augmented red-black tree KVA allocator, partitioned per-node busy/lazy trees with size-segregated pools, and a per-CPU `vmap_block` sub-allocator for short-lived small RAM mappings.

## Architecture & Data Flow

- In `struct vmap_area`, `subtree_max_size` and `vm` share a union: `subtree_max_size` is valid only in `free_vmap_area_root` and `vm` is valid only in `vn->busy.root`. Furthermore, `va->vm` is `NULL` for `vm_map_ram()` and `new_vmap_block()` allocations (`VMAP_RAM`), so `vn->busy` readers must null-check `va->vm` and lookups including `vm_map_ram()` ranges must use `find_vmap_area()` rather than `find_vm_area()`. [F39, F40]
- Whenever a `vmap_area` in `free_vmap_area_root` is inserted, shrunk in `va_clip()`, or expanded in `__merge_or_add_vmap_area()`, `augment_tree_propagate_from()` must be called on it. On insertion (`__link_va()` with `augment == true`), `va->subtree_max_size` must be set to `0` after `rb_insert_augmented()` before propagation. In `va_clip()`, `augment_tree_propagate_from(va)` must only run when `type != FL_FIT_TYPE` (as `FL_FIT_TYPE` frees `va`), and for `NE_FIT_TYPE` must run on the shrunk `va` before `insert_vmap_area_augment()` inserts `lva` beneath `&va->rb_node`. [F47, F56, F92]
- Because `struct vm_struct::size` includes an unmapped trailing `PAGE_SIZE` guard page whenever `!(area->flags & VM_NO_GUARD)`, bounds checks and page-mapping operations (`remap_vmalloc_range_partial()`, `vread_iter()`, `check_sparse_vm_area()`, `ioremap_page_range()`) must use `get_vm_area_size(area)` rather than `area->size`. `__get_vm_area_node()` must round `size` up to `1ul << shift` before adding the optional guard page so `get_vm_area_size(area)` is a multiple of `1UL << page_shift`. [F73, F116]
- `vm_area_alloc_pages()` populates every `PAGE_SIZE` slot of `area->pages[0 .. nr_pages - 1]` exclusively with pages of the `order` set via `set_vm_area_page_order()` (splitting with `split_page(page, order)`). Callers operating on high-order units (`__vmap_pages_range_noflush()`, `vm_reset_perms()`, `show_numa_info()`) must step `area->pages[]` by `1U << page_order`, while per-page callers (`vfree()`) step by 1. If high-order allocation fails mid-array, `__vmalloc_node_range_noprof()` must free the area and retry from scratch at `PAGE_SHIFT` (`align = original_align`). [F63, F82, F101]
- Because a busy `vmap_area` is inserted into `addr_to_node(va->va_start)` but can span multiple `vmap_zone_size` zones, `find_vmap_area()` and `find_unlink_vmap_area()` must scan backwards circularly across `vmap_nodes` via `i = (i + nr_vmap_nodes - 1) % nr_vmap_nodes` starting from `addr_to_node_id(addr)`. `encode_vn_id()` packs a 0-based node ID into `va->flags` as `(node_id + 1) << BITS_PER_BYTE`, and `decode_vn_id()` callers must check `is_vn_id_valid()` before calling `id_to_node()`. [F78, F80]
- `vmap_lazy_nr` must strictly equal the total pages queued across all `vn->lazy` and `vn->purge_list` lists (`free_vmap_area_noflush()` adds `va_size(va) >> PAGE_SHIFT` and `purge_vmap_node()` subtracts `nr_purged_pages`). Because `vb_alloc()` removes a full `vmap_block` from `vbq->free` while leaving it in `vbq->vmap_blocks`, `_vm_unmap_aliases()` must iterate `vbq->vmap_blocks` via `xa_for_each()` to flush dirty unmapped ranges and reset `vb->dirty_min = VMAP_BBMAP_BITS` and `vb->dirty_max = 0`. [F59, F64]
- In `vm_reset_perms()`, when freeing a `VM_FLUSH_RESET_PERMS` area, `set_area_direct_map(area, set_direct_map_invalid_noflush)` must run before `_vm_unmap_aliases(start, end, flush_dmap)`, and `set_area_direct_map(area, set_direct_map_default_noflush)` must run after `_vm_unmap_aliases()`. [F145]
- `vmap_range_noflush()`, `__vunmap_range_noflush()`, and `vmap_small_pages_range_noflush()` must track page-table modifications in `pgtbl_mod_mask mask` and call `arch_sync_kernel_mappings(start, end)` whenever `mask & ARCH_PAGE_TABLE_SYNC_MASK` is non-zero. [F144]

## Synchronization

- After releasing `vn->busy.lock`, callers (`find_vmap_area_exceed_addr_lock()`, `vread_iter()`, `vmalloc_dump_obj()`, `find_vm_area()`) must not dereference `va` or `va->vm` without external serialization. `vmalloc_dump_obj()` must use `spin_trylock(&vn->busy.lock)` and copy `vm` fields before unlocking. In `find_vmap_area_exceed_addr_lock()`, each node's `vn->busy.lock` must be dropped before locking the next and `__find_vmap_area()` re-verified after relocking; `vread_iter()` must unlock `vn->busy.lock` before `next_va` and on exit. [F13, F21, F31, F66, F132]
- `__vmalloc_node_range_noprof()` must keep `VM_UNINITIALIZED` set in `area->flags` until `area->pages` and `area->nr_pages` are populated and mapped, clearing it via `clear_vm_uninitialized_flag()` (`smp_wmb()`); `vn->busy` readers (`vread_iter()`, `vmalloc_info_show()`) must skip areas with `VM_UNINITIALIZED` set and execute `smp_rmb()` before reading `vm_struct` fields. It must also skip `kmemleak_vmalloc()` when `VM_DEFER_KMEMLEAK` is set. [F22, F23, F86]
- `__purge_vmap_area_lazy()` callers must hold `vmap_purge_lock`, which serializes the static `purge_nodes` cpumask (`nr_vmap_nodes <= nr_cpu_ids`) and per-node `purge_list`, `purge_work`, `nr_purged`, and `skip_populate` until `flush_work()` completes. Under `vn->lazy.lock`, it must move `vn->lazy.head` to `vn->purge_list` with `WRITE_ONCE(vn->lazy.root.rb_node, NULL)`, and run `flush_tlb_kernel_range()` before `purge_vmap_node()`. When `nr_purge_helpers == 0` runs `purge_vmap_node()` synchronously, `vn->purge_work.func` must be set to `NULL`. [F12, F24, F25, F60, F126]
- `new_vmap_block()` must initialize all `vmap_block` fields (`lock`, `va`, `used_map`, `free`, `dirty`, `dirty_min`, `dirty_max`, `free_list`, `cpu`) before publishing `vb` via `xa_insert()`, and must enqueue `vb->free_list` onto `per_cpu_ptr(&vmap_block_queue, vb->cpu)` under `vbq->lock`. When `purge_fragmented_block()` unlinks `vb->free_list`, it must lock `per_cpu(vmap_block_queue, vb->cpu).lock` (never the current CPU's or XArray bucket's queue lock). [F18, F19, F135]
- `vb->lock` must be acquired before `vbq->lock`. `vb_alloc()` and `purge_fragmented_blocks()` must hold `rcu_read_lock()` while iterating `vbq->free`, and after `READ_ONCE()` on `vb->free`/`vb->dirty` must lock `vb->lock` and recheck capacity or `vb->free + vb->dirty == VMAP_BBMAP_BITS`. `purge_fragmented_block()` must set `vb->free = 0` and `vb->dirty = VMAP_BBMAP_BITS`, `list_del_rcu(&vb->free_list)` under `vbq->lock`, and stage `vb` on `purge_list` before dropping `vb->lock`, deferring `free_vmap_block()` (`kfree_rcu()`) until after `rcu_read_unlock()`. [F9, F26, F65, F95, F136]
- `vb_free()` must clear `vb->used_map` under `vb->lock` and finish `vunmap_range_noflush()` before re-acquiring `vb->lock` to expand `vb->dirty_min`/`vb->dirty_max` and increment `vb->dirty` via `WRITE_ONCE()`. [F27]
- `preload_this_cpu_lock()` must allocate the preload `vmap_area` with `gfp_mask` before acquiring `free_vmap_area_lock` and install it via `__this_cpu_try_cmpxchg()`, while `va_clip()` under `free_vmap_area_lock` may only fallback-allocate with `GFP_NOWAIT`. `alloc_vmap_area()` must mask `gfp_mask` with `GFP_RECLAIM_MASK` and pass it to slab allocation, `kmemleak_scan_area()`, `preload_this_cpu_lock()`, and `kasan_populate_vmalloc()`. [F30, F128]
- Accesses to `vn->pool[i].head` in `node_pool_add_va()`, `node_pool_del_va()`, and `decay_va_pool_node()` must hold `vn->pool_lock`, `node_pool_del_va()` must recheck `!list_empty(&vp->head)` under `vn->pool_lock`, and every addition/removal must update `vn->pool[i].len` in lockstep using `WRITE_ONCE()` (paired with `READ_ONCE()` in `vmap_node_shrink_count()`). [F33, F58]

## Object Lifetimes

- In `vmap()`, when `VM_MAP_PUT_PAGES` is set in `flags`, ownership of the `pages` array (`kmalloc` or `vmalloc` memory) and one reference per page is transferred to `area` only after `vmap_pages_range()` succeeds, and the mapping must be freed with `vfree()` rather than `vunmap()`; if `vmap_pages_range()` fails, `vmap()` must call `vunmap(area->addr)` before assigning `area->pages` so caller-owned pages are not freed. [F1, F52]
- `__vmalloc_area_node()` frees `area` on every failure (`free_vm_area()` or `vfree()` at `fail:`), so callers must not free `area`. Before checking `area->nr_pages != nr_small_pages`, it must allocate `area->pages` with `__GFP_ZERO`, set `area->nr_pages` to `vm_area_alloc_pages()`'s count, add `area->nr_pages` to `nr_vmalloc_pages`, and charge `MEMCG_VMALLOC`. In `vfree()`, `MEMCG_VMALLOC` (on `vm->pages[0]`) and `nr_vmalloc_pages` are uncharged only when `!(vm->flags & VM_MAP_PUT_PAGES)`, and `vm_reset_perms()` runs between `remove_vm_area()` and freeing pages. [F3, F10, F44, F62, F153]
- `__merge_or_add_vmap_area()` consumes its `va` argument (either freeing `va` via `kmem_cache_free()` when coalesced or linking it into `root`/`head`), so callers must never dereference or free `va` afterward. `__unlink_va()` must detach `va->list` using `list_del_init(&va->list)` because `free_vmap_area_noflush()` aborts on `!list_empty(&va->list)`. [F5, F11]

## API Contracts

- In `vrealloc_node_align_noprof()`, `size == 0` frees `p` via `vfree(p)` and returns `NULL`, whereas any failure when `size > 0` (`!IS_ALIGNED((unsigned long)p, align)`, `get_vm_area_size(vm) < vm->requested_size`, or failed `__vmalloc_node_noprof()`) returns `NULL` leaving `p` intact. It must use `vm->requested_size` as `old_size` for `memcpy()` and KASAN; when resizing in place (`size <= get_vm_area_size(vm)`), it must set `vm->requested_size = size`, poison/unpoison the delta, zero shrunk bytes if init-on-free/alloc is enabled, and `return (void *)p`. [F17, F61, F85, F89, F118]
- `vm_map_ram()`, `vm_unmap_ram()`, and `vmap_ram_vread_iter()` must stay synchronized on `count <= VMAP_MAX_ALLOC`: small mappings use `vb_alloc()`/`vb_free()` (`VMAP_RAM | VMAP_BLOCK`), while larger ones use `alloc_vmap_area()`/`free_unmap_vmap_area()` (`VMAP_RAM`). `vm_unmap_ram(mem, count)` requires `count` to be the exact page count passed to `vm_map_ram()`. [F53, F71]
- Functions installing kernel virtual mappings (`vmap_page_range()`, `vmap_pages_range()`, `vmap_pfn()`, and `vmap_pages_range_noflush()` callers) must call `flush_cache_vmap(addr, end)` after setting PTEs via `set_pte_at(&init_mm, ...)` / `set_huge_pte_at(&init_mm, ...)`. Callers of `vunmap_range_noflush()` (`vunmap_range()`, `free_unmap_vmap_area()`, `vb_free()`) must call `flush_cache_vunmap()` before clearing PTEs and run `flush_tlb_kernel_range()` before KVA reuse (immediately when `debug_pagealloc_enabled_static()` is true). [F140, F142, F143, F161]
- When `vmalloc_to_page()` resolves a huge leaf entry (`p4d_leaf`, `pud_leaf`, `pmd_leaf`), it must add the sub-page PFN offset (`(addr & ~PMD_MASK) >> PAGE_SHIFT`, etc.) to the head `struct page *` to return the specific tail page. [F120]

## Error Handling

- In `pcpu_get_vm_areas()`, `free_vmap_area_lock` must be held across finding `base` and `va_clip()` and dropped before `kasan_populate_vmalloc()`, `vn->busy.lock`, or `reclaim_and_purge_vmap_areas()`. `kasan_populate_vmalloc()` must succeed for all areas before inserting into `vn->busy`. In `recovery:` and `err_free_shadow:`, `vas[area]->va_start`/`va_end` must be saved before `merge_or_add_vmap_area_augment()` (which may free `vas[area]` and returns the wider `va` for `kasan_release_vmalloc()`), and `vas[area]` nulled and reallocated on retry. [F6, F29, F43, F67]
- In `alloc_vmap_area()`, if `kasan_populate_vmalloc()` fails after `va` is inserted into `vn->busy.root`, rollback must call `free_vmap_area(va)` (whereas `overflow:` before insertion uses `kmem_cache_free()`). In `new_vmap_block()`, failure after `alloc_vmap_area()` (`xa_insert()`) must call both `kfree(vb)` and `free_vmap_area(va)`. [F7, F8]
- In `vmap_pages_pte_range()` and `vmap_pte_range()`, PTE errors after `arch_enter_lazy_mmu_mode()` must `break` rather than returning early so `arch_leave_lazy_mmu_mode()` runs and `PGTBL_PTE_MODIFIED` is set in `*mask`. Similarly, in `vmap_range_noflush()` and `vmap_small_pages_range_noflush()`, P4D errors must `break` rather than returning early so `arch_sync_kernel_mappings(start, end)` still runs if `mask & ARCH_PAGE_TABLE_SYNC_MASK` is set. [F14, F15]
- `__alloc_vmap_area()` and `va_alloc()` return negative errnos cast to `unsigned long` and must be checked with `IS_ERR_VALUE()`. `alloc_vmap_area()`, `new_vmap_block()`, and `vb_alloc()` return `ERR_PTR(-errno)` and must be checked with `IS_ERR()`. `vmap_pages_range_noflush()` and `vmap_page_range()` must propagate errors from `kmsan_vmap_pages_range_noflush()` and `kmsan_ioremap_page_range()`. [F35, F36, F37]

## Known Pitfalls

- When `__merge_or_add_vmap_area()` coalesces a freed `vmap_area` with both its `next` and `prev` neighbors, it must unlink the already-merged `next` sibling via `__unlink_va(va, root, augment)` before updating `prev->va_end`, or tree rotations during unlinking will corrupt augmented `subtree_max_size` state. [F57]
- In `vmap_pte_range()`, when `arch_vmap_pte_range_map_size()` returns a huge PTE `size != PAGE_SIZE`, `arch_make_huge_pte()` takes `ilog2(size)`, `set_huge_pte_at()` takes `size`, and the `CONFIG_HUGETLB_PAGE` branch must advance `pfn += PFN_DOWN(size)` before `continue` (while the loop condition advances `pte += PFN_DOWN(size)` and `addr += size`). In `vunmap_pte_range()`, `PTR_ALIGN_DOWN(pte, ...)` must multiply the page count by `sizeof(*pte)`. [F50, F103, F121]
- In `__vmalloc_area_node()`, the `(gfp_mask & (__GFP_FS | __GFP_IO))` checks that enter `memalloc_nofs_save()` (when `== __GFP_IO`) or `memalloc_noio_save()` (when `== 0`) before `vmap_pages_range()` must use identical multi-bit equality predicates to restore `flags` before `if (ret < 0) goto fail;`. [F16, F88, F129]
- In `struct vmap_area`, `va_start`/`va_end` must precede `rb_node` because `alloc_vmap_area()` calls `kmemleak_scan_area(&va->rb_node, SIZE_MAX, gfp_mask)` only on new `vmap_area_cachep` allocations (not on `node_alloc()` hits or inside `retry:`). `vfree_atomic()` writes an `llist_node` into `*addr`, so `kmemleak_free(addr)` must precede `llist_add()` and `delayed_vfree_work()` must use `llist_for_each_safe()`. Address lookup/check functions (`is_vmalloc_addr()`, `__find_vmap_area()`, `vm_unmap_ram()`, `vread_iter()`) must call `kasan_reset_tag()`. [F69, F96, F122, F123, F125, F160]
