# ARM/QUALCOMM MAILING LIST

This unit comprises Qualcomm platform infrastructure, peripheral drivers, and public subsystem/DT-binding headers, including `qcom_scm`, `qcom-cpufreq-hw`, ADM DMA, GENI/QUP I2C and UART serial controllers, `ufs-qcom`, `dwc3-qcom`, USB/PCIe/SGMII PHYs, PMIC GLINK/SMBB battery/chargers, WLED backlight, watchdog/reset, and headers for QMI, APR/GPR, GENI SE, LLCC, UBWC, and MDT loading.

## Architecture & Data Flow
- Under `__scm->scm_bw_lock`, `qcom_scm_bw_enable()` must only increment `scm_vote_count` after `icc_set_bw(__scm->path, 0, UINT_MAX)` succeeds on `0 -> 1`, and `qcom_scm_bw_disable()` calls `icc_set_bw(__scm->path, 0, 0)` only when `scm_vote_count-- == 1`. In `qup_i2c_disable_clocks()`, call `qup_i2c_vote_bw(qup, 0)` to zero `cur_bw_clk_freq` after resetting `QUP_STATE` while `qup->pclk` is still enabled. [F5, F72, F158]
- In `qcom-cpufreq-hw.c`, `qcom_cpufreq_hw_read_lut()` allocates `LUT_MAX_ENTRIES + 1` entries for `policy->freq_table` and, when `dev_pm_opp_of_add_table()` succeeds, sets `icc_scaling_enabled = true` and disables all DT OPPs (`rate++` after `dev_pm_opp_find_freq_ceil()`) so only LUT-matched OPPs are re-enabled. When `per_core_dcvs` is true, `target_index()` and `fast_switch()` must write `index` to `reg_perf_state + i * 4` for all sibling cores. [F63, F64, F92, F108]
- In `i2c-qup.c`, when `qup->use_dma` is true (forbidden if any `msgs[idx].buf` is `is_vmalloc_addr()`), `qup_i2c_interrupt()` must not write `QUP_RESET_STATE` on error, and `qup_i2c_xfer_v2()` must reset `qup->use_dma = false` after `qup_i2c_bam_xfer()`. Whenever `sg_cnt > qup->max_xfer_sg_len`, flush via `qup_i2c_bam_schedule_desc()` and reset `sg_cnt` and `tag_buf_pos` to 0 via `qup_i2c_bam_clear_tag_buffers()`. [F74, F99, F104, F180]
- In `qcom_adm.c`, `adm_prep_slave_sg()` snapshots `mux`, `crci`, and `blk_size` into `async_desc` for `adm_start_dma()`, validates `burst` via `adm_get_blksize()` when `device_fc` is true, includes `sizeof(*cple) + 2 * ADM_DESC_ALIGN` in `dma_len`, 8-byte aligns `cple`/`desc` (`>> 3` DMA addr, `wmb()` before `ADM_CH_CMD_PTR`), and frees unaligned `async_desc->cpl`. In `adm_process_fc_descriptors()`, set `ADM_CMD_LC` on `single_desc` if `remainder != 0`, else on non-NULL `box_desc` when `sg_is_last(sg)`. [F77, F95, F113, F131, F154]
- In `ufs-qcom.c`, `ufs_qcom_pwr_change_notify()` must keep `host->phy_gear` and `UFSHCD_QUIRK_REINIT_AFTER_MAX_GEAR_SWITCH` synced with `dev_req_params->gear_tx` on `PRE_CHANGE`, and copy `dev_req_params` into `host->dev_req_params` before `ufs_qcom_icc_update_bw()` on `POST_CHANGE`. `ufs_qcom_get_bw_table()` clamps 1-based gear/lane to `QCOM_UFS_MAX_GEAR`/`QCOM_UFS_MAX_LANE` and `[MODE_MAX][0][0]` must track the max table entry. [F370, F372, F374, F387]

## Synchronization
- In `qcom_scm-smc.c`, `__scm_smc_do()` must lock/unlock `qcom_scm_lock` inside the `QCOM_SCM_V2_EBUSY` loop around `__scm_smc_do_quirk_handle_waitq()` so it unlocks before `msleep()` or error return. Because `qcom_scm_lock` is held while waiting on `__scm->waitq_comp`, `qcom_scm_irq_handler()` and `scm_get_wq_ctx()` must call `__scm_smc_do_quirk()` directly via `ARM_SMCCC_FAST_CALL` without `qcom_scm_lock`. [F9, F28, F160]
- `__qcom_scm_qseecom_call()` requires `qcom_scm_qseecom_call_lock` held outside `qcom_scm_lock`. In `qcom_scm_probe()`, `smp_store_release(&__scm, scm)` must only run after `mempool`, clocks, resets, and waitq IRQ are initialized; any pre-probe reachable path (`qcom_scm_get_tzmem_pool()`, `qcom_scm_set_boot_addr*()`, `qcom_scm_cpu_power_down()`, `set_download_mode()`) must guard against `__scm == NULL`. [F25, F42, F167]
- In `qcom-cpufreq-hw.c`, `data->throttle_irq` (signed `int`, `-ENXIO` when absent) uses `IRQF_NO_AUTOEN` and is enabled in `qcom_cpufreq_ready()`. All LMh paths (`cpu_online/offline`, `lmh_exit`, `__qcom_cpufreq_hw_get`) must guard on `throttle_irq > 0` (`>= 0`). `cpu_offline()` sets `cancel_throttle = true` under `throttle_lock` and unlocks before `cancel_delayed_work_sync()`, while `qcom_lmh_dcvs_notify()` checks `cancel_throttle` under `throttle_lock`. Set `fast_switch_possible` only when `!icc_scaling_enabled`. [F32, F33, F56, F144, F171]
- In `qcom_adm.c`, `achan->vc.lock` is taken in hardirq `adm_dma_irq()`, so callers must use `spin_lock_irqsave()`; under `vc.lock`, `adm_issue_pending()` only calls `adm_start_dma()` when `!achan->curr_txd`, and `adm_dma_irq()` clears `curr_txd = NULL` before starting the next descriptor. In `i2c-qcom-geni.c`, `geni_i2c_abort_xfer()` must hold `spin_lock_irqsave(&gi2c->lock, flags)` while updating `cur`/`abort_done` and calling `geni_se_abort_m_cmd()`, unlocking before `wait_for_completion_timeout()`. [F78, F176, F178]
- In `pmic_glink` clients (`qcom_battmgr.c`), `battmgr->client = devm_pmic_glink_client_alloc()` and all state (`lock`, `ack`, `enable_work`, `power_supply` pointers) must be set before `pmic_glink_client_register()`. Because `cb` and `pdr` callbacks run under `spin_lock_irqsave(&pg->client_lock)`, they must never sleep, lock `battmgr->lock`, or call `pmic_glink_send()`/`qcom_battmgr_request()` directly (deferring to `enable_work`), while request paths must hold `battmgr->lock` and call `reinit_completion(&battmgr->ack)` before `pmic_glink_send()`. [F207, F208, F232, F298, F299, F494, F495]
- In `qcom_geni_serial.c`, `uport->irq` uses `IRQ_NOAUTOEN`; `startup()` calls `start_rx()` under `uart_port_lock_irq(uport)` before `enable_irq()`, and `shutdown()` calls `disable_irq()` before `uart_port_lock_irq(uport)` (serializing `stop_tx()`, `stop_rx()`, `cancel_tx_cmd()`). Console writes use `uart_port_trylock_irqsave()` when `oops_in_progress` (calling `poll_tx_done()` instead of `drain_fifo()` if `!locked` or `!tx_remaining`), and RX paths unlock via `uart_unlock_and_check_sysrq*()`. [F328, F329, F330, F331, F456, F473]
- In `msm_serial.c`, `port->lock` serializes all runtime `msm_port->imr` / `MSM_UART_IMR` updates; `msm_set_baud_rate()` must unlock `port->lock` around `msm_find_best_baud()` and `dev_pm_opp_set_rate()`, then relock. `msm_stop_dma()` clears `dma->rx.count` and `dma->tx_sg`, which `msm_complete_rx/tx_dma()` must revalidate after locking `port->lock`. [F333, F334, F335]
- In `dwc3-qcom.c`, port wakeup IRQs use `IRQF_NO_AUTOEN`, are enabled after core suspend, and disabled via `disable_irq_nosync()` before core resume; `dwc3_qcom_is_host()` and `qcom->dwc.xhci` must only be accessed when role switching cannot race. In `qmi.h`, `qmi->txn_lock` nests outside `txn->lock`, so a `QMI_RESPONSE` `qmi_msg_handler.fn` (called under `txn->lock`) must not call `qmi_txn_init/wait/cancel()` or `qmi_send_indication()`. [F339, F462, F463, F569]

## Object Lifetimes
- In `qcom_scm.c`, `qcom_scm_pas_init_image()` must allocate `mdata_buf` with `dma_alloc_coherent()` (never `qcom_tzmem_alloc()`), transfer it to `*ctx` on `ret >= 0 && ctx` (freed by `qcom_scm_pas_metadata_release()`, which checks `ctx->ptr` and zeroes `ptr`/`phys`/`size`), and free it on `ret < 0 || !ctx`. All ICE key functions must wipe TZMem key buffers with `memzero_explicit()` before `__free(qcom_tzmem)` runs. [F3, F4, F7, F169]
- In `i2c-qcom-geni.c` and `i2c-qup.c`, DMA channels from `dma_request_chan()` must be freed via `dma_release_channel()` on error/remove (resetting `ERR_PTR` to `NULL` in `qup_i2c_req_dma()`, and zeroing `msm_dma` in `msm_serial.c`). Release `i2c_get_dma_safe_msg_buf()` via `i2c_put_dma_safe_msg_buf()` after unmapping (using `gi2c->se.dev->parent` in GPI mode). In `qup_i2c_bam_schedule_desc()`, if RX prep fails after issuing TX, call `dmaengine_terminate_sync(qup->btx.dma)` before `dma_unmap_sg()`. [F19, F23, F60, F143, F179, F320]
- In `geni_i2c_xfer()`, if `pm_runtime_get_sync()` fails, call `pm_runtime_put_noidle()` and `pm_runtime_set_suspended()`, and on exit clear `gi2c->cur = NULL` and `gi2c->err = 0`. `geni_i2c_runtime_resume/suspend()` must manage `geni_icc`, `core_clk`, `geni_se_resources`, and `gi2c->irq` in LIFO order (re-enabling `irq` if `geni_se_resources_off()` fails). In `i2c-qup.c`, transfers must pair `enable_irq()` with `disable_irq()` before clearing `qup->msg = NULL`. [F20, F21, F24, F39]
- Teardown ordering: `btqcomsmd` must call `hci_unregister_dev()` and `hci_free_dev()` before `rpmsg_destroy_ept()`; `adm_dma_remove()` must mask channel IRQs, kill `vc.task`, and call `adm_terminate_all()` before `devm_free_irq()` and disabling clocks; `qcom_ssc_block_bus` must unwind attached/enabled power domains (`for (i--; i >= 0; i--)` with signed `int i`) and never `iounmap()` devm MMIO; `dwc3-qcom` must release `of_icc_get()` paths with `icc_put()` and never assert `qcom->resets` after `reset_control_deassert()`. [F2, F13, F36, F116, F141, F317, F449]
- In `ufs-qcom.c`, `ufs_qcom_power_up_sequence()` must call `phy_exit()` on post-`phy_init()` failure and complete before `ufs_qcom_enable_lane_clks()`, while `ufs_qcom_exit()` disables lane clocks and calls `phy_power_off()` before `phy_exit()`. `ufs_qcom_config_esi()` allocates `hba->nr_hw_queues - hba->nr_queues[HCTX_TYPE_POLL]` vectors and must only call `platform_device_msi_free_irqs_all()` after `platform_device_msi_init_and_alloc_irqs()` succeeds (and in `ufs_qcom_remove()` when `esi_enabled`), freeing `devm_request_irq()` only for `[0, idx - 1]` on error. [F310, F314, F432, F435, F470]
- In `qcom_geni_serial.c`, every `geni_se_tx/rx_dma_unprep()` call must zero `tx_dma_addr`/`tx_remaining` or `rx_dma_addr` (unprepping before `handle_rx_uart()` or re-prepping `rx_buf`), and `geni_serial_resources_off()` must zero the OPP rate and call `geni_se_resources_off()` before `geni_icc_disable()`. In `qcom-wled.c`, `wled_module_enable(wled, 0)` must call `disable_irq(wled->ovp_irq)` only if `cancel_delayed_work_sync(&wled->ovp_work)` returns false. [F324, F325, F327, F459]
- Ownership in `include/linux/soc/qcom/`: callers must `kfree()` buffers from `qmi_encode_message()`, `qcom_mdt_read_metadata()`, and `nvmem_cell_read()`, release `gpr_alloc_port()` with `gpr_free_port()`, `qmp_get()` with `qmp_put()`, and `qcom_smem_state_get/register()` with `qcom_smem_state_put/unregister()` (none accept `NULL`/`ERR_PTR`), and pair `dev_pm_opp_find_freq_*()` with `dev_pm_opp_put()`. [F16, F196, F312, F481, F483, F486, F489, F490]
- Borrowed pointers: never `kfree()` pointers returned by `qmi_ops.new/del_server`, `pdr_add_lookup()`, `geni_se_clk_tbl_get()`, `qcom_smem_get()`, or `qcom_ubwc_config_get_data()`. [F479, F485, F492, F493]

## API Contracts
- In `qcom_scm`, `qcom_scm_call()` requires preemptible context; atomic/idle/IRQ callers must use `qcom_scm_call_atomic()` (legacy supports `<= 5` args and does not remap errors), and `do_msm_poweroff()`/`qcom_wdt_restart()` must use `mdelay()`. `qcom_scm_shm_bridge_enable(scm_dev)` must use `scm_dev` (never `__scm`). `qcom_scm_qseecom_app_send()` requires `qcom_tzmem_alloc()` buffers. `qcom_scm_assign_mem()` takes/updates `*srcvm` as a `BIT(vmid)` mask (on success) while `src[]`/`newvm[].vmid` use indices `0..63` (`src[i++]`). [F45, F47, F48, F112, F138, F161, F164, F302, F466]
- Unit contracts: `qcom-cpufreq-hw` and `qcom_battmgr_sc8280xp_callback()` scale frequencies/capacities by `1000` (and `battmgr` checks `unit` `mAh` vs `mWh`); `ufs-qcom` maps OPP `freq` via `ufs_qcom_opp_freq_to_clk_freq()` (checking `found`), passes `ceil(clk_freq, HZ_PER_MHZ)` to `ufs_qcom_set_clk_40ns_cycles()`, and holds `ufshcd_hold(hba)` in `ice_keyslot_program/evict()`; `geni_se` FIFO depths/watermarks are in 4-byte words (`tx_fifo_width` in bits). [F126, F223, F305, F346, F347, F407, F424, F468, F514]
- Helper/driver contracts: `geni_se_setup_m/s_cmd()` take an unshifted `@cmd` opcode and use `writel()`, and `se->wrapper` must be set before `geni_se_*` calls; `qusb2_write_mask` takes `(base, off, val, mask)` while `qcom_snps_hsphy_write_mask` takes `(base, off, mask, val)`; `qmp_configure_lane()` takes a `BIT(lane)` mask; `dwc3-qcom` leaves `drvdata` (`&qcom->dwc`) to `dwc3_core_probe()`; keep `#else` stubs in `include/linux/soc/qcom/*.h` synced with `#if IS_ENABLED(CONFIG_*)`. [F215, F257, F423, F482, F491, F498, F513, F516, F520]

## Error Handling
- Return conventions: `qcom_hwspinlock_trylock()` returns `1` on lock, `0` on contention, `< 0` on error; `qcom_rng_read()` returns byte count for `qcom_hwrng_read()`, normalized (`ret >= 0` -> `0`) in `qcom_rng_generate()`; `apr/gpr_send_*pkt()` and `geni_se_clk_tbl_get()` return `> 0` on success; `qcom_scm_shm_bridge_enable()` maps `SHMBRIDGE_RESULT_NOTSUPP` to `-EOPNOTSUPP`; `qcom_ssc_block_bus_pds_attach()` checks `IS_ERR_OR_NULL()` (`NULL` -> `-ENODATA`). [F44, F51, F52, F53, F506, F515]
- State error checks: `qusb2_phy_probe()` and `qcom_usb_hs_phy_probe()` reset ignored `ERR_PTR` optional handles to `NULL`; `ufs_qcom_setup_clocks()` checks `ufshcd_get_variant(hba) != NULL`; `geni_i2c_err()` only sets `gi2c->err` if `!gi2c->err`; `btqcomsmd_send()` only frees `skb` when `!ret`. [F58, F62, F202, F343]
- Callback/QMI error checks: `qcom_battmgr` callbacks return `-EAGAIN` when `!service_up`, and `sm8350_callback()` checks `resp->intval.result` (jumping to `out_complete` to signal `ack`) for integer properties while skipping `intval.result` for `strval`; `qmi_txn_init()` (`ret >= 0`) requires either `qmi_txn_wait()` (checking `resp.result`) or `qmi_txn_cancel()`, never both. [F222, F245, F261, F509, F510]

## Known Pitfalls
- In `i2c-qcom-geni.c`, `geni_i2c_rx/tx_one_msg()` must snapshot `cur = gi2c->cur` before waiting/aborting and pass `cur` to cleanup; `geni_i2c_irq()` must check error bits before FIFO servicing and widen `cur->buf[gi2c->cur_wr++]` to `u32` before `<< (p * 8)`. In `i2c-qup.c`, `qup_i2c_bus_active()` must use `time_after(jiffies, timeout)` and `break` on timeout, and `qup_i2c_interrupt()` must only require `QUP_MX_OUTPUT_DONE` on writes when `blk->is_tx_blk_mode` is true. [F68, F101, F102, F106, F120, F124]
- In `qcom_battmgr.c`, `QCOM_BATTMGR_SC8280XP` is `0` (`NULL` match data), so `qcom_battmgr_probe()` must use `of_match_device()`; every `sm8350_*_props` entry must be mapped in `sm8350_*_prop_map` and `sm8350_callback()`; `sc8280xp_callback()` must compute `status.percent` from unscaled `resp->status.capacity` after checking `last_full_capacity >= 1000`. In `phy-qcom-qmp-usbc.c`, `qmp_usbc_power_on()` polls `QPHY_PCS_STATUS` for active-low `!(val & PHYSTATUS)`. [F221, F231, F263, F270, F271]
- In `msm_serial.c` and `qcom_geni_serial.c`, 32-bit FIFO `ioread32_rep`/`iowrite32_rep` require a 4-byte zeroed buffer and word count `1` for partial words; `__qcom_geni_serial_console_write()` right-shifts partial `write_cached_bytes` by `8 * (4 - cnt)`; console TX length includes `'\\n'` count; `set_termios()` clears `UART_CTS_MASK` when `CRTSCTS` is set; `RX_LAST` with `RX_LAST_BYTE_VALID == 0` means 4 bytes; earlycon helpers check `private_data->drv != NULL` before `to_dev_port()` and poll with `udelay()`. [F358, F384, F385, F402, F405, F419, F421, F425]
- In `qmi.h`, `QMI_DATA_LEN` target fields must be `u32`, `QMI_STRING` `elem_len` must include `+ 1` for NUL, and `qmi_msg_handler.fn` must not retain `decoded`/`txn` or access fields other than `txn->id` on requests/indications. In `apr.h`, `svc_to_apr_device()` is invalid on dynamic `gpr_port_t`, `apr_driver.gpr_callback` receives `gpr_device_t *`, and callbacks must check `payload_size > 0` and not retain `resp`/`payload`. [F511, F548, F549, F550, F551, F552, F553]
