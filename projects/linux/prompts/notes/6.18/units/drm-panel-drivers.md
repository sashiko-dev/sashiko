# DRM PANEL DRIVERS

This unit (`drivers/gpu/drm/panel`) contains DRM panel drivers for Samsung, Seiko, Sharp, Sitronix, Sony, Startek, and TDO panels, plus the generic `panel-simple` driver for DPI, LVDS, and MIPI-DSI panels. Each driver implements `drm_panel_funcs` to sequence regulators, GPIOs, DSI/SPI/DBI transfers, and display modes, optionally registering `backlight_ops` and runtime PM handlers.

## Architecture & Data Flow
- In `panel-simple.c`, `panel_simple_dsi_probe()` downcasts `panel->desc` via `container_of(..., struct panel_desc_dsi, desc)`. Every `dsi_of_match` entry must point to a `struct panel_desc_dsi` whose `desc.connector_type` is not `DRM_MODE_CONNECTOR_LVDS`. In `panel_simple_override_nondefault_lvds_datamapping()`, `panel->desc` must be duplicated via `devm_kmemdup()` before mutating `bus_format` and `bpc`. [F28, F44]
- In `panel_simple_probe()`, `panel_simple_get_desc()` must resolve `panel_desc` (including `panel_dpi_probe()` for `"panel-dpi"`) before `devm_drm_panel_alloc()`, which requires `desc->connector_type`. In `platform_of_match`, `panel-dpi` (`.data = NULL`) must remain last before the sentinel, and all other entries must set a non-NULL `struct panel_desc *`. [F29, F99]
- In `panel-simple.c`, `struct panel_desc` must specify either `modes` or `timings`, never both (`WARN_ON`). `panel_simple_parse_panel_timing_node()` may populate `panel->override_mode` and set non-zero `DRM_MODE_TYPE_*` on `override_mode.type` (checked by `panel_simple_get_non_edid_modes()`) only when `desc->num_modes == 0`, `desc->num_timings != 0`, and a `desc->timings[]` entry matches `ot->flags` and passes `PANEL_SIMPLE_BOUNDS_CHECK()` on all eight timing fields. [F30, F64, F106]
- In `panel-simple.c`, `.connector_type` must be `DRM_MODE_CONNECTOR_{LVDS,DSI,DPI}` (never `0` or `eDP`). LVDS descriptors must pair `MEDIA_BUS_FMT_RGB666_1X7X3_SPWG` with `.bpc = 6` or `MEDIA_BUS_FMT_RGB888_1X7X4_{SPWG,JEIDA}` with `.bpc = 8`, and limit `.bus_flags` to `DRM_BUS_FLAG_DE_{LOW,HIGH}` and `DRM_BUS_FLAG_DATA_{MSB_TO_LSB,LSB_TO_MSB}`. DPI/DSI descriptors must set `.bpc` to `6` or `8`, DPI must set non-zero `.bus_format` and valid `.bus_flags`, and any `display_timing.flags` polarities must match `panel_desc.bus_flags`. [F42, F123, F124, F125]
- In `panel-samsung-sofef00.c`, `panel-sony-tulip-truly-nt35521.c`, and `panel-startek-kd070fhfid015.c`, `devm_backlight_device_register()` takes `struct mipi_dsi_device *dsi` as `devdata`, so `backlight_ops` callbacks must cast `bl_get_data(bl)` to `struct mipi_dsi_device *`, not the panel struct. In `panel-sony-acx565akm.c`, `acx565akm_cabc_attr_group` on `&lcd->backlight->dev.kobj` relies on `backlight_device_register()` storing `struct acx565akm_panel *lcd` as `dev_get_drvdata(&lcd->backlight->dev)`. [F97, F98]
- Brightness/gamma bounds: `s6e63m0_probe()` must clamp DT `"max-brightness"` to `MAX_BRIGHTNESS` (`NUM_GAMMA_LEVELS - 1`). `s6e63j0x03_get_brightness_index()` must clamp `index` to `NUM_GAMMA_STEPS - 1` when `brightness / (MAX_BRIGHTNESS / NUM_GAMMA_STEPS) >= NUM_GAMMA_STEPS`. `s6e8aa5x01_ams561ra01_probe()` must set `max_brightness <= ARRAY_SIZE(s6e8aa5x01_ams561ra01_cmds) - 1` because `s6e8aa5x01_ams561ra01_update_status()` indexes the array directly with `backlight_get_brightness(bl)`. [F58, F59, F60]
- In `s6e88a0_ams427ap24_set_brightness()`, `candela_enum` must be validated against `CANDELA_10CD ... CANDELA_300CD` before indexing; `s6e88a0_ams427ap24_elvss` is indexed at `0` for `<= CANDELA_111CD` and `candela_enum - CANDELA_111CD` otherwise, and the variable trailing bytes (`VAR_LEN_*`) in `s6e88a0_ams427ap24_{aid,elvss,gamma}` must be copied at offset `FIX_LEN_*` after the fixed headers in `b2`, `b6`, and `ca`. [F61, F94]
- In `panel-samsung-s6e63j0x03.c`, `ctx->bl_dev->props.power` must be updated across `prepare` (`BACKLIGHT_POWER_REDUCED`), `enable` (`BACKLIGHT_POWER_ON`), `disable` (`BACKLIGHT_POWER_REDUCED`), and `unprepare` (`BACKLIGHT_POWER_OFF`), and `s6e63j0x03_update_gamma()` / `s6e63j0x03_enable()` must bracket MTP/gamma writes with `s6e63j0x03_apply_mtp_key(ctx, true)` and `(ctx, false)`. [F54, F55]
- In `panel-samsung-s6e8aa5x01-ams561ra01.c`, `s6e8aa5x01_ams561ra01_update_status()` must return `0` if `!ctx->panel.enabled`, and must bracket gamma/AID writes with `MCS_ACCESSPROT` unlock (`0xf0, 0x5a, 0x5a`), `MCS_GAMMAUPD` (`0xf7, 0x03`), and lock (`0xf0, 0xa5, 0xa5`). [F56]
- In `panel-startek-kd070fhfid015.c`, `dsi_dcs_bl_get_brightness()` and `dsi_dcs_bl_update_status()` clear `MIPI_DSI_MODE_LPM` in `dsi->mode_flags` before the DCS brightness transfer and must restore `dsi->mode_flags |= MIPI_DSI_MODE_LPM` afterward. [F57]
- In `panel-sony-acx565akm.c`, `acx565akm_power_on()` must set `lcd->enabled = true` before calling `acx565akm_set_cabc_mode(lcd, lcd->cabc_mode)` (which caches `cabc_mode` unconditionally but only writes hardware when `lcd->enabled`). `acx565akm_set_sleep_mode()` must wait for any remaining guard time and then set `lcd->hw_guard_wait = msecs_to_jiffies(120)` and `lcd->hw_guard_end = jiffies + lcd->hw_guard_wait` after sleep commands. [F50, F51]
- `st7789v_read_data()` must reject `len` values other than 1, 3, or 4 with `-EOPNOTSUPP` before setting `xfer[1].len = len * 2` into the 4-element `u16 rxbuf[4]` stack array. [F69]

## Synchronization
- In `panel-sony-acx565akm.c`, `lcd->mutex` must be held across all post-probe calls to `acx565akm_transfer`, `acx565akm_set_cabc_mode`, `acx565akm_power_on`, and `acx565akm_power_off` from sysfs, backlight, and panel callbacks. Paths already holding `lcd->mutex` (such as `acx565akm_power_on`) must update the backlight via `acx565akm_bl_update_status_locked`, not `acx565akm_bl_update_status` or `backlight_update_status`. [F14, F118]
- In `panel-simple.c`, `panel_simple_probe()` must initialize `desc`, `supply`, `enable_gpio`, `ddc`, and `dev_set_drvdata(dev, panel)` before `pm_runtime_enable(dev)` and `drm_panel_add(&panel->base)`. `panel_simple_remove()` must call `drm_panel_remove(&panel->base)` and `panel_simple_shutdown(dev)` before `pm_runtime_dont_use_autosuspend(dev)`, `pm_runtime_disable(dev)`, and `put_device(&panel->ddc->dev)`. [F17, F18, F100]
- In `panel-simple.c`, `panel_simple_suspend()` frees `p->drm_edid` (`p->drm_edid = NULL`) and records `p->unprepared_time`, and `panel_simple_resume()` waits for `p->desc->delay.unprepare` via `panel_simple_wait()` before enabling `p->supply`. Thus, all DDC EDID reads and `p->drm_edid` accesses in `panel_simple_get_modes()` must be bracketed by `pm_runtime_get_sync()` and `pm_runtime_mark_last_busy()` / `pm_runtime_put_autosuspend()`, and `panel_simple_prepare()` must call `pm_runtime_put_autosuspend()` if `pm_runtime_get_sync()` fails. [F102, F103, F120]
- `s6e63j0x03_probe()` must register `ctx->bl_dev` before `drm_panel_add()`, and teardown must call `drm_panel_remove()` before `backlight_device_unregister()`. `s6e88a0_ams427ap24_probe()` must set `ctx->dsi = dsi` before `s6e88a0_ams427ap24_register_backlight(ctx)`, which must precede `drm_panel_add()`. [F19, F20]
- In `s6e63m0`, `dbi->read_commands` (set to `s6e63m0_dbi_read_commands` after `mipi_dbi_spi_init()`), `ctx->transport_data`, `ctx->dcs_read`, `ctx->dcs_write`, and `ctx->bl_dev` must be initialized before `drm_panel_add()`, and `s6e63m0_dsi_remove()` must call `mipi_dsi_detach()` before `s6e63m0_remove()`. [F21, F131]

## Object Lifetimes
- When a DSI panel `.probe` registers the panel via `drm_panel_add()` (or `s6e63m0_probe()`) before calling `mipi_dsi_attach()` or `devm_mipi_dsi_attach()`, it must call `drm_panel_remove()` (or `s6e63m0_remove()`) if the DSI attach fails. [F11]
- In `panel_simple_probe()` and `panel_simple_remove()`, the `ddc-i2c-bus` `device_node` must be released with `of_node_put(ddc)` immediately after `of_find_i2c_adapter_by_node(ddc)`, and `panel->ddc` must be released via `put_device(&panel->ddc->dev)` on probe failure and in `panel_simple_remove()`. [F3]
- In `panel-sony-acx565akm.c`, `lcd->mutex` and `acx565akm_detect(lcd)` must be initialized before `acx565akm_backlight_init(lcd)`. On `sysfs_create_group()` failure or in `acx565akm_remove()`, `drm_panel_remove()` must run before `acx565akm_backlight_cleanup()`, which must remove `acx565akm_cabc_attr_group` before calling `backlight_device_unregister(lcd->backlight)`. [F6, F111]
- In `panel-sharp-lq101r1sx01.c`, `sharp_panel_probe()` binds to both DSI-LINK1 (`secondary != NULL`) and DSI-LINK2 (`secondary == NULL`), but only allocates `struct sharp_panel` and calls `sharp_panel_add()` on DSI-LINK1 (before `mipi_dsi_attach()`). `sharp_panel_remove()` must call `mipi_dsi_detach(dsi)` before `if (sharp) sharp_panel_del(sharp)`, probe failure must guard `sharp_panel_del(sharp)` with `if (secondary)`, and `put_device(&secondary->dev)` must release the `of_find_mipi_dsi_device_by_node()` reference on error and in `sharp_panel_del()`. [F22, F76, F109]

## API Contracts
- In `s6e63m0`, buffers passed to `s6e63m0_dcs_write()` must place the command byte at `data[0]` with `len >= 1`. `dcs_read` and `dcs_write` callbacks must normalize positive byte counts from `mipi_dsi_dcs_{read,write}()` to `0` on success because their return value is stored into `ctx->error`. [F23, F92]
- In `s6e63m0`, `ctx->transport_data` (`trsp`) is `NULL` in DSI mode (`dsi_mode == true`), so DSI callbacks must derive `mipi_dsi_device` from `dev`. `s6e63m0_spi_dcs_write()` must use `mipi_dbi_command_stackbuf()` (not `mipi_dbi_command_buf()`) because callers pass `static const` rodata and stack buffers. [F26, F93]
- In every `.get_modes` callback, each `struct drm_display_mode` allocated via `drm_mode_create()` or `drm_mode_duplicate()` transfers ownership to `connector` via `drm_mode_probed_add(connector, mode)`. `panel_simple_get_timings()` and `seiko_panel_get_timings()` must check `if (timings)` and clamp `num_timings` to `p->desc->num_timings` before copying, while returning `p->desc->num_timings`. [F13, F63]
- MIPI DCS column, page, and partial-row commands take inclusive 0-based end coordinates (`hdisplay - 1`, `vdisplay - 1`, `partial_end - 1`); in `sharp_setup_symmetrical_split()`, the links cover `[0, hdisplay / 2 - 1]` and `[hdisplay / 2, hdisplay - 1]`. Multi-byte offsets in `sharp_panel_{write,read}()` are big-endian, and `acx565akm_detect()` must convert the 4-byte status response with `__be32_to_cpu()`. [F68, F70]
- In `panel-sony-acx565akm.c`, 9-bit SPI transfers require 2 bytes per word: `acx565akm_transfer()` sets `x->len = 2` for the command word, and when `rlen > 1 && wlen == 0` it must set `bits_per_word = 10` and shift `cmd <<= 1` on `xfer[0]`. Single-word writes in `acx565akm_set_cabc_mode()` and `acx565akm_set_brightness()` must set bit 8 (`1 << 8`) in a 2-byte buffer. [F71, F82]
- `MIPI_DSI_MODE_NO_EOT_PACKET` and `MIPI_DSI_MODE_VIDEO_NO_{HFP,HBP,HSA}` have negative polarity (setting the flag disables the packet/interval). Callers of `sharp_wait_frames()` must pass a non-zero `frames <= drm_mode_vrefresh(sharp->mode)`, and `sharp_wait_frames()` must bail out when `frames > refresh` before `1000 / (refresh / frames)`. New panel drivers must not copy `panel_simple_shutdown()`'s calls to `drm_panel_disable()` / `drm_panel_unprepare()` into `.shutdown` or `.remove`. [F83, F86, F128]

## Error Handling
- In `sharp_ls060_prepare()`, `seiko_panel_prepare()`, and `stk_panel_prepare()`, staged regulator enable failure labels must disable only already-enabled supplies in LIFO order. In `s6e63j0x03_prepare()`, `s6e88a0_ams427ap24_prepare()`, `s6e88a0_ams452ef01_prepare()`, `sharp_panel_prepare()`, `sharp_nt_panel_prepare()`, `sony_td4353_jdi_prepare()`, and `tdo_tl070wsh30_panel_prepare()`, any DSI init failure after enabling supplies must disable those supplies before returning. [F9, F12]
- In `s6e8aa0` and `s6e63m0`, a negative `ctx->error` short-circuits all subsequent `dcs_read`/`dcs_write` calls and must be reset to `0` via `s6e8aa0_clear_error()` or `s6e63m0_clear_error()` on unprepare or completion. In `s6e8aa0_set_sequence()`, `s6e8aa0_read_mtp_id(ctx)` must run before `s6e8aa0_panel_init(ctx)` and set `ctx->error < 0` on a short read, `id[0] == 0x00`, or unknown `id[1]`, so `s6e8aa0_brightness_set()` aborts before dereferencing `ctx->variant->gamma_tables`; `s6e8aa0_prepare()` must call `s6e8aa0_unprepare()` when `ctx->error < 0`. [F10, F62, F114]
- Functions using `mipi_dsi_*_multi()` helpers must zero-initialize `struct mipi_dsi_multi_context` (`{ .dsi = dsi }`) so `accum_err` starts at `0`. Probe functions calling `of_drm_get_panel_orientation()` must propagate negative errors before `drm_panel_add()`. In `sharp_nt_panel_add()`, if `devm_gpiod_get()` for `reset` fails, `sharp_nt->reset_gpio` must be reset to `NULL`. In `st7789v_prepare()`, `st7789v_check_id()` must be skipped when `SPI_NO_RX` is set and only log `dev_warn` on failure. [F31, F32, F33, F116]

## External Contracts
- Physical dimensions (`size.width`/`size.height` and `width_mm`/`height_mm`) must specify the active display area in millimeters (not module outline) matching `hdisplay` vs `vdisplay`. Controllers requiring both RGB/DPI and MCU/DBI pixel format fields (`st7789v_prepare()`, `sharp_nt_panel_init()`, `sony_td4353_jdi_on()`, `stk_panel_init()`) must pass `(fmt << 4) | fmt` to `MIPI_DCS_SET_PIXEL_FORMAT`. In `panel-sony-acx565akm.c`, `cabc_mode_store()` must reject unknown modes or non-zero modes when `!lcd->has_cabc` with `-EINVAL`. [F38, F40, F72]

## Known Pitfalls
- Stack `struct spi_transfer` instances in `st7789v_spi_write()`, `st7789v_read_data()`, and `acx565akm_transfer()` must be zero-initialized before use. `s6e63m0_dcs_write()` must reject `len == 0`, and `s6e63m0_dsi_dcs_write()` must split payloads (`remain = len - 1`, which must not exceed `U8_MAX` / 255) into chunks of at most `S6E63M0_DSI_MAX_CHUNK` (15) bytes, prefixing subsequent chunks with an `MCS_GLOBAL_PARAM` (`0xb0`) write of `u8 cmdwritten`. [F35, F67, F87]

## Other
- In `panel_simple_wait()`, `ktime_to_ms(ktime_sub(min_ktime, now_ktime))` must be incremented by `1` before calling `msleep()` so sub-millisecond truncation does not wake up early. [F88]
