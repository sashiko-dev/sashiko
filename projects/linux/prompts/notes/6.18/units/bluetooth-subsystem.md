# BLUETOOTH SUBSYSTEM

This unit implements Bluetooth HCI event packet processing (`hci_event.c`), the `PF_BLUETOOTH`/`BTPROTO_HCI` socket layer (`hci_sock.c`), the Bluetooth Management (`mgmt`) protocol (`mgmt.c`, `mgmt_util.c`, `mgmt_config.c`), and the Microsoft vendor-specific HCI extension (`msft.c`).

## Architecture & Data Flow
- On connection teardown (`hci_le_big_sync_lost_evt`, `hci_disconn_complete_evt`, `hci_cs_disconnect`) or `mgmt_connect_failed`, pass `test_and_clear_bit(HCI_CONN_MGMT_CONNECTED, &conn->flags)` to `mgmt_device_disconnected` before `hci_conn_del` (and instead of `MGMT_EV_CONNECT_FAILED` if set). In `hci_cs_disconnect`, if `hdev->suspended` is true, immediately set `conn->state = BT_CLOSED` before `mgmt_device_disconnected`, `hci_disconn_cfm`, and `hci_conn_del`. [F49, F50, F185]
- Before accessing `conn->iso_qos.ucast` (a union with `bcast`), event handlers (`hci_unbound_cis_failed`, `hci_le_cis_established_evt`) must verify `conn->type == CIS_LINK`. In `hci_le_big_sync_established_evt`, when `!ev->status`, set `bis->state = BT_CONNECTED`, `HCI_CONN_BIG_SYNC`, and call `hci_debugfs_create_conn` and `hci_conn_add_sysfs` before `hci_iso_setup_path`; in `hci_le_big_info_adv_report_evt`, set `pa_sync->iso_qos.bcast.encryption` before `hci_connect_cfm`. [F42, F47, F52]
- Do not clear `HCI_LE_ADV` when a single extended advertising set is disabled/terminated if any `adv_info` in `hdev->adv_instances` has `adv->enabled`, and check `list_empty(&hdev->adv_instances)` before `hci_disable_advertising_sync` in `mesh_send_done_sync` and `remove_advertising_sync`. Call `cancel_adv_timeout(hdev)` whenever `hdev->cur_adv_instance` is modified or expired. [F59, F186, F200]
- In `le_set_scan_enable_complete`, `LE_SCAN_ENABLE` must only call `clear_pending_adv_report` and `hci_discovery_set_state(hdev, DISCOVERY_FINDING)` when `hdev->le_scan_type == LE_SCAN_ACTIVE`; `LE_SCAN_DISABLE` must cancel `hdev->le_scan_disable` and flush any pending report via `mgmt_device_found`. In `set_scan_params` and `set_mesh`, the endian-converted scan interval/period and window must be in `0x0004..0x4000` with `window <= interval` (`period`). [F53, F209]
- In `hci_cc_read_buffer_size` and `hci_cc_le_read_buffer_size{_v2}`, setting `*_pkts` must initialize the matching `*_cnt` counter, and reject `!hdev->acl_mtu || !hdev->acl_pkts` or non-zero `hdev->le_mtu < HCI_MIN_LE_MTU` with `HCI_ERROR_INVALID_PARAMETERS`. In `hci_num_comp_pkts_evt` and `hci_cc_delete_stored_link_key`, clamp unsigned `conn->sent` and `hdev->stored_num_keys` to 0 on subtraction and clamp `hdev->*_cnt` to `hdev->*_pkts` on addition. [F54, F70, F103]
- Access controller quirks and `dev_flags` via `hci_test_quirk` and `hci_dev_*_flag` (never `test_bit` on `&hdev->flags`), and verify `page < HCI_MAX_PAGES` before indexing `hdev->features[page]` (`hci_cc_read_local_ext_features`) or `conn->features[page]` (`hci_remote_ext_features_evt`). [F71, F244]
- `hci_mgmt_cmd` and `hci_logging_frame` must check `skb->len >= sizeof(*hdr)` (or `+ 3`) before unsigned subtraction `skb->len - sizeof(*hdr)`. For `HCI_MGMT_VAR_LEN` handlers, the handler must verify exact `len`: array handlers (`load_link_keys`, `load_irks`, `load_long_term_keys`, `load_conn_param`, `set_blocked_keys`, `start_service_discovery`) must bound `count <= (U16_MAX - sizeof(*cp)) / sizeof(elem)` and check `struct_size == len`; `mgmt_hci_cmd_sync` must check `len == offsetof(..., params) + le16_to_cpu(cp->params_len)`; `add_adv_patterns_monitor{_rssi}` and `add_advertising` must validate total `len` and pattern/TLV bounds (`HCI_MAX_EXT_AD_LENGTH`, `tlv_data_is_valid`). [F76, F77, F102, F203, F204, F206, F208, F268]
- Because `read_ext_controller_info` and `read_ext_index_list` replace legacy CoD/name and index event flags with `HCI_MGMT_EXT_INFO_EVENTS` and `HCI_MGMT_EXT_INDEX_EVENTS` on `sk`, every CoD/name/appearance change must call `ext_info_changed`, and `mgmt_index_added`/`mgmt_index_removed` must emit both legacy and extended index events while skipping `HCI_QUIRK_RAW_DEVICE` controllers (as must `read_{,unconf_,ext_}index_list`). [F194, F195, F252, F272]
- `hdev->advmon_pend_notify` must stay synced with `hdev->monitored_devices`: `msft_device_found` sets it `true`, `msft_resume_sync`/`msft_do_close` clear it, and `mgmt_adv_monitor_device_found` must set it back to `true` if any remaining entry has `!dev->notified` (never breaking early on the first `bdaddr` match). `mgmt_send_adv_monitor_device_found` must run before `mgmt_event_skb` pushes `struct mgmt_hdr`. [F201, F229, F235]

## Synchronization
- Event, LE subevent, CC, and CS callbacks are entered without `hdev->lock` and must release any `hci_dev_lock(hdev)` they acquire. Because `hci_conn_hash_lookup_*` drops `rcu_read_unlock()` before returning an unreferenced `struct hci_conn *`, event handlers (e.g., `hci_num_comp_pkts_evt` calling `hci_conn_tx_dequeue`) and helpers `check_pending_le_conn`, `process_adv_report`, and `hci_unbound_cis_failed` must hold `hci_dev_lock(hdev)`. Loops deleting from `conn_hash.list` or `adv_instances` must use `list_for_each_entry_safe` under `hdev->lock`, and BIS loops (`hci_le_create_big_complete_evt`, `hci_le_big_sync_lost_evt`) that sleep or delete must hold `hci_dev_lock(hdev)` and loop on `hci_conn_hash_lookup_big_state`. [F12, F22, F23, F93, F121]
- Lock hierarchy: `lock_sock(sk)` nests outside `mgmt_chan_list_lock`, `hdev->lock`, `hci_dev_list_lock`, and `hci_sk_list.lock` (`hci_sock_ioctl` must drop `lock_sock(sk)` before unbound device ioctls); `hdev->req_lock` -> `hdev->lock` -> `msft->filter_lock`, and `hdev->lock` -> `hdev->mgmt_pending_lock`. Never hold `hdev->lock` or `msft->filter_lock` across `__hci_cmd_sync`, and `mgmt_pending_foreach` callbacks (which hold `mgmt_pending_lock`) must never acquire `mgmt_pending_lock` or `hci_dev_lock`. [F127, F168, F259, F261]
- Allocations under `read_lock(&hci_sk_list.lock)` or `read_lock(&hci_dev_list_lock)` must use `GFP_ATOMIC`, and `mgmt_cmd_complete` (`GFP_KERNEL`) must only be called after `read_unlock(&hci_dev_list_lock)`. Serialize all `mgmt_chan_list` accesses and `hci_mgmt_cmd` under `mgmt_chan_list_lock`. [F126, F128, F257]
- In `mgmt.c`, `hci_cmd_sync` work callbacks for `hdev->mgmt_pending` commands must check `__mgmt_pending_listed` under `hdev->mgmt_pending_lock`, copy parameters from `cmd->param`/`cmd->user_data` (never reading `hdev` fields like `hdev->dev_name` updated after `hci_cmd_sync_queue`), and return `-ECANCELED` if unlinked; completion callbacks must return before `hci_dev_lock(hdev)` if `err == -ECANCELED` or `!mgmt_pending_valid(hdev, cmd)`, then call `mgmt_pending_free(cmd)`. Async callbacks (`add_device_complete`, `disconnect_sync`, `unpair_device_sync`, `get_conn_info_sync`, `get_clock_info_sync`) must re-lookup `hci_conn_params` or `hci_conn` by address rather than caching pointers. [F160, F161, F163, F188]
- Before sending `HCI_OP_READ_ENC_KEY_SIZE` in `hci_read_enc_key_size`, pre-populate `conn->enc_key_size`, and in `hci_cc_read_enc_key_size` reject smaller key sizes by clearing `HCI_CONN_ENCRYPT` and `HCI_CONN_AES_CCM` and setting `status = HCI_ERROR_AUTH_FAILURE`. In `hci_conn_complete_evt` and `le_conn_complete_evt`, verify `conn->state == BT_CONNECT` on any looked-up `HCI_ROLE_MASTER` `hci_conn`. [F16, F17, F55]
- `hci_sock_bind` must finish initializing `hci_pi(sk)` under `lock_sock(sk)` before setting `sk->sk_state = BT_BOUND`. In `set_powered`, power-off (`cp->val == 0`) must call `hci_cmd_sync_cancel_sync(hdev, -EHOSTDOWN)` before queueing `set_powered_sync`. [F15, F262]

## Object Lifetimes
- In `hci_le_big_sync_established_evt`, when `ev->status != 0x42` and `HCI_CONN_PA_SYNC` is set on a `BIS_LINK` `bis`, clear `conn->cleanup = NULL` on the temporary `PA_LINK` `conn` (while setting `HCI_CONN_PA_SYNC`, `HCI_CONN_BIG_SYNC`, `bis->sync_handle = conn->sync_handle`, and `iso_qos` on each `bis`). [F1, F98]
- `hci_conn` references: implicit auto-connect in `check_pending_le_conn` (`!params->explicit_connect`) stores `hci_conn_get(conn)` in `params->conn`, which `le_conn_complete_evt` must release via `hci_conn_drop`, `hci_conn_put`, and `params->conn = NULL`; entering `BT_CONFIG` in `hci_conn_complete_evt`/`le_conn_complete_evt` takes `hci_conn_hold(conn)` that must be balanced by `hci_conn_drop(conn)` when `BT_CONFIG` finishes or fails; in `pair_device`, error before `cmd->user_data = hci_conn_get(conn)` requires `hci_conn_drop(conn)`, and `pairing_complete` must clear `conn->{connect,security,disconn}_cfm_cb` and call both `hci_conn_drop` and `hci_conn_put`. [F2, F10, F150]
- In `hci_sock_bind`, if `hci_pi(sk)->hdev` has `HCI_UNREGISTER`, clear `hci_pi(sk)->hdev = NULL`, set `sk->sk_state = BT_OPEN`, and call `hci_dev_put(hdev)` before checking `BT_BOUND`. For `HCI_CHANNEL_USER`, if `hci_dev_open` fails (`!= -EALREADY`), roll back by clearing `HCI_USER_CHANNEL`, calling `mgmt_index_added(hdev)`, and calling `hci_dev_put(hdev)`; in `hci_sock_release`, call `hci_dev_do_close`, clear `HCI_USER_CHANNEL`, and call `mgmt_index_added` only if `!hci_dev_test_flag(hdev, HCI_UNREGISTER)`, while always decrementing `hdev->promisc` and calling `hci_dev_put(hdev)`. [F4, F5, F20, F119]
- SKB ownership: `hci_event_packet` frees `skb` at `done:` (event/CC callbacks must never call `kfree_skb(skb)`, and `orig_skb = skb_clone(skb, GFP_KERNEL)` must be saved before `skb_pull(skb, HCI_EVENT_HDR_SIZE)`); `sock_queue_rcv_skb(sk, skb)` transfers `skb` only on `0` (call `kfree_skb(skb)` on non-zero); `hci_send_to_sock` and `hci_send_to_monitor` must copy `skb` with `__pskb_copy_fclone` before `skb_push`. [F14, F57, F135, F137]
- `mgmt_pending_cmd`: `mgmt_pending_add` commands must be unlinked via `mgmt_pending_remove` or `mgmt_pending_valid` before `mgmt_pending_free`; when `mgmt_pending_foreach` has `remove = true`, it unlinks and frees `cmd` itself, so callbacks (`cmd_complete_rsp`, `pairing_complete`, `addr_cmd_complete`, `generic_cmd_complete`) must not call `mgmt_pending_remove`/`free`, and `cmd_complete_rsp` must call `hci_cmd_sync_dequeue(match->hdev, NULL, cmd, NULL)` first. `__mgmt_power_off` must drain `hdev->mgmt_pending` before connection teardown or `mgmt_index_removed`, and `mgmt_index_removed` must only cancel `discov_off`, `service_cache`, and `rpa_expired` if `HCI_MGMT` is set. [F146, F148, F162, F165, F256]
- Adv monitors and MSFT: `__add_adv_patterns_monitor` must call `hci_free_adv_monitor(hdev, m)` on error, and `mgmt_add_adv_patterns_monitor_complete` increments `adv_monitors_cnt` only when `!status`. During MSFT suspend/resume, set `msft->suspending`/`resuming` so `msft_le_cancel_monitor_advertisement_cb` only frees `monitor` and calls `msft_monitor_device_del` when `!msft->suspending` (while `msft_le_monitor_advertisement_cb` frees `monitor` under `hdev->lock` on error). In `msft_remove_addr_filters_sync`, set `AF_STATE_ADDING` filters to `AF_STATE_REMOVING` without freeing or moving them to `head`, and check `hdev->msft_data && test_bit(HCI_UP, &hdev->flags)` in `msft_{add,cancel}_address_filter_sync` before dereferencing `address_filter`. `msft_do_close` must free `handle_map` and `address_filters` locally without HCI commands and reset offloaded monitors to `ADV_MONITOR_STATE_REGISTERED`. [F151, F155, F156, F170, F171, F246]

## API Contracts
- `hci_hdev_from_sock(sk)` returns a borrowed `hdev` or `ERR_PTR` (never `NULL`); callers must hold `lock_sock(sk)`, check `IS_ERR(hdev)`, and never call `hci_dev_put(hdev)`. In `hci_mgmt_cmd`, `hdev = hci_dev_get(index)` is owned by `hci_mgmt_cmd` (can be `NULL` for `MGMT_INDEX_NONE`, so guard `if (hdev && chan->hdev_init)` and jump to `done:` for `if (hdev) hci_dev_put(hdev)`). [F7, F8, F30, F33]
- In `hci_sock_sendmsg`, `hci_logging_frame` and `hci_mgmt_cmd` borrow `skb` and jump to `drop:`, whereas `HCI_CHANNEL_RAW`/`USER` queue `skb` onto `raw_q`/`cmd_q` (and non-vendor `ogf != 0x3f` `HCI_COMMAND_PKT` on `HCI_CHANNEL_RAW` must set `hci_skb_opcode(skb)` and `HCI_REQ_START`). `mgmt_send_event_skb` and `mgmt_event_skb` require an `skb` from `mgmt_alloc_skb` and consume it via `kfree_skb(skb)`, whereas `mgmt_send_adv_monitor_device_found` borrows `skb`. [F6, F134, F145, F265]
- `hci_event_func`, `hci_le_meta_evt`, and `hci_cc_func` already pull `min_len` (`sizeof(*ev)`), so variable-length handlers must pull trailing bytes via `hci_ev_skb_pull`, `hci_le_ev_skb_pull`, or `hci_cc_skb_pull` using `flex_array_size` (never `struct_size`), and check the return (and `hci_sent_cmd_data`) for `NULL`. In `hci_le_{ext_}adv_report_evt`, pull `sizeof(*info)` first and then `info->length + 1` (legacy) or `info->length` (extended) on each iteration. [F37, F39, F66, F105, F106]
- `hci_cc_func` and `hci_cc_table` callbacks return a `u8` HCI status (`0x00` or `HCI_ERROR_*`, never negative errno). `hci_{,sync_}conn_complete_evt` and `le_conn_complete_evt` must abort `hci_debugfs_create_conn` and `hci_conn_add_sysfs` if `!HCI_CONN_HANDLE_UNSET(conn->handle)` or `hci_conn_set_handle(conn, handle)` is non-zero. [F38, F43]
- Management handlers that can run while powered off (`set_powered` on, `add_uuid`, `remove_uuid`, `set_dev_class`, `remove_adv_monitor`) must use `hci_cmd_sync_submit` rather than `hci_cmd_sync_queue`. `hci_mgmt_cmd` must check `hci_sock_test_flag(sk, HCI_SOCK_TRUSTED)` for handlers without `HCI_MGMT_UNTRUSTED`, and `hci_sock_ioctl` must use `sk_capable(sk, CAP_NET_ADMIN)` when setting `HCI_SOCK_TRUSTED`. [F142, F143, F164]

## Error Handling
- `hci_conn_add{_unset}`, `hci_connect_le{_scan}`, `hci_connect_acl`, and `hci_add_adv_instance` return `ERR_PTR` (never `NULL`, though `check_pending_le_conn` must check `!IS_ERR(conn)` and return `NULL` on error), whereas `hci_conn_hash_lookup_*`, `hci_conn_params_add`, and `mgmt_alloc_skb` return `NULL`. In `set_default_phy_complete` and `read_local_oob_{ext_}data_complete`, check both `!skb` and `IS_ERR(skb)` on `cmd->skb`; in `msft_add_address_filter_sync`, set `skb = NULL` on `IS_ERR(skb)` before `goto done`. [F40, F41, F174, F175, F176, F177]
- `mgmt_status(int err)` maps `err < 0` as kernel errnos and `err >= 0` as HCI status codes, so never store a negative errno in `u8` before calling `mgmt_status()`. `hci_sock_setsockopt{_old}` must use `copy_safe_from_sockptr()` rather than `copy_from_sockptr()`. [F31, F173]

## External Contracts
- MGMT contracts: `link_to_bdaddr` maps `CIS_LINK`, `BIS_LINK`, `PA_LINK`, and `LE_LINK` to LE address types while `mgmt_device_disconnected` only emits events for `ACL_LINK`, `LE_LINK`, and `BIS_LINK`; BR/EDR link keys use `BDADDR_BREDR` and SMP LE keys use LE address types while skipping debug keys (`MGMT_LTK_P256_DEBUG`, `HCI_LK_DEBUG_COMBINATION`); `read_exp_features_info` and `set_exp_feature` must handle `hdev == NULL`; `set_def_system_config` must validate all TLVs in a first pass before mutating `hdev`. [F179, F228, F267, F270, F274]

## Known Pitfalls
- In `ext_evt_type_to_legacy`, mask out `LE_EXT_ADV_DATA_STATUS_MASK` before testing `!evt_type` and check `LE_EXT_ADV_DIRECT_IND` before returning `LE_ADV_IND`. In `process_adv_report`, gate `direct_addr` RPA/IRK validation on `!hci_dev_test_flag(hdev, HCI_MESH) && direct_addr && hci_dev_test_flag(hdev, HCI_PRIVACY)`, and keep `!ext_adv` on the inner `store_pending_adv_report` check (never the outer `!has_pending_adv_report(hdev)` branch). [F82, F83, F84]
- Bound `hdev->dev_name`, `hdev->short_name`, and `ev->name` (`hci_remote_name_evt`) with `strnlen` and `sizeof(hdev->dev_name)`/`short_name`. In `eir_has_uuids`, check `field_len == 0` and `eir_len - parsed < field_len + 1` and use additive loop bounds (`i + elem_size <= field_len`). In `msft_monitor_device_evt`, under `HCI_QUIRK_USE_MSFT_EXT_ADDRESS_FILTER` queue `msft_add_address_filter` on pattern matches instead of reporting state, and record `address_filters` matches in a separate `address_filter = NULL` pointer; in `msft_suspend_sync` and `reregister_monitor`, increment `handle++` in the `idr_get_next` loop. [F111, F215, F223, F224, F233, F250]
