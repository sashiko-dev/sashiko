# POWER MANAGEMENT CORE

This unit comprises the power capping (`powercap`) subsystem core, the CPU idle injection framework (`idle_inject`), the Intel/AMD Running Average Power Limit (`intel_rapl`) common core and its MSR/TPMI interface drivers, and core headers for runtime PM (`pm_runtime.h`), PM QoS (`pm_qos.h`), wakeup sources (`pm_wakeup.h`), wake IRQs (`pm_wakeirq.h`), and PM clocks (`pm_clock.h`).

## Architecture & Data Flow

- `pm_qos_constraints.target_value`, `pm_qos_flags_request.flags`, and `pm_qos_flags.effective_flags` must remain 32-bit `s32` types and never be widened to 64-bit, because the lockless PM QoS read path relies on single-instruction atomic 32-bit loads across all architectures. [F26]
- In `struct rapl_package`, `domain_map` must remain `unsigned long` for `bitmap_weight()` and `test_bit()`. `rp->domains` is a dense array of length `rp->nr_domains` containing only active domains, so perf PMU callbacks must index `rp->domains` using `event->hw.idx` (after checking `event->hw.idx >= 0`), whereas `rp->pmu_data.scale[RAPL_DOMAIN_MAX]` is indexed by `enum rapl_domain_type` (`event->hw.flags`). [F73, F109]
- In `intel_rapl_common.c`, powercap `constraint_ops` callbacks receive a dense constraint index `cid` (`0` to `find_nr_power_limit(rd) - 1`) and must translate `cid` via `contraint_to_pl(rd, cid)` before indexing `rd->rpl[]` or calling `rapl_read_pl_data()` / `rapl_write_pl_data()`. [F54]
- `rp->lead_cpu` is `-1` when added with `id_is_cpu == false`, so `get_rid()`, `rapl_init_domains()`, `package_power_limit_irq_save()`, and `package_power_limit_irq_restore()` must check `rp->lead_cpu >= 0` first. In `rapl_cpu_down_prep()`, if clearing `cpu` from `rp->cpumask` leaves it empty (`lead_cpu >= nr_cpu_ids`), `rapl_remove_package_cpuslocked(rp)` must run before invalidating `rp->lead_cpu`; otherwise if `rp->lead_cpu == cpu`, update `rp->lead_cpu = lead_cpu`. [F33, F52]
- When `id_is_cpu` is true in `rapl_find_package_domain_cpuslocked()` and `rapl_add_package_cpuslocked()`, the package ID must come from `topology_physical_package_id(id)` when `rapl_msrs_are_pkg_scope()` (`X86_VENDOR_AMD` or `X86_VENDOR_HYGON`) and `topology_logical_die_id(id)` otherwise, rejecting negative IDs. [F121]
- `get_rpi()` must reject `prim < 0 || prim >= NR_RAPL_PRIMITIVES`. `rapl_read_data_raw()` and `rapl_write_data_raw()` must map `prim` via `prim_fixups(rd, prim)` before `get_rpi()`, and `write_raw` callbacks (`rapl_msr_update_func`, `tpmi_rapl_write_raw`) must do a masked read-modify-write (`(val & ~ra->mask) | ra->value`). In `rpi_msr` and `rpi_tpmi`, `mask` must be pre-shifted by `shift`. [F37, F61, F68]
- `POWER_LIMIT1`..`POWER_LIMIT4` must be contiguous at the start of `enum rapl_primitives` with `NR_POWER_LIMITS == POWER_LIMIT4 + 1` for `rd->rpl[]`, `pl_names[]`, and `is_pl_valid()`. `rapl_detect_powerlimit()` must probe presence using `PL_LIMIT` rather than `PL_ENABLE`, and `rpi_msr[]` must not define `PL4_ENABLE` because `MSR_VR_CURRENT_CONFIG` has no enable bit. [F72, F120]
- Modifying `enum rapl_domain_type` requires updating `rapl_domain_names[]`, `zone_ops[]`, and `rapl_check_domain()` in exact enum order. In `enum tpmi_rapl_register`, every hardware register (including reserved slots) must stay in exact architectural order up to `TPMI_RAPL_REG_MAX = 15`, as `parse_one_domain()` uses `reg_index` as both `BIT(reg_index)` in `tpmi_domain_flags` and the 8-byte MMIO offset. [F64, F69]
- `parse_one_domain()` must reject `TPMI_VERSION_INVALID` and `TPMI_MAJOR_VERSION != TPMI_RAPL_MAJOR_VERSION` with `-ENODEV` (allowing newer minor versions), require `tpmi_domain_size == 1`, `BIT(TPMI_RAPL_REG_UNIT)` and `BIT(TPMI_RAPL_REG_ENERGY_STATUS)`, and reject duplicate `domain_type` entries. For `TPMI_RAPL_DOMAIN_SYSTEM`, `BIT(TPMI_RAPL_REG_DOMAIN_INFO)` is required, and if `TPMI_RAPL_DOMAIN_ROOT` is clear, return `0` without registering `RAPL_DOMAIN_PLATFORM`. [F70, F118, F119]
- `power_limit_irq_save_cpu()` must only record `PACKAGE_THERM_INT_PLN_ENABLE` in `rp->power_limit_irq` when `PACKAGE_PLN_INT_SAVED` is not yet set, and `package_power_limit_irq_restore()` must only restore `MSR_IA32_PACKAGE_THERM_INTERRUPT` when `PACKAGE_PLN_INT_SAVED` is set. In `power_limit_state_save()`, if `rapl_read_pl_data()` fails, clear `rd->rpl[i].last_power_limit = 0` so `power_limit_state_restore()` does not write a stale limit. [F62, F63]
- In `rapl_pmu_update()`, skipping `perf_pmu_unregister()`/`perf_pmu_register()` requires `rapl_pmu.registered && !(rp->domain_map & (~rapl_pmu.domain_map))`, ensuring re-registration whenever a new package supports domain bits not yet in `rapl_pmu.domain_map`. [F91]
- In `powercap_class` callbacks (`powercap_release()`, `enabled_show()`, `enabled_store()`), `dev->parent != NULL` discriminates `to_powercap_zone(dev)` from `to_powercap_control_type(dev)` (whose optional `ops` must be NULL-checked). `powercap_register_zone()` and `powercap_unregister_zone()` must update `control_type->nr_zones` under `control_type->lock` so `powercap_unregister_control_type()` rejects unregistration while `nr_zones != 0`. [F30, F46]
- Constraint sysfs attribute names in `create_constraint_attribute()` must start with `"constraint_%d_"` (parsed via `sscanf()`), callbacks must check `id < power_zone->const_id_cnt` before indexing `power_zone->constraints[id]`, and `show_constraint_name()` must cap names to `POWERCAP_CONSTRAINT_NAME_LEN - 1`. Adding zone/constraint attributes requires updating `POWERCAP_ZONE_MAX_ATTRS`, `POWERCAP_CONSTRAINTS_ATTRS`, `seed_constraint_attributes()`, `free_constraint_attributes()`, and `create_constraints()` in lockstep. [F49, F77, F107]

## Synchronization

- Accesses to `rapl_packages` and `rp->lead_cpu` require the CPU hotplug lock: callers outside cpuhp callbacks must use `rapl_find_package_domain()`, `rapl_add_package()`, or `rapl_remove_package()` (or hold `cpus_read_lock()`), whereas cpuhp callbacks must call the `_cpuslocked` variants. Powercap sysfs callbacks in `intel_rapl_common.c` that access hardware via `rd->rp` must also hold `cpus_read_lock()`. [F18, F19]
- Under `rapl_package_pmu_data.lock`, `__rapl_pmu_event_start()` and `rapl_pmu_event_stop()` must update `event->hw.state`, `data->active_list`, `data->n_active`, and `data->hrtimer` (`0 <-> 1`) in lockstep. Because `event_read_counter()` is called under `raw_spin_lock_irqsave(&data->lock, flags)`, `rp->priv->read_raw()` on PMU-enabled interfaces (`RAPL_IF_TPMI`) must be non-blocking and IRQ-safe. [F57, F141]
- `rapl_event_update()` must update `event->hw.prev_count` via `local64_try_cmpxchg()` and accumulate `event->count` via `local64_add()` because `rapl_pmu_event_read()` calls it without `rapl_package_pmu_data.lock`, racing with `rapl_hrtimer_handle()` and `rapl_pmu_event_stop()`. [F21]
- All reads and writes to `idle_inject_device.run_duration_us`, `idle_duration_us`, and `latency_us` must use `READ_ONCE()` and `WRITE_ONCE()` because they are read locklessly by `idle_inject_timer_fn()` (hardirq) and `idle_inject_fn()` (kthread) while updated via `idle_inject_set_duration()` or `idle_inject_set_latency()`. [F13]
- `pm_runtime_mark_last_busy()` must use `ktime_get_mono_fast_ns()` rather than `ktime_get()` because runtime PM resume can run while the timekeeping seqcount write lock is held. Traversing wakeup sources with `for_each_wakeup_source()` requires holding `wakeup_sources_read_lock()` / `wakeup_sources_read_unlock()`. [F128, F133]

## Object Lifetimes

- When passing a pre-allocated `power_zone` or `control_type` to `powercap_register_*()`, `ops->release` must be non-NULL because `powercap_release()` only calls `kfree()` when `allocated` is true. In `powercap_release()`, all internal fields (`allocated`, `parent_idr`, `idr`, `lock`, `name`, `zone_dev_attrs`, `constraints`) must be read and destroyed before calling `ops->release()`, which may immediately free the enclosing struct. [F1, F2]
- `RAPL_DOMAIN_PACKAGE` (`0`) must remain at `rp->domains[0]` and be unregistered last in `rapl_package_register_powercap()` and `rapl_remove_package_cpuslocked()`, because `release_zone()` frees the `rp->domains` array via `kfree(rd)` when `rd->id == RAPL_DOMAIN_PACKAGE` and sets `rp->domains = NULL` to prevent double-free on rollback; `kfree(rp)` must not occur before `release_zone()` runs. [F6, F74]
- `rapl_package_add_pmu()` must initialize `data->scale[]`, `data->lock`, `data->active_list`, `data->timer_interval`, and `data->hrtimer` before `rapl_pmu_update(rp)` sets `rp->has_pmu = true`. On teardown (`intel_rapl_tpmi_remove()`), `rapl_package_remove_pmu(trp->rp)` must precede `rapl_remove_package(trp->rp)` (zeroing `rapl_pmu` when the last PMU package is removed), which must precede `trp_release(trp)`. In `rapl_msr_remove()`, `cpuhp_remove_state()` must precede `powercap_unregister_control_type()`. [F7, F8, F22, F58, F60]
- `rapl_msr_write_raw()` must call `smp_call_function_single()` with `wait = 1` because `rapl_write_data_raw()` passes a stack-allocated `struct reg_action` accessed on the target CPU by `rapl_msr_update_func()`. [F110]
- `idle_inject_register_full()` must allocate `sizeof(*ii_dev) + cpumask_size()` bytes, and if a CPU in `cpumask` already has `per_cpu(idle_inject_device, cpu)` set, rollback must only clear CPUs up to `cpu` (`cpu == cpu_rb`). `idle_inject_unregister()` must call `idle_inject_stop(ii_dev)` (which cancels `ii_dev->timer` before `cpu_hotplug_disable()` and iterates over `for_each_cpu()` in `ii_dev->cpumask`, including offline CPUs, to clear `iit->should_run` and `wait_task_inactive()`) before clearing `per_cpu(idle_inject_device, cpu)` and freeing `ii_dev`. [F9, F10, F12, F81]

## API Contracts

- `powercap_register_control_type()`, `powercap_register_zone()`, and `rapl_add_package*()` always return `ERR_PTR()` on failure and never `NULL` (despite header comments), whereas `rapl_find_package_domain*()` and `idle_inject_register*()` always return `NULL` (never `ERR_PTR()`). [F28, F32, F41]
- Powercap sysfs handlers invoke `powercap_zone_ops` and `powercap_zone_constraint_ops` without holding `control_type->lock`, so drivers must synchronize callbacks internally. `create_constraints()` requires non-NULL `const_ops` and its `get/set_power_limit_uw` and `get/set_time_window_us` callbacks even when `nr_constraints == 0`, and `nr_constraints <= MAX_CONSTRAINTS_PER_ZONE` (10). [F17, F145]
- Callers of `rp->priv->read_raw()` must initialize both `ra.reg` and `ra.mask` in `struct reg_action`. Unlike `package_power_limit_irq_save()`, `package_power_limit_irq_restore()` writes `MSR_IA32_PACKAGE_THERM_INTERRUPT` on the local CPU and must only run on the package's CPU. `get_pmu_cpu()` returns `nr_cpu_ids` on failure, so callers (`cpumask_show()`) must check `cpu < nr_cpu_ids`. [F35, F40, F142]
- Callers of `idle_inject` must externally serialize `idle_inject_start()`, `idle_inject_stop()`, and `idle_inject_unregister()`. `idle_inject_set_duration()` and `idle_inject_set_latency()` take microseconds, `run_duration_us + idle_duration_us > 0` must be set before `idle_inject_start()`, and the `update` callback in `idle_inject_register_full()` runs in hardirq context (`idle_inject_timer_fn()`) and must not sleep. [F14, F42, F134]
- `__pm_runtime_resume()` and `pm_runtime_get_sync()` return `1` when already active, `0` on synchronous resume, or `< 0` while leaving `usage_count` incremented; `pm_runtime_resume_and_get()` drops `usage_count` on `< 0` and normalizes `1` to `0`. `pm_runtime_suspended(dev)` requires `!dev->power.disable_depth`, whereas `pm_runtime_active(dev)` is `true` when disabled or `RPM_ACTIVE`; both and `pm_runtime_status_suspended()`/`pm_runtime_enabled()` are unlocked reads requiring `dev->power.lock` or stable state. [F27, F43, F92]
- `pm_runtime_set_active()`/`pm_runtime_set_suspended()` require runtime PM to be disabled, manual `pm_runtime_use_autosuspend()` must be paired with `pm_runtime_dont_use_autosuspend()`, and `pm_runtime_blocked()` is restricted to system suspend/resume. In atomic/cpuidle paths (`PREEMPT_RT`), use `dev_pm_qos_raw_resume_latency()` rather than `dev_pm_qos_read_value()`, which also triggers `WARN_ON(1)` on `DEV_PM_QOS_LATENCY_TOLERANCE` or `DEV_PM_QOS_FLAGS` when `!CONFIG_PM`. [F126, F129, F132, F158]

## Error Handling

- In `powercap_register_zone()`, after `idr_alloc()` sets `result >= 0`, reset `result = -ENOMEM` before jumping to error labels; call `dev_set_name()` only after all pre-registration allocations succeed right before `device_register(&power_zone->dev)`, and clean up `device_register()` failure via `put_device(&power_zone->dev)`. [F3, F31]
- `rapl_config()` must NULL-check `rp->priv->defaults` and `rp->priv->rpi`, and `set_domain_enable()` must NULL-check `defaults->set_floor_freq`. Because `rapl_write_data_raw()` does not check `ra.reg.val`, `tpmi_rapl_write_raw()` must return `-EINVAL` if `!ra->reg.mmio`. `rapl_write_pl_data()` must log BIOS-locked (`rd->rpl[pl].locked`) writes with `pr_debug()` and return `-EACCES`, and `parse_one_domain()` must log invalid MMIO headers with `pr_warn(FW_BUG ...)` without `WARN_ON()`. [F34, F36, F151, F152]

## External Contracts

- `dev_attr_energy_uj.attr.mode` in `create_power_zone_common_attributes()` must only grant access to root (`S_IRUSR` or `S_IWUSR | S_IRUSR`), never `S_IRUGO`. Writing `0` to `energy_uj` in `define_power_zone_store` calls `reset_energy_uj()`, while non-zero unsigned integers must be silently ignored and return `count`. In `rapl_pmu_event_init()`, validate `1 <= (event->attr.config & RAPL_EVENT_MASK) < PERF_RAPL_MAX` and `event->cpu >= 0` before indexing `event_to_domain[]`. [F78, F148, F155]

## Known Pitfalls

- `powercap_register_zone()` and `powercap_register_control_type()` `memset()` pre-allocated structs to zero, so fields like `power_zone->private_data` (`powercap_set_zone_data()`) must be set only after registration. In `set_domain_enable()`, read back `PL_ENABLE` after writing it to verify `mode == val` before calling `defaults->set_floor_freq(rd, mode)`. In `parse_one_domain()`, the `while (++reg_index != TPMI_RAPL_REG_MAX)` loop must `continue` (not `break`) on unmapped `switch (reg_index)` cases. [F47, F86, F117]
- Prevent 32-bit overflow and UB: in `rapl_compute_time_window_core()`, return `0` when `value < rd->time_unit` before `ilog2()` and clamp `y > 0x1f` to `0x7f` before `1ULL << y`; in `pm_qos.h`, cast `s32` microsecond limits to `s64` before `* NSEC_PER_USEC`; in `intel_rapl_common.c`, use `ULL`/`BIT_ULL()` for `rapl_primitive_info.mask` bits 31..63 and `u64` math (`1ULL << 32`) for `data->scale[domain]` and `max_count` in `rapl_package_add_pmu()`. [F79, F94, F95, F100]
