# KDUMP

The KDUMP component implements kernel crash dump preparation, memory reservation, panic-time kexec transition, and post-crash dump extraction via `/proc/vmcore`. In the primary kernel, it parses `crashkernel=` boot parameters, reserves physical/CMA memory, prepares ELF64 core headers and per-CPU/vmcoreinfo notes, handles CPU and memory hotplug updates to loaded crash images, and stages dm-crypt keys via configfs. In the secondary (kdump) kernel, it parses the previous kernel's ELF headers and notes, collects optional device dumps and driver-managed RAM ranges, restores dm-crypt keys, and exposes the crash image through `/proc/vmcore`.

## Architecture & Data Flow

- In `fs/proc/vmcore.c`, `elfcorebuf` must be allocated via `__get_free_pages()` (mapped via `__pa()` and `remap_pfn_range()`), whereas `elfnotes_buf` and `vmcoredd_node->buf` must be allocated via `vmcore_alloc_buf()` (`vmalloc_user()` on `CONFIG_MMU`, mapped via `remap_vmalloc_range_partial()`). `elfcorebuf_sz_orig` must always match the page order used to allocate `elfcorebuf` (updated only in `vmcore_realloc_elfcore_buffer_elf64()`), so `free_elfcorebuf()` passes the matching order to `free_pages()` even after `elfcorebuf_sz` shrinks. [F4, F113]
- `elfcorebuf_sz`, `elfnotes_sz`, and each `vmcoredd_node`'s size (summed in `vmcoredd_orig_sz`) must be `PAGE_SIZE`-aligned so `mmap_vmcore()` stays page-aligned. Each `vmcore_range` covers `[rounddown(paddr, PAGE_SIZE), roundup(paddr + p_memsz, PAGE_SIZE))`, while `PT_LOAD` `phdr->p_offset` in `process_ptload_program_headers_elf64/32()`, `vmcoredd_update_program_headers()`, and `vmcore_reset_offsets_elf64()` must include the sub-page offset (`paddr - start`). [F43, F64]
- `__read_vmcore()` and `mmap_vmcore()` place `vmcoredd_list` device dumps at file offsets `[elfcorebuf_sz, elfcorebuf_sz + vmcoredd_orig_sz)` ahead of `elfnotes_buf` at `[elfcorebuf_sz + vmcoredd_orig_sz, elfcorebuf_sz + elfnotes_sz)`, so indexing into `elfnotes_buf` must subtract both `elfcorebuf_sz` and `vmcoredd_orig_sz`. When mutating layout after `parse_crash_elf_headers()` (in `vmcoredd_update_size()` or `vmcore_add_device_ram_elf64()`), `elfcorebuf` program headers, `vmcore_list` offsets, `vmcore_size`, and `proc_vmcore->size` must all be updated together. [F42, F44]
- When marking the crash header unusable or consumed in a kdump kernel (via `vmcore_unusable()` or `vmcore_init()`), `elfcorehdr_addr` must be set to `ELFCORE_ADDR_ERR` (`-2ULL`) rather than `ELFCORE_ADDR_MAX` (`-1ULL`) or `0`, so `is_vmcore_usable()` returns `0` while `is_kdump_kernel()` remains `true`. [F25]
- In `merge_note_headers_elf64/32()`, `update_note_header_size_elf64/32()` must run before `get_note_number_and_size_elf64/32()` and `copy_notes_elf64/32()`, and `copy_notes_elf64/32()` must run before the `nr_ptnote - 1` redundant `PT_NOTE` headers in `elfptr` are compacted in place via `memmove()` and the vacated `i` bytes at `elfptr + *elfsz` are zeroed. [F46, F93]
- `crashk_res` and `crashk_low_res` store inclusive bounds `[start, end]` when reserved and `{0, 0}` when unreserved, so size queries must use `crash_resource_size()` (`!res->end ? 0 : resource_size(res)`), and releasing or promoting them in `__crash_shrink_memory()` or `crash_shrink_memory()` must zero both `start` and `end` alongside `release_resource()`. [F50, F54]
- `crash_exclude_mem_range()` requires `mem->ranges` to be sorted in ascending address order (breaking when `p_end < start`). Splitting an entry (`p_start > start && p_end < end`) must check `mem->nr_ranges >= mem->max_nr_ranges` before mutating `mem->ranges[i]`, shift trailing elements in-place using `memmove()` with byte length `(mem->nr_ranges - (i + 1)) * sizeof(mem->ranges[i])`, and adjust `i` and `mem->nr_ranges` in lockstep on removal (`i--`, `nr_ranges--`) and split (`i++`, `nr_ranges++`). [F49, F69, F88]
- `kimage_crash_copy_vmcoreinfo()` must map the crash control page for vmcoreinfo via `vmap()` into `image->vmcoreinfo_data_copy` (via `crash_update_vmcoreinfo_safecopy()`) so `crash_save_vmcoreinfo()` can write to it during a crash without accessing the protected kernel direct mapping or calling `vmap()` in panic context. [F110]
- In `crash_notes_memory_init()`, per-CPU `crash_notes` (`note_buf_t`) must satisfy `sizeof(note_buf_t) <= PAGE_SIZE` and be allocated with alignment `min(roundup_pow_of_two(sizeof(note_buf_t)), PAGE_SIZE)` so each CPU's note buffer stays within one physical page. `crash_save_cpu()` must validate `0 <= cpu < nr_cpu_ids` before indexing `crash_notes` and terminate notes with `final_note(buf)` (`n_namesz == 0` sentinel). [F58, F123]
- In `reserve_crashkernel_generic()`, any physical memory range reserved for `crashk_res` or `crashk_low_res` must be passed to `kmemleak_ignore_phys()` because it is later removed from the linear map. In `reserve_crashkernel_cma()`, halving `request_size` on failure must use `roundup(request_size / 2, PAGE_SIZE)` after verifying `request_size > PAGE_SIZE`. [F86, F112]
- In `kernel/crash_dump_dm_crypt.c`, `key_count` must be incremented in `config_keys_make_item()` and decremented in `config_key_release()` in lockstep with item lifecycle. Because `struct keys_header::keys` is `__counted_by(total_keys)`, `get_keys_header_size()` must use `struct_size(keys_header, keys, total_keys)`, and `build_keys_header()` must set `keys_header->total_keys = key_count` before indexing `keys_header->keys[i]`. Key descriptions, payloads, and counts must be bounded against `KEY_DESC_MAX_LEN`, `KEY_SIZE_MAX`, and `KEY_NUM_MAX`. [F52, F66, F89]

## Synchronization

- In `fs/proc/vmcore.c`, read-side accesses to `vmcore_cb_list` in `read_from_oldmem()`, `pfn_is_ram()`, and `vmcore_remap_oldmem_pfn()` must be protected by `vmcore_cb_srcu` rather than `vmcore_mutex` or an `rw_semaphore`, because `mmap_vmcore()` holds `mm->mmap_lock` while `read_from_oldmem()` may fault on user memory and acquire `mm->mmap_lock`. [F104]
- In `vmcore_add_device_dump()`, the dump buffer must be allocated, initialized with `vmcoredd_write_header()`, and populated by `data->vmcoredd_callback()` before acquiring `vmcore_mutex` to check `vmcore_open` and append `dump->list` to `vmcoredd_list`. Any error path after `dump` or `buf` is allocated—including returning `-EBUSY` when `vmcore_open` is non-zero—must release `vmcore_mutex` and free both `buf` and `dump` with `vfree()`. [F1, F19]
- `crash_check_hotplug_support()` and `crash_handle_hotplug_event()` must acquire `__crash_hotplug_lock` via `crash_hotplug_lock()` before attempting `kexec_trylock()`, and release `kexec_unlock()` before `crash_hotplug_unlock()`. `crash_shrink_memory()` must hold `kexec_trylock()` continuously across verifying `!kexec_crash_image` and shrinking or swapping `crashk_res` and `crashk_low_res`. [F15, F22]
- `__crash_kexec()` may run in NMI or atomic panic context and must only be invoked when `panic_cpu` holds the current CPU (via `panic_try_start()` in `crash_kexec()`), using non-blocking `kexec_trylock()` and busy-wait `mdelay()` in `crash_cma_clear_pending_dma()` rather than sleeping primitives. `crash_cma_clear_pending_dma()` must run after `machine_crash_shutdown()` and before `machine_kexec()` whenever `crashk_cma_cnt` is non-zero. [F96, F107]
- In `__read_vmcore()`, the loop iterating over `vmcore_list` must call `cond_resched()` on every iteration (and after reading the ELF note segment) to prevent softlockups and RCU stalls in kdump environments. [F67]

## Object Lifetimes

- `unregister_vmcore_cb()` must unlink `cb->next` with `list_del_rcu()` under `vmcore_mutex` and then call `synchronize_srcu(&vmcore_cb_srcu)` after dropping `vmcore_mutex` before returning. [F18]
- `vmcore_process_device_ram()` must call `vmcore_free_ranges(&list)` when `list` overlaps an existing `vmcore_list` entry or `vmcore_add_device_ram_elf64()` fails, and must not free `list` once `vmcore_add_device_ram_elf64()` splices its `struct vmcore_range` nodes into `vmcore_list`. [F2]
- `vmcore_cleanup()` must remove `/proc/vmcore` via `proc_remove(proc_vmcore)` and set `proc_vmcore` to `NULL` before freeing `vmcore_list`, `elfcorebuf`, `elfnotes_buf`, and `vmcoredd_list`. `free_elfcorebuf()` must reset both `elfcorebuf` and `elfnotes_buf` to `NULL` after freeing them to prevent double-frees. [F5, F6]
- In `mmap_vmcore_fault()`, the page returned by `find_or_create_page()` must be both unlocked with `unlock_page(page)` and released with `put_page(page)` if `__read_vmcore()` fails, whereas on success it must be unlocked and have its reference transferred to `vmf->page` without calling `put_page(page)`. [F11]
- In `kernel/crash_reserve.c`, `crashk_res` and `crashk_low_res` must be inserted into `iomem_resource` during `reserve_crashkernel_generic()` and `reserve_crashkernel_low()` only when `HAVE_ARCH_ADD_CRASH_RES_TO_IOMEM_EARLY` is defined, and deferred to `early_initcall(insert_crashkernel_resources)` otherwise. [F97]

## API Contracts

- `crash_exclude_mem_range()`, `struct crash_mem::ranges`, `crashk_res`, `crashk_low_res`, and `crashk_cma_ranges` represent physical memory regions with inclusive `[start, end]` bounds (`size = end - start + 1`), whereas `struct vmcore_range` and `vmcore_alloc_add_range()` take `(paddr, size)` with exclusive end `paddr + size`. [F40]
- `copy_oldmem_page()`, `copy_oldmem_page_encrypted()`, `vmcore_remap_oldmem_pfn()`, `remap_oldmem_pfn_checked()`, and `remap_oldmem_pfn_range()` take the target oldmem location as a page frame number (`paddr >> PAGE_SHIFT` or `*ppos / PAGE_SIZE`) rather than a physical byte address, while taking sizes and offsets in bytes. [F41]
- `read_from_oldmem()` (and wrappers `elfcorehdr_read()`, `elfcorehdr_read_notes()`, and `dm_crypt_keys_read()`) takes `*ppos` as a physical byte address in oldmem and advances `*ppos` in-place by the bytes read, so callers re-reading from `elfcorehdr_addr` or `dm_crypt_keys_addr` must reset their local address variable before the second read. [F39]
- A `struct vmcore_cb` `.pfn_is_ram` callback must return `true` when the PFN is RAM or when the callback cannot tell, and `false` only when known not to be RAM, because `pfn_is_ram()` stops on the first `false` and substitutes zeroes. A `.get_device_ram` callback must return `PAGE_SIZE`-aligned `paddr` and `size` ranges and free any `struct vmcore_range` nodes it allocated before returning an error; `vmcore_add_device_ram_elf64()` must also check that `ehdr->e_phnum + count` fits in 16-bit `Elf32_Half`. [F3, F26, F65]
- Callers of `parse_crashkernel()` that pass a non-NULL `high` pointer must also pass a non-NULL `low_size` pointer (along with non-NULL `crash_size` and `crash_base`), because the `,high` fallback path passes `low_size` as `crash_size` to `__parse_crashkernel()`, which executes `BUG_ON(!crash_size || !crash_base)`. Early boot parameters parsed from `saved_command_line` must also register a dummy `early_param()` handler (`parse_crashkernel_dummy`). [F30, F114]

## Error Handling

- In `read_from_oldmem()`, `nr_bytes` and `tmp` must be signed `ssize_t` so that a negative errno returned by `copy_oldmem_page()` or `copy_oldmem_page_encrypted()` is not promoted to an unsigned value when evaluated in `if (tmp < nr_bytes)`. [F24]
- In `mmap_vmcore()` and `remap_oldmem_pfn_checked()`, if any partial page-range mapping call fails after prior segments have been mapped, all already-mapped bytes (`[vma->vm_start, vma->vm_start + len)` or `[from, from + len)`) must be unmapped with `do_munmap()` before returning `-EAGAIN`. [F34]
- `__parse_crashkernel()` must initialize `*crash_size = 0` and `*crash_base = 0` and return `-ENOENT` when no matching `crashkernel=` option exists versus `-EINVAL` on malformed syntax, because `parse_crashkernel()` branches specifically on `ret == -ENOENT` to fall back to `,high` or apply `DEFAULT_CRASH_KERNEL_LOW_SIZE`. [F27]
- In `reserve_crashkernel_generic()`, if `crash_base >= CRASH_ADDR_LOW_MAX` requires low memory and `reserve_crashkernel_low(crash_low_size)` returns an error, `memblock_phys_free(crash_base, crash_size)` must be called and the function must return without populating `crashk_res` or calling `kmemleak_ignore_phys()`. [F33]
- When iterating `config_keys_subsys.su_group.cg_children` in `build_keys_header()`, each `struct config_item` must be checked for `item->ci_type == &config_key_type` before downcasting with `to_config_key(item)` and checked for non-NULL `key->description` before copying with `strscpy()`, and the destination index `i` for `keys_header->keys[i]` must only be incremented after that `ci_type` filter. [F29, F78]

## External Contracts

- In `merge_note_headers_elf64/32()` and `vmcoredd_update_program_headers()`, the merged `PT_NOTE` header's `p_filesz` and `p_memsz` must equal the unpadded note size (`elfnotes_orig_sz + vmcoredd_orig_sz`), while `PT_LOAD` file offsets begin at the page-aligned `elfcorebuf_sz + elfnotes_sz`. `vmcoredd_write_header()` must populate `struct vmcoredd_header.name` and `dump_name` using `strscpy_pad()` and set `n_descsz` to `size + sizeof(vdd_hdr->dump_name)` (`data_size - sizeof(struct vmcoredd_header) + sizeof(vdd_hdr->dump_name)`). [F63, F122]
- `parse_crashkernel_mem()` rounds `system_ram` up to `SZ_128M` as `total_mem`, rejects range clauses where `end <= start` or `size >= total_mem`, and matches `total_mem` against the half-open interval `[start, end)` (`total_mem >= start && total_mem < end`). [F56]
- `configfs_dmcrypt_keys_init()` must switch `config_keys_subsys.su_group.cg_item.ci_type` from `config_keys_type` to `kdump_config_keys_type` when `is_kdump_kernel()` is true, exposing only the `restore` attribute and disabling configfs child item creation in the kdump kernel. [F127]

## Known Pitfalls

- In `update_note_header_size_elf64/32()`, `nhdr_ptr->n_namesz` and `nhdr_ptr->n_descsz` must be widened to `u64` before adding 3 for 4-byte alignment rounding so values near `UINT_MAX` do not wrap around and pass `(real_sz + sz) > max_sz`, and advancing `nhdr_ptr` by byte size `sz` requires casting `nhdr_ptr` to `char *` first. [F80, F92]
- In `mmap_vmcore()` and `mmap_vmcore_fault()`, page offsets (`vma->vm_pgoff` and `vmf->pgoff` of type `pgoff_t`) must be widened to a 64-bit integer type (`u64` or `loff_t`) before shifting left by `PAGE_SHIFT` to compute byte offsets into `/proc/vmcore`. [F82]
- In `reserve_crashkernel_generic()`, `CRASH_ADDR_LOW_MAX` is the exclusive upper bound for low memory and inclusive lower bound for high memory, so checking whether `crash_base` was allocated from high memory must use `crash_base >= CRASH_ADDR_LOW_MAX` (not `>`). [F53]
- In `read_from_oldmem()`, `offset` is initialized to `*ppos % PAGE_SIZE` before the `do { ... } while (count)` loop and must be reset to `0` (while incrementing `pfn` and `*ppos`) at the end of each iteration. In `remap_oldmem_pfn_checked()`, on `!pfn_is_ram(pos)`, any preceding RAM span (`pos > pos_start`) must be remapped before remapping `zeropage_pfn` and setting `pos_start = pos + 1`, and any trailing span must be remapped after the loop. [F71, F73]
- In `parse_crashkernel_mem()`, breaking out of the `do { ... } while (*cur++ == ',')` loop on the first matching range leaves `cur` before remaining range entries, so `cur` must be advanced to `' '` or `'@'` before parsing `@offset`. In `get_last_crashkernel()`, when searching for an unsuffixed `crashkernel=` (`!suffix`), tokens ending with any entry in `suffix_tbl` (`",high"`, `",low"`, `",cma"`) must be skipped while scanning to the end of `cmdline` to return the last match. [F74, F75]
- Helper functions in `fs/proc/vmcore.c` reachable from exported APIs `vmcore_add_device_dump()` or `register_vmcore_cb()` (such as `get_vmcore_size()`, `set_vmcore_list_offsets()`, and `vmcore_alloc_buf()`) must not be marked `__init`. Header declarations in `include/linux/crash_dump.h` and `include/linux/crash_core.h` for overridable hooks (`elfcorehdr_alloc`, `elfcorehdr_free`, `elfcorehdr_read`, `elfcorehdr_read_notes`, `remap_oldmem_pfn_range`, `dm_crypt_keys_read`) must not carry `__weak`. [F98, F115]
