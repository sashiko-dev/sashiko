# MAC80211

`net/mac80211` implements the Linux IEEE 802.11 software MAC stack, bridging `cfg80211`/`nl80211` control-plane requests with hardware driver callbacks (`ieee80211_ops`), virtual interfaces, Multi-Link Operation (MLO) links, channel contexts, station/key lifecycles, MLME state machines, scanning, power management, rate control, and packet RX/TX paths.

## Architecture & Data Flow

- `NL80211_IFTYPE_AP_VLAN` interfaces are never added to the driver (`drv_add_interface()` rejects them). Driver-ops wrappers (`drv_sta_*`, `drv_set_key`, `drv_ampdu_action`, `drv_flush*`, `drv_net_*`) must call `sdata = get_bss_sdata(sdata)` before `check_sdata_in_driver()`. Updating an AP link's `chanreq`, `crypto_tx_tailroom_needed_cnt`, or `vif.offload_flags` must propagate to all child `sdata->u.ap.vlans` (`ieee80211_link_update_chanreq()`, `update_vlan_tailroom_need_count()`, `ieee80211_recalc_sdata_offload()`). `sdata->bss` is NULL when stopped and must be checked before `container_of`. [F45, F55, F551, F568, F569]
- `struct ieee80211_sta sta` in `struct sta_info`, `conf` in `struct ieee80211_key` and `struct ieee80211_chanctx`, `txq` in `struct txq_info`, and `vif` in `struct ieee80211_sub_if_data` must remain the final struct members because driver-private data or flexible arrays trail them. When populating `__counted_by` flexible array structs (`cfg80211_mbssid_elems`/`cfg80211_rnr_elems` or `local->hw_scan_req->req.channels`), the count field (`dst->cnt` or `req.n_channels`) must be assigned before indexing any array element. [F74, F415, F419, F598]
- During hardware reconfiguration (`local->in_reconfig`), `_ieee80211_link_use_channel()` must skip releasing the channel, `ieee80211_assign_link_chanctx()` must skip unassigning `curr_ctx` and adding `assigned_chanctx_list`, and `drv_wake_tx_queue()` must mark `IEEE80211_TXQ_DIRTY` instead of waking the queue. `ctx->driver_present` on `struct ieee80211_chanctx` must be maintained across `drv_add_chanctx()`, `drv_remove_chanctx()`, and `drv_switch_vif_chanctx()`, and checked before `drv_change_chanctx()` or `ieee80211_iter_chan_contexts_*()`. [F70, F73, F135]
- `WLAN_STA_AUTH`, `WLAN_STA_ASSOC`, and `WLAN_STA_AUTHORIZED` in `sta->_flags` must only be modified by `_sta_info_move_state()` (never `set_sta_flag()`/`clear_sta_flag()`), which keeps `sta->sta_state`, `num_mcast_sta`, and fast-TX/RX caches in sync. For MLO stations (`sta->sta.valid_links && sta->sta.mlo`), `__ieee80211_sta_recalc_aggregates()` must compute minimum A-MSDU lengths into `sta->cur` (`sta->sta.cur = &sta->cur`) rather than mutating `sta->sta.deflink.agg`. [F383, F385]
- On RX, `link_sta_info_get_bss(rx->sdata, hdr->addr2)` must be queried before `sta_info_get_bss()` in `ieee80211_rx_for_interface()`, and used in `__ieee80211_rx_handle_packet()` when `!status->link_valid && sta->sta.mlo` to populate `rx.link` and `rx.link_sta`. In `ieee80211_rx_data`, `rx->sta` and `rx->link_sta` can be NULL (including in `ieee80211_rx_h_action()` for public, self-protected, and spectrum-mgmt frames) and must be checked before dereferencing. [F373, F375, F430]
- `ieee80211_rx_h_action()` and `ieee80211_rx_h_action_post_userspace()` must verify `rx->skb->len` against `offsetofend` of the specific action payload before reading `mgmt->u.action.u` (as `ieee80211_rx_h_mgmt_check()` only checks `IEEE80211_MIN_ACTION_SIZE`). In `ieee80211_rx_h_decrypt()`, `rx->key = NULL` must be reset on entry (since `ieee80211_rx_handlers()` reuses `struct ieee80211_rx_data` across frames), and BIP key indices from `ieee80211_get_mmie_keyidx()` must be range-checked (`4..5` for IGTK, `6..7` for BIGTK, with the beacon check preceding the general `mmie_keyidx >= 0` check) before indexing `gtk[]`. [F403, F410, F431, F432]

## Synchronization

- Modifying `local->interfaces` or `local->monitor_sdata` requires holding RTNL, `wiphy->mtx`, and `local->iflist_mtx` and using RCU list/pointer primitives; in `ieee80211_if_add()`, `sdata` setup and `cfg80211_register_netdevice()` must finish before `list_add_tail_rcu()`. `ieee80211_remove_interfaces()` and `reset_write()` must release `wiphy_lock` before calling `cfg80211_shutdown_all_interfaces()`. In `ieee80211_stop()` on an AP, `dev_close(vlan->dev)` must run before acquiring `wiphy_lock`, while `ieee80211_stop_mbssid()` runs under `wiphy_lock`. [F138, F526, F668, F669, F670]
- `ieee80211_do_stop()` must clear `SDATA_STATE_RUNNING` and call `synchronize_rcu()` before tearing down state, flush stations (`sta_info_flush(sdata, -1)`) before `drv_remove_interface()`, and call `ieee80211_free_keys(sdata, true)` (`force_synchronize = true`) so `synchronize_net()` runs even when no keys exist. If `local->suspended` is true, or after `local->open_count == 0` triggers `ieee80211_stop_device()`, `ieee80211_do_stop()` must return without calling driver teardown/config callbacks. [F528, F653, F663, F671]
- `sta_info_get*()` and `link_sta_info_get_bss()` require the caller to hold `rcu_read_lock()` or `local->hw.wiphy->mtx`, whereas exported driver lookups `ieee80211_find_sta*()` require `rcu_read_lock()` across the call and all uses of the returned `ieee80211_sta *`. Two-phase station destruction (`__sta_info_destroy_part1()` -> `synchronize_net()` -> `__sta_info_destroy_part2()`), key removal (`ieee80211_free_keys_iface()`, `ieee80211_remove_link_keys()`), and MLO link removal (`ieee80211_tear_down_links()`) must unlink pointers/keys first and wait for `synchronize_net()` / `synchronize_rcu()` before freeing keys/links or removing the station from the driver. [F11, F359, F468, F488, F536, F621]
- `ieee80211_rx_handlers()` must hold `spin_lock_bh(&rx->local->rx_path_lock)`. `tid_agg_rx->reorder_lock` protects all `tid_ampdu_rx` reorder fields and must be released before calling `ieee80211_rx_handlers()`. `ieee80211_invoke_fast_rx()` runs without `rx_path_lock` and must punt to the slowpath if `RX_FLAG_DUP_VALIDATED` (or `RX_FLAG_PN_VALIDATED | RX_FLAG_DECRYPTED` when `fast_rx->key` is set) is missing. `ieee80211_rx_list()` must drop frames when `local->quiescing`, `local->suspended`, `local->in_reconfig`, or `!local->started` is set. [F362, F363, F476, F481]
- All `rate_control_ops` station callbacks (`rate_init`, `rate_update`, `tx_status`, `tx_status_ext`, `get_rate`, and `minstrel_ht_update_rates()`) run under `spin_lock_bh(&sta->rate_ctrl_lock)` and must use `GFP_ATOMIC` and never sleep; `WLAN_STA_RATE_CONTROL` must be set only after `rate_init` completes. Likewise, `ieee802_11_parse_elems_full()`, `drv_link_sta_rc_update()`, and `drv_get_key_seq()` run in atomic/RCU contexts and must not sleep. [F155, F194, F315, F318, F497]
- Driver notification entry points (`ieee80211_csa_finish()`, `ieee80211_color_change_finish()`, `ieee80211_obss_color_collision_notify()`, `ieee80211_chswitch_done()`, `ieee80211_request_smps()`) may run without `wiphy->mtx`; they must validate `link_id < IEEE80211_MLD_MAX_NUM_LINKS`, hold `rcu_read_lock()` across `rcu_dereference(sdata->link[link_id])` and `for_each_sdata_link_rcu()` until `wiphy_work_queue()` completes, and work handlers (`ieee80211_csa_finalize_work()`, `ieee80211_color_change_finalize_work()`) must recheck `csa_active`/`color_change_active` and `ieee80211_sdata_running(sdata)` under the wiphy lock. [F31, F32, F80, F139, F323, F682]
- In `ieee80211_set_disassoc()`, connection timers/works (`conn_mon_timer`, `bcn_mon_timer`, `ifmgd->timer`, `tx_tspec_wk`, `ttlm_work`, `neg_ttlm_timeout_work`, `ml_reconf_work`, `teardown_ttlm_work`) must be cancelled before `ieee80211_vif_set_links(sdata, 0, 0)`, and `synchronize_net()` + `ieee80211_flush_queues()` must precede sending deauth/disassoc and removing `ap_sta`. Whenever `local->dynamic_ps_timer` is stopped with `timer_delete_sync()`, `local->dynamic_ps_enable_work` must also be cancelled via `wiphy_work_cancel()`. [F206, F207, F208]

## Object Lifetimes

- Channel contexts on `local->chanctx_list` are traversed under RCU by `ieee80211_iter_chan_contexts_atomic()` and must be added with `list_add_rcu()` and removed with `list_del_rcu()` + `kfree_rcu()`. When `ieee80211_link_unreserve_chanctx()` drops a `ctx->replace_state == IEEE80211_CHANCTX_REPLACES_OTHER` context to refcount 0, it must clear the peer's `replace_ctx`/`replace_state` and free `ctx` via `list_del_rcu()` + `kfree_rcu()` without calling `ieee80211_free_chanctx()`. In `ieee80211_stop_ap()`, `ieee80211_link_copy_chanctx_to_vlans(link, true)` must run before `ieee80211_link_release_channel(link)`. [F3, F24, F69, F147]
- RCU-protected AP/IBSS/mesh pointers (`link->u.ap.{beacon,probe_resp,fils_discovery,unsol_bcast_probe_resp,s1g_short_beacon}`, `sdata->qos_map`, `ifibss->presp`, `ifmsh->beacon`, `ifmsh->csa`, `pubsta->rates`, `sta->fast_rx`) must be fully populated before `rcu_assign_pointer()` and their old values freed via `kfree_rcu()`. `struct beacon_data` in `ieee80211_assign_beacon()` embeds `mbssid_ies` and `rnr_ies` in one allocation (freed by a single `kfree_rcu()`), whereas `cfg80211_beacon_dup()` allocates `mbssid_ies` and `rnr_ies` separately on `link->u.ap.next_beacon` (which `ieee80211_free_next_beacon()` must `kfree()` individually, and `__ieee80211_channel_switch()` must abort any active color change before overwriting `next_beacon`). [F7, F26, F59, F120, F193, F485, F523, F524]
- `sta_info_insert()` and `sta_info_insert_rcu()` consume `sta` and free it on any failure; callers may only call `sta_info_free()` if `sta_info_insert*()` was never called. Similarly, `ieee80211_key_alloc()` returns an `ERR_PTR`, unlinked keys must be freed via `ieee80211_key_free_unused()`, and `ieee80211_key_link()` consumes and frees `key` on all non-zero returns. In `ieee80211_add_link_station()`, `ieee80211_sta_free_link()` must be called if `sta_link_apply_parameters()` fails, whereas `ieee80211_sta_activate_link()` consumes and frees the link on driver failure. [F9, F221, F470, F511, F544]
- `ieee802_11_parse_elems_full()` returns `&elems_parse->elems` (allocated with `GFP_ATOMIC`), which callers must `kfree()` on every exit or `goto again` path. Callers of `ieee80211_determine_chan_mode()` must hold `rcu_read_lock()` across both the call and all dereferences of the returned `elems` (which point into RCU-protected `cbss->ies->data`). [F176, F271, F319]

## API Contracts

- `ieee80211_link_or_deflink()` and `ieee80211_determine_chan_mode()` never return NULL and must be checked with `IS_ERR()`, whereas `ieee802_11_parse_elems_full()` returns NULL on failure. In `chan.c`, `ieee80211_find_chanctx()`, `ieee80211_find_reservation_chanctx()`, and `ieee80211_alloc_chanctx()` return NULL, whereas `ieee80211_new_chanctx()` and `ieee80211_replace_chanctx()` return `ERR_PTR()`. [F39, F42, F212]
- Negative `link_id` (`-1` for non-MLO) must be normalized before indexing `sdata->link[]`, `sta->link[]`, or shifting `BIT(link_id)`: `drv_mgd_prepare_tx()`, `drv_mgd_complete_tx()`, `drv_mgd_protect_tdls_discover()`, `sta_link_apply_parameters()`, `ieee80211_link_init()`, and `ieee80211_send_smps_action()` clamp `link_id < 0` to `0`, while key helpers (`ieee80211_key_enable_hw_accel()`, `ieee80211_key_replace()`, `ieee80211_key_switch_links()`) must check `link_id >= 0` before `BIT(link_id)`. Conversely, link-aware `cfg80211` notifications in CSA/color-change/`ieee80211_stop_ap()` must pass the actual `link_id` rather than `0`. [F51, F52, F81, F378, F592, F602, F635]
- `ieee80211_vif_cfg_change_notify()` only accepts `BSS_CHANGED_VIF_CFG_FLAGS`, `ieee80211_link_info_change_notify()` rejects `BSS_CHANGED_VIF_CFG_FLAGS`, and `ieee80211_bss_info_change_notify()` is restricted to non-MLD interfaces (`!ieee80211_vif_is_mld(&sdata->vif)`). `sta_info_insert_rcu()`, `ieee80211_ocb_finish_sta()`, `ieee80211_ibss_add_sta()`, and `ieee80211_ibss_finish_sta()` (`__acquires(RCU)`) must be called without `rcu_read_lock()` held and always return with `rcu_read_lock()` acquired on both success and error paths. [F313, F489, F562, F685]
- Handlers in `ieee80211_rx_handlers()` must return `RX_QUEUED` whenever they consume, enqueue, or free `rx->skb`, and return `RX_DROP` or a drop-reason code only when `rx->skb` remains unfreed for `ieee80211_rx_handlers_result()` to pass to `kfree_skb_reason()`; `RX_QUEUED` (`SKB_NOT_DROPPED_YET`) must never be passed to `kfree_skb_reason()`. In `ieee80211_rx_h_action()`, malformed frames (`goto invalid`) must set `IEEE80211_RX_MALFORMED_ACTION_FRM` and return `RX_CONTINUE` (not `RX_DROP`). [F44, F371, F433]

## Error Handling

- Non-standard return conventions: `ieee80211_set_probe_resp()` and `ieee80211_parse_ch_switch_ie()` return `< 0` on error, `0` when present/applied, and `1` when the IE is absent; `drv_hw_scan()` returns `1` in `__ieee80211_start_scan()` to request software-scan fallback; `drv_suspend()` returns `1` in `__ieee80211_suspend()` to request cfg80211 disconnect (and any non-zero return must wake `IEEE80211_QUEUE_STOP_REASON_SUSPEND` queues); `ieee80211_vif_use_reserved_switch()` returns `-EAGAIN` when deferred; `ieee80211_key_link()` returns `-EALREADY` on identical key reinstall (converted to `0` by `ieee80211_add_key()`); and `ieee80211_parse_bitrates()` returns `0` on failure (`-EINVAL`). [F40, F41, F43, F174, F192, F329, F366, F370]

## Known Pitfalls

- 64-bit bitmaps (`tid_agg_rx->reorder_buf_filtered` in `rx.c`, `color_bitmap` in `ieee80211_rx_check_bss_color_collision()`, `sinfo->filled` / `link_sinfo->filled` in `sta_info.c`, and `params->filter` / `care_about_ies` in `parse.c`) must use `BIT_ULL()` or `1ULL << id` (never 32-bit `BIT()` or `1 << id`). When passing a `u16` (`valid_links`, `active_links`) or `u64` (`changed` in `ieee80211_mbss_info_change_notify()`) to `for_each_set_bit()`, copy it into an `unsigned long` or `BITMAP_FROM_U64()` variable rather than casting its address to `unsigned long *`. [F279, F440, F442, F443, F639, F651]
- `for_each_sdata_link()` and `for_each_sdata_link_rcu()` expand to nested loops (outer `local->interfaces`, inner `sdata->link[]`), so a `break` statement only exits the inner per-interface link loop rather than terminating iteration across all interfaces. [F100]
- Cached pointers into `skb->data` (such as `struct ieee80211_hdr *hdr`) become invalid after cipher decrypt handlers in `ieee80211_rx_h_decrypt()`, `skb_linearize()` in `ieee80211_rx_h_defragment()`, or `skb_copy()` in `ieee80211_prepare_and_rx_handle()`, and must be re-fetched. In `ieee80211_invoke_fast_rx()`, once `skb` is mutated past the `don't punt to the slowpath!` comment, any error must `goto drop` (returning `true`) rather than returning `false`. [F391, F398, F501]
- In `ieee80211_parse_extension_element()`, `data` (`elem->data + 1`) and `len` (`elem->datalen - 1`) exclude the 1-byte extension ID while `ieee80211_he_oper_size(data)` and `ieee80211_he_spr_size(data)` include it, so callers must check `len >= sizeof(...)` first and then `len >= ieee80211_he_*_size(data) - 1`. In `struct ieee80211_mle_per_sta_profile`, `sta_info_len` includes its own length byte, so the offset past STA Info is `prof->variable + prof->sta_info_len - 1`. [F249, F251, F607]
- In `ieee80211_assoc_config_link()`, `ieee80211_determine_ap_chan()`, `ieee80211_add_link_elems()`, and `ieee80211_mgd_get_ap_ht_vht_capa()`, checks requiring VHT capabilities/operation when `conn.mode >= IEEE80211_CONN_MODE_VHT` must also check `sband->band == NL80211_BAND_5GHZ` / `sband->vht_cap.vht_supported`, because 2.4 GHz and 6 GHz HE/EHT links satisfy `conn.mode >= IEEE80211_CONN_MODE_VHT` without VHT IEs. [F272, F295]
- 12-bit 802.11 sequence numbers in `rx.c` must use `ieee80211_sn_less()` / `ieee80211_sn_inc()` / `& IEEE80211_SN_MASK`, and `ieee80211_release_reorder_frame()` must unconditionally increment `head_seq_num` and clear `BIT_ULL(index)` in `reorder_buf_filtered` on every path so caller loops terminate. [F424, F448]
