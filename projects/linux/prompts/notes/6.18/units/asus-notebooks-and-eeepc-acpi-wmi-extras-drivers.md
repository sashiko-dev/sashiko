# ASUS NOTEBOOKS AND EEEPC ACPI/WMI EXTRAS DRIVERS

This component provides x86 platform drivers for ASUS notebooks, ROG/TUF gaming laptops, ROG Ally handhelds, and Eee PCs. `asus-wmi.c` implements the core WMI framework (hotkeys, backlights, LEDs, rfkill with PCI hotplug, hwmon fans/curves, platform profiles, battery thresholds, and ROG tunables), while `asus-nb-wmi.c` and `eeepc-wmi.c` supply model-specific keymaps, i8042 filters, and DMI quirks. `asus-laptop.c` and `eeepc-laptop.c` support older systems directly via ACPI methods.

## Architecture & Data Flow
- `asus->custom_fan_curves[3]` is indexed by `FAN_CURVE_DEV_CPU` (0x00), `FAN_CURVE_DEV_GPU` (0x01), and `FAN_CURVE_DEV_MID` (0x02); `fan_curve_attr_2_select()` must extract this index with `nr & ~FAN_CURVE_PWM_MASK` rather than masking with `FAN_CURVE_DEV_GPU` or using raw `dev_attr->nr`. [F62]
- Because `asus_fan_curve_attr` mixes `sensor_device_attribute` (`pwm[1-3]_enable`) and `sensor_device_attribute_2` (`pwm[1-3]_auto_point*`), `asus_fan_curve_is_visible()` must not downcast `attr` to either type and instead relies on `attr->name[3]` being `'1'`, `'2'`, or `'3'`. [F96]
- Updating fan curve points (`fan_curve_store()`), fan mode (`pwm1_enable_store()`), or thermal policy (`throttle_thermal_policy_write()`) must set `custom_fan_curves[...].enabled = false`, and disabling a curve in `fan_curve_enable_store()` must reset fans via `throttle_thermal_policy_write()` or `asus_fan_set_auto()`. [F123]
- For `FAN_TYPE_AGFN` fans, `pwm1_store()` sets `asus->fan_pwm_mode = ASUS_FAN_CTRL_MANUAL` and `asus_agfn_fan_speed_write()` caches `asus->agfn_pwm`; while `fan_pwm_mode == ASUS_FAN_CTRL_MANUAL`, `fan1_input_show()` must return `-ENXIO` without calling `asus_agfn_fan_speed_read()`. [F60]
- `kbd_led_set()` must return without calling `do_kbd_led_set()` when `led_cdev->flags & LED_UNREGISTERING` is set, and `kbd_led_update()` must preserve `asus->kbd_led_wk` (ORed with `0x80` when writing `ASUS_WMI_DEVID_KBD_BACKLIGHT`) so `asus_hotk_resume()` and `asus_hotk_restore()` can restore brightness; when `asus->oobe_state_available` is true, both `asus_wmi_led_init()` and `asus_hotk_restore()` must call `asus_wmi_set_devstate(ASUS_WMI_DEVID_OOBE, 1, NULL)`. [F52, F53]
- `kbd_rgb_mode_groups` is a 3-element array (`{ NULL, NULL, NULL }`) populated via `num_rgb_groups++` in `asus_wmi_led_init()`; at most two groups can be added unless `kbd_rgb_mode_groups` is resized to keep the trailing `NULL` sentinel. [F65]
- In `asus_wmi_input_init()`, `SW_TABLET_MODE` and `tablet_switch_dev_id` / `tablet_switch_event_code` must only be configured when `quirks->tablet_switch_mode != asus_wmi_no_tablet_switch`; when `tablet_switch_mode` is `asus_wmi_kbd_dock_devid`, `asus->tablet_switch_inverted = true` must be set before `asus_wmi_tablet_sw_init()`, and `asus_wmi_tablet_sw_report()` must negate `value` when `tablet_switch_inverted` is true. [F74, F113]
- In `asus_i8042_filter()` (`asus-nb-wmi.c`), packets with `str & I8042_STR_AUXDATA` must return `false` before inspecting or updating static `extended_e0`/`extended_e1`, any byte after `0xe0`/`0xe1` must reset the flag to `false`, and `0xe0`-prefixed volume scancodes (`0x20`, `0x2e`, `0x30`) set `atkbd_reports_vol_keys = true` so `asus_nb_wmi_key_filter()` sets `*code = ASUS_WMI_KEY_IGNORE` for WMI codes `0x30`–`0x32`; wireless console codes `0x5D`, `0x5E`, and `0x5F` must all fall through to `quirks->key_wlan_event`. [F59, F75, F88]
- In `eeepc-laptop.c`, `set_acpi()`, `get_acpi()`, and `acpi_setter_handle()` index `cm_setv[cm]` / `cm_getv[cm]` and test `eeepc->cm_supported & (0x1 << cm)` without bounds checks, so every `CM_ASL_*` value must be in `0..31` with matching entries in both `cm_getv` and `cm_setv`; `get_cpufv()` must reject firmware `CFVG` values where `c->num == 0 || c->num > 12`, and `cpufv_store()` must reject `value < 0 || value >= c.num`. [F69, F70]

## Synchronization
- Non-blocking LED `.brightness_set` callbacks in `asus-wmi.c` (`tpd_led_set`, `wlan_led_set`, `lightbar_led_set`), `asus-laptop.c` (`asus_led_cdev_set`, `asus_kled_cdev_set`), and `eeepc-laptop.c` (`tpd_led_set`) must only record target state in `*_led_wk` and queue work on `led_workqueue` rather than evaluating WMI/ACPI methods directly. [F128, F129]
- In `asus-wmi.c`, `asus_rfkill_notify` must defer `asus_rfkill_hotplug()` to `asus->hotplug_workqueue` via `asus->hotplug_work`, and both `asus_rfkill_wlan_set()` and `asus_rfkill_hotplug()` must serialize WMI devstate evaluations under `asus->wmi_lock`. [F130]
- `asus_i8042_filter` in `asus-nb-wmi.c` runs in `i8042` serio interrupt context and must not sleep, take mutexes, or invoke ACPI/WMI methods. [F134]

## Object Lifetimes
- Every `wmi_evaluate_method()` call in `asus-wmi.c` using `struct acpi_buffer output = { ACPI_ALLOCATE_BUFFER, NULL }` owns `output.pointer` on success and must free it with `kfree()` on all return paths. [F1]
- In `asus_rfkill_hotplug()`, `eeepc_rfkill_hotplug()`, and `asus_wmi_set_xusb2pr()`, PCI device references from `pci_get_slot()`, `acpi_get_pci_dev()`, or `pci_get_device()` must be released with `pci_dev_put()` on every exit path, whereas devices returned by `pci_scan_single_device()` must not be passed to `pci_dev_put()`. [F2]
- In `asus_wmi_add()`, `wdrv->detect_quirks()` must run before `asus_wmi_platform_init()`, which must run before any `asus_wmi_get_devstate()` or `asus_wmi_dev_is_present()` call because it initializes `asus->dsts_id`; `asus->throttle_thermal_policy_dev`, `platform_profile_setup()`, and `asus_wmi_fan_init()` must run before `asus_wmi_custom_fan_curve_init()`; and quirks, input, LED, backlight, thermal/fan-boost state, and `fnlock_locked` must all be initialized before `wmi_install_notify_handler()` and `i8042_install_filter()`. [F21, F103, F104]
- `asus_wmi_remove()` must remove `asus->driver->i8042_filter` and `wmi_remove_notify_handler(asus->driver->event_guid)` before tearing down sub-devices (`asus_wmi_backlight_exit`, `asus_wmi_input_exit`, `asus_wmi_led_exit`) or freeing `asus`, and must call `throttle_thermal_policy_set_default()` (which `platform_profile_setup()` must also call before `devm_platform_profile_register()`) and `asus_fan_set_auto()`. [F22, F105]
- `asus_wmi_rfkill_init()` must initialize `hotplug_lock`, `wmi_lock`, `hotplug_workqueue`, and `hotplug_work` (via `asus_setup_pci_hotplug()`) before `asus_register_rfkill_notifier()`; in `asus_wmi_rfkill_exit()`, ACPI rfkill notifiers must be unregistered and `asus->wlan.rfkill` unregistered, destroyed, and set to `NULL` before `asus_rfkill_hotplug(asus)` runs, and `asus_rfkill_hotplug()` and `pci_hp_deregister()` must run before `destroy_workqueue(asus->hotplug_workqueue)`. [F6, F17]
- In `asus_setup_pci_hotplug()` and `eeepc_setup_pci_hotplug()`, if `pci_hp_register()` fails, `hotplug_slot.ops` must be reset to `NULL` (and `asus->hotplug_workqueue` destroyed in `asus_setup_pci_hotplug()`); `-EBUSY` from `*_setup_pci_hotplug()` must be cleared to `0` during rfkill init, and `pci_hp_deregister(&hotplug_slot)` on exit must only be called if `hotplug_slot.ops` is non-NULL. [F5, F149]
- In `asus_new_rfkill()`, `asus_rfkill_setup()`, and `eeepc_new_rfkill()`, if `rfkill_register()` fails, `rfkill_destroy()` must be called and the stored `struct rfkill *` pointer reset to `NULL` so `*_rfkill_exit()` does not call `rfkill_unregister()` on an unregistered instance. [F109]
- In `asus_wmi_led_init()`/`exit()`, `asus_led_init()`/`exit()`, and `eeepc_led_init()`/`exit()`, `led_workqueue` and `INIT_WORK()` must be set up before `led_classdev_register()`, and all LED classdevs must be unregistered via `led_classdev_unregister()` before `destroy_workqueue(led_workqueue)`. [F106]
- In `asus_acpi_add()`/`remove()` and `eeepc_acpi_add()`/`remove()`, `asus_platform_init()` / `eeepc_platform_init()` must succeed before initializing sub-devices (and `pega_accel_init()` must set `asus->pega_accel_poll` only after `input_register_device()` succeeds), and `asus_platform_exit()` / `eeepc_platform_exit()` must run after all sub-devices (including `pega_accel_exit()`) are torn down. [F9, F23]
- `asus_wmi_register_driver()` and `asus_wmi_unregister_driver()` must serialize `used` under `register_mutex`, and `asus_s2idle_check_register()` in `asus_wmi_probe()` must be paired with `asus_s2idle_check_unregister()` both when `asus_wmi_add()` fails and in `asus_wmi_unregister_driver()`. [F12]

## API Contracts
- Payloads passed to `asus_wmi_evaluate_method_agfn()` (such as `struct agfn_fan_args`) must be `__packed` with `agfn.len` set to the total struct size; `asus_wmi_evaluate_method_agfn()` must `kmemdup()` `args.pointer` into a `GFP_DMA | GFP_KERNEL` buffer, pass `virt_to_phys(input.pointer)` to `ASUS_WMI_METHODID_AGFN`, and copy the buffer back on success. [F37, F66]
- All sysfs `.store` callbacks across `asus-wmi.c`, `asus-laptop.c`, and `eeepc-laptop.c` must return `count` on success and a negative errno on failure (never `0`), while `attribute_group.is_visible` callbacks (`asus_hwmon_sysfs_is_visible()`, `asus_fan_curve_is_visible()`, `asus_sysfs_is_visible()`) return `umode_t` and must return `0` on ACPI/WMI failure rather than a negative errno. [F136, F137]
- In all `rfkill` callbacks across `asus-wmi.c`, `asus-laptop.c`, and `eeepc-laptop.c`, the `rfkill` `blocked` boolean is inverted relative to the ASUS ACPI/WMI state (`1` = enabled/unblocked, `0` = disabled/blocked), and in `asus_rfkill_hotplug()` / `eeepc_rfkill_hotplug()`, before scanning or removing PCI slot 0 on the wireless bus, the driver must read `PCI_VENDOR_ID` (`absent = (l == 0xffffffff)`) and abort if `blocked != absent`. [F55, F147]
- Because `asus->kbd_led` is an embedded `struct led_classdev` only registered on supported models, callers outside LED callbacks (`asus_hotk_resume()`, `asus_hotk_restore()`, notify/init paths) must check `!IS_ERR_OR_NULL(asus->kbd_led.dev)` before calling `kbd_led_update(asus)` or `led_classdev_notify_brightness_hw_changed()`. [F35]
- `eeepc_set_fan_ctrl()` must read `EEEPC_EC_FAN_CTRL` via `ec_read()` and modify only `EEEPC_EC_FAN_CTRL_BIT` (`0x02`) before `ec_write()`, preserving all other bits in `EEEPC_EC_SFB0 + 3`. [F57]

## Error Handling
- In `asus_wmi_evaluate_method_buf()`, the `ACPI_TYPE_BUFFER` branch must check `obj->buffer.length > size` and `obj->buffer.length == 0` and `break` before `memcpy()`, the `ACPI_TYPE_INTEGER` branch must convert `err == 0` to `-ENODATA`, and callers must test `if (err)` rather than `if (err < 0)` because positive ACPI integers (like `ASUS_WMI_DSTS_UNKNOWN_BIT`) can be returned; in `fan_curve_check_present()`, any error from `fan_curve_get_factory_default()` must set `*available = false; return 0;` rather than failing probe. [F26, F61, F84, F112]
- `asus_wmi_get_devstate_simple()` and `asus_wmi_get_devstate_bits()` return a negative errno on failure/absence and `>= 0` when present; callers must store the result in a signed `int` and check `< 0` rather than `!result`. [F25]
- In `asus-wmi.c` tunable, GPU, battery, and PWM `.store` handlers (e.g., `nv_temp_target_store()`, `ppt_*_store()`, `gpu_mux_mode_store()`, `pwm*_enable_store()`), after `asus_wmi_set_devstate(..., &result)` returns `0`, the handler must also verify `result` (rejecting `result > 1` or `result != 1` with `-EIO`) before updating state; conversely, `throttle_thermal_policy_write()` must pass `NULL` for `retval` and check only the negative WMI evaluation return because some firmwares return the active policy mode rather than `1`. [F27, F153]
- `write_acpi_int()` and `write_acpi_int_ret()` in `asus-laptop.c` and `write_acpi_int()` and `read_acpi_int()` in `eeepc-laptop.c` return `-1` (`-EPERM`) on failure; callers returning to userspace or kernel subsystems must translate non-zero returns to an errno like `-EIO` or `-ENODEV`. [F40]
- When `backlight_device_register()` returns `IS_ERR(bd)` in `asus_wmi_backlight_init()`, `asus_screenpad_init()`, `asus_backlight_init()`, or `eeepc_backlight_init()`, the error pointer must not be stored in the driver's `backlight_device` field because notify and exit paths check only for `NULL`. [F32]

## External Contracts
- `fan_curve_copy_from_buf()` reads 8 temperatures from `buf[0..7]` and 8 percentages from `buf[8..15]` (scaling `0..100` to `0..255`), while `fan_curve_write()` packs `temps[0..3]`, `temps[4..7]`, and rescaled `100 * percents[0..3] / 255` and `100 * percents[4..7] / 255` into 8-bit shifts of `arg1`..`arg4`. [F64]
- On `ASUS_WMI_DEVID_MINI_LED_MODE2` devices, `mini_led_mode_show()` and `mini_led_mode_store()` must bound `mode <= ASUS_MINI_LED_STRONG_MODE` (2) and remap between userspace sysfs (`0` = off, `1` = on, `2` = strong) and 2024 WMI encoding (`0` = weak, `1` = strong, `2` = off). [F68]
- `throttle_thermal_policy` and `platform_profile` share `asus->throttle_thermal_policy_mode` (`0` = default, `1` = overboost, `2` = silent); `throttle_thermal_policy_store()` must call `platform_profile_notify(asus->ppdev)`, and `throttle_thermal_policy_write()` (on Vivo) and `fan_curve_get_factory_default()` must swap modes `1` and `2` for WMI. [F144]
- `dgpu_disable_store()` and `egpu_enable_store()` must return `-ENODEV` when `asus->gpu_mux_dev` state is `0` (dGPU mode), and `gpu_mux_mode_store()` must return `-ENODEV` when switching `asus->gpu_mux_dev` to `0` while `ASUS_WMI_DEVID_DGPU` or `ASUS_WMI_DEVID_EGPU` state is `1`. [F124]
- `asus_wmi_add()` must only probe and enable `use_ally_mcu_hack` when it equals `ASUS_WMI_ALLY_MCU_HACK_INIT` (preserving prior `set_ally_mcu_hack()` calls from `hid-asus`), and every `ASUS_USB0_PWR_EC0_CSEE` call in `asus_wmi_add()`, `asus_hotk_prepare()`, and `asus_ally_s2idle_restore()` must be followed by `msleep(ASUS_USB0_PWR_EC0_CSEE_WAIT)`. [F125]

## Known Pitfalls
- In `fan1_input_show()`, `fan2_input_show()`, `fan3_input_show()`, and `asus_hwmon_temp1()`, the 32-bit DSTS value from `asus_wmi_get_devstate()` must be masked with `0xffff` to strip upper status flags before converting 100-RPM fan units to RPM (`* 100`) or deci-Kelvin to millidegrees Celsius (`deci_kelvin_to_millicelsius()`). [F92, F139]
- `dev_get_drvdata(dev)` does not always return the driver struct: in `kbd_rgb_mode_groups` callbacks on `asus->kbd_led` it returns `struct led_classdev *` (use `container_of(..., struct asus_wmi, kbd_led)`), in `charge_control_end_threshold_show()`/`store()` on `&battery->dev` it is a `power_supply` device (do not cast to `struct asus_wmi *`), and in `eeepc_hwmon_init()` `drvdata` is `NULL` (cannot obtain `struct eeepc_laptop *`). [F95, F97, F98]
- In `asus_wmi_add()`, detecting `asus->driver->wlan_ctrl_by_user` from `ASUS_WMI_DEVID_WLAN` requires `(result & (ASUS_WMI_DSTS_PRESENCE_BIT | ASUS_WMI_DSTS_USER_BIT)) == (ASUS_WMI_DSTS_PRESENCE_BIT | ASUS_WMI_DSTS_USER_BIT)`; when set, `asus_rfkill_set()` must write to `ASUS_WMI_DEVID_WLAN_LED`, and if `ashs_present()` is also true, `asus_wmi_add()` and `asus_wmi_rfkill_exit()` must skip WMI rfkill setup and teardown. [F73, F148]
- In `update_bl_status()`, when `quirks->store_backlight_power` is set, power changes must update `asus->driver->panel_power`, and when `scalar_panel_brightness` is also set, `update_bl_status()` must return immediately after changing `ASUS_WMI_DEVID_BACKLIGHT` without writing `ASUS_WMI_DEVID_BRIGHTNESS`; in `asus_wmi_add()`, calling `asus_wmi_set_devstate(ASUS_WMI_DEVID_BACKLIGHT, 2, NULL)` when `acpi_video_get_backlight_type() != acpi_backlight_vendor` must be gated on `quirks->wmi_backlight_set_devstate`. [F49, F114]
- Static `struct quirk_entry` definitions in `asus-nb-wmi.c` and `eeepc-wmi.c` must not be `const` because `asus_nb_wmi_quirks()` and `eeepc_wmi_quirks()` mutate `wapf`, `tablet_switch_mode`, and `hotplug_wireless` in place. [F116]
- In `infos_show()` (`asus-laptop.c`), `struct acpi_table_header` fields `oem_id` [6], `oem_table_id` [8], and `asl_compiler_id` [4] are not guaranteed to be NUL-terminated and must be bounded with `snprintf()` limits (`7`, `9`, `5`) before formatting with `%s`. [F71]
