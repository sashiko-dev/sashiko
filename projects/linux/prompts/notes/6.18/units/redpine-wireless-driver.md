# REDPINE WIRELESS DRIVER

The Redpine Signals RS9113/RS9116 driver (`rsi_91x`, `rsi_sdio`, `rsi_usb`) provides `mac80211` Wi-Fi (STA, AP, P2P) and Bluetooth coexistence support, managing firmware loading, state machines, WMM/EDCA and coexistence transmit queues, and SDIO/USB host transports.

## Architecture & Data Flow

- `struct skb_info` aliases `IEEE80211_SKB_CB(skb)->driver_data`, sharing a union with `control` and `IEEE80211_SKB_RXCB(skb)`. In TX (`rsi_core_xmit()`), `vif` must stay at `control.vif`'s offset, `skb_info` must end before `control.flags`, and `control.hw_key` must be copied before writing `tx_params`. In RX (`rsi_fill_rx_status()`), all `rx_params` fields must be copied to locals before `memset(info, ...)` or writing `rxs`. [F99, F100]
- Untyped context pointers map to distinct structs: `ieee80211_hw->priv` and `rsi_91x_usbdev->priv` point to `struct rsi_hw`; `rsi_proto_ops` `priv` and debugfs `inode->i_private` / `seq->private` point to `struct rsi_common`; `rx_usb_ctrl_block->data` (`u8 *`) points to `struct rsi_91x_usbdev` (not a packet buffer). [F105]
- `usb_host_intf_ops` leaves `read_pkt`, `master_access_msword`, `reinit_device`, and `ta_reset` as `NULL`; shared code must guard against `RSI_HOST_INTF_USB` before calling them. [F34]
- SDIO master accesses (`addr | RSI_SD_REQUEST_MASTER`) pass only the low 16 address bits in CMD52/CMD53 and rely on `rsi_sdio_master_access_msword()` for the high 16 bits, which must be updated across 64 KB boundaries and restored to `MISC_CFG_BASE_ADDR` (`0x4105`) for `rsi_sdio_ack_intr()`. [F76]
- `common->coex_cb` and `dev->rx_cb[1].rx_urb` exist only when `common->coex_mode > 1`, and `common->bt_adapter` is set only after `BT_CARD_READY_IND`. Callers must check `coex_mode > 1` and `common->bt_adapter` before invoking `rsi_bt_ops`, and every `rsi_bt_ops.detach(common->bt_adapter)` call must immediately clear `common->bt_adapter = NULL`. [F4, F35]
- USB endpoint constants (`WLAN_EP = 1`, `BT_EP = 2`, `rx_cb->ep_num`) are 1-based while `bulkout_endpoint_addr`, `bulkin_endpoint_addr`, and `rx_cb` in `struct rsi_91x_usbdev` are 0-based; `rsi_usb_card_write()`, `rsi_rx_urb_submit()`, and `rsi_rx_urb_kill()` must index them with `endpoint - 1` or `ep_num - 1`. [F69]
- In `rsi_91x_usb.c`, `rsi_usb_reg_read()` and `rsi_usb_reg_write()` must reject `len > RSI_USB_CTRL_BUF_SIZE`, `rsi_usb_read_register_multiple()` and `rsi_usb_write_register_multiple()` must clamp chunks to `RSI_USB_BUF_SIZE`, and `rsi_usb_load_data_master_write()` requires `block_size <= 256` to fit stack buffer `u8 temp_buf[256]`. [F64, F107]
- In `rsi_read_pkt()`, `extended_desc` may be read via `rsi_get_extended_desc()` only for `RSI_WIFI_DATA_Q` or `RSI_WIFI_MGMT_Q`, and on USB RX (`rcv_pkt_len == 0`), `offset` must be checked against `RSI_MAX_RX_USB_PKT_SIZE - FRAME_DESC_SZ` before accessing `frame_desc + offset`. In `rsi_mgmt_pkt_to_core()`, `pad_bytes` (`msg[4]`) must be subtracted from signed `s32 msg_len` and `msg_len <= 0` rejected before allocating the SKB. [F66, F67]
- `rsi_rates[12]` has 2.4 GHz CCK rates at `0..3` and OFDM at `4..11`; 5 GHz handling in `rsi_register_rates_channels()` and `rsi_send_auto_rate_request()` must offset by 4 (`rate_table_offset = 4`) and limit count to `ARRAY_SIZE(rsi_rates) - 4`. `configured_mask` packs legacy rates in bits `0..11` and HT MCS0..MCS7 shifted left by `ARRAY_SIZE(rsi_rates)`. `rsi_mac80211_set_rate_mask()` must update all bands in `ARRAY_SIZE(common->rate_config)`, setting `fixed_enabled = true` and using `ffs(bm) - 1` only when `hweight32(bm) == 1`. [F51, F73, F97]
- `adapter->ps_state` must transition through `PS_ENABLE_REQ_SENT` and `PS_DISABLE_REQ_SENT`, reaching `PS_ENABLED` or `PS_NONE` only in `rsi_handle_ps_confirm()`. In `rsi_mac80211_config()`, `IEEE80211_CONF_CHANGE_PS` must not call `rsi_enable_ps()` or `rsi_disable_ps()` if `common->mac_ops_resumed` is true or if any VIF in `adapter->vifs[]` is `NL80211_IFTYPE_AP` or `NL80211_IFTYPE_P2P_GO`. [F61, F122]
- Array indexing invariants: `fsm_state[]` in `rsi_stats_read()` must match `enum RSI_FSM_STATES` in count (`NUM_FSM_STATES`) and order; every `DEV_OPMODE_*` must be handled in `rsi_91x_init()` and have an entry at `rsi_max_ap_stas[oper_mode - 1]`; `metadata_flash_content[]` and `metadata[]` are indexed by `coex_mode` (`1`, `2`, `4`) and require placeholders at `0` and `3`; `"sdio_stats"` (`rsi_sdio_stats_read()`, which casts `rsi_dev` to `rsi_91x_sdiodev *`) must stay last in `dev_debugfs_files[]` because USB registers `MAX_DEBUGFS_ENTRIES - 1`. [F52, F54, F71, F72]

## Synchronization

- During hibernate resume, `rsi_mac80211_start()` holds `common->mutex` while waiting on `common->wlan_init_completion`; the RX and TX paths that drive firmware init and call `complete(&common->wlan_init_completion)` in `rsi_handle_ta_confirm_type()` (`rsi_rx_handler()`, `rsi_read_pkt()`, `rsi_mgmt_pkt_recv()`, `rsi_core_qos_processor()`) must never acquire `common->mutex`. [F26]
- Atomic-context paths: `rsi_rx_done_handler()` and `rsi_rx_urb_submit()` run in USB URB completion context (`GFP_ATOMIC` only, deferring parsing to `rsi_usb_rx_thread()`); `rsi_enable_ps()`, `rsi_disable_ps()`, and `rsi_send_ps_request()` run under `spin_lock_irqsave(&adapter->ps_lock, flags)` and must queue frames via `rsi_send_internal_mgmt_frame()` without sleeping; `rsi_mac80211_tx()` and `rsi_core_xmit()` run in `mac80211` atomic TX context and must only enqueue SKBs via `rsi_core_queue_pkt()` without acquiring mutexes or `common->tx_lock`. [F123, F124, F125]
- When `common->coex_mode > 1`, `rsi_send_pkt_to_bus()` serializes `adapter->host_intf_ops->write_pkt()` with `common->tx_bus_mutex`; when both are held (as in `rsi_core_qos_processor()`), `common->tx_lock` must be acquired before `common->tx_bus_mutex`. [F126]
- Every `mac80211_ops` callback acquiring `common->mutex` must unlock it on all return paths; `rsi_core_qos_processor()` must unlock `common->tx_lock` before every `break` in its TX loop; `rsi_rx_handler()` must unlock `common->rx_lock` before every early `return` in its SDIO interrupt loop. [F11, F12]
- In `rsi_91x_sdio.c`, SDIO bus configuration and raw command helpers (`sdio_enable_func()`, `sdio_disable_func()`, `sdio_claim_irq()`, `sdio_release_irq()`, `rsi_setupcard()`, `rsi_reset_card()`, `rsi_cmd52readbyte()`, `rsi_cmd52writebyte()`) must be called under `sdio_claim_host()`, balanced by `sdio_release_host()` on all exit paths. [F22]
- In `rsi_91x_init()`, `common->init_done` must stay `false` until `common->coex_mode` is set and `rsi_coex_attach()` finishes, because `rsi_tx_scheduler_thread()` is already running and gates `rsi_core_qos_processor()` on `common->init_done`. In SDIO `rsi_probe()`, `sdev->rx_thread` must be started before `sdio_claim_irq()`, and `common->fsm_state` must stay `FSM_FW_NOT_LOADED` until `rsi_hal_device_init()` completes. [F27, F28]
- `rsi_create_kthread()` takes `void *func_ptr` and passes `struct rsi_common *` to `kthread_run()`, while `rsi_kill_thread()` increments `handle->thread_done`, signals `handle->event`, and blocks in `kthread_stop()`. Every kthread function must take `struct rsi_common *`, check `atomic_read(&thread->thread_done)` after waking from `rsi_wait_event()`, and exit via `kthread_complete_and_exit(&thread->completion, 0)`. [F20, F104]

## Object Lifetimes

- `rsi_91x_deinit()` frees `adapter->rsi_dev` alongside `common` and `adapter`; bus-layer error and teardown paths (`rsi_deinit_usb_interface()`, `rsi_disconnect()`, `rsi_probe()`) must stop bus RX threads and free sub-allocations before calling `rsi_91x_deinit()` and must never `kfree(adapter->rsi_dev)` directly. [F3]
- During teardown or error paths in `rsi_91x_init()`, `rsi_91x_deinit()`, `rsi_coex_attach()`, `rsi_coex_detach()`, `rsi_deinit_usb_interface()`, and SDIO `rsi_probe()`/`rsi_disconnect()`, stop kthreads via `rsi_kill_thread()` before purging queues or freeing `coex_cb`, `common`, `rsi_dev`, or `adapter`. Free `coex_cb` if `rsi_create_kthread()` fails in `rsi_coex_attach()`, and unwind `sdio_release_irq()`, `rsi_kill_thread()`, `sdio_disable_func()`, and `rsi_91x_deinit()` in reverse order in SDIO `rsi_probe()`. [F1, F2, F13, F21]
- In `rsi_91x_usb.c`, submitted receive URBs (`WLAN_EP` and, when `common->coex_mode > 1`, `BT_EP`) must be synchronously stopped via `rsi_rx_urb_kill()` before `rsi_deinit_usb_interface()` and `rsi_91x_deinit()` free the URBs, `rx_thread`, and `adapter`. In `rsi_rx_urb_submit()`, if `usb_submit_urb()` fails, `rx_cb->rx_skb` must be freed with `dev_kfree_skb(skb)`. [F8, F18]
- Internal frame builders (`rsi_send_auto_rate_request()`, `rsi_send_bgscan_probe_req()`, `rsi_send_beacon()`) transfer `skb` ownership to `common->tx_queue` only at `rsi_send_internal_mgmt_frame()` or `skb_queue_tail()`, so they must free `skb` on prior errors and always free temporary buffers. SKBs queued via `rsi_send_internal_mgmt_frame()` must have `INTERNAL_MGMT_PKT` set in `tx_params->flags` so `rsi_coex_send_pkt()` does not drop them when `common->iface_down` is set and `rsi_send_mgmt_pkt()` frees them with `dev_kfree_skb()` instead of `rsi_indicate_tx_status()`. [F7, F135]
- In `rsi_load_9113_firmware()` and `rsi_load_9116_firmware()`, once `request_firmware(&fw_entry, ...)` succeeds, all return paths must call `release_firmware(fw_entry)`, and `rsi_load_9116_firmware()` must also `kfree(ta_firmware)` after `kmemdup()`. Every function starting `adapter->bl_cmd_timer` via `bl_start_cmd_timer()` must call `bl_stop_cmd_timer(adapter)` on both success and non-timeout error paths. [F9, F16]
- `rsi_mac80211_detach()` must stop queues, unregister and free `adapter->hw` (`adapter->hw = NULL`), free each `adapter->sbands[band].channels` array, and (under `CONFIG_RSI_DEBUGFS`) call `rsi_remove_dbgfs(adapter)` followed by `kfree(adapter->dfsentry)`. [F15]

## API Contracts

- `rsi_core_xmit()` owns the `skb` from `rsi_mac80211_tx()` and frees it via `ieee80211_free_txskb()` at `xmit_fail:` on error, so `rsi_prepare_mgmt_desc()` and `rsi_prepare_data_desc()` must return non-zero on error without freeing `skb`. Once `rsi_core_qos_processor()` dequeues `skb`, the downstream send path (`rsi_send_data_pkt()`, `rsi_send_mgmt_pkt()`, `rsi_send_bt_pkt()`) must consume `skb` on both success and failure via `rsi_indicate_tx_status()` or `dev_kfree_skb()`. [F5, F6]
- All buffers passed to `rsi_sdio_read_register_multiple()`, `rsi_sdio_write_register_multiple()`, `usb_control_msg()`, or `usb_bulk_msg()` must reside in `kmalloc`-backed DMA-capable memory, never on the stack or in `vmalloc` memory like `fw_entry->data`. [F130]
- `rsi_read_pkt()` requires `rcv_pkt_len` (typed as signed `s32`) to be `0` on USB (`rsi_usb_rx_thread()`) so `rcv_pkt_len -= actual_length` goes negative to exit the loop after one frame, and a positive byte count on SDIO (`rsi_process_pkt()`). `rsi_set_len_qno()` requires `len` to be payload length excluding the 16-byte descriptor (`skb->len - FRAME_DESC_SZ`, or `0` for descriptor-only frames). [F44, F47]
- `rsi_usb_master_reg_read()` must read the 16-bit register into a local `u16` variable when calling `rsi_usb_reg_read()` and then assign it to the caller's `u32 *value` out-parameter, rather than casting `u32 *` to `u16 *`. [F65]
- When `ieee80211_has_protected(hdr->frame_control)` is true on RX, `rsi_fill_rx_status()` must `memmove` the 802.11 header forward and `skb_pull` 4 bytes (WEP) or 8 bytes (non-WEP, setting `RX_FLAG_MMIC_STRIPPED`), set `RX_FLAG_DECRYPTED | RX_FLAG_IV_STRIPPED`, and refresh `hdr = (struct ieee80211_hdr *)skb->data` before inspecting `hdr` again. [F102, F137]

## Error Handling

- Callers of `rsi_usb_reg_read()`, `rsi_usb_reg_write()`, `rsi_usb_master_reg_write()`, and `adapter->host_intf_ops->master_reg_write()` must check `< 0` rather than `!= 0`, because on USB these return the positive byte count from `usb_control_msg()` on success. [F30]
- `adapter->check_hw_queue_status()` (`rsi_sdio_check_buffer_status()`, `rsi_usb_check_queue_status()`) returns `QUEUE_NOT_FULL` (`1`) when ready, `QUEUE_FULL` (`0`) when full, and `-1` on error; callers must store the result in a signed `int` and check `<= 0` before transmitting. [F31]
- In multi-step functions returning a shared `status` or `ret` variable (`rsi_probe()`, `rsi_load_9116_firmware()`, `rsi_reset_card()`), any failure branch after an earlier call set `status`/`ret` to `0` must explicitly assign a negative errno before jumping to a cleanup label. [F39]

## External Contracts

- In `mac80211_ops`, `rsi_mac80211_hw_scan_start()` must return `1` when `!vif->cfg.assoc` to fall back to software scan. On hibernate resume (`common->hibernate_resume`), `rsi_mac80211_resume()` must return `1` so `rsi_mac80211_start()` sets `common->reinit_hw = true`, calls `reinit_device()`, and waits on `common->wlan_init_completion`, which `rsi_handle_ta_confirm_type()` completes instead of calling `rsi_mac80211_attach()`. [F32, F121]
- When `BT_CARD_READY_IND` arrives in `rsi_read_pkt()`, `rsi_attach_bt()` may be called immediately only if `common->fsm_state == FSM_MAC_INIT_DONE`; otherwise `common->bt_defer_attach` must be set so `rsi_handle_ta_confirm_type()` attaches BT after Wi-Fi BB/RF programming completes. [F111]

## Known Pitfalls

- Because `rsi_send_internal_mgmt_frame()` sets `DESC_IMMEDIATE_WAKEUP` (`BIT(15)`) in `desc_dword0.len_qno` (bit 7 of `pkt[1]`), functions extracting the 3-bit HAL queue number (`rsi_get_queueno()`, `rsi_usb_host_intf_write_pkt()`) must mask `pkt[1] >> 4` with `0x7` rather than `0xf`. [F75]
- In `rsi_get_num_pkts_dequeue()`, walking `common->tx_queue[q_num]` via raw `skb = skb->next` pointers must stop when `skb_queue_len(&common->tx_queue[q_num]) - pkt_cnt` reaches zero, because `struct sk_buff_head` is a circular list whose last element's `next` points to the list head, not `NULL`. [F84]
- To 64-byte-align `skb->data` using `dword_align_bytes = (unsigned long)skb->data & 0x3f`, `skb_push()` takes `dword_align_bytes`, whereas `skb_pull()` (in `rsi_send_beacon()`) increments `skb->data` and must take `64 - dword_align_bytes`. [F91]
- `struct rsi_hw::country` is a non-NUL-terminated `char country[2]`; never pass it to `%s` without `%.2s` or to NUL-terminated string functions. [F108]
