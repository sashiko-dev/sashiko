# SPI SUBSYSTEM

This component contains core SPI helper headers (`internals.h`), the generic bitbanging SPI controller library (`spi-bitbang.c`, `spi-bitbang-txrx.h`), and a collection of hardware SPI and Quad/Octal SPI (`spi-mem`) host controller drivers (such as Atmel QSPI, Cadence QSPI/XSPI, Broadcom BCM2835/BCM2835aux, Altera, Armada 3700, Cavium Octeon/ThunderX, Au1550, Amlogic SPIFC, and CH341). These drivers bridge the Linux SPI and `spi-mem` subsystem APIs to platform, PCI, DFL, parallel-port, or USB hardware using MMIO, PIO, interrupts, and DMA engines.
This component comprises SPI, QSPI, and OSPI host controller drivers for various SoC platforms (STM32 QSPI/OSPI, NVIDIA Tegra114 and Tegra20 SFLASH/SLINK, TI QSPI, Allwinner sun4i/sun6i, Spreadtrum SPI/ADI, Socionext F-OSPI, Intel Topcliff PCH, UniPhier, ST SSC4, Xilinx, NetLogic XLP, and Analog Devices XCOMM), along with the Infineon TLE62x0 SPI peripheral switch driver (`spi-tle62x0.c`) and the SPI test header (`spi-test.h`). These drivers implement standard SPI transfers, `spi-mem` flash operations, direct memory mapping (`dirmap`), hardware status polling, and sysfs GPIO control.

## Architecture & Data Flow

- Drivers using `altera_spi_init_host()` must set `hw->irq` to a negative value (such as `-EINVAL` in `dfl_spi_altera_probe()` or the negative return of `platform_get_irq()`) when running without an interrupt, because `altera_spi_txrx()` branches on `if (hw->irq >= 0)` to select IRQ-driven mode over polling. [F49]
- When updating bitfields in `QSPI_SCR` or `QSPI_MR` in `atmel-quadspi.c`, callers must clear only the target bitfield mask in the shadow field (`aq->scr` or `aq->mr`), OR in the new bits, and write the shadow field to hardware so unrelated baudrate, CS delay, or `QSPI_MR_SMM` settings are preserved. [F53]
- In `bcm2835_spi_setup()`, whenever `target->prepare_cs` is updated for `spi->mode`, `target->clear_rx_cs` must be updated in lockstep (`cs | BCM2835_SPI_CS_TA | BCM2835_SPI_CS_DMAEN | BCM2835_SPI_CS_CLEAR_RX`) and synced via `dma_sync_single_for_device()` on `target->clear_rx_addr` when `ctlr->dma_rx` is present. [F58]
- In `spi-bcm2835aux.c`, `bs->pending` must be zeroed at the start of each transfer in `bcm2835aux_spi_transfer_one()`, incremented by `count` as `bs->tx_len` is decremented in `bcm2835aux_wr_fifo()`, and decremented by `count` as `bs->rx_len` is decremented in `bcm2835aux_rd_fifo()`. [F59]
- `bcm2835aux_spi_transfer_one()` must clear `BCM2835_AUX_SPI_CNTL0_SPEED` in `bs->cntl[0]` before ORing in the new transfer's `speed << BCM2835_AUX_SPI_CNTL0_SPEED_SHIFT`, because `bs->cntl[0]` is initialized only once per message in `bcm2835aux_spi_prepare_message()`. [F60]
- Whenever `cqspi_controller_init()` reinitializes the Cadence QSPI hardware (such as in `cqspi_probe()` and `cqspi_runtime_resume()`), `cqspi->current_cs` must be reset to `-1` and `cqspi->sclk` to `0` so the next `cqspi_configure()` call reprograms chip-select, baudrate, delay, and readcapture registers. [F61]
- In `cqspi_write_setup()`, setting `CQSPI_REG_WR_DISABLE_AUTO_POLL` in `CQSPI_REG_WR_COMPLETION_CTRL` when `cqspi->wr_completion` is true must also set `cqspi->use_direct_mode_wr = false` in lockstep, because direct access (DAC) mode writes in `cqspi_write()` require hardware auto-polling for write completion. [F62]
- In `cqspi_versal_indirect_read_dma()`, switching the OSPI mux to `PM_OSPI_MUX_SEL_DMA` and setting `CQSPI_REG_CONFIG_DMA_MASK` must be reverted (`CQSPI_REG_CONFIG_DMA_MASK` cleared and `PM_OSPI_MUX_SEL_LINEAR` restored) on both completion and `failrd` paths before any `cqspi_indirect_read_execute()` call. [F63]
- In `spi-altera-core.c`, all modifications to `ALTERA_SPI_CONTROL` (`ALTERA_SPI_CONTROL_SSO_MSK` in `altera_spi_set_cs()` and `ALTERA_SPI_CONTROL_IRRDY_MSK` in `altera_spi_txrx()` and `altera_spi_irq()`) must update `hw->imr` and write `hw->imr` to `ALTERA_SPI_CONTROL` rather than writing raw masks directly. [F64]
- In `spi-ath79.c`, `ath79_exec_mem_op()` must restore `AR71XX_SPI_FS_GPIO` in `AR71XX_SPI_REG_FS` and write the cached `sp->ioc_base` back to `AR71XX_SPI_REG_IOC` after temporarily clearing `AR71XX_SPI_REG_FS` for a memory-mapped read, so GPIO bitbang chip-select and clock/data line states remain synchronized. [F65]
- In `spi-au1550.c`, configuring word size in `au1550_spi_chipsel()` and `au1550_spi_setupxfer()` must both call `au1550_spi_bits_handlers_set()` to update `hw->txrx_bufs`, `hw->irq_callback`, `hw->rx_word`, and `hw->tx_word` and set or clear `PSC_SPICFG_DD_DISABLE` in `hw->regs->psc_spicfg` according to `hw->usedma && bpw <= 8`. [F66]
- In `au1550_spi_dma_txrxb()`, when `t->rx_buf` is `NULL` and `t->len > hw->dma_rx_tmpbuf_size`, `hw->dma_rx_tmpbuf` must be unmapped and freed via `au1550_spi_dma_rxtmp_free(hw)` and reallocated via `au1550_spi_dma_rxtmp_alloc()` before assigning `hw->rx = hw->dma_rx_tmpbuf`, `dma_rx_addr = hw->dma_rx_tmpbuf_addr`, and `hw->tx = hw->rx`. [F67]
- In `spi-armada-3700.c`, `a3700_spi_bytelen_set()` must update both the `A3700_SPI_BYTE_LEN` bit in `A3700_SPI_IF_CFG_REG` and `a3700_spi->byte_len` in lockstep, and `a3700_spi_transfer_setup()` must reset `byte_len` to 4 before each transfer because `a3700_spi_transfer_one_full_duplex()` drops `byte_len` to 1 when `buf_len < 4`. [F68]
- In `spi-cadence.c`, any code that raises `CDNS_SPI_THLD` above `1` (`cdns_spi_detect_fifo_depth()` and target-mode `cdns_transfer_one()`) must ensure `CDNS_SPI_THLD` is reset to `0x1` (`cdns_spi_detect_fifo_depth()` and `cdns_unprepare_transfer_hardware()`), because `cdns_spi_irq()` subtracts `threshold` from `trans_cnt` whenever `threshold > 1`. [F69]
- In `octeon_spi_do_transfer()`, `p->cs_enax` accumulates the `csena0..3` enable bits across transfers (`p->cs_enax |= 1ull << (12 + spi_get_chipselect(spi, 0))`) and must be ORed into `mpi_cfg.u64` before comparing against and updating `p->last_cfg` and writing `OCTEON_SPI_CFG(p)`. [F71]
- In `spi-butterfly.c`, all updates to the parallel port data register (`setsck()`, `setmosi()`, and power/reset setup in `butterfly_attach()`) must modify and write back `pp->lastbyte` via `parport_write_data(pp->port, byte)` so toggling `spi_sck_bit` or `spi_mosi_bit` preserves `vcc_bits` and `butterfly_nreset`. [F74]
- In `cdns_mrvl_xspi_setup_clock()`, the loop over `cdns_mrvl_xspi_clk_div_list` must bound `i` to `ARRAY_SIZE(cdns_mrvl_xspi_clk_div_list) - 1` because `cdns_mrvl_xspi_clk_div_list[i]` is unconditionally indexed after the loop terminates. [F75]
- In `atmel_qspi_exec_op()`, operations with `op->addr.val + op->data.nbytes > aq->mmap_size` or `op->addr.nbytes > 4` must be rejected before `aq->ops->set_cfg()` and `aq->ops->transfer()`, because transfers access `aq->mem + offset` (or `aq->mmap_phys_base + loff`) for `op->data.nbytes` bytes. [F77]
- `cqspi_command_read()` and `cqspi_command_write()` must reject `op->data.nbytes > CQSPI_STIG_DATA_LEN_MAX` (8 bytes) because STIG data transfers use only the two 32-bit registers `CQSPI_REG_CMDREADDATALOWER`/`UPPER` or `CQSPI_REG_CMDWRITEDATALOWER`/`UPPER` and a 3-bit length field encoding `nbytes - 1`. [F78]
- In `cqspi_read()` and `cqspi_write()`, direct access mode (`cqspi_direct_read_execute()` or `memcpy_toio()` on `cqspi->ahb_base`) may only be used when `(op->addr.val + op->data.nbytes) <= cqspi->ahb_size`, falling back to indirect mode otherwise. [F79]
- `bcm2835_spi_can_dma()` must reject transfers shorter than `BCM2835_SPI_DMA_MIN_LENGTH` (96 bytes), which guarantees that `bcm2835_spi_transfer_prologue()` can write up to 6 prologue bytes (including a 4-byte spillover into `tfr->tx_sg.sgl[1]`) without underflowing the transfer or scatterlist lengths. [F83]
- In `bcm2835_spi_max_transfer_size()`, the maximum DMA transfer size must be `65532` (a multiple of 4 bytes that fits in the 16-bit `BCM2835_SPI_DLEN` register) rather than `65535`, so that split DMA transfers remain 32-bit FIFO aligned. [F84]
- `cdns_xspi_adjust_mem_op_size()` must clamp `op->data.nbytes` to `cdns_xspi->sdmasize`, and `amlogic_spifc_a1_adjust_op_size()` must clamp `op->data.nbytes` to `SPIFC_A1_BUFFER_SIZE` (512), so that `exec_op` transfers do not exceed the controller's SDMA window or internal 512-byte data buffer. [F87]
- In `spi-cavium.h`, all bitfield structures inside `union cvmx_mpi_cfg`, `union cvmx_mpi_datx`, `union cvmx_mpi_sts`, and `union cvmx_mpi_tx` must provide matching `#ifdef __BIG_ENDIAN_BITFIELD` and `#else` definitions with reversed field order totaling 64 bits. [F88]
- In `a3700_spi_transfer_one_fifo()`, when `a3700_spi->tx_buf` is non-NULL and `a3700_spi->buf_len` is not a multiple of 4, `a3700_spi_header_set()` must transfer the leading `buf_len % 4` bytes via `A3700_SPI_IF_ADDR_REG` (packed big-endian) and subtract `addr_cnt` from `buf_len` before `a3700_spi_fifo_write()` writes 4-byte little-endian words. [F89]
- In `bitbang_txrx_le_cpha0()` and `bitbang_txrx_le_cpha1()`, the MISO shift position `rxbit = bits - 1` must be captured before the `for (; likely(bits); bits--)` loop rather than computed from the decrementing loop counter `bits`, because `word` is right-shifted on each iteration. [F93]
- When updating cached Mode Register or Serial Clock Register fields on `struct atmel_qspi`, writes to `QSPI_MR` must pass `aq->mr` and writes to `QSPI_SCR` must pass `aq->scr` to `atmel_qspi_write()`. [F95]
- In `atmel_qspi_wait_for_completion()` and `atmel_qspi_interrupt()`, status completion must be tested with `((... & irq_mask) == irq_mask)` while accumulating interrupt status bits in `aq->pending`, because `irq_mask` can be the multi-bit mask `QSPI_SR_CMD_COMPLETED`. [F96]
- In `bcm2835_spi_transfer_prologue()` and `bcm2835_spi_undo_prologue()`, `bs->tx_prologue` serves as the sole active-prologue guard (since `bs->rx_prologue > 0` always sets `bs->tx_prologue > 0`), and `bcm2835_spi_undo_prologue()` must reset `bs->tx_prologue = 0` on all paths including `!bs->tx_buf`. [F99]
- In `drivers/spi/spi-bcm2835aux.c`, `bcm2835aux_wr_fifo()` packs up to 3 bytes starting at bit 16 (`8 * (2 - i)`) and decrements `bs->tx_len` before testing `if (bs->tx_len)` to choose `BCM2835_AUX_SPI_TXHOLD` vs `BCM2835_AUX_SPI_IO`, while `bcm2835aux_rd_fifo()` unpacks via fallthrough from `case 3` down to `case 1`. [F101]
- In `cdns_spi_irq()` on `CDNS_SPI_IXR_TXOW`, `trans_cnt` must be computed from `CDNS_SPI_THLD` before `CDNS_SPI_THLD` is lowered to 1, and `if (xspi->tx_bytes)` must be tested before `cdns_spi_process_fifo()` decrements `xspi->tx_bytes` so the transfer is finalized only on the interrupt after the last TX bytes shift out. [F104]
- In `octeon_spi_do_transfer()`, the multi-chunk loop condition must be strictly `while (len > OCTEON_SPI_MAX_BYTES)` with `mpi_tx.s.leavecs = 1`, leaving the final `1..OCTEON_SPI_MAX_BYTES` bytes for the tail transfer where `mpi_tx.s.leavecs` is set to `last_xfer ? xfer->cs_change : !xfer->cs_change`. [F105]
- In `cqspi_indirect_read_execute()`, when `remaining < 4` causes `round_down(bytes_to_read, 4)` to become 0, the `else if (!word_remain && mod_bytes)` branch must read the final 32-bit word from `ahb_base` and set `bytes_to_read = mod_bytes` so `remaining` decrements to 0 and the loop terminates. [F107]
- In spi_bitbang_setup_transfer() (drivers/spi/spi-bitbang.c), the half-cycle delay calculation (NSEC_PER_SEC / 2) / hz must remain guarded by if (hz), because spi_bitbang_setup() invokes setup_transfer(spi, NULL) where hz falls back to spi->max_speed_hz, which can be 0. [F110]
- In altera_spi_txrx() (drivers/spi/spi-altera-core.c), hw->bytes_per_word must be computed with ceiling division DIV_ROUND_UP(t->bits_per_word, 8) before dividing t->len / hw->bytes_per_word, because the controller supports bits_per_word from 1 to 16 (or DATA_WIDTH) and packs each word into 1, 2, or 4 bytes. [F111]
- In bcm2835_spi_transfer_one() (drivers/spi/spi-bcm2835.c), when 0 < spi_hz < bs->clk_hz / 2, cdiv must be rounded up with DIV_ROUND_UP(bs->clk_hz, spi_hz), made even via cdiv += (cdiv % 2), and wrapped to 0 if cdiv >= 65536, with effective_speed_hz using cdiv ? (bs->clk_hz / cdiv) : (bs->clk_hz / 65536). [F112]
- In bcm2835_spi_transfer_one() (drivers/spi/spi-bcm2835.c) and bcm2835aux_spi_transfer_one() (drivers/spi/spi-bcm2835aux.c), the divisions (9 * 1000000) / polling_limit_us and tfr->effective_speed_hz / hz_per_byte must be guarded against zero divisors because polling_limit_us is a 0664 module parameter writable at runtime. [F113]
- In bcm2835_spi_transfer_one_poll() (drivers/spi/spi-bcm2835.c), bcm2835aux_spi_transfer_one_poll() (drivers/spi/spi-bcm2835aux.c), and cqspi_wait_idle() (drivers/spi/spi-cadence-quadspi.c), jiffies polling deadlines must be compared using time_after(jiffies, timeout) rather than direct relational operators. [F114]
- In a3700_spi_clock_set() (drivers/spi/spi-armada-3700.c), when prescale = DIV_ROUND_UP(clk_get_rate(a3700_spi->clk), speed_hz) is greater than 15, prescale must be recomputed as A3700_SPI_CLK_EVEN_OFFS + DIV_ROUND_UP(prescale, 2) so odd divisors above 15 round up to the next supported step of 2. [F115]
- In octeon_spi_do_transfer() (drivers/spi/spi-cavium.c), setting p->cs_enax via 1ull << (12 + spi_get_chipselect(spi, 0)) must remain guarded by spi_get_chipselect(spi, 0) < 4 so the shifted bit stays within csena0..csena3 (bits 12..15 of union cvmx_mpi_cfg) and does not encroach on clkdiv (bits 16..28). [F118]
- In cqspi_versal_indirect_read_dma() (drivers/spi/spi-cadence-quadspi.c), dma_addr must be programmed into CQSPI_REG_VERSAL_DMA_DST_ADDR and CQSPI_REG_VERSAL_DMA_DST_ADDR_MSB using lower_32_bits(dma_addr) and upper_32_bits(dma_addr) because CQSPI_DMA_SET_MASK enables 64-bit DMA addressing. [F120]
- In drivers/spi/spi-cadence-quadspi.c, cqspi_probe() stores struct cqspi_st * (not struct spi_controller *) as the device driver data via platform_set_drvdata(), so all removal and PM callbacks using platform_get_drvdata() or dev_get_drvdata() must cast the result to struct cqspi_st * and access the controller via cqspi->host. [F121]
- In drivers/spi/spi-amlogic-spifc-a1.c, amlogic_spifc_a1_probe() stores struct amlogic_spifc_a1 * via platform_set_drvdata(), so all PM callbacks retrieving dev_get_drvdata(dev) must cast it to struct amlogic_spifc_a1 * and pass spifc->ctrl to spi_controller_suspend() and spi_controller_resume(). [F122]
- In drivers/spi/spi-bitbang.c, callbacks cast spi_controller_get_devdata() directly to struct spi_bitbang *, so any driver allocating its private struct via spi_alloc_host() (such as struct butterfly, struct ath79_spi, and struct au1550_spi) must place struct spi_bitbang as its first member. [F123]
- In drivers/spi/spi-bitbang.c, bitbang_txrx_8(), bitbang_txrx_16(), and bitbang_txrx_32() track count in bytes (t->len) while advancing typed tx and rx pointers (u8 *, u16 *, u32 *) by one element per word, so each loop iteration must decrement count by the byte stride (1, 2, or 4) and guard with count > 0, count > 1, or count > 3 respectively. [F128]
- In drivers/spi/spi-altera-core.c, altera_spi_txrx() sets hw->len in words (t->len / hw->bytes_per_word) and altera_spi_rx_word() increments hw->count by 1 word, so altera_spi_tx_word() and altera_spi_rx_word() must scale hw->count by hw->bytes_per_word (1, 2, or 4) when indexing hw->tx and hw->rx. [F129]
- In drivers/spi/spi-bcm2835.c, bcm2835_spi_interrupt() receives struct bcm2835_spi *bs as its dev_id parameter (registered in bcm2835_spi_probe()), whereas DMA completion callbacks bcm2835_spi_dma_rx_done() and bcm2835_spi_dma_tx_done() receive struct spi_controller *ctlr as data (set in bcm2835_spi_prepare_sg()). [F132]
- In drivers/spi/atmel-quadspi.c, DLL control (`QSPI_CR_DLLON`, `QSPI_CR_DLLOFF`, `QSPI_DLLCFG`, and polling `QSPI_SR2_DLOCK`) must be gated on `aq->caps->has_dllon`, and pad calibration (`atmel_qspi_set_pad_calibration()`) must only run when both `aq->caps->octal` and `aq->caps->has_padcalib` are true. [F144]
- In `struct bcm2835_spidev`, `clear_rx_cs` must remain `____cacheline_aligned` and the structure must be allocated with size aligned to `dma_get_cache_alignment()` in `bcm2835_spi_setup` because `clear_rx_cs` is mapped for streaming DMA via `dma_map_single` and synced with `dma_sync_single_for_device`. [F154]
