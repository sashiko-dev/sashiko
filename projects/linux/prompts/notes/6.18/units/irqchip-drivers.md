# IRQCHIP DRIVERS

This unit implements core irqchip probing, per-CPU IRQ partitioning, and interrupt/MSI controller drivers across architectures, including ARM GICv3/v4/v5 (ITS, MBI, GICv2m, GIC PM), RISC-V (PLIC, APLIC, IMSIC), and SoC controllers (Atmel AIC/AIC5, BCM2712, Renesas RZ/G2L/RZ/V2H, STM32MP EXTI, Sophgo SG2042/SG2044, Allwinner sunxi, Qualcomm MPM, Socionext EXIU, and Xilinx).

## Architecture & Data Flow
- In `irq-gic-v3-its.c`, `irq_to_cpuid_lock()`/`unlock()` must check `d->chip == &its_vpe_irq_chip` before casting `d->chip_data` to `struct its_vpe *`, because non-vPE IRQs store `struct its_device *` in `d->chip_data` and only reach a vPE via `get_vlpi_map(d)`. [F42]
- Callers of `its_send_mapti()` must update `event_map.col_map[event]` before the call, whereas callers of `its_send_movi()` must update `event_map.col_map[event]` only after `its_send_movi()` returns because `its_build_movi_cmd()` reads the old collection from `col_map` for `SYNC`. [F59]
- In `its_vlpi_map()` and `its_vlpi_unmap()`, `irqd_set_forwarded_to_vcpu(d)` must precede `lpi_write_config()` on map, and `irqd_clr_forwarded_to_vcpu(d)` must precede `lpi_update_config()` on unmap, because `get_vlpi_map()` tests `irqd_is_forwarded_to_vcpu(d)` to select between `vm->vprop_page` and host `prop_table_va`. In `lpi_update_config()`, `direct_lpi_inv(d)` may run only when `gic_rdists->has_direct_lpi && (is_v4_1(its_dev->its) || !irqd_is_forwarded_to_vcpu(d))`; on GICv4.0, forwarded vLPIs must use `its_send_vinv()`. [F61, F105]
- In `its_vpe_set_affinity()`, whenever `from != cpu`, `its_send_vmovp()` and `its_vpe_db_proxy_move()` must always be called after updating `vpe->col_idx`, even if the old and new CPUs share a GICv4.1 `vpe_table_mask`. In `its_set_affinity()`, `its_dec_lpi_count(d, prev_cpu)` runs before CPU selection, so every exit path must call `its_inc_lpi_count()` on `cpu` (or `prev_cpu` on error). [F58, F60]
- In `irq-gic-v3-its.c`, `event_lpi_map` arrays (`lpi_map`, `col_map`, `vlpi_maps`) are 0-indexed by `d->hwirq - its_dev->event_map.lpi_base` (`its_get_event_id(d)`), whereas LPI property tables in `lpi_write_config()` are byte-indexed by `hwirq - 8192`. In `mip_middle_domain_free()`, `gicv2m_unalloc_msi()`, `mbi_free_msi()`, and `its_irq_domain_free()`, callers of `bitmap_release_region()`/`mip_free_hwirq()` must subtract `mip->msi_offset`, `v2m->spi_start`, `mbi->spi_start`, or `lpi_base`. [F85, F94, F128, F133]
- `its_allocate_entry()` must zero `cmd->raw_cmd[0..3]`, every ITS command builder must call `its_fixup_cmd(cmd)` for little-endian conversion, and `its_send_vmovp()` must zero-initialize `struct its_cmd_desc desc = {}` because `!its_list_map` leaves `seq_num` and `its_list` unassigned while `its_build_vmovp_cmd()` encodes them. [F47, F48]
- On GICv4.1 redistributors (`GICR_TYPER_RVPEID`), `__gic_update_rdist_properties()` and `allocate_vpe_l1_table()` must clear `GICR_VPENDBASER_Valid` (writing `GICR_VPENDBASER_PendingLast`) before clearing `GICR_VPROPBASER_4_1_VALID` or reprogramming `GICR_VPROPBASER`; `inherit_vpe_l1_table_from_rd()` must clear `GICR_VPROPBASER_4_1_Z`. In `its_cpu_init_lpis()`, jumping to `out` when LPI tables are preallocated must still run GICv4 `GICR_VPROPBASER`/`VPENDBASER` setup and `allocate_vpe_l1_table()`. [F70, F141, F151]
- In `irq-gic-v3.c`, `gic_chip` (EOImode 0) and `gic_eoimode1_chip` (EOImode 1) are parallel `irq_chip` structures; shared callbacks, flags, and EOI errata (`gic_arm64_erratum_2941627_needed(d)` falling back to `gic_poke_irq(d, GICD_ICACTIVER)`) must be updated in both. `gic_cpu_sys_reg_enable()` must precede `gic_prio_init()`, `gic_cpu_init()`, and `gic_cpu_sys_reg_init()` on boot, secondary bringup, and CPU PM exit. [F82, F135, F148]
- In `irq-sifive-plic.c`, source ID `0` is reserved (loops over priority/enable registers must start at `1`). `plic_irq_enable()` must call both `plic_irq_toggle(..., 1)` and `plic_irq_unmask(d)`, and `plic_set_affinity()` must clear the old hart enable bit using `irq_data_get_effective_affinity_mask(d)` before updating `effective_affinity` and only set the new bit if `!irqd_irq_disabled(d)`. [F242, F244, F259]
- In `irq-riscv-imsic-state.c`, `global->nr_ids` is 1-based inclusive, so `lpriv->dirty_bitmap`, `lpriv->vectors`, and `imsic->matrix` must be sized to `global->nr_ids + 1` with ID `0` reserved/skipped. In `__imsic_eix_read_clear()` and `__imsic_eix_update()`, `CSR_ISELECT` must be scaled by `(id / BITS_PER_LONG) * (BITS_PER_LONG / IMSIC_EIPx_BITS)` and `CSR_IREG` bit masks bounded to `[base_id, base_id + num_id)` and `__riscv_xlen`. [F261, F262, F281]

## Synchronization
- In `its_irq_set_vcpu_affinity()`, `its_dev->event_map.vlpi_lock` must be acquired with `raw_spinlock` (or `raw_spinlock_irqsave`), never `raw_spinlock_irq`, because callers hold `irq_desc` lock with IRQs disabled; it must be held across all vLPI helpers (`its_vlpi_map()`, `its_vlpi_get()`, `its_vlpi_unmap()`, `its_vlpi_prop_update()`), which must use `GFP_ATOMIC`. [F1, F18, F166]
- In `struct its_node`, `its->dev_alloc_lock` (mutex) serializes `its_msi_prepare()`/`teardown()`, while `its->lock` (`raw_spinlock_t`) nests inside `dev_alloc_lock` to protect `its_device_list` and command queue writes (held across allocation, `its_flush_cmd()`, and `its_post_commands()`, and dropped before `its_wait_for_range_completion()`). In GICv4 `its_map_vm()`, `its_unmap_vm()`, `its_vpe_set_affinity()`, and `its_send_vmovp()`, lock order is `vm->vmapp_lock` -> `vpe->vpe_lock` -> `vmovp_lock` -> `its->lock`. [F24, F163, F164]
- In `lpi_write_config()`, modifying `*cfg` must be followed by `gic_flush_dcache_to_poc()` (if `RDIST_FLAGS_PROPBASE_NEEDS_FLUSHING`) or `dsb(ishst)` before invalidation. When allocating L2 tables in `its_alloc_table_entry()` or `allocate_vpe_l2_table()`, the zeroed L2 page must be flushed to PoC (if non-shareable) before writing `cpu_to_le64(page_to_phys(page) | GITS_BASER_VALID)` into `table[idx]`, followed by flushing `table + idx` and `dsb(sy)`. [F26, F27, F91]
- In `__gic_handle_irq_from_irqson()`, pseudo-NMIs must run inside `nmi_enter()`/`nmi_exit()` before `gic_pmr_mask_irqs()` and `gic_arch_enable_irqs()` clear `DAIF.IF`. In `__gic_handle_irq_from_irqsoff()`, `ICC_PMR_EL1` must be saved and masked via `gic_pmr_mask_irqs()` + `isb()` before `gic_read_iar()`, then restored via `gic_write_pmr()`. [F168, F174]
- In `irq-riscv-imsic-state.c`, `lpriv->lock` nests outside `imsic->matrix_lock`: code holding `matrix_lock` must never acquire `lpriv->lock` or call `imsic_vector_alloc()`/`free()`. Updates to an allocated `imsic_vector`, `lpriv->dirty_bitmap`, `lpriv->timer`, and indirect CSRs (`__imsic_eix_update()`, `imsic_local_delivery()`) require local IRQs disabled; `imsic_state_offline()` must cancel `lpriv->timer` under `lpriv->lock` via `timer_delete_sync_try()`, and `__imsic_local_timer_start()` must use `add_timer_on(&lpriv->timer, cpu)`. [F204, F205, F237, F333, F334, F336]
- In `plic_probe()`, `irq_set_chained_handler()`, `cpuhp_setup_state()`, and `register_syscore_ops()` must only be called after `priv->irqdomain` and all online CPUs' `plic_handlers` entries are initialized; post-init accesses to `handler->enable_base` must hold `handler->enable_lock` with `raw_spin_lock_irqsave`. In `imsic_early_probe()`, `imsic_parent_irq` must be mapped and chained before `cpuhp_setup_state()`. [F201, F203, F344]
- In `irq-stm32mp-exti.c`, `chip_data->rlock` wraps `hwspin_lock_timeout_in_atomic(hwlock, ...)` in `stm32mp_exti_set_type()` and must be dropped before parent `irq_chip` calls. Similarly, `priv->lock` in `irq-qcom-mpm.c` and `irq-renesas-rzv2h.c` must be released before calling `irq_resolve_mapping()`, `irq_set_irqchip_state()`, or parent `irq_chip` callbacks. [F200, F210, F212, F215]

## Object Lifetimes
- `its_alloc_pages_node()` and `its_free_pages()` pass `order` to `alloc_pages_node()`/`free_pages()` but page count `1 << order` to `set_memory_decrypted()`/`set_memory_encrypted()`, and must intentionally leak pages rather than freeing them if `set_memory_decrypted()` or `set_memory_encrypted()` fails. [F3, F125]
- `its_vlpi_map()` must increment `its_dev->event_map.nr_vlpis` and call `its_map_vm()` only when `!irqd_is_forwarded_to_vcpu(d)`, and `its_vlpi_unmap()` must clear `its_dev->event_map.vm = NULL` and free `vlpi_maps` when `!--its_dev->event_map.nr_vlpis` reaches zero. [F6]
- `its_msi_teardown()` must hold `its_dev->its->dev_alloc_lock` and skip freeing LPIs, unmapping the ITT, and calling `its_free_device()` whenever `its_dev->shared` is true or `its_dev->event_map.lpi_map` is non-empty. [F7]
- `gicv2m_init_one()` takes ownership of `fwnode` on success, so on error callers (`gicv2m_of_init()`, `acpi_parse_madt_msi()`) must release `child`/`fwnode` themselves; breaking early out of `of_find_matching_node()` in `gicv2m_of_init()` also requires `of_node_put(child)`. [F13, F99]
- During IMSIC vector migration in `__imsic_local_sync()`, the old CPU frees the old vector via `imsic_vector_free(vec)` after clearing `vec->move_next`, and the new CPU must not clear `vec->move_prev` or its `dirty_bitmap` bit while `READ_ONCE(mvec->move_next)` is non-NULL. [F195]

## API Contracts
- `gic_retrigger()`, `its_irq_retrigger()`, and `its_vpe_retrigger()` must logically negate (`!`) the 0-on-success return of their `*_set_irqchip_state()` helpers because `irq_chip::irq_retrigger` returns non-zero on success. [F40]
- `its_irq_set_vcpu_affinity()` accepts `vcpu_info == NULL` to unmap a vLPI (`its_vlpi_unmap()`), so it must check `!info` before dereferencing `info->cmd_type`, and `its_vlpi_get()`/`unmap()`/`prop_update()` must verify `its_dev->event_map.vm && irqd_is_forwarded_to_vcpu(d)` before indexing `vlpi_maps`. [F44]
- Every `msi_prepare` callback over GICv3/v5 ITS must round `nvec` up to a power of two and set `info->scratchpad[0].ul` to the DeviceID (plus `info->scratchpad[1].ul` to the translate frame PA on GICv5) before calling the parent `msi_prepare`. In `its_create_device()`, `dev->nr_ites` must be `>= 2` and `dev->itt_sz >= ITS_ITT_ALIGN` (256) so `its_build_mapd_cmd()` does not underflow `ilog2(nr_ites) - 1`. [F52, F88, F89, F178]
- In `its_vpe_set_affinity()`, when `!atomic_read(&vpe->vmapp_count)`, `-EINVAL` may be returned only if `gic_requires_eager_mapping()` is true; otherwise update effective affinity and return `IRQ_SET_MASK_OK_DONE` without issuing hardware commands. In `its_build_vmapp_cmd()`, unmapping a vPE on GICv4.1 must return `NULL` so `its_send_single_vcommand()` skips `GITS_CMD_VSYNC`. [F98, F140]
- `msi_parent_ops` using `msi_lib_init_dev_msi_info()` must set `MSI_CHIP_FLAG_SET_EOI` without `MSI_CHIP_FLAG_SET_ACK` for fasteoi parents (`gic_v3/v5_its_msi_parent_ops`, `gicv2m_msi_parent_ops`, `gic_v3_mbi_msi_parent_ops`, `mip_msi_parent_ops`), and `MSI_CHIP_FLAG_SET_ACK` for edge-triggered parents (`sg2042/2044_msi_parent_ops`, `imsic_msi_parent_ops`). [F175, F176, F347]
- In RISC-V APLIC (`irq-riscv-aplic-*.c`), source `0` is reserved and valid `hwirq` IDs are `1..priv->nr_irqs`: `APLIC_SETIENUM`/`CLRIENUM`/`SETIPNUM_LE` take 1-based `d->hwirq`, whereas `APLIC_SOURCECFG_BASE`/`APLIC_TARGET_BASE` use `(d->hwirq - 1) * sizeof(u32)` and domain size is `priv->nr_irqs + 1`. Shared helpers in `irq-riscv-aplic-main.c` must never downcast `struct aplic_priv *` to `struct aplic_direct *`, and `aplic_msi_translate()` must read `((struct msi_domain_info *)d->host_data)->data`. [F224, F309, F310]
- In `irq-renesas-rzg2l.c`, `irq-renesas-rzv2h.c`, and `irq-pic32-evic.c`, callbacks must retrieve driver private data from `d->domain->host_data` (`irq_data_to_priv(d)` / `irqd_to_priv(data)`), never `irq_data_get_irq_chip_data(d)`. [F311, F312]

## Error Handling
- When the per-vPE loop in `its_vpe_irq_domain_alloc()` fails after `vm->db_bitmap` and `vm->vprop_page` are assigned, rollback must call only `its_vpe_irq_domain_free(domain, virq, i)` without also calling `its_lpi_free()` or `its_free_prop_table()` directly. Also, because `its_lpi_alloc()` halves `nr_irqs` until a range fits, callers requiring at least `nr_irqs` LPIs must check `*nr_ids < nr_irqs` and call `its_lpi_free()` on shortfall. [F2, F37]
- In `its_save_disable()`, if `its_force_quiescent()` fails, it must restore `its->ctlr_save` to `GITS_CTLR` on the failing node and iterate backward via `list_for_each_entry_continue_reverse()` to restore `GITS_CTLR` on all previously quiesced ITS nodes before dropping `its_lock`. [F10]
- In `gic_cpu_pm_notifier()`, the restoration branch (`gic_enable_redist(true)`, `gic_cpu_sys_reg_enable()`, `gic_cpu_sys_reg_init()`) must run on both `CPU_PM_EXIT` and `CPU_PM_ENTER_FAILED`. [F136]

## External Contracts
- Before writing `GITS_BASER<n>` or `GITS_CBASER` in `its_reset_one()`, `its_probe_one()`, or `its_restore_enable()`, `its_force_quiescent()` must clear `GITS_CTLR_ENABLE` and `GITS_CTLR_ImDe` and poll until `GITS_CTLR_QUIESCENT` is set. [F28]
- In `irq-gic-v3.c`, `gic_mask_irq()` must wait for `GICR_CTLR_RWP` or `GICD_CTLR_RWP` to clear after writing `GICD_ICENABLER`, `gic_set_affinity()` must mask an enabled IRQ before writing `GICD_IROUTER` and unmask afterward, and `gic_dist_init()` must enable `GICD_CTLR_ARE_NS` and wait for `gic_dist_wait_for_rwp()` before writing `GICD_IROUTER`/`GICD_IROUTERnE`. [F34, F146]

## Known Pitfalls
- In `its_vpe_mask_irq()`, `its_vpe_unmask_irq()`, `its_vpe_4_1_mask_irq()`, and `its_vpe_4_1_unmask_irq()`, `lpi_write_config()` must receive `d->parent_data` (physical doorbell LPI `>= 8192`), whereas `its_vpe_send_inv()` and `__direct_lpi_inv()` must receive `d` as the `irq_data` and `d->parent_data->hwirq` as the INTID. On GICv4.0 (`!is_v4_1`), `its_vlpi_set_doorbell()` must update a mapped vLPI's doorbell via `its_send_vmovi()` rather than `its_send_vmapti()`. [F104, F186]
- In `plic_irq_eoi()`, if `irqd_irq_disabled(d)` is true, the context enable bit must be temporarily set via `plic_toggle(handler, d->hwirq, 1)` before writing `d->hwirq` to `CONTEXT_CLAIM` and cleared afterward. In `imsic_early_dt_init()`, `of_node_clear_flag(node, OF_POPULATED)` must be called so `imsic_platform_driver` can later probe. [F243, F329]
- In `irq-renesas-rzg2l.c` and `irq-renesas-rzv2h.c`: `ISCR`/`ICU_ISCLR`/`ICU_TSCLR` must only be cleared when edge-triggered (never level-triggered), followed by a dummy `readl_relaxed()` on RZ/G2L; `rzv2h_tint_irq_endisable()` must write `BIT(tint_nr)` to `ICU_TSCLR` after updating `ICU_TSSR(k)`; `TSSR_OFFSET(n)` must be shifted by `TSSEL_SHIFT(tssr_offset)` (`8 * tssr_offset`) and computed before subtracting `TITSR0_MAX_INT` in `rzg2l_tint_set_edge()`; and in `rzv2h_tint_set_type()`, `ICU_TSSR_*` takes `tssel_n` while `ICU_TITSR_*` takes `titsel_n`. [F220, F249, F250, F276, F279, F316]
