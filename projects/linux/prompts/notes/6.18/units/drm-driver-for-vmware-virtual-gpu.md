# DRM DRIVER FOR VMWARE VIRTUAL GPU

This component implements kernel mode setting (KMS) display units (Legacy, Screen Object, and Screen Target), video overlays, Guest Memory Object (MOB) page tables, resource lifecycle/eviction, 3D resources (shaders, views, streamoutput, simple resources), coherent BO page-dirty tracking, PRIME handle conversion, and host RPC/mksGuestStats messaging for the VMware SVGA driver.

## Architecture & Data Flow
- `struct vmw_user_object` must never have both `surface` and `buffer` non-NULL: when `vmw_user_object_lookup` resolves a non-dumb BO handle to a surface via `vmw_lookup_surface_for_buffer`, it must release and clear `uo->buffer` via `vmw_user_bo_unref(&uo->buffer)`. In `vmw_sou_primary_plane_prepare_fb` and `vmw_sou_primary_plane_cleanup_fb`, `vps->bo_size` must be set to `bo_params.size` when `vps->uo.buffer` is created and reset to `0` whenever `vps->uo` is unreferenced. [F8, F74]
- In `vmw_stdu_crtc_atomic_disable` and `vmw_stdu_crtc_mode_set_nofb`, tearing down a defined Screen Target (`stdu->defined`) requires `vmw_stdu_bind_st(dev_priv, stdu, NULL)` and `vmw_stdu_update_st()` before `vmw_stdu_destroy_st()`. However, in `vmw_stdu_crtc_atomic_disable`, when `new_crtc_state->enable && !new_crtc_state->active && !new_crtc_state->mode_changed`, it must only unbind and update the screen target to blank it and must not call `vmw_stdu_destroy_st()`. [F72, F140]
- When pinning a legacy scanout buffer in `vmw_ldu_fb_pin` or allocating a VRAM backing buffer in `vmw_sou_primary_plane_prepare_fb`, bracket the operation with `vmw_overlay_pause_all` and `vmw_overlay_resume_all`. When pausing (`vmw_overlay_stop` with `pause == true`), retain `stream->buf` and `stream->saved` while unpinning `stream->buf` and setting `stream->paused = true`; when stopping (`pause == false`), unreference `stream->buf` and set `stream->paused = false`. [F77, F156]
- Display unit capabilities: `vmw_kms_sou_init_display` requires `dev_priv->has_gmr` and `SVGA_CAP_SCREEN_OBJECT_2`; `vmw_kms_stdu_init_display` requires `dev_priv->has_mob` and `SVGA_CAP_GBOBJECTS`; in `vmw_overlay_send_put` and `vmw_overlay_move_buffer`, test `dev_priv->active_display_unit` against `vmw_du_legacy` (not equality with `vmw_du_screen_object`) so `vmw_du_screen_target` is included. [F97, F145]
- `vmw_resource_mob_attach` and `vmw_resource_mob_detach` must update `gbo->res_tree` and `gbo->res_prios` in lockstep using the priority cached in `res->used_prio` at attach time (not recomputing from `res->res_dirty` on detach) and clear `res->mob_node` with `RB_CLEAR_NODE` on detach. [F62]
- In `vmwgfx_so.c`, an active `struct vmw_view` must be linked into both `srf->view_list` (`srf_head`) and `view->cotable` (`cotable_head`) with `res->id = view->view_id`, and unlinked from both with `list_del_init` and `res->id = -1` when destroyed or uncommitted. Every SVGA3D DX view define command in `vmw_view_add`/`vmw_view_create` must place 32-bit `view_id` at offset 0 and 32-bit `sid` at offset 4 (`struct vmw_view_define`). [F66, F87]
- Changes to `enum vmw_view_type` (`vmw_view_max`) must update `vmw_view_define_sizes`, `view_is_dirtying`, `vmw_view_destroy_cmds`, `vmw_view_cotables`, `union vmw_view_destroy`, and `vmw_view_cmd_to_type` in lockstep. `vmw_view_cmd_to_type` must check non-contiguous command IDs (e.g., `SVGA_3D_CMD_DX_DEFINE_UA_VIEW`, `SVGA_3D_CMD_DX_DEFINE_DEPTHSTENCIL_VIEW_V2`) before applying the unsigned `u32` calculation `tmp = (id - SVGA_3D_CMD_DX_DEFINE_SHADERRESOURCE_VIEW) / 2`. [F67, F103, F118]
- In `vmw_dx_shader_cotable_list_scrub` and `vmw_dx_streamoutput_cotable_list_scrub`, `entry->committed` must be preserved when `readback` is true and cleared to `false` only when `!readback`, whereas `res->id = -1` and `list_del_init(&cotable_head)` are always performed. [F68]
- `vmw_otables_setup` must `kmemdup` `dx_tables` or `pre_dx_tables` into `dev_priv->otable_batch.otables` before `vmw_otable_batch_setup` rounds each enabled `otables[i].size` up with `PFN_ALIGN()`. `vmw_mob_calculate_pt_pages` and `vmw_mob_build_pt` must both use ceiling page division (`DIV_ROUND_UP`/`PFN_ALIGN`), and `mob->pt_level` from `vmw_mob_pt_setup` must be offset by `VMW_MOBFMT_PTDEPTH_1 - SVGA3D_MOBFMT_PT_1` exactly once when `mob->pt_bo` is populated. [F69, F93, F119, F120]

## Synchronization
- `vmw_resource_pin` and `vmw_resource_unpin` must hold `dev_priv->cmdbuf_mutex` and bracket their operation with `vmw_resource_reserve` and `vmw_resource_unreserve`, only pinning `res->guest_memory_bo` via `vmw_bo_pin_reserved(vbo, true)` when `res->pin_count` transitions from 0 to 1 and unpinning when `--res->pin_count` reaches 0. [F7]
- Buffer object reservation (`bo->tbo.base.resv`) must be held when: unpinning via `ttm_bo_unpin` or `vmw_bo_pin_reserved(bo, false)` (or use `vmw_bo_unpin_unlocked`); calling `vmw_bo_dirty_add` (and initializing `surface->res.coherent`/`dirty_alloc` in `vmw_kms_fb_create`); calling `vmw_resource_mob_attach`, `vmw_resource_mob_detach`, or `vmw_resource_unbind_list`; and building a MOB page table in `vmw_mob_pt_setup` (where `vmw_mob_build_pt` maps pages with `kmap_atomic` and must pass the unincremented `save_addr` to `kunmap_atomic`). [F21, F33, F163, F169]
- In `vmw_bo_vm_fault`, call `dma_resv_unlock(bo->base.resv)` on every exit path after `ttm_bo_vm_reserve` succeeds except when `ttm_bo_vm_fault_reserved` returns `VM_FAULT_RETRY` with `!(vmf->flags & FAULT_FLAG_RETRY_NOWAIT)`. In `vmw_bo_vm_mkwrite`, clear `FAULT_FLAG_ALLOW_RETRY` from `vmf->flags` before `ttm_bo_vm_reserve(bo, vmf)`, restore it afterward, and unlock `bo->base.resv` before returning. [F18, F31]
- Hold `dev_priv->resource_lock` when modifying `res->id` in `res_idr[]` or `res->lru_head` in `res_lru[]`; in `vmw_resource_alloc_id`, `idr_alloc` under `resource_lock` must use `GFP_NOWAIT` bracketed by `idr_preload(GFP_KERNEL)` and `idr_preload_end()`. When evicting in `vmw_resource_validate` or `vmw_resource_evict_type`, take `vmw_resource_reference` and `list_del_init(&evict_res->lru_head)` before dropping `resource_lock` for `vmw_resource_do_evict`, re-adding via `list_add_tail` on failure while bounding `err_count > VMW_RES_EVICT_ERR_COUNT`. [F22, F23, F108, F162]
- Callers of `vmw_view_destroy`, `vmw_view_cotable_list_destroy`, `vmw_view_surface_list_destroy`, `vmw_dx_shader_cotable_list_scrub`, `vmw_dx_streamoutput_cotable_list_scrub`, and `vmw_query_readback_all` must hold `dev_priv->binding_mutex`. In `vmw_query_move_notify`, `vmw_dx_shader_unbind`, and `vmw_dx_streamoutput_unbind`, release `binding_mutex` before calling `vmw_execbuf_fence_commands`. [F25, F26]
- Lockless access to `mksstat_user_pages[slot]` and `mksstat_kern_pages[slot]` requires `atomic_cmpxchg(..., MKSSTAT_PID_RESERVED)` on `mksstat_user_pids[slot]` (`task_pgrp_vnr(current)`) or `mksstat_kern_pids[slot]` (`current->pid`). On add, transition `0 -> MKSSTAT_PID_RESERVED` before setting pages and `hypervisor_ppn_add`, then `atomic_set` pid; on removal, claim with `MKSSTAT_PID_RESERVED`, call `hypervisor_ppn_remove`/`reset_all`, unpin/free pages, null `mksstat_*_pages[slot]`, then `atomic_set` pid to `0`. [F14, F34, F35, F172, F192]
- Updating or checking display layout fields (`gui_x`, `gui_y`, `pref_width`, `pref_height`, `pref_active`) in `vmw_du_update_layout` and `vmw_kms_check_topology` requires holding `crtc->mutex` (inside `dev->mode_config.mutex` in `vmw_du_update_layout`). `vmw_kms_close` must call `drm_mode_config_cleanup` without holding `mode_config.mutex` and before `vmw_kms_ldu_close_display`. [F37, F139]

## Object Lifetimes
- Once `vmw_simple_resource_init` or `vmw_gb_shader_init` is called on an embedded `struct vmw_resource`, its `res_free` callback owns the enclosing struct and runs on init failure; callers (`vmw_simple_resource_create_ioctl`, `vmw_user_shader_alloc`, `vmw_shader_alloc`) must never `kfree` or `vmw_resource_unreference` if init fails. On init success, `vmw_simple_resource_create_ioctl` and `vmw_user_shader_alloc` must take a second `vmw_resource_reference` (`tmp`) before `ttm_base_object_init`, unreference `tmp` if `ttm_base_object_init` fails, and always unreference `res`. [F1, F2, F144]
- In `vmw_user_resource_lookup_handle` and `vmw_simple_resource_lookup`, take a `ttm_base_object` reference via `ttm_base_object_lookup` and call `vmw_resource_reference` on the embedded resource before calling `ttm_base_object_unref`. In `vmw_dx_shader_add`, `vmw_view_add`, and `vmw_dx_streamoutput_add`, acquire `cotable` and `srf` references via `vmw_resource_reference` before `vmw_resource_init`, and drop `res` via `vmw_resource_unreference(&res)` on both success and failure. [F3, F166]
- In `vmw_resource_release`, MOB unbind/detach, `vmw_binding_res_list_kill` (under `binding_mutex`), `hw_destroy(res)`, and `res_free(res)`/`kfree(res)` must all execute before removing `id` from `dev_priv->res_idr` under `resource_lock`. [F143]
- In `vmw_compat_shader_add`, create the bytecode `vmw_bo` with `.pin = false` and `.keep_resv = true`, and call `ttm_bo_unreserve(&buf->tbo)` on both the `ttm_bo_kmap` failure path and after `ttm_bo_validate` before `vmw_bo_unreference(&buf)`. [F4]
- When `switch_guest_memory` is true in `vmw_resource_unreserve`, detach `res->guest_memory_bo`, call `vmw_bo_dirty_release` (if `res->coherent`), and call `vmw_user_bo_unref` when switching to a different BO; still call `vmw_bo_dirty_release` when `new_guest_memory_bo == res->guest_memory_bo` and `res->coherent` is true. [F6]
- Because `mob->pt_bo` and `batch->otable_bo` are created pinned via `vmw_bo_create_and_populate`, every teardown and rollback path (`vmw_mob_destroy`, `vmw_mob_bind`, `vmw_otable_batch_setup`, `vmw_otable_batch_takedown`) must unpin the BO before `vmw_bo_unreference`. In `vmw_takedown_otable_base` and `vmw_mob_unbind`, reserve and fence `mob->pt_bo->tbo` via `vmw_bo_fence_single(bo, NULL)` before `vmw_mob_destroy`, and in `vmw_otable_batch_takedown` deactivate all enabled OTables via `vmw_takedown_otable_base` before fencing, unpinning, and unreferencing `batch->otable_bo`. [F12, F141, F170]
- When `vmw_du_plane_duplicate_state` copies `plane->state` with `kmemdup`, it must reset `vps->pinned = 0`, `vps->cpp = 0`, and `vps->cursor.mob = NULL`, and call `vmw_user_object_ref(&vps->uo)`. In `vmw_stdu_primary_plane_prepare_fb`, increment `vps->pinned` if `vmw_resource_pin` succeeds, or call `vmw_user_object_unref(&vps->uo)` if it fails. [F9, F19]
- Framebuffers from `vmw_kms_fb_create` acquire `vmw_bo_dirty_add(bo)` (and allocate `surf->res.dirty` when `dirty_alloc` is present), which must be released in `vmw_framebuffer_surface_destroy` or `vmw_framebuffer_bo_destroy` via `vmw_bo_dirty_release` (and `dirty_free` when `!bo->dirty && surf && surf->res.dirty`) before unreferencing `vfbs->uo` or `vfbd->buffer`. [F10]
- In `vmw_overlay_update_stream` (under `overlay->mutex`), if `vmw_overlay_send_put` fails after `vmw_overlay_move_buffer(dev_priv, buf, true, interruptible)` pinned `buf`, unpin `buf` non-interruptibly via `vmw_overlay_move_buffer(dev_priv, buf, false, false)`; on success, only assign `stream->buf = vmw_bo_reference(buf)` when `stream->buf != buf`. [F17, F176]

## API Contracts
- Callers of `vmw_kms_helper_validation_finish` (including `vmw_kms_readback`, `vmw_kms_sou_readback`, `vmw_kms_stdu_readback`) must pass `file_priv` and `user_fence_rep` as either both `NULL` or both non-NULL, and `vmw_kms_helper_validation_finish` must initialize `fence = NULL`, `handle = 0`, and `ret = 0` before the conditional call to `vmw_execbuf_fence_commands`. [F45, F189]
- Only downcast `struct vmw_framebuffer *vfb` via `vmw_framebuffer_to_vfbd` (or pass to `vmw_kms_readback`/`vmw_kms_sou_do_bo_dirty`) when `vfb->bo` is true, and via `vmw_framebuffer_to_vfbs` when `vfb->bo` is false. In `vmw_prime_handle_to_fd`, export handles `> VMWGFX_NUM_MOB` or non-dumb BOs (`!vbo->is_dumb`) with a positive `vmw_lookup_surface_handle_for_buffer` via `ttm_prime_handle_to_fd`, and dumb/non-surface BOs via `drm_gem_prime_handle_to_fd`. [F133, F188]
- Validate `(user_key, view_type)` with `vmw_view_id_ok` before `vmw_view_key` or indexing `vmw_view_cotables`, and validate `(user_key, shader_type)` with `vmw_shader_id_ok` before `vmw_shader_key`. In `vmw_shader_define`, cast both `size` and `offset` to `u64` before adding them to check against `buffer->tbo.base.size`. [F88, F90, F116]

## Error Handling
- On `struct vmw_validation_context`, failure of `vmw_validation_prepare` requires `vmw_validation_unref_lists(&val_ctx)`, whereas failure after `vmw_validation_prepare` succeeds requires `vmw_validation_revert(&val_ctx)`. When `VMW_CMD_RESERVE` fails in `vmw_mob_bind`, call `vmw_fifo_resource_dec(dev_priv)` and only unpin/unreference `mob->pt_bo` if `pt_set_up` is true. [F11, F13]
- In `vmw_mksstat_add_ioctl`, reject zero `stat_len`/`info_len`/`strs_len` or `PFN_UP(len) > ARRAY_SIZE(pdesc->...PPNs)` before calling `pin_user_pages_fast(..., FOLL_LONGTERM, ...)`. Store pin counts in signed `long` variables; on partial pin or `< 0`, unpin all `nr_pinned_* > 0` slices in reverse order via `unpin_user_pages`, reset `mksstat_user_pids[slot]` to `0`, and `kfree` only `page` and `pages_stat` (never interior pointers `pages_info` or `pages_strs`). [F15, F61, F81, F130, F191]
- Check `vmw_user_object_buffer` for `NULL` when `uo` may be surface-backed (`guest_memory_bo` can be `NULL`); check `old_mem` for non-NULL in `vmw_query_move_notify`; check `vmw_crtc_state_and_lock` for both `IS_ERR()` and `NULL`; check `drm_atomic_get_connector_state`, `vmw_shader_lookup`, `vmw_view_lookup`, `vmw_dx_streamoutput_lookup`, and `vmw_simple_resource_lookup` with `IS_ERR()`. [F41, F43, F44, F52, F56]
- In `vmw_kms_fb_create`, every branch jumping to `err_out` must set `ret` to a negative errno first (`err_out` is a pass-through label when `ret == 0`). `vmw_recv_msg` returns `0` with `*msg = NULL` when `MESSAGE_STATUS_DORECV` is clear (and on error/retry must `kfree(reply)` and set `reply = NULL`), so callers must check `*msg && *msg_len > 0` even after a `0` return and `kfree(*msg)` when done. [F16, F42, F58]

## Known Pitfalls
- Both `struct vmw_shader` and `struct vmw_dx_shader` have `res->func->res_type == vmw_res_shader`: only call `vmw_res_to_shader` when `res->func == &vmw_gb_shader_func` and `vmw_res_to_dx_shader` when `res->func == &vmw_dx_shader_func`. Also, `vmw_dx_shader_add` must pass `shader_type = 0` (`vmw_shader_key(user_key, 0)`) to `vmw_cmdbuf_res_add` after `vmw_shader_id_ok` because DX shader IDs are per-context. [F89, F134]
- In `vmw_stdu_primary_plane_prepare_fb`, assign `metadata.base_size` after copying `metadata = vmw_user_object_surface(&new_vfbs->uo)->metadata` when `new_content_type != SAME_AS_DISPLAY`, and when `vps->uo.buffer->is_dumb`, `!res->res_dirty`, and `drm_atomic_helper_damage_merged` reports damage, call `vmw_resource_dirty_update` explicitly. In `vmw_stdu_bo_cpu_commit`, compute `src_offset` with display coordinates and `src_pitch`, and `dst_offset` with framebuffer coordinates and `dst_pitch`. [F73, F102, F187]
- In `vmw_ldu_commit_list`, do not dereference the `list_for_each_entry` cursor `entry` after the loop finishes without a break (use the saved `crtc` pointer). In `vmw_resources_clean`, when the initial RB-tree lookup on `vbo->res_tree` finds an overlapping resource, record `found = cur_res` and continue traversing `cur = cur->rb_left` rather than breaking early. [F101, F105]
- Pass page indices (`pgoff_t`)—not byte offsets—to `vmw_resource_dirty_update`, `vmw_bo_dirty_unmap` (casting `(end - start)` to `loff_t` before `<< PAGE_SHIFT`), and `vmw_resources_clean`, using ceiling division (`DIV_ROUND_UP`) when converting `res->guest_memory_offset + res->guest_memory_size` to an end page index. [F112, F121, F126]
