# QAT DRIVER

This component implements the Intel QuickAssist Technology (QAT) PCI device drivers for Gen2 (`c3xxx`, `c62x`, and their VFs), Gen4 (`4xxx`, `420xx`), and Gen6 (`6xxx`) accelerators, along with common core infrastructure in `qat_common`. It manages device lifecycle, PCI BAR and CSR operations, firmware administration mailboxes, key-value configuration tables, AER error recovery, RAS error reporting, power management, PF/VF mailbox protocols, and debugfs/ioctl control interfaces.

## Architecture & Data Flow

- In `struct adf_accel_dev`, `pf` and `vf` share a union discriminated by `is_vf`; shared paths (like `adf_notify_fatal_error_worker()`) must check `!accel_dev->is_vf` before reading `pf.vf_info`. Similarly, `accel_dev->admin` (NULL on VFs) must be checked in `adf_init_admin_pm()`, `adf_get_pm_info()`, and `adf_exit_admin_comms()`, and `accel_dev->fw_loader` requires checking `hw_device->fw_name` in all `adf_accel_engine.c` lifecycle functions. [F37, F38, F41]
- Under `table_lock` in `adf_dev_mgr.c`, re-adding or removing a host VF (`is_vf && pf`) with an existing `vf_id_map` must increment/decrement `map->fake_id` and every subsequent `next->fake_id` while toggling `map->attached`. `adf_devmgr_get_dev_by_id()` must translate `fake_id` to `id` via `adf_get_vf_real_id()`, and only `map->id` (`accel_id`) may index `id_map[ADF_MAX_DEVICES]`. `adf_clean_vf_map(true)` must skip entries with `map->bdf == -1` and only update `id_map`/`num_devices` when `map->bdf != -1`. [F58, F86, F91]
- On Gen4, non-`SVC_DCC` `adf_fw_config` tables must place `ADF_FW_ADMIN_OBJ` last, preceded by at least `RP_GROUP_COUNT` (2) worker entries mapping to `RP_GROUP_0` and `RP_GROUP_1`. In `adf_gen4_get_ring_to_svc_map()`, when `SVC_DCC` is enabled, all `rps[0..RP_GROUP_COUNT - 1]` entries must be set to `COMP` rather than derived via `uof_get_obj_type`. On 420xx, `uof_get_num_objs()` must switch on `adf_get_service_enabled()` to return the active table's `ARRAY_SIZE`. [F54, F70, F104]
- In `get_accel_cap()` across Gen2/Gen4/Gen6, a set bit (`1`) in fuse/strap registers (`legfuses`, `fuses[ADF_FUSECTL0]`, `straps`, `fusectl1`) means the hardware slice is disabled and must clear the corresponding `ICP_ACCEL_CAPABILITIES_*` bits. On `qat_4xxx`, `qat_420xx`, and `qat_6xxx`, when `SVC_DCC` is configured, `ICP_ACCEL_CAPABILITIES_CRYPTO_SYMMETRIC` must be cleared from `(capabilities_dc | capabilities_sym)`. [F131, F132]
- `adf_get_pmisc_base()`, `adf_get_etr_base()`, and `adf_get_aram_base()` index `pci_bars[ADF_PCI_MAX_BARS]` using compact indices `0..2` from `get_*_bar_id()`, not raw PCI BAR numbers (`0, 2, 4`). In `qat_c62x/adf_drv.c:adf_probe()`, when `hw_data->fuses[ADF_FUSECTL0] & ADF_DEVICE_FUSECTL_MASK` is set, `pci_bars[]` population must start at `i = 1` so the remaining BARs map to `ADF_C62X_PMISC_BAR` (1) and `ADF_C62X_ETR_BAR` (2). [F77, F78]
- `adf_pfvf_csr_msg_of()` returns `0` if `msg.type` or `msg.data` overflows `pfvf_csr_format`, which `adf_gen2_pfvf_send()` and `adf_gen4_pfvf_send()` must check before writing the CSR. Because `csr_gen2_fmt` limits `type` to `0x0F` and `data` to `0x3FF`, message types `>= 0x10` are Gen4-only. In `adf_gen2_pfvf.c`, `ADF_GEN2_CSR_IN_USE` (`0x6AC2`) and `ADF_GEN2_CSR_IN_USE_MASK` (`0xFFFE`) must keep bit 0 clear so `remote_offset` updates never touch the remote `ADF_PFVF_INT` bit. [F35, F81, F82]
- In `adf_fw_counters_allocate()`, `fw_counters->ae_count` must be set before accessing `fw_counters->ae_counters[]` (`__counted_by(ae_count)`). In `cnv_err_stats_alloc()` and `adf_fw_counters_load_from_device()`, `ae_cnv_errors[]` and `ae_counters[]` are sized by `hweight_long(ae_mask)` and must be indexed by sequential `i++` while `for_each_set_bit()` is bounded by `GET_MAX_ACCELENGINES(accel_dev)`. [F115, F116]

## Synchronization

- `adf_put_admin_msg_sync()` and `adf_admin.c` callers of `adf_send_admin()` acquire `admin->lock` (`struct mutex`) and sleep in `read_poll_timeout()`, requiring sleepable context. `admin->lock` must be held continuously across checking mailbox not-busy (`== 1`), copying into `admin->virt_addr`, writing `1` to the mailbox CSR, polling for `0`, and copying out the response. `adf_init_admin_comms()` must finish all DMA/CSR/mutex setup before assigning `accel_dev->admin = admin`. [F25, F26, F150]
- `adf_gen2_pfvf_send()` and `adf_gen4_pfvf_send()` require sleepable context and must hold `csr_lock` (`pf2vf_lock` or `vf2pf_lock`) continuously across CSR writes, `read_poll_timeout()`, and (on Gen2) retry sleeps and clearing the remote in-use pattern. `adf_gen2_pfvf_recv()` and `adf_gen4_pfvf_recv()` run in tasklet `pf2vf_bh_tasklet` and must remain lockless and non-blocking; `gen2_csr_clear_in_use()` must only be called when `compat_ver >= ADF_PFVF_COMPAT_FAST_ACK && !is_notification_message(msg.type)`. [F29, F30, F151]
- `adf_notify_fatal_error()` and `adf_gen4_handle_pm_interrupt()` run in hardirq context (`adf_msix_isr_ae`) and must use `GFP_ATOMIC` when allocating work structs. `adf_pfvf_ops` interrupt mask callbacks (`enable_vf2pf_interrupts`, `disable_*_vf2pf_interrupts`) run under spinlock `vf2pf_ints_lock` with IRQs disabled and must not sleep; `disable_pending_vf2pf_interrupts` must first mask all VF interrupts (`ADF_GEN*_VF_MSK`) and then write `sources | disabled` in a second CSR write. [F102, F147, F149]
- In `adf_gen4_handle_pm_interrupt()`, the top-half must set `ADF_GEN4_PM_SOU` in `ADF_GEN4_ERRMSK2` before reading `ADF_GEN4_PM_INTERRUPT` and queuing `pm_irq_work`, and `pm_bh_handler()` must write `pm_int_sts` to `ADF_GEN4_PM_INTERRUPT` before clearing `ADF_GEN4_PM_SOU` in `ADF_GEN4_ERRMSK2`. In `adf_gen4_print_pm_status()`, `pm_info` must be allocated with `kmalloc()` (never stack/vmalloc), and `dma_unmap_single(..., DMA_FROM_DEVICE)` must be called on `p_state_addr` immediately after `adf_get_pm_info()` returns—before jumping to `out_free` or reading `pm_info`. [F15, F27, F157]
- During AER recovery (`adf_error_detected()`, `adf_dev_aer_schedule_reset()`, `adf_device_reset_worker()`, `adf_slot_reset()`), `ADF_STATUS_RESTARTING` must be set before `adf_dev_down()` or `adf_dev_restart()` and cleared only after SR-IOV re-enablement and restart notifications finish. `adf_device_reset_worker()` (`device_reset_wq`) waits for `adf_device_sriov_worker()` (`device_sriov_wq`), so the two workqueues must remain separate and `device_sriov_wq` must never wait on `device_reset_wq`. [F20, F155]
- In `adf_cfg_add_key_value_param()`, `down_write(&cfg->lock)` must be held continuously across `adf_cfg_key_val_get()`, conditional `adf_cfg_keyval_remove()` (when an existing key's value differs), and `adf_cfg_keyval_add()`, and the new `adf_cfg_key_val` must be `kfree()`d if the key already exists with an identical value. In `qat_dev_cfg_sops`, `qat_dev_cfg_start()` must unconditionally acquire `qat_cfg_read_lock` even when returning `NULL` to balance `qat_dev_cfg_stop()`. `adf_ctl_lock` nests outside `table_lock` and `accel_dev->state_lock`. [F7, F17, F152, F163]

## Object Lifetimes

- In `adf_aer.c`, `adf_device_reset_worker()` must `kfree()` `struct adf_reset_dev_data` only when `reset_data->mode == ADF_DEV_RESET_ASYNC`, because synchronous resets in `adf_dev_aer_schedule_reset()` retain ownership across `wait_for_completion_timeout()` and `cancel_work_sync()` before freeing it. [F1]
- During probe rollback and removal, `adf_dev_down()` must run before `adf_dbgfs_exit()`, `adf_cfg_dev_remove()`, and `adf_devmgr_rm_dev()`. Callers of `adf_dev_up()` must call `adf_dev_down()` if `adf_dev_up()` fails. In drivers using `adf_cleanup_accel()`, `adf_devmgr_add_dev()` must succeed before jumping to `adf_cleanup_accel()` (which unconditionally calls `adf_devmgr_rm_dev()`), and `adf_cleanup_accel()`, `adf_cfg_dev_remove()`, and `adf_cfg_dev_dbgfs_rm()` must guard against `NULL` `hw_device` and `cfg`. [F3, F9, F22, F42]
- In `qat_420xx` and `qat_4xxx`, `accel_dev`, `hw_data`, and PCI BARs use devres (`devm_kzalloc()`, `pcim_*()`), so `adf_cleanup_accel()` and `adf_remove()` must not manually free, unmap, or disable them. In `qat_6xxx/adf_drv.c`, all teardown steps are registered via `devm_add_action_or_reset()` using `void (*)(void *)` wrappers (never function casts), so `adf_driver` omits `.remove` and probe error paths must return directly. [F122, F129, F130]
- Every PF `pci_driver` must define `.shutdown` calling `adf_dev_down()`, and PF `adf_probe()` must call `pci_save_state(pdev)` after `pci_set_master(pdev)` and before `adf_dev_up()`. In VF `adf_probe()`, `init_completion(&accel_dev->vf.msg_received)` must precede `adf_dev_up()`; in VF `adf_remove()`, `adf_flush_vf_wq(accel_dev)` must precede `adf_dev_down()` and `adf_cleanup_accel()`. `adf_ctl_stop_devices()` must iterate `adf_devmgr_get_head()` in two passes: stopping all VFs (`is_vf`) before stopping PFs. [F12, F13, F23, F124, F126]
- In `adf_init_admin_comms()`, failure of the second `dma_alloc_coherent()` must free the first DMA buffer and `admin`, and `adf_exit_admin_comms()` must set `accel_dev->admin = NULL`. In `adf_ae_fw_load()` and `adf_ae_fw_load_images()`, any failure after requesting firmware or mapping UOF objects must call `adf_ae_fw_release()`, and `qat_uclo_del_obj(loader)` must be called at the end of each per-object loop iteration in `adf_ae_fw_load_images()`. [F4, F5, F103]

## API Contracts

- In `adf_cfg_add_key_value_param()`, `val` must be `long *` for `ADF_DEC`, a NUL-terminated string for `ADF_STR`, and `(void *)uintptr_t` for `ADF_HEX`. Callers of `adf_cfg_get_param_value()` and `adf_parse_service_string()` must pass a buffer of at least `ADF_CFG_MAX_VAL_LEN_IN_BYTES` (64) bytes. `adf_ctl_ioctl_dev_config()` must reject `IOCTL_CONFIG_SYS_RESOURCE_PARAMETERS` when `adf_dev_started(accel_dev)` is true, and `adf_copy_key_value_data()` must bound loops by `ADF_CFG_MAX_SECTION`/`ADF_CFG_MAX_KEY_VAL` and call `adf_cfg_del_all()` on error. [F47, F48, F97, F120, F161]
- `adf_bank_state_save()`, `adf_bank_state_restore()`, and `adf_gen4_bank_quiesce_coal_timer()` require `adf_gen4_init_hw_csr_ops()` (Gen2 leaves read callbacks `NULL` and its `tx_rx_gap == 8` with 16 rings overflows `state->rings[]`). Bank save/restore and `ring_pair_reset()` take PF bank indices (`vf_nr * num_banks_per_vf + bank_number`), whereas `GET_SRV_TYPE(accel_dev, idx)` requires a bundle-relative index (`ring_num % num_banks_per_vf`). `adf_gen4_bank_quiesce_coal_timer()` takes `timeout_ms` (reject `< 0`, cast to `u64`), whereas `adf_gen4_bank_drain_start()` takes `timeout_us`. [F39, F50, F51, F53, F87, F107]
- Gen4 `adf_init_hw_data_*()` paths using `adf_gen4_init_thd2arb_map()` must set `get_rp_group`, `get_ena_thd_mask`, `get_num_aes`, `uof_get_num_objs`, and `uof_get_ae_mask` across all device ID branches. `adf_gen4_init_num_svc_aes()` uses `container_of(device_data, struct adf_hw_device_data, rl_data)` and requires `hw_data->get_ae_mask` to be initialized first. On VFs, `hw_data->get_sram_bar_id` is `NULL`, so `adf_get_aram_base()` must not be called on VFs without checking it. [F40, F55, F118]
- `cnv_err_stats_alloc()` and `adf_fw_counters_get()` return an `ERR_PTR` on failure (check `IS_ERR()`) and transfer a `kmalloc`'d table to `qat_*_file_open()`, which must `kfree()` it if `seq_open()` fails or on release. `qat_comp_build_ctx()` requires a `2 * sizeof(struct icp_qat_fw_comp_req)` buffer and must increment `req_tmpl` after copying `req_tmpl` to `req_tmpl + 1` before `build_decomp_block()`. `adf_get_dc_capabilities()` must mask out `admin_ae_mask` from `ae_mask`. [F6, F80, F98, F136]

## Error Handling

- `adf_put_admin_msg_sync()` copies all 32 bytes (`ADF_ADMINMSG_LEN`) of `__packed` `icp_qat_fw_init_admin_req` into DMA memory and returns `0` on CSR completion even if FW rejects the command; callers must zero-initialize `req` and check both the return value and `resp.status`. Callers of `adf_get_fw_capabilities()` must zero-initialize `*caps` before calling it because it returns `0` without writing `*caps` when `admin_ae_mask == 0`. [F36, F43, F45, F79]
- Check non-standard error returns: `pcim_iomap_region()` returns `ERR_PTR` (check `IS_ERR(bar->virt_addr)`, not `!bar->virt_addr`); `hw_data->get_ena_thd_mask()` returns unsigned `u32` and signals error via `== ADF_GEN4_ENA_THD_MASK_ERROR` (`0x1ff`); `adf_get_service_enabled()` returns `0` for `SVC_ASYM` and `< 0` on error (store in signed `int`); and `adf_find_free_id()` returns `ADF_MAX_DEVICES + 1` when full (check `accel_id > ADF_MAX_DEVICES`). [F31, F32, F33, F34]
- In `bank_state_restore()`, if saved `state->ringexpstat` is non-zero, return `0` before writing `state->ringsrvarben` or checking ring status CSRs; otherwise verify `ops->read_csr_exp_stat(base, bank) == 0` before `write_csr_ring_srv_arb_en` and `check_stat()`. In `adf_init_aer()` / `adf_exit_aer()`, failure of a later workqueue or teardown must `destroy_workqueue()` and NULL any earlier workqueue pointer (`device_reset_wq`). [F2, F62]

## External Contracts

- `adf_user_cfg_key_val`, `adf_user_cfg_section`, and `adf_user_cfg_ctl_data` must remain `__packed` with each pointer unioned with `__u64` for `compat_ptr_ioctl`. `IOCTL_STATUS_ACCEL_DEV` must remain `_IOW(ADF_CTL_IOC_MAGIC, 3, __u32)` while `adf_ctl_ioctl_get_status()` copies a full `struct adf_dev_status_info` (which must be fully initialized by `copy_from_user()` or zeroed before `strscpy()` writes `dev_info.name`). PF drivers supporting multiple device IDs with distinct FW images must declare `MODULE_FIRMWARE()` for every variant's main FW and MMP binary. [F46, F74, F75, F158]

## Known Pitfalls

- In `adf_gen4_ras.c`, composite error dispatchers (`adf_gen4_process_errsou1..3`, `adf_handle_iaintstatssm`, `adf_handle_spppar_err`, `adf_handle_ssm`) must accumulate `reset_required` with bitwise `|=`, not `||` or early return; `*_WAT_WCP` CSR accesses must be guarded by `GET_ERR_MASK(accel_dev)->parerr_wat_wcp_mask`; in `adf_gen4_process_errsou3()`, `adf_handle_aramcerr()`, `adf_handle_aramuerr()`, and `adf_handle_reg_cppmemtgterr()` take `aram_csr` (and must OR `ADF_GEN4_REG_*_EN_BITMASK` when clearing W1C bits) while other sub-handlers take `csr`; and modifying `ADF_GEN4_TIMISCCTL` must preserve `ADF_GEN4_TIMSCCTL_RELAY_BITMASK`. [F95, F100, F135, F142, F143]
- Avoid 32-bit and bitop hazards: narrower bitmasks (`u16 accel_mask`, `u32 ae_mask`, `u32 fuses[]`, 32-bit CSRs) must be copied to `unsigned long` before passing `&mask` to `for_each_set_bit()` / `test_bit()`; `read_base()` (`adf_gen4_hw_csr_data.h`) must cast `u_base` to `u64` before `<< 32`; `adf_gen4_bank_quiesce_coal_timer()` must use `do_div(wait_us, clock_frequency)`; and `measure_clock()` must check `!delta_us` before dividing and parenthesize `(HZ_PER_MHZ / 10)` in `temp * (HZ_PER_MHZ / 10)`. [F105, F106, F108, F109, F121]
- In `bank_state_restore()`, before restoring `state->iaintflagsrcsel0`, write `write_csr_ring_head` a second time for empty TX rings (`state->ringestat & BIT(tx)`) after setting `ADF_RP_INT_SRC_SEL_F_RISE_MASK`, and write `write_csr_ring_tail` a second time for full RX rings (`state->ringfstat & BIT(rx)`). On 420xx, `get_accel_cap()` calls `update_ae_mask()` to intersect the fuse mask with the active FW config's `ae_mask`, so it must be called after `ADF_SERVICES_ENABLED` is configured in `accel_dev->cfg`. In `adf_get_service_enabled()`, two-bit service combinations (`SVC_SYM`+`SVC_ASYM`, `SVC_SYM`+`SVC_DC`, `SVC_ASYM`+`SVC_DC`) must be tested before single-bit checks. [F56, F61, F88]
- In Gen4/Gen6 `adf_*init_device()`, `ADF_GEN*_PM_SOU` in `ERRMSK2` must be masked before writing `PM_DRV_ACTIVE` to `PM_INTERRUPT`. When updating multi-bit fields in CSRs or PCI config (`ADF_GEN6_CSR_RINGMODECTL`, `PVC0CTL`, `PVC1CTL`), use `FIELD_MODIFY()` rather than `|= FIELD_PREP()`. In `adf_devmgr_add_dev()` / `adf_devmgr_rm_dev()`, `pf` is only tested in the branch condition while all list/ID/BDF operations target `accel_dev`. [F99, F137, F144]
