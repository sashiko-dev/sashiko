# ACPI APEI

The ACPI Platform Error Interface (APEI) subsystem provides core infrastructure for firmware-first hardware error reporting, serialization, and injection. It includes an action table bytecode interpreter and Generic Address Structure (GAR) resource manager (`apei-base.c`), BERT and HEST parsers, GHES notification and CPER dispatchers across polling, IRQ, SCI/HED, NMI, ARM SEA, and SDEI contexts (`ghes.c`), EINJ and CXL error injection (`einj-core.c`, `einj-cxl.c`), and an ERST debug miscdevice (`erst-dbg.c`).

## Architecture & Data Flow
- Variable-length `ghes_estatus_pool` allocations (`struct ghes_estatus_cache`, `struct ghes_estatus_node`, `struct ghes_vendor_record_entry`) place payloads immediately after the header and recompute `gen_pool_free()` size via `cper_estatus_len()` or `acpi_hest_get_record_size()`. Never mutate `raw_data_offset`, `raw_data_length`, `data_length`, `revision`, or `error_data_length` before freeing, and in `ghes_proc_in_irq()` save `llnode->next` and `node_len` before `gen_pool_free()`. [F67, F114]
- Reading a GHES status block in `ghes_read_estatus()` or `ghes_in_nmi_queue_one_entry()` must peek `sizeof(struct acpi_hest_generic_status)` bytes via `__ghes_peek_estatus()` and validate it with `__ghes_check_estatus()` before reading `cper_estatus_len()` bytes via `__ghes_read_estatus()`. In `ghes_in_nmi_queue_one_entry()`, pass `&tmp_header` (not `estatus`) to `ghes_clear_estatus()` so `estatus->block_status` in the queued node is not zeroed. [F74, F100]
- In `einj_get_parameter_address()`, when ACPI 6.5 EINJv2 is active (`is_v2 && (available_error_type & ACPI65_EINJV2_SUPP)`), unmap the initial `sizeof(struct set_error_type_with_address)` mapping and remap with `v5param_size` expanded via `struct_size(&v5param.einjv2_struct, component_arr, max_nr_components)`. When `acpi5` is set, `__einj_error_inject()` and `einj_remove()` must use `v5param_size` rather than `sizeof(*v5param)`. [F82, F113]
- In `__einj_error_inject()`, updates to `einj_param` (both `struct set_error_type_with_address` and `struct einj_parameter`) must first read the existing MMIO block via `memcpy_fromio()`, modify only target injection fields, and write back via `memcpy_toio()`. In `einj-core.c`, `error_type_set()` must update `is_v2` on a `"V2_"` prefix, and `error_inject_set()` must synchronize `SETWA_FLAGS_EINJV2` in `error_flags` with `is_v2`. [F55, F56]
- In `hest.c`, every HEST error source type with `-1` in `hest_esrc_len_tab[]` must be handled in `hest_esrc_len()` (`BUG_ON(len == -1)`) and cache IA-32 MCA descriptors in `mces` (`cmc`, `mc`, `dmc`) so `is_ghes_assist_struct()` skips invoking the parser callback on subsequent GHES/GHESv2 entries matching a `related_source_id` with `ACPI_HEST_GHES_ASSIST` set. [F60, F129]
- In `struct ghes`, `list`, `timer`, and `irq` share an anonymous union selected by `ghes->generic->notify.type` (while `ghes->elist` links into `ghes_devs` under `ghes_devs_mutex`), and `generic` / `generic_v2` alias the same HEST subtable pointer (`ghes->generic_v2` fields must only be accessed when `is_hest_type_generic_v2(ghes)` is true). [F64, F119]
- Every `generic->notify.type` accepted by the validation switch in `ghes_probe()` must also be handled in both the registration switch in `ghes_probe()` and the teardown switch in `ghes_remove()` (both end with `default: BUG()`). In `ghes_in_nmi_spool_from_list()` and `ghes_notify_hed()`, RCU list traversal must inspect every entry without breaking early on the first active source. [F101, F102]

## Synchronization
- `ghes_notify_lock_irq` must be held via `spin_lock_irqsave` across every call to `ghes_proc()`, serializing `ghes->estatus` and `FIX_APEI_GHES_IRQ` across `ghes_poll_func()`, `ghes_irq_func()`, `ghes_notify_hed()`, and `ghes_probe()`. [F16]
- Each NMI-like GHES handler (`ghes_notify_sea()`, `ghes_notify_nmi()`, `ghes_sdei_normal_callback()`, `ghes_sdei_critical_callback()`) must hold its dedicated raw spinlock across `ghes_in_nmi_spool_from_list()` or `__ghes_sdei_callback()` to serialize its `FIX_APEI_GHES_*` fixmap slot. `ghes_notify_nmi()` must also gate entry with `atomic_add_unless(&ghes_in_nmi, 1, 1)` and `atomic_dec(&ghes_in_nmi)` on exit. [F17, F18]
- `ghes_in_nmi_queue_one_entry()` must never touch `ghes->estatus` or call `ghes_do_proc()` directly; it must peek into a stack header, read into a `struct ghes_estatus_node` from `ghes_estatus_pool`, and fully populate it before `llist_add(&estatus_node->llnode, &ghes_estatus_llist)`. `ghes_proc_in_irq()` and `ghes_print_queued_estatus()` must call `llist_reverse_order()` after `llist_del_all()`. [F23, F62, F140]
- Because `ghes_do_proc()` and `ghes_estatus_cache_add()` run in atomic contexts, allocations in `ghes_do_memory_failure()`, `ghes_handle_aer()`, `ghes_defer_non_standard_event()`, and `ghes_estatus_cache_alloc()` must use `gen_pool_alloc(ghes_estatus_pool, ...)` and `gen_pool_free()`. Non-standard CPER sections must be copied into a pool entry by `ghes_defer_non_standard_event()` and deferred via `schedule_work()` for `vendor_record_notify_list`. [F25, F142]
- Mutations to `ghes_hed`, `ghes_sea`, and `ghes_nmi` must be serialized with `ghes_list_mutex` using `list_add_rcu()` and `list_del_rcu()`, and removal paths (`ghes_remove()`, `ghes_sea_remove()`, `ghes_nmi_remove()`) must call `synchronize_rcu()` before `ghes_fini()` and `kfree(ghes)`. [F19]
- `ghes_estatus_caches[]` must be read under `rcu_read_lock()` in `ghes_estatus_cached()`, updated via `xchg_release(&ghes_estatus_caches[slot], RCU_INITIALIZER(new_cache))` in `ghes_estatus_cache_add()`, and freed via `call_rcu(..., ghes_estatus_cache_rcu_free)`. `ghes_estatus_cache_alloc()` increments `ghes_estatus_cache_alloced` before checking `GHES_ESTATUS_CACHE_ALLOCED_MAX` and must decrement it on both failure paths and in `ghes_estatus_cache_rcu_free()`. [F13, F147]
- `cxl_cper_post_prot_err()` and `cxl_cper_post_event()` must hold `cxl_cper_prot_err_work_lock` / `cxl_cper_work_lock` (`spinlock_irqsave`) across checking the `work_struct` pointer, `kfifo_put()`, and `schedule_work()`, and `cxl_cper_unregister_*()` must verify `work` matches and reset the global pointer to `NULL` under the lock. [F15, F24]
- Hold `einj_mutex` across runtime calls to `__einj_get_available_error_type()`, `__einj_error_inject()`, and `einj_param` accesses. Hold `erst_dbg_mutex` in `erst_dbg_read()` and `erst_dbg_write()` across size checks, `erst_dbg_buf` reallocations (verifying `kmalloc()` succeeded before `kfree(erst_dbg_buf)` and updating `erst_dbg_buf_len`), ERST calls, and user copies. [F9, F26, F27]

## Object Lifetimes
- In `ghes_probe()`, `ghes_new()` must pre-map GARs and allocate `ghes->estatus` before registering notifications; if `IS_ERR(ghes)`, reset `ghes = NULL` after `rc = PTR_ERR(ghes)` before `goto err`. In `ghes_remove()`, set `GHES_EXITING` and synchronously stop notifications (`timer_shutdown_sync()`, `free_irq()`, `list_del_rcu()` + `synchronize_rcu()`, or `apei_sdei_unregister_ghes()`) before `ghes_fini(ghes)` and `kfree(ghes)`—returning early without freeing `ghes` if `apei_sdei_unregister_ghes()` fails. [F10, F11, F20, F21, F46]
- `apei_resources_request()` mutates `struct apei_resources` in-place by subtracting `apei_resources_all`, NVS, and `arch_apei_filter_addr` regions before requesting resources and merging into `apei_resources_all`; pass the same unmodified struct to `apei_resources_release()` before `apei_resources_fini()`. In `__einj_error_trigger()`, subtract `einj_resources` (and any memory-error `trigger_param_region`) from `trigger_resources` via `apei_resources_sub()` before `apei_resources_request()`. [F127, F128]
- In `hest_parse_ghes()`, free `ghes_dev` with `platform_device_put()` if `platform_device_add_data()` or `platform_device_add()` fails, whereas once added to `ghes_arr.ghes_devs`, rollback in `hest_ghes_dev_register()` must call `platform_device_unregister()`. [F5]
- Release `acpi_get_table()` references with `acpi_put_table()` on all exit paths in `bert_init()`, on probe failure and in `einj_remove()` for `einj_tab`, and on error in `acpi_hest_init()`, while keeping `hest_tab` mapped on success in `acpi_hest_init()` because GHES devices reference entries inside it. [F131]
- In `ghes_do_memory_failure()`, when `is_hest_sync_notify(ghes)` (`ACPI_HEST_NOTIFY_SEA`) is true, queue `memory_failure_cb` via `task_work_add(current, &twcb->twork, TWA_RESUME)` for `MF_ACTION_REQUIRED` only when `current->mm` is non-NULL (falling back to `memory_failure_queue()` for kernel threads so `struct ghes_task_work` is not leaked), and `ghes_do_proc()` must call `force_sig(SIGBUS)` if `sync && !queued`. [F141, F159]
- `ghes_handle_aer()` must allocate `aer_capability_regs` from `ghes_estatus_pool` (freed via `ghes_estatus_pool_region_free()` in `aer_recover_work_func()`) and override `aer_severity` to `AER_FATAL` when `gdata->flags & CPER_SEC_RESET` is set. [F160]

## API Contracts
- All GAR accesses must validate via `apei_check_gar()` (reading `reg->address` via `get_unaligned()`, checking `access_width` 1..4, alignment, `bit_width + bit_offset <= access_bit_width`, and `SYSTEM_MEMORY`/`SYSTEM_IO`). `apei_resources_add()` and `apei_res_add()` take `size` in bytes, so `collect_res_callback()` must pass `access_bit_width / 8` (not `reg->bit_width / 8` or bit widths). [F31, F109, F132]
- `apei_read()` and `apei_write()` use raw unshifted values, whereas `__apei_exec_read_register()` and `__apei_exec_write_register()` apply `entry->mask` and `bit_offset` (and preserve unmasked bits when `APEI_EXEC_PRESERVE_REGISTER` is set). In `ghes_clear_estatus()`, zero `estatus->block_status` in physical memory before `ghes_ack_error()` writes `read_ack_register` with `read_ack_preserve` and `read_ack_write` shifted by `bit_offset`. [F30, F133, F134]
- Because a CPER section header is `struct acpi_hest_generic_data_v300` when `acpi_hest_get_version(gdata) >= 3`, always use `acpi_hest_get_payload()`, `acpi_hest_get_size()`, `acpi_hest_get_record_size()`, and `acpi_hest_get_next()` instead of `gdata + 1` or `sizeof(*gdata)`. [F115]
- `hest_parse_cmc()` returns `!arch_apei_enable_cmcff(hest_hdr, data)`, so `arch_apei_enable_cmcff()` must return non-zero (`1`) on success and `0` on failure. In `hest_parse_ghes()`, `platform_device_add_data(ghes_dev, &hest_hdr, sizeof(void *))` stores a pointer to the pointer, so `ghes_probe()` must dereference `*(struct acpi_hest_generic **)ghes_dev->dev.platform_data`. [F34, F120]
- `einj_error_inject()` rejects CXL error types when `SETWA_FLAGS_MEM` is set (`einj_is_cxl_error_type(type) && (flags & SETWA_FLAGS_MEM)`), whereas `einj_cxl_rch_error_inject()` requires both so CXL 1.0/1.1 RCRB MMIO injections bypass `is_allowed_range()` only via `einj_cxl_inject_rch_error()`. In `cxl_dport_get_sbdf()`, check `bridge->domain_nr` against `PCI_DOMAIN_NR_NOT_SET` and cast `seg`/`bus` to `u64` before encoding `(seg << 24) | (bus << 16) | (devfn << 8)`. [F39, F103, F153]

## Error Handling
- In `apei_resources_request()`, set `rc = -EINVAL` before the `request_mem_region()` and `request_region()` loops and record any failing entry in `res_bak`. On failure, `err_unmap_ioport` releases `[0, res_bak)`, resets `res_bak = NULL`, falls through to `err_unmap_iomem`, and always calls `apei_resources_fini()` on `arch_res` (when `arch_apei_filter_addr` is set) and `nvs_resources`. [F2, F32, F93]
- If `apei_exec_pre_map_gars()` fails at entry `end`, unmap only `[0, end)` by passing a shallow copy of `ctx` with `entries = end` to `apei_exec_post_unmap_gars()`, without mutating `ctx->entries`. `apei_map_generic_address()` must return `0` after `apei_check_gar()` when `reg->space_id == ACPI_ADR_SPACE_SYSTEM_IO` before calling `acpi_os_map_generic_address(reg)`. [F3, F29]
- In `__einj_error_trigger()`, initialize `p = NULL` and set `rc = -EIO` (including after `einj_check_trigger_header()`). Unmap the initial header with `iounmap(p)` before remapping `p = ioremap_cache(trigger_paddr, table_size)` and copying into `full_trigger_tab` (never derive `trigger_entry` from stack `&trigger_tab`), and guard `iounmap(p)` at `out:` with `if (p)`. [F6, F36, F81, F112]
- `__ghes_peek_estatus()` must set `*buf_paddr = 0` whenever `apei_read()` fails or `estatus->block_status == 0` because callers pass `buf_paddr` uninitialized to `ghes_clear_estatus()` on error. On a `ghes_estatus_cached()` hit, `ghes_in_nmi_queue_one_entry()` clears and frees the non-panic status block without queueing it, whereas `ghes_proc()` only skips `ghes_print_estatus()` and still runs `ghes_do_proc()`. [F45, F164]

## Known Pitfalls
- In `apei_res_add()`, when an entry overlaps or abuts `[start, end]`, unlink it, merge it into `[start, end]` and `res_ins`, and `goto repeat` to rescan from the beginning. In `apei_res_sub()`, deleting a covered `res1` entry must `break` out of the inner `res_list2` loop, and splitting `res1` around `res2` must insert the upper half after `res1` and set `resn1 = res`. [F91, F92]
- In `ghes.c`, `GHES_ESTATUS_IN_CACHE_MAX_NSEC` (`10000000000ULL`) and cache timestamps (`now`, `time_in`, `duration`, `period`) must be `unsigned long long`, and `ghes_estatus_cache_add()` must compute eviction period via `do_div(period, (count + 1))` (using `do_div()` for 64-bit division and `count + 1` since `cache->count` starts at `0`). [F105, F107, F108]
- In `apei_hest_parse()`, HEST subtables have heterogeneous sizes and trailing bank arrays, so advance `hest_hdr` via `(void *)hest_hdr + len` using `hest_esrc_len(hest_hdr)` rather than `hest_hdr++`. In `einj_timedout()`, cast `*t` (`u64`) to `s64` and compare `< SLEEP_UNIT_MIN` before subtracting `SLEEP_UNIT_MIN`. [F111, F116]
- In `error_type_set()`, reject `count > sizeof(einj_buf) - 1` and zero-fill `einj_buf` so it stays NUL-terminated for `strlen()` and `sscanf()`. Device `.remove` callbacks (`einj_remove`, `ghes_remove`) must not be marked `__exit` or `__exit_p()`, and `acpi_disabled` must be checked in `einj_init()` before `faux_device_create()`. [F121, F126]
