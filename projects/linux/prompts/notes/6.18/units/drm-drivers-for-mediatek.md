# DRM DRIVERS FOR MEDIATEK

`drivers/gpu/drm/mediatek` implements the DRM/KMS and GEM drivers for MediaTek SoC display subsystems (MMSYS/VDOSYS), binding modular Display Data Path (DDP) hardware blocks (OVL, OVL adaptor, RDMA, ETHDR, MERGE, color/gamma/AAL, DSI, DPI, DP/eDP, and HDMI CEC) into unified CRTC, plane, encoder, and bridge pipelines via the component framework and CMDQ mailbox hardware.

## Architecture & Data Flow

- Because `DDP_COMPONENT_DRM_OVL_ADAPTOR` (`DDP_COMPONENT_ID_MAX + 1`) has no DT node (`comp_node` is `NULL`), component tables must be sized `DDP_COMPONENT_DRM_ID_MAX`, `mtk_drm_of_ddp_path_build_one()` must bound `idx` by `DDP_COMPONENT_DRM_ID_MAX` and deduplicate it via `ovl_adaptor_comp_added`, and `mtk_ddp_path_available()`, `mtk_crtc_create()`, and `mtk_find_possible_crtcs()` must exempt it from `comp_node` null checks when counting available CRTC indices. [F67, F82, F98]
- In `mtk_drm_get_all_drm_priv()`, each `mtk_drm_private` must be placed in `all_drm_priv` at the fixed index (`CRTC_MAIN`, `CRTC_EXT`, or `CRTC_THIRD`) matching its non-empty path (`main_len`, `ext_len`, or `third_len`), not discovery order, because `mtk_crtc_update_output()` indexes `all_drm_private` by `drm_crtc_index(crtc)`. In `mtk_drm_kms_init()`, `drm->dev_private` must be set to `private->all_drm_private[i]` before each `component_bind_all()`, and `dma_dev` must be populated on all `mmsys_dev_num` instances after CRTC creation. [F64, F83]
- When `conn_routes` is non-NULL, `mtk_crtc_create()` allocates `path_len + 1` entries in `mtk_crtc->ddp_comp` leaving `ddp_comp[ddp_comp_nr - 1]` as `NULL` until `mtk_crtc_update_output()` runs, so `mtk_ddp_comp_mode_valid()` must check `comp != NULL`. Disabled/uninitialized route components must have `comp->encoder_index = -1`, and `mtk_crtc_update_output()` must verify `comp->encoder_index >= 0` before shifting `BIT(comp->encoder_index)`. [F87, F109]
- All `drm_plane` instances for a CRTC must be allocated in a single contiguous `mtk_crtc->planes` array in the same component order (`comp_idx` 0 then 1) that `mtk_ddp_comp_for_plane()` walks via `mtk_ddp_comp_layer_nr()`, because `mtk_ddp_comp_for_plane()` computes `local_index = plane - mtk_crtc->planes`. [F88]
- `mtk_crtc_update_config()` promotes per-plane `pending.dirty`/`async_dirty` to `pending.config`/`async_config` and sets `mtk_crtc->pending_planes`/`pending_async_planes`, which must be cleared in `mtk_crtc_ddp_config()` (when `!cmdq_handle`) or `ddp_cmdq_cb()`. In `mtk_plane_atomic_async_update()`, `plane->state` is mutated in place via `mtk_plane_update_new_state(new_state, to_mtk_plane_state(plane->state))`, `swap(plane->state->fb, new_state->fb)`, `wmb()`, and `pending.async_dirty = true`. [F58, F80]
- In `mtk_disp_ovl.c` and `mtk_crtc.c`, AFBC registers (`DISP_REG_OVL_PITCH_MSB`, `DISP_REG_OVL_HDR_ADDR`, `DISP_REG_OVL_HDR_PITCH`) and `OVL_LAYER_AFBC_EN` must only be programmed when `ovl->data->supports_afbc` is true, and `mtk_crtc_init_comp_planes()` must gate AFBC modifier support on `mtk_ddp_comp_is_afbc_supported(comp)`. `DISP_REG_OVL_PITCH(idx)` takes `pending->pitch & GENMASK(15, 0)` while `DISP_REG_OVL_PITCH_MSB(idx)` takes `pending->pitch >> 16` (ORed with `OVL_PITCH_MSB_2ND_SUBBUF` for AFBC). [F95, F147]
- In `struct mtk_disp_ovl_data`, any non-zero `blend_modes` must include `BIT(DRM_MODE_BLEND_PREMULTI)` and `mtk_ovl_fmt_convert()` must only read `state->base.pixel_blend_mode` when that bit is set; `gmc_bits` must be `<= GMC_THRESHOLD_BITS` (16) to avoid shift underflow in `mtk_ovl_layer_on()`. In `mtk_ovl_layer_config()`, `OVL_CONST_BLEND` must be set when `blend_mode == DRM_MODE_BLEND_PIXEL_NONE` or `!state->base.fb->format->has_alpha`. [F56, F102, F121]
- In `mtk_ovl_adaptor_layer_config()`, when `!use_dual_pipe` (`align_width <= MTK_OVL_ADAPTOR_RDMA_MAX_WIDTH`), `r_w` is `0` and `rdma_r` must be stopped via `mtk_mdp_rdma_stop()`; on layer disable, `mtk_ethdr_layer_config()` must still be called after stopping `merge`, `rdma_l`, and `rdma_r`. In `mtk_ethdr_layer_config()`, `MIX_L_SRC_*` and `MIX_SRC_CON` use 0-based `idx` (`0..3`), whereas `mtk_mmsys_mixer_in_config()` takes 1-based `idx + 1`. In `mtk_merge_advance_config()`, `if (r_w)` must follow `if (priv->fifo_en)`. [F68, F86, F112]
- In `mtk_dp.c`, `mtk_dp->drm_dev` is `NULL` until `mtk_dp_bridge_attach()` completes and after `mtk_dp_bridge_detach()`, so `mtk_dp_wait_hpd_asserted()`, `mtk_dp_parse_capabilities()`, and `mtk_dp_aux_transfer()` must log with `mtk_dp->dev`. `mtk_dp_bridge_mode_valid()` and `mtk_dp_bridge_atomic_get_input_bus_fmts()` must compute available link bandwidth from `mtk_dp->train_info.link_rate` and `lane_count` scaled by `97 / 100`. [F39, F71]
- In `mtk_dsi.c`, SoC-dependent offsets and flags (`reg_cmdq_off`, `reg_vm_cmd_off`, `reg_shadow_dbg_off`, `has_shadow_ctl`, `has_size_ctl`, `cmdq_long_packet_ctl`, `support_per_frame_lp`) must be accessed via `dsi->driver_data`. In `mtk_dsi_poweron()`, `mtk_dsi_phy_timconfig(dsi)` must precede `mtk_dsi_config_vdo_timing(dsi)` so `dsi->phy_timing` is populated before LP timing calculations; `MIPI_DSI_MODE_NO_EOT_PACKET` sets `DIS_EOT` and omits the 2-byte EOT timing delta. [F76, F103, F149]

## Synchronization

- `mtk_crtc->config_lock` and `crtc->dev->event_lock` must always be acquired with `spin_lock_irqsave()`/`spin_unlock_irqrestore()`; `config_lock` nests inside `mtk_crtc->hw_lock` (in `mtk_crtc_update_config()`) and outside `crtc->dev->event_lock` (in `mtk_drm_finish_page_flip()` and `ddp_cmdq_cb()`). [F161, F162]
- `ddp_cmdq_cb()` and `mtk_drm_finish_page_flip()` must check `mtk_crtc->config_updating` under `mtk_crtc->config_lock`, and `ddp_cmdq_cb()` must not clear `state->pending_config`, `mtk_crtc->pending_planes`, or `mtk_crtc->pending_async_planes` when `config_updating` is true. When `mtk_crtc->cmdq_client.chan` is non-NULL, `mtk_drm_finish_page_flip()` must return after `drm_crtc_handle_vblank()`, deferring `mtk_crtc_finish_page_flip()` to `ddp_cmdq_cb()`. [F27, F28]
- In `mtk_crtc_update_config()`, when `mtk_crtc->cmdq_client.chan` is active, the driver must call `dma_sync_single_for_device(..., DMA_TO_DEVICE)`, set `cmdq_vblank_cnt = 3`, and clear `mtk_crtc->config_updating` under `config_lock` before `mbox_send_message()`. When disabling planes in `mtk_crtc_plane_disable()` or `mtk_crtc_atomic_disable()` with active CMDQ, it must call `mtk_crtc_update_config()` and wait on `mtk_crtc->cb_blocking_queue` via `wait_event_timeout()` until `mtk_crtc->cmdq_vblank_cnt == 0`. [F29, F157]
- In `mtk_dsi_switch_to_cmd_mode()` and `mtk_dsi_host_send_cmd()`, the target interrupt bit must be cleared in `dsi->irq_data` via `mtk_dsi_irq_data_clear()` before starting the hardware operation and calling `mtk_dsi_wait_for_irq_done()`. In `mtk_dsi_irq()`, `RACK` in `DSI_RACK` must be pulsed in a loop until `DSI_BUSY` in `DSI_INTSTA` clears before clearing `DSI_INTSTA`; timeout in `mtk_dsi_wait_for_idle()` or `mtk_dsi_wait_for_irq_done()` must call `mtk_dsi_enable()` and `mtk_dsi_reset_engine()`. [F33, F156]
- In `mtk_dp.c`, `mtk_dp->irq_thread_handle` is protected by `mtk_dp->irq_thread_lock`; `mtk_dp->plugged_cb` and `codec_dev` are protected by `mtk_dp->update_plugged_status_lock`, which `mtk_dp_audio_hook_plugged_cb()` must unlock before calling `mtk_dp_update_plugged_status()`. In `mtk_cec.c`, `cec->hpd_event` and `cec->hdmi_dev` must be snapshotted under `spin_lock_irqsave(&cec->lock, flags)` and invoked after unlocking. [F34, F35, F36]

## Object Lifetimes

- In `mtk_drm_bind()`, if initialization fails after assigning `private->all_drm_private[i]->drm = drm`, all `mmsys_dev_num` entries must be cleared to `NULL` alongside `drm_dev_put(drm)` so `mtk_drm_shutdown()` does not dereference a freed `drm_device`. `private->mutex_dev` holds a single reference and must be released with `put_device(private->mutex_dev)` once outside the `mmsys_dev_num` loop in `mtk_drm_bind()` and `mtk_drm_unbind()`. [F3, F4]
- In multi-MMSYS setups (`mmsys_dev_num > 1`), only the instance with `private->drm_master == true` may unregister/free `private->drm` in `mtk_drm_unbind()` or run suspend/resume in `mtk_drm_sys_prepare()`/`mtk_drm_sys_complete()`. In `mtk_drm_unbind()`, `drm_dev_unregister()` must precede `mtk_drm_kms_deinit()`, which must call `drm_kms_helper_poll_fini()` and `drm_atomic_helper_shutdown()` before `component_unbind_all()`. [F38, F143]
- When iterating with `for_each_child_of_node()` or `for_each_endpoint_of_node()` in `mtk_drm_drv.c`, early exits (`break`, `goto`, `return`) must call `of_node_put()` on the loop variable (never before `continue`). Because `mtk_drm_of_get_ddp_ep_cid()` writes the remote port parent node to `*next` before checking device availability or component type (and may return `-ENOENT`/`-EINVAL` before assigning `*next`), callers like `mtk_drm_of_ddp_path_build_one()` must initialize `next = NULL` and call `of_node_put(next)` even on error. [F1, F5, F6, F40, F151]
- In `mtk_crtc.c`, when `mbox_request_channel()` fails or a subsequent init step fails after `mbox_free_channel()`, `mtk_crtc->cmdq_client.chan` must be set to `NULL` because runtime checks and `mtk_crtc_destroy()` test it for non-NULL. `ddp_cmdq_cb()` uses `container_of()` on `mtk_crtc->cmdq_client.client`, so `cmdq_client` must remain embedded in `struct mtk_crtc`. [F7, F131]
- Because `drm->dev` is a virtual platform device, all GEM DMA and PRIME calls must use `priv->dma_dev` (from `mtk_crtc_dma_dev_get()`) and `obj->size` (page-aligned in `mtk_gem_init()`). `mtk_gem_free_object()` calls `drm_prime_gem_destroy(obj, mtk_gem->sg)` when `mtk_gem->sg` is non-NULL and `dma_free_attrs(priv->dma_dev, ...)` otherwise; `mtk_gem_prime_vunmap()` only calls `vunmap()`, clears `mtk_gem->kvaddr = NULL`, and frees `mtk_gem->pages` when `mtk_gem->pages` is non-NULL. [F11, F12, F137, F144]
- `mtk_dsi_poweron()`/`mtk_dsi_poweroff()` and `mtk_dpi_power_on()`/`mtk_dpi_power_off()` gate PHY/clocks on `dsi->refcount` and `dpi->refcount` and must unwind and decrement `refcount` on error. `mtk_dsi_stop()` must run in `mtk_dsi_poweroff()` rather than `mtk_output_dsi_disable()` because `mtk_crtc_atomic_disable()` still needs vblank IRQs. In `mtk_dsi_host_attach()`, `dsi->next_bridge->pre_enable_prev_first = true` must precede `drm_bridge_add()`, and `drm_bridge_remove()` must be called on `component_add()` failure and after `component_del()`. [F20, F21, F22, F138, F139]

## API Contracts

- `mtk_ddp_comp_funcs.config` and `.layer_config` callbacks must not sleep or allocate with `GFP_KERNEL` because `mtk_crtc_ddp_irq()` calls `mtk_crtc_ddp_config(crtc, NULL)` in hardirq context when neither `shadow_register` nor CMDQ is used. All direct calls to `cmdq_dev_get_client_reg()` and `cmdq_pkt_*()` must be guarded by `#if IS_REACHABLE(CONFIG_MTK_CMDQ)` with CPU MMIO fallbacks. [F164, F182]
- `mtk_disp_ovl_adaptor_master_bind()` passes `struct device *mmsys_dev` as `void *data` to `component_bind_all()`, whereas `mtk_drm_kms_init()` passes `struct drm_device *drm`, so `.bind` callbacks for `ovl_adaptor` sub-drivers (`mtk_ethdr_bind()`, `mtk_disp_merge_bind()`) must not cast `data` to `struct drm_device *`. Every `enum mtk_ddp_comp_type` with a dedicated platform driver that calls `platform_set_drvdata()` must return early in `mtk_ddp_comp_init()` before it overwrites drvdata with `struct mtk_ddp_comp_dev`. [F129, F130]
- `mtk_ovl_adaptor_layer_config()` and `mtk_ethdr_layer_config()` must check `!pending->enable || !pending->width || !pending->height` and disable the layer before computing `ALIGN_DOWN(pending->width, 2)` or `align_width / 2 - 1`. `mtk_ddp_comp_supported_rotations()` and `mtk_ovl_supported_rotations()` must include `DRM_MODE_ROTATE_0`, and `mtk_ovl_layer_check()` must test `state->rotation & ~DRM_MODE_ROTATE_0` when rejecting rotated YUV. [F84, F174]
- `mtk_find_possible_crtcs()` returns a negative errno on failure, so `mtk_dpi_bind()` and `mtk_dsi_encoder_init()` must check `< 0` in a signed `int` before assigning to `encoder.possible_crtcs`. In `struct mtk_dpi_conf`, `dimension_mask` and `hvsize_mask` must be unshifted masks, `output_fmts` must order RGB formats before BGR/YUV, and `mtk_dpi_bridge_atomic_get_output_bus_fmts()` must scale `num_output_fmts` by `sizeof(*output_fmts)` in `kcalloc()`/`memcpy()`. [F51, F55, F135, F176]

## Error Handling

- When `mtk_drm_kms_init()` binds sub-components across `private->data->mmsys_dev_num` devices, any `component_bind_all()` failure must unwind previously bound indices in reverse (`while (--i >= 0)`) with `component_unbind_all()`. In `mtk_drm_of_ddp_path_build_one()`, `-ENODEV` from `mtk_drm_of_get_ddp_ep_cid()` must be returned before final-component validation (which returns `-EINVAL`) so `mtk_drm_of_ddp_path_build()` can ignore `-ENODEV` and skip disabled CRTC paths. [F2, F53]
- In `mtk_dsi_host_transfer()`, if the controller was in video mode (`dsi_mode & MODE`) and switched to command mode via `mtk_dsi_stop()` and `mtk_dsi_switch_to_cmd_mode()`, every exit path must jump to `restore_dsi_mode` to call `mtk_dsi_set_mode()` and `mtk_dsi_start()`; `recv_cnt` must be signed `ssize_t` so negative `int ret` values in `return ret < 0 ? ret : recv_cnt;` are sign-extended rather than converted to `u32`. [F24, F118]
- In `mtk_dpi_probe()`, optional pinctrl handles (`dpi->pinctrl`, `dpi->pins_gpio`, `dpi->pins_dpi`) must be cleared from `IS_ERR()` to `NULL` on lookup failure because `mtk_dpi_bridge_enable()` and `mtk_dpi_bridge_disable()` only check for non-NULL. [F48]

## Known Pitfalls

- Register bit-update helpers use opposite argument orders: `mtk_dsi_mask()` and `rdma_update_bits()` take `(..., offset, mask, val)`, whereas `mtk_dp_update_bits()`, `mtk_dpi_mask()`, and `mtk_ddp_write_mask()` take `(..., val, mask)`. [F47]
- In `mtk_ovl_layer_config()`, `DRM_MODE_ROTATE_180` must be applied by XORing `rotation` with `DRM_MODE_REFLECT_X | DRM_MODE_REFLECT_Y` before checking reflection bits so 180-degree rotation cancels an active X or Y flip. In `mtk_ethdr_layer_config()`, disabling a layer must write `0` to `MIX_L_SRC_SIZE(idx)` rather than clearing `BIT(idx)` in `MIX_SRC_CON` to avoid a hardware screen shift. [F100, F111]
- In `mtk_dsi_config_vdo_timing()`, `mtk_dsi_ps_control()` must be called with `config_vact = false` so `DSI_HSTX_CKL_WC` is not overwritten after `mtk_dsi_config_vdo_timing_per_frame_lp()` sets it. `mtk_dp_aux_transfer()` must use a `do { ... } while (accessed_bytes < msg->size)` loop so zero-length (`msg->size == 0`) address-only I2C-over-AUX transactions still call `mtk_dp_aux_do_transfer()`. [F104, F114]
