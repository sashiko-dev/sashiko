# KEXEC

The KEXEC subsystem implements the `kexec_load` and `kexec_file_load` system calls and core infrastructure for loading and booting into a new normal or crash dump kernel without passing through firmware. It manages `struct kimage` lifecycle, non-overlapping source/destination page lists and indirection pages, CMA and reserved crash memory allocation, ELF parsing, purgatory relocation, SHA-256 segment digest verification, and the final reboot transition in `kernel_kexec()`.

## Architecture & Data Flow

- In `do_kexec_load()` and `SYSCALL_DEFINE5(kexec_file_load)`, a `struct kimage` must complete `machine_kexec_prepare()`, `kimage_crash_copy_vmcoreinfo()`, segment preparation, `kexec_calculate_store_digests()` (in file mode, after all segments including purgatory are prepared and before `kimage_load_segment()` copies `segment[i].kbuf`), `kimage_load_segment()`, `kimage_terminate()`, and `machine_kexec_post_load()` (plus `kimage_file_post_load_cleanup()` in file mode) before `xchg(dest_image, image)`. [F19, F49, F123]
- `kexec_add_buffer()` may only be called when `image->file_mode` is set and `list_empty(&kbuf->image->control_pages)` (before control page allocation scans `image->segment[]`), and must initialize `kbuf->cma = NULL`, `kbuf->buf_align = max(kbuf->buf_align, PAGE_SIZE)`, and `kbuf->memsz = ALIGN(kbuf->memsz, PAGE_SIZE)` before `arch_kexec_locate_mem_hole(kbuf)` because `kexec_add_buffer()` unconditionally records `kbuf->cma` in `image->segment_cma[]`. [F35, F84, F122]
- Both `kexec_load_check()` (before `kimage_alloc_init()`) and `kexec_add_buffer()` must verify `nr_segments` does not exceed `KEXEC_SEGMENT_MAX` before writing to `image->segment[]` or `image->segment_cma[]`. [F59]
- Before allocating or loading segment pages, `sanity_check_segment_list()` must verify for every segment that `mstart <= mend` and `(mstart & ~PAGE_MASK) == 0 && (mend & ~PAGE_MASK) == 0` prior to computing `PAGE_COUNT(memsz)` (which wraps on `memsz > ULONG_MAX - (PAGE_SIZE - 1)`), check that addresses are below `KEXEC_DESTINATION_MEMORY_LIMIT`, non-overlapping, and satisfy `bufsz <= memsz`, and call `accept_memory(mem, memsz)`. [F60, F86, F111]
- For `KEXEC_TYPE_CRASH` images, `kimage_alloc_init()` and `sanity_check_segment_list()` must verify `entry` and every segment's `[mem, mem + memsz - 1]` lie within `[phys_to_boot_phys(crashk_res.start), phys_to_boot_phys(crashk_res.end)]` before `kimage_load_crash_segment()` writes to `boot_pfn_to_page(maddr >> PAGE_SHIFT)`. [F61]
- `struct kexec_segment` unions userspace `buf` with kernel `kbuf`; `kimage_load_normal_segment()`, `kimage_load_cma_segment()`, and `kimage_load_crash_segment()` must check `image->file_mode` to select `kbuf` with `memcpy()` versus `buf` with `copy_from_user()`. [F31]
- `kimage_add_entry()` must reserve the final slot of each indirection page (`image->last_entry = ind_page + (PAGE_SIZE / sizeof(kimage_entry_t)) - 1`) for `IND_INDIRECTION`, keep the slot after the latest entry zeroed until `kimage_terminate()` writes `IND_DONE`, and require all addresses ORed with `IND_FLAGS` to be `PAGE_MASK`-aligned. [F64]
- Because `kimage_load_normal_segment()` emits one `IND_DESTINATION` entry per segment followed by per-page `IND_SOURCE` entries, any `for_each_kimage_entry()` walker tracking destination addresses (`kimage_dst_used()`, `kimage_map_segment()`) must reset its destination cursor on `IND_DESTINATION` and add `PAGE_SIZE` on each `IND_SOURCE`. [F74]
- In `kimage_alloc_crash_control_pages()`, when `[hole_start, hole_end]` overlaps `image->segment[i]`, the inner loop must advance `hole_start = ALIGN(mend, size)` and `break` to restart the scan from `i = 0`, and once `i == image->nr_segments`, set `image->control_page = hole_end + 1`. [F77]
- When searching non-crash System RAM for segments, `locate_mem_hole_callback()` must skip `IORESOURCE_SYSRAM_DRIVER_MANAGED` resources and `kexec_walk_memblock()` must pass `MEMBLOCK_NONE` to `for_each_free_mem_range()` / `for_each_free_mem_range_reverse()` to exclude `MEMBLOCK_DRIVER_MANAGED`. [F98]
- In `kexec_purgatory_setup_sechdrs()`, `kbuf->image->start` is initialized to `pi->ehdr->e_entry` and must only be relocated once by the `SHF_EXECINSTR` section containing `pi->ehdr->e_entry` while `kbuf->image->start == pi->ehdr->e_entry` and before `sechdrs[i].sh_addr` is overwritten; for each allocated non-BSS section, `sechdrs[i].sh_addr` and `sechdrs[i].sh_offset` in `pi->sechdrs` must be updated together to `kbuf->mem + offset` and `offset` within `pi->purgatory_buf` without mutating `pi->ehdr`. [F45, F80]
- `kexec_apply_relocations()` and `kexec_purgatory_find_symbol()` must validate section indices (`sh_info`, `sh_link`, `st_shndx`) are below `ehdr->e_shnum`, and `kexec_purgatory_get_set_symbol()` must verify `sym->st_size == size` and `sec->sh_type != SHT_NOBITS` before accessing `pi->purgatory_buf`. [F68]
- `elf_read_ehdr()` and `elf_read_phdr()` must byte-swap fields via `elf16_to_cpu()`, `elf32_to_cpu()`, or `elf64_to_cpu()` according to `EI_CLASS`, and `elf_is_ehdr_sane()` / `elf_is_phdr_sane()` must validate entry sizes and overflow-checked buffer bounds against `buf_len` before reading program headers or segments. [F67]
- In `do_kimage_alloc_init()`, `image->elfcorehdr_index` must be initialized to `-1` and `image->ima_segment_index` gated by `image->is_ima_segment_index_set` in `check_ima_segment_index()`, because `0` is a valid index in `image->segment[]`. [F56]

## Synchronization

- Serialization of `kexec_image` and `kexec_crash_image` must use the non-spinning atomic `cmpxchg` `kexec_trylock()` / `kexec_unlock()` on `__kexec_lock` rather than a sleeping mutex because `__crash_kexec()` acquires `__kexec_lock` in NMI panic context (`nmi_panic()`); process-context holders remain sleepable, while NMI or concurrent callers must never spin on `__kexec_lock`. [F100, F101]
- `do_kexec_load()`, `SYSCALL_DEFINE5(kexec_file_load)`, and `kernel_kexec()` must hold `__kexec_lock` across reading or updating `kexec_image` or `kexec_crash_image`; for crash images, when `kexec_crash_image` is non-NULL, `arch_kexec_unprotect_crashkres()` must be called and the old image freed via `kimage_free(xchg(&kexec_crash_image, NULL))` before allocating and loading the new image, and `arch_kexec_protect_crashkres()` must be called before `kexec_unlock()` only if `kexec_crash_image` is non-NULL. [F16, F18, F104]
- `kernel_kexec()` is called with `system_transition_mutex` already held by the reboot syscall path and must not call `lock_system_sleep()`, `unlock_system_sleep()`, or `mutex_lock(&system_transition_mutex)`, while always balancing `kexec_trylock()` with `kexec_unlock()` on every exit path. [F14]
- In `kernel_kexec()` when `kexec_image->preserve_context` is false, `kexec_in_progress = true` must be set under `__kexec_lock` before `kernel_restart_prepare()` and `machine_shutdown()`, and `cpu_hotplug_enable()` must be called after `migrate_to_reboot_cpu()` and `syscore_shutdown()` before `machine_shutdown()`. [F23, F97]
- In `kernel_kexec()` when `kexec_image->preserve_context` is set (`CONFIG_KEXEC_JUMP`), suspend must proceed in order: `pm_prepare_console()`, `freeze_processes()`, `console_suspend_all()`, `dpm_suspend_start(PMSG_FREEZE)`, `dpm_suspend_end(PMSG_FREEZE)`, `suspend_disable_secondary_cpus()`, `local_irq_disable()`, `syscore_suspend()`, and unwind in reverse using `PMSG_RESTORE` for `dpm_resume_start()` and `dpm_resume_end()`; failure of `dpm_suspend_start()` or `dpm_suspend_end()` must jump to `Resume_devices` (`dpm_resume_end(PMSG_RESTORE)`), skipping `dpm_resume_start()`. [F24, F94, F95]
- Both `kexec_load` (via `kexec_load_check()`) and `kexec_file_load` must call `kexec_load_permitted(image_type)`, which requires global `capable(CAP_SYS_BOOT)` and `!kexec_load_disabled`; `kexec_load_permitted()` and `kexec_limit_handler()` must hold `limit->mutex` (`load_limit_reboot.mutex` or `load_limit_panic.mutex`) across checking and updating `limit->limit`, enforcing one-way ratchets (`kexec_load_disabled` only transitions `0` to `1`, and `kexec_limit_handler()` rejects negative values or values `>= limit->limit` when `limit->limit != -1`). [F21, F119, F120]

## Object Lifetimes

- In `kimage_file_post_load_cleanup()`, `arch_kimage_file_post_load_cleanup(image)` must run before `kfree(image->image_loader_data)` because `image->fops->cleanup` reads `image->image_loader_data`; `kexec_load_purgatory()` must leave `pi->sechdrs` and `pi->purgatory_buf` allocated on success until `kimage_file_post_load_cleanup()`, and any freed file-mode or purgatory buffer pointer (`purgatory_buf`, `sechdrs`, `kernel_buf`, `initrd_buf`, `cmdline_buf`, `ima_buffer`, `image_loader_data`) must be set to `NULL`. [F2, F12, F32]
- Kexec page and segment paths (`kimage_alloc_pages()`, `kimage_alloc_crash_control_pages()`, `kexec_alloc_contig()`, `kimage_load_crash_segment()`) must pass a page count (`1 << order` or `memsz >> PAGE_SHIFT`, not byte size) to `arch_kexec_post_alloc_pages()` before writing/clearing data and to `arch_kexec_pre_free_pages()` before freeing (`kimage_free_pages()`, `kimage_free_cma()`) or after writing each crash page; `kimage_alloc_pages()` sets `PG_reserved` and `page_private`, so its pages must be freed only via `kimage_free_pages()` or `kimage_free_page_list()`. [F6, F89, F110]
- In `kimage_free(image)`, `crash_update_vmcoreinfo_safecopy(NULL)` must be called before `vunmap(image->vmcoreinfo_data_copy)`, and when freeing indirection pages via `for_each_kimage_entry()`, an `IND_INDIRECTION` entry must be saved in `ind` and freed only upon the next `IND_INDIRECTION` entry or after the loop, because the loop dereferences `*ptr` inside the current indirection page. [F10, F72]
- In `kimage_load_normal_segment()` and `kimage_load_crash_segment()`, each `kmap_local_page(page)` must be unmapped with `kunmap_local(ptr)` before error return or `cond_resched()`, and `kexec_flush_icache_page(page)` in `kimage_load_crash_segment()` must run before `kunmap_local(ptr)` and `arch_kexec_pre_free_pages()`. [F108]

## API Contracts

- `kimage_is_destination_range()`, `locate_mem_hole_top_down()`, `locate_mem_hole_bottom_up()`, and `locate_mem_hole_callback()` take an inclusive byte range `[start, end]`, so callers checking size `sz` at `addr` must pass `addr + sz - 1`, and `kexec_walk_memblock()` must set `res.end = mend - 1` before calling `func(&res, kbuf)`. [F36, F63]
- `locate_mem_hole_callback()`, `locate_mem_hole_top_down()`, `locate_mem_hole_bottom_up()`, `kexec_walk_resources()`, and `kexec_walk_memblock()` return `1` on success and `0` to continue searching, whereas `kho_locate_mem_hole()` returns `0` on success, `< 0` on error (which must abort `kexec_locate_mem_hole()` without falling back to CMA/RAM), and `1` when KHO is inactive or loading a crash image. [F78]
- `kexec_build_elf_info()` frees `elf_info->proghdrs` via `kexec_free_elf_info(elf_info)` on any failure and transfers ownership of `elf_info->proghdrs` (while borrowing `buf` and `ehdr`, which `kexec_free_elf_info()` must not free) to the caller only when returning `0`. [F11]
- `kexec_purgatory_get_symbol_addr()` returns `ERR_PTR(-EINVAL)` on failure while `kexec_purgatory_find_symbol()` returns `NULL`, so callers of `kexec_purgatory_get_symbol_addr()` must check `IS_ERR()`. [F28]
- `kexec_image_probe_default()` iterates `kexec_file_loaders[]` until `*fops && (*fops)->probe` is false, so `kexec_file_loaders[]` must end with a `NULL` sentinel. [F99]
- In `kimage_file_prepare_segments()`, a non-zero `cmdline_len` must have `image->cmdline_buf[cmdline_len - 1] == '\0'` (returning `-EINVAL` otherwise) and is stored including the NUL byte in `image->cmdline_buf_len`, while `ima_kexec_cmdline()` must be passed `image->cmdline_buf_len - 1`. [F93, F118]

## Error Handling

- In `kimage_file_prepare_segments()`, any `struct kimage` pointer field that may receive an `ERR_PTR` (such as `image->cmdline_buf` or `image->image_loader_data` from `kexec_image_load_default()`, which returns `ERR_PTR` on failure and `NULL` when unused) must be validated with `IS_ERR()` before assignment or reset to `NULL` before jumping to `out` (`kimage_file_post_load_cleanup()`). [F3, F25]
- In `kimage_file_prepare_segments()`, after `kernel_read_file_from_fd()` succeeds for `initrd_fd` and its positive byte count is saved in `image->initrd_buf_len`, `ret` must be reset to `0`; in `kimage_alloc_init()`, `kimage_file_alloc_init()`, and `kexec_calculate_store_digests()`, if `kimage_alloc_control_pages()` or `vzalloc()` fails after `ret == 0`, `ret` must be set to `-ENOMEM` before jumping to cleanup. [F27, F33]

## External Contracts

- Every UAPI flag added in `include/uapi/linux/kexec.h` must be added to `KEXEC_FLAGS` or `KEXEC_FILE_FLAGS` in `include/linux/kexec.h`; `kexec_load_check()` must mask `KEXEC_ARCH_MASK` when checking `KEXEC_FLAGS` (`(flags & KEXEC_FLAGS) != (flags & ~KEXEC_ARCH_MASK)`), and `COMPAT_SYSCALL_DEFINE4(kexec_load)` must reject `KEXEC_ARCH_DEFAULT`. [F54, F81]
- `struct kexec_segment` in `include/linux/kexec.h` must match the binary layout of UAPI `struct kexec_segment` in `include/uapi/linux/kexec.h` because `sys_kexec_load` copies descriptors directly via `memdup_array_user()`. [F58]
- Purgatory symbols accessed via `kexec_purgatory_get_set_symbol()` (`purgatory_sha_regions`, `purgatory_sha256_digest`) must have `STB_GLOBAL` binding in a non-`SHT_NOBITS` section and match the exact byte size passed by `kexec_calculate_store_digests()`. [F55]
- Under `CONFIG_KEXEC_SIG`, `kimage_validate_signature()` must fail the load if `kexec_image_verify_sig()` fails and either `sig_enforce` is true or `security_locked_down(LOCKDOWN_KEXEC)` is active without `ima_appraise_signature(READING_KEXEC_IMAGE)`. [F121]

## Known Pitfalls

- Callers reusing a `struct kexec_buf` across multiple `kexec_add_buffer()` calls (e.g., `kexec_elf_load()`, which must also initialize `lowest_addr = ULONG_MAX`, not `UINT_MAX`) must reset `kbuf->mem = KEXEC_BUF_MEM_UNKNOWN` before each call. [F34, F82]
- After `kexec_purgatory_setup_sechdrs()`, `pi->sechdrs` holds relocated `sh_addr` and `pi->purgatory_buf`-relative `sh_offset` values for `SHF_ALLOC` sections, whereas `(void *)pi->ehdr + pi->ehdr->e_shoff` holds un-relocated headers; `kexec_apply_relocations()`, `kexec_purgatory_get_symbol_addr()`, and `kexec_purgatory_get_set_symbol()` must look up target `SHF_ALLOC` sections in `pi->sechdrs`. [F79]
- In `kexec_calculate_store_digests()`, segment-index exclusions (`image->elfcorehdr_index` and `check_ima_segment_index()`) must compare against the `image->segment[]` index `i` rather than the `sha_regions[]` output index `j`. [F71]
- In `kimage_alloc_page()` and `kimage_alloc_normal_control_pages()`, checks against `KEXEC_CONTROL_MEMORY_LIMIT` and `KEXEC_SOURCE_MEMORY_LIMIT` must compare PFNs against `LIMIT >> PAGE_SHIFT` (avoiding 32-bit `pfn << PAGE_SHIFT` overflow), and rejected pages must be queued onto `image->unusable_pages`, `image->dest_pages`, or `extra_pages` during the loop rather than freed immediately. [F75, F83]
- When `kimage_alloc_page()` swaps `page` with an existing source `old_page` from `kimage_dst_used()`, it must update `*old` while preserving `*old & ~PAGE_MASK`, and if `old_page` is rejected for HighMem when `!(gfp_mask & __GFP_HIGHMEM)`, free `old_page` (not `page`) before `continue`. [F76]
- In `kexec_limit_handler()`, `table->data` points to `struct kexec_load_limit` (with `.maxlen` unset), so it must pass a temporary `struct ctl_table` with `.data = &val` and `.maxlen = sizeof(val)` to `proc_dointvec()`, and `kexec_dprintk()` must guard `pr_info()` with `if (kexec_file_dbg_print)` (reset to `false` in `kimage_file_post_load_cleanup()`). [F92, F126]
