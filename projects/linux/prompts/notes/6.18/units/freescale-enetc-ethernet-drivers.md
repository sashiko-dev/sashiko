# FREESCALE ENETC ETHERNET DRIVERS

This unit implements the NXP ENETC and NETC (v4.1+) PCIe Integrated Endpoint Ethernet drivers, covering Physical Functions (PF v1 and v4), Virtual Functions (VF), MDIO controllers, IERB/NETC block control, and the NTMP library. It supports DMA BD rings with NAPI, XDP, PTP hardware timestamping, RSS/RFS, SR-IOV VF-PF mailbox messaging, and TSN/QoS offloads (802.1Qbv taprio, 802.1Qav CBS, 802.1Qci PSFP, 802.1Qbu frame preemption, and ETF txtime).

## Architecture & Data Flow
- VFs call `enetc_pci_probe()` with `sizeof_priv == 0`, leave `si->hw.port`/`si->hw.global` unmapped, and leave `priv->phylink` NULL. Shared paths must guard `enetc_si_priv(si)`, port/global register accesses, and `HWTSTAMP_TX_ONESTEP_SYNC` on `enetc_si_is_pf(si)` (`!!si->hw.port`), and check `priv->phylink` before phylink calls. [F36, F37, F185]
- In PF port registers (`ENETC_PSIPMAR0(n)`, `ENETC_PSICFGR0(n)`, `ENETC_PSIVLANR(n)`, `ENETC4_PSICFGR0(a)`), SI 0 is the PF and VFs use 1-based indices (`vf + 1`), whereas `pf->vf_state`, `pf->rxmsg`, `ENETC_PSIVMSGRCVAR0(n)`, and `ENETC_PSIMSGRR_MR(n)` use 0-based VF indices. Promiscuous registers (`ENETC_PSIPMR`, `ENETC4_PSIPMMR`, `ENETC_PSIPVMR`, `ENETC4_PSIPVMR`) are shared across all SIs, so updating one SI must preserve other SIs' bits (and update `pf->vlan_promisc_simap` on v1). [F71, F82]
- On ENETC v1 (`enetc_sync_mac_filters()`), the first `EMETC_MAC_ADDR_FILT_RES` (3) MAC filter entries are reserved so PF unicast exact-match uses index 3; on ENETC4 (`enetc4_pf_set_uc_exact_filter()`, `enetc4_pf_set_mac_filter()`), MAFT entries use `0 .. pf->num_mfe - 1`, SI 0 unicast hash must be cleared on MAFT success, and `enetc4_pf_clear_maft_entries()` must clear all MAFT entries on hash fallback (setting `pf->num_mfe = i` before `clear_maft_entries` on failure at `i` in `enetc4_pf_add_maft_entries()`). [F43, F72, F84]
- A TX extension BD (`ENETC_TXBD_FLAGS_EX`) consumes its own ring slot and increments the descriptor count; ring space checks must reserve room for both the extension BD and the 1-BD ring-full gap via `ENETC_TXBDS_NEEDED()` or `enetc_lso_count_descs()`. In `enetc_map_tx_buffs()` and `enetc_lso_map_data()`, BDs are staged in `temp_bd`/`txbd_tmp` and committed to `*txbd` only when advancing or after the fragment loop so `ENETC_TXBD_FLAGS_F`, `is_eof`, and `skb` are set on the final BD. [F78, F97]
- In `struct enetc_tx_swbd`, `skb` and `xdp_frame` share a union discriminated by `is_xdp_tx` and `is_xdp_redirect` (read via `enetc_tx_swbd_get_skb()` / `enetc_tx_swbd_get_xdp_frame()`, with `page` valid only when `is_xdp_tx`). `enetc_unmap_tx_buff()` requires `is_dma_page = 0` for `dma_map_single()`, `is_dma_page = 1` with `is_xdp_tx = 0` for `skb_frag_dma_map()`, both set for `PAGE_SIZE` `XDP_TX` pages, and `tx_swbd->dma == 0` on pre-allocated coherent TSO/LSO header BDs (`enetc_map_tx_tso_hdr()`, `enetc_lso_map_hdr()`). [F38, F168, F169]
- `enetc_clean_tx_ring()` captures `do_twostep_tstamp`/`tstamp` on the first BD (`tx_swbd->check_wb`), consumes them and resets `do_twostep_tstamp = false` on the last BD (`tx_swbd->skb`), and must `memset(tx_swbd, 0, sizeof(*tx_swbd))` on every completed BD because TX mapping functions do not clear all fields when reusing slots. [F5, F99]
- In `union enetc_tx_bd`, the last 32-bit word overlays `l3_aux0`/`l3_aux1`/`l4_aux`/`flags` with `__le32 txstart`: TX checksum offload cannot be used when `tx_ring->tsd_enable` is active, and `enetc_txbd_set_tx_start()` must preserve `flags` at `ENETC_TXBD_FLAGS_OFFSET` (bits 24..31). [F91]
- Toggling `ENETC_F_RX_TSTAMP` in `enetc_hwtstamp_set()` must call `enetc_reconfigure(priv, extended, NULL, NULL)` so `enetc_alloc_rx_resource()` doubles `res->bd_size` and `enetc_setup_rxbdr()` updates `rx_ring->ext_en` and `ENETC_RBMR_BDS`. When `rx_ring->ext_en` is true, hardware RX BDs must only be indexed/advanced via `enetc_rxbd()`, `enetc_rxbd_next()`, and `enetc_rxbd_ext()`. [F66, F125]
- Hardware does not support clearing TX BDR (`ENETC_TBPIR`/`ENETC_TBCIR`) or NETC CBDR (`pir`/`cir`) index registers on setup, so `enetc_setup_txbdr()` and `ntmp_init_cbdr()` must initialize `next_to_use` and `next_to_clean` by reading the hardware registers rather than setting them to 0. [F65]
- `priv->xdp_tx_ring` points to `&priv->tx_ring[priv->num_tx_rings - num_possible_cpus()]`, and `enetc_rx_ring_from_xdp_tx_ring()` recovers the RX ring index via `&priv->tx_ring[tx_ring->index] - priv->xdp_tx_ring`, so `XDP_TX` on `rx_ring` must enqueue onto `priv->xdp_tx_ring[rx_ring->index]`. [F86]
- `enetc_setup_xdp_prog()` must return `-EBUSY` if `priv->min_num_stack_tx_queues + num_xdp_tx_queues > priv->num_tx_rings`. `enetc_reconfigure_xdp_cb()` must update `netif_set_real_num_tx_queues()` via `enetc_num_stack_tx_queues(priv)` (reverting `priv->xdp_prog` on error) so stack TX queues never share lockless XDP TX rings, and update every RX ring's `xdp.prog` and `buffer_offset` in lockstep. [F57, F165, F186]
- In `struct enetc_pf_ops`, `create_pcs`, `destroy_pcs`, and `enable_psfp` are optional (`NULL` in `enetc4_pf_ops`) and must be checked for non-NULL in `enetc_pf_common.c`. Shared Express/Preemptible Port MAC register writes must use `enetc_port_mac_wr()` instead of `enetc_port_wr()` so `reg + si->drvdata->pmac_offset` is updated when `ENETC_SI_F_QBU` is set. [F39, F68]

## Synchronization
- Fast-path MMIO accessors (`enetc_rd_reg_hot()`, `enetc_wr_reg_hot()`, `enetc_rd_hot()`, `enetc_wr_hot()`, `enetc_refill_rx_ring()`, `enetc_update_tx_ring_tail()`) assert `lockdep_assert_held(&enetc_mdio_lock)` when `enetc_has_err050089` is enabled and must be bracketed by `enetc_lock_mdio()` / `enetc_unlock_mdio()`. [F149]
- Because `enetc_lock_mdio()` takes `read_lock(&enetc_mdio_lock)` without disabling IRQs (including from `enetc_msix` and `enetc_poll`), code inside it must not sleep, allocate with `GFP_KERNEL`, or call MDIO accessors, and MDIO writers (`_enetc_rd_mdio_reg_wa`, `_enetc_wr_mdio_reg_wa`) must use `write_lock_irqsave()`. [F155, F157]
- `ENETC_TX_DOWN` in `priv->flags` must be set at the start of `enetc_stop()`, cleared only at the end of `enetc_start()`, and checked before `enetc_xdp_xmit()`, `XDP_TX` in `enetc_clean_rx_ring_xdp()`, and subqueue wakeup in `enetc_clean_tx_ring()`. In `enetc_stop()`, `enetc_disable_rx_bdrs()`, `enetc_wait_bdrs()`, and `enetc_disable_tx_bdrs()` must run before `disable_irq()`, `napi_synchronize()`, and `napi_disable()` so NAPI drains in-flight `XDP_TX` frames (`xdp_tx_in_flight` to 0). [F19, F20]
- One-step PTP Sync packets (`ENETC_F_TX_ONESTEP_SYNC_TSTAMP`) must acquire `ENETC_TX_ONESTEP_TSTAMP_IN_PROGRESS` via `test_and_set_bit_lock()` in `enetc_start_xmit()` (not `enetc_xmit()`), and worker `enetc_tx_onestep_tstamp()` must hold `netif_tx_lock_bh()` / `netif_tx_unlock_bh()` when clearing that bit and transmitting from `priv->tx_skbs`. [F21, F159]
- In `netc_xmit_ntmp_cmd()`, `cbdr->ring_lock` must be held with `spin_lock_bh()` across slot selection, `dma_wmb()`, `cbdr->regs.pir` write, `read_poll_timeout_atomic()` on `cbdr->regs.cir`, `dma_rmb()`, response copyback, and `ntmp_clean_cbdr()`. [F24, F171]
- `enetc_send_cmd()` runs in atomic contexts (`enetc_pf_set_rx_mode()` under `netif_addr_lock_bh` and `remove_one_chain()` under `spin_lock(&epsfp.psfp_lock)`) and must busy-wait with `udelay()` without sleeping. In `enetc_psfp_parse_clsflower()`, `enetc_psfp_hw_set()` must run before acquiring `epsfp.psfp_lock`, and `!enable` paths called by `remove_one_chain()` under `epsfp.psfp_lock` must never sleep or call `enetc_cbd_alloc_data_mem()`. [F160, F163]
- Because `ntmp_maft_add_entry()` / `ntmp_maft_delete_entry()` allocate with `GFP_KERNEL`, `enetc4_pf_set_rx_mode()` must defer to `si->rx_mode_task`, and `enetc4_pf_set_uc_exact_filter()` must snapshot `ndev->uc` with `GFP_ATOMIC` and drop `netif_addr_lock_bh(ndev)` before calling them. Because `enetc4_psi_do_set_rx_mode()` acquires `rtnl_lock()`, `si->rx_mode_task` / `si->workqueue` must never be flushed under `rtnl_lock()`, and `unregister_netdev()` must precede `cancel_work(&si->rx_mode_task)` and `destroy_workqueue(si->workqueue)`. [F161, F164]
- Accesses to MAC Merge registers (`ENETC_PFPMR`, `ENETC_MMCSR`, `ENETC_PTCFPR`) and `ENETC_F_QBU` in `priv->active_offloads` (`enetc_get_mm()`, `enetc_set_mm()`, `enetc_mm_link_state_update()`) must be serialized by `priv->mm_lock`. [F22]

## Object Lifetimes
- In `enetc_close()` and `enetc_reconfigure()`, `enetc_stop()` and `enetc_free_rxtx_rings()` must precede `enetc_assign_rx_resources()` and `enetc_assign_tx_resources()`. `enetc_reconfigure()` requires `rtnl_lock()`, allocates new `tx_res`/`rx_res` before stopping, and must only call `enetc_assign_*_resources()` after `cb(priv, ctx)` succeeds while the interface is stopped so `out_restart` can restore old rings on failure. [F9, F31, F42]
- When `enetc_xdp_tx()` succeeds for `XDP_TX` in `enetc_clean_rx_ring_xdp()`, `xdp_tx_bd_cnt` must be added to `rx_ring->xdp.xdp_tx_in_flight` (decremented in `enetc_recycle_xdp_tx_buff()`) and `rx_ring->rx_swbd[orig_i .. i).page` set to `NULL` so `enetc_refill_rx_ring()` does not reuse in-flight pages. [F7]
- `enetc_pci_probe()` allocates `struct enetc_si` and aligned `struct enetc_pf` in one buffer with padding in `si->pad`, so `si` must be freed via `enetc_kfree_si(si)`. `enetc4_pf_netdev_create()` unwind and `enetc4_pf_netdev_destroy()` must release in reverse order: `unregister_netdev()`, `destroy_workqueue(si->workqueue)` (after `cancel_work(&si->rx_mode_task)`), `enetc4_link_deinit()`, `enetc_free_msix()`, `free_netdev()`. [F14, F96]
- Teardown paths must cancel work and NAPI before freeing state: `netif_napi_del(&v->napi)` and `cancel_work_sync(&v->rx_dim.work)` before `kfree(v)` in `enetc_int_vector_destroy()`; `cancel_work_sync(&pf->msg_task)` and `enetc_msg_disable_mr_int()` before `enetc_msg_free_mbx()` in `enetc_msg_psi_free()`. In `enetc_mdiobus_destroy()`, `enetc_mdio_remove()` only calls `mdiobus_unregister(pf->mdio)` (devm-allocated), whereas `enetc_imdio_remove()` must call `pf->ops->destroy_pcs(pf->pcs)`, `mdiobus_unregister(pf->imdio)`, and `mdiobus_free(pf->imdio)`. [F15, F28, F29, F154]

## API Contracts
- In `enetc_map_tx_buffs()`, `enetc_map_tx_tso_buffs()`, and `enetc_lso_hw_offload()`, `tx_swbd->skb` must only be assigned on the final BD after all DMA mappings succeed so error unwinding does not free `skb` before `enetc_start_xmit()` frees it at `drop_packet_err`. In `enetc_start_xmit()`, non-GSO SKBs with `nr_frags > priv->max_frags` must be linearized via `skb_linearize()`, and GSO SKBs must use `enetc_lso_hw_offload()` only when `ENETC_F_LSO` is active and payload `skb->len - lso->hdr_len <= ENETC_LSO_MAX_DATA_LEN` (256 KiB). [F3, F92, F177]
- In `enetc_setup_tc_cbs()`, `cbs->queue` is compared directly against `prio_top = tc_nums - 1` and `prio_next = tc_nums - 2` (not via `netdev_get_prio_tc_map()`), and `prio_top` must be enabled before `prio_next` (and disabled after `prio_next`). Port-wide Qbv (`ENETC_PTGCR_TGE` in `enetc_setup_taprio()`) and per-ring ETF (`tx_ring[i]->tsd_enable` in `enetc_setup_tc_txtime()`) are mutually exclusive and must return `-EBUSY` if the other is active. [F54, F111, F112]

## Error Handling
- Callers of `enetc_unwind_tx_frame()` (`enetc_map_tx_buffs()`, `enetc_map_tx_tso_buffs()`) must pass the exact `count` of populated BDs (including extension and TSO header BDs) and rewind `i` if `enetc_bdr_idx_inc()` ran before a failed `enetc_map_tx_tso_data()`. `enetc_xdp_frame_to_xdp_tx_swbd()` returns `-1` on DMA map error, and when `enetc_xdp_tx()` returns `false` in `enetc_xdp_xmit()`, the caller must unmap all `xdp_tx_bd_cnt` descriptors via `enetc_unmap_tx_buff()`. [F2, F34]
- `enetc_pf_probe()` and `enetc_vf_probe()` must unwind to `enetc_pci_remove()` (via `enetc_psi_destroy()` on PF) after `enetc_pci_probe()`, whereas `enetc4_pf_probe()` registers `enetc4_pci_remove()` via `devm_add_action_or_reset()` and must not call `enetc_pci_remove()` manually. `enetc_psi_create()`, `enetc_alloc_tx_resources()`, `enetc_alloc_rx_resources()`, and `enetc_hw_alloc()` return `ERR_PTR()` (never `NULL`) and must be checked with `IS_ERR()`. [F13, F32]
- `enetc_setup_rxbdr()` must initialize `ENETC_RBPIR` to `0` and `ENETC_RBCIR` to `1` before `enetc_refill_rx_ring()` in case the first page allocation (`j == 0`) fails. `enetc_send_cmd()` overwrites `*cbd` with hardware writeback, so `struct enetc_cbd` must be zero-initialized and `status_flags`/payload fields reset before reuse. [F49, F50]

## External Contracts
- TX/RX/Control BD ring DMA base addresses must be 128B-aligned, TX/RX `bd_count` a multiple of 64, and external CBD/NTMP data buffers allocated with `dma_alloc_coherent()` over-allocated and aligned to `ENETC_CBD_DATA_MEM_ALIGN` (64B) or `NTMP_DATA_ADDR_ALIGN` (32B) (passing the unaligned base pointer/DMA handle to `dma_free_coherent()`). VSI mailbox messages (`enetc_msg_vsi_write_msg()`) require 32B-aligned DMA addresses and 32B-multiple sizes `<= ENETC_DEFAULT_MSG_SIZE` (1024). [F95, F152, F166]

## Known Pitfalls
- In `enetc_get_tx_tstamp()` and `enetc_get_rx_tstamp()`, `hi` (`ENETC_SICTR1`) must be decremented by 1 when `lo <= tstamp_lo` and cast to `u64` before `<< 32`. In `enetc_update_ptp_sync_msg()`, when `enetc_cb->udp && !csum_offload`, call `inet_proto_csum_replace2/4()` using the old `originTimestamp` bytes before overwriting them. [F73, F113]
