# INTEL ETHERNET DRIVERS

This component of the Intel E800 series (ice) driver manages MSI-X/virtual interrupt resource tracking, Link Aggregation (LAG) hardware offload and failover, LAN Tx/Rx descriptor formats, and core Virtual Station Interface (VSI) lifecycle library routines. It coordinates netdevice bonding notifications, switch recipes, queue/vector allocation, and VSI setup/rebuild/teardown across PF, VF, SF, and channel VSIs.
This component contains the primary entry point and net_device_ops implementation of the Intel E800 series (ice) driver (ice_main.c), along with Non-Volatile Memory (NVM) access routines (ice_nvm.c) and the DDP hardware packet parser simulation/profile engine (ice_parser.c). It handles PCI probe/remove, power management, service task background maintenance, reset/rebuild orchestration, XDP/AF_XDP setup, NVM shadow RAM/flash reads and updates, and DDP parser table parsing.
This component implements the Intel Infrastructure Data Path Function (idpf) driver, supporting both split-queue (completion/buffer queues) and single-queue Tx/Rx datapaths, virtual port (vport) lifecycle management, PCI probe/remove, VF register initialization, and IEEE 1588 PTP clock/timestamping via direct BAR registers or Virtchnl2 mailbox messages.
This component comprises the entire Intel 82576/I350 Virtual Function driver (igbvf) and the hardware abstraction, diagnostics, register dump, ethtool, LED, and MAC/NVM/I225 layers of the Intel I225/I226 2.5GbE driver (igc). It provides VF mailbox communication, netdev/NAPI datapath, and ethtool support for igbvf, alongside MAC/PHY/NVM hardware operations, ethtool NFC/RSS/coalesce/diagnostics, and LED classdev integration for igc.
This component contains the main driver, PHY, NVM, PTP, and Time-Sensitive Networking (TSN) modules for the Intel I225/I226 2.5GbE controller (igc), alongside the devlink, main header, and 82598 hardware support files for the Intel 10GbE driver (ixgbe). It implements igc PCI probe/remove, Tx/Rx/XDP/AF_XDP datapaths, IEEE 802.1Qbv taprio/hrtimer scheduling, IEEE 802.3br Frame Preemption (FPE/MMSV), PTP hardware clocks/PTM, and ixgbe devlink flash/reload/region operations and 82598 MAC/PHY/EEPROM callbacks.
This component of the Intel 10GbE (ixgbe) driver implements PHY and SFP+/QSFP+ transceiver management (ixgbe_phy.c), IEEE 1588 PTP hardware clock and timestamping across 82599/X540/X550/E610 chips (ixgbe_ptp.c), SR-IOV Virtual Function provisioning and PF-VF mailbox request handling (ixgbe_sriov.c), hwmon thermal sensor sysfs attributes (ixgbe_sysfs.c), X540 MAC/EEPROM/PHY operations (ixgbe_x540.c), and hardware register/descriptor type definitions (ixgbe_type.h, ixgbe_type_e610.h).
Core header definitions, devlink management, base queue/VSI configuration, shared adapter tracking, and Accelerated RFS (aRFS) flow steering for the Intel E800 series (ice) Ethernet driver. It manages devlink device/port/region/health reporter interfaces (including PF, VF, and Subfunction dynamic ports), AdminQ command layouts, VSI Tx/Rx queue and interrupt vector setup, and multi-PF shared adapter state.
Hardware abstraction layer, MAC/PHY/EEPROM operations for 82599 and E610 controllers, Data Center Bridging (DCB) configuration and dcbnl netlink interface, and debugfs interface for the Intel 10GbE (ixgbe) driver. It provides common register/EEPROM/MAC/fc routines, 82598/82599 DCB credit and hardware setup, and E610 Admin Command Interface (ACI) firmware communication.
Implements ethtool operations, Fibre Channel over Ethernet (FCoE) Direct Data Placement (DDP) offload, PLDM firmware flash update for E610, IPsec (XFRM) hardware offload, and ring/interrupt vector library helpers for the Intel ixgbe driver. It manages ring-to-register caching across RSS/VMDq/DCB/SR-IOV modes, per-CPU FCoE DMA pools, RCU-indexed Rx/Tx Security Association tables, and ethtool diagnostics/configuration.
Main PCI driver lifecycle, net_device_ops implementation, NAPI Tx/Rx/XDP data path, interrupt handling, service task watchdog, PCIe AER error recovery, and PF/VF mailbox hardware operations for the Intel 10GbE (ixgbe) driver. It also defines the header-parsing match/jump tables (ixgbe_model.h) used to translate tc-flower/u32 classifiers into Flow Director hardware filters.

## Architecture & Data Flow

- Channel VSIs (`vsi->type == ICE_VSI_CHNL`) do not allocate `tx_rings`, `rx_rings`, `txq_map`, `rxq_map`, `q_vectors`, or `pf->vsi_stats[vsi->idx]`, and loopback VSIs (`vsi->type == ICE_VSI_LB`) do not allocate `q_vectors`, so VSI lifecycle and helper functions must guard array, vector, and stat accesses by VSI type or NULL checks. [F46]
- When `vsi->type == ICE_VSI_VF`, `vsi->vf` must be non-NULL (checked via `WARN_ON(vsi->type == ICE_VSI_VF && !vsi->vf)` in `ice_vsi_set_num_qs()`, `ice_vsi_cfg()`, and `ice_vsi_rebuild()`), whereas for `vsi->type == ICE_VSI_CTRL`, `vsi->vf` is non-NULL only for VF control VSIs and NULL for the PF control VSI. [F47]
- Whenever the active uplink port of a primary SR-IOV LAG PF changes or unlinks in `ice_lag_monitor_act_bkup`, `ice_lag_act_bkup_unlink`, or `ice_lag_aa_move_vf_qs`, `ice_lag_config_eswitch` must be called with the active `net_device` to update `repr->dst->u.port_info.lower_dev` across `lag->pf->eswitch.reprs` and call `netif_keep_dst`. [F58]
- `ICE_AQ_VSI_SEC_FLAG_ALLOW_DEST_OVRD` is enabled by default in `vsi->info.sec_flags` for `ICE_VSI_PF` in `ice_vsi_init` to allow control frames out of the main VSI, and mode-specific VSI security updates via `ice_vsi_update_security` must preserve this flag on the PF VSI. [F59]
- Any partial VSI context update via `ice_update_vsi` (such as in `ice_vsi_update_security`, `ice_vsi_update_local_lb`, and `ice_vsi_cfg_tc`) must seed `ctx.info` from `vsi->info`, set the modified section's `ICE_AQ_VSI_PROP_*_VALID` bit in `ctx.info.valid_sections`, and copy the updated fields back to `vsi->info` on success. [F60]
- `vsi->stat_offsets_loaded` must be reset to `false` when a VSI is configured in `ice_vsi_cfg_def` and whenever `ice_is_reset_in_progress(pf->state)` is true in `ice_update_eth_stats`, before `ice_update_eth_stats` samples `GLV_*` hardware counters and sets `vsi->stat_offsets_loaded = true`. [F65]
- `ice_vsi_set_num_desc` must only initialize `vsi->num_rx_desc` and `vsi->num_tx_desc` to `ICE_DFLT_NUM_RX_DESC` and `ICE_DFLT_NUM_TX_DESC` when those fields are zero, so user-configured ring sizes from `ethtool -G` are preserved across `ice_vsi_set_num_qs` and `ice_vsi_rebuild`. [F66]
- When `ice_vsi_cfg_rss_lut_key` restores `vsi->rss_size` from `vsi->orig_rss_size` after ADQ (`ICE_FLAG_TC_MQPRIO`) teardown, it must immediately clear `vsi->orig_rss_size = 0` so the saved pre-ADQ value does not override subsequent RSS size changes. [F67]
- In `ice_set_q_vector_intrl`, interrupt rate limiting (`GLINT_RATE`) is per-vector rather than per-queue, so if either `q_vector->tx` or `q_vector->rx` has dynamic ITR enabled (`ITR_IS_DYNAMIC`), hardware must be programmed with 4 us via `ice_write_intrl(q_vector, 4)` without overwriting the user-configured `q_vector->intrl` cache. [F68]
- When moving a VSI into a scheduler aggregator node in `ice_set_agg_vsi`, `agg_node->num_vsis` (capped at `ICE_MAX_VSIS_IN_AGG_NODE`) and the VSI's cached `vsi->agg_node` pointer must be updated together, and `ice_vsi_decfg` must decrement `vsi->agg_node->num_vsis` when deconfiguring an `ICE_VSI_VF` VSI with a valid `vsi->agg_node`. [F69]
- When moving a VF's Tx queue nodes between primary and secondary ports in `ice_lag_aa_move_vf_qs`, each moved `q_node` must be unlinked from `parent->children` and `old_hw->port_info->sib_head[0][layer]`, linked into `new_hw->port_info->sib_head[0][layer]` and `n_prt->children`, and recorded in `lag->q_home[vf_id][i] = dest`. [F71]
- When a secondary PF links into a switchdev LAG in `ice_lag_set_swid`, it must cache `local_lag->bond_swid = primary_swid` so that on unlink (`!link`), even if the primary PF has already left the bond, it can free the shared `local_lag->bond_swid` resource and restore `local_lag->pf->hw.port_info->sw_id`. [F74]
- In Active-Active SR-IOV LAG, placeholder VF VSIs (`lag->sec_vf[vf->vf_id]`) created on the secondary PF in `ice_lag_monitor_act_act` must have MAC and VLAN anti-spoofing cleared via `ice_lag_aa_clear_spoof`, and must be released via `ice_vsi_release` and nulled in `primary_lag->sec_vf[]` on unlink in `ice_lag_changeupper_event`. [F75]
- Adding a new `enum ice_vsi_type` variant requires updating the `switch (vsi->type)` dispatches in `ice_vsi_type_str`, `ice_vsi_set_num_qs`, `ice_vsi_alloc_def`, `ice_vsi_init`, `ice_set_agg_vsi`, and `ice_vsi_cfg_def` in lockstep. [F78]
- `ice_get_irq_res` bounds `pf->irq_tracker.entries` XArray allocations with inclusive `xa_limit` range `[0, pf->irq_tracker.num_entries - 1]` when `dyn_allowed` is true and `[0, pf->irq_tracker.num_static - 1]` when `dyn_allowed` is false, marking `entry->dynamic` iff `index > pf->irq_tracker.num_static - 1`. [F80]
- Per-queue hardware registers (`QRX_CTRL`, `QRXFLXP_CNTXT`, `QRX_CONTEXT`, `QINT_TQCTL`, `QINT_RQCTL`) and `ice_aqc_cfg_txqs_buf` queue handles must be indexed by the PF-space queue ID from `vsi->rxq_map[q]` or `vsi->txq_map[q]`, whereas `vsi->rx_rings[q]` and `vsi->tx_rings[q]` are indexed by VSI-relative `q`. [F84]
- In `struct ice_lag`, `sec_vf` is sized `ICE_MAX_SRIOV_VFS` and indexed by `vf->vf_id`, while `q_home` is sized `[ICE_MAX_SRIOV_VFS][ICE_MAX_RSS_QS_PER_VF]` and indexed by `[vf_id][i]` for each queue `i < pv_ctx->num_lan_q_entries[0]` in `ice_lag_aa_move_vf_qs`. [F85]
- Both `ice_vsi_setup_q_map` and `ice_vsi_setup_q_map_mqprio` must validate that the total configured Tx and Rx queues across all traffic classes do not exceed `vsi->alloc_txq` and `vsi->alloc_rxq` before assigning `vsi->num_txq` and `vsi->num_rxq`. [F87]
- `ice_set_agg_vsi` must skip any scheduler aggregator node whose `num_vsis` has reached `ICE_MAX_VSIS_IN_AGG_NODE` (64) and must not iterate past `ICE_MAX_PF_AGG_NODES` in `pf->pf_agg_node[]` or `ICE_MAX_VF_AGG_NODES` in `pf->vf_agg_node[]`. [F91]
- Because `pf->vsi` is a sparse array where `ice_vsi_free()` clears released slots to `NULL`, every `ice_for_each_vsi(pf, i)` loop must check `pf->vsi[i]` for non-`NULL` before dereferencing fields such as `pf->vsi[i]->type`. [F93]
- In `ice_lag_qbuf_recfg()`, `i` indexes the source queue context in `ice_get_lan_q_ctx(hw, vsi_num, tc, i)` while `count` separately indexes `qbuf->queue_info[count]` and increments only for valid queues, so callers must check the returned `valq` (`count`) rather than assuming `numq` entries were populated. [F98]
- In `ice_vsi_ctrl_all_rx_rings()`, all Rx rings must first be enabled or disabled with `wait = false` (`ice_vsi_ctrl_one_rx_ring(vsi, ena, i, false)`), followed by a single `ice_flush(&vsi->back->hw)`, before polling completion in a second `ice_for_each_rxq` loop via `ice_vsi_wait_one_rx_ring()`. [F103]
- Bitmask macros in ice_lan_tx_rx.h for 64-bit descriptor qwords (struct ice_fltr_desc, struct ice_tx_desc.cmd_type_offset_bsz, and struct ice_tx_ctx_desc.qw1) whose fields reach or exceed bit 31 must use ULL-suffixed literals or BIT_ULL() so shifts and FIELD_PREP() do not sign-extend or truncate on 32-bit types. [F106]
- In ice_vsi_setup_q_map(), vsi->tc_cfg.numtc must be clamped to at least 1 before dividing qcount_rx and qcount_tx by vsi->tc_cfg.numtc, and num_rxq_per_tc must be clamped to at least 1 before passing it to order_base_2() to compute the rounded-up power-of-2 queue count exponent. [F109]
- In ice_vsi_alloc_arrays(), vsi->txq_map must be allocated with vsi->alloc_txq + num_possible_cpus() elements rather than vsi->alloc_txq, because XDP Tx ring mappings are stored in vsi->txq_map starting at offset vsi->alloc_txq (up to one ring per CPU) before vsi->num_xdp_txq is initialized. [F113]
- Heap allocations of flexible-array AdminQ buffers in ice_lag.c (struct ice_sw_rule_lkup_rx_tx, struct ice_sw_rule_vsi_list, struct ice_aqc_cfg_txqs_buf, and struct ice_aqc_alloc_free_res_elem) must compute both the kzalloc() size and the AdminQ buffer length parameter via ICE_SW_RULE_*_SIZE() or struct_size() rather than sizeof(*ptr). [F120]
- In `ice_init_feature_support()`, E810 time/clock features (`ICE_F_CGU`, `ICE_F_SMA_CTRL`, `ICE_F_GNSS`) must only be enabled on E810 device IDs after verifying `ice_pf_src_tmr_owned(pf)` is true and checking the respective netlist/module presence helpers (`ice_is_cgu_in_netlist()`, `ice_is_clock_mux_in_netlist()`, `ice_gnss_is_module_present()`). [F128]
- In `ice_lag_init_feature_support_flag()`, `ICE_F_SRIOV_LAG` and `ICE_F_SRIOV_AA_LAG` must only be enabled when both the NVM device capability (`caps->sriov_lag` / `caps->sriov_aa_lag` in `pf->hw.dev_caps.common_cap`) and the DDP package lport extraction capability (`ice_pkg_has_lport_extract(&pf->hw)`) are present. [F129]
- When `ice_is_safe_mode(pf)` is true (`ICE_FLAG_ADV_FEATURES` unset after package download failure), callers in `ice_lib.c` must skip DDP-dependent RSS flow and switch filter operations (`ice_vsi_set_rss_flow_fld()`, `ice_vsi_set_vf_rss_flow_fld()`, `ice_vsi_clean_rss_flow_fld()`, `ice_rem_vsi_rss_list()`, and PAUSE/LLDP rules). [F130]
- In `ice_lag_changeupper_event()` (on link) and `ice_lag_chk_comp()`, before configuring shared SWIDs, prune lists, or control packet filters for a LAG bond, the driver must verify that the primary PF has switchdev running via `ice_is_switchdev_running(primary_lag->pf)` (or `lag->pf` when becoming primary) and abort LAG hardware setup if false. [F131]
- When Double VLAN Mode is enabled (ice_is_dvm_ena(&vsi->back->hw)), ice_vsi_add_vlan_zero and ice_vsi_del_vlan_zero must manage two VLAN 0 filters (ICE_VLAN(0, 0, 0) and ICE_VLAN(ETH_P_8021Q, 0, 0)) matching ICE_DVM_NUM_ZERO_VLAN_FLTRS (2) in ice_vsi_num_zero_vlans, whereas Single VLAN Mode manages only ICE_VLAN(0, 0, 0) (1). [F161]
- ice_init_features() and ice_deinit_features() must check ice_is_safe_mode(pf) at entry and return immediately when in Safe Mode before initializing or tearing down DDP-dependent features (PTP, GNSS, DPLL, Flow Director, DCB, LAG, hwmon, or switchdev xarray). [F204]
- In `ice_set_vlan_filtering_features()`, Rx VLAN filtering (`vlan_ops->ena_rx_filtering`) must only be enabled when `NETIF_F_HW_VLAN_CTAG_FILTER` or `NETIF_F_HW_VLAN_STAG_FILTER` is set in `features` and `!ice_is_eswitch_mode_switchdev(vsi->back)` holds, because Rx VLAN filtering must never be enabled in switchdev mode. [F216]
- `netif_is_ice()` must check `dev->netdev_ops` against both `&ice_netdev_ops` and `&ice_netdev_safe_mode_ops`, because `ice_set_ops()` assigns `&ice_netdev_safe_mode_ops` when `ice_is_safe_mode(pf)` is true. [F217]
- During reset preparation in `ice_prepare_for_reset()`, if `ice_is_eswitch_mode_switchdev(pf)` is true, `ice_eswitch_br_fdb_flush(pf->eswitch.br_offloads->bridge)` must be called under `rtnl_lock()` before `ice_clear_hw_tbls(hw)` clears hardware switch tables. [F218]
- In `ice_prepare_for_reset()`, when `ICE_FLAG_TC_MQPRIO` is set and `reset_type != ICE_RESET_PFR`, ADQ channels must be torn down via `ice_remove_q_channels(vsi, true)` and `vsi->old_ena_tc`, `vsi->all_enatc`, `vsi->old_numtc`, `vsi->all_numtc`, `vsi->req_txq`, `vsi->req_rxq`, `ICE_FLAG_TC_MQPRIO`, and `vsi->mqprio_qopt` must all be cleared. [F219]
- When `ice_remove_q_channels()` deletes a channel from `vsi->ch_list`, it must clear the `ch` back-pointers on every associated `vsi->tx_rings[ch->base_q + i]`, `vsi->rx_rings[ch->base_q + i]`, and their `q_vector`s before freeing `ch`, and must null out `vsi->tc_map_vsi[i]` and zero `vsi->all_enatc` and `vsi->all_numtc`. [F220]
- When `ice_rem_all_chnl_fltrs()` removes a channel filter from hardware (`ice_rem_adv_rule_by_id` returns 0) and `fltr->dest_vsi->type == ICE_VSI_CHNL`, it must decrement `fltr->dest_vsi->num_chnl_fltr` and, if `fltr->flags` has `ICE_TC_FLWR_FIELD_DST_MAC` or `ICE_TC_FLWR_FIELD_ENC_DST_MAC`, decrement `pf->num_dmac_chnl_fltrs`. [F221]
- In `ice_prepare_xdp_rings()`, `ice_vsi_assign_bpf_prog(vsi, prog)` must only be called when `!ice_is_xdp_ena_vsi(vsi)` holds, because `ice_vsi_assign_bpf_prog()` unconditionally calls `bpf_prog_put()` on the previous `vsi->xdp_prog` and a VSI rebuild (such as `ethtool -L`) passes the existing `vsi->xdp_prog` without an extra reference. [F223]
