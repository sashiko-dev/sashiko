# INTEL DRM DISPLAY FOR XE AND I915 DRIVERS

This component implements core display pipeline subsystems for Intel i915 and Xe drivers, covering atomic plane management (`intel_plane.c`, `intel_plane_initial.c`), Panel Self Refresh and Panel Replay (`intel_psr.c`), Panel Power Sequencing (`intel_pps.c`), Punit PM Demand (`intel_pmdemand.c`), PCH detection and refclk/sideband control (`intel_pch*.c`, `intel_sbi.c`), panel fitting (`intel_pfit.c`), pipe CRC capture (`intel_pipe_crc.c`), DSC QP tables (`intel_qp_tables.c`), and hardware quirks (`intel_quirks.c`).

## Architecture & Data Flow
- `struct intel_global_state base` must be the first member of `struct intel_pmdemand_state` (`intel_pmdemand_destroy_state()` calls `kfree(state)` directly), and `struct drm_framebuffer base` must be the first member of `struct intel_framebuffer` (`plane_config_fini()` passes `&plane_config->fb->base` to `kfree()`). [F127, F128]
- `intel_plane_state_reset()` must set `plane_state->scaler_id = -1`, and `intel_plane_set_invisible()` must clear `BIT(plane->id)` from `active_planes`, `scaled_planes`, `nv12_planes`, `c8_planes`, and `async_flip_planes` while zeroing `data_rate`, `data_rate_y`, `rel_data_rate`, `rel_data_rate_y`, and `min_cdclk` in `crtc_state`. [F51, F63]
- In `icl_check_nv12_planes()`, existing `planar_linked_plane` links must be broken via `unlink_nv12_plane()` before `link_nv12_planes()` binds a free Y plane and copies the UV plane's state and rates. `intel_joiner_add_affected_planes()` must loop `do { ... } while (affected_planes != prev_affected_planes)` across `joined_pipes` until `intel_joiner_affected_planes()` converges. [F64, F108]
- In `skl_crtc_planes_update_arm()`, plane arming updates must be ordered via `while ((plane = skl_next_plane_to_commit(...)))`, which skips planes whose new `plane_ddb` or `plane_ddb_y` overlaps an uncommitted plane's old DDB entry, clears `BIT(plane_id)` in `*update_mask`, and updates `ddb`/`ddb_y`. [F107]
- In `intel_psr_compute_config()`, `intel_sel_update_config_valid()` must only run after `crtc_state->has_psr` is true. Because `intel_psr2_sel_fetch_config_valid()` sets `crtc_state->enable_psr2_sel_fetch = true`, any later failure in `intel_sel_update_config_valid()` must `goto unsupported;` to reset it to `false`. [F72, F101]
- In `intel_psr2_sel_fetch_update()`, `crtc_state->psr2_su_area` must be initialized with `x1 = 0`, `x2 = drm_rect_width(&crtc_state->pipe_src)`, and `y1 = y2 = -1` (empty-area sentinel). `intel_psr2_sel_fetch_et_alignment()` must run after `drm_atomic_add_affected_planes()` and before `intel_psr2_sel_fetch_pipe_alignment()` so unmodified visible cursor planes are included. Intersecting planes with `planar_linked_plane` must add the linked Y plane to the atomic state, copy `psr2_sel_fetch_area` (`y1`, `y2`), and set `BIT(linked->id)` in `crtc_state->update_planes`. [F53, F75, F100]
- When `crtc_state->enable_psr2_sel_fetch` is set, `intel_psr2_sel_fetch_update()` must compute both `psr2_man_track_ctl` and `pipe_srcsz_early_tpt`, and both `intel_psr2_program_trans_man_trk_ctl()` and `intel_psr2_panic_force_full_update()` must write `PIPE_SRCSZ_ERLY_TPT` alongside `PSR2_MAN_TRK_CTL` when `enable_psr2_su_region_et` is set. [F74]
- In `intel_psr_enable_sink()`, `_panel_replay_enable_sink()` and `_psr_enable_sink()` must derive sink DPCD configuration from pre-computed `intel_crtc_state` flags (`has_panel_replay`, `has_sel_update`, `enable_psr2_su_region_et`, `req_psr2_sdp_prior_scanline`) rather than re-evaluating capabilities or reading `intel_dp->psr`. `psr_global_enabled()` must check per-connector `connector->panel.vbt.psr.enable` when `psr.debug == I915_PSR_DEBUG_DEFAULT`, and `intel_psr_init()` must never overwrite device-wide `display->params.enable_psr`. [F71, F78]
- When `intel_num_pps(display) > 1`, `pps_initial_setup()` must reset `intel_dp->pps.pps_idx` to `-1` if `>= intel_num_pps(display)` before `bxt_initial_pps_idx()`. `pps_init_delays()` must round `final->power_cycle` up to `msecs_to_pps_units(100)` and `pps_units_to_msecs()` must use `DIV_ROUND_UP(val, 10)`. `pps_init_registers()` and `intel_pps_readout_hw_state()` must encode `seq->power_cycle` as `DIV_ROUND_UP(seq->power_cycle, 1000) + 1` and decode non-zero register values as `(power_cycle_delay - 1) * 1000`. [F81, F87, F117]
- In `intel_pmdemand_update_active_non_tc_phys()`, `intel_pmdemand_update_connector_phys()` must be called with `(old_conn_state, false)` (using `old_crtc_state`) before `(new_conn_state, true)` (using `new_crtc_state`). `intel_pmdemand_atomic_check()` and `intel_pmdemand_update_max_ddiclk()` must convert kHz to MHz via `DIV_ROUND_UP(..., 1000)` and clamp `active_dbufs` and pre-Xe3 `active_pipes` to `3` and `active_phys`/`plls` to `7`. [F104, F121]
- Enumerators in `enum intel_pch` must be ordered by south display compatibility (real PCHs `PCH_IBX`..`PCH_ADP`, fake on-die PCHs from `PCH_DG1 = 1024`), inserting any new PCH inheriting an earlier south display immediately after its parent. In `INTEL_PCH_TYPE(display) >= ...` chains like `intel_num_pps()`, higher-numbered PCH enums must precede lower-numbered ones. [F89, F97]

## Synchronization
- `intel_pps_lock()` must get the `POWER_DOMAIN_DISPLAY_CORE` wakeref before locking `display->pps.mutex`, and `intel_pps_unlock()` must unlock `display->pps.mutex` before putting that wakeref; reset hooks (`vlv_pps_reset_all()`, `bxt_pps_reset_all()`) must never lock `display->pps.mutex`. `cancel_delayed_work_sync(&intel_dp->pps.panel_vdd_work)` must not be called under `display->pps.mutex` (use `cancel_delayed_work()`), and `edp_panel_vdd_schedule_off()` must not queue `panel_vdd_work` while `pps.initializing` is true. [F10, F27, F154]
- `intel_psr_disable()` and `intel_psr_pause()` must update `psr.enabled` or `psr.pause_counter` under `intel_dp->psr.lock` and release `psr.lock` before calling `cancel_work_sync(&psr->work)` and `cancel_delayed_work_sync(&psr->dc3co_work)`. `intel_psr_debug_set()` must also release `psr.lock` before calling `intel_psr_fastset_force()`. [F28, F32]
- Because `__psr_wait_for_idle_locked()` drops `intel_dp->psr.lock`, `intel_psr_work()` must re-verify `enabled`, `!pause_counter`, `!busy_frontbuffer_bits`, and `!active` after re-acquiring `psr.lock` before calling `intel_psr_activate()`. In `intel_psr_flush()`, `busy_frontbuffer_bits &= ~pipe_frontbuffer_bits` must be cleared under `psr.lock` before checking `pause_counter` or queuing `psr.work`. [F17, F30]
- `intel_psr_wait_for_idle_locked()` requires `intel_dp->psr.lock` (`intel_psr_lock()`/`intel_psr_unlock()`). Because both sleep, vblank evasion callers must invoke them before `local_irq_disable()` and call `intel_psr_unlock()` after `local_irq_enable()`. In `intel_psr2_program_trans_man_trk_ctl()`, `psr.lock` must be held when `dsb` is `NULL`, and is not required when `dsb` is non-null. [F33, F48, F158]
- In hardirq context, `intel_psr_irq_handler()` must not acquire `psr.lock` or perform DP AUX; on `psr_irq_psr_error_bit_get`, it must mask the error bit in `psr_imr_reg`, set `psr.irq_aux_error = true`, and queue `psr.work`. In panic context, `intel_panic_flush()` and `intel_psr2_panic_force_full_update()` must not acquire mutexes or forcewake locks, using `intel_de_write_fw()` and `drm_clflush_virt_range()` without calling `disable_tiling()` on the fbdev framebuffer. [F157, F159, F170]
- All accesses to `XELPDP_INITIATE_PMDEMAND_REQUEST` in `intel_pmdemand.c` must hold `display->pmdemand.lock` and verify via `intel_pmdemand_check_prev_transaction()` that no prior request is active. In `intel_pmdemand_update_params()`, `intel_pmdemand_pre_plane_update()` must program `max3(old_val, new_val, current_val)` (reading `current_val` from hardware when `!serialized`), while `intel_pmdemand_post_plane_update()` passes `old = NULL` to program `max(new_val, current_val)`. [F142, F144]

## Object Lifetimes
- In `intel_plane_duplicate_state()`, after `kmemdup()`, `ggtt_vma` and `dpt_vma` must be reset to `NULL` and `drm_framebuffer_get()` called on non-NULL `hw.fb`, because `intel_plane_destroy_state()` warns on non-NULL VMAs and puts `hw.fb`. `intel_plane_copy_uapi_to_hw_state()` and `intel_plane_copy_hw_state()` must call `intel_plane_clear_hw_state(plane_state)` before overwriting `plane_state->hw` and taking a new `hw.fb` reference. [F1, F2]
- In `intel_prepare_plane_fb()`, any failure after `intel_plane_pin_fb()` must jump to `unpin_fb` to call `intel_plane_unpin_fb(new_plane_state)`, and `intel_cleanup_plane_fb()` must call both `intel_display_rps_mark_interactive(display, state, false)` and `intel_plane_unpin_fb(old_plane_state)` when `obj` is non-NULL. [F4]
- In `plane_config_fini()`, `plane_config->fb` must be freed via `drm_framebuffer_put(fb)` when `drm_framebuffer_read_refcount(fb)` is non-zero and `kfree(fb)` when zero. When `intel_find_initial_plane_obj()` attaches `fb` and `vma` to `plane_state`, it must call `__i915_vma_pin(vma)`, `i915_vma_get(vma)`, `drm_framebuffer_get(fb)`, and `intel_plane_copy_uapi_to_hw_state()`. [F7, F8]
- Enabling `EDP_FORCE_VDD` in `intel_pps_vdd_on_unlocked()` or adopting BIOS VDD in `pps_vdd_init()` must hold an `intel_aux_power_domain(dig_port)` wakeref in `intel_dp->pps.vdd_wakeref` until VDD or panel power is turned off in `intel_pps_off_unlocked()` or `intel_pps_vdd_off_sync_unlocked()` (when `PANEL_POWER_ON` is clear), which must set `panel_power_off_time = ktime_get_boottime()`, call `intel_dp_invalidate_source_oui(intel_dp)`, and release `fetch_and_zero(&intel_dp->pps.vdd_wakeref)`. [F69, F131]
- On VLV/CHV, `vlv_detach_power_sequencer()` requires `vlv_active_pipe == INVALID_PIPE` and must call `intel_pps_vdd_off_sync_unlocked(intel_dp)`, zero `PP_ON_DELAYS(display, pipe)`, and set `vlv_pps_pipe = INVALID_PIPE`. In `vlv_power_sequencer_kick()`, temporary DPLL/PHY overrides (`!pll_enabled`, `release_cl_override`) must be undone via `vlv_force_pll_off()` and `chv_phy_powergate_ch(..., false)`. [F11, F14]
- When disabling PSR1 in `intel_psr_exit()`, `intel_dmc_start_pkgc_exit_at_start_of_undelayed_vblank(..., false)` must only be called when `intel_dp->psr.pkg_c_latency_used` is true. [F15]

## API Contracts
- An uninitialized `struct intel_plane` from `intel_plane_alloc()` must be freed via `intel_plane_free(plane)`, whereas a registered plane uses `intel_plane_destroy()`. `plane->update_noarm` and `plane->async_flip` are optional and must be null-checked in `intel_plane_update_noarm()` and `intel_plane_update_arm()`. [F20, F46]
- `intel_plane_data_rate()` and `intel_plane_relative_data_rate()` must return `0` if `!plane_state->uapi.visible` before dereferencing `hw.fb->format`. `intel_adjusted_rate()` requires 16.16 fixed-point `src` and integer `dst` dimensions. In `.check_plane()`, `intel_plane_check_clipping()` must precede `intel_plane_check_src_coordinates()`, which truncates 16.16 `uapi.src` via `>> 16` and `<< 16` without rounding up. [F45, F55, F111, F169]
- Callers of `intel_pps_vdd_on_unlocked()` must only call `intel_pps_vdd_off_unlocked()` when `intel_pps_vdd_on_unlocked()` returned `true`, whereas `intel_pps_vdd_on()` cannot be nested. `intel_pps_have_panel_power_or_vdd()` and `intel_pps_check_power_unlocked()` require `edp_have_panel_power(intel_dp) || edp_have_panel_vdd(intel_dp)`. [F13, F99]
- Callers of `enc_to_intel_dp(encoder)` must first verify `encoder` is DP or DP MST. `intel_psr_needs_aux_io_power()` requires both `intel_crtc_has_type(crtc_state, INTEL_OUTPUT_EDP)` and `intel_encoder_can_psr(encoder)`. In `intel_psr_disable_locked()`, DPCD `DP_PSR_EN_CFG` and `DP_RECEIVER_ALPM_CONFIG` must only be cleared when `!panel_replay_enabled`, whereas `intel_alpm_disable(intel_dp)` runs when `panel_replay_enabled && intel_dp_is_edp(intel_dp)`. [F44, F137, F138]
- On `DISPLAY_VER(display) >= 12`, `TRANS_PSR_IMR`/`IIR` use unshifted `TGL_PSR_*` bits (`psr_irq_*_bit_get()`), whereas pre-12 `EDP_PSR_IMR`/`IIR` shift by `_EDP_PSR_TRANS_SHIFT(trans)`. `PORT_ALPM_CTL(port)` and `PORT_ALPM_LFPS_CTL(port)` take `enum port` (`_MMIO_PORT()`), whereas `PR_ALPM_CTL`, `ALPM_CTL`, and `ALPM_CTL2` take `enum transcoder`. [F56, F57]
- `intel_pmdemand_update_params()` accepts a nullable `old` pointer (`old ? old->params.<field> : 0`), and `intel_pmdemand_program_dbuf()` takes `dbuf_slices` as a bitmask (`hweight8(dbuf_slices)`), not a slice count. [F47, F60]

## Error Handling
- In `initial_plane_vma()`, if `orig_mm` is allocated via `i915_gem_gtt_reserve()`, `drm_mm_remove_node(&orig_mm)` must be called before retrying `i915_vma_pin()`, before returning `vma`, and on `err_obj` failure. `initial_plane_vma()` must convert `IS_ERR()` from `i915_gem_object_create_region_at()` and `i915_vma_instance()` into `NULL`. [F6, F41]
- `intel_plane_alloc()` and `intel_atomic_get_pmdemand_state()` return `ERR_PTR()` on failure, whereas `intel_plane_duplicate_state()`, `intel_pmdemand_duplicate_state()`, and `intel_atomic_get_old/new_pmdemand_state()` return `NULL`. [F40, F42]
- `intel_psr_entry_setup_frames()` returns `-ETIME` on failure, so its return type and caller variables (`entry_setup_frames`) must be signed `int`. In `intel_psr.c`, `drm_dp_dpcd_readb()` returns `1` on success, so callers must check `ret == 1` or `ret != 1`. In `intel_psr_fastset_force()`, `err` must be reset to `0` before `retry:` and `drm_atomic_commit(state)` called only when `err == 0`. [F38, F39, F49]

## Known Pitfalls
- In `plane_atomic_check()`, when `intel_crtc_is_joiner_secondary(new_crtc_state)` is true, `intel_plane_copy_uapi_plane_damage()` and `intel_plane_copy_uapi_to_hw_state()` must read from `old/new_primary_crtc_plane_state` while writing into the secondary pipe's `new_plane_state` and `crtc`. Every `panic_tiling` callback (`intel_ytile_get_offset()`, `intel_4tile_get_offset()`) takes `(width, x, y)` despite the header naming `(x, y, width)`. [F103, F123]
- `psr2_man_trk_ctl_calc()` and `psr2_pipe_srcsz_early_tpt_calc()` must bail out when `full_update` is true or `psr2_su_area.y1 == -1` before `REG_FIELD_PREP()`. `psr2_man_trk_ctl_calc()` encodes SU bounds as `y1` and `y2 - 1` on ADL-P and `DISPLAY_VER >= 14`, and as `y1 / 4 + 1` and `y2 / 4 + 1` on earlier platforms. `hsw_activate_psr2()` encodes wake lines as `8 - lines` (ver 9–11), `lines - 5` (ver >= 12), or `map[lines - 5]` (ADL-P `< STEP_E0`). [F86, F88, F115]
- On `DISPLAY_VER(display) >= 20`, `_psr_invalidate_handle()` and `_psr_flush_handle()` must call `intel_psr_exit()` (and queue `psr.work` on flush when `!busy_frontbuffer_bits`) rather than `intel_psr_configure_full_frame_update()`/`intel_psr_force_update()`. `intel_psr_wait_for_idle_locked()` and `intel_psr_wait_for_idle_dsb()` must skip polling `EDP_PSR_STATUS`/`EDP_PSR2_STATUS` when Panel Replay is active. [F135, F136]
- `pps_init_delays_bios()` must cache hardware timings in `bios_pps_delays` before `pps_init_delays()` overwrites `backlight_on/off = 1`. `intel_pps_off_unlocked()` must clear `PANEL_POWER_ON`, `PANEL_POWER_RESET`, `EDP_FORCE_VDD`, and `EDP_BLC_ENABLE` in `PP_CONTROL` in one write, followed by `intel_de_posting_read()` and `wait_panel_off()`. [F70, F132]
- `struct intel_pmdemand_state` and `struct pmdemand_params` must be zero-allocated because `intel_pmdemand_state_changed()` uses `memcmp()`. `intel_pmdemand_program_params()` must only trigger `XELPDP_PMDEMAND_REQ_ENABLE` when request registers changed, and on `DISPLAY_VER(display) == 20` `intel_pmdemand_wait()` must use `intel_pmdemand_poll()` instead of `wait_event_timeout()`. [F95, F143]
