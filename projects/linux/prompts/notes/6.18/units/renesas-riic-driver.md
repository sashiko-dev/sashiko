# RENESAS RIIC DRIVER

The Renesas RIIC driver (`drivers/i2c/busses/i2c-riic.c`) implements an interrupt-driven I2C bus controller adapter for Renesas RZ/A, RZ/V2H, and RZ/T2H SoCs, supporting transmit, receive, transmit-end, NACK, and stop interrupts, runtime PM, system sleep suspend/resume, reset control, and SCL/SDA bus recovery.

## Architecture & Data Flow

- When receiving the final byte (`riic->bytes_left == 1`) in `riic_rdrf_isr()`, enabling `ICIER_SPIE` in `RIIC_ICIER` and writing `ICCR2_SP` to `RIIC_ICCR2` (when `riic->is_last` is true) must precede setting `ICMR3_ACKBT` in `RIIC_ICMR3`, and both must precede reading `RIIC_ICDRR`. [F60]
- `riic_dev.bytes_left` must be a signed `int` guarded by `!riic->bytes_left` (never `riic->bytes_left <= 0`) on entry to `riic_tdre_isr()` and `riic_rdrf_isr()`, because `riic_xfer()` initializes it to `RIIC_INIT_MSG` (`-1`) for the address and dummy-read phase. [F36]
- In `riic_tdre_isr()`, `riic->bytes_left == 0` must be checked after the `RIIC_INIT_MSG` branch sets `riic->bytes_left = riic->msg->len` and before writing `RIIC_ICDRT`, so zero-length (`SMBUS_QUICK`) write messages switch from `ICIER_TIE` to `ICIER_TEIE` without dereferencing `riic->buf` or underflowing `riic->bytes_left`. [F37]
- In `riic_tend_isr()`, `riic_readb(riic, RIIC_ICSR2) & ICSR2_NACKF` must be evaluated before the `riic->bytes_left` check that returns `IRQ_NONE`, because NACK interrupts can occur while `riic->bytes_left` is still non-zero (`RIIC_INIT_MSG` or remaining payload bytes). When `ICSR2_NACKF` is set, the handler must dummy-read `RIIC_ICDRR`, clear `ICSR2_NACKF` in `RIIC_ICSR2`, set `riic->err = -ENXIO`, and issue a STOP (`ICIER_SPIE` in `RIIC_ICIER`, `ICCR2_SP` in `RIIC_ICCR2`). [F31, F43]
- Changes to NACK or STOP interrupt handling in `riic_tend_isr()` and `riic_stop_isr()` or to `RIIC_ICSR2` status bits (`ICSR2_NACKF`, `ICSR2_STOP`) must keep `riic_eei_isr()` in sync, because `riic_irqs` routes NACK and STOP to separate IRQs while `riic_rzt2h_irqs` multiplexes both through `riic_eei_isr()`. [F33]
- `RIIC_ICMR3` must retain `ICMR3_ACKWP | ICMR3_RDRFS` set by `riic_init_hw()` across all updates; `riic_rdrf_isr()` relies on read-modify-write via `riic_clear_set_bit()` to toggle `ICMR3_ACKBT` while keeping `ICMR3_ACKWP` (write enable for `ACKBT`) and `ICMR3_RDRFS` active. Broken by: overwriting `RIIC_ICMR3` with `riic_writeb()` or clearing `ICMR3_ACKWP` or `ICMR3_RDRFS`. [F27]
- In `riic_bus_barrier()`, after `readb_poll_timeout` confirms `ICCR2_BBSY` is cleared in `RIIC_ICCR2`, the driver must verify that both `ICCR1_SDAI` and `ICCR1_SCLI` are set (`(riic_readb(riic, RIIC_ICCR1) & (ICCR1_SDAI | ICCR1_SCLI)) == (ICCR1_SDAI | ICCR1_SCLI)`) and call `i2c_recover_bus()` if either bit is 0. Broken by: testing `!(riic_readb(riic, RIIC_ICCR1) & (ICCR1_SDAI | ICCR1_SCLI))`, which only recovers when both lines are low. [F45]
- In `riic_init_hw()`, `riic->i2c_t.bus_freq_hz` must be validated against `I2C_MAX_FAST_MODE_PLUS_FREQ` when `riic->info->fast_mode_plus` is true and `I2C_MAX_FAST_MODE_FREQ` otherwise. Both the initial `total_ticks` calculation (`DIV_ROUND_UP(rate, t->bus_freq_hz ?: 1)`, guarding against zero `bus_freq_hz`) and each prescaler halving step (`DIV_ROUND_UP(total_ticks, 2)`) must use ceiling division so the bus is never driven faster than `t->bus_freq_hz`. [F38, F49]
- In `riic_init_hw()`, the prescaler search loop must iterate inclusively over `0 <= cks <= 7` until `brl <= (0x1F + 3)` and return `-EINVAL` if `brl > (0x1F + 3)` after the loop, matching the 3-bit `ICMR1_CKS` field (`0..7`) and the 5-bit `RIIC_ICBRL` maximum (`0x1F`) plus 3 sync/noise ticks. [F39]
- All MMIO register accesses must translate `enum riic_reg_list` indices through `riic->info->regs` (via `riic_readb()`, `riic_writeb()`, `riic_clear_set_bit()`, or `riic->info->regs[...]` in `riic_bus_barrier()`), and every entry up to `RIIC_REG_END` must be populated in both `riic_rz_a_regs` and `riic_rz_v2h_regs`. [F64]
- Every `of_device_id` entry in `riic_i2c_dt_ids` must set `.data` to a non-NULL `struct riic_of_data` whose `.regs` array has `RIIC_REG_END` entries and whose `.num_irqs` matches `ARRAY_SIZE()` of its `.irqs` array, because `riic_i2c_probe()` indexes both via `riic->info` without NULL or bounds checks. [F53]

## Synchronization

- In `riic_xfer()`, per-message state (`riic->bytes_left`, `riic->buf`, `riic->msg`, `riic->is_last`) and `riic->msg_done` must be initialized before enabling interrupts in `RIIC_ICIER` and issuing `ICCR2_ST` or `ICCR2_RS` in `RIIC_ICCR2`, and must not be modified by process context until `wait_for_completion_timeout()` returns. [F8]
- Whenever `riic_tend_isr()` or `riic_rdrf_isr()` requests a STOP condition (`ICCR2_SP` in `RIIC_ICCR2`), it must enable `ICIER_SPIE` in `RIIC_ICIER` and defer `complete(&riic->msg_done)` to `riic_stop_isr()`, which must clear and read back `RIIC_ICSR2` and `RIIC_ICIER` before completing. [F62]
- In `riic_tend_isr()`, `ICIER_TEIE` must be cleared in `RIIC_ICIER` on both the STOP path and the non-final message path, and when `!riic->is_last && !riic->err`, `complete(&riic->msg_done)` must be called immediately without issuing `ICCR2_SP`. [F10]
- All interrupt handlers in `riic_irqs` and `riic_rzt2h_irqs` (`riic_tdre_isr`, `riic_tend_isr`, `riic_rdrf_isr`, `riic_stop_isr`, `riic_eei_isr`) are registered with flags `0` and execute in hardirq context where sleeping calls (such as `readb_poll_timeout`, `riic_bus_barrier`, or `pm_runtime_resume_and_get`) are forbidden. [F71]

## Object Lifetimes

- Every process-context access to RIIC MMIO registers (`riic_readb`, `riic_writeb`, `riic_clear_set_bit`, and `riic_bus_barrier`) in `riic_xfer`, `riic_init_hw`, `riic_i2c_remove`, and `riic_i2c_suspend` must execute while holding an active runtime PM reference acquired via `pm_runtime_resume_and_get(dev)`. [F4]
- In `riic_i2c_probe()`, `riic->clk`, `riic->info`, `adap->dev.parent`, `riic->i2c_t` (via `i2c_parse_fw_timings()`), `pm_runtime_use_autosuspend(dev)`, and `pm_runtime_enable(dev)` must all be initialized before calling `riic_init_hw(riic)` and `i2c_add_adapter(adap)`. Any subsequent failure in `riic_i2c_probe()` as well as teardown in `riic_i2c_remove()` must call `pm_runtime_disable(dev)` and `pm_runtime_dont_use_autosuspend(dev)`. [F1, F2]
- In `riic_i2c_remove()`, `i2c_del_adapter(&riic->adapter)` must be called before `pm_runtime_disable(dev)` so that any in-flight or client-teardown transfers on the adapter can complete while runtime PM remains enabled. [F16]
- `riic_i2c_probe()` acquires `riic->rstc` via `devm_reset_control_get_optional_exclusive_deasserted(dev, NULL)`, which transfers reset deassertion and release ownership to devres, so probe error paths and `riic_i2c_remove()` must not manually call `reset_control_assert()` or `reset_control_put()` on `riic->rstc`. [F7]
- In `riic_i2c_suspend()`, `pm_runtime_resume_and_get()` and `i2c_mark_adapter_suspended(&riic->adapter)` must precede clearing `ICCR1_ICE` in `RIIC_ICCR1`, `pm_runtime_put_sync()`, and `reset_control_assert(riic->rstc)`. In `riic_i2c_resume()`, `reset_control_deassert(riic->rstc)` must succeed before `riic_init_hw(riic)` and before `i2c_mark_adapter_resumed(&riic->adapter)`, re-asserting `riic->rstc` via `reset_control_assert(riic->rstc)` if `riic_init_hw(riic)` fails. [F5, F15, F69]

## API Contracts

- `riic_clear_set_bit(riic, clear, set, reg)` takes the shifted bitmask to clear as its second argument and the shifted bitmask to set as its third argument (`(riic_readb(riic, reg) & ~clear) | set`). Broken by: swapping `clear` and `set` or passing bit numbers instead of `BIT(...)` masks. [F20]
- In `riic_init_hw()`, `brl` and `brh` must be computed as signed `int` values, clamped to at least `1` after subtracting sync/noise and rise/fall clock ticks, and ORed with `ICBR_RESERVED` (`GENMASK(7, 5)`) when written to `RIIC_ICBRH` and `RIIC_ICBRL`; writes to `RIIC_ICMR1` must use `ICMR1_CKS(cks)` which sets the write-protect bit `ICMR1_BCWP` (`BIT(3)`). [F23, F40]
- `riic_i2c_probe()` must store the `struct riic_dev *` pointer in all three `void *` context slots (`devm_request_irq()` `dev_id`, `i2c_set_adapdata(&riic->adapter, riic)`, and `platform_set_drvdata(pdev, riic)`), because ISRs, I2C adapter/recovery callbacks, and PM/remove callbacks each cast their `void *` data directly to `struct riic_dev *`. [F54]

## Error Handling

- In `riic_xfer`, `riic_init_hw`, `riic_i2c_remove`, and `riic_i2c_suspend`, `pm_runtime_resume_and_get(dev)` does not hold a runtime PM reference when it returns a non-zero error, so `pm_runtime_put_autosuspend(dev)`, `pm_runtime_put(dev)`, and `pm_runtime_put_sync(dev)` must only be called when `pm_runtime_resume_and_get(dev)` returns 0. [F3]
- In `riic_xfer()`, `riic->err` must be initialized to `0` (via `riic->err = riic_bus_barrier(riic)`) before entering the message loop, and `wait_for_completion_timeout()` returning `0` must set `riic->err = -ETIMEDOUT` so `riic->err ?: num` returns a negative errno on failure or `num` on success. [F17]
- In `riic_i2c_probe()`, each IRQ must be fetched via `platform_get_irq(pdev, irq_desc->res_num)` into a signed `int` and checked with `if (irq < 0)` before passing it to `devm_request_irq()`. Broken by: passing the loop counter `i` instead of `irq_desc->res_num`, or storing the return value in an unsigned variable. [F21]

## Known Pitfalls

- In `riic_tdre_isr()`, updates to `RIIC_ICIER` (switching from `ICIER_TIE` to `ICIER_RIE` on read or to `ICIER_TEIE` when `riic->bytes_left == 0`) must occur before writing `RIIC_ICDRT`, because writing `RIIC_ICDRT` acknowledges TIE and can immediately re-trigger TIE if the byte moves to the shift register. [F25]
- Modifying `ICCR1_SCLO` or `ICCR1_SDAO` in `RIIC_ICCR1` (as in `riic_set_scl()` and `riic_set_sda()`) requires clearing `ICCR1_SOWP` in the same write and re-setting `ICCR1_SOWP` immediately afterward, whereas non-pin-output writes to `RIIC_ICCR1` must keep `ICCR1_SOWP` set. [F28]
- In `riic_init_hw()`, `RIIC_ICCR1` must first be written with `ICCR1_IICRST | ICCR1_SOWP`, then `ICCR1_ICE` set while `ICCR1_IICRST` remains asserted, and `ICCR1_IICRST` cleared only after programming `RIIC_ICMR1`, `RIIC_ICBRH`, `RIIC_ICBRL`, `RIIC_ICSER`, `RIIC_ICMR3`, and `RIIC_ICFER`. [F29]
- `riic_init_hw()` and `riic_xfer()` must pass `riic->adapter.dev.parent` (`adap->dev.parent`, the platform device) rather than `&riic->adapter.dev` to `pm_runtime_*` and `dev_err_probe()`, because runtime PM is enabled on the platform device and `riic_init_hw()` runs in `riic_i2c_probe()` before `i2c_add_adapter()` initializes `adap->dev`. [F80]
