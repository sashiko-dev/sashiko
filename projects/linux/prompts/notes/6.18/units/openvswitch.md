# OPENVSWITCH

`net/openvswitch` implements Open vSwitch virtual ports (`vport.c`), concrete vport backends for netdevs, internal bridge devices, and lightweight tunnels (VXLAN, Geneve, GRE), Generic Netlink configuration and token-bucket execution for OpenFlow traffic meters (`meter.c`), and kernel tracepoints.

## Architecture & Data Flow

- `dp_meter_instance.dp_meters` is a direct-mapped `__counted_by(n_meters)` array indexed by `meter_hash(ti, id)` (`id % ti->n_meters`) with no collision chains: `dp_meter_instance_alloc()` must set `ti->n_meters` to the exact count passed to `struct_size(ti, dp_meters, size)` before indexing, `lookup_meter()` must verify `meter->id == meter_id`, and `attach_meter()` must reject occupied slots with `-EBUSY`. [F58, F85]
- `attach_meter()` and `detach_meter()` must roll back both `ti->dp_meters` and `tbl->count` on failure (`attach_err` removes `meter` and decrements `tbl->count`; `shrink_err` re-inserts `meter` and increments `tbl->count`). In `detach_meter()`, shrinking `tbl->ti` to `half_size` is permitted only if every slot in `[half_size, ti->n_meters)` is `NULL`; if any upper-half slot is occupied, it must jump to `out` and return 0 without calling `dp_meter_instance_realloc()` or rolling back. [F9, F70]
- In `dp_meter_create()` and `ovs_meter_execute()`, `dp_meter_band.bucket` and `max_bucket_size` are maintained in bits (`meter->kbps == 1`, `cost = skb->len * 8`) or 1/1000th of a packet (`meter->kbps == 0`, `cost = 1000`), so full bucket capacity is strictly `band->burst_size * 1000ULL` (`1000LL`) without adding `band->rate`. `dp_meter_create()` must also set `meter->max_delta_t` to the maximum of `div_u64(band->bucket, band->rate)` across all bands so `ovs_meter_execute()` clamps `delta_ms` before multiplying by `band->rate`. [F40, F45, F78, F110]
- `ovs_meter_execute()` must iterate through all `meter->n_bands` bands to refill every `band->bucket` and deduct cost from bands with sufficient tokens while tracking the highest-rate exceeded band in `band_exceeded_max`, applying band stats and drop actions only after the loop completes. [F69]
- In `dp_meter_create()`, `struct dp_meter` must be allocated with `GFP_KERNEL_ACCOUNT` (and bounded by `tbl->max_meters_allowed` in `attach_meter()`) using `struct_size(meter, bands, n_bands)` only after counting nested band attributes in `a[OVS_METER_ATTR_BANDS]` and verifying the count does not exceed `DP_MAX_BANDS`, and the `__counted_by` field `meter->n_bands` must be initialized before writing `meter->bands[]`. [F56, F124]
- Before downcasting a `struct net_device *` to OVS vport state, `ovs_internal_dev_get_vport()` must verify `ovs_is_internal_dev(netdev)` (`netdev->netdev_ops == &internal_dev_netdev_ops`) and `ovs_netdev_get_vport()` must verify `netif_is_ovs_port(dev)` (`dev->priv_flags & IFF_OVS_DATAPATH`). `netdev_destroy()` and `ovs_netdev_tunnel_destroy()` must also check `netif_is_ovs_port(vport->dev)` under `rtnl_lock()` before calling `ovs_netdev_detach_dev(vport)`. [F33, F94]
- `ovs_vport_receive()` must initialize `OVS_CB(skb)` fields (`input_vport`, `mru`, `cutlen`, `probability`, `upcall_pid`) before key extraction, and when `dev_net(skb->dev) != ovs_dp_get_net(vport->dp)`, it must save and restore `skb->mark` across `skb_scrub_packet(skb, true)` and clear `tun_info = NULL` before calling `ovs_flow_key_extract()`. [F39, F54]
- In `ovs_vport_send()`, the switch on `vport->dev->type` must allow both `MAC_PROTO_ETHERNET` (converting the `skb` to `ETH_P_TEB`) and `MAC_PROTO_NONE` (leaving the L3 `skb` intact) for `ARPHRD_NONE` devices, restrict `ARPHRD_ETHER` devices strictly to `MAC_PROTO_ETHERNET`, and drop all other combinations. Before calling `vport->ops->send(skb)`, `ovs_vport_send()` must clear `skb` timestamps with `skb_clear_tstamp(skb)`. [F73, F114]
- In `ovs_vport_send()` and `packet_length()`, MTU enforcement must skip GSO packets (`!skb_is_gso(skb)`), subtract `dev->hard_header_len` and a single `VLAN_HLEN` (only when `!skb_vlan_tag_present(skb) && eth_type_vlan(skb->protocol)`) using signed `int` arithmetic, and clamp non-positive lengths to 0 before comparing against `mtu`. [F66, F74]
- In `internal_dev_recv()`, before injecting a packet via `netif_rx(skb)`, it must drop any routing dst (`skb_dst_drop(skb)`), reset conntrack state (`nf_reset_ct(skb)`), pull the Ethernet header via `eth_type_trans()`, and update `skb->csum` via `skb_postpull_rcsum(skb, eth_hdr(skb), ETH_HLEN)`. [F117]
- `struct vport_portids` stores an element count in `n_ids` (`nla_len(ids) / sizeof(u32)`), so callers allocating, copying, or serializing `vport_portids->ids[]` must convert between `n_ids` and byte sizes by multiplying or dividing by `sizeof(u32)`, and `ovs_vport_set_upcall_portids()` must reject `@ids` with `-EINVAL` if `nla_len(ids)` is 0 or not a multiple of `sizeof(u32)`. [F61, F86]
- For OVS internal devices, `do_setup()` must set `netdev->max_mtu = ETH_MAX_MTU` after `ether_setup(netdev)`, and `internal_dev_create()` must set `vport->dev->netns_immutable = true` before `register_netdevice()` when `vport->port_no == OVSP_LOCAL`. [F109, F118]

## Synchronization

- `rtnl_lock()` nests inside `ovs_mutex` (`ovs_lock()`): vport `create` and `destroy` callbacks are invoked under `ovs_lock()` and acquire `rtnl_lock()` internally. All mutations to `vport_ops_list`, `dev_table`, `vport->upcall_portids`, and `dp_meter_table` (`tbl->ti`, `tbl->count`, `ti->dp_meters[]`) must be serialized under `ovs_lock()`, while readers must hold `ovs_mutex` or `rcu_read_lock()` and use `rcu_dereference_ovsl()` / `hlist_for_each_entry_rcu(..., lockdep_ovsl_is_held())` (or `rcu_dereference_rtnl(dev->rx_handler_data)` in `ovs_netdev_get_vport()`). [F18, F100, F106]
- In `ovs_meter_cmd_set()` and `ovs_meter_cmd_del()`, `lookup_meter()` and `detach_meter()` (plus `attach_meter()` in `ovs_meter_cmd_set()`) must execute within a single continuous `ovs_lock()` critical section so concurrent commands cannot detach or free the same `old_meter` twice. [F20]
- Mutable fields of a published `struct dp_meter` (`used`, `stats`, `bands[]`) must be protected by `meter->lock`, using `spin_lock(&meter->lock)` in softirq `ovs_meter_execute()` and `spin_lock_bh(&meter->lock)` in process-context `ovs_meter_cmd_set`, `ovs_meter_cmd_get`, and `ovs_meter_cmd_del`. In `ovs_meter_execute()`, because `now_ms` is sampled before `spin_lock(&meter->lock)`, `long_delta_ms = now_ms - meter->used` must be checked for `< 0` and clamped to `0` under `meter->lock` before clamping to `meter->max_delta_t` and casting to `u32 delta_ms`. [F19, F24]
- Before registering a vport's netdevice, `ovs_vport_alloc()` must allocate per-CPU `vport->upcall_stats` and initialize `vport->upcall_portids` via `ovs_vport_set_upcall_portids()`, and `internal_dev_create()` must set `internal_dev_priv(vport->dev)->vport = vport` before `rtnl_lock()` and `register_netdevice()`. [F12, F13]
- Before RCU publication, `dp_meter_create()` must initialize `meter->lock`, `used`, `max_delta_t`, and `bands` before `attach_meter()`, and `ovs_vport_set_upcall_portids()` must populate `n_ids`, `rn_ids` (`reciprocal_value`), and `ids` before `rcu_assign_pointer()` and free the old struct via `kfree_rcu(old, rcu)`. Published `dp_meter` and `dp_meter_instance` objects unlinked or replaced on an active datapath must also be freed via RCU (`kfree_rcu` in `ovs_meter_free()`, `call_rcu(&ti->rcu, dp_meter_instance_free_rcu)` in `dp_meter_instance_realloc()`). [F14, F26, F104]
- In `ovs_netdev_link()`, `vport->dev->priv_flags |= IFF_OVS_DATAPATH` must be set under `rtnl_lock()` only after `netdev_rx_handler_register()` succeeds, and `ovs_netdev_detach_dev()` must clear `IFF_OVS_DATAPATH` under `rtnl_lock()` before calling `netdev_rx_handler_unregister()`. [F93]
- `ovs_vport_receive()` and `ovs_vport_find_upcall_portid()` must be called within an `rcu_read_lock()` critical section in non-sleeping context; `internal_dev_xmit()` explicitly takes `rcu_read_lock()` around `ovs_vport_receive()`, and `netdev_port_receive()` must use `GFP_ATOMIC`. [F102]
- `ovs_vport_add()` is called with `ovs_mutex` held; if `ovs_vport_lookup()` finds `ops`, it acquires `try_module_get(ops->owner)` and calls `module_put(ops->owner)` if `ops->create()` fails. If `ops` is not found, it drops `ovs_unlock()` around `request_module()`, reacquires `ovs_lock()`, re-verifies `ovs_vport_lookup(parms)`, and returns `ERR_PTR(-EAFNOSUPPORT)` if still absent or `ERR_PTR(-EAGAIN)` if registered. [F7, F72]

## Object Lifetimes

- `ovs_netdev_link()` consumes `vport` on failure by calling `ovs_vport_free(vport)` on every error path, so callers (`netdev_create()`, `geneve_create()`, `gre_create()`, `vxlan_create()`) must not free `vport` when `ovs_netdev_link()` returns an `ERR_PTR`. [F1]
- In `internal_dev_create()`, `vport->dev->priv_destructor = internal_dev_destructor` must be set only after `register_netdevice(vport->dev)` succeeds so the `error_unlock` path can call `free_netdev(dev)` and `ovs_vport_free(vport)` without double-freeing `vport`. Once registered (`needs_free_netdev = true`), `internal_dev_destroy()` must only call `unregister_netdevice(vport->dev)` and never call `free_netdev()` or `ovs_vport_free()` directly. [F4, F92]
- In `ovs_vport_del()`, `hlist_del_rcu(&vport->hash_node)` and `module_put(vport->ops->owner)` must execute before `vport->ops->destroy(vport)`, and every `vport_ops.destroy` implementation must wait for an RCU grace period before calling `ovs_vport_free(vport)`. [F5]
- In `ovs_netdev_tunnel_destroy()`, under `rtnl_lock()`, `rtnl_delete_link()` (called only if `vport->dev->reg_state == NETREG_REGISTERED`) and `netdev_put()` must be followed by `vport->dev = NULL`, because the RCU callback `vport_netdev_free()` also calls `netdev_put(vport->dev, &vport->dev_tracker)`. [F17]

## API Contracts

- `ovs_vport_receive()` and `ovs_vport_send()` consume `@skb` on every path (passing it downstream or freeing it with `kfree_skb(skb)`), so callers must not dereference or free `skb` afterwards. Conversely, `ovs_meter_execute()` never frees `@skb`; it returns `true` only when an `OVS_METER_BAND_TYPE_DROP` band triggers and `false` when the packet passes or `lookup_meter()` returns `NULL`, leaving the caller to drop `@skb`. [F10, F31]
- Before calling `ovs_vport_receive()`, `netdev_port_receive()` must unshare the packet with `skb_share_check(skb, GFP_ATOMIC)`, restore the Ethernet header on `ARPHRD_ETHER` devices via `skb_push_rcsum(skb, ETH_HLEN)`, and pass `skb_tunnel_info(skb)` as `tun_info`. [F112]
- `ovs_vport_alloc()` places private data at offset `ALIGN(sizeof(struct vport), VPORT_ALIGN)` only when `priv_size > 0`, and `vport_from_priv()` subtracts that exact aligned offset, so `vport_priv()` must only be used on vports allocated with sufficient `priv_size` and `vport_from_priv()` requires a pointer to the start of the private area. [F63]
- `ovs_vport_get_stats()` must retrieve network device statistics via `dev_get_stats(vport->dev, &temp)` rather than reading `vport->dev->tstats` directly, because external netdevs may not allocate per-CPU `tstats`. [F34]

## Error Handling

- In `ovs_netdev_link()`, once `dev_get_by_name()` assigns `vport->dev`, every subsequent failure must jump to `error_put` (or a label falling through to `error_put`) to release the reference via `netdev_put(vport->dev, &vport->dev_tracker)` before freeing `vport`. [F2]
- In `geneve_tnl_create()`, `gre_tnl_create()`, and `vxlan_tnl_create()`, once the fallback tunnel `net_device` is created under `rtnl_lock()`, any subsequent failure before returning (such as `dev_change_flags()`) must call `rtnl_delete_link(dev, 0, NULL)` before `rtnl_unlock()` and `ovs_vport_free(vport)`. [F6]
- In `ovs_meter_cmd_set()`, once `detach_meter(meter_tbl, old_meter)` succeeds, `old_meter` is unlinked and must be freed via `ovs_meter_free(old_meter)` both on normal completion and on the `exit_free_old_meter` error path if `attach_meter()` fails (whereas an unattached new `meter` is freed with `kfree(meter)`). [F8]
- `ovs_meter_cmd_set()` must validate that `a[OVS_METER_ATTR_ID]` is non-null before calling `dp_meter_create(a)`, and `dp_meter_create()` must initialize `meter->id` from it. Each nested band in `dp_meter_create()` must be validated with `band_policy` to have non-NULL `OVS_BAND_ATTR_TYPE`, `OVS_BAND_ATTR_RATE`, and `OVS_BAND_ATTR_BURST`, and `band->rate == 0` must be rejected with `-EINVAL` before `div_u64(band->bucket, band->rate)`. [F32, F57]
- In `ovs_meter_cmd_reply_start()`, after `*ovs_reply_header = genlmsg_put(...)`, the failure check must test `!*ovs_reply_header` (not `!ovs_reply_header`), and callers must check the returned `struct sk_buff *` with `IS_ERR()` and `PTR_ERR()` because it returns `ERR_PTR` rather than `NULL`. [F28, F68]
- When extracting tunnel options via `nla_find_nested()` without an `nla_policy` table in `geneve_tnl_create()` and `vxlan_tnl_create()`, the caller must verify `nla_len(a) == sizeof(u16)` before calling `nla_get_u16(a)` on `OVS_TUNNEL_ATTR_DST_PORT`. [F64]

## External Contracts

- In `ovs_vport_get_upcall_portids()`, `OVS_VPORT_ATTR_UPCALL_PID` must be serialized as a single `u32` (`ids->ids[0]`) when `OVS_DP_F_VPORT_PIDS` is not set in `vport->dp->user_features`, and as the full `ids->n_ids * sizeof(u32)` array only when `OVS_DP_F_VPORT_PIDS` is enabled. [F62]
- `OVS_TUNNEL_ATTR_DST_PORT` is exchanged over Netlink in host byte order (`u16`), so `vxlan_tnl_create()` and `vxlan_get_options()` must convert between the Netlink `u16` and network-byte-order `vxlan_config.dst_port` (`__be16`) using `htons()` / `ntohs()`, whereas `geneve_tnl_create()` and `geneve_get_options()` store `geneve_port.dst_port` in host byte order. [F65]

## Known Pitfalls

- Because `dp_meter_instance_realloc()` replaces `tbl->ti` with a newly allocated `struct dp_meter_instance` and schedules the old instance for freeing via `call_rcu()`, callers (`attach_meter()`, `detach_meter()`) must not mutate or dereference a cached `ti` pointer after `dp_meter_instance_realloc()` succeeds. [F88]
- Dividing 64-bit quantities such as `band->bucket` (`u64`) or `ktime_get_ns()` (`u64`) by a 32-bit divisor in `meter.c` must use `div_u64()` rather than `/` to avoid `__udivdi3` link failures on 32-bit architectures. [F80]
- In `openvswitch_trace.h`, checking whether a `struct sw_flow_key` has a valid MAC protocol must test `!(key->mac_proto & SW_FLOW_KEY_INVALID)` rather than comparing `key->mac_proto` against `MAC_PROTO_NONE` (0), because validity is encoded in bit `0x80` (`SW_FLOW_KEY_INVALID`). [F77]
