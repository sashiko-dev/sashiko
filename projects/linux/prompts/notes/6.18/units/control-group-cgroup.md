# CONTROL GROUP (CGROUP)

The Control Group (cgroup) subsystem provides the Linux kernel's hierarchical process-grouping and resource-accounting framework across the unified v2 hierarchy and legacy v1 hierarchies mounted via kernfs. It manages task-to-cgroup associations (`css_set`), subsystem state lifecycles (`cgroup_subsys_state`), task migrations, scalable per-CPU recursive statistics (`rstat`), cgroup namespaces, and built-in controllers including freezer, pids, RDMA, misc, and debug.

## Architecture & Data Flow

- A `struct cgroup_subsys_state` is `cgroup::self` iff `css_is_self(css)` (`css->ss == NULL`); helpers taking arbitrary CSS pointers must check `css_is_self(css)` or `css->ss` before dereferencing `css->ss`. In `css_task_iter`, `it->cset_head` links `css_set::e_cset_node[it->ss->id]` when `it->ss` is non-NULL, but `cgrp_cset_link::cset_link` when `it->ss` is NULL, so `it->cset_pos` must be downcast according to `it->ss`. [F49, F134]
- On cgroupfs `kernfs_node`s, `kn->priv` is `struct cgroup *` on `KERNFS_DIR` and `struct cftype *` on `KERNFS_FILE`; code obtaining `struct cgroup *` from `kn` must check `kernfs_type(kn) == KERNFS_DIR` or use `kn_priv(kn)`. `cgroup_add_file()`/`cgroup_rm_file()` compute `struct cgroup_file *` as `(void *)css + cft->file_offset`, requiring `self`/`css` to stay at offset 0 of outer structs. [F129, F133]
- `struct cgroup::ancestors[]` uses inclusive `0..cgrp->level` indexing (`cgrp` at `ancestors[cgrp->level]`); `cgroup_create()` must allocate `struct_size(cgrp, ancestors, level + 1)` and `cgroup_ancestor()` must reject `ancestor_level < 0 || ancestor_level > cgrp->level`. In `struct cgroup_root`, `cgrp_ancestor_storage` must immediately follow `cgrp` because `cgroup_setup_root()` writes `root_cgrp->ancestors[0] = root_cgrp` into it. [F91, F126]
- `cgroup_migrate_add_src()` and `cgroup_migrate_prepare_dst()` must use separate `mg_src_preload_node` and `mg_dst_preload_node` list heads with independent `css_set` references. Before `cgroup_migrate_execute()` returns (commit or `out_cancel_attach`), it must move all `mg_tasks` back to `cset->tasks`, unlink `cset->mg_node`, and reset `tset->nr_tasks = 0` and `tset->csets = &tset->src_csets`. [F6, F73]
- Before unlinking `task->cg_list` (`css_set_move_task()`, `cgroup_release()`), `css_set_skip_task_iters()` must be called under `css_set_lock`. `css_set_move_task()` must evaluate `css_set_populated()` from `cset->tasks` and `cset->mg_tasks` emptiness (not `nr_tasks`), updating `to_cset` populated counters before `list_add_tail()` and `from_cset` counters after `list_del_init()`. [F77, F110]
- In `rebind_subsystems()`, all controllers leaving `&cgrp_dfl_root` must be cleared from `cgrp_dfl_root.subsys_mask` and disabled together via `cgroup_apply_control()`/`cgroup_finalize_control()` before clearing `scgrp->subsys[ssid]`. Moving `css_set`s between `e_csets[ss->id]` lists under `css_set_lock` must preserve order and update `it->cset_head` on every `css_task_iter` in `cset->task_iters`. [F66, F67]
- Every `css_rstat_cpu` must keep `rstatc->updated_children == css` when empty and `rstatc->updated_next == NULL` when unlinked. In `cgroup_base_stat_flush()`, per-CPU `bstat` deltas against `rstatbc->last_bstat` must propagate to `cgrp->bstat` and `rstatbc->subtree_bstat`, and when `cgroup_parent(parent)` is non-NULL, to `parent->bstat` and `prstatbc->subtree_bstat` while advancing `last_bstat`/`last_subtree_bstat`. [F79, F80]
- `root_cgroup_cputime()` must categorize `kernel_cpustat` into `cgroup_base_stat` identically to `__cgroup_account_cputime_field()` (excluding `CPUTIME_STEAL`, `CPUTIME_GUEST`, `CPUTIME_GUEST_NICE`), where `CPUTIME_NICE` must fall through to `CPUTIME_USER` so nice time is added to both `ntime` and `cputime.utime`; `cgroup_base_stat_add()`/`sub()` must update every member. [F81, F106]
- `CGRP_ROOT_FAVOR_DYNMODS` must only be updated via `cgroup_favor_dynmods()` under `cgroup_threadgroup_rwsem` (never directly in `root->flags`), and `cgroup_enable_per_threadgroup_rwsem` must never be reset to `false` once enabled because `cgroup_threadgroup_rwsem` alone does not exclude tasks already inside `cgroup_threadgroup_change_begin()`/`end()`. [F78, F145]
- Every CSS gets an increasing `serial_nr` and is appended via `list_add_tail_rcu()` to `parent->children`; `css_release_work_fn()` must set `CSS_RELEASED` when unlinking `css->sibling` so `css_next_child()` scans by `serial_nr`. `link_css_set()` must use `list_add_tail()` on `cset->cgrp_links` and `find_css_set()` must iterate `old_cset->cgrp_links` in order so `compare_css_sets()` sees identical hierarchy order. [F69, F89]

## Synchronization

- `cgroup_mutex` nests outside kernfs `active_ref`: kernfs callbacks needing `cgroup_mutex` must use `cgroup_kn_lock_live()` (which pins `cgrp`, breaks active protection, locks `cgroup_mutex`, and checks `!cgroup_is_dead()`) and pair a non-NULL return with `cgroup_kn_unlock(kn)` (never calling `cgroup_kn_unlock()` if it returned `NULL`). [F9, F37]
- `css_set_lock` is an IRQ-disabling spinlock (`spin_lock_irq`/`irqsave`), so sleeping calls (`kernfs_walk_and_get()`, `GFP_KERNEL`, `cgroup_mutex`) are forbidden under it; use lockless `current_cgns_cgroup_dfl()` for default-hierarchy ns root lookups. Modifying `nr_descendants` or `nr_dying_descendants` requires holding both `cgroup_mutex` and `css_set_lock` (readers need either). [F32, F146]
- `cgroup_threadgroup_rwsem` (and per-threadgroup `tsk->signal->cgroup_threadgroup_rwsem`) nests inside `cpus_read_lock()`: `cgroup_attach_lock()` must acquire `cpus_read_lock()` first, and `->attach()` callbacks must not take `cpus_read_lock()`. In `legacy_freezer.c`, `cpus_read_lock()` must be taken before `freezer_mutex` whenever `freezer_active` may change, using `static_branch_inc/dec_cpuslocked()`. [F36, F144]
- `cgroup_procs_write_start()` returns a pinned `task_struct *` and holds attach locks for `*lock_mode`, which must be released via `cgroup_procs_write_finish(task, lock_mode)` iff `!IS_ERR(task)`. After dropping `rcu_read_unlock()` and taking `cgroup_attach_lock()`, `cgroup_procs_write_start()` must recheck `thread_group_leader(tsk)` when `threadgroup` is true and retry lookup if leadership changed. [F10, F38]
- `css_rstat_updated()` may run in hardirq, softirq, or NMI: callers must disable preemption, and it must return early if `in_nmi()` when NMI-safe cmpxchg/this_cpu ops are unavailable, using `llist_on_list()` and `this_cpu_cmpxchg(rstatc_pcpu->lnode.next, self, NULL)` before `llist_add()` (paired with `llist_del_first_init()`). Per-CPU `rstatbc->bstat` updates must use `get_cpu_ptr()` and `u64_stats_update_begin/end_irqsave(&rstatbc->bsync)` before `css_rstat_updated()`. [F30, F31, F139]
- `css_rstat_flush()` holds `__css_rstat_lock(css, cpu)` (`spin_lock_irq` on `rstat_base_lock` or `css->ss->rstat_ss_lock`) continuously across `css_rstat_updated_list()` and the entire `rstat_flush_next` loop, so `->css_rstat_flush()`, `cgroup_base_stat_flush()`, and `bpf_rstat_flush()` run in atomic IRQ-disabled context. In `cgroup_base_stat_cputime_show()`, `__css_rstat_lock(&cgrp->self, -1)` must be held while copying `cgrp->bstat` and calling `cputime_adjust()`. [F28, F29, F142]
- CSS destruction stages must use their dedicated `max_active=1` workqueues (`css_killed_work_fn` on `cgroup_offline_wq`, `css_release_work_fn` on `cgroup_release_wq`, `css_free_rwork_fn` on `cgroup_free_wq`) to avoid deadlock in `cgroup_lock_and_drain_offline()`. Before `cgroup_lock_and_drain_offline()` drops `cgroup_mutex` to wait on `dsct->offline_waitq`, it must pin `dsct` with `cgroup_get_live()` and restart the descendant walk after relocking. [F44, F147]
- In `css_create()`, `ss->css_idr` must be allocated with `NULL` and only populated via `cgroup_idr_replace()` and `list_add_tail_rcu()` after `percpu_ref_init()` and `css_rstat_init()` succeed; `online_css()` sets `cgrp->subsys[ss->id]` only after `ss->css_online()` succeeds. All `cgroup_idr`/`ss->css_idr` mutations must take `spin_lock_bh(&cgroup_idr_lock)`, with `idr_preload()` before the lock and `__GFP_DIRECT_RECLAIM` stripped inside. [F22, F153]
- In `kill_css()`, `css->ss->css_killed(css)` must run synchronously under `cgroup_mutex` before setting `CSS_DYING`, calling `css_clear_dir(css)`, and calling `percpu_ref_kill_and_confirm(&css->refcnt, css_killed_ref_fn)` while holding an extra `css_get(css)` reference that is dropped in `css_killed_work_fn()` after `offline_css(css)`. [F19, F23]
- `task_css_set_check()` (`task_css_set()`, `task_css()`, `task_dfl_cgroup()`) requires `rcu_read_lock()`, `rcu_read_lock_sched()`, `cgroup_mutex`, `css_set_lock`, or `PF_EXITING`. `task_cgroup_from_root()`/`cset_cgroup_from_root()` for `root != &cgrp_dfl_root` requires `css_set_lock` plus `cgroup_mutex` or `rcu_read_lock()`. `cgroup_e_css()` and `cgroup_css()` require `cgroup_mutex` or `rcu_read_lock()` and return an unpinned CSS, whereas `cgroup_get_e_css()` pins an online CSS requiring `css_put()`. [F1, F45, F149, F150]
- In `cgroup_post_fork()`, `child` must be linked via `css_set_move_task()` under `css_set_lock` before `ss->fork(child)`, and in `cgroup_exit()`, `tsk` must be unlinked under `css_set_lock` before `ss->exit(tsk)`. `__cgroup_kill()` increments `cgrp->kill_seq` under `css_set_lock` and `cgroup_post_fork()` compares it under `css_set_lock` against `kargs->kill_seq` from `cgroup_css_set_fork()`. [F34, F42]

## Object Lifetimes

- `cgroup_css_set_fork()` pins `kargs->cset` and enters `cgroup_threadgroup_change_begin(current)` on all forks (and locks `cgroup_mutex` and pins `kargs->cgrp` if `CLONE_INTO_CGROUP`), all of which `cgroup_css_set_put_fork()` must unconditionally release on `cgroup_cancel_fork()` and `cgroup_post_fork()`. In `cgroup_post_fork()`, `kargs->cset` transfers to `child->cgroups` (or is put if `child->pid == 0`) and must be cleared to `NULL` first. [F4, F5]
- Every `css_task_iter_start()` must be paired with `css_task_iter_end()` (including before restarting at `*pos == 0`). `cgroup_do_get_tree()` consumes the caller's `cgroup` ref on `&ctx->root->cgrp`; in `cgroup1_get_tree()`, if `ctx->root->cgrp.self.refcnt` is dying after `cgroup_do_get_tree(fc)` succeeds, call `fc_drop_locked(fc)` before `restart_syscall()`. [F11, F12, F13]
- `cgroup_sk_alloc()` must always set `skcd->cgroup` (`&cgrp_dfl_root.cgrp` when `in_interrupt()`) and take both `cgroup_get()` and `cgroup_bpf_get()` refs; `cgroup_sk_clone()` must use `cgroup_get()` (not `cgroup_get_live()`). `link_css_set()`/`put_css_set_locked()` refcount `link->cgrp` iff `cgroup_parent(cgrp)` is non-NULL. `pressure_write()` must pass `of` to `psi_trigger_create()`, publish `ctx->psi.trigger` via `smp_store_release()`, and destroy it in `cgroup_pressure_release()`. [F14, F20, F21, F46, F163]

## API Contracts

- Subsystem IDs (`ssid`) are 0-based indices in `[0, CGROUP_SUBSYS_COUNT)` (`<= 16`), whereas `do_each_subsys_mask()`, `rebind_subsystems()`, `cgroup_setup_root()`, and `u16` masks take `1 << ssid` (and must be copied to `unsigned long` bounded by `CGROUP_SUBSYS_COUNT` for bit scans); `css->id` in `ss->css_idr` is 1-based (`1` root, `>= 2` non-root). `cgroup_is_descendant(cgrp, ancestor)` takes descendant first, ancestor second. [F58, F59, F94, F95, F138]
- `pids_try_charge()` sets `*fail` only on `-EAGAIN`; `rdmacg_try_charge()` sets `*rdmacg` only on `0`. `pids_try_charge()` and `misc_cg_try_charge()` increment before checking limits so rollback uncharges inclusively through the failing node, whereas `rdmacg_try_charge()` checks first so `rdmacg_uncharge_hierarchy(cg, device, p, index)` uncharges `[cg, p)` exclusively and drops `cg`'s CSS ref. Validate `valid_type(type)` in `misc` APIs, `index < RDMACG_RESOURCE_MAX` in `rdma` APIs, and `index < 0` on signed `parse_resource()` returns. [F17, F63, F64, F101, F118]

## Error Handling

- In `cgroup_create()`, unwind in LIFO order: `css_rstat_init()` -> `out_kernfs_remove`, `psi_cgroup_alloc()` -> `out_stat_exit`, `cgroup_lifetime_notifier` -> `out_psi_free`. In `css_create()`, failures after `init_and_link_css()` must queue `css->destroy_rwork` on `cgroup_free_wq`, and `css_rstat_exit()` must check `css->rstat_cpu != NULL` before flushing/freeing. [F2, F3, F50]
- `__cgroup_get_from_id`, `cgroup_get_from_id`, `cgroup_get_from_path`, `cgroup_get_from_fd`, `cgroup_v1v2_get_from_fd`, `task_get_cgroup1`, and `css_tryget_online_from_dir` return `ERR_PTR` (never `NULL`), whereas `css_from_id`, `cgroup_css`, `cgroup_tryget_css`, and `find_css_set` return `NULL`. Subtree control changes must pair `cgroup_save_control()` and `cgroup_apply_control()` with `cgroup_finalize_control(cgrp, ret)`. [F15, F47]
- Check `task->nsproxy != NULL` in `current_cgns_cgroup_dfl()` and `cgroupns_get()`; `memset(bstat, 0, sizeof(*bstat))` in `root_cgroup_cputime()`; and on `cgroup_add_file()` failure in `cgroup_addrm_files()`, set `cft_end = cft` and `is_add = false` without clearing `ret`. [F51, F54, F113]

## External Contracts

- Write-time migration and delegation checks in `cgroup_file_write()`, `__cgroup_procs_write()`, and `__cgroup1_procs_write()` must use the opener's `of->file->f_cred` (via `override_creds()` around `cgroup_attach_permissions()`) and `ctx->ns` from `cgroup_file_open()`, never `current_cred()` or `current->nsproxy->cgroup_ns`. `cgroup_get_from_id()` and `cgroup_get_from_path()` must restrict lookups to `current_cgns_cgroup_dfl()`. [F168, F169, F171]
- Setting v1 `release_agent` requires `CAP_SYS_ADMIN` in `init_user_ns` (`ctx->ns->user_ns == &init_user_ns && file_ns_capable(of->file, &init_user_ns, CAP_SYS_ADMIN)`), `cgroupns_install()` requires `ns_capable(..., CAP_SYS_ADMIN)` in both `nsset->cred->user_ns` and `cgroup_ns->user_ns`, and `apply_cgroup_root_flags()` must only modify `cgrp_dfl_root.flags` when `current->nsproxy->cgroup_ns == &init_cgroup_ns`. [F170, F173, F174]

## Known Pitfalls

- `init_and_link_css()` zeroes `struct cgroup_subsys_state` after `ss->css_alloc()`, so `css_alloc` must only initialize outer fields. In `cgroup_migrate_prepare_dst()`, if `src_cset == dst_cset`, unlink `src_cset` from `preloaded_src_csets` and put both refs; if `dst_cset->mg_dst_preload_node` is already linked, put the duplicate `dst_cset` ref. [F119, F128]
- Revalidate cached `ctx->procs1.pidlist` via `cgroup_pidlist_find()` under `cgrp->pidlist_mutex` in `cgroup_pidlist_start()`, and cap `pidlist_array_load()` at `n == length` and set `length = n` before sorting. Skip `PF_EXITING` tasks in `cgroup_transfer_tasks()`; use `css = css_rightmost_descendant(css)` to skip subtrees in `css_for_each_descendant_pre()`; and test `cgroup_is_threaded(child)` (not `cgrp`) in `cgroup_update_populated()`. [F70, F102, F112, F116, F120]
