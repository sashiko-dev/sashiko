# BROADCOM BNXT_EN 50 GIGABIT ETHERNET DRIVER

This unit provides core header definitions and subsystem modules for the Broadcom NetXtreme-C/E (`bnxt_en`) Ethernet driver, implementing the HWRM firmware command/response protocol, ethtool configuration and NVRAM flashing, devlink device management and health reporting, IEEE 802.1Qaz DCB, PTP hardware clock and packet timestamping, coredump collection, hwmon temperature monitoring, DIM, and debugfs inspection.

## Architecture & Data Flow
- In `__hwrm_send()`, after polling confirms `*valid` is non-zero, `*valid` must be cleared to `0` before returning because the valid byte in an older HWRM spec may overlap a new response field in a newer spec. When `BNXT_HWRM_INTERNAL_CTX_OWNED` is set, `BNXT_HWRM_INTERNAL_RESP_DIRTY` must be set on exit and `ctx->resp` zeroed at the start of any subsequent `__hwrm_send()` on that context. [F43, F74]
- When calculating hardware TX ring, channel, or traffic class counts (`bnxt_get_channels()`, `bnxt_set_channels()`, `bnxt_queue_remap()`), read `bp->num_tc` rather than `netdev_get_num_tc(bp->dev)`. Because `bp->num_tc` is `0` when hardware TCs are unconfigured, `bnxt_get_channels()` must clamp the divisor with `max(tcs, 1)` (for combined) or guard with `if (tcs > 1)` (for TX-only). [F64, F136]
- In `bnxt_set_channels()`, after mutating `bp->rx_nr_rings`, `bp->tx_nr_rings_per_tc`, `bp->tx_nr_rings`, and `bp->cp_nr_rings`, `netdev_update_features(dev)` must be called before `bnxt_open_nic()` or `bnxt_reserve_rings()`. [F65]
- When `bnxt_queue_remap(bp, tc_mask)` changes `bp->tc_to_qidx`, callers must first verify `hweight(tc_mask) <= bp->max_lltc` so `bp->q_info[j]` is not overrun, and `bnxt_queue_remap()` must close/reopen the NIC if running and re-apply `bnxt_hwrm_queue_cos2bw_cfg()` and `bnxt_hwrm_queue_pri2cos_cfg()` if `bp->ieee_ets` is set. In `bnxt_ets_validate()`, the TSA and bandwidth sum validation loop must iterate only up to the highest mapped traffic class `max_tc`. [F77, F88, F125]
- Whenever `ptp->cc.mult` is updated in non-RTC/multi-host mode in `bnxt_ptp_adjfine()`, `timecounter_read(&ptp->tc)` must be called first under `write_seqlock_irqsave(&ptp->ptp_lock, flags)`. In `bnxt_ptp_init()`, non-RTC mode (`!BNXT_PTP_USE_RTC(bp)`) must call `bnxt_ptp_adjfine_rtc(bp, 0)` alongside `bnxt_ptp_timecounter_init(bp, true)`. In `bnxt_ptp_rtc_timecounter_init()`, `ptp->tc.cycle_last` must be set to `ns & ptp->cc.mask` after `timecounter_init()`. In `bnxt_ptp_adjphc()`, `bnxt_ptp_update_current_time(ptp->bp)` must be called on success. [F67, F68, F69, F130]
- `cpr->cp_desc_ring` is indexed by `[CP_RING(RING_CMP(raw_cons))][CP_IDX(RING_CMP(raw_cons))]`, whereas `TX_CMP_VALID(txcmp, raw_cons)` requires the unmasked `raw_cons`. `txr->tx_prod` and `txr->tx_cons` wrap at $2^{16}$, so `bnxt_tx_avail()` must mask `(READ_ONCE(txr->tx_prod) - READ_ONCE(txr->tx_cons))` with `bp->tx_ring_mask` before subtracting from `bp->tx_ring_size`, and `txr->tx_buf_ring` must be indexed with `RING_TX(bp, cons)`. [F108, F134]
- Hardware completion bitfield masks `RX_AGG_CMP_AGG_ID`, `RX_TPA_START_CMP_AGG_ID_P5`, and `RX_TPA_END_CMP_AGG_ID_P5` must remain `(0x0fff << 16)` rather than `(0xffff << 16)`. `BNXT_MAX_PAGE_MODE_MTU` must subtract `SKB_DATA_ALIGN((unsigned int)sizeof(struct skb_shared_info))` in addition to `VLAN_ETH_HLEN`, `NET_IP_ALIGN`, and `XDP_PACKET_HEADROOM` from `PAGE_SIZE`, wrapped in outer parentheses. [F92, F188]
- In `struct bnxt_ntuple_filter` and `struct bnxt_l2_filter`, `struct bnxt_filter_base base` must be the first member, and code iterating `bp->usr_fltr_list` must check `fltr->type` or `BNXT_ACT_RSS_CTX` before downcasting with `container_of()`. Every `BNXT_ACT_*` flag set in `bnxt_add_ntuple_cls_rule()` or `bnxt_add_l2_cls_rule()` must have a matching branch in `bnxt_grxclsrule()`. [F82, F145]
- `bnxt_get_num_stats()`, `bnxt_get_ethtool_stats()`, and `bnxt_get_strings()` must traverse all stat groups in identical order under identical predicates, and `bnxt_get_ethtool_stats()` must advance `j += bnxt_get_num_ring_stats(bp)` when `!bp->bnapi`. In `bnxt_get_regs()`, converting `struct pcie_ctx_hw_stats_v2` must swap 32-bit fields within `bnxt_pcie_32b_entries[]` (ordered by strictly ascending offsets) 4 bytes at a time via `le32_to_cpu()`, and all other offsets via `le64_to_cpu()`. [F91, F120, F121]
- In `__bnxt_get_coredump()` and `bnxt_hwrm_dbg_dma_data()`, segment writes into a non-NULL `buf` must be bounded by `BNXT_COREDUMP_BUF_LEN(buf_len)`, clamping `copylen = min_t(u16, len, info->dest_buf_size - off)` and breaking if `copylen < len`. In `bnxt_get_ctx_coredump()`, when `bnxt_bs_trace_avail(bp, type)` is true, `bnxt_fill_drv_seg_record()` must be called before `bnxt_copy_ctx_mem()`. [F87, F161, F200]

## Synchronization
- `__hwrm_acquire_token()` and `__hwrm_release_token()` must hold `bp->hwrm_cmd_lock` while updating sequence counters and `bp->hwrm_pending_list`, and `BNXT_HWRM_CHNL_CHIMP` tokens must use `hlist_add_head_rcu()`, `hlist_del_rcu()`, and `kfree_rcu(token, rcu)`. In `__hwrm_send()`, `wmb()` must precede writing the request and doorbell to `bp->bar0`, and polling DMA responses without a completion ring requires `dma_rmb()` before reading `*valid` after observing non-zero `READ_ONCE(ctx->resp->resp_len)` and matching `READ_ONCE(ctx->resp->seq_id)`. [F26, F27]
- `rtnl_lock()` must always be acquired before `netdev_lock(bp->dev)` and released after `netdev_unlock(bp->dev)`, with `bp->link_lock` nesting inside `netdev_lock(bp->dev)`. In `bnxt_dl_reload_down()` and `bnxt_dl_reload_up()`, `bnxt_ulp_stop()` / `bnxt_ulp_start()` must be called outside both locks; `bnxt_dl_reload_up()` enters with both locks held, must drop/re-acquire both in order across the `BNXT_STATE_FW_ACTIVATE` wait, and must release both on all return paths. [F9, F30, F174]
- Any path holding `netdev_lock(bp->dev)` (such as `bnxt_dl_reload_down()` / `bnxt_dl_reload_up()` error handling) must call `netif_close(bp->dev)` rather than `dev_close(bp->dev)`. Callers of `bnxt_sriov_cfg()` must hold `rtnl_lock`. [F32, F177]
- In `struct bnxt_fw_health`, reads and updates to `severity` and `remedy` must hold `fw_health->lock`. `bnxt_devlink_health_fw_report()` and `bnxt_dl_health_fw_status_update()` must unlock `fw_health->lock` before calling `devlink_health_report()` or `devlink_health_reporter_state_update()`, whereas `bnxt_fw_diagnose()` holds `h->lock` across `devlink_health_report()` (so `bnxt_fw_dump()` must not acquire `fw_health->lock`). [F34, F178]
- All acquisitions of `ptp->ptp_lock` must use `irqsave`/`irqrestore` (`write_seqlock_irqsave` or `read_seqlock_excl_irqsave`), never `_bh` variants, because netpoll can acquire it from hardirq context. All accesses to `ptp->tc` must hold `write_seqlock_irqsave(&ptp->ptp_lock, flags)`, and `bnxt_cc_read()` must call `__bnxt_refclk_read()` rather than `bnxt_refclk_read()` to avoid recursive deadlock. [F20, F170]
- Direct BAR0 reads of `ptp->refclk_mapped_regs` outside a `ptp->ptp_lock` write section must hold `read_seqlock_excl_irqsave(&ptp->ptp_lock, flags)` and abort with `-EIO` if `test_bit(BNXT_STATE_IN_FW_RESET, &bp->state)` is set. [F21]
- In `bnxt_get_tx_ts_p5()`, `txts_req->abs_txts_tmo` must be written before `smp_wmb()` and `txts_req->tx_skb = skb`, paired with `smp_rmb()` in `bnxt_stamp_tx_skb()`. Updates to `ptp->tx_avail` and `ptp->txts_prod` must hold `spin_lock_bh(&ptp->ptp_tx_lock)`, and `bnxt_ptp_free_txts_skbs()` must call `ptp_cancel_worker_sync(ptp->ptp_clock)` before draining `ptp->txts_req[]` and resetting `tx_avail`/`txts_cons`, then call `ptp_schedule_worker()`. [F22, F160, F172]
- Lookups over `bp->l2_fltr_hash_tbl` and `bp->ntp_fltr_hash_tbl` must be enclosed in `rcu_read_lock()` / `rcu_read_unlock()`, and `bnxt_srxclsrldel()` must drop `rcu_read_unlock()` before calling blocking filter free/delete helpers. In `bnxt_set_coalesce()`, applying coalescing changes to hardware must be gated on `test_bit(BNXT_STATE_OPEN, &bp->state)` rather than `netif_running(dev)`. `bnxt_hwmon_notify_event()` must only be called from process/workqueue context (`BNXT_THERMAL_THRESHOLD_SP_EVENT`), never from NAPI/softirq. [F36, F37, F169]

## Object Lifetimes
- `__hwrm_req_init()` allocates a request from `bp->hwrm_dma_pool` that is consumed and freed by `hwrm_req_send()` (even on error) unless the caller claims ownership via `hwrm_req_hold()`; if held (such as `get` in `bnxt_hwrm_set_dcbx_app()`, whose DMA slice is passed to `set`), or if an error occurs before `hwrm_req_send()` (including when `hwrm_req_dma_slice()` returns `NULL`), the caller must release it via `hwrm_req_drop()`. `bnxt_hwrm_dbg_dma_data()` always drops `msg` via `hwrm_req_drop(bp, msg)` and frees/clears `info->dest_buf` on `-ENOBUFS`. [F1, F7, F16, F41]
- `hwrm_req_replace()` frees any existing `ctx->slice_addr`, resets `ctx->allocated` and `ctx->req->resp_addr`, recalculates `ctx->sentinel` with `hwrm_calc_sentinel()`, and when `!(bp->fw_cap & BNXT_FW_CAP_SHORT_CMD)` and `len <= BNXT_HWRM_MAX_REQ_LEN`, stores a borrowed pointer `ctx->req = new_req` that must outlive `req`; callers must continue passing the original `req` pointer (not `new_req`) to all HWRM API calls. [F4, F72, F140]
- Because `bp->hwmon_dev`, `ptp->ptp_clock`, and `fw_health->fw_reporter` are tested for non-NULL during runtime and teardown, registration paths (`bnxt_hwmon_init()`, `bnxt_ptp_init()`, `__bnxt_dl_reporter_create()`) must convert `IS_ERR()` results to `NULL`, and teardown (`bnxt_dl_fw_reporters_destroy()`, `bnxt_ptp_free()`, `bnxt_ptp_clear()`) must clear `fw_health->fw_reporter`, `ptp->ptp_clock`, and `ptp->ptp_info.pin_config` to `NULL` after unregistering/freeing them. [F11, F14, F45]
- In `bnxt_ptp_init()`, `seqlock_init(&ptp->ptp_lock)` and `spin_lock_init(&ptp->ptp_tx_lock)` must run before `bnxt_ptp_timecounter_init()` or `bnxt_ptp_init_rtc()`. In `bnxt_ptp_free()` and `bnxt_ptp_clear()`, `ptp_clock_unregister(ptp->ptp_clock)` must precede freeing `ptp->ptp_info.pin_config` and `bnxt_unmap_ptp_regs(bp)`. [F19, F25]
- In `bnxt_create_rxfh_context()`, any failure after `bp->num_rss_ctx++` must unwind via `bnxt_del_one_rss_ctx(bp, rss_ctx, true)`. In `bnxt_add_ntuple_cls_rule()`, errors after `atomic_inc(&l2_fltr->refcnt)` and before `bnxt_insert_ntp_filter()` succeeds must unwind via `atomic_dec(&l2_fltr->refcnt)` and `kfree(new_fltr)` at `ntuple_err:`, whereas errors after `bnxt_insert_ntp_filter()` succeeds must unwind via `bnxt_del_ntp_filter(bp, new_fltr)`. [F17, F18]

## API Contracts
- `__hwrm_req_init()`, `hwrm_req_send()`, and `hwrm_req_send_silent()` must only be called from sleepable context. `hwrm_req_hold()` returns a response pointer valid only until `hwrm_req_drop()` and returns `NULL` if called on an already-owned request. Callers needing a zero-initialized DMA slice even when `hwrm_req_dma_slice()` falls back to `dma_alloc_coherent()` must call `hwrm_req_alloc_flags(bp, req, GFP_KERNEL | __GFP_ZERO)` first. [F2, F42, F168]
- When encoding the 5-bit BD count in `struct tx_bd.tx_bd_len_flags_type`, use `TX_BD_CNT(n)` (`((n) << TX_BD_FLAGS_BD_CNT_SHIFT) & TX_BD_FLAGS_BD_CNT`) so `TX_MAX_BD_CNT` (32) wraps to 0 without overflowing into `TX_BD_FLAGS_LHINT`. [F61]
- Both `bnxt_rxfh_context_check()` and `bnxt_set_rxfh()` must reject any non-zero `rxfh->hfunc` other than `ETH_RSS_HASH_TOP` with `-EOPNOTSUPP`. In `bnxt_create_rxfh_context()`, before `bnxt_modify_rss()`, the driver must call `bnxt_set_dflt_rss_indir_tbl(bp, ctx)`, set `ctx->hfunc = ETH_RSS_HASH_TOP`, and copy `bp->rss_hash_key` into both `vnic->rss_hash_key` and `ethtool_rxfh_context_key(ctx)`. [F90, F187]

## Error Handling
- Entry points reachable outside `ptp_clock_info` callbacks (`bnxt_hwtstamp_set()`, `bnxt_hwtstamp_get()`, `bnxt_get_ts_info()`, `bnxt_get_ptp_stats()`, `bnxt_ptp_cfg_tstamp_filters()`, `bnxt_ptp_reapply_pps()`, `bnxt_get_rx_ts_p5()`, `bnxt_ptp_init_rtc()`) must verify `bp->ptp_cfg` is non-NULL before dereferencing it. [F46]
- In `bnxt_ptp_ts_aux_work()`, the loop over `ptp->txts_req[cons]` must `break` without incrementing `ptp->tx_avail` or advancing `cons` when `!tx_skb` or `bnxt_stamp_tx_skb()` returns `-EAGAIN`, and skip via `goto next_slot` when `IS_ERR(tx_skb)`; `bnxt_ptp_free_txts_skbs()` must check `!IS_ERR_OR_NULL(tx_skb)`. [F47, F122]
- Because `bp->bnapi` and `bp->vnic_info` are `NULL` when the interface is down, `bnxt_rxfh_context_check()` and `bnxt_srxclsrlins()` must verify `netif_running(bp->dev)` (returning `-EAGAIN`), and `bnxt_get_ethtool_stats()` and `bnxt_get_rxfh()` must null-check `bp->bnapi` and `bp->vnic_info`. `bnxt_alloc_new_l2_filter()` returns an `ERR_PTR` on failure (not `NULL`), so callers must check `IS_ERR(fltr)`. [F54, F55]

## External Contracts
- In `bnxt_self_test()`, when `bp->num_tests` is non-zero on a PF, `buf` must be zero-initialized via `memset()` before any early failure check, and every early error return must set `etest->flags |= ETH_TEST_FL_FAILED`. `bnxt_ethtool_ops.rxfh_max_num_contexts` must be `BNXT_MAX_ETH_RSS_CTX + 1`. `struct hwrm_port_phy_qcfg_output_compat` must remain 96 bytes with `valid` at byte 96 and `PORT_PHY_QCAPS_RESP_FLAGS2_SPEEDS2_SUPPORTED` cleared in `option_flags`. [F53, F89, F93]

## Known Pitfalls
- In `__hwrm_send()`, polling without a completion ring releases `token` via `__hwrm_release_token()` and sets `token = NULL` when `token->state == BNXT_HWRM_DEFERRED`, so subsequent code must not dereference `token` unconditionally (use `le16_to_cpu(ctx->req->seq_id)`). `bp->fw_cap` is a `u64` mask, so all `BNXT_FW_CAP_*` definitions must use `BIT_ULL()`. [F6, F135]
- In `__bnxt_refclk_read()`, `refclk_mapped_regs[0]` must be re-read if `refclk_mapped_regs[1]` changes across the read, and the `u32` `high_now` value must be cast to `u64` before shifting left by 32. Similarly, `BNXT_GET_TX_TS_48B_NS` and `EVENT_PPS_TS` must cast masked upper 32-bit words to `u64` before shifting, and `bnxt_get_target_cycles()` must use `div64_u64(nsec_delta << ptp->cc.shift, ptp->cc.mult)`. In `bnxt_stamp_tx_skb()` and `bnxt_ptp_ts_aux_work()`, remaining jiffies (`deadline - now`) must only be computed after `!time_after_eq(now, deadline)`. [F127, F129, F131, F133]
- In `bnxt_reset()`, `BNXT_FW_RESET_CHIP` must be tested with `(req & BNXT_FW_RESET_CHIP) == BNXT_FW_RESET_CHIP`, `BNXT_FW_RESET_AP` (`bnxt_firmware_reset_ap()`) must be guarded by `!BNXT_CHIP_P4_PLUS(bp) && bp->hwrm_spec_code >= 0x10803`, and each succeeded reset component must clear its bits in `*flags`. Similarly, in `bnxt_dl_livepatch_activate()`, `BNXT_LIVEPATCH_STATE(flags)` must be compared with `==` rather than `&`. [F115, F116, F167, F199]
- In `bnxt_get_link_ksettings()`, port type and media link-mode bits must branch on `bnxt_get_media(link_info)` (handling `BNXT_MEDIA_KR` with `ETHTOOL_LINK_MODE_Backplane_BIT`) rather than raw `link_info->media_type`. In `bnxt_get_rxfh_indir_size()`, RSS indirection table size on `BNXT_FLAG_CHIP_P5_PLUS` devices must be `bnxt_get_nr_rss_ctxs(bp, bp->rx_nr_rings) * BNXT_RSS_TABLE_ENTRIES_P5`. [F110, F165]
