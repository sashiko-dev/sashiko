# KERNEL VIRTUAL MACHINE FOR X86 (KVM/x86)

`arch/x86/kvm/x86.c` implements core x86 KVM (`kvm.ko`), bridging generic KVM with VMX/SVM backends. It manages VM/vCPU lifecycles, the guest entry/exit loop (`vcpu_enter_guest`), instruction emulation callbacks, MSR/CR/FPU/debug register virtualization, event injection, `kvmclock`/TSC scaling, memslot metadata, and x86 ioctls.

## Architecture & Data Flow
- When `vcpu->arch.guest_state_protected` is true, guest GPRs, RIP, CPL, and segments are inaccessible (`vcpu_enter_guest`, `kvm_arch_vcpu_put`, `kvm_can_deliver_async_pf`, `kvm_get_linear_rip`, and `store_regs()` must guard against it); hypercalls must use `is_64_bit_hypercall(vcpu)`, and when `kvm->arch.has_protected_state` is set, `kvm_sync_valid_fields()` must return `0` so non-zero `kvm_valid_regs`/`kvm_dirty_regs` fail with `-EINVAL`. [F48, F84]
- In `vcpu_enter_guest()`, `KVM_REQ_TLB_FLUSH` (`kvm_vcpu_flush_tlb_all()`) must precede `kvm_service_local_tlb_flush_requests()`, and `KVM_REQ_CLOCK_UPDATE` must precede `KVM_REQ_HV_STIMER`. `run_flags` (`KVM_RUN_LOAD_GUEST_DR6`, `KVM_RUN_LOAD_DEBUGCTL`) must be set before the inner `vcpu_run` fastpath loop and cleared to `0` on `EXIT_FASTPATH_REENTER_GUEST`, while `sync_dirty_debug_regs()` runs after the loop before `hw_breakpoint_restore()`. [F64, F106, F156]
- In `kvm_check_and_inject_events()`, the re-injection `if`/`else if` chain must check `kvm_is_exception_pending(vcpu)` (doing nothing) before `nmi_injected` and `interrupt.injected`. Morphing a userspace exception to `exception_vmexit` via `kvm_queue_exception_vmexit()` must clear `exception.injected` and `pending`, and `KVM_GET_VCPU_EVENTS` must select `vcpu->arch.exception` whenever `injected` or `pending` is set. [F107, F121]
- In `kvm_deliver_exception_payload()`, delivering a `DB_VECTOR` payload to `vcpu->arch.dr6` must clear `DR_TRAP_BITS`, set `DR6_ACTIVE_LOW`, OR in `ex->payload`, flip active-low bits in `ex->payload`, clear `BIT(12)`, and reset `ex->has_payload`/`ex->payload`. Changes to `dr7`, `guest_debug_dr7`, or `KVM_GUESTDBG_USE_HW_BP` require calling `kvm_update_dr7()`, and `kvm_arch_vcpu_ioctl_set_guest_debug()` must bracket `guest_debug` and `singlestep_rip` updates with `kvm_get_rflags()` and `kvm_set_rflags()`. [F65, F72, F75]
- When `x86_emulate_instruction()` is called with `EMULTYPE_NO_DECODE`, it must not re-decode, clear the exception queue, check code breakpoints, or re-check L1 intercepts for L2. Exiting to userspace without writeback sets `emulate_regs_need_sync_to_vcpu` (flushed by `__get_regs()`), while `__set_regs()` sets `emulate_regs_need_sync_from_vcpu`. [F63, F73]
- In `complete_emulated_mmio()` and `complete_sev_es_emulated_mmio()`, each step processes `min(8u, frag->len)` bytes and only increments `mmio_cur_fragment` when `frag->len <= 8` (otherwise advancing `frag` in place); in `kvm_sev_es_outs()`/`kvm_sev_es_ins()`, PIO `count` must be clamped to `min_t(unsigned int, PAGE_SIZE / size, vcpu->arch.sev_pio_count)`. [F103, F114]
- `kvm_unprotect_and_retry_on_failure()` must return `false` when `EMULTYPE_WRITE_PF_TO_SP` is set to avoid infinite self-modifying page-table fault loops. In `kvm_inject_emulated_page_fault()`, non-reserved present faults (`(error_code & PFERR_PRESENT_MASK) && !(error_code & PFERR_RSVD_MASK)`) must call `kvm_mmu_invalidate_addr()` on `fault->nested_page_fault ? vcpu->arch.mmu : vcpu->arch.walk_mmu` before `inject_page_fault()`. [F116, F117]
- Transitions to `KVM_MP_STATE_RUNNABLE` must use `kvm_set_mp_state()` to clear `pv_unhalted`, and in `vcpu_block()`, if `!kvm_arch_vcpu_runnable(vcpu)` holds after `kvm_vcpu_halt()`/`kvm_vcpu_block()`, it must return `1` before the `mp_state` switch. Toggling `CR0.PG` in `kvm_post_set_cr0()` or `kvm_vcpu_reset()` must clear the async #PF queue, reset `apf.gfns` (which uses `~0` as empty sentinel and rehashes clusters in `kvm_del_async_pf_gfn()`), and flush the guest TLB when cleared. [F62, F79, F102, F119]
- `MSR_IA32_S_CET` and `MSR_IA32_INT_SSP_TAB` must never be in `is_xstate_managed_msr()` or loaded into host hardware via guest FPU XSTATE (only `MSR_IA32_U_CET` and `MSR_IA32_PL0_SSP ... MSR_IA32_PL3_SSP` are). In `kvm_load_guest_xsave_state()` and `kvm_load_host_xsave_state()`, hardware PKRU must be updated via raw `wrpkru()`, not `write_pkru()`. [F78, F164]
- In `kvm_set_msr_common()`, guest writes to `MSR_IA32_TSC_ADJUST` must call `adjust_tsc_offset_guest(vcpu, data - ia32_tsc_adjust_msr)` and request `KVM_REQ_CLOCK_UPDATE`, while guest `MSR_IA32_TSC` writes add the offset delta to `ia32_tsc_adjust_msr`. In `kvm_guest_time_update()`, clear `PVCLOCK_GUEST_STOPPED` right after updating `vcpu->pv_time` and clear `PVCLOCK_TSC_STABLE_BIT` for Xen only after `vcpu->pv_time` and `kvm_hv_setup_tsc_page()`; `kvm_setup_guest_pvclock()` must modify a local copy of `ref_hv_clock`. [F58, F71, F105]

## Synchronization
- `vcpu_run()`, `vcpu_enter_guest()`, and `vcpu_block()` run under `vcpu->kvm->srcu` and must unlock it via `kvm_vcpu_srcu_read_unlock(vcpu)` before `IN_GUEST_MODE`, blocking, or user-mode work, re-locking on return. Callers of `kvm_vcpu_ioctl_x86_set_vcpu_events()` must hold `kvm->srcu`, and `kvm_arch_vcpu_put()` (when `vcpu->preempted` is set) must hold `srcu_read_lock(&vcpu->kvm->srcu)` around `kvm_steal_time_set_preempted()` (`copy_to_user_nofault()` when `current->mm == kvm->mm`) and `kvm_xen_runstate_set_preempted()`. [F161, F162, F175]
- In `vcpu_enter_guest()`, `local_irq_disable()` must precede `smp_store_release(&vcpu->mode, IN_GUEST_MODE)` and `get_debugctlmsr()`, and `kvm_vcpu_srcu_read_unlock()` + `smp_mb__after_srcu_read_unlock()` must precede `sync_pir_to_irr` and `kvm_vcpu_exit_request()`. On VM-Exit, `vcpu->mode = OUTSIDE_GUEST_MODE`, `smp_wmb()`, and `fpu_sync_guest_vmexit_xfd_state()` precede `handle_exit_irqoff` and `local_irq_enable()`; `this_cpu_write(x86_ibpb_exit_to_user, true)` precedes `preempt_enable()`, and `smp_mb__after_srcu_read_lock()` follows `kvm_vcpu_srcu_read_lock()`. [F33, F34, F165, F166]
- Post-init masterclock updates must block entry via `kvm_start_pvclock_update()` (`KVM_REQ_MCLOCK_INPROGRESS`), write under `pvclock_sc` and `tsc_write_lock` with IRQs disabled (also required for `__kvm_synchronize_tsc()`), and request `KVM_REQ_CLOCK_UPDATE` before clearing `KVM_REQ_MCLOCK_INPROGRESS` in `kvm_end_pvclock_update()`. In `kvm_get_wall_clock_epoch()` and `__get_kvmclock()`, `get_cpu_tsc_khz()` and host TSC reads must run under `get_cpu()`/`put_cpu()`, snapshotting `master_cycle_now` and `master_kernel_ns` inside the `pvclock_sc` loop. [F18, F19, F170]
- Guest `pvclock_vcpu_time_info` (`kvm_setup_guest_pvclock()`) and `kvm_steal_time` (`record_steal_time()`) updates must write an odd `version`, `smp_wmb()`, payload fields, and the incremented even `version` (after `smp_wmb()` for pvclock). In `kvm_setup_guest_pvclock()`, `gpc->khva` must only be accessed under `read_lock_irqsave(&gpc->lock, flags)` after `kvm_gpc_check()`, dropping `gpc->lock` before `kvm_gpc_refresh()` and re-validating in a loop. [F22, F174]
- `__kvm_set_or_clear_apicv_inhibit()` must write-lock `kvm->arch.apicv_update_lock` and call `kvm_make_all_cpus_request(kvm, KVM_REQ_APICV_UPDATE)` before updating `apicv_inhibit_reasons`, while `__kvm_vcpu_update_apicv()` read-locks `apicv_update_lock` with preemption disabled. `kvm->arch.apic_map` in `kvm_sched_yield()` requires `rcu_read_lock()`/`rcu_dereference()`, and `kvm->arch.msr_filter` requires `srcu_read_lock(&kvm->srcu)` on read and `rcu_replace_pointer()` under `kvm->lock` plus `synchronize_srcu(&kvm->srcu)` before freeing on update. [F36, F168, F173]
- VM ioctls checking `!kvm->created_vcpus` must hold `kvm->lock` across the check and state update, whereas `kvm_arch_suspend_notifier()` must not acquire `kvm->lock` around `kvm_for_each_vcpu()`. Asynchronous `kvm_inject_nmi()` must use `atomic_inc(&vcpu->arch.nmi_queued)` and `KVM_REQ_NMI` (drained via `atomic_xchg()` in `process_nmi()`), and `sync_regs()` must copy `vcpu->run->s.regs.sregs` and `events` to stack locals before validation. [F27, F39, F40, F100]

## Object Lifetimes
- `kvm_mmu_post_init_vm()` (spawning the NX hugepage `vhost_task`) must be deferred to `kvm_arch_vcpu_ioctl_run()` so `KVM_CREATE_VM` stays single-threaded. `kvm_arch_pre_destroy_vm()` must cancel `kvmclock_sync_work` and `kvmclock_update_work`, call `kvm_free_pit()`, and call `kvm_mmu_pre_destroy_vm()` before `kvm_arch_destroy_vm()` destroys vCPUs; internal memslots must only be uninstalled via `__x86_set_memory_region()` (under `kvm->slots_lock`) when `current->mm == kvm->mm`. [F1, F3, F8]
- In `kvm_alloc_memslot_metadata()` and `kvm_arch_free_memslot()`, `slot->arch.rmap` is indexed `0 .. KVM_NR_PAGE_SIZES - 1` while `lpage_info` is indexed `i - 1` for `i = 1 .. KVM_NR_PAGE_SIZES - 1`. On `KVM_MR_MOVE`, `new->arch` must be zeroed before allocation and `old` freed only in `kvm_arch_commit_memory_region()`, and `vfree()` in `memslot_rmap_free()` / `kvm_arch_free_memslot()` must immediately NULL each pointer. [F6, F7, F101]
- `kvm_on_user_return()` must check/clear `msrs->registered` and call `user_return_notifier_unregister()` under `local_irq_save()`. Buffers passed as `val`/`data` to `emulator_read_write()`, `emulator_read_write_onepage()`, `kvm_sev_es_mmio_read()`, and `kvm_sev_es_mmio_write()` must outlive a `KVM_EXIT_MMIO` return to userspace (never stack-allocated). [F17, F140]

## API Contracts
- `KVM_RUN` helpers (`vcpu_run`, `vcpu_enter_guest`, `vcpu_block`, `kvm_x86_vcpu_pre_run`, `complete_userspace_io`) return `1` to continue in-kernel, `0` to exit to userspace, and `< 0` on errno. MSR helpers (`__kvm_set_msr`, `__kvm_get_msr`, `kvm_do_msr_access`, `__kvm_emulate_wrmsr`, `emulator_get_msr_with_filter`) return `0` on success, `1` for `#GP`, `KVM_MSR_RET_UNSUPPORTED`, `KVM_MSR_RET_FILTERED`, or `< 0` to abort to userspace. [F42, F43]
- `kvm_access_xstate_msr()` asserts `vcpu->arch.guest_fpu.fpstate->in_use`, so host-side MSR paths outside `KVM_RUN` (`__msr_io()`, `kvm_get_set_one_reg()`) and all paths calling `kvm_vcpu_reset(vcpu, true)` (`kvm_xstate_reset()`) must have guest FPU loaded via `kvm_load_guest_fpu()`/`kvm_put_guest_fpu()`. [F11, F12]
- Guest XCR writes must use `__kvm_set_xcr()`, and changes to dynamic XSTATE or MWAIT bits in `xcr0` (`XFEATURE_MASK_EXTEND`), `ia32_xss`, or `ia32_misc_enable_msr` (`MSR_IA32_MISC_ENABLE_MWAIT`) must set `cpuid_dynamic_bits_dirty = true`. In `do_set_msr()`, post-`KVM_RUN` writes to immutable MSRs matching `do_get_msr()` must fall through to `kvm_set_msr_ignored_check()`, and `MSR_IA32_PERF_CAPABILITIES` must skip `kvm_pmu_refresh()` if unchanged. [F70, F80, F109]

## Error Handling
- In `vcpu_enter_guest()`, any pre-entry abort after `kvm_check_and_inject_events()` succeeds must jump to `cancel_injection:` to roll back hardware-injected events, and `-EBUSY` in `kvm_check_and_inject_events()` must be converted to `*req_immediate_exit = true; r = 0`. Fastpath exit handlers (`handle_fastpath_invd`, `__handle_fastpath_wrmsr`, `handle_fastpath_hlt`) must return `EXIT_FASTPATH_EXIT_USERSPACE` when `kvm_skip_emulated_instruction()` returns `0`. [F10, F41, F44]
- In `x86_emulate_instruction()`, a decode exception (`ctxt->have_exception`) on `x86_decode_emulated_instruction()` failure must only be injected if `!(emulation_type & EMULTYPE_SKIP)`. In `kvm_do_msr_access()` (which, along with `__msr_io()` and `is_xstate_managed_msr()`, must tolerate `vcpu == NULL`), failed reads (`rw == MSR_TYPE_R`) must zero `*data` before checking `kvm_is_advertised_msr()` or `ignore_msrs`. [F49, F52, F108]
- `KVM_CREATE_IRQCHIP` must initialize PIC, IOAPIC, and default routing under `kvm->lock` before setting `irqchip_mode = KVM_IRQCHIP_KERNEL`, destroying created objects on error. In `kvm_arch_vcpu_ioctl()`, `memdup_user()` errors on union `u` must jump to `out_nofree` or NULL `u.buffer` before `kfree(u.buffer)`. `kvm_read_guest_virt()` and userspace exit/PV struct builders must zero `*exception`, padding, and unpopulated stack/PIO buffers. [F15, F50, F54, F182]

## External Contracts
- Guest/user array indices in `kvm_sched_yield()`, `kvm_set_dr()`, `kvm_get_dr()`, `set_msr_mce()`, `get_msr_mce()`, and `kvm_vcpu_ioctl_x86_set_mce()` must be bounds-checked (MCE banks against runtime `vcpu->arch.mcg_cap & 0xff`, with 4 `u64`s per bank in `mce_banks`) and clamped with `array_index_nospec()`. SSP MSR writes in `__kvm_set_msr()` must reject non-canonical addresses and require `IS_ALIGNED(data, 4)` for all except `MSR_IA32_INT_SSP_TAB`. [F81, F82, F181]
- `KVM_GET_XSAVE` must reject `uabi_size > sizeof(struct kvm_xsave)`; `kvm_vcpu_ioctl_x86_get_xsave2()` masks to `guest_supported_xcr0 | XFEATURE_MASK_FPSSE` while `kvm_vcpu_ioctl_x86_set_xsave()` validates against `kvm_caps.supported_xcr0`. In `____kvm_emulate_hypercall()`, when `!is_64_bit_hypercall(vcpu)`, mask `nr` and `a0`..`a3` to 32 bits (and truncate `ret` to `u32` in `complete_hypercall_exit()`); `KVM_HC_MAP_GPA_RANGE` must reject unaligned `gpa`, `!npages`, or GFN overflow, and `run->hypercall.ret` must be `0` before `KVM_EXIT_HYPERCALL`. [F87, F98, F99, F146, F186]

## Known Pitfalls
- `kvm_sync_valid_fields()` must return `u64` (not `u32`) so `~sync_valid_fields` covers all 64 bits; `kvm_is_vm_type_supported()` and `exception_type()` must bound shift counts (`< 32` / `<= 31`); `dbgregs->db` (`__u64[4]`) and `vcpu->arch.db` (`unsigned long[4]`) must be copied in a per-element loop rather than `memcpy()`; 32-bit builds require `do_div()`/`mul_u64_u32_div()` for `u64` division and `(u32)addr` truncation on page-crossing accesses in `emulator_read_write()` when `ctxt->mode != X86EMUL_MODE_PROT64`. [F86, F96, F126, F133, F135]
- In `kvm_get_msr_common()`, `host_initiated` reads of `MSR_IA32_TSC` must use `l1_tsc_offset` and `l1_tsc_scaling_ratio` (guest reads use active `tsc_offset`/`tsc_scaling_ratio`). `kvm_calc_nested_tsc_offset()` must use signed `mul_s64_u64_shr()` on `(s64)l1_offset`, `kvm_arch_vcpu_load()` must check backwards TSC via signed `s64 tsc_delta = rdtsc() - last_host_tsc < 0`, and `kvm_synchronize_tsc()` must check `data + tsc_hz > tsc_exp` rather than subtracting `tsc_hz`. [F122, F128, F136, F138]
- `kvm_vcpu_check_code_breakpoint()` must check host `guest_debug_dr7`/`eff_db` (`KVM_EXIT_DEBUG`) before guest `dr7`/`db` (`DB_VECTOR`). `kvm_inject_exception()` must mask `has_error_code &= is_protmode(vcpu)` rather than clearing `error_code`. Bitmask-validated MSR writes in `kvm_set_msr_common()` must store `data` unconditionally after checking `data & ~SUPPORTED_MASK` so writing `0` clears bits, and `emulator_cmpxchg_emulated()` must fall back to `emulator_write_emulated()` on cache-line splits when `X86_FEATURE_SPLIT_LOCK_DETECT` is present. [F104, F120, F123, F176]
