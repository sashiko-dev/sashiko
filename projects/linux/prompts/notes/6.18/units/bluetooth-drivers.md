# BLUETOOTH DRIVERS

Implements Bluetooth host controller transport drivers for USB (`btusb`), SDIO (`btsdio`, `btmtksdio`), PCMCIA (`dtl1_cs`), RSI coexistence (`btrsi`), UART line discipline (`hci_ldisc`), Serdev (`hci_serdev`), UART protocols (H4, BCSP, H5, Intel, TI HCILL, Marvell, Nokia, Broadcom, Atheros, AG6xx), virtual HCI (`hci_vhci`), and Virtio (`virtio_bt`), plus shared vendor libraries for MediaTek (`btmtk`), Qualcomm (`btqca`), and Realtek (`btrtl`).

## Architecture & Data Flow

- In `btusb.c`, `data->isoc` and `data->diag` can be `NULL`; always check first. When `btusb_switch_alt_setting()` changes `data->isoc_altsetting`, it must kill `isoc_anchor`, free/NULL `data->sco_skb` under `data->rxlock`, and call `__set_isoc_interface()` to re-resolve `isoc_tx_ep`/`isoc_rx_ep`. When `data->sco_num` drops to 0 in `btusb_work()`, it must kill `isoc_anchor`, clear `BTUSB_ISOC_RUNNING`, reset to altsetting 0, and clear `BTUSB_DID_ISO_RESUME` with `usb_autopm_put_interface()`. [F50, F55, F56]
- In USB packet reassembly (`btusb_recv_intr()`, `btusb_recv_bulk()`, `btusb_recv_isoc()`, `btmtk_recv_isopkt()`), once the HCI header is complete, check `skb_tailroom(skb) < hci_skb_expect(skb)` and free `skb` with `-EILSEQ` if exceeded; `btusb_recv_isoc()` must also validate new SCO headers via `btusb_validate_sco_handle()` (unless `HCI_USER_CHANNEL` is set). [F94, F180]
- `btrtl_initialize()` returns a valid `struct btrtl_device_info *` with `btrtl_dev->ic_info == NULL` when the chip is unmatched in `ic_id_table`; `btrtl_download_firmware()`, `btrtl_set_quirks()`, and `btrtl_setup_realtek()` must check `btrtl_dev->ic_info` for `NULL` before dereferencing. [F42]
- In `btqca.c`, `qca_download_firmware()` must copy `fw->data` into a writable `vmalloc()` buffer before calling `qca_tlv_check_data()`, which mutates `TLV_TYPE_NVM` bytes in place, bounds-checks each `tlv_type_nvm` entry, and sets both `config->dnld_mode` and `config->dnld_type` (since `qca_download_firmware()` overwrites `dnld_mode` on the last segment and checks `dnld_type` for `qca_inject_cmd_complete_event()`). [F69, F70, F82]
- Before `handle_dump_pkt_qca()` pulls headers, validate the packet on a cloned `skb` via `skb_pull_data()` in `acl_pkt_is_dump_qca()`/`evt_pkt_is_dump_qca()`. `handle_dump_pkt_qca()` pulls `offsetof(struct qca_dump_hdr, data0)` when `seqno == 0` vs `offsetof(..., data)` when `seqno > 0`, sets `BTUSB_HW_SSR_ACTIVE` and disables autosuspend on `seqno == 0`, and at `out:` re-enables autosuspend, zeroes `ram_dump_size`/`ram_dump_seqno`, and clears `BTUSB_HW_SSR_ACTIVE`. Coredump ACL packets (`0xfc6f`) in `btmtk`/`btmtksdio` also disable runtime autosuspend. [F61, F95, F156, F177]
- In `btmtksdio.c`, `close`, `remove`, and suspend/resume callbacks must verify `BTMTKSDIO_FUNC_ENABLED` before accessing the SDIO function. `btmtksdio_reset()` sets `BTMTKSDIO_HW_RESET_ACTIVE`, so `btmtksdio_shutdown()` must skip WMT commands while set, and `btmtksdio_setup()` must clear `BT_DL_STATE` in `MT7921_DLSTATUS` and `BTMTKSDIO_HW_RESET_ACTIVE`. [F64, F65]
- A `struct hci_uart` runs in either Serdev mode (`hu->serdev != NULL`) or TTY ldisc mode (`hu->tty != NULL`); shared helpers and dual-mode protocols (`h5`, `ll`, `mrvl`) must test `hu->serdev` first. Because `hci_uart_close()` clears `hdev->flush = NULL`, `hci_uart_open()` must restore `hdev->flush = hci_uart_flush`. [F215, F238]
- In `hci_bcsp.c` and `hci_h5.c`, `unack`, `rel`, `msgq_txseq`/`tx_seq` (modulo-8, `& 0x07`), and `tbcsp`/`h5->timer` update in lockstep under `unack.lock`: dequeue increments `tx_seq`, queues to `unack`, and arms the timer; timeout moves `skb`s from `unack` tail (`__skb_dequeue_tail`) to `rel` head (`skb_queue_head`) while decrementing `(seq - 1) & 0x07`; `pkt_cull` walks backward by `(seq - 1) & 0x07` at most `skb_queue_len(&unack)` times and stops the timer when empty. `enqueue` rejects `skb->len > 0xfff`, and RX `skb`s must be `>= 0x1005`. [F230, F231, F250, F252, F253, F267, F276]

## Synchronization

- In `btusb.c`, `data->rxlock` (`spin_lock_irqsave`) protects `evt_skb`, `acl_skb`, and `sco_skb` (and `isorxlock` protects `isopkt_skb` in `btmtk.c`); set them to `NULL` under lock when freed or handed off, and free via `dev_kfree_skb_irq()` (never `kfree_skb()`) in `btusb_free_frags()` and `btusb_switch_alt_setting()`. Because `btusb_recv_intr()`/`btusb_recv_bulk()` invoke `recv_event`/`recv_acl` under `data->rxlock` in URB completion context, those callbacks and their callees must not sleep and must use `GFP_ATOMIC`. [F8, F31, F157, F158]
- In `btusb.c`, `data->txlock` (`spin_lock_irqsave`/`spin_lock_irq`) protects `BTUSB_SUSPENDING` and `data->tx_in_flight` across `submit_or_queue_tx_urb()`, `play_deferred()`, `btusb_tx_complete()`, and `btusb_suspend()`/`btusb_resume()`. `btusb_suspend()`/`btusb_resume()` gate transitions on `data->suspend_count`, and `btusb_suspend()` must decrement `suspend_count` if it aborts autosuspend due to `tx_in_flight`. [F57, F58, F159]
- In `btmtk_usb_hci_wmt_sync()`, `wait_on_bit_timeout()` on `BTMTK_TX_WAIT_VND_EVT` must use `TASK_UNINTERRUPTIBLE`. When waking `BTMTK_TX_WAIT_VND_EVT` (`btmtk_usb_wmt_recv`), `BTMTKSDIO_TX_WAIT_VND_EVT` (`btmtksdio_recv_event`), or `STATE_FW_REQ_PENDING`/`STATE_CHIP_VER_PENDING` (`mrvl_recv_fw_req`/`mrvl_recv_chip_ver`), store the result (`evt_skb`, `tx_len`, `id`/`rev`) before clearing the bit and call `smp_mb__after_atomic()` before `wake_up_bit()`. [F22, F166, F207, F312]
- In `hci_ldisc.c`, `hci_uart_set_proto()` sets `HCI_UART_PROTO_INIT` before `hci_uart_register_dev()` and `HCI_UART_PROTO_READY` only after it succeeds. `hci_uart_tx_wakeup()` uses `percpu_down_read_trylock(&hu->proto_lock)`, so `percpu_down_write(&hu->proto_lock)` must only be acquired in `hci_uart_tty_close()` to clear `HCI_UART_PROTO_READY` and released before `cancel_work_sync(&hu->write_work)` or `hci_unregister_dev()`. [F199, F200, F303]
- `hci_bcsp.c` and `hci_h5.c` must acquire `unack.lock` before `rel.lock` (`SINGLE_DEPTH_NESTING`), and `bcsp_prepare_pkt()`/`h5_prepare_pkt()` as well as UART RX paths (`h4_recv_buf()`, `bcsp_recv()`, `h5_recv()`) must allocate SKBs with `GFP_ATOMIC` and never sleep. [F203, F307, F311]
- In `hci_bcm.c`, hold `bcm_device_lock` when accessing `bcm_device_list`, `bcm_device_exists()`, or a non-serdev `bcm->dev` or `bdev->hu`. In `hci_intel.c`, `idev->hu_lock` nests inside `intel_device_list_lock`; `intel_suspend_device()`/`intel_resume_device()` must only acquire `idev->hu_lock`, and `intel_irq()` must be a threaded IRQ (`IRQF_ONESHOT`, `handler == NULL`). [F38, F242, F309, F310]
- In `hci_vhci.c`, `data->open_mutex` serializes `vhci_create_device()`/`__vhci_create_device()`, must never be acquired in `hdev` callbacks (which hold `hdev->req_lock`), and `cancel_delayed_work_sync(&data->open_timeout)` must be called outside `data->open_mutex`. [F209, F246, F313]

## Object Lifetimes

- `hci_devcd_append()` consumes and may immediately free `skb` even on error; callers (`btmtk_process_coredump()`, `handle_dump_pkt_qca()`) must read all `skb->data`/`skb->len` fields before calling it, and `btmtk_process_coredump()` unconditionally consumes `skb`. In `btmtk_usb_recv_acl()` (`case 0xfc6f`), pass `skb_clone(skb, GFP_ATOMIC)` to `btmtk_process_coredump()` and fall through so the original `skb` reaches `hci_recv_diag()`. [F1, F2, F108]
- `hdev->send` callbacks (`btusb`, `btsdio`, `btmtksdio`, `dtl1`, `btrsi`) must NOT free `skb` when returning a negative error because the caller frees it; conversely, `hci_uart_send_frame()` ignores `hu->proto->enqueue(hu, skb)`'s return value and returns 0, so `enqueue` must queue or `kfree_skb(skb)` on all paths. In `btsdio_tx_packet()`/`btmtksdio_tx_packet()`, on `sdio_writesb()` failure after `skb_push()`, strip the header with `skb_pull()` and do not free `skb` (the worker requeues it). [F11, F174, F322]
- `h4_recv_buf()` frees any partial `skb` before returning `ERR_PTR()` and ignores `pkts[i].recv()` return values; callers storing the result in `rx_skb` must check `IS_ERR(rx_skb)` and reset `rx_skb = NULL` without calling `kfree_skb()`, and every `h4_recv_pkt.recv` callback must consume or free `skb`. [F213, F323]
- `btrtl_initialize()` returns an owned `struct btrtl_device_info *` (or `ERR_PTR`) that callers must release via `btrtl_free()` (never `kfree()`). Because `btrtl_parse_section()` stores borrowed pointers `subsec->data` into `btrtl_dev->fw_data`, `fw_data` must outlive `rtlbt_parse_firmware_v2()` and `btrtl_free()` must only free `entry` (not `entry->data`). [F5, F6, F109]
- In `btusb.c`, TX URBs store `skb` in `urb->context`, `(void *)hdev` in `skb->dev`, and a `kmalloc`'d `setup_packet` on control URBs; `kfree(urb->setup_packet)` must run on every failure or completion (`btusb_tx_complete()`, `btusb_isoc_tx_complete()`). Resources on `&data->udev->dev` (`reset_gpio`, wakeup) must be cleaned up manually, and `btusb_disconnect()` must clear `intfdata` on `intf`, `isoc`, and `diag` before `hci_unregister_dev()` and release only claimed interfaces other than the disconnecting `intf`. [F10, F128, F137, F138]
- In `btmtk.c` and `btmtksdio.c`, whenever `evt_skb` is freed via `kfree_skb()`, immediately set `evt_skb = NULL`. In `btmtk_usb_hci_wmt_sync()` and `btmtk_usb_shutdown()`, balance `usb_autopm_get_interface(data->intf)` with `usb_autopm_put_interface(data->intf)` on all paths. [F7, F152]
- In `hci_ldisc.c` and `hci_serdev.c`, `cancel_work_sync(&hu->init_ready)` and `cancel_work_sync(&hu->write_work)` must complete before checking `HCI_UART_REGISTERED` to unregister/free `hu->hdev` or calling `hu->proto->close(hu)`. `serdev_device_close(hu->serdev)` is gated on clearing `HCI_UART_PROTO_READY`. `bcsp_close()`/`h5_close()` must synchronously stop their timers before purging queues, and `h5_close()` must only `kfree(h5)` when `!hu->serdev`. [F189, F190, F191, F192, F289, F314]
- `vhci_release()` must drain `open_timeout` and `suspend_work` and call `vhci_debugfs_remove(hdev)` (when `!IS_ERR_OR_NULL(hdev->debugfs)`) before unregistering/freeing `hdev` and `data`. `virtbt_probe()` must register `vbt->hdev` before `virtio_device_ready()`, `virtbt_rx_done()` must defer `GFP_KERNEL` refill to `virtbt_rx_work()`, and `virtbt_remove()` must call `virtio_reset_device()` and `virtbt_close_vdev()` before detaching buffers or freeing `hdev`. [F211, F212, F228, F315]

## API Contracts

- `hci_set_drvdata(hdev, hu)` is reserved for `struct hci_uart *hu` in `hci_ldisc`, `hci_serdev`, and `h4_recv_buf()`; protocols must use `hu->priv` or `hci_get_priv(hdev)`. Any driver or `struct h5_vnd` entry calling `btrtl_*`/`btrealtek_*` or `btmtk_*` helpers must allocate `hdev` with `sizeof(struct btrealtek_data)` or `sizeof(struct btmtk_data)` via `hci_alloc_dev_priv()` / `hci_uart_register_device_priv()`. [F126, F127, F281, F282]
- Serdev drivers using `hci_uart_register_device_priv()` (`struct bcm_device`, `struct h5`) must embed `struct hci_uart` as the first member of drvdata and set `hu->serdev` before registering. Because `hci_uart_register_device_priv()` calls `p->open(hu)` before allocating `hu->hdev`, serdev-capable `open()` callbacks must not dereference `hu->hdev`. [F73, F286, F287]
- `hci_uart_set_flow_control(hu, enable)` has inverted semantics: `enable == true` throttles the peer (disables flow control/RTS) and `false` unthrottles it; TTY ldisc protocols calling it (`intel_proto`, `mrvl_proto_8897`) must check `hci_uart_has_flow_control(hu)` in `open()`. [F217, F318]
- TX URB allocation helpers (`alloc_ctrl_urb`, `alloc_bulk_urb`, `alloc_isoc_urb`, `alloc_diag_urb`, `alloc_mtk_intr_urb`) return `ERR_PTR(-errno)`, never `NULL`; callers must check `IS_ERR(urb)`. In `alloc_mtk_intr_urb()`, outgoing ISO packets must have `skb->len <= MTK_ISO_THRESHOLD` (264) and call `btmtk_isopkt_pad()` before `usb_fill_int_urb()` captures `skb->data`/`skb->len`. [F49, F129, F181]
- Buffers passed to `usb_control_msg()`/`usb_bulk_msg()` in `btusb.c`/`btmtk.c` must be `kmalloc`/`kzalloc`-allocated, never stack or `const` firmware pointers. RX URB submissions in `btusb_resume()`/`btmtk_usb_resume()` must use `GFP_NOIO`. `btusb_suspend()` must only return `-EBUSY` when `PMSG_IS_AUTO(message)` is true. [F54, F160, F163]
- Vendor coredump triggers (`btusb_coredump_qca`, `btmtk_coredump`, `btrtl_coredump`) must use `__hci_cmd_send()` (never `__hci_cmd_sync()`). When a command suppresses `HCI_EV_CMD_COMPLETE` (QCA firmware download with `QCA_SKIP_EVT_VSE*`, or `BTINTEL_HCI_OP_RESET`), inject a synthetic `HCI_EV_CMD_COMPLETE` via `hci_recv_frame()`. [F172, F173]
- Every function declared under `#if IS_ENABLED(CONFIG_BT_MTK/QCA/RTL)` in `btmtk.h`, `btqca.h`, and `btrtl.h` must have a matching `#else` stub returning `-EOPNOTSUPP` or `ERR_PTR(-EOPNOTSUPP)`. `hdev->quirk_flags` and `realtek->flags` are `DECLARE_BITMAP`s and must use `hci_*_quirk()` / `btrealtek_*_flag()`. [F78, F132]

## Error Handling

- In `btrtl_initialize()` (returns `ERR_PTR(ret)`) and `btqca.c` helpers that initialize `err = 0` and jump to `out:` (`qca_read_soc_version`, `qca_read_fw_build_info`, `qca_read_fw_board_id`, `qca_tlv_send_segment`), every error branch before `goto` must set a negative errno (including `ret = -EINVAL` when `cfg_len == 0` with `config_needed`). In `qca_download_firmware()`, all error paths after `vmalloc()` must `goto out` to `vfree(data)`. [F4, F41, F43]
- In `btmtk_usb_hci_wmt_sync()` and `mtk_hci_wmt_sync()`, `wait_on_bit_timeout()` returns positive (`1`) on timeout, so any non-zero non-`-EINTR` return must clear the wait bit and set `err = -ETIMEDOUT`. When polling `btmtk_usb_func_query()`/`btmtksdio_func_query()` via `readx_poll_timeout()`, check both `err < 0` and signed `status < 0`. [F47, F48]
- Coredump registration (`hci_devcd_register()`, `btmtk_register_coredump()`) returns `-EOPNOTSUPP` when `CONFIG_DEV_COREDUMP` is disabled and must not abort probe/setup. In `intel_setup()`, `btintel_download_firmware()` returning `-EALREADY` is not an error, and when `ver.fw_variant == 0x23` on entry, return early before calling bootloader-only `btintel_read_boot_params()`. [F45, F220, F296]

## External Contracts

- In `btqca.c`, controllers with `soc_type >= QCA_WCN3991` (plus `qca_read_fw_build_info`, `qca_send_patch_config_cmd`, `qca_read_fw_board_id`) return EDL responses in `HCI_EV_CMD_COMPLETE`, so pass `event = 0` (not `HCI_EV_VENDOR`) to `__hci_cmd_sync_ev()`, and on `soc_type >= QCA_WCN3991` read `qca_btsoc_version` at `edl->data + 1` with no `tlv_seg_resp`. `qca_set_bdaddr()`, `hci_ti_probe()`, and `ll_set_bdaddr()` must `baswap()` `bdaddr_t`, whereas `qca_set_bdaddr_rome()` and `btusb_set_bdaddr_wcn6855()` use native little-endian. [F44, F83, F84, F264]

## Known Pitfalls

- `btusb_reset()` and vendor `hdev->reset` callbacks (`btusb_intel_reset`, `btusb_rtl_reset`, `btusb_qca_reset`) must reset via `usb_queue_reset_device(data->intf)` or GPIO and never call `hdev->reset(hdev)`. [F105]
- In `handle_dump_pkt_qca()`, `QCA_LAST_SEQUENCE_NUM` (`0xffff`) is a sentinel, so the missing-packet gap calculation must guard against `seqno == QCA_LAST_SEQUENCE_NUM`. In `qca_read_fw_build_info()`, copy `&edl->data[1]` with `kstrndup()` after checking `skb->len`. In `qca_tlv_check_data()` for `TLV_TYPE_NVM`, bounds-check using `length + (tlv->data - fw_data)` to account for nested type-4 headers. [F120, F130, F131]
- In `btrsi.c`, `rsi_hci_send_pkt()` must preserve `bt_cb(new_skb)->pkt_type` across `skb_realloc_headroom()`, and when aligning `skb->data` to `RSI_DMA_ALIGN`, sample `skb->data`/`skb->len` before `skb_push()`/`skb_pull()` and use `memmove()` (not `memcpy()`). [F72, F123]
