# PAGE CACHE

The PAGE CACHE unit implements the core Linux `address_space` page cache, managing folio indexing in XArrays, buffered/direct file reads and writes, memory-mapped page faults, file readahead, truncation/invalidation, and dirty page writeback throttling.

## Architecture & Data Flow
- When removing a folio from `mapping->i_pages` or rolling back a failed insertion in `page_cache_delete()`, `page_cache_delete_batch()`, and `__filemap_add_folio()`, `folio->mapping` must be set to `NULL` while `folio->index` is left intact because concurrent truncation and invalidation batch walks rely on `folio->index`. [F2]
- `folio_clear_dirty_for_io()` clears `PG_dirty` and decrements `NR_FILE_DIRTY`, `NR_ZONE_WRITE_PENDING`, and `WB_RECLAIMABLE`, but leaves `PAGECACHE_TAG_DIRTY` and `PAGECACHE_TAG_TOWRITE` set in `mapping->i_pages`; before unlocking the folio, callers must either call `__folio_start_writeback()` or redirty via `folio_redirty_for_writepage()`, which calls `filemap_dirty_folio()` and subtracts `folio_nr_pages(folio)` from `current->nr_dirtied`, `NR_DIRTIED`, and `WB_DIRTIED`. [F17, F176]
- In both `folio_clear_dirty_for_io()` and `pagecache_isize_extended()`, if `folio_mkclean(folio)` returns non-zero on a locked folio, `folio_mark_dirty(folio)` must be called immediately so `a_ops->dirty_folio` records dirty PTE state in the filesystem before `PG_dirty` is cleared or `i_size` extension completes. [F177]
- Under `i_pages` lock, `__folio_start_writeback()` must check `mapping_tagged(mapping, PAGECACHE_TAG_WRITEBACK)` before setting that mark to call `wb_inode_writeback_start()` and `sb_mark_inode_writeback()`, whereas `__folio_end_writeback()` must check it after clearing the mark to call `wb_inode_writeback_end()` and `sb_clear_inode_writeback()`. [F79]
- `folio_unmap_invalidate()` must unmap the locked folio (`unmap_mapping_folio()`), run `folio_launder()`, and call `filemap_release_folio()` before checking `folio_test_dirty(folio)` under `xa_lock_irq(&mapping->i_pages)`, returning `-EBUSY` if the folio is still dirty under the lock. [F172]
- Page cache counters (`mapping->nrpages`, `__lruvec_stat_mod_folio()`, `wb_stat_mod()`, `wbc->nr_to_write`) and folio ref transfers (`folio_ref_add()`, `folio_put_refs()`) scale by `folio_nr_pages(folio)`, whereas `task_io_account_write()` and `task_io_account_cancelled_write()` require `nr * PAGE_SIZE` bytes. [F134]
- In `filemap_fault()` and `next_uptodate_folio()` (and `file_end` in `filemap_map_pages()`), converting `i_size_read(inode)` to an exclusive upper page-index bound requires ceiling division `DIV_ROUND_UP(i_size_read(inode), PAGE_SIZE)` so a final partial page straddling EOF remains mappable; `filemap_fault()` must check `vmf->pgoff >= max_idx` both on entry and after locking the folio (unlocking and releasing it to return `VM_FAULT_SIGBUS`). [F99, F129]

## Synchronization
- Lockless RCU page-cache lookups (`filemap_get_entry()`, `find_get_entry()`, `next_uptodate_folio()`, `filemap_get_folios_contig()`, `filemap_get_read_batch()`) must pin the folio with `folio_try_get(folio)` before checking `PF_NO_TAIL` flags like `folio_test_locked()` and must verify `folio == xas_reload(xas)` before using it. After acquiring `folio_lock()` or `folio_trylock()` on a looked-up folio (`__filemap_get_folio()`, `find_lock_entries()`, `filemap_fault()`, `filemap_page_mkwrite()`, `folio_prepare_writeback()`), callers must recheck `folio->mapping == mapping` to detect concurrent truncation. [F40, F42]
- Acquisitions of `mapping->i_pages` lock must disable local interrupts (`xa_lock_irq()`, `xas_lock_irq()`, `xa_lock_irqsave()`, or `xas_lock_irqsave()`). In `__folio_mark_dirty()`, `__folio_start_writeback()`, and `__folio_end_writeback()`, calls to `inode_to_wb()` and updates to `PAGECACHE_TAG_DIRTY`, `PAGECACHE_TAG_WRITEBACK`, and `PAGECACHE_TAG_TOWRITE` marks must occur inside `xa_lock_irqsave(&mapping->i_pages, flags)` (or `xas_lock_irqsave()`). [F32, F152]
- When deleting entries from `mapping->i_pages` in `filemap_remove_folio()`, `delete_from_page_cache_batch()`, `folio_unmap_invalidate()`, or `clear_shadow_entries()`, `mapping->host->i_lock` must be held outside `xa_lock_irq(&mapping->i_pages)` and across `mapping_shrinkable()` and `inode_add_lru()`. [F30]
- Whenever an `xa_state` traversal over `mapping->i_pages` drops `rcu_read_lock()` or `xas_lock_irq()` or yields the CPU (`folio_seek_hole_data()`, `filemap_cachestat()`, `tag_pages_for_writeback()`), `xas_pause(&xas)` must be called first; in `mapping_seek_hole_data()`, `xas_set(&xas, pos >> PAGE_SHIFT)` must also be called when `seek_size > PAGE_SIZE` so the next `find_get_entry()` does not re-visit the same large folio. [F116, F162]
- Waitqueue bucket locks (`q->lock`) in `folio_wait_table` must be acquired with local interrupts disabled (`spin_lock_irq()` or `spin_lock_irqsave()`), and `folio_unlock()` / `folio_end_read()` must not be called from NMI context. In `folio_wait_bit_common()` and `__folio_lock_async()`, calling `folio_set_waiters(folio)`, retesting the target bit, and waitqueue insertion must all occur under `spin_lock_irq(&q->lock)`. [F34, F154]
- When `__filemap_get_folio()` returns a folio and `!(fgp_flags & FGP_DONTCACHE)`, it must clear `PG_dropbehind` via `folio_clear_dropbehind(folio)`. Because `folio_end_writeback()` may run in interrupt context, `folio_end_dropbehind()` must check `in_task() && folio_trylock(folio)` before calling `filemap_end_dropbehind()`, where invalidation via `folio_unmap_invalidate()` must be gated under the folio lock on `!folio_test_writeback(folio) && !folio_test_dirty(folio)`, `folio_test_clear_dropbehind(folio)`, and `folio->mapping != NULL`. [F43, F84, F150]
- In `filemap_fault()`, whenever `maybe_unlock_mmap_for_io()` returns a non-NULL `fpin`, `filemap_fault()` must unlock `folio` (if locked) and jump to `out_retry:` to release `folio` (guarded by `if (!IS_ERR(folio))`), `mapping->invalidate_lock` (if `mapping_locked`), and `fpin` via `fput(fpin)` before returning `VM_FAULT_RETRY`. In `filemap_fault_recheck_pte_none()`, `pte_offset_map_ro_nolock(vma->vm_mm, vmf->pmd, vmf->address, &vmf->ptl)` must be used to refresh `vmf->ptl` before taking `spin_lock(vmf->ptl)`. [F13, F63, F82]
- Because taking a page fault while holding a locked folio and filesystem locks inside `write_begin` can deadlock, `generic_perform_write()` must use `copy_folio_from_iter_atomic()` between `a_ops->write_begin` and `a_ops->write_end` and call `fault_in_iov_iter_readable()` only after `write_end` unlocks the folio. Similarly, in `invalidate_inode_pages2_range()`, range-wide unmapping via `unmap_mapping_pages()` must be performed before acquiring `folio_lock(folio)`. [F38, F39]
- In `page_cache_ra_unbounded()` and `page_cache_ra_order()`, `memalloc_nofs_save()` and `filemap_invalidate_lock_shared(mapping)` must be held across folio allocation, insertion, and `read_pages(ractl)`. Multiple folios in the same `address_space` must be locked in ascending `folio->index` order, so `writeback_iter()` must not wrap `wbc->index` back to `0` within the same `range_cyclic` iteration, and only resets `mapping->writeback_index = 0` when `writeback_get_folio()` returns `NULL`. [F24, F158]
- In `truncate_inode_pages_final()`, `mapping_set_exiting(mapping)` must be called and, if `!mapping_empty(mapping)`, `xa_lock_irq(&mapping->i_pages)` must be cycled before `truncate_inode_pages()` so concurrent page reclaim sees `AS_EXITING` and does not install shadow entries after final truncate begins. [F27]

## Object Lifetimes
- Before `__filemap_add_folio()` stores a folio into `mapping->i_pages` under `xas_lock_irq()`, `filemap_add_folio()` locks it (`PG_locked`) and charges it to memcg, and `__filemap_add_folio()` initializes `folio->mapping` and `folio->index` and adds `folio_nr_pages(folio)` references; on failure, `filemap_add_folio()` uncharges memcg and unlocks the folio without dropping the caller's reference, so callers must call `folio_put(folio)`. [F1, F25]
- `filemap_remove_folio()` and `delete_from_page_cache_batch()` drop the pagecache's `folio_nr_pages(folio)` references via `filemap_free_folio()`, so callers must hold both the folio lock (`PG_locked`) and their own reference on each folio across the call before unlocking it. [F3]
- `folio_attach_private()` calls `folio_get()`, sets `folio->private`, and sets `PG_private`, whereas `folio_detach_private()` clears `PG_private`, zeroes `folio->private`, and calls `folio_put()` (which must happen before removing the folio in `folio_unmap_invalidate()`). Similarly, `folio_end_private_2()` clears `PG_private_2`, wakes waiters, and consumes the dedicated folio reference held for `PG_private_2` via `folio_put(folio)`. [F6, F7]
- Because writeback holds no folio reference and truncation only waits for `PG_writeback` to clear, `folio_end_writeback()` must pin `folio` with `folio_get(folio)` before calling `folio_end_writeback_no_dropbehind(folio)` and `folio_end_dropbehind(folio)`, and release it with `folio_put(folio)` afterwards. [F8]
- `folio_put_wait_locked()` (via `folio_wait_bit_common()` with `behavior == DROP`) enqueues the waitqueue entry under `q->lock` and drops the caller's folio reference before sleeping, so neither `folio_wait_bit_common()` nor its callers may dereference `folio` or call `folio_put(folio)` afterwards. [F9, F115]
- In `filemap_cachestat()`, because the RCU XArray walk does not pin folios with `folio_try_get()`, the `folio` pointer must never be dereferenced; all stats must be derived from XArray state (`xas_get_order()`, `xa_is_value()`, `xas_get_mark()`), `mem_cgroup_flush_stats_ratelimited()` must be called before `rcu_read_lock()`, and `workingset_test_recent()` must be called with `flush = false` (after checking `!non_swap_entry(swp)` and `shadow != NULL` on `shmem_mapping(mapping)` value entries). [F41, F53, F147]
- In `truncate_cleanup_folio()`, `folio_cancel_dirty(folio)` must be called after `folio_invalidate(folio, 0, folio_size(folio))` because filesystem `->invalidate_folio` callbacks may re-dirty the folio during invalidation before `filemap_remove_folio()` checks for dirty folios. [F22]

## API Contracts
- `__filemap_get_folio()`, `filemap_get_folio()`, `filemap_lock_folio()`, `filemap_grab_folio()`, and `do_read_cache_folio()` return an `ERR_PTR` (e.g., `ERR_PTR(-ENOENT)`) and never `NULL`, whereas `filemap_get_entry()` and `filemap_alloc_folio()` return `NULL` on miss or failure. When `__filemap_get_folio()` creates a new folio (`FGP_CREAT`) with `FGP_FOR_MMAP` set, it must unlock the folio via `folio_unlock(folio)` before returning; if `FGP_CREAT` fails with `-ENOMEM` while `FGP_NOWAIT` is set, it must return `ERR_PTR(-EAGAIN)` rather than `ERR_PTR(-ENOMEM)`. [F21, F47, F48]
- `replace_page_cache_folio(old, new)` requires both `old` and `new` to be locked with `new->mapping == NULL`, atomically transfers the pagecache reference and memcg charge from `old` to `new` (calling `a_ops->free_folio(old)` and `folio_put(old)`), and leaves adding `new` to the LRU (`folio_add_lru()`) to the caller. [F5]
- `__filemap_add_folio()` and `filemap_add_folio()` require `folio_order(folio) >= mapping_min_folio_order(mapping)` and `index` naturally aligned to `folio_nr_pages(folio)` (`mapping_align_index()`). `fgf_set_order()` and `filemap_get_order()` take a byte length (`size_t size`), not a page order or count, encoding `ilog2(size) - PAGE_SHIFT` for `FGF_GET_ORDER()`. [F67, F68]
- Single-bit constants in `enum mapping_flags` (`AS_EIO` through `AS_KERNEL_FILE`) are bit indices into `mapping->flags` accessed via bitops (`test_bit()`, `set_bit()`, etc.) or `mapping_*()` helpers, whereas `AS_FOLIO_ORDER_*_MASK` are pre-shifted bitmasks. `mapping_set_folio_order_range()` performs a non-atomic RMW on `mapping->flags`, so it must only be called before the mapping is active; `mapping_large_folio_support()` must never be called on an anonymous `folio->mapping` (`FOLIO_MAPPING_ANON`). [F51, F52, F146]
- Unlike `filemap_get_folios*()`, `find_get_entries()` and `find_lock_entries()` require a `pgoff_t indices[PAGEVEC_SIZE]` array and include exceptional XArray value entries in `fbatch->folios[]`, so callers must guard folio operations with `xa_is_value(folio)` and call `folio_batch_remove_exceptionals()` before `folio_batch_release()`. Unlike `find_get_entries()` and `filemap_get_folios_tag()`, `find_lock_entries()` must omit any folio or multi-index value entry whose base index is `< *start` or whose last index `base + nr - 1` is `> end`. [F50, F97, F133]
- `truncate_cleanup_folio()`, `truncate_inode_partial_folio()`, and `filemap_release_folio()` must check `folio_needs_release(folio)` rather than `folio_has_private(folio)` before invoking `folio_invalidate()` or `a_ops->release_folio()` so mappings with `AS_RELEASE_ALWAYS` are not skipped. [F171]
- Callers of `writeback_iter()` must never exit the loop early via `break` or `goto`, but must continue passing `folio` and `*error` back into `writeback_iter()` until it returns `NULL` (releasing `wbc->fbatch`, updating `mapping->writeback_index`, and restoring `wbc->saved_err`). In `mapping_set_error()`, `__folio_start_writeback()`, and `__folio_end_writeback()`, `mapping->host` can be `NULL` (e.g., `swapper_space`) and must be checked before dereferencing. [F69, F109]

## Error Handling
- `filemap_update_page()`, `filemap_create_folio()`, and `filemap_read_folio()` (or `filler_t` callbacks) return the positive sentinel `AOP_TRUNCATED_PAGE` (with `filemap_update_page()` and `filemap_create_folio()` having already dropped the folio reference); callers (`filemap_get_pages()`, `filemap_fault()`, `do_read_cache_folio()`) must only call `folio_put(folio)` when `err < 0` and must retry on `AOP_TRUNCATED_PAGE` rather than converting it to `ERR_PTR` or `VM_FAULT_SIGBUS`. [F56, F57]
- In `generic_perform_write()`, `copy_folio_from_iter_atomic()` advances the `iov_iter` by `copied` bytes before `a_ops->write_end` runs; if `write_end` returns `status != copied`, `iov_iter_revert(i, copied - max(status, 0L))` must be called. In `generic_file_read_iter()` and `generic_file_direct_write()`, after `mapping->a_ops->direct_IO`, any unconsumed `iov_iter` advancement must be rolled back with `iov_iter_revert()` whenever the return value is not `-EIOCBQUEUED`. [F19, F20]
- `folio_unmap_invalidate()` returns `1` on success and a negative errno on failure, so `invalidate_inode_pages2_range()` must only update `ret` when `ret2 < 0`, and `generic_file_direct_write()` must translate `-EBUSY` from `kiocb_invalidate_pages()` to `0` to fall back to buffered writes. In `filemap_write_and_wait_range()` and `file_write_and_wait_range()`, `__filemap_fdatawait_range()` must still be called when `__filemap_fdatawrite_range()` returns a non-`-EIO` error, and `filemap_check_errors()` / `file_check_and_advance_wb_err()` must only overwrite `err` if `err == 0`. [F58, F60]

## Known Pitfalls
- Raw `i_pages` XArray walks using `xas_load()` and `xas_next()` (`filemap_get_folios_contig()`, `filemap_get_read_batch()`) must check `xa_is_sibling(folio)` in addition to `xas_retry(&xas, folio)` and `xa_is_value(folio)` before `folio_try_get(folio)`, and must call `xas_advance(&xas, folio_next_index(folio) - 1)` after adding a folio to `fbatch` so `xas_next()` skips all indices of a multi-page folio. [F49, F105]
- Page cache indices (`pgoff_t` / `unsigned long`) must be widened to 64-bit (`loff_t` or `u64`) before shifting by `PAGE_SHIFT` or multiplying by `PAGE_SIZE` (`folio_pos()`, `readahead_pos()`, `mapping_seek_hole_data()`), and in `folio_seek_hole_data()` `bsz` (`size_t`) must be widened to `u64` in `~((u64)bsz - 1)` to avoid 32-bit truncation. In `truncate_inode_partial_folio()` and `truncate_pagecache_range()`, inclusive `loff_t` end bounds derived from `lend == (loff_t)-1` must be cast to `u64` before relational comparison so `-1` is treated as `ULLONG_MAX`. [F119, F120, F123]
- In `filemap_get_pages()`, `last_index` is exclusive, so `filemap_get_read_batch()` and `trace_mm_filemap_get_pages()` must receive `last_index - 1`. In `filemap_get_folios_tag()`, when entries up to `end` are exhausted without filling `fbatch`, `*start` must be set to `(pgoff_t)-1` when `end == (pgoff_t)-1` rather than `end + 1` to avoid wrapping to `0`. [F93, F108]
