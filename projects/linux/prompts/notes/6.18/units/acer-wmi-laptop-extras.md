# ACER WMI LAPTOP EXTRAS

The Acer WMI Laptop Extras driver (`drivers/platform/x86/acer-wmi.c`) integrates Acer, Gateway, Packard Bell, and legacy OEM laptops via ACPI-WMI (`AMW0`, `WMID`, and `WMID` Gaming interfaces), Embedded Controller (EC) registers, and `i8042` commands. It manages `rfkill` switches (WiFi, Bluetooth, 3G), LCD backlight brightness, the mail LED, sparse-keymap hotkey input and tablet-mode switch events, an ACPI BMA150 accelerometer, Predator/Nitro thermal platform profiles, turbo/fan/overclocking controls, and `hwmon` temperature and fan speed sensors.

## Architecture & Data Flow
- In `acer_wmi_init()`, `interface = &AMW0_interface` for `wmi_has_guid(AMW0_GUID1) && !wmi_has_guid(WMID_GUID1)` must be assigned only after `dmi_walk(type_aa_dmi_decode, NULL)` and the `WMID_GUID2` detection block, because that block runs whenever `interface != NULL` and returns `-ENODEV` if neither `WMID_GUID2`, `has_type_aa`, nor `force_caps` is present. [F46]
- In `acer_wmi_init()`, `interface->capability` must be updated in exact order: WMI/DMI probing, `set_quirks()`, clearing `ACER_CAP_BRIGHTNESS` when `acpi_video_get_backlight_type() != acpi_backlight_vendor`, and finally overriding with `force_caps` before testing `ACER_CAP_SET_FUNCTION_MODE`. [F47]
- `find_quirks()` must fall back to `quirks = &quirk_unknown` when no quirk matches because later code dereferences `quirks` unconditionally and `acer_wmi_init()` tests `quirks == &quirk_unknown` to reject non-whitelisted `AMW0_GUID1` machines not in `non_acer_quirks`. [F50]
- In `acer_quirks` and `non_acer_quirks`, `struct dmi_system_id.driver_data` must point to a `struct quirk_entry` when paired with `.callback = dmi_matched`, and hold an integer capability bitmask cast to `(void *)` when paired with `.callback = set_force_caps`. Never add new DMI entries to `non_acer_quirks`, and restrict `acer_quirks` to Acer, Gateway, or Packard Bell machines. [F58, F86]
- `type_aa_dmi_decode()` must clear `ACER_WMID3_GDS_RFBTN` from `commun_func_bitmap` (`commun_func_bitmap &= ~ACER_WMID3_GDS_RFBTN`) so `wmid3_set_device_status()` does not pass the RF button bit in `get_params.devices` or `set_params.devices`. [F33]
- `wmid3_set_device_status()` must first query current `commun_func_bitmap` state via `WMID_GUID3` method 2, verify both `return_value.error_code == 0` and `return_value.ec_return_value == 0`, and modify only the target `device` bit in `set_params.devices` before invoking method 1. [F32]
- `acer_predator_v4_platform_profile_probe()` must unconditionally advertise the fixed set of Predator V4 profiles without querying `ACER_WMID_MISC_SETTING_SUPPORTED_PROFILES` via `WMID_gaming_get_misc_setting()`, as some firmwares return invalid supported-profile bitmaps. `acer_predator_v4_platform_profile_probe()`, `acer_predator_v4_platform_profile_get()`, and `acer_predator_v4_platform_profile_set()` must map the exact same set of `enum platform_profile_option` and `enum acer_predator_v4_thermal_profile` values. [F37, F67]
- `last_non_turbo_profile` holds a valid `enum acer_predator_v4_thermal_profile` (never `PLATFORM_PROFILE_*` or `INT_MIN` after `acer_predator_v4_platform_profile_probe()`), updated in `acer_predator_v4_platform_profile_set()` and `acer_thermal_profile_change()` only when the profile is not `ACER_PREDATOR_V4_THERMAL_PROFILE_TURBO`. [F23]
- `acer_toggle_turbo()` must update the turbo LED (`ACER_CAP_TURBO_LED`), fan mode (`WMID_gaming_set_fan_mode()`), and—when `has_cap(ACER_CAP_TURBO_OC)` holds—both `ACER_WMID_MISC_SETTING_OC_1` and `ACER_WMID_MISC_SETTING_OC_2` together on transitions into or out of turbo mode. [F30]
- `enum acer_wmi_predator_v4_sensor_id` values are 1-based firmware IDs (1..16): `acer_wmi_hwmon_is_visible()` tests the 16-bit `supported_sensors` mask (`ACER_PREDATOR_V4_SUPPORTED_SENSORS_BIT_MASK`) via `BIT(sensor_id - 1)`, while `acer_wmi_hwmon_read()` packs `sensor_id` directly into `ACER_PREDATOR_V4_SENSOR_INDEX_BIT_MASK`. Channel counts in `acer_wmi_hwmon_info` for `hwmon_temp` and `hwmon_fan` must match the lengths of `acer_wmi_temp_channel_to_sensor_id` and `acer_wmi_fan_channel_to_sensor_id`. [F35, F39]
- Across `acer_suspend()` and `acer_resume()`, `ACER_CAP_MAILLED` and `ACER_CAP_BRIGHTNESS` states are saved in `interface->data` (`ACER_CAP_MAILLED` must be turned off on suspend and in `acer_platform_shutdown()`), and `acer_resume()` must call `acer_gsensor_init()` whenever `acer_wmi_accel_dev` is non-NULL. [F74]
- Array sentinels must be preserved: `{ "", 0 }` for `norfkill_ids`, `{KE_END, 0}` for `acer_wmi_keymap`, `NULL` for `acer_wmi_hwmon_info`, and `{}` for DMI tables (`acer_blacklist`, `amw0_whitelist`, `acer_quirks`, `non_acer_quirks`). [F42]

## Synchronization
- In `acer_rfkill_init()`, `rfkill_inited` must remain `false` until all `acer_rfkill_register()` calls complete so `acer_rfkill_set()` skips `set_u32()` while `rfkill_register()` applies initial state via `rfkill_set_sw_state()`. All enabled `wireless_rfkill`, `bluetooth_rfkill`, and `threeg_rfkill` devices must be registered before `schedule_delayed_work(&acer_rfkill_work, ...)`, and `acer_rfkill_exit()` must call `cancel_delayed_work_sync(&acer_rfkill_work)` under the matching condition before unregistering/destroying them. [F9, F10, F77]
- In `acer_wmi_input_setup()`, `acer_wmi_input_dev` must be allocated and initialized with `sparse_keymap_setup()` (and `SW_TABLET_MODE` via `input_set_capability()` when `ACER_CAP_KBD_DOCK` is set) before `wmi_install_notify_handler(ACERWMID_EVENT_GUID, acer_wmi_notify, NULL)` is called. [F12]
- In `acer_wmi_accel_setup()`, `gsensor_handle` must be populated before `acer_wmi_accel_dev` is allocated and registered, because `acer_gsensor_event()` (from `acer_wmi_notify()`) and `acer_resume()` only check `if (acer_wmi_accel_dev)` before evaluating ACPI methods on `gsensor_handle`. [F14]
- In `acer_wmi_hwmon_init()`, `supported_sensors` must remain a `u64` with static/device lifetime and be populated before `devm_hwmon_device_register_with_info()` passes `&supported_sensors` as `void *drvdata` to `acer_wmi_hwmon_is_visible()`, which casts `const void *data` to `const u64 *` and dereferences it during registration. [F15, F59]
- In `WMID_set_u32()`, setting `ACER_CAP_MAILLED` when `quirks->mailled == 1` must bracket `i8042_command(&param, 0x1059)` with `i8042_lock_chip()` and `i8042_unlock_chip()`. [F75]
- Low-level hardware accessors (`get_u32`, `set_u32`, `WMI_gaming_execute_u64`, `WMI_gaming_execute_u32_u64`, `acer_gsensor_init`, `acer_gsensor_event`) invoke sleeping ACPI/WMI evaluations, EC transactions, or `i8042_lock_chip()`, and must only be called from sleepable context. [F76]

## Object Lifetimes
- In `AMW0_set_capabilities()`, `struct acpi_buffer out` (`ACPI_ALLOCATE_BUFFER`) is reused in place for the second `wmab_execute()` call: `out.pointer` must not be freed if the first `wmab_execute()` fails, but must be freed via `kfree(out.pointer)` on every path after the first call succeeds (including when the second call fails, without resetting `out.length = ACPI_ALLOCATE_BUFFER` beforehand). [F1]
- `acer_rfkill_register()` calls `rfkill_destroy(rfkill_dev)` and returns an `ERR_PTR` when `rfkill_register()` fails; on success, ownership transfers to `acer_rfkill_init()` error rollback and `acer_rfkill_exit()`, which must call both `rfkill_unregister()` and `rfkill_destroy()`. [F2]
- In `acer_wmi_accel_setup()`, `struct acpi_device *adev` from `acpi_dev_get_first_match_dev("BST0001", NULL, -1)` must be released with `acpi_dev_put(adev)` after extracting `gsensor_handle`. [F5]
- In `acer_wmi_init()`, `acer_platform_device` must be assigned by `platform_device_alloc()` before `platform_device_add()` triggers `acer_platform_probe()` (which passes `&acer_platform_device->dev` to `acer_wmi_hwmon_init()`), and if `platform_device_add()` fails it must be freed via `platform_device_put()` (not `platform_device_unregister()`). [F7]
- During teardown in `acer_wmi_input_destroy()` and `acer_wmi_exit()`, `wmi_remove_notify_handler(ACERWMID_EVENT_GUID)` must be called before unregistering `acer_wmi_input_dev`, `acer_wmi_accel_dev`, or `acer_platform_device`. [F13]
- In `acer_platform_probe()` and `acer_platform_remove()`, `mail_led`, `acer_backlight_device`, and `rfkill` devices use non-devres APIs requiring manual teardown via `acer_led_exit()`, `acer_backlight_exit()`, and `acer_rfkill_exit()` in both probe error paths and remove, whereas `platform_profile` and `hwmon` are `devm_*`-managed and must not be manually unregistered. [F66]

## API Contracts
- `WMI_gaming_execute_u32_u64`, `WMID_gaming_get_sys_info`, `WMID_gaming_set_misc_setting`, and `WMID_gaming_get_misc_setting` return `0` or negative Linux errno (`int`), whereas `WMI_gaming_execute_u64`, `WMID_gaming_set_u64`, `WMID_gaming_get_u64`, `get_u32`, and `set_u32` return `acpi_status` (`AE_*`) tested with `ACPI_SUCCESS()`/`ACPI_FAILURE()`. Do not confuse their return conventions or return raw `acpi_status` from sysfs/subsystem callbacks. [F18]
- `AMW0_get_u32`, `AMW0_set_u32`, `WMID_get_u32`, `WMID_set_u32`, `wmid_v2_get_u32`, `wmid_v2_set_u32`, `get_u32`, and `set_u32` take an `ACER_CAP_*` capability flag as `cap`, whereas `wmid3_get_device_status` and `wmid3_set_device_status` take an `ACER_WMID3_GDS_*` device bitmask as `device`. [F24]
- On `ACER_AMW0_V2`, `set_u32()` must route `ACER_CAP_MAILLED` to `AMW0_set_u32()`, call `WMID_set_u32()` followed by `AMW0_set_u32()` for `ACER_CAP_WIRELESS` and `ACER_CAP_BLUETOOTH`, and fall through to `WMID_set_u32()` otherwise; `get_u32()` only routes `ACER_CAP_MAILLED` to `AMW0_get_u32()` before falling through to `WMID_get_u32()`. [F48]
- `AMW0_set_u32()` and `WMID_set_u32()` must reject `value > max_brightness` for `ACER_CAP_BRIGHTNESS` and `value > 1` for `ACER_CAP_MAILLED`, `ACER_CAP_WIRELESS`, `ACER_CAP_BLUETOOTH`, and `ACER_CAP_THREEG` because `acer_commandline_init()` passes unvalidated module parameters (`mailled`, `threeg`, `brightness`) to `set_u32()`. [F41]
- Acer WMI radio states (`get_u32`, `set_u32`, and `device_state & ACER_WMID3_GDS_*`) encode enabled as non-zero and disabled as `0`, so `acer_rfkill_set()`, `acer_rfkill_register()`, `acer_rfkill_update()`, and `acer_wmi_notify()` must logically invert the boolean (`!state` / `!blocked`) when calling `set_u32()`, `rfkill_set_sw_state()`, or `rfkill_set_hw_state()`. [F27]
- `acer_rfkill_register()` passes `(void *)(unsigned long)cap` directly as `rfkill_alloc()`'s context argument, so `acer_rfkill_ops` callbacks (`acer_rfkill_set()`) must extract `u32 cap = (unsigned long)data` by value and never dereference `data`. [F60]
- In `acer_gsensor_event()`, the 64-bit `integer.value` elements from the `RDVL` ACPI package must be cast to `s16` before `input_report_abs()` so 16-bit two's-complement readings sign-extend into `[-16384, 16384]`. [F56]
- When `acer_thermal_profile_change()` changes the hardware thermal profile on a WMI hotkey event without calling `platform_profile_cycle()`, it must call `platform_profile_notify(platform_profile_device)` after `WMID_gaming_set_misc_setting()` succeeds. [F82]
- In `update_bl_status()` (`acer_bl_ops.update_status`), target brightness must be obtained via `backlight_get_brightness(bd)` rather than reading `bd->props.brightness` directly, and `ACER_CAP_BRIGHTNESS` must be cleared in `acer_wmi_init()` when `acpi_video_get_backlight_type() != acpi_backlight_vendor`. [F84]

## Error Handling
- In `WMID_gaming_get_sys_info()`, `WMID_gaming_set_misc_setting()`, and `WMID_gaming_get_misc_setting()`, the low 8-bit firmware status field (`ACER_PREDATOR_V4_RETURN_STATUS_BIT_MASK` or `ACER_GAMING_MISC_SETTING_STATUS_MASK`) of `result` must be verified to be zero after WMI evaluation succeeds, returning `-EIO` before writing `*out` or `*value` if non-zero. [F16]
- Scalar WMI query helpers for `WMID_GUID1`, `WMID_GUID2`, and `WMID_GUID4` (`WMI_execute_u32`, `WMID_set_capabilities`, `get_wmid_devices`, `WMI_gaming_execute_u64`, `WMI_gaming_execute_u32_u64`) must check `obj != NULL` and handle both `ACPI_TYPE_INTEGER` and `ACPI_TYPE_BUFFER` (4- or 8-byte) `union acpi_object` responses; for 32-bit queries (`WMI_execute_u32`, `WMID_set_capabilities`, `get_wmid_devices`), both `sizeof(u32)` and `sizeof(u64)` buffers must be accepted, reading the low 32 bits. [F19, F45]
- In `wmid3_get_device_status()`, `wmid3_set_device_status()`, `wmid3_set_function_mode()`, `acer_kbd_dock_get_initial_state()`, and `acer_wmi_notify()`, `obj` must be verified non-NULL with `obj->type == ACPI_TYPE_BUFFER` and the exact expected `obj->buffer.length` (4 or 8) before dereferencing `obj->buffer.pointer`. [F20]
- `acer_wmi_init()` treats `acer_wmi_accel_setup()` failure as non-fatal and continues loading with `acer_wmi_accel_dev == NULL`, so `acer_gsensor_event()`, `acer_resume()`, `acer_wmi_init()` error cleanup, and `acer_wmi_exit()` must check `acer_wmi_accel_dev != NULL` before using or unregistering it. [F21]
- In `acer_backlight_init()`, the result of `backlight_device_register()` must be checked with `IS_ERR(bd)` in a local variable, setting `acer_backlight_device = NULL` on failure before returning `PTR_ERR(bd)` so `acer_backlight_exit()` never sees an `ERR_PTR`. [F22]

## External Contracts
- In `acer_wmi_hwmon_read()`, temperature readings extracted from `ACER_PREDATOR_V4_SENSOR_READING_BIT_MASK` are in degrees Celsius and must be multiplied by `MILLIDEGREE_PER_DEGREE` before storing into `*val`, whereas fan speed readings are in RPM and stored unscaled. [F26]
- In `acer_wmi_keymap`, scancode `0x61` must remain `{KE_KEY, 0x61, {KEY_UNKNOWN} }` (not `KE_IGNORE` or `KEY_SWITCHVIDEOMODE`) so userspace udev/hwdb rules can remap it on systems where it does not duplicate ACPI Video Bus events. [F43]

## Known Pitfalls
- `WMID_get_u32()` truncates the 32-bit `result` from `WMI_execute_u32()` to `u8` via `*value = (u8)result`; do not route a `WMID_GUID1` capability whose return value uses bits [31:8] through `WMID_get_u32()` without updating that cast. [F57]
- `WMID_gaming_get_sys_info()` and `WMI_gaming_execute_u32_u64()` take 32-bit `u32` inputs (`command` and `in`), so callers like `acer_wmi_hwmon_read()` and `WMID_gaming_get_misc_setting()` that construct `u64` inputs must not set bits above bit 31. [F55]
- In `WMID_gaming_set_fan_mode()`, `quirks->cpu_fans + quirks->gpu_fans` must not exceed 2; otherwise `1 << (i + 1)` in `gpu_fan_config2` and `fan_mode << (2 * i + 2)` in `gpu_fan_config1` collide with the GPU fan bit positions starting at bit 3 (`i + 3`) and bits [7:6] (`2 * i + 6`). [F54]
- In `acer_wmi_notify()`, when `sparse_keymap_entry_from_scancode()` maps `return_value.key_num` to `KEY_TOUCHPAD_TOGGLE`, `scancode` must be rewritten to `KEY_TOUCHPAD_ON` or `KEY_TOUCHPAD_OFF` based on `device_state & ACER_WMID3_GDS_TOUCHPAD` before calling `sparse_keymap_report_event()`, which requires matching `KEY_TOUCHPAD_ON`/`KEY_TOUCHPAD_OFF` entries in `acer_wmi_keymap`. [F49]
- In `acer_gsensor_event()`, the caller-allocated `union acpi_object out_obj[5]` buffer passed to `acpi_evaluate_object(gsensor_handle, "RDVL", NULL, &output)` must have at least 5 elements even though `out_obj->package.count` is 4, because `out_obj[0]` holds the `ACPI_TYPE_PACKAGE` header and `out_obj[1..4]` hold its 4 elements. [F61]
- While DMI match tables (`acer_quirks`, `non_acer_quirks`, `acer_blacklist`, `amw0_whitelist`), `norfkill_ids`, and `acer_wmi_keymap` are `__initconst`, `struct quirk_entry` definitions (`quirk_unknown`, `quirk_*`) must never be marked `__initdata` or `__initconst` because `quirks` is dereferenced at runtime after init. [F69]
