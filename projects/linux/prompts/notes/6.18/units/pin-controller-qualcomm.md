# PIN CONTROLLER - QUALCOMM

This unit implements the Qualcomm LPASS LPI (Low Power Island) pin controller core (`pinctrl-lpass-lpi.c`) and SoC-specific LPASS LPI and TLMM (Top-Level Mode Multiplexer) platform drivers across APQ, IPQ, MDM, SM6xxx–SM8xxx, Glymur, and Milos platforms. The LPASS LPI core handles MMIO muxing, pinconf, slew-rate control, and `gpio_chip` operations over audio-island bulk clocks, while TLMM drivers define static pin/group/function descriptors, register layouts, tile offsets, eGPIO slots, and MPM/PDC wakeup IRQ maps registered through `msm_pinctrl_probe()`.

## Architecture & Data Flow

- In `lpi_gpio_set_mux()`, the `i == GPIO_FUNC && (val & LPI_GPIO_OE_MASK)` check must precede `!test_and_set_bit(group, pctrl->ever_gpio)` in the short-circuit `&&` condition; when true, `LPI_GPIO_VALUE_OUT_MASK` must be synced to the sampled `LPI_GPIO_VALUE_IN_MASK` in `LPI_GPIO_VALUE_REG` before writing `LPI_GPIO_FUNCTION_MASK` to `LPI_GPIO_CFG_REG`, so non-GPIO or input-only muxing does not prematurely set `ever_gpio`. [F20, F38]
- When `lpi_config_set()` configures a pin as an output (`output_enabled` is true), it must write `LPI_GPIO_VALUE_OUT_MASK` to `LPI_GPIO_VALUE_REG` before setting `LPI_GPIO_OE_MASK` in `LPI_GPIO_CFG_REG`. [F19]
- `lpi_pinctrl::slew_base` is only mapped in `lpi_pinctrl_probe()` when `LPI_FLAG_SLEW_RATE_SAME_REG` is not set in `lpi_pinctrl_variant_data::flags`; any code accessing slew-rate registers (such as `lpi_config_set_slew_rate()`) must check `LPI_FLAG_SLEW_RATE_SAME_REG` and use `tlmm_base` instead of dereferencing `slew_base`. [F10]
- In `struct lpi_pingroup`, `slew_offset` must be `LPI_NO_SLEW` (`-1`) or in `[0, 30]`, and `lpi_config_set_slew_rate()` must check both `slew_offset == LPI_NO_SLEW` and `slew > LPI_SLEW_RATE_MAX` before executing `sval |= slew << slew_offset` on a 32-bit register with 2-bit `LPI_SLEW_RATE_MASK` (since `slew` is not masked when ORed into `sval`). [F45, F46]
- `lpi_pinctrl::tlmm_base` and `slew_base` are `char __iomem *` (1-byte stride), so `lpi_gpio_read()`, `lpi_gpio_write()`, and `lpi_config_set_slew_rate()` must use unscaled byte offsets (`pin_offset`, `LPI_TLMM_REG_OFFSET * pin`, and register offsets). [F50]
- Every `struct lpi_pinctrl_variant_data` must maintain 1-to-1 identity indexing (`pins[i].number == i` and `groups[i].pin == i`) because `lpi_gpio_set_mux()`, `lpi_config_set()`, `lpi_gpio_read()`, and `lpi_gpio_write()` index `state->data->groups[]` with `pin` and `group` selectors interchangeably; similarly, TLMM `<soc>_groups[]` must keep dense 0-based 1-to-1 indexing with `<soc>_pins[]` (including dummy `PINGROUP` entries for missing pins) because `pinctrl-msm.c` indexes `pctrl->soc->groups[offset]` directly by GPIO offset and `hwirq`. [F43, F97]
- In `pinctrl-lpass-lpi.c`, `MAX_NR_GPIO` (sizing the `ever_gpio` bitmap in `struct lpi_pinctrl`) must be `>= data->npins` for every registered `struct lpi_pinctrl_variant_data`, as `lpi_pinctrl_probe()` rejects `data->npins > MAX_NR_GPIO` with `-EINVAL`. [F29]
- In every SoC TLMM and LPASS LPI driver, `"gpio<id>"` must be in `<fname>_groups[]` if and only if `<fname>` is present in `PINGROUP(id, ...)` (`LPI_PINGROUP(id, ...)` / `LPI_PINGROUP_OFFSET(id, ...)`), and every enum constant `< ARRAY_SIZE(<soc>_functions)` in `enum <soc>_functions` or `enum lpass_lpi_functions` must have a designated initializer (`MSM_PIN_FUNCTION`, `MSM_GPIO_PIN_FUNCTION`, or `LPI_FUNCTION`) in `<soc>_functions[]`, with unindexed placeholders (`msm_mux__`, `LPI_MUX__`) placed last. [F25, F91]
- In `LPI_PINGROUP`, `LPI_PINGROUP_OFFSET`, and each SoC `PINGROUP` macro, `.nfuncs` must match the exact element count of the `(int[]){ ... }` compound literal assigned to `.funcs`; in TLMM `PINGROUP` definitions, `.nfuncs` must stay between `2` and `16` because `msm_pinmux_set_mux()` computes `GENMASK(g->mux_bit + order_base_2(g->nfuncs) - 1, g->mux_bit)` with `.mux_bit = 2` and `.drv_bit = 6`. [F48, F115]
- In multi-tile TLMM drivers (`pinctrl-sm6115.c`, `pinctrl-sm6125.c`, `pinctrl-sm7150.c`, `pinctrl-sm8150.c`, `pinctrl-sm8250.c`), tile enum values (`NORTH`, `SOUTH`, `EAST`, `WEST`) must match the 0-based order of `<soc>_tiles[]` and stay `< ntiles` (and `< MAX_NR_TILES`, `4`), and special pin macros (`SDC_PINGROUP`, `SDC_QDSD_PINGROUP`, `UFS_RESET`) must set `.tile` to the specific tile enum containing that pin's register bank rather than hardcoding a single tile. [F99, F121]
- Register offsets passed to `PINGROUP`, `SDC_PINGROUP`, `SDC_QDSD_PINGROUP`, and `UFS_RESET` must be relative to the OS-accessible TLMM or tile base mapped from Device Tree, and all pins of the same SDC controller (`clk`, `cmd`, `data`) sharing a control register must specify the identical `ctl` offset. [F122]
- In TLMM drivers, `PINGROUP` must set `.intr_detection_width` to `1` or `2` while non-interrupt macros (`UFS_RESET`, `SDC_PINGROUP`, `SDC_QDSD_PINGROUP`) must set `.intr_detection_width = -1`, because `msm_gpio_irq_init_valid_mask()` only masks out `0..ngpios-1` entries whose `intr_detection_width` is neither `1` nor `2`. [F111]
- In all wakeup IRQ mapping arrays (`sm6115_mpm_map`, `sm6125_mpm_map`, `sm6350_pdc_map`, `sm6375_mpm_map`, `sm7150_pdc_map`, `sm8150_pdc_map`, `sm8250_pdc_map`, `sm8350_pdc_map`, `sm8450_pdc_map`), every entry's `.gpio` field must be `< ngpios` (and `< MAX_NR_GPIO`, `300`). Broken by: swapping `.gpio` and `.wakeirq` or adding a `.gpio >= MAX_NR_GPIO`. [F102]

## Synchronization

- In `pinctrl-lpass-lpi.c`, every read-modify-write to `LPI_GPIO_CFG_REG` or `LPI_SLEW_RATE_CTL_REG` (in `lpi_gpio_set_mux()`, `lpi_config_set_slew_rate()`, and `lpi_config_set()`) must be serialized under `pctrl->lock`; because `lpi_config_set_slew_rate()` acquires `pctrl->lock` internally, `lpi_config_set()` must call it before acquiring `pctrl->lock`. [F6, F60]
- In `lpi_gpio_set_mux()`, `pctrl->lock` must be held continuously across reading `LPI_GPIO_CFG_REG`, testing and setting `pctrl->ever_gpio`, syncing `LPI_GPIO_VALUE_REG` to `LPI_GPIO_VALUE_IN_MASK`, and writing `LPI_GPIO_FUNCTION_MASK` to `LPI_GPIO_CFG_REG`. [F7]
- `lpi_gpio_set_mux()`, `lpi_config_set_slew_rate()`, `lpi_config_set()`, `lpi_gpio_direction_input()`, `lpi_gpio_direction_output()`, and `lpi_gpio_set()` acquire the sleeping `struct mutex lock` in `struct lpi_pinctrl` and must only be called from process context. [F66]

## Object Lifetimes

- In `lpi_pinctrl_probe()`, `platform_set_drvdata(pdev, pctrl)` must precede `devm_pinctrl_register()` and `devm_gpiochip_add_data()` (since `lpi_config_get()`, `lpi_config_set()`, and `lpi_pinctrl_remove()` fetch `pctrl` via drvdata), and `pctrl->ctrl = devm_pinctrl_register(...)` must complete before `lpi_build_pin_desc_groups()` and `devm_gpiochip_add_data()` (which dereference `pctrl->ctrl` and `pctldev->desc`). [F1, F2]
- In `lpi_pinctrl_probe()`, bulk clocks `"core"` and `"audio"` enabled via `clk_bulk_prepare_enable()` and `pctrl->lock` initialized via `mutex_init()` are not devres-managed: any error after `mutex_init()` must jump to `err_pinctrl`, and every LPASS LPI `platform_driver` must set `.data` in `lpi_pinctrl_of_match[]` and pair `.probe = lpi_pinctrl_probe` with `.remove = lpi_pinctrl_remove`. [F59, F128]
- In `lpi_build_pin_desc_groups()`, `pinctrl_generic_add_group()` stores the `pins` pointer directly without copying, so `pins` must point to `&pin_info->number` inside the static `pctrl->desc.pins` array with `num_pins == 1`. Broken by: passing a stack-local pin index address or `num_pins > 1`. [F51]
- SoC descriptor tables (`struct msm_pinctrl_soc_data`, `struct lpi_pinctrl_variant_data`, and their nested arrays) must remain non-`__initconst`/`__initdata` static storage because `msm_pinctrl_probe()` and `lpi_pinctrl_probe()` retain borrowed pointers in `pctrl->soc` and `pctrl->data` for runtime and remove use. [F78]

## API Contracts

- Every `lpi_pingroup` definition (`LPI_PINGROUP` or `LPI_PINGROUP_OFFSET`) must place `LPI_MUX_gpio` at `funcs[0]` (`GPIO_FUNC`), because `lpi_gpio_set_mux()` writes the matched array index `i` directly into `LPI_GPIO_FUNCTION_MASK` and checks `i == GPIO_FUNC` for glitch-free output initialization. [F17]
- In `lpi_config_set()`, `strength` is in milliamps (default `2` mA) and must be converted with `LPI_GPIO_DS_TO_VAL()` (`v / 2 - 1`) before writing `LPI_GPIO_OUT_STRENGTH_MASK`, whereas register reads must be converted back to mA with `lpi_regval_to_drive()` (`(val + 1) * 2`). [F16]
- In TLMM drivers (`struct msm_pinctrl_soc_data`), all GPIO-capable pingroups (`PINGROUP` and `UFS_RESET`) must be placed at `groups[0 .. ngpios - 1]` indexed by GPIO number, while non-GPIO pingroups (`SDC_PINGROUP`, `SDC_QDSD_PINGROUP`) must be placed at indices `>= ngpios`. Broken by: setting `.ngpios = ARRAY_SIZE(<soc>_groups)` when SDC pingroups are present. [F62]
- Any `reserved_gpios` array assigned to `struct msm_pinctrl_soc_data.reserved_gpios` (e.g., `ipq9574_reserved_gpios`) must be terminated by `-1` and contain at most `ngpios` entries with every GPIO number `< ngpios`. [F64]
- In TLMM drivers supporting eGPIO (`pinctrl-sm8250.c`, `pinctrl-sm8450.c`), `msm_pinctrl_soc_data.egpio_func` must equal the slot index (`9`, parameter `f9`) where `msm_mux_egpio` resides in `msm_pingroup.funcs[]`, every eGPIO-capable `PINGROUP` must pass `egpio` in `f9` and set `.egpio_present` and `.egpio_enable`, and `gpio` in all `<soc>_functions[]` (plus `egpio` in `sm8450_functions[]`) must use `MSM_GPIO_PIN_FUNCTION()` rather than `MSM_PIN_FUNCTION()`. [F81, F107]

## Error Handling

- In `lpi_config_set()`, local configuration variables (`pullup`, `strength`, and `output_enabled`) must be initialized to valid defaults before iterating over `configs[]`, because `lpi_config_set()` unconditionally writes all three fields into `LPI_GPIO_CFG_REG` even when omitted from `configs[]`. [F9]
- In `lpi_build_pin_desc_groups()`, `pinctrl_generic_add_group()` returns a non-negative group selector on success, so its return value must be checked with `ret < 0` (not `if (ret)`), and on failure at index `i` the rollback loop must iterate `for (; i > 0; i--)` removing group `i - 1`. [F12, F32]
- In `lpi_pinctrl_probe()`, `pctrl->clks[0].id` (`"core"`) and `pctrl->clks[1].id` (`"audio"`) must be initialized before calling `devm_clk_bulk_get_optional(dev, MAX_LPI_NUM_CLKS, pctrl->clks)` on the zero-allocated `struct lpi_pinctrl`. [F14]
- `lpi_gpio_dbg_show_one()` must normalize a `NULL` `pctldev` argument via `pctldev = pctldev ? : state->ctrl;` before dereferencing `pctldev->desc->pins[offset]`, because `lpi_gpio_dbg_show()` passes `pctldev = NULL`. [F15]

## External Contracts

- In TLMM drivers, `struct msm_pinctrl_soc_data` must populate `.wakeirq_map` and `.nwakeirq_map` with the SoC's exact `{ gpio, wakeirq }` MPM or PDC interrupt mappings, and set `.wakeirq_dual_edge_errata = true` when the parent wakeup controller cannot detect both edges in hardware. [F125]

## Known Pitfalls

- In `lpi_config_set()`, local `bool value` is declared uninitialized and read after the `configs` loop whenever `output_enabled` is true; any `switch (param)` branch that sets `output_enabled = true` (such as `PIN_CONFIG_OUTPUT_ENABLE`) must also assign `value`. [F40]
- In `SDC_PINGROUP` and `SDC_QDSD_PINGROUP` definitions, `pull` must be in `[0, 30]` and `drv` in `[0, 29]` (never `-1`), because `pull_bit` and `drv_bit` are 5-bit unsigned bitfields shifted as `3 << bit` and `7 << bit` into a 32-bit `u32` register value. [F113]
