# PCI ENHANCED ERROR HANDLING (EEH) FOR POWERPC

Implements PowerPC PCI Enhanced Error Handling (EEH) on `pseries` and `powernv` alongside generic PCIe error reporting and containment (`AER`, `DPC`, and `pcie_do_recovery`). On PowerPC, EEH detects frozen Partitionable Endpoints (PEs) or fenced PHBs, logs state via RTAS or OPAL, and drives asynchronous reset, BAR restoration, hotplug re-enumeration, and driver recovery via `eehd`. On generic PCIe platforms, AER, DPC, and `err.c` handle error interrupts, link containment, and recovery callbacks.

## Architecture & Data Flow

- During `eeh_pe_reset_full()`, `EEH_PE_RESET` is marked on the PE subtree so `pnv_eeh_get_pe_state()` returns active flags before querying OPAL (hardware stays frozen until BAR restore). During reset/recovery, EEH helpers (`eeh_bridge_check_link()`, `eeh_restore_*_bars()`, `pnv_eeh_do_*_flr()`) must use `eeh_ops->read_config`/`write_config`, and `pnv_eeh_cfg_blocked()` must check `if (edev->physfn && (edev->pe->state & EEH_PE_RESET))` before `EEH_PE_CFG_BLOCKED` to allow VF FLR config access. [F66, F91, F105, F149]
- `eeh_pe_mark_isolated()` and `eeh_pe_state_clear(..., EEH_PE_ISOLATED, ...)` must update PE isolation state, `pdev->error_state`, `pe->check_count`, and `EEH_PE_CFG_BLOCKED` (when `EEH_PE_CFG_RESTRICTED` is set) together across the PE subtree. When `EEH_PE_CFG_RESTRICTED` is set, `eeh_dev_save_state()`/`eeh_dev_restore_state()` skip `pci_save_state()`/`pci_restore_state()` (`eeh_dev_restore_state()` calls `eeh_pe_restore_bars(edev->pe)` on the last `edev` in `pe->edevs`), and `eeh_slot_error_detail()` checks `!(pe->state & EEH_PE_CFG_BLOCKED)` before `eeh_pe_restore_bars()` and `eeh_dump_pe_log()`. [F58, F138, F139]
- In `eeh_handle_normal_event()` and `pcie_do_recovery()`, recovery stages (`CAN_RECOVER`, `NEED_RESET`, `RECOVERED`) must remain sequential `if` statements because earlier stages mutate `result`/`status` to trigger later ones. In `eeh_result_priority()`, `CAN_RECOVER` (4) ranks above `RECOVERED` (3) and `NONE` (1), and `eeh_handle_normal_event()` must reset `result` from `NEED_RESET` (6) to `NONE` before `eeh_pe_report("slot_reset", ...)`. In `pcie_do_recovery()`, `status` must be preset to `RECOVERED` before `report_mmio_enabled` or `report_slot_reset` because `merge_result()` treats `NONE` as a no-op. [F73, F93, F94]
- Because `eeh_remove_device()` and `eeh_rmv_device()` clear `edev->pdev = NULL` while keeping `edev` on `pe->edevs` when `EEH_PE_KEEP` is set, any traversal of `pe->edevs` (`eeh_pe_for_each_dev`, `eeh_pe_dev_traverse`) must check `edev->pdev != NULL` (or `eeh_edev_actionable(edev)`). In `eeh_driver.c`, `edev->in_error` is set only when `eeh_report_error()` invokes `error_detected(pci_channel_io_frozen)`, must be checked before `slot_reset()` or `resume()`, and cleared on recovery completion or `eeh_remove_device()`. [F47, F68]
- `eeh_pe_bus_get()` must only return cached `pe->bus` when `EEH_PE_PRI_BUS` is set, and `EEH_PE_PRI_BUS` must be cleared when a PE's primary bus is torn down or right before `pci_hp_add_devices()` re-enumerates it (not before `eeh_pe_reset_full()` finishes in `eeh_reset_device()`). `eeh_reset_device()` must save/restore `pe->freeze_count` and `pe->tstamp` across device removal, and `eeh_handle_normal_event()` must call `eeh_pe_update_time_stamp(pe)` (clamping negative `freeze_count` to `0`) before comparing against `u32 eeh_max_freezes`. [F60, F63, F113]
- Because `0` is a valid PE address (`PE#0`), `eeh_dev_check_failure()` must test `!edev->pe` rather than `!pe->addr`, and `__eeh_pe_get()` must skip `EEH_PE_PHB` root PEs before matching `pe->addr`. In `eeh_dev_check_failure()`, `pnv_eeh_get_pe()`, and `pnv_eeh_next_error()`, the loop escalating a frozen PE to its ancestor must stop at `EEH_PE_PHB` and walk `parent_pe = parent_pe->parent` up to the highest frozen non-PHB ancestor without breaking on the first frozen parent. In `eeh_pe_next()`, the upward walk when `next == &pe->child_list` must check `if (pe == root) return NULL;` before accessing `pe->child.next` or `pe->parent`. [F77, F97, F106]
- `struct pci_io_addr_range` in `eeh_cache.c` stores inclusive bounds `[addr_lo, addr_hi]` (requiring `<` and `>` comparisons in `__eeh_addr_cache_get_device()` and `eeh_addr_cache_insert()`), and `__eeh_addr_cache_rmv_dev()` must restart from `rb_first()` after `rb_erase()`/`kfree()`. `eeh_token_to_phys()` (via `ppc_find_vmap_phys()`) must walk `init_mm` locklessly with `find_init_mm_pte()`, convert the PFN using `PFN_PHYS(pte_pfn(*ptep))` (`PAGE_SHIFT`), and mask the offset with `(1ul << hugepage_shift) - 1`. [F88, F99, F162]
- `struct pci_dev::aer_info` is `NULL` on devices without AER capability, so `aer_ratelimit()`, `pci_dev_aer_stats_incr()`, `pci_rootport_aer_stats_incr()`, and sysfs `is_visible` callbacks must check `aer_info != NULL`. Loops indexing `aer_info` error counters (`dev_cor_errs`, `dev_fatal_errs`, `dev_nonfatal_errs`) must bound iteration by counter array size (`AER_MAX_TYPEOF_*_ERRS`, where `COR_ERRS` is 16), whereas `aer_*_error_string` arrays must have 32 elements (`NULL`-padded) for `__aer_print_error()`. Indexing `e_info->dev[]` and `ratelimit_print[]` must enforce `i < AER_MAX_MULTI_ERR_DEVICES` (5), `find_source_device()` must reset `e_info->error_dev_num = 0`, and `aer_process_err_devices()` must log all devices via `aer_print_error()` before calling `handle_error_source()`. [F42, F83, F84, F85, F101]

## Synchronization

- Functions acquiring `pci_lock_rescan_remove()` (`eeh_handle_normal_event()`, `eeh_handle_special_event()`, `eeh_dev_restore_state()`, `eeh_pe_bus_get()`) must release it with `pci_unlock_rescan_remove()` on every path, and `eeh_handle_special_event()` must drop it before calling `eeh_handle_normal_event()`. [F6]
- In `eeh_dev_check_failure()` and `eeh_phb_check_failure()`, `confirm_error_lock` (`eeh_serialize_lock()`) must be held across checking `EEH_PE_ISOLATED`, `eeh_ops->get_state()`, and `eeh_pe_mark_isolated()`, and released before `eeh_send_failure_event()`. `eeh_check_failure()`, `eeh_dev_check_failure()`, and `eeh_ops->get_state()` must never sleep or block. `__eeh_send_failure_event()` also runs in atomic context: it must allocate `struct eeh_event` with `GFP_ATOMIC` and, when `pe != NULL`, mark `EEH_PE_RECOVERING` before queueing `event` onto `eeh_eventlist` under `spin_lock_irqsave(&eeh_eventlist_lock, flags)` so `eeh_pe_tree_remove()` cannot free `pe`. [F19, F20, F156, F157]
- In `eeh_pe_report_edev()`, the caller must copy `edev->pdev` to a local `pdev` and pin it with `get_device(&pdev->dev)` before `device_lock(&pdev->dev)`, holding `device_lock(&pdev->dev)` and a module reference from `eeh_pcid_get(pdev)` across the callback and `eeh_pcid_put(pdev)`. Likewise, in `drivers/pci/pcie/err.c` (`report_*()`) and `cxl_rch_handle_error_iter()`, `device_lock(&dev->dev)` must be held across reading `dev->driver`, checking `err_handler`, and invoking callbacks. [F8, F21, F34]
- In `eeh_reset_device()`, `EEH_PE_KEEP` must be marked on `pe` before removing devices and cleared only after `eeh_pe_restore_bars()` and `eeh_pe_detach_dev()`, so `eeh_remove_device()` marks devices `EEH_DEV_DISCONNECTED` instead of removing them from `pe`. In `eeh_handle_normal_event()`, `eeh_slot_error_detail(pe, EEH_LOG_TEMP)` must not be called until after `eeh_set_irq_state(pe, false)` and `eeh_pe_report("error_detected(IO frozen)", ...)` complete, because it may thaw MMIO. [F24, F25]
- On PowerNV, `pnv_eeh_event()` must mask its IRQ via `disable_irq_nosync(irq)` before queueing `eeh_send_failure_event(NULL)`. `eeh_handle_special_event()` must loop until `eeh_ops->next_error(&pe)` returns `EEH_NEXT_ERR_NONE` (or `EEH_NEXT_ERR_DEAD_IOC`), and `pnv_eeh_next_error()` must never return `EEH_NEXT_ERR_INF` and only call `enable_irq(eeh_event_irq)` when `ret == EEH_NEXT_ERR_NONE && eeh_enabled()`. `pnv_eeh_poll()` and `pnv_eeh_phb_reset()` must use `udelay()` instead of `msleep()` when `system_state < SYSTEM_RUNNING`. [F28, F103, F164]
- All accesses to `pci_io_addr_cache_root.rb_root` must hold `piar_lock` with `spin_lock_irqsave()`, and `eeh_addr_cache_insert()` must use `GFP_ATOMIC`. In `dpc_reset_link()`, `PCI_DPC_RECOVERING` must be set before clearing `PCI_EXP_DPC_STATUS_TRIGGER` (after waiting on `pcie_wait_for_link(pdev, false)` and `dpc_wait_rp_inactive(pdev)`), and `PCI_DPC_RECOVERED` updated before clearing `PCI_DPC_RECOVERING` and waking `dpc_completed_waitqueue`. `aer_irq()` and `dpc_irq()` must defer bus walks and `pcie_do_recovery()` to `aer_isr()` and `dpc_handler()`. `aer_recover_queue()` must pass element count `1` (not `sizeof(entry)`) to `kfifo_in_spinlocked(&aer_recover_ring, &entry, 1, &aer_recover_ring_lock)`, and `aer_recover_work_func()` must call `ghes_estatus_pool_region_free()` after `pci_print_aer()` and `pci_dev_put(pdev)`. [F29, F33, F36, F120, F150, F167]

## Object Lifetimes

- Callers of `eeh_handle_normal_event(pe)` (`eeh_event_handler()`, `eeh_handle_special_event()`) must not dereference or modify `pe` after it returns, because non-VF recovery failure removes the PE's devices via `pci_hp_remove_devices()` and frees `pe`. [F1]
- Because `eeh_for_each_pe()` advances via `eeh_pe_next()`, `eeh_pe_tree_remove()` must never unlink or free a PE while `EEH_PE_KEEP`, `EEH_PE_RECOVERING`, or `EEH_PE_PHB` (`pe->type`) is set, and `eeh_pe_cleanup()` must recurse over `pe->child_list` with `list_for_each_entry_safe` before freeing `pe`. In `eeh_pe_reset_and_recover()`, once `eeh_pe_state_mark(pe, EEH_PE_RECOVERING)` is called, every error and completion path must clear it via `eeh_pe_state_clear(pe, EEH_PE_RECOVERING, true)`. [F3, F7, F96]
- In `eeh_probe_device()`, if `eeh_ops->probe(dev)` returns an `edev` bound to a stale `edev->pdev != dev`, `eeh_pe_tree_remove(edev)`, `eeh_addr_cache_rmv_dev(edev->pdev)`, and `eeh_sysfs_remove_device(edev->pdev)` must run before rebinding; then `edev->pe`, `edev->pdev = dev`, and `dev->dev.archdata.edev = edev` must be set before `eeh_addr_cache_insert_dev(dev)` and `eeh_sysfs_add_device(dev)`. In `eeh_remove_device()`, `eeh_sysfs_remove_device(dev)` must run before clearing `dev->dev.archdata.edev = NULL`. [F18, F30, F130]
- Every `pci_dev` added to `e_info->dev[]` via `add_error_device()` has a `pci_dev_get()` reference that `aer_process_err_devices()` must release via `handle_error_source()`'s `pci_dev_put()`. In `pci_aer_init()`, if `kzalloc()` for `dev->aer_info` fails, `dev->aer_cap` must be cleared to `0`, and `pci_aer_exit()` must `kfree(dev->aer_info)` and set `dev->aer_info = NULL`. In `pcie_do_recovery()`, `pci_walk_bridge(bridge, pci_pm_runtime_get_sync, NULL)` must run before `error_detected`, and `pci_walk_bridge(bridge, pci_pm_runtime_put, NULL)` (and `report_perm_failure_detected` on failure) must run across the full `bridge` hierarchy on every exit path. [F13, F14, F35, F69]

## API Contracts

- `eeh_ops->get_state()` and `eeh_wait_state()` return `< 0` on error or `EEH_STATE_*` flags where `0` is a frozen PE; callers must use `eeh_state_active()` (requiring both `EEH_STATE_MMIO_ACTIVE` and `EEH_STATE_DMA_ACTIVE`) and check `EEH_STATE_NOT_SUPPORT` rather than testing `0`. In `pseries_eeh_get_state()`, RTAS state `0` must set `MMIO_ACTIVE | DMA_ACTIVE | MMIO_ENABLED | DMA_ENABLED`. `eeh_pe_get_state()` must return `EEH_PE_STATE_UNAVAIL` if `pe->parent` has `EEH_PE_ISOLATED` or `EEH_PE_RECOVERING` set, and test `rst_active` (`EEH_STATE_RESET_ACTIVE`) before `!dma_en && !mmio_en`. `get_state` implementations must set `*delay` whenever `delay != NULL` and `EEH_STATE_UNAVAILABLE` is returned, and `eeh_wait_state()` must keep `max_wait` signed and clamp `mwait` to `[EEH_STATE_MIN_WAIT_TIME, EEH_STATE_MAX_WAIT_TIME]`. [F37, F53, F65, F67, F90, F92, F114]
- Optional `struct eeh_ops` callbacks (`restore_config`, `notify_resume`, `err_inject`) must be checked for `NULL`. `eeh_pe_configure()` must call `eeh_ops->configure_bridge(pe)` even when `eeh_pe_passed(pe)` is true. `eeh_pe_reset_and_recover()` must not invoke `eeh_pe_report()` or driver callbacks. In `eeh_handle_normal_event()` and `eeh_handle_special_event()`, `eeh_set_channel_state(pe, pci_channel_io_perm_failure)` must run only after `eeh_pe_report(..., eeh_report_failure, NULL)`. `eeh_powernv_init()` must call `eeh_set_pe_aux_size()` before `eeh_init()`. [F46, F59, F74, F148, F171]
- Because RCECs and RCiEPs have `subordinate == NULL`, `pci_walk_bridge()` must check `bridge->subordinate` before `pci_walk_bus()`, and `find_source_device()` must use `pcie_walk_rcec()` for `PCI_EXP_TYPE_RC_EC`. In `pcie_do_recovery()`, any non-bridge device lacking `err_handler->error_detected` votes `PCI_ERS_RESULT_NO_AER_DRIVER`, which `merge_result()` preserves unconditionally. OS-initiated AER writes in `pci_aer_clear_*()` and `pcie_do_recovery()` must be gated on `pcie_aer_is_native(dev)`. In `dpc_process_error()`, `PCI_EXP_DPC_SOURCE_ID` may only be read when the trigger reason is `RSN_NFE` or `RSN_FE`, and RP PIO registers/TLP logs require checking `pdev->dpc_rp_extensions` and `pdev->dpc_rp_log_size`. [F44, F136, F137, F173, F174]

## Error Handling

- On PowerNV, `opal_pci_reset()` returns signed `s64` where `> 0` is a ms delay that reset helpers must pass to `pnv_eeh_poll()` and map final non-`OPAL_SUCCESS` to `-EIO`. On pSeries, `rtas_call(ibm_configure_pe, ...)` returns `> 0` for busy codes that `pseries_eeh_phb_configure_bridge()` must poll with `rtas_busy_delay()`. `reset_subordinates` callbacks (`aer_root_reset`, `dpc_reset_link`) must check reset/link-wait return values and return `PCI_ERS_RESULT_DISCONNECT` on failure; in `aer_root_reset()`, RCiEPs use `dev->rcec` as `root`, and `root && root->aer_cap` must be checked. Stack `struct aer_err_info` instances must be zero-initialized with `severity` set before `aer_get_device_error_info()` (which resets `status` and `tlp_header_valid`). [F38, F39, F40, F43, F50]

## External Contracts

- Buffers passed by physical address to RTAS (`pci_regs_buf`, `slot_errbuf` under `slot_errbuf_lock`, `rtas_data_buf` under `rtas_data_buf_lock`) must reside in static BSS RMO storage. `pseries_call_allow_unfreeze()` must convert VF PE numbers via `cpu_to_be16()`, pass `cur_vfs * sizeof(u16)`, avoid using `pdn` as the PF after `list_for_each_entry_safe(pdn, ...)`, and pass `physfn_pdn` to `pseries_send_allow_unfreeze()` in the VF branch. Both `eeh_pe_inject_err()` and `pnv_eeh_err_inject()` must independently validate `type`/`func` bounds. [F31, F80, F81, F109, F161, F178]

## Known Pitfalls

- In `eeh-powernv.c`, big-endian OPAL outputs (`frozen_pe_no`, `err_type`, `severity`, `pcierr`, `OpalIoP7IOCErrorData`) must be converted with `be16_to_cpu()`/`be64_to_cpu()`. `eeh_dump_dev_log()` and `eeh_dump_pe_log()` must use `scnprintf()` (not `snprintf()`) to avoid `len - n` underflow, and 32-bit config loops (`eeh_dump_dev_log`, `eeh_save_bars`, `eeh_restore_*_bars`) must advance offsets by `i * 4`. `EEH_IO_ERROR_VALUE(size)` only accepts byte sizes in `{1, 2, 4}` using unsigned `~0U`, whereas `EEH_POSSIBLE_ERROR(val, type)` must apply `~` to signed `~0` before casting to `type` so 64-bit `eeh_readq()` sign-extends to all-ones, and `eeh_memcpy_fromio()` must guard its trailing 4-byte check with `n >= 4` and offset `void *dest` by `n - 4` before casting to `u32 *`. [F76, F78, F89, F102, F111, F112, F118]
