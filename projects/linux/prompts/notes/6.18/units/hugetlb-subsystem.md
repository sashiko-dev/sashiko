# HUGETLB SUBSYSTEM

The HugeTLB subsystem manages persistent and surplus huge page pools (`hstate`), reservations (`resv_map`), page table operations (including PMD page table sharing), fault handling, migration, and hardware poison recovery. It includes the in-memory `hugetlbfs` filesystem for file-backed, anonymous (`MAP_HUGETLB`), and System V shared memory (`SHM_HUGETLB`) mappings, alongside HugeTLB vmemmap optimization (HVO), CMA-backed gigantic page allocation, and cgroup v1/v2 resource accounting.

## Architecture & Data Flow

- In hugetlb VMAs, `vma->vm_private_data` holds a `struct hugetlb_vma_lock *` when `VM_MAYSHARE` is set, and a `struct resv_map *` tagged with `HPAGE_RESV_MASK` (`HPAGE_RESV_OWNER | HPAGE_RESV_UNMAPPED`) when `VM_MAYSHARE` is clear; private-mapping callers must mask off `~HPAGE_RESV_MASK` via `vma_resv_map()`. [F142]
- Access a `hugetlbfs` inode's `struct resv_map` via `inode_resv_map(inode)` (`(&inode->i_data)->i_private_data`, not `inode->i_mapping->i_private_data`), and null-check it whenever non-regular, non-symlink inodes can be reached. [F50]
- Every successful `region_chg(resv, f, t, &out_regions_needed)` (which adds `*out_regions_needed >= 1` to `resv->adds_in_progress`) must be paired with `region_add()` or `region_abort()` (or `vma_commit_reservation()` / `vma_end_reservation()` after `vma_needs_reservation()`). [F72]
- In `free_huge_folio()`, call `hugepage_subpool_put_pages(spool, 1)` only when `!folio_test_hugetlb_restore_reserve(folio)`; if it returns `0`, set `restore_reserve = true` so `h->resv_huge_pages` is incremented under `hugetlb_lock`. [F15]
- In `remove_inode_single_folio()`, call `hugetlb_delete_from_page_cache(folio)` before `hugetlb_unreserve_pages()`; if `hugetlb_unreserve_pages(inode, index, index + 1, 1)` returns non-zero on a hole punch (`!truncate_op`), call `hugetlb_fix_reserve_counts(inode)`. [F73]
- Moving a folio onto or off `h->hugepage_freelists[nid]` in `enqueue_hugetlb_folio()`, `dequeue_hugetlb_folio_node_exact()`, and `remove_hugetlb_folio()` must update `h->free_huge_pages`, `h->free_huge_pages_node[nid]`, and `HPG_freed` in lockstep under `hugetlb_lock`. [F65]
- When `dissolve_free_hugetlb_folio()` dissolves a free folio, pass `adjust_surplus = true` to `remove_hugetlb_folio()` (and to `add_hugetlb_folio()` if `hugetlb_vmemmap_restore_folio()` fails) whenever `h->surplus_huge_pages_node[folio_nid(folio)]` is non-zero, alongside adjusting `h->max_huge_pages`. [F66]
- In `set_max_huge_pages()`, compute `min_count` for shrinking using `persistent_huge_pages(h)` and `persistent_free_count` (discounting `h->surplus_huge_pages` from `h->free_huge_pages`), rather than `h->nr_huge_pages` and raw `h->free_huge_pages`. [F67]
- In `__hugetlb_vmemmap_optimize_folio()` and `__hugetlb_vmemmap_restore_folio()`, update `hugetlb_optimize_vmemmap_key` and `HPG_vmemmap_optimized` in lockstep, setting `folio_set_hugetlb_vmemmap_optimized(folio)` before `vmemmap_remap_free()` copies the head page and rolling back on error. [F70]
- `NR_RESET_STRUCT_PAGE` in `mm/hugetlb_vmemmap.c` must be at least `1 + __NR_USED_SUBPAGE` (4 `struct page` entries) so `reset_struct_pages()` clears all hugetlb metadata when `vmemmap_restore_pte()` copies `walk->reuse_addr` into restored tail vmemmap pages. [F87]
- In `mm/hugetlb_vmemmap.c` (`free_vmemmap_page()`, `vmemmap_remap_free()`, `alloc_vmemmap_page_list()`), account vmemmap pages with global `memmap_pages_add()` for buddy pages and `memmap_boot_pages_add()` for `PageReserved` pages rather than per-node `mod_node_page_state()`. [F71]
- In `move_huge_pte()`, when `vma_has_uffd_without_event_remap(vma)` is true, clear uffd-wp across all three PTE encodings: `pte_marker_uffd_wp(pte)` via `huge_pte_clear()`, present PTEs via `huge_pte_clear_uffd_wp(pte)`, and swap PTEs via `pte_swp_clear_uffd_wp(pte)`. [F85]

## Synchronization

- `hugetlb_lock` and `struct hugepage_subpool::lock` are acquired with `spin_lock_irqsave()` in `free_huge_folio()` and `hugepage_subpool_put_pages()`, so all process-context callers must disable local IRQs (`spin_lock_irq()` or `spin_lock_irqsave()`). [F152]
- Never acquire `hugetlb_lock` while holding a page table lock `ptl` or `spool->lock`: `__unmap_hugepage_range()` must unlock `ptl` before taking `hugetlb_lock` (and reset `adjust_reservation` each iteration), and `unlock_or_release_subpool()` must drop `spool->lock` before `hugetlb_acct_memory()`. [F153, F154]
- Acquire the hugetlb VMA lock (`vma_lock->rw_sema` or `resv_map->rw_sema`) before `mapping->i_mmap_rwsem`; callers holding `i_mmap_rwsem` may only use `hugetlb_vma_trylock_write(vma)`. In `__hugetlb_zap_begin()` / `__hugetlb_zap_end()`, take `hugetlb_vma_lock_write(vma)` before `i_mmap_lock_write()`, and on `ZAP_FLAG_UNMAP` call `__hugetlb_vma_unlock_write_free(vma)` before `i_mmap_unlock_write()`. [F12, F29]
- In `hugetlb_fault()`, `hugetlb_no_page()`, and `hugetlb_wp()`, use `__vmf_anon_prepare()` rather than `vmf_anon_prepare()`, and call `vma_end_read(vma)` on `VM_FAULT_RETRY` only after `hugetlb_vma_unlock_read(vma)`. [F2]
- `hugetlb_fault()` transfers ownership of the held `hugetlb_vma_lock` read lock and `hugetlb_fault_mutex_table[hash]` to `hugetlb_no_page()`; for migration entries it unlocks `hugetlb_fault_mutex_table[hash]` first and transfers the `hugetlb_vma_lock` read lock to `migration_entry_wait_huge()`. [F5]
- `hugetlb_wp()` is entered with `vmf->ptl` held and drops it before `alloc_hugetlb_folio()`, so every subsequent exit path in `hugetlb_wp()` must re-acquire `spin_lock(vmf->ptl)` before returning. [F4]
- `hugetlb_wp()` must detect `MAP_PRIVATE` owner COW via `folio_test_anon(old_folio)` rather than locking the pagecache folio across `hugetlb_fault_mutex_table`, and `hugetlb_fault()` must use `folio_trylock(folio)` on anonymous folios under `hugetlb_fault_mutex_table`, dropping all locks before `unmap_ref_private()` or `folio_wait_locked()`. [F158]
- Before calling `handle_userfault()` from `hugetlb_fault()` or `hugetlb_no_page()`, release `vmf.ptl` (if held), `hugetlb_vma_lock`, and `hugetlb_fault_mutex_table[hash]`. [F160]
- For `VM_MAYSHARE` mappings, callers of `hugetlb_walk()` or `huge_pte_offset()` must hold either `vma_lock->rw_sema` or `i_mmap_rwsem` (read or write) to prevent concurrent `huge_pmd_unshare()` and `munmap()` from freeing the PMD page table page. [F33]
- In `huge_pmd_unshare()`, after `pud_clear(pud)`, call `tlb_remove_table_sync_one()` before `ptdesc_pmd_pts_dec(virt_to_ptdesc(ptep))`, and complete the PUD-aligned TLB flush (`tlb_flush_mmu_tlbonly()` or `flush_hugetlb_tlb_range()`) before `i_mmap_unlock_write(mapping)`. [F164, F166]
- `huge_pte_lockptr()` must select `pud_lockptr()` when `size >= PUD_SIZE`, `pmd_lockptr()` when `size >= PMD_SIZE || IS_ENABLED(CONFIG_HIGHPTE)`, and `ptep_lockptr()` only when `size < PMD_SIZE && !IS_ENABLED(CONFIG_HIGHPTE)`. [F168]
- In `remove_inode_single_folio()`, acquire `folio_lock(folio)` (under `hugetlb_fault_mutex_table[hash]`) before checking `folio_mapped(folio)` and calling `hugetlb_unmap_file_folio()`, and hold it until after `hugetlb_delete_from_page_cache(folio)`. [F32]
- Mark newly allocated folios uptodate via `__folio_mark_uptodate(folio)` before `set_huge_pte_at()` or `hugetlb_add_to_page_cache()`, and call `folio_set_hugetlb_migratable(folio)` only after insertion into the page cache and/or page table. [F44]
- When `update_and_free_hugetlb_folio()` is called with `atomic == true` on an HVO folio, enqueue `(struct llist_node *)&folio->mapping` onto `hpage_freelist` and schedule `free_hpage_work`; `free_hpage_workfn()` must clear `folio->mapping = NULL` and use `size_to_hstate(folio_size(folio))` instead of `folio_hstate(folio)`. [F26, F86]
- Callers requiring asynchronously freed HVO folios on `hpage_freelist` to finish returning to the buddy allocator (including `set_max_huge_pages()`) must drain `free_hpage_work` via `flush_free_hpage_work(h)` or `wait_for_freed_hugetlb_folios()` without holding `hugetlb_lock`. [F27]
- `__hugetlb_vmemmap_restore_folio()` and `__hugetlb_vmemmap_optimize_folio()` must call `synchronize_rcu()` only after confirming HVO applies to the folio, and batch helpers must clear `VMEMMAP_SYNCHRONIZE_RCU` after the first HVO folio. [F163]
- In `alloc_surplus_hugetlb_folio()`, `account_new_hugetlb_folio(h, folio)` and incrementing `h->surplus_huge_pages` / `h->surplus_huge_pages_node` must happen in the same `hugetlb_lock` critical section after rechecking `h->surplus_huge_pages >= h->nr_overcommit_huge_pages`. [F28]
- Modifying a folio's `hugetlb_cgroup` pointers and `h_cg->nodeinfo[nid]->usage[idx]` must occur under `hugetlb_lock` using `WRITE_ONCE()` for `usage[idx]`, and `__hugetlb_cgroup_charge_cgroup()` must look up `hugetlb_cgroup_from_task(current)` and loop on `css_tryget(&h_cg->css)` inside `rcu_read_lock()`. [F45, F165]

## Object Lifetimes

- When a folio from `alloc_hugetlb_folio()` is discarded before `hugetlb_add_to_page_cache()` succeeds (or before PTE installation for private mappings), call `restore_reserve_on_error()` before `folio_put(folio)`; after `hugetlb_add_to_page_cache()` succeeds, do not call `restore_reserve_on_error()`. [F6]
- In `hugetlb_no_page()`, call `__vmf_anon_prepare(vmf)` for private mappings before `alloc_hugetlb_folio()` so failure exits before any folio or reservation map state requires `restore_reserve_on_error()`. [F3]
- In `hugetlb_wp()`, after installing `new_folio` into `vmf->pte` under `vmf->ptl`, set `new_folio = old_folio` before `out_release_all:` so cleanup skips `restore_reserve_on_error()` and drops the page table's reference to `old_folio`. [F129]
- `remove_hugetlb_folio()` must keep `PG_hugetlb` set on HVO folios until `hugetlb_vmemmap_restore_folio()` / `hugetlb_vmemmap_restore_folios()` succeeds; if restoration fails, return the folio to the pool via `add_hugetlb_folio()` under `hugetlb_lock` instead of calling `hugetlb_free_folio()`. [F16]
- When `hugetlb_unmap_file_folio()` fails `hugetlb_vma_trylock_write(vma)`, pin `kref_get(&vma_lock->refs)` before dropping `i_mmap_rwsem`, acquire `down_write(&vma_lock->rw_sema)` then `i_mmap_lock_write(mapping)`, and revalidate `vma_lock->vma != NULL` and `hugetlb_vma_maps_pfn()`. [F30]
- `huge_pmd_share()` and `huge_pmd_unshare()` must track shared PMD tables via `ptdesc_pmd_pts_inc()`, `ptdesc_pmd_pts_dec()`, and `ptdesc_pmd_is_shared()` (only when `sz == PMD_SIZE`), and `huge_pmd_share()` must call `ptdesc_pmd_pts_dec()` if `!pud_none(*pud)` under `mm->page_table_lock`. [F13]
- Because `record_hugetlb_cgroup_uncharge_info()` takes a separate `css_get(&h_cg->css)` per `file_region`, `hugetlb_reserve_pages()` must release the initial `css` reference from `hugetlb_cgroup_charge_cgroup_rsvd()` via `hugetlb_cgroup_put_rsvd_cgroup(h_cg)` or `hugetlb_cgroup_uncharge_cgroup_rsvd()`. [F9]

## API Contracts

- When `CONFIG_HUGETLB_PAGE` is enabled, `alloc_hugetlb_folio()` and `filemap_lock_hugetlb_folio()` return `ERR_PTR` on failure (check `IS_ERR()`), whereas `alloc_hugetlb_folio_nodemask()`, `alloc_hugetlb_folio_reserve()`, and `alloc_hugetlb_folio_vma()` return `NULL`. [F47]
- In `hugetlb_mfill_atomic_pte()`, when `*foliop` is non-NULL on entry, it consumes ownership by calling `folio_put(*foliop)` and setting `*foliop = NULL` across all return paths, only setting `*foliop` to a newly allocated folio when returning `-ENOENT`. [F7]
- Undo `folio_isolate_hugetlb()` with `folio_putback_hugetlb(folio)` (which restores `HPG_migratable`, moves `folio->lru` back to `hugepage_activelist`, and calls `folio_put()`), never with a bare `folio_put(folio)`. [F22]
- `hugetlb_cgroup_charge_cgroup*()`, `hugetlb_cgroup_commit_charge*()`, `hugetlb_cgroup_uncharge_folio*()`, and `hugetlb_cgroup_uncharge_cgroup*()` take `nr_pages` in `PAGE_SIZE` pages, whereas `hugetlb_cgroup_uncharge_counter()` and `hugetlb_cgroup_uncharge_file_region()` take huge-page counts. [F60]
- `make_huge_pte()` must check both `try_mkwrite` and `(vma->vm_flags & VM_WRITE)` before marking a PTE writable and dirty. [F181]
- Hugetlb paths (`hugetlbfs_read_iter()`, `hugetlb_no_page()`, `hugetlb_mfill_atomic_pte()`) must test `folio_test_hwpoison(folio)` rather than `folio_test_has_hwpoisoned(folio)`, and `adjust_range_hwpoison()` must check subpages with `is_raw_hwpoison_page_in_hugepage()`. [F176]

## Error Handling

- When rolling back after `hugepage_subpool_get_pages(spool, chg)` returns `gbl_reserve`, callers must pass only `chg - gbl_reserve` to `hugepage_subpool_put_pages()` and unreserve its return value via `hugetlb_acct_memory(h, -gbl_resv)`. [F1]
- Callers of `vma_needs_reservation()` must store its return value in a signed type and check `< 0` (`-ENOMEM`) before calling `vma_add_reservation()`, `vma_commit_reservation()`, or `vma_end_reservation()`. [F46]
- On error in `hugetlb_reserve_pages()`, `out_err` must call `region_abort(resv_map, from, to, regions_needed)` when `chg >= 0 && add < 0` on a shared mapping, or put `resv_map` and call `set_vma_resv_map(vma, NULL)` when `HPAGE_RESV_OWNER` is set on a private VMA. [F54]
- In `alloc_vmemmap_page_list()`, call `memmap_pages_add(nr_pages)` only after the allocation loop succeeds, because the `out` rollback path frees partial allocations with `__free_page(page)`. [F18]
- In `vmemmap_remap_free()`, if `vmemmap_remap_range()` fails with `walk.nr_walked > 0`, restore `[reuse, reuse + walk.nr_walked * PAGE_SIZE)` with `vmemmap_restore_pte`, and `__hugetlb_vmemmap_optimize_folio()` must roll back `hugetlb_optimize_vmemmap_key` and `HPG_vmemmap_optimized`. [F19]
- When `demote_free_hugetlb_folios()` splits a folio, each `new_folio` must have `new_folio->mapping = NULL`, `init_new_hugetlb_folio(new_folio)` called, `folio_set_hugetlb_cma(new_folio)` propagated if the source had `HPG_cma`, and `split_page_owner()` / `pgalloc_tag_split()` passed both `huge_page_order(src)` and `huge_page_order(dst)`. [F57, F63]

## Known Pitfalls

- Because `hugetlb_vma_trylock_write(vma)` acquires `resv_map->rw_sema` on private VMAs and returns `1`, callers operating only on shareable-locked VMAs (such as `hugetlb_vmdelete_list()`) must check `__vma_shareable_lock(vma)` after trylocking and still call `hugetlb_vma_unlock_write(vma)` when skipping. [F31]
- Because `hugetlbfs_file_mmap()` sets `VM_HUGETLB` before validating alignment and reservations, `do_mmap()` error teardown can invoke `__hugetlb_zap_begin()` and `__hugetlb_zap_end()` with `vma->vm_file == NULL`, so both must guard against `!vma->vm_file`. [F52]
- Page-cache XArray operations (`__filemap_add_folio()`, `filemap_get_folio()`, `filemap_lock_folio()`, `folio->index`) use `PAGE_SIZE` indices (`idx << huge_page_order(h)`), whereas `filemap_lock_hugetlb_folio()`, `hugetlb_add_to_page_cache()`, `hugetlb_fault_mutex_hash()`, and `resv_map` use huge-page indices. [F101]
- In `hugetlb_change_protection()`, check `pte_marker_uffd_wp(pte) && uffd_wp_resolve` inside the `is_pte_marker(pte)` branch before `huge_pte_clear()` so `PTE_MARKER_POISONED` markers are not cleared; in `hugetlb_fault()`, filter out `PTE_MARKER_POISONED` and `PTE_MARKER_GUARD` in the `huge_pte_none_mostly(vmf.orig_pte)` branch before `hugetlb_no_page()`. [F115, F116]
- In `hugetlb_mfill_atomic_pte()`, when `is_continue` (`MFILL_ATOMIC_CONTINUE`) is true, the folio is already in the pagecache (`folio_in_pagecache = true`) and must skip `__folio_mark_uptodate()`, `hugetlb_add_to_page_cache()`, `folio_set_hugetlb_migratable()`, and `restore_reserve_on_error()`. [F119]
- Bound NUMA node ID loops and array allocations (`gather_bootmem_prealloc()`, `kobj_to_node_hstate()`, `hugetlb_cgroup_css_alloc()`) by `nr_node_ids` rather than `num_node_state(N_MEMORY)` or `num_online_nodes()`. [F99]
