# ENERGY MODEL

The Energy Model (EM) subsystem manages device and CPU performance domains (`struct em_perf_domain`), storing performance states (frequency, power, performance capacity, cost, and efficiency flags) in RCU-protected runtime-modifiable tables (`struct em_perf_table`). It provides energy estimation helpers (`em_cpu_energy()`, `em_pd_get_efficient_state()`) consumed by the Energy Aware Scheduler (EAS), thermal/cooling subsystems, and CPUFreq, as well as APIs to register, unregister, and dynamically update performance domains and frequency limits.

## Architecture & Data Flow
- `em_create_pd()` allocates trailing `cpumask_size()` bytes for the flexible array `struct em_perf_domain::cpus[]` only when `_is_cpu_device(dev)` is true, and `em_init_performance()` / `em_compute_costs()` return early when `!_is_cpu_device(dev)` (leaving `performance` and `cost` zero). Therefore `pd->cpus`, `em_span_cpus(pd)`, and `em_cpu_energy()` must never be used on non-CPU domains. [F18, F53]
- `em_perf_domain::min_perf_state` and `max_perf_state` are 0-based inclusive indices into `em_perf_table::state[]` satisfying `0 <= min_perf_state <= max_perf_state < nr_perf_states`. `em_pd_get_efficient_state()` iterates `i` from `min_ps` through `max_ps` inclusive and must return `max_ps` (not the post-loop cursor `i`, which is `max_ps + 1`) on loop fallthrough. [F36, F43]
- In `em_compute_costs()`, the reverse loop over `table[i]` initializes `prev_cost = ULONG_MAX` and updates `prev_cost = table[i].cost` only in the `else` branch when `table[i].cost < prev_cost`, ensuring all consecutive states with `cost >=` a higher-frequency state's cost are marked `EM_PERF_STATE_INEFFICIENT`. Broken by: updating `prev_cost` unconditionally on every iteration. [F40]
- When registering or replacing `pd->em_table` in `em_dev_register_pd_no_update()` or `em_dev_update_perf_domain()`, `em_cpufreq_update_efficiencies()` must be called to mark `EM_PERF_STATE_INEFFICIENT` frequencies in the CPUFreq policy and set `EM_PERF_DOMAIN_SKIP_INEFFICIENCIES` on `pd->flags` only if at least one was marked. [F27]
- In `em_create_perf_table()`, `em_compute_costs()`, and `em_create_pd()`, per-state `power` and callback-supplied `cost` must be validated in `(0, EM_MAX_POWER]` and CPU domain weight must not exceed `EM_MAX_NUM_CPUS` so that `table[i].power * 10` and `ps->cost * sum_util` in `em_cpu_energy()` do not overflow 32-bit `unsigned long`. [F50]
- `em_create_perf_table()` enforces `freq > prev_freq` starting from `prev_freq = 0` across all `nr_states > 0` entries, guaranteeing every `table[i].frequency` (including `fmax = table[nr_states - 1].frequency`) is strictly positive before `em_init_performance()` divides by `fmax`. [F51]

## Synchronization
- Callers of `em_perf_state_from_pd()` and `em_cpu_energy()` must hold `rcu_read_lock()` across the call and for the entire duration that a returned `struct em_perf_state *` is accessed, because replaced `struct em_perf_table` instances are freed via `kfree_rcu()`. Readers must never cache interior `struct em_perf_state *` pointers across RCU critical sections (e.g., `struct em_dbg_info` stores `pd` and `ps_id` and re-resolves under `rcu_read_lock()`). [F10, F28]
- Runtime modifications to performance states (such as in `em_adjust_new_capacity()` and `em_dev_update_chip_binning()`) must never mutate the active `pd->em_table->state` array in place; they must clone the table via `em_table_dup()`, modify the private copy, and publish it via `em_recalc_and_update()` or `em_dev_update_perf_domain()`. [F29]
- Writer-side accesses and replacements of `pd->em_table` in `em_dev_update_perf_domain()`, `em_dev_register_pd_no_update()`, and `em_dev_unregister_perf_domain()` must be serialized under `em_pd_mutex`, using `rcu_dereference_protected()` to read the current table and `rcu_assign_pointer()` to publish a new table. [F11]
- `em_dev_update_perf_domain()`, `em_dev_register_pd_no_update()`, `em_dev_register_perf_domain()`, `em_dev_unregister_perf_domain()`, and `em_update_performance_limits()` acquire the sleeping `em_pd_mutex` and must not be called from atomic or non-sleeping contexts. [F64]
- `em_rebuild_sched_domains()` must schedule `rebuild_sched_domains_energy()` asynchronously via `rebuild_sd_work` rather than calling it directly, because callers on the `cpufreq_register_driver()` path already hold `cpu_hotplug_lock`. [F13]

## Object Lifetimes
- `em_dev_update_perf_domain()` acquires its own reference to `new_table` via `kref_get(&new_table->kref)` on success and never consumes the caller's reference on success or failure; callers of `em_table_alloc()` or `em_table_dup()` (including `em_dev_update_chip_binning()` and `em_recalc_and_update()`) must always call `em_table_free()` on every exit path to drop their initial reference. [F1, F26]
- In `em_dev_update_perf_domain()`, `kref_get(&new_table->kref)` must execute before `em_table_free(old_table)` so that updating a domain with its already-installed `em_perf_table` (`new_table == old_table`) does not drop `kref` to zero and schedule `kfree_rcu()`. [F2]
- `em_dev_unregister_perf_domain()` must under `em_pd_mutex` remove debugfs files (`em_debug_remove_pd()`), release `dev->em_pd->em_table` via `em_table_free()`, free `dev->em_pd`, and set `dev->em_pd = NULL`. [F6]
- Because `em_debug_create_pd()` allocates the `struct em_dbg_info` array via `devm_kcalloc(dev, ...)` while `dev->em_pd`, `pd->em_table`, and the debugfs directory are manually managed, drivers for non-CPU devices must call `em_dev_unregister_perf_domain(dev)` before devres cleanup completes on unbind. [F60]
- Every `struct cpufreq_policy` reference acquired via `cpufreq_cpu_get()` in `em_cpufreq_update_efficiencies()` and `em_check_capacity_update()` must be released with `cpufreq_cpu_put(policy)` before returning or advancing to the next loop iteration. [F4]
- `em_check_capacity_update()` must free `cpu_done_mask` via `free_cpumask_var(cpu_done_mask)` on every exit path after `zalloc_cpumask_var(&cpu_done_mask, GFP_KERNEL)` succeeds. [F9]

## API Contracts
- `em_dev_unregister_perf_domain()` must return early without freeing `dev->em_pd` when `_is_cpu_device(dev)` is true, because a CPU performance domain is shared across all `cpu_dev->em_pd` pointers in its cpumask and accessed by the scheduler without domain teardown synchronization. [F7]
- Before calling `em_dev_compute_costs()` or `em_compute_costs()` on a non-artificial CPU domain, every `table[i].performance` must be non-zero and `table[i].flags` must be zeroed (e.g. by `em_table_alloc()`), as `em_compute_costs()` divides by `performance` and only writes `flags` when `cost >= prev_cost`. `em_dev_update_perf_domain()` must only be called from a sleeping context, and for non-artificial CPU domains the caller must populate `cost` and `EM_PERF_STATE_INEFFICIENT` flags in `new_table->state` before publishing `new_table`. [F15, F20]
- `em_table_alloc()` and `em_table_dup()` size the trailing `struct em_perf_table::state[]` flexible array and `memcpy()` byte count using `sizeof(struct em_perf_state) * pd->nr_perf_states`; `pd->nr_perf_states` must be initialized before `em_table_alloc(pd)` and must match the state count of every table assigned to `pd`. [F54]
- `em_cpu_energy()` expects `@max_util` to already be mapped from CPU utilization to effective performance (such as by `sugov_effective_cpu_perf()`) and must clamp `@max_util` to `@allowed_cpu_cap` without calling `map_util_perf()` again. [F16]
- `em_dev_register_pd_no_update()` checks `if (microwatts) ... else if (cb->get_cost)` (making `EM_PERF_DOMAIN_MICROWATTS` and `EM_PERF_DOMAIN_ARTIFICIAL` mutually exclusive and failing with `-EINVAL` if both are false/NULL), and for CPU devices requires a non-NULL `@cpus` mask whose CPUs all have equal `arch_scale_cpu_capacity(cpu)` and no existing EM (`em_cpu_get(cpu) == NULL`). [F22, F46]
- In `struct em_data_callback`, `active_power` is mandatory while `get_cost` is optional. Both are invoked in process context under `em_pd_mutex` during `em_dev_register_pd_no_update()`, so they may sleep but must not recursively acquire `em_pd_mutex`. `cb->active_power(dev, &power, &freq)` is called with `@freq` incremented by 1 kHz after each iteration and must return `0`, update `@freq` to a strictly increasing kHz value, and set `@power` in `(0, EM_MAX_POWER]`. [F21, F65, F70]
- `em_update_performance_limits()` requires both `@freq_min_khz` and `@freq_max_khz` to exactly match entries in `pd->em_table->state[].frequency` with `min_ps <= max_ps` before updating `pd->min_perf_state` and `pd->max_perf_state`, returning `-EINVAL` without modifying `pd` otherwise. [F23]
- CPU performance domain registration must keep `em_dev_register_pd_no_update()` separate from `em_dev_register_perf_domain()` so callers managing capacity themselves do not invoke `em_check_capacity_update()`, which reschedules `em_update_work` every 1000ms whenever any CPU in `cpu_possible_mask` lacks a CPUFreq policy. [F33]
- Every public function and callback macro declared under `#ifdef CONFIG_ENERGY_MODEL` in `include/linux/energy_model.h` must have a corresponding no-op or error-returning stub in the `#else` branch. [F77]

## Error Handling
- In `em_create_pd()`, `dev->em_pd` and per-CPU `cpu_dev->em_pd` pointers must only be assigned after `pd` allocation, `em_table_alloc()`, and `em_create_perf_table()` succeed, and errors after `em_table_alloc()` must free `em_table` and `pd` in reverse order. [F5]
- `em_compute_costs()` is called with `cb == NULL` from `em_dev_compute_costs()` and `em_recalc_and_update()`, so dereferencing `cb->get_cost` inside `em_compute_costs()` must be gated on `flags & EM_PERF_DOMAIN_ARTIFICIAL`, and `em_recalc_and_update()` must skip `em_compute_costs()` when `em_is_artificial(pd)` is true. [F19]
- In `em_check_capacity_update()`, when `cpufreq_cpu_get(cpu)` returns `NULL` during `for_each_possible_cpu(cpu)`, the loop must increment `failed_cpus` and `continue` rather than breaking or returning early, so all subsequent online CPUs' performance domains are updated before `em_update_work` is scheduled. [F41]
- `em_pd_get()`, `em_dev_unregister_perf_domain()`, and `em_dev_update_chip_binning()` must check `IS_ERR_OR_NULL(dev)` rather than just `!dev` before dereferencing `@dev`. [F24]
- In the scheduler hot path, `em_cpu_energy()` uses `WARN_ONCE(!rcu_read_lock_held(), ...)` to report RCU locking violations at most once, while registration and runtime update paths report invalid driver/OPP inputs via `dev_err()`/`dev_warn()` and return error codes without `WARN_ON`/`BUG_ON`. [F78]

## External Contracts
- `em_debug_init()` must be registered at `fs_initcall` or later (not `core_initcall`) so that debugfs is initialized before `debugfs_create_dir("energy_model", NULL)` is called, while still running before device drivers register performance domains. [F76]

## Known Pitfalls
- In `em_init_performance()`, `max_cap` (`arch_scale_cpu_capacity(cpu)`) and `fmax` (`table[nr_states - 1].frequency`) must be widened to `u64` and divided using `div64_u64(max_cap * table[i].frequency, fmax)` so that `max_cap * table[i].frequency` does not overflow 32-bit `unsigned long` and 64-bit division links on 32-bit targets. [F47]
- When computing `table[i].cost` for non-artificial domains in `em_compute_costs()`, `table[i].power` must be pre-multiplied by 10 (`power_res = table[i].power * 10`) before dividing by `table[i].performance` to preserve precision against integer division truncation. [F52]
- `em_debug_cpus_show()` passes `s->private` directly to `to_cpumask()`, whereas `em_debug_flags_show()` casts `s->private` to `struct em_perf_domain *`, so `debugfs_create_file()` for `em_debug_cpus_fops` in `em_debug_create_pd()` must pass `dev->em_pd->cpus` as private data rather than `dev->em_pd`. [F55]
- In `em_debug_create_ps()`, `char name[24]` is sized to the exact maximum byte length of `"ps:%lu"` for a 64-bit `unsigned long` (3 prefix bytes + 20 decimal digits + 1 NUL terminator); any expansion of the format string requires enlarging `name`. [F56]
