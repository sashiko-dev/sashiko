# SOFTWARE RAID (Multiple Disks) SUPPORT

This component implements the Linux MD RAID-4, RAID-5, and RAID-6 personalities (`drivers/md/raid5.c`, `drivers/md/raid5.h`), parity/syndrome calculation interfaces (`include/linux/raid/pq.h`, `include/linux/raid/xor.h`), autodetect declarations (`include/linux/raid/detect.h`), and UAPI superblock, journal/PPL, and ioctl definitions (`include/uapi/linux/raid/md_p.h`, `include/uapi/linux/raid/md_u.h`).

## Architecture & Data Flow

- On a batch head stripe, `sh->batch_head == sh`, so lone/head checks must test `(!sh->batch_head || sh == sh->batch_head)` and member checks must test `(sh->batch_head && sh != sh->batch_head)`. In `break_stripe_batch_list()`, resetting `sh->state` via `set_mask_bits()` must preserve `STRIPE_EXPAND_SYNC_FLAGS`, `STRIPE_PREREAD_ACTIVE`, and `STRIPE_ON_UNPLUG_LIST` before clearing `sh->batch_head` under `sh->stripe_lock` and calling `raid5_release_stripe(sh)`. [F3, F89]
- Shared RAID-4/5/6 code must check `sh->qd_idx >= 0` or `conf->level == 6` (or `s.q_failed`) before indexing `sh->dev[sh->qd_idx]` because `sh->qd_idx == -1` on RAID-4/5. Conversely, loops over `sh->dev[]` inspecting data-disk `dev[].sector` or counting non-overwritten data blocks (`stripe_ahead_of_reshape()`, `add_all_stripe_bios()`, `need_this_block()`, `handle_stripe_dirtying()`) must skip both `sh->pd_idx` and `sh->qd_idx`. [F50, F95]
- `need_this_block()` and `handle_stripe_dirtying()` must use identical conditions when forcing reconstruct-write (RCW) over RMW. In `handle_stripe_dirtying()`, forcing RCW (`rcw = 1; rmw = 2;`) at or beyond `mddev->resync_offset` requires `s->failed == 0`, entering the RCW pre-read branch must reset `rcw = 0` before recounting, and if `rcw > disks && rmw > disks` without `STRIPE_PREREAD_ACTIVE`, `STRIPE_DELAYED` must be set. [F62, F96, F97]
- `handle_stripe_dirtying()` may call `schedule_reconstruction()` while `STRIPE_COMPUTE_RUN` is set only if `s->req_compute` was set in the same `handle_stripe()` pass. Whenever `STRIPE_OP_COMPUTE_BLK` is scheduled (`fetch_block()`, `handle_parity_checks5/6()`), both `sh->ops.target` and `sh->ops.target2` must be initialized, setting any unused slot to `-1`. [F51, F74]
- When zero-copy write (`R5_SkipCopy`) aliases a bio page into `dev->page` in `ops_run_biodrain()`, `R5_UPTODATE` and `R5_OVERWRITE` must be cleared (and kept clear in `ops_complete_reconstruct()`), and `dev->page` restored to `dev->orig_page` when completing/failing `dev->written`. When discard bios complete in `handle_stripe_clean_event()`, `R5_Discard` and `R5_UPTODATE` must be cleared and every batched stripe unhashed via `remove_hash(sh)` under `conf->hash_locks[hash]`. [F67, F151]
- In `handle_stripe()`, leaving `reconstruct_state_drain_result` or `reconstruct_state_prexor_drain_result` must not set `STRIPE_INSYNC` when `prexor != 0` or `s.failed > 1`. In `handle_stripe_fill()`, skipping `fetch_block()` to flush journaled degraded data requires `s->to_read && s->injournal && s->failed`, and the loop must `break` when `fetch_block()` returns `1`. In `delay_towrite()`, delaying for `R5C_LOG_CRITICAL` or `s->log_failed` requires `s->injournal > 0`. [F98, F99, F102]
- Starting a parity check (`sh->check_state = check_state_run`) in `handle_parity_checks5/6()` must clear `R5_UPTODATE` on `sh->dev[sh->pd_idx].flags`, decrement `s->uptodate`, and (on RAID-6) zero `sh->ops.zero_sum_result`. In `raid5_end_read_request()`, a read error on a RAID-6 P disk (`sh->qd_idx >= 0 && sh->pd_idx == i`) must set `R5_ReadError` immediately rather than retrying with `R5_ReadNoMerge`. [F58, F73]
- `struct stripe_head` unions `log_io` and `ppl_io`; code must discriminate via `conf->log` / `raid5_has_log(conf)` vs `raid5_has_ppl(conf)` and never set both `MD_HAS_JOURNAL` and `MD_HAS_PPL`. In `raid5_error()`, `Faulty` must be set, `In_sync` cleared, and `mddev->degraded` updated via `raid5_calc_degraded(conf)` under `conf->device_lock`, setting `MD_BROKEN` if `has_failed(conf)`. [F49, F57]
- Before first releasing a new `stripe_head` in `grow_one_stripe()` or `resize_stripes()`, set `sh->hash_lock_index` and increment `conf->active_stripes`. Removing a stripe with `sh->group != NULL` from `handle_list`/`loprio_list` (`find_get_stripe()`, `__get_priority_stripe()`) must decrement `sh->group->stripes_cnt` and clear `sh->group` under `conf->device_lock`. Transitions of `conf->inactive_list + hash` between empty and non-empty must update `conf->empty_inactive_list_nr` in lockstep. [F16, F19, F71]
- `conf->active_aligned_reads` incremented in `raid5_read_one_chunk()` must be decremented on success in `raid5_align_endio()` or, if queued via `add_bio_to_retry()`, upon completion in `retry_aligned_read()`. Every `md_write_inc()` in `__add_stripe_bio()` and `make_discard_request()` must be balanced by `md_write_end()` before `bio_endio()`/`bio_io_error()` in `handle_stripe_clean_event()` and `handle_failed_stripe()`. [F15, F155]
- `check_reshape()` must call `resize_chunks()` and `resize_stripes()` before `raid5_start_reshape()` grows `raid_disks` or `chunk_sectors`, and neither may shrink `scribble_disks`, `scribble_sectors`, or `pool_size`. `grow_stripes()`/`resize_stripes()` must size `stripe_head` slabs with `struct_size_t(struct stripe_head, dev, devs)` for `max(raid_disks, previous_raid_disks)`. `scribble_alloc()` must allocate `chunk_sectors / RAID5_STRIPE_SECTORS(conf)` objects of `num + 2` elements each, updating `scribble_disks`/`scribble_sectors` only after all CPUs succeed. [F60, F86, F116, F117]
- `analyse_stripe()` must `memset(s, 0, sizeof(*s))` and set `s->failed_num[0..1] = -1`; for `R5_WriteError` and `R5_MadeGood` it must use `conf->disks[i].rdev` rather than local `rdev` (which may be `replacement`). All `raid5_attrs` sysfs handlers must check `if (!conf)` before dereferencing `mddev->private`. `drop_one_stripe()` must compute `hash` as `(conf->max_nr_stripes - 1) & STRIPE_HASH_LOCKS_MASK` rather than `%`. [F48, F52, F78, F106]

## Synchronization

- `conf->device_lock` and `conf->hash_locks` are taken in IRQ bio completion callbacks, so process context must use `_irq`/`_irqsave`. `conf->hash_locks[hash]` must be acquired before `conf->device_lock` (ascending `0..NR_STRIPE_HASH_LOCKS-1` in `lock_all_device_hash_locks_irq()`). All mutations to `stripe_hashtbl` and `inactive_list[hash]` require `conf->hash_locks[hash]`. [F24, F30, F135]
- In `find_get_stripe()`, if `atomic_inc_not_zero(&sh->count)` fails, acquire `conf->device_lock` (inside `hash_locks[hash]`) and recheck `!atomic_read(&sh->count)` before unlinking `sh->lru`. Each `temp_inactive_list` is appended under `conf->device_lock` and spliced into `conf->inactive_list[hash]` via `release_inactive_stripe_list()` under `conf->hash_locks[hash]` after dropping `device_lock`. [F26, F31]
- `handle_active_stripes()` is called with `conf->device_lock` held and must re-acquire `spin_lock_irq(&conf->device_lock)` before returning. When draining `conf->released_stripes` in `release_stripe_list()` or `cb->list` in `raid5_unplug()`, an `smp_mb()` / `smp_mb__before_atomic()` must precede clearing `STRIPE_ON_RELEASE_LIST` or `STRIPE_ON_UNPLUG_LIST` before `__release_stripe()`. [F13, F39]
- `handle_stripe()` must acquire `test_and_set_bit_lock(STRIPE_ACTIVE, &sh->state)` after `clear_batch_ready(sh)` returns 0 (re-setting `STRIPE_HANDLE` and returning if already active). Bio lists `dev[i].toread`/`towrite` and `sh->overwrite_disks` require `sh->stripe_lock`. `lock_two_stripes()` locks the lower `stripe_head` address first, and in `stripe_add_to_batch_list()`, `head->batch_head->batch_lock` nests inside `stripe_lock` while rechecking `stripe_can_batch(head)` and setting `sh->batch_head`. [F20, F28, F29, F137]
- In `raid5_start_reshape()`, geometry updates, `conf->generation++`, and `conf->reshape_progress` must be written under `conf->device_lock` and `write_seqcount_begin(&conf->gen_lock)` with `smp_mb()` before `reshape_progress`, then cycling `raid5_quiesce()` `true`/`false`. In `end_reshape()`, `md_finish_reshape()` must precede `smp_wmb()` and `conf->reshape_progress = MaxSector` under `device_lock`. `use_new_offset()` must execute `smp_rmb()` after reading `reshape_progress` and before reading `generation` or `data_offset`. [F22, F40, F63, F64]
- In `get_reshape_loc()`, if `reshape_progress != MaxSector`, sample `reshape_progress` and `reshape_safe` under `conf->device_lock` and recheck `reshape_progress == MaxSector` before `ahead_of_reshape()`. In `init_stripe()` and `make_stripe_request()`, protect reshape geometry reads with `read_seqcount_begin(&conf->gen_lock)` / `read_seqcount_retry()`, rechecking `stripe_ahead_of_reshape()` after `raid5_get_active_stripe()` when `previous` is set. [F34, F35]
- `raid5_quiesce(mddev, true)` must use `smp_store_release(&conf->quiesce, 2)` before waiting for `active_stripes` and `active_aligned_reads` to drain, then set `conf->quiesce = 1` and wake `wait_for_reshape`; `raid5_read_one_chunk()` must increment `active_aligned_reads` before checking `smp_load_acquire(&conf->quiesce) != 0`. [F38, F129]
- Handlers mutating stripe size, `skip_copy`, `worker_groups`, or consistency policy require `mddev_suspend_and_lock(mddev)`, and `raid5_store_group_thread_cnt()` must quiesce the array, flush `raid5_wq`, and update `worker_groups` under `conf->device_lock` before freeing `old_groups`. [F131, F159]
- Growing, shrinking, or resizing the stripe cache requires `conf->cache_size_mutex` (`mutex_trylock()` in `raid5_cache_scan()` and `raid5d()`, dropped around `md_allow_write()` in `raid5_set_cache_size()`). `raid5_cache_count()` must read `max_nr_stripes` and `min_nr_stripes` with `READ_ONCE()` and check `max_stripes < min_stripes`. In `resize_stripes()`, update `conf->slab_cache` and `conf->active_name` before calling `raid5_release_stripe(nsh)`. [F18, F25, F37, F142]
- `raid_run_ops()` must hold `local_lock(&conf->percpu->lock)` across `this_cpu_ptr(conf->percpu)` and all `ops_run_*` calls. In `raid5d()`, break immediately when `MD_SB_CHANGE_PENDING` is set in `mddev->sb_flags` without calling `md_check_recovery()` or waiting on `sb_wait`. In `raid5_remove_disk()`, journal removal runs in `raid5d` context, must not sleep, and must return `-EBUSY` if `active_stripes` or cached stripes are non-zero. [F138, F143, F146]

## Object Lifetimes

- Before blocking on `wait_for_quiescent`, `wait_for_stripe`, `wait_for_reshape`, or `R5_Overlap` during bio submission, callers holding `ctx->batch_last` must call `raid5_release_stripe(ctx->batch_last)` and set `ctx->batch_last = NULL`. When `ops_run_io()` submits I/O for a batched member (`sh != head_sh`), it must increment both `sh->count` and `head_sh->count`, and `raid5_end_write_request()` must release `sh->batch_head` before `sh`. [F2, F4]
- In `ops_run_io()`, after incrementing `rdev->nr_pending` for a write, `rdev_has_badblock()` must increment `rdev->nr_pending` again before `md_wait_for_blocked_rdev()` (`bad < 0`), or call `rdev_dec_pending()` and set `rdev = NULL` when skipping (`bad > 0`). Every `rdev->nr_pending` acquired in `analyse_stripe()` (`s->blocked_rdev`, `s->handle_bad_blocks`) must be released in `handle_stripe()` before `clear_bit_unlock(STRIPE_ACTIVE, &sh->state)`. [F5, F8]
- When `schedule_reconstruction()` runs RCW (`rcw != 0`), it must call `r5c_release_extra_page(sh)`. In `raid5_make_request()`, aborting after `md_account_bio(mddev, &bi)` due to `STRIPE_WAIT_RESHAPE` must call `md_free_cloned_bio(bi)` after `md_write_end(mddev)` instead of `bio_endio(bi)`. [F7, F154]
- In `raid5_run()`, once `mddev->thread` and `mddev->private = conf` are set, `abort:` must call `md_unregister_thread(mddev, &mddev->thread)` before `free_conf(conf)` and clear `mddev->private = NULL`. `free_conf()` must call `shrinker_free(conf->shrinker)` before `shrink_stripes(conf)`, and `raid5_free_percpu()` must call `cpuhp_state_remove_instance()` before `free_percpu(conf->percpu)` outside `cpus_read_lock()`. [F9, F125, F140]

## API Contracts

- When `raid5_read_one_chunk()` returns `0` to fall back to stripe cache, it must not call `bio_put()` or `md_account_bio()` on `raid_bio`. In `raid5_make_request()`, `REQ_PREFLUSH` handling must check `log_handle_flush_request()` (`0`, `-ENODEV`, `-EAGAIN`) and, on `-ENODEV`, continue processing `bi` when `md_flush_request(mddev, bi)` returns `false`. [F1, F47]
- Callers of `raid5_get_active_stripe()` with `R5_GAS_NOBLOCK` must NULL-check the return. `grow_one_stripe()`/`drop_one_stripe()` return `1` on success and `0` on failure, whereas `grow_stripes()`/`grow_buffers()` return `0` on success. In `resize_stripes()`, all allocations between draining `conf->inactive_list` (Step 2) and releasing new stripes (Step 4) must use `GFP_NOIO`. [F44, F45, F141]
- `raid5_compute_sector()` requires a non-NULL `int *dd_idx` and optional `sh`; because callers pass an uninitialized stack `stripe_head` with zero-length `dev[]`, it must only write `sh->pd_idx`, `sh->qd_idx`, and `sh->ddf_layout` and never read `sh` or `sh->dev[]`, while remaining the exact inverse of `raid5_compute_blocknr()`. [F53, F76, F120]
- Loops over `r5dev` bio chains (`toread`, `read`, `towrite`, `written`) must bound `bi->bi_iter.bi_sector < dev->sector + RAID5_STRIPE_SECTORS(conf)` and advance via `r5_next_bio(conf, bi, dev->sector)` before `bio_endio()`/`bio_io_error()`, never raw `bi->bi_next`. `release_inactive_stripe_list()` requires an array of `NR_STRIPE_HASH_LOCKS` lists when `hash == NR_STRIPE_HASH_LOCKS`, and reads only `temp_inactive_list[0]` when `hash < NR_STRIPE_HASH_LOCKS`. Store `rdev_has_badblock()` in a signed `int` (`< 0`, `> 0`, `0`). [F46, F84, F91]

## Error Handling

- `setup_conf()` returns `ERR_PTR()` (never `NULL`), so callers must check `IS_ERR(conf)`. In `setup_conf()` and `raid5_run()`, after a helper sets `ret = 0` (`bioset_init()`, `raid5_alloc_percpu()`, `raid5_set_limits()`), any later `goto abort` must set `ret` to a negative errno. [F41, F42, F43]
- In `raid5_set_cache_size()`, if `grow_one_stripe()` fails, roll back `conf->min_nr_stripes = conf->max_nr_stripes` under `cache_size_mutex`. In `resize_stripes()`, update `conf->pool_size = newsize` only when `!err`. [F59, F61]

## Known Pitfalls

- Use `sector_div()`, `do_div()`, or `DIV_ROUND_UP_SECTOR_T()` instead of `/` or `%` on `sector_t`/`u64`, passing a copy to `sector_div()` when the dividend is still needed. Cast alignment units (`RAID5_STRIPE_SECTORS(conf)`, `chunk_sectors`, `reshape_sectors`) to `sector_t` before `& ~(align - 1)`. [F107, F112, F113]
- In `batch_list` backward-`goto` loops (`ops_run_io`, `ops_run_biodrain`, `handle_stripe_clean_event`), reset `sh = head_sh` and `dev = &head_sh->dev[i]` on each disk iteration and after `unhash:`. In `ops_run_reconstruct5/6()`, increment `j` per batched stripe for `to_addr_page(percpu, j)` and `to_addr_conv(sh, percpu, j)` while attaching the completion callback only on `last_stripe`; `to_addr_page()` adds byte offsets whereas `to_addr_conv()`/`to_addr_offs()` add `sh->disks + 2` typed elements. [F92, F94, F118]
- If `conf->disks[i].replacement` becomes `NULL` during `raid5_end_read_request()`, `raid5_end_write_request()`, or `R5_MadeGoodRepl`, fall back to `conf->disks[i].rdev`. In `reshape_request()`, clamp forward `readpos`/`safepos` subtractions with `min_t(sector_t, reshape_sectors, ...)`, check `writepos >= reshape_sectors` on backward reshape, and use `time_after()` for `reshape_checkpoint`; in `do_release_stripe()`, test `sh->bm_seq - conf->seq_write > 0`. [F72, F83, F115]
