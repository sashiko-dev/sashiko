# DAMON

DAMON (Data Access Monitor) is a Linux kernel memory management subsystem that monitors memory access patterns using adaptive region splitting/merging and sampling, and applies DAMOS (DAMON-based Operation Schemes) actions such as page reclamation, LRU sorting, madvise, and NUMA page migration. It provides a core monitoring framework with pluggable address-space operation sets for virtual (`vaddr`, `fvaddr`) and physical (`paddr`) memory, a hierarchical sysfs control interface (`/sys/kernel/mm/damon/admin`), and standalone kernel module policies (`damon_reclaim`, `damon_lru_sort`, and `damon_stat`).

## Architecture & Data Flow

- In `damon_commit_ctx(dst, src)`, `damon_commit_schemes()` and `damon_commit_targets()` must run before `damon_set_attrs(dst, &src->attrs)` and `dst->ops = src->ops` so target PID cleanup uses `dst`'s prior ops and `damon_set_attrs()` scales the committed regions and schemes. `damon_set_attrs()` must rescale regions via `damon_update_monitoring_results()` before overwriting `ctx->attrs` and recompute `next_aggregation_sis`, `next_ops_update_sis`, and each scheme's `next_apply_sis` via `damos_set_next_apply_sis()`. [F57, F95]
- Scheme commit helpers (`damos_commit*`) must copy all user-configurable fields while preserving `dst`'s runtime accounting (`quota`, `stat`). `dst->type = src->type` or `dst->metric = src->metric` must be set before `damos_commit_filter_arg()` (`damos_new_filter()` leaves the union uninitialized) or `damos_commit_quota_goal_union()` (which copies only `current_value` for `DAMOS_QUOTA_USER_INPUT` and `nid` for `DAMOS_QUOTA_NODE_MEM_USED_BP`/`FREE_BP`, preserving `dst->last_psi_total`). [F41, F42, F70, F81]
- Adding an `enum damos_filter_type` value requires updating `damos_filter_for_ops()` (routing `damos_add_filter()` between `s->filters` and `s->ops_filters`), the matcher, `damos_commit_filter_arg()`, `damos_sysfs_filter_type_names[]`, and `damon_sysfs_add_scheme_filters()`. [F76]
- In `damos_set_filters_default_reject()`, if `s->ops_filters` is non-empty, `s->core_filters_default_reject` must be forced to `false` so unmatched regions reach the ops filter stage. When `damos_filter_out()` matches a core filter with `filter->allow`, it sets `s->core_filters_allowed = true`, and ops evaluators (`damos_va_filter_out()`, `damos_pa_filter_out()`) must check `scheme->core_filters_allowed` first and return `false` before iterating `scheme->ops_filters`. [F77, F78]
- In `struct damos`, `migrate_dests.nr_dests == 0` selects single-node migration using `s->target_nid` instead of `dests->node_id_arr` or `weight_arr`. `damos_va_migrate()` must allocate `priv.migration_lists` with `dests->nr_dests == 0 ? 1 : dests->nr_dests` elements because `damos_va_migrate_dests_add()` indexes `migration_lists[0]` when `nr_dests` is 0. [F43, F116]
- Because `damon_attrs->sample_interval` may be 0, core interval-to-sample-count divisions must substitute `1` when `sample_interval == 0`. Whenever `s->apply_interval_us == 0`, interval calculations (`damos_set_next_apply_sis()`, `kdamond_apply_schemes()`, `kdamond_init_ctx()`) must substitute `ctx->attrs.aggr_interval` rather than `sample_interval` or `0`. [F80, F102]
- Whenever `struct damon_region` access counts change (`damon_update_region_access_rate()`, `damon_merge_two_regions()`, `damon_split_region_at()`, `damon_update_monitoring_result()`), `r->nr_accesses_bp` must be updated in lockstep so it equals `r->nr_accesses * 10000` at aggregation reset. [F56]
- When `damos_adjust_quota()` initializes the first charge window (`!quota->total_charged_sz && !quota->charged_from`), it must call `damos_set_effective_quota(quota)` immediately along with `quota->charged_from = jiffies`. Every `damos_quota_goal` in `quota->goals` must have a non-zero `target_value` (`damos_sysfs_add_quota_score()` skips `!sysfs_goal->target_value`) because `damos_quota_score()` divides by `goal->target_value` unchecked. [F61, F108]
- Functions mapping schemes in a running `damon_ctx` to `sysfs_schemes->schemes_arr` by positional index (`damos_sysfs_set_quota_scores()`, `damos_sysfs_update_effective_quotas()`, `damon_sysfs_schemes_update_stats()`, `damos_sysfs_populate_region_dir()`) must verify `index < sysfs_schemes->nr` before indexing `schemes_arr`. [F153]

## Synchronization

- `__damon_start()` must reinitialize `ctx->kdamond_started` before `kthread_run()` and wait on `wait_for_completion(&ctx->kdamond_started)` under `ctx->kdamond_lock`. `__damon_stop()` must take `get_task_struct()` and drop `ctx->kdamond_lock` (and callers must not hold `damon_lock`) before `kthread_stop_put()`, because `kdamond_fn()` takes both `ctx->kdamond_lock` and `damon_lock` on exit. [F19, F121]
- During `kdamond_fn()` teardown, `ctx->kdamond = NULL` must be set under `ctx->kdamond_lock` before `kdamond_call(ctx, true)` and `damos_walk_cancel(ctx)`, because `damon_call()` and `damos_walk()` enqueue control blocks before checking `damon_is_running(ctx)`. In `kdamond_call()`, a non-repeating `damon_call_control` must be unlinked from `ctx->call_controls` under `ctx->call_controls_lock` before `complete(&control->completion)`, because synchronous callers allocate `damon_call_control` on the stack. [F21, F22]
- `kdamond_apply_schemes()` holds `c->walk_control_lock` continuously across `damon_do_apply_schemes()` and `damos_walk_complete()` so `damos_walk()` cannot install a control mid-walk; `walk_fn` and `apply_scheme` callbacks must never call `damos_walk()` or `damos_walk_cancel()` on the same `damon_ctx`. [F23, F123]
- Sysfs handlers dereferencing `kdamond->damon_ctx` (`state_show()`, `pid_show()`, `state_store()`) must hold `damon_sysfs_lock`. Because `state_store()` holds `damon_sysfs_lock` while waiting on `damon_call()` or `damos_walk()`, repeating callbacks (`damon_sysfs_repeat_call_fn()`) must use `mutex_trylock(&damon_sysfs_lock)`, and synchronous callbacks from `damon_sysfs_handle_cmd()` must not acquire `damon_sysfs_lock`. [F25, F124]
- `damon_sysfs_turn_damon_on()` must set `kdamond->damon_ctx = ctx` before queuing `repeat_call_control` with `damon_call()`. `damon_sysfs_kdamonds_add_dirs()` must verify `!damon_sysfs_kdamonds_busy()` before calling `damon_sysfs_kdamonds_rm_dirs()`. [F27, F28]
- Page table walk callbacks in `mm/damon/vaddr.c` and their callees (`damos_va_filter_out`, `damos_va_migrate_dests_add`) run under page table spinlocks (`ptl`) and must not sleep. `damos_va_filter_out()` must handle `DAMOS_FILTER_TYPE_YOUNG` via `damos_va_filter_young_match()` on the locked `ptep`/`pmdp` rather than `damos_folio_filter_match()` (which does a sleeping `rmap_walk()`). [F127, F128]
- In `damon_mkold_pmd_entry()` and `damon_young_pmd_entry()`, after `pmd_lock(walk->mm, pmd)`, the PMD must be re-read and rechecked for `pmd_present()` and `pmd_trans_huge()`, and `pmd_lock` must be released before `pte_offset_map_lock()`. [F33]
- In `damon_folio_young_one()`, breaking out of `page_vma_mapped_walk(&pvmw)` early requires calling `page_vma_mapped_walk_done(&pvmw)` and returning `*accessed == false` to stop `rmap_walk()`. `damon_folio_mkold()` and `damon_folio_young()` must pair `folio_trylock(folio)` with `folio_unlock(folio)` around `rmap_walk()` whenever `!folio_test_anon(folio) || folio_test_ksm(folio)`. [F16, F79]
- After `damon_get_folio()` calls `folio_try_get(folio)`, it must recheck `page_folio(page) == folio` and `folio_test_lru(folio)`, calling `folio_put()` and returning `NULL` if either fails. `__damon_va_three_regions()` (around `for_each_vma()`) and `damos_folio_filter_match()` (around `folio_memcg_check(folio)`) must hold `rcu_read_lock()`. [F30, F125, F126]

## Object Lifetimes

- `damon_destroy_target(t, ctx)` invokes `ctx->ops.cleanup_target(t)` (calling `put_pid(t->pid)` for `VADDR`/`FVADDR`), whereas `damon_free_target(t)` and `damon_destroy_target(t, NULL)` skip `cleanup_target`. In `damon_commit_target()`, `put_pid(dst->pid)` and `get_pid(src->pid)` must only run after `damon_commit_target_regions()` succeeds. When `damon_commit_targets()` destroys a `dst_target`, it must clear `s->quota.charge_target_from = NULL` and `charge_addr_from = 0` on any scheme referencing it. [F2, F3, F6]
- A repeating `struct damon_call_control` (`control->repeat = true`) is queued asynchronously and must be dynamically allocated per `damon_ctx` (never on the stack or shared statically). When `kdamond_call()` sees `control->canceled && control->dealloc_on_cancel`, it must unlink `control` and `kfree(control)`. Once `damos_walk()` sets `ctx->walk_control`, both `damos_walk_complete()` and `damos_walk_cancel()` must signal `complete(&control->completion)` and reset `ctx->walk_control = NULL`. [F8, F9, F66, F114]
- In sysfs teardown (`damon_sysfs_*_rm_dirs()`), a child directory's `*_rm_dirs()` helper must be called before `kobject_put(&child->kobj)`. `damon_sysfs_turn_damon_off()` retains `kdamond->damon_ctx`, so `damon_sysfs_turn_damon_on()` and `damon_sysfs_kdamond_release()` must call `damon_destroy_ctx(kdamond->damon_ctx)` if non-NULL. `memcg_path_store()` and `damon_sysfs_scheme_filter_release()` must `kfree(filter->memcg_path)` before overwriting or freeing `filter`. [F10, F11, F18]
- When a folio is isolated via `folio_isolate_lru(folio)` (`damon_pa_pageout()`, `damon_pa_migrate()`, `damos_va_migrate_dests_add()`), the caller must still drop its `damon_get_folio()` reference via `folio_put(folio)`. Any isolated folio not consumed by `reclaim_pages()` or `migrate_pages()` (including `folio_test_unevictable(folio)` in `damon_pa_pageout()`, or `ret_folios` and remaining `migrate_folios` in `damon_migrate_folio_list()`) must be returned via `folio_putback_lru()`. [F15, F139, F140]

## API Contracts

- `ctx->kdamond_lock` only protects `ctx->kdamond`; while a `damon_ctx` is running, any external read or update of its internal fields must run on the kdamond thread via `damon_call()` or `damos_walk()`, and configuration updates for `damon_commit_ctx(ctx, param_ctx)` must be staged on `param_ctx` rather than the live `ctx`. [F24, F94]
- `damon_new_scheme()` mutates `@quota` via `damos_quota_init(quota)` and resets `scheme->quota.goals` via `INIT_LIST_HEAD()`, so callers must pass a local copy when reusing a template and call `damos_add_quota_goal()` only after `damon_new_scheme()` returns. [F1, F68]
- `damon_get_folio(pfn)` returns a `struct folio *` with an elevated refcount requiring `folio_put()`, except when `damon_pa_invalid_damos_folio(folio, s)` returns `true` for `folio == s->last_applied` (which calls `folio_put(folio)` itself). Physical-address loops in `mm/damon/paddr.c` must advance `addr` by `folio_size(folio)` when processed and by `PAGE_SIZE` only when rejected. [F14, F134]
- `damon_ctx->addr_unit` must be non-zero (store handlers reject `0`, and `damon_reclaim_apply_parameters()` resets `addr_unit = 1` for default System RAM). `damon_sysfs_apply_inputs()` scales `ctx->min_sz_region = max(DAMON_MIN_REGION / sys_ctx->addr_unit, 1)` only for `DAMON_OPS_PADDR`. `damon_operations->apply_scheme` accumulates into `*sz_filter_passed` via `+=` (`damos_apply_scheme()` must zero-init it), and in `DAMON_OPS_PADDR` both `*sz_filter_passed` and the return value must be scaled via `damon_pa_core_addr()`. [F38, F50, F51, F104, F142]
- Callers of `damon_set_regions()` and `damon_commit_target_regions()` must pass sorted, non-overlapping ranges (`start <= end`, `ranges[i - 1].end <= ranges[i].start`). When `damos_skip_charged_region()` splits a region via `damon_split_region_at()`, it updates `*rp` to `damon_next_region(r)` and returns `false` so the caller processes the uncharged tail; `kdamond_apply_schemes()` and `damon_split_regions_of()` must use `damon_for_each_region_safe()`. [F52, F64, F82]
- `damon_migrate_pages()` must validate `target_nid` (`[0, MAX_NUMNODES)` and `N_MEMORY`), enter `memalloc_noreclaim_save()`, and partition `folio_list` per source node before calling `damon_migrate_folio_list()`. `damos_va_migrate_pmd_entry()` must set `walk->action = ACTION_CONTINUE` on a present THP PMD so `walk_page_range()` does not split it. [F130, F138, F141]

## Error Handling

- In `damon_commit_targets()` and `damon_commit_schemes()`, if committing into `new_target` or `new_scheme` fails, it must be destroyed via `damon_destroy_target(new_target, NULL)` or `damon_destroy_scheme(new_scheme)` before returning. When `damos_commit_dests()` frees `dst_dests->node_id_arr` and `weight_arr` to resize them, it must set `dst_dests->weight_arr = NULL` if allocating `node_id_arr` fails so `damon_destroy_scheme()` does not double-free it. [F4, F44]
- Synchronous (`!control->repeat`) callers of `damon_call()` must check both `damon_call()`'s return value and `control->return_code`. In `__damon_start()`, if `kthread_run()` returns an `ERR_PTR`, `ctx->kdamond` must be reset to `NULL` under `ctx->kdamond_lock`. `damon_sysfs_build_ctx()` always returns an `ERR_PTR` on failure (never `NULL`), so callers must check `IS_ERR()`. [F34, F35, F36]
- In sysfs array builders (`damon_sysfs_*_add_dirs()`), `->nr` must be incremented only after both `kobject_init_and_add()` and child `*_add_dirs()` succeed so error cleanup only runs `*_rm_dirs()` on `[0, ->nr)`. [F45]

## Known Pitfalls

- In `kdamond_fn()`, `ctx->next_aggregation_sis` must be sampled at loop start and restored before `kdamond_tune_intervals()`. Comparisons of `ctx->passed_sample_intervals` against target interval counters (`next_aggregation_sis`, `next_ops_update_sis`, `next_intervals_tune_sis`, `s->next_apply_sis`) must use `>=` or `<`, never `==` or `!=`. [F59, F110]
- In `damos_va_stat_pmd_entry()`, the PTE loop must save `start_pte` for `pte_unmap_unlock(start_pte, ptl)`, initialize `nr = 1` at the start of every iteration before any `continue`, and advance `pte += nr` and `addr += nr * PAGE_SIZE`. PMD walk callbacks in `mm/damon/vaddr.c` must return `0` when `pte_offset_map_lock()` fails and never set `walk->action = ACTION_AGAIN`. [F90, F93, F117]
- In `damos_va_migrate_dests_add()`, when `dests->nr_dests` is non-zero, both `!weight_total` (before `ilx % weight_total`) and `folio_nid(folio) == dests->node_id_arr[i]` must be checked before `folio_isolate_lru(folio)`. [F74, F112]
- `damon_va_check_accesses()` must reset `same_target = false` per target so `__damon_va_check_access()` does not reuse static cached address state across address spaces. In two-pass list commits (`damos_commit_ops_filters()`, `damos_commit_core_filters()`), pass 1 must index the matching source list (`damos_nth_ops_filter(i++, src)`) and pass 2 must skip updated entries via `if (j++ < i) continue`. [F69, F85]
