# SECURE DIGITAL HOST CONTROLLER INTERFACE (SDHCI) DRIVER

This component contains the SDHCI bus glue and vendor-specific host controller drivers for PCI (`sdhci-pci-core.c`, `sdhci-pci-gli.c`, `sdhci-pci-o2micro.c`, `sdhci-pci-arasan.c`), ACPI (`sdhci-acpi.c`), and platform/Device Tree (`sdhci-pltfm.c`, `sdhci-of-dwcmshc.c`, `sdhci-of-esdhc.c`, `sdhci-cadence.c`, `sdhci-iproc.c`, `sdhci-pxav2.c`, `sdhci-pxav3.c`, etc.). These drivers allocate and configure `sdhci_host` instances, supply hardware-specific `sdhci_ops`, `mmc_host_ops`, and `cqhci_host_ops` callbacks, apply silicon quirks, and manage clocks, PHY tuning, DMA descriptors, and power management transitions.

## Architecture & Data Flow
- Bus drvdata and `____cacheline_aligned` `private[]` layouts differ by bus: on platform (`sdhci_pltfm_init`), drvdata is `struct sdhci_host *`, `sdhci_priv(host)` is `struct sdhci_pltfm_host *`, and vendor priv is `sdhci_pltfm_priv(pltfm_host)`; on PCI, drvdata is `struct sdhci_pci_chip *`, `sdhci_priv(host)` is `struct sdhci_pci_slot *`, and vendor priv is `sdhci_pci_priv(slot)`; on ACPI, drvdata is `struct sdhci_acpi_host *` (`== sdhci_priv(host)`), and shared code must check `c->is_intel` before casting `sdhci_acpi_priv(c)` to `struct intel_host *`. [F125, F126, F127, F157]
- In `sdhci_be32bs_writew` and `esdhc_writew_fixup` (`esdhc_be_writew`/`esdhc_le_writew`), 16-bit writes to `SDHCI_TRANSFER_MODE` must be deferred in `pltfm_host->xfer_mode_shadow` (returned by `esdhc_readw_fixup`) and flushed with `SDHCI_COMMAND` as one 32-bit write; similarly, `sdhci_iproc_writew`/`sdhci_iproc_readw` must shadow `SDHCI_BLOCK_SIZE`, `SDHCI_BLOCK_COUNT`, and `SDHCI_TRANSFER_MODE` in `shadow_blk` (`is_blk_shadowed`) and `shadow_cmd` (`is_cmd_shadowed`), reading from shadows while active and flushing as 32-bit writes on `SDHCI_COMMAND`. [F57, F59]
- In sub-32-bit accessors (`elba_write_w`, `elba_write_b`, `esdhc_writew_fixup`, `esdhc_writeb_fixup`, `sdhci_be32bs_writew`, `sdhci_be32bs_writeb`, `REG_OFFSET_IN_BITS`), `reg` must be masked to its low byte-offset bits before shifting; `sdhci_be32bs_readw` and `sdhci_be32bs_readb` must XOR `reg` with `0x2` and `0x3`, and GL9750/GL9755 (`sdhci_gl9750_ops`, `sdhci_gl9755_ops`) must read 16/8-bit registers via 32-bit aligned `readl(host->ioaddr + (reg & ~3)) >> REG_OFFSET_IN_BITS(reg)` (`sdhci_gli_readw`/`sdhci_gli_readb`). [F92, F94, F118]
- Because `sdhci_cdns_probe` stores base MMIO in `priv->hrs_addr` and offsets `host->ioaddr += SDHCI_CDNS_SRS_BASE` (`0x200`), all `SDHCI_CDNS_HRS*` accesses must use `priv->hrs_addr` (never `host->ioaddr` or `sdhci_readl`/`sdhci_writel`). Also in `sdhci_cdns_probe`, `priv_size` passed to `sdhci_pltfm_init` must use `struct_size(priv, phy_params, nr_phy_params)` from `sdhci_cdns_phy_param_count(dev->of_node)`, and `priv->hrs_addr`, `priv->priv_writel`, and `data->init(pdev)` must be initialized before `sdhci_cdns_phy_init(priv)` or `__sdhci_read_caps()`. [F44, F119, F124]
- Because `dwcmshc_adma_write_desc` and `sdhci_sparx5_adma_write_desc` split DMA transfers spanning a `SZ_128M` boundary into two descriptors, `dwcmshc_probe` and `sdhci_sparx5_probe` must add `min(DIV_ROUND_UP_ULL(dma_get_required_mask(dev), SZ_128M), SDHCI_MAX_SEGS)` to `host->adma_table_cnt` before `sdhci_setup_host`. In `dwcmshc_adma_write_desc`, `dwcmshc_set_tran_desc`, and `sdhci_sparx5_adma_write_desc`, `!len` must be checked before `BOUNDARY_OK(addr, len)` to avoid `addr + len - 1` underflow when `len == 0`. [F68, F111]
- In `dwcmshc_probe()`, `priv->vendor_specific_area1` must be read from `DWCMSHC_P_VENDOR_AREA1` before `pltfm_data->init()`, and `priv->vendor_specific_area2` from `DWCMSHC_P_VENDOR_AREA2` before `dwcmshc_cqhci_init()`. In `dwcmshc_request`, `dwcmshc_check_auto_cmd23` must clear `SDHCI_AUTO_CMD23` when `mrq->sbc && (mrq->sbc->arg & SDHCI_DWCMSHC_ARG2_STUFF)` and set `SDHCI_AUTO_CMD23` otherwise. [F45, F56]
- In `esdhc_reset`, when `mask & SDHCI_RESET_DATA` is set on `esdhc->vendor_ver <= VENDOR_V_22`, the driver must save `ESDHC_CTRL_BUSWIDTH_MASK` from `ESDHC_PROCTL` before `sdhci_reset(host, mask)` and restore both it and `host->ier` (`SDHCI_INT_ENABLE`/`SDHCI_SIGNAL_ENABLE`) afterward; conversely, advertising `SDHCI_CAN_DO_ADMA2` in `esdhc_readl_fixup()` and polling `ESDHC_CLOCK_STABLE` in `esdhc_clock_enable()` and `esdhc_of_set_clock()` must be gated on `esdhc->vendor_ver > VENDOR_V_22`. [F60, F135]
- In `esdhc_of_set_clock()`, `esdhc_tuning_block_enable()`, and `esdhc_set_uhs_signaling()`, whenever `esdhc_clock_enable(host, false)` gates the clock (when `clock != 0`), the sequence must re-enable it with `esdhc_clock_enable(host, true)`. In `esdhc_set_uhs_signaling`, if `ESDHC_HS400_MODE` is set in `ESDHC_TBCTL`, the driver must clear `ESDHC_FLW_CTL_BG`, `ESDHC_CMD_CLK_CTL`, `ESDHC_HS400_MODE` (with clock disabled), `ESDHC_DLL_ENABLE | ESDHC_DLL_FREQ_SEL`, and `ESDHC_HS400_WNDW_ADJUST`, and disable the tuning block before configuring a new speed mode. [F62, F97]
- In `amd_sdhci_reset`, when `mask & SDHCI_RESET_ALL` is set, the driver must clear `amd_host->tuned_clock` and call `sdhci_acpi_amd_hs400_dll(host, false)` so subsequent `amd_set_ios` calls re-enable the DLL. In `amd_set_ios`, whenever `host->timing` changes while `amd_host->tuned_clock` is true, `SDHCI_CTRL_TUNED_CLK` in `SDHCI_HOST_CONTROL2` must be set if `host->timing` is `MMC_TIMING_MMC_HS400` or `MMC_TIMING_MMC_HS200` and cleared for any other timing mode (including `MMC_TIMING_MMC_DDR52`). [F52, F53]
- In `sdhci-pci-core.c`, `chip->fixes` and every member in `struct sdhci_pci_fixes` are optional (`chip->fixes && chip->fixes->...`), as are `c->slot`, `c->slot->chip`, and all `c->slot` callbacks in `sdhci-acpi.c`. In `sdhci_pci_probe` and `sdhci_pci_probe_slot`, `chip->allow_runtime_pm` is copied from `chip->fixes->allow_runtime_pm` and cleared if `chip->fixes->own_cd_for_runtime_pm` is true but `slot->cd_idx < 0`. [F36, F37, F66]

## Synchronization
- `sdhci_ops.reset` callbacks (`esdhc_reset`, `sdhci_gl9755_reset`, `sdhci_gl9767_reset`, `sdhci_milbeaut_reset`, `rk35xx_sdhci_reset`, `th1520_sdhci_reset`, `cv18xx_sdhci_reset`) must not sleep when `mask` is `SDHCI_RESET_CMD` or `SDHCI_RESET_DATA`, because `sdhci_core` invokes those resets while holding `host->lock` with IRQs disabled. [F153]
- On Pensando Elba (`sdhci_elba_ops`), sub-dword writes in `elba_write_w` and `elba_write_b` must compute the intra-dword byte offset `shift = reg & GENMASK(1, 0)` and write `ELBA_BYTE_ENABLE_MASK(GENMASK(1, 0) << shift)` or `ELBA_BYTE_ENABLE_MASK(BIT(0) << shift)` to `priv->ctl_addr` under `priv->wrlock` before `writew`/`writeb`. [F83]
- In `drivers/mmc/host/sdhci-pxav2.c`, `pxav1_request_done` must set `pxav2_host->sdio_mrq = mrq` and select `pins_cmd_gpio` before writing `SDHCI_COMMAND` for the dummy CMD0, and `pxav1_irq` must clear `SDHCI_INT_CMD_MASK`, restore `pins_default`, and clear `pxav2_host->sdio_mrq` before calling `mmc_request_done`. [F27]

## Object Lifetimes
- When host registration is split into `sdhci_setup_host` and `__sdhci_add_host` (as in `sdhci_acpi_probe`, `dwcmshc_probe`, `glk_emmc_add_host`, and `gl9763e_add_host`), any error after `sdhci_setup_host` succeeds must call `sdhci_cleanup_host(host)` before returning. [F1]
- In `remove` and suspend callbacks (`dwcmshc_remove`, `sdhci_pxav3_remove`, `sdhci_acpi_remove`, `sdhci_pci_remove`, `sdhci_pltfm_suspend`, etc.), runtime-PM-enabled devices must be resumed and runtime PM disabled (`pm_runtime_get_sync` + `pm_runtime_disable`, or `sdhci_pci_runtime_pm_forbid` when `chip->allow_runtime_pm` is set) before reading `SDHCI_INT_STATUS` or calling `sdhci_remove_host` / `sdhci_pci_remove_slot`, and `sdhci_remove_host` or `sdhci_*suspend_host` must complete before `clk_disable_unprepare`. [F11, F25, F26]
- In `sdhci_acpi_probe` and `sdhci_acpi_remove`, `c->slot->free_slot(pdev)` must run on probe failure (`err_free`) and on removal after `sdhci_remove_host` (with `*irq = sdhci_acpi_priv(c)` initialized to `-EINVAL` in `qcom_probe_slot` before any early return), whereas `c->slot->remove_slot(pdev)` runs only in `sdhci_acpi_remove` before `sdhci_remove_host`. In `sdhci_pci_probe_slot` and `sdhci_pci_remove_slot`, `chip->fixes->remove_slot` must run on errors after `probe_slot` (`goto remove`) and after `remove_host` / `sdhci_remove_host`. [F4, F5, F7]
- Non-devres references and allocations must be freed on all paths: `union acpi_object *obj` in `__intel_dsm` (`sdhci-acpi.c`, `sdhci-pci-core.c`) via `ACPI_FREE(obj)`; `of_clk_get(np, 0)` and `of_find_compatible_node` in `esdhc_init` / `sdhci_esdhc_probe` via `clk_put` and `of_node_put`; `scfg_node` and `scfg_base` in `esdhc_signal_voltage_switch()` via `of_node_put` and `iounmap`; and the non-NULL `sd_dev` cursor in `jmicron_probe()` via `pci_dev_put(sd_dev)` when breaking early out of `pci_get_device()`. [F3, F15, F107, F140]
- In `dwcmshc_cqhci_init()`, `SDHCI_CLOCK_INT_EN` in `SDHCI_CLOCK_CONTROL` must be enabled and verified before calling `cqhci_init()`, and if setup fails, `SDHCI_CLOCK_INT_EN` must be cleared, `cq_host` freed, and `MMC_CAP2_CQE | MMC_CAP2_CQE_DCMD` cleared from `host->mmc->caps2`. [F130]

## API Contracts
- Every `struct sdhci_ops` table assigned to `host->ops` must populate `.set_clock`, `.set_bus_width`, `.reset`, and `.set_uhs_signaling` (called by SDHCI core without NULL checks). Any driver setting `SDHCI_QUIRK_CAP_CLOCK_BASE_BROKEN` must also implement `.get_max_clock`, and if it uses `sdhci_pltfm_clk_get_max_clock`, `pltfm_host->clk` must be initialized before `sdhci_setup_host()` or `sdhci_add_host()`. [F164, F165]
- `sdhci_ops.irq` callbacks (`sdhci_cqhci_irq`, `sdhci_gl9763e_cqhci_irq`, `dwcmshc_cqe_irq_handler`, `esdhc_irq`, `pxav1_irq`) must return a `u32` bitmask of unhandled `SDHCI_INT_*` bits for `sdhci_irq()` to process (or `0` if consumed), never `IRQ_HANDLED` (`1 == SDHCI_INT_RESPONSE`). In CQHCI-enabled drivers, the callback must call `sdhci_cqe_irq(host, intmask, &cmd_error, &data_error)`, returning `intmask` when `false`, and calling `cqhci_irq()` then returning `0` when `true`. [F33, F170]
- CQHCI-enabled SDHCI drivers (`dwcmshc_probe`, `glk_emmc_add_host`, `gl9763e_add_host`) must call `sdhci_setup_host(host)` first, then check `host->flags & SDHCI_USE_64_BIT_DMA` to set `CQHCI_TASK_DESC_SZ_128` and call `cqhci_init()`, and finally call `__sdhci_add_host(host)`. On controllers where `SDHCI_RESET_ALL` clears CQHCI state (`sdhci_intel_glk_ops`, `sdhci_gl9763e_ops`), `.reset` must use `sdhci_and_cqhci_reset` to call `cqhci_deactivate(host->mmc)` when `(host->mmc->caps2 & MMC_CAP2_CQE) && (mask & SDHCI_RESET_ALL) && host->mmc->cqe_private` before `sdhci_reset`. [F54, F169]
- When splitting a 128MB-crossing DMA segment in `dwcmshc_set_tran_desc()`, the first `cqhci_set_tran_desc()` call must pass `end = false`, `*desc` must be manually advanced by `cq_host->trans_desc_len`, and the second call must pass the caller's `end` argument; in contrast, `dwcmshc_adma_write_desc` and `sdhci_sparx5_adma_write_desc` must NOT manually increment `*desc` because `sdhci_adma_write_desc()` advances `*desc += host->desc_sz` itself. [F48, F128]
- `sdhci_alloc_host()`, `sdhci_pltfm_init()`, and `sdhci_pci_probe_slot()` return an `ERR_PTR` on failure and never `NULL` (check `IS_ERR()`), whereas `sdhci_pci_add_gpio_lookup_table()` returns `NULL` when no DMI override matches, `ERR_PTR(-ENOMEM)` on failure, or a `kmemdup`-cloned table (`struct_size(..., count + 1)`), so `sdhci_pci_probe_slot()` must check `IS_ERR()` before passing the nullable pointer to `sdhci_pci_remove_gpio_lookup_table()`. [F31, F32, F65]
- `sdhci_ops.get_timeout_clock` callbacks (`sdhci_cdns_get_timeout_clock`, `sdhci_pltfm_clk_get_max_clock`) must return Hz, whereas pre-populating `host->timeout_clk` directly before `sdhci_setup_host()` (`intel_probe_slot`, `byt_emmc_probe_slot`) requires kHz. When overriding the spec version via `__sdhci_read_caps(host, &version, ...)`, the `u16` must be formatted as a raw `SDHCI_HOST_VERSION` register value shifted by `SDHCI_SPEC_VER_SHIFT`. [F46, F47]
- On GL9767 (`sdhci-pci-gli.c`), every modification to Vendor Header Space PCI config registers (`0x884`–`0x964`) must be bracketed by `gl9767_vhs_write(pdev)` and `gl9767_vhs_read(pdev)`, and functions disabling low-power negotiation (`PCIE_GLI_9767_CFG_LOW_PWR_OFF`) must re-enable it on all return paths. On O2Micro (`sdhci-pci-o2micro.c`), writing write-protected PCI config registers requires clearing bit 7 (`& 0x7f`) of `O2_SD_LOCK_WP` (`0xD3`) beforehand and setting bit 7 (`| 0x80`) afterward. [F142, F145]

## Error Handling
- In PCI probes and resume (`sdhci_pci_probe`, `jmicron_pmos`, `sdhci_pci_o2_probe`), positive `PCIBIOS_*` codes from `pci_read_config_*()` / `pci_write_config_*()` must be converted via `pcibios_err_to_errno()`. In platform/ACPI probes (`sdhci_pltfm_init`, `sdhci_acpi_probe`, `sdhci_milbeaut_probe`), negative errors from `platform_get_irq()` must be propagated directly, and `goto`-unwinding probes (`spacemit_sdhci_probe`, `dwcmshc_probe`, `sdhci_bcm_kona_probe`, `pic32_sdhci_probe`, `sdhci_milbeaut_probe`) must set a negative errno before jumping. [F29, F30, F42]
- Optional secondary clocks in `sdhci-of-dwcmshc.c` (`priv->bus_clk`) and `sdhci-pxav3.c` (`pxa->clk_core`) retain an `ERR_PTR` value from `devm_clk_get()` when absent, so `clk_prepare_enable()` and `clk_disable_unprepare()` must be guarded with `!IS_ERR(...)`; in contrast, optional pinctrl handles and pin states in `sdhci-pxav2.c` and `sdhci-pxav3.c` (`pinctrl`, `pins_default`, `pins_cmd_gpio`, `pins_uhs`) are tested for non-NULL at runtime, so probe must convert `IS_ERR()` returns from `devm_pinctrl_get()` and `pinctrl_lookup_state()` to `NULL`. [F39, F40]
- During driver teardown (`sdhci_pltfm_remove`, `sdhci_acpi_remove`, `sdhci_pci_remove_slot`, `sdhci_milbeaut_remove`, `pic32_sdhci_remove`), if `SDHCI_INT_STATUS` reads as `0xffffffff` (`~0`), `dead = 1` must be passed to `sdhci_remove_host()` and `slot->chip->fixes->remove_slot()` so MMIO resets and writes are skipped. In `sdhci_pci_probe` and `sdhci_pci_suspend_host`, the slot loop index `i` must remain a signed `int` and error rollback must pre-decrement `i` (`for (i--; i >= 0; i--)` and `while (--i >= 0)`) before indexing `chip->slots[i]`. [F78, F175]

## Known Pitfalls
- Across all drivers, `SDHCI_QUIRK_*` flags must only target `quirks` and `SDHCI_QUIRK2_*` flags must only target `quirks2`. In `sdhci_acpi_probe()`, `c->slot->probe_slot()` must run before applying `c->slot->chip` and `c->slot` flags, and `quirks`, `quirks2`, `caps`, `caps2`, and `pm_caps` from both `c->slot->chip` and `c->slot` must be bitwise-ORed (`|=`) rather than assigned (`=`). In `th1520_sdhci_set_phy()` and `cv18xx_sdhci_reset()`, testing the composite mask `emmc_caps` (`MMC_CAP2_NO_SD | MMC_CAP2_NO_SDIO`) requires `(host->mmc->caps2 & emmc_caps) == emmc_caps`. [F98, F99, F110]
- In `sdhci-of-esdhc.c`, `esdhc_be_writew` and `esdhc_le_writew` (and `read*`/`write*` pairs) must be updated in lockstep, sampling old 32-bit values before `esdhc_writew_fixup` to detect a `0 -> 1` transition of `ESDHC_EXTN` during `esdhc->in_sw_tuning`; `esdhc_readl_fixup()` / `esdhc_readw_fixup()` must combine all fixups for the same `spec_reg` (`SDHCI_PRESENT_STATE`, `SDHCI_HOST_VERSION`) before returning `ret`; and `esdhc_execute_tuning` must save `SDHCI_HS400_TUNING` before `sdhci_execute_tuning` and restore it before `esdhc_execute_sw_tuning` or retries. [F58, F61, F95]
- In `sdhci-pci-arasan.c`, `arasan_phy_write(struct sdhci_host *host, u8 data, u8 offset)` takes `data` before `offset`, whereas `arasan_phy_read(struct sdhci_host *host, u8 offset, u8 *data)` takes `offset` before `data`. [F50]
