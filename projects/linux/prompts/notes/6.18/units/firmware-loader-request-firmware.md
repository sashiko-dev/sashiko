# FIRMWARE LOADER (request_firmware)

The firmware loader subsystem (`drivers/base/firmware_loader/`, `include/linux/firmware.h`, and `rust/kernel/firmware.rs`) provides synchronous and asynchronous APIs to load device firmware from built-in kernel sections, VFS paths (with optional XZ/ZSTD decompression), EFI embedded platform firmware, or a userspace sysfs fallback, plus suspend/resume firmware caching, sysfs firmware upload (`firmware_upload_register`), and safe Rust bindings.

## Architecture & Data Flow

- `__allocate_fw_priv()` must initialize `fw_priv->pending_list` with `INIT_LIST_HEAD()`, and transitions of `fw_priv->fw_st.status` to `FW_STATUS_DONE` or `FW_STATUS_ABORTED` must go through `__fw_state_set()` (`fw_state_done()` / `fw_state_aborted()`) so `list_del_init(&fw_priv->pending_list)` and `complete_all(&fw_priv->fw_st.completion)` run in lockstep. [F43, F49]
- In `alloc_lookup_fw_priv()`, requests with `FW_OPT_NOCACHE` or `FW_OPT_PARTIAL` must not look up an existing `fw_priv` via `__lookup_fw_priv()`, and `FW_OPT_NOCACHE` requests must not add `tmp->list` to `fwc->head`, while still calling `INIT_LIST_HEAD(&tmp->list)` so `list_del()` in `__free_fw_priv()` is a no-op. [F48]
- For a paged-buffer `fw_priv` (`fw_priv->is_paged_buf`), `fw_priv->data` must stay `NULL` during writes and only be mapped via `fw_map_paged_buf()` at load completion because `firmware_data_read()`/`write()` test `fw_priv->data` to distinguish pre-allocated buffers from paged buffers; `fw_free_paged_buf()` must unmap `data`, free `pages[0..nr_pages - 1]` and `pages`, and reset `pages`, `page_array_size`, `nr_pages`, `data`, and `size` to `NULL`/`0` because `fw_priv` is reused across retries and uploads. [F50, F52]
- In `fw_grow_paged_buf()`, `page_array_size` and `nr_pages` count `struct page *` elements (while `size` and `allocated_size` count bytes); `kvmalloc_array()`, `memcpy()`, and the tail `memset()` at `&new_pages[fw_priv->page_array_size]` must scale by `sizeof(void *)`, and `nr_pages` must only be incremented after each `alloc_page()` succeeds. [F51, F89]
- `struct fw_sysfs` is shared between sysfs fallback (`fw_upload_priv == NULL`) and firmware upload (`fw_upload_priv != NULL`, `fw == NULL`); `fw_dev_release()`, `firmware_loading_store()`, `fw_upload_is_visible()`, and `fw_upload_start()` must check `fw_sysfs->fw_upload_priv` first, and because upload reuses a persistent `fw_sysfs->fw_priv`, every path ending or aborting an upload (`firmware_loading_store()` case `-1`/default, `fw_upload_start()` when `!fw_priv->size`, and `fw_upload_main()` exit) must call `fw_free_paged_buf()` and `fw_state_init(fw_sysfs->fw_priv)` under `fw_lock`. [F37, F56]
- `fw_upload_set_error()` must record `fwlp->err_progress = fwlp->progress` alongside `fwlp->err_code` under `fwlp->lock`, and `fw_upload_main()` must leave `err_code`, `err_progress`, and `remaining_size` intact when setting `progress = FW_UPLOAD_PROG_IDLE`, resetting them only in `fw_upload_start()` when the next upload begins. [F57]
- Every `fw_cache_entry` on `fw_cache.fw_names` must hold one reference on its `fw_priv` (taken via `kref_get()` in `fw_cache_piggyback_on_request()` or retained when `cache_firmware()` calls `kfree(fw)` instead of `release_firmware(fw)`), and `__async_dev_cache_fw_image()` must unlink and free the entry if `cache_firmware()` fails. [F58]
- `device_cache_fw_images()` must pair `fw_fallback_set_cache_timeout()` with `fw_fallback_set_default_timeout()`, and `fw_cache.state` must be reset to `FW_LOADER_NO_CACHE` in both `fw_suspend()` and the `PM_POST_*` cases of `fw_pm_notify()` (in case suspend aborts before syscore). [F59]
- In `fw_load_sysfs_fallback()`, `dev_set_uevent_suppress(f_dev, true)` must be set before `device_add(f_dev)` and only cleared before `kobject_uevent(&fw_sysfs->dev.kobj, KOBJ_ADD)` after `fw_priv->pending_list` is linked onto `pending_fw_head` under `fw_lock` and `FW_OPT_UEVENT` is verified. [F100]
- `assign_fw()` rejects any load where `fw_priv->size == 0` with `-ENOENT`, and `FwFunc` must only wrap C functions (`request_firmware`, `firmware_request_nowarn`, `firmware_request_platform`, `request_firmware_direct`) where a `0` return guarantees a non-null, exclusively owned `bindings::firmware` with non-zero `size` and immutable `data` until `Drop` calls `release_firmware`. [F71, F96, F97]

## Synchronization

- `free_fw_priv()` must acquire `fw_priv->fwc->lock` before calling `kref_put(&fw_priv->ref, __free_fw_priv)`; `__free_fw_priv()` must remove `fw_priv->list` while holding `fwc->lock` and then unlock `fwc->lock` before freeing buffers, while `free_fw_priv()` unlocks `fwc->lock` only when `kref_put()` returns `0`. [F3]
- Whenever `fw_priv` may be on `pending_fw_head`, any transition to `FW_STATUS_DONE` or `FW_STATUS_ABORTED` via `__fw_state_set()` (`fw_state_done()`, `fw_state_aborted()`, `__fw_load_abort()`) must hold `fw_lock`, and in `fw_load_sysfs_fallback()` after `device_add()` and acquiring `fw_lock`, `fw_load_abort_all` and `fw_state_is_aborted(fw_priv)` must be checked before `list_add(&fw_priv->pending_list, &pending_fw_head)`. [F15, F16]
- All firmware load paths (`fw_get_filesystem_firmware()`, `firmware_fallback_platform()`, and `firmware_loading_store()`) must finish populating `fw_priv->data` (including `fw_map_paged_buf()`) and `fw_priv->size` before calling `fw_state_done()`, which wakes batched waiters in `_request_firmware_prepare()` via `complete_all()`. [F19]
- `fw_sysfs->fw_priv` (and `fw_sysfs->fw_upload_priv` in `firmware_upload_register()`) must be initialized before `device_add(&fw_sysfs->dev)`, and in `fw_load_sysfs_fallback()`, `fw_sysfs_wait_timeout()` and `device_del(f_dev)` must be called without holding `fw_lock` because sysfs attribute/uevent handlers acquire `fw_lock`. [F24, F117]
- `fw_upload_start()` must be called with `fw_lock` held and acquires `fwlp->lock` inside `fw_lock` (fixing lock order `fw_lock` -> `fwlp->lock`); under both locks it must verify `fwlp->progress == FW_UPLOAD_PROG_IDLE`, set `progress = FW_UPLOAD_PROG_RECEIVING`, `data`, and `remaining_size`, and call `get_device(fw_dev->parent)` before `queue_work()`, while `fw_upload_main()` must never hold `fwlp->lock` across `ops->prepare()`, `write()`, `poll_complete()`, or `cleanup()` so `cancel_store()` / `firmware_upload_unregister()` can acquire `fwlp->lock` to call `ops->cancel()`. [F22, F27, F114]
- When `fw_cache_piggyback_on_request()` adds a `fw_cache_entry` to `fwc->fw_names`, it must call `kref_get(&fw_priv->ref)` before releasing `fwc->name_lock`, and `__device_uncache_fw_images()` must drain `fwc->fw_names` with a `while (!list_empty(&fwc->fw_names))` loop that unlinks one entry and drops `fwc->name_lock` before calling `uncache_firmware()` (which may sleep in `vunmap()`/`vfree()`). [F17, F83, F112]
- `__allocate_fw_priv()` (called under `spin_lock(&fwc->lock)`) and `alloc_fw_cache_entry()` / `dev_create_fw_entry()` (called under `spin_lock(&fwc->name_lock)` or `dev->devres_lock`) must allocate with `GFP_ATOMIC` and never sleep. [F109, F110]
- `device_cache_fw_images()` must call `cancel_delayed_work_sync(&fwc->work)` before starting caching and release `fw_lock` before `async_synchronize_full_domain(&fw_cache_domain)`; `fw_suspend()` runs with interrupts disabled as a syscore callback and must set `fw_cache.state = FW_LOADER_NO_CACHE` without acquiring `fw_lock`. [F23, F118]
- All callers of `fw_add_devm_name()` (`assign_fw()` and `firmware_request_cache()`) must hold `fw_lock` so the `fw_cache_is_setup()` check and `devres_add()` execute atomically. [F26]

## Object Lifetimes

- When `fw_priv->data` is pre-allocated by the caller (`fw_priv->allocated_size != 0`), loading helpers (`firmware_fallback_platform()`, `fw_decompress_zstd()`, `fw_decompress_xz()`, and `fw_get_filesystem_firmware()`) must write into `fw_priv->data` within `fw_priv->allocated_size` without replacing `fw_priv->data` or freeing it on error. [F5]
- Callers of `firmware_request_builtin()` pass a caller-owned `struct firmware` receiving borrowed pointers into `__start_builtin_fw` and must never pass it to `release_firmware()` (which calls `kfree(fw)`), while `release_firmware()` itself must check `!firmware_is_builtin(fw)` before calling `firmware_free_data(fw)` so it never calls `vfree()` on `.builtin_fw` pointers. [F1, F55]
- In `_request_firmware_nowait()`, `try_module_get(module)` and `get_device(fw_work->device)` must be acquired before `schedule_work(&fw_work->work)` (freeing `fw_work->name` and `fw_work` if `try_module_get()` fails) and released in `request_firmware_work_func()` only after `fw_work->cont(fw, fw_work->context)` returns; `cont` takes ownership of `fw` and must call `release_firmware(fw)`. [F8]
- In `fw_load_sysfs_fallback()`, if `device_add(f_dev)` fails after `device_initialize(f_dev)`, cleanup must call `put_device(f_dev)` without `device_del(f_dev)` (and never raw `kfree(fw_sysfs)`), whereas after `device_add(f_dev)` succeeds, both `device_del(f_dev)` and `put_device(f_dev)` must be called on exit. [F10]
- When `fw_sysfs->fw_upload_priv` is non-NULL, `fw_dev_release()` calls `fw_upload_free()` to free `fw_sysfs->fw_priv`, `fw_upload_priv->fw_upload`, and `fw_upload_priv` before `kfree(fw_sysfs)`; therefore in `firmware_upload_register()`, once `fw_upload_priv` and `fw_priv` are attached to `fw_sysfs`, a `device_add(fw_dev)` failure must call `put_device(fw_dev)` and jump directly to `exit_module_put` to avoid double-freeing them. [F11, F12]
- `fw_upload_main()` must invoke `fwlp->ops->cleanup` only if `prepare` succeeded, and on every exit path must call `put_device(fw_dev->parent)`, `fw_free_paged_buf()`, `fw_state_init()`, clear `fwlp->data = NULL`, and call `fw_upload_prog_complete()`; `firmware_upload_unregister()` must check `progress` under `fwlp->lock`, call `ops->cancel()` if non-idle, and `flush_work(&fwlp->work)` after unlocking before `device_unregister()`. [F14, F102]
- In `dev_cache_fw_image()`, `todo` must be iterated with `list_for_each_entry_safe()`, and when `__fw_entry_found(fce->name)` is true, `fce` must be set to `NULL` after `free_fw_cache_entry(fce)` so `async_schedule_domain()` is not called on a freed entry. [F82]

## API Contracts

- `_request_firmware()` must reject `NULL`/empty firmware names or names where `name_contains_dotdot(name)` is true with `-EINVAL` before calling `_request_firmware_prepare()`. [F62]
- `alloc_lookup_fw_priv()` returns `1` when batching onto an existing `fw_priv`, `0` when allocating a new one, and `< 0` on error; `_request_firmware_prepare()` returns `0` when firmware is already assigned, `1` when the caller must load it, and `< 0` on error, so `_request_firmware()` must stop loading on `ret <= 0` while only treating `ret < 0` as a failure. [F28, F29]
- `__allocate_fw_priv()` requires a non-NULL preallocated `dbuf` when `FW_OPT_PARTIAL` is set and forbids non-zero `offset` without `FW_OPT_PARTIAL`; in `_request_firmware()`, decompression, `firmware_fallback_platform()`, and `firmware_fallback_sysfs()` must be gated on `!(opt_flags & FW_OPT_PARTIAL)`, and in `fw_get_filesystem_firmware()` for preallocated buffers without decompression, `msize` is `fw_priv->allocated_size` and `file_size_ptr` is passed to `kernel_read_file_from_path_initns()` only when `FW_OPT_PARTIAL` is set. [F46, F64, F78]
- Both `fw_copy_to_prealloc_buf()` and `firmware_fallback_platform()` must verify that a preallocated target buffer capacity (`size` or `fw_priv->allocated_size`) is at least the firmware image size before calling `memcpy()`, failing with `false` or `-ENOMEM` if it does not fit. [F66]
- `assign_fw()` must only call `fw_add_devm_name()` when `FW_OPT_UEVENT` is set and `FW_OPT_NOCACHE` is clear (`fw_add_devm_name()` returns `0` if already registered and `< 0` on error, and `assign_fw()` must unlock `fw_lock` on error); `request_firmware_into_buf()`, `request_partial_firmware_into_buf()`, and `_request_firmware_nowait()` with `!uevent` must return `-EOPNOTSUPP` if `fw_cache_is_setup(device, name)` is true. [F31, F60]
- In `struct fw_upload_ops`, `prepare`, `write`, `poll_complete`, and `cancel` are mandatory while `cleanup` is optional (`if (fwlp->ops->cleanup)`); in `fw_upload_main()`, `ops->write()` receives the unshifted base pointer `fwlp->data` with cumulative `offset` and `fwlp->remaining_size`, and when returning `FW_UPLOAD_ERR_NONE` must set `*written` in `1..=size` (as `*written == 0` aborts with `FW_UPLOAD_ERR_RW_ERROR` and `*written > size` underflows `remaining_size`). [F38, F73, F90]

## Error Handling

- `_request_firmware()` must restore task credentials (`revert_creds(old_cred)` and `put_cred(kern_cred)`) after `override_creds(kern_cred)` and, on any negative `ret`, must call `fw_abort_batch_reqs(fw)`, `release_firmware(fw)`, and set `*firmware_p = NULL` before returning. [F7, F44]
- In `_request_firmware()`, each secondary lookup (`fw_decompress_zstd`, `fw_decompress_xz`, and `firmware_fallback_platform()`) must only run when the preceding lookup returned `-ENOENT`, whereas `firmware_fallback_sysfs()` runs on any non-zero `ret` and must return its `ret` argument unchanged when sysfs fallback is disabled or skipped by `fw_run_sysfs_fallback()` (which returns `bool` and must check `if (ret < 0) return false;` on `security_kernel_load_data()`). [F30, F39, F79]

## External Contracts

- Non-VFS firmware paths (`firmware_fallback_platform()`, `fw_run_sysfs_fallback()`, and `firmware_loading_store()`) must call `security_kernel_load_data(LOADING_FIRMWARE, true)` before loading and `security_kernel_post_load_data(..., LOADING_FIRMWARE, ...)` before marking `fw_priv` done; VFS loads use `prepare_kernel_cred(&init_task)` and `kernel_read_file_from_path_initns()`. [F129, F133]
- In `firmware_data_read()` and `firmware_data_write()`, writes require `capable(CAP_SYS_RAWIO)` (`-EPERM` otherwise), reads must return `0` when `offset > fw_priv->size` before subtracting `offset`, and writes to a preallocated buffer (`fw_priv->data != NULL`) must reject `offset + count > fw_priv->allocated_size` with `-ENOMEM`. [F131, F134]

## Known Pitfalls

- In `fw_get_filesystem_firmware()`, when `decompress` is non-NULL, the `fw_path` loop must reset `buffer = NULL` after `vfree(buffer)` and call `fw_free_paged_buf(fw_priv)` if `decompress()` fails before continuing, because `kernel_read_file_from_path_initns()` treats a non-NULL `*buffer` as a caller-allocated buffer; formatting `fw_path[i]` must use `%.*s` with `maxlen` (stripping trailing `'\n'` from `fw_path_para` at `i == 0`) and return `-ENAMETOOLONG` if `len >= PATH_MAX`. [F53, F94]
- `fw_decompress_zstd()` must check `zstd_is_error(len)` before assigning `len` to `fw_priv->size`, and when `fw_priv->allocated_size == 0` it must validate the frame with `zstd_get_frame_header()` and reject `ZSTD_CONTENTSIZE_UNKNOWN` with `-EINVAL` before calling `vzalloc(out_size)`. [F34, F67]
- In `firmware_loading_store()`, writing `0` when `!fw_state_is_loading(fw_priv)` must `fallthrough` to `default`/`-1` to call `fw_load_abort(fw_sysfs)`, and in `kill_pending_fw_fallback_reqs()`, `pending_fw_head` must be iterated with `list_for_each_entry_safe()` because `__fw_load_abort()` unlinks `fw_priv->pending_list`. [F80, F81]
- Because `fw_grow_paged_buf()` allocates `fw_priv->pages[]` with `__GFP_HIGHMEM` and `fw_map_paged_buf()` maps `fw_priv->data` `PAGE_KERNEL_RO`, `fw_realloc_pages()` must round up `min_size` (`offset + count`) with `PAGE_ALIGN(min_size) >> PAGE_SHIFT`, and `firmware_rw()` must use highmem-safe helpers (`kmap_local_page()` / `memcpy_from_page()` / `memcpy_to_page()`) and clamp per-page byte counts via `min_t(size_t, PAGE_SIZE - page_ofs, count)` before narrowing to `int`. [F86, F87, F120]
