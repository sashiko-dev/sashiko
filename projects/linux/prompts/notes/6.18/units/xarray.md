# XARRAY

The XArray unit implements an RCU-safe, radix-tree-based resizable array mapping unsigned long indices to pointers or tagged value entries, supporting multi-index entries and up to three hierarchical search marks. It also provides the IDR (ID-to-pointer translation) and IDA (compact bitmap-backed ID allocator) APIs built on top of the radix tree and XArray primitives.

## Architecture & Data Flow

- `xas->xa_node` encodes special cursor states (`NULL` for root, `XAS_BOUNDS` (`1UL`), `XAS_RESTART` (`3UL`), and `XA_ERROR(errno)` with low bits `10`) alongside `struct xa_node *` pointers; verify `xas_is_node(xas)` or `!xas_not_node(node)` before dereferencing `xas->xa_node` (a NULL check alone is insufficient). In `__xas_next()` and `__xas_prev()`, after updating `xas->xa_index` when `!xas_frozen(xas->xa_node)`, check `!xas->xa_node` to return `set_bounds(xas)` before checking `xas_not_node(xas->xa_node)` and calling `xas_load(xas)`. [F35, F83]
- XArray slot entries encode their type in the bottom two bits (`00` for pointers, `10` for internal entries via `xa_mk_internal()`, and `x1` for value entries via `xa_mk_value()` or tagged pointers via `xa_tag_pointer()`). Pointers passed to `xa_tag_pointer()` must be 4-byte aligned with tag 0, 1, or 3 (never 2). `xa_to_node()` subtracts 2 (`(unsigned long)entry - 2`), so callers must verify `xa_is_node(entry)` (checking both `xa_is_internal(entry)` and `(unsigned long)entry > 4096`), not just `xa_is_internal(entry)`. [F71, F107]
- Every mutation changing `node->count` or `node->nr_values`—in `update_node()`, `xas_split()`, `xas_try_split()`, `xas_shrink()`, and `xas_free_nodes()`—must call `xas_update(xas, node)` on each affected node before freeing or returning. In `xas_store()`, storing the identical non-multi-index entry (`(first == entry) && !xas->xa_sibs`) returns immediately without modifying `count`, `values`, or marks, whereas overwriting a child `xa_node` (`xa_is_node(next) && (!node || node->shift)`) frees the replaced subtree via `xas_free_nodes()`. [F9, F52]
- Within an `xa_node`, search mark bits in `node->marks` must only be set on canonical entry offsets and never on sibling slots (`xa_is_sibling()`); `xas_squash_marks()` merges sibling range marks onto `xas->xa_offset`, and `node_mark_slots()` during `xas_split()` / `xas_try_split()` strides by `sibs + 1`. [F53]
- On `XA_FLAGS_TRACK_FREE` arrays (`XA_FLAGS_ALLOC` / `XA_FLAGS_ALLOC1`), `xas_store()` sets `XA_FREE_MARK` via `xas_init_marks()` when storing `NULL`, but callers storing non-`NULL` entries (`__xa_store()`, `__xa_cmpxchg_raw()`, `__xa_alloc()`) must explicitly clear `XA_FREE_MARK`. For `XA_FLAGS_ZERO_BUSY` (`XA_FLAGS_ALLOC1`), `xas_create()` / `xas_expand()` must materialize an empty index 0 as `XA_ZERO_ENTRY` with slot 0's `XA_FREE_MARK` cleared, and `xas_shrink()` / `xa_destroy()` must convert `XA_ZERO_ENTRY` back to `NULL` in `xa->xa_head` and clear `XA_FREE_MARK` on `xa`. [F55, F56]
- Normal XArray APIs (`xa_load`, `__xa_erase`, `__xa_store`, `__xa_cmpxchg`) must translate `XA_ZERO_ENTRY` to `NULL` via `xa_zero_to_null()` before returning, whereas `__xa_insert()` must use `__xa_cmpxchg_raw()` so an existing `XA_ZERO_ENTRY` (reserved slot) is seen as non-NULL and causes `-EBUSY`. [F46]
- Each slot in `ida->xa` stores either a value entry (`xa_is_value(entry)`) for bit offsets `< BITS_PER_XA_VALUE` (`BITS_PER_LONG - 1`, never `BITS_PER_LONG`) or a `struct ida_bitmap *`, so IDA helpers must check `xa_is_value()` before dereferencing or freeing an entry as a bitmap. In `ida_alloc_range()` and `ida_free()`, value entries never have `XA_FREE_MARK` cleared; `XA_FREE_MARK` is cleared only when `bitmap_full()` is true and re-set via `xas_set_mark(&xas, XA_FREE_MARK)` when any bitmap bit is cleared. [F38, F61, F98]

## Synchronization

- While holding `xa->xa_lock`, `xas_alloc()` and `xas_try_split()` must only allocate `struct xa_node` objects from `radix_tree_node_cachep` with `GFP_NOWAIT` (plus `__GFP_ACCOUNT` if `XA_FLAGS_ACCOUNT`), deferring sleepable `gfp_t` allocations to `xas_nomem()`, `__xas_nomem()`, or `xas_split_alloc()` outside `xa->xa_lock`. Similarly, `ida_alloc_range()` must allocate `struct ida_bitmap` under `xas_lock_irqsave()` with `kzalloc(..., GFP_NOWAIT)`, only using caller `gfp` flags after `xas_unlock_irqrestore()` and `xas_set()`. [F22, F118]
- When `__xas_nomem()` drops and reacquires `xa->xa_lock` for a blocking allocation (`gfpflags_allow_blocking(gfp)`), it uses `xa_lock_type(xas->xa)` (`XA_FLAGS_LOCK_IRQ` or `XA_FLAGS_LOCK_BH` in `xa->xa_flags`), so XArrays locked with `xa_lock_irq()` or `xa_lock_bh()` and mutated with blocking GFP flags must be initialized with `XA_FLAGS_LOCK_IRQ` or `XA_FLAGS_LOCK_BH`. [F18]
- In `__xa_cmpxchg_raw()`, `curr = xas_load(&xas)` and `curr == old` must remain inside the `do { ... } while (__xas_nomem(&xas, gfp))` loop so the slot is reloaded and revalidated against `old` if `__xas_nomem()` drops `xa->xa_lock`. In `__xa_alloc()`, `xas.xa_index = limit.min` must also be re-initialized inside the `__xas_nomem()` loop before calling `xas_find_marked(&xas, limit.max, XA_FREE_MARK)`. [F25, F87]
- In `xas_expand()`, `xas_create()`, `xas_split()`, and `xas_try_split()`, all fields, child slots, and mark bitmaps of a new `struct xa_node` must be initialized before `rcu_assign_pointer()` publishes `xa_mk_node(node)` into `xa->xa_head` or parent `slots`. When splitting a multi-index entry within the same `xa_node`, `xas_split()` and `xas_try_split()` must store `entry` into each canonical slot `node->slots[canon]` before writing `xa_mk_sibling(canon)` into higher sibling slots while iterating `offset` downward to `xas->xa_offset`. [F14, F15]
- When unlinking an `xa_node` in `xas_shrink()` or `xas_free_nodes()`, every non-node present slot in the unlinked node must be overwritten with `XA_RETRY_ENTRY` before `xa_node_free()`, and `xas->xa_node` in `xas_shrink()` / `xas_delete_node()` must be set to `XAS_BOUNDS` when the root node is removed. [F57]
- In `xas_store()`, erasing an entry (`!entry`) must call `xas_init_marks(xas)` before `rcu_assign_pointer(*slot, entry)` publishes `NULL`, and if an RCU reader in `xas_find_marked()` or `xas_next_marked()` sees a mark on a `NULL` slot (other than `XA_FREE_MARK` on an `xa_track_free` array), it must continue searching rather than returning `NULL`. [F27]
- In `xas_descend()`, resolving a sibling entry under RCU must loop with `while (xa_is_sibling(entry))` to handle concurrent range stores, and if following a sibling in an internal node (`node->shift > 0`) loads a child node (`xa_is_node(entry)`) due to a concurrent split, it must return `XA_RETRY_ENTRY`. [F28]
- Lockless RCU callers of `xas_load()`, `xas_find()`, `xas_find_marked()`, `xas_for_each()`, or `xas_for_each_marked()` must filter returned entries with `xas_retry()`, which calls `xas_reset(xas)` on `XA_RETRY_ENTRY` to restart from `xa_head` while returning `true` without resetting `xas` on `XA_ZERO_ENTRY`. [F29]
- In `idr_get_next_ul()` and `idr_get_next()`, lockless RCU iteration must loop with `radix_tree_for_each_slot()`, skip `NULL` slots from concurrent `idr_remove()`, and call `radix_tree_iter_retry(&iter)` only when `entry` is `XA_RETRY_ENTRY` or an internal entry at `&idr->idr_rt.xa_head`. [F122]
- `struct idr` mutation functions (`idr_alloc_u32()`, `idr_alloc()`, `idr_alloc_cyclic()`, `idr_remove()`, `idr_replace()`) do not lock internally and require caller locking, whereas `struct ida` operations must take `xa_lock_irqsave(&ida->xa, flags)` because `ida_bitmap` is freed via `kfree()` without RCU. [F19]
- `xa_head_locked()`, `xa_entry_locked()`, and `xa_parent_locked()` assert `lockdep_is_held(&xa->xa_lock)`, so callers (`xas_create()`, `xas_store()`, `xas_set_mark()`, `xas_clear_mark()`, `xas_find_conflict()`, `xa_delete_node()`) require `xa->xa_lock`. An `xa_update_node_t` callback registered via `xas_set_update()` or passed to `xa_delete_node()` runs from `xas_update()` with `xa->xa_lock` held and interrupts possibly disabled, so it must never drop `xa->xa_lock`, re-enable interrupts, or sleep. [F21, F125]

## Object Lifetimes

- Because `xas_start()` trusts any valid `xas->xa_node` (`xas_valid(xas)`) and immediately dereferences it via `xas_reload()` without walking from `xa->xa_head`, any code that drops `xa->xa_lock` or `rcu_read_lock()` must reset `xas->xa_node` to `XAS_RESTART` (via `xas_reset()`, `xas_set()`, `xas_pause()`, or `xas_nomem()`) before reusing `xas`. [F23]
- When aborting an operation on `struct xa_state` or cleaning up after `xas_split_alloc()` or `xas_try_split()`, callers must call `xas_destroy()` rather than `xas_nomem()` to free preallocated nodes in `xas->xa_alloc`, because `xas_nomem()` allocates a new node when `xas->xa_node == XA_ERROR(-ENOMEM)`. Preallocated nodes in `xas->xa_alloc` must be freed via `xas_destroy()` / `radix_tree_node_rcu_free()` rather than raw `kmem_cache_free()`, because `radix_tree_node_cachep` requires freed nodes to have zeroed `slots` and `tags`. [F1, F106]
- `xas_alloc()` consumes a single preallocated `struct xa_node` by setting `xas->xa_alloc = NULL` rather than advancing along `node->parent`, whereas `xas_split_alloc()` chains multiple nodes via `node->parent` to be popped by `xas_split()` or freed by `xas_destroy()`. [F6]
- Because `private_list` and `rcu_head` share a union in `struct xa_node`, `list_empty(&node->private_list)` must hold before `xa_node_free()` queues `node->rcu_head` via `call_rcu()` or `xas_destroy()` passes `node->rcu_head` to `radix_tree_node_rcu_free()`. [F3]
- In `ida_alloc_range()`, a fallback `struct ida_bitmap` allocated into `alloc` after dropping `xa_lock` must be freed via `kfree(alloc)` on both the `nospc` error exit and the `out` exit path whenever `bitmap != alloc`. [F2]

## API Contracts

- `xas_reload()` requires `xas_valid(xas)` to be true because it dereferences `xas->xa_node` whenever non-NULL; if `xas` may be in an error, bounds, or restart state (after `XA_STATE()`, `xas_reset()`, or `xas_pause()`), call `xas_load()` instead. [F36]
- When `xas_pause()` is called on a valid `xas` pointing to an `xa_node`, it must be invoked while still holding `xa_lock` or `rcu_read_lock()` because it reads `xas->xa_node` to advance `xas->xa_index` past all sibling slots, setting `xas->xa_node` to `XAS_BOUNDS` if `xas->xa_index` wraps to `0` or `XAS_RESTART` otherwise. When `xas_find_marked()` finishes without finding a match, it must set `xas->xa_node` to `XAS_RESTART` whenever `xas->xa_index > max`, and to `XAS_BOUNDS` only when `xas->xa_index <= max`. [F58, F60, F89]
- `__xa_store()`, `__xa_cmpxchg_raw()`, and `__xa_alloc()` reject `xa_is_advanced(entry)` (`xa_is_internal(entry) && entry <= XA_RETRY_ENTRY`) with `-EINVAL` while permitting `XA_ZERO_ENTRY`, whereas `xa_store_range()` rejects all `xa_is_internal(entry)` entries (including `XA_ZERO_ENTRY`) with `XA_ERROR(-EINVAL)`. [F45]
- `__xa_alloc()` and `__xa_alloc_cyclic()` (and `xa_alloc*` wrappers) require the XArray to be initialized with `XA_FLAGS_TRACK_FREE` (`XA_FLAGS_ALLOC` or `XA_FLAGS_ALLOC1`), failing with `-EINVAL` and `WARN_ON_ONCE` if `!xa_track_free(xa)`. `__xa_alloc_cyclic()` returns `1` on wrap-around and `0` otherwise, whereas `xa_alloc_cyclic*()` wrappers normalize non-negative returns to `0`. [F34, F47]
- `xa_destroy()` frees only internal `struct xa_node` structures and never frees user pointers stored in the XArray, whereas `ida_destroy()` iterates over the IDA and calls `kfree()` on every non-value `struct ida_bitmap` entry. [F10]
- Any XArray mutation updating node counts on an array whose `xa_node`s may be linked on `node->private_list` must set `xas->xa_update` via `xas_set_update()`, because `xas_update()` asserts `list_empty(&node->private_list)` when `xas->xa_update` is `NULL`. [F131]
- `idr_alloc()` and `idr_alloc_cyclic()` take an exclusive upper bound `end` (treating `end <= 0` as `INT_MAX + 1`), whereas `idr_alloc_u32()`, `xa_alloc*()` (`struct xa_limit`), `ida_alloc_range()`, and `ida_find_first_range()` take inclusive upper bounds. [F49]

## Error Handling

- Pointer-returning XArray mutation functions (`xa_store`, `__xa_store`, `xa_cmpxchg`, `__xa_cmpxchg`, `xa_store_range`) return `XA_ERROR` pointers rather than `ERR_PTR`, so callers must use `xa_is_err()` / `xa_err()` instead of `IS_ERR()` / `PTR_ERR()`. By contrast, `idr_replace()` returns `ERR_PTR(-ENOENT)` when the ID is unallocated (`!slot` or tagged `IDR_FREE`) or negative (without `WARN_ON_ONCE()`, as UAPI ioctls pass untrusted handles), so callers of `idr_replace()` must use `IS_ERR()` / `PTR_ERR()`. [F31, F51, F128]
- `xa_is_err()` must compare internal entries against `xa_mk_internal(-MAX_ERRNO)` and `xa_err()` must extract the errno using a signed right shift `(long)entry >> 2` rather than `xa_to_internal()` (which does an unsigned shift). `xas_set_err()` must only be called with a negative `err`, and clearing an error from `struct xa_state` requires `xas_reset()` rather than `xas_set_err(xas, 0)`. [F32, F33]
- `xas_nomem()` and `__xas_nomem()` only allocate a node and reset `xas->xa_node` to `XAS_RESTART` when `xas->xa_node == XA_ERROR(-ENOMEM)`; for any other state (other errors or success), they call `xas_destroy(xas)` to free `xas->xa_alloc` and return `false` without overwriting `xas->xa_node`. When `xas_split_alloc()` or `xas_try_split()` fails, it must call `xas_destroy(xas)` before recording the error via `xas_set_err()`. [F40, F41]
- In `xas_create_range()`, parent traversal must stop if `node->shift >= shift`, and on `xas_error(xas)` it must restore `xas->xa_shift`, `xas->xa_sibs`, and `xas->xa_index` while preserving `xas->xa_node`. In `xa_store_range()`, check `if (xas_error(&xas)) goto unlock;` after `xas_store(&xas, entry)` before advancing `first += xas_size(&xas)`. [F39, F95]

## Known Pitfalls

- When computing an index delta or mask from `unsigned char` slot fields (`xas->xa_offset`, `xas->xa_sibs`, `node->offset`), widen the operand to `unsigned long` before left-shifting by `node->shift` or `xas->xa_shift` (which can reach 60 on 64-bit systems and overflow a 32-bit `int`). `xas_set_order()` must guard `(index >> order) << order` with `order < BITS_PER_LONG ? ... : 0`, and `xa_store_range()` must guard `__ffs(last + 1)` with `if (last + 1)` because `last == ULONG_MAX` wraps `last + 1` to 0. [F96, F99]
- In `xas_find_marked()`, after advancing `xas->xa_index` via `xas_move_index(xas, offset)`, the range check must be `if ((xas->xa_index - 1) >= max)` so advancing to `offset == XA_CHUNK_SIZE` at the top of the `ULONG_MAX` chunk (wrapping `xas->xa_index` to 0) is caught. `xa_find_after()` must return `NULL` immediately if `xas.xa_index = *indexp + 1` wraps to `0`, and inside its loop must `continue` when `xas_sibling(&xas)` is true before checking `xas_retry(&xas, entry)`. [F78, F90]
- In `xas_find_chunk()`, direct single-word bitmap masking (`*addr & (~0UL << offset)`) must only be used when `XA_CHUNK_SIZE == BITS_PER_LONG` and `offset < XA_CHUNK_SIZE`; otherwise `find_next_bit(addr, XA_CHUNK_SIZE, offset)` must be used. [F111]
