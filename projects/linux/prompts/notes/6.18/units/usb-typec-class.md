# USB TYPEC CLASS

This unit (`drivers/usb/typec`) implements USB Type-C and Power Delivery (PD) controller drivers and frameworks across three sub-areas: TCPM/TCPCI hardware drivers (Fairchild FUSB302, Maxim TCPCI with contaminant detection, MediaTek MT6360/MT6370, Richtek RT1711H, Intel WhiskeyCove PMIC), the TI TPS6598x / Apple CD321x / TI TPS25750 standalone PD controller driver (`tipd`), and the USB Type-C Connector System Software Interface (UCSI) core framework with its transport backends (ACPI, Cypress CCGx, Qualcomm PMIC GLINK, STM32G0, Lenovo Yoga C630).

## Architecture & Data Flow

- UCSI `MESSAGE_IN` reads via `ucsi_run_command()` cannot exceed `UCSI_MAX_DATA_LENGTH(ucsi)` (16 bytes prior to UCSI v2.0, 255 bytes in v2.0+), so callers reading larger structures (`ucsi_get_connector_status()`, `ucsi_get_pd_message()`, `ucsi_get_pdos()`) must clamp or chunk transfer sizes (at most `UCSI_MAX_PDOS` (4) PDOs at once). [F83]
- UCSI connector numbers (`con->num`, `UCSI_CCI_CONNECTOR`) and RDO indices (`rdo_index(con->rdo)`) are 1-based while `ucsi->connector`, `con->src_pdos`, and backend port arrays are 0-based: subtract 1 and validate `1 <= num <= max_ports` (rejecting 0 and `num > max_ports`, not `num >= max_ports`), and verify `index > 0` and `con->num_pdos > 0` before indexing `con->src_pdos` in `ucsi_psy_get_voltage_now()`/`max()`. [F81, F84]
- `ucsi_init()` allocates `ucsi->connector` with `ucsi->cap.num_connectors + 1` elements so the trailing NULL `con->port` terminates `for (con = ...; con->port; con++)` loops. Because `ucsi_register()` schedules `ucsi_init_work()` asynchronously, `ucsi_resume()`, `ucsi_unregister()`, and `yoga_c630_ucsi_read_port0_status()` must check `ucsi->connector != NULL` before dereferencing it. [F38, F97]
- `con->plug` is only allocated when `UCSI_CAP_ALT_MODE_DETAILS` is set, so `typec_plug_set_num_altmodes()` and `typec_unregister_plug()` require `con->plug != NULL`. Whenever the PPM is reset after init (`ucsi_role_cmd()`) or resumes (`ucsi_resume_work()`), re-send `UCSI_SET_NOTIFICATION_ENABLE | ucsi->ntfy`. [F37, F58]
- Call `ucsi_port_psy_changed(con)` alongside `typec_set_pwr_role()` in `ucsi_handle_connector_change()` and `ucsi_register_port()`, and after updating `con->num_pdos` in `ucsi_get_src_pdos()`; `ucsi_pwr_opmode_change()` must set `con->rdo = UCSI_CONSTAT(con, RDO)` in `UCSI_CONSTAT_PWR_OPMODE_PD` and `0` otherwise. [F55, F56]
- In `ucsi_partner_change()` and `ucsi_register_port()`, force `u_role = USB_ROLE_NONE` whenever `!UCSI_CONSTAT(con, PARTNER_FLAG_USB)` before `usb_role_switch_set_role()`, and test dual-role capabilities (`OPMODE_DRP`, `PROVIDER && CONSUMER`) before single-role flags. In `pmic_glink_ucsi_connector_status()`, check `UCSI_CONSTAT(con, CONNECTED)` first and set `TYPEC_ORIENTATION_NONE` when unplugged. [F60, F94, F96]
- In `ucsi_ccg_update_set_new_cam_cmd()`, bounds-check `UCSI_SET_NEW_CAM_GET_AM(*cmd)` against `ARRAY_SIZE(uc->updated)`; when `new_port->linked_idx == UCSI_MULTI_DP_INDEX`, mode entry must select the matching `uc->orig` index and save `new_port->active_idx`, whereas mode exit must reuse `new_port->active_idx`. In `ucsi_stm32g0.c`, guard `ucsi_stm32g0_unregister()` and `client->irq` with `!g0->in_bootloader` and `i2c_unregister_device(g0->i2c_bl)` with `g0->fw_name`. [F46, F82, F98]
- In `tipd/core.c`, invoke chip-specific operations through `tps->data` across all lifecycle paths, and only downcast `struct tps6598x *` to `struct cd321x *` when `tps->data` is `cd321x_data`. In `cd321x_interrupt()`, `tps25750_interrupt()`, and `tps6598x_interrupt()`, write `TPS_REG_INT_CLEAR1`/`CLEAR2` before reading status registers, and test 64-bit `TPS_REG_INT_*` masks only against `event[0]`/`event1[0]`/`event2[0]`, never `event[1]`. [F73, F77, F120, F134]
- In `fusb302.c`, `tcpm_set_pd_rx()` must check `chip->pd_rx_on == on` under `chip->lock` to return early without flushing FIFOs; `fusb302_set_cc_polarity_and_pull()` must preserve `FUSB_REG_SWITCHES0_VCONN_CC1`/`CC2` when `chip->vconn_on` is true; and `fusb302_pd_read_message()` must validate `len <= PD_MAX_PAYLOAD * 4` before reading `msg->payload`. [F66, F69, F75]
- In `max_contaminant_read_comparators()`, reset `CCLPMODESEL` in `TCPC_VENDOR_CC_CTRL2` to `LOW_POWER_MODE_DISABLE`; in `max_contaminant_is_contaminant()`, call `max_contaminant_enable_toggling(chip)` whenever `TCPC_CC_STATUS_TOGGLING` is off and `chip->contaminant_state` is non-`DETECTED` on an open port. In `rt1711h_probe()`, clear `TCPC_ALERT_MASK` to `0` after reset and before `tcpci_register_port()` / `devm_request_threaded_irq()`, then write `alert_mask` after IRQ registration. [F64, F65, F129]

## Synchronization

- UCSI lock hierarchy is `con->lock` -> `ucsi->ppm_lock` -> backend locks (`ucsi_ccg->lock`, `pmic_glink_ucsi->lock`). `ucsi_send_command_common()` must hold `ucsi->ppm_lock` continuously across `ucsi_run_command()` and `ucsi_read_error()` when `UCSI_CCI_ERROR` is set, and unlock it on all return paths. [F3, F18, F19]
- `ucsi_con_mutex_lock()` acquires `con->lock` only when it returns `true`, so callers must call `ucsi_con_mutex_unlock()` if and only if it returned `true`. `ucsi_displayport_work()` must not hold `dp->con->lock` around `typec_altmode_vdm()`, and `ucsi_displayport_ops` callbacks must use `ucsi_con_mutex_lock()` rather than `mutex_lock()`. [F2, F23]
- In `ucsi_sync_control_common()`, set `ACK_PENDING` or `COMMAND_PENDING` in `ucsi->flags` and call `reinit_completion(&ucsi->complete)` before `ucsi->ops->async_control()`, and test-and-clear the matching bit in `ucsi_notify_common()` before `complete()`. In `ucsi_dr_swap()` and `ucsi_pr_swap()`, run `reinit_completion(&con->complete)` and `ucsi_role_cmd()` under `con->lock`, then unlock `con->lock` before `wait_for_completion_timeout()`. [F17, F24]
- `ucsi_partner_task()` requires `con->lock` held, and `ucsi_poll_worker()` must lock `con->lock` and verify `con->partner != NULL` before calling `uwork->cb(con)`. In `ucsi_init()`, assign `ucsi->connector` and finish `ucsi_register_port()` before setting `UCSI_ENABLE_NTFY_CONNECTOR_CHANGE` in `ucsi->ntfy`. [F20, F25]
- In `ucsi_glink.c`, initialize `ucsi->ucsi`, works, completions, locks, and `ucsi->client` before `pmic_glink_client_register()`, and register `pmic_glink_ucsi_destroy()` before `devm_pmic_glink_client_alloc()`. `pmic_glink_ucsi_pdr_notify()` runs in atomic context and must update `ucsi->pd_running` under `ucsi->state_lock` and schedule `ucsi->register_work` instead of calling `ucsi_register()`/`unregister()`; `pmic_glink_ucsi_callback()` must defer `UC_UCSI_USBC_NOTIFY_IND` to `ucsi->notify_work` rather than calling `pmic_glink_ucsi_read()`. [F26, F146, F147]
- In `ucsi_ccg.c`, protect `uc->op_data` with `uc->op_lock` (zeroing `uc->op_data.cci` before writing `UCSI_CONTROL` in `ucsi_ccg_async_control()`, and calling `ccg_op_region_update()` before clearing `CCGX_RAB_INTR_REG` and calling `ucsi_notify_common()`). Hold `uc->lock` for `ccg_send_command()` and `RESET_PENDING`, and call `ucsi_unregister()` and `free_irq()` before `ccg_fw_update()`. [F27, F28]
- In `tipd/core.c`, `tipd_data::irq_handler` runs in process context under `tps->lock`. Access `cd321x->update_status` under `tps->lock`, OR-accumulating `status_changed |= (update_status.status ^ tps.status)` in `cd321x_queue_status()` and clearing `status_changed = 0` in `cd321x_update_work()`. `tps6598x_remove()` must stop the IRQ or `tps->wq_poll` and call `cd321x_remove()` before `tps6598x_disconnect()` and `unregister_port()`. [F30, F71, F157]
- In `fusb302.c`, `chip->logbuffer_lock` nests inside `chip->lock`; `fusb302_pm_suspend()` must set `chip->irq_suspended = true` under `chip->irq_lock` before `flush_work(&chip->irq_work)` and `fusb302_pm_resume()` must clear it under `chip->irq_lock`. In `tcpci_maxim_core.c`, `max_tcpci_isr()` must only call `pm_wakeup_event()`, check `chip->port`, and return `IRQ_WAKE_THREAD`. [F31, F155, F156]

## Object Lifetimes

- UCSI transport drivers must unregister notification handlers/IRQs and call `ucsi_unregister()` before `ucsi_destroy()`. `ucsi_unregister()` must cancel `ucsi->work` and `ucsi->resume_work`, disable notifications, and for each connector cancel `con->work` and reschedule all `con->partner_tasks` with delay `0` under `con->lock` before `destroy_workqueue(con->wq)` and port unregistration. [F4, F141]
- `ucsi_unregister_partner()` must unregister child objects before `typec_unregister_partner(con->partner)` (`ucsi_unregister_partner_pdos`, partner altmodes, and `ucsi_unregister_cable` after plug/altmodes) and NULL `con->partner`, `con->cable`, `con->plug`, `adev[i]`, `con->partner_sink_caps`, `con->partner_source_caps`, and `con->partner_pd` (including on `ucsi_register_partner_pdos()` error paths). [F6, F7]
- When unregistering `UCSI_RECIPIENT_SOP` DisplayPort or non-debug NVIDIA VLink altmodes, `ucsi_unregister_altmodes()` must call `ucsi_displayport_remove_partner()` on `typec_altmode_get_partner(adev[i])` before `typec_unregister_altmode(adev[i])`. [F8]
- Release owned `fwnode_handle` and switch references on all paths: `ucsi_register_port()` must put `cap->fwnode` after `ucsi_find_fwnode()`; `wcove` must pair `fwnode_create_software_node()` with `fwnode_remove_software_node()`; and `tps6598x_probe()` must call `fw_devlink_purge_absent_suppliers(fwnode)`, put `fwnode` on all paths, and release `tps->role_sw` with `usb_role_switch_put()`. [F1, F12, F133, F136]
- In `fusb302`, put `chip->tcpc_dev.fwnode` on probe failure and in `fusb302_remove()`, where `free_irq()` must precede `cancel_work_sync(&chip->irq_work)` and `cancel_delayed_work_sync(&chip->bc_lvl_handler)` before `tcpm_unregister_port()` and `destroy_workqueue()`. [F14, F29]
- `cd321x_register_port()` error paths and `cd321x_unregister_port()` must release `cd321x->mux` (`typec_mux_put()`), unregister and NULL `port_altmode_dp`/`port_altmode_tbt`, and unregister `tps->port` in reverse order; `cd321x_typec_update_mode()` must reset `cd321x->state.data = NULL` before returning whenever it points to stack data. [F11, F121]
- In `tipd/core.c`, `tps_request_firmware()` frees `*fw` and returns `-EINVAL` if `(*fw)->size == 0`, and callers must not dereference `fw` after `release_firmware(fw)`. Call `tps->data->reset(tps)` on probe failure after `TPS_REG_INT_MASK1` setup and in `tps6598x_remove()`, and re-run `tps->data->init(tps)` in `tps6598x_resume()` if `tps6598x_check_mode(tps) == TPS_MODE_PTCH`. [F9, F78, F137]

## API Contracts

- `ucsi_run_command()`, `ucsi_send_command_common()`, and `ucsi_send_command()` take `size` in bytes (convert `UCSI_GET_*_SIZE` bit-count macros with `BITS_TO_BYTES()`) and return non-negative `UCSI_CCI_LENGTH(*cci)` or a negative errno; store return values in signed `int` and check `< 0`. [F32, F35]
- `ucsi_get_pd_caps()` returns `NULL` (`ERR_PTR(0)`) when 0 PDOs are read and an `IS_ERR()` pointer on negative error, and must set `pd_caps.pdo[ret] = 0` when `ret < PDO_MAX_OBJECTS`. `ucsi_read_pdos()` must pass `num_pdos - 1` to `UCSI_GET_PDOS_NUM_PDOS` and `num_pdos * sizeof(u32)` as size. `ucsi_get_partner_identity()` and `ucsi_get_cable_identity()` must read `sizeof(u32[7])` and copy from `&vdo[1]`, skipping the VDM header at `vdo[0]`. [F41, F42, F125]
- `ucsi_bitfield_read()` requires field bit sizes between 1 and 32 and triggers a `WARN()` if `(_ver_) < f.version`, so check `con->ucsi->version` before reading versioned `UCSI_CONCAP()`/`UCSI_CONSTAT()` fields, and convert 0-based 2-bit PD major revisions with `UCSI_SPEC_REVISION_TO_BCD()`. [F109, F114, F139]
- `struct ucsi_operations` passed to `ucsi_create()` must provide non-NULL `read_version`, `read_cci`, `poll_cci`, `read_message_in`, `sync_control` (blocking), and `async_control` (non-blocking); use `poll_cci()` rather than `read_cci()` when notifications are disabled, and never acquire `con->lock` inside `connector_status()`. [F158, F159, F160, F161]
- `ccg_send_command()` returns a negative errno or positive `uc->cmd_resp`, so check `ret != CMD_SUCCESS` (or `RESET_COMPLETE`). In `tipd/core.c`, `tps6598x_read_status()`, `tps6598x_read_power_status()`, and `read_data_status()` return `bool` (check `!func(...)`), whereas `tps6598x_check_mode()` returns a non-negative mode enum or negative errno (check `ret < 0`). In `tcpci_maxim_core.c`, `tcpci_init()` must return `-1` and `max_tcpci_irq()` must loop `while (status)`. [F45, F48, F49, F130]

## Error Handling

- `ucsi_run_command()` must set `*cci = 0` before checking `size > UCSI_MAX_DATA_LENGTH(ucsi)` or calling `sync_control()`, preserve the primary error (`-EBUSY` or `err`) via `?:` when issuing `UCSI_CANCEL` or `ucsi_acknowledge()`, and pass `conn_ack = false` on error. Guard `con->psy` with `IS_ERR_OR_NULL(con->psy)` in `ucsi_unregister_port_psy()` and `ucsi_port_psy_changed()`. [F33, F34, F39]
- In `ucsi_ccg.c`, balance `pm_runtime_get_sync()` with `pm_runtime_put_sync()` on every exit path in `ucsi_ccg_sync_control()`, `ccg_read()`, and `ccg_write()`. In `tps25750_write_firmware()`, restore `client->addr` and `client->adapter->timeout` after `regmap_raw_write()`, and call `tps25750_abort_patch_process()` if `tps25750_start_patch_burst_mode()` fails. In `max_contaminant_read_resistance_kohm()`, return `mv` (not `ret`) when `mv < 0`. [F53, F138, F142]

## External Contracts

- In `ucsi_reset_connector()`, bit 23 of `UCSI_CONNECTOR_RESET` selects Hard Reset in UCSI < v1.1 (`UCSI_CONNECTOR_RESET_HARD_VER_1_0`), is omitted in v1.1..v1.2, and in v2.0+ bit 23 = 0 selects Hard Reset while bit 23 = 1 (`UCSI_CONNECTOR_RESET_DATA_VER_2_0`) selects Data Reset. In `ucsi/psy.c`, multiply mV/mA values by 1000 for `power_supply_propval.intval` (uV/uA), and only read `UCSI_CONSTAT(con, BC_STATUS)` in `ucsi_psy_get_charge_type()` when connected as `TYPEC_SINK`. [F88, F113, F165]

## Known Pitfalls

- Cast operands to `u64` before shifting in UCSI command macros, use `BIT_ULL()` for `UCSI_ENABLE_NTFY_*` and `TPS_REG_INT_*` constants, use `do_div()` in `_fusb302_log()`, and use `time_before()` / `time_is_before_jiffies()` / `time_is_after_jiffies()` in all `jiffies` polling loops. [F106, F107, F108, F111, F115]
- In `ucsi_register_altmodes()`, do not increment `i` on `-EBUSY`, stop when `len <= 0`, and advance `i` by `len / sizeof(alt[0])`; in `ucsi_register_altmodes_nvidia()`, `break` (do not `return 0`) on `!len` or `!alt.svid` in the first loop. In `ucsi_reset_ppm()`, clear pre-existing `UCSI_CCI_RESET_COMPLETE` via `UCSI_SET_NOTIFICATION_ENABLE` + `poll_cci()`, and re-send `UCSI_PPM_RESET` if `cci & ~UCSI_CCI_RESET_COMPLETE` is non-zero. [F92, F93, F95]
- In `tcpci_maxim_core.c`, do not clear `TCPC_ALERT_RX_STATUS` before `process_rx()` (and clear both `RX_STATUS` and `RX_BUF_OVF` when `RX_BUF_OVF` is set alone); read `count + 1 <= TCPC_RECEIVE_BUFFER_LEN` bytes from `TCPC_RX_BYTE_CNT` and parse `msg.header` at `TCPC_RECEIVE_BUFFER_RX_BYTE_BUF_OFFSET` (2); and in `process_tx()`, check `TCPC_ALERT_TX_SUCCESS` before `TX_FAILED` while separately checking `TX_SUCCESS && TX_FAILED` to call `max_tcpci_init_regs()`. [F102, F103, F122]
- In `fusb302.c`, `fusb302_handle_togdone_src()` must measure the first CC pin before `fusb302_set_toggling(chip, TOGGLING_MODE_OFF)` and restore the saved `toggling_mode` on retry; `FUSB_REG_INTERRUPTA_TX_SUCCESS` and `FUSB_REG_INTERRUPTB_GCRCSENT` must both read the RX FIFO and dispatch `tcpm_pd_transmit_complete()` vs `tcpm_pd_receive()` by checking if the header is a 0-length `PD_CTRL_GOOD_CRC`. [F104, F105]
- In `tipd/core.c`, `tps6598x_check_mode()` must use a zero-initialized `char mode[5] = { }` for NUL termination; `tps6598x_interrupt()` must use `TPS_65987_8_INTEVENT_LEN` (11 bytes) on TPS65987/8; and `tps6598x_block_read()`/`write()` must handle the 1-byte length prefix when `tps->i2c_protocol` is true. [F123, F135]
