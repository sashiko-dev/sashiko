# DPLL SUBSYSTEM

The DPLL (Digital Phase Locked Loop) subsystem provides a generic kernel framework and Generic Netlink UAPI (`dpll` family) for registering, querying, configuring, and monitoring hardware DPLL devices and their associated input, output, and MUX pins. Device drivers register `dpll_device` and `dpll_pin` instances with callback tables (`dpll_device_ops`, `dpll_pin_ops`), while the subsystem manages shared object lifetimes, multi-driver registrations, netdev pin associations, and multicast change notifications to user space.

## Architecture & Data Flow

- `dpll_device.pin_refs` and `dpll_pin.parent_refs` are indexed by driver-assigned `pin->pin_idx` and store `struct dpll_pin *` (`ref->pin` in `struct dpll_pin_ref`), whereas `dpll_pin_xa` and `dpll_pin.ref_sync_pins` are indexed by subsystem-allocated `pin->id`, and `dpll_device_xa` and `dpll_pin.dpll_refs` are indexed by `dpll->id` (never `dpll->device_idx`, with `dpll_refs` storing `ref->dpll`). Broken by: mixing `pin->id` (`DPLL_A_PIN_ID`) with `pin->pin_idx` or `dpll->id` with `dpll->device_idx`, or reading the wrong `dpll_pin_ref` union member. [F26, F27, F51]
- Because `dpll_pin_on_pin_register()` populates both `pin->parent_refs` and `pin->dpll_refs` on a MUX child pin, `dpll_cmd_pin_get_one()` must test `xa_empty(&pin->parent_refs)` first to choose between `dpll_msg_add_pin_dplls()` and `dpll_msg_add_pin_parents()`. Broken by: branching on `!xa_empty(&pin->dpll_refs)` before checking `pin->parent_refs`, causing MUX child pins to emit `DPLL_A_PIN_PARENT_DEVICE` instead of `DPLL_A_PIN_PARENT_PIN`. [F60]
- `dpll_device_xa` entries must carry `DPLL_REGISTERED` only while `dpll->registration_list` has a registration with non-NULL `ops->mode_get` and `ops->lock_status_get` (`dpll_device_registration_first(dpll)` is dereferenced unconditionally). `__dpll_pin_register()` and `__dpll_pin_unregister()` update `dpll->pin_refs` and `pin->dpll_refs` in lockstep, keeping `DPLL_REGISTERED` on `dpll_pin_xa` only while `pin->dpll_refs` is non-empty, and `dpll_*_unregister()` must send delete notifications before removing the final registration or clearing `DPLL_REGISTERED`. [F22, F23, F41]
- Before exposing or operating on a `struct dpll_pin` in netlink handlers or notifications (`dpll_pin_pre_doit()`, `dpll_nl_pin_id_get_doit()`, `dpll_nl_pin_get_dumpit()`, `dpll_pin_event_send()`, `dpll_msg_add_pin_ref_sync()`, `dpll_pin_ref_sync_state_set()`), `dpll_pin_available(pin)` must be verified rather than checking only `xa_load()` or `DPLL_REGISTERED`. [F36]
- Unregistering a pin via `__dpll_pin_unregister()` must call `dpll_pin_ref_sync_pair_del(pin->id)` to erase `pin->id` from every pin's `ref_sync_pins` XArray in `dpll_pin_xa` and emit `__dpll_pin_change_ntf()` for each affected pin. [F44]

## Synchronization

- Exported lifecycle and notification APIs (`dpll_device_get()`, `dpll_device_register()`, `dpll_pin_get()`, `dpll_pin_register()`, `dpll_device_change_ntf()`, `dpll_pin_change_ntf()`, etc.) acquire `dpll_lock` and use `GFP_KERNEL`, so callers must run in process context without holding any lock acquired inside `dpll_device_ops`/`dpll_pin_ops`. Paths already holding `dpll_lock` (Genl doit/dumpit and driver callbacks) must never call `dpll_device_change_ntf()` or `dpll_pin_change_ntf()`, using `__dpll_device_change_ntf()` / `__dpll_pin_change_ntf()` instead. [F15, F88]
- Because `dpll_nl_family.parallel_ops` is `true`, every `.doit` entry in `dpll_nl_ops` must pair `.pre_doit` (`dpll_lock_doit`, `dpll_pre_doit` for `dpll_device *`, or `dpll_pin_pre_doit` for `dpll_pin *`) with `.post_doit` (`dpll_unlock_doit`, `dpll_post_doit`, or `dpll_pin_post_doit`). `.pre_doit` must unlock `dpll_lock` before returning any non-zero error, and `.doit` handlers must never unlock `dpll_lock` or retain the unreferenced `info->user_ptr[0]` beyond `.post_doit`. [F16, F18, F75, F92]
- `dpll_nl_device_get_dumpit` and `dpll_nl_pin_get_dumpit` must lock and unlock `dpll_lock` inside `.dumpit` (not `.start`/`.done`), preserving `nlk_cb_mutex` -> `dpll_lock` order, and store only the XArray index `ctx->idx` (never a `dpll_device *` or `dpll_pin *` pointer) in `cb->ctx` (`struct dpll_dump_ctx`). On serialization failure in `.dumpit`, call `genlmsg_cancel(skb, hdr)`, and on `-EMSGSIZE` save index `i` into `dpll_dump_context(cb)->idx` and return `skb->len`. [F17, F46, F102]
- `dpll_netdev_pin_set()` and `dpll_netdev_pin_clear()` unconditionally acquire `rtnl_lock()` inside `dpll_netdev_pin_assign()`, so callers must invoke them from sleepable process context without already holding `rtnl_lock`. [F89]

## Object Lifetimes

- `dpll_pin_put()` synchronously destroys `pin->dpll_refs`, `pin->parent_refs`, `pin->ref_sync_pins`, and `pin->prop` via `dpll_pin_prop_free()` before `kfree_rcu(pin, rcu)`. RCU readers of `dev->dpll_pin` (`dpll_netdev_pin()`, `dpll_netdev_pin_handle_size()`, `dpll_netdev_add_pin_handle()`, `dpll_msg_add_pin_handle()`) use `rcu_dereference_rtnl()` without `dpll_lock`, so they require `kfree_rcu()` and may only access fields embedded directly in `struct dpll_pin` (like `pin->id`), never `pin->prop` strings or XArrays. [F20, F91]
- `dpll_netdev_pin_set()` publishes `dev->dpll_pin` under `rtnl_lock()` via `rcu_assign_pointer()` without taking a reference on `struct dpll_pin`, so the driver must call `dpll_netdev_pin_clear(dev)` to reset `dev->dpll_pin` to `NULL` before dropping the pin's final reference with `dpll_pin_put()`. [F10]
- `dpll_xa_ref_pin_del()` and `dpll_xa_ref_dpll_del()` must unlink and `kfree()` the matching `struct dpll_pin_registration` on every call, but must erase and `kfree()` the enclosing `struct dpll_pin_ref` only when `refcount_dec_and_test(&ref->refcount)` reaches zero. [F4]
- `dpll_pin_on_pin_register()` increments `pin->refcount`, adds `parent` to `pin->parent_refs` with `cookie = pin`, and registers `pin` on each DPLL in `parent->dpll_refs` via `__dpll_pin_register()` with `cookie = parent` (whereas direct `dpll_pin_register()` / `dpll_pin_unregister()` use `cookie = NULL` for `dpll_pin_registration_find()`). Both its error rollback path and `dpll_pin_on_pin_unregister()` must undo all three steps symmetrically with matching cookies. [F7, F29]
- Neither `dpll_pin_register()` nor `dpll_pin_on_pin_register()` may require the target `dpll_device` or parent `dpll_pin` to already carry the `DPLL_REGISTERED` mark, because multi-instance drivers can register pins before the instance owning the parent device or MUX pin registers it. [F77]
- `dpll_device_unregister()`, `dpll_pin_unregister()`, and `dpll_pin_on_pin_unregister()` only remove the `(ops, priv)` registration entry without dropping the object refcount, so drivers must still call `dpll_device_put()` and `dpll_pin_put()`. Before the final `dpll_device_put()` drops `dpll->refcount` to zero, all pins and device registrations on `dpll` must be unregistered so `dpll->pin_refs` and `dpll->registration_list` are empty and `DPLL_REGISTERED` is cleared. [F78, F79]
- `dpll_pin_alloc()` deep-copies all dynamically sized fields of `struct dpll_pin_properties` into `pin->prop` via `dpll_pin_prop_dup()` (rolling back partial allocations in reverse order on failure), and `dpll_pin_put()` releases them via `dpll_pin_prop_free()`. Broken by: adding a pointer field to `struct dpll_pin_properties` and only shallow-copying it via `memcpy()` in `dpll_pin_prop_dup()` without duplicating it or freeing it in `dpll_pin_prop_free()`. [F3]

## API Contracts

- `drivers/dpll/dpll_nl.c`, `drivers/dpll/dpll_nl.h`, and `include/uapi/linux/dpll.h` are YNL-generated files and must not be hand-edited; changes to DPLL Generic Netlink operations, attribute policies, or UAPI enums/constants must be made in `Documentation/netlink/specs/dpll.yaml` and regenerated. [F93]
- `dpll_device_get()`, `dpll_pin_get()`, `dpll_device_find_from_nlattr()`, and `dpll_pin_find_from_nlattr()` return `ERR_PTR(-errno)` on failure and never `NULL`, whereas `dpll_device_get_by_id()`, `dpll_pin_on_dpll_priv()`, and `dpll_pin_on_pin_priv()` return `NULL` when not found. Broken by: testing `!ptr` instead of `IS_ERR(ptr)` on `ERR_PTR`-returning functions or passing an `ERR_PTR` to `dpll_device_put()` / `dpll_pin_put()`. [F25]
- `dpll_pin_on_pin_priv(parent, pin)` takes `parent` first and child `pin` second, whereas `dpll_pin_ops.state_on_pin_get()` and `state_on_pin_set()` take `(pin, pin_priv, parent_pin, parent_pin_priv, ...)` where `pin_priv` comes from `dpll_pin_on_pin_priv(parent, pin)` and `parent_pin_priv` comes from `dpll_pin_on_dpll_priv(dpll, parent)`. [F28]
- `dpll_device_register()` only guarantees `ops->mode_get` and `ops->lock_status_get`; `dpll_pin_register()` requires matching `module` and `clock_id` and guarantees only `ops->direction_get` and `ops->state_on_dpll_get`; `dpll_pin_on_pin_register()` requires `parent->prop.type == DPLL_PIN_TYPE_MUX` and guarantees only `ops->direction_get` and `ops->state_on_pin_get`. All other callbacks must be NULL-checked, and `dpll_pin_ref_sync_pair_add(pin, ...)` requires `ops->ref_sync_get` on `pin`'s first DPLL ref. [F30, F31, F95, F96]
- Supporting `DPLL_A_PHASE_OFFSET_MONITOR` on a device or `DPLL_A_PIN_FREQUENCY`, `DPLL_A_PIN_ESYNC_FREQUENCY`, `DPLL_A_PIN_REFERENCE_SYNC`, or `DPLL_A_PIN_PHASE_ADJUST` setters on a pin requires both `*_get` and `*_set` callbacks across all registered DPLL refs (for no-op detection and rollback). Configuring pin state, priority, or direction (`dpll_pin_state_set()`, `dpll_pin_on_pin_state_set()`, `dpll_pin_prio_set()`, `dpll_pin_direction_set()`) requires both the `DPLL_PIN_CAPABILITIES_*_CAN_CHANGE` bit in `pin->prop.capabilities` and the `*_set` callback. [F97, F98]
- `dpll_device_event_send()` and `dpll_pin_event_send()` invoke `dpll_device_get_one()` and `dpll_cmd_pin_get_one()` with `extack = NULL`, so all `dpll_msg_add_*()` helpers and driver `.get` callbacks in `dpll_device_ops` and `dpll_pin_ops` must accept a `NULL` `extack` pointer. [F33]
- `dpll_msg_add_lock_status()` must initialize `status_error = 0` before `ops->lock_status_get()`. `dpll_msg_add_clock_quality_level()` must zero-initialize a `qls` bitmap of `DPLL_CLOCK_QUALITY_LEVEL_MAX + 1` bits before `ops->clock_quality_level_get()`, which sets 1-based `enum dpll_clock_quality_level` bit numbers (`1..DPLL_CLOCK_QUALITY_LEVEL_MAX`), whereas `dpll_pin_properties.capabilities` stores a pre-shifted bitmask of `enum dpll_pin_capabilities` (`1, 2, 4`). [F34, F49, F76, F99]
- `dpll_pin_get()` deep-copies `prop` via `dpll_pin_prop_dup()` only when first allocating the `struct dpll_pin` for `(clock_id, pin_idx, module)` and ignores `prop` on later lookups. Non-NULL `prop->freq_supported` requires `prop->freq_supported_num > 0` elements. `dpll_pin_ops.esync_get` must set `esync->range_num = 0` or point `esync->range` to at least `esync->range_num` persistent `struct dpll_pin_frequency` elements not freed by the caller. [F55, F73, F86]
- `dpll_pin_unregister()` requires `pin->parent_refs` to be empty (`WARN_ON(!xa_empty(&pin->parent_refs))`), so a pin registered with a parent MUX pin via `dpll_pin_on_pin_register()` must be unregistered via `dpll_pin_on_pin_unregister()`. [F80]

## Error Handling

- In Generic Netlink `.doit` handlers and notification senders that allocate an `sk_buff` with `genlmsg_new()` (`dpll_nl_pin_id_get_doit`, `dpll_nl_pin_get_doit`, `dpll_nl_device_id_get_doit`, `dpll_nl_device_get_doit`, `dpll_device_event_send`, `dpll_pin_event_send`), every error path before `genlmsg_reply()` or `genlmsg_multicast()` (including when `genlmsg_put_reply()` or `genlmsg_put()` returns `NULL`) must call `nlmsg_free(msg)`. [F11]
- When applying a pin setting across `pin->dpll_refs` in `dpll_pin_freq_set()`, `dpll_pin_esync_set()`, `dpll_pin_ref_sync_state_set()`, or `dpll_pin_phase_adj_set()`, failure on one entry must save `failed = ref` and jump to `rollback`, where a fresh `xa_for_each()` restores the old value on entries until `ref == failed` without overwriting `ret`. In `dpll_pin_on_pin_register()`, failure of `__dpll_pin_register()` on `parent->dpll_refs` must save `stop = i` and only unregister entries with `i < stop`. [F62, F63]
- In `dpll_xa_ref_pin_add()` and `dpll_xa_ref_dpll_add()`, when a new `struct dpll_pin_ref` is allocated and inserted into the XArray (`!ref_exists`), a subsequent failure to allocate `struct dpll_pin_registration` must erase the XArray entry and `kfree(ref)` before returning `-ENOMEM`. [F5]
- In `dpll_device_alloc()` and `dpll_pin_alloc()`, the return value of `xa_alloc_cyclic()` must be tested with `ret < 0` rather than `if (ret)` because `xa_alloc_cyclic()` returns `1` on wraparound and a negative errno only on failure. [F24]
- In nested attribute handlers `dpll_pin_ref_sync_set()`, `dpll_pin_parent_device_set()`, and `dpll_pin_parent_pin_set()`, each entry in `tb[]` populated by `nla_parse_nested()` can be `NULL` and must be checked for non-NULL before calling `nla_get_u32()` or other `nla_get_*()` accessors. [F37]
- When building pin netlink messages, `dpll_msg_add_ffo()` treats `-ENODATA` from `ops->ffo_get()` and `dpll_msg_add_pin_esync()` treats `-EOPNOTSUPP` from `ops->esync_get()` as non-fatal (omitting the attributes and returning `0`), whereas any other non-zero return aborts `dpll_cmd_pin_get_one()`. [F32]

## Known Pitfalls

- `dpll_pin_set_from_nlattr()`, `dpll_set_from_nlattr()`, `dpll_pin_find_from_nlattr()`, and `dpll_device_find_from_nlattr()` must iterate the raw Netlink payload via `nla_for_each_attr()` (not `info->attrs[]`) so repeated multi-attr nests in `SET` requests are processed and duplicate filter attributes in `ID_GET` requests fail with `-EINVAL`. In `dpll_pin_set_from_nlattr()` and `dpll_set_from_nlattr()`, `switch (nla_type(a))` must ignore unhandled attribute types (`DPLL_A_PIN_ID`, `DPLL_A_ID`). [F61, F105]
- In `dpll_pin_prop_dup()`, because `memcpy(dst, src, sizeof(*dst))` shallow-copies `src`'s pointers into `dst` first, each `kmemdup()`/`kstrdup()` call must check `!dst->...` rather than `!src->...`, and error unwind labels must only `kfree()` `dst` fields already overwritten prior to the failing allocation. [F59]
- In `dpll_xa_ref_pin_add()` and `dpll_xa_ref_dpll_add()`, breaking out of `xa_for_each()` with `ref_exists = true` preserves the matching `ref` cursor for appending `reg` to `ref->registration_list`, whereas normal loop termination leaves `ref` as `NULL` and requires allocating a new `struct dpll_pin_ref` under `if (!ref_exists)`. [F65]
