# NVM EXPRESS DRIVER

The NVMe host driver implements the core NVMe subsystem, fabrics host library, ANA multipath layer, ioctl/`io_uring` passthrough, DH-HMAC-CHAP/TLS authentication, Persistent Reservations, Zoned Namespaces, and the PCIe, TCP, and RDMA transport drivers.

## Architecture & Data Flow

- `gendisk->private_data` is `struct nvme_ns_head *` when `nvme_disk_is_ns_head(disk)` and `struct nvme_ns *` when `disk->fops == &nvme_bdev_ops`. `req->q->queuedata` is `struct nvme_ns *` on I/O queues and `NULL` on admin, fabrics, and connect queues; shared helpers (`nvme_init_request`, `nvme_req_qid`, `nvme_map_user_request`, `nvme_submit_user_cmd`, `nvme_log_error`) must check before dereferencing. [F41, F42]
- `blk-mq` does not zero `struct nvme_request` (`status`, `retries`, `flags`) on allocation, and transport PDUs (`struct nvme_iod`, `struct nvme_tcp_request`) are reused. Paths completing unprepped requests (`!(rq->rq_flags & RQF_DONTPREP)`, e.g. `nvme_fail_nonready_command`) must call `nvme_clear_nvme_request(rq)`; `nvme_prep_rq()` must zero `iod->flags`, `nr_descriptors`, `total_len`, and `meta_total_len`; `nvme_tcp_setup_cmd_pdu()` must reset `req->status = cpu_to_le16(NVME_SC_SUCCESS)` and send counters. [F47, F243]
- Per-request completion side effects (error logging gated on `!(req->rq_flags & RQF_QUIET)`, zoned append sector update via `nvme_end_req_zoned()`, bio tracing, and `nvme_mpath_end_request()` accounting) must run in `__nvme_end_req()` so both `nvme_end_req()` and batched `nvme_complete_batch_req()` execute them. [F53, F194]
- `nvme_cid()` packs a 4-bit generation counter (`nvme_req(rq)->genctr & 0xf`) in bits 12..15 of `command_id` and 12-bit `rq->tag` in bits 0..11. `nvme_find_rq()` and `nvme_cid_to_rq()` must strip the upper bits via `nvme_tag_from_cid()`, and `nvme_find_rq()` must mask 8-bit `rq->genctr` with `nvme_genctr_mask` (`0xf`). Untrusted wire `command_id`s must use `nvme_find_rq()`, whereas `nvme_cid_to_rq()` is only valid in `nvme_tcp_recv_data()` / `nvme_tcp_recv_ddgst()` after `nvme_tcp_handle_c2h_data()`. [F80, F115, F271]
- Async Event Requests (`nvme_is_aen_req` on QID 0 or `nvme_tcp_async_req` matching `&ctrl->async_req`) have no backing `struct request`; completion and failure paths in `pci.c`, `tcp.c`, and `rdma.c` must check `nvme_is_aen_req` or `nvme_tcp_async_req` before calling `nvme_find_rq()` or `blk_mq_rq_from_pdu()`. [F240]
- NVMe I/O queue IDs (`qid`) and `queues[1..n]` in `nvme_dev`, `nvme_tcp_ctrl`, and `nvme_rdma_ctrl` are 1-based (`0` is admin), while `blk-mq` I/O `hctx` indices, `tag_set.tags[]`, and `mq_map[]` are 0-based; mapping between them must offset by 1. Similarly, 1-based `crd` in `nvme_retry_req()`, `bi_write_stream` in `nvme_setup_rw()`, and `cur_fw_slot` in `nvme_get_fw_slot_info()` treat `0` as inactive and index `ctrl->crdt[]`, `head->plids[]`, and `log->frs[]` at `- 1`. [F78, F79, F110, F274]
- When `nvme_failover_req()` steals bios onto `ns->head->requeue_list`, it must reset each bio's device to `ns->head->disk->part0`, clear `REQ_POLLED` (`bi_cookie = BLK_QC_T_NONE`) and `REQ_NOWAIT` from `bio->bi_opf`, and zero `nvme_req(req)->status` before `nvme_end_req()`. In `nvme_decide_disposition()`, `blk_noretry_request(req)`, `NVME_STATUS_DNR`, and `retries >= nvme_max_retries` must return `COMPLETE` before checking `NVME_SC_AUTH_REQUIRED`, `REQ_NVME_MPATH` failover, or `RETRY`. [F55, F89]
- Multipath ANA paths (`nvme_scan_work`, `nvme_handle_aen_notice`, `nvme_failover_req`, `nvme_mpath_update`, `nvme_mpath_stop`, `nvme_mpath_add_disk`) must verify `ctrl->ana_log_buf != NULL` first. During `nvme_mpath_init_identify()`, `nvme_update_ns_ana_state()` must not call `nvme_mpath_set_live()` while `ctrl->state != NVME_CTRL_LIVE`, and if `ana_log_size` grows across reset, `nvme_mpath_stop(ctrl)` and `nvme_mpath_uninit(ctrl)` must precede reallocating `ctrl->ana_log_buf` and resetting `ctrl->nr_active = 0`. [F60, F61, F143]
- In `nvme_tcp_recv_pdu()`, `hdr->type == nvme_tcp_c2h_term` must dispatch to `nvme_tcp_handle_c2h_term()` before digest checks; otherwise `hdr->hlen == sizeof(struct nvme_tcp_rsp_pdu)` must be verified before `nvme_tcp_verify_hdgst()` indexes `pdu + hdr->hlen`. `nvme_tcp_init_recv_ctx()` resets `pdu_remaining`, `pdu_offset = 0`, `data_remaining = -1`, and `ddgst_remaining = 0` before `nvme_tcp_rsp`/`nvme_tcp_r2t` and after C2H data/DDGST, so `nvme_tcp_recv_state()` must test `pdu_remaining` before `ddgst_remaining` and `NVME_TCP_RECV_DATA` last. [F258, F266, F267, F292, F296]

## Synchronization

- Workqueues follow a strict drain hierarchy: `ctrl->reset_work` on `nvme_reset_wq` flushes `ctrl` works on `nvme_wq`, and `nvme_do_delete_ctrl()` on `nvme_delete_wq` calls `flush_work(&ctrl->reset_work)`, `nvme_stop_ctrl()`, `nvme_remove_namespaces()`, `ctrl->ops->delete_ctrl()`, and `nvme_uninit_ctrl()` in order. Before freeing the admin queue, transports must leave `NVME_CTRL_LIVE` via `nvme_change_ctrl_state()` and flush `async_event_work`; `nvme_remove_namespaces()` must clear paths and unquiesce I/O queues before `flush_work(&ctrl->scan_work)`. [F18, F20, F21, F32, F131]
- Any caller receiving non-zero `effects` from `nvme_passthru_start()` must call `nvme_passthru_end()`: when `NVME_CMD_EFFECTS_CSE_MASK` is set, `nvme_passthru_start()` acquires `ctrl->scan_lock` before `ctrl->subsys->lock` and freezes multipath queues (`nvme_mpath_start_freeze` / `nvme_mpath_wait_freeze`) before controller queues (`nvme_start_freeze` / `nvme_wait_freeze`), and `nvme_passthru_end()` reverses that order. [F9, F28]
- `nvme_subsystems_lock` must be acquired before `subsys->lock` and protects both `nvme_subsystems` and `subsys->ctrls` (with `__nvme_find_get_subsystem()` using `kref_get_unless_zero(&subsys->ref)`). `subsys->lock` serializes updates to `subsys->nsheads`, `head->list`, and `head->delayed_removal_secs` / `NVME_NSHEAD_QUEUE_IF_NO_PATH`, while readers of `head->list` and `head->current_path[]` (including `nvme_find_path(head)` and its synchronous command submission) must hold `srcu_read_lock(&head->srcu)`. [F25, F35, F58, F164, F228]
- Updates to `ctrl->namespaces` must hold `ctrl->namespaces_lock`, check `test_bit(NVME_CTRL_FROZEN, &ctrl->flags)` in `nvme_ns_add_to_ctrl_list()`, use RCU list primitives, and call `synchronize_srcu(&ctrl->srcu)` before `nvme_ns_remove()` runs unlocked via `list_for_each_entry_safe()`. In `nvme_ns_remove()`, clearing `NVME_NS_READY` must precede `synchronize_srcu(&ns->head->srcu)` and `nvme_mpath_clear_current_path(ns)`. Both `nvme_mpath_remove_disk()` and `nvme_remove_head_work()` must recheck `list_empty(&head->list)` under `head->subsys->lock`. [F22, F26, F98, F171, F173]
- In `drivers/nvme/host/pci.c`, writes to `nvmeq->sq_cmds`, `sq_tail`/`last_sq_tail` updates, and `nvme_write_sq_db()` must hold `nvmeq->sq_lock`. Non-IRQ callers of `nvme_poll_cq()` (`nvme_poll`, `nvme_poll_irqdisable`, `nvme_reap_pending_cqes`) must hold `nvmeq->cq_poll_lock` (with `nvme_poll_irqdisable()` bracketing it with `disable_irq()`/`enable_irq()`). `nvme_poll_cq()` needs `dma_rmb()` after `nvme_cqe_pending()`, and `nvme_dbbuf_update_and_check_event()` needs `wmb()` before `*dbbuf_db` and `mb()` before `*dbbuf_ei`. [F211, F212, F213, F214, F330]
- In `drivers/nvme/host/pci.c`, `nvme_setup_io_queues()` and `nvme_create_queue()` must not hold `dev->shutdown_lock` across synchronous admin commands and must re-acquire it via `nvme_setup_io_queues_trylock()`. `nvme_pci_update_nr_queues()` must `mutex_trylock(&dev->shutdown_lock)` and verify `dev->online_queues > 0` before `blk_mq_update_nr_hw_queues()` and `nvme_free_queues()`. [F217, F218]
- In `drivers/nvme/host/tcp.c`, draining `queue->req_list` into `queue->send_list`, modifying `queue->request`, and calling `nvme_tcp_try_send()` must hold `queue->send_mutex`. In `nvme_tcp_try_send_data()`, `req->data_len`, `h2cdata_left`, and `data_sent` must be snapshotted before `sock_sendmsg()`, calling `nvme_tcp_advance_req()` only when `req_data_sent + ret < req_data_len`. `__nvme_tcp_stop_queue()` must shut down the socket and call `nvme_tcp_restore_sock_ops(queue)` (under `write_lock_bh(&sk->sk_callback_lock)`) before `cancel_work_sync(&queue->io_work)`. [F221, F305, F333, F355]
- Request setup helpers (`nvme_setup_discard`, `nvme_prep_rq` PRP/SGL/dma_vecs allocations) run in `blk-mq` dispatch context and must use `GFP_ATOMIC`. Every acquisition of `head->requeue_lock` must use `spin_lock_irqsave` / `spin_lock_irq`. Quiesced queues must always be unquiesced (`nvme_unquiesce_io_queues` / `nvme_unquiesce_admin_queue`) before removing tagsets in `nvme_dev_disable`, `nvme_tcp_teardown_*`, and `nvme_rdma_teardown_*`. [F158, F160, F352, F380]

## Object Lifetimes

- When removing the last `nvme_ns` path in `nvme_alloc_ns()` rollback or tearing down a head in `nvme_remove_head()` and `nvme_mpath_remove_disk()`, the extra `head->ref` taken by `nvme_mpath_alloc_disk()` must be dropped via `nvme_put_ns_head(head)` whenever `head->disk != NULL` (even if `NVME_NSHEAD_DISK_LIVE` was never set). Before `put_disk(head->disk)` in `nvme_mpath_put_disk()`, both `head->requeue_work` and `head->partition_scan_work` must be flushed. [F1, F16]
- `nvme_init_ctrl()` initializes `ctrl->ctrl_device` at refcount 1 (`nvme_free_ctrl`), and `nvme_add_ctrl()` takes a second reference via `nvme_get_ctrl(ctrl)`; failures after `nvme_add_ctrl()` succeeds must call both `nvme_uninit_ctrl(ctrl)` and `nvme_put_ctrl(ctrl)`. If `nvme_alloc_admin_tag_set()` or `nvme_alloc_io_tag_set()` fails, it must destroy any allocated queue, free the tagset, and reset `ctrl->admin_q`, `ctrl->fabrics_q`, or `ctrl->connect_q` to `NULL`. In `nvme_remove_admin_tag_set()`, `nvme_stop_keep_alive(ctrl)` must precede destroying `ctrl->admin_q`. [F5, F13, F19]
- In `nvme_uring_cmd_io()`, `pdu->bio = req->bio` must be saved before `blk_execute_rq_nowait()`, and `nvme_uring_cmd_end_io()` must always defer completion via `io_uring_cmd_do_in_task_lazy(ioucmd, nvme_uring_task_cb)` so `nvme_uring_task_cb()` calls `blk_rq_unmap_user(pdu->bio)` in task context before `io_uring_cmd_done32()`. Before dispatching a controller ioctl from a multipath head, `nvme_ns_head_ctrl_ioctl()` must call `nvme_get_ctrl(ns->ctrl)` and drop `srcu_read_unlock(&head->srcu, srcu_idx)` before `nvme_ctrl_ioctl()`. [F10, F11, F156, F177]
- `nvme_mpath_start_request()` records `NVME_MPATH_CNT_ACTIVE` and `NVME_MPATH_IO_STATS` in `nvme_req(rq)->flags`, and `nvme_mpath_end_request()` must test those per-request flags (not `subsys->iopolicy` or queue flags) to decrement `ns->ctrl->nr_active` and call `bdev_end_io_acct()`. [F14]
- In `nvmf_parse_options()`, repeatable string and key fields in `struct nvmf_ctrl_options` must `kfree()` or `key_put()` any prior value before overwriting, and `opts->host`, `opts->keyring`, and `opts->tls_key` must never be left holding an `ERR_PTR` on error because `nvmf_free_options()` passes them to `nvmf_host_put()` and `key_put()`. [F7, F45]
- In `drivers/nvme/host/tcp.c`, `sock_alloc_file()` in `nvme_tcp_alloc_queue()` consumes `queue->sock` on failure (do not `sock_release`), and after it succeeds `queue->sock` must be released via `fput(queue->sock->file)` and set to `NULL`. Stopping a TCP queue (`nvme_tcp_stop_queue`, `nvme_tcp_stop_io_queues`) must follow `nvme_tcp_stop_queue_nowait()` with `nvme_tcp_wait_queue()`. [F205, F223]
- In `drivers/nvme/host/pci.c`, `iod->dma_vecs` must only be allocated from `dev->dmavec_mempool` when `!dma_use_iova(&iod->dma_state) && dma_need_unmap(dma_dev)`, and `nvme_free_descriptors()` must read `next_dma_addr` from `prp_list[last_prp]` before calling `dma_pool_free()`. In `drivers/nvme/host/rdma.c`, when `nvme_rdma_process_nvme_rsp()` posts `nvme_rdma_inv_rkey()`, it must return without calling `nvme_rdma_end_request(req)` so `nvme_rdma_inv_rkey_done()` drops the second `req->ref`. [F197, F199, F204]

## API Contracts

- Every NVMe transport must place `struct nvme_request` at offset 0 of its `blk-mq` request PDU because `nvme_req(req)` casts `blk_mq_rq_to_pdu(req)` directly. When a transport's `->queue_rq` fails after `nvme_setup_cmd()` succeeds, it must call `nvme_cleanup_cmd(req)`, and if it calls `nvme_host_path_error(req)` it must unwind transport resources and return `BLK_STS_OK`. [F8, F126]
- `nvme_try_complete_req()` expects a wire-format `__le16` status with the phase bit at bit 0 and shifts it right by 1 (`le16_to_cpu(status) >> 1`), so callers holding an unshifted `u16` status (e.g. `nvme_tcp_end_request()`) must pass `cpu_to_le16(status << 1)`. `__nvme_submit_sync_cmd()` only populates `*result` when `result && ret >= 0`, so callers must not read `*result` when `ret < 0`. [F46, F85, F244]

## Error Handling

- Synchronous NVMe helpers (`nvme_execute_rq`, `nvme_submit_sync_cmd`, `nvme_set_features`, `nvme_get_log`) return `< 0` for errnos and `> 0` for NVMe status codes: callers testing `NVME_STATUS_DNR` must guard with `ret > 0`; callers returning `ERR_PTR` or zone counts must convert `ret > 0` to negative errnos (`nvme_alloc_ns_head`, `nvme_tcp_create_ctrl`, `nvme_rdma_create_ctrl`, `nvme_ns_report_zones`); helpers tolerating feature rejection (`status > 0`) must treat `status < 0 || status == NVME_SC_HOST_PATH_ERROR` as fatal. [F36, F37, F38, F233, F234]
- In `nvme_handle_cqe()`, `nvme_req(req)->status` is a non-negative NVMe status code, so `blk_mq_add_to_batch()`'s `is_error` argument must be `nvme_req(req)->status != NVME_SC_SUCCESS` (not `< 0`). In `nvme_uring_cmd_end_io()`, when `nvme_req(req)->status == 0`, `pdu->status` must fall back to `blk_status_to_errno(err)`. [F40, F231]
- In `nvme_update_ns_info_block()`, any fallible check between `queue_limits_start_update()` / `blk_mq_freeze_queue()` and `queue_limits_commit_update()` must cancel the limits update and unfreeze `ns->disk->queue` on error. In `nvme_get_effects_log()` and `nvme_init_effects_log()`, `xa_store(&ctrl->cels, ...)` must be checked with `xa_is_err()`, freeing the `nvme_effects_log` on failure. [F2, F3]
- In `nvme_pci_setup_data_prp`, `nvme_pci_setup_data_sgl`, and `nvme_pci_setup_meta_sgls`, `iod->cmd.common.dptr` or `sg_list[0]` must be populated before calling `nvme_unmap_data()` or `nvme_unmap_metadata()` on `iter.status` failure. `nvme_try_sched_reset()` returns `0` when queued, so `nvme_timeout()` and `nvme_slot_reset()` must call `nvme_unquiesce_io_queues()` only when `nvme_try_sched_reset()` returns non-zero. [F230, F242]
- In `nvme_tcp_setup_ctrl()` and `nvme_rdma_setup_ctrl()`, any failure after initial admin queue setup (including the second `nvme_tcp_configure_admin_queue(ctrl, false)` for secure concatenation) must jump to `destroy_admin` and pass the caller's `new` flag to `teardown_admin_queue`. In `nvme_tcp_init_connection()`, `kernel_recvmsg()` with `MSG_WAITALL` must check `ret < 0` before comparing against `sizeof(*icresp)` (avoiding unsigned promotion). [F200, F232, F268]

## Known Pitfalls

- `nvme_lookup_ana_group_desc()` copies only the fixed header of `struct nvme_ana_group_desc` into the stack descriptor in `nvme_mpath_add_disk()`, so `nvme_update_ns_ana_state()` and `nvme_mpath_add_disk()` must never access `desc->nsids[]`. In `nvme_query_fdp_granularity()`, iteration must advance `void *log` by `le16_to_cpu(desc->dsze)` bytes rather than `sizeof(*desc)`. [F123, F125]
- `nvme_pci_setup_meta_sgls()` overwrites `iod->cmd.common.flags = NVME_CMD_SGL_METASEG`, so data SGL checks must test `NVME_CMD_SGL_METABUF | NVME_CMD_SGL_METASEG` via `nvme_pci_cmd_use_sgl()`. `nvme_tcp_try_send()` must use sequential `if (req->state == ...)` checks and `goto out` after `NVME_TCP_SEND_CMD_PDU` when `!nvme_tcp_has_inline_data(req)` because `nvme_tcp_try_send_cmd_pdu()` has already cleared `queue->request`. [F291, F297]
