# DRM DRIVERS FOR BRIDGE CHIPS

This unit provides the core DRM bridge subsystem (`drm_bridge.c`, `drm_bridge.h`), the generic bridge connector helper (`drm_bridge_connector.c`), and display bridge drivers for Toshiba (`tc358768`, `tc358775`), Thine (`thc63lvd1024`), Texas Instruments (`ti-sn65dsi83`, `ti-tdp158`, `ti-tfp410`, `ti-tpd12s015`), and Waveshare (`waveshare-dsi`). It manages encoder bridge chains, refcounted lifecycles, bus format negotiation, atomic state propagation, and connector operations.

## Architecture & Data Flow
- Reverse chain traversals in `drm_atomic_bridge_chain_disable()`, `drm_atomic_bridge_chain_pre_enable()`, and `drm_atomic_bridge_chain_check()` must terminate their `list_for_each_entry_reverse()` loop when `iter == bridge`. In `drm_atomic_bridge_chain_pre_enable()`, when `iter->pre_enable_prev_first` is true, the inner reverse scan must stop at `next == bridge` or `!next->pre_enable_prev_first` and set `iter = limit` after enabling `iter` before checking `if (iter == bridge) break;`. [F11, F81]
- In `drm_atomic_bridge_chain_post_disable()`, the inner forward scan over consecutive `pre_enable_prev_first` bridges must break when `list_is_last(&next->chain_node, &encoder->bridge_chain)` or `!next->pre_enable_prev_first` (backing up via `next = list_prev_entry(next, chain_node)`), and set `limit = next` so `bridge = limit` skips the reversed sub-chain. [F80]
- In `select_bus_fmt_recursive()` and `drm_atomic_bridge_chain_select_bus_fmts()`, format-selection loops only continue iterating while `ret == -ENOTSUPP` (`if (ret != -ENOTSUPP) break;`), and `select_bus_fmt_recursive()` only indexes `in_bus_fmts[i]` when `!ret`. [F83]
- When `bridge_connector->bridge_hdmi` is non-NULL: `drm_bridge_connector_init()` must clear `BIT(HDMI_COLORSPACE_YUV420)` from `supported_formats` before `drmm_connector_hdmi_init()` if `!connector->ycbcr_420_allowed`; `drm_bridge_connector_detect()` must call `drm_atomic_helper_connector_hdmi_hotplug(connector, status)`; and `drm_bridge_connector_get_modes()` must check `bridge_hdmi` before `bridge_edid` and `bridge_modes`, calling `drm_edid_connector_add_modes(connector)` directly. [F51, F58, F85]
- `__devm_drm_bridge_alloc()` registers `drm_bridge_put_void` with the embedded `struct drm_bridge *bridge` pointer (not `container`), so `drm_bridge_put_void()` and `devm_drm_put_bridge()` require the `void *` devres data argument to be the `struct drm_bridge *` address. [F99]
- In `tc358768_calc_pll()`, `tc358768_bridge_mode_valid()` must pass `verify_only = true` so validation returns before mutating `priv` PLL fields, and after searching `frs_limits` for `target_pll >= frs_limits[i]`, both `i == 0` and `i == ARRAY_SIZE(frs_limits)` must be rejected before indexing `frs_limits[i - 1]` and `frs_limits[i]`. [F65, F71]
- In `tc358768_dsi_host_transfer()`, `msg->tx_len > 8` must be rejected with `-ENOTSUPP` because only four 16-bit data registers (`TC358768_DSICMD_WD0`..`WD3`) exist before `TC358768_DSI_EVENT`, and the `i += 2` loop must check `i + 1 < packet.payload_length` before reading `packet.payload[i + 1]`. [F69, F70]

## Synchronization
- In `drm_bridge.c`, `bridge_lock` protects `bridge_list` across all insertions, removals, lookups, and iterations (`drm_bridge_add`, `drm_bridge_remove`, `of_drm_find_bridge`, `allbridges_show`). In `drm_bridge_remove()`, `bridge->list` must be unlinked under `bridge_lock` before `mutex_destroy(&bridge->hpd_mutex)` and `drm_bridge_put(bridge)`. [F14, F16]
- `bridge->hpd_mutex` protects `bridge->hpd_cb` and `bridge->hpd_data` across `hpd_enable`, `hpd_disable`, and `hpd_cb`. Under `hpd_mutex`, `drm_bridge_hpd_enable()` sets `hpd_cb`/`hpd_data` before calling `funcs->hpd_enable()`, and `drm_bridge_hpd_disable()` calls `funcs->hpd_disable()` before clearing them. Broken by: `hpd_enable`, `hpd_disable`, or `hpd_cb` synchronously calling `drm_bridge_hpd_notify()`, `drm_bridge_hpd_enable()`, or `drm_bridge_hpd_disable()` on the same bridge. [F17, F56]
- In `drm_bridge_connector_handle_hpd()`, `dev->mode_config.mutex` must be acquired to update `connector->status` and released before calling `drm_bridge_connector_hpd_notify()` and `drm_kms_helper_connector_hotplug_event()`, establishing the lock order `bridge->hpd_mutex` -> `dev->mode_config.mutex`. [F18]
- `drm_bridge_get_current_state()` requires `bridge->base.lock` held (`drm_modeset_lock_assert_held(&bridge->base.lock)`), and `bridge->base.lock` may only be accessed on bridges where `bridge->funcs->atomic_reset` is non-NULL. [F128]
- In `ti-sn65dsi83`, `sn65dsi83_atomic_disable()` stops error monitoring (clearing `REG_IRQ_EN`/`REG_IRQ_GLOBAL` or calling `sn65dsi83_monitor_stop()` -> `cancel_delayed_work_sync(&ctx->monitor_work)` under modeset locks) before asserting `enable_gpio` and disabling `vcc`. Thus `sn65dsi83_monitor_work()` must defer `sn65dsi83_reset_pipe()` to `ctx->reset_work` rather than acquiring modeset locks directly. [F23, F130]
- When `ctx->irq` is used in `sn65dsi83_handle_errors()`, the IRQ must be disabled with `disable_irq_nosync(ctx->irq)` (not `disable_irq()` inside threaded handler `sn65dsi83_irq`) before scheduling `ctx->reset_work`, and re-enabled with `enable_irq(ctx->irq)` in `sn65dsi83_reset_work()` only after `sn65dsi83_reset_pipe(ctx)` succeeds. In `sn65dsi83_reset_pipe()`, `drm_modeset_acquire_ctx` must handle `-EDEADLK` via `drm_modeset_backoff(&ctx)` and call `drm_modeset_drop_locks(&ctx)` and `drm_modeset_acquire_fini(&ctx)` before returning. [F12, F22]
- In `tfp410_attach()`, `INIT_DELAYED_WORK(&dvi->hpd_work, tfp410_hpd_work_func)` must precede `drm_bridge_hpd_enable()`; in `tfp410_detach()`, `drm_bridge_hpd_disable()` must precede `cancel_delayed_work_sync(&dvi->hpd_work)`, and both must be guarded by `if (dvi->connector.dev)` because `DRM_BRIDGE_ATTACH_NO_CONNECTOR` skips initializing `dvi->connector` and `dvi->hpd_work`. [F47, F108]
- In `tc358768.c`, `drm_bridge_add(&priv->bridge)` must only be called inside `tc358768_dsi_host_attach()` after `priv->output`, `priv->dsi_lanes`, `priv->dsi_bpp`, and `priv->pd_lines` are initialized, and `tc358768_dsi_host_detach()` must call `drm_bridge_remove(&priv->bridge)` before `drm_panel_bridge_remove(priv->output.bridge)`. [F27]

## Object Lifetimes
- Bridge drivers registering `struct drm_bridge` with `drm_bridge_add()` in `.probe` must call `drm_bridge_remove()` in `.remove` and on post-add `.probe` error paths, never in `drm_bridge_funcs.detach`. I2C DSI bridges (`tc_probe()`, `sn65dsi83_probe()`) must call `drm_bridge_add()` before `devm_mipi_dsi_attach()` and `drm_bridge_remove()` if host attach fails. [F4, F111]
- Bridges attached to an encoder via `drm_bridge_attach()` are automatically detached during `drm_encoder_cleanup()`; bridge drivers must never call `drm_bridge_detach()` on their downstream bridge in `.detach` or `.remove`. [F103]
- Every `struct device_node *` from OF graph helpers (`of_graph_get_endpoint_by_regs()`, `of_graph_get_remote_port_parent()`, `of_graph_get_remote_endpoint()`, `of_graph_get_remote_node()`, `of_graph_get_port_by_id()`) must be released with `of_node_put()` on all paths. [F6]
- Because `.atomic_pre_enable` returns `void` and cannot abort a modeset, `sn65dsi83_atomic_pre_enable()` must not call `regulator_disable(ctx->vcc)` on PLL lock failure after `regulator_enable(ctx->vcc)`, as `sn65dsi83_atomic_disable()` will still run and disable `ctx->vcc`. [F118]

## API Contracts
- `drm_bridge_get_prev_bridge()`, `drm_bridge_chain_get_first_bridge()`, and `drm_bridge_chain_get_last_bridge()` return a refcounted `struct drm_bridge *` that callers must release with `drm_bridge_put()`, whereas `drm_bridge_get_next_bridge()` and `of_drm_find_bridge()` return borrowed pointers without incrementing `bridge->refcount`. [F2]
- Every `struct drm_bridge` passed to `drm_bridge_add()` or `devm_drm_bridge_add()` must be allocated via `devm_drm_bridge_alloc()` with a non-NULL `drm_bridge_funcs` pointer so `bridge->container`, `bridge->funcs`, and `bridge->refcount` are initialized before registration and final `kfree(bridge->container)`. [F133]
- In `drm_bridge_attach(encoder, bridge, previous, flags)`, `bridge` is the unattached downstream bridge (`bridge->dev == NULL`) and `previous` is the already-attached upstream bridge (`previous->dev != NULL && previous->encoder == encoder`). `bridge->dev`, `bridge->encoder`, and `bridge->chain_node` insertion into `encoder->bridge_chain` must be set before calling `bridge->funcs->attach()` and `atomic_reset()`, and rolled back in reverse order (`funcs->detach()`, clearing `dev`/`encoder`, `list_del(&bridge->chain_node)`, `drm_bridge_put()`) on failure. [F3, F20, F44]
- `drm_bridge_attach()` only initializes `bridge->base` as an atomic private object when `bridge->funcs->atomic_reset` is non-NULL (`drm_bridge_is_atomic()`). Any bridge implementing `atomic_check`, `atomic_get_input_bus_fmts`, or `atomic_get_output_bus_fmts` must also provide `atomic_reset` (returns `ERR_PTR` on failure), `atomic_duplicate_state` (returns `NULL` on failure), and `atomic_destroy_state`. [F30, F54]
- Because `drm_atomic_bridge_propagate_bus_flags()` overwrites `bridge_state->output_bus_cfg.flags` and `input_bus_cfg.flags` right before `drm_atomic_bridge_check()`, a bridge that customizes bus flags must do so inside `.atomic_check()` (which returns `0` or negative errno and suppresses `.mode_fixup()`, which returns `bool`). [F45, F137]
- `atomic_get_input_bus_fmts` and `atomic_get_output_bus_fmts` must return a `kmalloc()`-allocated `u32` array and set `*num_input_fmts` / `*num_output_fmts` to the length, or set the count to `0` when unsupported (returning `NULL` with a non-zero count is `-ENOMEM`). In `drm_atomic_bridge_chain_select_bus_fmts()`, when the last bridge lacks `atomic_get_output_bus_fmts`, `conn->display_info.bus_formats[0]` may only be read after checking both `num_bus_formats` and `bus_formats` are non-zero/non-NULL. [F78, F136]
- `drm_bridge_edid_read()` transfers ownership of the returned `const struct drm_edid *` to the caller, which must free it with `drm_edid_free()` even when `drm_edid_valid()` returns false. [F8]
- Bridge drivers must keep `drm_bridge_funcs` as `static const` and never set `DRM_BRIDGE_OP_DETECT`, `DRM_BRIDGE_OP_MODES`, or `DRM_BRIDGE_OP_EDID` in `bridge->ops` unless the corresponding callback is non-NULL. Conversely, `DRM_BRIDGE_OP_HPD` bridges may omit `.hpd_enable` and `.hpd_disable` (null-checked by `drm_bridge_hpd_enable()` / `drm_bridge_hpd_disable()`), allow only one HPD callback at a time, and require a sleeping context for `drm_bridge_hpd_notify()`. [F41, F138, F143]
- Bridges setting `DRM_BRIDGE_OP_HDMI` must populate `bridge->ops` and `bridge->supported_formats` before `drm_bridge_add()` / `devm_drm_bridge_add()` (which derives `bridge->ycbcr_420_allowed` from `HDMI_COLORSPACE_YUV420`), and `drm_bridge_connector_reset()` must call `__drm_atomic_helper_connector_hdmi_reset(connector, connector->state)` after `drm_atomic_helper_connector_reset(connector)` whenever `bridge_connector->bridge_hdmi` is non-NULL. [F52, F102]
- `drm_bridge_connector_init()` enforces singleton bridges in a chain (returning `ERR_PTR(-EBUSY)` on duplicates) for `DRM_BRIDGE_OP_HDMI`, audio (`DRM_BRIDGE_OP_HDMI_AUDIO` and `DRM_BRIDGE_OP_DP_AUDIO`, mutually exclusive), and CEC (`DRM_BRIDGE_OP_HDMI_CEC_NOTIFIER` and `DRM_BRIDGE_OP_HDMI_CEC_ADAPTER`, mutually exclusive), and requires the last bridge (`drm_bridge_is_last`) to set `bridge->type != DRM_MODE_CONNECTOR_Unknown`. [F59, F140, F141]

## Error Handling
- `devm_drm_bridge_alloc()`, `__devm_drm_bridge_alloc()`, `devm_drm_of_get_bridge()`, and `drmm_of_get_bridge()` return `ERR_PTR` on failure (check `IS_ERR()`), whereas `of_drm_find_bridge()` returns `NULL` (check `!bridge`). [F28, F29]
- Exported bridge chain helpers in `drm_bridge.c` (`drm_atomic_bridge_chain_check()`, `drm_bridge_chain_mode_valid()`, chain enable/disable) accept `NULL` `bridge` and must check `!bridge` before dereferencing `bridge->encoder`. `drm_atomic_get_new_bridge_state()` returns `NULL` for bridges without atomic state hooks, so `select_bus_fmt_recursive()` and `drm_atomic_bridge_propagate_bus_flags()` must null-check bridge states before dereferencing. [F37, F39]
- In `tc358768.c`, `tc358768_write()`, `tc358768_read()`, `tc358768_update_bits()`, and `tc358768_dsicmd_tx()` no-op when `priv->error` is non-zero, and `tc358768_read()` leaves `*val` unmodified on 32-bit `regmap_bulk_read()` failure; callers of `tc358768_read()` must check `if (priv->error) return;` before using `*val`, and every register transaction sequence must consume and reset `priv->error` via `tc358768_clear_error(priv)`. In `tc358768_bridge_atomic_pre_enable()`, failures after `tc358768_hw_enable(priv)` must call `tc358768_hw_disable(priv)`. [F10, F32, F63]
- Callers of `drm_of_get_data_lanes_count()` (`tc358775_parse_dt()`, `sn65dsi83_host_attach()`) must store the result in a signed `int` and check `< 0` (with `tc358775_parse_dt()` validating 1..4 lanes); in `tpd12s015_probe()`, `gpiod_to_irq()` must be stored in signed `int tpd->hpd_irq` and checked with `>= 0`. [F35, F36, F95]

## External Contracts
- In `ti-sn65dsi83`, `bridge.pre_enable_prev_first` must be `true` so the DSI host enters LP-11/HS clock before `sn65dsi83_atomic_pre_enable()` writes CSR registers (using `cpu_to_le16()` for 16-bit `regmap_bulk_write()`), enables `REG_RC_PLL_EN`, polls `REG_RC_LVDS_PLL` (clearing `REG_RC_PLL_EN` on failure), and triggers `REG_RC_RESET_SOFT_RESET` + 10ms delay; `sn65dsi83_atomic_enable()` then clears `REG_IRQ_STAT` (write-1-to-clear) after video starts. [F62, F76, F119]
- In `tc358768`, `tc358768_dsicmd_tx()` must poll `TC358768_DSICMD_TX` until `TC358768_DSI_CMDTX_DC_START` clears, and `TC358768_DSI_CONTROL` (`0x040C`, read-only) must be modified indirectly via `TC358768_DSI_CONFW` (`0x0500`) using `MODE_CLR` and `MODE_SET`. [F114, F115]

## Known Pitfalls
- In `drm_bridge_connector_init()`, after `drm_for_each_bridge_in_chain(encoder, bridge)` finishes, the `bridge` cursor points to the list head rather than a valid bridge, so post-loop setup blocks must reassign `bridge` from `bridge_connector->bridge_*` before dereferencing it. [F79]
- In `tc358768`, `tc358768_write()` and `tc358768_read()` access `0x100 <= reg < 0x600` as 32-bit big-endian transfers and other registers as 16-bit transfers; `tc358768_read()` must zero `*val` before 16-bit reads, and access tables must cover `reg` through `reg + 2` for 32-bit registers. Clock/byte helpers (`tc358768_pll_to_pclk()`, `tc358768_pclk_to_pll()`, `tc358768_calc_pll()`, `tc358768_dpi_to_ns()`, `tc358768_dpi_to_dsi_bytes()`, `tc358768_dsi_bytes_to_ns()`) must widen to `u64` before multiplying and use `div_u64()`. [F90, F91, F112]
