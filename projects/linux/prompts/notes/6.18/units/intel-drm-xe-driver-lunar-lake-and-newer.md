# INTEL DRM XE DRIVER (Lunar Lake and newer)

The Intel Xe DRM driver (`drivers/gpu/drm/xe` and `include/uapi/drm/xe_drm.h`) manages Intel graphics devices across bare-metal, SR-IOV Physical Function (PF), and Virtual Function (VF) modes. It implements TTM-based buffer objects (`xe_bo`), multi-level GPU virtual memory (`xe_vm`, `xe_pt`) with userptr and HMM/devmem Shared Virtual Memory (`xe_svm`), GuC and execlist workload submission (`xe_exec_queue`, `xe_guc_submit`, `xe_lrc`), GSC/HuC/late-binding firmware, GT power/reset/MCR steering, GPU migration, PXP, and telemetry.

## Architecture & Data Flow

- When `bo_flags` includes both `XE_BO_FLAG_SYSTEM` and `XE_BO_FLAG_VRAM_MASK`, `try_add_system()` marks `XE_PL_TT` with `TTM_PL_FLAG_FALLBACK`; thus `xe_bo_validate()` must return 0 immediately when `xe_bo_is_pinned(bo)` is true, and `xe_dma_buf_pin()` must pass `in_place = true` to `xe_bo_pin_external()` so validation does not migrate a pinned TT BO back to VRAM. [F58, F59]
- Shrinker page counts in `xe->mem.shrinker` must be updated in lockstep via `xe_ttm_tt_account_add()` and `xe_ttm_tt_account_subtract()` whenever a mappable `ttm_tt` is populated, unpopulated, shrunken, pinned/unpinned while populated, or has `xe_tt->purgeable` mutated under `xe_bo_lock()`. [F61, F965]
- On SR-IOV VFs (`IS_SRIOV_VF(xe)`), `vf_update_device_info()` clears PF-only flags and sets `skip_guc_pc`/`skip_pcode`, `xe_guc_init()` skips `log`, `capture`, `ads`, `dbm`, `pc`, and `engine_activity` (leaving their BOs NULL), and `gt->sriov` unions `pf` and `vf`; VF-reachable paths and sysfs/debugfs registration must guard on `!IS_SRIOV_VF(xe)` or NULL-check those pointers. [F148, F151, F365, F819, F1106, F1107, F1242]
- In `xe_pt.c`, only page tables with `pt->level > 0` are allocated as `struct xe_pt_dir` (requiring `pt->level > 0` before `as_xe_pt_dir(pt)`), `xe_pt_destroy()` only recurses into directories when `pt->num_live > 0` via `pt_dir->staging`, and `entry->pt_entries` is indexed relative to `entry->ofs` (`0 .. entry->qwords - 1`) whereas `pt_dir->children` and `pt_dir->staging` use the absolute PDE index (`entry->ofs + j`). [F775, F867, F895]
- In `xe_vm.c`, `vm_bind_ioctl_ops_parse()` must increment `vops->pt_update_ops[i].num_ops` via `xe_vma_ops_incr_pt_update_ops()` for every page-table update sub-op that `xe_pt_update_ops_prepare()` will stage, and every `DRM_GPUVA_OP_REMAP` handler must check `op->remap.prev` and `op->remap.next` with independent `if` statements (not `else if`), propagating `tile_present` and `xe_vma_max_pte_size(old)` when `skip_prev` or `skip_next` is set. [F1307, F1308, F1309, F1344]

## Synchronization

- Across VM, execution, and validation paths, locks must be acquired in the order: `group->mode_sem` (`xe_hw_engine_group_get_mode`) -> `vm->lock` -> `xe_validation_device.lock` (`val->lock`) -> `drm_exec` (`dma_resv` locks, with `xe_bo_lock()` outer to `bo->ttm.bdev->lru_lock`) -> `vm->svm.gpusvm.notifier_lock` -> `vm->userptr.invalidated_lock`. `xe_validation_should_retry()` must call `drm_exec_fini(ctx->exec)` before unlocking/relocking `val->lock` and re-init `ctx->exec` even on failure. [F174, F978, F979, F1258, F1279]
- In BO creation helpers that accept an optional `@vm` whose `dma_resv` lock is held by the caller (`__xe_bo_create_locked()`, `xe_bo_create_user()`, `xe_bo_create_pin_map_at_aligned()`), unlocking the BO on exit or error must use `xe_bo_unlock_vm_held(bo)` instead of `xe_bo_unlock(bo)`. [F4]
- `xe_bo_put()` may sleep and acquire reclaim-tainted locks (`client->bos_lock`, `ggtt->lock`, `dma_resv`), so dropping an `xe_bo` reference in atomic context, under a spinlock (such as `client->bos_lock` in `show_meminfo()` or `xe->pinned.lock` in `xe_bo_apply_to_pinned()`), or in a reclaim-tainted scope must use `xe_bo_put_deferred()` + `xe_bo_put_commit()` or `xe_bo_put_async()`. [F66, F111, F166, F171, F176]
- Spinlocks acquired in hardirq or `irq_work` context require IRQ-disabling `spin_lock_irq()`/`spin_lock_irqsave()` in all process/worker/timer callers: `xe->irq.lock`, `xe_execlist_port.lock`, `gsc->lock`, `pf_queue->lock` (`xe_gt_pagefault.c`), `xe_hw_fence_irq.lock`, `ct->fast_lock` (`xe_guc_ct.c`), `ct->dead.lock`, `tlb_inval->pending_lock` (inner to mutex `tlb_inval->seqno_lock`), and `stream->oa_buffer.ptr_lock`. [F165, F233, F370, F557, F560, F613, F929, F1090, F1223, F1398, F1399]
- Code in the dma-fence signaling path or holding reclaim-primed locks (`guc->submission_state.lock`, `guc->ct.lock`, `m->job_mutex`, `coredump->lock`, `ct->fast_lock`, `ct->dead.lock`) must never perform `GFP_KERNEL`/`vmalloc` allocations or sleep on hardware responses; crash and VM snapshots (`xe_devcoredump()`, `xe_guc_exec_queue_snapshot_capture()`, `xe_lrc_snapshot_capture()`, `xe_vm_snapshot_capture()`, `ct_dead_capture()`) must use `GFP_ATOMIC`/`GFP_NOWAIT` and defer `GFP_KERNEL`/`xe_bo_lock()`/`ttm_bo_vmap()` to their delayed workers. [F167, F411, F556, F559, F618, F745, F1222, F1224, F1229, F1230, F1397]
- Callers in reclaim-unsafe contexts (`xe_bo_move()`, `xe_shrinker_runtime_pm_get()`), holding locks acquired inside `xe_pm_runtime_suspend()`/`resume()` (such as `dma_resv` locks when `xe->d3cold.capable` is true, or `vram_userfault.lock`), or in G2H handlers (`receive_g2h()`) must never call synchronous `xe_pm_runtime_get()`; they must check `xe_rpm_reclaim_safe(xe)` or use `xe_pm_runtime_get_if_active()` / `xe_pm_runtime_get_noresume()`. [F183, F603, F604, F802, F1089]
- In `xe_guc_ct.c`, lock order is `ct->lock` (mutex) -> `ct->fast_lock` (spinlock); `__guc_ct_send_locked()` must hold `ct->fast_lock` continuously across `has_room()`, `h2g_write()`, and `__g2h_reserve_space()`, and `guc_ct_send_recv()` must re-acquire `ct->lock` after `wait_event_timeout()` on `ct->g2h_fence_wq` before reading stack `g2h_fence` fields or erasing `g2h_fence.seqno` from `ct->fence_lookup`. [F1080, F1081, F1083, F1085]
- Before notifying the GPU or updating shared ring tails, `xe_device_wmb(xe)` (which also writes `VF_CAP_REG` on DGFX) is required before updating `wq_desc.tail` in `wq_item_append()`, before `desc_write(..., tail)` in `h2g_write()`, after CPU PTE updates in `xe_migrate_update_pgtables_cpu()`, after PTE zapping before TLB invalidation in `xe_svm_invalidate()` and `xe_vm_invalidate_vma()`, and before `pxp_pkt_submit()` in `gsccs_send_message()`. [F180, F563, F619, F804, F923, F1084, F1277]

## Object Lifetimes

- Because an `xe_bo`'s `drm_gem_object` refcount (`bo->ttm.base.refcount`) holds a `ttm_buffer_object` refcount only dropped in `xe_gem_object_free()`, TTM callbacks and shrinker/eviction paths walking TTM BOs must first verify `xe_bo_is_xe_bo(tbo)` (to exclude ghost objects) and obtain a GEM reference via `xe_bo_get_unless_zero()` (paired with `xe_bo_put()`) before accessing `struct xe_bo` fields outside `ttm_buffer_object`. [F2, F132]
- `__xe_bo_create_locked()` calls `xe_vm_get(vm)` and `xe_ttm_bo_destroy()` calls `xe_vm_put(bo->vm)` only when `bo->vm && xe_bo_is_user(bo)`; conversely, `xe_vma_create()` and `xe_vma_destroy_late()` hold a GEM reference (`drm_gem_object_get`/`xe_bo_put`) without `xe_vm_get` for BO-backed VMAs, but hold an `xe_vm_get`/`xe_vm_put` reference for userptr, sparse (`DRM_GPUVA_SPARSE`), and `XE_VMA_SYSTEM_ALLOCATOR` VMAs. [F5, F1259]
- In `xe_exec_queue_create()`, any failure after `__xe_exec_queue_init(q)` must call `__xe_exec_queue_fini(q)` (which runs `q->ops->fini(q)` and releases `q->lrc[i]`) before `__xe_exec_queue_free(q)`; in `xe_exec_queue_create_ioctl()` and `xe_vm_create_ioctl()`, `xa_alloc()` into `xef->exec_queue.xa` or `xef->vm.xa` must be the final step (calling `xe_exec_queue_kill(q)` before `xe_exec_queue_put(q)` if `xa_alloc()` fails). [F8, F9, F395, F1267]
- Once `xe_sched_job_arm(job)` is called in `xe_exec_ioctl()`, job ownership transfers to the scheduler via `xe_sched_job_push(job)` and must not be freed with `xe_sched_job_put(job)`; similarly, `xe_bb_create_job()` and `xe_bb_create_migration_job()` never consume `bb`, and `xe_bb_free(bb, fence)` (passing `NULL` before push and `fence` after `xe_sched_job_push()`) does not consume the caller's `fence` reference. [F15, F586, F959, F961]
- Before `xe_pt_commit_prepare_bind()`, `entries[i].pt_entries[j].pt` owns newly allocated child `xe_pt` subtrees and requires `xe_pt_cancel_bind()` on error; `xe_pt_commit_prepare_bind()` swaps new subtrees into `pt_dir->staging` and displaced subtrees into `pt_entries[j].pt`, requiring `xe_pt_abort_bind()` on error or `xe_pt_commit()` on success. [F772]
- `xe_tlb_inval_fence_init()` acquires a runtime PM reference via `xe_pm_runtime_get_noresume()` that is only released by `xe_tlb_inval_fence_fini()` when the fence signals, so every initialized `xe_tlb_inval_fence` must be signaled (including on backend issue failure or GT reset); in `xe_tlb_inval_job_destroy()`, `job->fence` is raw `kmalloc` memory freed via `kfree()` when `!job->fence_armed` and via `dma_fence_put()` when `job->fence_armed` is true. [F1251, F1252, F1270]

## API Contracts

- `xe_force_wake_get(fw, XE_FORCEWAKE_ALL)` returns a bitmask of woken domains rather than a boolean: callers must check full success via `xe_force_wake_ref_has_domain(fw_ref, XE_FORCEWAKE_ALL)` and still call `xe_force_wake_put(fw, fw_ref)` on partial failure, and must never pass `XE_FORCEWAKE_ALL` (`BIT(XE_FW_DOMAIN_ID_COUNT)`) to `xe_force_wake_ref()` or `xe_force_wake_assert_held()`, which index `fw->domains[XE_FW_DOMAIN_ID_COUNT]`. [F43, F79, F98, F127, F910, F1050]
- `xe_bo_alloc()` returns `ERR_PTR(-ENOMEM)` and must only be freed with `xe_bo_free(bo)` when aborting before `xe_bo_init_locked()` or `xe_dma_buf_init_obj()` (which consume and free `bo` on failure); similarly, `xe_hw_fence_alloc()` and `xe_preempt_fence_alloc()` return `ERR_PTR(-ENOMEM)` and must be freed with `xe_hw_fence_free()` / `xe_preempt_fence_free()` before `xe_hw_fence_init()` / `xe_preempt_fence_arm()`, and `dma_fence_put()` afterward. [F45, F442, F523, F644]
- Address and range boundary conventions: `xe_bo_create_pin_map_at_novm()` and `xe_bo_create_pin_map_at_aligned()` require `offset = ~0ull` (not `0`) for unconstrained placement; `xe_ggtt_node_insert_balloon_locked()` takes the exclusive `end` address as its third parameter (despite the header naming it `size`); `xe_pt_walk_range()` and `xe_pt_walk_shared()` take an exclusive `end` (`last + 1`), whereas `xe_vma_create(start, end, ...)` (`start + range - 1`), `xe_range_fence_*()`, and `xe_vm_pgtable_update_ops` (`start`, `last`) take an inclusive upper address. [F50, F247, F864, F1289]
- G2H event handlers invoked from `process_g2h_msg()` run under `ct->lock` and cannot reserve G2H space: any H2G sent from a G2H handler (such as `deregister_exec_queue()`) must use `xe_guc_ct_send_g2h_handler()` after pre-reserving G2H space in `disable_scheduling_deregister()`, and every G2H event whose H2G sender reserved `g2h_len > 0` must release `len` dwords via `g2h_release_space()` in `parse_g2h_event()` (or `__g2h_release_space()` in `g2h_fast_path()`). [F552, F1086, F1115, F1124, F1166]

## Error Handling

- Many struct fields (`ggtt->scratch`, `bo->ggtt_node[tile_id]`, `xe->psmi.capture_obj[id]`, `bo->bb_ccs[ctx_id]`, `ct->bo`, `log->bo`, `ads->bo`, `pc->bo`, `guc->hwconfig.bo`, `vm->pt_root[id]`, `vm->scratch_pt[id][i]`, and `ops[i]` in `xe_vm_bind_ioctl()`) are tested for `NULL` rather than `IS_ERR()` by cleanup/consumer paths, so callers of `ERR_PTR`-returning allocators (`xe_ggtt_node_init()`, `xe_bb_new()`, `xe_pt_create()`, `xe_managed_bo_create_pin_map()`, `vm_bind_ioctl_ops_create()`) must check `IS_ERR()` on a local variable or reset the slot to `NULL` on failure. [F244, F246, F645, F981, F1109, F1261, F1264]
- Inside `xe_validation_guard()` / `drm_exec_until_all_locked()` loops (`xe_bo_create_pin_range_novm()`, `handle_vma_pagefault()`, `__xe_svm_handle_pagefault()`), any locally created BO must be unlocked and put, and `xe_vm_set_validation_exec(vm, NULL)` must be called, before `drm_exec_retry_on_contention(&exec)`, `xe_validation_retry_on_oom(&ctx, &err)`, or breaking/jumping out of the loop, and `xe_validation_ctx_fini(&ctx)` must run before jumping to `retry_userptr`. [F115, F302, F786, F1265]
- Sentinel and tri-state return values: `ERR_PTR(-ETIME)` from `xe_migrate_update_pgtables_cpu()` is the sole return value that triggers GPU fallback in `xe_migrate_update_pgtables()`; `ERR_PTR(-ENODATA)` from `ops_execute()` means no PT updates were needed (requiring `vm_bind_ioctl_ops_fini()` and fence signaling without unwinding in `xe_vm_bind_ioctl()`); `-ECANCELED` from `send_tlb_inval_ggtt/ppgtt()` tells `xe_tlb_inval_issue()` to signal the fence immediately and return `0`; `xe_pxp_get_readiness_status()` returns `1` for ready, `0` for in-progress, and `< 0` for error; `xe_vma_need_vram_for_atomic()` returns `1`, `0`, or `-EACCES`; and `do_compare()` in `xe_wait_user_fence.c` returns `0` on match, `1` on mismatch, and `< 0` on error. [F439, F624, F811, F1288, F1290, F1434]

## External Contracts

- All user extension parsers (`xe_eu_stall_user_extensions`, `exec_queue_user_extensions`, `gem_create_user_extensions`, `xe_oa_user_extensions`), property handlers, `xe_hw_engine_lookup()`, `xe_query_ioctl()`, `vm_bind_ioctl_check_args()`, and `xe_vm_madvise_ioctl()` must reject non-zero `pad`/`reserved`/`extensions` fields with `-EINVAL`, cap extension recursion at `MAX_USER_EXTENSIONS` (`-E2BIG`), and bounds-check plus sanitize user indices (`ext.name`, `ext.property`, `engine_class`, `query->query`, `pat_index`, `args->type`) with `array_index_nospec()` before indexing dispatch or PAT tables. [F195, F484, F766, F940, F1333, F1506]

## Known Pitfalls

- 64-bit shift and overflow hazards: page counts/offsets (`num_pages`, `page_offset`, `place->fpfn`, `lpfn`, `tbo->page_alignment`, `page_to_pfn(page)`), 32-bit register/descriptor fields (`PFD_VIRTUAL_ADDR_HI`, `REG_FIELD_GET` in `get_flat_ccs_offset`/`tile_vram_size`, high dwords in `make_u64*`), `gsm_size / 8` in `xe_ggtt_init_early()`, `si.totalram` in `xe_ttm_sys_mgr_init()`, and shift bases for `walk->shifts[level]`, `xe_pt_shift(level)`, `xe->info.va_bits`, and `rebar_size` must be widened to 64-bit unsigned (`u64` / `1ULL`) before shifting or multiplying, and 64-bit divisions must use `div_u64`/`div64_u64`/`DIV_ROUND_UP_ULL`/`mul_u64_u32_div` rather than `/`. [F122, F123, F125, F315, F316, F700, F884, F888, F892, F1032, F1174, F1176, F1359, F1360, F1361, F1362, F1366]
- Although `xe_bo_is_vram()` returns true for `XE_PL_STOLEN` on DGFX, `XE_PL_STOLEN` is not managed by `xe_ttm_vram_mgr` and has no cgroup region (`man->cg == NULL`), so `mem_type_is_vram()` must exclude `XE_PL_STOLEN` and functions like `xe_ttm_io_mem_pfn()` and `vram_region_gpu_offset()` must branch on `XE_PL_STOLEN` before calling `res_to_mem_region()`; also, because `xe_ttm_tt_create()` sets `TTM_TT_FLAG_EXTERNAL | TTM_TT_FLAG_EXTERNAL_MAPPABLE` on normal BOs, `xe_ttm_bo_is_imported()` requires `TTM_TT_FLAG_EXTERNAL` set and `TTM_TT_FLAG_EXTERNAL_MAPPABLE` clear. [F103, F109, F1422]
- 32-bit modular timestamp and sequence number comparisons: `xe_hw_fence_signaled()`, `xe_sched_job_started()`, and `xe_sched_job_completed()` must use `!__dma_fence_is_later()`; `xe_exec_queue_num_job_inflight()` must compute `next_seqno - xe_lrc_seqno(lrc) - 1` as signed `s32`; `check_timeout()` (`xe_guc_submit.c`) and `get_engine_active_ticks()` (`xe_guc_engine_activity.c`) must truncate the 64-bit timestamp with `lower_32_bits()` before subtracting the 32-bit start/update tick; and `xe_tlb_inval_seqno_past()` must check the `TLB_INVALIDATION_SEQNO_MAX / 2` wrap window. [F128, F511, F513, F889, F1177, F1364]
