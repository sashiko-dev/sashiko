# SERIAL LOW-POWER INTER-CHIP MEDIA BUS (SLIMbus)

The SLIMbus subsystem provides the core Linux bus framework for the MIPI Serial Low-power Inter-chip Media Bus, managing controller and client device registration, Device Tree enumeration, and logical address allocation. It implements synchronous and asynchronous value/information element messaging using transaction IDs (TIDs), bus clock-pause reconfiguration scheduling, and audio data stream lifecycle management (allocate, prepare, enable, disable, unprepare, and free) integrated with ASoC.

## Architecture & Data Flow

- Every child `struct device` registered under `slim_controller.dev` must be embedded in a `struct slim_device`, because `slim_ctrl_remove_device()`, `slim_match_dev()`, and `of_find_slim_device()` unconditionally downcast `ctrl->dev` children via `to_slim_device()` without checking `dev->bus`. Broken by: registering a non-`slim_device` child (such as `slim_framer.dev`) with `parent = ctrl->dev`. [F67]
- Stack-allocated `struct slim_val_inf` instances passed to `slim_xfer_msg()` for synchronous TID transactions must have `msg->comp` initialized to `NULL` (as `slim_fill_msg()` does), because `slim_do_transfer()` treats a non-NULL `txn->msg->comp` as an asynchronous caller-supplied completion and skips waiting on its on-stack `done` completion. [F28]
- In `slim_device_alloc_laddr()`, the `ctrl->get_laddr` branch must be evaluated before the `report_present` branch so `slim_get_logical_addr()` (`report_present = false`) can still obtain a logical address when `ctrl->get_laddr` is implemented; when `ctrl->get_laddr` is `NULL` and `report_present` is true, `ida_alloc_max(&ctrl->laddr_ida, SLIM_LA_MANAGER - 1, ...)` must be used so client addresses `0x00..0xFE` are allowed while `SLIM_LA_MANAGER` (`0xFF`) is reserved. [F43, F53]
- `slim_device_alloc_laddr()` and `slim_report_absent()` must keep `sbdev->is_laddr_valid` and `sbdev->status` synchronized by updating `sbdev->is_laddr_valid` under `ctrl->lock` and then calling `slim_device_update_status()` to transition `sbdev->status` and notify `sbdrv->device_status`. [F34]
- When entering clock pause (`wakeup == false`), `slim_ctrl_clk_pause()` must reject `restart > SLIM_CLK_UNSPECIFIED` with `-EINVAL`, scan `ctrl->tid_idr` across `0 <= i < SLIM_MAX_TIDS` under `ctrl->txn_lock` to return `-EBUSY` if any transaction is pending, set `ctrl->sched.clk_state = SLIM_CLK_ENTERING_PAUSE` before sending reconfiguration messages via `slim_do_transfer()`, and transition to `SLIM_CLK_PAUSED` (calling `complete(&sched->pause_comp)`) on success or revert to `SLIM_CLK_ACTIVE` on failure. [F35, F50]
- When adding or modifying core value/information element message codes (`SLIM_MSG_MC_*`), `slim_val_inf_sanity()`, `slim_xfer_msg()`, `slim_tid_txn()`, and `slim_ec_txn()` must be updated in lockstep; in `slim_xfer_msg()`, `txn->rl` starts at 6, adds `msg->num_bytes` only for write-bearing codes (`CHANGE_VALUE`, `REQUEST_CHANGE_VALUE`, `CLEAR_INFORMATION`, `REQUEST_CLEAR_INFORMATION`), and adds 1 when `slim_tid_txn(txn->mt, txn->mc)` is true. [F40, F58]
- Message codes and flags stored in or tested against `struct slim_msg_txn.mc` (or passed as `u8 mc` to `slim_xfer_msg()`, `slim_tid_txn()`, and `slim_ec_txn()`) must fit within the 8-bit `u8` type (and 7-bit wire mask `SLIM_MSG_MC_MASK`), never using bit shifts `>= 8`. [F59]
- When `ctrl->enable_stream` is `NULL`, `slim_stream_enable()` must finish the loop calling `slim_define_channel()` and `slim_define_channel_content()` across all `stream->num_ports` ports before starting the loop calling `slim_activate_channel()`; regardless of whether `ctrl->enable_stream` is used, `slim_stream_enable()` transitions every `stream->ports[i].ch.state` to `SLIM_CH_STATE_ACTIVE` upon success. [F39, F55]
- `slim_define_channel()` must add 1 extra slot to the truncated slot count (`stream->bps / SLIM_SLOT_LEN_BITS + 1`) when `stream->prot != SLIM_PROTO_ISO` (PUSH/PULL protocols), whereas `slim_define_channel_content()` always encodes the unadjusted sample slot count `stream->bps / SLIM_SLOT_LEN_BITS`. [F65]
- Each entry in `slim_presence_rate_table` (`drivers/slimbus/stream.c`) must store the exact SLIMbus 2.0 Table 66 natural frequency in Hz at the array index matching its presence rate code so `slim_get_prate_code()` resolves `cfg->rate` to the specification code. [F77]

## Synchronization

- Every access to `ctrl->tid_idr` (`slim_msg_response()`, `slim_alloc_txn_tid()`, `slim_free_txn_tid()`, and `slim_ctrl_clk_pause()`) must hold `ctrl->txn_lock` via `spin_lock_irqsave()`, `idr_alloc_cyclic()` in `slim_alloc_txn_tid()` must use `GFP_ATOMIC`, and `slim_msg_response()` must release `ctrl->txn_lock` before calling `slim_free_txn_tid(ctrl, txn)` (which acquires `ctrl->txn_lock`). [F86, F87]
- `slim_device_alloc_laddr()` and `slim_report_absent()` must release `ctrl->lock` before calling `slim_device_update_status()`, and controller `get_laddr`/`set_laddr` callbacks (invoked under `ctrl->lock`) must not call `slim_get_logical_addr()`, `slim_device_report_present()`, or `slim_report_absent()` on the same `ctrl`. [F89]
- In `slim_ctrl_clk_pause()`, `ctrl->sched.m_reconf` must be held across the entire clock-pause entry or wakeup sequence, and when nesting locks, `ctrl->sched.m_reconf` must be acquired before `ctrl->txn_lock`. [F18]
- In `slim_do_transfer()`, core reconfiguration messages (`txn->mt == SLIM_MSG_MT_CORE` with `txn->mc` in `SLIM_MSG_MC_BEGIN_RECONFIGURATION..SLIM_MSG_MC_RECONFIGURE_NOW`) sent while `ctrl->sched.clk_state == SLIM_CLK_ENTERING_PAUSE` must bypass `pm_runtime_get_sync()`, the `SLIM_CLK_ACTIVE` check, and `pm_runtime_put_autosuspend()`. [F90]
- Insertions and removals on a `slim_device`'s `stream_list` (in `slim_stream_allocate()` and `slim_stream_free()`) must hold `dev->stream_list_lock`, with `rt->name` and `rt->dev` initialized before `list_add_tail()` and `kfree(stream)` called after `list_del()`. [F20]

## Object Lifetimes

- In `slim_do_transfer()`, if `ctrl->xfer_msg()` returns `-ETIMEDOUT` or `wait_for_completion_timeout()` on `txn->comp` expires, `slim_free_txn_tid(ctrl, txn)` must be called before returning so delayed interrupts in `slim_msg_response()` cannot dereference a stack-allocated `slim_msg_txn` via `ctrl->tid_idr`. [F1]
- In `slim_msg_response()`, `slim_free_txn_tid(ctrl, txn)` and `memcpy(msg->rbuf, reply, len)` must execute before `complete(txn->comp)`, because `txn`, `txn->msg`, `msg->rbuf`, and `txn->comp` (`done`) are allocated on the waiting thread's stack in `slim_do_transfer()`, `slim_xfer_msg()`, and `slim_read()`. [F68]
- `slim_alloc_txn_tid()` allocates TIDs in `[1, SLIM_MAX_TIDS)` via `idr_alloc_cyclic()`, reserving `txn->tid == 0` as the unallocated sentinel; `slim_do_transfer()` must initialize `txn->tid = 0` before `slim_tid_txn()`/`ctrl->xfer_msg()` and release a non-`clk_pause_msg` runtime PM reference at `slim_xfer_err` only when `txn->tid == 0 || ret == -ETIMEDOUT`, because `slim_msg_response()` releases it for any transaction with a non-zero `tid` (including `tid`s allocated inside `ctrl->xfer_msg()`). [F26, F73]
- Once `slim_add_device()` sets `sbdev->dev.release = slim_dev_release` and calls `device_register(&sbdev->dev)` (after `sbdev->e_addr`, `sbdev->ctrl`, `sbdev->stream_list`, `sbdev->stream_list_lock`, `sbdev->dev.of_node`, and the device name are initialized), `sbdev` must be freed only via `put_device(&sbdev->dev)` or `device_unregister(&sbdev->dev)`, never via direct `kfree(sbdev)`. [F11, F80]
- `slim_register_controller()` must allocate `ctrl->id` from `ctrl_ida` and initialize `ctrl->laddr_ida`, `ctrl->tid_idr`, `ctrl->lock`, `ctrl->sched.m_reconf`, `ctrl->sched.pause_comp`, and `ctrl->txn_lock` before calling `of_register_slim_devices(ctrl)`. [F78]
- `slim_unregister_controller()` must unregister all child `slim_device` instances via `slim_remove_device()` (which balances `of_node_get()` via `of_node_put(sbdev->dev.of_node)` and calls `device_unregister(&sbdev->dev)`) before freeing `ctrl->id` in `ctrl_ida`, and must not call `slim_ctrl_clk_pause()` during teardown. [F9, F76]
- `slim_stream_unprepare()` must `kfree(stream->ports)` and clear both `stream->ports = NULL` and `stream->num_ports = 0`, because `slim_stream_prepare()` rejects any stream with non-NULL `rt->ports` and `slim_stream_free()` frees only `stream->name` and `stream`. [F7]

## API Contracts

- Every `struct slim_driver` registered via `__slim_driver_register()` must provide `drv->probe` and a non-NULL `drv->id_table` terminated by a `{}` zero sentinel (`manf_id == 0`, `prod_code == 0`), because `slim_device_match()` unconditionally dereferences `sbdrv->id_table` in `slim_match()` whenever `of_driver_match_device()` returns 0; `remove` and `device_status` are optional and must be NULL-checked after verifying `dev->driver` is non-NULL. [F30, F94]
- In `slim_device_probe()`, `sbdrv->probe(sbdev)` runs before `slim_get_logical_addr(sbdev)` and `slim_device_update_status(sbdev, SLIM_DEVICE_STATUS_UP)`, so a `slim_driver` cannot rely on `sbdev->laddr` being valid during `probe()` unless it calls `slim_get_logical_addr()` or defers bus transfers to `device_status()`. [F95]
- `slim_register_controller()` synchronously enumerates child DT nodes via `of_register_slim_devices()` and registers child `slim_device` instances, so a controller driver must initialize `ctrl->dev` and its callbacks (`get_laddr`, `set_laddr`, `xfer_msg`) before calling `slim_register_controller()`. [F96]
- In `struct slim_controller`, `get_laddr`, `set_laddr`, `wakeup`, `enable_stream`, and `disable_stream` are optional callbacks that may be `NULL`; when `ctrl->get_laddr` is non-NULL, logical addresses come from `ctrl->get_laddr` rather than `ctrl->laddr_ida`, so `slim_report_absent()` only calls `ida_free(&ctrl->laddr_ida, sbdev->laddr)` when `!ctrl->get_laddr`. [F29, F33]
- `txn->msg` in `struct slim_msg_txn` can be `NULL` for broadcast control transactions such as `SLIM_MSG_MC_BEGIN_RECONFIGURATION` and `SLIM_MSG_MC_RECONFIGURE_NOW`, so `slim_do_transfer()` and `ctrl->xfer_msg` implementations must not dereference `txn->msg` without checking `slim_tid_txn()`, message code, or `txn->msg != NULL`. [F27]
- For any transaction registered in `ctrl->tid_idr`, `txn->msg->rbuf` must be non-NULL and large enough to hold the `len` bytes passed to `slim_msg_response(ctrl, reply, tid, len)`, because `slim_msg_response()` executes `memcpy(msg->rbuf, reply, len)` without checking `msg->num_bytes`. [F71]
- In `slim_xfer_msg()`, `slim_val_inf_sanity()` must validate that `msg != NULL`, `msg->num_bytes <= 16`, `msg->start_offset + msg->num_bytes <= 0xC00`, and the required `msg->rbuf`/`msg->wbuf` pointers are non-NULL for `mc` before `slim_slicesize()` and `txn->ec`/`txn->rl` arithmetic execute. [F45]
- `slim_readb()` must read into an unsigned `u8` buffer so bytes `0x80..0xFF` zero-extend to `128..255` in `int` rather than sign-extending into negative values, and callers must store the return value in a signed integer and check `< 0` before truncating to `u8`. [F23, F62]
- `slim_get_device()` and `slim_stream_allocate()` return `ERR_PTR(-ENOMEM)` on allocation failure (requiring `IS_ERR()` checks), whereas `of_slim_get_device()` never allocates a device and returns `NULL` when no matching child device is found on `ctrl->dev` (requiring a `NULL` check). [F6, F22]
- Before `slim_stream_prepare()` is called, `rt->dev->ctrl->a_framer` must point to a valid `struct slim_framer` with a non-zero `superfreq`, `cfg->rate` must exist in `slim_presence_rate_table`, `cfg->chs` must have at least `hweight32(cfg->port_mask)` elements, and the `rt->ports` allocation count (`hweight32(cfg->port_mask)`) must match the `SLIM_DEVICE_MAX_PORTS` (32-bit) scan width. [F70, F101]
- When stopping an active stream, callers must invoke `slim_stream_disable(stream)` before `slim_stream_unprepare(stream)`, because `slim_stream_disable()` requires `stream->ports` and `stream->num_ports` to be non-zero to deactivate and remove each port's channel. [F8]
- In `slim_stream_enable()`, `ctrl->enable_stream` replaces the core channel-definition and `SLIM_MSG_MC_RECONFIGURE_NOW` transfers, whereas in `slim_stream_disable()`, `ctrl->disable_stream` is called before the core still sends `SLIM_MSG_MC_BEGIN_RECONFIGURATION`, `slim_deactivate_remove_channel()`, and `SLIM_MSG_MC_RECONFIGURE_NOW`. [F102]

## Error Handling

- In the wakeup path of `slim_ctrl_clk_pause()`, `ret` must be reset to `0` after `wait_for_completion_timeout(&sched->pause_comp, ...)` succeeds before conditionally calling `ctrl->wakeup(ctrl)`, because `wait_for_completion_timeout()` returns positive remaining jiffies on success. [F25]

## External Contracts

- `struct slim_eaddr` must remain a 6-byte `__packed` structure ordered as `instance` (`u8`), `dev_index` (`u8`), `prod_code` (`u16`), and `manf_id` (`u16`), whereas DT child nodes under `ctrl->dev->of_node` parsed by `of_register_slim_devices()` require `compatible` matching `"slim%x,%x"` (`manf_id`, `prod_code`) and a 2-cell `u32` `reg` property (`reg[0] = dev_index`, `reg[1] = instance`), formatted by `slim_add_device()` and `slim_device_uevent()` as `MODALIAS=slim:%x:%x:%x:%x`. [F48, F104]

## Known Pitfalls

- `slim_fill_msg()` narrows `u32 addr` to `u16 msg->start_offset` and `size_t count` to `u8 msg->num_bytes` before `slim_xfer_msg()` runs `slim_val_inf_sanity()`, so callers of `slim_read()` and `slim_write()` must not rely on `slim_val_inf_sanity()` to catch `addr >= 0x10000` or `count >= 256` that wrap modulo `2^16` or `2^8` into range. [F66]
- When reusing a `struct slim_msg_txn` across multiple `slim_do_transfer()` calls (as in `slim_ctrl_clk_pause()`), callers must explicitly reinitialize `txn.mc`, `txn.rl`, and `msg` fields (`num_bytes`, `wbuf`) before each call because `ctrl->xfer_msg` implementations may mutate `txn->rl` or `txn->msg` in place. [F41]
- `slim_stream_prepare()` allocates `rt->ports` with `hweight32(cfg->port_mask)` elements and populates `rt->ports[i]` and `port->ch.id = cfg->chs[i]` using a dense 0-based counter `i` while iterating set bits of `cfg->port_mask` below `SLIM_DEVICE_MAX_PORTS` (32), storing the sparse bit position in `port->id`. Broken by: indexing `rt->ports` or `cfg->chs` by `port->id` instead of `i`. [F46]
- In `of_register_slim_devices()`, per-child validation failures inside `for_each_child_of_node(ctrl->dev->of_node, node)` must use `continue` rather than `return` or `break` without `of_node_put(node)`, so that remaining child DT nodes are registered and node references are not leaked. [F57]
- In `slim_slicesize()`, the bounded value returned by `clamp(code, 1, (int)ARRAY_SIZE(sizetocode))` must be assigned back to `code` before indexing `sizetocode[code - 1]`. [F24]
