# LTC4282 HARDWARE MONITOR DRIVER

This unit is an I2C hardware monitoring (`hwmon`) and common clock framework driver for the Analog Devices LTC4282 High Current Hot Swap Controller (`drivers/hwmon/ltc4282.c`). It configures device operating parameters from firmware properties, registers an optional clock provider for the `CLKOUT` pin, and exposes voltage (`VSOURCE`, `VDD`, `VGPIO`), current, power, and energy telemetry, limits, and fault logs via `hwmon` sysfs attributes and `debugfs`.

## Architecture & Data Flow

- When switching the ADC mux between `LTC4282_CHAN_VSOURCE` and `LTC4282_CHAN_VDD` in `ltc4282_vdd_source_enable()`, the boolean written to `LTC4282_VDD_MONITOR_MASK` in `LTC4282_ILIM_ADJUST` must be inverted for `LTC4282_CHAN_VDD` (0 selects VDD), the two `st->in0_1_cache[].en` flags must be set to opposite values, the outgoing channel saved via `ltc4282_cache_history()`, and the incoming channel restored via `ltc4282_cache_sync()`. [F23, F39]
- For `LTC4282_CHAN_VSOURCE` and `LTC4282_CHAN_VDD`, `ltc4282_vdd_source_read_lim()` and `ltc4282_vdd_source_write_lim()` must access `LTC4282_VSOURCE_MIN`/`LTC4282_VSOURCE_MAX` only when `st->in0_1_cache[channel].en` is true, and otherwise only read or update `st->in0_1_cache[channel].in_min_raw`/`in_max_raw` to avoid clobbering or reading the active sibling channel's hardware limit. [F25]
- `ltc4282_vdd_source_reset_hist()` must always reset `st->in0_1_cache[channel].in_lowest` and `in_highest`, and call `__ltc4282_in_write_history()` on `LTC4282_VSOURCE_LOWEST` only when `st->in0_1_cache[channel].en` is true (matching `ltc4282_vdd_source_read_hist()`, which reads hardware and updates `*cached` only when `.en` is true). [F26]
- `st->in0_1_cache` has only `LTC4282_CHAN_VGPIO` (2) entries (channels 0 and 1); `ltc4282_read_in()` and `ltc4282_write_in()` must branch on `channel == LTC4282_CHAN_VGPIO` before indexing `st->in0_1_cache[channel]` or calling `ltc4282_vdd_source_*`, and channel 2 in `ltc4282_info` must not set `HWMON_I_ENABLE`. [F31]
- Because `ltc4282_regmap_config` sets `val_bits = 8`, 16-bit telemetry/history registers must use 2-byte `regmap_bulk_read()`/`regmap_bulk_write()` with `__be16` conversions, and the 48-bit `LTC4282_ENERGY` register must be read via a 6-byte `regmap_bulk_read()` into an 8-byte `__be64 raw` followed by `be64_to_cpu(raw) >> 16` to align the 48-bit value and discard the 2 trailing uninitialized stack bytes. [F32, F51]
- `ltc4282_setup()` enforces `st->rsense >= CENTI` (100 nOhm) on `"adi,rsense-nano-ohms"` and divides `st->rsense` by `CENTI`, so `st->rsense` is non-zero and stored in units of 0.1 micro-ohms; all current, power, and energy scaling formulas must include the `DECA` (10) factor. [F14]
- In `ltc4282_setup()`, `ltc4282_get_defaults()` must run before parsing optional firmware properties or calling `ltc4282_set_max_limits()` so EEPROM-backed defaults for `st->energy_en`, `vin_mode`, `st->vsense_max`, and `st->in0_1_cache` are loaded before overrides and limit calculations. [F56]
- In `ltc4282_setup()`, setting `"adi,vin-mode-microvolt"` must write the same `LTC4282_VIN_*` index to both `LTC4282_CTRL_VIN_MODE_MASK` and `LTC4282_FOLDBACK_MODE_MASK`, and set `st->vfs_out` and `st->vdd` from `ltc4282_vfs_milli` and `ltc4282_vdd_milli` before `ltc4282_set_max_limits()` runs. [F29]
- `ltc4282_set_max_limits()` must initialize `st->power_max` and write it to `LTC4282_POWER_MAX`, and `ltc4282_write_power_byte()` must clamp `val` to `st->power_max` so `ltc4282_read_power_byte()` cannot overflow a 32-bit `long`. [F34]
- `st->rsense`, `st->vfs_out`, `st->vdd`, `st->vsense_max`, and `st->power_max` are initialized in `ltc4282_setup()` before `devm_hwmon_device_register_with_info()` and `ltc4282_debugfs_init()` and must remain read-only thereafter because runtime `hwmon` callbacks read them without `st->lock`. [F10]
- `st->energy_en` must be kept synchronized under `st->lock` with the logical inverse of `LTC4282_METER_HALT_MASK` in `LTC4282_ADC_CTRL` across `ltc4282_get_defaults()` and `ltc4282_energy_enable_set()`, as `ltc4282_energy_show()` gates `ltc4282_read_energy()` on `st->energy_en`. [F28]
- In `ltc4282_gpio_setup()`, configuring `"adi,gpio2-mode"` as `"adc_input"` (setting `LTC4282_GPIO_MODE_MASK` in `LTC4282_ILIM_ADJUST`) and enabling `"adi,gpio3-monitor-enable"` (clearing `LTC4282_GPIO_MODE_MASK`) are mutually exclusive and must be rejected with `-EINVAL` if both are present. [F30]
- `ltc4282_out_rates` must remain sorted in ascending numerical order (`LTC4282_CLKOUT_CNV` then `LTC4282_CLKOUT_SYSTEM`) because `ltc4282_determine_rate()` passes it to `find_closest()`. [F44]
- `ltc4282_readable_reg()` and `ltc4282_writable_reg()` must reject `LTC4282_RESERVED_1` (0x32) and `LTC4282_RESERVED_2` (0x33), and `ltc4282_writable_reg()` must also reject the read-only registers `LTC4282_STATUS_LSB` (0x1e) and `LTC4282_STATUS_MSB` (0x1f). [F63]

## Synchronization

- After registration in `ltc4282_probe()`, every read or write of `st->in0_1_cache` or `st->energy_en` and its paired `st->map` register transfer must be serialized under `st->lock` (acquired outside the regmap internal lock). [F70]
- Callers holding `st->lock` must use the unlocked helpers `__ltc4282_read_alarm()`, `__ltc4282_in_write_history()`, `ltc4282_cache_history()`, and `ltc4282_cache_sync()`; unlocked runtime callers must acquire `st->lock` or call the locking wrappers `ltc4282_read_alarm()` and `ltc4282_in_write_history()`. [F7]
- In `ltc4282_probe()`, `ltc428_clks_setup()` registers `st->clk_hw` (`ltc4282_ops`) before `ltc4282_setup()` and `mutex_init(&st->lock)`, so `ltc4282_ops` callbacks (`ltc4282_recalc_rate`, `ltc4282_determine_rate`, `ltc4282_set_rate`, `ltc4282_disable`) must only access `st->map` unless `mutex_init(&st->lock)` and `ltc4282_setup()` are moved before `ltc428_clks_setup()`. [F9]

## Object Lifetimes

- In `ltc4282_probe()`, `st->map` must be initialized via `devm_regmap_init_i2c()`, followed by setting `LTC4282_RESET_MASK` in `LTC4282_ADC_CTRL` and sleeping `msleep(3200)` for soft-reset and EEPROM reload, before calling `ltc428_clks_setup()`, `ltc4282_setup()`, `devm_hwmon_device_register_with_info()`, or `ltc4282_debugfs_init()`. [F1, F55]
- In `ltc4282_probe()`, `mutex_init(&st->lock)` must precede `devm_hwmon_device_register_with_info()` and `ltc4282_debugfs_init()`, and `ltc4282_debugfs_init()` must run only after all fallible probe steps succeed and create its `debugfs_create_file_unsafe()` entries under `i2c->debugfs` so `i2c_device_remove()` removes them before `devres` frees `st`. [F58, F77]
- In `ltc428_clk_provider_setup()`, `st->clk_hw.init` must be populated and registered via `devm_clk_hw_register(dev, &st->clk_hw)` before calling `devm_of_clk_add_hw_provider()` with `&st->clk_hw`. [F3]
- In `ltc428_clks_setup()`, the optional input clock must be acquired via `devm_clk_get_optional_enabled()`, checked to be within `[LTC4282_CLKIN_MIN, LTC4282_CLKIN_MAX]` (250 kHz to 15.5 MHz), and divided to 250 kHz by writing `rate / (2 * LTC4282_CLKIN_MIN)` to `LTC4282_CLK_DIV_MASK` in `LTC4282_CLK_DIV`. [F67]

## API Contracts

- `__ltc4282_read_alarm()` clears the queried `mask` bits via `regmap_clear_bits()` only for `LTC4282_ADC_ALERT_LOG` and skips clearing when `reg` is `LTC4282_STATUS_LSB` or `LTC4282_FAULT_LOG` (whose bits are cleared in `ltc4282_power_reset_hist()`, `ltc4282_vdd_source_reset_hist()`, and `ltc4282_curr_reset_hist()`); any caller passing another read-only or persistent register (such as `LTC4282_STATUS_MSB`) must add it to that exclusion guard. [F40, F64]
- `ltc4282_probe()` attaches `st` as driver data only to the `hwmon` child device via `devm_hwmon_device_register_with_info()` and never calls `i2c_set_clientdata()`, so `dev_get_drvdata()` returns `st` only on the `hwmon` `struct device` and returns `NULL` on `&i2c->dev`. [F54]
- `ltc4282_write_voltage_byte_cached()`, `ltc4282_write_voltage_byte()`, and `__ltc4282_in_write_history()` require the target voltage (`val` or `lowest`/`highest`) and full-scale `fs` to be in the same unit (both mV or both uV; e.g., `st->vsense_max` in uV requires `fs = 40 * MILLI`). [F20]
- `__ltc4282_in_write_history()` and `ltc4282_in_write_history()` require `reg` to be a `*_LOWEST` register (`LTC4282_VGPIO_LOWEST`, `LTC4282_VSOURCE_LOWEST`, or `LTC4282_VSENSE_LOWEST`) because `__ltc4282_in_write_history()` writes `lowest` to `reg` and `highest` to `reg + 2`. [F12]
- In `ltc4282_read_voltage_byte_cached()` and `ltc4282_write_voltage_byte_cached()`, a non-NULL `cached_raw`/`cache_raw` pointer redirects the 8-bit limit access to the in-memory cache without touching `st->map`, whereas a NULL pointer accesses register `reg`. [F11]
- `ltc4282_recalc_rate()` (`clk_ops.recalc_rate`) returns an `unsigned long` rate in Hz and must return `0` (not a negative errno) when `regmap_read()` fails or `FIELD_GET(LTC4282_CLKOUT_MASK, clkdiv)` is `0`. [F22]
- In `ltc428_clk_provider_setup()`, calls to `devm_clk_hw_register()` and `devm_of_clk_add_hw_provider()` must remain guarded by `IS_ENABLED(CONFIG_COMMON_CLK)` because `SENSORS_LTC4282` does not depend on `COMMON_CLK`. [F71]
- `energy1_input` must be exposed as a `u64` custom attribute in `ltc4282_attrs` via `ltc4282_energy_show()` rather than `HWMON_E_INPUT` in `ltc4282_info`, and `HWMON_CHANNEL_INFO(energy, ...)` must only include `HWMON_E_ENABLE` unless `ltc4282_read()`, `ltc4282_write()`, and `ltc4282_is_visible()` check `attr` and avoid the `long *val` truncation. [F72]

## Error Handling

- Reading a live input for a disabled channel or meter (`!st->in0_1_cache[channel].en` in `ltc4282_vdd_source_read_in()` or `!st->energy_en` in `ltc4282_energy_show()`) must return `-ENODATA` without reading the hardware register. [F16]
- In `ltc4282_vdd_source_enable()` and `ltc4282_energy_enable_set()`, `regmap_update_bits()` on `LTC4282_ILIM_ADJUST` or `LTC4282_ADC_CTRL` must succeed before updating `st->in0_1_cache[].en` or `st->energy_en`. [F21]
- In `ltc428_clks_setup()`, `devm_clk_get_optional_enabled()` returns `ERR_PTR` on error and `NULL` when absent, so `IS_ERR(clkin)` must be checked first and `!clkin` must return `0` before calling `clk_get_rate(clkin)`. [F17]

## Known Pitfalls

- `ltc4282_vdd_source_read_alm()` must return `*val = 0` without calling `__ltc4282_read_alarm()` when `st->in0_1_cache[channel].en` is false, because `__ltc4282_read_alarm()` clears `LTC4282_ADC_ALERT_LOG` bits on read and would consume the active sibling channel's alarm. [F24]
- `ltc4282_read_voltage_word()` must widen `fs` to `u64` before multiplying by `be16_to_cpu(in)` and divide with `DIV_ROUND_CLOSEST_ULL`, because `ltc4282_read_current_word()` passes `fs = DECA * 40 * MILLI` (400000), whose product with a 16-bit ADC code exceeds `U32_MAX`. [F46]
- In `ltc4282_read_power_word()`, `ltc4282_write_power_word()`, and `ltc4282_read_energy()`, 64-bit numerator products must be guarded with `check_mul_overflow()` and fall back to pre-dividing by `U16_MAX` or `DECA * MICRO` before multiplying the remaining factor. [F48]
- Divisions in `ltc4282_read_power_word()`, `ltc4282_read_power_byte()`, `ltc4282_read_energy()`, `ltc4282_write_power_byte()`, and `ltc4282_write_power_word()` whose divisors can exceed `U32_MAX` must use `DIV64_U64_ROUND_CLOSEST` with a `(u64)`-widened divisor rather than `DIV_ROUND_CLOSEST_ULL`. [F49]
- In `ltc4282_gpio_setup()`, `const char *func` must be initialized to `NULL`, retain the string from `"adi,gpio2-mode"` (or a non-`"adc_input"` string from `ltc4282_gpio1_modes`) without being reused, and be checked with `if (func && !strcmp(func, "adc_input"))` when `"adi,gpio3-monitor-enable"` is set. [F19, F42]
- In `ltc4282_setup()`, the local variable `val` must be initialized to `vin_mode` before reading `"adi,vin-mode-microvolt"`, mapped in-place to the `LTC4282_VIN_*` enum (0..3) when the property is present, and not reused before indexing `ltc4282_vfs_milli[val]` and `ltc4282_vdd_milli[val]`. [F43]
- In `ltc4282_setup()`, each firmware property check (such as `device_property_read_bool` for `"adi,fault-log-enable"`) and its `regmap` modification must appear only once without duplicate conditional blocks. [F61]
