# WWAN DRIVERS

The WWAN subsystem core (`wwan_core.c`) manages virtual WWAN devices (`struct wwan_device`), exposes modem control channels as character devices (`struct wwan_port`), and provides an RTNL link interface (`rtnl_link_ops` kind "wwan") for multiplexed WWAN network interfaces. Accompanying drivers include MHI client drivers for modem control ports (`mhi_wwan_ctrl.c`) and MBIM IP data multiplexing (`mhi_wwan_mbim.c`), plus a software simulator (`wwan_hwsim.c`) with debugfs controls and an AT command echo parser.

## Architecture & Data Flow
- After `mhi_wwan_rx_budget_dec()` decrements `rx_budget`, `mhi_wwan_ctrl_refill_work()` must call `mhi_wwan_rx_budget_inc()` directly only if `alloc_skb()` fails before `skb->destructor = __mhi_skb_destructor` is set; once set, freeing `skb` on any path restores `rx_budget` via `__mhi_skb_destructor()`. In `mhi_wwan_rx_budget_dec()`, `MHI_WWAN_RX_REFILL` must be checked whenever `rx_budget` was non-zero before decrementing, even when the decrement brings it from `1` to `0`. [F9, F47]
- In `mhi_mbim_dl_callback()` and `mhi_dl_xfer_cb()`, `transaction_status == -EOVERFLOW` indicates a split transfer rather than a fatal error: bytes must be finalized with `skb_put()` and appended to `mbim->skbagg_head` via `mhi_net_skb_agg()` (without calling `mhi_mbim_rx()`) or forwarded to `wwan_port_rx()`, and `mbim->skbagg_head` must be reset to `NULL` once the final (`0`) fragment is aggregated or when dropping an incomplete chain. [F34, F73]
- When chaining a fragment SKB onto a head SKB's `frag_list` in `mhi_net_skb_agg()` or `wwan_port_fops_write()`, `head->len`, `head->data_len`, and `head->truesize` must all be incremented by `skb->len`, `skb->len`, and `skb->truesize` alongside updating the tail pointer. [F52]
- Because `wwan_class` and `wwandev->dev` host devices of different types, a `struct device *` must be verified against `wwan_dev_type`, `wwan_port_dev_type`, or `wwan_type` before downcasting with `to_wwan_dev()`, `to_wwan_port()`, or `to_net_dev()`. [F38]
- `wwan_dev_parent_match()` must check both `dev->parent == parent` and `dev == parent` so `wwan_dev_get_by_parent()` resolves lookups passed either the hardware parent or `&wwandev->dev` itself (from `netdev->dev.parent` in `wwan_rtnl_newlink()` and `wwan_rtnl_dellink()`). [F67]
- In `wwan_core.c`, `is_wwan_child()` must return non-zero on a matching `wwan_class` port child to short-circuit `device_for_each_child()` in `wwan_remove_dev()`, whereas `wwan_child_dellink()` must always return `0` so `device_for_each_child()` in `wwan_unregister_ops()` queues every child netdev onto `kill_list`. [F71]
- In `struct wwan_netdev_priv`, `drv_priv[]` must remain the final flexible-array member aligned to `sizeof(void *)`, `wwan_rtnl_alloc()` must allocate `sizeof(struct wwan_netdev_priv) + wwandev->ops->priv_size`, and WWAN netdev drivers must access per-link private data via `wwan_netdev_drvpriv(dev)` rather than `netdev_priv(dev)`. [F42, F112]
- In `mhi_net_rx_refill_work()`, both `alloc_skb()` and `mhi_queue_skb()` must use `mbim->mru` (initialized from `mhi_dev->mhi_cntrl->mru`) rather than `MHI_DEFAULT_MRU`, and in `mhi_mbim_setup()`, `ndev->max_mtu` must not exceed `MHI_MAX_BUF_SZ - sizeof(struct mbim_tx_hdr)` (`0xffff - ndev->needed_headroom`) so `skb->len` after `skb_push()` fits in `nth16->wBlockLength`. [F49, F64]
- `mbim_rx_verify_ndp16()` must reject `le16_to_cpu(ndp16->wLength) < USB_CDC_NCM_NDP16_LENGTH_MIN` before subtracting `sizeof(struct usb_cdc_ncm_ndp16)` and decrementing `ret` for the NULL terminator entry. [F63]
- Every `enum wwan_port_type` below `__WWAN_PORT_MAX` must have a `.name` and `.devsuf` entry in `wwan_port_types`, `WWAN_PORT_UNKNOWN` must remain above `WWAN_PORT_MAX`, and every `mhi_wwan_ctrl_match_table` entry before `{}` must set `.driver_data` to a valid `enum wwan_port_type` (`<= WWAN_PORT_MAX`). [F68, F97]
- In `mhi_wwan_ctrl.c`, RX refilling in `mhi_wwan_ctrl_start()` must be gated on `MHI_WWAN_DL_CAP` (`mhi_dev->dl_chan` present) and TX queueing in `mhi_wwan_ctrl_tx()` on `MHI_WWAN_UL_CAP` (`mhi_dev->ul_chan` present). [F92]
- `port->at_data.termios` must remain `struct ktermios` (not `struct termios`) because `wwan_port_fops_at_ioctl()` copies both `sizeof(struct termios)` and `sizeof(struct termios2)` bytes to/from it, and `wwan_rtnl_link_ops.maxtype` must be `IFLA_WWAN_MAX` (not `__IFLA_WWAN_MAX`) to match `wwan_rtnl_policy[IFLA_WWAN_MAX + 1]`. [F58, F65]

## Synchronization
- `mhiwwan->rx_lock` must always be acquired with `spin_lock_bh()` / `spin_unlock_bh()` because `__mhi_skb_destructor()` can invoke `mhi_wwan_rx_budget_inc()` from softirq/BH context while MHI holds `pm_lock`. [F98]
- In `mhi_wwan_ctrl_tx()` and `mhi_ul_xfer_cb()`, `mhiwwan->tx_lock` must be held with `spin_lock_bh()` across `mhi_queue_skb()`, `mhi_queue_is_full()`, and `wwan_port_txoff()` / `wwan_port_txon()`; in `mhi_mbim_ndo_xmit()`, `mbim->tx_lock` must be held with `spin_lock_irqsave()` across `mbim_tx_fixup()`, `mhi_queue_skb()`, `mhi_queue_is_full()`, and incrementing `mbim->tx_seq`. [F18, F21]
- In `mhi_mbim_probe()`, `mbim->tx_lock`, `mbim->rx_refill`, `mbim->mdev`, `mbim->mru`, and driver data must be initialized before `mhi_prepare_for_transfer()` and `wwan_register_ops()`; in `mhi_mbim_newlink()`, all `struct mhi_mbim_link` fields (`mbim`, `session`, `ndev`, `rx_syncp`, `tx_syncp`) must be initialized before `hlist_add_head_rcu()` publishes `link->hlnode`. [F14, F15]
- In `mhi_mbim_rx()`, `mhi_mbim_get_link_rcu()` and all accesses to `link` and `link->ndev` must stay within `rcu_read_lock()` / `rcu_read_unlock()`, paired with `hlist_del_init_rcu()` and `synchronize_rcu()` before `unregister_netdevice_queue()` in `mhi_mbim_dellink()`. All 64-bit stats accesses in `struct mhi_mbim_link` must use `u64_stats_update_begin()`/`end()` and `u64_stats_fetch_begin()`/`retry()` with `link->rx_syncp` or `link->tx_syncp`. [F80, F102]
- `wwan_register_lock` must be held across lookup, allocation, and registration in `wwan_create_dev()`, across the active-ops/child-port check and `device_unregister()`/`put_device()` in `wwan_remove_dev()`, and continuously across `__wwan_port_dev_assign_name()` and `device_register(&port->dev)` in `wwan_create_port()` after initializing all `struct wwan_port` fields and locks. [F22, F23]
- `wwan_remove_port()` must acquire `port->ops_lock`, call `port->ops->stop(port)` if `port->start_count` is non-zero, and set `port->ops = NULL` before calling `wake_up_interruptible(&port->waitqueue)` (so `is_read_blocked()` and `is_write_blocked()` become `false`), purging `port->rxq` via `skb_queue_purge()`, and calling `device_unregister(&port->dev)`. `wwan_port_op_stop()` must also purge `port->rxq` on final close. [F54, F94, F105]
- In `wwan_core.c`, access to `port->at_data` in `wwan_port_fops_at_ioctl()` must hold `port->data_lock`, and walking `port->rxq` in `wwan_port_fops_ioctl()` (`TIOCINQ`) must hold `port->rxq.lock` with `spin_lock_irqsave()`. [F27]
- In `wwan_hwsim.c`, debugfs `destroy` write handlers must defer deletion to `wwan_wq`; deletion paths must unlink `port->list` or `dev->list` with `list_del_init()` under `dev->ports_lock` or `wwan_hwsim_devs_lock` and drop the spinlock before calling `wwan_hwsim_port_del()` or `wwan_hwsim_dev_del()`, which must guard `cancel_work_sync()` with `current_work() != &...->del_work`. [F28, F76]

## Object Lifetimes
- In `mhi_wwan_mbim.c`, `mbim_tx_fixup()` frees `skb` via `dev_kfree_skb_any(skb)` and returns `NULL` when `skb_cow_head()` fails, whereas `mhi_queue_skb()` leaves `skb` unfreed on error for `mhi_mbim_ndo_xmit()` to free after releasing `mbim->tx_lock`. [F2]
- Before calling `wwan_remove_dev(wwandev)`, `wwan_remove_port()` must call `device_unregister(&port->dev)` and `wwan_unregister_ops()` must delete all child WWAN netdevs via `wwan_child_dellink()` and `unregister_netdevice_many()` under `rtnl_lock()` and then set `wwandev->ops = NULL`, because `wwan_remove_dev()` only unregisters `wwandev->dev` when `wwandev->ops` is `NULL` and no `wwan_class` child remains attached. [F4, F26]
- In `wwan_create_dev()`, `wwan_create_port()`, and `wwan_hwsim_dev_new()`, IDA IDs (`wwan_dev_ids`, `minors`) and struct memory must be freed directly only if failure occurs before `device_register()`; if `device_register()` fails, rollback must call `put_device()` so `wwan_dev_destroy()` or `wwan_port_destroy()` frees them once, and cleanup after `device_register()` succeeds must call `device_unregister()` while preserving `err` for `ERR_PTR(err)`. [F6, F39]
- In `mhi_wwan_ctrl_stop()`, `MHI_WWAN_RX_REFILL` must be cleared under `spin_lock_bh(&mhiwwan->rx_lock)` before `cancel_work_sync(&mhiwwan->rx_refill)` and `mhi_unprepare_from_transfer(mhiwwan->mhi_dev)`, because unpreparing MHI and purging `port->rxq` free RX SKBs whose `__mhi_skb_destructor()` would otherwise re-schedule `mhiwwan->rx_refill`. [F10]
- In `mhi_mbim_remove()`, `mhi_unprepare_from_transfer(mhi_dev)` and `cancel_delayed_work_sync(&mbim->rx_refill)` must run before `wwan_unregister_ops()` and `kfree_skb(mbim->skbagg_head)`, because `mhi_mbim_ul_callback()` dereferences `skb->dev` (`ndev`) and `wwan_netdev_drvpriv(ndev)` while MHI flushes in-flight buffers. [F11]
- In `wwan_hwsim_exit()` and `err_clean_devs` of `wwan_hwsim_init()`, `debugfs_remove(wwan_hwsim_debugfs_devcreate)` and `wwan_hwsim_free_devs()` must be followed by `flush_workqueue(wwan_wq)` before removing `wwan_hwsim_debugfs_topdir`, unregistering `wwan_hwsim_class`, and destroying `wwan_wq`. [F96]

## API Contracts
- `wwan_port_ops.tx` and `wwan_port_ops.tx_blocking` take ownership of `skb` only when returning `0`; on any non-zero error return they must leave `skb` unfreed because `wwan_port_fops_write()` frees `head` via `kfree_skb(head)`. In `wwan_port_fops_write()`, each allocated `skb` must be linked into `head` before `copy_from_user()` can jump to `freeskb`, and any non-NULL `caps` passed to `wwan_create_port()` must have `caps->frag_len != 0`. [F1, F70]
- `wwan_port_rx()`, `wwan_port_txon()`, and `wwan_port_txoff()` are called from atomic/BH contexts and under driver spinlocks (`mhiwwan->tx_lock`), so they must never sleep or acquire `port->ops_lock` or `port->data_lock`. [F103]
- Every `skb` passed to `wwan_port_rx()` must be linear (`skb->data_len == 0`) with its length committed via `skb_put()`; because MHI does not update `skb->len` on DMA completion, `mhi_dl_xfer_cb()` and `mhi_mbim_dl_callback()` must call `skb_put(skb, mhi_result->bytes_xferd)` before passing `skb` to `wwan_port_rx()`, `mhi_net_skb_agg()`, or `mhi_mbim_rx()`. [F61, F116]
- Any `wwan_ops.setup` callback whose driver relies on `unregister_netdevice_queue()` in `.dellink` (or `wwan_rtnl_dellink()`) without calling `free_netdev()` must set `ndev->needs_free_netdev = true`, whereas `wwan_create_default_link()` must call `free_netdev(dev)` if `wwan_rtnl_newlink()` fails and `rtnl_configure_link()` if `wwan_rtnl_newlink()` succeeds. [F8, F109]
- When `CONFIG_WWAN_DEBUGFS` is enabled, `wwan_get_debugfs_dir()` acquires a reference on `wwandev->dev` via `wwan_dev_get_by_parent()` that must be released by `wwan_put_debugfs_dir()`, which drops both the lookup reference from `wwan_dev_get_by_debugfs()` and the caller's reference. [F3]
- In `struct wwan_port_ops`, `start`, `stop`, and `tx` are mandatory while `tx_blocking` and `tx_poll` are optional and `port->ops` becomes `NULL` in `wwan_remove_port()`, so core callers must check `port->ops` under `port->ops_lock` and null-check `tx_blocking` and `tx_poll`. Similarly, in `struct wwan_ops`, `setup` is mandatory while `newlink`, `dellink`, and `wwandev->ops` itself may be `NULL`, so RTNL handlers must check `wwandev->ops` and fall back to `register_netdevice()` / `unregister_netdevice_queue()`. [F36, F37]
- `mhi_wwan_ctrl_probe()`, `mhi_mbim_probe()`, and `mhi_mbim_remove()` must pass the shared MHI controller device `&cntrl->mhi_dev->dev` (not `&mhi_dev->dev`) as `parent` to `wwan_create_port()`, `wwan_register_ops()`, and `wwan_unregister_ops()`, and must call `mhi_prepare_for_transfer()` before `mhi_get_free_desc_count(..., DMA_FROM_DEVICE)` to set `rx_budget` or `rx_queue_sz`. [F88, F89]

## Error Handling
- `wwan_create_dev()` and the lookup helpers `wwan_dev_get_by_parent()`, `wwan_dev_get_by_name()`, `wwan_dev_get_by_debugfs()`, and `wwan_port_get_by_minor()` always return an `ERR_PTR` (never `NULL`) on failure, so callers must check `IS_ERR()`. [F29]
- `mbim_rx_verify_nth16()` and `mbim_rx_verify_ndp16()` return either a non-negative 16-bit offset/frame count or `-EINVAL` as an `int`, so callers in `mhi_mbim_rx()` must store the result in a signed `int` (`ndpoffset`, `nframes`) and check `< 0`. [F33]
- When `mhi_res->transaction_status == -ENOTCONN` in `mhi_mbim_dl_callback()` or `mhi_mbim_ul_callback()`, the callback must free the SKB and return immediately without scheduling `mbim->rx_refill`, incrementing `link->tx_errors`, or calling `netif_wake_queue()`. [F93]
- `wwan_port_fops_at_ioctl()` must return `-ENOIOCTLCMD` for unrecognized ioctls and only run when `port->type == WWAN_PORT_AT`, so `wwan_port_fops_ioctl()` guards `port->at_data` and falls through to generic ioctls (`TIOCINQ`). [F35]
- `wwan_register_ops()` must not roll back `wwandev->ops` if `wwan_create_default_link()` fails, and `wwan_port_op_start()` must initialize `ret = 0` before `if (!port->start_count)` so already-started ports increment `port->start_count` and return `0`. [F40, F41]

## External Contracts
- In `mhi_wwan_mbim.c`, `usb_cdc_ncm_ndp16.dwSignature` packs the session ID in bits 24–31 and the NDP signature in bits 0–23 (`MBIM_NDP16_SIGN_MASK`), so `mhi_mbim_rx()` must mask `dwSignature` with `MBIM_NDP16_SIGN_MASK` (`0x00ffffff`) when checking for `USB_CDC_MBIM_NDP16_IPS_SIGN`. [F79]
- In `wwan_port_fops_poll()`, if `!port->ops` under `port->ops_lock`, the returned poll mask must include `EPOLLHUP | EPOLLERR`. [F110]

## Known Pitfalls
- `WWAN_PORT_TX_OFF` and `enum mhi_wwan_flags` (`MHI_WWAN_DL_CAP`, `MHI_WWAN_UL_CAP`, `MHI_WWAN_RX_REFILL`) must be unshifted 0-based bit numbers rather than `BIT()` masks because they are passed to `set_bit()`, `clear_bit()`, and `test_bit()`. [F43]
- `mhi_mbim_probe()` must pass `0` as `def_link_id` to `wwan_register_ops()`, while `mhi_mbim_newlink()` must add `mhi_mbim_get_link_mux_id()` to `if_id` when setting `link->session` so both default and user-created links receive the base mux ID offset once. [F44]
- In `mbim_tx_fixup()`, `skb_cow_head(skb, sizeof(struct mbim_tx_hdr))` must run before `skb_push()`, and the IP datagram length must be sampled from `skb->len` before `skb_push(skb, sizeof(struct mbim_tx_hdr))` mutates `skb->len` so `dpe16[0].wDatagramLength` records payload size while `nth16->wBlockLength` records total NTB size. [F50, F115]
- In `mhi_mbim_rx()`, all reads at variable offsets (`ndpoffset`, `dpeoffset`, `dgram_offset`) must use `skb_copy_bits()` rather than indexing `skb->data` because `mhi_net_skb_agg()` chains fragments via `frag_list`, and any non-fatal NDP skip in the outer `while (1)` loop must jump to `next_ndp` (or `unlock`) rather than `continue` so `ndpoffset` advances to `wNextNdpIndex`. [F62, F72]
- The `fmt` passed to `__wwan_port_dev_assign_name()` must contain a single `%d` specifier (`%%d` in `namefmt` in `wwan_create_port()`) and fit within the 32-byte `namefmt` and `buf` stack buffers for both `sscanf()` and `snprintf()`. [F85]
