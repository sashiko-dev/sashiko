# CRYPTO LIBRARY

This component provides the kernel cryptographic library implementations for message digests and HMACs (MD5, SHA-1, SHA-224/256, SHA-384/512, SM3), the Poly1305 authenticator, Multi-Precision Integer (MPI) arithmetic and scatterlist/buffer coders, constant-time memory comparison (`__crypto_memneq`) and XOR (`__crypto_xor`) utilities, and architecture-specific dispatch headers for MIPS, PowerPC, RISC-V, s390, and SPARC alongside KUnit tests.

## Architecture & Data Flow
- `mpi_size_t` must remain signed because MPI reverse loops (`MPN_COPY_DECR`, `mpihelp_cmp`, `mpihelp_lshift`, `mpihelp_divrem`, `mpi_powm`) terminate on `< 0` and limb loops (`mpihelp_add_n`, `mpihelp_sub_n`, `mpihelp_mul_1`, `mpihelp_addmul_1`, `mpihelp_submul_1`) index from `j = -size` to `-1`. [F56]
- `mpi_alloc(0)` sets `a->d == NULL` and `a->alloced == 0` (`mpi_alloc_limb_space(0)` returns `NULL`), so check `nlimbs` or call `mpi_resize` before indexing `a->d`. In `mpi_copy`, clear immutable/constant flags (`b->flags &= ~(16|32)`). [F26, F45]
- In `mpihelp_mul_karatsuba_case`, allocate `ctx->tspace` and `ctx->tp` to `2 * vsize` limbs via `mpi_alloc_limb_space(2 * vsize)` while recording `ctx->tspace_size = vsize` and `ctx->tp_size = vsize`, as recursive calls write up to `2 * vsize` limbs. [F99]
- In `mpi_cmp`, after normalizing operands, check opposite signs first, then unequal limb counts (`usize - vsize` when non-negative, `vsize - usize` when both negative), then `!usize`, before calling `mpihelp_cmp(u->d, v->d, usize)` and negating `cmp` if `u->sign` is set. [F73]
- Architecture `*_blocks` functions falling back to `*_blocks_generic` when `!may_use_simd()` must share the generic in-memory state layout. `struct md5_block_state` stores `state->h[0..3]` in CPU byte order, so little-endian backends (`mips/md5.h`, `sparc/md5.h`) must convert `state->h` with `cpu_to_le32_array` on entry and `le32_to_cpu_array` on exit. [F66, F118]
- In `__hmac_*_preparekey`, `derived_key` must be zero-initialized (`= { 0 }`) before copying/hashing `raw_key` and cleared with `memzero_explicit` before returning. HMAC context initializers (`hmac_*_init*`, `__hmac_*_init`) must set the inner hash `bytecount` (or `bytecount_lo` with `bytecount_hi = 0`) to the hash block size, not `0`. [F35, F48]
- In `__sha512_update`, compute `partial = ctx->bytecount_lo % SHA512_BLOCK_SIZE` before adding `len` to `ctx->bytecount_lo`, and propagate carry to `ctx->bytecount_hi` via `check_add_overflow`. [F49]
- After appending `0x80` at `ctx->buf[partial++]`, `__md5_final`, `__sha1_final`, and `__sha256_final` must flush an extra block when `partial > BLOCK_SIZE - 8` (`> SHA512_BLOCK_SIZE - 16` in `__sha512_final`). `hmac_sha1_final`, `__hmac_sha256_final`, and `__hmac_sha512_final` rely on `memset(&ctx->sha_ctx.buf[digest_size], 0, BLOCK_SIZE - digest_size)` to zero the upper bytes of the 64/128-bit length field before writing the 32-bit bit length at `buf[BLOCK_SIZE - 4]`. [F63, F64]
- `sha1_transform`, `sha512_block_generic`, and `sm3_transform` use a 16-word circular schedule array (`W[16]` / `array[16]`) and must mask all round indices with `& 15` (`& 0x0f`). [F62]
- In `poly1305_core_emit`, constant-time selection between `h` and `h + -p` relies on subtracting `1UL << 26` (`g4`) or `1ULL << 42` (`g2`) and deriving the mask as `(g >> (width - 1)) - 1`. [F96]
- When `!IS_ENABLED(CONFIG_HAVE_EFFICIENT_UNALIGNED_ACCESS)`, `__crypto_xor` must compute the shared relative alignment `relalign` of `dst`, `src1`, and `src2`, advance byte-by-byte until `(unsigned long)dst & (relalign - 1)` is zero, and gate direct `u64`/`u32`/`u16` accesses on `!(relalign & 7/3/1)`. [F70]

## Synchronization
- Exported hash, HMAC, and Poly1305 functions must be callable in task, softirq, and hardirq contexts without sleeping or `GFP_KERNEL` allocations, whereas MPI allocation, coding, and arithmetic functions (`mpi_alloc`, `mpi_resize`, `mpi_get_buffer`, `mpi_read_raw_*`, `mpi_add*`, `mpi_sub*`, `mpi_mul*`, `mpi_tdiv_qr`, `mpi_powm`, `mpi_set_bit`, `mpi_rshift`) use `GFP_KERNEL` or `cond_resched()` and require process context. [F117, F119]
- In PowerPC and RISC-V arch helpers (`chacha_crypt_arch`, `poly1305_blocks`, `sha*_blocks`), bracket vector/SPE assembly calls with `vsx_begin`/`vsx_end`, `spe_begin`/`spe_end`, or `kernel_vector_begin`/`kernel_vector_end`. On PowerPC, `preempt_disable()` must precede `enable_kernel_vsx()`/`enable_kernel_spe()`, `disable_kernel_*()` must precede `preempt_enable()`, and `chacha_crypt_arch` and SPE `sha1_blocks`/`sha256_blocks` must chunk inputs by `SZ_4K` or `MAX_BYTES`. [F15, F122]
- In `lib/crypto/mips/*.h`, `md5_blocks` and `sha*_blocks` must check `octeon_has_crypto()` and enclose all COP2 register accesses between `flags = octeon_crypto_enable(&cop2_state)` and `octeon_crypto_disable(&cop2_state, flags)`. [F113]
- In `hash_irq_test2_func`, acquire each `struct hash_irq_test2_hash_ctx` slot via `atomic_cmpxchg(&ctx->in_use, 0, 1) == 0` and release via `atomic_set_release(&ctx->in_use, 0)` after all updates to `ctx->hash_ctx`, `ctx->offset`, and `ctx->step`. [F16]

## Object Lifetimes
- `mpi_get_buffer` must allocate at least 1 byte (`if (!n) n++;`) when `mpi_get_size(a) == 0`, transfer ownership of `buf` to the caller on success (even when `*nbytes == 0`), and `kfree(buf)` if `mpi_read_buffer` fails. [F1, F105]
- In `mpi_mul` and `mpi_powm`, destination limb buffers (`wp` or `rp`) must not alias inputs (`up`, `vp`, `bp`, `ep`, `mp`). In `mpi_mul`, when `w->alloced < wsize` and `w->d` aliases `up` or `vp`, allocate a new `wp` (`assign_wp = 1`) instead of calling `mpi_resize(w, wsize)`, freeing `wp` if `mpihelp_mul` fails or installing it via `mpi_assign_limb_space` on success; when `w->alloced >= wsize` and `wp == up`, copying `up` to `tmp_limb` must also check `if (wp == vp)` and set `vp = up`. [F3, F39, F84]
- In `mpi_powm`, record temporary limb allocations in `mp_marker`, `bp_marker`, `ep_marker`, and `xp_marker` and free via those markers, because `rp` and `xp` are swapped in the loop and `rp` is reassigned to `res->d`. [F4]
- In `mpi_tdiv_qr`, push every temporary limb buffer onto `marker[markidx++]` and free them in LIFO order at `out_free_marker:` on both normal and `-ENOMEM` exits. [F8]
- In `mpihelp_mul_karatsuba_case`, free the old buffer before reallocating `ctx->tspace` or `ctx->tp`, and if allocating `ctx->tp` fails, free `ctx->tspace` and set `ctx->tspace = NULL`. In `mpihelp_release_karatsuba_ctx`, the root `ctx` is stack-allocated while `ctx->next` nodes are heap-allocated: only free `tp` and `tspace` on the head `ctx`, then iterate `for (ctx = ctx->next; ctx; ctx = ctx2)` saving `ctx2 = ctx->next` before `kfree(ctx)`. [F44, F76]
- In `mpi_read_raw_from_sgl`, stop the `SG_MITER_ATOMIC` iterator with `sg_miter_stop(&miter)` on the `nbits > MAX_EXTERN_MPI_BITS` error path and before `mpi_alloc(nlimbs)`. [F7]

## API Contracts
- Internal finalizers (`__md5_final`, `__sha*_final`) must finish reading `ctx->buf` before writing to `out` and must not zeroize `*ctx`, whereas public `*_final` functions (`md5_final`, `sha*_final`, `hmac_*_final`, `poly1305_final`) must zeroize `*ctx`. `sha1_transform` does not clear its `array` workspace, so callers (`sha1_blocks_generic` and sensitive-data callers) must zeroize it after the last block. [F11, F50]
- Hash and Poly1305 functions must accept arbitrary byte alignments for `data` and `out`, never read past `data + len` or `out + digest_size`, and allow `out` to alias `data` (and `ctx->buf` in `__*_final`). [F65]
- `sha256_finup_2x()` must treat a `NULL` `ctx` as `&initial_sha256_ctx` without modifying `*ctx`. In `lib/crypto/sha256.c`, the `"sha256.h"` include and all `sha256_finup_2x*` and `hmac_sha224*`/`hmac_sha256*` definitions and exports must remain under `#ifndef __DISABLE_EXPORTS`. [F129, F134]
- `poly1305_blocks()` takes byte length `len` and `poly1305_emit()` takes `(state, digest, nonce)`, whereas `poly1305_core_blocks()` takes 16-byte block count `nblocks` and `poly1305_core_emit()` / `poly1305_emit_64()` takes `(state, nonce, dst)`. Pass unshifted `padbit`/`hibit = 1` for full blocks in `poly1305_update`, and `0` in `poly1305_final` for a partial block with `0x01` appended. [F32, F67, F130]
- Unlike `mpi_alloc`, `mpi_copy`, `mpi_read_raw_data`, and `mpi_read_raw_from_sgl` (which return `NULL` on error), `mpi_read_from_buffer` returns an `ERR_PTR` and never `NULL`. Its `*ret_nread` is an in-out length: verify `*ret_nread >= 2` before reading the header, verify `nbits <= MAX_EXTERN_MPI_BITS` and `DIV_ROUND_UP(nbits, 8) + 2 <= *ret_nread` before `mpi_read_raw_data`, and write `nbytes + 2` to `*ret_nread` only on success. [F18, F25, F52]
- `mpi_read_raw_data` and `mpi_read_raw_from_sgl` must strip leading zero bytes before computing `nbits = nbytes * 8`, checking `nbits > MAX_EXTERN_MPI_BITS`, and computing `nlimbs = DIV_ROUND_UP(nbytes, BYTES_PER_MPI_LIMB)` (likewise `DIV_ROUND_UP(nbits, 8)` in `mpi_read_from_buffer`). In `mpi_read_buffer`, `mpi_get_buffer`, and `mpi_write_to_sgl`, `sign` is optional (`if (sign)`), while `nbytes` is required. [F23, F51, F93]
- `mpi_tdiv_qr` accepts `quot == NULL` (`mpi_tdiv_r`): guard all `quot` accesses with `if (quot)`, and when `quot == NULL` and `dsize > 1`, allocate `nsize + 1` limbs in `rem` and write quotient limbs at `qp = rp + dsize`. [F22]
- `mpihelp_add` and `mpihelp_sub` require `s1_size >= s2_size`; `mpihelp_mul` and `mpihelp_mul_karatsuba_case` require `usize >= vsize` and `prodp` disjoint from `up`/`vp`; `mpihelp_add_n`, `mpihelp_sub_n`, `mpihelp_mul_1`, `mpihelp_addmul_1`, and `mpihelp_submul_1` require limb count `>= 1`. [F30, F57]
- `mpihelp_lshift` and `mpihelp_rshift` require `0 < cnt < BITS_PER_MPI_LIMB` and `usize > 0` (in `mpi_rshift`, guard `mpihelp_rshift` with `nbits != 0`). When overlapping, `mpihelp_lshift` requires `wp >= up` and `mpihelp_rshift` requires `wp <= up`. [F74, F90, F100]
- `mpihelp_divrem(qp, qextra_limbs, np, nsize, dp, dsize)` requires `nsize >= dsize >= 1`, MSB of `dp[dsize - 1]` set, and `qp` either disjoint from `np`/`dp` or `qp + dsize >= np` with `np` sized for `dsize` remainder limbs plus `nsize - dsize + qextra_limbs` quotient limbs. `udiv_qrnnd(q, r, nh, nl, d)` requires `nh < d` (and MSB of `d` set when `UDIV_NEEDS_NORMALIZATION` or `UDIV_QRNND_PREINV` is used). [F60, F101, F128]
- Arch init contracts: SPARC `*_mod_init_arch` must check `sparc64_elf_hwcap & HWCAP_SPARC_CRYPTO` before reading `%asr26` and check `CFR_*`; s390 `sha*_mod_init_arch` must check `S390_CPU_FEATURE_MSA` and `cpacf_query_func(CPACF_KIMD, CPACF_KIMD_SHA_*)`; RISC-V `*_mod_init_arch` must check `riscv_vector_vlen() >= 128` and `riscv_isa_extension_available`, and callers must check the static key and `may_use_simd()`/`crypto_simd_usable()`. [F110, F111, F112, F123]
- Arch ChaCha and MIPS COP2: `chacha_p10le_8x`, `chacha20_vx` (s390: requires `kernel_fpu_begin`/`end` with `KERNEL_VXR`, `bytes > CHACHA_BLOCK_SIZE`, `nrounds == 20`, `cpu_has_vx()`, and `state->x[12] += round_up(bytes, CHACHA_BLOCK_SIZE) / CHACHA_BLOCK_SIZE`), and `chacha_zvkb` (RISC-V: takes `(state, in, out, nblocks, nrounds)`) require valid block multiples and `state->x[12]`/tail handling. On MIPS Octeon, write block dwords `0..6`/`0..14` via `write_octeon_64bit_block_*` before calling `octeon_*_start()`. [F69, F108, F116, F124]

## Error Handling
- Check all MPI limb allocations/resizes (`mpi_resize`, `RESIZE_IF_NEEDED`, `mpi_copy`, `mpi_alloc_limb_space`, `mpihelp_mul`) and propagate `-ENOMEM`. In `mpi_mul`, initialize `int err = 0;` at declaration for fast paths bypassing `mpi_resize`/`mpihelp_mul`. [F19, F20]
- In `mpi_powm`, check `if (!bsize)` *after* the `if (bsize > msize)` modular reduction so a base that is a multiple of `mod` exits early with `res->nlimbs = 0`. [F75]
- `mpi_write_to_sgl` and `mpi_read_raw_from_sgl` must check `sg_nents_for_len(sgl, nbytes) < 0` before `sg_miter_start`. `mpi_read_buffer` strips `count_lzeros(a)` leading zero bytes and must set `*nbytes = n - lzeros` (and `*sign` if non-NULL) before returning `-EOVERFLOW` when `buf_len < n - lzeros`, whereas `mpi_write_to_sgl` requires `nbytes >= mpi_get_size(a)` or returns `-EOVERFLOW`. [F53, F54, F136]

## Known Pitfalls
- In `mpi_add` and `mpi_tdiv_qr`, load limb pointers (`->d`) only after all `RESIZE_IF_NEEDED` and `mpi_resize` calls complete, in case an input aliases the resized destination. [F37]
- In `mpi_tdiv_qr`, when `qsize <= 0`, copy `num` to `rem` before zeroing `quot->nlimbs` and `quot->sign` in case `quot == num`; for multi-limb division, copy `np` to temp space when `quot && qp == np`, and copy `dp` when `normalization_steps != 0` or `dp == rp || (quot && dp == qp)`. In `mpi_fdiv_r`, sample `divisor->sign` and `mpi_copy` `divisor` when `rem == divisor` before calling `mpi_tdiv_r`. [F40, F41, F85]
- In `mpi_powm`, the loop swaps `rp` and `xp`, so afterward `rp` must be copied or shifted into `res->d` (and `rp` reset to `res->d`) before normalization. [F81]
- In `mpi_set_bit`, when `limbno >= a->nlimbs`, zero `a->d[a->nlimbs .. a->alloced - 1]` before `mpi_resize(a, limbno + 1)`. In `mpi_test_bit` and `mpi_set_bit`, shift `A_LIMB_1` (`(mpi_limb_t)1`), not `1`/`1U`. [F89, F103]
- In `mpihelp_add_1` and `mpihelp_sub_1`, `s1_ptr` and `res_ptr` are post-incremented before `--s1_size`, so at `leave:` copy `s1_size - 1` limbs. In `mpihelp_cmp`, return `(op1_word > op2_word) ? 1 : -1`, not `op1_word - op2_word`. [F77, F95]
- In `mpihelp_divrem`, stop quotient-refinement loops when `r += d1` (or `r += dX`) wraps (`r < d1`/`dX`), and in `case 2:` when `n1 == d1` and `r < d1`, write `qp[i] = q` and update `(n1, n0)` before `continue`. In `mpihelp_mod_1` and `mpihelp_divmod_1`, when `!(divisor_limb << 1)`, set `divisor_limb_inverted = ~(mpi_limb_t)0` instead of calling `udiv_qrnnd`. [F82, F92]
- In `mpi_read_raw_data` and `mpi_read_raw_from_sgl`, subtract `(BITS_PER_LONG - 8)` from `count_leading_zeros(...)` on the leading `u8`, and pre-offset the byte position by `(BYTES_PER_MPI_LIMB - nbytes % BYTES_PER_MPI_LIMB) % BYTES_PER_MPI_LIMB` to fill `val->d[nlimbs - 1]` first. In `mpi_read_raw_data` and `mpi_read_buffer`, reset the intra-limb offset (`i` or `lzeros`) to `0` at the end of the outer loop body so lower limbs process full limbs. [F55, F80, F94]
- In `mpi_read_raw_from_sgl`, pass 1 must subtract `lzeros` from `nbytes` and reset `lzeros = 0` per zero segment, then set `miter.consumed = lzeros` before `sg_miter_stop(&miter)`; pass 2 must initialize `a`, `j`, and `z` before `while (sg_miter_next(&miter))` and preserve them across segments, resetting `a = 0` only when `((z + x + 1) % BYTES_PER_MPI_LIMB) == 0` and advancing `z += x`. [F78, F79]
- In `poly1305-donna32.c`, cast `h0`..`h4` to `u64` before multiplying by `r0`..`r4`/`s1`..`s4` or adding `nonce[0..3]`. In `poly1305-donna64.c`, cast `u32 hibit` to `u64` before `<< 40`, widen `u64` limbs to `u128` before multiplying, and cast `nonce[1]`/`nonce[3]` to `u64` before `<< 32`. [F86, F87]
- In `lib/crypto/memneq.c`, follow every XOR accumulation into `neq` with `OPTIMIZER_HIDE_VAR(neq)`. In `mips/sha1.h`, access `state->h[4]` via the `hash_tail` union, not `((u64 *)state->h)[2]`. In `powerpc/curve25519.h`, `fe51_frombytes` must stage the 32-byte input through `PTR_ALIGN((void *)sbuf, 8)` before calling `x25519_fe51_frombytes`. [F106, F109, F127]
