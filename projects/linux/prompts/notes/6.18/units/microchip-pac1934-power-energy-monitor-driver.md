# MICROCHIP PAC1934 POWER/ENERGY MONITOR DRIVER

This Industrial I/O (IIO) ADC driver supports the Microchip PAC1931, PAC1932, PAC1933, and PAC1934 multi-channel DC power and energy monitors over I2C/SMBus. It parses channel configurations (shunt resistors, bipolar settings, labels, and sampling rates) from ACPI (`_DSM`) or Device Tree/fwnode properties, dynamically registers per-channel IIO channels and custom sysfs shunt-resistor attributes, and maintains a periodic delayed work item (`work_chip_rfsh`) alongside on-demand register snapshots to accumulate 48-bit hardware power measurements into 64-bit energy totals before saturation.

## Architecture & Data Flow

- Because `pac1934_chip_configure()` clears `PAC1934_SMBUS_NO_SKIP_MASK`, the 76-byte `meas_regs` readout via `pac1934_i2c_read()` omits hardware-disabled channels (`(ctrl_regs_tmp << cnt) & 0x80` from `ctrl_regs[PAC1934_CHANNEL_DIS_LAT_REG_OFF]`). `pac1934_reg_snapshot()` must advance `offset_reg_data_p` for every hardware-enabled channel—including advancing by `PAC1934_VPOWER_ACC_REG_LEN` even when `info->enable_energy[cnt]` is false. Broken by: using fixed offsets, testing `info->active_channels[cnt]`, or skipping `offset_reg_data_p` advancement when `!info->enable_energy[cnt]`. [F22, F59]
- Because `reg_data->meas_regs` starts with the 3-byte `ACC_COUNT` register (`PAC1934_ACC_REG_LEN`), `pac1934_reg_snapshot()` must read subsequent fields with unaligned big-endian helpers (`get_unaligned_be48`, `get_unaligned_be16`, and `get_unaligned_be32` >> 4) and sign-extend from bit 47, 15, or 27 (`sign_extend32(tmp, 27)`) when `info->bi_dir[cnt]` is true. [F34]
- In `pac1934_send_refresh()`, when `info->chip_revision` is 2 or 3, sending `refresh_cmd` must be preceded and followed by writing `bidir_reg` (derived from `info->bi_dir[0..3]`) to `PAC1934_CTRL_STAT_REGS_ADDR + PAC1934_NEG_PWR_REG_OFF`, and `info->tstamp` must be updated to `jiffies` before waiting `wait_time`. Broken by: sending `REFRESH` or `REFRESH_V` directly via `i2c_smbus_write_byte()` at runtime. [F24]
- After writing a new sample rate to `PAC1934_CTRL_REG_ADDR` in `pac1934_write_raw()`, `info->tstamp` must be rewound by `msecs_to_jiffies(PAC1934_MIN_POLLING_TIME_MS)` before calling `pac1934_retrieve_data()` so a `REFRESH` snapshot latches the new rate, scales prior `vpower_acc` with the old latched rate, and updates `tstamp`. [F20]
- When `pac1934_retrieve_data()` triggers a hardware refresh and snapshot via `pac1934_reg_snapshot()`, it must also reset the periodic refresh timer via `mod_delayed_work(system_wq, &info->work_chip_rfsh, msecs_to_jiffies(PAC1934_MAX_RFSH_LIMIT_MS))`. [F23]
- Cache expiration of `info->chip_reg_data` in `pac1934_retrieve_data()` must be checked with `time_after(jiffies, info->tstamp + msecs_to_jiffies(PAC1934_MIN_POLLING_TIME_MS))` rather than `<` or `>` to handle `jiffies` wrap-around. [F48]
- When disabling a channel's energy accumulation (`!val` for `IIO_CHAN_INFO_ENABLE` in `pac1934_write_raw()`), `info->chip_reg_data.energy_sec_acc[chan->channel - 1]` must be reset to `0` alongside setting `info->enable_energy[chan->channel - 1] = false` under `info->lock`. [F21]
- In `pac1934_probe()`, all elements of `info->enable_energy` must be initialized to `true` before the initial `pac1934_reg_snapshot()` call so that energy accumulation is active on every channel from startup. [F14]
- Right-shifting the `u8` control register bytes `ctrl_regs[PAC1934_CTRL_LAT_REG_OFF]` or `regs[PAC1934_CTRL_ACT_REG_OFF]` by 6 (`PAC1934_SAMPLE_RATE_SHIFT`) bounds the index into `samp_rate_map_tbl` to `0..3`, guaranteeing non-zero power-of-two sample rates (`8, 64, 256, 1024`) and a `get_count_order()` shift exponent in `{3, 6, 8, 10}`. Broken by: indexing `samp_rate_map_tbl` with an unmasked/wider integer or adding non-power-of-two or zero entries. [F45]
- In `pac1934_fw_parse_channel_config()`, the child-node `"reg"` property is 1-based (`1..4`); it must be decremented (`idx--`) and checked against `0 <= idx < info->phys_channels` before indexing `info->active_channels`, `info->shunts`, `info->labels`, or `info->bi_dir`, whereas `current_channel` only counts visited child nodes and must never be used as an array index. [F32, F42]
- In `pac1934_acpi_parse_channel_config()`, whenever `info->shunts[idx]` is populated from ACPI `_DSM` function 1 (`PAC1934_ACPI_GET_NAMES_AND_MOHMS_VALS`) or overwritten by function 2 (`PAC1934_ACPI_GET_UOHMS_VALS`), `info->active_channels[idx]` must be updated in lockstep to `(info->shunts[idx] != 0)`. [F29]
- In `pac1934_read_label()` and the `IIO_CHAN_INFO_SCALE` branch of `pac1934_read_raw()`, `switch (chan->address)` must include all four per-channel register addresses (`_1_ADDR` through `_4_ADDR`) for each register type because `pac1934_prep_iio_channels()` offsets `ch_sp[...].address` by the physical channel index `cnt`. [F41]
- Although the custom sysfs attributes `in_shunt_resistor1` through `in_shunt_resistor4` use 1-based names, their `IIO_DEVICE_ATTR` declarations must pass 0-based addresses `0..3` because `pac1934_shunt_value_show()` and `pac1934_shunt_value_store()` use `this_attr->address` directly to index `info->shunts`. [F37]
- `pac1934_prep_iio_channels()` must set `scan_type.sign` to `'s'` on every `iio_chan_spec` belonging to a bidirectional physical channel (`info->bi_dir[cnt]` is true), because `pac1934_read_raw()` inspects `chan->scan_type.sign == 'u'` rather than `info->bi_dir` to select unidirectional vs. bidirectional `IIO_CHAN_INFO_SCALE` factors. [F70]
- The element order of `pac1934_single_channel` must match `enum pac1934_ch_idx` (`PAC1934_CH_ENERGY` through `PAC1934_CH_CURRENT_AVERAGE`), because `pac1934_prep_iio_channels()` copies `pac1934_single_channel` with `memcpy` and patches per-channel descriptors by indexing `ch_sp` with `enum pac1934_ch_idx`. [F50]
- In `pac1934_id`, `pac1934_of_match`, and `pac1934_acpi_match`, `.driver_data` and `.data` must store a pointer to a `struct pac1934_features` entry in `pac1934_chip_config` rather than an integer `enum pac1934_ids` constant. [F54]

## Synchronization

- Callers of `pac1934_reg_snapshot()` and `pac1934_retrieve_data()` (including `pac1934_write_raw()`, `pac1934_read_raw()`, `pac1934_work_periodic_rfsh()`, and `pac1934_probe()`) must not hold `info->lock`, because `pac1934_reg_snapshot()` acquires `info->lock` via `guard(mutex)(&info->lock)`. [F3]
- `cancel_delayed_work_sync(&info->work_chip_rfsh)` (used in `pac1934_cancel_delayed_work()`) must never be called while holding `info->lock`, because `pac1934_work_periodic_rfsh()` acquires `info->lock` inside `pac1934_reg_snapshot()`. [F66]

## Object Lifetimes

- In `pac1934_probe()`, `devm_mutex_init(&info->lock)`, `info->client`, `info->phys_channels`, `info->chip_revision`, `info->bi_dir`, and `info->enable_energy` must be initialized before `pac1934_chip_configure()` (which schedules `info->work_chip_rfsh` and registers `pac1934_cancel_delayed_work()` via `devm_add_action_or_reset()`), and `pac1934_chip_configure()` must run before `devm_iio_device_register()` so devres teardown unregisters the IIO device before canceling the work and destroying the mutex. [F1, F7]
- `pac1934_probe()` must execute an initial `pac1934_reg_snapshot()` with `do_refresh = true` before calling `devm_iio_device_register()` so that `info->tstamp` and `info->chip_reg_data` are populated before `pac1934_read_raw()` can be invoked. [F9]
- `pac1934_prep_iio_channels()` and `pac1934_probe()` must copy the `const` templates `pac1934_single_channel` and `pac1934_info` into per-device allocations (`dyn_ch_struct` and `info->iio_info`) before mutating them; specifically, `indio_dev->info` must point to `info->iio_info` before `pac1934_prep_custom_attributes()` sets `info->iio_info.attrs` and before `devm_iio_device_register()` runs. [F4, F62]
- In `pac1934_acpi_parse_channel_config()`, every non-NULL `union acpi_object *rez` returned by `acpi_evaluate_dsm()` must be freed with `ACPI_FREE(rez)` before `rez` is reassigned or the function returns, and any string data in `rez` needed later (such as `info->labels[idx]`) must be copied via `devm_kmemdup()` before `ACPI_FREE(rez)`. [F2]

## API Contracts

- `pac1934_prep_iio_channels()` sets `scan_index = cnt` (`0..3`), `.channel = cnt + 1` (`1..4`) for instantaneous channels, and `cnt + 5` (`5..8`) for `PAC1934_CH_VOLTAGE_AVERAGE` and `PAC1934_CH_CURRENT_AVERAGE` (avoiding `-EBUSY` on duplicate sysfs `scale`/`label` names); thus `pac1934_read_label()` must index `info->labels` with `chan->scan_index`, `pac1934_read_raw()` must map `chan->channel` to `0..3` via `- 1` (and `- PAC1934_MAX_NUM_CHANNELS` for average channels), and `pac1934_write_raw()` (`chan->channel - 1`) requires `IIO_CHAN_INFO_ENABLE` only on channels 1..4. [F16, F31, F68, F71]
- Control registers at `PAC1934_CTRL_STAT_REGS_ADDR`, `NEG_PWR`, and `PAC1934_SLOW_REG_ADDR` (`0x20`) must be written individually via `i2c_smbus_write_byte_data()` rather than `i2c_smbus_write_block_data()` or offset `PAC1934_SLOW_REG_OFF` (`0x1E`), because the chip lacks SMBus block write support and skips `0x1E`–`0x1F` only on multi-byte accesses. [F56]
- `pac1934_send_refresh()` must only be called with a command-only refresh register address (`PAC1934_REFRESH_REG_ADDR` or `PAC1934_REFRESH_V_REG_ADDR`) because it sends a single-byte SMBus command via `i2c_smbus_write_byte(client, refresh_cmd)`, and its `wait_time` parameter (and that of `pac1934_reg_snapshot()` / `pac1934_retrieve_data()`) must be in microseconds for `usleep_range()`. [F17]
- When issuing a refresh after updating `PAC1934_CTRL_REG_ADDR` in `pac1934_chip_configure()` or `pac1934_write_raw()`, the post-refresh delay (`wait_time`) must be computed from the previously active sampling rate (`regs[PAC1934_CTRL_ACT_REG_OFF]` or `old_samp_rate`) as `(1024 / samp_rate) * 1000` microseconds rather than from the newly written rate. [F58]
- `pac1934_reg_snapshot()` and `pac1934_send_refresh()` (and `pac1934_retrieve_data()`) may only be invoked from sleepable process context because they acquire `info->lock`, perform blocking I2C/SMBus transfers, and sleep via `usleep_range()`. [F67]
- `info->shunts` stores shunt resistances in micro-ohms, so `pac1934_acpi_parse_channel_config()` must multiply the milli-ohm values from `_DSM` function `PAC1934_ACPI_GET_NAMES_AND_MOHMS_VALS` by `1000` while storing micro-ohm values from `PAC1934_ACPI_GET_UOHMS_VALS` and DT `"shunt-resistor-micro-ohms"` unscaled. [F18]
- `pac1934_cancel_delayed_work()` passes its untyped `void *dwork` parameter directly to `cancel_delayed_work_sync()`, so `devm_add_action_or_reset()` in `pac1934_chip_configure()` must pass `&info->work_chip_rfsh` rather than `info` or `&info->work_chip_rfsh.work`. [F52]
- When `pac1934_read_raw()` returns `IIO_VAL_INT_64` for `IIO_ENERGY`, it must place the lower 32 bits of the 64-bit `curr_energy` value in `*val` and the upper 32 bits in `*val2` to match `__iio_format_value()`. [F75]

## Error Handling

- `i2c_smbus_read_i2c_block_data()` and `i2c_transfer()` return a positive byte or message count on success and a negative errno on failure, so `pac1934_i2c_read()`, `pac1934_read_revision()`, `pac1934_reg_snapshot()`, and `pac1934_chip_configure()` must check `ret < 0` rather than `if (ret)` and normalize helper return values to `0`. [F12]
- `pac1934_chip_identify()` returns a non-negative `enum pac1934_ids` index (`0..3`) on success and a negative errno on failure, and `pac1934_get_samp_rate_idx()` returns a non-negative `samp_rate_map_tbl` index (`0..3`) on match and `-EINVAL` when not found; callers (`pac1934_probe()`, `pac1934_write_raw()`) must store the result in a signed `int` and check `ret < 0` rather than `if (ret)`. [F10, F11]
- In `pac1934_acpi_parse_channel_config()`, a `NULL` return from `acpi_evaluate_dsm()` for `PAC1934_ACPI_GET_UOHMS_VALS` is a valid fallback path that sets `info->sample_rate_value = PAC1934_DEFAULT_CHIP_SAMP_SPEED_HZ` and returns `0`, whereas `NULL` from functions 1, 4, or 5 must return `-EINVAL`. [F13]

## External Contracts

- In `pac1934_read_raw()`, `IIO_CHAN_INFO_SCALE` for bipolar channels (`chan->scan_type.sign != 'u'`) must halve the scale denominator by right-shifting `info->shunts[channel]` by 1 for `VSENSE`, `VSENSE_AVG`, `VPOWER`, and `VPOWER_ACC`, and use `PAC1934_VOLTAGE_S_RES` (`15`) instead of `PAC1934_VOLTAGE_U_RES` (`16`) for `VBUS` and `VBUS_AVG`. [F47]

## Known Pitfalls

- In `pac1934_prep_iio_channels()`, `tmp_data` is a `void *` cursor into `dyn_ch_struct` that advances by `sizeof(pac1934_single_channel)` bytes per active channel while `indio_dev->num_channels` is set to the `struct iio_chan_spec` element count (`attribute_count`) accumulated via `ARRAY_SIZE(pac1934_single_channel)`. Broken by: changing `tmp_data` to `struct iio_chan_spec *` while still advancing by `sizeof(pac1934_single_channel)`, or assigning `channel_size` to `indio_dev->num_channels`. [F49]
- Although `info->labels` is typed as `char *labels[PAC1934_MAX_NUM_CHANNELS]`, `pac1934_fw_parse_channel_config()` populates it via `fwnode_property_read_string()` by casting `&info->labels[idx]` to `const char **`, so `info->labels` entries must be treated as read-only and never mutated or freed with `kfree()` after probe. [F55]
