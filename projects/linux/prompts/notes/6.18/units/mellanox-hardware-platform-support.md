# MELLANOX HARDWARE PLATFORM SUPPORT

`drivers/platform/mellanox` provides platform drivers for NVIDIA/Mellanox switch systems, DPUs, and BlueField SoCs, covering CPLD/FPGA register mapping and sub-device instantiation (`mlx-platform`, `mlxreg-dpu`), interrupt-driven hotplug management (`mlxreg-hotplug`), and BlueField Virtio console/network over TmFifo (`mlxbf-tmfifo`), SMC boot/manufacturing control (`mlxbf-bootctl`), and performance monitoring counters (`mlxbf-pmc`).

## Architecture & Data Flow

- When `mlxbf_tmfifo_check_tx_timeout()` aborts an in-flight network Tx packet, it must record `round_up(vring->rem_len, sizeof(u64))` in `vring->rem_padding` before zeroing `vring->rem_len`, and `mlxbf_tmfifo_rxtx()` must drain `vring->rem_padding` as zero words to `fifo->tx.data` before starting a new Tx header. [F49]
- `fifo->vdev` in `struct mlxbf_tmfifo` is a sparse array of size `MLXBF_TMFIFO_VDEV_MAX` (`VIRTIO_ID_CONSOLE + 1`) indexed directly by `VIRTIO_ID_NET` (1) and `VIRTIO_ID_CONSOLE` (3); any loop or lookup over `fifo->vdev` must check for `NULL` entries before dereferencing. [F71]
- `item->data` in `mlxreg-hotplug.c` is indexed by the ordinal rank of each set bit in `item->mask`, not the raw bit position `bit`: `mlxreg_hotplug_work_helper()` must translate `bit` via `mlxreg_hotplug_item_label_index_get(item->mask, bit)` and `mlxreg_hotplug_attr_init()` must advance `data` and `k` once per set bit in `item->mask`. [F82]
- In `mlxreg_hotplug_health_work_helper()`, the masked two-bit ASIC health status (`regval &= data->mask`) must be checked for exact equality with `MLXREG_HOTPLUG_GOOD_HEALTH_MASK` (`0x02`) rather than bitwise AND, because `0x03` is the booting state where the device must not be attached. [F77]
- For non-health `struct mlxreg_core_item` entries with `item->inversed` set, `mlxreg_hotplug_set_irq()` must initialize `item->cache` to `item->mask`, `mlxreg_hotplug_work_helper()` must destroy the device when `regval & BIT(bit)` is non-zero and create it when zero, and `mlxreg_hotplug_attr_show()` must invert `regval & data->mask`. [F78]
- `mlxreg_dpu_copy_hotplug_data()` must deep-copy `hotplug_data`, `hotplug_data->items`, and each `hotplug_data->items[i].data` array into `mlxreg_dpu->hotplug_data` before registering `"mlxreg-hotplug"`, because the hotplug driver mutates `item->mask`, `item->cache`, and `data` in place per DPU instance. [F87]
- When `mlxplat_mlxcpld_verify_bus_topology()` shifts each mux's `parent` and `base_nr` by a positive `shift` because the default parent I2C adapter number is occupied, it must also set `mlxplat_hotplug->shift_nr = shift` so `mlxreg_hotplug_device_create()` resolves `data->hpdev.nr` with `pdata->shift_nr`. [F55]
- In `mlxbf-pmc.c`, `mlxbf_pmc_program_l3_counter()` and `mlxbf_pmc_program_crspace_counter()` must read-modify-write the shared selection register to preserve sibling counter bitfields (disabling L3 counters first via `mlxbf_pmc_config_l3_counters()`). For `MLXBF_PMC_TYPE_CRSPACE`, two counters share each 4-byte register at offset `(cnt_num / 2) * MLXBF_PMC_CRSPACE_PERFSEL_SZ` (even `cnt_num` in `MLXBF_PMC_CRSPACE_PERFSEL0`, odd in `MLXBF_PMC_CRSPACE_PERFSEL1`). [F57, F62]
- Every `struct attribute *` in `pmc->block[blk_num].block_attr[]` must be `.dev_attr.attr` of a `struct mlxbf_pmc_attribute` with `.nr = blk_num`, because all `mlxbf_pmc_*_show()` and `mlxbf_pmc_*_store()` callbacks use `container_of(attr, struct mlxbf_pmc_attribute, dev_attr)`. [F101]
- In `lifecycle_state_show()`, `status_bits` must be masked with `MLXBF_BOOTCTL_SB_SECURE_MASK` before indexing `mlxbf_bootctl_lifecycle_states[]`, and `test_state` (`MLXBF_BOOTCTL_SB_TEST_MASK`) must be checked before the `use_dev_key` (`MLXBF_BOOTCTL_SB_DEV_MASK`) and `MLXBF_BOOTCTL_SB_LIFECYCLE_GA_SECURE` branch. [F76]

## Synchronization

- In `struct mlxbf_tmfifo`, `fifo->lock` serializes `fifo->vdev[]` lifecycle in `mlxbf_tmfifo_create_vdev()` and `mlxbf_tmfifo_delete_vdev()` against `mlxbf_tmfifo_work_handler()` and may nest outside `fifo->spin_lock[0..1]`, never inside them. Rx `vring_interrupt()` notifications must lock `fifo->spin_lock[1]`, while Tx notifications and console `cons->tx_buf` accesses in `mlxbf_tmfifo_console_output()` and `mlxbf_tmfifo_console_tx()` must use `spin_lock_irqsave(&fifo->spin_lock[0], flags)`. [F16, F18, F119]
- In `mlxbf-tmfifo.c`, `mlxbf_tmfifo_get_next_desc()` must execute `virtio_rmb(false)` after reading `vr->avail->idx` and before reading `vr->avail->ring[idx]` and `vr->desc[head]`. In `mlxbf_tmfifo_release_desc()`, `vr->used->ring[idx]` must be populated and followed by `virtio_mb(false)` before updating `vr->used->idx`, and callers must execute `virtio_mb(false)` and acquire `fifo->spin_lock[is_rx]` before calling `vring_interrupt()`. [F13, F133]
- In `mlxbf_tmfifo_virtio_find_vqs()`, `vq->num_max` and `vq->priv` must be set and ordered by `virtio_mb(false)` before assigning `vring->vq = vq`; `mlxbf_tmfifo_create_vdev()` must allocate `tx_buf.buf` and set `fifo->vdev[vdev_id]` before `register_virtio_device()`; and `mlxbf_tmfifo_probe()` must set `fifo->is_ready = true` only after `virtio_mb(false)` following vdev creation and timer setup, with `mlxbf_tmfifo_work_handler()` checking `fifo->is_ready` before locking `fifo->lock`. [F19, F20]
- In `mlxbf_tmfifo_work_rxtx()`, `test_and_clear_bit(irq_id, &fifo->pend_events)` must execute before iterating over `fifo->vdev[]` and calling `mlxbf_tmfifo_rxtx()`. [F22]
- When `mlxreg_hotplug_work_handler()` processes non-zero `aggr_asserted` bits while the top aggregation interrupt is masked, it must cancel and immediately reschedule `priv->dwork_irq` under `spin_lock_irqsave(&priv->lock, flags)`. On a pass where `aggr_asserted` is zero, if `priv->not_asserted` reaches `MLXREG_HOTPLUG_NOT_ASSERT` (3), it must force `aggr_asserted = pdata->mask` and reset `priv->not_asserted = 0` before unmasking `pdata->cell + MLXREG_HOTPLUG_AGGR_MASK_OFF`. [F24, F106]
- In `mlxplat_i2c_main_init()`, `mlxplat_i2c->regmap` and `mlxplat_i2c->handle` must be set before registering `"i2c_mlxcpld"`, and `mlxplat_i2c_mux_topology_init()` must defer initialization by setting `priv->i2c_main_init_status = MLXPLAT_I2C_MAIN_BUS_NOTIFIED` if invoked via `completion_notify` while `priv->pdev_i2c` is still `NULL`. [F28]
- In `mlxbf-bootctl.c`, `rsh_log_store()` must acquire the hardware RShim semaphore via `mlxbf_rsh_log_sem_lock()` before accessing `mlxbf_rsh_scratch_buf_ctl` or `mlxbf_rsh_scratch_buf_data` and release it via `mlxbf_rsh_log_sem_unlock()` on every exit path. All sysfs handlers invoking `MLXBF_BOOTCTL_GET_MFG_INFO`, `MLXBF_BOOTCTL_SET_MFG_INFO`, or `MLXBF_BOOTCTL_LOCK_MFG_INFO` SMCs must hold `mfg_ops_lock` across the entire operation, including the full multi-qword loop. [F29, F30]

## Object Lifetimes

- `mlxbf_tmfifo_cleanup()` must clear `fifo->is_ready`, synchronously stop `fifo->timer` (`timer_delete_sync`), disable all IRQs (`mlxbf_tmfifo_disable_irqs`), and drain `fifo->work` (`cancel_work_sync`) outside `fifo->lock` before calling `mlxbf_tmfifo_delete_vdev()`. [F21]
- Because `mlxbf_tmfifo_rxtx_header()` sets `fifo->vring[is_rx] = vring` for an active packet, both `mlxbf_tmfifo_rxtx_one_desc()` on completion and `mlxbf_tmfifo_check_tx_timeout()` on timeout must clear `fifo->vring[is_rx]` to `NULL` and reset `vring->desc` and `vring->desc_head` via `mlxbf_tmfifo_release_pkt()`. [F8]
- In `mlxreg_hotplug_probe()`, `priv->irq` must be disabled via `disable_irq(priv->irq)` immediately after `devm_request_irq()`, and `priv->lock`, `priv->dwork_irq`, and `priv->hwmon` must be initialized before `mlxreg_hotplug_set_irq()` runs `mlxreg_hotplug_work_handler()` and calls `enable_irq(priv->irq)`. In `mlxreg_hotplug_unset_irq()`, `disable_irq(priv->irq)` and `cancel_delayed_work_sync(&priv->dwork_irq)` must run in that order before masking hardware events, calling `mlxreg_hotplug_device_destroy()`, freeing `priv->irq`, or unregistering `priv->hwmon`. [F23, F25]
- For `MLXREG_HOTPLUG_DEVICE_DEFAULT_ACTION`, `mlxreg_hotplug_device_create()` must call `i2c_put_adapter()` and set `data->hpdev.adapter = NULL` if `i2c_new_client_device()` fails, and `mlxreg_hotplug_device_destroy()` must clear both `data->hpdev.client` and `data->hpdev.adapter` to `NULL` after releasing them. [F3]
- In `mlxreg_dpu_probe()`, every error path after `i2c_get_adapter()` must release `data->hpdev.adapter` via `i2c_put_adapter()`, and every error path after `i2c_new_client_device()` must first call `i2c_unregister_device(data->hpdev.client)` while preserving `err`. `mlxreg_dpu_config_init()` registers `io_regs` before `hotplug` (unwinding `io_regs` if `hotplug` fails), and `mlxreg_dpu_remove()` must call `mlxreg_dpu_config_exit()` (unregistering `hotplug` before `io_regs`) before `i2c_unregister_device(data->hpdev.client)`. [F1, F2, F27]
- `mlxplat_i2c_main_exit()` must unregister child platform devices (`mlxplat_platdevs_exit()`) before I2C muxes (`mlxplat_i2c_mux_topology_exit()`) and `priv->pdev_i2c`, and both `mlxplat_probe()` error paths and `mlxplat_remove()` must call `mlxplat_i2c_main_exit()` before `mlxplat_logicdev_exit()`. [F11]

## API Contracts

- In `mlxbf-pmc.c`, when `pmc->svc_sreg_support` is true, `pmc->block[i].mmio_base` holds an unmapped physical address cast to `void __iomem *`, so all register accesses must go through `mlxbf_pmc_read()`, `mlxbf_pmc_readl()`, or `mlxbf_pmc_write()`. In `mlxbf_pmc_secure_read()`, the register address is passed in SMC `a2` (`arm_smccc_smc(command, pmc->sreg_tbl_perf, (uintptr_t)addr, ...)`), whereas `mlxbf_pmc_secure_write()` passes `value` in `a2` and `(uintptr_t)addr` in `a3`. [F34, F36]
- In `mlxbf_pmc_read_reg()` and `mlxbf_pmc_write_reg()`, `"ecc"` and `"clock_measure"` blocks must use 32-bit accesses (with `"clock_measure"` rejecting writes with `-EINVAL`), whereas other `MLXBF_PMC_TYPE_REGISTER` blocks require `mlxbf_pmc_valid_range()` and 64-bit accesses. In `mlxbf_pmc_counter_store()`, non-zero writes must be rejected with `-EINVAL` unless `pmc->block_name[blk_num]` contains `"ecc"`, and all writes must be rejected with `-EINVAL` for `"l3cache"`. [F81, F114]
- Virtio descriptor and ring fields in `mlxbf-tmfifo.c` (`vring_desc`, `vring_avail`, `vring_used`, including `vring->drop_desc.len`) must use `cpu_to_virtio16()`/`cpu_to_virtio32()` and `virtio16_to_cpu()`/`virtio32_to_cpu()`/`virtio64_to_cpu()`. Because `MLXBF_TMFIFO_NET_FEATURES` omits `VIRTIO_F_VERSION_1`, `tm_vdev->config.net` (`mtu`, `status`) must use `virtio_legacy_is_little_endian()` with `__cpu_to_virtio16()` and `__virtio16_to_cpu()`. [F68, F131]
- In `mlxreg-hotplug.c`, an item's `item->capability` register masked by `item->mask` is a component count converted via `GENMASK((regval & item->mask) - 1, 0)`, whereas an attribute's `data->capability` register is tested directly against the bitmask `data->bit` (`regval & data->bit`). [F46]
- In `mlxreg_hotplug_device_create()`, negative adapter numbers (`data->hpdev.nr < 0`) must only return early when `data->hpdev.action != MLXREG_HOTPLUG_DEVICE_NO_ACTION`, so event-only items with `MLXREG_HOTPLUG_DEVICE_NO_ACTION` still invoke `data->hpdev.notifier->user_handler`. Whenever `data->hpdev.brdinfo->platform_data` is non-NULL, it must point to a writable `struct mlxreg_core_hotplug_platform_data` because `mlxreg_hotplug_pdata_export()` casts it and writes `dev_pdata->regmap`. [F80, F97]
- In `rsh_log_store()` (`mlxbf-bootctl.c`), the message word count `num` must be computed with `DIV_ROUND_UP(size, sizeof(u64))` for both the `MLXBF_RSH_LOG_LEN_MASK` header field and the write loop, and clamped to at most `RSH_SCRATCH_BUF_CTL_IDX_MASK - idx - 1` (where `idx` is read from `mlxbf_rsh_scratch_buf_ctl`) to reserve one slot for the header word. [F66, F90]

## Error Handling

- In `mlxbf-tmfifo.c`, when `mlxbf_tmfifo_rxtx_header()` receives a `VIRTIO_ID_NET` packet with `ntohs(hdr.len) > mtu + MLXBF_TMFIFO_NET_L2_OVERHEAD`, it must release any active `vring->desc_head` via `mlxbf_tmfifo_release_pkt()` and redirect `*desc`, `vring->desc_head`, and `vring->desc` to `&vring->drop_desc`. When `IS_VRING_DROP(vring)` is true (`drop_desc.addr == 0`), `mlxbf_tmfifo_rxtx_word()` and `mlxbf_tmfifo_rxtx_one_desc()` must check `!IS_VRING_DROP(vring)` before writing to `addr`, following `desc->next`, or releasing the packet. [F40, F69]
- On the `vdev_fail` path of `mlxbf_tmfifo_create_vdev()`, `fifo->vdev[vdev_id]` must be reset to `NULL`, freeing `tm_vdev` via `put_device(&tm_vdev->vdev.dev)` if `register_virtio_device()` was called (`reg_dev != NULL`) or via `kfree(tm_vdev)` otherwise. [F41]
- Callers of `mlxbf_pmc_get_event_num()` (`mlxbf_pmc_counter_show()`, `mlxbf_pmc_counter_store()`, `mlxbf_pmc_event_store()`) must store its return value in a signed `int` and check `< 0` before using it. In `mlxbf_pmc_map_counters()`, a `-ENOENT` return from `mlxbf_pmc_create_groups()` must log a warning and continue the loop, whereas any other non-zero return must abort `mlxbf_pmc_map_counters()`. [F31, F33]
- In `mlxbf-bootctl.c`, MFG sysfs `_show()` functions (`opn`, `sku`, `modl`, `sn`, `uuid`, `rev`) must zero-initialize a `u64` buffer of length `MLNX_MFG_VAL_QWORD_CNT(type) + 1`, and `_store()` functions must zero-initialize `u64` buffers of length `MLNX_MFG_VAL_QWORD_CNT(type)` before `memcpy(buf, count)`. When writing a partial trailing 64-bit word (`< sizeof(u64)` bytes) to a FIFO register in `rsh_log_store()` or `mlxbf_tmfifo_rxtx_word()`, the local `u64 data` variable must be zeroed before `memcpy(&data, ...)` and `writeq()`. [F38, F39]

## External Contracts

- For `VIRTIO_ID_NET` packets in `mlxbf-tmfifo.c`, `struct virtio_net_hdr` exists only in the virtio descriptor and never on the TmFifo wire: Rx zeros it via `mlxbf_tmfifo_init_net_desc()` and offsets `cur_len` and `pkt_len` by `sizeof(struct virtio_net_hdr)`, while Tx skips it and subtracts its size from `hdr.len`. [F130]
- In `mlxbf_pmc_event_store()`, a numeric event ID parsed from `buf` must be validated via `mlxbf_pmc_get_event_name()`—and a string event name must have its trailing `'\n'` stripped before `mlxbf_pmc_get_event_num()`—before calling `mlxbf_pmc_program_counter()`. [F59]

## Known Pitfalls

- In `mlxbf_tmfifo_rxtx_header()`, when an Rx packet's `vdev_id` differs from `vring->vdev_id`, `*desc` must be saved to the old `vring->desc` before switching `vring` to `tm_dev2`'s Rx vring, and `mlxbf_tmfifo_rxtx_one_desc()` must return `false` when `vring_change` is true before `mlxbf_tmfifo_desc_done`. [F86]
- In `mlxreg-hotplug.c`, 32-bit bitmasks from `struct mlxreg_core_item` (`item->mask` and `item->cache ^ regval`) must be assigned to an `unsigned long` local variable before passing its address to `for_each_set_bit()`, never cast from `u32 *` to `unsigned long *`. [F93]
- In `mlxbf_pmc_event_list()` and `mlxbf_pmc_map_counters()`, `strstr()` checks for longer block-name prefixes (`"tilenet"`, `"triogen"`, `"llt_miss"`) must precede checks for their shorter substrings (`"tile"`, `"trio"`, `"llt"`). In `mlxplat_dmi_table[]`, entries matching both `DMI_BOARD_NAME` and `DMI_PRODUCT_SKU` must precede board-only `DMI_BOARD_NAME` entries for the same board. [F74, F75]
- Because `mlxreg_hotplug_attr_init()`, `mlxbf_pmc_init_perftype_reg()`, and `mlxbf_pmc_create_groups()` pass `data->label`, `events[count].evt_name`, and `pmc->block_name[blk_num]` directly as the format string argument to `devm_kasprintf()`, those strings must never contain `'%'` characters. [F100]
