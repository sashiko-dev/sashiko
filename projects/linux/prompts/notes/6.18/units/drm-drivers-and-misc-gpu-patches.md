# DRM DRIVERS AND MISC GPU PATCHES

This unit provides core DRM infrastructure for GEM buffer objects and backing-store helpers (shmem, DMA, TTM, VRAM, shadow planes, and LRU), framebuffers, GPU Shared Virtual Memory (GPUSVM) and device-private page migration (`drm_pagemap`), `drm_mm` range allocation, PRIME/DMA-BUF sharing, `drmm_*` managed resources, KMS objects/properties/planes/modes and `ww_mutex` locking, DRM master leasing, output probing and hotplug polling, MIPI DBI/DSI helpers, Device Tree/panel quirks, privacy screens, panic rendering, and IOCTL dispatch.

## Architecture & Data Flow
- In `drm_gem_shmem_mmap()`, `vma->vm_pgoff` must retain the fake VMA offset from `obj->vma_node` so `drm_vma_node_unmap()` in `drm_gem_shmem_purge_locked()` can unmap active VMAs, while `drm_gem_shmem_fault()` must compute `page_offset` from `(vmf->address - vma->vm_start) >> PAGE_SHIFT` rather than `vmf->pgoff`. [F65]
- Every `struct drm_gem_lru` mutation in `drm_gem_lru_remove_locked()`, `drm_gem_lru_move_tail_locked()`, and `drm_gem_lru_scan()` must update `obj->lru`, `obj->lru_node`, and `lru->count` (by `obj->size >> PAGE_SHIFT`) in lockstep under `lru->lock`; a `shrink()` callback returning `true` must have removed `obj` from `still_in_lru`, and any unremoved object must have `obj->lru`, `lru->list`, and `lru->count` restored from `still_in_lru` before unlocking `lru->lock`. [F13, F67]
- In `drm_gpusvm`, interval tree nodes (`notifier->itree`, `range->itree`) store inclusive end addresses in `itree.last` (`ALIGN(fault_addr + 1, size) - 1`), whereas GPUSVM APIs take and return exclusive end addresses (`end - 1` / `itree.last + 1`); `drm_gpusvm_notifier_insert()`/`_remove()` and `drm_gpusvm_range_insert()`/`__drm_gpusvm_range_remove()` must keep the interval tree and companion list synchronized in ascending order via `rb_prev()`. [F70, F104]
- In `drm_gpusvm_get_pages()` and `__drm_gpusvm_unmap_pages()`, loops must advance PFN index `i` by `1 << order` while incrementing `dma_addr` index `j` by 1, and `err_unmap` must pass `num_dma_mapped` (tracking `i`, not `j`) to `__drm_gpusvm_unmap_pages()`; in `drm_pagemap_migrate_map_pages()`, `_unmap_pages()`, and `_populate_ram_pfn()`, each loop must initialize `order = 0` per iteration and advance `i` by `NR_PAGES(order)`. [F119, F320]
- In `drm_mm_reserve_node()`, `drm_mm_insert_node_in_range()`, and `drm_mm_remove_node()`, `node->node_list` must be updated and any existing hole removed via `rm_hole()` before calling `add_hole()`, and zero-sized nodes or ranges where `node->start + node->size <= node->start` must be rejected with `-ENOSPC` before inserting into the inclusive `[START, LAST]` interval tree (`LAST = start + size - 1`). [F280, F308]

## Synchronization
- The global lock hierarchy enforced by `drmm_mode_config_init()` orders `crtc_ww_class` (`drm_modeset_lock`) outer to `mmap_lock` (page faults), and `mmap_lock` outer to `reservation_ww_class` (`dma_resv_lock`). [F384]
- `dev->object_name_lock` protects `obj->handle_count`, `obj->name`, and `dev->object_name_idr`; `drm_gem_handle_create_tail()` requires `dev->object_name_lock` on entry and always unlocks it before returning, reserves the slot in `file_priv->object_idr` with `NULL` (`GFP_NOWAIT`) under spinlock `file_priv->table_lock`, and replaces it with `obj` via `idr_replace()` only after `drm_vma_node_allow()` and `obj->funcs->open()` succeed. `file_priv->prime.lock` (a mutex) must never be acquired inside `file_priv->table_lock`, and in `drm_gem_prime_fd_to_handle()`, if `drm_prime_add_buf_handle()` fails after `drm_gem_handle_create_tail()`, `file_priv->prime.lock` must be unlocked before calling `drm_gem_handle_delete()`. [F4, F24, F28, F188, F223]
- For non-imported `struct drm_gem_shmem_object`, `shmem->base.resv` protects `pages`, `sgt`, `vaddr`, `madv`, and their refcounts across `drm_gem_shmem_get_pages_sgt()`, `drm_gem_shmem_fault()`, and `drm_gem_shmem_purge_locked()`; `drm_gem_vmap()`/`_vunmap()` and `drm_gem_map_attach()`/`_detach()` hold `obj->resv` across `.vmap`, `.vunmap`, `.pin`, and `.unpin` callbacks, so those callbacks must not re-acquire `obj->resv`. [F29, F30, F393]
- When `drm_gem_lock_reservations()` fails after `ww_acquire_init(acquire_ctx, &reservation_ww_class)`, it must unlock `objs[0..i-1]` plus `objs[contended]` when `contended != -1 && contended >= i`, tear down `acquire_ctx` with `ww_acquire_fini()` (not `ww_acquire_done()`), and on `-EDEADLK` set `contended = i` and skip `i == contended` during the retry pass after slow-locking `objs[contended]`. [F12, F116]
- In `drm_gpusvm`, callers of `drm_gpusvm_range_find_or_insert()` and `drm_gpusvm_range_remove()` must hold the driver SVM lock (`drm_gpusvm_driver_lock_held()`); `gpusvm->notifier_lock` protects `notifier->root`, `notifier->range_list`, and `svm_pages` in write mode for MMU invalidation and read mode otherwise (and must be dropped before `GFP_KERNEL` allocations). In `drm_gpusvm_get_pages()`, `map_pages` must hold `notifier_lock` and revalidate `!svm_pages->flags.unmapped` and `!mmu_interval_read_retry()` (including after dropping `notifier_lock` to allocate `dma_addr`), and GPU page-table binding commits must verify `drm_gpusvm_range_pages_valid()` under `notifier_lock`. [F31, F32, F39, F40, F179]
- When `drm_modeset_lock()` returns `-EDEADLK` for a non-NULL `ctx`, it sets `ctx->contended` and callers must call `drm_modeset_backoff(ctx)` before further `drm_modeset_lock()` or `drm_modeset_drop_locks()` calls; in `modeset_lock()`, `-EALREADY` from `ww_mutex_lock*()` must be converted to `0` without re-adding `lock->head` to `ctx->locked`; unlike `drm_modeset_lock_all()`, `drm_modeset_lock_all_ctx()` does not lock `dev->mode_config.mutex`, which callers must acquire outside the `ww_mutex` retry loop. [F228, F229, F322]
- `dev->mode_config.mutex` must be held for `drm_mode_probed_add()`, `drm_connector_list_update()`, and `drm_helper_probe_single_connector_modes()`, whereas `drm_kms_helper_hotplug_event()` and `drm_kms_helper_connector_hotplug_event()` must be called with no modesetting locks held (`output_poll_execute()` must use `mutex_trylock(&dev->mode_config.mutex)` and unlock before sending hotplug events). During poll teardown (`drm_kms_helper_poll_disable()`, `drm_kms_helper_poll_fini()`), `drm_kms_helper_disable_hpd(dev)` must precede `cancel_delayed_work_sync(&dev->mode_config.output_poll_work)` and run only when `poll_enabled` is true; `.detect` callbacks in `output_poll_execute()` must check `drm_kms_helper_is_poll_worker()` to avoid deadlocking on runtime PM. [F252, F254, F255, F380, F391]
- In `draw_panic_plane()`, `get_scanout_buffer`, `panic_flush`, and `drm_scanout_buffer.set_pixel` run under `raw_spinlock_t` `dev->mode_config.panic_lock` with IRQs disabled and must not sleep or allocate with `GFP_KERNEL`; allocations in `drm_mm_reserve_node()`, `drm_mm_insert_node_in_range()`, or `save_stack()` must use `GFP_NOWAIT`, and `drm_pagemap_zdd_destroy()` (invoked synchronously from `put_page()`) must call `complete_all(&devmem->detached)` before `devmem->ops->devmem_release(devmem)`, which must not sleep. [F257, F381, F397, F399]

## Object Lifetimes
- In `drm_framebuffer_init()`, each non-NULL `fb->obj[i]` with an existing GEM handle must acquire a handle ref via `drm_gem_object_handle_get_if_exists_unlocked()`, record `DRM_FRAMEBUFFER_HAS_HANDLE_REF(i)` in `fb->internal_flags`, and release it via `drm_gem_object_handle_put_unlocked()` on init failure and in `drm_framebuffer_cleanup()`; in `drm_gem_object_handle_put_unlocked()`, when `--obj->handle_count` reaches zero under `dev->object_name_lock`, `drm_gem_object_handle_free()` and `drm_gem_object_exported_dma_buf_free()` must run while `object_name_lock` is still held and before `drm_gem_object_put(obj)`. [F1, F5]
- Because `drm_gem_mmap_obj()` gets `obj` and presets `vma->vm_private_data` and `vma->vm_ops` before calling `obj->funcs->mmap()`, callbacks delegating VMA ownership (`drm_gem_shmem_mmap()` on imported objects via `dma_buf_mmap()`, or `drm_gem_ttm_mmap()` via `ttm_bo_mmap_obj()`) must put `obj` on success, and `drm_gem_shmem_mmap()` must clear `vma->vm_private_data` and `vma->vm_ops` to `NULL` before `dma_buf_mmap()`. [F66, F153]
- `drm_gem_shmem_vm_open()` must lock `shmem->base.resv` uninterruptibly via `dma_resv_lock()` and unconditionally increment `shmem->pages_use_count` via `refcount_inc_not_zero()` alongside `drm_gem_vm_open(vma)`; for non-imported shmem objects, `drm_gem_shmem_vunmap_locked()` must only call `vunmap(shmem->vaddr)`, clear `shmem->vaddr = NULL`, and call `drm_gem_shmem_unpin_locked(shmem)` inside `refcount_dec_and_test(&shmem->vmap_use_count)`. [F8, F9]
- In `drm_gem_vram_create()`, once `ttm_bo_init_validate()` is called with `ttm_buffer_object_destroy`, a failure of `ttm_bo_init_validate()` automatically invokes `ttm_buffer_object_destroy()` (calling `drm_gem_object_release()` and `kfree(gbo)`), so the caller must not free `gbo` again; `drm_gem_vram_vunmap()` only decrements `gbo->vmap_use_count` and leaves `gbo->map` mapped for reuse, whereas `drm_gem_vram_bo_driver_move_notify()` must unmap `gbo->map` via `ttm_bo_vunmap()` and clear it with `iosys_map_clear(&gbo->map)`. [F15, F16]
- On foreign DMA-BUF import, `drm_gem_prime_import_dev()` attaches, calls `get_dma_buf()`, and maps the attachment, rolling back in LIFO order on error and requiring `drm_prime_gem_destroy()` in `drm_gem_object_funcs.free`; on self-import (`drm_gem_is_prime_exported_dma_buf(dev, dma_buf)`), it must increment `dma_buf->priv`'s `drm_gem_object` refcount and return it without `get_dma_buf()` or `dma_buf_attach()`; `drm_gem_dmabuf_export()` takes refs on both `drm_device` and `drm_gem_object`, requiring `dma_buf_ops.release` to call `drm_gem_dmabuf_release()`. [F221, F222, F404]
- Every `drm_for_each_connector_iter()` traversal must call `drm_connector_list_iter_end()` on all exit paths, and retaining a `connector` pointer past `drm_connector_list_iter_end()` (as in `drm_helper_hpd_irq_event()`) requires `drm_connector_get()` inside the loop; `drm_mode_config_cleanup()` must call `flush_work(&dev->mode_config.connector_free_work)` after dropping connector refs and before checking `connector_list` or destroying properties, planes, CRTCs, blobs, and `object_idr`. [F239, F253, F325]

## API Contracts
- Once `drm_gem_objects_lookup()` allocates the `objs` array and sets `*objs_out = objs`, it does not free `*objs_out` or drop partially acquired `drm_gem_object` references on subsequent error, leaving the caller responsible for putting non-NULL entries and calling `kvfree(*objs_out)`. [F6]
- `drm_gem_object_lookup()` and `drm_framebuffer_lookup()` return `NULL` on miss, whereas `drm_gem_get_pages()`, `drm_gem_shmem_get_pages_sgt()`, `drm_gem_dma_get_sg_table()`, `drm_gem_fb_create_with_funcs()`, `drm_privacy_screen_get()`, and `drm_get_panel_backlight_quirk()` return `ERR_PTR` (never `NULL`); `__drm_mm_interval_first(mm, start, last)` takes an inclusive `last` and returns `&mm->head_node` (never `NULL`) when empty, and `mipi_dbi_poweron_conditional_reset()` returns `0` on reset, `1` if already on, or `< 0` on error. [F47, F48, F260, F273, F278]
- `drm_helper_probe_detect(connector, ctx, force)` returns a positive `enum drm_connector_status` (handling `-EDEADLK` internally) when `ctx == NULL`, but may return `-EDEADLK` or `< 0` when `ctx != NULL`; in `drm_connector_mode_valid()` and `drm_mode_validate_pipeline()`, mode rejection is reported via `*status` (`enum drm_mode_status`) while the `int` return is `0` or a locking error (`-EDEADLK`). [F274, F275]
- Low-level MIPI DSI transfer helpers (`mipi_dsi_generic_write`, `mipi_dsi_dcs_write_buffer`, `mipi_dsi_dcs_read`) return `ssize_t` byte counts or negative errno, whereas higher-level command helpers return `int` (`0` or negative errno), and every `mipi_dsi_*_multi()` helper must return immediately if `ctx->accum_err` is non-zero and record negative transfer results in `ctx->accum_err`; MIPI DCS getters (`mipi_dsi_dcs_get_power_mode`, `mipi_dsi_dcs_get_pixel_format`, `mipi_dsi_dcs_get_display_brightness*`) must treat a `0` return from `mipi_dsi_dcs_read()` as `-ENODATA`. [F43, F44, F131]
- Callers of `drm_mm_insert_node_in_range()` and `drm_mm_reserve_node()` must zero-initialize `struct drm_mm_node` because `node->flags` is not cleared; `drm_object_attach_property()` must only be called before the target `drm_mode_object` is registered, and downcasting a `drm_mode_object` via `obj_to_connector()`, `obj_to_crtc()`, `obj_to_plane()`, `drm_connector_set_obj_prop()`, or `drm_mode_crtc_set_obj_prop()` requires verifying `obj->type` first. [F259, F358, F369]

## Error Handling
- `drm_pagemap_zdd_alloc()` returns `NULL` (not `ERR_PTR`) on failure; in `drm_pagemap_migrate_to_devmem()` and `__drm_pagemap_migrate_to_ram()`, once `migrate_vma_setup(&migrate)` succeeds with `migrate.cpages > 0`, every subsequent error path must jump to `err_finalize` to unlock/put `migrate.dst` pages, call `migrate_vma_pages()` and `migrate_vma_finalize()`, and unmap DMA pages before freeing `buf`, and `drm_pagemap_migrate_to_devmem()` only transfers the caller's `devmem_allocation` reference to `zdd->devmem_allocation` after `ops->copy_to_devmem()` succeeds. [F219, F265]
- In `atomic_remove_fb()`, `-EDEADLK` at `unlock:` must clear `state`, call `drm_modeset_backoff(&ctx)`, and jump to `retry:` (resetting `plane_mask = 0`), whereas `-EINVAL` when `!disable_crtcs` must put `state` and drop/finalize `ctx` before setting `disable_crtcs = true` and jumping to `retry_disable:`; in `set_property_atomic()`, `-EDEADLK` must call `drm_atomic_state_clear(state)` before `drm_modeset_backoff(&ctx)`; in `drm_mode_page_flip_ioctl()`, `out:` must put and reset `fb = NULL` and `plane->old_fb = NULL` before retrying on `-EDEADLK`, cancel `e` via `drm_event_cancel_free()`, and call `drm_crtc_vblank_put(crtc)` only after the retry loop exits on error. [F124, F227, F232]

## Known Pitfalls
- In `drm_gem_get_pages()`, pages copied per folio must be clamped to `min(npages - i, folio_nr_pages(folio))`, and in `drm_gem_put_pages()`, the `for (i = 0; i < npages; i++)` loop must advance `i += folio_nr_pages(folio) - 1` at the end of the body so multi-page folios are released once; in `drmm_release_action()` and `drmm_kfree()`, the lookup loop must store a match into a separate `dr_match` pointer (initialized to `NULL`) before breaking rather than inspecting the `list_for_each_entry` cursor after the loop; in-place updates of a linked `struct drm_display_mode` (as in `drm_connector_list_update()`) must use `drm_mode_copy()` to preserve `dst->head`, whereas uninitialized stack modes must use `drm_mode_init()`. [F100, F117, F127, F288, F330]
