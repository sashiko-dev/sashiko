# DRM DRIVERS

This unit comprises the core DRM subsystem, display protocol (`include/drm/display/*.h`), and bridge headers (`include/drm/bridge/*.h`), UAPI definitions (`include/uapi/drm/*.h`), AMD ASIC definitions, and the Rust kernel abstractions (`kernel::drm`).

## Architecture & Data Flow
- Because `drm_atomic_state.connectors` is sized to `state->num_connector` with sparse `NULL` holes at unplugged indices (and `drm_connector.index` must be in `[0, 31]` for `drm_connector_mask()`), direct lookups by `drm_connector_index()` must check `index < state->num_connector` first and loops over `state->connectors` must check `state->connectors[__i].ptr != NULL`. [F79, F108]
- Before downcasting a `struct drm_private_obj *` or `struct drm_private_state *` in `drm_atomic_state.private_objs[]` (e.g. via `to_dp_mst_topology_state()` or `drm_priv_to_bridge_state()`), `objs_state->ptr->funcs` must be compared against that subtype's `drm_private_state_funcs` vtable pointer. [F50]
- `struct drm_connector.registration_state` is a tristate (`DRM_CONNECTOR_INITIALIZING`, `DRM_CONNECTOR_REGISTERED`, `DRM_CONNECTOR_UNREGISTERED`) where `drm_connector_is_unregistered()` is true only for `DRM_CONNECTOR_UNREGISTERED`; treating `!= DRM_CONNECTOR_REGISTERED` as unregistered breaks modesets on `DRM_CONNECTOR_INITIALIZING` connectors. [F126]
- In `struct drm_dp_mst_branch`, `port_parent` is `NULL` and `rad[8]` is all zeros (`lct == 1`) for the root primary branch `mgr->mst_primary`, and `rad` nibbles are only valid for link counts `2 .. mstb->lct`. [F52]
- In `rust/kernel/drm/`, any `impl drm::Driver for T` must have `<T::File as DriverFile>::Driver == T` and any `U: DriverObject` used with `gem::Object<U>` must have `<U::Driver as drm::Driver>::Object == gem::Object<U>`, because `File::open_callback` and `gem::open_callback`/`close_callback` downcast raw C pointers via those associated types. [F256, F261]

## Synchronization
- `drm_dev_is_unplugged()` drops its critical section immediately via `drm_dev_exit()` and races with concurrent `drm_dev_unplug()`; drivers must guard hardware-access critical sections with paired `drm_dev_enter()` and `drm_dev_exit()` calls instead. [F35]
- When a `struct drm_private_obj` stores state shared across multiple CRTCs, drivers must store a reference to `struct drm_crtc_commit` in the private state during `atomic_commit_setup` and wait for that commit at the start of `atomic_commit_tail` to prevent out-of-order non-blocking commits from freeing the state. [F29]
- `__drm_atomic_get_current_plane_state()` reads `plane->state` without checking modeset locks when `plane` is not in `drm_atomic_state`; only call it when a lock protecting `plane->state` (such as a fixed CRTC's lock) is already held, and use `drm_atomic_get_plane_state()` if planes can be dynamically reassigned. [F30]
- In `struct drm_connector`, `registration_state` updates require `connector->mutex` (unlocked readers must use `drm_connector_is_unregistered()`), `mode_config.connection_mutex` protects `state`, `mode_config.mutex` protects `modes`, `status`, `probed_modes`, `display_info`, and `edid_blob_ptr`, and `eld_mutex`, `edid_override_mutex`, `hdmi.infoframes.lock`, and `hdmi_audio.lock` protect `eld`, `edid_override`, `audio`, and `plugged_cb`. [F34, F40]
- When `drm_connector_list_iter` drops the final reference to a `struct drm_connector` under the `drm_mode_config.connector_list_lock` spinlock (or in IRQ context), final cleanup must be deferred by queuing `connector->free_node` onto `connector_free_list` and scheduling `connector_free_work`, never by calling `drm_connector_put()` or `destroy()` directly. [F133]
- `drm_device.vbl_lock` is the outer spinlock wrapping `vblank_time_lock`, and `drm_crtc_funcs.{enable_vblank,disable_vblank,get_vblank_counter,get_vblank_timestamp}` execute with both spinlocks held and IRQs disabled so they must never sleep; `vblank->last` requires `vbl_lock`, `vblank->hwmode` is only valid while `vblank->enabled` is true, and `vblank->count` must be read via `drm_crtc_vblank_count()` or `drm_crtc_vblank_count_and_time()`. [F134, F179, F213]
- In `struct drm_dp_mst_topology_mgr`, `up_req_recv` and `down_rep_recv` are read without `mgr->lock` so topology removal must set `mgr->reset_rx_state = true` under `mgr->lock` rather than resetting them directly; `port->mstb` and `mstb->ports` may only be modified by `work` and `up_req_work` under both `mgr->probe_lock` and `mgr->lock` (and read elsewhere under `mgr->lock`); `payload_count` and `next_start_slot` must only be accessed in atomic commit context (never `atomic_check`); and `drm_dp_mst_atomic_payload.vc_start_slot` may only be read during atomic commit after `drm_dp_mst_atomic_wait_for_dependencies()`. [F22, F24, F25, F138]
- `struct drm_buddy` has no internal locking so callers must externally serialize `drm_buddy_alloc_blocks()`, `drm_buddy_block_trim()`, `drm_buddy_free_block()`, and `drm_buddy_free_list()`, must not touch `block->link` after freeing a block, and must call `drm_buddy_reset_clear()` under the buddy lock after suspend/resume may have dirtied memory. [F39, F59]
- `drm_syncobj.fence` must not be dereferenced directly; lockless readers must hold a `drm_syncobj` reference and call `drm_syncobj_fence_get()` (`dma_fence_get_rcu_safe`), while updates to `fence`, `cb_list`, and `ev_fd_list` must hold `drm_syncobj.lock`. [F177]
- While holding the read lock from `drm_vma_offset_lock_lookup(mgr)`, callers are in atomic context, must only call `drm_vma_offset_lookup_locked` or `drm_vma_offset_exact_lookup_locked`, and must pin the returned object's reference before `drm_vma_offset_unlock_lookup(mgr)`; `drm_vma_node_unmap()` accesses `node->vm_node` unlocked and must be externally serialized against `drm_vma_offset_remove()`. [F180, F181]

## Object Lifetimes
- All `struct drm_private_obj` instances on a `struct drm_device` must be initialized with `drm_atomic_private_obj_init()` before `drm_dev_register()` and cleaned up with `drm_atomic_private_obj_fini()` only after `drm_dev_unregister()` completes. [F1]
- Drivers and helpers must invoke `drm_plane_helper_funcs.end_fb_access` and finish all reads of `new_crtc_state` and `new_plane_state` before calling `drm_atomic_helper_commit_hw_done()`, and must wait on `state->crtcs[i].commit->flip_done` rather than `new_crtc_state->commit->flip_done` afterwards because signaling `hw_done` allows a subsequent commit to swap and free `new_crtc_state` and `new_plane_state`. [F3, F6]
- `drm_connector_state.crtc` must only be modified via `drm_atomic_set_crtc_for_connector()` (never direct assignment) to keep connector refcounts and `crtc_state->connector_mask` symmetric; similarly, `drm_writeback_job::fb` must only be set via `drm_writeback_set_fb(conn_state, fb)`. [F20, F203]
- A `struct drm_connector *` from `drm_connector_list_iter_next()` or `drm_for_each_connector_iter()` is only valid until the next step or `drm_connector_list_iter_end()` (unless `drm_connector_get()` is called), and every `drm_connector_list_iter_begin()` must pair with `drm_connector_list_iter_end()` on all exit paths. [F11]
- Drivers retaining a `struct drm_dp_mst_port *` must acquire a malloc reference via `drm_dp_mst_get_port_malloc()` inside `drm_dp_mst_topology_cbs.add_connector` and release it with `drm_dp_mst_put_port_malloc()` (never touching `topology_kref`); DP tunnel references from `drm_dp_tunnel_get()` must be released with `drm_dp_tunnel_put()` passing the same `struct ref_tracker **`; and `drm_file_get_master()` references must be released with `drm_master_put(&master)`. [F16, F17, F18]
- In `rust/kernel/drm/`, `Device::release` must only call `core::ptr::drop_in_place` without freeing the backing pointer (which C frees after `release`), `AlwaysRefCounted::dec_ref` for `Device<T>` and `IntoGEMObject` must end any `&Self` borrow before calling `drm_dev_put`/`drm_gem_object_put`, and `gem::Object::<T>::new` must set `funcs = &Self::OBJECT_FUNCS` before `drm_gem_object_init` and only call `KBox::into_raw`/`ARef::from_raw` after it succeeds (with `free_callback` calling `drm_gem_object_release` before `KBox::from_raw`). [F164, F167, F264, F268]

## API Contracts
- Atomic KMS drivers (`drm_drv_uses_atomic_modeset()`) must provide both `atomic_duplicate_state` and `atomic_destroy_state` on `drm_crtc_funcs` and `drm_connector_funcs`, incrementing refcounts for all copied refcounted objects in `atomic_duplicate_state` and releasing them in `atomic_destroy_state`; `atomic_set_property` callbacks must only update the passed-in `state` struct without touching hardware/persistent state or doing cross-property validation. [F7, F147, F151]
- Drivers must never modify `drm_atomic_state.allow_modeset`, must use `drm_atomic_crtc_needs_modeset()` instead of `allow_modeset` in the commit path, and must check `state->allow_modeset` before adding an unrelated `drm_crtc_state` via `drm_atomic_get_crtc_state()`; atomic check helpers and drivers must also inspect `state->duplicated` (set by `drm_atomic_helper_duplicate_state()`) to permit or fix up modesets on unregistered connectors during suspend/resume restoration. [F65, F76]
- For DRM-managed init helpers (`drmm_crtc_init_with_planes()`, `drmm_crtc_alloc_with_planes()`, `drmm_connector_init()`, `drmm_connector_hdmi_init()`), `funcs->destroy` must be `NULL`, whereas for unmanaged `drm_crtc_init_with_planes()` and `drm_connector_init*()`, `funcs->destroy` must be non-NULL. [F53]
- The DRM core calls `drm_crtc_vblank_get()` before `drm_crtc_funcs.page_flip_target` and calls `drm_crtc_vblank_put()` itself on non-zero error, whereas on `0` return the driver owns the reference and must call `drm_crtc_vblank_put()` when the flip completes; KMS drivers must also call `drm_crtc_vblank_off` when disabling a CRTC and `drm_crtc_vblank_on` when enabling it, and `drm_device.max_vblank_count` (when non-zero) must be a contiguous low-bit mask `(1 << N) - 1`. [F8, F110, F270]
- `drm_dp_dpcd_read()`/`write()`/`readb()`/`writeb()` return the positive transferred byte count or negative errno, whereas `drm_dp_dpcd_read_data()`/`write_data()`/`read_byte()`/`write_byte()`, `drm_scdc_read()`/`write()`, and `drm_dp_dual_mode_read()`/`write()` return `0` on full transfer and negative errno (including `-EPROTO`) on failure; `drm_dp_calc_pbn_mode()`, `drm_dp_bw_overhead()`, `drm_dp_link_symbol_cycles()`, and `drm_dsc_config.bits_per_pixel` all use `.4` binary fixed-point bpp (`bpp << 4`, 1/16th bpp units). [F41, F42, F55, F109]
- `drm_vma_offset_manager_init`, `drm_vma_offset_lookup_locked`, `drm_vma_offset_add`, `drm_vma_node_start`, and `drm_vma_node_size` use page-based offsets/counts (whereas `drm_vma_node_offset_addr` returns a byte offset shifted by `PAGE_SHIFT`), and `drm_vma_offset_exact_lookup_locked()` must verify `node->vm_node.start == start` because `drm_vma_offset_lookup_locked()` matches interior offsets. [F191, F243]
- Per-device feature overrides must modify `drm_device.driver_features` rather than the shared `drm_driver.driver_features` (checked via `drm_core_check_feature()`/`drm_core_check_all_features()`), and signature changes to functions guarded by `CONFIG_DRM_AUX_BRIDGE` / `CONFIG_DRM_AUX_HPD_BRIDGE`, `CONFIG_DEBUG_FS`, or `CONFIG_DRM_DISPLAY_DP_TUNNEL` must be updated in lockstep with their `#else` inline stubs. [F60, F61, F64, F77, F124]

## Error Handling
- When an atomic commit fails after `drm_atomic_helper_prepare_planes()` but before `drm_atomic_helper_swap_state()`, rollback must call `drm_atomic_helper_unprepare_planes()` (which cleans up `new_plane_state`) rather than `drm_atomic_helper_cleanup_planes()` (which operates on `old_plane_state`). [F4]
- `drm_atomic_get_{crtc,plane,connector,private_obj,bridge,mst_topology}_state()`, `devm_drm_dev_alloc()`, `drmm_crtc_alloc_with_planes()`, `drm_client_framebuffer_create()`, `drm_suballoc_new()`, and `drm_get_panel_backlight_quirk()` return `ERR_PTR()`; `drm_atomic_get_{old,new}_*_state()`, `drm_atomic_state_alloc()`, `.atomic_duplicate_state()`, `drm_syncobj_find()`, `drm_syncobj_fence_get()`, and `drm_gem_object_lookup` return `NULL`; and `devm_drm_dp_hpd_bridge_alloc()` / `drm_dp_hpd_bridge_register()` return `ERR_PTR()` when `CONFIG_DRM_AUX_HPD_BRIDGE` is enabled but `NULL` when disabled. [F44, F45, F46, F188, F193, F196, F204]
- `drm_vblank_work_schedule()`, `drm_dp_tunnel_update_state()`, and `drm_dp_tunnel_handle_irq()` return `1` when work was scheduled or state changed, `0` when unchanged/unscheduled, and `< 0` on error; `drm_dp_tunnel_get_allocated_bw()` and `drm_dp_tunnel_available_bw()` return `-1` when undetermined/disabled; and in Rust `Device::new`, `bindings::__drm_dev_alloc` must be decoded with `from_err_ptr` and `bindings::drm_dev_put` must be called if `data.__pinned_init` fails, while `declare_drm_ioctls!` handlers returning `Ok(i)` with `i > i32::MAX as u32` fail with `-ERANGE`. [F48, F186, F190, F200]

## External Contracts
- In `struct drm_crtc_state`, `enable` governs shared resource reservation while `active` governs hardware DPMS state (and in self-refresh mode `active` is `false` while `self_refresh_active` is `true`, so active-pipeline checks must use `drm_atomic_crtc_effectively_active(state)`); drivers must not release shared resources when `active` becomes `false` while `enable` remains `true` or reject a commit in `atomic_check` solely because `active` flips while `enable` is set, and atomic drivers must always populate `drm_connector_state.best_encoder` when routing a connector. [F69, F70, F103]

## Known Pitfalls
- In `include/drm/drm_atomic.h`, `for_each_{oldnew,old,new}_private_obj_in_state` must evaluate `(__i) < (__state)->num_private_objs` before indexing `private_objs[__i]` via `&&`, the sparse-array iterators `for_each_{oldnew,old,new}_{connector,crtc,plane}_in_state*` must only assign cursor variables inside `for_each_if` after checking `.ptr != NULL`, `for_each_{oldnew,new}_plane_in_state_reverse` require a signed `int` loop cursor `@__i`, and `atomic_check` paths validating incoming plane attachments before state swap must use `drm_atomic_crtc_state_for_each_plane()` or `drm_atomic_crtc_state_for_each_plane_state()` on the incoming `crtc_state` rather than `drm_atomic_crtc_for_each_plane(plane, crtc)`. [F80, F81, F96, F100]
- Multi-bit fields that cannot be tested with bitwise `&` alone: `DRM_BUDDY_HEADER_STATE` (`DRM_BUDDY_ALLOCATED = 1 << 10`, `DRM_BUDDY_FREE = 2 << 10`, `DRM_BUDDY_SPLIT = 3 << 10`) must be checked via `drm_buddy_block_state(block)` equality; extended KMS property types (`DRM_MODE_PROP_OBJECT`, `DRM_MODE_PROP_SIGNED_RANGE`) must be checked via `(prop->flags & DRM_MODE_PROP_EXTENDED_TYPE) == type`; OMAP BO flags (`OMAP_BO_TILED_32 == OMAP_BO_TILED_8 | OMAP_BO_TILED_16` and `OMAP_BO_CACHED == 0`) must be masked with `OMAP_BO_TILED_MASK` or `OMAP_BO_CACHE_MASK` and compared for equality; and multi-field DPCD registers (such as `DP_DSC_MAX_BITS_PER_PIXEL_HI` and `DP_DSC_BITS_PER_PIXEL_INC`) must parenthesize `(val & mask)` before shifting or comparing. [F97, F98, F241, F242]
- `__drm_atomic_helper_crtc_duplicate_state()` does not reset `drm_crtc_state.no_vblank`, so drivers that dynamically toggle `no_vblank` must explicitly update it; calling `drm_dev_unplug()` before `drm_atomic_helper_shutdown()` skips disable callbacks guarded by `drm_dev_enter()` on module unload; `DP_LTTPR_BASE(dp_phy)` and `DP_FEC_BASE(dp_phy)` require 1-based `dp_phy` via `DP_PHY_LTTPR(i)` (never `DP_PHY_DPRX` = 0); `drm_connector_hdmi.{vendor,product}` are `__nonstring` arrays that may not be NUL-terminated; and in `rust/kernel/drm/ioctl.rs`, `declare_drm_ioctls!` entries must be contiguous from `DRM_COMMAND_BASE` with matching struct sizes and handler parameters `&drm::Device<Self>` and `&drm::File<Self::File>`. [F66, F84, F91, F120, F217, F255]
