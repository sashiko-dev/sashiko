# PER-CPU MEMORY ALLOCATOR

This component defines the header interfaces, architecture-specific accessors, and internal metadata for the kernel per-CPU memory allocator and per-CPU synchronization and accounting primitives (`DEFINE_PER_CPU`, `alloc_percpu`, `this_cpu_*`/`raw_cpu_*`, `mm/percpu-internal.h`, `percpu_ref`, `percpu_rw_semaphore`, and `percpu_counter`).

## Architecture & Data Flow

- In `mm/percpu-internal.h`, all `struct pcpu_block_md` fields (`scan_hint`, `scan_hint_start`, `contig_hint`, `contig_hint_start`, `left_free`, `right_free`, `first_free`, `nr_bits`) are in `PCPU_MIN_ALLOC_SIZE` allocation bits, whereas `pcpu_chunk->free_bytes`, `start_offset`, and `end_offset` are in bytes. Broken by: mixing block hints/offsets with byte sizes without converting via `PCPU_MIN_ALLOC_SIZE` / `PCPU_MIN_ALLOC_SHIFT`. [F37]
- In `struct pcpu_block_md`, `scan_hint_start > contig_hint_start` holds iff `scan_hint == contig_hint`; when `scan_hint` is non-zero and smaller than `contig_hint`, `scan_hint_start` must precede `contig_hint_start`. Broken by: leaving a non-zero `scan_hint < contig_hint` at `scan_hint_start > contig_hint_start` in `pcpu_block_update()` or `pcpu_block_refresh_hint()`. [F39]
- `PCPU_BITMAP_BLOCK_SIZE` must equal `PAGE_SIZE` so each `struct pcpu_block_md` in `chunk->md_blocks` (`pcpu_chunk_nr_blocks()`) maps to one page when adjusting `chunk->nr_empty_pop_pages` and `pcpu_nr_empty_pop_pages`. For a `struct pcpu_chunk` serving `chunk->nr_pages` pages, `alloc_map` and `obj_exts` are sized for `pcpu_chunk_map_bits(chunk)` entries, `bound_map` requires `pcpu_chunk_map_bits(chunk) + 1` bits for the end-boundary bit, and `populated[]` has `chunk->nr_pages` bits. [F40, F56]
- `pcpu_stats_save_ai()` copies only `sizeof(struct pcpu_alloc_info)` bytes into static global `pcpu_stats_ai`, omitting the `groups[]` flexible array even though `pcpu_stats_ai.nr_groups` is copied; readers of `pcpu_stats_ai` must never access `pcpu_stats_ai.groups`. [F80]
- `PERCPU_COUNTER_LOCAL_BATCH` (and any `batch` passed to `percpu_counter_add_batch()` under `CONFIG_SMP`) is typed as `s32` and bounded by `INT_MAX` so local deltas satisfying `abs(count + amount) < batch` fit without overflow in `s32 __percpu *counters` before folding into `s64 count`. [F78]
- On s390, `arch_this_cpu_to_op_simple()` must set `old__ = prev__` at the start of each `do { ... } while (prev__ != old__)` iteration (where `prev__` is updated by `cmpxchg(ptr__, old__, new__)`) so retries recompute `new__` from the latest witness value; under `MARCH_HAS_Z196_FEATURES`, `arch_this_cpu_add()` may emit `"asi"`/`"agsi"` (`op2`) only when `val__` is a constant in `(-129 < (szcast)val__ && (szcast)val__ < 128)`, and `"laa"`/`"laag"` (`op1`) otherwise. [F64, F71]
- Whenever `CONFIG_AMD_MEM_ENCRYPT` is enabled, `DECLARE_PER_CPU_DECRYPTED` and `DEFINE_PER_CPU_DECRYPTED` must place variables in `"..decrypted"` regardless of `CONFIG_VIRTUALIZATION` so decrypted per-CPU variables never share pages with encrypted ones. [F100]

## Synchronization

- Fast-path `percpu_ref` helpers (`percpu_ref_get_many()`, `percpu_ref_tryget_many()`, `percpu_ref_tryget_live_rcu()`, `percpu_ref_put_many()`) must hold an RCU read-side critical section continuously across `__ref_is_percpu()` and the subsequent per-CPU or `ref->data->count` update. [F12]
- `__ref_is_percpu()` must load `ref->percpu_count_ptr` once with `READ_ONCE()`, test that snapshot against `__PERCPU_REF_ATOMIC_DEAD` (both `__PERCPU_REF_ATOMIC` and `__PERCPU_REF_DEAD`), and only when returning `true` assign `*percpu_countp` from the same snapshot; when returning `false`, `*percpu_countp` is uninitialized. Broken by: dereferencing `percpu_count` without checking `__ref_is_percpu()`, masking only `__PERCPU_REF_ATOMIC`, or re-fetching `ref->percpu_count_ptr`. [F27, F44]
- In `include/linux/percpu-rwsem.h`, `percpu_down_read_internal()`, `percpu_down_read_trylock()`, and `percpu_up_read()` must wrap `rcu_sync_is_idle(&sem->rss)` and the `*sem->read_count` update in `preempt_disable()` / `preempt_enable()`, use IRQ-safe `this_cpu_inc()` / `this_cpu_dec()` (not `__this_cpu_*`), and in the `percpu_up_read()` slow path (`!rcu_sync_is_idle(&sem->rss)`) execute `smp_mb()` before `this_cpu_dec(*sem->read_count)` and `rcuwait_wake_up(&sem->writer)`. [F17, F105]
- Under `CONFIG_PERCPU_STATS`, `pcpu_stats_area_alloc()` and `pcpu_stats_area_dealloc()` must be called with `pcpu_lock` held and update both global `pcpu_stats` and `chunk->nr_alloc` (plus `chunk->max_alloc_size` on alloc) in lockstep, whereas `pcpu_stats_chunk_alloc()` and `pcpu_stats_chunk_dealloc()` acquire `pcpu_lock` internally via `spin_lock_irqsave()` and must not be called with `pcpu_lock` held. [F18, F41]
- Under `!CONFIG_SMP`, `percpu_counter_add()` and `percpu_counter_limited_add()` must wrap the read-modify-write of `fbc->count` in `local_irq_save()` / `local_irq_restore()`. [F20]
- On x86, `this_percpu_xchg_op` (`this_cpu_xchg_{1,2,4,8}`) must use `this_cpu_read()` and a `do { } while (!this_cpu_try_cmpxchg(_var, &pxo_old__, _nval));` loop (relying on `percpu_try_cmpxchg_op()` updating `*pco_oval__ = pco_old__` on failure) rather than `raw_percpu_xchg_op`'s non-atomic read-then-write or a `LOCK`-prefixed `xchg` instruction. [F22, F70]
- In `this_cpu_*` helpers that resolve a pointer via `raw_cpu_ptr()` before accessing memory (`_pcp_protect`, `_pcp_protect_return`, `this_cpu_cmpxchg128`, `_protect_cmpxchg_local`, `arch_this_cpu_to_op_simple`), both `raw_cpu_ptr()` and the memory access must stay inside `preempt_disable_notrace()` / `preempt_enable_notrace()`. [F91]
- In `__kern_my_cpu_offset()` (arm64) and `__my_cpu_offset()` (arm), the non-volatile `asm` reading `tpidr_el1`/`tpidr_el2` or `TPIDRPRW` must keep `"Q" (*(const unsigned long *)current_stack_pointer)` as an input operand so `barrier()` invalidates cached CPU offsets across preemption; on LoongArch, `set_my_cpu_offset(off)` must write `off` to both `$r21` (`__my_cpu_offset`) and `PERCPU_BASE_KS` via `csr_write64()`, and `__my_cpu_offset` must include `__asm__ __volatile__("":"+r"(__my_cpu_offset))`. [F24, F97]
- In `arch/arm64/include/asm/percpu.h`, when `__KVM_NVHE_HYPERVISOR__` is defined, `__my_cpu_offset` must resolve to `__hyp_my_cpu_offset()` (`read_sysreg(tpidr_el2)`), and under `CONFIG_DEBUG_PREEMPT`, `this_cpu_ptr`, `__this_cpu_read`, and `__this_cpu_write` must be redefined to their `raw_cpu_*` counterparts. [F96]

## Object Lifetimes

- `get_cpu_var(var)` and `get_cpu_ptr(var)` call `preempt_disable()` before returning the current CPU's lvalue or pointer and must be paired on all exit paths with `put_cpu_var(var)` and `put_cpu_ptr(var)` to call `preempt_enable()`. [F8]
- On x86 with `CONFIG_SMP`, `DEFINE_EARLY_PER_CPU` and `DEFINE_EARLY_PER_CPU_READ_MOSTLY` size `_name##_early_map` to `NR_CPUS` (indexed without bounds checks by `early_per_cpu_map()` and `early_per_cpu()`, requiring `[0, NR_CPUS)`), and must have `_early_map` copied to `per_cpu(_name, cpu)` and `early_per_cpu_ptr(_name)` set to `NULL` before `__initdata` is freed. [F43, F63]

## API Contracts

- In atomic mode (`__ref_is_percpu()` false), `percpu_ref_tryget()` and `percpu_ref_tryget_many()` increment `ref->data->count` whenever non-zero even if `__PERCPU_REF_DEAD` is set, whereas `percpu_ref_tryget_live()` and `percpu_ref_tryget_live_rcu()` return `false` when `__PERCPU_REF_DEAD` is set; while `__ref_is_percpu()` is true, `percpu_ref_{get,tryget,put}_many()` must do unchecked modular `unsigned long` arithmetic on `*percpu_count` without single-CPU zero/underflow checks. [F6, F79]
- `percpu_ref_put_many()` invokes `ref->data->release(ref)` inside `rcu_read_lock()` when `atomic_long_sub_and_test()` hits zero, and `percpu_ref_kill()` does not imply an RCU grace period before `release` (so `release` must not sleep and needs explicit `call_rcu()` to free RCU objects); `percpu_ref_is_dying()` checks `__PERCPU_REF_DEAD` without locking/RCU, requiring external synchronization. [F15, F104]
- A `struct percpu_ref` initialized with `PERCPU_REF_INIT_DEAD` starts at 0 in atomic/dead mode and requires `percpu_ref_reinit()` before use, whereas `PERCPU_REF_INIT_ATOMIC` starts at 1 in sticky atomic mode (`force_atomic`) until `percpu_ref_switch_to_percpu()` is called. [F49]
- `raw_cpu_*()` and `__this_cpu_*()` do not disable preemption or interrupts (`__this_cpu_*()` only calls `__this_cpu_preempt_check()`); callers must only use them when preemption (and interrupts, if an IRQ handler touches the variable) is already disabled, and otherwise use `this_cpu_*()`. [F25]
- `this_cpu_try_cmpxchg()`, `__this_cpu_try_cmpxchg()`, and `raw_cpu_try_cmpxchg()` take a pointer `ovalp`, return `bool`, and overwrite `*ovalp` on failure; on x86, `percpu_try_cmpxchg{,64,128}_op()` cast `_ovalp` to the exact target width, and on arm64/s390, `this_cpu_cmpxchg128(pcp, ...)` casts `raw_cpu_ptr(&(pcp))` to `(void *)`, requiring a 16-byte aligned `u128`-sized `pcp`. [F34, F85, F86]
- Architecture implementations of `this_cpu_add_return_*` and `raw_cpu_add_return_*` (`percpu_add_return_op` on x86, `__PERCPU_RET_OP_CASE` on arm64, `__percpu_add` on LoongArch, `arch_this_cpu_add_return` on s390) must add `val` to the old value returned by hardware fetch-and-add instructions; on arm64, `this_cpu_and_{1,2,4,8}(pcp, val)` must pass `~(val)` to bit-clearing `__percpu_andnot_case_*()`. [F35, F36]
- On x86, `this_cpu_read_stable()` (`__raw_cpu_read_stable`) omits `volatile` and uses an `"i"` constraint with no memory input, so it must only be used for per-CPU variables invariant across CPU migration for the current task (e.g. `current_task`, `cpu_current_top_of_stack`). [F93]
- When a `struct percpu_counter` is updated via `percpu_counter_{add,sub}_local()`, deltas accumulate in `fbc->counters` up to `PERCPU_COUNTER_LOCAL_BATCH` without updating `fbc->count`, so readers must use `percpu_counter_sum()`; on `CONFIG_SMP`, `percpu_counter_read()` can be negative for a non-negative counter, so non-negative approximate reads must use `percpu_counter_read_positive()`. [F32, F60]
- `percpu_counter_compare()` and `__percpu_counter_compare()` return a signed `1`/`0`/`-1` result, whereas `percpu_counter_limited_add()` and `__percpu_counter_limited_add()` return `bool`; in `!CONFIG_SMP` `percpu_counter_limited_add()`, `amount == 0` must short-circuit to `true`, and `limit` is an upper bound for `amount > 0` (`count <= limit`) and a lower bound for `amount < 0` (`count >= limit`). [F30, F68]
- `pcpu_obj_full_size(size)` scales `size` by `num_possible_cpus()` and adds `size / PCPU_MIN_ALLOC_SIZE * sizeof(struct obj_cgroup *)` when `CONFIG_MEMCG` is enabled and `!mem_cgroup_kmem_disabled()`, requiring `PCPU_MIN_ALLOC_SIZE`-aligned byte `size` on both charge and uncharge; in `struct pcpu_group_info`, unmapped `cpu_map` slots must be set to `NR_CPUS`. [F58, F81]
- Because `CONFIG_ARCH_MODULE_NEEDS_WEAK_PER_CPU` (alpha, s390) and `CONFIG_DEBUG_FORCE_WEAK_PER_CPU` emit `__weak` symbols for `DEFINE_PER_CPU_SECTION()`, every per-CPU variable name (even `static`) must be globally unique and outside function bodies; module exports must use `EXPORT_PER_CPU_SYMBOL()` or `EXPORT_PER_CPU_SYMBOL_GPL()` so `sparse` preserves `__percpu`. [F110, F111]

## External Contracts

- On x86, `percpu_cmpxchg64_op`, `percpu_try_cmpxchg64_op`, `percpu_cmpxchg128_op`, and `percpu_try_cmpxchg128_op` must split 64/128-bit values via an anonymous union with `struct { low, high; }` (`low` before `high`) and pass `&(_var)` in `"S"`, `old__` in `"+a"`/`"+d"`, `new__` in `"b"`/`"c"` with outputs wrapped in `ALT_OUTPUT_SP()` to match little-endian register pairs and the `this_cpu_cmpxchg{8,16}b_emu` assembly ABI. [F61, F98]
- Every `DECLARE_PER_CPU_SECTION()` declaration and its corresponding `DEFINE_PER_CPU_SECTION()` definition must pass the exact same section suffix `sec` to `__PCPU_ATTRS(sec)`. Broken by: declaring with `DECLARE_PER_CPU()` a variable defined with `DEFINE_PER_CPU_READ_MOSTLY()`, `DEFINE_PER_CPU_SHARED_ALIGNED()`, or `DEFINE_PER_CPU_PAGE_ALIGNED()`. [F99]

## Known Pitfalls

- In `include/linux/percpu_counter.h`, `struct percpu_counter` and its helpers are duplicated across `#ifdef CONFIG_SMP` and `#else /* !CONFIG_SMP */` and must be updated in lockstep; `percpu_counter_initialized(fbc)` checks `fbc->counters != NULL` on `CONFIG_SMP` but unconditionally returns `true` on `!CONFIG_SMP`. [F9, F52]
- `this_cpu_sub`, `__this_cpu_sub`, `this_cpu_sub_return`, `__this_cpu_sub_return`, and `raw_cpu_sub_return` must cast `val` to `typeof(pcp)` before unary negation (`-(typeof(pcp))(val)`); in x86 `percpu_add_op`, the `-1` check must compare `(val) == (typeof(val))-1` before casting `(int)(val)` so a 64-bit `UINT_MAX` (`0xffffffffULL`) is not truncated to `-1` (`dec`). [F73, F74]
- `x86_this_cpu_constant_test_bit(_nr, _var)` casts `&(_var)` to `(unsigned long __percpu *)`, advances `addr__` by `(_nr) / BITS_PER_LONG` words, and tests `1UL << ((_nr) % BITS_PER_LONG)` via `raw_cpu_read(*addr__)`; `_var` passed to `x86_this_cpu_test_bit()` must be `unsigned long`-aligned and a multiple of `sizeof(unsigned long)` in size. [F76, F87]
- On LoongArch, `PERCPU_OP` (`__percpu_add`, `__percpu_and`, `__percpu_or`) only handles `case 4:` and `case 8:` (`BUILD_BUG()` for 1 and 2); `this_cpu_{add,add_return,and,or}_{1,2}` must not be wired to `_percpu_*` without adding subword handling as in `__percpu_xchg()`. [F69]
- `PERCPU_PTR(__p)` must cast `__p` directly to `(TYPEOF_UNQUAL(*(__p)) __force __kernel *)((__force unsigned long)(__p))` without a statement-expression temporary variable, and `SHIFT_PERCPU_PTR(__p, __offset)` must apply `RELOC_HIDE()` to `PERCPU_PTR(__p)`. [F101]
