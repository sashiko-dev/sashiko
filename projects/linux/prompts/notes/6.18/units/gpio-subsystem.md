# GPIO SUBSYSTEM

The GPIO subsystem (`gpiolib`) manages `struct gpio_device` and `struct gpio_desc` lifecycles, mediates between consumers and `struct gpio_chip` providers using SRCU so hot-unplugged controllers fail safely, and integrates `gpio_irq_chip` domains, `pinctrl` ranges, Device Tree/swnode/legacy/sysfs frontends, and controller drivers.

## Architecture & Data Flow
- `gpio_chip_hwgpio()` and `desc_to_gpio()` compute a descriptor's hardware offset via `desc - &desc->gdev->descs[0]`; every `struct gpio_desc *` passed to gpiolib must be an element inside `desc->gdev->descs`, never a standalone or copied struct. [F441]
- `gpiod_get_array()` must place `struct gpio_array` (`array_info`) in the same `krealloc()` block right after `descs->desc[count]`, set `array_info->desc = descs->desc` after reallocation, and size fastpath masks to `BITS_TO_LONGS(max(gdev->ngpio, count))`. In `gpiod_get/set_array_value_complex()`, if `array_info` fails fastpath validation it must be reset to `NULL`, and stack `fastpath_mask`/`fastpath_bits` may only be used when `guard.gc->ngpio <= FASTPATH_NGPIO`. [F406, F419, F435, F438]
- In `gpiod_configure_flags()`, the early return on `!(dflags & GPIOD_FLAGS_BIT_DIR_SET)` must precede `if (dflags & GPIOD_FLAGS_BIT_DIR_OUT)` so `GPIOD_ASIS` (`0`) leaves hardware direction unchanged. In `gpiod_direction_output_nonotify()`, when open-drain/open-source emulation calls `gpiod_direction_input_nonotify(desc)`, `set_bit(GPIOD_FLAG_IS_OUT, &desc->flags)` must run afterward; `gpiod_get_direction()` must return `0` immediately when both `GPIOD_FLAG_OPEN_DRAIN` and `GPIOD_FLAG_IS_OUT` are set. [F392, F422, F423]
- `gpiod_free_commit()` must clear per-consumer flags (`GPIOD_FLAG_ACTIVE_LOW`, `OPEN_DRAIN`, `OPEN_SOURCE`, bias, edge, `IS_HOGGED`, `REQUESTED`), `desc->hog`, `desc->label`, and `desc->debounce_period_us`, while preserving `GPIOD_FLAG_IS_OUT` and `GPIOD_FLAG_USED_AS_IRQ`. [F397]
- `gpiochip_allocate_mask()` fills `valid_mask` with `bitmap_fill(p, gc->ngpio)` so lines start valid before `gpiochip_apply_reserved_ranges()` or `init_valid_mask` clears bits. In `gpiochip_apply_reserved_ranges()`, both `ranges[--size]` decrements must precede the `if (start >= gc->ngpio || start + count > gc->ngpio) continue;` check. [F386, F430]
- `gpiochip_set_names()` must return early when `"gpio-line-names"` `count <= chip->offset` and clamp `count - chip->offset` to `chip->ngpio`. In `gpiolib-of.c`, `OF_POPULATED` on a `gpio-hog` node must be cleared via `of_node_clear_flag(rd->dn, OF_POPULATED)` if `of_gpiochip_add_hog()` fails in `of_gpio_notify()` or when `of_gpiochip_remove_hog()` runs on `OF_RECONFIG_CHANGE_REMOVE`, and legacy SPI CS quirks mapping `"cs"` to `"gpios"` must update `of_gpio_spi_cs_get_count()` and `of_find_gpio_rename()` in lockstep. [F398, F402, F407]
- In `gpio-mmio.c`, `reg_dir_in` and `reg_dir_out` are independently optional (null-check before access), `chip->sdir` (`1` out, `0` in) is written inverted (`~chip->sdir`) to `reg_dir_in`, and `bgpio_get_dir()` checks `chip->dir_unreadable` first. `chip->sdata`, `chip->sdir`, and `bgpio_line2mask()` must use `unsigned long` and `BIT()`, `chip->bits` must remain `cfg->sz * 8` even when `gc->ngpio` is smaller, and `bgpio_get_multiple()`/`bgpio_get_set_multiple()` must not be used when `chip->be_bits` is true. [F33, F49, F72, F87, F100, F126]

## Synchronization
- Runtime accesses to `gdev->chip` and internal wrappers (`gpiochip_get_direction()`, `gpiochip_direction_input()`, `gpiochip_direction_output()`, `gpiochip_get()`, `gpio_chip_get_multiple()`, `gpiochip_set()`, `gpiochip_set_multiple()`) must hold `gdev->srcu` (e.g. via `gpio_chip_guard`) and verify `gc != NULL`; pre-registration queries in `gpiochip_add_data_with_key()` must call `gc->get_direction()` directly, and cross-descriptor chip comparisons must use `gpio_device_chip_cmp(gdev, gc)`. [F359, F362, F369]
- `gpiod_find_and_request()` must hold `gpio_devices_srcu` continuously across lookup (`gpiod_fwnode_lookup()` / `gpiod_find()`) and `gpiod_request()`. Modifications to `gpio_devices` must hold `gpio_devices_lock`, use RCU list primitives, and follow removal with `synchronize_srcu(&gpio_devices_srcu)` after unlocking before freeing or numbing `gdev`. [F367, F476]
- `desc_set_label()` replaces `desc->label` with `rcu_replace_pointer()` and defers freeing via `call_srcu(&desc->gdev->desc_srcu, &old->rh, desc_free_label)` (with `synchronize_srcu(&gdev->desc_srcu)` before `cleanup_srcu_struct()` in `gpiodev_release()`). Callers of `gpiod_get_label(desc)` must hold `desc->gdev->desc_srcu` while accessing the returned string and check for `NULL`. [F382, F469, F470]
- `gpiod_line_state_notify()` must hold `read_lock_irqsave(&desc->gdev->line_state_lock)` around `raw_notifier_call_chain()`, matching `write_lock_irqsave()` on notifier registration. `gpio_lookup_list` accesses require `gpio_lookup_lock`, `gpio_machine_hogs` accesses require `gpio_machine_hogs_mutex`, and `gpiod_free_irqs()` must release `irqd->request_mutex` after reading `irqd->action->dev_id` before calling `free_irq()`. [F366, F370, F478]
- In `gpio-mmio.c`, `chip->lock` (`raw_spin_lock_irqsave`) must be held across every modification of `chip->sdata` or `chip->sdir` and the corresponding `chip->write_reg()` call, and `bgpio_dir_in()` / `bgpio_dir_out*()` must release `chip->lock` before invoking `gc->set()` or `bgpio_dir_return()`. Similarly, direction/IRQ callbacks that call their own setter or direction helper (`gpio-mpsse.c`, `gpio-twl4030.c`, `gpio-viperboard.c`, `gpio-mxc.c`, `gpio-sifive.c`) must release their lock first. [F16, F17, F23, F158, F159, F214, F327]
- In I2C/SPI/PMIC IRQ expanders (`gpio-pca953x.c`, `gpio-max732x.c`, `gpio-pmic-eic-sprd.c`, `gpio-stmpe.c`, `gpio-tc3589x.c`), atomic `irq_chip` callbacks must only update cached bitmaps/regs and defer bus I/O to `*_bus_sync_unlock()`, with `irq_lock` nesting outside `i2c_lock`/`lock`. In `gpio-pca953x.c` (`disable_locking = true`), post-probe `regmap` accesses and `disable_irq()`/`regcache_cache_only()` toggles must hold `i2c_lock`, and `pca953x_irq_handler()` / `pcf857x_irq()` must unlock before `handle_nested_irq()`. [F18, F29, F54, F149, F151, F160, F161, F241]

## Object Lifetimes
- `gpiochip_remove()` must unregister sysfs, free hogs and IRQs, unlink `gdev->list` under `gpio_devices_lock`, call `synchronize_srcu(&gpio_devices_srcu)`, set `gdev->chip = NULL`, and call `synchronize_srcu(&gdev->srcu)` before tearing down `gc` state and calling `gcdev_unregister(gdev)`. `gpiochip_free_mask()` must set `*p = NULL` after `bitmap_free(*p)` so `err_remove_irqchip` unwind does not double-free `valid_mask`. [F348, F363]
- `gpiod_request()` pins `desc->gdev->owner` and `desc->gdev` (released by `gpiod_free()`), whereas `gpiochip_request_own_desc()` takes neither reference and must be paired with `gpiochip_free_own_desc()`. `gpiochip_reqres_irq()` must call `try_module_get(gc->gpiodev->owner)` before `gpiochip_lock_as_irq()` and roll it back with `module_put()` on failure. [F344, F358]
- `gpio_device_find*()` returns a refcounted `struct gpio_device *` requiring `gpio_device_put()`, whereas `gpio_device_get_desc()` and `gpiod_to_gpio_device()` do not increment the refcount. `devm_gpiod_put*()` must use `devm_release_action()` while `devm_gpiod_unhinge()` uses `devm_remove_action_nowarn()`, and `devm_gpiod_get_index()` with `GPIOD_FLAGS_BIT_NONEXCLUSIVE` must check `devm_is_action_added(dev, devm_gpiod_release, desc)` first. [F349, F451, F453]
- `gdev->label` is allocated with `kstrdup_const()` and must be freed with `kfree_const()`. `gpiochip_set_names()` must free only the temporary `names` pointer array (`kfree(names)`) and never the individual string pointers or `desc->name`. In `gpiod_unexport()`, `device_unregister(desc_data->dev)` must precede `gpio_sysfs_free_irq(desc_data)` under `sysfs_lock`, and `gpiochip_sysfs_unregister()` must release `sysfs_lock` before calling `gpiod_unexport()` on `GPIOD_FLAG_SYSFS` lines. [F356, F372, F445, F479]

## API Contracts
- Non-optional `gpiod_get*()` functions return `ERR_PTR(-ENOENT)` when unassigned (`ERR_PTR(-ENOSYS)` when `!CONFIG_GPIOLIB`), whereas `_optional` variants convert only `-ENOENT` (`gpiod_not_found()`) to `NULL` and propagate other `ERR_PTR`s; `gpiod_fwnode_lookup()` falls back to `fwnode->secondary` on `-ENOENT`. `gpio_to_desc()` takes a global GPIO number (`NULL` on failure), while `gpio_device_get_desc()` and `gpiochip_get_desc()` take a chip-relative offset (`0 .. ngpio - 1`), clamp with `array_index_nospec()`, and return `ERR_PTR(-EINVAL)` when out of range. [F374, F375, F458, F486, F498]
- Public `gpiod_*` consumer entry points must validate `desc` with `VALIDATE_DESC()` / `VALIDATE_DESC_VOID()` (treating `NULL` as a no-op returning `0`) before calling internal helpers, except `gpiod_get_direction()` and `gpiod_to_irq()` which must check `validate_desc(desc, __func__) <= 0` and return `-EINVAL` because `0` is a valid return (`GPIO_LINE_DIRECTION_OUT` / `NO_IRQ`). [F376, F377]
- `GPIOD_FLAG_*` constants in `gpiolib.h` are bit numbers (`0`..`19`) for `test_bit()`/`set_bit()` on `desc->flags`, while `gpiod_flags`/`gpio_lookup_flags`/`of_gpio_flags` are bitmasks. `gpiod_direction_output()` and `gpiod_get/set_value*()` use logical values (`ACTIVE_LOW` and open-drain/source applied), while `*_raw*()` use physical levels. Non-sleeping accessors forbid `can_sleep`, and `bitmap_alloc()` in `gpiod_get/set_array_value_complex()` uses `can_sleep ? GFP_KERNEL : GFP_ATOMIC`. [F388, F472, F473, F493]
- `struct gpio_chip` callbacks `.request`, `.direction_input`, `.direction_output`, `.set`, `.set_multiple`, `.get_multiple`, and `.set_config` must return `0` or negative errno, and `.get` / `.get_direction` must return `0`, `1`, or negative errno (larger positive returns become `-EBADE`). `.set_config` must return `-ENOTSUPP` for unsupported parameters, `gpiod_set_config()` requires `pinconf_to_config_packed()`, and `PIN_CONFIG_INPUT_DEBOUNCE` arguments are in microseconds. [F171, F172, F379, F389]
- In `get_multiple` callbacks (`bgpio_get*multiple*`, `pcf857x_get_multiple`), `*bits` must be cleared with `*bits &= ~*mask` before ORing read values. When `array_info` fastpath is used, `gpiod_set_array_value_complex()` mutates `value_bitmap` in-place via `bitmap_xor()` and passes it directly as `bits`. [F50, F440]
- For gpiolib IRQ domains, `irq_data_get_irq_chip_data()` is `struct gpio_chip *gc`, and `irq_desc_get_handler_data()` is `gc` unless `girq->parent_handler_data` or `parent_handler_data_array` (`per_parent_data`) is set. When `gc->can_sleep` is true, `gc->irq.parent_handler` is rejected (`-EINVAL`) and `gpiochip_lock_as_irq()` skips `gpiod_get_direction()`. `IRQF_SHARED` parent IRQs require `parent_handler = NULL`, non-nested `handle_edge_irq` chips must define `.irq_ack`, and `IRQCHIP_IMMUTABLE` chips need `GPIOCHIP_IRQ_RESOURCE_HELPERS`. [F177, F178, F384, F444, F455, F474, F475, F491]
- In `gpio-mmio.c`, callbacks must recover `struct gpio_generic_chip *` via `to_gpio_generic_chip(gc)` (never `gpiochip_get_data(gc)`), drivers must use `gpio_generic_read_reg()`/`gpio_generic_write_reg()`, `cfg->sz` must be a power-of-two byte width (`1`, `2`, `4`, `8`, not bits), and `gc.ngpio` must not exceed `cfg->sz * 8`. [F114, F115, F173, F245]
- `gpiochip_dup_line_label()` returns `NULL` when unrequested/out-of-range, `ERR_PTR(-ENOMEM)` on allocation failure, or a `kfree()`-able string. `struct gpiod_lookup_table.table` arrays must end with `.key == NULL` (using `chip_hwnum == U16_MAX` for line-name lookup), `struct gpiod_hog` arrays must end with `.chip_label == NULL`, and `gpio_device_find()` visitor callbacks like `gpiofind_sysfs_register()` must return `0` to avoid stopping early with an unput `gpio_device_get()` reference. [F383, F411, F431]

## Error Handling
- In `gpiod_direction_input_nonotify()` and `gpiod_direction_output_raw_commit()`, the return value of `gpiochip_get_direction()` (`1` for `GPIO_LINE_DIRECTION_IN`) must not be left in `ret` on success because callers pass non-zero `ret` to `ERR_PTR(ret)`. In `gpiod_get_array()`, `descs->ndescs` must only be incremented after `gpiod_get_index()` succeeds so `gpiod_put_array()` on error never passes an `ERR_PTR` to `gpiod_put()`. [F378, F385]
- Functions called before `gpiochip_add_data_with_key()` sets `gc->gpiodev` (`gpiochip_line_is_valid()`, `gpiochip_get_ngpios()`) must not dereference `gc->gpiodev` unconditionally or call `chip_err()`/`chip_warn()`, and `gpiochip_add_data_with_key()` must suppress `pr_err()` when `ret == -EPROBE_DEFER`. In `gpiochip_sysfs_register()`, `PTR_ERR(data->cdev_base)` / `PTR_ERR(data->cdev_id)` must be saved before `kfree(data)`. [F350, F381, F497]

## Known Pitfalls
- In `gpiod_set_array_value_complex()`, the slowpath loop must skip active-low inversion when `array_info && test_bit(i, array_info->invert_mask)` because the fastpath `bitmap_xor()` already inverted `value_bitmap` in-place for all `invert_mask` pins (including open-drain/open-source pins). In `gpiod_get/set_array_value_complex()`, `mask` must be zeroed with `bitmap_zero(mask, guard.gc->ngpio)` before setting batch bits. [F387, F418]
- `for_each_hwgpio_in_range()` and its wrappers pass `&_label` and `&_i` to `_gpiochip_for_each_data` (`const char **label, int *i`) and call `kfree(_label)` on each step and scope exit; callers must declare `_i` as `int`/`unsigned int` and never reassign `_label` to a non-kmalloc pointer or free it manually. `for_each_gpio_property_name(propname, con_id)` uses `sizeof(propname)`, so `propname` must be a fixed-size `char` array in scope, never a `char *` pointer. [F437, F446]
- In `gpiochip_get_ngpios()`, the `gc->ngpio == 0` check must test the 16-bit `gc->ngpio` field after assigning the `u32` `ngpios` property value so multiples of 65536 that truncate to `0` are caught. In `gpiodev_add_to_list_unlocked()`, `list_for_each_entry_safe(prev, next, &gpio_devices, list)` must check `if (&next->list == &gpio_devices) break;` before reading `next->base`. In `gpiod_unexport()`, `list_for_each_entry()` must record a match in a separate `desc_data = tmp` pointer rather than testing the loop cursor `tmp` after the loop. [F416, F424, F434]
- In `gpio_is_visible()` (`gpiolib-sysfs.c`), `dev_attr` must only be downcast to `struct gpiod_data` via `container_of()` after matching `attr->name` to the corresponding `dir_attr`, `val_attr`, `edge_attr`, or `active_low_attr` member, and `gpio_sysfs_set_active_low()` must save a local copy of `data->irq_flags` before `gpio_sysfs_free_irq()` zeroes it when re-requesting single-edge IRQs. [F396, F442]
