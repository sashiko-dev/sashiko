# MICROCHIP SAMA5D2-COMPATIBLE ADC DRIVER

This component is the Linux Industrial I/O (IIO) driver (`at91-sama5d2_adc`) for Microchip/Atmel SAMA5D2 and SAMA7G5 analog-to-digital converters and its Device Tree channel binding header. It supports single-ended and differential voltage channels, resistive touchscreen position/pressure sensing (SAMA5D2), and on-SoC temperature sensing with NVMEM OTP calibration (SAMA7G5), via direct sysfs reads and hardware- or software-triggered buffer capture using cyclic DMA or interrupt-driven polling.

## Architecture & Data Flow

- Because `IIO_CHAN_INFO_SCALE` reports a fixed denominator of `chan_realbits`, all raw samples in direct, non-DMA, and DMA paths must be left-shifted by `chan_realbits - nbits` via `at91_adc_adjust_val_osr` or `at91_adc_adjust_val_osr_array` before sign extension or buffer push. Each SoC's `platform->chan_realbits` (SAMA5D2 = 14, SAMA7G5 = 16) must equal its voltage channels' `scan_type.realbits`, and `oversampling_avail` must only list ratios whose `nbits` (12..16 for ratios 1..256) is at most `chan_realbits`. [F67, F81, F108]
- In `at91_adc_config_emr`, `oversampling_ratio` must be validated against the first `oversampling_avail_no` entries of `platform->oversampling_avail` before the `switch` statement, and `EMR` oversampling changes and `st->oversampling_ratio` updates must always happen in lockstep via `at91_adc_config_emr`. [F34, F59]
- Before enabling any voltage or temperature channel in `CHER` (in `at91_adc_buffer_prepare` or `at91_adc_read_info_raw`), `at91_adc_cor` must read-modify-write `COR` to set or clear both `BIT(chan->channel)` and `BIT(chan->channel2)` (shifted by `COR_diff_offset`) according to `chan->differential`. [F37]
- `st->dma_st.dma_chan` must be reset to `NULL` whenever `dma_request_chan()` returns an `ERR_PTR` or when the channel is released in `at91_adc_dma_init()` and `at91_adc_dma_disable()`, because the driver tests `st->dma_st.dma_chan != NULL` to check if DMA is enabled. [F26]
- `st->dma_st.rx_buf` is allocated in `at91_adc_dma_init` and freed in `at91_adc_dma_disable` with byte size `DIV_ROUND_UP(AT91_HWFIFO_MAX_SIZE * st->soc_info.platform->nr_channels * 4, PAGE_SIZE) * PAGE_SIZE`, whereas `st->dma_st.rx_buf_sz` holds only the active cyclic transfer size (`sample_size * st->dma_st.watermark`) computed in `at91_adc_dma_start`. `at91_adc_set_watermark()` must clamp `val` to `AT91_HWFIFO_MAX_SIZE`. [F51, F74]
- The cyclic DMA buffer `st->dma_st.rx_buf` is indexed over `0 .. st->dma_st.rx_buf_sz - 1` (an exact multiple of `sample_size`), so `st->dma_st.buf_idx` must be reset to `0` in `at91_adc_dma_start()` and wrapped to `0` when `st->dma_st.buf_idx >= st->dma_st.rx_buf_sz` in `at91_adc_trigger_handler_dma()`. [F52]
- Channel `scan_index` values in `at91_sama5d2_adc_channels` and `at91_sama7g5_adc_channels` are non-contiguous, so scan-mask bits and DT channel specifiers must be resolved via `at91_adc_chan_xlate` / `at91_adc_chan_get`, and scan-mask bitmaps sized to `st->soc_info.platform->max_index + 1`. Because `st->touch_st.channels_bitmask` is a single `unsigned long`, `max_index` and all touchscreen channel indices must remain `< BITS_PER_LONG` (32 on 32-bit). [F76, F102]
- `st->buffer` in `struct at91_adc_state` must use `IIO_DECLARE_BUFFER_WITH_TS(u16, buffer, ...)` sized for at least the maximum channel count (32) to guarantee 8-byte alignment and space for the 64-bit timestamp passed to `iio_push_to_buffers_with_timestamp()` in `at91_adc_trigger_handler_nodma()`. [F54]
- In `at91_adc_buffer_prepare` and `at91_adc_buffer_postdisable`, `at91_adc_current_chan_is_touch(indio_dev)` must be checked and returned on before testing `!(iio_device_get_current_mode(indio_dev) & INDIO_ALL_TRIGGERED_MODES)`. [F57]
- In `at91_adc_interrupt`, the touchscreen data-ready branch must test `(status & AT91_SAMA5D2_ISR_PENS) && ((status & rdy_mask) == rdy_mask)` before the fallback `else if (status & AT91_SAMA5D2_ISR_PENS)` branch, and all touchscreen branches must precede the `iio_buffer_enabled(indio)` branches. [F55]
- `at91_adc_touch_pressure` relies on `st->touch_st.x_pos` having been updated by `at91_adc_touch_x_pos`, so `touch_chan_x` must have a lower scan index than `touch_chan_p` and be read first in `at91_adc_touch_data_handler`. In `at91_adc_no_pen_detect_interrupt`, `st->touch_st.touching` must be set to `false` before calling `at91_adc_touch_data_handler(indio_dev)`. [F41, F42]
- In `at91_adc_trigger_handler_nodma`, the polling loop must initialize `eoc = 0` and wait while `((eoc & mask) != mask) && timeout`, decrementing `timeout` each iteration and returning without pushing data if `!timeout`. [F62]
- In `at91_sama7g5_adc_channels` (or any platform channel table with `temp_sensor = true`), `AT91_SAMA5D2_CHAN_TEMP` must be the final element because `at91_adc_probe()` hides it by setting `indio_dev->num_channels = st->soc_info.platform->max_channels - 1` when `at91_adc_temp_sensor_init()` fails. [F83]
- In `at91_adc_temp_sensor_init()`, the byte length `len` returned by `nvmem_cell_read()` must be validated to be at least `AT91_ADC_TS_CLB_IDX_MAX * 4` before indexing the `u32 *buf` calibration array, and any `enum at91_adc_ts_clb_idx` offset must be `< AT91_ADC_TS_CLB_IDX_MAX`. [F50]
- `at91_adc_trigger_list` must contain `st->soc_info.platform->hw_trig_cnt` hardware trigger descriptors followed at index `hw_trig_cnt` by the software trigger descriptor with `edge_type = IRQ_TYPE_NONE`, because `at91_adc_probe()` scans indices `0` through `hw_trig_cnt` inclusive. [F49]

## Synchronization

- Because `at91_adc_read_info_raw`, `at91_adc_read_temp`, `at91_adc_config_emr`, and `at91_adc_setup_samp_freq` call `pm_runtime_resume_and_get(st->dev)` while holding `st->lock`, `at91_adc_runtime_suspend` and `at91_adc_runtime_resume` must never acquire `st->lock`. [F96]
- When `at91_adc_interrupt` handles `AT91_SAMA5D2_IER_DRDY` for a non-DMA triggered buffer, it must mask `st->irq` with `disable_irq_nosync` before calling `iio_trigger_poll`. When DMA is active (`st->dma_st.dma_chan != NULL`), `at91_adc_buffer_check_use_irq` must return `false` (so `AT91_SAMA5D2_IER_DRDY` is not enabled) and `at91_adc_reenable_trigger` must return without calling `enable_irq(st->irq)` or reading `LCDR`. [F94, F106]
- In `at91_adc_touch_data_handler` (invoked from hardirq handler `at91_adc_interrupt`), touchscreen samples placed in `st->buffer` must not be pushed via `iio_push_to_buffers` directly; instead, `schedule_work(&st->touch_st.workq)` must defer `iio_push_to_buffers` to process-context `at91_adc_workq_handler`. [F93]

## Object Lifetimes

- Triggered buffer setup via `at91_adc_buffer_prepare` (which starts cyclic DMA in `at91_adc_dma_start`) must be invoked from `at91_adc_set_watermark` after `at91_adc_dma_init` has initialized DMA and `st->dma_st.watermark` is set, rather than from an `at91_buffer_setup_ops.preenable` callback. [F1]
- `at91_adc_dma_disable` must call `dmaengine_terminate_sync(st->dma_st.dma_chan)` before freeing `st->dma_st.rx_buf` with `dma_free_coherent` and releasing `st->dma_st.dma_chan` with `dma_release_channel`. Both `at91_adc_dma_init` and `at91_adc_dma_disable` must pass `st->dma_st.dma_chan->device->dev` (never `st->dev` or `&st->indio_dev->dev`) to `dma_alloc_coherent` and `dma_free_coherent`. [F4, F65]
- `at91_adc_configure_touch` and `at91_adc_configure_trigger` each acquire a persistent runtime PM reference via `pm_runtime_resume_and_get(st->dev)` when called with `state == true` and release it via `pm_runtime_put_autosuspend(st->dev)` after clearing hardware registers when called with `state == false`. [F7]
- `at91_adc_probe` enables non-devm resources in the order `st->reg`, `st->vref`, `st->per_clk`, runtime PM, and `iio_device_register(indio_dev)`, and both `at91_adc_probe` error paths and `at91_adc_remove` must unwind them in reverse order (`iio_device_unregister`, `at91_adc_dma_disable`, runtime PM disable, `st->per_clk`, `st->vref`, `st->reg`). Broken by: replacing `iio_device_register` with `devm_iio_device_register` while keeping manual teardown in `at91_adc_remove`. [F11]
- Across system sleep, if `iio_buffer_enabled(indio_dev)` is true, `at91_adc_suspend()` must call `at91_adc_buffer_postdisable()` before writing `AT91_SAMA5D2_CR_SWRST` to `CR`. `at91_adc_resume()` must re-enable resources in reverse suspend order (`pinctrl_pm_select_default_state`, `st->reg`, `st->vref`, `st->per_clk`, `pm_runtime_get_noresume`, `at91_adc_hw_init`, and if buffer enabled, `at91_adc_buffer_prepare` and `at91_adc_configure_trigger_registers(st, true)`), unwinding in LIFO order on failure. [F12, F91]
- `at91_adc_temp_sensor_init` owns the heap buffer returned by `nvmem_cell_read(temp_calib, &len)` and must release it with `kfree(buf)` on both the invalid-length error path and normal completion. [F6]

## API Contracts

- In `at91_adc_read_raw` (`IIO_CHAN_INFO_RAW` and `IIO_CHAN_INFO_PROCESSED`) and `at91_adc_write_raw`, direct mode must be claimed with `iio_device_claim_direct(indio_dev)` before acquiring `st->lock` or accessing registers, and released after unlocking `st->lock`. Callers of `at91_adc_read_info_raw` must hold both `iio_device_claim_direct` and `st->lock`; `at91_adc_read_info_raw` leaves both held while managing its own `pm_runtime_resume_and_get` / `pm_runtime_put_autosuspend` reference and resetting `st->conversion_done = false` on conversion success. [F8, F100]
- `at91_adc_read_position()` and `at91_adc_read_pressure()` must initialize `*val = 0` before returning `-ENODATA`, because `at91_adc_touch_data_handler()` ignores their return status and copies `val` into `st->buffer` even on pen-up when `st->touch_st.touching` is `false`. [F27]
- `at91_adc_update_scan_mode` must reject any `scan_mask` that intersects `st->touch_st.channels_bitmask` without being a subset of `st->touch_st.channels_bitmask`. [F43]
- `at91_adc_adjust_val_osr_array` receives `len` in bytes (`sample_size`) while indexing `buf` as `u16 *buf_u16`, so its loop bound must divide `len` by `sizeof(u16)` (2) rather than iterating `len` elements. [F73]
- In `at91_adc_dma_start`, the cyclic DMA buffer size `st->dma_st.rx_buf_sz` must be computed by summing `chan->scan_type.storagebits / 8` across active channels and multiplying by `st->dma_st.watermark`, rather than using `indio_dev->scan_bytes` (which includes timestamp padding). [F105]
- In `at91_adc_dma_init`, the DMA slave source address `config.src_addr` must be computed from the physical resource address `st->dma_st.phys_addr` (saved from `res->start` in `at91_adc_probe`) plus `layout->LCDR`, never from the ioremapped virtual address `st->base`. [F97]
- Platform PM and remove callbacks receive `&pdev->dev` where driver data is `struct iio_dev *` (`dev_get_drvdata` / `platform_get_drvdata`), whereas IIO buffer sysfs attribute callbacks (`at91_adc_get_fifo_state`, `at91_adc_get_watermark`) receive `&indio_dev->dev` and must obtain `struct iio_dev *` via `dev_to_iio_dev(dev)`. [F78]

## Error Handling

- When `at91_adc_buffer_prepare` fails inside `at91_adc_set_watermark`, `at91_adc_set_watermark` must call `at91_adc_dma_disable(st)` to tear down the DMA channel and coherent buffer acquired by `at91_adc_dma_init`. [F2]
- In `at91_adc_dma_start`, if `dma_submit_error(cookie)` indicates that `dmaengine_submit(desc)` failed, `dmaengine_terminate_async(st->dma_st.dma_chan)` must be called before returning the error. [F5]
- In `at91_adc_read_temp`, after `at91_adc_temp_sensor_configure(st, true)` overrides the ADC sample rate and oversampling settings, every exit path (including VBG read failure) must call `at91_adc_temp_sensor_configure(st, false)` and `pm_runtime_put_autosuspend(st->dev)` while still holding `st->lock`. [F9]
- `at91_adc_allocate_trigger()` must return an `ERR_PTR`-encoded error on all failure paths (converting `NULL` from `devm_iio_trigger_alloc()` into `ERR_PTR(-ENOMEM)`), because `at91_adc_buffer_and_trigger_init()` checks `st->trig` solely with `IS_ERR()`. [F24]
- In `at91_adc_read_info_raw()`, `ret = at91_adc_adjust_val_osr(st, val)` must only be called when the preceding read or wait succeeded (`ret > 0`), because `at91_adc_adjust_val_osr()` returns `IIO_VAL_INT` and would overwrite a negative error code in `ret`. [F25]
- In `at91_adc_touch_pos()` and `at91_adc_touch_pressure()`, the hardware divisor fields extracted from `XPOSR`/`YPOSR` (`scale`) and `PRESSR` (`z1`) must be checked for zero before dividing. [F69]
- In `at91_adc_trigger_handler_dma`, hardware conversion overrun (`AT91_SAMA5D2_IER_GOVRE` in `ISR`) must be logged with `pr_info_ratelimited`, whereas in `at91_adc_temp_sensor_init`, a missing `temperature_calib` NVMEM cell (`-ENOENT`) must not log an error via `dev_err`. [F109]

## External Contracts

- The `scan_index` values in `at91_sama5d2_adc_channels` (including even-only indices 12..22 for differential channels and 24..26 for touch channels) and `at91_sama7g5_adc_channels` (including 31 for `AT91_SAMA7G5_ADC_TEMP_CHANNEL`), along with `include/dt-bindings/iio/adc/at91-sama5d2_adc.h`, define the Device Tree (`at91_adc_fwnode_xlate`) and IIO userspace ABI and must not be renumbered. [F47]
- In `at91_adc_probe()`, a missing `atmel,trigger-edge-type` property must default `edge_type` to `IRQ_TYPE_NONE` (selecting the software trigger with `hw_trig = false`), and `at91_adc_buffer_and_trigger_init()` and `at91_adc_set_watermark()` must skip hardware trigger allocation, FIFO attributes, and DMA setup when `!st->selected_trig->hw_trig`. [F85]

## Known Pitfalls

- On platforms where `st->soc_info.platform->layout->EOC_IDR` is non-zero (`sama7g5_layout`), `at91_adc_eoc_dis()` must not write to `EOC_IDR` during normal conversion teardown due to hardware errata, whereas `at91_adc_eoc_ena()`, `at91_adc_irq_status()`, and `at91_adc_irq_mask()` must use `EOC_IER`, `EOC_ISR`, and `EOC_IMR` when present. [F82]
- In `at91_adc_read_info_raw()`, when `chan->type == IIO_TEMP`, `AT91_SAMA5D2_TEMPMR_TEMPON` must be written to `TEMPMR` only after enabling the channel in `CHER` (and cleared to `0U` before disabling the channel in `CHDR`), because setting `TEMPMR.TEMPON` with no channels enabled in `CHER` triggers a spurious `DRDY` interrupt. [F88]
- To clear pending hardware conversion and overrun status, `LCDR` must be read in `at91_adc_read_info_raw()` and `at91_adc_reenable_trigger()`, and `at91_adc_buffer_postdisable()` must read `OVER` and each disabled channel's data register (`chan->address`) when DMA is used before calling `dmaengine_terminate_sync()`. [F89]
- `iio_trigger_validate_own_device(indio->trig, indio)` returns `0` when the active trigger belongs to `indio` and a negative errno when it is an external trigger, so callers (`at91_adc_buffer_check_use_irq()` and `at91_adc_trigger_handler()`) test it as non-zero when the trigger is NOT owned by this ADC. [F32]
- When bridging between `u16` and `int` out-parameters across `at91_adc_read_position()`, `at91_adc_read_pressure()`, and `at91_adc_adjust_val_osr()`, callers (`at91_adc_read_info_raw()` and `at91_adc_adjust_val_osr_array()`) must copy through a width-matched local variable rather than casting between `u16 *` and `int *`. [F53]
- In `at91_adc_read_temp()`, `vtemp` must be widened to `u64` before multiplying by `clb->p6` (`u32`), and the 64-bit calibration divisions must use `DIV_ROUND_CLOSEST_ULL()` rather than `/`. In `at91_adc_trigger_handler_dma()`, dividing the 64-bit signed timestamp delta `ns - st->dma_st.dma_ts` by `sample_count` must use `div_s64()` rather than `/`. [F68, F71]
