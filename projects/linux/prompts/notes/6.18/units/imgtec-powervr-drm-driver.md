# IMGTEC POWERVR DRM DRIVER

This unit implements the DRM driver for Imagination Technologies PowerVR (Rogue Series 6+) GPUs, covering device init, firmware management (META, MIPS, RISC-V), GEM/VM mapping, free lists, HWRT datasets, contexts, job scheduling via circular command buffers (KCCB, FWCCB, CCCB), and debugfs trace.

## Architecture & Data Flow
- `pvr_ccb` (`KCCB`, `FWCCB`) `write_offset`, `read_offset`, and `wrap_mask` are command slot indices, and `pvr_kccb_capacity()` caps usable slots at `slot_count - 1`. In contrast, `pvr_cccb` offsets and `size` are in bytes, `size` must be a power of two (`1 << size_log2`) for `get_ccb_space()`, and every command sequence must fit `size + PADDING_COMMAND_SIZE <= pvr_cccb->size / 2` and leave `PADDING_COMMAND_SIZE` bytes at buffer end or emit `ROGUE_FWIF_CCB_CMD_TYPE_PADDING` and wrap to 0. [F85, F86, F127, F134]
- Free list page counts (`initial_num_pages`, `max_num_pages`, `grow_num_pages`, `ready_pages`) are in 4 KB PM pages (`ROGUE_BIF_PM_PHYSICAL_PAGE_SIZE`) and must align to `FREE_LIST_ALIGNMENT` (4 pages), while `pvr_free_list_insert_pages_locked()` takes `@offset` in bytes. [F55, F83]
- Free list entries grow downward (`start_page = max_pages - current_pages - num_pages` in `pvr_free_list_insert_node_locked()`): `free_list_fw_init()` and `pvr_free_list_reconstruct()` subtract `ready_pages` from `current_pages` (`current_stack_top = current_pages - 1`), whereas `pvr_free_list_process_grow_req()` must add `ready_pages` back to `current_pages` and zero `ready_pages` before calling `pvr_free_list_grow()`. [F61, F84]
- Free list backing GEM objects must have `DRM_PVR_BO_PM_FW_PROTECT` set, `DRM_PVR_BO_ALLOW_CPU_USERSPACE_ACCESS` clear, and `size >= max_num_pages * FREE_LIST_ENTRY_SIZE`. In `pvr_gem_object_flags_validate()`, each `combo` in `invalid_combinations` is tested with `(flags & combo) == combo` (not `flags & combo`), and `pvr_gem_mmap()` rejects mmap with `-EINVAL` unless `DRM_PVR_BO_ALLOW_CPU_USERSPACE_ACCESS` is set. [F97, F176]
- `pvr_context::queues` is a union discriminated by `ctx->type`, so accesses must switch on `ctx->type` or use `pvr_context_get_queue_for_job()`. Similarly, `job->hwrt` is non-NULL only for geometry/fragment jobs and NULL for compute/transfer jobs; job-type-agnostic helpers must guard `job->hwrt` dereferences. [F46, F50]
- In `struct pvr_fw_mem`, `core_code_obj`, `core_data_obj`, `core_code`, and `core_data` are optional and NULL when absent; callers must check non-NULL before calling `pvr_fw_object_*` helpers (which dereference `fw_obj->gem`). `fw_mem->code_obj` must be mapped at offset 0 of the FW heap via `pvr_fw_object_create_and_map_offset(pvr_dev, 0, ...)`, making FW address/offset 0 invalid for any other object. [F49, F87]
- In `pvr_fw_get_device_info()`, `pvr_device_info_set_common()`, and `pvr_device_info_set_features()`, mask/param sizes are counts of `u64` words (not bytes): `const u64 *` pointers advance by word count, and bits are tested with `bitmask[i >> 6] & BIT_ULL(i & 63)` for `i < min(bitmask_size * 64, mapping_max)`. [F122, F129]
- In `pvr_device_info_set_features()`, `param_idx` increments only when a set feature bit has a non-zero `features_mapping[i].value_offset`, must be checked with `param_idx < feature_param_size`, and writes via `*(u64 *)((u8 *)pvr_dev + value_offset)`, requiring all value fields in `struct pvr_device_features` to have type `u64`. [F89, F109, F128]
- Every quirk ID in `pvr_dev_query_quirks_get()` must have a matching `case` in `pvr_device_has_uapi_quirk()`, and every enhancement ID in `pvr_dev_query_enhancements_get()` must have a matching `case` in `pvr_device_has_uapi_enhancement()`. All handle XArrays in `struct pvr_file` and ID XArrays in `struct pvr_device` must use `XA_FLAGS_ALLOC1` so 0 remains a reserved sentinel. [F74, F92]

## Synchronization
- Lookups in `pvr_dev->ctx_ids` (`pvr_context_lookup_id()`) and `pvr_dev->free_list_ids` (`pvr_free_list_lookup_id()`) must hold `xa_lock` and call `kref_get_unless_zero()`, because entries are erased inside `pvr_context_release()` and `pvr_free_list_release()` after `ref_count` hits zero. Lookups in per-file handle XArrays (`ctx_handles`, `free_list_handles`, `hwrt_handles`) must hold `xa_lock` across both `xa_load()` and `kref_get()`. [F20, F21]
- In `pvr_destroy_contexts_for_file()`, `pvr_dev->ctx_list_lock` protects `pvr_file->contexts`; each entry must be unlinked with `list_del_init(&ctx->file_link)` and pinned via `pvr_context_get_if_referenced(ctx)` before dropping `ctx_list_lock` to call sleeping `pvr_vm_unmap_all()` and `pvr_context_put()`. `pvr_context_put()` must never drop the final reference from interrupt context because `pvr_context_release()` sleeps. [F23, F155]
- `pvr_dev->kccb.ccb.lock` protects `ccb.ctrl`, `ccb.ccb`, `kccb.reserved_count`, and `kccb.waiters` (which `pvr_kccb_wake_up_waiters()` must iterate with `list_for_each_entry_safe()` until `available_count == 0`). [F25, F104]
- In `pvr_kccb_send_cmd_reserved_powered()`, populating `kccb[old_write_offset]` and clearing `kccb.rtn[old_write_offset]` must precede `WRITE_ONCE(ctrl->write_offset, new_write_offset)` by `mb()`, and `pvr_fw_mts_schedule()` must bracket `ROGUE_CR_MTS_SCHEDULE` with `wmb()` and `mb()`. Before `pvr_cccb_send_kccb_kick()` or `pvr_cccb_send_kccb_combined_kick()`, callers must reserve a KCCB slot and order prior CCCB writes with `wmb()`. [F26, F27]
- `pvr_fwccb_process()` must copy `fwccb[read_offset]` by value and advance `ctrl->read_offset` before dropping `pvr_dev->fwccb.lock` to call `process_fwccb_command()`. In `pvr_free_list_release()`, if `pvr_fw_structure_cleanup()` returns `-EBUSY`, `pvr_fwccb_process()` must be called to drain pending FWCCB requests before retrying cleanup and freeing `mem_block_list`. [F33, F67]
- `pvr_fw_object_fw_map()` and `pvr_fw_object_fw_unmap()` must hold `fw_dev.fw_mm_lock` when mutating `fw_obj->fw_mm_node` in `fw_dev->fw_mm`, but must drop `fw_mm_lock` before calling `fw_dev->defs->vm_map()` or `vm_unmap()`. `fw_dev.fw_objs.lock` protects `fw_objs.list`: a `pvr_fw_object` is added only after its GEM object is mapped and `fw_obj->init()` completes, and `fw_obj->init()` must never create/destroy a `pvr_fw_object` or acquire `fw_objs.lock` because `pvr_fw_hard_reset()` calls `fw_obj->init()` under `fw_objs.lock`. [F30, F31, F166]
- `pvr_gem_object_vmap()` and `pvr_gem_object_vunmap()` must hold `dma_resv_lock(obj->resv, NULL)` and sync `shmem_obj->sgt` for `PVR_BO_CPU_CACHED` objects. In `pvr_gem_object_create()`, `shmem_obj->map_wc`, `pvr_obj->flags`, and `drm_gem_shmem_get_pages_sgt(shmem_obj)` must be set up before `pvr_gem_object_zero()`, and both `pvr_gem_object_zero()` and `pvr_free_list_insert_pages_locked()` must execute `wmb()` before `pvr_gem_object_vunmap()`. [F36, F168, F169]
- `free_list->lock` protects `current_pages`, `ready_pages`, `mem_block_list`, and `hwrt_list`. `pvr_dev->queues.lock` protects `queues.active` and `queues.idle`, and must be held in `pvr_device_process_active_queues()` across splicing `queues.active` and calling `pvr_queue_process()`. [F38, F167]
- In `pvr_submit_jobs()`, `pvr_mmu_flush_exec()` and `prepare_job_syncs_for_each()` must run before `prepare_job_resvs_for_each()` locks `ctx->fw_obj->gem` and `hwrt->fw_obj->gem` via `drm_exec`, and those locks must stay held across `pvr_jobs_link_geom_frag()`, `update_job_resvs_for_each()`, and `push_jobs()`. [F170]
- `pvr_device_irq_handler()` must only perform non-sleeping MMIO checks and return `IRQ_WAKE_THREAD`, deferring mutexes, runtime PM, and CCB/queue work to `pvr_device_irq_thread_handler()`. Outside the IRQ handler, scheduler workqueue, or reset path, any code submitting KCCB commands (e.g., `pvr_fw_structure_cleanup()`, `update_logtype()`) must hold `down_read(&pvr_dev->reset_sem)` and check `drm_dev_enter()`. [F163, F164]

## Object Lifetimes
- `pvr_kccb_reserve_slot()` always consumes `@f` (from `pvr_kccb_fence_alloc()` with `base` at offset 0 and `fence->ops == NULL`): if a slot is available it frees `@f` via `pvr_kccb_fence_put(f)`, increments `kccb.reserved_count`, and returns `NULL`; otherwise it initializes `@f`, queues it on `kccb.waiters`, and returns an extra `dma_fence_get()` reference. Callers must clear their pointer to `@f` and always release KCCB fences via `pvr_kccb_fence_put()`. Every reserved slot must be balanced by `pvr_kccb_send_cmd_reserved_powered()` or `pvr_kccb_release_slot()`. [F2, F4, F42, F132]
- In `pvr_jobs_link_geom_frag()`, pairing `geom_job` and `frag_job` via `paired_job` must free and null `frag_job->kccb_fence` via `pvr_kccb_fence_put()`, take `pvr_job_get(geom_job)` to match `pvr_job_put(job->paired_job)` when `frag_job` is freed, and increment `i++` to skip `frag_job`; also, `get_last_queued_job_scheduled_fence()` returns a `dma_fence_get()` reference that `drm_sched_job_add_dependency()` consumes on both success and failure. [F11, F13, F107]
- In `pvr_submit_jobs()`, `pvr_job_data_fini()` must be passed `jobs_alloced` rather than `args->jobs.count`, because per-job loops overwrite `args->jobs.count` with the failing job index `i` for userspace. [F12, F95]
- `pvr_gem_object_into_handle()` consumes the caller's `pvr_obj` reference and writes `*handle` only on success; on error, the caller retains ownership of `pvr_obj`. Conversely, in `pvr_ioctl_vm_map()`, `pvr_gem_object_from_handle()` and `pvr_vm_context_lookup()` each return a reference that the ioctl must drop on both success and failure because `pvr_vm_map()` takes its own reference. [F1, F18]
- In `pvr_context_create()`, once `ctx` is inserted into `pvr_dev->ctx_ids`, any subsequent failure must clean up via `pvr_context_put(ctx)` rather than jumping to manual teardown labels. Because `pvr_fw_hard_reset()` zeroes every `pvr_fw_object` without `PVR_BO_FW_NO_CLEAR_ON_RESET` and re-runs `fw_obj->init(cpu_ptr, fw_obj->init_priv)`, the `init_priv` backing state (`ctx->data`, `hwrt->common`, `hwrt_data->data`) must stay valid for the lifetime of `fw_obj`. [F5, F70]
- `pvr_hwrt_data` delegates `get()`/`put()` to `hwrt->hwrt_dataset->ref_count`, so `hwrt->data[i].hwrt_dataset = hwrt` must be set before exposing the dataset in `hwrt_handles`, and `pvr_hwrt_data_lookup()` must drop the dataset reference if `index >= ARRAY_SIZE(hwrt_dataset->data)`. In `pvr_hwrt_dataset_create()` and `pvr_hwrt_dataset_release()`, `hwrt_data_fini_fw_structure()` must unlink each `hwrt_data` from `hwrt->free_lists[0]` before `hwrt_fini_kernel_structure()` drops the free list references, and must destroy `raa_obj` and `srtc_obj` only when `hwrt->max_rts > 1`. [F14, F15]
- In `pvr_device_fini()`, `pvr_device_irq_fini()` must run before `pvr_device_gpu_fini()`, which must run `pvr_fw_fini(pvr_dev)` before dropping `pvr_dev->kernel_vm_ctx` (created only when `processor_type != PVR_FW_PROCESSOR_TYPE_MIPS`). In `pvr_fw_fini()`, every `pvr_fw_object` on `fw_dev.fw_objs.list` must be destroyed before `drm_mm_takedown(&fw_dev->fw_mm)` and `fw_dev->defs->fini()`. [F16, F17, F141]
- In `pvr_fw_process()` and `pvr_fw_cleanup()`, both host shadow buffers (`fw_mem->code`, `data`, `core_code`, `core_data`) and FW objects (`code_obj`, `data_obj`, and optional `core_code_obj`, `core_data_obj`) must be freed even after their CPU mappings are unmapped and local pointers set to NULL. [F9]

## API Contracts
- Creation/vmap helpers (`pvr_gem_object_create()`, `pvr_gem_object_vmap()`, `pvr_fw_object_create_and_map()`, `pvr_free_list_create()`, `pvr_hwrt_dataset_create()`) return `ERR_PTR`, whereas handle/ID lookups (`pvr_gem_object_from_handle()`, `pvr_context_lookup()`, `pvr_hwrt_data_lookup()`) and `pvr_build_firmware_filename()` return `NULL`. `get_fw_obj_size()` returns a positive size or `-EINVAL` and must be checked in a signed `int` before assigning to unsigned types. [F40, F43, F44]
- `pvr_load_gpu_id()`, `pvr_request_firmware()`, and `pvr_fw_validate_init_device_info()` must run before any `PVR_HAS_FEATURE()`, `PVR_FEATURE_VALUE()`, `PVR_HAS_QUIRK()`, or `PVR_HAS_ENHANCEMENT()` call; callers must use these macros (checking `PVR_FEATURE_VALUE()`'s return code) rather than reading `pvr_dev->features`, `quirks`, or `enhancements` directly. [F139, F145]
- `pvr_kccb_send_cmd_powered()` and `pvr_kccb_send_cmd_reserved_powered()` require a runtime PM reference on `pvr_dev`; callers without one must use `pvr_kccb_send_cmd()`. Safety event registers must only be accessed when `pvr_dev->has_safety_events` is true, and `pvr_device_irq_thread_handler()` must bracket safety event handling with `pvr_power_get()`/`put()`. [F146, F153, F154]
- `pvr_cccb_write_command_with_header()` is unlocked; callers must serialize access and check `pvr_cccb_cmdseq_fits()` first. In `pvr_cccb_send_kccb_combined_kick()`, when `@frag_is_pr` is true, pass `NULL` instead of `@hwrt` to `fill_cmd_kick_data()` for the fragment kick so the HWRT cleanup control structure is not attached twice. [F28, F60]
- `pvr_ccb_init()` takes `@num_cmds_log2` and `@cmd_size`, whereas `pvr_cccb_init()` takes `@size_log2` (total byte size log2), and `pvr_cccb_get_size_of_cmd_with_hdr()` requires 8-byte aligned `@cmd_size`. `pvr_fw_object_create_and_map_offset()` takes a 32-bit byte offset from `fw_dev.fw_mm_base`, whereas `pvr_fw_object_fw_map()` takes a 64-bit GPU VA where `0` allocates dynamically from the main FW heap. [F56, F58]
- UAPI ioctls that create, map, query, or submit resources must guard execution with `drm_dev_enter()`/`drm_dev_exit()`, whereas destroy ioctls omit `drm_dev_enter()`. Every UAPI ioctl/query must reject non-zero `_padding_*` or unused flags and validate union padding with `PVR_IOCTL_UNION_PADDING_CHECK()` (which requires the union member to start at offset 0 of the union). [F137, F144, F178]
- Userspace BO creation must reject `args->flags & ~DRM_PVR_BO_FLAGS_MASK` and `args->size > SIZE_MAX`, and `pvr_ioctl_vm_map()` must check `check_add_overflow(args->offset, args->size, &offset_plus_size)`. `pvr_get_uobj_array()` leaves `*out` unmodified when `in->count == 0`, so callers must pre-zero `*out` before passing it to `kvfree()`. [F45, F81, F179]

## Error Handling
- When an `ERR_PTR`-returning call is assigned to a struct field whose teardown checks for non-NULL (`ctx->queues.*`, `fw_obj->gem`, `trace_buffer->buf`, `job_data_out[i].job`), reset the field to `NULL` before jumping to cleanup. In `pvr_job_data_init()`, if `PVR_UOBJ_GET_ARRAY()` fails after `create_job()` at index `i`, set `*job_count = i` before `i++` for `pvr_job_data_fini(job_data_out, i)`. In `pvr_hwrt_dataset_create()`, loop counter `i` for `hwrt->data[i]` must be signed so `while (--i >= 0)` terminates. [F51, F106, F108]

## External Contracts
- Entries in `rogue_fw_log_sfgroups`, `stid_fmts[]` (max 20 32-bit integer specifiers for `seq_printf()`), `drm_pvr_dev_query`, and `drm_pvr_heap_id` must only be appended. [F96, F133]

## Known Pitfalls
- PowerVR register masks (`ROGUE_CR_*_CLRMSK`) are inverted clear-masks (`0`s in the target field); masking a field requires `~ROGUE_CR_*_CLRMSK`. `rogue_slc_init()` must update `ROGUE_CR_SLC_CTRL_MISC` via 32-bit `pvr_cr_read32()`/`write32()` while preserving `ENABLE_PSG_HAZARD_CHECK_EN`. [F57, F73]
- `fill_cmd_kick_data()` appends to `k->cleanup_ctl_fw_addr[k->num_cleanup_ctl++]` without initializing `num_cleanup_ctl`, so callers must zero-initialize `struct rogue_fwif_kccb_cmd`. In `pvr_get_uobj_array()`/`pvr_set_uobj_array()`, widen `u32 obj_size` to `unsigned long` before multiplying by `count`, and allocate with `kvmalloc_array()`. [F54, F119]
- In `pvr_mips_fw_process()`, translate each 4 KB FW page (`page_nr * ROGUE_MIPSFW_PAGE_SIZE_4K`) into a host page index (`>> PAGE_SHIFT`) and offset (`& ~PAGE_MASK`) on `mips_data->pt_dma_addr`, and size `PVR_MIPS_PT_PAGE_COUNT` with `DIV_ROUND_UP(..., PAGE_SIZE)`. In `pvr_meta_fw_process()`, `ROGUE_FW_BOOTLDR_CONF_OFFSET` (`0x80`) is in `u32` dwords (`((u32 *)fw_code_ptr) + ROGUE_FW_BOOTLDR_CONF_OFFSET`), and skipping an L1 block in `process_ldr_command_stream()` must `goto next_block` rather than `continue`. [F93, F112, F123, F136]
- In `get_cr_isp_mtile_size_val()` and `get_cr_te_aa_val()`, the `samples >= 2`, `>= 4`, and `>= 8` checks must remain sequential `if` statements (not `else if`) so bits and shifts accumulate. [F100]
