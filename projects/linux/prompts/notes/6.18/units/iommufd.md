# IOMMUFD

IOMMUFD provides a userspace character device (`/dev/iommu` and `/dev/vfio/vfio` compatibility) and in-kernel driver APIs for managing IOMMU hardware objects, I/O Address Spaces (IOAS), hardware page tables (paging and nested), vIOMMUs, vDevices, hardware queues, and I/O page fault/event queues. It maintains tiered page pinning and IOVA-to-PFN mappings across shared `iopt_pages`, interval trees of `iopt_area`s, and attached `iommu_domain`s or in-kernel accessors (`iommufd_access`).

## Architecture & Data Flow

- In `io_pagetable` trees (`area_itree`, `allowed_itree`, `reserved_itree`), `node.start` and `node.last` are inclusive byte IOVAs; in `iopt_pages` trees (`access_itree`, `domains_itree`) and `iopt_area::pages_node`, they are inclusive 0-based page indices. `last_*` variables are inclusive `[start, last]`, whereas `pfn_reader::batch_end_index`, `pfn_reader_user::upages_end`, and `pfn_batch::end` are exclusive `[start, end)`. [F57, F84]
- Because an `iopt_area` can start at a non-zero sub-page `area->page_offset` within its first page (`iopt_area_index(area)`), `iopt_area_index_to_iova()`, `batch_from_domain()`, `raw_pages_from_domain()`, and `batch_to_domain()` must apply `area->page_offset` only on the first page index and reset `page_offset` to `0` thereafter. [F87]
- Every `iopt_area` must be allocated via `iopt_area_alloc()` (`RB_CLEAR_NODE()`). When `iopt_area_split()` replaces `area` with `lhs` and `rhs`, if `area->storage_domain` is set it must also replace `area->pages_node` with `lhs->pages_node` and `rhs->pages_node` in `pages->domains_itree`, copy `storage_domain` to both, and increment `rhs->pages->kref`. [F48, F61]
- `iopt_table_remove_domain()` must compact `iopt->domains` into `[0, iopt->next_domain_id)` before `iopt_unfill_domain()`, which uses `xa_load(&iopt->domains, 0)` to reassign `area->storage_domain` or remove `area->pages_node`. Mutations to `iopt->domains`, `iopt->access_list`, or `iopt->disable_large_pages` must recalculate `iopt->iova_alignment` under write-locked `domains_rwsem` and `iova_rwsem` (reverting `disable_large_pages` on failure). [F62, F63]
- In `interval_tree_double_span_iter_update()`, `itrees[0]` (`access_itree`) takes priority over `itrees[1]` (`domains_itree`) and `iter->last_used` is clamped to `min(iter->spans[i].last_used, last_hole)`. In `pfn_reader_next()`, `interval_tree_double_span_iter_next(&pfns->span)` must only be called when `pfns->batch_end_index == pfns->span.last_used + 1`. [F102, F103]
- In `__iopt_area_unfill_domain()`, `iopt_area_unpin_domain()`, and `iopt_area_unfill_domains()`, all attached `iommu_domain`s must unmap the IOVA range via `iopt_area_unmap_domain_range()` before `batch_unpin()` unpins the pages. Whenever `read_and_clear_dirty()` is called without `IOMMU_DIRTY_NO_CLEAR`, `iommu_iotlb_sync()` must follow. [F164, F167]
- Bound devices (`iommufd_device_bind()`) must support `IOMMU_CAP_CACHE_COHERENCY` and claim DMA ownership before `iommufd_object_finalize()`. IOAS protection masks must include `IOMMU_CACHE`, and `iommufd_hwpt_paging_alloc()` must run `iommufd_hwpt_paging_enforce_cc()` and optional `immediate_attach` before `iopt_table_add_domain()`. [F139, F141, F166]
- Check `hwpt->obj.type` or use `find_hwpt_paging()` before `to_hwpt_paging()` or `to_hwpt_nested()`. In `iommufd_viommu_alloc_hwpt_nested()`, set both `hwpt_nested->viommu = viommu` and `hwpt_nested->parent = viommu->hwpt`, while `iommufd_hwpt_nested_destroy()` decrements only `viommu->obj.users`. [F51, F111]
- Internal `iommufd_access` objects leave `access->ictx` and `access->ops` NULL; check `!iommufd_access_is_internal(access)` before using either. `iommufd_access_change_ioas()` must reject `access->ioas != access->ioas_unpin` (`-EBUSY`), clear `access->ioas = NULL` while keeping `access->ioas_unpin = cur_ioas` before dropping `ioas_lock` for `ops->unmap()`, and update both to `new_ioas` afterward. [F53, F70]
- In `iommufd_ioas_change_process()`, the first loop must zero `pages->last_npinned` after accumulating `all_npinned`, the error path must restore `last_npinned = npinned`, and the final loop must call `change_mm(pages)` so shared `iopt_pages` are handled once. Check `pages->type` (`IOPT_ADDRESS_USER` vs `IOPT_ADDRESS_FILE`) before accessing `uptr` or `file`/`start`. [F106, F138]
- `veventq->lost_events_header` is embedded and uncounted in `veventq->num_events`: `iommufd_veventq_deliver_fetch()` must heap-copy it, `iommufd_veventq_fops_read()` must not decrement `num_events` for it, and `iommufd_veventq_abort()` must not `kfree()` it. `iommufd_viommu_report_event()` must `kzalloc()` events. [F49, F72]

## Synchronization

- Lock ordering is strictly `iopt->domains_rwsem` -> `iopt->iova_rwsem` -> `pages->mutex` -> `pages->source_mm->mmap_lock`. In `update_mm_locked_vm()`, if `user && user->locked` is non-zero, release `mmap_read_lock(pages->source_mm)` and set `user->locked = 0` before taking `mmap_write_lock(pages->source_mm)`. [F27, F157]
- `iommufd_lock_obj()` must increment `obj->users` before `obj->wait_cnt` (under `xa_lock(&ictx->objects)` unless `obj->users` is held), and `iommufd_put_object()` must decrement `obj->users` before `obj->wait_cnt`. `ictx->vfio_ioas` holds no refcount; lock it via `iommufd_lock_obj()` under `xa_lock(&ictx->objects)` in `get_compat_ioas()`, and clear `ictx->vfio_ioas = NULL` under `xa_lock` in `iommufd_object_remove()`. [F24, F71]
- Callers of `iommufd_hwpt_paging_alloc()` must hold `ioas->mutex` until after finalize or abort, and `iommufd_hwpt_paging_abort()` must `list_del_init(&hwpt_paging->hwpt_item)` under `ioas->mutex`. Conversely, `iommufd_hw_pagetable_put()` must only be called after releasing `ioas->mutex` and `igroup->lock`. [F6, F26]
- `area->storage_domain` and `area->pages_node` are protected by `area->pages->mutex`; `iopt_unfill_domain()` must update/clear `area->storage_domain` under `pages->mutex` before unmapping. Lockless reads of `pages->pinned_pfns` (`batch_from_xarray()`, `iopt_pages_fill_from_xarray()`) require `pages->mutex` (with the range in `access_itree`), `rcu_read_lock()`, and `xas_retry()`. [F31, F163]
- Modifying `area->num_accesses` requires both `iopt->iova_rwsem` and `area->pages->mutex`. Before calling `access->ops->unmap()`, release `access->ioas_lock`, `iova_rwsem`, `domains_rwsem`, and `xa_lock(&ioas->iopt.access_list)`. In `iopt_unmap_iova_range()`, set `area->prevent_access = true` before dropping locks for `iommufd_access_notify_unmap()`, and reset `tries = 0` only when `area_first != start` (max 100 retries before `-EDEADLOCK`). [F29, F101, F152]
- `iommufd_take_all_iova_rwsem()` holds `down_write(&ictx->ioas_creation_lock)` while locking all `ioas->iopt.iova_rwsem` in ascending ID order; `iommufd_ioas_alloc_ioctl()` must hold `down_read(&ucmd->ictx->ioas_creation_lock)` around `iommufd_object_finalize()`. [F33]
- `idev->igroup->lock` protects `idev->vdev` and `idev->destroying`: `iommufd_vdevice_alloc_ioctl()` must check `!idev->destroying && !idev->vdev` under `igroup->lock`, and `iommufd_device_remove_vdev()` must set `idev->destroying = true` and drop `igroup->lock` before `iommufd_object_tombstone_user()`. [F34]
- `iommufd_viommu_find_dev()` requires `xa_lock(&viommu->vdevs)` across the call and use of `dev`. Allocations under `veventq->common.lock` (`iommufd_viommu_report_event()`, `iommufd_veventq_deliver_fetch()`) must use `GFP_ATOMIC`, and both `veventq->common.lock` and `fault->common.lock` (nested inside `fault->mutex`) must be dropped before `copy_to_user()`, `xa_alloc(..., GFP_KERNEL)`, or `iopf_group_response()`. `iommufd_hwpt_detach_device()` and `iommufd_hwpt_replace_device()` must detach/replace the IOMMU attach handle before `iommufd_auto_response_faults()`. [F35, F36, F149, F150]
- `iommufd_fops_mmap()` must hold `mtree_lock(&ictx->mt_mmap)` while looking up `immap` and calling `refcount_inc_not_zero(&immap->owner->users)`, dropping that ref on error. After dropping `xa_lock(&ictx->groups)` in `iommufd_get_group()`, relocking must loop on `__xa_cmpxchg()` and `iommufd_group_try_get()`. [F25, F37]

## Object Lifetimes

- `_iommufd_object_alloc()` reserves `XA_ZERO_ENTRY`; do not call `iommufd_object_finalize()` until all fallible steps and `iommufd_ucmd_respond()` succeed (else call `iommufd_object_abort[_and_destroy]()`). fd-backed objects holding a `users` ref must set `IOMMUFD_FILE_OFFSET` and defer `fd_install()` until all fallible steps succeed. [F20, F22]
- `iommufd_device_do_replace()` must check `iommufd_device_is_attached(idev, pasid)`, return `NULL` when `hwpt == old_hwpt`, and on replacement add `num_devices` to `hwpt->obj.users`, subtract `num_devices - 1` from `old_hwpt->obj.users`, and return `old_hwpt` for `iommufd_device_change_pt()` to put after unlocking. [F9, F40, F67]
- `iommufd_vdevice_alloc_ioctl()` transfers the `iommufd_get_device()` reference (`users` and `wait_cnt`) to `vdev->idev`, and `iommufd_vdevice_destroy()` must release it via `iommufd_put_object()` after `iommufd_vdevice_abort()` clears `idev->vdev = NULL` under `igroup->lock`. [F11]
- `iommufd_hw_queue_alloc_phys()` must free `pages` with `kvfree()` and unwind `iommufd_access_pin_pages()`, `iommufd_access_detach_internal()`, and `iommufd_access_destroy_internal()` in reverse order; `iommufd_hw_queue_destroy()` must call `hw_queue->destroy()` before `iommufd_hw_queue_destroy_access()`. [F13, F146]
- `iopt_map_pages()` transfers `elm->area` and `elm->pages` ownership only when setting `elm->area->pages = elm->pages` and clearing `elm->pages` and `elm->area` to `NULL` under locks; on earlier errors, `iopt_free_pages_list()` must call `iopt_abort_area()` and `iopt_put_pages()`. [F15]
- On error in `iopt_area_fill_domain[s]()`, call `pfn_reader_release_pins(&pfns)` before `iopt_area_unfill_partial_domain()` and `pfn_reader_destroy(&pfns)`. When extracting `npin > 1` subpages from a memfd folio, call `folio_add_pins(folio, npin - 1)` and unpin unconsumed folios with `unpin_folios()`. [F16, F176]
- `iopt_pages_fill_xarray()` must reset `user.upages = NULL` before `pfn_reader_user_destroy(&user, pages)` on every exit path so the caller's `out_pages` buffer is not `kfree()`d. Callers of `batch_init_backup(&batch, ..., backup, sizeof(backup))` must pass the same `backup` pointer to `batch_destroy(&batch, backup)`. [F17, F129]

## API Contracts

- Every `iommufd_object` must be at offset 0. `iommufd_get_object()` and `iommufd_get_*()` return `ERR_PTR(-ENOENT)` on failure and never `NULL`; callers using `IOMMUFD_OBJ_ANY` must validate `obj->type` before downcasting. `_iommufd_object_alloc_ucmd()` requires `abort == NULL` and handles finalize/abort automatically in `iommufd_fops_ioctl()`. [F39, F56, F123, F126]
- When `to_destroy` is non-NULL, `iommufd_object_remove()` always consumes the caller's `to_destroy->users` reference even on failure, and if `refcount_dec_if_one(&obj->users)` fails after `REMOVE_WAIT` zeroed `obj->wait_cnt`, it must restore `obj->wait_cnt` to 1 under `xa_lock`. [F4]
- Callers of `iopt_set_allow_iova()` must always free all nodes remaining in `allowed_iova` after the call returns. Callers of `iopt_for_each_contig_area()` must check `iopt_area_contig_done(&iter)` after the loop (`iter->area` is cleared to `NULL` on gaps or `!area->pages`). [F19, F43, F98]
- `iommufd_access_pin_pages()` requires `PAGE_SIZE`-aligned `iopt_area` slices (`iopt_area_contig_is_aligned()`), and `iommufd_access_unpin_pages()` / `iopt_area_remove_access()` require the exact same range and `unlock_area` flag. Drivers must not hold any lock across `iommufd_access_destroy()` that their `.unmap` callback acquires. [F58, F88, F153]
- IOAS map/copy ioctls require `IOMMU_IOAS_MAP_WRITEABLE` or `IOMMU_IOAS_MAP_READABLE` (`-EINVAL`) and `iova, length < ULONG_MAX` (`-EOVERFLOW`). `iopt_alloc_user_pages()` / `iopt_alloc_file_pages()` must check end-address overflow (`-EOVERFLOW`), `iopt_alloc_pages()` must reject `!length || length > SIZE_MAX - PAGE_SIZE`, and `iommufd_check_iova_range()` must validate `bitmap->iova + bitmap->length - 1 <= ULONG_MAX` and `bitmap->page_size`. [F78, F80, F117]
- `iopt_alloc_pages()` saves `source_mm`, `source_task`, and `source_user`; all later pinning and `RLIMIT_MEMLOCK` accounting must use those fields rather than `current`. `kthread_use_mm(pages->source_mm)` in `iopt_pages_rw_access()` requires `IOMMUFD_ACCESS_RW_KTHREAD` and `pages->type == IOPT_ADDRESS_USER`. [F165, F177]
- Callers of `temp_kmalloc()` must derive array element counts from the updated `*size`. `batch_add_pfn_num()` must check `nr <= MAX_NPFNS - batch->npfns[end - 1]` before coalescing. [F120, F127]
- `iommufd_hwpt_nested_alloc()`, `iommufd_hwpt_alloc()`, and `iommufd_vdevice_alloc_ioctl()` must verify that the parent domain owner or `viommu->iommu_dev` matches `idev->dev`. Domain-alloc callers must strip `IOMMU_HWPT_FAULT_ID_VALID` from `flags` and set `owner`, `iommufd_hwpt = hwpt`, and `cookie_type = IOMMU_COOKIE_IOMMUFD`. [F172, F173]

## Error Handling

- When domain allocation returns an `ERR_PTR` in `iommufd_hwpt_paging_alloc()`, `iommufd_hwpt_nested_alloc()`, or `iommufd_viommu_alloc_hwpt_nested()`, set `hwpt->domain = NULL` before jumping to `out_abort`. Callers of `iommufd_hw_pagetable_detach()` must check the returned `hwpt` for `NULL` before decrementing `idev->obj.users`. [F8, F42]
- Initialize `rc = -EINVAL` before `iopt_for_each_contig_area()` in `iommufd_access_rw()`, and ensure every exit path in `iopt_unmap_iova_range()` writes `unmapped_bytes` to `*unmapped`. `iopt_add_access()` must only assign `access->iopt_access_list_id` after `iopt_calculate_iova_alignment()` succeeds. [F44, F45, F64]
- In `iommufd_device_do_replace()`, `err_unresv` must pass `hwpt_paging` (not `old_hwpt_paging`) to `iommufd_group_remove_reserved_iova()`. In `iommufd_hw_pagetable_attach()`, `xa_store(&igroup->pasid_attach, ...)` must happen after `iommufd_hwpt_attach_device()` succeeds so `iommufd_group_first_attach()` stays true on error. [F95, F110]
- In `iommufd_access_pin_pages()`, `iopt_area_add_access()` must be the last fallible step in the loop body so `err_remove` unpins `[iova, iter.cur_iova - 1]` accurately. In `iopt_area_fill_domains()`, track `done_first_end_index` and `done_all_end_index` separately so `out_unmap` unmaps the right range per domain. [F99, F104]

## External Contracts

- Every `/dev/iommu` ioctl must be in `union ucmd_buffer`, use `IOCTL_OP(..., _last)`, respond via `iommufd_ucmd_respond()` without retaining `ucmd->cmd`, reject non-zero `__reserved` or unknown flags/enums with `-EOPNOTSUPP`, and zero-initialize (`= {}`) stack structs copied to userspace. [F75, F136, F168, F170]
- `iommufd_fault_fops_read()`, `iommufd_fault_fops_write()`, and `iommufd_veventq_fops_read()` reject `*ppos != 0` (`-ESPIPE`), never split entries, and if an error occurs after `done > 0` bytes are transferred, restore the failed entry to the queue and return `done`. [F60, F90]

## Known Pitfalls

- `batch_clear_carry()` must compute `batch->pfns[0]` using `batch->npfns[batch->end - 1]` before overwriting `batch->npfns[0] = keep_pfns`, and in `iopt_area_unpin_domain()`, `batch_last_index` must be `start_index + batch->total_pfns - 1` (not `start + batch->total_pfns - 1`). [F65, F85]
- In `iova_bitmap`, `bitmap->bitmap` is `u8 __user *`, `iova_bitmap_get()` must add `!!offset_in_page(addr)` to `npages` before clamping, and `iova_bitmap_set()` must check `page_idx > last_page_idx` every iteration (calling `iova_bitmap_advance_to()`) and add `mapped->pgoff * BITS_PER_BYTE` to bit offsets rather than adding `mapped->pgoff` to `kaddr`. [F83, F133, F134]
- Use `check_add_overflow()` instead of `ALIGN()` or `PAGE_ALIGN()` in `__alloc_iova_check_range()` and `iommufd_hw_queue_alloc_phys()`, shift `1UL` (not `1`) by `__ffs()` / `pgshift` bit indices, and prefetch `next = iopt_reserved_iter_next(...)` before removing/freeing nodes in `__iopt_remove_reserved_iova()`. [F108, F112, F113, F116]
