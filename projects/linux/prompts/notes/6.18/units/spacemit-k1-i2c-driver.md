# SPACEMIT K1 I2C DRIVER

The SpacemiT K1 I2C driver (`drivers/i2c/busses/i2c-k1.c`) is the platform bus controller driver for `spacemit,k1-i2c` devices. It manages MMIO registers and the `func` and `bus` clocks, executing interrupt-driven standard-mode (100 kHz) and fast-mode (400 kHz) I2C message transfers registered with the core I2C subsystem.

## Architecture & Data Flow

- `spacemit_i2c_xfer()` must call `spacemit_i2c_init()` and `spacemit_i2c_enable()` at the start of every transfer and unconditionally call `spacemit_i2c_disable()` before returning, because `spacemit_i2c_err_check()`, `spacemit_i2c_disable()`, `spacemit_i2c_reset()`, and `spacemit_i2c_conditionally_reset_bus()` mask interrupts, clear `SPACEMIT_CR_IUE`, or overwrite `SPACEMIT_ICR` and `SPACEMIT_IRCR`. Broken by: moving `spacemit_i2c_init()` to `spacemit_i2c_probe()` or returning early before `spacemit_i2c_disable()`. [F17, F46]
- `spacemit_i2c_init()` must set `SPACEMIT_RCR_SDA_GLITCH_NOFIX` in `SPACEMIT_IRCR` before each transfer (especially since `spacemit_i2c_conditionally_reset_bus()` overwrites `SPACEMIT_IRCR` without preserving it), so the hardware SDA glitch filter does not delay repeated-start signals. [F43]
- `spacemit_i2c_init()` must not set `SPACEMIT_CR_DTEIE` in `SPACEMIT_ICR`; transmit-empty interrupts must only be unmasked in `spacemit_i2c_start()` after loading `SPACEMIT_IDBR` and setting `SPACEMIT_CR_START | SPACEMIT_CR_TB`, preventing an immediate spurious TX-empty interrupt before transfer start. [F40]
- When updating `SPACEMIT_ICR` via read-modify-write during a transfer, `spacemit_i2c_start()` must clear `SPACEMIT_CR_STOP`, and `spacemit_i2c_irq_handler()` must clear `SPACEMIT_CR_TB | SPACEMIT_CR_ACKNAK | SPACEMIT_CR_STOP | SPACEMIT_CR_START` and set the next transfer's `SPACEMIT_CR_TB`, `SPACEMIT_CR_ALDIE`, `SPACEMIT_CR_STOP`, and `SPACEMIT_CR_ACKNAK` bits in a single `writel()`. Broken by: splitting the clear and set in `spacemit_i2c_irq_handler()` into two `writel()` calls, or ORing control bits without masking old ones. [F22, F41]
- In `spacemit_i2c_handle_read()`, reading `SPACEMIT_IDBR` into `*i2c->msg_buf++` and decrementing `i2c->unprocessed` must occur before the early return on `i2c->status & (SPACEMIT_SR_MSD | SPACEMIT_SR_ACKNAK)`, because the final read byte arrives in the same interrupt that asserts `SPACEMIT_SR_MSD` or `SPACEMIT_SR_ACKNAK`. Broken by: moving the `SPACEMIT_SR_MSD | SPACEMIT_SR_ACKNAK` return to the top of `spacemit_i2c_handle_read()` to match `spacemit_i2c_handle_write()`. [F30]
- On the last message (`i2c->msg_idx == i2c->msg_num - 1`), `spacemit_i2c_is_last_msg()` must test `i2c->unprocessed == 1` for reads (`i2c->read`) and `!i2c->unprocessed` for writes, because `spacemit_i2c_handle_write()` decrements `unprocessed` before `SPACEMIT_CR_TB` is set whereas `spacemit_i2c_handle_read()` decrements it on the next IRQ. Broken by: using `!i2c->unprocessed` for both, or moving `spacemit_i2c_is_last_msg()` before the `switch (i2c->state)` dispatch in `spacemit_i2c_irq_handler()`. [F29]
- `spacemit_i2c_handle_write()` and `spacemit_i2c_handle_read()` must guard `i2c->unprocessed--` and `*i2c->msg_buf++` with `if (i2c->unprocessed)` so `u32 unprocessed` never underflows if an interrupt fires after the final message byte. [F36]
- In `spacemit_i2c_conditionally_reset_bus()`, the initial check of `SPACEMIT_IBMR` must require both `SPACEMIT_BMR_SDA` and `SPACEMIT_BMR_SCL` to be set before returning early; after `spacemit_i2c_reset()`, recovery must check `SPACEMIT_BMR_SDA` (not `SPACEMIT_BMR_SCL`) and issue up to `SPACEMIT_BUS_RESET_CLK_CNT_MAX` 1-cycle resets via `SPACEMIT_IRCR` and `SPACEMIT_CR_RSTREQ` in `SPACEMIT_ICR` until `SPACEMIT_BMR_SDA` is set. [F28, F42]
- `spacemit_i2c_probe()` must test `!i2c->clock_freq` before `i2c->clock_freq < SPACEMIT_I2C_MAX_STANDARD_MODE_FREQ` and clamp `i2c->clock_freq` into `[SPACEMIT_I2C_MAX_STANDARD_MODE_FREQ, SPACEMIT_I2C_MAX_FAST_MODE_FREQ]` (defaulting `0` to `SPACEMIT_I2C_MAX_FAST_MODE_FREQ`), preventing a divide-by-zero in `spacemit_i2c_calc_timeout()` and preserving the 400 kHz default when `clock-frequency` is omitted or zero. [F23, F33]
- `spacemit_i2c_probe()` must pass the `struct spacemit_i2c_dev *` instance to `i2c_set_adapdata(&i2c->adapt, i2c)` (before `i2c_add_numbered_adapter()`), `platform_set_drvdata(pdev, i2c)`, and `devm_request_irq()`, matching the unconditional `void *` casts in `spacemit_i2c_xfer()`, `spacemit_i2c_remove()`, and `spacemit_i2c_irq_handler()`. [F37, F38]
- `spacemit_i2c_of_match` must remain terminated by a zeroed `{ /* sentinel */ }` entry. [F26]

## Synchronization

- For each message in `spacemit_i2c_xfer_msg()`, `i2c->msg_buf`, `i2c->unprocessed`, `i2c->status = 0`, `reinit_completion(&i2c->complete)`, `i2c->read`, `i2c->state`, and `SPACEMIT_IDBR` must be initialized inside the per-message loop before `spacemit_i2c_start()` writes `SPACEMIT_CR_START | SPACEMIT_CR_TB | SPACEMIT_CR_DTEIE` to `SPACEMIT_ICR`, preventing IRQ races, premature `wait_for_completion_timeout()` returns, or stale `SPACEMIT_SR_ERR` bits triggering `spacemit_i2c_handle_err()`. [F6, F13]
- Before calling `complete(&i2c->complete)`, `spacemit_i2c_handle_write()` and `spacemit_i2c_handle_read()` must set `i2c->state = SPACEMIT_STATE_IDLE` (so `spacemit_i2c_irq_handler()` neither writes `SPACEMIT_CR_TB` to `SPACEMIT_ICR` nor races with the waking `spacemit_i2c_xfer_msg()` loop), and `spacemit_i2c_err_check()` (on `SPACEMIT_SR_ERR` or `SPACEMIT_SR_MSD`) must additionally mask `SPACEMIT_I2C_INT_CTRL_MASK` in `SPACEMIT_ICR` and clear `SPACEMIT_I2C_INT_STATUS_MASK` in `SPACEMIT_ISR`. [F7, F8]
- `spacemit_i2c_irq_handler()` runs in hardirq context (`devm_request_irq()`), so neither it nor its callees (`spacemit_i2c_handle_start()`, `spacemit_i2c_handle_read()`, `spacemit_i2c_handle_write()`, `spacemit_i2c_err_check()`) may call sleeping helpers (`spacemit_i2c_conditionally_reset_bus()`, `spacemit_i2c_wait_bus_idle()`, `spacemit_i2c_check_bus_release()`, `usleep_range()`, `readl_poll_timeout()`). [F47]

## Object Lifetimes

- In `spacemit_i2c_probe()`, `i2c->base` must be mapped via `devm_platform_ioremap_resource()` and both `"func"` and `"bus"` clocks acquired and enabled via `devm_clk_get_enabled()` before `spacemit_i2c_reset(i2c)` accesses `SPACEMIT_ICR`. [F2]
- `i2c->adapt` is registered via non-devres `i2c_add_numbered_adapter()` as the final step of `spacemit_i2c_probe()` and must be unregistered via `i2c_del_adapter()` in `spacemit_i2c_remove()` before devres tears down the `func`/`bus` clocks, IRQ, MMIO mapping, and `struct spacemit_i2c_dev` memory. [F45]

## API Contracts

- Clearing interrupt status bits in `SPACEMIT_ISR` must go through `spacemit_i2c_clear_int_status()`, which masks the value with `SPACEMIT_I2C_INT_STATUS_MASK` so non-interrupt status bits (`SPACEMIT_SR_ACKNAK`, `SPACEMIT_SR_UB`, `SPACEMIT_SR_IBB`, `SPACEMIT_SR_EBB`) are not written to `SPACEMIT_ISR`. [F16]
- `spacemit_i2c_xfer()` must assign `i2c->msgs = msgs` and `i2c->msg_num = num` (where the I2C core guarantees `num >= 1`) before calling `spacemit_i2c_calc_timeout()`, which divides by `i2c->msg_num` and stores `i2c->adapt.timeout` in jiffies via `usecs_to_jiffies()` (consumed by `wait_for_completion_timeout()` and `__i2c_transfer()`), and before `spacemit_i2c_is_last_msg()` evaluates `i2c->msg_num - 1` on `u32 msg_num`. [F35, F52]
- `spacemit_i2c_func()` must exclude `I2C_FUNC_SMBUS_QUICK` from `I2C_FUNC_SMBUS_EMUL` unless zero-length message `SPACEMIT_CR_STOP` generation is supported in `spacemit_i2c_start()` and `spacemit_i2c_irq_handler()`. [F51]

## Error Handling

- In `spacemit_i2c_xfer()`, the call to `spacemit_i2c_xfer_msg()` and its `ret < 0` check must remain nested inside the `if (!ret)` success branch of `spacemit_i2c_wait_bus_idle()` so the `else` branch runs `spacemit_i2c_check_bus_release()` whenever `spacemit_i2c_wait_bus_idle()` returns a negative error. Broken by: flattening the `if`/`else` chain so `spacemit_i2c_check_bus_release()` becomes unreachable. [F27]
- `spacemit_i2c_xfer()` must capture `ret = spacemit_i2c_xfer_msg(i2c)` and return `ret` when negative or `num` on success, because `spacemit_i2c_xfer_msg()` returns `0` or a negative errno (`-ETIMEDOUT`, `-EAGAIN`, `-ENXIO`, `-EIO`) while `i2c_algorithm.xfer` expects the transferred message count or a negative errno. [F10]
- In `spacemit_i2c_handle_err()` and `spacemit_i2c_xfer()`, non-timeout/non-arbitration transfer errors (`-ENXIO`, `-EIO`) must only be logged with `dev_dbg()`, reserving `dev_err()` for `-ETIMEDOUT` and `-EAGAIN` and `dev_warn_ratelimited()` for bus reset failure in `spacemit_i2c_conditionally_reset_bus()`. [F54]
