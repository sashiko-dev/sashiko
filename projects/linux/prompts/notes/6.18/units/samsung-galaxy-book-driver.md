# SAMSUNG GALAXY BOOK DRIVER

The Samsung Galaxy Book x86 platform driver (`drivers/platform/x86/samsung-galaxybook.c`) manages platform features on Samsung Galaxy Book laptops via their ACPI companion device (`SAM0426`–`SAM0430`). It provides keyboard backlight control via the LEDs subsystem, battery charge control end thresholds via ACPI battery hooks, performance modes via `platform_profile`, firmware attributes (`power_on_lid_open`, `usb_charging`, and `block_recording`) via the `firmware-attributes` class, camera lens cover switch reporting via an input device, and hotkey handling through ACPI notifications and an i8042 keyboard filter.

## Architecture & Data Flow
- `galaxybook_probe` must initialize ACPI features in the strict order `GB_SASB_POWER_MANAGEMENT` (`galaxybook_acpi_init`, `galaxybook_platform_profile_init`, `galaxybook_battery_threshold_init`), then `GB_SASB_KBD_BACKLIGHT` (`galaxybook_kbd_backlight_init`), and then `GB_SASB_BLOCK_RECORDING` (`galaxybook_fw_attrs_init`). [F67]
- Capability flags `has_kbd_backlight`, `has_block_recording`, and `has_performance_mode` in `struct samsung_galaxybook` must remain `false` unless their respective init functions return `0`, and hotkey handlers (`galaxybook_i8042_filter`, `galaxybook_acpi_notify`) must check the corresponding flag before scheduling work or calling `platform_profile_cycle()`. [F73]
- When `galaxybook_i8042_filter` consumes a `0xe0` prefix byte by setting `extended = true` and returning `true`, any subsequent non-AUXDATA byte that is not a handled Galaxy Book hotkey scancode must clear `extended`, re-inject `0xe0` via `serio_interrupt(port, 0xe0, 0)`, and return `false`. Broken by: returning `false` early after `extended = true` without clearing `extended` and calling `serio_interrupt`. [F21]
- In `struct sawb`, `iob_prefix[18]` must match the combined 18-byte size of `caid[16]`, `fncn`, and `subn` so that `iobs[0]` aliases `iob0` (the mode count) and `iobs[1..9]` alias `iob1..iob9` for 1-based iteration (`i = 1; i <= buf.iob0; i++`) in `galaxybook_platform_profile_probe()`. [F25]
- `get_performance_mode_profile` must return `0` only after setting `*profile` to a valid `enum platform_profile_option` constant strictly less than `PLATFORM_PROFILE_LAST`, which bounds the bit offset passed to `set_bit(profile, choices)` and the index into `perfmodes[profile]` in `galaxybook_platform_profile_probe`. [F39]
- When `galaxybook_platform_profile_probe` iterates over `buf.iobs[i]`, `GB_PERFORMANCE_MODE_PERFORMANCE_V2` must only be assigned to `perfmodes[profile]` if `perfmodes[profile] != GB_PERFORMANCE_MODE_ULTRA`, preserving `ULTRA > PERFORMANCE_V2 > PERFORMANCE` precedence regardless of list order. [F32]
- Any `kobj_attribute` in `galaxybook_fw_attr_init` whose `.show` or `.store` callback resolves `struct galaxybook_fw_attr` via `container_of` on `attr` (such as `display_name` and `current_value`) must be embedded per-instance in `struct galaxybook_fw_attr` rather than shared as a static `kobj_attribute`. [F20]
- Every `enum galaxybook_fw_attr_id` value must have a corresponding designated initializer in both `galaxybook_fw_attr_name` and `galaxybook_fw_attr_desc`, because `galaxybook_fw_attr_init()` and `display_name_show()` index those arrays directly by `fw_attr_id` without bounds checks. [F29]
- `galaxybook_fw_attr_init` allocates `NUM_FW_ATTR_ENUM_ATTRS + 1` elements for `attrs` via `devm_kcalloc` and sets `attrs[6] = NULL`, so `NUM_FW_ATTR_ENUM_ATTRS` must match the exact number of populated attribute pointers (6) to preserve the `NULL` terminator required by `sysfs_create_group`. [F42]
- When `galaxybook_kbd_backlight_hotkey_work` updates keyboard backlight brightness via `led_set_brightness_sync(&galaxybook->kbd_backlight, brightness)`, it must notify userspace via `led_classdev_notify_brightness_hw_changed(&galaxybook->kbd_backlight, brightness)` while holding `galaxybook->kbd_backlight_lock`. [F24]

## Synchronization
- `kbd_backlight_store` and `kbd_backlight_acpi_set` must never acquire `galaxybook->kbd_backlight_lock`, because `galaxybook_kbd_backlight_hotkey_work` holds `kbd_backlight_lock` while calling `led_set_brightness_sync(&galaxybook->kbd_backlight, brightness)`, which synchronously invokes `kbd_backlight_store`. [F11]
- `galaxybook_i8042_filter` executes in atomic `i8042` interrupt/spinlock context and must defer any ACPI evaluation or mutex acquisition (`kbd_backlight_lock`, `fw_attr_lock`) to process context via `schedule_work` on `kbd_backlight_hotkey_work` or `block_recording_hotkey_work`. [F56]
- `power_on_lid_open_acpi_set`, `usb_charging_acpi_set`, and `block_recording_acpi_set` assert `lockdep_assert_held(&galaxybook->fw_attr_lock)`, so callers invoking these functions or `fw_attr->set_value` (such as `current_value_store` and `galaxybook_block_recording_hotkey_work`) must hold `galaxybook->fw_attr_lock`. [F9]
- `galaxybook_block_recording_hotkey_work` must hold `galaxybook->fw_attr_lock` continuously across `block_recording_acpi_get` and `block_recording_acpi_set` so that reading and inverting the block-recording state and reporting `SW_CAMERA_LENS_COVER` on `camera_lens_cover_switch` are atomic with respect to `current_value_store`. [F10]
- In `galaxybook_fw_attrs_init`, `devm_mutex_init(&galaxybook->platform->dev, &galaxybook->fw_attr_lock)` must execute before `galaxybook_block_recording_init` and before any `galaxybook_fw_attr_init` call, because `galaxybook_block_recording_init` locks `fw_attr_lock` and `galaxybook_fw_attr_init` exposes `current_value_store`. [F15]

## Object Lifetimes
- In `galaxybook_acpi_init`, `galaxybook_acpi_disable` must be registered with `devm_add_action_or_reset` immediately after enabling `GB_ACPI_METHOD_ENABLE` and before `acpi_install_notify_handler` and `galaxybook_acpi_remove_notify_handler`, so LIFO devres teardown removes the notify handler before disabling the ACPI device. [F55]
- `galaxybook_i8042_filter_install` must be called in `galaxybook_probe` after `galaxybook_kbd_backlight_init` and `galaxybook_fw_attrs_init` have set `has_kbd_backlight` and `has_block_recording` and registered their devres actions, so the i8042 filter is installed only when needed and removed first during LIFO devres teardown. [F47]
- `galaxybook_i8042_filter_install` must initialize both `kbd_backlight_hotkey_work` and `block_recording_hotkey_work` with `INIT_WORK` before calling `i8042_install_filter`, and `galaxybook_i8042_filter_remove` must call `i8042_remove_filter` before `cancel_work_sync` on both work items. Broken by: conditionally calling `INIT_WORK` for only one work item, or calling `cancel_work_sync` before `i8042_remove_filter`. [F4]
- In `galaxybook_block_recording_init`, `galaxybook->camera_lens_cover_switch` must be allocated and registered via `input_register_device` before `galaxybook_fw_attrs_init` sets `galaxybook->has_block_recording = true` and exposes `GB_ATTR_BLOCK_RECORDING` in sysfs. [F8]
- In `galaxybook_fw_attrs_init`, `galaxybook->fw_attrs_dev` must be registered with `devm_add_action_or_reset(..., galaxybook_fw_attrs_dev_unregister, ...)` before `galaxybook->fw_attrs_kset` is created under `&galaxybook->fw_attrs_dev->kobj` and registered with `galaxybook_kset_unregister`. [F3]
- `galaxybook_acpi_method` must validate that `out_obj->buffer.length == len`, `out_obj->buffer.pointer[GB_SAWB_RFLG_POS] == GB_RFLG_SUCCESS`, and `out_obj->buffer.pointer[GB_SAWB_GB_GUNM_POS] != GB_GUNM_FAIL` before copying into `buf`, and must call `kfree(out_obj)` on every path after `acpi_evaluate_object_typed` succeeds. [F52]

## API Contracts
- Callers of `galaxybook_acpi_method()` must zero-initialize `struct sawb` (`struct sawb buf = {}`) and pass a `len` between `GB_SAWB_GB_GUNM_POS + 1` (6) and `sizeof(struct sawb)` (256) matching the exact ACPI buffer length returned by `method` (`GB_SAWB_LEN_SETTINGS` for `GB_ACPI_METHOD_SETTINGS`, `GB_SAWB_LEN_PERFORMANCE_MODE` for `GB_ACPI_METHOD_PERFORMANCE_MODE`), as `galaxybook_acpi_method()` sends `len` bytes from `buf` to ACPI, rejects responses where `out_obj->buffer.length != len`, and copies `len` bytes back into `*buf`. [F26, F71]
- `galaxybook_kbd_backlight_init` must wire `kbd_backlight_store` to `kbd_backlight.brightness_set_blocking` (not `.brightness_set`) and set `LED_BRIGHT_HW_CHANGED` in `kbd_backlight.flags` because `kbd_backlight_acpi_set` sleeps in ACPI evaluation and `galaxybook_kbd_backlight_hotkey_work` calls `led_classdev_notify_brightness_hw_changed`. [F64]

## Error Handling
- `galaxybook_platform_profile_init`, `galaxybook_kbd_backlight_init`, and `galaxybook_block_recording_init` return positive `GB_NOT_SUPPORTED` (`EOPNOTSUPP`) when unsupported and negative errnos on failure, so `galaxybook_probe` and `galaxybook_fw_attrs_init` must filter out `GB_NOT_SUPPORTED` before propagating `err`. Broken by: checking `if (err < 0)` to detect `GB_NOT_SUPPORTED` or propagating `GB_NOT_SUPPORTED` unfiltered. [F70]
- In `galaxybook_platform_profile_probe`, when `get_performance_mode_profile` returns non-zero for an entry `buf.iobs[i]` (such as `-EOPNOTSUPP` for `GB_PERFORMANCE_MODE_IGNORE1` or `GB_PERFORMANCE_MODE_IGNORE2`), the loop must `continue` without calling `set_bit(profile, choices)` or aborting probe. [F33]
- In `galaxybook_enable_acpi_feature`, the `GB_ACPI_METHOD_SETTINGS` call succeeds if either `buf.gunm == GB_GUNM_FEATURE_ENABLE_SUCCESS` (`0xdd`) or `buf.guds[0] == GB_GUDS_FEATURE_ENABLE_SUCCESS` (`0xcc`), and returns `-ENODEV` only when neither field matches its success constant. Broken by: requiring both `buf.gunm` and `buf.guds[0]` to match simultaneously. [F77]

## External Contracts
- `block_recording_acpi_get` and `block_recording_acpi_set` must invert the hardware byte (`GB_BLOCK_RECORDING_ON` = `0x0`, `GB_BLOCK_RECORDING_OFF` = `0x1`) relative to the boolean `value` (`1` = recording blocked), and whenever `block_recording_acpi_set` updates the `GB_SASB_BLOCK_RECORDING` state via `galaxybook_acpi_method`, it must report the new `SW_CAMERA_LENS_COVER` state on `galaxybook->camera_lens_cover_switch` and call `input_sync` while holding `galaxybook->fw_attr_lock`. [F17, F65]
- For `POWER_SUPPLY_PROP_CHARGE_CONTROL_END_THRESHOLD`, `galaxybook_battery_ext_property_set()` must validate that the threshold is in `1..100` and map `100` to `0` before calling `charge_control_end_threshold_acpi_set()`, and `galaxybook_battery_ext_property_get()` must map hardware value `0` back to `100`. [F28]

## Known Pitfalls
- `galaxybook_probe` never calls `platform_set_drvdata` or `dev_set_drvdata` on `pdev`, so `dev_get_drvdata` is only valid on the `platform_profile` class device passed to `galaxybook_platform_profile_get` and `galaxybook_platform_profile_set`, not on `&galaxybook->platform->dev`. [F44]
