# X86 MICROCODE UPDATE SUPPORT

This unit implements early-boot (initrd and built-in firmware) and late-runtime (sysfs and firmware loader) CPU microcode update support for x86 Intel and AMD processors. `core.c` provides the vendor-agnostic framework, including command-line parsing, sysfs interfaces, CPU hotplug and syscore resume hooks, and `stop_machine`/NMI rendezvous synchronization across SMT siblings and offline CPUs during late loading. `intel.c` and `amd.c` implement vendor-specific binary blob parsing, header/checksum/SHA-256 verification, patch caching, and MSR-based microcode application.

## Architecture & Data Flow

- Whenever a CPU's microcode revision is collected or updated in `mc_cpu_online()`, `apply_microcode_late()`, or `apply_microcode_amd()`, `ucode_cpu_info[cpu].cpu_sig.rev`, `cpu_data(cpu).microcode`, and (when `cpu` is the boot CPU) `boot_cpu_data.microcode` must be updated in lockstep. [F37]
- Before calling `find_patch(cpu)`, `ucode_cpu_info[cpu].cpu_sig.sig` must already be populated with `CPUID(1).EAX` (as done in `load_ucode_amd_bsp()`, `load_ucode_amd_ap()`, and `collect_cpu_info_amd()`), and `mc_cpu_online()` must zero `ucode_cpu_info[cpu]` before calling `collect_cpu_info()`. [F32]
- In `load_late_locked()`, `setup_cpus()` must validate online/offline CPU state before `microcode_ops->request_microcode_fw()` is invoked. In `load_late_stop_cpus()`, `store_cpu_caps(&prev_info)` must be called before `stop_machine_cpuslocked()` so `microcode_check(&prev_info)` compares against pre-update hardware CPUID capabilities rather than software-modified `boot_cpu_data`. [F38, F39]
- In `load_ucode_intel_bsp()` and `load_ucode_amd_bsp()`, `ed->old_rev` must be sampled before applying the patch and `ed->new_rev` must be set only if applying the patch succeeds, because `microcode_init()` tests `early_data.new_rev` to report whether an early update occurred. [F40]
- On AMD Zen and newer CPUs (`x86_family(bsp_cpuid_1_eax) >= 0x17`), `equiv_table` is bypassed (`find_equiv_id()`, `verify_equivalence_table()`, `install_equiv_cpu_table()`, `free_equiv_cpu_table()`) and patches are matched by decoding family/model/stepping from `patch_id` via `ucode_rev_to_cpuid()`. Both `cpuid_to_ucode_rev()` and `ucode_rev_to_cpuid()` must zero-initialize `union zen_patch_rev` and `union cpuid_1_eax` before writing individual bitfields because callers compare full 32-bit words containing reserved bits. [F33, F106]
- In AMD containers, the equivalence table byte length `hdr[2]` excludes `CONTAINER_HDR_SZ` (12 bytes; entries start at `buf + CONTAINER_HDR_SZ`, `num_entries = hdr[2] / sizeof(struct equiv_cpu_entry)`, advancing by `hdr[2] + CONTAINER_HDR_SZ`), and the patch size `sh_psize` at section offset 4 excludes `SECTION_HDR_SIZE` (8 bytes; `struct microcode_header_amd` and `struct microcode_amd` start at `+ SECTION_HDR_SIZE`, advancing by `patch_size + SECTION_HDR_SIZE`). Both `struct equiv_cpu_entry` and `struct microcode_header_amd` must remain `__packed`. [F62, F86, F87]
- In `verify_and_add_patch()`, `patch` must be allocated with `sizeof(*patch)` while `patch->data` is allocated with `kmemdup(fw + SECTION_HDR_SIZE, *patch_size, GFP_KERNEL)` and `patch->size` is set to `*patch_size`, because `__apply_microcode_amd()` passes `p->size` to `verify_sha256_digest()` to hash the exact patch payload without slab padding or section headers. [F85]
- In `intel_microcode_sanity_check()`, `data_size + MC_HEADER_SIZE > total_size` must be rejected before subtracting `MC_HEADER_SIZE + data_size` from `total_size`, `ext_table_size < EXT_HEADER_SIZE` must be rejected before computing `(ext_table_size - EXT_HEADER_SIZE) % EXT_SIGNATURE_SIZE`, and the `u32 *` checksum loops over `ext_tablep` and `(u32 *)mc` must divide byte sizes (`ext_table_size` and `MC_HEADER_SIZE + data_size`) by `sizeof(u32)`. [F79, F90]
- In `intel_find_matching_signature()` and `intel_microcode_sanity_check()`, `ext_header` starts at byte offset `MC_HEADER_SIZE + intel_microcode_get_datasize(mc_hdr)` from `mc`, and byte offsets `EXT_HEADER_SIZE` and `EXT_SIGNATURE_SIZE * i` must be added to `(void *)ext_header` rather than a typed `struct extended_sigtable *`. [F89]

## Synchronization

- Secondary and soft-offlined SMT threads in `load_secondary()`, `load_secondary_wait()`, `wait_for_cpus()`, `wait_for_ctrl()`, and `microcode_offline_nmi_handler()` must remain `noinstr` and use `raw_cpu_*`/`raw_atomic_*` accessors until `wait_for_ctrl()` returns, because instrumentation exceptions (`#INT3`, `#DB`, `#PF`) reenable NMIs via `IRET`. Moreover, `wait_for_cpus()` and `wait_for_ctrl()` must only enter `instrumentation_begin()` to call `touch_nmi_watchdog()` when `!microcode_ops->use_nmi`. [F116, F117]
- Before sending `NMI_VECTOR` to an online or soft-offlined CPU for microcode rendezvous, the sender (`load_cpus_stopped()` or `kick_offline_cpus()`) must set that CPU's `ucode_ctrl.nmi_enabled` to `true`, and `microcode_nmi_handler()` and `microcode_offline_nmi_handler()` must clear `ucode_ctrl.nmi_enabled` to `false` upon entry. [F14]
- In `__load_primary()`, the primary thread must write its own `ucode_ctrl.result` before setting `per_cpu(ucode_ctrl.ctrl, sibling)` to `SCTRL_APPLY` or `SCTRL_DONE`, and must always update `ucode_ctrl.ctrl` for every sibling after `wait_for_cpus(&late_cpus_in)` succeeds. [F17]
- In `load_primary()` on CPU 0 (`!cpu && nr_offl`), if `kick_offline_cpus(nr_offl)` times out waiting for `offline_in_nmi == nr_offl`, `__load_primary(cpu)` must be skipped, and `release_offline_cpus()` must still be called unconditionally to set `ucode_ctrl.ctrl = SCTRL_DONE` on all CPUs in `cpu_offline_mask`. [F114]
- When `wait_for_cpus()` times out waiting for `cnt` to reach zero, it must execute `raw_atomic_inc(cnt)` before returning `false` so late-arriving CPUs cannot decrement `cnt` to zero and proceed after other CPUs have timed out. [F74]
- `load_late_locked()` and `load_late_stop_cpus()` must be called with `cpus_read_lock()` held (acquired in `reload_store()`). In `setup_cpus()`, every present CPU in `cpus_booted_once_mask` that is a primary SMT thread (`topology_is_primary_thread(cpu)`) must be online, and any offline secondary SMT thread is permitted only when `microcode_ops->nmi_safe || (microcode_ops->use_nmi && apic->nmi_to_offline_cpu)` holds. [F113, F120]

## Object Lifetimes

- `microcode_bsp_resume()` tests `ucode_cpu_info[cpu].mc` to dispatch `microcode_ops->apply_microcode(cpu)` vs `reload_early_microcode(cpu)`. Intel must keep `ucode_cpu_info[cpu].mc` `NULL` (since `apply_microcode_late()` uses `ucode_patch_late`), whereas AMD sets it to `p->data` (looked up via `find_patch(cpu)`) and must clear it to `NULL` via `microcode_fini_cpu_amd()` when `mc_cpu_down_prep()` calls `microcode_fini_cpu(cpu)` and `sysfs_remove_group()`. [F6, F98]
- In `intel.c`, `load_ucode_intel_bsp()` sets `ucode_patch_va` to the sentinel `UCODE_BSP_LOADED` (`0x1UL`) rather than storing the raw initrd/built-in pointer from `get_microcode_blob()`, and `save_builtin_microcode()` must clear `ucode_patch_va` to `NULL` via `xchg()` before copying the patch to heap with `save_microcode_patch()`. [F1]
- In `parse_microcode_blobs()` (`intel.c`), `mc` is a reusable scratch buffer across loop iterations; when promoting `mc` to `new_mc`, the code must `kvfree(new_mc)` any prior candidate and reset `mc = NULL` so subsequent iterations do not overwrite `new_mc` and exit paths (`kvfree(mc)` and `fail:`) do not double-free it. [F2]
- When `request_microcode_fw()` returns `UCODE_NEW` or `UCODE_NEW_SAFE`, `load_late_stop_cpus()` must pass `!updated` (`0` on success, `1` on failure) to `microcode_ops->finalize_late_load()`. Intel's `finalize_late_load()` must transfer `ucode_patch_late` to `ucode_patch_va` via `update_ucode_pointer()` (which `kvfree()`s the old `ucode_patch_va`) on `0` or `kvfree(ucode_patch_late)` on non-zero and reset `ucode_patch_late = NULL`; AMD's `finalize_late_load_amd()` must call `cleanup()` on non-zero. [F3, F100]
- In `amd.c`, `free_equiv_cpu_table()` must zero `equiv_table` after `vfree(equiv_table.entry)`, and `_load_microcode_amd()` must call `free_equiv_cpu_table()` before `install_equiv_cpu_table()` and call `cleanup()` (freeing both `equiv_table` and `microcode_cache`) whenever `__load_microcode_amd()` fails. `free_cache()` must use `list_for_each_entry_safe()` to unlink and free `struct ucode_patch` nodes, whereas `update_cache()` must immediately `return` after `list_replace()` and `kfree(p)` inside `list_for_each_entry()`. [F5, F76]
- In `request_microcode_fw()` (`intel.c`) and `request_microcode_amd()` (`amd.c`), the `const struct firmware *` obtained from `request_firmware_direct()` must be released with `release_firmware()` on every return path after acquisition, and any retained patches must be heap-copied beforehand. [F7]

## API Contracts

- In `amd.c`, `update_cache()` unconditionally consumes ownership of `new_patch` and `new_patch->data`, either linking `new_patch` into `microcode_cache` (and freeing any replaced entry `p` and `p->data`) or freeing `new_patch->data` and `new_patch` when an equal or newer patch is already cached. Callers must never dereference or free `patch` after calling `update_cache()`. [F4]
- Despite their `unsigned int family` parameter name in `internal.h`, `load_ucode_amd_bsp()` and `load_ucode_amd_ap()` require the full `CPUID(1).EAX` signature value (`cpuid_1_eax`) rather than `x86_family(cpuid_1_eax)`, because they store it in `bsp_cpuid_1_eax` and `ucode_cpu_info[cpu].cpu_sig.sig`. [F24]
- `MSR_IA32_UCODE_WRITE` in `__apply_microcode()` must be passed the address of the Intel payload `mc->bits` (past the 48-byte `struct microcode_header_intel`), whereas `MSR_AMD64_PATCH_LOADER` in `__apply_microcode_amd()` must be passed `(unsigned long)&mc->hdr.data_code` (past `SECTION_HDR_SIZE`) after `verify_sha256_digest()` succeeds, followed on Family `0x17` by `invlpg()` on `p_addr` and on `p_addr_end` (`p_addr + psize - 1`) if it crosses a page boundary. [F34, F104]
- Callers of `intel_microcode_sanity_check(void *mc, bool print_err, int hdr_type)` must ensure the buffer at `mc` holds at least `sizeof(struct microcode_header_intel)` and `get_totalsize(mc)` bytes before calling it, must check for any negative (or non-zero) return value rather than only `-EINVAL` (an extended signature table size mismatch returns `-EFAULT`), and must run it before `intel_find_matching_signature(mc, sig)` so `ext_hdr->count` is validated against `ext_table_size`. [F35, F55, F129]
- `verify_patch()` and `verify_and_add_patch()` use a tri-state `int` return convention—negative on structural or allocation error, `0` on a valid matching-family patch, and positive (`1`) on a valid non-matching-family patch—and must populate `*patch_size` before returning a positive value. `parse_container()` returns `0` both when `verify_equivalence_table()` fails and when a match is found (`desc->mc` is non-NULL), and `orig_size - size` when a valid container had no match; callers of `scan_containers()` must zero-initialize `struct cont_desc` and check `desc.mc`. [F26, F27]
- `intel_collect_cpu_info()` must initialize `sig->pf = 0` before checking `IFM(...) >= INTEL_PENTIUM_III_DESCHUTES`, and when populating `sig->pf` from `MSR_IA32_PLATFORM_ID` must store the shifted bitmask `1 << ((val[1] >> 18) & 7)` rather than the raw 3-bit index because `cpu_signatures_match()` tests `s1->pf & pf2`. Reading the revision in `intel_get_microcode_revision()` requires writing `0` to `MSR_IA32_UCODE_REV`, executing `native_cpuid_eax(1)`, and reading the high 32-bit half (`edx`). [F36, F102]
- Before executing `native_cpuid_eax(1)` or vendor-specific microcode loading on the BSP, `load_ucode_bsp()`, `save_builtin_microcode()`, `save_microcode_in_initrd()`, and `microcode_init()` must check `microcode_loader_disabled()`. `load_ucode_intel_bsp()` and `load_ucode_amd_bsp()` run before memory allocators are usable and must apply patches in-place from initrd/built-in memory, deferring heap copies (`save_microcode_patch()`, `_load_microcode_amd()`) to `early_initcall`. [F94, F122]

## Error Handling

- `__apply_microcode_amd()` and other `bool`-returning microcode helpers (`verify_sha256_digest()`, etc.) must return `false` (never a negative error code such as `-1` or `-EINVAL`) on failure, because C implicitly converts any non-zero integer to `true`. [F25]
- In `load_late_locked()`, the `switch` on `microcode_ops->request_microcode_fw()` must explicitly handle `UCODE_OK` by returning `0` without calling `load_late_stop_cpus()`, because `request_microcode_amd()` returns `UCODE_OK` when all cached patches are already at or below the running CPU revision. [F64]
- `scan_microcode()` must return `size ? NULL : patch` after its loop so that any early `break` on a malformed or truncated record (which leaves `size` non-zero) rejects the entire blob even if an earlier record matched and set `patch`. [F71]

## Known Pitfalls

- In `update_cache()`, `patch_newer(p, new_patch)` must be handled as a signed tri-state where `< 0` (different stepping on Family >= `0x17`) continues scanning `microcode_cache`, `0` frees `new_patch` and returns, and `> 0` replaces `p` with `new_patch`. [F67]
- In `load_microcode_amd()`, after `_load_microcode_amd()` populates `microcode_cache`, check `find_patch(cpu)` against `cpu_data(cpu).microcode` across every CPU-populated NUMA node via `for_each_node_with_cpus(nid)` (never `for_each_node(nid)`, where an empty node cpumask yields `cpu >= nr_cpu_ids`, and never only CPU 0 on mixed-stepping systems). Conversely, `save_microcode_in_initrd()` (`early_initcall`) must call `_load_microcode_amd()` directly because NUMA node cpumasks are not yet initialized. [F47, F61, F110]
- Unlike Intel, AMD early BSP loading in `load_ucode_amd_bsp()` and AP/late loading in `apply_microcode_amd()` must apply a patch even when the current revision equals `mc->hdr.patch_id` (skipping only when `rev > mc->hdr.patch_id`), whereas `reload_ucode_amd()` and `load_microcode_amd()` only trigger when `rev < patch_id`. When `cur_rev` is `0` on an AMD Zen+ CPU, `need_sha_check()` must synthesize a baseline revision via `cpuid_to_ucode_rev(bsp_cpuid_1_eax)` before switching on `cur_rev >> 8`. [F105, F109]
- In `get_totalsize()` and `intel_microcode_get_datasize()`, a zero `hdr->datasize` in `struct microcode_header_intel` indicates a legacy format where `hdr->totalsize` is ignored and sizes default to `DEFAULT_UCODE_DATASIZE` (2000) and `DEFAULT_UCODE_TOTALSIZE` (2048); callers must never read `hdr->totalsize` or `hdr->datasize` directly. [F56]
- `load_ucode_ap()`, `load_ucode_intel_ap()`, and `load_ucode_amd_ap()` run during AP bringup both at boot and during post-init CPU hotplug with interrupts disabled, so they must not be marked `__init`, call `__init` helpers (`microcode_loader_disabled()`, `find_microcode_in_initrd()`), or sleep. Furthermore, `microcode_loader_disabled()`, `amd_check_current_patch_level()`, `load_ucode_bsp()`, and `load_ucode_ap()` must query CPU vendor and family via `x86_cpuid_vendor()` and `native_cpuid_eax(1)` instead of `boot_cpu_data`. [F119, F125]
