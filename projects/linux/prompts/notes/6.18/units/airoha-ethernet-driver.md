# AIROHA ETHERNET DRIVER

This unit implements the Ethernet and hardware packet offload drivers for Airoha EN7581 SoCs, encompassing the Frame Engine (FE), QDMA scatter-gather/QoS controllers, Packet Processing Engine (PPE), and RISC-V Network Processor Unit (NPU) for GDM MAC ports, QoS, and L2/L3/L4 TC flower flow offloading.

## Architecture & Data Flow
- In `struct airoha_foe_entry`, `bridge`, `ipv4`, `ipv4_dslite`, and `ipv6` must keep `data` at offset 36 because `airoha_ppe_foe_commit_subflow_entry()` and `airoha_ppe_foe_entry_prepare()` alias them. However, `ipv6` places `ib2` at offset 44 and uses a 16-byte `struct airoha_foe_mac_info_common l2` (no `src_mac_lo` or `pppoe_id`), whereas `bridge`/`ipv4`/`dslite` place `ib2` at 12/16 and `l2` at 40 (`struct airoha_foe_mac_info`), so callers must check `AIROHA_FOE_IB1_BIND_PACKET_TYPE >= PPE_PKT_TYPE_IPV6_ROUTE_3T` before accessing `ib2` or `l2`. [F33, F61]
- For SRAM FOE entries (`hash < PPE_SRAM_NUM_ENTRIES`), `ppe->foe` is only a DMA staging buffer: reads must call `airoha_ppe_foe_get_entry_locked()` to pull `REG_PPE_RAM_ENTRY` into `ppe->foe`, and writes in `airoha_ppe_foe_commit_entry()` must invoke `npu->ops.ppe_foe_commit_entry()`. [F53]
- In `airoha_ppe_foe_flow_stats_update()`, redirecting a non-WLAN FOE entry (`pse_port != FE_PSE_PORT_CDM4`) to PSE port 6 for NPU accounting must mutate `hwe` in `ppe->foe` (not `e->data`), save original `ib2`/`data` bits into `AIROHA_FOE_TUNNEL_MTU` and `AIROHA_FOE_ACTDP` before overwriting `*ib2`, and call `airoha_ppe_foe_flow_stat_entry_reset()`. [F52]
- In `struct airoha_flow_table_entry`, `e->hash == 0xffff` means unbound; callers must check `e->hash != 0xffff` before indexing hardware FOE/stats entries and set `e->hash = 0xffff` before removing an evicted flow. In `airoha_ppe_foe_insert_entry()`, iterating `ppe->foe_flow[index]` must `continue` on `!airoha_ppe_foe_compare_entry(e, hwe)` without setting `e->hash = 0xffff`. [F37, F85]
- `struct airoha_foe_bridge` must keep `dest_mac_hi`, `src_mac_hi`, `dest_mac_lo`, and `src_mac_lo` as its first 12 bytes, and `ppe->l2_flows` lookups must build keys via `airoha_ppe_foe_set_bridge_addrs()`. Also, `struct airoha_foe_entry data` must remain the last member of `struct airoha_flow_table_entry` because `airoha_foe_entry` ends in `DECLARE_FLEX_ARRAY(u32, d)`. [F60, F71]
- When `airoha_ppe_foe_commit_subflow_entry()` binds a hardware subflow from a bridge template, for IPv6 (`type >= PPE_PKT_TYPE_IPV6_ROUTE_3T`) it must set `hwe.ipv6.l2.src_mac_hi = FIELD_PREP(AIROHA_FOE_MAC_SMAC_ID, 0xf)`, and for IPv4 HNAPT (`type == PPE_PKT_TYPE_IPV4_HNAPT`) it must copy `hwe.ipv4.orig_tuple` to `hwe.ipv4.new_tuple`. [F47, F48]
- Updating a GDM port's MAC in `airoha_set_macaddr()` must call `airoha_ppe_init_upd_mem(port)` so PPE `REG_UPDMEM_DATA` matches `port->dev->dev_addr` for routed IPv6 FOE entries. [F46]
- Each QDMA TX completion ring (`irq_q->q`) uses `0xff` as the empty sentinel (`0x0` is queue 0, desc 0) and must be `memset` to `0xff` on init. In `airoha_qdma_tx_napi_poll()`, every non-`0xff` entry at `irq_q->q[head]` must be reset to `0xff` with `head`, `irq_queued`, and `done` updated before any `continue` or `goto unlock`, and `done` must be cleared in `REG_IRQ_CLEAR_LEN(id)` in chunks `<= 0x80`. [F42, F91]
- In `airoha_qdma_rx_process()`, `q->tail` and `q->queued` are updated immediately after checking `QDMA_DESC_DONE_MASK`. `q->skb` tracks scattered frames across `QDMA_DESC_MORE_MASK` descriptors: non-final fragments `continue` without incrementing `done` or clearing `q->skb`, while terminal fragments (`napi_gro_receive`) or aborted frames (`free_frag`) must reset `q->skb = NULL`. [F63, F93]
- Because multiple `airoha_gdm_port` instances share an `airoha_qdma`, `airoha_dev_stop()` must only disable DMA in `REG_QDMA_GLOBAL_CFG` and drain `qdma->q_tx` via `airoha_qdma_cleanup_tx_queue()` when `atomic_dec_and_test(&qdma->users)` is true. [F55]

## Synchronization
- `ppe_lock` is shared between RX softirq (`airoha_ppe_check_skb`) and process context (`airoha_ppe_setup_tc_block_cb`, `airoha_ppe_foe_get_entry`), so it must use `spin_lock_bh(&ppe_lock)`, nesting inside `flow_offload_mutex` and outside `airoha_npu_core.lock`. It protects all accesses to `ppe->foe_flow`, `e->l2_flows`, and `airoha_ppe_foe_get_entry_locked()` (unlocked callers use `airoha_ppe_foe_get_entry()`). [F17, F18, F142]
- All TC flower offload operations in `airoha_ppe_setup_tc_block_cb()`, including `airoha_ppe_offload_setup()` and `eth->flow_table` accesses, must hold `flow_offload_mutex`. `eth->npu` is published via `rcu_assign_pointer(eth->npu, npu)` only after NPU PPE/SRAM/stats init completes; readers outside `flow_offload_mutex` must use `rcu_read_lock()` and check for `NULL`. [F19, F29]
- In `airoha_ppe_foe_commit_entry()`, copying into `hwe->d` in `ppe->foe` must be ordered by `wmb()` before writing `hwe->ib1`. In `airoha_npu_send_msg()`, because `npu->regmap` has `.disable_locking = true`, `spin_lock_bh(&npu->cores[core].lock)` must be held across the entire `REG_CR_MBQ0_CTRL` sequence and poll, and `dma_unmap_single()` must happen after `spin_unlock_bh()`. [F21, F22]
- All TX ring accesses (`q->head`, `q->tail`, `q->queued`, `q->entry`, `q->desc`, queue stop/wake) in `airoha_dev_xmit()`, `airoha_qdma_tx_napi_poll()`, and `airoha_qdma_cleanup_tx_queue()` must hold `spin_lock_bh(&q->lock)`. Completing `q->entry[index]` requires unmapping `e->dma_addr` and zeroing `*e` under `q->lock` before advancing `q->tail` while `!q->entry[q->tail].dma_addr`. [F10, F26]
- `airoha_irq_bank.irq_lock` is used in hardirq, NAPI, and process context, so `airoha_qdma_set_irqmask()` must use `spin_lock_irqsave()` and read back `REG_INT_ENABLE` before unlocking. `DEV_STATE_INITIALIZED` in `eth->state` is set at the end of `airoha_hw_init()` and checked by `airoha_irq_handler()` before scheduling NAPI. `airoha_update_hw_stats()` must hold `spin_lock(&port->stats.lock)` and bracket updates and `REG_FE_GDM_MIB_CLEAR` with `u64_stats_update_begin()`/`end()`. [F24, F27, F139]

## Object Lifetimes
- RX rings (`qdma->q_rx`) rely solely on NAPI serialization. During teardown in `airoha_remove()` and `airoha_probe()` error paths after `airoha_hw_init()`, `airoha_qdma_stop_napi()` and `airoha_ppe_deinit(eth)` must run before `airoha_hw_cleanup()` deletes NAPI, drains RX queues (`airoha_qdma_cleanup_rx_queue()`), and calls `page_pool_destroy()`, followed by `free_netdev(eth->napi_dev)`. If `page_pool_create()` fails in `airoha_qdma_init_rx_queue()`, `q->page_pool` must be reset to `NULL`. [F4, F7, F8, F28, F141]
- In `airoha_qdma_rx_process()`, the `free_frag` error path must either call `dev_kfree_skb(q->skb)` (and set `q->skb = NULL`) when `q->skb` is non-NULL, or call `page_pool_put_full_page(q->page_pool, page, true)` when `q->skb` is `NULL`, never both. [F6]
- In `airoha_dev_xmit()`, only the first descriptor (`i == 0`) stores `e->skb = skb` and calls `netdev_tx_sent_queue()` (`i > 0` sets `e->skb = NULL`), and `q->head` must not be mutated until all fragments are mapped so `error_unmap` can unmap `[0, i - 1]` at `(q->head + i) % q->ndesc` before unlocking and freeing `skb`. `airoha_qdma_tx_napi_poll()` only calls `netdev_tx_completed_queue()` and `dev_kfree_skb_any()` when `e->skb` is non-NULL. [F9, F94, F158]
- `FLOW_TYPE_L2_SUBFLOW` entries are not in `eth->flow_table` and are freed via `kfree(e)` inside `airoha_ppe_foe_remove_flow()` under `ppe_lock` (including children on `e->l2_flows` when removing a parent `FLOW_TYPE_L2`), whereas `FLOW_TYPE_L4`/`L2` entries are freed by `airoha_ppe_flow_offload_destroy()`. [F13]
- Per-port `net_device`s use `devm_alloc_etherdev_mqs()` (never call `free_netdev(port->dev)`), whereas `port->dsa_meta` must be freed via `airoha_metadata_dst_free(port)` on unregistration or if `airoha_alloc_gdm_port()` fails before `register_netdev()` succeeds. [F5, F124]
- `airoha_npu_probe()` must finish firmware boot and init before `platform_set_drvdata()`. `airoha_npu_wdt_handler()` defers `vzalloc()` and `dev_coredumpv()` (which owns `dump`; do not `vfree(dump)`) to `wdt_work`, and `airoha_npu_remove()` must call `cancel_work_sync()` on all cores. [F16, F23, F150]
- In `airoha_npu_get()` and `airoha_ppe_get_dev()`, `of_node_put(np)` must wait until after the `!pdev` error log reads `np->name`. In `airoha_npu_run_firmware()`, the first firmware must be freed with `release_firmware(fw)` before requesting the second, and a second `request_firmware()` failure must return directly without jumping to `out`. [F1, F15]

## API Contracts
- `airoha_npu_get()` and `airoha_ppe_get_dev()` acquire both `platform_device` and module references (released via `airoha_npu_put()`/`airoha_ppe_put_dev()`), and callers that can build without `CONFIG_NET_AIROHA`/`CONFIG_NET_AIROHA_NPU` must check `IS_ERR_OR_NULL()`. [F2, F162]
- `port->id` is 1-based (`1..4`) for GDM registers, whereas `eth->ports[]` is 0-based (`port->id - 1`). For hardware PSE port fields (`AIROHA_FOE_IB2_PSE_PORT`, `QDMA_ETH_TXMSG_FPORT_MASK`), `port->id == 4` must map to `FE_PSE_PORT_GDM4` (`9`) because `4` is `FE_PSE_PORT_PPE1`. [F40, F65]
- Before dereferencing `netdev_priv(dev)` as `airoha_gdm_port` on an offload `net_device`, `airoha_is_valid_gdm_port(eth, port)` must verify it belongs to `eth->ports[]`. Guard `dev->dsa_ptr` with `netdev_uses_dsa(dev)` (not `IS_ERR()`), and check `dsa_port_from_netdev()` with `IS_ERR()`. [F32, F108]
- `airoha_npu_send_msg()` uses streaming `dma_map_single()`, so callers must pass `kzalloc`-allocated buffers, never stack or vmalloc memory. `npu->stats` is `__iomem` (use `memset_io()`/`memcpy_fromio()`), and callers of `airoha_ppe_foe_entry_get_stats()` must zero-initialize `*stats` first. [F38, F147, F151]
- QDMA RX done interrupts for queues 16..31 use bits 0..15 (`RX_DONE_HIGH_INT_MASK`) of `QDMA_INT_REG_IDX2` (shift by `RX_DONE_HIGH_OFFSET` = 16). `airoha_qdma_set_chan_tx_sched()` and `CHAN_QOS_MODE_MASK(_n)` require `channel < 8` (`% AIROHA_NUM_QOS_CHANNELS`). [F41, F102]
- In `airoha_qdma_cleanup_rx_queue()`, pass `allow_direct = false` to `page_pool_put_full_page()`. In NAPI poll, only call `airoha_qdma_irq_enable()` when `done < budget` and `napi_complete(napi)` is true. In `airoha_dev_stop()`, call `netdev_tx_reset_subqueue()` on each TX queue. [F149, F157, F159]
- On TX, `airoha_get_dsa_tag()` and GSO in `airoha_dev_xmit()` must call `skb_cow_head(skb, 0)` before reading/modifying SKB header pointers, and `airoha_get_dsa_tag()` must use `memmove()` (not `memcpy()`) when stripping the 4-byte `MTK_HDR_LEN` tag into `QDMA_ETH_TXMSG_SP_TAG_MASK`. [F111, F112, F153, F154]

## Error Handling
- In `airoha_ppe_offload_setup()`, errors before `rcu_assign_pointer(eth->npu, npu)` must call `airoha_npu_put(npu)`. In `airoha_ppe_flow_offload_replace()`, if `rhashtable_insert_fast()` fails after `airoha_ppe_foe_flow_commit_entry()`, call `airoha_ppe_foe_flow_remove_entry()` before `kfree(e)`. In `airoha_tc_htb_alloc_leaf_queue()`, if `netif_set_real_num_tx_queues()` fails, reset the rate limit to 0 and do not set `port->qos_sq_bmap`. [F3, F12, F14]
- Callers of `airoha_ppe_foe_get_entry()`/`_locked()` must NULL-check the return value. Validate `hash <= PPE_HASH_MASK` in `airoha_ppe_check_skb()`, `index < PPE_STATS_NUM_ENTRIES` for FOE stats, RX `len` and `nr_frags` in `airoha_qdma_rx_process()`, and TX `qid`/`index` in `airoha_qdma_tx_napi_poll()`. [F31, F76, F77, F79]
- In `airoha_npu_send_msg()`, after `regmap_read_poll_timeout_atomic()` returns 0, verify `FIELD_GET(MBOX_MSG_STATUS, val) == NPU_MBOX_SUCCESS`. In `airoha_npu_run_firmware()`, check `fw->size` against `NPU_EN7581_FIRMWARE_RV32_MAX_SIZE` and `NPU_EN7581_FIRMWARE_DATA_MAX_SIZE`. [F44, F70]

## External Contracts
- In HTB offload callbacks, `opt->qid` must be `AIROHA_NUM_TX_RING + channel`, and `airoha_dev_xmit()` must index `qdma->q_tx[]` with `skb_get_queue_mapping(skb) % ARRAY_SIZE(qdma->q_tx)`. For 3-tuple routing flows (`PPE_PKT_TYPE_IPV4_ROUTE`, `PPE_PKT_TYPE_IPV6_ROUTE_3T`), `airoha_ppe_foe_entry_prepare()` must set `ports` to `0xa5a5a500 | (l4proto & 0xff)`. [F66, F67, F81]

## Known Pitfalls
- Callers of `airoha_ppe_foe_commit_entry()` must copy `airoha_ppe_foe_get_entry_locked()` into a local `struct airoha_foe_entry` before passing it as `e`. Because `d` starts after `u32 ib1`, `memcpy()`/`memcmp()` on `&hwe->d` must subtract `sizeof(hwe->ib1)`, and pointer arithmetic on `void *ppe->foe` or `ppe->foe_dma` must multiply `hash` by `sizeof(struct airoha_foe_entry)`. [F54, F109, F110]
- `struct airoha_foe_entry` stores IP/MAC/port fields in host CPU byte order (use `%pI4h` and `ipv6_addr_cpu_to_be32()` in debugfs), unlike `__le32` in `airoha_qdma_desc`. [F74, F118]
- In `airoha_ppe_foe_remove_l2_flow()`, access parent `e` before `hlist_for_each_entry_safe(e, ...)` overwrites `e`. In `airoha_ppe_foe_flow_l2_entry_update()`, use a separate cursor `iter` so parent `e->data.ib1` is updated. [F87, F88]
- In `airoha_ppe_check_skb()`, truncate `(u16)jiffies - ppe->foe_check_time[hash]` to `u16` before comparing with `HZ / 10`. In `airoha_ppe_get_entry_idle_time()`, mask `now` to 8-bit `AIROHA_FOE_IB1_UNBIND_TIMESTAMP` when unbound. Cast 32-bit upper stats counters to `u64` before `<< 32`, and use `div_u64()` for 64-bit rates/sizes. [F98, F99, F100, F103, F104, F105]
