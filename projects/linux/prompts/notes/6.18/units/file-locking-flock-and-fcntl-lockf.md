# FILE LOCKING (flock() and fcntl()/lockf())

This unit (`fs/fcntl.c`, `fs/locks.c`) implements the `fcntl()` and `flock()` system calls, asynchronous I/O signal notification (`fasync` and `f_owner`), and VFS file locking. It manages BSD (`flock`), POSIX byte-range, Open File Description (`FL_OFDLCK`), and file lease/delegation/layout locks attached to inodes via `struct file_lock_context`, including conflict resolution, range splitting/merging, deadlock detection, and `/proc/locks` reporting.

## Architecture & Data Flow
- Every lock or lease added to or removed from a per-inode `file_lock_context` list via `locks_insert_lock_ctx()` or `locks_unlink_lock_ctx()` must in lockstep be linked into or unlinked from the per-CPU `file_lock_list` via `locks_insert_global_locks()` or `locks_delete_global_locks()` using `flc->flc_link_cpu` (never `this_cpu_ptr(&file_lock_list)` on delete). [F34]
- When `__locks_insert_block()` adds a waiter to `blocker->flc_blocked_requests`, if `(blocker->flc_flags & (FL_POSIX|FL_OFDLCK)) == FL_POSIX` it must also insert `waiter` into `blocked_hash` via `locks_insert_global_blocked()`, and `__locks_unlink_block()` must remove `waiter` from both `blocked_hash` and `flc_blocked_member`. [F35]
- Because `blocker->flc_blocked_requests` holds both `struct file_lock` waiters and `struct file_lease` breakers inserted by `__break_lease()`, `__locks_wake_up_blocks()` must check `waiter->flc_flags & (FL_POSIX | FL_FLOCK)` before downcasting `file_lock(waiter)` to access `fl->fl_lmops`. Similarly, `lock_get_status()` must only dereference `file_lock(flc)` (`fl_start`, `fl_end`) when `FL_POSIX` is set, and `file_lease(flc)` when `FL_LEASE|FL_DELEG|FL_LAYOUT` is set. [F84, F85]
- When `flock_lock_inode()` or `posix_lock_inode()` copies `request` into a newly allocated `new_fl` via `locks_copy_lock()`, it must also call `locks_move_blocks(new_fl, request)` to splice waiters on `request->c.flc_blocked_requests` to `new_fl` and update their `flc_blocker` to `&new_fl->c`. In `locks_move_blocks()`, the loop updating `f->c.flc_blocker` after `list_splice_init()` must iterate over `&new->c.flc_blocked_requests`, not the emptied `&fl->c.flc_blocked_requests`. [F37, F75]
- In `posix_lock_inode()`, when splitting an existing lock (`left == right`), `locks_copy_lock(left, right)` must copy `right` into `new_fl2` before `right->fl_start` is mutated to `request->fl_end + 1`, and `locks_wake_up_blocks()` must be called on both `right` and `left` after shrinking their ranges. When inserting `new_fl` in the `!added` branch after `list_for_each_entry_safe_from()`, `new_fl` must be inserted before `&fl->c.flc_list` and `fl` reassigned to `new_fl` so a subsequent `left == right` split inserts `left` (`new_fl2`) before `new_fl`. [F38, F69]
- Because `__break_lease()` can set `FL_UNLOCK_PENDING` on a lease that already has `FL_DOWNGRADE_PENDING` set, `target_leasetype()` must test `FL_UNLOCK_PENDING` before `FL_DOWNGRADE_PENDING`, and `lease_clear_pending()` must fall through from `F_UNLCK` to `F_RDLCK` to clear both flags. [F64]
- When `lease_modify()` changes a lease's `flc_type`, it must clear superseded break flags via `lease_clear_pending()` and wake waiters via `locks_wake_up_blocks()`; when `arg == F_UNLCK`, it must also reset `f_delown(filp)`, `file_f_owner(filp)->signum = 0`, and `fl->fl_fasync` via `fasync_helper()` before `locks_delete_lock_ctx()`. [F36]
- Because `past_time()` treats `0` as a sentinel meaning a lease timer never expires, `__break_lease()` must increment `break_time` whenever `jiffies + lease_break_time * HZ` or `break_time - jiffies` evaluates to `0`. [F58]
- Every loop iterating over `&ctx->flc_lease` that can unlink entries via `locks_delete_lock_ctx()` or `lease_modify(..., F_UNLCK, ...)`—including `time_out_leases()`, `__break_lease()`, and `locks_remove_lease()`—must use `list_for_each_entry_safe()`. [F68]
- In `setfl()`, whenever `filp->f_flags` is modified under `filp->f_lock`, `filp->f_iocb_flags` must be recomputed in lockstep via `iocb_flags(filp)` while holding `filp->f_lock`. [F31]

## Synchronization
- Lock operations in `fs/locks.c` must obey the hierarchy `file_rwsem` -> `ctx->flc_lock` -> `{ blocked_lock_lock, fll->lock }`, and `locks_insert_global_locks()` / `locks_delete_global_locks()` must only be called while holding both `file_rwsem` (read-locked) and `ctx->flc_lock`. [F99]
- Inserting a blocked request into `blocker->flc_blocked_requests` via `__locks_insert_block()` requires holding both `ctx->flc_lock` and `blocked_lock_lock` (in that order), whereas removing requests requires only `blocked_lock_lock`, so `locks_wake_up_blocks()` must recheck `list_empty()` after acquiring `blocked_lock_lock`. [F23]
- In `posix_lock_inode()`, `__locks_wake_up_blocks(&request->c)`, `posix_locks_deadlock(request, fl)`, and `__locks_insert_block(&fl->c, &request->c, posix_locks_conflict)` must execute within a single `blocked_lock_lock` critical section while holding `ctx->flc_lock`. [F25]
- In `__locks_wake_up_blocks()` and `__locks_delete_block()`, `waiter->flc_blocker` must be cleared via `smp_store_release(&waiter->flc_blocker, NULL)` only after unlinking and waking `waiter`, and `waiter` must not be accessed afterward because `__locks_delete_block()` uses `smp_load_acquire(&waiter->flc_blocker)` locklessly before freeing `waiter`. Also, `fl->fl_lmops->lm_notify()` runs under `blocked_lock_lock` and must not sleep or re-acquire `blocked_lock_lock`. [F21, F92]
- Callers sleeping on `flc_wait` (`posix_lock_inode_wait()`, `flock_lock_inode_wait()`, `do_lock_file_wait()`, and `__break_lease()`) must use `list_empty(&fl->c.flc_blocked_member)` as the wait condition (not `!fl->c.flc_blocker`) and call `locks_delete_block()` / `__locks_delete_block()` upon waking. [F22]
- Callers removing locks or leases under `ctx->flc_lock` and `file_rwsem` must pass a non-NULL `dispose` list head to `locks_delete_lock_ctx()` (or `lease_modify()` / `time_out_leases()`) and invoke `locks_dispose_list(&dispose)` only after dropping `ctx->flc_lock` and `file_rwsem` (including before sleeping in `__break_lease()`). Because `struct file_lock` and `struct file_lease` use separate slab caches, `locks_delete_lock_ctx()` with `dispose == NULL` must never be called on a `struct file_lease`. [F9, F83]
- In `posix_lock_inode()`, any dereference of `request` (including `trace_posix_lock_inode(inode, request, error)`) must occur before `spin_unlock(&ctx->flc_lock)`, because `request` may have been reassigned to an entry on `ctx->flc_posix` that another task can free once `ctx->flc_lock` is dropped. [F26]
- In `generic_add_lease()`, for `FL_DELEG` leases `check_conflicting_open()` leaves open-count checks to its caller, and `generic_add_lease()` must take `inode_trylock(inode)` before `file_rwsem` and `ctx->flc_lock` (returning `-EAGAIN` on contention) and call `inode_unlock(inode)` on every exit path. After `locks_insert_lock_ctx()`, `generic_add_lease()` must run `smp_mb()` (pairing with `smp_mb()` before `list_empty_careful(&flctx->flc_lease)` in `break_lease()`, `break_deleg()`, and `break_layout()`) and recheck `check_conflicting_open()`, unlinking `lease` on failure. [F13, F28, F115]
- In `__break_lease()`, after dropping `ctx->flc_lock` and `file_rwsem` to sleep in `wait_event_interruptible_timeout()`, the function must reacquire both locks, call `__locks_delete_block(&new_fl->c)`, recheck `any_leases_conflict()`, and `goto restart` to re-read `list_first_entry(&ctx->flc_lease, ...)` rather than reusing `fl`. [F41]
- `fasync_insert_entry()` and `fasync_remove_entry()` must acquire `filp->f_lock` before `fasync_lock` and update `FASYNC` in `filp->f_flags` under both locks, while `setfl()` must exclude `FASYNC` from `SETFL_MASK` so `filp->f_op->fasync()` manages it. [F4]
- Because `kill_fasync_rcu()`, `send_sigio()`, and `send_sigurg()` can run in hardirq or softirq context using `read_lock_irqsave()` on `fa->fa_lock` and `fown->lock`, all process-context acquisitions of `fa->fa_lock` and `f_owner->lock` must disable local IRQs (`_irq` or `_irqsave`), and user-memory copies must not occur while holding them. [F94]
- In `file_f_owner_allocate()` and `locks_get_lock_context()`, all internal locks and list heads of `struct fown_struct` and `struct file_lock_context` must be initialized before `cmpxchg()` publishes `file->f_owner` or `inode->i_flctx` to concurrent lockless readers. [F15]
- `send_sigio_to_task()` must read `fown->signum` once via `READ_ONCE(fown->signum)` into a local variable and use that snapshot across `sigio_perm()`, `sig_specific_sicodes()`, `si.si_signo`, and `do_send_sig_info()` because `f_owner_sig()` (`F_SETSIG`) modifies `fown->signum` locklessly. [F48]

## Object Lifetimes
- `fasync_insert_entry()` consumes `new` and returns `NULL` only when no entry for `filp` exists on `*fapp`; otherwise it updates and returns the existing entry without consuming `new`, requiring `fasync_add_entry()` to free `new` via `fasync_free()` and `lease_setup()` to leave `*priv` non-NULL for the caller to free. [F2]
- `fasync_free()` must only be called on `struct fasync_struct` entries never inserted into an fasync list; entries linked via `fasync_insert_entry()` must be removed by `fasync_remove_entry()`, which sets `fa->fa_file = NULL` under `write_lock_irq(&fa->fa_lock)` and frees via `kfree_rcu(fa, fa_rcu)`. [F3]
- Callers of `__f_setown()` must first allocate `filp->f_owner` via `file_f_owner_allocate()` (outside RCU read lock). In `f_setown()` and `f_setown_ex()`, `rcu_read_lock()` must span both `find_vpid()` and `__f_setown()`, and `__f_setown()` must call `put_pid(f_owner->pid)` and `get_pid(pid)` under `write_lock_irq(&f_owner->lock)`. [F5, F97]
- `locks_release_private()` requires `fl->c` to be unlinked from all waitqueues, lists, and hashes, and must clear `fl->fl_ops = NULL`, `flc->flc_owner = NULL`, and `fl->fl_lmops = NULL` after calling `fl_release_private` and `lm_put_owner` so repeated or `locks_free_lock()` calls are idempotent; it must be called before scope exit even on stack-allocated `struct file_lock` instances (such as in `sys_flock()`). [F6, F47]
- `locks_copy_conflock()` acquires an `lm_get_owner` reference and `locks_copy_lock()` requires `new->fl_ops == NULL` before copying `fl_ops` and calling `fl_copy_lock`, so any destination `struct file_lock` of either helper must be released with `locks_release_private()` or `locks_free_lock()`. [F7]
- `posix_lock_inode()` must pre-allocate `new_fl` and `new_fl2` before taking `file_rwsem` and `ctx->flc_lock`, clear each local pointer to `NULL` when inserted into `ctx->flc_posix` so `out:` frees only unused locks, and abort with `-ENOLCK` if `right && left == right && !new_fl2` before modifying `left` or `right`. [F10]
- In `posix_test_lock()` and `posix_lock_inode()`, when `fl_lmops->lm_lock_expirable` returns `true`, `fl_lmops->lm_expire_lock` must be non-NULL, and the caller must copy `lm_mod_owner` and `lm_expire_lock` into locals and call `__module_get(owner)` before dropping `ctx->flc_lock` (and `file_rwsem` in `posix_lock_inode()`), then invoke `(*func)()`, call `module_put(owner)`, and retry. [F11, F109]
- Standard POSIX locks use `current->files` as `flc_owner` whereas `FL_OFDLCK` locks use `filp`. In `fcntl_setlk()` and `fcntl_setlk64()`, after `do_lock_file_wait()` succeeds for a non-unlock (`flc_type != F_UNLCK`), non-`FL_OFDLCK` lock, the caller must verify `files_lookup_fd_locked(files, fd) == filp` under `spin_lock(&files->file_lock)` (not RCU) and, on mismatch, remove the locks via `locks_remove_posix(filp, files)` and return `-EBADF`. [F12, F43]
- When `generic_add_lease()` finds an existing lease (`my_fl != NULL`), it must reassign `lease = my_fl` before jumping to `out_setup:` so `lm_setup()` operates on `my_fl`, and at exit it must only clear `*flp = NULL` when `!error && !my_fl` so the caller frees the unused `*flp` allocation. [F76]

## API Contracts
- In `generic_setlease()`, `kernel_setlease()`, and `vfs_setlease()`, `void **priv` is overloaded: when `arg == F_UNLCK`, `priv` must be non-NULL and `*priv` must hold the `flc_owner` (`filp`, matching `lease_init()`'s `fl->c.flc_owner = filp`) for `generic_delete_lease()`; for `F_RDLCK`/`F_WRLCK` with `lease_setup()`, `*priv` must point to a `struct fasync_struct`. [F44, F89]
- In `__f_setown()`, `f_owner->pid`, `pid_type`, `uid`, and `euid` are updated only when `force || !f_owner->pid` (requiring `lease_setup()` to pass `force = 0` so acquiring a lease does not overwrite an `F_SETOWN` owner). When `pid` is non-NULL under `force || !f_owner->pid`, `f_owner->uid`, `f_owner->euid`, and `security_file_set_fowner(filp)` must be captured from `current_cred()` inside `write_lock_irq(&f_owner->lock)`, and `sigio_perm()` must check those saved UIDs rather than `current_cred()`. [F16, F45, F127]
- In `fcntl_setlk()` and `fcntl_setlk64()`, `F_OFD_SETLK` and `F_OFD_SETLKW` must rewrite `cmd` to `F_SETLK`/`F_SETLKW` (or `F_SETLK64`/`F_SETLKW64`) before calling `do_lock_file_wait()`, and `F_OFD_SETLKW` must fall through to set `FL_SLEEP`. [F65]
- File locking, lease, and `fcntl` operations on a `struct file *` must resolve the target inode via `file_inode(filp)` rather than `filp->f_path.dentry->d_inode`, and inode ownership checks in `vfs_setlease()`, `setfl()` (`O_NOATIME`), and `fcntl_set_rw_hint()` must map the inode's UID through `file_mnt_idmap(filp)` via `i_uid_into_vfsuid()` or `inode_owner_or_capable()`. [F112, F126]

## External Contracts
- For `F_OFD_GETLK`, `F_OFD_SETLK`, and `F_OFD_SETLKW`, `fcntl_getlk[64]()` and `fcntl_setlk[64]()` must reject `flock->l_pid != 0` with `-EINVAL`, set `FL_OFDLCK` with `flc_owner = filp`, and reject `F_OFD_*` in 32-bit `fcntl` (requiring `fcntl64`). `fcntl_getlk[64]()` must permit `flock->l_type == F_UNLCK` when `cmd == F_OFD_GETLK` (rejecting types other than `F_RDLCK`/`F_WRLCK` otherwise), and `posix_test_locks_conflict()` must handle `lock_is_unlock(caller_fl)` before `posix_locks_conflict()` by matching overlapping same-owner locks. [F66, F121]
- On 32-bit architectures, `posix_lock_to_flock()` must return `-EOVERFLOW` if `fl_start` or a finite `fl_end` exceeds `OFFT_OFFSET_MAX`. In `do_compat_fcntl64()`, `fixup_compat_flock()` (returning `-EOVERFLOW` if `l_start > COMPAT_OFF_T_MAX` and clamping `l_len` to `COMPAT_OFF_T_MAX`) must be applied to 32-bit `F_GETLK` (`struct compat_flock`), and must not be called for `F_GETLK64` or `F_OFD_GETLK` (`struct compat_flock64`). [F56, F118]

## Known Pitfalls
- Any change to lock acquisition, `FL_OFDLCK` handling, or close-race recovery in `fcntl_setlk()` or `fcntl_getlk()` must be mirrored in `fcntl_setlk64()` or `fcntl_getlk64()` under `#if BITS_PER_LONG == 32`. [F49]
- When testing whether two byte ranges are adjacent in `posix_lock_inode()`, comparisons between `fl_start` and `fl_end` must use `fl_start - 1` rather than `fl_end + 1`, because `fl_end` can be `OFFSET_MAX` where adding `1` overflows signed `loff_t`. [F80]
- Stack-allocated structs copied to userspace in `fs/fcntl.c` (`struct compat_flock` in `put_compat_flock()`, `struct compat_flock64` in `put_compat_flock64()`, `struct f_owner_ex` in `f_getown_ex()`, and `kernel_siginfo_t` in `send_sigio_to_task()`) must be zero-initialized before field assignment and `copy_to_user()`. [F88]
