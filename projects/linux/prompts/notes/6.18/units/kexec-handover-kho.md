# KEXEC HANDOVER (KHO)

Kexec Handover (KHO) preserves arbitrary physical pages, folios, vmalloc regions, and subsystem state metadata across a kexec reboot into a new kernel. During boot, it reserves movable CMA scratch regions so the next kernel can allocate early memory without overwriting preserved state, and exposes a notifier chain, Flattened Device Tree (FDT) hierarchy, and debugfs control interface to serialize and deserialize preserved memory maps and subsystem subtrees.

## Architecture & Data Flow

- `kho_out.ser.fdt` is allocated as an uninitialized page in `kho_init()` whenever `kho_enable` is true and is only formatted as a valid FDT in `kho_finalize()`. Functions exporting outbound KHO state (such as `kho_fill_kimage()`) must gate access on `kho_out.finalized`, never `kho_enable` or `kho_is_enabled()`. [F22]
- In `kho_out_finalize_set()`, `kho_out.finalized` must be set to `true` only after `kho_finalize()` succeeds and before `kho_out_update_debugfs_fdt()` runs, because `__kho_preserve_order()` rejects calls with `-EBUSY` when `kho_out.finalized` is true while `kho_out_update_debugfs_fdt()` branches on `kho_out.finalized`. [F30]
- In `kho_finalize()`, `fdt_property_placeholder()` for `PROP_PRESERVED_MEMORY_MAP` must precede the `KEXEC_KHO_FINALIZE` notifier chain, while `kho_mem_serialize()` and writing `*preserved_mem_map` must follow the notifiers, because `kho_add_subtree()` appends child subnodes in sequential-write FDT mode and notifiers preserve pages. [F31]
- `kho_mem_serialize()` must allocate a new `struct khoser_mem_chunk` via `new_chunk(chunk, order)` at the start of every outer `xa_for_each(&ser->track.orders, order, physxa)` iteration as well as when `chunk->hdr.num_elms == ARRAY_SIZE(chunk->bitmaps)`, because `chunk->hdr.order` applies to all `bitmaps[]` entries in a chunk. [F56]
- `__kho_preserve_order()` and `__kho_unpreserve()` take PFNs (not byte physical addresses), shift `pfn_high = pfn >> order`, index `phys_bits` by `pfn_high / PRESERVE_BITS`, and set/clear bit `pfn_high % PRESERVE_BITS`, matching `(phys * PRESERVE_BITS) << (order + PAGE_SHIFT)` in `kho_mem_serialize()` and `bit << (order + PAGE_SHIFT)` in `deserialize_bitmap()`. [F29]
- On a KHO boot (`kho_in.scratch_phys != 0`), `kho_memory_init()` must run `kho_mem_deserialize()` before `kho_restore_folio(kho_in.fdt_phys)` or any other `kho_restore_*` call, because `kho_restore_page()` requires `page->private` to contain `KHO_PAGE_MAGIC` and `order` written by `deserialize_bitmap()`. [F77]
- `kho_restore_page()` must validate `info.magic == KHO_PAGE_MAGIC` and `info.order <= MAX_PAGE_ORDER` on `page->private` and immediately clear `page->private = 0` before computing `nr_pages = 1 << info.order` or indexing `page + i`; clearing `page->private` ensures each preserved folio or page range is restored at most once, with repeat `kho_restore_folio()` or `kho_restore_pages()` calls triggering `WARN_ON_ONCE` and returning `NULL`. [F3, F45]
- In `kho_preserve_vmalloc()`, the `vm->pages` loop must step `i` by `nr_contig_pages` (`1 << order`) and record one physical address per contiguous block in `chunk->phys[idx++]`. In `kho_restore_vmalloc()`, each `chunk->phys[i]` entry must fill `contig_pages` slots of `pages[idx++]`, verifying `idx + contig_pages <= total_pages` before filling and `idx == total_pages` after walking all chunks before calling `vmap_pages_range()`. [F49, F58]
- `struct kho_vmalloc_chunk` pages allocated in `new_vmalloc_chunk()` must be zero-initialized (`get_zeroed_page(GFP_KERNEL)`) because `kho_vmalloc_unpreserve_chunk()` and `kho_restore_vmalloc()` iterate `for (int i = 0; chunk->phys[i]; i++)` without a per-chunk count, relying on a zero `phys_addr_t` terminator. [F25]
- `KHO_VMALLOC_SUPPORTED_FLAGS`, `vmalloc_flags_to_kho()`, and `kho_flags_to_vmalloc()` must be updated in lockstep when adding supported vmalloc flags, as `kho_preserve_vmalloc()` and `kho_restore_vmalloc()` reject flags outside `KHO_VMALLOC_SUPPORTED_FLAGS` and translate between `VM_*` and `KHO_VMALLOC_*` bits. [F36]
- During early boot before linear direct mappings exist, `kho_populate()` must access `fdt_phys` and `scratch_phys` via `early_memremap()`/`early_memunmap()` (never `phys_to_virt()`) and call `memblock_set_kho_scratch_only()` before `kho_memory_init()` accesses them via `phys_to_virt()`. [F85]
- `kho_populate()` derives `kho_scratch_cnt` by dividing `scratch_len` by `sizeof(*kho_scratch)`, so `kho_reserve_scratch()` and `kho_fill_kimage()` must size the scratch descriptor buffer as an exact multiple of `sizeof(struct kho_scratch)`. [F70]
- When `kho_parse_scratch_size()` sets explicit `scratch_size_lowmem`, `scratch_size_global`, and `scratch_size_pernode` values, it must set `scratch_scale = 0` so `scratch_size_update()` and `scratch_size_node()` do not overwrite them with percentage-scaled sizes. [F38]
- In `kho_parse_scratch_size()`, the `len > ARRAY_SIZE(s_scale)` check relies on `len` including the trailing `'%'` character so `memcpy(s_scale, p, len - 1)` copies at most `ARRAY_SIZE(s_scale) - 1` bytes into zero-initialized `s_scale`, preserving a trailing NUL for `kstrtouint()`. [F71]

## Synchronization

- `kho_out.lock` is held across `kho_finalize()` and `kho_abort()`, which invoke `kho_out.chain_head` notifiers; therefore `KEXEC_KHO_FINALIZE`/`KEXEC_KHO_ABORT` callbacks and helpers they call (`kho_preserve_*`, `kho_add_subtree()`) must never acquire `kho_out.lock` or call `register_kho_notifier()`/`unregister_kho_notifier()`. [F12]
- `kho_add_subtree()` mutates `ser->fdt` in-place via `libfdt` sequential-write functions and appends to `ser->fdt_list` via `list_add()` without internal locking, so it may only be called from `KEXEC_KHO_FINALIZE` notifier callbacks serialized under `kho_out.lock` and `kho_out.chain_head`. [F13]
- Because `kho_preserve_*` runs outside `kho_out.lock`, `xa_init(&new_physxa->phys_bits)` must be called before publishing `new_physxa` into `track->orders` in `__kho_preserve_order()`, insertions into `track->orders` and `physxa->phys_bits` must use `xa_cmpxchg(..., NULL, new_elm, GFP_KERNEL)` and free `new_elm` on race, and bitmap updates must use atomic `set_bit()`/`clear_bit()`. [F11, F83]
- `__kho_unpreserve()` must only clear bits in `bits->preserve` via atomic `clear_bit()` and must never free or remove `struct kho_mem_phys` or `struct kho_mem_phys_bits` entries from `track->orders` or `physxa->phys_bits`, because `__kho_preserve_order()` and `__kho_unpreserve()` dereference `xa_load()` results without holding a lock. [F14]

## Object Lifetimes

- Preserved pages are marked `memblock_reserved_mark_noinit` during `deserialize_bitmap()` and only enter page-allocator accounting when `kho_restore_page()` sets the head page refcount to 1, zeroes tail page refcounts, calls `prep_compound_page()`, and calls `adjust_managed_page_count()`, returning a refcount-1 allocation to the caller. Broken by: freeing preserved pages with `__free_page()`/`folio_put()` before restoring them via `kho_restore_pages()`/`kho_restore_folio()`, or leaking the returned refcount-1 reference. [F4]
- `kho_abort()` must destroy all per-order `phys_bits` XArrays and the top-level `orders` XArray, free `kho_out.ser.preserved_mem_map` via `kho_mem_ser_free()` and reset `kho_out.ser.preserved_mem_map = NULL`, and invoke the `KEXEC_KHO_ABORT` notifier chain both on explicit abort and when `kho_finalize()` fails after allocations or notifiers. [F6]
- `new_vmalloc_chunk()` and `kho_preserve_vmalloc()` must preserve both each `struct kho_vmalloc_chunk` page and each `1 << order` data block via `kho_preserve_pages()`, and `kho_restore_vmalloc()` must restore each chunk page via `kho_restore_pages()`. When tearing down chunk lists in `kho_restore_vmalloc()`, `kho_vmalloc_free_chunks()`, and `kho_mem_ser_free()`, `KHOSER_LOAD_PTR(chunk->hdr.next)` must be evaluated before freeing the current chunk (`__free_page(page)`, `free_page()`, or `kfree()`). [F35, F57]
- `kho_populate()` maps `fdt` and `scratch` with `early_memremap()` and must release every non-NULL mapping with `early_memunmap()` via the `out` label on all return paths. [F10]
- In `kho_debugfs_fdt_add()` and `kho_out_update_debugfs_fdt()`, `f->wrapper.data` and `f->wrapper.size` must be populated before `debugfs_create_blob()` exposes the file, and `debugfs_remove(ff->file)` must complete before `kfree(ff)` frees the containing `struct fdt_debugfs`. [F15]

## API Contracts

- Fields declared with `DECLARE_KHOSER_PTR(name, type)` store a physical address (`phys`) at runtime and must only be read via `KHOSER_LOAD_PTR()`, which checks `(s).phys != 0` before calling `phys_to_virt()`. Because `KHOSER_STORE_PTR(dest, val)` calls `virt_to_phys(val)` without checking for `NULL`, nullable `DECLARE_KHOSER_PTR` fields (such as `hdr.next` in `khoser_mem_chunk` or `kho_vmalloc_chunk`) must be zero-initialized and never passed `NULL` in `KHOSER_STORE_PTR()`. [F20, F21]
- Every pointer stored via `KHOSER_STORE_PTR()` or passed as `@fdt` to `kho_add_subtree()` must be a direct-mapped kernel virtual address valid for `virt_to_phys()`/`phys_to_virt()` (never `vmalloc` or `early_memremap`). Callers of `kho_add_subtree()` must also ensure `@fdt` has a valid `fdt_totalsize(fdt)` header and separately preserve its backing pages via `kho_preserve_folio()` or `kho_preserve_pages()`. [F37, F84]
- `kho_preserve_folio()`, `kho_preserve_pages()`, and `kho_preserve_vmalloc()` must only be called from sleepable process context because `__kho_preserve_order()` asserts `might_sleep()` and performs `GFP_KERNEL` allocations. [F80]
- `kho_preserve_pages()` and `kho_restore_pages()` must decompose `[start_pfn, end_pfn)` using the identical `min(count_trailing_zeros(pfn), ilog2(end_pfn - pfn))` order step, and `kho_restore_pages()` must call `split_page(page, order)` on each block returned by `kho_restore_page()` to restore order-0 pages. Broken by: restoring `kho_preserve_pages()` memory via `kho_restore_folio()`, or diverging the PFN order decomposition. [F34]
- `kho_restore_folio()`, `kho_restore_pages()`, and `kho_restore_vmalloc()` (and their `!CONFIG_KEXEC_HANDOVER` stubs) return `NULL` on failure and never an `ERR_PTR`, despite the stale kernel-doc on `kho_restore_pages()`. Callers must check `!ptr`, not `IS_ERR(ptr)`. [F19]
- `kho_locate_mem_hole()` returns `0` when a scratch hole is found (`kho_walk_scratch()` returned `1`), `-EADDRNOTAVAIL` when KHO is active and no scratch region fits, and `1` when KHO does not apply (`!kho_enable`, `KEXEC_TYPE_CRASH`, or `!CONFIG_KEXEC_HANDOVER`) so `kexec_locate_mem_hole()` falls back to normal allocation. [F17]

## Error Handling

- `xa_load_or_alloc()` converts `xa_cmpxchg()` errors into error pointers via `ERR_PTR(xa_err(res))` and returns `ERR_PTR(-ENOMEM)` on allocation failure (never `NULL`), so callers such as `__kho_preserve_order()` must check `IS_ERR()` and extract `PTR_ERR()` rather than checking `!bits` or `xa_is_err()`. [F16]
- `kho_finalize()` and `kho_abort()` pass the return value of `blocking_notifier_call_chain(&kho_out.chain_head, ...)` through `notifier_to_errno()`, so callbacks registered via `register_kho_notifier()` must return `NOTIFY_DONE`/`NOTIFY_OK` on success and `notifier_from_errno(err)` or `NOTIFY_BAD` on error, never raw negative errnos. [F18]
- In `kho_init()`, a failure in `kho_in_debugfs_init(fdt)` must only log an error and return `0` without jumping to `err_free_fdt` or running the `init_cma_reserved_pageblock()` loop, whereas `alloc_page()` or `kho_out_debugfs_init()` failures must free `kho_out.ser.fdt`, release scratch areas, and set `kho_enable = false`. [F24]
- In `kho_reserve_scratch()`, the loop index `i` must be a signed `int` incremented only after each `memblock_*alloc*` call succeeds and populates `kho_scratch[i]`, so `err_free_scratch_areas` (`for (i--; i >= 0; i--)`) frees only completed allocations without unsigned underflow. [F59]

## External Contracts

- `kho_populate()` must validate the early-mapped handover FDT with both `fdt_check_header(fdt)` and `fdt_node_check_compatible(fdt, 0, KHO_FDT_COMPATIBLE)` (`"kho-v1"`) and successfully mark all scratch regions in memblock before calling `memblock_set_kho_scratch_only()` or setting `kho_in.fdt_phys` and `kho_in.scratch_phys`. Because `is_kho_boot()` and `kho_get_fdt()` test `kho_in.fdt_phys`, calling `is_kho_boot()` or `kho_retrieve_subtree()` before `kho_populate()` succeeds returns `false` / `-ENOENT`. [F23, F75]
- In the KHO root FDT, `PROP_PRESERVED_MEMORY_MAP` (`"preserved-memory-map"`) and child `PROP_SUB_FDT` (`"fdt"`) properties are stored as raw native-endian 64-bit (`u64`) physical addresses (not byte-swapped FDT integers) and must be validated with `!val || len != sizeof(u64)` before dereferencing. [F51]
- In `kho_out_finalize_set()` (backing `/sys/kernel/debug/kho/out/finalize`), writing a boolean equal to the current `kho_out.finalized` must return `-EEXIST` when already finalized or `-ENOENT` when already unfinalized without re-invoking `kho_finalize()` or `kho_abort()`. [F97]

## Known Pitfalls

- In `kho_restore_vmalloc()`, `preservation->total_pages` (`unsigned int`) must be widened to `unsigned long total_pages` before multiplying by `PAGE_SIZE` in `__get_vm_area_node(total_pages * PAGE_SIZE, ...)` to avoid 32-bit overflow. [F64]
- In `kho_mem_serialize()` and `deserialize_bitmap()`, the XArray index `phys` and bitmap offset `bit` must remain 64-bit `unsigned long` values when computing `(phys * PRESERVE_BITS) << (order + PAGE_SHIFT)` and `elm->phys_start + (bit << (order + PAGE_SHIFT))`. [F65]
- `kho_enable` is `__ro_after_init` and may only be modified during init (up to `late_initcall(kho_init)`), whereas `kho_scratch` and `kho_scratch_cnt` must not be marked `__initdata` because runtime debugfs handlers (`scratch_phys_show()`, `scratch_len_show()`) and kexec hooks (`kho_fill_kimage()`, `kho_walk_scratch()`) read them after init. [F79]
