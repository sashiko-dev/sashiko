# S390 VFIO AP DRIVER

The S390 VFIO AP driver (`vfio_ap`) implements VFIO mediated device (mdev) passthrough of s390 Adjunct Processor (AP) cryptographic adapters, usage domains, and control domains to KVM guests. It registers a virtual `matrix` bus and root device (`matrix_dev`), an AP bus driver (`vfio_ap_drv`) for CEX4 and newer crypto queues, and an mdev driver (`vfio_ap_matrix_driver`) exposing sysfs matrix assignment attributes and `vfio_ap_matrix_dev_ops`. It manages guest APCB shadow masks (`shadow_apcb`), intercepts guest `PQAP(AQIC)` instructions via a KVM `pqap_hook` (`handle_pqap`) to pin NIB pages and register GISA interrupts, resets AP queues via `system_long_wq` workers, and handles dynamic host AP configuration changes.

## Architecture & Data Flow

- Bit-level operations on `ap_matrix`, `ap_config_info`, and `ap_matrix_mdev` masks (`apm`, `aqm`, `adm`, `apm_add`, `aqm_add`, `adm_add`) must use s390 inverted bitops (`test_bit_inv`, `set_bit_inv`, `clear_bit_inv`, `find_first_bit_inv`, `for_each_set_bit_inv`), whereas word-level `bitmap_*` calls must be passed full-long bit counts (`AP_DEVICES` or `AP_DOMAINS`, both 256) rather than `*_max + 1`. [F55, F80]
- `ap_matrix.apm_max`, `aqm_max`, and `adm_max` hold inclusive 0-based maximum IDs, so ID validation in sysfs store handlers and `ap_matrix_overflow_check()` must reject `bit > *_max` with `-ENODEV`, while bit-search limits in `vfio_ap_mdev_matrix_show()` and `control_domains_show()` must use `*_max + 1`. `ap_matrix_copy()` copies only the bitmaps, so `matrix` and `shadow_apcb` max bounds must be initialized via `vfio_ap_matrix_init(&matrix_dev->info, ...)`. [F39, F56, F62]
- In `vfio_ap_find_queue()`, after `ap_get_qdev(apqn)` returns a `struct ap_queue *`, the driver must verify `queue->ap_dev.device.driver == &matrix_dev->vfio_ap_drv->driver` before reading `dev_get_drvdata(&queue->ap_dev.device)` as `struct vfio_ap_queue *`, and must always call `put_device(&queue->ap_dev.device)`. [F32]
- In `vfio_ap_mdev_filter_matrix()`, after intersecting `matrix_mdev->matrix` with `matrix_dev->info` into `shadow_apcb`, `_queue_passable()` checks must iterate over `shadow_apcb.apm` and `shadow_apcb.aqm` (not `matrix_mdev->matrix`). Any APID cleared from `shadow_apcb.apm` that was set in `prev_shadow_apm` must be recorded in `apm_filtered` and its queues reset via `reset_queues_for_apids()`. [F43, F44]
- In `vfio_ap_mdev_remove_queue()`, if the removed queue's APID and APQI are set in `shadow_apcb`, the driver must clear the APID from `shadow_apcb.apm`, call `vfio_ap_mdev_update_guest_apcb()`, and call `reset_queues_for_apid()` before unlinking `q` via `vfio_ap_unlink_queue_fr_mdev()`. Otherwise, it must check that both APID and APQI are set in `matrix_dev->info` before calling `vfio_ap_mdev_reset_queue(q)`. [F47, F85]
- In `vfio_ap_mdev_hot_unplug_adapters()` and `vfio_ap_mdev_hot_unplug_domains()`, `vfio_ap_mdev_unlink_adapter()` or `vfio_ap_mdev_unlink_domain()` must be called before clearing the bit in `matrix_mdev->shadow_apcb`, and `qlist` cleanup must use `list_for_each_entry_safe` to call `list_del(&q->reset_qnode)`. [F67]
- In `ap_config_store()`, `matrix_mdev->matrix` must hold `m_new` during `vfio_ap_mdev_validate_masks()` and `ap_matrix_overflow_check()`, be restored to `m_old` before `vfio_ap_mdev_hot_unplug_adapters()` and `vfio_ap_mdev_hot_unplug_domains()`, and be copied from `m_new` again before `vfio_ap_mdev_link_adapter()` and `vfio_ap_mdev_link_domain()`. [F68]
- In `vfio_ap_mdev_probe_queue()`, `vfio_ap_mdev_link_queue(matrix_mdev, q)` must execute before checking whether `matrix_mdev->apm_add` or `matrix_mdev->aqm_add` is non-empty, and `vfio_ap_on_scan_complete()` must clear `apm_add`, `aqm_add`, and `adm_add` only after `vfio_ap_mdev_hot_plug_cfg(matrix_mdev)`. [F70]
- In sysfs assign/unassign store handlers and `vfio_ap_mdev_link_queue()`, the driver must check whether the bit or queue is already in the target state before mutating `matrix_mdev->matrix` or calling `hash_add()`. Because `vfio_ap_mdev_validate_masks()` and `ap_matrix_overflow_check()` validate `matrix_mdev->matrix` in place, `assign_adapter_store()`, `assign_domain_store()`, and `ap_config_store()` must revert `matrix_mdev->matrix` (`clear_bit_inv()` or `ap_matrix_copy(&matrix_mdev->matrix, &m_old)`) when validation fails. [F16, F37, F49]

## Synchronization

- When updating a guest's APCB or modifying `matrix_mdev->kvm`, locks must be acquired in the order `matrix_dev->guests_lock`, `kvm->lock` (if attached), then `matrix_dev->mdevs_lock`, and released in reverse order via `get_update_locks_for_*` and `release_update_locks_for_*`, null-checking `matrix_mdev`, `q->matrix_mdev`, and `matrix_mdev->kvm` before dereferencing `kvm`. `get_update_locks_by_apqn()` always locks `guests_lock` and `mdevs_lock`, so callers must call `release_update_locks_for_mdev(matrix_mdev)` even when it returns `NULL`. [F7, F18, F33]
- `matrix_mdev->kvm` must not be modified between `get_update_locks_for_mdev()` (or `get_update_locks_by_apqn()` / `get_update_locks_for_queue()`) and `release_update_locks_for_mdev()`; `vfio_ap_mdev_set_kvm()` and `vfio_ap_mdev_unset_kvm()` must use `get_update_locks_for_kvm(kvm)` and `release_update_locks_for_kvm(kvm)` with a local `kvm` pointer. [F20]
- `kvm->arch.crypto.pqap_hook_rwsem` must never be acquired for write while holding `matrix_dev->mdevs_lock`, `guests_lock`, or `kvm->lock`, because KVM holds `pqap_hook_rwsem` for read when invoking `handle_pqap()`, which then locks `matrix_dev->mdevs_lock` and verifies both `vcpu->kvm->arch.crypto.pqap_hook` and `matrix_mdev->kvm` are non-NULL before accessing `matrix_mdev->qtable`. [F22, F101]
- Callers of `vfio_ap_mdev_validate_masks()` must lock `ap_perms_mutex` before `get_update_locks_for_mdev()` because `ap_apqn_in_matrix_owned_by_def_drv()` requires `ap_perms_mutex`, whereas `vfio_ap_mdev_resource_in_use()` is called with `ap_perms_mutex` already held and must not lock it. [F112]
- Every `vfio_ap_mdev_reset_queue()` call must be under `matrix_dev->mdevs_lock` and paired with `flush_work(&q->reset_work)` before releasing `mdevs_lock`, and `apq_reset_check()` must never acquire `mdevs_lock`, `guests_lock`, or `kvm->lock`. `vfio_ap_mdev_reset_queues()` and `vfio_ap_mdev_reset_qlist()` must run in two full passes—queuing `reset_work` on all entries, then flushing all entries without breaking early on non-zero `q->reset_status.response_code`. [F23, F66]
- When unplugging or filtering queues from a guest (`vfio_ap_mdev_hot_unplug_adapters()`, `vfio_ap_mdev_hot_unplug_domains()`, `vfio_ap_mdev_remove_queue()`, `vfio_ap_mdev_unset_kvm()`, or `vfio_ap_mdev_filter_matrix()` callers), the guest's APCB must be updated or cleared before resetting the removed queues. [F25]

## Object Lifetimes

- During queue unassignment, mdev removal, or KVM detachment (`vfio_ap_mdev_remove()`, `vfio_ap_mdev_hot_unplug_adapters()`, `vfio_ap_mdev_hot_unplug_domains()`, `vfio_ap_mdev_unset_kvm()`), `vfio_ap_mdev_reset_qlist()` or `vfio_ap_mdev_reset_queues()` must finish flushing `q->reset_work` before `q->matrix_mdev` or `matrix_mdev->kvm` is cleared or `kvm_put_kvm()` is called. [F24]
- In `vfio_ap_mdev_remove_queue()`, `q->matrix_mdev` must be saved into a local variable after `get_update_locks_for_queue(q)`, `flush_work(&q->reset_work)` must complete before `kfree(q)`, and the saved `matrix_mdev` pointer must be passed to `release_update_locks_for_mdev()`. [F9]
- `vfio_ap_free_aqic_resources()` must reset `q->saved_isc = VFIO_AP_ISC_INVALID` after `kvm_s390_gisc_unregister()` and `q->saved_iova = 0` after `vfio_unpin_pages()` to prevent double-unregistering or double-unpinning. [F13]
- When guest memory is unmapped via `vfio_ap_mdev_dma_unmap()`, `unmap_iova()` must hold `matrix_dev->mdevs_lock` and call `vfio_ap_irq_disable(q)` for every queue in `matrix_mdev->qtable.queues` whose `q->saved_iova` falls within `[iova, iova + length)`. [F98]
- In `vfio_ap_mdev_probe_queue()`, `q->apqn`, `q->saved_isc = VFIO_AP_ISC_INVALID`, `q->reset_status`, and `INIT_WORK(&q->reset_work, apq_reset_check)` must be initialized before `vfio_ap_mdev_link_queue()` or `dev_set_drvdata(&apdev->device, q)`. [F27]
- In `vfio_ap_matrix_dev_create()`, if `device_register(&matrix_dev->device)` fails, error recovery must call `put_device(&matrix_dev->device)` (where `vfio_ap_matrix_dev_release()` uses `container_of(dev, struct ap_matrix_dev, device)` to free `matrix_dev`), whereas failures after `device_register()` must call `device_del()` before `put_device()`. In `vfio_ap_mdev_probe()`, failure of `vfio_register_emulated_iommu_dev(&matrix_mdev->vdev)` must call `vfio_put_device(&matrix_mdev->vdev)`. [F1, F2, F77]
- In `vfio_ap_set_request_irq()` and `vfio_ap_set_cfg_change_irq()`, an existing `req_trigger` or `cfg_chg_trigger` must be released with `eventfd_ctx_put()` only after `eventfd_ctx_fdget(fd)` succeeds (when `fd >= 0`), and cleared to `NULL` after `eventfd_ctx_put()` when `fd == -1`. [F15]

## API Contracts

- Because `vfio_ap_irq_enable()` and `vfio_ap_free_aqic_resources()` use `vfio_pin_pages()` and `vfio_unpin_pages()`, `vfio_ap_mdev_probe()` must use `vfio_register_emulated_iommu_dev()` and `vfio_ap_matrix_dev_ops` must wire `.dma_unmap` (`vfio_ap_mdev_dma_unmap`) and `vfio_iommufd_emulated_*`. Callbacks taking `struct vfio_device *vdev` must use `container_of(vdev, struct ap_matrix_mdev, vdev)`, whereas `mdev->dev` callbacks must use `dev_get_drvdata(dev)`. [F79, F108]
- `vfio_pin_pages()` and `vfio_unpin_pages()` take a page count of `1`, and `vfio_ap_irq_enable()` must treat only a return value of `1` as success (mapping any other value to `AP_RESPONSE_INVALID_ADDRESS`). `vfio_ap_irq_enable()` must zero-initialize `aqic_gisa` (`gisc = isc`, `isc = nisc`, `gisa = virt_to_phys(gisa) >> 4`) and pass host physical `h_nib = page_to_phys(h_page) | (nib & ~PAGE_MASK)` to `ap_aqic()`. [F29, F42, F109]
- In `vfio_ap_validate_nib()`, a zero guest NIB (`!*nib`) must be explicitly rejected with `-EINVAL` in addition to `kvm_s390_is_gpa_in_memslot()`, because GPA 0 is a valid s390 memslot while `q->saved_iova == 0` is the sentinel for an unpinned NIB in `vfio_ap_free_aqic_resources()`. [F53]
- In `vfio_ap_irq_disable()`, when `ap_aqic()` returns `AP_RESPONSE_NORMAL` or `AP_RESPONSE_OTHERWISE_CHANGED`, the driver must call `vfio_ap_wait_for_irqclear(q->apqn)` (which only returns on `AP_RESPONSE_NORMAL` or `AP_RESPONSE_RESET_IN_PROGRESS` when `!status.irq_enabled`, otherwise falling through to `AP_RESPONSE_BUSY`) before calling `vfio_ap_free_aqic_resources(q)`. [F64, F93]
- Queue reset paths (`vfio_ap_mdev_reset_queue()` and `apq_reset_check()`) must rely on `ap_zapq()` to disable queue interrupts and call `vfio_ap_free_aqic_resources(q)` directly rather than `vfio_ap_irq_disable(q)`. In `apq_reset_check()`, when `ap_tapq()` stops reporting `-EBUSY`, if the prior `q->reset_status.response_code` was `AP_RESPONSE_RESET_IN_PROGRESS`, `AP_RESPONSE_BUSY`, or `AP_RESPONSE_STATE_CHANGE_IN_PROGRESS`, or if `apq_status_check()` returned `-EAGAIN`, the worker must re-issue `ap_zapq(q->apqn, 0)` and continue polling before freeing AQIC resources. [F86, F94]
- In `vfio_ap_mdev_cfg_add()`, `vfio_ap_filter_apid_by_qtype()` must query added queues via `ap_test_queue(..., 1, &info)` and clear any APID from `apm_add` whose adapter type `info.at` is below `AP_DEVICE_TYPE_CEX4` or whose response code does not populate `info`. [F91]

## Error Handling

- In `vfio_ap_irq_enable()`, once `vfio_pin_pages()` returns `1`: if `kvm_s390_pv_cpu_is_protected(vcpu)` is true, `ensure_nib_shared(h_nib & PAGE_MASK)` must be called; `kvm_s390_gisc_register()` must be stored in a signed `int nisc` and checked for `nisc < 0` before setting `aqic_gisa.isc`; and any failure in `ensure_nib_shared()`, `kvm_s390_gisc_register()`, or `ap_aqic()` returning `AP_RESPONSE_OTHERWISE_CHANGED` must unpin `nib` via `vfio_unpin_pages(&q->matrix_mdev->vdev, nib, 1)` (without `gmap_convert_to_secure()`) and unregister `isc` if registered. [F10, F12, F30, F110]
- In `vfio_ap_irq_enable()`, `switch (status.response_code)` after `ap_aqic()` must distinguish `AP_RESPONSE_NORMAL` (calling `vfio_ap_free_aqic_resources(q)` before saving the new `nib` and `isc` into `q`), `AP_RESPONSE_OTHERWISE_CHANGED` (cleaning up only the local `isc` and `nib` without touching `q`'s saved resources), and `default` (calling `vfio_ap_irq_disable(q)`). [F63]
- In `vfio_ap_mdev_probe_queue()`, if allocating `struct vfio_ap_queue` fails after `sysfs_create_group(&apdev->device.kobj, &vfio_queue_attr_group)`, the error path must call `sysfs_remove_group()`. [F8]

## External Contracts

- `handle_pqap()` must return `-EOPNOTSUPP` only when `ECA_AIV` is clear in `vcpu->arch.sie_block->eca`; on all other paths it must return `0` after copying the 32-bit `struct ap_queue_status` (`qstatus`, initialized to `AP_RESPONSE_Q_NOT_AVAIL`) into `vcpu->run->s.regs.gprs[1]` and right-shifting `gprs[1]` by 32 bits. [F31]
- In `vfio_ap_mdev_request()`, `kvm_arch_crypto_clear_masks()` and `signal_guest_ap_cfg_changed()` must be invoked under `get_update_locks_for_mdev(matrix_mdev)` before signaling `matrix_mdev->req_trigger`, rather than calling `signal_guest_ap_cfg_changed()` in `vfio_ap_mdev_unset_kvm()`. [F26]
- `vfio_ap_mdev_get_device_info()`, `vfio_ap_get_irq_info()`, and `vfio_ap_irq_set_init()` must copy only `minsz` from userspace, convert any non-zero `copy_from_user()`/`copy_to_user()` residual count to `-EFAULT`, and validate `argsz >= minsz` and `index < VFIO_AP_NUM_IRQS` (plus `VFIO_IRQ_SET_DATA_EVENTFD` in `vfio_ap_set_irqs()`) before reading the eventfd at `arg + minsz`. [F28, F59, F115]

## Known Pitfalls

- In `ap_config_store()`, `vfio_ap_mdev_hot_unplug_cfg()`, `vfio_ap_mdev_cfg_remove()`, `vfio_ap_mdev_on_cfg_remove()`, `vfio_ap_mdev_on_cfg_add()`, and `vfio_ap_mdev_hot_plug_cfg()`, dirty flags across `vfio_ap_mdev_filter_matrix()`, `vfio_ap_mdev_filter_cdoms()`, and `bitmap_andnot()` must be combined with bitwise `|=` rather than logical `||` so later bitmap-mutating calls are not short-circuited. [F61]
- In `vfio_ap_mdev_verify_no_sharing()`, `assigned_to` must be skipped when `assignee == assigned_to`, both `bitmap_and()` checks on `apm` and `aqm` must be non-zero to report a conflict, and when `assignee` is NULL the `else` branch must pass `assigned_to` (not `assignee`) to `vfio_ap_mdev_log_in_use_err()`. [F69]
- `VFIO_AP_DBF_*` calls must not pass `%s` pointers to non-persistent memory (such as mdev device names) and must stay within `DBF_MAX_SPRINTF_ARGS` (10 total arguments), converting an mdev's `guid_t` into `unsigned long uuid[6]` via `vfio_ap_le_guid_to_be_uuid()` (using `le32_to_cpup`/`le16_to_cpup` on `guid->b[0..7]` and unsigned `__u16`/`__u32` casts on `guid->b[8..15]`). [F60, F76]
