# review-runtime

Orchestrates patchset and commit code reviews across daemon, local CLI, worker subprocess, and benchmark modes, plus background bug analysis and Git maintenance workers (`BugWorker`, `RepackWorker`, `GitSyncWorker`). It manages baseline resolution and worktree setup, C context prefetching (`prefetch`), multi-stage LLM workflows (`Worker`), diff location resolution (`location_resolver`), database persistence, and benchmark evaluation.

## Architecture & Data Flow
- In `Reviewer`, terminal status transitions at the end of `review_patchset_task` and in `mark_patchset_failed_unless_cancelled` must check `get_patchset_status` and never overwrite `ReviewStatus::Cancelled` with `Reviewed` or `Failed`. [F3]
- In `Reviewer::review_patchset_task`, any patch filtered before `ValidJob` enqueueing (`skip_filters`, `only_filters`, `max_lines_changed`, `max_files_touched`) has no `reviews` row and must persist `"Skipped"` via `Database::update_patch_status` before continuing; the intra-patchset worker spawn loop must stop acquiring extra `ctx.semaphore` permits once `remaining <= handles.len()`. [F5, F103]
- In `Reviewer::prepare_baseline_worktree`, each `BaselineResolution` candidate's git ref must come from `candidate.as_str()`, and a candidate with `is_merged_default_head` true must be deferred to the back of `queue` as `(candidate, true)` on its first visit so non-merged candidates are tried first. [F7]
- In `local_review::run_worker_in_worktree`, a failed patch in the concurrent stream must not discard other patches' reviews: it must record `review_status: 'incomplete'` via `mark_patch_review_incomplete`, accumulate `WorkflowFailure` tokens and history, and set `partial: true` and `error` (`combined_review_error`). Before extending `combined_history`, each patch's `review_map` stage `log_start`/`log_end` must be shifted by `combined_history.len()` via `offset_review_map_log_bounds` (`attach_patch_review_map`). [F9, F10]
- In `Worker::run`, when `patchset["patch_index"]` matches entries in `patchset["patches"]`, `target_commit_diff` and `target_commit_diff_only` must be populated only from matching entries rather than concatenating other series patches. [F117]
- `SourceSnapshot::new` requires a 40- or 64-char ASCII hex `target_sha` verified via `git rev-parse --verify --end-of-options <target_sha>^{commit}`, and `SourceSnapshot::read` reads blobs solely via `git show <sha>:<path>` without worktree fallback. [F118]
- In `prefetch::prefetch_context`, `called_functions` must merge into `symbols_to_lookup` only after `find_opaque_types` filters `symbols_to_lookup` (or `struct X *var` checks drop function names). Phase 2 must truncate `symbols` to `<= 50` entries and cap `candidates` per symbol to `<= 32` `priority` and `<= 32` `general` `git grep` hits before `best_definition_range`. `render_range_map` must render `modified_files` before definition-only files and stop with a truncation notice before exceeding `MAX_PREFETCH_CHARS` (200,000 bytes). [F14, F98, F99]
- In `location_resolver::parse_two_sided_diff`, `post_ranges` and `pre_ranges` must record only `+`/`-` line indices (or header ranges when a hunk has no body), never context lines or inter-hunk gaps, so `ResolvedLocation.in_diff` is true only on modified lines. `ParsedDiff`, `parse_diff_ranges`, and `find_snippet_in_lines*` use 0-based `usize` line indices, while `hint_line`, `symbol_line`, and `ResolvedLocation` (`line`, `end_line`) are 1-based. [F17, F114]
- In `location_resolver`, `compute_character_offsets`, `find_snippet_in_lines_fallback`, and `find_snippet_in_deleted_lines_fallback` must measure line lengths and indentation in Unicode scalar values (`.chars().count()`), never byte lengths (`.len()`). In `read_file_content`, when `revision` is `Some`, content is read only from git blobs `<= MAX_RESOLVE_FILE_SIZE` (4 MiB) via `git cat-file` without disk fallback; when `None`, disk fallback must verify `canon_file.starts_with(&canon_worktree)`. [F105, F122]
- In `Reviewer::process_patch_review`, findings with `preexisting == Some(true)` and pre-existing `concerns` are persisted only when `ctx.settings.linux_bug.enabled` is true, and `concerns` must be submitted via `process_issue_for_project` on `ctx.db.with_bug_actor(...)`. [F151]
- `Reviewer::release_patchset_results` must claim via `db.claim_patchset_embargo_release(patchset.id, now)` and clear via `db.clear_patchset_embargo_release_claim` on error; `queue_patchset_notifications` must always call `db.release_embargoed_forge_outbox` and `db.clear_patchset_embargo` even if `reviews` is empty. In `queue_notifications`, `preexisting == true` findings are excluded from `new_findings` and `total_issues_count`, and notifications are muted (`"Muted"` in `email_outbox`) when `EmailRouter::is_ignored_author` matches or the author's bare email matches `sender_address`. [F139, F140]
- `BugWorker::sweep_zero_token_fix_checks` bounds each sweep to `<= MAX_FIX_CHECK_SCAN_CHUNKS` (80) chunks of `FIX_CHECK_SCAN_CHUNK_SIZE` (250) bugs and `<= MAX_CACHED_RANGES_PER_SWEEP` (64) cached `CommitRangeLookup` indices, advancing `FixCheckClassification::Untouched` bugs without consuming `batch_size`. [F100]
- `GitSyncWorker::sync_all_remotes` must skip remotes starting with `"fetcher-"` and call `refresh_remote(&self.repo_path, remote, &url, false)` (`force_fetch = false`) to enforce fetch intervals and 1-hour failure backoff. [F144]
- In `persist_benchmark_patch`, all SQL writes must go through `Database::execute` (not `db.conn.execute`) after dropping any `db.conn.query` cursor (`rev_rows`); it deletes only `reviews` (and their `findings`/`tool_usages`) where `status != 'Reviewed'`, and resets `patches.status`/`patchsets.status` to `'Pending'` only when no `'Reviewed'` row exists. Both `count_commit_review_progress` and `load_commit_review_data` select the canonical review with `ORDER BY CASE WHEN status = 'Reviewed' THEN 0 ELSE 1 END ASC, id DESC LIMIT 1`; `load_commit_review_data` decodes `ai_interactions.output_raw` via `get_compressed_string_opt` and runs `load_bugs_for_review` before `populate_dismissed_from_output`. [F145, F146, F147, F148]

## Synchronization
- `Reviewer::start` must gate `worktree_dir` removal and `db.reset_reviewing_status()` behind `self.initialized.swap(true, Ordering::SeqCst)` and run the filesystem wipe in `tokio::task::spawn_blocking` so supervisor restarts do not delete active worktrees or block the executor. [F23]
- In `Reviewer::process_pending_patchsets`, after acquiring a `self.semaphore` permit, the loop must atomically claim via `self.db.claim_patchset_for_review(patchset.id)` and skip spawning on `Ok(false)` in case the patchset was `Cancelled` while awaiting. [F24]
- In `Reviewer::review_patchset_task`, intra-patchset workers sharing `valid_jobs_queue: Arc<tokio::sync::Mutex<Vec<ValidJob>>>` and `worktree.path` must drop the queue lock before `process_patch_review(...).await` and must all be joined before `worktree.remove().await`. [F27]
- `Reviewer::fetch_missing_commit` (`try_fetch_within`) must bound the entire loop over candidate maintainer remotes with one shared `FETCH_TIMEOUT` deadline (deduplicating URLs, skipping `mainline_url`) and pass `-c protocol.version=2 fetch --no-tags --no-write-fetch-head`. [F96]
- `Reviewer::new` and `run_worker_in_worktree` bound total in-flight LLM requests with a shared `llm_semaphore` (`llm_permits(concurrency)`). `run_review_tool_with_cmd_and_overrides` and `local_review::decorate_provider` must wrap `ConcurrencyLimitedProvider` (inner) inside `BackoffProvider` (outer) so rate-limited sleeps release their `llm_semaphore` permit first; for `stdio-*` providers, `decorate_provider` must skip both wrappers and `worker_max_attempts` must return `1`. [F30, F31, F94]
- In `run_review_tool_with_cmd_and_overrides`, `ai_request` and `ai_request_with_cache` lines must run in spawned tasks (serializing replies via `stdin_writer`), whereas `ai_forget` (`provider.forget(&req)`) must be awaited inline. The shared `deadline: Arc<std::sync::Mutex<TokioInstant>>` (`DeadlineBudget`) must be locked only to copy `*d` into `current_deadline` before `tokio::select!` and `timeout_at`. [F32, F111]
- `BugWorker::run` must acquire an `OwnedSemaphorePermit` before `self.db.claim_pending_bug` and move it into the spawned task (or drop it on `Ok(None)`/`Err`) so at most `settings.concurrency.max(1)` bugs are `Running`. [F35]
- In `Worker::run`, `state.resolve_locations()` must run inside `tokio::task::spawn_blocking` when `state.worktree_path.is_some()`. [F36]
- `benchmark::count_commit_review_progress` must treat a commit as pending until `patchsets.status` leaves `""`, `"Pending"`, `"In Review"`, and `"Fetching"`, even if `reviews.status` is terminal, so `run_benchmark_reviews` does not abort `reviewer_task` and delete `paths.worktree_dir` early. [F38]

## Object Lifetimes
- `Reviewer::spawn_supervised_patchset_review` must hold the `OwnedSemaphorePermit` in an outer task that awaits a nested `tokio::spawn(review_fut)` and calls `mark_patchset_failed_unless_cancelled` on `JoinError`. [F25]
- When the interaction block in `run_review_tool_with_cmd_and_overrides` exits, all `spawned_tasks` must be aborted before `stdin_writer` is shut down/dropped and before `child` is killed or awaited. On timeout, `ReviewError::Cancelled`, or `ReviewError::BudgetExceeded`, the child must be killed via `child.start_kill()` with `child.wait()` bounded by `tokio::time::timeout`. [F33, F40]
- In `local_review::run_worker`, when `options.current_tree` is true or `options.reuse_worktree` is `Some`, `GitWorktree` must be built with `GitWorktree::from_path` (`is_managed: false`) so `worktree.remove().await` does not delete a caller-owned or shared worktree. [F45]
- `run_benchmark_reviews` must guard the `Reviewer::start` task with `AbortTaskOnDrop(reviewer_task.abort_handle())` and explicitly abort and await `reviewer_task` before removing `paths.worktree_dir`. [F46]
- In `BugWorker`, both `run` and `verify_single_bug_upstream` must scope `Database` with `with_bug_claim(bug.id, &claim_id)` inside `run_while_leased(..., maintain_lease(...))`. `maintain_lease` retries transient `db.renew_bug_lease` errors only until the last confirmed `deadline` (`timeout_at(deadline, ...)`) and returns on `Ok((_, Ok(false)))` or `Err(_)`, dropping the analysis future without calling `release_bug_lease` or `fail_bug_analysis`. [F18, F65]

## API Contracts
- `local_review`, `worker::location_resolver`, `worker::prefetch`, and `worker::prompts` must compile without `feature = "server"`, and `build_review_output` and `run_worker_in_worktree` must preserve `summary`, `findings`, `concerns`, `dismissed_concerns`, `concerns_count`, `dismissed_concerns_count`, and single-patch `review_map` in the top-level `review` JSON object (plus `patch_index`/`patch_subject` on aggregated items). [F75, F152]
- `normalize_file_path_with_worktree_and_rev` (`normalize_file_path_with_worktree`, `normalize_file_path`) must reject empty paths, parent/root/prefix components, and components starting with `'-'`, stripping a leading `a/` or `b/` only after verifying the unstripped path does not exist in the target revision or worktree. [F83]
- `resolve_single_location_two_sided` and `resolve_finding_locations_with_parsed_diff` (`resolve_finding_locations`) must treat each location `serde_json::Value` as untrusted JSON that may contain only `file` and `code_snippet`, accessing optional keys via `.get(...)` and `as_object_mut()`. [F106]
- In `Worker::run`, `WorkerProgressEvent::ReviewStarted` may be emitted a second time when post-verification stages are refined into `planned_stages`, so `ProgressEvent::AiReviewPlanReady` handlers must only update the planned stage list without resetting completed or active stages. [F87]
- `parse_judge_verdict` requires a non-empty response whose trimmed, ASCII-uppercased JSON `status` or plain-text fallback token is `DETECTED`, `PARTIALLY_DETECTED`, or `MISSED`, returning `ValidationError::FormatViolation` otherwise. [F124]

## Error Handling
- In `Reviewer::review_patchset_task`, DB errors in `get_patch_diffs`, `get_message_body`, or `get_baseline_commit` must mark the patchset `Failed` via `mark_patchset_failed_unless_cancelled` and return rather than falling back to heuristic baselines and `FailedToApply`. [F4]
- All `ReviewError` variants (`LimitExceeded`, `BudgetExceeded`, `FormatRejection`, `OutputTruncated`, `Cancelled`) classify as `AiErrorClass::Fatal` (`ClassifyAiError`). `Reviewer::process_patch_review` must skip patches where `count_successful_reviews >= ctx.target_review_count` or `has_failed_review` is true, and never retry `ReviewError::Cancelled` or `ReviewError::BudgetExceeded`. [F125, F137]
- In `run_review_tool_with_cmd_and_overrides`, `max_total_tokens` is checked against cumulative `(prompt_tokens - cached_tokens) + completion_tokens` and `max_total_output_tokens` against cumulative `completion_tokens`; on overflow, the task must send `ReviewError::BudgetExceeded` on `abort_tx` without writing to child stdin, and the parent must poll `abort_rx` via `biased;` `select!` plus post-loop `try_recv()` and kill the child. Child stderr lines containing `" ERROR "`, starting with `"Error:"`, or containing `"panicked"` must be logged at `error!`. [F52, F64, F126]
- In `Worker::run`, `prefetch_context` or `select_code_notes` errors degrade to warnings and empty strings (setting `state.prefetch_failed = true` on prefetch error), whereas `WorkflowEngine::execute` or location-resolution errors propagate with `?`. In `prefetch_context`, `git grep` exit code `1` (`Some(1)`) means no matches and is not an error. [F54, F70]
- When `!options.agent`, `extract_inline_review` must return `Err` if `output["findings"]` is non-empty but `output["review_inline"]` is missing or whitespace-only, causing `review_single_patch` to retry. [F56]
- In `BugWorker::verify_single_bug_upstream`, if `check_bug_fixed_upstream_with_candidates` returns `Err` while leased, it must call `scoped_db.touch_bug_fix_check_timestamp(bug.id)` so the bug does not block the keyset-paginated queue head. [F66]
- `CommitReviewData::is_completed_review` (`build_benchmark_summary`) requires `self.review_id.is_some()` and `self.review_status` not in `None | Some("" | "Pending" | "In Review" | "Failed" | "Skipped" | "Cancelled")`. [F67]
- Outbox workers (`ForgeWorker`, `PatchworkWorker`) must build HTTP clients via `worker::outbox_client` / `worker::build_outbox_client` to enforce `OUTBOX_CONNECT_TIMEOUT` (10s) and `OUTBOX_REQUEST_TIMEOUT` (60s). [F69]

## External Contracts
- `print_worker_json` must flush `std::io::stdout()` immediately after printing the worker JSON line. `progress_to_stderr` and `progress_line` must prefix lines with `PROGRESS_LINE_PREFIX` (`"progress: "`) and emit `" turn "` only for `ProgressEvent::AiReviewStageTurn`. [F41, F74]
- `format_agent_review_output` must set `status` to `"error"` when `result_has_error(result)` is true, `"issues_found"` when `review.findings` is non-empty, or `"clean"` otherwise, stripping `review_map` from `patches` and omitting `history`, `input_context`, `inline_review`, and `dismissed_concerns`. [F77]
- In `run_review_tool_with_cmd_and_overrides` (`WorkerSubprocessOverrides`), spawning `sashiko worker` must call `cmd.env_clear()`, restore only `PATH`, `HOME`, `USER`, `LANG`, `LC_ALL`, and `TERM`, forward `SASHIKO_*` vars (and overridden `SASHIKO_CONFIG`), and pass `--project`. [F81]
- `Reviewer::queue_notifications` must unpack `To`/`Cc` headers with `crate::patch::split_address_list` rather than `str::split(',')`. [F72]
- `configure_benchmark_settings` must set `settings.smtp = None` and `settings.forge.enabled = false`, and `write_benchmark_artifacts` must write both `paths.results_json_path` and `benchmark_results.json`. [F89]

## Known Pitfalls
- In `parse_diff_git_paths`, the symmetric check (`k = (rest.len() - 5) / 2`) must slice `rest` with `.get(...)` rather than `&rest[..]` because `2 + k` can fall inside a multi-byte UTF-8 codepoint. [F104]
- Because `Worker::run` uses `"unknown"` for unresolved `baseline_sha` and `target_commit_sha`, revision helpers (`path_exists_in_git`, `read_file_content`, `build_follow_up_series_context`, `build_sashiko_series_context`) must reject `"unknown"` as well as `""`. [F115]
