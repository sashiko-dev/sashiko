# notes

The `notes` component scopes a repository at a pinned Git revision into ownership units and components, mines historic bug fixes, and runs multi-stage LLM workflows (survey, history classification, exploration, deduplication, independent verification, and synthesis) to produce verified code notes and fact sidecars. It also provides CLI subcommands (`plan`, `build`, `corpus`, `agenda`) for deriving agendas and building notes sets, plus deterministic review-time note selection.

## Architecture & Data Flow
- When CLI component filtering (`--select` or `--component` in `cli::run`) retains a subset of `UnitPlan::components`, `UnitPlan::all_component_names` must keep the full pre-filter component list in plan order so `is_split_unit`, `is_partial_selection`, and `component_slug_map` preserve split-unit status and deterministic slugs. `build_unit` writes a single `units/<slug>.md` only when `!unit.is_split_unit()`, routing split units through `synthesize_and_write_components` so each component gets its own `cfg.note_bytes` budget under `units/<unit>--<comp>.md`. [F1, F71]
- Multi-component manifest keys must use `<unit.slug>--<comp_slug>` (while `unique_slug` collapses non-alphanumeric runs to single `-`) so `unit_group` in `select_symbol_notes` and `prune_stale_unit_entries` can split on `"--"` to group siblings. `prune_stale_unit_entries` must pass `prune_children: false` when `unit.is_partial_selection()` is true so a component-filtered rebuild removes only a legacy unsplit `<unit_slug>` entry without deleting unselected `<unit_slug>--*` siblings from `manifest.json` and `units/`. [F2, F9]
- `NotesCommand::Build` in `cli.rs` must scope `BuildConfig::work_dir` by project, `set`, and resolved commit `sha`, and `build_unit` must join `unit.slug`. When resuming (`cfg.resume`) and `state.components` has any component missing from saved `survey.json` or `explore.json`, `extended` becomes `true`, which must bypass saved `checked.json`, `dedup.json`, `note.md`, and `notes/<comp>.md` checkpoints (via `.filter(|_| !extended)`) while reusing saved `verdicts.json` entries by `fact_id`. [F3, F24]
- Both normal explore reduction and `salvage_explore` must run `ground_symbols` on every kept `Fact` to strip any `FactScope::symbols` entry not appearing as a substring of at least one of its `Evidence::snippet`s. `check_verifier_evidence` must check every `VerdictKind::Confirmed` verdict's cited `evidence` via `RevisionFiles::check` and downgrade it to `VerdictKind::Unverifiable` if no `Evidence` entry passes `EvidenceCheck::is_ok()`. [F6, F8]
- Only facts selected by `noted_facts` (`VerdictKind::Confirmed` and `ReviewValue::PatchRule`) may be passed to synthesis/fallback note generation or counted in `ManifestUnit::confirmed_facts` and `ManifestUnit::symbols`, whereas `UnitFacts::facts` persists the entire `VerifiedFact` list. [F7]
- Before writing any synthesized, empty, or fallback note to `note.md`, `notes/<comp_slug>.md`, or `units/<slug>.md`, `build_unit` and `synthesize_and_write_components` must pass the text through `neutralize_directives`, while `select_notes` and `select_symbol_notes` strip `[F<n>]` citations via `strip_citations` when loading notes for review. [F18]
- `choose_set` must order candidate `NotesSet`s with valid repository `commit_time` timestamps by commit time and pick the newest set whose `manifest.revision` is an ancestor of `baseline` via `is_ancestor` (`git merge-base --is-ancestor`), falling back to the oldest set only when no set is an ancestor. [F14]
- In `select_symbol_notes`, a foreign unit is selected for `NoteReason::UsedSymbols` only when a touched symbol satisfies `is_cross_unit_symbol`, appears in at most `MAX_UNITS_PER_SYMBOL` parent unit groups in both `owner_groups` and `note_freq_groups`, and is extracted as a leading clause subject by `bullet_subject_symbols` in `focus_symbol_note` (not `focus_note`). [F15]
- In `assign_units`, only the first unit returned by `UnitSource::owners` owns a file in `Unit::files` while subsequent owners list its path at most once in `Unit::shared`, and `MaintainersUnits::owners` must exclude `catch_all` (`F: *`) sections so files matched only by catch-all remain `unassigned`. In `split_dir`, recursion stops when `lines <= max_lines` or `group.len() == 1 && dir_components(&group[0].path).len() <= depth`, placing a single file exceeding `max_lines` into its own component. [F10, F68]
- For `Language::Rust` files, `list_source_files` splits lines from the first column-0 `#[cfg(test)]` or `#[cfg(all(test, ...))]` (`rust_test_boundaries`) into `SourceFile::test_lines` and keeps only preceding lines in `SourceFile::lines`, and `extract_entry_points` must ignore matches with `file.test_lines > 0 && line > file.lines`. [F11]
- `multi_component_unit_history` must hydrate deduplicated fix commits against all `scope_files` of the unit (not just the mining component's files) so `place_lessons` can attach each `LessonKind::CodeBug` lesson to every component whose `files` intersect `HistoryCase::files` (or all unit components when `case.files` is empty). [F12]
- `collect_fix_commits` and `rule_comments` chunk `files` by `PATHS_PER_CALL` (400): `collect_fix_commits` sorts and truncates deduplicated results across chunks to `max_cases`, while `rule_comments` stops once `found.len() >= max` and truncates each comment to `LINE_CHARS` (200). `hydrate_history_cases` restricts `git show` diffs to `scope_files` when `scope_files.len() <= PATHS_PER_CALL` and truncates `message` and `diff` via `truncate_chars` to `MESSAGE_CHARS` (1,500) and `DIFF_CHARS` (3,000). [F64, F66, F93]
- `corpus::analyze` and `classify_history` pass 12-char `fix_id` prefixes (`FIX_ID_LEN`) to LLM stages, so `records_for` must join `CaseAnalysis::fix` by `fix_id` before restoring the full SHA into `CorpusRecord::fix`, whereas `place_lessons` keeps the 12-char `PlacedLesson::fix`. `case_context` truncates `CorpusCase` messages to `MESSAGE_CHARS` (2,000) and fix diffs to `FIX_DIFF_CHARS` (12,000), attaching at most `MAX_INTRODUCED` (2) distinct resolved `IntroducedChange` commits restricted to the fix's `files` and truncated to `INTRODUCED_DIFF_CHARS` (4,000). [F84, F94]
- `derive_agenda` bounds theme reduction to `MAX_MERGE_LEVELS` (8) levels, sorts remaining themes by descending `count` and truncates to `MAX_FINAL_THEMES` before `write_stage`, while `map_themes` and `merge_themes` cap `Theme::examples` at `THEME_EXAMPLES`. `RevisionFiles::lines` caches `Option<Vec<String>>` (including `None`) per path, and `relocate` bounds whole-file snippet searches to `(wanted.len() * 2).max(cited_span) + 10` lines from each candidate first line. [F70, F74]
- `llm_env` (`cli.rs`) must pin `ToolBox::set_virtual_head` to the resolved `sha` and wrap the provider with `decorate_provider` (attaching a `Semaphore` of `settings.review.concurrency.max(1)` permits and a `QuotaManager`) before running workflows. `TokenEstimate::for_component` and `TokenEstimate::add` must use `saturating_mul` and `saturating_add` when computing `[low, high]` bounds from `TOKENS_PER_LINE`, `CONTEXT_PASSES_LOW..CONTEXT_PASSES_HIGH`, and `COMPONENT_OVERHEAD_LOW..COMPONENT_OVERHEAD_HIGH`. [F101, F103]

## Synchronization
- `write_unit` and `prune_stale_unit_entries` (`output.rs`) must hold an exclusive `File::lock()` on `<set_dir>/.manifest.lock` (`LOCK_FILE`) across loading `manifest.json`, verifying in `write_unit` that any existing `Manifest` matches `manifest_header` (`project`, `set`, `revision`), writing or removing unit files, and calling `write_atomic` on `manifest.json`. [F4, F19]
- `write_atomic` and `CorpusMeta::claim` must write to a PID-suffixed temp file in the target directory and `std::fs::rename` it over the destination. Before writing shard records, `CorpusMeta::claim` must verify any existing `corpus-meta.json` (`META_FILE`) equals `self` (`revision`, `fix_patterns`, `limit`, `sample`, `seed`) and bail on mismatch. [F5, F20]
- In `list_source_files` and `build_plan`, CPU-bound parsing of full-tree Git output (`parse_tree_paths`, `parse_count_output`), language classification, `assign_units`, and `plan_unit` must run inside `tokio::task::spawn_blocking`. In `cli::run` for `NotesCommand::Build`, the concurrency limit passed to `buffer_unordered` must be clamped with `(*jobs).max(1)`. [F21, F80]

## Object Lifetimes
- `write_unit` must atomically write `<slug>.md` and `<slug>.facts.json` into `UNITS_DIR` via `write_atomic` before inserting `slug` into `manifest.units` and calling `write_atomic` on `MANIFEST_FILE`. [F26]

## API Contracts
- `resolve_revision`, `commit_time`, `is_ancestor`, and `read_at_revision` must reject revisions or paths starting with `-` (and `..` segments in `read_at_revision`) before invoking `git`. `cli::run` and `load_agenda` must validate `--set` via `is_safe_set_id` and agenda module names via `is_safe_module_name` before joining filesystem paths. [F54, F55]
- In `parse_selection`, a line naming only a unit (or with an empty component after `\t`) sets that unit's `Selection` entry to `None`, overriding earlier and later component-specific lines. Component-filtered `--select` entries must key units by exact `UnitPlan::name` (not slug or case-insensitive name), because `cli::run` looks up `selection.get(&unit.name)` even though `select_units` matches case-insensitively. [F16, F62]
- `select_symbol_notes` requires `chosen` to contain the `SelectedNote`s returned by `select_notes` for the same patch so it can skip already-selected units by `unit.name` and detect touched parent groups via `NoteReason::TouchedFiles` on `<unit>--<comp>` entries. [F63]

## Error Handling
- When `WorkflowEngine::execute` fails in `run_step` with a `WorkflowFailure`, `run_step` best-effort saves `failure.outcome.history` to `<step>.history.json` before returning `Err`, without writing `<step>.stages.json` or the caller's `<step>.json` (`save_step`). In `cli::run` (`NotesCommand::Build`), `build_unit` errors are collected into `failures` while draining the entire `buffer_unordered` stream, bailing after the loop if `failures` is non-empty. [F38, F39]
- In `build_unit`, `salvage_explore` parses only a failed explore stage's last non-empty `AiRole::Assistant` message, keeps unique-ID facts passing `check_fact`, truncates to `MAX_FACTS_PER_STAGE`, and runs `ground_symbols`. If `notes_dedup` fails, `build_unit` logs `warn!` and saves an empty `groups` `Vec` to `dedup.json` so all `checked` facts reach verification. `verified_facts` defaults facts missing from `verdicts` to `VerdictKind::Unverifiable` and `ReviewValue::Unknown`. When `notes_synthesize` fails, `build_unit` and `synthesize_and_write_components` set `summary.synthesis_fallback = true` and render `fallback_note` within `max_bytes`. [F34, F36, F96, F102]
- `corpus::read_done` and `agenda_derive::read_corpus` warn and skip unparseable `CorpusRecord` JSONL lines, while `append_records` prepends `"\n"` if the file lacks a trailing `b'\n'`. In `corpus::analyze`, `case_context` and workflow errors are logged with `warn!` and counted in `summary.failed`, appending only matched `records_for` entries to `cfg.out_file`. In `case_context`, candidate introducing commit IDs are checked via `resolve_commit`, skipping unresolved, self-equal, or duplicate IDs without failing. [F40, F41, F42]
- In `derive_agenda`, `run_groups` logs workflow errors with `warn!`, and at each reduce level any failed batch (`!ok` in `done`) carries its unmerged input `Theme` slice forward into `merged`. Every module string from `render_module` must pass `parse_agenda_module(&module.module, &text)` before writing `<module>.md`. At review time, `load_sets`, `choose_set` (`commit_time`), `select_notes`, `select_symbol_notes`, and `load_maintainer_notes` skip broken manifests, commits, or `.md` files rather than failing. [F43, F44, F46]
- In `count_lines_output`, `rust_test_boundaries`, `grep_lines`, and `rule_comments`, `git grep` exit code `Some(1)` is treated as empty output, whereas other non-zero codes bail. `parse_grep_records` skips non-UTF-8 paths or bad line numbers, whereas `parse_count_output` returns `Err` on malformed records. In `read_at_revision`, empty paths, leading `'-'`, `".."` segments, and non-zero `git show` exits return `Ok(None)` (`EvidenceCheck::MissingFile`). [F47, F48, F49]

## External Contracts
- Agenda modules parsed by `parse_agenda_module` and `load_agenda` (`check_unique_ids`) must have `## ID: Title` headings, at least one `- ID: question` bullet per topic prefixed with `"{topic.id}-"`, uppercase ASCII/digit/`-`/`_` IDs, and globally unique topic and question IDs across modules. Synthesized and fallback notes must place preamble text before the first `## ` heading, format each rule as a single `- ` bullet with backticked identifiers and leading clause subject symbols, and cite `[F<n>, ...]` for `focus_symbol_note` and `strip_citations`. [F56, F57]
- `MaintainerNote::parse` requires `+++`-delimited TOML front matter with only `title`, `paths`, and `symbols` (`deny_unknown_fields`), non-empty `title` and `body`, and at least one entry in `paths` or `symbols`, while `applies` matches `symbols` only by exact match or a single trailing `*`. `render_block` wraps `SelectedNote`s from a `NotesSet` in `<code_notes>` and `<unit_note>` tags with the pinned-revision caveat; `render_maintainer_notes` replaces `"` with `'` in `MaintainerNote::title` for `<maintainer_note subsystem="...">` and frames `<maintainer_notes>` as policy rather than code facts. [F58, F91, F92]

## Known Pitfalls
- Parallel workflow stages in `build_unit`, `classify_history`, `synthesize_and_write_components`, `corpus::analyze`, and `agenda_derive::run_groups` zip batches with fixed `*_STAGE_NAMES` slices (`VERIFY_STAGE_NAMES`, `CORPUS_STAGE_NAMES` of length `VERIFY_BATCH_SIZE`, `CORPUS_BATCH_SIZE`), so callers must chunk batches by `*_STAGE_NAMES.len()` per round or `.zip(...)` silently drops excess batches. `map_themes` and `merge_themes` must resolve `ThemeDraft::members` via `items.get(m)` and `themes.get(m)` rather than `[m]`. [F73, F85]
- Avoid UTF-8 and bounds panics: `clause_subject_spans` (and `strip_paren_span`) must slice only at offsets from `find` or `strip_prefix` on the same string (checking `first_tick > 25` before `rest[..first_tick]`); `truncate_chars` must use `.chars().count()` and `.chars().take(max)`; `parse_grep_records` and `parse_count_output` must advance past newlines via `.get(end + 1..).unwrap_or_default()`; and `RevisionFiles::check` must clamp `start = evidence.start_line.max(1)` and `end = evidence.end_line.max(start)` and return `EvidenceCheck::BadRange` when `start > lines.len()` before slicing. [F86, F87, F88, F89]
