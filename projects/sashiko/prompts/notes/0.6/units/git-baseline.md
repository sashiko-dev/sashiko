# git-baseline

`git-baseline` provides sanitized git subprocess construction, repository and worktree lifecycle management, remote synchronization with backoff and commit-graph recovery, Linux kernel `MAINTAINERS` parsing/matching, baseline candidate resolution, and b4/Lore prerequisite patch series resolution.

## Architecture & Data Flow

- `BaselineRegistry::new` loads `MAINTAINERS` from `<mainline_remote>/master:MAINTAINERS` via `git show` before falling back to `<repo_path>/MAINTAINERS`, and `load_git_remotes` populates `remote_map` with both raw remote URLs and `.git`-stripped forms. [F2]
- For `T: git <url> [branch]`, `BaselineRegistry::parse_maintainers` and `MaintainersIndex::from_reader` take only `parts[1]` as the optional branch (ignoring trailing comments), and `BaselineResolution::as_str` formats `RemoteTarget` as `<name>/<branch>` or `<name>/HEAD`. [F3]
- `MaintainersIndex::from_reader` must set `MaintainerSection::catch_all` from raw `F:` text (`val == "*" || val == "*/"`) before `CompiledPattern::compile`, as `*` and `*/` do not compile to whole-tree matchers and cannot be distinguished afterward when `from_sections` populates `global_addresses`. [F111]
- `FileMatcher::match_file` must match `MaintainersIndex::match_file`'s exact section list and ordering (`depth()` descending, `section.name` ascending, `X:` overriding `F:`/`N:`). `FileMatcher` stores section indices `idx: usize` from `sections.iter().enumerate()` and byte offsets from 1-byte ASCII `'/'`/`'*'`/`'?'`, relying on `self.sections` staying immutable so `self.sections[idx]` and `&path[..end]` cannot panic. [F15, F114]
- In `refresh_remote`, `.sashiko/fetch_timestamps/<name>` is updated and `<name>.fail` removed only when `fetch_remote` succeeds (`fetch_ok`); on failure, `<name>.fail` is updated and `<name>` is untouched even on `Ok(FetchOutcome::StaleLocalRef(_))`. When `should_fetch && fetch_ok`, it sets `refs/remotes/<name>/HEAD` via `git remote set-head <name> --auto` (falling back to `master`, `main`, `for-next`, `for-linus`), and when `name == "origin"`, updates existing `refs/heads/master` and `refs/heads/main` to `refs/remotes/origin/<branch>`. [F11, F12]
- `ensure_gc_disabled` must attempt all four git configs (`gc.auto=0`, `maintenance.auto=false`, `gc.writeCommitGraph=false`, `fetch.writeCommitGraph=false`) without short-circuiting on failure, `repack_repository` must repack with `--geometric=2 -d --write-midx` without reachability pruning, and `pack_stats` must read `.pack` entries directly from `object_dir(repo_path, "pack")` via `tokio::fs::read_dir` instead of spawning `git count-objects -v`. [F87, F127]
- `PrerequisiteResolver` bounds recursion to `MAX_PREREQUISITE_DEPTH` (8), `series_cache` to `MAX_PREREQUISITE_SERIES` (128), and unique patches in `resolved` (`append_patch`) to `MAX_PREREQUISITE_PATCH_IDS` (128), recording finished series in `resolved_series` to skip shared DAG nodes. It keys `series_cache`, `resolved_series`, and `active_message_ids` via `clean_message_id` (`load_series`, `resolve_series`, `resolve_target`), while `PrerequisiteSeries::message_id` may keep `<...>`. [F98, F115]
- `series_from_storage`, `cache_required_patches`, `append_patch`, and `resolve_patch_ids` must validate and lowercase every 40-char hex `git_patch_id` via `normalize_patch_id` before indexing `patch_cache` or `seen_patch_ids`. `series_from_storage` also enforces `MAX_PREREQUISITE_PATCH_IDS` (128) and backfills `None` patch IDs via `calculate_git_patch_id_batch`, failing if any part yields no stable patch ID. [F116, F143]

## Synchronization

- Worktree metadata mutations (`git worktree add --detach --no-checkout` in `GitWorktree::new`, `git worktree remove` in `GitWorktree::remove`, and `git worktree prune` in `prune_worktrees`) must hold `get_worktree_lock()`, while file checkout (`git reset --hard`) in `GitWorktree::new` runs after releasing the lock. [F24]
- `get_remote_lock` holds the synchronous `LOCKS` `std::sync::Mutex` only to prune idle entries (`Arc::strong_count(lock) > 1` when `map.len() >= 64`) and clone `Arc<AsyncMutex<()>>`, releasing the guard before `.await`. `refresh_remote` must acquire `get_remote_lock(name)` before `get_global_config_lock()` and release `get_global_config_lock()` before `fetch_remote`, re-acquiring it afterward for `git remote set-head`. [F104, F130]
- `write_commit_graph` and `repack_repository` serialize on `get_object_store_lock()` (`OBJECT_STORE_LOCK`) without holding a remote lock. `drop_commit_graph` must never acquire `get_object_store_lock()` (called under `OBJECT_STORE_LOCK` in `write_commit_graph` and under a remote lock in `refresh_remote`), and `schedule_commit_graph_rebuild` spawns a detached task using `REBUILD_LOCK.try_lock()` to call `write_commit_graph` without blocking remote fetches. [F109, F128]
- `calculate_git_patch_id` and `calculate_git_patch_id_batch` must acquire `GIT_PATCH_ID_SEMAPHORE` (`MAX_CONCURRENT_GIT_PATCH_IDS = 8`) before running `git patch-id --stable` under `GIT_PATCH_ID_TIMEOUT` (30s), with `calculate_git_patch_id_batch` preserving input order including `None` slots. `run_git_patch_id_command` must run `stdin.write_all(input)` (then `drop(stdin)`) and `child.wait_with_output()` concurrently via `tokio::join!`, ignoring `ErrorKind::BrokenPipe` when `!output.status.success()`. [F107, F135]
- `parse_mbox_messages` must run synchronous `split_mbox` and `parse_email` inside `tokio::task::spawn_blocking` (enforcing `messages.len() <= MAX_MBOX_MESSAGES`) and propagate both `JoinError` and the inner `Result` via `.await.context(...)?`. [F108]

## Object Lifetimes

- Callers creating a managed `GitWorktree` via `GitWorktree::new` (`is_managed == true`) must await `worktree.remove().await` before drop (whereas `from_path` and `new_scratch_clone` set `is_managed: false`). `GitWorktree::remove` must keep `self.path` and `self.dir` intact on disk until `git worktree remove -f <self.path>` finishes, or git fails with "not a working tree" and leaks `.git/worktrees/` metadata. [F32, F124]
- During shared-repo startup recovery, `cleanup_worktree_dir` (`remove_dir_all` on `sashiko-worktree-*`) must run before `prune_worktrees` (`git worktree prune`) so orphaned `.git/worktrees/` entries are pruned. [F33]
- `init_global_maintainers` only populates `GLOBAL_MAINTAINERS` when `None` (`if guard.is_none()`); any test calling `init_global_maintainers`, `clear_global_maintainers`, `get_global_maintainers`, or `sections_for_diff` must hold `GLOBAL_INDEX_TEST_LOCK` for its entire body and call `clear_global_maintainers()` before init and on teardown. [F40]

## API Contracts

- In `src/lib.rs`, `baseline`, `git_cmd`, `git_ops`, and `maintainers` compile unconditionally for `--no-default-features` CLI builds, while `prerequisites` is gated behind `#[cfg(feature = "server")]`. [F144]
- `CommitId::parse` accepts only 40-byte lowercase ASCII hex strings (`0..=9`, `a..=f`), and `extract_base_commit` skips any `base-commit:` trailer failing `CommitId::parse` so invalid trailers neither reach `git` nor shadow later valid trailers. When resolving `&str` revisions in `get_commit_hash` and `BaselineRegistry::is_merged_default_head`, `git rev-parse` must pass `--verify`, `--end-of-options`, and `^{commit}`. [F64, F101]
- In `BaselineRegistry::resolve_candidates`, the mainline fallback is `BaselineResolution::RemoteTarget` with `branch: Some("master")` when `mainline_remote` is `Some` (and `LocalRef("HEAD")` only when `None`) so `ensure_remote` fetches mainline. `BaselineRegistry::is_merged_default_head` returns `true` only for `RemoteTarget` candidates with `branch: None` and `url != LINUX_NEXT_URL` whose `sha` is a strict ancestor of `<mainline>/master^{commit}`, using `offline_git` (`GIT_NO_LAZY_FETCH=1`, `OFFLINE_GIT_TIMEOUT` 30s) and returning `false` on error or tip equality. [F66, F67]
- For subjects with a `[stable]` prefix token, `explicit_stable_versions` inspects only the first token matching `stable_series_version` (`[vV]?<major>.<minor>[.yY]?`) or a two-endpoint `first-last` pair, emitting at most two `stable` remote branches (`linux-<version>.y`) in `subject_version_candidates` without expanding ranges. [F69]
- `fetch_remote` and `refresh_remote` must pass all logged/returned remote URLs and `git` stderr strings (`remote add`, `remote set-url`, `remote set-head`, `fetch`) through `redact_secret`. [F73]
- `maintainer_address` trims and ASCII-lowercases an email from `M:`/`R:` entries only when it has a non-empty local part, one `@`, no whitespace, and a domain containing `.` (not at start/end), returning `None` otherwise; `subsystems_for_address` and `is_global_maintainer` must also normalize `address` with `.trim().to_ascii_lowercase()`. [F78, F112]
- `sections_for_diff` returns an empty `Vec<String>` both when `get_global_maintainers()` is `None` and when no section matches, preventing directory-prefix fallbacks. Callers matching many paths against `MaintainersIndex` must reuse `MaintainersIndex::file_matcher` (`FileMatcher`) rather than calling `match_file`/`match_files` in a loop. [F80, F92]
- `parse_prerequisite_metadata` gives `prerequisite-patch-id:` precedence over series trailers (`parse_prerequisite_thread_hints` retains at most `MAX_LORE_OPERATIONS` hints), and errors in `parse_prerequisite_patch_ids` if `prerequisite-patch-id:` lines exist with no valid 40-hex ID rather than falling back to `prerequisite-message-id:`/`Based-on:`. `PrerequisiteResolver` charges every `fetch_series`, `fetch_thread_patches`, and `search_patch_id` call to one shared `MAX_LORE_OPERATIONS` (8) budget via `count_remote_operation`; `resolve_patch_ids` enforces `MAX_PREREQUISITE_PATCH_IDS` (128), `cache_required_patches` filters fetched patches against `wanted` (`HashSet<&str>`) before `patch_cache` insertion via `Entry::or_insert`, and `resolve_patch_ids` appends matches in declared `patch_ids` order. [F81, F82, F97, F99]
- `git_find_file_rename` caps forward rename tracing at 5 hops (`0..5`), passes `"--"` before `&current_file` to `git log`, and only returns a candidate from `git show -M` or `git log --follow` after `git_file_exists_at` confirms it exists at `target_commit`. `get_git_log` also appends `"--"` before non-empty `GitLogParams::paths`. [F119, F120]

## Error Handling

- `GitWorktree::apply_patch` invokes `git am` with `LC_ALL=C` and `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, running `git am --abort` on failure before returning `GitAmError`. `PatchApplyFailure::classify` returns `Unknown` if `stderr` has multiple distinct failure kinds, any unrecognized `error: `/`fatal: ` line, or if `Patch is empty.` is not the exact standalone `stdout`; `from_error` maps non-`GitAmError` errors to `Unknown`, and public baseline logs must use `PatchApplyFailure::from_error(&e).public_message()`. [F43, F75, F125]
- When a non-forced remote in `refresh_remote` has a `.fail` timestamp < 1h old, it returns `Ok(FetchOutcome::BackedOff)` if `refs/remotes/<name>/HEAD` exists and the success timestamp is < 24h old, or `Err(BackoffError)` otherwise; `ensure_remote` turns `FetchOutcome::BackedOff` into `Err`. [F45]
- When `fetch_remote` in `refresh_remote` or `run_commit_graph_write` in `write_commit_graph` fails matching `is_stale_commit_graph`, it calls `drop_commit_graph` and retries (with `refresh_remote` enforcing at least `GRAPH_RETRY_FLOOR` timeout and calling `schedule_commit_graph_rebuild`). `ensure_submodule_config_compat` treats exit code 5 from `git config --unset core.worktree` as `Ok(())`. [F48, F50]
- `parse_prerequisite_thread_hints` silently drops malformed `prerequisite-message-id:` values, whereas `parse_prerequisite_series_ids` and `parse_based_on_message_id` return `Err` on any invalid message ID (`parse_message_id`) or multiple distinct `Based-on:` IDs. `cache_hinted_patches` calls `count_remote_operation()` before `fetch_thread_patches` and downgrades errors to a `warn!` via `redact_secret` so fallback to `search_patch_id` can proceed. [F57, F58]
- `PrerequisiteResolver::resolve_series` removes `requested_id`, `actual_id`, and `series.local_patchset_id` from `active_message_ids` and `active_patchset_ids` after awaiting inner dependency resolution regardless of `Ok`/`Err`, inserting `actual_id` into `resolved_series` only on `Ok`. `select_series_head` and `select_series_patches` return `Err` if the message ID is not the unique series head (`0/N` cover or `1/N` where `!has_matching_cover_ancestor`) or if any part `1..=head.total` is missing, duplicated, or mismatched. [F60, F61]

## External Contracts

- Every git subprocess must be built via `git_cmd::in_dir`, `git_cmd::in_dir_async`, or `git_cmd::detached_async` (never `Command::new("git")`) so `INHERITED_LOCATION_VARS` are stripped and async commands set `kill_on_drop(true)`. [F122]
- `refresh_remote` and `ensure_remote` accept `MAINTAINERS` URLs without a domain allowlist, relying on `GIT_PROTOCOL_RESTRICTIONS` (`protocol.allow=never` with only `http`, `https`, `git`, `ssh`, `file` set to `always`) on `fetch_remote` and `git remote set-head`. `is_dirty` passes `--porcelain --untracked-files=no` to `git status`, while `git_status` passes `--untracked-files=normal`. [F71, F77]

## Known Pitfalls

- In `BaselineRegistry::resolve_subsystem_heuristic`, `tree_subsystems` maps each `(url, branch)` tree to its `MaintainersEntry::subsystem`, and `MEMORY MANAGEMENT` (`mm-new`/`mm-unstable`/`mm-stable`) and `STAGING SUBSYSTEM` (`staging-testing`/`staging-next`) branch overrides check only `candidates[0].0` (highest-file-count tree) in `tree_subsystems`, not whether any matched file touched MM or Staging. [F5]
