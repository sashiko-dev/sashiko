# workflows

Defines the declarative multi-stage LLM workflows and validation pipelines for patch review, standalone bug triage, and automated code-notes generation across Linux and Sashiko projects. It manages review and build states (`LinuxPatchReviewState`, `NotesBuildState`, `AgendaState`, `CorpusState`), prompt construction, stage output validators, finding lineage enrichment, path/stage-name sanitization (`guard`), `#[cfg(feature = "server")]` `linux_bug` sessions, and the `review_map` builder.

## Architecture & Data Flow

- `build_linux_patch_review_workflow_with_effort` and `build_sashiko_patch_review_workflow_with_effort` must forward configured `temperature` and `effort` to every stage builder (including `prescreen_stage_with_effort` and `planning_stage_with_effort`, never falling back to `StagePolicy::default()`), and `report_stage_with_effort` must map effort via `EffortMode::report_stage_effort` (`Medium` unless `EffortMode::Low`) with `RecitationPolicy::FallbackToFreeForm` rather than `lightweight_stage_effort`. [F1, F97]
- `build_sashiko_patch_review_workflow_with_effort` must use `skip_if` on `verification_stage_with_effort` and `report_stage_with_effort` rather than workflow-level `early_exit_if` when concerns or findings are empty, so `summary_stage_with_effort` still runs and populates `SashikoPatchReviewState::summary` when `skip_report` is false. [F2]
- `apply_planning_stage_output` must always seed `planned_stages` with all non-optional `AnalysisStage` entries (`!d.optional`), admit `PlanningOutput::relevant_stages` and `stage_efforts` only as canonical `AnalysisStage::name` values resolved via `stage_lookup` (`normalize_stage_name`) so `resolve_stage_effort` matches them, and clamp `ReasoningEffort::Low` to `Medium` in `planned_efforts` when `dynamic_effort` is true. [F7, F78]
- Every review stage constructed by `linux_patch_review` and `sashiko_patch_review` must register a name recognized by `is_known_stage` (and labeled by `stage_short_label` for all stages except `"pre-screen"` and `"planning"`) so `is_counted_stage` tracks progress. Broken by: omitting a new stage name from `ANALYSIS_STAGES`, `CONSOLIDATION_STAGES`, or `POST_VERIFICATION_STAGE_NAMES`. [F50]
- `batch_hard_cases_by_severity` must sort `hard_cases` by descending `estimated_severity` and cap output at `MAX_POST_VERIFICATION_STAGES` (10) batches by grouping excess lower-severity items into tail batches, because callers index `POST_VERIFICATION_STAGE_NAMES` directly by batch index. [F64]
- Because review items in `LinuxPatchReviewState` are untyped `serde_json::Value` maps, stage reducers must stamp prefix-coded IDs (`C*`, `D*`, `VF*`/`H*`/`VD*`, `PVF*`/`PVD*`) classified by `review_map::split_raw_ids` and `build_threads`, and `enrich_item_provenance` must propagate matched items' `"source_ids"` into `"raw_source_ids"` alongside `"source_ids"` so `collect_raw_ids_from_pv_item` and `state.hard_cases` can link `PVF*`/`PVD*` back to `C*`/`D*`. [F5, F79]
- `record_verified_findings` must always record `"preexisting": true` items into `LinuxPatchReviewState::concerns`—remapping `"problem"` to `"description"` (and `"type"`) and `"severity_explanation"` to `"reasoning"` while copying all 9 lineage/provenance keys—and only append them to `state.findings` when `state.report_preexisting` is true, whereas `"preexisting": false` items go only to `state.findings`. [F3, F80]
- `STAGE_JSON_SCHEMA_EXAMPLE`, `CONCERN_JSON_SCHEMA_EXAMPLE`, `STAGE_VERIFICATION_INSTRUCTION`, and `STAGE_POST_VERIFICATION_INSTRUCTION` must instruct the model to keep bugs already triggerable at `Baseline SHA` as `"preexisting": true` and never dismiss them into `dismissed_concerns`. [F86]
- In `linux_system_prompt` and `sashiko_system_prompt`, untrusted commit diffs, prefetched code, notes, and `custom_prompt` must be bound via `PromptTemplate::with_var` (wrapping `custom_prompt` in `<custom_instructions>` at the end only when non-whitespace); `linux_system_prompt` must place `{ {maintainer_notes}}` immediately after `</global_review_guidelines>` and before `{ {code_notes}}` and state that `<code_notes>` are not a source of truth; and every stage embedding `series_context_placeholder(wants)` (`SERIES_CONTEXT_PLACEHOLDER`) must pair it with `with_series_context(template, wants)`. [F9, F82, F83]
- `resolve_official_subsystems_for_project` must only construct `AttributedSubsystem::from_maintainers` when `MaintainersIndex::match_files` matches `verified_files`, using `AttributedSubsystem::from_path_prefix` for directory fallbacks and preserving caller provenance when `tools` is `None`. Broken by: wrapping `input_subsystems` or directory prefixes in `from_maintainers`. [F12]
- `prescreen_stage_with_effort` in `sashiko_patch_review.rs` must normalize LLM-selected guides with `normalize_guide_name`, exclude stage-exclusive guides via `!is_stage_exclusive_guide`, and filter with `sanitize_guide_name` (rejecting empty names, `'/'`, `'\\'`, and `".."`) before storing `state.selected_guides`. [F87]
- In `code_notes.rs`, `renumber_facts` must overwrite stage-local `Fact::id`s with sequential unit-wide IDs (`F1`, `F2`, ...) before `dedup_stage`/`verify_stage`; `keep_representatives` indexes `group[0]` directly (relying on `validate_groups` rejecting empty groups in `DedupOutput::groups` and `group_of` being populated only from group elements) while merging `from_history` across the whole group; and `synthesize_stage` / `synthesize_component_stage` must prompt with softer `target_bytes(max_bytes)` (85%) and `MAX_BULLET_CHARS` (600) while `validate_note` enforces `max_bytes` and `HARD_MAX_BULLET_CHARS` (1,000). [F14, F72, F74]
- `process_issue_for_project` must never call `db.link_review_to_bug` while a bug is `Pending`; linking happens only in `DedupAttemptContext::check_and_fold` (with `is_newly_discovered = false`) when `db.mark_bug_as_duplicate(..., preserve_triage: true)` returns `Ok(true)` (if it returns `Ok(false)` because the bug left `BugLifecycleStatus::New`, `check_and_fold` must return `Ok(None)` without linking or returning `BugOutcome::Duplicate`), or after `process_issue_worker_for_project` commits `BugLifecycleStatus::Open` (`true`). [F28, F44]
- In `linux_bug.rs`, `extract_bug_files` must filter every path from `bug.source_files()` and `bug.locations()` through `sanitize_bug_file_path` (rejecting empty strings, leading `'-'`, `'/'`, `'\\'`, or `".."`); and `prefetch_bug_locations` must reject `locations[].file` paths starting with `'/'` or `'\\'`, containing `".."`, or not ending in `.c`/`.h`/`.rs`, while capping output at `MAX_BUG_PREFETCH_FILES` (3), `MAX_BUG_PREFETCH_SNIPPETS_TOTAL` (5), `MAX_BUG_SNIPPET_LINES` (100), and `MAX_BUG_PREFETCH_CHARS` (20,000). [F93, F94]
- Both `CommitRangeIndex::find_candidates` and `find_candidate_fix_commits` must return `None` when `files` is empty and cap collection at 100 file-touching commits plus 100 commits matching the 7-to-12-char `introducing_sha` prefix; `prefetch_candidate_fix_commits` must inspect at most `MAX_FIX_CANDIDATE_COMMITS` (10) commits, fetching full diffs up to `MAX_FULL_COMMIT_PREFETCH_BYTES` (12,000) before falling back to file-filtered hunks and capping total output at `MAX_FIX_CHECK_PREFETCH_BYTES` (24,000). [F66, F68]
- When truncating git output or bug descriptions in `linux_bug.rs`, cuts must align to UTF-8 boundaries via `is_char_boundary` (`prefetch_candidate_fix_commits`) or `crate::utils::utf8_prefix` (`format_known_bug_description`, which collapses whitespace and caps candidate descriptions at `MAX_DEDUP_DESCRIPTION_BYTES` = 800 bytes before appending `"...[truncated]..."`). [F71, F75]

## Synchronization

- `BUG_DEDUP_LOCK` in `linux_bug.rs` must remain a `tokio::sync::Mutex` (never `std::sync::Mutex`) and in `process_issue_worker_for_project` must be scoped strictly to Stage 3 (snapshotting `seen_bug_ids` from `list_all_bugs_for_vector_search` and awaiting `check_and_fold`) and the final write block after Stages 4–6 (re-running `check_and_fold` on newly arrived bugs not in `seen_bug_ids` before `update_bug_outcome` sets `BugLifecycleStatus::Open` and publishes `vector_json`), never held across `NormalizeSession`, `VerifySession`, `TracingSession`, `SeveritySession`, or `ReportSession`. [F16, F17, F76]
- In `linux_bug.rs`, async helpers running synchronous `crate::git_cmd::in_dir` subprocesses or Tree-sitter `extract_enclosing_block` (`get_master_sha`, `format_commit`, `prefetch_bug_locations`) must offload work via `tokio::task::spawn_blocking`, while direct async git queries use `crate::git_cmd::in_dir_async`. [F21]
- In `VerifyUpstreamFixSession::call_tools`, batched tool calls must be deduplicated against both `self.last_turn_tool_calls` and earlier entries in `current_turn_calls` before running via `futures::future::join_all`, updating `self.last_turn_tool_calls` only when `current_turn_calls` is non-empty. [F22]
- In `linux_patch_review.rs` and `sashiko_patch_review.rs`, parallel `analysis_stage` and `post_verification_stage_with_effort` stages (`apply_post_verification_stage_output`) must assign sequential lineage IDs (`C*`, `D*`, `PVF*`, `PVD*`) and append to shared state strictly inside `.reduce_with_outcome(...)` closures; in `notes_agenda.rs`, `group_stage` must tag each `ThemesOutput` with its `batch` index when pushing to `AgendaState::grouped` because `agenda_workflow` uses `ParallelPolicy::BestEffort` where failed stages are omitted. [F23, F24]

## Object Lifetimes

- `run_git_query_capped` must set `kill_on_drop(true)` and `stdin(Stdio::null())` on the `git` `Command` before awaiting `capped_output_with_limit` inside `tokio::time::timeout(UPSTREAM_GIT_TIMEOUT, ...)`, ensuring child termination on timeout or cancellation. [F30]
- `LinuxPatchReviewState::resolve_locations` must be invoked while `worktree_path` still exists on disk and before `build_review_map` snapshots location arrays, and it must ground locations across all 10 `Vec<Value>` item collections on `LinuxPatchReviewState` because stage reducers clone `Value` items into separate per-stage and aggregate vectors. [F31, F81]

## API Contracts

- `src/workflows/mod.rs` gates `pub mod linux_bug` behind `#[cfg(feature = "server")]` while compiling `code_notes`, `guard`, `linux_patch_review`, `notes_agenda`, `notes_corpus`, `review_map`, and `sashiko_patch_review` unconditionally. Broken by: referencing `linux_bug` from an ungated module in `src/workflows/`. [F107]
- `planned_stages_from` must return an empty `Vec` and omit `CONSOLIDATION_STAGES` whenever `stage_names` has no stage recognized by `analysis_stage_by_name`, allowing `WorkflowEvent::ParallelResolved` callers to distinguish post-verification fan-out from initial analysis fan-out and call `refine_planned_stages_with_post_verification`. [F49]
- Prompt paths recorded by `push_unique_prompt` or `build_prompts_manifest` must pass `sanitize_prompt_relpath`, which strips bundle prefixes via `normalize_prompt_relpath` and admits only `.md` paths matching `"<file>.md"`, `"subsystem/<file>.md"`, or `"patterns/<file>.md"` without `/`, `\`, or `..`. [F54]

## Error Handling

- `validate_concerns_output`, `validate_verification_stage_output`, and `validate_post_verification_batch_output` require every `dismissed_concerns` item to satisfy `has_valid_proof_location` (at least one location with non-empty `file`, `function_or_symbol`, `code_snippet`, and `side` in `"PARENT"` or `"REVISION"`, checked via `validate_locations_side`). [F90]
- When `state.all_concerns` or `state.all_dismissed_concerns` is non-empty, `validate_verification_stage_output` requires every output item to have non-empty `source_ids` covering every input `C*` and `D*` ID at least once, with `findings` citing only `C*` IDs and `dismissed_concerns` citing only `D*` IDs; `validate_post_verification_batch_items` rejects outputs when both `findings` and `dismissed_concerns` are empty or any batch `H*` ID is missing from `source_ids`, while allowing multiple `H*` IDs to merge into one item. [F34, F55]
- Because parallel analysis and post-verification stages run under `ParallelPolicy::BestEffort` (or can be skipped via `--stages`), `review_map::build_threads` must emit fallback threads with outcome `"unresolved_hard_case"`, `"unverified_concern"`, or `"unverified_dismissed"` for any `H*`, `C*`, or `D*` IDs not resolved downstream. [F38]
- When `LinuxPatchReviewState::prefetch_failed` is `true`, `linux_system_prompt` and `sashiko_system_prompt` must inject a fallback warning into `{ {prefetched_block}}` instructing stages to use `git_read_files` and `git_grep` at `target_commit_sha` rather than emitting an empty block or reading the checkout. [F36]
- In `linux_bug.rs`, `TracingSession::validate` must reject any non-`null` `introducing_commit_sha` failing `git cat-file -e <sha>^{commit}` with `ValidationError::FormatViolation` (and `process_issue_worker_for_project` must fall back to `deterministic_blame_fallback` when it outputs `None`); when `VerifyUpstreamFixSession` reports `status == "fixed"`, `check_bug_fixed_upstream_with_candidates` must verify `fixing_commit_sha` via `verify_commit_is_ancestor(repo_path, raw_fix_sha, linus_sha)` and, if `None`, downgrade to `UpstreamFixCheckOutcome::Uncertain` and call `touch_bug_fix_check_timestamp`. [F40, F43, F95]
- `build_commit_range_index` and `parse_commit_range_index_output` must return `CommitRangeLookup::TooLarge` (never `Err` or a partial index) if `git log` fails, `out.stdout_capped` is true, commit count hits `MAX_INDEXED_RANGE_COMMITS`, or a record is malformed, so callers fall back to `find_candidate_fix_commits`. [F45]
- `code_notes::validate_survey`, `validate_lessons`, `validate_groups`, `validate_verdicts`, `notes_agenda::validate_themes`, and `notes_corpus::validate_analyses` must require an exact partition of expected input IDs or `0..count` indices (rejecting missing, duplicate, or unknown entries); in `notes_agenda.rs`, `validate_draft` must also reject any `TopicDraft` using `RESERVED_TOPIC_IDS` (`"HIST"`) or a question matching `IDENTIFIER`. [F15, F47]
- In `code_notes::explore_stage`, `ground_symbols` strips ungrounded `fact.scope.symbols` during `reduce` rather than failing `validate_explore`, whereas `validate_explore` and `validate_note` must aggregate all fact violations or all bullets exceeding `HARD_MAX_BULLET_CHARS` into a single `Err` so one retry can fix them all. [F46]

## External Contracts

- `build_review_map` emits the `"version": 1` JSON schema for `reviews.result_json`, adding `history_offset` to each stage's `log_start`/`log_end` and sorting `threads` by `outcome_rank` descending then `severity_rank` descending before assigning sequential `"thread_id": "T1".."Tn"`. [F58]
- Every `BugStage` session in `linux_bug.rs` must start its `initial_user_prompt` with `stage.heading()` (`"# <title>"` with no numeric index), and `process_issue_worker_for_project` and `DedupAttemptContext::check_and_fold` must persist each completed stage immediately via `record_bug_stage` under enrichment kind `stage.enrichment_kind()` (`"<id>_run"`) before starting the next stage. [F27, F59]
- Synthesized code notes in `code_notes.rs` must pass `validate_note` (starting with `"# {unit}"`, containing no triple-backtick fences after `strip_code_fence`, within `max_bytes` and `HARD_MAX_BULLET_CHARS`, and citing each known `[F*]` ID at most once) and have `"{ {"` and `"@ include"` replaced with `"{ {"` and `"@ include"` via `neutralize_directives`. [F63, F85]
