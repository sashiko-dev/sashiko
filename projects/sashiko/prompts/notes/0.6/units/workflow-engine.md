# workflow-engine

Provides a generic, composable, and declarative AI workflow framework (`src/workflow/*`) that orchestrates multi-stage LLM execution over typed application state `S`. It defines workflow graphs (`Workflow`, `WorkflowStep`) supporting sequential stages, static and dynamic parallel fan-out, conditional branching, and early exits, alongside prompt templating (`PromptTemplate`), output validation (`OutputFormat`), and `LlmSession` stage execution (`Stage`, `WorkflowEngine`).

## Architecture & Data Flow

- Each `StageRunRecord` in `WorkflowOutcome::stage_runs` indexes `WorkflowOutcome::history[history_start..history_end]`, so `merge_workflow_outcome` must capture `base_history_len = outcome.history.len()` before extending `outcome.history` and add `base_history_len` to every merged record's `history_start` and `history_end`. [F1]
- `Stage::execute_isolated` and `stage_outcome_from_error` must convert `usize` token usage via `u32::try_from(...).unwrap_or(u32::MAX)`, and `record_stage_outcome`, `merge_workflow_outcome`, and `WorkflowEngine::execute` must accumulate token counts and history offsets with `saturating_add`. [F53]
- When a stage's `skip_if` predicate returns `true`, `Stage::execute_isolated` returns a `StageOutcome` with `skipped: true` and an empty `history`, and `record_stage_outcome` must still push a `StageRunRecord` with `skipped: true`, `turns: 0`, and `history_start == history_end`. Broken by: short-circuiting before `record_stage_outcome` when `stage_outcome.skipped()` is `true`. [F2]
- `PromptTemplate` matches `@ include("...")` and `@ includes` directives via `place` only against `Segment::Template` segments (splicing in `Segment::Included` segments) before `assemble` runs `substitute_vars` on remaining `Segment::Template` segments only, so neither included files nor variable values are ever scanned for directives. Broken by: substituting `{ {key}}` variables before `place`, or scanning `Segment::Included` or `trailing` blocks. [F11]
- `PromptTemplate::substitute_vars` must replace bound `{ {key}}` placeholders in a single left-to-right pass over `text` without rescanning substituted values, leaving unbound `{ {...}}` placeholders intact and advancing by one `{` when a `{ {` does not match a bound variable. Broken by: sequential `String::replace` calls per variable. [F13]
- `StageOutcome::read_prompts` must pair each assistant `read_prompt` call with the first unused matching `AiRole::Tool` message in the following contiguous tool block (relying on `StageSession::call_tools` returning results in input `calls` order) and record its normalized `"name"` only when the response JSON lacks `"error"`. [F10]
- When `recitation_fallback_active` is set under `RecitationPolicy::FallbackToFreeForm`, `StageSession::response_format` returns `None` and `OutputFormat::validate_with_recitation_fallback` skips `TextValidator` for `OutputFormat::Text` (requiring only non-empty text) while keeping `JsonValidator` for `OutputFormat::Json`. [F67]

## Synchronization

- Under `ParallelPolicy::FailFast`, `execute_parallel_batch` runs all sibling stages via `ExecutableStage::execute_isolated` against an immutable `&S` snapshot; each future must lock its `completed_outcomes[idx]` `std::sync::Mutex` only after `execute_isolated(...).await` finishes, and after `try_join_all` completes the slots are consumed sequentially via `into_inner()`—applying `StateMutation<S>` closures only if `try_join_all` succeeds while still recording `completed_outcomes` into `WorkflowOutcome` on failure. [F4, F15]
- Under `ParallelPolicy::BestEffort`, `execute_parallel_batch` awaits all sibling futures via `futures::future::join_all` before iterating in `stages` slice order to sequentially apply `mutation(state)` for succeeding stages and `record_stage_outcome` for both succeeding and failed stages; it returns `Ok(())` if `stages` is empty or `successes > 0`, and returns `Err` (wrapping the first failure) only when all stages in a non-empty batch fail. [F16, F31]
- `StageSession::call_tool` and `StageSession::call_tools` track the most recent `(function_name, arguments)` across turns in `StageSession::last_tool_call` and reject only consecutive identical calls with a synthetic `"Duplicate tool call blocked..."` JSON error (allowing non-consecutive repeats); `call_tools` must check duplicates and update `self.last_tool_call` synchronously in input order before running non-duplicate `tools.call` futures concurrently via `futures::future::join_all` and writing each result back to `results[idx]`. [F48, F59]

## Object Lifetimes

- In `ExecutableStage::execute_isolated`, a stage holds only an immutable reference `&S` while rendering prompts, running `SessionRunner`, and validating output, deferring all state writes to the returned `StateMutation<S>` closure so concurrent stages in `execute_parallel_batch` cannot observe each other's mutations. Broken by: mutating state via interior mutability inside a prompt extractor, validator, or `execute_isolated`. [F19]
- `StageSession` is instantiated per `Stage::execute_isolated` invocation and dropped as soon as `SessionRunner::run` finishes, scoping `last_tool_call` duplicate blocking and `recitation_fallback_active` across turns of that single stage execution without leaking across stages. Broken by: moving either field onto `Stage`, `ToolBox`, or `WorkflowEnv`. [F23]

## API Contracts

- `StageBuilder::build` requires both `user_prompt` and `output_format` to be set before building and panics via `Option::expect` if either is omitted, whereas `system_prompt`, `reducer`, and `skip_if` are optional. [F33]
- `StageBuilder::reduce` clears `self.outcome_reducer` to `None`, whereas `StageBuilder::reduce_with_outcome` sets both `outcome_reducer` and a fallback `reducer` that passes `StageOutcome::default()` when `(stage.reducer)` is called directly instead of `ExecutableStage::execute_isolated`. Broken by: chaining `.reduce(...)` after `.reduce_with_outcome(...)`, or calling `(stage.reducer)(state, output)` directly when real `StageOutcome` telemetry is needed. [F34]
- `Stage::execute_isolated` must forward both `self.policy.max_turns` and `self.policy.max_validation_attempts` to `SessionRunner` via `with_max_turns` and `with_max_validation_attempts` before calling `SessionRunner::run`. [F49]
- `OutputFormat::json()` sets `schema: None` so `StageSession::response_format` sends no JSON schema to the `AiProvider`; stages requiring provider-enforced structured JSON output must use `OutputFormat::json_with_schema`. [F38]
- `OutputFormat::Text` must only be constructed when the stage output type parameter `T` is `String`, because `OutputFormat::validate_with_recitation_fallback` converts the validated text to `T` by boxing `raw_text.to_string()` as `Box<dyn std::any::Any>` and downcasting to `T`. [F54]
- In `WorkflowStep::DynamicParallel`, `WorkflowEngine::execute_steps` must always invoke `resolver(state)` and emit `WorkflowEvent::ParallelResolved` after `planner.execute` succeeds, even when the `planner` stage was skipped via `skip_if` or `resolver(state)` returns an empty stage list. [F47]

## Error Handling

- When `WorkflowEngine::execute` fails, it must attach `WorkflowFailure` via `err.context(WorkflowFailure { message, outcome })` containing the partial `WorkflowOutcome` (including `stage_outcome_from_error` for the failing stage); when a nested `WorkflowEngine::execute` call in `WorkflowStep::Branch` returns `Err(err)`, the branch handler must downcast `err` to `WorkflowFailure` and call `merge_workflow_outcome` before returning `Err(err)` because the outer `WorkflowEngine::execute` attaches a new `WorkflowFailure` context that shadows the inner one on `downcast_ref`. [F22, F45]
- `StageSession::call_tool` and `StageSession::call_tools` must catch `ToolBox::call` errors and consecutive duplicate tool calls and return them as `Ok(json!({ "error": ... }))` tool responses rather than `Err`, because returning `Err` from `LlmSession::call_tools` aborts the entire stage and workflow. [F41]
- `PromptTemplate::render_for_model` treats missing static or dynamic inclusion paths (`!full_path.exists()` or `!dir_path.exists()`) as empty strings rather than errors and still consumes any matching `@ include(...)` directive via `place`, while propagating filesystem read errors on existing paths via `?`. [F32]

## Known Pitfalls

- Because `merge_workflow_outcome` merges only token counters, `history`, and `stage_runs`, a `WorkflowStep::Branch` in `WorkflowEngine::execute_steps` must explicitly copy `branch_outcome.early_exit` and `branch_outcome.early_exit_reason` onto the parent `WorkflowOutcome` and `break` when `early_exit` is `true`. [F5]
- `OutputFormat::with_validator` and `OutputFormat::with_feedback_formatter` only modify `OutputFormat::Json` and silently no-op on `OutputFormat::Text` (even though `String: DeserializeOwned` allows chaining on `OutputFormat::text()`), so custom plaintext validation and feedback must be configured through `OutputFormat::text_with_validator`. [F55]
- `StageSession::tools` filters tool declarations exposed to the model using `StagePolicy::tools` (`ToolScope::None`, `ToolScope::All`, `ToolScope::Selected`), but `StageSession::call_tool` and `StageSession::call_tools` dispatch directly to `self.tools.call` without checking `StagePolicy::tools`. [F69]
- When `parse_json_from_text` fails to parse model output as JSON, it must truncate `raw_text` using `crate::utils::utf8_prefix(raw_text, 200)` in the returned error string rather than embedding the full raw response into validation retry feedback. [F52]
