# ingestion-forge

This unit handles patch and email ingestion from NNTP servers, public-inbox git archives, lore.kernel.org mbox endpoints, and remote git repositories, as well as GitHub and GitLab forge webhook validation, payload parsing, and PR review comment delivery. It also parses RFC 5322 email messages into patchset metadata and diffs, and performs one-shot startup backfills to attribute historical patchsets to MAINTAINERS sections.

## Architecture & Data Flow

- `backfill_patchset_maintainer_sections` must return `Ok(())` without setting `SECTIONS_BACKFILLED_KEY` (`"patchset_maintainer_sections_backfilled"`) whenever `get_global_maintainers()` is `None` or `is_empty()`, and must set the key only after the paging loop over `patchsets_missing_maintainer_sections` finishes. Inside the loop, `after_id` must advance (`after_id = after_id.max(id)`) on every inspected patchset before `sections_for_patchset` or `replace_patchset_maintainer_sections` is called, avoiding an infinite paging loop on unreadable or unattributable patchsets. [F7, F8]
- `FetchAgent::is_present` must suffix single revisions with `^{commit}` (`rev-parse --verify <rev>^{commit}`) and range endpoints with `^{commit}..^{commit}` (`rev-list -n 1 <start>^{commit}..<end>^{commit}`) so that existing tree or blob SHAs are not treated as present commits, which would skip fetching the commit. [F9]
- `FetchRequest::commit_hash` carries either a single commit ref or a `"base..head"` range string; `FetchAgent::process_queue` must look up `self.mr_metadata` and format `article_id` (`mr-{number}-{commit_or_range}`) using the original `commit_or_range` string rather than a resolved `full_sha` or per-commit `sha` so it matches the placeholder patchset ID. [F98]
- In `parse_email`, `Patch` is returned as `Some(Patch)` only when `has_diff && index != 0`; cover letters (`index == 0`) always yield `patch = None` even if their body contains a unified diff, and replies (`is_reply == true`) always set `metadata.is_patch_or_cover = false`. [F17]
- `parse_email` must pass display names (`From`, `X-Original-From`, `To`, `Cc`), `Message-ID`, `Subject`, `In-Reply-To`, and `References` through `clean_display_name` to strip control characters (`c.is_control()`) before storing them in `PatchsetMetadata`, preventing RFC 2047 encoded CR/LF characters in stored headers. [F15]
- When matching `M/N` inside square brackets, `parse_subject_index` must require a preceding `PATCH`, `RFC`, `RESEND`, or `v\d+` token inside the brackets (or match `PATCH|RFC|RESEND M/N` or a leading `M/N` after `clean_subject`), so hardware model numbers or bot tags like `[508/512]` are not parsed as series indices. [F18]
- In `is_mbox_separator`, trailing `\r` and `\n` bytes must be stripped before computing `len` and checking `len < 30` (and `len >= 31` for 2-digit day offsets), because subsequent suffix indexing (`line[len - 24]`, `line[len - 25]`) relies on the stripped length to avoid out-of-bounds panics on short `"From "` lines. [F93]
- In `Ingestor`, `Event::ArticleFetched` carries the message body in `content: Vec<String>` with `raw: None` and `receipt: Some(...)` when emitted by `process_nntp_cycle`, but in `raw: Some(content)` with an empty `content: Vec::new()` and `receipt: None` when emitted by `ingest_git_objects`. Broken by: assuming `content` is always non-empty or `receipt` is always `Some`. [F103]
- `Ingestor::run_git_bootstrap` splits `limit` across tracked groups with `limit.div_ceil(groups.len())` and decrements `group_remaining` across newest-first epochs, passing `group_remaining` as `--depth` to `bootstrap_clone_command`/`bootstrap_fetch_command` and `--max-count` to `git rev-list` in `ingest_git_objects`. [F84]
- `Ingestor::process_nntp_cycle` bounds initial catch-up (`current == 0`) and ahead-of-tip watermark resets (`current > info.high` when `info.high > 0`) to `info.high.saturating_sub(overlap)` (100 after git bootstrap or tip reset, 4000 otherwise), and skips clamping when `info.high == 0`. [F85]
- `GitHubForge::review_intent` returns `ReviewIntent::Review` only for `"opened"`, `"reopened"`, `"synchronize"`, and `"ready_for_review"`, returning `ReviewIntent::Skip` for all other `pull_request` actions so non-commit webhook deliveries do not trigger redundant reviews. [F121]

## Synchronization

- `native_tls_config` in `src/nntp.rs` must load system certificates inside `tokio::task::spawn_blocking(rustls_native_certs::load_native_certs)` and initialize its static `OnceLock<Arc<ClientConfig>>` only after verifying `added > 0`, so blocking directory I/O runs off the async executor and transient trust-store failures or empty `RootCertStore`s are not cached. [F24]
- `Ingestor::find_epoch_urls` and `LoreMboxClient::fetch` must run `decode_manifest` and `decompress_mbox` inside `tokio::task::spawn_blocking`, because synchronous `flate2::read::GzDecoder` decompression of up to 256 MiB (`MAX_MANIFEST_DECOMPRESSED`) or 50 MiB (`MAX_MBOX_DECOMPRESSED`) would block Tokio worker threads. [F96]
- Unit tests that call `init_global_maintainers`, `clear_global_maintainers`, or `backfill_patchset_maintainer_sections` must hold `GLOBAL_INDEX_TEST_LOCK` across the entire test body so parallel tests do not race on the process-wide `MaintainersIndex`. [F27]

## Object Lifetimes

- Every `NntpClient` socket operation (`connect_with_tls_config`, `read_line_with_timeout`, `send_command`, and `quit` TLS shutdown) must run under `tokio::time::timeout` (`DEFAULT_TIMEOUT` = 15s), with `read_line_with_timeout` and `send_command` taking `self.stream` and restoring it only on `Ok(Ok(_))`. In `NntpClient::quit`, `self.stream` must be taken after exchanging `"QUIT"` and `stream.get_mut().shutdown()` awaited under `self.timeout` before dropping, so a TLS `close_notify` is sent without stalling indefinitely. [F31, F87]
- Git subprocesses spawned by `Ingestor` (`bootstrap_clone_command`, `bootstrap_fetch_command`, and the piped `git rev-list` and `git cat-file --batch` children in `Ingestor::ingest_git_objects`) must be built via `git_cmd` with `kill_on_drop(true)` so task cancellation or early error return terminates both child processes. [F34]
- Both `Ingestor::run_git_bootstrap` (once `bootstrap_repo` succeeds for a group) and `Ingestor::process_nntp_cycle` (after `client.group` succeeds) must call `self.db.ensure_mailing_list` before ingesting messages (`ingest_git_objects`) or reading/updating `last_article_num` so the mailing list row exists before messages or watermarks reference it. [F35]

## API Contracts

- `FetchAgent::extract_patch` initializes `Event::PatchSubmitted::message_id` to `String::new()`, so every caller in `FetchAgent::process_queue` must overwrite `message_id` with the resolved commit SHA (`sha` or `full_sha`) before sending the event on `self.main_tx`. [F99]
- `parse_email` serializes `PatchsetMetadata::to` and `PatchsetMetadata::cc` as comma-joined strings using `format_mailbox` (which escapes `\` and `"` inside double-quoted display names), and consumers must unpack them (and persisted `messages.to`/`cc` columns) with `split_address_list` rather than `.split(',')`. [F14]
- `format_mr_subject` and `extract_mr_version_from_subject` in `src/forge.rs` must use matching prefix and revision syntax (`#` or `!` followed by `number`, optional ` [vN]` for `version >= 2`, and `: `), and `format_mr_subject` must strip any existing `#N`/`!N` prefix via `strip_existing_mr_prefix` so re-formatting is idempotent and prior MR versions are detected in `db.rs` and `reviewer.rs`. [F12]
- In `GitHubForge::validate_event` and `GitLabForge::validate_event`, missing or unsupported event headers must return `Err(StatusCode::BAD_REQUEST)` before checking signatures, while missing or invalid signature/token headers when `secret` is `Some` must return `Err(StatusCode::UNAUTHORIZED)`, including for GitHub `"ping"` (`ForgeEvent::Handshake`). [F55]
- `GitLabForge::parse_payload` returns `payload["object_kind"]` (`"merge_request"`) rather than `payload["object_attributes"]["action"]` as its `action` string, so `GitLabForge::review_intent` cannot filter on merge-request action names (like `"open"` or `"update"`) unless `GitLabForge::parse_payload` is updated to extract the action and `oldrev` fields. [F100]
- `is_safe_repo_url` requires `is_valid_repo_url` (`https://`, `http://`, or `git@`), extracts only the host (taking the segment after the last `@` before `:` for `git@` URLs), and checks the blocklist against that host only (including decimal, hex `0x7f`/`0xa9fe`, and octal `0177` forms). `ForgeProvider::parse_payload` implementations (`GitHubForge` and `GitLabForge`) must validate both `head_sha` and `base_sha` with `is_valid_git_sha` (40 or 64 hex chars), enforce `pr_number > 0`, and validate any `repo_url` with `is_safe_repo_url` before returning `ForgeMetadata`. [F63, F64]
- Caller-supplied webhook strings echoed into logs (such as provider names, event headers via `event_label`, actions, and authors) must be sanitized through `crate::forge::loggable`, which returns `"(invalid)"` unless the value is `1..=32` bytes of ASCII alphanumerics or `'_' | '-' | '.' | ' ' | '[' | ']'`. [F65]
- `LoreMboxClient::search_patch_id` requires a 40-character ASCII hex `patch_id`, and `LoreMboxClient::thread_url` appends `message_id` as a single encoded path segment via `path_segments_mut().push` while clearing query and fragment so untrusted message IDs cannot alter the origin or traverse paths. Broken by: formatting URLs with `format!` or `Url::join`. [F72]
- `is_mbox_separator` in `src/mbox.rs` (re-exported by `src/ingestor.rs`) and its duplicate in `src/bin/sashiko-cli.rs` must remain synchronized on the exact byte-level separator rules, while `mbox::split_mbox` strips the `"From "` separator line whereas `sashiko-cli`'s `split_mbox` retains it. [F74]
- `extract_changelog_from_body` only captures lines after a standalone `---` separator up to the first line starting with `"diff --git "`, `"--- a/"`, or `"--- /dev/null"`, returning `None` if no separator exists or the trimmed text between them is empty. `inject_changelog_into_git_show` splices `---\n<changelog>` before the first `"diff --git "` substring in `git_show` (or appends it after `git_show` when no `"diff --git "` is present). [F106, F107]

## Error Handling

- When an intermediate `commit_article_mark` batch in `Ingestor::process_nntp_cycle` returns `committed < handed_off`, the loop must immediately `continue 'groups` rather than fetching subsequent batches or running the final flush, because `take_safe_mark` clears `lowest_lost` and a later commit would advance past the failed article. [F2]
- In `Ingestor::process_nntp_cycle`, an NNTP `423` (no such article) error advances `handed_off` and `current` to skip the missing article only when `next_id < info.high`; when `next_id >= info.high` or on any non-423 error, the loop must break without advancing `handed_off` past the unfetched article. [F4]
- In `FetchAgent::process_queue`, if `ensure_remote` fails or both `fetch_commits` and fallback `fetch_all` fail, `FetchAgent` must send `Event::IngestionFailed` for each commit in `missing_commits`, and when local commits are missing (`is_local` or `url_opt` is `None`), it must fall through to Step 3 so each item fails individually. [F42]
- In `Ingestor::bootstrap_repo`, a failed `git clone` (`bootstrap_clone_command`) when `!path.exists()` must return `Err` so `run_git_bootstrap` skips that epoch, whereas when `path.exists()`, non-zero exit statuses from `git remote set-url` or `git fetch` (`bootstrap_fetch_command`) are downgraded to `warn!` and `bootstrap_repo` returns `Ok(())` so existing local objects are still ingested. [F52]
- `LoreMboxClient::fetch` retries `fetch_once` across `self.retry_delays` only when `LoreFetchFailure::retryable` is true (transport timeout/connect/body/request errors, HTTP 408, HTTP 429, or 5xx responses via `is_retryable_status`), and must fail immediately without retry on non-retryable HTTP statuses (such as 404) or `MAX_MBOX_DOWNLOAD` size-limit violations. [F53]
- `decompress_mbox` (`src/mbox.rs`) and `decode_manifest` (`src/ingestor.rs`) must read from `GzDecoder` with `.take((LIMIT + 1) as u64)` and return an `Err` if `raw.len()` exceeds `MAX_MBOX_DECOMPRESSED` or `MAX_MANIFEST_DECOMPRESSED`, rather than `.take(LIMIT as u64)` which would silently return a truncated payload. [F54]
- In `GitLabForge::validate_event` when `secret` is `Some`, if the Standard Webhooks headers (`webhook-id`, `webhook-timestamp`, `webhook-signature`) are all present and `verify_standard_webhook_signature` returns `false`, it must immediately return `Err(StatusCode::UNAUTHORIZED)` without falling back to `x-gitlab-token`. [F56]
- `parse_email` returns `Err` only when `MessageParser::parse` returns `None` or the `Message-ID` header is missing or empty after `clean_display_name`; an `X-Original-From` header whose address fails `is_b4_alias(&author_email, address)` must be ignored (and warned on if `author_email` starts with `"devnull+"`) while preserving the `From` author. [F58]
- `sections_for_patchset` must read diffs via `db.patch_diffs_only(id)` (not `db.get_patch_diffs`, which silently truncates on row errors) and union `sections_for_diff` across all parts before `backfill_patchset_maintainer_sections` calls `db.replace_patchset_maintainer_sections`, continuing on per-patchset errors rather than propagating with `?`. [F127]

## External Contracts

- `NntpClient::group` must verify that the 211 response contains at least 5 whitespace-separated fields and that `parts[4]` matches the requested `group_name`, returning `Err` otherwise instead of returning a `GroupInfo` for a mismatched group. [F47]
- `decode_webhook_secret` strips the `"whsec_"` prefix and base64-decodes the remainder only for `verify_standard_webhook_signature` (logging a warning and falling back to `secret.as_bytes().to_vec()` if base64 decoding fails), whereas `verify_github_signature` and `verify_secret_token` use the raw UTF-8 bytes of `secret` as-is. [F57, F61]
- `compose_pr_review_comment` always returns a non-empty markdown comment (treating `inline_review` values of `None`, empty, or `"No issues found."` as clean in `PatchReviewSummaryItem`) and truncates the body on a UTF-8 char boundary (`is_char_boundary`) so the total length with footer never exceeds `MAX_GITHUB_COMMENT_BYTES` (60,000 bytes). [F67]
- All network-facing git subprocess commands in `bootstrap_clone_command`, `bootstrap_fetch_command`, and `FetchAgent::fetch_with_graph_retry` must place `crate::git_ops::GIT_PROTOCOL_RESTRICTIONS` before the git subcommand (`clone` or `fetch`) so git does not ignore the `-c` flags and refuses arbitrary transport helpers like `ext::`. [F68]
- `resolve_tracked_group` resolves `mailing_lists.track` entries in order: explicit `"name:group"` overrides, email addresses (`'@'`) via `derive_nntp_group`, dotted group names (`'.'`), and short names (normalizing `"linux-rt"`/`"linux-target"`, mapping `"linux-mm"` to `"org.kvack.linux-mm"`, matching `available_groups`, then `"org.kernel.vger.{normalized_entry}"`). [F71]

## Known Pitfalls

- In `src/nntp.rs`, TLS configs must be built via `ClientConfig::builder_with_provider(crypto_provider())` (as in `client_config`) rather than `ClientConfig::builder()`, because both `ring` and `aws-lc-rs` are linked into the binary without a process-wide default provider and `ClientConfig::builder()` panics at runtime. [F91]
- In `clean_subject`, after matching `lower.starts_with(prefix)` on `cleaned.to_lowercase()`, stripping the prefix from `cleaned` must use checked slicing `cleaned.get(prefix.len()..)` rather than `&cleaned[prefix.len()..]`, because Unicode case-folding in `to_lowercase()` can change byte lengths and shift UTF-8 char boundaries. [F94]
