# api-server

Implements Sashiko's Axum-based HTTP API and static web server, authentication (JWT session/sign-in/API tokens and filesystem-backed `LocalToken`), and capability/subsystem-scoped authorization (`Principal`, `BugAccess`, `TranscriptPrincipal`). It exposes endpoints for viewing and managing patchsets, messages, reviews, statistics, Linux kernel bug reports, authentication flows, patch submissions, and forge webhooks while enforcing embargo and subsystem visibility boundaries.

## Architecture & Data Flow

- `BugAccess` variants must stay in strictly increasing authority order (`None`, `Read`, `Comment`, `Manage`) for derived `Ord` checks and token attenuation. `Principal::with_max_access` and all `Principal`/`TranscriptPrincipal` capability predicates must treat `max_access` strictly as an upper bound (`base.min(limit)`), clearing `may_create` when `max_access < Some(BugAccess::Manage)` and denying read, visibility, embargo, and transcript access when `max_access == Some(BugAccess::None)`. [F3, F81]
- `SectionTitle` must compute equality, hashing, and ordering from `normalized` (trimmed, whitespace-collapsed, lowercased) while retaining the trimmed `original` spelling in `Principal::maintained_section_names` for SQL queries against verbatim MAINTAINERS section titles. Broken by: returning `title.as_str()` instead of `title.original()` from `maintained_section_names`, or comparing `SectionTitle` by `original`. [F1]
- `Principal::resolve` must return `Principal::anonymous()` (empty `email`, no roles, `may_create == false`) whenever `email.trim().is_empty()` or `acl.is_blocklisted(email)` holds. In `is_authorized`, checking `acl.is_blocklisted` against `user.email` and `user.sid` must run before `testing_mode` and `allow_all_submit` so blocklisted credentials are rejected even in permissive modes. [F2, F7]
- `LocalToken` grants local operator capability on `is_authorized` (when `perm.granted_by_local_token()`), `forge_webhook`, `create_auth_token`, and `TranscriptPrincipal::access_to_patchset`, but must never be consulted by `Principal::from_request_parts` or `TranscriptPrincipal::principal()` to grant bug visibility. Broken by: checking `presents_local_token` in `Principal::from_request_parts`, or using `access_to_patchset` instead of `principal()` when redacting bugs. [F4]
- JWT `Claims.typ` separates token lifecycles: `AuthUser::from_request_parts` only accepts `"session"` or `"api_token"`, `verify_link` only accepts `"sign_in_link"`, and `refresh_token`, `create_auth_token`, and `is_authorized` must reject `"api_token"` so non-interactive tokens cannot refresh, mint tokens, or exercise `Permission` capabilities. [F5]
- When `refresh_token` re-issues a session JWT via `create_token_with_session`, it must preserve the original `user.iat` and `user.sid` claims and reject sessions where `now.saturating_sub(iat) > MAX_SESSION_LIFETIME_SECONDS` (1 year), preventing session rotation from resetting the lifetime cap or evading `sid` blocklisting. Broken by: calling `create_token` instead of `create_token_with_session`. [F6]
- Subsystem authority in `bug_access_for_query`, `readable_bug_ids`, `resolve_patchset_embargo_access`, and `populate_embargoed_patchset_findings` must be resolved via `db.authorizing_sections_for_bug(s)` and `db.authorizing_sections_for_patchset(s)`, never from path-prefix or reporter-supplied `Bug.subsystems` names. [F8]
- Before returning bug data from `get_bug` or `get_bug_enrichments`, `redact_inaccessible_duplicate_enrichments` must scrub both `deduplication` enrichments and `audit` enrichments with `field == "duplicate_of_id"` unless every ID in `referenced_duplicate_ids(bug)` (including historical `old` and `new` audit values) is in `readable_targets`. Broken by: checking only `bug.duplicate_of_id`. [F11]
- Raw bug analysis transcripts and candidate inputs (`get_bug_raw`, `get_bug_input`, `get_bug_logs`, and `candidate` / `raw_candidate` items in `get_bug` activity and `get_bug_enrichments`) must be gated on `principal.has_global_bug_visibility()`, because deduplication prompts embed problem statements of unrelated bugs across subsystems. [F12]
- Public patchset and review endpoints (`get_patchset`, `get_review`, `get_review_log`) must call `redact_embedded_bugs(&state, &principal, &mut details)` before returning, filtering `details["bugs"]` via `readable_bug_ids` so embedded bug summaries obey the same subsystem visibility as `/api/bug`. [F13]
- `list_patchsets` must cache the unfiltered page-1 `PatchsetRow` slice in `patchsets_homepage_cache` before calling `populate_embargoed_patchset_findings` on the cloned `items` vector, and `release_patchset_embargo` must call `state.patchsets_homepage_cache.invalidate().await` when `released` is true. [F14]
- `list_bug_subsystems` must key `bug_subsystems_cache` on both the canonical parsed `BugLifecycleStatus::as_str()` (accepting the `status` alias on `BugSubsystemsQuery`) and the caller's `Principal::visibility` scope (`"*"` or sorted `Principal::maintained_section_names`) so counts are never shared across visibility scopes. [F69]
- In `bug_action` for `BugAction::MarkDuplicate`, the target bug must be distinct from `bug.id`, must be canonical (`target.duplicate_of_id.is_none()`), and the caller must hold `BugAccess::Manage` on BOTH `bug.id` and `target.id`, returning an identical 400 message when `target` is missing, non-canonical, or outside the caller's manage authority. Broken by: checking `bug_access` only on `bug.id`, or returning 403 instead of 400 when `!target_access.can_manage()`. [F16]
- `assignment_notice` and `is_notifiable_address` must suppress `BugAssignment` emails when `assigner` is empty, `assignee` equals `assigner` case-insensitively, `assignee` is unparsable as `lettre::Address`, its domain is in `KNOWN_MAILING_LIST_DOMAINS`, it matches `smtp.sender_address`, or it is blocklisted in `state.settings.server.acl`. [F17]
- `SignInLinkRateLimiter::check_and_record` must check all three sliding windows (per-IP 10/15m, per-lowercased-email 3/15m and 10/24h, and global 100/1h) before recording the timestamp in any bucket, so a request rejected by a later bucket does not consume quota in earlier buckets. [F18]
- Before sending a `FetchRequest` on `state.fetch_sender` or spawning `fetch_and_inject_thread`, `submit_patch` and `forge_webhook` must insert a placeholder via `db.create_fetching_patchset`: `Remote`/`RemoteRange` returns early if `db.has_patchset_by_msgid(&id)` is true and otherwise uses `"{sha}@sashiko.local"`, while `forge_webhook` skips when `forge.review_intent(&action) == ReviewIntent::Skip` or `is_dependabot_author` matches `metadata.author` and otherwise uses `"mr-{pr_number}-{base_sha}..{head_sha}@sashiko.local"`. [F19, F98, F101]
- For `SubmitRequest::Thread` in `submit_patch`, `normalize_thread_message_id` must only strip surrounding `<` and `>` without URL-encoding, and `submit_patch` must await `db.create_fetching_patchset` with `clean_msgid` before spawning `fetch_and_inject_thread`; the detached task must pass `clean_msgid` to `fetch_and_inject_thread` and send `Event::IngestionFailed` on `sender` if it returns an error. [F20, F36]
- All mutation endpoints in `src/server.rs` and capability flag exporters (`resolve_patchset_embargo_access`, `get_bug`, `get_config`) must enforce `state.read_only` by rejecting mutations with `403 Forbidden` and reporting mutation capability flags (`can_release_embargo`, `can_comment`, `can_manage`, `permissions.*`) as `false`. [F21]
- In `analyze_bug` and `bug_action`, the audit actor passed to `state.db.with_bug_actor` must always be derived from the authenticated `principal.email()` (falling back to `format!("authorized client ({})", addr.ip())` only when `principal.email().is_empty()`, as in `testing_mode`), never from client-supplied request fields. [F22]
- When `analyze_bug` constructs a `ToolBox` for `process_issue_for_project`, it must pass `None` as the worktree path to `ToolBox::new` and pin the virtual HEAD via `set_virtual_head` to the first resolving server-side ref in `["origin/master", "origin/main", "master", "main", "HEAD"]` rather than a client-supplied commit. [F93]

## Synchronization

- In `AsyncCache::get_or_fetch` and `AsyncMapCache::get_or_fetch`, the read guard from `self.inner.read().await` must be dropped before `self.inner.write().await` is awaited, and the TTL check (`cached.timestamp.elapsed() < self.ttl`) must be re-evaluated under `write_guard` before awaiting `fetch()`. [F28]
- `health_check` loads `AppState::email_worker_heartbeat` (`AtomicI64`) with `Ordering::Relaxed` and must return `StatusCode::SERVICE_UNAVAILABLE` only when `last > 0` and `now.saturating_sub(last) > EMAIL_WORKER_STALE_SECONDS`, treating `None` or a non-positive initial timestamp as healthy. [F31]

## API Contracts

- In `submit_patch`, `analyze_bug`, `forge_webhook`, and `create_auth_token`, `read_only`, authorization (`is_authorized`, `principal.may_create()`, `presents_local_token`), and feature checks must run before extracting the body from `axum::extract::Request` via `FromRequest`. Broken by: extracting `Json<T>` or `Bytes` as a handler parameter before checking authorization. [F53]
- In `build_router`, the 25 MiB `DefaultBodyLimit` layer must be attached only to `/api/submit` and `/api/webhook/{provider}`, while `/api/auth/request-link` and `/api/auth/token` are capped at 64 KiB and other routes remain under Axum's default limit. [F54]
- `is_authorized` and `forge_webhook` must never trust the peer `SocketAddr` (including loopback) for access control because reverse proxies forward internet traffic from loopback; callers must prove authority via `webhook_secret` signature (`validate_event`), `AuthUser`, `presents_local_token`, or `allow_all_submit`. [F57]
- `get_bug` (`GET /api/bug`) grants capability `BugAccess::Read` to unauthenticated or out-of-subsystem callers only when addressed by `bugid` or `slug` without `id` (`BugQuery::by_bugid` via `resolve_bug_read_principal` and `readable_bug_for_view`), whereas numeric `id` lookups require a valid token and subsystem/global read authority. Broken by: using `resolve_bug_read_principal` or `readable_bug_for_view` outside `get_bug`, or allowing `BugQuery::effective_bugid` to return `Some` when `query.id.is_some()`. [F59]
- `resolve_patchset_embargo_access` denies both viewing and releasing embargoes when `is_auth_blocklisted` is true (before `is_authorized` bypasses), permits viewing in `read_only` mode or with `BugAccess::Read` (`may_view_embargoed`), and requires `!state.read_only` plus `Permission::Review` or `BugAccess::Manage` (`may_release_embargo`) to release. [F105]
- `PatchQuery` must keep `per_page` and `limit` as separate fields deserialized with `page_size` (clamping integers to `1..=MAX_PATCHSET_PAGE_SIZE` and mapping non-integers to `None`), and `get_patchset` and `get_patchset_summary` must pass `query.page_size()` rather than `query.per_page` to database queries and `attach_patchset_flags`. [F71]
- List handlers (`list_patchsets`, `list_messages`, and `list_bugs`) must clamp `page` with `.unwrap_or(1).max(1)` and `per_page` with `.unwrap_or(50).clamp(1, 100)` before computing SQL offsets or querying `Database`. [F72]
- `build_bug_assignment_email` must collapse whitespace in the bug title and truncate the subject's title to `ASSIGNMENT_SUBJECT_TITLE_BYTES` (80 bytes) and the body's note to `ASSIGNMENT_NOTE_BYTES` (4096 bytes) using `crate::utils::utf8_prefix`. Broken by: slicing `title` or `note` by byte index directly or leaving them unbounded. [F77]

## Error Handling

- Single-bug lookups (`readable_bug`, `readable_bug_for_view`) and `bug_action` (via `bug_lookup_denial`) must return `StatusCode::NOT_FOUND` (`"Bug not found"`) rather than `403 Forbidden` when a bug exists but `Principal` lacks read access (`!can_read()`), whereas `transcript_bug` returns `StatusCode::FORBIDDEN` when `!principal.has_global_bug_visibility()` after `readable_bug` succeeds. [F39, F60]
- `enforce_review_embargo` (called by `get_review` and `get_review_log`) must return `Err(StatusCode::NOT_FOUND)` rather than `StatusCode::FORBIDDEN` when a review has `embargo_until > now` and either lacks `patchset_id` or the caller lacks embargo view permission (`!can_view`). [F42]
- When `resolve_jwt_secret` returns `Some`, `request_link` must swallow JSON deserialization errors, ineligible or blocklisted email addresses, and rate-limit rejections (`!rate_ok`), execute dummy `create_token` and DB `SELECT 1` work on the rejected path, and return `Ok(StatusCode::OK)` with an empty body. Broken by: using `Json<RequestLinkRequest>` extractor or returning `400`, `403`, or `429`. [F43]
- `analyze_bug` must log errors from `crate::ai::create_provider` and `crate::workflows::linux_bug::process_issue_for_project` internally and return fixed `500 Internal Server Error` strings (`"Analysis is unavailable."` and `"Analysis failed."`), never serializing the underlying error into the HTTP response. [F44]
- `list_bugs` and `list_bug_subsystems` must reject unparsable `lifecycle_status` (or `status`) and `pipeline_state` query parameters with `Err(StatusCode::BAD_REQUEST)` rather than falling back to a default or returning an empty result set. [F45]
- `LocalToken::write_to` must unlink any existing file at `path` (ignoring only `io::ErrorKind::NotFound` and propagating any other `remove_file` error) before opening with `create_new(true)` and `mode(0o600)`, and `LocalToken::read_from` must reject non-64-hex-character contents (`is_token_shaped`) with `io::ErrorKind::InvalidData`. [F50]

## External Contracts

- `list_mailing_lists` (`GET /api/lists`) must return a JSON array of `{ "name": name, "group": group }` objects from `db.get_mailing_lists()` rather than bare strings. [F65]
- `src/api.rs` and `LocalToken` in `src/auth.rs` are compiled unconditionally without optional server crates (`axum`, `jsonwebtoken`), whereas JWT types and helpers (`Claims`, `AuthUser`, `OptionalAuthUser`, `create_token`, `create_api_token`, `create_token_with_session`, `verify_token`) in `src/auth.rs` must be gated on `#[cfg(feature = "server")]`. [F116]

## Known Pitfalls

- Handlers filtering or enriching multiple bugs or embargoed patchsets (`redact_embedded_bugs`, `get_bug`, `attach_duplicate_relations`, and `populate_embargoed_patchset_findings`) must batch database lookups via `readable_bug_ids`, `authorizing_sections_for_patchsets`, and `get_patchset_finding_counts`. Broken by: calling `bug_access` or `resolve_patchset_embargo_access` inside a per-item loop. [F74]
