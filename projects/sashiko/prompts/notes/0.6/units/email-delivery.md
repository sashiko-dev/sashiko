# email-delivery

Configures and executes outbound notification routing and delivery across email (SMTP and local sendmail), Patchwork REST APIs or notification emails, and GitHub pull request comments. It parses mailing-list delivery policies from TOML, resolves recipients and Patchwork check states from review findings, and runs three sequential outbox background workers (`EmailWorker`, `PatchworkWorker`, and `ForgeWorker`) that poll database outbox tables with ghost-row recovery and bounded retry/backoff logic.

## Architecture & Data Flow

- `PatchworkPolicy::normalize` (invoked by `EmailPolicyConfig::parse_content`) strips trailing `'/'` characters from `api_url` and clears `api_url` to `None` unless it starts with `"https://"` or `"http://"`, which `PatchworkWorker::resolve_token` relies on when comparing `entry.api_url` to `sub.patchwork.api_url`. Broken by: constructing or mutating `EmailPolicyConfig` or `PatchworkPolicy::api_url` without calling `normalize()`. [F1]
- `EmailPolicyConfig::apply_token_override` sets `patchwork.token` from the fallback token (such as `SASHIKO_PATCHWORK_TOKEN`) only when `patchwork.enabled` is true, `patchwork.api_url` is `Some`, and `patchwork.token` is `None`, never overwriting an explicit TOML token. [F2]
- `EmailRouter::resolve_patchwork` splits each enabled `PatchworkPolicy` into separate API-only (`email = None`) and email-only (`api_url = None`, `token = None`) targets keyed by `api_url` and `email`. When `EmailRouter::merge_policies` merges duplicates targeting the same endpoint, `min_severity` (`merge_severity_opt`, where `None` means all severities and dominates `Some`) and `fail_severity` each resolve to the lower (more inclusive) `Severity`, and `a.token` is preserved unless `None`. [F5, F103]
- In `EmailRouter::resolve_recipients`, when `matched_lists` is non-empty, each matched list's `ReplyTarget::List` adds only its own `list_bare` to `allowed_lists`, whereas `mute_all = true` on any matched list mutes the entire message (`Action::Mute`). Broken by: allowing one matched list's `ReplyTarget::List` to include all cross-posted lists in `To`/`Cc`, or ignoring `mute_all` when another matched list has `mute_all = false`. [F7]
- `EmailRouter::resolve_recipients` immediately returns `Action::Mute` if `EmailRouter::is_ignored_author(policy, patch_author)` is true or `patch_author` matches/contains `sashiko_address`. `EmailRouter::dedup_addresses` deduplicates by `extract_bare_email`, drops any address matching/containing `sashiko_bare` or in `exclude_bare`, upgrades a bare entry in-place if a later duplicate has a `<...>` display name, and in `resolve_recipients` / `resolve_positive_recipients` passes `Some(&to_bare_set)` as `exclude_bare` for `final_cc`. [F10, F99]
- `EmailRouter::too_many_individuals` counts distinct bare non-list incoming `To`/`Cc` addresses excluding `sashiko_bare`, `author_bare` (when `include_author` is true), and `static_cc`, and disables `include_recipients` when that count exceeds `MAX_RELAYED_RECIPIENTS` (128) while still mailing allowed lists, the author, and `static_cc`. Broken by: counting the bot address, author, `static_cc`, or mailing lists toward the cap, or muting the entire email. [F9]
- When `resolve_recipients` returns `PositiveReviewPolicy::All` for a patch matching configured lists, `EmailRouter::resolve_positive_recipients` recomputes `allowed_lists`, `include_recipients`, and per-list `static_cc` using only matched lists whose own `positive_review` is `PositiveReviewPolicy::All` (plus `include_author` if `Author`). Broken by: reusing the `(to, cc)` vectors from `resolve_recipients` directly when `matched_lists` is non-empty. [F11]
- `PatchworkCheckResult::from_policy` filters out findings with `Severity` below `policy.min_severity` before counting, and derives `state` (`"success"`, `"warning"`, or `"fail"` at or above `policy.fail_severity`) exclusively from non-`preexisting` findings while still reporting `preexisting` counts in `description`. [F12]
- `PatchworkWorker` never stores or reads API tokens in `patchwork_outbox`; `PatchworkWorker::resolve_token` reloads `EmailPolicyConfig` via `EmailPolicyConfig::load_async(&self.email_policy_path)` (`tokio::fs::read_to_string`, never blocking `EmailPolicyConfig::load`) on every attempt and matches `entry.api_url` against enabled list policies before falling back to `config.defaults.patchwork`. [F17, F28]
- `ForgeWorker` caches the GitHub App installation token and expiration timestamp (`now + 3600`) in `cached_token: Mutex<Option<(String, i64)>>`, reusing it only while `now + 300 < expires_at` and clearing it via `invalidate_cached_token` whenever `post_github_pr_comment` returns an error containing `"401 Unauthorized"`. In `ForgeWorker::resolve_token`, the `cached_token` lock guard must be dropped before reading the private key, minting the JWT, and awaiting `exchange_github_installation_token`, then re-acquired to store the token. [F18, F84]
- `EmailWorker::send_email` and its helpers (`build_email_message`, `send_via_smtp`, `send_via_sendmail`) must not mutate shared state on `EmailWorker` across a potential panic point because `EmailWorker::run` wraps `self.send_email(&email)` in `std::panic::AssertUnwindSafe` and continues running the worker loop after catching a panic. [F81]
- In `build_email_message`, `email_row.to_addresses` and `email_row.cc_addresses` must be deserialized as JSON string arrays (`serde_json::from_str::<Vec<String>>`), whereas `email_row.references_hdr` is whitespace-separated bare message-IDs and `email_row.in_reply_to` is a single bare message-ID that must each be wrapped in `<...>`. [F89]
- When `SmtpSettings::dry_run` is enabled and `EmailWorker::log_sign_in_links` is `false`, `EmailWorker::send_email` must withhold `email_row.body` from logs whenever `email_row.kind` is `EmailKind::SignInLink` because that outbox row body carries a bearer sign-in credential. [F111]

## Synchronization

- `EmailWorker::run` must call `self.record_heartbeat()` on `Ok(None)` when the outbox is idle, after completing or failing an email row, and before sleeping during transient SMTP retries, but must not update the heartbeat when `lock_pending_email` returns a database `Err`. [F29]
- `EmailWorker::run` wraps `self.send_email(&email)` in `catch_unwind` and `tokio::time::timeout(SMTP_SEND_TIMEOUT, ...)` (60s), and `EmailWorker::send_via_smtp` sets `.timeout(Some(SMTP_SOCKET_TIMEOUT))` (30s) on `AsyncSmtpTransport`, so a panic or stalled SMTP peer cannot block the loop and transitions the `'Sending'` row to `'Failed'` via `mark_email_failed` rather than looping via `sweep_ghost_emails`. [F13, F75]
- `ForgeWorker::run` and `ForgeWorker::handle_failure` mark an entry `'Failed'` via `mark_forge_outbox_failed` if `entry.provider != "github"`, `is_permanent_failure(err)` matches `"404 Not Found"` or `"422 Unprocessable"`, or `retry_count + 1 >= self.max_retries as i64`. Non-terminal retries in `ForgeWorker::handle_failure` and `PatchworkWorker::run` (also bounded by `retry_count + 1 >= self.max_retries as i64`) must be scheduled via database `retry_at` timestamps (`backoff_seconds`: 5s, 30s, capped at 180s) via `set_forge_outbox_retry_at` rather than sleeping inline. [F19, F78]

## Object Lifetimes

- `EmailWorker::send_via_sendmail` must await `AsyncSendmailTransport::send` inside `tokio::time::timeout(SENDMAIL_TIMEOUT, ...)` using a transport that spawns the MTA child with `kill_on_drop`, so that timing out or aborting the send future kills the child process before any retry can run. [F30]
- Unless `SmtpSettings::dry_run` is true or `SmtpSettings::transport` is not `MailTransport::Sendmail`, `EmailWorker::check_sendmail_path` must verify before `EmailWorker` starts that `settings.sendmail_command()` is an executable regular file (`meta.is_file()` and mode `& 0o111 != 0`). [F31]
- On each loop iteration before locking the next pending row, `EmailWorker::run`, `PatchworkWorker::run`, and `ForgeWorker::run` must call `sweep_ghost_emails`, `sweep_ghost_patchwork`, and `sweep_ghost_forge_outbox` respectively to reclaim rows left in `Sending` after a crash or abort. Broken by: removing `sweep_ghost_*` or running it only once before entering `loop`. [F33]
- `ForgeWorker::run` and `PatchworkWorker::run` must obtain their `reqwest::Client` from `crate::worker::outbox_client` (which sets connect and total request timeouts) rather than `reqwest::Client::new()`, because all HTTP requests are awaited inline in each worker's sequential loop. [F34]

## API Contracts

- `EmailRouter::address_matches_list` must match incoming `To`/`Cc` headers against configured mailing lists by comparing only normalized bare email addresses (`extract_bare_email`), never by substring matching on the full header or display name. [F58]
- `EmailRouter::is_mailing_list_address` classifies any address in `configured_lists` or whose domain is in `KNOWN_MAILING_LIST_DOMAINS` as a mailing list, so `ReplyTarget::Recipients` never relays reviews to unconfigured mailing lists on known list domains. [F60]
- All six modules in `email-delivery` (`email_policy`, `email_router`, `patchwork` in `src/lib.rs`, and `worker::email`, `worker::forge`, `worker::patchwork` in `src/worker/mod.rs`) are compiled only under `#[cfg(feature = "server")]`, whereas `build_outbox_client` and `outbox_client` in `src/worker/mod.rs` are compiled unconditionally. Broken by: importing the `server`-gated modules from code compiled in `--no-default-features` builds. [F116]

## Error Handling

- `EmailWorker::run` retries failed deliveries up to `SMTP_MAX_ATTEMPTS` (3) only when `is_transient_smtp_error` returns true: transient 4xx `smtp::Error`, errors starting with `"transient error (4"` or `"Connection error"`, or any `lettre::transport::sendmail::Error` (treated as transient because `lettre` drops the child exit status and cannot distinguish `EX_TEMPFAIL` from permanent rejection). Never retry delivery/socket timeouts or mid-stream network errors, which can occur after the remote MTA accepted `DATA`. [F14, F41]
- In `build_email_message`, errors parsing `settings.sender_address` or deserializing `email_row.to_addresses` and `email_row.cc_addresses` from JSON propagate as `Err`, whereas an unparseable individual `to`, `cc`, or `settings.reply_to` address (`parse_lenient`) is logged with `warn!` and skipped without failing the message. [F44]
- `EmailPolicyConfig::load` and `EmailPolicyConfig::load_async` must return `Ok(EmailPolicyConfig::default())` only when reading the file fails with `std::io::ErrorKind::NotFound`, and must surface any other I/O error, TOML syntax or unknown-field error, or `EmailPolicyConfig::validate` failure as `Err`. [F45]

## External Contracts

- `build_email_message` and `parse_lenient` must strip control characters via `crate::patch::clean_display_name` from `subject`, `in_reply_to`, `references_hdr` tokens, and mailbox display names in `sender_address`, `reply_to`, `to_addresses`, and `cc_addresses` before passing them to `lettre`. [F53]
- `build_email_message` must omit `Reply-To` whenever `email_row.kind` is not `EmailKind::ReviewNotification`, and for kinds where `transactional_list_label()` is `Some(label)`, it must set `Auto-Submitted: auto-generated` and `List-Id: <{label}.{sender_domain}>`. Broken by: applying `settings.reply_to` unconditionally to sign-in or bug-assignment emails. [F54]
- `build_email_message` must set a deterministic `Message-ID` header formatted as `<sashiko-outbox-{id}@{sender_domain}>` derived from `email_row.id` so retries of the same outbox row carry an identical `Message-ID`. [F55]
- `EmailWorker::send_via_sendmail` must pass envelope recipients on the command line after `--` (via `AsyncSendmailTransport`) rather than invoking `sendmail -t` or omitting `--` before recipient addresses, preventing header-parsed or hyphen-prefixed addresses from being interpreted as MTA options. [F57]
- `EmailPolicyConfig::parse_content` enforces `#[serde(deny_unknown_fields)]` on `DefaultListPolicy`, `MailingListPolicy`, and `PatchworkPolicy`, and `EmailPolicyConfig::validate` rejects any top-level table key (other than `[defaults]`) that is not `local@domain.tld` or any list that repeats its own bare address in `cc`. [F63]
- `post_patchwork_check` must strip `<` and `>` from `msgid` when querying `GET {api_url}/patches/?msgid=...`, return `Err(PatchworkCheckError::NotIndexedYet)` when the returned JSON patch list is empty, and POST `{state, target_url, description, context: "sashiko"}` (`PatchworkCheckRequest`) with `Authorization: Token {token}`. [F67]
- `compose_patchwork_email` must format the subject as `"[sashiko-check] {status} - {patch_subject}"` and the body as newline-separated `msgid`, `status`, `description`, `target_url`, and `context: sashiko` key-value lines for downstream parsers such as `pw_tools`. [F68]
