Static/targeted seed preservation rule:
- If a retained concern has preservation=proof_required_drop or preservation_policy=proof_required_drop, Stage 9 must adjudicate it explicitly. These seeds may be wrong, but they must not disappear without proof.
- Allowed outcomes are: emit a finding; drop as subsumed_by with subsumed_by_finding_id pointing to a finding that preserves the exact bug mechanism; or drop as false_positive with concrete proof.
- Do not drop proof-required seeds as duplicate, unclear, insufficient_evidence, too speculative, not_security_relevant, or generic cleanup/API concern.
- For cgroup_keyed_parse_missing_value, a finding must preserve file/function, keyed limit option or changed cgroup file key, missing value/absent option, NULL dereference or invalid parse, and write path trigger. A false_positive drop must prove the write handler cannot receive a bare key, the parser rejects missing values before the vulnerable access, the value pointer is checked before dereference/parse, or the alleged key is not handled by the changed path.
- For rcu_teardown_iteration_without_read_lock, a finding must preserve the teardown/unregister function, list_for_each_rcu or equivalent iterator, missing rcu_read_lock/equivalent protection, teardown/unregister context, and warning/race mechanism. A false_positive drop must prove rcu_read_lock() is held, a documented update-side lock/lockdep condition covers the traversal, or the function is not reachable in unregister/teardown context.
- For skb_fragment_capacity_max_skb_frags, a finding must preserve the append function, nr_frags/frag array capacity, missing MAX_SKB_FRAGS or equivalent guard, and overflow/capacity consequence. A false_positive drop must prove a MAX_SKB_FRAGS or equivalent nr_frags guard executes before every append.
- For retry_error_path_resource_leak, a finding must preserve the operation/helper, response/resource buffer, cleanup helper, failed operation followed by retry/fallback, and leak-before-retry/overwrite mechanism. A false_positive drop must prove the exact cleanup path and free call run before the retry/fallback can overwrite or lose the buffer.
